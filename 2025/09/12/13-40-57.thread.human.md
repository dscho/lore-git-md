This thread investigates a bug report where Git's merge behavior sometimes loses formatting changes from one branch when merging with a branch that didn't modify the same location. Guo Tingsheng originally reported that multi-line Java method call formatting changes (adding line breaks) can disappear during merges, even when the other branch made no conflicting changes. The behavior appears non-deterministic in Git 2.43.0 on Ubuntu 24.04, with before/after code snippets clearly showing the lost changes.

Elijah Newren, a Git contributor with deep merge machinery expertise, has now joined the discussion. He suggests a possible technical explanation involving non-unique merge bases, where one base might have introduced the same change, making it appear that branch A's changes were undone by branch B. However, Newren emphasizes this is just a hypothesis and requests more concrete reproduction materials - either a shareable repository or complete set of commands to recreate the scenario from scratch. The next step in the investigation awaits Guo Tingsheng providing these more detailed reproduction steps to help determine whether this represents a genuine merge bug or an edge case in Git's diff/merge algorithms.
