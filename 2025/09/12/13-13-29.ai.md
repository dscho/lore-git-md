Bugfix targeting Git's merge functionality for indentation preservation.

Guo Tingsheng reports a whitespace handling issue during merges where newly added indented blocks sometimes lose their indentation when merged with an unchanged version of the file. The bug manifests when merging a branch that adds properly indented code with a branch that made no changes to the same file, resulting in inconsistent indentation in the merged result.

The issue affects Java-style code blocks (though the underlying problem may be more general) and occurs with both ort and recursive merge strategies. The reporter specifically notes this isn't related to core.whitespace settings, suggesting it's a deeper issue in how Git handles indentation for newly introduced blocks during merges.

The bug appears non-deterministic, making it potentially disruptive for teams working with strictly formatted codebases. While the example shows Java code, similar problems could affect any language where indentation is significant. The report includes clear reproduction steps and environment details (Git 2.43.0 on Ubuntu 24.04), though it doesn't indicate whether the issue exists in other versions or platforms.

This seems like a legitimate merge algorithm issue rather than a configuration problem, though the non-deterministic nature suggests it may be edge-case behavior. The report is well-structured with clear before/after examples, but lacks information about whether this occurs with other indentation styles (tabs vs spaces) or more complex nesting scenarios.
