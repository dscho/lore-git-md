Bug report thread on Git merge behavior where multi-line Java formatting changes are lost during merge when one branch didn't modify the location. Originating author Guo Tingsheng initially reported the issue with code snippets showing method call formatting changes disappearing non-deterministically in Git 2.43.0. He has now provided a public reproduction repository (github.com/CoriWork/bug-replay) with detailed steps showing this occurs deterministically when: (1) a patch is split into two disjoint hunk sets applied to separate branches, then merged; (2) the merged result incorrectly reverts branch B's formatting change (collapsing multi-line method calls) despite branch A not touching that code section.

Elijah Newren, the merge machinery maintainer, previously hypothesized this might relate to non-unique merge bases making changes appear undone. The reproduction case now enables proper investigation of this theory by providing the exact commit history and merge base. Key technical details: the issue manifests with whitespace/multi-line changes when one side is unmodified, producing output that differs from the original commit's content. The thread has progressed from initial report to testable case, with next steps being analysis of whether this represents an edge case in the merge algorithm's handling of disjoint hunk sets and whitespace changes when one branch is unmodified.
