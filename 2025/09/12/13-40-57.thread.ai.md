Bug report thread on Git merge behavior where changes from one branch can be lost during merge when the other branch didn't modify the same location. The issue manifests when: 1) Branch A modifies a multi-line Java method call (adding line breaks) 2) Branch B makes no changes to this location 3) Merging sometimes loses Branch A's formatting changes. Behavior appears non-deterministic, suggesting possible merge strategy internals or line-based diff heuristics issue. Reproduction uses Git 2.43.0 on Ubuntu 24.04 with before/after code snippets showing expected (preserved changes) vs actual (lost changes) merge results. Underlying cause not yet identified - could involve merge machinery's handling of whitespace or multi-line changes when one side is unmodified. No workaround provided but clear reproduction steps should aid investigation into whether this represents a real merge bug or diff/merge algorithm edge case.
