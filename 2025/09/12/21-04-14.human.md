This is a status update and call for help on the SHA-256 transition work, specifically focusing on the interoperability aspects between SHA-1 and SHA-256 repositories. Brian Carlson provides a detailed breakdown of current progress and areas needing assistance as the project targets a Git 3.0 release in 2026.

Brian reports having 93 patches in progress for SHA-256 interoperability, with core functionality like object mapping, pack index v3, and basic clone/push operations working. However, significant work remains to productionize these changes, including test coverage expansion, scale testing, and implementing missing functionality like partial clone and submodule support. The email highlights several concrete areas where contributors could help: writing more tests (especially for edge cases in different protocols), fixing broken tests in compatibility mode, implementing `git gc` integration for new object maps, and creating repository conversion tools.

The message emphasizes the importance of distributing the workload, as the anticipated 200-300 total patches would be overwhelming for a single maintainer to submit last-minute. Brian plans to organize the remaining work into a public task list and suggests using GitHub/GitLab issues for coordination. The tone is welcoming of assistance while being realistic about the scope - this is clearly a major undertaking that will benefit from multiple contributors, but one where the technical direction and core implementation are already well-established.
