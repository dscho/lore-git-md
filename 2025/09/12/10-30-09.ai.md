This is a feature patch in the `git sparse-checkout clean` series, adding verbose output capability to show individual files that would be affected by the clean operation.

The patch introduces a `--verbose` flag that causes `git sparse-checkout clean` to list every file within directories marked for removal, rather than just showing the directory names. This helps users understand why directories are being cleaned and what specific files are involved. The verbose output works with both `--dry-run` (showing "Would remove" messages) and actual execution (showing "Removing" messages).

Key technical details:
- New `list_file_iterator()` callback and `list_every_file_in_dir()` helper function implement the verbose file listing
- Uses the existing `for_each_file_in_dir()` traversal infrastructure from earlier in the series
- Output format matches the existing directory-level messages but applies to individual files
- Test cases verify verbose output shows correct file paths in dry-run mode
- Documentation updated to explain the new `--verbose` option's purpose

The implementation builds on the series' earlier work to remove `the_repository` usage, with the verbose mode leveraging the new directory traversal helpers. This maintains the thread's refactoring goals while adding user-facing functionality. The patch follows the established pattern of matching `git clean` behavior, where verbose output shows more detailed information about the cleaning operation.

This appears to be a well-integrated addition to the series, with clear documentation and test coverage. The verbose output addresses a real usability need by helping users understand exactly what files are being cleaned and why directories might persist due to remaining contents.
