This is part 3 of a 4-part series fixing batched reference update issues on case-insensitive filesystems, specifically addressing file/directory (F/D) conflicts. The patch modifies the files backend to properly detect conflicts like 'refs/heads/foo' vs 'refs/heads/Foo/bar' by lowercasing refnames during validation when on case-insensitive systems.

The key change is in `lock_raw_ref()` where refnames are now lowercased before F/D conflict checks, while maintaining the original behavior on case-sensitive systems. This prevents leaving behind orphaned lock files when transactions abort due to undetected conflicts. The patch includes a new test case that verifies proper error reporting when fetching would create such conflicts.

This iteration follows previous discussion about keeping case-sensitivity concerns within the files backend rather than pushing them into shared utilities. The solution is cleanly scoped, with clear memory management of the temporary lowercased strings. Test coverage now includes both the direct case collision scenarios from earlier patches and this new F/D conflict case.

The series as a whole has seen thorough review, with Junio Hamano reporting the original bug and Patrick Steinhardt providing detailed feedback on error handling. This patch in particular shows careful attention to edge cases while maintaining the principle that non-conflicting updates should proceed whenever possible.
