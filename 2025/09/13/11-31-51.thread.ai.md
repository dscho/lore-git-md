Thread subject: "gitk: fix handling of deleted remote tracking branches"  
Thread type: bugfix for gitk (Git GUI tool)  
Authors: Michael Rappazzo (original patch), Johannes Schindelin (forwarded patch), Johannes Sixt (reviewer)  

Core problem: gitk fails when opening its "Tags and Heads" view after remote branch deletion due to inconsistent state between `headids` (tracking branch heads) and `upstreamofref` (tracking relationships). The missing branch remains referenced in `upstreamofref` after being removed from `headids`.

Technical details:  
- Bug location: `refill_reflist` in gitk (Tcl script)  
- Root cause: Missing existence check for `headids($upstreamofref($n))`  
- Fix: 4-line change (3 insertions, 1 deletion) adding existence checks  
- Includes reproduction recipe demonstrating error case
