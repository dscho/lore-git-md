This is a bug report about the `safe.directory` security feature not working as documented. The user reports that despite following Git's suggested workaround to mark a shared repository as safe, they still cannot clone or push to it due to ownership checks.

The issue occurs when trying to work with a shared repository where files are owned by root but group-writable (a common setup for shared repositories). Git's security measure blocks access, and the documented solution of adding the directory to `safe.directory` in the config (either globally or via command line) fails to resolve the issue. The user has tried using `safe.directory="*"` as a workaround, which also doesn't work.

The report comes with detailed reproduction steps and shows the user has tested with both Git 2.39.5 and 2.51.0. The tone suggests frustration with what they perceive as a breaking change introduced without proper opt-in mechanisms. While the report is clear and well-documented, it's worth noting this appears to be a known pain point with Git's security model for shared repositories rather than a new bug.
