This is the third patch in a series improving worktree conflict handling, specifically extending the new `--ignore-other-worktrees` behavior to `git rebase`. The patch adds an advice message when rebase fails due to a branch being checked out in another worktree, mirroring the behavior added for checkout operations in earlier patches.

The technical change replaces the direct `die_if_checked_out()` call with `die_message_if_checked_out()` and adds an advice message suggesting the `--ignore-other-worktrees` workaround when the operation would fail. This matches the pattern established in the first patch of the series, maintaining consistency between checkout and rebase behavior. The advice uses the same `ADVICE_BRANCH_USED_IN_OTHER_WORKTREE` enum introduced earlier.

Key implementation details include:
- The advice appears only when the operation would fail (exit code non-zero)
- Maintains the same exit code behavior as before
- Preserves the existing `ignore_other_worktrees` flag check
- Keeps all other rebase logic unchanged

This completes the core functionality of the series by providing consistent user experience across both checkout and rebase operations when dealing with branch conflicts across worktrees. The patch builds on the infrastructure (advice system, refactored branch checking functions) established in previous patches while keeping the changes focused and minimal.
