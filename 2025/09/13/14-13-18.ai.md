This is the first patch in a series improving worktree behavior around the `--ignore-other-worktrees` option, specifically focusing on user experience when operations fail due to branch conflicts.

The patch adds a new advice message that appears when checkout/switch operations fail because the target branch is already checked out in another worktree. The advice suggests using `--detach` or `--ignore-other-worktrees` as workarounds. The implementation involves:

1. Adding a new `ADVICE_BRANCH_USED_IN_OTHER_WORKTREE` enum and config option
2. Modifying `die_if_checked_out()` to split into two functions: one that dies immediately (keeping backward compatibility) and a new `die_message_if_checked_out()` that returns an error code after printing the message
3. Updating the checkout implementation to show the new advice before exiting

Key technical details:
- New function signature in branch.h: `int die_message_if_checked_out()`
- Advice text suggests both `--detach` and `--ignore-other-worktrees` options
- The patch explicitly notes rebase operations are not yet supported (left for future work)
- Changes span advice infrastructure, branch checking logic, and checkout implementation

This appears to be a well-scoped first contribution that improves user experience while maintaining backward compatibility. The patch follows Git's advice system conventions and includes documentation updates. The split of `die_if_checked_out()` into two functions suggests this may be groundwork for future extensions in the series.
