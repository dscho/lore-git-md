Bugfix targeting case-insensitive filesystem behavior in batched reference updates. This is the first patch in a 4-part series addressing reference conflicts on case-insensitive filesystems.

The patch modifies the files backend to properly handle case conflicts during batched reference updates (introduced in Git 2.51). Previously, such conflicts would either silently overwrite references (pre-2.51) or fail the entire batch (post-2.51). The changes:

1. Introduce `REF_TRANSACTION_ERROR_CASE_CONFLICT` error type for case collisions
2. Add case conflict detection via `transaction_has_case_conflicting_update()`
3. Modify `lock_raw_ref()` to return specific error types for different conflict scenarios
4. Update `git fetch` to show helpful messages about case-insensitive filesystem limitations
5. Add tests verifying behavior on both case-sensitive and insensitive filesystems

Key technical details:
- Affects `git fetch`, `git receive-pack`, and `git update-ref --batch-updates`
- Modifies error handling in `files_transaction_prepare()`
- Adds new test cases in t/t1400-update-ref.sh and t/t5510-fetch.sh
- Recommends reftable backend as long-term solution
- Maintains backward compatibility while improving error reporting

The patch builds on previous discussion (v1/v2) with refinements to error handling and test coverage, particularly around lock file edge cases. It represents a middle ground between the pre-2.51 silent overwrite and post-2.51 total failure behaviors, allowing non-conflicting updates to proceed while properly reporting conflicts.
