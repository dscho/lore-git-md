This is a bugfix patch addressing case-insensitive filesystem issues in Git's batched reference updates. It's the first of four patches in a series that improves how Git handles reference name collisions on systems like macOS and Windows.

The patch fixes a regression introduced in Git 2.51 where batched reference updates would completely fail when encountering case conflicts (like refs/heads/Foo vs refs/heads/foo) on case-insensitive filesystems. Previously, such updates would silently overwrite each other, while now they fail the entire batch operation. The patch makes three key changes:

1. Introduces a new `REF_TRANSACTION_ERROR_CASE_CONFLICT` error type to distinguish case conflicts from other errors
2. Modifies `lock_raw_ref()` to properly detect and report case conflicts during batched updates
3. Adds user-friendly warnings recommending migration to the reftable backend which doesn't have these limitations

The solution allows partial updates to succeed while rejecting only the conflicting references, rather than failing the entire batch. Tests demonstrate the behavior on both case-sensitive and case-insensitive filesystems, with special handling for `git fetch`, `git receive-pack`, and `git update-ref --batch-updates`.
