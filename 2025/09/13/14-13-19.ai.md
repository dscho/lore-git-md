This is the second patch in a series extending `--ignore-other-worktrees` support from `git checkout` to `git rebase`. The patch adds the option to bypass Git's safety check that prevent rebasing a branch that's checked out in another worktree.

The technical changes include:
- Adding `--ignore-other-worktrees` documentation to `git-rebase.adoc`
- Introducing a new `ignore_other_worktrees` flag in `struct rebase_options`
- Modifying the rebase command to check this flag before calling `die_if_checked_out()`
- Adding a test case in t/t3400-rebase.sh that verifies the option works as expected

The implementation follows the same pattern as the checkout command, defaulting to the safe behavior (failing if the branch is checked out elsewhere) unless explicitly overridden. The test demonstrates both the default failure case and successful override with the new flag.

This continues the series' goal of providing migration support for users accustomed to older worktree behavior, now extending it to rebase operations. The changes are straightforward and maintain backward compatibility while adding the new functionality.
