This is a refinement to the alias-shadowing functionality in the command deprecation framework series. Jeff King responds to Kristoffer Haugsbakk's suggestion about moving alias tracking logic into `handle_alias()` by proposing two alternative implementations that further improve the error reporting for recursive aliases.

The first suggestion moves the `string_list_append()` call earlier in `handle_alias()` and changes the lookup to check `new_argv[0]` instead of `args->v[0]`. This maintains the same loop detection but changes when commands are added to the tracking list.

The second suggestion goes further by removing the special-case recursive alias check entirely and enhancing the loop detection output to better indicate when a command references itself. The proposed output would show both the start and end of the loop more clearly with `==>` markers.

Key technical points:
- Modifies the alias expansion tracking in `git.c`
- Affects how recursive aliases are detected and reported
- Changes error message format to be more explicit about loop structure
- Maintains all existing functionality while potentially improving user feedback

This appears to be a final polish on the already-approved alias shadowing implementation, addressing edge cases in the error reporting. The changes are focused and well-motivated, building on the comprehensive recursion handling that was previously validated by the maintainers.
