This is a review comment on the first patch in Gabriel Scherer's worktree safety check series. Kristoffer Haugsbakk raises several points about the implementation and user experience:

First, they note an unexpected interaction where the new branch-in-use advice doesn't appear when using a `co` alias, though other advice messages do work with aliases. This stems from how aliases execute as subprocesses using the system Git rather than the development version being tested.

The review then critiques the commit message structure, suggesting it should follow the standard "present tense for current behavior, imperative for changes" format from SubmittingPatches. They also proposes the message could better motivate why these particular options (--detach and --ignore-other-worktrees) are being suggested.

On the implementation, the reviewer confirms the documentation additions follow style guidelines but points out the advice.c enum insertion appears out of alphabetical order. They also question whether "--detach" is the right term to use in the advice message, since it doesn't truly avoid the restriction but rather changes the checkout mode.

The technical discussion remains focused on polish rather than fundamental issues - sort order, commit message style, and advice wording. No changes to core functionality are suggested. The review doesn't block the series but offers opportunities to improve clarity and consistency before final acceptance.
