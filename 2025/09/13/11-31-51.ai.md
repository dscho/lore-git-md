Bugfix for gitk's handling of deleted remote tracking branches. This patch addresses a specific edge case where gitk would error out and fail to open the "Tags and Heads" view after a remote tracking branch is deleted.

The issue occurs because gitk maintains two parallel data structures: `headids` (which tracks branch heads) and `upstreamofref` (which tracks remote tracking relationships). When a remote branch is deleted (e.g., via `git push --delete`), the corresponding `headids` entry is removed but `upstreamofref` may still reference it. The current code doesn't check for this case before trying to access the deleted branch's headid.

The fix adds a check for the existence of `headids($upstreamofref($n))` before attempting to use it in the `refill_reflist` function. This prevents the error and allows the Tags and Heads view to open normally. The patch includes a detailed reproduction recipe showing how to trigger the bug by creating a test repository with a remote tracking branch and then deleting it.
