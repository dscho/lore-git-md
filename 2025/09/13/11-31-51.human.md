Bugfix for gitk's handling of deleted remote tracking branches. 

This patch fixes an error that occurs in gitk when a remote tracking branch is deleted (e.g. via `git push --delete`). The issue arises because gitk's headids array removes the entry for the deleted branch, but the upstreamofref variable may still reference it, causing gitk to error out and preventing the Tags and Heads view from opening.

Michael Rappazzo provides a clear reproduction case showing how to trigger the bug by creating a test repository with a remote tracking branch and then deleting it. The fix is straightforward - it adds a check to verify the headids entry exists before trying to access it in the refill_reflist function.

The patch is small (4 lines changed) and focused, with a good commit message that explains both the problem and solution. This appears to be a solid fix for a real usability issue in gitk that would affect users who regularly delete remote branches.
