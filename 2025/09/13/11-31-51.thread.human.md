This thread addresses a bug in gitk (Git's graphical history viewer) where deleting a remote tracking branch could prevent access to the "Tags and Heads" view. The issue stems from inconsistent state between gitk's internal data structures tracking branch heads (`headids`) and remote relationships (`upstreamofref`).

Michael Rappazzo originally identified and fixed the problem with a minimal 4-line change that adds proper existence checks before accessing potentially stale references. Johannes Schindelin (gitk's maintainer) submitted the patch to the list. Johannes Sixt, another long-time gitk contributor, has now reviewed and approved the change, stating it looks reasonable and has been queued for inclusion.

The fix is straightforward and uncontroversial - it simply adds the missing safety checks that prevent gitk from erroring when a deleted remote branch is referenced. With the maintainer's submission and another contributor's approval, this small but useful fix appears ready to be merged, ensuring gitk remains stable when users clean up remote branches.
