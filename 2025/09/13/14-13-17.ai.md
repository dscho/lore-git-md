This is a feature patch series addressing worktree behavior, specifically around the `--ignore-other-worktrees` option. The series comes from a new contributor and aims to improve the migration path for users accustomed to the older 'workdir' script behavior.

The core issue is Git's current safety check that prevents checking out or rebasing branches already checked out in other worktrees. While this prevents accidental index changes across worktrees, the author argues it creates mental overhead for users who want more independence between worktrees. The series builds on the existing `--ignore-other-worktrees` option (currently only in `checkout`) by:

1. Adding helpful hints when operations fail due to other worktree usage, suggesting `--detach` or `--ignore-other-worktrees` as alternatives
2. Extending `--ignore-other-worktrees` support to `rebase` operations
3. Laying groundwork for a potential future `branch.ignoreOtherWorktrees` config option

The changes touch advice infrastructure, checkout/rebase implementations, and related documentation. Test coverage appears in t/t3400-rebase.sh. The author notes this is their first Git contribution and welcomes beginner-level feedback, suggesting reviewers may need to pay extra attention to project conventions.

Key technical points for future reference:
- New advice message: `ADVICE_IGNORED_OTHER_WORKTREES`
- `branch_checked_out()` gains `ignore_current_worktree` parameter
- Rebase learns to respect `--ignore-other-worktrees` like checkout does
- Documentation updates cover the new rebase option and advice hint
