This patch addresses file/directory (F/D) conflict detection on case-insensitive filesystems in the files backend. It's part of a series fixing batched reference update issues, specifically handling the scenario where references like 'refs/heads/foo' and 'refs/heads/Foo/bar' would conflict on such systems.

The key change modifies `refs/files-backend.c` to lowercase reference names during conflict checking when on a case-insensitive filesystem, ensuring F/D conflicts are properly detected. The patch introduces a new `STRING_LIST_INIT_DUP` initialization for the refnames list to properly handle the lowercased strings, and adds a test case in t/t5510-fetch.sh that verifies the behavior.

The implementation avoids leaking files-backend specifics into the shared `refs_verify_refnames_available()` function by handling the case-insensitive transformation locally. This maintains backend abstraction while solving the immediate problem. The test demonstrates that conflicting updates now properly fail while non-conflicting references remain unaffected.

This is a well-contained change that builds on the thread's established approach of distinguishing between different conflict types (now adding F/D conflicts to the existing case collision handling). The test coverage is thorough, including both the error case and verification that existing references remain intact. The patch maintains the series' principle of failing only the conflicting parts of batched operations while allowing valid updates to proceed.
