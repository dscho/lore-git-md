This is a review comment on the first patch in Gabriel Scherer's worktree safety check series. Kristoffer Haugsbakk raises several points about the implementation and documentation:

First, they note an unexpected behavior where Git aliases don't show the new advice message (though other advice messages do work with aliases). This appears to be because aliases execute via the system Git binary rather than the development version where the new advice was added.

The review then provides detailed feedback on the patch's commit message style, suggesting it should use present tense for current behavior and imperative for changes. They also propose the message could better motivate why these particular options (--detach and --ignore-other-worktrees) are being suggested.

Several technical observations are made about the implementation:
- The advice documentation maintains proper sort order and style consistency
- The advice insertion point in advice.c may be out of alphabetical order
- The wording of the --detach suggestion might be technically misleading
- The patch series does handle rebase (contrary to initial impression from the commit message)

The review is thorough and constructive, focusing on documentation clarity and implementation details while acknowledging the overall quality of the work. It doesn't challenge the fundamental approach but suggests refinements to make the behavior and intent clearer to end users.
