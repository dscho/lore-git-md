This is part 2 of a 4-part bugfix series addressing batched reference updates on case-insensitive filesystems. The patch focuses on improving error handling when reference locks already exist during fetch operations.

The change modifies `lock_raw_ref()` to properly distinguish between different types of conflicts. Previously, it would either report a case conflict (on case-insensitive systems) or a generic error for all other cases. Now it introduces `REF_TRANSACTION_ERROR_CREATE_EXISTS` for pre-existing reference locks, allowing batched updates to fail only the conflicting reference while processing others successfully.

The patch includes a new test case that verifies this behavior by simulating a fetch operation where one reference has an existing lock file. The test confirms that while the locked reference fails to update, other references in the batch still succeed. This maintains the partial-update behavior that was broken in Git 2.51.

This iteration shows careful attention to edge cases, with clear commit message explaining the change and thorough test coverage. The change is part of a well-reviewed series that has evolved through multiple versions to handle various filesystem edge cases around case sensitivity.
