This is a follow-up in the mergetool environment variables discussion thread. Randall Becker is seeking clarification about how custom mergetools access the BASE, LOCAL, REMOTE, and MERGED variables.

The email builds on Johannes Sixt's earlier explanation that these are shell variables rather than environment variables. Randall attempts to reconstruct Git's mergetool implementation logic, suggesting that since the variables aren't exported, custom mergetools outside Git's built-in set wouldn't have access to them. He proposes this forces custom tools to work around the limitation by parsing working directory filenames instead.

The core question remains whether the documentation accurately reflects the behavior for custom mergetools. Randall's analysis implies there may be a functional difference between built-in mergetools (which can access the shell variables) and custom ones (which may not). The thread appears to be moving toward either a documentation clarification or possibly a code change to make the behavior more transparent.
