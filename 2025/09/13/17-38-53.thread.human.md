This thread reports a security-related bug where Git's `safe.directory` feature fails to work as documented when cloning shared repositories. The user describes a scenario where a bare repository with group permissions (owned by root:git) triggers Git's "dubious ownership" protection despite having configured the path in `safe.directory` both globally and via command-line options. The issue persists across Git 2.39.5 and 2.51.0, suggesting either a long-standing bug or an undocumented behavior change in the security mechanism.

The reporter has tried multiple workarounds - including the wildcard `*` setting - without success, indicating this may affect legitimate shared repository workflows. They're seeking either a fix for the `safe.directory` mechanism or information about when the security check was introduced to consider downgrading. The detailed reproduction steps and environment information make this a well-documented bug report that should be investigated by maintainers familiar with Git's ownership security model.
