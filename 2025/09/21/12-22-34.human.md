**Bugfix and refactoring patch addressing curl type safety in HTTP interactions**

This is the first of a 3-part series fixing a type mismatch issue in Git's curl integration that causes CI failures on ARM64 Windows builds. The immediate problem stems from libcurl expecting a `long` for `CURLOPT_INFILESIZE` while receiving an incompatible type, caught by clang.

The patch moves and renames a helper function (`xcurl_off_t` to `cast_size_t_to_curl_off_t`) from `remote-curl.c` to the more central `http.h`, making it reusable across the codebase. The function safely validates that a `size_t` value fits within `curl_off_t` before casting. While the relocation improves code organization, it comes with a minor tradeoff - the error message can't be localized via `_()` at this stage of compilation.

The changes are cleanly focused, touching only two files (http.h and remote-curl.c) with straightforward modifications. The commit message provides clear rationale for both the technical change and naming convention alignment with Git's existing type-casting helpers. This appears to be a well-considered fix that follows Git's practice of improving surrounding code when addressing issues.
