This is a refactoring patch in the xdiff preparation series, now merged to 'next', that touches on namespace concerns in the diff algorithm internals.

Junio C Hamano raises a concern about patch 10/10's introduction of generic `YES/NO/MAYBE` macros in xdiff.h, which could pollute the namespace of other files that include this header. While these macros are meant specifically for the `xdfile_t.rchg` enum-like usage within xdiff, their overly generic names risk conflicting with other parts of Git's codebase that might use similar names for different purposes.

The concern comes after the preparatory series (patches 1-10) has already been merged, suggesting this is a retrospective observation rather than a blocking issue. Junio notes that while xdiff headers have historically maintained good namespace isolation through distinctive naming conventions (xdsomething/s_xsomething), these new macros break that pattern with their extremely common names.

This appears to be a minor but valid architectural concern about header file hygiene, though it doesn't affect the functionality changes that were the main focus of the preparatory series. The discussion may influence future work on the Rust-specific follow-up patches (11-17) regarding how type definitions are exposed.
