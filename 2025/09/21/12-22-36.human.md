Bugfix completing a 3-part series addressing curl type mismatches in Git for Windows ARM64 builds. This final patch fixes a compilation error in `http-push.c` where `CURLOPT_INFILESIZE` was being passed a `size_t` instead of the expected `long` parameter.

The error surfaced after a cURL update in Git for Windows' ARM64 builds, specifically with LLVM-based compilers. Rather than just casting the type (which would silence the warning), the patch properly switches to using `CURLOPT_INFILESIZE_LARGE` - a more appropriate option that was already available in cURL since version 7.11.0 and is used elsewhere in Git's codebase.

This change leverages the new `cast_size_t_to_curl_off_t()` helper function introduced earlier in the series, maintaining consistency with the type safety improvements made to the IMAP subsystem in patch 2. The fix is clean and follows the established pattern of using cURL's large file size support where applicable.

The series as a whole demonstrates careful attention to both fixing the immediate issue and improving type safety across multiple subsystems that interact with cURL. The commit message provides clear context about why this is better than a simple cast, referencing both the cURL API history and the series' architectural decisions.
