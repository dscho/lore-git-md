This is a technical follow-up in the Rust adoption thread, specifically addressing cross-compilation possibilities for NonStop platforms. Ezekiel Newren probes further into Randall Becker's earlier confirmation about cross-compiler limitations, asking why Git couldn't be compiled on Windows and then transferred to NonStop machines rather than running natively.

The email highlights two key technical constraints: the proprietary licensing requirement for the only available Windows-to-NonStop cross-compiler (C99 version), and the incompatibility of standard configure processes with this Windows-based compilation approach. Newren's question suggests exploring a workaround where Git would run on Windows while serving NonStop targets, though this appears to conflict with Git's typical usage patterns where it runs directly on the target system.

This exchange represents the final technical clarification in the thread, effectively closing the door on cross-compilation solutions after Becker's definitive response about licensing and configuration barriers. The discussion now clearly shifts from technical feasibility to project policy decisions about how to handle Rust adoption given these immutable platform constraints.
