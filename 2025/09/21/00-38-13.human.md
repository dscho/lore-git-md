Ezekiel Newren responds to Junio C Hamano's concern about the generic NO/YES/MAYBE macro names potentially polluting the namespace when included via xdiff headers. He proposes two alternative approaches: (1) moving the macros into xprepare.c (making them private to the xdiff implementation) while changing the underlying type from `char` to `bool`, or (2) keeping the current approach but having xdiff.h include compat/posix.h to properly support bool types.

The discussion reveals an interesting compatibility wrinkle - Git's header inclusion history with stdbool.h has been inconsistent, which complicates using proper boolean types. Newren notes that without bool, the eventual Rust port would need to use numeric comparisons (like `!= 0`) which would obscure the boolean intent of these values.
