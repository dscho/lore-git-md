Refactoring follow-up in the xdiff Rust compatibility series. This is a response to Phillip Wood's question about the apparent inconsistency between removing `xdl_get_rec()` in patch 4/10 while adding `get_hash()` in patch 6/10 of the now-merged preparatory cleanups.

Ezekiel Newren explains the distinction: `xdl_get_rec()` was removed because it merely performed trivial array indexing (`xdf->recs[ri]` access) that didn't justify a helper function. By contrast, `get_hash()` serves as temporary scaffolding during the refactoring process - it abstracts the more complex relationship between `xdf->ha` (a sparse copy of hash values) and `xdf->recs[]` (the original records), which will undergo further changes. The function also helps manage confusion around the dual-purpose use of `xrecord_t.ha` (first as line hashes, later as minimal perfect hashes).

Newren references two prior emails (linked) that provide additional context about the planned struct reorganization and the rationale for incremental changes. The response clarifies that while both patches deal with accessor functions, they serve different purposes in the refactoring sequence - one removed as unnecessary indirection, the other added as transitional scaffolding for more complex changes to come. This maintains the series' goal of simplifying xdiff internals for eventual Rust compatibility while minimizing churn.
