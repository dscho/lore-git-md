This is a bugfix series addressing a curl_easy_setopt() type mismatch that started causing CI failures in Git for Windows' ARM64 builds. The issue stems from a libcurl update where a parameter expected as `long` was being passed incorrectly, caught by clang but not GCC.

The series does more than just fix the immediate problem: it introduces a safe casting function for `size_t` to `curl_off_t`, applies this to the problematic http-push case (switching from CURLOPT_INFILESIZE to CURLOPT_INFILESIZE_LARGE), and cleans up a similar unsafe cast in imap-send. The author notes this is part of Git's tradition of improving surrounding code when fixing issues.

Key technical details: The changes span http-push.c, imap-send.c, http.h and remote-curl.c, introducing a new safe casting helper in http.h. The fix applies cleanly back to v2.22, though testing older versions would be difficult. The author finds it surprising the more correct CURLOPT_INFILESIZE_LARGE wasn't used originally, as it predates Git's existence.

This appears to be a well-motivated series addressing a real build breakage while improving type safety in related curl interactions. The changes are focused and the commit message provides good historical context about the curl API choices. The patch series is small (3 patches) and touches limited, related areas of the codebase.
