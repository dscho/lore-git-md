This is the second patch in a bugfix series addressing type mismatches in curl interactions, specifically for Git for Windows ARM64 builds. The patch focuses on `imap-send.c`, where a `size_t` to `curl_off_t` cast could theoretically truncate values (though the commit notes this is currently uncommon).

The change replaces a direct cast with the new `cast_size_t_to_curl_off_t()` helper introduced in patch 1, ensuring proper bounds checking when setting the message size for IMAP operations. This matches the series' broader goal of improving type safety around libcurl API calls.

The patch is straightforward - a one-line change with clear justification in the commit message. It's part of a well-motivated series that's cleaning up technical debt in curl interactions, with each commit handling a different subsystem (this one follows the http-push.c fix from patch 1). The changes are surgical and maintainable, though reviewers might want to verify the helper function's safety guarantees apply equally well to IMAP as they did to HTTP.
