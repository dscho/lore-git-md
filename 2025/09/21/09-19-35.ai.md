This is a technical discussion about the final loose end in the xdiff refactoring series - specifically how to handle the NO/YES/MAYBE macros introduced in patch 10/10 for tracking xdfile_t.rchg state while maintaining Rust compatibility.

Phillip Wood responds to Ezekiel Newren's proposal about two possible solutions for the macro namespace pollution issue. He supports the first option of moving the macros to xprepare.c and changing `rchg` to `bool changed`, noting this would prevent misuse of MAYBE outside xprepare.c. He clarifies that including stdbool.h via compat/posix.h is already properly set up in git-compat-util.h since commit 75a044f748f, so there should be no technical barrier to using bool.

The email provides important context about Git's header inclusion chain that resolves one of Newren's concerns about bool availability. This moves the discussion forward by confirming one proposed solution is viable from a build system perspective, while still leaving open the question of whether to pursue this path versus having xdiff.h include compat/posix.h directly. The exchange remains focused on the technical merits of each approach and their implications for Rust integration.
