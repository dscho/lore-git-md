Johannes Schindelin (Dscho) has completed a bugfix series addressing type mismatches in Git's curl interactions that were causing CI failures in Git for Windows ARM64 builds. The issue stemmed from libcurl expecting a `long` type for CURLOPT_INFILESIZE while receiving incorrect types, caught by clang in ARM64 builds. The three-patch series introduces consistent type handling across HTTP and IMAP subsystems.

The first two patches, covering HTTP helper functions and IMAP operations, were acked by maintainer Junio C Hamano with minor documentation clarifications requested. The final patch, applying the same fixes to HTTP push operations, has now also received Junio's approval. All patches use the newly introduced `cast_size_t_to_curl_off_t()` helper function and replace CURLOPT_INFILESIZE with CURLOPT_INFILESIZE_LARGE where appropriate. While the issue was caught on ARM64, the fixes provide platform-agnostic improvements to curl interaction code.

With all three patches now reviewed and approved, the series is ready for integration into Git's main codebase. This concludes the cross-subsystem effort to ensure type safety when working with libcurl's file size options, preventing similar issues from arising in future builds.
