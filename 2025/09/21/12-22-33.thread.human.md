Johannes Schindelin (Dscho) has sent a 3-patch series fixing curl type mismatches that were causing compilation failures in Git for Windows ARM64 builds. The issue stems from libcurl expecting a `long` for `CURLOPT_INFILESIZE` while Git was passing a `size_t`, caught by clang's stricter type checking.

The series takes a comprehensive approach: patch 1 introduces a new helper function `cast_size_t_to_curl_off_t()` with proper bounds checking, patch 2 applies this to the IMAP subsystem, and the just-added patch 3 completes the work by fixing the HTTP push case. The solution uses `CURLOPT_INFILESIZE_LARGE` which was available all along but not previously used, and maintains consistency across both HTTP and IMAP code paths.

Dscho's patches follow Git's tradition of improving surrounding code while fixing issues, with clear commit messages that provide historical context about curl API choices. The changes are minimal but thorough, addressing both the immediate ARM64 build failure and improving type safety more generally. The series appears complete and well-researched, though it hasn't yet received review feedback from others on the list.
