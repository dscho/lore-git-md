This is a follow-up response in the ongoing xdiff refactoring thread, specifically addressing Phillip Wood's question about the removal of `xdl_get_rec()` in patch 4/10 versus the introduction of a new getter function in patch 6/10.

Ezekiel Newren explains that while both patches deal with getter functions, they serve different purposes. The removed `xdl_get_rec()` was a trivial array index operation that didn't justify its own function, while the new `get_hash()` function in patch 6/10 serves as temporary scaffolding to reduce refactoring churn. He notes that `get_hash()` handles more complex logic around the `ha` field (which stores line hashes that later get repurposed) and will undergo several changes before eventually being removed. The response includes code snippets showing the simplicity of the removed function versus the more involved hash access logic in the new one.

This email provides useful context for the earlier refactoring decisions, though it doesn't directly address Wood's other post-merge questions about patches 5/10, 7/10 and 9/10. The explanation seems technically sound, showing thoughtful consideration of when helper functions add versus detract from code clarity during a transitional refactoring phase.
