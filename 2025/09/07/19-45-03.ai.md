This is a refactoring series with two distinct parts, aiming to prepare xdiff internals for potential Rust integration by adopting Rust-style type conventions without actually introducing Rust code. The series comes with a clear split between uncontroversial cleanups and more substantial type changes.

The first 9 patches perform cleanup work on xdiff's data structures (xrecord_t and xdfile_t), removing unused fields and simplifying memory management. These changes are presented as standalone improvements that could be merged independently. The author notes these cleanups make the structs more Rust FFI-friendly by eliminating pointer chains and storage classes that would complicate Rust interop.

Patches 10-17 introduce Rust-inspired type definitions in a new compat/rust_types.h header, then systematically replace C types (long, char*) with Rust-style types (usize, u8, i32) throughout xdiff. The changes include splitting the 'ha' hash field into two distinct purposes (line_hash and minimal_perfect_hash) and adjusting array index types. These changes are more invasive but maintain the same behavior while aligning with Rust's stronger type system.

The series touches core diff algorithms across multiple files (xprepare.c, xdiffi.c, xemit.c etc.), with significant line count reductions (358 deletions vs 293 additions). The author suggests the first part is ready for merging while the second warrants more discussion, positioning this as preparatory work for future Rust integration rather than an immediate Rust adoption.
