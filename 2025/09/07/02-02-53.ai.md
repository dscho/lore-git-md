Bug report/question about `git add` behavior with invalid pathspecs.

Jon Forrest reports unexpected behavior in `git add` when mixing valid and invalid pathspecs. When attempting to add both an existing file ("x") and a non-existent file ("bogus_file"), the command fails entirely with "fatal: pathspec 'bogus_file' did not match any files" and doesn't stage the valid file either. The same occurs with multiple valid files followed by one invalid one.

The email questions whether this all-or-nothing behavior is intentional. The report suggests this might be surprising since one might expect the valid files to be staged while only the invalid ones are rejected. The behavior is observed on Git 2.50 running on Fedora 6.16.4-200.fc42.x86_64.

This appears to be a long-standing behavior that may or may not be considered a bug - the email doesn't indicate whether this differs from historical behavior or if there's prior discussion about it. The question seems aimed at understanding design intent rather than proposing a specific change.
