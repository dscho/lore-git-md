This is the third patch in a 4-part refactoring series addressing sign comparison warnings in the string-list API. The patch changes `string_list_find_insert_index()` to return `size_t` instead of `int`, completing the transition started in earlier patches to eliminate signed/unsigned comparison warnings.

The key changes are:
- Updates the function signature in both declaration and implementation to return `size_t`
- Modifies all callers to use `size_t` variables for storing the return value
- Fixes a subtle loop condition in `mailmap.c` to properly handle `size_t` underflow
- Removes the now-unneeded `DISABLE_SIGN_COMPARE_WARNINGS` from `mailmap.c`

This builds on patch 2's introduction of an `exact_match` boolean parameter, allowing the function to return a pure index value without needing negative returns for signaling. The changes are mechanical but require careful handling of the unsigned`size_t` type, particularly in the mailmap loop where the previous `0 <= --i` condition could underflow.

The patch affects several files (`add-interactive.c`, `mailmap.c`, `refs.c`, `string-list.[ch]`) but maintains the same behavior - it's purely a type safety improvement. With this change, the API is now properly typed for its index-returning purpose, setting up the final patch which will enable sign comparison warnings for refs. The series shows careful, incremental refactoring with each patch building logically on the last.
