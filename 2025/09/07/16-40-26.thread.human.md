This thread discusses a proposed change to the string-list API that would make the `exact_match` parameter optional in `get_entry_index()`. The original patch from shejialuo aimed to reduce boilerplate for callers that only need the index position by allowing NULL to be passed for this parameter, adding NULL checks in the implementation.

Junio C Hamano has raised concerns about the tradeoffs involved, questioning whether the small reduction in caller code justifies the added conditional logic in the implementation. While not rejecting the change outright, he suggests the current approach may be preferable for its simplicity, noting that avoiding a single throw-away variable in callers may not be worth the added complexity.

The discussion highlights a common API design question in C - whether to optimize for caller convenience or implementation clarity. This feedback may influence the direction of the remaining patches in what appears to be a 4-part series on string-list API improvements. The change itself remains small and well-contained to `string-list.c`, but the conversation could shape how the series evolves.
