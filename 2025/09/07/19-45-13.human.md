This is part 10 of a 17-patch series refactoring xdiff internals for Rust compatibility, now shifting focus to type definitions. The patch introduces a new header file `compat/rust_types.h` that defines Rust-style primitive types (u8, i32, f64, etc.) as C typedefs, establishing a common vocabulary for future Rust interop.

The commit message makes a strong case for standardizing on Rust's type names in C code, citing benefits like cross-language consistency, clearer intent signaling, and avoiding C's type ambiguities. It specifically argues against using Rust's `c_*` types (like `c_char`) on the Rust side, preferring pure Rust primitives throughout. The actual changes are straightforward - the new header provides typedefs matching Rust's integer, float, and pointer types, plus a `rust_char` for Rust's 32-bit Unicode characters.

This marks a transition point in the series from internal xdiff cleanups to Rust-specific preparations. While mechanically simple, the change has architectural significance by defining how C and Rust will communicate types at their boundary. The approach appears well-considered, with clear rationale for each choice, though it may invite discussion about whether Rust's type names should permeate C code to this degree.
