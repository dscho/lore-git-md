This is a discussion about the proposal to make blobless clones the default behavior in Git. Ben Knoble pushes back against the idea, arguing that having the complete repository available offline is a key advantage of distributed version control. While acknowledging that some users might prefer reduced downloads, he strongly disagrees with making this the default behavior system-wide.

Knoble suggests that users who want blobless clones by default should configure it locally rather than imposing it on everyone. He notes that in his workflow (and for many others), having full history available immediately is valuable for history exploration. The email also touches on the broader philosophy of Git as a distributed system where any clone can function independently of the network.
