Makefile infrastructure patch in Rust transition series. This is a technical review of the Makefile integration for Rust support, part of Patrick Steinhardt's larger Rust infrastructure series (v2 2/7). SZEDER Gábor identifies two specific problems with the current implementation:

1. The `$(RUST_LIB)` target uses `FORCE` rather than properly declaring its dependencies, which could lead to unnecessary rebuilds. This is a common Makefile anti-pattern that should be fixed for correctness.

2. More critically, the cargo build error handling is broken in two ways:
   - Build failures don't propagate to make (exit code is swallowed)
   - Error messages appear before the command that generated them, violating the standard make output ordering

The review demonstrates this with a concrete test case showing how a syntax error in Rust code fails to stop the build and produces confusing output ordering. These are legitimate technical issues that need addressing before the Makefile changes can be considered production-ready.

This feedback comes amidst broader discussion about the Rust transition's build system integration, where proper error handling and dependency tracking are particularly important given the mixed C/Rust build environment. The issues raised don't challenge the overall approach but identify specific technical shortcomings in the current implementation that would affect developer experience and build reliability.
