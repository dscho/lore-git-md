Summary of git add pathspec behavior discussion:

Jon Forrest reports unexpected behavior in `git add` where mixing valid and invalid pathspecs causes the command to fail entirely rather than staging the valid files. The specific case shows that when attempting to add both an existing file ("x") and non-existent file ("bogus_file"), Git fails with "fatal: pathspec 'bogus_file' did not match any files" without staging the valid file. This behavior occurs on Git 2.50 (Fedora 6.16.4-200.fc42.x86_64) and appears consistent across multiple valid files followed by an invalid one.

The core question is whether this all-or-nothing behavior is intentional design or potentially surprising/unintended. The report suggests users might expect valid files to be staged while only invalid pathspecs are rejected. No prior discussion or historical context is provided about this specific behavior. The inquiry seeks to clarify whether this represents the intended design or merits reconsideration.
