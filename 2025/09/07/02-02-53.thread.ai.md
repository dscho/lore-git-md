The thread examines Git's `git add` behavior when given mixed valid and invalid pathspecs, where current implementation fails completely rather than staging valid files. Jon Forrest initially reported this as unexpected behavior, with K Jayatheerth confirming it's intentional via PATHSPEC_PREFER_FULL flag usage in builtin/add.c. Jeff King provided historical context showing this design dates to 2006 Git versions and even earlier in cogito (where partial success was considered a bug). Key technical aspects include: hardcoded pathspec processing in add.c, die_if_path_beyond_symlink() checks, and the PATHSPEC_PREFER_FULL flag. Core considerations are Git's conservative philosophy favoring unambiguous failures over partial success, technical challenges with exit code signaling for mixed states, and backward compatibility concerns.

Jon Forrest has proposed an optional command-line flag to control behavior - maintaining the current strict failure mode by default while allowing an opt-in "ignore invalid files" mode. This suggestion addresses backward compatibility while providing a path forward for users wanting lenient behavior. The proposal remains conceptual without implementation details, focusing discussion on whether such an approach would be acceptable. Technical considerations still center on PATHSPEC_PREFER_FULL flag behavior and exit code semantics, with the new dimension being the flag-based opt-in mechanism. The thread remains exploratory with no consensus yet on changing behavior versus maintaining status quo. Participants include Jon Forrest (reporter and proposal author), K Jayatheerth (implementation confirm), and Jeff King (historical analysis).
