The thread examines Git's `git add` behavior when given mixed valid and invalid pathspecs, where current implementation fails completely rather than staging valid files. Jon Forrest initially reported this as unexpected behavior, with K Jayatheerth confirming it's intentional via PATHSPEC_PREFER_FULL flag usage in builtin/add.c. Jeff King provided historical context showing this design dates to 2006 Git versions and even earlier in cogito (where partial success was considered a bug). Key technical aspects include: hardcoded pathspec processing in add.c, die_if_path_beyond_symlink() checks, and the PATHSPEC_PREFER_FULL flag. Core considerations are Git's conservative philosophy favoring unambiguous failures over partial success, technical challenges with exit code signaling for mixed states, and backward compatibility concerns. While the behavior matches original design intent, the thread remains open for discussion about whether modern use cases warrant reconsideration. No concrete proposals for change have been made, but the historical analysis provides context for evaluating potential alternatives. Participants so far include Jon Forrest (reporter), K Jayatheerth (implementation confirm), and Jeff King (historical analysis).
