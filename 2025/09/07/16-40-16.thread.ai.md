This thread documents a completed 4-patch series refactoring the string-list API to eliminate sign comparison warnings, with particular attention to `string_list_find_insert_index()`. The final version completes the type safety transition by converting `exact_match` parameter to `bool*`, consolidating patches with improved commit messages, changing `string_list_find_insert_index()` return type to `size_t`, removing `DISABLE_SIGN_COMPARE_WARNINGS` from `refs.c`, and converting remaining loop iterators to `size_t` in `run_transaction_hook()` and `ref_transaction_for_each_queued_update()`. All string-list API functions now consistently use `size_t` for indices and `bool` for flags.

Key technical details include updates to internal helper `get_entry_index()` and its callers, changes to `string_list_has_string()` return type, and fixes for callers in `add-interactive.c`, `mailmap.c`, and `refs.c`. A subtle `mailmap.c` loop condition was fixed to prevent underflow with `size_t`. Sign comparison warning suppression was removed from both `mailmap.c` and `refs.c` while maintaining identical behavior.
