Refactoring patch in the xdiff cleanup series, removing redundant hash array storage. This is patch 6/17 in the series preparing xdiff internals for potential Rust integration.

The patch eliminates `xdfile_t.ha`, a redundant array that duplicated hash values already stored in the individual `xrecord_t` structures. The commit message notes that `xdfile_t.ha[i]` was always equal to `xdfile_t.recs[xdfile_t.rindex[i]]->ha`, making the separate array unnecessary. The changes include:
- Adding a new `get_hash()` helper function to access the hash through the record pointer
- Updating all hash comparisons in `xdl_split()` and `xdl_recs_cmp()` to use the new accessor
- Removing `ha` field allocation and initialization in `xdl_prepare_ctx()`
- Simplifying the cleanup logic in `xdl_cleanup_records()` that previously maintained both arrays
- Removing the field declaration from `xdfile_t` in xtypes.h

The changes maintain the series' pattern of removing unnecessary indirections and redundant data structures while keeping the same diff algorithm. The patch touches 3 files with 21 lines removed and 16 added, continuing the codebase simplification trend seen in earlier patches. No behavior changes are introduced - this is purely an internal cleanup that could make future Rust integration easier by reducing the number of parallel data structures to maintain.
