This is the second patch in a series refactoring the string-list API to eliminate sign comparison warnings. The patch changes how `string_list_find_insert_index()` signals exact matches, replacing the current negative return value encoding with an explicit `exact_match` boolean output parameter.

The current implementation uses negative indices (converted via `-1 - index`) to indicate exact matches, which the patch identifies as problematic for two reasons: it requires callers to understand and decode this convention, and forces the function to return `int` instead of `size_t`, triggering sign comparison warnings. The new version makes the exact match status explicit through the output parameter while returning the raw index directly.

The changes affect several callers across `add-interactive.c`, `mailmap.c`, and `refs.c`, updating them to use the new parameter. The diff shows straightforward conversions where negative index checks become `exact_match` checks, and cases that didn't need the exact match information (like in `refs.c`) can now pass NULL for the parameter. The core change in `string-list.c` simplifies the function to just return the index from `get_entry_index()` while passing through the exact match flag.

This is a clean, focused change that improves API clarity while maintaining backward compatibility. The patch follows logically from the first in the series (which made the exact match parameter optional) and sets up for the subsequent conversion to `size_t` return values in patch 3. The changes are well-contained and the commit message clearly explains the motivation and benefits.
