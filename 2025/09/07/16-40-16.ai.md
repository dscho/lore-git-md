This is a refactoring patch series addressing sign comparison warnings in the string-list API. The changes focus on `string_list_find_insert_index()`, which currently uses negative return values to signal exact matches, triggering compiler warnings about signed/unsigned comparisons.

The series makes several coordinated changes: first allowing NULL to be passed for the index output parameter (patch 1), then replacing the negative return value convention with an explicit `exact_match` boolean parameter (patch 2), and finally changing the function's return type from `int` to `size_t` (patch 3). The final patch (4) enables sign comparison warnings for the refs subsystem to prevent regressions.

The changes touch several files that use this API (`add-interactive.c`, `mailmap.c`, `refs.c`), with the bulk of modifications in `string-list.[ch]`. The approach appears well-considered, replacing an implicit convention (negative values) with explicit parameters, while maintaining backward compatibility through the API changes. The patch series is small (4 patches) and focused, with cleanly separated changes that build logically on each other.
