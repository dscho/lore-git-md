Refactoring patch for the string-list API, part 1 of a series addressing sign comparison warnings. This initial change modifies `get_entry_index()` to make the `exact_match` parameter optional, allowing callers to pass NULL when they only need the index position. The modification is straightforward - it simply adds NULL checks before dereferencing the `exact_match` pointer.

The patch is part of a coordinated series that will ultimately replace the current convention of using negative return values to signal exact matches, which triggers compiler warnings about signed/unsigned comparisons. This first step makes the API more flexible by removing the requirement to always provide an `exact_match` output parameter, which should simplify some calling code that doesn't need this information.

The change is minimal and focused, touching only `string-list.c` with a simple 6-line diff that adds NULL checks around the `exact_match` assignments. The patch maintains backward compatibility while providing more flexibility to callers. This appears to be a clean, well-scoped change that sets up for the subsequent patches in the series which will handle the sign comparison issues more directly.
