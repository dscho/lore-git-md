This is a focused refactoring of the string-list API's index return convention, part 2 of a 4-patch series. The core change modifies `string_list_find_insert_index()` to replace its negative-index encoding for exact matches with a cleaner boolean `exact_match` output parameter. This addresses type-safety concerns with the current `int` vs `size_t` handling while maintaining identical insertion semantics.

The patch updates all callers to the new convention:
- `add-interactive.c` and `mailmap.c` now check the boolean flag directly
- `refs.c` passes NULL when match information isn't needed
- The behavior remains identical to before, just with clearer signaling

The change touches several subsystems but is mechanically straightforward - each caller is updated to use the new interface in a way that preserves the original logic. The commit message clearly explains the motivation around API clarity and type safety. This appears to be a well-scoped improvement to an internal API used by multiple parts of the codebase.
