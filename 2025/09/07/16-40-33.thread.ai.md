This is a focused refactoring of the string-list API's index return convention, part 2 of a 4-patch series. The core change modifies `string_list_find_insert_index()` to replace its negative-index encoding for exact matches with a cleaner boolean `exact_match` output parameter, addressing type-safety concerns with the current `int` vs `size_t` handling.

Junio C Hamano has raised concerns about the justification for this change, arguing that the negative-index encoding is a well-established convention and that the patch's reasoning is backwards. He suggests restructuring the argument to first demonstrate why the full range of `size_t` is needed (currently limited by `int` return type), then show how the negative encoding further restricts usable range, before proposing the boolean parameter solution.

The patch currently updates all callers to the new convention:
- `add-interactive.c` and `mailmap.c` now check the boolean flag directly
- `refs.c` passes NULL when match information isn't needed
- Behavior remains identical to before, just with clearer signaling

The technical approach (adding a boolean parameter) remains uncontested, but its necessity requires clearer demonstration.
