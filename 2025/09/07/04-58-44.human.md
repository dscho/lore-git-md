This is a technical critique of the Rust infrastructure implementation in the ongoing Rust integration series. Elijah Newren points out two key issues with Patrick Steinhardt's Makefile changes in patch 2/7:

First, he argues that using `WITH_RUST` as an opt-in flag (rather than `WITHOUT_RUST` as opt-out) reduces the notice period for distributors about the upcoming mandatory Rust requirement. This aligns with his broader position advocating for immediate Rust-by-default in Git 2.52 rather than the phased approach proposed by Steinhardt.

Second, he questions whether Windows-specific Rust build requirements (previously addressed by Johannes Schindelin's tooling in git-for-windows) are being properly incorporated, suggesting the current implementation might be incomplete for Windows platforms.

The email continues the thread's pattern of technical scrutiny combined with policy debate - here focusing on build system semantics and platform support while maintaining Newren's consistent advocacy for faster Rust adoption. The critique is specific and actionable, identifying concrete implementation choices that could impact both the transition experience and cross-platform compatibility.
