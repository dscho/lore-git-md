Refactoring patch in the xdiff preparation series for Rust compatibility. This is patch 9/17 in Ezekiel Newren's series to clean up xdiff internals ahead of potential Rust integration.

The patch introduces named constants (NO, YES, MAYBE) for the previously magic-numbered values (0, 1, 2) used in the `xdfile_t.rchg` array, which tracks line change states during diff operations. The change makes the code more readable while maintaining identical behavior. The author also floats the idea of renaming `rchg` to `changed` in the commit message, though this isn't implemented in the patch.

This continues the series' pattern of mechanical, non-controversial cleanups that don't modify behavior. The changes touch multiple xdiff algorithm implementations (myers, histogram, patience) but are straightforward replacements. Like previous patches, this reduces cognitive overhead for future work rather than introducing new functionality. The patch appears well-scoped and maintains the series' focus on preparatory changes that could benefit both C and future Rust implementations.
