Refactoring patch in the xdiff cleanup series for Rust compatibility.

This is patch 5/17 in the series preparing xdiff internals for potential Rust integration. It removes the `diffdata_t` struct which was found to be redundant - all its fields were direct copies of fields already present in `xdfile_t`. The patch updates all callers of `xdl_recs_cmp()` to pass `xdfile_t` pointers directly rather than creating temporary `diffdata_t` structs.

Key technical changes:
- Deletes the `diffdata_t` struct definition from xdiffi.h
- Modifies `xdl_recs_cmp()` to take `xdfile_t*` parameters instead of `diffdata_t*`
- Updates all call sites to directly access `xdfile_t` fields (`nreff`, `ha`, `rindex`, `rchg`)
- Simplifies `xdl_do_diff()` by removing the temporary `dd1`/`dd2` struct setup
- Files modified:
  - xdiff/xdiffi.c (32 lines changed)
  - xdiff/xdiffi.h (11 lines changed)
- Net effect: -33 lines of code

The change continues the series' pattern of removing unnecessary indirections and simplifying the codebase without altering behavior. This particular cleanup appears straightforward and low-risk since it's just removing a redundant wrapper struct. The patch maintains the series' focus on preparatory changes that could make future Rust integration easier while keeping current functionality intact.
