This thread examines how `git add` handles cases where some pathspecs are valid while others are invalid. The current behavior fails the entire operation rather than staging the valid files, which Jon Forrest reported as unexpected. K Jayatheerth confirmed this is intentional due to the PATHSPEC_PREFER_FULL flag in the implementation.

Junio C Hamano clarified that `--ignore-errors` only handles permission-related issues (like read-only files) but not pathspec validation failures, maintaining Git's conservative design that prefers unambiguous failures over partial success. Jeff King provided historical context showing this behavior dates back to 2006 and even earlier in cogito, where partial success was considered a bug. In the latest exchange, Jeff agrees with Junio's technical distinction between pathspec validation failures (which abort) versus file access errors (which can be skipped), noting the original issue would require something like a new `--ignore-missing` flag rather than the existing `--ignore-errors`.

The discussion points center on whether to maintain the current strict behavior, better document the limitations, or potentially extend functionality for partial success cases. Key participants include Jon Forrest (reporter), K Jayatheerth (implementation details), Jeff King (historical context), and Junio C Hamano (maintainer perspective).
