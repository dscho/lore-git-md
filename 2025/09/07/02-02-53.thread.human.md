Here's a human-readable summary of the thread so far:

Jon Forrest reported unexpected behavior in `git add` where the command fails completely if any pathspec is invalid, even when other pathspecs match existing files. For example, `git add x bogus_file` fails without staging file "x". This behavior was observed on Git 2.50 and appears consistent across cases with multiple valid files followed by an invalid one.

K Jayatheerth has now clarified that this behavior is intentional, pointing to code in builtin/add.c that implements this design. The code includes comments and uses the PATHSPEC_PREFER_FULL flag in a way that suggests failing on any invalid pathspec is the expected behavior. While this confirms the current implementation matches the intended design, the thread remains open for discussion about whether this behavior should be reconsidered to better match user expectations of partial success when some pathspecs are valid.
