This thread examines how `git add` handles mixed valid and invalid pathspecs, where the current implementation fails completely rather than staging just the valid files. Jon Forrest initially reported this behavior as unexpected, with K Jayatheerth confirming it's intentional due to the PATHSPEC_PREFER_FULL flag in the code. Jeff King provided historical context showing this conservative design dates back to 2006 and even earlier versions.

The discussion initially explored adding a new flag for lenient behavior, but Jon realized the existing `--ignore-errors` option might serve this purpose. However, Jeff has now clarified through concrete examples that `--ignore-errors` doesn't actually change the fundamental behavior - Git still fails completely on invalid pathspecs, though the status output shows valid files remain unstaged. This reveals an important distinction in Git's error handling that wasn't clear from the option name alone.

Key open questions remain about whether to maintain the strict default behavior, how to better document the existing options (especially since `--ignore-errors` doesn't work as one might expect), and why the related `--ignore-missing` functionality is currently limited to dry-run mode. The thread has involved Jon Forrest as the original reporter, K Jayatheerth explaining the implementation details, and Jeff King providing historical context and correcting misconceptions about the options. The focus has shifted from proposing new flags to understanding the boundaries and documentation of Git's existing partial success mechanisms.
