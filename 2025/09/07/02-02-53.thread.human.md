This thread examines whether `git add` should fail completely when given pathspecs containing both valid and invalid paths, or whether it should stage the matching files while ignoring invalid ones. The current behavior—failing entirely—is intentional, dating back to 2006 and even earlier in cogito, as Jeff King's historical analysis showed. The design reflects Git's conservative philosophy, prioritizing unambiguous failures over partial success, with technical considerations around exit code signaling and backward compatibility.

Jon Forrest, who initially reported the behavior as unexpected, has now proposed a compromise: adding an optional flag (e.g., `--ignore-invalid`) that would allow partial success while keeping the strict default behavior. This addresses backward compatibility concerns while providing a path forward for users who prefer leniency. The discussion remains exploratory, with no implementation yet and no clear consensus on whether to change the behavior. Key participants include Jon Forrest (proposing the flag), Jeff King (providing historical context), and K Jayatheerth (confirming the current implementation's intent). The core technical considerations—PATHSPEC_PREFER_FULL, exit code semantics, and the conservative design philosophy—remain unchanged.
