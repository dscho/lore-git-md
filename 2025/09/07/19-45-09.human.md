This is part 6 of a 17-patch series refactoring xdiff internals for Rust compatibility. The patch removes redundant data in the xdiff implementation by eliminating the `xdfile_t.ha` array, which was storing hash values that could already be accessed via `xdfile_t.recs[xdfile_t.rindex[i]]->ha`.

The change introduces a new `get_hash()` helper function to access the hash values through the existing indirection chain, then updates all callers to use this instead of direct array access. The patch touches core diff algorithm functions like `xdl_split()` and `xdl_recs_cmp()`, modifying their signatures to take `xdfile_t` pointers rather than hash arrays.

This continues the series' pattern of removing unnecessary abstractions while maintaining identical behavior. The change reduces memory usage by eliminating a redundant array and simplifies the code by centralizing hash access. Like previous patches in the series, this appears to be a straightforward cleanup with no expected controversy, though reviewers may want to verify the performance impact of the additional indirection in `get_hash()`.
