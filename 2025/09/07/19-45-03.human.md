This is a refactoring series with two distinct parts, aiming to modernize xdiff's internal data structures by adopting Rust-inspired type patterns without actually introducing Rust code. The series comes from Ezekiel Newren as a 17-patch set.

The first 9 patches perform cleanup work on xdiff's core data structures (xrecord_t and xdfile_t), removing unused fields and simplifying memory management. These changes are presented as immediately mergeable improvements that stand on their own merits. The author shows before/after comparisons demonstrating how fields like `next` pointers and hash arrays are eliminated from the structs.

Patches 10-17 introduce a new `compat/rust_types.h` header defining Rust-style primitive types (u8, usize, u64 etc.) and refactor xdiff to use these types. This includes changes like making string pointers explicitly unsigned (u8 instead of char) and using more precise integer types. The author suggests this portion warrants more discussion, likely due to the novelty of adopting Rust's type system conventions in C code.

The series touches nearly all xdiff implementation files with a net reduction of over 100 lines. While the changes are mechanical in nature, they appear carefully considered - each commit message explains the rationale, and the author has maintained diff functionality (including --color-words view). This looks like a serious, well-structured effort to modernize xdiff's internals while sidestepping Rust toolchain debates. The split into independently reviewable parts is particularly thoughtful.
