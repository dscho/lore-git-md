This is a refactoring patch that changes how the `string_list_find_insert_index()` function indicates exact matches were found. Currently, it encodes this by returning negative indices (which callers must decode), but the patch replaces this with an explicit `exact_match` output parameter.

The change addresses two issues: (1) callers shouldn't need to understand the negative-index encoding scheme, and (2) using `int` return values (needed for negatives) causes sign-comparison warnings where `size_t` would be more natural. The patch updates all callers to use the new interface, including in `add-interactive.c`, `mailmap.c`, and `refs.c`. 

The change appears well-motivated and cleanly implemented, with straightforward updates to the handful of callers. This is part of a 4-patch series (position 2/4), though the cover letter wasn't provided in this digest. The change touches core string-list functionality but doesn't introduce new behavior - it makes the existing behavior more transparent to callers.
