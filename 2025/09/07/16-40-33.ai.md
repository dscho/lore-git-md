Refactoring patch to improve string-list API's index return convention.

This is part 2 of a 4-patch series (no cover letter seen) that changes how `string_list_find_insert_index()` indicates exact matches. Currently, exact matches are signaled by returning a negative index (encoded as `-1 - index`), which requires callers to decode and has type-safety issues with `int` vs `size_t`. The patch replaces this with an output `exact_match` parameter while keeping the same insertion index semantics.

The change affects several callers across the codebase (add-interactive, mailmap, refs) that needed to handle the negative index convention. The new version is more direct - callers check the boolean `exact_match` flag rather than decoding negative values. The refs.c caller passes NULL when it doesn't need the match information.

The patch appears well-scoped and mechanically sound - it maintains the same behavior while cleaning up the interface. The commit message clearly explains the motivation around API clarity and type safety. This seems like a straightforward improvement to an internal API that several subsystems rely on. The changes to callers are consistent and the diff shows no obvious oversights in the conversion.
