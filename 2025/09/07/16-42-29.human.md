This is the second patch in a series refactoring the string-list API to eliminate sign comparison warnings. The patch changes how `string_list_find_insert_index()` signals exact matches - instead of encoding them as negative return values (which required callers to decode and caused type warnings), it now uses an explicit `exact_match` output parameter.

The change makes the API more straightforward by removing the need for callers to understand and handle the negative index encoding scheme. It also enables the function to return a `size_t` in future patches (coming in patch 3) since it no longer needs negative values. The patch updates all callers to use the new parameter, including in `add-interactive.c`, `mailmap.c`, and `refs.c`.

The change is well-contained and mechanical - each caller is updated to check the new boolean parameter rather than interpreting negative values. The patch follows logically from the first in the series (which made the exact match parameter optional) and sets up for the subsequent type change. The commit message clearly explains the motivation and benefits of the change.
