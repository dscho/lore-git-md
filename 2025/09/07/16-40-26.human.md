Refactoring patch to make `get_entry_index()` more flexible with NULL parameters.

This is a small but thoughtful change to the string-list API's internal `get_entry_index()` function. Currently callers must pass a non-NULL boolean to track exact matches, even when they only care about the index position. The patch makes the `exact_match` parameter optional by adding NULL checks before writing to it.

The change is cleanly implemented with minimal diff noise (just 4 lines changed) and maintains all existing behavior when callers do want exact match information. This appears to be a genuine quality-of-life improvement for API users who don't need the exact match flag, allowing them to skip declaring unused variables.

As the first in a 4-part series, this seems like a straightforward foundation - the subsequent patches will likely build on this flexibility. The change is low-risk since it only affects internal callers of this helper function.
