This is a policy discussion email in the ongoing Rust infrastructure thread, where Elijah Newren responds to Patrick Steinhardt's concerns about the Rust transition timeline. The exchange focuses on communication strategies and the practical implications of making Rust mandatory.

Newren pushes back against Steinhardt's characterization that there's been "no notice" about Rust becoming mandatory, pointing to multiple public communications beyond the mailing list (release notes, blog posts, news coverage) that signaled Rust's eventual inclusion. He agrees the notice may be inadequate but argues the existing optional Rust components in contrib/ (libgit-rs and libgit-sys) did provide some advance warning, contrary to Steinhardt's dismissal of them.

The discussion highlights a key tension: Steinhardt worries about "pulling the rug" from distributors who may be stuck on older versions if Rust becomes mandatory, while Newren questions why distributors must immediately adopt the latest Git version. Newren suggests the Rust transition is fundamentally different from typical breaking changes since it doesn't affect user workflows, only build requirements.

On security fixes, Newren acknowledges the valid concerns but is skeptical the project can provide detailed answers about backport policies in advance. He suggests the team will likely handle each case based on severity and backport cost, with extra consideration for the last C-only version.

The email advances the thread by clarifying what constitutes adequate notice and challenging assumptions about distributor requirements, while maintaining a constructive tone. It doesn't resolve the timeline debate but helps frame the discussion more precisely around what problems a transition period would actually solve.
