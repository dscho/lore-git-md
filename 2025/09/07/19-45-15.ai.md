This is patch 12/17 in the xdiff refactoring series for Rust compatibility, focusing on type system changes. The patch changes `xrecord_t.ptr` from `char*` to `u8*` (unsigned byte) to better match Rust's type expectations while maintaining the same underlying behavior. The change is mechanical but widespread, requiring pointer casts in 7 files where the pointer is passed to functions expecting `char*` (like string comparison and regex functions).

Key technical details:
- Changes `xrecord_t.ptr` type in `xtypes.h` from `char const*` to `u8 const*`
- Updates all call sites to cast to `(const char*)` when needed for string operations
- Affects core diff operations (xdiffi.c), merge logic (xmerge.c), and utility functions
- Maintains identical runtime behavior while aligning with Rust's stricter type system
- Follows the type definition pattern established in patch 10 (rust_types.h)

The patch continues the series' pattern of mechanical changes that don't modify behavior but prepare for future Rust integration. It touches many of the same files modified in earlier patches (xdiffi.c, xmerge.c, etc.), showing how the type changes propagate through the codebase. The casts are somewhat noisy but localized to interface boundaries where C string functions are called.

This change is likely non-controversial as it doesn't affect functionality, though reviewers may want to verify the casting doesn't introduce any platform-specific issues. It represents another incremental step toward making xdiff data structures compatible with Rust's type system expectations.
