This is a bug report about Git's behavior with dumb HTTP protocol. Milan Hauth reports that while local file-based repository access works fine (with or without the `.git` suffix), the same operations fail over HTTP unless `update-server-info` is run first. The current behavior requires this extra step even for simple read-only operations like `ls-remote`.

The report notes that `update-server-info` creates an optimization file (`info/refs`) that shouldn't be strictly necessary for basic functionality, especially when using HTTP servers that support range requests. The author argues that dumb HTTP remotes should work out of the box like file remotes do, with optimizations being optional.

Two workarounds are mentioned: running `update-server-info` (which the author considers an unnecessary requirement), and using `httpdirfs` (which currently fails for Git repos). The report links to StackOverflow discussions about `update-server-info`'s purpose and private Git repositories over HTTP.

The issue appears to be a long-standing behavior quirk rather than a new regression, and the report makes a reasonable case that the current behavior is unnecessarily restrictive for simple use cases. The suggested change would make Git's HTTP protocol more consistent with its file protocol behavior.
