This thread documents the ongoing effort to refactor Git's xdiff internals to prepare for potential Rust integration. The preparatory cleanups (patches 1-10) have been merged to the 'next' branch, focusing on non-Rust-specific improvements to memory management and type usage while maintaining identical runtime behavior. Key participants include Ezekiel Newren (the series), Phillip Wood (reviewer), and Junio C Hamano (maintainer).

Phillip Wood recently raised several post-merge questions about implementation details. In response to one query about the removal of `xdl_get_rec()` while adding `get_hash()`, Newren explained these represent different refactoring needs - the former was removed as trivial indirection while the latter serves as transitional scaffolding for more complex upcoming changes. The most significant remaining open issue concerns the NO/YES/MAYBE macros introduced for state tracking, with discussion ongoing about their naming and location. Wood has also raised new questions about implementation choices in patches 7/10 and 9/10 regarding struct field access patterns and compiler optimization impacts, which Newren has yet to address. The series maintains a clear separation between the now-merged preparatory work and future Rust-specific type changes (patches 11-17).
