This thread documents a series of preparatory cleanups to Git's xdiff diff algorithm implementation, led by Ezekiel Newren, to make the code more amenable to potential Rust integration. The work has been carefully structured into two phases: first, behavior-preserving refactoring (patches 1-10), followed by Rust-specific changes (patches 11-17) in a future series.

The current v3 iteration of the preparatory series is now complete, with the final patch (10/10) standardizing the previously magic-numbered values in xdiff's `rchg` array (which marks changed lines) with named constants NO/YES/MAYBE. This follows earlier patches that simplified memory management and removed redundant variables. Maintainer Junio C Hamano has confirmed these 10 preparatory patches are ready for merging to the 'next' integration branch.

Performance impact across the series is net neutral - a 5% speedup from removing the chastore_t structure (patch 8) offsets a 5% slowdown from hash array removal (patch 6). The changes touch core diff algorithms but maintain identical behavior, focusing on making the code's intent clearer while keeping the changes minimal. The Rust-specific type changes will be addressed separately in a follow-up series once these foundational cleanups are merged.
