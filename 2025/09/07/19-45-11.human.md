This is patch 8/17 in a refactoring series preparing xdiff internals for Rust compatibility. The patch removes the `chastore_t` type from `xdfile_t`, which was an allocation pool for `xrecord_t` structures. The change eliminates this redundant storage mechanism since the records are already stored in a growable `recs` array.

The patch makes mechanical changes across 8 xdiff source files to update all record access patterns from pointer-to-pointer (`xrecord_t**`) to direct structure access (`xrecord_t*`). This simplifies the code by removing an unnecessary indirection layer while maintaining identical behavior. The changes are widespread but straightforward, touching diff calculation, merge conflict handling, and various diff algorithms (histogram, patience).

This continues the series' pattern of removing unnecessary abstractions in xdiff to make the code more straightforward and Rust-FFI-friendly. The patch removes 69 lines while adding 63, for a net reduction. Like previous patches in the series, this appears to be a well-contained, mechanical change that doesn't affect functionality but makes the code simpler and more direct.
