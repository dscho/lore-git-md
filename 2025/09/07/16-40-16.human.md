This is a refactoring patch series addressing sign comparison warnings in the string-list API. The changes focus on the `string_list_find_insert_index` function, which currently uses negative return values to signal exact matches - a pattern that triggers compiler warnings when comparing signed and unsigned values.

The series makes several coordinated changes: first allowing NULL to be passed for an unused index parameter, then replacing the negative value signaling with an explicit boolean parameter, and finally changing the return type to `size_t` to eliminate the sign comparison issues entirely. The final patch enables sign comparison warnings for the refs subsystem to catch similar issues.

The changes touch several files that use this API (add-interactive, mailmap, refs) but appear to be straightforward mechanical updates rather than behavior changes. The commit messages could benefit from more detailed explanations of the motivation and potential impacts, but the changes themselves look like a clean improvement to the API's type safety.
