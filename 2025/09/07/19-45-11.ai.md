Refactoring patch in the xdiff internals series, continuing the removal of redundant data structures for Rust compatibility. This patch (8/17) eliminates the `chastore_t` from `xdfile_t`, which was used for memory allocation of `xrecord_t` structures. The change makes the code more straightforward by directly using the `recs` array that was already growing to store records, rather than maintaining parallel allocation through the chastore.

The patch affects multiple xdiff implementations (xdiffi, xemit, xhistogram, xmerge, xpatience, xprepare, xtypes, xutils) with mechanical changes to access records directly from the array rather than through pointers. The diff shows 63 insertions and 69 deletions across 8 files, with the main simplification being the removal of the chastore allocation system in favor of direct array access.

Key technical details:
- Removes `xdl_cha_alloc()` calls and `xdf->rcha` field
- Changes record access from `xdf->recs[ri]` to `&xdf->recs[ri]` throughout
- Updates all record pointer types from `xrecord_t**` to `xrecord_t*` where arrays are passed
- Maintains the same record storage but with simpler memory management
- Preserves all existing behavior while removing an indirection layer

This continues the series' pattern of removing unnecessary abstractions while preparing the codebase for potential Rust integration. The change is mechanical and well-contained like previous patches, with no test modifications needed. The series remains focused on preparatory C cleanups before introducing any Rust code.
