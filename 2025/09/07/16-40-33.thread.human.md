This thread discusses a refactoring of the string-list API's index return convention, specifically changing `string_list_find_insert_index()` to use a boolean `exact_match` parameter instead of negative-index encoding for exact matches. The original patch (part 2 of a 4-patch series) argued this improves type safety and clarity, updating callers in `add-interactive.c`, `mailmap.c`, and `refs.c` while preserving behavior.

Junio Hamano has now questioned the justification, noting that negative-index encoding is a well-established convention. He suggests restructuring the argument to first demonstrate why the full `size_t` range is needed (currently limited by the `int` return type), then show how negative encoding further restricts it, before proposing the boolean parameter as a solution. While not rejecting the technical approach outright, he's asking for stronger motivation behind the change. The discussion remains focused on design justification rather than implementation details.
