This is a policy discussion about the Rust transition timeline in Git, specifically addressing Patrick Steinhardt's proposal to make Rust mandatory in Git 3.0. Elijah Newren provides a detailed critique of the plan while acknowledging the importance of announcing the change.

Newren identifies what he sees as contradictions in the current approach - the "test balloon" is not actually testing anything since it silently falls back to C, and the proposed phased rollout doesn't provide meaningful testing periods. He argues the project should instead make Rust the default immediately in Git 2.52 (with opt-out capability) rather than waiting for Git 3.0.

The email contains specific suggestions for improving the BreakingChanges documentation, including more accurate version history (noting Rust was first in contrib in 2.49) and removing the tie to gcc-rs readiness. Newren maintains his position from previous discussions that the transition should be decoupled from the Git 3.0 timeline, potentially accelerating 3.0 to 2.55 if SHA-256 interop isn't affected.

This continues the ongoing debate between three main transition approaches: Steinhardt's phased plan, Phillip Wood's 6-month adoption period, and Newren's immediate default proposal. The technical merits appear settled (as shown by recent approvals of components like the version reporting), but the policy discussion around timing and rollout strategy remains active.
