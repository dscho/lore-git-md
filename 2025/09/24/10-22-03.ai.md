Final refinement in xdiff modernization series: field renaming and documentation suggestion.

This is Phillip Wood's review of patch 11/13 in Ezekiel Newren's completed xdiff refactoring series, which renames the `rchg` field to `changed` in the `xdfile_t` struct. The change itself is mechanical, updating all references across xdiff's diff algorithms (xdiffi.c, xpatience.c, xhistogram.c) and supporting code (xprepare.c, xutils.c, xtypes.h).

Phillip agrees the new name is clearer but suggests the commit message should explain what this field represents - it's a boolean array marking which records (lines) in the diff have changed. This would help future readers understand the rename's purpose without digging through the code. The field is central to xdiff's operation, used to track line changes during diff calculation and when building the final edit script.

The change is part of the series' final naming improvements that also included converting dis1/dis2 to matches1/matches2 and adding enum-like macros for similarity states. Phillip's feedback is non-blocking style guidance - the series is otherwise complete with all structural simplifications finished and type safety enhancements in place. This matches his earlier pattern of constructive review focused on documentation clarity and naming consistency.
