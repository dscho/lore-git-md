This is a preparatory refactoring patch for the `git repo stats` series, modifying the ref-filter interface to handle NULL pattern arrays more gracefully.

The patch makes two small but important changes to `ref-filter.c` to treat a NULL `name_patterns` array the same as an empty array in the pattern matching logic. Currently, callers must provide an allocated array even when they don't need any patterns, which is an unnecessary constraint. The changes affect both the direct pattern matching function (`filter_pattern_match()`) and the full reference iteration function (`for_each_fullref_in_pattern()`).

The modification is straightforward - it simply adds NULL checks before dereferencing the patterns array. This maintains all existing behavior while allowing NULL to indicate "no patterns needed". The change is mechanical and well-contained, touching only the necessary condition checks without altering any surrounding logic.

This patch serves as groundwork for the `git repo stats` command being developed in the series, which will use this more flexible interface. The change is low-risk since it doesn't introduce new functionality, just makes the existing interface more convenient to use. The patch follows the established pattern of the series by keeping changes minimal and focused, with clear commit message explaining the change.
