This is a follow-up in the thread about month numbering in `git log` output, where Jeff King (Peff) responds to the original report about 1-based vs 0-based month indexing.

Peff clarifies two key points in response to the original complaint: First, he questions whether the suggestion to use 0-based months (where September would be 8) is actually desirable, noting this would require locale support via strftime's `%c` option. Second, he points out that if the concern is simply about date formatting preferences rather than month numbering, Git already provides flexible formatting options through `--date=format:` with strftime specifiers.

The response effectively closes the discussion by showing the current behavior is intentional (matching standard date conventions) and that customization is already possible for those who want different formats. No changes to Git's core behavior appear necessary, though users with specific formatting needs can use existing tools to achieve their preferred output.
