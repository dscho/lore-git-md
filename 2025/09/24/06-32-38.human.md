This is a reply in the ongoing discussion about the new `git refs get` plumbing command, which aims to provide strict reference reading without DWIM behavior. Patrick Steinhardt responds to Junio Hamano's suggestion that the functionality should be added to `git show-ref` rather than creating a new subcommand.

Patrick defends the decision to place the functionality in `git-refs`, arguing that while discoverability is currently lower (since it's a new command), users will adapt over time. He positions `git-refs` as the natural home for reference-related operations, suggesting that having a complete set of reference-handling tools in one place will ultimately improve the user experience. The reply maintains the original vision of keeping this as a separate command rather than extending `show-ref`, though it doesn't directly address Junio's specific `--no-deref` flag suggestion.

The exchange highlights the architectural question of whether new functionality should extend existing commands or create new, more specialized ones - a recurring theme in Git's design discussions. Patrick's response keeps the door open for further debate while standing by the initial design choice.
