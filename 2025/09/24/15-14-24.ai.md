This is the final patch in a refactoring series modernizing xdiff internals for Rust compatibility. The patch converts the `xdfile_t.changed` field from `char` to `bool` to better reflect its actual usage as a boolean flag marking changed lines in diffs. 

The change follows previous work that introduced enum-like macros (`NONE/SOME/TOO_MANY`) for similarity matching states, making the distinction between boolean flags and numerical match states clearer. Phillip Wood approved the change, noting it improves code clarity compared to the previous version where both concepts used `char` types. 

The commit message explains the rationale: while the field was previously stored as a `char` alongside other `char` fields used for numerical match states, the `changed` field logically represents a boolean value. The change maintains identical behavior while making the code's intent more obvious to future readers. This completes the series' type safety improvements, which also included converting other fields to proper types (`uint8_t*` for match arrays, `bool` return types) and adding validation checks.

The patch touches xdiff's core diffing logic in `xdiff/xdiffi.c` and related files, but like the rest of the series, makes no behavioral changes - only type and naming improvements to support future maintenance and potential Rust integration. All prior feedback has been addressed, including Phillip Wood's suggestions about documentation clarity. The series is now complete and ready for merging.
