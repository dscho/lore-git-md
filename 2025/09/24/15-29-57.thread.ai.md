`git stash` bug report: untracked files lost during complex file operations. Reporter demonstrates a sequence where moving a tracked file between directories (`d1/f` to `d2/f`) while modifying it causes `git stash -u` to only record the deletion, not the untracked version. Tested on `git 2.51.0` (Darwin/arm64), the operation fails to preserve the modified content (`code2`) when stashing both the deletion and new untracked state. Recovery attempts via `git stash pop` or `git checkout 'stash@{0}'` cannot restore the lost data. The bug appears related to how `stash` handles file movement with low similarity index combined with `-u` flag behavior, potentially causing data loss in edge cases involving simultaneous tracking of deleted and untracked file states. Reproduction recipe provided.
