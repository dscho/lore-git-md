This is a follow-up in the already-settled discussion about 0-based date indexing in `git log` output. Emily Shaffer responds to a resubmitted proposal for a configuration option to use 0-based month/day numbering, reiterating the thread's consensus that this would be non-standard behavior. She notes that Git relies on `strftime` for date formatting, which follows locale conventions (1-based by default), and that implementing such an option would require modifying low-level date handling code. The response politely but firmly suggests that if the requester wants this non-standard behavior, they should maintain a local patch rather than proposing it for upstream inclusion. The email reinforces the thread's conclusion that the current behavior is correct and that existing `--date=format:` options provide sufficient customization without introducing non-standard configurations. No new technical points are raised beyond what was already discussed and rejected in the thread.
