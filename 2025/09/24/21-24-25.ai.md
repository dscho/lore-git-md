Feature patch (5/6 in series) adding machine-readable output formats to `git repo stats`.

This patch introduces `--format` options for the new `git repo stats` command, providing machine-parsable alternatives to the default human-readable table output. The implementation adds two new formats: `keyvalue` (newline-delimited key=value pairs) and `nul` (NUL-delimited with newline separating keys/values). The formats follow established patterns from `git repo info` and handle special characters consistently.

Key technical details:
- Adds `FORMAT_TABLE`, `FORMAT_KEYVALUE`, and `FORMAT_NUL_TERMINATED` enum values
- Implements `stats_keyvalue_print()` helper that handles both new formats with configurable delimiters
- Updates documentation to describe all three formats and their use cases
- Adds comprehensive tests verifying both new formats against expected output
- Maintains backward-compatible default table format
- Follows same quoting rules as `core.quotePath` for keyvalue format
- Uses NUL delimiters consistently with other Git commands
- Properly handles format validation and error cases

The implementation builds on the series' existing stats collection while cleanly separating format-specific output logic. Test coverage verifies correct behavior for repositories with various object and reference counts. This completes the output format options planned for the command, with the final patch in the series (6/6) adding progress meter functionality.
