This is a follow-up discussion in the ongoing thread about `git rebase -i`'s fixup command behavior with the `-C` flag. Mathias Rav responds to Johannes Sixt and Junio Hamano's earlier comments about the proposed change to make `fixup -C` preserve the current commit's author information rather than taking it from the previous commit.

Mathias acknowledges Junio's position that fixup operations should maintain original authorship, and reveals they were previously using a custom shell script (`~/.local/lib/git-rebase-utils/f`) to achieve the desired "fixdown" behavior (where a previous commit acts as a fixup for a later one). The script combines `git cherry-pick -n` with `git commit --amend -nC` to preserve the current commit's author while taking the message from the target commit.

Key technical details mentioned:
- The custom solution uses `cherry-pick -n` followed by `commit --amend -nC`
- Requires PATH modification via shell alias to use in interactive rebase
- Mathias notes they were unaware of the "amend!" autosquash feature before this work

The email shows Mathias is willing to revert to their custom solution if the maintainers reject the patch, though they still see value in the proposed behavior for cases where preserving author dates isn't critical. This continues the thread's exploration of balancing design principles (Junio's stance on fixup semantics) against practical use cases (Johannes' "reverse fixups" scenario), with Mathias now providing a working alternative implementation path.
