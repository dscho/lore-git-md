This is a discussion about Git project communication channels, specifically considering whether to create a dedicated announcement mailing list.

Junio Hamano responds to Christian Couder's defense of the single-list model by acknowledging that a read-only announce list wouldn't necessarily fracture the community, but points out the practical challenges of maintaining it. He notes that such a list would require ongoing effort from already-busy maintainers, making it an unlikely solution unless the requester is willing to help operate it. 

The email reinforces two key points from the thread: that specialized lists create maintenance overhead, and that importance is subjective (as Christian noted with Git for Windows and Git Rev News examples). Junio's response maintains the project's pragmatic stance - while technically possible, new infrastructure shouldn't be added without committed maintainers.

This moves the discussion from theoretical design to practical constraints, emphasizing that the status quo persists not just philosophically but because volunteers are already stretched thin. The thread appears to be reaching consensus that while multiple notification methods exist (RSS, scripts), creating new official channels requires more than just user demand.
