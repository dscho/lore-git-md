This is the final patch in the `git repo stats` series, adding a progress meter to the new repository statistics command. The patch introduces user feedback during potentially long-running operations when counting references and objects in a repository.

The progress meter is enabled by default when the command runs in a terminal, with explicit control via `--[no-]progress options`. The implementation uses Git's existing progress API, showing separate meters for reference counting (with a known total) and object counting (with an initially unknown total that updates as objects are processed).

The changes integrate cleanly with the existing stats collection infrastructure, adding progress callbacks to both the reference counting and object walking paths. The implementation follows Git conventions, including proper cleanup of progress resources and translation support for progress messages.

This appears to be a well-considered addition to complete the user experience for the new command. The patch maintains the series' high standard of implementation, with careful attention to edge cases (like TTY detection) and clean integration with the existing code. As the final piece of the series, it addresses one of the last remaining items from earlier reviews.
