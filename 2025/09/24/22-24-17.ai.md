Maintainer follow-up addressing memory leak in diff-no-index fix.

Junio Hamano confirms his earlier speculation about a memory leak in Jacob Keller's `diff-no-index` buffer overflow fix. Testing with SANITIZE=leak revealed that the `ps_match1` and `ps_match2` strbufs were not being released in the error-handling path. The proposed fix adds two `strbuf_release()` calls at the `out:` label in `diff_no_index.c`, which resolves the leak detection failure.

The change is minimal (2 lines) and focused specifically on resource cleanup, not altering the core logic of the original fix. Hamano offers to either incorporate this change himself or let Keller squash it into the existing patch. This maintains the thread's pattern of iterative improvement, where each round tightens both functionality and robustness.

The context shows this is the final polish on a solution that already addressed both safety (buffer overflow) and performance (redundant string operations). With this leak fix, the changes would satisfy both functional correctness and modern memory hygiene standards. The maintainer's direct involvement in testing and proposing the fix suggests this will likely be the last revision needed before merging.
