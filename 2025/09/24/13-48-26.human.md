This is a licensing policy discussion in the ongoing Rust infrastructure thread, specifically addressing concerns around derivative works and GPL exceptions.

Phillip Wood weighs in on Jeff King's legal analysis of Johannes Schindelin's GPLv2+exception proposal for Git's Rust code. Wood expresses agreement with King's concerns about derivative works - that even conceptually similar Rust implementations of GPLv2 C code may inherit licensing restrictions. 

The email raises two practical concerns about Schindelin's proposed exception that would allow Git's Rust code to be used in Gitoxide: (1) the difficulty for third parties to track code provenance when some files have exceptions and others don't, and (2) the potential for the exception to create a loophole where any project could bypass copyleft requirements by routing code through Gitoxide first.

This continues the thread's deepening examination of Rust licensing challenges, moving from technical implementation questions to substantive legal and policy concerns. Wood's intervention highlights practical complications that would arise even if the legal theory behind the exception were sound. The discussion remains unresolved but is becoming more focused on the community's need for clear guidelines around derivative works and code reuse.
