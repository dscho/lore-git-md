This is the final patch in a series adding configurable index restoration to `git stash`. The patch implements the core functionality to honor the new `stash.index` configuration when applying or popping stashes, with the default remaining false for backward compatibility. The author confirms Phillip Wood's observation that this change will also affect `--autostash` behavior during merge/pull/rebase operations, and they discuss whether to document this interaction.

The patch series has been through several rounds of review and testing, with all feedback addressed. The maintainer has approved it for integration. This final version includes test isolation improvements and preparatory refactoring. The only remaining question is whether to explicitly document the `--autostash` interaction in the commit message or documentation, though Phillip Wood notes this behavior is likely what users would want anyway.

The change resolves a long-standing inconsistency where `stash push` saves staged changes but `apply/pop` doesn't restore them by default. Users can opt out with `--no-index` if needed. The implementation is clean and well-tested, with comprehensive coverage of config/flag interactions and edge cases. This appears ready to merge as a final documentation tweak is considered.
