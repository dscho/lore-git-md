This is a test infrastructure patch in the SHA-1/SHA-256 interoperability series. Patrick Steinhardt reviews a change from brian m. carlson that adds support for specifying compatibility hash algorithms in test scripts.

The patch introduces two main changes: First, it extends `test_detect_hash()` to handle a new `GIT_TEST_DEFAULT_HASH` format that can specify both primary and compatibility hash algorithms (like "sha256:sha1"). Second, it adds a `BROKEN_OBJECTS` prerequisite that checks whether the test environment supports writing deliberately broken objects, which isn't possible when running with SHA-1 compatibility mode.

Patrick's review is light - he suggests a minor subject line prefix change ("t:") and fixes a grammatical nit ("if" -> "whether"). He notes the infrastructure change seems reasonable though he'd like to see actual tests using it, but doesn't consider that a blocker. The change appears straightforward and aligns with the series' established technical direction.
