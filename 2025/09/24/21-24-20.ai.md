Feature implementation for a new `git repo stats` command, building on previous discussion and review rounds.

This cover letter introduces version 2 of the series implementing repository statistics functionality directly in Git, inspired by third-party tools like git-sizer. The command will report reference and object counts initially, with plans to expand to more detailed metrics in future work. The implementation has evolved through multiple review cycles addressing core functionality, output formats, and code organization.

Key technical updates in this revision:
- Refactored translation handling to separate formatting from translatable terms
- Consolidated output format patches (keyvalue and NUL-delimited) into one
- Added progress meter feedback during potentially long-running operations
- Improved documentation structure using bullet points
- Test consolidation to reduce duplication
- Ref-filter interface enhancement allowing NULL filter patterns
- Various renames and cleanups for clarity

The series consists of 6 patches:
1. Renames existing `repo_info()` to follow `cmd_` prefix standard
2. Modifies ref-filter to accept NULL patterns (prep work for stats)
3. Core stats subcommand implementation
4. Object counting functionality
5. Keyvalue and NUL-delimited output formats
6. Progress meter addition

The implementation appears thorough, with careful attention to Git conventions and review feedback. Test coverage is comprehensive, and the separation of concerns between data collection and presentation is well-maintained. The cover letter clearly outlines both immediate scope and future directions, suggesting this is part of a longer-term effort to bring repository health metrics into core Git.
