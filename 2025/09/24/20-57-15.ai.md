Bugfix for `git diff --no-index` path handling when paths end in '/'. This patch addresses a buffer overflow issue that occurs when comparing directories where one path ends with a slash, reported by Johannes Schindelin. The root cause is an incorrect length calculation in `diff_no_index()` that always adds an extra byte for the slash, even when not needed.

The fix reworks the path matching logic to avoid expensive `strbuf_remove()` operations and instead builds up match paths incrementally using `strbuf` operations. This both corrects the off-by-one error and improves performance by eliminating redundant string copying. The patch introduces two new test cases to verify correct behavior with trailing slashes in pathspecs.

Key technical changes:
- Replaces `skip1`/`skip2` integer parameters with `strbuf` structs `ps_match1`/`ps_match2`
- Modifies `read_directory_contents()` to work with pre-initialized `strbuf` instead of creating temporary ones
- Updates `queue_diff()` to maintain match paths through recursive calls
- Adds test cases in `t4053-diff-no-index.sh` for paths ending in '/'

The patch appears well-considered, addressing both the immediate bug and underlying inefficiencies in the path handling logic.
