This is a governance discussion email in the Rust infrastructure series, focusing on LTS (Long-Term Support) management for the Rust transition. Patrick Steinhardt responds to Junio Hamano's concerns about maintaining a Rust-free LTS branch, proposing to defer detailed LTS handover decisions until later.

The key points center around trust and maintainer competence for the LTS branch. Hamano expressed skepticism about the project endorsing potentially less-experienced LTS maintainers, while Steinhardt suggests there's a middle ground where distro maintainers (competent but less Git-specialized) could collaborate with core contributors. The discussion reveals fundamental differences in approach - Hamano prefers a clean fork model (like Git for Windows) while Steinhardt envisions a more integrated solution with canonical repository tags.

Steinhardt proposes a patch to modify the BreakingChanges.adoc document, removing specifics about the LTS handover process in favor of deferring those decisions until the actual need arises. The change softens the language around distributor involvement and repository tagging, acknowledging that many practical questions (timing, maintainer selection, duration) remain unresolved at this stage of the Rust transition planning.

This email doesn't introduce new technical elements but continues the strategic discussion about how to manage the Rust mandate's impact on downstream users and distributions. The proposed documentation change represents a pragmatic step back from premature specification while keeping options open for future adaptation. The thread remains active on core questions of project governance, versioning policy, and maintainer trust models.
