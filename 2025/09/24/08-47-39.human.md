This is a discussion about the behavior of `git rebase -i`'s fixup command with the `-C` flag, following Junio Hamano's rejection of Mathias Rav's proposed change to preserve the current commit's author info.

Johannes Sixt ("Hannes") offers a counterpoint to Junio's position, arguing that there are legitimate cases where you'd want to preserve the later commit's metadata - specifically when a fixup commit needs to be reordered but conflicts prevent simple reordering. He suggests this isn't about fixing a broken commit (which Junio argued should keep original authorship) but rather about properly attributing work that was temporarily split out of sequence.

Hannes proposes that if the term "fixup" is too semantically loaded, perhaps the functionality could be added to "squash" commands instead. This keeps the discussion alive despite Junio's authoritative rejection, offering a potential compromise path forward.

The thread has now clearly bifurcated between:
1. Junio's position that fixup should maintain original authorship semantics
2. Hannes' argument for a metadata-preserving option in either fixup or squash for reordering scenarios

The core disagreement remains philosophical - whether preserving authorship chains should be the default when amending commits versus allowing intentional reattribution in certain workflow scenarios.
