Feature patch adding object counting to the `git repo stats` command, part of the ongoing series (4/6). This patch extends the repository statistics output to include counts of reachable objects (commits, trees, blobs, and tags) alongside the existing reference counts.

The implementation uses the path-walk API to traverse all objects reachable from regular references, categorizing them by type. The human-readable table format introduced in patch 3/6 is expanded to show both reference and object statistics in a hierarchical format. Object counting happens in parallel with reference counting, with the results combined in a new `repo_stats` struct that merges the previous `ref_stats` with the new `object_stats`.

Key technical details:
- Adds `object_stats` struct to track counts by object type (tags, commits, trees, blobs)
- Implements `count_objects()` callback for path-walk API to categorize objects
- Extends `stats_table_setup()` to format both reference and object counts
- Uses revision walking infrastructure to find reachable objects
- Updates tests to verify object counting with specific expected values (130 total objects in test case)
- Documents the object counting feature in git-repo.adoc

The patch maintains the series' clean separation of concerns, with data collection (now handling both references and objects) remaining distinct from presentation. Memory management remains careful with proper cleanup of revision walking state. Test coverage is thorough, verifying both empty repository and populated cases.

This appears to be a well-constructed addition to the series, building logically on the foundation established by earlier patches while introducing new functionality. The implementation follows established patterns from the earlier reference counting code and integrates smoothly with the existing output formatting.
