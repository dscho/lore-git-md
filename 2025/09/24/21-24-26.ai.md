This is the final patch in the `git repo stats` series, adding a progress meter to the new statistics command. The patch implements progress reporting for both reference counting and object traversal operations, with automatic TTY detection and explicit `--[no-]progress` override.

Key technical details:
- Progress meters added to both `stats_count_references()` and `stats_count_objects()` functions
- Uses Git's standard progress API with `start_progress()`/`display_progress()`/`stop_progress()`
- Progress enabled by default when stderr is a TTY, controllable via new `--progress`/`--no-progress` options
- Two distinct progress messages: "Counting references" (with known item count) and "Counting Objects" (with indeterminate count)
- Requires passing repository context through call chain for progress initialization
- Introduces `count_objects_data` struct to carry both stats and progress state
- Maintains existing functionality while adding progress reporting
- Implementation follows Git's standard progress patterns
- Progress state properly cleaned up via `stop_progress()`
- No changes to output formats or core statistics logic
- Progress integration requires minimal changes to existing function signatures
- Preserves all existing error handling and memory management

The patch completes the series by addressing a key usability concern for large repositories, while maintaining the clean separation of concerns seen throughout the implementation. The progress reporting integrates smoothly with the existing architecture and follows established Git conventions.
