This is a refactoring patch that's part of the `git repo stats` series, specifically preparing the ref-filter interface for the new statistics functionality. The change allows the `name_patterns` field in `struct ref_filter` to be NULL, treating it the same as an empty array of patterns. This makes the API more flexible by removing the requirement to allocate an empty array when no filtering is needed.

The patch is straightforward - it modifies two condition checks in ref-filter.c to first test for NULL before dereferencing the patterns array. This is a small but meaningful improvement to the ref-filter interface that will be used by the upcoming `git repo stats` command when it needs to process all references without filtering.

As the second patch in a 6-part series, this builds on the mechanical naming changes from patch 1/6 and provides groundwork for the actual stats functionality coming in later patches. The change appears well-contained and properly tested (though the tests aren't shown in this diff), following the established pattern of making interfaces more robust before building on them.
