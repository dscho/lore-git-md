Feature implementation for the `git repo stats` command series (3/6). This patch introduces the core reference counting functionality of the new subcommand, which aims to provide repository health metrics similar to git-sizer but natively in Git.

The implementation collects and displays reference counts categorized by type (branches, tags, remotes, others) in a human-readable table format. The output is modeled after git-sizer's presentation style with auto-adjusted column widths. The patch includes:
- A `cmd_repo_stats()` function that orchestrates the reference counting
- `ref_stats` struct to track counts by reference type
- `stats_table` infrastructure for formatting the output
- Comprehensive tests verifying empty and populated repository cases
- Key technical details:
  - Uses ref-filter API to categorize references (FILTER_REFS_BRANCHES etc.)
  - Implements table formatting with dynamic column sizing
  - Handles translation of output strings
  - Includes thorough test coverage for all reference types
  - Follows established `cmd_` prefix convention
  - Carefully manages memory with cleanup functions

This represents the first concrete functionality in the series, building on the preparatory ref-filter changes from patch 2/6. The implementation appears clean and well-tested, with clear separation between data collection and presentation. The table output is explicitly marked as not intended for machine parsing, leaving room for future patches to add machine-readable formats.
