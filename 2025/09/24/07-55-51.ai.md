Bugfix for the ref-cache iterator's handling of empty directories when using packed-refs. This patch addresses a segfault that occurs in `cache_ref_iterator_seek()` when seeking references in empty directories (like `refs/heads/` after repacking). The fix adds a check for empty directories (`dir->nr == 0`) to break out of the seek loop early.

The patch includes two new test cases in t6302-for-each-ref-filter.sh that verify the fix works with both fully packed refs and mixed packed/loose ref scenarios. The tests specifically exercise the `--start-after` flag of `git-for-each-ref`, which uses this seeking functionality. The test cases create repositories with packed refs and verify the iterator correctly handles empty directories without crashing.

This appears to be a straightforward fix for a clear edge case in the ref-cache mechanism. The commit message clearly explains the problem and solution, and the test coverage is thorough, including both the crash scenario and normal operation with packed refs. The change is minimal (just 3 lines added) and focused on the specific issue.
