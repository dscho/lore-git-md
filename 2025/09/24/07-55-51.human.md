Bugfix for ref-cache seeking in empty directories. 

Karthik Nayak fixes a segfault that occurs when using `git for-each-ref --start-after` with packed refs where some ref directories are empty (like right after repacking). The issue happens because the ref-cache seek mechanism doesn't properly handle empty directories when searching for references.

The patch adds a simple check to break out of the search loop when encountering an empty directory. It includes two new test cases that verify the fix works with both fully packed refs and mixed packed/loose ref scenarios. The tests simulate the problematic case by creating packed refs and then using `--start-after` to trigger the seek operation.

This appears to be a straightforward and well-tested fix for a real edge case. The commit message clearly explains the problem and solution, and the new tests provide good coverage of both the bug scenario and related cases. The change is minimal (just 3 lines of code) with the bulk of the patch being test coverage.
