This is a discussion email in the completed ODB transaction refactoring series, where Taylor Blau raises concerns about the safety and justification for removing transaction nesting support. The series has already been finalized, with Patrick Steinhardt and Justin Tobler having established a new public transaction API in odb.[ch] that enforces single transactions via BUG().

Taylor questions whether removing nested transaction support (where inner transactions were no-ops) actually improves safety, noting it shifts responsibility to callers to check for existing transactions. He's concerned this could lead to BUG() triggers if new code doesn't perform these checks, and asks what benefits justify this added caller burden. While the patch's newer version addresses some motivations, Taylor seeks clearer justification for the tradeoff between simplified internals and increased caller complexity.

The discussion doesn't propose changes to the merged work but seeks to better document the design rationale, particularly around safety implications of the single-transaction enforcement. This is post-merge reflection rather than active controversy, with Taylor aiming to understand the decision rather than challenge it.
