This is part 3/5 of Karthik Nayak's reftable fsck validation series, focusing on stack integrity checks. The patch originally proposed validating the number of reftable files by counting files in the directory and comparing to `tables.list`, but Patrick Steinhardt raised concerns about false positives during concurrent updates and Windows file deletion behaviors.

Karthik agrees with Patrick's feedback and plans to restructure the validation approach. Instead of strict file counting, they'll verify there are no unexpected files in the reftable directory. The validation will be organized hierarchically, with stack-level checks (including this new file-name validation) separate from the deeper table/block/ref validations.

This continues the series' careful separation between reftable internals and Git's fsck framework, with Karthik maintaining the principle that the library reports errors while Git determines severity. The patch shows good responsiveness to review feedback while keeping the overall validation structure coherent.
