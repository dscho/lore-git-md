This is a CI modernization patch in the Rust infrastructure series, specifically enabling Rust testing in the breaking-changes CI jobs. The patch modifies both dependency installation and test execution scripts to include Rust tooling when running these jobs.

The changes are straightforward: `cargo` is added to the package lists for both Fedora and Ubuntu/Debian CI environments, and the breaking-changes job configuration now sets `WITH_RUST=YesPlease` and `-Drust=enabled` flags. This ensures the CI system will build and test Git with Rust components enabled, validating the infrastructure works as expected.

This patch builds on the earlier CI modernization work that converted the obsolete "pedantic" job to a Fedora-based breaking-changes test. The changes are minimal but important for verifying Rust integration across different build configurations. The patch demonstrates the project's commitment to testing Rust support across multiple platforms and build systems as part of the transition plan.

Key technical points for future reference:
- Adds `cargo` to `ci/install-dependencies.sh` for Fedora and Ubuntu/Debian
- Sets `WITH_RUST` and `-Drust=enabled` in `ci/run-build-and-tests.sh` for breaking-changes jobs
- Maintains existing breaking-changes testing while adding Rust validation
- Follows the pattern established in earlier build system patches for Rust enablement
- Part of the broader effort to validate Rust infrastructure before the planned mandatory transition

The patch appears well-contained and aligns with the series' goal of comprehensive Rust testing infrastructure. It addresses the practical need to verify Rust builds in CI environments that will be affected by the breaking changes required for Rust integration.
