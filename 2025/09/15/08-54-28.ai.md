This is part 10/15 of Patrick Steinhardt's packfile store refactoring series, continuing the migration of packfile management from `struct object_database` to the new `struct packfile_store`. The patch focuses on `install_packed_git()`, which adds packfiles to the object store.

The key change renames `install_packed_git()` to `packfile_store_add_pack()` and modifies it to operate directly on a packfile store rather than a repository. The function now takes a `packfile_store` parameter instead of a `repository`, making its scope and dependencies more explicit. The implementation remains largely the same - it still increments the pack open FD count, links the pack into the store's list, and adds it to the hashmap - but now operates on the store's fields directly.

The patch updates 7 call sites across various components (fast-import, index-pack, http, midx) to use the new function name and pass the packfile store from the repository's objects. Documentation is added to packfile.h explaining the function's purpose. The changes are mechanical but important for establishing the new architectural pattern where packfile operations explicitly work with the packfile store rather than implicitly through the repository.

This continues the series' pattern of maintaining all existing behavior while shifting the underlying implementation to use the new abstraction. No functional changes are introduced, just the refactoring needed to support the packfile store as the single source of truth for pack management. The patch fits cleanly into the series' established approach and doesn't introduce any new technical questions or concerns.
