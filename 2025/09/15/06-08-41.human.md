This is a technical discussion about transaction handling in `git update-index` when the `--verbose` flag is used. The thread continues Patrick Steinhardt and Justin Tobler's work on refactoring Git's transaction interfaces for the object database (ODB).

The current discussion focuses on an edge case where `--verbose` output in `git update-index` forces immediate flushing of objects, making the transaction mechanism effectively useless after that point. Justin explains that since options are processed as they appear (not all upfront), objects added before `--verbose` still benefit from batching, but all subsequent adds must be flushed immediately to support the verbose output. 

Patrick expresses surprise at this design, questioning whether it's intentional behavior. The exchange highlights an awkward interaction between the transaction system and Git's option parsing order that may need reconsideration. This appears to be a minor but interesting corner case in the larger ODB transaction refactoring effort.
