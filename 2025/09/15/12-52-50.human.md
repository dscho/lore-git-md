Refactoring patch in a series improving `git config get --type=color` functionality. This is the third of five patches in v2 of the series.

The patch modifies the `get_color()` function in builtin/config.c to return an error code rather than calling `die()` when encountering invalid color values. This makes the function more flexible for future callers that may want to handle errors differently. The change is straightforward - it converts the existing error case to return an error code while maintaining the same behavior for the existing caller (which already handles other error cases).

This is part of a larger effort that started with test cleanups and addresses several issues with color handling in git config`, including a regression in parsing color values and unwanted pager behavior. The series appears well-structured, with this refactoring preparing for subsequent functional fixes. The patch itself is small and focused, with clear justification in the commit message.
