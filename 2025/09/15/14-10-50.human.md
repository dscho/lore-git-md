Feature refinement for `git-history` command's sequencer integration. Phillip Wood follows up on Patrick Steinhardt's implementation of HEAD management in the new `git-history` command, suggesting improvements based on how `git rebase` handles similar operations. 

The discussion focuses on whether `git-history` should detach HEAD during operations like rebase does, which would prevent branch reflog pollution and enable easier result verification via `git range-diff`. Phillip notes this approach would let users compare changes using `git range-diff $branch@{1}...HEAD` after operations. 

This is a technical refinement to the ongoing `git-history` development, showing the careful consideration being given to how the new command should interact with Git's existing mechanisms. The exchange demonstrates the project's attention to detail in designing new features that integrate cleanly with established workflows.
