Refactoring patch in Patrick Steinhardt's packfile store series (v5 14/15). This patch converts `get_all_packs()` to operate on a packfile store rather than a repository, completing the migration of packfile management functions to the new abstraction layer.

The change affects 18 files across the codebase, updating callers to first access the repository's packfile store before getting the pack list. The new `packfile_store_get_all_packs()` function maintains the same behavior as the old `get_all_packs()` - it prepares the packfile store and returns all packs including those referenced by multi-pack indices. The patch includes mechanical updates to all call sites, with no functional changes to the actual packfile handling logic.

Key technical details:
- Introduces new `packfile_store_get_all_packs()` function in packfile.h
- Removes old `get_all_packs()` declaration from packfile.h
- Updates callers in commands like `pack-objects`, `repack`, `fsck`, and `gc`
- Maintains MIDX preparation side effect that was present in original function
- Follows same pattern as previous patches in the series for accessing packfile store via `the_repository->objects->packfiles`

This is the second-to-last patch in the series, continuing the mechanical refactoring to establish the packfile store as the single source of truth for pack management. The changes are straightforward and consistent with the architectural direction already established in earlier patches.
