This is a refactoring patch in the ongoing object database (ODB) transaction interface series. It removes the `flush_odb_transaction()` function which allowed partial flushing of transactions without completing them, simplifying the API to only support full transaction completion via `end_odb_transaction()`.

The patch eliminates 17 lines of code across bulk-checkin.c and .h files by removing the standalone flush function and moving its core operations directly into `end_odb_transaction()`. This enforces a cleaner transactional model where operations are either fully committed or not at all, rather than allowing intermediate states. The change follows the series' broader goal of making ODB transactions more robust and predictable as part of preparing for pluggable backends.

Key technical points:
- Removes `flush_odb_transaction()` interface entirely
- Moves its `flush_batch_fsync()` and `flush_bulk_checkin_packfile()` calls into `end_odb_transaction()`
- Maintains NULL-safety checks in v2
- Preserves the transaction state assertion from previous patches
- Updates header file documentation to reflect simplified interface

This builds on earlier work in the series that already migrated all callers away from partial flushing. The change appears well-contained and aligns with the thread's direction toward simpler, more robust transaction handling. No behavioral changes are expected since the function was already unused.
