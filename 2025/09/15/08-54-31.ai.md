Refactoring patch in Patrick Steinhardt's packfile store series (v5 13/15). This continues the migration of packfile management from direct repository access to the new `struct packfile_store` abstraction.

The patch renames and refactors `get_packed_git()` to operate on a packfile store rather than a repository, renaming it to `packfile_store_get_packs()`. The function now takes a `packfile_store` parameter instead of a `repository`, making its scope and dependencies more explicit. The implementation remains largely the same - it prepares the packfile store if needed and returns the linked list of packfiles.

Key changes include:
- Updates callers in `builtin/gc.c`, `builtin/grep.c`, and `object-name.c` to use the new function
- Adds documentation clarifying that this function does not load MIDX or referenced packs
- Maintains the existing behavior where the function ensures packfiles are prepared
- Keeps the function signature in packfile.h while removing the old declaration

This is a mechanical change that continues the series' pattern of moving packfile operations to work through the packfile store interface. The patch follows the established approach from previous patches in the series, with no functional changes to the actual packfile handling logic. All call sites are updated consistently to use the new interface.
