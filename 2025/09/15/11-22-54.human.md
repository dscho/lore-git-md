This is a documentation patch announcing the planned mandatory adoption of Rust in Git's build process, part of the ongoing Rust infrastructure series (v5 7/9). Patrick Steinhardt formalizes the transition timeline that has been discussed throughout the thread, with Rust becoming required starting in Git 3.0 (estimated second half of next year). The patch updates BreakingChanges.adoc to explain the phased approach: optional Rust in 2.52 (current), default-enabled but still optional in 2.53, and mandatory in 3.0.

The documentation addresses ecosystem concerns by noting this gives distributors time to prepare their toolchains and build systems. It also outlines a long-term support plan for the final pre-3.0 release, with extended maintenance windows for distributors who need more time to adopt Rust. The text maintains the "test balloon" terminology that Junio questioned earlier, framing the current optional Rust support as a transitional measure.

This patch represents the policy counterpart to the technical groundwork laid in earlier patches. While the implementation details appear settled (as seen in the build system and varint conversion work), this formal announcement may spark further discussion about the timeline, LTS model, or wording - particularly around the "test balloon" phrasing that has been a mix of defended and questioned in previous thread exchanges. The patch itself is well-structured, with clear milestones and build flag examples, though some distributors may want more specifics about platform support timelines.
