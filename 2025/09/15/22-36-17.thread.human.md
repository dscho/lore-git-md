This thread introduces a new `--all` flag for the experimental `git-repo-info` command, proposed by Lucas Seiki Oshiro as part of GSoC work under mentorship from Karthik Nayak and Patrick Steinhardt. The initial patch implemented the flag to output all available repository metadata keys at once, maintaining consistency with the command's existing output formats and adding test coverage.

Junio C Hamano has now reviewed the patch, focusing on clarifying the semantics and edge case behavior. He suggests improving the description to make clear that `--all` returns values for all keys (not just listing them) and analyzing how the command should behave when `--all` is combined with individual key requests. The current implementation silently ignores extra arguments in this case, but Junio outlines alternative approaches including warning, rejecting, or processing all arguments sequentially. He also recommends expanding test coverage to verify these edge cases.

The review maintains the experimental nature of `git-repo-info` while pushing for more precise documentation and consideration of the flag's interaction with other arguments. The core functionality appears sound, but the author now needs to address these documentation and edge case handling questions before the patch can proceed.
