This is a refactoring patch in a series preparing Git's object database (ODB) subsystem for pluggable backends. It removes the ability to nest ODB transactions, which was previously used to allow internal codepaths to optimize object writes without worrying about existing transactions. 

The patch simplifies the transaction model by enforcing that only one transaction can be active at a time. It replaces the nested counting mechanism with explicit BUG() checks if a transaction is already active, making the ownership semantics clearer. The changes affect several key files including bulk-checkin.c, object-file.c, and callers like cache-tree.c and read-cache.c.

The author (Justin Tobler) has updated the documentation to reflect the new single-transaction requirement. This change helps clarify the transaction interface and removes the need for special flush handling that was previously required. The patch is part of a larger effort to refactor Git's object database code for better abstraction, with Patrick Steinhardt leading the overall ODB work.

The changes appear well-contained and focused, with clear updates to both implementation and documentation. The patch follows up on feedback from v1 of the series, showing careful attention to the review process. This foundational work will help enable future pluggable ODB backends.
