This is part 11/15 of Patrick Steinhardt's packfile store refactoring series, introducing a new helper function to consolidate packfile loading logic. The patch adds `packfile_store_load_pack()` which handles the common pattern of checking if a packfile exists in the store, loading it if not, and adding it to the store. This replaces several ad-hoc implementations across the codebase with a single unified interface.

The new function takes a packfile store, index path, and local flag as parameters. It handles the key conversion from .idx to .pack path internally and performs the hashmap lookup/insertion atomically. The patch updates four call sites (fast-import, index-pack, midx, and packfile.c's prepare_pack) to use this new helper, removing ~40 lines of duplicated logic while maintaining identical behavior.

Key technical details:
- New function signature: `packfile_store_load_pack(store, idx_path, local)`
- Handles path conversion from .idx to .pack for hashmap lookups
- Combines packfile loading and store addition into one operation
- Updates callers in fast-import.c, index-pack.c, midx.c, and packfile.c
- Preserves all existing behavior while reducing code duplication
- Part of broader effort to centralize packfile management in packfile_store

The change is a mechanical refactor that follows the architectural direction established in earlier patches of the series. It demonstrates the packfile store abstraction working as intended to simplify client code while maintaining the same invariants. The patch appears well-contained and properly integrated with the surrounding series.
