This is a documentation patch in the Rust infrastructure series, specifically addressing the BreakingChanges documentation to announce Rust becoming mandatory in Git 3.0. The email continues the discussion with Junio C Hamano about phrasing and practical concerns regarding the LTS maintenance model.

The key discussion points revolve around terminology and maintenance logistics. Patrick Steinhardt defends the "test balloon" phrasing for new Rust features (despite no current examples existing) as intentionally permissive language to encourage future contributions, noting the SHA-256 interoperability work as a precedent. Junio had questioned whether "test balloon" was appropriate given the mandatory nature of the Rust transition.

Regarding the LTS maintenance handoff proposal, Steinhardt clarifies his vision: while distributors would do the backporting work, the Git project would retain canonical control by hosting the LTS branch and reviewing all backports through normal processes. This addresses Junio's concerns about security embargo coordination by suggesting LTS maintainers would need git-security@ access, while maintaining project oversight of the release artifacts.

The exchange reveals two unresolved documentation issues: finding better terminology than "test balloon" for the Rust adoption process, and precisely defining the Git project's role in LTS maintenance after handoff. These sit alongside previously noted open questions about security team involvement in the LTS model. The discussion remains constructive, with Steinhardt showing willingness to adapt phrasing while maintaining the core technical and organizational proposals from the RFC.
