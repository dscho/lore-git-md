This is a technical exploration of error message routing in the ongoing `safe.directory` thread. Jeff King (peff) tests a proposed solution where `upload-pack` would send early errors via ERR packets, but finds several practical issues with the approach.

The experimental patch modifies `upload-pack` to install a die handler that formats errors into ERR packets before exiting. While this successfully transmits the server-side `safe.directory` error to the client, it creates new problems: duplicate error output (once via stderr, once via ERR packet), poor multi-line message formatting, and loss of local error context that normally helps diagnose issues like missing repositories.

Key technical observations:
- Current implementation shows both original stderr and ERR packet versions of the same error
- Multi-line messages lack proper "remote:" prefixing for clarity
- Early ERR packet termination prevents collection of supplemental local error messages
- Degrades user experience for common cases like cloning non-existent repos
- HTTP transport limitations remain unresolved by this approach

The experiment suggests this direction may not be viable without significant protocol changes or tradeoffs in error reporting quality. The thread continues to seek alternative solutions for improving `safe.directory` error visibility while maintaining existing diagnostic capabilities.
