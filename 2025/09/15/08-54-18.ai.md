This is a refactoring series (v5, 15 patches) that introduces `struct packfile_store` to centralize packfile management, part of the ongoing effort to enable pluggable object databases. The series has already been through extensive discussion and is now in its final form with all key technical points resolved.

The core change moves packfile-related fields from `struct object_database` and `struct packed_git` into the new `struct packfile_store`, which becomes the single source of truth for packfile management. This is a preparatory step for future work where packfile management will be moved down to the object database source level rather than being tied to the object database itself.

Key technical points from the thread context:
- The series maintains existing behavior while enabling future evolution
- Both `get_packed_git()` and `get_all_packs()` load all packfiles, with the latter also preparing MIDX information
- `packfile_store_free()` no longer calls `packfile_store_close()` (reverting to original behavior)
- Approximately 50 call sites are updated to use the packfile store directly
- All participants have agreed on the approach with no remaining open questions

The v5 changes focus on final behavioral adjustments:
- Stops closing packfiles when freeing the packfile store
- Keeps `get_packed_git()` for now (to be removed in a future series)
- Includes various code style and commit message improvements from reviewers

The series touches 31 files with ~400 lines added and ~250 removed, primarily in packfile.c and packfile.h. It affects core packfile operations across many commands including `pack-objects`, `repack`, `fsck`, and `gc`. The changes are mechanical refactors that maintain existing behavior while establishing the new architectural pattern.

This represents the culmination of careful discussion and refinement, with all substantive technical points resolved and the series ready for merging as an important step toward pluggable ODB support.
