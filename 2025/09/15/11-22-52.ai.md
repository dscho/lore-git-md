Refactoring patch in the Rust infrastructure series, focusing on varint type safety. This is patch 5/9 in v5 of the series, converting the varint subsystem to use explicit integer widths (`uint64_t` for values, `uint8_t` for lengths) instead of implicit types like `uintmax_t` and `int`. The change affects four files (dir.c, read-cache.c, varint.c, varint.h) with straightforward mechanical updates to function signatures and variable declarations.

The motivation is twofold: platform independence and preparation for Rust reimplementation. The patch notes varints are bounded (max 16 bytes encoded), making these widths safe. Junio C Hamano previously accepted the technical approach while noting `uint8_t` for length isn't strictly necessary, anticipating future discussions about `u64` vs `uint64_t` in Rust.

This is a clean, focused change with no behavior modifications. It follows Ezekiel Newren's suggestion and fits into the larger Rust integration work by ensuring type compatibility between C and Rust implementations. The diff shows careful attention to maintaining existing logic while updating types, with changes like `int varint_len` -> `uint8_t varint_len` and `uintmax_t decode_varint()` -> `uint64_t decode_varint()`. The patch builds on prior build system work (v1-v3) and precedes the actual Rust reimplementation hinted at in the commit message.
