This is a refactoring series (v5, 15 patches) that introduces a new `struct packfile_store` to centralize packfile management in Git's object database. The series is now merged after resolving several technical discussions about behavior preservation.

Patrick Steinhardt's work moves packfile-related fields from `struct object_database` and `struct packed_git` into the new `struct packfile_store`, creating a clearer architectural boundary. The changes are preparatory work for upcoming pluggable object databases, where packfile management needs to be more modular.

Key changes in v5 include:
- The removal of packfile closing when freeing the store (reverting to original behavior)
- Keeping `get_packed_git()` for now (to be removed in a follow-up series)
- Various code style and commit message improvements from reviewers

The series touches over 30 files, primarily in the packfile and object database subsystems. All substantive discussion points from the thread appear resolved, with maintainer approval. The changes maintain existing behavior while establishing the foundation for future ODB abstraction work.

This represents a significant internal restructuring that doesn't change user-visible behavior, but improves the codebase's organization for upcoming features. The careful approach to behavior preservation and thorough review process suggest this is a high-quality contribution to Git's architecture.
