This is the final patch in a refactoring series to prepare Git's object database (ODB) for pluggable backends by moving transaction handling code from bulk-checkin to object-file. The series has been through multiple iterations with core relocation and API simplification already completed.

The patch introduces a new ODB-level transaction interface (`odb_transaction_{begin,commit}()`) while renaming the existing files-backend functions to clarify their scope (`object_file_transaction_{begin,commit}()`). This creates a clear separation between the generic ODB interface and files-backend implementation, which is key for future pluggability. The changes are mechanical but wide-ranging, updating callers across builtins and core code to use the new interface.

The work appears well-executed, completing the terminology transition from "bulk-checkin" to "transaction" that was begun earlier in the series. All prior feedback from the thread has been addressed, and the patch maintains the series' focus on establishing clean API boundaries while preserving existing functionality. This final piece positions the codebase well for future work on alternative ODB backends.
