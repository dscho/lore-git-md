This is the final patch in a 6-part refactoring series to prepare Git's object database (ODB) for pluggable backends by relocating transaction code from bulk-checkin to object-file. The series is now complete with this patch establishing the ODB subsystem's transaction API.

The patch introduces new `odb_transaction_{begin,commit}()` functions in odb.[ch] that serve as the public interface for transactions, while renaming the existing files-backend functions to `object_file_transaction_{begin,commit}()` to clarify their scope. This creates a clear separation between the generic ODB layer (which will eventually support multiple backends) and the files-backend implementation.

Key changes include:
- New odb.h declarations for the transaction interface
- Implementation in odb.c that forwards to the files-backend
- Updates to all callers (add.c, unpack-objects.c, update-index.c, etc.) to use the new API
- Renaming of internal functions to reflect their files-backend specificity
- Documentation updates clarifying the API boundaries

The patch completes the series' goal of establishing clean ODB transaction boundaries while maintaining all existing functionality. With this change, the bulk-checkin code has been fully migrated and the terminology standardized to "transaction" throughout. The groundwork is now laid for future pluggable ODB backends to implement their own transaction handling while callers use the unified odb_transaction interface.

The implementation appears thorough, with consistent updates across all affected files and clear documentation of the new API contracts. This concludes the series' technical work, though reviewers may want to verify the final naming choices and API documentation before merging.
