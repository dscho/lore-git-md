Bugfix for `git send-email` preventing duplicate Reply-To headers.

NeilBrown reports that when using `git send-email --compose --reply-to` with an edited intro message, the resulting email ends up with two identical Reply-To headers, which causes Gmail to reject the email. The issue occurs because the Reply-To header gets added both in the message template and again during header processing.

The patch fixes this by having the header parser recognize an existing Reply-To header in the intro message and use it to set the $reply_to variable, rather than blindly copying it into the new headers. The change is a straightforward 3-line addition to git-send-email.perl that checks for and handles the Reply-To header similarly to how other headers like In-Reply-To are processed.

This appears to be a clean, focused fix for a real-world usability issue that affects users trying to send patches via Gmail. The change is minimal and well-contained, touching only the header parsing logic without introducing any other behavioral changes.
