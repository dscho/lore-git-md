This is a review response to a feature addition for the experimental `git-repo-info` command. Junio C Hamano provides feedback on Lucas Seiki Oshiro's patch that adds an `--all` flag to output all repository metadata keys at once.

The review focuses on clarifying documentation and considering edge case behavior. Junio suggests rewording the description to make clear `--all` returns values for all keys, not just listing keys. He also analyzes four possible behaviors when `--all` is combined with individual keys, noting the current implementation silently ignores extra arguments but suggesting alternatives like warning, rejecting, or processing them sequentially.

Key technical points raised:
- The implementation currently ignores any keys passed with `--all`
- Test coverage should be expanded to verify behavior with `--all key` combinations
- Documentation should precisely state whether `--all` returns values or just keys

The review maintains the experimental status of `git-repo-info` while pushing for clearer semantics around the new flag. It doesn't reject the approach but invites consideration of alternative designs for handling combined flags, suggesting the most logical option may be to process all arguments sequentially when `--all` is present.
