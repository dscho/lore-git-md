This is a feature patch adding a new `--all` flag to `git repo info`, part of the experimental `git-repo` command. The change allows users to retrieve all available repository metadata keys at once, rather than having to specify each one individually. The patch comes from Lucas Seiki Oshiro as part of their GSoC work, with help from Karthik Nayak and Patrick Steinhardt.

The implementation adds a new `print_all_fields()` function that iterates through all available keys and prints their values, while maintaining the existing output format options (key-value pairs or NUL-terminated). The patch includes documentation updates and a new test case verifying the `--all` behavior matches explicitly listing all known keys.

The change appears well-structured, with clean separation of concerns between the new bulk-printing logic and the existing per-field printing. The commit message clearly states the motivation (avoiding the need to know all keys in advance) and the patch includes appropriate test coverage. As this is part of the still-experimental `git-repo` command, the change seems like a reasonable quality-of-life improvement for users exploring this new functionality.
