This is a bugfix patch in Justin Tobler's series refactoring Git's object database transaction handling. It addresses a specific edge case in `git update-index --verbose` where the interaction between option parsing and transaction handling could lead to awkward behavior.

The patch changes how `update-index` handles transactions when `--verbose` is specified. Previously, it would flush (but not commit) the object database transaction before each verbose output, keeping the transaction technically open. Now it cleanly ends the transaction as soon as `--verbose` is encountered, processing subsequent updates without any transaction.

The change makes the behavior more straightforward while maintaining compatibility with any hypothetical scripts that might rely on the verbose output to know when objects are written. The commit message provides clear historical context about why this behavior exists (dating back to 2022) and explains the technical details of the option parsing order issue.

This appears to be a well-considered change that simplifies the code while preserving functionality. It's part of a larger effort to clean up transaction handling in preparation for pluggable object database backends, and incorporates feedback from the v1 discussion. The patch maintains the same level of safety (objects still become visible when expected) while removing an awkward intermediate state.
