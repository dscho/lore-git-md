Feature proposal for `git-history` command, specifically discussing the `reword` subcommand implementation.

Phillip Wood responds to Patrick Steinhardt's plan to drop the current `reword` implementation from the RFC v3 series. He suggests a simpler approach that would reuse the sequencer's existing reword capability by passing a todo-list with "reword $oid" entries. This would avoid reimplementing functionality and could be extended with minor tweaks to hook execution for the `git-history` context.

The exchange shows Phillip continuing his role as a key reviewer, identifying opportunities to leverage existing Git infrastructure rather than building parallel implementations. His suggestion aligns with the project's preference for code reuse where possible. Patrick had already agreed to defer the `reword` work to a future series, and this email provides concrete technical guidance for when that implementation resumes.

This is part of the broader `git-history` command development, which aims to provide user-friendly history editing operations building on Git's sequencer while taking inspiration from Jujutsu. The thread has seen active design discussion about command architecture, with recent focus on technical refinements like the `skip_commit_summary` flag simplification and HEAD management strategies.
