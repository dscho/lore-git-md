This is a documentation patch announcing the mandatory Rust adoption timeline as part of the ongoing Rust infrastructure series. The patch adds a detailed section to BreakingChanges.adoc outlining the phased transition plan for making Rust a required build dependency by Git 3.0.

The announcement explains the current optional Rust support (introduced in Git 2.52) serves as a "test balloon" to give distributors time to adapt, while making clear this is temporary. It lays out three key milestones: initial infrastructure setup (2.52), default-enabled Rust (2.53), and mandatory Rust (3.0). The document provides specific build flags (`WITH_RUST=YesPlease`, `-Drust=enabled`) and notes the final transition is tentatively planned for second half of next year.

A notable addition is the LTS plan for the pre-3.0 release, promising 4 cycles of bug fixes and 6 of security updates, with potential distributor-maintained extensions. The text carefully positions this as Git project-controlled while allowing for ecosystem needs. The patch follows earlier discussion about terminology ("test balloon" vs mandatory) and incorporates feedback about documenting the transition clearly.

This represents the policy documentation counterpart to the technical Rust infrastructure patches in the series, providing the official project stance on the Rust transition timeline and support commitments.
