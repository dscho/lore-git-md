This is a follow-up discussion in the feature patch series adding signature handling to `git fast-import`. The exchange focuses on finalizing the behavior of STRIP mode for commit signatures.

Christian Couder responds to Junio Hamano's feedback about signature parsing in STRIP mode. The key technical point revolves around whether STRIP mode should parse signatures (like ABORT mode does) or skip parsing for performance. Junio argues that STRIP mode should parse signatures to properly handle malformed input, as users may rely on STRIP to skip bad signatures. Christian acknowledges this and plans to modify the implementation to maintain parsing in STRIP mode while avoiding the "code ergonomics regression" noted in the initial review.

The discussion confirms the final behavior decision: STRIP mode will parse signatures (like ABORT mode) but still strip them from the output, differing from v1's approach that avoided parsing. This aligns with the thread's earlier resolution to make parsing behavior consistent across modes while maintaining distinct actions (abort/strip/warn). The exchange shows all technical feedback has been addressed in v2, with only this final implementation detail being settled.
