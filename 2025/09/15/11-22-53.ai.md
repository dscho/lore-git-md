This is a Rust implementation of Git's varint subsystem, part of the ongoing Rust infrastructure series. The patch reimplements the varint.c functionality in Rust as a "test balloon" for Rust integration, chosen for its simplicity and lack of dependencies. When Rust is enabled, the build system will now compile src/varint.rs instead of varint.c.

The Rust implementation provides the same C-compatible interface via `#[no_mangle]` extern functions `decode_varint` and `encode_varint`, maintaining the same behavior including overflow handling. The patch includes comprehensive tests verifying edge cases like overflow conditions and various encoding/decoding scenarios. Build system changes in both Makefile and meson.build ensure the Rust version is used when WITH_RUST is enabled, falling back to the C version otherwise.

This follows the type safety improvements made to the C varint implementation in earlier patches (converting to explicit uint64_t/uint8_t types). The Rust version uses usize for values and u8 for lengths/buffers, with careful attention to maintaining the same overflow semantics as the C version. The implementation is straightforward with direct pointer manipulation to match the C interface, though it uses Rust's safer pointer operations like `std::ptr::copy_nonoverlapping`.

As part of the larger Rust infrastructure effort, this serves as a proof-of-concept for Rust/C interop in Git's core, demonstrating how subsystems can be incrementally ported while maintaining compatibility. The choice of varint as the first subsystem to port reflects its isolation from other components, making it a low-risk starting point for Rust adoption.
