Refactoring patch addressing transaction handling in `git update-index --verbose` as part of the ODB transaction interface series.

This patch modifies how `git update-index` handles object database operations when the `--verbose` flag is used. The current implementation awkwardly flushes (but doesn't commit) transactions when verbose output is generated, which creates a hybrid state where some objects are transactional and others are immediately visible. The patch changes this behavior to cleanly end the transaction when `--verbose` is encountered, making all subsequent object writes non-transactional.

Key technical changes:
- Removes `flush_odb_transaction()` call from the `report()` function
- Adds new logic in the option parsing loop to detect `--verbose` and end the transaction immediately
- Updates comments to explain the new behavior and rationale
- Maintains backward compatibility with any scripts relying on verbose output synchronization

The change addresses a quirk in option parsing where `--verbose` might appear after some objects have already been written transactionally. The new approach is cleaner than the previous partial solution and better matches user expectations for `--verbose` behavior. This is part of Justin Tobler's v2 series refining the ODB transaction interfaces, incorporating feedback from the v1 discussion about making transaction handling more robust and predictable.

The patch preserves the existing behavior where objects become visible to callers parsing verbose output, while eliminating the awkward intermediate state of flushed-but-not-committed transactions. This simplification aligns with the series' goal of making transaction handling more straightforward as the code moves toward pluggable ODB backends.
