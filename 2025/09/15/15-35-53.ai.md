This is a follow-up in the mergetool environment variables discussion thread, confirming and expanding on the technical details of custom mergetool integration.

D. Ben Knoble shares their practical experience with custom mergetools, confirming Phillip Wood's earlier suggestion about using `mergetool.<tool>.cmd` configuration. They provide a real-world example from their dotfiles repository showing how they pass BASE, LOCAL, and REMOTE variables to their custom tool through the config. This serves as concrete validation of the config-based approach that Phillip Wood and Junio Hamano had previously described as the intended integration method.

The email reinforces two key technical points from the thread: 1) the variables are indeed available when properly configured via the eval'd cmd setting, and 2) this is a working alternative to installing tools in the Git mergetools directory. Knoble's comment about this being an "unfortunate interface" suggests they find the current system somewhat awkward, though they've made it work in practice.

This reply doesn't introduce new technical information but provides empirical confirmation of the solution path the thread has converged on - using git config to define custom tools with access to the shell variables. The reference to actual working configuration may serve as a useful example for documentation updates.
