This is a refactoring patch in the Rust infrastructure series, specifically addressing type safety in the varint subsystem. It changes the varint implementation to use explicit integer widths (`uint64_t` for values and `uint8_t` for lengths) rather than implicit types like `uintmax_t` and `int`. 

The change makes the code more predictable and platform-independent, which is particularly important as this subsystem will be reimplemented in Rust in a subsequent patch. The author notes that since varints are limited to 16 bytes, these explicit types are sufficient and well-defined. The patch touches several files (`dir.c`, `read-cache.c`, `varint.c`, `varint.h`) with straightforward mechanical changes to type declarations and function signatures.

Junio C Hamano had previously reviewed this approach and agreed with the technical direction, though he observed that `uint8_t` for length isn't strictly necessary. The change appears well-contained and uncontroversial, serving as groundwork for the Rust conversion while improving type safety in the C code.
