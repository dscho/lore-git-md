Bugfix for `git send-email` handling of Reply-To headers when using `--compose --reply-to` together, causing duplicate headers rejected by providers like Gmail. NeilBrown's patch modifies `git-send-email.perl` to detect/store the Reply-To header during pre-processing (case-insensitive `^Reply-To:` match) via `$reply_to` variable, preventing duplicates through the same mechanism used for In-Reply-To/References.

NeilBrown acknowledges these requirements in follow-up, planning a resend with corrected attribution and phrasing while keeping the functional solution unchanged. The maintainer validated the core design of storing Reply-To during pre-process to avoid `@xh` array duplication. Outstanding considerations include whether test coverage should be added for the modified header handling behavior, though this may not block initial acceptance if the documentation and commit message improvements are addressed first.
