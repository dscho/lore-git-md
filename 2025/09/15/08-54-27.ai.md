This is part 9/15 of Patrick Steinhardt's packfile store refactoring series, focusing on separating packfile responsibilities from broader object database management. The patch splits `reprepare_packed_git()` into two distinct functions: `odb_reprepare()` now handles the broader ODB maintenance (reloading alternates, clearing loose caches), while `packfile_store_reprepare()` focuses solely on packfile-specific reloading.

Key technical changes:
- Introduces new `odb_reprepare()` function in odb.c to centralize all ODB refresh operations
- Reduces `reprepare_packed_git()` to just `packfile_store_reprepare()` with a narrower scope
- Updates 13 call sites across various commands (gc, repack, fetch, etc.) to use the new function
- Maintains the same locking behavior and sequence of operations
- Documents the new functions in odb.h and packfile.h headers

The change affects core operations in packfile.c while touching several command implementations that need to refresh object state. This continues the series' pattern of cleanly separating packfile management from the broader object database infrastructure, with all behavioral invariants preserved during the refactoring. The patch appears mechanically sound with thorough call site updates and clear documentation of the new division.
