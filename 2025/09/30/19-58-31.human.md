This is a documentation patch in Julia Evans' v4 series improving explanations of upstream branch behavior in Git's man pages. It adds a new "UPSTREAM BRANCHES" section to `urls-remotes.adoc` to centralize information about this important concept that was previously scattered across multiple commands' documentation.

The patch addresses user confusion about what "upstream branch" means by providing a comprehensive explanation of how upstream branches work in Git's workflow. It covers automatic upstream configuration (during clone, with `push.autoSetupRemote`, and when checking out remote branches), how upstreams affect commands like `git status` and `git pull`, and where this information is stored in the config file. The section also clarifies Git's dual terminology ("upstream" vs "tracking") while standardizing on "upstream branch" as the primary term.

This is part of a larger effort to improve documentation clarity around Git's remote operations, particularly following discussions about the divergence between `push.default=simple`'s original design and current behavior. The patch maintains technical accuracy while making the information more accessible to users who may not realize their branches have upstreams or understand how they're used.
