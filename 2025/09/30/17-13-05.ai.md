Maintainer feedback on reflog write config handling fix.

Junio Hamano provides review comments on Michael Lohmann's v2 patch fixing the `git reflog write` command's config handling. While the technical solution is sound, Junio suggests several improvements to the implementation and test coverage.

First, he recommends rewording the commit message to more clearly indicate the missing `repo_config()` call was the root cause of the configuration oversight. This would help future readers understand the fix's intent.

The more substantive feedback concerns the placement of the config reading logic. Junio notes that while the current placement works, it's not architecturally ideal - config reading should happen before `parse_options()` to properly support future command-line overrides. He also raises the question of whether this logic belongs in the top-level `cmd_reflog()` rather than the write subcommand, anticipating future subcommands that might need similar config handling.

For the tests, Junio suggests two enhancements: adding a case verifying environment variables still override config values (complementing the existing test that verifies config works without environment variables), and using `$GIT_COMMITTER_DATE` instead of a hardcoded timestamp to make the test more robust against future test additions.

This feedback doesn't indicate any fundamental problems with the fix, but rather focuses on making the implementation more future-proof and the test coverage more comprehensive. The suggestions align with Git's architectural patterns and testing best practices.
