The thread discusses the potential deprecation of `git whatchanged`, a legacy command that duplicates functionality available through `git log`. The discussion was prompted by the addition of a deprecation warning that requires users to pass `--i-still-use-this` to continue using the command, intended to identify real-world usage patterns rather than block usage outright.

Stephen Harding reported active use via an oh-my-zsh alias (`gwch`) that invokes `git whatchanged` with specific formatting flags (-p --abbrev-commit --pretty=medium). Kristoffer Haugsbakk confirmed the technical redundancy with `git log` and suggested migration paths, noting that adding `--no-merges` might better match common usage patterns.

Junio Hamano has now clarified the deprecation approach, explaining that the flag requirement aims to uncover unanticipated use cases rather than prove usage statistics. He provided a direct translation for Harding's alias, showing how to achieve the same output with `git log --no-merges -p --abbrev-commit` (noting that `--pretty=medium` is already the default for `git log`). This moves the discussion forward by both validating the reported usage pattern and demonstrating a clean transition path, while maintaining the original goal of gathering information about edge cases before any final removal decision.
