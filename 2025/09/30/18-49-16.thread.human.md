This thread discusses the planned deprecation of `git whatchanged`, a legacy command whose functionality is fully covered by `git log`. The discussion began with the introduction of a new `--i-still-use-this` flag to track active usage patterns before removal. Stephen Harding identified one important real-world use case - the oh-my-zsh shell alias `gwch` that maps to `git whatchanged -p --abbrev-commit --pretty=medium`.

Junio Hamano, the Git maintainer, clarified that the flag serves only to gather usage data rather than block removal, and provided a complete migration path showing how to replace the alias with equivalent `git log` flags (`--no-merges -p --abbrev-commit`). The latest email confirms this resolution, with Harding acknowledging the clear migration path and noting that `--pretty=medium` is redundant since it matches `git log`'s default formatting.

With this shell alias case now addressed, the deprecation appears to be proceeding smoothly. The main remaining question is whether other unanticipated use cases will surface before final removal. The thread demonstrates the project's careful approach to command-line simplification - identifying real usage patterns, providing clear migration paths, and gathering data before making breaking changes. Documentation updates may be needed to help users transition, particularly those relying on similar shell aliases.
