This thread discusses the potential deprecation of `git whatchanged`, a legacy command that duplicates `git log` functionality but with different default formatting. The discussion began with a deprecation warning that now requires users to pass `--i-still-use-this` to keep using the command, aiming to track real-world usage. Stephen Harding reported active usage via an oh-my-zsh alias (`gwch`) that maps to specific formatting flags (`-p --abbrev-commit --pretty=medium`), providing concrete evidence of workflow dependencies.

Kristoffer Haugsbakk's follow-up reinforces the technical rationale for deprecation, noting the commands have been functionally equivalent for over 12 years. He suggests a straightforward migration path for Harding's alias—switching to `git log` as the base command while preserving the formatting flags, possibly adding `--no-merges` to match common `whatchanged` usage patterns. The exchange highlights both the redundancy of the command and the practical considerations for users who rely on it, with maintainers seeking to balance cleanup efforts with respect for established workflows. The thread remains open to further usage reports that might influence the final deprecation timeline.
