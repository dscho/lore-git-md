Bugfix for `git reflog write` to properly respect user configuration. This patch addresses an inconsistency where the `reflog write` subcommand was ignoring local `user.name` and `user.email` settings, falling back to system defaults instead. The issue was masked in testing because the test suite always sets committer environment variables.

The fix is straightforward - adding a call to `repo_config(repo, git_ident_config, NULL)` to properly initialize Git's identity handling before writing reflog entries. Michael Lohmann (with co-authorship from Patrick Steinhardt) also includes a new test case that verifies the fix by unsetting environment variables and checking that local config values are properly used.

This aligns `reflog write` with Git's standard configuration handling patterns and fixes a real usability issue where users' configured identities weren't being respected. The patch appears well-constructed with both the code change and corresponding test coverage. The commit message clearly explains both the problem and solution.
