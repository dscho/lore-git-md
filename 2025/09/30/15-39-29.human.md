This is a discussion about cherry-pick tracking mechanisms in Git, continuing the thread about alternatives to the current "(cherry picked from commit X)" trailer format. Junio Hamano provides historical context about why the current implementation uses just a commit hash - it was designed for public commits within the same project (like Linux kernel maintenance branches) before reference formatting existed. He explains how the feature evolved from being default-on to opt-in due to problems with private branch cherry-picking creating useless references.

The email reinforces Oswald Buddenhagen's earlier suggestion that git-notes would be a better solution than message modification, noting notes' advantages of being addable after-the-fact and supporting bidirectional linking. Hamano's historical perspective helps explain why the current system exists in its limited form while acknowledging the tracking limitations compared to centralized VCS systems like Subversion.

This moves the discussion forward by validating the notes-based alternative while providing important context about the current system's origins and constraints.
