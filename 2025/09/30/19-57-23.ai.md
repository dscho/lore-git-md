This is a follow-up in the `git whatchanged` deprecation discussion thread. Kristoffer Haugsbakk responds to Stephen Harding's report of active usage via an oh-my-zsh alias, confirming the command's redundancy with `git log` while suggesting a migration path.

The email notes that `git whatchanged` has been functionally equivalent to `git log` for over 12 years, differing only in default output. Haugsbakk proposes that Harding's specific alias (`git whatchanged -p --abbrev-commit --pretty=medium`) could be replaced with `git log` as the base command, possibly adding `--no-merges` to match common `whatchanged` usage patterns.

This response reinforces the technical rationale for deprecation while providing practical advice for users needing to transition.
