This is a discussion about improving cherry-pick tracking in Git, specifically responding to Rasmus Villemoes' proposal for customizing the cherry-pick reference message.

Oswald Buddenhagen agrees with the general need for better cherry-pick tracking but suggests an alternative approach using git-notes for bi-directional linking between commits rather than modifying the cherry-pick message format. They note that the current "(cherry picked from commit X)" format is already a compromise from Git's early ideological stance against cherry-picks, and point out that other version control systems like Subversion and Perforce handle this tracking better despite their limitations.

The email provides a concrete example of how they currently manually modify these messages to indicate partial cherry-picks or source repositories. While not rejecting the original proposal outright, Buddenhagen's suggestion of using git-notes would provide more robust tracking capabilities without changing the core cherry-pick behavior. This represents a different technical approach to solving the same underlying problem of tracking backports across versions.
