This thread continues the complex planning for Git 3.0's SHA-256 interoperability work, which has been a major focus since the Contributor Summit. The core tension remains between moving forward with the release timeline and ensuring ecosystem readiness, particularly for platforms like NonStop that face Rust toolchain challenges.

brian m. carlson has been driving much of the technical and coordination work, maintaining an informal October 2026 target while acknowledging the need for flexibility. The discussion has evolved from high-level concerns to concrete process design, with recent emails focusing on how to gather meaningful progress reports from stakeholders. While some projects like libgit2 and Forgejo already have partial SHA-256 support, others may need more time or can only provide limited status updates.

The latest contribution from brian suggests a pragmatic middle ground for progress reporting - accepting varying levels of detail from different types of stakeholders (open source projects versus companies), while still aiming for concrete enough information to make informed timeline decisions. This builds on earlier proposals for phased engagement but adds nuance to how readiness might be assessed. The thread shows growing consensus that unresponsive stakeholders shouldn't indefinitely block progress, though platform-specific concerns like NonStop's Rust availability remain unresolved.
