This is a documentation patch in Julia Evans' v4 series improving explanations of upstream branch behavior in Git's documentation. It adds a new "UPSTREAM BRANCHES" section to `urls-remotes.adoc` that consolidates scattered information about upstream branches from various man pages into one central location.

The patch addresses user confusion about the term "upstream branch" by providing a comprehensive explanation of how upstream branches are used across Git commands (`pull`, `push`, `fetch`, `status`, `checkout`). It documents both explicit configuration methods (`--set-upstream`, `--track`) and automatic setup scenarios (cloning, `push.autoSetupRemote`, checking out remote branches). The section also explains the configuration storage format in `.git/config` and notes the dual terminology ("upstream" vs "tracking") used in different parts of Git's documentation.

Key technical details include:
- The relationship between local branches and their upstream counterparts
- How upstream branches affect default behavior in various commands
- Configuration options that influence upstream behavior (`branch.<name>.pushRemote`, `push.default=simple`)
- Automatic upstream setup scenarios (cloning, first push with `push.autoSetupRemote`)
- The patch maintains consistency with Junio Hamano's terminology guidance while improving clarity

This continues the series' effort to better document the divergence between original design constraints and current implementation behavior regarding upstream branches, particularly around `push.default=simple`. The new section provides foundational knowledge that will help users understand subsequent documentation about push/pull behavior.
