This is part of the ongoing color handling refactoring series, specifically patch 7/13. It focuses on making color handling in the diff subsystem more type-safe by properly using `git_colorbool` enums rather than boolean values.

The patch addresses a subtle but correct behavior in `emit_hunk_header()` where `ecbdata->color_diff` was being used both as a `git_colorbool` (passed to `diff_get_color()`) and as a strict boolean (for reverse color). While the current implementation works due to `want_color()`'s idempotence, the patch makes this more explicit and consistent by:

1. Changing the direct boolean check to use `want_color()` explicitly
2. Passing through the raw `git_colorbool` value from callers rather than pre-converting it to a boolean with `want_color()`

The changes affect three locations in diff.c:
- The hunk header emission logic
- Rewrite diff handling
- Builtin diff functionality

This is a quality-of-life improvement that makes the code more maintainable by being explicit about color handling types, though it doesn't change observable behavior. The patch is small (6 lines changed) and focused, touching only the diff subsystem. It builds on the series' broader goal of enum-ifying color parameters and follows the pattern established in earlier patches of the series.
