Patch 8/13 in the color handling series: A refactoring of pretty-format color type safety.

This patch changes how `auto_color` is handled in the pretty-print formatting code when processing `%C(auto)` placeholders. Previously, the code would immediately convert the color setting to a boolean via `want_color()`, then store that boolean in `format_commit_context.auto_color`. The new approach stores the original `git_colorbool` enum value instead, only calling `want_color()` when actually needed for the color decision.

The change improves type safety by maintaining the enum type through more of the call chain, though the behavior remains identical due to `want_color()` being idempotent. The patch is small (4 lines changed) and focused on pretty.c, specifically around the `%C(auto)` handling logic. It continues the series' theme of making color handling more type-correct by reducing boolean/color enum confusion.

Key technical details:
- Changes `format_commit_context.auto_color` from boolean to `git_colorbool`
- Moves `want_color()` call to the single usage site rather than at storage time
- Maintains identical behavior through `want_color()` idempotence
- Affects only pretty.c's handling of `%C(auto)` color codes
- Part of broader enum-ification effort in the series
- Builds on previous patches' introduction of proper color enums

This is a straightforward quality improvement that aligns with the series' goals, though reviewers should verify the moved `want_color()` call doesn't introduce any subtle timing differences in color evaluation. The change is mechanical and well-contained within the pretty-formatting subsystem.
