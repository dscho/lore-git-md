This is part 2 of a 6-part refactoring series to establish object database transaction interfaces, moving code from bulk-checkin to object-file to enable pluggable backends. The patch focuses on modifying `update-index --verbose` to properly handle object database transactions.

The change addresses an awkward interaction where `update-index --verbose` was previously calling `flush_odb_transaction()` to make objects visible without actually ending the transaction. This patch simplifies the behavior by fully ending the transaction when `--verbose` is encountered, causing subsequent object writes to happen outside a transaction (and thus be immediately visible). The commit message explains this matches the existing behavior while being more straightforward.

The change moves the transaction handling logic from the `report()` function to where options are processed, and replaces the flush operation with a full transaction end. This appears to be a clean improvement to the series' overall goal of clarifying transaction boundaries, though it does mean that later objects in the same `update-index` invocation won't benefit from transactional batching if `--verbose` appears early in the command. The patch maintains compatibility with any hypothetical scripts relying on the verbose output for synchronization.

This is a focused change that fits well with the series' progression from initial NULL-return transaction model toward complete API separation. The diff shows careful attention to maintaining behavior while cleaning up the implementation.
