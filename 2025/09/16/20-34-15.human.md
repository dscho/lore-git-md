This is a follow-up in the ongoing discussion about `git clone --shallow-exclude` limitations in CI pipelines. Ben Knoble responds to Philipp Hahn's explanation of GitLab's "Merged Result Pipelines" scenario, where temporary merge commits complicate shallow exclusion.

The key clarification is that when GitLab creates a temporary merge commit "X" between the topic branch and master, the range `master..temp` only includes "X" itself, not the individual topic branch commits "A-B-C". Ben suggests that to properly lint all relevant commits, one should still use `master..topic` to get the individual commits, then optionally include "X" separately to lint the merge result.

This reinforces the thread's emerging consensus that shallow exclusion has inherent limitations for this CI use case, with blobless clones being the more robust alternative. The exchange helps clarify the specific workflow challenge while maintaining focus on practical solutions rather than protocol changes.
