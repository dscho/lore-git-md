This is a bugfix patch in Jeff King's ongoing series to improve Git's color handling code. It specifically addresses type safety issues in how color boolean values are stored and passed around.

The patch converts variables storing `git_colorbool` enum values from `int` to the proper enum type across 23 files. While this doesn't change behavior (C will still implicitly convert between enums and ints), it makes the code's intent clearer and could help catch some misuse patterns where color enums are incorrectly treated as simple booleans.

Key technical changes:
- Changes declarations of color-related variables from `int` to `enum git_colorbool`
- Updates function signatures like `want_color_fd()` to take the enum type
- Adds missing `#include "color.h"` to `log-tree.h` to fix a CI failure
- Affects color handling in commands like branch, commit, push, and config
- Maintains all existing behavior while improving type safety

The patch is a straightforward mechanical conversion that builds on the series' goal of making color handling more robust. It follows up on earlier corrections to patches 3 and 5 in the series, with Jeff noting he's trying to avoid needing a full v2 resend for this small fix.
