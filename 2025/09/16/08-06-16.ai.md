This is a follow-up discussion on the `git-repo-info --all flag` feature patch. Patrick Steinhardt, one of the mentors for this GSoC project, suggests reconsidering the design approach rather than adding a new `--all` flag.

The main proposal is to change the default behavior of `git repo-info` when no arguments are given - instead of silently doing nothing (current behavior), it would output all available fields by default. This would make the command more discoverable while maintaining its experimental status. Patrick argues the current silent behavior isn't useful and the experimental nature of the command allows for such behavioral changes.

Technical points raised:
- The `print_field()` helper extraction could be split into a separate preparatory commit for cleaner review
- Suggests simplifying the `print_all_fields()` implementation by removing intermediate `get_value` and `key` variables
- Proposes checking for empty arguments (`if (!argc)`) instead of the `--all` flag check
- Recommends restructuring the test to make field additions easier by putting each field on its own line

This continues the thread's discussion about interface design for the experimental repo-info command, shifting focus from "how to implement --all" to "whether we need --all at all". The suggestion would simplify the user interface while requiring updates to both implementation and tests from the original patch.
