This is a technical follow-up in the Rust infrastructure thread, focusing on Windows platform support and build system concerns. Ezekiel Newren raises several implementation-level issues with Patrick Steinhardt's v5 Rust series that was recently acked by Junio, particularly around build system integration and modularity.

The email outlines key technical gaps in the current approach: the Makefile's inability to properly handle Rust builds without Meson, the single-crate architecture leading to monolithic header generation via cbindgen, and insufficient CI coverage for Rust/non-Rust build variations. Newren contrasts this with his own work-in-progress solution that uses a `build_rust.sh` wrapper called by both Make and Meson, advocates for multi-crate modularity, and emphasizes Cargo's primacy over Meson for Rust builds.

Notable technical specifics include the libgit.a location problem during `cargo test`, the observation that Meson requires explicit .rs file enumeration unlike Cargo, and concerns about crates.io dependency management. The email positions these as unresolved issues that his upcoming patch series will address, particularly important for Windows support where build toolchain differences are more pronounced.

This represents a significant divergence from the v5 approach, suggesting the Rust transition may require further iteration even after the core infrastructure lands. The critique focuses on practical build system concerns rather than opposing Rust adoption itself, with Newren appearing to take ownership of resolving these Windows-specific and build integration challenges.
