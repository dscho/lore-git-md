Ben Knoble responds to Philipp Hahn's explanation of GitLab's "Merged Result Pipelines" scenario, where temporary merge commits complicate shallow exclusion. The key issue is that `master..temp` only includes the merge commit X, missing the topic branch commits A-B-C that need testing. The exchange confirms the practical limitations of shallow exclusion in this CI workflow, where the temporary merge topology breaks the expected range specification. This builds on earlier discussion establishing that while commit hash exclusion was fixed in Git 2.48, the protocol-level behavior creates crafted root commits that may not suit all workflows.
