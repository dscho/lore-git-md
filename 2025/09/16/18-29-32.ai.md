This is the final version of a 6-part refactoring series that establishes transaction interfaces for Git's object database (ODB) subsystem, completing the relocation of transaction code from bulk-checkin to object-file and introducing a pluggable backend infrastructure.

The series changes include:
1. Removing ODB transaction nesting in favor of explicit NULL returns when a transaction is active, simplifying caller requirements
2. Modifying `update-index --verbose` to end transactions rather than flushing them, maintaining object visibility while removing awkward flush semantics
3. Dropping the now-unused `flush_odb_transaction()` function
4. Moving all transaction code from bulk-checkin.[ch] to object-file.[ch]
5. Renaming functions to better reflect their new location (e.g., `object_file_transaction_begin()`)
6. Introducing the public ODB transaction API in odb.[ch] with `odb_transaction_{begin,commit}()`

Key technical points:
- The public interface now consists of `odb_transaction_begin()` and `odb_transaction_commit()` in odb.[ch]
- Files-backend implementation uses `object_file_transaction_{begin,commit}()`
- Callers updated across add.c, unpack-objects.c, update-index.c, merge-ort.c, pack-objects.c, and cache-tree.c
- NULL-safety paired with nesting removal ensures safe no-op behavior
- Transaction state tracked via `struct object_directory`'s `transaction` field
- Bulk-checkin.[ch] files removed entirely (403 lines added, 438 removed)

The series resolves all previous discussion points around transaction behavior and API design, with only minor documentation updates remaining. It establishes the foundation for future pluggable ODB backends while maintaining current functionality for the files backend. The changes have been reviewed and approved by key maintainers, with safety guarantees validated by Junio Hamano.
