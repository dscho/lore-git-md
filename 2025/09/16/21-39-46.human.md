This is a feature proposal addressing a workflow issue in Git's rebase behavior. Antonio Mennillo presents `git-rebase-clean`, a userland tool that mitigates cascading conflicts during rebases of semantically dependent commits by first squashing the feature branch.

The core problem identified is that when rebasing a series of interdependent commits (like interface changes followed by their implementations), Git's commit-by-commit replay can trigger repeated conflicts that require reconstructing context across multiple resolutions. The proposed solution squashes the branch first, concentrating conflicts into a single resolution point at the cost of losing commit granularity.

The tool has seen several months of real-world use with reported benefits: processing 30-40 feature branches with reduced conflict resolution time, though with occasional IDE-specific issues when handling large conflict sets. The author seeks feedback on whether this represents an expected limitation of Git's design, if the pattern merits documentation in Git's official guidance, and whether there are better existing solutions.

Notably, the tool's licensing has transitioned to AGPL-3.0 for newer versions while maintaining MIT for historical releases, showing consideration for open source norms. The proposal is framed as an RFC, with the author explicitly open to adapting the approach based on community feedback. The email demonstrates thoughtful analysis of a real pain point and provides concrete usage data to support the proposed solution.
