This is the third patch in a series addressing batched reference update issues on case-insensitive filesystems, specifically focusing on file/directory (F/D) conflict detection. The patch modifies `lock_raw_ref()` in refs/files-backend.c to properly handle F/D conflicts (like 'refs/heads/foo' vs 'refs/heads/Foo/bar') by lowercasing refnames when checking for conflicts on case-insensitive filesystems.

Key technical details:
- Uses `strbuf_tolower()` to normalize refnames for comparison when `ignore_case` is true
- Maintains the existing behavior for case-sensitive filesystems
- Adds test coverage in t/t5510-fetch.sh to verify the F/D conflict detection
- Fixes an issue where lockfiles could be left behind when conflicts occurred
- Preserves the backend abstraction by handling case-sensitivity at the files-backend level rather than modifying the shared `refs_verify_refnames_available()` function

The change ensures that conflicting updates are properly rejected while allowing non-conflicting ones to proceed, addressing a pre-existing issue that was exacerbated by batched reference updates. Justin Tobler's review confirms the approach makes sense and properly handles the F/D conflict cases. The patch builds on previous work in the series that established distinct error codes for different conflict types.
