This is part of the ongoing color handling refactoring series, specifically focusing on the interactive add code. The patch changes how color decisions are handled in `add-interactive.c` to align with the rest of Git's color code.

The key change is moving from immediate boolean conversion of color settings to retaining the `git_colorbool` enum values until actual use. This matches the pattern established in daa0c3d971 (color: delay auto-color decision until point of use) that's used throughout Git's diff code. The patch modifies several functions to pass through the enum values rather than converting to booleans early, then calls `want_color()` at the point of use.

The changes affect both the interactive and diff color handling in the add-interactive code. Function signatures are updated from `int` to `enum git_colorbool`, and all call sites are adjusted to use `want_color()` when they need a boolean decision. The patch touches core color initialization functions and the main interactive prompt display logic.

This is a type-safety improvement that makes the code more consistent with Git's color handling patterns elsewhere, though as noted in the commit message, the original code wasn't technically wrong due to C's weak type system. The changes are mechanical but require careful verification that all color decisions remain correct, particularly around the AUTO color state handling.

The patch builds on earlier work in the series that standardized color handling and continues the effort to make color-related code more maintainable and type-safe.
