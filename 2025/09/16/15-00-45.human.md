This is a follow-up discussion in the completed refactoring series that moved ODB handling from bulk-checkin to object-file, establishing pluggable backend infrastructure. Justin Tobler responds to Karthik Nayak's feedback on the transaction nesting changes.

The exchange focuses on two minor documentation fixes (semantics typo and sentence flow) and the handling of nested transactions in cache-tree.c. Justin acknowledges the feedback and indicates plans to simplify the interface further in the next version by making begin_odb_transaction() return NULL when a transaction already exists, avoiding explicit global state checks.

Karthik had expressed a wish for passing parent transactions explicitly rather than deriving them from global state, calling the current approach "a great improvement" despite this limitation. Justin notes that while the ODB still needs to come from the_repository global for now, the interface will be cleaner in the next iteration. This continues the thread's pattern of refining the transaction API's ergonomics while maintaining its safety guarantees.
