This is part 8 of a 13-patch series refactoring Git's color handling code to be more type-safe and consistent. The patch focuses on the pretty-printing code that handles "%C(auto)" color formatting.

The change modifies how the `auto_color` field in `format_commit_context` is stored. Previously it stored the boolean result of `want_color()`, which would then get passed to functions expecting a `git_colorbool` enum. The patch now stores the original colorbool value instead, only calling `want_color()` when actually needed (right where the value is used). This makes the types clearer while maintaining the same behavior, since `want_color()` is idempotent.

The change is small (just 2 lines modified in pretty.c) but continues the series' theme of making color handling more type-correct. It touches the interaction between pretty-printing and color output, which is a sensitive area, but the change appears straightforward and well-contained. The commit message clearly explains the rationale and notes there's only one spot where the color evaluation needs to happen.

This patch fits into the larger series by further eliminating confusion between boolean and enum color values, building on earlier patches that introduced the `git_colorbool` type. It's a logical next step in the enum-ification effort.
