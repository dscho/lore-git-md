Refactoring patch in a series standardizing Git's color handling. This is patch 11/13 in Jeff King's ongoing effort to clean up and type-safe Git's color code.

The patch focuses on the interactive add interface (`add-interactive.c`), which currently converts color configuration to boolean values earlier than most other parts of Git. While this works (due to C's loose type system), it's inconsistent with the rest of the codebase where color decisions are typically deferred until point-of-use via the `want_color()` function.

The changes convert the interactive add code to store color settings as `git_colorbool` enum values rather than booleans, and move the `want_color()` calls to the actual usage points. This matches the pattern established in the rest of the codebase and improves type safety. The diff shows straightforward mechanical changes to function signatures and conditionals across both the implementation and header files.

This appears to be a well-justified change that brings the interactive add code in line with Git's standard color handling patterns. The patch is part of a larger, carefully considered series that has been building up these improvements systematically. The changes are behavior-preserving but make the code more consistent and maintainable.
