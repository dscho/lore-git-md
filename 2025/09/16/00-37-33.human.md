This is a revised version of the `git stash` index behavior change proposal, now using a config option rather than the breaking changes mechanism. The series has been reduced from 9 to 4 patches, with the main change being the introduction of a `stash.index` config option that makes `git stash apply/pop` restore the index by default when set to true. The author cites this as fixing a common pitfall where carefully staged changes are lost during stash application.

Key changes from v1:
- Drops the breaking changes approach in favor of a config option
- Adds `stash.index` configuration to control the default behavior
- Keeps `--no-index` as the opt-out mechanism
- Includes test updates to verify the new config-driven functionality
- Leaves some test cleanup as future work to avoid distracting from the core changes

The patch series:
1. Makes stash tests more independent (unchanged from v1)
2. Removes a blank line in t3905 (unchanged from v1)
3. Refactors stash internals to prepare for config handling
4. Implements the `stash.index` config option and updates tests

The author notes they've left some test duplication in place temporarily to get feedback on the core changes first. The implementation appears thorough, with clear motivation from real-world user pain points. The config-based approach seems like a pragmatic middle ground after Junio C Hamano's concerns about changing the default behavior for all users.

This version directly addresses the main feedback from the thread while preserving the original goal of making stash operations more intuitive. The test coverage looks comprehensive, though the author acknowledges some test modernization could still be done.
