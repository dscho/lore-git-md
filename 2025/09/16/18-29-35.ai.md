Refactoring patch in a series establishing ODB transaction interfaces. This is the third patch in a 6-part series that relocates and simplifies transaction handling code from bulk-checkin to object-file to enable pluggable backends.

The patch removes the `flush_odb_transaction()` function, which previously allowed partial flushing of transactions without completing them. The commit message explains this made the transactional interface awkward, and now that there are no remaining callers, the function can be safely removed. The functionality is consolidated into `end_odb_transaction()`, which now directly calls the underlying flush operations (`flush_batch_fsync` and `flush_bulk_checkin_packfile`).

Key technical details:
- Removes 17 lines of code (12 from implementation, 7 from header)
- Moves the flush operations directly into `end_odb_transaction()`
- Maintains the same safety checks (NULL handling, transaction validation)
- Part of the broader effort to simplify and standardize the ODB transaction API
- The change follows the series' pattern of removing intermediate APIs in favor of clearer begin/commit semantics
- No behavior change for callers since they were already using `end_odb_transaction()`
- The patch continues the series' work toward complete API separation between generic ODB-specific code

This is a straightforward cleanup that builds on the previous patches' work to establish clearer transaction boundaries. The removal of the flush function simplifies the interface while maintaining all necessary functionality through the consolidated end operation.
