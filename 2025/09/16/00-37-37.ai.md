Feature addition to `git stash` with configurable index restoration behavior.

This final patch in the 4-part series implements the core functionality of the `stash.index` configuration. When set to true, `git stash apply` and `git stash pop` will now restore the stashed index by default, with `--no-index` available to opt out. The change addresses the long-standing inconsistency where `stash push` saves the staged changes but `apply/pop` doesn't restore them by default, which has been a common source of user confusion.

The implementation adds a new `use_index` static variable in builtin/stash.c that reads from the config, defaulting to false for backward compatibility. The patch updates both `apply_stash()` and `pop_stash()` to use this value as the default for their `index` parameter. Documentation is added to config/stash.adoc explaining the new setting.

Extensive test coverage is added across multiple test files (t3903, t3904, t3905) to verify the new config's behavior with various stash operations: basic apply/pop, drop operations, pathspec handling, subdirectory cases, and interactive (-p) mode. Each test case has a parallel version that exercises the config-driven behavior. The tests confirm that staged changes are properly restored when the config is enabled, while maintaining the existing behavior when it's disabled or when `--no-index` is used.

The patch maintains the series' incremental approach, building on the preparatory refactoring from patch 3/4. It preserves all the safety checks and edge case handling from the original stash implementation while adding the new configurable behavior. The implementation avoids any conditional compilation, making the feature available to all users at runtime based on their config.
