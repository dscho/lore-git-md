This thread discusses a user experience issue with Scalar's configuration behavior. The original report from Matthew Hughes describes confusion after running `scalar register`, which silently sets several repository configuration options (including `status.aheadBehind false`) without clearly indicating their origin. The core problem is discoverability - users cannot easily determine which config values come from Scalar versus their own settings.

The discussion points center around two potential solutions: improving documentation to make Scalar's config modifications more visible, or having `scalar register` annotate the changes it makes (possibly via config comments). The issue touches on Git's broader configuration management challenges where setting provenance is often unclear.

Key technical details:
- Scalar command involved: `scalar register`
- Example modified config: `status.aheadBehind false`
- Behavior: silently sets multiple config values without indication

This raises questions about Scalar's configuration strategy and Git's config management patterns more generally. The thread may explore how to make such automated config changes more transparent to users while maintaining Scalar's optimization benefits for large repositories.
