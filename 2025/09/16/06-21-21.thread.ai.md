Thread discusses improving discoverability of Scalar's configuration modifications, originally reported by Matthew Hughes as a user experience issue where `scalar register` silently sets config values (like `status.aheadBehind false`) without clear origin indication. Patrick Steinhardt proposes a technical solution to append source comments ("# set by scalar") to config entries modified by Scalar, using `repo_config_set_multivar_in_file_gently()` in `scalar.c` instead of `repo_config_set_gently()`. This change would make Scalar's modifications immediately visible in config files while maintaining backward compatibility.

Key technical details:
- Modifies config writing in `scalar.c` to append provenance comments
- Affects all Scalar-modified configs (not just `status.aheadBehind`)
- Uses existing Git config infrastructure
- Adds trace2 logging for config operations

The solution addresses the core discoverability problem more directly than documentation improvements alone, though the thread may still discuss whether comments are the optimal mechanism versus other provenance tracking approaches. The patch is narrowly focused on the config-writing logic. Open questions include whether this approach should be generalized beyond Scalar to other Git tools that modify configs, and whether the comment format should be standardized.
