Thread discusses improving discoverability of Scalar's configuration modifications, originally reported by Matthew Hughes as a user experience issue where `scalar register` silently sets config values (like `status.aheadBehind false`) without clear origin indication. Patrick Steinhardt proposed a technical solution to append source comments ("# set by scalar") to config entries modified by Scalar, using `repo_config_set_multivar_in_file_gently()` in `scalar.c`. Matthew Hughes now supports this approach and suggests two additional improvements: adding explanatory comments in `set_recommended_config()` source code about why Scalar recommends specific configs, and reviewing whether some historical Scalar configs (like `credential.https://dev.azure.com.useHttpPath`) may no longer be universally applicable given Scalar's evolution from Microsoft project to Git-for-Windows to core Git.

Derrick Stolee responds to Junio Hamano's endorsement of documentation improvements, agreeing with the technical approach but proposing to locate explanatory content in the Scalar documentation on git-scm.com rather than in-code comments or config files. He cites better discoverability through web documentation and indicates plans to contribute documentation patches himself targeting the Scalar manpage, though notes this will require time the following week.

Key technical details:
- Core solution modifies config writing in `scalar.c` to append provenance comments via `repo_config_set_multivar_in_file_gently()`
- Documentation target now includes git-scm.com scalar docs as primary location for config rationale
- Specific configs under review for relevance: Azure-related settings
- Maintains trace2 logging for config operations
- Affects all Scalar-modified configs (not just `status.aheadBehind`)

Open questions and directions:
