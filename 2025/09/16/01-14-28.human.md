This is a bugfix for `git send-email` addressing duplicate Reply-To headers when using `--compose --reply-to` together, which causes email rejection by providers like Gmail.

Junio C Hamano reviews NeilBrown's patch that fixes an issue where the compose workflow would insert the Reply-To header twice - once in the intro message template, and again during header processing. The fix modifies the header parsing logic in `git-send-email.perl` to properly capture the Reply-To value during pre-processing, preventing the duplicate.

The review notes the patch is conceptually sound but suggests improvements to the commit message: clarifying the solution's mechanism and fixing author attribution (the email's From header doesn't match the Signed-off-by line). Junio also observes the analysis could better explain the current broken behavior to help reviewers.

While the technical solution appears correct, the review highlights the importance of clear commit message structure in the Git project - both for explaining the problem and describing fixes in an imperative style. The patch itself is a small but meaningful change to email header handling logic.
