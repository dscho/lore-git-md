Thread identity: Discussion about `git status` command suggestions for unstaging files in pre-commit vs post-commit states, initiated by Anselm Schüler with Junio Hamano participating.

Core problem: Inconsistency in `git status` suggestions - it recommends `git rm --cached` when no commits exist yet (pre-commit state) but `git restore --staged` after commits exist. Schüler finds this unintuitive despite understanding the technical rationale.

Current status: Junio explained the technical necessity - `git restore --staged` requires HEAD to reference, while `git rm --cached` works in pre-commit states by removing from index while preserving working tree file. Schüler acknowledges this but remains uncomfortable with the UX inconsistency.

Key technical details:
- `git rm --cached` removes file from index while keeping it in working tree
- `git restore --staged` resets index to HEAD state (requires existing commit)
- Fundamental difference between index and working tree behaviors
