This is part 2 of a 6-part refactoring series establishing ODB transaction interfaces, focusing on modifying `update-index --verbose` behavior to properly handle object database transactions.

The patch changes how `git update-index --verbose` interacts with object database transactions. Currently, when `--verbose` is specified, the command flushes pending objects to the main object database without ending the transaction, maintaining object invisibility during the transaction. This creates an awkward situation where the verbose output suggests objects are available when they might not be fully committed.

The change makes `--verbose` terminate the transaction entirely, causing subsequent object writes to happen outside any transaction (and thus be immediately visible). This better matches user expectations when using `--verbose` while simplifying the implementation by removing the special-case flush behavior. The patch moves the transaction handling from the report() function to the main update processing loop, ending the transaction when `--verbose` is first encountered.

Key technical details:
- Removes `flush_odb_transaction()` call from report()
- Adds transaction termination logic in main update loop when `verbose` is true
- Updates comments to reflect new behavior
- Maintains backward compatibility for scripts parsing verbose output
- Affects only the files-backend implementation (part of larger ODB abstraction effort)

This change aligns with the series' goal of cleaning up transaction semantics while addressing a specific usability issue in `update-index`. The modification is straightforward and well-explained, with clear justification for the behavior change. It builds on the transaction infrastructure established in earlier patches while simplifying one particular edge case.
