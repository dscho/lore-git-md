This is a follow-up discussion in the CI/build system thread about optimizing documentation builds in Meson. The thread has already covered the core technical approach of adding a "docs" alias target to compile documentation separately from the full build.

Karthik Nayak questions whether the new "docs" target should also be added to 'meson_options.txt' with a default true value, which would make documentation building automatic during regular `meson compile` commands. This suggests a potential gap in the current implementation where documentation might not build by default unless explicitly requested via the new target.

The thread context shows this is part of a v1 series that has already addressed naming convention concerns (supporting both "doc" and "docs" aliases) and received technical review. The current discussion appears to be a final refinement point about default build behavior rather than a fundamental issue with the approach. The series otherwise seems ready for integration, with this being one of the last open questions about whether documentation should remain opt-in or return to being built by default.
