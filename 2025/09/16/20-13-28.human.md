This is the first patch in a 13-part series refactoring Git's color handling code. It's a straightforward refactoring that replaces magic numbers (-1, 0, 1) with named constants (GIT_COLOR_UNKNOWN, GIT_COLOR_NEVER, GIT_COLOR_ALWAYS) throughout the codebase.

The change improves code readability by making color-related decisions more explicit. The patch touches 21 files across various subsystems, consistently applying the same transformation wherever color state variables are used. The author notes this builds on a 2011 change that introduced the AUTO state but didn't fully convert all color handling to use these constants.

While purely a code quality improvement, the wide scope means reviewers should verify the changes don't accidentally alter behavior. The series as a whole aims to standardize and type-safe Git's color handling, with this patch laying the groundwork by eliminating "magic number" usage.
