This is a refactoring patch in a series improving Git's color handling code. It changes `git_config_colorbool()` to return an enum type rather than an integer, making the code's intent clearer while maintaining the same behavior. The enum values match the existing GIT_COLOR_* constants (-1 for UNKNOWN, 0 for NEVER, etc.), which were previously defined as macros.

The change improves code clarity and debuggability (enum names appear in debuggers) without affecting functionality. The patch leaves callers unchanged for now, as some require more careful handling. This is patch 2 of 13 in a series that standardizes color handling across Git's codebase, building on previous work by the same author. The series appears well-planned, with this patch being a straightforward type-safety improvement.
