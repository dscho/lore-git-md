This is part of a larger refactoring series standardizing Git's color handling code, specifically patch 6 of 13. The change focuses on the diff subsystem's color parameter passing.

The patch simplifies how color preferences are passed to `fill_metainfo()` in diff.c. Currently, the code calculates a boolean value using `want_color(o->use_color) && !pgm`, then passes that to `diff_get_color()` which re-evaluates it through `want_color()`. While this works (due to `want_color()` being idempotent), it's unnecessarily convoluted.

The change makes the boolean calculation more direct by passing the `git_colorbool` enum value directly, using `GIT_COLOR_NEVER` when `pgm` is present (indicating an external diff program) and the original `o->use_color` value otherwise. This aligns with the series' broader goal of using proper enum types for color handling rather than implicit boolean conversions.

Key technical details:
- Modifies the `fill_metainfo()` call in `run_diff_cmd()`
- Replaces boolean logic with direct enum passing
- Maintains identical behavior while being more type-correct
- Touches only 1 line in diff.c
- Part of systematic enum-ification of color variables across the codebase

This is a straightforward cleanup that makes the code more maintainable while preserving all existing behavior. It's a small but meaningful step in the larger color handling standardization effort.
