This is part 2 of a 13-patch series refactoring Git's color handling code. The patch focuses on type safety and code clarity by converting the return type of `git_config_colorbool()` from `int` to a new `enum git_colorbool` type.

The change replaces the existing macro-defined constants (GIT_COLOR_UNKNOWN, NEVER, ALWAYS, AUTO) with proper enum values while maintaining the same numeric values. The author notes this makes the code's intent clearer to human readers and improves debuggability since enum names are visible in debuggers. The patch updates the function declaration in both color.c and color.h but deliberately leaves callers unchanged for now, as some require more careful handling.

Key technical details include:
- New enum definition in color.h with same values as previous macros
- Function signature change in both implementation and header
- Callers not yet updated (to be handled in later patches)
- Maintains backward compatibility since enums can still be assigned to ints

This is a straightforward refactoring that improves type safety without changing behavior. It's part of the series' broader goal of standardizing color handling across Git's codebase. The change is low-risk since it doesn't yet modify any call sites, and the enum maintains binary compatibility with existing code.
