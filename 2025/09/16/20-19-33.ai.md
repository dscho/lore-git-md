This is a performance optimization patch in the color handling series, specifically addressing color-moved detection in diffs. The patch fixes a subtle issue where `diff_setup_done()` was using a strict boolean check on `use_color` (which can be in AUTO/UNKNOWN states) to disable color-moved detection, leading to unnecessary line detection work even when colors would ultimately not be shown.

The key changes are:
1. Removes the premature `use_color` check in `diff_setup_done()` that was incorrectly handling AUTO/UNKNOWN states
2. Moves the color availability check to `diff_flush_patch_all_file_pairs()` where it properly uses `want_color()` to respect pager configuration
3. Maintains the same output behavior while providing a measurable 4% performance improvement in non-coloring cases (demonstrated with benchmarks)

The patch builds on daa0c3d971's color evaluation timing and shows how the enum-based color handling enables more precise performance optimizations. It touches only diff.c but affects core diff functionality, particularly interacting with the color-moved feature. The change is well-motivated by both correctness (proper handling of AUTO state) and performance, with clear benchmark evidence provided.
