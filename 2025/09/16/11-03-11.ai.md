Implementation discussion for git stash --only-unstaged feature, focusing on documentation and conflict handling. Phillip Wood responds to Ben Knoble's concerns about the current --keep-index example in git-stash documentation, which implies working tree modifications during testing without warning about likely conflicts.

Wood confirms that conflicts will occur when popping the stash if any staged changes were edited during testing, though conflicts may be avoided for lines that matched across index and worktree at stash creation. He agrees the documentation should be updated to clarify this behavior, though notes the example isn't technically incorrect as written.

The discussion reveals two potential paths forward: either update the documentation to explicitly mention expected conflicts (simpler solution), or modify the stash pop behavior to avoid conflicts entirely by implementing Wood's earlier script-based approach (more complex but better user experience). Wood indicates preference for the latter solution if user feedback confirms the script's usefulness, but awaits input from J. Dettweiler who originally raised the workflow need.

Key technical details mentioned include the conditions triggering conflicts (editing staged-change lines) and the distinction between staged/unmodified line handling. The thread shows the proposal progressing from design validation to concrete implementation choices, with documentation accuracy emerging as a parallel concern alongside the core feature development.
