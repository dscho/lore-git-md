This is patch 9/13 in a series refactoring Git's color handling code, focusing on type safety improvements. The patch systematically changes variables storing color configuration from `int` to the proper `enum git_colorbool` type across 23 files. While this doesn't change runtime behavior (C freely converts between enums and ints), it makes the code's intent clearer and helps document which variables are meant to hold color configuration values (GIT_COLOR_NEVER/ALWAYS/AUTO/UNKNOWN).

The changes are mechanical but wide-ranging, touching core color handling, diff/grep, and various builtin commands. Key subsystems affected include diff color handling, grep output coloring, commit formatting, and transport/remote output. The patch maintains all existing behavior while making the type system better reflect the intended usage of these variables.

The author notes this could have come earlier in the series since it's logically independent, but was sequenced after more substantive refactoring. While the compiler won't catch all potential misuses (like treating color enums as booleans), the change improves code clarity and serves as documentation of intended usage patterns. This continues the series' theme of making color handling more type-safe and self-documenting.
