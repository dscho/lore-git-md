This is the first patch in a 6-part refactoring series that establishes clearer ODB transaction interfaces, moving code from bulk-checkin to object-file to enable pluggable backends. The series is now complete and has been reviewed by key maintainers.

The patch specifically removes the nesting mechanism for ODB transactions, which previously allowed nested begin/end calls to act as no-ops. The new approach makes transaction behavior more explicit: `begin_odb_transaction()` now returns NULL if a transaction is already active, and `end_odb_transaction()` becomes a no-op when passed NULL. This change simplifies the need for explicit flushes and makes transaction semantics clearer.

The implementation touches bulk-checkin.c/h and object-file.c, removing the `nesting` counter from the transaction struct and updating documentation to reflect the new behavior. The changes maintain safety through assertions while making the API more straightforward. This foundational work enables future ODB backend improvements while preserving current functionality.
