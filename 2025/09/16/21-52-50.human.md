This is the third patch in a 4-part series fixing batched reference update issues on case-insensitive filesystems. It specifically addresses file/directory (F/D) conflicts that can occur when creating references in a single batch transaction (like 'refs/heads/foo' and 'refs/heads/Foo/bar').

The patch modifies `lock_raw_ref()` in refs/files-backend.c to properly detect these conflicts by lowercasing refnames when operating on case-insensitive filesystems. This ensures F/D conflicts are caught during the prepare phase rather than leaving orphaned lock files when the transaction later aborts. The change maintains backend abstraction by handling the case-sensitivity issue within the files backend rather than pushing it into the shared `refs_verify_refnames_available()` utility.

Justin Tobler's review notes this isn't actually related to the batched updates change from Git 2.51, but rather a pre-existing case-insensitive filesystem issue. The solution adds detection while maintaining the key behavior of allowing non-conflicting updates to proceed. The implementation includes test coverage in t/t5510-fetch.sh and handles the string memory management carefully using strbuf.

This patch completes one of the four identified conflict types in the series, with reviewers having signed off on the approach after minor documentation fixes. The changes are focused and well-contained, building toward the series' goal of robust reference handling across all filesystem types.
