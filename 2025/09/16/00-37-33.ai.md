This is a revised feature proposal for `git stash` behavior, now using a config option rather than the breaking changes mechanism. The series has been reduced from 9 to 4 patches after feedback.

The core change introduces a new `stash.index` config option that makes `stash apply/pop` restore the index by default when set to true, with `--no-index` available to opt out. This addresses the long-standing inconsistency where `stash apply` wasn't the inverse of `stash push` regarding staged changes.

Key technical changes in v2:
- Drops the GIT_BREAKING_CHANGES approach entirely
- Adds `stash.index` config (default false) to control the behavior
- Updates builtin/stash.c to check this config in apply/pop operations
- Documents the new config in stash.adoc
- Includes extensive test updates showing both old and new behavior
- Refactors config-related globals in preparation

The author notes some test files still need modernization (particularly t3903) but focuses this revision on the core functionality. The cover letter references previous discussion threads about the motivation for this change.

Notable differences from v1:
- More incremental adoption path via config rather than breaking change
- Simpler implementation without conditional compilation
- Maintains backward compatibility by default
- Still addresses the original "footgun" concern but with opt-in behavior

The thread context shows Junio C Hamano had expressed ergonomic concerns about making --index the default, which this revision addresses by making it configurable rather than mandatory. The submodule improvements noted in v1 are not mentioned here since they were tied to the breaking changes approach.
