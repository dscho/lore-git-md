Feature addition to `git stash` with new `stash.index` config option. This is the final patch in a 4-part series that makes `git stash apply/pop` restore the index by default when `stash.index` is set to true, addressing a common pain point where staged changes are lost during stash operations.

The patch introduces the new config option and modifies the `apply` and `pop` commands to respect it, while maintaining backward compatibility via the `--no-index` flag. The change is well-motivated by real user reports of accidentally losing staged changes, and the implementation follows Git's incremental approach - adding configurability rather than changing default behavior.

Extensive test coverage is added to verify the new behavior across various stash operations (apply, pop, drop) and edge cases (pathspecs, subdirectories, IFS characters). The tests demonstrate both the new config-driven behavior and continued support for the traditional workflow via `--no-index`.

This appears to be a carefully considered solution to a genuine usability issue, with thorough testing and documentation. The patch builds on preparatory refactoring from earlier in the series and maintains Git's philosophy of making behavior changes opt-in rather than breaking existing workflows.
