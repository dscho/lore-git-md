This is a bugfix patch addressing case-insensitive filesystem issues in Git's batched reference updates. It's part of a 4-patch series that has already been thoroughly reviewed and is ready for inclusion.

The patch specifically fixes a regression introduced in Git 2.51 where batched reference updates would completely fail when encountering case conflicts on case-insensitive filesystems (like having both refs/heads/Foo and refs/heads/foo). Previously, these would silently overwrite each other in serial updates, but now the transaction properly detects and reports these conflicts while allowing non-conflicting updates to proceed.

The key changes include:
1. Introducing a new `REF_TRANSACTION_ERROR_CASE_CONFLICT` error type for case collisions
2. Adding validation to detect same-transaction case conflicts via `transaction_has_case_conflicting_update()`
3. Improving user messaging to explain the filesystem limitation and suggest migrating to the reftable backend
4. Maintaining the ability to apply non-conflicting updates in batched operations

The fix affects `git fetch`, `git receive-pack`, and `git update-ref --batch-updates`. The implementation is careful to only trigger the new error for actual case conflicts within the same transaction, not all lockfile conflicts. The patch represents the final piece of a well-tested solution that has evolved through multiple rounds of review.
