This is part 9 of a 13-patch series refactoring Git's color handling code to use proper enums instead of raw integers. The patch standardizes variable types across the codebase by changing `int` declarations to `enum git_colorbool` for all color-related variables.

The change improves code clarity by making the intended usage of these variables explicit, though the author notes that C's weak enum typing means this won't catch all potential misuse (like incorrectly treating enum values as booleans). The patch touches 23 files with mechanical changes to variable declarations and function signatures, maintaining all existing behavior while making the code more type-correct.

This continues the series' theme of type safety improvements, following earlier patches that replaced magic numbers with named constants. While not fixing any bugs directly, it helps prevent future issues by making the code's intent clearer to both humans and static analyzers. The changes are widespread but straightforward, affecting core color handling as well as builtin commands like branch, commit, and push.
