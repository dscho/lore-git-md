This is a proposed enhancement to Scalar's configuration behavior, addressing the thread about making Scalar-set config values more discoverable. Patrick Steinhardt suggests adding source comments to config entries modified by `scalar register` rather than relying on documentation, since documentation could become outdated.

The patch modifies `scalar.c` to use `repo_config_set_multivar_in_file_gently()` instead of `repo_config_set_gently()`, appending "# set by scalar" comments to each config line Scalar modifies. This creates immediate visibility in the config file itself, showing which settings came from Scalar (e.g., `FSCache = true # set by scalar`).

Key technical details:
- Uses existing Git config infrastructure (`repo_config_set_multivar_in_file_gently`)
- Applies to all Scalar modifications (not just `status.aheadBehind`)
- Maintains backward compatibility with existing config writes
- Adds trace2 logging for config operations

The approach avoids the documentation staleness problem while providing direct visibility into Scalar's config changes. This seems like a pragmatic solution to the discoverability issue, though it may warrant discussion about whether comments are the right mechanism versus some other form of provenance tracking. The patch is small and focused, touching only the config-writing logic in scalar.c.
