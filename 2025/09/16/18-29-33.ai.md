This is the first patch in a 6-part refactoring series that establishes ODB transaction interfaces, moving code from bulk-checkin to object-file to enable pluggable backends. The patch focuses on removing transaction nesting behavior in favor of a clearer NULL-return model.

The change modifies the ODB transaction API to eliminate nested transactions, which previously inner transactions were no-ops. Now `begin_odb_transaction()` returns NULL when a transaction is already active, and `end_odb_transaction()` becomes a no-op when passed NULL. This makes transaction boundaries more explicit while maintaining safety - callers must check for NULL returns and can't accidentally nest transactions.

Key technical changes include:
- Removal of the `nesting` counter from `struct odb_transaction`
- Modified `begin_odb_transaction()` to return NULL for active transactions
- Simplified `end_odb_transaction()` that only act on non-NULL transactions
- Updated documentation in bulk-checkin.h to reflect the new semantics
- Adjusted `index_fd()` in object-file.c to use the active transaction directly

The patch maintains all existing functionality while making the API more straightforward. It's part of a larger effort to clean up the object database interface in preparation for pluggable backends. The changes have been carefully reviewed and validated by maintainers, with all technical concerns addressed in this final version.
