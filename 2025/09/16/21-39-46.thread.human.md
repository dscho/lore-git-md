Antonio Mennillo's `git-rebase-clean` tool continues to spark debate about how Git should handle semantically dependent commits during rebase operations. The tool proposes a three-phase approach (temporary squash, single conflict resolution, and commit reconstruction) to avoid repeated conflict resolution, particularly for cases where `git rerere` falls short. 

Elijah Newren has raised significant technical concerns about edge cases—like overlapping line conflicts and non-content conflicts—and philosophical objections about whether Git should accommodate non-atomic commit workflows at all. Mennillo acknowledges these critiques but has deferred a full response due to travel, promising to address them by Wednesday. 

The discussion has broadened beyond implementation details to a fundamental disagreement: Mennillo prioritizes practical workflow improvements, while Newren argues Git should encourage better practices rather than adapt to fragmented history. No maintainers have yet intervened, leaving the thread at an impasse until Mennillo's detailed reply or project leadership engagement clarifies whether this approach aligns with Git's design principles.
