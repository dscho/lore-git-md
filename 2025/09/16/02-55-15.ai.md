This is a follow-up discussion in the completed ODB transaction refactoring series, specifically addressing concerns about removing transaction nesting support.

Justin Tobler responds to Taylor Blau's and Patrick Steinhardt's concerns about the removal of ODB transaction nesting in the refactoring. The key points are:

1. Justin acknowledges the current implementation where nested transactions are no-ops (just incrementing/decrementing a counter) is safer for callers since they don't need to check transaction state. The proposed change would require callers to explicitly check for existing transactions.

2. The original goal was to guarantee that `end_odb_transaction()` always flushes, allowing removal of `flush_odb_transaction()` and preventing cases where callers think objects are committed when they're not (in nested transactions).

3. Justin proposes a middle ground: keep the no-op behavior for nested calls by having `begin_odb_transaction()` return NULL when a transaction exists, while still removing the internal nesting counter. This maintains safety while simplifying internals.

4. The discussion highlights the trade-off between internal simplicity (removing nesting) and caller convenience (not requiring explicit state checks). Justin indicates he'll send an updated version addressing these concerns.

This email doesn't introduce new code changes but refines the design approach based on feedback, showing the careful consideration being given to API design in this foundational refactoring. The thread demonstrates the Git community's attention to both implementation cleanliness and practical usability concerns.
