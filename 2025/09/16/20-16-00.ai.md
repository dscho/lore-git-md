This is a performance-focused bugfix in the grep color handling code, part of a larger series standardizing Git's color variable usage. The patch addresses an inefficiency where `opt->color` was being checked directly as a boolean when it's actually a `git_colorbool` enum that may be in an intermediate state (GIT_COLOR_UNKNOWN or GIT_COLOR_AUTO). While this didn't cause incorrect behavior due to later correct checks in `output_color()`, it led to unnecessary processing of match isolation for coloring that would ultimately be discarded when output was redirected.

The key technical change replaces direct `opt->color` checks with `want_color(opt->color)` to properly collapse the enum to a final boolean state. This yields significant performance improvements in non-coloring cases - benchmarks show a 1.65x speedup when grepping with redirected output (a particularly dramatic case when searching for common patterns). The patch touches only grep.c, modifying two conditionals to use the proper color state check.

This patch builds on the series' broader goal of type-safe color handling while incidentally fixing a performance issue. It demonstrates how the enum-based approach can surface optimization opportunities that weren't apparent with the previous numeric constants. The change is straightforward but impactful, showing measurable benefits from proper typing even when the original code wasn't technically wrong.
