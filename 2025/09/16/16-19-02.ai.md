This is a design discussion about the experimental `git-repo-info` command's interface, specifically responding to Patrick Steinhardt's proposal to remove the `--all` flag in favor of default-all behavior when no arguments are given.

Junio C Hamano pushes back on the idea of making no-argument invocations output all fields by default, arguing this would be problematic for scripting use cases. He contrasts interactive tools (where discoverability is important) with scripting tools (where silent behavior changes based on argument count could cause subtle bugs). The core concern is that `tool "$@"` behaving differently from `tool --all` when no arguments are passed could lead to unexpected behavior in scripts.

The email continues the thread's central debate about whether to:
1. Keep the explicit `--all` flag (current implementation)
2. Switch to implicit all-fields output when no arguments given (Patrick's proposal)
3. Or find some middle ground

This response from the project lead suggests the default-all approach may not be suitable for Git's scripting-oriented design philosophy, though the discussion remains open. The thread's key technical files (builtin/repo-info.c, docs, tests) remain relevant, with the outcome potentially affecting how field output is triggered and documented.
