This is the final patch in a 6-part refactoring series that establishes a clean ODB transaction interface, completing the transition from bulk-checkin to transaction terminology and separating the public API from files-backend implementation.

The patch introduces new public-facing `odb_transaction_{begin,commit}()` functions in odb.[ch], making the transaction interface object-source agnostic. It renames the existing implementation-specific functions to `object_file_transaction_{begin,commit}()` to clarify their scope. The changes are mechanical but important for the API separation - all callers are updated to use the new odb interface rather than directly calling the object-file implementation.

Key technical details:
- Public API now in odb.[ch] with odb_transaction_* functions
- Implementation remains in object-file.[ch] with object_file_transaction_* names
- 9 files updated to use new interface (builtin/add.c, unpack-objects.c, update-index.c, cache-tree.c, read-cache.c)
- Maintains all existing behavior including NULL transaction handling
- Completes the series' goal of separating generic ODB interface from files-backend specifics

This patch represents the culmination of the series' architectural work, providing the clean public interface that future ODB backends (like reftable) can implement while keeping the files-backend specifics properly encapsulated. The changes are straightforward renames and caller updates with no behavior modifications.
