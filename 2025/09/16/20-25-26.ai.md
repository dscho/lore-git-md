This is a refactoring patch in the color handling series, focusing on type safety improvements for the `want_color()` function and related helpers.

The patch changes the return type of `want_color_fd()` and its helper `check_auto_color()` from `int` to `bool`, making the boolean nature of these functions more explicit in the type system. The change maintains the existing behavior where boolean true/false values correspond to the numeric 1/0 used by `GIT_COLOR_ALWAYS`/`GIT_COLOR_NEVER` enum values, preserving idempotency when these values are stored in `git_colorbool` variables. The author notes this doesn't help with compiler warnings about type mixing but improves human readability.

Key technical details:
- Updates function signatures in both color.c and color.h
- Changes `check_auto_color()` to return `bool`/`false` instead of `int` 1/0
- Maintains the same implicit conversion behavior for compatibility
- Touches only 5 lines across 2 files
- Builds on previous enum-ification in the series
- Part of broader effort to make color handling more type-safe
