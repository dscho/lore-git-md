This is a follow-up discussion in the CI/build system thread about documentation build optimization in Meson.

Patrick Steinhardt clarifies a point about the `docs` option in `meson_options.txt` in response to Karthik Nayak's question. The key points:

1. The `docs` option already exists in `meson_options.txt` (it's required for all Meson options) and cannot be omitted.

2. The option is configured as an array accepting "man" or "html" values, allowing selective building of documentation types. The build is automatically enabled when at least one documentation type is selected.

This exchange resolves a minor point of confusion in the ongoing discussion about documentation build behavior in the Meson transition. The thread's main technical questions (about default build behavior and alias naming) remain open, but this clarifies how the existing implementation handles documentation option configuration. The response confirms the current approach is intentional and properly integrated with Meson's option system.
