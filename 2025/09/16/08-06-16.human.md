This is a follow-up discussion about the proposed `--all` flag for the experimental `git-repo-info` command. Patrick Steinhardt, one of the mentors for this GSoC project, suggests reconsidering the design approach.

The key proposal is to make the command print all fields by default when no arguments are given, rather than introducing a new `--all` flag. Patrick argues the current silent behavior with no arguments isn't useful, and since the command is still experimental, this behavior change would be acceptable. He notes this would simplify the interface by removing the need for an explicit flag.

Patrick also provides several technical suggestions:
1. The preparatory refactoring of `print_field()` could be split into its own commit for easier review
2. Suggests removing unnecessary temporary variables in `print_all_fields()`
3. Proposes a more maintainable test format where new fields can be added by simply appending lines

This continues the thread's discussion about edge cases and interface design, now focusing on whether to have an explicit flag versus making "all fields" the default no-arg behavior. The suggestions aim to simplify both the user interface and the code maintenance, while keeping the experimental nature of the command in mind.
