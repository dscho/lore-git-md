Matthew Hughes raised a user experience concern about Scalar's configuration behavior. After running `scalar register` in a repository, he discovered it had silently set several configuration options (including `status.aheadBehind false`) without clearly indicating their origin. This creates discoverability issues, as users may not realize which config values come from Scalar versus their own settings.

The thread explores two potential solutions: improving documentation to make these implicit behaviors more visible, or having `scalar register` annotate the config changes it makes. The discussion touches on Git's broader configuration management challenges, where the provenance of settings isn't always clear to users. The specific case of `status.aheadBehind` being modified without explicit user consent serves as a concrete example of this general problem in Scalar's workflow.
