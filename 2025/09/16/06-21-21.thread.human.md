This thread addresses how to make Scalar's configuration modifications more transparent to users, originally prompted by Matthew Hughes' report that `scalar register` silently sets config values like `status.aheadBehind false` without clear indication. Patrick Steinhardt proposed a technical solution to append source comments ("# set by scalar") to config entries, which Matthew Hughes supported while also suggesting documenting the rationale behind these settings in the source.

The discussion has evolved with maintainer input - Junio Hamano strongly endorsed adding explanatory comments in the code, while Derrick Stolee's latest contribution suggests focusing this documentation effort on the Scalar manpage at git-scm.com for better discoverability. Stolee indicates he'll personally handle these documentation updates in the coming week, though it remains open whether source code comments might still be added as Junio preferred.

The core technical approach of using `repo_config_set_multivar_in_file_gently()` to mark Scalar-modified configs remains unchanged. The thread has productively expanded from implementation details to consider both the mechanics and policy of config management - including reviewing whether historical Scalar-related configs (particularly Azure-specific settings) remain relevant as Scalar transitions from a Microsoft project to core Git. With maintainer support now clearly established, the work appears likely to proceed along two tracks: Stolee's documentation updates and potential follow-ups from Matthew Hughes on config relevance review.
