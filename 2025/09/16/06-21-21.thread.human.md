This thread explores how to make Scalar's configuration modifications more transparent to users. It began with Matthew Hughes reporting that `scalar register` silently sets various config values (like `status.aheadBehind false`) without clear indication of their origin. Patrick Steinhardt proposed a technical solution to append source comments (e.g., "# set by scalar") to config entries modified by Scalar, using Git's existing config infrastructure.

In a follow-up, Hughes supports this approach while suggesting two additional improvements: adding explanatory comments in Scalar's source code about why specific configs are recommended, and reviewing whether some historical Scalar configs (particularly Azure-specific ones like `credential.https://dev.azure.com.useHttpPath`) remain universally applicable. The discussion has now expanded to consider both the technical implementation (how to best annotate config changes) and policy questions (which configs Scalar should still be setting by default).

The thread may produce changes in several areas: the config file comment mechanism Patrick proposed, documentation of Scalar's config philosophy in the code, and potentially pruning of outdated config settings. Hughes indicates he may contribute patches to address these aspects while also seeking historical context about Scalar's evolution from a Microsoft project to its current home in core Git.
