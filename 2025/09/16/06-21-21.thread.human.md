This thread addresses how to make Scalar's configuration changes more transparent to users. It began with Matthew Hughes reporting that `scalar register` silently modifies Git configs without clear indication of origin. Patrick Steinhardt proposed a technical solution to append "# set by scalar" comments to affected config entries, which Matthew supported while suggesting additional documentation about why Scalar recommends specific settings.

The discussion has now converged on a two-pronged approach: Patrick's technical solution will mark config provenance directly in the config files, while Derrick Stolee will lead an effort to document the rationale for these settings in Scalar's web documentation on git-scm.com. Junio Hamano has endorsed this direction, and Patrick has confirmed his implementation is ready for integration. The group is also reviewing whether some historical Scalar configs (particularly Azure-related ones) remain relevant as Scalar has evolved from its Microsoft origins to become part of core Git.

With clear agreement on both the technical marking and documentation strategy, the thread is now transitioning to implementation, with Derrick taking ownership of the documentation work while Patrick's config-commenting solution stands ready for merging. This coordinated approach ensures users will have both immediate visibility of Scalar's config changes (via in-file comments) and deeper understanding (via centralized documentation).
