This is the first patch in a 13-part series refactoring Git's color handling code. It's a systematic cleanup that replaces numeric constants (0, 1, -1) with named GIT_COLOR_* constants (NEVER, ALWAYS, UNKNOWN, AUTO) throughout the codebase.

The patch touches 21 files across multiple subsystems, standardizing how color decisions are represented. The changes are mechanical replacements that don't alter behavior, just making the code more readable and self-documenting. Key changes include:
- Replacing -1 with GIT_COLOR_UNKNOWN for uninitialized states
- Replacing 0 with GIT_COLOR_NEVER for "never colorize" cases
- Replacing 1 with GIT_COLOR_ALWAYS for "always colorize" cases
- Updating related conditionals to check the named constants

The commit message explains this builds on daa0c3d971 which introduced the AUTO state but didn't fully convert existing code. This patch completes that transition, making it clearer when reading code what each color decision represents. The changes are widespread but straightforward, touching core color handling, diff/grep functionality, and several builtin commands.

This appears to be a well-scoped, mechanical change that improves code clarity without introducing behavior changes. It sets the foundation for more substantive color-related refactoring in subsequent patches of the series.
