This is part of the ongoing refactoring series to improve Git's color handling code. Patch 7/13 focuses on making the diff subsystem's color handling more consistent by properly using the `git_colorbool` enum type rather than boolean values.

The patch fixes a subtle inconsistency in `emit_hunk_header()` where `ecbdata->color_diff` was being used both as an enum (passed to `diff_get_color()`) and as a boolean (for reverse color). While this happened to work due to `want_color()`'s idempotence, the patch makes the behavior more explicit and correct by consistently using the enum type throughout the diff code.

The changes are mechanical but meaningful:
1. Updates `emit_hunk_header()` to properly use `want_color()` when needing a boolean
2. Modifies two call sites (`emit_rewrite_diff()` and `builtin_diff()`) to pass the raw enum value rather than pre-collapsing it to a boolean

This continues the series' theme of making color handling more type-safe while maintaining identical behavior. The changes are focused and well-explained, with the commit message clearly detailing both the current behavior and why the change is safe. As with other patches in this series, it's a quality-of-life improvement that makes the code more maintainable without changing user-visible behavior.
