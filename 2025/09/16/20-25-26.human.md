This is part 10 of a 13-patch series refactoring Git's color handling code to improve type safety and consistency. The patch focuses on the `want_color()` function, which determines whether color output should be enabled based on configuration and terminal capabilities.

The change makes `want_color()` return a proper `bool` type rather than an integer, better reflecting its purpose of converting the `git_colorbool` enum into a simple true/false decision. The author notes this doesn't solve all type-safety issues (since C still allows implicit conversions between types), but it makes the intent clearer for human readers. The patch maintains backward compatibility needed by existing code that stores the boolean result in enum variables.

This is a straightforward type-safety improvement that continues the series' theme of making color-related code more robust and self-documenting. The changes are mechanical but meaningful, touching both the implementation and header file.
