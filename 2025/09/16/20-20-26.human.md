This is part of a larger refactoring series standardizing Git's color handling code. Patch 6/13 in the series focuses on cleaning up type usage in the diff` subsystem.

The patch simplifies how color information flows through the diff machinery by passing the raw `git_colorbool` enum value directly to `fill_metainfo()` rather than converting it to a boolean first. The change eliminates a redundant `want_color()` call while maintaining identical behavior, since the function is idempotent. The logic also becomes more explicit by using `GIT_COLOR_NEVER` when a diff program (`pgm`) is present, rather than the previous boolean `&&` check.

This is a straightforward cleanup that aligns with the series' broader goal of making color handling more type-safe and consistent. The change is small (just one line modified) but contributes to the larger effort. The patch builds on previous work in the series that introduced proper enum types for color handling.
