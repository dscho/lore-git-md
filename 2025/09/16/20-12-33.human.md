This is a bugfix targeting Git's build system and platform compatibility on HP-UX. Michael Osipov reports two related issues with pthread detection during Git's build process on HP-UX systems.

The first issue is a misleading configure message that claims only `-pthread` and `-lpthread` will be tried, when in fact the code also tests `-mt` and an empty string. The second, more serious issue is that pthread detection can incorrectly succeed during configuration due to transitive dependencies through GNU gettext, leading to runtime failures when Git attempts to use threading functions.

The patch proposes removing the empty string option from the pthread detection logic, forcing explicit linking with `-mt`, `-pthread`, or `-lpthread`. This matches HP-UX's documented requirements where multithreaded applications must explicitly link against pthreads. The author provides a concrete example where Git's clone operation fails at runtime without this fix.

The issue appears well-researched, with references to HP-UX documentation and a similar problem reported in MIT Kerberos. The proposed change is minimal (a one-line modification to configure.ac) and comes with a clear explanation of both the symptom and root cause. Platform-specific build issues like this often require input from maintainers familiar with HP-UX, but the analysis looks thorough and the proposed solution straightforward.
