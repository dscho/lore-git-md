The patch updates all related code across four files (`builtin/log.c`, `builtin/range-diff.c`, `range-diff.c`, and `range-diff.h`), consistently changing the variable name and its usage. The commit message provides historical context, tracing the field back to its introduction in commit bd361918 and explaining why the new name better describes the field's role in passing `--[no-]notes` and `--diff-merges` options to `git log`.

This is purely a code clarity improvement with no behavior changes. The patch is well-contained and appears ready for inclusion, having already addressed all feedback from the initial review. It sets up the foundation for the subsequent patches in the series which will fix the actual notes display inconsistency.
