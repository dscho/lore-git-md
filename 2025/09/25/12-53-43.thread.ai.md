Adrian Ratiu's hook subsystem refactoring series (10 parts) modernizes Git's hook infrastructure via `run_hooks_opt`, achieving 50-60% code reduction while maintaining compatibility. The series elements include `feed_pipe_fn` for stdin streaming, `consume_sideband` output capture, and batched line feeding in receive-pack.

Patch 1 (parallel process stdin handling) v2 keeps file descriptor `0` for "no file descriptor" after determining Unix-standard `-1` would require extensive cross-codebase changes (Patrick Steinhardt and Junio Hamano's feedback). Retains callback mechanism (`feed_pipe_fn`) with context pointers and `BUG()` enforcement for input method mutual exclusion, with corrected `hook_cb_data` scope docs (Emily Shaffer's feedback).

Patch 3 (post-rewrite hook) includes `pipe_from_strbuf` callback with batched writes, planning v2 simplifications like removing unnecessary `strbuf_reset()`.

Patch 4 (pre-push hook) incorporates Phillip Wood's strbuf reuse optimization via `hook.h`'s `feed_pipe_fn` model with per-reference callback processing.

Patch 5 (reference-transaction hook) addresses Patrick Steinhardt's design concern by proposing batching 50-100 references per callback in `transaction_hook_feed_stdin`, resolving architectural discrepancy with patch 4 while maintaining functionality through `hook_cb_data` and `run_hooks_opt`. Processes transaction data in a loop while skipping `REF_LOG_ONLY` updates.

Patch 6's `consume_sideband_fn` callback needs resolution of t1416 test failures, `BUG()` enforcement, and documentation improvements (Junio's prior notes).

Patch 8 (receive-pack update hook conversion) introduces sideband output handling via new `hook_output_to_sideband` callback, replacing direct child process management with `run_hooks_opt` API. Maintains same hook arguments (refname, old_oid, new_oid) through `run_hooks_opt.args`. Emily Shaffer identified undocumented keepalive functionality (three modes: never, always, after-NUL) as potentially problematic for sideband consumers; Adrian Ratiu confirms this will be removed in v2 as it was an unnecessary addition not present in original implementation. The series continues refining implementation details and architectural approach to hook processing patterns, with the `update` hook conversion being the primary remaining discussion point.

Technical implementation spans `run-command.c` sideband support, `consume_sideband_fn` type, unified `hook.c` process management, test updates (t0061, t1416), and signal handling from run-processes_parallel(). Phillip Wood's strbuf optimizations (patches 3-4) and parallel execution safety analysis remain incorporated.
