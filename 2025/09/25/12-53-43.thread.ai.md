Thread summary: Hook subsystem refactoring series (v7, 12 parts) by Adrian Ratiu and Emily Shaffer continues progressing toward merge with incremental improvements to parallel process handling, stdin streaming, and pre-push hook stream separation. The series standardizes Git hooks on the `hook.h` API with `feed_pipe_fn`/`consume_output_fn` callbacks and parallel execution via `struct parallel_child`, converting all core hook types while preserving backward compatibility.

Key changes in v7 include: reduction from 13 to 12 patches, implementation of Jeff King's design suggestions for sideband output and child process communication, comprehensive test coverage for hook output streams (patch 1), separate stdout/stderr stream support for pre-push hook compatibility (patch 6) addressing Chris Darroch's reported regression via a new `stdout_to_stderr` flag in `struct run_hooks_opt` with design input from brian m. carlson, removal of unused `refs.c` includes (patch 8), jobs option for parallel execution (patch 9), and improved child process stdin polling (patch 10). Patch 2 introduces a named `parallel_child` structure and `child_is_working()` helper function in `run-command.c` as suggested by Junio Hamano, improving readability of parallel process state checks.

Patch 3 introduces a stdin callback mechanism for `run_processes_parallel()`, allowing callers to stream large amounts of data to child processes without buffering everything in memory. Patch 4 complements this with a `feed_pipe_fn` callback interface in `struct run_hooks_opt` specifically for hook processes, enabling stdin streaming without filesystem involvement while maintaining backward compatibility with the existing `path_to_stdin` approach. The implementation enforces mutual exclusivity between these methods via BUG checks and integrates with the parallel process infrastructure through `pp_task_cb`. Changes span `hook.c` (stdin handling logic) and `hook.h` (API documentation), with sign-offs from both original author Emily Shaffer and major contributor Ævar Arnfjörð Bjarmason.

Patch 5 converts the post-rewrite hook implementation in sequencer.c from direct `run-command` calls to the new `hook_run_opt()` interface, replacing manual child process setup and SIGPIPE handling with the hook API's built-in capabilities. The change moves hook input preparation into a `pipe_from_strbuf` callback registered via `opt.feed_pipe`, letting the hook API handle process execution and cleanup while maintaining all existing functionality. This conversion of the rebase/amend-related hook comes with sign-offs from both Emily Shaffer and Ævar Arnfjörð Bjarmason, continuing the pattern of incremental subsystem conversions.

Patch 7 converts the pre-push hook implementation in `transport.c` from direct `run-command` usage to the `hook.h` interface, replacing manual child process setup with a `run_hooks_opt` structure and moving ref iteration logic into a `pre_push_hook_feed_stdin` callback that streams ref data. It preserves the pre-push hook's stdout/stderr stream separation via the `stdout_to_stderr` flag introduced earlier, addressing Chris Darroch's regression report with design input from brian m. carlson. The implementation follows Jeff King's sideband output approach and simplifies the code by about 40 lines while maintaining all functionality, with sign-offs from both Emily Shaffer and Ævar Arnfjörð Bjarmason.

Patch 8 converts the reference-transaction hook implementation to the `hook.h` interface, moving stdin feeding logic into a `transaction_hook_feed_stdin()` callback that processes ref updates incrementally. The change eliminates manual child process setup and signal handling while maintaining the hook's ref update format and error semantics. A new `transaction_feed_cb_data` struct tracks state across callback invocations, enabling potential future batching optimizations. The patch removes now-unneeded `run-command.h` and `sigchain.h` includes, continuing the series' pattern of reducing direct dependencies. Sign-offs from Emily Shaffer and Ævar Arnfjörð Bjarmason confirm technical consensus.

Patch 9 (new) introduces parallel execution capabilities for Git hooks by adding a `jobs` option to the hook API. The change defaults to sequential execution (jobs=1) but lays groundwork for future parallelization by: adding a `jobs` field to `struct run_hooks_opt` with documentation, setting `ungroup=0` when jobs>1 to buffer output de-interleaving, adding BUG checks for invalid job counts, and preserving the existing sideband output mechanism for sequential case. The patch includes detailed ASCII diagrams showing output handling differences between sequential and parallel modes, implementing Jeff King's suggested design for maintaining output integrity while enabling future parallelization.

The series maintains all prior approvals from Patrick Steinhardt and Junio Hamano, having passed CI checks with no outstanding objections. The test additions and parallel process refactoring represent final validation and code quality enhancements rather than substantive rework, with the test file establishing verification patterns that will be referenced in future hook development. The receive-pack changes demonstrate particular attention to maintaining sideband output during transition. This completes the foundation for the next phase of hook subsystem development (config-based hooks and parallel execution) with all major technical concerns addressed and consensus reached. The latest changes continue the pattern of incremental improvements based on maintainer feedback while preserving the series' readiness for merging.
