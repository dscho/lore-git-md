Hook subsystem refactoring series (v3, 10 parts) by Adrian Ratiu and Emily Shaffer continues with patch 5/10 converting the reference-transaction hook in `refs.c` to the new callback-based API. The series introduces parallel process stdin handling via `feed_pipe_fn` in `run-command.c`, with previous patches establishing the pattern through `post-rewrite` (3/10) and `pre-push` (4/10) hook conversions.

Patch 5/10 replaces manual `child_process` setup with a `transaction_hook_feed_stdin` callback that processes ref updates one at a time, using a `transaction_feed_cb_data` struct to track state across calls. The implementation handles both OID and symbolic ref cases while skipping `REF_LOG_ONLY` updates, maintaining EPIPE error semantics without explicit SIGPIPE management. The conversion removes 48 lines of process code while adding 53 lines of logic, following the established pattern of strbuf-based streaming.

Technical progression shows: consistent application of streaming pattern across multiple hook types (post-rewrite, pre-push, now reference-transaction), elimination of manual signal handling, strbuf-based callback implementations, and maintained backward compatibility. Core infrastructure remains in `run-command.c` with `pp_buffer_stdin()` helper and `hook.c` API extensions enforcing stdin method exclusivity.

Open items from v1 persist: file descriptor `0` vs `-1` convention, pending test failures in patch 6, performance validation of reference batching (noted as potential future work in this patch), edge case testing, and non-blocking write investigation. Reviewers including Patrick Steinhardt and Junio Hamano have approved the design direction with outstanding concerns noted. Testing continues to rely on existing hook tests (`t0061-run-command.sh` for core functionality, reference-transaction tests for this conversion) without new test cases added in this patch. The series shows steady progress toward final review pending resolution of remaining test issues.
