Hook subsystem refactoring series (v2/v3 mixed, 10 parts) by Adrian Ratiu and Emily Shaffer concludes with receive-pack hook conversion and performance optimization (v2 10/10), following receive-pack update/post-update hooks (v2 9/10), parallel output control (v2 8/10), grouping behavior (v3 6/10), and parallel capture (v2 7/10). The series systematically converts hooks to a callback-based API, now completing the receive-pack pipeline with batching optimizations.

Final patch 10/10 (v2) introduces:
- `feed_receive_hook_cb` implementing 500-line input batching to avoid per-line ppoll overhead
- Preservation of sideband output via `hook_output_to_sideband` callback
- Push certificate handling moved to `prepare_push_cert_sha1`
- Sequential execution (`processes=1`) maintained for compatibility
- Complete hook state cleanup

Core infrastructure remains in `run-command.c` (`pp_buffer_stdin()`) and `hook.c` APIs. The batching optimization addresses a discovered performance regression while maintaining the series pattern of thin wrapper APIs over run-command functionality. Implementation stays focused on receive-pack.c without core hook changes.

Open items from earlier versions persist:
- File descriptor `0` vs `-1` convention unresolved
- Test failures in patch 6 (v3 grouping behavior)
- Performance validation of reference batching pending
- Edge case testing incomplete
- Non-blocking write investigation outstanding
- Version synchronization needed between parallel (v2) and grouping (v3) patches

Reviewers including Patrick Steinhardt and Junio Hamano have approved the design direction while noting these outstanding concerns. The series now covers all targeted hook conversions with receive-pack completion, though parallel execution and grouping behavior for receive-pack hooks remain future work.
