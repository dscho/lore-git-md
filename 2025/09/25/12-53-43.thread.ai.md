Thread summary: Hook subsystem refactoring series (v3, 10 parts) by Adrian Ratiu and Emily Shaffer introduces stdin handling capabilities to `run_processes_parallel()` as the foundational change enabling safe parallel execution of hooks with large stdin inputs. The series addresses final blockers in converting receive-pack, pre-push, post-rewrite, and now reference-transaction hooks to use the new callback-based API in `run-command.c` and `hook.c`.

Key technical changes include:
- New `feed_pipe_fn` callback for incremental stdin streaming to child processes, preventing buffer overflows (introduced in part 1)
- Part 2 adds `feed_pipe` callback in `struct run_hooks_opt` with associated context pointers (`feed_pipe_ctx` and `feed_pipe_cb_data`) for state management
- Part 3 converts post-rewrite hook in sequencer.c to use `hook_run_opt()` with new `pipe_from_strbuf()` callback for OID stdin feeding
- Part 5 converts reference-transaction hook in refs.c with `transaction_hook_feed_stdin()` callback and `transaction_feed_cb_data` struct managing incremental stdin generation of ref updates in "old_oid new_oid refname\n" format
- Part 6 (new) adds configurability to output grouping behavior via `ungroup` bitfield in `struct run_hooks_opt`, addressing sideband reading requirements while preserving backward compatibility
- Part 10 converts pre-push hook in transport.c to structured `run_hooks_opt` approach with new `feed_pre_push_hook_data` struct
- Strict BUG() assertions enforcing mutual exclusivity between file-based (`path_to_stdin`) and callback-based stdin approaches
- `pp_buffer_stdin()` helper managing stdin feeding with SIGPIPE handling and per-process state tracking
- Memory safety fixes across all conversions including proper strbuf initialization/cleanup in reference-transaction hook context
- Complete handling of all REF_STATUS_REJECT_* statuses in pre-push hooks and REF_LOG_ONLY filtering in reference-transaction hooks
- API naming improvements removing hook-specific "sideband" terminology per Patrick Steinhardt's feedback
- Enhanced documentation for `hook.h` and `run-command.h` interfaces, including clear specification of memory management responsibilities

The implementation maintains `struct run_hooks_opt` with configurable `ungroup` behavior and output capture via `consume_output_fn` while adding the new stdin capability. Test coverage includes EPIPE scenarios and comprehensive behavior verification. The series has addressed Junio Hamano's memory safety concerns and shows successful CI runs, with design approval from both Junio and Patrick Steinhardt. Kristoffer Haugsbakk contributed documentation accuracy reviews. The v3 iteration represents the hook modernization effort's completion, standardizing execution while preserving sequential operation (processes=1) and laying groundwork for future parallel hook execution.
