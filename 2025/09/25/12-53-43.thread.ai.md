Thread summary: Hook subsystem refactoring series (v7, 12 parts) by Adrian Ratiu and Emily Shaffer standardizes Git hooks on the `hook.h` API with parallel execution support via `struct parallel_child`, converting all core hook types while preserving backward compatibility. The series introduces `feed_pipe_fn`/`consume_output_fn` callbacks and parallel execution infrastructure, with key technical changes including: sideband output handling, separate stdout/stderr streams (notably for pre-push hook compatibility via `stdout_to_stderr` flag), jobs option for parallel execution, and improved child process I/O polling.

Final patch converts receive-pack's update/post-update hooks to the new API, implementing: ref update streaming via `feed_receive_hook_cb` callback, push certificate/option environment setup in `run_hooks_opt`, preservation of async muxer thread for sideband output, and proper cleanup of descriptors/muxer state. The conversion maintains all existing functionality while preparing for future parallel execution and config-based hooks.

New performance optimization addresses throughput throttling in parallel hook execution (reported by Kristoffer Haugsbakk, diagnosed by Jeff King) by modifying I/O polling in `run-command.c` to monitor both child input/output descriptors simultaneously, eliminating 100ms latencies while preventing deadlocks from full pipes. The change preserves sequential execution behavior while optimizing parallel case, building on prior `parallel_child` infrastructure.
