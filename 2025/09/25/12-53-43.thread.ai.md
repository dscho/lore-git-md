Thread summary: Hook subsystem refactoring series (v3, 10 parts) by Adrian Ratiu and Emily Shaffer introduces stdin handling capabilities to `run_processes_parallel()` as the foundational change enabling safe parallel execution of hooks with large stdin inputs. The series addresses final blockers in converting receive-pack, pre-push, and post-rewrite hooks to use the new callback-based API in `run-command.c` and `hook.c`.

Key technical changes include:
- New `feed_pipe_fn` callback for incremental stdin streaming to child processes, preventing buffer overflows
- `pp_buffer_stdin()` helper managing stdin feeding with SIGPIPE handling and per-process state tracking
- Memory safety fixes for receive-pack hook conversions (unfreed `receive_hook_feed_state` and `state->buf` leaks)
- API naming improvements removing hook-specific "sideband" terminology per Patrick Steinhardt's feedback
- Complete handling of all REF_STATUS_REJECT_* statuses in pre-push hooks
- Enhanced documentation for hook.h` and `run-command.h` interfaces

The implementation maintains `struct run_hooks_opt` with `ungroup` bitfield and output capture via `consume_output_fn` while adding the new stdin capability. Test coverage includes EPIPE scenarios and comprehensive verification. The series has addressed Junio Hamano's memory safety concerns and shows successful CI runs, with design approval from both Junio and Patrick Steinhardt. Kristoffer Haugsbakk contributed documentation accuracy reviews. The v3 iteration represents the likely final version pending verification of memory management fixes, positioning this as the culmination of the long-running hook modernization effort that preserves sequential execution (processes=1) while laying groundwork for future parallel hook execution.
