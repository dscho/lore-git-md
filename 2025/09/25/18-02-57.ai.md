This is the final patch in Adrian Ratiu's series refactoring Git's hook subsystem to use the modern `hook.h` interface, specifically converting the receive-pack hooks. The patch completes the series by converting the remaining receive-pack hooks to use the new infrastructure.

The key changes in this patch:
- Replaces direct process management in `run_receive_hook()` with `run_hooks_opt`
- Introduces a new `receive_hook_feed_context` struct to manage state
- Implements batched line feeding (500 lines at a time) to optimize performance
- Maintains all existing functionality including:
  - Push certificate handling (moved to `prepare_push_cert_sha1`)
  - Sideband output support
  - Push option forwarding
  - Broken reference skipping
- Reduces code by ~50% while preserving behavior

The implementation follows the pattern established in previous patches, using the `feed_pipe` callback mechanism to stream data to the hook process. The conversion demonstrates the flexibility of the new interface by handling receive-pack's complex requirements (push certs, sideband, batched input) while significantly simplifying the code.

This completes the series' goal of modernizing Git's hook infrastructure. The changes maintain backward compatibility while providing a cleaner, more maintainable codebase. The series has shown consistent quality throughout, with each patch building on tested foundations and demonstrating measurable code reduction.
