Refactoring patch in the Rust infrastructure series, specifically preparing the varint subsystem for Rust implementation by standardizing integer widths.

This patch (5/9 in v7) refactors Git's varint encoding/decoding subsystem to use explicit integer widths (`uint64_t` for values, `uint8_t` for lengths) instead of platform-dependent types like `uintmax_t` and `int`. The change is motivated by two factors: establishing platform-independent behavior (since varints are limited to 16 bytes maximum anyway) and easing the upcoming Rust reimplementation in patch 6/9. The changes touch four files (`dir.c`, `read-cache.c`, `varint.c`, `varint.h`) with straightforward mechanical conversions of type declarations and related variable usage.

Key technical details include:
- Varint value type changed from `uintmax_t` to `uint64_t` in both decode function return and encode function parameter
- Length/position tracking changed from `int` to `uint8_t` where appropriate
- All call sites updated to match new signatures, including untracked cache handling and read-cache operations
- No behavioral changes - just type safety improvements

The patch appears well-contained and properly motivated as preparatory work, with Ezekiel Newren credited for the suggestion. It follows the series' pattern of incremental, verifiable changes while maintaining compatibility with both C and upcoming Rust components. The changes align with the overall series goal of making Git's codebase more amenable to mixed C/Rust compilation while improving type safety.
