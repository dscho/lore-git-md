This is a v2 cover letter for a bugfix series addressing inconsistent Git notes handling in `git format-patch`'s range-diff output for single-commit cases. The series builds on previous review feedback and makes several improvements to the implementation and commit messages.

The core issue remains that when using `git format-patch` with range-diff on a single commit, notes display inconsistently between the main commit message and range-diff section. The range-diff would revert to default notes behavior rather than respecting the `--[no-]notes` options specified for the main output.

Key changes in v2:
1. Renamed `other_arg` to `log_arg` throughout for clarity (new patch 1/3)
2. Fixed struct initialization in `rev_info` by properly using `STRVEC_INIT`
3. Rewrote commit messages to better explain the problem and solution, particularly:
   - Added introductory context about notes handling expectations
   - Clarified the distinction between "range diff" output and "range-diff" machinery
   - Incorporated Junio's feedback about the `--no-notes` case

The series now:
1. Renames the variable for clarity
2. Adds `rdiff_log_arg` to `rev_info` struct to pass notes arguments
3. Uses this new member in `log-tree.c` to fix the single-commit case

Technical details:
- Changes span `builtin/log.c`, `log-tree.c`, `range-diff.[ch]`, and `revision.h`
- Adds test coverage in `t/t3206-range-diff.sh`

- Follows recent test hygiene practices with `test_when_finished`
