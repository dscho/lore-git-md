Bugfix for `git add -p`'s hunk splitting behavior. This is the first patch in Phillip Wood's v3 series that improves how split hunks are handled in the interactive patch interface.

The patch changes `add-patch.c` to mark all new hunks created by splitting as "undecided" rather than inheriting the selection state from the original hunk. Previously, if you split a selected hunk, all resulting hunks would remain selected, forcing users to manually navigate back to deselect any but the first one. Now each split hunk prompts for individual selection, making it easier to choose subsets while slightly increasing the work needed when keeping most of the split hunks.

The change is implemented with straightforward modifications to the hunk state handling in `add-patch.c` and includes a new test case in `t3701-add-interactive.sh` to verify the behavior. This follows Junio Hamano's preference for an unconditional behavior change rather than version-gating or configuration options, as discussed in earlier thread iterations. The patch appears well-tested and ready for merging.
