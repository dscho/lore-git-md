This is the fourth patch in a series refactoring Git's hook subsystem to use the new `hook.h` interface, focusing on converting the pre-push hook implementation in transport.c.

The patch moves the pre-push hook handling from direct `run-command.h` usage to the new `hook.h` infrastructure, maintaining the same line-by-line stdin feeding behavior to avoid excessive memory buffering. The key changes include:

1. Introducing a new `pre_push_hook_feed_stdin` callback that handles the stdin feeding logic previously done inline, with careful EPIPE handling for when hooks don't read all input
2. Simplifying the main `run_pre_push_hook` function to use the new hook API while preserving the same arguments and remote/URL passing
3. Maintaining all existing pre-push hook functionality including ref status filtering and the same stdin format

The conversion follows the pattern established in earlier patches, showing the hook.h interface's flexibility for different hook types. The patch carries signatures from all three major contributors to this effort (Shaffer, Bjarmason, Ratiu), indicating continued consensus on the approach.

This is part of a larger effort to modernize Git's hook handling with better process management and streaming capabilities, particularly important for high-volume hooks like pre-push. The implementation looks clean and maintains all existing behavior while using the new infrastructure.
