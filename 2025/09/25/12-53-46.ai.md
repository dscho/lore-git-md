This is part 3 of a 10-patch series refactoring Git's hook subsystem to use the new `hook.h` interface, focusing on converting the post-rewrite hook in sequencer.c.

The patch replaces the manual `struct child_process` setup for the post-rewrite hook with the new `hook.h` interface, introducing a `pipe_from_strbuf` helper function to handle stdin feeding via the new callback mechanism. The conversion maintains the same functionality while removing redundant signal handling (now handled by `run_processes_parallel()`). Key changes include:

1. A new `pipe_from_strbuf` callback that safely writes hook input from a strbuf while handling EPIPE and buffer management
2. Migration from direct child_process usage to `run_hooks_opt` with stdin feeding via the new callback
3. Preservation of the "amend" argument and rebase-related notes copying behavior
4. Removal of manual SIGPIPE handling since it's now managed by the parallel process machinery

The patch continues the series' pattern of maintaining three contributor signatures (Shaffer, Bjarmason, Ratiu) indicating this builds on stabilized prior work. It touches sequencer.c's hook handling while leaving the core rebase functionality unchanged. The changes are focused on the patch maintains all existing behavior, just with cleaner internal abstractions.

This conversion is part of the broader effort to standardize hook handling across Git, with future patches in the series expected to tackle other hooks like pre-push and receive-pack. The implementation here follows the patterns established in earlier patches while handling the sequencer's specific needs for stdin feeding during rebase operations.
