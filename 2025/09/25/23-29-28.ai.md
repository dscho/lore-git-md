Feature completion for the `git repo stats` series (7/7) - progress reporting.

This final patch in the series adds progress meter functionality to the new `git repo stats` command, addressing the anticipated need for user feedback during potentially long-running repository analysis. The implementation follows Git's standard progress reporting patterns with several notable technical details:

The progress meter is implemented for both reference counting (via `stats_count_references()`) and object traversal (via `stats_count_objects()`), with distinct progress messages for each phase. The system respects Git's standard progress control mechanisms - enabled by default when stderr is a tty, controllable via `--[no-]progress` option, and respecting `GIT_PROGRESS_DELAY`.

Key implementation points:
- Adds `progress` parameter threading through the counting functions
- Introduces `count_objects_data` struct to carry both stats and progress state
- Uses `start_delayed_progress()`/`display_progress()`/`stop_progress()` API
- Includes comprehensive tests verifying:
  - Progress output appears with `--progress`
  - Progress output matches expected reference/object counts
  - No output with `--no-progress`
  - Correct interaction with progress delay configuration

The patch completes the core functionality of the `git repo stats` command, which now provides both human-readable and machine-parsable output with progress feedback. The implementation maintains the series' pattern of thorough test coverage and careful API integration, using established Git progress reporting conventions. With this patch, the command appears ready for real-world use, though documentation (presumably coming in a follow-up) will be needed to make it fully user-accessible.
