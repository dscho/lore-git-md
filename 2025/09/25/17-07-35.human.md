Bugfix patch (part 2/3) addressing inconsistent Git notes display in `git format-patch` range-diffs. This is the second version of a series that fixes a subtle issue where notes display behavior differs between the main commit message and range-diff output when formatting a single commit.

The core problem is that `git format-patch` wasn't properly propagating notes-related arguments to the range-diff machinery in single-commit cases, causing the range-diff to revert to default notes behavior. This patch lays groundwork by adding a `rdiff_log_arg` member to the `rev_info` struct, moving the notes arguments storage from a local variable to the struct where it can be accessed consistently.

The changes are technically sound, with clean diffs and clear commit messages that explain both the problem and solution.
