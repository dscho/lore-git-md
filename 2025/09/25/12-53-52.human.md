This is part 9/10 in Adrian Ratiu's ongoing series to modernize Git's hook subsystem by migrating hooks to use the new `hook.h` interface. The patch converts the post-update hook in receive-pack to use the standardized hook-running infrastructure.

The change replaces a custom hook implementation with the new `run_hooks_opt()` API, similar to previous conversions in the series. Key changes include:
- Removing manual process management code
- Using the standard hook argument handling via `strvec_push`
- Supporting sideband output through the `consume_sideband` callback
- Maintaining all existing functionality while being more maintainable

This continues the series' pattern of methodically converting each hook type while preserving behavior. The post-update hook is simpler than some previous conversions (like the update hook in patch 8) since it doesn't need stdin streaming or complex output handling. The patch appears straightforward and well-contained, building on the infrastructure established in earlier parts of the series.

With only one patch remaining in the series, this represents the final stretch of the hook modernization effort that has been progressing steadily through the past several patch rounds. The changes here look clean and consistent with the series' approach.
