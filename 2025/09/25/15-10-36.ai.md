This is a bugfix patch series for `git add -p`'s hunk splitting behavior, following up on earlier discussions about how to handle state inheritance during splits. The series removes the conditional `WITH_BREAKING_CHANGES` guard that was introduced in v2, implementing Junio Hamano's suggestion to make the behavior change unconditional and revert if users complain. The changes affect how split hunks are marked in `add-patch.c` and include corresponding test updates in `t/t3701-add-interactive.sh`.

Key technical changes in this version:
- Removes all `WITH_BREAKING_CHANGES` conditionals from the code and tests
- Maintains the core behavior where split hunks are marked as `UNDECIDED_HUNK` rather than inheriting their parent's state
- Updates `recount_edited_hunk()` to properly maintain `splittable_into` counts after edits
- Simplifies test cases since they no longer need to account for both old and new behaviors
