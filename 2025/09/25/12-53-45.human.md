This is the second patch in a 10-part series refactoring Git's hook subsystem to use a new callback-based stdin mechanism, continuing work originally by Emily Shaffer and Ævar Arnfjörð Bjarmason.

The patch introduces a `feed_pipe` callback option in the hook API as an alternative to the existing `path_to_stdin` file-based approach. The key benefit is avoiding filesystem overhead when processing large hook inputs (like ref lists in pre-push hooks) by streaming data directly via callbacks. The implementation builds on the parallel process stdin callback added in the previous patch.

The changes add a new `feed_pipe_fn` callback type and related context fields to `struct run_hooks_opt`, while maintaining backward compatibility. A BUG() check prevents mixing both stdin methods. The documentation explains the performance motivation and proper usage patterns.

This appears to be a well-constructed technical foundation for the series' goal of efficient hook processing. The commit message clearly explains the benefits over the existing approach, and the implementation follows established patterns in the hook subsystem. Reviewers will likely want to verify the callback integration with parallel execution and edge cases around pipe handling.
