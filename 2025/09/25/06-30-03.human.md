This is the first patch in a 9-part series introducing Rust infrastructure to Git core, now at version 7. The series has Junio Hamano's ack and addresses previous technical feedback, particularly around Windows/MSVC compatibility.

The patch adds Meson build system support for an optional internal Rust library called "gitcore" (The name was changed from "git" to avoid Windows artifact collisions.) The Rust build is entirely optional at this stage, serving as a test balloon for both developers and distributors. The implementation includes:

1. Auto-detection of Rust toolchain availability via Meson
2. A `-Drust=` feature toggle to control Rust compilation
3. Rust unit test integration with `meson test`
4. Use of Rust 2018 edition for compatibility with gcc-rs backend

The patch sets up the basic scaffolding but doesn't yet include any actual Rust functionality - that comes in subsequent patches. The approach is conservative, using an older Rust edition to maximize compiler compatibility while still allowing future upgrades if needed.

This appears to be a well-constructed infrastructure patch that cleanly integrates Rust into Git's build system without disrupting existing workflows. It's part of a carefully planned transition where Rust will become optional in Git 2.52, default in 2.53, and mandatory by 3.0. The patch addresses previous Windows/MSVC concerns through the crate rename and build script updates.
