This is part 6 of Adrian Ratiu's series refactoring Git's hook subsystem, introducing a new feature to capture and redirect parallel process output. The patch adds a `consume_sideband` callback to `run_processes_parallel()` that lets callers intercept and process child process output rather than having it always go to stderr.

The main use case is server-side hooks that need to relay output to clients, where direct stderr output isn't suitable. The callback receives output in a strbuf, making it to be processed or forwarded without temporary files or pipes. The implementation maintains backward compatibility by falling back to stderr when no callback is provided.

Key technical points:
- Adds `consume_sideband_fn` callback type and integrates it throughout the parallel process machinery
- Disables ungrouped output when sideband capture is active (they're mutually exclusive)
- Includes test coverage demonstrating output redirection to a file
- Touches several callers (fetch, submodule, hook code) to accommodate the non-const opts change

This continues the series' pattern of careful, incremental modernization while preserving existing behavior. The change looks well-considered with thorough test coverage, addressing a real need for server-side hook implementations. As with previous patches, it carries forward signatures from the original authors (Emily Shaffer and Ævar Arnfjörð Bjarmason) whose work this builds upon.
