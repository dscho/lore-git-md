Policy documentation update announcing Rust's phased adoption timeline in Git. This patch adds a section to `BreakingChanges.adoc` detailing when Rust will become mandatory (Git 3.0, estimated second half of 2026) and the transition path:

1. Git 2.52: Rust auto-detected by Meson but disabled in Makefile
2. Git 2.53: Rust enabled by default in both build systems (but still optional)
3. Git 3.0: Rust becomes mandatory with build-time opt-outs removed

The document explains the current optional Rust components (contrib wrapper, test subsystems, non-critical features) are test balloons for distributors. It also announces a forthcoming LTS release before Git 3.0 that will receive extended support, with maintainership potentially handed to distributors. The policy includes flexibility to defer the Rust requirement if downstream impact proves too severe.

This formalizes the governance aspects of the Rust integration that were previously discussed in the thread, while maintaining the technical timeline established in earlier patches. The wording reflects feedback about maintaining distribution flexibility while committing to the eventual transition.
