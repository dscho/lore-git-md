This is part 5 of Adrian Ratiu's ongoing series to refactor Git's hook subsystem using the new `hook.h` interface. The patch converts the reference-transaction hook to use the new infrastructure while maintaining its existing behavior.

The reference-transaction hook runs during ref updates (like pushes) and receives the list of refs being modified. The patch replaces the direct child process management with the new `hook.h` API, including its stdin feeding mechanism. The key changes are:

1. The hook execution is handled by `run_hooks_opt()` instead of manual `child_process` setup
2. Stdin feeding is done via a new `transaction_hook_feed_stdin` callback that streams ref updates line by line
3. Error handling is preserved, including the special EPIPE case when the hook closes stdin early

The conversion follows the same careful approach seen in earlier patches - maintaining all existing behavior while moving to the new interface. The patch carries forward signatures from previous contributors to this work (Emily Shaffer and Ævar Arnfjörð Bjarmason), showing this is part of a coordinated effort.

This is a significant conversion as the reference-transaction hook is performance-sensitive (it handles potentially many ref updates) and has specific error handling needs. The successful conversion here demonstrates the flexibility of the new hook infrastructure.
