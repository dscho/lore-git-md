This is part 7 of Adrian Ratiu's hook subsystem refactoring series, introducing output capture capability for hooks. The patch adds a `consume_sideband` callback to the `run_hooks_opt` struct, allowing server-side hooks to redirect output (e.g., for sending over sideband to clients) rather than always printing to stderr. The change is minimal - just exposing the existing `run_parallel_processes()` capability through the hook interface.

The implementation adds the callback field to both the header and passes it through in `run_hooks_opt()`. The commit message notes this is particularly useful for server-side hooks, building on Emily Shaffer's original work. The header comment explains the field's purpose and references test-run-command.c for example usage.

This continues the series' pattern of incrementally exposing parallel process capabilities through the hook interface while maintaining backward compatibility. The change is straightforward but enables important functionality for server-client communication in hooks like `receive-pack`. The patch appears well-contained with clear documentation and proper sign-offs from previous contributors to the hook infrastructure.
