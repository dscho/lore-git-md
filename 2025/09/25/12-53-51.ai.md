Feature patch extending Adrian Ratiu's hook modernization series, converting the receive-pack 'update' hook to use the new hook.h interface with sideband output capabilities introduced in previous patches.

This patch replaces the direct child process management in `run_update_hook()` with the new `hook.h` interface, specifically utilizing the `consume_sideband` callback added in patch 7. The implementation handles three keepalive scenarios (never, always, after-NUL) through the new `hook_output_to_sideband` helper which properly formats output for the sideband protocol. Key technical details include:

- Complete rewrite of `run_update_hook()` to use `run_hooks_opt`
- New `hook_output_to_sideband` callback implementing the sideband formatting logic previously handled by `copy_to_sideband`
- Maintains all existing hook arguments (ref_name, old_oid, new_oid)
- Preserves the sideband protocol's keepalive behavior and NUL handling
- Continues the series' pattern of converting hooks while maintaining backward compatibility

The changes are focused in `builtin/receive-pack.c`, converting one of the last remaining direct hook invocations to use the modern interface. This demonstrates the series' progression toward comprehensive hook modernization, with receive-pack being a critical path for server-side operations. The patch appears well-integrated with the prior work, though as with previous conversions, real-world testing in high-volume server environments would be needed to verify edge cases.
