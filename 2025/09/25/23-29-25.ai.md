This is the 4th patch in a 7-part series introducing a new `git repo stats` command, focusing on the core statistics functionality for reference counts. The patch implements the initial version of the `stats` subcommand that categorizes and counts references by type (branches, tags, remotes, others).

The implementation introduces several key components:
- A `ref_stats` struct to track counts of different reference types
- A `stats_table` system for formatting output with auto-adjusting column widths
- The main `cmd_repo_stats()` function that drives the reference counting
- Comprehensive tests in t1901-repo-stats.sh covering empty repos and repos with various reference types

The output format mimics git-sizer's human-readable table style, with columns that automatically adjust to content width. The current implementation only handles reference counting, but the commit message notes this is just the first step toward more comprehensive repository statistics.

The patch builds on previous infrastructure work in the series (NULL pattern handling in ref-filter) and includes tests verifying the output format and count accuracy. The implementation appears thorough, with proper memory management via `stats_table_clear()` and error handling for ref filtering failures.

This represents the first user-visible functionality in the series, moving beyond preparatory refactoring to deliver actual statistics capabilities. The clean separation between data collection and presentation suggests the architecture will accommodate planned future additions like object counting and progress reporting.
