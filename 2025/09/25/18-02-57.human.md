This is the final patch in Adrian Ratiu's series refactoring Git's hook subsystem to use the modern `hook.h` interface. The patch converts the remaining receive-pack hooks to the new infrastructure, completing the series' goal of unifying hook execution across Git.

The changes replace the direct process management in `run_receive_hook()` with the `run_hooks_opt` interface, following the pattern established in previous patches. Key improvements include:

1. Simplified hook execution flow by removing manual process handling
2. Better batching of ref updates (500 lines at a time) to reduce overhead
3. Consistent sideband output handling via the new interface
4. Cleaner environment variable management for push options and certificates

The patch maintains all existing functionality while reducing code complexity. It demonstrates the flexibility of the new hook interface by handling both sideband and non-sideband cases, push certificates, and temporary object directories through the unified `run_hooks_opt` mechanism.

With this patch, the series appears complete - all major hook types have been converted to the new interface. The changes are thorough and maintain backward compatibility needed for Git's stability. Reviewers will likely focus on verifying edge cases in receive-pack's complex hook interactions, but the implementation follows the proven patterns from earlier patches in the series.
