Adrian Ratiu, with contributions from Emily Shaffer, has sent version 2 of their 10-part series refactoring Git's hook subsystem. The work modernizes hook infrastructure by introducing callback-based stdin handling (`feed_pipe_fn`) and output capture (`consume_sideband_fn`), while maintaining backward compatibility. The series converts all remaining hooks to use the new `hook.h` API, achieving significant code reduction (50-60%) in the process.

Key improvements in v2 address feedback from v1: stricter enforcement of input method mutual exclusion via `BUG()`, simplified callback patterns in post-rewrite and pre-push hooks, a redesigned reference-transaction callback to match pre-push patterns, and removal of problematic keepalive logic in update hooks. The implementation touches multiple areas including parallel process handling in `run-command.c` and hook API extensions in `hook.c`.

Two notable design decisions remain unchanged from v1: using file descriptor `0` (rather than Unix-standard `-1`) for "no file descriptor" due to `run-command.h` constraints, and keeping SIGPIPE handling outside `pp_buffer_stdin()` to avoid excessive calls. The series lays groundwork for future work on config-based hooks and parallel execution through well-documented callback patterns and resource ownership rules.

Testing shows all hook-specific tests passing, though there are some unrelated CI failures on Windows+Meson and documentation builds. Reviewers including Patrick Steinhardt and Junio Hamano have largely approved the architectural approach, with remaining feedback addressed through simplifications and documentation improvements. The series appears ready for final review pending resolution of minor test failures in patch 6's sideband handling.
