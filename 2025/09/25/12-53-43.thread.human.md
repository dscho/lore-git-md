This thread covers Adrian Ratiu and Emily Shaffer's multi-part series refactoring Git's hook subsystem to use a new structured API. The work standardizes how hooks are invoked across Git, introducing capabilities like structured stdin handling, output capture, and parallel execution while maintaining backward compatibility. The latest patch (v5 part 11) converts receive-pack's receive hooks to the new API, completing the major hook type coverage.

The series has seen thorough review from key contributors. Junio Hamano provided early input on memory safety and pipe handling, which was addressed in v3. Patrick Steinhardt's API design feedback was incorporated, and Ævar Arnfjörð Bjarmason signed off on several technical aspects including the pre-push hook conversion and output capture mechanism. Emily Shaffer (co-author) reviewed the post-rewrite hook approach. All CI runs have been successful, and performance optimizations (like batching 500 lines of input at a time for receive hooks) demonstrate the improvements.

With part 11's conversion of receive hooks, all major hook types now use the new API while preserving existing functionality like sideband output. The changes show the API's flexibility in handling both streaming input (via batched callbacks) and specialized output needs. Only final polishing patches remain in parts 11-12, marking this as a mature series ready for maintainer consideration. The work represents a significant modernization of Git's hook infrastructure that should improve reliability and maintainability while opening doors for hook-based extensions.
