This thread introduces a 10-patch series that advances the ongoing effort to modernize Git's hook infrastructure by converting remaining hook implementations to use the new `hook.h` interface. The work builds on prior contributions from Emily Shaffer and Ævar Arnfjörð Bjarmason, with Adrian Ratiu now taking the lead by contributing one new patch and rebasing/updating Emily's earlier work.

The series introduces two significant new capabilities in the hook execution APIs: the ability to feed hook stdin via a callback function (rather than fixed input), and support for collating outputs from server-side hooks. The implementation carefully maintains performance parity with existing code by minimizing copying and batching writes, particularly for high-volume hooks like pre/post-receive. Changes span multiple hook implementations (post-rewrite, pre-push, update, and receive hooks) and touch core infrastructure in `run-command.c` and `hook.[ch]`.

Technical refinements include removing the string_list API and simplifying newline handling from earlier iterations, though the author opted against a mmap-based zero-copy approach due to backwards compatibility concerns. The changes lay important groundwork for future work on config-based hooks and parallel execution. Testing appears thorough, with CI passes and integration against the `next` branch. Given the wide-ranging impact on core hook execution paths and several builtin commands, careful review will be needed—particularly around performance-sensitive areas like receive-pack.
