This is the final patch in a three-part bugfix series addressing inconsistent Git notes display in `git format-patch` when used with range-diff on single commits. The issue occurs when notes options (like `--notes=custom` or `--no-notes`) specified for the main output aren't properly passed to the range-diff section for single-commit cases.

The patch builds on infrastructure changes from the previous patches (renamed `log_arg` variable and new `rdiff_log_arg` struct member) to properly pass notes arguments to the range-diff subprocess in `log-tree.c`. It also adds a test case specifically verifying the fix works for single-commit scenarios, complementing existing tests for multi-commit cases.

The changes are focused and well-contained, touching only two files: modifying the notes argument passing in `log-tree.c` and adding a targeted test case. The commit message clearly explains the problem and solution, referencing the preparatory work done in earlier patches. The test follows modern practices with proper cleanup handling via `test_when_finished`.
