This is a review feedback email from Junio C. Hamano on patch 6/10 of Adrian Ratiu's hook subsystem refactoring series, which introduces output capture mechanism for hooks. The patch originally from Emily Shaffer adds a `consume_sideband_fn` callback to handle collated output from parallel processes, particularly useful for server-side hooks that need to relay output to clients.

Junio identifies several undocumented changes in the patch that need clarification:
1. The conversion of `const struct run_process_parallel_opts` to non-const in multiple files (fetch.c, submodule--helper.c, hook.c) isn't explained in the commit message
2. The interaction between `ungroup` and `consume_sideband` options needs explicit documentation of their mutual exclusivity
3. Suggests converting the silent mutual exclusion into a BUG() check to prevent accidental misuse
4. Notes the same unexplained const-to-non-const change in the run_processes_parallel() function signature

The technical changes involve:
- New `consume_sideband_fn` callback type in run-command.h
- `consume_sideband` field added to `run_process_parallel_opts`
- Output handling modifications in run-command.c
- Test updates in t/helper/test-run-command.c and t/t0061-run-command.sh

This continues Junio's pattern of focusing on documentation quality in his reviews of this series. While the technical implementation appears sound, the review highlights the need for clearer explanations of interface changes and their rationale, particularly around the constness changes and option interactions. The feedback suggests the patch is nearly ready but needs these documentation gaps filled before integration.
