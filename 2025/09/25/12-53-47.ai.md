This is the fourth patch in a 10-part series refactoring Git's hook subsystem to use the new `hook.h` interface, focusing on converting the pre-push hook implementation in transport.c.

The patch moves the pre-push hook from direct `run-command.h` usage to the new `hook.h` infrastructure while maintaining the same line-by-line stdin feeding behavior to avoid excessive memory buffering. Key technical changes include:

1. Introduces a new `pre_push_hook_feed_stdin` callback that handles the stdin feeding logic previously inline in `run_pre_push_hook()`. The callback processes refs one at a time, maintaining all the original filtering logic (skipping non-fast-forward, stale, and up-to-date refs).

2. The main hook execution now uses `run_hooks_opt()` with:
   - Remote name and URL passed via `opt.args`
   - The stdin feeding callback registered via `opt.feed_pipe`
   - The ref list passed as context via `opt.feed_pipe_ctx`

3. The implementation preserves all original error handling, including EPIPE tolerance when the hook doesn't read all input, while letting the parallel process machinery handle signal management.

This continues the series' pattern of maintaining identical external behavior while modernizing the implementation. The pre-push hook conversion demonstrates the interface's flexibility with streaming input - an important case given this hook's potential to process many refs. The patch carries forward signatures from all three major contributors to this effort (Shaffer, Bjarmason, Ratiu), indicating stabilized consensus on the approach.

The series appears to be progressing methodically through hook conversions, with this patch tackling one of the more complex cases due to the pre-push hook's stdin requirements. The clean separation of concerns and maintained behavior suggest this is a robust step toward the series' goal of unified hook handling.
