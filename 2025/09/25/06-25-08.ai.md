This is a discussion about the architectural direction of the new `git refs get` plumbing command, part of the broader `git-refs` subcommand consolidation effort. Patrick Steinhardt responds to Junio Hamano's skepticism about creating new subcommands versus extending existing tools like `git show-ref`.

Patrick defends the consolidation approach, arguing that having all ref-related operations under `git-refs` provides better long-term discoverability through a single entry point with tab completion and unified documentation. He contrasts this with the current fragmented state where users must remember multiple specialized commands (`show-ref`, `symbolic-ref`, `update-ref`, etc.) for different ref operations. While acknowledging documentation could help, Patrick maintains that a dedicated command family offers more natural discoverability than a reference manpage.

The exchange highlights the core tension between Junio's preference for extending proven tools versus Patrick's vision of organized subcommands. Patrick positions `git refs get` as completing the reference operation set within this new structure, though he remains open to adding DWIM behavior via flags based on earlier feedback. The discussion remains unresolved on whether the consolidation provides enough user value to justify new commands versus improving existing ones.
