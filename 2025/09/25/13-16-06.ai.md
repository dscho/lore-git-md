This is a feature patch in the `git repo stats` series, specifically addressing the keyvalue and NUL-delimited output formats. The email contains Justin Tobler's response to Patrick Steinhardt's review feedback on patch 5/6 of the series.

Key technical points from the discussion:
- Documentation will be clarified to explicitly state the table format is default
- The keyvalue format documentation currently claims `core.quotePath` handling exists but doesn't implement it; Justin prefers keeping the documentation as future-proofing
- The `stats_keyvalue_print()` function will be modified to write directly to stdout rather than using a strbuf intermediary
- The `parse_options()` call will be moved to the initial subcommand patch for consistent argument handling
- The NUL-delimited format test verification will be optimized with a single `tr` command and renamed to `expect_nul`

The discussion also notes that while the NUL format's newline-as-delimiter choice is unusual, it matches existing `git repo info` behavior. Justin considers whether to change this experimental format but seems inclined to maintain consistency.
