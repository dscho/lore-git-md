Junio Hamano weighs in on the ongoing debate about commit graph ownership in the pluggable ODB effort. He questions Patrick Steinhardt's position that each backend should independently implement commit graph support if desired, aligning more with Taylor Blau's view that commit graphs represent fundamental repository metadata rather than backend-specific optimizations.

Hamano argues that core Git operations (like commit traversal and reachability checks) fundamentally rely on commit graph data, making it cleaner to treat these as repository-wide abstractions rather than leaving them to individual storage backends. He cites examples where generic code paths already depend on commit graph optimizations, suggesting the current design implicitly assumes these auxiliary data structures exist at the repository level.

This email highlights the key philosophical divide in the discussion: whether commit graphs are (a) essential repository infrastructure that all backends must support consistently (Hamano/Blau view) or (b) optional backend-specific optimizations (Steinhardt view). Hamano's intervention as project maintainer suggests this debate may need resolution before the ODB refactoring can proceed. The thread remains active with no clear consensus yet.
