This patch introduces output capture capability to `run_processes_parallel()`, allowing callers to intercept and process child process output rather than having it always go to stderr. It's part of Adrian Ratiu's ongoing hook subsystem refactoring series (patch 6/10), building on prior work by Emily Shaffer and Ævar Arnfjörð Bjarmason.

The key addition is a `consume_sideband` callback in `run_process_parallel_opts` that receives output via a strbuf, enabling server-side hooks to relay messages to clients. The callback is invoked even when empty to support keepalives. The patch maintains backward compatibility by defaulting to stderr output when no callback is provided.

Implementation touches core process handling in `run-command.c`, modifying output buffering and dispatch logic while adding new test coverage. The changes affect several callers (fetch, submodule, hook subsystems) by making the opts struct` non-const to accommodate the new callback field. A test helper demonstrates writing captured output to a file instead of stderr.

This continues the series' pattern of incrementally modernizing hook infrastructure while preserving existing behavior. The output capture capability specifically addresses use cases where hook output needs redirection, like server-client communication in `receive-pack`. The implementation avoids new pipe creation by working directly with strbuf content.
