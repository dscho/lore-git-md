This is a refactoring patch in the Rust infrastructure series, specifically preparing the varint subsystem for Rust implementation by making integer widths explicit.

Patch 5/9 changes the varint encoding/decoding functions to use specific integer types (`uint64_t` and `uint8_t`) instead of platform-dependent types like `uintmax_t` and `int`. The change ensures consistent behavior across platforms and simplifies the upcoming Rust port, since Rust requires explicit integer types. The patch touches several files that use varints, including dir.c (untracked cache handling), read-cache.c (index operations), and the varint implementation itself.

The changes are mechanical but widespread, updating both the varint interface and its callers. The commit message notes this refactoring is particularly helpful for the Rust implementation coming in patch 6/9, as Rust's type system will enforce these width constraints. The patch appears well-scoped and properly tested, with Ezekiel Newren credited for suggesting the approach.
