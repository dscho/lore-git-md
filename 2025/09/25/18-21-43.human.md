Maintainer approval for `git add -p` hunk splitting behavior change.

Junio Hamano gives final approval to Phillip Wood's patch series that changes how `git add -p` handles hunk splitting. The key change makes split hunks always start in an "undecided" state rather than inheriting their parent hunk's selection status. While this requires users to explicitly select each split hunk (potentially adding some workflow steps), Junio argues this is ultimately better because:

1. It removes ambiguity - users no longer need to remember or deduce the current selection state of hunks they're viewing
2. It provides a more consistent mental model where splitting resets the decision process
3. It sidesteps UI issues where the current selection state isn't clearly visible

The patch includes test coverage verifying the new behavior. Junio acknowledges this might require more work in some cases (like when users want to deselect only small parts of a previously selected hunk), but believes the clarity benefits outweigh these costs. With no outstanding objections and all design questions resolved, the series is now queued for merging.
