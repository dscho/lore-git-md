This thread discusses adding boolean config parsing to Git's Rust bindings (`libgit-rs`). The initial patch series proposed implementing the logic directly in Rust, but reviewers - and now the maintainer - have made it clear this should instead wrap Git's existing C implementation through the FFI layer for consistency.

Junio Hamano has now weighed in, strongly agreeing with Phillip Wood's earlier feedback that the Rust bindings should act as safe wrappers around Git's core C functions rather than reimplementing functionality. This is particularly important for edge cases like numeric string parsing ("00", "100") where behavior might otherwise diverge. Hamano frames this as a key design principle distinguishing wrapper libraries (like `libgit-rs`) from full reimplementations (like gitoxide).

The original series also included an unrelated documentation fix for PO file formatting, which may now be split off. The author will need to restructure the boolean parsing implementation to use Git's `git_configset_get_bool()` via the FFI layer in `libgit-sys`, while maintaining the existing test coverage and safety guarantees. This maintainer input effectively settles the architectural direction for the feature.
