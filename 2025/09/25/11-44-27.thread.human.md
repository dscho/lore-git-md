This thread involves a patch series adding configuration value parsing to the Rust implementation of libgit, now at version 4. The series implements boolean, unsigned long, and pathname parsing through FFI-wrapped C functions, maintaining consistency with existing methods. 

The initial discussion led to separating out a documentation fix into its own thread, fixing boolean symbol exports, and consolidating the changes into a single commit. The v4 patch was rebased onto the current mainline and includes comprehensive test coverage for all three methods.

Phillip Wood has now reviewed v4 and raised one key technical concern: the handling of `c_ulong` types in Rust versions prior to 1.64 (like Debian oldstable's Rust 1.63). The current implementation assumes `u64` as a fallback, which may not match C's platform-dependent `ulong` size. Wood suggests splitting this into two changes - first updating fallback definitions to use `std::os::raw` types (available before Rust 1.64), then adding proper `c_ulong` support separately. He also recommends documenting the UTF-8 requirement for path parsing in the commit message.

Apart from this platform-specific type handling issue, Wood indicates the implementation looks good. The series has addressed all previous feedback points and appears ready for merging once this final technical refinement is made. The author now needs to decide whether to implement Wood's suggested approach or propose an alternative solution for the platform compatibility concern.
