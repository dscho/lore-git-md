This thread concerns a two-part patch series adding boolean configuration parsing to the Rust libgit implementation (`contrib/libgit-rs`). The first patch implements a `get_bool()` method in Rust's `ConfigSet` module, while the second fixes some markdown formatting in the translation documentation.

The initial implementation appeared technically sound, with Chris Torek providing minor feedback about improving error message phrasing. However, Phillip Wood has raised a more substantial architectural concern: rather than reimplementing boolean parsing in Rust, the patch should expose Git's native C implementation (`git_configset_get_bool()`) through the FFI layer first, then wrap it in Rust. This would ensure perfect behavioral consistency with Git's core, particularly for edge cases like numeric values ("00", "100") that the current Rust implementation might parse differently.

Wood's feedback doesn't reject the feature - he explicitly welcomes the contribution - but suggests significant restructuring across both the `libgit-sys` (FFI) and `libgit-rs` layers. The documentation formatting fix, while correct, may now be split off as a separate submission since the boolean implementation will need a redesign. The author will likely need to send a v2 series addressing both Torek's phrasing suggestions and Wood's architectural guidance.
