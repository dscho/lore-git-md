Git maintainer Junio C Hamano responds to a feature request about `git stash`'s untracked file visibility. This is part of an ongoing discussion about whether `stash.showIncludeUntracked` should default to true, making stashed untracked files visible by default in `git stash show`.

Hamano acknowledges the merit of the proposal, noting that when users explicitly stash untracked files (using `-u`), it's reasonable to show them by default. He points out this would be a behavior change requiring a major version bump (Git 3.0), but seems generally supportive of the idea. Interestingly, he suggests the existence of the configuration option itself might have been unnecessary - implying the behavior should perhaps always show stashed untracked files without requiring configuration.

The response maintains the technical context from earlier in the thread (that untracked files are stored in stash^3) while focusing on the interface design question. Hamano's tone suggests this change has a decent chance of being accepted, though it would need to wait for a major version release. The discussion has evolved from a specific data-loss bug report to considering broader usability improvements to `git stash`'s default behavior.
