Bugfix for `git add -p` hunk splitting behavior in `add-patch.c`. This patch implements the final agreed-upon solution from the thread, marking all split hunks as UNDECIDED_HUNK rather than inheriting the parent hunk's selection state.

The change makes split hunks require explicit selection, addressing the previous issue where users had to navigate back to deselect inherited selections. While this means more work when keeping all split hunks selected, it provides better control when only wanting subsets. The implementation is now unconditional, following Junio Hamano's guidance to avoid version-gating or configuration options.

Key technical details:
- Modifies `split_hunk()` in `add-patch.c` to set `use = UNDECIDED_HUNK` for all new hunks
- Updates both the initial split hunk and subsequent ones created during splitting
- Adds a test case in `t/t3701-add-interactive.sh` verifying the new behavior with a multi-line file modification scenario

This represents the consensus solution from the thread, with Phillip Wood having removed all conditional logic and version-gating approaches in favor of this straightforward behavioral fix. The test coverage confirms the new interaction pattern where users must explicitly select each split hunk.
