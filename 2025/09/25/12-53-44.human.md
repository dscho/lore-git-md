Hook subsystem refactoring introducing stdin callback for parallel execution.

This is the first patch in a 10-part series modernizing Git's hook subsystem. It adds a new `feed_pipe_fn` callback to the parallel process API, allowing callers to stream large amounts of data to child processes without hitting memory limits. The implementation handles stdin feeding in a unified way, avoiding the need for workarounds like those currently in `transport.c`.

The patch builds on prior work by Emily Shaffer and Ævar Arnfjörð Bjarmason, now rebased and updated by Adrian Ratiu. It includes comprehensive test coverage showing the new functionality works with parallel processes. The changes are focused on `run-command.c` and its header, with supporting test updates.

This appears to be a well-considered change that solves a real limitation in the parallel execution API. The commit message clearly explains the motivation and relates it to existing code patterns. The implementation looks thorough, with careful handling of edge cases like SIGPIPE and proper cleanup. As the foundation for the rest of the series, this patch merits close review from anyone working on hook execution or parallel processing in Git.
