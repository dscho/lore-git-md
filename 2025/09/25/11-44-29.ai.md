Feature implementation for Rust libgit boolean config parsing.

This is the second patch in a two-part series adding boolean configuration handling to the Rust libgit implementation (`contrib/libgit-rs`). The patch introduces a `get_bool()` method to the `ConfigSet` struct that parses boolean values according to Git's standard rules (accepting `true/yes/on/1` for true and `false/no/off/0` for false).

The implementation builds on existing `get_string()` infrastructure, adding case-insensitive parsing logic. It follows Rust safety practices with proper string conversion and memory management, including freeing the C-allocated string. The patch includes test coverage verifying both successful boolean parsing and handling of missing keys.

Key technical details:
- Adds 24 lines to `config.rs` implementing the new method
- Uses `CString`/`CStr` for FFI safety
- Includes test case in `config3` test file
- Matches Git's C implementation behavior for boolean values
- Returns `None` for invalid or missing boolean values

The implementation appears straightforward and well-contained. The test coverage is minimal but sufficient for the core functionality. The patch maintains consistency with Git's existing boolean parsing behavior while following Rust idioms. This completes the series' goal of adding boolean config support to the Rust implementation.
