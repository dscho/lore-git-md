Maintainer response to `stash.showIncludeUntracked` default change proposal. Junio C Hamano acknowledges the usability argument for showing stashed untracked files by default, noting the current behavior can be confusing when a stash contains only untracked files (making `git stash show` appear empty). He points out two key constraints: 1) such a behavioral change would typically require a major version bump (Git 3.0) due to potential widespread impact, and 2) the fact that users explicitly opt-in to stashing untracked files (via `-u`) already signals they care about these files. 

While maintaining his general reluctance to change long-standing defaults, Hamano expresses unusual sympathy for this case, even suggesting the configuration option itself might have been unnecessary ("I am actually tempted to argue that the presence of the configuration variable...is a bug"). The response keeps open the possibility of changing the default while highlighting the version compatibility considerations that would need to be addressed. The technical context about stash storage format (untracked files in stash^3) remains relevant but unstated, as the focus shifts to policy questions about interface design and change management.
