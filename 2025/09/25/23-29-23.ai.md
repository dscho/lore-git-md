Refactoring patch in the `git repo stats` series, modifying ref-filter to handle NULL patterns.

This second patch in the series prepares the ref-filter infrastructure for the upcoming repository statistics functionality by making `name_patterns` NULL-safe. The change allows callers to pass NULL for the pattern array rather than requiring an empty array when no filtering is needed. The modification affects two key functions in ref-filter.c that check patterns: `filter_pattern_match()` and `for_each_fullref_in_pattern()`. Both now explicitly handle NULL `name_patterns` the same way they previously handled empty arrays - by considering it a match-all case.

The change is minimal (4 lines modified) and focused, touching only the pattern matching logic while maintaining all existing behavior. This appears to be a clean preparatory change for the statistics functionality that will follow in later patches, where the command may need to process all references without filtering. The patch follows the established pattern of the series - making targeted infrastructure improvements before adding new features.
