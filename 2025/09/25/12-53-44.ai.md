Feature: Parallel process stdin callback for hook subsystem refactoring.

This is the first patch in a 10-part series refactoring Git's hook subsystem to use the new `hook.h` interface. It introduces a stdin callback mechanism to `run_processes_parallel()` that enables feeding input to child processes without buffering everything in memory first. The change is motivated by cases like the pre-push hook where large amounts of data might need to be streamed to multiple parallel processes.

The implementation adds a new `feed_pipe_fn` callback type and integrates it with the parallel process machinery. When provided, this callback is responsible for writing data to each child's stdin pipe incrementally. The patch handles edge cases like SIGPIPE when children close their stdin early and maintains the existing ungrouped output behavior. Test coverage includes both the basic functionality and error cases.

This foundational change enables subsequent patches to convert hooks to the parallel interface while properly handling stdin. The implementation avoids string_list dependencies and explicit newline handling from earlier iterations, focusing instead on a clean callback-based approach. Performance-sensitive areas like receive-pack will need particular attention in review, though the patch includes test cases for the core functionality.
