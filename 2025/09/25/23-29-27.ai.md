Feature patch adding machine-readable output formats to `git repo stats`.

This is patch 6/7 in the `git repo stats` series, implementing the promised output format options. It adds `--format=keyvalue` and `--format=nul` modes alongside the existing table output, with key differences in delimiters and quoting behavior to support machine parsing. The keyvalue format uses newline-separated `key=value` pairs with c-quoting for special characters, while the nul format uses NUL-delimited records with newline-separated keys/values and no quoting.

Technical details:
- Adds `FORMAT_TABLE` enum alongside existing `FORMAT_KEYVALUE`/`FORMAT_NUL_TERMINATED`
- Implements `stats_keyvalue_print()` helper with configurable delimiters
- Extends option parsing in `cmd_repo_stats()` to handle the new formats
- Updates documentation with detailed format specifications
- Adds comprehensive tests in t1901-repo-stats.sh covering:
  - Keyvalue format output validation
  - NUL format round-trip via `tr` conversion
  - Empty stderr verification
- Maintains backward compatibility with table as default format

The implementation follows the series' pattern of thorough testing and clear documentation. The output format choices align with Git's existing conventions for machine-readable data (e.g., `-z` for NUL-delimited, similar to `ls-files`). This completes the core functionality before the final documentation patch.
