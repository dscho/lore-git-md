Cover letter for a feature series introducing `git repo stats` command.

This is the cover letter for v3 of a series introducing a new `git repo stats` subcommand to provide repository health metrics, positioned as a native alternative to tools like git-sizer. The series has evolved through multiple review cycles addressing core statistics, output formats, and progress reporting.

Key technical aspects of the final implementation:
- Provides reference counts (branches/tags/remotes/others) and object counts (commits/trees/blobs/tags)
- Three output formats:
  - Human-readable table (default) with auto-adjusted columns
  - Machine-readable keyvalue (key=value pairs)
  - NUL-delimited format matching existing `git repo info` behavior
- Progress reporting using `start_delayed_progress()` with TTY detection
- Clean separation of data collection and presentation layers
- Comprehensive test coverage including progress meter verification

Changes since v2:
- Added clang-format patch to fix false positives
- Converted table formatting to use varargs
- Direct stdout printing instead of strbuf intermediaries
- Earlier `parse_options()` integration
- Delayed progress reporting
- Added `--[no-]progress` test verification

The series is now complete with all planned functionality, having addressed review feedback on output formats, progress implementation, and code organization. Remaining minor items include documenting the default table format and potential future varargs support for table formatting. The implementation follows Git's design patterns while providing actionable repository statistics.
