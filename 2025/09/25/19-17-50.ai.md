Junio Hamano weighs in on the ongoing debate about commit graph ownership in the pluggable ODB effort. This is a design discussion response in the thread about Patrick Steinhardt's patch series moving commit-graph storage to `struct odb_source`.

Hamano directly challenges Steinhardt's position that commit graphs should be backend-specific optimizations, aligning more with Taylor Blau's view that graphs represent fundamental repository metadata. He argues that core Git operations (like commit traversal and reachability checks) fundamentally rely on graph data structures, making them repository-wide to be useful. The key technical concern is that generic code paths need consistent access to graph data regardless of storage backend.

Hamano's critique focuses on the architectural implications: if graphs are backend-specific, then core operations would need to handle multiple possible optimization paths, creating complexity. He suggests it's cleaner to treat auxiliary data (graphs, bitmaps) as repository-level concepts that backends must support in a standardized way. This directly opposes Steinhardt's vision where backends could implement their own optimization structures.

The email references Taylor Blau's earlier message (linked) as articulating similar concerns. This continues the thread's central tension between viewing commit graphs as either fundamental abstractions (Junio/Taylor) or implementation details (Patrick). The discussion remains unresolved but is moving toward needing a formal design document from Steinhardt to clarify the proposed architecture.
