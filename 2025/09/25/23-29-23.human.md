Refactoring patch in the `git repo stats` series (2/7) that modifies ref-filter internals to handle NULL patterns.

This patch makes the ref-filter subsystem more flexible by allowing NULL to be passed for `name_patterns` in `struct ref_filter`, treating it equivalently to an empty array (which means "match everything"). Currently, callers must provide an allocated array even if empty. The change is minimal - just two condition checks in `ref-filter.c` that now first test for NULL before dereferencing.

This appears to be groundwork for the repository statistics functionality coming in later patches, where the stats command will need to process references without pattern filtering. The change is cleanly implemented with clear safety checks and maintains existing behavior while removing an awkward requirement on callers.

As part of a larger series, this follows the initial mechanical rename (patch 1/7) and precedes the core stats functionality. The patch shows good attention to detail by updating both pattern-matching functions consistently. No behavior changes for existing callers, just a more flexible interface.
