This is a review comment on patch 2/10 of Adrian Ratiu's hook subsystem refactoring series. Junio C. Hamano points out two documentation and design issues with the new `feed_pipe` callback infrastructure.

The first observation notes that while the code correctly handles the pipe setup when `feed_pipe` is specified (setting `cp->in = -1` to trigger pipe creation), the behavior isn't clearly documented in relation to the existing `path_to_stdin` option. The current implementation silently gives precedence to `path_to_stdin` when both are specified.

The second and more substantive point critiques the documentation width and content for the new `feed_pipe` struct member. Junio suggests the comment lines are too long (a style issue) and more importantly, that the documentation fails to mention the interaction with `path_to_stdin`. He questions whether silently ignoring `feed_pipe` when `path_to_stdin` is set is the right approach, proposing instead to either document this precedence clearly or make it a BUG() condition since there's no inherent reason one input method should automatically override the other.

This feedback comes late in the review cycle (patch 2/10 was previously discussed) and focuses on tightening the interface documentation and design consistency. The core functionality isn't challenged - the series has already demonstrated the value of the `feed_pipe` approach in later patches - but Junio is ensuring the foundational pieces are properly specified before integration.
