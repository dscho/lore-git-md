This is part 5 of Adrian Ratiu's 10-part series refactoring Git's hook subsystem to use the new `hook.h` interface. The patch converts the reference-transaction hook implementation in `refs.c` to use the modern hook infrastructure while maintaining its streaming behavior.

The key changes:
- Replaces direct `child_process` handling with the new `hook.h` interface
- Introduces a dedicated `transaction_hook_feed_stdin` callback that streams ref updates line-by-line to the hook process
- Maintains all existing error handling including EPIPE tolerance when the hook closes stdin early
- Preserves the hook's role in the reference transaction workflow (prepared/committed/aborted states)
- The conversion follows the pattern established in earlier patches:
  - Moves stdin feeding logic to a callback
  - Uses `feed_pipe_ctx` to pass the transaction object
  - Maintains identical behavior while reducing boilerplate
- The implementation demonstrates the interface's flexibility by handling:
  - Per-ref filtering (skipping REF_LOG_ONLY updates)
  - Multi-line output with proper error propagation
  - Early termination when hooks close stdin

This continues the series' disciplined approach to maintaining behavior while modernizing implementations. The reference-transaction hook conversion is particularly important as it handles critical ref updates and needs to work reliably during operations like pushes. The patch carries forward signatures from previous contributors (Shaffer, Bjarmason) while Ratiu leads the current implementation.
