**Technical clarification in reftable validation series**

Patrick Steinhardt weighs in on the terminology discussion around update index validation in the reftable fsck series. This follows Karthik Nayak's response to Junio Hamano's suggestion to use "monotonically increasing" instead of "sequential" to describe the index ordering requirements, where Karthik proposed "ascending order" as an alternative to avoid implying equality is allowed.

Patrick suggests the mathematically precise term "strictly monotonically increasing" would be most accurate, as it explicitly requires prev_table.max_update_index < cur_table.min_update_index (no equality) while still allowing gaps between indices. This builds on earlier discussions where compaction scenarios were shown to legitimately produce non-consecutive indices, prompting the relaxation from strictly consecutive validation.

The exchange demonstrates careful attention to technical precision in documenting the reftable format's requirements, with multiple contributors refining the language. This patch remains part of the larger effort to implement robust validation for the reftable backend while maintaining clear specifications.
