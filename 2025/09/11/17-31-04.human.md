This is a bugfix follow-up in the command deprecation series, specifically addressing alias shadowing behavior. Kristoffer Haugsbakk reports a regression in recursion detection when dealing with deprecated command aliases. While the series had previously fixed a memory leak and added test coverage for nested deprecated aliases, this email reveals that the recursion detection works for regular aliases but fails for deprecated ones, causing an infinite loop.

The issue manifests when two deprecated commands alias to each other (e.g., `whatchanged` and `pack-redundant`), where the system fails to detect the recursion and enters an infinite loop of alias resolution. This contrasts with the correct behavior for regular aliases, which properly detect and error out for recursive cases.

The email includes a test case demonstrating both the working case (regular aliases) and the broken case (deprecated aliases). The fix for this regression will need to ensure consistent recursion detection behavior between regular and deprecated command aliases, maintaining the same safety guarantees. This appears to be the final technical issue needing resolution before the deprecation series can be fully complete.
