This is a CI/build system patch that improves visibility into documentation build configuration. It's part of a 3-patch series (position 2/3) that adds documentation build optimizations to the Meson system.

The patch makes it easier to see which documentation processor (Asciidoc or Asciidoctor) is being used during the build by adding this information to Meson's summary output. Currently this is only visible if explicitly requested via `-Ddocs_backend=`, but will now appear alongside other backend information like the crypto and HTTPS implementations.

The change is straightforward - it adds the docs backend to Meson's summary output section and ensures "none" is shown when documentation isn't being built. This is a small quality-of-life improvement for developers working with the build system, particularly useful for debugging documentation build issues.

The patch appears cleanly implemented and focused, though like the rest of the series it doesn't include tests (which may not be necessary for this purely informational change). It logically follows the first patch's introduction of documentation build targets while keeping the scope narrow to just the summary output improvement.
