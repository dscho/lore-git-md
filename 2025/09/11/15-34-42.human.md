This is a bugfix and refactoring patch in the ongoing ODB transaction interface series. Justin Tobler addresses Patrick Steinhardt's question about transaction handling in `git update-index --verbose` mode, clarifying when and why transactions should be ended early.

The patch fixes an awkward interaction where verbose mode was flushing transactions without committing them, making objects visible while keeping the transaction open. Justin explains that transactions still serve a purpose for objects added before the first `--verbose` flag is encountered (like in `--add foo --add bar --verbose` sequences, where foo and bar benefit from batching). However, once verbose output begins, the transaction is ended since each subsequent object must be immediately visible for reporting.

The discussion shows good technical alignment between the authors, with Justin agreeing to clarify the commit message to better explain this subtle timing issue. This appears to be a straightforward improvement to the transaction API's edge case handling, though reviewers will want to verify the commit message updates adequately document the behavior.
