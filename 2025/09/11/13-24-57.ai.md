This is patch 4/5 in a bugfix series addressing color handling in `git config get`. The patch specifically fixes a regression where retrieving color values with an empty key and default value (used to get ANSI reset sequences) was broken in the new `get` subcommand.

The key technical changes are:
- Adds special-case handling in `builtin/config.c` when all three conditions are met: empty config key, color type requested, and default value provided
- Directly calls `get_color()` in this case rather than going through the normal config lookup path
- Adds a new test case in t1300-config.sh verifying the old `--get-color` behavior matches the new `get --type=color` behavior
- Documents the use case in the commit message, showing the documented command and linking to the bug report from SZEDER Gábor

The change is narrowly scoped to restore documented functionality while maintaining the same output behavior as before. The test coverage appears thorough, verifying both the direct color parsing and equivalence with the older command. This patch builds on the test modernization from earlier in the series while leaving the pager handling fixes for the final patch.
