This is the fourth patch in a series fixing bugs in `git config get --type=color` functionality. It addresses a specific regression where retrieving color values without a config key (using an empty string) fails, despite being documented as valid usage.

The patch adds special handling for the case where:
- The config key is empty
- The type is color
- A default value is provided

In this case, it bypasses normal config lookup and directly processes the default value through the color parser. This matches the behavior of the older `git config --get-color` command and fixes the documented use case for getting ANSI reset sequences.

The change is small (just 2 lines in builtin/config.c) but comes with a new test case verifying both the old and new commands work equivalently. This continues the series' pattern of careful test coverage for color handling edge cases.
