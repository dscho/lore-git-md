This is the third patch in a series fixing bugs in `git config get --type=color` functionality, focusing on error handling improvements in the color parsing code.

The patch modifies `get_color()` in builtin/config.c to return an error code instead of calling `die()` when encountering invalid color values. The change prepares for a future caller that needs its own error handling path, and aligns with existing error handling patterns in the surrounding code. The function now returns 0 on success or -1 on failure, while maintaining the same stdout output behavior.

Key technical changes:
- Converts `get_color()` from void to int return type
- Replaces `die()` with `error()` for invalid default color values
- Updates the `cmd_config_actions()` caller to check the return value
- Preserves all existing color parsing and output behavior
- Touches the same config location options and color parsing infrastructure as previous patches

This appears to be a straightforward refactoring that improves the function's flexibility while maintaining backward compatibility. The change is well-motivated by the need to support new error handling paths in upcoming patches. The patch follows the series' pattern of preparatory changes before the main behavioral fixes.
