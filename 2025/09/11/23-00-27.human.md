This is a review response in the ongoing refactoring series for commit graph handling as part of the pluggable ODB effort. Taylor Blau raises two key concerns about Patrick Steinhardt's patch 6/6, which moves commit-graph handling from the object database to individual object sources.

First, Taylor notes that the new `read_commit_graph_one()` behaves differently from the old `prepare_commit_graph()` by returning NULL on subsequent calls, even when a graph exists. This could surprise callers who expect the old pattern of returning the loaded graph.

Second, and more significantly, Taylor questions whether the patch unintentionally changes behavior by potentially returning commit graphs from alternates where previously only the main repository's graph would be used. While not opposed to the idea conceptually, he suggests this behavioral change should be considered separately from the refactoring work.

The exchange highlights the careful balance required in this refactoring - while the mechanical changes look correct, subtle behavioral differences could emerge. Taylor's review maintains the constructive tone seen throughout this series, focusing on technical implications rather than blocking progress. This patch represents the final piece of Steinhardt's current series, which has otherwise seen positive reception for its preparation work toward source-specific storage models.
