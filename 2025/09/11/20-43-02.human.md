This is a technical refinement to the command deprecation framework series, specifically addressing alias recursion detection. Jeff King proposes moving the alias loop detection logic from `run_argv()` into `handle_alias()` as a cleaner architectural solution, while maintaining all existing functionality.

The patch relocates the recursion check to happen earlier in the process flow, before command processing begins. This fixes the edge case where deprecated commands could form recursive cycles (like `whatchanged -> pack-redundant -> whatchanged`). The implementation passes the `cmd_list` tracking structure into `handle_alias()` and performs the cycle detection there.

The change has minor behavioral differences in `-h` help output for recursive aliases (showing one extra line), but Jeff considers this acceptable. He suggests potential follow-ups like renaming `cmd_list` to something more descriptive (`expanded_aliases`) and optimizing the cycle detection to catch loops sooner, though leaves those as future improvements.

This appears to be the final technical piece needed for the deprecation framework series, which has already incorporated extensive review from multiple contributors. The change is well-motivated and maintains all previously agreed-upon behavior while fixing the last known edge case.
