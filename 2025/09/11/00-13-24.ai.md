This is a reply in the ongoing private branches discussion thread, offering a pragmatic perspective on the feature request. Henrique Soares responds to ynckz's request for private branches by pointing out that local branches are inherently private when not pushed to a remote. They suggest two existing solutions: keeping sensitive work local (the simplest approach) or using submodules for selective sharing of sensitive files like `.env`.

The reply reinforces the thread's emerging consensus that Git's design already provides adequate privacy mechanisms through local branches and submodules, without needing new private branch functionality. Soares' response aligns with Brian M. Carlson's earlier technical explanation about Git's security model, though focuses more on practical workflow solutions rather than protocol limitations. This continues the thread's shift away from core Git changes toward workable alternatives, though doesn't address the feature development isolation use case from the original request.
