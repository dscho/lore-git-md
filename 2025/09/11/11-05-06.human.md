This is a bugfix patch in the ongoing `git config get` subcommand series, addressing a regression in color handling.

Patrick Steinhardt responds to Junio Hamano's workaround suggestion for the empty key issue in `git config get --type=color`. The current implementation rejects empty keys while the old `--get-color` accepted them, breaking scripts that use empty keys for color reset sequences. Patrick identifies two specific bugs: the unnecessary pager setup for color output (which should always go to stdout) and the failure to handle empty keys with default values in color lookups.

The discussion reveals this was already a known issue in the test suite, which uses a non-existent key (`no.such.slot`) as a workaround. Patrick acknowledges this is suboptimal and plans to send fixes for both the pager behavior and empty key handling. The patch will be part of the larger effort to replace `--get`/`--get-all` with the new `get` subcommand while maintaining backward compatibility.

This appears to be a well-identified regression that needs addressing before the new subcommand can fully replace the old interface. The proposed fixes seem straightforward and focused on maintaining expected behavior from the older implementation.
