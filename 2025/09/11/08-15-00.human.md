This is a brief reply in the ongoing discussion about private branches, offering a simple workflow alternative. Kristoffer Haugsbakk suggests using a completely separate repository (`.git-mine`) alongside the main project's `.git` directory to maintain private files or work-in-progress features. This approach keeps the content physically separate while allowing parallel work in the same directory structure.

The suggestion aligns with the thread's emerging consensus that true private branches aren't feasible in Git's design, and that workarounds involving separate repositories (whether submodules or adjacent clones) are the practical solution. Haugsbakk's method is particularly lightweight - it requires no special tooling beyond basic Git operations, though it does mean manually managing two repositories where some files might overlap in purpose but not in name.

This reply doesn't introduce new technical arguments but provides another data point in favor of the "separate repositories" pattern that has dominated the thread's solutions. The simplicity of the approach makes it accessible for users who might find submodules or hosting-provider features too complex for their needs.
