This is a technical refinement to the command deprecation framework series, specifically addressing alias recursion detection. Jeff King proposes moving the alias loop detection logic from `run_argv()` into `handle_alias()` as a more natural home for this functionality. The change maintains all existing behavior while cleaning up the code organization.

The key technical changes in the patch:
- Moves the string list tracking of expanded aliases into `handle_alias()`
- Passes the `cmd_list` parameter through to `handle_alias()`
- Preserves the same loop detection mechanism but applies it earlier in the process
- Notes some minor output differences in `-h` help text display for recursive aliases

The patch suggests potential follow-ups:
- Renaming `cmd_list` to something more descriptive like `expanded_aliases`
- Optimizing cycle detection by checking `new_argv` earlier
- Possibly unifying the direct-recursion check with the general loop detection

This builds on the previously agreed-upon alias shadowing approach for deprecated commands, now with improved architectural placement of the recursion checks. The change is presented as a preparatory patch that could be followed by additional optimizations, though the current version already correctly handles all test cases including the problematic `whatchanged -> pack-redundant -> whatchanged` cycle.
