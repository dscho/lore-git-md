This is a follow-up discussion about the packfile store refactoring series, specifically addressing patch 13/15 which removes `get_packed_git()`. Taylor Blau points out a previously overlooked case where `get_packed_git()` and `get_all_packs()` actually do differ in behavior when MIDX (multi-pack index) packs are involved, contrary to the patch's assertion.

The key technical detail is that while both functions return the same list of packfiles, `get_all_packs()` additionally loads MIDX pack information, which affects certain callers like `want_object_in_pack_mtime()` and `cmd_grep()`. Taylor suggests either properly preparing all callers for MIDX-aware behavior or deferring this patch to a future series.

This email represents a post-merge clarification rather than a blocking issue, as the core architecture has already been accepted. Taylor advocates for a pragmatic approach, recommending handling the remaining MIDX-related cases separately to keep the current series focused. The discussion shows consensus for gradual migration of callers rather than attempting comprehensive changes all at once.
