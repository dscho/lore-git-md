This is a technical follow-up in the command deprecation framework series, specifically addressing the newly identified regression in recursive alias detection for deprecated commands. Jeff King (peff@peff.net) responds to Kristoffer Haugsbakk's discovery that the current implementation fails to detect recursive aliases involving deprecated commands like `whatchanged` and `pack-redundant`.

The key technical issue is that the alias recursion check currently happens too late in `run_argv()` - after attempting to handle deprecated commands but before processing aliases. This allows infinite recursion when deprecated commands form a cycle (`whatchanged -> pack-redundant -> whatchanged`). Jeff proposes moving the recursion check to the start of the loop in `git.c`, before any command processing occurs.

The proposed solution involves:
1. Moving the existing alias loop detection code to the top of `run_argv()`
2. Maintaining the same string list tracking mechanism but applying it earlier
3. Preserving all existing functionality for non-recursive cases

Jeff notes the current placement feels somewhat odd architecturally, suggesting the recursion check might better belong in `handle_alias()`, but provides the minimal fix to address the immediate issue. The patch demonstrates working detection of the recursive case while maintaining all other functionality.

This addresses the last remaining technical blocker in the deprecation framework series, which has otherwise completed review and testing. The change is focused on `git.c` and maintains compatibility with all previously agreed-upon behavior, including the alias shadowing mechanism and memory management.
