This is a bugfix and refactoring patch in the ongoing ODB transaction abstraction series, addressing behavior when `git update-index --verbose` is used. The patch focuses on the interaction between verbose output and transaction handling in `builtin/update-index.c`.

The core issue is that `--verbose` currently flushes transactions without committing them, creating an awkward intermediate state where objects are visible but the transaction remains open. Justin Tobler proposes ending the transaction entirely when `--verbose` is first encountered, since subsequent object writes must be immediately visible for the verbose output to be useful. This maintains transactional behavior for objects written before `--verbose` while simplifying the control flow.

Key technical points:
- Changes behavior when `--verbose` is used in `git update-index`
- Removes `flush_odb_transaction()` call in favor of early `odb_transaction_end()`
- Preserves transactional behavior for objects written before `--verbose` appears
- Updates the commit message to clarify transaction purpose in non-verbose case
- Maintains compatibility with existing callers that parse verbose output

The patch responds to Patrick Steinhardt's review questions by clarifying that transactions still serve a purpose for objects written before `--verbose` appears in the command line. The implementation appears straightforward but touches subtle timing behavior around when objects become visible, so reviewers should pay particular attention to the edge cases around option parsing order and transaction boundaries.
