This is a bugfix for the command deprecation framework series, specifically addressing a regression in alias recursion detection. Jeff King responds to Kristoffer Haugsbakk's discovery that the current implementation fails to catch recursive aliases involving deprecated commands (like `whatchanged` and `pack-redundant`), leading to infinite loops.

Jeff confirms the issue and provides a fix that moves the alias loop detection check earlier in `run_argv()`, before the deprecated command handling. While this placement might seem slightly odd (since it runs even when executing builtins directly), he notes it doesn't cause harm and properly catches the recursive case. He also muses that the logic might better belong in `handle_alias()` itself, but provides the working solution as-is.

The patch demonstrates the fix with a clear diff that relocates the detection code while maintaining all existing functionality. This addresses the last known issue in the deprecation framework series, which has otherwise received thorough review and testing from multiple contributors.
