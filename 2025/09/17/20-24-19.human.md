This is the final patch in a series implementing Git's command deprecation system, specifically cleaning up documentation about the `git-whatchanged` removal process. The patch removes an outdated claim from BreakingChanges.adoc that stated there had been "not a single complaint" about deprecating `git-whatchanged`. The author notes this may have been a work-in-progress comment from when the deprecation warning system was first added.

The change is minimal - just deleting one sentence - but it's part of a larger effort to refine the deprecation messaging throughout this patch series. Earlier versions had already improved the migration guidance and warning messages for `git-whatchanged`. This final tweak removes what appears to be temporary commentary rather than enduring documentation.

The patch follows naturally from the series' progression, where earlier versions established the technical deprecation infrastructure (flags, alias handling, warning system) while later versions like this one polish the user-facing aspects. With this change, the BreakingChanges document now simply states the deprecation status without editorializing about user response.
