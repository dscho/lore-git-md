This is part 4 of a 9-patch series implementing a comprehensive command deprecation framework, focusing on allowing aliases to shadow deprecated builtins. The patch enables users to create aliases that replace deprecated commands like `git-whatchanged` before they are fully removed, addressing a key usability gap in the deprecation process.

The change modifies `git.c` to check if a command is deprecated before applying the usual alias shadowing restrictions, adding a new `is_deprecated_command()` helper. The implementation is thorough, with tests verifying both simple shadowing and edge cases like alias loops between deprecated commands. Documentation is updated to clarify the new behavior.

The patch builds on Jeff King's earlier work and addresses real-world concerns from users who want to transition away from deprecated commands while keeping their muscle memory. The implementation is clean and well-tested, with careful attention to edge cases like infinite alias loops. This is a meaningful quality-of-life improvement for users affected by command deprecations.
