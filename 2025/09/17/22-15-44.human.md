This is a follow-up discussion about a refactoring patch that was already merged as part of Patrick Steinhardt's packfile store series. Justin Tobler notes that while moving the packfile map into `struct packfile_store` makes sense, it creates an apparent inconsistency with the comment stating this struct should only be accessed by `packfile.c`. The `midx.c` file now directly accesses the `map` field, which seems to violate this intended encapsulation.

The observation doesn't challenge the technical correctness of the change (the series is already merged and considered successful), but raises a documentation/design question about whether the comment should be updated to reflect that `midx.c` is also a legitimate user of this structure. The thread context shows this is a minor point in an otherwise settled architectural change, with no indication it will require any follow-up action.
