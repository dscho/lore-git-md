Documentation patch completing a two-part series reorganizing the git-push refspec documentation. This second patch rewrites the refspec specification section with clearer examples and more comprehensive coverage of all refspec variants.

The patch addresses user confusion by restructuring the refspec documentation into a bulleted list of all possible forms, each with concrete examples. It adds documentation for two previously missing cases: pattern refspecs (using `*` globbing) and negative refspecs (using `^` prefix). The rewrite maintains technical accuracy while using more approachable language where possible, though acknowledges refspecs remain an advanced feature.

Key technical changes include:
- Converting prose explanations into a structured list of refspec forms
- Adding examples for each variant including `main:other`, `refs/heads/*`, and `^refs/heads/dev-*`
- Clarifying the `+` prefix behavior as equivalent to `--force`
- Documenting the special `tag <tag>` syntax separately since it's not technically a refspec
- Preserving all existing behavior descriptions but making them more discoverable

The patch follows the first in the series which extracted push rules to a dedicated section. Together they represent a significant reorganization (102 insertions, 96 deletions across both patches) with no behavior changes. The series appears ready for merging with no outstanding objections from the mailing list.
