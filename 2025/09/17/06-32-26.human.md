Bugfix for `git send-email` handling of Reply-To headers. This patch addresses an issue where specifying `--reply-to` on the command line while also editing an intro message would result in duplicate Reply-To headers, causing email rejection by some providers like Gmail.

The problem occurs because `send-email` wasn't properly processing Reply-To headers during message editing - it would both pass through the original header unmodified and generate a new one from the command-line argument. The fix adds explicit Reply-To header parsing to match the existing handling of similar headers like In-Reply-To and References.

The change is straightforward - just 3 lines added to recognize and store the Reply-To header value during preprocessing. This ensures the edited message won't get duplicate headers and that any Reply-To changes made during editing will properly propagate to all generated emails. The patch appears well-targeted and clearly explains both the problem and solution.
