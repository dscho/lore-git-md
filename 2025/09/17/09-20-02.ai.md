Refactoring patch in a completed series to improve type safety in the string-list API.

This is the third patch in a 4-part series that has already gone through review and revision (v2 incorporates all feedback from v1). The series systematically eliminates sign comparison warnings by converting the string-list API to use proper unsigned types. This specific change focuses on `string_list_find_insert_index()`, making its return type `size_t` to match its internal helper `get_entry_index()`.

The patch updates all callers in `add-interactive.c`, `mailmap.c`, and `refs.c` to use `size_t` variables. The most notable fix is in `mailmap.c` where the loop condition needed adjustment to properly handle `size_t` underflow by changing from `0 <= --i` to `i--`. This allows removing the `DISABLE_SIGN_COMPARE_WARNINGS` flag from `mailmap.c`.

The changes are mechanical but important for type safety:
- Function declaration updates in both `string-list.c` and `string-list.h`
- Caller variable type changes to `size_t`
- Loop condition fix in `mailmap.c` lookup logic
- Warning suppression removal in `mailmap.c`

This continues the series' pattern of maintaining identical behavior while improving type safety. The thread shows consensus on the technical approach, with Patrick Steinhardt having reviewed and approved the changes in v2. The patch is now ready for inclusion, completing the transition to proper unsigned types in the string-list API.
