This is a refactoring patch in the larger Rust integration series, focusing on making varint handling more precise and platform-independent. Patrick Steinhardt updates the varint subsystem to use explicit integer widths (`uint64_t` for values and `uint8_t` for lengths) instead of implicit types like `uintmax_t` and `int`. 

The change is motivated by two factors: the known maximum sizes needed for varints (16 bytes for encoding), and upcoming Rust reimplementation where explicit widths will be helpful. The patch touches several files (`dir.c`, `read-cache.c`, `varint.c`, `varint.h`) to consistently apply these type changes across the codebase.

This appears to be a straightforward, mechanical change that improves type safety without altering behavior. It's co-signed by Ezekiel Newren (who suggested the approach) and fits into the broader Rust integration work by making the C/Rust boundary clearer. The changes are limited to type declarations and don't introduce new logic, so the risk of regression seems low.
