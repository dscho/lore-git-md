This is a refactoring patch that improves type safety of the string-list API by eliminating a clever but problematic encoding scheme. The patch changes `string_list_find_insert_index()` to use a proper `bool*` parameter for exact-match detection instead of overloading negative return values, which had caused sign-comparison warnings and limited the usable index range.

The key changes are:
1. Replacing the negative-index encoding with a separate `exact_match` boolean parameter
2. Making the `exact_match` parameter optional (NULL can be passed when callers don't need this information)
3. Updating all callers in `add-interactive.c`, `mailmap.c`, and `refs.c` to use the new interface

This is patch 2/4 in a series that has already gone through one round of review, with v2 incorporating feedback to use `bool*` instead of `int*` for the exact-match parameter. The changes are mechanical but important for type safety, allowing the code to use the full range of `size_t` indices while eliminating signed/unsigned comparison warnings. The patch appears well-constructed with appropriate test coverage from existing callers, and follows logically from the previous patch in the series that made the index parameter optional.
