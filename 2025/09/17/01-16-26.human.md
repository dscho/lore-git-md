This is a documentation patch announcing Git's transition to requiring Rust as a mandatory build dependency. It's part of the larger Rust integration effort (v2 06/18 in an 18-patch series).

The patch adds a section to BreakingChanges.adoc detailing the planned timeline for Rust adoption, with two key milestones: Git 2.52 will enable Rust by default (while still allowing opt-out), and Git 3.0 will make Rust mandatory. The document explains this phased approach gives distributors time to adapt their build infrastructure while the project tests Rust integration through optional subsystems.

The announcement acknowledges Rust's impact on the ecosystem - some platforms may need to update toolchains or bootstrap sequences. To ease the change, Git will designate the last pre-3.0 release as a long-term support version, maintained for 4-6 release cycles to accommodate slower-moving distributions.

The patch reflects consensus from the broader Rust integration work (documented in Patch 5's rust-support.adoc) and provides clear transition guidance. It's primarily informational rather than technical, serving as official notice of the project's direction rather than implementing any code changes.
