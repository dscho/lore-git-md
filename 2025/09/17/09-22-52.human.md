This is a follow-up patch in the completed series switching Git's default initial branch name from "master" to "main" when built with WITH_BREAKING_CHANGES. The technical implementation has already been merged, and this email addresses the final open question about advice messaging strategy.

Junio Hamano proposes adding a new advice message specifically for users who follow tutorials assuming the old "master" branch name. The patch modifies the existing advice system to show a different message after the default branch name change occurs in Git 3.0, focusing on how to rename the branch rather than how to configure the default name. The message is designed to be temporary and will reuse the existing advice.defaultBranchName configuration to avoid forcing long-time users to reconfigure their settings.

The implementation touches several files:
- Updates advice.c and advice.h to maintain the advice across both build configurations
- Modifies refs.c to show context-appropriate messages
- Adjusts tests in t0000-basic.sh and t0001-init.sh to handle the new advice output

This appears to be a well-considered solution to the last remaining issue in this long-running effort, balancing the needs of new users following old instructions with the desire to minimize annoyance for existing users. The patch maintains consistency with the series' overall approach while addressing Phillip Wood's concerns about message longevity.
