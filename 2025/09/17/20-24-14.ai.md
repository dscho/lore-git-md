Feature patch implementing alias shadowing for deprecated builtins, part of the ongoing command deprecation framework series (patch 4/9). This change allows users to create aliases that override deprecated commands like `git-whatchanged` and `git-pack-redundant`, addressing a key usability gap in the deprecation workflow.

The core change introduces `is_deprecated_command()` to check the `DEPRECATED` flag on builtins, then modifies `run_argv()` to permit alias expansion for these commands. The implementation handles both direct shadowing (e.g. `whatchanged -> log --raw --no-merges`) and chained cases (e.g. `whatchanged -> pack-redundant -> status`), with comprehensive tests verifying the behavior.

Key technical details:
- New `is_deprecated_command()` helper checks the `DEPRECATED` flag via `get_builtin()`
- Modified alias handling in `run_argv()` now bypasses the builtin check for deprecated commands
- Tests cover:
  - Loop detection for deprecated command alias chains
  - Successful shadowing of all deprecated commands via `--list-cmds=deprecated`
  - Multi-hop deprecated command aliasing
- Documentation updated to clarify the exception for deprecated commands

The patch builds on Jeff King's earlier work and addresses the specific case where users want to alias deprecated commands to their modern equivalents before the commands are fully removed. This completes one of the last major pieces of the deprecation framework's user-facing behavior.
