Documentation patch reorganizing git-push rules into a dedicated section. This is part 1 of a 2-patch series following up on PR #1964, moving push validation rules from being embedded in the refspec section to a new standalone "PUSH RULES" section.

The patch extracts all push validation logic (previously mixed with refspec syntax) into a new section at the end of the man page. Key changes include: moving the rules about branch/tag/other ref updates (91 lines relocated), updating the `--force` documentation to reference the new section, and adding a cross-reference from the refspec section. The rules themselves remain unchanged - this is purely organizational.

Technical details show substantial line movement (44 insertions, 49 deletions) as content is relocated. The new section clearly separates rules for branches (fast-forward only), tags (all updates rejected), and other refs (case-by-case behavior). Force push behavior and configuration overrides are consolidated here. The patch follows Junio Hamano's feedback on list formatting and technical accuracy from prior review.

This structural change enables better cross-referencing (now used by `--force` docs) and makes the push rules more discoverable while allowing readers to skip less common cases (tag/non-branch pushes). The second patch in the series will rewrite the refspec specification itself.
