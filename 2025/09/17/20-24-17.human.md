This is part 7/9 of the command deprecation framework series, focusing on improving user experience when transitioning from `git-whatchanged` to `git log`. The patch enhances the deprecation warning message to include concrete instructions for replacing `whatchanged` with equivalent `log` options (`--raw --no-merges`) and shows how to create an alias for those who prefer keeping the old command name.

The changes include:
1. Adding a detailed hint to the `whatchanged` deprecation message showing both direct replacement syntax and alias creation
2. Updating the documentation to explicitly show the equivalent `git log` command
3. Modifying the `you_still_use_that()` function signature to accept optional hints
4. Applying consistent changes to both `whatchanged` and `pack-redundant` commands

The motivation comes from real-world reports of users struggling with the transition since Git 2.51.0. The patch provides immediate, actionable solutions while maintaining the deprecation stance. This appears well-integrated with the broader deprecation framework work, particularly the alias shadowing capability introduced earlier in the series.
