Documentation patch reorganizing the git-push man page to better structure push rules. This is part 1 of a 2-patch series that moves the push permission rules from being buried in the refspec section to a new standalone "PUSH RULES" section.

The change makes the rules more discoverable and referenceable, particularly for the `--force` option which can now focus on the common branch case while deferring tag/non-branch details to the new section. The patch is purely organizational - no behavior changes - but significantly restructures the content (93 lines modified). 

The new section clearly separates rules for branches (only fast-forward commits), tags (all updates rejected), and other refs (mixed rules). It also notes how `--force` and `+` refspecs can override these safety checks, with exceptions for branch object types. The author notes this will allow better cross-referencing from other sections like `--force`.

This follows up on prior documentation work (PR #1964) and has already addressed review feedback from Junio Hamano about formatting choices. The changes appear well-considered and the patch seems ready for inclusion.
