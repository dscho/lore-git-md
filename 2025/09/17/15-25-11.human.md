This is the first patch in a bugfix series addressing case-insensitive filesystem issues with batched reference updates. The patch focuses on improving error handling when case conflicts occur during reference updates on case-insensitive filesystems.

Before Git 2.51, conflicting case references (like refs/heads/Foo and refs/heads/foo) would silently overwrite each other during fetches. Since 2.51's switch to batched updates, such conflicts cause the entire operation to fail. This patch introduces a new REF_TRANSACTION_ERROR_CASE_CONFLICT error type that allows partial updates to succeed while rejecting only the conflicting references.

The change modifies the files backend to detect case conflicts during the prepare phase of reference transactions. When conflicts are found, the operation continues with non-conflicting updates while providing clear error messages about the case sensitivity issue. The patch also recommends migrating to the reftable backend as a long-term solution, since it doesn't have these case-sensitivity limitations.

The implementation includes thorough test coverage in t1400-update-ref.sh and t5510-fetch.sh, with separate tests for both files and reftable backends. This is a well-crafted solution to a real problem that affects users on case-insensitive filesystems, with clear error messages and a path forward via the reftable backend. The patch has already undergone several rounds of review and appears ready for integration.
