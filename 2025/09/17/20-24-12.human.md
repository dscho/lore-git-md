This is part 2 of a 9-patch series implementing a deprecation framework for Git commands, specifically adding support for listing deprecated commands. The patch introduces a new `deprecated` category to `git --list-cmds` to help users identify which builtins are marked for deprecation.

The change adds a `DEPRECATED` flag (1<<6) to the command flag system and modifies the `list_builtins()` function to support both inclusion and exclusion filtering. The patch marks `pack-redundant` and `whatchanged` as deprecated (when not built with `WITH_BREAKING_CHANGES`), updates the documentation, and includes a BUG check to prevent mutually exclusive filtering options.

This is a well-structured patch that builds on the series' goal of improving command deprecation visibility. The commit message clearly explains the motivation (helping track deprecated commands among Git's 145 builtins) and acknowledges the experimental nature of using `--list-cmds` for this purpose. The implementation has been refined across multiple versions with input from Patrick Steinhardt, who provided both code formatting suggestions and an Ack.

The change is straightforward and focused, touching only git.c and Documentation/git.adoc. It serves as infrastructure for later patches in the series that will implement alias shadowing of deprecated commands. The patch appears ready for inclusion, with no obvious technical issues.
