Bugfix for `git send-email` handling of Reply-To headers. This is a follow-up to address maintainer feedback on a previous patch submission.

NeilBrown responds to Junio C Hamano's review of his fix for duplicate Reply-To headers when using `--compose --reply-to` together. The original patch correctly identified that the issue stemmed from Reply-To being both inserted into the intro message template and then duplicated when headers were copied, causing rejection by email providers like Gmail.

Junio had suggested several improvements to the commit message: fixing the author/Signed-off-by mismatch, using more imperative language in the solution text, and providing more detailed analysis of the problem. NeilBrown acknowledges the feedback and indicates he will incorporate these changes in a resubmission.

The technical solution itself (a small change to `git-send-email.perl` that properly captures Reply-To headers during pre-processing) was deemed sound by Junio. The interaction between the header parsing logic and the `@xh` array was clearly explained in the review discussion. While functionally complete, the patch just needs these documentation polishings before being ready for inclusion.
