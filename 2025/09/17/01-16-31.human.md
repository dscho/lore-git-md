CI/build system patch in the Rust integration series. This is patch 11/18 in a larger effort to bring Rust components into Git while maintaining compatibility with the existing C codebase.

Ezekiel Newren's patch modifies GitHub Actions workflows to upload `Cargo.lock` files as build artifacts. This change appears in four different workflow jobs: the standard Windows build/test, Windows with Meson build, Linux builds, and static analysis. The lock files will be named differently for each job (e.g. `cargo-lock-windows`, `cargo-lock-windows-meson`) to distinguish them.

The stated purpose is to enable auditing of build dependencies, suggesting this is part of ensuring security and reproducibility in the Rust components. The change is straightforward - it simply adds artifact upload steps using GitHub's standard `actions/upload-artifact` action - but serves an important piece of infrastructure as Git's Rust integration progresses.

This patch fits into the broader series' focus on CI/build system support for Rust, following earlier patches that established Rust toolchain installation and build infrastructure. The implementation looks clean and well-contained, addressing a specific CI need without introducing complexity.
