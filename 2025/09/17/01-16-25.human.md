Documentation patch establishing Git's Rust adoption policy. This is part of a larger 18-patch series introducing Rust components to Git, with this particular piece providing the rationale and guidelines for the transition.

The document makes the case for Rust adoption by citing security benefits (reducing memory safety vulnerabilities), developer ergonomics, and modern language features. It proposes an incremental approach where Rust code will be linked as a static library initially, with potential future moves to dynamic linking or Rust-compiled binaries. The policy requires Rust support as part of Git's platform requirements, aligning with Debian stable's Rust version plus one year of oldstable support (approximately 3 years total).

Key technical decisions outlined include: avoiding C types like `long` in favor of unambiguous Rust types (`i32`/`i64`), cautious use of interop tools like bindgen/cbindgen, and careful dependency management (no `Cargo.lock` in repo). The document also notes community support from the Berlin Git Merge Contributor Summit.

As documentation, this patch doesn't change any functionality but provides important governance for the Rust work happening in the rest of the series. The thorough rationale and clear policy statements should help guide both current contributors and downstream maintainers through the transition.
