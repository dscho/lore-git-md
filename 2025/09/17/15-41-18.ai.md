This is a follow-up discussion in the command deprecation system thread, specifically addressing a build system issue affecting the `whatchanged` command removal. Kristoffer Haugsbakk confirms Jeff King's diagnosis that the Makefile` still includes `git-whatchanged` in `BUILT_INS` even when built with `WITH_BREAKING_CHANGES=YesPlease`, despite the command being removed from the builtin table. This creates a stale executable that conflicts with the deprecation system's intended behavior.

The key technical points are:
- The current build produces a confusing error (`fatal: cannot handle whatchanged as a builtin`) rather than the expected "command not found" message
- The proposed fix adds a conditional to the `Makefile` to exclude `git-whatchanged` from `BUILT_INS` when `WITH_BREAKING_CHANGES` is active
- A remaining issue is that existing builds may leave stale `git-whatchanged` executables that would need manual cleanup
- The problem also affects alias shadowing behavior since the system misclassifies `whatchanged` as an external command rather than a deprecated builtin

Kristoffer verifies the issue persists even after a clean build (`git fsck -d -x -f` followed by `make`), and plans to incorporate Jeff's Makefile change into the series. The discussion confirms this is the final outstanding issue for the deprecation system implementation, with all other aspects (documentation, test coverage, core functionality) already resolved in previous iterations.
