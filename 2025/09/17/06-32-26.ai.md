Bugfix for `git send-email` handling of Reply-To headers. This patch addresses a specific issue where using `--compose --reply-to` would result in duplicate Reply-To headers in the intro message, causing rejection by some email providers like gmail.

The problem occurs because `send-email` wasn't properly parsing Reply-To headers during message preprocessing, causing it to both pass through the original header and generate a new one from the `$reply_to` variable. The fix adds explicit Reply-To header parsing to the `pre_process_file` subroutine, ensuring the header is only included once and allowing edits to the Reply-To field in the compose message to properly propagate to all generated emails.

The change is minimal (just 3 lines added) and focused, touching only the header parsing logic in `git-send-email.perl`. The commit message clearly explains both the problem and solution, including reproduction steps and the specific email provider behavior that revealed the issue. This appears to be a straightforward fix for a real-world usability problem in email submission.
