This thread documents Julia Evans' work to reorganize and clarify the git-push man page's refspec documentation. The effort split into two patches: the first (already merged) extracted push validation rules into a dedicated "PUSH RULES" section, while the second (now in v2) completely rewrote the refspec specification section with clearer structure and examples.

The rewrite addresses long-standing user confusion by presenting refspec forms in a bulleted list with concrete examples, documenting previously obscure features like pattern refspecs and negative refspecs, and clarifying force-push behavior. Junio Hamano provided detailed feedback that Julia incorporated, particularly around simplifying tag object explanations and making deletion rules more explicit.

The technical discussion included a brief detour about man page formatting when Brian m. carlson raised concerns about indentation, but Jeff King's analysis confirmed the current approach is dictated by the toolchain. Both patches have now addressed all substantive feedback, with the first already merged, this final revision appears ready for inclusion. The changes represent a significant documentation improvement with no behavior impact, making push refspec rules more discoverable and understandable.
