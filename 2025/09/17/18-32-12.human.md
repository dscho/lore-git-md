This is a follow-up in the ongoing Rust infrastructure thread, focusing on build system dependencies and platform compatibility. Ramsay Jones responds to Ezekiel Newren's clarification about Rust toolchain requirements, pointing out that the current `build_rust.sh` script makes assumptions that may not hold for all developers.

The key issue is that the script currently requires `rustup` (the Rust toolchain manager) even when developers have Rust installed through their distribution's package manager (like Linux Mint's `apt`). Jones notes this is problematic since some distributions treat `rustup` and system Rust packages as mutually exclusive. He suggests the Windows platform detection (the script's current use of `rustup`) could be implemented differently.

Jones also seeks clarification about `cbindgen` - whether the Debian package provides the same functionality as installing it via Cargo, and whether it's considered an executable or a crate. This touches on the broader question of how Rust dependencies should be managed across different packaging systems.

The exchange highlights practical distribution-level concerns that need addressing as the Rust infrastructure work progresses, particularly around making the build system flexible enough to work with various Rust installation methods while maintaining cross-platform compatibility.
