Feature patch implementing signature handling in `git fast-import` to match `git fast-export`'s capabilities. This is the second patch in a 2-part series, building on the refactoring in patch 1/2 that moved shared signature handling code to gpg-interface.[ch].

The patch adds a `--signed-commits=<mode>` option to `git fast-import` with the same modes as fast-export (verbatim, warn-verbatim, strip, warn-strip, abort), though with a default of "verbatim" rather than "abort". The implementation cleanly splits signature handling into new `import_one_signature()` and `discard_one_signature()` helper functions, with robust switch statement handling in `parse_new_commit()` that includes a BUG() for invalid modes.

Key technical details:
- Uses the shared `sign_mode` enum and parsing from gpg-interface.[ch] introduced in patch 1/2
- Handles all signature formats (OpenPGP/X.509/SSH) and hash algorithms (SHA-1/SHA-256)
- Includes comprehensive tests in new t9305-fast-import-signatures.sh covering:
  - All handling modes
  - Warning message verification
  - Dual-signature stripping
  - Malformed signature resilience
- Maintains backward compatibility while adding new functionality

The implementation appears solid with thorough test coverage. The only remaining design questions (from the thread context) are about mode naming conventions and warning verbosity control, which don't affect the technical correctness. This completes the feature parity between fast-import and fast-export for signature handling.
