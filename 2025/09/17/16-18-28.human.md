This is a follow-up patch in the completed series switching Git's default branch name from "master" to "main" when built with WITH_BREAKING_CHANGES. The patch focuses on refining the user advice messages during this transition period.

Junio Hamano explains the rationale for keeping a simplified advice message even after the default branch name switch. The key insight is that new users following older tutorials expecting "master" will still need help renaming their branch, but they no longer need instructions for permanent configuration since "main" is now the default. The patch maintains the same advice token (ADVICE_DEFAULT_BRANCH_NAME) to avoid forcing existing users to reconfigure their settings.

The technical changes include:
- Keeping the advice.defaultBranchName configuration active (previously it was conditional)
- Adding a new advice message specifically for the post-3.0 case
- Updating test infrastructure to set GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME appropriately based on WITH_BREAKING_CHANGES
- Removing the MAYBE_UNUSED annotation from the quiet parameter in repo_default_branch_name()

This appears to be a well-considered refinement of the user experience during the transition period, with thoughtful attention to backward compatibility and clear communication about temporary versus permanent configuration needs. The patch builds on Phillip Wood's earlier test improvements and represents the final polishing of this long-planned change.
