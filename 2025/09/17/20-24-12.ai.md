This is part of the command deprecation framework series, specifically implementing the `--list-cmds=deprecated` interface. The patch adds infrastructure to query deprecated commands through Git's experimental `--list-cmds` mechanism.

The key technical changes include:
- Adding a new `DEPRECATED` flag (1<<6) to mark deprecated commands in the `commands[]` array
- Extending `list_builtins()` to support both inclusion and exclusion filtering, with a BUG check to prevent mutually exclusive modes
- Marking `pack-redundant` and `whatchanged` as deprecated when not built with `WITH_BREAKING_CHANGES`
- Updating documentation to include the new `deprecated` category in `git.adoc`

The implementation builds on previous work by Patrick Steinhardt, who provided feedback on code formatting and helped refactor the for-loop logic. The commit message notes this is part of a larger effort to help users identify deprecated commands, though it acknowledges using an experimental interface for this purpose isn't ideal.

This patch is well-integrated with the series' goals, with clean separation of concerns from other patches. The changes are focused and maintainable, though the documentation update is minimal - just adding the new category to the existing list. The BUG check ensures logical consistency in the filtering behavior.
