This is a documentation patch in the ongoing Rust infrastructure series, specifically addressing the announcement of Rust becoming mandatory in Git 3.0. SZEDER Gábor raises an important concern about the interaction between two major upcoming changes: the mandatory Rust requirement and the SHA-1/SHA-256 transition.

The original patch by Patrick Steinhardt outlines a phased approach to making Rust mandatory, with Git 2.52 introducing optional Rust support, 2.53 making it default-enabled, and 3.0 removing the opt-out capability. It also proposes an LTS release for platforms that can't adopt Rust immediately.

SZEDER Gábor points out a potential conflict: Git 3.0 will also switch the default hash algorithm to SHA-256, but the SHA-1/SHA-256 interoperability features appear to require Rust. This could leave non-Rust platforms unable to work with repositories transitioning between hash algorithms. The response suggests this limitation should be explicitly acknowledged in the BreakingChanges document, along with justification that the project has considered and accepted these constraints.

The exchange highlights how the infrastructure change intersects with other major Git features, requiring careful coordination. While the Rust transition plan appears well-considered for general build requirements, this specific interaction with hash algorithm transitions warrants explicit documentation and consideration. The thread shows the project's attention to real-world deployment concerns, particularly for platforms that may lag in Rust adoption.
