This is a follow-up patch in the completed series switching Git's default initial branch name from "master" to "main" when built with WITH_BREAKING_CHANGES. The technical implementation is already merged; this email addresses the last open discussion point about advice messaging strategy.

Junio Hamano proposes a new patch (positioned as 5/4) to modify the advice shown when users create repositories with the new default branch name. The key changes are:

1. Reuses the existing advice.defaultBranchName configuration rather than introducing a new one, ensuring users who previously disabled the "master" warning won't see the new message either.

2. Changes the advice text to focus narrowly on helping users following older tutorials that assume "master" - it shows how to rename the branch once (`git branch -m master`) without mentioning permanent configuration.

3. Justifies this design by noting the original purpose was to eliminate the need for configuration, so the advice should only address the temporary tutorial-matching case.

4. Updates tests to handle both the old and new advice messages, including colorized output tests.

5. Marks ADVICE_DEFAULT_BRANCH_NAME in advice.h as "To be retired sometime after Git 3.0" since this is transitional messaging.

The patch maintains all existing behavior when not built with WITH_BREAKING_CHANGES. It resolves Phillip Wood's concern about message longevity by keeping the same advice token and explicitly noting the temporary nature of this guidance. The implementation is complete with test updates and documentation in the commit message explaining the deliberate design choices.
