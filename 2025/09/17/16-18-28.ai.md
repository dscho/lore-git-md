This is a follow-up patch in the completed series switching Git's default initial branch name from "master" to "main" when built with WITH_BREAKING_CHANGES. The patch focuses on refining the user advice system during this transition period.

The key change modifies the advice shown when creating a new branch to better serve post-3.0 users who might follow older tutorials assuming "master" as the default. The new advice only shows how to rename the branch (via `git branch -m master`) rather than explaining permanent configuration, as the latter is no longer needed now that "main" is the preferred default. The same advice token (ADVICE_DEFAULT_BRANCH_NAME) is maintained to avoid forcing existing users to reconfigure their settings.

Technical changes include:
- Restores ADVICE_DEFAULT_BRANCH_NAME unconditionally in advice.c/advice.h (previously gated)
- Adds new advice text for the WITH_BREAKING_CHANGES case in refs.c
- Modifies test-lib.sh to set GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME appropriately based on WITH_BREAKING_CHANGES
- Removes MAYBE_UNUSED from repo_default_branch_name() parameters
- Updates the advice message format to be more focused on immediate branch renaming

The patch builds on Phillip Wood's earlier test simplification work and represents the final polish to the advice system before the 3.0 transition. Junio Hamano's commit message explains the deliberate design choices around advice scope and configuration, noting this targets a specific transitional user need without encouraging outdated practices. The changes maintain backward compatibility while providing clearer guidance path for new users following old tutorials.
