This is a refactoring patch in a completed series that modernizes the string-list API to eliminate sign comparison warnings. 

The patch changes `string_list_find_insert_index()` to use a `bool* exact_match` parameter instead of encoding exact matches via negative indices. This addresses two key limitations: it allows using the full range of `size_t` for indices (important for large string lists) and eliminates signed/unsigned comparison warnings. The change makes the API more type-safe and explicit about its behavior.

Key technical changes include:
- Modifying `get_entry_index()` to make `exact_match` parameter optional (can be NULL)
- Updating `string_list_find_insert_index()` to directly return the index and use the new `bool*` parameter
- Adjusting callers in `add-interactive.c`, `mailmap.c`, and `refs.c` to use the new interface
- Maintaining identical behavior while improving type safety

The patch builds on previous work in the series (v1 had made the index parameter optional) and incorporates feedback to use `bool*` instead of `int*` for the exact match flag. It demonstrates careful attention to backward compatibility while modernizing the API. All changes are mechanical adaptations to the new interface with no functional changes.
