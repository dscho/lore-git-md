This is a feature enhancement to Git's command deprecation system, building on the recently completed alias shadowing support. Kristoffer Haugsbakk's v6 patch series focuses on improving the error messaging and user experience when deprecated commands like `git whatchanged` are used.

The key improvements in this version:
1. More helpful error messages that suggest concrete alternatives (using `git log` with specific flags or creating an alias)
2. Better troubleshooting guidance pointing users to documentation and mailing list discussions
3. A fix to ensure `git-whatchanged` is properly excluded from builtins when `WITH_BREAKING_CHANGES` is set
4. Cleaned up alias loop detection code (incorporating Jeff King's suggestions)

The series now includes 9 patches (up from 8 in v5), with the first being a new Makefile fix. The error messages now provide clear next steps rather than just telling users to email the list. For example,git whatchanged` now suggests both the equivalent `git log` command and how to create an alias.

This appears to be a well-considered refinement of the deprecation system, with thorough test coverage and documentation updates. The changes are focused on making the transition smoother for users while maintaining the deprecation warnings' effectiveness. The v6 incorporates feedback from Jeff King and others to clean up some implementation details.
