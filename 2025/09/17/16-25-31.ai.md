This is a follow-up to the command deprecation framework series, specifically the build system integration issue that was the last remaining item in v5. The patch addresses the problem where `git-whatchanged` was still being included in `BUILT_INS` in the Makefile when built with `WITH_BREAKING_CHANGES=YesPlease`, despite having been removed from the commands list in git.c. This created a confusing situation where the command would fail with "fatal: cannot handle whatchanged as a builtin" rather than the expected "not a git command" message.

The fix properly removes `git-whatchanged` from `BUILT_INS` when breaking changes are enabled, ensuring consistent behavior with the deprecation system. The change completes the technical implementation of the deprecation framework by properly handling the build system integration, which was the last remaining issue after all other aspects (alias shadowing, error messaging, documentation) had been addressed in previous patches.
