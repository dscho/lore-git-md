This is a test patch in the ongoing command deprecation framework series, specifically focusing on verifying alias shadowing behavior for regular (non-deprecated) builtins.

The patch adds test coverage to confirm that regular Git commands cannot be shadowed by aliases, as documented in git-config(1). It introduces a new test function `cannot_alias_regular_builtin()` that checks this behavior for a sample of builtins (`grep`, `check-ref-format`, `interpret-trailers`, `checkout-index`, `fast-import`, `diagnose`, `rev-list`, `prune`). The test verifies that attempting to shadow these commands with an alias to `status` does not affect their behavior.

The implementation is careful about performance, explicitly noting that only a sample of builtins is tested to avoid adding ~600ms to the test suite runtime. The test uses `test_might_fail` since some commands may fail when run with `-h`, and includes checks to ensure the output files are non-empty before comparison.

This patch complements the earlier tests for deprecated command shadowing (added in patch 4/9) and helps validate the documentation's claim about alias behavior. The test infrastructure added here could potentially be extended in the future to cover more builtins if needed.
