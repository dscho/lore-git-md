This is a discussion about error handling in Git's bundle-URI feature, specifically whether to fix malformed server responses on the client side or require server-side fixes. Justin Tobler responds to Toon Claes' argument for client-side workarounds by advocating for server-side fixes as the primary solution.

The email focuses on the philosophical debate around error handling strategy. Justin argues that servers advertising bundle-URI capabilities should be required to send valid data, and that as the root cause, server-side fixes would be more appropriate than client-side workarounds. He acknowledges Toon's point about existing broken servers but considers the scenario niche enough that server updates would be preferable to client-side accommodations.

Key technical points include the specific code change in connect.c line 536 that converts an error to a warning, and the three requirements for the issue to manifest (server advertising bundle-URI, misconfiguration, and client enabling the feature). Justin suggests the problem can be worked around by disabling bundle-URI entirely on the client side.

The discussion represents the ongoing tension between strict protocol validation (favored by Justin and previously by Junio Hamano) versus practical client resilience (advocated by Toon based on GitLab deployment experience). Justin remains skeptical of client-side fixes but leaves the door open if server-side approach proves insufficient. The exchange helps clarify the real-world considerations influencing this design decision.
