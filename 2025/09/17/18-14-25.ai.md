This is the v3 cover letter for a feature patch series adding signature handling to `git fast-import`. The series builds on previous iterations that introduced shared signature-handling infrastructure in gpg-interface.[ch] and implemented the new `--signed-commits=<mode>` option.

The key changes in v3 focus on code organization and robustness:
- The signature parsing logic in fast-import.c has been split into two new helper functions (`import_one_signature()` and `discard_one_signature()`) for better modularity
- The switch statement handling different signature modes now has clearer organization with comments and a BUG() default case
- The commit message better explains the design choices around signature stripping
- The SIGN_ABORT case is now handled more consistently with other modes

The cover letter reiterates two open design questions from previous versions about whether to keep synonym modes ("ignore" for "verbatim") and whether warning variants should be separate modes or controlled by a --verbose flag. The author expresses a preference for removing the synonyms to reduce confusion but notes this would complicate the parsing code.

The series remains well-tested with comprehensive coverage of signature formats (OpenPGP/X.509/SSH), handling modes, hash algorithms (SHA-1/SHA-256), and edge cases. CI tests are passing. With the v3 refinements addressing previous review feedback, the technical implementation appears solid, leaving only the higher-level design questions about mode naming and warning control to resolve before potential merging.
