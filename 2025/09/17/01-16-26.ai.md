This is a documentation patch announcing Git's planned transition to requiring Rust as a mandatory build dependency. The patch adds a section to `BreakingChanges.adoc` detailing the roadmap for Rust adoption, with key milestones:

1. Git 2.52 will enable Rust by default in builds (while still allowing opt-out)
2. Git 3.0 will make Rust mandatory with no opt-out option

The announcement explains the rationale for the gradual transition, noting that Git has already begun optional Rust adoption (starting in 2.49) with test balloon implementations to allow distributors time to prepare. The document outlines specific build flags for opting out of Rust (`WITH_RUST=false` for Makefile, `-Dwith_rust=false` for Meson) during the transition period.

The patch also mentions plans for a long-term support release just before the 3.0 transition, which will receive extended maintenance (4 cycles for bug fixes, 6 for security fixes) to accommodate distributors needing more time. The announcement positions this as part of Git's broader Rust adoption strategy that has been developing through the current patch series (particularly referencing the Rust policy documentation in Patch 5 of the same series).

The technical details align with the ongoing work in the thread to integrate Rust via cbindgen and consolidate library dependencies (xdiff, reftable) into libgit.a. The announcement serves as formal documentation of the project's direction that was previously discussed at the Berlin Contributor Summit and is now being implemented through this patch series.
