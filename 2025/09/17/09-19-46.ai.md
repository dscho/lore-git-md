This is a refactoring patch in a completed series converting the string-list API to use proper types and eliminate sign comparison warnings. 

The patch changes the `exact_match` parameter in the string-list API from `int*` to `bool*` to better reflect its semantic meaning as a true/false indicator. This change affects several functions including the internal `get_entry_index()` helper and its callers like `string_list_has_string()` and `string_list_lookup()`. The header file is updated to reflect the changed return type of `string_list_has_string()` from `int` to `bool`.

This change was suggested by Patrick Steinhardt in review of v1 of the series and has been implemented in v2. It's a straightforward improvement to type safety that makes the code's intent clearer without changing behavior. The patch updates all callers to use the new boolean type consistently.

The change is part of a larger effort to eliminate sign comparison warnings in the string-list API by using proper types (size_t for indices, bool for flags). This particular patch focuses on the boolean conversion while subsequent patches in the series handle the index type changes. The thread shows consensus on this approach with no objections raised to this specific change.
