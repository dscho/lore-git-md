This is a minor follow-up to the already-merged series switching Git's default branch name to "main" when built with WITH_BREAKING_CHANGES. Kristoffer Haugsbakk points out two small issues in Junio Hamano's final patch (5/4) that finalized the advice messaging strategy for the branch name change.

First, there's a typo in the commit message where "thta" should be "that". Second, the advice text contains redundant wording - both "can rename" and "can be renamed" appear in the same message. The patch itself modifies refs.c to provide transitional advice when the new default branch name is in effect, specifically helping users who follow tutorials expecting 'master' by showing them how to rename their branch.

The thread context shows this series is fully merged with all technical questions resolved, so these are purely editorial observations about the final patch. The core functionality remains gated behind the WITH_BREAKING_CHANGES flag, with the message focused on temporary tutorial-matching cases and marked as transitional advice to be retired post-3.0. The test infrastructure and documentation updates from earlier in the series are unaffected by these minor wording issues.
