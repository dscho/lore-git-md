This is the third patch in a 4-part series fixing batched reference update issues on case-insensitive filesystems. The series has already been reviewed and approved, with this particular patch addressing file/directory (F/D) conflicts that could occur when creating references in a single transaction (like 'refs/heads/foo' and 'refs/heads/Foo/bar').

The patch modifies the files backend to properly detect these conflicts by lowercasing reference names when checking for F/D conflicts on case-insensitive filesystems. This ensures proper cleanup of lockfiles that would previously be left behind when such conflicts occurred. The change is implemented by adding case-folding logic in `lock_raw_ref()` while maintaining the existing behavior for case-sensitive systems.

Justin Tobler confirmed the approach makes sense, and Karthik Nayak has incorporated the minor wording suggestion ("lowercase" vs "a lower case"). The patch includes tests in t/t5510-fetch.sh to verify the new behavior. This completes one of the four key problems identified in the series, with the implementation now properly handling all identified conflict types on case-insensitive filesystems.
