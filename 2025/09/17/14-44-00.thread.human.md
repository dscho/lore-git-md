Here's a human-readable summary of the thread so far:

Kevin Puetz reported an unexpected behavior where `git fetch --dry-run --filter=tree:0` modifies the local `.git/config` file by adding promisor remote configuration, despite the `--dry-run` flag which should prevent any repository changes. The issue occurs when checking if a commit exists on the remote without triggering a full download, a use case that came up while working with the Conan package manager.

The core problem is that the dry-run semantics aren't being properly respected for filter-related operations - Git is writing promisor configuration (`promisor = true` and `partialclonefilter = tree:0`) when it should either perform a read-only check or fail explicitly. The behavior was observed on Windows using Git 2.51.0, and the clear reproduction steps make this easy to verify. While not causing data loss, this violates the expected dry-run contract and could affect automated systems relying on this guarantee. The Windows-specific aspect may be relevant since configuration file handling can differ across platforms.
