This was observed on Windows with Git 2.51.0, where the expected behavior was either a read-only operation or an error about missing refs.

Brian m. carlson has now responded, acknowledging the core issue that dry-run shouldn't modify config files. The response suggests the original use case (checking commit existence without downloading, as needed by the Conan package manager) may not be well-served by `--dry-run`, since it shouldn't contact the server at all in proper dry-run mode.

The discussion has expanded from a Windows-specific bug report to a deeper examination of dry-run semantics with partial clones. While no fix is proposed yet, the exchange highlights a tension between partial clone requirements and dry-run guarantees that may require either documentation updates or protocol-level changes. The thread remains open with questions about whether this behavior affects other platforms and what the right solution approach should be.
