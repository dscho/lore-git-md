This is a bugfix patch addressing a build system issue in the command deprecation framework series. It resolves a conflict where `git-whatchanged` was still being included in the `BUILT_INS` list in the Makefile despite being marked as deprecated when built with `WITH_BREAKING_CHANGES=YesPlease`.

The patch fixes a confusing error message scenario where users would see "fatal: cannot handle whatchanged as a builtin" instead of the expected "not a git command" message. The issue occurred because the command was still being built but not properly registered in Git's command list. The maintainer Junio C Hamano acknowledges this as a well-thought-out fix for a previous oversight.

This appears to be the final piece needed to complete the deprecation framework series, which has gone through multiple rounds of review and refinement. The patch is narrowly focused on the Makefile change and includes a clear commit message explaining both the problem and solution. With this fix, the deprecation system should now behave consistently across all components.
