This is a bug report about unexpected behavior in `git fetch` with `--dry-run` and `--filter` options. The reporter, Kevin Puetz, found that running `git fetch --dry-run` with filter options (`--filter=tree:0`) modifies the local `.git/config` file by adding promisor remote configuration, despite the `--dry-run` flag which should prevent any changes.

The key issue is that `--dry-run` is not preventing configuration changes when used with partial clone filters. The reporter expected this to be a read-only operation to check if a commit exists on the remote, but instead Git modified the repository configuration by adding `promisor = true` and `partialclonefilter = tree:0` under the remote section. This behavior was observed on Windows using Git 2.51.0.

The context suggests this was discovered while working on a Conan package manager issue where they wanted to check commit existence without triggering a full download. The reporter expected either a no-op or a clear error message about missing refs, not configuration changes.

This appears to be a genuine bug where the dry-run semantics aren't being properly respected for filter-related operations. The report includes clear reproduction steps and expected/actual behavior, making it easy to verify. The impact is moderate - while not causing data loss, it violates the dry-run contract and could affect automated systems that rely on this guarantee. The Windows platform details may be relevant since configuration file handling can differ across systems.
