This is a clarification email in the ongoing discussion about `git clone --shallow-exclude` behavior. Elijah Newren responds to Philipp Hahn's question about why excluding commits by revision is considered "flawed" in the documentation.

Newren explains that his earlier documentation fix (commit 00e10e07510) wasn't making a judgment about whether revision-based exclusion could theoretically work, but rather was correcting the misleading impression that the current implementation supports it. He emphasizes that the current code simply can't handle revision-based exclusions in a useful way, and his changes were focused on making that limitation clear in both documentation and error messages.

The email reinforces that this was a documentation/error-message cleanup effort rather than a technical solution to the underlying functionality. Newren notes he only got involved due to user confusion and doesn't express interest in further developing the shallow clone functionality. The response maintains the status quo where blobless clones remain the recommended workaround for CI pipeline use cases.
