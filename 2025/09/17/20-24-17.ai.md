This is part 7/9 of the v6 series extending Git's command deprecation system with alias shadowing support, focusing on improving the user experience for `git whatchanged` deprecation.

The patch enhances the deprecation warning for `git whatchanged` by adding concrete guidance on how to replace it, either by directly using `git log --raw --no-merges` or by creating an alias. The changes include:
- Adding the replacement command syntax to the `git-whatchanged` documentation
- Modifying `you_still_use_that()` to accept an optional hint parameter
- Updating the `whatchanged` implementation to show specific migration hints
- Maintaining backward compatibility by passing NULL for other deprecated commands like `pack-redundant`

Key technical changes:
- New `hint` parameter added to `you_still_use_that()` declaration in git-compat-util.h
- Implementation in usage.c now conditionally shows hints before the standard deprecation message
- Documentation update shows the exact `git log` equivalent
- All callers updated - `whatchanged` provides hints while `pack-redundant` passes NULL

The patch addresses real-world user confusion post-2.51.0 release, as evidenced by multiple mailing list reports. It builds on the alias shadowing capability introduced earlier in the series while maintaining the deprecation framework's consistent behavior. The implementation is clean and focused, with the hint system designed to be extensible to other deprecated commands if needed.
