This is part 6/9 of the command deprecation framework series, focusing on improving user-facing error messages when deprecated commands are used. The patch refactors the `you_still_use_that()` function to provide more actionable guidance rather than just refusing execution.

Key changes:
- Replaces the terse error message with a structured list of suggestions including:
  - Reading the BreakingChanges documentation
  - Searching mailing list archives (with URL containing percent-encoded command name)
  - Contacting the mailing list if no suitable replacement is found
- Removes the "please add" phrasing and "Thanks" to streamline the message flow
- Uses a `strbuf` to properly encode the command name for the search URL
- Maintains the same refusal behavior but with clearer justification

The changes build on Eric Sunshine's feedback from v2 about making the email suggestion more conditional and using explicit URLs. This patch specifically addresses the user experience aspect of the larger deprecation framework, ensuring users encountering deprecated commands get clear next steps rather than just a refusal.

Implementation notes:
- Adds `strbuf.h` include for percent-encoding
- Keeps the same die() at the end but with simplified message
- The percent-encoding ensures special characters in command names won't break the search URL
- Documentation references point to git-scm.com and lore.kernel.org

This is a well-considered UX improvement that fits cleanly into the series' goal of making command deprecation more user-friendly while maintaining the project's ability to phase out old commands. The changes are focused and the commit message clearly explains the rationale behind each modification.
