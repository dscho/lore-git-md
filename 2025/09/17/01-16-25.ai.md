Documentation patch establishing Git's Rust adoption policy. This is patch 5/18 in a series introducing Rust components to Git, with this particular document serving as the foundational rationale and guidelines for Rust usage.

The patch adds a new technical document `rust-support.adoc` that systematically outlines why and how Git will incorporate Rust. It makes Rust a mandatory platform requirement by updating `platform-support.adoc`. The rationale emphasizes memory safety (citing Android's vulnerability reduction and CISA warnings), developer ergonomics, and incremental adoption. Key policy decisions include: requiring Rust versions matching Debian stable/oldstable (approximately 3-year support window), avoiding `Cargo.lock` in-repo, preferring idiomatic Rust over FFI-optimized code, and caution around crates like libc/rustix due to platform-specific type issues. The document also notes community consensus from the Berlin Contributor Summit.

The policy balances technical benefits with practical constraints - it mandates Rust but with version flexibility for distributors, advocates for gradual transition via static library integration, and establishes clear boundaries around supported toolchains. The type system discussion shows particular attention to cross-platform compatibility challenges. As documentation accompanying a major architectural shift, this provides both justification for the change and concrete guardrails for implementation.
