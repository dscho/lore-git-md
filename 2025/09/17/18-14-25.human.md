This is the third version of a feature patch series adding signature handling control to `git fast-import`. The series introduces a new `--signed-commits=<mode>` option that matches the existing functionality in `git fast-export`, allowing tools like git-filter-repo to control how commit signatures are handled during repository filtering operations. The implementation shares core parsing logic between fast-import and fast-export through a refactored gpg-interface module.

The v3 iteration makes several improvements based on previous reviews:
- Better commit message explanations
- Refactored signature handling into clearer functions (import_one_signature() and discard_one_signature())
- More robust switch statement with BUG() for invalid modes
- Cleaner handling of the SIGN_ABORT case

The author notes this is just the first step, with plans to eventually add more complex modes (re-signing capabilities) and tag signature handling. Two key design questions remain open for feedback:
1. Whether to keep potentially confusing synonym modes ("ignore" for "verbatim")
2. Whether warning variants should remain as separate modes or be controlled by a --verbose flag

The series appears well-tested with comprehensive coverage of signature types and modes, and has received positive review feedback. The implementation seems solid, with CI passing cleanly. The remaining questions are about interface design rather than technical correctness, making this likely ready for merge once those are resolved.
