This is a bug report about unexpected behavior in `git fetch` with `--dry-run` and `--filter` options. Kevin Puetz reports that running `git fetch --dry-run` with a filter (`--filter=tree:0`) unexpectedly modifies the local `.git/config` file by adding promisor remote configuration, despite the `--run` flag suggesting this should be a read-only operation.

The use case involves checking if a specific commit exists on a remote without downloading full objects, which should either succeed silently or fail with an error message. Instead, the command makes persistent configuration changes that affect future operations. The bug occurs on Windows with Git 2.51.0 and appears related to partial clone filter behavior incorrectly interacting with dry-run mode.

This looks like a legitimate bug where dry-run semantics aren't being properly respected. The report is clear and includes reproduction steps, expected vs actual behavior, and context about the real-world use case (related to Conan package manager integration). The configuration changes could cause problems for automated systems that expect dry-run operations to be non-destructive.
