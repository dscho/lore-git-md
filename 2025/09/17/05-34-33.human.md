This is a design discussion about the experimental `git-repo-info` command's interface. Patrick Steinhardt had previously suggested making the command output all fields by default when run without arguments, but after Junio Hamano's concerns about scripting safety, he agrees to keep the explicit `--all` flag approach.

The key point is that while showing all fields by default might be better for interactive discovery, it could cause problems for scripts that call the command without arguments. Junio argues that commands should not silently change behavior based on argument count, especially for scripting use cases. Patrick concedes this point, so the design will maintain the explicit `--all` flag rather than changing the default.

This resolves one of the open questions in the thread, keeping the command's behavior more predictable for scripts while requiring users to explicitly request all fields when they want them. The discussion shows the careful balance Git maintainers strike between interactive usability and scripting reliability.
