Build system fix for the command deprecation framework series.

This patch (1/9 in v6) addresses a build system inconsistency in the git-whatchanged deprecation path. When built with `WITH_BREAKING_CHANGES`, git-whatchanged was removed from the command list in `git.c` but remained in `BUILT_INS` in the Makefile, causing confusing error messages. The fix adds a conditional to exclude git-whatchanged from `BUILT_INS` when `WITH_BREAKING_CHANGES` is active, ensuring users get the proper "not a git command" error rather than a misleading "cannot handle as builtin" message.

Key technical details:
- Modifies `Makefile` to conditionally include git-whatchanged in `BUILT_INS`
- Builds on Jeff King's earlier diagnosis of the issue
- Maintains consistency with 07572f220a8 which removed git-whatchanged from `commands` in `git.c`
- Part of final polishing for the deprecation framework series

The patch is straightforward and uncontroversial, fixing an obvious inconsistency in the build system behavior that was identified during the series' review. It completes the technical implementation of git-whatchanged's deprecation path when `WITH_BREAKING_CHANGES` is enabled.
