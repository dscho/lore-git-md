This is a refactoring patch in the xdiff preparation series, specifically addressing memory management in the xdiff internals. The patch consolidates cleanup code by removing redundant variable handling in `xdl_prepare_ctx()` and standardizing on using the existing `xdl_free_ctx()` function for freeing xdfile_t resources. 

The key technical change replaces manual freeing of individual xdfile_t members with a call to `xdl_free_ctx()`, which already contained the necessary cleanup logic. Junio notes this makes the code safer by having a single point of maintenance for xdfile_t resource management. The patch also properly initializes all xdfile_t members at the start of `xdl_prepare_ctx()`, though this was already the only initialization point in the xdiff API.

While the change alters error handling behavior slightly (now fully clearing xdfile_t on error rather than preserving some fields), analysis shows this doesn't impact actual usage since all callers pass uninitialized memory. The patch maintains the series' goal of behavior-preserving refactoring while simplifying the codebase. Junio approves the changes, particularly noting the attention to detail in brace placement and the safety improvement from having one canonical cleanup path.

This patch (v3 02/10) is part of the now-merged preparatory series that standardized xdiff's internal patterns without introducing Rust-specific changes. The consolidation of memory management here supports the larger goal of making the codebase more maintainable and Rust-compatible, though this particular change focuses purely on C-side improvements.
