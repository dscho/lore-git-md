This is a technical response in the ongoing debate about making Rust mandatory in Git, focusing on NonStop platform constraints. Randall Becker (rsbecker@nexbridge.com) replies to Ezekiel Newren's suggestion about using a cross-platform C compiler to test gccrs solutions for NonStop.

The email clarifies that NonStop only has a C++17 compiler available, with no working GCC implementation. While `gcc -std=c17` might theoretically work for Linux compatibility testing, Becker notes that none of GCC's extensions would function in this scenario. This effectively closes off Newren's proposed path of using a shared C compiler to test gccrs adaptations for NonStop.

The response reinforces the platform-specific technical barriers that make Rust adoption problematic for NonStop systems, where neither mrustc (due to its hidden GCC dependencies) nor gccrs (due to C++17 requirements and loader issues) currently provide viable solutions. The prohibitive cost of real NonStop hardware testing ($500,000 mentioned by Newren) remains an additional obstacle to finding workable solutions for this platform.

This exchange highlights the concrete technical impasse between Git's Rustification goals and the reality of NonStop's constrained toolchain environment, with no immediately apparent resolution that would satisfy both the memory safety objectives and platform compatibility requirements.
