This is a bug report about gitk's macOS-specific behavior. The issue describes how gitk unconditionally tries to use the `osascript` command to focus/raise its UI window on macOS, but fails completely if the command isn't available in PATH. The reporter notes this can happen in environments like Nix shells where the command might be missing, and suggests gracefully handling the failure since this is just a quality-of-life feature rather than core functionality.

The bug appears in gitk version 2.50.1 and relates to macOS-specific UI behavior. The reporter (Robert Scott) proposes making the `osascript` call non-fatal, allowing gitk to continue running normally when the command isn't available. This seems like a straightforward quality-of-life improvement that wouldn't break existing functionality for users who do have `osascript` available. The change would make gitk more robust in constrained environments while maintaining current behavior in standard macOS setups. The report is concise but provides enough technical detail to understand the issue and proposed solution direction.
