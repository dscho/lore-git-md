This is a cover letter for a two-patch series improving window geometry persistence in gitk, the Git repository browser. The series focuses on making window positions and sizes "sticky" (preserved between sessions) for both the main window and the "Tags and Heads" view.

The first patch fixes an oversight where the main window's position wasn't being preserved on startup, though its size was. The second patch makes the "Tags and Heads" window geometry persistent, switching from relative to absolute positioning for more reliable restoration. The changes are relatively small (35 lines added, 2 removed) and focused on gitk's Tcl/Tk UI code.

The v2 iteration simplifies the storage mechanism for window positions compared to v1 and adds the main window position fix. The changes appear straightforward with clear motivation - improving user experience by maintaining window layouts between sessions. The patches target a specific, contained area of gitk and don't appear controversial.
