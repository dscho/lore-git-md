This is a follow-up in the ongoing discussion about `git whatchanged` deprecation. Ben Knoble responds to James Puleo's report about the deprecation causing friction in his workflow of tracking deleted files.

Ben suggests a simpler alternative to both `git whatchanged` and the more complex `git log` variants previously discussed - just using `git log -- path/to/deleted/file`. This provides a more direct solution to James's specific use case of finding which ref last contained a deleted file, without needing the deprecated command or its workaround flag.

The response is brief but adds a potentially more user-friendly solution to the thread's growing collection of alternatives. It doesn't address the broader deprecation debate but offers practical help for the immediate problem. The suggestion aligns with the maintainers' position that `git log` can handle all `whatchanged` use cases, while being simpler than the previously suggested `--raw --no-merges` combination.
