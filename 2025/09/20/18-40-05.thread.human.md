In this thread, Johannes Sixt (Hannes) is improving gitk's window persistence behavior across sessions. The two-patch series addresses how gitk remembers window positions and sizes - a common frustration for users who frequently reposition the interface. 

The first patch fixed the main window's geometry restoration by using Tcl/Tk's `after idle` callback to handle timing issues across different operating systems. The second patch, just submitted, extends this persistence to the Tags and Heads dialog windows. It stores their positions in the config file and maintains their spatial relationship to the main window, with careful handling of window movement and destruction events.

The implementation touches several parts of gitk's Tcl/Tk UI code, adding geometry management to the dialog windows while following the same pattern established for the main window. The changes appear well-contained and should provide a more polished user experience, though the series hasn't yet received review feedback. Given gitk's maintenance model and Hannes' role as its maintainer, these improvements are likely to be adopted once any technical feedback is addressed.
