This thread is about improving gitk's window persistence, specifically making the main window and Tags/Heads dialogs remember their positions and sizes between sessions. Johannes Sixt (Hannes) has submitted a two-patch series addressing this long-standing issue - he's been carrying a revert of the 2008 change that removed position restoration in his personal branch for 17 years.

The first patch fixes main window position restoration using a Tcl/Tk `after idle` callback to handle OS-specific timing issues. The second patch, currently under discussion, adds persistence for the Tags/Heads windows by storing their geometry in gitk's config. Johannes is reviewing Michael Rappazzo's implementation of this second part and has raised several technical questions about the event handling approach, particularly around potential timing issues with the restoration logic and the design of the helper functions.

While the basic approach of storing window geometry is agreed upon, Johannes is seeking clarification on some implementation details before proceeding. The discussion remains constructive, focused on refining the solution rather than questioning its merit. Notably, Johannes has also reached out to Mark (the author of the original 2008 change) to understand the historical rationale for removing position restoration, as this may reveal platform-specific considerations that should inform the current solution.
