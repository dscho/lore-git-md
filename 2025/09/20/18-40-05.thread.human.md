Johannes Sixt (Hannes) has been working on making gitk's window geometry persistent across sessions, addressing a long-standing issue where window positions and sizes weren't reliably remembered. The current patch series (v2) has two parts: one for the main window and another for the Tags/Heads windows. 

Mark Levedahl provided important historical context, explaining that window position restoration was originally removed in 2008 due to bugs in Cygwin's outdated Tcl/Tk 8.4.1 port. This became irrelevant after 2011 when Cygwin switched to a modern X11-based Tcl/Tk implementation (now at version 8.6). This confirmation removes any lingering concerns about platform-specific issues blocking the current approach.

The technical solution for the main window (using Tcl/Tk's `after idle` callback for geometry restoration) is now clearly validated. Discussion can now focus on the remaining implementation details for the Tags/Heads windows, where Johannes has raised some technical questions about the event handling approach and design patterns. These windows need to maintain their spatial relationship to the main window while properly saving and restoring their positions.
