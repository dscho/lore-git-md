This is a technical follow-up in the ongoing debate about making Rust mandatory in Git, focusing on compiler compatibility details. Sam James from Gentoo provides clarifications about GCC's C++ version requirements and mrustc's bootstrap path in response to Ezekiel Newren's questions about NonStop platform constraints.

The email notes that while GCC defaults to C++17, it's actually written in C++14 (recently upgraded from C++11), and suggests gccrs could likely get approval to use C++17 if needed. It clarifies that mrustc isn't part of Rust's official bootstrap path (which uses binaries) and currently has some trivial GCC dependencies that might be portable to Clang. The key limitation highlighted is that mrustc is written in C++ - problematic for NonStop which lacks a C++ compiler.

This adds nuance to the platform support discussion by distinguishing between official Rust toolchain requirements and alternative implementations' constraints. The technical details help frame the challenges of making Rust work across all Git's supported platforms, particularly the NonStop case where even C++ compilation is unavailable. The email maintains a neutral, informative tone while reinforcing the practical difficulties in the mandatory Rust proposal.
