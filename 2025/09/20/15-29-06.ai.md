This is a documentation clarification in the SHA-1/SHA-256 interoperability series, specifically addressing tag signature handling. Brian m. carlson responds to Junio C Hamano's questions about the terminology used to describe dual-signature tags in the documentation.

The email clarifies two key points about tag signature fields: First, it explains that "current algorithm" refers to the main hash algorithm (SHA-256 when configured) while "other algorithm" refers to the compatibility hash (SHA-1), with these roles reversing when converting objects to SHA-1 format. Second, it confirms that a tag cannot simultaneously contain both `gpgsig` and `gpgsig-sha256` headers unless a third hash algorithm is introduced in the future.

Brian agrees with Junio's suggestion to improve the documentation's phrasing about signature field removal, changing "and" to "or" when describing which header fields get stripped during signature verification. This makes the text clearer about the mutually exclusive nature of the two header fields. The response indicates these changes will be incorporated in a future revision of the patch series.

The discussion remains focused on precise documentation wording rather than implementation changes, continuing the thread's pattern of refining technical accuracy in the SHA-1/SHA-256 transition work.
