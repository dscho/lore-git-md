Response from a PowerPC Darwin maintainer opposing mandatory Rust inclusion due to platform support gaps. This is part of the ongoing debate about making Rust a required dependency in Git.

The maintainer provides concrete examples from their experience maintaining ports for PowerPC systems, where Rust currently lacks support. They emphasize that while they don't object to optional Rust support, making it mandatory would hurt open-source accessibility on platforms like PowerPC Darwin and NonStop. 

Key concerns raised include:
1) Current Rust implementations (including mrustc) have platform support gaps and bootstrapping challenges
2) The dependency chain becomes problematic - mrustc itself requires GCC, creating a double requirement
3) Git is essential infrastructure for their porting work and build systems

The email notes they are actively working to improve Rust availability but face technical limitations outside their control, particularly regarding the NonStop platform's loader complexities. They reference specific GitHub issues (#1312, #300) documenting these platform support challenges.

This response adds weight to the portability concerns in the thread, coming from an experienced maintainer with hands-on knowledge of the affected platforms. The technical specifics about mrustc's GCC dependency and NonStop loader issues provide new concrete obstacles to consider in the mandatory Rust debate.
