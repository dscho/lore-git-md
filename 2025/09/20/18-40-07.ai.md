Feature patch for gitk's UI persistence, part 2/2 in a series. This patch extends the window geometry persistence from the main gitk window (handled in part 1) to the Tags and Heads dialog. The implementation stores the dialog's geometry in the config file under `geometry(showrefs)` and maintains its position relative to the main window.

The technical approach involves several Tcl/Tk modifications: adding geometry management to the `showrefs` proc, introducing new `manage_showrefs_geometry` and `destroy_showrefs` helper procs, and updating the window's close/destroy handlers. The geometry is saved both during window movement (via `<Configure>` binding) and before destruction, then restored on recreation using Tk's `after idle` mechanism similar to part 1's solution.

The patch appears well-contained, focusing solely on the Tags/Heads window while following the same persistence pattern established for the main window. The implementation handles edge cases like window existence checks and maintains the existing spatial relationship to the main window. No tests are included, which is typical for gitk's Tcl/Tk codebase. The change should provide a more polished user experience by preserving window layouts across sessions.
