Thread identity: bug report about gitk's macOS-specific window focusing behavior when `osascript` is unavailable in PATH, reported by Robert Scott against gitk version 2.50.1, with follow-up from Eric Sunshine and now maintainer action from Johannes Sixt.

Core problem: gitk unconditionally calls `osascript` to focus/raise its UI window on macOS, failing completely if the command isn't available. This affects environments like Nix shells where `osascript` might be missing, despite being non-critical functionality. The issue was previously identified in 2018 with a fix proposed but not merged.

Current status: Johannes Sixt, the current gitk maintainer, has picked up Eric Sunshine's 2018 patch and created a branch implementing the solution - making the `osascript` call non-fatal while maintaining current behavior when available. The patch is now in testing phase with one minor documentation question about updating lore.kernel.org links in the commit message.

Key technical details: macOS-specific UI behavior in gitk, dependency on `osascript` command in PATH, failure mode when command is missing. The solution wraps the `exec osascript` call in Tcl error handling to prevent complete failure. The technical approach remains valid from 2018, requiring only verification that it works with current gitk code.
