Carlson responds to Junio Hamano's feedback about the pack index v3 format documentation, specifically addressing whether SHA-256 checksums should be truncated to 20 bytes like SHA-1 or use their full 32-byte length.

The discussion centers on a technical detail in the documentation - whether the pack index format should use 20-byte or 32-byte SHA-256 checksums. Brian explains that while there was initial consideration of using truncated 20-byte checksums (matching SHA-1's length), the implementation already uses full 32-byte checksums for SHA-256, and maintaining the shorter length would add unnecessary complexity.
