This thread reports a macOS-specific issue in gitk (Git's graphical history viewer) where the program fails completely if it can't find the `osascript` command, which it uses to focus its window. The reporter notes this happens in environments like Nix shells where `osascript` might not be in PATH, even though the command is just a quality-of-life feature rather than essential functionality. 

The bug affects gitk 2.50.1 and appears to be a straightforward case of missing error handling - the program should gracefully continue when `osascript` is unavailable rather than failing. The proposed solution would make gitk more robust in constrained environments while maintaining the current window-focusing behavior for standard macOS setups. This seems like a reasonable quality-of-life improvement that wouldn't risk breaking existing functionality.
