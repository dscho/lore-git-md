This thread addresses a long-standing issue with gitk's behavior on macOS, where the graphical interface would fail completely if the `osascript` command wasn't available in the PATH - a problem particularly affecting users in constrained environments like Nix shells. The bug was first reported in 2018 but saw no action until now.

Robert Scott originally reported the current manifestation of the issue, with Eric Sunshine providing crucial historical context by pointing to an unmerged 2018 patch that proposed the solution. Johannes Sixt, the current gitk maintainer, has now taken ownership of the fix, implementing the same approach from 2018 - making the `osascript` call non-fatal through Tcl error handling while preserving the window-focusing functionality when possible.

The solution has reached consensus, with Eric Sunshine verifying the technical correctness of Johannes' implementation. The only remaining discussion point is a minor documentation refinement - updating lore.kernel.org links in the commit message to reference the historical context more accurately. With the maintainer engaged and the technical approach validated, this long-dormant issue appears headed for resolution after six years, demonstrating how persistent problems can find new life when the right maintainer attention aligns with community contributions.
