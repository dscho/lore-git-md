This is a technical discussion about Rust toolchain issues on NonStop systems, part of the ongoing debate about making Rust mandatory in Git.

Ezekiel Newren responds to concerns about Rust toolchain availability on NonStop systems, where the GCC compiler isn't always available. The previous email noted that mrustc (a Rust compiler written in C) has hidden GCC requirements and C17 incompatibilities, while gccrs (a GCC-based Rust frontend) faces loader issues on NonStop.

Newren explores potential workarounds, asking whether any C compiler exists that works on both NonStop and Linux, which might allow porting gccrs (written in C++17) to NonStop. He notes Rust's native bootstrap process uses mrustc first, then compiling the rest in Rust itself. The email highlights the practical constraints (including the prohibitive cost of NonStop hardware) that make solving these toolchain issues difficult.

The exchange continues to surface real technical barriers to Rust adoption on some platforms, with no clear solutions yet. The tone remains constructive but underscores the challenges facing Git's Rustification effort on less common architectures.
