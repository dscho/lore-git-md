This thread investigates a regression report where `git fetch --tags` fails to update tags in bare repositories, working in Git 2.50.1 but broken in 2.51.0. The original reporter, David Bohman, provided clear reproduction steps showing the tags would display as being updated but not actually appear in the repository.

Maintainer Junio C Hamano attempted to reproduce the issue but found tags updated correctly in his test environment, with the new tag appearing in `refs/tags/` as expected. His detailed test transcript shows the bare repository's config lacked fetch refspecs (which explains the branch not updating, but this is separate from the tag behavior). The discrepancy suggests the issue may be environment-specific or require more precise reproduction steps. The thread remains open as the core question persists: why does the reporter see different behavior with the same Git version? Further debugging will likely require additional details from the original reporter about their specific setup.
