Summary of thread "Managing inode exhaustion with many small Git repos on NFS":

Thread is a help request about operational scaling challenges when storing thousands of small Git repositories (typically ~5 commits each) on an NFS server, where inode exhaustion occurs before disk space becomes an issue. The author describes constraints: repositories cannot be deleted (valuable data), NFS stores only .git directories exposed as remotes, and existing solutions (repacking, archiving) have proven insufficient. Current workaround is increasing disk size solely to gain more inodes.

Core problem is Git's object storage model (one file per object) interacting poorly with NFS inode limits at scale, exacerbated by small repository size and strict retention requirements. No proposed solution yet - thread is soliciting community input. Potential discussion directions may include alternative storage strategies, filesystem tuning, or Git configuration optimizations for this high-volume, small-repo use case.
