This is a review response in the ongoing series adding Rust FFI wrappers for Git's config parsing functions. Phillip Wood provides feedback on the v3 patch that adds `get_ulong()` and `get_pathname()` methods to the Rust libgit implementation.

The review raises several technical points: the naming of `get_ulong()` (suggesting `get_u64` might be better to avoid platform-dependent types), questions about combining both methods in one commit, and notes about platform-specific type handling in the FFI bindings. Phillip confirms the core implementation looks good but points out the same missing symbol export issue seen in earlier boolean implementation patch - these new functions also need to be declared in `public_symbol_export.[ch]`.

The review also notes some Rust-specific concerns: comment formatting should wrap at 80 columns, and there's a limitation in path handling being restricted to UTF-8 encoded paths due to Rust's standard library constraints. Phillip suggests the pathname handling could be improved on Windows if there were better ways to convert between string encodings.

This continues the pattern seen throughout the thread where the technical approach is sound but needs some polish in implementation details and build system integration. The review doesn't block the functionality but identifies several areas needing attention before the patch can be merged.
