Custom cherry-pick message format proposal from Rasmus Villemoes, seeking to improve backport tracking by replacing the standard "(cherry picked from commit X)" message with version-aware context via a hook. Oswald Buddenhagen counters with an alternative git-notes-based approach for bi-directional commit linking, arguing the current trailer is a historical artifact of Git's early cherry-pick opposition. Notes could provide more robust tracking than message modification while avoiding core changes.

Brian m. carlson suggests a third approach leveraging existing `prepare-commit-msg` hooks for cherry-pick message modification, though without implementation details or addressing the version-tracking requirement. This maintains the thread's core dichotomy between Villemoes' version-aware solution requiring new mechanisms and less invasive approaches using existing systems, while adding a middle path via standard hooks. Open questions remain on all fronts: Villemoes' hook exit semantics and empty output handling, Buddenhagen's notes implementation specifics, and carlson's untested hook applicability. The fundamental tension persists between adding new functionality for robust tracking versus working within current systems, with SHA-1 reference limitations in distributed backports acknowledged by all proposals.
