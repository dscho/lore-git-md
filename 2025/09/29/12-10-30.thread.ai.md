Proposal to improve cherry-pick commit message tracking with three competing approaches: Rasmus Villemoes' hook-based version-aware format, Oswald Buddenhagen's git-notes bidirectional linking alternative, and brian m. carlson's suggestion to use existing `prepare-commit-msg` hooks. Junio C Hamano provides historical context explaining the current bare SHA-1 trailer format originated from Linux kernel workflows where both original and cherry-picked commits were public in the same project, making SHA-1s sufficient identifiers. The feature was originally always-on but became opt-in after user complaints about "useless" references when cherry-picking across private branches.

Key technical points: Villemoes' proposal would add version context through a new hook mechanism, Buddenhagen advocates for git-notes as a more robust tracking solution without core changes, and carlson suggests leveraging existing hooks. Hamano's historical note clarifies the current format was designed for specific public workflow needs rather than being ideologically motivated, with `git show --format=reference` not existing when the feature was created. Open questions remain about hook exit semantics (Villemoes), notes implementation specifics (Buddenhagen), and hook applicability (carlson), with the fundamental tension persisting between new functionality for robust tracking versus working within current systems. All proposals acknowledge SHA-1 reference limitations in distributed backport scenarios.
