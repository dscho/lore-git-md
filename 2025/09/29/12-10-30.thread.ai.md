Custom cherry-pick message format proposal from Rasmus Villemoes. Thread discusses adding a configurable hook to replace the standard "(cherry picked from commit X)" message with version-aware context (e.git describe output) when backporting fixes in projects like U-Boot/Linux kernels. Current -x flag's SHA-1-only reference makes tracking backport status across versions difficult. Proposal would add a config option specifying an executable to generate the message, receiving the commit as input. Open questions include: hook exit code semantics (fail vs fallback to default), empty output handling, and whether the feature's utility justifies core Git changes. Implementation would modify sequencer.c's message generation and introduce new config options. No code yet - seeking community feedback on use case validity and design approach first.
