Bugfix for the Rust libgit boolean config parsing implementation. Phillip Wood reports a build failure in the v3 patch series adding boolean configuration parsing to the Rust libgit implementation (`contrib/libgit-rs`). The issue stems from a missing symbol export - `libgit_configset_get_bool()` is not properly exposed in `contrib/libgit-sys/public_symbol_export.[ch]`, causing linker errors when running the tests. This follows the same pattern as the existing `configset_get_int()` implementation that the patch series builds upon.

The original patch from ionnss added comprehensive boolean parsing support via FFI-wrapped C functions, including tests for all Git boolean formats (true/false, yes/no, on/off, 1/0) and edge cases. Phillip's response indicates the implementation is otherwise correct but needs this one technical fix to properly expose the symbol through the FFI layer. This appears to be a straightforward oversight in an otherwise well-tested patch that has already had its core approach (using FFI-wrapped C functions) confirmed by maintainers in earlier rounds.
