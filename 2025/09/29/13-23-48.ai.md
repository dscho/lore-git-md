This is a bugfix for the Rust libgit implementation's boolean configuration parsing feature. Phillip Wood identifies a build failure in patch 2/3 of the v3 series, where the FFI wrapper for `git_configset_get_bool()` is missing from the public symbol exports.

The issue manifests as a linker error when running tests, specifically an undefined reference to `libgit_configset_get_bool`. Phillip notes this occurs because the function isn't properly exposed in `contrib/libgit-sys/public_symbol_export.[ch]`, unlike the existing `configset_get_int()` wrapper. This prevents the Rust implementation from linking against the C function it depends on.

The original patch added comprehensive boolean parsing support through FFI-wrapped `git_configset_get_bool()`, including tests for all Git boolean formats (true/false, yes/no, on/off, 1/0) and edge cases. The implementation returns `Option<bool>` and handles missing keys properly. Test coverage appears thorough with 9 cases covering various boolean representations and edge conditions.

This appears to be a straightforward omission in the FFI plumbing - the Rust-side declaration exists in `lib.rs` but the C-side export is missing. The fix should involve adding the symbol to the public exports file, following the same pattern used for other config functions. The boolean parsing logic itself seems correct and well-tested, matching Git's native behavior exactly as required by the project's FFI-wrapping approach.

Key technical details:
- Missing symbol: `public_symbol_export.[ch]` needs `libgit_configset_get_bool` export
- Affected files: `contrib/libgit-sys/` build infrastructure
- Test failure mode: linker error when running `cargo test`
- Correct behavior: should mirror `configset_get_int()` export pattern
- Implementation otherwise complete with:
  - Proper FFI binding in `lib.rs`
  - Comprehensive tests in `config4`
  - Memory-safe Rust wrapper returning `Option<bool>`
