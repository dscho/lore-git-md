Rasmus Villemoes proposes adding configurable cherry-pick message formatting to help maintainers track backported fixes more effectively. The current `-x` flag simply appends "(cherry picked from commit X)", which lacks context about which version tags contain the original commit. This creates maintenance headaches in projects like U-Boot where backports need to be tracked across multiple version branches.

The suggested approach would introduce a hook that receives the commit SHA-1 and can generate a custom message - for example, one that includes `git describe` output to show version tag context. Rasmus is seeking feedback on several design questions before implementing: how the hook should be configured, what should happen when the hook fails or produces no output, and whether this feature would be useful enough to include in mainline Git. The change would touch the sequencer code that handles cherry-pick message generation. While clearly valuable for downstream maintainers, it remains to be seen whether the broader community will find the functionality generally useful enough to warrant the new configuration surface area.
