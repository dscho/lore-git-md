This thread explores ways to improve tracking of cherry-picked commits across different versions of a project. Rasmus Villemoes originally proposed adding a configurable hook to replace Git's standard "(cherry picked from commit X)" message with version-aware context (like `git describe` output), particularly useful for projects like U-Boot and Linux kernels that maintain multiple versions. The discussion initially focused on implementation details like hook behavior and whether the change merited core Git modifications.

Oswald Buddenhagen has now introduced an alternative approach using git-notes to create explicit links between original and cherry-picked commits, arguing this would provide more robust tracking than message trailers. He notes the current message format reflects Git's early ideological stance against cherry-picks and that many projects already manually customize these messages. While this suggestion doesn't address the original hook proposal's specifics, it presents a conceptually different solution that would work within Git's existing mechanisms rather than adding new configurability.

The thread now has two distinct directions: Villemoes' hook-based approach for customizable messages versus Buddenhagen's git-notes proposal for bi-directional commit linking. Both aim to solve the same core problem of improving cherry-pick traceability across versions, but through different technical means. No code has been proposed yet for either approach - the discussion remains at the design stage, weighing the merits of each solution.
