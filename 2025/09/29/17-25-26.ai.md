This is a discussion contribution to the ongoing thread about root-level file sharing between repositories. Randall Becker adds new use cases and implementation considerations to George Ogden's original proposal.

Randall introduces two concrete examples where root-level file sharing would be valuable: GNU autoconf's `config.guess` and `config.sub` files, and organizational root certificates. These join the original `.pre-commit-config.yaml` example, strengthening the case for the feature by showing diverse scenarios where tools mandate root-level configuration files that should be centrally managed.

The email suggests two possible implementation directions: extending submodules to support "link upwards" functionality (presumably allowing files to appear in parent directories), or leveraging the sparse-checkout infrastructure. Both ideas are presented tentatively as areas for exploration rather than concrete proposals. The mention of sparse-checkout is particularly interesting as it suggests a potential connection to Git's existing partial checkout mechanisms.

This contribution expands the discussion's technical scope while maintaining focus on the core problem - the need for version-controlled root files that can be shared across repositories without manual synchronization or workarounds. The examples given are particularly compelling because they involve files that are clearly external to the project's main content (platform detection scripts, security certificates) yet must reside at the root.
