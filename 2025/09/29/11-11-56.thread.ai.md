Thread identity: Bug report and fix for `git reflog write` command's committer information handling.

Core problem: The new `git reflog write` command was failing to honor local `user.name` and `user.email` configuration values, falling back to system defaults for reflog entry authorship. This created inconsistency with Git's standard configuration hierarchy that other commands follow.

Current status: Michael Lohmann has implemented the fix following Patrick Steinhardt's diagnosis, adding proper config lookup via `repo_config(repo, git_ident_config, NULL)` in `builtin/reflog.c`. The patch includes test coverage verifying config handling by unsetting environment variables and checking locally configured user information appears in reflog entries. Patrick has reviewed the implementation and suggested minor improvements to commit message formatting and test organization.

Key technical details: The fix addresses the command's previous omission of Git's normal config lookup mechanisms. The test in t1421-reflog-write.sh demonstrates corrected behavior by creating reflog entries with custom local config after clearing environment variables. Patrick recommends splitting this test case into a separate block from the 'simple writes' test for better organization. The implementation maintains existing functionality when environment variables are present while adding config hierarchy support.
