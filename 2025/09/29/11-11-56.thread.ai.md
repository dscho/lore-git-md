Thread identity: Bug report and fix for `git reflog write` command's committer information handling.

Core problem: The new `git reflog write` command was failing to honor local `user.name` and `user.email` configuration values, falling back to system defaults for reflog entry authorship, creating inconsistency with Git's standard configuration hierarchy.

Current status: Version 3 of the fix has been approved by Patrick Steinhardt and is ready for inclusion. The implementation properly respects both environment variables and config values in correct precedence order, with config reading moved before `parse_options()` in `builtin/reflog.c` per Junio Hamano's architectural suggestion. The test suite in t1421-reflog-write.sh validates config usage when environment variables are unset and confirms environment variable precedence when both are present.

Key technical details: The solution uses `repo_config(repo, git_ident_config, NULL)` positioned early in command flow to support future subcommands. Tests use `$GIT_COMMITTER_DATE` for maintainability. The commit message clearly explains problem and solution, addressing all documentation concerns.

Open questions: None - all concerns addressed. The pattern established may influence future subcommand implementations.
