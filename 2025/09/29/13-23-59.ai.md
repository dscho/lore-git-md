This is a review response in the ongoing series implementing configuration value parsing in Rust libgit (`contrib/libgit-rs`), specifically addressing patch that adds `get_ulong()` and `get_pathname()` methods. The reviewer, Phillip Wood, provides technical feedback on the implementation while generally approving the approach.

Key points raised:
1. Naming concern for `get_ulong()` - suggests `get_u64` might be more platform-independent while noting the current implementation correctly returns u64
2. Suggests splitting the commit into separate patches for ulong and pathname functionality, following the pattern used for `get_bool()`
3. Notes platform-dependent type issues with `c_ulong` definition and questions why std::ffi types aren't used directly
4. Requests comment wrapping to 80 columns
5. Observes UTF-8 limitation in path handling due to Rust stdlib constraints
6. Confirms missing symbol exports in `public_symbol_export.[ch]` (a recurring issue also affecting the boolean implementation)
7. Generally approves the technical implementation while flagging these organizational and platform-specific concerns

The review maintains the thread's technical focus on using FFI-wrapped C functions (`git_configset_get_ulong()` and `git_configset_get_pathname()`) while identifying remaining work items. The feedback suggests the series is nearing readiness pending these adjustments and maintainer approval of the expanded scope beyond boolean handling.
