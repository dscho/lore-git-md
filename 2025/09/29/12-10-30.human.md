This is a feature proposal for customizing cherry-pick commit messages. Rasmus Villemoes suggests adding a configurable way to augment the standard "(cherry picked from commit X)" line with additional context, specifically the version tag containing the original commit (like "v2025.01-rc2~35^2~5"). 

The author currently does this manually when cherry-picking fixes from upstream projects like U-Boot or Linux kernels, finding it helpful for tracking whether commits still need to be ported to newer versions. The proposal is to add a config option that would specify an executable to generate this supplemental information automatically, with clear semantics for handling cases where the executable fails or produces no output.

The email thoughtfully considers edge cases and asks for feedback on the proposed behavior before implementing. This appears to be a well-motivated quality-of-life improvement for maintainers who regularly backport fixes, though its utility may depend on how common this particular version-tagging workflow is among Git users. The author is open to alternative approaches and community input on the design.
