This is a feature proposal for customizing the cherry-pick commit message format. Rasmus Villemoes suggests adding a configurable hook that would allow replacing the standard "(cherry picked from commit X)" message with a more informative version that includes version tag context.

The key motivation is improving maintainability when backporting fixes in projects like U-Boot or Linux kernels. The current `-x` flag's simple SHA-1 reference makes it hard to track whether commits are already included in future versions. Rasmus demonstrates manually adding version tag context (via `git describe`) to these messages but seeks to automate this.

The proposal centers around a config option that would specify an executable to generate the cherry-pick message. The executable would receive the commit SHA-1 as input. Rasmus outlines several possible behaviors for the hook's exit code and output handling, seeking feedback on the most sensible approach (e.g., whether empty output should fall back to default or fail the operation).

This touches the cherry-pick machinery's message generation in `sequencer.c` and would require adding new config options. The change appears well-motivated for maintainers of downstream forks but may be too niche for general Git usage. The thread starter is soliciting community feedback on both the utility of the feature and the proposed implementation approach before writing code.
