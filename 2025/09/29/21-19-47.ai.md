This is a discussion contribution to the ongoing patch workflow optimization thread, specifically addressing testing of the 'next' branch. Ben Knoble builds on Kristoffer Haugsbakk's suggestion about large projects testing against 'next' by proposing a Rust-inspired "crater" approach - where known major Git users would run their test suites against Git's development branches (both 'next' and 'master') on a regular basis, potentially on every commit.

The email references Rust's crater system (a distributed tool that compiles and tests Rust code against compiler changes to detect regressions) as a potential model for Git. This would theoretically provide broader testing coverage of the 'next' branch than currently exists, addressing Taylor Blau's concern about limited real-world testing of 'next'.

The proposal remains conceptual, with no implementation details or analysis of how to coordinate with large Git-using projects. It represents an expansion of the thread's exploration of ways to improve confidence in 'next' branch stability, which is key to discussions about potentially shortening the 7-day integration period. The suggestion maintains the thread's technical focus while introducing a new testing paradigm from another open source ecosystem.
