This is part 5 of a 7-patch series extending the promisor-remote protocol to support configurable validation of remote attributes. The series is now at v8 with all technical implementation complete, pending final terminology decisions.

This patch focuses on code hygiene by replacing `strbuf_split_str()` with `string_list_split()` in `filter_promisor_remote()`. The change builds on the previous introduction of `parse_one_advertised_remote()` which takes a `const char*` argument, making the heavier `strbuf` infrastructure unnecessary. The patch simplifies the parsing flow by:
- Replacing the `struct strbuf` array with a lighter `string_list`
- Using the new `string_list_split()` helper
- Iterating with `for_each_string_list_item()`
- Cleaning up with `string_list_clear()`

The change maintains all existing functionality while aligning with the series' broader effort to modernize string handling. It follows Junio Hamano's preference for non-destructive string splitting and connects to the project's ongoing string literal elimination effort. The patch appears well-contained and focused, with no behavioral changes beyond the internal implementation improvement.
