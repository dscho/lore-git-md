Junio Hamano weighs in on the discussion about Git's dumb HTTP protocol limitations, firmly rejecting Jeff King's suggestion that the protocol could be enhanced to scrape directory listings like httpdirfs does. As the Git project maintainer, Hamano draws a clear line - any such change would fundamentally alter the nature of "dumb HTTP" transport. His brief but definitive response suggests the current behavior (requiring pre-generated `info/refs`) is an intentional design constraint rather than an implementation limitation to be worked around.

This maintains the thread's consensus about HTTP's inherent limitations while shutting down one potential avenue for improvement. The exchange highlights the project's conservative stance on protocol changes, especially for less-maintained components like dumb HTTP transport. Readers following this thread now have a clear signal that while the current behavior may be inconvenient, significant changes to dumb HTTP's operation are unlikely to be accepted.
