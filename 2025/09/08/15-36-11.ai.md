This is a feature series extending Git's command deprecation system, building on the recently merged `git whatchanged` deprecation work. The v3 series introduces several key technical changes to improve the deprecation workflow, particularly around alias handling for deprecated commands.

The series adds 4 new patches (1-4) implementing Peff's proposed solution for allowing aliases to shadow deprecated builtins, plus documentation and test coverage. The remaining patches (5-8) update the existing deprecation messaging to include alias suggestions now that this is possible. Key technical components include:
- New `DEPRECATED` flag in command definitions
- Modified `list_builtins()` to support include/exclude filtering
- `is_deprecated_command()` helper function
- Alias shadowing logic in `run_argv()`
- Comprehensive test coverage in t0014-alias.sh

The implementation allows users to create aliases for deprecated commands like `whatchanged` and `pack-redundant` while maintaining the existing prohibition against shadowing non-deprecated builtins. The error messages have been updated to suggest both direct command alternatives and alias creation.
