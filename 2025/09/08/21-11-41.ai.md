This is a technical refinement discussion in the ongoing command deprecation framework series, specifically addressing patch 3/8 which implements alias shadowing for deprecated commands. Jeff King (Peff) responds to Junio Hamano's suggestion about improving the deprecation check implementation.

The core issue revolves around the current implementation's use of a hardcoded list in `is_deprecated_command()` versus the newly introduced `DEPRECATED` flag in the `cmd_struct` array. Junio had pointed out this inconsistency, suggesting the flag-based approach would be more maintainable.

Peff agrees with the general direction, proposing a simpler implementation that would check the `DEPRECATED` flag via `get_builtin()`. He acknowledges this might not cover external deprecated commands (which would require name matching), but considers that an unlikely edge case that could be addressed later if needed. The proposed change would make the code more maintainable as new deprecated commands would automatically be handled by setting the flag rather than updating the hardcoded list.

This discussion represents a late-stage refinement to an otherwise complete implementation, focusing on internal consistency rather than user-facing behavior. The thread shows consensus on the core design while working through final implementation details before the series can be merged.
