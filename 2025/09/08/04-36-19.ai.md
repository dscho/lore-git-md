Feature implementation for `git replay` adding atomic ref updates. This is the first patch in a 2-part series introducing a new `--update-refs` option to perform reference updates directly within `git replay` rather than requiring piping to `git update-ref`. The change enables atomic transactions by default) and adds a `--batch` mode for partial failure tolerance.

The implementation modifies `builtin/replay.c` to handle direct ref updates using Git's ref transaction API, with extensive test coverage (nearly 600 lines across new test files t3650 and t3651). Key technical details:
- Uses `ref_store_transaction_begin()` with atomic mode by default
- Supports `REF_TRANSACTION_ALLOW_FAILURE` flag for batch mode
- Validates incompatible flag combinations (`--update-refs` vs `--update`)
- Maintains backward compatibility with existing behavior
- Specifically designed for bare repository/server-side workflows (Gitaly use case mentioned)

The patch appears well-structured with thorough test coverage of both success and failure cases, including edge conditions like empty ranges and conflict scenarios. The implementation follows patterns from `builtin/update-ref.c` and maintains the existing replay command's behavior when not using the new option.
