Feature implementation and test balloon for Rust infrastructure in Git core. This is patch 5/8 in Patrick Steinhardt's RFC series introducing Rust support to Git.

The patch converts the varint encoding/decoding subsystem from C to Rust as a test case, chosen for its simplicity and lack of dependencies. When Rust is enabled, the build system now compiles `varint.rs` instead of `varint.c`. The Rust implementation provides identical functionality through `decode_varint()` and `encode_varint()` functions with the same signatures as their C counterparts, plus comprehensive test coverage.

Key technical details:
- Build system modifications in both Makefile and meson.build to conditionally include either the C or Rust version
- New Rust module varint with unsafe extern C functions matching the original API
- Thorough test cases covering normal operation and edge cases (including overflow detection)
- Maintains identical behavior to the C implementation
- First concrete example of a Rust/C boundary in the series

The implementation demonstrates several important aspects of the Rust integration:
- Direct FFI compatibility with existing C callers
- Memory safety through Rust's ownership system while maintaining pointer-based C API
- Comprehensive test coverage as part of the conversion
- Build system integration for optional feature inclusion

This serves as both a technical proof point and a template for future subsystem conversions in the Rust migration effort. The choice of varint as the first target provides a low-risk validation of the approach before tackling more complex subsystems.
