This is a bugfix patch addressing file/directory (F/D) conflicts on case-insensitive filesystems, part of a series improving batched reference updates. The patch specifically handles conflicts like 'refs/heads/foo' vs 'refs/heads/Foo/bar' that weren't properly detected during transaction preparation.

The solution modifies `lock_raw_ref()` in refs/files-backend.c to lowercase reference names when checking for conflicts on case-insensitive systems, while maintaining the original case for actual reference creation. This avoids leaking filesystem-specific behavior into the shared `refs_verify_refnames_available()` function. The patch includes a new test case in t5510-fetch.sh that verifies the fix by attempting to fetch conflicting references.

This is the third patch in a v2 series that has seen thorough review, with Junio Hamano identifying the original issue and Patrick Steinhardt providing technical feedback. The implementation is clean and focused, with clear test coverage showing the expected behavior when conflicts occur - the transaction fails for conflicting references while allowing non-conflicting updates to proceed. The approach maintains backend separation while solving a real-world problem affecting users on case-insensitive filesystems.
