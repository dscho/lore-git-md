Feature patch in the command deprecation framework series, specifically implementing alias shadowing for deprecated commands. This is patch 3/8 in v3 of the series, building on Jeff King's earlier proposal and addressing user experience concerns around deprecated commands like `git whatchanged`.

The core change allows aliases to override deprecated builtins (currently `whatchanged` and `pack-redundant`), solving the awkward transition period where users couldn't create working aliases for deprecated commands they wanted to replace. The implementation adds an `is_deprecated_command()` check in `git.c` that bypasses the normal alias-blocking logic for deprecated commands, plus documentation update noting this exception.

Key technical details include:
- New `is_deprecated_command()` helper function checking against hardcoded list
- Modified alias handling in `run_argv()` with explicit deprecated command check
- Comprehensive test in t0014-alias.sh verifying shadowing works for all deprecated commands
- Documentation update in alias.adoc clarifying the exception

The patch maintains backward compatibility while solving the specific pain point of users wanting to alias `whatchanged` to its modern equivalent during the deprecation period. Test coverage is thorough, including edge case handling via `test_might_fail` and output verification. The implementation follows the series' pattern of being conservative with behavioral changes while adding targeted flexibility where needed.
