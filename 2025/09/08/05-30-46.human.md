This is version 8 of a feature series extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series builds on previous work to introduce `struct promisor_info` and now adds server-side field transmission (`promisor.sendFields`) and client-side validation (`promisor.checkFields`).

Key changes in v7->v8:
- Rebased to avoid conflicts with recent topics
- Replaced remaining `git_config_get_string*` calls with `repo_config_get_string*`
- Simplified parsing using new `skip_field_name_prefix()` helper
- Improved `parse_one_advertised_remote()` to avoid modifying input strings
- Added two new patches (5/7 and 7/7) to fully eliminate `strbuf_split*` usage
- Moved string constants patch earlier in series to reduce churn

The implementation appears technically complete with:
- Passing CI tests
- Thorough test coverage
- Polished documentation
- Addressed review feedback from Junio and others
- Clean string handling using modern `string_list` APIs

The main outstanding question is whether to use "field" vs "configuration variable" terminology, but the code itself seems ready. This refresh comes just in time to prevent the series being dropped from 'seen' due to inactivity. The changes look focused and well-justified, continuing the trend of careful refinement seen in previous iterations.
