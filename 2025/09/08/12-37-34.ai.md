This is a bugfix series addressing case-insensitive filesystem issues in the files backend's batched reference updates. The cover letter summarizes four distinct but related problems that emerged after Git 2.51's switch to batched transactions for fetch/receive-pack operations.

The series handles three categories of case-sensitivity conflicts: (1) direct case collisions (foo vs Foo), (2) file/directory conflicts (foo vs Foo/bar), and (3) directory/file conflicts (Foo/bar vs foo). Each case now properly reports conflicts while allowing non-conflicting updates to proceed, rather than aborting the entire transaction. The implementation adds case-folding checks in `lock_raw_ref()` and `refs_verify_refnames_available()`, with memory optimizations using `string_list_append_nodup()`.

Key technical changes include a new `REF_TRANSACTION_ERROR_CASE_CONFLICT` error code, case-insensitive conflict detection during reference verification, and proper lock cleanup for failed transactions. The series affects `git fetch`, `git receive-pack`, and `git update-ref --batch-updates`, with user-facing warnings recommending migration to the reftable backend for case-insensitive environments.

Test coverage in t/t1400-update-ref.sh and t/t5510-fetch.sh verifies the fixes by creating repositories with conflicting references and confirming partial updates succeed where appropriate. The implementation builds on Patrick Steinhardt's feedback from v1, particularly around memory management and error categorization. One outstanding test case for D/F conflicts on macOS remains to be addressed in future versions.
