This thread introduces a new `--update-refs` option for `git replay` to enable atomic reference updates directly within the command, eliminating the need to pipe output to `git update-ref`. The RFC series consists of two patches: an implementation patch and this documentation update.

The core functionality provides atomic transaction behavior by default (all refs update or none do), with an optional `--batch` mode for partial updates. The change is specifically designed for bare repositories, making it suitable for server environments. The implementation modifies `builtin/replay.c` to handle direct ref updates using Git's ref transaction API, with extensive test coverage.

The newly submitted documentation patch thoroughly explains the new options, including:
- How `--update-refs` uses Git's ref transaction API for atomic updates
- The behavior of `--batch` mode for partial updates
- Differences in output behavior between regular mode (piped to update-ref), `--update`, and `--update-refs`
- Multiple examples showing usage patterns
- Updated output format details for all three modes of operation

The series appears well-structured with both implementation and documentation carefully considered. It was motivated by discussions about improving server-side workflows, particularly with Christian Couder. While marked as experimental, the patches show thorough attention to both technical implementation and user-facing documentation. No reviews have been posted yet on this initial RFC version.
