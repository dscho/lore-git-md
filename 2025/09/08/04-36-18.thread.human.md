This RFC thread explores adding atomic reference updates to `git replay`, primarily for server-side workflows like GitLab/Gitaly. The initial 2-patch series proposed new `--update-refs` functionality to enable direct, atomic ref updates without piping to `git update-ref`. 

Christian Couder provided early documentation review, clarifying GitLab's use case and flag design questions. Patrick Steinhardt then raised substantive implementation issues, particularly around performance with the reftable backend and flag complexity, suggesting consolidation to a single `--update-refs` with modes. Kristoffer Haugsbakk identified several mechanical issues with patch formatting and documentation synchronization.

In the latest update, Siddharth Asthana addresses Christian's feedback, agreeing to merge the documentation with the implementation patch in v2. He's reconsidering the flag design - potentially simplifying from three flags to one parameterized option - and clarifying the atomicity behavior differences from `git rebase --update-refs`. The discussion has progressed from high-level design to specific UX and implementation tradeoffs, with the author demonstrating responsiveness to review feedback while preserving the core atomic update functionality needed for server workflows.
