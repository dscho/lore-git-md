This RFC thread explores adding atomic reference update capabilities to `git replay`, primarily targeting server-side workflows like GitLab/Gitaly. The initial proposal introduced `--update-refs` and `--update` flags to enable direct ref updates without piping to `git update-ref`, with Christian Couder providing early documentation feedback on flag design and behavior.

Patrick Steinhardt has now weighed in with substantive implementation concerns, suggesting the current approach may be inefficient for reftable backends and proposing API simplifications. His review highlights three key areas needing attention: performance (particularly around batched vs individual ref updates), reducing the flag interface complexity, and aligning with Git's existing ref transaction patterns. This moves the discussion from documentation review into deeper technical considerations.

The thread remains in design phase, with open questions about how to best balance atomicity guarantees with performance across different ref backends. Patrick's involvement signals the importance of getting the reftable integration right, given his role in that subsystem. Next steps will involve addressing these implementation concerns while preserving the core goal of atomic updates for server workflows.
