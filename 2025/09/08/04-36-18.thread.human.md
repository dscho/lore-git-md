This RFC thread explores adding atomic reference updates to `git replay` via a new `--update-refs` flag, primarily targeting server workflows like GitLab/Gitaly. The feature would enable direct ref updates without piping to `git update-ref`, with current implementation spanning code and documentation changes. The core design provides atomic transactions by default using Git's ref transaction API.

The discussion has evolved through several phases: Patrick Steinhardt proposed the technical implementation, Christian Couder raised deployment concerns given 18 months of existing usage, and Elijah Newren countered that the command's prominent experimental markings (four separate warnings) justify interface improvements. Documentation refinements from Siddharth Asthana and Andrei Rybak have clarified the server-side benefits.

In the latest exchange, Newren and Junio Hamano have found common ground - they agree that if the new behavior is clearly superior for most cases, changing the default is reasonable despite prior usage, given the command's experimental status. They're converging on making `--update-refs` the default while preserving backward compatibility through a new flag for the old behavior. The thread shows how the project balances technical improvement against real-world adoption constraints, particularly for server-side features where behavior changes can be disruptive.
