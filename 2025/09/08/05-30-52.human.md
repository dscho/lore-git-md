This is part 6 of a 7-patch series extending the promisor-remote protocol to support configurable validation of remote attributes. The series is now at v8 with all technical implementation complete, pending final terminology decisions.

The current patch introduces client-side validation of additional promisor-remote fields ("partialCloneFilter" and "token") through a new `promisor.checkFields` config variable. When set, the client will verify that any advertised values for these fields match its local configuration before accepting the remote. The validation is strict - all three conditions must pass: local config must be set, server must advertise the field, and values must match exactly.

The implementation builds on the series' earlier introduction of `struct promisor_info` and includes thorough documentation of the new config option. Test coverage demonstrates the validation behavior, showing how mismatched filter configurations cause the client to reject the remote. The patch maintains the series' focus on security and consistency while completing the bidirectional protocol extension.

This appears to be a well-polished addition to the series, with clear documentation and tests that verify the intended behavior. The only remaining discussion point is the terminology choice between "field" and "configuration variable" for the new config options, which doesn't affect the technical implementation.
