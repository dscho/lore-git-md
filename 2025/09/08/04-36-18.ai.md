This is a feature patch series introducing a new `--update-refs` option to `git replay`. The series aims to simplify server-side operations by enabling atomic reference updates directly within the replay command, eliminating the need to pipe output to `git update-ref`.

The main patch adds the `--update-refs` option which provides atomic transaction behavior by default (all refs update or none do), with an optional `--batch` mode for partial updates. The implementation specifically supports bare repositories, making it suitable for server environments like Gitaly. The second patch documents these new options in the man page.

Key technical details include:
- The option cannot be used with the existing `--update` flag
- Success cases produce no output, matching `git update-ref --stdin` behavior
- Tests are extensive, adding over 500 lines across two new test files (t3650 and t3651)
- Changes touch the replay command implementation and documentation

The motivation comes from discussions with Christian Couder about improving server-side workflows. The patch appears well-structured with thorough test coverage for the new functionality. The atomic behavior addresses a reliability gap in the current two-command workflow while maintaining backward compatibility.
