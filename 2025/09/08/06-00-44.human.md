This is a documentation patch in an ongoing thread about adding atomic reference updates to `git replay`. Christian Couder provides feedback on Siddharth Asthana's documentation for the new `--update-refs` and `--batch` options.

The feedback focuses on several documentation issues: the separation of documentation from implementation, unclear relationship between `--update` and `--update-refs`, and some redundant phrasing. Christian questions the naming choices and asks how these options compare to similar ones in `git rebase`. He also points out missing details about atomicity guarantees and failure behavior, particularly noting that the docs don't clearly state whether `--update` provides atomic updates.

The discussion highlights that the documentation needs to better explain:
- When to use each option (`--update` vs `--update-refs`)
- The atomicity guarantees (or lack thereof) for each mode
- How failure cases are handled differently between modes
- The relationship to similar functionality in other Git commands

This is part of an RFC series that aims to make `git replay` more suitable for server-side use by adding direct, atomic ref updates. The feedback suggests the documentation needs refinement to clearly communicate the behavior and tradeoffs of the new options.
