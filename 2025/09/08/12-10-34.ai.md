Feature proposal for HTTP protocol to support WebDAV PROPFIND.

Milan Hauth reports that Git's dumb HTTP protocol fails to work with WebDAV-enabled HTTP servers like nginx with the WebDAV extension module. Currently, operations like `git ls-remote` fail with "repository not found" errors when pointing to WebDAV-hosted repositories, requiring manual `update-server-info` as a workaround.

The email demonstrates the issue with nginx configuration showing WebDAV PROPFIND and OPTIONS methods enabled, along with curl commands showing the directory listing capability. Hauth references a previous discussion where WebDAV support was considered but rejected due to concerns about server compatibility, but argues this should be reconsidered for better interoperability with WebDAV-enabled servers.

Key technical details include:
- Current failure modes with `git ls-remote` on WebDAV paths
- nginx WebDAV module configuration showing PROPFIND support
- Workaround requiring manual `update-server-info`
- Reference to prior discussion about WebDAV support tradeoffs

This appears to be a serious proposal to extend Git's HTTP protocol support, though it would require careful consideration of backward compatibility and server support implications. The patch would likely touch Git's HTTP transport code to add WebDAV PROPFIND handling when available.
