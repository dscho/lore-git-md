This is the first patch in a bugfix series addressing color handling issues in Git's interactive patch mode. Jeff King fixes a specific case where `git stash -p` could produce malformed output when the `GIT_PAGER_IN_USE` environment variable is set, causing the underlying `diff-tree` and `diff-index` plumbing commands to incorrectly emit color codes.

The patch explicitly adds `--no-color` flags to all `diff-tree` and `diff-index` calls in `builtin/stash.c` to prevent color output regardless of environment settings. This matches the behavior already used in `add-interactive`. The change comes with new test cases that verify the fix works for both partial stashes (`-p`) and staged changes.

The commit message provides good context about why this is needed (the historical "auto" color default in plumbing commands) and why a more comprehensive fix would be risky changes to diff plumbing behavior. This appears to be a well-justified, targeted fix for a real (if somewhat obscure) bug, with thorough test coverage. It's part of a larger series addressing color handling inconsistencies that arose during the 2021 Perl-to-C conversion.
