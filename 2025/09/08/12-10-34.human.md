This is a bug report and feature request regarding Git's HTTP protocol support. Milan Hauth reports that Git's dumb HTTP transport fails to work with WebDAV-enabled servers, specifically when using nginx with WebDAV extensions. The issue manifests when trying to perform read operations like `git ls-remote` against repositories served via WebDAV, with Git client failing to find the repository.

The email demonstrates the problem with clear reproduction steps, showing how the operations fail with standard Git but can be made to work with a manual `update-server-info` workaround. Hauth references a previous discussion about why Git doesn't use WebDAV by default (for broader server compatibility), but argues this should be reconsidered for WebDAV-enabled setups.

The report is well-researched, including specific nginx configuration examples and curl commands to verify WebDAV functionality. It builds on prior mailing list discussions and presents a concrete use case where current behavior is problematic. The issue appears legitimate and the presentation thorough, making it worth consideration for developers working on Git's HTTP transport layer.
