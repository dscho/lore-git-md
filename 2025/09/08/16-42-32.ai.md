This is the first patch in a bugfix series addressing color handling issues in Git's interactive patch mode, specifically focusing on the `stash` command. The patch fixes a regression where child `diff-tree` and `diff-index` processes could incorrectly output color when `GIT_PAGER_IN_USE` is set, causing `git-apply` to fail.

The core issue stems from plumbing commands (like `diff-tree`) having a baked-in "auto" color default that bypasses the normal `color.ui` check. While the broader issue of plumbing command color defaults remains unresolved (as noted in the historical discussion referenced), this patch takes the pragmatic approach of explicitly passing `--no-color` to all relevant `stash` subprocesses.

Key technical changes:
- Adds `--no-color` to all `diff-tree` and `diff-index` invocations in `builtin/stash.c`
- Expands test coverage in `t/t3904-stash-patch.sh` with two new tests that verify the fix works for both partial stashes (`-p`) and staged changes, even when `GIT_PAGER_IN_USE` and `TERM` are set for color output

The patch builds on prior work (1c6ffb546b) that fixed a similar issue in `add-interactive`, and addresses Patrick Steinhardt's feedback from v1 by expanding coverage to include both `diff-tree` and `diff-index` cases. The solution is backward-compatible and low-risk, deferring the larger question of plumbing command color defaults to future work.
