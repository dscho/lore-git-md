Bugfix for case-insensitive filesystem reference conflicts in the files backend. This is the first of four patches addressing issues with batched reference updates on case-insensitive filesystems that were introduced in Git 2.51.

The patch modifies the files backend to properly handle case conflicts (like refs/heads/Foo vs refs/heads/foo) by introducing a new REF_TRANSACTION_ERROR_CASE_CONFLICT error code. When such conflicts occur during batched updates (used by git fetch, receive-pack, and update-ref --batch-updates), the conflicting reference will be rejected while allowing non-conflicting updates to proceed. This is an improvement over both the pre-2.51 behavior (which silently overwrote references) and post-2.51 behavior (which failed the entire transaction).

The changes include:
- New case conflict detection in lock_raw_ref()
- User-facing warnings recommending migration to the reftable backend
- Test cases verifying the behavior on both case-insensitive and reftable-backed repositories

The patch appears well-constructed with thorough test coverage and clear commit message explaining both the problem and solution. It addresses a real pain point for users on case-insensitive filesystems while maintaining backward compatibility. The recommendation to use reftable as a long-term solution is a pragmatic approach given the files backend's inherent limitations with case conflicts.
