This is part of the submodule gitdir path encoding series, specifically addressing Phillip Wood's question about version compatibility for the new `.git/submodules/` location.

Adrian Ratiu responds to Phillip Wood's concern about whether an `extensions.submoduleEncoding` config key is needed to prevent older Git versions from attempting to read repositories with the new path structure. While initially uncertain, Adrian concludes that adding such a version marker would be prudent to avoid potential issues when users switch between Git versions. The concern stems from older versions not being able to locate submodule gitdirs under the new `.git/submodules/` path, which could lead to inconsistent states.

The email confirms the series is otherwise production-ready, with v2 having incorporated various reviewer feedback. The core question about version compatibility remains the primary open issue before finalizing the series. Adrian indicates they will add the version marker in v3 unless better alternatives emerge.
