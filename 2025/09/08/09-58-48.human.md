This is a discussion about the removal of the `git-new-workdir` script from Git's contrib directory, part of Patrick Steinhardt's ongoing cleanup series. Gabriel Scherer reports that the script's removal (which happened in Git 2.51) affects their workflow, as they frequently need to check out the same branch in multiple worktrees - something that `git worktree` prevents by default.

Kristoffer Haugsbakk chimes in to note that `git worktree` does allow overriding this restriction with `--force`, though they acknowledge this has discoverability issues. The discussion highlights a tension between Git's safety mechanisms and real-world workflows, with Scherer preferring the old script's behavior of freely allowing same-branch checkouts across worktrees.

This exchange surfaces an important workflow consideration that wasn't fully addressed in the original removal decision. While the technical removal is complete, this suggests the need to either document the `--force` workaround more prominently or reconsider whether `git-new-workdir` should be retained as a convenience script for this specific use case. The thread shows how even well-intentioned cleanups can have unexpected impacts on users' established workflows.
