Feature patch adding deprecated command listing support, part of the alias shadowing series.

This first patch in the v3 series introduces a new `deprecated` category to `git --list-cmds`, allowing users and scripts to query which builtin commands are deprecated. The change marks `pack-redundant` and `whatchanged` as deprecated (following prior work) and extends the command listing infrastructure to support filtering by this new flag.

The implementation modifies `list_builtins()` to handle both include and exclude filtering, with the new `DEPRECATED` flag added to the command option bitfield. Documentation is updated to mention the new category alongside existing ones like `builtins` and `parseopt`. The author notes this is an experimental interface but argues it's better than requiring documentation scans.

This foundational change will be used in later patches to implement alias shadowing for deprecated commands. The patch appears well-structured with clear commit message and rationale, though the author raises an open question about whether `command-list.txt` should also be updated to reflect deprecations. The change maintains backward compatibility while enabling the series' broader goal of improving the deprecation workflow.
