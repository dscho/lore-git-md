This is patch 6/10 in a series implementing path encoding for submodule gitdirs to prevent filesystem conflicts. The patch focuses on the core encoding mechanism that transforms submodule names into safe filesystem paths.

The patch introduces URL-style path encoding (RFC 3986) with case encoding (A->_a, B->_b etc.) to handle case-insensitive filesystems and Windows reserved names. The main changes are:

1. Implements `strbuf_addstr_case_encode()` for case transformation alongside the existing URL encoding
2. Updates `submodule_name_to_gitdir()` to apply both encodings when constructing paths under `.git/submodules/`
3. Marks `validate_submodule_git_dir()` with a TODO noting it will need cleanup since encoded paths intentionally violate its current assumptions
4. Updates test expectations to match the new encoded paths (e.g. converting `/` to `%2f`)

The encoding follows a specific flow: first URL-encode the submodule name, then apply case-encoding to handle filesystem case sensitivity issues. Windows reserved names (like COM1) are noted as still problematic for workdirs despite the gitdir encoding.

Test changes show the new encoding in action, with paths like `hippo/hooks` becoming `hippo%2fhooks`. The patch also reorganizes some test assertions to verify the encoded paths rather than testing for nesting conflicts, since the encoding now prevents those conflicts by design.

This is a key technical patch in the series that implements the actual encoding mechanism while maintaining the series' goals of backward compatibility and cross-platform support. The implementation builds on Brandon Williams' original work but extends it with case encoding and integrates with the new config override system added earlier in the series.
