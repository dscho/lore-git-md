This is part 2/10 of a series introducing URL-style encoding for submodule gitdir paths to prevent filesystem conflicts. The patch focuses on changing the default location for new submodule gitdirs from `.git/modules/` to `.git/submodules/`, while maintaining backward compatibility with existing submodules.

The key changes in this patch:
- Creates a clear separation between legacy (unencoded) submodules in `.git/modules/` and new (encoded) ones in `.git/submodules/`
- Updates documentation across multiple files to reflect the new default path
- Modifies path handling in `submodule.c` to check both locations, preferring the new path but falling back to legacy
- Updates numerous test files to account for the new path structure

The patch is well-structured with thorough test coverage updates, though it's primarily preparatory work - the actual encoding logic comes in later patches. The commit message clearly explains the motivation for separating the paths (to avoid ambiguity with encoded names) and maintains backward compatibility. This appears to be a solid infrastructure change that enables the more complex encoding work to follow.
