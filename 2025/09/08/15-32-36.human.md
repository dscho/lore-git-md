This is a policy discussion in the ongoing Rust infrastructure thread, focusing on LTS (Long-Term Support) requirements for enterprise users, particularly around CVE backports and certification needs. Randall Becker from NonStop systems raises critical concerns about how security fixes will be handled for organizations that cannot immediately adopt Rust-based Git versions.

The email clarifies that enterprise users in regulated industries (finance, manufacturing, pharmaceuticals) require CVE fixes to come from official Git sources, not third parties, for audit compliance. Becker proposes maintaining an official C-only support branch within the main repository for post-Rust-deprecation security fixes, with occasional assistance from core maintainers. He notes this would require deeper involvement from his team to vet changes.

Key points:
- Current Git testing infrastructure is described as flaky, complicating backport validation
- NonStop users often build Git from source due to security policies
- Becker commits 10-20 hours/month to Git maintenance but warns this may become unsustainable without official LTS support
- While personally advocating for Rust adoption internally, he stresses enterprise timelines (6+ months) exceed proposed transition plans

The email represents a concrete counterproposal to Newren's LTS maintainer suggestion, focusing on technical implementation of security backports rather than governance models. It highlights the tension between architectural progress and real-world deployment constraints in high-compliance environments.
