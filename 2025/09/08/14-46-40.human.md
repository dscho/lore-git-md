This is a technical discussion in the ongoing debate about commit graph architecture in the pluggable ODB effort. Derrick Stolee responds to Patrick Steinhardt's position that commit graphs are storage-format-specific optimizations rather than fundamental repository concepts.

Stolee agrees in principle that alternative storage formats could exist, but argues that as long as commits maintain their current structure, the commit graph remains a valuable cache for speeding up commit operations. He shares insights from Azure DevOps' more efficient implementation that works directly with in-memory integer labels rather than full commit objects, suggesting this further demonstrates the graph's independence from the object store.

The email reinforces Stolee's view that commit graphs operate at a higher level than individual object sources, even if they're physically stored alongside objects. This continues the core architectural debate between repository-wide coherence (Stolee/Hamano) versus source-specific flexibility (Steinhardt), with Stolee providing concrete examples of how graphs can abstract above storage details while still delivering performance benefits.
