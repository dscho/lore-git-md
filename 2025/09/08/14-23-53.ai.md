This is a follow-up discussion on patch 3/9 in the submodule gitdir path encoding series, focusing on the config override mechanism. Phillip Wood asks whether later patches in the series set the `submodule.<name>.gitdirpath` config key when encoding gitdir paths, which would allow JGit to locate submodule directories by reading the config rather than needing to match Git's encoding scheme exactly.

The original patch (from Adrian Ratiu) introduced:
1. A new `submodule.<name>.gitdirpath` config option to override the default gitdir location
2. A `git submodule--helper gitdir` subcommand to querying paths
3. A test helper `verify_submodule_gitdir_path()` to validate paths in tests
4. Test cases verifying the config override behavior

Key technical details for future reference:
- The override is checked first in `submodule_name_to_gitdir()` before falling back to legacy or encoded paths
- The helper command provides a machine-readable way to query paths
- Tests verify the override works and can be unset
- The implementation maintains backward compatibility

The discussion clarifies the relationship between this config mechanism and the broader goal of making submodule paths work across implementations (like JGit) without requiring identical encoding schemes. This patch provides the plumbing while later patches implement the actual encoding.
