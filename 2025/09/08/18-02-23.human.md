This is a UX bug report about confusing prompt wording in `git restore -p`'s interactive hunk editing. Lino Haupt identifies an ambiguity in how the word "discard" is used differently between the normal operation prompt and the error prompt when a manually edited hunk fails to apply.

The core issue is that in the error case, "discard" refers to abandoning the edit attempt, while in the normal flow it refers to discarding the hunk itself from the worktree. This creates potential for user confusion, especially since both prompts appear in quick succession during interactive use. The bug affects both `git restore -p` and `git add -p`, though the ambiguity is more pronounced in `restore -p` where both prompts use "discard" terminology.

Haupt provides clear reproduction steps and three alternative wording proposals that would resolve the ambiguity by either explicitly stating what is being discarded (the edit rather than the hunk) or avoiding the word "discard" altogether in favor of "cancel". The suggestions are well-considered minimal changes that maintain consistency with Git's existing prompt style while eliminating the potential for misinterpretation.

This appears to be a legitimate usability issue that could trip up users, particularly those new to Git's interactive patch editing. The report is thorough and the proposed solutions seem reasonable starting points for discussion. The patch would be a small but meaningful quality-of-life improvement for interactive workflows.
