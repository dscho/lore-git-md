This is a policy discussion email in the ongoing Rust infrastructure thread, specifically addressing security backport concerns for the xdiff Rust port. Patrick Steinhardt responds to Elijah Newren's position on transition timelines and backport policies.

The exchange focuses on how to handle security fixes during the C-to-Rust transition period, particularly for distributions that may be stuck on older C-only versions for years. Steinhardt acknowledges Newren's point that backport decisions will always be case-by-case, but argues the project should establish some baseline guarantees about support for the last C-only release. He suggests a compromise where the project commits to maintaining the LTS version for a defined period before potentially handing off maintenance to the community.

A key tension emerges around whether "must ship latest Git" is a hard requirement for distributions. Steinhardt clarifies his concern isn't about new features (which he's fine developing in Rust immediately) but about security updates - if the only available non-Rust version becomes insecure, some distributions may be forced to drop Git entirely. The discussion also touches on whether existing optional Rust components (libgit-rs) provided sufficient notice of the transition, with Steinhardt conceding they had more uptake than he initially thought but maintaining they weren't an effective warning system.

This email advances the thread by moving from abstract transition concerns to concrete policy proposals, while revealing differing assumptions about what constitutes acceptable breakage for downstreams. The technical implementation remains stable, but the policy debate grows more nuanced around long-term support obligations.
