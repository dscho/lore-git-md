Bugfix targeting case-insensitive filesystem behavior in the files refs backend. This is the first patch in a 4-part series addressing batched reference update issues, specifically handling direct case collisions (foo vs Foo) that were introduced when reference updates switched to batched transactions in Git 2.51.

The patch modifies `lock_raw_ref()` to detect case conflicts during reference locking, returning a new `REF_TRANSACTION_ERROR_CASE_CONFLICT` error code instead of the generic error that would abort the entire transaction. This allows batched updates (used by `git fetch`, `git receive-pack`, and `git update-ref --batch-updates`) to reject conflicting updates while applying non-conflicting ones, improving on both the pre-2.51 behavior (silent overwrites) and post-2.51 behavior (complete failure).

Key changes include:
- New case-folding check in `duplicate_reference_case_cmp()`
- Modified error handling in `builtin/fetch.c` to show user-friendly warnings about case conflicts
- Test cases in t/t1400-update-ref.sh and t/t5510-fetch.sh verifying behavior on both files and reftable backends
- Documentation of the new error code in refs.h

The implementation maintains backward compatibility while providing better user feedback, recommending migration to reftable as a long-term solution. The patch builds on previous discussion about handling preexisting refs with case differences and addresses Patrick Steinhardt's optimization suggestions.
