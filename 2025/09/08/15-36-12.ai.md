Feature patch adding deprecated command listing capability to `git --list-cmds`, part of the broader alias shadowing for deprecated commands series.

This first patch in the v3 series introduces a new `DEPRECATED` flag for builtin commands and extends the experimental `--list-cmds` interface to include a `deprecated` category. The change allows users and scripts to programmatically identify deprecated commands, addressing the visibility gap noted in post-merge discussions of the `git whatchanged` deprecation. The implementation modifies `git.c` to add the flag and enhance `list_builtins()` with include/exclude filtering capabilities, while marking `pack-redundant` and `whatchanged` as deprecated in the commands array. Documentation is updated to reflect the new `deprecated` category in the man page.

Key technical details for future reference:
- New `DEPRECATED` bit (1<<6) in command flags
- Modified `list_builtins()` now takes both include/exclude parameters
- `git --list-cmds=deprecated` returns only deprecated builtins
- Initial deprecation markers on `pack-redundant` and `whatchanged`
- Maintains backward compatibility with existing `--list-cmds` usage
- Documentation update in git.adoc

The patch builds logically on the thread's progression from identifying the deprecation visibility problem to implementing programmatic access, while keeping the experimental nature of `--list-cmds` intact. It provides the foundation for subsequent patches to leverage this capability in the alias shadowing implementation. The author notes this was originally conceived as an independent change but now serves the series' goals, while raising an open question about potential `command-list.txt` updates.
