This is a bugfix patch in a series addressing batched reference updates on case-insensitive filesystems. It improves error handling when reference locks already exist during fetch operations.

The patch changes the files backend to return a more specific `REF_TRANSACTION_ERROR_CREATE_EXISTS` error (instead of the generic error) when encountering an existing lock file. This allows batched updates to fail just the conflicting reference while still processing other updates, rather than failing the entire transaction. The change is particularly relevant for case-insensitive filesystems where reference name conflicts are more likely.

The implementation modifies `lock_raw_ref()` in refs/files-backend.c to distinguish between case conflicts and simple lock existence. A new test case verifies the behavior by simulating a fetch operation where one reference is locked while others should still update successfully.

This is the second patch in a 4-part series that builds on previous work to properly handle reference conflicts. The change appears well-contained with clear test coverage, though it's worth noting this only addresses one aspect of the broader case-sensitivity issues being worked on in the series.
