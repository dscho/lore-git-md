This is a documentation patch announcing plans to make Rust a mandatory build dependency for Git, part of Patrick Steinhardt's ongoing RFC series introducing Rust infrastructure.

The patch adds a section to BreakingChanges.adoc detailing the planned timeline for Rust adoption, starting with Git 2.52 (where Rust support is optional) through to Git 3.0 (where it becomes mandatory). The transition is designed to give distributors time to prepare, with clear milestones and escape hatches at each stage. The document explains the current optional Rust usage (like the varint subsystem conversion from earlier in the series) is meant as a "test balloon" for this transition.

Key points in the announcement include:
- Rust will become mandatory in Git 3.0, estimated for second half of 2026
- Four-phase rollout with increasing requirements (2.52: initial support, 2.53: default-on with breaking changes, 2.54: default-on always, 3.0: mandatory)
- Git will provide a long-term support release before 3.0 for distributors needing extended transition time
- Build flags for both Meson and Makefile systems are documented

The patch appears well-considered, with clear technical writing and a responsible approach to a major ecosystem change. It builds on the concrete Rust infrastructure work demonstrated in earlier patches of the series while addressing the broader implications for Git's build requirements. The phased approach and LTS commitment show awareness of Git's role as critical infrastructure.
