This is the final version of a bugfix series addressing color handling inconsistencies in Git's interactive patch mode (`--patch`). The series has been updated based on Patrick Steinhardt's review feedback and is now ready for inclusion.

The patches fix several issues that arose from the 2021 Perl-to-C conversion, where color configuration settings (`color.diff` and `color.ui`) weren't being properly respected in interactive mode across commands like `stash`, `checkout`, `reset`, and `restore`. The key improvements in v2 include:

1. Expanded coverage of plumbing commands that need `--no-color` flags (now handling both `diff-tree` and `diff-index`)
2. Better test coverage including new cases for `GIT_PAGER_IN_USE` scenarios
3. Clarified commit message about config key pattern matching behavior
4. Minor code formatting fixes and test improvements

The series maintains its original structure:
- Patch 1 ensures plumbing commands don't produce color output when they shouldn't
- Patch 2 makes `add-interactive` respect `color.diff` settings
- Patch 3 implements proper fallback to `color.ui` when other color configs aren't set
- Patch 4 documents the `interactive.diffFilter` workaround in diff-highlight

The changes are well-tested and have been reviewed by both Patrick Steinhardt and Junio Hamano. The author (Jeff King) has addressed all feedback while deferring broader color system cleanups (like standardizing on `GIT_COLOR_UNKNOWN`) to future work. This appears to be a solid, focused fix for the immediate color handling issues.
