This is a policy clarification in the ongoing Rust infrastructure series, specifically addressing the BreakingChanges documentation patch (RFC v2 5/7). Patrick Steinhardt responds to Eli Schwartz's feedback about the proposed Rust transition LTS policy, clarifying the maintainership handoff process for the legacy C-only branch.

The key point resolves ambiguity around post-transition support: while the Git project would officially maintain the C-only LTS branch for ~2 years (8 release cycles), after that period responsibility would shift to remaining dependents - but crucially, the branch would still be hosted and reviewed through the official Git project infrastructure rather than fragmenting into external forks. This addresses Eli's concern about shadow maintenance while preserving the project's governance model.

Patrick acknowledges the need to reword the documentation to make this hosting commitment explicit. The exchange shows consensus building around a time-bound LTS approach (2 years) with an orderly transition to community-driven maintenance for any remaining users, all within the project's official channels. This refinement comes alongside ongoing technical discussions about build system implementation details in other parts of the series.
