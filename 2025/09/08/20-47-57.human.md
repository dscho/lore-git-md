Command deprecation infrastructure patch with feedback from maintainer.

This is part 3 of an 8-part series improving Git's deprecation system, specifically focusing on allowing aliases to shadow deprecated builtin commands. The patch introduces a new `is_deprecated_command()` helper that currently hardcodes the list of deprecated commands ("whatchanged" and "pack-redundant").

Maintainer Junio C Hamano notes a potential inconsistency - while the series introduces a `DEPRECATED` flag in the command structure, this helper function doesn't use that flag and instead maintains a separate hardcoded list. He suggests moving the function to git.c and having it consult the command array directly.

The patch appears technically sound but may need this architectural refinement before final approval. The series as a whole is maturing well, with all prior feedback addressed and comprehensive test coverage. This particular note from the maintainer suggests one final improvement to make the implementation more elegant and maintainable.
