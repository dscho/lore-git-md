This is part 2 of a 7-patch series extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series is now at v8 with all technical implementation complete, pending final terminology decisions.

The patch introduces server-side transmission of additional remote attributes through a new `promisor.sendFields` configuration variable. This allows servers to advertise more information about promisor remotes beyond just name and URL. Currently supported fields are `partialCloneFilter` (the remote's filter specification) and `token` (authentication credential), with strict validation to reject unknown fields.

Key technical changes:
- Adds `promisor.sendFields` config to specify which additional fields to transmit
- Introduces `known_fields` array to validate allowed field names
- Extends `struct promisor_info` to store filter and token values
- Modifies protocol documentation to describe new field transmission format
- Includes comprehensive tests verifying field transmission behavior

The implementation maintains backward compatibility while adding the new capability. Field names are case-sensitive in the protocol but case-insensitive in config lookups. Values are URL-encoded for transmission. The patch builds on the foundational `struct promisor_info` introduced in patch 1 of the series.

This is part of the ongoing effort to make promisor remotes more configurable and secure. The next patch in the series will implement client-side validation of these fields.
