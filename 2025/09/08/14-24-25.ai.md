This is a follow-up discussion in the submodule gitdir path encoding series, specifically addressing patch 2/9 which moves new submodule gitdirs from `.git/modules/` to `.git/submodules/`. Phillip Wood raises an important compatibility question about whether an `extensions.submoduleEncoding` config key is needed to prevent older Git versions from trying to read repositories with the new path structure.

The patch itself is a preparatory change that:
1. Creates a clear separation between legacy (plain) and new (encoded) submodule namespaces
2. Updates all documentation and test references from `.git/modules/` to `.git/submodules/`
3. Maintains backward compatibility by first checking the legacy path before falling back to the new path
4. Touches 24 files with path updates and test adjustments

Key technical points for future reference:
- The change affects `submodule_name_to_gitdir()` path resolution logic
- Both legacy and new paths are checked in `repo_has_absorbed_submodules()`
- Test updates verify the new path structure works across various submodule operations
- The thread context shows this is part of a larger effort to handle submodule name conflicts and cross-platform compatibility

Phillip's question about version compatibility suggests this change might need additional safeguards to prevent issues when repositories with the new path structure are accessed by older Git versions that only know about `.git/modules/`. This could become a point of discussion in the thread.
