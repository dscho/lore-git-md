This is part 3 of an 8-patch series extending Git's command deprecation system with alias shadowing support. The patch specifically allows users to create aliases that override deprecated builtin commands like `git whatchanged` and `git pack-redundant`.

The change addresses a usability issue where users couldn't create aliases for deprecated commands during the deprecation period. The patch modifies the alias handling in `git.c` to make an exception for deprecated commands, while maintaining the existing protection against shadowing non-deprecated commands. The implementation includes documentation updates and new tests verifying the behavior.

The technical approach adds a new `is_deprecated_command()` helper function and modifies `run_argv()` to check for aliases before processing deprecated commands. Test coverage in t0014-alias.sh verifies the new behavior works for all deprecated commands. The patch builds on Jeff King's earlier proposal and appears well-considered, with careful attention to backward compatibility and test coverage.

This is a focused change that solves a specific pain point in the deprecation workflow while maintaining Git's conservative approach to command behavior changes. The series as a whole is progressing toward addressing both interactive usage concerns and programmatic discovery needs around deprecated commands.
