This is a policy discussion email in the ongoing Rust infrastructure series, focusing on the transition timeline and Git 3.0 coordination. Patrick Steinhardt responds to Elijah Newren's critique of the proposed phased Rust adoption plan, defending the gradual approach while acknowledging flexibility around Git 3.0 timing.

The email clarifies Patrick's rationale for the current transition plan (auto-detection in 2.52, default-on in 2.53, mandatory in 3.0) as allowing infrastructure development while minimizing early adopter pain. He addresses concerns about the plan's effectiveness compared to existing Rust Git implementations, arguing that gradual exposure helps avoid training users to disable Rust due to initial issues. The discussion reveals differing philosophies: Elijah advocates immediate default-on in 2.52 for maximum visibility, while Patrick prefers controlled rollout.

Key technical points include the connection between Rust adoption and Git 3.0's breaking changes, with Patrick suggesting 2.55 as a potential 3.0 candidate if consensus forms. He acknowledges SHA-256 interop as the remaining blocker for 3.0 readiness. The email also references Junio Hamano's earlier position that 6 months is too short for mandatory Rust transition, putting the realistic timeline at ~1 year regardless of 3.0 coordination.

Policy considerations dominate, with Patrick maintaining that tying Rust adoption to 3.0 provides additional value through the proposed LTS release supporting both non-Rust platforms and other breaking changes. The exchange highlights ongoing tension between immediate visibility (Newren) and controlled transition (Steinhardt) approaches, with Git 3.0 feature readiness (particularly SHA-256) emerging as a key dependency for either timeline.
