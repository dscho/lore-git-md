Feature patch adding atomic ref updates to `git replay`. This is the first of two patches in a series introducing a new `--update-refs` option to `git replay` that performs reference updates directly using Git's ref transaction API, rather than outputting commands to be piped to `git update-ref`. The change provides atomic transaction behavior by default (all refs update or none do) with an optional `--batch` mode for partial updates.

The implementation is focused on server-side use cases (particularly Gitaly) where atomic operations are important, while maintaining compatibility with existing `git replay` options like `--onto`, `--advance`, and `--contained`. The patch includes extensive test coverage (nearly 600 lines across new test files) verifying the atomic behavior, error handling, and edge cases. The author notes this was motivated by discussions with Christian Couder about improving server-side workflows.

The code appears well-structured, following patterns from `builtin/update-ref.c` and maintaining the existing behavior where successful operations produce no output (matching `git update-ref --stdin`). The patch enforces mutual exclusion between the new `--update-refs` and the existing `--update` flag, and requires `--batch` to be used with `--update-refs`. This looks like a solid implementation of a clearly motivated feature, though as an RFC the author is likely open to feedback on the design choices.
