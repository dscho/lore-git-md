This is a thread closure note regarding clone connectivity issues. Ellie reports that the original problem (intermittent clone failures with HTTP/2 errors on GitHub) has been resolved as a GitHub server configuration issue. While the resolution came from GitHub's side, Ellie notes the general usefulness of resumable transfers for internet software and hopes this capability might be added to Git in the future.

The thread involved troubleshooting various network configurations (HTTP/1.1 fallback, firewall/proxy settings) to address clone failures that manifested with different error messages but similar symptoms. The discussion included input from multiple participants analyzing whether the root cause was client-side (network configuration) or server-side, with GitHub's fix confirming the latter. The email serves as a conclusion to the investigation while leaving open the broader feature request for transfer resumption.
