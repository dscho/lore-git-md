This is part 6 of a 7-patch series extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series is now at v8 with all technical implementation complete, pending final terminology decisions.

The patch introduces client-side validation of additional promisor-remote fields (partialCloneFilter and token) through a new `promisor.checkFields` configuration variable. When set, the client will verify that server-advertised field values match locally configured values before accepting a promisor remote. The validation happens in three cases: when the field is locally configured, when the server advertises it, and when the values match exactly (case-sensitive comparison).

Key technical changes include:
- New `fields_checked()` function to parse `promisor.checkFields` config
- `match_field_against_config()` helper for field-specific value comparison
- `all_fields_match()` function implementing the validation logic
- Updates to `should_accept_remote()` to incorporate field validation
- New test cases verifying the validation behavior
- Documentation explaining the configuration syntax and validation rules

The implementation builds on the series' earlier introduction of `struct promisor_info` and maintains consistency with the protocol's case sensitivity rules (case-sensitive for protocol, case-insensitive for config lookups). Test coverage verifies both successful validation and rejection cases.

This completes the bidirectional protocol extension, allowing both servers to advertise additional fields (via `promisor.sendFields` from earlier patches) and clients to validate them.
