Bugfix addressing color configuration fallback in interactive patch mode. This is the third patch in Jeff King's v2 series fixing color handling regressions in Git's interactive patch mode (`-p`) across multiple commands.

The patch specifically ensures that color settings in interactive mode properly fall back to `color.ui` when `color.diff` or `color.interactive` aren't set. The issue arose after the 2021 Perl-to-C conversion, where the fallback mechanism broke for commands like `checkout -p` that don't explicitly load color configuration. The fix centralizes the fallback logic in `add-interactive.c` rather than requiring each command to handle it, avoiding both code duplication and potential future regressions.

The solution adds explicit `color.ui` checking in the interactive setup code while maintaining Git's design principle of keeping plumbing commands unaware of porcelain configurations. New test cases verify the fallback behavior works across all interactive commands (`add`, `checkout`, `commit`, `reset`, `restore`, and `stash`).

This builds on the previous patches in the series that fixed color initialization and command-specific issues. The approach has been reviewed and approved by Junio C Hamano, with Patrick Steinhardt's feedback incorporated in v2. The patch demonstrates careful consideration of Git's configuration architecture while providing a robust solution to the reported regression.
