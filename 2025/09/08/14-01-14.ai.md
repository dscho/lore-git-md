This is a platform compatibility patch in the submodule gitdir path encoding series, specifically addressing filename length validation on systems with path length limits.

The patch introduces portable handling of NAME_MAX constraints when encoding submodule gitdir paths, with special attention to Windows compatibility. It adds a fallback pathconf() implementation for platforms that lack it (notably Windows), using NAME_MAX as the default limit. The core change in submodule.c now checks encoded path lengths against the system's NAME_MAX, erroring out if the encoded name would be too long.

Key technical details:
- New compat/pathconf.c provides a stub implementation for Windows (NO_PATHCONF)
- Windows/MINGW builds now define NO_PATHCONF in config.mak.uname
- Meson build system updated to check for pathconf()
- submodule.c's submodule_name_to_gitdir() now validates encoded path length against NAME_MAX
- Error message includes both the encoded name and length limits
- The patch leaves room for future enhancement (trimming/sharding) via a TODO comment

The implementation follows Jeff King's suggestion to error out rather than commit to a specific policy for handling long names, though the possibility of future configurable handling is noted. This maintains the series' cross-platform compatibility while adding safety checks for the encoded path scheme.
