The thread discusses a proposal to add WebDAV PROPFIND support to Git's dumb HTTP protocol, initiated by Milan Hauth who reported that WebDAV-enabled servers like nginx fail with "repository not found" errors during operations like `git ls-remote`. The current workaround requires manual `update-server-info` updates.

Junio C Hamano, the Git maintainer, has responded with a strong stance against the proposal, framing the current behavior as intentional design rather than a bug. He argues that dumb HTTP is meant to be a minimal protocol, and adding WebDAV support would compromise this simplicity. Hamano characterizes the manual `update-server-info` step as the expected workflow for dumb HTTP repositories, not a workaround needing elimination.

The discussion reveals a fundamental philosophical divide: while the original author sees WebDAV interoperability as a valuable improvement, the maintainer views it as contrary to dumb HTTP's purpose as a simple, low-overhead protocol. Hamano suggests using smarter protocols like SSH or smart HTTP when more sophisticated features are needed, rather than expanding dumb HTTP's capabilities. This appears to close the door on the feature proposal unless significant new arguments emerge.
