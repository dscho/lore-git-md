This thread discusses a proposal to enhance Git's HTTP protocol support to work with WebDAV-enabled servers like nginx. Milan Hauth reports that current Git clients fail with "repository not found" errors when accessing repositories hosted on WebDAV servers, requiring manual `update-server-info` as a workaround. The email demonstrates the issue with nginx configurations and curl commands, showing that WebDAV's PROPFIND method could provide the necessary directory listing capability that Git currently lacks in this context.

The proposal references prior discussions where WebDAV support was considered but rejected due to compatibility concerns. Hauth argues this should be reconsidered for better interoperability, particularly as many hosting solutions now use WebDAV-enabled HTTP servers. Implementing this would require modifying Git's HTTP transport code to handle WebDAV PROPFIND responses when available, while maintaining backward compatibility with existing dumb HTTP servers. The change could significantly improve the out-of-the-box experience for users accessing repositories on WebDAV-enabled infrastructure.
