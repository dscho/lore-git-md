Milan Hauth continues to add WebDAV PROPFIND support to Git's HTTP transport, proposing a detailed fallback strategy (GET, OPTIONS, PROPFIND) for repository discovery when interacting with WebDAV-enabled servers like nginx. This builds on their initial report that current behavior fails with "repository not found" errors unless manual `update-server-info` is run. 

Junio C Hamano maintains strong opposition, viewing this as unnecessary bloat for the intentionally minimal dumb HTTP protocol. While Milan's latest email provides concrete technical details about the fallback sequence and frames WebDAV support as an extension of dumb HTTP principles, the fundamental disagreement remains unresolved. The thread now presents two clear perspectives: Milan's push for better WebDAV interoperability versus Junio's commitment to protocol minimalism, with the maintainer's position carrying significant weight in Git's decision-making. 

The discussion has evolved from initial problem report to design philosophy clash, with Milan referencing related effort to modernize HTTP transport behavior more broadly. However, without new technical arguments to counter Junio's objections or additional community support for the feature, the proposal appears unlikely to progress in its current form.
