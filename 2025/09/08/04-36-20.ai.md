Documentation patch for the new `--update-refs` and `--batch` options in `git replay`. This is the second part of a two-patch series introducing atomic reference updates to `git replay`.

The patch thoroughly documents the new options and their interactions with existing functionality. Key additions include:
- Clear explanation of `--update-refs` using Git's ref transaction API for atomic updates (all succeed or none)
- Documentation of `--batch` mode for partial updates when used with `--update-refs`
- Clarification of output behavior differences between regular mode (piped to update-ref), `--update`, and `--update-refs`
- Multiple practical examples showing usage patterns for direct updates, atomic transactions, and batch mode
- The documentation maintains the experimental warning while clearly explaining the new behavior
- Output format details are updated to reflect all three modes of operation (default piping, direct updates, and transaction-based)
- Exit status behavior is implicitly documented through the descriptions of failure modes

The patch follows the implementation from the first patch, providing comprehensive user-facing documentation that matches the technical behavior. It maintains consistency with existing `git replay` documentation while extending it for the new features. The examples cover common use cases and demonstrate the progression from basic to advanced usage patterns.
