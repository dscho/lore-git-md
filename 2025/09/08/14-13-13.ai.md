This is a documentation patch proposing Rust as a mandatory build requirement, part of the ongoing Rust infrastructure series. The patch adds a formal announcement to BreakingChanges.adoc outlining the planned timeline for Rust adoption in Git, starting with optional support in 2.52 and culminating in mandatory requirements by Git 3.0 (estimated second half of next year).

The document details four key milestones: initial infrastructure setup (2.52), opt-in breaking changes (2.53), default-enabled Rust (2.54), and finally mandatory Rust (3.0). It includes build system flags (`WITH_RUST=YesPlease` for Makefile, `-Drust=enabled` for meson) and notes the final pre-3.0 release will be designated a long-term support version with extended maintenance.

This builds on the series' previous technical work (varint conversion, build system integration) by formalizing the transition plan. The announcement addresses ecosystem concerns by proposing a gradual rollout and LTS support for distributors needing more time to adapt. The patch maintains the series' careful approach while signaling the project's long-term direction regarding Rust adoption.
