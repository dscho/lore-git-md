This is a bugfix and platform compatibility patch in the submodule gitdir path encoding series. It addresses a potential issue where encoded submodule names could exceed filesystem filename length limits.

The patch adds portable handling for maximum filename length checks when creating encoded submodule gitdir paths. Since URL-encoding submodule names makes them longer, there's a small risk of hitting filesystem limits (typically 255 bytes). The solution:

1. Introduces a new `git_pathconf()` compatibility wrapper for platforms without `pathconf()` (notably Windows)
2. Adds build system support for the new compatibility code
3. Implements length checking in `submodule_name_to_gitdir()` that:
   - Uses `pathconf()` where available, falling back to `NAME_MAX`
   - Errors out if the encoded name would be too long
   - Leaves room for future improvements (trimming/sharding via config)

The patch follows Jeff King's suggestion to start with simple error handling rather than committing to a specific policy. It maintains the series' cross-platform focus with Windows-specific compatibility code. While the likelihood of hitting this limit is low, the check provides safety against filesystem errors that could occur with very long submodule names after encoding.

This is patch 7/10 in the v2 series, building on the core encoding mechanism introduced earlier. It's a focused addition that completes the platform compatibility story for the path encoding scheme.
