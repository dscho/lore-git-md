This is part 2/7 of a feature series extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series is now at v8 with all technical implementation complete, pending final terminology decisions.

This patch introduces server-side transmission of additional remote attributes beyond just name/URL. It adds a new `promisor.sendFields` config that lets servers specify which remote properties to advertise (currently supporting "partialCloneFilter" and "token"). The protocol documentation is updated to describe the new fields and their format.

The implementation:
- Defines allowed field names in a `known_fields` array
- Adds config parsing via `fields_from_config()`
- Extends `struct promisor_info` to store the new fields
- Modifies the advertisement format to include the additional fields
- Includes tests verifying field transmission

This is a well-structured patch that clearly builds on the foundational refactoring from patch 1. The documentation updates are thorough, and the test case demonstrates both the happy path and proper handling of unsupported fields. The changes are focused and maintain backward compatibility while enabling the new functionality.

The patch appears ready for inclusion, with the only outstanding question being whether to use "field" vs "configuration variable" terminology (a thread-wide discussion that doesn't affect the technical correctness here).
