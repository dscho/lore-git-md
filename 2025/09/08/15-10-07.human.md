This is a policy discussion in the ongoing Rust infrastructure thread, specifically addressing version support and CVE backporting concerns raised by enterprise users.

Ezekiel Newren responds to Randall Becker's concerns about NonStop platform users being unable to upgrade to Rust-enabled Git versions while still needing security fixes. While acknowledging the specific NonStop case, Newren questions why other platforms (Windows, Mac, Linux) would *require* the latest Git version in their package managers when most distributions already don't ship the latest version today.

The email highlights a key tension in the Rust transition debate: while NonStop has clear technical constraints preventing upgrades, Newren argues the broader "must upgrade" assumption for other platforms remains unsubstantiated. He notes that organizations needing latest versions can already build Git themselves, and questions why backporting security fixes to older versions (as proposed for NonStop) wouldn't suffice for other platforms during the Rust transition.

This continues the thread's central debate about balancing modernization against enterprise stability needs, with Newren pushing back on what he sees as overgeneralized claims about version requirements. The response maintains the technical/policy split seen throughout the thread - while Rust implementation details are stable, the discussion remains focused on support timelines and upgrade policies.
