This is a technical discussion about the limitations of Git's dumb HTTP protocol. Brian M. Carlson strongly opposes Jeff King's earlier suggestion that the protocol could be enhanced to scrape directory listings like httpdirfs does, arguing this would be unreliable and insecure. Carlson draws parallels to the painful experience of parsing FTP LIST output, noting HTTP directory listings would face similar problems with inconsistent formats, server quirks, and security risks from manual HTML parsing in C. They emphasize this approach has historically been problematic in other tools and would be a maintenance burden for Git's already poorly-maintained dumb HTTP code. The response reinforces the thread's consensus that dumb HTTP's current limitations (requiring pre-generated metadata) are intentional design constraints rather than oversights.
