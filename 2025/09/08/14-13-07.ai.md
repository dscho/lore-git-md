This is the third version of Patrick Steinhardt's RFC patch series introducing Rust infrastructure to Git core, now expanded to 8 patches with significant refinements from previous rounds. The series establishes Rust build infrastructure (meson and Makefile), implements a varint subsystem conversion proof-of-concept, documents the transition timeline, and enables CI testing.

Key technical changes in v3:
- Makefile improvements: Proper dependency tracking for Rust library builds, fixed variable ordering (WITH_RUST now after config.mak inclusion)
- Varint safety: Added overflow test and used `wrapping_add()` to match C behavior in all build modes
- CI fixes: Resolved AlmaLinux job dependencies, added Rust toolchain
- Policy refinements: Updated LTS documentation to clarify 2-year support window with maintenance handoff process
- Build system: Added fallback to use cargo directly when meson's Rust module is insufficient
- The series now explicitly targets Rust 2018 edition for broader compatibility

The varint conversion serves as infrastructure validation rather than a "test balloon", demonstrating C/Rust interop while being self-contained. The transition plan proposes:
1. Auto-detection in 2.52
2. Default-on with breaking changes in 2.53 
3. Full default enablement in 2.54
4. Mandatory in Git 3.0

Notable open issues:
- Makefile error handling still needs improvement (failure propagation, message ordering)
- macOS meson.build limitations remain due to upstream meson Rust module issues
- Windows support explicitly deferred to future work
- The series has evolved significantly from its initial "test balloon" framing to a more comprehensive infrastructure proposal, with Patrick now defending a phased transition approach against proposals for immediate default-on Rust enablement. Technical implementation appears solid with safety concerns addressed, though build system refinements remain. The policy discussion around transition timelines and LTS support continues to evolve in parallel threads.
