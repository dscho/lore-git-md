Response from Git maintainer Junio Hamano to WebDAV PROPFIND proposal. This is a rejection of the feature request, arguing that supporting WebDAV would undermine the fundamental purpose of Git's "dumb HTTP" protocol.

Hamano clarifies that the current behavior requiring manual `update-server-info` is not a workaround but the intended design. He emphasizes that dumb HTTP exists specifically to support the simplest possible HTTP servers, and adding WebDAV support would compromise this goal by making assumptions about server capabilities.

The response suggests this is a philosophical boundary - dumb HTTP is meant to be truly minimal, even at the cost of efficiency. Hamano implies that users needing more sophisticated HTTP interactions should use Git's smarter transport protocols instead. This appears to close the discussion unless new technical arguments emerge about why WebDAV support wouldn't violate the dumb HTTP design constraints.
