This is a test patch in the ongoing command deprecation framework series, specifically focusing on verifying alias shadowing behavior for both deprecated and regular builtins.

The patch adds comprehensive test coverage for the alias shadowing functionality introduced earlier in the series. It tests two key scenarios: that deprecated commands can be shadowed by aliases (as tested in the previous commit), and that regular builtins cannot be shadowed (the new test in this patch). The test samples several builtins (`grep`, `check-ref-format`, `interpret-trailers`, etc.) to verify the documented behavior that only deprecated commands allow alias shadowing.

The implementation uses a helper function `cannot_alias_regular_builtin` that checks each command's behavior with and without an alias, using `test_might_fail` to handle commands that may fail normally. The test is deliberately limited to a sample of builtins rather than all of them for performance reasons (a full test would add ~600ms to the test suite runtime).

This patch builds on the technical foundation established in earlier patches (particularly patch 3/8 which implemented the shadowing logic) and helps validate the documentation changes made to `git-config(1)` regarding alias behavior. The test coverage appears thorough while being pragmatic about runtime costs, and maintains the series' focus on both interactive usability and script safety.
