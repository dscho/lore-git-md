This is part of a 7-patch series extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series is now at v8 with all technical implementation complete, pending final terminology decisions.

Patch 4/7 refactors the parsing logic for advertised promisor remote fields into a new `parse_one_advertised_remote()` function that populates a `struct promisor_info`. This prepares for upcoming additions that will parse more fields (like filters and tokens) from the server. The changes make the code more maintainable by centralizing field parsing and memory management, while keeping the same.

Key changes include:
- Extracting field parsing into a dedicated function
- Simplifying memory management with a new `promisor_info_free()` helper
- Passing the full `promisor_info` struct rather than individual fields to `should_accept_remote()`
- Maintaining all existing functionality while making the code more extensible

The patch appears well-structured and focused, with clean separation of concerns. It builds on earlier foundational work in the series that introduced `struct promisor_info` and shows good test coverage. The changes align with the series' goal of making the promisor-remote protocol more flexible while maintaining security through configurable validation.
