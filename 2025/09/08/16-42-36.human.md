This is the second patch in a four-part bugfix series addressing color handling inconsistencies in Git's interactive patch mode (`--patch`). The patch focuses specifically on `add-interactive` (used by `git add -p` and related commands) to properly respect `color.diff` settings, which was lost during the 2021 Perl-to-C conversion.

The key fix separates color handling for prompts (controlled by `color.interactive`) from diff output (controlled by `color.diff`), maintaining historical behavior. Previously, the C version would only check `color.ui`, ignoring explicit `color.diff=false` settings. The patch introduces separate color state tracking and initialization for these two purposes, including distinct reset colors.

Two new tests verify the behavior: one shows colored prompts with disabled diff colors, while another demonstrates diff coloring (including custom fragment colors) with disabled prompt colors. The implementation carefully preserves all existing color slot handling while adding the missing `color.diff` support.

This is a well-motivated fix that restores expected behavior while maintaining clean separation between interactive UI colors and diff output colors. The patch includes thorough test coverage and maintains all existing functionality, making it a low-risk improvement to color handling.
