Feature proposal for HTTP protocol to support WebDAV PROPFIND. Milan Hauth reports Git's dumb HTTP protocol fails with WebDAV-enabled servers like nginx, causing `git ls-remote` to fail with "repository not found" errors. Current workaround requires manual `update-server-info`.

Junio C Hamano opposes adding WebDAV support, arguing dumb HTTP is intentionally minimal and `update-server-info` is the expected workflow, not a workaround. He maintains that adding PROPFIND support would bloat the intentionally simple protocol, contrasting it with smarter SSH/smart HTTP alternatives. The response frames this as a design philosophy disagreement rather than technical debate.

Key technical details: failure occurs when accessing WebDAV-hosted repos due to missing PROPFIND support in HTTP transport. Original proposal included nginx WebDAV config and curl examples showing directory listing capability. Hamano's response doesn't engage with PROPFIND implementation specifics but rejects the premise based on protocol design constraints.

Open questions remain about whether to proceed given maintainer opposition, though Hamano's position suggests this would require strong technical justification to reconsider. The thread now presents two perspectives: interoperability improvement versus protocol purity, with the maintainer favoring the latter.
