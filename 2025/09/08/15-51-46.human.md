This is a discussion about path length validation in the submodule gitdir path encoding series. Jeff King (peff@peff.net) responds to Adrian Ratiu's patch that adds error handling for overly long submodule names after URL encoding, which increases their length.

Jeff acknowledges the proposed solution using pathconf() is reasonable but suggests simpler alternatives: either letting the filesystem operations fail naturally when hitting limits, or using a fixed conservative length limit (like 255 chars) for consistency across platforms. He notes Git has historically taken the first approach for similar issues.

The exchange highlights a design tradeoff in the series - while the current patch proactively checks path length limits, Jeff's comments suggest the simpler "try and fail" approach might be sufficient given Git's historical practices. This doesn't appear to block the series, but offers food for thought about implementation simplicity versus explicit validation.

The discussion remains constructive, with Jeff explicitly noting his limited context on the topic and leaving the final decision to the patch author. This appears to be a minor implementation detail in an otherwise well-vetted series that's nearing completion.
