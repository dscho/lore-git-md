This is a platform compatibility discussion regarding NonStop x86 builds, specifically addressing test infrastructure issues with `uintptr_t` usage in the clang test framework.

Jeff King responds to Randall Becker's report about build failures on NonStop x86 systems due to recent test additions using `uintptr_t`. He notes that while Git's main codebase handles `uintptr_t` portably through `compat/posix.h`, the clang test framework (clar) has its own compatibility layer that needs similar treatment. The immediate issue involves both `uintptr_t` and the `PRIxPTR` format specifier which may not be universally available.

King proposes a concrete solution: replacing the problematic `uintptr_t`/`PRIxPTR` combination with `uintmax_t`/`PRIuMAX` in clar.c's assertion formatting code. This mirrors Git's own approach of using more widely available types when possible. The suggested change would modify pointer comparison output formatting while maintaining the same functionality.

The discussion highlights an ongoing tension between test modernization (using standard types) and platform compatibility, particularly for less common architectures like NonStop. King's response suggests this might be resolvable with targeted test infrastructure changes rather than requiring broader compiler flag workarounds. The proposed diff is minimal and focused specifically on the test framework's output formatting, leaving Git's core pointer handling unchanged.
