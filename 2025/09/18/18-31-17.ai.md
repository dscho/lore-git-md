This is a review response in the ongoing command deprecation framework series, specifically addressing build system concerns around the `git-whatchanged` removal.

Jeff King (peff@peff.net) acknowledges Kristoffer Haugsbakk's incorporation of his suggested fixes in v6, particularly regarding the `git-whatchanged` binary handling when built with `WITH_BREAKING_CHANGES`. While approving the current approach, he raises a subtle build system concern about potential test suite confusion from leftover `git-whatchanged` binaries when switching between builds with and without the breaking changes flag.

The key technical point is that while the current solution works, there remains a minor edge case where the test suite might interact with stale binaries. Peff notes this could become more visible when the breaking change becomes default, though the `.gitignore` entry removal at that point would help `git clean` handle it. He concludes the current solution is acceptable, with the option to revisit if the issue becomes problematic in practice.

This email doesn't propose code changes but flags a build system consideration that might need attention in the deprecation timeline. The discussion remains focused on the technical implementation details rather than the higher-level deprecation strategy, which appears settled from previous rounds.
