This is the first patch in a 9-part series implementing a new ref optimization API, part of the ongoing effort to modernize Git's reference storage backend architecture. The series builds on previous discussions that established the architectural framework under Junio Hamano's guidance.

The patch introduces a new `refs_optimize()` API function that provides a generic interface for reference storage optimization, dispatching to backend-specific implementations via a new vtable method. The files backend will use this for packing refs (maintaining current behavior), while the reftable backend will use it for compaction. The implementation is clean and straightforward, adding the new function alongside the existing `refs_pack_refs()` while maintaining the same options structure.

This foundational change enables the subsequent patches in the series to implement the backend-specific behaviors while providing a unified interface.
