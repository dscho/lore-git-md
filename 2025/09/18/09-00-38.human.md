Bugfix addressing `commit.cleanup` behavior during interactive rebase with fixup commits. This is the first patch in a two-part series from Phillip Wood, building on previous work to fix autosquash behavior.

The patch corrects an inconsistency where fixup commits in an interactive rebase weren't respecting the user's `commit.cleanup` configuration. The issue stems from a 2021 change that incorrectly used VERBATIM_MSG flag for final fixup commits, overriding the user's cleanup preferences. The fix removes this flag, making fixup commits behave consistently with regular pick commands regarding message cleanup.

The change is well-motivated with clear references to prior bug reports and commits. Phillip provides thorough test coverage showing both the old incorrect behavior and new correct behavior with different `commit.cleanup` settings. The test uses a prepare-commit-msg hook to verify comment handling, demonstrating real-world impact.

This appears to be a straightforward and well-tested fix for a specific edge case in rebase behavior. The patch maintains backward compatibility while fixing the inconsistency, and the commit message provides excellent context about why the original behavior was problematic.
