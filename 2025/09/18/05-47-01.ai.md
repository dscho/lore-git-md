Documentation patch in the ref optimization series. This is part 6 of 9 in Meet Soni's GSoC implementation series to introduce `git refs optimize` as a modern replacement for `git pack-refs`.

The patch factors out the common options documentation from `git-pack-refs.adoc` into a new shared file `pack-refs-options.adoc`, using AsciiDoc's include mechanism. This prepares for reuse by the upcoming `git refs optimize` command documentation while maintaining identical rendered output for `git pack-refs`. The extracted options include `--all`, `--no-prune`, `--auto`, `--include`, and `--exclude` with their detailed behaviors for both files and reftable backends.

This is a straightforward documentation refactoring that follows the architectural pattern established earlier in the series of extracting shared components. The change is mechanical - the content remains identical, just relocated to enable sharing. The patch maintains the same option descriptions including backend-specific behaviors and pattern matching rules.

The documentation restructuring aligns with the code refactoring done in previous patches that moved the core packing logic into a shared library. This continues the series' pattern of careful preparation for the new subcommand while maintaining backward compatibility. The next patches will presumably introduce the actual `git refs optimize` documentation and complete the user-facing side of the feature.
