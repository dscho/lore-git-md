This is a refactoring patch that's part of the ongoing effort to make reference optimization backend-agnostic. It converts the `git pack-refs` command to use the new `refs_optimize()` API instead of the files-backend-specific `refs_pack_refs()` function.

The change is minimal (just one line) but significant - it makes `git pack-refs` work with any reference backend that implements the optimization API, rather than being limited to the files backend. Currently this means it will work with both files and reftable backends, with each handling the optimization appropriately (packing for files, compaction for reftable).

The patch maintains all existing functionality including command-line option handling, just changing the underlying implementation. This is part of a larger 9-patch series (this is patch 4) that's systematically building out the reference optimization infrastructure, as documented in the thread summary. The change appears straightforward and well-motivated, following the architectural direction established earlier in the thread.
