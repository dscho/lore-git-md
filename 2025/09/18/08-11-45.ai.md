This is part of the reftable fsck validation series, specifically addressing sequential update index validation in reftable stacks. Patch 4/8 adds runtime checking to ensure tables loaded into a reftable stack have sequential update indices, where each table's min_update_index should be exactly one greater than the previous table's max_update_index.

The implementation modifies `reftable_stack_reload_once()` to track the previous table and validate this sequencing, returning REFTABLE_FORMAT_ERROR if violated. A new unit test `test_reftable_stack__non_seq_update_indices()` demonstrates the check by attempting to add two refs with non-sequential indices (1 and 3), which fails as expected. The change follows the series' architectural approach of moving validation from fsck to runtime while maintaining reftable library boundaries.

This patch builds on prior feedback to handle validation cases that could lead to stack corruption, with careful error handling distinguishing format issues from other failures. The test uses the standard reftable test infrastructure to verify both the new validation and that correct sequences still work. As with other patches in the series, this maintains separation between reftable internals and Git's fsck system while closing a specific validation gap in the stack loading process.
