This is a bugfix discussion for `git check-ignore`'s exit code behavior with negative patterns. Jeff King confirms David Goldstein's bug report about incorrect exit codes when using the `-v` flag with negative ignore rules, reproducing it in the latest Git version. 

The technical analysis identifies the root cause in `builtin/check-ignore.c`: the code counts a file as ignored if any pattern matches, but fails to exclude negative patterns from this count in verbose mode (where it needs to show the matching pattern). Jeff provides a simple patch that would fix the behavior by adding a check for `PATTERN_FLAG_NEGATIVE` when incrementing the ignored count.

An open question is whether the current behavior might be intentionally useful - Jeff speculates the exit code could indicate "any output shown" rather than "file ignored" in verbose mode, though he notes no personal experience relying on this behavior. The discussion now hinges on whether to treat this as a bug (aligning behavior with documentation) or consider if the current behavior serves an undocumented but useful purpose. The patch is straightforward but the decision requires input from those who might depend on the current exit code semantics.
