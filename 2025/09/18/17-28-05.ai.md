Bugfix for `git check-ignore` exit code behavior with negative patterns.

This patch identifies and documents a clear bug in `git check-ignore` where the `-v` flag causes incorrect exit codes when only a negative pattern matches. The core issue is that with `- v`, the command returns exit code 0 (indicating a file is ignored) when a negative pattern matches, even though the file is not actually ignored. Without `-v`, the exit code correctly returns 1 in this case. The behavior contradicts the documented specification that exit code 0 should only indicate an ignored file.

The bug appears to be long-standing, present in multiple Git versions, though the reporter hasn't verified against the very latest development version. A self-contained reproduction case is provided in a linked GitHub repository, showing the discrepancy between documented and actual behavior. The test case involves both tracked and untracked files matching negative patterns in `.gitignore`.

The patch appears well-motivated and clearly demonstrates a deviation from documented behavior. The bug affects the core functionality of `git check-ignore`'s exit code reporting, which could impact scripts relying on this behavior. The reproduction case provides a solid foundation for testing any proposed fix. This seems like a straightforward bug that should be addressed, though the actual fix would need to maintain consistency between the exit codes with/without `-v` while respecting negative ignore patterns.
