This is a technical discussion about the behavior of `git fetch --dry-run` with partial clones, specifically regarding object storage and quarantine mechanisms. The thread has evolved from a bug report about unexpected config modifications to a deeper exploration of implementation tradeoffs.

Junio C Hamano responds to Jeff King's suggestion about using tmp-objdir for true dry-run behavior in `git fetch --dry-run`. The key technical points are: 1) The quarantine mechanism (tmp-objdir) didn't exist when dry-run was originally implemented, 2) Junio questions whether true dryness is actually better since the current behavior of storing healthy objects between dry-run and real fetch can provide performance benefits, and 3) The stored objects help subsequent fetches by allowing Git to skip re-downloading already-verified objects.

The discussion highlights an important implementation tradeoff between purity (true dry-run behavior) and practical performance optimization. Junio's position suggests that the current behavior, while not strictly "dry", may be preferable due to its performance characteristics when dry-run and real fetches are run consecutively. This adds another dimension to the ongoing discussion about how to handle commit existence checking in partial clones while maintaining both correctness and efficiency.
