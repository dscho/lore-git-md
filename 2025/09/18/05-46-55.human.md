This is a feature implementation following Junio Hamano's architectural guidance for ref optimization. Meet Soni presents v3 of the `git refs optimize` series, which now properly implements a backend-agnostic approach to replace `git pack-refs`.

The series has been completely reworked from v2 to:
1. Introduce a new `refs_optimize()` API in the refs backend interface
2. Provide implementations for both files and reftable backends
3. Convert `pack-refs` to use the new API
4. Factor out common test infrastructure
5. Add comprehensive tests for the new subcommand

The implementation looks thorough, with 9 patches covering API design, backend implementations, documentation, and testing. The test coverage is particularly notable, with over 400 lines of shared test infrastructure and new tests specifically for the optimize subcommand. The documentation work factors out common options into a shared file, following earlier feedback.

This appears to be a well-executed response to the architectural direction set in the thread, moving the optimization functionality into the refs backend interface while maintaining the existing `pack-refs` behavior. The series seems ready for review, with the main outstanding question being whether any further adjustments are needed to the backend-specific optimization behaviors.
