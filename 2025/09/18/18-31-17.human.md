This is a review response in the ongoing command deprecation framework series, specifically addressing build system concerns around the `git-whatchanged` removal.

Jeff King (Peff) acknowledges Kristoffer Haugsbakk's v6 changes that incorporate his earlier suggestions, particularly around removing `git-whatchanged` from the builtins list when `WITH_BREAKING_CHANGES` is set. While generally approving the changes, Peff raises a subtle but important concern about potential test suite confusion from leftover `git-whatchanged` binaries when switching between configurations.

The note highlights a real but likely manageable issue - the build system won't automatically clean up old binaries when toggling the breaking changes flag, which could cause intermittent test failures. Peff pragmatically suggests accepting this known limitation for now, as the problem would be no harder to fix later if it becomes more troublesome. This reflects the series' maturity - minor edge cases remain, but the core functionality appears solid and ready for integration.
