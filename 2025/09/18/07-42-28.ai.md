Julien Jerphanion's latest response clarifies that in their workflow, `upstream` refers to the official repository, but they don't typically set local branches to track remote branches there. The technical implementation remains unchanged from the initial patch - a one-line addition to `builtin/pull.c` to add the `-u` option mapping. The discussion has shifted from technical feasibility to workflow justification, with the maintainer specifically questioning how frequently users actually need to change upstreams in fork-based workflows like conda-forge.
