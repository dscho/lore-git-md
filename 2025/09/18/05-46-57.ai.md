Files backend implementation for the ref optimization series.

This patch provides the files-backend implementation for the new `refs_optimize()` API introduced in the previous patch of the series. It completes the first concrete backend implementation for the ref optimization functionality, making the new API operational for files-based repositories.

The implementation is straightforward - it simply calls the existing `files_pack_refs()` function since packing is the optimization mechanism for the files backend. The patch adds a new `files_optimize()` function and wires it into the files backend's virtual table. This maintains the architectural separation while reusing existing functionality.

The commit message clearly explains the relationship between the new optimization operation and the existing packing operation for this backend. This matches the thread's established pattern of introducing new functionality while preserving backward compatibility. The implementation appears clean and minimal, focused on wiring up the new API without introducing behavior changes at this stage.

Key technical details:
- Adds `files_optimize()` function in refs/files-backend.c
- Wires to `optimize` slot in `refs_be_files` virtual table
- Reuses existing `files_pack_refs()` implementation
- Maintains all current packing behavior
- Follows the established pattern from the architectural discussion
