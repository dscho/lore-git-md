This is a platform compatibility discussion about test output formatting for pointer comparisons in the clar test framework.

Junio Hamano responds to Patrick Steinhardt's discovery that the proposed `uintmax_t` solution for NonStop compatibility fails on 32-bit systems. He agrees with Patrick's suggestion to use the `%p` format specifier instead, accepting platform-dependent output formatting. Junio notes this is acceptable since the pointer comparison output is only used for test failure diagnostics, not for test logic itself.

The key tradeoff is between cross-platform consistency (lost with `%p`) and universal compatibility (gained with `%p`). Junio suggests that even with varying output formats, the test could still verify basic functionality by checking for any output at all when pointers differ. This would allow keeping the test while accepting different output formats across platforms.

The discussion shows the project prioritizing broad compatibility over perfect test output consistency, a pragmatic approach given this is diagnostic output rather than core test logic. The solution appears headed toward adoption unless other maintainers raise objections about the loss of output format consistency.
