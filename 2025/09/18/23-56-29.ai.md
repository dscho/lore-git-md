This is the final patch (10/10) in the v2 series of xdiff refactoring cleanups preparing for potential Rust integration. The patch introduces enum-style macros (NO, YES, MAYBE) to clarify the meaning of `xdfile_t.rchg` values throughout the xdiff codebase, replacing magic numbers 0, 1, and 2. The change is purely semantic - the commit message carefully explains that while some conditionals now explicitly check for YES, this doesn't affect behavior since MAYBE is only used in temporary arrays during diff processing and never persists in rchg itself.

The patch touches multiple xdiff algorithm implementations (myers, histogram, patience) and the core preparation code, standardizing how changed line markers are checked. The author notes the variable name 'rchg' could potentially be renamed to 'changed' for clarity, but leaves that as a future consideration. This change follows the series' pattern of improving code readability and maintainability without altering diff output or performance characteristics.

Key technical details:
- Adds NO/YES/MAYBE macros in xdiff/xdiff.h
- Updates all xdiff algorithms to use these macros when checking rchg values
- Documents MAYBE state as unused in final rchg array
- Maintains identical behavior since MAYBE is only used internally during diff calculation
- Includes "Best-viewed-with" trailer for reviewing the changes
- Completes the preparatory cleanups before Rust-specific changes

This patch concludes the non-Rust-specific portion of the xdiff refactoring series, which is now ready for merging to 'next' while the Rust-specific changes continue in a separate discussion.
