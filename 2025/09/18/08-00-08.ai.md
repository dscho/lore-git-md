Bugfix for the new `git last-modified` command addressing a BUG() when processing criss-cross merges. This is the third iteration of the fix, now taking a more conservative approach than previous versions.

The core issue stems from `diff_tree_combined()` unconditionally setting `diffopt.flags.recursive=1` since 2006, which conflicts with `last-modified`'s path tracking when run in non-recursive mode (the default). The new solution introduces a `no_recursive_diff_tree_combined` flag to suppress this behavior selectively rather than changing the default, maintaining backward compatibility for other callers like `diff-tree -c`.

Key technical changes:
- Adds new `no_recursive_diff_tree_combined` flag to `struct diff_flags`
- Sets this flag in `builtin/last-modified.c` initialization
- Modifies `combine-diff.c` to respect the flag when setting recursive mode
- Includes a new test case specifically for criss-cross merge scenarios

The patch demonstrates careful consideration of the diff machinery's historical behavior while solving the immediate issue. The commit message provides clear reproduction steps showing the BUG() trigger and explains the technical interaction between the path tracking hashmap and recursive diff behavior. Test coverage appears thorough, with the new case specifically targeting the criss-cross merge scenario that exposed the bug.

This version addresses Patrick Steinhardt's concerns from previous iterations by avoiding broad behavioral changes to `diff_tree_combined()`. The solution is now more surgical, affecting only the `last-modified` command while preserving existing behavior for other callers. Performance improvements (~2x speedup) for non-recursive mode remain intact.
