This is the final patch in a completed 5-patch series fixing color handling in `git config get --type=color`. The series has already addressed several issues including test cleanup, color parsing fixes, and now this final change about pager behavior.

The patch specifically prevents the pager from being spawned when printing ANSI color escape sequences via `git config get --type=color`. The author argues this matches the behavior of the older `--get-color` syntax and is more useful for scripting purposes, as color codes are typically meant to be consumed directly by terminal output rather than viewed in a pager.

Junio Hamano raised a safety concern that direct terminal output could accidentally leave the terminal in a colored state if the user is interactively testing color codes. The author acknowledges this but notes the change maintains consistency with the historical `--get-color` behavior and that script usage (the primary use case) would need to handle color resets properly anyway.

Key technical details:
- Modifies pager handling in builtin/config.c to bypass the pager for `--type=color` output
- Follows same pattern as older `ACTION_GET_COLOR` behavior which also skipped the pager
- Maintains backward compatibility with existing scripts using color output
- Junio accepted the change despite the terminal safety trade-off
