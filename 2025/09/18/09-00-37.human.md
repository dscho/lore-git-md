This is a bugfix patch series addressing an issue with `git rebase --autosquash` behavior. Phillip Wood submits a two-patch set to fix a reported problem where fixup commits being squashed would incorrectly retain comments in the commit message, contrary to the `commit.cleanup` configuration.

The first patch makes `rebase -i` properly respect the `commit.cleanup` setting when processing fixup commits during an interactive rebase. The second patch follows up by removing now-unused code (the VERBATIM_MSG flag) that became obsolete after the first patch's changes.

The changes are focused and well-motivated by a user report (linked in the cover letter), with test updates included to verify the corrected behavior. The patch set appears to be a straightforward cleanup of a specific edge case in the rebase/autosquash workflow, building on existing configuration options rather than introducing new behavior.
