This is a cover letter for v3 of a reftable fsck validation series, now expanded to 8 patches. The series adds consistency checks for the reftable backend while maintaining separation between Git's fsck implementation and reftable internals.

The key architectural approach introduces a new 'reftable/fsck.[ch]' that implements validation logic while returning reftable-specific error codes, with Git's refs backend mapping these to fsck messages. This version moves two checks (trailing newlines in 'tables.list' and sequential update indices) from fsck to runtime validation per Junio Hamano's feedback, recognizing these as fundamental format requirements rather than advisory checks.

The series now includes preparatory cleanups (removing unused headers, moving a consistency message to generic code) and adds table name validation as a warning (since the reftable spec only suggests rather than enforces naming). The implementation carefully handles platform-specific behaviors and maintains the layered validation approach (Stack->Table->Block->Ref).

Notable changes from v2 include rebasing, modularizing the fsck code, making table name checks non-fatal, and splitting commits for easier review. The cover letter references ongoing discussions about concurrency handling and edge cases while showing responsiveness to prior feedback from Junio, Patrick Steinhardt, and Shejialuo. The changes touch core reftable files, fsck infrastructure, and add new tests while maintaining the reftable-as-library boundary.
