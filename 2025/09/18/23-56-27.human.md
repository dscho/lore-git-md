Performance optimization and refactoring in xdiff subsystem. This is patch 8/10 in a series preparing xdiff internals for potential Rust integration, focusing on removing the `chastore_t` arena allocator from `xdfile_t`.

The patch replaces the arena allocator with a simple contiguous array of `xrecord_t` structures, which provides a 5% performance improvement in the author's benchmarks. The change simplifies memory management while maintaining identical diff output. The commit explains this was likely an artifact from when `xrecord_t` was a linked list, and the arena is no longer needed now that records are stored contiguously.

The change touches multiple xdiff implementations (myers, histogram, patience diff algorithms) but is purely an internal optimization. The patch includes thorough performance measurements showing the impact of removing both the arena allocator and a redundant hash array (the latter was removed in a previous patch with a 5% performance cost).

This appears to be a well-justified cleanup that stands on its own merits regardless of the eventual Rust integration goal. The change is mechanical but wide-ranging, updating all the code that accessed records through the old arena-based interface. The performance impact is clearly documented and the commit message explains the historical context well.
