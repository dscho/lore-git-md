This is a refactoring patch in Karthik Nayak's reftable fsck validation series, addressing Junio Hamano's feedback about moving certain validation from fsck to runtime. The patch modifies the `parse_names()` function in the reftable library to properly detect and report missing trailing newlines in the 'tables.list' file, which contains the list of reftable files.

The changes include:
1. Adding error reporting to `parse_names()` via an `err` out-parameter
2. Updating callers to handle the new error reporting
3. Adding unit tests for the missing-newline case
4. Cleaning up existing tests to use the new error reporting

Junio notes the changes look sensible and only points out a minor whitespace issue that doesn't require a resend. This is a focused improvement that moves validation earlier in the process while maintaining the reftable library's error handling patterns. The patch demonstrates responsiveness to prior review feedback in this ongoing series to strengthen reftable validation.
