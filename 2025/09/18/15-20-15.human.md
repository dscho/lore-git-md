Platform compatibility confirmation for NonStop systems. Randall Becker reports that using `%p` for pointer formatting in the clar test framework works correctly on NonStop x86 systems, despite documentation warnings suggesting it might not. This confirms Junio Hamano's earlier suggestion to use `%p` as the solution for cross-platform pointer comparison output in test failures.

The email resolves one of the key open questions in the thread - whether NonStop systems would properly support the proposed `%p` approach. With this confirmation from the NonStop maintainer, the path forward is clearer: the team can proceed with using `%p` for pointer output in test failures, though they'll still need to decide whether to adjust expectations to check for output presence rather than exact format (as Junio suggested) or make other test adjustments.

This represents the third iteration of solutions for this platform compatibility issue, moving from `uintptr_t` (broken on NonStop) to `uintmax_t` (broken on 32-bit systems) to now `%p` (confirmed working everywhere). The solution maintains the test framework's ability to show pointer differences in failure cases while working across all supported platforms.
