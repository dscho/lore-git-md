This is a platform compatibility discussion regarding test framework pointer comparison output on NonStop and 32-bit systems.

The thread has progressed from an initial `uintptr_t`/`PRIxPTR` solution to `uintmax_t`/`PRIxMAX` (which failed on 32-bit systems) and now considers using the `%p` format specifier. Junio Hamano weighs in on Patrick Steinhardt's latest proposal, agreeing that `%p` seems appropriate if it works consistently across platforms, since the pointer comparison output is only used for test failure diagnostics.

Key technical points in this email: Junio suggests the test verification could be simplified to just checking for presence/absence of output rather than exact format matching, which would make the platform-dependent nature of `%p` output acceptable. This represents potential consensus forming around sacrificing cross-platform output consistency for broader compatibility.

The discussion remains open on whether this approach is sufficient or if the test case needs to be dropped entirely. The solution direction would affect how pointer comparison failures are reported in the clar test framework, with implications for test reliability across different architectures. NonStop maintainer input is still needed to confirm `%p` works on that platform.
