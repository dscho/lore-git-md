This is the final patch in a 5-part bugfix series addressing color handling in `git config get --type=color`. The patch specifically prevents the pager from being used when outputting ANSI color escape sequences, which completes the series' goal of making color handling consistent and reliable.

The change modifies `builtin/config.c` to skip pager setup when the output type is color, matching the behavior of the older `--get-color` syntax that this feature replaces. The patch includes a new test case in t1300-config.sh that verifies the pager is bypassed when outputting colors, even when core.pager is set. The test uses test-terminal.sh infrastructure to simulate a terminal environment.

The patch addresses two key issues: color codes being incorrectly sent to pagers (where they serve no purpose without accompanying text), and inconsistency with the older `--get-color` behavior which never used a pager. The solution follows the same pattern as the older implementation while maintaining the newer `--type=color` interface's documented behavior as a drop-in replacement.

Junio Hamano had previously acknowledged this architectural trade-off as necessary despite being suboptimal, since the primary use case for color output is direct terminal display. The patch completes the series' comprehensive handling of color-related behaviors while maintaining backward compatibility. All review feedback from previous iterations has been addressed, making this the final version ready for inclusion.
