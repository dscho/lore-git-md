Refactoring patch in the xdiff preparation series for Rust compatibility.

This is patch 3/10 in the second version of Ezekiel Newren's series to clean up xdiff internals ahead of potential Rust integration. The patch removes three unused fields from xdiff's core data structures: `xrecord_t.next`, `xdfile_t.hbits`, and `xdfile_t.rhash`. The changes are straightforward deletions of dead code that was being initialized but never actually used in the diff algorithm.

The modifications touch `xdiff/xprepare.c` and `xdiff/xtypes.h`, removing initialization code, cleanup code, and the structure definitions themselves. The `xdl_classify_record()` function signature is simplified since it no longer needs the hash-related parameters. The changes are purely internal cleanup with no behavior impact, continuing the series' theme of simplifying xdiff's implementation before any Rust-specific changes.

This patch follows the established pattern of the series by including a "Best-viewed-with" trailer to highlight the code motion. It builds on the preparatory work in patches 1-2 and will be followed by additional cleanups in the remaining patches. The changes are uncontroversial and align with the series' goal of removing unnecessary complexity from xdiff's implementation.
