This is a cover letter for a bugfix series addressing an issue with `git rebase --autosquash`. The two-patch series corrects behavior where fixup commit messages were not being properly cleaned up according to the `commit.cleanup` configuration during interactive rebase.

The first patch fixes the core issue where `commit.cleanup` settings were being ignored when processing fixup commits during rebase. The second patch follows up by removing now-unused code (the VERBATIM_MSG flag) that became obsolete after the first patch's changes. The bug was originally reported by Simon, with the series building on commit 92c87bdc40.

The changes primarily touch the sequencer.c file (removing flag handling code) and add test coverage in t/t3415-rebase-autosquash.sh. The test modifications show the before/after behavior, demonstrating that fixup commit messages now properly respect the cleanup configuration. This appears to be a straightforward quality-of-life fix for users of autosquash functionality, with this change will get consistent message cleanup behavior whether they're making normal commits or fixups during rebase.
