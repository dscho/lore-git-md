This is a bugfix patch in the reftable fsck validation series, specifically addressing validation of the 'tables.list' file format. The patch tightens parsing requirements by ensuring the file properly ends with a newline, which was previously not enforced.

The change modifies `parse_names()` in reftable/basics.c to return an error when encountering a missing trailing newline, adding proper error handling through a new `err` parameter. The implementation now distinguishes between memory allocation errors (REFTABLE_OUT_OF_MEMORY_ERROR) and format errors (REFTABLE_FORMAT_ERROR). Corresponding unit tests are added to verify both valid and invalid cases.

This appears to be a well-contained change that follows the series' architectural approach of moving validation checks from runtime to fsck time where appropriate. The patch maintains clean separation between the reftable library and Git's fsck infrastructure while improving format robustness. Test coverage is thorough, including cases for valid newline-terminated input, missing newlines, and empty strings.

The change was prompted by Junio Hamano's feedback in earlier versions of the series to move certain validations from runtime to fsck time. This particular check was previously missing entirely from both phases.
