This thread addresses a platform compatibility issue in Git's test framework, specifically the clar test framework's handling of pointer comparison output across different architectures. The problem first surfaced when NonStop x86 builds failed due to `uintptr_t` usage, then expanded to include 32-bit system limitations with `uintmax_t`.

After several iterations of proposed solutions, the current consensus is to use the `%p` format specifier for pointer formatting, as suggested by Junio Hamano. This approach was initially uncertain due to documentation warnings about NonStop's support for `%p`, but Randall Becker (the NonStop maintainer) has now confirmed it works correctly on NonStop systems. This validation removes the last major obstacle to adopting this solution.

The resolution involves implementing `%p` formatting in clar.c and adjusting test expectations to verify output presence rather than exact format matching. This maintains useful test diagnostics while working across all supported architectures, though it means accepting some platform-dependent output formatting. The thread demonstrates how architectural constraints can require multiple solution attempts before finding one that works universally, and may serve as a reference for similar platform-dependent test formatting issues in the future.
