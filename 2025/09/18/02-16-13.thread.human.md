This thread addresses a platform compatibility issue affecting NonStop x86 builds, where recent test additions using `uintptr_t` break CI builds. The problem stems from the clar test framework's pointer comparison output formatting, which assumes `uintptr_t` availability - an optional extension on NonStop systems.

Jeff King proposed replacing `uintptr_t`/`PRIxPTR` with the more portable `uintmax_t`/`PRIuMAX` in the test framework, mirroring Git's existing portable type handling. Randall Becker, the NonStop maintainer who initially reported the issue, has now confirmed this solution would work on NonStop systems. While Becker is currently testing a workaround using a compiler flag (`-D__NSK_OPTIONAL_TYPES__`), he acknowledges King's approach as a more permanent solution.

The discussion has narrowed to implementation details - whether to modify the code directly (King's preference) or handle the compatibility via build system configuration (Becker's suggestion). The technical viability of the type substitution is now confirmed, with the integration path being the remaining open question. This represents progress toward resolving the NonStop build issue while maintaining test framework functionality across all platforms.
