This is the first patch in a 9-part series implementing the ref optimization API, part of the ongoing effort to modernize Git's ref storage backend architecture. The patch introduces the core `refs_optimize()` function and vtable method that will serve as the unified interface for backend-specific optimization operations.

The implementation adds three key pieces:
1. A new `optimize_fn` typedef in refs-internal.h for backend implementations
2. The `refs_optimize()` wrapper in refs.c that dispatches to backends
3. Documentation in refs.h noting this is backend-specific (files backend will treat it as equivalent to packing)

The patch builds on prior thread discussion where Junio Hamano guided the architecture toward a backend-agnostic API. It maintains compatibility by keeping the existing `pack_refs_opts` struct rather than introducing new options, though the commit message notes backends may implement different behaviors (e.g., reftable compaction vs files packing).

This foundational change enables the series' subsequent patches that will:
- Implement backend-specific optimization (files/reftable)
- Add the new `git refs optimize` command
- Deprecate `git pack-refs` in favor of the more general interface

The implementation appears clean and focused, with clear documentation of the architectural intent. As the first in a series, it sets up the necessary plumbing without yet providing the complete functionality - subsequent patches will fill in the backend implementations and command-line interface.
