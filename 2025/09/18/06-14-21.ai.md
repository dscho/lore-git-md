This is a refactoring patch in the series fixing `git config get --type=color` functionality. It modifies the error handling behavior of the `get_color()` function in builtin/config.c to make it more flexible for future callers.

The patch changes `get_color()` from a function that dies on invalid color values to one that returns an error code. This prepares for a subsequent patch that will introduce another caller with its own error handling. The existing caller (`ACTION_GET_COLOR`) is updated to handle the new return value.

Key technical changes:
- Function signature changes from `void` to `int` return type
- Error cases now return `error()` instead of calling `die()`
- Caller in `cmd_config_actions()` now checks return value in `ACTION_GET_COLOR` case
- Maintains same output behavior (still prints parsed color via `fputs`)
- Error message text remains identical, just delivered via different mechanism

This is part of the systematic improvements to color handling in the config command, specifically addressing the architectural need for more flexible error handling. The change is straightforward and maintains all existing behavior while enabling future extensions. The patch follows the series' pattern of careful, incremental improvements with clear commit messages explaining the rationale.
