Bugfix for `git last-modified` addressing criss-cross merge handling. This is the third version of a patch that fixes a BUG() condition that occurs when processing certain merge scenarios, particularly criss-cross merges.

The issue stems from `diff_tree_combined()` forcibly setting recursive mode (a behavior dating back to 2006) which conflicts with `last-modified`'s path tracking mechanism. The v3 solution introduces a new flag `no_recursive_diff_tree_combined` to selectively disable this behavior rather than changing the default, maintaining backward compatibility for other callers like `diff-tree -c`.

The patch adds test coverage for the criss-cross merge case and includes performance improvements (previously measured at ~2x speedup for non-recursive mode). The discussion thread shows ongoing debate about the safety of this change, with Patrick Steinhardt wanting more evidence of impact on other callers while Toon Claes maintains this is a focused fix for a clear bug.

Key technical changes:
- New flag in `diff_flags` struct to control recursive behavior
- Modified `diff_tree_combined()` logic to respect the new flag
- Test case added in `t/t8020-last-modified.sh` for criss-cross merges

The patch appears well-constructed with clear commit message and test coverage, though the thread suggests some reviewers may still want broader analysis of impacts on other diff machinery users.
