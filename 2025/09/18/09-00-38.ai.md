This is a bugfix patch in a two-part series addressing `git rebase --autosquash` behavior regarding `commit.cleanup` configuration. The patch comes from Phillip Wood and builds on previous work in commit f7d42ceec52.

The core issue fixes a regression where fixup commits weren't respecting the user's `commit.cleanup` configuration during interactive rebase operations. The problem originated when VERBATIM_MSG flag was incorrectly used instead of simply removing the CLEANUP_MSG flag, causing fixup commits to behave differently from regular pick commands regarding message formatting.

Key technical changes:
- Removes the VERBATIM_MSG flag setting in sequencer.c when handling final fixup commits
- Replaces the existing test in t3415-rebase-autosquash.sh with a more comprehensive one that verifies both pick and fixup commands properly respect commit.cleanup
- The new test uses prepare-commit-msg hooks to verify message cleanup behavior with and without commit.cleanup=strip

The patch appears well-constructed with:
- Clear explanation of the problem and its history
- References to original bug reports
- Thorough test coverage showing both the fixed behavior and regression prevention
- Minimal code change focused on the specific issue

This addresses Simon Cheng's reported issue where prepare-commit-msg hook comments weren't being cleaned up during fixup commits when commit.cleanup was set. The change makes fixup behavior consistent with regular pick commands regarding message formatting.
