Bugfix for color handling in `git config get`. This is the fourth patch in a completed 5-patch series addressing issues with `git config get --type=color`.

The patch fixes a regression where `git config get --type=color --default="reset" ""` would fail with an error about an empty key section, despite being documented as the way to get color reset sequences. The regression was introduced in commit 4e51389000 when the new `get` subcommand was added, though the older `--get-color` syntax still worked.

The solution adds a special case in `builtin/config.c` to directly call the color parsing function when three conditions are met: (1) the config key is empty, (2) the type is color, and (3) a default value is provided. This matches the documented behavior and maintains compatibility with the older `--get-color` syntax. The patch includes tests verifying both the subcommand and legacy syntax produce identical output.

This is part of a comprehensive series that has gone through three iterations with all review feedback addressed. The series modernizes test formatting, improves error handling, and fixes several color-related issues in `git config`. Junio Hamano has already acknowledged the architectural trade-offs in this solution as necessary for maintaining backward compatibility.
