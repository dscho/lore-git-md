This is a bugfix and feature patch in Karthik Nayak's reftable fsck validation series (v3 8/8). It adds filesystem consistency checks for reftable backend by validating table names and file types in the reftable directory.

The patch introduces two new fsck checks:
1. Table name validation that warns about non-conformant names (following the pattern `${min}-${max}-${random}.ref`)
2. File type validation that errors on unexpected file types in the reftable directory

The implementation adds glue code in `refs/reftable-backend.c` to call reftable library checks and map reftable errors to Git's fsck error system. Two new fsck message IDs are added (`badReftableTableName` as a warning and `badReftableFiletype` as an error), with corresponding documentation updates.

The patch includes comprehensive tests in `t0614-reftable-fsck.sh` that verify both valid and invalid cases, showing the patch is well-tested. This continues the series' pattern of thorough validation while maintaining separation between Git's fsck and reftable internals.

As the final patch in the v3 series, this completes the core fsck validation infrastructure for reftable, addressing one of the last major gaps in reftable backend functionality. The implementation appears clean and follows the established patterns from earlier patches in the series.
