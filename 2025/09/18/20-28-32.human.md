This is a follow-up discussion in the command deprecation framework series, specifically addressing build system concerns. Kristoffer Haugsbakk responds to Jeff King's review of v6, which introduced changes to handle `git-whatchanged` when built with `WITH_BREAKING_CHANGES`.

The main topic is a lingering build system issue where leftover `git-whatchanged` binaries from previous builds can confuse the test suite when switching between builds with and without breaking changes. Jeff King acknowledges this as a potential future irritation but considers it manageable for the time being, suggesting the current approach (relying on `.gitignore` changes) is acceptable despite not being perfect.

Kristoffer agrees with the issue's complexity and shares his personal workflow of isolating such builds in separate worktrees where frequent cleaning isn't problematic. Both maintainers seem comfortable with the current solution while remaining open to addressing any problems that might emerge when the breaking changes become the default.

The exchange shows consensus on moving forward with the series as-is, treating the build edge case as a minor operational issue rather than a blocker. This maintains the series' momentum while acknowledging a technical debt item that may need revisiting later in the deprecation timeline.
