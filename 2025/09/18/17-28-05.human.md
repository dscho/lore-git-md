Bugfix for `git check-ignore` exit code behavior with negative patterns.

David Goldstein reports a long-standing bug in `git check-ignore` where the command returns the wrong exit code (0 instead of 1) when using the `-v` flag and a file matches only a negative pattern in `.gitignore`. The behavior is correct without `-v`, and incorrect with it. 

The issue affects whether Git considers a file to be ignored - negative patterns (those starting with `!`) should un-ignore files, but the exit code logic appears to be reversed when verbose output is requested. Goldstein provides a self-contained reproduction repository demonstrating the problem.

This appears to be a genuine bug that's been present across multiple Git versions. The patch doesn't propose a fix but thoroughly documents the incorrect behavior, making it a good starting point for someone to address the issue. The report is well-structured with clear reproduction steps, though it doesn't investigate whether the bug exists in the very latest development version of Git.
