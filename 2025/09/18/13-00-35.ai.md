This is a platform compatibility follow-up in the NonStop x86 build issue thread. Patrick Steinhardt reports a new technical complication with the proposed `uintmax_t` solution - it fails on 32-bit systems due to size mismatches when casting pointers. The thread had previously settled on replacing `uintptr_t`/`PRIxPTR` with `uintmax_t`/`PRIxMAX` in clar.c's assertion formatting, but this approach now appears unworkable for some architectures.

Steinhardt suggests falling back to using `%p` format specifier instead, which would mean accepting platform-dependent output formatting and potentially dropping the affected test case. This represents a significant shift from the prior consensus solution, as it trades consistent test output for broader compatibility. The change would affect pointer comparison failure messages in the clar test framework's output formatting.

The email continues the technical discussion between Patrick Steinhardt and Jeff King about implementation details for fixing the NonStop build issue. This new wrinkle about 32-bit compatibility wasn't previously discussed in the thread, and may require revisiting the earlier agreed-upon solution path. The proposed `%p` approach would simplify the code at the cost of test consistency across platforms.
