Thread summary:

Bug in `git check-ignore` exit code behavior when using `-v` flag with negative patterns. Core issue is that `-v` causes incorrect exit code 0 (indicating ignored file) when only a negative pattern matches, despite the file not actually being ignored. Without `-v`, the exit code correctly returns 1 in this case, contradicting documented behavior where exit code 0 should only indicate an ignored file.

Bug appears long-standing across multiple Git versions, with unverified status in latest development version. Reproduction case provided in linked repository, demonstrating discrepancy between documented and actual behavior for both tracked and untracked files matching negative patterns in `.gitignore`.

Impact affects scripts relying on `git check-ignore` exit codes for accurate ignored/not-ignored status determination. The bug report is well-motivated with clear demonstration of deviation from documentation. Next step would be technical analysis of the exit code logic in `check-ignore.c` to propose a fix that maintains consistency between `-v` and non-`-v` modes while properly handling negative patterns.
