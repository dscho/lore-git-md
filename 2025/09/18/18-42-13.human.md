This is a follow-up discussion in the completed series about switching Git's default branch name from "master" to "main" when built with WITH_BREAKING_CHANGES. The technical implementation has already been merged, and this final exchange addresses a test case detail.

Phillip Wood noticed that a test checking for advice messages about the default branch name was unnecessarily gated behind !WITH_BREAKING_CHANGES, since the advice messages should continue to appear regardless of the compilation setting. Junio Hamano agrees with this observation and acknowledges he was too quick to revert some test changes in the previous version.

The discussion is minor but shows careful review of test coverage for the new behavior. Both maintainers are aligned that the advice message should be tested in all configurations, not just the non-breaking-change case. This represents the final polish on a long-running effort to modernize Git's default branch naming.
