Bugfix discussion for `git check-ignore` exit code behavior with negative patterns. Jeff King confirms David Goldstein's reported bug where `git check-ignore -v` incorrectly returns exit code 0 (indicating an ignored file) when only a negative pattern matches, despite the file not actually being ignored. The bug has existed since the feature's introduction and persists in the latest Git version.

King provides a simple fix that modifies the pattern counting logic in `builtin/check-ignore.c` to exclude negative patterns from the ignored count, even in verbose mode. The proposed change would make the behavior consistent between `-v` and non-`-v` modes while maintaining the ability to show negative patterns in verbose output.

The email raises an interesting question about whether the current behavior might be intentionally useful - suggesting exit code 0 could mean "any output was shown" rather than "file is ignored." However, King notes this is speculative since he hasn't personally used the exit code functionality. The discussion leaves open whether to fix the behavior to match documentation or potentially update the documentation to match current behavior.
