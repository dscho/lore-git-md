Platform compatibility follow-up confirming `%p` solution works on NonStop systems.

Randall Becker reports that using `%p` for pointer formatting in the clar test framework works correctly on NonStop x86 systems, despite documentation warnings suggesting it might not. This confirms Junio Hamano's earlier suggestion to use `%p` as the solution for cross-platform pointer comparison output in test failures, addressing both the original NonStop `uintptr_t` issue and the subsequent 32-bit system limitations with `uintmax_t`.

The email resolves one of the key open questions in the thread by verifying that NonStop systems properly support the `%p` format specifier. This validation from the NonStop maintainer removes a major obstacle to adopting the `%p` approach, which had emerged as the leading solution after two previous attempts (`uintptr_t` and `uintmax_t`) failed on different platforms.

With this confirmation, the path forward appears to be: 1) implement `%p` formatting in clar.c for pointer comparison failures, and 2) adjust test expectations to verify output presence rather than exact format, as Junio suggested. The solution maintains useful test diagnostics while working across all supported architectures, though it does mean accepting platform-dependent output formatting.

This represents the third and likely final iteration of this platform compatibility fix, showing how architectural constraints can require multiple solution attempts before finding one that works universally. The case may serve as a reference for handling platform-dependent test formatting in Git's test infrastructure.
