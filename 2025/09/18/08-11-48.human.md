This is part 7 of a 9-patch series adding reftable consistency checks, focusing on the infrastructure for validating reftable files. The patch introduces a new `reftable/fsck.[ch]` module that provides validation logic while maintaining separation between Git's fsck and reftable internals.

The core addition is the `reftable_fsck_check()` function, which performs file-level validation on the reftable directory. It checks that all files have valid table names (following the expected hexadecimal index range format) and are regular files, reporting any issues through callback functions. The implementation carefully handles directory traversal and name validation while preserving the reftable library's independence from Git internals.

This patch builds on earlier work in the series that moved some validation from fsck to runtime checks. The validation here is thorough, with specific error codes for different failure modes (invalid file types vs malformed names). The changes include Makefile updates to properly order object files and add the new module to the build system.

The patch appears well-structured and focused, continuing the series' pattern of careful boundary maintenance between Git and the reftable library. It addresses a clear gap in the reftable backend's validation while following the architectural approach established in earlier patches.
