Bugfix/refactoring patch removing obsolete VERBATIM_MSG flag from sequencer.c, completing the fix for `git rebase --autosquash` cleanup behavior.

This is the second patch in Phillip Wood's series addressing inconsistent message formatting during interactive rebase with fixup commits. The first patch fixed the core issue by making fixup commits properly respect `commit.cleanup` configuration, rendering the VERBATIM_MSG flag unnecessary. This follow-up removes all remaining traces of that flag from sequencer.c.

The changes include:
- Complete removal of the VERBATIM_MSG flag definition and its BUG() check for mutual exclusivity with CLEANUP_MSG
- Removal of the flag's associated command-line argument handling in run_git_commit()
- Removal of the flag's cleanup mode selection logic in try_to_commit()
- Reverts remaining parts of commit f7d42ceec52 that weren't handled in the first patch

The removal is straightforward and low-risk since the flag was only used for fixup commits, which are now properly handled through the standard cleanup mechanism. The patch maintains all existing functionality while simplifying the codebase by removing now-dead code paths. This appears to be a clean-up operation following the substantive fix in patch 1, with no new test coverage needed since the behavioral changes were already verified in the first patch's tests.
