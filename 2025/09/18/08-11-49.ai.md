This is a bugfix and feature patch in Karthik Nayak's reftable fsck validation series (v3 8/8). It adds filesystem consistency checks for reftable backend by implementing glue code that maps reftable library's validation errors to Git's fsck infrastructure.

The patch introduces two new fsck checks:
1. Table name validation (treated as warning) - enforces the `${min}-${max}-${random}.ref` naming convention from reftable spec
2. File type validation (treated as error) - rejects unexpected file types in reftable directory

Key technical details:
- Adds `badReftableTableName` (WARN) and `badReftableFiletype` (ERROR) to `fsck-msgids.adoc` and `fsck.h`
- Implements error mapping via `fsck_msg_id_map[]` array in `refs/reftable-backend.c`
- Adds verbose output handler `reftable_fsck_verbose_handler`
- Includes comprehensive tests in new `t0614-reftable-fsck.sh` covering:
  - Various malformed table name patterns
  - Directory entries
  - Verifies warning vs error behavior

The implementation maintains separation between reftable internals and Git's reporting system while providing clear user feedback. This completes the core fsck functionality for reftable backend, building on prior patches that established the validation framework. The careful error classification (warning for non-conformant names vs error for invalid types) shows thoughtful consideration of real-world usage patterns.
