This is a feature patch introducing reftable consistency checks as part of Karthik Nayak's ongoing reftable fsck validation series (v3, patch 7/8). It adds infrastructure for validating reftable backend integrity while maintaining separation between Git's fsck and reftable internals.

The patch introduces two new files: `reftable/fsck.c` and `reftable/reftable-fsck.h`, which provide an entry point `reftable_fsck_check()` for running fsck checks on a reftable stack. The implementation validates that all files in the reftable directory have expected types (regular files) and proper naming patterns (hexadecimal min/max update indices with .ref/.log suffixes). Invalid cases trigger specific error codes (REFTABLE_FSCK_ERROR_INVALID_FILE_TYPE and REFTABLE_FSCK_ERROR_TABLE_NAME) reported through callback functions.

Key technical details include:
- The validation skips special files (".", "..") and "tables.list"
- Table name parsing uses strtoull() to verify hexadecimal update index ranges
- Error reporting uses a callback pattern to maintain library independence
- Makefile/meson.build updates add the new fsck component while maintaining lexicographic ordering

This builds on prior patches in the series by implementing the first concrete validation check while establishing the architectural pattern for future checks. The implementation follows the series' principle of keeping reftable-specific validation within the library while providing hooks for Git's fsck to consume the results. The patch appears well-structured with clear error handling and maintains the separation of concerns established in earlier versions of the series.
