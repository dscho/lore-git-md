This is a review response to a gitk UI improvement patch about remembering window geometry. Johannes Sixt provides testing feedback and suggestions for Michael Rappazzo's initial patch that aimed to make the "Tags and Heads" window position and size persistent across sessions.

The review notes the patch works partially - it retains size/position during a session on Windows, but only size on Linux. A key limitation is that geometry is only saved if gitk is closed while the Tags and Heads window is open. Johannes suggests simplifying the implementation by using the Configure event handler to set the geometry, which could reduce code size.

Several specific technical improvements are proposed: making the geometry parsing fail explicitly on bad input rather than silently returning empty, adjusting the window bounds checking to handle oversize windows more gracefully by correcting lower/right bounds first, and fixing an edge case where the title bar could go off-screen. The review is constructive but highlights that the current implementation has platform-specific behavior and some edge cases to address before it would work reliably everywhere.
