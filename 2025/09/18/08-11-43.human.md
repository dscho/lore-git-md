This is a refactoring patch in Karthik Nayak's reftable fsck validation series (v3, 2/8). It moves a consistency check message from the files backend to the generic refs layer, allowing both files and reftable backends to share the same output when running reference checks.

The change is straightforward: the "Checking references consistency" message that was previously printed in `files-backend.c` is now moved to the generic `refs.c` file's `refs_fsck()` function. This ensures the message appears regardless of which backend is being used, while maintaining the same conditional behavior (only showing when fsck is run in verbose mode).

The patch is small (4 lines added, 2 removed) and focused, with no functional changes beyond the message location. It's part of the larger effort to align behavior between the traditional files-based ref storage and the newer reftable backend. The change appears uncontroversial and well-contained, though it's worth noting this is just one piece of a more comprehensive validation series.
