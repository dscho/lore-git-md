This is a feature proposal to add JSON output support to `git log`. The author argues that while machine parsing of git logs is common, current solutions rely on post-processing human-readable output through third-party tools like `jc` or `jq`, which can be fragile (especially for timezone handling) and violate the Unix philosophy of having tools output directly in machine-readable formats when possible.

The proposal suggests adding a `--pretty=json` flag that would output commit data in a structured JSON format, including commit hashes, refs, author/committer info (with proper timestamp handling), and commit messages. The example output shows a nested structure with arrays for refs and merge parents, and proper escaping of special characters in messages.

Key technical points include: adding a `PRETTY_JSON` constant, creating `pretty-json.c` for the formatting logic, and reusing existing utility functions. The author cites several existing tools that work around this limitation (git-log2json, jc parsers) and a blog post by Simon Willison demonstrating a jq-based workaround, arguing these validate the need for native support.

Potential discussion points may include: whether JSON belongs in core Git (vs. external tools), the specific schema design (e.g. field naming, nesting structure), performance implications of JSON generation, and whether this should be a separate output format or integrated with the existing pretty-print system. The proposal is well-motivated with clear use cases but doesn't address how this would interact with other `--pretty` formats or complex log filtering scenarios.
