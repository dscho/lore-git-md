This thread explores ways to improve Git's history manipulation workflow, particularly for interactive rebase operations. The original request from R. Diez sought a graphical interface for mouse-driven commit reordering and squashing, noting that existing GUIs don't adequately support these advanced operations. After terminology clarification from Konstantin Khomoutov and Junio Hamano's suggestion to create a GUI frontend that generates rebase todo files, Patrick Steinhardt has now proposed a more concrete approach.

Patrick's upcoming patch series introduces a new `git history` command with subcommands for common operations like reordering, dropping, and splitting commits. Designed to be more intuitive than raw rebase commands, this CLI tool could serve both as a standalone improvement and as a backend for future GUI development. The interface uses explicit positional arguments (--before/--after) to specify commit relationships, potentially making it easier to build upon for graphical tools while also being useful directly from the command line.

While we await the actual patches to evaluate the technical implementation, this represents a promising middle ground that addresses the original workflow concerns. The thread has progressed from identifying a tooling gap to seeing both high-level direction from the maintainer and now a specific technical proposal from a core contributor. The `git history` command, if implemented well, could satisfy both CLI users wanting better ergonomics and GUI developers needing a structured backend.
