This is a policy clarification in the ongoing Rust dependency series regarding Windows version support. Junio Hamano responds to Matthias Aßhauer's explanation about Git for Windows' version support practices, acknowledging that while core Git doesn't maintain extended Windows version support, Git for Windows explicitly documents its support policies (currently including Windows 8.1+). 

The key points center around the need for conscious decisions about version support rather than accidental side effects of technical choices. Junio emphasizes the importance of documenting these decisions in commit messages, suggesting specific references to Git for Windows' version support documentation when choosing Rust build targets. He also reiterates his concern about potentially encouraging use of unsupported platforms while accepting Git for Windows' divergent practices.

The exchange provides important context for patch 09/17 in the series, which deals with Windows support after introducing Rust. It clarifies that while core Git follows Microsoft's EOL dates, Git for Windows maintains its own extended support timeline, and this divergence should be explicitly documented in the technical implementation choices (like CARGO_BUILD_TARGET selection). The discussion also reveals an underlying tension between security best practices and practical backward compatibility requirements.
