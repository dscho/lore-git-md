Thread identity: User question about viewing the SHA-1 checksum stored at the end of Git index files (`.git/index`), initiated by Jon Forrest, with a technical response from Jeff King.

Core problem: The asker seeks to inspect the overall index file checksum that Git writes at the file's footer for integrity verification. This is a diagnostic question about Git's on-disk index format rather than a feature request. Jeff King confirms there is no built-in Git command for this specific checksum inspection.

Current status: Jeff King provided a shell command workaround to manually extract and verify the checksum, noting this functionality isn't currently exposed through Git commands. The solution requires calculating file offsets and checksums manually, with adjustments needed for SHA-256 repositories.

Technical details: The index file format includes:
- Per-entry checksums (visible via `git ls-files --debug`)
- A trailing SHA-1 checksum covering the entire file contents (20 bytes from end for SHA-1, 32 for SHA-256)
- No standard porcelain/plumbing command exposes the footer checksum
- The provided solution uses shell commands to:
  1. Calculate file size to locate checksum position
  2. Compute checksum of file contents (excluding footer)
  3. Display stored checksum from file

Open questions:
- Should this checksum inspection be added as a formal Git command?
- Are there better approaches than the provided shell commands?
- How should this be documented for SHA-256 repositories?

Participant positions:
- Jon Forrest: Initial question about index checksum inspection
- Jeff King: Confirmed lack of built-in command and provided shell workaround, noting it's primarily useful for debugging

Related work: The index file structure is documented in technical/internal documentation but the specific checksum viewing capability remains undocumented in Git's command interface. The response notes similar limitations exist for other checksummed Git files like pack idx files.
