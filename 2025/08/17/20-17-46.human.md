Feature proposal: Adding JSON output format to `git log`

Ron Ziroby Romero proposes adding a `--pretty=json` option to `git log` to enable direct JSON output rather than requiring third-party tools to parse the human-readable format. The motivation cites several existing workarounds (like `jc`, `jq` hacks, and git-log2json) that parse Git's output, arguing these are imperfect solutions that could be replaced by native JSON support.

The proposal includes a detailed example of what the JSON output would look like, showing commit hashes, refs, author/committer info with proper timestamps, and commit messages. The author argues JSON is well-suited because it handles special characters well and has universal parser support across programming languages.

Implementation would involve adding a new pretty-printer module for JSON output while reusing existing Git internals. The RFC appears well-researched with multiple references to existing solutions and their limitations, though it doesn't yet address potential concerns about output stability or schema versioning that often come up with machine-readable formats in Git. This could be a useful quality-of-life improvement for tooling, but may need discussion about the exact output format details.
