This is a documentation patch in the completed series converting Git's man pages to the new AsciDoc format. SZEDER Gábor reports rendering issues in the `pretty-formats.adoc` conversion when built with Asciidoctor 2.0.16, specifically around the `%(decorate)` section.

The issues observed include:
1. Unwanted `+` characters appearing in default values for `prefix` and `pointer` options
2. The ASCII `->` being rendered as a Unicode arrow character
3. Misaligned example formatting (though this predates the current changes)

The patch being discussed (v3 7/9) had converted the decorate options documentation to use AsciiDoc's `++` escaping for parenthetical format specifiers and backtick-wrapped option names. While the conversion was approved for merging, this email points out that the Asciidoctor rendering differs from the intended output, particularly around the handling of special characters and formatting codes.

This appears to be a toolchain compatibility issue between Git's standard asciidoc.py and Asciidoctor's handling of the same markup. The series has already been approved for merging by Junio Hamano, so this is likely being noted for future reference rather than as a blocking issue. The divergence highlights ongoing challenges in maintaining consistent rendering across different AsciiDoc processors, a known theme in the broader documentation standardization effort.
