[PATCH] Feature request: GUI for interactive history manipulation

R. Diez requests a graphical interface for Git history operations including mouse-driven commit manipulation (drag-and-drop reordering, visual squashing, interactive diff inspection), having evaluated 15 existing GUIs as unsuitable. Konstantin Khomoutov clarifies technical terminology (merging vs squashing) while Junio C Hamano suggests creating a new GUI frontend generating `rebase -i` todo files as a potential GSoC/Outreachy project.

Patrick Steinhardt proposes a new `git history` command with structured subcommands (reorder, drop, split) using explicit --before/--after arguments, serving both as CLI interface and GUI backend. R. Diez responds with concrete workflow pain points (messy commit sequences during long builds) and suggests two additions: a `git history squash` subcommand and a "safe mode" workflow operating on duplicate branches for failure recovery.

Bernd Petrovitsch counters with a `git rebase -i` solution demonstrating how to squash fixup commits (fixA1, fixA2) into parent commit A using existing interactive rebase functionality, including `HEAD~11` range syntax and the fixup command. This provides a working alternative to new tooling while not addressing R. Diez's GUI usability concerns or safe mode request. The discussion now presents three approaches: 1) new GUI generating rebase instructions, 2) Patrick's proposed `git history` CLI backend, and 3) Bernd's demonstration of existing rebase capabilities. Technical evaluation awaits Patrick's promised implementation while the thread explores tension between power user workflows and guided interfaces for history manipulation.
