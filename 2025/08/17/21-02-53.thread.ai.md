[PATCH] Feature request: GUI for interactive history manipulation

R. Diez requests graphical interface for Git history operations including mouse-driven commit manipulation (drag-and-drop reordering, visual squashing, interactive diff inspection), having evaluated 15 existing GUIs as unsuitable. Three approaches emerged: 1) new GUI generating rebase instructions (Junio suggests as GSoC project), 2) Patrick Steinhardt's `git history` CLI backend (9-part series in `builtin/` implementing structured subcommands), and 3) Bernd Petrovitsch's demonstration of existing `git rebase -i` capabilities.

R. Diez's workflow pain points with CLI-based history manipulation include: 1) cognitive overhead of commit position tracking (HEAD~11 syntax), 2) loss of original commit sequences after rebase in git-gui, 3) manual branch management for safe experimentation, and 4) compilation breakage when squashing before verification. The plane ticket analogy illustrates frustration with current CLI workflows.

Johannes Sixt proposes a hybrid CLI-GUI workflow combining `gitk` for visualization and `git gui` for staging with `--fixup`/`--autosquash`: 1) `gitk --branches HEAD` for commit inspection and line origin tracing, 2) `git gui` for selective staging, 3) `commit --fixup` to mark changes for squashing, and 4) `rebase -i --autosquash` to automatically position fixup commits. This addresses compilation-fixup cycles while working within existing tooling, though depends on meaningful commit messages for proper fixup targeting.

Junio C Hamano previously responded to Bernd Petrovitsch's `rebase -i` demonstration, noting the CLI solution works but doesn't address GUI accessibility needs. Ben Knoble provided CLI techniques (`reflog`, defensive branching, `--autosquash`) that partially address pain points. Patrick's `git history` implementation remains potential technical foundation with open questions about squash subcommand implementation and failure recovery.

Key technical terms for follow-ups: reflog, immutable objects, defensive Git branching, autosquash workflow, upstream vs push references in rebase, HEAD~N syntax, compilation-fixup cycle management, gitk line-origin tracing. The core tension remains between expert CLI proficiency and making history manipulation approachable, with Johannes Sixt's hybrid workflow offering a middle ground that maintains rebase power while adding visual aids.
