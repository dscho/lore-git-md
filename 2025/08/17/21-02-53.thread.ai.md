[PATCH] Feature request: GUI for interactive history manipulation

R. Diez requests a graphical interface for Git history operations, specifically mouse-driven commit manipulation including drag-and-drop reordering, visual squashing of commits (mislabeled as merging in original), and interactive diff inspection. The proposal stems from workflow friction with command-line rebase despite terminal proficiency, having evaluated 15 existing GUIs as unsuitable for this visual workflow. Konstantin Khomoutov clarified key technical terminology, distinguishing merging (combining divergent branches) from squashing (combining sequential commits) with ASCII-art examples, noting GUI tools typically target novices rather than complex history rewriting. Junio C Hamano acknowledges the tooling gap and suggests creating a new GUI frontend that generates `rebase -i` todo files, framing it as a suitable project for programs like Google Summer of Code or Outreachy.

Patrick Steinhardt responds to Junio's suggestion by proposing a new `git history` command as a potential building block for graphical tools. The command would provide structured subcommands for history manipulation (reorder, drop, split) with explicit positional arguments (--before/--after) designed to be more intuitive than raw rebase -i syntax. This CLI approach could serve both as a direct interface and as a backend for future GUI tools, addressing the original workflow needs. The implementation appears more concrete than previous high-level GUI discussion, with a patch series promised soon. The proposal represents a middle ground between pure CLI rebase and full GUI tools, potentially evolving with additional subcommands over time. Technical evaluation awaits the actual patch submission.
