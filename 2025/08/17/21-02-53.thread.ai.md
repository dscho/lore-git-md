[PATCH] Feature request: GUI for interactive history manipulation

R. Diez requests a graphical interface for Git history operations, specifically mouse-driven commit manipulation including drag-and-drop reordering, visual squashing of commits (mislabeled as merging in original), and interactive diff inspection. The proposal stems from workflow friction with command-line rebase despite terminal proficiency, having evaluated 15 existing GUIs as unsuitable for this visual workflow. Konstantin Khomoutov clarified key technical terminology, distinguishing merging (combining divergent branches) from squashing (combining sequential commits) with ASCII-art examples, noting GUI tools typically target novices rather than complex history rewriting. Junio C Hamano acknowledges the tooling gap and suggests creating a new GUI frontend that generates `rebase -i` todo files, framing it as a suitable project for programs like Google Summer of Code or Outreachy. The discussion has evolved from terminology clarification to maintainer-endorsed recognition of the problem space, with Junio's response providing a potential implementation direction (GUI-to-todo-file translation) while leaving technical specifics open. No concrete alternative tools or implementation details have been proposed beyond this high-level suggestion.
