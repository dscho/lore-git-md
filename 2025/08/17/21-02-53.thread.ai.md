[PATCH] Feature request: GUI for interactive history manipulation

R. Diez requests graphical interface for Git history operations including mouse-driven commit manipulation (drag-and-drop reordering, visual squashing, interactive diff inspection), having evaluated 15 existing GUIs as unsuitable. Three approaches emerged: 1) new GUI generating rebase instructions (Junio suggests as GSoC project), 2) Patrick Steinhardt's `git history` CLI backend (9-part series in `builtin/` implementing structured subcommands), and 3) Bernd Petrovitsch's demonstration of existing `git rebase -i` capabilities.

R. Diez's workflow pain points with CLI-based history manipulation include: 1) cognitive overhead of commit position tracking (HEAD~11 syntax), 2) loss of original commit sequences after rebase in git-gui, 3) manual branch management for safe experimentation, and 4) compilation breakage when squashing before verification. The plane ticket analogy illustrates frustration with current CLI workflows.

Ben Knoble responds with concrete CLI techniques addressing some pain points: 1) `git reflog <branch>` for recovery of lost commit states, emphasizing Git's immutable object model, and 2) defensive branching workflow (create branch -> rewrite history -> reset if needed) to prevent irreversible changes. Also mentions `commit --fixup/squash` and `rebase --autosquash` as partial automation solutions, though noting they don't eliminate conflict potential.

Patrick's `git history` implementation (reorder/drop/split subcommands with --before/--after args) remains potential technical foundation, but open questions persist about: 1) squash subcommand implementation, 2) integration with failure-recovery workflows, and 3) bridging gap between expert CLI techniques and exploratory interface needs. Konstantin Khomoutov's earlier merging vs squashing clarification remains relevant context.

Key technical terms for follow-ups: reflog, immutable objects, defensive Git branching, autosquash workflow, upstream vs push references in rebase. The discussion is converging toward evaluating which pain points can be addressed by existing CLI patterns versus those requiring new tooling (GUI or enhanced CLI).
