This is a technical discussion about adding JSON output to `git log`, focusing on character encoding challenges.

Brian m. carlson responds to Ron Ziroby Romero's proposal for `--pretty=json` output by raising a critical implementation issue: Git's data (refs, commit messages, author info) often contains non-UTF-8 byte strings, while JSON requires valid Unicode. They note this isn't just theoretical - they've encountered real cases in their work where encoding issues caused problems.

The email suggests two potential solutions: extending Git's JSON writer to handle binary data by URL-encoding non-UTF-8 strings, or using CBOR (which natively supports byte strings) instead of JSON. It also warns against problematic approaches like replacing invalid characters with U+FFFD or outputting raw bytes, which would break parsing.
