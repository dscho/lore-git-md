This is a refactoring patch in Patrick Steinhardt's reftable/libgit2 compatibility series, focusing on error handling in the file locking subsystem. The patch simplifies error propagation from the `flock` interface by removing fragile `errno`-based error code translation in favor of direct reftable-specific error codes.

The change makes the need to interpret `errno` values an implementation detail of the `flock` subsystem rather than something callers must handle. The patch updates three key areas: the stack initialization code, compaction logic, and the actual system implementation. It also documents the expected error codes in the interface header.

This is a straightforward improvement that makes the locking behavior more predictable and maintainable. The change is part of the broader effort to make reftable more robust for libgit2 integration by standardizing error handling patterns. The patch appears well-contained and builds on the series' earlier work to introduce reftable-specific error codes.
