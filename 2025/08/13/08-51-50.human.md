This is a feature proposal for a new `git stash --only-unstaged` option to improve commit-splitting workflows during interactive rebases.

The author describes a common scenario where they need to test staged changes in isolation while preserving unstaged changes for a future commit. Current solutions like `--keep-index` still store the index in the stash (causing potential conflicts on restore), while manual diff/apply workflows are cumbersome. The proposed `--only-unstaged` would stash just the working tree changes, leaving the index untouched in both the working directory and stash object.

The proposal is well-motivated with clear use cases and identifies specific pain points in existing workflows. It appears technically sound, addressing a gap between `git stash`'s current capabilities and a common rebase scenario. The author has thoughtfully considered alternatives and found them lacking.

This seems like a focused, practical addition that would make interactive rebasing smoother. The change would be uncontroversial if implemented cleanly, though the mailing list may want to discuss whether the name `--only-unstaged` is the best choice versus alternatives like `--skip-index`. The proposal doesn't include implementation details or patches yet, so this is early-stage discussion.
