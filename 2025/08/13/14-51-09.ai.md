This is a discussion thread continuation regarding Git diff output formatting, specifically about the display of "no newline" markers. Junio C Hamano reinforces Phillip Wood's earlier explanation that the current behavior is correct and matches GNU diff's output format.

The key technical point is that each "\ No newline at end of file" marker applies to the preceding line in its respective version (old/new) in the diff output. Removing the first marker would incorrectly imply a newline status change when only content was modified. Junio notes this is part of the diff specification, though laments the lack of a formal POSIX reference to cite.

The thread shows maintainers consistently defending the current implementation as technically correct, while acknowledging the original reporter's UX concerns about visual redundancy. No code changes are being proposed - this remains a conceptual discussion about whether the output should be considered a bug (reporter's view) or correct specification implementation (maintainers' view).

The example case involves an HTML template where only the closing tag changes (`) }}` -> `}}`) with both versions lacking final newlines. The technical consensus is that showing both markers properly represents that neither version had a newline, rather than suggesting the newline status changed between versions.
