This thread discusses whether Git's diff output unnecessarily duplicates the "no newline at end of file" marker when comparing two versions that both lack terminating newlines. The original reporter, Дилян Палаузов, raised this as a UX concern, arguing that showing the marker twice is visually noisy when both file versions share the same newline status.

Maintainers Phillip Wood and Junio C Hamano have consistently explained that this is intentional behavior that matches GNU diff's format. Each marker applies to the preceding line in its respective version (old/new), and removing one would incorrectly imply a newline status changed when only content was modified. They emphasize this properly represents the diff specification, though Junio notes the lack of a formal POSIX reference to cite.

The example case involves an HTML template where only the closing tag changes (`) }}` -> `}}`), with both versions lacking final newlines. While the reporter continues to express concerns about visual redundancy, the technical consensus among maintainers is firm - the current output correctly shows that neither version had a newline, rather than suggesting the newline status changed between versions. No code changes are being proposed, as this remains a conceptual discussion about specification compliance versus presentation preferences.
