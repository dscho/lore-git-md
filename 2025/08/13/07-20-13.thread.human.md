This thread discusses a report about `git diff` showing duplicate "\ No newline at end of file" markers when comparing two versions that both lack terminating newlines. The original reporter, Дилян Палаузов, observed this behavior in both local Git and GitHub's web interface, using an HTML template example where only the closing tag changed between versions.

Phillip Wood has since clarified that this output is intentional and matches GNU diff's format - each marker applies to the line preceding it, and removing the first marker would incorrectly imply the newline status changed when only content was modified. While the current behavior is technically correct per diff format standards, the reporter finds it undesirable from a user experience perspective. The discussion now centers on whether Git should modify this output for clarity or maintain strict compatibility with traditional diff tools. No code changes have been proposed yet.
