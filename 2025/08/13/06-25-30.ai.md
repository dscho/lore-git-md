This is a bugfix patch in Patrick Steinhardt's reftable/libgit2 compatibility series, addressing race conditions during stack compaction operations.

The patch fixes error handling when detecting outdated reftable stacks during compaction. Previously, the `stack_uptodate()` function could return positive values (indicating an outdated stack) that were incorrectly treated as errors. The fix properly translates these cases to `REFTABLE_OUTDATED_ERROR` and updates `reftable_addition_commit()` to handle this error code as benign, similar to how it already handles `REFTABLE_LOCK_ERROR`.

Key technical changes:
1. Improved documentation for `stack_uptodate()` to clearly specify its return values (0=up-to-date, 1=outdated, negative=error)
2. Modified `stack_compact_range()` to explicitly convert outdated stack conditions (positive return) to `REFTABLE_OUTDATED_ERROR`
3. Updated `reftable_addition_commit()` to treat both `REFTABLE_LOCK_ERROR` and `REFTABLE_OUTDATED_ERROR` as benign conditions during auto-compaction

The changes maintain the existing best-effort compaction behavior while properly distinguishing between actual errors and expected race conditions. The patch continues the series' focus on making reftable operations safe in concurrent scenarios, with particular attention to error handling consistency.

This is part of the ongoing effort to make reftable production-ready for libgit2 integration, with all test feedback from previous rounds addressed. The changes are focused in reftable/stack.c and maintain backward compatibility while improving robustness.
