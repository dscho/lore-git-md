Feature proposal for gitignore file inclusion capability.

Ryan Johnson proposes adding an `include` directive to `.gitignore` files that would allow including patterns from other gitignore files. The motivation comes from managing complex projects with multiple language-specific ignore patterns, where copying templates from repositories like github/gitignore leads to unwieldy monolithic files that mix template content with project-specific rules.

The key technical aspect would be a new syntax like `include .gitignore.python` that would inline the contents of the specified file during pattern evaluation. This would help maintain separation between template patterns (which could be updated by pulling from upstream sources) and project-specific ignores. The proposal notes this would be particularly valuable for teams where multiple contributors might otherwise interleave custom patterns within template sections.

The suggested implementation approach isn't specified, but the change would presumably need to modify the pattern parsing logic in `dir.c` and related ignore-handling code. The proposal references GitHub's collection of language-specific gitignore templates as evidence of the problem space, though it doesn't address potential security considerations around including arbitrary paths.

This appears to be an initial feature suggestion rather than a patch submission, so implementation details and edge cases (relative path handling, include cycles, performance impact) remain unexplored. The idea builds on established patterns from other tools (like Makefile includes) but would represent a new capability in Git's ignore system.
