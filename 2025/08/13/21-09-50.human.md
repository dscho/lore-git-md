This is a feature proposal for `.gitignore` files to support including other ignore files, similar to how Makefiles can include other files. Ryan Johnson suggests this would help manage complex ignore patterns, particularly when working with multiple language templates from sources like GitHub's gitignore collection.

The proposal notes that current practice requires copying large template files (like the 300+ line Python.gitignore) directly into project ignore files, which becomes unwieldy for multi-language projects and makes it hard to distinguish template content from project-specific ignores. The suggested `include` syntax would let projects reference external ignore files while keeping local modifications separate.

The motivation focuses on maintainability - it would be easier to update template files and prevent team members from accidentally modifying template sections. The proposal is straightforward but doesn't address potential implementation details like path resolution, cycle detection, or how this might interact with existing ignore file precedence rules. The idea appears well-intentioned but would need technical specification and likely some discussion about edge cases.
