This thread discusses a bug where commit message cleanup behaves inconsistently during autosquash rebases when using prepare-commit-msg hooks with commit.cleanup=strip. While normal commits properly strip hook-injected comments, autosquash operations preserve them due to a 2021 change (f7d42ceec52) that prioritized verbatim message preservation.

Simon Cheng originally reported the issue and provided a clear reproduction case. Phillip Wood identified the root cause and questioned the current behavior's inconsistency, proposing to make fixup/squash commands respect commit.cleanup like pick commands do. In the latest email, Simon confirms agreement with this approach and suggests updating the git-config documentation to clarify which commands honor the cleanup setting.

The discussion has reached consensus on the solution path, with Phillip expected to submit a patch implementing the behavior alignment when he returns. The fix will likely involve both code changes to respect cleanup during autosquash and documentation updates to reflect the consistent behavior. This addresses the core inconsistency while maintaining the prepare-commit-msg hook's functionality.
