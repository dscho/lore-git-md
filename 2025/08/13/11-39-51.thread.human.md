Here's a human-readable summary of the thread:

A bug report highlights an unexpected interaction between commit message hooks and autosquash rebases. When using a `prepare-commit-msg` hook that adds comments to commit messages (like recent history) combined with `commit.cleanup=strip` configuration, the cleanup step fails during autosquash rebases. While normal commits properly strip the hook-injected comments, rebase operations preserve them in the final squashed commit when they should be removed.

The issue affects Git 2.50.1 and appears to stem from the rebase machinery not fully applying the message cleanup pipeline during autosquash operations. This could impact developers who rely on both commit message automation and the convenience of fixup/squash commits. The test case demonstrates the problem clearly by showing how injected comments persist in the final commit when they should be stripped according to the configuration.
