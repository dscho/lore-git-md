This is a bug report about commit message cleanup not working as expected during autosquash rebases. The issue occurs when using a custom `prepare-commit-msg` hook that injects comments into commit messages, combined with `commit.cleanup=strip` configuration.

The reporter demonstrates that while `commit.cleanup=strip` works as expected for normal commits (stripping the hook-injected comments), this cleanup does not occur during an autosquash rebase operation. This results in the final squashed commit retaining the injected comments when it should be stripped. The test case shows this by using a simple hook that adds recent commit history as comments.

Key technical details include:
- `prepare-commit-msg` hook injecting content
- `commit.cleanup=strip` configuration
- `git rebase --autosquash` operation
- The issue appears when squashing fixup commits
- Git version 2.50.1 (relatively recent)

The bug appears to be in the interaction between the rebase machinery and the commit message processing pipeline, where the cleanup step is either skipped or not properly applied during the autosquash operation. This could affect any users relying on both commit message hooks and autosquash functionality.
