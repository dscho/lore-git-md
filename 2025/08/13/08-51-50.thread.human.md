This thread explores a proposed enhancement to `git stash --only-unstaged` to improve commit-splitting workflows during interactive rebases. The core idea is to modify `--keep-index` behavior via a backward-compatible trailer-based approach, allowing users to test staged changes while cleanly stashing unstaged ones without the conflicts that currently occur during pop operations.

Phillip Wood has demonstrated technical feasibility using `git merge-tree` with the stash's index state as a merge base, creating temporary index files to preserve state during conflict resolution. While Junio Hamano initially questioned whether the existing `--keep-index` behavior might suffice, Wood countered with practical workflow needs, and the discussion has converged on adding a commit message trailer (likely `Stash-created-with: --keep-index`) to enable automatic unstaged-change-only behavior during pops.

In the latest exchange, Wood addresses Ben Knoble's concerns about documentation examples and import/export compatibility, confirming the trailer approach should work seamlessly across boundaries since stash exports preserve full commit messages. The main open questions now involve edge cases in merge conflict resolution when the trailer is present and verifying behavior in less common scenarios. With Wood's technical leadership and Knoble's implementation-focused feedback, the proposal appears to be on track for eventual inclusion, balancing workflow improvements with Git's stability guarantees.
