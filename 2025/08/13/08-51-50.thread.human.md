This thread explores a proposed `git stash --only-unstaged` feature to improve workflows during interactive rebases, where users need to temporarily set aside unstaged changes without disturbing staged content. The original proposal by D. Ben Knoble identified that current `--keep-index` solutions still store the index in stash entries, causing potential conflicts during restore operations. Knoble's analysis showed these conflicts stem from duplicate working tree states in the current stash format, not the index as previously assumed.

Phillip Wood has now contributed a practical workaround - a shell script that safely restores only unstaged changes from existing `--keep-index` stashes. His solution uses a three-way merge with the stashed index as a base to isolate unstaged modifications, handling most conflict-free cases automatically while preserving the index state. The script demonstrates the technical feasibility of the approach and could evolve into a proper `--unstaged` option for `git stash pop`.

While Junio Hamano's concerns about edge case behavior remain open for the core feature proposal, Wood's contribution provides immediate relief for the pain point while validating the underlying concept. The script's architecture - particularly its use of `git merge-tree` and temporary index files - may directly inform the design of the eventual built-in solution. The discussion now has both a clear long-term direction (`--only-unstaged`) and a practical stopgap, with the technical foundations well-established through collaborative analysis.
