This thread proposes adding a `git stash --only-unstaged` option to better support commit-splitting workflows during interactive rebases. The author describes a common scenario where developers need to test staged changes (for an earlier commit) while temporarily setting aside unstaged changes (for a later commit). Current solutions like `--keep-index` still store the index in the stash, which can cause conflicts when popping the stash later.

The proposed solution would create stash entries containing only working tree changes, leaving the index untouched in both the working directory and the stash object. This would provide a cleaner way to manage intermediate states during rebase operations. The author has found no existing command that offers this exact functionality, suggesting it may fill a genuine gap in Git's tooling. The proposal is now open for discussion about prior consideration of such a feature and potential implementation interest.
