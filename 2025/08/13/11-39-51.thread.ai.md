Thread identity: Bug report about commit message cleanup behavior during autosquash rebases when using prepare-commit-msg hooks with commit.cleanup=strip configuration.

Core problem: When a prepare-commit-msg hook injects comments into commit messages and commit.cleanup=strip is set, the cleanup step fails to strip these comments during autosquash rebase operations, though it works correctly for normal commits. This results in unwanted hook-injected content persisting in final squashed commits.

Current status: Phillip Wood has identified the root cause in commit f7d42ceec52 (2021) and proposed making fixup/squash commands respect commit.cleanup consistently with pick commands. Simon Cheng has confirmed agreement with this approach and suggested updating documentation. Phillip may work on a fix after returning from absence.

Key technical details:
- prepare-commit-msg hook can inject content (shown via example hook adding recent commit history as comments)
- commit.cleanup=strip configuration normally removes comments
- rebase --autosquash operation skips cleanup due to f7d42ceec52's verbatim preservation
- Regular "pick" commands respect commit.cleanup while fixup/squash do not
- Hook modifications make "verbatim" preservation impossible in practice
- Documentation may need update to clarify which commands respect commit.cleanup

Open questions:
- Exact implementation approach to align fixup behavior with pick commands
- Potential impact on existing workflows relying on current behavior
