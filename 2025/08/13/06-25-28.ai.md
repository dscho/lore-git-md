Bugfix in Patrick Steinhardt's reftable/libgit2 compatibility series (v4 4/8), addressing a compiler warning in older toolchains. The patch removes the `REFTABLE_ADDITION_INIT` macro that was causing brace-related warnings during zero-initialization of nested structs, replacing it with explicit `memset()` calls in the initialization function.

The change affects `reftable/stack.c`, specifically the `reftable_addition` struct initialization pattern. While the warning was deemed bogus in prior discussions (referencing a 2022 thread), this patch provides a cleaner solution by centralizing initialization in `reftable_stack_init_addition()` rather than using a macro. This simplifies the calling convention while maintaining the same zero-initialization behavior.

The modification touches several functions that create or initialize `reftable_addition` structs, including `stack_try_add()` and `reftable_stack_new_addition()`. The change is purely technical with no functional impact, aligning with the series' goal of improving code quality and portability for libgit2 integration. Carlo Arenas suggested this approach, which Patrick implemented while maintaining the series' focus on production-ready reftable support.
