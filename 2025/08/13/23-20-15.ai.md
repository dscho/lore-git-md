This is the first patch in Julia Evans' v2 documentation series for improving the `git-add` man page, focusing on making the DESCRIPTION section more beginner-friendly. The patch replaces the original technical introduction with a concrete example workflow showing how to stage and commit changes, while maintaining the same core information.

Key changes in this revision:
- Replaces abstract description of the index with a practical example showing `git add file.c` followed by `git commit`
- Defines the index explicitly as "where Git stores the changes that will be in the next commit"
- Shifts from a snapshot-based explanation to a diff-based one, arguing this better matches how users typically interact with Git via `git diff` and `git status`
- Adds a mention of partial staging with `git add -p`
- Moves some reference material about alternative commit methods to flow more naturally with the example
