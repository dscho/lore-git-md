This thread documents a comprehensive redesign of `git describe`'s blob handling to address several edge cases and improve error reporting. The effort began with a bug report and has evolved into a 5-patch series that refactors the code for safety and more explicit behavior.

Jeff King is leading the implementation, building on initial work by René Scharfe. The first patch (already merged) refactored object_id handling to use const pointers, while the second introduced explicit error reporting when blobs cannot be found - changing from silent failure to die() with a descriptive message. The third patch, just submitted, tackles another edge case: it improves error messages when attempting to describe a blob on an unborn branch, replacing a generic "ambiguous argument" error with a specific "cannot search for blob on an unborn branch" message.

The series maintains thorough test coverage, with each patch adding new test cases. While the architectural direction is settled, some open questions remain about the impact on existing usage (particularly scripts that might rely on silent failure) and whether to formally document the `--always` behavior. Phillip Wood, who previously reviewed the safety changes, is expected to review the new patches. The remaining patches in the series will address the final edge cases around blob traversal with no commits.
