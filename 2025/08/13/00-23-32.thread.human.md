This thread addresses a bugfix and architectural redesign of Git's `describe` functionality, specifically focusing on error handling improvements in `builtin/describe.c`. Jeff King (Peff) has submitted a 5-patch series that systematically replaces silent failure modes with explicit error reporting.

The core changes include making blob description behavior consistent with commit description by having `describe_blob()` explicitly fail (via `die()`) when encountering unreachable objects, rather than silently returning an empty string. The series also adds proper handling for unborn branches and corrupted HEAD cases. Junio Hamano has approved the first three patches, which cover object ID handling, blob error reporting, and unborn branch cases. Patches 4-5, addressing corrupted HEAD states and interface cleanup, remain under review but appear to be on track.

Patrick Steinhardt has now chimed in with a +1 on Patch 2/5, reinforcing the consensus that silent failures should be eliminated despite potential backward compatibility concerns. The thread shows broad agreement among maintainers (Junio, Patrick, Phillip Wood) that the changes improve code safety and consistency. Junio has noted some future considerations, like searching beyond HEAD for blobs, but these don't block the current series.

With three patches approved and the remaining two nearing completion, this thread demonstrates Git's careful approach to fixing subtle behaviors - methodically addressing edge cases while maintaining backward compatibility where possible. The changes will make `git describe` more reliable while setting the stage for future enhancements.
