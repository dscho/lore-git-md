This thread documents a series of improvements to `git describe`'s error handling, particularly around blob descriptions. Jeff King is leading the effort to replace silent failures with explicit error messages, with Junio Hamano providing review and approval.

The series has three approved patches so far: one standardizing object ID handling, another fixing blob error reporting, and now this third patch that properly handles blob descriptions on unborn branches (where HEAD doesn't point to any commit). The new patch adds explicit error checking when resolving HEAD, preventing potential crashes and providing clear feedback. 

Junio noted some technical details that will be addressed in later patches, including an object ID copying pattern and whether blob searches should look beyond HEAD (deferred as future work). The discussion also touched on various HEAD resolution methods used throughout Git's codebase, though the current conservative approach was deemed sufficient for this fix.

With patches 1-3 either approved or submitted, the remaining work focuses on edge cases (corrupted HEAD states) and interface cleanup. The series maintains backward compatibility while systematically improving robustness, with test coverage expanded to verify the new handling. While some design questions remain open for future consideration, the core improvements are progressing toward merging.
