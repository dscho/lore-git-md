Thread identity: Bug report about `git send-email`'s `--suppress-cc` option failing to handle comma-separated keywords.

Core problem: The `--suppress-cc` option in `git send-email` incorrectly processes multiple comma-separated keywords (e.g., `--suppress-cc=author,self`) by treating them as a single invalid keyword rather than parsing them individually. The expected behavior would suppress CCs for each specified keyword, but instead it errors with "Unknown --suppress-cc field: 'author,self'".

Current status: Bug reported by Timur Tabi against git version 2.50.1. A workaround exists by specifying `--suppress-cc` multiple times (once per keyword). No patches have been proposed yet.

Key technical details: The issue appears in the command-line option parsing logic for `git send-email`, specifically in how it handles comma-separated values for the `--suppress-cc` option. The bug affects the suppression of multiple types of automatic CCs (author, self, cc, bodycc, sob, cccmd) in a single command.

Participant positions: Timur Tabi reported the bug with system details (Linux, glibc 2.39, GCC 13.3) confirming it's not system-specific issue but rather a parsing logic bug in the command-line option handling.
