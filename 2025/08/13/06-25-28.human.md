This is a refactoring patch in Patrick Steinhardt's reftable/libgit2 compatibility series (v4, 4/8). It addresses a compiler warning about brace initialization in older toolchains while simplifying the code.

The patch removes the `REFTABLE_ADDITION_INIT` macro that was causing warnings when initializing nested structs with `{0}`. Instead, it moves to explicit zeroing via `memset()` in `reftable_stack_init_addition()`, which callers must already invoke. This change both silences the warning and simplifies the calling convention by removing redundant initialization.

The approach follows prior Git project decisions about compiler compatibility - while the warning could be fixed with `{{0}}`, the project prefers not to cater to older compilers with such quirks. The solution here is cleaner as it centralizes initialization logic in one place.

This is a minor but thoughtful improvement in the larger series, showing attention to both code quality and maintainability. The change is straightforward with no behavior impact, just better organization and compiler compatibility.
