This is a bug report about commit message cleanup behavior during autosquash rebases. Simon Cheng reports that when using a `prepare-commit-msg` hook to inject comments into commit messages, the expected cleanup (specifically `commit.cleanup=strip`) doesn't happen during autosquash operations, leaving unwanted comments in the final commit message.

The issue occurs when:
1. A hook injects comments (in this case showing recent commit history)
2. `commit.cleanup=strip` is set to remove such comments
3. An autosquash rebase combines commits

The expected behavior would be for the cleanup to strip comments during the squash, but instead the injected content remains. The report includes clear reproduction steps and the hook script, making it easy to verify. This appears to be a genuine inconsistency in Git's behavior around message processing during rebase operations.

The bug affects users who rely on both commit message automation (via hooks) and autosquash workflows. While not a critical issue, it does impact commit message hygiene in automated scenarios. The report is well-structured with all necessary technical details included.
