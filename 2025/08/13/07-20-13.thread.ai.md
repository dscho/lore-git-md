Git diff output formatting: duplicate "no newline" marker discussion. Author Дилян Палаузов reported that when comparing two file versions both lacking terminating newlines, `git diff` shows "\ No newline at end of file" after both old and new content, which they consider redundant. Phillip Wood clarifies this is intentional behavior matching GNU diff's format - each marker applies to the preceding line, and removing the first would incorrectly imply a newline status change when only content was modified. The thread now presents two perspectives: the original reporter's UX concern about visual redundancy versus the maintainers' position that the current output correctly represents the diff format specification and maintains compatibility with traditional diff tools. No code changes have been proposed yet; the discussion remains at the level of whether the behavior should be considered a bug (reporter's view) or correct implementation (Phillip's view). The example case remains an HTML template where only the closing tag changes (`) }}` -> `}}`) with both versions lacking final newlines.
