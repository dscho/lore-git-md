Git diff output formatting: duplicate "no newline" marker discussion. Author Дилян Палаузов reported that when comparing two file versions both lacking terminating newlines, `git diff` shows "\ No newline at end of file" after both old and new content, which they consider redundant. Phillip Wood and Junio C Hamano clarify this is intentional behavior matching GNU diff's format - each marker applies to the preceding line in its respective version (old/new), and removing the first would incorrectly imply a newline status change when only content was modified.

Junio C Hamano reinforces Phillip Wood's explanation that the current behavior is correct and matches GNU diff's output format, though laments the lack of a formal POSIX reference to cite. The key point is that each "\ No newline at end of file" marker applies to the preceding line in its respective version, and omitting one would misrepresent the newline status of that version.
