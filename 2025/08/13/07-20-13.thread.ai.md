Git diff output formatting bug: duplicate "no newline" marker. When comparing two file versions that both lack terminating newlines, `git diff` currently shows the "\ No newline at end of file" warning after both old and new content, despite the newline status not changing between versions. Author Дилян Палаузов reports this occurs in both local git diffs and GitHub's web interface. The issue is demonstrated with an HTML template example where only the closing tag changes (`) }}` -> `}}`), with both versions lacking final newlines. The proposed solution would suppress the first warning when both versions share the same newline status. This is purely a cosmetic output formatting issue affecting user experience, not a change to diff algorithm behavior. No code changes or tests are included in the initial report.
