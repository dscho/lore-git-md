This thread began with Timur Tabi reporting what appeared to be a bug in `git send-email`'s `--suppress-cc` option, where comma-separated keywords weren't working as expected. Eric Sunshine clarified that the behavior was actually intentional - the option was designed to require separate flags for each suppression category (like `--suppress-cc=author --suppress-cc=self`), matching its documentation. This effectively closed the discussion as the implementation matched its specification.

Junio Hamano has now followed up with a documentation patch to make this behavior clearer for future users. The patch explicitly states that the flag can be given multiple times to suppress different categories, and notes that the corresponding config variable `sendemail.suppressCc` works the same way. This small but useful clarification helps prevent similar confusion while maintaining the existing implementation. The thread demonstrates how even well-documented features can sometimes benefit from making implicit behaviors more explicit.
