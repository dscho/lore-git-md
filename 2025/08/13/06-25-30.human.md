This is a bugfix patch in Patrick Steinhardt's reftable/libgit2 compatibility series, addressing race conditions during stack compaction. The patch improves error handling when detecting outdated reftable stacks during compaction operations.

The core issue stems from how `stack_uptodate()` returns different values (0 for up-to-date, 1 for outdated, negative for errors) but some callers weren't properly distinguishing between the outdated case and actual errors. The patch makes two key changes: it documents the return values more clearly, and ensures `REFTABLE_OUTDATED_ERROR` is properly propagated when the stack is outdated rather than treating it as a generic error.

The fix is particularly important for `reftable_addition_commit()`, which now explicitly handles both `REFTABLE_LOCK_ERROR` and `REFTABLE_OUTDATED_ERROR` as benign conditions during its best-effort auto-compaction. The patch also adds defensive programming in `stack_compact_range()` to abort cleanly if the stack is outdated, with a detailed comment explaining why this is the safest approach.

This is a focused improvement to the reftable stack's concurrent modification handling, building on the series' broader goal of making reftable operations production-ready. The changes are well-contained (just stack.c) and maintain backward compatibility while making error conditions more explicit.
