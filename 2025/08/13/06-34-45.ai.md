This is a clarification about the `git send-email` `--suppress-cc` option's documented behavior versus user expectations. Eric Sunshine responds to Timur Tabi's bug report by pointing out that the behavior Timur observed (comma-separated keywords not working) is actually the intended behavior, not a bug.

The key points are that:
1. The documentation never claims `--suppress-cc` accepts comma-separated values - it only shows examples using multiple `--suppress-cc` flags
2. The current implementation matches this documented behavior
3. The workaround Timur found (using multiple flags) is the correct approach

This email effectively closes the bug report by explaining it's a documentation of expectations issue rather than a code bug. The thread shows a common case where a user assumes comma-separation would work (as it does for many other Git options) when the feature was actually designed to require separate flags. No code changes are proposed - just clarification of the existing behavior.
