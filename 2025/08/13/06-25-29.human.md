This is part 5/8 of Patrick Steinhardt's reftable/libgit2 compatibility series, focusing on atomic stack operations. The patch adds a `flags` parameter to `reftable_stack_add()` to enable automatic stack reloading when modifications occur during locking. This addresses a race condition where concurrent writers could modify the stack before a transaction acquires its lock.

The change is straightforward - it threads the new `flags` parameter through the stack addition call chain while maintaining backward compatibility by passing 0 in all existing callers. The patch includes updates to the function signature, documentation, and test cases, though no tests exercise the new flag yet (presumably coming in a later patch).

This is a well-contained change that builds on the series' goal of making reftable operations more robust for libgit2 integration. The implementation looks clean and maintains existing behavior while adding the necessary plumbing for future functionality. As with the rest of the series, this appears production-ready.
