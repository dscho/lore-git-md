This is a response in the thread about duplicate "no newline" markers in git diff output. Phillip Wood explains that the current behavior is intentional and matches GNU diff's output format - each "\ No newline at end of file" marker applies to the line preceding it, and removing the first marker would incorrectly imply the newline status changed when only the content was modified. The response clarifies this is not a bug but rather the expected diff format, though the original reporter found this behavior undesirable from a UX perspective. The discussion centers on whether the output should be changed for clarity versus maintaining compatibility with traditional diff tools. No code changes are proposed in this response, just an explanation of the current behavior's rationale.
