This is a feature proposal for a new `git stash --only-unstaged` option to improve commit-splitting workflows during interactive rebases. The author describes a common scenario where they need to test staged changes (for an earlier commit) while temporarily setting aside unstaged changes (for a later commit). Current solutions like `--keep-index` still store the index in the stash, leading to potential conflicts when popping the stash later. The proposed `--only-unstaged` would create stash entries containing only working tree changes, leaving the index untouched in both the working directory and the stash object.

Key technical details for future reference: The proposal specifically addresses the stash object format (which currently always includes index state) and the interaction with `git stash pop`. The suggested flag name is `--only-unstaged`, positioned as a `git stash push` sub-option. The use case centers around interactive rebase workflows where commit splitting requires testing intermediate states without disturbing pending changes.

The proposal appears well-motivated by a concrete workflow pain point and offers a clean solution that doesn't seem to conflict with existing stash behavior. The author notes they've found no existing command or option providing this exact functionality, suggesting this may be a genuine gap in Git's tooling. The email invites discussion about prior consideration of such a feature and potential interest in implementing it.
