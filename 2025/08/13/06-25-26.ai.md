Refactoring patch in Patrick Steinhardt's reftable/libgit2 compatibility series (v4 2/8), removing Git-specific dependencies to improve standalone usability.

This patch replaces the Git-specific `QSORT()` macro with standard `qsort()` in reftable/writer.c, making two key changes: adding explicit element size` parameter and adding null checks before sorting. The modification affects both ref and log record sorting paths (`reftable_writer_add_refs` and `reftable_writer_add_logs`), though the actual sorting behavior remains identical.

The change is part of the broader effort to make reftable usable by libgit2 by removing Git-specific dependencies. While functionally equivalent, this makes the code more portable since `QSORT()` is a Git-internal convenience macro that hides the element size parameter. The patch maintains all existing error handling and control flow, just with the sorting implementation detail changed.

This appears to be a straightforward, well-contained change with clear motivation stated in the commit message. It follows the series' pattern of removing Git-isms while preserving behavior, and the diff shows careful handling of edge cases (the null check addition). As with other patches in this series, the change has already been validated through libgit2's test suite.
