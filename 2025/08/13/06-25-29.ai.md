This is a refactoring patch in Patrick Steinhardt's reftable/libgit2 compatibility series (v4, patch 5/8). It extends the `reftable_stack_add()` function to accept flags, specifically to enable automatic stack reloading when modifications are detected during locking.

The change adds a `flags` parameter to `reftable_stack_add()` and propagates it through the call chain to `reftable_stack_init_addition()`. All existing callers are updated to pass `0` for now, maintaining current behavior. The patch includes updates to the function's documentation header to clarify the new parameter's purpose.

Key technical elements:
- New `flags` parameter added to `reftable_stack_add()` interface (reftable-stack.h)
- Parameter propagated through `stack_try_add()` helper (stack.c)
- 18 test call sites updated in t/unit-tests/t-reftable-stack.c to pass `0` flags
- Documentation updated to note flags will be used by libgit2 in future

The change is part of the series' goal to enable proper concurrent write safety in reftable operations. While this patch itself doesn't implement the reload functionality (reserved for a subsequent patch), it lays the groundwork by making the flag plumbing consistent across the stack API. The extensive test updates demonstrate the change's mechanical nature - no behavior is altered yet, just the interface extended.
