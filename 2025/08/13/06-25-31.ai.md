This is a refactoring patch in Patrick Steinhardt's reftable/libgit2 compatibility series, focusing on error handling in the file locking subsystem. The patch simplifies error handling in the reftable stack implementation by removing fragile errno-based checks in favor of direct reftable error codes. The key change makes the flock_acquire() interface consistently return reftable-specific error codes (REFTABLE_LOCK_ERROR for contention, REFTABLE_IO_ERROR for other failures) rather than relying on callers to interpret errno values. This affects three main code paths in reftable/stack.c that handle table locking during stack operations.

The changes include updating the system.h documentation to explicitly state the expected error codes, modifying system.c to return REFTABLE_IO_ERROR directly (rather than -1) for non-EEXIST failures, and removing redundant errno translation code from multiple call sites in stack.c. The patch maintains all existing behavior while making the error handling more robust and self-documenting, particularly important for libgit2 integration where the locking implementation may vary.

This is part of the broader effort to make reftable's interfaces more standardized and less dependent on Git-specific behaviors. The changes are focused on internal implementation details rather than user-visible behavior, with all test cases continuing to pass as before. The patch follows the series' pattern of improving code quality and interface consistency in preparation for production use in libgit2.
