Git diff behavior clarification regarding "no newline" markers. Junio C Hamano weighs in on the ongoing discussion about whether `git diff` should show duplicate "no newline" markers when both old and new versions of a file lack terminating newlines. He explains that each marker correctly annotates the state of its respective version - the first marks the old version's incomplete line, the second marks the new version's similarly incomplete line. Junio provides concrete examples showing how the markers would differ if either version had a terminating newline, reinforcing that the current output accurately represents the diff format specification. This maintains compatibility with traditional diff tools while precisely documenting the file state at each point in the change history. The response solidifies the maintainers' position that this is correct behavior rather than a bug, though the original reporter's UX concerns about visual redundancy remain unaddressed.
