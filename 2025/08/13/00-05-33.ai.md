Bugfix for `git send-email`'s `--suppress-cc` option handling. Timur Tabi reports that the `--suppress-cc` option fails when given multiple comma-separated keywords (like `--suppress-cc=author,self`), treating them as a single invalid keyword rather than parsing them individually. The expected behavior would be to recognize each keyword and suppress the corresponding CCs, but instead it errors with "Unknown --suppress-cc field: 'author,self'".

The bug appears in git version 2.50.1, and the reporter found a workaround by specifying `--suppress-cc` multiple times (once per keyword). The issue seems to be in the parsing logic of the `--suppress-cc` option, which isn't properly splitting the comma-separated values. This affects users trying to suppress multiple types of automatic CCs in one command.

The bugreport includes full system information showing this occurs on a Linux system with glibc 2.39 and GCC 13.3. No patches or hooks are involved. The issue appears to be a straightforward parsing bug in the command-line option handling rather than anything system-specific.
