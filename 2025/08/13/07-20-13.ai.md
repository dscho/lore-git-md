Bugfix targeting git diff output formatting. This patch addresses a cosmetic issue where `git diff` shows the "\ No newline at end of file" marker twice when displaying diffs for files that lack a terminating newline. The author, Дилян Палаузов, observes that this occurs both in local git diffs and on GitHub's web interface, arguing the marker should only appear once since the newline status isn't actually changing between file versions.

The example shows a simple HTML template modification where the closing tag changes from `) }}` to `}}`, with both versions lacking a final newline. Currently, git outputs the newline warning after both the old and new content, though the file's newline status remains unchanged throughout. The patch suggests suppressing the first instance of this warning when comparing two versions that both lack terminating newlines.

This appears to be a straightforward output formatting improvement with no behavioral changes to the actual diff algorithm. The issue is clearly demonstrated with a minimal test case, though the submission doesn't include proposed code changes or tests. The problem affects both command-line git and web interfaces that parse its output, making it a visible (if minor) user experience issue.
