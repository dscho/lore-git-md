git stash --only-unstaged feature proposal to improve commit-splitting workflows during interactive rebases, with ongoing discussion about modifying --keep-index behavior via a backward-compatible trailer-based approach. Original motivation centered on testing staged changes while temporarily setting aside unstaged changes, addressing current --keep-index limitations where pop operations cause conflicts due to working tree state in both stash commits.

Phillip Wood demonstrated technical feasibility via shell script using git merge-tree with stash's index state as merge base, creating temporary index file ($GIT_DIR/stash-pop-index) to preserve real index state during conflict resolution. Junio Hamano initially questioned the design direction, suggesting --keep-index's original behavior might suffice if users avoid modifying working tree files during testing, while Wood countered with practical workflow needs.

Current proposal involves adding a trailer to stash commit messages when created with --keep-index, enabling automatic unstaged-change-only behavior during pop operations while maintaining backward compatibility. Ben Knoble raises a practical concern about potential interactions with stash import/export functionality, though notes this might not be an issue if those operations already omit index information. The trailer approach addresses Hamano's concern about default behavior by making it opt-in via the original creation command.

Implementation would still need to handle three-way merge mechanics from Wood's script, particularly conflict cases where adjacent lines were modified. Open questions include: verifying trailer preservation across stash import/export boundaries, edge cases in merge conflict resolution when the trailer is present, and whether the solution should eventually replace --keep-index entirely. The thread shows convergence toward a solution balancing workflow improvements with Git's stability guarantees, with Wood's technical proposals and Knoble's implementation-focused feedback driving the discussion forward. Core participants remain Wood (sequencer/rebase expert), Hamano (maintainer perspective), and Knoble (build system/tooling expertise).
