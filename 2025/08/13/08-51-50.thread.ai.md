git stash --only-unstaged feature proposal to improve commit-splitting workflows during interactive rebases. Original motivation: need to test staged changes while temporarily setting aside unstaged changes, with current --keep-index solution proving insufficient due to conflicts during pop operations. D. Ben Knoble's analysis showed conflicts stem from working tree state in both stash commits, motivating a new stash format that excludes index state entirely.

Phillip Wood contributed an interim shell script demonstrating safe restoration of only unstaged changes from a --keep-index stash, using git merge-tree with stash's index state as merge base to isolate unstaged changes via three-way merge between HEAD, stashed index, and stashed worktree. The script creates temporary index file ($GIT_DIR/stash-pop-index) to preserve real index state until conflicts resolved, handling most conflict-free cases automatically while properly reporting adjacent line modifications.

Junio Hamano questions whether the proposed --unstaged behavior should be enabled by default rather than requiring a new option, suggesting the original --keep-index design assumed users wouldn't modify working tree files while testing staged changes. His response highlights design philosophy differences - whether to expand stash's capabilities (Wood's approach) or maintain its original focused purpose. The discussion references stash commit structure (stash_oid^1 and stash_oid^2 components) and continues exploring backward compatibility implications.

Open questions remain about whether the new behavior should complement or replace --keep-index, with Hamano's skepticism contrasting with Wood's demonstrated technical feasibility. Implementation considerations must still address backward compatibility with existing stash operations while supporting index-less stash entries, with the script's architecture potentially informing the built-in solution. The thread shows active progress toward solving the core workflow pain point in interactive rebase testing scenarios, now including maintainer input on design direction.
