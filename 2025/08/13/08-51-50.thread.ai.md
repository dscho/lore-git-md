git stash --only-unstaged feature proposal to improve commit-splitting workflows during interactive rebases. Original motivation: need to test staged changes while temporarily setting aside unstaged changes, with current --keep-index solution proving insufficient due to conflicts during pop operations. D. Ben Knoble's analysis showed conflicts stem from working tree state in both stash commits, motivating a new stash format that excludes index state entirely.

Phillip Wood contributes an interim shell script solution demonstrating safe restoration of only unstaged changes from a --keep-index stash. The script uses git merge-tree with stash's index state as merge base to isolate unstaged changes via three-way merge between HEAD, stashed index, and stashed worktree. Implementation creates temporary index file to preserve real index state until conflicts resolved, handling most conflict-free cases automatically while properly reporting adjacent line modifications. Wood suggests this approach could evolve into a proper --unstaged option for git stash pop.

Open questions remain about whether the new behavior should complement or replace --keep-index, per Junio Hamano's earlier concerns. The script provides concrete validation of technical feasibility while the core feature is debated, with its architecture potentially informing the built-in solution. Implementation considerations must still address backward compatibility with existing stash operations while supporting index-less stash entries. The thread shows active progress toward solving the core workflow pain point in interactive rebase testing scenarios.
