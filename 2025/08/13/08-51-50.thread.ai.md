git stash --only-unstaged feature proposal to improve commit-splitting workflows during interactive rebases. Author describes a common scenario needing to test staged changes (for earlier commit) while temporarily setting aside unstaged changes (for later commit). Current solutions like --keep-index still store index in stash, causing potential conflicts when popping later. Proposed --only-unstaged would create stash entries containing only working tree changes, leaving index untouched in both working directory and stash object.

Technical details: addresses stash object format (currently always includes index state) and interaction with git stash pop. Suggested flag name is --only-unstaged as a git stash push sub-option. Use case centers around interactive rebase workflows where commit splitting requires testing intermediate states without disturbing pending changes.

Proposal appears well-motivated by concrete workflow pain point, offering clean solution that doesn't conflict with existing stash behavior. Author notes no existing command provides this exact functionality, suggesting genuine gap in Git's tooling. Invites discussion about prior consideration and potential implementation interest.
