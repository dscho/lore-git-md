This is a bugfix patch in Patrick Steinhardt's reftable series, addressing error handling in the file locking interface. The patch simplifies error propagation by removing fragile assumptions about `errno` values and instead having the `flock` subsystem directly return standardized reftable error codes (`REFTABLE_LOCK_ERROR` and `REFTABLE_IO_ERROR`).

The changes clean up redundant error code translation in `reftable/stack.c` that was previously converting `errno` values, and ensures the `flock_acquire()` implementation in `reftable/system.c` consistently returns the right error codes. Justin Tobler notes this is an improvement while also spotting a pre-existing typo ("Retrun") in the documentation that could be fixed.

This appears to be a straightforward quality-of-life improvement that makes the error handling more robust and maintainable. It fits well with the series' ongoing work to standardize error handling and prepare the reftable code for libgit2 integration. The patch is small (31 lines removed, 12 added) and focused, touching only the error handling paths without changing any core functionality.
