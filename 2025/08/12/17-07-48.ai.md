This is a post-merge discussion thread about documentation command recommendations, specifically regarding the use of `git checkout` versus `git switch` in rebase examples.

The discussion continues from earlier exchanges about Julia Evans' documentation improvement series for `git-rebase`. While the main series has been merged, this thread provides additional technical rationale for keeping `git checkout` in the examples rather than switching to `git switch`. 

D. Ben Knoble reinforces Junio Hamano's earlier position that `git checkout` remains preferable in this context because the rebase target (referred to as `topic` in the example) could technically be any commit-ish, not just a branch name. While `git switch` requires `--detach` for non-branch arguments, `git checkout` handles this case naturally. The discussion highlights how implementation details of these commands affect documentation recommendations, even when the example text specifically mentions a branch context.

This exchange serves as documentation of the decision-making process, showing how technical constraints (the behavior of `git switch` with detached HEADs) influence documentation choices even when newer commands like `git switch` might seem preferable at first glance. The thread confirms the project's consensus on maintaining `git checkout` in these examples while providing useful context for future documentation maintainers.
