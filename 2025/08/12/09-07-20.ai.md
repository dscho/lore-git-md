This is a post-merge discussion thread about documentation wording in the recently merged git-rebase man page improvements. The thread had previously settled on using `git checkout` rather than `git switch` in examples, following Junio Hamano's technical rationale that `checkout` handles detached HEAD states more straightforwardly.

Karthik Nayak revisits this decision with a minor suggestion to use `git switch` instead, since the example specifically mentions a branch name (`topic`) rather than a commit-ish. Phillip Wood responds by reiterating Junio's earlier position, noting that even though the example uses a branch name, `git switch` performs additional checks that don't align with rebase's behavior, making `checkout` technically more accurate. Karthik acknowledges the point while maintaining that either approach would be acceptable.

The exchange demonstrates ongoing attention to command recommendation consistency across Git's man pages, particularly around the transition from `checkout` to `switch`. The discussion remains collegial and doesn't reopen any substantive issues from the merged series, serving instead as a minor clarification of the rationale behind the final documentation wording.
