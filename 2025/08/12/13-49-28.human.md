This is the final patch in Julia Evans' documentation improvement series for the git-rebase man page, focusing on refining the explanation of rebase internals. The patch significantly restructures the technical description of how rebase works under the hood, making it clearer and more concise while maintaining accuracy.

The key changes include:
1. Reorganizing the internals explanation into a clear 5-step numbered list showing the rebase process from commit selection to final branch update
2. Removing redundant explanations about `--fork-point` and `--root` (now properly referenced in the OPTIONS section)
3. Consolidating the commit-skipping behavior description into a single bullet point and removing the ASCII-art diagram
4. Moving all `ORIG_HEAD` discussion into a NOTE section with clearer warnings about its volatility during rebase

This completes the series that has systematically improved the rebase documentation's structure and clarity. The changes reflect Junio Hamano's technical review feedback from earlier in the thread, particularly around making the multi-step nature of rebase more explicit. The patch maintains the project's preference for using `git checkout` in examples rather than `git switch` for detached HEAD operations, a decision that was confirmed in post-merge discussion.

The result is a more navigable and technically precise rebase man page that better serves both new users trying to understand the command and experienced users looking for implementation details.
