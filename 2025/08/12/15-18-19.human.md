This is a feature proposal for Git's signing functionality. Andrea Pappacoda suggests adding configuration options to allow using different signing methods (SSH vs OpenPGP) for commits versus tags, which isn't currently possible in Git.

The proposal suggests introducing new configuration knobs like `commit.gpg.format` and `tag.gpg.format` (or alternatively namespaced as `gpg.tag.format`) to specify different signing formats for each operation. This would complement the existing `commit.gpgSign` and `tag.gpgSign` options that currently control whether signing happens at all.

The motivation appears to be practical workflow needs - some users might prefer SSH keys for commit signing (which Git recently gained support for) while still using OpenPGP for tags. The proposal is straightforward and well-articulated, though it doesn't provide concrete use cases or discuss potential implementation challenges.

This seems like a reasonable quality-of-life improvement that would give users more flexibility in their signing workflows. The change would be purely additive and backward-compatible. The mailing list discussion will likely focus on the exact configuration syntax and whether there are any hidden complexities in supporting different signing formats for different operations.
