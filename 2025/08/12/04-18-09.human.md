Bugfix patch addressing compiler warnings in reftable stack initialization. Carlo Arenas responds to Patrick Steinhardt's discussion about compiler compatibility in the reftable/libgit2 series, suggesting an alternative approach to initializing structs that avoids both older C and C++ compiler warnings.

The proposed solution replaces a macro-based zero initialization with either a static const empty struct or explicit memset(), which should work across all compilers without warnings. This addresses the specific case in `reftable/stack.c` where `REFTABLE_ADDITION_INIT` was causing issues.

The email continues the thread's broader discussion about how to handle toolchain differences between Git and libgit2, though this particular suggestion focuses narrowly on the technical solution rather than the architectural debate about shim layers. The change appears straightforward and well-motivated, though it would need to be evaluated against the series' other compatibility considerations.
