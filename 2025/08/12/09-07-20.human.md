This is a post-merge discussion thread about documentation improvements to `git-rebase`.

Karthik Nayak follows up on a previously merged patch series that restructured the `git-rebase` man page, suggesting that the examples should use `git switch` rather than `git checkout` now that `git switch` is no longer experimental. Phillip Wood points out that Junio Hamano had already expressed a preference for keeping `git checkout` in these examples, since rebase can work with commit-ish values (not just branch names) and `git switch` requires extra flags in those cases. Karthik acknowledges the point but notes that since the example specifically mentions a branch name, `git switch` would still be appropriate here.

The exchange is brief and collegial, with both participants recognizing the technical merits of each approach. This appears to be a minor stylistic discussion that doesn't require any changes to the already-merged documentation, as the original decision to use `git checkout` was intentional and well-considered. The thread demonstrates the ongoing attention to detail in Git's documentation, even after patches have been merged.
