This is a feature patch series (v5) that enhances `git send-email` with IMAP integration, building on the v4 implementation that was technically complete but needed minor documentation adjustments. The series now avoids using `-[no-]parameter` syntax in response to Junio's earlier feedback about boolean flag documentation standards.

The first patch adds SMTP+IMAP hybrid functionality, allowing copies of sent emails to be archived in a specified IMAP folder (useful for providers like iCloud that don't support SMTP-based sent mail archiving). The second patch implements pure-IMAP mode where emails are only archived without SMTP transmission, useful for creating drafts to be sent later via another client.

Key technical changes in v5 include:
- Removal of `-[no-]` prefix from parameters in documentation
- Preservation of the `imap-sent-folder` terminology established in v3
- Continued support for Bcc header preservation in archive copies
- Dry-run protection remains intact
- The pure-IMAP mode still requires explicit folder specification

The thread history shows this has evolved through multiple rounds of review, with v4 having addressed all major technical concerns (dry-run behavior, documentation format, naming). The v5 change appears to be a final polish of the boolean flag documentation rather than introducing new functionality. The series seems ready for merging, having incorporated all requested changes from maintainers while maintaining the dual workflow approach (SMTP+archive and pure-IMAP) that provides clear value for different use cases.
