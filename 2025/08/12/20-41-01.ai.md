Maintainer feedback on git-add documentation simplification. This is Junio Hamano's review of the first patch in Julia Evans' series, which proposes removing detailed options from the SYNOPSIS section of git-add's man page.

The review acknowledges the simplification approach may work well for `git add` since it has a single mode of operation, but cautions this wouldn't generalize well to commands with multiple modes like `git branch`. Hamano references test t0450 which aims to align `-h` output with man page SYNOPSIS, suggesting this as context for future standardization efforts.

Key technical points raised:
- Notes the value of option grouping cues for showing mutual exclusivity
- Suggests alternative simplification approaches like line folding and short-option-only notation
- Points to `git-commit.adoc` as a better model for SYNOPSIS formatting
- Highlights the tension between new user accessibility and experienced user efficiency

The feedback maintains the patch's focus on documentation structure while surfacing deeper considerations about command interface consistency across Git. Hamano's comments suggest the change might be acceptable for git-add specifically but would need more careful consideration if applied as a broader documentation pattern. The review doesn't reject the approach outright but invites reflection on balancing competing documentation needs.
