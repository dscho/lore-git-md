This is a post-merge discussion thread about documentation command recommendations, specifically regarding the use of `git checkout` versus `git switch` in rebase examples.

The discussion follows up on Julia Evans' recently merged documentation improvement series for `git-rebase`. While the series itself is already finalized, Karthik Nayak raised a question about whether the examples should be updated to use `git switch` instead of `git checkout`, now that `git switch` is no longer experimental. 

Phillip Wood points out that Junio Hamano had previously expressed a preference for keeping `git checkout` in these examples, for technical reasons: `git checkout` works more reliably with arbitrary commit-ish references (including detached HEAD states), while `git switch` requires `--detach` for non-branch references. D. Ben Knoble reinforces this position, noting that while the example shows a branch name, the underlying rebase operation could work with any commit-ish.

The discussion serves as useful documentation of the project's rationale for keeping `git checkout` in these examples, even as other parts of the documentation may transition to `git switch`. The exchange shows careful consideration of both user experience (wanting to recommend modern commands) and technical correctness (needing commands that work in all rebase scenarios).
