This is a build system patch proposing developer workflow improvements for test linting.

Junio C Hamano responds to Eric Sunshine's suggestion about local test linting by proposing a new `check-developer` make target that would run basic lint checks (including test scripts) during normal development builds when DEVELOPER=Yes is set. The patch adds this target alongside existing check targets for docs, builtins and headers.

The change would help catch portability issues in test scripts earlier in the development cycle, addressing the problem Ben Knoble encountered where CI caught unportable test code that local runs missed. Currently developers must explicitly run `make test-lint` or similar in the t/ directory, while this would make those checks automatic during normal development.

The patch is straightforward - it adds the new target and hooks it into the DEVELOPER build path. It's a small quality-of-life improvement that could help prevent portability issues from reaching CI. The implementation is conservative, keeping the existing explicit lint targets while adding this new convenience option.
