This is the final patch in Patrick Steinhardt's v2 reftable/libgit2 compatibility series, focusing on error handling during stack compaction. The patch addresses a race condition where a stack might become outdated while being compacted, by explicitly checking and failing with `REFTABLE_OUTDATED_ERROR` if the stack is no longer current.

The key change modifies `stack_compact_range()` to:
1. Check stack status via `stack_uptodate()`
2. Map positive return values (indicating outdated state) to `REFTABLE_OUTDATED_ERROR`
3. Abort compaction if the stack is outdated

Justin Tobler suggested having `stack_uptodate()` return the error directly rather than mapping it, but Patrick declines this refinement as not currently necessary. The implementation maintains the existing error handling approach while adding explicit outdated state detection.

This completes the series' technical refinements to the reftable stack implementation, particularly around initialization patterns and error handling. The patch appears focused and well-contained, though as noted in the thread summary, broader architectural discussions about Git/libgit2 compatibility boundaries remain ongoing elsewhere.
