This is a response to Jimmy Thrasibule's synthetic worktree proposal, offering a practical workaround using existing Git features. Antonio Russo shares their experience achieving similar functionality through a combination of gitignore-everything policies, sparse checkout in non-cone mode, and manual repository switching via GIT_DIR/GIT_WORK_TREE environment variables.

The workaround comes with notable limitations: it requires force-adding all files and lacks the proposed layer prioritization system. Antonio acknowledges the approach is "janky" but presents it as a stopgap solution for those needing similar functionality today. They also suggest ostree as a potentially relevant technology for this use case, though they don't explore that connection in depth.

The response doesn't engage with the core design challenges of the synthetic worktree proposal (conflict resolution, tracking preservation) but provides useful real-world context about how developers are currently solving similar problems with existing tools. This could inform future discussion about whether a native Git solution would need to support these workflows more elegantly.
