Feature proposal for configurable signing formats for commits vs tags.

Andrea Pappacoda proposes adding separate configuration options to specify different signing formats (SSH vs OpenPGP) for commits versus tags. Currently Git uses the same signing mechanism (configured via `gpg.format`) for both operations when signing is enabled via `commit.gpgSign`/`tag.gpgSign`.

The suggestion is to introduce parallel options like `commit.gpg.format` and `tag.gpg.format`, or alternatively namespace them as `gpg.commit.format`/`gpg.tag.format`. This would allow users to automatically sign commits with SSH keys while using OpenPGP for tags (or vice versa), addressing a current limitation where the same format must be used for both.

The email is an initial RFC-style proposal seeking feedback rather than a concrete implementation. No patch is attached. The author notes they are not subscribed to the list and requests to be CC'd on replies. The proposal touches on Git's signing infrastructure and configuration system, potentially requiring changes to how signing backends are selected and invoked.
