This is a refactoring patch in Patrick Steinhardt's reftable/libgit2 compatibility series (v3 4/8), addressing a compiler warning about brace initialization in older toolchains.

The patch removes the `REFTABLE_ADDITION_INIT` macro that was causing warnings when initializing nested structs with `{0}` syntax, instead moving the zero-initialization into `reftable_stack_init_addition()` via `memset()`. This change affects the `reftable_addition` struct initialization in `reftable/stack.c`.

The modification is straightforward and improves the code by:
1. Eliminating the problematic macro
2. Centralizing initialization logic in the expected initialization function
3. Maintaining the same behavior while being more compiler-friendly

The change is minimal (7 lines changed) and focused, touching only the stack.c file. It follows the project's preference for avoiding workarounds for old compilers while still fixing the immediate issue in a clean way. The patch appears well-justified and properly integrated with the existing code flow where callers already expect to use `reftable_stack_init_addition()`.
