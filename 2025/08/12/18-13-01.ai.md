Build system enhancement for developer workflow. This email from Eric Sunshine responds to Junio C Hamano's proposal for integrating test linting into the developer build workflow. The discussion focuses on naming and visibility of the new make target that would run various lint checks (including test-lint in the t/ directory) as part of regular builds when DEVELOPER=Yes is set.

Eric agrees with the general approach but suggests the name "check-sanity" might be more intuitive than "check-developer", though acknowledges the latter may better convey the target's purpose. He notes the checks shouldn't necessarily be hidden behind DEVELOPER=Yes. This continues the thread's theme of improving developer experience around test infrastructure while maintaining existing functionality.

Key technical details under discussion:
- Proposed make target names ("check-developer" vs "check-sanity")
- Whether to gate the checks behind DEVELOPER=Yes
- The composition of checks (test-lint, check-docs, check-builtins, etc.)
- Integration with the existing build system via config.mak.dev

This email doesn't introduce new technical changes but provides naming feedback on Junio's build system proposal while reinforcing the thread's focus on developer workflow improvements around test infrastructure.
