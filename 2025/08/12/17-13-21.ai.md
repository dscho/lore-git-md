This is a technical discussion about test infrastructure linting behavior, specifically around environment variable handling in test scripts. Eric Sunshine responds to D. Ben Knoble's question about why a shell function invocation with one-shot environment variables (`VAR=val cmd`) wasn't caught during local test runs but was flagged by CI.

The key points are:
1. The `chainlint` linter runs automatically during local test execution but doesn't catch one-shot variable assignments before shell functions
2. The `check-non-portable-shell` linter (which does catch these) only runs in CI because it requires a two-phase process:
   - First scans all scripts to build a function name table
   - Then checks individual scripts against that table
3. Eric explains this is due to technical limitations in `chainlint`'s current implementation, which only sees the single script being tested
4. He suggests this could theoretically be improved by having `chainlint` track included scripts and their functions
5. The discussion reveals an underlying goal to eventually consolidate all linting into `chainlint` for efficiency

This email provides important context about the test infrastructure's linting architecture and explains the discrepancy between local and CI test behavior that the patch author encountered. It doesn't propose any immediate changes but clarifies the system's current limitations and potential future improvements.
