This is the fifth version of a feature series adding IMAP integration to `git send-email`. The patches provide two main capabilities: archiving sent emails to an IMAP folder (useful for providers like iCloud that don't support SMTP-based sent mail archiving), and a pure-IMAP mode that creates drafts without SMTP transmission.

The v5 iteration primarily addresses documentation formatting by removing the `--[no-]` parameter syntax in favor of separate option entries, as requested in previous reviews. The core functionality remains unchanged from v4, which had already resolved the dry-run bug and completed the pure-IMAP implementation.

The series appears technically solid with thorough test coverage and clear documentation. The changes are focused on `git-send-email.perl` and `imap-send.c`, introducing new config options (`sendemail.imapSentFolder`) and command-line flags (`--imap-sent-folder`). The pure-IMAP mode is particularly useful for users who want to leverage `send-email`'s formatting features while deferring actual transmission to another client.

With all previous feedback addressed and no outstanding technical issues, this version seems ready for final review. The feature fills a clear gap for users of IMAP-based mail providers while maintaining compatibility with existing SMTP workflows.
