The second patch in Aditya Garg's v5 series implements the pure-IMAP mode for `git send-email`, allowing users to archive formatted emails to an IMAP folder without SMTP transmission. This completes the dual-workflow functionality introduced in earlier versions, with all technical and documentation issues now resolved.

Key technical additions in this patch:
- Introduces `--use-imap-only` flag and `sendemail.useImapOnly` config to enable pure-IMAP archiving
- Requires `imap-sent-folder` to be set when in pure-IMAP mode (validated at runtime)
- Preserves all `send-email` formatting features (Cc list manipulation, cover letters) while bypassing SMTP
- Maintains dry-run safety by skipping IMAP operations during `--dry-run`
- Updates documentation with proper backtick formatting for `--smtp-encryption` reference

The implementation routes messages through `git imap-send` when the pure-IMAP mode is active, while keeping the existing SMTP+archive workflow available. The error handling ensures users must explicitly configure the destination folder when opting for pure-IMAP operation. Documentation follows project standards with separate `--option`/`--no-option` entries and proper boolean flag syntax.

This patch represents the final functional piece of the series, complementing the SMTP+archive mode from earlier versions. With all technical concerns addressed and documentation properly formatted per Junio's earlier feedback, the series appears technically complete and ready for integration.
