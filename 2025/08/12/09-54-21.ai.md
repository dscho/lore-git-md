This is part 7/8 of Patrick Steinhardt's reftable/libgit2 compatibility series, focusing on error handling improvements in the flock interface. The patch simplifies error handling by having the flock subsystem directly return reftable-specific error codes rather than relying on errno values, which makes the interface more robust and self-documenting.

The key changes include:
1. Removing errno-based error translation in stack.c (multiple locations) and having callers trust the error codes returned by flock_acquire()
2. Updating system.c to return REFTABLE_IO_ERROR directly when appropriate
3. Documenting in system.h that REFTABLE_LOCK_ERROR should be returned for locked paths
4. Simplifying the error handling logic in stack_compact_range() to work directly with the returned error codes

The changes are relatively small (12 insertions, 31 deletions) but improve the robustness of the locking interface by making error handling more consistent and explicit. This continues the series' theme of strengthening error handling and interface contracts while removing implementation assumptions that could cause problems for libgit2 integration. The patch appears well-contained and focused, with clear documentation of the expected behavior.
