Here's a human-readable thread summary:

Andrea Pappacoda has proposed allowing different signing formats (SSH vs OpenPGP) to be configured separately for commits and tags. Currently, Git uses the same signing mechanism (set via `gpg.format`) for both operations when signing is enabled through `commit.gpgSign` or `tag.gpgSign`. The suggestion is to add new configuration options - either as parallel settings (`commit.gpg.format` and `tag.gpg.format`) or namespaced under `gpg` (`gpg.commit.format`/`gpg.tag.format`).

This change would let users automatically sign commits with SSH keys while using OpenPGP for tags (or vice versa), addressing a current limitation where the same format must be used for both operations. The proposal is currently at the RFC stage, with no implementation yet attached, and the author is seeking feedback from the community. Andrea notes they aren't subscribed to the mailing list and requests to be CC'd on any replies. The change would involve Git's signing infrastructure and configuration system, potentially requiring modifications to how signing backends are selected and called.
