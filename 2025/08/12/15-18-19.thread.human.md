Andrea Pappacoda has proposed allowing Git to use different signing formats (SSH vs OpenPGP) for commits versus tags, which currently must use the same `gpg.format` setting. The initial RFC suggested new configuration options to decouple these choices, enabling workflows like SSH-signed commits with PGP-signed tags without manual switching. The proposal touches Git's signing infrastructure and configuration system but hasn't yet included an implementation.

Brian m. carlson has now responded, engaging with the technical merits while raising important practical considerations. He suggests a temporary workaround using Git aliases and requests clarification on the motivating use case, noting this appears to be a novel request. His response thoughtfully examines implementation challenges around backward compatibility (proposing new options should default to existing values) and verification complexity, since verification occurs more frequently than signing and would require configuration awareness from all verifiers. The discussion continues to explore whether decoupling commit and tag signing formats is viable while maintaining reliable verification, with open questions remaining about signature autodetection and potential configuration burdens.
