This is a continuation of the build system discussion around developer workflow improvements, specifically focusing on the integration of lint checks into the build process. Eric Sunshine responds to Junio C Hamano's proposal to include `check-developer` as part of the `all` target when `DEVELOPER=Yes` is set.

Eric acknowledges he initially misread Junio's proposal, thinking the target was only defined (not automatically run) under DEVELOPER mode. He now sees the actual implementation wires it into `all::` when DEVELOPER is enabled. While Eric previously suggested these checks shouldn't be DEVELOPER-gated, he now considers that making them part of `all` might be too aggressive, especially for early-stage development where skeletal implementations aren't yet ready for full linting.

The email highlights two key tensions in the build system design: (1) whether lint checks should run automatically during development (potentially interrupting workflow) versus being opt-in, and (2) whether documenting the checks in SubmittingPatches might be preferable to automatic enforcement. The discussion remains focused on finding the right balance between catching issues early and maintaining developer productivity.
