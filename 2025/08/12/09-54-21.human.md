This is part 7/8 of Patrick Steinhardt's series improving reftable/libgit2 compatibility, focusing on error handling in the file locking subsystem. The patch simplifies error handling from the `flock` interface by having it directly return reftable-specific error codes rather than relying on `errno` values.

The changes make the fragile assumption that callers can check `errno` for specific values like `EEXIST`, replacing it with explicit `REFTABLE_LOCK_ERROR` and `REFTABLE_IO_ERROR` returns. The implementation in `system.c` is updated to match this new contract, and the documentation in `system.h` is clarified to specify the expected error codes.

This appears to be a straightforward improvement that makes the interface more robust and self-documenting. The changes are focused and well-contained, touching just 3 files with mostly removal of error-handling boilerplate. As part of the larger series preparing reftable for libgit2 integration, this helps ensure consistent error handling across different implementations of the locking interface.
