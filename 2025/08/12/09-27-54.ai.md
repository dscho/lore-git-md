This is a technical refinement in Patrick Steinhardt's reftable/libgit2 compatibility series, specifically addressing flag handling in the stack implementation. The patch allows passing flags to `reftable_stack_add()`, with particular focus on the `REFTABLE_STACK_NEW_ADDITION_RELOAD` flag that enables stack reloading before locking.

The discussion reveals that while Git's current usage patterns don't expose the need for this flag (as it uses `reftable_stack_new_addition()` directly), there are code paths where passing this flag would be more correct. Patrick acknowledges this could be fixed now, though the series currently focuses on library improvements rather than backend changes.

The change is relatively contained (modifying initialization in stack.c) and builds on previous work in the series to improve reftable stack handling. It maintains compatibility between Git and libgit2 while providing more flexible control over stack operations. The implementation appears technically sound, though Patrick notes there's room to extend the flag usage to more Git code paths in the future.

Key technical details include:
- Added `flags` parameter to `stack_try_add()`
- Modified initialization to pass flags through to `reftable_stack_init_addition()`
- Specific flag `REFTABLE_STACK_NEW_ADDITION_RELOAD` enables pre-lock stack reloading
- Changes are backward compatible with existing callers

This continues the series' pattern of making targeted, pragmatic improvements to the shared reftable code while leaving broader architectural questions about Git/libgit2 compatibility boundaries for later discussion.
