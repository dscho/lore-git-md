This is a refactoring patch in Patrick Steinhardt's reftable/libgit2 compatibility series (v3, 2/8). The change removes Git-specific `QSORT()` macro usage from the reftable writer in favor of standard `qsort()`, improving portability for libgit2 integration.

The patch modifies two functions in `reftable/writer.c` that sort ref and log records before writing them to the reftable. While `QSORT()` is a Git convenience wrapper that automatically determines element size, the standard `qsort()` requires explicit size parameters. The change adds a null check (`if (n)`) before sorting, which wasn't present in the original macro usage - this appears to be a defensive improvement rather than a direct requirement of the switch.

The technical impact is localized to the writer implementation, with no behavioral changes expected. The modification aligns with the series' goal of making reftable usable outside Git's codebase by removing Git-specific dependencies. The change is mechanical and straightforward, with clear motivation stated in the commit message. This appears to be a low-risk adjustment that maintains existing functionality while improving code portability.
