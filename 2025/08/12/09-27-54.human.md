This is a technical refinement in Patrick Steinhardt's reftable/libgit2 compatibility series, specifically addressing stack initialization behavior. Patrick acknowledges that Git should likely adopt this flag in some currently-unmodified code paths, as the verification already happens under lock anyway. While the series primarily focuses on library improvements rather than backend changes, he notes there's no strong reason to defer these Git-side updates.

The change appears straightforward - adding a flags parameter to `stack_try_add()` and passing it through to `reftable_stack_init_addition()`.
