Thread summary:

Andrea Pappacoda's RFC proposes decoupling signing formats (SSH vs OpenPGP) between commits and tags through new configuration options (`commit.gpg.format`/`tag.gpg.format` or similar), currently constrained by a single `gpg.format` setting. The initial technical discussion focuses on configuration namespace design and backend selection changes. Brian m. carlson's response engages with the proposal while raising implementation considerations: (1) backward compatibility (new options should default to existing `gpg.format`), (2) verification complexity (signature autodetection needs and configuration awareness for verifiers), and (3) requests clarification on the motivating use case as this appears novel. A temporary alias-based workaround is suggested. Key open questions include preferred configuration syntax, verification workflow impacts, and whether the feature warrants a new signing backend abstraction layer. The thread remains in exploratory phase with no implementation yet proposed; technical discussion centers on balancing flexibility against verification reliability and configuration burden.
