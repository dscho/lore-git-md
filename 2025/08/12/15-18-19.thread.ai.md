Thread summary:

Andrea Pappacoda proposes configurable signing formats (SSH vs OpenPGP) for commits versus tags, currently constrained to use the same `gpg.format` setting. The RFC suggests new options like `commit.gpg.format`/`tag.gpg.format` or `gpg.commit.format`/`gpg.tag.format` to decouple these choices. This would enable use cases like SSH-signed commits with PGP-signed tags without manual format switching. The proposal targets Git's signing infrastructure and configuration system, requiring backend selection changes. No implementation yet provided; author requests CC on replies as they're not list-subscribed. Key technical points: signing format divergence between commit/tag operations, configuration namespace design options, and potential interaction with existing `gpg.program`/`gpg.ssh.defaultKeyCommand` settings. Open questions include preferred configuration syntax and whether this warrants a new signing backend abstraction layer.
