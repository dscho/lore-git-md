This is a feature proposal for a new "synthetic worktree" capability in Git. Jimmy Thrasibule suggests creating a single worktree that can overlay files from multiple Git repositories (or refs) without subfolder separation, while maintaining independent version control for each source repository.

The proposal draws inspiration from OverlayFS, allowing files from different repositories to coexist in one directory structure. Key use cases mentioned include vendoring dependencies and managing patch sets with tools like Quilt. The suggested CLI interface would let users push/pop different repository contents to the top of the overlay stack, with Git commands automatically applying to whichever repository is currently "on top."

The concept appears well-motivated for workflows involving multiple interdependent projects, though the implementation details and potential edge cases (like handling file conflicts between repositories) aren't fully explored. The proposal is at an early stage, presenting the core idea without a concrete implementation plan or patch series. This could spark interesting discussion about Git's worktree model and how it might better support composite workspaces.
