This is the first patch in a 2-part series implementing IMAP-based sent mail archiving for `git send-email`. The patch adds the core functionality to archive sent emails to an IMAP folder after SMTP transmission completes, addressing cases where email providers like iCloud Mail don't automatically save SMTP-sent messages to the Sent folder.

The implementation introduces a new `sendemail.imapSentFolder` config option and `--imap-sent-folder` CLI parameter to specify the target IMAP folder. Messages are archived via `git imap-send` after SMTP transmission completes, with Bcc headers preserved in the archive copy (though not in the original SMTP transmission). The patch modifies both `git-send-email.perl` (adding the archiving logic and new option handling) and `imap-send.c` (adjusting message parsing to handle the `git-send-email` format).

Key technical details:
- Archive operation occurs after successful SMTP transmission
- Bcc headers are included in archive copies but not original SMTP messages
- Uses existing `git imap-send` infrastructure
- Dry-run mode properly skips IMAP operations
- Documentation covers both config and CLI options

The patch appears well-structured with clear commit message explaining the motivation (iCloud Mail limitation) and thorough documentation updates. The implementation handles edge cases like dry-run mode and preserves privacy-sensitive headers appropriately. This provides a clean solution to the stated problem while maintaining existing SMTP workflow compatibility.
