This is the fourth patch in Julia Evans' documentation series for `git-add`, continuing the effort to make the man page more approachable while maintaining technical accuracy.

The patch focuses on making the explanation of how `git add` works less abstract by introducing concrete examples and practical commands. It replaces a somewhat dry procedural explanation with a more direct example showing what happens when you edit a file after adding it. The patch also adds references to `git diff --staged` as a way to inspect staged changes, linking to the `git-diff` man page, which wasn't previously mentioned in the SEE ALSO section.

Key changes include:
- Replacing abstract "content of specified files" language with a concrete `file.c` example
- Adding `git diff --staged` as an inspection tool alongside `git status`
- Including `git-diff` in SEE ALSO
- Maintaining the same technical information while making it more actionable

The changes are small (7 insertions, 6 deletions) but meaningful for readability. This continues the series' pattern of improving accessibility without sacrificing accuracy, though it doesn't address any of the open questions from earlier patches about terminology or SYNOPSIS structure. The patch stands alone well but clearly fits into the broader series goal of making `git-add` documentation more beginner-friendly.
