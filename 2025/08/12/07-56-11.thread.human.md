Jimmy Thrasibule has proposed a novel "synthetic worktree" feature that would allow files from multiple Git repositories to be combined in a single worktree view while maintaining independent version control. The proposal introduces new commands (`git worktree push/pop/top`) inspired by OverlayFS, with use cases ranging from dependency management to patch workflows. Key challenges include conflict resolution and maintaining repository independence.

Antonio Russo has responded with a practical workaround using existing Git features: combining sparse checkout (non-cone mode) with gitignore-everything and manual GIT_DIR manipulation. While this achieves some of the desired functionality, it comes with notable limitations - particularly the need for force-adding files and the lack of layer prioritization. Antonio also mentions ostree as a potentially related system, though the connection remains unexplored. This response demonstrates real-world demand for such functionality while highlighting gaps in current tooling that a proper implementation would need to address.
