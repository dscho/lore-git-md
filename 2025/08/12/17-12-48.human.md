This is a bugfix patch in Patrick Steinhardt's reftable series, addressing race conditions in stack operations. The patch standardizes the use of `REFTABLE_STACK_NEW_ADDITION_RELOAD` across all stack modification operations in the reftable backend, ensuring consistent handling of concurrent writes.

The key change makes stack reloads automatic when acquiring locks, eliminating a race window where concurrent modifications could cause operations to fail unnecessarily. Justin Tobler confirms the patch looks good, noting it also fixes an ordering issue in reflog expiration where the lock was previously acquired too late.

The changes affect several operations including ref updates, reflog creation/deletion, and reflog expiration. The patch removes one redundant manual reload since the flag now handles that automatically. This continues the series' focus on making reftable operations more robust against races while maintaining data consistency.
