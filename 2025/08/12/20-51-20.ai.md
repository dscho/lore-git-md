Documentation patch series follow-up regarding terminology clarification. This is a reply to Julia Evans' v1 series improving the `git-add` man page, specifically addressing the new TERMINOLOGY NOTE section in patch 5/5.

Chris Torek points out an important exception to the general rule that `--staged`, `--index`, and `--cached` flags all refer to the index. The `git apply` command is noted as the sole exception where `--index` and `--cached` have distinct meanings - `--index` updates both the working tree and index while `--cached` updates only the index. This nuance isn't captured in the current terminology note.

The observation introduces a potential refinement needed for the documentation's accuracy, as the current wording might mislead readers about `git apply`'s behavior. The exception is significant because it's the only known case where these flags diverge in meaning across Git commands. This feedback comes after maintainer Junio Hamano's earlier review of the series' SYNOPSIS simplification approach.

The thread context shows this is the final patch in a complete v1 series that has already addressed several documentation issues around terminology consistency and beginner accessibility. The series includes structural reorganization, concrete examples, and now this terminology clarification section. Chris's input suggests the need to either qualify the general rule or explicitly call out `git apply` as an exception.
