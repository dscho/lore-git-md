This is a CI/build system patch from Junio C Hamano proposing to add developer-focused lint checks during regular builds. The email responds to Eric Sunshine's suggestion about local lint checking by proposing to make `test-lint` run automatically during development builds when `DEVELOPER=Yes` is set.

The patch adds a new `check-developer` target that runs several verification steps including `check-tests` (which runs `test-lint` in the t/ directory). This would help catch shell syntax issues earlier in development without requiring explicit `make test-lint` invocations. The change is implemented by adding the new target to the `all` rule when in developer mode.

Key technical details:
- New `check-developer` target runs `check-docs`, `check-tests`, `check-builtins`, and `check-headers`
- `check-tests` target runs `test-lint` in the t/ directory
- Hooked into developer builds via `all:: check-developer` in the DEVELOPER section
- Currently leaves `make check` unchanged but notes it could be repurposed
- Maintains existing `test-lint` behavior while making it more discoverable

This builds on the ongoing discussion about test infrastructure improvements and linting, providing a more integrated developer experience. The change is relatively straightforward and non-controversial, addressing a workflow pain point identified in the thread. The implementation preserves all existing functionality while adding the new convenience feature.
