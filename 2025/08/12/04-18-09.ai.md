This is a platform compatibility patch in Patrick Steinhardt's reftable/libgit2 series, addressing compiler warnings about initialization syntax. Carlo Arenas responds to the ongoing discussion about how to handle initialization differences between C and C++ compilers, suggesting an alternative approach to the current `{0}` initialization pattern.

The email proposes replacing the macro-based initialization with either a static zero-initialized struct or explicit `memset()`, which would avoid both the C90 compatibility issues and C++ warnings. The change would affect `reftable_addition` initialization in stack.c, removing the `REFTABLE_ADDITION_INIT` macro entirely. This builds on Junio Hamano's earlier suggestion about using a shim layer for such compatibility cases, though Patrick had previously argued against overusing shims for minor syntax differences.

Key technical elements include the removal of `REFTABLE_ADDITION_INIT` macro and replacement with either static zero initialization (for `reftable_stack_new_addition`) or `memset()` (for `stack_try_add`). The patch continues the thread's theme of balancing Git's modern practices with libgit2's need for broader compiler compatibility, though this particular suggestion hasn't yet been discussed in terms of performance implications of `memset()` versus static initialization.
