This is the final patch in Patrick Steinhardt's reftable/libgit2 compatibility series (v3 8/8), focusing on atomic stack modifications and error handling. The patch completes the transition to using `REFTABLE_STACK_NEW_ADDITION_RELOAD` across all operations that modify the reftable stack, ensuring consistent handling of concurrent writes.

Key changes include:
1. Removing a redundant manual stack reload in `prepare_transaction_update()` since `reftable_stack_new_addition()` now handles this
2. Adding the reload flag to all remaining operations (`rename_ref`, `copy_ref`, `create_reflog`, `delete_reflog`)
3. Fixing a race condition in `reflog_expire` by reordering operations to acquire the lock before initializing the log iterator

The changes affect `refs/reftable-backend.c` with 12 lines added and 11 removed. Justin Tobler reviewed the patch positively, noting the corrected operation ordering in reflog expiration. This completes the series' work on atomic stack modifications, with all changes now using the standardized error handling approach introduced earlier in the series.

The patch maintains the series' focus on production-ready reftable support while improving the user experience by reducing unnecessary bailouts from concurrent writes.
