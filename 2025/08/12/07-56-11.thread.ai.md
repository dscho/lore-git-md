new feature proposal for "synthetic worktree" capability from Jimmy Thrasibule. Concept would combine files from multiple Git repositories into a single worktree view while maintaining independent version control per source repository. Inspired by OverlayFS, with proposed commands `git worktree push`, `git worktree top`, `git worktree pop` to manage layered repositories. Key challenges identified: file conflict resolution, maintaining Git tracking across synthetic view while preserving source repository independence, clean removal of files when repositories are removed from stack. Potential use cases include vendoring dependencies and Quilt-style patch management. No prior discussion found; this appears to be a novel proposal that would require significant design discussion around implementation details and edge cases before implementation could be considered.
