This is a bugfix patch in Patrick Steinhardt's reftable/libgit2 compatibility series, focusing on error handling in the file locking subsystem. The patch simplifies error propagation by removing fragile errno-based error code translation in favor of direct reftable error codes from the flock implementation.

The changes center around the `flock_acquire()` interface in reftable/stack.c, where it's called for various locking operations. Previously, callers would examine errno` to distinguish between lock conflicts (EEXIST) and other I/O errors, converting them to REFTABLE_LOCK_ERROR and REFTABLE_IO_ERROR respectively. The new approach makes the flock implementation responsible for returning the correct error codes directly.

Key technical changes include:
- Removal of errno checks in stack.c callers of flock_acquire()
- Standardization on REFTABLE_IO_ERROR for non-EEXIST failures in system.c
- Documentation update in system.h clarifying expected error returns
- Special handling preserved for STACK_COMPACT_RANGE_BEST_EFFORT cases

The patch maintains consistency with the series' focus on robust error handling and atomic operations, though it's a relatively small and focused change compared to earlier patches in the sequence. Justin Tobler notes the improvement in error handling while spotting a pre-existing typo ("Retrun") in the documentation that could be fixed.
