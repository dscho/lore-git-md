This is part 6/8 of Patrick Steinhardt's reftable/libgit2 compatibility series, focusing on error handling improvements during stack compaction operations.

The patch addresses a subtle issue in the reftable stack's compaction logic where positive return values from `stack_uptodate()` (indicating an outdated stack) weren't being properly handled. The fix ensures these cases are translated to `REFTABLE_OUTDATED_ERROR` for consistent error handling. The changes affect two key areas:

1. The `reftable_addition_commit()` function now explicitly handles `REFTABLE_OUTDATED_ERROR` as a benign condition during auto-compaction, similar to how it already treated `REFTABLE_LOCK_ERROR`.

2. The `stack_compact_range()` function now properly aborts compaction when detecting an outdated stack by converting positive `stack_uptodate()` returns to `REFTABLE_OUTDATED_ERROR`. The patch includes improved documentation for `stack_uptodate()` to clarify its return value semantics (0=up-to-date, 1=outdated, negative=error).

This change strengthens the reftable stack's handling of concurrent modifications while maintaining backward compatibility. The implementation follows the series' pattern of careful error handling and explicit state management, with clear documentation of the behavior changes. The patch touches only `reftable/stack.c` with a 26-line addition and 6-line deletion, focused specifically on the error handling paths.
