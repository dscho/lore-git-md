Documentation patch continuing the `git-add` man page improvements series, focusing on making the introductory section more accessible to beginners. This is the second of five patches in Julia Evans' series.

The patch replaces the technical description of the index with a practical example showing how to add a changed file (`file.c`) and commit it. It also adds a mention of partial staging with `git add -p`. The changes shift from explaining Git's snapshot model to focusing on the diff-based workflow that users typically encounter through `git diff` and `git status`. The terminology is adjusted to consistently use "index" and "staging area" together.

Key technical changes include:
- New introductory example showing basic `git add`/`git commit` workflow
- Removal of snapshot-based explanation of the index
- Added reference to `git add -p` for partial staging
- Changed description from "file contents" to "new or changed files"
- Moved `git-commit` reference closer to the example
- Lines changed: +14/-17 in Documentation/git-add.adoc
- Follows the SYNOPSIS simplification from patch 1
- Prepares for further examples and terminology work in later patches

The changes align with the series goal of making the documentation more approachable while maintaining accuracy. The patch maintains all existing technical information but presents it in a more user-friendly way, particularly for beginners who may not need to understand Git's internal snapshot model to use `git add` effectively.
