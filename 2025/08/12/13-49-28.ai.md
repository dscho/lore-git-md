Documentation patch finalizing the git-rebase internals explanation as part of Julia Evans' rebase documentation improvement series.

This fifth patch in the merged v7 series refines the technical description of how `git rebase` works internally. It reorganizes the explanation into a clearer 5-step numbered list that better reflects the actual process, particularly when using the merge backend. The changes remove redundant details that were covered elsewhere (like `--fork-point` and `--root` mechanics) and consolidate the explanation of how duplicate changes are skipped (now using `git patch-id` rather than SHA comparison).

Key technical changes include:
- Explicit step-by-step breakdown replacing the previous prose description
- Removal of the ASCII-art commit graph example showing skipped commits
- Moving all `ORIG_HEAD` discussion into a NOTE section
- More precise language about the commit selection process (using `git patch-id`)
- References to equivalent commands like `git checkout --detach` and `git checkout -B`

The patch follows through on Junio Hamano's review feedback to make the internals description both more accurate and more approachable. It maintains the series' consistency by continuing to use `git checkout` rather than `git switch` in examples, as previously established in the thread.
