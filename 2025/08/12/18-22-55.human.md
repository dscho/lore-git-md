Build system discussion on lint check naming and developer workflow.

This email continues the discussion about integrating lint checks into Git's build system, specifically addressing whether the new `check-developer` target should be gated behind the `DEVELOPER` flag. Junio C Hamano responds to Eric Sunshine's concern that the target shouldn't be hidden, explaining the rationale behind the current proposal.

The key points are:
1. The `check-developer` target is meant as a lightweight set of checks for in-progress code, not production builds
2. Junio acknowledges it might be annoying for early-stage developers to be forced to write docs before their code compiles
3. While the checks are currently part of `all` to increase visibility, Junio questions if limiting to DEVELOPER is still too restrictive

This represents a thoughtful middle ground in the naming/visibility discussion - Junio isn't fully committing to removing the DEVELOPER gate but is clearly considering Eric's feedback about developer experience. The email maintains the thread's focus on balancing thoroughness with workflow friendliness in the build system changes.
