This is a documentation patch in a completed series improving the `git-add` man page. The email provides additional context about version control mental models in response to Junio Hamano's observation that Git may now be the baseline SCM for new developers.

Julia Evans shares her experience as a long-time Git user who never used CVS/Subversion, supporting the idea that Git's model is now the default for many developers. She references an informal poll she conducted showing roughly equal split between developers thinking of commits as "snapshots" versus "diffs", noting that many respondents use both models situationally. This data point informs the ongoing documentation philosophy debate about whether to emphasize Git's internal snapshot model or present it in more diff-oriented terms that may align with user mental models.

The exchange highlights how the documentation improvements need to balance technical accuracy (Git's snapshot-based internals) with pedagogical effectiveness (how users actually conceptualize version control). Julia's response suggests that while the snapshot model is important to document, many users naturally think in terms of diffs in their workflow, supporting her approach of using concrete examples and workflow-oriented explanations in the revised man page.
