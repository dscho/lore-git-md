This is a technical refinement in Patrick Steinhardt's reftable/libgit2 compatibility series (v2 patch 6/6), addressing error handling during stack compaction.

The patch focuses on improving how the reftable stack handles outdated stacks during compaction operations. When checking if a stack is up-to-date, the code now explicitly returns a `REFTABLE_OUTDATED_ERROR` when the stack is outdated, rather than just a positive error code. This makes the error condition more specific and clear.

Justin Tobler had suggested having `stack_uptodate()` return the error directly to simplify the code, but Patrick responds that while possible, there isn't a strong enough reason to make that change at this time. The current implementation maintains consistency with existing error handling patterns.

The change is relatively small (about 15 lines) but improves error signaling in a potentially tricky edge case where a stack becomes outdated during compaction. The commit message notes this isn't a complete solution - a more robust approach would involve having callers pass specific tables to compact rather than ranges - but considers the current solution "good enough" for now.

This patch appears to be a clean, focused improvement to the reftable stack's error handling, though as with the rest of the series, it's primarily relevant for libgit2 compatibility rather than addressing immediate Git needs.
