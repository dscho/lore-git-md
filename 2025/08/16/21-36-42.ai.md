Final test patch in the submodule gitdir path encoding series. This adds comprehensive test coverage for the new path encoding scheme, exercising edge cases and verifying behavior across different scenarios:

The patch adds two new test cases to t7425-submodule-mixed-gitdir-paths.sh that systematically validate the path encoding implementation. First test verifies correct encoding of various problematic submodule names:
- Paths containing slashes (`foo/bar` -> `foo%2fbar`)
- Existing legacy paths with percent signs (`foo%bar` remains in modules/)
- New paths with percent signs (`fooish%bar` -> `fooish%25bar`)
- Mixed case names (`FooBar` -> `_foo_bar` on case-insensitive systems)
- Windows reserved names (`COM1` -> `_c_o_m1`)

Second test confirms the system enforces `NAME_MAX` limits by attempting to create a submodule with a name that would encode to exceed the filesystem's maximum filename length. The test dynamically determines `NAME_MAX` and creates an intentionally too-long name by repeating percent signs (which expand during encoding).

The tests use the series' established `verify_submodule_gitdir_path` helper to check path resolution. This completes the test coverage for the path encoding work, complementing earlier tests for nested paths and mixed legacy/new-style directories. The test cases align with the implementation's design goals of handling special characters, case sensitivity, and system limitations while maintaining backward compatibility.
