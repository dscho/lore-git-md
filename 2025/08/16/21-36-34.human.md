This is a refactoring patch in a submodule-related series, part of an effort to standardize submodule gitdir path construction.

Adrian Ratiu noticed during testing that `submodule--helper` was still using a hardcoded path construction (".git/modules/%s") rather than the centralized `submodule_name_to_gitdir()` helper function introduced in commit ce125d431a. The patch updates the `add_submodule()` function to use this helper instead.

The change is straightforward - replacing manual string formatting with the helper function and adjusting the memory management from direct `free()` calls to `strbuf_release()`. This brings consistency with how submodule paths are handled elsewhere in the codebase.

As the first patch in a 9-part series, this appears to be setting up some groundwork for subsequent changes. The commit message doesn't specify what test failures prompted this change, but the modification itself looks like a clear improvement in code organization. The patch is cleanly implemented with appropriate memory management changes.
