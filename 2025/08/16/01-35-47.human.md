This is a follow-up in the now-closed thread about Git's alias behavior, specifically regarding shell function aliases and command shadowing.

Christoph Anton Mitterer pushes back slightly on some of the maintainers' explanations from earlier in the thread. While acknowledging the thread's resolution, he questions whether the "user confusion" argument against command shadowing holds water, comparing it to other user-customizable features like shell aliases and git-config options. He also raises concerns about the potential dangers of aliases being active in scripts, noting this could lead to breakage if new built-in commands are introduced that shadow existing aliases.

The email then shifts to documentation concerns, with Mitterer suggesting the man pages could be more explicit about the shell execution environment for `!`-prefixed aliases. He asks about environment variable sanitization, shell selection (`/bin/sh` vs login shell), and whether profile/rc files are loaded - reasonable technical questions that weren't fully addressed in the earlier discussion.

While the core issue of command shadowing is settled, this email surfaces some peripheral documentation gaps about shell alias execution that might warrant clarification in the man pages, though these are unlikely to change the thread's overall resolution.
