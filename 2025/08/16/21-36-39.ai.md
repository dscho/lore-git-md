This is part 6/9 of the submodule gitdir path encoding series, implementing the core path encoding mechanism to prevent filesystem conflicts in submodule gitdir paths. The patch introduces URL-style encoding for submodule names in `.git/submodules/` paths, with special handling for case-insensitive filesystems and Windows reserved names (encoding uppercase letters as `_a`, `_b` etc.). It builds on Brandon Williams' 2018 work but uses a simpler encoding scheme than full RFC 3986 URL encoding.

Key technical changes:
- Adds `strbuf_addstr_case_encode()` helper to transform uppercase letters
- Modifies `submodule_name_to_gitdir()` to apply URL encoding followed by case encoding
- Adds path length validation against `NAME_MAX`
- Updates test expectations for encoded paths (e.g. `dirdir%2fsubsub`)
- Marks `validate_submodule_git_dir()` with a TODO for future cleanup
- Adjusts tests that previously checked for nested gitdir conflicts to now verify correct path encoding

The implementation maintains backward compatibility by keeping the config override mechanism from earlier patches. The encoding handles edge cases like Windows reserved names (COM1 etc.) and case conflicts while producing deterministic paths. The patch includes test updates across t7400, t7406 and t7450 to verify the new encoding behavior works with submodule operations like clone, update and checkout.

This is a foundational change that enables safe submodule naming while the series transitions from legacy `.git/modules/` to new `.git/submodules/` paths. The encoding approach was debated in 2018 and this implementation follows that design direction with practical adaptations for filesystem limitations.
