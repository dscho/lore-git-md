Feature implementation (final documentation refinements) for the new `git repo` command hierarchy. This v11 patch series from Lucas Seiki Oshiro addresses the last round of feedback from Junio Hamano on documentation and test formatting. The changes are minor but important for consistency with Git's conventions:

1. Standardized test output file naming to always use "expect" and "actual"
2. Improved documentation indentation and formatting, particularly for the `--format` option's description list
3. Consistently using "NUL characters" terminology instead of "null characters"
4. Repository initialization moved outside test cases for efficiency

The series maintains all the core functionality from v10 that was already merged to 'next', including:
- The new `git repo info` subcommand for querying repository metadata
- Support for both human-readable (keyvalue) and machine-readable (NUL-delimited) output formats
- Fields for checking repository layout (bare/shallow) and reference storage format

This appears to be the final polish before full integration, with all architectural decisions settled and now just ensuring the documentation matches Git's style. The changes are small but demonstrate careful attention to the project's conventions.
