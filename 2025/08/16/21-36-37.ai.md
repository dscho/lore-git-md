This is a test patch in the submodule gitdir path encoding series, specifically adding test coverage for mixed legacy and new-style submodule paths.

The patch introduces a new test script `t7425-submodule-mixed-gitdir-paths.sh` that verifies basic functionality when repositories contain both legacy `.git/modules/` paths and new `.git/submodules/` paths. The tests cover:

1. Creating a repository with both legacy and new-style submodules (simulating legacy paths by manually moving them)
2. Cloning such a repository and verifying submodules are properly initialized in the new path format
3. Making commits and pushing changes through both submodule types
4. Fetching updates and verifying the mixed paths remain functional

The test infrastructure sets up three repositories (legacy-sub, new-sub, and main) to model the transition period where both path schemes must coexist. Key assertions verify the correct path locations and commit hashes are maintained through clone, push, and pull operations.

This builds on the series' earlier work (patches 2-3) that introduced the new path scheme and config override mechanism. The test focuses on the basic compatibility layer rather than the URL encoding aspects that will come in subsequent patches. The 101-line test file establishes a foundation for more complex encoding tests to be added later.
