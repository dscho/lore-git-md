This is part 6/9 of a submodule gitdir path encoding series, implementing the core path encoding logic to prevent filesystem conflicts in submodule gitdir paths. The patch introduces URL-style encoding for submodule gitdir paths, with special handling for case-insensitive filesystems and Windows reserved filenames (like "COM1") by converting uppercase letters to "_a", "_b" etc. The implementation builds on Brandon Williams' 2018 work and uses RFC 3986 URL encoding as the base scheme.

Key changes include:
- A new `strbuf_addstr_case_encode()` helper that handles the case conversion
- Path length validation against system NAME_MAX limits
- Updates to test cases to expect encoded paths (like "dirdir%2fsubsub")
- A temporary workaround for `validate_submodule_git_dir()` that will be cleaned up later
- The patch maintains backward compatibility while fixing path conflicts that could previously occur with nested submodule names ("foo" vs "foo/bar") or case differences.

The implementation looks thorough, with careful handling of edge cases and good test coverage. The author notes some potential future improvements like handling very long paths through sharding, but the current solution appears robust for typical cases. This is a foundational change that enables safer submodule handling across different platforms.
