This is a refactoring patch that's part of the submodule gitdir path encoding series. It moves the `is_rfc3986_unreserved()` function from being a static helper in credential-store.c back to being a public function in strbuf.[ch], where it can be reused by other parts of Git.

The change is motivated by the need to use URL encoding for submodule gitdir paths to avoid filesystem conflicts. The function, which checks if a character is unreserved according to RFC 3986 (the URL specification), was previously moved to credential-store.c when it was only used there, but now needs to be available more widely.

The patch is straightforward - it removes the static implementation from credential-store.c and adds it to strbuf.c with a corresponding declaration in strbuf.h. This is a clean change that follows Git's usual patterns for utility functions. The commit message clearly explains the change and its motivation in the context of the larger series.

This is a small but necessary piece of the broader effort to properly encode submodule paths, which will help prevent issues on case-insensitive filesystems and with Windows reserved filenames. The change maintains backward compatibility while enabling the new functionality.
