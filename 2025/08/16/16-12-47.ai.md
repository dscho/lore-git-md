This is a technical follow-up in the `git stash --only-unstaged` feature discussion, proposing an interim shell script solution while the core feature is being developed. Phillip Wood contributes a workaround script that demonstrates how to safely restore only unstaged changes from a `--keep-index` stash without triggering the merge conflicts that currently plague this workflow.

The script implements a three-way merge between the stashed index, HEAD, and stashed worktree to isolate unstaged changes. It handles most conflict-free cases automatically while preserving the index state, only reporting conflicts when adjacent staged/unstaged lines were modified. Wood suggests this could evolve into a proper `--unstaged` option for `git stash pop` if the approach proves useful.

Key technical details: The script uses `git merge-tree` with the stash's second parent (containing the index state) as the merge base, comparing HEAD against the stashed worktree. It creates a temporary index file to avoid modifying the real index until conflicts are resolved. The implementation shows careful handling of edge cases through explicit status checks and proper cleanup.

This contribution advances the thread by providing a concrete, testable implementation that addresses the core use case while the larger `--only-unstaged` feature is debated. It validates the technical feasibility of separating unstaged changes while maintaining Junio Hamano's earlier concerns about edge case behavior. The script's architecture may inform the eventual built-in solution's design.
