This is a platform compatibility discussion in the ongoing Rust integration series, specifically about Windows version support requirements.

Matthias Aßhauer responds to Junio Hamano's comments about Windows version support in the Rust transition. The key point centers on whether to use `x86_64-pc-windows-gnu` (which would drop Windows 8.1 support) versus `*-win7-windows-gnu` targets (maintaining compatibility). Matthias notes that while Junio suggests following Microsoft's EOL timelines, Git for Windows has historically supported versions well beyond Microsoft's official support periods (citing examples like XP, Vista, 7, and 8).

The email highlights a policy divergence: Junio views platform support through the lens of vendor support cycles, while Git for Windows maintains its own extended support timeline for older Windows versions. Matthias emphasizes this should be a conscious decision rather than an accidental side effect of the Rust transition. He also points out that Windows 10 LTSC releases will be supported until 2026/2029, complicating any simple version cutoff.

This exchange represents an important policy discussion that needs resolution before finalizing the Rust integration, as it affects both build configurations and user expectations. The tone remains constructive, with Matthias providing historical context and technical details to inform the decision.
