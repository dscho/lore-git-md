This is a proposed workaround for the `git stash --only-unstaged` feature discussion, offering an interim script-based solution while the full feature is being debated.

Phillip Wood contributes a shell script that provides a safer way to restore only unstaged changes from a stash created with `--keep-index`. The script uses `git merge-tree` to perform a three-way merge between the stashed index, HEAD, and stashed worktree, avoiding the conflicts that occur when using regular `stash pop` with `--keep-index`. The key insight is that conflicts only arise when staged lines adjacent to unstaged lines are changed.

The script represents a practical stopgap that could be useful for users needing this functionality today. Wood suggests that if the approach proves valuable, it might warrant being incorporated as a proper `--unstaged` option to `git stash pop`. The implementation appears carefully considered, handling both successful merges and conflict cases while maintaining the index state.

This contribution moves the discussion forward by demonstrating a concrete solution to the workflow pain point, though it doesn't resolve the broader questions about whether the stash format should be modified to support index-less entries natively. The script's existence may help inform the ongoing debate about the proposed `--only-unstaged` feature by providing real-world validation of the use case.
