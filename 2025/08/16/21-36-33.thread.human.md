This thread discusses a series that reworks how Git stores submodule gitdir paths to prevent filesystem conflicts, using URL-style encoding and moving the storage location from `.git/modules/` to `.git/submodules/`. The current version (v2) is a 12-patch series that has addressed prior review comments, including fixes for pointer arithmetic safety (Phillip Wood), Windows compatibility (Jeff King), and test improvements (Josh Steadmon, Ben Knoble, Junio Hamano). The series introduces a config override mechanism (`submodule.<name>.gitdirpath`) that serves both immediate customization needs and future interoperability with other Git implementations like JGit.

In the latest discussion, Phillip Wood raises an important compatibility consideration: whether an `extensions.submoduleEncoding` config key might be needed to prevent older Git versions from attempting to read repositories using the new path structure. The change moves submodule gitdirs to `.git/submodules/` while maintaining backward compatibility by first checking the legacy `.git/modules/` location. The series appears production-ready from a technical standpoint, but this versioning question may need resolution before final merge. The core team (particularly Junio Hamano) will likely weigh in on whether additional safeguards are required for smooth transitions between Git versions.
