This thread discusses a series implementing runtime configuration for submodule gitdir paths, now in its sixth iteration. The core idea is to handle submodule paths through a new `extensions.submodulePathConfig` setting rather than hardcoded formats, preventing filesystem conflicts while maintaining a unified directory structure. The series has reached architectural agreement after extensive review, with Junio Hamano mandating that all path handling must be purely runtime-configurable (no build-time options) and that repositories using this extension must fully specify submodule paths in config.

The latest email introduces the first patch of v6, which refactors `submodule--helper` to use the centralized `submodule_name_to_gitdir()` function rather than hardcoding paths. This change standardizes path handling across submodule operations and fixes test failures, while maintaining backward compatibility. The patch demonstrates the series' principle of centralizing path resolution logic, preparing for the new system while keeping existing behavior unchanged for repositories not using the extension.

Key participants include Adrian Ratiu (the series author), Patrick Steinhardt (who suggested separating core extension from migration concerns), and Junio Hamano (who set the config requirements). The v6 series incorporates their feedback through renaming the extension, adding an explicit migration command, and cleanly separating infrastructure from encoding logic.
