This thread discusses a proposed change to how Git stores submodule metadata directories (gitdirs) to avoid filesystem conflicts, particularly on case-insensitive systems. The current approach would move these from `.git/modules/` to `.git/submodules/` using URL-encoded paths, with a new `extensions.submoduleEncoding` config key to mark repositories using this scheme.

The discussion has reached consensus that the version marker is necessary after Phillip Wood and Adrian Ratiu analyzed edge cases where older Git versions or alternative implementations (JGit, libgit2) might mishandle the new paths. However, Patrick Steinhardt has raised broader architectural questions about whether introducing a new directory structure is the right approach versus alternatives like repository extensions or random suffixes in the existing directory.

The series has incorporated substantial review feedback, including safety fixes from Phillip Wood, Windows-specific improvements from Jeff King, and test enhancements from multiple contributors. While the technical implementation appears sound, the team is still weighing the best migration strategy to ensure smooth adoption across all Git implementations before finalizing the design.
