This thread continues the discussion of the submodule gitdir path encoding series (now at v5), which implements a configurable encoding scheme (`extensions.submoduleEncoding`) to prevent filesystem conflicts in `.git/modules/` paths. The core architecture is functionally complete with comprehensive test coverage, but final design decisions remain open.

Junio C Hamano has been the primary reviewer, raising several architectural concerns. The latest exchange focuses on where to locate the `is_rfc3986_unreserved()` helper function used for URL-style encoding. Adrian Ratiu proposed moving it to strbuf.[ch], but Junio strongly objects, arguing it doesn't belong there since strbuf itself doesn't use URL functionality. He suggests submodule.c as a more appropriate home, continuing a pattern of careful attention to code organization principles.

This placement debate is one of several open questions, alongside the encoding scheme details (custom `_a` vs standard %-encoding for case handling), documentation wording about encoding permanence, Windows reserved name handling, and Junio's recent proposal to rethink long path handling entirely - suggesting automatic truncation rather than erroring out when encoded names exceed filesystem limits. The series remains under final architectural review, with Junio's latest input shifting focus toward system-wide robustness considerations.
