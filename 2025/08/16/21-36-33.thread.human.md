This thread documents the finalization of a major submodule path encoding feature after eight iterations of review. The 12-patch series, primarily implemented by Adrian Ratiu with input from Patrick Steinhardt and others, introduces a new repository extension (`extensions.submodulePathConfig`) that enables flexible submodule gitdir paths while preventing filesystem conflicts. The solution includes a four-tier fallback system (plain/encoded/numbered/hashed paths), case-folding protection using RFC3986 encoding, and atomic migration command for existing repositories.

The latest patch addresses a subtle validation gap where conflicting paths could slip through initial checks but fail later during submodule addition. It adds thorough conflict detection that compares absolute paths across all configured submodules, handling both direct conflicts and case-insensitive filesystem edge cases. Junio Hamano has given his final ack for merging, with all prior review feedback incorporated - including improvements to error messages, version handling, and test coverage that now spans nested submodules, migration scenarios, and pathological naming cases.

The series represents a significant architectural change to submodule paths while maintaining backward compatibility. Core functionality is centralized in `submodule_name_to_gitdir()`, with new config options (`submodule.<name>.gitdir`, `init.defaultSubmodulePathConfig`) and extended URL encoding helpers completing the implementation. With this final patch addressing the last edge case, the feature is now ready for inclusion in an upcoming release.
