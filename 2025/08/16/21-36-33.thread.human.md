This thread discusses a series implementing path encoding for submodule gitdirs to prevent filesystem conflicts, introducing a new `extensions.submoduleEncoding` config option. The core architecture maintains a unified directory structure in `.git/modules/` with path resolution through `submodule_name_to_gitdir()`. 

Junio C Hamano raised several key concerns in his review, including case sensitivity handling in the encoding scheme, documentation phrasing about encoding permanence, and proposing automatic truncation for long paths rather than erroring out. The discussion had narrowed on URL encoding helper placement, with Junio preferring submodule.c over url.[ch]. Adrian Ratiu later agreed with Junio that strict length checking might be unnecessary, suggesting either dropping validation or using hashed prefixes.

In the latest development, Adrian has responded to Junio's concern about consistency when enabling the new encoding feature. The current implementation leaves existing submodule gitdirs unencoded, creating a mixed state. Adrian now agrees this is problematic and proposes migrating all submodule gitdirs to the new encoding scheme when the extension is enabled, marking a shift from the previous backwards-compatible approach. This would simplify the code's assumptions and ensure consistent path handling, addressing one of the remaining open questions about the transition between old and new storage formats.

The series remains functionally complete, with the helper placement debate effectively settled.
