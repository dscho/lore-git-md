This thread continues the work on encoding submodule gitdir paths to prevent filesystem conflicts, building on Brandon Williams' 2018 effort. The current 12-patch series (expanded from v1's 9 patches) introduces URL-style encoding with case handling for cross-platform compatibility, while maintaining backward compatibility. Key decisions have solidified - notably using a repository extension (`extensions.submoduleEncoding`) as the primary interoperability mechanism, with config overrides now clearly positioned as an optional feature.

The latest email addresses a minor but important cleanup item: removing unused variables in `submodule_name_to_gitdir()` that trigger compiler warnings, as reported by SZEDER Gábor. Adrian Ratiu confirms these variables (`base_len`, `encoded_len`, `name_max`) were left behind during refactoring and will be removed in v3. While this doesn't affect core functionality, it demonstrates the author's attention to code quality during the series' evolution.

Larger architectural questions remain open, particularly around path length validation (with three approaches under discussion) and final directory structure decisions. The series has incorporated substantial reviewer feedback, including safety fixes from Phillip Wood, platform-specific improvements from Jeff King, and test enhancements from Josh Steadmon. With the version marker approach now agreed upon for cross-implementation compatibility, the config override role clarified, and these final cleanups being addressed, the series appears to be nearing readiness for inclusion.
