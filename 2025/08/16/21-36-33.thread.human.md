This thread has reached consensus on how to handle path encoding for submodule gitdirs, with Adrian Ratiu and Junio C Hamano aligning on all major design decisions. The series introduces a config-based approach (`extensions.submoduleEncoding` and `submodule.<name>.gitdirpath`) to safely encode paths when needed to prevent filesystem conflicts, particularly for case-sensitive systems.

The latest email confirms Adrian has accepted Junio's guidance on the migration strategy: rather than automatically migrating all existing gitdirs, the system will only move directories when actual conflicts occur (like between `.git/modules/A` and `.git/modules/A/B`). Adrian notes such cases are already rare due to existing validation checks, and exceptional conflicts (like with `.git/reftable/`) can be handled as one-time migrations when they arise.

The implementation uses URL percent-encoding for paths when necessary, with the gitdirpath config serving as the authoritative mapping to insulate users from encoding details. Junio has emphasized keeping the approach minimal - only encoding when absolutely required for filesystem safety.
