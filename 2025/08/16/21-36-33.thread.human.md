This thread discusses a major rewrite of how Git handles submodule paths to prevent filesystem conflicts, using URL-style encoding for cross-platform compatibility. The current 12-patch series (expanded from an earlier 9-patch version) has passed all tests and incorporates feedback from reviewers.

Key technical changes include a new path resolution order that checks for config overrides first, then legacy paths, before generating new encoded paths in `.git/submodules/`. The implementation maintains backward compatibility while adding features like a `git submodule--helper gitdir` command for machine-readable path queries. Reviewers Phillip Wood, Adrian Ratiu, and Jeff King have contributed important safety fixes and platform-specific improvements.

A significant development is the consensus around using `extensions.submoduleEncoding` as a version check, addressing concerns from Phillip Wood and Adrian Ratiu about compatibility across Git versions and alternative implementations. Patrick Steinhardt has raised broader architectural questions about whether to use a new directory structure (`.git/submodules/`) or modify the existing one (`.git/modules/`), suggesting alternatives like repository extensions or random suffixes.

In the latest exchange, Adrian Ratiu clarified that the config override feature (`submodule.<name>.gitdirpath`) will serve as a complementary tool rather than the primary interoperability mechanism, as the series will use repository extensions in v3 for cross-implementation support. This helps focus the ongoing discussion on the directory structure question and migration strategy, which remain the key open issues before the series can proceed.
