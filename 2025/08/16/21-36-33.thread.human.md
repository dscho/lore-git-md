This thread discusses a major rewrite of how Git handles submodule paths to prevent filesystem issues, particularly focusing on cross-platform compatibility and interoperability with other Git implementations. The series, now at version 2 with 12 patches, introduces URL-style encoding for submodule paths and moves them to `.git/submodules/` (protected by a new config key to maintain backward compatibility).

The discussion has evolved through several rounds of review, with key contributions from Phillip Wood (safety fixes), Adrian Ratiu (version compatibility), Jeff King (Windows/platform concerns), and Patrick Steinhardt (cross-implementation issues). The current implementation is technically sound and well-tested, but design questions remain open about path length validation and broader ecosystem impact.

Patrick Steinhardt's latest email raises important concerns about how alternative Git implementations (JGit, libgit2, Gitoxide) will handle these changes. He suggests either making the new path scheme opt-in via a repository extension or reconsidering the need for a new directory structure entirely, proposing to instead use randomized suffixes in the existing `.git/modules/` location. These suggestions add new dimensions to the discussion about how to balance innovation with ecosystem stability.

While the technical implementation appears production-ready, the thread now faces broader design questions about migration strategies and compatibility guarantees. The path forward may require either additional documentation to set expectations for other implementations or potentially significant changes to the rollout approach. Junio Hamano and other maintainers will likely need to weigh in on these ecosystem-wide considerations before the series can proceed.
