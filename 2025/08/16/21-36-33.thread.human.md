The thread has reached consensus on how to handle the migration to encoded submodule gitdir paths. Junio C Hamano has settled the approach: rather than automatically converting existing submodule directories when enabling the new `extensions.submoduleEncoding` feature, Git will use the existing `submodule.<name>.gitdirpath` configuration to permanently record paths for existing submodules. This avoids the risks of physically moving directories during migration.

Junio's key insight is that directory moves should only be necessary in rare cases where there are pre-existing path conflicts (like `.git/modules/A` and `.git/modules/A/B` coexisting). For most repositories, the config-based mapping will serve as the authoritative source of truth without requiring filesystem changes. He notes this approach is safer and points out that introducing new top-level `.git/` directories - while uncommon - does happen (citing `.git/reftable/` as an example).

With this decision, Adrian Ratiu's v5 series - which implements percent-encoding for new submodules - now has all major design questions resolved. The remaining work focuses on implementing the config-based migration strategy and finalizing documentation. The thread has progressed from initial design discussions through multiple iterations to reach this technically sound solution that balances safety with functionality.
