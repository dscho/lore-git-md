This thread concerns a major change to how Git handles submodule paths, moving from a fixed filesystem layout to a configurable approach via a new `extensions.submodulePathConfig` extension. The 10-patch series, now in its sixth iteration, has reached architectural consensus after incorporating feedback from key reviewers like Patrick Steinhardt and Junio Hamano.

The core change introduces runtime configuration of submodule gitdir paths through `submodule.<name>.gitdir` entries, replacing the previous build-time options. The implementation includes strict validation, case-folding protection, and a comprehensive fallback strategy. Recent versions added a migration command with atomic operation guarantees following Patrick Steinhardt's suggestions, and restricted the feature to new repositories to avoid breaking existing ones.

However, Josh Steadmon has identified two important issues. First, the fallback mechanism may not properly handle pre-existing encoded paths. More critically, he's found that the automatic configuration of gitdir paths during recursive submodule cloning isn't working as documented - the config entries are missing without any error, despite the extension being enabled. This undermines a core promise of the feature and could leave repositories in an inconsistent state.

The series is otherwise mature, having addressed all major design concerns. Junio Hamano has approved the runtime configuration approach while suggesting additional documentation examples. Patrick Steinhardt's feedback on configuration scope and migration atomicity has been implemented by series author Adrian Ratiu. Remaining work focuses on fixing the cloning bug, improving documentation, and resolving the fallback edge case.
