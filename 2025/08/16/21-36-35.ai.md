Submodule path encoding series (part 2/9) - this patch changes the default location for new submodule gitdirs from `.git/modules/` to `.git/submodules/` to prepare for URL-encoded submodule names. 

The change creates a clean separation between legacy unencoded paths (remaining in `.git/modules/`) and new encoded paths (going to `.git/submodules/`). This prevents potential conflicts between encoded and unencoded names, particularly important for case-insensitive filesystems and Windows reserved filenames. The patch updates all relevant documentation and test cases to reference the new path.

Key technical changes:
- Modifies `submodule.c` to first check legacy paths before falling back to new `submodules/` location
- Updates path references in 24 files across documentation and tests
- Maintains backward compatibility with existing submodules
- Prepares ground for actual encoding logic in later patches

The change is mechanical but extensive, touching many test cases that hardcoded `.git/modules/` paths. The patch appears thorough in its updates, suggesting careful review of the test suite was done. This foundational change enables the subsequent encoding work while minimizing disruption to existing repositories.
