Feature patch in the submodule gitdir path encoding series, adding configurable path overrides.

This is the third patch in a 9-part series reworking how Git handles submodule gitdir paths to avoid filesystem conflicts. The patch introduces a new configuration option `submodule.<name>.gitdirpath` that allows overriding the default gitdir location for a submodule. This provides flexibility for cases where other Git implementations (like JGit) might need different path encodings.

The implementation adds a new `git submodule--helper gitdir` command to query paths and updates `submodule_name_to_gitdir()` to check for the config override before falling back to the default path. A new test helper `verify_submodule_gitdir_path()` is introduced to verify paths in tests, with accompanying test cases showing the config override in action.

The patch maintains the series' focus on backward compatibility while adding new functionality. The config override is a thoughtful addition that acknowledges real-world needs for path flexibility while keeping the default behavior simple. The test coverage is thorough, verifying both the override and fallback cases. This continues the series' pattern of careful, well-tested changes to the submodule infrastructure.
