Submodule gitdir path encoding series (v6) - complete implementation of pure runtime configuration through `extensions.submodulePathConfig` with all build-time options definitively rejected. The 10-patch series implements path encoding via a new extension name (`submodulePathConfig`) to prevent filesystem conflicts in submodule gitdirs, with architectural consensus requiring complete `submodule.<name>.gitdir` configuration when enabled. Core architecture maintains unified directory structure in `.git/modules/` with path resolution through `submodule_name_to_gitdir()`.

New issue identified by Josh Steadmon: collision detection may not properly handle pre-existing encoded paths, causing `submodule_name_to_gitdir()` to fail with "fatal: A git directory for 'nested%2fsub' is found locally" rather than applying further encoding as expected. This suggests either:
1. The fallback mechanism isn't properly engaged when encountering encoded paths
2. Error handling path in `builtin/submodule--helper.c` is bypassing the encoding logic
3. Platform-specific behavior affecting path resolution (reference to downstream Google patch)

New bug report from Josh Steadmon reveals critical gap in automatic configuration during `--recurse-submodules` clone operations - despite extension being active, required `submodule.<name>.gitdir` config entries are not created as documented, yet no error is raised. This violates core extension requirement of config-driven paths and indicates validation layer is not properly enforcing config existence during clone operations. The silent failure could lead to repositories being in inconsistent state where extension is enabled but required configs are missing.
