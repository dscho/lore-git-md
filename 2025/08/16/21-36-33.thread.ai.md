Submodule gitdir path encoding series (v5) - complete implementation with final design discussions on URL encoding scheme, helper placement, and now path length handling robustness. The series implements path encoding to prevent filesystem conflicts in submodule gitdirs via `extensions.submoduleEncoding` config option, with all major components in place including platform-portable length validation and test coverage.

Core architecture maintains unified directory structure in `.git/modules/` with path resolution through `submodule_name_to_gitdir()`. Junio C Hamano's latest review raises three key technical concerns: 1) case sensitivity handling in the encoding scheme (questioning why uppercase letters use `_a` encoding rather than standard URL percent-encoding like `%41`), 2) objection to the "For now" phrasing in documentation about the URL-based encoding, and now 3) proposing a fundamental rethink of long path handling - suggesting automatic truncation and uniquification rather than erroring out when encoded names exceed filesystem limits.

The URL encoding helper function `is_rfc3986_unreserved()` placement debate continues, with Junio maintaining strbuf.[ch] is inappropriate unless strbuf itself uses URL functionality, preferring submodule.c as its current user location. Historical context notes the function was previously in credential-store.c when that was its only consumer.
