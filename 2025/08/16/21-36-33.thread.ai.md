Submodule gitdir path encoding series (v2) - complete rewrite of 2018 Brandon Williams work to prevent filesystem conflicts in submodule gitdir paths using URL-style encoding (RFC 3986) with case encoding for cross-platform compatibility. Current status:

- 12-patch series (expanded from v1's 9 patches) passing all CI tests
- Core path validation in `submodule_name_to_gitdir()` updated per Phillip Wood's review to fix potential undefined behavior in pointer arithmetic
- Patch 2/9's move to `.git/submodules/` now confirmed to require `extensions.submoduleEncoding` config key (per Phillip Wood's technical analysis and Adrian Ratiu's confirmation) to prevent older Git versions and alternative implementations (JGit, libgit2) from accessing new path structure
- Patch 3/11's config override mechanism (`submodule.<name>.gitdirpath`) clarified as complementary feature rather than core interoperability requirement, with repository extension becoming primary cross-implementation mechanism in v3
- Implementation maintains backward compatibility while providing forward-looking interoperability path
- `git submodule--helper gitdir` subcommand provides machine-readable path querying
- Test coverage includes config override behavior verification via `verify_submodule_gitdir_path()` helper

Key technical details:
- Path resolution order in `submodule_name_to_gitdir()`:
  1. Config override check (now positioned as optional feature)
  2. Legacy path check in `.git/modules/`
  3. New encoded path generation in `.git/submodules/` (protected by version check)
  4. NAME_MAX validation (currently using `pathconf(_PC_NAME_MAX)` per Adrian Ratiu, with Jeff King suggesting simpler alternatives)
  5. BUG assertions for path invariants
- URL encoding implementation with shared `is_rfc3986_unreserved()` utility
- Case encoding for cross-platform compatibility
- 64 files updated across code and documentation
- Comprehensive test coverage (202 cases) including edge cases and platform-specific validation

Design evolution:
- Repository extension (`extensions.submoduleEncoding`) confirmed as primary cross-implementation mechanism for v3 (per Patrick Steinhardt's suggestion and Adrian Ratiu's implementation plan)
- Config override (`submodule.<name>.gitdirpath`) now clearly positioned as optional feature for testing/custom schemes rather than core interoperability requirement
- Considering elimination of separate `.git/submodules/` directory in favor of using `.git/modules/` with random suffixes when extension is enabled
- Improved error messaging planned for path conflicts, directing users to enable extension
- URL encoding remains default human-readable format while leaving room for future configurable schemes

Open questions:
- Path length validation approach in `submodule_name_to_gitdir()` - three options under discussion:
  1. Keep current `pathconf()`-based check (Adrian Ratiu's implementation)
  2. Let filesystem operations fail naturally (Jeff King's first suggestion)
  3. Use fixed conservative limit like 255 chars (Jeff King's second suggestion)
- Final directory structure decision (`.git/submodules/` vs `.git/modules/` with random suffixes) pending implementation of extension mechanism
- Migration timeline considerations for alternative implementations
- Whether to keep separate `.git/submodules/` directory or modify existing one when extension is enabled
- Need to clean up unused variables (`name_max`, `encoded_len`, `base_len`) in `submodule_name_to_gitdir()` that trigger compiler warnings with `-Werror`
