Submodule gitdir path encoding series (v1) - complete rewrite of 2018 Brandon Williams work to prevent filesystem conflicts in submodule gitdir paths. Uses RFC 3986 URL-style encoding for path components. Current status:

- Patch 2/9 changes default location for new submodule gitdirs from `.git/modules/` to `.git/submodules/` to separate legacy unencoded paths from new encoded paths
- Patch 3/9 introduces config override mechanism via `submodule.<name>.gitdirpath` for per-submodule gitdir path customization
- Maintains backward compatibility by checking legacy paths first, then config overrides, then falling back to new default paths
- Updates 24 files across documentation and tests to reference new path
- Adds new `git submodule--helper gitdir` subcommand for path querying
- New test infrastructure in lib-verify-submodule-gitdir-path.sh reused across series
- Comprehensive test coverage in t7400 (config override) and t7425 (mixed gitdir paths, 207 new test lines)

Key technical details:
- URL encoding implementation for submodule gitdir paths in submodule.c
- Config override lookup in `submodule_name_to_gitdir()`
- Removal of obsolete validate_submodule_git_dir()
- Path changes affect case-insensitive filesystems and Windows reserved filenames
- Designed to accommodate alternative implementations (JGit mentioned) via config escape hatch

The series remains well-structured with logical separation between implementation, test infrastructure, and path updates. Builds on 2018 discussion where URL encoding approach was debated and chosen over custom encoding schemes. This foundational change enables subsequent encoding work while minimizing disruption to existing repositories. Patch 3 cleanly introduces the config override mechanism without prematurely exposing the URL encoding logic that will follow in later patches.
