Submodule gitdir path encoding series (v5) - implementation now settled with expanded deployment considerations from Google's experience. The series implements path encoding via `extensions.submoduleEncoding` config to prevent filesystem conflicts in submodule gitdirs, with architectural agreement from Adrian Ratiu, Patrick Steinhardt, and Junio Hamano. Core architecture maintains unified directory structure in `.git/modules/` with path resolution through `submodule_name_to_gitdir()`.

Technical implementation includes:
- Simplified collision detection via directory scan with `strcasecmp()`/`strcmp()`
- URL percent-encoding (`%41`) for case-folding conflicts
- Config-based transition using `submodule.<name>.gitdirpath` mapping
- Comprehensive test coverage in t7425-submodule-encoding.sh
- No dependency on `core.ignorecase` config

Deployment challenges and responses:
1. Josh Steadmon identified limitations in automated migration and distributed config enablement
2. Adrian Ratiu proposes build-time configuration option to force-enable the extension
3. Planned test expansion for backward compatibility scenarios
4. Migration tools still needed for existing repos with custom encoding schemes
