Submodule gitdir path encoding series (v5) - complete implementation with final design discussions on URL encoding scheme, helper placement, path length handling, and now migration strategy for existing submodules. The series implements path encoding to prevent filesystem conflicts in submodule gitdirs via `extensions.submoduleEncoding` config option, with all major components including platform-portable length validation and test coverage.

Core architecture maintains unified directory structure in `.git/modules/` with path resolution through `submodule_name_to_gitdir()`. Junio C Hamano's review raised key concerns: 1) case sensitivity encoding scheme (`_a` vs URL percent-encoding), 2) documentation phrasing about encoding permanence, 3) proposing truncation+uniquification for long paths, and now 4) consistency when enabling the feature with existing submodules (mixed encoded/unencoded state).

Adrian Ratiu now agrees with Junio that the current v3 approach of leaving existing gitdirs unencoded creates inconsistency and proposes migrating all submodule gitdirs to the new encoding scheme when the extension is enabled. This marks a second significant shift in approach (following the earlier reconsideration of path length handling) and would simplify code assumptions about path formats.

Implementation includes:
- `repository_format_submodule_encoding` flag in repository.h
- Config handling in setup.c
- Case-aware encoding via `strbuf_addstr_case_encode()`
- Comprehensive coverage in t7425-submodule-encoding.sh
- Refactored `add_submodule()` using centralized path helpers
