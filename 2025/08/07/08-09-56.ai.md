This is part 6/9 of Patrick Steinhardt's series refactoring multi-pack index (MIDX) handling to use the object database (ODB) source system. The patch focuses on loading MIDX files via their ODB source rather than passing redundant repository and object directory parameters.

The key changes in this patch:
- Modifies MIDX loading functions (`load_multi_pack_index_one`, `load_midx_chain_fd_st`, `load_multi_pack_index_chain`) to take an `odb_source` parameter instead of separate repository/object_dir/local parameters
- Updates callers in `builtin/multi-pack-index.c` and test helpers to handle the new interface
- Adds a helper function `handle_object_dir_option` to manage alternate object directories for cases where MIDX operations target non-default locations
- Maintains existing behavior while removing duplicate information flow (object_dir and local flag are derived from the source)
- Updates test infrastructure to work with the new interface

The changes continue the series' goal of deduplicating information and better integrating MIDX handling with the ODB source abstraction. The patch surfaces one edge case where test helpers and commands need to work with MIDX files in alternate object directories, which is handled by temporarily adding them as in-memory alternates.

This represents a significant step in the ODB abstraction work, with all MIDX loading operations properly integrated with the source system. The changes are mechanical refactoring with no intended behavior changes, though the test updates show some path handling differences in the test output format.
