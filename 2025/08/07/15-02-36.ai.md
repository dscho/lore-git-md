This is patch 2/5 in the v9 series introducing the new `git repo info` command hierarchy, focusing on repository metadata reporting. The patch moves the reference storage format reporting functionality from `git rev-parse --show-ref-format` to the new `git repo info references.format` command.

The implementation adds:
- A new `references.format` field that reports the ref storage format ("files" or "reftable")
- Core functionality in builtin/repo.c with:
  - A field lookup system using bsearch for efficient key matching
  - Dual strbuf architecture for handling both quoted (keyvalue) and unquoted (nul) output formats
  - Proper error handling for invalid keys
- Comprehensive test coverage in t1900-repo.sh verifying:
  - Correct format reporting for both files and reftable backends
  - Error handling for invalid keys
  - Deduplication of duplicate key requests
  - Mixed valid/invalid key handling

The patch follows Git's established patterns for command output formatting, using C-style quoting for the default keyvalue format. It integrates with the existing ref-storage infrastructure through `ref_storage_format_to_name()`. The test suite demonstrates the command's behavior across different repository configurations and error cases.

This represents a clean migration of functionality from rev-parse to the new command hierarchy while maintaining backward-compatible behavior. The implementation has been reviewed by multiple core contributors and mentors, with all feedback incorporated by the v9 iteration.
