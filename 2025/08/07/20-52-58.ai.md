This is the main feature patch in a 3-part series introducing a `--max-depth` option to Git's diff machinery. The patch implements depth-limited tree traversal for diff operations, allowing users to specify how many directory levels below a pathspec to descend (similar to `git grep --max-depth`).

The implementation adds `max_depth` and `max_depth_valid` fields to `struct diff_options` and modifies core diff infrastructure in tree-diff.c to respect depth limits during recursive traversal. Key technical details:

- Depth is measured from the closest pathspec match (not from root)
- Uses `within_depth()` helper from dir.c (fixed in patch 2/3)
- Explicitly disallows use with:
  - Wildcard pathspecs (checked in `diff_setup_done()`)
  - Non-tree diffs (index/worktree comparisons)
- Supports `-1` as "no limit" value
- Includes extensive tests (109 lines in t4072-diff-max-depth.sh) covering:
  - Various depth combinations
  - Pathspec edge cases
  - Tree vs index/worktree behavior differences
  - Embedded pathspec handling

The patch builds on Jeff King's original work with refinements from Toon Claes and Patrick Steinhardt's review. It addresses all feedback from v1, including making error messages translatable and using `BUG()` for internal checks. The implementation appears thorough with good test coverage, though some open questions remain about option parsing internals (handling of `max_depth_valid` flag).
