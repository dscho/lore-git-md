This is part 8/10 of Patrick Steinhardt's series to remove global state from the commit-graph subsystem, specifically targeting `the_hash_algo` usage. The patch systematically replaces direct `the_hash_algo` references with repository-specific hash algorithms throughout commit-graph operations.

Key changes:
- Updates `open_commit_graph_chain()` to take an explicit `hash_algo` parameter instead of using `the_hash_algo` implicitly
- Modifies hash-related calculations in core commit-graph functions to use the graph's stored hash algorithm (`g->hash_algo`) or repository's algorithm (`r->hash_algo`)
- Adjusts chunk validation, OID writing, and graph file generation to use repository-aware hash sizes
- Maintains special handling for cross-repository cases by falling back to `the_repository->hash_algo` where needed (to be removed in later patches)

The changes are mechanical but thorough, touching:
- Graph file loading and validation
- Chunk size calculations
- OID writing in various graph chunks (data, base, oids)
- Progress reporting
- Cross-graph operations

This continues the series' pattern of eliminating implicit global state while preserving all existing behavior. The patch follows the established approach of passing hash algorithms explicitly through the call chain, preparing for complete `the_repository` removal. All modifications are straightforward replacements with no functional changes beyond the global state elimination goal.
