This is a review comment on patch 5/8 in Patrick Steinhardt's series integrating multi-pack indices with the ODB source system. Karthik Nayak points out a potential inconsistency in the patch's approach to handling MIDX files in alternate object directories.

The patch refactors MIDX loading to work through object sources rather than direct paths, which helps deduplicate information and prepares for pluggable backends. However, Karthik notes it currently only addresses the read path (`cmd_multi_pack_index_verify`) while leaving write operations potentially broken. He suggests the next commit (which presumably handles writes) should be squashed into this one to maintain consistency.

The review indicates general approval of the technical direction but flags an important sequencing issue - the patch introduces a temporary state where write operations to alternate object directories would not work as expected. This appears to be a thoughtful technical review catching an integration issue that could cause problems if not addressed before merging.
