This is the third and final patch in a v2 series introducing a `--max-depth` option to Git's diff machinery, originally authored by Jeff King and now being proposed by Toon Claes. The feature adds depth-limiting functionality to tree diffs, similar to `git grep --max-depth`, allowing users to stop recursive traversal at a specified depth from the pathspec.

The patch implements the core functionality, adding a `max_depth` parameter to `struct diff_options` and modifying the tree-diff logic to respect depth constraints. Key aspects include:
- Depth is measured from the closest pathspec match (not from root)
- Uses `-1` for unlimited depth (matching grep's convention)
- Explicitly disallows use with wildcard pathspecs and non-tree diffs
- Includes comprehensive tests (109 lines in t4072-diff-max-depth.sh) covering various depth combinations and edge cases

The implementation appears well-considered, with careful attention to pathspec handling and clear documentation. The test coverage is thorough, verifying both expected matches and error conditions. This addresses a real use case for optimizing operations like git-blame-tree where full tree traversal is unnecessary.

The patch builds on previous work in the series that fixed initialization issues in combine-diff and added unit tests for the depth calculation logic. All feedback from v1 appears to have been addressed, making this likely ready for inclusion.
