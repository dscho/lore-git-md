This is a feature addition to Git's diff machinery, introducing a `--max-depth` option to limit recursive tree traversal depth. The patch series is now in its second version, with 3 patches:

1. A preparatory cleanup in combine-diff.c using `CALLOC_ARRAY()`
2. A fix for the `within_depth()` function with new unit tests
3. The main implementation adding `--max-depth` support

Key technical details:
- Adds `max_depth` and `max_depth_valid` fields to `struct diff_options`
- Implements depth checking in tree-diff.c with const-correct helpers
- Supports `-1` as "no limit" value
- Explicitly disallows use with wildcard pathspecs
- Includes comprehensive tests (109 lines in t4072-diff-max-depth.sh)
- Documents the option in diff-options.adoc

Notable changes in v2:
- Added unit tests for `within_depth()` in dir.c
- Implemented `-1` as unlimited depth value
- Made error messages translatable
- Switched from `die()` to `BUG()` for internal checks
- Improved documentation wording
- The series builds on Jeff King's original work, with Toon Claes now leading the effort and incorporating feedback from Patrick Steinhardt.

The implementation differs from `git grep --max-depth` by putting the depth limit in `diff_options` rather than `pathspec`, which the cover letter acknowledges as a potential consolidation opportunity but not an immediate priority.

The patch appears well-tested and documented, with clear motivation from historical discussions around git-blame-tree/git-last-modified use cases. The v2 changes address previous feedback and expand test coverage significantly.
