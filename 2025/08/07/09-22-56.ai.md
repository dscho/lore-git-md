Refactoring and type safety patch introducing a new `count_t` typedef for entity counting.

This patch proposes adding a new `count_t` typedef (aliased to `uintptr_t`) specifically for counting entities (like array elements) rather than bytes. The motivation stems from Git's historical mixing of signed/unsigned types and use of `size_t` for both byte counts and entity counts, which has led to out-of-bounds bugs. The change includes:
- Adding the typedef in git-compat-util.h with documentation about its purpose
- Updating CodingGuidelines to specify `size_t` for bytes and `count_t` for entities
- Converting `builtin/rm.c` as an example, changing several `int` counters to `count_t`

The author argues this provides better type safety by clearly distinguishing byte counts from entity counts, and using unsigned types helps prevent negative values where they don't make sense. The choice of `uintptr_t` ensures it can count all possible entities even in the theoretical worst case where each entity is 1 byte filling all memory. The patch appears well-motivated with a thorough commit message discussing the rationale and type choice. It's part of ongoing efforts to improve type safety following the enabling of `-Wsign-compare` warnings.
