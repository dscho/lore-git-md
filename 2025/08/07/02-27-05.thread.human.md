The thread began with a report that `git stash --include-untracked` was unexpectedly modifying timestamps of .pack files in Git's object store, even when no untracked files needed stashing. This behavior triggered unnecessary transfers in backup systems that rely on file timestamps.

Patrick Steinhardt responded that this is actually expected behavior stemming from Git's object freshening mechanism - Git updates access times of objects (and their containing packfiles) whenever writing to the object database. He explained this is fundamental to Git's garbage collection system and not specific to `stash`. While the `save_untracked_files()` function might be optimized to reduce some cases, the core behavior would remain since many Git operations could trigger similar timestamp updates.

The discussion suggests this isn't a bug to fix in Git, but rather something backup systems may need to accommodate by adjusting how they handle Git's object storage patterns. The original issue appears to be working as designed, even if it causes unintended side effects for certain workflows.
