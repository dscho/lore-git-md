This thread reports an unexpected behavior where `git stash --include-untracked` modifies timestamps of certain .pack files in the object store, even when there are no untracked files to stash. The timestamp changes trigger unnecessary file transfers in backup systems like rsync, despite no actual content changes. The issue doesn't occur with regular `git stash` command.

The problem appears consistently for specific .pack files within a repository, though the selection pattern isn't yet understood. The behavior persists regardless of whether the affected packfiles have corresponding .keep files. While no fix has been proposed yet, the report clearly demonstrates the impact on backup workflows and suggests the issue may stem from preparatory steps in the --include-untracked operation rather than its core functionality. This warrants investigation since it affects a fundamental Git operation and interacts with external systems.
