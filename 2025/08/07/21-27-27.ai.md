This is a bugfix patch addressing the inconsistency between content-ignoring diff options (`-w`, `-I<regex>`) and metadata outputs (`--name-only`, `--name-status`, `--raw`). The patch represents the final v4 version of a solution that has undergone significant design discussion and refinement in the thread.

The core issue is that metadata outputs were only comparing SHA values for performance reasons, while content-ignoring options require examining file contents. This led to cases where files could appear in metadata outputs but not in patch output when using ignore options. The solution introduces a `dry_run` mode in `diff_options` and a `quick_consume()` callback to efficiently detect changes without full processing.

Key technical details:
- New `dry_run` boolean flag in `diff_options` struct
- `quick_consume()` callback sets `found_changes` flag when differences are detected
- `diff_flush_patch_quietly()` helper function coordinates the dry-run behavior
- Comprehensive test coverage in t4013 and t4015
- Documentation updates in xdiff-interface.h

The implementation has evolved through multiple versions, with the current approach being simpler than earlier attempts that used `/dev/null` redirection or `DIFF_FORMAT_DRY_RUN`. Junio Hamano provides final review feedback focusing on:
1. Improving commit message clarity around file equivalence
2. Removing unnecessary local `dry_run` variable
3. Adding explanatory comments about error returns in dry-run mode
4. Using `test_grep` helper in tests
5. Considering test file cleanup with `test_when_finished`
6. Questioning whether test modifications for `--raw/--name-only/--name-status` are still needed
