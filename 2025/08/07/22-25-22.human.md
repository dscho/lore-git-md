This is a review response in Patrick Steinhardt's ongoing ODB source system integration series (v2, 9 patches). Taylor Blau is seeking input on patch 6/9, which refactors how multi-pack indices (MIDX) are loaded to use the new ODB source system rather than direct path access.

The patch makes MIDX loading work through object sources, which helps prepare for pluggable backends by removing redundant path/state passing and enabling future backend-specific MIDX handling. However, Taylor raises a question about the approach taken for handling the `--object-dir` option - the patch adds user-provided directories as in-memory alternates, and Taylor isn't sure if this is the right solution, asking for input from Stolee who originally added this functionality.

The technical changes look solid (57 lines modified in midx.c with clear simplifications), but there's an open design question about backward compatibility with tools that expect to read/write MIDX files in alternate locations. This appears to be the last major question before the series can proceed, as 8/9 patches already have positive reviews.
