This is a bugfix patch in a 3-part series adding `--max-depth` functionality to Git's diff machinery. The patch fixes an edge case in the `within_depth()` function used for depth-limited tree traversal.

The core issue is that `within_depth()` was incorrectly returning `true` for empty paths when the base depth was non-zero, which could lead to inconsistent behavior. While this doesn't currently cause user-visible bugs (since existing callers always pass base depth 0), it could affect future uses of the function. The patch makes the behavior consistent by properly comparing the calculated depth to the maximum depth in all cases.

The change is well-validated with a new unit test file (`u-dir.c`) that thoroughly tests various depth combinations, including edge cases. The commit message provides clear examples of the behavioral change and explains why the current inconsistency doesn't affect `git grep` (the only current user), while noting this is still the right fix for future diff functionality.

This patch was originally authored by Jeff King and is now being carried forward by Toon Claes, who has added the comprehensive test coverage. It's part of preparing the diff infrastructure for the upcoming `--max-depth` feature in patch 3/3 of the series.
