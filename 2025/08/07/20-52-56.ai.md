This is a preparatory refactoring patch for the `--max-depth` diff series, originally authored by Jeff King and now being proposed by Toon Claes in v2. The patch fixes an initialization issue in the combine-diff machinery where `diff_filepair` structs were allocated with `xmalloc()` but not zero-initialized, potentially leaving fields with random values.

The change switches to using `CALLOC_ARRAY()` which ensures all fields are zeroed, matching the behavior of the regular diff code. The commit message notes this is particularly important for fields like `status` and `rename_score` that don't make sense for combined diffs but could have contained garbage values before. While the author suggests a potential future `DIFF_STATUS_COMBINED` flag might be useful, this patch keeps the status as 0 for now since the proper semantics aren't yet clear.

The change is minimal (just one line changing `xmalloc` to `CALLOC_ARRAY`) but important for correctness. This is the first of three patches in the series, serving as groundwork for the main `--max-depth` functionality by ensuring proper initialization of diff structures. The patch maintains Jeff King's original authorship while being carried forward by Toon Claes, and has already been reviewed in previous iterations of the series.
