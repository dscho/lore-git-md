Bugfix addressing inconsistency between content-ignoring diff options (`-w`, `-I`) and metadata outputs (`--name-status`, `--raw`, `--name-only`). This v4 patch finalizes the implementation after review feedback, adding a `dry_run` optimization mode to `struct diff_options` and introducing `diff_flush_patch_quietly()` for quick change detection.

The core change makes metadata outputs respect content-ignoring options by:
1. Adding a boolean `dry_run` flag to skip full diff processing when only checking for changes
2. Implementing `quick_consume()` callback to detect changes without generating full output
3. Using `diff_flush_patch_quietly()` to determine when to show files in metadata outputs
4. Removing the `/dev/null` redirection hack from earlier versions

Key technical details:
- New `dry_run` field in `diff_options` struct
- `quick_consume()` sets `found_changes` flag on first difference
- `xdiff-interface.h` docs updated to reference the new pattern
- Comprehensive test coverage in t4013 and t4015
- Jeff King has signed off (Reviewed-by)

The patch maintains all functionality while simplifying the control flow in `diff_flush()`. It resolves the original inconsistency where files could appear in metadata outputs but not in patch output when using content-ignoring options. Performance impact is negligible since the optimization only affects cases where content-ignoring options are used with metadata outputs.
