This is a feature addition to Git's diff machinery, introducing a `--max-depth` option to limit recursive tree traversal. The 3-patch series is now in its second iteration, with Toon Claes shepherding Jeff King's original work through review.

The core change adds depth-limiting functionality similar to `git grep --max-depth`, stopping recursion at a specified depth from pathspecs. This is particularly useful for operations like git-blame-tree/git-last-modified where full tree traversal is unnecessary. The implementation adds `max_depth` and validation fields to `diff_options` rather than reusing the pathspec structure.

Key improvements in v2 include:
- Added comprehensive unit tests for the `within_depth()` function
- Support for `-1` as "no limit" value
- Better documentation and error messages (now translatable)
- Const-correctness and use of `BUG()` macros
- More thorough test coverage in t4072-diff-max-depth.sh

The series shows careful attention to detail, with clear commit messages explaining both the technical implementation and edge case handling. Review feedback from Patrick Steinhardt has been incorporated, and the patches now appear ready for serious consideration. The only remaining design question seems to be whether to consolidate the depth tracking with grep's similar functionality, though the current approach appears sound.
