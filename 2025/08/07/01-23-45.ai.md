This is a bugfix patch addressing the interaction between content-ignoring diff options and metadata outputs, part of an ongoing thread that has reached near-consensus on the technical approach. The patch implements a `DIFF_OPT_DRY_RUN` optimization mode to handle content-ignoring options (`-I`, `-w`) consistently across all diff output formats including `--name-only` and `--raw`.

Key technical elements in this iteration:
- Replaces the `/dev/null` redirection hack with a proper `dry_run` flag in `diff_options`
- Introduces `quick_consume()` callback to detect changes without full processing
- Handles metadata formats through `diff_flush_patch_quietly()` (renamed from `_quiet` per Junio's suggestion)
- Maintains performance by avoiding content examination when only metadata is needed

Junio's review notes several refinements needed:
- Suggests simplifying the `dry_run` flag from an enum since no other optimization modes are anticipated
- Recommends removing redundant "diff_" prefix from struct member names
- Questions the zero-context implication in dry-run mode (Lidong explains this was for regex matching but agrees to remove)
- Points out the error-handling limitation in `quick_consume()` (acknowledged but deferred)

The implementation has already received Jeff King's Reviewed-by and addresses the core inconsistency where content-ignoring options previously had no effect on metadata outputs. With only minor naming and code organization tweaks remaining, this appears to be the final iteration before merging.
