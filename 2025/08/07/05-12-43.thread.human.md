This thread documents Lidong Yan's performance optimization series that enables Bloom filter usage with wildcard pathspecs in revision traversal. The key innovation is filtering only the non-wildcard portion of pathspecs up to the last directory separator, while maintaining compatibility mask for pathspec magic signatures (excluding problematic cases like exclude and icase). The series went through four iterations with thorough review from both Patrick Steinhardt and Junio Hamano.

Patrick provided detailed feedback on implementation robustness and test coverage, while Junio focused on edge cases in wildcard handling. The v4 iteration incorporates all prior feedback and includes a final fix for a minor leak (restoring a missing `free(path_alloc)`). Benchmarks show substantial improvements: 18-27% faster in Git's own repository and 47-63% faster in large repositories like LLVM when using wildcard pathspecs.

The implementation carefully handles edge cases like zero-length paths and trailing slashes, with comprehensive test coverage in t4216-log-bloom.sh. With all technical concerns addressed and Junio's sign-off on the final version, this optimization is now ready for inclusion in the main branch. The changes maintain backward compatibility while significantly improving performance for common wildcard pathspec cases.
