This is a refactoring patch in the `git rebase --trailer` feature series, specifically addressing reviewer feedback on the trailer processing internals. The patch moves trailer handling from an external `interpret-trailers` helper into built-in code via a new `trailer_process()` function.

Key technical changes in this iteration:
- Removes fork/exec of `git interpret-trailers` in favor of direct in-process calls
- Introduces `trailer_process()` as the central API for all trailer operations
- Adds new helpers `parse_trailer_args()` and `free_new_trailer_list()`
- Maintains backward compatibility with existing behavior
- Still needs work on code organization and error handling per Phillip Wood's review

Reviewer concerns still to address:
1. Code movement should be separated from refactoring into distinct commits
2. Error handling needs standardization (currently mixes `die()` and error returns)
3. Some logic paths around empty trailers/message formatting need justification
4. API design questions around `--trailer=` prefix handling
5. Various style issues (alignment, blank lines, bool conversion)
6. Test coverage appears solid but implementation details need polish

The patch represents significant progress on the series' goal of in-process trailer handling, but needs another iteration to address the review feedback before being ready for inclusion. The core functionality appears sound but the presentation needs refinement to make the changes easier to review.
