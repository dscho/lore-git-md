Bugfix addressing the interaction between content-ignoring diff options and metadata outputs. This is the third iteration of a patch that ensures options like `-w` and `-I` work consistently across all diff output formats, including `--name-only` and `--raw`.

The patch implements a "dry-run" mode in the diff_options struct to quickly detect changes without full content processing, addressing the core inconsistency where content-ignoring options were previously ignored for metadata outputs. The approach has evolved through several iterations with input from Jeff King and Junio Hamano, who have both approved the technical direction.

Key changes in this version respond to Junio's feedback about naming (`diff_flush_patch_quietly` instead of `diff_flush_patch_quiet`) and avoiding unnecessary context line suppression in dry-run mode. The author acknowledges remaining considerations about error handling but proposes deferring those to future work to keep this focused fix clean.

The patch appears well-considered and addresses a real inconsistency in Git's diff behavior. With the core maintainers' approval and only minor naming/style tweaks remaining, this looks ready for final polishing and inclusion.
