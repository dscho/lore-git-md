Performance optimization for Bloom filters with wildcard pathspecs. This patch enables Bloom filter usage during commit traversal even when pathspecs contain wildcards or certain magic signatures, by filtering only on the non-wildcard portion of the path. The change shows measurable speedups in both Git's own test suite (20-25% faster for `t/*` and `:(top)t`) and larger repositories like LLVM (60-90% faster for `libc/*` and `:(top)libc`).

The key technical change modifies `revision.c` to stop disabling Bloom filters for all wildcard pathspecs, instead only disabling them for pathspecs with "exclude" or "icase" magic. The patch includes careful handling of path boundaries to ensure the Bloom filter uses the maximal non-wildcard prefix of each path. New test cases verify the behavior with various wildcard patterns and magic signatures.

The implementation appears well-considered, with clear benchmark improvements and thorough test coverage of edge cases. This could provide meaningful performance benefits for users frequently searching commit histories with wildcard pathspecs, particularly in large codebases. The change is backward-compatible since it only expands when Bloom filters are used rather than changing their core behavior.
