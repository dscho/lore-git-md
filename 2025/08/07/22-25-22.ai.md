This is a review response in Patrick Steinhardt's ongoing ODB source system integration series (v3, 9 patches). Taylor Blau is seeking input on patch 6/9 which refactors MIDX loading to work through object sources rather than direct paths.

The patch makes MIDX handling more consistent with the series' goal of explicit ODB source tracking by:
- Loading MIDX files via their owning source` rather than raw paths
- Removing redundant parameter passing (object directory and locality flags)
- Preparing for future backend-specific MIDX handling
- Addressing edge cases where tools need to work with MIDX files in alternate object directories

Taylor expresses uncertainty about the approach for handling user-provided object directories (added as in-memory alternates), specifically questioning whether this is the right solution. He's seeking input from Stolee who originally added the `--object-dir` functionality.

Key technical points:
- New `handle_object_dir_option()` helper manages alternate object directory cases
- `odb_find_source()` and `odb_add_to_alternates_memory()` used to locate/create sources
- Changes affect MIDX loading in both production code (`builtin/multi-pack-index.c`) and test helpers
- Maintains existing functionality while moving toward source-based API

This continues the series' pattern of making ODB behaviors more explicit while maintaining backward compatibility. The review highlights one of the more subtle integration points in the series where legacy behavior (direct object directory specification) meets the new source-based model. Taylor's request for Stolee's input suggests this may be a key decision point before proceeding.
