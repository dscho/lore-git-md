This is a cover letter for a 9-part refactoring series in the multi-pack index (MIDX) subsystem, building on Patrick Steinhardt's ongoing work to integrate MIDX handling with Git's object database (ODB) source system. The series represents version 2 of the effort to eliminate redundant information between MIDX structures and their ODB sources.

The key technical changes in this iteration include:
1. Adding a new commit (4/9) that simplifies the `link_alt_odb_entry()` calling convention by removing a redundant path parameter
2. Fixing a comment typo in the locality tracking commit (1/9)
3. Continuing the mechanical refactoring to make MIDX operations consistently use ODB sources rather than duplicating information

The series affects multiple subsystems including MIDX loading/writing, bitmap handling, and revindex operations, touching 15 files with roughly equal parts additions and deletions (239 lines each). Changes are focused on internal interfaces - no user-visible behavior is modified.

This version addresses all feedback from v1, including Junio Hamano's correction about "deduplicating" vs "duplicating" in the series title and Toon Claes' terminology suggestions. The discussion has identified additional interface improvements like the redundant path parameter in ODB source creation that's now addressed in the new commit 4/9.

The work builds on prior MIDX/ODB integration efforts and represents a significant step in abstracting Git's object storage layer. All changes are mechanical refactorings with no behavior changes, maintaining consistency with the ongoing `the_repository` removal effort's patterns. The series appears well-tested with existing MIDX tests being updated to accommodate the refactored interfaces.
