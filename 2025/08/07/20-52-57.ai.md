Bugfix for edge case in depth-limited tree traversal, part of the `--max-depth` feature series. This patch corrects the `within_depth()` function in dir.c which handles path depth calculations for the new max-depth functionality. The core issue involves how empty paths are handled when base depth > 0 - previously these would incorrectly return true. While this didn't cause user-visible bugs in current callers (which all use base depth 0), it could affect future uses. The fix makes the function consistently return whether the total depth (base + path components) is <= max_depth.

The patch adds comprehensive unit tests in t/unit-tests/u-dir.c covering various depth combinations, including the empty path case. Test cases verify behavior with different base depths (0 and 1) against max_depth values (0 and 1), showing the corrected behavior where empty paths with base depth 1 now properly respect max_depth constraints.

This is patch 2/3 in the series, building on Jeff King's original work. The change is technically a behavior modification but one that aligns with the intended semantics of depth-limited traversal. The commit message notes this could affect future diff operations using DIFF_OPT_TREE_IN_RECURSIVE, though current grep usage remains unaffected. The thorough test coverage helps ensure the change doesn't introduce regressions while providing clear specification of the expected behavior.
