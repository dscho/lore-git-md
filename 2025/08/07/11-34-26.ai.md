This is a feature proposal for partial cloning of submodules. The author, Petar Vutov, suggests adding support for filtering submodule contents during clone/update operations through a new `submodule.<name>.filter` configuration in `.gitmodules`. The proposal outlines a basic implementation approach where the existing partial clone plumbing would be leveraged to filter paths during submodule updates, with recursive updates respecting the filter specifications (potentially excluding filtered submodules from status output). 

The key technical aspects are:
- New configuration option in `.gitmodules` to specify filters per submodule
- Integration with existing partial clone machinery (`git clone --filter`)
- Behavior implications for recursive operations and status reporting

This appears to be a well-motivated proposal that would extend Git's existing partial clone capabilities to the submodule workflow. The author is seeking feedback before implementation, suggesting this is an early-stage RFC. The change would affect submodule handling in `git-submodule.sh` and related plumbing commands, potentially requiring coordination with the partial clone implementation. No specific filter syntax is proposed yet, leaving that open for discussion.
