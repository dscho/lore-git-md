This is part 2/10 of Patrick Steinhardt's series to remove global state from the commit-graph subsystem, specifically focusing on converting signed integer counters to unsigned for Bloom filter statistics.

The patch changes five counters in `struct write_commit_graph_context` from `int` to `unsigned` since they track non-negative values (counts of computed/not-computed/truncated/upgraded Bloom filters). The corresponding `trace2_data_intmax()` calls are updated to use the new `trace2_data_uintmax()` function introduced in patch 1/10.

Key technical details:
- Counters track statistics about Bloom filter generation during commit-graph writes
- All counters are naturally non-negative (only incremented from 0)
- Changes affect `struct write_commit_graph_context` fields and their trace2 reporting
- Follows the pattern established in earlier discussion about using unsigned types where negative values are impossible
- Maintains consistency with the series' goal of removing implicit assumptions about data types

This is a straightforward mechanical change that aligns with the series' broader integer type cleanup and has already been reviewed/approved by key contributors (Derrick Stolee, Taylor Blau) with no outstanding objections. The change is low-risk since it only affects internal counters and their instrumentation, not actual Bloom filter behavior.
