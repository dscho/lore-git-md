This is a follow-up to the heap overflow fix for `git diff --no-index` stdin handling, proposing a more fundamental architectural change to how `--no-index` mode interacts with the working directory.

Junio Hamano suggests that the original fix (which added special handling for "-" in path normalization) addresses only a symptom of a deeper issue: the `--no-index` mode incorrectly inherits Git repository working directory assumptions. The patch instead makes `--no-index` properly ignore the Git working tree context by:

1. Reverting the original working directory change (chdir'ing back to the user's starting directory)
2. Clearing the prefix that was set during Git's startup sequence
3. Adding a test case verifying correct stdin ("-") handling in subdirectories

The change affects `builtin/diff.c`'s initialization sequence and adds a new test to `t4053-diff-no-index.sh`. The commit message provides historical context about how Git's `--no-index` mode was originally as a "better GNU diff" feature bolted onto Git's diff machinery, explaining why these impedance mismatches exist.

Key technical points:
- The fix changes behavior only for `--no-index` mode
- Maintains identical output format for stdin comparisons ("a/- b/-")
- Preserves all other existing diff functionality
- Includes direct reproduction test case in subdirectory context

This appears to be a more architecturally sound solution than the original path normalization fix, properly addressing the root cause rather than the symptom. The change is minimal (14 lines) and well-tested, though it does represent a more significant behavioral change in how `--no-index` interacts with the working directory setup.
