Performance optimization for Bloom filters in revision traversal with wildcard pathspecs. Originating from Lidong Yan's patch series to enable Bloom filter usage with wildcard pathspecs and certain magic signatures where previously disabled. Key changes in revision.c: 1) Switched from forbid-mask to allow-mask approach for pathspec magic handling (Patrick Steinhardt's suggestion, endorsed by Junio Hamano) with variable renamed to `allowed_magic` for clarity 2) For wildcards, uses non-wildcard portion up to last directory separator for Bloom matching, with clarified behavior for first-component wildcards (falling back to non-filtered traversal) 3) Added comprehensive test coverage in t4216-log-bloom.sh, with fixes pending for commit message grammar (Junio suggests adding more rationale about allowed magic signatures), missing rationale documentation, and a bug in path component handling identified during review.

Benchmarks show significant improvements: 18-27% faster in Git repo tests, 47-63% faster in LLVM repo tests. Implementation carefully handles path components with thorough test coverage while maintaining backward compatibility. Patrick Steinhardt provided detailed technical review focusing on implementation robustness (allow-mask approach), test quality, and edge cases (first-component wildcards). Junio Hamano concurred with technical direction while suggesting variable naming improvements and additional documentation. Yan responded with fixes for all raised issues, committing to address in next version. Open questions resolved: allow-mask approach accepted, first-component wildcard behavior clarified. Performance gains remain substantial, particularly in larger repositories, with no fundamental design issues remaining.
