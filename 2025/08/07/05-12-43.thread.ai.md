Performance optimization for Bloom filters in revision traversal with wildcard pathspecs, originating from Lidong Yan's patch series (now at v4 with final cleanup). The series enables Bloom filter usage with wildcard pathspecs and specific pathspec magic signatures (top, glob, attr, --depth, literal) while excluding incompatible ones (exclude, icase) through an allow-mask approach (`allowed_magic` variable). For wildcards, it uses the non-wildcard portion up to the last directory separator for Bloom matching, with clear fallback to non-filtered traversal for first-component wildcards.

Key technical changes in revision.c include: 1) Implementation of allow-mask approach for pathspec magic handling (Patrick Steinhardt's suggestion) 2) Robust wildcard handling strategy with clarified behavior for edge cases 3) Comprehensive test coverage in t4216-log-bloom.sh verifying both positive and negative cases. Performance benchmarks show consistent improvements: 18-27% faster in Git repo tests (e.g., `git log -100 -- "t/*"` 23.4ms->20.4ms) and 47-63% faster in LLVM repo (`git log -100 -- "libc/*"` 26.7ms->16.0ms).
