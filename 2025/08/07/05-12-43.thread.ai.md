Performance optimization for Bloom filters in revision traversal with wildcard pathspecs. Originating from Lidong Yan's patch series to enable Bloom filter usage with wildcard pathspecs and certain magic signatures where previously disabled. Key changes in revision.c: 1) Only disable Bloom filters for pathspecs containing PATHSPEC_EXCLUDE or PATHSPEC_ICASE magic (was all magic before), with Patrick Steinhardt suggesting an allow-mask approach for better future compatibility 2) For wildcards, use non-wildcard portion up to last directory separator for Bloom matching, with discussion of edge cases when wildcards appear in first path component 3) Added comprehensive test coverage in t4216-log-bloom.sh, with suggested improvements for heredoc indentation and test_when_finished cleanup usage. Benchmarks show significant improvements: 18-27% faster in Git repo tests, 47-63% faster in LLVM repo tests. Implementation handles path components carefully with thorough test coverage. Maintains backward compatibility while expanding Bloom filter applicability to common wildcard use cases. Performance gains particularly notable in larger repositories. Open questions include whether to switch to allow-mask approach for pathspec magic and potential edge cases in wildcard path component handling. Patrick Steinhardt has provided detailed technical review focusing on implementation robustness and test quality while affirming the core approach.
