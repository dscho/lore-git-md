Performance optimization for Bloom filters in revision traversal with wildcard pathspecs. Originating from Lidong Yan's patch series (now at v2) to enable Bloom filter usage with wildcard pathspecs and certain magic signatures where previously disabled. Key technical changes in revision.c: 1) Implemented allow-mask approach for pathspec magic handling (Patrick Steinhardt's suggestion) with variable renamed to `allowed_magic` for clarity, enabling specific signatures (top, glob, attr, --depth, literal) while excluding incompatible ones (exclude, icase) 2) For wildcards, uses non-wildcard portion up to last directory separator for Bloom matching, with clarified behavior for first-component wildcards (falling back to non-filtered traversal) 3) Added comprehensive test coverage in t4216-log-bloom.sh verifying both positive and negative cases, including various magic signatures and wildcard positions.

Junio Hamano's review of v2 focuses on edge cases in wildcard handling, confirming correct behavior for full-wildcard paths ("builtin*") while suggesting code simplifications: initialize `res` to -1 (pessimistic), move zero-length check before allocation, eliminate redundant `strlen()`, and remove misleading leading-slash example from comments.
