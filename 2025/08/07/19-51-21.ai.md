This is the third patch in a 4-part series fixing corruption issues in `git archive`'s ZIP output for large files. The patch refactors the zlib compression loop in `archive-zip.c` to properly handle cases where `git_deflate()` cannot process all input data in a single pass.

The change wraps the existing compression call in a `do-while` loop that continues processing the same input buffer until all data is consumed (indicated by `zstream.avail_out` being non-zero). This matches Git's standard zlib usage patterns and prevents data loss that could occur when the original code assumed single-pass completion.

René Scharfe reviews the change positively, noting it corrects the mistaken assumption that `deflateBound()` implies single-pass processing capability. The patch maintains all existing error checking and Z_OK validation while making the compression more robust. This continues the series' pattern of improving `write_zip_entry()`'s zlib handling through incremental, well-reasoned changes that have received consistent approval from reviewers.

Key technical elements remain the `zstream` state management and `compressed` output buffer in `archive-zip.c`. The change adds proper input processing without altering the core compression logic or error handling paths.
