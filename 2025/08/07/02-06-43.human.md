Bugfix addressing inconsistent behavior between content-ignoring diff options (`-w`, `-I`) and metadata outputs (`--name-status`, `--raw`). This is the final version (v4) of a patch that has gone through extensive review, with Jeff King's sign-off and Junio Hamano's approval of the approach.

The core issue is that Git currently checks only SHA values for metadata outputs, ignoring content-filtering options, which can show files as changed in `--name-status` but unchanged in `--patch` output. The solution introduces a `dry_run` mode in `diff_options` and a new `diff_flush_patch_quietly()` helper that quickly checks for actual changes when content-ignoring options are active.

Key implementation details:
- New boolean `dry_run` flag in `diff_options`
- `quick_consume()` callback detects changes without full processing
- Special handling for metadata outputs when content filters are active
- Comprehensive test coverage added
- Performance impact kept minimal by avoiding full diff generation

The patch represents the culmination of a thread where the initial `/dev/null` redirection approach evolved into this cleaner solution. All major technical questions appear resolved, and this version addresses final code quality feedback from Junio. The change makes diff behavior more consistent while maintaining the performance benefits of SHA comparisons when no content filters are active.
