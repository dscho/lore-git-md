Refactoring patch converting an if-else chain to a switch statement in remote.c's push error handling. This is a follow-up stylistic improvement to the recently concluded bugfix series about invalid object ID handling during push operations.

The patch transforms the nested if-else blocks in show_push_unqualified_ref_name_error() into a switch statement for better readability, maintaining identical behavior. The function provides user advice when pushing invalid object types (commits, tags, trees, blobs) to unqualified refs. This change was suggested during review of the original series but was considered out of scope at the time.

Key technical details:
- Changes only the control flow structure in remote.c's error advising logic
- Preserves all existing error messages and conditions exactly
- Handles the same OBJ_* types (COMMIT, TAG, TREE, BLOB) plus default case
- Maintains identical advise() output formatting
- Each case includes the same matched_src_name and dst_value parameters

The patch has already received implicit approval from both Junio C Hamano and Patrick Steinhardt during the original thread's discussion, where they suggested this improvement as a follow-up. Denton Liu now implements it as a clean-up after the main series was finalized. The change is purely stylistic with no functional impact on Git's push behavior or error reporting.
