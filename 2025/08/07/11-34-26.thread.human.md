Here's a human-readable summary of the thread so far:

Petar Vutov has proposed adding partial cloning support for submodules, which would allow filtering submodule contents during clone and update operations. The key idea is to introduce a new `submodule.<name>.filter` configuration in `.gitmodules` that would work similarly to Git's existing partial clone filters (`--filter` flag). This would let users to specify which parts of a submodule's content they want to fetch, rather than always getting the full history.

The proposal suggests leveraging Git's existing partial clone plumbing to implement this feature. When updating submodules recursively, the system would respect these filter specifications, potentially excluding filtered submodule content from status output. The change would primarily affect `git-submodule.sh` and related plumbing commands.

This is still an RFC-stage proposal - the author is seeking feedback on the general approach before implementation. Some open questions remain, including the exact filter syntax and how to best handle recursive operations. The feature would build on Git's existing partial clone capabilities while addressing a specific pain point in submodule workflows.
