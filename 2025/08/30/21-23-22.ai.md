This is a bugfix patch in the multi-pack-index (midx) series, addressing a segfault that can occur during `git multi-pack-index repack` and `git multi-pack-index expire` operations. The issue stems from improperly initialized memory when loading packfiles in `fill_packs_from_midx()`, a regression introduced in Git 2.47.0.

The patch makes several key changes to `midx-write.c`:
1. Reverts `fill_packs_from_midx()` to its previous behavior of not relying on incremental flags or preferred pack names, while maintaining the ability to scan incremental midx layers
2. Moves the `open_pack_index()` call to just before it's needed for preferred pack selection
3. Skips allocating space in the pack_info array if pack preparation fails
4. Fixes error handling to properly use 0/1 return values

A new EXPENSIVE test is added that creates 100 packfiles to reliably reproduce the issue under SANITIZE=address. The test demonstrates the segfault occurs when closing packfiles later in the process, though the root cause is in the earlier pack initialization.

This is patch 1/6 in the v2 series, building on previous discussion that identified the regression from fcb2205b77. The changes address the immediate segfault while preserving the incremental midx functionality. The test provides concrete validation of the fix under stress conditions.
