Bugfix for the interactive add interface's input handling. This patch addresses a subtle but potentially confusing behavior in `git add -i` where malformed numerical input like "2m3" would be silently interpreted as a range selection (equivalent to "2-"). The change makes the interface reject such invalid input outright rather than trying to guess the user's intent.

The fix is straightforward - adding a single else clause to mark invalid input when parsing fails. While the impact is limited to interactive sessions, it improves the robustness of a core workflow command. The patch is small and focused, with a clear commit message explaining both the problem and solution. No test changes are included, which might be worth requesting given this is user-facing behavior.
