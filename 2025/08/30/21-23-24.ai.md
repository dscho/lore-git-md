Bugfix for midx incremental write error handling. This is patch 3/6 in Derrick Stolee's series addressing midx-write issues, following up on Taylor Blau's original work. The patch focuses on improving error handling during incremental midx writes by replacing direct `return -1` statements with proper cleanup paths that set the result variable before jumping to cleanup.

The changes ensure proper resource cleanup when incremental midx writes fail, particularly around temporary file handling and chain file operations. The patch modifies several error paths in `write_midx_internal()` to:
1. Set `result = -1` before cleanup when temporary file creation fails
2. Handle shared permission adjustment failures
3. Properly clean up when opening the multi-pack-index chain file fails
4. Handle midx-to-chain linking failures
5. Clean up properly when renaming temporary midx layers fails

The commit message notes these error conditions are difficult to reproduce in tests, which explains why the memory issues weren't caught earlier. The changes align with the series' overall goal of hardening midx-write error handling, following feedback from Taylor Blau and Junio Hamano to standardize on pessimistic initialization and proper cleanup patterns.

This is a straightforward improvement to existing functionality rather than new behavior, continuing the series' focus on making midx-write operations more robust. The changes are contained to `midx-write.c` and complement the earlier patches' fixes for packfile handling and error code restoration.
