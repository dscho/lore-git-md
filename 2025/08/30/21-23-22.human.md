This is a bugfix patch in a series addressing segfaults in the multi-pack-index (midx) functionality. It's the first of six patches in version 2 of the series, focusing on fixing a memory corruption issue that occurs during `git multi-pack-index repack` and `git multi-pack-index expire` operations.

The patch fixes a regression introduced in Git 2.47.0 where improperly initialized memory could be accessed when closing packfiles. The issue manifests as a segfault under memory sanitizers when working with many packfiles (100 in the new test case). The fix restores safer behavior in `fill_packs_from_midx()` while maintaining the ability to scan incremental midx layers.

Key changes include:
- Removing reliance on incremental flags/preferred pack names during pack loading
- Moving pack index opening to when it's actually needed
- Adding a stress test with 100 packfiles that reliably reproduces the issue
- Maintaining the existing error return convention (0 for success, 1 for failure)

The test is marked EXPENSIVE due to the resource requirements of creating and managing 100 packfiles. The patch appears well-constructed with a clear explanation of both the problem and solution, and it addresses a concrete issue that could affect users running maintenance operations.
