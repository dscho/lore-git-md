This is a cleanup patch in the multi-pack-index (midx) bugfix series, focusing on error handling simplification in `write_midx_internal()`.

The patch standardizes the error handling pattern throughout the midx writing code by initializing the `result` variable to -1 (error) at the start and only setting it to 0 (success) at the very end of successful execution paths. This replaces the previous approach where `result` was initialized to 0 and error cases had to explicitly set it to 1 or -1 before jumping to cleanup. The change makes the code more consistent and reduces the chance of missing error state assignments.

Several cleanup jumps that previously required explicit error state setting now rely on the default -1 value, making the control flow simpler. The patch also fixes an inconsistency where some error paths returned 1 while others returned 1 - now all errors consistently return -1. The changes are mechanical and don't affect functionality, but improve code maintainability by making the patterns more predictable.

This is the final patch in a 6-part series that has already addressed critical midx bugs and received positive reviews. The changes here are purely about code quality, building on the earlier substantive work to fix segfaults and improve error handling. The patch follows the series' theme of making midx-write.c more robust and maintainable.
