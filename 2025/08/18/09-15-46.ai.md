Bugfix attempt for submodule hash algorithm mismatch issue, addressing previous feedback. This is a revised version of the patch that handles cases where a submodule uses a different hash algorithm (and thus different hash length) than its superproject. The key change is using the submodule's hash algorithm when converting commit hashes to hex strings during fetch operations, rather than truncating hashes.

The patch modifies `builtin/submodule--helper.c` to:
1. Extend `get_default_remote_submodule()` to optionally return the submodule's hash algorithm
2. Use `hash_to_hex_algop()` with the submodule's algorithm when fetching specific commits
3. Maintain existing behavior in other code paths by passing NULL for the hash algorithm parameter

This version responds to Junio C Hamano's earlier feedback about implementation elegance by using `hash_to_hex_algop()` instead of manual truncation. However, it doesn't yet address Brian M. Carlson's more fundamental concern about whether mixed hash algorithms in submodules are viable at all, particularly regarding tree object compatibility. The patch focuses narrowly on fixing the shallow clone fetch case while leaving the larger architectural questions open.
