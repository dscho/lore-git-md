Maintainer approval for error reporting in `git describe` blob handling.

Junio Hamano agrees with Jeff King's patch to make `git describe` report an error when a blob cannot be found, rather than silently succeeding with empty output. This brings the blob behavior in line with how commits are handled. The change is implemented by adding a `die()` call when the output strbuf remains empty after attempting to describe the blob.

The patch includes a new test case verifying the error message appears for unreachable blobs. Junio finds the approach sensible, noting that silent success without useful output is uncharacteristic of Git's usual behavior. This was the second patch in a 5-part series overhauling `builtin/describe.c`, with the first patch already approved for merging.

The change is technically complete but represents a behavior change that might affect scripts relying on the old silent behavior. The discussion suggests this was likely an unintentional bug rather than a deliberate design choice, given that blob support was added after the initial commit-focused implementation.
