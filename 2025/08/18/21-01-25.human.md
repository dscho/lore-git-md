This is patch 2/5 in a bugfix series addressing edge cases in `git describe`'s blob handling. The patch fixes an inconsistency where `describe_blob()` would silently return an empty string for unreachable blobs, while `describe_commit()` properly errors out. Jeff King argues this was likely an oversight when blob support was added, not intentional behavior.

The change makes `describe_blob()` die with an error message when the blob isn't reachable from HEAD, matching the commit behavior. A new test confirms the error is properly reported. While this changes user-visible behavior, the author considers it clearly bug-fixing rather than controversial, though notes it's the most debatable change in the series.

The implementation takes a straightforward approach rather than tracking the strbuf's original size as in René Scharfe's earlier version, since the function's single caller always passes an empty buffer. This continues the series' work to make blob handling more robust and consistent with the rest of `git describe`.
