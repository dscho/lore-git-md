Bugfix discussion regarding submodule hash algorithm interoperability. Michael Schroeder responds to Brian M. Carlson's concerns about potential data corruption when mixing SHA-1 and SHA-256 algorithms between superprojects and submodules.

Schroeder argues the current behavior (where Git either truncates or zero-pads commit hashes depending on direction) already works in practice for non-shallow clones, citing existing usage and Git's prefix matching behavior. He maintains his patch specifically targets the shallow clone case where fetches currently fail.

The exchange reveals a fundamental disagreement: Carlson believes mixed hash algorithms should be prohibited entirely to prevent data corruption, while Schroeder sees value in supporting the existing behavior. Schroeder questions whether Carlson's proposed solution (using compatObjectFormat) would actually work, especially for shallow clones.

This email doesn't introduce new code but clarifies the practical considerations behind the earlier patch, highlighting the tension between theoretical correctness and real-world usage patterns. The discussion remains unresolved on whether to support mixed hashes at all versus enforcing algorithm consistency.
