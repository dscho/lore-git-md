Bugfix for line-log assertion failures when using multiple `-L` ranges. This is the first patch in a two-part series addressing issues reported by Evgeni Chasnovski where Git would either crash with an assertion error, enter an infinite loop, or show incorrect output when processing multiple disjoint line ranges in the same file.

The core issue stems from incorrect handling of line range boundaries in three places within `line-log.c`, where the code mistakenly treated the 'end' of a range as inclusive rather than exclusive. The patch carefully explains each problematic case with clear examples, showing how the miscalculations led to the various failure modes. The fixes involve adjusting comparison operators in `diff_ranges_filter_touched()`, `range_set_difference()`, and `dump_diff_hacky_one()`.

The patch includes comprehensive test coverage with new expected output files for both SHA-1 and SHA-256 repositories, verifying the fixes handle the original assertion failure scenario and produce correct output when multiple line ranges interact with diff ranges. The test case is modeled after the reproduction scenario from the bug report.

This appears to be a well-researched and thorough fix for a real edge case in the line-log functionality. The commit message provides excellent technical detail about both the problems and solutions, making it easy to understand the changes. The test coverage gives confidence that the fixes work as intended across different hash implementations.
