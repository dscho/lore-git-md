Bugfix addressing an output correctness issue in Git's line-log functionality when multiple `-L` ranges are specified. This is the second patch in SZEDER Gábor's series fixing line-log problems, following up on the initial assertion failure fix.

The patch corrects a case where `git log -L` would only show changes when a diff range affected the first of multiple specified line ranges, even if it also affected subsequent ranges. The fix modifies `dump_diff_hacky_one()` in line-log.c to properly handle cases where a single diff range touches multiple disjoint line ranges by adjusting the range comparison logic.

Notably, the bug has existed since the initial line-log implementation in 2013, and the patch reveals that two test cases (added in 2da1d1f6f and 209618860c) had incorrect expected output all along - they should have been failing but weren't due to the bug. The patch updates these test expectations to match the corrected behavior, with identical updates needed for both SHA-1 and SHA-256 test variants.

The change is relatively small (9 lines added) but has significant impact on the correctness of line-log output. It completes the series' goal of fixing all known issues with multiple `-L` range specifications, building on the previous patch's fixes for assertion failures and infinite loops. The comprehensive test updates provide confidence in the fix across both hash implementations.
