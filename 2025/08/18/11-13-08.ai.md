This is a bugfix series addressing issues in Git's line-log functionality, specifically around handling multiple `-L` range specifications. The series comes from SZEDER Gábor in response to a bug report from Evgeni Chasnovski about assertion failures when using multiple `-L` flags.

The first patch fixes an assertion error that occurs with specific combinations of line ranges and diff ranges. The commit message notes this wasn't just a simple assertion fix - it uncovered additional issues including an infinite loop and incorrect output that also needed addressing. The fix modifies `line-log.c` and adds several test expectations to verify the behavior.

The second patch addresses another unrelated line-log output issue discovered while testing the first fix. It ensures all line ranges touched by the same diff range are properly shown. This also includes test updates to verify the corrected behavior.

The series includes comprehensive test coverage with new expected output files for both SHA-1 and SHA-256 repositories, suggesting the author took care to validate the fixes across different hash implementations. The test cases appear to cover both the original assertion failure scenario and the additional output correctness issues.
