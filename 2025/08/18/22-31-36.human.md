This is a policy and direction discussion in the ongoing Rust integration effort, specifically regarding the xdiff optimization series.

Junio Hamano responds to Ezekiel Newren's cover letter for the RFC series that introduces Rust as a hard dependency with xdiff optimizations. While generally supportive of establishing Rust coding standards (suggesting rustfmt adoption), Junio raises several important considerations about the series' direction.

He questions whether the performance improvements (5-19% claimed) are truly due to Rust itself or rather from the faster hash function implementation, noting that speed wasn't the primary motivation for Rust adoption. Junio expresses mild disappointment that this series overlaps with another optimization effort (am/xdiff-hash-tweak) that could have been integrated separately, suggesting future Rust experiments might better target different code paths.

The email also addresses practical concerns about Rust version requirements across platforms, accepting that some platforms may need newer versions due to port quality issues, as long as it doesn't require extensive version-specific codepaths. This maintains the thread's focus on establishing foundational policies for Rust integration while acknowledging the tension between optimization efforts and the primary goal of safely introducing Rust infrastructure.

The response indicates the series is nearing acceptance but highlights ongoing questions about Rust's role in performance improvements versus its value for code safety and maintainability. Junio's comments suggest the technical implementation is sound but the framing of benefits may need adjustment in future iterations.
