This is part 3 of a bugfix series addressing error handling in `git describe`'s blob description functionality. The patch specifically handles the case where a user tries to describe a blob while on an unborn branch (no HEAD commit exists).

The patch adds an explicit check for this case using `repo_get_oid()` and provides a clear error message, replacing what would have been a silent failure or crash. Maintainer Junio Hamano has approved the approach, noting that while there's potential future work to make blob description more flexible (by searching beyond just HEAD), this change represents a clear improvement over the current behavior.

Jeff King (the author) acknowledges there might be room for enhancement via a new option to search more broadly for blobs, but considers that out of scope for this series focused on fixing error cases. The discussion also touches on some implementation details around HEAD resolution methods, but concludes the current approach is sufficient.

This continues the series' pattern of replacing silent failures with explicit errors, with patches 1-2 already approved and patches 4-5 still under review. The change is well-motivated and comes with test coverage for the new error case.
