Bugfix follow-up addressing hash algorithm mismatch in submodule fetches. This is version 2 of Michael Schroeder's patch to handle cases where a superproject and submodule use different hash algorithms (e.g., SHA-256 vs SHA-1). The key change is using the submodule's hash algorithm when converting commit hashes during fetch operations, rather than truncating hashes as in the previous version.

The patch modifies `builtin/submodule--helper.c` to pass the submodule's hash algorithm through the call chain, using it in `hash_to_hex_algop()` when fetching specific commits. This addresses the shallow clone case where zero-padded hashes from the superproject would previously fail when interpreted as refnames in the submodule.

While this version improves on the initial approach, the thread's broader discussion (notably from Brian M. Carlson) suggests there may be fundamental limitations to mixing hash algorithms between superprojects and submodules. The patch appears technically sound for its specific case but may not resolve all interoperability concerns raised in the thread.
