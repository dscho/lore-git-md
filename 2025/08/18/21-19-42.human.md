This is patch 3/5 in a bugfix series improving error handling in `git describe` for edge cases involving blobs. The patch specifically addresses the case where a user tries to describe a blob while on an unborn branch (a branch that exists but has no commits yet).

The change makes `describe_blob()` explicitly check for and reject this case with a clear error message, rather than silently failing or producing incorrect output. The implementation uses `repo_get_oid()` to check HEAD status, which maintainer Junio Hamano confirms is a reasonable approach despite initial expectations of using the refs subsystem directly.

A new test case verifies the behavior by creating an unborn branch and confirming the expected message appears when attempting to describe a blob. The patch follows the series' pattern of replacing silent failures with explicit error reporting, though Hamano notes this is a strict improvement rather than an enhancement of the blob search functionality.

With patches already approved in this series, this one appears to be a straightforward addition that completes the error handling for another edge case. The implementation looks clean and maintains consistency with the series' goals.
