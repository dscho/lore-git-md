This is a small refactoring patch in the `git describe` series, specifically addressing object ID handling. The patch changes how `struct object_id` parameters are passed in `builtin/describe.c`, switching from passing by value to passing by const pointer, which is the more conventional pattern in the Git codebase.

The changes are straightforward and uncontroversial:
1. Updates the `describe_blob()` function signature and its single call site
2. Modifies the `process_commit_data` struct to store a pointer rather than a full copy of the OID
3. Adjusts the comparison logic in `process_object()` to work with the pointer

Junio Hamano has already acknowledged the change positively, noting it makes the code "less odd." The patch appears to be a clean improvement that follows existing patterns without changing behavior. It's part of a larger series (5 patches) that's nearing completion, with this being a minor but sensible cleanup noticed while working in the area.
