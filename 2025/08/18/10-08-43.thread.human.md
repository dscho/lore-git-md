Seyi Kuforiji proposed adding a `--with-line-numbers` flag to `git format-patch` to include line numbers in patch context, aiming to simplify code review by making it easier to reference specific changes. The initial proposal suggested this would be a purely cosmetic change that wouldn't affect how patches apply.

Junio Hamano, the Git maintainer, has now responded with skepticism about both the need for and feasibility of the feature. He questions how often line number references are actually used in reviews and asks for concrete examples where manual line counting has been problematic. More critically, he points out that the straightforward implementation of inserting line numbers would actually break patch application - a fundamental technical constraint that any solution would need to work around.

The discussion has now shifted from a general proposal to needing to address specific concerns: demonstrating real-world cases where this would help reviewers, and finding an implementation approach that preserves patch applicability while adding the line number information. Junio's response suggests this will need stronger justification and a more carefully thought-out technical design before it could move forward.
