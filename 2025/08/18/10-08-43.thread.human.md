This thread began with Seyi Kuforiji proposing a `--with-line-numbers` flag for `git format-patch` to make patch review easier. The discussion revealed this was unnecessary - Junio Hamano demonstrated that the existing hunk header syntax (`@@ -L,K +M,N @@`) already provides equivalent line number information, and that modifying the context lines would break patch application. Seyi withdrew the proposal upon understanding this.

In a follow-up, Junio suggested documenting hunk header interpretation in the MyFirstContribution guide rather than the formal documentation, since the syntax is already specified by POSIX. This serves as a helpful reference for new contributors while keeping core documentation focused. The thread is now fully resolved, with no remaining action items beyond potential documentation improvements for contributor onboarding.
