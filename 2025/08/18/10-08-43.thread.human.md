This thread explored a proposal to add `--with-line-numbers` to `git format-patch`, aiming to include line numbers in patch context for easier review. The idea came from Seyi Kuforiji, who initially believed this would help reviewers locate changes more easily in email-based patch review.

Junio Hamano, the Git maintainer, raised several concerns - both questioning whether this was actually needed (since hunk headers already provide line number context) and demonstrating that inserting numbers into context lines would technically break patch application. After this discussion, Seyi recognized they had misunderstood how to interpret the existing `@@ -L,K +M,N @@` hunk headers, which already provide the line number information they were seeking. 

Seyi has now acknowledged Junio's points and withdrawn the proposal, considering the feature unnecessary given that the information is already present in the standard diff format. They suggest that better documentation explaining hunk headers might help others avoid similar confusion, though no specific wording is proposed. Unless new use cases emerge where hunk headers prove insufficient, this thread appears resolved with no changes planned to `git format-patch`.
