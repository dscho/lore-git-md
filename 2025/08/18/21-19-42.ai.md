This is patch 3/5 in the series improving error handling in `builtin/describe.c`, specifically addressing the case of blob description on an unborn branch. The patch adds explicit error checking for the unborn branch case, where previously the code would silently fail or produce incorrect results.

The key changes are:
1. Adds a check for HEAD resolution failure using `repo_get_oid()`, with a new error message when attempting to describe a blob on an unborn branch
2. Includes a test case that verifies the new error behavior by temporarily making HEAD point to a non-existent branch
3. Maintains consistency with the series' goal of replacing silent failures with explicit error reporting

Junio Hamano's review notes that while the implementation could theoretically be enhanced to search beyond HEAD, this patch represents a strict improvement over the current behavior. The review also observes an unrelated issue with object ID copying in the `process_commit_data` struct initialization that could be addressed separately.

This patch builds on the already-approved patches 1 and 2, continuing the series' pattern of defensive programming and explicit error handling. The test case follows the pattern established in patch 2's unreachable blob test, maintaining consistent error reporting behavior across different failure modes in the describe functionality.
