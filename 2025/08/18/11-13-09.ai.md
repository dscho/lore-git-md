Bugfix for line-log assertion failures and incorrect output with multiple `-L` ranges. This first patch in SZEDER Gábor's series addresses three related issues in the line-log machinery when processing multiple disjoint line ranges in the same file. The problems occur when a commit's diff hunk starts immediately after one line range ends, causing incorrect range comparisons that treat the exclusive 'end' boundary as inclusive.

The patch fixes three distinct manifestations of this boundary condition:
1. An assertion failure in `range_set_append()` when shifted ranges overlap
2. An infinite loop in `range_set_difference()`
3. Incorrect output showing unmodified line ranges

The core fix modifies three comparison conditions in `line-log.c` to properly handle the exclusive range boundaries. The changes are minimal (6 lines modified) but touch critical path logic in the line-range processing. The patch includes a comprehensive test case that reproduces the original failure scenario and verifies correct output, with parallel test files for SHA-1 and SHA-256 repositories.

The commit message provides detailed technical analysis of each issue and fix, along with before/after command output demonstrating the corrected behavior. This appears to be a well-researched fix for a clear bug, with thorough test coverage across hash implementations. The patch builds on Evgeni Chasnovski's bug report and addresses all described failure modes while maintaining the existing line-log semantics.
