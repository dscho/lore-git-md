Feature proposal for `git format-patch` to add line numbers in patch emails.

Seyi Kuforiji proposes adding a `--with-line-numbers` flag to `git format-patch` to help with code review on the mailing list. The motivation comes from their experience sending patches where reviewers had to manually count lines to reference specific issues. The feature would add line numbers as visual markers without affecting patch application.

The benefits are clear: it would make mailing list reviews more efficient by allowing direct line references ("line 52 has an issue") rather than requiring manual counting. This could be particularly helpful for new contributors. The author acknowledges potential concerns about visual clutter but suggests this could be addressed in the implementation.

The proposal is well-motivated by a concrete pain point in the review process. The author is seeking feedback before implementing, which suggests they're approaching this collaboratively. The feature seems relatively straightforward and focused, though the actual implementation would need to carefully consider formatting to avoid making diffs harder to read.
