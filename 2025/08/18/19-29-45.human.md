This is a feature request proposing to allow nested interactive rebases. Isaac Oscar Gariano describes a common workflow pain point where they realize they need to make additional changes during an ongoing rebase, but Git currently prevents starting a new rebase while one is already in progress.

The proposal suggests modifying `git rebase` to allow nesting by:
1. Computing a new todo list and prepending it to the current one
2. Resetting to the new start point
3. Maintaining some limitations (likely only working with the merge backend)

The email includes a proof-of-concept fish script demonstrating how this could work by manipulating the rebase-merge directory contents. The script handles edge cases like label conflicts between the nested rebases.

The author is gauging interest in this feature before potentially implementing it in Git proper, noting they could alternatively just maintain a wrapper script for personal use. The proposal seems well-motivated by a concrete workflow problem, though the implementation details would need careful consideration to avoid introducing edge cases or confusing behavior.
