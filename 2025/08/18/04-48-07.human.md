Bugfix discussion for `git describe`'s blob-handling edge case. Jeff King responds to René Scharfe's analysis of callback safety in the `describe_commit()` interface redesign, confirming that the current code can indeed segfault when processing a corrupted repository where HEAD points to a non-commit object. 

King demonstrates how to trigger this by manually pointing HEAD to a tag referencing a blob, showing the existing code would dereference NULL. While this represents repository corruption, he argues the code should handle it gracefully. The discussion reveals this blob-describing behavior may be a historical artifact, with `--find-object` now providing better alternatives.

The exchange solidifies the case for the proposed interface changes while uncovering a real (though obscure) edge case the new design would need to handle. King's analysis suggests the feature's blob-handling behavior might warrant deprecation in a future major version. The thread shows technical consensus forming around both the immediate NULL-dereference fix and broader interface improvements.
