Bugfix patch in the `describe` command series, addressing error handling for unreachable blobs.

This is patch 2/5 in Jeff King's series to improve error handling and safety in `builtin/describe.c`. The patch changes `describe_blob()` to explicitly error out when it cannot find the requested blob, rather than silently returning an empty string. This brings its behavior in line with `describe_commit()`, which already fails loudly in such cases.

The key technical change is adding a check for an empty `strbuf` in `describe_blob()` and calling `die()` with an appropriate error message. The patch includes a new test case that verifies this behavior by attempting to describe an intentionally unreachable blob. Junio Hamano agrees with the change, noting that silent success without useful output is not Git's usual behavior.

This patch follows the already-approved first patch in the series (which handled object ID conversions) and precedes patches addressing unborn branch handling, corrupted HEAD cases, and redundant commit lookups. The change is somewhat behavior-changing but considered justified as fixing what appears to be an unintentional bug in the original implementation. The implementation avoids being overly defensive since the function has only one caller that always passes an empty strbuf.
