This is the third patch in a bugfix series improving `git describe`'s handling of edge cases, particularly around blob descriptions. The patch addresses a specific issue where describing a blob on an unborn branch produces a confusing error message.

The problem occurs when `git describe` tries to traverse from HEAD that points to a non-existent branch (an "unborn" branch). Currently, it fails with a generic message about ambiguous arguments. The patch improves this by first resolving HEAD explicitly and providing a more specific error message when the branch is unborn: "cannot search for blob '%s' on an unborn branch".

The change is straightforward - it moves the HEAD resolution earlier in the process and handles the error case explicitly. The patch includes a new test case that verifies the improved error message appears when expected. This continues the series' pattern of making error conditions more explicit and user-friendly while maintaining the existing behavior where valid cases work as before.

This patch builds on the previous work in the series (patch 1 refactored object_id handling, patch 2 made blob-not-found errors explicit) and maintains the same careful approach with thorough test coverage. The change seems well-contained and unlikely to cause controversy, as it's clearly an improvement over the current behavior.
