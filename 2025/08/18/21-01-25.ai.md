This is patch 2/5 in a bugfix series addressing edge cases in `git describe`'s blob handling. The patch focuses on error reporting when a requested blob cannot be found in the repository.

The change makes `describe_blob()` consistently fatal when it cannot describe a blob, matching the behavior of `describe_commit()`. Currently, the function silently returns an empty string when a blob isn't found, which appears to be an unintentional inconsistency from when blob support was added. The patch adds a `die()` call when the output was generated, along with a new test case verifying the error message.

Key technical details:
- Adds error check after blob description attempt fails
- Uses same `die()` pattern as commit handling
- New test creates an unreachable blob and verifies failure
- Error message includes blob OID for identification
- Follows the series' pattern of making error handling more consistent

The patch represents one of the more behaviorally significant changes in the series, as noted by the author's comment about it being "the most controversial". It transitions from silent failure to explicit error reporting, which could potentially affect scripts relying on the current behavior. The implementation avoids over-engineering by not tracking the strbuf's original state, given the constrained calling context.

This change builds on the preparatory refactoring from patch 1 and will be followed by patches addressing other edge cases (unborn branches and blob traversal with no commits). The test coverage expansion continues the series' thorough validation approach.
