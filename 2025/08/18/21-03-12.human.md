Bugfix patch addressing edge case in `git describe` blob handling, part of a series improving `builtin/describe.c` safety.

This fourth patch in the series fixes a segfault that occurs when trying to describe a blob in a corrupted repository where HEAD points directly to a blob rather than a commit. The issue arises because the code assumes it will always have a valid commit to work with during traversal. The fix adds a check for the null OID case and returns an empty result, which triggers the existing "blob not found" error path.

The patch acknowledges this is a rare case that requires repository corruption to trigger (by manually setting HEAD to a blob hash), and that the fix represents a minor lie since the blob was technically "found" but not in a meaningful way. The author explains why more complex cases (like tags pointing directly to blobs) don't need handling here, as the code's purpose is specifically to find blobs within commits.

Notably, this patch doesn't include a test case because creating the necessary corruption is only straightforward with the files ref backend, and the test overhead was deemed not worthwhile for such an edge case. The change is small (4 lines added/changed) and builds on the safety improvements from earlier patches in the series.

This continues the thread's pattern of methodically addressing edge cases while maintaining the tool's core purpose of describing objects within commit history. The patch appears well-considered, with clear reasoning about what cases do and don't need handling.
