This is a refactoring patch that's part of a larger series addressing edge cases in `builtin/describe.c`. It's the first of five patches implementing agreed-upon solutions for blob handling in `git describe`.

The patch changes how object_id structs are passed in the describe_blob() function and related callbacks, switching from passing by value to passing by pointer. This aligns with Git's typical convention for handling object_ids. The changes are mechanical but improve consistency:
- describe_blob() now takes a const pointer to object_id
- The process_commit_data struct holds a pointer rather than a full copy
- All related comparisons and function calls are updated to use pointer syntax

The change doesn't affect functionality but makes the code more idiomatic. As noted in the commit message, this was inspired by recent discussions about object_id handling patterns. The patch serves as preparatory cleanup before the subsequent patches that implement the actual edge case fixes.

Key technical details for future reference:
- Modifies process_commit_data struct to store looking_for as pointer
- Updates process_object() callback to use pointer comparison
- Changes describe_blob() signature and its call site
- Maintains same behavior through const-correct pointer usage
