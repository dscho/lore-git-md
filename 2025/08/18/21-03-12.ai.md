Implementation patch addressing edge case in blob description handling, part of the ongoing `builtin/describe.c` safety redesign series. This fourth patch in the five-part series fixes a segfault that occurs when attempting to describe a blob in a repository where HEAD points directly to a blob (an invalid state normally prevented by refs code). The solution adds a null check for the current commit OID before attempting to describe it, falling back to the existing "blob not found" error path.

Key technical details: The patch modifies `process_object()` in `builtin/describe.c` to skip commit description when `current_commit` is null, which maintains the expected behavior of reporting unfound blobs while preventing crashes. The change specifically handles the case where blob traversal starts with no commits seen, a scenario that requires repository corruption to trigger (by manually setting HEAD to a blob OID). The author notes this matches the original intent of finding blobs within commits, not standalone blobs, and deliberately omits a test case since it would require filesystem-level repository corruption.

This builds on patch 2's error reporting improvements and patch 3's unborn branch handling, completing the series' coverage of edge cases in blob description. The implementation follows the established pattern from earlier patches by maintaining safety while preserving existing behavior where valid. The change is narrowly scoped to prevent crashes without expanding functionality, consistent with the series' focus on hardening rather than feature addition.
