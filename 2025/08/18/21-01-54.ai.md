This is the third patch in a 5-part series addressing edge cases in `git describe` blob handling, following the architectural redesign of `builtin/describe.c`. The patch focuses on improving error reporting when attempting to describe a blob on an unborn branch.

The change modifies `describe_blob()` to explicitly check for and handle unborn branch cases by resolving HEAD before traversal. Previously, passing HEAD to `setup_revisions()` would fail with a generic "ambiguous argument" error when on an unborn branch. The new implementation provides a more specific error message ("cannot search for blob on an unborn branch") that directly explains the situation.

Key technical details:
- Adds `repo_get_oid()` check for HEAD resolution before traversal
- Replaces direct "HEAD" string with resolved OID in revision setup
- Includes new test case verifying the improved error message
- Maintains consistency with patch 2's error reporting approach
- Follows the series' pattern of explicit error handling

The patch continues the series' thorough test coverage approach with a new test case that:
1. Simulates an unborn branch by pointing HEAD to a non-existent ref
2. Verifies the expected error message appears
3. Includes cleanup to restore original HEAD

This change builds on the series' established patterns of NULL pointer handling and error reporting while addressing one of the remaining edge cases identified in the redesign discussion. The implementation matches the architectural direction established in earlier patches, with careful attention to both behavior and user-facing messaging.
