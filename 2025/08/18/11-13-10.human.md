This is the second patch in a bugfix series addressing line-log issues with multiple `-L` range specifications. The patch fixes a case where `git log -L` would only show changes from the first line range when a single diff range affected multiple disjoint line ranges in the same file.

The core issue stems from `dump_diff_hacky_one()` in line-log.c not properly handling cases where one diff range touches multiple line ranges. The fix adds logic to step back and show all affected line ranges when this occurs. The patch includes a clear example showing the incorrect output (only showing changes to lines 1-2) versus the corrected output (showing changes to lines 1-2, 4-5, and 7-8).

Interestingly, the author discovered this bug has existed since the initial line-log implementation in 2013, and that two test cases had incorrect expected outputs that masked the issue. The patch updates these test expectations to match the correct behavior. The changes are hash-agnostic, with identical updates to both SHA-1 and SHA-256 test expectations.

This appears to be a well-justified fix with thorough test coverage. The patch builds on the first patch in the series (which fixed assertion failures and infinite loops) to complete the solution for multiple `-L` range handling. The changes are focused and the commit message provides clear before/after examples and historical context.
