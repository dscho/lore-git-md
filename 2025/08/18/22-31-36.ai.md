This is a policy discussion in the ongoing RFC series introducing Rust as a hard dependency with xdiff optimizations. Junio Hamano responds to Ezekiel Newren's cover letter questions about Rust adoption, focusing on three key areas: code style, version requirements, and performance tradeoffs.

On code style, Junio agrees that having a consistent Rust style (likely via rustfmt) is important, though defers to Rust experts to define the specifics. For version requirements, he accepts platform-specific Rust version variations as reasonable given Rust's rapid evolution, so long as it doesn't require pervasive version-specific codepaths.

The most substantive discussion centers on performance tradeoffs. Junio expresses concern about overlapping with the C-based xdiff optimization work (am/xdiff-hash-tweak), suggesting the series might have better targeted a different area for Rust experimentation. He clarifies that while the speed improvements (5-19%) are valuable, they stem primarily from hash function choice rather than Rust itself. Junio emphasizes that the primary goals for initial Rust adoption should be establishing the framework (platform support policies, FFI patterns, build integration) and demonstrating safety/ergonomic benefits, not performance.

This email doesn't introduce new technical changes but provides important maintainer perspective on the series' priorities. Junio's comments suggest the performance claims may need reframing to avoid overemphasizing speed as Rust's primary value proposition. The discussion also highlights ongoing tension between parallel optimization efforts and the need to clearly articulate Rust's role in Git's architecture.
