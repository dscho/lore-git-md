This is a documentation question about the behavior of `git count-objects -v`'s "garbage" field. Daniele Sassoli investigates why the field doesn't seem to count dangling objects (which are cleaned by `git gc`) and questions whether the documentation accurately describes its behavior.

The email notes that the "garbage" field is documented to count files in the object database that are neither valid loose objects nor valid packs, but practical testing shows it only counts random files manually placed in object directories, not corrupted objects or dangling references. The author questions whether this is a documentation issue, a misunderstanding of the term "garbage", or a bug in the implementation.

Key technical details for future reference: the "garbage" field appears to only count extraneous files in object directories (like lock files or manually created test files) rather than Git's internal concept of garbage (dangling objects). The test methodology involved corrupting objects (which `git fsck` detected but `count-objects` ignored) and creating non-Git files in object directories (which did increment the counter). The question centers on whether this behavior matches the documented intent.
