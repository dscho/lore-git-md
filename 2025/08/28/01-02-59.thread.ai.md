Thread identity: Bug report regarding deprecation of `git whatchanged` in Git 2.51.0 for Windows, affecting Jenkins CI pipelines.

Core problem: The `git whatchanged` command now requires explicit `--i-still-use-this` flag due to deprecation, breaking existing Jenkins workflows that invoke it without the flag. This is a known Jenkins issue (JENKINS-76017) but users cannot always immediately upgrade their Git client plugin.

Current status: No proposed fix in this report, but highlights real-world impact of the deprecation on existing tooling. The error occurs specifically when Jenkins pipelines call `git whatchanged` without the required flag, causing CI to fail.

Key technical details: The deprecation warning has become a hard error in Git 2.51.0 for Windows builds. The reporter suggests others may be similarly affected but haven't reported yet. The workaround would be migrating to `git log` alternatives, but this requires plugin updates not always immediately available.

Open questions: Whether the Git project should consider any mitigation for this transition period, or if the breakage is an expected consequence of deprecation that tooling must adapt to. No maintainer response yet to this specific report.

Participant positions: James Tuttle reports the issue from a user perspective, noting it affects their production CI but not proposing a code change. No other participants have replied yet.

Related work: Jenkins issue JENKINS-76017 tracks the need to update their Git client plugin to handle the `whatchanged` deprecation. The Git project's original deprecation notice for `whatchanged` (from 2018) suggested migration to `git log` as the preferred alternative.
