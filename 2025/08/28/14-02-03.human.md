Bugfix for gitk's preferences dialog when themed widgets are disabled. 

Mark Hills reports that in Alpine Linux 3.22 with Git 2.49.1, disabling the "Themed widgets" option in gitk's preferences causes the preferences window to fail to open on subsequent launches. The error shows Tcl/Tk failing to find the "combobox" widget command, suggesting the themed widgets setting affects widget availability.

The bug is easily reproducible: after disabling themed widgets and restarting gitk, attempting to open preferences triggers Tcl errors about missing combobox commands, resulting in an empty preferences window. The report includes detailed version information showing this occurs with Tcl/Tk 8.6.16.

This appears to be a regression where gitk assumes themed widgets will always be available for certain UI elements, rather than gracefully falling back to non-themed alternatives. The report provides clear reproduction steps and environment details, making it straightforward to verify. The issue affects core functionality (preferences dialog) in a way that could impact many gitk users who prefer non-themed widgets.
