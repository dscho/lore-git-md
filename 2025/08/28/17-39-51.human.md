Bugfix for midx (multi-pack-index) segfault during repack/expire operations. This is the first patch in a 5-part series addressing a regression introduced in Git 2.47.0 that could crash when handling many packfiles during maintenance.

The core issue occurs when `git multi-pack-index repack` or `expire` tries to access uninitialized pack data. Derrick Stolee's fix modifies `fill_packs_from_midx()` to properly initialize packs before adding them to the context, while maintaining the incremental midx behavior added in the original refactor. The patch includes a thorough test case that creates 100 packfiles to reliably reproduce the crash under ASAN.

Key technical changes:
- Removes premature packfile array growth before initialization
- Moves pack index opening closer to where it's actually needed
- Simplifies error handling by removing redundant checks
- The test is marked EXPENSIVE due to resource requirements but provides important coverage for this edge case.

This appears to be a well-constructed fix for a real regression, with clear commit message explaining both the problem and solution. The test case is particularly valuable as it demonstrates the failure mode and verifies the fix. Given this affects maintenance operations, it likely warrants prompt review from midx experts.
