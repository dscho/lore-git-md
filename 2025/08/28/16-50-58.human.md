This is a documentation clarification regarding the "garbage" field in `git count-objects -v` output. Elijah Newren responds to Daniele Sassoli's investigation into what constitutes "garbage" in Git's object database.

Newren explains that the garbage counter primarily catches temporary files left behind by interrupted operations - specifically partial packfiles from aborted pushes or fetches that remain with temporary names. This aligns with Sassoli's observation that manually created files increment the counter while corrupted Git objects do not.

The response suggests the current behavior is intentional, though perhaps not well-documented. The "garbage" field appears designed to track filesystem-level artifacts rather than Git's conceptual garbage (like dangling objects). This distinction between operational debris and unreachable objects may warrant clearer documentation.

The email doesn't propose any code changes but provides important context about expected behavior that could inform future documentation updates. The explanation helps bridge the gap between the technical implementation and user expectations about what "garbage" means in this context.
