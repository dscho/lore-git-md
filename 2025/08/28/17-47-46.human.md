This is a follow-up discussion about documentation improvements, specifically around making Git's glossary more discoverable in the HTML version of the man pages.

Julia Evans responds to D. Ben Knoble's suggestion about linking to the glossary for "ref" terminology. She shares that she's already working on an interactive tooltip feature for the HTML documentation (git-scm.com) that would show glossary definitions when hovering over jargon terms. Currently this only works for terms in angle brackets like `<ref>`, but she's considering a new `linkgitglossary:` macro similar to the existing `linkgit:` for more flexible linking.

The discussion highlights the challenge of making glossary references work well across both terminal man pages and HTML documentation. While the interactive features would only benefit web users, the underlying goal is to make Git's specialized terminology more accessible to all users. This builds on the already-merged first patch in Julia's series that improved the `git-push` introduction with clearer "ref" terminology.

The exchange shows thoughtful consideration of how documentation improvements can span both content and presentation layers, with Julia actively working on tooling to support better glossary discoverability in the web interface.
