Submodule bugfix addressing security-related behavior change. This patch modifies how Git handles submodule paths containing symbolic links, which were made fatal errors in commit e8d060894448 due to security concerns (CVE-2024-32002). The current behavior aborts operations like `git show` with `diff.submodule=log` when encountering such links, sometimes producing incomplete output.

Julian Prein proposes making these cases non-fatal where possible, allowing operations to continue while skipping problematic submodules. The patch converts several `exit(128)` calls to error returns in submodule.c, affecting commands like push, fetch, and diff display. For example, `git show` would now display "(commits not present)" for affected submodules rather than truncating output.

The author acknowledges this touches security-sensitive code and submits it as an RFC without tests initially, seeking feedback on the approach. The changes appear focused and well-motivated by real-world usability issues, though the security implications warrant careful review. The patch maintains safety by still rejecting invalid submodules, just more gracefully in contexts where partial operation is possible.
