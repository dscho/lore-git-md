Documentation clarification follow-up regarding `git count-objects -v` "garbage" field terminology.

Daniele Sassoli follows up on the confirmed understanding that `git count-objects -v`'s "garbage" field only counts filesystem artifacts (temporary files, lock files) rather than Git's conceptual garbage (dangling/corrupt objects). The email reports that multiple users - both in personal conversations and public forums like Stack Overflow - have misunderstood this distinction, expecting the field to report garbage-collectable objects.

The core issue is now framed as a documentation problem with potential terminology implications. While the implementation behavior is correct (as confirmed by Junio C Hamano and Elijah Newren in the thread), the term "garbage" appears misleading to users. Daniele proposes either clarifying the documentation or possibly renaming the field to better reflect its actual scope.

This moves the discussion from technical verification to user experience considerations, with Daniele indicating intent to submit a documentation patch after final confirmation of the approach. The thread has established clear technical consensus about the current behavior, making this a suitable time for documentation improvements.
