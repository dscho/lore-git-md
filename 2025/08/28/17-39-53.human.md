Bugfix and cleanup in the midx-write series. This is patch 3/5 in a series addressing a segfault in multi-pack-index operations introduced in Git 2.47.0. The patch focuses on improving error handling during incremental MIDX writes.

Derrick Stolee fixes several cases where the code was returning directly rather than going through the cleanup path when errors occur during incremental MIDX writing. The changes ensure proper resource cleanup by replacing direct returns with gotos to the existing cleanup section. This prevents potential memory leaks when operations fail.

The patch modifies three error paths in `write_midx_internal()` where temporary files and other resources might not be properly released. While the author notes these cases are hard to reproduce in tests, the changes follow established patterns for resource cleanup in the codebase.

This continues the series' theme of tightening up MIDX error handling, following the critical fixes in patches 1-2. The changes are focused and mechanical, converting error returns to use the existing cleanup infrastructure. The patch appears straightforward and low-risk, though as noted, lacks direct test coverage for these specific error cases.
