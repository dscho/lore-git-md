This is patch 2/4 in a series improving deprecation guidance for `git whatchanged`. The patch focuses on documenting the equivalent `git log` command that users should migrate to.

The author Kristoffer Haugsbakk is making minor corrections to the documentation references, fixing a missing colon in one citation and expanding another reference to clarify that differences in output only occur with empty commits (no changes). This appears to be a follow-up to feedback received during review.

The patch is in its final stages, with the core implementation already approved by maintainers. The series as a whole establishes a three-step deprecation message structure (notice, alternatives, contact prompt) with explicit linkage between replacement hints and the contact prompt. This approach differs from how `pack-redundant` was deprecated.

While this particular patch is just documentation refinement, it's part of a carefully considered deprecation strategy that has gone through multiple rounds of review and maintainer approval. The changes are small but meaningful for users transitioning away from the deprecated command.
