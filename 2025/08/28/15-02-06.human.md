This is a performance optimization patch for sparse index handling in `git ls-files` that has now been queued for inclusion. The patch moves index expansion inside the iteration loop, triggering it only when encountering sparse directories that match pathspecs rather than doing full expansion upfront. 

The change was originally motivated by `ls-files` performance but has since been shown to also benefit `git mergetool` workflows where pathspec-triggered index expansion was causing slowdowns. The implementation maintains all existing behavior while optimizing common cases, preserving index sorting invariants during mid-iteration expansion.

The patch received thorough technical review from both sparse index experts (Derrick Stolee and Elijah Newren) and maintainer Junio Hamano, who confirmed the approach is safe given Git's index sorting behavior. The additional real-world use case with `mergetool` strengthens the argument for inclusion, showing the optimization addresses concrete performance pain points.

Junio notes the patch wasn't overlooked due to being niche (as initially thought by the author) but simply got buried in the volume of other threads. With the reviews complete and the maintainer's approval, this well-considered optimization is now queued for the next release.
