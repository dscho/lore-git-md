This thread documents a regression in gitk's Tk widget theming, tracing its lifecycle from introduction to fix to subsequent removal of the affected feature. The original bug, reported on Alpine Linux, caused gitk to crash when users disabled "Themed widgets" in preferences - a regression introduced in Git 2.48.0 and fixed in 2.50.0. Johannes Sixt identified the problematic commits (904b36b and daa364cf) that first broke and then restored this functionality.

Mark Hills has now raised a new concern about commit cb9fa4d9 in Git 2.51.0, which completely removed support for classic (non-themed) widgets from gitk. While the commit author Mark Levedahl justified this as reducing maintenance burden (since themed widgets are now the well-tested default and Tk 8.4 is rare), Hills argues the removal was premature - he personally uses and maintains the classic widget path, and notes others had contributed fixes for it. The discussion highlights an ongoing tension in the project between simplifying maintenance and preserving backward compatibility, particularly for niche but actively used features. All key commits and version contexts are clearly identified, making this a well-documented case study in feature deprecation decisions.
