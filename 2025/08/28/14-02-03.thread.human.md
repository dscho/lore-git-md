This thread reports a bug in gitk, Git's graphical history viewer, where disabling the "Themed widgets" option causes the preferences dialog to fail on subsequent launches. The issue occurs specifically with combobox widget initialization when theming is disabled, suggesting gitk incorrectly assumes themed widgets will always be available.

The reporter, testing on Alpine Linux 3.22 with Git 2.49.1 and Tcl/Tk 8.6.16, provides clear reproduction steps and error traces showing the failure occurs in the `prefspage_general` procedure during preferences dialog setup. The bug appears to be contained within gitk's Tk script (likely gitk.tcl) and its interaction with Tk's theming system, rather than affecting core Git functionality. The well-documented report with specific version information and error output makes this a good candidate for fixing in the next gitk update.
