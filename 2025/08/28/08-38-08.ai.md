Performance patch for `git range-diff` introducing memory limits feature to prevent excessive memory usage when comparing large commit ranges. This is the second and final patch in the v2 series, implementing the core functionality after the preparatory cleanup in patch 1/2.

The patch adds a configurable memory limit (default 4GB/2GB for 64/32-bit systems) for the n×n cost matrix allocation in `get_correspondences()`. When comparing extremely large commit ranges (e.g. 250,000+ commits), this prevents both memory exhaustion and integer overflow issues. The limit is controlled via a new `--max-memory` option accepting human-readable sizes (e.g. "1G", "500M").

Key technical changes:
- New `max_memory` field in `struct range_diff_options`
- Memory size parsing via `parse_max_memory()` callback
- Human-readable error messages using `strbuf_humanise_bytes()`
- Checks in `get_correspondences()` before matrix allocation
- Default limits set via `RANGE_DIFF_MAX_MEMORY_DEFAULT` macro
- Affects three call sites: builtin/log.c, builtin/range-diff.c, log-tree.c

The implementation remains Acked-by Johannes Schindelin from v1. The patch addresses a real-world issue observed in Shopify's monorepo and provides clear error messages when limits are exceeded. The approach was chosen over alternatives like pre-counting commits or streaming due to implementation complexity tradeoffs.
