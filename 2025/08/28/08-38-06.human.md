Performance and safety patch series for `git range-diff` addressing memory exhaustion in large commit ranges. This v2 follows up on Junio Hamano's request to split the changes into two logical commits.

The first commit is a preparatory cleanup that reorders options lexicographically in `builtin/range-diff.c`. The second implements the core solution - a configurable memory limit for the n×n cost matrix calculation that prevents both integer overflow and excessive memory allocation. The limit defaults to 4GB (2GB on 32-bit) and can be set via `--max-memory` with human-readable values like "1G".

The patch maintains Johannes Schindelin's Acked-by and addresses Junio's feedback about patch organization and formatting. The technical approach remains unchanged from v1, with clear error messages when limits are exceeded. The solution avoids more complex alternatives like pre-counting commits or algorithm refactoring.

This addresses a real-world issue seen in Shopify's monorepo where comparing 250,000+ commits would attempt to allocate ~260GB. The new limit allows practical comparisons (up to ~32,000 commits by default) while preventing system-crashing allocations.
