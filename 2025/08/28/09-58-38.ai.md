This is a CI/build system discussion regarding Patrick Steinhardt's v4 series, specifically about the rootless container jobs implementation. Johannes Schindelin raises a critical issue with the proposed approach - while the current patch makes tests run as non-root, it breaks test failure debugging when tests fail. The key problem is that the `builder` user lacks permissions to write to GitHub Actions' temporary directories, preventing both test log output and artifact uploads from working on failures. Schindelin provides a concrete example where this causes the CI pipeline to fail without providing any test debugging information.

The issue centers around permissions in the `/__w/_temp/` directory (mapped to GitHub's `$RUNNER_TEMP`), where the test harness tries to write environment variables. Schindelin suggests the solution may require adding the `builder` user to a specific group with write access to this directory, but notes this is just a hypothesis since he can't investigate further. This represents a significant blocker for the rootless container approach, as reliable test failure analysis is essential for CI.

This discussion occurs after Christian Couder's documentation review was addressed, meaning this is a new technical concern that wasn't raised in previous review rounds. The issue affects the core functionality of the CI system rather than being a documentation or style matter. Schindelin's email indicates the rootless execution approach may need deeper changes to properly handle failure cases, potentially requiring another revision of the patch series despite previous approvals.
