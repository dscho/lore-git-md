This is a bugfix patch addressing memory safety in Git's slab allocator API, part of an ongoing thread about improving the allocator's cleanup behavior. The patch from ノウラ | Flare fixes a NULL pointer dereference that could occur when reusing an alloc_state after cleanup. The original `clear_alloc_state()` function freed memory slabs but left tracking fields (`slab_alloc`, `nr`, and `p`) with stale values, creating potential undefined behavior.

Torsten Bögershausen has reviewed the technical approach and suggested improving the message style to use Git's preferred imperative form ("Rename X to Y" rather than bullet points). The solution renames functions for better consistency (`allocate_alloc_state` becomes `alloc_state_alloc`) and combines cleanup operations to prevent the inconsistent state that caused the original bug. The changes affect alloc.c, alloc.h, and object.c, with all call sites updated to use the new API.
