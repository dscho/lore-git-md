Bugfix for midx-write.c addressing a segfault in multi-pack-index operations. This patch is part of a series fixing issues in the multi-pack-index (midx) writing functionality, specifically addressing a segfault that occurs during `git multi-pack-index repack` and `git multi-pack-index expire` operations. The root cause was improper packfile initialization in `fill_packs_from_midx()`, where pack_info structs were being populated even when pack preparation failed.

The key changes in this patch:
- Reverts to previous behavior of `fill_packs_from_midx()` that doesn't rely on incremental flags or preferred pack names
- Maintains scanning of incremental midx layers
- Skips allocation in pack_info array when pack preparation fails
- Moves `open_pack_index()` call to where it's actually needed (for preferred pack checks)
- Adds an EXPENSIVE test case that reliably reproduces the issue with 100 packfiles under ASAN

The patch fixes a regression introduced in fcb2205b77 that could lead to accessing uninitialized memory when closing packfiles later in the process. The test case demonstrates the issue by triggering auto-GC during commit creation, which helps expose the memory corruption.

This appears to be a well-justified fix for a real crash scenario, with a thorough test case that validates the solution. The changes are focused and maintain the intended functionality while fixing the memory safety issue. The patch is part of a larger series that includes both urgent fixes (like this one) and subsequent code quality improvements.
