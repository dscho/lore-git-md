This is the first patch in a 4-part series porting Windows-specific GUI credential/prompt helpers to mainline git-gui. The patch adds a new Tcl/Tk script `git-gui--askyesno` that implements a simple yes/no dialog, which will be used as a fallback when file operations fail on Windows (like unlink/rename/rmdir on locked files). 

The new script follows git-gui's existing patterns for credential helpers, creating a basic dialog with Yes/No buttons that can be triggered via Enter/Escape keys. It gets installed alongside git-gui and is automatically set as the `GIT_ASK_YESNO` helper when the GUI starts. The implementation is clean and straightforward, with proper error handling if no question is provided.

This is part of a larger effort to improve the Windows GUI experience by providing better interactive prompts for operations that may fail due to file locking. The patch appears well-crafted with clear commit messages and follows git-gui's existing patterns. As the first in the series, it lays the foundation for the subsequent Windows-specific enhancements.
