Bugfix for midx (multi-pack-index) segfault during repack/expire operations. This is the first patch in a series addressing a regression introduced in Git 2.47.0 that could cause crashes during background maintenance when dealing with many packfiles.

The patch fixes a segfault that occurs when `fill_packs_from_midx()` loads improperly initialized packfiles. The fix involves several careful adjustments:
1. Removing reliance on incremental flags/preferred pack checks that were causing issues
2. Keeping the ability to scan incremental midx layers
3. Skipping allocation for failed pack preparations
4. Correcting error return value handling
5. Moving pack index opening to just before it's needed

A new expensive test case is added that creates 100 packfiles and exercises the problematic code paths under ASAN. The test reliably reproduces the segfault without the fix. While the test is marked EXPENSIVE due to resource requirements, it provides important coverage for this edge case.

The changes are focused on midx-write.c and maintain the existing functionality while making the code more robust. This appears to be a well-justified fix for a real regression, with clear explanation of both the problem and solution in the commit message. The patch series as a whole has already received review attention from midx experts.
