This is the first of two preparatory refactoring patches in a series addressing memory exhaustion issues in `git range-diff`. The patch performs a straightforward cleanup by reordering command-line options in `builtin/range-diff.c` to be in lexicographic order, improving code organization and readability. 

The changes are purely mechanical - no functionality is altered. The author (Paulo Casaretto) has split this cleanup from the main memory-limiting feature patch per Junio Hamano's feedback on v1 of the series. This separation makes the actual feature changes in the next patch easier to review.

The reordering affects several option definitions including `--diff-merges`, `--left-only`, `--no-dual-color`, and `--notes`, grouping related options together alphabetically. The patch is small (4 line changes) and focused, with a clear commit message stating its limited scope.

This appears to be a well-executed preparatory change that follows Git's development practices. The next patch in the series will introduce the substantive memory limit feature that addresses the core performance issue.
