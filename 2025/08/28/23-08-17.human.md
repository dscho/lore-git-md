This is a feature patch adding a `-z` flag to `git repo info` as part of a GSoC project. The patch is technically sound but Junio C Hamano raises some design-level concerns about the implementation approach for handling the `-z` and `--format` options.

The patch adds `-z` as a shorthand for `--format=nul`, following Git's convention for null-terminated output seen in commands like `git-config` and `git-status`. The implementation currently treats `-z` and `--format` as mutually exclusive options, which Junio points out doesn't make logical sense since `-z` is just a shorthand for one particular format.

Junio suggests a more elegant solution using a callback-based option parser that would allow the options to work together naturally with "last one wins" semantics, similar to how other commands handle such cases. He provides a code sketch showing how this could be implemented with `OPT_CALLBACK_F`.

While the current implementation is functionally correct, Junio's feedback indicates the parsing logic could be improved for better consistency with Git's conventions. The patch is otherwise well-structured and follows established patterns, with proper test coverage and documentation.
