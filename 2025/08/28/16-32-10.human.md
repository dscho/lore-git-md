This is a user question about the behavior and documentation of `git count-objects -v`'s "garbage" field. Daniele Sassoli is trying to understand why the field doesn't count dangling objects (which they expected) and only seems to count random files in the objects directory, contrary to the documentation's description of "invalid" objects.

The email notes that:
1. The "garbage" field remains 0 even when there are dangling objects that `git gc` would clean up
2. Creating obviously corrupt objects doesn't increment the counter
3. The only way to make it report non-zero is by placing random files in the objects directory
4. The documentation suggests it should count invalid objects, but there's no clear definition of what makes an object "invalid"

This appears to be either a documentation clarity issue or potentially a bug in what `count-objects` actually counts versus what it claims to count. The question is well-posed with clear reproduction steps and references to both observed behavior and documentation.
