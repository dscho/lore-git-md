This is a documentation clarification thread about the "garbage" field in `git count-objects -v` output. Junio C Hamano confirms Daniele Sassoli's observations that the counter only tracks filesystem-level artifacts (like manually created files or temporary files) rather than Git's internal concept of garbage (dangling or corrupted objects).

The thread establishes that the current behavior is intentional - `count-objects` is designed as a lightweight operation that doesn't perform the deeper analysis needed to identify unreachable or corrupted objects (which `git fsck` and `git gc` handle). The documentation could be clearer about this distinction between filesystem garbage and object model garbage.

Junio provides a concrete example showing how creating an arbitrary file in the objects directory triggers the warning, demonstrating the current behavior. The discussion suggests the documentation might benefit from being more explicit about what constitutes "garbage" in this context, though no code changes to the functionality itself appear necessary.
