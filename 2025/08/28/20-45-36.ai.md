This is a bugfix patch in the midx-write.c series, addressing error handling in multi-pack-index operations. The patch restores a missing error code assignment that was accidentally dropped in commit fcb2205b77, ensuring proper error reporting when `fill_packs_from_midx()` fails during MIDX writes.

Junio Hamano points out that this isn't just cleanup as claimed in the cover letter - it actually changes program behavior by properly propagating errors from `write_midx_internal()` to its callers (`write_midx_file_only()`, `write_midx_file()`, and `expire_midx_packs()`). These functions are used in builtin/multi-pack-index.c, so the fix affects user-facing commands.

The change is straightforward - adding back `result = 1` before the error path jump - but its impact is meaningful for error reporting. While the patch maintains Git's convention of "0 for success, non-zero for error", Hamano notes this isn't necessarily an ideal pattern, though he's not objecting to it here.

This patch is part of a larger series addressing midx issues, with earlier patches fixing more critical segfaults and this one completing the error handling improvements. The technical scope remains focused on midx-write.c, with the change being small but important for correct error propagation.
