This is a bugfix and security-related RFC patch addressing submodule handling when paths contain symbolic links. The patch follows up on security hardening from commit e8d060894448 which introduced strict checks after CVE-2024-32002, but currently causes Git to abort operations like `git show` and submodule fetches when encountering such links.

The key changes replace hard `exit(128)` calls with error returns in several submodule.c functions (`push_submodule`, `fetch_task_create`, `bad_to_remove_submodule`, `submodule_to_gitdir`). This allows operations to continue with degraded functionality rather than aborting entirely - for example, showing "(commits not present)" for affected submodules in diffs rather than truncating output. The fetch/push operations will now skip problematic submodules while completing the main operation.

The author acknowledges this touches security-sensitive code and submits as RFC without tests initially, requesting maintainer feedback on the approach. The changes appear focused and well-motivated by real-world usability problems while maintaining security by still rejecting the invalid paths (just more gracefully). The patch modifies 27 lines across 4 functions, with clear error handling additions and a NEEDSWORK comment about improving error reporting.
