Maintainer feedback on option reordering patch for `git range-diff`. This is part of a series addressing memory exhaustion issues in large commit range comparisons, but focuses on a preparatory cleanup commit that reorders command-line options lexicographically.

Junio Hamano expresses reservations about the change, arguing that strict alphabetical ordering may actually reduce usability by separating related options (like `--left-only` and `--right-only`). He suggests that grouping related functionality together - as Git typically does in help output - is more user-friendly than pure alphabetical ordering. The maintainer indicates he would prefer to see logical grouping headers added rather than this reorganization.

While acknowledging the patch is mechanically sound (having already been applied as part of the series), Hamano's comments suggest this particular change might not represent an improvement from a user experience perspective. The feedback leaves open the possibility of reconsideration if stronger justifications emerge, but currently serves as a caution about prioritizing mechanical consistency over practical usability.
