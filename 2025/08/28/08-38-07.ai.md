This is the first of two preparatory refactoring patches in a series addressing memory exhaustion issues in `git range-diff`. The patch performs a straightforward mechanical cleanup, reordering the command-line options in `builtin/range-diff.c` into lexicographic order for better organization and readability. No functional changes are introduced - this is purely a code hygiene change to make the subsequent memory limit patch (coming in patch 2/2) easier to review.

The changes affect only the option definitions in the `cmd_range_diff()` function, moving `diff-merges` and `left-only` up in the list while shifting `notes` and `remerge-diff` down. The patch follows Junio Hamano's feedback from v1 to separate the cleanup from the functional changes, making this a standalone preparatory commit.

The author (Paulo Casaretto) has correctly maintained the separation of concerns requested in the v1 review, with Johannes Schindelin's Acked-by still applying to the core memory limit functionality that will follow in the next patch.
