This is a documentation clarification thread about `git count-objects -v` behavior, with Junio C Hamano confirming the current implementation's scope. The thread has established that the "garbage" field specifically tracks filesystem artifacts (like temporary files and non-Git files) rather than Git's conceptual garbage (dangling or corrupted objects).

Junio confirms Daniele Sassoli's testing methodology and conclusions, noting the command correctly reports filesystem-level garbage like manually created files in object directories. He emphasizes that `count-objects` intentionally avoids the deeper analysis performed by `git fsck` (for corruption) and `git gc` (for reachability), as it's designed for lightweight repository statistics.

The key distinction is between:
1. Filesystem garbage: Counted by `count-objects` (temporary files, lock files, foreign files)
2. Object model garbage: Handled by other commands (dangling objects, corrupt objects)

This aligns with Elijah Newren's earlier explanation about the counter tracking "filesystem-level garbage from interrupted operations." The thread consensus suggests the behavior is correct but the documentation could be clearer about this specific scope. No code changes appear necessary - the focus is on improving the man page to better distinguish between these two types of repository garbage.
