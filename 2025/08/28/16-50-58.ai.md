Elijah Newren provides context about when garbage files typically appear in practice - specifically during interrupted transfers (pushes or fetches) where temporary packfiles remain. This explains why manually created test files show up as garbage while corrupted/dangling objects do not. The behavior appears to be working as intended, though the documentation could be clearer about distinguishing between Git's internal object model (where corrupted objects are still "valid" in some sense) and foreign filesystem artifacts.

Key technical point: The garbage counter specifically tracks filesystem-level artifacts from interrupted operations (temporary packfiles) rather than Git's conceptual garbage (dangling/corrupt objects). This aligns with the implementation but may not match user expectations from the documentation's wording.

The response suggests the current behavior is correct but implies the documentation could better explain the distinction between filesystem garbage (counted) and object model garbage (handled by other commands like `git fsck` and `git gc`).
