Junio Hamano is nudging the stalled sparse-checkout 'clean' command patch series forward. This is a feature addition to `git sparse-checkout` that would help maintain cone mode performance by cleaning up tracked-but-sparse directories outside the sparse-checkout scope.

The series has been in review since mid-July with some outstanding comments. Key aspects include:
- Mimics `git clean`'s `--force`/`--dry-run` options and `clean.requireForce` config
- Adds `--verbose` output showing files that would be removed
- Introduces a new `for_each_file_in_dir()` helper for directory traversal
- Handles merge conflicts and staged files more gracefully than previous approaches

While the core functionality appears solid, there are some unresolved questions about the user interface (whether to mirror `git clean`'s options) and edge case behavior with staged files. The maintainer is looking to move this forward soon, either by addressing remaining feedback or making a judgment call on the open questions.
