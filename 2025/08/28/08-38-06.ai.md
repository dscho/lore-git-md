Performance and safety patch series for `git range-diff` addressing memory exhaustion issues, now split into two commits per Junio Hamano's feedback. The core technical solution remains unchanged from v1, which was already Acked-by Johannes Schindelin.

The first commit (new in v2) performs a purely mechanical reordering of options in `builtin/range-diff.c` to be lexicographical, separating this cleanup from the functional changes. The second commit introduces the memory limit feature for the n×n cost matrix calculation, preventing both integer overflow and excessive memory allocation when comparing very large commit ranges (250,000+ commits).

Key technical details carried forward from v1:
- New `max_memory` field in `struct range_diff_options`
- Memory size parsing via `parse_max_memory()` callback
- Human-readable error messages using `strbuf_humanise_bytes()`
- Default limits of 4GB (64-bit) and 2GB (32-bit)
- Checks occur in `get_correspondences()` before matrix allocation

Changes in v2:
- Split into two commits as requested by Junio
- Fixed formatting of Acked-by trailer
- Corrected author name from "pcasaretto" to "Paulo Casaretto"
- Removed unrelated option reordering from the feature commit
- Cleaned up some whitespace and indentation issues noted in v1

The patch continues to address the same real-world issue seen in Shopify's monorepo where comparing 256,783 commits would attempt to allocate ~260GB. The solution remains well-motivated and technically sound, now better organized for review.
