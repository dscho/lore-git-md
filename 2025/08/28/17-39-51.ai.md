Bugfix for midx-write.c addressing a segfault in multi-pack-index operations. This is the first patch in a 5-part series (previously summarized) that fixes a regression introduced in Git 2.47.0 affecting `git multi-pack-index repack` and `git multi-pack-index expire`.

The core issue occurs when accessing uninitialized pack data during midx operations, specifically in `fill_packs_from_midx()`. The patch modifies this function to properly initialize packs before use, moving pack index opening to when it's actually needed for preferred packs. A key change is skipping allocation in the pack_info array for failed pack preparations.

The patch includes a new expensive test case that creates 100 packfiles to reliably reproduce the segfault under ASAN. The test demonstrates the issue occurs during auto-GC operations when packfiles are being cleaned up. The stack trace shows the failure manifests when closing packfiles, though the root cause is earlier initialization issues.

Technical details worth noting for future reference: the fix maintains incremental midx scanning behavior while reverting other aspects of fcb2205b77's changes; it updates error handling to properly check return values; and it relocates the `open_pack_index()` call to just before its results are needed. The changes are focused on midx-write.c with test coverage in t5319.
