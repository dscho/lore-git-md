Maintainer feedback on the lexicographic ordering patch in the range-diff memory limit series. Junio Hamano expresses reservations about the purely alphabetical ordering approach for command-line options, arguing it breaks logical grouping of related options (like left/right-only) that helps users understand the command's structure. He suggests that if reorganization is needed, it should focus on adding clear section headers in the help output rather than mechanical sorting.

This is a notable pushback on what was previously considered a straightforward preparatory cleanup. The patch had already been split out from the main feature work per earlier feedback, but now faces substantive design criticism. The maintainer's position suggests this change may not be accepted in its current form, though he leaves room for others to present counterarguments.

Key technical points:
- Current patch moves `--left-only` away from `--right-only` in builtin/range-diff.c
- Maintainer prefers semantic grouping over strict alphabetical order
- Suggests adding help text section headers as alternative improvement
- Original author Paulo Casaretto will need to either justify the current approach or revise

This feedback doesn't impact the core memory limit functionality (patch 2/2), but may require reworking or dropping the preparatory cleanup. The thread shows maintainers carefully considering even mechanical changes for their impact on user experience.
