Bugfix for gitk's Tk widget theming interaction. This email reports a regression in gitk where disabling the "Themed widgets" option in preferences causes the preferences dialog to fail on subsequent launches. The error occurs when trying to create combobox widgets, suggesting the theming system is required for certain UI elements to function properly.

The issue is reproducible on Alpine Linux 3.22 with Git 2.49.1 and Tcl/Tk 8.6.16. The error stack trace shows the failure occurs when trying to initialize combobox widgets during preferences dialog construction after theming is disabled. The reporter provides clear reproduction steps: disable themed widgets, quit gitk, then reopen to see the preferences dialog fail with combobox-related errors.

This appears to be a genuine bug in gitk's handling of widget theming state, where it doesn't properly fall back to non-themed widgets when theming is disabled. The error suggests gitk assumes themed widgets (specifically comboboxes) will always be available, which isn't the case when theming is turned off. The report is well-documented with version information and a clear reproduction path, making it easy to verify.

Key technical details for future reference:
- Failing command: `::combobox` widget creation
- Affected files: gitk's Tk script (likely gitk.tcl)
- Error occurs in `prefspage_general` procedure during preferences dialog setup
- Specific Tcl/Tk versions involved: 8.6.16
- Related setting: "Themed widgets" checkbox in gitk preferences

The bug appears to be specific to the interaction between gitk's UI and Tk's theming system, rather than a general Git issue. The clear reproduction case and error output make this a strong candidate for fixing in the next gitk update.
