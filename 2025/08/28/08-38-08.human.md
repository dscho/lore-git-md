Performance patch for `git range-diff` that adds memory protection against extreme allocations. This is the second and final patch in a series addressing memory exhaustion issues when comparing very large commit ranges (250,000+ commits).

The core change introduces a configurable memory limit for the n×n cost matrix calculation, preventing both integer overflow and excessive memory usage. Users can now set a `--max-memory` option (defaulting to 4GB on 64-bit systems, 2GB on 32-bit) with human-readable sizes like "1G" or "500M". When exceeded, Git shows a clear error message with both requested and allowed memory sizes.

The implementation touches several files to add the new option and checks, with careful handling of memory size calculations. The approach was chosen over alternatives like pre-counting commits or streaming due to implementation complexity tradeoffs. The patch carries forward Johannes Schindelin's Acked-by from v1 and appears ready for merging, having addressed all prior feedback in the thread.

This solves a real-world problem observed in Shopify's monorepo where comparing 256,784 commits would attempt to allocate ~256GB. The solution is well-contained and maintains backward compatibility while adding important safeguards.
