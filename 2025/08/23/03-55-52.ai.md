Refactoring patch in the Rust infrastructure series (v3 11/15) that replaces xdiff's chastore memory pool with an FFI-compatible ivec. This continues the systematic modernization of xdiff internals for Rust interoperability while simplifying the code structure.

The patch removes the dual data structure setup where xdfile_t used both a chastore memory pool and a separate recs array, replacing it with a single ivec (interoperable vector) that handles both storage and access. This eliminates the redundant nrec and recs fields (to be removed in subsequent patches) and removes the xdl_cha_alloc() calls in favor of ivec operations. The change maintains identical functionality while making the code more straightforward and better aligned with Rust FFI requirements.

Key technical details:
- Adds ivec.h include and DEFINE_IVEC_TYPE for xrecord_t
- Replaces chastore_t rcha with ivec_xrecord record
- Modifies xdl_prepare_ctx() to use ivec_push() instead of manual allocation
- Keeps temporary recs array during transition (to be removed later)
- Updates xdl_free_ctx() to use ivec_free()
- Maintains all existing pointer arithmetic and memory patterns

The change builds on prior standardization of xrecord_t fields in v3 9/15 and continues the pattern of replacing C-specific constructs with FFI-compatible alternatives. The author notes this is part of cleaning up overlooked legacy structures (like the unused xrecord_t.next field) while progressing toward the series' goal of Rust interoperability.
