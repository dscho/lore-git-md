This is a continuation of the Rust infrastructure debate, specifically addressing the mrustc proposal as a potential solution for NonStop platform support. Randall Becker responds to Brian Carlson's suggestion of using mrustc (a C++-based Rust compiler) by noting practical limitations - mrustc requires GCC which doesn't port to NonStop, and their platform only supports C11 (with C17 coming soon) but can't handle the G++ requirements in the makefiles.

The email reinforces the fundamental platform compatibility challenge at the heart of this debate: while Carlson proposes mrustc as a technical bridge solution, Becker's testing indicates it still won't work for NonStop's constrained environment. This maintains the core impasse between security-driven Rust adoption and concrete platform support limitations.

Key technical details mentioned:
- mrustc's GCC dependency as a blocker
- NonStop's current C11/C++ mode capabilities
- Makefile requirements for G++ being problematic
- Mention of upcoming C17 support timeline

The response doesn't fundamentally change the policy positions but provides important technical constraints on the feasibility of the mrustc approach for this specific platform. It suggests the discussion may need to shift to either finding alternative build system approaches that could work with NonStop's toolchain, or accepting that some platforms may need to be left behind in the Rust transition.
