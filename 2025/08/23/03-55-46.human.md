This is a CI/build system patch in the ongoing series introducing Rust infrastructure for xdiff (now at v3 5/15). The change ensures each GitHub Actions workflow uploads its `Cargo.lock` file as a build artifact, allowing for dependency auditing.

The patch systematically adds `Cargo.lock` upload steps to all relevant CI jobs - Windows builds (both Makefile and Meson-based), Linux test jobs, and static analysis. Each upload uses a descriptive artifact name matching the job context (e.g. `cargo-lock-windows`, `cargo-lock-${{matrix.vector.jobname}}`).

This appears to be a straightforward quality-of-life improvement for the Rust integration work, making dependency tracking more transparent across different build environments. The change is mechanical and well-contained, following the series' pattern of methodically addressing infrastructure needs before core functionality changes. No new platform requirements or technical challenges are introduced here - it simply makes existing dependency information more accessible for debugging and auditing purposes.
