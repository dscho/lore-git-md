This is a refactoring and Rust integration patch series for xdiff, now in its third version. The series has shifted focus from performance optimizations to structural cleanup and Rust interoperability, dropping earlier hashing changes to unblock other work.

The 15-part series introduces several key changes:
1. Adds a Rust policy document (from brian m. carlson) with clarifications about type safety and platform compatibility
2. Sets up Rust infrastructure in the build system (Makefile, meson, CI)
3. Introduces an `ivec` type for safe C/Rust data sharing
4. Performs extensive xdiff cleanup (removing unused fields, standardizing memory management)
5. Implements `xdl_trim_ends()` in Rust as the first translated function

Notable technical aspects:
- The `ivec` type provides a vector implementation that works across C/Rust boundaries
- Windows/MSVC compatibility is maintained through target adjustments
- The series now focuses on making xdiff internals more Rust-friendly rather than immediate performance gains
- The Rust policy document warns about platform-specific type sizes (like `c_long`) and recommends avoiding C types in favor of explicit sizes (i32/i64)

The series appears well-structured, with each commit focused and the overall direction aligned with maintainer feedback from earlier versions. The Rust integration is incremental, starting with infrastructure and simple functions while keeping the core diff algorithms in C for now. The CI setup shows careful attention to cross-platform compatibility.
