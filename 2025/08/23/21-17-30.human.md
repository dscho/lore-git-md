This is a technical clarification in the ongoing Rust infrastructure discussion. Haelwenn Monnier responds to Brian Carlson's suggestion about using mrustc as an alternative Rust compiler for NonStop support, pointing out that mrustc is only designed for bootstrapping rustc itself, not for general Rust compilation. They note that gccrs might eventually serve as a true alternative compiler, but it's not yet mature enough.

The email reinforces Sam James' earlier point about mrustc's limitations, further narrowing the technical options for supporting Rust on NonStop platforms. This leaves the Git project with a difficult choice between adopting Rust (with its security benefits) and maintaining full platform support, as there appears to be no viable technical solution that satisfies both requirements. The discussion has reached a policy decision point rather than a technical one.
