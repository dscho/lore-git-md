This thread discusses a two-patch series that replaces Git's progress meter signaling from `setitimer()` to the simpler `alarm()` function, improving cross-platform compatibility since `setitimer()` is marked obsolescent in POSIX.1-2017. The first patch performed the core replacement, removing platform-specific code while noting a race condition during shutdown that would be addressed in the second patch.

The just-arrived second patch introduces a three-state shutdown protocol to safely handle process termination. It replaces a simple boolean flag with a tri-state system (0=no progress, 1=update needed, 2=shutdown) that prevents unsafe signal handler execution during shutdown. All progress display logic is updated to check only the least significant bit, maintaining functionality while adding safety. The changes are well-contained in `progress.c` and complete the series' goal of modernizing the signal handling infrastructure.

The series appears ready for review, with the key technical concern (shutdown safety) now addressed. Reviewers will likely focus on the atomicity of state changes and whether any edge cases remain in the termination sequence. The work fits into Git's broader effort to modernize signal handling while maintaining compatibility across platforms.
