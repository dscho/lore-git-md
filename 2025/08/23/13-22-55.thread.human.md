This thread discusses a two-patch series that replaces `setitimer()` with `alarm()` for progress meter signaling, motivated by `setitimer()` being marked obsolescent in POSIX.1-2017. The first patch performs the direct replacement in `progress.c`, significantly simplifying the code by removing platform-specific compatibility layers and build system checks while adding only minimal new code. The change affects Windows compatibility code in `compat/mingw*` and introduces a potential race condition during shutdown.

The second patch (not yet sent) will address this race condition by adding a `shutting_down` flag to the progress structure to prevent unsafe handler execution during termination. The series is part of broader work to modernize Git's signal handling infrastructure. Reviewers will likely focus on verifying the robustness of the shutdown handling changes in the upcoming second patch. The changes appear well-motivated for improving cross-platform compatibility while maintaining functionality.
