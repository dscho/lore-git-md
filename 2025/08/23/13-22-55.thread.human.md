This thread explores modernizing Git's progress meter signal handling, moving away from the obsolescent setitimer() API. Johannes Sixt has proposed a signal-free approach using periodic getnanotime() checks, which initially faced skepticism from maintainer Junio Hamano over performance concerns. However, Hamano has since reconsidered, acknowledging modern OS optimizations make the overhead acceptable.

In the latest development, Sixt reinforces the Windows compatibility benefits of removing signal dependencies, calling the current implementation problematic. He notes Git already uses similar timing checks elsewhere (in throughput display) and commits to addressing two remaining issues: performance measurements and fixing delayed progress indicator behavior. While these implementation details need work, the fundamental approach appears to have gained acceptance, with Hamano's earlier reservations largely addressed.

The discussion has effectively moved past Carlo Marcelo Arenas Belón's original alarm() proposal, converging on Sixt's more comprehensive signal-free solution. With the maintainer's concerns mitigated and platform advantages clear, the focus now shifts to finalizing the technical implementation before submission.
