Refactoring patch in the Rust xdiff infrastructure series (v3 08/15) that removes unused fields from core xdiff data structures. This continues the systematic preparation work for Rust porting by cleaning up dead code before introducing new functionality.

The patch eliminates three unused fields from xdiff`'s internal types:
- `xrecord_t.next` (linked list pointer)
- `xdfile_t.hbits` (hash table size)
- `xdfile_t.rhash` (hash table pointer)

These fields were initialized but never actually used in the code. The changes cascade through several functions:
- `xdl_classify_record()` loses its hash table parameters
- `xdl_prepare_ctx()` simplifies its memory allocation patterns
- `xdl_free_ctx()` removes corresponding cleanup code
- Header file definitions are trimmed accordingly

The removal is straightforward with no behavior changes, just deleting dead code. This follows the series' pattern of cleaning up xdiff internals before introducing Rust components. The changes align with the overall goal of making the codebase more amenable to automated translation tools by removing unnecessary complexity.

This patch builds on previous infrastructure work (CI setup, build system integration) and prepares for upcoming interop components by reducing the surface area that will need Rust/C FFI handling. The series continues its methodical approach of addressing technical debt before adding new capabilities.
