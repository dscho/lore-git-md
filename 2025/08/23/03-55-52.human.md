This is part 11/15 of a refactoring series preparing xdiff for Rust integration, focusing on memory management changes. The patch replaces xdiff's internal `chastore` memory pool with an `ivec` (interoperable vector) structure for storing `xrecord_t` entries. This eliminates redundant data structures (`chastore` + parallel array) and removes FFI-unfriendly C types while maintaining the same functionality.

Key changes:
- Removes `chastore_t` in favor of `ivec_xrecord` (a Rust-compatible vector type)
- Simplifies memory management by using a single vector instead of separate allocation structures
- Keeps the same record processing logic but stores records directly in the vector
- Prepares for follow-up patches that will remove now-redundant fields (`nrec` and `recs`)

The change appears well-motivated, cleaning up confusing dual data structures while advancing the series' goal of Rust compatibility. The implementation maintains all existing behavior while using more straightforward memory management. This continues the series' careful, incremental approach to refactoring xdiff internals.
