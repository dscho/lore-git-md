Feature request for committing untracked files directly.

Isaac Oscar Gariano proposes adding the ability to commit untracked files directly via `git commit <file>` without requiring a separate `git add` step first. They note this would be particularly useful for quick commits and suggest extending the functionality to work with the `-a` option as well.

The email asks two key questions: (1) whether there are technical reasons this isn't already supported, and (2) whether the community would accept a patch implementing this, including whether it would need to be gated behind an option for backward compatibility. The request appears motivated by workflow convenience rather than any deeper technical need.

This seems like a straightforward quality-of-life improvement, though the impact would be modest since the current two-step process (add then commit) is already well-established. The backward compatibility question is particularly relevant since changing this behavior could potentially break scripts that rely on the current error behavior with untracked files. The proposal would likely to spark discussion about whether the convenience justifies the change.
