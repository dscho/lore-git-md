Refactoring patch in the Rust xdiff infrastructure series (v3 13/15), completing the transition from chastore to ivec by removing the now-redundant `recs` field from `xdfile_t`. This follows the previous patch (v3 12/15) which eliminated the dual data structure (chastore + recs array).

The change removes the secondary pointer array that previously mapped to records in a 1:1 fashion with the ivec storage, since the ivec's direct access makes this indirection unnecessary. The patch updates all xdiff components to use `record.ptr[]` directly instead of `recs[]`:
- Core diff algorithm (xdiffi.c)
- Output generation (xemit.c)
- Merge handling (xmerge.c)
- Patience diff variant (xpatience.c)
- Initialization/cleanup (xprepare.c)

Key technical points:
- Maintains all existing functionality while simplifying the data structure
- Updates array bounds checks and loops across all xdiff components
- Preserves type casts (long-based array indexing) from prior work
- Removes now-unnecessary memory management for the recs array
- Keeps all existing platform support and CI infrastructure

The change is part of the systematic preparation for Rust integration, continuing the pattern of incremental improvements to xdiff's data structures while maintaining compatibility with the patch demonstrates careful attention to the transition, with thorough updates to all affected code paths.
