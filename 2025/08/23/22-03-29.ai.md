This is a follow-up in the progress meter signaling modernization discussion, where Johannes Sixt responds to Junio Hamano's concerns about the signal-free approach. The email focuses on platform considerations and performance implications of replacing setitimer() with periodic getnanotime() checks.

Sixt counters Hamano's reservations by noting that Windows compatibility benefits significantly from removing signal dependencies, calling the current Windows implementation "as dirty as it can get." He also points out that Git already uses getnanotime() in display_throughput(), suggesting the performance impact may be less severe than feared. However, Sixt acknowledges he needs to conduct performance measurements and fix an observed behavior change with delayed progress indicators before submitting final patches.

Key technical points raised:
- Windows implementation currently has problematic signal handling
- getnanotime() usage already exists in throughput display code
- Performance impact remains to be measured
- Behavior change with delayed progress indicators needs investigation

The email shows Sixt preparing to address the remaining technical hurdles for his signal-free approach, while maintaining that the platform compatibility benefits outweigh the performance concerns Hamano raised. This moves the discussion toward implementation refinements rather than fundamental approach questions.
