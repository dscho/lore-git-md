Subject: Replacing setitimer() with alarm() for progress meter signaling

This thread explores modernizing Git's progress meter signal handling, originally using POSIX.1-2017 obsolescent setitimer(). Carlo Marcelo Arenas Belón's initial two-patch series proposed using alarm() as a simpler alternative, but Johannes Sixt countered with a more radical timer-based approach eliminating signals entirely.

The current state shows consensus around Sixt's getnanotime()-based solution, which would:
- Replace signal infrastructure with periodic time checks (1/8 second intervals)
- Maintain identical user-visible behavior
- Simplify Windows compatibility
- Track last_update timestamps in struct progress

Sixt has now provided a polished prototype branch `progress-wall-clock` in his GitHub fork, responding to Belón's request for collaboration/handoff. The implementation is ready for CI validation before formal patch submission, confirming the transition to signal-free design.

Key technical considerations still in play:
- Performance impact of timer check frequency vs signal overhead
- Behavior on systems with coarse timer resolution
- Final implementation details before submission

The thread has decisively rejected both setitimer() and alarm() approaches in favor of Sixt's signal-free design. With Sixt's Windows expertise and working prototype, the effort moves into final testing phase with him clearly leading the implementation. Belón has endorsed this direction, marking a clear path forward after evaluating alternatives.
