Subject: Replacing setitimer() with alarm() for progress meter signaling

This two-patch series by [author] aims to improve platform compatibility by replacing `setitimer()` with `alarm()` for progress meter updates, motivated by `setitimer()` being marked obsolescent in POSIX.1-2017. The core change simplifies signal handling infrastructure while maintaining progress reporting functionality during operations like clones and fetches.

Patch 1 performs the direct replacement from `setitimer()` to `alarm()` in `progress.c`, removing 108 lines of platform-specific code while adding only 34 lines. Key changes include eliminating `compat/` layers for `setitimer()`, removing build system checks for `setitimer()` and `struct itimerval`, adding a minimal `alarm()` implementation for MinGW, and simplifying Windows timer thread handling in `compat/mingw.c`. The patch notes a race condition during shutdown that will be addressed in patch 2.

Patch 2 (not yet sent) will add a `shutting_down` state flag to `struct progress` to prevent unsafe SIGALRM handler execution during termination. The series represents part of broader work to modernize Git's signal handling, with a third patch mentioned as deferred for future work.

Technical details:
- Progress meter now uses standard `alarm()` instead of POSIX `setitimer()`
- Removed `NO_SETITIMER` and `NO_STRUCT_ITIMERVAL` build flags
- Simplified Windows compatibility code (`compat/mingw*`)
- MinGW timer thread modified to check signal handler changes
- Changes affect core progress reporting in `progress.c`
