Subject: Replacing setitimer() with alarm() for progress meter signaling

This thread examines modernizing Git's progress meter signal handling, moving from the POSIX.1-2017 obsolescent setitimer() to alternative approaches. Carlo Marcelo Arenas Belón initially proposed using alarm(), while Johannes Sixt countered with a more radical signal-free timer-based solution using getnanotime() checks every 1/8 second, implemented in his `progress-wall-clock` branch.

The discussion has evolved through several phases: initial consideration of alarm(), Sixt's signal-free proposal, Junio Hamano's performance concerns about frequent gettimeofday() calls, and Hamano's subsequent reconsideration acknowledging modern OS optimizations. Sixt's latest response emphasizes Windows compatibility benefits from removing signal dependencies (calling the current Windows implementation "as dirty as it can get") and notes Git already uses getnanotime() in display_throughput(), suggesting performance impact may be manageable.

Key technical points:
- Sixt's working prototype eliminates signal infrastructure while maintaining identical user behavior
- Windows compatibility significantly improved by removing signal dependencies
- Timer resolution and system impact considerations remain but appear less severe than initially thought
- Existing getnanotime() usage in display_throughput() provides precedent
- Hamano's stance has shifted from skepticism to cautious openness
- Sixt acknowledges need for performance measurements and behavior change fixes (delayed progress indicators)

Open questions:
- Final performance measurements of signal-free approach
- Resolution of delayed progress indicator behavior
- Windows-specific implementation details

The thread now clearly favors Sixt's signal-free solution, with Hamano's reservations largely addressed and Sixt preparing to tackle remaining implementation refinements. The original alarm() proposal appears fully superseded by this more comprehensive approach, with the discussion shifting from fundamental design to final technical validation before potential submission.
