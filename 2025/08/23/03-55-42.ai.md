This is a documentation patch establishing Git's Rust adoption policy, part of the larger RFC series introducing Rust infrastructure for xdiff. The patch adds `rust-support.adoc` as a new technical document and updates `platform-support.adoc` to require Rust support.

The document provides a comprehensive rationale for introducing Rust (memory safety, developer ergonomics, security vulnerabilities in C) and outlines Git's incremental adoption strategy. Key policy decisions include:
- Rust becomes a mandatory platform requirement alongside existing criteria
- Version support tied to Debian stable/oldstable (approx. 3-year support window)
- Avoidance of C-style Rust via bindgen/cbindgen in favor of idiomatic Rust
- Careful dependency management without `Cargo.lock` inclusion
- Platform-specific type handling guidance (avoiding `c_long` etc.)

The document reflects consensus from the Berlin Contributor Summit and addresses downstream/distributor concerns while establishing technical guardrails. It serves as the foundational policy for subsequent Rust work in the series, particularly the xdiff integration. The content shows thorough consideration of cross-platform implications and version compatibility, though actual implementation tradeoffs will emerge as the series progresses.
