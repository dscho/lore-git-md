This is part 14/15 of the ongoing Rust infrastructure series for xdiff, focusing on type alignment between C and Rust. The patch continues the type standardization work by converting remaining ambiguous fields in `xdfile_t` from C types (`long`, `unsigned long`, `char*`) to explicit Rust-compatible types (`usize`, `isize`, `u8*`, `u64*`).

The changes touch core diff algorithm components across xdiffi.c, xdiffi.h, and xtypes.h, updating:
- Hash array pointers to `u64` (from `unsigned long`)
- Change markers to `u8` (from `char`)
- Array indices to `usize`/`isize` (from `long`)
- Record counts to `usize` (from `long`)

This follows the pattern established in earlier patches of the series, maintaining the same memory layout while making types explicit for Rust interoperability. The changes are mechanical and focused on the diff algorithm's internal data structures, with no behavioral changes.

The patch appears well-contained, touching only the intended type conversions while preserving all existing logic. It builds on the foundation laid by previous patches in the series (particularly the ivec transition completed in v3 13/15) and keeps the codebase moving toward eventual Rust component integration.
