This is a two-patch series addressing progress meter functionality, specifically replacing `setitimer()` with `alarm()` for signal handling. The changes focus on simplifying the code while maintaining compatibility, particularly on Windows.

The first patch does a straightforward swap from `setitimer()` to `alarm()`, which is simpler but introduces a race condition during process shutdown. The second patch fixes this by adding a "shutting down" state to the SIGALRM handler. A third patch for Windows compatibility was deferred.

The series removes significant amounts of platform-specific code (108 lines deleted vs. 34 added) while maintaining the same functionality. The changes touch the progress meter system, POSIX compatibility layers, and build configuration files. This appears to be a well-motivated cleanup that could make the code more maintainable, though Windows users may want to watch for any follow-up patches addressing the deferred compatibility work.
