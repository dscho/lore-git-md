This is a reply in the ongoing RFC series introducing Rust infrastructure for xdiff (now at v3 15/15). Randall Becker raises a key platform compatibility concern about whether the changes make Rust a mandatory dependency, potentially excluding some platforms.

The email references patch v3 02/15 which introduced initial Rust build infrastructure, including:
- Makefile and meson.build changes to integrate Rust compilation
- A build_rust.sh script for cargo invocation
- Basic type definitions in git-compat-util.h for C/Rust interop
- Empty Rust crate scaffolding (xdiff and interop)

Becker's specific concern focuses on the build system changes that appear to make Rust compilation a prerequisite for building Git (evidenced by the `compile_rust` target being added to numerous build rules). This could impact platforms where Rust toolchains aren't available or are difficult to install.

The thread context shows this is part of a larger effort to port xdiff to Rust while maintaining identical behavior across platforms. However, this particular concern about mandatory Rust dependencies wasn't previously addressed in the thread's open items list (which focused more on Windows/MSVC specifics, musl support, and type safety verification).

This raises an important policy question about whether the Rust conversion should remain optional for platforms where Rust isn't available, or if the project is willing to drop support for such platforms. The series maintainer will need to clarify the intended platform support stance and potentially modify the build system to make Rust optional if needed.
