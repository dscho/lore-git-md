CI / build system patch in the Rust infrastructure series (5/15), focusing on dependency tracking.

This patch enhances GitHub Actions workflows to upload `Cargo.lock` files as build artifacts across all CI jobs that involve Rust compilation. The change appears in four distinct job configurations: standard Windows builds, Meson-based Windows builds, Linux test matrices, and static analysis runs. Each upload uses a job-specific artifact name (`cargo-lock-windows`, `cargo-lock-windows-meson`, etc.) to preserve the lockfile from that particular build environment.

The stated motivation is to enable auditing of build dependencies, suggesting this is groundwork for future dependency management and security reviews. The implementation is straightforward - each relevant job gets a new step using GitHub's standard `actions/upload-artifact` action to capture the `rust/Cargo.lock` file.

As part of the larger Rust infrastructure series, this continues the pattern of methodical platform support work before core functionality changes. While not addressing any specific open items from previous patches, it complements the series' focus on robust CI infrastructure by ensuring dependency snapshots are available for inspection. The change is uncontroversial in isolation but contributes to the series' broader goal of making Rust components maintainable in production.
