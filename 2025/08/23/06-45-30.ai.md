Feature request for direct commits of untracked files. Isaac Oscar Gariano proposes extending `git commit` to accept untracked files directly, similar to how it handles tracked files, rather than requiring a separate `git add` step first. The suggestion includes supporting this behavior with the `-a` option as well.

The request stems from personal workflow friction where the current behavior forces an extra step when committing new files. The author asks whether this functionality would be welcome, whether it should be gated behind a new option for backward compatibility, and if the community would be open to a patch implementing this change.

This appears to be a straightforward usability improvement targeting the commit porcelain. The change would affect the command-line interface of `git commit` and potentially touch related documentation. No technical hurdles are mentioned, but the proposal raises questions about backward compatibility strategy that would need resolution before implementation. The request is framed as an inquiry rather than a concrete proposal, suggesting the author is seeking feedback before investing in implementation work.
