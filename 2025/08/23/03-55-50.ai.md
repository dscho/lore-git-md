This is part of the ongoing Rust infrastructure preparation work for xdiff (v3 09/15). The patch focuses on making xdiff's core data structures more Rust-friendly by standardizing types and adding necessary casts for interoperability.

The key changes involve modifying the `xrecord_t` struct to use Rust-compatible primitive types (`u8 const*` for pointers, `usize` for size, `u64` for hash values) and propagating these changes through the xdiff codebase. This requires adding explicit casts in several places where C's implicit pointer conversions would normally handle the type differences. The patch also aligns `xdlclass_t::ha` with `xrecord_t::ha` as suggested by Johannes Schindelin.

The changes touch nearly all major xdiff components (xdiffi.c, xemit.c, xmerge.c, xpatience.c, xprepare.c, xtypes.h, xutils.c) but are mechanical in nature - adding casts and type updates without changing behavior. The patch maintains all existing functionality while preparing the codebase for future Rust integration.

This continues the series' pattern of incremental, infrastructure-focused changes that simplify xdiff internals while maintaining compatibility. The explicit casts introduced here will eventually be replaced by proper Rust FFI handling in later patches. The changes demonstrate careful attention to cross-language type safety while avoiding any functional impact on Git's diff behavior.
