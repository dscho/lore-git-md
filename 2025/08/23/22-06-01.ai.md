This is a documentation patch clarifying the experimental status of the `extensions.compatobjectformat` configuration option. The patch adds a warning note to the config documentation stating that the feature is incomplete and subject to change.

The commit explains that the compatibility object format currently only works for loose objects, not packed objects, making it unsuitable for real-world use with push/fetch operations. The author notes they've observed users (particularly Gitolite users) attempting to use this feature expecting full functionality when it's actually broken in many cases.

The patch acknowledges this should have been marked experimental from the start, as the current implementation has significant limitations: inefficient storage format, lack of submodule support, and pathological performance with even small repositories. The author defends the retroactive experimental label by pointing out the feature is fundamentally incomplete without their broader SHA-256 interoperability work.

The change is minimal - just a 3-line addition to the config file documentation with a clear technical downside, though it may be controversial with users who were relying on the existing (albeit broken) behavior. The patch provides important context about the feature's limitations that wasn't previously documented.
