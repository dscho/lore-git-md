This is part 14/15 of the ongoing Rust infrastructure series for xdiff, specifically focusing on type alignment between C and Rust. The patch completes the type conversion of xdfile_t fields that were still using C types, making them consistent with Rust's type system.

The changes standardize several key data types across xdiff implementation files:
- Converts `unsigned long` hash arrays to `u64`
- Changes `char*` change markers to `u8*`
- Updates array indices from `long` to `usize`/`isize`
- Affects core diff operations in xdiffi.c, xdiffi.h, and xtypes.h

The modifications maintain all existing behavior while ensuring type compatibility with Rust. This continues the series' pattern of incremental, behavior-preserving changes that prepare for future Rust integration. The patch touches fundamental diff algorithm components but doesn't introduce new functionality - it's purely a type system alignment change.

Key technical points:
- Updates diffdata_t struct fields (ha, rindex, rchg)
- Modifies xdfile_t struct to use Rust-aligned types throughout
- Maintains all existing casts and array bounds checks
- Preserves the dual C/Rust memory management approach
- Keeps all platform support constraints unchanged from previous patches
