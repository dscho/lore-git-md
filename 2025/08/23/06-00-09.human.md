Feature patch adding `git refs exists` subcommand as part of ref command consolidation effort. This is the first patch in a v2 series from Meet Soni's GSoC project, building on prerequisite work that has now been merged.

The patch introduces a new `git refs exists` command that duplicates the functionality of `git show-ref --exists`, checking whether a reference exists and returning appropriate exit codes (0 for exists, 2 for missing, 1 for errors). The implementation intentionally duplicates the ~20 lines of core logic from show-ref rather than creating shared infrastructure, as the author argues this would be overkill for such a small amount of code.

Documentation is added to git-refs.adoc explaining the new subcommand's behavior. The implementation uses refs_read_raw_ref() for the same error handling as show-ref, maintaining behavioral parity while moving the functionality under the refs namespace. This continues the broader effort to consolidate ref-related commands.

The patch appears well-crafted with clear commit message explaining the design choice to duplicate rather than share code. It follows the test reorganization suggested in v1 reviews (though the tests themselves appear in later patches in the series). The change is focused and maintains compatibility while advancing the refs command consolidation goal.
