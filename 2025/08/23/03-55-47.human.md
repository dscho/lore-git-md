This is a feature patch introducing a new interoperable vector type (`ivec`) for the ongoing Rust infrastructure work in Git. It's part 6 of a 15-part series focused on enabling Rust components to work smoothly with Git's C codebase.

The patch creates a new vector abstraction designed specifically for FFI (Foreign Function Interface) use between C and Rust. The standard Rust `Vec` and Git's `ALLOC_GROW` macros aren't well-suited for cross-language use due to allocator mismatches and interface differences. The new `ivec` type provides a consistent contract between languages, with matching memory layout and operations on both sides.

Key aspects include:
- Complete implementations in both C (`interop/ivec.c`) and Rust (`rust/interop/src/ivec.rs`)
- Support for common vector operations (push, reserve, resize, etc.)
- Memory management that works across language boundaries
- Type safety checks via an `element_size` field
- Comprehensive test coverage in the Rust implementation

The implementation looks thorough, with careful attention to alignment, capacity management, and cross-language consistency. This appears to be a foundational piece for the Rust integration work, solving a real interoperability problem in a way that could eventually be replaced by standard Rust vectors once the FFI needs diminish. The patch fits well with the series' systematic approach to infrastructure building.
