Platform compatibility patch simplifying progress meter signaling by replacing `setitimer()` with `alarm()`. This is the first of two patches in a series aimed at modernizing Git's signal handling infrastructure.

Carlo Marcelo Arenas Belón replaces the POSIX `setitimer()` function (marked obsolescent in recent standards) with the simpler `alarm()` for progress meter updates, since Git only needs whole-second intervals. The change removes 108 lines of platform-specific code while adding just 34 lines, significantly simplifying the implementation. The patch:
- Removes compatibility layers for `setitimer()` and related structs
- Updates the MinGW Windows compatibility code with a minimal `alarm()` implementation
- Adjusts build system files to remove now-unneeded checks
- Maintains the same progress reporting functionality during operations like clones and fetches

The change is well-motivated by standards compliance and code simplification. Reviewers will want to verify the Windows compatibility implementation works correctly, though the core change appears straightforward. The second patch in the series will address a race condition during shutdown that this change introduces.
