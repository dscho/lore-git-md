This is a feature patch introducing an FFI-compatible vector type (`ivec`) for the Rust infrastructure work in Git. It's part 6/15 of the ongoing xdiff Rust port series, following CI enhancements from previous patches.

The patch creates a new `ivec` type (interoperable vector) designed specifically for C/Rust FFI boundaries. It addresses several pain points in mixing Rust's `Vec` with Git's `ALLOC_GROW` macros by providing a unified interface that both languages can use directly. The implementation includes both C (`interop/ivec.c/h`) and Rust (`rust/interop/src/ivec.rs`) sides with matching functionality.

Key technical aspects:
- Struct layout is identical in both languages (ptr, length, capacity, element_size)
- Includes standard vector operations (push, reserve, clear, etc.)
- Memory management uses Git's allocator on C side, Rust's on Rust side
- Type-safe wrappers via macros in C (`DEFINE_IVEC_TYPE`)
- Comprehensive test suite in Rust
- Integrated into build system via new `INTEROP_OBJS` and `INTEROP_LIB`

The implementation is thorough, with careful attention to alignment, bounds checking (in Rust), and memory safety. The commit message clearly explains the motivation and design tradeoffs, particularly around the `element_size` field which enables concrete functions rather than macros. This appears to be a well-considered foundation for future Rust/C interop work in Git.

The patch fits cleanly into the series' incremental approach, building on previous infrastructure work while introducing core functionality needed for subsequent xdiff porting. The implementation quality suggests it will serve as a reliable building block for the Rust migration effort.
