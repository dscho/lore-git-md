This thread documents an update to the warning text for the experimental `extensions.compatobjectformat` configuration option, which was designed to allow SHA-1 repositories to reference SHA-256 objects but remains fundamentally incomplete. The original patch from brian m. carlson added a note about the feature's experimental status, but subsequent discussion with Junio C Hamano revealed this understated the situation - the option cannot fulfill its core purpose of enabling object exchange between repositories with different hash algorithms.

The latest patch strengthens the documentation to explicitly state this is a development-only tool with severe limitations: it only works for loose objects (not packed objects), making push/fetch operations non-functional, has inefficient storage characteristics, lacks submodule support, and exhibits pathological performance. The new wording makes clear this should not be used in production, particularly warning Gitolite administrators who might otherwise mistakenly enable it expecting cross-hash functionality. The thread demonstrates careful consideration of how to accurately communicate the feature's limitations while preventing user confusion about its capabilities. The patch maintains all previously established technical details while focusing specifically on improving the warning language in the config documentation.
