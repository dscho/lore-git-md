This thread discusses the documentation of the `extensions.compatobjectformat` config option, which was intended to enable SHA-1 repositories to reference SHA-256 objects but is fundamentally incomplete. The original patch from brian m. carlson added a warning about the feature's experimental status and known limitations, including that it only works with loose objects (not packed objects), making push/fetch operations non-functional, and has performance issues even in small repositories.

Junio C Hamano has now responded, agreeing that the warning is necessary but suggesting the "experimental" label may understate the situation. He proposes stronger wording to make clear that this extension exists purely for development purposes and is not suitable for end users. Both agree the current implementation could mislead users—particularly Gitolite administrators—into thinking the feature is functional when it isn't. The core technical limitation remains unchanged: without support for packed objects, the feature cannot fulfill its intended purpose of enabling object exchange between repositories. The discussion highlights the challenge of accurately documenting partially implemented features while setting appropriate user expectations.
