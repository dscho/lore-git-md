This is the first patch in a two-part series aimed at improving platform compatibility by replacing `setitimer()` with `alarm()` for progress meter signaling. The change is motivated by `setitimer()` being marked obsolescent in POSIX.1-2017.

The patch performs a direct replacement of `setitimer()` with `alarm()` in the progress meter implementation (`progress.c`), as the progress meter only require whole-second intervals. This results in significant code simplification, removing 108 lines while adding only 34. The changes include:

1. Removing platform-specific `setitimer()` compatibility layers in `compat/` directories
2. Eliminating build system checks for `setitimer()` and `struct itimerval`
3. Adding a minimal `alarm()` implementation for MinGW
4. Simplifying the Windows timer thread implementation in `compat/mingw.c`

The MinGW changes include modifying the timer thread to check if the signal handler has changed before raising SIGALRM, which helps prevent potential race conditions during shutdown. The patch notes this introduces a race condition that will be addressed in patch 2.

Key technical details:
- Progress meter now uses standard `alarm()` instead of POSIX `setitimer()`
- Removed `NO_SETITIMER` and `NO_STRUCT_ITIMERVAL` build flags
- Simplified Windows compatibility code (`compat/mingw*`)
- Changes affect core progress reporting in `progress.c`

The patch appears well-motivated and cleanly implemented, with clear commit message explaining the rationale. The follow-up patch will need to address the noted race condition. This change is part of broader work to modernize Git's signal handling infrastructure.
