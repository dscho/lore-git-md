This is a documentation patch introducing Git's Rust support policy, part of the larger RFC series for adding Rust infrastructure to xdiff (now in its third iteration). The patch adds a new `rust-support.adoc` document that lays out the rationale, goals, and technical approach for incrementally introducing Rust into Git.

The document makes a strong case for Rust adoption, citing memory safety benefits (noting that 70% of vulnerabilities in non-memory-safe languages are memory-related), developer ergonomics, and alignment with industry trends (including U.S. government security recommendations). It proposes an incremental approach where Rust will be introduced via a static library linked into existing binaries, with potential future moves to dynamic libraries or Rust-compiled binaries.

Key technical decisions include:
- Avoiding C-style types in favor of unambiguous Rust types (i32/i64) for better portability
- Preferring manual FFI wrappers over bindgen tools for more idiomatic Rust
- Supporting Rust versions matching Debian stable's lifecycle (approximately 3 years)
- Excluding Cargo.lock to allow distribution flexibility
- Explicitly not supporting beta/nightly Rust toolchains

The patch also updates the platform support policy to require Rust compatibility, making it a hard requirement for supported platforms going forward. The document appears thorough and well-considered, with clear technical reasoning behind each policy choice. As the foundational policy document for Git's Rust adoption, this is an important piece that will guide future technical work in the series.
