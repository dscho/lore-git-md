This is a two-patch series addressing platform compatibility, specifically replacing `setitimer()` with `alarm()` for progress meter signaling. The series is part of ongoing work to simplify Git's signal handling and improve Windows compatibility.

The first patch does a straightforward swap from `setitimer()` to `alarm()`, which is more widely available across platforms. However, as noted in the cover letter, this introduces a race condition during process shutdown. The second patch addresses this by adding a "shutting down" state to the SIGALRM handler to prevent potential crashes.

The series removes significant platform-specific code (108 lines deleted vs 34 added) across multiple build system files and compatibility layers. A third patch was considered but deferred, suggesting this may be part of a larger effort to modernize signal handling. The changes touch core progress meter functionality in `progress.c` while removing now-unneeded compatibility code from `compat/` directories and build files.

Key technical points for future reference:
- Replaces POSIX `setitimer()` with simpler `alarm()` calls
- Adds `shutting_down` state flag to `struct progress`
- Removes platform-specific timer implementations and build-time checks
- Affects progress meter updates during operations like clones/fetches
- Windows compatibility layer (`compat/mingw*`) sees significant simplification
