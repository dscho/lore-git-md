This is patch 5/16 in Patrick Steinhardt's series refactoring packfile management into `struct packfile_store`. The patch moves the MRU (most-recently-used) list of packfiles from `struct object_database` to the new `packfile_store` structure.

The changes are mechanical but wide-ranging:
- Removes `packed_git_mru` from `struct object_database`
- Adds `mru` field to `struct packfile_store`
- Updates all MRU list operations to use `store->mru` instead of `r->objects->packed_git_mru`
- Initializes the MRU list in `packfile_store_new()`
- Affects MRU handling in midx.c and packfile.c, particularly in `find_pack_entry()` which uses the MRU order for object lookups

The patch follows the established pattern of the series by moving packfile-specific state out of the generic ODB structure. It maintains identical behavior while better organizing the code for future pluggable ODB backends. The changes touch packfile.c/h, odb.c/h, and midx.c, with straightforward updates to call sites.

This continues the thread's focus on architectural encapsulation, with Patrick has previously noted that MRU list handling will be further standardized in later patches (particularly via `packfile_store_store_add()`). The patch doesn't address the open question about potentially consolidating the `packs` and MRU lists that was raised earlier in the thread - that appears to be deferred to a future series.
