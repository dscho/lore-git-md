This is part 12 of Patrick Steinhardt's ongoing series to abstract packfile management into a dedicated `struct packfile_store`. The patch introduces a new helper function `packfile_store_load_pack()` that consolidates the common pattern of checking for an existing packfile and loading/adding it if missing.

The new function handles:
1. Converting .idx paths to .pack paths for hashmap lookup
2. Checking if the packfile already exists in the store
3. Loading and adding new packfiles when needed
4. Returning either the existing or newly loaded packfile

The patch updates four call sites to use this helper:
- `fast-import.c` for end-of-pack registration
- `index-pack.c` for fsck operations
- `midx.c` for MIDX pack preparation
- `packfile.c` for general pack discovery

Key technical details:
- Maintains the same packfile loading logic but centralizes it
- Preserves all existing behavior including MRU list updates (via `packfile_store_add_pack()`)
- Handles both local and non-local packfiles through the `local` parameter
- Returns NULL on failure (matching existing error handling)

This is a straightforward refactoring that eliminates duplicate packfile loading logic while continuing the series' goal of encapsulating packfile operations. The changes are mechanical but improve maintainability by reducing code duplication around packfile management. The patch fits naturally in the series' progression toward a fully abstracted packfile store.
