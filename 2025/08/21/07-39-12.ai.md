This is a refactoring patch in Patrick Steinhardt's ongoing series to abstract packfile management into a dedicated `struct packfile_store`. Patch 14/16 removes the redundant `get_packed_git()` function in favor of using `get_all_packs()` consistently.

The key change eliminates the distinction between two similar packfile access functions - `get_packed_git()` simply loaded packfiles while `get_all_packs()` also prepared MIDX (multi-pack index) information. The patch argues this distinction is unnecessary since MIDX preparation is lightweight (relying on already-loaded data) and the function names were misleading about their actual differences.

The change affects several call sites:
- `builtin/gc.c` for incremental repacking
- `builtin/grep.c` for repository initialization
- `object-name.c` for object disambiguation and abbreviation length calculation

The implementation removes `get_packed_git()` from packfile.c and its declaration from packfile.h, converting all callers to use `get_all_packs()` instead. The patch maintains identical behavior while simplifying the API surface. This continues the series' pattern of consolidating packfile-related functionality into the new store abstraction.

The change is well-justified in the commit message with analysis of the performance impact and rationale for unification. It follows naturally from previous patches in the series and doesn't introduce new complexity. The diff shows straightforward mechanical conversions at each call site, suggesting this is a safe, focused refactoring step in the larger architectural effort.
