This is a documentation patch discussion for gitk's README.md, with maintainer feedback on content focus and presentation.

Johannes Sixt, the gitk maintainer, provides substantive feedback on Michael Rappazzo's proposed README.md. He argues the current technical contribution-focused content should be rebalanced to better serve first-time visitors, suggesting the document should open with a clear explanation of what gitk is and include usage examples or links to the manual. Sixt recommends removing the detailed email submission tutorial in favor of simpler guidelines, noting the existing 'gitk:' commit prefix convention is sufficient for distinguishing submissions without requiring special `format-patch` syntax.

Key technical points raised include:
- Rejection of declaring any repository as "official" by fiat, preferring the Git project's conventional approach to authority
- Suggestion to de-emphasize the gitk-git/ subtree relationship details
- Confirmation that patches from gitk-git/ are technically acceptable (contrary to the README's current wording)
- Preference for linking to external resources rather than duplicating submission tutorials

The feedback indicates the maintainer wants the README to prioritize user orientation over contributor mechanics, while still maintaining the core requirements (Signed-off-by, dual-hosting status). This represents a significant shift from Rappazzo's current patch which focuses heavily on contribution workflows. The discussion continues the thread's pattern of refining documentation to balance technical accuracy with accessibility, now with the maintainer weighing in on the document's primary audience and scope.
