This is the first patch in a 16-part series refactoring Git's object database (ODB) infrastructure to better support pluggable backends. The patch introduces a new `struct packfile_store` to centralize packfile management, which is currently spread across `struct packed_git` and `struct object_database`.

The change is purely structural at this point - the new empty structure is allocated when creating an ODB but doesn't yet contain any functionality. The commit message explains this is preparatory work for two future goals: (1) making packfile management self-contained so it can be moved to the ODB source level, and (2) eventually removing the `next` pointer from `struct packed_git` to make it purely represent a single packfile.

The patch touches odb.c/h and packfile.c/h, adding the new structure and its allocation/free functions while maintaining all existing behavior. This appears to be a well-scoped first step in a larger architectural change, with clear explanations of both the immediate change and the longer-term direction. The patch follows the series' pattern of mechanical but careful refactoring to enable future pluggable ODB backends.
