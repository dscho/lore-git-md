Feature patch implementing `git refs exists` subcommand as part of refs command consolidation effort (GSoC project). This is patch 1/2 in the series, introducing the core functionality.

The patch adds a new `exists` subcommand to `git refs` that duplicates the behavior of `git show-ref --exists`, checking for ref existence with the same exit codes (0=exists, 2=missing, 1=error). The implementation in builtin/refs.c directly calls refs_read_raw_ref() and handles the same error cases as show-ref, though the author notes this is a deliberate duplication rather than shared helper since the logic is minimal (~20 lines).

Key technical details:
- New subcommand added to builtin/refs.c with corresponding usage string
- Uses get_main_ref_store() and refs_read_raw_ref() to check existence
- Documents behavior in git-refs.adoc including exit code meanings
- Follows same error handling patterns as show-ref (ENOENT/EISDIR for missing refs)
- Part of broader refs command consolidation but maintains duplicate logic with show-ref for now
