This is part 4 of Patrick Steinhardt's ongoing refactoring series to move packfile management into a dedicated `struct packfile_store`. The patch relocates the packfile map (used to track loaded packfiles by path) from `struct object_database` to the new store structure.

The changeset:
- Moves the `pack_map` hashmap and its initialization/cleanup code
- Converts the comparison function `pack_map_entry_cmp()` to static since it's now only used within packfile.c
- Updates MIDX code to reference the map via the new location
- Maintains all existing functionality while better organizing the code

This continues the mechanical but systematic work to separate packfile concerns from the generic object database infrastructure. The patch appears straightforward and well-contained, following the established pattern from earlier patches in the series. No behavioral changes are introduced - it's purely moving code to its logical home in preparation for future pluggable ODB backends.
