This is the foundational patch in Patrick Steinhardt's 16-part series refactoring packfile management as part of the object database (ODB) abstraction effort. It introduces a new `struct packfile_store` to centralize packfile-related state that is currently scattered between `struct object_database` and `struct packed_git`.

The patch creates the basic infrastructure with allocation/free functions (`packfile_store_new()` and `packfile_store_free()`) and hooks it into the ODB initialization via `odb_new()`. The structure is currently empty but will be populated with packfile-related fields in subsequent patches. The commit message explains this is preparatory work for two future goals: (1) making packfile management self-contained and (2) eventually moving this responsibility down to the ODB source level for pluggable backends.

Key technical details for future reference:
- New files/modified: odb.c, odb.h, packfile.c, packfile.h
- Initializes empty `struct packfile_store` with just an `odb` backpointer
- Adds store to `struct object_database` as `packfiles` member
- Maintains all existing behavior - purely additive changes
- Sets up for subsequent patches to migrate:
  - `packed_git` list
  - MRU list
  - packfile map
  - other packfile-related fields from ODB

The patch follows the series' established pattern of mechanical, behavior-preserving refactoring. It touches core packfile infrastructure but introduces no functional changes, keeping risk low while enabling the larger architectural goal of better encapsulation. The thread context indicates this approach has been well-received in reviews, with discussion focused on implementation details rather than the overall direction.
