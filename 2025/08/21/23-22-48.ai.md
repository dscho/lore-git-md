This is the third patch in a refactoring series that's part of the `the_repository` removal effort, specifically targeting the bulk-checkin subsystem. The patch makes `index_blob_bulk_checkin()` require a transaction parameter, eliminating its previous dual-mode operation where it could work with or without a transaction.

The key change is removing the fallback path in `index_blob_bulk_checkin()` that previously created a temporary packfile for standalone operations. Now all calls must provide a transaction, with the single call site in `object-file.c` updated to create one if none exists. The patch simplifies the bulk-checkin implementation by removing 15 lines of conditional logic while maintaining the same behavior through proper transaction handling.

The documentation in bulk-checkin.h is updated to clarify the new contract - objects written during the same transaction go to the same packfile, which only flushes when the transaction commits. The change affects three files with 21 insertions and 22 deletions, with the main impact being in `object-file.c` where transaction handling is now explicitly managed around the bulk-checkin call.

This continues the series' pattern of systematically eliminating global state while maintaining backward compatibility. The implementation follows the architectural consensus from earlier discussion, with the transaction now properly carrying repository context through its object_database parent. The change is relatively straightforward but important for the subsystem's long-term design.
