This is part 10 of Patrick Steinhardt's ongoing series to abstract packfile management into a dedicated `struct packfile_store`. The patch refactors `install_packed_git()` to work directly with the packfile store rather than a repository, renaming it to `packfile_store_add_pack()` to better reflect its scope.

The changes are mechanical but wide-ranging, updating callers in fast-import.c, index-pack.c, http.c, midx.c, and packfile.c to use the new interface. The function now takes a `packfile_store` parameter instead of a repository, and maintains the same behavior - adding the pack to both the main pack list and the hashmap for lookups. The patch elements include:
- Renamed function with updated signature
- Updated documentation in http.h
- Call site updates across multiple subsystems
- Maintained existing packfile addition logic (pack list prepending and hashmap insertion)

This continues the series' pattern of moving packfile-specific operations out of the generic object database infrastructure. The changes are straightforward given the established direction of the series, with no new functionality introduced. The mechanical nature of the patch suggests it should integrate cleanly with the prior work, though reviewers will want to verify the call site updates are complete and correct.
