This is the second patch in Jeff King's series fixing color handling in Git's interactive patch mode. It specifically makes `add-interactive` respect `color.diff` settings, restoring behavior that was lost in the 2021 Perl-to-C conversion.

The patch addresses a regression where `git add -p` would ignore `color.diff=false` and always color diffs if `color.ui` was enabled. The fix involves properly separating the color configurations for interactive prompts (controlled by `color.interactive`) from diff colors (controlled by `color.diff`). This required significant refactoring of the color initialization code in `add-interactive.c` to maintain two color states independently.

The changes are well-motivated by historical behavior and include two new tests that verify the proper separation of concerns between prompt and diff coloring. The implementation carefully handles edge cases like the "reset" color which is used in both contexts, introducing separate reset colors for each purpose.

This is a thorough fix that maintains backward compatibility while properly restoring the documented behavior. The patch builds on the thread's earlier discussion and sets up the foundation for the remaining fixes in the series.
