Documentation formatting clarification for `git repo info` patch series.

Junio C Hamano confirms Jean-Noël Avila's correction about the proper syntax formatting for the `git repo info` command's option documentation. The discussion centers on how to correctly space the pipe character (`|`) when showing alternative options in the man page syntax. 

This is a minor but important documentation polish for the GSoC patch series that adds a `-z` shorthand flag to `git repo info`. The series is otherwise technically ready, with mentor sign-offs, and builds on the existing `lo/repo-info` topic. The only remaining open questions are about naming conventions for the new object format field, which are being discussed separately in the thread.

The correction follows Git's CodingGuidelines, which specify different spacing rules for pipes depending on whether they separate top-level options (needs spacing) or sub-options within parentheses/brackets (no spacing).
