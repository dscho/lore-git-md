This is a documentation patch for gitk's README.md, with maintainer feedback on content priorities. Maintainer Johannes Sixt responds to Michael Rappazzo's proposed README with several key suggestions for improvement.

The maintainer wants the README to better serve first-time visitors by explaining what gitk is and how to use it, with links to the manual, rather than focusing on contribution mechanics. He suggests removing the detailed `format-patch` tutorial in favor of simpler guidelines, noting that the existing 'gitk:' commit prefix convention is sufficient for distinguishing submissions. 

Sixt also clarifies repository status messaging - avoiding "official repository" claims since any clone could make the same claim, and suggests simplifying the dual-repository explanation. He's more permissive about contribution sources than the draft README, noting that patches from gitk-git/ are technically workable via `git am -3`.

The feedback indicates this documentation effort is heading in the right direction but needs to rebalance its audience priorities - less emphasis on contributor mechanics (which could be linked to rather than explained in detail) and more on welcoming new users to the tool itself. The patch appears well-intentioned but needs refinement to match the maintainer's vision for the README's role.
