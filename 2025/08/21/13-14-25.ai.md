This is a follow-up in the submodule gitdir path encoding series, specifically addressing platform compatibility issues in patch 6/9. Adrian Ratiu acknowledges two Windows-specific problems identified by Jeff King: 

1) The use of `pathconf()` which isn't available on Windows, requiring a compat wrapper that falls back to `NAME_MAX`. 

2) Format string portability issues with `%z` and `%ld` that need to be replaced with `PRIuMAX` for Windows' 64-bit LLP model.

Ratiu also notes potential macOS CI failures in t7527.62 (submodule absorbgitdirs test) that may relate to the series, though the exact connection isn't yet diagnosed. He commits to fixing these issues in v2 using GitHub CI for testing since he lacks direct access to Windows/macOS systems. 

The response highlights the challenges of cross-platform development in Git, particularly around filesystem path handling and printf formatting. Ratiu's acknowledgment of the issues and commitment to fixes maintains the series' forward progress while addressing the critical platform-specific edge cases that emerged in CI testing. The core path encoding mechanism remains unchanged - this is purely about making it work correctly across all supported platforms.
