This is a refactoring patch in Patrick Steinhardt's ongoing series to move packfile management into `struct packfile_store`. The email responds to Jeff King's historical context about why Git maintains both a main packfile list and an MRU (most-recently-used) list, with Patrick noting there are currently some code paths that don't properly maintain the MRU list.

Key technical details:
- The MRU list optimization was originally kept separate from the main packfile list to avoid breaking order-dependent code
- Patrick confirms there are currently inconsistencies in MRU list maintenance (fast-import.c, index-pack.c, packfile.c via prepare_pack())
- Later in the series, `packfile_store_store_add()` will standardize MRU handling
- Patrick plans a follow-up series to potentially consolidate the lists, agreeing with Jeff King that this should happen after the current refactoring

The discussion continues the careful, incremental approach to this major refactoring - first mechanically moving functionality, then considering optimizations and simplifications in subsequent work. Patrick's response shows awareness of the historical context while maintaining focus on the immediate goal of cleanly separating packfile state from the ODB structure.
