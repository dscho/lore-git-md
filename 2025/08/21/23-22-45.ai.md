This is a v2 patch series continuing the `the_repository` removal effort, specifically targeting the bulk-checkin subsystem which handles batched object writes to the object database. The series builds on previous discussion where consensus was reached about requiring transactions for all bulk-checkin operations.

The key changes in v2:
1. Makes `index_blob_bulk_checkin()` require a transaction parameter, eliminating the special case where it could be called without one
2. Updates all functions to consistently access repository context through the transaction's `struct object_database` pointer
3. Adjusts call sites across multiple files to provide the required transaction context

Technical details:
- Introduces `struct odb_transaction` to encapsulate state (patch 1)
- Moves transaction state from globals to `struct object_database` (patch 2)
- Enforces transaction requirement in `index_blob_bulk_checkin()` (patch 3)
- Updates repository access to use transaction context (patch 4)

The series affects 9 files with 142 insertions and 101 deletions, following established patterns for global state removal. Two globals (`pack_compression_level` and `pack_size_limit_cfg`) remain temporarily via `USE_THE_REPOSITORY_VARIABLE`.

This version addresses the architectural concern raised in the thread about repository context propagation by making transactions mandatory throughout the subsystem. The changes appear thorough and maintain consistent behavior while progressing toward the long-term goal of removing `the_repository` dependencies.
