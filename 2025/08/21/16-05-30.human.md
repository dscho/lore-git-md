Maintainer follow-up on reftable adoption for case collision issues.

Junio Hamano responds to Patrick Steinhardt's proposed error message about case collision handling in the files backend, arguing that simply telling users to "live with" the limitation isn't practical since it prevents basic operations like fetching updates. He emphasizes that the reftable backend is the real solution, though notes Patrick's point about ecosystem compatibility (particularly libgit2) remains relevant.

The exchange shows the maintainer pushing for clearer guidance to users to migrate to reftable rather than attempting workarounds with the files backend. While Patrick is working on libgit2 support, Junio's position suggests the Git project should move forward with recommending reftable as the default solution for this class of problems, treating ecosystem support as a secondary consideration that will follow.

This continues the thread's shift toward treating reftable as production-ready rather than an experimental option, with the maintainer now clearly advocating for it as the primary resolution path for case collision issues.
