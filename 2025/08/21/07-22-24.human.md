This is the third patch in Jeff King's series fixing color handling regressions in Git's interactive patch mode (`-p`/`--patch`). The patch addresses a subtle issue where commands like `checkout -p` weren't properly falling back to the `color.ui` setting when `color.diff` wasn't explicitly configured.

The core problem stems from the 2021 Perl-to-C conversion, where the Perl version automatically handled color fallbacks via `git config --get-colorbool`, but the C version relies on each command properly initializing color configuration. While `add -p` worked fine, other commands like `checkout -p` didn't initialize color at all, causing them to ignore `color.ui` settings.

King's solution is elegant - rather than requiring every command to initialize color config (which would be error-prone), he centralizes the fallback logic in the interactive code itself. The patch adds explicit handling for `color.ui` in `add-interactive.c` while being careful not to break plumbing commands that intentionally avoid porcelain configs. The change comes with new test coverage verifying that `color.ui=false` now properly disables colors across all interactive commands.

This is a well-motivated fix that maintains backward compatibility while solving the root cause. The patch demonstrates careful consideration of Git's configuration architecture and includes thorough testing. It's a solid middle piece of the series, building on the previous patches' groundwork while setting up for the final documentation update.
