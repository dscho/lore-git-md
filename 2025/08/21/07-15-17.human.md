Bugfix addressing color handling in `git stash -p` when used with `GIT_PAGER_IN_USE`. This is the first patch in a series fixing color configuration regressions in interactive patch mode across several Git commands.

Jeff King fixes a specific issue where `git stash -p` could produce malformed output when `GIT_PAGER_IN_USE` is set in the environment. Normally, `diff-tree` wouldn't output color when piped (due to non-tty stdout), but this environment variable overrides that check. The color codes then confuse `git-apply`, causing the stash operation to fail. While this is an edge case (mainly affecting test environments that set `GIT_PAGER_IN_USE` to test color output), it's a real bug that could affect users.

The fix explicitly passes `--no-color` to all `diff-tree` calls in `builtin/stash.c`. This is a conservative solution that avoids tackling the larger issue of whether plumbing commands like `diff-tree` should default to color output at all - a longstanding debate referenced in the commit message. The patch includes a new test case that verifies the fix works when both `GIT_PAGER_IN_USE` and `TERM` are set.

This appears to be a well-justified fix with clear motivation and test coverage. It's part of a larger effort to clean up color handling regressions introduced during the 2021 Perl-to-C conversion of interactive commands. The patch stands on its own but fits into the broader series addressing color configuration issues across multiple commands.
