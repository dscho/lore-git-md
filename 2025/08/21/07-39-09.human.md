This is part 11 of Patrick Steinhardt's ongoing series to refactor packfile management into a dedicated `packfile_store` structure. The patch addresses an inconsistency in how packfiles are added to the most-recently-used (MRU) list.

Currently, when adding a packfile to the store, it gets added to the main list and hashmap but not consistently to the MRU list. Some subsystems manually add it to MRU later, while others rely on it being added when objects are accessed. This patch standardizes the behavior by always adding packfiles to the MRU list when they're first added to the store.

The change is straightforward - it moves the MRU list addition into the central `packfile_store_add_pack()` function and removes the redundant addition from `midx.c`. This makes the MRU handling more consistent and predictable while maintaining the same behavior. The patch continues the series' pattern of mechanical refactoring while improving internal consistency.

This change aligns with earlier discussion in the thread about MRU list handling, where Patrick noted plans to standardize this behavior. It's a clear improvement to the internal API that should make future maintenance easier.
