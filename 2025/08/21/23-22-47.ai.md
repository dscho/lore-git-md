This is the second patch in a 4-part series refactoring Git's bulk-checkin subsystem as part of the `the_repository` removal effort. The patch moves transaction state management from global variables into `struct object_database`, completing the architectural shift agreed upon in earlier discussion.

Key technical changes:
- Adds `transaction` field to `struct object_database` to hold bulk-checkin state
- Updates all transaction functions (`begin_odb_transaction`, `flush_odb_transaction`, `end_odb_transaction`) to operate on a repository-specific transaction object
- Modifies bulk-checkin operations (`prepare_loose_object_bulk_checkin`, `fsync_loose_object_bulk_checkin`, `index_blob_bulk_checkin`) to require transaction context
- Updates call sites across 9 files to provide the transaction parameter
- Maintains backward compatibility by handling NULL transactions in `index_blob_bulk_checkin`

The changes systematically eliminate global state while preserving existing behavior. The patch follows the established pattern for `the_repository` removal by first restructuring state management before fully removing global dependencies. This represents significant progress in the subsystem's modernization, with all bulk-checkin operations now properly repository-aware.
