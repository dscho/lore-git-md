This is a feature patch introducing a new `git refs exists` subcommand, part of Meet Soni's GSoC project to consolidate ref-related commands under the `git refs` namespace. It's the first of a 2-patch series (v1).

The patch adds functionality identical to `git show-ref --exists` - checking if a reference exists and returning appropriate exit codes (0 for exists, 2 for missing, 1 for errors). The implementation intentionally duplicates the simple ~20-line logic from show-ref rather than creating shared infrastructure, which the commit message argues would be overkill for such a small function.

The change adds documentation to git-refs.adoc and implements the command in builtin/refs.c using the refs API directly. The implementation looks straightforward and well-contained, with proper error handling and cleanup. The patch appears to be part of a mentored project, carrying sign-offs from both mentors.

This continues the broader effort to move ref-related functionality under the `git refs` umbrella, though it notably doesn't deprecate `show-ref --exists` yet. The approach seems pragmatic for this initial implementation, though the long-term plan for handling the duplicate functionality isn't addressed here.
