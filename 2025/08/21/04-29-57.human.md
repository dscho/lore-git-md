This is a feature proposal regarding Git's conditional configuration includes. The author, engdoc, points out that when both `includeIf.gitdir` and `includeIf.hasconfig` conditions match for a repository, Git always processes the gitdir condition first, regardless of their order in the config file. This hardcoded behavior prevents users from overriding gitdir-based includes with hasconfig-based ones when both match.

The proposal suggests three possible solutions: allowing users to specify include priority order, always processing hasconfig first, or adding a configuration option to control this behavior. The motivation is to enable more flexible configuration setups where users could override repository-path-based includes with config-file-based ones when needed.

The patch appears to be a thoughtful request for a real-world use case, though it's currently just an RFC without implementation details. The change would affect Git's config parsing logic and could have implications for existing configurations that rely on the current behavior. The proposal seems well-motivated for team workflows where context-aware configuration overrides would be useful.
