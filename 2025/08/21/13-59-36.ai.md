Bugfix proposal for deprecated `git whatchanged` interaction with Jenkins GitSCM. 

This email reports that the new requirement in Git 2.51.0 to use `--i-still-use-this` with the deprecated `git whatchanged` command is breaking Jenkins' GitSCM plugin, which still relies on this command internally. The author has reported the issue to the Jenkins team but suggests adding a Git configuration option (proposing names like `core.ignoreDeprecations` or `core.iReallyMeanIt`) to bypass the CLI requirement, since Jenkins provides no way to modify the command being run.

The patch appears motivated by real-world compatibility concerns, though the proposed solution would effectively undermine the deprecation warning's purpose. The suggestion to make the warning suppressible via config rather than CLI flag may prove controversial, as it could lead to silent continued use of deprecated features. The email doesn't propose specific code changes but floats the config option idea for discussion. The issue highlights the tension between deprecating old interfaces and maintaining compatibility with third-party tools that haven't yet updated.
