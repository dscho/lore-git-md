Bugfix discussion regarding case-sensitivity conflicts in batched ref transactions during fetch operations.

Jeff King responds to Patrick Steinhardt's analysis of the "lock file exists" errors in bare repository fetches, agreeing that the new batched transaction mode in git-fetch(1) is likely exposing pre-existing case-sensitivity issues on macOS filesystems. Where previous versions might have silently allowed inconsistent ref updates due to case collisions (treating "PTV-2164" and "ptv-2164" as distinct), the batched mode now properly detects these as lock conflicts.

The discussion suggests two paths forward: either adding detection logic to handle case collisions gracefully (ejecting problematic refs while continuing the transaction) or waiting for wider adoption of the reftable backend which avoids filesystem-level locking entirely. Jeff King leans toward the latter approach, hinting that reftable support in Git 3.0 might make this a temporary issue.

This appears to be a case where new correctness checks are revealing underlying filesystem quirks rather than introducing new bugs. The thread shows developers converging on understanding the root cause while considering both short-term fixes and long-term architectural solutions.
