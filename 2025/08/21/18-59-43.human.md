This is a refactoring patch for git-gui's command execution infrastructure, now in its second version with all feedback addressed. Johannes Sixt (signing as Hannes) is giving final approval to Mark Levedahl's simplification of how git-gui handles the `nice(1)` command for long-running operations.

The patch moves from dynamically checking for `nice` availability during each command execution to a single check at startup, stored in a global `_nice` variable. This reduces the code from 23 lines to 7 while maintaining identical functionality. Version 2 fixes path handling with spaces (using Tcl's `{*}` expansion operator) and incorporates documentation improvements suggested in the first round.

Johannes notes the only behavioral difference - `nice` is now checked once at startup rather than on demand - but considers this negligible for performance. He queues the patch with a minor typo fix in the commit message ("lets" -> "let's"). The change appears uncontroversial and ready for inclusion, having addressed all feedback from the first submission.
