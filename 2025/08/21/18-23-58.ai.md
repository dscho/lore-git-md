Feature patch series follow-up regarding documentation formatting.

Jean-Noël AVILA points out a documentation formatting issue in Lucas Seiki Oshiro's patch adding the `-z` flag to `git repo info`. The current patch shows the option syntax as `[--format=(keyvalue|nul)|-z]` but should follow Git's CodingGuidelines by adding spaces around the pipe when used for alternate options (as opposed to alternate arguments within an option).

The correct formatting should be `[--format=(keyvalue|nul) | -z]` per the guidelines, which distinguish between:
1. Alternate options (spaces around pipes)
2. Alternate arguments within an option (no spaces around pipes)

This is a minor documentation nit in an otherwise merge-ready patch series that adds two features to `git repo info`:
1. The `-z` flag as shorthand for null-terminated output
2. An `objects.format` field showing the repository's object format

The series has already received mentor sign-offs from Karthik Nayak and Patrick Steinhardt, with Junio C Hamano confirming it builds on the `lo/repo-info` topic for Git 2.51. This appears to be the final documentation clarification needed before merging.
