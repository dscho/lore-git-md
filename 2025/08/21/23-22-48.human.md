This is the third patch in a refactoring series to eliminate global state in Git's bulk-checkin subsystem as part of the `the_repository` removal effort. The patch focuses on `index_blob_bulk_checkin()`, which previously had special handling for cases where no transaction was provided - it would create and immediately commit a single-object packfile. 

The change makes transactions mandatory for all `index_blob_bulk_checkin()` calls, simplifying the function by removing its dual-mode behavior. The single call site in `object-file.c` is updated to create a transaction if one doesn't already exist, using the new transaction API from earlier patches. The patch maintains backward compatibility while enforcing the new transaction requirement.

The implementation is straightforward - the bulk-checkin.c changes remove the conditional logic, while object-file.c gains transaction handling. Documentation in bulk-checkin.h is updated to clarify the transaction requirement. This continues the series' pattern of moving toward repository-parameterized interfaces while eliminating global state.

The changes are well-contained (22 lines net change across 3 files) and follow the architectural direction established in earlier discussion. This represents another incremental step in making the bulk-checkin subsystem properly repository-aware.
