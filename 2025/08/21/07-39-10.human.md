This is part 12 of Patrick Steinhardt's ongoing series to refactor packfile management into a dedicated `struct packfile_store`. The patch introduces a new helper function `packfile_store_load_pack()` that consolidates the common pattern of checking if a packfile exists in the store and adding it if not.

The function handles the non-trivial logic of converting .idx paths to .pack paths for hashmap lookups, checking for existing packfiles, and adding new ones when needed. It replaces several manual implementations of this pattern in fast-import.c, index-pack.c, midx.c, and packfile.c with a single consistent interface.

The change is a natural progression in the series' goal of centralizing packfile operations. It follows the earlier standardization of MRU list handling in patch 11 and continues the mechanical but careful refactoring approach seen throughout. The patch maintains identical behavior while making the code more maintainable by eliminating duplicate logic.

The implementation looks clean and well-contained, affecting only packfile operations while leaving other subsystems unchanged. As with previous patches in the series, this appears to be a straightforward improvement that moves the codebase toward the ultimate goal of pluggable ODB backends.
