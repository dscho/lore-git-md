This is a documentation patch that fixes and clarifies the formatting of `includeIf` condition syntax in Git's configuration documentation.

The patch corrects an inconsistency where the `hasconfig:remote.*.url:` condition was documented with an extra colon after the keyword, while other conditions were not. The documentation preamble already states that the colon is a separator between the keyword and its data, not part of the keyword itself. 

Junio Hamano updates the documentation to:
1. Remove the erroneous extra colon from `hasconfig:remote.*.url:`
2. Consistently phrase all condition descriptions to clarify that the data follows "the keyword and a colon"
3. Maintain the same meaning while making the syntax rules clearer

The changes are straightforward and improve consistency in the docs. Since this comes from the Git maintainer and touches only documentation, it's likely to be accepted without controversy. The patch is small (4 insertions, 5 deletions) and focused purely on documentation clarity.
