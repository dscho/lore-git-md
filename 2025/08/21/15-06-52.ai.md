This is a documentation patch fixing inconsistencies in how includeIf conditions are described in the config documentation. Junio Hamano points out that commit 399b1984 accidentally documented the `hasconfig:remote.*.url:` condition with an extra colon in the keyword itself, when the colon should properly be seen as a separator between the keyword and its parameter. The patch standardizes all includeIf condition descriptions to clarify that the colon is not part of the keyword but rather separates it from the parameter data. 

The changes affect three conditions in Documentation/config.adoc: `gitdir`, `onbranch`, and `hasconfig:remote.*.url`. Each is updated to consistently show the colon as a separator rather than part of the keyword, with matching phrasing about "the keyword X and a colon". The `hasconfig:remote.*.url` case also loses its trailing colon in the keyword definition.

This is a straightforward documentation cleanup that brings consistency to how these configuration include conditions are described. The patch maintains all existing functionality while making the documentation more precise about the syntax. The changes are minimal but improve clarity for users reading about includeIf conditions.
