This is a feature proposal regarding Git's conditional configuration includes. The author requests changing the precedence between `includeIf.gitdir` and `includeIf.hasconfig` when both conditions match for a repository.

Currently, Git always processes `gitdir` includes first, which the author finds limiting for their workflow where they'd prefer `hasconfig` to take precedence. The proposal suggests three possible solutions: allowing user-specified priority order, always processing `hasconfig` first, or adding a configuration option to control the behavior.

The use case involves wanting per-repository configuration overrides based on config file presence rather than repository path. The current hardcoded behavior prevents this workflow. The proposal is framed as an RFC (Request for Comments) rather than a concrete implementation, suggesting the author is seeking feedback on the best approach before writing code.
