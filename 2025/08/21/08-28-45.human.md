This is a technical response in the ongoing hash algorithm transition discussion. Brian m. carlson clarifies several practical concerns raised by Simon Richter about maintaining compatibility with SHA-1 commit IDs during the transition to SHA-256.

The key points are that:
1. Object IDs will remain usable - the testsuite changes are about reducing brittleness, not deprecating SHA-1 references
2. Existing repositories will keep using SHA-1 unless explicitly converted
3. New repositories will default to SHA-256 but can still opt for SHA-1
4. Interoperability code exists (though not yet upstream) that will allow conversion between hash formats via cloning

Brian notes the interoperability work currently has limitations (no support for shallow/partial clones or submodules) and needs more polish before submission. This response provides concrete technical details about the transition mechanics while reassuring users that SHA-1 references won't suddenly break. The tone is informative and addresses the specific workflow concerns raised, positioning this as part of the broader SHA-1/SHA-256 transition effort.
