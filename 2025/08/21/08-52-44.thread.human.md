This thread introduces a new `git refs exists` subcommand as part of Meet Soni's GSoC project to consolidate ref-related commands under the `git refs` namespace. The command duplicates the functionality of `git show-ref --exists` with identical exit codes (0 for existing refs, 2 for missing, 1 for errors).

The implementation in builtin/refs.c uses refs_read_raw_ref() for lookups, matching show-ref's behavior. Meet deliberately chose to duplicate the ~20 lines of checking logic rather than abstracting it, considering this simpler for such a focused operation. The series builds on Git v2.51.0 with prerequisite refs-list changes already merged.

In version 2, Meet addressed all major feedback from the initial review. Key changes include rebasing onto master and reorganizing the test infrastructure per Patrick Steinhardt's suggestion - splitting existence checks from t1403-show-ref.sh into a new test file and sharing setup logic between test suites. The tests cover regular refs, HEAD, symrefs, and special refs like FETCH_HEAD.

Patrick reviewed the initial version and supports the approach, while Junio Hamano provided guidance on prerequisite documentation format. The implementation appears complete pending final review, with one open question about whether to maintain duplicate existence-checking logic between show-ref and refs exists long-term. This is part of Git's broader effort to consolidate ref-related commands under a unified namespace.
