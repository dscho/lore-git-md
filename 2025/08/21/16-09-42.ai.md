This is a documentation clarification in the ongoing `git repo info` enhancement series.

Junio C Hamano points to existing Git documentation guidelines regarding spacing around pipe characters in option syntax specifications. The thread had previously discussed formatting for the new `-z` flag in the `git repo info` synopsis, where Karthik Nayak suggested adding spaces around the pipe for readability. Hamano cites Documentation/CodingGuidelines which explicitly states not to use spaces around pipes when separating alternate arguments of an option, providing both correct and incorrect examples.

This resolves the last open question in the patch series about man page formatting - the correct syntax should be `[--format=(keyvalue|nul)|-z]` without spaces around the pipes. The series now appears ready for merging with all technical and documentation issues addressed, including the new `-z` flag alias and `objects.format` field addition, with both patches having mentor sign-offs from Karthik Nayak and Patrick Steinhardt.
