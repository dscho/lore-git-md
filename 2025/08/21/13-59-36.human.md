This is a bug report about a compatibility issue between Git's deprecation warning for `git whatchanged` and Jenkins' GitSCM plugin.

Randall Becker reports that the new requirement in Git 2.51.0 to use `--i-still-use-this` with the deprecated `git whatchanged` command is causing errors in Jenkins' GitSCM plugin, which still relies on this command. He has reported the issue to the Jenkins team but suggests Git could provide a config option like `core.ignoreDeprecations` or `core.iReallyMeanIt` to suppress the warning requirement, since Jenkins doesn't appear to offer a way to add the CLI option.

The issue highlights a real-world impact of Git's deprecation process, where a widely-used CI system hasn't yet updated its usage of the deprecated command. The suggestion for a config-based workaround seems practical, though it would need careful consideration to avoid undermining the deprecation warning's purpose. The tone is constructive, focusing on solving a concrete problem rather than complaining about the deprecation itself.
