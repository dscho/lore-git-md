Bugfix addressing color handling in `git stash -p` when `GIT_PAGER_IN_USE` is set. This is the first patch in a series fixing color configuration regressions in interactive patch mode across several Git commands.

The patch fixes a specific edge case where `git stash -p` could produce malformed output when `GIT_PAGER_IN_USE` is set in the environment. Normally, `diff-tree` wouldn't output color when piped to another command (like `git-apply`), but `GIT_PAGER_IN_USE` overrides this safety check. The fix explicitly passes `--no-color` to all `diff-tree` child processes spawned by `stash` operations.

The commit explains this is a workaround for a deeper issue where diff plumbing commands default to color output due to historical decisions (commit 4c7f1819b3). While changing that default was discussed in 2017, the author now agrees it would be better but considers it too risky to change now. The patch includes a new test case that verifies the fix by simulating the problematic environment conditions.

Key technical details:
- Files modified: `builtin/stash.c` (3 call sites updated) and `t/t3904-stash-patch.sh` (new test)
- Fix approach: Explicit `--no-color` flags for `diff-tree` invocations
- Edge case addressed: `GIT_PAGER_IN_USE` environment variable causing color output in plumbing
- Related commits referenced: 4c7f1819b3 (original color.ui default), 1c6ffb546b (similar fix for add-interactive)

The patch appears well-justified and narrowly focused, with clear test coverage for the specific issue. It leaves the larger question of plumbing command color defaults for future discussion while solving the immediate problem. The change is low-risk as it only affects behavior when color would have caused problems anyway.
