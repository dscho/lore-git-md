This is the second patch in Jeff King's four-part series fixing color handling regressions in Git's interactive patch mode. The patch specifically addresses how `add-interactive` (used by commands like `add -p`) handles color configuration.

The core issue is that after the Perl-to-C conversion, the interactive mode stopped respecting `color.diff` settings, instead only checking `color.ui`. The patch restores the historical behavior where:
- Interactive prompts follow `color.interactive` settings
- Diff output follows `color.diff` settings
- Each has its own independent "reset" color to avoid conflicts

Key technical changes include:
- Splitting the single `use_color` field in `add_i_state` into separate `use_color_interactive` and `use_color_diff` fields
- Adding corresponding `reset_color_interactive` and `reset_color_diff` fields
- Modifying `init_color()` to take the color setting to check as a parameter
- Updating all color initialization and usage sites to use the appropriate setting
- Adding two new tests that verify the independent control of prompt vs diff coloring

The changes affect several files:
- `add-interactive.c` gets the core logic changes
- `add-interactive.h` gets the new struct fields
- `add-patch.c` updates to use the correct color settings
- New test cases in `t/t3701-add-interactive.sh`

This is a well-motivated change that restores historical behavior while making the code more precise about which color settings apply to which parts of the interface. The patch includes thorough test coverage of both the basic functionality and edge cases around color configuration.
