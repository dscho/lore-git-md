Maintainer follow-up on reftable adoption for case collision issues.

Junio Hamano responds to Patrick Steinhardt's proposed error message about case collision handling in the files backend, making several key points:

1. Rejects the notion that users can simply "accept" the current behavior as-is, since it effectively blocks fetch operations entirely when case collisions occur, requiring manual refspec tweaking to make any progress.

2. Strengthens the case for reftable adoption by emphasizing that the files backend's limitations create real workflow problems rather than being a minor inconvenience.

3. Implicitly endorses Patrick's work on libgit2 reftable support by acknowledging it as the remaining ecosystem piece needed for broader adoption, though notes it still needs review.

This email reinforces the thread's emerging consensus that reftable is the proper solution, with Junio taking a stronger stance than Patrick's original message by dismissing the "accept as-is" option as non-viable. The exchange suggests the documentation strategy should present reftable migration as the primary solution without suggesting workarounds for the files backend. Junio's position as maintainer carries significant weight in directing the solution path.
