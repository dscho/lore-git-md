Bugfix for the `git-jump` contrib script handling filenames with spaces in diff output. This is a follow-up to Greg Hurrell's patch that addressed the core issue where Git's diff output appends a tab after filenames containing spaces, causing `git-jump` to incorrectly process these as part of the filename.

D. Ben Knoble confirms the patch works as intended, noting it correctly handles the common case of filenames with spaces (case 1) and the edge case of filenames with spaces followed by tabs (case 3), while dropping support for filenames ending with literal tabs (case 2). The tradeoff is acknowledged as reasonable since case 2 is extremely rare in practice.

The discussion suggests two potential future directions if needed: making tab-stripping conditional on space presence, or parsing `--patch-with-raw` output for more accurate filename handling. The current solution is minimal (a one-line Perl regex change) and effectively solves the main pain point while keeping complexity low.
