Performance optimization enabling Bloom filters for wildcard pathspecs and certain pathspec magic signatures in revision traversal. This is the final version (v3) of Lidong Yan's patch series, now incorporating all feedback from Junio Hamano and Patrick Steinhardt. The key technical changes allow Bloom filter usage with wildcards by using only the non-wildcard portion up to the last directory separator, while carefully handling magic signatures through an allow-mask approach (`allowed_magic` variable) that permits top/glob/attr/depth/literal signatures but excludes incompatible ones like exclude/icase.

The implementation shows measurable performance gains: 18-27% faster in Git repo tests (e.g., `git log -100 -- "t/*"` drops from 23.4ms to 20.4ms) and 47-63% faster in larger repos like LLVM (`git log -100 -- "libc/*"` improves from 26.7ms to 16.0ms). The patch includes comprehensive test coverage in t4216-log-bloom.sh verifying both positive cases (wildcards with non-wildcard components, allowed magic signatures) and negative cases (full wildcards, excluded magic signatures).

Code changes focus on clarity and robustness: renamed variables for better understanding, reorganized pathspec conversion logic, added detailed comments about wildcard handling strategy, and fixed edge cases like zero-length paths. The implementation maintains backward compatibility while expanding Bloom filter applicability. All outstanding technical issues from previous rounds have been addressed, with Junio Hamano's final sign-off confirming the patch's readiness for inclusion.
