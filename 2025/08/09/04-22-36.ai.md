Performance optimization for Bloom filters in revision traversal, now at v4 of the patch series. This version enables Bloom filter usage with wildcard pathspecs and specific pathspec magic signatures (top, glob, attr, --depth, literal) while excluding incompatible ones (exclude, icase). The key technical change is using the non-wildcard portion up to the last directory separator for Bloom matching, with fallback to non-filtered traversal for first-component wildcards.

The implementation in revision.c introduces an `allowed_magic` mask to selectively enable compatible pathspec magic while rejecting others. For wildcard pathspecs, it now extracts the directory portion (up to the last '/') for Bloom filter matching. Junio Hamano contributed a refinement to avoid allocating zero-length paths in `convert_pathspec_to_bloom_keyvec()`. 

Test coverage in t4216-log-bloom.sh verifies both positive cases (where Bloom filters are used with supported wildcard patterns and magic signatures) and negative cases (where they're correctly disabled for unsupported patterns). Performance benchmarks show consistent improvements: 18-27% faster in Git repo tests (e.g., `git log -100 -- "t/*"` 23.4ms->20.4ms) and 47-63% faster in LLVM repo (`git log -100 -- "libc/*"` 26.7ms->16.0ms).
