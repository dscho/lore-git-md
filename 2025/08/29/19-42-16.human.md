This is part 12 of a 15-patch series introducing Rust support to Git's xdiff subsystem. The patch continues the cleanup and preparation work for Rust integration by removing the now-redundant `nrec` field from the `xdfile_t` struct.

The change builds on patch 11's replacement of the C-specific `chastore` memory pool with the new `ivec` type. Since `ivec` already tracks its length via `record.length`, the separate `nrec` field becomes unnecessary. The patch updates all references to use `record.length` instead, with appropriate type casts where needed to maintain compatibility with existing code that expects `long` values.

The changes touch several xdiff components (xdiffi.c, xemit.c, xmerge.c, xpatience.c, xprepare.c) but are mechanical in nature, simply replacing one way of counting records with another. The diff shows careful attention to maintaining exact behavior while removing the redundant field.

This continues the series' pattern of incremental, low-risk preparatory changes before introducing Rust components. The patch appears well-tested and maintains the existing functionality while simplifying the data structures.
