This is a documentation discussion thread follow-up regarding the `git-checkout` manpage revisions. D. Ben Knoble confirms Julia Evans' earlier observation that the documentation incorrectly stated that `git checkout <something>` defaults to interpreting the argument as a tree-ish, when in fact it first tries to interpret it as a commit-ish (branch or other commit reference) before falling back to path interpretation. 

Junio Hamano provides implementation details about the actual behavior: Git first attempts to resolve the argument as a commit-ish (with branch names and other commit references taking different code paths), then as a path, and fails if neither interpretation works. This corrects the longstanding inaccuracy in the documentation that suggested tree-ish was the default interpretation.

The exchange serves as final confirmation that Julia's v2 patch series has properly addressed all technical inaccuracies in the documentation, including this subtle but important distinction in argument parsing behavior. The thread shows consensus that the implementation details are now accurately reflected in the revised documentation.
