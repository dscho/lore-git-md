This is the foundational documentation patch for introducing Rust support to Git, part of a 15-patch series to add Rust to the xdiff subsystem. The patch establishes the project's Rust adoption policy in Documentation/technical/rust-support.adoc, which becomes required reading for platform support (as noted in platform-support.adoc).

The document makes a comprehensive case for Rust adoption, citing security benefits (70% reduction in memory safety vulnerabilities), developer ergonomics, and community support from the Berlin Contributor Summit. It outlines key principles: incremental adoption via static library linking, avoidance of C-compatibility crates (libc/rustix) in favor of idiomatic Rust, and version support tied to Debian stable releases (approximately 3-year support window). The policy explicitly rejects maintaining parallel C implementations and sets conservative dependency management practices (no Cargo.lock, minimal version bounds).

Technical specifics include warnings about platform-specific type pitfalls (c_long inconsistencies), recommendations against bindgen/cbindgen for non-idiomatic output, and compiler support policies excluding nightly/beta Rust. The document anticipates future transitions like dynamic library usage while emphasizing current constraints for cross-platform stability. This establishes the governance framework for all subsequent Rust work in the series.
