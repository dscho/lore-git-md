This is the foundational documentation patch for a 15-part series introducing Rust support to Git's xdiff subsystem. The patch establishes the project's official policy for incrementally adopting Rust, with a focus on improving security and maintainability while maintaining broad platform compatibility.

The new Documentation/technical/rust-support.adoc file presents a detailed rationale for using Rust (memory safety statistics, government security recommendations, developer ergonomics) alongside concrete design decisions. Key points include: requiring Rust as part of platform support, using an incremental static-library-first strategy, avoiding C-compatibility crates that compromise portability, and version support tied to Debian stable releases. The document also specifies non-goals like maintaining C-only versions of Rust code.

The patch updates platform-support.adoc to mandate Rust and adds the new document to the technical docs build. It carries sign-offs from both brian m. carlson and Ezekiel Newren, indicating collaboration on the Rust policy. As the series opener, this provides essential context for the subsequent infrastructure and implementation patches, showing careful consideration of downstream impacts and long-term maintenance. The thoroughness suggests this represents consensus from prior discussions, including Git Merge Contributor Summit feedback mentioned in the commit message.
