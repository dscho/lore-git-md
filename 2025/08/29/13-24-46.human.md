This is a user request to preserve the `git whatchanged` command, which was recently proposed for removal. 

Anthony Clay, a kernel audio driver maintainer, argues that `git whatchanged` serves his workflow needs perfectly by showing exactly the changes he cares about without distractions. He notes that while `git log` can provide similar functionality, he doesn't use it at all in his work. Removing `whatchanged` would force him to create an alias, which could cause problems when working with older Git versions in Docker build chains.

The email comes from a maintainer perspective where workflow efficiency is critical. The request suggests that `whatchanged` fills a niche use case that isn't fully replaced by `git log` for some users, particularly those working in constrained environments with version compatibility concerns. The tone is direct and practical, focused on real-world maintenance scenarios rather than theoretical alternatives.
