This is part 13 of the 15-patch series introducing Rust support to Git's xdiff subsystem, focusing on refactoring the C code to be more FFI-friendly for Rust integration. The patch removes the redundant `recs` field from `xdfile_t` since the `ivec_xrecord` type (introduced in patch 11) now provides direct access to the same records through its `ptr` field. 

The patch updates 8 xdiff files (xdiffi.c, xemit.c, xhistogram.c, xmerge.c, xpatience.c, xprepare.c, xtypes.h, xutils.c) to use `xdf->record.ptr[i]` instead of `xdf->recs[i]`, eliminating the indirection through the `recs` array. The changes are mechanical but widespread, touching core diff algorithms (histogram, patience, merge) and utility functions. The removal of `recs` from `xdfile_t` in xtypes.h completes the transition to using `ivec_xrecord` as the single source of truth for record storage.

This continues the series' pattern of incremental C-side cleanup before Rust integration, removing duplicate state and simplifying the codebase. The change is low-risk since the 1:1 mapping between `recs` and `record.ptr` was already established in patch 11, and all tests continue to pass. The patch helps reduce memory usage slightly by removing the `recs` array allocation while maintaining identical behavior.
