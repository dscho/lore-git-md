This is part 13 of a 15-patch series introducing Rust support to Git's xdiff subsystem. The series has been systematically refactoring the C code to make it more FFI-friendly before introducing Rust components.

This patch removes the redundant `recs` field from `xdfile_t`, which was previously an array of pointers to records that duplicated the data already stored in the `record` vector (an `ivec_xrecord` type introduced earlier in the series). The change touches 8 files with 82 lines removed and 76 added, mostly mechanical updates to access records through `record.ptr[i]` instead of `recs[i]`.

The patch continues the series' pattern of simplifying the C codebase to prepare for Rust integration. Since the `ivec` type now provides direct access to the records, maintaining a parallel pointer array was unnecessary complexity. The change appears straightforward and well-contained, with no behavioral changes - just removing now-redundant indirection.

This is another incremental step in the larger effort to make xdiff's data structures more Rust-friendly while maintaining identical functionality. The series has been carefully structured with each patch building on the last, and this one follows that pattern by cleaning up after the earlier `ivec` conversion.
