CI / build system patch in the Rust xdiff integration series. This is patch 5/15, adding Cargo.lock artifact collection to GitHub Actions workflows.

The patch modifies `.github/workflows/main.yml` to upload the `rust/Cargo.lock` file as a build artifact in several CI jobs: Windows builds (both Make and Meson), Linux test jobs, and static analysis. Each upload uses a distinct artifact name incorporating the job context (e.g. `cargo-lock-windows`, `cargo-lock-windows-meson`). 

This change supports the series' dependency auditing goals by preserving the exact dependency versions used in each CI run, though it's worth noting this contrasts with the policy document's stance against committing Cargo.lock files (they remain build artifacts rather than version-controlled files). The implementation is straightforward, using GitHub's standard artifact upload action with path-based naming that will help correlate lockfiles with specific test environments. As part of the larger Rust infrastructure work, this provides traceability for dependency resolution across platforms while maintaining the series' conservative approach to dependency management.
