This is part 14 of the ongoing series to prepare Git's xdiff subsystem for Rust integration, focusing on type system alignment between C and Rust. The patch completes the type conversion work by updating the remaining ambiguous fields in `xdfile_t` and related structures to use Rust-compatible types (`u8`, `u64`, `usize`, `isize` instead of `char`, `unsigned long`, `long`). 

The changes are mechanical but widespread, touching core diff algorithm implementations in xdiffi.c and type definitions in xdiffi.h/xtypes.h. Key conversions include: changing hash arrays from `unsigned long*` to `u64*`, change markers from `char*` to `u8*`, and index fields from `long` to `usize/isize`. The patch maintains identical behavior while ensuring type compatibility with Rust FFI, where fixed-width types are preferred over C's platform-dependent types.

This continues the series' pattern of preparatory refactoring before introducing Rust components, with each patch making incremental progress toward FFI compatibility. The changes here follow naturally from previous patches that introduced the `ivec` type and removed redundant fields. The patch appears well-contained and focused changes, though reviewers will want to verify the type conversions don't introduce any subtle behavioral differences in the diff algorithms.
