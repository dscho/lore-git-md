This is a technical follow-up in the `git stash --only-unstaged` feature discussion, focusing on implementation details of the proposed trailer-based approach. Phillip Wood responds to Ben Knoble's concerns about documentation examples and stash import/export compatibility.

He reiterates the proposed solution of adding a commit message trailer to mark stashes created with `--keep-index`, which would enable automatic unstaged-change-only behavior during pop operations.

On the import/export question, Wood confirms the trailer approach should work seamlessly since stash export preserves commit messages verbatim. This addresses Knoble's secondary concern about cross-boundary compatibility. The exchange shows consensus forming around the trailer mechanism as a backward-compatible way to improve the stash workflow without breaking existing use cases.
