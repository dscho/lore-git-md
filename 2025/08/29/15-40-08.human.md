This is a performance and safety patch for `git range-diff` that has now reached its third version and appears ready for merging. The patch addresses memory exhaustion issues when comparing very large commit ranges by introducing configurable memory limits for the cost matrix calculation.

The core solution adds a `--max-memory` option that accepts human-readable sizes (like "1G" or "500M") with sensible platform-specific defaults (4GB for 64-bit, 2GB for 32-bit systems). When the limit is exceeded, users get clear error messages showing both requested and allowed memory in human-readable units. The implementation has received Acked-by tags from key reviewers Johannes Schindelin and Elijah Newren.

Maintainer Junio Hamano notes the patch looks good and will queue it as-is, though he observes the option placement in the help output isn't perfectly logical (between diff-merges and remerge-diff options). He suggests this could be improved later if users find it problematic. Hamano also mentions two potential future enhancements - better option grouping and algorithmic improvements to reduce the matrix size - but explicitly states these are out of scope for this already-solid patch.

The patch appears well-vetted through multiple iterations, with all substantive feedback incorporated. This addresses a real-world problem seen in large monorepos while maintaining Git's CLI-first philosophy.
