This is the final version of a feature series improving deprecation messaging for `git whatchanged` and other deprecated commands. The series has received maintainer approval and addresses all previous feedback.

The patches provide clearer guidance when users attempt to run deprecated commands like `whatchanged` and `pack-redundant`. The new output offers:
1. Specific replacement instructions (for `whatchanged`, suggesting `git log --raw --no-merges`)
2. Multiple troubleshooting steps before contacting maintainers
3. Better documentation of behavior differences

Key changes in v2 include:
- Refined email contact wording (now explicitly ties contact to unsuccessful replacement attempts)
- Fixed whitespace and documentation issues
- Added clarification about empty commit behavior differences
- Updated URLs to be more precise

The implementation preserves backward compatibility while making it easier for users to transition away from deprecated commands. The series is now in its approved final form, ready for inclusion.
