This is the first patch in a v2 series implementing structured deprecation messaging for `git whatchanged`. The patch focuses on improving user guidance when they attempt to use deprecated commands, establishing a three-step pattern (notice/alternatives/contact prompt) that was formally endorsed by the maintainer.

The implementation introduces a more helpful error message in `usage.c` that:
1. Clearly states the command is nominated for removal
2. Provides concrete steps for users:
   - Points to BreakingChanges documentation
   - Suggests checking mailing list discussions (with URL containing the command name)
   - Invites email contact if no suitable replacement is found
3. Uses `strbuf_add_percentencode` to generate search URLs while maintaining backward compatibility

Key technical details:
- The message structure follows Eric Sunshine's approved wording
- URL generation remains unchanged from v1
- Removes redundant "please add" phrasing and "Thanks" for conciseness
- Maintains clear distinction from `pack-redundant` deprecation case
- Uses `strbuf` for safe URL encoding of command names

The patch represents the final approved implementation of the core messaging mechanism, with all reviewer feedback incorporated. It's part of broader efforts to improve communication around breaking changes, and establishes a model for future deprecations with its structured three-step approach.
