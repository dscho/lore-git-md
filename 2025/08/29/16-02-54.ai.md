Performance and bugfix patch for `git range-diff` addressing memory exhaustion issues when comparing very large commit ranges (250,000+ commits). This is version 4 of a series that has already been reviewed and approved with minor wording tweaks pending.

The core issue is that `range-diff` allocates an n×n cost matrix which can attempt excessive memory usage (e.g. 260GB for 256,783 commits). The solution introduces configurable memory limits with clear error messaging. The patch adds a `--max-memory` option accepting human-readable sizes (e.g. "1G", "500M") with platform-specific defaults (4GB/2GB). When the limit is exceeded, it shows both requested and allowed memory in human-readable units.

Key technical changes:
- New `max_memory` field in `struct range_diff_options`
- Memory parsing via `parse_max_memory()` accepting human-readable sizes
- Pre-allocation validation in `get_correspondences()`
- Three affected call sites updated (builtin/log.c, builtin/range-diff.c, log-tree.c)
- Error message wording improved from v3 to clarify "limited to" rather than "available"

The patch is ready for merging with all substantive feedback incorporated. Maintainers Johannes Schindelin and Elijah Newren have given their Acked-by, and Junio Hamano has confirmed readiness for inclusion. The only remaining change is a final wording clarification in the error message requested by Elijah Newren. The implementation follows Git's CLI-first approach and addresses a real-world issue encountered in Shopify's monorepo.
