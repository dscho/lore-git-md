This is a feature series introducing Rust support to Git, specifically targeting the xdiff subsystem. The 15-patch series builds on a previous RFC version, now removing the RFC label after addressing feedback. The series is a collaborative effort with contributions from Ezekiel Newren (13 patches), Johannes Schindelin (1 patch), and brian m. carlson (1 patch).

The series begins by establishing a Rust usage policy document (patch 1) and introducing Rust infrastructure (patch 2). It then makes CI/build system changes to support Rust (patches 3-5). The core technical work introduces an interop vector type (ivec) that works across C and Rust (patch 6), cleans up xdiff internals to be more Rust-friendly (patches 7-14), and finally demonstrates the approach by translating one xdiff function to Rust (patch 15).

Key technical components include:
- The `ivec` type (interop/ivec.{c,h,rs}) provides a vector implementation that can be used from both C and Rust, with proper memory management and type safety
- Xdiff cleanup removes redundant fields from xrecord_t and xdfile_t, replaces the chastore memory pool with ivec, and makes structures more Rust-compatible
- The translated xdl_trim_ends() function shows how C can call into Rust implementations
- Build system changes support Rust compilation and linking, including Windows/Meson compatibility

The series appears well-structured and thorough, with good test coverage for the ivec implementation. The changes to xdiff internals are preparatory work to enable further Rust integration while maintaining compatibility with existing C code. The approach of introducing interop utilities first, then incrementally translating functions while cleaning up the C side to be more Rust-friendly seems sound.
