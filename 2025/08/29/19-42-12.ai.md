Refactoring patch in the xdiff Rust integration series, removing unused fields from xrecord_t and xdfile_t structs. This is patch 8/15 in the series that prepares xdiff for Rust integration.

The patch eliminates three unused fields that were initialized but never referenced: xrecord_t.next (a linked list pointer), xdfile_t.hbits (hash table size), and xdfile_t.rhash (hash table array). The changes are straightforward deletions with no behavior impact - the fields were remnants of an earlier implementation that used chained hashing, but the current code only uses the .ha field for direct comparison. The removal simplifies the data structures before Rust integration work begins.

Key technical details: the patch modifies xdiff/xprepare.c to remove all references to these fields, including their initialization, cleanup, and passing as parameters (notably simplifying xdl_classify_record()'s signature). The corresponding struct definitions in xdiff/xtypes.h are updated to remove the fields. The changes are purely subtractive with no new code added, maintaining the existing functionality while reducing complexity. This cleanup follows the series' pattern of preparatory refactoring before introducing Rust components.
