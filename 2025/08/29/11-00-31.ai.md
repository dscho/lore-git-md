Performance and safety patch for `git range-diff` addressing memory exhaustion issues when comparing very large commit ranges (250,000+ commits). This is version 3 of a series that has been under active review, now reduced to a single commit after removing unrelated changes from previous versions.

The patch adds a configurable memory limit for the n×n cost matrix calculation that can otherwise attempt excessive memory (e.g. 260GB for 256,784 commits). Key technical changes include:
- New `max_memory` field in `struct range_diff_options` with platform-specific defaults (4GB/2GB)
- Memory parsing via `parse_max_memory()` accepting human-readable sizes
- Pre-allocation validation in `get_correspondences()` with clear error messages
- CLI interface via new `--max-memory` option (e.g. `--max-memory=1G`)

The implementation follows Junio Hamano's preferred CLI-first approach, with config file support left for potential future work. Error messages now show both requested and allowed memory in human-readable units. The patch retains Acked-by from Johannes Schindelin and addresses all feedback from previous rounds, including fixing author name consistency and removing an unrelated option reordering commit.

The solution specifically targets Shopify's monorepo use case while maintaining reasonable defaults for typical workflows. The technical approach is solid, having converged through multiple review iterations, with the remaining discussion points around interface details now resolved.
