Performance and safety patch for `git range-diff` addressing memory exhaustion issues when comparing very large commit ranges. This is version 3 of a series that has been under active review, with previous versions receiving Acked-by tags from Johannes Schindelin and Elijah Newren.

The patch adds a configurable memory limit to prevent `range-diff` from attempting to allocate an impractically large n×n cost matrix when comparing huge commit ranges (e.g. 250,000+ commits). The new `--max-memory` option accepts human-readable sizes (like "1G" or "500M") with sensible defaults (4GB for 64-bit, 2GB for 32-bit systems). When exceeded, it provides clear error messages showing both requested and allowed memory.

The implementation checks memory requirements before allocation in `get_correspondences()`, preventing both excessive memory usage and integer overflow issues. The patch includes thorough documentation of the problem (including real-world crash reports from Shopify's monorepo) and rationale for this solution over alternatives like pre-counting commits or streaming approaches.
