Refactoring patch in the xdiff Rust integration series, replacing chastore with ivec for FFI compatibility.

This patch continues the preparatory work for Rust integration in xdiff by replacing the C-specific chastore memory pool with the previously introduced ivec (interoperable vector) type. The change affects xdfile_t's internal storage of xrecord_t entries, moving from a dual-structure approach (chastore + recs array) to a single ivec-based storage. The patch demonstrates the series' strategy of establishing common data structures before Rust implementation.

Key technical changes:
- Adds ivec.h include to xtypes.h
- Replaces xdfile_t.rcha (chastore_t) with xdfile_t.record (ivec_xrecord)
- Modifies xdl_prepare_ctx() to use ivec_push() instead of cha_alloc()
- Maintains backward compatibility by still populating the recs array (to be removed in subsequent patches)
- Updates xdl_free_ctx() to use ivec_free()

The change simplifies memory management while maintaining the same functionality, removing 36 lines of code. As noted in the commit message, this also makes the code more FFI-friendly for the upcoming Rust integration. The patch follows the series' pattern of mechanical refactoring before introducing Rust components, with no test or build system impact.
