D. Ben Knoble confirms Julia Evans' observation that the current description of `git checkout <something>` defaulting to a tree-ish interpretation is incorrect, as Git actually first tries to interpret the argument as a commit-ish (branch or commit) before falling back to path interpretation. Junio Hamano provides implementation details about the different code paths taken for branch names versus other commit-ish values.

The exchange reveals an inaccuracy in the documentation that has existed since 2016, which Julia is correcting in her patch series.
