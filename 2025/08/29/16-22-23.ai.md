This is a documentation patch in Julia Evans' v2 series restructuring `git-checkout.adoc`, specifically addressing terminology around branch modification operations. The patch replaces vague "reset" language with more precise descriptions of what actually happens to branch pointers.

Junio Hamano provides feedback on the wording changes, agreeing with the direction but suggesting potential further refinements. He questions the premise that users don't understand "reset" (given `git reset` is a common command), suggesting the real issue was the original phrasing's lack of specificity about what the branch is reset to. He proposes alternative wording that more explicitly describes the branch pointer modification behavior.

The patch makes two key changes:
1. For `-B` behavior, replaces "reset" with "forced to point at the commit"
2. Simplifies the transactional behavior explanation to "the branch will not be created or modified unless git checkout is successful"

Junio suggests the transactional explanation could be rewritten more clearly by removing the "that is" clarification and making the behavior description more direct. He provides a sample rewrite that explicitly states the branch pointer modification only occurs if checkout succeeds.

This continues the series' pattern of making the documentation more precise while maintaining technical accuracy, with Junio now focusing on fine-tuning the phrasing of branch modification descriptions after earlier rounds addressed larger structural issues.
