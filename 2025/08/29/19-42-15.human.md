This is part 11 of a 15-patch series introducing Rust support to Git's xdiff subsystem, focusing on refactoring the data structures to be more Rust-friendly. The patch replaces the C-specific `chastore` memory pool in `xdfile_t` with an `ivec` (interoperable vector) type, which was introduced earlier in the series specifically for C/Rust FFI.

The change simplifies the code by removing redundant fields (`nrec` and `recs` which will be removed in subsequent patches) and eliminating the confusing dual data structure setup where `xrecord_t` was previously managed both through a memory pool and a separate array. The patch updates memory management in `xdl_prepare_ctx()` to use vector operations instead of manual allocation, while maintaining the same functionality.

This is a mechanical refactoring that continues the series' pattern of preparing xdiff for Rust integration by aligning data structures between C and Rust. The change touches only xdiff internals (xprepare.c and xtypes.h) with no user-visible impact. The commit message notes this is part of cleaning up historical cruft while making the code more suitable for Rust interoperability.
