Performance and safety patch for `git range-diff` addressing memory exhaustion issues. This is version 4 of a patch that has already received multiple acks and is nearly ready for merging, with only minor wording tweaks remaining.

The core issue is that `range-diff` can attempt to allocate massive amounts of memory (e.g. 260GB for comparing 250,000+ commits) when computing its cost matrix, leading to crashes or system hangs. The solution adds a configurable memory limit with sensible defaults (4GB on 64-bit systems, 2GB on 32-bit) via a new `--max-memory` option that accepts human-readable sizes like "1G" or "500M".

The patch includes clear error messages showing both the requested and allowed memory when limits are exceeded. The implementation has been through several review iterations and maintains acks from Johannes Schindelin and Elijah Newren. The only remaining discussion point is a minor wording clarification in the error message.

This addresses a real-world problem encountered in Shopify's monorepo and follows Git's preferred CLI-first approach. The patch is well-tested and ready for inclusion, demonstrating good attention to both technical correctness and user experience.
