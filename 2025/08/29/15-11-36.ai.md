This is a response in the ongoing thread about `git whatchanged` output format breakage affecting third-party tools. Junio Hamano replies to Ron Yorston's complaint about the lack of deprecation notice before the format change.

The response clarifies that `git whatchanged` has actually been in a deprecated state since August 2013 (commit 52f425e1a9a), though acknowledges the deprecation notice may not have been explicit enough about potential output changes. This reinforces Kristoffer Haugsbakk's earlier position that this isn't a regression but rather a case of a tool relying on behavior that was never guaranteed stable.

The email doesn't introduce new technical details but provides authoritative confirmation of the command's long-standing discouraged status from Git's maintainer. This likely closes the discussion about whether the breakage should be treated as a regression, shifting focus firmly toward tool-side adaptation. The response maintains Git's position while acknowledging the frustration caused by insufficient communication about the implications of deprecation.
