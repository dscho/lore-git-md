This is part 2 of a 4-part series improving guidance for users of deprecated Git commands, specifically focusing on `git whatchanged`. The series has already received maintainer approval and is in its final form.

The patch enhances the deprecation messaging for `git whatchanged` by explicitly telling users the equivalent `git log` command they should use instead (`git log --raw --no-merges`). This addresses real-world confusion where users weren't finding this information in the man pages. The patch adds this hint both to the runtime error message and the documentation.

A technical note from Jeff King is incorporated explaining that the output will only differ for empty commits (those with no changes). The implementation uses a new optional `hint` parameter in the `you_still_use_that()` helper function to show the alternative command right after the deprecation notice.

This is a well-polished patch that completes the series' goal of providing clear migration paths for deprecated commands. It follows the established three-step deprecation pattern (notice/alternatives/contact prompt) and maintains consistency with the series' other patches. The changes are minimal but impactful, touching documentation and the deprecation helper implementation while preserving backward compatibility.
