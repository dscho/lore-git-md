The thread concerns a breakage in `git whatchanged`'s output format that affected the third-party `git-restore-mtime` tool from the git-tools collection. Ron Yorston reported the issue, frustrated by the lack of deprecation notice before the format change. Kristoffer Haugsbakk and Junio Hamano both clarified that `git whatchanged` has actually been in a deprecated state since 2013 (commit 52f425e1a9a), though they acknowledged the deprecation notice may not have been explicit enough about potential output instability.

Junio's response as maintainer confirms this isn't a regression but rather a case of a tool relying on behavior that was never guaranteed stable. The git-tools maintainers have already opened an issue and pull request to address the breakage on their side. While the discussion highlights the frustration caused by insufficient communication about deprecation implications, the consensus is now firmly on tool-side adaptation rather than expecting Git to maintain compatibility for this long-discouraged command.
