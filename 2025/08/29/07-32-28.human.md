Follow-up in thread about `git whatchanged` output format breakage affecting `git-restore-mtime`. Kristoffer Haugsbakk responds to Ron Yorston's report by pointing out that while the `git whatchanged` command wasn't formally deprecated, its use has been discouraged since 2013 (commit 52f425e1a9a). 

This adds important context to the discussion - the breakage may be more defensible given the longstanding discouragement of `git whatchanged` usage. However, the email doesn't address whether the specific output format change was intentional or accidental, nor does it comment on whether a compatibility fix might be warranted. 

The response is brief and factual, simply pointing to historical documentation rather than engaging with the core concerns about the sudden breakage. It leaves open the key questions about whether this should be treated as a regression versus an expected consequence of using a discouraged command. 

Kristoffer also helpfully links to the GitHub issue and pull request where the git-tools project is already working on a fix, suggesting the immediate impact may be mitigated regardless of Git's stance on the change.
