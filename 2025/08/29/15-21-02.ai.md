This is the v2 cover letter for a series improving deprecation messaging, specifically for `git whatchanged`. The series has received maintainer approval and incorporates feedback from Eric Sunshine and Jeff King.

The key changes in v2 include:
- Refined email bullet point wording to clarify users should only contact maintainers if they can't find a replacement
- Fixed whitespace issues and footnote formatting
- Expanded documentation about empty commit behavior differences between `whatchanged` and `log`
- Added explicit `--raw --no-merges` mapping for `whatchanged` users

Technical details:
- Uses `you_still_use_that()` helper in `usage.c` with three-part guidance
- Documents edge cases in `git-whatchanged.adoc` and `BreakingChanges.adoc`
- Maintains clear distinction from `pack-redundant` deprecation case
- Preserves backward compatibility while improving migration path

The series is now in final form with all design elements confirmed, awaiting Junio Hamano's merge. It represents a model for future deprecation messaging with its structured approach (deprecation notice, alternatives, contact prompt) and careful documentation of behavior differences.
