This is a response in the ongoing discussion about `git whatchanged` output format breakage affecting third-party tools.

Junio Hamano responds to Ron Yorston's complaint about the recent breakage of `git-restore-mtime` due to changes in `git whatchanged`'s output format. He notes that while the deprecation notice might not have been explicit enough, the command has been officially discouraged since 2013 (commit 52f425e1a9a).

The response maintains the position that this isn't a regression needing Git-side fixes, as `git whatchanged` has long been considered a legacy command. This reinforces Kristoffer Haugsbakk's earlier stance that the solution lies in tool adaptation rather than Git compatibility changes.

The exchange highlights the tension between maintaining backward compatibility for tools that parse Git's porcelain output versus the project's right to evolve discouraged commands. While the specific format changes remain unspecified, the thread suggests the Git maintainers consider this a settled matter of tooling needing to adapt to long-standing deprecation notices.
