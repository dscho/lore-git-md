This is a discussion response in the Rust support thread, specifically addressing the Rust policy document from patch 1. Brian m. carlson agrees with most of the proposed Rust adoption guidelines but raises two key concerns about implementation details.

The response focuses on type safety and FFI generation approaches. They strongly endorse using fixed-size types (i32/i64) over platform-dependent C types like `long`, noting this prevents portability issues Git has historically faced. However, they express reservations about completely avoiding bindgen/cbindgen tools, arguing that manual synchronization of C/Rust structures risks subtle ABI mismatches, particularly on big-endian systems that most developers don't test on. They suggest a compromise: using cbindgen when structures must be shared between languages, while still preferring idiomatic Rust where possible.

This feedback comes from someone with demonstrated platform compatibility expertise (noting endianness issues) and suggests practical adjustments to the policy's FFI approach. The tone is constructive but firm on the structure synchronization concern, indicating this may become a discussion point as the series progresses. The response doesn't challenge the overall Rust adoption strategy but focuses on implementation safety.
