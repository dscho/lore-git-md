This is part 14 of a 15-patch series introducing Rust support to Git's xdiff subsystem, focusing on making the xdfile_t data structure more Rust-friendly. The patch continues the series' incremental approach by converting remaining ambiguous field types in xdfile_t from C types to Rust types for better interoperability.

The changes are mechanical but widespread, updating type declarations in xdiffi.c, xdiffi.h, and xtypes.h. Key conversions include changing `char*` to `u8*` for rchg fields, `long*` to `usize*` for rindex fields, and `unsigned long*` to `u64*` for hash arrays (ha fields). These changes align with Rust's stricter type system while maintaining identical runtime behavior.

The patch builds on previous work that introduced the ivec_xrecord type and removed redundant fields, now completing the transition to Rust-compatible types throughout the xdiff data structures. This is part of the series' broader goal of preparing xdiff for Rust integration while maintaining C callability, with the final patch expected to demonstrate the approach by translating xdl_trim_ends() to Rust.

The changes are focused and well-contained, touching only type declarations without modifying algorithm logic. The series has shown careful attention to maintaining compatibility and test coverage throughout these preparatory refactorings.
