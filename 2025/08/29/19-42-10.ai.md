This is patch 6/15 in the Rust integration series, introducing an interoperable vector type (ivec) for C/Rust FFI. The patch creates a new vector abstraction designed specifically for cross-language use, with parallel implementations in C (interop/ivec.{c,h}) and Rust (rust/interop/src/ivec.rs).

The ivec type addresses several FFI pain points: it provides a consistent memory layout and allocation strategy between languages, avoids allocator mismatches, and simplifies parameter passing by bundling the pointer/length/capacity triplet. The implementation includes core vector operations (push, reserve, resize etc.) with identical semantics on both sides. The Rust version matches Rust's Vec API where possible while maintaining C compatibility through raw pointer access and manual memory management.

Key technical details include:
- The C struct rawivec and Rust IVec<T> share identical memory layout (ptr, length, capacity, element_size)
- Both implementations use malloc/free for allocation to ensure compatible memory management
- The Rust version includes safety checks via test_invariants() in debug builds
- Makefile/meson.build updates add the new interop library as a dependency
- Comprehensive test coverage in Rust for drop semantics, bounds checking, and resize operations

This foundational type will be used in later patches to replace xdiff's internal vector handling as part of the Rust integration proof-of-concept. The careful attention to cross-language consistency and memory safety reflects the series' overall approach to gradual, interoperable Rust adoption.
