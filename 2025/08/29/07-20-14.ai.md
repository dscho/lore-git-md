Documentation patch discussion about glossary linking strategies in Git's man pages. This is a follow-up to the merged patch 1/4 in Julia Evans' series improving `git-push` documentation, specifically addressing how to handle terminology links to the glossary.

Kristoffer Haugsbakk builds on the earlier discussion between Junio Hamano and D. Ben Knoble about linking "ref" terminology to the glossary. While the previous exchange settled on direct linking and explicit terminology notes, Haugsbakk proposes a new approach: using footnotes for glossary references in essential commands' documentation. The rationale is to avoid cluttering the main text with parenthetical explanations while still making glossary terms discoverable, particularly for common commands where jargon density is high.

The suggestion introduces a new technical consideration for the documentation style - whether to implement footnote-based glossary references system-wide. This would affect both the ongoing `git-push` documentation work and potentially other core commands. The proposal doesn't conflict with Julia Evans' parallel work on HTML tooltips (git-scm.com PR #2040) or the `linkgitglossary:` macro, but presents an alternative presentation layer consideration for terminal output.

Key technical points: glossary footnotes as alternative to inline parentheticals or direct linking, presentation layer considerations for man pages versus HTML output. The discussion remains compatible with the thread's established direction of glossary integration but adds a new formatting option to evaluate.
