Performance optimization follow-up for Bloom filters with wildcard pathspecs. This is a brief response from Lidong Yan to Junio Hamano's positive reaction to the performance numbers shown in the previous patch. Yan notes that initial testing was done on Git versions 2.39 and 2.51 using `git commit-graph write --split`, which produced a large `filter_not_present` value in the performance traces. However, after rebuilding the commit-graph, retesting on HEAD and HEAD~1 still showed improved performance on the current version. Yan commits to updating the experimental results in the next version of the patch series.

Key technical details carried forward: the optimization enables Bloom filter usage with wildcard pathspecs by using a non-wildcard portion up to the last directory separator for Bloom matching, with fallback behavior for first-component wildcards. The implementation uses an allow-mask approach for pathspec magic handling (variable renamed to `allowed_magic`) and includes comprehensive test coverage in t4216-log-bloom.sh. Performance improvements remain significant (18-27% faster in Git repo, 47-63% in LLVM repo) despite the testing artifact mentioned.
