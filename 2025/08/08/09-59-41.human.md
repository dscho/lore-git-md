This is a test improvement series addressing documentation verification in the Git test suite. Toon Claes follows up on earlier discussion about the `t0450-txt-doc-vs-help.sh` test, which checks consistency between command-line help and documentation files.

The first patch fixes an out-of-tree build issue where the test was looking for `.adoc` files in the wrong location (the build directory rather than source directory), particularly affecting Meson builds. This was a straightforward fix already agreed upon in the thread.

The second patch introduces a more significant change by adding an allowlist for builtins with missing documentation, replacing the test's silent-skip behavior. This addresses the core issue identified in the thread - that the current prereq mechanism could mask real documentation problems. The allowlist approach makes missing documentation explicit, helping catch omissions for new subcommands.

The changes are small (8 lines total) but meaningful, with the second patch being new in v2 based on thread discussion. The series shows good responsiveness to the earlier analysis by Patrick Steinhardt about the test's design limitations. The patches appear well-constructed with a logical progression from fixing the immediate issue to improving test robustness.
