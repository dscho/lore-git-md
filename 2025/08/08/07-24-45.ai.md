This is the second patch in a three-part series fixing a bug in remote.c's push error handling, following a test cleanup patch and preceding a refactoring patch. The series has already been reviewed and approved, with this patch addressing the core issue.

The patch replaces a BUG() assertion in `show_push_unqualified_ref_name_error()` with user-friendly advice when pushing a non-existent full object ID to an unqualified ref destination. The original code would trigger a BUG() when `odb_read_object_info()` reported no such object (returning -1), which was incorrect since this is a user error case rather than a programming error. The new behavior provides clear advice about the non-existent object ID instead of crashing.

Key technical details:
- Changes the error path for full 40 hex OIDs that don't exist in the object database
- Preserves all other existing behavior (including BUG() for unexpected object types)
- Adds a new test case using `test_oid 001` to verify the fixed behavior
- Affects only the error reporting path in remote.c's push validation
- Maintains identical behavior for partial OIDs and refnames (which still die with different error messages)

The patch has already been reviewed by Junio C Hamano and Patrick Steinhardt, with all feedback addressed. The series is approved for integration, with one acknowledged follow-up needed (removing a temporary `type` variable in the subsequent refactoring patch). This change improves user experience while maintaining all safety checks.
