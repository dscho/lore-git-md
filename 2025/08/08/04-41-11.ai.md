Refactoring patch in a completed series about push error handling. This is the second of three patches that started with fixing a BUG() assertion when pushing invalid object IDs to unqualified refs.

The patch converts an if-else chain (previously called a "ladder" in discussion) in show_push_unqualified_ref_name_error() to a switch statement, improving readability while maintaining identical behavior. The change was suggested by Patrick Steinhardt as a follow-up to the initial bugfix. The switch statement directly uses the odb_read_object_info() call as its expression, eliminating the now-redundant `type` variable that was previously declared separately.

The refactoring handles the same four object types (commit, tag, tree, blob) with the same advice messages as before, plus the same BUG() for unexpected types. The change is purely structural - no behavior modifications or new functionality. The patch has already been reviewed and approved by both Patrick Steinhardt and Junio C Hamano, with Junio noting the improved commit message and Patrick suggesting the final variable removal optimization seen here.

This completes the stylistic improvement portion of the series, with the third patch being a separate test cleanup. The thread shows consensus that this refactoring is a clear improvement over the original if-else structure while preserving all existing error handling paths.
