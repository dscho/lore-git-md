Bugfix for `git-jump` (contrib script) handling filenames with spaces in diff output. Core issue stems from Git's diff.c behavior (since 2006) appending tabs after filenames containing spaces (e.g. "foo bar.txt\t"), causing `git-jump` to incorrectly process these as part of the filename in Vim's quickfix mode. Current solution implements a one-line Perl regex modification (`(.*?)\t?$`) to optionally strip trailing tabs, solving the common case while remaining simple.

Key technical developments:
1. D. Ben Knoble validated the fix works for filenames with spaces while confirming it drops support for the edge case of filenames ending with literal tabs
2. Phillip Wood's analysis reveals Git quotes filenames containing control characters (including tabs), making these edge cases distinguishable from space-containing filenames with appended tabs
3. This quoting behavior means the simple regex solution is more robust than initially thought, as true tab-terminated filenames would be quoted in diff output

Two solution approaches under consideration:
- Minimal regex fix (current proposal): handles space-containing filenames via trailing tab stripping, with edge cases protected by Git's quoting
- Comprehensive "diff --git" parsing (Phillip Wood): would handle all cases including quoted filenames but requires more complex logic

Junio Hamano, while not a git-jump user himself, concurs with the tradeoff favoring the simpler solution, noting space-containing filenames are the practical concern while quoted tab-terminated ones are extremely rare. The discussion maintains focus on contrib/git-jump's practical needs versus theoretical edge cases, with clear examples of problematic filename patterns preserved in the technical record. The interaction between `diff.c`'s tab-appending behavior, Git's filename quoting, and Vim's quickfix parsing remains key context for future reference.
