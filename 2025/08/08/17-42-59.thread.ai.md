Bugfix for `git-jump` (contrib script) handling filenames with spaces in diff output. Core issue stems from Git's diff.c behavior (since 2006) appending tabs after filenames containing spaces (e.g. "foo bar.txt\t"), causing `git-jump` to incorrectly process these as part of the filename in Vim's quickfix mode. Current solution implements a one-line Perl regex modification to optionally strip trailing tabs, solving the common case while remaining simple. D. Ben Knoble validated the fix works for filenames with spaces while confirming it drops support for the edge case of filenames ending with literal tabs. Two alternative approaches are noted for potential future consideration if the edge case becomes problematic: (1) making tab-stripping conditional on space presence, or (2) parsing `--patch-with-raw` output instead. The thread maintains that the current minimal solution is appropriate for now, with the tab-terminated filename case left as an open question. The change remains focused on contrib/git-jump with clear examples of problematic cases and solution rationale in the commit message.
