Bugfix for `git-jump` handling of filenames with spaces in diff output. The patch addresses an issue where `git-jump` would incorrectly process filenames containing spaces due to Git's diff output appending a trailing tab to such filenames. This caused Vim quickfix mode to fail when trying to open these files.

The core problem stems from Git's diff.c adding a tab after filenames containing spaces (like "foo bar.txt\t"), which `git-jump` would then treat as part of the filename. The patch modifies the Perl regex in `git-jump` to optionally strip any trailing tab, solving the common case while remaining simple. The author acknowledges this doesn't perfectly handle the edge case of filenames ending with literal tabs, but argues this is a worthwhile tradeoff.

The change is minimal (a one-line regex modification) and focused on the contrib/git-jump script. The commit message provides clear examples of the problematic cases and rationale for the chosen solution. This appears to be a well-motivated fix for a real usability issue, though it might be worth considering whether the tab-stripping should be made conditional on space presence if edge cases become problematic.
