Performance optimization for Bloom filters in revision traversal with wildcard pathspecs. This is Junio Hamano's review of Lidong Yan's v2 patch, focusing on edge cases in the wildcard handling logic and suggesting a code simplification.

The review examines the path component extraction logic for wildcard pathspecs, particularly cases like "builtin*" that could match both directories ("builtin/") and top-level files ("builtin.h"). Junio confirms the current behavior (falling back to non-filtered traversal when the wildcard covers the entire path) is correct but suggests optimizing the zero-length path case to avoid unnecessary allocations.

Key technical points addressed:
- Clarifies that pathspecs cannot begin with '/' (contrary to example comment)
- Verifies correct handling of mixed wildcard/non-wildcard pathspecs ("A/* file4")
- Confirms test coverage appropriately includes negative cases for incompatible magic signatures (icase, exclude)

Junio proposes a revised implementation that:
- Initializes `res` to -1 (pessimistic) rather than 0
- Moves the zero-length check before allocation
- Eliminates redundant `strlen()` call
- Updates code comments to remove misleading leading slash example

The suggested changes maintain all existing functionality while making the control flow more straightforward. Junio also notes the comprehensive test suite properly covers both positive and negative cases for various magic signatures (top, glob, attr) and wildcard positions.

This appears to be final polish on an otherwise ready patch series, addressing edge case handling in the wildcard path processing logic while preserving all performance gains demonstrated in earlier benchmarks.
