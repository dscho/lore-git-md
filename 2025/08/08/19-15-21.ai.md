This is the first patch in a documentation series (1/5) that restructures the `git-rebase` man page for better accessibility. The patch moves a practical example to the start of the DESCRIPTION section, mirroring the approach used in `git-merge` documentation. It shows a common rebase scenario with ASCII art illustrating the before/after state when rebasing a `topic` branch onto `master`.

The patch introduces two equivalent syntax forms for the same operation: `git rebase master` (when on topic branch) and `git rebase master topic` (from any branch). It explains the latter is just a shortcut for switching branches first. The example replaces a similar one that appeared later in the original document, while maintaining all technical accuracy.

This initial patch sets the tone for the series by front-loading practical usage, which was well-received by maintainers (note it's marked as merged with Junio's feedback in the thread context). The changes are purely organizational - 23 lines added and 26 removed - with no behavior changes to Git itself. The author demonstrates good documentation practices by keeping the explanation clear and linking concepts to existing user knowledge (the parallel with `git-merge` docs).
