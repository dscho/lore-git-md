This thread documents the evolution of Julia Evans' improvements to the `git-rebase` man page, which has now merged. The initial series restructured the documentation for better readability, consolidating explanations and adding helpful examples. A post-merge discussion emerged about whether to use `git checkout` or the newer `git switch` in documentation examples, particularly when dealing with commit-ish arguments that may not be branch names.

Junio Hamano, Karthik Nayak, Phillip Wood, and D. Ben Knoble contributed to a technical discussion establishing that `git checkout` remains the correct choice in these examples because it handles both branch and detached HEAD cases naturally, while `git switch` requires explicit `--detach` for non-branch arguments. Junio has reinforced this position in his latest response, emphasizing the importance of consistency within existing documentation and noting that explaining the subtle differences between commands would distract from the rebase documentation's primary purpose.

While acknowledging that a future documentation sweep might systematically replace some `checkout` uses with `switch`/`restore` where appropriate, Junio has made clear this larger effort should remain separate from the current rebase improvements. The discussion now stands as a well-documented case study in how implementation details should guide command choices in documentation examples, providing valuable precedent for future documentation work.
