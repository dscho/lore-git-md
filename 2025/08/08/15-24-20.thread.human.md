This thread documents the evolution of Julia Evans' improvements to the `git-rebase` man page, which has now entered a post-merge refinement phase. The original series restructured the documentation to be more approachable, consolidating explanations and adding visual examples while removing redundant content. A key discussion point emerged around whether to use `git checkout` or `git switch` in examples, with Junio Hamano and others establishing that `checkout` is technically preferable choice for rebase documentation due to its more natural handling of detached HEAD operations.

Phillip Wood's latest contribution adds nuance to the simplified internals description by noting the performance benefits of the `--reapply-cherry-picks` option in partial clones. He raises whether similar niche options might be omitted for consistency, while reinforcing the established principle that documentation should maintain command consistency within sections based on technical requirements rather than surface preferences. The discussion has now fully captured both the implementation rationale behind command choices and the careful balance between accessibility and technical completeness in documentation. All participants - including Julia Evans, Junio Hamano, Karthik Nayak, and Phillip Wood - have aligned on these decisions, making this thread a valuable reference for future documentation work.
