This thread documents the collaborative refinement of Git's rebase documentation, led by Julia Evans with key input from Phillip Wood and Junio Hamano. The original series restructured the man page to be more approachable, adding clear examples and consolidating explanations while accurately representing rebase's internals as a five-step process. After merging, discussion continued to fine-tune technical details, particularly around how to document the commit selection pipeline and its performance characteristics.

Phillip Wood provided important implementation context about how rebase detects cherry-picks using patch-ids, especially relevant for large repositories. Junio suggested simplifying the documentation by combining two steps (finding commits and detecting cherry-picks) into one, maintaining the conceptual model while removing potentially confusing implementation details. Julia has now implemented this change, agreeing to move the performance specifics (like those around `--reapply-cherry-picks`) to the relevant option descriptions where they'll be more useful to readers.

The thread shows the project's documentation philosophy in action: complex internals are explained clearly without oversimplifying, with implementation details placed where they're most relevant. While the main documentation questions are now resolved, the discussion may inform future work on command modernization planned for Git 3.0.
