This is the first patch in a documentation series aimed at making the `git-rebase` man page more beginner-friendly. The patch moves a rebase example to the very start of the DESCRIPTION section, mirroring the structure of the `git-merge` documentation. This helps newcomers immediately understand the core concept of rebasing before diving into technical details.

The change is purely organizational - it takes an existing example that was buried deeper in the document and promotes it to be the first thing readers see. The example shows a simple branch topology before and after rebasing, clearly illustrating how commits are "replayed" on top of another branch. The author notes this aligns with the `git-merge` documentation's approach, making it easier to compare these two fundamental operations.

As the first patch from a new contributor, it demonstrates good attention to documentation structure while preserving all technical content. The change is focused and well-explained in the commit message. This appears to be a solid start to the series' goal of improving accessibility without sacrificing completeness.
