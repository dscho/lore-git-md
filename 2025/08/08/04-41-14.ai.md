This is the final patch in a three-part series addressing error handling in `remote.c` when pushing to unqualified refs. The patch converts a BUG() assertion into user-friendly advice when pushing a non-existent object ID to an unqualified ref destination.

The change replaces a hard BUG() crash with an `advise()` message when `odb_read_object_info()` reports a non-existent object (type -1). The new behavior provides clearer feedback when users push invalid full OIDs, matching the existing handling of partial OIDs and non-ref names. A new test case verifies this scenario by attempting to push test_oid 001 (a known non-existent OID) to an unqualified branch.

Key technical details:
- Modifies `show_push_unqualified_ref_name_error()` in remote.c
- Maintains identical handling for valid object types (commit/tag/tree/blob)
- Adds test case in t5516-fetch-push.sh using test_oid 001
- Follows through on earlier discussion about proper error messaging
- Completes the series' transition from BUG() to advise() for this error path

The patch has already received acks from both Junio C Hamano and Patrick Steinhardt, with all prior feedback incorporated. This concludes the series which has now been rebased on latest and marked ready for inclusion in 'next'.
