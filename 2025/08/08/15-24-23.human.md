This is the third patch in a documentation series improving the `git-rebase` man page organization. The series aims to make rebase concepts more accessible to beginners while preserving all technical content.

Patch 3/5 focuses on clarifying the argument syntax for `git rebase`. The changes simplify the explanation of how `<upstream>` and `<branch>` arguments work:
- Replaces a multi-sentence explanation of `<branch>` behavior with a concise one-liner showing it's equivalent to running `git switch` first
- Rewords the `<upstream>` default behavior to be more direct ("If you don't specify..." rather than "If <upstream> is not specified...")
- Maintains all the same technical information about fallback to configured upstream and `--fork-point` behavior

The patch continues the series' pattern of making the documentation more approachable without altering any functionality. The changes are small (3 lines added, 5 removed) but meaningful for readability. As with previous patches, the author demonstrates good practices - atomic changes, clear commit message, and proper sign-off.

This follows logically after patch 2's merge conflict resolution consolidation, now addressing argument syntax which naturally comes next when learning rebase works. The series remains focused on its goal of progressive documentation improvements for beginners.
