Performance optimization for revision traversal with wildcard pathspecs. This is the second version of Lidong Yan's patch to enable Bloom filter usage with pathspecs containing wildcards and certain magic signatures, building on previous discussion that refined the technical approach.

The key change switches from a "forbid-mask" to an "allow-mask" approach for pathspec magic handling, permitting Bloom filters for specific useful magic signatures (top, glob, attr, depth, literal) while excluding others (icase, exclude). For wildcard pathspecs, it now uses the non-wildcard portion up to the last directory separator for Bloom matching, falling back to full traversal for pathspecs that are entirely wildcards.

Benchmarks show significant speedups: 18-27% faster in Git's test directory and 47-63% faster in LLVM's libc directory. The implementation includes thorough test coverage in t4216-log-bloom.sh, verifying both the wildcard handling and magic signature cases.

This version addresses feedback from Patrick Steinhardt and Junio Hamano, including renaming for clarity (`allowed_magic`) and fixing path component handling. The patch appears ready for inclusion, having resolved all major technical concerns from the review while maintaining the substantial performance benefits originally demonstrated.
