This is a technical discussion about experimental Git setups for AI agent workflows, continuing the thread about Git's scalability challenges for AI parallelism.

Tanish Desai shares their experimental setup using Docker pods on a GCP instance, contrasting with Skybuck Flying's Windows/PostgreSQL/Gitea approach. The key innovation is using host-specific instruction files in a shared Git repo to coordinate AI agents (via Gemini CLI), with three different merge conflict handling strategies tested.

The most interesting findings come from the performance comparisons: direct merging causes frequent conflicts, patch queues help but don't scale well, and file-level locking works for small numbers of agents but becomes problematic at higher concurrency. These results empirically demonstrate the core challenge - Git's merge machinery wasn't designed for AI-speed parallel operations.

The email provides concrete data points about what fails and at what scale (2-4 vs 10-20 agents), making it a valuable contribution to understanding Git's practical limits in AI workflows. While not proposing Git core changes, it shows real-world workarounds developers are forced to implement, reinforcing the thread's theme that Git needs architectural evolution for AI-scale use cases.
