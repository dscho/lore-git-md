This is the first patch in a documentation series restructuring the `git-rebase` man page, now merged in its final form. The patch moves a rebase example to the start of the DESCRIPTION section, mirroring the approach used in `git-merge` documentation to help newcomers understand rebasing concepts earlier. It introduces ASCII art showing branch topology before and after rebasing, along with clear explanations of both the basic `git rebase master` form and the shortcut `git rebase master topic` syntax.

Key technical changes include adding 23 lines of new explanatory text at the beginning of the DESCRIPTION section while removing 26 lines of redundant explanations later in the document. The patch establishes the pattern of front-loading practical examples that continues through the rest of the series. The example demonstrates rebasing a `topic` branch onto an updated `master` branch, with before/after ASCII diagrams showing the commit history transformation.

The patch maintains technical accuracy while improving accessibility, particularly by explaining the relationship between the two command forms (`git rebase master` vs `git rebase master topic`). This initial patch set the tone for the series by showing how to balance completeness with approachability in Git's documentation.
