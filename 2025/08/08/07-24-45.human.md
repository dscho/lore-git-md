This is a bugfix patch that improves error handling when pushing with a non-existent object ID as the source. It's the second in a three-patch series that has already been reviewed and approved, addressing an issue where Git would incorrectly trigger a BUG() assertion when users provided a full but non-existent OID as the push source.

The patch replaces the BUG() call with a proper advise() message when pushing an invalid full 40 object ID to an unqualified ref. The new error message clearly tells users when they've specified an object ID that doesn't exist, rather than crashing with a developer-oriented assertion. A new test case is added to verify this behavior using test_oid 001 (a known non-existent OID).

The change is straightforward and well-contained, touching only remote.c's error handling and adding one test case. The commit message clearly explains the problem and shows the improved error output. This follows naturally from the first patch in the series (which cleaned up test formatting) and leads into the third patch that refactors the error handling code structure.

Since the series has already been reviewed and approved by Junio Hamano and Patrick Steinhardt, with all feedback addressed, this patch appears ready for inclusion. The only remaining technical note (about a temporary variable needed for the BUG() case) will be handled in a future follow-up.
