This is a bugfix patch that resolves an inconsistency in Git's diff behavior when using content-ignoring options (`-w`, `-I<regex>`) with metadata output formats (`--name-only`, `--name-status`, `--raw`). The patch is the fifth iteration (v5) of a solution that has been thoroughly reviewed and refined through discussion thread.

The core issue is that Git's metadata outputs were only comparing SHA values for performance reasons, which could show files as changed even when content-ignoring options would consider them equivalent. The solution introduces a `dry_run` mode in the diff machinery that quickly checks for actual changes while respecting ignore rules, without generating full patch output.

Key technical changes include:
- New `dry_run` flag in `struct diff_options`
- `quick_consume()` callback to detect changes without full processing
- `diff_flush_patch_quietly()` helper for efficient change detection
- Comprehensive test coverage in t4013 and t4015
- Documentation updates in xdiff-interface.h

The patch has been reviewed by Jeff King (who provided a Reviewed-by tag) and addresses all feedback from the mailing list discussion. It maintains performance while fixing the inconsistency, and includes thorough test cases to verify the behavior. The implementation is clean and well-documented, making this a solid fix for a real behavioral inconsistency in Git's diff output.
