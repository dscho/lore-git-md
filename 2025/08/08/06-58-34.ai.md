Performance optimization for Bloom filters in revision traversal, specifically enabling their use with wildcard pathspecs and certain magic signatures. This is version 2 of Lidong Yan's patch, incorporating feedback from the previous round.

The key technical changes include:
1. Switching from a forbid-mask to allow-mask approach for pathspec magic handling (as suggested by Patrick Steinhardt), with the variable renamed to `allowed_magic` for clarity
2. For wildcard pathspecs, using only the non-wildcard portion up to the last directory separator for Bloom matching
3) Adding comprehensive test coverage in t4216-log-bloom.sh, including tests for various magic signatures (top, glob, attr) and edge cases with wildcards

The patch shows significant performance improvements in benchmarks:
- 18-27% faster in Git repository tests (e.g., `git log -100 -- "t/*"` goes from 23.4ms to 20.4ms)
- 47-63% faster in larger repositories like LLVM (`git log -100 -- "libc/*"` improves from 26.7ms to 16.0ms)

The implementation carefully maintains backward compatibility while enabling Bloom filters for previously excluded cases. Magic signatures that are enabled include "top", "glob", "attr", "--depth" and "literal", while "exclude" and "icase" remain disabled due to functional incompatibility with Bloom filters.

The test suite now verifies both the positive cases (where Bloom filters should be used) and negative cases (where they should be disabled), including paths with wildcards in different positions and various magic signatures. The patch appears ready for inclusion pending final documentation polish as noted in the thread.
