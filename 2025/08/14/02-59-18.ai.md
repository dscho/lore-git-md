This is a conceptual discussion about Git's index implementation that emerged from the documentation patch series for `git-add`. Julia Evans responds to Junio Hamano's explanation about why Git discards intermediate index states during the edit-add cycle, probing deeper into the design rationale.

The exchange highlights a key aspect of Git's snapshot model that isn't immediately obvious to users - the index only stores the current state, not a history of changes. Julia articulates an alternative mental model where the index could maintain historical states (similar to the reflog), allowing selective reverts of intermediate changes. She correctly identifies this isn't how Git works but seeks to understand why this design choice was made, suggesting performance might be a factor.

This discussion has implications for documentation strategy - it suggests that explicitly stating the index discards past states (rather than just describing it as a snapshot) could help users better understand Git's behavior.
