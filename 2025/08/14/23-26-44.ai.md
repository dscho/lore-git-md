This is a refactoring suggestion in the ongoing discussion about potential null pointer dereference in `builtin/describe.c`. Jeff King proposes changing the interface of `describe_commit()` to take a `struct commit*` directly rather than an OID, which would eliminate the need for the potentially unsafe `lookup_commit_reference()` call that started this thread.

The key technical changes would be:
- `describe_commit()` signature changes from taking `struct object_id*` to `struct commit*`
- All callers would need to be updated to pass commit objects directly
- The `process_commit_data` struct would store a commit pointer rather than OID
- The `describe_blob()` initialization would use `NULL` instead of a null OID

This approach would make the NULL dereference impossible at compile time by design, though it would require updating all call sites. Jeff notes this is just an inspirational suggestion rather than something he plans to implement, leaving it open for others to pick up if interested.

The proposal doesn't directly address Phillip Wood's question about whether the NULL case is practically reachable, but offers an architectural solution that would prevent the issue entirely. This continues the thread's exploration of how to handle the potential vulnerability, now considering interface design changes rather than just adding validation.
