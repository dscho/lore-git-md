This is a bugfix for the `git-jump` contrib script, finalizing the solution for handling filenames with spaces in diff output. The patch has already gone through review iterations and reached consensus among multiple reviewers (Phillip Wood, D. Ben Knoble, Junio Hamano).

The core fix is a one-line Perl regex modification (`(.*?)\t?$`) that optionally strips trailing tabs from filenames in diff output. This addresses the common case where Git's diff.c historically appends tabs after filenames containing spaces (e.g. "foo bar.txt\t"). The solution intentionally does not handle edge cases of filenames ending with literal tabs or quoted filenames with control characters, as these are rare in practice and would require more complex parsing.

Jeff King confirms the patch makes things strictly better without regressions, noting that handling quoted filenames would be tricky and likely not worth the effort given Vim's quickfix parsing limitations. The implementation is minimal and efficient, with no performance impact on existing cases.

Key technical points:
- Fixes space-containing filenames while maintaining current behavior for simple filenames
- Preserves Git's existing protection against control character ambiguity through its automatic quoting
- Explicitly documents the boundaries of supported functionality
- Rejects more complex solutions as unnecessary for practical needs

The patch is ready for inclusion with all technical concerns addressed and reviewer approvals secured. The thread shows clear consensus that this is the right balance between solving the common case and avoiding over-engineering.
