This is a follow-up discussion on the submodule hash algorithm bugfix patch. Junio C Hamano provides code review feedback on Michael Schroeder's patch that fixes shallow submodule fetches when superproject and submodule use different hash algorithms (SHA-1 vs SHA-256).

Key points raised in the review:
1. Clarification needed in commit message about which direction the hash length mismatch occurs (superproject longer than submodule)
2. Questions the use of "truncate" terminology since it implies making something shorter than natural length rather than removing excess padding
3. Suggests a more robust implementation approach - first determine submodule's hash algorithm, then use hash_to_hex_algop_r() to properly convert only valid bits rather than manual null-termination
4. Notes the current approach feels unsatisfying as it converts full hash first then truncates, rather than using hash algorithm knowledge upfront

The review doesn't propose specific code changes but identifies areas where the implementation could be more elegant and the commit message more precise. This continues the technical discussion of how best to handle hash algorithm mismatches in submodule operations, particularly focusing on edge cases in shallow clone scenarios.
