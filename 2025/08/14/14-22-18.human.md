This is a technical discussion about the storage format for SHA-1/SHA-256 object ID mappings in Git's hash transition effort. Junio C Hamano responds to brian m. carlson's proposal for improving the current `loose-object-idx` approach, which was identified as inefficient for large-scale use.

Hamano questions whether repurposing a single bit in the pack index v3 format would be sufficient, suggesting instead that any new format should be designed with extensibility in mind from the start. He proposes a two-layer storage approach similar to how packed and loose refs work - a stable base file optimized for reading, plus an overlay for easier writes.

The discussion touches on how to handle mostly-static mapping data versus dynamic information needed for features like shallow clones. Hamano suggests separating these concerns, with the dynamic data stored in auxiliary tables since it affects only a small subset of objects. The exchange shows careful consideration of both current needs and future extensibility in this important infrastructure work.
