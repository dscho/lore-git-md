This is a discussion email in the ongoing `git repo info` command implementation thread, specifically about the output ordering behavior for the new command.

Phillip Wood confirms Eric Sunshine's interpretation of his earlier position regarding output ordering for the new `git repo info` command. The key point is that the command should output values in the order they were requested on the command line, without any deduplication or sorting. 

Phillip makes a clear distinction between human-readable output (where sorting/deduplication might be preferable) and script usage (where preserving input order is more important). Since this command is designed to replace `git rev-parse` in scripts, he argues the input-order-preserving behavior is more appropriate for the use case.

This email represents final alignment among the contributors on this design decision, with Phillip, Eric, and Lucas all agreeing on the simpler approach of preserving input order without any additional processing. The discussion shows the careful consideration being given to the command's intended use cases and the tradeoffs between human and machine consumption of the output.
