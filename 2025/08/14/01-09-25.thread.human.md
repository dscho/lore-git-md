This thread continues the technical discussion about how to store bidirectional mappings between SHA-1 and SHA-256 object IDs, a key piece of Git's hash algorithm interoperability work. The conversation has evolved from initial architectural considerations to concrete format proposals.

brian m. carlson and Junio Hamano had previously established that the storage format should separate static mappings (which rarely change) from dynamic metadata (which updates frequently). They were considering either extending the pack index format or creating new dedicated files. Hamano strongly advocated for physical file separation to avoid rewriting static data during updates.

Derrick Stolee has now entered the discussion with a detailed proposal for a new file format that takes a different approach. He argues against repurposing the pack index format, instead suggesting a reftable-like structure optimized for bidirectional lookups and incremental updates. His design features lexically-ordered tables with positional cross-references and a multi-layer approach to handle updates efficiently. While this aligns with the emerging consensus around storage separation, it introduces new considerations around compaction strategies and on-disk representation.

The thread shows clear technical convergence on separating concerns between static and dynamic data, but with competing visions for the implementation details. Stolee's proposal moves the discussion forward by providing a concrete alternative to the pack-index-extension approach, though questions remain about the exact performance characteristics and implementation complexity. The core participants continue to engage thoughtfully, with carlson maintaining focus on GC integration and Hamano emphasizing storage structure simplicity.
