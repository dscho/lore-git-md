Feature proposal for SHA-1/SHA-256 interoperability storage. Brian Carlson is working on Git's hash algorithm transition support and has hit a scaling problem with the current flat-file approach for storing object ID mappings. The existing `loose-object-idx` works for basic cases but will perform poorly for shallow clones, submodules, and partial clones where many mappings need to be stored long-term.

The email outlines requirements for a new storage format that needs to be fast for bidirectional lookups, support incremental updates, handle object types, and remain flexible for potential future hash algorithms. Several possible approaches are suggested, including extending pack index v3, using multi-pack indexes, or creating a reftable-like format. The proposal seeks feedback from format experts before implementation.

This is part of the ongoing SHA-256 transition work that has been discussed on the list before. The author has working code for basic interoperability cases and is now tackling edge cases that require more sophisticated storage. The proposal is well-motivated with clear technical constraints and appears to be building on existing transition design documents.
