This is a follow-up in the `--max-depth` feature series for git-diff-tree, now being shepherded by Toon Claes after initial work by Jeff King. The email comes from Junio Hamano checking on the status of the v2 series, which has seen no new feedback since addressing previous review comments.

The v2 changes include important refinements like unit tests for the depth calculation logic, support for `-1` as unlimited depth, improved error handling (using BUG() macros and translatable messages), and documentation tweaks. The series appears ready for consideration, with Junio suggesting it may be suitable for inclusion in the post-2.51 release cycle.

Key technical points from the series remain relevant: the depth measurement starts from pathspec matches (not repository root), the implementation avoids wildcard pathspecs and non-tree diffs, and the core diff machinery now tracks depth constraints via new fields in struct diff_options. The thread summary notes some remaining design questions around option parsing defaults and the max_depth_valid flag, but these don't block current progress.
