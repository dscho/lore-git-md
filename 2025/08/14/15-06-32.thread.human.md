This thread explores a tricky issue with submodule handling when the superproject and submodule use different hash algorithms (SHA-1 vs SHA-256). The original patch attempted to fix shallow submodule clones by truncating commit hashes, but Brian M. Carlson identified a fundamental problem: tree objects can't be automatically converted between hash algorithms, making mixed-algorithm submodules potentially unworkable.

The latest patch version from Michael Schroeder improves the implementation by using the submodule's hash algorithm when converting commit hashes during fetch operations, addressing Junio's earlier feedback about code elegance. However, the core architectural concern remains unresolved - whether Git should support mixed hash algorithms in submodules at all, given the deeper compatibility issues with tree objects.

Key participants are Michael Schroeder (patch author), Brian M. Carlson (raising architectural concerns), and Junio C Hamano (reviewing implementation details). The discussion has evolved from a specific bugfix to questioning whether the entire approach is viable. The patch now handles the immediate fetch case more cleanly, but the larger questions about hash algorithm interoperability in submodules remain open.
