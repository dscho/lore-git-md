This thread explores a complex issue at the intersection of submodules and Git's hash algorithm transition. The core problem involves shallow submodule clones failing when the superproject and submodule use different hash algorithms (SHA-1 vs SHA-256). Michael Schroeder initially proposed a practical fix to handle hash length mismatches by truncating or padding commit hashes as needed, which Junio C Hamano helped refine in v2 of the patch.

The discussion has since broadened to fundamental questions about whether mixed hash algorithms should be supported at all. Brian M. Carlson, who has deep expertise in Git's hash algorithm transition, argues strongly against the current pragmatic approach. He reveals that upcoming protocol changes for object ID conversion will make the current workarounds incompatible, and emphasizes that the hash transition design always assumed a single object format per repository. Carlson is working on proper shallow clone support that would handle these cases correctly, with code expected after Git Merge.

Key tensions remain between immediate bugfix needs and long-term architectural soundness. Schroeder maintains the current mixed-hash behavior works for most cases in practice, while Carlson warns these workarounds may create repositories that can't benefit from future interoperability features. The thread now sits at a crossroads between applying a focused fix for shallow clones or waiting for a more comprehensive solution that addresses the immediate issue while maintaining compatibility with the broader hash transition roadmap.
