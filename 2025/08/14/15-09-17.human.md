This is the final patch in a resolved thread about fixing object name abbreviation in Git. The patch addresses a regression from Git 2.16 that incorrectly limited abbreviation length for disambiguating object names.

The core change simplifies the logic in `extend_abbrev_len()` to properly handle NUL-terminated hexadecimal object names, removing the artificial 32-character limit that was causing disambiguation failures in SHA-1 repositories. The new version checks for string terminator rather than using fixed constants, which makes it work correctly regardless of hash algorithm (SHA-1 or SHA-256).

The patch represents the consensus solution after extensive discussion, incorporating feedback from multiple contributors. It maintains all the correct behavior while being simpler than previous iterations - René Scharfe and Junio Hamano collaborated to remove unnecessary conditions and make the code more focused on its actual purpose.

The change is particularly important for repositories with many objects that share long prefixes in their hashes, where Git previously failed to generate sufficiently long abbreviations to uniquely identify objects. This was a regression from pre-2.16 behavior where abbreviations could extend to the full SHA-1 length when needed.
