This is a follow-up discussion on the submodule hash algorithm bugfix patch. Junio C Hamano provides review feedback on Michael Schroeder's proposed solution for handling submodule commits when superproject and submodule use different hash algorithms.

The review focuses on two main points of clarification: First, Hamano suggests the problem description should more precisely state it occurs when the superproject uses a longer hash (like SHA-256) than the submodule. Second, he questions the use of "truncate" in the commit message, noting it's typically used to mean making something shorter than natural length, whereas here it's removing excess padding.

Hamano also identifies a potential optimization opportunity - rather than converting the full hash first and then truncating, the code could first determine the submodule's hash algorithm and only convert the relevant portion of the hash. This would avoid the need for manual null-termination.

The discussion doesn't raise any fundamental objections to the approach, but seeks to refine both the explanation and implementation details. The patch remains focused on fixing the shallow submodule clone failure case when hash algorithms differ between superproject and submodule.
