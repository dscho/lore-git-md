This is a technical discussion about submodule handling with mixed hash algorithms (SHA-1 vs SHA-256). Brian Carlson responds to Michael Schroeder's proposed fix for shallow submodule clones when superproject and submodule use different hash algorithms.

Carlson raises a critical concern about the fundamental approach: the current behavior of padding submodule commit hashes with zeros could lead to data corruption when the superproject uses SHA-1 and submodule uses SHA-256 (reverse of the original case). They argue the proper solution requires storing submodule states in matching hash algorithms, since tree objects are binary data that must maintain consistency.

The response suggests the issue is more fundamental than just shallow clone handling - it implies the entire approach of mixing hash algorithms between superproject and submodules may be unsafe. This challenges the premise of Schroeder's patch, which focused on making the existing mixed-hash behavior work rather than questioning whether it should be allowed at all.

The tone is direct but technical, pointing out a potentially serious flaw in the current implementation's assumptions. This appears to be an important architectural consideration that may require rethinking how Git handles submodules across hash algorithm boundaries.
