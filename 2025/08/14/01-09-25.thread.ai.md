[Thread summary: SHA-1/SHA-256 interoperability storage format proposal]

Thread identity: Technical discussion between brian m. carlson and Junio C Hamano about storage format for bidirectional SHA-1/SHA-256 object ID mappings, part of carlson's `sha256-interop` branch work. Thread has evolved from initial proposal to focused architectural discussion of static vs dynamic data separation.

Core problem: Need efficient storage format supporting bidirectional lookups between hash algorithms that cleanly separates static mappings (stable once computed) from dynamic metadata (shallow boundaries, incremental updates). Must minimize I/O overhead for frequent updates while maintaining lookup efficiency. Current status: Active design phase with convergence toward two-layer approach. Discussion now focuses on concrete implementation of separate files for static mappings vs dynamic data.

Key technical details:
- Prototype uses dual hashmaps (SHA-1<->SHA-256) but needs disk format
- Pack index v3 extension remains possible for static portion
- Hamano advocates two distinct files: static mappings (rarely changed) + dynamic metadata (frequently updated)
- `git gc` integration still proposed but now focused on static portion
- Fundamental challenge remains: sorting by one hash makes reverse lookups linear
- Clear architectural division emerging between immutable mappings and volatile metadata

Open questions:
- Whether to implement as pack index v3 extension + auxiliary file vs two new dedicated formats
- Exact format for dynamic metadata layer (reftable-like vs simpler approach)
- Write-path optimization for high-frequency updates to dynamic data
- Whether static mappings should include any metadata or remain pure translation
- Performance impact of file separation on lookup operations

Participant positions:
- carlson: Now considering separate files approach while maintaining gc integration for static portion. Still evaluating tradeoffs of various lookup strategies.
- Hamano: Strongly advocates physical file separation to avoid rewriting static data. Clarifies position is about storage structure, not timing of operations. Suggests simpler formats may emerge from this division.

Related work: Connects to carlson's SHA-256 interoperability work, reftable design, and Git's ref storage model. Hash transition docs remain key reference. Discussion shows technical progress with architectural separation now a clear focus.
