This is part 4/7 of Junio Hamano's string-list API refactoring series, introducing a new trimming capability for split strings. The patch adds a `STRING_LIST_SPLIT_TRIM` flag that automatically trims whitespace from both ends of each substring when splitting strings.

The implementation modifies the internal `split_string()` helper to handle left and right trimming when the flag is set, while maintaining the existing behavior when it's not. Two flag-aware variants are exposed through new API functions `string_list_split_f()` and `string_list_split_in_place_f()`, keeping the original functions for backward compatibility.

The changes include thorough unit tests demonstrating the trimming behavior with various edge cases: leading/trailing spaces, multiple delimiters, and maxsplit constraints. This builds on the series' earlier work to unify the string splitting implementations while adding new functionality cleanly.

As with previous patches in the series, this is a well-constructed internal refactoring with no user-facing impact. The changes are focused and clearly motivated, with comprehensive test coverage showing the new trimming behavior works as expected in both regular and in-place splitting modes. The patch follows the established pattern of the series by introducing flags through enum-based bitfields and maintaining const-correctness.
