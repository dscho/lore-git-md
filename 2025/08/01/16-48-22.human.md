This is a test fix addressing a security verification in t7450-bad-git-dotfiles.sh. The patch corrects the path being checked in a test that verifies Git's protection against malicious repositories executing post-checkout hooks during recursive submodule clones.

The test was introduced to validate the security fix from commit 05e9cd64, which prevents repositories from tricking Git into running unauthorized hooks. While the test properly verified the security behavior, it was checking the wrong path ("$PWD/foo") where a vulnerable Git version would create files via the post-checkout hook. The corrected path ("$PWD/bad-clone/sub/foo") matches the actual directory structure where the attack would occur.

Justin Tobler confirms the technical correctness of this change, noting it maintains the test's dual verification approach - both ensuring the security behavior works and demonstrating the original vulnerability through the preserved "bad-clone/sub\r/post-checkout" marker file. The patch appears to be in its final form after incorporating feedback from multiple reviewers, including improvements to commit message clarity and author name consistency.

This is a straightforward correction to an existing security test that brings it into alignment with the actual attack scenario it was designed to verify. The change is uncontroversial and ready for integration.
