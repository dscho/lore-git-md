This is a refactoring patch from Junio Hamano's string-list API cleanup series, converting error handling from `die()` to `BUG()` for invalid string-list usage. The change affects two functions in string-list.c that check the `.strdup_strings` flag - `string_list_split()` and `string_list_split_in_place()`. 

The patch makes these functions use `BUG()` instead of `die()` when called with incompatible string-list configurations, as this represents a programming error rather than a runtime condition. The author notes the error text could be more concise but keeps the existing message for now. 

This is the first patch in a v3 series that has already undergone significant review, with all major technical decisions settled. The change is straightforward and uncontroversial, aligning with Git's error handling conventions where programming errors should trigger `BUG()` rather than `die()`. The rest of patches builds on this foundation to unify string-list splitting behavior across the codebase.
