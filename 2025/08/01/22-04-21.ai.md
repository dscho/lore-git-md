Refactoring patch demonstrating the new string-list API in action. This is part 5/7 of Junio Hamano's series to modernize Git's string-list handling.

The patch simplifies the parsing of `diff.colormovedws` configuration by leveraging the new `STRING_LIST_SPLIT_TRIM` flag introduced in the previous patch. The original code manually split the comma-separated list and then used a temporary `strbuf` to trim whitespace from each token before comparison. The new version uses the string-list API's built-in trimming capability, eliminating the need for intermediate `strbuf` allocations and cleanup.

Key changes:
- Replaces `string_list_split()` with `string_list_split_f()` plus `STRING_LIST_SPLIT_TRIM` flag
- Removes all `strbuf` handling code since trimming now happens during the initial split
- Maintains identical functionality for all valid inputs ("no", "ignore-space-change", etc.)
- Preserves the same error message for invalid values

This serves as a practical demonstration of the API improvements from earlier in the series, showing how callers can be simplified when the string-list handles more functionality internally. The change affects only `diff.c` and is purely a code cleanup with no behavior changes. As with the rest of the series, this maintains backward compatibility while reducing code duplication.
