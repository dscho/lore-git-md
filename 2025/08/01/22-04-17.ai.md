This is a refactoring patch from Junio Hamano's string-list API series, converting error handling from `die()` to `BUG()` for invalid string-list usage. The change affects two functions in string-list.c that check the `.strdup_strings` flag - `string_list_split()` and `string_list_split_in_place()`. 

The patch makes these internal consistency checks use Git's standard `BUG()` macro rather than `die()`, which is more appropriate for programming errors that should never occur in correct usage. The error messages themselves remain unchanged for now, though the commit message notes they could potentially be made more concise in the future.

This is a straightforward change that aligns with Git's error handling conventions, where `BUG()` is used for internal consistency violations while `die()` is reserved for runtime errors. The modification is mechanical and focused, touching only the error reporting mechanism while leaving the actual string splitting logic unchanged. As part of the larger string-list refactoring series, this helps standardize the API's error handling approach.
