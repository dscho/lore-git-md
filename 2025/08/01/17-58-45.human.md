Bugfix report: `git remote rename` drops comments in config file refspecs.

Skybuck Flying reports that when using `git remote rename`, the command strips inline comments from refspec lines in the `.git/config` file while updating the remote name. The email shows a before-and-after comparison where descriptive comments about branch, tag, and pull request handling are lost during the rename operation, though commented-out refspecs remain intact.

The issue appears to be a minor quality-of-life problem rather than a functional bug, as the core rename operation works correctly. The reporter notes they can manually restore the comments from backup, and observes that the unchanged comments in the renamed section might actually be helpful for potential reverts.

This seems like a straightforward parser issue where the config file rewrite isn't preserving comments on active refspec lines. The impact is low since it doesn't affect functionality, but could be annoying for users who document their remote configurations with inline comments. The patch would likely be welcome as a quality improvement if someone submits a fix.
