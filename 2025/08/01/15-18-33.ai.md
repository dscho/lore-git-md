This is a follow-up discussion on the recently completed `core.commentChar=auto` deprecation series. Oswald Buddenhagen raises several concerns about the user experience design of the deprecation warning system implemented by Phillip Wood.

The discussion focuses on whether Git should provide detailed guidance about fixing deprecated configs, with Buddenhagen arguing that:
1) The complexity of the warning system may not be justified given the relatively small number of affected users
2) The warnings focus too much on trivial usage patterns rather than explaining the deeper rationale for the change
3) The partial guidance (when dealing with read-only config files) could actually mislead users rather than help them

Buddenhagen suggests the simpler approach of just telling users to use `git config --show-origin` would be sufficient, as the change doesn't create an urgent burden for users. The critique implies the current implementation may be over-engineered for the actual user impact of this deprecation.

This feedback comes after the series was already completed and merged, suggesting it's more of a retrospective design critique than a blocking issue. The exchange highlights ongoing philosophical differences about how much hand-holding Git should provide for configuration changes versus letting users figure things out themselves.
