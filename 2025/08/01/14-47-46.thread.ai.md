Patrick Steinhardt's reftable/libgit2 compatibility series (v5, 11 patches) implements production-ready reftable support through standardized error handling, atomic stack modifications, and race condition fixes, enabling libgit2 to run its full test suite with reftable-enabled repositories. The series builds on v4's technical foundation with additional error handling standardization in the file locking subsystem.

Key technical elements:
1. Type safety fix standardizing on `size_t` for record counts in reftable writer interface (reftable-writer.[ch])
2. Error handling standardization with reftable-specific codes (REFTABLE_IO_ERROR, REFTABLE_LOCK_ERROR, REFTABLE_OUTDATED_ERROR) replacing errno-based translation, now extended to file locking subsystem in new patch 5/11
3. Atomic stack operations via `REFTABLE_STACK_NEW_ADDITION_RELOAD` flag consistently applied across all ref operations, including final bugfix in v4 patch 8/8 that adds the flag to rename_ref, copy_ref, create_reflog, and delete_reflog operations
4. Race condition fixes in reflog operations through proper lock ordering and compaction handling, including fix for `stack_uptodate()` error handling and reordering in reflog_expire to create addition before initializing iterator
5. Removal of Git-specific dependencies (replaced `QSORT()` with standard `qsort()` in reftable/writer.c)
6. Simplified file locking error handling in reftable/stack.c by making `flock_acquire()` return reftable error codes directly rather than relying on errno interpretation
7. Code reorganization in reftable/stack.c eliminating forward declarations
8. Compiler warning fix removing `REFTABLE_ADDITION_INIT` macro in favor of explicit `memset()` calls
9. New `flags` parameter added to `reftable_stack_add()` interface
10. Updated system.h documentation to explicitly specify expected error codes from file operations
11. Removal of redundant errno translation code from multiple stack.c call sites and redundant manual stack reload in prepare_transaction_update

Technical scope spans reftable-stack.[ch], reftable-writer.[ch], system.[ch], refs/reftable-backend.c, addressing:
- Concurrent write safety via operation reordering and improved error handling
- Compiler warnings through initialization pattern changes
- Future-proofing for libgit2 integration by removing Git-specific macros and standardizing error codes
- Code organization improvements reducing forward declarations
- Race condition robustness in compaction operations and reflog operations
- Consistent error reporting across file locking operations
