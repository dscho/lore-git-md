The series builds on v3's technical foundation with minor documentation polish.

Key technical elements:
1. Error handling standardization with reftable-specific codes (REFTABLE_IO_ERROR, REFTABLE_LOCK_ERROR) replacing errno-based translation
2. Atomic stack operations via `REFTABLE_STACK_NEW_ADDITION_RELOAD` flag consistently applied across all ref operations
3. Race condition fixes in reflog operations through proper lock ordering and compaction handling
4. Removal of redundant stack reloads in favor of unified handling

Technical scope spans reftable-stack.[ch], reftable-writer.[ch], refs/reftable-backend.c, and system.c, addressing:
- Concurrent write safety via operation reordering
- Compiler warnings through initialization pattern changes
- Future-proofing for libgit2 integration
