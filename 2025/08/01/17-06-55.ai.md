This is a documentation patch that follows up on an implementation discussion about naming conventions for cleanup functions in the `git last-modified` series.

Junio Hamano proposes clarifying Git's CodingGuidelines to better distinguish between `S_release()` and `S_clear()` functions. The patch stems from confusion during code review where even experienced contributors weren't certain about the distinction. The key clarification is that `S_release()` only frees resources without reinitializing the structure for reuse, while `S_clear()` does both (release + reinit).

The change modifies the CodingGuidelines document to explicitly state that `S_release()` doesn't prepare the structure for immediate reuse, making the distinction from `S_clear()` more obvious without requiring cross-referencing both entries. This is a small but meaningful documentation improvement that could prevent similar confusion in future code reviews.

The patch is straightforward and uncontroversial, directly addressing an ambiguity in the project's coding standards. It doesn't affect any runtime behavior but improves contributor documentation. The change aligns with Git's emphasis on clear, precise documentation of API contracts and naming conventions.
