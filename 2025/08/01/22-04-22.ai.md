This is patch 6/7 in Junio Hamano's v3 series refactoring Git's string-list API, adding a new STRING_LIST_SPLIT_NONEMPTY flag to omit empty string pieces from split operations. The patch builds on the series' unified string-list splitting machinery introduced earlier.

The change adds a new flag (bit 1 in the existing flags system) that makes string_list_split_f() skip empty substrings when splitting. The implementation adds a simple check in append_one() to return early when encountering an empty piece with NONEMPTY set. The patch includes comprehensive test coverage in u-string-list.c, demonstrating the new behavior both standalone and in combination with the existing TRIM flag.

Key technical details:
- New STRING_LIST_SPLIT_NONEMPTY flag (1<<1) in string-list.h
- Core logic change in string-list.c's append_one() with defensive bounds check
- 6 new test cases covering:
  - Basic empty-string skipping
  - Edge cases with leading/trailing delimiters
  - Interaction with STRING_LIST_SPLIT_TRIM
  - Both string_list_split_f() and string_list_split_in_place_f() variants

The change is purely internal API improvement with no user-facing impact, continuing the series' pattern of cleaning up string-list usage across the codebase. The implementation is minimal and consistent with the series' established patterns, with thorough test coverage demonstrating the new functionality works as intended.
