Build system patch simplifying Git/Meson compatibility for `ls-files --deduplicate`. This is a follow-up to the ongoing discussion about handling build failures with older Git versions.

Martin Storsjö responds to Patrick Steinhardt's suggestions for improving the initial patch. The key development is agreement on a simpler approach: instead of version detection (which required different code paths for different Meson versions), they'll use `check: false` on the `run_command()` call and check the return code directly. This eliminates the need for the version comparison logic entirely.

The email also shows Martin incorporating Patrick's suggested commit message improvements and variable name change (from `new_enough_git` to the more descriptive `git_supports_file_deduplication`), though the latter becomes moot with the new approach. The discussion remains technical and collaborative, with both contributors focused on finding the cleanest solution.

This appears to be converging toward a clean resolution of the build compatibility issue, with the simpler failure-handling approach likely to be implemented in the next version of the patch. The change affects only build-time behavior (specifically the optional static analysis feature) and won't impact runtime functionality.
