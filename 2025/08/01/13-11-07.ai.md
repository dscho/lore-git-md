Feature implementation for the new `git repo info` command, specifically adding the `references.format` field. This patch is part of the v7 series introducing a new command hierarchy to migrate functionality from `git rev-parse`.

The patch implements the first concrete field for repository metadata - `references.format` - which reports whether the repository uses files or reftable for reference storage. The implementation:
- Adds the field definition to `repo_info_fields` array
- Implements `get_references_format()` to query the repository's ref storage format
- Includes comprehensive tests in new file `t1900-repo.sh` covering:
  - Correct output for both files and reftable formats
  - Error handling for invalid keys
  - Graceful continuation when some keys are invalid
  - Deduplication of duplicate key requests

Key technical details:
- Uses `ref_storage_format_to_name()` to convert enum to string
- Implements lexicographical sorting of output as established in the series
- Follows the series' pattern of `quote_c_style` for key=value output
- Maintains the error recovery behavior via `continue` when invalid keys are requested
- The test file demonstrates proper null-byte handling and output comparison
- Documentation updates include the new field in the man page with reference to existing ref-storage-format docs

This represents the first production field implementation in the new command, establishing the pattern for future fields to follow. The implementation appears thorough with good test coverage and follows the architectural decisions established in earlier patches of the series.
