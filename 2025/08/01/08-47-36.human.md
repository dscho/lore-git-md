This is a refactoring patch in Junio Hamano's string-list API series, specifically addressing the NONEMPTY flag functionality. Patrick Steinhardt provides final polish feedback on patch 6/7, which teaches the split_string() machinery to optionally omit empty split pieces.

The patch adds the STRING_LIST_SPLIT_NONEMPTY flag and implements it in append_one() by checking for empty strings (end <= p). Patrick notes that the condition is probably overly defensive since end < p shouldn't occur, and suggests a BUG() might be appropriate though likely not worth adding. This continues the thread's pattern of minor style discussions as the series nears completion.

The feedback is purely about implementation details - the core functionality is settled and working as intended. This represents one of the final subjective code organization questions (defensive checks vs assertions) before the series can be merged. The change remains internal to string-list.c with no API or behavioral impact beyond what was already agreed upon in earlier discussion.
