Bugfix targeting blobless clone behavior. This email reports a fetch failure that occurs specifically when fetching from a new remote into a repository that was originally cloned with `--filter=blob:none`. The reporter demonstrates the issue with a clear reproduction case involving cloning a repository, adding an upstream remote, and attempting to fetch from it.

The key symptom is that while the remote enumerates and transfers objects normally, the fetch ultimately fails with "fatal: did not receive expected object" followed by "invalid index-pack output". The reporter notes this only manifests with blobless clones, suggesting a problem in how Git handles object expectations when fetching into a repository with partial object storage.

The report includes complete system information (Git 2.50.1 on macOS with clang 16) and shows the full error output. While the commit message doesn't propose a fix, it provides all the necessary details to investigate the issue, including the specific object hash that failed to be received (0020d54b979cc8cf59a13406f98bfe515b190559). This appears to be a legitimate bug in Git's handling of filtered clones rather than a user error or environmental issue.
