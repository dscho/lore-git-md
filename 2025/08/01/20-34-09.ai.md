This is a documentation refinement for the `git last-modified` command, part of the post-merge polishing phase. Jean-Noël AVILA responds to earlier feedback from Patrick Steinhardt and Toon Claes about improving the man page formatting for the new command.

The key discussion point is about option documentation style - specifically whether to show both short and long forms of options in the man page synopsis and descriptions. Patrick Steinhardt notes that Git typically lists long options in the synopsis rather than short single-letter ones, and suggests showing both forms in the option descriptions (like `-r, --recursive::`). Jean-Noël AVILA agrees with this approach but proposes a slight variation: showing each form on its own line in the descriptions (e.g. `-r::` and `--recurse::` as separate entries).

The email also references the `-t/--tree-in-recursive` option, though this naming is likely to change to `--show-trees-in-recursive` per Junio Hamano's recent strong preference mentioned in the thread context. The documentation updates here will need to reflect that final naming decision when it's settled.

The changes discussed are straightforward and uncontroversial, focused purely on presentation rather than functionality.
