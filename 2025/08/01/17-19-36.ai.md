This is a post-merge discussion about the recently completed `core.commentChar=auto` deprecation series, focusing on the user experience of configuration warnings. Junio C Hamano responds to Oswald Buddenhagen's critique of Phillip Wood's approach to advising users about deprecated config values.

The discussion centers on whether Git should provide detailed guidance when users encounter the deprecated `core.commentChar=auto` setting. Buddenhagen argues the current implementation adds unnecessary complexity for a relatively rare case, suggesting users could simply be directed to use `git config --show-origin` to find and fix the setting themselves. He also notes the advice doesn't cover all edge cases (like read-only config files), potentially leading users to suboptimal solutions.

Hamano acknowledges the simplicity argument but defends the current approach, noting most users prefer direct instructions over having to deduce solutions themselves. He agrees the advice isn't perfect (particularly regarding read-only files) but considers it acceptable as long as it doesn't actively mislead users. The exchange reveals differing philosophies about Git's responsibility in configuration migration - whether to provide comprehensive automated guidance or maintain simpler code at the cost of user convenience. This appears to be a retrospective discussion rather than seeking changes to the already-merged series.
