Bug report regarding `git remote rename` behavior with config file comments. Skybuck Flying reports that the command strips inline comments from active fetch refspec lines in the config file while updating the remote name, though comments on commented-out refspecs remain intact (albeit with outdated remote names). The issue specifically affects the `[remote]` section during remote renaming, where the right-hand side of fetch refspecs is updated to use the new remote name while discarding any trailing comments. The report demonstrates the behavior through concrete before/after examples, noting that while the comment loss is non-functional (original config remains available), it affects user documentation in config files. No proposed fix is included, but the report clearly identifies the problematic behavior in the config rewriting logic.
