Documentation patch clarifying API naming conventions.

Junio C Hamano proposes a clarification to the CodingGuidelines document regarding the distinction between `S_release()` and `S_clear()` functions. The current text makes the difference clear only when reading both entries, so this patch makes the `S_release()` description self-contained by explicitly stating it doesn't reinitialize the structure for reuse.

The change stems from a discussion about naming in the `git last-modified` implementation, where even experienced contributors found the current guidelines ambiguous. The patch cleanly documents the convention that `S_release()` only frees resources while `S_clear()` both frees and reinitializes. This is a straightforward improvement to the project's style guide that will help prevent future confusion.

The patch is minimal and focused, touching only the relevant section of CodingGuidelines. As a documentation clarification from the project maintainer, it's likely to be accepted without controversy.
