Refactoring patch in Junio Hamano's string-list API series. This is the third patch in a 7-part series that has already gone through several rounds of review and technical refinement.

The patch unifies the implementations of `string_list_split()` and `string_list_split_in_place()` into a single internal helper function called `split_string()`. The key difference between these functions is that one works on immutable strings (making copies of the split results) while the other modifies the input string directly. The patch maintains this behavioral distinction while eliminating code duplication.

The implementation introduces a new `append_one()` helper to handle the string copying/placement logic, and carefully preserves the existing error checking (converted to `BUG()` calls as per earlier decisions in the series). The changes are purely internal - no user-facing behavior is altered.

This continues the series' pattern of cleaning up the string-list API while adding flexibility for future extensions (noted by the comment about how flags could later be added). The patch follows the established patterns from previous iterations, including the enum-based flags and defensive programming approach that were settled in earlier review discussions.
