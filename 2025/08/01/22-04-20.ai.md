Internal refactoring of string-list API with new trimming functionality.

This patch introduces the STRING_LIST_SPLIT_TRIM flag to the string-list API, allowing split operations to automatically trim whitespace from resulting string pieces. The change builds on the unified split_string() helper established in the previous patch, adding both left and right trimming logic in append_one().

Key technical details:
- New flag STRING_LIST_SPLIT_TRIM (1 << 0) added to string-list.h
- Both ltrim and rtrim operations implemented in append_one()
- New _f variants (string_list_split_f and string_list_split_in_place_f) expose the flags parameter
- Comprehensive test coverage in t/unit-tests/u-string-list.c demonstrates:
  - Basic trimming functionality
  - Interaction with maxsplit
  - Both regular and in-place split variants
- Maintains const-correctness through internal cast for in_place operations

The implementation handles edge cases like empty strings and preserves the existing behavior when the flag isn't set. The changes are contained to string-list.c/h with no impact on callers that don't use the new flag. This continues the series' pattern of careful API evolution with thorough test coverage, adding functionality while maintaining backward compatibility.

The patch follows the established pattern from earlier in the series, using the _f suffix for flag-taking variants and maintaining separation between internal implementation and external API. It integrates cleanly with the unified split_string() helper from patch 3/7.
