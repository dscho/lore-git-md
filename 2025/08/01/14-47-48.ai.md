This is a refactoring patch in Patrick Steinhardt's series improving reftable compatibility with libgit2. The change replaces Git's `QSORT()` macro with standard `qsort()` in the reftable writer code to make the library more portable for non-Git consumers like libgit2.

The patch modifies two sorting calls in `writer.c` that handle ref and log records. While `QSORT()` automatically determines element size, the new version explicitly passes `sizeof(*refs)` and `sizeof(*logs)` to `qsort()`. The author also adds null checks (`if (n)`) before sorting, though this appears defensive since the original code would have crashed on empty arrays too.

This is a straightforward change that removes a Git-specific dependency while maintaining identical functionality. The modification touches core writer operations but doesn't affect behavior - it's purely about interface compatibility. The patch fits cleanly into the series' goal of making reftable usable by libgit2 by eliminating Git internals.
