This is a discussion about pattern matching behavior in the `git refs list` feature, which is part of an RFC patch series introducing a new ref listing command.

Junio Hamano responds to Phillip Wood's concern about the potentially confusing behavior of single-asterisk pattern matching in ref listings. The current implementation (inherited from `git for-each-ref`) treats `refs/heads/m*` as matching only at a single hierarchy level (e.g., matching `morning` but not `mid/night`). Junio clarifies that this is intentional - it's not a simple prefix match but rather anchored at hierarchy boundaries, which explains why `refs/hea` wouldn't match branches either.

This email confirms the decision to maintain the current pattern matching semantics for the new `git refs list` command, keeping consistency with `git for-each-ref`. The thread has previously discussed potentially adding double-asterisk (`**`) syntax in the future for cross-hierarchy matching, but that would be a separate enhancement.

The exchange represents the final resolution of one of the last open questions in this well-developed patch series, with the maintainer weighing in to settle the behavior question. The architectural foundation of sharing core logic between `for-each-ref` and the new `refs list` command means this decision affects both commands consistently.
