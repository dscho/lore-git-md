This is a discussion about pattern matching behavior in the `git refs list` feature implementation, which inherits its matching semantics from `git for-each-ref`. The thread involves Junio Hamano responding to Phillip Wood's concerns about the current behavior being confusing.

Junio clarifies that the current behavior is intentionally hierarchical - patterns like `refs/heads/m*` only match at a single hierarchy level (showing `morning` but not `mid/night`). He argues this is useful for listing main branches without showing topic branches. He suggests the current behavior (anchored at hierarchy boundaries) is preferable to requiring explicit wildcards or doing prefix matching.

Junio proposes considering an enhancement where double-asterisk (`**`) could match across hierarchy boundaries, allowing patterns like `refs/heads/m**` to catch all branches starting with 'm' at any level. This would maintain the current single-asterisk behavior while adding more flexible matching when explicitly requested.

The discussion is part of final UX polishing for the `git refs list` command, which shares core implementation with `git for-each-ref`. The architectural foundation is solid, but this thread highlights an important behavioral decision about pattern matching that needs resolution before merging. Junio's position suggests maintaining current semantics while potentially extending them with `**` for cross-hierarchy matching.
