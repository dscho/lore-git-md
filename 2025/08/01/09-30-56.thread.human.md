This thread investigates a fetch failure that occurs in blobless clones (`--filter=blob:none`) when adding a new remote. Justin Su originally reported the issue, where fetches fail with errors about unexpected objects and invalid index-pack output, despite correct remote object enumeration. Jeff King initially couldn't reproduce the problem locally, suggesting it might depend on server state.

Justin has now confirmed the issue remains reproducible on their system, strengthening the case that this is a real (if intermittent) edge case rather than a universal client bug. The divergence in reproduction results points to environment-specific factors, likely involving server-side delta generation behavior when base objects are missing from the client's blobless clone. While the root cause remains unclear, the persistent reproduction suggests this merits deeper investigation into how Git handles object transfers in filtered clones when deltas reference missing bases. The thread currently has two data points - one reproducible case and one non-reproducible - which may help narrow down the triggering conditions.
