Justin Su reported a fetch failure in blobless clones when adding a new remote, where Git complains about missing expected objects during index-pack operations despite successful object transfer. The error occurs with a specific hash (0020d54...) and affects Git 2.50.1 on macOS.

Jeff King (Peff) has responded but couldn't reproduce the issue locally. He suspects the problem might be server-dependent, possibly relating to delta compression against blobs from the original remote that aren't present in the blobless clone. This suggests an intermittent issue tied to server-side packing strategies rather than a consistent protocol violation. The discussion remains open, with the root cause still unclear but now pointing toward server interactions with partial clones as the likely investigation path.
