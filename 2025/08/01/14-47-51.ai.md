This is a refactoring patch in Patrick Steinhardt's series improving reftable compatibility with libgit2. The change adds a `flags` parameter to `reftable_stack_add()` to allow passing creation flags through to the stack addition process, though no flags are actually used yet in the Git codebase (they're intended for future libgit2 use).

The modification touches the reftable stack interface and its implementation, updating:
- The function signature in `reftable-stack.h` with new documentation
- All call sites in `refs/reftable-backend.c` to pass `0` as the flags value
- The internal `stack_try_add()` helper function to pass through the flags
- Numerous test cases in `t-reftable-stack.c` to maintain consistency

The key technical detail is that this enables future automatic stack reloading when modifications occur during locking, though that functionality isn't implemented here. The patch is straightforward - it mechanically adds the parameter without changing behavior, maintaining all existing test coverage while preparing for libgit2's needs. This continues the series' pattern of making incremental, focused changes to improve reftable's interface for external consumers.
