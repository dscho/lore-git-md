This is part 6/7 of Junio Hamano's string-list API refactoring series, introducing a new STRING_LIST_SPLIT_NONEMPTY flag to skip empty string pieces during splitting operations. The patch adds the flag to both the in-memory and in-place splitting variants, with corresponding test cases demonstrating its behavior when used alone and in combination with the existing STRING_LIST_SPLIT_TRIM flag.

The implementation is straightforward - it simply checks for empty strings (where end <= p) when the NONEMPTY flag is set and skips adding them to the result. The test coverage is thorough, showing the flag works correctly with edge cases like leading/trailing delimiters and when combined with trimming. This continues the series' pattern of careful API design with comprehensive testing.

As with previous patches in the series, this is purely internal refactoring with no user-facing impact. The changes are minimal (just 3 lines of implementation plus tests) and build logically on the foundation established by earlier patches.
