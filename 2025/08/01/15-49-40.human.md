This is a discussion about pattern matching behavior in the `git refs list` command, which inherits its ref selection logic from `git for-each-ref`. The thread involves Phillip Wood and Junio Hamano debating the current semantics of wildcard matching in ref patterns.

Phillip initially expressed confusion about the current behavior, noting inconsistencies like `refs/heads/m*` matching some branches but not others, and `refs/heads*` matching nothing. Junio clarifies that the current behavior is intentionally hierarchical - a pattern like `refs/heads/m*` matches branches starting with 'm' at the top level (like 'morning') but not in subhierarchies (like 'mid/night').

Junio argues this behavior is useful for listing main branches without showing topic branches, and suggests maintaining compatibility with `for-each-ref` while proposing a future enhancement: using double-asterisk (`**`) syntax for cross-hierarchy matching. Phillip agrees this would be a good improvement to the current behavior.

The discussion shows consensus forming around:
1. Keeping the current single-asterisk behavior (anchored at hierarchy boundaries)
2. Potentially adding `**` syntax in the future for more flexible matching
3. Maintaining consistency between `for-each-ref` and the new `refs list` command

This is part of the larger `git refs list` feature series that's nearing completion, with most technical issues already addressed in previous rounds of review.
