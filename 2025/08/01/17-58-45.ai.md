Bugfix report regarding `git remote rename` behavior with config file comments.

Skybuck Flying reports that `git remote rename` strips inline comments from refspec lines in the config file while updating the remote name. The email shows a before/after comparison where all comments on active fetch refspec lines are lost during the rename operation, though comments on commented-out refspecs remain intact. The issue affects the config file's `[remote]` section when renaming a remote, specifically modifying the right-hand side of fetch refspecs to use the new remote name while discarding any trailing comments.

The report notes two specific behaviors: 1) comments on active refspec lines are completely removed, and 2) comments on inactive (commented-out) refspecs are preserved but retain the old remote name in their text. The submitter considers the comment loss "somewhat unfortunate" but notes the original config is still available. The unchanged remote names in commented refspecs are seen as potentially useful for reverting changes.

This appears to be a bug in the config rewriting logic of `git remote rename` where it doesn't properly preserve comments when modifying refspec lines. The issue affects user documentation/comments in config files but doesn't impact functionality. The report doesn't include a proposed fix but clearly demonstrates the problematic behavior through concrete before/after examples.
