Bugfix for blobless clones failing when fetching from additional remotes.

Justin Su reports that fetching from an additional remote fails when working with a blobless clone (created with `--filter=blob:none`). The error occurs during object transfer, with Git failing to receive an expected object and producing invalid index-pack output. The issue is reproducible with Git 2.50.1 on macOS.

The problem appears specific to blobless clones - normal clones don't exhibit this behavior. The error suggests there may be an issue with how Git handles object transfer negotiation or verification when working with partial clones that lack blob objects. While the exact cause isn't diagnosed in the report, the clear reproduction steps make this a promising candidate for investigation by someone familiar with Git's partial clone and fetch machinery.

This looks like a legitimate bug report with good technical details provided, though it would benefit from including whether the issue persists with the latest Git version. The reporter has identified a specific edge case in Git's partial clone functionality that could affect users who work with multiple remotes.
