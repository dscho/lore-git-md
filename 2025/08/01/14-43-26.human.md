Maintainer feedback on ref listing pattern matching behavior. Junio Hamano responds to Phillip Wood's concerns about the inconsistent pattern matching behavior inherited by the new `git refs list` command from `git for-each-ref`.

Hamano clarifies that the current behavior is intentionally hierarchical - patterns like `refs/heads/m*` match only at a single hierarchy level (showing `morning` but not `mid/night`). He argues this is useful for listing main branches without showing topic branches, and that consistency between `for-each-ref` and `refs list` is important.

The email explores potential improvements to the pattern matching, suggesting that double-asterisk (`**`) could be introduced to match across hierarchy boundaries while maintaining the current single-asterisk behavior. This would address the confusion while preserving the useful hierarchical filtering.

This is a key design decision point in the final review of the `git refs list` series, with the maintainer weighing in on how pattern matching should work. The discussion will likely influence whether the command ships with the existing behavior or gets modified to be more intuitive.
