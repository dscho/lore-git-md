This is a bugfix series addressing complex edge cases in merge-ort's rename detection, now at version 3 with minor documentation and comment improvements. The series builds on the previously reviewed v2, which had already resolved all technical issues and received sign-offs from maintainers.

The v3 changes are primarily documentation-focused:
1. Adds a new patch (5/7) clarifying string interning in merge_options_internal's path member
2. Improves comments about rename-to-self cases in process_renames()
3. Updates test case references to include both testfile and testcase names (e.g., "t6423 12n" instead of just "12n")

The core fixes remain unchanged from v2, handling tricky directory rename scenarios where:
- Directory renames affect source paths of other operations
- Rename-to-self cases could cause silent file deletions or incorrect index entries
- Path collision detection needed strengthening in path_in_way()

The series includes comprehensive test coverage (+519 lines) in t6423-merge-rename-directories.sh, now with better documentation of edge cases (12i2, 12n, 12n2, 12o, 12p, 12q). These fixes originated from real-world merge problems observed at GitHub.

With all technical issues resolved in v2 and only minor polish added in v3, this series appears ready for merging. The changes are well-documented and maintainers have already reviewed the substantive fixes.
