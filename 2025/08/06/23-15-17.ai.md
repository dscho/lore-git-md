This is a refactoring patch in the merge-ort rename detection series, specifically addressing an internal implementation detail in directory rename handling.

The patch simplifies the `check_for_directory_rename()` function in merge-ort.c by replacing a verbose check using `strmap_get_entry()` with a direct `strmap_contains()` call. The change removes an unnecessary temporary variable (`otherinfo`) and makes the code more straightforward while maintaining identical behavior. The commit message explains this was a "weirdly coded check" that the new version makes more natural.

The modification relates to directory rename exclusions - a mechanism that prevents certain renames when they would conflict with other directory renames happening in the merge. The comment block above the changed code explains this prevents both "dumbdir" renames and N-way transient rename confusion, referencing test cases 9c and 9d in t6423.

This is patch 2/7 in the v3 series, building on the directory rename collision fixes from previous versions. The change is purely internal - no behavior or interface changes - and aligns with the series' goal of improving merge-ort's rename detection robustness.
