This is the third patch of a feature series adding `--max-depth` support to Git's diff machinery, continuing the discussion of implementation details from Patrick Steinhardt's review.

The email clarifies several edge cases in the `--max-depth` behavior:
- Confirms that with multiple pathspecs (like "a/b" and "a/b/c"), max-depth applies to matches from either pathspec
- Explains that sibling directories at the same depth (like "foo/qux" when matching "foo") will be included
- Acknowledges that -1 should be supported as "no limit" value like in `git grep --max-depth`

The author (Toon Claes) accepts several technical improvements:
- Making error messages translatable
- Using `git_parse_unsigned()` for argument validation
- Adding `const` to function parameters where appropriate
- Replacing `die()` with `BUG()` for internal checks
- Documenting wildcard pathspec incompatibility

Open questions remain about:
- Whether to use `OPT_UNSIGNED()` with flag setting in `diff_setup_done()`
- How to best handle the `max_depth_valid` flag alongside unsigned conversion
- The exact behavior when no pathspec is given (currently treats as depth from top-level)

The patch maintains Jeff King's original authorship while incorporating these review-driven refinements to the depth calculation logic and error handling. The discussion shows careful attention to edge cases and consistency with similar features like `git grep --max-depth`.
