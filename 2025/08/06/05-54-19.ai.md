This is a refactoring patch in Patrick Steinhardt's reflog migration infrastructure series, specifically addressing the handling of the REF_HAVE_OLD flag for log-only updates.

The patch changes how Git handles the REF_HAVE_OLD flag during reflog updates. Previously, this flag was explicitly unset for log-only updates (like those during ref storage migration) since the old OID didn't need to match the current ref state. The patch preserves this flag while still skipping the old-OID verification for log-only updates, preparing for a future change that will use this flag as a signal that the caller provided an old OID.

Key technical changes include:
- Removing the flag-clearing code from ref_transaction_update_reflog()
- Modifying ref_update_expects_existing_old_ref() to return 0 for REF_LOG_ONLY updates
- Updating old-OID verification checks in both files and reftable backends to skip when REF_LOG_ONLY is set
- Adding clarifying comments about the relationship between REF_LOG_ONLY and REF_HAVE_OLD

The changes are consistent with the series' focus on robust reflog handling during storage format conversion, though this particular change is more about internal flag usage than direct functionality. The patch maintains all existing behavior while enabling future enhancements to use the preserved REF_HAVE_OLD flag as a signal.
