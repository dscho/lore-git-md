This is patch 2/10 in Patrick Steinhardt's series to remove global state from the commit-graph subsystem, part of the broader `the_repository` removal effort. The patch focuses on type consistency for Bloom filter counters.

The change converts five signed integer counters in `write_commit_graph_context` to unsigned integers, since these values (tracking computed/not-computed/truncated/upgraded Bloom filters) are inherently non-negative. The commit message argues this makes the code's intent clearer by eliminating any possibility of negative values. Corresponding Trace2 logging calls are updated to use the new `trace2_data_uintmax()` function introduced in patch 1/10.

This appears to be a straightforward refactoring with no behavior change, addressing one of the type consistency issues raised in earlier review discussions. The patch is small (30-line diff) and focused, with all changes contained to commit-graph.c. It follows the series' pattern of using unsigned types where values cannot be negative, a principle that had explicit reviewer buy-in from Taylor Blau and Junio Hamano in previous rounds.
