This is part of the ongoing `the_repository` removal effort in the commit-graph subsystem. Patch 7/10 refactors `parse_commit_graph()` to take a full `struct repository*` parameter instead of just repository settings, eliminating more global state access.

The change allows the function to use the repository's hash algorithm directly rather than accessing `the_hash_algo`, and moves the `prepare_repo_settings()` call inside the function for better encapsulation. A minor fuzzer workaround was needed since it doesn't fully initialize repositories, but this is handled cleanly by marking settings as initialized.

The patch follows Taylor Blau's suggestion from earlier review and maintains the series' pattern of methodically replacing global state with explicit parameters. It touches core commit-graph operations (parsing, verification) but the changes are mechanical and well-contained. The fuzzer cleanup removing a redundant function declaration is a nice bonus.

With all technical discussions resolved and key reviewers already approving the approach, this appears to be a straightforward step toward the series' goal of removing global state from the commit-graph subsystem.
