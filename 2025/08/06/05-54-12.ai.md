Documentation patch converting git-reflog(1) man page to new synopsis format as part of Patrick Steinhardt's reflog migration infrastructure series (v6). This first patch in the 9-part series focuses purely on documentation formatting changes to comply with Jean-Noël Avila's synopsis style requirements introduced in commit 974cdca345c.

The patch converts the git-reflog(1) man page from verse formatting to the new [synopsis] type and wraps all option references in backticks (`` `--option` ``) to satisfy upcoming linter requirements. The changes are mechanical and do not affect technical content - the command syntax and behavior remain identical. Key formatting changes include:
- Replaced [verse] with [synopsis] for the command overview
- Removed single quotes around command forms (now handled by synopsis type)
- Added backticks around all option references (--expire, --single-worktree, etc.)
- Maintained all existing option descriptions and behavior text

This patch represents the documentation polish portion of the larger reflog migration series, with all technical solutions (HEAD race handling, transaction abortion, OID preservation) carried forward unchanged from v5. The changes align with broader documentation standardization efforts while keeping the reflog command's functionality intact.
