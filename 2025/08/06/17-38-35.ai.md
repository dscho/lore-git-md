This is a bugfix patch addressing an oversight in interactive rebase's handling of merge commits. The patch follows up on commit 4c063c82e9 which added error messages for cases where merge commits are used with incompatible sequencer commands, but missed handling the 'drop' command case.

The core change is that `TODO_DROP` is now added to the `check_merge_commit_insn()` function in sequencer.c alongside `TODO_MERGE`, allowing merge commits to be dropped without triggering the BUG() condition. A test case is added to t/t3404-rebase-interactive.sh that verifies dropping a merge commit no longer produces an error message.

The patch is straightforward and well-contained, touching only two files with minimal changes. It appears to be a logical extension of the previous commit's behavior, though the commit message could be more explicit about why dropping merge commits should be allowed (the current rationale of "permit it without a message" is somewhat terse). The test addition provides clear verification of the fixed behavior.
