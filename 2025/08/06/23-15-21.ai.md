Bugfix patch addressing multiple edge cases in merge-ort's rename-to-self handling, part of a larger series (6/7) improving directory rename detection. This patch specifically fixes three issues that occur when directory renames result in a file being renamed to itself (A->A): silent file deletion when the file should be kept, silent retention when it should be deleted, and incorrect index entry counts.

The core fix adds a check in process_renames() to skip processing when oldpath and newpath are identical (using pointer comparison since paths are interned). This prevents the function's normal rename logic from incorrectly manipulating what is essentially a no-op rename. The patch includes two new test cases (12i2 and 12n2) that demonstrate the bugs by modifying existing scenarios to trigger the edge cases, plus converts test 12n from expect_failure to expect_success now that the index count is correct.

Key technical details:
- Fixes process_renames() in merge-ort.c by adding early continue when oldpath == newpath
- Adds test case 12i2 showing silent deletion bug (modified version of 12i with extra content in 'bar' file)
- Converts test 12n to expect_success now that index entry count is correct
- Adds test 12n2 showing silent retention bug (modified version of 12n with merge.directoryRenames=true)
- Maintains all prior fixes from the series while adding these new cases
- Builds on string interning behavior documented in patch 5/7 of the series

The patch is well-integrated with the ongoing thread, addressing feedback from previous versions while maintaining the technical correctness of the directory rename fixes. The test additions follow the established pattern from earlier in the series and help verify the more subtle rename-to-self cases that were previously mishandled.
