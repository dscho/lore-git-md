This is a feature patch introducing a new `git reflog write` subcommand, part of Patrick Steinhardt's v6 series improving reflog handling for the reftable backend. The patch adds the ability to manually append reflog entries, which becomes particularly useful with reftable's binary format where manual editing isn't practical.

The new subcommand takes a ref, old/new OIDs, and a message, with strict validation: refs must be fully qualified, OIDs must be complete and reference existing objects, and messages get normalized. The implementation uses Git's ref transaction API to safely append entries. The feature is accompanied by comprehensive tests covering error cases (invalid args, bad refs, nonexistent objects) and success scenarios.

This fills a gap in the reflog tooling that wasn't critical for the files backend but becomes necessary with reftable. The implementation is clean and well-tested, though deliberately minimal - it doesn't yet support features like custom timestamps or bulk writes, which could be added later if needed. The patch fits logically into the larger series addressing reftable migration challenges.
