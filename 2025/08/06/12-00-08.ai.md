This is part 3/10 of Patrick Steinhardt's series to remove global state from the commit-graph subsystem, specifically addressing type consistency in write options. The patch fixes signed/unsigned integer mismatches for two commit-graph write options ("max-commits" and "size-multiple") that should logically be unsigned values.

The changes convert the option fields in `struct commit_graph_opts` from `int` to `size_t` and update the corresponding option parsing to use `OPT_UNSIGNED()`. This resolves sign comparison warnings in `split_graph_merge_strategy()` where these values were being compared with commit counts. The commit message notes these options were documented as positive integers all along, and suggests their original signed type might have been due to `OPT_UNSIGNED()` being a relatively recent addition.

The patch touches three files with straightforward mechanical changes: builtin/commit-graph.c (option parsing), commit-graph.c (internal usage), and commit-graph.h (type definitions). This continues the series' theme of type consistency improvements while maintaining functional behavior, with all changes being clearly motivated by the documented contract of these options. The changes align with prior reviewer feedback about using appropriate unsigned types for inherently non-negative values.
