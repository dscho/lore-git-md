This is a type safety refactoring patch in Patrick Steinhardt's reflog migration series, specifically addressing the `split_ident_line()` function signature. The change switches the line length parameter from `int` to `size_t` to better match the actual usage patterns where callers pass string lengths from `strlen()`, `strbuf::len`, or pointer differences - all of which are naturally unsigned values.

The patch modifies both the declaration in `ident.h` and implementation in `ident.c` with straightforward signature changes. While this appears to be a simple type change, it's part of the broader reftable infrastructure work where this function is used for parsing reflog entries. The commit message notes the logical inconsistency of accepting signed integers when the function will only ever receive positive values from its callers.

This change maintains compatibility with existing callers while making the interface more type-correct. It's a small but meaningful improvement to the codebase's type safety, particularly relevant for the reflog handling code paths that are being hardened in this series. The patch follows the series' pattern of careful attention to type safety and API contracts.
