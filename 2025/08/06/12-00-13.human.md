This is part of Patrick Steinhardt's ongoing series to remove reliance on global state in the commit-graph subsystem, specifically targeting `the_hash_algo` usage. Patch 8/10 systematically replaces direct calls to `the_hash_algo` with repository-specific hash algorithm references, either from the repository parameter or the commit-graph context.

The changes are mechanical but thorough, touching commit-graph operations across parsing, writing, and verification. Key modifications include updating hash size calculations, file validation checks, and data chunk handling to use the repository's hash algorithm rather than the global. The patch follows the established pattern from earlier in the series, with one notable addition: `open_commit_graph_chain()` now explicitly takes a hash algorithm parameter.

The changes maintain all existing behavior while progressing the series' goal of eliminating implicit dependencies on `the_repository`. As with previous patches in this well-reviewed series, the modifications are straightforward and unlikely to be controversial, building toward the larger architectural improvement of making the commit-graph subsystem work with pluggable object storage backends.
