This is a bugfix addressing the interaction between content-ignoring diff options (`-w`, `-I`) and metadata outputs (`--name-only`, `--name-status`). The patch represents the third iteration of a solution to make these options behave consistently across different diff output formats.

Junio Hamano provides detailed feedback on the implementation, focusing on design and naming choices. He questions whether the new `diff_optimize` enum is overkill compared to a simple boolean `dry_run` flag, and suggests `diff_flush_patch_quietly()` would be a clearer name than the current `diff_flush_patch_quiet()`. The core concern is about the design decision to force zero context lines in dry-run mode, which lacks explanation in the commit message.

The technical approach uses a new `quick_consume()` callback that short-circuits diff processing once any change is detected, avoiding full content examination while still respecting ignore patterns. Junio notes this creates some awkwardness around error handling since the same return value is used both for early termination and actual errors.

While generally approving of the direction, Junio requests better documentation of the zero-context design choice in the commit message. The patch already has Jeff King's Reviewed-by, indicating technical approval from another core maintainer, and appears ready for integration pending these final clarifications.
