Bugfix for HEAD race conditions in reflog generation. This patch from Patrick Steinhardt's reflog migration series addresses a subtle race that could occur when generating reflog entries for HEAD while updating references it points to. The core issue is that HEAD's target wasn't properly locked during this process, potentially leading to missing or incorrect reflog entries.

The solution introduces a new `REF_LOG_VIA_SPLIT` flag that triggers additional validation after locking HEAD, ensuring it still points to the expected reference. When races are detected, the transaction is aborted - a conservative approach that prioritizes correctness over edge case handling, since these races are extremely rare in practice.

The patch modifies the files backend to properly track parent updates and validate HEAD's target, while acknowledging it can't fully prevent all possible races without unacceptable performance penalties. This builds on earlier work in the series to improve reflog handling during the files-to-reftable migration, with Jeff King having previously validated the transaction abortion approach.

The changes are focused on `refs/files-backend.c` and maintain compatibility with the series' other improvements to reflog handling. While the solution isn't perfect (it can't catch all race scenarios), it significantly improves the situation for a case that would rarely occur in normal usage.
