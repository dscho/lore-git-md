This is a documentation and code organization patch in Patrick Steinhardt's reflog migration series (v6 2/9). It restructures the presentation of `git reflog` subcommands to group them more logically, separating read-only operations from write operations and positioning the new `write` subcommand (to be introduced later) appropriately.

The changes reorganize both the man page and implementation code to:
1. Move read-only commands (`show`, `list`, `exists`) before write commands
2. Place the destructive `expire` command last in the sequence
3. Reorder option documentation sections to match the new subcommand ordering
4. Update the command usage strings in `builtin/reflog.c` to maintain consistency

The patch maintains all existing functionality while improving the logical flow, particularly in preparation for adding the new `write` subcommand in subsequent patches. The changes are mechanical and don't affect behavior, focusing purely on organization and documentation structure. This continues the series' documentation standardization effort while keeping all technical solutions from v5 intact.
