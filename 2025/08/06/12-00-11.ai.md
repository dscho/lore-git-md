This is part of the `the_repository` removal effort in the commit-graph subsystem, specifically patch 6/10 in Patrick Steinhardt's v2 series. The patch refactors how the commit-graph stores hash algorithm information, changing from storing just the hash length to storing the full hash algorithm pointer.

The technical change replaces all instances of `g->hash_len` with `g->hash_algo->rawsz` throughout commit-graph.c, while updating the struct definition in commit-graph.h to hold a `hash_algo` pointer instead of a length. This prepares for future changes that will need the full algorithm rather than just its size, continuing the series' pattern of removing implicit global state.

The patch touches core commit-graph operations including parsing, verification, and writing, updating all hash-size-dependent calculations to use the algorithm's raw size instead. While mechanical in nature, this change is foundational for the series' goal of making the commit-graph subsystem work with pluggable object storage backends by removing its dependency on `the_hash_algo` global.

The change maintains identical behavior while making the code more flexible for future extensions. It follows the established pattern seen in earlier patches of the series, where global state is replaced with explicitly passed parameters. The patch is straightforward and unlikely to be controversial given the series' prior review consensus.
