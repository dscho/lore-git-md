This is part 4/10 of Patrick Steinhardt's series to remove global state from the commit-graph subsystem, specifically addressing sign comparison warnings in commit-graph.c. The patch focuses on type consistency, converting several signed integer declarations to unsigned types where they represent inherently non-negative quantities like counts or sizes. Key changes include:

- Converting `num_commit_graphs_before` and `num_commit_graphs_after` from `int` to `uint32_t` in `struct write_commit_graph_context`
- Changing loop variables from `int` to `size_t` when iterating over unsigned counts
- Making `write_graph_chunk_base_1()` return `size_t` instead of `int` for chunk counting
- Using explicit casts for the Bloom filter hash version's sentinel value (-1)
- Fixing comparisons between signed and unsigned values with appropriate casts

The changes are mechanical but important for type safety, eliminating compiler warnings while maintaining the same behavior. This aligns with the series' broader goal of cleaning up the commit-graph implementation and follows through on prior reviewer discussions about using appropriate types for non-negative values. The patch builds on earlier work in the series that introduced unsigned integer tracing (patch 1) and converted other counters to unsigned types (patch 2).
