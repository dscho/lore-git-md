Feature addition for reftable migration: new `git reflog write` subcommand. This patch introduces a basic manual reflog entry creation capability, addressing a gap that becomes critical with the reftable backend's binary format making manual edits impractical.

The new subcommand `git reflog write <ref> <old-oid> <new-oid> <message>` provides strict validation: refs must be fully qualified, OIDs must be complete and reference existing objects, and messages get normalized. The implementation uses the existing ref transaction infrastructure, including the newly exported `ref_transaction_update_reflog()` API from earlier in the series. Test coverage verifies error cases (invalid refs, abbreviated OIDs, missing objects) and basic functionality.

Key technical constraints noted in the command's current limitations: no batch writes, no historical insertion, fixed timestamps, and strict object existence checking. The test suite (`t1421-reflog-write.sh`) reveals a known issue with incorrect old-OID recording in sequential writes that will be addressed in later patches. This foundational capability supports the broader reftable migration effort by enabling manual reflog manipulation where previously only automated operations were possible.
