Bugfix in the reflog migration infrastructure, part of Patrick Steinhardt's v6 series for files<->reftable conversion. This patch fixes an identity reconstruction issue when migrating reflog entries between storage formats. Currently, the migration incorrectly passes the full committer identity (name + email) as just the email parameter to `fmt_ident()`, resulting in malformed output like "pks <Patrick Steinhardt ps@pks.im>". 

The solution properly splits the identity line into name and email components using `split_ident_line()`, then passes them separately to `fmt_ident()`. The patch also adds new `name` and `mail` string buffers to the migration callback structures to avoid repeated allocations during processing. 

While this fixes the immediate issue, the commit message notes that test coverage will be added in a subsequent patch that tightens reflog verification in t1450. This is part of a larger effort to ensure correct reflog preservation during the files-to-reftable transition, with all technical solutions from previous versions (including HEAD race handling via transaction abortion) remaining intact. The change is well-contained and follows the series' pattern of careful type safety improvements.
