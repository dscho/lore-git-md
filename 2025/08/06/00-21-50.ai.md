This is a bugfix and refinement patch for the `git sparse-checkout clean` command, part of the ongoing sparse-checkout feature development. The patch aims to make the clean command more thorough in removing tracked-but-sparse directories while addressing edge cases from merge conflicts and staged changes.

Key technical changes:
- Uses `update_sparsity()` with `update=0` to clear SKIP_WORKTREE bits without worktree changes
- Now removes `folder1/` in addition to `deep/deeper2/` in test cases
- Updates test expectations to reflect more aggressive cleaning behavior
- Maintains staged changes in the index while removing worktree files

New edge cases identified:
- After cleaning, `git status` shows deleted files that were staged (folder1/file)
- Some Git commands (`checkout`, `add`) fail to operate on these paths while others (`reset`, `commit`) work
- `reapply` is still needed after `clean` to fully resolve some states
- Documentation gaps around these behaviors and recommended workflows

The patch appears to fix the immediate issue of merge conflict resolution without requiring `reapply`, but Elijah Newren's analysis reveals several subtle interaction cases that remain problematic. The behavior around staged changes and subsequent Git operations is particularly tricky and may need either code adjustments or clearer documentation. The test updates verify the new cleaning behavior but don't yet cover all the status/command interaction cases Newren demonstrated.
