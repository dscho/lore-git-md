This is a follow-up discussion on Patrick Steinhardt's refactoring series for the multi-pack index (MIDX) integration with object database (ODB) sources. The original patch modified ODB source creation functions to return newly created sources, which is part of the larger effort to eliminate redundant information in MIDX handling.

Toon Claes suggests an alternative implementation for the `odb_add_to_alternates_memory()` function that could avoid duplicating the path by using `"/"` as the relative base instead of calling `real_pathdup()`. The suggestion is presented as an untested idea, with Toon acknowledging the readability trade-offs between the two approaches.

The discussion is focused on implementation details of the ODB source creation mechanics, specifically around path handling in memory-based alternates. This is a minor optimization consideration in the context of the larger series, which has already received positive feedback and is nearing readiness for merging after addressing some documentation clarifications.
