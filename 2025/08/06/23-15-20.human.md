This is a documentation patch in Elijah Newren's series improving merge-ort's rename detection. It clarifies how path strings are interned in merge-ort's internal data structures to enable efficient pointer comparisons rather than string comparisons.

The patch updates comments in merge-ort.c to more accurately describe that the string interning optimization applies to all paths (both files and directories), not just directories as the original comment suggested. It also points developers to a concrete example in apply_directory_rename_modifications() where the code properly handles this optimization by reusing interned strings when available.

This change doesn't modify any behavior - it just improves the documentation for future maintainers. The patch builds on the series' broader work to make merge-ort's rename detection more robust and better documented, particularly around edge cases involving directory renames. The commit references two earlier commits that established this string interning approach, showing this is a long-standing design decision being clarified rather than a new feature.
