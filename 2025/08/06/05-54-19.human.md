This is a refactoring patch in Patrick Steinhardt's reflog migration infrastructure series, specifically addressing how the `REF_HAVE_OLD` flag is handled for log-only updates. The patch is part of a larger effort to improve reflog handling during files-to-reftable conversions.

The change stops unsetting the `REF_HAVE_OLD` flag for log-only updates, which previously was done to avoid unnecessary verification of old object IDs during reflog writes. While this verification isn't needed for the reflog entries themselves, keeping the flag set provides useful information about whether the caller provided an old object ID - information that will be used in a subsequent commit to implement new reflog writing behavior.

The patch modifies the flag handling across multiple backend implementations (files and reftable) while ensuring log-only updates still skip the old OID verification. The changes are straightforward and maintain consistency between the different backends. This appears to be a well-justified preparatory change for upcoming functionality in the series.
