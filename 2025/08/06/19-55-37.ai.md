This is a feature patch adding format options to the new `git repo info` command, part of the v8 series migrating repository metadata functionality from `git rev-parse`. The patch introduces `--format` with two output options: `keyvalue` (human-readable, default) and `nul` (machine-parsable).

The implementation follows Git's established pattern seen in commands like `git config`, using separate formatting paths for each output type. The `nul` format uses null-terminated strings for machine consumption while `keyvalue` maintains human-friendly quoting. The patch includes comprehensive tests verifying both formats work correctly with all existing repository info fields (ref format, bare status, and the newly added shallow status).

Key technical details:
- New enum `output_format` in builtin/repo.c with FORMAT_KEYVALUE/FORMAT_NUL_TERMINATED
- Modified `print_fields()` to handle both formats
- `keyvalue` uses `quote_c_style()` for proper quoting
- `nul` format prints unquoted values with newline delimiters and null terminators
- Tests cover:
  - Both formats for all field types
  - Error cases (invalid format, invalid keys)
  - Multi-key output
  - Binary comparison of nul format output
- Documentation updates show example usage of both formats
