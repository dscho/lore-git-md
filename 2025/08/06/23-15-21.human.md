Bugfix patch addressing edge cases in merge-ort's rename-to-self handling, part of a larger series improving directory rename detection. This is patch 6/7 in v3 of the series, which has already seen review and iteration.

The patch fixes three specific issues that occur when directory renames result in a file being renamed to itself (A->A). These cases were previously causing silent file deletions, incorrect file retention, and wrong index entry counts. The core fix is simple - skip the problematic rename processing when old and new paths are identical (checked via pointer comparison since paths are interned).

The patch includes:
1. A new test case (12i2) that modifies a file slightly during rename to expose silent deletion bugs
2. Updates to existing test cases (12n and 12n2) that were previously marked as failing but now pass
3. Clear documentation in the code explaining why the special case handling is needed

This builds on earlier work in the series that improved test coverage and documentation around directory rename handling. The changes are focused and well-justified, with thorough test coverage demonstrating both the bugs and their fixes. The patch maintains the series' high quality with clear commit messages and minimal, targeted code changes.
