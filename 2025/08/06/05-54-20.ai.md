This is a bugfix patch in Patrick Steinhardt's reflog migration infrastructure series, addressing incorrect old object IDs during reflog format conversion. The patch introduces a new `REF_LOG_USE_PROVIDED_OIDS` flag to properly preserve old OIDs when migrating reflogs between storage formats.

The issue occurs when migrating reflog entries - instead of using the caller-provided old OID, the code was incorrectly resolving the reference's current state (which doesn't exist in the new format yet), resulting in all-zero OIDs. The fix ensures backends use the provided OIDs when this new flag is set, which is now done in `ref_transaction_update_reflog()`.

Key technical changes include:
- New `REF_LOG_USE_PROVIDED_OIDS` flag definition in refs.h
- Flag validation in both files and reftable backends
- Updated test infrastructure using `test-tool ref-store` to verify both old and new OIDs
- Fixes to test cases that previously expected broken zero OIDs

The patch maintains the series' focus on robust reflog migration while closing this specific gap in OID preservation. It builds on previous work fixing identity reconstruction and adds explicit test coverage for both the OID and identity preservation aspects. The changes are localized to the refs backend implementations and test infrastructure, with no user-facing behavior changes beyond correct migration.
