This is part of Patrick Steinhardt's reflog migration infrastructure series (v6), specifically focusing on API exports for reftable conversion support. The patch exports the previously internal `ref_transaction_update_reflog()` function to allow other parts of Git to write reflog entries through the transaction API. The function's signature is simplified by removing the `flags` parameter since all current callers use the same set of flags (REF_HAVE_OLD|REF_HAVE_NEW|REF_LOG_ONLY|REF_FORCE_CREATE_REFLOG|REF_NO_DEREF), which are now hardcoded in the implementation.

The change includes moving the function declaration to refs.h with an updated docstring clarifying its purpose for reflog updates only, with ordering controlled by the index parameter. The implementation remains functionally equivalent but now has a fixed set of flags. This prepares for subsequent patches that will need to write reflog entries outside refs.c, particularly for the reftable migration work.

The patch maintains the series' focus on robust reflog handling during storage format transitions, with all technical solutions from previous versions preserved. Documentation follows the standardized format required by the series' lint compliance efforts, though this particular patch has minimal doc changes beyond the moved header comment.
