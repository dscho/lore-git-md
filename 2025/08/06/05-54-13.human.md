This is a documentation and code organization patch in Patrick Steinhardt's reflog migration series (v6). It reorganizes the `git reflog` subcommands in both documentation and code to follow a more logical grouping: read-only commands first (`show`, `list`, `exists`), followed by write operations affecting single reflogs (`delete`, `drop`), with the broadest write operation (`expire`) last. 

The changes are purely structural - no behavior is altered. The motivation is to improve command discoverability and prepare for adding a new `write` subcommand in a future patch. The patch touches both the man page and the builtin implementation, keeping them in sync.

This appears to be a straightforward cleanup that makes the command's organization more intuitive. The changes are mechanical but thoughtful, with the documentation updates carefully mirroring the code changes. As part of the larger reflog series that has already seen extensive review, this patch seems ready to go in.
