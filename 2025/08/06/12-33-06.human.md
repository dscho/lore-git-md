Bugfix addressing inconsistent behavior between content-ignoring diff options (`-w`, `-I`) and metadata outputs (`--name-status`, `--raw`). This is the third version of a patch that emerged from an extended technical discussion about how Git should handle these cases.

The patch introduces a new `DIFF_OPT_DRY_RUN` mode in the diff machinery that allows quick detection of whether files differ when content-ignoring options are active. The core change makes metadata outputs respect ignore rules by running a lightweight diff check before deciding whether to show the file. This aligns behavior between different output formats while maintaining performance - the dry-run mode skips expensive operations like context line generation.

The implementation adds a new `diff_flush_patch_quiet()` helper and modifies `builtin_diff()` to support the dry-run mode. Test cases verify the new behavior works correctly with both regex (`-I`) and whitespace (`-w`) ignore options. The solution represents the consensus approach from the thread discussion, moving away from earlier buffering proposals in favor of this simpler dry-run mechanism.

This appears to be a well-considered solution to a real inconsistency in Git's diff behavior. The patch has already been signed off by Jeff King (Peff), suggesting it has passed initial technical review. The changes are focused and come with appropriate test coverage, making this a solid contribution that should improve user experience when combining these diff options.
