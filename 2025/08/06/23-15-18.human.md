This is a test and bugfix patch in a series addressing directory rename detection in merge-ort. It documents and fixes two edge cases where a file is renamed to itself through transitive directory renames, which currently causes incorrect behavior.

The patch adds detailed documentation for test case 12n in t6423, which was previously missing an English description and proper index state verification. It reveals that when directory renames cause a file to be renamed to itself (world -> tools/world -> world), Git currently fails to properly handle the case where the file should be deleted due to Side B's changes.

A second test case (12n2) is added to show a related bug when directory renames are enabled (merge.directoryRenames=true). In this case, Git silently keeps the file when it should be deleted, rather than either properly deleting it or at least reporting a conflict for user review.

Both test cases are currently marked as expecting failure, with fixes planned in subsequent patches. The patch provides thorough test coverage for these edge cases, including verification of the expected number of index entries and conflict messages. This continues the series' focus on improving merge-ort's handling of complex directory rename scenarios.
