This is a documentation refinement in the ongoing terminology consistency effort for Git's manual pages, specifically addressing the `git-add` man page.

Junio Hamano responds to Jean-Noël Avila's concerns about phrasing in Julia Evans' patch regarding how commits interact with the index. The discussion centers on whether to describe Git's commit behavior as "by default" (implying alternatives exist) or as the only behavior (since commits always use index contents). Hamano clarifies there are indeed alternative commit paths via `git commit <pathspec>` that bypass some index contents, justifying the "by default" phrasing.

The exchange also considers the pedagogical balance in documentation - how much to explain about commit behavior when teaching `git-add`. Hamano suggests either keeping both the "by default" note and the reference to alternative commit methods, or removing both for simplicity, but finds the current patch's middle ground (keeping one) inconsistent.

This represents final polishing of technical accuracy in a nearly-ready documentation series, with Hamano providing maintainer perspective on both correctness and teaching approach. The discussion shows careful attention to how subtle phrasing choices might affect user understanding of Git's index model.
