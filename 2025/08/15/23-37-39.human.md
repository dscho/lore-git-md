This is a policy discussion about Windows version support in the context of the Rust dependency changes.

Junio Hamano weighs in on the ongoing debate about whether Git should continue supporting Windows versions that Microsoft no longer maintains (specifically Windows 8.1, which reached end-of-life in 2023). He notes that while Git's Platform Support Policy doesn't explicitly list supported versions, it does require active security support from vendors. 

Hamano suggests that dropping unsupported versions is reasonable as long as it's clearly documented, though he acknowledges Git for Windows (GfW) may have its own policies for maintaining older versions. He defers to GfW maintainers if they choose to support older releases, noting this wouldn't conflict with the main project's Platform Support Policy.

The email continues the unresolved tension between Junio's position (aligning with Microsoft's support lifecycle) and GfW's stance (maintaining compatibility with older Windows versions through documented deprecation timelines). This comes as the Rust integration work finalizes, where platform compatibility has been a recurring discussion point.
