This is a policy discussion thread regarding Windows version support in the context of the Rust dependency changes.

Junio Hamano clarifies his position on Windows version support, noting that while the Platform Support Policy (PSP) document doesn't explicitly list supported versions, it does require "active security support" from vendors. He acknowledges that dropping Windows 8.1 (which reached EOL in January 2023) would be reasonable under this policy, though he leaves room for exceptions if the Git for Windows (GfW) project chooses to maintain support for older versions.

The email suggests a potential compromise where the core Git project could follow Microsoft's EOL schedule while allowing GfW to maintain extended support if they document their policies clearly. This continues the ongoing debate between Junio's preference to align with vendor support cycles and the GfW maintainers' desire to maintain backward compatibility with documented deprecation timelines.

Key points:
- References the PSP document's security support requirement
- Suggests core Git and GfW could have different support policies
- Leaves the door open for GfW to maintain older Windows versions if properly documented
- Does not resolve the fundamental disagreement about version support policy
