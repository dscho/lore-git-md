This is a follow-up in the merged documentation improvement series for `git-rebase`, specifically addressing the placement of performance details in the man page.

Julia Evans agrees with Junio Hamano's suggestion to simplify and combine the description of cherry-pick detection steps in the rebase documentation. The discussion had previously established that while cherry-pick detection (which can be slow with many upstream commits) is technically part of `git log`, this implementation detail may not belong in the high-level "how it works" section. 

The thread had already reached consensus that performance characteristics like those motivating the `--reapply-cherry-picks` option (added in commit 0fcb4f6b62) should be documented with the option itself rather than in the conceptual overview. Julia confirms she'll implement this simplification, wrapping up one of the last open points in this documentation refinement effort.
