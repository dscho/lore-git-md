This is a documentation patch establishing Git's Rust adoption policy, serving as the foundational document for the larger Rust integration effort. It's the first patch in a 17-part series proposing Rust as a hard dependency with xdiff optimizations.

The document provides a comprehensive rationale for introducing Rust, citing memory safety concerns (noting that 70% of vulnerabilities in non-memory-safe languages are memory-related), developer ergonomics, and alignment with industry trends (including government recommendations against memory-unsafe languages). It outlines goals like maintaining cross-platform support while incrementally transitioning to Rust, and explicitly states non-goals like maintaining parallel C implementations.

Key technical decisions include:
- Using `bindgen`/`cbindgen` for FFI and preferring `rustix` over raw `libc`
- Version policy tied to Debian stable (providing ~3 years of support per version)
- Exclusion of `Cargo.lock` from version control (already consensus in the thread)
- Support for alternative compilers like gccrs when stable

The policy balances Rust's rapid release cycle with Git's need for stability, while acknowledging platform support constraints discussed elsewhere in the thread. It serves as a reference point for subsequent technical decisions in the Rust integration effort, particularly around version compatibility and dependency management that have been contentious in the discussion.
