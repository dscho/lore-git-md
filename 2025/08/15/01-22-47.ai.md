This is a CI/build system patch in the ongoing Rust integration series, specifically addressing GitHub Actions workflow consolidation for Rust toolchain management.

The changes centralize Rust version and target definitions in the main GitHub Actions workflow file (main.yaml), moving them from scattered script locations into a single configuration point. Key technical details include:
- Platform-specific Rust version requirements (Windows 1.78.0 for bcrypt fixes, musl 1.72.0 for libc compatibility)
- Target triple overrides (x86_64-pc-windows-gnu for Windows, i686-unknown-linux-gnu for 32-bit containers)
- Removal of now-redundant BITNESS detection in ci/lib.sh
- Cleanup of Rust installation scripts (install-rust.sh) to handle only docker-specific cases
- CARGO_HOME path standardization across all environments

The patch demonstrates careful attention to cross-platform consistency, with clear rationale for each version constraint in the commit message. It builds on prior work in the series by ensuring the CI system properly supports the Rust toolchain requirements established in earlier patches (like Windows system library handling from patch 9/17). The changes appear well-tested, with fallback paths maintained for docker environments where the standard actions-rs/toolchain approach doesn't work.
