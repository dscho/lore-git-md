This is part 2/6 of Patrick Steinhardt's series to remove global state dependencies from the commit-graph subsystem, specifically targeting the `the_repository` removal effort. The patch refactors how hash algorithms are handled in the commit-graph code. Previously, the code stored only the hash length (as `hash_len`), but now it stores the full hash algorithm pointer (as `hash_algo`). This mechanical change updates all related calculations to use `hash_algo->rawsz` instead of the previous `hash_len` field.

The changes are widespread but straightforward, touching nearly all commit-graph operations that deal with hash sizes - from parsing and verification to commit data access. The patch maintains all existing functionality while preparing for future changes that will need the full algorithm context. This is a foundational step for the series' goal of making commit-graph operations repository-agnostic.

Key technical details:
- Replaces `hash_len` field with `hash_algo` pointer in `struct commit_graph`
- Updates 20+ calculations to use `hash_algo->rawsz` instead of `hash_len`
- Affects core operations like OID lookup, commit data access, and graph verification
- Maintains special handling for cross-repository cases
- All callers in commit-graph.c are updated
- The change is purely mechanical with no behavior modifications

This patch follows naturally from the series' architectural direction and appears well-executed, with comprehensive updates to all affected code paths. It sets up the infrastructure needed for subsequent patches to fully remove `the_repository` dependencies.
