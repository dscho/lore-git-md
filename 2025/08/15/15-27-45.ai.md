Feature proposal for SHA-1/SHA-256 interoperability storage format.

Derrick Stolee enters the ongoing discussion about bidirectional hash mapping storage with a concrete proposal for a new file format. He expresses skepticism about repurposing pack index v3 for this purpose, arguing it's not well-suited for mappings beyond local repository objects. His key requirements are efficient bidirectional lookups (O(log N) time) and efficient incremental updates (~O(new) time).

Stolee advocates for a reftable-like format with these characteristics:
- Header containing version info, hash types, OID count, and offsets to lookup tables
- Two lex-ordered tables (Hash1 and Hash2) with positional cross-references
- Multi-layer structure allowing incremental updates with periodic compaction
- Estimated performance: O(L * log N) lookups (L = layer count) with efficient writes via new layers

The proposal differs from previous discussions by:
- Rejecting pack index extensions in favor of dedicated format
- Suggesting simpler structure than full reftable implementation
- Explicitly separating the bidirectional mapping tables
- Allowing for future format extensions

Technical considerations noted:
- Tradeoff between lookup speed and write efficiency
- Need for background compaction of layers
- Potential complexity not captured in initial sketch

This moves the thread forward by providing a concrete alternative to the pack-index-extension approach, while aligning with the emerging consensus around physical storage separation. The proposal appears technically sound but leaves implementation details open, particularly around compaction strategy and exact on-disk representation.
