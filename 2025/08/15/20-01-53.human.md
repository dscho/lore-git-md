This is a documentation discussion thread about improving Git's teaching approach for new users, specifically regarding the index/staging area concept.

Junio Hamano responds to D. Ben Knoble's comment about fixing old documentation mistakes, clarifying that his philosophy is about avoiding new mistakes rather than necessarily fixing old ones. The core of the email is a thoughtful reflection on how Git's documentation needs to evolve for today's users.

Junio notes that early Git documentation focused on contrasting Git with older SCM systems (like BitKeeper), since many users needed help understanding Git's distributed nature and features like private history rewriting. However, with most current users having no experience with those older systems, these comparisons may no longer be the most effective teaching tools.

The discussion is part of Julia Evans' ongoing documentation improvement series (now at v2) that aims to make concepts like the index more accessible to beginners while maintaining technical accuracy. Junio's comments reinforce the need to adapt documentation to the current user base's knowledge while being careful not to oversimplify core concepts.

This email doesn't propose specific documentation changes but provides important historical context and maintainer perspective that will help guide future documentation efforts, particularly around explaining Git's fundamental concepts to modern users.
