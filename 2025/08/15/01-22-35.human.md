This is a cover letter for version 2 of a major RFC series proposing to make Rust a hard dependency while optimizing xdiff performance. The series now includes 17 patches (up from 7 in v1) with several key improvements:

1. **Cross-platform support**: Now builds and passes tests on all platforms, thanks to Windows-specific fixes from Johannes Schindelin and 32-bit Linux support.

2. **Documentation**: Adds a new Rust usage policy document from Brian Carlson as the first patch, establishing guidelines for Rust adoption.

3. **Dependency management**: Removes `Cargo.lock` from version control (addressing supply chain concerns) while preserving it as a CI artifact for auditing.

4. **Whitespace handling**: Implements slower whitespace flag support as requested by Junio Hamano, though this comes with performance tradeoffs (faster for no flags/`--ignore-cr-at-eol`, slower for other whitespace combinations).

The cover letter highlights several open questions for discussion:
- Rust code style (suggesting `rustfmt` defaults)
- Version consistency across platforms (32-bit/Windows require newer Rust)
- Performance tradeoffs of whitespace handling
- Ongoing type system discussions with Phillip Wood about FFI boundaries

Performance claims remain at 5-19% speedups from xxhash adoption and structural changes, though whitespace modes now show mixed results. The series represents a significant step toward Rust integration while acknowledging this is just the beginning of xdiff's potential rustification.

Notable changes from v1 include expanded CI support, Windows compatibility fixes, and addressing initial feedback about dependency management. The author invites review of the type system discussions and performance implications while acknowledging some feedback from v1 may still need addressing.
