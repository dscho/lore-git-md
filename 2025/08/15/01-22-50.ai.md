This is part 15/17 of the RFC series introducing Rust as a hard dependency with xdiff optimizations. The patch introduces two core functions for line comparison in the Rust xdiff implementation: `line_hash()` and `line_equal()`. 

The functions leverage the `WhitespaceIter` struct introduced in earlier patches to handle whitespace-aware comparisons when the `XDF_WHITESPACE_FLAGS` are set. The `line_hash()` function uses XXH3 hashing (via the `Xxh3Default` hasher) for both regular and whitespace-filtered content, while `line_equal()` performs direct byte comparison or whitespace-filtered comparison using the `chunked_iter_equal` utility. 

The implementation maintains the zero-copy FFI approach seen throughout the series, with unsafe extern C bindings (`xdl_line_hash` and `xdl_line_equal`) that convert raw pointers to Rust slices before processing. The patch continues the pattern of type alignment (u8/u64) for cross-language compatibility.

This appears to be a straightforward technical implementation building on prior work in the series, though it lacks performance measurements for the new whitespace-aware operations. The changes are focused on the Rust side of the xdiff implementation and don't yet address the open questions about XXH3 non-SIMD performance or the broader type consistency debates noted in the thread summary.
