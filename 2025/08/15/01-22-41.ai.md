This is a refactoring patch in the Rust integration series, specifically targeting xdiff's line processing internals. It separates line parsing from hashing to facilitate the planned switch to xxhash and simplify the code structure.

The patch introduces a new `xdl_parse_lines()` function that handles the line-by-line parsing of input files, storing raw line data in `xdf->recs` with zeroed`ha` fields. The hashing step is then performed in a separate loop in `xdl_prepare_ctx()`, calling `xdl_hash_record()` on each pre-parsed line. This structural change makes the code more modular and prepares for swapping hash algorithms independently of line parsing.

Key technical changes include:
- New `xdl_parse_lines()` function taking over memory allocation and line boundary detection from `xdl_prepare_ctx()`
- Conversion of pointer arithmetic to use Rust-compatible `usize` types
- Simplified error handling by moving allocations before the parsing loop
- Cleaner separation of concerns between parsing and line classification

The change maintains all existing behavior while enabling future hash algorithm changes. It follows the series' pattern of incremental, verifiable refactoring steps before introducing Rust code. The patch touches core xdiff preparation logic but doesn't yet incorporate Rust - it's purely a C-side restructuring to make the FFI boundary cleaner when Rust hash implementations are added later.
