This is a documentation patch series for the git-rebase man page, representing the eighth iteration of Julia Evans' work to improve the command's documentation. The series has already been through extensive review and refinement, with several technical aspects (like commit selection mechanics and performance details) already resolved in previous rounds.

The v8 series focuses on final polishing of the rebase internals description, specifically combining what were previously two separate steps (commit enumeration and cherry-pick detection) into a single, clearer step. The changes result in a more concise explanation of how rebase selects commits to replay, while maintaining all the technical accuracy established through earlier discussion.

The patch series includes five changes that were already accepted in previous versions (now being carried forward unchanged) plus the refined internals description in patch 5. The documentation improvements include better examples, deduplicated conflict resolution explanations, clearer argument syntax, and better organization of the --onto option details.

This represents the culmination of a long-running effort that has involved input from multiple core Git contributors, with the documentation now reflecting both conceptual clarity and implementation realities. The changes are purely explanatory - they don't affect how rebase actually works, just how it's described to users.
