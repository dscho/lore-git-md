Performance optimization for sparse index handling in `git ls-files`.

Derrick Stolee contributes a patch that improves `git ls-files` performance when working with sparse checkouts. The change makes the index expansion conditional rather than always expanding it when `--sparse` isn't used. 

Previously, `ls-files` would always expand the index when not using `--sparse`, even when the pathspec wouldn't match any sparse directories. The new version only expands the index if it encounters a sparse directory that matches the pathspec, which avoids unnecessary work in common cases. The patch includes tests verifying the behavior change in t1092.

This appears to be a well-motivated optimization that maintains correctness while improving performance for a common case. The change is relatively small and focused, with clear test coverage. It continues the ongoing work to optimize Git's behavior with sparse checkouts.
