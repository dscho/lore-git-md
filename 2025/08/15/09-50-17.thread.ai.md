Thread identity: Bug report about branch deletion behavior on case-insensitive filesystems (macOS), reported by Richard Carlsson. Now includes solution path via reftable backend.

Core problem: Git incorrectly allows deletion of a branch when given a case variant of the current branch name on case-insensitive filesystems (e.g., deleting "Dummy" when on "dummy"), leaving the user in a broken state. This is an unfixable limitation of the traditional files backend due to filesystem behavior.

Current status: Patrick Steinhardt confirms the files backend cannot be fixed for this case and endorses reftable as the solution. Provides migration instructions: `git init --ref-format=reftable` for new repos or `git refs migrate --ref-format=reftable` for existing ones. Requires Git 2.45+.

Key technical details:
- Files backend's case-sensitivity behavior is platform-dependent (macOS vs Linux)
- Reftable backend avoids issue by not using filesystem for ref storage
- Migration commands available but require recent Git version
- Libgit2 support exists but third-party tools may lag
- No viable path to fix files backend's fundamental limitation
