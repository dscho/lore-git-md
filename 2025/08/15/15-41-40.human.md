This is a response to a bug report about case-sensitivity issues with branch deletion on macOS. Junio Hamano suggests an interesting workaround: using the reftable backend instead of the traditional filesystem-based ref storage, since reftable doesn't suffer from the same case-sensitivity issues.

The original bug report showed that on macOS (with case-insensitive filesystems), Git incorrectly allows deleting a branch when given a case variant of the current branch name (e.g., deleting "Dummy" when on "dummy"), leaving the user in a broken state. On Linux (case-sensitive), Git properly prevents this.

Hamano's suggestion to use reftable is notable because it represents a different approach than fixing the filesystem-based behavior - it would avoid the problem entirely by changing the underlying storage mechanism. This hints that the issue might be deeper than just the branch deletion logic, tied to fundamental filesystem behavior differences.

The response doesn't propose a direct fix for the current behavior, but offers an interesting architectural perspective. This could spark discussion about whether to: 1) fix the immediate bug in the filesystem backend, 2) encourage reftable adoption, or 3) both. The suggestion comes from Git's maintainer, so it carries significant weight regarding future directions.
