This is a discussion about Windows platform support in the context of the Rust xdiff optimization series. Johannes Schindelin responds to Junio Hamano's comments about Windows version requirements, specifically addressing Matthias Aßhauer's earlier concerns about maintaining Windows 8.1 compatibility.

The key points:
- Johannes confirms Matthias's technical assessment that using `*-pc-windows-gnu` targets would drop Windows 8.1 support, while `*-win7-windows-gnu` would maintain it
- He emphasizes the Git for Windows project's consensus to support older Windows versions as long as reasonably possible, with documented deprecation timelines
- The current policy (documented at gitforwindows.org) supports Windows 8.1, following the same deprecation process used for Windows 7/8
- Johannes pushes back against Junio's suggestion to automatically drop support for OS versions Microsoft no longer supports, advocating for a more nuanced approach

This continues the thread's ongoing debate about platform support tradeoffs, particularly around Windows version requirements in the Rust transition. The discussion remains unresolved but clarifies the Git for Windows maintainers' position on maintaining backward compatibility with clear deprecation processes.
