Performance optimization for sparse index handling in `git ls-files` (builtin/ls-files.c). The patch series builds on sparse index infrastructure (commit 78087097b8) to modify sparse index expansion, triggering only when encountering a sparse directory that matches the pathspec rather than doing full expansion upfront. This avoids unnecessary index operations when pathspecs match directories covered by sparse-checkout patterns.

Key technical changes move `ensure_full_index()` inside the file iteration loop, activating only for sparse directory entries (without `--sparse`). Test coverage in t1092 verifies correctness for pathspecs hitting sparse directories mid-iteration and pathspecs filtering to sparse directories. Derrick Stolee originally proposed this as a small but meaningful optimization addressing a user-reported performance case.

Elijah Newren provided review feedback clarifying that the performance benefit comes from `prune_index()` filtering index entries by pathspec prefix before iteration begins, not just for single pathspecs. He suggested updating the commit message to explicitly mention `prune_index()`'s role in reducing the working set before sparse directory checks. The discussion confirmed the patch's safety - expanding the index mid-iteration is valid as earlier entries remain stable, verified by the test case (`ls-files deep/deeper1`) demonstrating unnecessary expansion is avoided when pathspecs match sparse-checkout patterns.

Junio Hamano's review focuses on verifying three key assumptions about index ordering during sparse directory handling: (1) index entries remain sorted throughout, (2) expanding a sparse directory won't cause its contents to sort before their original position, and (3) no need to restart iteration since only the current entry is processed. He confirms these are reasonable given Git's index sorting behavior while noting past experiences with edge cases. This maintainer-level verification adds confidence in the patch's safety regarding index invariants without requesting changes.

Implementation details:
- Moves `ensure_full_index()` inside iteration loop in `builtin/ls-files.c`
- Only expands for sparse directories (`S_ISSPARSEDIR`) without `--sparse`
- Maintains existing behavior while optimizing common cases
- Preserves index sorting invariants during mid-iteration expansion
