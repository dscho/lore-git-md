This is a documentation patch series for the git-rebase man page, representing the 8th iteration of Julia Evans' work to clarify the DESCRIPTION section. The series has already been through extensive discussion and refinement, with consensus reached on most technical points.

The v8 series focuses on finalizing the simplified description of rebase internals, specifically combining the first two steps of the rebase process (commit enumeration and cherry-pick detection) into a single step as suggested by Junio Hamano. The key change in this version is in patch 5, which now describes the commit selection as "all commits...that do not have an equivalent commit in <upstream>" rather than separating the enumeration and filtering steps.

The series maintains all previous improvements from v7, including:
- Starting with a practical example comparing rebase vs merge
- Deduplicating merge conflict explanations
- Clarifying argument syntax
- Moving the --onto explanation to a more logical location
- Updating the internals discussion with the new combined step approach

The changes are purely documentation-focused, with no code modifications. The man page restructuring removes 32 net lines while improving clarity, particularly around the rebase operation's conceptual model. This version appears to incorporate all feedback from the extensive discussion thread, suggesting it's likely in its final form before merging.
