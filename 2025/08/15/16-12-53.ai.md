Performance optimization for sparse index handling in `git ls-files`. This patch modifies the sparse index expansion behavior in `ls-files` to only expand the index when encountering a sparse directory that matches the pathspec, rather than doing a full expansion upfront. The change is motivated by cases where pathspecs match directories already covered by sparse-checkout patterns, making the full expansion unnecessary.

The key technical change moves the `ensure_full_index()` call inside the file iteration loop, triggered only when a sparse directory entry is found (and `--sparse` isn't specified). The patch includes tests in t1092 that verify the new behavior maintains correctness while avoiding unnecessary index operations. The test cases specifically check pathspec filtering that hits sparse directories mid-iteration and pathspecs that filter to only sparse directories.
