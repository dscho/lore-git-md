This is a security-focused follow-up in the now-closed thread about `git stash` aliases. Randall Becker reinforces the maintainers' position with an additional security argument against allowing command shadowing via aliases.

The email strongly supports the earlier maintainer consensus that Git should never allow aliases to override built-in commands, framing it as a potential security vulnerability. Becker suggests that allowing such shadowing could enable man-in-the-middle attacks (e.g., maliciously redefining `git clone`), and warns that any implementation would likely be considered a high-severity CVE.

This adds security weight to the previously stated technical reasons (infinite recursion prevention and script reliability) for Git's current behavior. The email doesn't introduce new technical details but provides a security practitioner's perspective on why the design decision is correct. The thread remains fully resolved with this being the final word - a security-conscious endorsement of the status quo.
