This is a technical proposal in the ongoing SHA-1/SHA-256 interoperability discussion, specifically about the storage format for bidirectional object ID mappings. Derrick Stolee weighs in with concerns about the current approach of repurposing pack index formats and suggests an alternative reftable-like design.

Stolee expresses skepticism about using pack index v3 for storing mappings, particularly for objects that aren't in packs. He outlines three key requirements for the storage format: efficient bidirectional lookups (O(log N) time) and efficient insertion of new mappings (~O(new) time).

The email proposes a new file format inspired by reftable, with separate lex-ordered tables for SHA-1 and SHA-256 OIDs linked by integer IDs. The design includes versioning, hash algorithm identification, and forward/backward lookup tables. Stolee acknowledges this would require creating a new format but argues it would be simpler than adapting existing formats and could better handle future needs.

This appears to align with the thread's emerging consensus around separating static mappings from dynamic data, though Stolee's proposal doesn't explicitly make that distinction. The suggestion seems technically sound and comes from an experienced contributor, though it would require significant implementation work. The email positions itself as exploratory rather than prescriptive, inviting further discussion of the tradeoffs.
