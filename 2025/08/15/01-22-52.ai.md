This is the final patch (17/17) in a performance-focused series introducing Rust as a hard dependency for Git, specifically targeting xdiff whitespace processing optimizations. The patch completes the transition by fully replacing the C implementations of `xdl_hash_record()` and `xdl_recmatch()` with their Rust counterparts `xdl_line_hash()` and `xdl_line_equal()`, deleting 158 lines of legacy C code while maintaining all existing functionality.

Key technical changes include:
- Removal of the standalone `xxh3_64()` FFI function now that all hashing goes through the unified `xdl_line_hash()` path
- Type consistency enforcement with `u8 const*` pointers and `char const*` conversions eliminated
- Direct calls to Rust implementations from xdiff's core preparation and merge logic
- Preservation of all whitespace handling flags (`XDF_IGNORE_WHITESPACE`, `XDF_IGNORE_CR_AT_EOL` etc.) through the Rust boundary

The patch demonstrates the series' zero-copy FFI approach in its final form, with the Rust code now handling all line comparison and hashing operations that were previously split between C's `xutils.c` and the Rust bridge. This completes the architectural shift where Rust manages the performance-critical diff operations while the C layer focuses on coordination.

Open questions from earlier in the thread about XXH3 hashing performance and whitespace flag optimizations remain relevant but are now implementation details of the Rust code rather than interface concerns. The deletion of `xdl_hash_record_with_whitespace()`'s complex flag-specific logic suggests the new implementation handles these cases through different internal mechanisms.

As the series conclusion, this patch leaves the project with a cleaner xdiff architecture but also permanent Rust dependencies that future contributors will need to consider. The performance gains (5-19% claimed in earlier patches) now apply across all diff operations rather than just specific code paths.
