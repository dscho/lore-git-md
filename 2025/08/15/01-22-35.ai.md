This is a feature and performance patch series (v2) introducing Rust as a hard dependency while optimizing xdiff, now with platform fixes and whitespace handling. The 17-part series builds on previous discussion about Rust adoption in Git, addressing several key concerns from the initial RFC.

The series now passes all platform tests after incorporating Windows and 32-bit fixes from Johannes Schindelin. It removes `Cargo.lock` from version control (per prior consensus) while preserving dependency auditing via CI artifacts. The core xdiff optimizations remain - switching from DJB2a to xxhash (5-19% speedups) and separating line parsing from hashing - but now include whitespace flag handling that was previously omitted due to performance concerns.

Key technical changes in v2 include:
- New Rust support policy documentation from Brian Carlson
- Windows/MSVC compatibility patches
- Whitespace iterator implementation in Rust
- Optimized `--ignore-cr-at-eol` path
- Type alignment between C and Rust (u64 for xdlclass_t::ha)
- CI workflow updates for Rust version management

Open questions highlighted for feedback:
1. Rust code style adoption (rustfmt?)
2. Platform-specific Rust requirements (newer versions for 32-bit/Windows)
3. Performance tradeoffs with whitespace flags (slower except for default cases)
4. Type translation approaches between C and Rust
5. Any missed feedback from v1

The series demonstrates concrete FFI patterns while continuing the broader discussion about Rust integration tradeoffs - particularly around type alignment versus conversion costs, whitespace handling performance, and platform support constraints. Performance measurements now show xxhash's limitations with whitespace modes versus DJB2a's byte-by-byte processing.
