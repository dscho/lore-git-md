This is a platform compatibility discussion in the context of the Rust xdiff optimization series, specifically addressing Windows build requirements.

Junio Hamano responds to Matthias Aßhauer's concern about Windows version support in the Rust transition. The key issue revolves around the `x86_64-pc-windows-gnu` target potentially raising Git's minimum Windows requirement from 8.1 to 10. Matthias had previously noted this in an earlier review, suggesting `*-win7-windows-gnu` targets would maintain 8.1 compatibility.

Junio takes a pragmatic stance, arguing that Git shouldn't maintain support for operating systems Microsoft no longer supports. He notes Windows 8.1 reached end-of-life in January 2023, with Windows 10's end-of-life approaching in late 2025. While acknowledging his own lack of Windows expertise, Junio suggests clearly documenting any platform support changes would be sufficient, implying he's not opposed to dropping Windows 8.1 support.

The exchange highlights an ongoing tension in the series between technical modernization and backward compatibility, particularly for platforms where Microsoft's own support policies create versioning constraints. This follows earlier platform-specific discussions in the series regarding Cygwin builds and ARM64 Windows support. The thread shows maintainers weighing Rust's technical benefits against real-world deployment constraints, with Junio favoring alignment with vendor support lifecycles.
