This is a maintainer discussion thread about Git's alias behavior, specifically regarding the security and usability implications of allowing aliases to shadow built-in commands like `git stash`.

Junio C Hamano responds to Elijah Newren's points about command shadowing, agreeing that the current behavior (preventing aliases from overriding built-in commands) is correct. He acknowledges the potential for infinite recursion with shell function aliases, demonstrating how the current implementation fails to catch all cases. While recognizing the theoretical problems, he notes there's no obvious foolproof fix for recursive shell aliases.

The discussion touches on broader implications for script writers and helpers who rely on consistent command behavior. Hamano wryly observes that script authors using porcelain commands are "beyond salvation" anyway, given Git's many configuration options that already alter behavior. The exchange reinforces the maintainers' position that preventing command aliasing is the right design choice, though it leaves some edge cases unaddressed.

This email serves as a capstone to the thread, with both maintainers in agreement about the core design decision while acknowledging some imperfect implementation details. No new technical questions remain open.
