This thread discusses a bug where Git allows deletion of a branch when given a case variant of the current branch name on case-insensitive filesystems like macOS (e.g., deleting "Dummy" while on "dummy"), leaving the user in a broken state. Richard Carlsson reported the issue with clear reproduction steps showing the divergent behavior between macOS (allows deletion) and Linux (correctly prevents it).

Junio Hamano has now responded, suggesting the reftable backend as a potential workaround since it stores references differently than the traditional filesystem-based approach. The reftable backend avoids case-sensitivity issues by not using individual files for each reference, which could provide more consistent behavior across platforms. While this doesn't directly fix the current filesystem-based implementation, it points toward a longer-term solution. The discussion may now turn to whether to pursue wider reftable adoption or to address the case-sensitivity handling in the traditional backend. The core issue remains open with no patches proposed.
