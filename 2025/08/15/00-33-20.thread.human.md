This thread explores an edge case in Git's alias system where shell function aliases work for most commands but fail when named "stash". The original reporter, Christoph Anton Mitterer, demonstrates that while they can create working shell function aliases for other Git commands using the `!c(){}; c` syntax, an alias named "stash" doesn't behave as expected - specifically when trying to make `git stash` with no arguments act like `git stash list`.

The discussion reveals technical questions about how Git executes shell function aliases, including concerns about the shell environment (IFS handling), function namespace pollution, and environment sanitization. This appears to touch on a potential bug in Git's alias handling for built-in commands or possibly an undocumented restriction. The thread may need input from Git maintainers to clarify whether this behavior is intentional and what constraints exist around alias execution.
