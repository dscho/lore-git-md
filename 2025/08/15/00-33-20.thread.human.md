Christoph Anton Mitterer raised an interesting question about why shell function aliases in Git work for most commands but fail when named "stash". Multiple maintainers, including Junio Hamano and Elijah Newren, provided authoritative explanations that this is intentional - Git prevents aliases from shadowing built-in commands like `stash` to avoid infinite recursion and maintain script reliability. They pointed to existing documentation that covers both shell function syntax and this shadowing prevention mechanism, which has been part of Git's design since 2009.

Randall Becker has now reinforced this position from a security perspective, warning that allowing command shadowing could enable man-in-the-middle attacks (like maliciously redefining `git clone`) and would warrant a high-severity CVE if introduced. His input adds security weight to the maintainers' existing technical and design rationale, effectively closing any remaining conceptual space for debate. The thread is now fully resolved with clear consensus that the behavior is correct, well-documented, and important for both reliability and security.
