This is a documentation refinement discussion in Julia Evans' ongoing series to improve Git's terminology consistency, specifically focusing on the `git-add` man page.

Jean-Noël Avila responds to Junio Hamano's review of the patch series, agreeing with the need for more precise language about how `git add` works. He emphasizes that Git fundamentally operates on snapshots rather than changes, and suggests the documentation should reflect this by describing `git add` as capturing the current working tree state (including removals) rather than just "adding" changes.

Key points in the response:
- Strongly advocates for describing Git operations in terms of state snapshots rather than changes
- Agrees with Junio's suggestion to clarify that `git add` handles removals as well as additions
- Questions the phrasing about `git commit` behavior, noting the index is always the source for commits (not just "by default")
- Supports moving the reference to alternative commit methods to a more logical location

This continues the thread's theme of refining documentation to be both technically precise and pedagogically clear, with particular attention to the snapshot model that underlies Git's design. The discussion appears to be converging on final wording that will accurately represent Git's behavior while remaining accessible to beginners.
