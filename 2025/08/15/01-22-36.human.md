This is a documentation patch introducing Git's Rust adoption policy, serving as the foundational document for the larger Rust integration effort. It's the first patch in a 17-part series proposing Rust as a hard dependency with xdiff optimizations.

The document makes the case for Rust adoption by highlighting C's memory safety issues (citing Android's vulnerability reduction and US government security recommendations) and Rust's ergonomic advantages. It outlines goals like maintaining broad platform support while incrementally transitioning, and explicitly states non-goals like maintaining parallel C implementations. The policy mandates Rust support as part of Git's platform requirements, aligning version support with Debian stable's Rust compiler to ensure multi-year compatibility.

Key technical decisions include using `bindgen`/`cbindgen` for FFI, preferring `rustix` over raw `libc`, and excluding `Cargo.lock` from version control (a point already settled in thread discussion). The document reflects consensus from the Berlin Git Merge Contributor Summit and carries sign-offs from both the primary author and a core contributor (Ezekiel Newren), suggesting early buy-in from key stakeholders.

As the series' foundational policy piece, this appears well-considered and thorough, addressing both technical and community concerns. The timing is strategic - establishing policy before implementation patches - and the content seems designed to preempt common objections around platform support and maintenance burdens. The only notable absence is any discussion of code style guidelines, which the thread summary indicates remains an open question.
