This is the final patch (5/5) in the v10 series implementing the new `git repo info` command, focusing on output format options. The patch adds a `--format` flag with two output modes: `keyvalue` (human-readable, default) and `nul` (machine-readable). The implementation follows patterns established in `git-config`, with careful attention to quoting behavior differences between formats.

Key technical details:
- Adds `enum output_format` with `FORMAT_KEYVALUE` and `FORMAT_NUL_TERMINATED` values
- Implements format parsing via `parse_options()`
- Modifies `print_fields()` to handle both formats:
  - `keyvalue`: quoted key=value pairs (using `core.quotePath` rules)
  - `nul`: unquoted key\nvalue\0 pairs
- Documents both formats and adds examples
- Extends tests to verify both formats work correctly
- Adds error handling for invalid format requests
- Files modified: `builtin/repo.c`, `Documentation/git-repo.adoc`, `t/t1900-repo.sh`

The patch maintains the series' design principles of input order preservation and duplicate key support while adding this new capability. Testing is thorough, covering both happy paths and error cases. The implementation has been reviewed and helped by multiple contributors including Phillip Wood and Junio Hamano.

This completes the core functionality of the `git repo info` command as proposed in the GSoC project, with all architectural decisions from earlier in the series now fully realized in the codebase.
