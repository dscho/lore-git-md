This is part 5/17 of the ongoing RFC series proposing Rust integration with Git, specifically focusing on making xdiff internals compatible with Rust FFI (Foreign Function Interface). The patch modifies core xdiff data types to align with Rust primitives, changing `xrecord_t` fields from C types (`char*`, `long`, `unsigned long`) to Rust-compatible types (`u8*`, `usize`, `u64`). This enables safer zero-copy interoperability between C and Rust code by ensuring type sizes match exactly across language boundaries.

The changes are mechanical but widespread, touching nearly every xdiff file to add casts where needed (particularly for string pointers now typed as `u8 const*`). A notable fix aligns `xdlclass_t::ha` with `xrecord_t::ha` as u64, addressing a potential 32-bit overflow issue spotted by Johannes Schindelin. While introducing casts is normally undesirable, here they serve as temporary markers for future Rust-side safety wrappers.

This continues the series' strategy of incremental, verifiable changes to xdiff internals before introducing Rust code. The patch maintains all existing behavior while laying groundwork for efficient FFI - a tradeoff between immediate code cleanliness and future interoperability benefits that has sparked debate about whether type alignment is truly necessary versus handling conversions in Rust wrappers. Performance implications appear neutral since this is purely type system work, though it may affect later optimizations.
