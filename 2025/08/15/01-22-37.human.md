This is the foundational infrastructure patch in a series introducing Rust to Git's xdiff implementation. It sets up the build system integration and type definitions needed for future Rust work.

The patch adds Rust build support to both Makefile and meson.build, creating a new workspace with two empty crates (`xdiff` and `interop`). It also adds Rust primitive type definitions to git-compat-util.h to facilitate C/Rust interop. The build system is configured to build Rust code via cargo while linking the resulting static library into Git's main build.

Notably, this is patch 2/17 in a series that aims to accelerate xdiff through Rust optimizations (with claimed 5-19% performance gains in earlier discussion). The patch itself is mostly scaffolding - the actual Rust implementations will come in later patches. It follows the project's emerging Rust adoption policy established in patch 1 (not shown here), which includes using `bindgen`/`cbindgen` for FFI and tying Rust version support to Debian stable.

The changes are straightforward build system additions, though they represent a significant architectural shift by introducing Rust as a build dependency. The patch appears well-structured, with clean separation between the build integration and empty module stubs. The type definitions in git-compat-util.h will be important for later FFI work, though there's already some discussion in the wider thread about whether this type alignment is strictly necessary.
