This is a follow-up in the thread about `git stash` alias behavior, where Elijah Newren reinforces the maintainer position that command shadowing via aliases is intentionally prevented.

Elijah firmly states there will never be an override mechanism for aliases that shadow built-in commands like `git stash`, linking to a 2009 email that established this design principle. He explains that such aliases would both hide the original command and could create infinite recursion (since `git stash` would call itself). The thread has now clearly established this as non-negotiable Git behavior.

When the original poster questions whether the documentation sufficiently explains shell command aliases, Elijah quotes the relevant `git-config` documentation verbatim and asks what part the user finds unclear. This suggests the documentation is perceived as complete by maintainers, though the user may still want more implementation details.

The exchange shows the Git project's strong commitment to not allowing command shadowing, prioritizing script stability over alias flexibility. While the technical question is settled, there remains a mild tension between the project's design philosophy and some users' desire for more override capabilities.
