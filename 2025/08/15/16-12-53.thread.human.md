This thread discusses a performance optimization for `git ls-files` when working with sparse indexes. The core idea is to make sparse index expansion more efficient by only triggering it when encountering a sparse directory that matches the given pathspec, rather than doing a full index expansion upfront. This avoids unnecessary work when pathspecs match directories already covered by sparse-checkout patterns.

The technical implementation moves the `ensure_full_index()` call inside the file iteration loop, activating it only for sparse directory entries (when not using `--sparse`). Test coverage in t1092 verifies correct behavior for two key cases: pathspecs that hit sparse directories mid-iteration, and pathspecs that filter directly to sparse directories. The change builds on prior sparse index work (commit 78087097b8).
