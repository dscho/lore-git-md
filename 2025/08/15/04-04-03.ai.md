This is a follow-up in the resolved thread about `git stash` alias behavior, where Elijah Newren reinforces the maintainer position against allowing command shadowing via aliases.

The email responds to Christoph Anton Mitterer's question about potential workarounds for Git's intentional prevention of built-in command shadowing through aliases. Newren firmly states there will never be an override mechanism for this behavior, citing a 2009 email from Junio Hamano that established this design principle. He explains that allowing such aliases would create problems including potential infinite recursion (when an alias calls the command it shadows) and break script reliability by making command behavior unpredictable.

Newren also addresses Christoph's comment about the shell command alias documentation being unclear, quoting and defending the existing git-config(1) manpage text that describes shell command aliases' execution context and environment variables. The response implies the documentation is sufficiently detailed about how `!`-prefixed aliases work.

The exchange shows the Git maintainers' consistent position that command shadowing prevention is non-negotiable for script compatibility and system reliability, with no plans to introduce exceptions. While the original technical question is settled, this email serves to firmly close any remaining hope for workarounds while defending the completeness of the existing documentation.
