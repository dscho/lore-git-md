This is a bugfix report highlighting a platform-specific issue with branch deletion on case-insensitive filesystems (specifically macOS). Richard Carlsson discovered that when attempting to delete a branch with a case variant of the current branch name (e.g., "Dummy" vs "dummy"), Git incorrectly allows the deletion on macOS, leaving the user in a broken state where their current branch no longer exists. On case-sensitive filesystems like Linux, Git correctly reports the branch as not found.

The issue demonstrates a filesystem case-sensitivity handling problem in Git's branch deletion logic. The key problematic behavior is that Git on macOS treats "dummy" and "Dummy" as the same branch for deletion purposes, even though they should be considered distinct. This leads to the dangerous situation where a user can accidentally delete their current working branch by specifying a case variant of its name.

The report includes clear reproduction steps showing the different behavior between macOS (where the deletion succeeds) and Linux (where it properly fails). The most concerning aspect is that after the deletion, Git leaves the user in a state where their current branch pointer is invalid ("your current branch does not have any commits yet"), which could lead to confusion or data loss.

This appears to be a legitimate bug that warrants attention, particularly for macOS users. The report is well-documented with clear reproduction steps and platform comparison, making it easy to verify. The issue touches on core branch management functionality and filesystem interaction, so it would need careful consideration of case-sensitivity handling across different platforms.
