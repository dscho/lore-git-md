This is a documentation discussion thread about Git's index behavior, specifically addressing how to best explain the index's snapshot model in the `git-add` man page.

Junio Hamano responds to Julia Evans' suggestion about clarifying that index snapshots are discarded (rather than accumulated). He explains Git's design philosophy - that commits (not the index) are meant for preserving states worth returning to, which is why the index doesn't maintain multiple snapshots. He notes this is a deliberate choice because commits provide a better mechanism for this purpose, citing `git stash` as an example of temporary commits being used when needed.

The response also mentions one exception - conflicted states - where Git does preserve previous index states to help recover from bad conflict resolutions. Junio politely but firmly suggests this line of questioning has reached its useful limit, indicating further "why" questions about Git's fundamental design would be unproductive without concrete proposals for change.

This exchange appears to refine the documentation's technical accuracy while maintaining focus on practical user needs rather than theoretical possibilities. The discussion seems to be wrapping up with Junio's authoritative explanation of Git's design rationale.
