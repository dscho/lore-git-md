This is a status update on the `--max-depth` feature series for Git's diff machinery. Reviewer Patrick Steinhardt confirms that all his previous feedback has been addressed in the v2 version of the patches, which adds depth-limiting functionality to diff operations similar to `git grep --max-depth`.

The series, originally authored by Jeff King and now shepherded by Toon Claes, has gone through several rounds of review with improvements to test coverage, error handling, and documentation. Key changes in v2 include comprehensive unit tests for the depth calculation logic, support for `-1` as "no limit" value, and various code quality improvements like const-correctness and better error messages.

With Patrick's approval and Junio Hamano's earlier indication that the series appears ready, this feature seems likely to land in Git after the 2.51 release. The implementation looks solid with thorough test coverage, addressing edge cases in path handling while maintaining compatibility with existing diff behavior.
