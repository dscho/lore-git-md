This is a follow-up in the thread about a potential null pointer dereference in `builtin/describe.c`. Phillip Wood agrees with Jeff King's earlier suggestion to change the interface of `describe_commit()` to take a `struct commit*` directly rather than an object ID, which would eliminate the need for the potentially unsafe commit lookup inside the function.

The discussion has moved from the initial vulnerability report to considering architectural improvements. Phillip notes that this change would make the code's intent clearer by showing the commit lookup happens before calling `describe_commit()`. Jeff King had provided an untested prototype diff showing how this change would propagate through the calling code, though he's not planning to implement it himself.

The thread appears to be converging on this interface redesign approach rather than just adding null checks, as it would both fix the immediate issue and improve the code structure. The main open question now seems to be who will implement the change, as neither Phillip nor Jeff have committed to doing so yet.
