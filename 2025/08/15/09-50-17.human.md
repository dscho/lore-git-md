This is a bugfix report for a case-sensitivity issue affecting branch deletion on macOS. Richard Carlsson discovered that when trying to delete a branch with `git branch -d` on a case-insensitive filesystem (like HFS+ or APFS), Git will unexpectedly delete the current branch if the case of the branch name doesn't match exactly. 

The problem occurs when attempting to delete a differently-cased version of the current branch (e.g., trying to delete "Dummy" when on branch "dummy"). On Linux (case-sensitive filesystems), this correctly fails with "branch not found", but on macOS, it deletes the current branch while leaving the working tree in a confused state where it thinks the branch still exists.

The report includes clear reproduction steps showing how this can happen accidentally when mistyping the branch name. This appears to be a potentially dangerous edge case that could lead to accidental data loss, particularly since the error message about the branch being in use doesn't prevent the deletion when the case differs. The bug seems specific to case-insensitive filesystems and involves Git's branch name matching logic.
