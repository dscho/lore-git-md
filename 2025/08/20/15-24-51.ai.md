This is a refactoring patch for git-gui that simplifies how the `nice` command is handled when running long-running Git operations. The patch removes a helper function `_lappend_nice` that was dynamically checking for `nice` availability during each command execution, and replaces it with a simpler approach that checks `nice` once at startup and stores the result in a global variable `_nice`. The new implementation in `git_read_nice` then just prepends the stored `nice` command (if available) to the Git command being executed.

The change reduces code complexity by eliminating the dynamic checking and function call overhead, while maintaining the same behavior - commands will still be run with `nice` when available, and without it otherwise.
