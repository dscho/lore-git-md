This is a documentation patch addressing Asciidoctor rendering compatibility in the final patch of a completed series standardizing Git's man pages. The patch specifically fixes formatting issues in `pretty-formats.adoc` that arise from differences between Asciidoc.py and Asciidoctor 2.0.16's handling of verbatim syntax.

The technical issue centers on how the tools detect verbatim spans marked with `+` characters. Asciidoc.py treats `{nbsp}` as a non-word character for span detection while Asciidoctor does not, causing inconsistent rendering. The solution uses double `++` markers around parentheses and arrows in the `prefix` and `pointer` defaults to create "unconstrained" spans that work consistently in both tools, while leaving `suffix` and `separator` defaults unchanged as they don't trigger the same issues.

Jean-Noël Avila explains the root cause and provides the fix, noting this behavior reflects markup assumptions biased toward Roman-based languages. Junio Hamano had questioned why some elements required doubled markers while others didn't, leading to this clarification about span detection rules. The patch maintains identical functionality while ensuring consistent rendering across toolchains.
