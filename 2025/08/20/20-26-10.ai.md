This is a documentation patch addressing Asciidoctor compatibility in the final piece of a larger documentation standardization effort. The patch specifically fixes rendering differences between Asciidoc.py and Asciidoctor 2.0.16 in the `pretty-formats.adoc` file's `%(decorate)` section.

The technical issue stems from how the two documentation processors handle verbatim spans marked with `+` characters. Asciidoc.py treats `{nbsp}` as a non-word character that triggers verbatim span detection, while Asciidoctor does not. The solution uses double `++` markers around the `prefix` and `pointer` defaults to create "unconstrained" spans that behave consistently in both processors, while leaving the `suffix` and `separator` defaults unchanged.

This patch represents the final tweak to a 14-patch series that has already been approved by Junio Hamano for merging into the 'next' branch. While the technical fix is straightforward, Junio has raised a documentation question about why some elements require doubled markers while others do not - a point that remains open but doesn't block merging. The change maintains identical functionality while ensuring consistent rendering across documentation toolchains.

Key files affected:
- `Documentation/pretty-formats.adoc` (specifically the `%(decorate)` format specifier defaults)
- No behavior changes, only documentation rendering improvements

The patch demonstrates attention to cross-toolchain compatibility between Git's traditional Asciidoc.py processing and git-scm.com's Asciidoctor-based implementation. This completes the comprehensive documentation standardization effort that has converted multiple Git man pages to the new synopsis format style.
