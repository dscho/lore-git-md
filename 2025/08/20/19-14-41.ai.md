This is the final patch in Jeff King's series fixing dangling symref handling in `git fetch`. The patch specifically prevents `git update-ref` from overwriting dangling symrefs when operating in `--no-deref` mode with `followRemoteHEAD=create` configuration.

The technical discussion with Patrick Steinhardt confirms the implementation approach, particularly around the nested condition checking for null OIDs and dangling symrefs. The patch adds careful validation in both files-backend.c and reftable-backend.c to detect and preserve dangling symrefs when they should not be overwritten, returning REF_TRANSACTION_ERROR_CREATE_EXISTS in such cases.

Key implementation details include:
- The check_old_oid() function now considers both the null OID case and REF_NO_DEREF flag
- Test coverage in t1400-update-ref.sh verifies the new behavior
- The reftable backend implementation differs slightly due to locking requirements
- A minor i18n inconsistency between backends was noted but deferred

The email exchange clarifies some test coverage questions, confirming the existing tests do verify the symref-to-normal-ref conversion behavior. With the technical review complete and all questions resolved, this patch appears ready for integration as the final piece of the series fixing the dangling symref issue.
