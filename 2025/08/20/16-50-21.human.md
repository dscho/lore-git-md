This is a refactoring patch for git-gui's handling of the `nice` command, following up on earlier discussion about documentation improvements.

Mark Levedahl's v2 patch simplifies how git-gui runs Git commands with `nice` by moving the availability check from per-command execution to startup time. The key change replaces a helper function that dynamically checked for `nice` on each invocation with a single check during initialization, storing the result in a global variable. This reduces the code from 23 lines to 7 while maintaining the same functionality - using `nice` when available, falling back to direct execution otherwise.

The patch addresses two issues from v1 feedback: fixing the handling of paths with spaces (which should have been in v1 but was accidentally omitted) and incorporating Kristoffer Haugsbakk's suggested documentation improvements. The commit message now properly refers to `nice(1)` and fixes a grammatical "lets" to "let's".

The change appears well-scoped and uncontroversial, with the thread showing only minor documentation suggestions rather than technical objections. The refactoring makes the code more straightforward while preserving the existing behavior of gracefully falling back when `nice` isn't available.
