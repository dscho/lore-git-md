Thread identity: Bug report about inconsistent color handling in Git's interactive patch mode (`--patch`) across different subcommands, originating from a user experiencing issues with color configuration.

Core problem: Multiple Git commands (`stash push/save`, `checkout`, `reset`, `restore`) incorrectly handle color configuration (`color.diff` and `color.ui` settings) in interactive patch mode due to a regression from the 2021 Perl-to-C conversion (commit 0527ccb1b5), while other commands (`commit`, `add`, `stash` without push/save) behave correctly. The inconsistency affects both color disabling (`never`) and forced color output (`always`), particularly when piping output.

Current status: Jeff King has identified the root cause where some commands fail to initialize color configuration variables that the interactive code relies on. A workaround using `interactive.diffFilter` with `diff-highlight` has been confirmed effective by Isaac Oscar Gariano, though this solution isn't currently documented. The thread now includes both technical analysis of the regression and a verified workaround.

Key technical details:
- Commands affected: `stash push/save`, `checkout`, `reset`, `restore` in `--patch` mode
- Root cause: Missing color initialization in C conversion (commit 0527ccb1b5)
- Core issue: `add-interactive.c` handles `color.interactive` but relies on parent command for `color.ui`
- Configuration settings mishandled: `color.diff` and `color.ui` (both `color.interactive` works correctly)
- Workaround: `interactive.diffFilter` with `diff-highlight` (confirmed working by Isaac Oscar Gariano)
- Additional ignored settings: `diff.wordRegex` and related diff configs (intentional design limitation)
- Impact: Breaks workflows piping colored output through tools like `diff-highlight`
