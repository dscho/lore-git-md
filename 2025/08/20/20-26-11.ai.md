This is a documentation patch addressing toolchain compatibility in the Git documentation system, specifically fixing rendering differences between Asciidoc.py and Asciidoctor in the `pretty-formats.adoc` file.

The patch modifies the verbatim syntax formatting for the `%(decorate)` format specifier defaults in the pretty formats documentation. It changes single `+` markers to double `++` around parentheses and arrows in the `prefix` and `pointer` defaults to ensure consistent rendering across both documentation toolchains. The `suffix` and `separator` defaults remain unchanged as they don't trigger the same toolchain differences.

The technical issue stems from Asciidoctor 2.0.16 not treating `{nbsp}` as a non-word character for verbatim span detection, which was causing unwanted `+` characters and Unicode arrow conversion in the rendered output. The changes maintain identical functionality while improving rendering consistency between the toolchains used by git-scm.com (Asciidoctor) and core Git (asciidoc.py).

This patch is part of a larger completed effort to standardize Git's documentation format, with this being a follow-up to address specific toolchain compatibility issues identified after the main series was approved. The changes are minimal but technically precise, targeting only the specific syntax elements that required adjustment for cross-toolchain compatibility.

The patch has already been reviewed and approved for merging into the 'next' branch by Junio Hamano, though he noted an open question about why some elements require doubled `+` markers while others don't - a documentation point that may inform future work on AsciiDoc/Asciidoctor compatibility patterns.
