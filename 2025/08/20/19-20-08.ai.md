This is a technical discussion about the packfile MRU list implementation in Patrick Steinhardt's ongoing ODB refactoring series.

Jeff King (Peff) responds to Karthik Nayak's question about why the packfile store maintains both a regular list (`packfile_store.packs`) and an MRU (most-recently-used) list (`packfile_store.mru`) of packfiles. Peff explains this is historical - when he originally introduced the MRU optimization, he kept both lists to avoid breaking any code that might depend on the original list's order. He suggests it might now be safe to consolidate to a single MRU-ordered list, but cautions this should be done carefully to avoid iteration issues if lookups reorder the list during traversal.

The key technical details:
- Both lists currently contain the same packfiles, just in different orders
- The MRU list optimizes searches by keeping recently accessed packs first
- Original list was kept for backward compatibility with potential order-dependent code
- Peff suggests this consolidation would be better done after Patrick's current refactoring series

This discussion touches on an architectural decision point in the larger ODB abstraction work - whether to maintain parallel data structures or consolidate them. Peff's response provides historical context and practical advice about sequencing this potential future change. The thread continues to show careful consideration of both implementation details and broader design implications in this significant refactoring effort.
