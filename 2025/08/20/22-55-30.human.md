This is the second patch in a 3-part refactoring series that continues the `the_repository` removal effort by eliminating global state in the bulk-checkin subsystem. The patch moves transaction state from global variables into `struct object_database`, updating all callers to pass the transaction state explicitly.

The changes affect several builtin commands (`add`, `unpack-objects`, `update-index`) and touch core object database operations. The patch introduces a new `transaction` field in `struct object_database` and modifies bulk-checkin APIs to operate on transaction objects rather than implicit global state. Key functions like `begin_odb_transaction()` now return a transaction pointer that callers must pass to subsequent operations.

The implementation looks thorough, with careful attention to maintaining existing behavior while removing global dependencies. The patch follows established patterns seen in other parts of the codebase for migrating away from global state. As part of a larger series, this change builds on the foundation established in patch 1 while setting up for the final wiring through of repository variables in patch 3.
