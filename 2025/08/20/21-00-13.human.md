This is a follow-up documentation patch addressing Asciidoctor rendering issues in the `pretty-formats.adoc` file, part of the larger documentation standardization effort. The patch specifically fixes formatting inconsistencies between Asciidoc.py and Asciidoctor 2.0.16 in how they handle verbatim syntax for the `%(decorate)` format specifier defaults.

Jean-Noël Avila explains that the issue stems from differing behavior in how the two processors detect verbatim spans - Asciidoc.py treats `{nbsp}` as a non-word character while Asciidoctor does not. The solution is to use double `++` markers around parentheses and arrows in the `prefix` and `pointer` defaults to create "unconstrained" spans that work consistently across both tools, while leaving `suffix` and `separator` defaults unchanged as they don't trigger the same issues.

Junio Hamano had questioned why some elements required this treatment while others didn't, and the response clarifies the technical rationale. This appears to be the final tweak needed before the entire documentation conversion series can be merged, with Junio having already indicated the v3 series is ready for inclusion in the 'next' branch. The patch is small but demonstrates careful attention to cross-toolchain compatibility in Git's documentation.
