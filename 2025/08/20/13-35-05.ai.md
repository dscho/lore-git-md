This is part 11 of Patrick Steinhardt's ongoing series to refactor Git's packfile subsystem into a dedicated `packfile_store` structure. The patch addresses an inconsistency in how packfiles are added to the most-recently-used (MRU) list when they are first loaded into the store.

Currently, new packfiles are added to the main packfile list and map but not automatically to the MRU list, requiring them to be added later when first accessed. Some subsystems work around this by manually adding to the MRU, creating inconsistency. The patch standardizes this by always adding to the MRU during initial packfile addition.

Karthik Nayak responds positively to the change, noting it helps move toward better encapsulation of `packfile_store` internals. He suggests the long-term goal should be making the MRU implementation details completely private behind clean APIs, and sees this patch as a step in that direction. The comment indicates general approval of the architectural direction while implicitly reinforcing the earlier question about whether both the main packfile list and MRU list need to remain separate long-term.

This continues the series' pattern of mechanical refactoring while maintaining behavior, with no new technical concerns raised. The change affects packfile.c and aligns with the broader effort to separate packfile management from the generic object database infrastructure.
