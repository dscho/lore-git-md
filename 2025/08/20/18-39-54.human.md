This is the first patch in a bugfix series addressing an issue with `git repack --path-walk` where certain singleton objects can be incorrectly omitted. The patch adds a failing test case that demonstrates the problem.

The test creates a repository with several scenarios where objects exist in the index but have no second versions in history - including single-version files, staged-only files, and cache-tree entries. After a `--path-walk` repack with sparse pack usage (the default), these objects go missing, causing `git fsck` to report errors about invalid and missing objects.

The test is carefully constructed to isolate the failure scenario, first doing a non-path-walk repack to ensure loose objects are packed, then verifying the path-walk case fails as expected. The commit message provides detailed technical background about why the bug occurs - the path-walk API fails to properly mark certain pending objects as "maybe_interesting", causing them to be skipped during the repack.

This is a well-crafted test that clearly shows the bug's symptoms and will help verify the fix in the next patch. The commit message thoroughly explains both the test setup and the underlying technical issue, making this a strong start to the series.
