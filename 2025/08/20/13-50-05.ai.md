This is patch 14/16 in Patrick Steinhardt's series refactoring Git's packfile subsystem as part of the object database abstraction effort. The patch removes the `get_packed_git()` function, consolidating packfile access through `get_all_packs()` instead.

Karthik Nayak raises two technical questions about the change:
1. He asks for clarification on when a packfile might be indexed by a multi-pack-index but not returned by `get_packed_git()`, suggesting this distinction may not be well-documented.
2. He notes a grammatical issue in the commit message's description of the `builtin/grep.c` changes.

The patch itself removes `get_packed_git()` after analyzing its three remaining call sites and determining they can safely use `get_all_packs()` instead. The commit message explains:
- `builtin/gc.c` already handles MIDX-indexed packs correctly
- `builtin/grep.c` can use the newer `packfile_store_prepare()`
- `object-name.c` functions already have MIDX awareness

This continues the series' pattern of simplifying the packfile interface while maintaining behavior. The change affects packfile.c/h, builtin/gc.c, builtin/grep.c, and object-name.c. Karthik's questions suggest the commit message could better explain the MIDX edge case being removed, though the technical approach appears sound.
