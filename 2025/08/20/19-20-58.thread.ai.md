Thread identity: User query about potential removal of `git whatchanged` in Git 2.51, seeking alternatives for timestamp extraction.

Core problem: Dan Allen's Python script uses `git whatchanged --pretty=%at` to get UNIX timestamps of last modification for files, then sets filesystem mtimes accordingly. Needs migration path if command is removed.

Current status:
- Kristoffer Haugsbakk initially provided documentation-suggested replacement using `git log --raw --no-merges --pretty=%at`
- Junio Hamano (maintainer) confirmed `git log --raw --pretty=%at` as the direct replacement, suggesting `--no-merges` may be unnecessary
- Ben Zanin verified near-identical output between the commands in Git 2.51.0's repository, with `git log` showing 5 additional timestamps
- Jeff King identified the root cause: `git log` shows empty commits (non-merges with identical trees to first parent) due to `revs.always_show_header` flag, while `whatchanged` skips them

Key technical details:
- Current method extracts UNIX timestamps via `%at` format from `whatchanged`
- Maintainer-approved alternative: `git log --raw --pretty=%at`
- Behavioral differences:
  - `git log` shows empty commits (5 more in test case)
  - Difference is hardcoded via `revs.always_show_header` with no toggle
  - Pathspec filtering possible but may have side effects
  - `git log` behavior more correct by showing all commits
- Script purpose: Local repository browsing via filesystem metadata synchronization
- `whatchanged` is legacy command largely superseded by `git log`
- Both commands share `--pretty=` format capabilities
