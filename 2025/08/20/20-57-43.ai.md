This is a follow-up in the thread about replacing `git whatchanged` functionality for timestamp extraction. Ben Zanin provides a detailed comparison between the legacy `git whatchanged --pretty=%at` command and the proposed replacement `git log --raw --no-merges --pretty=%at`.

Key technical findings:
- The outputs are nearly identical except for a few additional timestamps appearing in the `git log` version
- Ben tested this in Git 2.51.0's own repository
- The diff shows exactly which extra timestamps appear (5 additional entries in this test case)
- The core functionality of extracting UNIX timestamps via `%at` format works the same way in both commands

The email leaves open:
- Whether these extra timestamps would affect Dan Allen's Python script that sets filesystem mtimes
- If the additional entries represent meaningful data that should be processed or filtered
- No discussion yet of how this relates to merge commits or edge cases like renames

This provides concrete verification data for the migration path suggested earlier in the thread, though the practical implications for the original use case remain to be confirmed by Dan Allen.
