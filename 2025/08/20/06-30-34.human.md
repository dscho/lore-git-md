This is the final patch in a series hardening `git describe`'s error handling, specifically addressing an edge case where HEAD points to a non-commit object. The patch prevents a segfault when describing a blob in this invalid repository state, returning a proper error instead.

The implementation adds a check for the null OID before attempting to describe the commit, falling back to the existing "not reachable" error path. The test case cleverly uses `git symbolic-ref` to simulate the invalid state without direct repository corruption, though the commit message notes this relies on a historical loophole in Git's ref validation that may be tightened in the future.

The patch includes a detailed comment explaining the test's temporary nature, acknowledging it may need removal if HEAD validation becomes stricter. This maintains compatibility with Git's permissive historical behavior while properly handling the error case. With all five patches in the series now approved, this completes the architectural improvements to `builtin/describe.c`'s robustness.
