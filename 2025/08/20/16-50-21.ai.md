Git-gui refactoring to simplify `nice` command handling, version 2.

This is the second version of a refactoring patch that simplifies how git-gui handles the Unix `nice(1)` utility for long-running Git operations. The key change moves the `nice` availability check from per-command execution to a single check at startup, stored in a global `_nice` variable. The patch reduces code from 23 lines to 7 while maintaining identical functionality.

The v2 changes address feedback from Kristoffer Haugsbakk and fix an oversight in v1 regarding path handling with spaces. The `_nice` variable is now properly initialized as a list to handle paths containing spaces, and the commit message has been updated to use "nice(1)" notation for clarity. The implementation now uses Tcl's `{*}` expansion operator to properly handle command construction.

The patch touches git-gui's command execution infrastructure, specifically modifying how the `git_read_nice` proc and its supporting code work. The original dynamic checking via `_lappend_nice` helper is completely removed in favor of the simpler startup check. The behavior remains unchanged - commands will still be prefixed with `nice` when available, falling back to direct execution when not.

This appears to be a straightforward quality-of-life improvement for git-gui maintainers, reducing code complexity without affecting functionality. The v2 changes show careful attention to edge cases (paths with spaces) and incorporate documentation feedback, suggesting this is likely ready for inclusion.
