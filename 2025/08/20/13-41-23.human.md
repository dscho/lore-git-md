This is part 12 of Patrick Steinhardt's ongoing refactoring series to move packfile management into a dedicated `packfile_store` structure. The patch introduces a new helper function `packfile_store_load_pack()` that consolidates the common pattern of checking if a packfile exists in the store and adding it if not. 

The change replaces several instances of manual packfile checking/adding with calls to this new function, simplifying code in fast-import.c, index-pack.c, midx.c and packfile.c. Karthik Nayak notes this addresses their earlier observation about midx.c handling packfile loading directly, and generally approves of the direction. 

The patch appears to be a straightforward mechanical improvement that reduces code duplication while maintaining the same behavior. It continues the series' trend of incrementally moving packfile operations into the new store abstraction. No new concerns are raised in the response, though Karthik does question whether the underlying hashmap implementation could use Git's newer strmap` API instead.
