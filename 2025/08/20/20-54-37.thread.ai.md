Thread summary:

Bug report and investigation into spurious "lock file exists" errors during fetch operations in bare repositories, originally reported by Joe Drew on macOS ARM64 with Git 2.51.0. Core issue involves phantom lock file errors when mirroring remote refs in bare repos, not present in Git 2.39.5. Jeff King and Patrick Steinhardt have identified the root cause as case-sensitivity conflicts on macOS's case-insensitive filesystem interacting with Git's new batched ref transaction mode in git-fetch(1). 

Technical details:
- Specific versions involved: 2.39.5 (working) vs 2.51.0 (failing)
- Batched ref transactions (introduced between these versions) now properly detect case collisions that previously went unnoticed
- Old one-by-one updates could result in flip-flopping ref values without detection
- Reftable backend (`--ref-format=reftable`) works as workaround by avoiding filesystem locks entirely
- macOS case-insensitive filesystem masks underlying case collision issues

Current consensus:
- Not strictly a regression but rather improved correctness revealing hidden filesystem-level problems
- Batched transaction behavior is working as intended by detecting case collisions
- Previous behavior allowed silent inconsistencies with case-colliding refs

Open questions/options:
- Whether to modify batched transaction logic to handle case collisions more gracefully
- Potential to defer solution by encouraging reftable adoption in Git 3.0
- Need to document this as a known issue for users with case-colliding refs

Participant positions:
- Patrick Steinhardt confirms case collision scenario and technical analysis
- Jeff King agrees with analysis and raises possibility of deferring code changes in favor of reftable transition
- Both recognize this as a case where improved correctness reveals previously hidden filesystem-level issues

The reftable backend remains the cleanest solution, avoiding filesystem-level case issues entirely. Next steps may involve documenting this as a known issue and considering whether to add collision detection code or encourage reftable adoption as the preferred path forward.
