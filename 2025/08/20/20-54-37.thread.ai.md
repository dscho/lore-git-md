Bug report and technical discussion of spurious "lock file exists" errors during fetch operations in bare repositories, originally reported by Joe Drew on macOS ARM64 with Git 2.51.0. Core issue involves phantom lock file errors when mirroring remote refs in bare repos, traced to case-sensitivity conflicts on macOS's case-insensitive filesystem interacting with Git's batched ref transaction mode (introduced in 2.51.0 via commit 0e358de64a). Jeff King and Patrick Steinhardt identified the root cause, with Karthik Nayak proposing a files backend modification as interim solution while reftable remains the preferred long-term fix.

Technical details:
- Specific versions: 2.39.5 (working) vs 2.51.0 (failing)
- Batched ref transactions properly detect case collisions that previously went unnoticed
- Old one-by-one updates allowed flip-flopping ref values without detection
- Reftable backend (`--ref-format=reftable`) avoids filesystem locks and case collision issues
- macOS case-insensitive filesystem masks underlying case collision issues
