Thread summary:

Bug report regarding ref locking behavior in bare repositories during fetch operations, reported by Joe Drew. Core issue involves spurious "lock file exists" errors when creating new references during fetch in Git 2.51.0 on macOS ARM64 with clang 17.0.0, not present in Git 2.39.5. The error occurs specifically when mirroring remote refs to local refs in bare repos, with the existence of phantom lock files being reported for non-existent branches. Technical details indicate this may be either a regression in lock file handling or platform-specific issue in newer Git versions, particularly around the refs backend in bare repositories. The reporter has verified the absence of actual lock files when the error occurs, suggesting incorrect lock state tracking. System diagnostics confirm ARM64 macOS environment but proprietary repository prevents full reproduction details. Open questions include whether this is a known regression, if other platforms are affected, and what changed in ref transaction handling between 2.39.5 and 2.51.0 that might trigger this behavior.
