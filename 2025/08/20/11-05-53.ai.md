This is a bug report about inconsistent color handling in Git's interactive patch mode across different subcommands. The reporter identifies two groups of commands with differing behavior regarding color.diff and color.ui settings when using --patch mode.

The "good" commands (commit, add, stash) behave as expected, while "bad" commands (stash push/save, checkout, reset, restore) incorrectly handle color settings. Key observations:
1. Commands ignore color.diff=never and color.ui=never settings
2. Piped output (| cat) doesn't respect color.diff=always/color.ui=always
3. All commands correctly respect color.interactive settings
4. The reporter notes diff config options like diff.wordRegex are also ignored

The issue affects users trying to pipe colored output through tools like diff-highlight. The report includes clear reproduction steps and references relevant documentation (color.interactive behavior). While focused on color issue, it also notes a related configuration inconsistency with diff settings that may warrant separate attention.

The bug appears to be in the color handling plumbing for several interactive commands, suggesting a need for unified behavior across all --patch mode implementations. The reporter provides technical details that would help developers reproduce and investigate the issue.
