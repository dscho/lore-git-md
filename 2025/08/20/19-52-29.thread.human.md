This thread documents the collaborative effort to add a comprehensive README.md to the gitk repository, Git's graphical repository browser maintained by Johannes Sixt. The discussion has evolved through multiple iterations, with patch author Michael Rappazzo incorporating feedback from maintainers and contributors.

The core documentation covers gitk's dual-hosting status (both in a standalone GitHub repository and as a subtree in git.git), contribution requirements including Signed-off-by tags, and build dependencies (Tcl/Tk). The current discussion focuses on refining the submission workflow examples, particularly around `git format-patch` syntax variants like `@{u}..` versus `master..`, with D. Ben Knoble's latest contribution explaining the triangular workflow implications of these choices.

Maintainer Junio Hamano has been actively involved, sharing his personal workflow using topic-specific directories and emphasizing the importance of pre-submission review. Kristoffer Haugsbakk contributed practical review techniques using `less`, while Knoble's recent email suggests linking to git-send-email.io as an additional resource for newcomers. The thread demonstrates how even documentation patches undergo rigorous review, with participants balancing technical precision against approachability for new contributors.

The patch is nearing final form, with Rappazzo preparing a v2 that will incorporate these refinements while maintaining the core requirements. The discussion has remained focused on documentation polish, with no technical concerns raised about gitk itself. This thread serves as both a case study in Git contribution practices and a resource that will help future gitk contributors understand the project's workflow expectations.
