This thread documents the collaborative effort to create a comprehensive README.md for gitk, Git's repository browser GUI maintained by Johannes Sixt (Hannes). The discussion began with Michael Rappazzo's initial patch proposing detailed contribution guidelines, including email submission protocols, GitHub PR alternatives, and build requirements.

The thread has seen active participation from key contributors. Maintainer Junio C Hamano provided multiple rounds of feedback, emphasizing the importance of pre-submission review and sharing his personal workflow for organizing patches. Kristoffer Haugsbakk contributed practical review advice using `less`, while D. Ben Knoble added technical depth about `git format-patch` syntax and workflow implications.

The most recent development comes from gitk maintainer Johannes Sixt, who suggests reorienting the README's focus. Rather than emphasizing contribution mechanics, he advocates for a document that better serves first-time visitors by explaining what gitk is and including usage examples. Sixt recommends simplifying the submission guidelines, noting the existing 'gitk:' commit prefix convention is sufficient, and prefers linking to external resources rather than duplicating detailed tutorials.

The discussion has now converged on several key points: maintaining core requirements (Signed-off-by, dual-hosting status), balancing technical accuracy with accessibility, and acknowledging the document's multiple audiences. Rappazzo is preparing a v2 that will incorporate this feedback, particularly Sixt's guidance on document focus and structure. The thread demonstrates how Git's documentation process benefits from both technical precision and maintainer perspective on user needs.
