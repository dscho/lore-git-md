This is a bug report about inconsistent color handling in Git's interactive patch mode across different subcommands. Isaac Oscar Gariano identifies a discrepancy where some commands (commit, add, stash) properly respect color.diff and color.ui settings in --patch mode, while others (stash push/save, checkout, reset, restore) ignore these settings.

The core issue is that the "bad" commands show colored output even when explicitly told not to via color.diff=never or color.ui=never, and fail to show output when piped despite color.ui=always. The behavior contradicts Git's documented behavior for color.interactive, which these commands do follow for prompts but not for diffs.

The reporter notes this became noticeable when trying to pipe `git restore --patch` through diff-highlight, and mentions a related (though likely intentional) issue where --patch modes ignore diff configuration like diff.wordRegex. The report is well-documented with clear reproduction steps and references to relevant documentation, suggesting a genuine inconsistency worth addressing.
