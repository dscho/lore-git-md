This is a follow-up in the thread about replacing `git whatchanged` usage for timestamp extraction. Ben Zanin provides a concrete comparison between the legacy `git whatchanged --pretty=%at` command and the proposed replacement `git log --raw --no-merges --pretty=%at`.

The key finding is that the two commands produce nearly identical output, with the `git log` version showing only a few additional timestamps in the diff. Ben asks whether this minor difference would still work for Dan Allen's script that sets filesystem modification times based on commit dates.

The email includes a specific test case showing the exact diff output when comparing the two commands in the Git repository itself (at v2.51.0). This provides practical verification that the replacement command works as expected, though with slightly more output that might need to be accounted for in the script.

The thread appears to be converging on a solution, with this email providing empirical evidence that the `git log` alternative works for the timestamp extraction use case. The remaining question is whether Dan's script can handle the few extra timestamps that appear in the new output format.
