Thread identity: Bugfix series for `git repack --path-walk` feature addressing missing singleton objects under specific conditions, now at v1 with 3 patches.

Core problem: When using `git repack -adf --path-walk`, certain singleton objects (those with only one version in history, present in index, not loose objects) can be incorrectly omitted from repacked output when sparse pack usage is enabled (default). Root cause is initialization oversight in pending objects setup during path walking.

Current status:
- Patch 1: Failing test case demonstrating issue with singleton objects (a/b/c), staged files (a/i, x/y), and cache-tree entries (x/)
- Patch 2: Fix for initialization issue by properly marking pending object lists as "maybe_interesting" (now reviewed by Junio Hamano)
- Patch 3: Refactoring to prevent similar issues via new helper function `add_path_to_list()` that standardizes path list initialization

Key technical details:
- Affects `builtin/repack.c` and `path-walk.c`
- `add_path_to_list()` helper coming in patch 3 will consolidate three repetitive initialization patterns
- Fix in patch 2 specifically addresses `setup_pending_objects()` in `path-walk.c`
- Handles `OBJ_TREE` and `OBJ_BLOB` paths with proper `maybe_interesting` flag setting
- Test coverage includes multiple object types with sparse-index to verify cache-tree interaction
- Demonstrates failure with pack.useSparse=true (default)
- Prepares loose objects via initial repack to isolate path-walk issue

Open questions:
