This is a bugfix follow-up in the submodule gitdir path encoding series, addressing platform compatibility issues in patch 6/9. Jeff King identifies two specific Windows build failures in the path length validation code:

1. Missing `pathconf()` and `_PC_NAME_MAX` on Windows, requiring a compat wrapper that returns -1 (falling back to `NAME_MAX`). This matches the pattern seen elsewhere in Git's codebase for platform-specific filesystem limits.

2. Format string portability issues with `%z` and `%ld` for size types on Windows (LLP64 model), which should use `PRIuMAX` instead. This is a common pitfall when writing cross-platform C code.

Additionally, Jeff notes observed failures in macOS CI for test t7527.62 (submodule absorbgitdirs with implicit daemon start), though he hasn't investigated the root cause yet. Given the timing, these may relate to the path encoding changes in this series.

The issues are localized to the path length validation portion of the new encoding logic, not affecting the core URL/case encoding mechanism. The feedback suggests straightforward fixes that maintain the series' goals while improving portability. This continues the pattern of incremental refinement seen throughout the thread, now focusing on platform-specific edge cases.
