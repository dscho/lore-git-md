This is a discussion thread about the RFC for the new `git-history` command, focusing on notes handling and multi-branch operation possibilities.

Ben Knoble responds to Junio Hamano's feedback on Patrick Steinhardt's RFC series for `git-history`. The discussion centers on two key aspects: notes handling and the potential for multi-branch operations.

On notes handling, Ben agrees with Junio's point that the command should properly handle `notes.rewriteref` configuration, noting that cherry-pick deliberately doesn't handle this and the new command should.

The more substantial discussion revolves around expanding the command's capabilities beyond linear history. Ben draws parallels between Junio's suggestion for multi-branch operation and Git's existing `rebase --update-refs` functionality, as well as Jujutsu's (jj) approach. He suggests that editing commits reachable from multiple branches could update all of them, while proposing safety heuristics based on push/pull relationships.

Ben also expresses appreciation for the project's willingness to borrow improvements from tools like Jujutsu, comparing it to how Neovim has inspired Vim improvements. The tone is constructive and forward-looking, focusing on how to expand the command's capabilities while maintaining safety.
