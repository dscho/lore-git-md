This is a follow-up in the ongoing discussion about `git whatchanged` usage and migration paths. Kristoffer Haugsbakk responds to Junio C Hamano's clarification about command aliasing behavior, agreeing with the technical explanation but suggesting an improvement to the user experience.

The email focuses on refining the deprecation messaging for `git whatchanged`. Haugsbakk proposes enhancing the error message to explicitly state two key points: (1) users can take proactive steps beyond just reporting usage, and (2) the `git log --raw` equivalent exists (as documented in git-whatchanged(1)). The current message might be misinterpreted as suggesting the only action is to request keeping the command.

This builds on the established technical understanding that command aliases cannot override built-ins, and that `git log --raw` provides equivalent functionality. The suggestion aims to make the migration path clearer for users who encounter the deprecation warning, potentially reducing confusion and support requests. No new technical solutions are introduced - this is purely about improving communication of the existing migration strategy.
