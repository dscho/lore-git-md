Refactoring patch in the bulk-checkin subsystem as part of `the_repository` removal effort.

This second patch in the 3-part series eliminates the remaining global transaction state in bulk-checkin by moving it into `struct object_database`. The key changes include:

1. The `struct odb_transaction` is now allocated per-object-database rather than being a global variable, with each `object_database` instance maintaining its own transaction state via a new `transaction` field.

2. All bulk-checkin functions that previously operated on global state now take a `struct odb_transaction*` parameter, including:
   - `begin_odb_transaction()` now returns the transaction pointer
   - `index_blob_bulk_checkin()`, `prepare_loose_object_bulk_checkin()`, and `fsync_loose_object_bulk_checkin()` all require transaction context
   - Transaction lifecycle functions (`flush_odb_transaction()`, `end_odb_transaction()`) now operate on specific transactions

3. The patch updates all bulk-checkin callers across 9 files to pass the transaction context properly, including builtin commands like `add`, `update-index`, and `unpack-objects`. Each caller now properly manages transaction state through the repository's object database.

The changes maintain identical behavior while removing the last global state from bulk-checkin. This prepares for the final patch which will wire through the repository parameter more completely. The implementation follows established patterns for removing globals, with careful attention to transaction nesting behavior and proper cleanup.
