Bugfix test case demonstrating `git repack --path-walk` issue with singleton objects.

This is the first patch in a series addressing a bug where `git repack -adf --path-walk` fails to include certain singleton objects (those with only one version in history) when pack.useSparse is enabled (the default). The test creates a repository with several scenarios that trigger the bug: a file with only one committed version (a/b/c), staged files that don't exist in history (a/i and x/y), and a tree that only exists in the cache-tree (x/).

The test performs a normal repack followed by a path-walk repack, then verifies object integrity with `git fsck`. The expected failure shows missing objects including blobs and trees that should have been preserved. The test uses sparse-checkout with sparse-index to ensure cache-tree walking is properly tested. The commit message thoroughly explains the root cause - the path-walk API fails to mark pending object lists as "maybe_interesting", causing the pack.sparse optimization to incorrectly skip these objects. This test will be used to verify the fix in the next patch.

Key technical details:
- Tests `builtin/repack.c` path-walking behavior
- Demonstrates failure with pack.useSparse=true (default)
- Covers multiple object types (blobs, trees)
- Uses sparse-index to test cache-tree interaction
- Shows fsck output with specific missing objects
- Prepares loose objects via initial repack to isolate the path-walk issue

The test follows good practice of demonstrating the bug before fixing it, and the commit message provides clear reproduction steps and expected failure output. This will be useful for verifying the subsequent fix and preventing regressions.
