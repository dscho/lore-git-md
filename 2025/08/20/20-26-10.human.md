This is a documentation patch addressing toolchain compatibility in the Git man pages conversion effort. It's part of the final follow-up to a larger series that standardizes Git's documentation format, now ready for merging.

The patch specifically fixes rendering differences between Asciidoc.py and Asciidoctor in the `pretty-formats.adoc` file. The issue stems from how the two processors handle verbatim spans marked with `+` characters - they differ in what they consider a "non-word" character that triggers span detection. The solution uses double `+` markers to create "unconstrained" spans that behave consistently across both processors.

Jean-Noël Avila explains that while he hasn't investigated the exact implementation details, the empirical solution works for both toolchains. This addresses SZEDER Gábor's earlier report of rendering issues with the `%(decorate)` format specifier defaults, particularly around unwanted `+` characters and Unicode arrow conversion.

Junio Hamano has already approved the series for merging into 'next', though he raised a question about why some elements require doubled `+` markers while others don't. This doesn't block the merge but may inform future documentation practices. The patch maintains identical functionality while ensuring consistent rendering across documentation toolchains.
