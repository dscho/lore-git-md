This is a response to a bug report about spurious "lock file exists" errors during fetch operations in bare repositories on macOS. Jeff King suggests two potential explanations:

First, he hypothesizes this could be a case-sensitivity issue where colliding branch names (like "ptv-2164" vs "PTV-2164") on a case-insensitive filesystem might cause lock file conflicts that are cleaned up before being visible. He recommends trying the reftable backend as a workaround since it doesn't use filesystem-based locking.

Second, he notes the version discrepancy (working in 2.39.5 but failing in 2.51.0) is unexpected for a case collision issue and suggests bisecting between these versions to identify the regression. The response is helpful and diagnostic, offering both an immediate mitigation path and a way to investigate the root cause, though it doesn't yet confirm whether this is a known issue or regression.
