This is part of Patrick Steinhardt's ongoing refactoring of Git's packfile subsystem to better encapsulate packfile management in a dedicated `struct packfile_store`. 

In this patch 6/16, Patrick moves the "kept pack cache" from `struct object_database` to the new `packfile_store` structure. Junio Hamano questions whether this change should have been included in the initial patch that created `packfile_store`, to which Patrick clarifies that this was the logical point to remove the change since it completes the encapsulation of all packfile-related private data.

The change is mechanical but important - it removes the last piece of packfile-specific private data from the generic ODB structure, making the comment about "should only be accessed directly by packfile.c" redundant. Patrick notes he'll update the commit message to better explain this rationale.

This continues the series' pattern of systematically moving packfile management out of the generic object database abstraction, with each patch handling a specific component. The discussion shows maintainers are carefully reviewing both the architectural approach and the logical grouping of changes across patches.
