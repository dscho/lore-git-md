This is a refactoring patch for git-gui that simplifies how the "nice" command is used when running long Git operations. The current implementation has a helper function `_lappend_nice` that checks for and appends "nice" to commands, but the patch replaces this with a simpler approach.

The change moves the "nice" detection to a one-time check at startup, storing the result in a global `_nice` variable. This eliminates the need for the helper function and makes the `git_read_nice` implementation much cleaner - it just prepends the stored "nice" command (if available) to the Git command being run.

The patch appears well-motivated and straightforward, removing about 20 lines of code while maintaining the same functionality. The commit message clearly explains the purpose, though it might benefit from mentioning that this is a pure refactoring with no behavior change. The change touches only git-gui.sh and doesn't require any test updates since it's just simplifying existing code paths.
