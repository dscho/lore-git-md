This thread examines a subtle bug where bare repositories on macOS report spurious "lock file exists" errors during fetch operations, first noticed by Joe Drew in Git 2.51.0. The root cause involves case-sensitivity conflicts on macOS's case-insensitive filesystem interacting with Git's newer batched ref transaction mode. Jeff King and Patrick Steinhardt determined this isn't a regression but rather improved correctness revealing previously undetected filesystem-level issues - the older one-by-one ref updates could silently allow case collisions, while batched transactions properly flag them.

The technical discussion has solidified around two paths: Karthik Nayak proposed modifying the files backend to better handle case collisions, while Junio Hamano strongly advocates for adopting the reftable backend (which avoids filesystem locks entirely) as the proper solution. Jeff King's latest email adds an important data point: while reftable does resolve the fetch issues (as confirmed by Dave Evans' testing), some older tools like cgit that link directly against Git's C code fail to recognize the new format. This highlights the real-world migration challenges even for a technically superior solution. The consensus remains that reftable is the right long-term direction, but the thread continues to explore how to manage the transition period where not all ecosystem components support it yet.
