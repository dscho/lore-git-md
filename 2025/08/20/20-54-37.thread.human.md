This thread began with a report of spurious "lock file exists" errors during fetch operations in bare repositories on macOS, where Git 2.51.0 was failing where 2.39.5 had worked. Investigation by Jeff King and Patrick Steinhardt revealed the issue stems from case-sensitivity conflicts on macOS's case-insensitive filesystem interacting with Git's newer batched ref transaction mode - what appeared to be a regression was actually improved correctness exposing previously undetected filesystem-level problems.

The discussion has now clearly converged on reftable as the solution, with maintainer Junio Hamano taking a firm position that this isn't just a long-term ideal but the immediate path forward. Where Patrick initially proposed adding case collision detection to the files backend as an interim measure, Junio has rejected this approach as insufficient, noting that the current behavior effectively blocks workflows entirely when collisions occur. He emphasizes that reftable - which avoids filesystem locks and these case collision issues entirely - is production-ready and should be recommended to users rather than suggesting workarounds for the files backend.

The remaining open questions center on documentation and ecosystem readiness: how to best guide users in migrating to reftable, and the status of libgit2's reftable implementation (which Patrick has been working on) as the last major piece needed for full ecosystem support. With the maintainer's clear direction, the thread appears to be moving toward concluding with reftable adoption as the endorsed solution, likely to be reflected in upcoming documentation updates.
