Documentation refinement for gitk contribution guidelines.

This is a follow-up discussion about improving the README.md for gitk's contribution process. The thread has been focused on clarifying the patch submission examples, particularly around `git format-patch` usage. 

Ben Knoble chimes in to explain the `@{u}..` syntax, noting it refers to the upstream branch where work began (like `origin/master`), contrasting with GitHub-style workflows that set `@{upstream}` differently. He suggests this triangular workflow is more typical for mailing list contributions. The discussion highlights how different Git workflows affect reference syntax, with maintainers preferring clarity about branch relationships in examples.

Knoble also endorses linking to git-send-email.io as a helpful resource for newcomers, reinforcing the thread's theme of making email contributions more approachable. The exchange shows the careful consideration going into making these documentation examples both accurate and accessible, with multiple contributors weighing in on best practices.
