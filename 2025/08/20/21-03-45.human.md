This is a documentation discussion thread follow-up regarding gitk's new README.md contribution guidelines.

Kristoffer Haugsbakk chimes in with a personal workflow suggestion for reviewing patches before email submission. He shares his habit of using `git format-patch` to output patches to a directory and then reviewing them with `cat` and `less` before sending, citing both general caution about mailing list submissions and potential `format-patch` bugs as motivations.

The comment builds on Junio Hamano's earlier suggestion to add a review step between patch creation and sending in the example workflow. While not proposing specific wording changes to the README, Haugsbakk's real-world example reinforces the value of reviewing patches before submission, which the original author Michael Rappazzo had already agreed to incorporate.

This appears to be a supportive comment from an experienced contributor validating the maintainer's suggestion, rather than introducing new substantive discussion points. The thread remains focused on refining the documentation's practical guidance for contributors.
