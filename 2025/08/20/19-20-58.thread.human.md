The thread explores how to migrate from the legacy `git whatchanged` command to modern alternatives for extracting file modification timestamps. Dan Allen originally asked about replacing his Python script's use of `git whatchanged --pretty=%at`, which synchronizes filesystem mtimes with Git history. Kristoffer Haugsbakk suggested using `git log --raw --no-merges --pretty=%at`, and maintainer Junio Hamano confirmed this approach while noting `--no-merges` might be unnecessary.

Ben Zanin has now provided concrete test results comparing both commands in Git 2.51.0's own repository. The outputs are nearly identical, though `git log` produces a few additional timestamps (five more entries in this test case). The core timestamp extraction works the same way in both commands, but it's unclear whether these extra entries would affect Dan's mtime synchronization script. The thread has established a clear replacement path, but awaits confirmation from Dan about whether the minor output differences matter for his specific use case. Junio's involvement suggests this migration approach carries the maintainer's endorsement, making it the likely way forward regardless of `whatchanged`'s eventual deprecation timeline.
