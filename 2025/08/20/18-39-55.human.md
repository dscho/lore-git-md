Bugfix for `git repack --path-walk` handling of singleton objects. This is the second patch in a 3-part series addressing an issue where certain objects tracked in the index could be incorrectly omitted during repacking when using path-walking with sparse packs (the default configuration).

The patch fixes a specific initialization bug where the `maybe_interesting` flag wasn't being set for pending objects during path-walk setup. This flag, introduced in commit 6333e7ae0b, helps optimize pack creation by skipping UNINTERESTING objects, but the uninitialized state was causing valid singleton objects to be incorrectly skipped. The fix simply adds proper initialization of this flag when setting up pending trees and blobs.

The accompanying test change marks a previously failing test as passing, demonstrating that the fix properly handles cases where objects exist in the index but have only one historical instance. The test verifies correct repacking behavior for various object types including blobs, trees, and cache-tree entries.
