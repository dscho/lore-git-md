Refactoring patch in the `git repack --path-walk` bugfix series, introducing a helper function to standardize path list initialization.

This is the third patch in a series addressing a bug where `git repack -adf --path-walk` could incorrectly omit singleton objects when sparse packs are enabled. The previous patch fixed the immediate issue by properly initializing path lists, and this follow-up refactors that solution into a reusable helper function `add_path_to_list()`.

The new helper consolidates three repetitive initialization patterns from `path-walk.c` that were handling path lists (struct type_and_oid_list) for tree and blob objects. The function handles:
1. Allocating new list entries when needed
2. Setting the object type
3. Managing the `maybe_interesting` flag
4. Appending OIDs to the list

The patch leaves special-case initializations (for tags, commits, root trees, etc.) as-is since they have different usage patterns. The changes are mechanical replacements of the previous initialization code with calls to the new helper, maintaining identical behavior while reducing duplication.

This appears to be a clean refactoring that follows the "fix then prevent" pattern seen in the series - first addressing the bug directly, then making the code more maintainable to avoid similar issues. The changes are focused and well-contained to the path-walk implementation.
