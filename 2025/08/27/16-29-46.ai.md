This is the first patch in a series improving guidance for deprecated commands, focusing on `git whatchanged`. The patch modifies the error message in `usage.c` when users attempt to run deprecated commands, replacing a passive "email us" suggestion with proactive troubleshooting steps.

Key technical changes:
- Adds a structured error message listing concrete actions users can take when encountering a deprecated command
- Introduces percent-encoding of the command name for search URL generation
- Removes the "--i-still-use-this" option mention in favor of direct guidance
- Uses `strbuf` to safely construct the search URL

The new message guides users to:
1. Check BreakingChanges documentation
2. Search mailing list archives for prior discussion
3. Contact the list if needed

The patch includes an implementation note about potentially moving BreakingChanges to a man page format, though this would require coordination with other in-flight changes. The change is part of a broader effort to improve the deprecation experience, particularly around `git whatchanged`, by providing clear migration paths rather than just warnings.
