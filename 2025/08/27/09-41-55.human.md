Documentation patch discussion about rev-list` options in `git cherry-pick` and `git revert`.

Phillip Wood responds to Emily Shaffer's v2 patch that adds standard rev-list option documentation to both commands' man pages. While agreeing the documentation is needed, Phillip raises concerns about the verbosity and relevance of including the full rev-list options documentation. He notes this adds significant content before more frequently used options like `--continue` and questions whether sections like bisect, cherry-mark, boundary, history simplification, and commit formatting are actually relevant to cherry-pick/revert operations.

Phillip suggests exploring whether the rev-list-options.adoc file could be modified with additional conditionals to only include the most relevant options for these commands, similar to how other commands selectively include portions of the documentation. This would maintain completeness while reducing noise for users.

The discussion highlights a tension between comprehensive documentation and usability, with Phillip advocating for a more targeted approach that considers the actual use cases of these commands. The patch itself remains technically sound, but this feedback may lead to a v3 that refines the documentation scope.
