This is a status update on the sparse-checkout refactoring series, following Derrick Stolee's recommendation to split the work into two phases. Ayush Chandekar reports progress on moving the sparse-checkout configuration variables (`core.sparsecheckout`, `core.sparsecheckoutcone`, and `sparse.expectfilesoutsideofpatterns`) from globals to `struct repository`.

The email confirms understanding of Stolee's suggested approach: first mechanically moving the globals to `the_repository->sparse_checkout[_cone]` while maintaining current behavior, then later implementing proper per-repo configuration handling. Chandekar has experimented with three different implementation branches exploring storage approaches (int vs boolean values and initialization states), though notes test failures in one approach.

Key technical points for future reference:
- Implementation branches test different storage types (int vs boolean) and initialization states (-1 for uninitialized)
- Phase 2 will require passing repo struct to multiple functions
- Early config parsing behavior differences between `the_repository` and other repos remain a consideration
- Test failures observed when changing initialization behavior

The update shows active development following the phased strategy proposed by Stolee, with multiple implementation approaches being explored while maintaining focus on the core goal of removing these sparse-checkout globals as part of the broader `the_repository` removal effort.
