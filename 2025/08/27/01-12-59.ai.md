This is a refactoring patch in Patrick Steinhardt's ongoing series to migrate packfile management to `struct packfile_store`. The patch introduces a new helper function `packfile_store_load_pack()` that consolidates the common pattern of checking if a packfile exists in the store and adding it if not.

The new function handles:
1. Converting .idx paths to .pack paths for hashmap lookup
2. Checking if the pack is already known
3. Adding new packs via `add_packed_git()` and `packfile_store_add_pack()`

Taylor Blau reviews the changes positively, noting:
- The refactoring correctly preserves behavior while eliminating duplication
- The MIDX pack handling logic is simplified
- Some minor ordering changes in fast-import.c are harmless
- The implementation matches the behavior of the callers being refactored

The patch touches fast-import.c, index-pack.c, midx.c, and packfile.c, standardizing packfile loading across these components. Taylor suggests a potential optimization to avoid string allocation in prepare_pack() but indicates the current implementation is acceptable.

This continues the series' progression toward encapsulating packfile operations in the new store interface, with no new technical concerns raised in this review. The changes are straightforward refactoring with no behavior changes, and Taylor's approval suggests this patch is likely to proceed without further discussion.
