This is the first patch in a three-part series that removes the `core.commentChar=auto` configuration option, now merged into Git. The patch lays the groundwork for deprecating this feature, which will be fully removed in Git 3.0.

The `core.commentChar=auto` feature was originally designed to automatically select a comment character that wouldn't conflict with existing commit message lines, but it has several fundamental limitations. Phillip Wood explains it doesn't work properly with commit templates, prepare-commit-msg hooks, rebase operations (fixup/squash commands), cherry-pick conflict markers, or git notes. These issues stem from the feature's core design and would be difficult to fix properly.

The patch makes several technical changes to start the deprecation process: it adds documentation about the upcoming removal in BreakingChanges.adoc, updates the core.commentChar documentation to explain the limitations, and introduces conditional compilation with `WITH_BREAKING_CHANGES` to prepare for the eventual removal. Several test cases are also marked to be skipped when breaking changes are enabled.

This is a well-justified change that addresses a problematic feature with clear architectural limitations. The patch is thorough, touching all relevant areas including documentation, core functionality, and tests. The commit message provides a comprehensive explanation of why the feature is being removed and what scenarios are affected.
