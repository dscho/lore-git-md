This is a refactoring patch in Patrick Steinhardt's ongoing series to migrate packfile management to `struct packfile_store`. The patch converts `get_all_packs()` to work directly with the packfile store rather than a repository, renaming it to `packfile_store_get_packs()`.

Taylor Blau raises concerns about the change, arguing that removing the convenience wrapper `get_all_packs()` forces callers to explicitly reference the packfile store through `the_repository->objects->packfiles`, which exposes implementation details. He suggests this may be premature optimization given that all current object stores still use packfiles. The patch affects 19 files with mostly mechanical changes to update callers.

The discussion highlights an architectural tension between encapsulation and convenience. While the change aligns with the series' goal of separating packfile concerns from the repository/object-store layer, Taylor questions whether this particular refactor provides enough benefit to justify the added verbosity at call sites. He suggests at least keeping the wrapper function for now, and proposes a local variable pattern to manage line length if the change proceeds.

This continues the thread's recurring theme of balancing clean abstractions against practical API ergonomics, with Taylor advocating for preserving convenience functions during the transition period. The change itself is straightforward but touches many call sites, making the ergonomic impact non-trivial.
