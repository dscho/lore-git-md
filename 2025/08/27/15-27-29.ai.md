This is part 2/3 of a series removing the deprecated `core.commentChar=auto` configuration option, which has already been merged into Git. The patch introduces warning infrastructure for the deprecated setting, with behavior that differs based on whether Git is compiled with `WITH_BREAKING_CHANGES`:

Without the flag, Git emits a one-time warning when commands like `git commit` or `git rebase` encounter `core.commentChar=auto`, using environment variables to prevent duplicate warnings. With the flag enabled, Git instead dies with an error message, previewing the behavior that will become mandatory in Git 3.0.

Key technical components include:
- New `comment_char_config` struct tracking which config key (`core.commentChar` or `core.commentString`) was used to set the value
- `repo_read_config()` callback system to detect deprecated settings
- Environment variable tracking (`GIT_AUTO_COMMENT_CHAR_CONFIG_WARNING_GIVEN`) for single-warning behavior
- Repository flag (`check_deprecated_config`) to suppress warnings during config writes
- Test coverage in t3404 (rebase) and t7502 (commit)

The implementation handles both `core.commentChar` and `core.commentString` aliases, with tailored warning messages indicating which key triggered the deprecation notice. The odd `die_message()+die(NULL)` pattern is explicitly noted as scaffolding for the next patch's advice insertion.

This represents an intermediate state of the series that was later refined based on list discussion, particularly around warning frequency and user experience. The final merged version incorporated additional advice system improvements from subsequent patches.
