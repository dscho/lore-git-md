This is a documentation and user experience patch, part of a series aimed at improving guidance for users of deprecated Git commands like `git whatchanged`. 

The patch modifies the error message shown when users attempt to run commands marked for removal, replacing a generic "email us" suggestion with more actionable steps. The new message directs users to check the BreakingChanges documentation, search mailing list archives for solutions, and only then contact the list if needed. It also removes the "--i-still-use-this" option mention since that would now appear redundant with the more detailed guidance.

The implementation adds URL encoding for the command name to create a proper search link to the mailing list archives. The author notes an alternative approach of making BreakingChanges a proper man page, but defers that decision pending other in-flight changes to the documentation system.

This appears to be a well-considered improvement to the deprecation workflow, providing users with immediate self-help options rather than just asking them to report usage. The patch is cleanly implemented with proper string handling and maintains the existing error exit behavior. As the first in a series about deprecated commands, it sets up the pattern for subsequent patches to follow.
