This is a documentation patch in a series about improving guidance for deprecated commands, specifically `git whatchanged`. It's the third of four patches in Kristoffer Haugsbakk's series.

The patch simplifies the documentation by removing an unnecessary comparison about command length ("not even shorter to type than `log --raw`") from the deprecation warning. It also fixes a grammatical issue by changing "default" to "defaults" to properly reflect that `git whatchanged` differs from `git log` in multiple default behaviors.

The change is straightforward and uncontroversial, aligning with the series' goal of providing clear, concise guidance for users transitioning away from deprecated commands. The patch maintains the key information that `git log --raw --no-merges` is the closest equivalent to `git whatchanged`.

This follows patch 2 in the series which added more detailed migration guidance, and precedes a planned patch 4 that will clarify the deprecation timeline in BreakingChanges.adoc. The series as a whole shows careful attention to both technical accuracy and user experience.
