This is a refactoring patch in Patrick Steinhardt's ongoing series to migrate packfile management to `struct packfile_store`. The patch proposes removing the redundant `get_packed_git()` function in favor of `get_all_packs()`, which provides more complete packfile information including MIDX (multi-pack index) status.

Taylor Blau's review identifies several key considerations:
1. The two functions currently differ in MIDX handling - `get_packed_git()` skips MIDX packs while `get_all_packs()` includes them
2. Most callers appear ready to handle MIDX packs, with two potential exceptions:
   - `cmd_grep()` in builtin/grep.c doesn't actually use the packfile list it requests
   - `want_object_in_pack_mtime()` in builtin/pack-objects.c may process MIDX packs twice
3. The performance impact appears minimal since both functions already load all packfiles
4. The naming could be clearer if both functions are kept (e.g. `get_non_midx_packs()`)

The review suggests the commit message could better explain the safety of transitioning callers and notes the remaining architectural question of whether maintaining two functions with clearer names might be preferable to consolidation. The discussion continues the thread's focus on API clarity and proper handling of MIDX edge cases in the packfile store abstraction.
