This is a bugfix patch addressing a test failure caused by changes in libcurl's logging behavior. The patch adds support for curl's component-specific tracing system to maintain compatibility with newer libcurl versions while keeping the existing test working.

The issue stems from libcurl 8.16-rc2 moving SOCKS-related debug messages from generic tracing to a component-specific system (CURL_TRC_CF). This broke Git's t5564 test which verifies SOCKS proxy functionality by checking for specific trace messages. The patch introduces a new GIT_TRACE_CURL_COMPONENTS environment variable that gets passed to curl_global_trace(), allowing selective enabling of logging components (in this case "socks" for the test).

The implementation is version-aware through a new GIT_CURL_HAVE_GLOBAL_TRACE compatibility define, making it safe with older curl versions. The author considered but rejected hardcoding "all" components due to verbosity concerns, and also contemplated making the test more flexible with message matching. The solution is intentionally undocumented as it's considered internal debugging infrastructure rather than a user-facing feature.

Key technical details for future reference:
- New env var: GIT_TRACE_CURL_COMPONENTS
- Affected files: git-curl-compat.h, http.c, t/t5564-http-proxy.sh
- Curl API used: curl_global_trace()
- Test now requires "socks" component to be explicitly enabled
- Maintains backward compatibility with older curl versions
- Related to libcurl commit ab5e0bfddc which changed SOCKS logging behavior

The patch appears well-considered with appropriate version checking and fallback behavior. The test modification is minimal and focused, though future discussion might debate whether this is the best approach versus adapting the test to match different message formats across curl releases.
