Bugfix and refactoring for Git's slab allocator API, addressing a NULL pointer dereference issue while improving the interface design.

This v2 patch from ノウラ | Flare builds on the ongoing discussion about fixing the slab allocator's cleanup behavior. The key problem is that `clear_alloc_state()` freed memory slabs but left tracking fields (`slab_alloc`, `nr`, and `p`) non-zero, creating potential for NULL pointer dereferences if the alloc_state was reused. The solution combines several improvements:

1. Renames `allocate_alloc_state()` to `alloc_state_alloc()` to follow Git's naming conventions
2. Replaces `clear_alloc_state()` with `alloc_state_free_and_null()` that handles both freeing and nulling in one atomic operation
3. Updates all callers in object.c to use the new API, removing redundant `FREE_AND_NULL()` calls

The changes affect alloc.c, alloc.h, and object.c, with the main safety improvement being that the new API prevents the inconsistent state that caused the original bug. The patch appears well-structured with clear commit message explaining both the technical issue and the solution approach. It aligns with Junio C Hamano's earlier suggestion for a more comprehensive architectural fix rather than just zeroing fields, though it's unclear if this was directly coordinated. The diff shows clean changes to the allocator interface and thorough updates to all call sites. No test case is included, which might be worth noting given the potential severity of the original bug.
