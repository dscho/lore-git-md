Deprecation notice for `core.commentChar=auto` configuration. This is the first patch in a three-part series that removes the problematic auto-comment feature, with changes slated for Git 3.0.

The patch documents the deprecation in BreakingChanges.adoc and updates core.adoc to explain the feature's limitations, including incompatibilities with commit templates, hooks, rebase operations, and git notes. The implementation uses conditional compilation with `WITH_BREAKING_CHANGES` to maintain backward compatibility while preparing for removal. Key changes include:
- Adding deprecation warnings in documentation
- Guarding auto-comment functionality behind `#ifndef WITH_BREAKING_CHANGES`
- Marking affected tests with `!WITH_BREAKING_CHANGES` conditionals
- Preserving the existing comment character selection logic for now

The changes touch core files like environment.c/h and builtin/commit.c, with test updates in t3404, t3418, and t7502. The commit message thoroughly explains the architectural limitations that make the feature unmaintainable, particularly around template/hook interactions and rebase operations. This sets up the foundation for the subsequent patches that will add user warnings and migration advice.
