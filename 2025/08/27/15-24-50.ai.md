This is the final patch in a 6-part series implementing the breaking change to switch Git's default initial branch name from "master" to "main" when built with WITH_BREAKING_CHANGES enabled. The patch completes the implementation after the first five patches updated test infrastructure.

The core changes in this patch:
- Modifies refs.c to use "main" as the hardcoded default branch name when WITH_BREAKING_CHANGES is set, removing the deprecation warning advice
- Updates git-init.adoc documentation with conditional compilation to show both current and future behavior
- Adds the change to BreakingChanges.adoc release notes
- Removes GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME support when WITH_BREAKING_CHANGES is enabled
- Keeps backward compatibility code for old servers that may still use "master"

The patch maintains careful backward compatibility - the advice system still warns about the upcoming change for non-breaking builds, and remote protocol handling still looks for "master" when dealing with older servers. Documentation changes are minimal and focused on git-init.adoc, with other docs left for future updates due to complexity.

Technical details include:
- Changes to refs.c's repo_default_branch_name() to implement the new default
- Advice system modifications in advice.c/h to conditionally compile the warning
- Test updates in t0001-init.sh and t/test-lib.sh to handle the new behavior
- Documentation updates using ifdef/ifndef blocks to show both current and future states

The implementation follows through on the deprecation warning added in 2020 (commit 675704c74dd) and aligns with major Git forges' defaults. The change is gated behind WITH_BREAKING_CHANGES, allowing for gradual ecosystem adoption. The patch appears well-considered with attention to backward compatibility and clear documentation of the transition.
