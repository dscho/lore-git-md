This is a documentation patch discussion regarding the inclusion of rev-list options in `git cherry-pick` and `git revert` man pages. Phillip Wood raises concerns about the current v2 patch's approach of including the full `rev-list-options.adoc` content, which adds substantial documentation before more commonly used options like `--continue`. He questions whether all sections (like `--bisect`, `--cherry-mark`, `--boundary`, history simplification) are actually relevant to these commands, suggesting instead that the documentation should be more selectively included using existing `ifdef` mechanisms in `rev-list-options.adoc`.

The thread context shows this is the first substantive feedback on the v2 patch, which expanded coverage from just `git cherry-pick` (v1) to include `git revert` as well. The core issue remains documenting long-standing but previously only example-documented rev-list options that have been accepted since 2010 (commit f873a273d1). Phillip's comment introduces a new consideration about documentation weight versus completeness, proposing a middle ground between the current undocumented state and the full inclusion approach taken in v2. This may require revisiting the `rev-list-options.adoc` conditional inclusion system to better serve these sequencer commands.
