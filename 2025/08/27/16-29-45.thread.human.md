This thread documents the evolution of a comprehensive command deprecation framework for Git, now in its sixth iteration. The series introduces infrastructure to mark commands as deprecated (with a `DEPRECATED` flag), provides alias shadowing support, and offers user guidance for transitioning away from deprecated commands like `git whatchanged`.

The latest version (v6) includes significant improvements to the deprecation messaging, particularly in patch 7/9 which added specific migration hints showing users exactly how to replace `git whatchanged` with `git log --raw --no-merges`. The new patch (8/9) refines the documentation further by making the warning message more factual - removing subjective comparisons about typing length and properly noting that `whatchanged` has different defaults (plural) rather than a singular default behavior difference.

Key contributors Junio Hamano and Jeff King have maintained approval of the core approach throughout the series' progression. The framework is now complete with all technical aspects addressed, including build system integration, alias handling with recursion detection, and comprehensive test coverage. The documentation updates in this latest patch represent final polishing of the user-facing messaging before the series is likely to be merged.
