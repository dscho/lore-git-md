This thread has finalized the implementation of Git's command deprecation framework with alias shadowing support, now ready for integration. The series, originally proposed by Kristoffer Haugsbakk, allows marking commands like `whatchanged` and `pack-redundant` as deprecated while ensuring they can still be referenced via aliases without infinite recursion.

The technical work is complete after four iterations, with Junio Hamano confirming all recursion cases are properly handled - including both simple self-referential aliases and complex inter-command cycles. Jeff King contributed key architectural refinements, moving the recursion detection logic from `run_argv()` to `handle_alias()` for better structure. The current discussion revolves around minor polish of error message formatting when recursive aliases are detected.

Kristoffer has decided to keep the current error reporting behavior in the upcoming v5, as the informational messages only appear in `-h` help cases and don't affect normal usage. This represents the final discussion point before the series can be merged, with all substantive technical concerns already addressed and maintainer approval secured. The implementation includes comprehensive test coverage and handles all identified edge cases while maintaining clean separation between the deprecation system and core alias functionality.
