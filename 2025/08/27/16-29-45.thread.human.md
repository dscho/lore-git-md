This thread is about finalizing a series to improve Git's command deprecation system, particularly adding support for alias shadowing of deprecated commands like `whatchanged` and `pack-redundant`. The fourth version of the series is nearly complete, having received thorough review from key contributors.

Junio Hamano has approved the overall design pending resolution of one remaining technical issue - a memory leak in the alias lookup path identified by Jeff King. Patrick Steinhardt, who provided significant structural feedback earlier in the review process, has now confirmed that his concerns about the command listing infrastructure (patch 1/7) have been fully addressed. The implementation properly handles include/exclude semantics for command filtering and the `--list-cmds=deprecated` interface.

With Patrick's sign-off, the memory leak fix in patch 2/7 remains the only outstanding issue before the series can be integrated. The team is considering two approaches to resolve it - either explicitly freeing the `alias_lookup()` result or creating an `alias_exists()` wrapper. Once this final technical hurdle is cleared, the well-vetted series appears ready for inclusion in the 'next' branch.
