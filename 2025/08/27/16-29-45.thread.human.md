This thread documents the successful deprecation process for `git whatchanged`, now merged with a clear three-step pattern (notice/alternatives/contact) that will serve as a model for future deprecations. Kristoffer Haugsbakk's series implemented runtime warnings linking to documentation, with technical refinements addressing edge cases like empty commit behavior (noted by Peff) and command translation to `git log --raw --no-merges`.

While the core implementation is complete, post-merge discussion has revealed new considerations around interactive usage. A key limitation emerged: Git's alias system currently prevents shadowing builtin commands, meaning users can't create a `whatchanged` alias during the deprecation period. Peff referenced an August 2025 proposal for allowing exceptions to this rule specifically for deprecated commands. Eric Sunshine acknowledges this constraint while maintaining that the current warnings - though thorough for scripted use - may still leave interactive users confused when muscle memory leads them to type the deprecated command.

The thread captures an ongoing tension between documentation-based guidance (Kristoffer's preference) and runtime solutions (Eric's suggestion), now complicated by technical constraints of the alias system. Junio notes users' tendency to email rather than investigate alternatives, suggesting the project may need to accept some support burden during transition periods. With the 2.51.0 approaching, attention turns to measuring real-world impact and considering backports, while Jean-Noël Avila's documentation format changes may affect how these warnings are presented long-term.
