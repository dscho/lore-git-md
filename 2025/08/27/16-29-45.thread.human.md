This thread documents the deprecation of `git whatchanged` and the project's evolving approach to guiding users through such transitions. The original patch series by Kristoffer Haugsbakk implemented a three-step deprecation pattern (notice/alternatives/contact) that was merged after technical refinements, including Jeff King's note about empty commit behavior differences.

Post-merge discussion has revealed two distinct user patterns: scripted usage (handled by the current implementation) and interactive usage (now the focus). Eric Sunshine suggested enhancing runtime messages with minimal alias suggestions for interactive users, but Kristoffer maintains concerns about information overload and prefers documenting solutions in BreakingChanges.adoc. The latest exchange highlights a technical constraint: Git's design prevents shadowing builtins with aliases, making exact command aliases impossible. Kristoffer references Jeff King's earlier proposal about loosening alias rules for deprecated commands as a potential solution, while questioning whether slightly different command names (like `whatchange`) would confuse users.

Junio Hamano has observed that users often email for help rather than investigating alternatives, underscoring the challenge of balancing thorough guidance with support burden. The discussion now grapples with how to best serve different user workflows within Git's technical constraints, with the alias limitation adding a new dimension to the debate between runtime messages versus documentation-based guidance.
