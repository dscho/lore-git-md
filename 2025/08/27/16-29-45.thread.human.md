This thread documents the deprecation of `git whatchanged` and the project's evolving approach to communicating breaking changes to users. Kristoffer Haugsbakk's patch series established a three-step deprecation pattern (notice/alternatives/contact) that has now been merged, with technical implementation including a new `you_still_use_that()` helper function in `usage.c` that generates deprecation messages with alternative command suggestions.

While the core implementation is settled, post-merge discussion has shifted to refining how these messages are presented to users. Eric Sunshine noted that the current guidance focuses primarily on scripted usage, while interactive users relying on muscle memory or mnemonics might need different advice. Kristoffer acknowledges the challenge of balancing thorough guidance with clarity, observing that lengthy messages sometimes cause users to miss key information. The consensus emerging is to document interactive-use solutions (like aliases) in the BreakingChanges.adoc file rather than expanding the runtime error message.

Maintainer Junio Hamano has provided insight into typical user behavior patterns, noting that users often email for help rather than investigating alternatives themselves. This discussion represents Git's ongoing effort to improve how it communicates breaking changes, with this series serving as a model for future deprecations. The technical work is complete, but the project continues to refine the user experience aspects based on real-world usage patterns.
