The command deprecation framework series has now reached completion with the resolution of the final build system issue. The series, which introduces alias shadowing and a formal deprecation mechanism for Git commands, had been approved in principle since v4 but needed one last fix to properly handle the Makefile integration for deprecated commands like `git-whatchanged`.

Jeff King identified and proposed a solution for the issue where `git-whatchanged` was incorrectly remaining in the `BUILT_INS` list when built with breaking changes enabled, causing confusing error messages. Kristoffer Haugsbakk incorporated this fix into the series, which Junio Hamano has now acknowledged as properly addressing the oversight. The change ensures deprecated commands are consistently handled across both the command list and build system, producing the expected "not a git command" message rather than a misleading error about built-in handling.

With all technical aspects now addressed - including alias shadowing behavior, error messaging, documentation updates, and this final build system integration - the series appears ready for merging. The implementation has benefited from thorough review by multiple contributors, with Junio maintaining oversight throughout the iterations. The framework will allow for smoother transitions when commands are deprecated in future Git releases.
