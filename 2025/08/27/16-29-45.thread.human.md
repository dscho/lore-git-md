This thread documents the deprecation process for `git whatchanged`, now merged with a three-step deprecation pattern (notice/alternatives/contact) implemented by Kristoffer Haugsbakk. The series added documentation about behavior differences and alternative commands (`git log --raw --no-merges`), plus a helper function for deprecation warnings.

Post-merge discussion has revealed a key technical constraint: Git's alias system currently prevents shadowing builtin commands, meaning users can't create a `git whatchanged` alias while the builtin still exists. Jeff King (Peff) notes this limitation and references his earlier proposal to allow exceptions for deprecated commands. This impacts the practical usefulness of recommending aliases during the deprecation period.

The discussion now balances several considerations: whether to enhance runtime messages (Eric Sunshine's suggestion), document solutions in BreakingChanges.adoc (Kristoffer's preference), or modify Git's alias rules (Peff's proposal). Junio Hamano observes that users often email for help rather than investigating alternatives themselves, highlighting the challenge of effective communication during deprecations. The thread remains technically settled but continues exploring how best to guide users through this transition.
