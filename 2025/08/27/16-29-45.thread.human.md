This thread focuses on improving user guidance around deprecated Git commands, particularly `git whatchanged`. Kristoffer Haugsbakk's four-patch series (currently at v1) aims to provide clear alternatives when users encounter deprecated functionality while cleaning up documentation.

The series has received positive feedback from maintainer Junio Hamano, who praised the documentation improvements. The technical changes include structured error messages, a new hint parameter for deprecated commands, and specific command translations (like suggesting `git log --raw --no-merges` as a modern alternative to `git whatchanged`).

A minor whitespace issue in patch 2 was recently identified - the author accidentally mixed tabs and spaces in `builtin/log.c` due to an editor configuration problem. Kristoffer quickly acknowledged this and noted the usefulness of Git's `ci/check-whitespace.sh` script in catching such issues. Since the substantive content of the patches was already approved, this formatting fix should be straightforward to address in v2.

The series appears on track for potential inclusion, with only this minor formatting correction and some remaining questions about documentation format migration and timing considerations to resolve. Junio's continued positive reception suggests the changes are well-aligned with the project's direction for handling deprecated functionality.
