This thread has been working through the final details of implementing a command deprecation system in Git, with a focus on properly handling the removal of `git-whatchanged` and other deprecated commands. The core approach - using alias shadowing and a `DEPRECATED` flag - was approved in earlier iterations, and the current discussion centers on a build system issue that emerged during testing.

Jeff King identified that the Makefile wasn't properly excluding `git-whatchanged` from the built-ins list when built with breaking changes enabled, causing the deprecation system to misclassify the command. Kristoffer Haugsbakk confirmed this behavior and verified that a proposed Makefile change would resolve it, though existing installations might need manual cleanup of stale executables. 

The series is otherwise complete, with comprehensive test coverage, documentation updates, and all other technical aspects addressed. Junio Hamano had previously approved the core approach, and Eric Sunshine provided feedback that's been incorporated. The final step is to land the Makefile fix, after which the deprecation system should be ready for merging. This will provide a structured way to phase out commands like `whatchanged` while giving users clear migration paths through aliases and error messages.
