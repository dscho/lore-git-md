This is a response in the ongoing discussion about Rust adoption in Git, specifically addressing platform compatibility concerns. Brian m. carlson pushes back against Randall Becker's proposal to make Rust optional for certain commands while keeping core functionality in C.

The response argues that Rust integration will touch fundamental code paths (diff, index-pack, fetch-pack, etc.) that are too pervasive to make optional without significant complexity. Carlon cites the memory safety benefits of Rust (reducing 70% of vulnerabilities in memory-unsafe code) and references Git's existing non-goals document which explicitly rejects maintaining parallel C implementations. They also note broader industry trends toward memory-safe languages, including U.S. government recommendations.

The tone is firm but constructive, acknowledging the platform concerns while maintaining that Rust adoption in core functionality is both necessary and inevitable for security and future viability. This appears to be a key moment in the Rust adoption debate, with Carlon representing the core maintainer perspective that optional Rust would undermine the project's safety goals.
