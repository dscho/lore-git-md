This is a security and sustainability review of the SMTP autoconfiguration feature for `git send-email`. Brian Carlson raises two important points about the proposed `--get-smtp-server` implementation that queries Mozilla's ISPDB service.

First, they question whether Mozilla has explicitly consented to Git embedding their Thunderbird autoconfig service, noting the long-term implications of hardcoding such dependencies in widely-distributed software. They cite historical cases where similar integrations caused unintentional DDoS effects due to scale and longevity (Git installations may persist for 12+ years with millions of daily uses).

Second, they identify a security vulnerability in the HTTP request implementation - the code fails to explicitly enable SSL certificate verification in HTTP::Tiny, which defaults to insecure behavior in older Perl versions (pre-0.083) that Git still supports. This would allow MITM attacks during SMTP config fetching.

The message doesn't reject the feature outright but insists these operational and security considerations must be resolved before inclusion. It suggests the Mozilla integration might need removal if permission isn't secured, and the SSL verification is a mandatory fix. These are the final substantive issues raised in what has otherwise been a well-received patch series now at v4.
