Emily Shaffer's documentation patch series aims to properly document rev-list options that `git cherry-pick` and `git revert` have accepted since 2010 but were only mentioned in examples. The v2 patch expanded coverage to both commands by including the standard `rev-list-options.adoc` section, following the pattern used by other Git commands.

Phillip Wood has raised an important consideration about the current approach - while complete, the full rev-list options documentation includes many sections (like bisect and boundary options) that may not be relevant to these sequencer commands. He suggests using the existing `ifdef` system in `rev-list-options.adoc` to selectively include only the applicable options, keeping the documentation focused on what users actually need for cherry-pick and revert operations. This would address the original oversight while avoiding information overload.

The patch appears technically sound but may benefit from this refinement before merging. Andrew Jeffery's earlier attribution correction can be handled during application. The discussion now turns to finding the right balance between documentation completeness and usability for these specific commands.
