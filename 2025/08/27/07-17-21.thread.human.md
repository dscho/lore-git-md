This thread discusses how to properly document the rev-list options that `git cherry-pick` and `git revert` have accepted since 2010 but never documented. Emily Shaffer's patch initially proposed including all rev-list options via standard includes, but Phillip Wood raised concerns about including irrelevant options like `--bisect`. 

Junio C Hamano has now weighed in, strongly supporting a more selective approach. He notes the documentation system already has an `ifdef` mechanism to filter options and points to `--graph` as another clearly irrelevant option for these commands. His intervention shifts the discussion from whether to be selective to how to implement that selectivity.

The key open question is which rev-list options actually make sense for cherry-pick/revert. The thread now awaits either a revised patch implementing selective inclusion or further discussion to identify the relevant options. Given Junio's input, the solution will likely involve extending the existing `ifdef` system rather than including all options indiscriminately.
