This thread wraps up the multi-year effort to change Git's default branch name from "master" to "main" when built with the WITH_BREAKING_CHANGES flag enabled. The technical implementation is now complete and merged, with the final patches refining the test suite and advice messaging strategy for the transition period.

The series, which builds on a deprecation warning introduced in 2020, makes the change opt-in via compile-time flag while maintaining backward compatibility. Key technical work included updating repo_default_branch_name() in refs.c, standardizing test suite handling of GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME, and finalizing the advice system. The advice messages now focus specifically on helping users rename branches when following old tutorials, deliberately avoiding encouragement of permanent configuration changes.

Phillip Wood has raised one remaining test suite question about whether to maintain conditional expectations for advice output when init.defaultBranch is unconfigured, given that the advice system has been simplified. This appears to be the last minor point in an otherwise settled discussion. Junio Hamano has shepherded the series to completion, with previous approvals from Johannes Schindelin and brian m. carlson remaining valid. The change is documented as applying only to new repositories, with the implementation now in its final form after addressing all substantive technical feedback.
