This thread documents the final stages of a multi-year effort to change Git's default initial branch name from "master" to "main" when built with the WITH_BREAKING_CHANGES flag enabled. Phillip Wood has submitted a revised 4-patch series that implements the change while maintaining backward compatibility, following up on a 2020 deprecation warning. The implementation updates the repo_default_branch_name() function, modifies documentation, and cleans up remaining test cases that still referenced "master".

The technical discussion has largely converged, with consensus reached about maintaining the GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME test infrastructure while considering future approaches. The only remaining open question is whether the reftable backend specifically requires "master" as a branch name or could use any 6-byte identifier - Junio Hamano suggested testing this with "banana" as an example. Patrick Steinhardt has requested clarification on this implementation detail.

The series has been revised to address prior feedback, particularly around documentation clarity (the change only affects new repositories) and test infrastructure. Most technical objections have been resolved, and the patches appear ready for final review. This represents the culmination of an effort that began when major Git forges like GitHub and GitLab switched their defaults, with the project now providing an opt-in path for this change while preserving compatibility for existing workflows.
