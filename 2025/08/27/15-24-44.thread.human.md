This thread proposes changing Git's default initial branch name from "master" to "main" when built with WITH_BREAKING_CHANGES enabled. The series follows through on a deprecation warning introduced in 2020, aligning with industry practice where major forges like GitHub and GitLab have already made this transition.

The first five patches methodically updated test infrastructure to use "main" instead of "master" or environment variables, touching over 100 files to ensure test stability before the core change. The final patch (6/6) now implements the actual behavior change in refs.c and advice.c, while maintaining careful backward compatibility. When WITH_BREAKING_CHANGES is enabled, new repositories will default to "main", the deprecation notice is removed, and the transitional GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME variable is dropped. The implementation still handles old servers expecting "master" and documents the current and future states conditionally in git-init.adoc.

The change appears well-considered, with attention to both forward progress and backward compatibility. While the technical implementation is now complete, the thread hasn't yet discussed when or how the project might enable WITH_BREAKING_CHANGES by default - that timing and migration strategy remains an open question. The series follows Git's conservative approach to breaking changes, giving the ecosystem years to prepare while now providing a clear path forward.
