This thread documents the final steps in implementing Git's long-planned switch from using "master" to "main" as the default branch name when built with the WITH_BREAKING_CHANGES flag enabled. The 6-patch series, building on a 2020 deprecation warning, updates test infrastructure and core behavior while maintaining backward compatibility.

Junio C Hamano has reviewed the changes positively overall, approving the documentation updates and core implementation in refs.c and advice.c that conditionally return "main" as the default branch name. However, he maintains a strong position about preserving test infrastructure like GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME, arguing this should be viewed as one step in an evolving naming convention rather than a permanent solution. The series author has addressed Junio's technical feedback about reftable constraints by making t0613 explicitly use --initial-branch=master.

With 110 files modified, the changes are comprehensive but carefully gated behind the breaking changes flag. The only remaining discussion point is whether to maintain test infrastructure that could support future naming changes, reflecting Junio's view that "main" may not be the final word on default branch naming. The technical implementation itself appears uncontested and ready for merging.
