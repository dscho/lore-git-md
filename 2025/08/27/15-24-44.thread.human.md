This thread discusses the ongoing effort to change Git's default branch name from "master" to "main" when built with the WITH_BREAKING_CHANGES flag enabled. The 6-patch series implements this long-planned change following a 2020 deprecation warning, while maintaining backward compatibility.

Junio Hamano and Phillip Wood have been debating test infrastructure maintenance - Phillip argues the GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME variable was meant as transitional, while Junio advocates keeping it for future flexibility. In the latest exchange, Junio agrees that hardcoding "main" in test expectations (t0018-advice.sh) makes sense now, but suggests an auto-adjusting test would be better for future changes. He also questions whether switching from "trunk" to "main" in tests provides much long-term benefit.

The discussion has expanded to include practical migration considerations. Junio describes the current workaround of pushing to both 'master' and 'main' simultaneously (used on git.kernel.org) and the CI challenges this creates on GitHub. He suggests modifying GitHub workflows to exclude one branch when the time comes to fully transition.

While the technical implementation appears sound, the core disagreement about maintaining test infrastructure for potential future changes remains unresolved. The series otherwise seems ready to proceed, representing an alignment with current industry practice while being appropriately gated behind a breaking changes flag.
