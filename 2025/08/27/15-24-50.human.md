This is the final patch in a 6-part series implementing the long-planned change of Git's default initial branch name from "master" to "main" when built with WITH_BREAKING_CHANGES enabled. The series has been working through test updates first, and this patch now implements the core behavior change.

The patch updates the default branch name logic in refs.c to use "main" when WITH_BREAKING_CHANGES is set, removing the warning advice that was added in 2020. It also removes support for the GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME environment variable in this mode. The documentation in git-init.adoc is updated with conditional formatting to show both the current and future behavior, while BreakingChanges.adoc gains a new entry explaining the change.

Notably, the patch leaves some documentation (like gitcore-tutorial.adoc) unchanged due to the impracticality of mass updates via ifdefs, suggesting these can be updated during the 3.0 release cycle. The implementation is careful to maintain compatibility with older servers that might still use "master" in protocol interactions.

This appears to be a well-considered implementation of a change that's been in the works for years, following industry trends while providing a clear migration path. The patch maintains backward compatibility through the build flag and handles edge cases like old servers gracefully. The series has taken a methodical test-first approach, with this final implementation building on the test updates from previous patches.
