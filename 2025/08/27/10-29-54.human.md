This is a feature proposal for adding comment functionality to Git commits. Rune Philosof suggests introducing a way to attach supplemental comments to existing commits, which would be displayed alongside the original commit message when using `git show`. The proposal notes this could integrate with existing platform features like GitHub's commit comments.

The suggestion appears motivated by the common need to add forgotten information to commit messages after the fact. The email briefly mentions a potential implementation approach using a new field to link comment commits to their targets, with indexing for performance. However, no concrete implementation details or patches are provided.

The proposal touches on an interesting gap in Git's functionality, as commit message augmentation currently requires rewriting history. However, the email doesn't address how this feature would interact with Git's distributed nature or how comment conflicts would be resolved when repositories are synced. The suggestion to integrate with GitHub comments hints at platform-specific considerations that might complicate a core Git implementation.

This appears to be an early-stage idea rather than a fully formed proposal. The lack of technical specifics makes it hard to assess feasibility, though the core concept of commit annotations has merit and could spark productive discussion about Git's metadata capabilities.
