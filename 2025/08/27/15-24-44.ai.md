This is a cover letter for a feature series proposing to change Git's default initial branch name from "master" to "main" when WITH_BREAKING_CHANGES is enabled. The series consists of 6 patches, with the first 5 updating tests that currently expect "master" as the default branch, and the final patch making the actual switch.

The motivation cites that major Git forges have already made this change and that Git has been warning about this upcoming change since 2020 (commit 675704c74dd). The test updates are largely mechanical renames of test files and references from "master" to "main", with patch 2 being particularly large but mechanically generated for easier review.

Key technical points for future reference:
- Changes are gated behind WITH_BREAKING_CHANGES flag
- Removes GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME when enabled
- Updates Documentation/BreakingChanges.adoc and git-init.adoc
- Modifies refs.c and advice.c/h for the new default
- Extensive test updates across multiple test files (t0018, t4013, t9902, etc.)
- 109 files changed with 281 insertions and 253 deletions

The series appears well-structured with a clear progression from test preparation to the actual change. The mechanical nature of most changes suggests lower risk of functional issues, though the breaking change nature may warrant discussion about timing and migration impacts.
