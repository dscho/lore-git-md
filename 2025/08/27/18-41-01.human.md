This is the final patch in a 6-part series implementing the long-planned change to make "main" the default branch name when Git is built with WITH_BREAKING_CHANGES enabled. The patch updates documentation, removes the deprecated branch name advice, and implements the core behavior change in refs.c.

Junio C Hamano reviews the changes and generally approves of the implementation, calling several parts "Good" and the refs.c changes "Very good". However, he raises two specific concerns marked as "Questionable": the GIT_TEST_DEFAULT_INITIAL_BRANCH_NAME environment variable removal in ci/run-build-and-tests.sh and the related change in refs.c. These echo his earlier thread comments about maintaining test infrastructure flexibility for potential future naming changes.

The patch follows through on the 2020 deprecation warning by making "main" the default branch name for users opting into breaking changes, while maintaining backward compatibility. Documentation is updated to reflect both the current state and future plans, with conditional blocks in git-init.adoc to handle both WITH_BREAKING_CHANGES and non-breaking builds.

Junio's review suggests the series is technically sound but hints at an ongoing discussion about whether this should be viewed as a permanent solution or just one step in evolving naming conventions. His approval of the core implementation while questioning the test infrastructure removal indicates the change is likely to proceed but may see further refinement around testing flexibility.
