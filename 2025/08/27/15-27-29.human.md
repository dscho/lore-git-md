This is part 2 of a 3-patch series removing the deprecated `core.commentChar=auto` configuration option, which has already been merged into Git. The series addresses architectural limitations in the auto-comment feature that caused problems in various Git operations.

This particular patch introduces warnings when users have `core.commentChar=auto` or `core.commentString=auto` configured, preparing for the feature's eventual removal in Git 3.0. The warnings are carefully designed to avoid being overly noisy - they only appear once per command and only for commands that invoke the commit machinery (commit, merge, rebase, revert). The implementation includes infrastructure to track which config option was used (`commentChar` vs `commentString`) to provide tailored warning messages.

The patch adds a well-considered deprecation framework that:
- Uses environment variables to prevent duplicate warnings in subprocesses
- Includes both warning (current behavior) and die (future 3.0 behavior) paths
- Adds comprehensive test coverage in t3404 and t7502
- Carefully handles read-only config files

This represents a middle ground between verbose user assistance and implementation simplicity, as discussed in the thread. The work integrates with Patrick Steinhardt's ongoing `config-wo-the-repository` refactoring effort.
