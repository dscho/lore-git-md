This is a feature patch that enhances the advice system for deprecated `core.commentChar=auto` configuration. The patch adds detailed, context-sensitive advice that helps users transition away from the deprecated auto-comment feature by providing specific commands to either unset the config or set a custom comment string.

The implementation tracks where each config key is set (system, global, local, worktree) and whether it appears multiple times in a file, then produces tailored advice based on the user's write permissions and config structure. The advice includes:
- Instructions to unset all occurrences of the problematic config
- Guidance for setting a custom comment string
- Special handling when system config is read-only (suggests global config changes instead)

The patch modifies `config.c` to track config origins and adds new helper functions to generate the advice strings. It includes tests verifying the advice appears correctly in both warning (pre-3.0) and fatal error (post-3.0) scenarios. The implementation is thorough, handling edge cases like multiple definitions in included configs and different config scopes.

Key technical details:
- New `comment_char_config` struct tracks config file origins via `item` array
- `strintmap` tracks whether keys appear multiple times in files
- Advice generation considers write permissions via `access()` checks
- Scope-specific advice uses `--system`, `--global`, `--worktree` flags appropriately
- Tests cover simple cases, included configs, and multiple definitions

This appears to be the final piece of a series phasing out `auto` comment behavior, building on earlier warning infrastructure. The implementation is careful and user-focused, providing actionable steps rather than just warnings.
