This is a documentation patch addressing an oversight in `git cherry-pick`'s man page. The patch adds a reference to `rev-list-options.adoc` to properly document rev-list options that have been accepted by `git cherry-pick` since 2010 but were only mentioned in examples rather than formally documented.

The change is straightforward - it inserts a single include directive to pull in the standard rev-list options documentation. The commit message notes this was reported by Andrew Jeffrey after noticing the options were undocumented despite being usable. The author, Emily Shaffer, points out that while the rev-list options documentation is verbose, it's better than having undocumented or semi-documented features.

The patch appears well-justified and correctly implemented. It follows Git's standard documentation practices by including the shared rev-list options section, which is done for other commands as well. The commit message provides clear historical context (referencing commit f873a273d1) and links to the original report. This is a low-risk documentation improvement that closes a long-standing documentation gap.
