This is a discussion about the SMTP autoconfiguration feature for `git send-email`, specifically raising concerns about Mozilla's ISPDB service usage and SSL verification.

Brian M. Carlson raises two important points about the proposed `--get-smtp-server` feature. First, they question whether Mozilla has explicitly granted permission for Git to use their ISPDB service at scale, noting that hardcoding such dependencies can create long-term maintenance burdens and potential service abuse risks (citing historical examples of embedded services causing DDoS issues). They emphasize that Git userbase's size means even rare usage patterns could create significant load.

Second, they identify a security vulnerability in the implementation - the HTTP request code needs explicit SSL certificate verification (`verify_SSL => 1`) since older Perl versions (which Git still targets) default to insecure behavior. This is a concrete security fix that would need addressing regardless of the ISPDB question.

The email doesn't oppose the feature outright but calls for due diligence on service dependencies and immediate correction of the security issue. It comes late in the thread (v4) but raises fundamental questions about sustainability and security that weren't previously discussed. The tone is constructive but firm about these being blocking concerns before inclusion.
