This is part 3/4 of a refactoring series in the ongoing `the_repository` removal effort, focusing on the bulk-checkin subsystem's transaction management. The patch makes transactions mandatory for `index_blob_bulk_checkin()` by eliminating its fallback behavior for non-transactional cases, simplifying the implementation by merging `deflate_blob_bulk_checkin()` into it.

The key technical changes include:
- Removing the conditional transaction handling in `index_blob_bulk_checkin()`, which previously had separate paths for transactional vs non-transactional cases
- Combining `deflate_blob_bulk_checkin()` into `index_blob_bulk_checkin()` since the separate function is no longer needed
- Updating `index_fd()` to explicitly create and manage transactions when calling `index_blob_bulk_checkin()`
- Clarifying documentation to emphasize the now-mandatory transaction requirement
- Maintaining the same behavior through transaction nesting in `begin_odb_transaction()`

The changes affect bulk-checkin.c, bulk-checkin.h, and object-file.c, with significant line reductions from removing the dual-path implementation. This continues the series' progression toward stricter transaction requirements while preserving existing functionality through proper transaction management at call sites. The patch follows through on earlier discussion points regarding transaction documentation and function organization.
