This is the fifth patch in Patrick Steinhardt's RFC series introducing a new `git-history` command with `drop`, `reorder`, and `split` subcommands. The patch implements the core functionality for the `drop` subcommand, which removes commits from history.

The implementation builds on Git's sequencer infrastructure and includes careful validation of commit relationships - ensuring the "old commit" is actually an ancestor of HEAD and rejecting merge commits for now. The code collects commits in a range and prepares them for processing by the sequencer.

Ben Knoble pointed out two minor issues in review: a stale comment about array swapping (which Patrick acknowledges and will fix) and a suggestion to clarify "old commit" terminology. Patrick confirms both observations and notes the sequencer API's learning curve.

This appears to be solid technical work that moves the RFC forward, though the discussion reveals some implementation details that still need polish. The patch maintains the series' incremental approach while handling edge cases conservatively (like rejecting merges for now). Readers interested in history rewriting functionality or sequencer internals will want to examine this closely.
