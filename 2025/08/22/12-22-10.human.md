This is the final patch in Patrick Steinhardt's RFC series introducing the new `git-history` command, implementing the "split" subcommand. The subcommand allows interactively splitting a commit into two by selecting which hunks should go into a new commit that becomes the parent of the original.

The discussion focuses on several UX details of the split operation:
- Whether to show the original commit message as a template for both new commits (currently only shown for the split-out portion)
- Improving the commit message template to match Git's standard format and include more context
- Behavior when aborting the operation (currently loses staged changes, unlike interactive rebase)
- Documentation needs for the pathspec filtering capability

Patrick acknowledges these as valid points to address in v2, particularly around the commit message template and documentation. The thread shows active collaboration on refining the implementation details while maintaining the core functionality. This patch completes the initial feature set (drop/reorder/split) proposed in the RFC, with clear paths identified for improvement in the next iteration.
