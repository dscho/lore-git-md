This is a bug report about `git status` behavior being inconsistent depending on file modification timing. Damien Cassou reports that when a file is modified rapidly (without the 1-second delay in their test script), `git status` fails to detect the changes, but with the delay it works correctly. The issue occurs across platforms (macOS and Linux) with Git 2.50.1.

The report notes two key observations: (1) if the file's modification timestamp changes, `git status` always detects the change, and (2) if the file size changes, detection also works reliably. The core question is why timing affects this behavior and where in Git's code this logic is implemented.

This appears to be a real edge case where Git's` stat-based change detection can miss rapid modifications, likely related to filesystem timestamp granularity or caching behavior. The report is well-structured with clear reproduction steps and platform details, making it easy to investigate. The behavior seems unintentional and worth fixing, though the impact may be limited to very rapid file modifications.
