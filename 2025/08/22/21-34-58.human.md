This is part 2/4 of a refactoring series in the ongoing `the_repository` removal effort, focusing on the bulk-checkin subsystem. The patch removes global transaction state from bulk-checkin operations, moving it into `struct object_database` instead.

The key change is converting the static `transaction` variable into a proper type stored in each repository's object_database. This affects all transaction-related functions (`begin_odb_transaction`, `flush_odb_transaction`, `end_odb_transaction`), which now take the transaction as a parameter. The patch updates all callers across builtin commands (add, unpack-objects, update-index) and core functions (cache-tree, read-cache) to handle the new transaction parameter.

The implementation maintains the same behavior while enforcing stricter transaction requirements. Transaction state now includes a reference to its owning object_database, and the patch ensures proper cleanup when transactions end. This is a well-contained change that builds on the previous patch's introduction of `struct odb_transaction` and moves the bulk-checkin subsystem closer to being free of global state.

The patch appears carefully implemented with thorough updates to all affected call sites. It's part of a well-reviewed series that's making steady progress toward the larger goal of removing `the_repository` global and supporting pluggable ODB backends.
