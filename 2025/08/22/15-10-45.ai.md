Feature: SMTP autoconfiguration for `git send-email` via `--get-smtp-server` (v3)

This patch series continues to refine the SMTP autoconfiguration feature for `git send-email`, now at version 3. The core functionality remains automatic SMTP server discovery through three fallback methods, but the sequence has been reordered to check provider-specific autoconfig endpoints before Mozilla's ISPDB, matching Thunderbird's behavior.

Key technical updates in v3:
- Added support for `.well-known/autoconfig/mail/` path variant
- Enhanced authentication method reporting (now lists all supported mechanisms)
- Added explicit warning for unencrypted connections
- Improved OAuth2 guidance with documentation references
- Provides copy-paste ready config commands (global vs repo-specific)
- Better error messages suggesting `--get-smtp-server` when SMTP init fails
- Fixed email validation and XML parsing edge cases from v2

The implementation adds 5 new Perl dependencies (Net::DNS, URI::Escape, XML::LibXML etc.) and touches both the main script (219 new lines) and documentation (51 lines). The output format now clearly maps each discovered setting to its corresponding `sendemail.*` config option.

Discussion in previous rounds has focused on dependency weight, OAuth2 handling, and XML parsing robustness. This version appears to address most concerns while maintaining the core value proposition of automatic SMTP configuration. The patch is well-documented with example output and thorough fallback logic.
