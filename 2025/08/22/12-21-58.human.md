This is a patch in Patrick Steinhardt's RFC series introducing a new `git-history` command, specifically addressing in-memory index handling for the interactive patch mode.

The patch adds support for in-memory index patching in `add-patch.c`, with Patrick responding to code review feedback from D. Ben Knoble. Knoble caught a duplicated `read_index_from()` call and questioned whether `discard_index()` should be called for in-memory indices as it is in the regular path. Patrick confirms the duplication was unintentional and explains that discarding the index isn't appropriate for in-memory operations where multiple revisions might be applied to the same index.

The changes are part of the broader effort to build flexible history editing operations, with this particular piece focusing on the plumbing needed to support interactive operations on in-memory index states. The discussion remains technical and focused on implementation details, with Patrick being responsive to the code review feedback.
