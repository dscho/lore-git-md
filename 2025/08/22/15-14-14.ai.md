Feature refinement for `git send-email`'s SMTP autoconfiguration. This v3 patch from Aditya Garg incorporates feedback from Julian Swagemakers on the `--get-smtp-server` functionality, now with several usability improvements.

The key changes in this iteration include reordering the fallback sequence to match Thunderbird's behavior (checking provider-specific autoconfig URLs before Mozilla ISPDB), adding warnings about unencrypted connections ("plain" socketType now triggers an explicit warning), and leveraging `user.email` from gitconfig as the email input default. The patch also now provides copy-paste ready configuration commands to help users apply the discovered settings, similar to Git's identity setup hints.

Technical enhancements include better handling of authentication method reporting (with OAuth2 documentation references) and improved error messaging that suggests using `--get-smtp-server` when SMTP initialization fails. The XML parsing now properly handles various username format placeholders (%EMAILADDRESS%, %EMAILLOCALPART%, %EMAILDOMAIN%) and supports the `.well-known/autoconfig/mail/` path variant as an alternative to autoconfig subdomains.

The implementation remains in `git-send-email.perl` with the same Perl dependencies (Net::DNS, URI::Escape, XML::LibXML). The thread shows active collaboration between Swagemakers and Garg, with this version addressing most of the previously noted concerns while maintaining the core autoconfiguration approach modeled after Thunderbird's system.
