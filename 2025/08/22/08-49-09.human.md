Feature patch adding hostname-based conditional includes to Git config.

This patch introduces a new "hostname:" condition for Git's includeIf mechanism, allowing users to load different configuration files based on their machine's hostname. The implementation uses gethostname(2) to check against the specified hostname in the config, with straightforward string comparison logic.

The motivation is clear - this enables users to maintain different configurations (like work vs. home settings) without needing separate branches or manual switching. The example shows typical use cases for work and home machines. The implementation appears clean, adding about 30 lines to config.c with a simple string comparison at its core.

The patch seems well-structured with proper error handling (checking gethostname() return value) and memory management (using strbuf). However, it lacks test coverage - a notable omission for a feature touching core config functionality. The whitespace changes in the surrounding code (like the indentation changes in include_condition_is_true) seem unnecessary and could be cleaned up.

This would be particularly useful for developers who work across multiple machines with different environments, though some might argue host-specific config could also be managed through existing mechanisms like environment variables. The simplicity of the implementation suggests it's unlikely to be controversial.
