This is part 3/4 of a refactoring series in the ongoing `the_repository` removal effort, focusing on the bulk-checkin subsystem. The patch makes transactions mandatory for `index_blob_bulk_checkin()`, eliminating the previous dual-mode behavior where it could work with or without a transaction.

The key change is that `index_blob_bulk_checkin()` now always requires an explicit transaction parameter, removing the fallback case where it would create a single-object transaction internally. This simplifies the function by merging it with the previously separate `deflate_blob_bulk_checkin()` helper. The main call site in `index_fd()` is updated to handle the new transaction requirements by creating a transaction when needed.

The patch appears well-considered, with clean code changes that maintain the same behavior while enforcing stricter transaction requirements. It's part of a larger effort to move transaction management into `struct object_database` and away from global state, with all feedback from previous versions addressed. The changes are focused on internal plumbing rather than user-facing behavior, but they represent an important step toward supporting pluggable ODB backends in the future.
