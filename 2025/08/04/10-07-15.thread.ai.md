Compiler warning fixes for remote.c and clar.c addressing -Wmaybe-uninitialized under GCC -Og, split into two patches in v2. Jeff King (Peff) restructured builtin/remote.c's `set_head()` to validate the remote name argument immediately before option processing, making `struct remote*` initialization unconditional - implementing Junio Hamano's endorsed approach by improving control flow while eliminating the warning. The change duplicates one usage message line but makes initialization paths unambiguous while preserving identical behavior (failing early if no remote name provided). Denton Liu's clar.c patch initializes `matchlen=0` when no filter is provided, suppressing the warning with a logical default (zero matched bytes).

Patrick Steinhardt acknowledged the clar.c fix and requested Liu submit the same change upstream to clar-test/clar repository, as the maintainer of libgit2 (which uses clar) he recognized this as a generally applicable improvement beyond Git's usage. Liu has now completed this action by submitting and getting merged a pull request to the upstream clar project with the same initialization change. The warning was theoretically impossible to trigger in practice due to the `exact` flag guard, but the initialization provides a clean default state. Technical details remain unchanged from the original patches - remote.c's control flow restructuring by Peff and clar.c's initialization by Liu are both behavior-neutral improvements. The series is fully resolved with consensus established on all patches tested and ready for integration, and the upstream clar PR merged fulfilling the remaining action item. No open questions remain in either the Git codebase or related projects regarding these warnings.
