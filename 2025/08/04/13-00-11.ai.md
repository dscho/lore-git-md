This is a bugfix addressing a compiler warning in the revert/cherry-pick code. The patch deals with a const variable used as a sentinel value that triggers a clang warning under DEVELOPER=1 mode. The variable's address is used to detect whether certain options were set, but its value is never actually read.

The patch explains three possible solutions and chooses the simplest one - initializing the variable to 0 with a clarifying comment. The other considered approaches (using a magic number address or making it static) were rejected as being either technically questionable or potentially confusing. The change is minimal and focused, touching only the variable declaration in builtin/revert.c.

Key technical details for future reference: The sentinel_value is used to distinguish between unset options (address equals &sentinel_value), explicitly disabled options (NULL), and set options (other values). The warning comes from clang-22's -Wdefault-const-init-var-unsafe check when building with DEVELOPER=1. The affected code is in the sequencer logic shared by revert and cherry-pick operations.
