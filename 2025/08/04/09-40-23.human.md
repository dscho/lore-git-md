This is a refactoring patch in Patrick Steinhardt's series to improve reftable compatibility with libgit2. The change replaces Git's internal `QSORT()` macro with the standard `qsort()` function in two places within the reftable writer code. The motivation is straightforward: while `QSORT()` is slightly more convenient (it infers the element size), it's Git-specific and thus creates an unnecessary dependency that prevents the reftable code from being cleanly used by external projects like libgit2.

The patch makes two nearly identical changes - one for sorting ref records and another for log records - each now explicitly passing the element size to `qsort()`. The author also adds a defensive check for empty arrays (the `if (n)` condition), though this wasn't present in the original `QSORT()` usage. This is a clear improvement for the library's portability with minimal risk, as the behavior remains functionally equivalent. The change aligns with the series' broader goal of making reftable a more independent component while maintaining its role within Git.
