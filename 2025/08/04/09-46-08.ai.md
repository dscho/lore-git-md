This is a refactoring patch in Patrick Steinhardt's reflog migration series, focusing on flag behavior for reflog updates. The patch modifies how the `REF_HAVE_OLD` flag is handled during log-only updates, preserving it as a signal that an old OID was provided while skipping verification of that OID against the current ref state.

The key change stops unsetting `REF_HAVE_OLD` for log-only updates, which was previously done to avoid verifying the old OID against the ref's current state. This preserved flag will be used in a subsequent commit as a signal for new reflog-writing behavior. The patch updates four files to maintain this invariant: `refs.c` removes the flag-clearing code, while `files-backend.c`, `refs-internal.h`, and `reftable-backend.c` modify their checks to skip old-oid verification when `REF_LOG_ONLY` is set.

The changes are technically sound, with careful attention to the interaction between `REF_HAVE_OLD` and `REF_LOG_ONLY` flags across all ref backends. The commit message clearly explains the motivation and maintains consistency with the series' focus on reflog integrity during format conversion. This appears to be a well-considered preparatory change for upcoming functionality in the migration infrastructure.
