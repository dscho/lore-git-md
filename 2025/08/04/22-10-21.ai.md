This is a technical review comment on patch 7/9 of the commit-graph global state removal series, focusing on hash algorithm handling. Taylor Blau acknowledges the patch's correctness in removing `the_hash_algo` usage but questions the API design of `parse_commit_graph()`. The current patch adds a separate `hash_algo` parameter alongside the existing `repo_settings`, while Taylor suggests it might be cleaner to pass the full `struct repository*` instead. 

The key technical point is whether commit-graph parsing should accept components (settings + hash_algo) independently or require a complete repository context. Taylor raises the architectural question of whether disassociated settings/hash_algo pairs would ever be meaningful, implying the repository abstraction might be the more natural boundary. This continues the series' theme of repository context propagation but focuses on API design rather than the integer type debates seen in earlier patches.

The comment doesn't challenge the patch's correctness or the broader direction of removing globals, but seeks clarification on this specific interface choice. It represents a thoughtful review point about abstraction boundaries that could influence how future pluggable ODB implementations interact with the commit-graph system. The question remains open-ended, inviting either justification for the current approach or consideration of the repository-based alternative.
