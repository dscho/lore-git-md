This is the first patch in a two-part bugfix series addressing an incorrect BUG() assertion in remote.c. The patch adds a test case that demonstrates the issue: when pushing with a non-existent object ID (like all-zeros) to an unqualified ref destination (e.g. "branch" instead of "refs/heads/branch"), Git incorrectly triggers a BUG() claiming the object ID should be valid, when the real problem is the unqualified refname.

The test case shows the current error message, which confusingly suggests both a refname qualification issue and an invalid object ID assertion. The test is marked as 'expect_failure' since it documents the current broken behavior that the next patch will fix. The test is cleanly implemented in t5516-fetch-push.sh, using the existing test infrastructure (mk_test and test_oid helpers).

This appears to be a well-scoped test addition that clearly documents the bug before fixing it - a good practice that makes the problem and solution easier to review. The commit message and test output show the problematic behavior that will be addressed in the next patch.
