This is a discussion about type choices in the commit-graph refactoring series, specifically addressing the use of `size_t` versus signed integers for bloom filter counters.

Junio Hamano responds to Patrick Steinhardt's justification for using `size_t` to count bloom filters in the commit-graph code. While Patrick cites the common practice of using `size_t` for counting, Junio argues this is often misguided unless actually measuring memory allocation sizes. He points out that platform-native integers are usually more appropriate for general counting, and that signed integers can be useful for representing uninitialized states (with -1). Junio also notes that overflow protection (like `st_mult()`) is needed regardless of type choice.

The exchange highlights an ongoing philosophical difference in the project about type selection, with Junio cautioning against what he sees as overuse of `size_t`. This discussion doesn't introduce new technical changes to the patch series but provides important context for reviewers considering the type changes in patch 2/9. The thread shows maintainer feedback that may influence future direction of similar refactorings.
