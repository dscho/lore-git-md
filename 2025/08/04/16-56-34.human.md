This is the third patch in a series fixing corruption issues in `git archive` ZIP output for large files. The patch addresses improper zlib compression handling where input data could be lost when `git_deflate()` doesn't complete in one go.

The change restructures the compression loop in `write_zip_entry()` to properly handle partial compression results, matching how zlib is used elsewhere in Git. Instead of immediately reading more input data after each `git_deflate()` call, it now processes all available input through a nested loop before moving to new data. This ensures no compressed data is lost mid-stream.

The patch continues the series' focus on robust zlib handling while maintaining the same buffer management established in earlier patches. The diff shows the straightforward conversion to nested loops while preserving the existing error handling and output writing. Testing confirms this fixes the corruption issues seen with large files in chromium.git.
