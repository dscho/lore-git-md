This thread continues Patrick Steinhardt's work to remove global state from Git's commit-graph subsystem, part of the broader effort to eliminate `the_repository` dependency and enable pluggable object storage backends. The series has grown to 10 patches in its second version, with all major technical discussions now resolved.

The latest patch (2/10) focuses on type consistency, converting Bloom filter counters from signed to unsigned integers since these values tracking filter states can never be negative. This follows the pattern established earlier in the series and addresses prior feedback about type safety. The change is small (30 lines) and contained to commit-graph.c, updating counters and their corresponding Trace2 logging calls to use the new unsigned integer support added in patch 1/10.

Key reviewers Derrick Stolee and Taylor Blau have already given their approval to the overall approach, with Junio Hamano providing input on integer type choices. The series appears merge-ready, having addressed all substantive feedback while maintaining its original goals of removing global state and improving type safety. These changes pave the way for future work on pluggable object storage backends.
