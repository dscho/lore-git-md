This thread continues the discussion of Patrick Steinhardt's series to remove global state dependencies from the commit-graph subsystem. The 9-patch series refactors the code to eliminate `the_repository` and `the_hash_algo` usage while enabling future pluggable object storage, with mechanical changes across commit-graph handling, builtins, and test helpers.

A new discussion point has been raised by Oswald Buddenhagen regarding the type changes for bloom filter counters in patch 2/9. While the original change converted these counters from signed to unsigned integers (`size_t`), Buddenhagen questions whether this is the most appropriate choice, citing concerns about semantic meaning, potential size increases on some platforms, and compatibility with command-line option parsing. This appears to be a substantive technical discussion about type system choices in a performance-sensitive area of the code.

The core functionality remains unchanged throughout the series, as confirmed by the unmodified test suite. The work achieves two important goals: complete removal of direct `the_repository` usage in the commit-graph subsystem, and foundational improvements for future pluggable object storage by making all operations repository-aware. The current discussion focuses on refining one aspect of these changes before the series can proceed.
