Patrick Steinhardt's series to remove global state dependencies from the commit-graph subsystem has sparked a focused debate about integer type choices in the bloom filter counters. The thread began with Oswald Buddenhagen questioning Patrick's change from `int` to `size_t`, which Junio Hamano then expanded into a broader discussion about type semantics. Junio argued that `size_t` should be reserved for memory-related counts, while platform-native integers are more appropriate for general counting.

Taylor Blau has now weighed in, siding with Junio's position. As the original author of the bloom filter code, Taylor notes he used `int` deliberately and doesn't see a compelling reason to change to `size_t` beyond the counters being non-negative. He points to the MIDX code as an example where `uint32_t` handles similar non-memory counts, though acknowledges `int` might be insufficient for very large repositories. Taylor maintains an open tone but clearly questions whether the type modification provides meaningful benefits.

The discussion remains constructive and narrowly focused on patch 2/9's type changes, with implications for similar decisions in later patches. While the core technical work of removing global state dependencies is uncontroversial, this type semantics debate may require Patrick to reconsider some implementation choices before the series can proceed. All participants agree the actual behavior remains unchanged - this is purely about selecting the most appropriate types for the code's long-term maintainability.
