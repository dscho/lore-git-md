This thread documents Patrick Steinhardt's series removing global state dependencies from Git's commit-graph subsystem, now at version 2 with 10 patches. The series systematically eliminates `the_repository` and `the_hash_algo` usage while making the code hash-algorithm aware, paving the way for pluggable object storage backends. Key reviewers including Derrick Stolee and Taylor Blau have approved the technical approach, with Junio Hamano weighing in on design details.

A recent follow-up email from Junio addresses a philosophical question about integer types that emerged during review - specifically whether Bloom filter counters should use signed integers to accommodate sentinel values and error handling patterns, even when the values are logically non-negative. Junio cites practical considerations like compiler warnings and existing error-handling conventions where negative values signal problems. This refines earlier discussions where Oswald Buddenhagen raised concerns about unsigned integer usage patterns.

The series itself is merge-ready, having addressed all substantive feedback. The integer type discussion represents ongoing attention to code quality rather than a blocking issue. When merged, this work will complete the commit-graph subsystem's transition away from global state while establishing clearer guidelines for similar conversions in other parts of the codebase. The changes are foundational for future ODB abstraction work Patrick is leading.
