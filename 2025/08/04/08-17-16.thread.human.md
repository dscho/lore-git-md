Patrick Steinhardt continues his series to remove global state dependencies from the commit-graph subsystem, part of the broader effort to eliminate `the_repository` and enable pluggable object storage backends. The latest patch (5/9) focuses on two hash-algorithm-dependent macros, converting them to functions that take the hash algorithm as an explicit parameter rather than relying on the `the_hash_algo` global.

The changes are mechanical but important - they affect core commit-graph operations like loading, parsing and tree lookups by making the graph file format calculations explicit about their hash algorithm dependencies. The patch introduces `graph_data_width()` (calculating per-commit data size) and `graph_min_size()` (computing minimum valid file size), updating all call sites to pass the hash algorithm parameter. While this doesn't fully eliminate `the_hash_algo` yet (it's still passed explicitly), it removes two more direct dependencies as groundwork for future work. The changes are behavior-preserving with no test updates needed, following the series' pattern of mechanical refactoring while maintaining existing functionality.

This continues Steinhardt's careful, incremental approach to global state removal - each patch tackles a focused piece of the problem while keeping the changes reviewable and the behavior stable. The series remains on track with its dual goals of eliminating global state and enabling future pluggability in the object storage layer.
