Patrick Steinhardt's series to remove global state dependencies from the commit-graph subsystem has reached an important technical discussion point. The 9-patch series refactors the commit-graph code to eliminate `the_repository` and `the_hash_algo` dependencies, part of the broader effort to enable pluggable object storage backends.

A key change in patch 2/9 converts bloom filter counters from `int` to `size_t`, which Oswald Buddenhagen questioned on three grounds: semantic appropriateness, potential memory impact, and compatibility with `OPT_UNSIGNED`. Patrick has now responded to each concern, noting that `size_t` is already a common pattern in the codebase, that compatibility was established in a prior merge (commit 2bc5414c41), and that memory impact would be negligible since commit graphs aren't typically loaded in bulk.

While Patrick has provided technical justification for his approach, the discussion remains open regarding whether `size_t` is semantically the right choice for these counters. The series otherwise appears ready to proceed, having completed the mechanical work to make commit-graph operations fully repository-aware while maintaining existing behavior (confirmed by passing tests). This represents significant progress toward both removing global state dependencies and enabling future pluggable storage backends.
