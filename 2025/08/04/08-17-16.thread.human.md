Patrick Steinhardt has completed his series removing global state dependencies from Git's commit-graph subsystem, a key step in the broader effort to make Git's object database pluggable. The six-part series, now at version 4, systematically eliminated all uses of `the_repository` and global hash algorithms from commit-graph operations.

The final patch cleans up now-redundant repository parameters that were made unnecessary by earlier changes in the series. Functions now consistently obtain their repository context from object database parameters rather than receiving it separately. The changes are mechanical and follow the established pattern from previous patches, with the exception of `load_commit_graph_chain_fd_st()` which must still operate at the object database level to handle chains spanning multiple repositories.

The series has received thorough review from multiple core contributors, with Junio Hamano, Derrick Stolee, and Taylor Blau all providing feedback that has been incorporated. No new objections have been raised to the final version, and the architectural approach has consensus. With this last cleanup patch, the commit-graph subsystem is now fully repository-aware with no remaining global state dependencies, marking an important milestone in Git's ongoing internal refactoring efforts.
