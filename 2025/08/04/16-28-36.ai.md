This is a maintainer response in the ongoing `git mv --after` feature proposal thread. Junio C Hamano, Git's maintainer, weighs in to reinforce the technical objections raised earlier about the fundamental mismatch between the proposed feature and Git's rename tracking model.

The email is brief but significant as it represents the first maintainer input in the thread. Hamano explicitly endorses Kristoffer Haugsbakk's reference to Linus Torvalds' 2005 email documenting Git's design philosophy around rename detection, effectively closing the door on any proposal that would track renames as explicit commit operations rather than heuristically detected tree differences.

Key technical points confirmed:
1. Git's rename detection is and will remain heuristic-based rather than explicitly recorded
2. The project has no interest in changing this fundamental behavior
3. The reference to Torvalds' email serves as canonical documentation of this design choice

The email also subtly reinforces mailing list etiquette by noting the importance of keeping CC intact when replying, though this is secondary to the technical confirmation. This response effectively concludes the technical discussion about the proposal's feasibility while leaving open the possibility of further discussion about alternative approaches to handle IDE/refactoring-tool renames within Git's existing model.
