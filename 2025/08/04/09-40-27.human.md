Reftable bugfix addressing concurrent compaction edge cases. This final patch in Patrick Steinhardt's v2 series improves error handling when detecting outdated reftable stacks during compaction operations.

The patch fixes an issue where `stack_uptodate()` could return positive values (indicating an outdated stack) that weren't properly handled in all code paths. It now consistently converts these to `REFTABLE_OUTDATED_ERROR` and adds explicit documentation about the function's return values. The change particularly affects `reftable_addition_commit()`, which now treats outdated stacks as benign errors (like it already did for lock conflicts) during auto-compaction attempts.

The commit message clearly explains the concurrent modification scenario being addressed, where multiple writers might be compacting the stack simultaneously. The implementation maintains backward compatibility while making the error handling more robust. This continues the series' theme of preparing reftable for libgit2 compatibility while keeping Git's behavior stable.

The patch appears well-considered, with clear documentation updates and targeted changes to the error handling logic. It completes the series' work on concurrent access patterns, following earlier patches that introduced the flags parameter and reorganized stack.c internals.
