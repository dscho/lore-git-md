This thread addressed a compiler warning from clang-22 about const variable initialization in Git's revert/cherry-pick sequencer code. The core issue involved how to properly handle the `sentinel_value` variable in `builtin/revert.c`, which uses pointer addresses (not values) to track option states - where &sentinel_value means unset, NULL means disabled, and other values mean set.

The discussion saw initial proposals from Jeff King (Peff) to remove the const qualifier, but Patrick Steinhardt and Phillip Wood ultimately convinced the group that keeping the const initialization with an explanatory comment was the most pragmatic solution. Junio Hamano has now weighed in to confirm this approach, though he playfully suggested renaming the variable to `sentinel_address` to better reflect its address-based usage pattern.

With Junio's approval, the matter appears fully resolved. The consensus maintains the existing address-based state tracking mechanism while satisfying clang's warning requirements through const initialization and documentation. While the variable name suggestion remains open for consideration, no further technical changes are expected as all parties agree the current solution works well.
