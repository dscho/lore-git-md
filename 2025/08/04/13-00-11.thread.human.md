This thread addresses a compiler warning from clang-22 about const variable initialization in Git's revert/cherry-pick sequencer code. The warning appears when building with DEVELOPER=1 mode, where the code pattern uses the address (not value) of a sentinel_value to track option states: &sentinel_value means unset, NULL means disabled, and other values mean set.

The original fix initialized a const variable to 0 with an explanatory comment. Jeff King suggested removing the "const" qualifier as an alternative approach that would maintain type safety while allowing a non-const pointer. However, Patrick Steinhardt and now Phillip Wood have both supported keeping the original const initialization approach, arguing it's the most pragmatic solution with no functional downsides, and that the rationale remains discoverable through git-blame. 

The discussion appearing to converge on this solution, with no new objections raised. This represents a minor but settled code style question about how to best implement the address-based state tracking pattern in this shared sequencer logic.
