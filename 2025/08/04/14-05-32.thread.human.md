FMorschel proposed adding a `--after` flag to `git mv` to better track file renames made outside Git (e.g., by IDEs), inspired by Mercurial's similar feature. However, several contributors - including Konstantin Khomoutov and Kristoffer Haugsbakk - explained that Git fundamentally tracks renames differently than Mercurial, using heuristics when comparing trees rather than recording them explicitly. Haugsbakk provided a 2005 email from Linus Torvalds documenting this as an intentional design choice.

Maintainer Junio Hamano has now weighed in, firmly closing the door on changing Git's rename tracking model. He endorsed the reference to Torvalds' email as canonical documentation of Git's design and made clear the project has no interest in moving to explicit rename recording. While the thread began as a feature proposal, it has effectively become a case study in Git's architectural philosophy. The discussion may continue around alternative approaches for handling IDE-initiated renames within Git's existing model, but the core proposal is now settled as incompatible with Git's design.
