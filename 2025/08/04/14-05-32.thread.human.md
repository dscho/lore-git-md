This thread explored a proposal to add a `--after` flag to `git mv` that would help track file renames performed outside Git (such as by an IDE). The original author, FMorschel, suggested modeling it after Mercurial's similar feature. However, multiple contributors - including maintainer Junio C Hamano - explained that Git fundamentally doesn't record renames in commits, instead detecting them heuristically when comparing trees. The thread became a useful reference for Git's rename tracking philosophy, anchored by Linus Torvalds' original design decisions.

Johannes Sixt recently added a brief follow-up, noting that if such a flag were implemented (despite the maintainer's rejection of the concept), it would more naturally be called `--cached` to align with Git's terminology for index operations. While expressing sympathy for the use case, his comment reinforces that `git mv` is essentially just a convenience wrapper for `rm`+`add` operations on the index. The thread is now effectively closed, serving as documentation of Git's approach to rename tracking.
