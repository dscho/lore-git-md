This thread discusses a proposal for adding a `--after` flag to `git mv` to better track file renames made outside Git (e.g., by IDEs or refactoring tools). The original poster, FMorschel, suggests modeling this after Mercurial's `hg mv --after` command.

Konstantin Khomoutov has provided key technical context in response, explaining that Git's rename tracking works differently than Mercurial's - Git doesn't record renames in commits but detects them heuristically when comparing trees. He notes that `git mv` is essentially just a convenience for `rm`+`add`, so a `--after` flag wouldn't provide additional tracking capabilities beyond Git's existing rename detection. This suggests the feature might be unnecessary since Git's heuristics should work regardless of how files were moved.

The discussion is still in its early stages, with the original proposal now facing questions about whether it addresses a real gap in Git's functionality. The next steps would likely involve either refining the proposal to account for Git's different model or reconsidering whether the change is needed at all. No maintainers or other contributors have weighed in yet.
