This thread explored a proposal to add `--after` or `--cached` flags to `git mv` to better track file renames performed outside Git (e.g., by an IDE). The idea, inspired by Mercurial's `hg mv --after`, was quickly met with technical and philosophical objections from core contributors. Maintainer Junio Hamano confirmed that Git's design fundamentally relies on heuristic rename detection rather than explicit tracking, a principle dating back to Linus Torvalds' 2005 email explaining Git's content-oriented approach.

The discussion produced several educational insights: Johannes Sixt noted that `--cached` would be more Git-idiomatic terminology than `--after`, Konstantin Khomoutov provided historical context by quoting Torvalds' original design rationale, and Kristoffer Haugsbakk documented Git's philosophy. The original proposer, FMorschel, gracefully accepted the outcome while noting their personal workflow preference.

In a final follow-up, Hamano explored what hypothetical implementations might entail—either simple path pairing or more sophisticated automatic detection—while reaffirming that neither approach aligns with Git's current design. The thread now stands as a clear reference for why Git handles renames differently than version control systems that track file operations explicitly.
