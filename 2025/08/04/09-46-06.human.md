This is a bugfix in Patrick Steinhardt's reflog migration series, addressing an issue with committer identity formatting during storage format conversions.

The patch migrates reflog entries between storage formats (like files to reftable), it was incorrectly passing the full committer identity (name + email) as just the email parameter to `fmt_ident()`. This resulted in malformed output like "pks <Patrick Steinhardt ps@pks.im>". The fix properly splits the identity line into name and email components before formatting.

The change adds new string buffers to the migration data structures to store the split name and email components, avoiding repeated allocations. While the fix is straightforward, the commit notes that test coverage will come in a subsequent patch that tightens reflog verification in t1450.

This is part of a larger 9-patch series that has already been merged, with this particular fix addressing a subtle formatting issue that could affect migrated reflog entries. The solution is clean and maintains the existing behavior while fixing the malformed output case.
