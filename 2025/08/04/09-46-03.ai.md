Refactoring patch in Patrick Steinhardt's reflog migration series, specifically exporting and simplifying the `ref_transaction_update_reflog()` function. This is part of the larger effort to enable reflog migration between files and reftable backends.

The patch makes two key changes to the reflog update function: (1) exports it from refs.c to refs.h since it will be needed by upcoming reflog migration code, and (2) removes the flags parameter since all callers were using identical flags (REF_HAVE_OLD|REF_HAVE_NEW|REF_LOG_ONLY|REF_FORCE_CREATE_REFLOG|REF_NO_DEREF). The function documentation is updated to clarify the index parameter's behavior when zero.

The implementation maintains all existing behavior while cleaning up the interface. The migrate_one_reflog_entry() caller is updated to match the new signature. This appears to be a straightforward plumbing change that enables future work without introducing new behavior, keeping with the series' goal of building reflog migration infrastructure. The change is well-contained, touching only refs.c and refs.h with straightforward modifications.
