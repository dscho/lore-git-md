This is a bugfix and feature series addressing reflog migration issues between files and reftable backends, now in its fourth iteration. The series fixes two critical problems discovered while implementing reftable support in libgit2: incorrect committer identity in migrated reflog entries and all-zero old OIDs during migration. It also introduces a new `git reflog write` subcommand for direct reflog manipulation.

Key technical changes in v4 include:
- The test for abbreviated OIDs in `git reflog write` now properly uses existing abbreviated OIDs rather than non-existent ones
- Changed error handling for HEAD race conditions - instead of failing the transaction, it now silently drops the log-only update when HEAD is racily updated
- The race condition mitigation now includes proper handling of multi-level symrefs (HEAD -> refs/heads/foo -> refs/heads/bar)
- The `unlock_ref()` function now returns a status to support the new error handling approach
- Transaction update arrays are adjusted when dropping entries due to races

The series maintains its core improvements from previous versions:
- Standardized documentation format for git-reflog(1)
- Reorganized reflog subcommands with clear read/write separation
- Exported `ref_transaction_update_reflog()` with simplified interface
- Fixed committer identity formatting during migration
- Added `REF_LOG_VIA_SPLIT` flag for HEAD race mitigation
- Preserved `REF_HAVE_OLD` for log-only updates
- Added `REF_LOG_USE_PROVIDED_OIDS` to fix zero-OID migration issue

The implementation appears technically sound with thorough test coverage. The debate around error handling philosophy (failing transaction vs silent drop) continues, but Patrick has provided a prototype implementation of Jeff King's suggested silent-drop approach. The series is now rebased on v2.50.1 for potential backporting.
