This thread has evolved from a simple build fix to a more robust approach for verifying Git's built-in command documentation. The discussion started with a one-line fix for out-of-tree builds, but Patrick Steinhardt identified a deeper issue: the test was silently skipping undocumented commands, potentially masking real documentation gaps.

The current solution, now in its second iteration, introduces explicit allowlists to track which builtins should have documentation and which are intentionally undocumented. The latest patch from Patrick provides the implementation details that were missing in the initial submission, properly reversing the grep condition and including the actual allowlist file with nine intentionally undocumented commands like `checkout--worker` and `submodule--helper`.

Junio Hamano has been shepherding the discussion, noting when implementation details were incomplete and now leaving the decision about whether to squash this fixup with the previous patch to Toon Claes when he returns. The test now actively verifies documentation presence or absence against the allowlists rather than silently skipping checks, making the verification process more rigorous while maintaining compatibility with both Makefile and Meson builds. The thread shows good technical collaboration between Patrick, Toon, and Junio to improve Git's documentation verification infrastructure.
