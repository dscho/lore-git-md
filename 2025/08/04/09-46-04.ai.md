This is patch 4/9 in Patrick Steinhardt's series implementing reflog migration infrastructure between files and reftable backends. The patch introduces a new `git reflog write` subcommand that allows manually appending entries to reflogs, which was previously impossible with the reftable backend due to its binary format.

The new subcommand is intentionally strict in its requirements: it only accepts fully-qualified refnames (no DWIM resolution), requires full (non-abbreviated) OIDs that must exist in the object database, and normalizes reflog messages. The implementation includes thorough validation of these requirements and adds corresponding test cases. Notably, this differs from other reflog subcommands which do perform DWIM resolution, a design choice that was discussed and accepted in earlier thread discussions.

The patch adds the subcommand to both the documentation and implementation, including usage strings and a new test script (t1421-reflog-write.sh) that verifies the strict validation behavior. The tests cover error cases (invalid refnames, abbreviated OIDs, nonexistent objects) as well as successful writes, including verification of message normalization and special handling of root refs like HEAD.

This is part of the larger reflog migration effort that includes race condition mitigation and OID handling fixes (addressed in other patches of the series). The implementation uses the ref-transaction infrastructure and builds on the exported `ref_transaction_update_reflog()` function that was simplified in earlier patches. The strict validation aligns with the plumbing-like nature of the write operation, though it creates a behavioral inconsistency with other reflog subcommands that was acknowledged but left for future resolution.
