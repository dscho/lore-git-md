This is the second patch in a series fixing ZIP archive corruption issues, specifically addressing unnecessary code in the compression path. The patch simplifies `write_zip_entry()` in `archive-zip.c` by removing a redundant check around `write_or_die()`. The author notes that `write_or_die()` can safely handle zero-length writes, and the removed condition was guarding against a case that cannot occur (negative `out_len` would already indicate data loss). 

This change is part of a larger effort to properly handle zlib compression for large files in Git archives, building on Justin Tobler's initial diagnosis. The modification is straightforward - just removing 5 lines of unnecessary code while maintaining the same behavior. The patch keeps Tobler's co-authorship credit from the original investigation. 

While small, this cleanup helps make the code more maintainable as part of the broader fix for ZIP corruption issues. The change is low-risk since it only removes a redundant check rather than modifying any core logic.
