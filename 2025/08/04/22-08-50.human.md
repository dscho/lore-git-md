Bugfix for edge cases in merge-ort's rename-to-self handling. This is part 5/6 in a series addressing complex directory rename scenarios in merge operations.

The patch fixes three specific issues that can occur when a file is renamed to itself (a situation that arises from directory renames): silent file deletion when the file should be kept, silent retention when the file should be deleted, and incorrect index entry counts. The core fix adds a check in process_renames() to skip processing when old and new paths are identical (detected via pointer comparison, which is safe due to merge-ort's path interning optimization).

The changes include:
- Modifying testcase 12i to use a multi-line file (preparing for new test)
- Adding testcase 12i2 that demonstrates the silent deletion bug
- Converting testcases 12n and 12n2 from expect_failure to expect_success
- Adding detailed comments explaining the pointer comparison optimization
