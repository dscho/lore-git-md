This is a bugfix patch from Patrick Steinhardt's reflog migration series, addressing an identity formatting issue during reflog storage format conversion.

The patch fixes how committer identities are reconstructed when migrating reflog entries between storage formats. Previously, the migration code incorrectly passed the full identity string (name + email) as just the email parameter to `fmt_ident()`, resulting in malformed output like "pks <Patrick Steinhardt ps@pks.im>". The fix properly splits the identity line into name and email components using `split_ident_line()` before passing them to `fmt_ident()`.

Key technical changes include:
- Adds new `name` and `mail` string buffers to both `migration_data` and `reflog_migration_data` structs to avoid repeated allocations
- Uses `split_ident_line()` to properly extract name and email from the committer string
- Updates the identity formatting logic in `migrate_one_reflog_entry()`
- Initializes and cleans up the new string buffers in `repo_migrate_ref_storage_format()`

The patch notes that test coverage for this fix will come in a subsequent commit that tightens reflog verification in t1450. This is part of a larger effort to ensure proper identity preservation when converting between files-based and reftable-based reflog storage formats. The change maintains the existing behavior while fixing the malformed output case.
