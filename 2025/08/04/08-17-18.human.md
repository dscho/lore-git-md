This is a refactoring patch in Patrick Steinhardt's series to remove global state dependencies from the commit-graph subsystem. It's part 2 of 9 in the series.

The patch changes several integer counters in the commit-graph code from signed `int` to unsigned `size_t` types. These counters track statistics about bloom filters (how many were computed, not computed, truncated, etc.) and naturally only count upwards from zero. The change is purely about using more appropriate type for these counters.

The patch also updates the corresponding trace2 logging calls to use the new `trace2_data_uintmax()` function (introduced in an earlier patch) instead of `trace2_data_intmax()`, maintaining consistency with the type changes. The diff shows straightforward mechanical changes to both the struct field declarations and their usage in the trace2 calls.

This appears to be a clean, focused change that aligns with the series' goal of improving type correctness while removing global state dependencies. The patch doesn't introduce any functional changes - it's purely about using more appropriate types for these counters.
