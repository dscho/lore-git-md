This is a technical response in the ongoing discussion about adding a `--after` flag to `git mv` for tracking external renames. The email comes from Konstantin Khomoutov, who is engaging with FMorschel's initial proposal.

The core argument presented is that Git's rename tracking works fundamentally differently than Mercurial's model - Git doesn't actually record renames in commits, but rather detects them heuristically when comparing trees. Khomoutov demonstrates that `git mv` is essentially just a convenience wrapper for `git rm` + `git add` operations, and therefore a `--after` flag would provide no additional tracking capability beyond what Git's existing rename detection already offers.

The response suggests the proposed feature might be unnecessary since Git's rename detection would work the same whether files were moved via `git mv`, external tools`, or manual operations. This challenges the premise that IDE/refactoring tool moves need special handling to preserve history. The email doesn't reject the idea outright but provides important technical context about Git's underlying model that the original author should consider when refining their proposal.
