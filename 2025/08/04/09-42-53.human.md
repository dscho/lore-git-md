This is a bugfix patch series addressing an incorrect BUG() assertion in remote.c when pushing a non-existent object ID to an unqualified ref.

The series documents and fixes a case where Git incorrectly triggers a BUG() when pushing a non-existent object (like all-zeros) to an unqualified branch name. Currently, this results in a confusing error message that claims an internal bug when in fact it's just an invalid push operation. The first patch adds a test case to demonstrate the issue, while the second replaces the BUG() with a more appropriate advisory message.

The change appears straightforward and well-motivated - the current behavior is clearly misleading since the situation isn't actually a bug in Git's internals, just an invalid user operation. The test case provides clear coverage, and the fix itself is minimal (changing a BUG to an advise call). This seems like a clear improvement to error handling that shouldn't be controversial.
