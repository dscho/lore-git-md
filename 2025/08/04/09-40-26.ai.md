Feature patch in Patrick Steinhardt's reftable/libgit2 compatibility series (5/6). This change adds a `flags` parameter to `reftable_stack_add()` to enable future control over stack addition behavior, particularly for libgit2's needs around automatic stack reloading when modifications occur during locking.

The patch modifies the core stack addition interface across multiple files, with the main change being the new `flags` parameter that gets passed through from `reftable_stack_add()` down to `stack_try_add()` and `reftable_stack_init_addition()`. All existing callers in Git's codebase are updated to pass `0` for now, maintaining current behavior. The test suite is similarly updated to pass the new parameter while keeping all test cases unchanged.

This appears to be a preparatory change for libgit2 integration, where the ability to automatically reload the stack when detecting concurrent modifications will be needed. The implementation is clean and maintains backward compatibility, with thorough updates to both production code and extensive test coverage. The change is part of the larger effort to make reftable a robust shared library while keeping Git's own usage simple.
