This is the final patch in Patrick Steinhardt's v2 series improving reftable/libgit2 compatibility, focusing on error handling during stack compaction. The patch addresses a subtle issue where the code wasn't properly distinguishing between different error conditions from `stack_uptodate()` - specifically treating outdated stacks (positive return) the same as actual errors (negative return).

The key change makes `stack_uptodate()`'s behavior more explicit in its documentation and properly handles the outdated stack case by converting it to `REFTABLE_OUTDATED_ERROR`. This error is then specially handled in `reftable_addition_commit()` where it's treated as benign (like `REFTABLE_LOCK_ERROR`), while other call sites like `stack_compact_range()` now explicitly abort when encountering an outdated stack.

The patch maintains backward compatibility while improving the robustness of concurrent operations. It's part of the broader effort to make reftable more suitable for libgit2's needs, particularly around concurrent access patterns. The changes are localized to stack.c and focus on error handling paths, with no behavioral changes to the happy path.
