This is a refactoring patch from Patrick Steinhardt's reflog migration series, specifically reorganizing the subcommands in `git-reflog` for better logical grouping. The changes are purely structural with no behavior modifications.

The patch reorders both the documentation and implementation to group read-only subcommands (`show`, `list`, `exists`) before write operations (`delete`, `drop`, `expire`). It also moves the `expire` subcommand to the end of the write operations section to prepare for the upcoming `write` subcommand addition. The changes affect both the man page (reordering sections and option descriptions) and the C implementation (rearranging usage strings and subcommand dispatch table).

Key technical details:
- Documentation changes in `git-reflog.adoc` reorder subcommand synopses and descriptions while preserving all content
- Implementation changes in `builtin/reflog.c` reorder:
  - Usage string definitions (BUILTIN_REFLOG_* macros)
  - Usage string arrays (reflog_*_usage)
  - Subcommand dispatch table (options[] array)
- Maintains identical functionality while improving logical organization
- Prepares codebase for subsequent addition of `git reflog write` subcommand

The patch is part of the larger reflog migration infrastructure work between files and reftable backends, though this particular change is focused solely on improving code organization. The thread context shows this was the second patch in a 9-part series that has since been merged.
