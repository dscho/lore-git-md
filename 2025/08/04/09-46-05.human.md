This is a type safety refactoring patch in Patrick Steinhardt's reflog migration series. It changes the `split_ident_line()` function to use `size_t` for its length parameter instead of `int`, which better matches how the function is used (with `strlen()` and `strbuf` lengths that are inherently unsigned). The change is straightforward - just updating the function signature in both the declaration and implementation files.

The patch is part of a larger effort to improve reflog handling between files and reftable backends, though this particular change is more of a general code quality improvement than something specific to reflogs. The commit message clearly explains the rationale - the length parameter logically represents an unsigned quantity, and callers already pass unsigned values to it. This makes the code's intent clearer and prevents potential signed/unsigned conversion issues.

The change is minimal (just two lines modified) and low-risk since it doesn't affect behavior - it just makes the types more accurate. The patch has already gone through several iterations of the v4 series and appears ready for inclusion.
