This is a refactoring patch from Patrick Steinhardt's 9-part series on reflog migration infrastructure. The patch reorganizes the `git reflog` subcommands to group them more logically - read-only operations (`show`, `list`, `exists`) come first, followed by write operations that affect single reflogs (`delete`, `drop`), with the broadest write operation (`expire`) last. 

The changes are purely organizational - no behavior is altered. The documentation and code are updated in parallel to maintain consistency. This prepares for a subsequent patch that will add a new `write` subcommand. The patch is cleanly implemented with straightforward documentation and code changes that follow Git's existing patterns.

As part of the larger series that has already been merged, this patch helps create a more maintainable structure for the reflog command's growing functionality while maintaining backward compatibility. The changes are non-controversial and focused on improving code organization.
