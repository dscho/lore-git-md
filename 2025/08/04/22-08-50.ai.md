Bugfix patch addressing edge cases in merge-ort's rename-to-self handling, part of a larger series fixing directory rename interactions. This fifth patch in the series specifically targets three issues that emerge when files are renamed to themselves during merges: silent file deletions, incorrect file retention, and wrong index entry counts.

The patch changes include:
- Adding a pointer comparison check in process_renames() to skip rename-to-self cases (oldpath == newpath)
- Modifying testcase 12i to use a multi-line file as preparation for new testcase
- Adding testcase 12i2 demonstrating silent deletion bug
- Converting testcases 12n and 12n2 from expect_failure to expect_success
- Fixing test assertions to properly check index state via `git ls-files -s`

The core issue stems from merge-ort's assumption that rename source and destination paths are different, which breaks down in rename-to-self scenarios. The fix leverages merge-ort's existing path interning optimization (where all paths are stored in a central strmap) to use efficient pointer comparisons rather than string comparisons.

Review discussion with Patrick Steinhardt led to:
- Clarification of testcase modifications
- Agreement to improve commit message explanation of root cause
- Confirmation that pointer comparison optimization is safe due to test coverage
- Acknowledgment that the optimization relies on merge-ort's path interning design

The patch builds on earlier work in the series that established expected behavior for directory rename cases and prepares for subsequent fixes of path-in-way conflicts. Test coverage is comprehensive, with particular attention to verifying index states after merges.
