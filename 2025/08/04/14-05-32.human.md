This is a feature proposal for adding a `--after` flag to `git mv`, similar to Mercurial's `hg mv --after`. The author FMorschel suggests this would help when files are renamed/moved by external tools (like IDEs during refactoring) but still need to be properly tracked in Git's history.

The proposal is light on implementation details but clearly motivated by improving workflow integration with development tools. This appears to be the author's first contribution to the Git mailing list, and they've politely asked for feedback about whether this has been proposed before or if more information is needed.

The idea seems reasonable at first glance - providing a way to record moves after they happen could help maintain better history when using external refactoring tools. However, the proposal would benefit from more concrete use cases and potentially some implementation thoughts to help reviewers evaluate it. The mailing list may ask for these details in follow-up discussion.
