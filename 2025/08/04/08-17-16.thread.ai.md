[PATCH 0/9] commit-graph: remove global state dependencies

Series by Patrick Steinhardt completing the commit-graph subsystem's transition away from global state as part of the broader `the_repository` removal effort and ODB abstraction work. The 9-patch series mechanically refactors commit-graph.[ch], builtins, and test helpers (284+/-262 LOC total) to eliminate `the_repository` and `the_hash_algo` dependencies while enabling future pluggable object storage.

Key technical changes across all patches:
- Type consistency: converted signed counters to unsigned (bloom filter stats, loop counters, array indices) and changed `struct commit_graph_opts` fields from `int` to `size_t`
- Hash algorithm handling: replaced `GRAPH_DATA_WIDTH`/`GRAPH_MIN_SIZE` macros with functions taking explicit `hash_algo` parameters; stored full `hash_algo` pointers instead of just `hash_len`; updated all size calculations and parsing to use repository-specific algorithms
- Trace2: added `trace2_data_uintmax()` for unsigned value logging (23+/- LOC)
- Parameter cleanup: removed redundant `struct repository*` parameters where `odb_source` already provided context (15+ functions affected), except for special cross-repo handling in `load_commit_graph_chain_fd_st()`
- Verification: updated to use repository from graph's odb_source rather than passed parameters
- Progress reporting: modified to use repository context (`ctx->r`) consistently
- File operations: changed to use passed repository rather than global state
- Test helpers: updated signatures to match new parameter requirements

Open discussion:
- Oswald Buddenhagen questions the change from signed to unsigned integers (`size_t`) for bloom filter counters in patch 2/9, raising three concerns: (1) semantic appropriateness of `size_t` for counters, (2) potential size increase on LP64 platforms, and (3) compatibility with `OPT_UNSIGNED`. This appears to be a blocking concern requiring resolution before the change can proceed.

Behavior remains unchanged throughout the series, confirmed by unmodified test suite. The work achieves two long-term goals: (1) complete removal of direct `the_repository` usage in commit-graph subsystem, and (2) foundational improvements for future pluggDB abstraction by making all operations repository-aware. Changes follow established patterns for global state removal - converting macros to functions, adding explicit parameters, and maintaining existing algorithms while removing implicit dependencies. The final patch (9/9) completes the transition by eliminating parameter redundancy where odb_source already carries repository context.
