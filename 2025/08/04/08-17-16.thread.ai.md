[PATCH 0/9] commit-graph: remove global state dependencies

Series by Patrick Steinhardt completing the commit-graph subsystem's transition away from global state as part of the broader `the_repository` removal effort and ODB abstraction work. The 9-patch series refactors commit-graph.[ch], builtins, and test helpers to eliminate `the_repository` and `the_hash_algo` dependencies while enabling future pluggable object storage.

Key technical changes:
- Type consistency: converted signed counters to unsigned (bloom filter stats, loop counters, array indices) and changed `struct commit_graph_opts` fields from `int` to `size_t`
- Hash algorithm handling: replaced macros with functions taking explicit `hash_algo` parameters (patch 5/9); stored full `hash_algo` pointers (patch 6/9); updated all size calculations
- Trace2: added `trace2_data_uintmax()` for unsigned value logging (reviewed by Taylor Blau as straightforward and uncontroversial)
- Parameter cleanup: removed redundant `struct repository*` parameters where `odb_source` provided context
- Verification, progress reporting, and file operations updated to use repository context consistently
- Test helpers updated to match new parameter requirements
- Patch 8/9 reviewed and acked by Taylor Blau, eliminating remaining `the_repository` usage from builtins (`commit.c`, `merge.c`) with 42-line net reduction

Ongoing discussions:
1. Integer type choices (patches 2/9 through 4/9):
   - Oswald Buddenhagen initially questioned using `size_t` for bloom filter counters
   - Patrick Steinhardt defended changes citing existing code patterns
   - Junio Hamano and Taylor Blau push back:
     * Prefer platform-native integers unless specifically memory-related
     * Signed integers can represent uninitialized states (-1)
     * Question value of -Wsign-compare warnings driving changes
   - Taylor Blau provides concrete example in patch 3/9:
     * Current --size-multiple validation produces confusing overflow message for -1
     * While unsigned type would reject negatives upfront, argues validation needs fixing regardless
     * Maintains semantic meaning should drive type choices, not just warning avoidance
   - In patch 4/9 discussion, Taylor Blau expresses mixed opinions:
     * Supports `size_t` for array element counts
     * Questions other conversions' value, particularly bloom filter version handling (-1 as unspecified)
     * Notes filesize comparison requiring signed/unsigned conversion
     * Suggests current approach may not improve clarity or safety
   - Philosophical divide remains: Steinhardt's consistency approach vs semantic-based type selection
   - Core issue extends beyond just bloom filters to commit-graph write options

2. Hash algorithm conversion (patches 5/9 through 7/9):
   - Taylor Blau provides positive review ("Very nice") for macro-to-function conversion in 5/9
   - For 6/9, confirms storing full hash algorithm pointer makes sense
   - Notes existing validation in `parse_commit_graph()` properly handles hash version mismatches
   - In patch 7/9 review, questions API design of `parse_commit_graph()`:
     * Current patch adds separate `hash_algo` parameter alongside `repo_settings`
     * Suggests passing full `struct repository*` might be cleaner abstraction
     * Raises architectural question whether disassociated settings/hash_algo pairs would ever be meaningful
     * Implies repository abstraction might be more natural boundary
   - Does not challenge patch correctness or global removal direction
   - Represents thoughtful review about abstraction boundaries for future pluggable ODB implementations
   - Question remains open-ended, inviting justification for current approach or consideration of alternative

Behavior remains unchanged throughout series (confirmed by unmodified test suite). The work achieves two long-term goals: (1) complete removal of direct `the_repository` usage in commit-graph subsystem, and (2) foundational improvements for future pluggable ODB abstraction. While the core technical merits of global state removal are uncontested (as evidenced by Taylor Blau's ack of patch 8/9), the integer type discussion represents a broader project-wide tension between consistency and semantic type selection, and the hash algorithm API design question highlights ongoing considerations about appropriate abstraction boundaries in the evolving ODB architecture.
