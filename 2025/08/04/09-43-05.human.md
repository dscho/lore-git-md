Bugfix for incorrect BUG() assertion in push validation. This is the second patch in a two-part series addressing an issue where Git would incorrectly trigger a BUG() when pushing a non-existent object ID to an unqualified ref (like "branch" instead of "refs/heads/branch").

The patch replaces the BUG() assertion in `show_push_unqualified_ref_name_error()` with a proper advise() message when the source object ID doesn't exist. The original code mistakenly treated this as an impossible condition when in fact it can occur in normal usage - `repo_get_oid()` doesn't verify object existence for fully-qualified OIDs, so the subsequent `odb_read_object_info()` may legitimately fail.

The accompanying test case in t5516-fetch-push.sh is updated from test_expect_failure to test_expect_success, now that the behavior is fixed. The test verifies that pushing a known-bad OID (test_oid 001) to an unqualified branch name fails gracefully with appropriate advice rather than triggering a BUG().

This is a straightforward correction that improves error handling for an edge case in push validation. The change is minimal (5 lines modified) and well-contained to the push error path in remote.c. The commit message clearly explains why the BUG() was incorrect and how the new behavior better matches reality.
