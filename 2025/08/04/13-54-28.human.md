This is a discussion about the proposed `--json` output format for `git status`, now in its second revision. The thread has revealed a fundamental debate about whether JSON output is actually needed, with maintainer Junio Hamano expressing skepticism about its value compared to improving the existing porcelain format, while Phillip Wood argues for JSON's practical benefits in tooling integration.

Phillip makes the case that JSON's widespread parser availability and built-in base64 handling for special characters would save tool authors from writing custom parsers. Junio acknowledges this point but remains unconvinced it justifies the complexity, suggesting prerequisite refactoring of Git's format selection infrastructure would be needed first.

The discussion has shifted from implementation details (which were addressed in v2) to more fundamental questions about whether this feature should exist at all. Key open questions include whether JSON's encoding overhead is worth its parser ecosystem advantages, and whether the porcelain format could be enhanced instead. The patch remains blocked pending resolution of these design questions and the suggested refactoring work.
