This is a discussion about integer type choices in the commit-graph bloom filter counters, part of the ongoing `the_repository` removal effort.

Taylor Blau weighs in on the debate about whether bloom filter counters should use `size_t` (as proposed in patch 2/9) or platform-native integers. He agrees with Junio Hamano's position that `size_t` should generally be reserved for memory-related counts, not general counting. Taylor cites the MIDX code as an example where uint32_t is used for object counting, noting this matches the on-disk format while avoiding the need for `size_t`.

The discussion reveals Taylor originally wrote these counters and doesn't see a compelling reason to change their signedness, despite their always-non-negative nature. He questions whether the patch's rationale goes beyond "these are always non-negative" and suggests dropping it if no stronger justification exists. The exchange highlights a philosophical divide about type selection patterns in the codebase, with this patch becoming a focal point for that broader discussion.

This email moves the thread toward potential resolution, with Taylor (as the original author of the affected code) indicating openness to keeping the current signed integers unless stronger arguments emerge. The core series goal of removing global state remains unaffected by this type discussion.
