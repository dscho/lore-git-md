This is a follow-up discussion in the ongoing thread about making content-ignoring diff options (`-I`, `-w`, etc. behave consistently across output formats. Junio Hamano is reviewing Lidong Yan's v2 patch that aims to fix the inconsistency where files would appear in `--name-only` output but not in `--stat` or `-p` when content-ignoring options are used.

Junio suggests the patch should better emphasize that this isn't just about `-I<regex>` but all options that set `.diff_from_content`. He also questions why the patch's `ignore_match()` helper needs to duplicate so much logic from `diff.c` when Jeff King's earlier proposed solution (using `/dev/null` redirection) seemed cleaner and avoided this code repetition.

The discussion is now at the implementation refinement stage, with Junio appearing to favor Jeff's more architecturally simple approach, though the thread remains open for final performance analysis and maintainer decisions. This email continues the technical evaluation of the two competing solutions' tradeoffs around code duplication and maintainability.
