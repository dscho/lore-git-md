This is a follow-up discussion on an already-accepted Windows platform compatibility patch that removes obsolete Windows 7 workarounds. Oswald Buddenhagen raises two thoughtful questions about the patch from Johannes Schindelin that's part of the mingw_rename() regression fixes.

First, they question whether the justification for removing the Windows 7-specific code (Git for Windows dropping support) logically extends to newer Windows versions. Second, they suggest the commit message should better explain both the specific failure scenarios being guarded against and why removing the handle inheritance restrictions doesn't create security risks.

The questions appear constructive rather than oppositional - they're seeking clarification on technical details that weren't fully explained in the original patch. Since this series is already approved for merging, these points are likely to be addressed either in follow-up documentation or as minor commit message improvements rather than blocking the changes. The exchange demonstrates healthy post-merge review of Windows-specific changes that affect security-sensitive file handle behavior.
