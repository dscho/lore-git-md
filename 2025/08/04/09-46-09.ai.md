Bugfix for reflog migration between storage formats, specifically addressing invalid all-zero OIDs in migrated entries. This is the final patch in Patrick Steinhardt's 9-part series on reflog migration infrastructure.

The core issue occurs when migrating reflog entries between storage formats (e.g., files to reftable) - the old OID was being incorrectly resolved to all zeros because the code was trying to resolve the reference in the target storage where it didn't yet exist. The fix introduces a new `REF_LOG_USE_PROVIDED_OIDS` flag that tells backends to use the caller-provided OIDs directly rather than attempting resolution. The flag is set in `ref_transaction_update_reflog()` and implemented consistently across both files and reftable backends.

The patch includes validation check that ensures required flags (`REF_HAVE_OLD`, `REF_HAVE_NEW`, `REF_LOG_ONLY`) are present when `REF_LOG_USE_PROVIDED_OIDS` is used. Test coverage is improved by modifying the migration test to use a new test helper (`print_all_reflog_entries`) that shows both old and new OIDs, fixing a previous testing gap. The tests in t1421-reflog-write.sh are also updated to verify the correct OIDs are preserved.

This completes the series' work on ensuring accurate reflog migration between storage formats, building on previous fixes for committer identity handling and race condition mitigation. The implementation appears thorough with consistent handling across both backend types and proper error checking.
