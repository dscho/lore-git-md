This is part 5/6 of Patrick Steinhardt's series to improve reftable compatibility with libgit2. The patch adds a `flags` parameter to `reftable_stack_add()`, which is currently unused in Git but will be needed by libgit2 for automatic stack reloading when modifications occur during locking. The change is straightforward - passing the parameter through the stack addition chain while maintaining existing behavior. All callers in Git are updated to pass `0` for now. The patch includes updates to header files, implementation, and extensive test coverage (50+ test modifications) to ensure no regressions in the existing stack operations. This continues the series' pattern of making reftable more robust as a shared library while keeping Git's behavior unchanged.
