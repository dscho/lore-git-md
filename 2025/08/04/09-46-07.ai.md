This is a bugfix patch in Patrick Steinhardt's reflog migration series, specifically addressing race conditions in HEAD reflog generation. The patch introduces a new `REF_LOG_VIA_SPLIT` flag to improve handling of concurrent HEAD updates during reflog writes.

The core issue stems from `split_head_update()` not locking HEAD after reading its target, leading to two race scenarios: missing reflog entries when HEAD moves to a processed ref, or creating spurious entries when HEAD moves away. The solution adds post-lock verification of HEAD's target and propagates the parent update's old OID state, though it fully fixes only the second race condition.

Key technical changes include:
- New `REF_LOG_VIA_SPLIT` flag marking reflog-only updates from `split_head_update()`
- Modified `unlock_ref()` to return status for cleanup
- Added parent_update linkage to track relationship between HEAD and ref updates
- Post-lock verification of HEAD's target against the parent ref
- Silent drop of reflog updates when HEAD no longer points to the expected ref
- Propagation of old OID from parent update when available

The patch maintains the existing limitation that it cannot fully prevent missed reflog entries when HEAD racily moves to a processed ref, as locking HEAD throughout would serialize all writes. The changes focus on preventing incorrect reflog entries while accepting some cases where entries might be missing (deemed preferable to incorrect data).
