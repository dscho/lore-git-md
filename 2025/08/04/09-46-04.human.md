This is part of Patrick Steinhardt's series adding reflog migration infrastructure between files and reftable backends. The patch introduces a new `git reflog write` subcommand that allows manually appending entries to a reflog.

The new subcommand`git reflog write <ref> <old-oid> <new-oid> <message>` provides strict, plumbing-like behavior: it requires fully-qualified refnames, unabbreviated OIDs that must exist in the object database, and normalizes the message (converting newlines to spaces). The implementation includes thorough validation and error handling, with tests covering invalid inputs, message normalization, and basic write scenarios.

This fills a gap that became more pressing with the reftable backend, where manual reflog edits are impractical due to the binary format. The design intentionally keeps the initial implementation minimal - it doesn't support writing multiple entries, arbitrary timestamps, or references to non-existent objects, leaving those as potential future extensions.

The patch is well-structured with clear documentation, comprehensive tests, and careful input validation. It fits into the larger series by providing the write-side counterpart to the existing reflog manipulation commands, completing the tooling needed for reflog migration between backends.
