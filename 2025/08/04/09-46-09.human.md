This is the final patch in Patrick Steinhardt's 9-part series fixing reflog migration between files and reftable backends. It addresses a bug where migrated reflog entries were incorrectly showing all-zero old object IDs instead of preserving the original values.

The root cause was that during migration, the code was trying to resolve the old OID by looking up the reference in the target backend (where it didn't exist yet) rather than using the provided OID from the source reflog. The patch introduces a new `REF_LOG_USE_PROVIDED_OIDS` flag that tells the backend to use the caller-supplied OIDs directly.

The change is well-tested with updates to t1460-refs-migrate.sh that now properly verify both old and new OIDs in migrated reflogs using a new test helper. This also provides coverage for the committer identity fixes from the previous patch. The implementation handles the files and reftable backends consistently and includes appropriate error checking.

This completes the series' goal of reliable reflog migration between storage formats, with all patches now in their final form and rebased on v2.50.1. The changes are focused and well-justified, addressing a real data integrity issue that could affect users converting between ref storage formats.
