This is a refactoring patch from Patrick Steinhardt's reflog migration series, now in its final merged state. The change exports the previously internal `ref_transaction_update_reflog()` function to make it available for other parts of Git that need to write reflog entries, specifically for the upcoming reflog migration work. 

The patch simplifies the function's interface by removing the `flags` parameter since all callers were using the same set of flags (REF_HAVE_OLD, REF_HAVE_NEW, etc.), which are now hardcoded inside the function. The documentation is updated to clarify that the index parameter defaults to ordering by refname when zero.

This is a straightforward plumbing change that enables future work while cleaning up the interface. The modification is minimal and well-contained, affecting only refs.c and refs.h. The commit message clearly explains the change and its motivation, and the patch follows Git's coding standards. As part of the larger reflog migration effort that has already been reviewed and merged, this change represents a small but necessary piece of infrastructure work.
