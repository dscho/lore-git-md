Refactoring patch in the reftable/libgit2 compatibility series, replacing Git-specific QSORT with standard qsort.

This patch continues Patrick Steinhardt's effort to make reftable usable by libgit2 by removing Git-specific dependencies. The change replaces the `QSORT()` macro with standard `qsort()` calls in two writer functions (`reftable_writer_add_refs()` and `reftable_writer_add_logs()`), adding explicit size calculations and null checks. The modification is straightforward but important for library portability.

The patch maintains identical sorting behavior while removing a Git implementation detail that would complicate external use. The null check addition (testing `n` before sorting) appears to be a defensive programming improvement rather than a bugfix, as the original QSORT macro would have handled zero-length arrays safely. This change aligns with the series' goal of making reftable a standalone library while preserving its functionality within Git.

Key technical details for future reference: the affected functions are core writer interfaces that sort ref/log records before writing; the comparison functions (`reftable_ref_record_compare_name` and `reftable_log_record_compare_key`) remain unchanged; the patch touches only writer.c with minimal delta (4 insertions, 2 deletions). This appears non-controversial as it's a mechanical change with clear motivation stated in the commit message.
