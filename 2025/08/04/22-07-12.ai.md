This is a technical review response in the ongoing commit-graph refactoring series aimed at removing global state dependencies. Taylor Blau is responding to patch 6/9 from Patrick Steinhardt's series, which changes how the commit-graph subsystem handles hash algorithms.

The patch replaces storage of just the hash algorithm's length with storing the full hash algorithm pointer, a necessary step for the broader effort to eliminate `the_repository` and `the_hash_algo` global dependencies. Taylor confirms the change makes sense and notes that existing validation in `parse_commit_graph()` already properly handles hash version mismatches by comparing the stored `hash_version` against `oid_version(the_hash_algo)`.

This appears to be one of the less controversial changes in the series, with Taylor providing a straightforward positive review. The technical merits are clear - storing the full algorithm pointer enables proper repository independence while maintaining existing safety checks. This contrasts with the more debated integer type changes earlier in the series, as noted in the thread context. The change is purely internal with no user-visible behavior modification, keeping with the series' goal of maintaining functionality while enabling future pluggable object storage.
