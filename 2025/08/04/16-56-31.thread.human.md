This thread addresses corruption issues in `git archive` when creating ZIP files containing large files, where files exceeding `core.bigFileThreshold` would produce bad CRC checksums or deflate errors. Justin Tobler initially diagnosed the problem as improper zlib compression loop handling in `archive-zip.c`. Toon Claes has led the solution with a four-patch series that systematically restructures the zlib usage to follow proper patterns.

The series progressed through incremental improvements: first simplifying buffer management, then removing unnecessary write conditions, and finally (in the third patch) adding proper input processing with a `do-while` loop. The just-arrived fourth and final patch completes the refactoring by moving the Z_FINISH flush operation into the main deflation loop, eliminating duplicate code and fully aligning with standard zlib practices. This change introduces a `flush` state variable and removes 16 lines of now-redundant post-loop handling.

The solution maintains focus on both fixing the corruption issues and improving code maintainability, with all changes confined to `archive-zip.c`'s compression path. Testing against the chromium.git reproduction case confirms the fixes work. With no outstanding technical objections raised during review, the series appears ready for final consideration by the maintainer.
