This thread addresses corruption issues in `git archive` when producing ZIP files containing large files that exceed `core.bigFileThreshold`, which can result in deflate errors or bad CRC checksums. Justin Tobler initially diagnosed the problem as improper zlib compression loop handling in `archive-zip.c`, and Toon Claes is now leading a comprehensive four-patch solution to restructure the zlib usage.

The first patch simplified buffer management in `write_zip_entry()` by centralizing zlib output buffer setup, eliminating duplicate initialization while maintaining behavior. The second patch, which just arrived, further cleans up the code by removing an unnecessary conditional check around `write_or_die()`, since the function can safely handle zero-length writes. This change makes the compression output path more straightforward without altering functionality, continuing the series' goal of improving zlib stream handling while fixing the corruption issues.

The changes focus on `archive-zip.c`, specifically around `zstream.next_out` and the `compressed` buffer array. Testing has confirmed the fixes work against reproduction cases from chromium.git. The remaining patches in the series will implement correct zlib compression looping and move the Z_FINISH flush into the main loop. The solution appears to be gaining traction, with Claes acknowledging Tobler's original diagnosis while proposing this alternative approach.
