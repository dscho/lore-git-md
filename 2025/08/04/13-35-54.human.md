This is a technical discussion about a bugfix for compiler warnings in the revert/cherry-pick sequencer code. The thread has been exploring different ways to handle a sentinel value that uses pointer addresses (rather than values) to track option states in `builtin/revert.c`.

Jeff King initially proposed initializing a const variable with a dummy value (option 3) to silence clang-22's `-Wdefault-const-init-var-unsafe` warning under DEVELOPER=1 mode. In this follow-up, he suggests another alternative: removing the "const" qualifier entirely since the pointers pointing to it are already const-qualified.

Patrick Steinhardt weighs in supporting the original approach, arguing it's a pragmatic solution with no real downsides - the comment explaining the dummy value might raise questions, but git-blame would lead to the explanatory commit. The discussion remains focused on technical correctness versus code clarity for this low-level C pattern used in shared sequencer logic.
