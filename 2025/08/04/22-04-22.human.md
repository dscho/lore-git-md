Reply in thread about integer type choices in commit-graph refactoring

This is a follow-up in the ongoing discussion about integer type choices in Patrick Steinhardt's series to remove global state from the commit-graph subsystem. Taylor Blau responds to patch 4/9, which addresses sign comparison warnings in commit-graph.c.

Taylor expresses mixed reactions to the changes. While sympathetic to using `size_t` for counting array elements, he questions the value of other type changes meant to silence compiler complaints. He specifically calls out a cast of `the_hash_algo->hexsz` to `ssize_t` as potentially making the code less clear without clear safety benefits.

The email continues the thread's central tension between Patrick's drive for type consistency and Taylor's preference for semantically meaningful types. Taylor's tone suggests this patch may need revision, though he doesn't outright reject the approach. The discussion remains technical and collegial, focused on maintainability tradeoffs rather than functionality.

This exchange is part of the broader series debate about how aggressively to standardize integer types during the `the_repository` removal work. While the series' core goal of eliminating global state remains uncontroversial, these implementation details continue to generate discussion.
