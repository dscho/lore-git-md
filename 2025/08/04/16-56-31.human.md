This is a bugfix series addressing issues with `git archive` when creating ZIP files containing large files. The problem manifests when files exceed `core.bigFileThreshold`, causing deflation errors and producing corrupted archives with bad CRCs.

The series builds on earlier work by Justin Tobler, who diagnosed the root cause - the ZIP archiving code wasn't properly handling the zlib compression loop for large files. Toon Claes presents two approaches: Justin's minimal fix (which addresses the immediate error but may leave edge cases) and a more comprehensive solution following zlib's official usage pattern.

The 4-patch series refactors the ZIP writing logic to:
1. Clean up buffer handling code
2. Remove redundant conditions
3. Properly implement the compression loop per zlib best practices
4. Move the final flush operation into the main loop

The changes are focused on `archive-zip.c` and while the series appears technically sound, the discussion may center on whether the more extensive refactor is justified versus the minimal fix. The chromium repository test case provides clear reproduction steps for validation.
