Refactoring patch in the `the_repository` removal effort, focusing on commit-graph hash algorithm handling. This is part 6/9 of Patrick Steinhardt's series to eliminate global state dependencies in the commit-graph subsystem.

The patch changes how the commit-graph stores hash algorithm information - instead of just storing the hash length (`hash_len`), it now stores a pointer to the full hash algorithm` structure (`hash_algo`). This is a preparatory change that will allow future patches to access more hash algorithm details beyond just the length.

The change is mechanical but widespread, touching 36 lines across commit-graph.c to update all references from `g->hash_len` to `g->hash_algo->rawsz`. The behavior remains identical since `rawsz` contains the same length value that was previously stored directly. The patch follows the series' pattern of making dependencies explicit rather than relying on globals.

This continues the incremental, behavior-preserving refactoring approach seen in earlier patches. No test changes are needed since the underlying behavior doesn't change - it just sets up infrastructure for later work in the series. The changes are focused and well-contained to the commit-graph implementation.
