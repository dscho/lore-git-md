Reply in the `git mv --after` proposal thread from Konstantin Khomoutov, providing technical clarification about Git's rename tracking.

This response explains that Git doesn't actually track renames in commits - it only records the before/after state of files. The proposed `--after` flag would therefore just be syntactic sugar for manually removing and adding the files. The email serves as a reality check on the proposal's technical merits, pointing out that the underlying rename detection would still rely on Git's existing heuristics rather than any explicit tracking.

Khormoutov's response suggests the feature might not provide as much value as initially thought, since the rename detection would work similarly whether the move was done via `git mv` or manually. This could influence whether maintainers see the proposal as worth implementing versus just documenting the current manual approach. The reply is technical but constructive, focusing on how Git actually works rather than dismissing the idea outright.
