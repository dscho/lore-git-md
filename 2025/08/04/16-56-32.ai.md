This is a refactoring patch in a series addressing `git archive` ZIP corruption issues. It's the first of four patches from Toon Claes that restructure the zlib compression handling in `archive-zip.c`.

The patch simplifies the buffer management in `write_zip_entry()` by moving the zlib output buffer setup (`next_out` and `avail_out`) to a single location right before the `git_deflate()` call, eliminating duplicate initialization code. This change doesn't modify behavior but makes the code more maintainable by centralizing the buffer setup logic. The patch retains Justin Tobler's co-authorship credit from earlier work on this issue.

Key technical details for future reference: the change affects the zlib stream buffer handling in the ZIP archiving path, specifically moving buffer setup into the compression loop. The variables involved are `zstream.next_out`, `zstream.avail_out`, and the `compressed` buffer array. This is preparatory work for the more substantial fixes to zlib compression handling that follow in the series.
