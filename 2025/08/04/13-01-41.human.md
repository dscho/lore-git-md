This is a follow-up discussion about a bugfix patch addressing a compiler warning in the revert/cherry-pick sequencer code. The original patch initialized a const variable used as a sentinel value to silence a clang warning under DEVELOPER=1 mode, where the variable's address (not its value) is used to track option states.

Jeff King (peff@peff.net) now suggests an alternative approach: removing the "const" qualifier from the sentinel variable entirely. He notes that while the pointers using this sentinel are declared as "const char *", they can legally point to a non-const variable. This would avoid both the compiler warning and the need for initialization or special comments explaining the workaround.

The discussion highlights the tradeoffs between different solutions to this technical issue, with the author reconsidering whether his initial approach (initializing the const variable with a comment) might be more confusing than alternatives like pointer casting or removing constness. This appears to be a minor but thoughtful refinement of the original fix.
