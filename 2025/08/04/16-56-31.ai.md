This is a bugfix series addressing issues with `git archive` producing corrupt ZIP files when archiving certain large files. The problem occurs when files exceed `core.bigFileThreshold` and manifests as either a "deflate error" or silent corruption with bad CRC checksums.

The series builds on earlier work by Justin Tobler who diagnosed the root cause - the ZIP archiving code wasn't properly handling the zlib compression loop for large files. While Tobler's minimal fix addressed the immediate crash, Toon Claes found it didn't fully resolve the corruption issues. Claes proposes a more comprehensive solution that restructures the zlib usage to match official patterns, calling `git_deflate()` in a proper loop like other Git code does.

The patch series:
1. First cleans up some redundant buffer handling code
2. Then implements the proper zlib compression loop
3. Finally moves the Z_FINISH flush into the main loop

The changes are focused in `archive-zip.c` and significantly reduce the code while making it more robust. Claes acknowledges Tobler's initial diagnosis but presents an alternative approach that may be more correct, leaving it to the community to decide which solution to adopt. The series appears well-tested against the reproduction case from chromium.git.
