This is part 4/9 in Patrick Steinhardt's series to remove global state dependencies from the commit-graph subsystem, focusing on fixing sign comparison warnings. The patch addresses several cases where signed integers were being used for counting operations that should logically be unsigned, or where signed/unsigned comparisons were triggering compiler alerts.

The changes are mechanical but important for correctness - converting loop counters, progress tracking variables, and chunk counts to use appropriate unsigned types. Notable fixes include bloom filter settings that used `-1` as a sentinel value (now properly cast), and several variables tracking commit-graph chain lengths that were incorrectly typed as `int`. The patch also removes a `DISABLE_SIGN_COMPARE_WARNINGS` define that was previously suppressing these issues.

As with earlier patches in the series, this is a behavior-preserving refactoring that maintains existing functionality while improving type safety. The changes align with the broader effort to make the codebase more robust in preparation for removing `the_repository` global and enabling pluggable storage backends. The patch shows careful attention to detail, with 27 lines changed across various commit-graph operations to ensure consistent unsigned counting.
