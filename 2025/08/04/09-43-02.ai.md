Test case demonstrating a remote.c push bug with invalid object IDs.

This is the first patch in a two-part series fixing a bug where pushing with a non-existent object ID (like all-zeros) to an unqualified ref destination incorrectly triggers a BUG() assertion. The test case creates a scenario where pushing an invalid OID (test_oid 001) to an unqualified branch name ("branch") would currently fail with a misleading BUG() message about the object ID being invalid, when the real issue is the unqualified refname.

The test is marked as test_expect_failure since it documents the broken behavior that will be fixed in the next patch. The test setup is minimal - it creates a test repository with mk_test and attempts the problematic push operation. The commit message includes the full error output that demonstrates the current incorrect behavior, showing both the proper advice about refname qualification and the incorrect BUG() assertion about object validation.

This test will serve to verify the fix in patch 2/2, which will replace the BUG() with proper advice about refname qualification. The test is narrowly focused on this specific edge case in push validation logic, isolated from other push scenarios.
