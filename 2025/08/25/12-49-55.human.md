This is a bugfix series addressing missing singleton objects in `git repack --path-walk` when sparse pack usage is enabled (the default). The issue occurs when repacking repositories containing files that have only one version in history and exist in the index, causing these objects to be incorrectly omitted from the repacked output.

The v2 series combines the test case and fix into a single patch (1/2) after feedback from Junio Hamano, while the second patch (2/2) introduces a refactoring to consolidate path list initialization to prevent similar issues. The test demonstrates the failure scenario with a carefully constructed repository state involving singleton blobs, staged changes, and cache-tree entries.

The root cause was an uninitialized `maybe_interesting` flag in the path-walk optimization code, which caused the repack to skip certain objects. The fix properly initializes this flag when setting up pending objects. The refactoring in patch 2 creates a helper function to standardize initialization of path lists, reducing the chance of similar oversights.

The series has been reviewed by Elijah Newren and Junio Hamano, with only minor wording improvements suggested. Performance data shows the path-walk optimization provides significant space savings (16GB to 6.4GB in one case) with moderate time improvements, justifying keeping the optimization despite its somewhat fragile implementation.
