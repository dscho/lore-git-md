This is a clarification about shallow clone implementation in the ongoing discussion about grafts removal.

Junio Hamano explains that shallow cloning actually uses neither the grafts mechanism (which is being removed) nor the intended replacement (git replace), but rather its own internal mechanism. While it happens to share some code paths with grafts, the data storage is separate from the grafts system.

This provides important technical context for the thread's core concern about whether shallow clones will continue working after grafts removal. The answer appears to be yes - since shallow clones don't actually depend on grafts proper, their functionality should remain intact. However, the explanation also highlights the complexity of the situation, with multiple similar-but-distinct mechanisms in play.

The response doesn't directly address the other major concern in the thread (the history.git repository's use of grafts), but does help clarify one of the two key use cases that had been worrying participants. The explanation suggests the grafts removal may be less disruptive to shallow clone operations than some feared, though the implementation details remain somewhat obscure.
