This is a refactoring patch in the `git-history` RFC series, specifically touching cache-tree functionality to support arbitrary in-memory index writes. The patch introduces a new `struct index_state` parameter to `write_in_core_index_as_tree()`, allowing callers to specify which index to write rather than always using the repository's index.

Junio Hamano notes this could potentially simplify the code paths for `git commit -o <pathspec>`, which currently uses a temporary index. However, he raises a consideration about hook exposure requiring the index to be written to disk, suggesting the change might not fully address that use case without additional work. The patch appears to be preparatory infrastructure for the larger `git-history` effort, with clean separation of concerns but some open questions about broader applicability.
