This is a refactoring patch in the line-log optimization series, specifically addressing patch 2/4 which eliminates dynamic allocation of diff queues in merge commit processing. The change converts the code from using an array of diff queues (one per parent) to processing each parent's diff queue immediately after it's computed, then clearing it before moving to the next parent.

The key technical change removes the `diffqueues` array allocation and replaces the two-pass approach (first compute all diffs, then process them) with an interleaved single pass. This reduces memory usage by avoiding storing all parent diffs simultaneously and simplifies cleanup by removing the need for a dedicated `free_diffqueues()` function. The diff shows a net reduction of 12 lines while maintaining the same functionality.

The change is purely internal with no behavior modifications, aligning with the series' goal of making the code both faster and cleaner.
