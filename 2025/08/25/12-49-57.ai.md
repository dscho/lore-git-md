Refactoring patch in the `git repack --path-walk` bugfix series, focusing on path list initialization.

This second patch in the v2 series introduces a new helper function `add_path_to_list()` that consolidates the initialization logic for path lists in `path-walk.c`. The change addresses code duplication that led to the bug fixed in patch 1, where some path lists weren't properly marked as `maybe_interesting`. The new helper handles allocation, type setting, paths map insertion, flag management, and OID array handling in one place.

The refactoring touches three main initialization sites that were previously handling these operations independently: tree entry processing, pending object setup for trees, and pending object setup for blobs. The patch maintains special handling for "fixed" lists (tags, commits, root trees, tagged trees, and tagged blobs) which operate differently and don't use the `maybe_interesting` flag.

Key technical details include:
- New static function `add_path_to_list()` with parameters for path, type, OID, and interesting flag
- Preserved behavior for root trees (still marked interesting) and tagged blobs (still go to special list)
- Reduced duplicate code while maintaining all existing functionality
- Follows from the bugfix in patch 1 where missing `maybe_interesting` flags caused issues

The change appears well-contained and builds on the established patterns in the path-walk machinery. It doesn't introduce new functionality but makes the existing code more maintainable and less prone to the kind of initialization oversight that caused the original bug. The patch has already been reviewed by Elijah Newren and Junio Hamano, with no outstanding technical concerns raised.
