Documentation patch clarifying limitations of `extensions.compatobjectformat` config option. This is a follow-up discussion in the thread about warning users that the SHA-1/SHA-256 interoperability feature is fundamentally incomplete.

Brian m. carlson acknowledges Junio C Hamano's point that "experimental" understates the feature's limitations, as it currently only works for loose objects via `git rev-parse` and cannot actually exchange objects between repositories with different hash algorithms. The thread establishes that the documentation should strongly discourage use by making clear this is purely a development tool, not a functional feature. Key technical limitations remain: no packed object support (making push/fetch non-functional), inefficient storage format, and missing submodule handling. The patch will be revised to use stronger wording emphasizing the extension exists solely for ongoing development work, not end users. This continues the thread's focus on preventing user confusion about a feature that was exposed prematurely without its core functionality implemented.
