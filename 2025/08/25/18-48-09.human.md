This is a performance discussion email in the ongoing thread comparing khash and commit-slab data structures for Git metadata storage. Junio Hamano responds to Jeff King's experiment showing commit-slabs performing 7x faster than khash for dense commit traversals in topological sorting.

Hamano expresses surprise at the magnitude of the performance difference, particularly since both approaches should be doing similar OID-based lookups. He questions whether the oidhash() range might be too small, though quickly dismisses this as unlikely given the kernel repository size. The email highlights how this dense-access scenario differs from the earlier `git describe` case where khash showed a modest advantage.

The exchange reinforces the emerging consensus that performance characteristics are highly context-dependent - with commit-slabs excelling in this dense traversal case while khash remains competitive for sparse access patterns. This moves the discussion toward understanding the underlying reasons for these performance characteristics rather than advocating one approach universally.
