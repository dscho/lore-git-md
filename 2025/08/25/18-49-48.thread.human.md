This thread discusses adding `-u` as shorthand for `--set-upstream` in `git pull` to match the existing `git push -u` behavior. Julien Jerphanion proposed the change to create consistency across Git commands, citing fork-based workflows like conda-forge as motivation. 

The technical implementation is straightforward - a one-line change in `pull.c` - but the discussion has stalled on whether this use case justifies permanently allocating the short option in Git's limited namespace. Junio Hamano, the maintainer, remains skeptical and has specifically asked for evidence that fork workflows actually involve frequent enough upstream changes to warrant the shorthand.

In the latest response, Julien clarifies that in their workflow, 'upstream' refers to official repositories, but they don't typically set local branches to track these upstream branches. While they reiterates the consistency argument with other Git commands, they haven't provided the quantitative data about usage frequency that Junio requested. 

The thread remains at an impasse. The maintainer appears to need either: (1) concrete evidence that `--set-upstream` is used frequently in real workflows, or (2) broader consensus that command consistency alone justifies the change. Until one of these is provided, this simple change will likely remain blocked despite its technical soundness.
