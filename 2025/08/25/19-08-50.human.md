This is the second patch in a documentation series improving the `git-checkout` man page. It focuses specifically on clarifying the branch switching behavior (`git checkout <branch>`), addressing several points of confusion reported by experienced users.

The patch makes four key improvements to the branch switching section:
1. Rewrites the introductory description to be more direct about what Git does ("Switch to _<branch>_" rather than "To prepare for working on...")
2. Standardizes on "changes" instead of "modifications" for consistency with other Git docs
3. Explicitly mentions that checkout will fail if there are merge conflicts
4. Clarifies the behavior of running `git checkout` without arguments, noting it's slower than using `git status` for tracking information

The changes are focused and well-motivated by user feedback, maintaining technical accuracy while improving clarity. The patch continues the series' pattern of careful rewording without altering functionality, showing good attention to both pedagogical concerns and consistency with the rest of Git's documentation.
