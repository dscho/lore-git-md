Technical clarification on Rust/C interop for the xdiff vector type.

Ezekiel Newren responds to Ben Knoble's questions about the `ivec` implementation in the Rust xdiff series. The exchange focuses on why Rust's native `Vec` isn't suitable for C interop and the design rationale behind the custom `ivec` type.

Key technical points:
- `Vec<T>` cannot be used directly for FFI due to unstable struct layout between Rust versions (demonstrates changes from 1.61.0 to 1.89.0)
- `#[repr(C)]` cannot be applied to `Vec` to stabilize its layout
- The `ivec` type was deliberately implemented in both C and Rust to avoid making Rust a hard dependency
- Current implementation lives in `interop/ivec.[ch]` and `rust/interop/src/ivec.rs`

Newren leaves the door open for alternative approaches but maintains the current design was necessary given versioning concerns and dependency constraints. This continues the thread's technical discussion while the fundamental policy impasse remains unresolved.
