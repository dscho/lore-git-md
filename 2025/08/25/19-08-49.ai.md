This is the first patch in a documentation series improving the `git-checkout` man page. It focuses on clarifying the introductory section and argument disambiguation behavior.

The patch makes several key changes to improve clarity for users:
1. Reorganizes the DESCRIPTION section to immediately present the two main modes of `git checkout` (branch switching and file restoration) rather than starting with technical terms like "index" and "pathspec"
2. Uses terminology ("Switch" and "Restore") that aligns with the newer `git switch` and `git restore` commands
3. Rewrites the ARGUMENT DISAMBIGUATION section to be more conversational and explicit about how Git interprets ambiguous arguments
4. Adds clear examples of using `--` to force interpretation as either a branch/commit or filespec

The changes maintain all existing functionality while making the documentation more approachable, particularly for users unfamiliar with Git's technical terminology. The patch shows careful attention to both accuracy and pedagogy, with clear examples and logical organization. As the first in a series based on user feedback, it sets up the foundation for subsequent clarifications in other sections of the man page.
