Documentation patch strengthening warnings about the experimental `extensions.compatobjectformat` feature. This is the third version of a patch that makes explicit the incomplete nature of this SHA-1/SHA-256 interoperability feature, following discussion on the mailing list about how the current documentation understates its limitations.

The patch adds clear language stating the extension is incomplete, subject to change, and exists solely for development/testing purposes - not for end users. This reflects the technical reality that the feature cannot actually exchange objects between SHA-1 and SHA-256 repositories due to lacking packed object support, despite being designed for that purpose. The current implementation only handles loose objects via `git rev-parse` while missing key components needed for practical use like packed object support, efficient storage format, and submodule handling.

The changes follow from thread discussion where Junio C Hamano and brian m. carlson agreed the original "experimental" label was insufficient since the feature doesn't fulfill its core purpose of inter-repo object exchange. The patch incorporates Junio's suggestion to use "extension" rather than "option" for consistency with surrounding documentation. The new wording aims to prevent user confusion, particularly for Gitolite administrators who might mistakenly believe the feature is functional.

Key technical limitations called out: no push/fetch functionality due to missing packed object support, inefficient storage format likely to change, and no submodule support. The patch follows Git's documentation best practices by being explicit about partial implementations that might mislead users about production readiness.
