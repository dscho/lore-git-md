This is the second patch in a bugfix series addressing issues with `git repack --path-walk` when handling singleton objects. The patch refactors path list initialization in the path-walk machinery to prevent future bugs.

The change introduces a new helper function `add_path_to_list()` that consolidates three separate initialization patterns that were previously duplicated in the code. This helper handles allocation, type setting, path map insertion, and OID array management in one place. The refactoring maintains all existing behavior while reducing the chance of initialization bugs like the one fixed in patch 1 of this series.

The patch keeps special handling for "fixed" lists (tags, commits, root trees) that operate differently from the main path-walk logic. Reviewers Elijah Newren and Junio Hamano have already looked at this version, which combines what was previously two separate patches in v1 of the series. The changes are focused on code organization and maintainability rather than behavior changes.

This appears to be a straightforward cleanup that follows naturally from the bugfix in the first patch. The consolidation of initialization logic makes the code more robust while keeping the same functionality. With the bug now fixed and the code better organized, this series seems ready for inclusion pending any final design discussions about the underlying optimization approach.
