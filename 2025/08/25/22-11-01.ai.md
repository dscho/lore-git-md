Documentation patch updating warnings about the experimental `extensions.compatobjectformat` config option. This follows up on thread discussion where it was agreed the documentation should more strongly emphasize the feature's limitations and development-only status.

The patch adds explicit text stating the option is incomplete, subject to change, and exists solely for development/testing purposes - not for end users. This reflects the technical reality that the feature cannot actually exchange objects between SHA-1 and SHA-256 repositories due to lacking packed object support, despite being designed for that purpose. The current implementation only handles loose objects via `git rev-parse` while missing key components needed for practical use.

The commit message explains the background: while the original documentation hinted at incompleteness, it didn't sufficiently warn users about the feature's non-functional state for its intended purpose of inter-repo object exchange. The new wording makes clear this is purely a development tool with known limitations (inefficient storage format, no submodule support, pathological performance characteristics) rather than a production-ready feature.

This aligns with the thread's consensus that the documentation should prevent user confusion by accurately representing the extension's capabilities, particularly for administrators who might otherwise mistakenly enable it expecting cross-hash-algorithm functionality. The patch focuses specifically on the config documentation while maintaining the technical details established in earlier discussion.
