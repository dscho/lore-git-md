Performance optimization follow-up in the `git describe` thread, testing khash vs commit-slabs in a different context.

Jeff King shares an experiment replacing a commit-slab (used for storing author dates in topological sorting) with a khash implementation, finding it performs *worse* - about 7x slower when running `git rev-list --author-date-order HEAD` on the Linux kernel. This contrasts with René Scharfe's earlier findings where khash showed a 3% speedup in `git describe`'s depth computation.

The patch demonstrates a complete conversion of the `author_date_slab` to use khash with object pointers as keys, including quality-of-life wrappers. While the implementation appears correct, the poor performance suggests commit-slabs may be better suited to densely-filled cases like this traversal. This adds nuance to the ongoing discussion about when each data structure is preferable.

The email doesn't propose changing course on the `git describe` optimization (where khash showed better results), but provides important real-world data about where commit-slabs maintain an advantage. It highlights how performance characteristics can vary significantly based on access patterns and data density.
