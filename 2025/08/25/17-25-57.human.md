This is a documentation patch thread discussing how to properly warn users about the experimental and incomplete nature of the `extensions.compatobjectformat` config option. 

Junio C Hamano responds to Brian Carlson's patch that added a warning about the feature's experimental status. While agreeing the warning is needed, Junio suggests the current wording might understate the feature's brokenness - it's not just experimental but fundamentally non-functional for key operations like push/fetch. He proposes stronger language emphasizing the feature exists solely for development purposes.

The discussion highlights how the feature's partial implementation (only working for loose objects) creates misleading expectations. Junio notes that "experimental" typically implies at least minimal functionality, whereas this feature can't complete basic repository operations. The thread shows maintainers being careful to properly set user expectations for a feature that was prematurely exposed.

This is part of ongoing work to properly document the limitations of SHA-1/SHA-256 interoperability features, particularly important since some users (like Gitolite) have tried using the feature despite its incomplete state. The exchange demonstrates Git's careful approach to labeling experimental features.
