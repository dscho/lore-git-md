Bugfix for progress meter delay functionality, part of the signal-free timer implementation effort.

Johannes Sixt fixes a long-standing bug in Git's progress meter delay handling where the delay was effectively always just 1 second, regardless of the configured GIT_PROGRESS_DELAY value. The issue stemmed from the progress_update flag not being reset after being checked, causing subsequent calls to incorrectly count down the delay. The patch properly captures the flag state in a local variable and resets it immediately.

Since users seem comfortable with the current 1-second behavior (despite the documentation previously claiming a 2-second default), the patch updates both the implementation and documentation to make 1 second the official default. This change aligns with the ongoing signal-free timer work that has been discussed in the thread, though it's a separate bugfix from the core signal infrastructure changes.

The patch is a straightforward fix that improves correctness while maintaining existing user experience. It follows the thread's recent discussion about variable typing by using `int` rather than `sig_atomic_t` for the local flag (though the commit message notes this could be `bool` in newer code). This appears to be a well-justified change that closes a subtle but long-present bug.
