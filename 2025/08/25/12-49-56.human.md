Bugfix for `git repack --path-walk` handling of singleton objects. This is the first patch in a v2 series addressing an issue where certain objects (particularly staged changes and cache-tree entries) could be incorrectly omitted from repacks when using the path-walk optimization with `pack.useSparse=true` (the default).

The patch fixes an initialization oversight in `setup_pending_objects()` where the `maybe_interesting` flag wasn't being set for objects added from the index. This caused the path-walk machinery to skip these objects during repacking if they only had one version in the repository. The fix is straightforward - properly initializing the flag when adding these pending objects.

The commit includes a comprehensive test case that demonstrates the problem by creating several scenarios: a file with only one committed version, staged changes that exist only in the index, and cache-tree entries. The test verifies these objects are properly retained after a path-walk repack. The test also incidentally confirms a known limitation with `git fsck` not checking resolve-undo cache entries, though that remains a separate issue.

This version combines the test and fix that were previously separate patches in v1, following feedback from Junio Hamano. The patch has been reviewed by both Elijah Newren and Junio, with positive feedback on the technical approach. The fix is low-risk and addresses a real data-loss scenario, making it a strong candidate for inclusion.
