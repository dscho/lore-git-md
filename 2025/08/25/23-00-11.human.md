This is a documentation patch finalizing warnings about the experimental `extensions.compatobjectformat` feature. Junio C Hamano confirms acceptance of brian m. carlson's v3 patch series, which strengthens documentation to clearly state this SHA-1/SHA-256 interoperability feature is incomplete and unsuitable for production use. The series evolved through careful review, with this final version incorporating Junio's suggested terminology change from "option" to "extension" for consistency with surrounding documentation.

The patch documents known limitations: the feature only works for loose objects (not packed objects), lacks push/fetch functionality, has inefficient storage, and doesn't support submodules - making it fundamentally unable to achieve its intended purpose of object exchange between hash-algorithm-different repositories. The warnings aim to prevent Gitolite administrators and others from mistakenly deploying this development-only feature.

Junio indicates he'll apply the patch with a fixup (a Git commit amendment technique), suggesting this concludes the thread. The discussion demonstrates Git maintainers' attention to precise wording when documenting experimental features, especially when partial implementations might mislead users about production readiness. The final version accurately reflects the technical consensus that this extension exists solely for testing purposes.
