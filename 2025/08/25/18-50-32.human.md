This is a code clarity improvement in the ongoing progress meter signal handling refactoring. Junio Hamano and Carlo Marcelo Arenas Belón are discussing the variable typing for the progress update flag in the signal-free implementation that Johannes Sixt proposed.

The discussion focuses on whether to use `sig_atomic_t`, `int`, or `bool` for the local `update` variable that tracks whether progress should be displayed. Hamano had previously noted that using `sig_atomic_t` was misleading since the variable isn't signal-accessed, suggesting `int` instead. Carlo now proposes using `bool` for clearer semantic intent.

Hamano responds that any non-`sig_atomic_t` type would be acceptable here, noting that while Git has been adopting `bool` in new code, that's somewhat orthogonal to the current discussion about signaling semantics. This exchange represents the final polish on the already-agreed signal-free approach, with the technical solution settled and now focusing purely on code readability.
