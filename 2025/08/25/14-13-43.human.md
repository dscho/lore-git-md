Performance optimization for line-log merge processing. This is the first patch in a series that improves Git's line-log functionality (`git log -L`), specifically focusing on merge commits.

Derrick Stolee provides additional benchmarking and analysis of SZEDER Gábor's patch that optimizes merge commit handling in line-log.c. The original patch combined two separate operations (diff computation and processing) into one pass, avoiding unnecessary tree diffs when the first parent shows no changes to tracked paths. Stolee's testing confirms significant speedups across multiple repositories, with particularly impressive results in a large internal monorepo where the new version runs 2.18x faster.

The email also explores how this optimization interacts with changed-path Bloom filters, noting that while the filters already provide some performance benefits by avoiding merge processing, this patch delivers additional gains especially for users without Bloom filters enabled. Stolee's analysis reveals that much of the Bloom filter's benefit actually came from avoiding the same redundant work this patch eliminates, making this a valuable improvement for all users.

The patch appears well-vetted, with multiple independent benchmarks showing consistent performance improvements.
