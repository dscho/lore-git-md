Performance optimization experiment comparing commit-slabs and khash for author-date storage in topological sorting.

Jeff King shares experimental results from replacing a commit-slab with a khash-based implementation for storing author dates during topological sorting. The test case (`git rev-list --author-date-order HEAD` on the Linux kernel) shows the khash version performing 7x slower than the slab version, contrary to earlier findings where khash showed advantages in sparse commit scenarios.

Key technical details:
- The patch introduces a new `obj_timestamp` khash type using object pointers as keys with OID-based hashing
- Wrapper functions (`obj_timestamp_put/get`) provide similar interface to commit-slabs
- Changes affect both standalone topological sort in `commit.c` and revision walker in `revision.c`
- The test case represents a dense commit graph scenario where commit-slabs' cache locality shines

This demonstrates that while khash may outperform commit-slabs in sparse access patterns (as seen in the `git describe` case), commit-slabs maintain clear advantages for dense traversals. The results validate Jeff King's earlier position about commit-slabs being better suited for certain access patterns, though he acknowledges the macro-heavy interface remains a maintenance burden.

The experiment doesn't directly impact the ongoing `git describe` optimization discussion (where khash shows a 3% advantage), but provides important context about data structure selection tradeoffs in different scenarios. The findings suggest that neither approach is universally superior - the optimal choice depends on the specific access patterns of each use case.
