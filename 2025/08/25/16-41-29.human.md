This is a refactoring patch in Patrick Steinhardt's `git-history` RFC series, specifically splitting the `add-patch` declarations from `add-interactive.h` into a new `add-patch.h` header. The change cleanly separates the patch-specific declarations from the broader interactive add functionality, reducing the header's size by 20 lines while creating a more focused interface.

Junio Hamano notes that the refactoring makes conceptual sense since it isolates the patch-specific code from other `add -i` operations. However, he raises an interesting point about clients like `git reset -p` that use the patch machinery but don't need the rest of the interactive add functionality - these clients could potentially be updated to include only the new `add-patch.h` rather than the full `add-interactive.h`.

The patch appears to be a straightforward and well-motivated code organization improvement that's part of the larger preparatory work for the `git-history` feature. Junio's observation suggests there may be follow-up opportunities to further optimize header inclusions in other commands that use the patch functionality.
