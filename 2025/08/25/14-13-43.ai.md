Performance optimization for line-log merge processing, with additional benchmarking analysis.

This is a follow-up discussion to patch 1/4 in the line-log optimization series, where Derrick Stolee provides additional performance measurements and analysis of SZEDER Gábor's changes to `process_ranges_merge_commit()`. Stolee confirms the original speedup claims (2.18x in an internal monorepo) and explores interaction with changed-path Bloom filters, finding they reduce but don't eliminate the optimization's impact (1.15-1.38x speedups when filters are present).

Key technical details confirmed:
- The optimization avoids unnecessary tree diffs against secondary parents when first parent shows no changes
- Changed-path Bloom filters already provided some similar benefits by skipping merge processing entirely when first parent is TREESAME
- The patch's cleanest win is for repositories without Bloom filters (where speedups reach 2x+)
- Internal implementation removed `free_diffqueues()` helper and consolidated diff processing into single loop

Stolee's testing methodology is thorough, comparing both with and without Bloom filters across multiple repositories (git.git, linux.git, internal monorepo). The analysis reveals the optimization complements rather than conflicts with Bloom filter acceleration, making it valuable regardless of filter availability. The discussion reinforces the patch's value while providing deeper context about its interaction with existing performance features.
