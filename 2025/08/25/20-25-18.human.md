This is the final patch series in the bulk-checkin refactoring effort, completing the removal of global transaction state as part of the larger `the_repository` elimination project. The series has gone through multiple rounds of review and iteration, with all feedback addressed.

The key changes in this version include combining `index_blob_bulk_checkin()` with `deflate_blob_bulk_checkin()` for cleaner organization, consistently using `repo_get_object_directory()`, and enforcing that callers must provide a properly set up transaction structure. The implementation now fully routes repository access through the transaction's object database rather than using global state.

Junio Hamano gives the final approval, indicating the series is ready to be merged. The changeset touches several builtin commands (add, unpack-objects, update-index) and core object handling code, with significant modifications to bulk-checkin.c. While two globals remain (pack_compression_level and pack_size_limit_cfg), this represents a major step forward in the architectural cleanup.

The work maintains existing behavior while enforcing stricter transaction requirements, paving the way for future pluggable ODB backends. The series appears well-tested with all callers updated to handle the new transaction model, demonstrating the careful incremental approach taken throughout this refactoring effort.
