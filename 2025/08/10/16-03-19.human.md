This is the final patch in a 3-part series modernizing editor-related test infrastructure and code. The patch updates Git's editor APIs to use the modern strvec interface for environment variables rather than the older const char** approach.

The change is a straightforward refactoring that maintains all existing behavior while bringing the editor code in line with current Git conventions. The patch modifies three functions in editor.c/h to accept strvec pointers instead of string arrays, and updates the single caller in builtin/commit.c that passes environment variables (for GIT_INDEX_FILE) to use the new interface.

The change builds on prior work from 2007 and 2017, completing the migration to dynamic allocation that was started earlier. The commit message notes there's only one non-NULL environment caller, which already has a strvec available, making this a clean conversion. The patch has been reviewed and helped by Johannes Schindelin.

This is a technical improvement that follows Git's established patterns, with no expected controversy. It concludes the series which has evolved from initial security concerns to focus on uncontroversial test and code modernization, as discussed in the thread.
