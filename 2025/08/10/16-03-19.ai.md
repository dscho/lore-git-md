This is the final patch in a 3-part series modernizing editor-related code and tests, focusing on converting the editor API to use the standard strvec interface for environment variables.

The patch updates the editor functions in editor.c and editor.h to accept a `struct strvec` pointer` for environment variables instead of the older `const char *const *` array. The change is behavior-preserving but brings the editor code in line with Git's modern string handling conventions. The only caller that passes environment variables (in builtin/commit.c) already has a strvec available, making this a straightforward conversion.

Key technical details:
- Updates all three editor-related functions in editor.h to use `struct strvec *` instead of `const char *const *` for environment parameters
- Modifies the implementations in editor.c to handle the new parameter type
- Changes the single caller in builtin/commit.c to pass its strvec directly
- Maintains all existing functionality while modernizing the API
- Builds on previous strvec conversions (8babab95af, 8d7aa4ba6a, 46b225f153)
- Touches builtin/commit.c, editor.c, and editor.h

The patch completes the series' goal of modernizing editor handling code after the earlier test improvements in patches 1-2. It has already received positive feedback from reviewers and aligns with Git's ongoing migration to the strvec API. The changes are straightforward and uncontroversial, with no expected impact on behavior or performance.
