Bugfix for `git diff --no-index` behavior when used within a Git repository.

Junio Hamano fixes an edge case where `git diff --no-index` (which is meant to behave like a standalone diff tool) incorrectly handles the working directory when run inside a Git repository. Normally Git's startup sequence changes to the repository root, but this causes problems for `--no-index` mode which should ignore repository context entirely. The fix ensures the command returns to the original directory and clears the prefix, making it behave as a proper standalone diff tool.

The patch includes a new test case that specifically checks the `-` (stdin) special case, which previously failed due to the directory handling issue. The change is small (15 lines) and focused, with error handling added in v2 based on feedback. This appears to be a straightforward correction of unintentional behavior in a rarely-used mode.
