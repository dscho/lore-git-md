This is the final patch in a 3-part series modernizing editor-related test infrastructure and API, building on earlier discussion about exec-path security concerns. The series has evolved from its initial focus on process spawning behavior to uncontroversial infrastructure improvements after community feedback.

The patch updates all three editor-related functions in editor.h to use `struct strvec *` for environment parameters, with corresponding implementation changes in editor.c. The single caller in builtin/commit.c is modified to pass its strvec directly. This maintains existing functionality while modernizing the API to match Git's current string handling conventions (building on prior strvec conversions like 8babab95af).

Key technical details include:
- Behavior-preserving conversion of `setup_editor()`, `launch_editor()`, and `launch_sequence_editor()` functions
- Files touched: builtin/commit.c, editor.c, editor.h
- Maintains all existing editor functionality while using modern strvec API
- Follows established patterns from previous strvec conversions

The patch has already received positive feedback from reviewers including Patrick Steinhardt, who approved the strvec conversion approach. It represents the final piece of a well-reviewed series that addresses test isolation concerns through subshell wrapping (patch 2) and now completes the modernization of editor environment handling. The changes are straightforward with no impact on behavior or performance.
