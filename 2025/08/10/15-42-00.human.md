This is a follow-up discussion on the recently merged documentation patch series for `git-rebase`. Phillip Wood provides two technical corrections to the newly added "detailed description" section in the man page.

First, he points out that the commit selection logic should reference `git log --cherry-pick --right-only <upstream>...HEAD` rather than the simpler `git log <upstream>..HEAD` shown in the documentation, since rebase automatically drops commits that have already been cherry-picked to the upstream branch. This is a subtle but important distinction in how rebase determines which commits to replay.

Second, he notes that the documentation should mention `--reapply-cherry-picks` alongside `--fork-point` and `--root` as another option that affects how the commit list is constructed. This maintains consistency with the thoroughness shown throughout the rest of the documentation improvements.

The feedback is constructive and aligns with the series' goal of technical accuracy while improving readability. Phillip acknowledges the overall improvement to the documentation's clarity, and his suggestions would make the internals description even more precise. These appear to be straightforward corrections that could be addressed in a follow-up patch if the maintainers agree.
