This is a bugfix for the `git-jump` contrib script, addressing its handling of filenames containing spaces in diff output. The patch follows up on the ongoing discussion about how Git's output format (which appends tabs to filenames containing spaces) interacts with Vim's quickfix mode.

The proposed solution modifies the Perl regex in `git-jump` to optionally strip trailing tabs when parsing diff output. This fixes the common case of filenames with spaces while intentionally breaking the edge case of filenames ending with literal tabs. Junio Hamano notes he doesn't personally use git-jump but agrees with the tradeoff, acknowledging that space-containing filenames are the practical concern while tab-terminated ones are extremely rare.

The change is minimal (a one-line regex modification) and well-justified in the commit message, which clearly explains the three possible filename cases and why this solution makes sense. The patch maintains focus on the contrib script rather than trying to change Git's core diff output behavior. While alternative approaches are noted (like making tab-stripping conditional or using `--patch-with-raw`), the current solution is presented as the right balance of simplicity and effectiveness.

Key technical details for future reference: the regex change from `(.*)` to `(.*?)\t?$` in the Perl one-liner, the specific interaction between `diff.c`'s tab-appending behavior and Vim's quickfix parsing, and the three filename test cases described in the commit message (space-containing, tab-terminated, and both). The discussion suggests this may be revisited if users report problems with tab-terminated filenames, but considers that unlikely.
