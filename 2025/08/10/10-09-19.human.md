This is a follow-up discussion about the ongoing bugfix for `git-jump`'s handling of filenames with spaces in diff output. Phillip Wood suggests an alternative approach to the current solution (which strips trailing tabs from filenames) - parsing the "diff --git" line directly, similar to how `git apply` works. 

The key points are:
1. The proposed solution would use the post-image filename from the "diff --git a/file b/file" line (or pre-image for deletions)
2. This would work because `git-jump` generates diffs with `--no-prefix`
3. Deletions would need special handling by checking either the "+++" line or looking for "deleted file mode"

This approach would potentially handle all edge cases (filenames with spaces, ending in tabs, or both) without the tradeoffs of the current solution. However, it would require more complex parsing logic compared to the simple regex currently proposed. The discussion continues to explore the best way to handle this long-standing edge case in the contrib script.
