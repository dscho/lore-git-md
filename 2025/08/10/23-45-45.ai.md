This is part 1 of a 2-patch series in the ongoing `the_repository` removal effort, specifically targeting the `merge_log_config` global variable used in merge message formatting. The patch localizes this variable within `cmd_fmt_merge_msg()` and `cmd_merge()` functions, passing it via callback parameters instead of using the deprecated global.

The changes affect several files, with the main modifications being:
- Removal of `merge_log_config` from `environment.c`
- Addition of local variables in `builtin/fmt-merge-msg.c` and `builtin/merge.c`
- Update to `fmt_merge_msg_config()` to use the callback parameter instead of the global
- Removal of the extern declaration from `fmt-merge-msg.h`

The patch maintains the existing behavior where `merge.summary` takes precedence over `merge.log` when both are set, and preserves the special handling of boolean values (defaulting to `DEFAULT_MERGE_LOG_LEN` when true). The changes appear focused and well-contained, with the diff showing straightforward mechanical transformations of the config handling logic.

This represents progress on the technical requirements from the v1 review, particularly around maintaining config precedence while eliminating global state. The patch doesn't yet address all outstanding concerns from the thread (like repository initialization timing), but provides a clean foundation for those follow-ups. The changes look technically sound for this specific aspect of the refactoring.
