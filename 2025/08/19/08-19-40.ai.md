This is part 11 of Patrick Steinhardt's ongoing refactoring series to move packfile management into a dedicated `packfile_store` structure as part of the object database abstraction effort.

The patch addresses an inconsistency in how packfiles are added to the Most-Recently-Used (MRU) list. Currently, some subsystems add packfiles to the MRU list when first adding them to the store (like in midx.c), while others don't (like the core packfile_store_add_pack function). The patch standardizes this behavior by always adding packfiles to the MRU list when they're first added to the store.

Key technical changes:
- Removes the manual MRU list addition from midx.c's prepare_midx_pack()
- Adds MRU list insertion directly in packfile_store_add_pack()
- Maintains the same MRU ordering behavior (using list_add_tail)
- Affects both the midx.c and packfile.c components

This continues the series' pattern of moving packfile-related state and behavior into the packfile_store structure while maintaining existing functionality. The change appears straightforward and mechanical like previous patches in the series, with no expected behavior changes beyond the intended consistency improvement.
