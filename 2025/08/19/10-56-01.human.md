This is a feature patch implementing the first subcommand (`drop`) for the proposed new `git-history` command, part of Patrick Steinhardt's RFC series to provide more intuitive history editing operations.

The patch adds a `git history drop <commit>` command that removes a commit from history while preserving its descendants by replaying them on top of the dropped commit's parent. This simplifies what would otherwise require an interactive rebase. The implementation handles edge cases like dropping the root commit (converting its child to the new root) and refuses to operate on merge commits or when it would leave an empty branch.

The command builds on Git's existing sequencer infrastructure, reusing components like `reset_head()` and the replay machinery while adding new logic to collect and reorder commits. The 300+ lines of implementation come with thorough tests covering basic dropping, middle-of-chain removal, root commit handling, and merge commit rejection.

As an RFC, this shows a promising direction for simplifying common history edits, though the series still has open questions around merge handling and conflict resolution that will need addressing before final version. The clean implementation and comprehensive test coverage suggest this is a serious proposal worth considering for inclusion.
