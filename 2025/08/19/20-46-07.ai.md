This is a documentation patch series (v3) refining the `git-add` man page, now reduced to 3 patches from the previous v2's 4. The series focuses on improving clarity and accessibility for beginners while maintaining technical accuracy, as part of the ongoing documentation improvements thread.

The main changes in this version are:
1. Restructuring the DESCRIPTION section to be more example-driven and less jargon-heavy
2. Clarifying the relationship between "index" and "staging area" terminology
3. Simplifying the explanation of how `git add` handles ignored files
4. Removing redundant explanations about the index's snapshot model
5. Better explaining default commit behavior and the `-p` option

Key technical adjustments include:
- Added concrete example of basic `git add`/`git commit` workflow
- Changed "must use" to "can use" regarding `git add` before commit (acknowledging `commit -a`)
- Moved `--force` option explanation earlier in ignored files section
- Removed discussion of shell vs Git globbing gotchas
- Kept only one reference to "index"/"staging area" equivalence

The series has been reviewed by Junio Hamano and incorporates feedback from multiple users. The changes appear well-considered, focusing on pedagogical clarity while avoiding information overload.
