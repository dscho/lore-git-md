Core problem: The grafts mechanism is scheduled for removal, but key use cases like history.git demonstrably depend on it. The replacement mechanism (git replace) needs verification for these cases before grafts removal. Shallow clone operations were initially thought to depend on grafts but have been clarified to use a separate mechanism.

Current status: Grafts remain available but marked for removal in Git 3.0. No demonstrated migration path exists for history.git. Shallow clone operations have been confirmed to use their own mechanism (separate from grafts) and won't be directly affected by grafts removal.

- Functional requirement: history.git must have a working migration path before grafts removal
