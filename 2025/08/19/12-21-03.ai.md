Feature addition to reftable fsck validation. This is patch 4/5 in Karthik Nayak's series adding fsck checks for the reftable backend. The patch introduces validation for a trailing newline in `tables.list` files, which the reftable backend expects but doesn't currently verify.

The implementation adds a new error type `REFTABLE_FSCK_ERROR_STACK_LIST_MISSING_NEWLINE` and corresponding fsck message ID `badReftableStackListNewline`. The check is performed by reading the last character of the file and verifying it's a newline. The patch follows the established pattern of the series by adding the check to `reftable/fsck.c` while keeping the fsck infrastructure changes minimal.

Key technical details include: a new `reftable_fsck_stack_contains_newline()` function that uses `fseek/ftell` to check the last byte; integration with the existing error reporting mechanism via `reftable_fsck_info`; and a test case that verifies the check by manually removing the newline from `tables.list`. The error message includes the path to the malformed file for debugging.

This continues the series' clean separation between reftable internals and fsck infrastructure while expanding validation coverage. The rationale is that missing newlines indicate manual tampering, though the reftable format itself doesn't strictly require them. The implementation is thorough with proper error handling and test coverage.
