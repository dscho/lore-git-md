This is the final patch in a three-part series completing Meson build system integration for Git's Tcl/Tk-based GUI components (gitk and git-gui). The patch wires up the subprojects that were relocated in the first two patches, making them buildable via Meson with feature parity to the Makefile system.

The changes add Meson build rules for both gitk and git-gui, controlled by new options in meson_options.txt. The build system now checks for required Tcl/Tk tools (tclsh and wish) and automatically disables the GUI components if dependencies are missing. The patch maintains the same conditional build behavior as the Makefile system, where gitk and git-gui are built by default if their dependencies are present.

Key technical details include:
- New `gitk` and `git_gui` feature options in meson_options.txt
- Dependency checks for `tclsh` (git-gui) and `wish` (both)
- Subproject integration via `subproject()` calls
- Build summary reporting for both components
- Careful handling of auto-disable when dependencies are missing

This completes the Meson integration work for these GUI tools, marking a significant milestone in achieving full feature parity between Meson and Makefile builds. The changes are purely build-system related with no runtime impact. As noted in the thread, follow-up documentation updates will be needed to reflect Meson's new status as a fully-supported build system option.
