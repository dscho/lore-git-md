Bugfix introducing reftable fsck validation for table names. This is the second patch in Karthik Nayak's 5-part series adding fsck validation to the reftable backend. It builds on the infrastructure from patch 1 (which alphabetized fsck message types) to implement the first concrete validation check - verifying proper table naming in `tables.list`.

The patch introduces a new `reftable/fsck.[ch]` module that provides validation while maintaining separation between Git's fsck implementation and reftable internals. The core validation happens in `reftable_fsck_check()`, which verifies table names match the expected format (hex min/max timestamps with random suffix and `.ref` extension). Errors are mapped to Git's fsck system via a new `badReftableTableName` message ID.

The implementation includes:
- New `reftable_fsck_info` struct and error reporting callbacks
- Glue code in `refs/reftable-backend.c` to bridge between Git fsck and reftable validation
- Comprehensive test in `t0614-reftable-fsck.sh` that verifies both success and failure cases
- Build system updates to include the new fsck module

This appears to be a well-structured patch with clear separation of concerns between the reftable library and Git's fsck system. The test coverage is thorough, checking both valid and intentionally corrupted cases. The changes are focused and maintainable, following the pattern established in the series' architectural approach.
