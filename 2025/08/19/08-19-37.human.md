This is part 8 of Patrick Steinhardt's ongoing refactoring series to move packfile management into a dedicated `packfile_store` structure as part of the object database abstraction effort.

The patch refactors the `prepare_packed_git()` function and related helpers to operate on a `packfile_store` rather than a repository. The changes include:
- Renaming `prepare_packed_git()` to `packfile_store_prepare()`
- Moving the MRU (most recently used) list preparation into `packfile_store_prepare_mru()`
- Consolidating the pack sorting directly into the prepare function rather than using a separate helper
- Updating all callers to pass the packfile store instead of repository

The changes are mechanical but touch many call sites across packfile.c, as this is a core function used throughout the packfile subsystem. The patch maintains all existing behavior while shifting the implementation to work with the new store structure. This continues the series' pattern of moving packfile-specific functionality out of the generic object database structure.

The patch appears well-contained and follows the established pattern from previous patches in the series. It's part of the larger technical groundwork needed for future pluggable ODB backends, though this particular change doesn't introduce any new functionality.
