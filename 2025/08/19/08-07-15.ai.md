This is a feature proposal for a new `git history` command that could serve as a building block for graphical history manipulation tools. Patrick Steinhardt responds to Junio Hamano's suggestion about creating a GUI frontend for rebase operations by mentioning an upcoming patch series that introduces a new command-line interface for history manipulation.

The proposed `git history` command would provide subcommands for basic history operations like reordering commits (`reorder`), removing commits (`drop`), and splitting commits (`split`). The interface appears designed to be more intuitive than raw rebase -i commands, with explicit positional arguments for commit relationships (--before/--after). 

While positioned as a starting point, this CLI approach could potentially serve as the backend for a future GUI tool, addressing the workflow needs raised in the original request. The email suggests this could evolve with additional subcommands over time. The implementation appears to be more concrete than the high-level GUI discussion so far, though we'll need to see the actual patches to evaluate the technical approach.

This represents a potential middle ground between pure CLI rebase and full GUI tools, offering structured commands that could be both used directly and potentially driven by graphical interfaces. The mention of sending the series later suggests we'll soon have concrete code to evaluate for this approach to history manipulation.
