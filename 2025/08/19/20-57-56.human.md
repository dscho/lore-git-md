This is a follow-up in the `git whatchanged` discussion thread, offering a practical workaround suggestion. Randall Becker proposes using a Git alias to maintain similar functionality if/when the legacy `git whatchanged` command is removed. The suggestion is straightforward - creating a global alias that maps `whatchanged` to `log`, which would preserve the ability to use familiar syntax like `git whatchanged --since="2 week"`.

The email doesn't introduce any new technical changes or proposals, but rather provides a user-level solution to the potential deprecation of `git whatchanged`. It's a practical response to the original thread's concern about command usage, though it doesn't address the parallel discussion about mailing list submission issues that emerged in this thread.

The suggestion appears well-intentioned and technically sound, though it's worth noting that the alias would need additional flags (`-p --raw --no-abbrev`) to fully replicate `git whatchanged`'s current behavior. The email maintains a helpful tone while acknowledging the command's likely eventual removal.
