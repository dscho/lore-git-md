This is part 4/5 of Karthik Nayak's reftable fsck validation series, focusing on detecting malformed reftable files. The patch adds a check for missing trailing newlines in `tables.list` files, which the reftable backend always writes with a newline but doesn't verify when reading.

The change introduces a new error type `REFTABLE_FSCK_ERROR_STACK_LIST_MISSING_NEWLINE` and corresponding fsck message ID `badReftableStackListNewline` to flag files that appear to have been manually tampered with. The implementation checks the last character of the file and reports an error if it's not a newline, with test coverage verifying both valid and invalid cases.

This continues the series' pattern of adding focused validation checks while maintaining clean separation between fsck infrastructure and reftable internals. The patch is well-contained with thorough test coverage, addressing a subtle but potentially important consistency check for the reftable backend.
