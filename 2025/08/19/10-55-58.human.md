This is a preparatory patch for the `git-history` command series, modifying sequencer internals to support history editing operations. Authored by Patrick Steinhardt, it introduces a new `restore_head_target` option that allows the sequencer to reset HEAD to its original branch after operations like cherry-pick, similar to how rebase already handles this.

The change is motivated by the upcoming `git-history` command which needs to detach HEAD during operations but restore it afterward, without using the full rebase machinery. The patch adds persistence for this setting across sequencer operations (like when handling merge conflicts) and implements the actual HEAD resetting logic using the existing `reset_head` infrastructure.

The implementation looks thorough, touching all the expected places in the sequencer code - option handling, serialization, and the actual operation logic. It's a focused change that clearly serves the needs of the larger `git-history` effort while being self-contained enough to review independently. The commit message provides good context about why this is needed now and how it differs from existing behavior.
