Bugfix for dangling symref handling in refs backend. This is the final patch in a 4-part series addressing incorrect behavior with dangling symrefs and `followRemoteHEAD=create` in `git fetch`. The core issue is that fetch would overwrite explicitly created remote HEAD symrefs despite being configured to only create them if missing.

The patch fixes a subtle edge case where dangling symrefs (those pointing to non-existent refs) could be silently overwritten during `--no-deref` operations. The fix modifies both files and reftable backends to properly detect and preserve dangling symrefs when they should be treated as existing refs. The commit includes detailed examples showing both the problematic cases and correct usage patterns.

New tests verify the behavior for both direct `update-ref` usage and the `followRemoteHEAD` fetch configuration that originally exposed the issue. The implementation maintains consistency between backends while following their existing conventions (notably differing in translation of error messages).

This completes the series after preparatory test modernization in earlier patches. The change is well-motivated and carefully implemented, with clear documentation of both the problem and solution in the commit message.
