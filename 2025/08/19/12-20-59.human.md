This is a feature series introducing fsck checks for the reftable backend. Karthik Nayak proposes adding infrastructure to validate reftable consistency while maintaining separation between Git's fsck implementation and the reftable library internals.

The series creates a new 'reftable/fsck.[ch]' module that implements checks specific to reftable's structure, then maps those to Git's fsck error system. The initial checks focus on the tables.list file, verifying: proper naming conventions, table count consistency, trailing newlines, and correct index sequencing. The implementation touches fsck message IDs, build systems, and adds new test cases.

The approach looks well-considered, with clear separation of concerns between library and Git integration layers. The commit messages explain the technical rationale well, and the test coverage appears thorough for the initial checks. Karthik mentions plans for follow-up series to add deeper validation of tables, blocks, and references, suggesting this is the foundation for more comprehensive reftable verification.

For those working with reftable or interested in Git's data integrity tools, this series warrants attention as it establishes important validation infrastructure for the newer backend. The implementation appears clean and focused on maintainability, though reviewers may want to scrutinize the error mapping approach between layers.
