This is a documentation patch in Julia Evans' ongoing series improving the `git-add` man page, now at version 2. The patch focuses on incorporating real user feedback to make the documentation more accessible while maintaining technical accuracy.

Julia shares insights from surveying 13 experienced Git users about the current pain points in the `git-add` man page. The key findings show persistent confusion around the term "index" (even among veteran users), overly complex sentence structures, and unclear phrasing about glob quoting. Users also requested clearer guidance on undoing `git add` operations.

The feedback reveals that while technical concepts like the index's snapshot behavior are understood by experienced users, the terminology itself remains a barrier. Julia notes that users consistently prefer "staging area" over "index" in documentation, though she maintains the need to keep both terms for accuracy. The patch appears well-grounded in real user experience data, suggesting thoughtful attention to actual documentation pain points rather than theoretical improvements.

This email demonstrates the series' methodical approach - gathering concrete feedback, identifying specific problematic phrases, and proposing changes based on actual user comprehension challenges. The inclusion of both quantitative data (7/13 users confused by "index") and qualitative comments strengthens the case for the proposed documentation changes.
