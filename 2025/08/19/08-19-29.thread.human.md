Patrick Steinhardt's packfile store refactoring series has been making steady architectural improvements to centralize packfile management. The latest patch (v6, 05/15) continues this work by moving the Most-Recently-Used (MRU) list of packfiles from `struct object_database` to the new `struct packfile_store`. This is a mechanical change that updates five call sites while maintaining the same optimization behavior - recently used packfiles will still be favored for object access, just from their new location.

The series has already seen significant progress, with 15 patches merged that established the foundational `struct packfile_store` and migrated core packfile management functionality. This latest MRU list migration follows the same careful pattern as earlier changes - preserving behavior while moving state to its new architectural home. The changes touch the expected files (odb.[ch], packfile.[ch], and midx.c) with clean, balanced diffs. 

Reviewers including Justin Tobler have previously raised questions about architectural boundaries, but all technical discussions appear resolved at this point. The series represents an important step toward enabling pluggable object database backends, with the MRU list migration being one of the final pieces needed to complete the packfile management centralization.
