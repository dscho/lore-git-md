This thread follows Patrick Steinhardt's ongoing refactoring of Git's packfile storage system (v4, 15 patches), part of the larger ODB abstraction effort. The series systematically reorganizes how Git manages packfiles, moving related functions and data structures into a dedicated `packfile_store` subsystem while maintaining all existing functionality.

The latest patch (13/15) simplifies the interface by removing the redundant `get_packed_git()` function in favor of `get_all_packs()`, which serves the same purpose but with slightly more complete initialization. This change affects several callers in gc.c, grep.c and object-name.c, continuing the series' trend of cleaning up the packfile API without altering behavior. Earlier patches have relocated key functions like `get_multi_pack_index()` to more logical homes and reorganized internal data structures.

Review feedback has been consistently positive, with only minor documentation nits remaining from earlier rounds. The series has benefited from input by Karthik Nayak on implementation details, Jeff King on design aspects like the MRU cache, and Taylor Blau on style matters. Junio C Hamano has been monitoring the changes as they progress toward merging. With all major architectural questions settled and no outstanding technical concerns, this well-structured series appears ready for integration in the near future.
