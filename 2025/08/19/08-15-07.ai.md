This is a response in the ongoing discussion about branch deletion behavior on case-insensitive filesystems, specifically addressing the reftable backend as a solution.

Patrick Steinhardt confirms that the reported issue (where Git incorrectly allows deletion of case-variant branch names on macOS) is an inherent limitation of the traditional "files" backend that cannot be fixed. He agrees with Junio Hamano's earlier suggestion that the reftable backend would avoid this problem entirely, since it doesn't use filesystem-based reference storage.

The email provides concrete instructions for using the reftable backend: creating new repositories with `git init --ref-format=reftable` or migrating existing ones with `git refs migrate --ref-format=reftable`. Steinhardt notes two important caveats: users need Git 2.45 or newer, and some third-party tools (like those using libgit2) may not yet support the reftable format despite a working implementation existing.

This response effectively moves the discussion from problem identification to solution implementation, though it doesn't address potential fixes for the files backend. The technical details about reftable migration commands and version requirements will be important for future discussion about adoption paths and compatibility concerns. The mention of libgit2 support suggests this may become a coordination point with other Git ecosystem projects.
