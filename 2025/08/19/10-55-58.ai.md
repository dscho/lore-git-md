This is a preparatory patch for the `git-history` command series, modifying sequencer internals to support history editing operations. Authored by Patrick Steinhardt, it introduces a new `restore_head_target` option in the sequencer to properly handle HEAD rewinding after cherry-pick-like operations.

The patch adds infrastructure needed for the upcoming `git-history` subcommands, specifically addressing how HEAD should behave after history modifications. Currently, the sequencer only rewinds HEAD after rebase operations, not cherry-picks. The new `restore_head_target` option allows saving and restoring the original branch reference when performing history edits that detach HEAD, similar to rebase behavior but without using the full rebase machinery.

Key technical changes include:
- New `restore_head_target` string field in `struct replay_opts`
- Configuration handling for the new option in `populate_opts_cb()`
- Persistence of the setting via `save_opts()`
- Implementation of HEAD reset logic in `pick_commits()` using `reset_head()`
- Proper cleanup in `replay_opts_release()`

The change is well-contained and focused, with clear motivation tied to the larger `git-history` effort. It follows established sequencer patterns for option handling and persistence. The implementation appears robust, using existing reset infrastructure (`reset_head()`) rather than reinventing wheel. This is a necessary building block for the more user-friendly history editing commands to come in the series.
