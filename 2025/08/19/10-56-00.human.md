Feature proposal introducing a new `git history` command for easier history rewriting, part of a larger series inspired by Jujutsu (jj) functionality.

This patch adds the initial scaffolding for a new `git history` command, which aims to provide more intuitive alternatives to common history editing operations that currently require interactive rebase. The command will eventually support subcommands like `drop`, `reorder`, and `split` to handle common use cases that are currently cumbersome with `git rebase -i`. The implementation builds on Git's existing sequencer infrastructure.

The patch itself is mostly boilerplate - it adds the new command to various build systems and includes a minimal implementation in `builtin/history.c` that just handles option parsing. The accompanying man page describes the intended purpose and notes current limitations (no merge commit support). This appears to be a well-structured initial commit in what looks to be a thoughtfully planned series, with clear documentation of both goals and limitations.

As part of a larger RFC series, this represents the first concrete step toward implementing Jujutsu-inspired history editing commands while leveraging Git's existing infrastructure. The preparatory work in earlier patches suggests careful consideration of the implementation approach.
