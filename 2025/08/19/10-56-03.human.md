This is a refactoring patch that splits header declarations between the interactive add and patch subsystems. It's part of Patrick Steinhardt's larger RFC series introducing a new `git-history` command, though this particular patch focuses on cleaning up existing code organization rather than adding new functionality.

The patch moves declarations related to the patch functionality from `add-interactive.h` into a new `add-patch.h` header. This includes the `add_p_opt` struct, its initialization macro, the `add_p_mode` enum, and the `run_add_p()` function declaration. The motivation is to better separate concerns between the interactive add and patch subsystems, making the code boundaries clearer and easier to navigate.

The changes are straightforward - declarations are moved verbatim to the new header, with `add-interactive.h` now including `add-patch.h` to maintain compatibility. The patch appears mechanically sound, with proper header guards and includes updated in both the header and implementation files. While this is a preparatory change for the larger series, it stands as a clean, focused improvement to the codebase organization on its own merits.
