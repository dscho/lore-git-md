This is part 8 of Patrick Steinhardt's ongoing refactoring series to move packfile management into a dedicated `packfile_store` structure as part of the object database abstraction effort. The patch refactors the `prepare_packed_git()` function and related helpers to operate on a `packfile_store` rather than a repository. Key changes include:

- Renames `prepare_packed_git()` to `packfile_store_prepare()` and updates all callers
- Moves the MRU (Most Recently Used) list preparation into `packfile_store_prepare_mru()`
- Combines the separate `rearrange_packed_git()` function into the main prepare function
- Updates all call sites that previously took a repository to now pass the packfile store
- Maintains the same initialization sequence and behavior while changing the storage location

The changes affect core packfile operations in packfile.c, updating functions like `get_packed_git()`, `get_multi_pack_index()`, and `find_pack_entry()` to use the new store-based interface. This continues the pattern seen in previous patches of moving packfile-specific state out of the generic ODB structure while preserving existing functionality.

The patch is purely mechanical - it doesn't introduce new behavior but helps clarify the separation between repository-wide operations and packfile-specific management. This groundwork supports the larger goal of making packfile implementation details pluggable in the ODB abstraction.
