This is a documentation patch clarifying remote repository usage for Git contributors. The patch updates `MyFirstContribution.adoc` to explicitly state that both `gitgitgadget/git` and `git/git` can be used as remotes when submitting PRs, though with different workflows. The original text only mentioned `gitgitgadget/git`, which could cause confusion for contributors who cloned from `git/git`.

The key changes are:
1. Explicitly stating both remote options in the PR creation instructions
2. Adding a note about needing to open PRs from forks when using `git/git` as base
3. Including a link to documentation explaining the differences between the two approaches

The patch maintains the existing documentation structure while adding this clarification. The commit message clearly explains the motivation (avoiding confusion) and the solution (documenting both options). This appears to be a straightforward, well-motivated documentation improvement that should help new contributors navigate the PR submission process more easily.
