This is part 10 of Patrick Steinhardt's RFC series introducing a new `git-history` command with `drop` and `reorder` subcommands. The patch adds infrastructure support for the history editing functionality.

The patch introduces `run_add_p_index()`, a new function that extends the existing `run_add_p()` infrastructure to support applying changes to an in-memory index rather than always operating on the repository's main index. This is a technical building block needed for the history editing operations, where the code needs to manipulate commits without immediately modifying the working tree or index.

The implementation:
- Adds new `index` and `index_file` fields to `struct add_p_state`
- Modifies index handling in several functions to use the specified index rather than always using `r->index`
- Introduces the new `run_add_p_index()` function with similar parameters to `run_add_p()` but accepting an explicit index
- Maintains all existing behavior when operating on the repository's main index
