Feature implementation for the new `git-history` command series. This is patch 11/11 in the RFC series, introducing the "split" subcommand to interactively break a commit into two parts.

The patch adds functionality to split a commit by interactively selecting which hunks should be moved to a new commit that becomes the parent of the original (now modified) commit. This automates what would otherwise be a multi-step rebase process. The implementation includes:

- Interactive hunk selection using the existing `add-patch` infrastructure
- Validation to prevent creating empty commits
- Support for root commits and path limiting via pathspecs
- Preservation of original authorship while allowing new commit messages
- Comprehensive test coverage (300+ lines) for various split scenarios

The command follows the pattern of the series' other subcommands by building on Git's sequencer infrastructure. Like the rest of the series, it currently doesn't support merge commits. The implementation looks thorough, with careful handling of edge cases and good test coverage, though as an RFC it may still need refinement based on list feedback.
