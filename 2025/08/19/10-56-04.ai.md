This is a refactoring patch in Patrick Steinhardt's RFC series introducing a new `git-history` command. The change focuses on cleaning up the interactive add/patch infrastructure that will be used by the new command.

The patch splits out a new `struct interactive_options` to hold configuration shared between `git add -i` and `git add -p`, moving it from the previous `struct add_p_opt`. This clarifies the separation between the two subsystems' configuration needs. The change introduces:

- A new `struct interactive_options` to hold common configuration like color settings, diff contexts, and single-key mode
- New `interactive_config_init()` and `interactive_config_clear()` functions to manage this state
- Updates to all callers (add, checkout, commit, reset, stash) to use the new structure

The refactoring is part of the larger effort to build `git-history` on top of Git's existing interactive infrastructure. While this patch doesn't yet fully detangle the subsystems (as noted in the commit message), it makes progress toward that goal. The changes are mechanical but touch many files, updating them to use the new configuration structure.
