This is part 9 of Patrick Steinhardt's ongoing refactoring series to move packfile management into a dedicated `packfile_store` structure as part of the object database (ODB) abstraction effort.

The patch focuses on `reprepare_packed_git()`, which previously handled three distinct responsibilities: reloading alternates, clearing loose object caches, and repreparing packfiles. The change splits these into separate concerns - the new `odb_reprepare()` function in odb.c now handles the first two (alternates and loose caches), while the renamed `packfile_store_reprepare()` focuses solely on packfile management. This better aligns with the series' goal of separating packfile-specific logic from general ODB operations.

The change affects 13 files across the codebase, updating all existing callers of `reprepare_packed_git()` to use the new `odb_reprepare()` interface instead. The packfile-specific functionality is now properly scoped to the packfile store structure, with `packfile_store_reprepare()` being called internally by `odb_reprepare()` when needed. This maintains the same behavior while better organizing the code for future pluggable ODB backends.

Key technical changes include:
- New `odb_reprepare()` function in odb.h/c consolidating alternate and loose cache management
- Renamed `packfile_store_reprepare()` with narrower responsibility for packfiles only
- Updates to call sites throughout the codebase to use the new interface
- Documentation updates reflecting the split responsibilities

The change is mechanical but important for the architectural goal of separating packfile concerns from the broader ODB interface. It follows the pattern seen in earlier patches of moving packfile-specific state and operations into the dedicated store structure.
