This is the fourth patch in an RFC series introducing a new `git history` command, building on three preparatory patches that modified sequencer internals and cache-tree handling. The patch establishes the basic scaffolding for the new command.

The `git history` command is proposed as a more intuitive alternative to interactive rebase for common history editing operations like reordering, splitting, and dropping commits. The implementation will use Git's existing sequencer infrastructure but provide imperative subcommands inspired by Jujutsu (jj)'s workflow. This initial patch adds the command skeleton without implementing any functionality - it just sets up the build system integration, empty implementation in builtin/history.c, and basic documentation.

Key technical details:
- New builtin/history.c with empty cmd_history() function
- Documentation/git-history.adoc with high-level description and limitations (no merge commit support yet)
- Build system updates in Makefile, meson.build, and Documentation/meson.build
- .gitignore entry for the new binary
- Basic command registration in git.c with RUN_SETUP flag

The documentation notes this is similar to git-rebase but focused on specific commit modifications rather than range operations, and explicitly states the current limitation around merge commits. The implementation will be filled in by subsequent patches in the series (which introduce drop, reorder, and split subcommands).

This is purely infrastructure patch - the actual functionality comes later. The changes are straightforward plumbing to add a new command, with no behavior yet to evaluate. The documentation suggests the command will target the same use cases as Jujutsu's jj-abandon, jj-new, and jj-split commands but built on Git's sequencer.
