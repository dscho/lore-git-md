This is a refactoring patch in Patrick Steinhardt's RFC series introducing a new `git-history` command. It focuses on cleaning up the code organization around interactive add operations.

The patch splits out a new `struct interactive_options` to hold configuration settings that are shared between `git add -i` and `git add -p`. Previously these were passed via `struct add_p_opt` which was confusing circular dependencies - options meant for the interactive mode were being passed through the patch-specific interface.

Key changes:
- Introduces `struct interactive_options` to hold common settings like color config, diff context, etc.
- Creates `struct interactive_config` to manage the runtime state
- Moves color initialization and config parsing into new helper functions
- Updates all callers to use the new interfaces

The changes are mechanical and don't modify behavior, just reorganize the code to be clearer about which options apply to which components. The patch is part of a larger effort to build new history editing commands while reusing existing interactive infrastructure.

This appears to be a well-scoped preparatory change that makes the codebase more maintainable. The patch touches many files but the changes are straightforward and consistent. It builds on earlier work in the series that split out `add-patch.h` from `add-interactive.h`.
