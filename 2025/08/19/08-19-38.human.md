This is part 9 of Patrick Steinhardt's ongoing series to refactor Git's packfile subsystem as part of the object database (ODB) abstraction effort. The patch focuses on cleaning up responsibilities around packfile reloading.

The change splits the multi-purpose `reprepare_packed_git()` function into two more focused operations: a new `odb_reprepare()` that handles general ODB maintenance (reloading alternates, clearing caches), and `packfile_store_reprepare()` that specifically handles packfile reloading. This better aligns with the series' goal of separating packfile management from the broader ODB infrastructure.

The patch updates 13 call sites across various commands (`gc`, `repack`, `fetch-pack`, etc.) to use the new `odb_reprepare()` function instead. The changes are mechanical but wide-ranging, touching core operations that need to refresh the object database state. The commit message clearly explains the motivation - the original function was doing too much in packfile.c that properly belonged to the ODB layer.

This continues the series' pattern of carefully separating packfile-specific state from generic ODB functionality while maintaining identical behavior. The changes appear well-contained and follow the established pattern of previous patches in the series.
