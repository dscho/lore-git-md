Reftable fsck validation series (v3, now 9 patches) - comprehensive stack integrity checks for reftable backend. Authored by Karthik Nayak, this series implements layered validation (Stack->Table->Block->Ref) while maintaining separation between Git's fsck and reftable internals. Key architectural elements include new files `reftable/fsck.[ch]` implementing validation logic with reftable-specific error codes mapped to fsck messages.

The series begins with preparatory cleanups (removing unused headers from refs files) and refactors fsck messaging to standardize "Checking references consistency" output across backends. Significant changes from v2 to v3 include:
- Moving certain checks (trailing newlines in 'tables.list', sequential update indices) from fsck to runtime validation per Junio Hamano's feedback
- Making table name validation non-fatal
- Modularizing fsck code while maintaining validation layers
- Adding comprehensive filesystem consistency checks in the final patch

Core technical components:
1. Runtime validation in `reftable_stack_reload_once()` for sequential update indices (patch 4/8)
2. New fsck_msg_type entries `badReftableTableName` (WARN) and `badReftableFiletype` (ERROR)
3. Error mapping infrastructure via `fsck_msg_id_map[]` in `refs/reftable-backend.c`
4. Comprehensive test coverage in `t0614-reftable-fsck.sh` for:
   - Malformed table name patterns
   - Invalid directory entries
   - Warning vs error classification behavior
5. Documentation updates in `fsck-msgids.adoc` (including removal of `gitmodulesLarge` duplicate)

The latest patch specifically refactors trailing newline validation in 'tables.list' files:
- Modifies `parse_names()` in reftable/basics.h to return errors via an `err` parameter rather than silently failing
- Updates callers like `fd_read_lines()` to handle the new error reporting
- Adds explicit unit tests for missing newline cases that should return `REFTABLE_FORMAT_ERROR`
- Maintains existing behavior of dropping empty strings while adding proper error checking
- Includes a minor whitespace fix (extra space after `==` in tests) noted by Junio
- Moves this validation from fsck to runtime checks while maintaining proper error reporting

Implementation handles platform-specific cases (Windows behaviors, concurrency) while preserving reftable-as-library boundaries. The series demonstrates responsiveness to feedback through:
- Structural changes moving validation layers
- Commit splitting for better reviewability
- Focused bugfixes addressing specific format validation gaps
- Incorporation of suggestions from Patrick Steinhardt and Shejialuo
- Specific implementation of Junio Hamano's feedback on trailing newline validation

Open considerations remain around:
- Translation of reftable library strings
- Message unification (generic vs backend-specific phrasing)
- Concurrency edge cases in validation

The series represents significant progress in reftable backend maturity, adding robust validation while maintaining the architectural separation that makes reftable suitable as a standalone library. Changes touch core reftable files, fsck infrastructure, documentation, and test coverage, with each validation layer carefully designed to catch specific classes of corruption while providing actionable error messages.
