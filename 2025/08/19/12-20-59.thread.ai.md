Reftable fsck validation series (v4, 7 patches) - refined stack integrity checks for reftable backend. Authored by Karthik Nayak, this iteration completes the integration of validation while maintaining core design principles. The series introduces `reftable/fsck.[ch]` with reftable-specific error codes mapped to fsck messages, culminating in patch 7/7's fsck integration in `refs/reftable-backend.c`.

Key structural changes from v3 to v4 include removal of redundant update index validation, narrowed table name validation scope, and non-fatal naming convention warnings. The series establishes:
1. `reftable_fsck_check()` API for callback-based validation (patch 6/7)
2. `reftable_be_fsck()` integration with Git's fsck infrastructure (patch 7/7)
3. `badReftableTableName` warning ID and documentation
4. Strict table name pattern enforcement (hex-hex-hex.ref format)

Technical refinements in v4:
1. `parse_names()` in basics.c enforces trailing newline requirement in 'tables.list' (patch 3/7)
2. Callback architecture via `reftable_fsck_info` struct (patch 6/7)
3. Comprehensive test coverage in `t0614-reftable-fsck.sh` expanded with name validation cases (patch 7/7)
4. Documentation updates in `fsck-msgids.adoc` maintained throughout
5. Lexicographical ordering preserved in all file modifications

The evolution reflects substantial feedback integration:
- Patrick Steinhardt's race condition concerns addressed by eliminating directory scans
- Junio Hamano's validation scope feedback fully realized
- Callback architecture enables future checks while maintaining separation from Git's fsck
- Table name validation now includes strict format enforcement (patch 6/7) with warning-level reporting (patch 7/7)

Implementation details:
- Core changes span reftable/basics.c, stack.c, fsck.[ch], reftable-backend.c, and test suite
- Error handling unified across parsing functions with new callback pattern
- Test cases verify both strict format requirements and graceful handling
- Makefile/Meson build system updates maintain file ordering
