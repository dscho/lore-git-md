Reftable fsck validation series (v3, 9 patches) - comprehensive stack integrity checks for reftable backend. Authored by Karthik Nayak, this series implements layered validation (Stack->Table->Block->Ref) while maintaining separation between Git's fsck and reftable internals. Key architectural elements include new files `reftable/fsck.[ch]` implementing validation logic with reftable-specific error codes mapped to fsck messages.

The series begins with preparatory cleanups and refactors fsck messaging to standardize output across backends. Significant changes from v2 to v3 include moving certain checks (trailing newlines in 'tables.list', sequential update indices) from fsck to runtime validation per Junio Hamano's feedback, making table name validation non-fatal, and modularizing fsck code while maintaining validation layers.

Core technical components:
1. Runtime validation in `reftable_stack_reload_once()` for sequential update indices (patch 4/8)
2. New fsck_msg_type entries and error mapping infrastructure
3. Comprehensive test coverage in `t0614-reftable-fsck.sh`
4. Documentation updates in `fsck-msgids.adoc`

Patrick Steinhardt has provided extensive technical review throughout:

- In patch 7/8 (table name validation), identified implementation issues around error handling, string comparisons, race conditions with lock/temp files, code structure, and style
- In the latest review of patch 8/8, noted platform-specific concerns with enum range checking in error handling code and validated the BUG check for message ID mappings
- Previous feedback on patch 3/8 included suggestions for conventional error reporting patterns and safer string operations
