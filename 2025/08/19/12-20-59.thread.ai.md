Reftable fsck validation series (v1) - initial validation infrastructure and tables.list checks. Authored by Karthik Nayak, this 5-patch series introduces fsck validation for the reftable backend while maintaining separation between Git's fsck implementation and reftable internals. The first patch [PATCH 1/5] alphabetizes the `fsck_msg_type` enum in `fsck.h` and fixes a duplicate `gitmodulesLarge` entry in `Documentation/fsck-msgids.adoc`, performing purely mechanical reorganization without functional changes. The core architectural approach creates a new `reftable/fsck.[ch]` module that implements validation using reftable internals, then maps these to standard Git fsck errors via glue code in `refs/reftable-backend.c`. The current series focuses on validating the `tables.list` file with four specific checks: proper table naming per reftable spec, consistent table count, trailing newline requirement, and correct index sequencing. Changes touch fsck infrastructure (including the alphabetized message types) and add new reftable-specific fsck headers. Comprehensive tests are added in `t/t0614-reftable-fsck.sh`. The author notes plans for follow-up series to implement deeper validation at table and block levels. This work is part of the ongoing reftable backend effort primarily driven by Patrick Steinhardt and Karthik Nayak.
