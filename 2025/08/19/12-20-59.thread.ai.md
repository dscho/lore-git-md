Reftable fsck validation series (v3, 9 patches) - comprehensive stack integrity checks for reftable backend. Authored by Karthik Nayak, this series implements layered validation (Stack->Table->Block->Ref) while maintaining separation between Git's fsck and reftable internals. Key architectural elements include new files `reftable/fsck.[ch]` implementing validation logic with reftable-specific error codes mapped to fsck messages.

The series begins with preparatory cleanups and refactors fsck messaging to standardize output across backends. Significant changes from v2 to v3 include moving certain validations (trailing newlines in 'tables.list', sequential update indices) from fsck to runtime validation per Junio Hamano's feedback, making table name validation non-fatal, and modularizing fsck code while maintaining validation layers. The latest discussion confirms "strictly monotonically increasing" as the mathematically precise description for update index validation in patch 4/8, resolving earlier terminology discussions between Karthik Nayak ("ascending order"), Junio Hamano ("monotonically increasing"), and Patrick Steinhardt's final formulation.

Core technical components:
1. Runtime validation in `reftable_stack_reload_once()` for update indices (strictly monotonically increasing)
2. New fsck_msg_type entries and error mapping infrastructure
3. Comprehensive test coverage in `t0614-reftable-fsck.sh`
4. Documentation updates in `fsck-msgids.adoc`

Patch 7/8's table name validation has been simplified after Patrick Steinhardt identified race condition risks with directory scanning. The consensus now is that unknown files in the reftable directory don't affect repository integrity, so validation focuses only on known tables from the stack. This resolves the earlier open question about validation scope (all files vs known tables) while avoiding race conditions with temporary/lock files. Karthik's implementation strengthened `strtoull()` error handling, simplified string comparisons, and properly handles `.log` suffix files.

Patch 8/8 addresses error handling in fsck validation, with Karthik responding to Patrick's platform-specific enum handling concerns by proposing to typecast `info->error` to `int`. The BUG check for missing fsck message ID mappings remains valid.
