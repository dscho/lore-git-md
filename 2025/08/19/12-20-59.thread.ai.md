Reftable fsck validation series (v5) - completing stack integrity checks. Authored by Karthik Nayak, this 5-patch series adds comprehensive fsck validation for basic reftable stack integrity while maintaining clear separation between Git's fsck implementation and reftable internals. The first patch [PATCH 1/5] alphabetized the `fsck_msg_type` enum in `fsck.h` and fixed a duplicate `gitmodulesLarge` entry in `Documentation/fsck-msgids.adoc`. The second patch [PATCH 2/5] implemented table name validation in `tables.list` through a new `reftable/fsck.[ch]` module, introducing the `reftable_fsck_info` struct for error reporting and adding `badReftableTableName` message ID. The third patch [PATCH 3/5] added stack count validation, checking consistency between the number of tables listed in `tables.list` and actual files in the reftable directory via `reftable_fsck_valid_stack_count()`, with mismatches reported as `badReftableStackCount`. The fourth patch [PATCH 4/5] introduced validation for a trailing newline in `tables.list` files through `reftable_fsck_stack_contains_newline()`, adding error type `REFTABLE_FSCK_ERROR_STACK_LIST_MISSING_NEWLINE` and fsck message ID `badReftableStackListNewline`. The new fifth patch [PATCH 5/5] completes the series by adding sequential update index validation, ensuring tables listed in `tables.list` have properly sequential update indices through new error type `REFTABLE_FSCK_ERROR_UPDATE_INDEX` and fsck message ID `badReftableUpdateIndex`. Test coverage in `t0614-reftable-fsck.sh` verifies all checks, including new cases for index validation by manually modifying table names to create non-sequential indices. The implementation maintains the series' architectural separation between components, with fsck infrastructure changes, reftable validation (covering table names, stack counts, file formatting, and index sequencing), and comprehensive test coverage. The commit notes this completes the current focus on stack integrity checks while leaving deeper table and block level validation for future work in the ongoing reftable backend effort primarily driven by Patrick Steinhardt and Karthik Nayak.
