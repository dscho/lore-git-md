This is a follow-up in the thread about Jenkins' continued use of the deprecated `git whatchanged` command. Junio Hamano acknowledges Mark Waite's notification that the Jenkins Git client plugin still relies on this command for changelog generation, as required by Git's deprecation policy.

Hamano clarifies that the `--i-still-use-this` flag is only a temporary workaround, emphasizing that `git whatchanged` will be completely removed in Git 3.0 (though no release date is set yet). He suggests using `git log --raw` with appropriate options as the long-term replacement, while noting the removal could theoretically be reconsidered if there's overwhelming feedback about the command being indispensable.

The exchange serves as both documentation of a major CI system's dependency on deprecated functionality and a reminder that the deprecation timeline remains firm unless significant new evidence emerges. The tone is professional and appreciative while being clear about Git's future direction.
