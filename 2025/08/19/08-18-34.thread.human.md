This thread documents the completion of Meson build system support for Git's GUI components (gitk and git-gui) through Patrick Steinhardt's three-patch series. The technical work has progressed through two phases: first relocating the components to a `subprojects/` directory (patches 1-2), then implementing Meson build rules (patch 3). Karthik Nayak reviewed the series positively, suggesting only minor optimizations to dependency checking logic.

The discussion has now reached a key decision point with Junio Hamano's response. While acknowledging the technical completion of Meson support and agreeing to remove its "experimental" status after documentation updates, Junio raises architectural concerns about the approach. He questions whether Git's source tree organization should adapt to Meson's requirements by moving components into a `subprojects/` directory, contrasting this with Git's current build system which handles these components in-place. This introduces a philosophical dimension to the discussion about whether build tools should conform to a project's structure or vice versa.

The series represents a significant milestone in Git's build system modernization, with all technical aspects now implemented and reviewed. Junio's feedback suggests the final decision may hinge on broader considerations of source tree organization principles rather than the implementation details, which have already been vetted through Nayak's thorough reviews. Documentation updates remain as follow-up work before Meson can be considered fully supported.
