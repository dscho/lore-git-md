This thread documents the ongoing effort by Patrick Steinhardt to integrate Git's GUI components (gitk and git-gui) with the Meson build system. The discussion has progressed through several iterations, with v2 of the patch series settling on a symlink-based approach that preserves the original source layout while meeting Meson's requirements. 

Karthik Nayak reviewed the technical implementation, confirming it matches the Makefile's behavior for conditional builds (git-gui requires both tclsh and wish, while gitk only needs wish) and successfully preserves the source layout through symlinks. The architectural approach was further validated when Patrick explained Meson's subproject_dir parameter limitations, making the symlink solution necessary.

The final major concern came from Junio Hamano, who questioned Windows symlink reliability - a historically problematic area. Patrick's response clarifies that while modern Windows supports symlinks in Developer Mode, behavior varies across environments (native, Cygwin, MSYS2). The solution should work in common development environments like Cygwin/MSYS2, though comprehensive Windows testing remains outstanding.

With core technical questions resolved and the symlink approach validated for most use cases, the series appears ready pending final verification of Windows behavior. Ramsay Jones noted a few remaining minor issues around libexecdir path adjustments and shell quoting, but these seem like straightforward fixes. The documentation updates regarding gitk's maintenance (now handled by Johannes Sixt) have already been merged separately.

This represents the culmination of careful architectural discussion, with the symlink approach emerging as the consensus solution that balances Meson's requirements with Git's source layout needs.
