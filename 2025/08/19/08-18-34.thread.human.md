This thread continues the discussion about integrating Git's components (gitk and git-gui) with the Meson build system, focusing on architectural questions around source code organization. Patrick Steinhardt has led the effort, with Karthik Nayak providing review and Junio Hamano raising important structural concerns.

The core debate centers on whether Git should adapt its source structure to Meson's requirements or vice versa. Steinhardt's current approach moves gitk and git-gui into a `subprojects/` directory to satisfy Meson's `subproject()` requirements, which enables standalone builds but requires this directory restructuring. He argues this is a worthwhile tradeoff that also helps clean up Git's top-level directory. Junio maintains that build systems should adapt to Git's organization rather than the other way around, and this fundamental question remains unresolved.

Technically, the series is nearly complete, with the relocation and Meson integration working. However, Ramsay Jones has identified several practical issues that need resolution before Meson can be considered fully supported, including libexecdir path handling and shell quoting problems. Documentation updates clarifying gitk's maintenance (now handled by Johannes Sixt) and properly crediting original author Paul Mackerras have already been merged.

The discussion remains open-ended, as Steinhardt hints at broader source reorganization possibilities while Junio continues to understand whether the current approach represents an acceptable long-term direction for the project. While the technical implementation is largely settled, the architectural implications and remaining practical issues mean this transition isn't yet complete.
