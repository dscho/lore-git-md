This is a technical discussion about hash algorithm interoperability in Git submodules, specifically addressing a bugfix for shallow clones when superprojects and submodules use different hash algorithms (SHA-1 vs SHA-256).

Brian M. Carlson responds to Michael Schroeder's earlier defense of the current behavior where mixed hash algorithms work in practice for non-shallow clones. Carlson strongly disagrees with this approach, arguing it will break future interoperability work and could lead to data corruption. He cites Git's long-standing design principle that repositories must use a single consistent hash algorithm for all objects.

The key contention point is whether to support mixed hash algorithms pragmatically (Schroeder's position) or enforce strict same-algorithm requirements (Carlson's position). Carlson reveals he's actively working on interoperability code for shallow clones and submodules, suggesting this discussion may soon become moot when his more comprehensive solution lands.

This email escalates the architectural debate beyond the immediate shallow clone fix, highlighting fundamental incompatibilities in the mixed-hash approach, particularly around tree objects and future protocol conversions. Carlson's response carries significant weight given his deep involvement in Git's hash transition work.
