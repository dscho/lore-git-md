This is the final patch in a series of bugfixes for `builtin/describe.c`, addressing a theoretical NULL dereference that could occur in `describe_commit()`. The patch simplifies the interface by having callers pass a `struct commit` directly rather than an object ID that needs to be re-looked-up.

Patrick Steinhardt raised a question about potential edge cases with commit-graphs where commits might be found in the graph but not the ODB, but Jeff King explains this isn't actually a concern due to how `parse_object()` works with already-parsed commits. Even if there were an issue, this refactoring would incidentally fix it by removing the redundant lookup.

The patch has already been approved as part of the series, which has now reached consensus on all technical points. This completes the hardening of `describe`'s edge case handling while cleaning up internal interfaces. The only remaining considerations are some potential follow-ups around HEAD validation and commit-graph behavior that were noted earlier in the thread.
