This thread clarifies documentation around Git contribution workflows, specifically which GitHub remotes contributors should use when submitting pull requests. The original patch by Daniele Sassoli updated `MyFirstContribution.adoc` to explicitly state that both `gitgitgadget/git` and `git/git` can serve as remotes, though with different workflows. This addressed potential confusion for contributors who cloned from `git/git` rather than `gitgitgadget/git`.

Maintainer Junio Hamano has now responded, questioning whether the documentation should remain neutral or actively guide users toward the more capable `gitgitgadget/git` workflow. He suggests adding specific instructions for switching a fork's remote from `git/git` to `gitgitgadget/git`, including example `git remote` commands, though notes this would need validation. The discussion remains open on whether to present both options equally or recommend one workflow over the other, with the technical focus staying on GitHub remote configuration for new contributors.
