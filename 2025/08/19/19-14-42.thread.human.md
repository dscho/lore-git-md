This thread discusses how to best document GitHub remote repository configuration for new Git contributors. The original patch from Daniele Sassoli updated the "My First Contribution" guide to neutrally describe both `git/git` and `gitgitgadget/git` as possible remotes, noting their different workflows. Junio Hamano suggested going further by actively guiding users toward the more capable `gitgitgadget/git` workflow, including potential instructions for switching remotes.

In the latest response, Daniele pushes back on this approach, pointing out that the document currently directs new contributors to clone from `git/git` initially. They argue that the disadvantages of this approach are minor for first-time contributors and that suddenly introducing remote-switching instructions later in the document might create more confusion than it solves. Daniele suggests that if the project wants to standardize on `gitgitgadget/git`, the entire document should be restructured to use it from the beginning rather than adding piecemeal changes.

The discussion now centers on a documentation philosophy question: should the guide remain neutral about remote choices (current approach) or actively recommend one workflow (Junio's suggestion)? Daniele's position favors maintaining consistency unless making a more comprehensive restructuring, while Junio appears to prefer steering contributors toward what he sees as the better workflow. The next steps will likely involve either implementing Junio's suggestion with remote-switching instructions or discussing whether to rewrite the entire document's flow around `gitgitgadget/git`.
