This is the third patch in a 5-part series adding fsck validation for the reftable backend, focusing on checking the consistency between the number of tables listed in `tables.list` and the actual files present in the reftable directory.

The patch introduces a new validation check that counts the regular files in the reftable directory (excluding `tables.list` itself and compares this count against the number of tables listed in `tables.list`. A mismatch is reported as a new `badReftableStackCount` error through Git's fsck system. The implementation includes:

1. A new `REFTABLE_FSCK_ERROR_STACK_COUNT` error type in `reftable-fsck.h`
2. The core validation logic in `reftable_fsck_valid_stack_count()` which uses `opendir/readdir` to count files
3. Glue code in `refs/reftable-backend.c` to map the reftable error to Git's fsck message ID
4. Documentation updates for the new `badReftableStackCount` message
5. A new test case in `t0614-reftable-fsck.sh` that verifies the check by creating an extra table file

The validation follows the same pattern established in previous patches of the series, maintaining separation between reftable internals and Git's fsck system while providing comprehensive test coverage. The error reporting uses the same `reftable_fsck_info` struct mechanism seen in patch 2/5.

This continues the series' incremental approach to reftable validation, with each patch adding a specific check while keeping the architecture clean. The implementation appears thorough with proper error handling and test coverage, following the style established in earlier patches.
