This is the fifth patch in Patrick Steinhardt's RFC series introducing a new `git-history` command, implementing the first concrete subcommand `drop`. The patch builds on the preparatory infrastructure from earlier patches to provide a simplified interface for removing commits from history.

The `drop` subcommand automates what would otherwise require an interactive rebase, handling both regular commits and edge cases like root commits. Key implementation details include:

- New helper functions `collect_commits()` and `apply_commits()` that handle the commit selection and rebase operations
- Special handling for root commits (creating a new empty root when needed)
- Integration with the sequencer infrastructure via `sequencer_pick_revisions()`
- Use of `reset_head()` for branch reference updates
- Comprehensive test coverage in t/t3450-history-drop.sh verifying:
  - Merge commit rejection
  - Empty history prevention
  - Tip commit dropping
  - Mid-history commit removal
  - Root commit handling
  - Commit ordering preservation

The implementation currently has several limitations noted in the code:
- No support for merge commits in the rewritten history
- Only single commits can be dropped (no ranges yet)
- Conflict handling falls back to basic cherry-pick behavior

The patch adds 297 lines to builtin/history.c and 127 lines of tests, demonstrating thorough coverage of the new functionality. The implementation builds on the sequencer modifications from earlier patches in the series, particularly the new `skip_commit_summary` and `restore_head_target` fields in `struct replay_opts`.
