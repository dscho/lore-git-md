This is a preparatory patch for the proposed `git-history` command series, focusing on sequencer internals. Patrick Steinhardt introduces a new `skip_commit_summary` option to suppress the verbose commit output that normally appears during operations like cherry-pick. The change is motivated by the upcoming `git-history` command where this output would be undesirable.

The patch adds the new flag to `struct replay_opts` and ensures it persists across sequencer operations by saving it in the sequencer configuration. The implementation is straightforward, touching only the sequencer internals while maintaining backward compatibility. This appears to be a well-scoped change that cleanly extends the existing infrastructure without introducing any obvious complexity.

As the first patch in an 11-part series proposing a new `git-history` command inspired by Jujutsu's workflow, this sets the stage for more substantial changes to come. The clean separation of concerns suggests thoughtful planning for the larger feature.
