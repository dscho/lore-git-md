This is part 12 of Patrick Steinhardt's ongoing refactoring series to move packfile management into a dedicated `packfile_store` structure as part of the object database abstraction effort.

The patch introduces a new helper function `packfile_store_load_pack()` that combines the common pattern of checking if a packfile exists in the store and, if not, loading and adding it. This replaces several instances of manual packfile lookup and insertion that were previously duplicated across fast-import.c, index-pack.c, midx.c, and packfile.c. The new function handles the key reconstruction (converting .idx paths to .pack paths for the hashmap lookup) and takes care of the full load-and-add sequence.

Key technical details:
- The function signature takes a packfile store, index path, and local flag
- Internally it converts .idx and .pack paths for hashmap lookup
- Returns either the existing packfile or newly loaded one (or NULL on failure)
- Updates callers in fast-import, index-pack, midx, and packfile.c to use the new helper
- Maintains the same behavior while reducing code duplication

This continues the series' pattern of moving packfile-specific operations into the store abstraction while simplifying calling code. The change is mechanical but touches several components that interact with packfiles, making their behavior more consistent.
