This is a follow-up in the bug report thread about branch deletion behavior on case-insensitive filesystems. Patrick Steinhardt confirms that the issue is an inherent limitation of Git's traditional "files" backend and cannot be fixed directly. He agrees with Junio Hamano's earlier suggestion that the reftable backend would avoid this problem entirely since it doesn't store references as individual files.

Steinhardt provides practical instructions for using the reftable backend: creating new repositories with `git init --ref-format=reftable` or migrating existing ones with `git refs migrate --ref-format=reftable`. He notes this requires Git 2.45 or newer and cautions about potential compatibility issues with other tools like libgit2, though a working backend exists there too.

The response effectively closes the technical discussion by confirming the filesystem backend's limitations and promoting reftable as the solution. This moves the conversation toward adoption considerations rather than further debugging of the current behavior. The tone is matter-of-fact, acknowledging the issue while providing clear migration paths for affected users.
