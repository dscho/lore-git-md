This is the final patch in a 4-part series fixing dangling symref handling in `git fetch` with `followRemoteHEAD=create`. The core issue is that fetch would incorrectly overwrite explicitly created remote HEAD symrefs when they pointed to non-existent refs, despite being configured to only set HEAD if missing.

The patch modifies both the files and reftable ref backends to detect and preserve dangling symrefs during no-dereference operations. When a symref points to a non-existent ref, it currently returns the null oid - this patch makes such cases fail the "create" operation rather than silently overwriting the symref. The change affects `git update-ref --no-deref` and `git fetch`'s remote HEAD handling.

Key technical details:
- Adds `referent` parameter to `check_old_oid()` to track symref targets
- Detects dangling symrefs by checking for null oid + non-empty referent + REF_NO_DEREF flag
- Returns REF_TRANSACTION_ERROR_CREATE_EXISTS in this case
- Includes test cases in t1400-update-ref.sh and t5510-fetch.sh
- Handles both files and reftable backends separately (with minor message translation differences)
- Does not address related gaps in symref-delete operations

The patch builds on the test modernization from earlier in the series and depends on ps/reflog-migrate-fixes for proper old-oid checking. The implementation is clean and well-tested, with clear commit message explaining both the problem and solution. This completes the series' goal of fixing the dangling symref behavior while maintaining backward compatibility.
