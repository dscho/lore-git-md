Refactoring patch in the ongoing packfile store series. This is patch 7/16 in Patrick Steinhardt's series to move packfile management into a dedicated `packfile_store` structure as part of the object database abstraction work.

The patch performs a simple code reorganization in packfile.c to eliminate a forward declaration of `prepare_packed_git()` by reordering functions. The main change moves the `repo_approximate_object_count()` function definition after `get_packed_git_mru()` so it can see the `prepare_packed_git()` definition naturally rather than needing a forward declaration.

This is a straightforward mechanical change that doesn't affect behavior - it's purely about code organization. The patch follows the same careful approach seen in earlier parts of the series, maintaining all existing functionality while cleaning up the code structure. The change is small (67 lines modified) and focused, typical of the incremental steps in this refactoring effort.

As with previous patches in the series, this continues the pattern of moving packfile-related code into better positions to support the eventual goal of pluggable ODB backends, though this particular patch is more about code hygiene than the broader architectural changes.
