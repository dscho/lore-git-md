This is the fifth and final patch in Karthik Nayak's reftable fsck validation series, adding a check for sequential update indices in reftable files. The patch introduces validation to ensure tables listed in `tables.list` have properly sequential update indices, which is a requirement for correct reftable operation.

The implementation adds a new error type `REFTABLE_FSCK_ERROR_UPDATE_INDEX` and corresponding fsck message ID `badReftableUpdateIndex`. The check compares each table's index range against the previous table's maximum index, ensuring they form a continuous sequence. The patch maintains the series' architectural separation between reftable internals and fsck infrastructure.

Two new test cases in `t0614-reftable-fsck.sh` verify the check by manually modifying table names to create non-sequential indices, both between tables and within a single table's index range. The tests confirm the fsck check catches these violations with appropriate error messages.

The commit notes this is just the first step in update index validation - future work will need to ensure the index in the table name matches the index in the table's header and contents. This patch completes the current series' focus on basic stack integrity checks while leaving deeper table-level checks for future work.
