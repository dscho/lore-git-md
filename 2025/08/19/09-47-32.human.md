This is a review comment on the first patch of Patrick Steinhardt's 16-part refactoring series to centralize packfile management in Git's object database abstraction.

Karthik Nayak points out a minor documentation issue in the odb.h changes from patch 1/16, noting that the comment about "should only be accessed directly by packfile.c" currently appears to apply only to the newly added `packfiles` field when it should also cover the existing `packed_git` field. The spacing makes this relationship unclear.

The comment is purely about code organization and documentation clarity - it doesn't affect functionality. This is a small but valid observation about making the header file intentions clearer as part of this larger refactoring effort to move packfile management into the new `struct packfile_store`.

The patch itself (which Karthik is commenting on) is the foundational change in the series, introducing the empty `packfile_store` structure that subsequent patches will populate with packfile-related state currently scattered across other structures.
