Refactoring patch in the `git-history` RFC series, focusing on the `add-patch` subsystem's dependency cleanup.

This patch continues the refactoring work from patch 8/11 by fully removing `add-patch.c`'s dependency on the `add-interactive` subsystem. The key change is replacing the embedded `add_i_state` struct with direct storage of the repository pointer and interactive configuration (`struct interactive_config`) that was split out in the previous patch. The patch updates all references from `s->s.cfg.*` to `s->cfg.*` and removes the `add-interactive.h` include.

The changeset is mechanical but wide-ranging, touching nearly all parts of the interactive patch application flow - from diff parsing and hunk rendering to user prompts and color handling. All interactive configuration (colors, context settings, diff algorithm) is now managed through the new `interactive_config` helpers rather than the old `add_i_state` path. The patch maintains all existing functionality while cleaning up the architectural layering.

This is part of a larger effort to modularize Git's interactive components, with potential implications for other commands using `add-patch` functionality (add, checkout, commit, reset, stash). The changes appear thorough and consistent, with no obvious functionality regressions in the diff. The patch follows logically from the preparatory work in patch 8/11 and helps further separate concerns between the interactive patch application machinery and its configuration.
