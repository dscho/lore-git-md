Thread identity: RFC proposal for `git-history` command with twelve-patch v5 series (including `reword` and `split` subcommands), authored by Patrick Steinhardt. Series builds on Git's sequencer while drawing inspiration from Jujutsu's history editing capabilities, now focused on non-conflicting operations after Git Contributor's Summit discussions.

Core problem/goal: Implement flexible history editing operations (`reword` and `split` subcommands) with supporting infrastructure refactoring (interactive add/patch, cache-tree modifications, and wt-status tree-to-tree diff capabilities) to enable in-memory index operations. Current implementation avoids `drop` and management commands based on community feedback.

Current status: v5 series now complete with addition of `split` subcommand implementation, rebased onto latest `seen` branch with sa/replay-atomic-ref-updates. Series incorporates all technical review feedback from previous iterations, with infrastructure improvements progressing alongside both `reword` (patch 6/12) and now `split` (new patch) functionality. Multiple patches continue progress on `the_repository` removal in replay infrastructure.

Key technical details:
- New `builtin/history.c` implementing both subcommands:
  - `cmd_history_reword()` handling commit ancestry checks and message editing
  - New `cmd_history_split()` implementing interactive commit splitting
- `split_commit()` helper handles core split logic with temporary index manipulation
- Uses existing `run_add_p_index()` from earlier patches for hunk selection
- Validates split commits aren't empty by comparing tree OIDs
- Preserves original commit author and handles message editing
- Documentation in `Documentation/git-history.adoc` (marked experimental) with initial positioning relative to `git-rebase`
- Test coverage expanded with:
  - `t/t3451-history-reword.sh` (8 test cases)
  - New `t/t3452-history-split.sh` (18 test cases, 447 lines)
  - Existing `t/t3450-history.sh`
- Shared `replay.[ch]` infrastructure used by both subcommands via `apply_commits()`
- Patch 7/12 introduced new `add-patch.h` header, separating declarations from `add-interactive.h`
- Patch 8/12 refactors shared code with:
  - New `struct interactive_options` replacing `struct add_p_opt`
  - New `struct interactive_config` consolidating color/config settings
  - `interactive_config_init()` centralizing initialization logic
- Previous patch generalizes `write_in_core_index_as_tree()` to:
  - Accept arbitrary `index_state` parameter instead of using repository index
  - Maintain identical behavior when passed repository index
  - Enable future use with temporary in-memory indexes
- `wt_status_collect_changes_trees()` wraps diff machinery with wt_status formatting
- tree-to-tree diff capability added while maintaining rename detection
- Multiple patches replace `the_repository` with passed `repo` parameters
- Remaining `the_repository` dependencies noted for DEFAULT_ABBREV, get_commit_output_encoding
- Build system updates (Makefile, meson.build) for new command
