Thread identity: RFC proposal for `git-history` command with twelve-patch v6 series (with `reword` and `split` subcommands), authored by Patrick Steinhardt. Series builds on Git's replay machinery while drawing inspiration from Jujutsu's history editing capabilities, focused on non-conflicting operations after Git Contributor's Summit discussions.

Core problem/goal: Implement flexible history editing operations (`reword` and `split` subcommands) with supporting infrastructure refactoring (interactive add/patch, cache-tree modifications, and wt-status tree-to-tree diff capabilities) to enable in-memory index operations. Current implementation avoids `drop` and management commands based on community feedback.

Current status: While maintainer Junio Hamano previously indicated the series was nearing completion, substantive concerns from Elijah Newren's review have prompted discussion about potentially limiting initial scope to single-branch cases for earlier integration. Key infrastructure refactoring patches have stabilized but implementation details around `run_add_p_index()` and branch handling design remain active discussion points, with Junio now advocating for an incremental approach.

Key technical details:
- Foundational infrastructure (completed/updated):
  - New add-patch/add-interactive separation completed via `struct interactive_config` integration
  - `add-patch.h` header with decoupled configuration
  - `run_add_p_index()` for in-memory operations (current discussion point)
  - Generalized `write_in_core_index_as_tree()`
  - `replay.[ch]` infrastructure extraction
  - Tree-to-tree diff in wt-status
  - Final `the_repository` removal in `replay_create_commit()`
- `reword` subcommand:
  - Current implementation uses manual ancestry checking
  - May not properly restrict revision walk to descendants
  - Uses `commit_tree()` instead of `commit_tree_extended()`
- `split` subcommand:
  - Binary split implementation (creates exactly two commits)
  - Interactive hunk selection via `run_add_p_index()`
  - Preserves authorship and reuses original message
  - Includes extensive test coverage
- Documentation follows experimental command style
- Build system updates for new components

Open questions:
- Infrastructure refactoring:
  - Current discussion on `run_add_p_index()` implementation approach
  - Potential for accidental use of `s->r->index` instead of intended `s->index`
- Branch handling design:
  - Junio suggests limiting initial scope to single-branch cases
  - Elijah's concerns about commits on multiple branches remain
- Index preservation:
  - Edge case where splitting commits while editing patches could lead to unexpected state
- Split subcommand design:

  - Unnecessary HEAD reachability requirement
  - Reword subcommand merge commit support
