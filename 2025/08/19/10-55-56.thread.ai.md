Thread identity: RFC proposal for `git-history` command with twelve-patch v6 series (with `reword` and `split` subcommands), authored by Patrick Steinhardt. Series builds on Git's sequencer while drawing inspiration from Jujutsu's history editing capabilities, focused on non-conflicting operations after Git Contributor's Summit discussions.

Core problem/goal: Implement flexible history editing operations (`reword` and `split` subcommands) with supporting infrastructure refactoring (interactive add/patch, cache-tree modifications, and wt-status tree-to-tree diff capabilities) to enable in-memory index operations. Current implementation avoids `drop` and management commands based on community feedback.

Current status: v6 series now includes three refactoring patches - splitting add-patch declarations into their own header file (`add-patch.h`), decoupling color/configuration handling between add-patch and add-interactive subsystems via new `struct interactive_options` and `struct interactive_config`, and this latest patch removing direct `add-i` subsystem dependencies from `add-patch.c`. Series simplifies implementation by dropping `-m` options, removing replay machinery usage, and eliminating redundant commit parsing checks. Rebased on latest upstream changes. Includes infrastructure patch extracting commit-picking logic from `builtin/replay.c` into shared `replay.[ch]` files and additional refactoring to remove `the_repository` usage in `replay_create_commit()`. Queued for integration pending stabilization of sa/replay-atomic-ref-updates dependency. Junio Hamano has approved multiple patches including the `the_repository` removal in `create_commit()` buffer handling with "obviously correct" assessment. Documentation patch updated to address all style feedback from Junio regarding experimental warning format (now matching `backfill`/`for-each-repo` conventions) and subcommand phrasing. New infrastructure adds tree-to-tree diff capability to wt-status subsystem.
