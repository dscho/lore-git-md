This thread began with Chris Judkins-Fisher raising two separate but related points: the continued use of the legacy `git whatchanged` command (which duplicates `git log -p --raw --no-abbrev` functionality) and mailing list submission issues when messages violate HTML formatting rules. The discussion has since focused primarily on the technical aspects of `git whatchanged`.

Randall Becker proposed a user-side workaround via git configuration aliases (`git config --global alias.whatchanged 'log'`), which Kristoffer Haugsbakk has now clarified would only work in Git 3.0 and later, as earlier versions don't support aliasing core commands. This version constraint significantly limits the usefulness of the alias approach for users on older Git installations.

The mailing list submission issue mentioned in the thread's origin remains unaddressed, with kernel.org's HTML formatting requirements still causing friction for some contributors. On the technical side, while there's consensus that `git whatchanged` is redundant, the discussion has revealed practical challenges in migrating away from it, particularly for users who can't upgrade to Git 3.0+. No code changes to Git itself have been proposed, and the thread continues to explore user-side solutions rather than core modifications.
