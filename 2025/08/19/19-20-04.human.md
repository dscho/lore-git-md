This is a bugfix series addressing an issue with dangling symrefs and the `followRemoteHEAD=create configuration. The core problem occurs when `git fetch` incorrectly overwrites a remote HEAD symref that was explicitly created, even when configured to only create it if missing. Jeff King found this while investigating a related (now fixed) bug.

The series starts with three preparatory test cleanups (patches 1-3) that modernize and clarify the test infrastructure around remote HEAD tracking. The actual fix comes in patch 4, which modifies both the files and reftable backends to properly respect creation events for dangling symrefs. The change affects not just `git fetch` but also `git update-ref`.

The patches appear well-structured, with the fix properly isolated after test improvements. The commit message provides clear reproduction steps and links to prior discussion, suggesting this is a thoughtful solution to a real edge case. The changes touch core refs handling but are focused on the specific symref behavior.
