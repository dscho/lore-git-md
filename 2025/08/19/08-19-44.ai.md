This is part 15/16 of Patrick Steinhardt's series refactoring Git's packfile subsystem as part of the object database (ODB) abstraction effort. The patch focuses on `get_all_packs()`, which returns all packfiles including those referenced by multi-pack indices.

The key changes are:
- Renames `get_all_packs()` to `packfile_store_get_packs()` to better reflect its scope
- Makes the function operate directly on a `packfile_store` rather than a repository
- Updates 19 call sites across various builtins and helper code to use the new interface
- Maintains identical behavior while better isolating packfile operations within the store abstraction

The patch continues the pattern seen in previous parts of the series by moving packfile-specific functionality out of generic repository/ODB code and into the dedicated packfile store structure. This is groundwork for making packfile management implementation-specific in the ODB abstraction.

Technical details important for future thread context:
- The new `packfile_store_get_packs()` is declared in packfile.h
- It still handles MIDX pack preparation like the original function
- All callers now access packs via `the_repository->objects->packfiles`
- The changes affect core operations in packfile.c/h plus various builtins and test helpers

This is a straightforward mechanical change that follows the established pattern of the series, with no expected controversy. The wide scope of call site updates reflects how fundamental packfile enumeration is throughout the codebase.
