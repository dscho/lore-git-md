This is the first patch in a 16-part series refactoring Git's packfile management as part of the object database (ODB) abstraction effort. It introduces a new `struct packfile_store` to centralize packfile-related data currently scattered between `struct packed_git` and `struct object_database`.

The patch creates the basic infrastructure for the new store with minimal initial content - just an ODB pointer. The commit message explains this is preparatory work to eventually move all packfile management into this structure, enabling pluggable ODB backends where packfile handling can be implementation-specific. The changes touch odb.c/h and packfile.c/h, adding the new struct and its allocation/free functions.

Key technical details: The store is initialized when creating a new ODB via `odb_new()`. The empty struct will be populated in subsequent patches with packfile chain, MRU list, and other packfile management fields currently in `object_database`. The patch explicitly notes this is an intermediate step - the store will later move from ODB level to ODB source level.

This foundational change is mechanical but important for the larger architectural goal. The patch follows good practices with clear commit message explaining both current state and future direction. No behavior changes yet - this purely adds infrastructure for the refactoring to come in later patches.
