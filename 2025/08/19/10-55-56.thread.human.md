Patrick Steinhardt's RFC series for a new `git-history` command continues to evolve, now at v4 with seventeen patches. The thread began as a proposal for Jujutsu-inspired history editing operations and has been refined through several iterations based on community feedback. The latest addition introduces a `split` subcommand that interactively divides a commit into two parts, complementing the existing `reword` functionality.

The `split` implementation builds on infrastructure refactoring from earlier in the series, particularly the modified `write_in_core_index_as_tree()` function that enables in-memory index operations. It handles various commit positions (tip, root, or middle of history) and uses Git's familiar `add -p` interface for interactive hunk selection. The subcommand includes safeguards against creating empty commits and preserves original authorship information. A comprehensive test suite covers basic scenarios, edge cases like merge commits, and pathspec filtering.

Key participants have engaged with the series throughout its development. Patrick has addressed concerns from SZEDER Gábor, Phillip Wood, and Oswald Buddenhagen by narrowing the scope, and Junio C Hamano's merge conflict concerns have been resolved. The work also advances René Scharfe's ongoing effort to remove `the_repository` global variable. While the core functionality appears solid, open questions remain about hook execution integration and performance with large commit chains. The series continues to demonstrate careful, incremental infrastructure improvements while adding user-facing features.
