Patrick Steinhardt is proposing a new `git-history` command through an RFC patch series (now at v9) that would provide flexible history editing capabilities. The command is positioned as an experimental alternative to parts of `git rebase`, with initial focus on non-conflicting operations like rewording commit messages.

The latest additions include the command infrastructure and the first concrete subcommand - `reword`. This allows changing commit messages without checking out the commit, working even with unmodified changes present. It offers three reference update modes and preserves original authorship while being faster than interactive rebase for this specific operation.

The implementation builds on Git's replay machinery, refactoring parts of it into library code. Recent patches have addressed feedback around documentation, naming, and error handling. Key contributors like Phillip Wood and Elijah Newren have helped shape the design, particularly around performance considerations and scope (currently limited to local branches).

Open questions remain about how this will interact with stacked branch workflows, hook execution policy, and some remaining technical debt in the replay infrastructure. The series continues to evolve incrementally, with the command framework now in place and the first subcommand implemented. Junio Hamano will evaluate the replay-based implementation approach as the series progresses.
