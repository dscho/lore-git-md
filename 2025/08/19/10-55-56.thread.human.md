Patrick Steinhardt's RFC for a new `git-history` command continues to receive detailed technical review. The series, now at v1 with thirteen patches, proposes three subcommands (`drop`, `reorder`, and `split`) inspired by Jujutsu's history editing capabilities while building on Git's existing sequencer infrastructure.

D. Ben Knoble has been actively reviewing the implementation, with his latest feedback focusing on the `drop` subcommand's commit collection logic. He identified two specific issues: unclear variable naming in `collect_commits()` and a potential bug in the array reversal code where the comment's description doesn't match the implementation. While noting the rest of the code looks reasonable, Knoble qualified his review by acknowledging limited familiarity with the sequencer APIs.

Earlier in the thread, Junio C Hamano provided design feedback on notes handling and operation semantics, endorsing the current linear-history limitation while speculating about future multi-branch possibilities. The discussion has remained technical and constructive, with participants drawing comparisons to Jujutsu's approaches while ensuring the new functionality fits Git's workflow. Several open questions remain around merge commit support, conflict handling, and performance characteristics, but the RFC appears to be progressing through the review process with careful attention to implementation details.
