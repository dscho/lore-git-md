This RFC thread explores Patrick Steinhardt's proposal for a new `git-history` command with `drop`, `reorder`, and `split` subcommands, inspired by Jujutsu's functionality. The thirteen-patch v1 series has sparked a lively debate about Git's history manipulation architecture, particularly around how these new operations should relate to existing commands like rebase and cherry-pick.

The discussion has evolved into two parallel tracks: one examining high-level command architecture (led by Sergey Organov and Ben Knoble debating whether rebase should subsume cherry-pick's functionality), and another focused on implementation constraints in the current series (where Steinhardt is addressing Junio Hamano's notes-handling concerns and Knoble's observations about commit reachability). Steinhardt is taking a conservative approach, prioritizing simplicity in the initial implementation by failing on complex cases like merge commits and deferring full notes support until v3, while leaving the door open for future expansion based on the ongoing design discussions.

Key participants have staked out positions: Organov advocates for rebase as the primary history manipulation primitive, while Knoble counters that `rebase --onto` already provides sufficient capability. Meanwhile, Steinhardt remains focused on incremental progress, acknowledging the architectural debates while keeping his implementation narrowly scoped to demonstrate the core functionality. The thread remains productive, with the RFC status allowing these design questions to be explored without blocking the series' technical evolution.
