Steinhardt maintains the current behavior is intentional, citing practical workflow cases where commits intentionally exist on multiple dependent branches but should only be modified on one. He notes that checking all references for multi-branch cases could introduce performance overhead, particularly with long-lived release branches.

This debate reflects a philosophical tension between Git's traditionally conservative approach to history modification and more aggressive editing capabilities found in tools like Jujutsu. The resolution will significantly impact how the command handles complex branch topologies, with Newren warning that the current behavior - if marked experimental but left unchanged - may become entrenched and harder to modify later.
