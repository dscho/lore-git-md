This RFC thread introduces a new `git-history` command with `drop`, `reorder`, and `split` subcommands, inspired by Jujutsu's history editing capabilities. Patrick Steinhardt's initial 13-patch series has sparked productive discussion about implementation details and documentation standards.

The core functionality builds on Git's sequencer infrastructure to provide more flexible history manipulation than rebase or cherry-pick alone. Maintainer Junio C Hamano has endorsed the conservative implementation approach, particularly the strict error handling in the split operation. Technical discussions have covered in-memory index handling, merge commit strategies, and the sequencer API's complexity.

Jean-Noël Avila has provided thorough documentation reviews for all three subcommands, with this latest round focusing on the `split` operation. His feedback addresses synopsis formatting, parameter naming consistency, and option ordering - continuing the pattern of incremental documentation polish across the series. The implementation itself remains unchanged, with the split operation using interactive hunk selection similar to `add -p` while preserving authorship and preventing empty commits.

Key open questions remain about notes rewriting, merge commit support expansion, and long-term alignment with either rebase or cherry-pick models. The thread shows consensus on starting simple while leaving room for future refinements, particularly around user experience details like message handling in split operations. With this final documentation review complete, the series appears ready for Patrick to incorporate feedback and send a v2 iteration.
