Patrick Steinhardt continues his RFC series introducing a new `git-history` command with the addition of a "reorder" subcommand, bringing the series to 6 patches out of a planned 11. The command automates commit reordering (moving commits before or after others) that would otherwise require manual interactive rebase steps, following the same pattern as the previously introduced "drop" subcommand.

The implementation builds on the same infrastructure from earlier patches, reusing the `collect_commits()` and `apply_commits()` helpers while adding new reordering logic. Like the drop command, it currently rejects merge commits and falls back to standard cherry-pick conflict resolution. The patch includes comprehensive tests (218 lines) covering basic reordering, edge cases, and conflict scenarios.

This continues the series' approach of bringing Jujutsu-inspired history editing capabilities to Git while leveraging Git's existing sequencer infrastructure. The implementation appears solid, though the RFC nature means there are still open questions about how these commands will interact with other history-rewriting operations and whether the cache-tree changes might need broader review. The series remains in early stages, with several more subcommands (including "split") still to come.
