This RFC thread explores Patrick Steinhardt's proposal for a new `git-history` command, now in its third iteration with eighteen patches (down from twenty-six in previous versions). The command would provide Jujutsu-inspired history editing operations like `drop`, `reorder`, `split`, and `reword`, along with management commands (`abort`/`continue`/`quit`). The series builds on Git's sequencer infrastructure while introducing new capabilities like an `oidmap` for tracking rewritten commits and proper hook execution.

The latest patch adds preparatory sequencer infrastructure - a `skip_commit_summary` option that will be used by the history command to suppress redundant commit summaries during bulk operations. This well-contained change modifies `struct replay_opts` and its configuration handling while following established Git patterns.

Key discussion points include D. Ben Knoble's report of a diff visibility issue in the `split` subcommand (still unresolved) and Patrick's confirmation that `squash` functionality will be added later. The series may be reorganized after this RFC round, potentially stopping after the `reorder` implementation before proceeding with additional subcommands. Technical implementation details now include proper hook support and respect for `commit.verbose` configuration.

The thread shows active design discussion about both immediate implementation concerns (like the `split` behavior) and longer-term direction, with Patrick demonstrating responsiveness to feedback while maintaining a vision for expanded functionality. The preparatory nature of the latest patch suggests the series is progressing methodically toward its goals.
