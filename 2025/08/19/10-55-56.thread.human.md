This RFC thread introduces Patrick Steinhardt's proposal for a new `git-history` command, inspired by Jujutsu (jj) functionality, with subcommands for flexible history editing. The series currently stands at thirteen patches implementing `drop`, `reorder`, and `split` operations, building on Git's sequencer infrastructure.

The discussion has evolved through technical reviews of implementation details, with recent focus on the `split` subcommand's user experience. D. Ben Knoble suggested showing the original commit message as a reference when splitting commits, which Patrick acknowledged as a potential future improvement. The current implementation takes a simpler approach, only prompting for a new message for the split-out changes. Patrick has agreed to enhance the message template in v2 and document the current "all or nothing" error recovery behavior.

Throughout the thread, Patrick has been responsive to feedback while maintaining a clear incremental development approach. Key open questions remain about notes handling, merge commit support strategy, and how to balance cherry-pick versus rebase models long-term. The discussion remains productive, with the latest exchanges shifting from low-level implementation details to polishing user-facing behavior as the RFC matures.
