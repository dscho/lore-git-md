This RFC thread explores Patrick Steinhardt's proposal for a new `git-history` command with `drop`, `reorder`, and `split` subcommands, inspired by Jujutsu's functionality. The thirteen-patch series introduces history editing operations building on Git's sequencer infrastructure, with preparatory refactoring and three subcommand implementations. Key technical aspects include interactive hunk selection, pathspec support, and notes handling considerations.

The discussion has evolved to focus on two critical design questions: notes handling semantics and potential multi-branch operation. Junio Hamano and Ben Knoble agree the command must properly implement `notes.rewriteref` behavior, distinguishing between history rewriting (which should update notes) and cherry-picking (which shouldn't). Ben also explores how future versions might expand beyond linear history editing, drawing parallels with Git's existing `rebase --update-refs` and Jujutsu's multi-branch approaches, suggesting safety heuristics around pushed/unpushed commits while preserving force-push capability.

Open questions remain about merge commit support, conflict handling, and performance. The thread reflects Git's careful approach to adopting features from tools like Jujutsu while maintaining its core workflow - a theme Ben explicitly appreciates in this latest email.
