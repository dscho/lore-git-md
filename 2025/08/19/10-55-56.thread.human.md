Here's a human-readable summary of the thread's current state:

Patrick Steinhardt has proposed a new `git-history` command through an RFC patch series, now expanded to include twelve patches. The command aims to provide more powerful history editing capabilities than interactive rebase, taking inspiration from Jujutsu (jj)'s workflow. The series introduces three subcommands: `drop` for removing commits, `reorder` for rearranging commit order, and now `split` for interactively breaking apart commits.

The implementation builds carefully on Git's existing infrastructure, with preparatory changes to the sequencer and cache-tree systems, followed by command scaffolding and the three subcommands. The new `split` functionality completes the core feature set, allowing users to interactively select hunks from a commit to move into a new parent commit - a common but complex operation that currently requires manual rebase steps.

While the implementation is quite thorough (with over 1,100 lines of test coverage across three test files), there are several known limitations. Most notably, the commands don't yet support merge commits, and conflict handling remains basic. The series also includes significant refactoring work to support these features, including header reorganization, interactive configuration changes, and add-patch subsystem improvements that affect multiple commands.

The RFC appears technically solid but hasn't yet received review feedback. Given the scope of changes and their potential impact on other subsystems (particularly around the sequencer and index handling), we can expect detailed technical review once maintainers and domain experts like Phillip Wood (sequencer) and René Scharfe (code organization) begin examining the patches. The merge commit limitation in particular will likely need addressing before the series could be considered for merging.
