Here's a human-readable summary of the thread's current state:

Patrick Steinhardt is proposing a new `git-history` command that would provide more intuitive ways to edit commit history, taking inspiration from Jujutsu (jj). The RFC has reached v3 with twenty patches that include both preparatory infrastructure work and command implementations. The command would offer subcommands for common operations like dropping, reordering, splitting, and rewording commits.

The latest additions include significant infrastructure changes to support this functionality: a new `REPLAY_HISTORY_EDIT` sequencer mode, removal of `the_repository` dependency in sequencer code, and cache-tree refactoring to handle in-memory index states. These changes lay the groundwork for the history editing operations while also improving Git's core infrastructure.

Maintainer Junio Hamano has approved the conservative implementation approach, which currently uses cherry-pick mechanics as a foundation but may evolve toward rebase-like functionality. Active discussions continue around several aspects: how the command differs from interactive rebase (particularly the `reorder` subcommand), merge commit handling, notes rewriting, and user experience details like split commit message handling.

The implementation is currently marked as experimental, with documentation clearly noting its limitations and potential for change. Reviewers have provided detailed feedback on both technical implementation (D. Ben Knoble) and documentation formatting (Jean-Noël Avila). Comparisons with Jujutsu's behavior (from Martin von Zweigbergk) and questions about workflow advantages (from Kristoffer Haugsbakk) continue to shape the design discussions.

The series represents both new functionality and architectural improvements, with Patrick actively responding to feedback while maintaining focus on the command's core goals. The experimental status allows for iteration as the community evaluates the approach and its integration with Git's existing tools.
