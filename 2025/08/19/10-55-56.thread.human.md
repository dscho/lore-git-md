This RFC series from Patrick Steinhardt introduces a new `git-history` command with several subcommands for flexible history editing, inspired by Jujutsu (jj). The v3 series now includes implementations for all proposed editing operations: `drop`, `reorder`, `split`, and the newly added `reword`, along with management commands (`abort`/`continue`/`quit`).

The latest addition, `reword`, provides a standalone way to rewrite commit messages while preserving all other commit metadata, similar to `git rebase -i`'s "reword" action. It handles the full workflow including validation (rejecting merge commits, checking for clean working state), preserves original authorship, and supports both direct message specification and interactive editing. The implementation builds on the series' existing infrastructure for collecting and applying commits, and includes comprehensive test suite covering edge cases.

The series follows a careful, incremental approach - each new subcommand builds on preparatory infrastructure from earlier patches, including refactoring of the `add-patch` subsystem, tree-diff capabilities, and sequencer infrastructure. The `reword` implementation demonstrates the same attention to edge cases and user experience seen in previous subcommands like `split` (which allows interactively splitting commits by hunk selection) and `drop`.

While the core implementations appear solid, some design questions remain open about how these subcommands will interact in more complex editing scenarios, particularly around root commit handling and documentation of the relationship to existing `rebase -i` functionality. The RFC status continues to be appropriate as these discussions evolve. The series represents a significant expansion of Git's history editing capabilities while maintaining careful attention to building on stable infrastructure.
