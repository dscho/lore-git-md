Patrick Steinhardt's `git-history` proposal continues to evolve through rigorous review, with the v5 series now in its final polishing stages. The thread began as an RFC to introduce flexible history editing commands (`reword` and `split` subcommands), drawing inspiration from Jujutsu while respecting Git's constraints. After addressing initial technical concerns about conflict handling and infrastructure dependencies, the series has reached near-consensus on implementation approach, with Junio Hamano already queuing it for integration.

The latest discussion focuses on UX refinements. Junio, while expressing enthusiasm for the feature's utility, suggests simplifying both the interface and implementation of the `reword` subcommand. He questions keeping the command-less form in documentation now that subcommands are required, proposes standardizing the option ordering, and—most significantly—recommends bypassing the replay machinery entirely for this simple case since rewording involves no content changes. This could lead to a leaner implementation that directly constructs new commits rather than using the pick infrastructure.

Meanwhile, an active three-way discussion continues about message handling in the `split` subcommand, with D. Ben Knoble now advocating for requiring editor-based editing rather than supporting `-m` flags, adding a third perspective to Patrick's and Karthik Nayak's earlier exchange. With only documentation style nits and these final design questions remaining—alongside Junio's technical queries about commit parsing safety—the series appears poised for inclusion once these last details are resolved. The thorough test coverage (26 tests across two new test files) and comprehensive addressing of prior reviews position this as one of the more polished large features currently in flight.
