This RFC thread explores Patrick Steinhardt's proposal for a new `git-history` command, inspired by Jujutsu (jj) functionality, with subcommands for dropping, reordering, and splitting commits. The thirteen-patch series builds on Git's sequencer infrastructure while introducing new interactive capabilities, particularly for the `split` subcommand which will allow hunk-by-hunk commit editing via the familiar `add-patch` interface.

The discussion has drawn detailed technical reviews from D. Ben Knoble and Junio C Hamano. Knoble has been examining implementation specifics, recently flagging a potentially duplicated index read in the new in-memory index infrastructure patch while praising its cleaner error handling. Earlier exchanges covered commit collection logic in the `drop` subcommand and notes handling semantics. Junio has weighed in on design-level considerations, endorsing the current linear-history focus while speculating about future multi-branch possibilities.

Key open questions remain around merge commit support, conflict handling, and performance characteristics. The series is still in RFC stage, with the author incorporating feedback on both the high-level design and low-level implementation details as the infrastructure takes shape. The collaborative review process is yielding incremental improvements to the code while maintaining focus on the command's goal of bringing more sophisticated history editing to Git's core.
