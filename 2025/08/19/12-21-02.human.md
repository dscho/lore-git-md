This is the third patch in a 5-part series adding fsck validation for the reftable backend. It introduces a check to verify that the number of reftable files in the directory matches what's recorded in 'tables.list'.

The patch adds a new validation step that counts the regular files in the reftable directory (excluding 'tables.list' itself) and compares this count against the stack's recorded table count. A mismatch triggers a new 'badReftableStackCount' fsck error. The implementation follows the same pattern as the previous table name validation, with corresponding updates to documentation, error handling, and test coverage.

The change is straightforward and well-contained, adding about 60 lines of code including tests. The test case demonstrates both the successful case and the error condition by manually adding an extra table file. This continues the series' focus on basic reftable consistency checks while maintaining clean separation between reftable internals and Git's fsck system.
