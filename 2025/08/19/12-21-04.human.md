This is the fifth and final patch in Karthik Nayak's reftable fsck validation series, adding a check for sequential update indices in reftable files. The patch ensures tables listed in 'tables.list' have properly ordered update indices, catching cases where table names might be manually edited to create gaps or out-of-order sequences.

The implementation adds a new error type `REFTABLE_FSCK_ERROR_UPDATE_INDEX` and corresponding fsck message ID `badReftableUpdateIndex`, following the series' pattern of clean separation between reftable internals and fsck infrastructure. Two test cases verify the check works for both inter-table and intra-table sequence validation.

The patch completes the current round of reftable fsck checks, though the commit message notes future work remains to validate internal table consistency (matching indices between table names, headers, and contents). The series as a whole represents solid incremental progress on reftable validation, with clear architectural separation and thorough test coverage for each new check.
