This is patch 14/16 in Patrick Steinhardt's series refactoring Git's packfile subsystem as part of the object database (ODB) abstraction effort. The patch removes the redundant `get_packed_git()` function in favor of using `get_all_packs()` consistently.

The key change is eliminating the duplicate packfile accessor function that returned the same underlying list as `get_all_packs()` but without MIDX handling. The patch updates three call sites to use the more comprehensive `get_all_packs()` or the new `packfile_store_prepare()` function introduced earlier in the series. The changes are in builtin/gc.c (for auto-repack counting), builtin/grep.c (for eager pack loading), and object-name.c (for object disambiguation).

The removal is justified because:
1. The functions ultimately accessed the same packfile list
2. All callers were already prepared to handle MIDX-loaded packs
3. The `packfile_store_prepare()` function provides a more direct way to eagerly load packs when needed

This continues the series' pattern of simplifying the packfile interface while maintaining behavior, removing now-unnecessary distinctions as the codebase moves toward the new `packfile_store` abstraction. The changes are mechanical but help reduce confusion by having a single way to access packfiles.
