Feature implementation adding a `split` subcommand to the proposed `git-history` command, completing the RFC series. This patch introduces interactive commit splitting functionality that automates what would otherwise be a complex rebase workflow.

The new `git history split` command allows users to interactively select hunks from a commit to move into a new parent commit, with the original commit being rewritten to sit on top. The implementation builds on the series' existing infrastructure including `collect_commits()` and `apply_commits()` helpers, while adding new `split_commit()` logic that handles the interactive hunk selection via the `add-patch` subsystem. Key aspects include:

- Interactive hunk selection interface similar to `git add -p`
- Pathspec support to limit which files are considered for splitting
- Validation to prevent creating empty commits (either split-out or remaining)
- Automatic commit message handling (either via editor or `-m` option)
- Test coverage for various scenarios (root commits, in-between commits, path limiting)

The implementation shows careful attention to edge cases with 300+ lines of test coverage in t3452-history-split.sh. The patch integrates with the series' existing sequencer-based approach while adding new functionality that significantly simplifies a common but tricky history editing task. As with other patches in the series, merge commits remain unsupported - a noted limitation that may need addressing before finalization.
