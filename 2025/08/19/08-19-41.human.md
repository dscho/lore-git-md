This is part 12 of Patrick Steinhardt's ongoing refactoring series to move packfile management into a dedicated `packfile_store` structure as part of the object database abstraction effort.

The patch introduces a new helper function `packfile_store_load_pack()` that combines the common pattern of checking if a packfile exists in the store and, if not, loading and adding it. This replaces several instances of manual packfile lookup and insertion across the codebase with a single standardized operation.

The changes affect packfile handling in fast-import, index-pack, midx, and core packfile operations. The new function properly handles the conversion between .idx and .pack filenames that was previously duplicated at each call site. The implementation maintains all existing behavior while reducing code duplication.

This continues the series' pattern of moving packfile-specific logic out of generic ODB code and into the dedicated store structure. The change appears well-contained and mechanical, following the established approach of the previous patches in the series.
