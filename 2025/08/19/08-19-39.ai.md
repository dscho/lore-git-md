This is part 10 of Patrick Steinhardt's ongoing refactoring series to move packfile management into a dedicated `packfile_store` structure as part of the object database abstraction effort. The patch refactors `install_packed_git()` to work directly with a `packfile_store` rather than a repository, renaming it to `packfile_store_add_pack()` to better reflect its scope. The function's core behavior remains unchanged - it still adds a packfile to the store's list and hashmap while tracking open file descriptors. The changes propagate through several call sites in fast-import, index-pack, http, and midx code that need to now pass the packfile store explicitly.

Key technical details:
- The renamed `packfile_store_add_pack()` takes ownership of the packfile by adding it to both the store's `packs` linked list and `map` hashmap
- All 7 call sites are updated to pass `the_repository->objects->packfiles` instead of the repository
- The http.h documentation is updated to reference the new function name
- The change maintains identical behavior while better isolating packfile operations within the store abstraction

This continues the series' pattern of moving packfile-specific functionality out of the generic object database structure. The patch is mechanical but touches several components that interact with packfiles, requiring careful updates to maintain correct behavior.
