This is a technical discussion about submodule hash algorithm interoperability, specifically addressing the bugfix for shallow submodule handling when superproject and submodule use different hash algorithms (SHA-1 vs SHA-256). Brian M. Carlson responds to Michael Schroeder's assertion that mixed-hash configurations already work in practice, arguing this is fundamentally unsupported and will break with future interoperability features.

The email makes several key technical points: 1) The protocol will soon support object ID conversion between hash algorithms, making the current truncation/padding approach incompatible; 2) The hash transition design has always mandated a single object format per repository; 3) There's no way to distinguish between a SHA-256 submodule with trailing zeros and a SHA-1 submodule in tree objects. Carlson reveals they are actively working on shallow clone interoperability and plans to address submodules next, with code to be submitted upstream after Git Merge.

The response highlights deeper architectural concerns beyond the immediate shallow clone fix, suggesting the current workarounds may create repositories that become permanently incompatible with future interoperability features. This moves the discussion from practical bugfix territory into fundamental design constraints, with Carlson taking a firm stance that mixed hash algorithms in submodules should not be supported at all rather than patching current behavior. The email references ongoing but not-yet-published work on pack interoperability and shallow clone support that would properly handle these cases.
