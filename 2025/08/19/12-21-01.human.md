Reftable fsck validation (part 2/5) - table name checking. This patch introduces the core infrastructure for reftable fsck validation and implements the first concrete check: verifying that reftable filenames follow the expected format (hex min/max hashes, random suffix, and `.ref` extension). The architecture cleanly separates reftable internals from Git's fsck system via new `reftable/fsck.[ch]` files that handle validation while `refs/reftable-backend.c` maps reftable errors to standard Git fsck messages. The implementation includes verbose output support and handles both main and worktree ref backends. A new test in `t0614-reftable-fsck.sh` verifies the table name validation works by deliberately corrupting a table name and checking the error output. This is part of Karthik Nayak's series to bring fsck validation to the reftable backend, with future patches planned to add more checks. The code appears well-structured with clear separation of concerns and thorough test coverage for this initial check.
