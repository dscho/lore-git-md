This thread discusses concerns about the planned removal of git grafts functionality in Git 3.0. The discussion was prompted by a user who raised specific objections about the impact this change would have on real-world usage, particularly for the Linux kernel history repository (history.git) which relies heavily on grafts to connect different segments of Linux history.

The user strongly argues that grafts shouldn't be removed until history.git is made fully compatible with the replacement mechanism (git replace), noting this repository is widely used and referenced (including on StackOverflow and archive.org). They also raise questions about whether shallow clones might be affected and request that Git 3.0 release notes include clear migration instructions for history.git users. The concerns focus on practical impacts rather than technical implementation, emphasizing the need for proper migration paths before deprecating this feature.
