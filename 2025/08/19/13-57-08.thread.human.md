This thread discusses the planned removal of the grafts functionality in Git 3.0, focusing on two key use cases: the kernel's history.git repository and shallow clone operations. The grafts mechanism, which allows rewriting commit parent relationships, is scheduled for deprecation in favor of git replace, but concerns were raised about whether this replacement would work for these important real-world cases.

Junio Hamano has now clarified that shallow clone operations (--depth, --shallow-since, etc.) use their own internal mechanism separate from grafts, despite sharing some code paths. This means grafts removal shouldn't impact shallow clone functionality, addressing one of the two major concerns. However, the question of how history.git will migrate from grafts to git replace remains open - this repository uses grafts to stitch together segments of Linux kernel history and needs a verified migration path before the deprecation can proceed.

The discussion has narrowed to focus on the history.git case, with participants still needing concrete verification that git replace can handle this complex history-rewriting scenario without breaking references. The thread shows the project carefully validating real-world impacts before removing long-standing functionality.
