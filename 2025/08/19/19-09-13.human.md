This is a workflow suggestion in the ongoing discussion about GUI tools for Git history manipulation. Johannes Sixt proposes a "half-GUI" approach combining `gitk` for visual diff inspection and `git gui` for staging changes, used alongside the CLI's `commit --fixup` and `rebase --autosquash` workflow.

The key points are:
1. The method leverages existing tools (`gitk` and `git gui`) to provide visual feedback while still using CLI commands for the actual history rewriting
2. It demonstrates how to use `--fixup` commits that automatically position themselves correctly during an interactive rebase with `--autosquash`
3. The workflow includes a useful `gitk` feature for tracing line origins to identify which commit needs fixing
4. Johannes notes the approach depends on having meaningful commit messages for the autosquash matching to work properly

This is a practical middle ground that addresses some of R. Diez's pain points (visual inspection, partial changes) while staying within Git's existing capabilities.
