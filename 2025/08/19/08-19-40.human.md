This is part 11 of Patrick Steinhardt's ongoing series to refactor Git's packfile subsystem as part of the object database abstraction effort. The patch focuses on making packfile MRU (Most-Recently-Used) list handling more consistent.

The change ensures that packfiles are always added to the MRU list when they're first added to the packfile store, rather than waiting until their objects are accessed. Currently, some subsystems add packs to the MRU list immediately while others don't, creating inconsistency. The patch simplifies this by moving the MRU list addition into the core `packfile_store_add_pack()` function.

The implementation removes explicit MRU additions from midx handling code since they'll now happen automatically, and adds the MRU list update to the main packfile addition function. This is a small but logical step in the larger packfile store refactoring, maintaining the same behavior while making it more consistent across the codebase. The changes are minimal (just 3 lines changed) and focused on the MRU list management aspect of the packfile store abstraction.
