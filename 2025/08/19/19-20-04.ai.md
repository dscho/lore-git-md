This is a bugfix series addressing an issue with dangling symrefs and the `followRemoteHEAD=create` configuration. The core problem occurs when `git fetch` incorrectly overwrites a remote HEAD symref that was explicitly created, even when configured to only create it if missing. The series starts with three preparatory test cleanup patches (1-3/4) that modernize and clarify the test infrastructure around remote HEAD tracking. These include making config cleanup more explicit, avoiding top-level directory changes, and preferring `git -C` over subshells. The main fix in 4/4 modifies refs backend behavior to properly respect creation events for dangling symrefs, affecting both files and reftable backends. The patch includes detailed explanation of the issue and adds new test coverage in both t1400-update-ref.sh and t5510-fetch.sh. The changes are focused and well-motivated, with the test cleanups making the actual bugfix easier to verify. The series appears to be a solid fix for a subtle interaction between symref handling and fetch configuration.
