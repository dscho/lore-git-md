This is a feature proposal introducing a new `git-history` command for easier history editing, inspired by Jujutsu's functionality. The RFC cover letter outlines three initial subcommands (`drop`, `reorder`, `split`) with plans for future additions like `absorb`, `reword`, and `squash`. The implementation builds on existing sequencer infrastructure but currently has some limitations around merge conflicts and merge commits.

The series touches multiple areas: it adds a new builtin command, modifies sequencer behavior, refactors add-patch functionality to support in-memory operations, and updates cache-tree handling. The implementation includes substantial test coverage (over 600 lines of new tests across three test files) and documentation.

Key technical points for future reference:
- New `git-history` command with subcommands for common history editing operations
- `drop` removes commits (similar to `jj-abandon`)
- `reorder` moves commits (inspired by `jj-new`)
- `split` divides commits (similar to `jj-split`)
- Uses modified sequencer infrastructure (with some current limitations)
- Refactors add-patch to work with in-memory indexes
- Current limitations:
  - Uses `cherry-pick --continue` for conflicts
  - Doesn't handle merge commits in rewritten history
- Future directions mentioned: absorb, reword, squash functionality

The proposal appears well-structured with clear motivation from Jujutsu's workflow, though some implementation details (like conflict handling) remain to be polished. The extensive test coverage suggests serious consideration of edge cases.
