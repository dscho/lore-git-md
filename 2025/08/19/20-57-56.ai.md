This is a follow-up in the `git whatchanged` discussion thread, offering a practical workaround suggestion. The email from Randall Becker proposes using `git log` with an alias as a forward-compatible replacement for the legacy `git whatchanged` command.

The suggestion centers on creating a global alias that maps `whatchanged` to `log`, which would maintain similar functionality through `git log`'s existing flags like `--since`. This approach would let users keep their workflow while preparing for a potential future removal of `git whatchanged` from Git.

The email doesn't engage with the parallel mailing list submission issues discussed earlier in the thread, focusing solely on the technical aspect of command alternatives. It assumes `git whatchanged` might eventually be removed, though no such removal is currently proposed in Git's development. The suggestion is straightforward and non-controversial, offering a simple configuration change rather than advocating for any code changes to Git itself.

Key technical details include the specific alias configuration command (`git config --global alias.whatchanged 'log'`) and the example usage with `--since`. This maintains the thread's technical focus while sidestepping the earlier process discussion about mailing list submissions.
