This is a discussion about the strvec API conversion in the editor-related test infrastructure series. Junio C Hamano weighs in on Eric Sunshine's critique of patch 4/4, which changes the `launch_editor()` function to require a `strvec` parameter rather than a `const char*` array.

Junio agrees with Eric's assessment that the change unnecessarily constrains the API by requiring callers to use the broader `strvec` type when a simpler `const char*` array would suffice. He notes that since the parameter is `const`, the change doesn't even provide the benefit of allowing `launch_editor()` to modify the environment. 

This appears to be the final nail in the coffin for this particular API change in its current form. With both Eric's technical critique and Junio's agreement, the patch will likely need to be revised or reverted to maintain API flexibility. The discussion confirms that while the strvec conversion effort has merit, this specific implementation choice was overly restrictive without clear benefits.

The exchange shows the project's careful attention to API design principles, particularly around maintaining flexibility for callers. This feedback will likely lead to a v4 of the patch series with a revised approach to the strvec conversion.
