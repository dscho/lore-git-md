This is the first patch in a documentation series introducing automated linting for Git's man pages. It focuses specifically on validating `linkgit:` macros, which are used to cross-reference other Git commands in the documentation.

The patch does two things: it fixes an instance in `gitweb.conf.adoc` where `git-daemon[1]` wasn't properly wrapped in a `linkgit:` macro, and it adds a Perl linter (`lint-gitlink.perl`) that checks for malformed or missing `linkgit:` references. The linter will flag any Git command references (like `git-foo[1]`) that aren't properly wrapped in `linkgit:` macros or conditional blocks.

This is part of a larger effort to systematically improve documentation consistency through automated checks. The patch is straightforward and well-contained, fixing one real example while introducing a tool to catch similar issues elsewhere. It's the foundation for the subsequent patches in the series that add more sophisticated linting rules.
