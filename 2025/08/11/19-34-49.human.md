This is a technical refinement in Patrick Steinhardt's reftable/libgit2 compatibility series, specifically patch 5/6. Justin Tobler is reviewing a change that adds flag-passing capability to `reftable_stack_add()`, enabling future stack reloading when modifications occur before locking.

The patch extends the stack addition interface to accept flags that will eventually allow libgit2 to automatically reload an outdated stack. While Git's own code doesn't currently need this functionality (as it uses lower-level APIs directly), the change prepares the shared reftable codebase for libgit2's needs. The implementation passes flags through to `reftable_stack_init_addition()` while maintaining existing behavior when no flags are specified.

Justin approves the change, noting it cleanly enables the reload capability that will be useful for libgit2 integration. This appears to be a straightforward, well-contained enhancement that fits within the series' broader goal of aligning Git and libgit2's reftable handling while keeping the implementations maintainable.
