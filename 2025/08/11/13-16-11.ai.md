Bugfix for the `git-jump` contrib script's handling of filenames with spaces in diff output. This is a follow-up email in an ongoing thread discussing the v2 patch from Greg Hurrell, which improves the commit message while keeping the same code change from v1.

Phillip Wood confirms agreement with the approach in v2, specifically endorsing the decision to focus on supporting filenames containing spaces (common case) while explicitly not handling the edge cases of filenames ending with literal tabs (very uncommon). The key technical context remains that Git's diff.c appends tabs after filenames containing spaces (since 2006), while quoting filenames containing control characters like tabs, making these edge cases distinguishable.

The patch modifies a Perl regex in git-jump to optionally strip trailing tabs (`(.*?)\t?$`), solving the space-containing filename case while remaining simple. The improved commit message now includes concrete examples of Git's filename quoting behavior and clarifies that quoted paths weren't previously supported in git-jump anyway. The discussion has converged on this as the right tradeoff between complexity and practical needs, with Junio Hamano also weighing in favor of the simpler solution.

This email represents final approval from a key reviewer (Phillip Wood) for the v2 patch, suggesting it's likely to proceed to inclusion. The thread demonstrates careful consideration of edge cases while prioritizing real-world usability, with clear documentation of the technical constraints and design decisions in the commit message.
