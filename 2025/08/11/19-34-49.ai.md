This is a technical refinement in Patrick Steinhardt's reftable/libgit2 compatibility series, specifically addressing stack handling flags. The patch adds a `flags` parameter to `reftable_stack_add()` to allow passing through creation flags, particularly the `REFTABLE_STACK_NEW_ADDITION_RELOAD` flag that libgit2 will use for automatic stack reloading when modifications are detected before locking.

The changes are straightforward plumbing through the stack addition machinery: the new parameter is added to the function signature in reftable-stack.h and propagated through to `stack_try_add()` and `reftable_stack_init_addition()`. The commit message explains this is currently unused by Git itself, which typically calls `reftable_stack_new_addition()` directly when needed.

Justin Tobler's review confirms the technical soundness of the change, noting how it enables the reload behavior for libgit2 while maintaining Git's existing patterns. This patch represents one of the concrete technical improvements in the series that can proceed independently of the broader architectural discussion about compatibility layers between Git and libgit2.
