This is the third patch in a 6-part documentation series introducing automated linting tools for Git's man pages. The patch adds a new linter (`lint-documentation-style.perl`) that enforces single-term entries in definition lists (option descriptions) to simplify automated translation and address portability issues in `generate-configlist.sh`.

The 24-line Perl script detects and reports cases where multiple terms appear in a single definition list item (e.g., `-a, --all::`), requiring them to be split into separate entries. The patch demonstrates this by fixing 4 files: `git-check-attr.adoc`, `git-check-ignore.adoc`, `git-http-fetch.adoc`, and `api-path-walk.adoc`. The changes involve splitting combined option definitions (like `-a, --all::` into separate `-a::` and `--all::` entries) and fixing spacing.

The linter integrates into the documentation build system via additions to `Documentation/Makefile` and `shared.mak`, with quiet output handling matching the existing lint infrastructure. Collin Funk has reviewed the technical implementation, which specifically addresses newline handling in `sed` rather than carriage returns. A portability issue in `generate-configlist.sh` affecting definition list handling was identified by Ramsay Jones and will be addressed in a future reroll.

This patch builds on the series' goal of establishing systematic documentation quality control through automated checks, with particular attention to translation needs. The linter complements the broader documentation standardization effort while maintaining compatibility with parallel work like Jean-Noël Avila's synopsis conversion.
