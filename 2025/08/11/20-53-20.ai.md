This is the final patch in a 6-part documentation series introducing automated linting for Git's man pages. It adds backtick-wrapping enforcement to `lint-documentation-style.perl` to ensure consistent formatting of option names in synopsis-style documentation.

The 6-line addition to the linter checks for definition list items (marked with `::` or `;;`) in files using the `[synopsis]` style, requiring option names to be wrapped in backticks. This catches cases where options like `--ref-format=<format>` or `<branch>` appear without proper formatting. The patch fixes two files (`git-checkout.adoc` and `git-refs.adoc`) to comply with this rule, converting unadorned option names to backtick-wrapped versions (e.g., changing "migrate::" to "`migrate`::").

The changes are straightforward mechanical conversions, with special handling for parameter references (like `<branch>`) and `--[no-]` options that were already addressed in earlier patches. This completes the series' goal of enforcing consistent documentation style through automated checks, specifically targeting the transition to synopsis-style formatting that Jean-Noël Avila has been leading. The linter now covers linkgit macros, section formatting, definition lists, `--[no-]` options, and synopsis backtick requirements.
