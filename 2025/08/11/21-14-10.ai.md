This is a discussion about the behavior of `git clone -c` with submodules, continuing the thread about whether the current behavior is a bug or expected.

D. Ben Knoble argues that the current behavior where `-c` configurations aren't propagated to submodules when placed after `clone` (but are when placed before) is not actually a bug, but rather reflects two distinct uses of `-c` in Git's command-line syntax. They cite documentation showing that `git -c` (before the command) passes configuration to the command itself, while `git clone -c` sets configuration in the newly created repository.

The email suggests that while the behavior might be confusing, it's technically correct according to the documentation. However, they note that the `git clone` man page's caveats about certain configurations not taking effect immediately might warrant adding `url.<name>.insteadOf` to that list, since it's particularly relevant for authentication scenarios.

This moves the discussion from "is this a bug?" to "should the documentation be clarified or behavior changed?" regarding configuration passing in submodule clones. The technical distinction between command-level and repository-level configuration passing remains central to understanding the issue.
