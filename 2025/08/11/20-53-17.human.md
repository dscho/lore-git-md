This is the third patch in a documentation series introducing automated linting tools for Git's man pages. The patch adds a new Perl linter (`lint-documentation-style.perl`) that enforces a style rule for definition lists in documentation: each entry should contain only one term rather than multiple comma-separated options. This change helps with automated translation workflows, as individual terms can be marked as non-translatable more easily.

The patch modifies four documentation files to split up combined option definitions (e.g., changing `-a, --all::` into separate `-a::` and `--all::` entries). The linter will catch violations of this rule going forward. The change also addresses a portability issue in `generate-configlist.sh` that made it unable to properly format multiple terms in a single definition list entry.

The patch has already received a Reviewed-by from Collin Funk and appears to be part of a well-organized effort to systematically improve documentation consistency through automated checks. This particular change focuses on making the docs more translation-friendly while maintaining clarity.
