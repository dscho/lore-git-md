This is a bugfix for the `git-jump` contrib script, specifically addressing its handling of filenames containing spaces in diff output. The patch is version 2 of a fix that has already seen positive review from key contributors.

The core issue stems from Git's diff output behavior dating back to 2006, where filenames containing spaces get a trailing tab appended. This caused `git-jump` to incorrectly process these filenames when opening them in Vim's quickfix mode. The solution uses a simple Perl regex to strip these trailing tabs while intentionally not handling the rare case of filenames that legitimately end with tabs (which Git would quote in the output anyway).

The discussion has reached consensus that this is the right tradeoff - supporting the common case of spaces in filenames while accepting that literal tab-terminated filenames remain unsupported. Phillip Wood has explicitly endorsed this approach, and Junio Hamano has indicated agreement with prioritizing simplicity for the common case.

The v2 patch maintains the same code change but improves the commit message with clearer examples of Git's filename quoting behavior and better documentation of the supported/unsupported cases. The patch appears ready for inclusion, having addressed all substantive technical concerns.
