This is part 2 of a 6-patch documentation series introducing automated linting for Git's man pages. The patch adds a new linter (`lint-delimited-sections.perl`) that enforces proper formatting of AsciiDoc delimited sections (those marked with `---` or `...` lines).

The linter checks three key requirements: (1) delimited sections must be preceded by an empty line to prevent malformed output in translations, (2) section underlines must match the length exactly when used as titles, and (3) sections must be properly terminated within the same file. The patch fixes 12 documentation files where these rules weren't followed, including `git-rebase.adoc`, `gitprotocol-http.adoc`, and `gitsubmodules.adoc`.

The changes are straightforward and well-justified - the empty line requirement in particular helps prevent subtle formatting issues in translated documentation where authors can't easily verify the rendered output. The 48-line Perl script integrates cleanly into the existing documentation build system. This continues the series' pattern of small, focused linters that incrementally improve documentation consistency.
