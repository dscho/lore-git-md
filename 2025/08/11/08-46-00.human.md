This is a follow-up discussion on a merged documentation patch (1/5) in Julia Evans' series reorganizing the `git-rebase` man page. Patrick Steinhardt suggests a small refinement to better reflect modern rebase usage patterns.

The original patch (already merged) front-loaded a basic rebase example to help newcomers understand the difference between rebase and merge. Patrick observes that while transplanting commits is one common use case, interactive rebasing (editing commits without changing their base) is equally important today. He proposes updating the DESCRIPTION section's opening line to mention both modes, suggesting wording like "Edit a series of commits and optionally transplant it onto a different starting point."

This aligns with Phillip Wood's earlier suggestion (noted in the thread summary) that the section should mention interactive rebasing. Patrick extends this by proposing the NAME section should also be updated for consistency. The feedback is constructive and narrowly focused, maintaining the series' goal of making the documentation more accurate and accessible.

Since this is post-merge feedback on an already-accepted patch, it would likely be addressed either as a follow-up commit or incorporated if the series gets rerolled. The suggestion doesn't conflict with any existing changes and would further improve the documentation's technical accuracy regarding modern rebase usage.
