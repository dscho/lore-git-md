This is the final patch in a 4-part series modernizing Git's editor-related test infrastructure and APIs, focusing on converting the strvec API for editor environment handling.

The patch updates the editor subsystem to use `struct strvec` consistently for passing environment variables to external editors, bringing it in line with modern Git conventions. The change affects three editor-related functions in editor.c/h and their single caller in builtin/commit.c. The motivation traces back to historical evolution of these APIs, noting that while surrounding code moved to strvecs (starting in 2017), the editor code remained using the older const char** style.

The implementation is straightforward, changing parameter types and adjusting the one caller that passes environment variables (for GIT_INDEX_FILE). The patch maintains all existing functionality while making the code more consistent with Git's current string handling patterns. Johannes Schindelin provided guidance on the change.

As the concluding patch in a well-reviewed series that has gone through three iterations, this appears to be a clean, focused technical improvement. It completes the series' goal of modernizing editor-related code while improving test isolation and security handling in the preceding patches. The changes are minimal (10 lines changed) and focused solely on the strvec conversion aspect.
