This is the final version of a performance optimization patch enabling Bloom filters for wildcard pathspecs in revision traversal, now incorporating all reviewer feedback.

Lidong Yan's patch allows Git to use Bloom filters with certain types of wildcard pathspecs and pathspec magic signatures (top, glob, attr, --depth, literal) while explicitly excluding incompatible cases (exclude, icase). The key insight is using only the non-wildcard portion up to the last directory separator for Bloom matching, with a clear fallback to non-filtered traversal for pathspecs that are entirely wildcards.

The patch shows measurable performance gains: 18-27% faster in Git's own repository (e.g., `git log -100 -- "t/*"` goes from 23.4ms to 20.4ms) and 47-63% faster in larger repositories like LLVM (`git log -100 -- "libc/*"` improves from 26.7ms to 16.0). The implementation includes comprehensive test coverage verifying both the enabled and disabled cases.

This v5 iteration addresses final code structure feedback from Junio Hamano, particularly around error handling patterns and resource cleanup in `convert_pathspec_to_bloom_keyvec()`. The patch has gone through multiple rounds of review with all substantive technical issues resolved, and now carries Junio's sign-off. The changes are well-justified, thoroughly tested, and represent a clear performance win for common wildcard pathspec cases.
