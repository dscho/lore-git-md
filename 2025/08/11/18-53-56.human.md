This is a follow-up to the object name abbreviation bugfix, where Junio C Hamano points out an important correction to the proposed solution. The original patch aimed to fix a regression where object hash abbreviations were incorrectly limited to 20 bytes (GIT_MAX_RAWSZ) instead of 40 hex characters (GIT_MAX_HEXSZ), but Junio notes that using GIT_MAX_HEXSZ isn't quite right either - it should actually use the specific hash function's hex length (GIT_SHA1_HEXSZ for SHA-1 repositories).

The key insight here is that while the original patch correctly identified the regression from Git 2.16, its solution would break in repositories using hash algorithms with different lengths (like SHA-256). Junio indicates he'll be sending a revised version that properly accounts for the current repository's hash function.

This refinement shows the careful attention to detail needed when working with Git's hash abstraction layer. The discussion is moving toward a more robust solution that will work correctly across all supported hash algorithms, not just SHA-1.
