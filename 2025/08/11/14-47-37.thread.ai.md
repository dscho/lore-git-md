Thread identity: Bug report about `git clone -c key=value --recurse-submodules` failing to propagate `-c` configurations to submodules.

Core problem: When cloning with both `-c` (configuration) and `--recurse-submodules`, the configuration specified via `-c` is not forwarded to submodule clones, though it works when `-c` is placed before `clone` (`git -c key=value clone`). This particularly affects authentication-related configurations like `url.new.insteadOf`.

Current status: Initial bug report with reproduction case, no patch yet proposed. Workaround identified (placing `-c` before `clone`).

Key technical details:
- Submodule initialization fails to properly forward `-c` command-line arguments
- Underlying configuration passing mechanism exists (works in workaround case)
- Affects URL rewrites and other per-clone configurations

Open questions:
