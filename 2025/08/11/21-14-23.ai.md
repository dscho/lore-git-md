Documentation patch completing a series to improve git-rebase man page organization.

This final patch in Julia Evans' series restructures the internals section of git-rebase.adoc into a clearer numbered list format while maintaining all technical content. The changes include condensing commit detection explanations, removing redundant details already covered in OPTIONS, and moving ORIG_HEAD discussion into a NOTE block. The patch removes 43 lines while adding 23, primarily converting prose to bullet points.

Junio Hamano provides review comments suggesting further refinements to the presentation. He questions whether labeling this as a "detailed description" sets wrong expectations, since some implementation details are still simplified. He notes the steps could better reflect the actual code flow (like combining steps 1-2) and suggests maintaining consistent command references (using either `git checkout` or `git switch` throughout).

The changes follow the series' pattern of improving documentation structure without adding new information. Earlier patches had already relocated the `--onto` explanation and consolidated conflict resolution instructions. This completes the reorganization by making the internals section more approachable through step-by-step formatting while preserving technical accuracy.

Key technical points in the new structure:
- Explicit 5-step breakdown of rebase operations
- Removal of redundant explanations for `--fork-point` and `--root`
- Consolidated commit detection into single bullet point
- ORIG_HEAD discussion moved to NOTE block
- Maintained all cross-references to other sections

The series has now addressed all prior feedback and appears ready for finalization, with this patch representing the last planned structural improvements to the rebase documentation.
