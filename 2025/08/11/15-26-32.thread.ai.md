This is a bugfix patch addressing object name abbreviation in Git, correcting a regression introduced in Git 2.16 where the abbreviation length for disambiguating object hashes was incorrectly limited to GIT_MAX_RAWSZ (20 bytes for SHA-1) instead of GIT_MAX_HEXSZ (40 hex characters). The change restores pre-2.16 behavior where abbreviations could extend up to the full hex length when needed for disambiguation.

Key technical details:
- Modifies object-name.c to compare against GIT_MAX_HEXSZ instead of GIT_MAX_RAWSZ in find_unique_abbrev()
- Fixes cases where objects sharing more than half their hash length (e.g., 10 bytes for SHA-1) weren't properly disambiguated
- Reverts behavior to match Git 2.15 and earlier versions
- Test coverage is noted as impractical due to difficulty creating objects with >20 character hash collisions

The patch is straightforward and well-explained, addressing a real (though rare) edge case in object disambiguation. The lack of test coverage is acknowledged as unavoidable given the nature of the fix.
