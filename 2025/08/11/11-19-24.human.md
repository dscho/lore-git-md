Bugfix and documentation issue in git credential URL handling. 

Muhammad Fahri Muharram reports that the `git credential` command has surprising behavior when processing URL fields. The implementation clears all credential fields whenever it encounters a URL, but this behavior isn't documented, leading to inconsistent results depending on field ordering.

The bug manifests when using `git credential fill` - if the URL appears after other fields like username, those fields get wiped out, causing the command to fall back to values from `~/.gitconfig`. The email shows concrete examples where the same credential data produces different output based solely on field ordering.

This appears to be a genuine bug in the credential helper interface, where the current implementation's behavior doesn't match user expectations. The author suggests either documenting this behavior more clearly or modifying the implementation to avoid the field-clearing side effect. The patch would likely need to touch both the credential.c implementation and the gitcredentials documentation.

The issue seems straightforward to reproduce and the impact is clear - it affects anyone using `git credential` with URLs in a non-standard order. The suggested solutions (documentation vs implementation change) would both be reasonable approaches, though an implementation fix might be preferable to avoid surprising behavior.
