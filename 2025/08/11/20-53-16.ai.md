Documentation patch adding a linter for AsciiDoc delimited sections. This is patch 2/6 in a series introducing automated documentation linting tools.

The patch adds a 48-line Perl script (`lint-delimited-sections.perl`) that enforces three formatting rules for delimited sections (marked with `---` or `...` lines):
1. Requires empty lines before delimited sections to prevent accidental title generation in translations
2. Verifies section underlines match the title length
3. Ensures sections are properly terminated within the same file

The linter is integrated into the documentation build system via `Documentation/Makefile` and `shared.mak`. It fixes 12 files where these rules were violated, including `git-rebase.adoc`, `gitprotocol-http.adoc`, and `gitsubmodules.adoc`. The changes are mostly adding empty lines before sections and fixing underline lengths.

The motivation explains that while the original authors can manually catch formatting issues in English docs, translations need automated checks since translators can't easily verify the rendered output. This complements the series' goal of establishing systematic documentation quality control through focused linters.

Key technical details:
- The linter tracks section state with `$in_section` and `$section_header` variables
- It skips special lines like `[attributes]` and `ifdef::` directives
- Reports errors via the `report()` function with file/line context
- Integrated into the existing `lint-docs` target hierarchy

The patch follows the series pattern of small, focused linters (this one is 48 lines) with corresponding documentation fixes. It addresses a specific class of formatting issues that could cause rendering problems, particularly in translated documentation.
