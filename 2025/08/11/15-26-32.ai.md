This is a bugfix patch addressing an issue with object name abbreviation in Git. The change corrects a regression introduced in Git 2.16 where the abbreviation length for disambiguating object hashes was incorrectly limited to GIT_MAX_RAWSZ (20 bytes for SHA-1) instead of GIT_MAX_HEXSZ (40 hex characters).

The patch explains that when two objects share more than half their hash length (e.g., 10 bytes for SHA-1), the current abbreviation code fails to properly disambiguate them. The fix restores the pre-2.16 behavior where abbreviations could extend up to the full hex length of the hash (40 characters for SHA-1) when needed for disambiguation.

Key technical details:
- Changes the comparison in object-name.c from GIT_MAX_RAWSZ to GIT_MAX_HEXSZ
- Affects the find_unique_abbrev() function's disambiguation logic
- Reverts behavior to match Git 2.15 and earlier versions
- The author notes testing would be difficult since it would need objects with >20 character hash collisions

The patch is straightforward and well-explained, though the lack of test coverage is noted as intentional due to the impracticality of creating test cases with sufficiently colliding hashes. This appears to be a legitimate fix for a real (though likely rare) edge case in object disambiguation.
