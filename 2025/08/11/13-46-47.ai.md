This is part 7/10 of Patrick Steinhardt's ODB source system integration series, focusing on MIDX (multi-pack-index) loading changes. The patch refactors MIDX loading to work through object source pointers rather than separate repository and object directory parameters.

Key technical changes:
- Replaces `load_multi_pack_index()` and related functions to take a `struct odb_source*` instead of `repository*` + `object_dir` + `local` parameters
- Updates MIDX test helper and `git-multi-pack-index` to handle user-provided object directories by adding them as in-memory alternates
- Modifies verification logic in `verify_midx_file()` to work with the new source-based interface
- Touches midx.c, midx.h, builtin/multi-pack-index.c, and test infrastructure

The changes address several issues:
1. Eliminates redundant parameter passing (object dir and locality info already exist in the source)
2. Enables future MIDX deduplication by storing source pointers
3. Moves toward pluggable object backends by making MIDX handling source-aware

The patch maintains existing behavior while cleaning up the interface. It follows the series' theme of making ODB relationships more explicit. The test changes show the new approach handles edge cases like alternate object directories correctly.

This continues the series' steady progress with MIDX changes now approved by Taylor Blau and Karthik Nayak. The main remaining question (handling user-provided object dirs) is addressed here by treating them as in-memory alternates.
