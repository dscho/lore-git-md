This is a bugfix patch in Patrick Steinhardt's reftable/libgit2 compatibility series, addressing error handling during stack compaction. The patch clarifies and fixes how outdated stack conditions are reported when compacting reftable stacks.

The key change is properly distinguishing between general errors (negative values) and the specific case of an outdated stack (positive value) in `stack_uptodate()`. The patch ensures `REFTABLE_OUTDATED_ERROR` is properly propagated when compaction detects concurrent modifications, rather than letting positive values leak to callers. The changes affect `reftable_addition_commit()` and `stack_compact_range()` in stack.c, treating outdated stacks as a non-fatal condition during auto-compaction while maintaining proper error reporting for other cases.

Justin Tobler reviews the change positively, though he suggests an alternative approach where `stack_uptodate()` could directly return `REFTABLE_OUTDATED_ERROR` rather than having callers map the positive return value. The current implementation maintains consistency with existing error checking patterns while solving the immediate issue of proper error propagation.

This patch represents one of the final technical refinements in the v2 series, following earlier structural cleanups and flag additions for libgit2 integration. The changes are narrowly focused on error handling correctness without venturing into the broader architectural questions about Git/libgit2 compatibility that remain under discussion in the thread.
