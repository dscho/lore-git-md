Bugfix for the `git-jump` contrib script, now in its second iteration. The patch addresses how the script processes filenames containing spaces in diff output, where Git has historically appended a tab character after such filenames (e.g., "foo bar.txt\t"). The fix uses a simple Perl regex modification to strip trailing tabs, solving the common case while intentionally not handling the rare edge case of filenames that legitimately end with tabs.

Phillip Wood confirms the approach is reasonable in this reply, agreeing with Greg Hurrell's assessment that supporting filenames-with-spaces (case 2) is the practical priority, while quoted paths containing tabs (cases 3-4) can remain unsupported unless someone specifically requests them. The v2 patch maintains the same one-line code change from v1 but improves the commit message with clearer examples of Git's filename handling behavior.

This appears to be a well-considered solution to a real usability issue, with the tradeoffs clearly documented. The discussion has reached consensus that the simple regex fix is preferable to more complex parsing approaches for this contrib script's use case. The patch seems ready for inclusion.
