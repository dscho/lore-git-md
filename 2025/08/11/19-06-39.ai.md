- Updates extend_abbrev_len() to use max_len instead of GIT_MAX_RAWSZ
- Passes hexsz from repo_find_unique_abbrev_r() to initialize max_len
- Improves the logic for determining when to extend the abbreviation length

The implementation now correctly handles both SHA-1 and SHA-256 repositories, addressing the core issue where the previous version was limited by fixed constants rather than the actual hash algorithm in use.
