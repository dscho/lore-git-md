This is patch 4/10 in Patrick Steinhardt's series to integrate the ODB source system, focusing on making alternate object database handling more explicit. The patch modifies `odb_add_to_alternates_memory()` to return the newly created `odb_source` structure rather than being void-returning. This change prepares for future code that will need to reference the newly added alternate source. The implementation remains functionally the same but now provides callers access to the source pointer.

The change is straightforward - converting the function signature and adjusting the internal `link_alt_odb_entry()` helper to propagate the source pointer up through the call chain. The commit message explains this is groundwork for a subsequent change that will need the source pointer, though that use isn't visible in this patch itself.

This continues the series' pattern of making object database interactions more explicit while maintaining backward compatibility. The change has already received positive review from Taylor Blau and Karthik Nayak, suggesting it's a non-controversial improvement to the API.
