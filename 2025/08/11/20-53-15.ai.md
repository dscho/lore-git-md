This is the first patch in a 6-part documentation series introducing automated linting for Git's man pages. The patch establishes core linting for `linkgit:` macros, which are used to reference other Git commands in the documentation.

The patch adds a Perl linter (`lint-gitlink.perl`) that checks for malformed or missing `linkgit:` macros when referencing Git commands. It detects cases where command references appear without the proper `linkgit:` prefix (like the fixed `git-daemon[1]` reference in `gitweb.conf.adoc`) and reports them as errors. The linter also verifies the command name spelling and section number format.

The implementation scans each line for command references in square brackets (e.g., `git-daemon[1]`) and checks that they are properly prefixed with `linkgit:`. It handles edge cases by excluding certain AsciiDoc directives (`ifdef::`, `endif::`) from the check. The patch demonstrates the linter by fixing one instance in `gitweb.conf.adoc` where `git-daemon[1]` was not properly wrapped in a `linkgit:` macro.

This is part of a broader effort to systematically enforce consistent documentation formatting through automated checks. The linter will catch common issues that have been reported by readers, such as missing or misspelled command references. The patch is relatively small (7 lines of Perl code plus one documentation fix) and focuses specifically on linkgit macro validation, leaving other documentation style issues for subsequent patches in the series.
