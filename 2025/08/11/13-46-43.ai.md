Refactoring patch in Patrick Steinhardt's ODB source system integration series (v3, 3/10). This patch standardizes parameter naming and simplifies string handling in the alternate object database code.

The changes focus on making the code more consistent by:
1. Renaming all parameters for alternate object directory paths from "reference" or "entry" to consistently use "dir" throughout odb.c
2. Modifying `link_alt_odb_entry()` to take a plain C string instead of a `struct strbuf`, since it only needs the path string
3. Updating all callers to use the new parameter name and string type

The patch follows Taylor Blau's suggestion and maintains the same functionality while improving code consistency. It touches only odb.c, with straightforward mechanical changes to parameter names and string handling. This is part of the larger effort to standardize the object database interface and remove implicit assumptions about object storage.

The changes are purely internal refactoring with no behavior changes, keeping with the series' pattern of making implicit behaviors more explicit. The patch has already received positive review from Taylor Blau and Karthik Nayak earlier in the thread.
