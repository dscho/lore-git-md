Documentation patch enforcing consistent formatting for `--[no-]` options in man pages. This is part 4 of a 6-patch series introducing automated linting tools for Git's documentation.

The patch adds a check to ensure that command-line parameters expressed as `--[no-]parameter` are split into separate `--parameter` and `--no-parameter` entries in the documentation. The rationale is that this improves searchability, as users may search for either the positive or negative form. The change affects 36 documentation files across core commands and auxiliary documentation, with the linter itself getting a 3-line addition to detect the unwanted format.

This continues the series' systematic approach to documentation consistency, following earlier patches that handled linkgit macros, section formatting, and definition lists. The changes are mechanical but thorough, touching commands from `git-blame` to `git-worktree`. The patch has been reviewed by Collin Funk and addresses portability concerns raised by Ramsay Jones regarding newline handling in definition lists.

The series is being shepherded by Jean-Noël Avila and will be merged by Junio C Hamano after resolving conflicts with in-flight topics. This particular patch demonstrates the value of the linting approach by catching and fixing a documentation pattern that, while not incorrect, could hinder user experience when searching for command options.
