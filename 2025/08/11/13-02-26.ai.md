Documentation patch follow-up discussing merge conflict resolution details in `git-rebase` man page.

Phillip Wood agrees with Patrick Steinhardt's earlier assessment that removing the mention of `.git/rebase-apply` from the merge conflict resolution section is a positive change. He provides additional technical context that this path only exists when using the apply backend (which is not the default), making the original reference potentially confusing. The default state directory is `.git/rebase-merge` for the merge backend.

This email reinforces the thread's goal of removing implementation details from user-facing documentation while maintaining all the essential conflict resolution options (continue/skip/abort). The discussion shows maintainers validating the patch's design decision to hide backend-specific implementation details from users, with Phillip adding technical precision about the current default backend behavior. No new changes are proposed - this is post-merge validation of an already-merged documentation improvement.
