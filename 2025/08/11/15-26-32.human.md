This is a bugfix patch addressing an issue with Git's abbreviation disambiguation logic. Junio Hamano identifies that when two object hashes share more than half their length (e.g., 10 bytes for SHA-1), the current code fails to properly disambiguate them due to an incorrect limit in the abbreviation extension loop.

The patch changes the limit from `GIT_MAX_RAWSZ` (the raw byte length) to `GIT_MAX_HEXSZ` (the hexadecimal character length), which was the intended behavior before a 2017 change. This allows the disambiguation algorithm to continue extending abbreviations beyond 20 characters when needed, matching Git 2.15's behavior.

The commit notes this is hard to test since it would require finding two valid objects with extremely similar hashes, and the current test infrastructure doesn't support this scenario well. The change is small (a one-line modification) but corrects a subtle edge case in object name disambiguation that could affect users with repositories containing many objects with similar prefixes.
