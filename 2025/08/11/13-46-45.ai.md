This is patch 5/10 in Patrick Steinhardt's ODB source system integration series, continuing the refactoring of object database handling. The patch simplifies the calling convention of `link_alt_odb_entry()` by removing a redundant path parameter.

The key change is eliminating the `normalized_objdir` parameter from `link_alt_odb_entry()`, which was always being passed the resolved path of the primary object database. Instead, the function now resolves this path internally using the `odb->sources->path` field. This makes the interface cleaner by reducing the number of parameters callers need to provide.

The patch affects several related functions:
- `link_alt_odb_entries()` no longer needs to maintain a `strbuf` for the resolved path
- `odb_add_to_alternates_memory()` becomes simpler by not having to resolve the path separately
- The `alt_odb_usable()` check now resolves the path internally when needed

While this does mean some paths may be resolved multiple times in loop scenarios, the commit message argues this is an acceptable tradeoff given the typically small number of alternates. The changes maintain all existing functionality while making the code more straightforward.

This continues the series' pattern of cleaning up the ODB interface, following positive reviews on earlier patches. The change is focused and mechanical, touching only odb.c with straightforward parameter removal and path resolution consolidation.
