Bugfix for the `git-jump` contrib script handling filenames with spaces in diff output. This is version 2 of the patch, with no code changes from v1 but an improved commit message that better explains the edge cases.

The patch addresses a long-standing issue where `git-jump` would incorrectly process filenames containing spaces in diff output due to Git's diff.c behavior of appending tabs after such filenames (e.g. "foo bar.txt\t"). The fix modifies the Perl regex in git-jump to optionally strip trailing tabs via `(.*?)\t?$`, solving the common case while remaining simple.

Key technical points in this revision:
1. The commit message now includes explicit examples showing how Git quotes filenames containing control characters (including tabs), making these edge cases distinguishable from space-containing filenames with appended tabs
2. Clarifies that quoted paths never worked in git-jump before, so the change isn't taking away existing functionality but rather adding support for space-containing filenames
3. Maintains the position that supporting the edge case of literal tab-terminated filenames isn't worth the complexity given their rarity

The patch remains a one-line change to the git-jump Perl script, modifying the regex pattern that parses diff output. The thread context shows this approach has been validated by multiple contributors and deemed a reasonable tradeoff between complexity and practical utility. The discussion has established that Git's quoting behavior for control characters provides additional safety net for the edge cases not explicitly handled by this change.
