This is the fourth patch in a 6-part documentation series introducing automated linting tools for Git's man pages. The patch extends the `lint-documentation-style.perl` linter to enforce splitting `--[no-]parameter` style flags into separate `--parameter` and `--no-parameter` entries for better searchability.

The change adds a 3-line check to detect and report any remaining `--[no-]` style options in definition lists. The patch updates 36 documentation files to comply with this rule, including core commands like `git-commit`, `git-push`, and `git-send-email`, as well as auxiliary documentation. Each instance is split into two separate entries while maintaining the same description text.

The patch follows the same pattern as previous linters in the series - adding focused checks with minimal code while systematically fixing existing documentation. It builds on Collin Funk's review of the technical implementation in patch 3 and will need to address Ramsay Jones' identified portability issue in the next reroll. The changes maintain compatibility with Jean-Noël Avila's parallel synopsis conversion work.

Key technical details:
- Adds regex check in `lint-documentation-style.perl` for `--[no-]` patterns
- Updates span 36 files with 159 insertions and 78 deletions
- Maintains same descriptive text while splitting options
- Follows same Makefile integration pattern as previous linters
- Part of broader documentation standardization effort
