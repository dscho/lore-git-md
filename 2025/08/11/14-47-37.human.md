This is a bug report about `git clone` behavior with submodules and configuration options. 

The issue describes how `-c key=value` options passed to `git clone` are correctly applied to the parent repository clone but not propagated to submodule clones when using `--recurse-submodules`. The reporter provides a concrete example where this matters - using URL rewrites for authentication purposes. 

They note that placing the `-c` option before the `clone` command (as `git -c key=value clone`) does work as expected, suggesting this is inconsistent behavior rather than a fundamental limitation. The bug appears to affect any configuration passed via `-c` during recursive submodule cloning.

The report is clear and provides both the problematic and working command forms, making it easy to reproduce. This seems like a legitimate bug that could affect users relying on `-c` for submodule configuration, particularly for authentication-related cases. The impact appears limited to users of recursive cloning with configuration overrides, but for those cases it could be quite disruptive.
