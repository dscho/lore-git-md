Bugfix addressing object name abbreviation length calculation, now properly handling for SHA-256 repositories.

Junio Hamano follows up on the earlier discussion about object name abbreviation with a revised solution. The patch fixes a regression where Git would incorrectly limit abbreviation length based on raw byte size (GIT_MAX_RAWSZ) rather than the full hex length of the current hash algorithm. This caused disambiguation failures when objects shared more than half their hash length.

The key change passes down the repository's hash algorithm hex length (hexsz) to use as the maximum abbreviation length, replacing the hardcoded GIT_MAX_RAWSZ check. This ensures proper behavior for both SHA-1 (40 hex chars) and SHA-256 (64 hex chars) repositories. The implementation now dynamically adjusts based on the repository's hash algorithm rather than making assumptions about hash length.

The patch appears well-considered, building on the previous discussion to provide a complete solution. It maintains the same basic algorithm but removes the SHA-1-specific assumptions that made the original version problematic for SHA-256 repositories. The change is focused and clearly explained in the commit message, which details both the problem and solution while providing historical context about when the regression was introduced.
