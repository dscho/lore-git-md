This is a follow-up discussion on a merged documentation patch (2/5 in the series) that restructured the `git-rebase` man page. The patch had already removed implementation details about `.git/rebase-apply` working files from the merge conflict section.

Phillip Wood agrees with Patrick Steinhardt's earlier approval of this implementation detail removal, noting two good reasons: (1) users shouldn't need to know about internal state directories, and (2) mentioning `.git/rebase-apply` is misleading since the default backend now uses `.git/rebase-merge`. This is a minor post-merge validation of a design decision in the documentation reorganization.

The exchange shows the maintainers' careful attention to keeping documentation focused on user needs rather than implementation details, even after patches are merged. No action is required - this is simply confirming the wisdom of the original change.
