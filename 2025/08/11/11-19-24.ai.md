This is a bug report and documentation issue regarding Git's credential handling. The report identifies a subtle but important behavior in `credential.c` where processing a `url=` field clears all existing credential fields, which isn't documented and leads to unexpected behavior depending on field ordering.

The key technical details are:
- `credential_from_url_1()` calls `credential_clear()` when processing URLs
- This means `url=` must come first in input to avoid wiping other fields
- Current behavior causes different outputs based on field order
- The example shows `username` being lost when `url=` appears after it
- The reporter suggests either documenting this requirement or changing the implementation

The bug manifests when using `git fill` with different field orderings, where username/password values can be unexpectedly cleared or overridden. The report includes clear reproduction steps showing how field ordering affects behavior, with the username being lost when it appears before the URL.

This appears to be a legitimate issue that could trip up users and credential helper implementations. The behavior is clearly unintuitive and the documentation gap should be addressed. The implementation change might be more controversial as it could affect existing credential helpers that rely on the current behavior.
