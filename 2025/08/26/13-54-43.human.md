This is a discussion about the planned removal of the legacy `git whatchanged` command. Kristoffer Haugsbakk responds to Chris Palmer's concerns about two remaining use cases for the command, confirming that equivalent functionality exists via `git log --no-merges --raw` with some minor output differences for empty commits.

The email clarifies that while the command is indeed slated for removal in Git 3.0 (with no set release date), the core functionality will remain available through `git log`. A link to the BreakingChanges documentation from Git 2.51.0 is provided as reference for the deprecation plan.

The response is technically accurate but doesn't address all of Palmer's concerns about the specific use cases, particularly regarding searching for file changes. The thread appears to be moving toward consensus that `git log` can serve as a replacement, though some details about output formatting differences remain to be worked out.
