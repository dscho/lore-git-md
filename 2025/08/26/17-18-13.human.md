Feature and performance patch for `git range-diff` that adds a configurable memory limit to prevent crashes when comparing extremely large commit ranges. 

The patch addresses a real-world problem where comparing ranges with hundreds of thousands of commits (like in Shopify's monorepo) would attempt to allocate massive memory (e.g., 260GB for 256k commits) leading to crashes or system hangs. The solution adds a `--max-memory` option with human-readable size units (defaulting to 4GB on 64-bit systems) that prevents the operation if the required n×n cost matrix would exceed the limit.

The implementation is thorough, with clear error messages showing both requested and allowed memory sizes. The commit message provides excellent context including reproduction steps, stack traces, and rationale for choosing this solution over alternatives like commit counting or streaming approaches. The patch has already received an Ack from Johannes Schindelin and references prior discussion on the mailing list.

This is a practical improvement that makes `range-diff` more robust for large repositories while maintaining its functionality for normal use cases. The defaults seem well-chosen to catch pathological cases while not interfering with typical workflows.
