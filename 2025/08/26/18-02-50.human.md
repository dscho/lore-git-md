This is a build system discussion about parallel Rust component builds, continuing the thread about synchronization approaches. Kyle Lippincott clarifies his earlier suggestion about target dependencies in response to Randall Becker's platform compatibility objection.

Kyle explains that his proposal doesn't make `libgit-rs` a required component - it would still be conditional on `INCLUDE_LIBGIT_RS`. His approach would split the current combined target into separate targets with `libgit-rs` explicitly depending on `libgit-sys`, then simplify the `all::` rule to just list `libgit-rs` (which would transitively pull in `libgit-sys`).

The key distinction from the original `.WAIT` solution is that this approach uses Make's native dependency mechanism rather than explicit synchronization directives. Kyle maintains this would work within the same conditional block while being more idiomatic for Makefiles. The discussion continues to weigh the tradeoffs between explicit synchronization versus dependency-based ordering for these optional Rust components.
