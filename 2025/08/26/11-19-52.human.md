Bugfix follow-up regarding reftable adoption for case-insensitive filesystem issues. Jeff King shares an off-list report from Dave Evans confirming that using `--ref-format=reftable` successfully resolves the "lock file exists" errors when fetching in bare clones on macOS. The test case involved problematic repositories (vectorgraphics/asymptote and ghc/ghc) that previously failed with the files backend.

The report notes one expected limitation: older tools like cgit (5 years old in this case) that link directly against Git's C code won't recognize the reftable format. King explains this is because such tools bypass Git's command-line interface and use internal APIs that predate reftable support. He suggests there might be some compatibility measures in place (like the dummy HEAD value), but full functionality can't be expected from older versions.

This email reinforces the thread's emerging consensus that reftable is the proper solution for the case-sensitivity issues, though with some transitional challenges for tools with tight Git integration. The report provides real-world validation of the technical solution while highlighting ecosystem adoption considerations.
