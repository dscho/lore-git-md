Build system fix for parallel Rust component builds. This patch addresses concurrency issues when building Git with Rust components enabled (`INCLUDE_LIBGIT_RS`), where parallel builds (`make -JN`) could trigger cargo lock warnings and linker errors due to simultaneous inner make invocations.

The solution makes `libgit-rs` depend on `libgit-sys` to enforce serial execution, while also simplifying the build recipes by using cargo's `--manifest-path` option instead of directory changes. The same dependency logic is applied to test invocations in `t/Makefile`. This appears to be a refinement of Kyle Lippincott's earlier proposal that has already gained acceptance from other contributors in the thread.

The changes are clean and focused - splitting targets while maintaining the existing conditional inclusion of Rust components. The patch represents progress in the ongoing effort to properly integrate Rust components into Git's build system while handling platform constraints. With the main build issue now addressed, Junio Hamano's question about parallel test execution remains the only outstanding point in the thread.
