This thread addresses build system fixes needed for parallel builds when Rust components (`libgit-sys` and `libgit-rs` in contrib/) are enabled via `INCLUDE_LIBGIT_RS`. The core issue involves preventing cargo lock warnings and linker errors during concurrent builds while maintaining platform compatibility where Rust isn't supported.

The discussion has evaluated three approaches: the original `.WAIT` directive between targets, Kyle Lippincott's initial dependency-based solution, and his refined version that keeps Rust components optional while properly sequencing builds. Randall Becker, who initially objected due to platform constraints, now acknowledges Lippincott's refined approach addresses his concerns by maintaining the conditional compilation guard while improving Makefile semantics through explicit target dependencies (`libgit-rs` depending on `libgit-sys`).

While technical consensus is forming around Lippincott's solution as the thread's most maintainable option, one open question remains from Junio Hamano regarding parallel test execution (`cargo test` in `t/Makefile`), which hasn't yet been incorporated into the proposed solutions. The discussion has productively narrowed to balancing build correctness against Makefile clarity, with platform compatibility requirements now satisfied by the leading proposal.
