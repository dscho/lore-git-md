This thread addressed a build system problem where parallel builds (`make -JN`) would fail when compiling Git's optional Rust components (`libgit-sys` and `libgit-rs` in contrib/) due to cargo lock warnings and linker errors from concurrent inner make invocations. The discussion evaluated solutions that needed to work across all platforms, including those where Rust components cannot be built.

Kyle Lippincott proposed the key solution that was ultimately implemented: making `libgit-rs` properly depend on `libgit-sys` in the Makefile to enforce serial execution, while using cargo's `--manifest-path` option for cleaner build recipes. The fix handles both build and test phases when `INCLUDE_LIBGIT_RS` is enabled. Randall Becker confirmed this approach addressed his platform compatibility concerns, and Junio Hamano verified it properly handled test execution serialization.

With all technical concerns resolved and the solution reviewed by multiple contributors, Junio has indicated he will apply the patch. This provides a robust fix for parallel builds with Rust components while maintaining the optional nature of Rust support across all build environments. The implementation serves as a useful reference for similar build system challenges in mixed Make/Cargo projects.
