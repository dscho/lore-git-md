This is a code review comment on the `split` subcommand implementation in Patrick Steinhardt's `git-history` RFC series. D. Ben Knoble identifies several usability issues in the interactive splitting workflow:

1. **Diff visibility**: Questions whether changes between old/new trees are only shown during hunk editing, noting that partial acceptance of changes doesn't appear in the commit template. This suggests the diff display behavior may not match user expectations for interactive splitting.

2. **Message options**: Points out a documentation mismatch - the error message references `-F` option for supplying commit text, though the command only supports `-m` according to its usage.

3. **Error recovery**: Notes that empty commit message errors force an abort rather than allowing retry, acknowledging this may be a technical limitation given the in-memory index architecture but flagging it as a UX concern previously raised.

The feedback focuses on edge cases in the interactive workflow that could confuse users, particularly around diff visibility during partial commits and error recovery paths. These are practical usability observations rather than fundamental design issues, continuing Knoble's pattern of thorough interface review in this series. The comments suggest the `split` implementation may need minor adjustments to error messaging and diff display behavior to match user expectations.
