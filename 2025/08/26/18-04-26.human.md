This is a compatibility proposal regarding Rust integration in Git. Randall Becker suggests making Rust an optional dependency, only required for commands that specifically need it, while allowing the core C-based functionality to remain available on platforms without Rust support. This mirrors Git's existing approach with other optional dependencies like Subversion or Perforce integration.

The proposal aims to maintain compatibility with platforms where Rust is difficult to port (particularly those without GCC), while still allowing new development in Rust. Becker notes this would ensure security updates remain available even for non-Rust platforms, though some newer commands might be unavailable there.

The suggestion comes from a long-time developer with experience on NonStop and UNIX systems, who appears concerned about maintaining Git's broad platform support during the Rust transition. The email doesn't propose specific implementation details, but frames this as a compatibility strategy to give platforms more time to adopt Rust support.
