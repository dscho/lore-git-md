Performance optimization for `git ls-files` sparse index handling. This is a follow-up to the initial patch that moved sparse index expansion to be conditional on encountering matching sparse directories rather than doing full expansion upfront. The author notes this addresses a specific user-reported performance case and is safely scoped to maintain existing behavior while avoiding unnecessary index operations.

The key technical detail is moving `ensure_full_index()` inside the file iteration loop, activating only when hitting sparse directory entries (without `--sparse`). The patch maintains the test coverage from t1092 that verifies correct handling of pathspecs that either (1) hit sparse directories mid-iteration or (2) filter to sparse directories directly.
