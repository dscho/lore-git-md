Thread identity: Build system fix for parallel builds with Rust components (`INCLUDE_LIBGIT_RS` enabled)

Core problem: Parallel builds (`make -JN`) of Rust components `libgit-sys` and `libgit-rs` in contrib/ can fail due to cargo lock warnings and linker errors from concurrent inner make invocations. The issue stems from Make's parallel execution model conflicting with Cargo's build system requirements.

Current status: Patch v1 proposes adding a `.WAIT` directive between the two targets to enforce serialization - `libgit-sys` must complete before `libgit-rs` starts. This is a minimal change preserving existing functionality while fixing the build race condition.

Key technical details: Modifies the Makefile in contrib/ area where Rust components reside. Targets affected are `libgit-sys` and `libgit-rs` when built with `INCLUDE_LIBGIT_RS=Y`. The solution uses Make's native `.WAIT` synchronization primitive rather than introducing external dependencies.
