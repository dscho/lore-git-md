This is part 2 of a 3-patch series removing the `core.commentChar=auto` configuration option, which has been deprecated due to unreliable behavior in various Git operations. The patch implements the warning system that will notify users when they have the deprecated setting enabled.

The change adds infrastructure to detect and warn about deprecated config settings, specifically targeting `core.commentChar=auto` and its alias `core.commentString=auto`. The warnings appear only when running commit-related commands (commit, merge, rebase, revert) and are shown just once per command invocation to avoid spamming users. When compiled with `WITH_BREAKING_CHANGES`, Git will instead error out immediately, previewing the behavior that will become standard in Git 3.0.

The implementation is thorough, with careful handling of edge cases like multiple config sources and read-only configurations. It includes tests verifying both the warning behavior and the future error behavior. The patch builds on the deprecation announcement from part 1 and sets up the framework for the final removal in part 3.

This appears to be a well-considered transition path for a breaking change that affects interactive workflows. The warning system is designed to be minimally intrusive while still ensuring users are aware of the upcoming removal. The implementation shows attention to detail with its handling of various edge cases and config scenarios.
