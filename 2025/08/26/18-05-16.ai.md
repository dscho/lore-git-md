Build system discussion on Rust component parallel builds continues with platform compatibility focus.

Randall Becker (rsbecker@nexbridge.com) responds to Kyle Lippincott's refined proposal for handling Rust component builds in the Git Makefile. The exchange clarifies that Lippincott's suggestion maintains the `INCLUDE_LIBGIT_RS` conditional while restructuring target dependencies - having `libgit-rs` depend on `libgit-sys` rather than using `.WAIT` between parallel targets. Becker acknowledges this approach addresses his earlier platform compatibility concerns, as it keeps the Rust components optional while improving build ordering.

The technical distinction centers on whether to use make's `.WAIT` directive (original proposal) versus explicit target dependencies (Lippincott's approach). Both solutions prevent concurrent cargo builds that cause lock warnings and linker errors, but Lippincott's version better expresses the semantic relationship between the Rust components. The discussion has now established that either approach would work technically, with the choice coming down to Makefile semantics and maintainability preferences.

This email marks a point of agreement in the thread, with Becker accepting that Lippincott's dependency-based solution satisfies the platform constraints that motivated his initial objection. The exchange leaves open Junio Hamano's earlier question about parallel test execution, which remains unaddressed in the current proposals. The thread appears to be converging on Lippincott's approach as the preferred solution, pending any new concerns about the test suite implications.
