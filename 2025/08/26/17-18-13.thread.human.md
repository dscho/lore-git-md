This thread addresses memory exhaustion issues in `git range-diff` when comparing very large commit ranges (250,000+ commits). The series introduces configurable memory limits to prevent excessive memory usage during the n×n cost matrix calculation, with clear error messaging for exceeded limits. The core functionality (patch 2/2) has Johannes Schindelin's Acked-by and appears ready for merging.

A preparatory cleanup patch (1/2) that reordered command-line flags alphabetically had already been split out per earlier feedback and was thought to be uncontroversial. However, Junio Hamano has now raised concerns that the purely mechanical sorting breaks logical grouping of related options (like left/right-only pairs), which helps users understand the command's structure. He suggests that any reorganization should instead add clear section headers in the help output rather than enforce strict ordering. This may require the author (Paulo Casaretto) to either justify the current approach or revise the patch.

The core memory limit functionality remains unaffected by this discussion. The series is at version 2, with all prior feedback on the main feature addressed. The only open question now is how to handle the option reorganization, which may be revised or dropped based on further discussion.
