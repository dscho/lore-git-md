This thread introduces a performance and safety patch for `git range-diff` that prevents memory exhaustion when comparing extremely large commit ranges (250,000+ commits). The core issue stems from the n×n cost matrix allocation, which could attempt to use hundreds of GB of memory in such cases.

The solution adds a configurable `--max-memory` option with sensible defaults (4GB on 64-bit systems, 2GB on 32-bit) and clear error messages when limits are exceeded. The patch carefully checks matrix size requirements before allocation and includes thorough analysis of the problem, drawing from real-world experience in Shopify's monorepo. Johannes Schindelin has reviewed and acked the changes, which affect three call sites across the codebase. The implementation appears well-considered, with human-readable error reporting and proper handling of edge cases.
