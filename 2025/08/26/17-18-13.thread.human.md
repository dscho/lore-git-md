This thread addresses memory exhaustion issues in `git range-diff` when comparing very large commit ranges (250,000+ commits), introducing configurable memory limits to prevent excessive allocations. The core technical solution (v2) has been Acked-by Johannes Schindelin, with minor wording improvements suggested by Elijah Newren for the error messages.

The discussion has now shifted to the first patch in the series, which mechanically reordering command-line options alphabetically. Junio Hamano and Elijah Newren both object to breaking logical groupings of related options (like `--left-only`/`--right-only`), though they differ slightly in their preferred solutions. Newren suggests a hybrid approach: grouping related options first, then alphabetizing within groups, which aligns with Junio's earlier idea of using section headers. The author Paulo Casaretto will need to revise this patch to preserve logical groupings while still improving organization.

The memory limit implementation itself remains uncontested and ready for merging once this UI consideration is resolved. The thread highlights an ongoing tension in Git's CLI design between strict alphabetical ordering and semantic grouping of related options.
