Phillip clarified that while this is planned for Git 3.0, it hasn't yet been formally documented in BreakingChanges.adoc. His patches propose a two-stage fallback in `remote.c` (trying "main" first, then "master"). Jeff King provided crucial context that modern Git versions handle default branch detection through protocol features, making the fallback primarily relevant for very old servers where "master" remains the better guess. 

The discussion confirms the fallback mechanism is needed only for legacy cases, with Phillip acknowledging Jeff's analysis that protocol v0/v2 symref handling means the `remote.c` code only activates for ancient servers. This narrows the scope of where the fallback is actually needed, potentially simplifying the changes.
