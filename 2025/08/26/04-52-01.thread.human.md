This thread discusses changing Git's default branch name from 'master' to 'main' in core code locations while maintaining backward compatibility through `init.defaultBranch`. The change would touch `refs.c`, `remote.c`, and test infrastructure, and is being considered for Git 3.0. Phillip Wood initially thought this was already documented for 3.0 but corrected that misstatement while still advocating for that release target.

Technical discussion has focused on the fallback behavior in `remote.c` when dealing with older Git versions. Phillip proposed a two-stage fallback (checking "main" first, then "master"), while Jeff King provided protocol-level context showing this primarily affects legacy cases. The group is now weighing whether the two-stage fallback remains necessary given how rarely the legacy cases occur. Andreas Schwab previously noted an outdated comment in `remote.c` that would need updating.

The thread remains active with open questions about timing (whether to make the change in 3.0 or later) and implementation details (particularly around fallback behavior). Phillip appears to be coordinating this as part of broader Git 3.0 changes, though the exact scope and schedule are still being discussed.
