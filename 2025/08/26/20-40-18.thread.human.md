This thread documents the evolution of Git's `push.default=simple` behavior through both documentation improvements and implementation history. Julia Evans initiated the discussion with a patch series refining the `git-push` man page, which was merged after thorough review. The documentation now accurately describes the intended design where `simple` mode enforces name matching constraints and requires explicit push targets.

However, post-merge analysis by Junio Hamano revealed an important divergence between design and implementation. Tracing back to a 2013 change (commit ed2b18292b), the actual behavior has become more permissive - allowing pushes to same-named branches without upstream configuration in many common scenarios. Junio notes this behavior is now effectively entrenched due to a decade of user expectations, making it impractical to revert to the original stricter design.

The documentation currently reflects the intended constraints, but the discussion suggests future updates may need to better account for the real-world behavior where upstream configuration is only strictly required when explicitly set to an incompatible branch. This thread serves as both a case study in careful documentation refinement and a reminder of how implementation details can subtly drift from original designs over time.
