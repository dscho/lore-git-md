This thread documents the evolution in understanding and explaining Git's `push.default=simple` behavior, which has diverged from its original 2012 design. The discussion was sparked by Julia Evans' documentation series (v4, now merged) that clarified how the current implementation allows same-name pushes without upstream configuration in some cases, while still enforcing it for special remotes.

The merged documentation includes technical explanations, usage examples, and push precedence rules, with contributions from Jean-Noël Avila on formatting and D. Ben Knoble on syntax corrections. Junio Hamano approved the series while noting the current behavior has become the de facto standard.

In the latest exchange, Julia responds to Junio's concern that mentioning `git branch --track` alongside `git push --set-upstream` might confuse beginners. She shares her own difficulty understanding `--track`'s usage pattern, particularly for setting up new upstream branches, and considers removing it from the introductory documentation if its behavior can't be clearly explained. This continues the thread's focus on making upstream branch configuration instructions both accurate and accessible to new users.
