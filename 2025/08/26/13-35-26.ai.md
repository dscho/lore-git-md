This is the first patch in a three-part series deprecating and removing the `core.commentChar=auto` configuration option, a breaking change targeting interactive commit/rebase workflows. The patch lays out the technical rationale for removal, documenting several scenarios where the auto-selection heuristic fails: commit templates with comments, prepare-commit-msg hooks, rebase fixup/squash operations, and git notes. These limitations stem from architectural constraints in how Git components coordinate comment character selection.

The implementation introduces conditional compilation via `WITH_BREAKING_CHANGES` to maintain dual behavior during the deprecation period. Documentation updates in BreakingChanges.adoc and config/core.adoc explicitly list the failure scenarios and outline the deprecation timeline (warning until Git 3.0, then error). The code is modified to conditionally compile the auto-selection logic, with tests marked to skip when `WITH_BREAKING_CHANGES` is enabled.

Key technical details include:
- New documentation of specific incompatibilities in config/core.adoc
- Conditional compilation guards around `auto_comment_line_char` usage
- environment.c changes to handle the deprecation
- Test updates in t3404, t3418, and t7502 to respect the breaking changes flag
- The patch establishes a pattern for future config deprecations via `check_deprecated_config`

The commit message acknowledges the feature's original purpose (avoiding commented lines when amending commits) but concludes the architectural limitations outweigh the benefits. It leaves open the possibility of reinstating the feature if someone provides a comprehensive fix. The implementation shows careful attention to backward compatibility during the deprecation period while clearly signaling the eventual removal.
