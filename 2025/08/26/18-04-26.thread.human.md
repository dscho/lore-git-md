Randall Becker has proposed a new approach to integrating Rust into Git that would make it an optional dependency rather than a hard requirement. The key idea is that only commands actually using Rust code would need the Rust toolchain, while core functionality could still be built in pure C for platforms where Rust isn't available - particularly those without GCC support, like NonStop systems where Becker has expertise.

The proposal draws parallels with Git's existing handling of optional integrations like Perforce or Subversion support, suggesting this would allow gradual Rust adoption while maintaining compatibility for slower-moving platforms. Security maintenance appears to be a driving concern, with Becker noting this approach would ensure security fixes remain available even to non-Rust builds.

This starts a fresh discussion thread about Rust adoption strategy, separate from ongoing technical work on Rustification. The email doesn't propose specific implementation details but rather frames a policy question about how to balance modernization with platform compatibility, coming from someone with deep experience in Unix and NonStop system development.
