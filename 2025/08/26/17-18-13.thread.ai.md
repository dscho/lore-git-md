Thread identity: Performance and safety patch series for `git range-diff` addressing memory exhaustion issues when comparing very large commit ranges (250,000+ commits), with a configurable memory limit for the cost matrix calculation to prevent integer overflow and excessive memory usage.

Core problem: The n×n cost matrix allocation in `range-diff` can attempt to use hundreds of GB of memory for extremely large commit ranges (e.g. 260GB for 256,783 commits), causing memory exhaustion. The solution introduces memory limits with clear error messaging.

Current status: Version 2 complete with both cleanup and feature patches. First commit (mechanical option reordering) faces maintainer pushback regarding option organization. Second commit implementing core memory limit functionality remains solid with Acked-by from Johannes Schindelin, now with minor wording improvements suggested by Elijah Newren.

Key technical details:
- New `max_memory` field in `struct range_diff_options`
- Memory size parsing via `parse_max_memory()` callback accepting human-readable sizes (e.g. "1G", "500M")
- Human-readable error messages using `strbuf_humanise_bytes()`, now to be reworded from "X bytes available" to "X bytes limited to" per Newren's suggestion
- Default limits: 4GB (64-bit) and 2GB (32-bit) via `RANGE_DIFF_MAX_MEMORY_DEFAULT` macro
- Checks in `get_correspondences()` before matrix allocation
- Affects three call sites: builtin/log.c, builtin/range-diff.c, log-tree.c
- First commit's lexicographic option ordering now contested for breaking logical groupings
