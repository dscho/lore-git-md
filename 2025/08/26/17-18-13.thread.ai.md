Thread identity: Performance and safety patch for `git range-diff` addressing memory exhaustion issues when comparing very large commit ranges (250,000+ commits), with a configurable memory limit for the cost matrix calculation to prevent integer overflow and excessive memory allocation.

Core problem: The n×n cost matrix allocation in `range-diff` can attempt to use hundreds of GB of memory for extremely large commit ranges, causing memory exhaustion. The patch introduces a memory limit solution with clear error messaging.

Current status: Patch version 1, with Acked-by from Johannes Schindelin, now under review by Junio Hamano who suggests splitting into two commits for cleanliness. Core technical solution remains approved while patch organization needs improvement.

Key technical details:
- New `max_memory` field in `struct range_diff_options`
- Memory size parsing via new `parse_max_memory()` callback
- Human-readable error messages using `strbuf_humanise_bytes()`
- Check occurs in `get_correspondences()` before matrix allocation
- Affects three call sites: builtin/log.c, builtin/range-diff.c, and log-tree.c
- Junio identifies style issues: unnecessary whitespace changes, unexplained indentation tweaks, mixed option reordering

Open questions: Whether to split into preparatory cleanup + feature commits as Junio suggests. No new technical concerns raised about the memory limit mechanism itself.
