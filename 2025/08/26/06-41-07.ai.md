Feature patch adding `git refs exists` subcommand as part of refs command consolidation effort. This is the first patch in a 4-part series that has gone through multiple revisions (now at v3) as part of Meet Soni's GSoC project.

The patch introduces a new `exists` subcommand to `git refs` that duplicates the functionality of `git show-ref --exists`, providing identical exit code semantics (0=exists, 2=missing, 1=error). The implementation is a straightforward ~20-line function in builtin/refs.c that uses refs_read_raw_ref() with the same error handling as show-ref. The commit message explains the deliberate choice to duplicate this small amount of logic rather than create shared infrastructure.

Documentation in git-refs.adoc clearly specifies the subcommand's behavior and exit codes. The implementation appears complete and well-tested, building on the merged `ms/refs-list` branch. All technical feedback from previous versions has been addressed, with only minor style nits remaining in the test infrastructure (handled in other patches of the series).

Key technical details for future reference:
- New subcommand implementation in builtin/refs.c (~50 lines including boilerplate)
- Uses refs_read_raw_ref() with same ENOENT/EISDIR handling as show-ref
- Exit codes documented in git-refs.adoc (0/1/2 semantics)
- Part of broader refs command consolidation effort
- Builds on Git v2.51.0 with ms/refs-list merged
- Test infrastructure (shown in other patches) uses shared setup between show-ref and refs exists tests

The patch appears ready for final review, with all substantive feedback from Patrick Steinhardt and others addressed in this v3 submission. The only remaining discussion points would be about the long-term maintenance implications of having duplicate existence-checking logic between commands.
