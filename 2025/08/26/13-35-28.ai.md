This is the final patch in a three-part series removing the `core.commentChar=auto` configuration option. The patch implements user-facing advice that appears when Git encounters the deprecated setting, guiding users through the migration to a fixed comment character.

The implementation tracks where the auto-setting appears in config files (system, global, local, etc.) and generates customized advice based on the user's specific configuration. It handles edge cases like read-only system configs by recommending global config changes instead. The advice includes both unset commands (to revert to default #) and set commands (for custom choices), with proper scoping flags based on where the setting was found.

Key technical details:
- New `comment_char_config` struct tracks config file paths and key occurrences
- `add_config_scope_arg()` determines appropriate `--system/--global/--file` flags
- `can_unset_comment_char_config()` checks write permissions for system configs
- Advice appears both in warning mode (pre-3.0) and fatal error mode (post-3.0)
- Comprehensive test coverage in t3404 and t7502 verifies advice formatting

The patch concludes the deprecation effort with a user-friendly migration path, implementing the verbose assistance approach favored in earlier discussion. It maintains all functionality from previous iterations while adding the final advice system component.
