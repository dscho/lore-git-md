This is part 2 of a 3-patch series deprecating and removing the `core.commentChar=auto` configuration option. The patch implements the warning system for the deprecated setting, which will become a hard error in Git 3.0.

The patch adds infrastructure to detect and warn about deprecated config settings through a new `repo_read_config()` callback system. For `core.commentChar=auto`, it:
- Prints a deprecation warning when the setting is used (unless `WITH_BREAKING_CHANGES` is enabled)
- Only warns once per command invocation to avoid spamming users
- Uses an environment variable to prevent duplicate warnings in subprocesses
- Includes the config source (`core.commentChar` vs `core.commentString`) in warning messages
- Silences warnings during `git config` operations to allow users to fix the setting

The implementation touches several key areas:
- New `warn_on_auto_comment_char` flag in environment.h
- `check_deprecated_config` flag in repository struct
- Modified config reading logic in config.c with new callback system
- Integration with commit/rebase/merge/revert commands
- Test coverage in t3404 and t7502 for both warning and error cases

The patch maintains dual behavior via `WITH_BREAKING_CHANGES` compilation flag, with warnings being the default and errors when that flag is set. The warning text clearly states the deprecation timeline (removal in Git 3.0). The implementation handles edge cases like multiple config sources and read-only config files.
