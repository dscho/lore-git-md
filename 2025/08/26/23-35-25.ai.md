Build system fix for parallel Rust component builds (`INCLUDE_LIBGIT_RS` enabled). This patch implements the dependency-based solution that emerged as the preferred approach in the ongoing thread about parallel build issues with Git's optional Rust components.

The patch addresses concurrent build problems that occur when using `make -JN` with Rust components enabled, where simultaneous inner `make` invocations for `libgit-sys` and `libgit-rs` would cause cargo lock warnings and linker errors. The solution makes `libgit-rs` depend on `libgit-sys` to enforce serial execution, while also simplifying the build recipes by using cargo's `--manifest-path` instead of directory changes.

Key technical changes include:
- Splitting the targets to allow explicit dependencies between Rust components
- Applying the same serialization logic to test invocations in `t/Makefile`
- Using `--manifest-path` consistently to avoid `cd` operations
- Maintaining the `INCLUDE_LIBGIT_RS` conditional guard for optional builds

This version improves upon the initial proposal by better expressing the component relationships through Makefile dependencies while addressing platform compatibility concerns. The changes align with the thread's technical direction and appear to resolve the core parallel build issue, though the separate question about parallel test execution (raised by Junio Hamano) remains as a potential follow-up consideration.
