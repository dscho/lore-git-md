This is a follow-up discussion about a build system fix for parallel Rust builds. The original patch from David Aguilar proposed adding a `.WAIT` directive to serialize the `libgit-sys` and `libgit-rs` builds when `INCLUDE_LIBGIT_RS` is enabled, addressing parallel build issues with Cargo.

Kyle Lippincott suggests an alternative approach: instead of using `.WAIT` in the `all` target, they propose making `libgit-rs` depend directly on `libgit-sys` and only listing `libgit-rs` in the `all` target. This would maintain the serialization requirement while potentially being a cleaner solution.

The discussion highlights an interesting technical point about Makefile dependencies versus explicit serialization. The thread context indicates this is part of broader Rust integration work, with Junio Hamano having previously raised questions about whether similar parallel build protections are needed for test execution. The current exchange focuses specifically on the build-time dependencies between Rust components.
