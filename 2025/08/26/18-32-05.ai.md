Feature patch adding object format reporting to `git repo info`. This is the second patch in a v2 series from GSoC contributor Lucas Seiki Oshiro, with mentor sign-offs from Karthik Nayak and Patrick Steinhardt.

The patch adds an `object.format` field to `git repo info` that exposes the repository's object storage format (SHA-1 or SHA-256), equivalent to `git rev-parse --show-object-format`. The implementation reads from `repo->hash_algo->name` and includes tests verifying correct output for both hash algorithms. Documentation is updated to describe the new field alongside existing repository metadata fields.

This follows the naming convention settled in the thread (singular `object.format` rather than `objects.format` as originally proposed). The change is straightforward - adding a new field handler in builtin/repo.c that reports the hash algorithm name, with corresponding documentation and test coverage. The patch builds on the existing `git repo info` infrastructure and aligns with Git's object format handling conventions.

The only remaining open question from the thread is the naming of the related `references.format` field, which may be renamed to better align with `extensions.refStorage`/`--ref-format` conventions. This patch doesn't address that issue but implements the agreed-upon object format reporting functionality in a clean, well-tested way.
