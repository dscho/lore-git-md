This is a status update on the `core.commentChar=auto` deprecation series, part of the ongoing effort to simplify Git's configuration handling. Phillip Wood reports sending v3 of his patch series with minor cleanups, while noting an open discussion point about warning behavior for submodule configurations. The series proposes deprecating the dynamic comment character selection feature due to its maintenance burden outweighing its utility.

The thread context shows this is one of several breaking changes being considered for Git 3.0, with Junio Hamano previously flagging it as a candidate for merging to 'next'. The current email indicates the author is waiting for user feedback before potentially refining the submodule warning behavior, suggesting this aspect may see future iteration. The series has already incorporated changes from the parallel `the_repository` removal work via a merge with ps/config-wo-the-repository.

Key technical details for future reference: affects `core.commentChar` configuration handling, specifically the "auto" mode that tries to dynamically select a comment character. The implementation adds user warnings when this deprecated mode is detected, with special consideration needed for submodule cases. The changes touch config.c and commit.c, with documentation updates in breaking-changes.txt. The open question about submodule warnings suggests this could become a discussion point in future replies.
