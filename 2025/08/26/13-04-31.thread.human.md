The thread discusses the planned removal of the legacy `git whatchanged` command in Git 3.0. Chris Palmer initially raised concerns about two remaining use cases for the command: examining recent commits and searching for changes to specific files. Kristoffer Haugsbakk has now with a concrete solution, showing that `git log --no-merges --raw` provides equivalent functionality with only minor output differences for empty commits.

The removal has been planned since Git 2.51.0, though the exact timing of Git 3.0's release remains undetermined. The discussion appears to be moving toward documenting this migration path rather than reconsidering the removal decision, as the proposed `git log` flags address both of Palmer's use cases. No maintainer position has been stated yet, but the thread seems to be converging on acceptance of this change with proper documentation of the replacement pattern.
