Performance optimization for `git ls-files` with sparse-checkout pathspecs. This is a follow-up to Derrick Stolee's patch that improves sparse index handling by avoiding unnecessary full index expansions.

Elijah Newren provides a review that initially questioned the performance benefit but confirmed it through debugging. He notes the key insight is that `prune_index()` filters index entries early when pathspecs share a common prefix, making the optimization more broadly applicable than the commit message suggests. The patch itself moves sparse directory expansion inside the iteration loop rather than doing it upfront, which avoids work when pathspecs match sparse-checkout patterns.

The review confirms the change is safe and correctly implemented, with test cases that helped verify the behavior. Newren suggests clarifying the commit message to better explain the interaction with `prune_index()` and the broader pathspec case. The optimization appears sound and narrowly focused, coming from an experienced contributor in this area.
