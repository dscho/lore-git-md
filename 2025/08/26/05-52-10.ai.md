Performance experiment exploring object flag storage via khash versus direct struct access, continuing the thread's investigation of data structure tradeoffs in Git's core.

Jeff King presents a radical experiment: moving all object flag storage from direct struct access to khash lookups, using Coccinelle to automate the codebase conversion. The results show significant performance penalties - a 25% slowdown for `merge-base` and 93% for `rev-list --objects --all`, demonstrating the cost of hash lookups versus direct flag access. The patch includes both the Coccinelle transformation rules and manual fixups for edge cases.

Key technical details:
- Introduces new `objflags` khash table and helper functions (`objflags_get/set/clear`)
- Benchmarks show 1.25x-1.93x slowdowns across operations
- Reveals special cases like `describe.c`'s direct flag assignment that needed manual handling
- Suggests commit-slabs might perform better but acknowledges diminishing returns

This experiment provides concrete data supporting the thread's emerging consensus that direct flag access remains optimal for performance-critical paths, while also demonstrating the feasibility (with caveats) of more flexible storage approaches. The results help quantify the tradeoffs discussed earlier between sparse/dense access patterns and implementation complexity.
