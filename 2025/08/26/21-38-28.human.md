Junio Hamano provides detailed feedback on Julia Evans' documentation patch for `git-checkout`'s man page. This is part of an ongoing effort to clarify the command's behavior, particularly around branch switching and detached HEAD states.

Junio questions whether simply saying "To prepare for working on <branch>" should be removed, as it helped explain what "switch to branch" means. He also points out that the phrase "changes on <branch>" could be misleading - it's really about differences between the current state and the target branch, not just changes made on that branch.

The email also corrects a misunderstanding about the "glorified no-op" description of running `git checkout` without arguments. Junio explains this was meant to contrast with doing nothing at all, not to compare with `git status` (which is actually more expensive). He suggests keeping the original intent while acknowledging the new text is otherwise an improvement.

This continues the careful back-and-forth between technical accuracy and user clarity that has characterized the thread. Junio's feedback shows attention to both precise technical meaning and how users might interpret the documentation, while still supporting the overall goal of making the man page more approachable.
