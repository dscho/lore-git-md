This is the cover letter for version 3 of a feature patch series introducing the `git refs exists` subcommand, part of Meet Soni's GSoC project to consolidate ref-related commands under the `git refs` namespace. The series is now complete with all requested changes implemented from previous reviews, including a full test infrastructure refactoring suggested by Patrick Steinhardt.

The new subcommand duplicates the functionality of `git show-ref --exists` but places it under the more logical `git refs` namespace. The implementation is clean and minimal (~20 lines of code) using `refs_read_raw_ref()` with the same error handling as show-ref. The series includes comprehensive test coverage through shared test infrastructure that validates behavior for regular refs, HEAD, symrefs, and special refs.

Documentation specifies the same exit codes as show-ref (0=exists, 2=missing, 1=error). The only remaining issues are minor style nits in test script formatting. This appears ready for final review and potential merging, though there's an open question about long-term maintenance of duplicate existence-checking logic between commands.

The v3 changes are minimal - reverting a commit message change and adding an empty line. The series builds on Git v2.51.0 with the prerequisite `ms/refs-list` branch merged. This represents a well-executed GSoC contribution that follows established patterns from Patrick's earlier refs work.
