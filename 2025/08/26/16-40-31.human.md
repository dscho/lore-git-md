This is a performance optimization patch for `git ls-files`'s handling of sparse indexes, following up on an earlier submission. The change delays expanding a sparse index until actually encountering a sparse directory that matches the given pathspec, rather than doing a full expansion upfront. This avoids unnecessary work when pathspecs match directories already covered by sparse-checkout patterns.

The patch comes from an experienced contributor (Derrick Stolee) and builds on established sparse index infrastructure. It includes test coverage in t1092 that verifies correct behavior for pathspecs hitting sparse directories both mid-iteration and when filtering to sparse directories. The implementation appears carefully considered, moving the `ensure_full_index()` call inside the iteration loop only when needed.

While the optimization is narrow in scope (affecting only `ls-files` with specific sparse index scenarios), the performance motivation is clear.
