This is a follow-up in the ongoing discussion about case-sensitivity issues with lock files in bare repositories. Jeff King shares an off-list report from Dave Evans confirming that switching to the reftable backend (`--ref-format=reftable`) resolves the "lock file exists" errors when fetching from problematic repositories like asymptote and ghc on macOS. However, Evans notes that older tools like cgit (which links directly against Git's C code) fail to recognize the reftable-formatted repository.

Key technical points:
- The reftable solution works as expected for the fetch operation itself
- The cgit incompatibility stems from its direct linking against older Git libraries that lack reftable support
- Jeff King notes reftable was designed with backward compatibility in mind (via HEAD dummy value), suggesting the cgit issue might be more severe than expected

This email reinforces the transitional challenges around reftable adoption, particularly for tools that tightly couple to Git's implementation details. While the technical solution works, ecosystem compatibility remains a practical concern. The discussion continues to highlight reftable as the correct long-term solution while acknowledging real-world migration pain points.
