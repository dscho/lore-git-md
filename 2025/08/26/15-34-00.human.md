This is a performance discussion email in the ongoing thread comparing khash and commit-slab data structures for Git's internal metadata storage. Junio Hamano responds to Jeff King's corrected benchmark results showing that commit-slabs maintain a 2-6% performance advantage over khash for topological sorting operations, particularly in large repositories like linux.git.

The conversation reinforces the emerging consensus that commit-slabs are better suited for dense access patterns where metadata is needed for most objects, while khash remains preferable for sparse access cases. Hamano provides a clear heuristic: use slab storage when you need per-object metadata for all objects being processed, and khash when you only need metadata for a subset.

The email also teases an interesting direction - Jeff King's suggestion to explore moving object flags into a hash table, which would represent a more radical architectural change from the current direct-access approach. Hamano acknowledges this could reveal even more dramatic performance tradeoffs, setting up potential future discussion about fundamental object storage design.
