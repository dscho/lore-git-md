Bugfix for fetch-pack's object existence checking during fetches. This patch addresses a race condition where Git could incorrectly report that an object is missing from the object database when it's actually present but was recently repacked. The issue occurs when checking objects that exist in the commit graph but might have moved between packs.

Jeff King explains that the current code fails to rescan the pack directory when verifying object existence, which can lead to false negatives if another process repacks objects simultaneously. The fix adds the `HAS_OBJECT_RECHECK_PACKED` flag to force a rescan in this case, as the performance impact is negligible and correctness is critical here.

The bug was originally reported by Дилян Палаузов and manifests most clearly in partial clone scenarios with multiple rapid fetches, though it could theoretically occur in any fetch operation concurrent with a repack. While difficult to reproduce reliably, the fix is straightforward and low-risk since it only affects the error-checking path. The patch modifies just one line in fetch-pack.c to add the missing flag.
