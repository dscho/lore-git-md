This is a follow-up discussion in the RFC thread for the new `git-history` command series, focusing on Jujutsu (jj) command comparisons and potential UX considerations.

Martin von Zweigbergk provides detailed comparisons between the proposed `git-history` subcommands and their Jujutsu counterparts, noting several behavioral differences that could inform future design decisions. Key points include:

1. **Drop command behavior**: Notes that `jj-abandon` automatically rebases descendants and updates branch/HEAD pointers, asking whether `git history drop` will do the same.

2. **Reorder command**: Points out the similarity to `jj rebase -r` rather than `jj-new`, though doesn't request changes.

3. **Split command**: Explains additional Jujutsu functionality like `-A/-B/-d` options for positioning split changes, beyond the basic parent/child split being implemented.

4. **Future commands**: Suggests considering Jujutsu's multi-commit message editing (`jj describe`) and revsets syntax as potential inspirations for future extensions.

The email maintains a constructive tone, providing background information rather than requesting immediate changes. It serves to ensure the Git implementation team is aware of Jujutsu's more advanced features as they plan the command's evolution. The discussion occurs after maintainer approval of the conservative initial implementation but before any major redesign work.
