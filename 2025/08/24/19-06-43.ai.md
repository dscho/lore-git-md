Code cleanup patch in the line-log optimization series, focusing on initialization safety.

This is the third patch in a 4-part series improving Git's line-log functionality (`git log -L`). The change addresses a minor code quality issue in `process_ranges_ordinary_commit()` where a local `diff_queue_struct` variable was being used uninitialized before being passed to `queue_diffs()`. While functionally harmless (the uninitialized data gets overwritten without being read), the author notes it was visually concerning during code review.

The patch simply initializes the queue with `DIFF_QUEUE_INIT` for clarity and defensive programming. This follows the series' pattern of small, focused cleanups after the initial performance optimization in patch 1. The change is minimal (1 line modified) and maintains the separation between performance-critical changes and code quality improvements established earlier in the series.

No behavior changes or performance impact - this is purely about making the code more obviously correct to human readers. The patch continues the series' trend of reducing potential confusion points while keeping the diff small and focused.
