This is a preparatory patch for the `git-history` command series, adding sequencer infrastructure to support rewinding HEAD after cherry-pick-like operations. Currently, the sequencer only rewinds HEAD for rebases, not cherry-picks, since cherry-picks typically operate directly on HEAD. The new `git-history` command will need this behavior for its history editing operations.

The patch introduces a new `restore_head_target` option in `struct replay_opts` that when set will make the sequencer reset HEAD to the specified branch after completing operations. The option is persisted in the sequencer state file so it works across processes (e.g. after resolving conflicts). The implementation uses the existing `reset_head()` machinery with `RESET_HEAD_REFS_ONLY` to avoid touching the working tree.

This is a well-contained change that clearly serves the needs of the upcoming `git-history` command while maintaining backward compatibility. The patch follows Git's coding style and includes appropriate error handling. As part of the larger RFC series, this infrastructure will enable more flexible history editing operations while reusing existing sequencer components.
