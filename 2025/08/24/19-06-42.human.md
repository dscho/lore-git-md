This is the second patch in a refactoring series for Git's line-log functionality (used by `git log -L`). It follows a performance optimization in patch 1 and focuses on code cleanup.

The change removes a dynamically allocated array of parent pointers in the merge commit processing logic, instead iterating directly through the commit's parent list. While this eliminates a memory allocation per merge commit, the author notes the performance impact is negligible - this is primarily a code simplification.

The patch modifies `process_ranges_merge_commit()` in line-log.c to work with the parent list directly rather than copying it to an array first. The diff shows careful attention to maintaining the same logic flow while reducing memory management complexity. This is a straightforward cleanup that follows the pattern seen in the series - first optimize performance (patch 1), then streamline the resulting code (patches 2-4).

As with the rest of the series, there are no user-facing changes or test updates needed since this only affects internal implementation details. The change reduces line count while preserving behavior, making the code slightly easier to maintain.
