This is a preparatory patch in the `git-history` command series, introducing a new sequencer mode for history editing operations. The patch adds `REPLAY_HISTORY_EDIT` mode to the sequencer infrastructure, which will be used by the upcoming `git-history` command.

The changes create parallel infrastructure to existing cherry-pick/revert functionality, including:
- New `HISTORY_EDIT_HEAD` ref tracking (analogous to `CHERRY_PICK_HEAD`)
- Updated advice messages pointing to `git history continue/abort`
- Modified state cleanup and detection logic
- New error messages using the generic `action_name()` helper
- Basic test scaffolding for the command

The implementation carefully mirrors existing sequencer behavior while adding the new mode, with special attention to:
- Maintaining backward compatibility
- Proper ref cleanup in all code paths
- Consistent error handling
- Clear user messaging

The patch is part of a larger effort to build history editing capabilities inspired by Jujutsu (jj), with this piece focusing on the low-level sequencer integration needed to support the higher-level commands. The changes are conservative and follow the incremental approach approved by the maintainer, though the test coverage is currently minimal (just checking command invocation fails without a subcommand).
