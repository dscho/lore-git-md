This is a technical clarification in the ongoing Meson build system integration thread, specifically addressing Karthik Nayak's question about the `wish` dependency check logic in the gitk build configuration.

Patrick Steinhardt explains that the `disable_auto_if(not wish.found())` check is necessary because the build system distinguishes between `enabled()` (explicit user request) and `allowed()` states. The check ensures proper handling when gitk is set to "auto" mode - if `wish` isn't found in this case, gitk should be automatically disabled rather than failing the build. This maintains the expected behavior where gitk only builds when both explicitly requested and its dependencies are available, or when in auto mode with all dependencies present.

The exchange highlights an implementation detail in the Meson integration that preserves the conditional build behavior from the original Makefile system. This follows the pattern seen throughout the series of carefully maintaining existing functionality while transitioning to the new build system. The technical clarification helps ensure the build system will handle edge cases correctly when users have mixed availability of Tcl/Tk tools.
