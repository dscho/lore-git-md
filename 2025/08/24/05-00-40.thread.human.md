This thread addresses a race condition in `fetch-pack` where objects that exist in the commit-graph might be incorrectly reported as missing if they were recently repacked. The issue manifests when a fetch operation runs concurrently with a repack - the initial object check may fail to see newly repacked objects, causing unnecessary fetch failures.

The proposed fix adds the `HAS_OBJECT_RECHECK_PACKED` flag to force a rescan of packfiles when an object isn't found initially. This ensures we'll properly find objects that were recently repacked. The change is minimal (just adding one flag) but effectively closes the race window. The patch includes a detailed reproduction scenario, though no automated test due to the race's flakiness.

The bug was discovered in partial clone scenarios with submodules, where rapid fetches can trigger background repacking, but could theoretically affect any fetch operation running alongside a repack. The fix maintains performance since it only affects objects we should already have (those in our commit-graph).
