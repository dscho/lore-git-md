This thread explores performance optimizations for `git describe`'s depth computation, which currently suffers from quadratic complexity due to linear scans of unflagged commits. The original proposal from René Scharfe introduced a khash-based set to track these commits more efficiently, demonstrating a 1.4x speedup in benchmarks.

Jeff King has now weighed in with an alternative approach using commit-slabs, which were specifically designed for this type of zero-cost lookup scenario. While the khash version shows a small performance advantage (1.03x faster than commit-slabs), both approaches significantly outperform the original implementation (1.31x and 1.28x speedups respectively). The discussion has broadened to consider tradeoffs between these approaches - including cache performance, memory overhead, and future flexibility - as well as potential implications for how Git manages object metadata more generally. The small performance difference suggests the decision may come down to factors beyond raw speed.
