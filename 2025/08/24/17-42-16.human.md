This is a preparatory patch in Patrick Steinhardt's RFC series introducing a new `git-history` command. It adds infrastructure to the sequencer to support a new `REPLAY_HISTORY_EDIT` mode that will be used by the upcoming command's subcommands (`drop`, `reorder`, `split`, and `reword`).

The patch introduces parallel handling for history editing operations alongside existing cherry-pick and revert functionality. Key changes include:
- A new `HISTORY_EDIT_HEAD` ref to track in-progress operations
- Updated advice messages pointing to `git history continue/abort`
- Integration with existing sequencer cleanup and rollback mechanisms
- Basic test scaffolding

The implementation follows the cherry-pick model as a temporary foundation, with the commit noting this will be improved in future versions. The patch is part of a larger effort to provide Jujutsu-inspired history editing capabilities while building on Git's existing sequencer infrastructure.

This is a technical plumbing change that enables the user-facing features to come in later patches. The implementation looks thorough, with appropriate attention to error handling and integration with existing sequencer behavior. The accompanying test is minimal but reasonable for this infrastructure-focused patch.
