This is a feature patch implementing the "reword" subcommand for the proposed `git-history` command, part of Patrick Steinhardt's RFC v2 series. The subcommand allows rewriting commit messages while preserving all other commit details, similar to using "reword" in an interactive rebase.

The implementation handles several cases: rewording the tip commit, middle commits, and root commits. It preserves authorship and validates against empty commit messages. The patch includes comprehensive tests covering merge commit rejection, dirty worktree detection, and various reword scenarios. The command integrates with the existing `git-history` infrastructure for commit rewriting and validation.

This appears to be a well-constructed addition to the history editing toolkit, building cleanly on the preparatory work in earlier patches. The implementation is thorough, with careful attention to edge cases and good test coverage. As with other subcommands in this series, it demonstrates the value of having dedicated commands for common history editing operations rather than requiring interactive rebase.

The patch fits naturally into the larger `git-history` proposal, which aims to provide Jujutsu-inspired history editing capabilities. While the functionality overlaps with `rebase -i`, having it as a standalone command makes the operation more discoverable and straightforward for users.
