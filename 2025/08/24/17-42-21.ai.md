Feature implementation for the `git-history` command series, specifically the `drop` subcommand. This patch adds functionality to drop a single commit from history while preserving its descendants, building on Git's sequencer infrastructure with new `REPLAY_HISTORY_EDIT` mode.

The implementation handles several key cases:
- Dropping tip commits via direct reset when possible
- Dropping root commits by creating a new empty root
- Rejecting merges and empty-history cases
- Detecting and handling conflicts (with `continue` support via existing sequencer)
- Maintaining commit ordering through careful revision walking

The patch includes:
- Core implementation in `builtin/history.c` with `collect_commits` and `apply_commits` helpers
- Comprehensive test suite covering edge cases (merges, empty history, conflicts)
- Documentation updates with examples
- Integration with existing sequencer state management

Technical details of note:
- Uses `reset_head` for direct tip-dropping optimization
- Creates synthetic empty root commits when needed
- Validates commit reachability and merge-free history
- Leverages existing sequencer conflict resolution
- Adds new test t3451-history-drop.sh with 7 test scenarios

This is patch 8/16 in v2 of the RFC series, implementing one of the core history-editing operations alongside the previously added management commands. The implementation appears thorough with good test coverage, though the series remains marked as RFC pending broader design discussion.
