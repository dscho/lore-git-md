This is a discussion about the `reorder` subcommand implementation in Patrick Steinhardt's `git-history` RFC series, specifically addressing Kristoffer Haugsbakk's questions about its use cases and documentation.

The exchange focuses on clarifying when the imperative `reorder` command would be preferable to interactive rebase. Documentation refinements are discussed:

- Potential clarification of "current `HEAD` commit" phrasing in the man page
- Question about whether the example demonstrates both usage patterns and revision syntax

The thread continues examining the command's conceptual boundaries with rebase, with Patrick maintaining that direct imperative reordering has value in certain workflows despite Kristoffer's preference for rebase's interactive model.
