Performance optimization patch for `git describe`'s depth computation.

This patch replaces the linear scan in `finish_depth_computation()` with a khash-based set implementation to track unflagged commits, avoiding quadratic complexity in the commit queue processing. The key changes are:

1. Introduces a khash set (`commit_set`) using commit index values as keys, with helper functions for insertion/removal
2. Maintains the set of unflagged commits during queue operations
3. Uses the set size to quickly determine when all remaining commits are flagged
4. Carefully handles flag transitions when commits are first seen or when their flags change

The benchmark shows a 1.4x speedup when describing commits between v2.41.0 and v2.47.0. The implementation avoids using an object flag for queue membership to preserve flag space for candidate tags. The commit index is used as the hash key since it's unique and readily available.

The patch builds on previous work (08bb69d70f) and demonstrates careful consideration of edge cases, particularly around flag transitions. The performance improvement is well-documented with clear benchmarks. The implementation appears robust, with proper initialization and cleanup of the khash set.
