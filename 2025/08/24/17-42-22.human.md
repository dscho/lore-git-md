Feature implementation for the proposed `git-history` command, adding a "reorder" subcommand. This is part of Patrick Steinhardt's ongoing RFC series (now at v2 09/16) to create a more flexible history editing tool inspired by Jujutsu (jj).

The new `reorder` subcommand allows moving a commit to come either before (`--before`) or after (`--after`) another specified commit, with the commits being rewritten to maintain the new order. The implementation handles various edge cases:
- Rejects merge commits
- Requires clean working tree/index
- Validates commit relationships
- Includes comprehensive tests (234 lines across 12 scenarios)
- Integrates with the sequencer for conflict resolution

The patch builds on shared infrastructure from earlier in the series (like `collect_commits` and `apply_commits`) while adding new helpers like `replace_commits`. The documentation shows clear examples of reordering commits in different positions in the history.

This appears to be a well-considered addition to the proposed `git-history` command, with thorough test coverage and careful handling of edge cases. The implementation follows Git's existing patterns while providing a more direct alternative to interactive rebase for this common operation.
