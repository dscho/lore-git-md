This is a preparatory refactoring patch in Patrick Steinhardt's `git-history` RFC series (v2 13/16). It adds support for in-memory index patching to the `add-patch` infrastructure, which will be used by subsequent history editing operations.

The patch introduces a new `run_add_p_index()` function that allows applying changes to an arbitrary in-memory index rather than always using the repository's main index. This is a mechanical change that:
- Adds new `index` and `index_file` fields to `struct add_p_state`
- Modifies index operations to use the provided index
- Preserves all existing functionality while adding the new capability
- Includes comprehensive error handling and edge case detection

The implementation appears clean and focused, with clear separation between the new functionality and existing code paths. The commit message explains the motivation well - this enables future history editing operations to work with temporary in-memory indexes during complex operations. As part of the larger `git-history` effort, this continues the pattern of careful infrastructure preparation before introducing new user-facing features.
