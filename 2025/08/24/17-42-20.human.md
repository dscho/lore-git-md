This is part of the ongoing `git-history` feature series, specifically introducing management subcommands for interrupted history rewrites. Patch 7/16 in the v2 RFC adds three new subcommands to handle interrupted operations: `abort`, `continue`, and `quit`.

The patch builds on the new `REPLAY_HISTORY_EDIT` sequencer mode introduced earlier in the series. The subcommands mirror similar functionality from `git rebase`/`git cherry-pick` but are tailored for the new history editing workflow. `abort` resets HEAD to the original branch, `continue` resumes after conflict resolution, and `quit` aborts while preserving the current HEAD and working tree state.

The implementation is straightforward, wrapping existing sequencer operations (`sequencer_rollback`, `sequencer_continue`, `sequencer_remove_state`) with the new `REPLAY_HISTORY_EDIT` mode. The patch includes basic tests verifying argument handling and error conditions, though the tests can't yet exercise the full functionality since the actual history editing commands aren't implemented yet.
