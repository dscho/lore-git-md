Performance optimization for line-log functionality (git log -L) when processing merge commits. This is the first and most substantive patch in a 4-part series, focusing on eliminating unnecessary tree diffs during merge commit processing.

The patch restructures `process_ranges_merge_commit()` in line-log.c to combine two separate loops (one computing diffs, one processing them) into a single pass. This avoids computing tree diffs against secondary parents when the first parent already shows no changes to the tracked paths. The change yields significant speedups: 2.25x faster in git.git (25.8% merges) and 1.32x in linux.git (7.5% merges), with benchmarks provided.

As a side effect, the optimization removes the need to store diff queues for each parent, allowing removal of the `free_diffqueues()` helper function. The change is purely performance-focused with no user-visible behavior changes, touching only line-log.c internals (-15 lines net). The implementation appears clean and well-measured, with clear benchmark evidence supporting the optimization's value in merge-heavy histories.

Key technical details for future reference:
- Modifies merge commit processing in line-log.c
- Eliminates diff queue array in favor of local queue
- Removes now-unused free_diffqueues() helper
- Preserves all existing functionality while optimizing the hot path
- Benchmarks show 1.3-2.25x speedups depending on merge frequency
