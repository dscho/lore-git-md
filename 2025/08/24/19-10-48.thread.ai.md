Thread identity: Bugfix for `git subtree` contrib command addressing regression in squashed subtree merges under prefixes during split operations.

Core problem: When splitting subtrees with `--prefix`, squashed merges of nested subtrees (e.g. `subA/subB`) were being incorrectly ignored due to faulty commit examination logic in `should_ignore_subtree_split_commit`. This regression was introduced in commit 98ba49ccc2 and affects versions since v2.44.0-rc0.

Current status: Patch v1 fixes the issue by modifying the commit examination logic to use `rev^!` syntax to focus only on the specified commit rather than searching through parent commits. Maintains existing behavior for non-squashed cases while properly handling squashed subtree merges.

Key technical details: Changes limited to `contrib/subtree/git-subtree.sh`, specifically the `should_ignore_subtree_split_commit` function. Adds comprehensive test coverage in t7900-subtree.sh verifying both regular and squashed subtree merge scenarios, including nested subtree cases (`subA/subB`).

Test coverage: New test cases create nested subtrees and verify split operations maintain all expected files, demonstrating the bug and its resolution. Tests cover both squashed and non-squashed merge scenarios to ensure no regression in existing behavior.

Related work: Regression originated in commit 98ba49ccc2. Fix targets behavior introduced in v2.44.0-rc0.
