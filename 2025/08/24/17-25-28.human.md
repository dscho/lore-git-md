This is a follow-up discussion in the ongoing thread about Meson build system integration for Git's GUI components (gitk and git-gui). Patrick Steinhardt responds to Junio Hamano's architectural concerns about moving git-gui and gitk into subprojects/ directories to accommodate Meson's requirements.

Steinhardt acknowledges the suboptimal nature of this reorganization, agreeing it's a tool limitation rather than an ideal design. He presents two options: either maintain the current approach (allowing standalone use of the GUI tools) or switch to using Meson's `subdir()` directive (which would prevent standalone builds but allow more flexible directory placement). While expressing no strong preference, he leans toward accepting the one-time pain of reorganization to preserve standalone build capability.

The exchange highlights the tension between build system constraints and source tree cleanliness, with both parties recognizing the compromise involved. This isn't introducing new code changes - as part of the broader Meson integration effort - but rather discussing the architectural tradeoffs already made in the patch series. The discussion remains constructive, with Steinhardt open to alternatives if the current approach proves problematic.
