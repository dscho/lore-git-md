This is a feature patch in the `git-history` series, introducing management subcommands (`abort`, `continue`, `quit`) for interrupted history rewrites. The patch builds on the new `REPLAY_HISTORY_EDIT` sequencer mode infrastructure from earlier in the series.

The implementation provides three subcommands that mirror similar functionality in `git rebase`/`git cherry-pick`:
- `abort`: Resets HEAD to original branch and cleans up state
- `continue`: Restarts after resolving merge conflicts
- `quit`: Cleans up state without resetting HEAD

The patch adds documentation, command implementations in `builtin/history.c`, and basic tests verifying argument handling and error cases. The subcommands delegate to existing sequencer infrastructure (`sequencer_rollback`, `sequencer_continue`, `sequencer_remove_state`) while using the new `REPLAY_HISTORY_EDIT` mode flag. The test coverage is minimal but verifies core behaviors - rejecting arguments, proper error messages when no operation is active, and `quit`'s silent success when inactive.

This is a straightforward plumbing patch that will enable subsequent history-editing subcommands to handle interruption states properly. The implementation appears clean and well-integrated with existing sequencer machinery, though the real utility will become apparent when the actual history modification commands are introduced in later patches.
