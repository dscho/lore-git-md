This is a feature proposal for `git diff` that suggests introducing a new `--index` flag while deprecating the existing `--cached` flag. The patch appears to make these two flags functionally equivalent while favoring `--index` as the more intuitive name for showing changes between the index and HEAD.

The author argues that `--cached` is confusing terminology, especially for new users, since it doesn't clearly indicate it shows staged changes. The name `--index` would better reflect what the option actually does - show differences between the index (staging area) and the current commit.

The change would be backward compatible, keeping `--cached` working but marking it as deprecated in documentation. This follows Git's pattern of maintaining compatibility while improving usability. The patch includes updates to documentation and tests to reflect the new flag.

The proposal seems straightforward and well-motivated, addressing a known pain point in Git's CLI design. However, it may need discussion about whether this is the right time to deprecate `--cached`, given its widespread use in existing scripts and documentation. The patch appears technically sound but would benefit from broader community input on the naming change.
