Junio Hamano responds to Johannes Sixt's progress meter modernization work with some technical considerations. This is part of the ongoing discussion about replacing Git's signal-based progress meter with a timer-based approach.

Hamano notes that while Sixt's current approach using getnanotime() in display_throughput() exists, it could potentially be restructured to avoid frequent time checks. He suggests accumulating throughput data until the progress_update flag triggers, then doing the time-based calculations all at once. This would maintain the same user-visible behavior while potentially reducing system call overhead.

The email acknowledges Sixt's observation about behavior changes with delayed progress indicators (GIT_PROGRESS_DELAY) and expresses appreciation for Sixt's plan to investigate and fix these issues before submitting revised patches. This shows the discussion is moving toward concrete implementation concerns after establishing the signal-free approach as the preferred direction.

The exchange demonstrates careful technical consideration of the tradeoffs between the current signal-based approach and the proposed timer-based solution, with both maintainers working toward an optimal implementation that maintains Git's responsiveness while eliminating signal handling complexity.
