This is a feature patch introducing the scaffolding for a new `git-history` command, part of Patrick Steinhardt's RFC v2 series (patch 6/16) proposing history editing operations inspired by Jujutsu (jj). The patch adds the basic command infrastructure without implementing any subcommands yet.

The patch creates all the necessary plumbing for a new builtin command: adds `git-history` to `.gitignore`, creates a stub implementation in `builtin/history.c`, adds documentation (marking it as EXPERIMENTAL), and updates build systems (Makefile and meson). The documentation positions this as an alternative to interactive rebase for specific common operations like reordering, splitting, dropping, and squashing commits, while noting current limitations (no merge support) and experimental status.

Key technical details for future reference:
- New files: `builtin/history.c`, `Documentation/git-history.adoc`
- Build system updates: Makefile, meson.build, Documentation/meson.build
- Command registration: added to `command-list.txt` and `git.c` with `RUN_SETUP` flag
- Documentation explicitly compares to `git-rebase` and warns about merge commit limitations
- Current implementation is just a stub that parses no options
- Marked as experimental in docs with warning about potential behavior changes

The patch is part of a larger effort to provide more intuitive history editing operations, with subsequent patches planned to implement specific subcommands (`drop`, `reorder`, `split`, `reword`). The implementation builds on Git's sequencer infrastructure while taking inspiration from Jujutsu's approach.
