This is the third patch in a refactoring series for Git's line-log functionality, focusing on code quality improvements after an initial performance optimization. The change addresses a minor but potentially confusing implementation detail in `process_ranges_ordinary_commit()` where a local queue variable was left uninitialized before use.

The patch initializes the `diff_queue_struct` variable properly with `DIFF_QUEUE_INIT`, even though the uninitialized state wasn't causing any functional issues (the queue contents get overwritten later without being read first). The author notes this change is primarily for code hygiene and maintainer peace of mind, as seeing uninitialized variables being passed around could raise unnecessary concerns during code review.

This continues the series' theme of cleaning up the line-log implementation, following the performance optimization in patch 1 and parent iteration refactoring in patch 2. The change is straightforward - just a one-line diff that makes the code's behavior more obviously correct at a glance. No behavior changes or performance impact are expected from this cleanup.
