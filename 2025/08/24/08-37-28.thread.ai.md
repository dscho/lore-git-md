Thread identity: Performance optimization for `git describe`'s depth computation, comparing khash-based and commit-slab approaches to replace the linear scan in `finish_depth_computation()`.

Core problem: The current `git describe` implementation uses a quadratic-complexity linear scan for depth computation. Two competing solutions are proposed: René Scharfe's khash-based set and Jeff King's commit-slab alternative, both significantly faster than the original.

Key technical details:
- Khash approach (René Scharfe):
  - Uses commit index values as keys in a khash set (O(1) operations)
  - Preserves object flag space for candidate tags
  - Benchmarked 1.03x faster than commit-slabs (1.31-1.4x faster than original)
  - Lower memory for sparse commit sets but requires key storage
  - Supports removal operations
- Commit-slab approach (Jeff King):
  - Uses direct array access via commit->index
  - Better cache locality but allocates for all commits
  - Benchmarked 1.28x faster than original
  - No rehashing or key management overhead
  - Doesn't support removals
- Both approaches enable future enhancements:
  - Pointer-based hashing could eliminate commit->index field
  - Dynamic value sizes in hash implementations
  - Support for non-commit objects

Current status:
- Initial khash version demonstrated working solution
- Commit-slab alternative proposed with comparable performance
- Additional benchmarking shows consistent 3% khash advantage
- Technical tradeoffs clearly articulated for both approaches
