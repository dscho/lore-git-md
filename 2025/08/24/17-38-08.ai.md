This is a follow-up in the ongoing discussion about the new `git-history` command series, specifically addressing hook integration. Patrick Steinhardt responds to Kristoffer Haugsbakk's suggestion about triggering the `post-rewrite` hook for all operations in the new command.

The key point is Patrick agrees with Kristoffer's proposal to have `post-rewrite` hook integration, particularly noting its importance for the `split` subcommand which performs one-to-many rewrites. This would complete the coverage of rewrite patterns (one-to-one, many-to-one via squash, and one-to-many via split). Patrick confirms this will be added for v3 of the series.

This exchange continues the hook integration discussion that was previously identified as an open question in the thread. The maintainer had already approved the conservative implementation approach, and this represents a natural extension of that approach to include proper hook support. The response is brief but significant as it confirms another planned feature for the next iteration of the series.
