Performance optimization discussion for `git describe`'s depth computation, comparing khash and commit-slab approaches.

René Scharfe responds to Jeff King's proposal to use commit-slabs instead of khash for tracking commit membership in `git describe`'s depth computation. Both approaches significantly outperform the original linear scan (1.3-1.4x faster), with khash showing a slight 3% edge over commit-slabs in benchmarks.

Key technical details:
- Commit-slabs allocate memory for every commit but offer zero-cost lookups
- Khash scales with actual usage but requires hash computation
- Both approaches avoid the quadratic behavior of the original
- Khash implementation tested with pointer-based hashing shows similar performance

The discussion explores tradeoffs:
- Memory overhead vs lookup speed
- Potential to eliminate commit->index field
- Generalizability to non-commit objects
- Maintenance characteristics (commit-slabs require no rehashing)

While khash currently shows better performance, the difference is small enough that other factors like memory usage patterns and code simplicity may influence the final choice. The exchange highlights how Git's core contributors rigorously evaluate even small performance differences when selecting data structures.
