Feature implementation for the `git-history` command series. This patch adds a "split" subcommand to interactively divide a commit into two parts, addressing a common but complex history-editing workflow that currently requires multiple rebase steps.

The new `git history split` command lets users select which hunks from a commit should be moved into a new parent commit, with the original commit retaining the remaining changes. It handles the entire process interactively, including commit message editing (with `-m` option support), and prevents empty commits from being created. The implementation builds on previous preparatory work in the series, particularly the in-memory index patching capability.

The patch includes comprehensive tests covering various scenarios: splitting tip/root/in-between commits, partial hunk selection, pathspec filtering, and edge cases like merge commits and empty splits. The implementation appears thorough, with careful attention to preserving commit authorship and handling error conditions. This continues the series' pattern of well-structured, incremental development with strong test coverage.
