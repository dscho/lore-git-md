This is a test modernization patch in Jeff King's series about `followRemoteHEAD` behavior in `git fetch`. SZEDER Gábor provides feedback on patch 3/4, which converts subshell-based test operations to use `git -C` for directory changes.

Gábor argues that the original subshell approach is more readable than scattering `-C` throughout the commands. He notes that subshells make directory changes visually obvious at a glance, while `-C` requires closer inspection to verify which commands run where. He also raises concerns about potential mistakes when some commands might accidentally omit the `-C` flag among many that include it.

The discussion highlights a stylistic trade-off in test writing: subshells provide clear scope boundaries but require manual cleanup, while `-C` enables using `test_config` but may reduce readability. Jeff had already acknowledged this trade-off in his commit message, leaving the door open to revert if reviewers found the change undesirable.

This feedback comes after the technical aspects of the series have been settled, focusing purely on test style preferences. The core functionality fixes in the series remain uncontroversial.
