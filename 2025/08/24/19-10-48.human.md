This is a bugfix for the `git subtree` contrib command, addressing a regression introduced in Git 2.44.0-rc0. The patch fixes an issue where nested subtree merges performed with `--squash` were being ignored during `git subtree split` operations, causing missing files and incorrect commit hashes.

The problem occurs when splitting a subtree (e.g., `subA/`) that contains nested squashed subtrees (e.g., `subA/subB/`). The fix modifies the `should_ignore_subtree_split_commit` function to properly examine only the specified commit (using `rev^!`) rather than searching through parent commits, which was causing valid subtree commits to be incorrectly ignored.

The patch includes comprehensive tests that verify the fix works for both regular and squashed subtree merges, demonstrating the correct behavior through file existence checks. The test cases cover both initial subtree additions and follow-up merges, providing good coverage of the problematic scenario.
