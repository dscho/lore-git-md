This is a test modernization patch in Jeff King's series about dangling symrefs and `followRemoteHEAD` behavior. SZEDER Gábor provides feedback on patch 3/4, which converts subshell-based test operations to use `git -C` instead.

Key technical details:
- The patch modifies t5510-fetch.sh tests to replace subshell directory changes with `git -C` invocations
- Tests affected involve `followRemoteHEAD` configuration and remote HEAD symref behavior
- Original approach used subshells with manual cleanup via `test_when_finished`
- New approach uses `test_config -C` for automatic cleanup but requires `-C` on every command

SZEDER Gábor argues the subshell version is more readable because:
1. Subshell boundaries clearly delineate which commands run in the subdirectory
2. Commands outside subshells are obviously intentional, while missing `-C` could be oversight
3. The visual noise of repeated `-C` makes the test flow harder to follow

This feedback comes after the series has already completed technical review, with all patches (including this one) previously agreed upon. The discussion highlights an ongoing tension in test style preferences between explicit isolation (subshells) and command-line consistency (`-C`). While the patch was ready for integration, this late feedback suggests some developers may still prefer the subshell approach for readability.
