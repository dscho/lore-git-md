Refactoring patch in the line-log optimization series, eliminating an unnecessary parents array allocation in merge commit processing. This is patch 2/4 in a series that began with a performance optimization for `git log -L` merge handling.

The change removes a dynamically allocated array of parent commits in `process_ranges_merge_commit()`, instead iterating directly through the commit's parent list. While this avoids one allocation per merge commit, the author notes the runtime impact is "unmeasurable" - this appears primarily as a code cleanliness improvement rather than a performance change.

The patch modifies the same function that was optimized in patch 1, now simplifying its memory management. Key changes include:
- Removing the `parents` array and its allocation/free operations
- Converting array-indexed parent access to direct linked-list traversal
- Maintaining identical logic for blame assignment to parents
- Keeping the existing `cand` array for tracking line ranges

This continues the series' pattern of internal cleanups following the core optimization, with no behavior changes. The diff shows a net reduction of 12 lines, mostly from removed allocation code.
