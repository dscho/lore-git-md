Feature implementation for the `git-history` command series, specifically adding the "split" subcommand. This is patch 15/16 in the RFC v2 series by Patrick Steinhardt.

The patch introduces a new `git history split` command that simplifies splitting a commit into two by interactively selecting hunks to move into a new commit. The command handles the complex workflow of resetting, staging partial changes, and rewriting history automatically. Key technical details:

- Uses the interactive `add-patch` interface to select hunks (building on previous preparatory patches)
- Creates two new commits - one with the split-out changes (as selected by the user) and one with the remaining changes
- Maintains authorship and allows custom commit messages via `-m` or editor
- Validates against empty commits (either all or no hunks selected)
- Includes comprehensive tests covering edge cases (merge commits, empty splits, pathspec filtering)
- Integrates with the series' existing infrastructure for commit rewriting and status reporting

The implementation builds on several preparatory patches in the series, particularly the in-memory index patching capability and tree-to-tree diff support. The command appears well-designed with thorough test coverage, though as an RFC there may still be design discussions around edge case handling and integration with other history-editing operations.
