This is a bugfix patch addressing an issue in Git's progress meter delay functionality, part of the ongoing signal-handling modernization discussion.

Johannes Sixt identifies and fixes a long-standing bug where delayed indicators (configured via `GIT_PROGRESS_DELAY`) would only wait 1 second regardless of configuration, due to incorrect flag handling. The patch modifies `progress.c` to properly track elapsed time by immediately clearing the `progress_update` flag after checking it, preventing premature countdown of the delay timer. It also updates the default delay from 2 to 1 second in both code and documentation to match the de facto behavior users have experienced.

The change is minimal and focused, touching just the progress display logic while leaving the broader signal-handling discussion (the thread's main topic) for future patches. Sixt notes this fix could serve as a hook point for Carlo Arenas Belón's original alarm() proposal, though the thread has largely moved toward Sixt's signal-free approach.

Key technical details:
- Fixes incorrect flag management in `display()` function
- Changes default `GIT_PROGRESS_DELAY` from 2 to 1
- Preserves existing user experience while making behavior match documentation
- Minimal changes to progress.c and git.adoc
- Does not address the larger signal-handling questions from the thread

The patch appears well-justified with commit message references to prior changes that missed this issue, and maintains backward compatibility by formalizing the existing (albeit unintended) behavior.
