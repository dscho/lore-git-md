This is a preparatory patch in Patrick Steinhardt's RFC v2 series introducing the `git-history` command. It adds infrastructure to support future history editing operations by extending the working tree status (`wt-status`) subsystem.

The patch introduces a new function `wt_status_collect_changes_trees()` that diffs two arbitrary trees and formats the status output, similar to how `wt-status` normally shows working tree/index changes. While this stretches the "working tree" status concept slightly, the author argues it's better than open-coding this functionality elsewhere. The implementation reuses the existing diff machinery and callback system from `wt-status`, maintaining consistency with how Git already handles status reporting.

Key technical details:
- New function takes two tree-ish OIDs and a `wt_status` struct
- Uses standard diff options setup with rename detection parameters
- Calls the same `wt_status_collect_updated_cb` callback used for regular status
- Includes header declaration and basic implementation
- Not yet used, but clearly intended for upcoming history editing operations

This continues the series' pattern of careful infrastructure preparation before implementing user-facing features. The patch is cleanly focused and maintains existing behavior while adding the new capability. It follows the established diff/status patterns in the codebase, suggesting it will integrate well with the planned history editing commands.
