This is a review comment on the `split` subcommand implementation in Patrick Steinhardt's `git-history` RFC series. Kristoffer Haugsbakk provides feedback on the interactive splitting functionality while suggesting potential enhancements.

The email focuses on the usability of the interactive splitting workflow, praising its simplicity compared to the manual rebase-and-split process. Haugsbakk notes the intuitive nature of the command (`git history split $COMMIT`) and its integration with revision selection syntax (`:/'The second batch'`). The review highlights how this fills a gap in Git's history editing capabilities.

A key suggestion emerges regarding the interactive-only nature of the current implementation. Haugsbakk proposes considering a stateful split session model that would allow using external tools for patch selection, similar to how the staging area works in regular Git operations. This would maintain the command's simplicity while offering more flexibility for advanced users.

The email also touches on the relationship between the `split` and `reword` subcommands, showing how they could be used together in a workflow. This reinforces the thread's broader discussion about how these subcommands will interact in complex editing scenarios.

Technical details mentioned include:
- The interactive patch selection interface
- Revision specification syntax (`:/'commit message'`)
- Potential session state management
- Integration with other subcommands like `reword`

This feedback contributes to the RFC's open questions about subcommand interactions and edge case handling, particularly around whether the current interactive-only approach should be expanded to support alternative workflows. The suggestion aligns with the series' goal of providing flexible history editing while maintaining usability.
