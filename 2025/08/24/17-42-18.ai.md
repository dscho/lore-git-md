This is a refactoring patch from Patrick Steinhardt's `git-history` RFC series (v2 patch 5/16). It modifies the cache-tree infrastructure to allow writing arbitrary in-memory index states as trees, rather than only the repository's active index.

The key change is modifying `write_in_core_index_as_tree()` to accept a `struct index_state` parameter instead of always using `repo->index`. This enables callers to pass different index states for tree conversion. The patch updates the function signature, implementation, and all callers (currently just `builtin/checkout.c`).

This appears to be preparatory work for the `git-history` command's planned functionality, where operations may need to work with temporary in-memory indexes rather than the repository's main index. The change is mechanical and maintains existing behavior when passing the repository's index, while enabling new use cases.

The patch touches core index-handling code in `cache-tree.c` and its header, plus the checkout command that uses this functionality. It's a focused change that follows Git's established patterns for index manipulation, though reviewers might want to verify there are no subtle implications for index state management.
