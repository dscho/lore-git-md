This is a bugfix for the `git subtree` contrib command, addressing a regression introduced in commit 98ba49ccc2. The patch fixes an issue where squashed subtree merges under a target prefix were being incorrectly ignored during split operations.

The core problem occurs when:
1. A subtree exists nested under another subtree (e.g., `subA/subB`)
2. The nested subtree was merged using `--squash`
3. Running `git subtree split --prefix=subA` would incorrectly ignore the squashed subtree commits

The fix modifies the `should_ignore_subtree_split_commit` function to properly examine only the specified commit (using `rev^!` syntax) rather than searching through parent commits. This ensures squashed subtree merges are correctly identified and processed during splits.

The patch includes comprehensive test coverage in t7900-subtree.sh, adding new test cases that verify the fix works for both regular and squashed subtree merges. The tests create nested subtrees and verify the split operation maintains all expected files in both scenarios.

This appears to be a well-constructed fix for a clear regression, with thorough test coverage demonstrating both the bug and its resolution. The commit message provides good context about the regression's origin and impact (starting in v2.44.0-rc0). The changes are focused and minimal, touching only the core detection logic while maintaining the existing behavior for non-squashed cases.
