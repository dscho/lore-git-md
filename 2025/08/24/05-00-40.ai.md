This is a bugfix for fetch-pack that addresses a race condition in object existence checking during fetches. The patch modifies how we verify objects that exist in the commit-graph but might be missing from the object database.

The core issue occurs when:
1. We check for an object that exists in the commit-graph
2. The object was recently repacked into a new packfile by another process
3. Our initial check fails because it doesn't see the new packfile
4. We incorrectly conclude the object is missing and abort the fetch

The fix adds HAS_OBJECT_RECHECK_PACKED to the odb_has_object() call, forcing a rescan of packfiles if the object isn't found initially. This ensures we'll find objects that were recently repacked. The performance impact is negligible since these are objects we should already have (they're reachable from our refs and in the commit-graph).

The bug was discovered in partial clone scenarios with submodules, where multiple rapid fetches can trigger background repacking. However, the race could theoretically occur in any fetch operation concurrent with a repack. The patch includes a detailed reproduction scenario but no automated test due to the race's inherent flakiness.

Key technical details:
- Modifies fetch-pack.c's odb_has_object() call
- Uses HAS_OBJECT_RECHECK_PACKED flag
- Fixes interaction between commit-graph and object database checks
- Addresses a race condition first introduced in commit 5d4cc78f72
