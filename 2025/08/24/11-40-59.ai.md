This is a feature proposal for `git diff` that suggests introducing a new `--index` flag while deprecating the existing `--cached` flag. The patch appears to be attempting to standardize terminology, as `--cached` is currently used to show changes staged in the index, while other commands like `git rm` and `git add` use `--index` for similar functionality.

The change would make `git diff --index` behave identically to the current `--cached` option, showing the difference between the index and HEAD. The author proposes this as a first step toward eventually removing `--cached` to reduce confusion between similar flags. The patch includes updates to documentation and tests to reflect the new option.

From a technical perspective, this is a straightforward change that adds the new flag as an alias while keeping all existing behavior. The implementation looks clean, simply adding the new option alongside the existing `--cached` handling in the diff code. The patch includes appropriate test updates to verify the new option works identically to `--cached`.

This touches core diff functionality but shouldn't impact performance or introduce compatibility issues since it's purely additive at this stage.
