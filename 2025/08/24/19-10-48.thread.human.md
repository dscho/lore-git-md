This thread addresses a regression in `git subtree` where squashed merges of nested subtrees (like `subA/subB`) were being incorrectly ignored during split operations when using `--prefix`. The issue was introduced in v2.44.0-rc0 and affects all versions.

Colin Stagner proposed a fix that removes an unclear `git-subtree-dir:` trailer check while keeping the necessary `git-subtree-mainline:` verification. The technical discussion has largely converged, with Phillip Wood initially questioning the placement of these checks but later confirming they're correctly positioned in `check_parents()` to properly prune subtree recursions. The fix will employ `git show --no-patch --format` for cleaner trailer parsing.

While Zach's input on the original trailer design would provide useful historical perspective, it's not considered essential for moving forward. The remaining open questions are minor implementation details around test coverage and exact format strings. The core approach is now well-established, with the regression test's `$extracount` variable serving as the key validation mechanism for the fixed behavior.
