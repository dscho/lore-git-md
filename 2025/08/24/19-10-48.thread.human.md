This thread addressed a regression in `git subtree` where squashed merges of nested subtrees (like `subA/subB`) were being incorrectly ignored during split operations when using `--prefix`. The bug was introduced in v2.44.0-rc0 and affected subtree splits under prefixes.

Colin Stagner identified the root cause: the `should_ignore_subtree_split_commit()` function was examining parent commits when it should only check the specified commit. After technical discussion with Phillip Wood, they agreed on an approach that replaces multiple `git log` calls with a single `git show` to extract commit trailers, while maintaining the same logical conditions for ignoring commits.

The final v2 patch, now targeting maint-2.44, includes comprehensive test coverage for nested subtree behavior and removes non-POSIX `local` usage. While the purpose of the `git-subtree-dir:` trailer remains unclear, the patch conservatively retains it as agreed in the discussion. All open questions have been resolved, and the fix is ready for merging.
