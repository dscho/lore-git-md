This is a feature patch in Patrick Steinhardt's ongoing `git-history` series, specifically discussing the `split` subcommand implementation. Kristoffer Haugsbakk provides feedback on the interactive splitting functionality.

The email focuses on the usability improvements of the proposed `git history split` command compared to the current multi-step rebase workflow for splitting commits. Haugsbakk agrees the new approach fills an important gap in Git's history editing capabilities, particularly praising the interactive mode that lets users select which changes to split out.

Key points raised:
- The command simplifies a complex 7-step rebase process into a single interactive command
- Haugsbakk notes the flexibility to split commits (using commit references like `:/'The second batch'`) and combine with `reword`
- Questions whether the implementation could support non-interactive workflows or external tools, similar to how the staging area works
- Suggests considering a "stateful split session" model for greater flexibility

The feedback is constructive and engages with the design tradeoffs, suggesting the command could be even more powerful if it allowed alternative workflows beyond its current interactive-only approach. This continues the thread's thoughtful discussion about balancing usability with flexibility in history editing operations.
