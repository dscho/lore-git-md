Performance optimization and refactoring series for Git's line-log functionality (git log -L), focusing on merge commit processing. Series consists of 4 patches: 1 performance optimization followed by 3 subjective cleanups.

Core change in patch 1 optimizes merge commit handling in line-log.c by restructuring `process_ranges_merge_commit()` to combine two separate passes (diff computation and processing) into one, avoiding unnecessary tree diffs against secondary parents when the first parent shows no changes to tracked paths. Original benchmarks showed 2.25x speedup in git.git (25.8% merges) and 1.32x in linux.git (7.5% merges). Derrick Stolee's follow-up analysis confirms these gains (2.18x in internal monorepo) and explores interaction with changed-path Bloom filters, finding speedups persist at 1.15-1.38x when filters are present.

Patch 2 refactors the same function to eliminate dynamic allocation of diff queues in merge commit processing, converting from an array of diff queues (one per parent) to processing each parent's diff queue immediately after computation. This reduces memory usage by avoiding storing all parent diffs simultaneously and removes the need for a dedicated cleanup function. Junio C Hamano confirms the effectiveness of this 12-line reduction, noting its small size relative to the waste it eliminates.

Patch 3 makes `process_ranges_ordinary_commit()` more obviously correct by properly initializing a local `diff_queue_struct`. Patch 4 simplifies control flow in `process_ranges_arbitrary_commit()` by putting merge case first (3 lines changed).

Derrick Stolee has reviewed the series positively, confirming through independent benchmarking that the performance improvements hold across different repository configurations (1.15-1.38x speedup even with Bloom filters active). He characterizes the remaining three patches as welcome cleanups improving code quality in line-log.c and endorses the entire series as "excellent" with no suggested changes. Junio's approval of patch 2 further reinforces the series' trajectory toward inclusion.

All changes are internal to line-log.c with cumulative -43 LOC across 63 modified lines. No user-facing behavior changes.
