Performance optimization and refactoring series for Git's line-log functionality (git log -L), focusing on merge commit processing. Series consists of 4 patches: 1 performance optimization followed by 3 cleanups, now fully reviewed and merged into 'seen'.

Core change in patch 1 optimizes merge commit handling in line-log.c by restructuring `process_ranges_merge_commit()` to combine two separate passes into one, avoiding unnecessary tree diffs against secondary parents when the first parent shows no changes to tracked paths. Benchmarks show 2.25x speedup in git.git (25.8% merges), 1.32x in linux.git (7.5% merges), and 1.15-1.38x with Bloom filters active (confirmed by Derrick Stolee's analysis).

Patch 2 refactors the same function to eliminate dynamic allocation of diff queues, converting from an array of diff queues to immediate processing of each parent's diff. This 12-line reduction removes memory overhead and cleanup function, approved by Junio Hamano. Patch 3 makes `process_ranges_ordinary_commit()` more obviously correct via proper initialization.

Patch 4 (final subjective cleanup) reorganizes control flow in `process_ranges_arbitrary_commit()` to check for merge commits first, improving readability by using a positive check for multiple parents (c->parent && c->parent->next) instead of negated OR condition. Junio acknowledges this as a taste-based change but considers poor readability a form of "brokenness" worth fixing, and has included it in 'seen' pending any further discussion.

Derrick Stolee reviewed the entire series positively, confirming performance gains across repository configurations and endorsing the cleanups. Junio engaged on all patches, approving the substantive changes and ultimately accepting the final readability improvement. All changes are internal to line-log.c (-43 LOC across 63 modified lines) with no user-facing behavior changes. The series combines measurable performance gains with structural improvements, now progressing through integration.
