Feature implementation for the `git-history` command series, adding the `reorder` subcommand. This patch introduces functionality to move commits within a linear history, positioning them either before or after a specified anchor commit. The implementation builds on the shared infrastructure from previous patches in the series (like `collect_commits` and `apply_commits`) while adding new helper functions like `replace_commits` to handle the commit rearrangement.

Key technical aspects:
- Accepts either `--before` or `--after` to position the moved commit relative to another
- Rejects merge commits and dirty working trees
- Uses the same sequencer integration as other subcommands for conflict resolution
- Includes comprehensive tests (t3452-history-reorder.sh) covering:
  - Basic reordering in both directions
  - Edge cases (making commits roots/tips)
  - Conflict detection and resolution
  - Input validation

The implementation appears robust, with careful attention to edge cases and thorough test coverage. It follows the same pattern as the previously implemented `drop` subcommand, suggesting a consistent approach across the history-editing operations. The patch is part of the larger RFC v3 series proposing the `git-history` command, which continues to evolve based on mailing list feedback.
