Feature proposal for `git-history` command with Jujutsu-inspired functionality. This is a follow-up discussion in the ongoing RFC thread about Patrick Steinhardt's proposed `git-history` command, specifically addressing comparisons with Jujutsu's (jj) behavior.

The email clarifies several design decisions and future directions in response to Martin von Zweigbergk's detailed comparisons with Jujutsu's implementation. Key points include:

1. The `git-history` commands will automatically rebase descendants when dropping commits (like `jj-abandon`), including updating branch pointers and HEAD when needed.

2. The `reorder` subcommand is functionally similar to Jujutsu's `jj rebase -r X -A/-B Y`, though named differently to avoid confusion with Git's existing rebase terminology.

3. Future enhancements might include additional split options (-A/-B/-d) inspired by Jujutsu's more flexible splitting capabilities, though these are deferred for now.

4. The design consciously adapts Jujutsu concepts to fit Git's existing terminology and workflows (e.g., using "reword" to match interactive rebase rather than Jujutsu's "describe").

5. While revset syntax is acknowledged as a potentially valuable future direction, the focus remains on implementing core functionality first.

The exchange shows thoughtful consideration of how to integrate Jujutsu's powerful history editing concepts into Git while respecting Git's established conventions and user expectations. The discussion remains open to future UX refinements while maintaining a clear path for the initial implementation.
