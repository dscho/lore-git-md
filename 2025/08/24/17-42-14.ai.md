This is a preparatory patch for the `git-history` command series, introducing infrastructure to optionally suppress commit summary output in the sequencer. The patch adds a `skip_commit_summary` flag to `struct replay_opts` that controls whether the sequencer prints the summary after operations like cherry-pick. The flag is saved in the sequencer state file to persist across processes (e.g., during conflict resolution).

The change is motivated by upcoming `git-history` subcommands where the summary output would be undesirable. The implementation adds the new option to both the in-memory struct and the configuration persistence logic, with careful attention to maintaining existing behavior when the flag is not set. The patch touches key sequencer functions like `do_commit()`, `populate_opts_cb()`, and `save_opts()`.

This appears to be a straightforward, well-contained change that follows Git's established patterns for sequencer configuration. The commit message clearly explains the motivation and the implementation approach. As the first patch in a larger series, it sets up infrastructure that will be used by subsequent patches implementing the actual `git-history` subcommands. The change is conservative in nature - it adds functionality toggle without modifying default behavior.
