Feature patch implementing the "drop" subcommand for the proposed `git-history` command. This is part of Patrick Steinhardt's RFC v2 series (16 patches) to create a new history-editing command inspired by Jujutsu (jj).

The patch adds functionality to drop a single commit from history and rebase its descendants onto its parent, handling several edge cases:
- Can drop the tip commit via a simple reset
- Can drop middle commits by rebasing descendants
- Handles root commits by creating a new empty root
- Detects and rejects merge commits
- Includes comprehensive tests for various scenarios

The implementation builds on Git's sequencer infrastructure and shares some logic with rebase. The commit message clearly explains the motivation - simplifying what would otherwise require multiple interactive rebase steps. The patch appears well-structured with thorough test coverage and documentation updates.

This is one of the core history-editing operations in the proposed `git-history` command, alongside previously introduced management commands (`abort`, `continue`, `quit`). The implementation looks solid but remains experimental as part of the RFC series.
