This is a preparatory patch for the `git-history` command series, adding sequencer infrastructure to support rewinding HEAD after non-rebase operations like cherry-picks. The patch introduces a new `restore_head_target` option in `struct replay_opts` that will be used by the upcoming `git-history` command to return HEAD to its original branch after operations, similar to how rebase currently handles HEAD rewinding.

The implementation adds persistence for this option through the sequencer state file, ensuring it survives across processes (e.g., during conflict resolution). The core change happens in `pick_commits()` where it now conditionally resets HEAD using the existing `reset_head()` machinery when `restore_head_target` is set. The patch also includes the necessary memory management and configuration handling for the new field.

This appears to be a well-contained infrastructure addition that cleanly extends the sequencer's capabilities without disrupting existing behavior. The changes are focused and properly integrated with the sequencer's state management system. The commit message clearly explains the motivation (supporting `git-history`'s needs) and the technical approach taken.
