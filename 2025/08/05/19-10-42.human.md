This is the third patch in a 6-part documentation series introducing automated linting tools for Git's man pages. The patch adds a new linter (`lint-documentation-style.perl`) that enforces proper formatting of definition lists in AsciiDoc documentation.

The linter specifically checks for and rejects multiple terms in a single definition list entry (like `-a, --all::`), requiring them to be split into separate entries (as `-a::` and `--all::`). The patch includes fixes for several documentation files that violated this rule, including `git-check-attr.adoc`, `git-check-ignore.adoc`, and `git-http-fetch.adoc`.

The implementation follows the same pattern as previous linters in the series, integrating with the existing Documentation/Makefile infrastructure. The changes are mechanical and focused purely on formatting consistency, continuing the series' goal of establishing systematic documentation quality control through automated checks.

This patch appears well-contained and builds logically on the previous work in the series. The changes are straightforward and unlikely to be controversial, though reviewers may want to verify the specific formatting choices in the fixed documentation examples.
