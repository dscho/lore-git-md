This is the final version (v5) of Patrick Steinhardt's 9-patch series fixing reflog migration issues between files and reftable backends, now rebased on v2.50.1 for potential backporting. The series addresses two key problems discovered while implementing reftable support in libgit2: incorrect committer identity in migrated reflog entries and all-zero old OIDs that were breaking test cases.

The series includes documentation standardization, a new `git reflog write` subcommand for testing, type safety improvements, and core fixes for reflog migration. The most notable change in v5 is reverting back to aborting transactions when detecting race conditions during HEAD updates, as the edge case is deemed extremely rare and the alternative solution would require complex new infrastructure.

The patches have undergone several rounds of review, with refinements to test coverage, race condition handling, and error reporting. The implementation now correctly handles transaction status reporting and memory management during update skips. While focused on reflog migration, this work also contributes to the broader reftable adoption effort in preparation for Git 3.0.

The series appears well-tested and reviewed, with all technical issues resolved in this final iteration. It represents a solid improvement to reflog handling that should benefit both Git and libgit2 implementations.
