This is the final patch in a 6-part documentation series introducing automated linting tools for Git's man pages. The series has been systematically adding Perl linters to enforce consistent formatting, with each patch focusing on a specific aspect of documentation style.

This patch adds a check to ensure that when manpages use the synopsis style (marked with `[synopsis]`), option names in description lists are properly formatted with double backticks (e.g., `` `--option` ``). The change updates two files (git-checkout.adoc and git-refs.adoc) to demonstrate the correct formatting and adds a 6-line addition to the existing `lint-documentation-style.perl` script to enforce this rule.

The changes are mechanical but important for consistency - they ensure option names stand out clearly in the rendered documentation. The patch follows the same pattern as previous ones in the series, where each new linter comes with corresponding documentation fixes to demonstrate the expected style.

With this final patch, the series completes its goal of establishing systematic documentation quality control through automated checks for common formatting issues. The changes are straightforward and align with Jean-Noël Avila's ongoing work on synopsis conversion, making them likely to be accepted after review.
