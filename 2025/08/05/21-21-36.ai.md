Performance issue with `git cat-file --batch-command` in large repositories.

Rob Browning reports significant performance problems with `git cat-file --batch-command` when processing many object info requests in a large (~125GB, 3M objects) repository. The command processes only 32 hashes/sec with cold cache, maintaining 300-400MB/s disk reads without improvement across runs. This contrasts sharply with a custom Python implementation that achieves 1.5k hashes/sec cold and 9k hashes/sec warm.

The key observation is that `cat-file` performs much better (53k hashes/sec) after the cache is warmed by the custom tool, suggesting Git's current approach (likely mmap-based) creates excessive read amplification. The issue appears to be in how Git manages its working set during batch operations.

This is a concrete performance regression report with clear reproduction steps and comparative benchmarks. The author offers to assist with testing or potential fixes, but also notes they can work around the issue in their bup tool if this isn't a priority. The report focuses specifically on the `info` subcommand of `--batch-command`, which retrieves basic object metadata without content.
