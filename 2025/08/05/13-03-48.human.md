This is the first patch in a 6-part documentation series introducing automated linting tools for Git's man pages. The series aims to catch common formatting issues that currently require manual review.

This specific patch adds a Perl script to check for well-formed `linkgit:` macros in documentation. It fixes one instance in gitweb.conf.adoc where a command reference was missing the `linkgit:` prefix, and enhances the lint-gitlink.perl script to detect when command references should be wrapped in `linkgit:` macros but aren't. The linter will now flag cases where Git command names appear in square brackets (like `git-daemon[1]`) without the proper `linkgit:` prefix.

The patch appears well-scoped and mechanically sound, focusing on a specific documentation issue that has caused problems for readers. As the first in a larger series to automate documentation style checks, it sets up the infrastructure that subsequent patches will build upon. The change is relatively small (8 lines net) and touches only documentation files, making it low-risk for merge conflicts outside the documentation tree.
