This is the third patch in a 6-part series introducing `git refs list` as a thin wrapper around `git for-each-ref`. The patch performs a refactoring to extract core logic from `cmd_for_each_ref()` into a new shared helper function.

The patch creates a new `for-each-ref.h` header containing:
- A `for_each_ref_core()` function that handles the common option parsing, filtering and formatting logic (26 lines)
- The `COMMON_USAGE_FOR_EACH_REF` macro that consolidates all shared option documentation

The original `cmd_for_each_ref()` is reduced to a 14-line wrapper that just defines its specific usage string and calls the shared helper. The refactoring enables code reuse for the upcoming `git refs list` command while maintaining identical behavior.

Key technical details:
- The core logic moves to `for_each_ref_core()` which takes the command-specific usage string as a parameter
- All option handling including `--start-after` is now in the shared implementation
- Error handling and validation remains unchanged, just relocated
- The header establishes the public interface for shared ref listing functionality

This is a clean architectural change that follows the pattern established in earlier patches of the series, with thorough documentation synchronization already handled in patch 1/6. The change is well-contained and maintains all existing behavior while enabling the `refs list` command implementation in the next patch.
