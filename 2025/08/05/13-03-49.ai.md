This is the second patch in a 6-part documentation series introducing automated linting tools for Git's man pages. The patch adds `lint-delimited-sections.perl` to check for proper formatting of AsciiDoc delimited sections (blocks marked with `---` or `...`).

The linter enforces three rules: 1) delimited sections must be preceded by an empty line to prevent unintended title generation in translations, 2) section underlines must match the length exactly when used as titles, and 3) sections must be properly terminated within the same file. The commit explains that while English documentation can manually catch these issues, automated checking is needed for translated docs where authors can't verify the rendered output.

The patch includes the new Perl script and adds it to the documentation build system via Makefile changes. It also includes several documentation file fixes that demonstrate the linter's purpose - adding missing empty lines before delimited sections and fixing mismatched section underlines. The changes touch 14 files total, with the bulk being the new 48-line linter script.

This continues the series' pattern of establishing automated checks for documentation style issues, following the first patch's linkgit macro validation. The implementation appears thorough, with clear explanations of both the technical problem and solution. The changes are focused and mechanical, suggesting this should be uncontroversial as part of the larger documentation standardization effort.
