Refactoring patch in Patrick Steinhardt's reflog migration series. This is patch 3/9 in the v5 series that's preparing infrastructure for reftable conversion.

The patch exports the previously internal `ref_transaction_update_reflog()` function from refs.c to refs.h, making it available for other parts of Git to use when writing reflog entries. The change is motivated by upcoming work that will need this functionality. As part of the export, the patch simplifies the interface by removing the `flags` parameter since all current callers use the same set of flags (REF_HAVE_OLD, REF_HAVE_NEW, etc.), which are now hardcoded in the function.

The changes are straightforward: moving the function declaration to the header file, updating its documentation, and adjusting the single existing caller in migrate_one_reflog_entry() to match the new signature. This appears to be a clean, mechanical change that's part of the larger effort to improve reflog handling during the reftable transition.
