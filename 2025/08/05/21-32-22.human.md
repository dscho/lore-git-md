This is a bugfix/enhancement patch in the ongoing `sparse-checkout clean` series, addressing edge cases around staged changes and merge conflicts. Elijah Newren provides detailed feedback on the implementation, pointing out several areas where the behavior doesn't match the documentation or expectations.

The key issues raised:
1. The documentation and commit message are unclear about exactly which files get removed (tracked vs untracked, staged vs unstaged)
2. The error message about failing to convert to sparse index should be more general since there are multiple conditions that prevent conversion
3. Test coverage is incomplete - it doesn't verify behavior with tracked files that have no changes
4. Current behavior shows `sparse-checkout reapply` actually handles some cases better than `clean`

Newren demonstrates through manual testing that:
- Tracked files with no changes remain untouched by `clean` (contrary to documentation)
- The command gives no warning about files it doesn't clean
- `reapply` handles some cases more appropriately than `clean`

This is a thorough technical review pointing out real inconsistencies that need to be addressed before finalizing the feature. The feedback suggests either expanding test coverage and documentation to properly document the current behavior, or modifying the implementation to better match the intended behavior described in the commit message.
