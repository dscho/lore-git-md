This is the first patch in a 6-part documentation series introducing automated linting tools for Git's man pages. The patch adds a Perl linter (`lint-gitlink.perl`) to validate `linkgit:` macro usage in documentation files.

The linter now detects and reports malformed references to Git commands that should use the `linkgit:` macro but don't, catching cases where command references appear without proper macro formatting. The patch includes a fix for one such instance in `gitweb.conf.adoc` where `git-daemon[1]` was not properly wrapped in a `linkgit:` macro.

The technical implementation adds pattern matching in the Perl script to identify command references (matching `git[-a-z]+` or `scalar` followed by a section number in brackets) that aren't properly prefixed with `linkgit:`. The linter will report these as errors while allowing for some special cases like conditional blocks (`ifdef::`/`ifndef::`).

This establishes the first of several automated checks for documentation formatting, with subsequent patches in the series building on this foundation to enforce other documentation style rules. The change is mechanical in nature and focused specifically on macro formatting consistency rather than content changes.
