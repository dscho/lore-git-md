Final patch in the documentation linting effort, adding synopsis-style inline formatting checks. This completes the 6-part series that systematically enforces consistent documentation formatting across Git's man pages.

The patch extends the existing `lint-documentation-style.perl` script to detect when option names in definition lists should be wrapped in backticks for proper synopsis formatting. It adds a new check that triggers when a line starts with `[synopsis]` (marking a synopsis-style document) followed by un-backticked option definitions. The implementation modifies `git-refs.adoc` as an example, converting 10 instances of plain option names to backtick-wrapped format (e.g. `--option`).

This builds on the series' pattern of adding focused linters (24-line Perl script additions) with corresponding documentation fixes. The changes are mechanical but important for consistency, particularly as they interact with Jean-Noël Avila's parallel synopsis conversion work. The patch completes the planned linter suite after earlier installments handled linkgit macros, delimited sections, definition lists, and parameter documentation formats. With all 6 patches now submitted, the series has touched 115 files total while maintaining a clear, incremental approach to documentation standardization.
