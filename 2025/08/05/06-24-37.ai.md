This is a test case addition for a bugfix targeting remote.c's push error handling. The patch adds a failing test that demonstrates a BUG() assertion when pushing a non-existent object ID (specifically all-zeros) to an unqualified ref destination. The test is marked as test_expect_failure to document the current broken behavior.

The test creates a minimal repository setup and attempts to push an invalid OID (test_oid 001) to an unqualified branch name, which currently crashes with a BUG() message from remote.c. The error occurs because repo_get_oid() doesn't verify object existence for full OIDs, leading to an invalid assumption in the refname qualification logic.

This is the first patch in a two-part series that will ultimately replace the BUG() with proper error handling. The test is intentionally minimal, focusing only on reproducing the specific edge case without additional setup. The commit message includes the exact error output that demonstrates the current failure mode, showing both the ref qualification advice and the subsequent BUG() crash.

The patch follows the standard test pattern of first documenting the bug with a failing test before fixing it. The test will be updated to test_expect_success in the follow-up patch that implements the fix. The changes are limited to t/t5516-fetch-push.sh, adding just 7 lines to create the test case.
