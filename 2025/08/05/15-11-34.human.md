Feature addition to support reflog writes in the reftable backend. This patch introduces a new `git reflog write` subcommand as part of Patrick Steinhardt's reflog migration infrastructure series. The command allows manually appending reflog entries, which becomes particularly important with the reftable backend where manual edits aren't feasible due to the binary format.

The implementation is intentionally minimal - it only supports appending single entries with strict validation: references must be fully qualified, OIDs must be complete and exist in the object database, and messages get normalized. The patch includes comprehensive tests covering error cases (invalid refs, abbreviated OIDs, missing objects) and basic functionality.

This appears to be a well-considered addition with thorough test coverage. The implementation is clean and the commit message clearly explains both the motivation (reftable compatibility) and current limitations (no bulk writes, no timestamp control). As part of the larger reftable migration effort, this provides a crucial missing piece for users who need to manually manage reflog entries.
