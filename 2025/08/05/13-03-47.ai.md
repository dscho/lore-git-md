This is a documentation patch series introducing new linting tools for Git's man pages. The series aims to automate checks for common documentation style issues that are currently caught manually during review.

The 6-patch series adds three new Perl scripts to check documentation for:
1. Well-formed `linkgit` macros (used for cross-referencing man pages)
2. Properly delimited sections (like `[[section]]` markers)
3. Correct formatting of description lists (ensuring single terms per entry)
4. Absence of `--[no-]parameter` forms (which should be split into separate options)
5. Fixes styling and typos in `git-for-each-ref` documentation as an example
6. Ensures synopsis sections use proper synopsis formatting

The series conflicts with two other patch sets currently under review (the refs list subcommand and reflog migration patches). The author notes these documentation checks address common review comments about style guidelines that are easy to forget but simple to automate.

The changes touch 56 files, with most being documentation fixes to bring existing pages into compliance with the new linting rules. The series adds three new lint scripts to the build system and updates the shared Makefile to run them. This appears to be a well-motivated effort to improve documentation consistency through automated checks rather than manual review.
