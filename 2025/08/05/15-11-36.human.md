This is a bugfix patch in Patrick Steinhardt's reflog migration infrastructure work. It corrects how committer identities are handled when migrating reflog entries between storage formats.

The patch fixes an issue where the full identity line (containing both name and email) was being incorrectly passed as just the email parameter to `fmt_ident()`. This resulted in malformed output like "pks <Patrick Steinhardt ps@pks.im>". The solution properly splits the identity line first using `split_ident_line()` to extract the name and email components separately.

The change adds new string buffers to store the split name and email components, avoiding repeated allocations during migration. While the commit message notes there are no new tests yet (as they'll come with a subsequent fix), the change is straightforward and builds on existing identity parsing infrastructure.

This is part of the larger effort to improve reflog handling in preparation for the reftable backend, with this specific patch ensuring proper identity preservation during format migrations. The change is well-contained and clearly explained, with the technical approach matching Git's existing identity handling patterns.
