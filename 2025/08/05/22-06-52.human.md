This is a refinement to the `git sparse-checkout clean` feature, adding safety controls similar to `git clean`. The patch introduces `--force`/`--dry-run` options and respects the `clean.requireForce` config setting to prevent accidental deletions. 

Elijah Newren raises two key questions in response: First, whether applying `clean.requireForce` is appropriate given that `sparse-checkout clean` only affects untracked/ignored files (unlike `git clean` which can delete tracked files). Second, he notes an inconsistency where merge conflicts trigger an error about sparse index conversion, while tracked files without conflicts are silently preserved.

The implementation itself appears solid, with thorough test coverage for the new force/dry-run behavior and config option handling. The documentation clearly explains the safety mechanisms. However, Newren's comments suggest the design rationale may need revisiting to align with Junio Hamano's philosophy on when force requirements are appropriate.

This patch is part of the ongoing sparse-checkout clean series that aims to efficiently remove directories outside the cone-mode patterns while preserving important edge cases like staged changes. The discussion here focuses on fine-tuning the safety mechanisms rather than the core functionality.
