This is a bugfix patch series addressing an incorrect BUG() assertion in remote.c's push error handling. The two-patch set:

1. Adds a test case demonstrating the issue where pushing a non-existent object ID (like all-zeros) to an unqualified ref destination triggers a BUG() instead of proper error handling. The test was initially marked as expecting failure to document the broken behavior.

2. Fixes the core issue by replacing the BUG() in show_push_unqualified_ref_name_error() with an advise() message when the source OID doesn't exist. The commit message explains that this isn't actually a programming error case - it's a normal user mistake when providing a full hexadecimal OID that doesn't exist in the repository.

The series has already incorporated feedback from Junio C Hamano about improving the commit message clarity and error messaging. The changes are focused and well-tested, addressing a clear edge case in push validation where the error reporting was overly aggressive. The fix maintains the same underlying push validation logic while providing more appropriate user feedback.
