This is the final patch in Patrick Steinhardt's reflog migration infrastructure series, fixing invalid old object IDs during reflog format conversion. The patch addresses a subtle bug where migrated reflog entries were incorrectly showing all-zero OIDs for the old object ID due to improper resolution logic during format conversion.

The core fix introduces a new `REF_LOG_USE_PROVIDED_OIDS` flag that instructs backends to use the caller-provided OIDs directly rather than attempting to resolve them. This ensures proper preservation of old OIDs during migration between storage formats. The change affects both files and reftable backends, with corresponding validation to ensure required flags are set when using the new behavior.

Test coverage is improved by modifying t1460-refs-migrate.sh to use a new test helper that verifies both old and new OIDs in reflog entries, closing a previous testing gap. The patch also fixes related tests in t1421-reflog-write.sh that were previously masking the issue by not properly checking old OIDs.

This completes the series' technical work by ensuring accurate OID preservation during reflog migration, a critical requirement for the upcoming reftable backend adoption. The change maintains backward compatibility while fixing the migration path, with comprehensive test coverage verifying both the direct fix and related identity handling from previous patches.
