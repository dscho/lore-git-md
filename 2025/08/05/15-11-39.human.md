Final patch in the reflog migration infrastructure series, fixing invalid old OID handling during format conversion.

This is the concluding patch in Patrick Steinhardt's 9-part series preparing Git's reflog infrastructure for the reftable backend transition. The patch addresses a subtle bug where reflog entries being migrated between storage formats would incorrectly show all-zero old object IDs instead of preserving the original values. The root cause was that the migration code was trying to resolve the old OID from the reference rather than using the provided value.

The solution introduces a new `REF_LOG_USE_PROVIDED_OIDS` flag that tells the backend to use the caller-supplied OIDs directly. The patch updates both the files and reftable backends to honor this flag, with appropriate validation to ensure all required fields are present. Test coverage is improved by modifying the migration tests to use a new test helper that verifies both old and new OIDs in reflog entries, closing a previous testing gap.

This completes the series' technical work, having addressed documentation, command organization, race conditions, identity handling, and now OID preservation during migration. The changes are well-contained and focused, with clear commit messages explaining both the problem and solution. The series as a whole appears ready to support Git's upcoming reftable backend transition.
