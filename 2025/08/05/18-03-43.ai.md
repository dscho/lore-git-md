This is a follow-up in the `jt/archive-zip-deflate-fix` thread about fixing zlib API misuse in `git archive --format=zip`. Junio Hamano explains his revert of the fix from 'next' was due to premature merging before broader discussion, not a rejection of the technical approach. The original patch by Justin Tobler correctly addressed the issue by properly flushing the deflate stream until Z_STREAM_END, which Toon Claes confirms was the right solution despite having proposed alternative patches earlier. 

The core technical issue involves the zip compression code path's handling of deflate streams, where the original fix used a 2x input buffer size that Toon has verified shouldn't cause problems. While the fix itself is technically sound, Junio wants to ensure consensus before re-merging. The thread shows the patch is likely to be accepted after this procedural delay, as there are no substantive objections to the approach - just a desire for more review time. This maintains Git's standard conservative merging practices for fixes touching compression internals.
