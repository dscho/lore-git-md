This is the second patch in a two-part bugfix series addressing incorrect BUG() behavior in remote.c's push error handling. The patch replaces a BUG() assertion with proper user-facing advice when pushing a non-existent full object ID to an unqualified ref destination.

The change modifies `show_push_unqualified_ref_name_error()` in remote.c to handle the case where `odb_read_object_info()` reports a non-existent object (which occurs with full hexadecimal OIDs) by showing an advice message instead of triggering a BUG(). The test case from the first patch is updated from `test_expect_failure` to `test_expect_success` to verify the fix.

Key technical details:
- The fix specifically handles the edge case where a full 40-character OID (like all zeros) is provided as the source
- Maintains existing behavior for partial OIDs and refnames (which still die with error messages)
- The advice message is concise and actionable, focusing on the OID existence issue
- Test case remains minimal (7 lines) and verifies this specific error path

The patch incorporates feedback from Junio C Hamano, adopting his suggested commit message wording that clarifies the distinction between full/partial OID handling in `repo_get_oid()`. The changes are localized to the error reporting path and don't affect core push validation logic. With this change, the series fully resolves the original issue with no remaining technical questions.
