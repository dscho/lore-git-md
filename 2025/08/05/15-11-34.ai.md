Feature addition to the reftable migration infrastructure, introducing a new `git reflog write` subcommand. This patch (4/9 in the v5 reflog series) adds the ability to manually append reflog entries, which becomes particularly important with the reftable backend's binary format making manual edits impractical.

The new subcommand has strict validation: it requires fully-qualified ref names, unabbreviated OIDs that must exist in the object database, and normalizes the reflog message. Current limitations include no support for multiple entries, arbitrary insertion points, custom timestamps, or references to nonexistent objects. The implementation uses the newly exported `ref_transaction_update_reflog()` API from earlier in the series.

The patch (t1421-reflog-write.sh) thoroughly tests error cases (invalid refs, abbreviated OIDs, missing objects) and happy paths (message normalization, root ref handling). One known issue noted in the "simple writes" test shows incorrect old-OID recording in subsequent entries, which the commit message indicates will be fixed later in the series. This appears to be a well-scoped, carefully implemented addition to the reftable tooling, with clear documentation and comprehensive tests.
