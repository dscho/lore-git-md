This is the third patch in a 6-part documentation linting series, focusing on definition list formatting in AsciiDoc documentation. The patch adds a new Perl linter script (`lint-documentation-style.perl`) that enforces single-term entries in definition lists (marked with `::` or `;;`), fixing instances where multiple terms were incorrectly grouped together in the same entry.

The linter catches cases like `-a, --all::` and requires them to be split into separate entries (`-a::` and `--all::`). This addresses a regression introduced when `generate-configlist.sh` was modified to handle carriage returns, which inadvertently broke multi-term definition list entries. The patch includes fixes for several man pages (`git-check-attr`, `git-check-ignore`, `git-http-fetch`, and `api-path-walk.adoc`) that violated this style rule.

The 24-line Perl script integrates with the existing documentation build system through new Makefile` targets (`lint-docs-doc-style`), following the same pattern as previous linters in the series. The changes are mechanical and focused on documentation consistency rather than semantic content. This continues the series' theme of catching documentation formatting issues early through automated checks rather than manual review.

Key technical details for future reference: the linter checks for patterns matching `^[ \t]*`?[-a-z0-9.]+`?(, `?[-a-z0-9.]+`?)+(::|;;)$` to detect multiple terms in a definition list item. The patch touches 7 files total (including the new linter script and Makefile integration) with mostly one-line changes to split definition list entries.
