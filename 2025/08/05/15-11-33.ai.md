This is a refactoring patch in Patrick Steinhardt's reflog migration infrastructure series (v5 3/9). The change exports the previously internal `ref_transaction_update_reflog()` function from refs.c to refs.h, making it available for other parts of the codebase that need to write reflog entries. 

The patch simplifies the function by removing the `flags` parameter since all current callers use the same set of flags (REF_HAVE_OLD, REF_HAVE_NEW, REF_LOG_ONLY, REF_FORCE_CREATE_REFLOG, REF_NO_DEREF), which are now hardcoded in the function. The documentation is updated to clarify that the index parameter defaults to ordering by refname when zero.

This change supports the series' broader goal of enabling reflog migration between storage backends by making the reflog update functionality available to other components. The modification is mechanical and low-risk, maintaining all existing behavior while removing an unnecessary parameter. The patch follows the series' pattern of careful refactoring to support the reftable transition work.
