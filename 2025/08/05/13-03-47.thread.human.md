This thread tracks a 6-patch series introducing automated linting tools to enforce consistent formatting across Git's man pages. The series, now at v3, has evolved through feedback from Collin Funk (who provided a Reviewed-by on patch 3) and Ramsay Jones (who identified portability issues to address in the next reroll).

The latest email focuses on patch 3, which adds a new linter (`lint-documentation-style.perl`) to enforce single-term entries in definition lists - a change that will simplify automated translation workflows. The 24-line script detects and fixes cases where multiple terms appear in a single definition list item (like `-a, --all::`), splitting them into separate entries. The patch demonstrates this by updating 4 documentation files, with Collin Funk confirming the technical approach handles newline issues correctly. Ramsay Jones noted a related portability problem in `generate-configlist.sh` that will be fixed in a future version.

The series as a whole introduces several focused Perl linters (3-48 lines each) that check various documentation formatting rules, from `linkgit:` macro validation to section delimiters and option formatting. These tools are being integrated into Git's build system while carefully coordinating with Jean-Noël Avila's parallel effort to standardize man page synopses.
