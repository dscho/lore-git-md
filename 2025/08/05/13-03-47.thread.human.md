This thread documents a systematic effort to improve Git's man page consistency through automated linting tools. The 6-patch series, now complete and merged into the main branch, introduces several focused Perl linters that enforce specific formatting rules across Git's documentation.

The series follows a clear pattern: each patch adds a new linter targeting a particular documentation issue while fixing existing files as examples. The linters cover linkgit macros, section formatting, definition lists, --[no-] option splitting, and backtick-wrapping of option names. Together they form a comprehensive quality control system for documentation formatting.

Key changes include standardizing how options appear in definition lists (splitting combined entries like `-a, --all::`), enforcing consistent backtick usage for option names, and ensuring proper section delimiters. The changes touch 117 files total, with the most substantial updates to `git-for-each-ref.adoc` which saw a 132-line reformatting to align with the new standards.

Jean-Noël Avila has been reviewing the series, which complements his parallel work on synopsis standardization. Ramsay Jones contributed a minor formatting correction during review. The series has been carefully coordinated with other in-flight documentation work to avoid conflicts, and Junio C Hamano has merged it into the main branch, establishing these automated checks as part of Git's documentation quality control.
