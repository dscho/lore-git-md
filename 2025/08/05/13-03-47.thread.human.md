This thread introduces a new documentation linting system for Git's man pages. The author has sent a 6-patch series that adds automated checks for common documentation style issues like proper `linkgit` macro usage, section delimiters, description list formatting, and option syntax. The series also fixes styling in the `git-for-each-ref` documentation as an example of the improvements these tools will enforce.

The changes are substantial, touching 56 files to bring existing documentation into compliance with the new linting rules. Three new Perl scripts are being added to the build system to automate these checks. The author notes this addresses frequent review comments about documentation style - issues that are easy to miss manually but simple to catch automatically.

There are currently conflicts with two other in-flight patch sets (the refs list subcommand and reflog migration work), which will need to be resolved. The series appears well-motivated as a way to improve documentation consistency through automation rather than relying solely on manual review.
