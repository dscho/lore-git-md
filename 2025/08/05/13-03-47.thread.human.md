This thread documents a 6-patch series introducing automated linting tools to enforce consistent formatting across Git's man pages, now integrated into the main branch. The series systematically adds focused Perl linters (3-48 lines each) with corresponding documentation fixes, following an incremental improvement pattern.

The third patch, now reviewed by Collin Funk with a Reviewed-by tag, introduces `lint-documentation-style.perl` to enforce proper definition list formatting. It splits combined entries like `-a, --all::` into separate items with correct spacing, fixing 4 documentation files. Collin confirmed the implementation addresses newline handling in `sed` rather than carriage returns. Jean-Noël Avila notes an upcoming iteration will extend this linter to also check config description files, which weren't covered here.

The series as a whole adds five new linters covering linkgit macros, section formatting, definition lists, `--[no-]` options, and synopsis backtick requirements. These changes establish systematic documentation quality control through automated checks while maintaining compatibility with Jean-Noël's parallel synopsis conversion effort. With Collin's review on this patch and the series being small and non-conflicting, it's expected to be merged by Junio after resolving minor conflicts with two in-flight topics.
