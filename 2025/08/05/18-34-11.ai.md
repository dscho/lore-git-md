Bugfix patch in the merge-ort rename detection series, specifically addressing rename-to-self edge cases. This is part of the ongoing effort to handle complex rename interactions during merges, particularly when directory renames affect file paths.

The patch fixes three distinct issues that occur when a file is renamed to itself (A->A) during a merge: silent file deletions when files should be kept, silent file retentions when files should be deleted, and incorrect index entry counts. The core fix adds a check in process_renames() to skip processing when oldpath == newpath, leveraging merge-ort's path interning optimization to safely use pointer comparison rather than strcmp().

Technical details include:
- Adds explicit check in process_renames() for rename-to-self cases
- Uses pointer comparison optimization (safe due to merge-ort's path interning)
- Modifies testcase 12i and adds new testcase 12i2 to demonstrate silent deletion bug
- Converts testcases 12n and 12n2 from expect_failure to expect_success
- Includes detailed commit message explaining the transitive rename case handling

The discussion with Patrick Steinhardt confirms the safety of the pointer comparison approach through merge-ort's path interning design, though there was initial concern about brittleness. The patch is ready for inclusion with only minor documentation improvements planned for the v2 submission. This completes the technical fixes for the rename-to-self edge cases in the series.
