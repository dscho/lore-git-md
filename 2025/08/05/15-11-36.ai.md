This is a bugfix patch in Patrick Steinhardt's reflog migration infrastructure series, addressing incorrect identity handling during reflog format conversion. The patch fixes how committer identities are reconstructed when migrating reflog entries between storage formats.

The core issue stems from incorrectly passing the full identity string as the email parameter to `fmt_ident()`, which expects separate name and email components. This resulted in malformed identities like "pks <Patrick Steinhardt ps@pks.im>". The solution splits the identity line using `split_ident_line()` to properly extract name and email components before formatting.

The patch introduces two new string buffers (`name` and `mail`) in the migration callback structures to avoid repeated allocations when processing identities. These buffers are initialized in `repo_migrate_ref_storage_format()` and properly released. While the commit mentions there's another related bug to be addressed later, this change stands on its own as a clear correctness fix for identity handling.

This change is part of the larger reftable migration effort and specifically builds on the infrastructure added in earlier patches of the series. The fix is technically sound, though the commit notes test coverage will be added in a subsequent patch when additional reflog verification is implemented in t1450. The change maintains consistency with the series' focus on robust reflog handling during storage format transitions.
