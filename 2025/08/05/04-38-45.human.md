This is a discussion about test expectations in the merge-ort rename detection bugfix series. Patrick Steinhardt is providing feedback on patch 3/6, which documents edge cases involving files being renamed to themselves during directory renames.

The key point of discussion is how strictly test cases should enforce specific outcomes. While Elijah Newren's patch includes comments explaining why some test outcomes are flexible, Patrick argues that tests should still assert one specific expected result (with explanatory comments) rather than accepting multiple possible outcomes. This would make future behavior changes more noticeable while still acknowledging the inherent complexity of these edge cases.

Patrick's position reflects a preference for precise test assertions that serve as clear indicators when behavior changes, even for cases where multiple resolutions might be technically correct. This is part of the broader review process for a series fixing subtle directory rename interaction bugs in merge-ort.
