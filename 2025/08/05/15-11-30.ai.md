This is the final version (v5) of Patrick Steinhardt's bugfix series addressing reflog migration issues between files and reftable backends, now including all race condition fixes and transaction handling refinements. The series has evolved through five iterations with input from multiple contributors, culminating in a robust solution that:

1. Corrects committer identity in migrated reflog entries
2. Fixes the all-zero old OID issue that was breaking libgit2 compatibility
3. Adds a new `git reflog write` subcommand for testing and manual reflog manipulation
4. Implements comprehensive race condition handling for HEAD updates
5. Preserves REF_HAVE_OLD flag for log-only updates

Key technical changes in v5 include reverting to transaction abortion (rather than silent dropping) for detected HEAD races, as this edge case is extremely rare in practice. The implementation now properly handles transaction status reporting and memory management during update skips. Test coverage has been expanded with a new helper (`GIT_TEST_PRETEND_SPLIT_HEAD`) to simulate race conditions more precisely.

The series builds on reftable migration infrastructure and addresses several subtle edge cases in the files backend's reflog handling. It's particularly notable for:
- Exporting `ref_transaction_update_reflog()` to enable cross-backend reflog operations
- Type-safety improvements in identity parsing
- Strict refname validation in the new write subcommand
- Careful handling of the HEAD/<branch> relationship during concurrent updates

With all technical issues resolved and the series rebased on v2.50.1 for potential backporting, this represents the final form of these fixes before Git 3.0's reftable transition. The changes are well-tested and have undergone extensive review, making them low-risk for inclusion.
