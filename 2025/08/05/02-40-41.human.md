This is the second and final patch in a series modernizing Git's editor-related code, focusing on converting the environment variable handling to use the strvec API. The patch completes the series by updating the editor.c and editor.h interfaces to consistently use strvec for environment variable passing, matching Git's modern conventions.

The change is a straightforward refactoring that replaces the old const char** parameter with struct strvec* across all editor-related functions. The patch notes there's only one caller (in builtin/commit.c) that actually passes environment variables, and it already has a strvec available. The modification preserves all existing behavior while making the code more consistent with Git's current string handling patterns.

This follows through on the series' narrowed scope after discussion revealed the original PATH modification concerns were better addressed elsewhere. The changes are well-contained, touching only editor.c, editor.h, and the single caller in builtin/commit.c. With Johannes Schindelin's help and prior reviews from Patrick Steinhardt, this appears to be a clean, uncontroversial modernization that improves code consistency without changing functionality.
