Bugfix for merge-ort's handling of rename-to-self cases during directory renames. This is patch 5/6 in a series addressing edge cases in merge-ort's rename detection, building on earlier fixes for directory rename interactions.

The patch fixes three specific bugs that occur when files are renamed to themselves during merges: silent file deletion when files should be kept, silent retention when files should be deleted, and incorrect index entry counts. These issues arise because the code assumes rename source and destination paths are different, which isn't true in rename-to-self scenarios.

Elijah Newren adds a new test case (12i2) that modifies a file just enough to still be detected as a rename, exposing the silent deletion bug. The fix is straightforward - skip processing when old and new paths are identical. The patch also updates existing test cases (12n and 12n2) that were previously marked as failing to now expect success.

This appears to be a well-constructed fix with thorough test coverage. The commit message clearly explains the bugs and how they were masked by optimizations, and the changes are minimal and focused. As part of an already-reviewed series, this patch looks ready for inclusion.
