This is the fourth patch in a 6-part documentation series adding automated linting tools for Git's man pages. The patch introduces a new linter that enforces a style for command-line options in documentation, specifically prohibiting the `--[no-]parameter` form in favor of listing `--parameter` and `--no-parameter` separately.

The change affects 36 documentation files, splitting combined option declarations into separate entries. The linter checks for patterns like `^`?--[no-][a-z0-9-]+.*(::|;;)$` to detect violations. The rationale given is improved searchability when options are listed separately.

This continues the series' mechanical, uncontroversial approach to documentation standardization. Like previous patches, it includes both the linter implementation (a small Perl script) and the mass application of fixes. The changes are straightforward syntax updates without semantic impact, though they do touch many files (159 insertions, 78 deletions across the docs). 

The patch maintains consistency of the series by following the same pattern: a focused linter with clear rules, Makefile integration, and bulk fixes. It's part of an ongoing effort to catch documentation style issues early through automation rather than manual review.
