Performance issue report for `git cat-file --batch-command` in large repositories.

Rob Browning reports a significant performance problem when using `git cat-file --batch-command` to query object information in a large (~125GB, 3M objects) repository. The command processes only 32 hashes per second with cold cache, while a custom Python script achieves 1,500 hashes/sec under the same conditions. The performance gap persists even after multiple runs, suggesting the Git implementation may be causing kernel-level read amplification through its mmap approach.

Interestingly, when the cache is warmed by the custom script first, `cat-file` performance jumps to 53k hashes/sec, indicating the underlying hardware is capable of much better throughput. The author suspects Git's memory mapping strategy may be artificially inflating the working set size.

This appears to be a genuine performance bottleneck that could affect tools like bup that rely on `git cat-file`. The report is well-documented with clear reproduction steps and comparative benchmarks. Rob offers to assist with testing or potentially working on a solution if the Git maintainers consider this worth addressing. The next step would likely be for performance-conscious maintainers to verify the findings and discuss potential optimization approaches.
