This is the second and final patch in a series modernizing editor-related code, focusing on security and compatibility through infrastructure improvements. The patch converts the editor API from using raw string arrays to the modern strvec interface for environment variable handling.

The change updates all editor-related functions in editor.c and editor.h to accept a `struct strvec*` instead of a `const char* const*` for environment variables. The only caller that passes non-NULL environment variables (in builtin/commit.c) already has a strvec available, making this a straightforward conversion. The patch maintains all existing behavior while aligning with current Git coding conventions.

Key technical details:
- Updates function signatures in editor.h for `launch_editor()`, `launch_sequence_editor()`, and `strbuf_edit_interactively()`
- Modifies editor.c to use strvec API when processing environment variables
- Adjusts the single non-NULL env caller in builtin/commit.c
- Builds on previous strvec conversions (8babab95af)
- Maintains version consistency requirements for editor-spawned subprocesses
- Files touched: builtin/commit.c, editor.c, editor.h

This completes the uncontroversial portion of the original series after discussion revealed the PATH modification changes were unnecessary. The change is behavior-preserving and has already received positive review from Patrick Steinhardt. It represents a straightforward modernization of editor environment handling to match current Git coding standards.
