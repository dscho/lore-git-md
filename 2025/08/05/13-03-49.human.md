This is the second patch in a 6-part documentation series adding automated linting tools for Git's man pages. The patch introduces `lint-delimited-sections.perl`, which checks for proper formatting of AsciiDoc delimited sections (blocks marked with `---` or `...`).

The linter enforces three rules: 1) delimited sections must be preceded by an empty line to prevent unintended title generation in translations, 2) section underlines must match the length exactly (a common AsciiDoc gotcha), and 3) sections must be properly terminated within the same file. The patch includes fixes to 10 documentation files where these rules were violated, mostly adding missing empty lines before sections.

The motivation is to prevent subtle documentation rendering issues, particularly in translated versions where authors can't easily verify the rendered output. This continues the series' theme of automating documentation style checks that previously required manual reviewer attention. The implementation follows the pattern established in patch 1, adding the linter to the build system with appropriate Makefile rules.

The changes are straightforward and the commit message clearly explains both the technical problem and solution. This appears to be a well-considered addition to the documentation tooling that should help maintain consistency, especially for non-English translations.
