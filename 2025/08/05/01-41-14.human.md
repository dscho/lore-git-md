This is a follow-up in a thread discussing how Git handles PATH environment variables for child processes, particularly focusing on security and version consistency concerns. The author, D. Ben Knoble, is responding to feedback from Phillip Wood about their patch series that aimed to remove Git's exec-path from non-Git child programs.

Phillip Wood made several key points that have influenced the author's thinking: the issue stems from scripts making incorrect assumptions about Git's installation layout rather than Git's behavior itself, and that Git needs to maintain environment modifications (like GIT_EXEC_PATH in PATH) to ensure version consistency for editor-spawned Git subprocesses. Wood also noted that distributions have discretion over where contrib scripts are installed.

As a result of this discussion, Knoble has decided to scale back their changes - they'll resend only the first two cleanup patches (which modernize test isolation in t7005-editor.sh and refactor editor.c/h to use the strvec API) and drop the more controversial changes to PATH handling. This represents a shift from their original broader approach to a more focused, less disruptive change that maintains compatibility while still providing some code quality improvements.

The exchange highlights the careful balance needed between security (not exposing Git internals) and functionality (ensuring spawned processes use the correct Git version), with the consensus leaning toward preserving current behavior for editor-related cases. The author's willingness to adjust their approach based on this feedback suggests these initial cleanups have a good chance of being accepted.
