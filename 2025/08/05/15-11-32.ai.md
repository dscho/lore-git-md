This is a documentation and code reorganization patch in Patrick Steinhardt's reflog migration infrastructure work (v5 2/9). The patch reorders the `git-reflog` subcommands for better logical grouping, moving read-only commands before write operations and positioning the "expire" subcommand last to prepare for an upcoming "write" subcommand addition.

The changes affect both documentation (git-reflog.adoc) and implementation (builtin/reflog.c), with the following key reorderings:
- Moves "exists" before write operations
- Groups "delete" and "drop" together as single-ref write operations
- Positions "expire" last as a multi-ref write operation
- Reorders corresponding usage strings and option declarations to match
- Maintains all existing functionality while improving command organization

The patch is part of a larger series addressing reflog handling improvements, with this particular change being a preparatory reorganization. The commit message clearly explains the motivation for the new ordering, which will accommodate future additions to the command set. The changes are mechanical and well-contained, touching only the command ordering without modifying any behavior.
