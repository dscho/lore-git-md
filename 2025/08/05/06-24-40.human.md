This is the second patch in a two-part bugfix series addressing an incorrect BUG() assertion in remote.c when pushing with a non-existent object ID. The patch replaces the BUG() call with a proper advise() message when users attempt to push an invalid OID to an unqualified ref destination.

The change is straightforward: instead of crashing with a BUG() when detecting a non-existent object (which was inappropriate for a user error), it now shows advice explaining the issue. The accompanying test case, which previously marked as test_expect_failure, is updated to test_expect_success to verify the fixed behavior.

The patch incorporates feedback from Junio C Hamano, including improvements to the commit message that better explain the behavior differences between full and partial OIDs. The fix is well-contained, touching only the error reporting path without modifying core push validation logic. This completes the series that addresses a clear edge case in push error handling.
