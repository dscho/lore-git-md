This is a refactoring patch in Patrick Steinhardt's reflog migration infrastructure series, specifically addressing flag handling for reflog updates. The change focuses on the `REF_HAVE_OLD` flag behavior during log-only updates.

The patch stops unsetting `REF_HAVE_OLD` for log-only updates while maintaining the same safety guarantees. Previously, this flag was cleared for reflog entries since their old OIDs don't need to match the current ref state. However, keeping the flag set (while skipping the actual verification for log-only updates) preserves important signaling about whether an old OID was provided. This prepares for a subsequent commit that will use this signal for new functionality.

Key technical changes include:
- Removing the `REF_HAVE_OLD` clearing in `ref_transaction_update_reflog()`
- Modifying `ref_update_expects_existing_old_ref()` to return 0 for log-only updates
- Updating verification logic in both files and reftable backends to skip old OID checks for log-only updates
- Adding clarifying comments about log-only update behavior

The changes affect multiple backend implementations (files and reftable) and core refs code, with careful attention to maintaining existing behavior while enabling future functionality. This is part of the larger effort to improve reflog handling in preparation for reftable adoption.
