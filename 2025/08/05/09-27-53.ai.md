Documentation refactoring patch for the `git refs list` series, now incorporating `--start-after` option details.

This is the first patch in the v6 series that introduces `git refs list` as a wrapper around `git for-each-ref`. The patch factors out all common option documentation from `git-for-each-ref.adoc` into a new shared file `for-each-ref-options.adoc`, using Asciidoc's include mechanism. The refactoring is purely organizational - the rendered documentation remains identical, but the shared file can now be included by both `for-each-ref` and the new `refs list` command's man pages.

Key technical aspects:
- Creates new 88-line `for-each-ref-options.adoc` containing all option documentation
- Updates `git-for-each-ref.adoc` to use `include::` directive instead of inline options
- Maintains all existing option descriptions including the recently added `--start-after` pagination option
- Preserves exact documentation formatting and structure
- The patch is part of a larger architectural effort to share implementation and documentation between `for-each-ref` and the new `refs list` command
- Follows established Git documentation practices for shared includes
- Has been reviewed by multiple mentors including Patrick Steinhardt and incorporates Karthik Nayak's `--start-after` documentation

This foundational change enables subsequent patches to reuse the same option documentation for the new `refs list` command while keeping everything synchronized. The patch appears well-structured and follows Git's documentation patterns, with no functional changes to the actual documentation output.
