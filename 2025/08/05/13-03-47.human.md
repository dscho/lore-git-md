This is a documentation patch series introducing automated linting for Git's documentation. Jean-Noël Avila proposes adding several new checks to catch common documentation issues that currently require manual review. The series aims to automatically enforce documentation guidelines that are "easy to forget and almost trivial to automatically check."

The 6-patch series adds three new linting tools that check for:
1. Well-formed `linkgit` macros and delimited blocks
2. Proper formatting of description lists and command-line options (avoiding `--[no-]parameter` forms)
3. Correct synopsis formatting in manpages

The patches also include some documentation cleanups (notably for `git-for-each-ref`) that were presumably found by these new checks. The changes touch a wide range of documentation files (56 files modified) but appear to be focused on style and formatting rather than content changes.

The author notes this series currently conflicts with two other in-progress documentation efforts (the refs list subcommand and reflog migration patches). The approach looks well-motivated and systematically implemented, with the tests being added to the documentation Makefile. This seems like a useful quality-of-life improvement for documentation maintenance.
