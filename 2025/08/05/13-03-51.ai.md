Documentation patch enforcing separate `--parameter`/`--no-parameter` options rather than combined `--[no-]parameter` form.

This is the fourth patch in a 6-part series adding automated linting tools for Git's man pages. The new linter enforces that documentation should list separate `--parameter` and `--no-parameter` options rather than the combined `--[no-]parameter` form, for better searchability. The patch modifies 36 documentation files to split these combined forms into separate entries, touching common commands like `git-clone`, `git-push`, and `git-config`.

The linter script (`lint-documentation-style.perl`) is updated to detect the `--[no-]` pattern in definition lists (marked with `::` or `;;`). The changes are mechanical and widespread, affecting options across many commands, but each follows the same simple transformation pattern. This continues the series' focus on documentation consistency, though it's distinct from Jean-Noël Avila's parallel synopsis-style conversion work. The patch maintains the series' pattern of including both the linter script and the resulting documentation changes in each commit.
