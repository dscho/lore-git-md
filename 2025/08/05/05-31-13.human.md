This is a bugfix and refactoring patch for `git remote set-head`, addressing a compiler warning while improving code clarity. Authored by Jeff King but submitted by Denton Liu, it restructures the argument handling in `set_head()` to validate the remote name immediately rather than conditionally.

The change makes the control flow more straightforward by requiring the remote name up front, which eliminates a GCC `-Og` warning about potential uninitialized variable access (though the original code was technically safe due to early error exits). The patch duplicates a single-line usage message but makes the logic more maintainable by ensuring the `remote` struct is always set before use.

This is the first of two patches in v2 of a series addressing compiler warnings. The changes are behavior-neutral - they don't fix a runtime bug but improve code quality and silence a legitimate (if overly cautious) compiler complaint. The approach follows Junio Hamano's preferred solution of restructuring rather than adding compiler-specific workarounds.
