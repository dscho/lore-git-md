Documentation patch in an ongoing series to standardize Git's man pages.

This is part 3 of a 6-patch series introducing automated linting for Git's documentation. The patch adds a new Perl linter (`lint-documentation-style.perl`, 24 lines) that enforces proper formatting of definition lists in man pages, specifically requiring that multiple terms in a single entry (like `-a, --all::`) be split into separate entries. The linter is integrated into the build system via `Documentation/Makefile` and `shared.mak`.

The patch fixes four documentation files as examples: `git-check-attr.adoc`, `git-check-ignore.adoc`, `git-http-fetch.adoc`, and `api-path-walk.adoc`. The changes are mechanical but important for consistency and searchability. Ramsay Jones points out a minor formatting issue in the diff where `-a::-c::` should be split into separate lines with proper spacing.

The linter is part of a broader effort to systematically improve documentation quality through automated checks, complementing Jean-Noël Avila's parallel work on standardizing synopses. The implementation follows the pattern established in previous patches of the series, adding focused checks for specific formatting issues. The changes maintain compatibility with existing documentation while enforcing more consistent styling.
