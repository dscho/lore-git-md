This is a bugfix for the push error handling in remote.c, finalizing a two-patch series that addresses an incorrect BUG() assertion when pushing invalid object IDs.

Patrick Steinhardt provides a quick review of Denton Liu's fix, agreeing with the core approach but suggesting two minor wording improvements to the error message. First, he recommends spelling out "object ID" rather than using the abbreviation "oid" for better user comprehension. Second, he notes the message should explicitly mention which object ID is problematic when multiple refspecs are involved, to help users in debugging.

The change itself is straightforward - replacing a BUG() with an advise() message when an invalid full OID is pushed to an unqualified ref. The thread summary indicates this series has already been reviewed and approved by Junio Hamano, with Patrick's suggestions being the final polish before merging. The fix maintains all existing error handling for partial OIDs and refnames while properly handling this edge case.
