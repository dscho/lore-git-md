Bugfix in test setup for merge-ort's rename detection tests. This is part of a series addressing edge cases in directory rename handling during merges.

The patch fixes a test setup issue where several test cases (12i, 12j, 12k) in t6423-merge-rename-directories.sh were missing proper staging of a modified file ('baz'). While this didn't affect the test assertions, it made the test environment unnecessarily complex and obscured a related bug that will be fixed in a subsequent patch.

The changes are straightforward: adding `git add` commands for the 'baz' file modifications in each test setup, and updating the expected status output to show staged ('M') rather than unstaged (' M') changes. This brings the tests in line with their intended behavior and prepares for the upcoming fix of a rename-to-self bug that was being masked by the optimization in merge-ort.

The patch is part of a well-documented series (now at v2) that has seen thorough review, with all technical aspects resolved. This particular fix is a clean-up that improves test reliability before addressing the deeper issue in the next patch.
