This is the 4th patch in a 6-part documentation series introducing automated linting tools for Git's man pages. The patch adds a new linter that enforces splitting `--[no-]parameter` style flags into separate `--parameter` and `--no-parameter` entries for better searchability.

The linter (`lint-documentation-style.perl`) is a simple 3-line addition that detects and reports any remaining `--[no-]` style parameter documentation. The bulk of the patch updates 36 documentation files to split such parameters into separate entries, with changes being purely mechanical formatting improvements (e.g. converting `--[no-]progress` into `--progress` and `--no-progress`).

The changes span core commands (`git-commit`, `git-push`, `git-send-email`) and auxiliary documentation (options files, scalar). Each split maintains the same description text for both variants, just duplicating it under the separate entries. The patch follows the established pattern from previous linters in the series, with the linter integrated into the documentation build system.

This continues the systematic approach to documentation consistency seen in earlier patches, with the motivation being improved searchability rather than any functional change. The changes are straightforward and unlikely to be controversial, being part of an already-reviewed series.
