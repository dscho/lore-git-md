Bugfix patch addressing multiple edge cases in merge-ort's handling of rename-to-self scenarios during directory renames. This is patch 5/6 in a series fixing complex edge cases in merge-ort's rename detection, building on previous work from 2021 and 2025.

The patch fixes three specific bugs that occur when directory renames result in files being renamed to themselves (A->B where A and B are the same path):
1. Silent deletion of files that should be kept (testcase 12i2)
2. Silent retention of files that should be deleted (testcase 12n2)
3. Incorrect index entry counts (testcase 12n)

The core fix adds a check in merge-ort.c's process_renames() to skip processing when oldpath == newpath, since the existing code assumed they were different paths. The patch includes extensive test updates:
- Modified testcase 12i to have multi-line content (prep for new test)
- New testcase 12i2 demonstrating the silent deletion bug
- Updates to testcases 12n and 12n2 (previously marked expect_failure) to now pass
- Total of +69 lines to t6423-merge-rename-directories.sh

The changes build on prior directory rename work and specifically address cases where merge-ort's optimizations were masking these bugs. The test modifications carefully preserve existing coverage while adding new edge case verification.
