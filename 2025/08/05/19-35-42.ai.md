This is a refactoring patch in the merge-ort rename detection series, specifically addressing a code simplification in the directory rename checking logic.

The patch replaces an indirect check for a key's presence in a strmap (using a temporary variable and strmap_get_entry()) with a direct strmap_contains() call in check_for_directory_rename(). This change makes the code more straightforward while maintaining identical behavior. The function is part of merge-ort's complex directory rename detection system that prevents problematic renames when multiple directory renames interact.

The commit message explains that this optimization also helps prevent N-way transient rename confusion, referencing test cases 9c and 9d in t6423. The change removes an unused variable (otherinfo) and slightly improves the comment to better reflect the actual check being performed. This is a clean, uncontroversial improvement that follows naturally from the introduction of strmap_contains() in Git's API.

As part of the larger series fixing edge cases in merge-ort's rename detection, this patch stands out as a pure code quality improvement rather than a bugfix. It was authored by merge-ort maintainer Elijah Newren and appears ready for inclusion, building on the established pattern of using strmap_contains() elsewhere in the codebase.
