Feature patch series (3 parts) finalizing improvements to `-h` and `--help-all` behavior, following earlier discussion that led to dropping a controversial fourth patch.

This version from D. Ben Knoble incorporates feedback from the previous round, notably switching from an enum to `#define` constants for the parse-options refactoring. The series now focuses on three clear goals: fixing test dependencies, clarifying internal parse-options flags, and enabling `--help-all` outside repository contexts.

The first patch cleans up test infrastructure from the ua/t1517-short-help-tests branch, fixing several test issues including an instaweb marker and t5200 test. The second refactors parse-options.c to use named constants (`USAGE_NORMAL`, `USAGE_FULL` etc.) instead of magic numbers, improving readability without changing behavior. The third modifies builtin command handling to properly support `--help-all` without requiring a repository, while preserving special cases for `ls-remote` and `grep`.

The series appears well-considered, with the most contentious aspects (around mid-command `-h` handling) already resolved by dropping patch 4 in response to security and technical concerns raised by Junio C Hamano and Jeff King. The remaining changes seem uncontroversial and focused on clear improvements to the help system infrastructure.
