Refactoring patch in Junio Hamano's string-list API modernization series, addressing a safety issue in interactive clean. This is part 3 of 12-patch series that's been well-reviewed and appears ready for integration.

The patch converts `parse_choice()` in builtin/clean.c from using the problematic `strbuf_split()` to the safer `string_list_split_in_place()`. The function handles user input selection in interactive clean operations, parsing space/comma-separated tokens that specify menu items (like number ranges or single-letter commands).

Key improvements:
1. Eliminates unsafe strbuf array handling that could lead to dangling pointers
2. Simplifies parsing by directly supporting multiple delimiters (spaces and commas) without preprocessing
3. Maintains identical user-facing behavior while using the more robust string_list API

The change demonstrates the practical benefits of the string_list API refactoring work, fixing a real safety issue in a user-facing command. The series has already converted over 30 call sites and this patch shows the API's value in eliminating dangerous patterns while keeping code simple.
