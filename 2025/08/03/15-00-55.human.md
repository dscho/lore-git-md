This is a feature patch series introducing a new `--trailer` option to `git rebase`, along with necessary plumbing changes to make it work efficiently.

The series (v3) from Li Chen adds the ability to append trailers (like Signed-off-by) to commit messages during rebase operations. The implementation moves all trailer handling from the external `interpret-trailers` helper into built-in code for better performance, eliminating fork/exec overhead. The rebase integration forces use of the merge backend (since the apply/am backends lack message filtering), automatically enables `--force-rebase` to ensure trailers are added even to fast-forwarded commits, and stores state to support interrupted rebases.

The changes look well-considered, with thorough test coverage (new t3440 test file) and clean integration. The v3 iteration addresses previous feedback by consolidating trailer handling paths. The implementation touches several areas (trailer.c, rebase.c, sequencer) but appears focused and properly scoped. This seems like a useful feature for workflows that maintain consistent trailers across rebased commits, and the performance improvements from in-process trailer handling would benefit all users of commit message trailers.
