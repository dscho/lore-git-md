This is the second patch in a performance optimization series for `git describe`, building on the previous conversion to use `prio_queue`. The patch introduces a wrapper struct `lazy_queue` around the priority queue to optimize the common get+put sequence into a more efficient peek+replace operation, avoiding unnecessary heap rebalancing.

The key technical change is the introduction of `struct lazy_queue` which tracks pending get requests via a `get_pending` flag. New wrapper functions (`lazy_queue_get/put/empty/clear`) handle the state transitions, replacing direct `prio_queue` operations throughout `describe_commit()` and related functions. The `all_have_flag()` helper is updated to account for the pending state.

Benchmarks show this provides an additional speedup on top of the first patch's improvements - the new version runs 1.41x faster than the intermediate `prio_queue` version and 1.83x faster than Git 2.50.1. The patch maintains identical functionality while reducing overhead, with clean separation of concerns via the wrapper struct. The implementation appears thorough, with proper state handling and cleanup. This completes the performance optimization series with what looks like a straightforward win.
