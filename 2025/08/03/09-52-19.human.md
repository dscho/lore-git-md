Bugfix for zip archive generation when deflating large files. This is a follow-up to Justin Tobler's patch that fixes an edge case in `git archive` where creating zip archives could fail with "deflate error (0)" when processing certain large files.

René Scharfe, the original author of the zip archive code, confirms this is a legitimate bug in the handling of zlib's deflate stream. The issue occurs when the output buffer isn't large enough to hold all compressed data in one pass, which the original code didn't properly account for. While the current buffer sizing (twice the input size) was thought to be sufficient based on zlib's deflateBound(), it didn't consider the stream's internal state.

Scharfe approves of the fix but notes that while the solution could be more tightly integrated with the first loop, that would complicate the patch unnecessarily. The current approach of using a separate do-while loop to handle the Z_FINISH case is straightforward and correct.

The patch was tested against a specific problematic file in the chromium.git repository, though both authors acknowledge it would be useful to find a more general way to test this edge case. One suggestion is to artificially reduce the output buffer size to make the bug easier to trigger during testing.

This appears to be a well-justified fix for a real but uncommon edge case in zip archive generation, with clear technical explanation and maintainer approval. The change is small and focused, touching only the deflate handling logic in `archive-zip.c`.
