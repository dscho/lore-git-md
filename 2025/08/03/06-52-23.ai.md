This is the final patch in Junio Hamano's v4 string-list API refactoring series, focusing on internal API improvements. The patch demonstrates the practical application of the new STRING_LIST_SPLIT_NONEMPTY flag introduced in patch 6/7, eliminating the common pattern of splitting strings and then separately removing empty items.

The changes update four call sites (notes.c, pathspec.c, and two test helpers) to use the new flag-based filtering during the initial operation rather than performing a separate string_list_remove_empty_items() call. The conversions are mechanical but demonstrate the API's cleaner usage pattern - each case replaces a two-step process (split+remove_empty) with a single split_f() call including the NONEMPTY flag.

The patch maintains all existing functionality while reducing code duplication and improving efficiency by avoiding the intermediate list with empty items. The changes are consistent with the series' goal of unifying behavior between string_list_split() variants while expanding their capabilities through flags.

Key technical details for future reference:
- Uses STRING_LIST_SPLIT_NONEMPTY (1<<1) flag introduced in 6/7
- Updates calls in notes.c (colon-separated refs), pathspec.c (attr matching), and test helpers (hashmap and json-writer)
- Preserves all existing behavior while removing empty items during initial split
- Follows the series' pattern of using _f-suffixed wrapper functions for type safety
- Maintains the established flag-based extension approach seen throughout the series
