This is a refactoring patch in Junio Hamano's ongoing string-list API modernization series (now up to 12 patches in v3). The change focuses on the interactive clean command's choice parsing logic.

The patch simplifies the `parse_choice()` function's interface by having it accept a simple `char*` instead of a full `strbuf` structure, since the function only needs the NUL-terminated string content. This follows the series' pattern of making APIs more minimal and type-appropriate. The change is mechanical but demonstrates good API design principles - passing only what's needed rather than larger structures.

Key technical details:
- Changes parameter type from `struct strbuf*` to `char*` in `parse_choice()`
- Updates all callers to pass `choice.buf` instead of `&choice`
- Maintains identical functionality for interactive selection
- Builds on previous string_list conversions in clean.c
- Part of broader effort to standardize string processing APIs

The change is small (6 lines modified) but meaningful, continuing the series' theme of eliminating unnecessary strbuf usage where simpler types suffice. It follows established patterns from earlier patches and maintains all existing behavior while making the code more direct.
