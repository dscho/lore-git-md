This is a refactoring patch in Junio Hamano's ongoing string-list API modernization effort, specifically targeting `merge-tree.c`'s input parsing. The patch converts the code from using `strbuf_split()` to the newer `string_list_split_in_place_f()` API, continuing the series' pattern of eliminating manual string buffer management.

The change simplifies `merge-tree`'s standard input parsing by:
1. Replacing `strbuf_split()` with `string_list_split_in_place_f()` which handles both splitting and trimming via the `STRING_LIST_SPLIT_TRIM` flag
2. Using the string_list's `nr` field for bounds checking instead of array indexing
3. Removing explicit `strbuf_rtrim()` calls that are now handled by the API
4. Replacing `strbuf_list_free()` with `string_list_clear()`

The patch maintains identical functionality while reducing code complexity - the input format (merge-base followed by two branches, optionally with a `--` separator) remains unchanged. This conversion follows the series' established pattern of using the string_list API's type-safe, flag-based features to eliminate manual string manipulation while preserving behavior. The change affects only internal parsing logic with no user-visible impact.

This continues demonstrating the API's benefits in command implementations, following similar conversions in `wt-status` and `clean.c` earlier in the series. The patch shows the string_list API handling another real-world parsing scenario (interactive merge instruction processing) while eliminating error-prone buffer management.
