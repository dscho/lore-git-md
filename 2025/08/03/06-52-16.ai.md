This is a v4 iteration of Junio Hamano's refactoring series for Git's string-list API, building on the technically complete v3 series that unified string-list splitting behavior across 21 callers. The series introduces STRING_LIST_SPLIT_TRIM and STRING_LIST_SPLIT_NONEMPTY flags while maintaining the existing multi-delimiter support.

The key changes in v4 focus on documentation improvements and historical context:
1. Patch 2 now explains the historical reason for the delimiter discrepancy, referencing 52acddf3's addition of multi-delimiter support to string_list_split_in_place() that wasn't mirrored in string_list_split().
2. Patch 4 expands the in-code comments to explicitly state that STRING_LIST_SPLIT_TRIM handles "whitespaces around" split pieces, addressing Jeff King's earlier request for clarity.
3. The cover letter provides more background on the original motivation for multi-delimiter support (intended for strtok() replacement) that wasn't fully utilized.

The technical implementation remains unchanged from v3, maintaining:
- Unified handling between string_list_split() and string_list_split_in_place()
- Enum flags with explicit bit shifts
- Trim operation placement consistency
- Error handling converted to BUG()
- Preserved multi-delimiter capability

The series continues to demonstrate thorough test coverage in t/unit-tests/u-string-list.c and practical benefits like simplifying diff.colormovedws parsing. All architectural decisions appear settled with consensus from multiple contributors, making this a mature refactoring ready for final review. The v4 changes are purely documentation-focused, suggesting this is likely the final iteration before potential merging.
