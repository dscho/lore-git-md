Refactoring patch in Junio Hamano's ongoing string-list API modernization series, converting notes copy input parsing from strbuf to string_list.

This patch updates the notes copy-from-stdin functionality to use the newer string_list_split_in_place_f() API instead of the older strbuf_split() approach. The change follows the established pattern seen in previous patches of the series, eliminating manual string buffer management in favor of the safer string_list API.

Key technical changes:
- Replaces strbuf_split() with string_list_split_in_place_f() using STRING_LIST_SPLIT_TRIM flag
- Uses string_list's nr field for bounds checking instead of array indexing
- Removes explicit strbuf_rtrim() calls as trimming is now handled by the split function
- Replaces strbuf_list_free() with string_list_clear()
- Maintains identical functionality while simplifying the code

The patch notes that while the input parsing could be made stricter (currently ignoring extra tokens after the first two), that improvement is considered out of scope for this refactoring series. The conversion follows the same successful pattern demonstrated in previous patches for wt-status, clean.c, and merge-tree input handling.

This continues the series' trend of providing safer string processing while reducing code duplication and eliminating unsafe patterns. The change is focused and mechanical, maintaining all existing behavior while leveraging the string_list API's improvements.
