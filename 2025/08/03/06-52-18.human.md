This is part 2/7 in Junio Hamano's v4 series refactoring Git's string-list API. The patch aligns the behavior of `string_list_split()` with its `_in_place()` counterpart by allowing it to accept multiple delimiter characters, matching functionality added to `string_list_split_in_place()` in an earlier commit (52acddf36c).

The change updates 19 call sites across the codebase to pass delimiter strings (like `","` or `" "`) rather than single characters. This is a mechanical but widespread change that touches various subsystems including diff, blame, merge, and transport code. The patch maintains all existing behavior while preparing for future API enhancements.

The modification is well-contained with comprehensive test coverage in t/unit-tests/u-string-list.c. As part of a larger API cleanup effort that has already undergone several rounds of review, this change appears straightforward and low-risk, though it does require careful verification of all call sites to ensure they handle the new string delimiter parameter correctly.
