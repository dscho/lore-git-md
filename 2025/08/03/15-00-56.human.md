Refactoring patch for Git's trailer handling infrastructure, part of a series adding `--trailer` support to `git rebase`. This first patch moves trailer processing from an external `interpret-trailers` helper into built-in code.

The patch eliminates the fork/exec overhead by implementing trailer processing directly in `trailer.c`, introducing a new `trailer_process()` function that handles both file and in-memory operations. The existing `amend_file_with_trailers()` is reimplemented to use this new infrastructure rather than shelling out. The `interpret-trailers` command becomes a thin wrapper around these new functions.

Key technical changes include:
- New `trailer_process()` core function that handles all trailer operations
- Removal of temporary file handling from `interpret-trailers`
- Consolidation of `amend_strbuf_with_trailers()` logic into the main processing path
- Preservation of all existing behavior (confirmed by passing test suite)

This appears to be a well-executed refactoring that cleanly separates concerns while maintaining backward compatibility. The changes are focused and the commit message clearly explains the transformation. As the first part of a two-patch series, this lays the groundwork for the subsequent `git rebase --trailer` feature.
