This is a bugfix patch in Junio Hamano's ongoing string-list API refactoring series. It addresses a potentially dangerous situation in `builtin/clean.c` where a `strbuf` was being passed by value to the `parse_choice()` function.

The core issue is that while passing a struct by value normally gives the callee an independent copy, this doesn't work safely with `strbuf` because it contains a pointer to the underlying character buffer. The function was modifying this shared buffer (replacing commas with spaces) and could have caused memory corruption if a reallocation occurred.

The fix changes the function signature to take a `strbuf*` instead, which is the proper way to handle `strbuf` parameters. This is a straightforward change that eliminates the risk while maintaining the same functionality. The patch is small (5-line change) but important, as it prevents what could become a double-free or use-after-free bug in the interactive `git clean` menu interface.

This appears to be a well-justified change that follows established Git conventions for `strbuf` handling. It's part of a larger, well-reviewed series that's modernizing string handling across the codebase.
