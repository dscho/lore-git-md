This is a response in the ongoing discussion about making content-ignoring diff options (`-I`, `-w`) behave consistently across output formats. Junio C Hamano is commenting on Jeff King's proposed implementation approach that uses `/dev/null` redirection to check for ignorable changes before producing metadata outputs like `--name-only`.

Junio finds Jeff's solution more elegant than previous proposals, as it avoids code duplication by reusing the existing `diff_flush_patch()` machinery and only needs to check the `diff_from_contents` flag rather than tracking multiple content-ignoring options. The approach works by temporarily redirecting output to `/dev/null` to test whether changes would be hidden by the content filters, then only showing the file in metadata outputs if real changes remain.

The maintainer notes this solution is "much more palatable" than earlier iterations, though it does require an extra pass through the diff queue. He emphasizes the architectural benefit of the approach being agnostic to which specific options set the `diff_from_contents` flag, making it more maintainable long-term. This suggests Junio may be leaning toward accepting this direction over the previously proposed `diffcore_ignore()` solution.
