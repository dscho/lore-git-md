This is a refactoring series that builds upon the recent string-list API improvements to eliminate unnecessary uses of strbuf_split*() functions. The 12-patch series demonstrates how modern string_list_split*() can replace strbuf_split*() in various parts of the codebase while maintaining or improving functionality.

The series focuses on cases where strbuf_split*() was being used primarily for string splitting and trimming, which the newer string_list_split*() API can handle more efficiently. Key changes include:
- Converting callers in wt-status, clean, merge-tree, notes, config, environment, sub-process, and trace2 subsystems
- Demonstrating how string_list_split*() can replace two-step split+trim operations with single calls
- Removing redundant strbuf operations where string_list's built-in trimming suffices
- Cleaning up related code patterns like unnecessary strbuf passing by value

The patches show a pattern of:
1. Splitting strings directly into string_lists instead of strbuf arrays
2. Leveraging string_list's built-in trimming capabilities
3. Simplifying code that previously did manual trimming after splitting
4. Removing now-unnecessary strbuf management

Notable technical changes include:
- Conversion of colon-separated ref parsing in notes.c
- Environment variable handling cleanup in config.c and environment.c
- Trace2 pattern loading simplification by removing redundant trimming
- Clean command internals restructuring to avoid strbuf passing

The series builds on Junio's earlier string-list API modernization work and demonstrates practical applications of those API improvements. It maintains backward compatibility while providing more maintainable code. The changes are internal with no user-facing impact, focusing on code health and reducing unnecessary strbuf usage where simpler string_list operations suffice.
