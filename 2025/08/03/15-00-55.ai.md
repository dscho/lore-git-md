Feature patch series for `git rebase` adding `--trailer` support, with prerequisite refactoring of trailer handling.

This two-part series introduces a new `--trailer` option to `git rebase` that appends specified trailers to rewritten commits. The implementation requires moving trailer processing from the external `interpret-trailers` helper into built-in code, which becomes the focus of the first patch. The first patch refactors trailer handling to work entirely in-process via a new `amend_strbuf_with_trailers()` function, eliminating fork/exec calls. This appears to be a clean internal API improvement that could benefit other commands too. The second patch builds on this to implement the new rebase feature, which automatically forces the merge backend (since the apply/am backends lack message filtering) and enables `--force-rebase` to ensure trailers are added even to fast-forwarded commits. State is properly persisted to survive interrupted rebases.

The series includes comprehensive testing via new test file t3440 that covers normal operation, conflicts, root commits, and invalid inputs. The v3 iteration consolidates trailer handling paths as suggested in prior review feedback, removing duplicate code. The implementation looks thorough, with careful consideration of edge cases and rebase internals. This appears ready for serious consideration as a useful feature for maintaining commit metadata during history rewriting.
