Part of Junio Hamano's v4 string-list API refactoring series, this patch leverages the new STRING_LIST_SPLIT_TRIM functionality to simplify diff.colormovedws parsing. The change demonstrates the practical application of the series' infrastructure improvements in a real-world configuration parsing scenario.

The patch modifies diff.c's parse_color_moved_ws() function to use the new trimming capability of string_list_split_f() when processing the comma-separated diff.colormovedws configuration values. This eliminates the need for manual strbuf allocation, population, and trimming for each token, reducing the function from 20 lines to 7 while maintaining identical behavior. The simplification removes temporary strbuf handling while preserving all existing functionality: whitespace trimming, value validation, and bitwise flag setting for recognized modes (ignore-space-change, ignore-all-space, etc.).

This change depends on the earlier patches in the series that introduced the STRING_LIST_SPLIT_TRIM flag and unified the string splitting implementations. It serves as a clean example of how the refactored API can reduce boilerplate in configuration parsing while maintaining type safety through the _f-suffixed wrapper function. The patch maintains all existing error handling, including reporting unknown modes and validating flag combinations (like preventing allow-indentation-change from being used alone).

As with the rest of the series, this is an internal refactoring with no user-facing behavior changes, though it does make the code more maintainable by removing manual string manipulation steps. The change follows the established pattern of mechanical conversions that leverage the new API capabilities while preserving existing test coverage.
