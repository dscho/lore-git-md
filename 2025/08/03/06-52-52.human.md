This is a refactoring series that continues Junio Hamano's work to modernize string handling in Git by replacing strbuf_split() usage with the newer string_list_split() API. The 12-patch series builds on his earlier string-list API improvements and targets various subsystems including clean, merge-tree, notes, config, and trace2.

The key motivation is that strbuf arrays are often overkill for string splitting tasks, especially when combined with trimming operations. The series demonstrates how string_list_split() can handle these cases more efficiently while maintaining the same functionality. Notable changes include:

1. Removing strbuf_split() from wt-status, clean, merge-tree, notes, config, and trace2 subsystems
2. Simplifying code that previously did strbuf_split() followed by manual trimming
3. Adding a new patch (4/12) to avoid passing whole structures unnecessarily in clean.c
4. Fixing some typos and improving commit messages from v2 to v3

The changes are mechanical but thorough, touching 8 files with 129 insertions and 166 deletions. The series maintains backward compatibility while cleaning up what Junio calls a "misdesigned API function" (strbuf_split*()). He notes this is part of ongoing cleanup work and invites others to continue converting remaining strbuf_split() uses.

This appears to be a well-considered refactoring that builds logically on prior work. The changes are focused and the commit messages clearly explain both the technical changes and the rationale.
