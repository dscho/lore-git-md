Refactoring patch in Junio Hamano's string-list API modernization series, focusing on sub-process communication. This patch (10/12 in v3) simplifies the status reading from subprocesses by replacing an over-engineered strbuf_split*() approach with direct string parsing.

The change modifies sub-process.c to read "status=<foo>" packets more efficiently. Instead of splitting each line into two strbufs and checking the first part, it now uses skip_prefix() to directly check for and extract the status value. This eliminates:
- The allocation and freeing of temporary strbuf pairs
- The 2-element array management
- The redundant strcmp() after split

The new version maintains identical behavior (last "status=" line still wins) while being more direct and reducing code by 3 lines (9 deletions vs 6 additions). This continues the series' pattern of replacing string processing with simpler, safer alternatives, here applied to Git's sub-process communication channel. The change is straightforward and aligns with the series' goal of eliminating unnecessary string buffer management.
