This is a Windows platform compatibility patch that fixes Git's behavior when renaming files on ReFS filesystems in Windows 2022. The change is part of a series addressing various Windows filesystem operation improvements.

The patch specifically handles a case where Windows 2022's ReFS filesystem returns ERROR_NOT_SUPPORTED when Git attempts atomic renames using POSIX semantics (a behavior introduced in an earlier commit). Previously, Git only handled ERROR_INVALID_PARAMETER for this case. The fix treats both error codes the same way - by falling back to a non-atomic rename operation when the POSIX-style rename isn't supported.

The change is minimal (just one line modified) but important for users on Windows 2022 systems using ReFS, as it prevents rename operations from breaking. The patch comes from production-tested Git for Windows code and fixes a specific GitHub issue (#5427). It follows the pattern seen elsewhere in the series of maintaining compatibility across different Windows versions and filesystems while removing obsolete code paths.
