This is a refactoring patch in a series about improving Git's help system behavior. It's the second of three patches that aim to make `-h` and `--help-all` work consistently outside repository contexts.

The change focuses on making parse-options.c more readable by replacing magic numbers (0 and 1) with named constants for the flags passed to `usage_with_options_internal()`. The author introduces four new `#define` constants: `USAGE_NORMAL`, `USAGE_FULL`, `USAGE_TO_STDOUT`, and `USAGE_TO_STDERR`. This makes the function calls more self-documenting without changing any behavior.

The patch is straightforward and uncontroversial, following up on earlier discussion in the thread where the approach using `#define` constants was settled upon. It touches only parse-options.c, updating all call sites to use the new constants. The author notes some minor readability concerns about deep indentation but considers this the best available option.

This is a clean improvement that makes the code more maintainable while being part of a larger effort to improve Git's help system behavior. The change is well-contained and unlikely to introduce any issues since it's purely a naming change with identical runtime behavior.
