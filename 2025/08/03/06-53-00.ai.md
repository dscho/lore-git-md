This is a refactoring patch in Junio Hamano's ongoing string-list API modernization series (now at 24 patches). It converts config parameter parsing from using strbuf_split() to the newer string_list_split() API.

The patch focuses on git_config_parse_parameter() which handles GIT_CONFIG_PARAMETERS environment variable parsing. The key changes are:
- Replaces strbuf_split_str() with string_list_split()
- Eliminates manual delimiter trimming since string_list handles this via flags
- Simplifies memory management by using string_list_clear() instead of strbuf_list_free()
- Maintains identical functionality while reducing code by 3 lines (13 deletions vs 10 additions)

The conversion follows the established pattern seen in previous patches of the series, applying the safer string_list API to eliminate manual string buffer management. The commit notes one ergonomic quirk of string_list_split()'s max parameter (it counts splits rather than pieces), but this doesn't affect the correctness of the conversion.

This change is part of the broader effort to modernize string processing across Git's codebase, demonstrating the API's benefits in config handling after previous conversions in areas like interactive clean, merge-tree, and notes functionality. The patch maintains all existing behavior while improving safety and reducing code complexity.
