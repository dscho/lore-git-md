Refactoring patch in the string-list API series. This is the first of seven patches in Junio Hamano's v4 iteration of the string-list refactoring effort. The change converts two error messages from `die()` to `BUG()` when the string-list API is misused - specifically when the `.strdup_strings` flag doesn't match the expected value for either `string_list_split()` or `string_list_split_in_place()`.

The patch is straightforward, changing only the error reporting mechanism while keeping the same error messages (though the commit notes these could be made more concise in the future). This aligns with Git's convention of using `BUG()` for programming errors rather than user-facing `die()` calls. The change affects only internal API usage and has no user-visible impact.

As part of the larger series that's already been technically reviewed in v3, this patch appears uncontroversial and well-justified. The series as a whole is focused on unifying string-list behavior across Git's codebase while improving documentation and internal consistency.
