This is a bugfix patch addressing inconsistent behavior in Git's diff output when using content-ignoring options like `-I<regex>` and `-w` with metadata-focused outputs like `--name-only`. The patch introduces a new `diffcore_ignore()` function to filter out file pairs containing only ignored changes before output, ensuring consistent behavior across all diff formats.

The issue stems from how Git currently processes diffs - content-ignoring options were being applied only during content examination in `builtin_diff()`, while metadata outputs bypass this examination entirely. This led to files appearing in `--name-only` output even when their changes were supposed to be ignored by `-I` or whitespace options.

Lidong Yan's solution adds a new diffcore transformation that checks for ignorable changes at the diffcore level, before any output formatting occurs. The implementation handles various edge cases like unmerged files, binary diffs, and text conversions. The patch includes comprehensive tests verifying the new consistent behavior across `-I<regex>`, `-w`, and other ignore options when used with different output formats.

This is version 2 of the patch, following discussion in the thread where Jeff King and others identified the UX problems with the current behavior. The solution maintains backward compatibility for machine-readable formats like `--raw` while fixing the inconsistency for human-oriented outputs. The implementation looks thorough, with careful attention to performance and edge cases.
