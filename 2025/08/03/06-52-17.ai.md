This is a refactoring patch in Junio Hamano's string-list API series, converting error handling from `die()` to `BUG()` for invalid string-list usage. The change affects two functions in string-list.c:

1. `string_list_split()` now uses `BUG()` when called with `.strdup_strings` unset
2. `string_list_split_in_place()` similarly uses `BUG()` when called with `.strdup_strings` set

The patch maintains the same error message text for now triggers Git's BUG() mechanism rather than die() for these programmer errors. This aligns with Git's convention of using BUG() for internal API misuse rather than die() which is more suited for user-facing errors. The change is straightforward with no behavior impact beyond the error reporting mechanism, and fits into the larger series' goal of cleaning up and documenting the string-list API. The commit message notes the error message could be more concise but leaves that for future improvement.
