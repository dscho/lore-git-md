This is a refactoring patch in a series about improving Git's help system behavior. It focuses on making the parse-options.c code more readable by replacing magic numbers with named constants for usage flags.

The patch introduces four new `#define` constants in parse-options.c to clarify the boolean parameters passed to `usage_with_options_internal()`:
- `USAGE_NORMAL` (0) vs `USAGE_FULL` (1) for help output verbosity
- `USAGE_TO_STDOUT` (0) vs `USAGE_TO_STDERR` (1) for output destination

The author notes that while Junio C Hamano preferred keeping the "0" case short, they opted for more explicit names to improve readability at call sites. The patch updates all callers of `usage_with_options_internal()` to use these new constants, maintaining identical behavior while making the code's intent clearer.

This change is part of a larger effort to improve Git's help system (particularly `-h` and `--help-all` behavior) but stands as an independent readability improvement.
