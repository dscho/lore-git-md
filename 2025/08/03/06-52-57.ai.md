This is part 5 of Junio Hamano's ongoing string-list API refactoring series, specifically converting interactive clean command's pattern filtering to use the modern string_list_split_in_place_f() API. The patch continues the series' pattern of replacing strbuf-based string processing with safer, more maintainable string_list alternatives.

The change focuses on filter_by_patterns_cmd() in builtin/clean.c, which handles interactive pattern exclusion during git-clean operations. The key technical changes are:
1. Replaces strbuf_split_max() with string_list_split_in_place_f()
2. Eliminates manual string trimming via STRING_LIST_SPLIT_TRIM flag
3. Removes strbuf_list_free() in favor of string_list_clear()
4. Simplifies the loop structure using string_list_item access
5. Maintains identical functionality while reducing buffer management code

The conversion follows the established pattern seen in earlier patches of the series, applying the string_list API's safety and simplicity benefits to interactive user input processing. The patch demonstrates how the API can handle real-time user input parsing while eliminating manual memory management. This continues the series' theme of providing type-safe, maintainable alternatives to older string processing patterns across Git's codebase.
