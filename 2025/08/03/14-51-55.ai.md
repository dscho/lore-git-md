This is a bugfix patch addressing inconsistent behavior of content-ignoring diff options (`-I<regex>`, `-w`, etc.) across different output formats. The patch implements a new `diffcore_ignore()` mechanism that filters out file pairs containing only ignorable changes before output, ensuring consistent behavior between metadata outputs (`--name-only`, `--name-status`) and content-based outputs (`--stat`, `-p`).

The implementation introduces a new `diffcore-ignore.c` file with logic to:
1. Check file pairs for ignorable changes using xdiff with the specified ignore patterns
2. Preserve existing behavior for unmerged, binary, and mode-changed files
3. Maintain backward compatibility for machine-readable formats (`--raw`, `--check`)
4. Handle all content-ignoring options consistently via the `diff_from_contents` flag

The patch includes comprehensive tests in t4013 and t4015 verifying:
- Basic functionality with `-I<regex>`
- Interaction with whitespace options (`-w`, `--ignore-space-at-eol`, `--ignore-space-change`)
- Correct behavior with `--stat` and `--name-status` outputs
- Preservation of existing behavior for `--raw` and `--check` formats

This represents Lidong Yan's proposed `diffcore_ignore()` approach from the ongoing thread discussion, addressing Junio's design principles while providing consistent user experience. The implementation carefully handles edge cases like textconv and binary files while maintaining performance by only running the content check when needed for metadata outputs.
