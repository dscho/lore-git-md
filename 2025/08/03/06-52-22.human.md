This is the 6/7 patch in Junio Hamano's v4 string-list API refactoring series, adding a new flag to skip empty string pieces when splitting. The patch introduces STRING_LIST_SPLIT_NONEMPTY which, when set, prevents empty strings from being added to the resulting string list after splitting.

The change is straightforward - it adds a check in append_one() to skip adding the string if it's empty (when end <= p) and the NONEMPTY flag is set. The patch includes tests demonstrating the new behavior with various delimiter patterns, including combinations with the existing TRIM flag. This continues the series' pattern of adding useful functionality while maintaining consistency between the in-place and copying split variants.

The implementation looks clean and well-tested, with the new flag following the same pattern as previous additions to the API. This is a logical extension of the string-list splitting functionality that could simplify callers that currently filter out empty strings after splitting. The patch fits naturally with the series' goal of unifying and enhancing the string-list API.
