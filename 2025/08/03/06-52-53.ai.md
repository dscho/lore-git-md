This is a refactoring patch in Junio Hamano's ongoing string-list API modernization series, specifically converting wt-status.c's abbrev_oid_in_line() from strbuf_split to string_list_split.

The change replaces a strbuf-based string splitting approach with the newer string_list API for processing rebase todo list lines. The function abbreviates object IDs in commands like "pick <oid> title" while preserving the rest of the line. The key technical changes are:

1. Replaces strbuf_split_max() + manual trimming with a single string_list_split() call
2. Simplifies the string reconstruction by using strbuf_addf() directly with string_list items
3. Removes intermediate strbuf allocations and manual buffer management
4. Maintains identical functionality while reducing code by 11 lines (21 deletions vs 10 additions)

The patch demonstrates the series' goal of eliminating unnecessary strbuf operations where string_list's built-in functionality suffices. This particular conversion is straightforward since the split strings are only used for read access before being reassembled, making strbuf's mutability features unnecessary overhead.

The change affects rebase todo list display in wt-status subsystem, with no user-facing behavior modification. It builds on the string_list_split() improvements from earlier in the series, particularly the ability to limit splits and handle whitespace consistently.
