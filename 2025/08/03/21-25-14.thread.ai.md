This Windows platform compatibility patch series addresses regressions in mingw_rename() and upstreams mature Git for Windows patches across five patches, focusing on filesystem operation improvements. The core issues involve POSIX-semantics changes to mingw_rename() that broke functionality on pre-Windows 11 systems using ReFS and Windows Server 2016, along with directory handling improvements and handle inheritance modernization.

Johannes Schindelen contributes three patches: (1) removing an obsolete Windows 7 workaround, (2) adding ReFS support for Windows 2022 (handling ERROR_NOT_SUPPORTED and ERROR_INVALID_PARAMETER for ReFS volumes), and (3) restoring Windows Server 2016 compatibility. Matthias Aßhauer provides the fourth patch improving mingw_open_existing() directory handling by adding FILE_FLAG_BACKUP_SEMANTICS for directory access via CreateFileW(). The fifth patch (also from Schindelen) completes the Server 2016 support by adding ERROR_INVALID_FUNCTION to mingw_rename()'s fallback conditions, fixing "Function not implemented" errors during operations like git init.

Technical changes focus on compat/mingw.c, with 172 lines modified overall (146 removed, 26 added). Key modifications include: Windows version-specific workaround removal (including core.restrictinheritedhandles), ReFS/Server 2016 compatibility restoration (covering ERROR_NOT_SUPPORTED, ERROR_INVALID_PARAMETER, and now ERROR_INVALID_FUNCTION cases), proper directory access flag handling with fallback logic, and simplified handle inheritance. The implementation preserves existing error patterns while fixing real-world breakages including GitHub issues #5427 (ReFS) and #5695 (Server 2016).

All patches originate from production-tested Git for Windows improvements and appear ready for merging with no outstanding objections. The series collectively improves Git's Windows filesystem operation reliability across Windows versions (7 through 2022) and filesystems (NTFS, ReFS) while maintaining backward compatibility and removing obsolete code. The changes demonstrate a pattern of streamlining Windows compatibility code by removing dead paths while preserving important real-world behaviors like antivirus workarounds and filesystem-specific error handling.
