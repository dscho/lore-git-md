Performance optimization patch replacing a list-based priority queue with Git's `prio_queue` in the `describe` command. This is part 1 of a 2-patch series.

The change replaces the commit list maintained by `commit_list_insert_by_date()` with a more efficient `prio_queue` implementation, avoiding quadratic worst-case complexity. The patch includes benchmark results showing a 29% speed improvement when describing a range of 4751 commits (v2.41.0 to v2.47.0).

Key technical changes:
- Introduces new helper function `all_have_flag()` to check flags across queue items
- Modifies `finish_depth_computation()` and `describe_commit()` to use `prio_queue` operations (`prio_queue_put`, `prio_queue_get`, `clear_prio_queue`)
- Maintains same functionality while changing the underlying data structure
- Includes proper cleanup with `clear_prio_queue()`

The implementation appears thorough, with careful attention to maintaining existing behavior while improving performance. The benchmark results provide clear evidence of the improvement, and the commit message explains both the technical change and its motivation well. This seems like a straightforward performance win with no obvious downsides.
