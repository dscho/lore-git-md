Refactoring patch for trailer processing infrastructure, part of Phillip Wood's `git rebase --trailer` feature series (v3 1/2). This preparatory patch moves trailer handling from an external `interpret-trailers` helper into core Git functionality.

The key change is introducing a new trailer_process() function in trailer.c that handles all trailer operations in-process, eliminating the fork/exec to `git interpret-trailers`. The existing amend_file_with_trailers() is reimplemented to use this new infrastructure. The builtin/interpret-trailers.c command is simplified to become a thin wrapper around trailer_process().

Behavior remains identical to the forked version, verified by passing the full test suite. The patch includes comprehensive internal API changes:
- New trailer_process() handles all trailer operations in one call
- parse_trailer_args()/free_new_trailer_list() helpers for argument processing
- Streamlined amend_strbuf_with_trailers() implementation
- Maintains all existing functionality (in-place editing, stdin/stdout handling)

This appears to be a well-executed refactoring that cleanly separates concerns while maintaining backward compatibility needed for the subsequent `rebase --trailer` patch. The changes are focused and the commit message clearly explains the transformation of the code paths.
