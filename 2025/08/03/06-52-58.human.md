Refactoring patch in Junio Hamano's string-list API modernization series (part 6/12). This continues the systematic conversion of string splitting code from older strbuf-based approaches to the newer string_list API.

The patch updates `builtin/merge-tree.c` to use `string_list_split_in_place_f()` for parsing merge instructions from stdin, replacing the previous `strbuf_split()` approach. Key changes include:

1. The new version automatically handles whitespace trimming via the STRING_LIST_SPLIT_TRIM flag, eliminating manual `strbuf_rtrim()` calls
2. Error checking is simplified by checking `split.nr` (number of items) rather than array indexing
3. Memory management is cleaner with `string_list_clear()` replacing `strbuf_list_free()`

The conversion maintains all existing functionality while making the code more robust and consistent with the broader string-list API improvements seen throughout this series. This follows the established pattern of the series by removing redundant strbuf management while preserving behavior.

As with previous patches in the series, this demonstrates the API's benefits in real-world usage - here simplifying input parsing in a core command while eliminating error-prone manual string manipulation. The change is well-contained and follows the established conversion patterns reviewers have already approved in earlier patches.
