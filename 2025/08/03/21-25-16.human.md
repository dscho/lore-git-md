Windows platform compatibility patch removing obsolete Windows 7 support while preserving important fallback behavior.

This is the second patch in a series improving Windows filesystem operations. Johannes Schindelin removes code that was specifically maintaining compatibility with Windows 7, since Git for Windows dropped support for Windows 7/8 after v2.46.2. The patch eliminates a configuration option (`core.restrictinheritedhandles`) and simplifies the handle inheritance logic in `compat/mingw.c`.

The key change keeps the fallback behavior that retries process creation without handle restrictions when the first attempt fails. This has proven useful in cases where security software like Windows Defender temporarily locks files. The patch removes about 70 lines of version-checking and warning code while maintaining the core functionality's reliability.

The changeset appears well-considered, preserving real-world useful behavior while cleaning up obsolete code. Since it comes from production-tested Git for Windows improvements and is part of a coordinated series, it seems ready for integration.
