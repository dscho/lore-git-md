Feature patch implementing `--trailer` option for `git rebase`, part of a series moving trailer handling into Git's core. This is the second patch in v3 of the series originally authored by Phillip Wood, though this particular implementation comes from Li Chen.

The patch adds a `--trailer` option to `git rebase` that appends specified trailers (like Signed-off-by) to each rebased commit. Key technical aspects:
- Only works with merge/interactive backends (rejects apply/am backend early)
- Automatically enables `--force-rebase` when trailers are specified
- Validates trailer syntax before starting rebase (rejects empty trailers/missing keys)
- Preserves existing trailers while adding new ones
- Comprehensive test coverage in new t3440 (backend validation, conflict handling, root commits, duplicate handling)
- Stores trailer args in rebase state directory for continuation after conflicts
- Uses new in-process trailer infrastructure from first patch in series

The implementation appears thorough, with careful attention to edge cases and backward compatibility. The test suite covers normal operations, conflicts, root commits, and invalid inputs. This builds on the refactored trailer processing from the first patch, demonstrating the new in-process trailer handling capabilities.
