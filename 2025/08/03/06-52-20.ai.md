This is part 4/7 of Junio Hamano's string-list API refactoring series, introducing a new trimming capability to the string splitting functions. The patch adds a STRING_LIST_SPLIT_TRIM flag that automatically trims whitespace from both ends of each split string before adding it to the list.

The implementation modifies the internal split_string() helper to handle left-trimming (in the main loop) and right-trimming (in append_one()), with new _f-suffixed wrapper functions (string_list_split_f() and string_list_split_in_place_f()) exposing the flag to callers. The existing non-_f functions remain unchanged for compatibility. Test cases demonstrate the trimming behavior with various whitespace patterns, including edge cases like empty strings and maxsplit limits.

This builds on the series' earlier unification of the split functions while maintaining the distinction between copying and in-place variants. The change is mechanical and well-tested, with 64 lines of unit tests covering the new functionality. As with previous patches in the series, this is an internal refactoring with no user-facing impact, continuing the pattern of adding capabilities through flags while preserving existing behavior.
