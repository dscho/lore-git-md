This is a test modernization patch that completes the automation of help output testing for Git commands outside a repository context. It's part of a v5 3-patch series implementing Junio Hamano's proposed strategy for organizing help tests, following up on Patrick Steinhardt's original idea.

The patch replaces manual `-h` flag tests with an automated loop that checks all main commands via `git --list-cmds=main`. This ensures comprehensive coverage of help output behavior when commands are run outside a Git repository, while automatically including any new commands added in the future. The implementation handles exceptions through a case statement that marks certain commands (like `p4`, `pickaxe`, and script-based commands) as expected failures.

Key technical details include:
- Suffix stripping (`.sh`, `.perl`) to normalize command names
- A comprehensive exception list covering known problematic commands
- Consistent use of exit code 129 and usage pattern matching
- Removal of now-redundant manual tests for `update-server-info` and `prune`

The patch builds on previous work that moved repository-dependent help tests back to command-specific test files, leaving t1517 focused exclusively on outside-repo behavior. It represents the final implementation of the automated testing approach after several iterations, with the exception list refined through earlier discussion. The Windows-specific handling of `instaweb.sh` remains a separate edge case being addressed independently.
