Platform compatibility patch removing Windows 7-specific handle inheritance restrictions while preserving fallback behavior. This is the second in a series of four Windows filesystem operation improvements.

The patch removes code that made handle inheritance restrictions optional on Windows 7 and later, since Git for Windows no longer supports Windows 7/8. It keeps the fallback logic that retries without restrictions when ACCESS_DENIED occurs, which has proven useful for cases like antivirus software locking files. The change eliminates 70 lines of version-specific handling while maintaining the core functionality's robustness.

Technical changes include removing the `core.restrictinheritedhandles` config option and associated version-checking logic in `compat/mingw.c`. The fallback path remains but is simplified, dropping Windows 7-specific error detection and verbose warning messages that previously suggested filing bug reports. The implementation continues using `InitializeProcThreadAttributeList` for handle restriction when possible, silently falling back to unrestricted inheritance if that fails.

This change builds on the thread's theme of streamlining Windows compatibility code by removing obsolete version checks while preserving important real-world behaviors.
