Refactoring patch in a series improving Git's help system. This is part 2 of 3 in the final version of a series that makes `-h` and `--help-all` work consistently outside repository contexts.

The patch replaces magic numbers in `parse-options.c` with clearly named constants (`USAGE_NORMAL`, `USAGE_FULL`, `USAGE_TO_STDOUT`, `USAGE_TO_STDERR`) for the flags passed to `usage_with_options_internal()`. This improves code readability without changing behavior, making it easier to understand calls that previously used obscure "0, 1" style arguments.

The changes are mechanical but well-contained, touching only the parse-options implementation while updating all call sites to use the new constants. This refactoring supports the series' broader goal of standardizing help behavior while maintaining special cases for commands like `ls-remote` and `grep`.

The patch follows the thread's consensus approach after earlier security concerns were addressed, and it builds on test infrastructure from the ua/t1517-short-help-tests branch. The implementation looks clean and focused, with no apparent loose ends.
