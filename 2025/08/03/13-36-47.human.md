This is a discussion about the proposed SMTP autoconfiguration feature for `git send-email`. Julian Swagemakers provides feedback on Aditya Garg's v2 patch that adds `--get-smtp-server` functionality.

The discussion focuses on several potential improvements to the implementation:
1. Suggests reordering the fallback sequence to check the provider's autoconfig URL before Mozilla's ISPDB, matching Thunderbird and aerc's behavior
2. Proposes adding support for the `.well-known/autoconfig/mail/` standard path
3. Notes a typo in the commit message ("inpired" -> "inspired")
4. Recommends warning users when falling back to unencrypted 'plain' connections
5. Suggests enhancing the output to include copy-paste commands for applying the settings
6. Proposes processing authentication details from the XML config, including OAuth2 references
7. Recommends using `user.email` from gitconfig as a default rather than prompting
8. Suggests improving the error message when no server is configured to point users to the new option

The feedback appears constructive and well-researched, referencing implementations in Thunderbird and aerc. The suggestions would make the feature more user-friendly and aligned with existing email client behavior. No major objections to the feature itself, just refinements to the implementation details.
