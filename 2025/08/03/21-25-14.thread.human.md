This thread addresses a series of Windows platform compatibility patches that fix regressions in Git's filesystem operations, particularly affecting Windows Server 2016 and ReFS support. The changes originated from production-tested improvements in Git for Windows, with Johannes Schindelen contributing most of the patches and Matthias Aßhauer providing one key fix.

The core issue involved POSIX-semantics changes to `mingw_rename()` that broke basic operations like `git init` on Windows Server 2016, causing "Function not implemented" errors when writing config files. The series systematically addresses these problems while removing obsolete Windows 7 workarounds. The final patch adds `ERROR_INVALID_FUNCTION` to the error codes triggering fallback behavior in `mingw_rename()`, completing the robust error coverage that now handles `ERROR_INVALID_PARAMETER` and `ERROR_NOT_SUPPORTED` as well.

All patches focus on `compat/mingw.c`, with the series collectively improving Git's reliability across Windows versions 7 through 2022 and filesystems (NTFS, ReFS). The changes maintain backward compatibility while streamlining the code by removing dead paths. With no outstanding issues raised, the series appears ready for merging, having addressed real-world breakages reported in GitHub issues #5427 and #5695.
