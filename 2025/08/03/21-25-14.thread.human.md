This thread concerns a Windows platform compatibility patch series that has already been accepted for merging into Git's master branch. The 4-patch series, contributed by Johannes Schindelen and Matthias Aßhauer, addresses filesystem operation regressions across various Windows versions (7 through 2022) and filesystems (NTFS, ReFS). The changes remove obsolete Windows 7 workarounds, improve ReFS support, restore Server 2016 compatibility, and enhance directory access handling - all changes that have been thoroughly tested in Git for Windows.

While the series has maintainer approval and is considered production-ready, Oswald Buddenhagen has raised questions about the security implications of removing Windows 7-specific file handle inheritance restrictions in PATCH 2/4. He suggests the commit message could better document the safety considerations, particularly regarding potential security vulnerabilities from unintended handle inheritance. The discussion doesn't propose any code changes to the already-accepted series, but highlights areas where additional documentation might help future readers understand the security model assumptions. Given that these changes have been extensively tested in Git for Windows, the concerns appear to be more about documentation completeness than functional issues.
