This is a refactoring patch in Junio Hamano's ongoing string-list API modernization series (now at 12 patches). It simplifies subprocess status reading in `sub-process.c` by replacing an over-engineered string splitting approach with a direct prefix check.

The change replaces `strbuf_split_str()` with a simpler `skip_prefix()` check when parsing "status=<foo>" lines from subprocess communication. Instead of splitting the line into two strbufs and comparing the first part to "status=", it now directly checks for the prefix and uses the remainder as the status value. This eliminates memory allocations and cleanup for the temporary string buffers.

The patch follows the series' pattern of replacing complex string processing with simpler, more direct approaches where appropriate. It reduces the function from 15 to 6 lines while maintaining the same behavior (last "status=" line still wins). This is part of the broader effort to modernize Git's string handling code for better safety and maintainability.
