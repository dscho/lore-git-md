This thread addresses a bug in `git archive` where creating zip archives containing certain large files could fail with a "deflate error (0)". The issue occurs in the streaming deflation path when `core.bigFileThreshold` is set to force more files through this code path, as was the case when archiving large Chromium source files.

The root cause was an incorrect assumption in `archive-zip.c` that `git_deflate()` with Z_FINISH would always complete in a single pass. The zlib documentation actually specifies that when the output buffer is too small, multiple calls may be needed before receiving Z_STREAM_END. The patch fixes this by restructuring the deflation logic into a proper loop that continues until Z_STREAM_END is received, while maintaining proper buffer management and compressed output writing.

The solution appears sound and well-justified with reference to zlib's specifications. While the reporter provided a specific reproduction case using Chromium sources, the fix should benefit anyone using `git archive` with large files when the streaming deflate path is active. The patch maintains all existing CRC and size accounting while properly handling the partial output case that could previously cause failures.
