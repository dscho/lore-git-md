This thread addresses a bug in `git archive` where creating zip archives could fail when deflating certain large files, particularly when `core.bigFileThreshold=1` forces more files through the streaming deflate path. The issue stems from incorrect assumptions in `archive-zip.c` about zlib's behavior when the output buffer is too small.

Justin Tobler originally identified and fixed the problem by restructuring the deflation into a do-while loop that properly handles zlib's Z_OK return code when the output buffer fills. René Scharfe, who wrote the original code, confirmed the bug and approved Justin's solution, though he noted the buffer sizing assumptions that led to the issue.

Toon Claes has now joined the discussion with additional test data from the Chromium repository and an alternative implementation that more closely follows zlib's official example code. His version uses nested loops and better handles edge cases where the buffer size exactly matches the input size, though it's more complex than Justin's minimal fix. Claes presents both approaches neutrally, seeking feedback on which direction to pursue.

The technical consensus remains that the core issue needs fixing, with two valid solutions now proposed: Justin's simpler approach (already has René's approval) and Toon's more comprehensive refactoring that better matches zlib's documentation. The thread is currently shifted to evaluating these implementation choices while maintaining the focus on robust testing and correctness.
