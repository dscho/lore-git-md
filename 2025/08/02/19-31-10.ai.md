Bugfix targeting fsck behavior in blobless clones with fsckObjects enabled.

Jeff King confirms the reproduction of the fetch failure in blobless clones when `fetch.fsckObjects` is enabled, identifying the root cause as index-pack incorrectly failing when encountering missing blobs that are intentionally omitted due to the blob filter. The issue occurs during fsck's tree walk when it encounters references to filtered-out blobs, triggering an object verification failure despite these objects being legitimately absent in a partial clone.

The technical analysis reveals that while the `--promisor` flag is correctly passed to index-pack (indicating this is a partial clone transfer), the fsck verification still fails for missing blobs. Jeff proposes a potential fix in `builtin/index-pack.c` that would mark promisor objects as checked when verification fails, but notes concerns about the performance impact of additional `is_promisor_object()` checks and seeks input from Jonathan Tan (original author of related code) on the proper solution.

This moves the discussion from reproduction to potential fixes, with the core question being whether the solution should modify fsck's behavior for promisor objects (as proposed) or if there's a deeper protocol-level issue in how servers handle base objects during partial clone fetches. The thread appears to be converging on recognizing this as a genuine bug in the interaction between partial clones and object verification.
