This is a follow-up discussion on Junio Hamano's string-list API refactoring series, specifically addressing patch 2/7 which aligns string_list_split() with its _in_place() counterpart by allowing multiple delimiter characters.

Jeff King responds to Junio's commit message note about the "unknown reason" for the inconsistency between the two functions. He traces the divergence back to commit 52acddf36c from 2023, which added multi-delimiter support to string_list_split_in_place() for strtok() replacement purposes but didn't update the original string_list_split(). Jeff speculates this was likely due to oversight, lack of immediate need, or reluctance to update callers, though the original motivation wasn't documented.

The email serves as a historical clarification rather than requesting changes, with Jeff explicitly stating no re-roll is needed. This discussion provides useful context about the evolution of these APIs but doesn't introduce new technical concerns or require action on the series, which has otherwise reached consensus on all major design points. The exchange demonstrates the careful attention to API consistency in Git's development, even for historical quirks.
