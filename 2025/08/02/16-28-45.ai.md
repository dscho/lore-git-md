This is a technical discussion about the final patch in a series expanding Git's help option handling, now likely to be dropped due to both security concerns and implementation issues.

Jeff King confirms and expands on D. Ben Knoble's assessment that patch 4 (enabling `-h`/`--help-all` mid-command) has fundamental technical problems. The key issue is that the current implementation would break for hypothetical future commands needing both repository setup (RUN_SETUP) and `-h` support, since help detection happens before option parsing. Jeff notes this would either require awkward future tightening or new signaling mechanisms.

He also shares Junio C Hamano's security concern about loosening the conservative "asking for help" detection rules. The discussion reveals the patch was built on a test branch (ua/t1517-short-help-tests) that requires merging to master for proper application, explaining earlier patch application failures.

The exchange solidifies the emerging consensus to drop patch 4 entirely while keeping patches 1-3, as the remaining issues appear unresolvable without deeper architectural changes. Jeff's analysis confirms the technical inconsistencies D. Ben Knoble identified, particularly around RUN_SETUP interactions and parse-options API consistency. The thread shows the series narrowing to its uncontroversial core while shelving the more complex behavioral change.
