This is a documentation refinement in the ongoing string-list API refactoring series. Junio Hamano responds to Jeff King's suggestion to clarify the meaning of "trim" in the STRING_LIST_SPLIT_TRIM flag documentation. 

The exchange confirms that the flag's current implementation matches Jeff's first interpretation - it trims whitespace from each piece before adding to the list, rather than trimming excess delimiters. Junio acknowledges this should be made explicit in the enum documentation, noting that while "trim" usually means whitespace removal in Git's codebase, there are exceptions that could cause confusion.

This is a minor but important clarification for the v3 series, which has otherwise reached technical consensus. The change doesn't affect functionality but will help future developers understand the API's behavior. The series remains on track for merging with this final documentation tweak.
