Bugfix for zip archive generation when deflating large files. This patch addresses an issue where `git archive` could fail with a "deflate error (0)" when creating zip archives containing certain large files. The problem occurs in `archive-zip.c`'s `write_zip_entry()` function when using stream input for deflation.

The core issue is that the code incorrectly assumes `git_deflate()` with Z_FINISH will always return Z_STREAM_END in a single pass. According to zlib documentation, when the output buffer is too small, it's valid for `deflate()` to return Z_OK, requiring additional calls until Z_STREAM_END is received. The patch modifies the code to properly handle this case by implementing a loop that continues deflating until Z_STREAM_END is returned.

The reporter found this issue specifically when archiving a large Chromium source file with `core.bigFileThreshold=1`, which forces more files to use the streaming deflate path. The fix involves restructuring the deflation loop to properly handle partial outputs and buffer management, while maintaining the same compressed output writing behavior.

Key technical changes:
- Replaces single `git_deflate()` call with a do-while loop continuing until Z_STREAM_END
- Moves compressed output writing inside the loop to handle partial results
- Maintains same buffer management but with proper error checking
- Preserves existing CRC and size accounting

The patch appears well-justified with reference to zlib documentation and includes a reproduction case, though the author notes uncertainty about more general testing approaches. This seems like a legitimate edge case in the zip archive generation that could affect users archiving large files.
