Bugfix for zip archive generation when compressing large files. Justin Tobler addresses an issue where `git archive` could fail with a deflate error when creating zip archives of certain large files, specifically when using stream compression (triggered by setting `core.bigFileThreshold` low).

The patch fixes incorrect handling of the zlib deflate stream in `archive-zip.c`. The current code assumes a single `git_deflate()` call with Z_FINISH will always return Z_STREAM_END, but per zlib documentation, it may need multiple calls when the output buffer is too small. The fix properly loops until Z_STREAM_END is received.

The issue was discovered when archiving a specific large file from the chromium repository. While the patch resolves that case, the problem could theoretically affect any sufficiently large file where the compressed output doesn't fit in the buffer in one pass. The commit includes a helpful reproduction recipe using chromium.git.

The change is well-justified with zlib documentation references and maintains the existing error handling while making it more robust. This appears to be a straightforward correction of a real edge case bug in archive generation.
