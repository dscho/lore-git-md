This is a refactoring patch in a series modernizing Git's string handling by replacing `strbuf_split*()` calls. It addresses a memory safety issue in `builtin/clean.c` where passing a `strbuf` by value could lead to double-free bugs if reallocation occurs.

The patch fixes the immediate issue by passing the `strbuf` by pointer instead of by value, preventing potential dangling pointers. Junio C Hamano acknowledges Jeff King's suggestion to go further by passing just the string buffer rather than the full `strbuf` struct, but chooses to keep this as a separate lesson about struct passing for now.

The discussion highlights two complementary best practices: avoiding dangerous struct-by-value passing, and only passing what a function actually needs. While this patch focuses on the first principle, the thread suggests both approaches have merit and may be addressed sequentially. The change is part of a larger, well-received series that's systematically improving string handling safety across Git's codebase.
