This is a follow-up in an ongoing bug investigation about blobless clones failing when fetching from newly added remotes. Jeff King responds to Justin Su's original bug report where a blobless clone (`--filter=blob:none`) failed with "did not receive expected object" errors during fetch operations from a second remote.

Jeff notes he cannot reproduce the issue locally but hypothesizes it might be server-dependent - perhaps relating to delta compression against blobs from the original remote that aren't present in the blobless clone. He asks if the issue persists for the original reporter, suggesting the behavior might vary based on server-side repository state (like repacks or new pushes).

The exchange shows active debugging of a tricky partial clone edge case where object expectations during fetches appear to break down. The thread remains open with no definitive root cause identified yet, but Jeff's response indicates the issue may be sensitive to repository states that aren't immediately reproducible.
