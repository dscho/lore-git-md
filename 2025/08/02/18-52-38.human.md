Bugfix proposal for pathspec validation inconsistency in `git grep`.

Jeff King responds to the ongoing discussion about `git grep`'s handling of exclude pathspecs with a proposed solution. His patch replaces the current ad-hoc pathspec validation in `check_filename()` with proper pathspec parsing using `parse_pathspec()`, which correctly handles the `:^:` syntax that was causing problems. The change makes `:^:Documentation` work as expected, matching `git ls-files` behavior.

However, the patch reveals a compatibility issue - it breaks existing tests that expect bare `:on` syntax to be treated literally rather than as a pathspec. Jeff notes this creates a dilemma: while the proper pathspec parsing is cleaner, it may break existing usage. He suggests a middle path - enhancing `check_filename()` to specifically handle the magic prefixes and trailing colons needed for exclude syntax, even if it's less elegant.

This email advances the technical discussion by providing a concrete implementation that solves the original issue but uncovers a deeper compatibility question. The core tension is between proper pathspec parsing (cleaner long-term) versus maintaining backward compatibility with existing usage patterns. Jeff's pragmatic suggestion leans toward targeted fixes for the problematic cases rather than a full pathspec parsing overhaul.
