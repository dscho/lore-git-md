This is a discussion about the controversial patch in a series that aims to make `-h` and `--help-all` work more consistently across Git commands. The patch in question (4/4) would allow `-h` to show help even when other arguments are present, but has raised security concerns.

Jeff King (Peff) digs into why `git grep -h` still works as expected (grepping rather than showing help) despite the changes, revealing that the behavior depends on which code path is taken in parse-options.c. He identifies two potential issues with the current approach: inconsistency between parse-option and non-parse-option callers, and a possible problem with repository-requiring commands that might show help too early.

The email also notes technical difficulties in applying the patch series, suggesting it may be based on unpublished work. This comes as the thread has already seen significant discussion about whether the final patch's behavior is desirable, with Junio C Hamano strongly opposing it on security grounds. The exchange highlights the complexity of changing help behavior while maintaining consistency and safety across Git's many commands.
