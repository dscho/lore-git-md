This is a technical follow-up in the ongoing discussion about making content-ignoring diff options (`-I`, `-w`) behave consistently across output formats. Jeff King (peff) responds to Junio's concerns about generalizing the solution beyond just `-I<regex>` and avoiding redundant diff operations.

The email proposes a concrete implementation approach that would apply content filtering consistently to all metadata outputs (`--name-only`, `--name-status`, etc.) by leveraging the existing `diff_from_contents` flag. The key idea is to run the full diff pipeline internally when needed to determine whether changes should be shown, while preserving the original output behavior.

Peff acknowledges the current implementation is "horribly hacky" but demonstrates it works for simple cases. He identifies several technical challenges that would need refinement:
- Avoiding repeated `/dev/null` file operations
- Properly handling different output types (suggesting `--raw` might deserve different treatment)
- Potential impacts on related options like `--stat` and `--dirstat`
- The fundamental tradeoff between running diffs twice versus buffering output

The email moves the discussion forward by showing a viable technical direction while clearly marking areas needing further work. It maintains the thread's focus on both fixing the UX inconsistency and respecting Git's performance constraints. The tone is collaborative, with peff positioning his contribution as a starting point for others to refine rather than a final solution.
