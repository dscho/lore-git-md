This is a follow-up discussion in the string-list API refactoring thread. Jeff King confirms Junio Hamano's observation that the multi-delimiter capability in string_list_split_in_place() was only used in test helpers, not in core Git code. 

Jeff had previously discovered this feature was added in commit 52acddf36c (2023) to replace strtok() calls, but now confirms through code search that all strtok() usage was indeed limited to test code. He humorously notes this reflects well on Git's code quality that strtok() didn't leak into production code.

The exchange serves as post-facto validation of Junio's design decision in the series to unify the string-list splitting APIs while preserving the multi-delimiter capability, even though its original motivation (replacing strtok() in production code) turned out to be less critical than initially thought. The discussion doesn't raise any new technical points or require any changes to the already-finalized patch series.
