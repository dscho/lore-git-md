Bugfix for fsck behavior in blobless clones. Jeff King follows up on the thread about fetch failures in blobless clones when fsck is enabled, providing both a minimal reproduction case and a proposed fix. The issue occurs when fsck encounters missing blobs that are legitimately omitted in a blobless clone (`--filter=blob:none`), incorrectly treating them as corruption.

The reproduction demonstrates how a fetch operation can fail when transferring objects that reference blobs intentionally excluded by the clone filter. King's proposed solution modifies `builtin/index-pack.c` to mark promisor objects (those that can be fetched on demand) as checked when verification fails, preventing the false corruption error.

The email includes a self-contained test case that creates a server repository with two commits, a fork that references an old blob, and shows the failure when fetching from the fork into a blobless clone with fsck enabled. This concrete example helps verify both the problem and the proposed solution.

While the patch resolves the immediate issue, King notes potential performance concerns with the additional `is_promisor_object()` check and seeks input from Jonathan Tan, the original author of related code. The discussion appears to be moving toward consensus that this is a genuine bug in fsck's handling of partial clones rather than expected behavior.
