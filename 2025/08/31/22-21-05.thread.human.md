This thread discusses the future of the legacy `git whatchanged` command, which shows commit history with diffs but has been discouraged in favor of `git log -p` for years. The discussion began with a user strongly advocating to keep the command due to personal workflow integration and muscle memory. 

A follow-up from Kristoffer Haugsbakk reinforces this position by showing another user's dependence on the command and connecting the discussion to broader debates about command deprecation strategies. The email references Jeff King's (Peff) suggestion about allowing aliases to shadow deprecated commands, potentially offering a compromise path forward. This positions the `git whatchanged` discussion as part of a larger conversation about how Git should handle legacy commands while maintaining backward compatibility.

While no maintainer has yet weighed in, the thread is building a case against deprecation by demonstrating real user reliance on the command. The discussion may shift toward exploring technical solutions like command shadowing rather than focusing solely on whether to keep or remove `git whatchanged`.
