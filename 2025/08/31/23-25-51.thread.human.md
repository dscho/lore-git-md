Brooke Kuhlmann started this thread seeking a way to safely synchronize Git stashes across multiple machines. The core challenge involves pushing stashes created with `git stash export --to-ref` to a remote, where they sometimes get rejected as non-fast-forward updates. Phillip Wood provided key technical analysis, identifying that the issue stems from stash refs lacking reflogs by default, which breaks the safety checks in `--force-with-lease`.

Brooke has now implemented Phillip's suggested solutions - enabling reflogs globally and setting up a custom fetch refspec for stashes. While this makes the synchronization work functionally, Brooke reports some rough edges: the push still shows rejection errors despite succeeding, and the reflog entries don't clearly reflect stash operations. The solutions work but reveal opportunities to improve the user experience through better error messages and documentation.

The thread has effectively answered the original question about how to make stash synchronization safe, with Phillip's technical guidance proving correct in practice. What remains are polish issues - making the behavior more intuitive and better documented. The discussion also leaves open whether `git stash export` should automatically create reflogs, which could simplify this workflow for future users.
