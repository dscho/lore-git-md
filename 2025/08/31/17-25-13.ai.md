This email continues the performance optimization discussion around data structure choices in `git describe`, specifically comparing khash-based approaches with commit-slabs and oidsets. René Scharfe responds to Jeff King's experiments with additional technical analysis and security considerations.

Key technical points:
- Clarifies that khash flags only use 2 bits per bucket (not a full uint32_t), addressing Jeff's earlier comment about storage overhead
- Expresses security concerns about using `oidhash()` directly, noting it could enable hash collision attacks (though impact would likely be limited)
- Validates Jeff's oidset approach with benchmarks showing no measurable performance difference from the custom khash implementation
- Agrees oidset is preferable when performance is equivalent, as it avoids custom hash type definitions
- Discusses potential for a generalized "objset" abstraction but notes measurement challenges
- References Jeff's historical use of commit-slabs' dynamic sizing feature in `--contains` optimization work
- Suggests dynamic sizing could be useful for `describe`'s `--max-candidates` if expanded

The email reinforces the thread's emerging consensus that oidset provides the right balance of simplicity and performance for this specific `describe` use case, while acknowledging context-dependent tradeoffs between different data structures.
