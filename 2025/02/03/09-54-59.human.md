Performance monitoring proposal: Patrick Steinhardt shares GitLab's setup for continuous benchmarking of Git performance and gauges community interest in making this an official project effort.

The email describes GitLab's current system that runs daily benchmarks against Git's `master` and `next` branches using hyperfine-based tests outside the Git repository, with results uploaded to Bencher for analysis and alerting. While this provides some visibility into performance changes, the author acknowledges limitations like inconsistent CI environments and the single-maintainer nature of the setup.

Steinhardt proposes several potential next steps for community adoption: expanding Git's existing performance tests, creating tools to upload perf data to Bencher, establishing dedicated benchmarking infrastructure (rather than relying on CI), and setting up mailing list alerts. The proposal is framed as exploratory - the author explicitly welcomes all feedback including disinterest, noting GitLab would continue maintaining their private setup if the community prefers.

This appears to be a serious, well-motivated proposal from an active contributor, addressing a clear need for better performance regression detection. The current implementation seems functional but preliminary, and the email thoughtfully outlines what would be needed for a more robust community solution. The tone is collaborative, seeking input rather than pushing a specific agenda.
