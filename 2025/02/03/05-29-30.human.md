This is a follow-up discussion on patch 2/3 of Patrick Steinhardt's series fixing repository reinitialization with different formats. The patch prevents `GIT_DEFAULT_REF_FORMAT` from overriding an existing repository's ref storage format during reinitialization, which could otherwise lead to corruption.

Junio had suggested adding a warning when the environment variable is ignored, but Patrick argues against this. His reasoning is that environment variables should only set defaults, not force changes to existing repositories, and that silent ignoring is appropriate here (unlike command-line arguments which should fail explicitly). He also rejects the idea of automatic ref backend migration during initialization, preferring explicit user action for such risky operations.

The exchange shows consensus on the core protection mechanism but differing opinions on user feedback. Patrick's position aligns with how Git handles similar configuration defaults, maintaining that environment variables shouldn't trigger disruptive actions implicitly. The discussion reinforces that this is a safety measure first and foremost, with the series now complete and approved.
