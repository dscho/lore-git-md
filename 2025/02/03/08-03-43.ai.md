This is part of Patrick Steinhardt's ongoing series to decouple the reftable library from Git core infrastructure, specifically addressing the removal of Git-specific utility functions.

The patch replaces the Git-specific `sleep_millisec()` function with a direct call to `poll()` in reftable/stack.c. This change occurs in the retry logic for reloading reftable stacks, where random delays are used between attempts (using the newly introduced `reftable_rand()` from earlier in the series). The commit explains that while a more direct millisecond sleep would be ideal, POSIX's `poll()` serves as the closest portable alternative.

The change is mechanical and maintains the same behavior - the delay calculation remains identical, only the underlying sleep implementation changes. This continues the series' pattern of removing Git dependencies while preserving functionality. The patch is small (1 line changed) and focused, with no apparent behavioral impact beyond the architectural decoupling goal.

Key technical details for future reference:
- Location: reftable/stack.c, in `reftable_stack_reload_maybe_reuse()`
- Replaced function: `sleep_millisec()` (Git-specific) with `poll(NULL, 0, delay)`
- Context: Used in retry delay logic with random backoff
- Related to earlier `reftable_rand()` introduction in the series
- Maintains identical delay calculation formula
- Part of final push to remove remaining Git utility dependencies
