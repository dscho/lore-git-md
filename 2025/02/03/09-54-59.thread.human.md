### Thread Summary: Proposal for Continuous Benchmarking Infrastructure

Patrick Steinhardt (GitLab) has proposed establishing continuous benchmarking infrastructure for Git to detect performance regressions systematically. The GitLab team currently runs daily benchmarks against Git's `master` and `next` branches using hyperfine-based scripts via GitLab CI, with results visualized through Bencher. While functional, this external setup has limitations—CI noise causes variability, and the single-maintainer model poses sustainability risks.

The proposal outlines four steps to integrate this into Git proper: enhancing the existing `t/perf` framework, creating a Bencher adapter for perf output, setting up dedicated benchmarking hardware (to avoid CI inconsistencies), and configuring email alerts for regressions. This RFC explicitly seeks community input on whether to adopt the system as a project-maintained resource or continue with GitLab's external implementation. No patches are attached yet; the focus is on gathering consensus about the infrastructure approach before implementation begins.  

Key technical components under discussion include hyperfine for measurements, Bencher for visualization, and Git's `t/perf` framework as a potential foundation. The thread is positioned as an open invitation for feedback on the overall direction, particularly from maintainers and contributors who would interact with or maintain this infrastructure long-term.
