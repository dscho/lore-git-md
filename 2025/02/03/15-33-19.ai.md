This is a discussion about potential diff options metadata in commit messages, continuing from earlier thread exchanges about viewing context in diffs.

Jeff King responds to Junio Hamano's concerns about embedding diff options in commit trailers. The original idea was for a `Diff-options: -U10` trailer that would automatically apply when viewing commits, similar to the existing `Best-viewed-with` convention. However, both agree this could be problematic viewing preferences on others.

Key technical considerations raised:
- The proposal would affect commands like `format-patch` and `show` via `setup_revisions()`
- Per-path or per-hunk granularity might be needed for optimal usefulness
- Security concerns around arbitrary diff options being forced on users
- Alternative limited syntax like `Diff-context: 10` was considered but deemed insufficient
- Other potentially useful options like `--color-moved`, `-w`, and `--function-context` would need support

Jeff suggests this might work better as an interactive feature in tools like tig, where the trailer could serve as a micro-format for optional viewing modes rather than enforced defaults. This would avoid the security issues while still allowing authors to suggest helpful viewing contexts.

The discussion appears to be winding down this exploration path, with both participants recognizing the fundamental tension between author suggestions and viewer preferences that makes automated enforcement problematic.
