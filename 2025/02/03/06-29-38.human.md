This is the final patch in a series fixing atomic push exit code propagation, addressing a case where git-receive-pack errors weren't properly reported back to the pusher. The patch focuses on gracefully closing connections during atomic push failures.

The key change adds a `packet_flush(out)` call in `send-pack.c` when atomic push fails, ensuring git-receive-pack properly terminates rather than hanging. This fixes the root cause that was previously worked around by ignoring exit codes in `transport.c`. The patch also reverts that workaround since it's no longer needed.

Two test cases in t5543-atomic-push.sh that were previously marked as `test_expect_failure` are now passing and updated to `test_expect_success`, verifying that:
1. Atomic push correctly reports exit code failures
2. This works properly with the porcelain output format

The patch builds on earlier work in the series that introduced protocol-level error codes and transport layer fixes, now completing the solution with proper connection cleanup. The changes are focused and well-tested, with clear commit message explaining both the problem and solution.
