Feature patch in the `git backfill` series, adding sparse-checkout integration. This is patch 4/5 in v3 of the series, implementing the `--sparse` option to restrict downloads to paths matching the current sparse-checkout patterns. The patch builds on the path-walk infrastructure to efficiently skip non-matching paths in cone mode while still walking all paths in non-cone mode (only downloading matching blobs).

Key technical changes:
- Adds `--sparse` flag to `git backfill` that loads sparse-checkout patterns into a new `pattern_list` field in `path_walk_info`
- Extends path-walk API to respect sparse-checkout patterns, with different handling for cone mode (prunes non-matching directories) vs non-cone mode (walks all paths but only processes matching blobs)
- Makes `add_patterns_from_buffer()` public in dir.h for test helper usage
- Adds comprehensive tests covering both cone and non-cone modes, including negative patterns
- Documents the new option and updates API docs for the `pl` field in `path_walk_info`

Performance measurements show the sparse option significantly reduces download size compared to full clones (192MB vs 277MB for Git repo, 2.2GB vs 6GB for Linux kernel) while maintaining reasonable fetch times. The implementation cleanly integrates with existing batch size controls and handles both sparse-checkout modes appropriately.

The patch appears well-tested with trace2 verification of path walking behavior and object fetch counts. It completes the technical feedback from previous reviews in this series, leaving only the experimental flag discussion as an open question.
