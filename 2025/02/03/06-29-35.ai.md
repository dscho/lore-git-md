This is a test patch in the atomic push exit code propagation series, adding porcelain output verification for dry-run push operations. The patch introduces four new test cases in t5548-push-porcelain.sh that verify the machine-readable output format of `git push --porcelain` in dry-run mode, covering both regular and forced pushes with and without atomic operations. 

The tests validate that dry-run porcelain output correctly reports ref updates (including [up to date], [deleted], [new branch], [rejected], and forced updates) while ensuring no actual refs are modified. Each test case checks both the porcelain output and verifies the upstream refs remain unchanged. The implementation leverages the existing protocol-agnostic test infrastructure (setup_upstream_and_workbench, make_user_friendly_and_stable_output) that was refactored earlier in the series, now extended to handle dry-run scenarios.

Key technical details include:
- New run_git_push_dry_run_porcelain_output_test function handling both file and HTTP protocols
- Four test scenarios covering all combinations of --dry-run with --force and --atomic
- Verification that porcelain output matches expected format while refs remain unchanged
- Protocol-agnostic implementation using the existing URL_PREFIX handling
- Follows the series' pattern of comprehensive porcelain output verification

This builds on the series' prior work modernizing test infrastructure and ensuring proper error reporting, now extending coverage to dry-run scenarios. The tests confirm dry-run mode produces accurate porcelain output without side effects, which is particularly important for atomic push operations where the output must reflect what would happen in a real push.
