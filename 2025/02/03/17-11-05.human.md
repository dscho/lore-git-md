Feature patch introducing a `--min-batch-size` option for the new `git backfill` command, part of the PATH WALK series (v3 3/5). This patch adds configurable batching for blob downloads in partial clones, with extensive performance testing justifying the default value of 50,000 objects.

The commit provides detailed benchmark results across four repositories (Git, nodejs/node, microsoft/fluentui, and Linux), showing how different batch sizes affect packfile counts, total size, and operation time. The data reveals that smaller batches (5K-50K objects) often yield better compression ratios than larger ones, particularly in repositories with suboptimal packing. The microsoft/fluentui case demonstrates particularly dramatic improvements - a 348MB backfill with 5K batches versus 738MB for a full clone.

The implementation adds the new option to both documentation and code, with a new test case verifying the batch size behavior via trace2 events. The patch follows the series' established patterns and addresses all prior feedback, maintaining clean integration with the path-walk infrastructure. The thorough performance analysis strengthens the case for this being a useful tunable parameter, though the default seems well-chosen for most cases.
