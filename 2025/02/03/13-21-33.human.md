This is a project organization discussion about where to maintain Git's list of microprojects, emerging from the GSoC 2025 planning thread.

Junio Hamano responds to Patrick Steinhardt's suggestion to move the microprojects list into the main Git repository (as Documentation/Projects.txt) with some reservations. He's concerned this would create maintenance overhead, as frequent updates to a single file would lead to merge conflicts and require the usual "cook in 'next'" workflow. Instead, he proposes alternatives that would keep this documentation outside the main repository: either a separate Git branch (like the existing 'todo' branch) or a wiki.

The email reflects Junio's ongoing effort to delegate maintenance tasks where possible, noting that the project already has more patch contributors than reviewers. The discussion remains open-ended, with Junio inviting consideration of lighter-weight solutions that don't require core maintainer attention for routine updates. This fits into the broader GSoC thread's transition from policy debates to practical implementation questions.
