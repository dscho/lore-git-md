This is part of Patrick Steinhardt's ongoing series to decouple the reftable library from Git core infrastructure. The patch removes another Git-specific dependency by replacing `COPY_ARRAY()` with an open-coded equivalent in reftable/record.c.

The change does more than just swap out the macro - it also adds a guard against zero-sized array allocations, which could previously trigger a NULL pointer return and incorrect out-of-memory errors. The new implementation includes explicit size checking to prevent potential integer overflow when calculating the allocation size.

This is one of the final steps in the reftable decoupling effort, though as noted in the thread summary, there's still some discussion around memory safety implications of removing `COPY_ARRAY()`. The patch follows the established pattern of the series by maintaining identical behavior while removing Git-specific helpers.
