This is a protocol consistency fix in the atomic push error reporting series. The patch introduces a new error code `ERROR_SEND_PACK_BAD_REF_STATUS` (value 1) to distinguish reference status errors from other failures in `send-pack.c`, addressing a behavioral discrepancy between the smart protocol and HTTP transports.

The core issue is that `send_pack()` for the Git smart protocol would return -1 for bad ref statuses (like rejected non-fast-forwards), while HTTP transport's `push_refs_with_push()` would return 0. The patch makes `send_pack()` return the new specific error code, which `git_transport_push()` in transport.c then ignores to maintain consistency with HTTP behavior. This ensures uniform handling of ref status errors across protocols while still allowing `push_had_errors()` to detect failed refs later.

Key technical changes:
- New `ERROR_SEND_PACK_BAD_REF_STATUS` constant in send-pack.h
- Modified error handling in send-pack.c to use the new code instead of -1
- Transport.c now explicitly ignores this specific error to match HTTP behavior
- Improved documentation for `send_pack()` return values

The change is part of a larger series (now at v5) fixing atomic push exit code propagation, with this patch maintaining protocol consistency while preserving the ability to detect push failures through the ref status mechanism. The implementation follows careful review of transport behavior differences and maintains backward compatibility.
