Bugfix for `git repack --keep-unreachable` edge case when no packfiles exist. This is the second patch in a two-part series that addresses a crash scenario when using `--keep-unreachable` in repositories with no preexisting packfiles.

The patch fixes the logic that determines when to pass `--pack-loose-unreachable` to `git-pack-objects`. Previously, this option was incorrectly gated on the existence of other packfiles, even though loose objects can be packed regardless. The fix separates this condition from the packfile check while maintaining the other valid constraints (not creating a cruft pack and when redundant objects would be deleted).

The change is minimal (5 lines modified) but important for the edge case it handles. The accompanying test that was previously marked as `test_expect_failure` is updated to expect success, demonstrating the fix works. The commit message provides clear analysis of why the original conditions were problematic and which ones remain valid.

This appears to be a well-justified and cleanly implemented fix for a documented behavior that wasn't working in all cases. The patch builds on comprehensive test coverage added in the first patch of the series.
