This is a refactoring patch in Patrick Steinhardt's ongoing series to decouple the reftable library from Git core infrastructure. The patch replaces a `COPY_ARRAY()` macro call with an open-coded `memcpy()` equivalent in `reftable/record.c`, continuing the effort to remove Git-specific dependencies.

Justin Tobler raised a concern about potential integer overflow in the size calculation, noting that `COPY_ARRAY()` includes overflow protection via `st_mult()`. Patrick acknowledges this is theoretically unnecessary since the source record's allocation was already validated, but agrees to add the safety check anyway as a precaution.

The change is small (3 lines modified) and straightforward, though it touches a sensitive area dealing with memory copying. The discussion shows the careful attention to detail in this architectural separation work, with reviewers catching subtle safety implications even in simple-looking changes. This patch appears ready to proceed as part of the larger series, which has already addressed multiple rounds of review feedback.
