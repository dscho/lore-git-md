Maintainer feedback on quoting behavior for missing object reporting. This is part of the ongoing discussion about how `git rev-list` should report missing objects, specifically focusing on whether path quoting should ignore user configuration.

Junio Hamano questions the need for configuration-independent quoting in the machine-readable output from `rev-list --info`. He argues that since consumers must already handle quoted paths (including C-style escapes for special characters), varying output based on `core.quotePath` shouldn't be problematic. He suggests the current approach may be over-engineering, especially considering Git's long-term plan to change `core.quotePath` defaults.

The email specifically critiques patch 2/4 in Justin Tobler's series, which introduces a `QUOTE_PATH_IGNORE_CONFIG` flag. Junio proposes that instead of forcing consistent quoting, the tests could simply set a known `core.quotePath` value. He also raises broader concerns about whether non-ASCII bytes should always be quoted in this context.

This represents a significant design challenge to the patch series, coming from Git's maintainer. The feedback suggests the quoting approach may need substantial revision, though the core functionality of reporting missing objects with paths remains uncontroversial. Justin will need to either justify the current design or propose an alternative that addresses these concerns while maintaining the feature's goals.
