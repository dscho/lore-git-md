This is part of Patrick Steinhardt's ongoing series to decouple the reftable library from Git core infrastructure, specifically focusing on removing Git-specific error handling patterns.

The patch replaces Git's `st_mult()` overflow-checking helper in reftable array allocation macros with direct overflow detection. The key technical changes are:

1. Introduces a new `reftable_alloc_size()` helper that explicitly checks for size_t overflow before multiplication, returning -1 on overflow
2. Updates three allocation macros (REFTABLE_ALLOC_ARRAY, REFTABLE_REALLOC_ARRAY, and reftable_alloc_grow) to use this helper
3. Maintains the same memory safety properties but now returns NULL with ENOMEM on overflow rather than dying via BUG()
4. Preserves the existing allocation patterns (growth factor of 2x + 1 in reftable_alloc_grow)

The change is part of the broader effort to make reftable usable as a standalone library by removing all Git-specific dependencies. This particular patch addresses one of the last remaining Git-specific utilities (st_mult) while maintaining robust overflow checking. The implementation carefully preserves the existing error behavior (ENOMEM on failure) while eliminating the Git-specific die() path.
