Bugfix patch in the packed-refs validation series, addressing NUL character detection in refnames. This is part of the larger effort to improve `git fsck`'s validation of packed references.

Patrick Steinhardt reviews shejialuo's patch that catches a subtle corruption case where NUL bytes embedded in refnames could go undetected. The current code uses pointer arithmetic to determine refname length, which could miss NULs after a valid prefix. The proposed solution adds a check for embedded NULs before validating the refname format.

Steinhardt suggests simplifying the implementation by inlining the NUL check directly into `next_record()` rather than creating a new function, since the logic is simple and unlikely to be reused elsewhere. He also notes the ideal solution would be to enhance `check_refname_format()` itself, but that would require broader refactoring due to its C-string interface.

The patch appears technically sound and addresses a real gap in validation, though the implementation could be made slightly more direct as suggested. This continues the series' trend of catching edge cases in packed-refs parsing while maintaining compatibility with existing repositories.
