This is a refactoring patch in Patrick Steinhardt's ongoing series to decouple the reftable library from Git core infrastructure. The change removes one of the last Git-specific behaviors by converting `reftable_record_cmp()` from using Git's `BUG()` macro to proper library error handling.

The patch modifies `reftable_record_cmp()` to return an error code when comparing records of different types, rather than aborting. This requires cascading changes through the call chain:
- The function signature changes to return an `int` error code and take an output parameter for the comparison result
- All callers (in merged.c, pq.c, and test files) are updated to handle the new error return
- The priority queue implementation in pq.c is modified to propagate comparison errors
- Test cases are updated to verify the new error handling behavior

Key technical details:
- The comparison now returns REFTABLE_API_ERROR (-1) for type mismatches
- Callers in merged.c and pq.c must now check return values before using comparison results
- Test coverage is maintained for all record types (REF, LOG, OBJ, INDEX)
- The change preserves all existing comparison semantics when types match

This continues the series' pattern of systematically replacing Git-specific behaviors with reftable-local implementations while maintaining functionality. The patch appears well-tested and follows the established pattern of the larger decoupling effort.
