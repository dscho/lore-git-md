This is part of Patrick Steinhardt's ongoing effort to decouple the reftable library from Git core infrastructure (v3 series, patch 3/18). The change removes another Git-specific dependency by replacing `xmmap()` with direct `mmap()` calls in the reftable blocksource implementation.

The patch addresses two key issues with the current `xmmap()` usage: it prevents the reftable code from handling mmap failures gracefully (since `xmmap()` dies on error), and it ties the implementation to Git's utility functions. The new version uses `mmap()` directly with proper error handling, where failures now properly propagate up through `reftable_block_source_from_file()`'s return value as `REFTABLE_IO_ERROR`.

The implementation maintains compatibility by still potentially using Git's `git_mmap()` wrapper on systems without native mmap` support, but does so through the standard POSIX interface rather than Git's convenience wrapper. The changes are localized to `reftable/blocksource.c`, modifying the file block source initialization to:
1. Initialize the pointer explicitly to NULL
2. Use direct mmap with MAP_FAILED error checking
3. Properly clean up resources on failure
4. Return the error code rather than always returning 0

This continues the series' pattern of replacing Git-specific utilities with reftable-local implementations while maintaining identical behavior for valid cases. The change is straightforward but important for the architectural goal of making reftable usable outside Git.
