This is a refactoring patch in Patrick Steinhardt's ongoing series to decouple the reftable library from Git core infrastructure. The patch replaces Git's `write_in_full()` helper with a reftable-specific `reftable_write_data()` implementation in stack.c, continuing the effort to remove Git dependencies from the reftable codebase.

The new implementation handles the same core functionality - writing all data with proper error handling - but does so with direct POSIX `write()` calls rather than going through Git's I/O layer. It maintains identical error behavior (returning REFTABLE_IO_ERROR on failures) while adding explicit handling for EAGAIN/EINTR cases. The change affects three write sites in stack.c that handle table list updates during compaction and addition operations.

The patch is mechanically straightforward, substituting the new wrapper while preserving all existing behavior. This follows the pattern established in prior patches of the series to replace Git-specific utilities with reftable-local implementations. The change appears well-contained with no obvious behavioral differences, though reviewers may want to verify the EAGAIN/EINTR handling matches Git's xwrite() semantics exactly.

This continues the architectural separation work by removing another Git-specific dependency, bringing the reftable library closer to being fully standalone. The implementation choice here mirrors the earlier read() changes in the series, establishing consistent I/O patterns throughout the codebase.
