This is part of Patrick Steinhardt's ongoing effort to decouple the reftable library from Git's core infrastructure. The patch removes another Git-specific dependency by replacing `xmmap()` with direct `mmap()` calls in the reftable blocksource implementation.

The change addresses two key issues: first, `xmmap()`'s behavior of terminating the program on failure is too aggressive for a library component, and second, it unnecessarily ties reftable to Git's codebase. The new implementation uses standard `mmap()` with proper error handling, returning an error code rather than dying when mapping fails. This is patch 3 of 18 in the v3 series, continuing the pattern of replacing Git utilities with reftable-local implementations while maintaining identical behavior. The change is straightforward but important for the blocksource layer that handles file I/O for reftable operations.
