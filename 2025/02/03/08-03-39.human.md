Refactoring patch in Patrick Steinhardt's reftable decoupling series, replacing Git's `st_mult()` with custom overflow-checked allocation helpers. This continues the effort to remove Git-specific dependencies from the reftable library.

The patch introduces a new `reftable_alloc_size()` helper that performs explicit overflow checking when calculating allocation sizes, returning an error rather than dying like `st_mult()` would. This change affects three macros (`REFTABLE_ALLOC_ARRAY`, `REFTABLE_REALLOC_ARRAY`, and the internal `reftable_alloc_grow`) that now handle allocation failures gracefully by setting `errno` and returning NULL rather than aborting.

The implementation carefully maintains the same overflow protection as `st_mult()` while removing the Git dependency. The change is part of a larger architectural effort to make reftable usable as a standalone library, with this patch specifically addressing memory allocation patterns. The series has been through multiple rounds of review and this appears to be a straightforward, well-contained change that follows the established pattern of replacing Git utilities with reftable-local implementations.
