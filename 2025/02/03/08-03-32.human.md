This is a refactoring patch as part of Patrick Steinhardt's ongoing effort to decouple the reftable library from Git's core infrastructure. The patch removes one of the last Git-specific dependencies by open-coding the `read_in_full()` function in reftable/stack.c rather than using the Git-provided version.

The change is straightforward - it replaces the single call to `read_in_full()` with a direct implementation that handles the same basic read operation, but without Git's additional non-blocking I/O handling (which isn't needed here since reftable doesn't use non-blocking mode). The new implementation maintains the same error handling behavior while being self-contained within the reftable library.

This is part of a larger 18-patch series (v3) that has been through extensive review, with nearly all technical concerns already addressed. The series aims to make the reftable library fully portable by removing its dependencies on Git's core infrastructure. This particular patch is a small but necessary step in that direction, cleanly removing one more Git-specific helper function.
