This is a refinement to the final patch in the packed-refs validation series, focusing on the fsck integration layer. Patrick Steinhardt provides two key suggestions for the `git refs verify` child process implementation in `builtin/fsck.c`:

1. **Progress meter removal** - Points out the current progress indicator (showing only 0 or 1) provides no meaningful information since it just signals completion, which is already apparent to users. This aligns with Junio's earlier feedback about redundant progress reporting.

2. **Disable flag proposal** - Suggests adding a `--[no-]references` option to control whether ref validation runs during fsck, noting that users who want ref-only checking can directly invoke `git refs verify`. This maintains flexibility while avoiding the need for an `--only-references` flag.

The feedback addresses final polish items before the series can be merged, focusing on user interface considerations rather than core validation logic. Patrick's suggestions continue the thread's pattern of refining the integration points (here between `git fsck` and the new ref verification subsystem) while keeping the architectural separation clean. The changes would affect command-line options and progress reporting but not the underlying packed-refs validation machinery that was the focus of earlier patches.
