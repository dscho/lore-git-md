Bugfix patch adding NUL character detection in packed-refs parsing, part of the larger packed-refs validation series.

This patch addresses a specific edge case in packed-refs parsing where embedded NUL characters in refnames could go undetected. The current code calculates refname validity based on pointer arithmetic between the start of the refname and the next newline, which could miss NULs in the middle of the name if the truncated portion remains valid. Patrick Steinhardt suggests simplifying the implementation by inlining the NUL check rather than creating a new helper function, and notes this could ideally be handled in `check_refname_format()` if not for its C-string interface limitations.

The change is technically sound and clearly motivated, though Patrick's review suggests some implementation simplifications. This fits into the broader series by adding another validation check to the packed-refs verification process. The discussion indicates general agreement on the need for the check, differing only on implementation details. The patch appears ready to proceed with minor adjustments based on Patrick's feedback.
