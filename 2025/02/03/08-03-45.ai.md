This is part of Patrick Steinhardt's ongoing series to decouple the reftable library from Git core infrastructure, specifically addressing the removal of Git-specific macros.

The patch replaces Git's `UNUSED` macro with a new `REFTABLE_UNUSED` macro throughout the reftable codebase. The key technical aspects are:

1. The new macro provides a weaker guarantee than Git's version - it suppresses unused parameter warnings but doesn't enforce that parameters marked as unused are actually unused. This avoids needing compiler-specific logic while still preventing warnings.

2. Changes are mechanical replacements across multiple files (basics.h, blocksource.c, iter.c, record.c, writer.c) where `UNUSED` was previously used to mark intentionally unused function parameters.

3. The implementation in basics.h simply casts the parameter to void, matching common C patterns for suppressing unused parameter warnings.

4. In record.c, several functions that took `UNUSED` parameters for hash_size or scratch buffers now use the new macro, maintaining the same parameter signatures but with the reftable-specific annotation.

This continues the series' pattern of removing Git dependencies while preserving functionality. The change is straightforward and maintains the code's behavior while further isolating reftable from Git's utility macros. No behavior changes are introduced - this is purely about dependency cleanup.
