This is part of Patrick Steinhardt's ongoing refactoring series to decouple the reftable library from Git core infrastructure (v3 16/18). The patch splits POSIX-emulation functionality out of `git-compat-util.h` into a new `compat/posix.h` header, continuing the architectural separation work.

The change moves 541 lines of POSIX-related definitions and compatibility wrappers (file operations, time functions, socket handling, etc.) to the new header while keeping Git-specific utilities in the original file. Key technical aspects include:
- New `COMPAT_POSIX_H` header guard
- Preserved functionality for Windows/MinGW/MSVC builds
- Maintained compatibility macros like `UNUSED`, `GIT_GNUC_PREREQ`
- POSIX feature test macros (`_XOPEN_SOURCE` etc.) relocated
- System header includes reorganized by platform
- No behavior changes - purely structural separation

This is a mechanical split that follows the established pattern of the series, removing another Git dependency from reftable by isolating POSIX emulation. The patch appears well-contained and maintains build compatibility across platforms. It sets up the next step of using this header in reftable instead of pulling in Git's compat-util.
