This is a refactoring patch in Patrick Steinhardt's ongoing reftable decoupling series, specifically addressing feedback from Justin Tobler about memory safety in the array-copying operation.

The patch originally replaced Git's `COPY_ARRAY()` macro with an open-coded `memcpy()` as part of removing Git-specific dependencies from the reftable library. Justin pointed out that `COPY_ARRAY()` includes overflow protection via `st_mult()` that the direct `memcpy()` lacks. Patrick acknowledges this and agrees to add overflow checking, though he believes it's theoretically unnecessary since the source record's allocation was already validated.

The change affects `reftable/record.c` where object record offsets are copied between structures. The discussion shows careful attention to edge cases in the reftable separation work, with Patrick being responsive to safety concerns even when they might be redundant. This exemplifies the thorough review process seen throughout the reftable decoupling effort.

Key technical details:
- Original change: `COPY_ARRAY()` → `memcpy()`
- Concern: Missing overflow protection from `st_mult()`
- Location: `reftable_obj_record_copy_from()` function
- Fields involved: `offsets` array and `offset_len` count
- Resolution: Patrick will add overflow checking while maintaining the Git-dependency removal goal
