Bugfix for `git repack --keep-unreachable` behavior when no packfiles exist. This is the second patch in a two-part series that addresses an edge case where the command would fail when run on repositories without any preexisting packfiles.

The patch modifies the conditions under which `--pack-loose-unreachable` is passed to `git-pack-objects`. The original code incorrectly required existing packfiles for this flag to be set, even though loose objects can be packed regardless of packfile existence. The fix separates this condition from the other pack-related checks, now only requiring that `--keep-unreachable` is active, redundant objects are being deleted (as documented), and we're not creating a cruft pack.

The change is minimal (5 lines modified) but important for the edge case it addresses. The accompanying test update changes a previously failing test case (`test_expect_failure`) to expect success, demonstrating the fix works. The commit message provides thorough analysis of the original conditions and why the change is correct, noting that two of the three original conditions remain valid while the packfile existence check was inappropriate for this specific flag.

This appears to be a well-justified and carefully implemented fix for a clear bug, with comprehensive test coverage already established in the first patch of the series. The change maintains all documented behavior while fixing the edge case where no packfiles exist.
