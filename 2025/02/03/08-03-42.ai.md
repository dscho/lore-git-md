This is part of Patrick Steinhardt's ongoing series to decouple the reftable library from Git core infrastructure. The patch introduces a new `reftable_rand()` function to replace direct calls to Git's random number generator.

The change creates a reftable-specific random number generation interface that:
1. Provides a simple `uint32_t` return value (unlike Git's more complex CSPRNG interface)
2. Currently implements it via Git's git_rand() for compatibility
3. Is designed to allow external callers to provide their own seeded RNG
4. Updates two call sites in stack.c that generate random filenames and retry delays

The implementation maintains the same behavior while providing a cleaner abstraction boundary. This continues the series' pattern of replacing Git-specific functionality with reftable-local equivalents that can be implemented by external consumers. The change is mechanical and low-risk, affecting only debug/retry functionality rather than core reftable operations.
