This is the core implementation patch (2/5) in the `git backfill` series, introducing the basic functionality and tests for the new command. The patch builds on the path-walk infrastructure to implement blob backfilling in partial clones.

The implementation centers around `fill_missing_blobs()`, which processes path-walk batches of objects, collecting missing blobs into batches for fetching. A key design choice is the default minimum batch size of 50,000 objects, chosen to balance server request efficiency with interruptibility. The function uses `has_object()` to check for existing blobs before requesting them, addressing previous review feedback.

The patch includes comprehensive documentation explaining the command's purpose in blobless partial clones, where it helps avoid the performance pitfalls of single-blob downloads during operations like `git blame`. Tests verify both local and HTTP-based backfilling scenarios, checking that all reachable objects are properly downloaded in batches. The test suite creates a complex repository structure with multiple versions of files across nested directories to exercise the path-walk behavior.

Key technical details include:
- The `backfill_context` struct manages batch collection and minimum size
- `download_batch()` handles the actual object fetching via promisor-remote
- The implementation integrates with Git's existing packfile machinery
- Tests use trace2 events to verify fetch behavior and object presence

This is a well-structured patch that follows Git's established patterns for new builtins, with thorough test coverage and clear documentation. It addresses all technical feedback from previous iterations while maintaining the experimental flag status that remains under discussion.
