This is part 16/18 of Patrick Steinhardt's series to decouple the reftable library from Git's core infrastructure, focusing on splitting POSIX-emulating functionality from Git-specific utilities.

The patch extracts all POSIX compatibility definitions from `git-compat-util.h` into a new `compat/posix.h` header. This is a mechanical reorganization that doesn't change behavior, but helps separate concerns - the reftable library will only need the POSIX emulation layer without pulling in Git-specific functionality. The split creates a clear boundary between platform compatibility code (now in `posix.h`) and Git's own utilities (remaining in `git-compat-util.h`).

The change is substantial (over 1000 lines moved between files) but straightforward - it's primarily moving code reorganization to support the larger architectural goal of making reftable library more independent. The patch follows the established pattern in this series of structural improvements that maintain existing behavior while removing Git dependencies.

This continues the high-quality work seen throughout the series, with careful attention to maintaining compatibility while cleaning up the codebase. The change is well-contained and clearly motivated by the overall goal of reftable independence.
