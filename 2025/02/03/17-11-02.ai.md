Feature patch series introducing `git backfill` command, now at v3. This builds on the recently merged path-walk infrastructure to provide blob backfilling in partial clones with configurable batch sizes and sparse-checkout integration.

The series adds a new builtin that downloads missing blobs in blobless partial clone by walking paths to group related objects, aiming to improve server-side packfile efficiency. Key technical details include:
- New `--min-batch-size` option (default 50,000 objects) controls request grouping
- `--sparse` option (auto-enabled when sparse-checkout is active) restricts downloads to paths matching sparse patterns
- Implements `fill_missing_blobs()` using path-walk API with sparse-checkout awareness
- Adds comprehensive tests covering both sparse modes (cone and non-cone) and batch size variations

The v3 updates rebase onto master, improve documentation formatting (using `[synopsis]` style), rename batch_size to min_batch_size consistently, add more sparse-checkout test cases, and fix memory management. Performance data shows smaller batch sizes (5K-25K objects) can yield better compression ratios (348MB vs 738MB full clone) at modest time overhead.

Open questions from previous reviews appear addressed, though the experimental flag discussion remains active. The implementation now uses `has_object()` per Patrick's suggestion and clarifies sparse behavior differences between cone/non-cone modes.
