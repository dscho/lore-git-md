This is a proposal for continuous benchmarking infrastructure to catch performance regressions in Git. Patrick Steinhardt from GitLab describes their current setup that benchmarks `master` and `next` branches daily using hyperfine-based scripts (hosted externally) running via GitLab CI, with results uploaded to Bencher for visualization and alerting.

The proposal suggests moving this into the Git project proper by: (1) expanding t/perf tests, (2) creating a Bencher adapter for perf script output, (3) establishing dedicated benchmarking infrastructure (as CI is noisy), and (4) setting up mailing list alerts. The current GitLab-run system already provides basic regression detection but suffers from CI inconsistency and single-maintainer fragility.

Key technical elements mentioned: hyperfine benchmarking tool, Bencher visualization platform, GitLab CI integration, and Git's existing t/perf framework. The email explicitly invites community feedback on whether to adopt this as a project resource or keep it as a GitLab-maintained external system. No specific implementation patches are included - this is purely a discussion-starting RFC about infrastructure approach.
