This thread addresses a bug in `git repack --keep-unreachable` that caused crashes when no preexisting packfiles existed. The two-patch series first added comprehensive test coverage (73 lines across three scenarios in t7700-repack.sh) before fixing the core issue in builtin/repack.c. The bug stemmed from an incorrect assumption that packfiles would always exist when processing `--keep-unreachable`, which the fix resolves by properly gating the `--pack-loose-unreachable` option only on the flag being active, redundant deletion occurring, and no cruft pack creation.

Jeff King (Peff), who originally implemented the `--keep-unreachable` functionality, confirmed the root cause analysis and fix are correct, tracing the behavior back to commit e26a8c4721. He noted this flag has been somewhat superseded by cruft packs in modern Git usage. Junio Hamano observed some test coverage overlap with t7701-repack.sh but acknowledged the edge case with no existing packs was previously untested. Both reviewers suggested minor optional improvements to test helper functions but agreed these don't affect the core fix's correctness.

The discussion concluded with consensus that the series is technically sound and ready for merging. Peff's follow-up email served as final validation from the original author, confirming no outstanding issues remain. The patches demonstrate careful attention to edge cases and maintain backward compatibility while fixing a real-world crash scenario.
