This is a discussion about test framework improvements in the context of the ongoing unit test conversion to the Clar framework.

Patrick Steinhardt responds to Phillip Wood's feedback about string comparison assertions in the hashmap test conversion. Phillip had noted that `cl_assert_equal_s()` doesn't handle NULL values as well as the old `check_str()` helper, and suggested an improvement to Clar's string comparison diagnostics that would properly quote non-NULL values while clearly indicating NULL pointers. Patrick agrees this should be fixed in Clar itself and asks Phillip to submit an upstream pull request for the change.

The second point addresses Phillip's concern about losing debug messages during the test conversion. Patrick pushes back, arguing that verbose debug messages add unnecessary noise since tests should pass silently, and if they fail, developers would likely use a debugger rather than rely on these messages. This represents a philosophical difference in test writing style between concise assertions versus verbose debugging aids.

This exchange occurs in the context of Seyi Kuforiji's v2 series converting Git's unit tests to Clar, which has already received maintainer approval from Junio Hamano but still needs to address Phillip Wood's consistent feedback about test diagnostics. The specific technical points here (NULL handling in string comparisons and debug message verbosity) exemplify the broader discussion about preserving test debuggability during the framework transition.
