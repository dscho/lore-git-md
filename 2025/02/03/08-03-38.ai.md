This is part of Patrick Steinhardt's ongoing series to decouple the reftable library from Git core infrastructure, specifically focusing on removing Git-specific error handling patterns.

The patch converts remaining trivial uses of Git's `BUG()` macro in the reftable library to proper error returns using `REFTABLE_API_ERROR`. Key changes include:

1. In `iter.c`, replaces a `BUG()` call in the unsupported seek operation with an error return, maintaining the same semantic (this operation remains unsupported but now fails gracefully).

2. In `reader.c`, removes `BUG()` checks for refcount operations entirely since these would only trigger after the structure was already freed (undefined behavior territory anyway).

3. In `writer.c`, converts two `BUG()` calls to error returns:
   - For invalid block size configuration
   - For type mismatches when adding records

The changes maintain all existing functionality while making the library more suitable for external use by removing Git-specific abort behavior. This continues the series' systematic replacement of Git utilities with reftable-local implementations, with particular attention to error handling boundaries. The patch appears straightforward with no obvious technical concerns - it's a clean mechanical conversion that maintains test coverage while advancing the architectural goal of separation.
