Technical clarification in the `git backfill` sparse-checkout pattern matching logic.

Derrick Stolee responds to Patrick Steinhardt's question about an apparent asymmetry in the pattern matching conditions for the new `--sparse` option. The explanation reveals subtle behavior differences between cone mode (which treats MATCHED, MATCHED_RECURSIVE and UNDECIDED equivalently) and non-cone mode (which needs to distinguish MATCHED from other cases when handling blobs). Stolee confirms the current implementation is correct based on test verification, and plans to both document this in the commit message and add a test case with nested patterns in the next version.

This is part of the ongoing refinement of the `git backfill` command's sparse-checkout integration, where the v2 series is receiving detailed technical review. The exchange shows careful attention to edge cases in the sparse-checkout pattern matching behavior.
