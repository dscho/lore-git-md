This is part of Patrick Steinhardt's ongoing series to decouple the reftable library from Git core infrastructure (v3, patch 12/18). The patch continues the architectural separation by removing another Git-specific dependency - this time replacing `sleep_millisec()` with a direct call to poll(3p)` for millisecond delays.

The change is mechanical and maintains the same functionality - it's used for retry delays when reloading the reftable stack, where the delay grows with random jitter (using the newly introduced `reftable_rand()` from earlier in the series). The commit notes that while poll() isn't the most direct sleep mechanism, it's the POSIX-standard way to achieve millisecond precision sleeping.

This is a straightforward change that follows the established pattern in this series of replacing Git utilities with standard POSIX equivalents. It's part of the near-complete effort to make reftable usable as a standalone library with minimal dependencies. The patch appears well-considered and maintains the existing behavior while removing another Git-specific dependency.
