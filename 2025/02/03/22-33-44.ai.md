Junio Hamano raises important design concerns about the quoting behavior in Justin Tobler's patch to make `git rev-list` output ignore `core.quotePath`. This is part of the ongoing thread about extensible missing object reporting.

Key points from Junio's response:
1. Questions the fundamental need for config-independent quoting in rev-list` output, noting that unlike email patches (where `core.quotePath` was originally targeted), machine-readable output should minimize unnecessary quoting
2. Reveals a long-term consideration to flip `core.quotePath`'s default to 'no' in Git 3.0 to better support non-ASCII locales
3. Points out that `git rev-list --objects` already shows paths unquoted, as the output is primarily for hash computation rather than strict round-tripping
4. Acknowledges the need to quote certain control characters (LF, quotes) but argues against blanket quoting of non-ASCII bytes in modern contexts

This email represents a significant design-level pushback on the current approach, suggesting the quoting strategy may need reconsideration. Junio's position as Git maintainer gives this feedback particular weight in the thread's progression. The response focuses on the broader implications of the quoting behavior rather than the implementation details that were previously under discussion.
