This is a cover letter for v5 of a bugfix series addressing atomic push exit code propagation, now maintained by Patrick Steinhardt after initial work by Jiang Xin. The series fixes a case where git-receive-pack errors during atomic pushes weren't properly reported back to the client, causing silent failures when ref updates succeeded but receive-pack failed with a non-zero exit code.

The v5 iteration focuses on final polish and test improvements:
- Heredocs in tests are now escaped with `\EOF` where possible, implementing Eric Sunshine's earlier suggestion
- Test organization was improved to make changes clearer by avoiding unnecessary reordering
- Windows compatibility was addressed in test URL prefixes
- Documentation was added about ignoring `git_transport_push()` return values
- Comments were improved to better explain behavior

The series combines:
- Test modernization (t5504 heredoc relocation, t5548 protocol-flexible setup functions)
- New test cases for porcelain output and dry-run mode
- Core protocol changes introducing ERROR_SEND_PACK_BAD_REF_STATUS
- The actual fix ensuring graceful connection closure on atomic push failures

Key technical changes remain:
- New error code to distinguish ref status errors
- send-pack.c modifications for proper flush packet behavior
- transport.c cleanup simplification
- Comprehensive test coverage across multiple test files

The collaboration between Jiang Xin, Patrick Steinhardt, Eric Sunshine, and Junio C Hamano has produced a robust solution that maintains atomic push semantics while fixing the silent failure case. The v5 changes represent final refinements to the test infrastructure before the core issue is addressed in the final patches.
