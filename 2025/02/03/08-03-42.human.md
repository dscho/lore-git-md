This is part of Patrick Steinhardt's ongoing series to decouple the reftable library from Git core infrastructure. The patch introduces a new `reftable_rand()` function to replace Git's random number generation in the reftable code.

The change creates a new system-level abstraction for random number generation, with the implementation still defaulting to Git's `git_rand()` for now. This allows external projects using reftable to provide their own random number generator if desired. The patch updates two call sites in the reftable stack implementation that were previously using `git_rand()` directly.

This continues the series' pattern of systematically replacing Git-specific functionality with reftable-specific abstractions while maintaining identical behavior. The change is straightforward and mechanical like previous patches in the series, with minimal impact beyond the architectural separation goal. The implementation remains functionally equivalent, just with a different function name and layer of indirection.
