This is a follow-up discussion in Patrick Steinhardt's bugfix series about repository reinitialization with different formats, specifically addressing Junio Hamano's suggestion to add a warning when `GIT_DEFAULT_REF_FORMAT` is ignored during reinitialization.

Patrick argues against adding a warning, maintaining that environment variables like `GIT_DEFAULT_REF_FORMAT` should behave as defaults that don't override existing repository configurations, similar to how `init.defaultRefFormat` works. He expresses concern that warnings could be noisy and that environment variables are too easily left set accidentally. The discussion also touches on the broader question of automatic ref backend migration, which Patrick believes should remain an opt-in operation rather than something triggered implicitly by git-init.

The technical context centers around `setup.c`'s handling of repository formats, where the patch modifies the logic to preserve existing ref storage formats when reinitializing. This contrasts with Junio's proposed alternative implementation that would warn when ignoring the environment variable. Patrick's position reflects a design philosophy that prioritizes safety and explicitness over convenience in repository format changes.
