This is part of Patrick Steinhardt's ongoing effort to decouple the reftable library from Git core infrastructure (v3, patch 2/18). The patch replaces Git's `write_in_full()` helper with a reftable-specific implementation called `reftable_write_full()`, continuing the series' goal of reducing Git dependencies in the reftable code.

The new implementation handles the same core functionality - writing all data with proper EAGAIN/EINTR retry logic - but does so without pulling in Git's I/O helpers. The change is mechanical, replacing three call sites in the reftable stack implementation while maintaining identical error behavior (REFTABLE_IO_ERROR on failures).

This follows the pattern established in earlier patches of the series, where Git-specific utilities are systematically replaced with reftable-local versions. The implementation looks straightforward and maintains the same safety characteristics as the original, though reviewers will want to verify the error handling matches Git's behavior exactly. As with the rest of the series, this moves reftable closer to being a truly standalone library.
