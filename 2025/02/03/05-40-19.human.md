This is a continuation of the test infrastructure discussion about failure handling in unit tests, specifically regarding the reftable test suite. Patrick Steinhardt responds to Jeff King's observation about potential undefined behavior when test assertions fail but execution continues.

The key points are:
- Patrick agrees that continuing test execution after failed assumptions is problematic and "the wrong thing to do in almost all cases"
- He notes this is a known pitfall of Git's current test framework
- Suggests the upcoming migration to the `clar` test framework will naturally solve this, as it aborts on assertion failures
- Leaves open whether to fix existing tests now or wait for the `clar` migration

The email doesn't propose any immediate action, but reinforces that the current behavior is undesirable and that the planned framework transition will address it. This keeps the discussion alive while acknowledging the broader solution path already in motion.
