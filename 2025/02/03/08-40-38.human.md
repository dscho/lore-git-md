This is a bugfix patch in the ongoing packed-refs validation series, specifically addressing sortedness verification. Patrick Steinhardt clarifies an important point about when to check for sortedness in packed-refs files.

The key insight is that we should only verify sorting when the packed-refs file explicitly claims to be sorted in its header. This matches Git's historical behavior where unsorted refs are technically allowed, but we want to catch cases where the file claims to be sorted but actually isn't - which has caused real-world bugs in the past.

Patrick identifies two scenarios where this mismatch can occur: (1) incorrect comparison functions in implementations (like a past libgit2 issue), and (2) manual edits by users unaware of the sorting requirement. This feedback helps refine the validation approach to be both precise and practical - checking sortedness only when explicitly promised, while maintaining compatibility with legacy files that don't make such claims.
