This is a bugfix patch in a series addressing atomic push exit code propagation issues. It introduces a new error code to properly handle ref status errors during pushes.

The patch adds ERROR_SEND_PACK_BAD_REF_STATUS (value 1) to distinguish when references are rejected by the remote side, fixing an inconsistency between the smart protocol and HTTP transport handlers. Previously, send_pack() would return -1 for bad ref statuses while HTTP transport would return 0, leading to silent failures in some cases.

The change makes send_pack() return the new error code when references are rejected, while transport.c is modified to ignore this specific error to maintain consistency with HTTP behavior. The commit explains this doesn't lose error detection entirely, as push_had_errors() will still catch failed ref updates later in the process.

This is part of a well-developed series (now at v5) that has undergone extensive review and testing modernization. The patch appears cleanly implemented with clear documentation of the new error code and its purpose. It represents a key technical piece of the overall solution to ensure proper error reporting in atomic pushes.
