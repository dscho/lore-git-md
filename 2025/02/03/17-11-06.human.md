Feature patch adding sparse-checkout integration to `git backfill`. This is part 4/5 of the v3 series introducing the new `git backfill` command for blobless partial clones.

The patch adds a `--sparse` option to `git backfill` that restricts downloads to paths matching the current sparse-checkout patterns. This is particularly useful for history investigations in blobless clones, where computing blob diffs would otherwise trigger individual promisor remote requests. The implementation integrates with both cone and non-cone mode sparse-checkouts, with cone mode providing additional path-walk optimizations.

Key technical changes include:
- New `--sparse` option that automatically loads sparse-checkout patterns
- Path-walk API extended to accept a `pattern_list` for filtering
- Comprehensive tests covering both cone and non-cone mode behavior
- Performance measurements showing the tradeoffs for various batch sizes

The patch appears well-tested with thorough coverage of both sparse modes and clear documentation updates. Performance data shows meaningful reductions in download size compared to full clones (e.g., Linux repository going from 6GB to ~2.2GB when restricted to kernel/ directory). This builds on the series' earlier work while cleanly integrating with Git's existing sparse-checkout infrastructure.
