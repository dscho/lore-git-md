This is a technical review discussion about MIDX bitmap layer handling in the pack-bitmap subsystem, specifically addressing potential stack overflow risks in recursive bitmap lookups.

Patrick Steinhardt raises concerns about the recursive nature of `bitmap_for_commit()` when traversing MIDX base layers, noting that deep recursion could theoretically cause stack overflow if there were thousands of MIDX layers. He references a previous discussion about layer compaction, asking whether existing mechanisms already prevent excessive layer depth.

The patch under discussion modifies `bitmap_for_commit()` to handle incremental MIDX cases by recursively checking base layers when a commit isn't found in the current layer. Steinhardt's review focuses on the safety implications of this recursion pattern rather than the functional correctness of the lookup logic itself.
