This is a technical response in an ongoing thread about `transfer.hideRefs` behavior inconsistencies between packed and loose refs. Taylor Blau (the Git maintainer) provides a detailed explanation of the current implementation, pushing back against the claim that commit 59c35fa caused the issue.

Key technical clarifications:
- Loose refs iterator intentionally doesn't handle exclusions at the filesystem level (unlike packed refs which can skip sections)
- Current filtering happens in `upload-pack` via `ref_is_hidden()` which checks both exact matches and prefix matches (with '/')
- Points out the actual behavior change came in 18b6b1b5c5, not 59c35fa as originally claimed
- Requests a reproduction script to better understand the reported issue

The response maintains this is working as designed, though notes the loose refs implementation could theoretically be optimized to skip excluded directories at the filesystem level (just hasn't been done yet). This appears to be a maintainer-level clarification attempting to correct misconceptions about the root cause while keeping the door open for further investigation if concrete reproduction steps are provided.
