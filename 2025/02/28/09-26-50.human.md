Performance optimization patch for the refs subsystem, part 13/16 in a series addressing refname availability checks. This patch implements seek capability for ref-cache iterators, continuing the cross-backend optimization work.

The change splits the seeking logic out from `cache_ref_iterator_begin()` into a new `cache_ref_iterator_seek()` function, allowing iterator reuse. A tradeoff is made where empty ref iterators are no longer returned when no references exist, as this would prevent reseeking to different prefixes. The commit notes this shouldn't significantly impact performance due to early bailout in the `advance()` path.

This builds on previous iterator infrastructure changes in the series, with the ref-cache implementation now matching the seek capabilities already added for reftable iterators in patch 12. The implementation includes careful handling of prefix states and directory priming while maintaining the existing iterator interface.

The patch appears well-constructed with clear commit message explaining the tradeoffs. It's part of a larger performance effort that has already demonstrated measurable speedups (1.19-2.32x in earlier patches), though this specific change's impact isn't quantified in isolation. The series as a whole is progressing through thorough review with multiple contributors involved.
