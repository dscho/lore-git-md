Bugfix for gitweb's UTF-8 encoding handling. Thorsten Glaser reports that gitweb is double-encoding UTF-8 content in diffs, causing mojibake (garbled text) regardless of the system locale. The issue occurs when displaying plain diffs and patches.

The proposed fix wraps the output in `to_utf8()`, which properly handles already-UTF-8 content by passing it through unchanged while converting non-UTF-8 text appropriately. The patch modifies two locations in `gitweb.perl` that handle commit diffs and patches.

Glaser notes this is likely not the only place needing this fix (mentioning `blobdiff` as another candidate) and asks the maintainers to identify and fix all affected locations. The patch appears straightforward and addresses a clear encoding issue, though it would benefit from verification that the `to_utf8` function behaves as described across different input scenarios.
