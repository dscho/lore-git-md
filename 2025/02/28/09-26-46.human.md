Refactoring of the refs iterator lifecycle management in Patrick Steinhardt's performance optimization series.

This patch (9/16) decouples iterator lifecycle management from iteration itself, addressing two key issues with the current design. First, it removes the automatic deallocation of iterators when exhausted, which required careful handling of `ref_iterator_abort()` calls. Second, it enables potential future iterator reuse by separating the iteration state from the iterator object itself.

The changes introduce a new `ref_iterator_free()` function that callers must explicitly use to deallocate iterators, replacing the implicit cleanup in `ref_iterator_abort()`. This makes the ownership semantics clearer and paves the way for reseeking iterators to different prefixes in future optimizations. The patch touches all ref iterator implementations across files, packed, and reftable backends, updating their vtable methods from `abort` to `release`.

This is a foundational change in the larger series optimizing refname availability checks, with the immediate goal of enabling batched verification optimizations in later patches. The implementation appears thorough, with consistent updates to all iterator types and their callers.
