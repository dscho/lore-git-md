This thread addresses a regression in the gitweb.js build system where the build script was incorrectly included in the JavaScript output due to a Makefile issue. The problem originated when gitweb.js generation was moved to a shell script (commit 19d8fe7da65), creating an unintended dependency through the use of `$^` (all dependencies) instead of properly isolating output files.

The discussion has evaluated three potential fixes: Thorsten Glaser's original patch with explicit file listing (portable but potentially less maintainable), Simon Richter's proposal using order-only dependencies (GNU make-specific but semantically cleaner), and Patrick Steinhardt's suggestion using `$(filter %.js,$^)` to avoid repeating file lists while excluding non-JS files. Patrick has also provided guidance on improving the commit message to properly document the regression's origin and requested proper Signed-off-by formatting.

In the latest update, Patrick is checking with Thorsten about next steps - whether Thorsten will submit a revised version incorporating these suggestions or if Patrick should take over to finalize the fix. The technical aspects are well understood, and the thread is now focused on the final coordination needed to apply the solution, with Patrick offering to shepherd the patch to completion if needed. The discussion has remained focused throughout on finding a solution that balances Makefile portability with long-term maintainability for gitweb builds with JavaScript enabled.
