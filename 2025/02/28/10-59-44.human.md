Bugfix discussion regarding `git rev-list` sorting behavior with `--no-walk` and `--topo-order`.

Phillip Wood points out a missing flag in Clement Moyroud's test case for the `git rev-list` commit ordering issue. The original problem involves commits with identical timestamps not maintaining topological order when using `--no-walk=sorted`, causing issues for automated cherry-picking workflows. 

Wood clarifies that the correct command should include `--no-walk` when testing `--topo-order`, as in `git rev-list --stdin --topo-order --no-walk`. This combination should theoretically list only the input commits in topological order, without including their ancestors (which was the problem in Moyroud's original test case that returned 400k+ extra commits).

This suggests there may be a viable solution using existing flags that wasn't properly explored in earlier discussion.
