This is a review comment on a refactoring patch that enables `repo_config()` to handle NULL repository pointers. Phillip Wood agrees with the general approach but points out a technical limitation: using `read_very_early_config()` would ignore command-line config options (`-c` flags). He suggests calling `config_with_options()` directly instead for more precise control.

The review also notes that `git for-each-repo` currently uses `repo_config_get_string_multi()` and would need updating to use callbacks when it's converted away from `the_repository`. This is part of the broader effort to make Git work better in repository-less contexts.

The patch itself is conceptually approved but still needs test coverage (per Junio's earlier review) and now this additional consideration about command-line config handling. The discussion remains focused on implementation details rather than fundamental design.
