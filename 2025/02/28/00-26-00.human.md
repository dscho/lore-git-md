Feature implementation for batch blob diff processing. This is the fourth version of a series introducing `git-diff-pairs(1)`, a new plumbing command for efficiently generating diffs between multiple blob pairs in a single process. The command takes NUL-delimited raw diff format as input (like from `git diff-tree -z`) and produces patch or raw output, allowing large diff operations to be split across processes.

The series has evolved through multiple rounds of review, with all major architectural decisions now settled. Key aspects include:
- Strict input validation rejecting pathspecs and tree objects (for future compatibility)
- Required `-z` mode for NUL-delimited I/O
- Default patch output format
- New `skip_resolving_statuses` diff option to preserve rename/copy info from input
- Explicit flush control via NUL bytes between batches

The current version addresses final review feedback by:
- Replacing a `found_follow` workaround with the new `skip_resolving_statuses` field
- Refactoring options parsing while maintaining usage message functionality
- Adding submodule test coverage
- Various cleanups to error handling and documentation

This appears to be in its final polish phase before merging, with all substantive feedback incorporated. The implementation looks thorough, with comprehensive test coverage and clear documentation following Git's standards. The command fills a clear need for server-side diff processing where large operations may need to be batched.
