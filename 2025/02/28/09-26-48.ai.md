Performance optimization patch (11/16 in series) implementing seek capability for merged ref iterators, building on the iterator reseek foundation from patch 10/16. This change enables more efficient ref lookups by allowing merged iterators (which handle multiple ref sources) to reposition their search without being recreated.

The patch modifies the merge iterator implementation to:
- Track owned vs active iterators separately (new `iter0_owned`/`iter1_owned` fields)
- Preserve iterator state across seeks rather than freeing exhausted iterators
- Implement the new `seek` vtable method to reset and reposition both underlying iterators
- Maintain the existing merge selection logic during iteration

Key technical points:
- Seeks are implemented by resetting both iterators to their initial state and propagating the seek request
- The change enables future optimizations in patch 16/16 that reuse iterators
- Follows the pattern established in patch 10/16 for other iterator types
- Modifies the release logic to only free the original owned iterators

This is part of a measured performance improvement series showing 1.19-2.32x speedups. The implementation appears straightforward and maintains consistency with the broader refactor while enabling the batched optimization approach. No new tests are included here as the functionality is exercised by existing tests and the performance benchmarks mentioned in the series.
