Bugfix for gitweb's UTF-8 handling in diff output. Thorsten Glaser reports that gitweb is double-encoding UTF-8 content in plain diff and patch views, treating already-UTF-8 text as if it were Latin-1. The provided patch fixes this for commitdiff_plain and patch formats by wrapping the output with `to_utf8`, which properly handles both UTF-8 and non-UTF-8 input.

The change is minimal - just two lines modifying print statements in gitweb.perl to use the existing `to_utf8` helper function. The author notes this likely needs to be applied to other similar output handlers like blobdiff, but hasn't audited all possible locations that might need the same treatment.

This appears to be a straightforward correctness fix for a real display issue, though it would benefit from either a more comprehensive audit of all output paths or confirmation from gitweb maintainers about other spots needing similar treatment. The patch itself is simple and targets a clear problem, but may represent just part of a larger UTF-8 handling cleanup needed in gitweb.
