Build system patch refinement for gitweb.js generation. This email continues the discussion about fixing a regression where the build script was incorrectly included in the generated JavaScript output. Patrick Steinhardt responds to Thorsten Glaser's patch, suggesting improvements to both the commit message and the implementation approach.

The proposed commit message rewrite better explains the issue: when the gitweb.js generation was moved to a separate script, the Makefile's use of `$^` started including the build script itself in the output. Patrick offers two alternative solutions - either explicitly listing the JavaScript files (as in the original patch) or using `$(filter %.js,$^)` to automatically exclude non-JS files. He also notes the project's convention of using plain names rather than aliases in Signed-off-by lines.

This builds on the ongoing technical discussion about the fix's portability implications, with Patrick's alternatives potentially offering cleaner solutions than the current patch or Simon Richter's earlier order-only dependency proposal. The exchange shows careful attention to both technical correctness and project conventions.
