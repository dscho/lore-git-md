Performance optimization for the files ref backend, part of a larger series improving refname availability checks. This patch (7/16) extends the batched verification approach to initial transactions in the files backend, where references are first created in a repository.

The change refactors the initial transaction logic to collect all new refnames first and verify them in a single batch, rather than checking each one individually. While this doesn't yet show performance gains (the actual optimization comes in later patches), it sets up the infrastructure needed for those improvements. The patch maintains all existing behavior and error handling, just reorganizing when and how the checks occur.

This is part of a well-structured series that has already shown significant speedups (1.19x for files backend, 2.32x for reftable in previous patches). The commit message clearly explains this is groundwork for future optimizations that will benefit cloning and ref migration operations. The change is cleanly implemented with proper cleanup handling and maintains the existing packed-refs locking behavior.
