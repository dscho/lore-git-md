This is the core implementation patch (3/4) in the `git-diff-pairs` series, introducing the new plumbing command for batch blob diff generation. The command processes NUL-delimited raw diff format input (as produced by `git diff-tree -z -r`) and generates patch or raw output, enabling the diff pipeline to be split into stages.

Key technical details for future reference:
- Input must use `-z` mode (NUL-delimited) and come from raw diff format
- Handles all diff statuses (added/modified/deleted/renamed/copied/typechanged)
- Uses new `skip_resolving_statuses` flag to preserve rename/copy info from input
- Rejects tree objects and pathspecs (must be filtered upstream)
- Default output format is DIFF_FORMAT_PATCH
- Comprehensive test coverage in t4070-diff-pairs.sh verifies:
  * Raw output recreation
  * Patch output generation
  * Input validation (non-NUL, tree objects, pathspecs)
  * Submodule handling

The implementation builds on the refactored diff queue infrastructure from earlier patches and integrates with the existing diff machinery while maintaining strict input validation. This provides the core functionality needed for server-side batch diff processing scenarios where recomputing renames for each diff would be expensive.
