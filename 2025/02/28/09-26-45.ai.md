Performance optimization in the refs subsystem, part 8/16 of Patrick Steinhardt's series to improve refname availability checks. This patch specifically targets redundant verification of common refname prefixes during batch operations.

The change introduces a `strset` to track already-verified refname prefixes (like "refs/heads/") to avoid repeatedly checking the same prefixes when processing multiple references in a transaction. This provides significant speedups, particularly for the reftable backend (1.58x faster when creating 10k refs against 100k existing), with more modest gains for the files backend (1.03x). The optimization also shows benefits (1.09-1.10x) when migrating large numbers of refs between backends.

Key technical details:
- Adds `struct strset dirnames` to track verified prefixes in `refs_verify_refnames_available()`
- Skips re-checking prefixes already in the strset
- Maintains all existing error handling and validation logic
- Benchmarks show reftable backend benefits more from this optimization than files backend
- Performance improvements are most noticeable when creating many refs with common prefixes

The patch builds on previous work in the series (patches 1-7) that established batched refname verification infrastructure. This change specifically addresses a performance bottleneck identified in the reftable backend's handling of prefix checks, though it provides some benefit across all backends. The implementation is straightforward, adding the strset tracking while preserving the existing verification semantics.
