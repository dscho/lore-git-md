This is a technical discussion in the ongoing Git cat-file batch mode filtering enhancement series, specifically addressing filter combination support.

Patrick Steinhardt responds to Toon Claes' question about why the patch doesn't support combining filters (LOFC_COMBINE). The key points are:

1. **Filter Combination Rationale**: Patrick explains that most filter combinations would be meaningless since they primarily filter by object type, which would result in empty sets. The only potentially useful combination would be `blob:limit` plus `object:type=blob`.

2. **Implementation Tradeoff**: Supporting filter combinations would add significant complexity to the implementation, and Patrick notes there's no current use case that justifies this complexity.

3. **Current Scope**: The patch focuses on implementing basic type-based filtering (LOFC_OBJECT_TYPE) alongside existing blob-specific filters, as shown in the diff where it adds handling for the new filter type in the batch output logic.

This exchange highlights a design decision in the series - keeping the initial implementation simple by not supporting filter combinations, with the rationale that the feature would provide minimal practical benefit relative to its implementation cost.
