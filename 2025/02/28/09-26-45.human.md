Performance optimization in refs subsystem (patch 8/16). This patch builds on the batched refname verification infrastructure introduced earlier in the series to optimize a specific inefficiency in prefix checking.

When verifying reference names, Git checks whether any prefixes of the name already exist (e.g., checking "refs/heads" when creating "refs/heads/main"). The patch eliminates redundant checks by tracking already-verified prefixes in a `strset`, which provides significant speedups particularly for the reftable backend (1.58x faster when creating 10k refs against 100k existing ones). The files backend sees a more modest 3% improvement. The change also helps reference migration between backends by about 10%.

The implementation is straightforward - it adds a `strset` to track checked prefixes and skips re-checking them. Benchmarks show the optimization is most effective when dealing with many references sharing common prefixes, which is a common case in practice. This continues the series' trend of measurable performance improvements while maintaining correctness.
