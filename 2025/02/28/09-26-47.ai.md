Performance optimization patch introducing iterator reseek capability for ref backends, part of a larger series (v4 10/16) addressing refname availability checks. This patch builds on the iterator lifecycle changes from patch 9/16 to enable reuse of ref iterators by adding a new `.seek` vtable function.

The change allows iterators to be reseeked to new prefixes without requiring full reinitialization, which is particularly beneficial for the reftable backend where internal iterator state can be preserved. The implementation maintains existing behavior for prefix matching while explicitly not supporting changes to other iterator parameters (exclude patterns, trimmed prefixes, flags) as there's no current use case for those modifications.

Key technical additions:
- New `ref_iterator_seek()` function and corresponding vtable entry
- Implementation for debug, empty, and prefix iterator types
- Documentation of the seek behavior in refs-internal.h
- Explicit limitation to prefix-only reseeks (other parameters remain fixed)

This infrastructure enables the iterator reuse optimizations planned for later in the series (particularly patch 16/16), where preserving iterator state across seeks can provide performance benefits. The patch follows the series' pattern of first establishing API changes before implementing backend-specific optimizations.
