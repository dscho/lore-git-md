Refactoring patch for the new `git-diff-pairs` plumbing command infrastructure. This is the first of four patches in v4 of the series, which has already gone through extensive review and is in its final polishing phase.

The patch splits the existing `diff_addremove()` and `diff_change()` functions into two layers: low-level queue operations that return the created `diff_filepair`, and thin wrappers that maintain the existing callback interface. This prepares for future patches that need to modify file pairs after they're queued, while preserving the current callback behavior used elsewhere in the codebase.

The changes are well-contained and documented, with new functions clearly commented in diff.h. The implementation maintains all existing functionality while adding the ability to access queued pairs. This foundational work enables the subsequent patches in the series to implement the new batch diff functionality.

The patch follows the established design direction from the thread, with all major architectural decisions already settled in prior iterations. It represents a clean separation of concerns that will support the new `git-diff-pairs` command while not disrupting existing diff machinery.
