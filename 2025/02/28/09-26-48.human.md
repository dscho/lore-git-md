Performance optimization for refs subsystem (patch 11/16 in series). This patch implements seek capability for merged ref iterators, a key building block for the series' batched refname checking optimizations.

The change modifies the merged iterator implementation to support seeking by prefix while preserving iterator state, which is particularly beneficial for the reftable backend. The implementation is straightforward but requires careful handling of iterator ownership - the patch introduces new fields (`iter0_owned` and `iter1_owned`) to track which iterators should be freed while keeping the active iterators reusable.

This continues the series' pattern of preparing infrastructure for later optimizations (particularly patch 16/16's iterator reuse). The changes maintain consistency with the refs API while enabling more efficient operations. Performance measurements from earlier in the series show this work contributes to significant speedups (1.19-2.32x depending on backend and workload).
