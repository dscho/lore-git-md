This is part 2/4 of the `git-diff-pairs` plumbing command implementation, focusing on a core diff infrastructure change needed for the new command.

The patch introduces a new `skip_resolving_statuses` option in `struct diff_options` that prevents `diffcore_std()` from automatically resolving file pair statuses (like rename/copy detection) when enabled. This is important for the new `git-diff-pairs` command which needs to preserve pre-computed status information when processing batched diffs.

The change is small but strategic - it modifies just one condition in `diff.c` while adding thorough documentation in `diff.h`. The implementation carefully works around an existing special case (`found_follow`) that already bypasses status resolution. This appears to be a well-considered change that maintains backward compatibility needed by existing code while enabling the new batch processing functionality.

As part of a mature patch series now in its fifth iteration, this change has already incorporated feedback from multiple reviewers. It represents one of the final architectural pieces needed before the new command can be merged.
