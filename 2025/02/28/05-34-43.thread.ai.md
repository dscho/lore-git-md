Gitweb.js build system bug: Addressing a regression where the build script was incorrectly included in the generated JavaScript output due to Makefile using `$^` (all dependencies) instead of properly isolating output files. The issue emerged when gitweb.js generation was moved to a shell script (commit 19d8fe7da65), creating an unintended dependency. Current discussion evaluates three approaches: (1) Thorsten Glaser's patch with explicit file listing in the Makefile rule (most portable but potentially less maintainable), (2) Simon Richter's proposed order-only dependencies (`|`) (GNU make-specific, semantically cleaner), and (3) Patrick Steinhardt's new suggestion using `$(filter %.js,$^)` to avoid repeating file lists while excluding non-JS files. Patrick also provided commit message improvements, noting the regression's origin and requesting proper Signed-off-by formatting. Technical debate continues weighing portability (BSD make compatibility) against maintainability and semantic clarity, with the thread identifying this as a pattern that may need broader build system auditing. The discussion remains focused on finding a solution that balances correctness across make implementations with long-term maintainability, particularly for gitweb builds with JavaScript enabled. All proposed solutions would fix the immediate issue, with differences in approach reflecting deeper considerations about Makefile best practices and portability tradeoffs.
