Gitweb.js build system bug: Fix regression where the build script was incorrectly included in the generated JavaScript output due to Makefile using `$^` (all dependencies) instead of properly isolating output files. The issue emerged when gitweb.js generation was moved to a shell script, adding an unintended dependency. Two solutions under discussion: (1) current patch's approach of explicitly listing output files in the Makefile rule, and (2) Simon Richter's proposed alternative using order-only dependencies (`|`) to maintain the script as a prerequisite without including its contents. Thorsten Glaser notes the order-only approach is GNU make-specific and may impact portability, particularly for BSD make users, while observing that `$^` in non-suffix rules often causes broader issues. The discussion remains technical, weighing implementation approaches (explicit listing being more portable versus order-only being more precise semantically) without yet reaching consensus. The thread has identified this as a Makefile pattern that may need broader auditing elsewhere in the build system, with portability considerations now explicitly part of the evaluation criteria. Affects gitweb builds with JavaScript enabled. Straightforward build system correction with additional complexity around make implementation differences.
