Performance optimization patch in a series improving refs subsystem efficiency. This is patch 3/16 in v4 of Patrick Steinhardt's series addressing refname availability checks across Git's storage backends.

The patch modifies `git-update-ref` to skip ambiguity checks when parsing object IDs, similar to a previous optimization made for `git-cat-file`. The change eliminates unnecessary reference lookups during DWIM resolution, which provides measurable performance improvements - 1.19x faster for the files backend and 2.32x for reftable in benchmarks creating 10,000 refs against a 100,000-ref repository.

The rationale is threefold: (1) update-ref is plumbing where object ID intent should be clear, (2) warnings are less relevant for non-interactive use, and (3) users should use fully-qualified refnames in plumbing scripts anyway. The behavior remains correct - ambiguous inputs still resolve the same way, just without the warning.

This builds on the API changes from patches 1-2 (adding `repo_get_oid_with_flags` and `GET_OID_SKIP_AMBIGUITY_CHECK`) and aligns with Junio Hamano's earlier approval of the warning suppression approach. The implementation is clean, swapping `repo_get_oid` calls for the new flag-enabled variant throughout update-ref.c.
