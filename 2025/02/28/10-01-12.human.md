This is a technical review of a patch in Taylor Blau's incremental MIDX bitmaps series, focusing on the pack-revindex changes needed to support the feature. Patrick Steinhardt examines the implementation details and raises several thoughtful questions about object counting across MIDX layers and the handling of reverse indexes.

The patch introduces `bitmap_non_extended_bits()` to properly account for objects in base MIDX layers when calculating bitmap sizes, and modifies the revindex code to handle MIDX chains. Steinhardt notes that while most callers are converted to use the new counting function, a few remain using the old `bitmap_num_objects()` - particularly in commit bitmap merging and bitmap filtering code - and suggests documenting the rationale for these exceptions.

The review also catches a minor style nit (missing space in a type declaration) and generally confirms the technical approach makes sense, though it highlights some subtle points about how positions are calculated across layered MIDXs that might benefit from more explanation in the commit message. The exchange continues the thread's pattern of careful technical scrutiny from two experienced Git contributors working on adjacent subsystems.
