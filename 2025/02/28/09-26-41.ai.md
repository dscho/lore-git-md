Performance optimization patch introducing batched refname availability checks in the refs subsystem (patch 4/16 in the series). This builds on the API groundwork from earlier patches to optimize reference updates, particularly for reftable and files backends.

The patch introduces a new `refs_verify_refnames_available()` function that checks reference name conflicts for multiple refs at once, replacing the existing single-ref `refs_verify_refname_available()` which is reimplemented as a wrapper. The core logic remains similar - checking for conflicts with existing refs and their prefixes - but now operates on a list of refnames. This prepares for future optimizations that will take advantage of batching.

Key technical changes:
- New function signature in refs.h taking a `string_list` of refnames
- Main verification logic moved into the batch function with refname iteration
- Existing single-ref function becomes a thin wrapper creating a single-item list
- All error handling and conflict detection logic preserved
- String buffers reused across checks for efficiency

This is part of a larger effort to optimize ref operations where the same checks were being repeated unnecessarily. The series has shown significant speedups (1.19-2.32x) in benchmarks, with this change laying groundwork for further iterator optimizations in later patches. The implementation carefully maintains all existing behavior while providing the structural changes needed for batching.
