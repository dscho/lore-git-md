This is a follow-up to the proposal about documenting third-party Git ecosystem issue trackers in MaintNotes. Git maintainer Junio C Hamano is reconsidering the approach after receiving no feedback on the initial patch, noting he will withdraw the changes from the next maintainer notes if discussion doesn't materialize.

The email reiterates three key open questions about the proposal's viability: whether maintaining such a list is worthwhile given the overhead, how to determine which projects qualify for inclusion, and what the maintenance responsibilities would entail. The attached diff shows the originally proposed changes - adding an "Other places" section to MaintNotes with GitHub links and contribution guidelines for git-scm.com, Git for Windows, and ProGit book.

The tone suggests this may be the last call for input before abandoning the idea, framing the lack of response as a negative signal. The proposal remains technically sound (clear URLs, specific file location) but the maintainer appears concerned about long-term sustainability without explicit community buy-in on the maintenance model. This serves as both a status update and final opportunity for others to weigh in on whether/how to proceed with ecosystem documentation.
