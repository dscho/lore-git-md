This is a documentation patch updating the BreakingChanges.adoc file, part of an ongoing discussion about how to handle backward-incompatible changes in Git. The patch clarifies the procedure for managing breaking changes through a compile-time switch (WITH_BREAKING_CHANGES) rather than the previously considered runtime configuration (feature.git3). It removes an outdated reference to the abandoned runtime approach and updates the text to reflect that CI testing of breaking changes is now implemented.

The patch emphasizes that breaking changes need to be prepared over time but deployable all at once when the version boundary is reached. It also notes that repository-incompatible changes should use the extensions.* mechanism independently of the breaking changes process, though this isn't added to the document as it's considered out of scope.

The changes are straightforward documentation updates reflecting decisions made in the thread referenced in the commit message. The patch appears well-considered, removing obsolete information while clarifying the current approach to managing breaking changes in Git's development process.
