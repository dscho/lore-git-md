This is a follow-up in the thread about making `--filter=blob:none` fail hard when server-side filtering is unsupported, rather than silently falling back to full downloads. John Giorshev responds to Jeff King's analysis, which pointed out that Git already fails hard for explicitly disallowed filters (like `blob:none` when forbidden by server config), suggesting the proposed change might be reasonable without breaking backward compatibility.

John summarizes Jeff's position that the patch might be acceptable as-is, but seeks broader feedback before proceeding. He has opened a pull request (#1869) with the implementation. The discussion remains open on whether to make this a hard error by default or introduce configurability, with Jeff noting the performance implications of silent fallback versus immediate failure. The thread shows technical alignment on the patch's direction but awaits more community input before finalizing the approach.
