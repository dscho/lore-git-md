Performance optimization patch for the reftable backend, part of a larger series (5/16) addressing refname availability checks. This patch refactors the reftable backend to batch refname availability checks during transaction preparation, though the performance benefits will only be realized in later patches that build on this change.

The change moves from checking each refname individually to collecting them in a list and verifying all at once using the new `refs_verify_refnames_available()` function introduced in patch 4/16. The implementation maintains all existing error handling while setting up for future optimizations that will reduce redundant checks. The patch is cleanly focused - it touches only the reftable backend code and keeps the same safety checks, just reorganizing when they occur.

This is an incremental but important step in the larger performance optimization effort for ref operations, particularly benefiting the reftable backend which showed 2.32-7.56x speedups in benchmarks when the full series is applied. The commit message clearly states this is groundwork for later optimizations rather than delivering immediate gains.
