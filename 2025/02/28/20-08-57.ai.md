Build system issue affecting test suite variable overrides. This email from Taylor Blau identifies a regression in how build options propagate to test suites after commit 4638e8806e changed the Makefile to use a template for GIT-BUILD-OPTIONS generation. The key problem is that the template now writes empty values for variables like GIT_PERF_MAKE_OPTS, which then override any non-empty values passed to test suite invocations.

The issue manifests when running performance or interop tests with custom make options - the GIT-BUILD-OPTIONS file sourced by the test scripts clobbers the intended settings. Taylor provides a concrete example where NO_EXPAT=1 gets ignored, causing builds to fail when expat headers are missing. The email notes this affects at least 15 different test-related variables that could be similarly impacted.

Taylor suggests two potential solutions: either adopt the same temporary-variable workaround currently used for TEST_OUTPUT_DIRECTORY (though notes this approach has its own flaws), or modify the Makefile to only emit variable assignments in GIT-BUILD-OPTIONS when they have non-empty values. A sample diff is provided showing how this might look for GIT_PERF_REPO, though Taylor acknowledges this may need corresponding changes for Meson builds and invites discussion on the best approach.

The issue was discovered while merging Git v2.48.1 into GitHub's internal fork, indicating it has real-world impact on CI systems that customize test runs. The email raises valid concerns about the robustness of the current implementation and its potential to silently break various test configurations.
