This is part 9/16 of Patrick Steinhardt's performance optimization series for the refs subsystem, focusing on iterator lifecycle management. The patch separates iterator lifecycle from iteration to enable iterator reuse and simplify calling patterns.

The key change decouples iterator deallocation from iteration completion, replacing the automatic cleanup at exhaustion with explicit `ref_iterator_free()` calls. This addresses two problems: awkward abort patterns where callers had to carefully time cleanup, and the inability to reuse iterators for repeated searches. The patch introduces `dir_iterator_free()` for the special case of directory iterators that don't implement the full ref_iterator interface.

Implementation-wise, it:
- Replaces `ref_iterator_abort()` with `ref_iterator_free()` across all backends
- Drops the return value from abort operations since it wasn't meaningfully used
- Moves cleanup from `base_ref_iterator_free()` into `ref_iterator_free()`
- Updates all iterator implementations to match the simpler lifecycle model
- Modifies calling code to explicitly free iterators when done

The change is foundational for later optimizations in the series that will reuse iterators, particularly patch 16/16 which implements iterator reseek capability. While this patch doesn't yet enable reuse, it establishes the necessary infrastructure by making iterator lifecycle management more flexible and predictable. The changes are mechanical but touch many files across the refs subsystem.
