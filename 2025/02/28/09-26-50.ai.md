This is patch 13/16 in a performance optimization series for the refs subsystem, implementing seek capability for ref-cache iterators. The patch builds on previous iterator infrastructure work and is part of a broader effort to optimize refname availability checks across different ref backends.

The key technical change is the extraction of seek logic from `cache_ref_iterator_begin()` into a new `cache_ref_iterator_seek()` function, allowing iterator reuse with different prefixes. The implementation makes several structural changes: the prefix field becomes heap-allocated to support dynamic updates during seeks, iterator state tracking is simplified, and the empty iterator optimization is removed since it would prevent reseeking to valid prefixes. The patch maintains consistency with the cross-backend iterator interface established earlier in the series.

Notable aspects include:
- The `prime_dir` flag is now stored in the iterator for reuse during seeks
- Error handling for failed seeks returns NULL from the begin function
- Memory management changes (prefix field ownership, allocation patterns)
- Preserved optimization of early bailout in `advance()` when no more directories remain

This change enables the batched refname checking optimizations planned in later patches while maintaining the files backend's performance characteristics. The removal of the empty iterator optimization is noted as a deliberate tradeoff to support reseeking functionality.
