This is patch 2/16 in a performance optimization series for the refs subsystem, introducing a new flag to skip ambiguity checks in object ID lookups.

The patch adds a `GET_OID_SKIP_AMBIGUITY_CHECK` flag that allows callers to bypass the check for ambiguous references (where an object ID matches a refname). While this check is normally useful for catching potential confusion, it adds runtime overhead in cases where the check isn't needed. The flag will be used in later patches in the series to optimize ref operations.

The change is minimal but strategic - it modifies `get_oid_basic()` to respect the new flag while maintaining all existing behavior when the flag isn't set. This is part of a broader effort to optimize refname availability checks across different backends (files, packed, reftable), with the series showing significant speedups (4-7x for reftable).

This appears to be a well-considered change that maintains backward compatibility of the existing API while enabling future optimizations. The commit message clearly explains the tradeoff being made (runtime overhead vs. safety check) and its role in the larger optimization effort.
