This is a bugfix addressing an issue in the build system where `GIT-BUILD-OPTIONS` unintentionally overrides manually specified build variables. The problem stems from a recent change (4638e8806e) that modified how the Makefile generates `GIT-BUILD-OPTIONS`, causing it to write empty values for certain variables rather than omitting them entirely. This creates conflicts when running performance or interop tests with custom build options, as the empty values in `GIT-BUILD-OPTIONS` override the intended settings.

Taylor Blau demonstrates the issue with a concrete example where `NO_EXPAT=1` is ignored when running perf tests, leading to build failures when expat headers are missing. The email identifies 15 potentially affected variables (including test and performance-related settings) and suggests a fix that would only include non-empty values in `GIT-BUILD-OPTIONS`, similar to the pre-4638e8806e behavior.

The patch appears well-motivated and addresses a real problem that affects both the main Git project and downstream users (like GitHub's CI). The proposed solution seems reasonable but raises questions about implementation details, particularly regarding the Meson build system equivalent. The email invites discussion about whether this approach is the right way forward.
