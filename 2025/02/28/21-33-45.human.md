Feature: New `git-diff-pairs` plumbing command for batch diff processing

This is the third patch in a 4-part series introducing a new git-diff-pairs(1) command that enables batch processing of blob diffs. The command acts as a backend that takes NUL-delimited raw diff format input (like from `git diff-tree -z -r`) and produces patch or raw output, allowing the diff pipeline to be split into stages.

The implementation handles all diff statuses (added, modified, deleted, renamed, copied, typechanged) while preserving rename/copy information via a new `skip_resolving_statuses` flag. The patch includes comprehensive tests verifying the command works with various diff types and properly rejects unsupported inputs like tree objects and pathspecs.

This builds on the refactoring from earlier patches and represents a key piece of infrastructure for server-side batch processing where computing all diffs at once may be impractical. The design has been refined through multiple rounds of review, with all major architectural decisions now settled. Only minor documentation and style tweaks remain before the series can be merged.
