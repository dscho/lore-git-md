Performance optimization for the files ref backend, part of a larger series improving refname availability checks. This patch (6/16 in v4) extends the batched refname checking approach from the reftable backend to the files backend, focusing on two key scenarios: checking for packed ref conflicts during normal updates and repository initialization.

The patch carefully analyzes five different contexts where refname availability is checked in the files backend, identifying only two (conflict checks during updates and repository initialization) as suitable for batching. The implementation queues refnames during `lock_raw_ref()` and checks them in bulk later, though notes a subtle race condition where packed-refs could change between the check and the actual update - a tradeoff made to avoid changing locking semantics.

This continues the series' pattern of maintaining backward compatibility while improving performance, with the files backend changes following the same batched verification pattern established for reftable in the previous patch. The commit message provides clear rationale for the design choices and acknowledges the remaining limitations, with repository initialization handling deferred to the next patch.
