This thread discusses a regression in Git's build system that affects how test suite variables are handled. The issue stems from commit 4638e8806e, which changed the Makefile to use a template for generating GIT-BUILD-OPTIONS. Taylor Blau reports that this change causes the build system to write empty values for test-related variables (like GIT_PERF_MAKE_OPTS) into GIT-BUILD-OPTIONS, which then override any non-empty values passed to test suite invocations.

The problem manifests when running performance or interop tests with custom make options - for example, NO_EXPAT=1 gets ignored, causing builds to fail when expat headers are missing. Taylor notes this affects at least 15 different test-related variables. He proposes two potential fixes: either adopting the temporary-variable workaround used for TEST_OUTPUT_DIRECTORY (though this has known limitations), or modifying the Makefile to only emit variable assignments in GIT-BUILD-OPTIONS when they have non-empty values. A sample diff is provided showing how this might work for GIT_PERF_REPO.

The issue was discovered while merging Git v2.48.1 into GitHub's internal fork, confirming it has real-world impact on CI systems. The current behavior risks silently breaking various test configurations, making this an important issue to address for anyone customizing test runs. Discussion is needed to determine the best solution that works across both Makefile and Meson builds.
