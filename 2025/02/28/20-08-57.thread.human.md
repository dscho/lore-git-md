This thread examines a build system regression affecting test suite variable propagation, introduced by commit 4638e8806e's changes to GIT-BUILD-OPTIONS generation in the Makefile. The core issue is that empty variable assignments (for GIT_PERF_MAKE_OPTS, NO_EXPAT, etc.) now override environment variables passed to test invocations, breaking real-world CI scenarios like performance testing and builds without expat support.

Taylor Blau originally reported the regression, which surfaced during GitHub's v2.48.1 integration, and proposed two approaches: adopting TEST_OUTPUT_DIRECTORY's temporary variable pattern or modifying the Makefile to only emit non-empty variable assignments. Jeff King has now joined the discussion, questioning the underlying workflow assumptions. He notes the typical performance test pattern involves setting variables during the initial build rather than at test time, though acknowledges this convention isn't documented. While agreeing Taylor's fix would address the regression, Jeff raises concerns about whether supporting variable overrides at test time is the right long-term solution.

The discussion now balances two concerns: fixing the immediate regression (where empty values clobber environment settings) versus establishing clearer conventions for test configuration. The thread remains open on whether to prioritize backward compatibility with existing workflows or use this as an opportunity to document and enforce a more intentional build/test separation.
