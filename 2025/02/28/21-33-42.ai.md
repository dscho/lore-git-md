This is the v5 cover letter for the `git-diff-pairs` feature series, introducing a new plumbing command for batch blob diff generation. The series has evolved through multiple rounds of review, with all major architectural decisions now finalized and only minor polish remaining.

The command provides a backend for processing NUL-delimited raw diff input (typically from `git diff-tree -z`) to generate diffs between blob pairs, with explicit flush control between batches. Key features include status preservation via the new `skip_resolving_statuses` diff option, rejection of tree objects/pathspecs for forward compatibility, and comprehensive test coverage including submodule handling.

Changes in v5 focus on final naming conventions and test modernization:
- Renamed usage/options variables to follow project conventions
- Removed unnecessary `PARSE_OPT_KEEP_UNKNOWN_OPT` flag
- Replaced deprecated `test_create_repo` with direct `git init` calls
- The implementation now fully matches the design goals of enabling batched diff processing with explicit flush control while maintaining NUL-delimited format consistency
- All known workarounds have been replaced by proper architectural solutions
- Only minor documentation and style tweaks remain before merge

The series is structured as:
1. Diff queue refactoring (mechanical changes to enable subsequent patches)
2. New `skip_resolving_statuses` diff option
3. Core `diff-pairs` command implementation
4. Explicit flush control between batches

This represents the final iteration of a well-reviewed feature that fills a gap in Git's diff plumbing capabilities, particularly useful for server-side batch processing scenarios where large diffs need to be split across processes.
