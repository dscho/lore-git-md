Performance optimization patch implementing seek capability for reftable ref iterators, part of a larger series (v4 12/16) improving refname availability checks across Git's ref backends. This patch builds on the merged iterator seek capability introduced in patch 11/16, now extending it to the reftable backend specifically.

The changes implement the seek vtable method for reftable ref iterators, allowing efficient repositioning within the ref namespace without recreating iterators. Key technical details include:
- Adds `reftable_ref_iterator_seek()` implementing the seek operation by updating the prefix filter and delegating to the low-level reftable iterator
- Makes the prefix field heap-allocated to support dynamic updates during seeks
- Adds error checking for `reftable_stack_init_ref_iterator()`
- Explicitly disables seeking for reflog iterators with a BUG() assertion, noting no current use case exists for reflog seeking

The implementation maintains consistency with the series' cross-backend interface while leveraging reftable's native seek capabilities. This is one of several optimizations contributing to the series' measured 2.32x speedup for reftable operations with 10k refs against 100k existing references. The patch follows the established pattern of the series, with clean separation between iterator management and backend-specific implementations.
