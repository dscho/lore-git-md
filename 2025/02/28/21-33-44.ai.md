This is a refactoring patch that's part of the `git-diff-pairs` plumbing command series, specifically introducing a new diff option to control status resolution behavior.

The patch adds a `skip_resolving_statuses` flag to `struct diff_options` that prevents `diffcore_std()` from automatically resolving file pair statuses via `diff_resolve_rename_copy()`. This preserves manually-set status information that would otherwise be overwritten during standard diff processing. The change is minimal - just a new field in diff.h and a one-line modification to the status resolution logic in diff.c.

This builds on the thread's established design where rename detection responsibility belongs to the frontend rather than the diff plumbing. The implementation replaces one of the remaining uses of the `found_follow` workaround in `tree-diff.c` with a more explicit control mechanism, as previously discussed in the thread. The patch maintains backward compatibility while enabling the new batch diff functionality where statuses need to be preserved across operations.
