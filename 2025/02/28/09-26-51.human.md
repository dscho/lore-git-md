Refactoring patch for packed-refs iterator performance in refs optimization series.

This is patch 14/16 in Patrick Steinhardt's performance optimization series for the refs subsystem, focusing on implementing seek capability for packed-ref iterators. The change builds on previous iterator work (particularly patch 13's ref-cache iterator changes) to enable more efficient refname lookups across all Git ref backends.

The patch modifies the packed-ref iterator to support dynamic seeking by:
1. Adding a `prefix` field to track the current search scope
2. Moving prefix matching logic into the `advance()` function
3. Implementing a new `seek()` operation that can reposition the iterator
4. Removing the empty iterator optimization to maintain consistency with other backends

The implementation shows careful attention to maintaining performance characteristics while adding functionality. The commit message notes this is a straightforward change except for the need to open-code prefix matching rather than using the prefix iterator helper, which would prevent reseeking.

This continues the series' pattern of making each backend support consistent iterator capabilities, enabling future optimizations (like batched refname checking) to work uniformly across files, packed, and reftable backends. The changes are well-contained to the packed-backend implementation with no interface changes.
