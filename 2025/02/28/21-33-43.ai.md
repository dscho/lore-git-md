Refactoring patch for the new `git-diff-pairs` plumbing command infrastructure. This is the first of four patches in v5 of the series, focusing on restructuring the diff queue internals to support the new batch processing functionality.

The patch splits `diff_addremove()` and `diff_change()` into two layers: low-level queue operations that return the created `diff_filepair` (new `diff_queue_addremove()` and `diff_queue_change()` functions), and the original functions which become thin wrappers. This enables subsequent patches to modify queued filepairs when needed. The changes maintain backward compatibility while exposing the queue operations directly.

Key technical details:
- New functions return `struct diff_filepair*` to allow post-queue modifications
- Original functions remain as wrappers to preserve callback compatibility
- Submodule handling and prefix filtering behavior unchanged
- Comprehensive documentation added in diff.h
- Memory management patterns preserved
- Part of preparing the diff infrastructure for batched processing needs

This is a mechanical refactoring that enables the core functionality in later patches while maintaining all existing behavior. The changes follow Git's established pattern of exposing low-level operations while keeping backward-compatible wrappers. The patch has already been reviewed in previous iterations and addresses all feedback, now in its final form with only documentation/style items remaining in the series.
