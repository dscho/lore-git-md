Performance optimization for refs subsystem (patch 15/16 in series). This patch implements seek capability for the files backend's ref iterator, completing the seek functionality across all ref storage backends (following similar changes for reftable and packed-refs in previous patches). The implementation leverages the existing ref-cache iterator underneath, making it straightforward. Notably, like with the reftable backend, seeking is not implemented for reflog iterators - attempts to seek these will trigger a BUG().

This is part of a larger series addressing performance bottlenecks in refname availability checks, particularly around tombstone references. The seek capability enables more efficient batched refname checking in later optimizations. The patch maintains consistency with the architectural approach seen in patches 12-14, where each backend received similar seek functionality. Performance measurements from earlier in the series show significant speedups (1.19-7.56x depending on backend and workload).

The implementation looks clean and focused, directly following the pattern established in previous backends. It includes proper error handling via BUG() for unsupported operations on reflog iterators. As the 15th of 16 patches in a well-reviewed series, this appears to be a solid incremental step toward the overall optimization goals.
