Performance optimization in the refs subsystem (patch 4/16). This patch introduces a new batch version of the refname availability check function, `refs_verify_refnames_available()`, which can process multiple refnames at once rather than requiring individual calls. The current implementation maintains the same behavior as the single-ref version (which is now reimplemented as a wrapper), but sets up the infrastructure for future optimizations in subsequent patches.

The change is part of a larger series addressing performance bottlenecks in refname checks, particularly for operations involving tombstone references in the reftable backend. While this patch itself doesn't yet show the performance gains, it's a foundational change that enables more efficient processing in later patches - the series ultimately demonstrates significant speedups (1.19-2.32x for files backend and up to 7.56x for reftable).

The patch appears well-structured, with the new function carefully maintaining all the existing validation logic while generalizing it to handle multiple refnames. The implementation follows the project's style and includes appropriate comments explaining the behavior and rationale.
