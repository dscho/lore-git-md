Performance optimization completing a refs subsystem series. This is the final patch (16/16) in Patrick Steinhardt's v4 series optimizing refname availability checks across Git's ref backends. The patch implements iterator reuse when checking for nested refname conflicts, building on the iterator reseek capability added in previous patches.

The change allows reusing ref iterators rather than recreating them for each nested ref check, which shows significant gains for the reftable backend (1.25x faster when creating 10k refs against 100k existing). The files backend sees minimal improvement (1.01x) since its performance is dominated by filesystem operations. The implementation modifies `refs_verify_refnames_available()` to conditionally create or reseek iterators.

This completes the series' cross-backend optimization work, which has demonstrated substantial performance improvements (1.19-1.27x for files backend, 2.32-7.56x for reftable in various scenarios). The patch follows the established pattern from earlier iterator changes and maintains consistent behavior while eliminating redundant iterator allocations. With this change, all three backends (files, packed, reftable) now support efficient iterator reuse for refname verification.
