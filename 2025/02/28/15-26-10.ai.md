Todd Zullinger reports that despite his earlier patch to ensure GNUPGHOME creation, the tests continue to fail in GitHub CI runs with unexpected SHA-1 mismatches when verifying signed commits. He suspects this may be related to the gpg wrapper script not properly applying `--faked-system-time` in the GitHub environment, though he notes this is just speculation. The key issue is that currently all tests requiring GPG2 are being skipped, masking what appears to be a deeper test reliability problem.

The email serves as a) a status update showing the problem persists, and b) a request for help from others more familiar with the test infrastructure to diagnose why the SHA-1 verification fails in CI but not in local Fedora/Rocky Linux environments. The core technical details involve the test's interaction with GPG signing and SHA-1/SHA-256 object format compatibility testing.
