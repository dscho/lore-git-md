This is the final patch in the v4 series implementing the new `git-diff-pairs` plumbing command, focusing on explicit flush control for batch processing. The patch adds the ability to trigger diff queue flushes mid-stream by sending a NUL byte between input file pairs, rather than waiting for stdin closure. This provides more flexible pipeline control when using `git-diff-pairs` as part of a multi-stage diff processing workflow.

The implementation introduces a new behaviors: when a NUL byte is encountered in input, it immediately processes the queued diffs, outputs them with a NUL delimiter, and continues processing. The patch modifies the diff queue to disable automatic freeing (`no_free=1`) to preserve state between batches, only enabling cleanup at the end. Test coverage verifies the new flush behavior works correctly with rename/copy detection and maintains output consistency with the existing end-of-stream flush.

This completes all planned functionality for the series, with the implementation now matching the design goals established in earlier discussion. The changes are well-contained, touching only the core command logic and its documentation while maintaining the established NUL-delimited input/output format. The test case demonstrates proper integration with `git diff-tree` as the expected frontend. With this patch, the series' architectural elements are fully realized: refactored diff queue, status preservation via `skip_resolving_statuses`, and now explicit flush control.
