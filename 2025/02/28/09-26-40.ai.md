Performance optimization patch in the refs subsystem series (3/16) that disables ambiguous reference warnings in `git-update-ref` to improve performance while maintaining the same behavior. This builds on the API changes from patches 1-2/16 that introduced `repo_get_oid_with_flags()` and the `GET_OID_SKIP_AMBIGUITY_CHECK` flag.

The patch modifies `builtin/update-ref.c` to use the new flag when parsing object IDs, skipping the expensive ambiguity checks that would normally warn when an object ID could also be interpreted as a branch name. The rationale is that:
1) `update-ref` is plumbing where object ID input is expected
2) Warnings are less useful in non-interactive contexts
3) Users should use fully-qualified refnames when needed
4) The check causes measurable performance overhead

Benchmarks show significant speedups: 1.19x faster for files backend and 2.32x faster for reftable backend when creating 10,000 refs against 100,000 existing refs. The reftable improvement is proportionally larger due to its faster baseline performance.

The change follows precedent from `git-cat-file` which made a similar optimization in 25fba78d36b. The patch maintains all existing functionality - it only suppresses the warning messages, not the ability to resolve ambiguous references. The implementation updates all OID parsing calls in update-ref.c to use the new flag consistently.

This is part of a larger performance optimization series for ref operations, with this patch specifically addressing a bottleneck in the object ID parsing path that affects both backends. The reftable backend sees particularly notable gains from this change.
