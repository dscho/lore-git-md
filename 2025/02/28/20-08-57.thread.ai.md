Thread summary:

Build system regression affecting test suite variable propagation, introduced by commit 4638e8806e's Makefile changes to GIT-BUILD-OPTIONS generation. The core issue is that the template-based approach now emits empty assignments for test-related variables (GIT_PERF_MAKE_OPTS, NO_EXPAT, etc.), which override any non-empty values passed to test invocations. Taylor Blau reports this breaks real-world CI scenarios like performance testing and builds without expat support, where variables like NO_EXPAT=1 get silently clobbered.

Two proposed solutions under discussion: 1) Adopt TEST_OUTPUT_DIRECTORY's temporary variable pattern (though known to be suboptimal), or 2) Modify Makefile to only emit non-empty variable assignments in GIT-BUILD-OPTIONS, with a provided sample diff for GIT_PERF_REPO handling. The fix needs to consider Meson build compatibility and maintain robustness across ~15 affected test configuration variables. The regression was discovered during GitHub's v2.48.1 integration, indicating production impact on customized test environments. Open questions remain about the optimal implementation approach and whether the solution should handle empty vs. unset variables differently.
