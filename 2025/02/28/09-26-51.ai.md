This is patch 14/16 in a performance optimization series for the refs subsystem, focusing on implementing seek capability for packed-ref iterators. The patch builds on previous work to enable batched refname checking optimizations across all ref backends.

The key technical changes in this patch include:
- Adding a `prefix` field to `packed_ref_iterator` to support dynamic updates during seeks
- Implementing a new `packed_ref_iterator_seek()` function that handles both empty and non-empty prefix cases
- Moving prefix matching logic into `advance()` rather than using `prefix_ref_iterator_begin()`
- Removing the empty iterator optimization to maintain consistency with seek capability
- Proper cleanup of allocated resources in `packed_ref_iterator_release()`

The implementation maintains the performance characteristics of the files backend while enabling the batched refname checking optimizations that will follow in later patches. The changes are part of a broader effort to optimize refname availability checks, particularly for operations involving tombstone references in the reftable backend.

This patch follows a similar pattern to patch 13/16 (for ref-cache iterators) and patch 12/16 (for reftable iterators), demonstrating a consistent approach to implementing seek capability across different backend types. The series as a whole has shown significant performance improvements (1.19x files backend speedup, 2.32x reftable speedup in 10k refs against 100k existing refs test case).
