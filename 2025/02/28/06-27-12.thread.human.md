This thread addresses a bug in gitweb where UTF-8 content in plain diff and patch views was being incorrectly double-encoded, treating already-UTF-8 text as Latin-1. Thorsten Glaser reported the issue and provided a minimal fix that modifies two print statements in gitweb.perl to properly handle UTF-8 output using the existing `to_utf8` helper function.

The patch specifically targets the commitdiff_plain and patch formats, though the author notes similar issues may exist in other output handlers like blobdiff that haven't been audited yet. While the change itself is small and clearly corrects a real display problem, it likely represents just one piece of a broader UTF-8 handling cleanup needed across gitweb's various output paths. The fix would benefit from either maintainer input about other affected areas or a more comprehensive review of all text output codepaths to ensure consistent UTF-8 handling throughout the interface.
