Performance optimization patch implementing seek capability for files backend iterators, completing the cross-backend iterator reseek functionality in this series (following packed-ref in patch 14/16 and reftable in patch 12/16). The change adds seek support to the files backend by leveraging the underlying ref-cache iterator, while explicitly preventing seek operations on reflog iterators via a BUG() assertion. This maintains consistency with the reftable backend's approach to reflog iteration.

Key technical details:
- Adds `files_ref_iterator_seek()` function to delegate to the wrapped ref-cache iterator
- Implements `files_reflog_iterator_seek()` with BUG() to match reftable backend behavior
- Updates iterator vtable structures to include seek operations
- Follows same pattern as previous patches (12-14/16) for cross-backend consistency
- Completes the seek capability groundwork needed for batched refname checking optimizations

The patch demonstrates the series' architectural consistency by applying the same seek pattern across all three backends (files, packed, reftable) while maintaining backend-specific constraints like reflog iterator limitations. This is the penultimate patch in the performance optimization effort, with only the batched verification optimization remaining in patch 16/16.
