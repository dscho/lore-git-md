This is the first patch in a 16-part performance optimization series for Git's refs subsystem, focusing on refname availability checks across different backends (files, packed, reftable). The series originates from inefficiencies found in handling tombstone references in the reftable backend.

The patch introduces `repo_get_oid_with_flags()`, a new function that extends `repo_get_oid()` by adding a flags parameter that gets passed through to `get_oid_with_context()`. This is a preparatory change that will be used in subsequent patches of the series. The implementation is straightforward - it wraps the existing functionality while adding the flags parameter, and maintains the same behavior when flags are zero (via the existing `repo_get_oid()` now calling the new function).

Key technical details:
- Adds new function `repo_get_oid_with_flags()` in both object-name.c and object-name.h
- Keeps existing `repo_get_oid()` as a wrapper for backward compatibility
- Passes flags parameter through to `get_oid_with_context()`
- Updates header documentation to note the function accepts GET_OID_* flags
- No behavior change in this patch - the new functionality will be used by later patches in the series

This is a foundational change that enables the subsequent performance optimizations in the series, particularly around object ID parsing and reference handling. The patch is cleanly separated from the actual optimization work that will follow in later patches.
