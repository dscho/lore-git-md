This is patch 10/16 in a performance optimization series for Git's refs subsystem, introducing iterator reseek capability. The patch adds infrastructure to allow ref iterators to be reused for multiple iterations by seeking to new prefixes, rather than requiring a new iterator for each search. This is particularly beneficial for the reftable backend where iterators can already be reused internally, but couldn't be exposed to callers before.

The change introduces a new `.seek` function in the ref iterator vtable and implements it for empty and prefix iterators, with other backends to follow in later patches. The implementation maintains the same behavior as creating a new iterator but allows for potential performance optimizations through state reuse. The patch includes thorough documentation of the new interface and its expected behavior.

This is a foundational change that enables the more significant performance optimizations coming later in the series, particularly patch 16/16 which will leverage iterator reuse. The implementation is clean and well-documented, with clear separation between the interface and initial implementations. The commit message does a good job explaining both the technical need and the limitations of the current approach (not supporting parameter changes beyond the prefix).
