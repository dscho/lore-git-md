This is the first patch in the v4 series implementing the new `git-diff-pairs(1)` plumbing command, focusing on refactoring the diff queue infrastructure. The patch splits the existing `diff_addremove()` and `diff_change()` functions into two layers: low-level queue operations that return the created `diff_filepair` (now called `diff_queue_addremove()` and `diff_queue_change()`), and thin wrapper functions that maintain the existing callback interface. This refactoring enables future patches to modify queued filepairs when needed.

Key technical changes include:
- New `diff_queue_addremove()` and `diff_queue_change()` functions that return the queued `diff_filepair*`
- Preserved existing callback signatures via wrapper functions
- Added comprehensive documentation in diff.h for the new queue functions
- Maintained all existing behavior including submodule handling and prefix filtering
- Kept the same memory management patterns (callers still don't need to free returned pairs)

The changes are mechanical and focused on enabling the subsequent patches in the series while maintaining backward compatibility. The patch follows the established pattern seen elsewhere in Git's codebase where low-level operations are exposed alongside convenience wrappers. This foundational work was previously reviewed and approved in earlier iterations of the series.
