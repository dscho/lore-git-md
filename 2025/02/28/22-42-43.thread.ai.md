Thread identity: Proposal to replace the git-mentoring@googlegroups.com infrastructure for new contributor support, initiated by Emily Shaffer. Thread type is community infrastructure discussion.

Core problem: The current Google Groups-based mentoring list has become unsustainable due to excessive spam and repeated content takedowns by Google that erase legitimate discussions without recourse. The list sees minimal legitimate traffic (few questions per year) but requires significant maintenance overhead.

Proposed solution: Johannes Schindelin (Dscho) suggested moving mentoring discussions to the existing Git Discord server, which already handles some new contributor questions effectively. Discord offers better moderation control but has tradeoffs: requires account creation (unlike email) and lacks web crawler accessibility.

Key considerations:
- Google Groups' repeated content takedowns with opaque removal processes
- Original purpose as lower-stress alternative to git@vger.kernel.org
- Discord's existing but imperfect suitability as replacement
- Accessibility vs moderation needs
- Documentation requirements for alternative help channels
- Maintenance processes for keeping support information current

Current status: Discussion has progressed from platform evaluation to implementation planning. Junio Hamano has expressed support for closing the Google Groups list while raising practical considerations about the Discord transition. The migration appears likely to proceed pending resolution of documentation and maintenance questions.

Key technical details:
- Need to document all available help channels (not just Discord)
- Determine documentation location (Contributing docs or Maintainer notes)
- Establish update processes for support information

Open questions:
- Where exactly to document the support channel information
- Who will be responsible for maintaining this documentation
- Whether additional outreach is needed to inform current list subscribers
- How to handle historical archives from Google Groups
