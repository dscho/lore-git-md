Thread identity: Proposal to replace the git-mentoring@googlegroups.com infrastructure for new contributor support, initiated by Emily Shaffer. Thread type is community infrastructure discussion.

Core problem: The current Google Groups-based mentoring list has become unsustainable due to excessive spam and repeated content takedowns by Google that erase legitimate discussions without recourse. The list sees minimal legitimate traffic (few questions per year) but requires significant maintenance overhead.

Proposed solution: Johannes Schindelin (Dscho) suggested moving mentoring discussions to the existing Git Discord server, with Christian Couder adding support for including #git-devel IRC and the main git@vger.kernel.org list as alternative help channels. Discord offers better moderation control but has tradeoffs: requires account creation (unlike email) and lacks web crawler accessibility.

Key considerations:
- Google Groups' repeated content takedowns with opaque removal processes
- Original purpose as lower-stress alternative to git@vger.kernel.org
- Multiple existing platforms (Discord, IRC, mailing list) as potential replacements
- Accessibility vs moderation needs across different platforms
- Documentation requirements for alternative help channels
- Maintenance processes for keeping support information current

Current status: Strong consensus has emerged to retire the Google Groups list, with discussion now focused on implementation details. Junio Hamano supports the shutdown while raising practical considerations about the transition. Christian Couder's endorsement of multiple channels (Discord + IRC + mailing list) has expanded the scope of potential replacements beyond the initial Discord proposal.

Key technical details:
- Need to document all available help channels (Discord, IRC, mailing list)
- Determine documentation location (Contributing docs or Maintainer notes)
- Establish update processes for support information
- Consider relative prominence of different channels in documentation

Open questions:
- Whether to formally endorse all three channels (Discord/IRC/mailing list) or prioritize one
- Exact documentation location and maintenance responsibilities
- Outreach strategy to inform current list subscribers
- Handling of historical archives from Google Groups

Participant positions:
- Johannes Schindelin (Dscho) originally suggested Discord migration
- Christian Couder supports shutdown and proposes including IRC/mailing list
- Emily Shaffer presented proposal and sought community input
- Junio Hamano supports closing Google Groups list and focuses on implementation logistics

Related work: Existing Git Discord server and #git-devel IRC channel already handle some new contributor questions. The discussion references the project's Contributing documentation and Maintainer notes as potential locations for updated support channel information.
