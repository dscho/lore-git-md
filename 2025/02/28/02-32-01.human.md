This is a bug report and follow-up discussion about inconsistent behavior in `transfer.hideRefs` between packed and loose refs in upload-pack. SURA provides a concrete reproduction case showing that after running `git gc`, hidden refs matching a prefix pattern (like `refs/heads/sura`) are filtered more aggressively when stored as packed refs compared to when they are loose.

The key issue is that with loose refs, `upload-pack` sees all refs and filters them via `ref_is_hidden()`, which does proper prefix matching (hiding `sura*` when configured to hide `sura`). But with packed refs, the filtering happens earlier in the iteration process using a simpler front-matching approach that hides all refs starting with the pattern (so `sura` hides only exact matches, not prefixes).

Taylor Blau had previously explained this was by design, but SURA's reproduction shows it can cause observable behavior differences for users when refs transition between loose and packed states. The email includes clear steps to reproduce the issue, which should help move the discussion forward on whether this needs fixing (and if so, which behavior should be standardized on). The thread remains open with no clear resolution yet.
