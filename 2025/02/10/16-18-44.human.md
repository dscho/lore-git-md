Cross-compilation path handling in Meson builds, with implications for make-based builds.

Junio Hamano responds to the ongoing discussion about cross-compilation issues in Git's Meson build system, where host paths (like `/usr/bin/sh`) were leaking into target builds. While acknowledging Patrick Steinhardt's proposed fix using Meson's `native:` parameter to separate build-time and target-time tool paths, Junio raises a broader question: should similar path separation be implemented for make-based builds as well?

He notes that historically, make-based builds assumed host and target paths would match, making cross-compilation impossible. While he personally favors consistency between build systems on principle (to prevent make-based builds from bitrotting), he acknowledges that nobody has seriously complained about make-based cross-compilation limitations in 20 years, suggesting it may not be worth the effort.

The email doesn't propose concrete changes but rather invites consideration of whether the Meson fixes should trigger parallel makefile improvements. The tone suggests this is more a philosophical question about build system maintenance priorities than an immediate technical proposal.
