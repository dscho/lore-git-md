This thread reports a bug in Git's handling of temporary packfiles on NFSv4 filesystems that experience failovers. The core issue occurs when cloning over NFSv4 to a high-availability filesystem: Git creates temporary packfile with read-write flags (O_RDWR) but read-only permissions (0444). While this works initially, when the NFS server recovers from a failover, it re-evaluates permissions and rejects the previously valid file handles, resulting in EACCES errors.

The problem manifests as "Bad file descriptor" errors in Git's output and "state recovery failed" messages in kernel logs. The reporter provides clear reproduction steps showing the error occurring during a clone operation when the NFS server is restarted mid-operation. The affected code paths are in object-file.c (for creating temp files with git_mkstemp_mode) and wrapper.c (the underlying open() call).

This appears to be a legitimate bug specifically impacting HA NFSv4 deployments where failovers are expected behavior. The report is thorough, with detailed error logs and code references, suggesting this is a real issue rather than a configuration problem, though the impact is limited to NFSv4 environments with failover scenarios. No proposed fix has been shared yet in this initial report.
