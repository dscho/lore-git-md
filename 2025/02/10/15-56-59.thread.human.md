This thread discusses a bug report about Git's packfile handling under NFSv4 failover conditions, where temporary files created with O_RDWR flags but 0444 permissions cause EACCES errors when NFS servers recover state. The original report from Bryan Maloney clearly demonstrated the issue during clone operations when NFS servers restart mid-operation, with kernel logs showing state recovery failures.

Brian Carlson has now weighed in, acknowledging the problem but framing it as an NFSv4 compliance issue rather than a Git bug. He cites POSIX standards that permit opening files with write permissions then changing to read-only, noting Git intentionally uses 0444 permissions to prevent repository corruption. Carlson points out similar behavior in other software like zsh and Emacs, and suggests the solution likely needs to come from NFSv4 server configuration or implementation changes to better handle POSIX-compliant operations during failover. He raises concerns that even if Git were modified to first open with 0644 then fchmod to 0444, it might not fully resolve the issue, and notes all major Git implementations would need parallel fixes. The discussion now centers on whether this should be addressed in Git or in NFSv4 implementations, with Carlson leaning toward the latter being the more appropriate fix.
