This is a discussion about cross-compilation path handling in Git's build systems, specifically focusing on the shell path (`/bin/sh` vs `/usr/bin/sh`) leaking between host and target builds.

Junio Hamano responds to Peter Seiderer's observation that most autoconf cross-build users may have been content with the default `/bin/sh` path in the Makefile. While Peter suggests this historical satisfaction might justify leaving the make build system unchanged while fixing Meson, Junio expresses skepticism. He points out that the fundamental issue - the Makefile's lack of distinction between host and target shell paths - exists regardless of whether users customized paths or not, and autoconf doesn't automatically solve this.

The exchange highlights the core architectural question: whether to maintain the current asymmetric approach (fix Meson while leaving make alone) or address the underlying cross-compilation issue consistently across both build systems. Junio's response leans toward the latter, suggesting the problem exists in make's design even if it hasn't caused widespread complaints. This keeps open the possibility of future make build system changes, though the thread had been converging toward a Meson-only solution.
