This is a discussion about NFSv4 compatibility issues with Git's temporary packfile handling. Brian M. Carlson responds to Bryan Maloney's bug report about Git clone operations failing during NFSv4 server failovers due to permission mismatches on temporary packfiles.

The core issue stems from Git creating temporary packfiles with O_RDWR flags but setting 0444 permissions, which causes problems when NFSv4 servers recover state after failover. Carlson acknowledges the problem but argues this behavior is POSIX-compliant, suggesting the issue lies with NFSv4's non-compliant handling of file permissions during state recovery rather than with Git itself.

Carlson questions whether a Git-side fix would be effective, noting that even if permissions were set differently, the same issue might persist during failover recovery. He also points out that many other applications (including zsh and Emacs) follow similar patterns, implying the problem is broader than just Git. The response suggests the solution may need to come from the NFSv4 server side through better state synchronization between primary and replica servers.

The discussion highlights a fundamental tension between Git's security-conscious file permission model and NFSv4's failover recovery mechanisms, with no clear resolution path emerging from this exchange. The technical depth of the response indicates this is a legitimate edge case that may require coordination between Git and filesystem developers to resolve properly.
