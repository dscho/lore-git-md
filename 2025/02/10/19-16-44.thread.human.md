This thread introduces a useful refinement to `git rebase`'s `--update-refs` functionality, addressing a common workflow pain point. The patch adds an "interactive" mode for ref updates, allowing users to configure automatic ref updates specifically for interactive rebases while keeping them disabled for non-interactive ones. This solves the problem where users who set `rebase.updateRefs=true` globally found it unexpectedly updating refs during automated rebases.

The implementation is thorough, adding new enum values and helper functions to handle the three-state option (off/on/interactive) while maintaining backward compatibility. The author has carefully considered the interaction between config and command-line options, ensuring the new mode works predictably in different contexts. Documentation updates clearly explain the new behavior and its intended use cases, particularly for workflows involving multiple interdependent feature branches.

The change appears well-motivated by real-world experience (the author mentions having "made quite an amount of mess" with the current behavior) and provides a balanced solution that doesn't force one behavior on all users. The technical implementation touches rebase's option parsing and config handling while keeping the changes focused and maintainable.
