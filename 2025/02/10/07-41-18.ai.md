Build system fix for cross-compilation shell path issue in Meson. Patrick Steinhardt responds to Peter Seiderer's report about the Meson build system incorrectly using the host's shell path (/usr/bin/sh) when cross-compiling, where the target expects /bin/sh. The problem stems from `find_program('sh')` calls that don't distinguish between build-time and target-time executables.

The proposed solution involves using Meson's `native:` parameter to properly separate build-host vs target-host program paths, with target paths configurable via cross files. The patch demonstrates this by adding `native: true` to all build-time tool lookups (asciidoc, perl, python etc.) while introducing new `target_*` variables for target-side paths. This maintains the existing functionality while properly supporting cross-compilation scenarios.

The changes span multiple meson.build files, modifying how shell, perl, python and other tool paths are detected and used. Key changes include separating `shell` vs `target_shell` and similar for other tools, with target paths used where the binary will run on the target system. The patch conflicts with Patrick's in-flight meson improvements series, so he plans to submit it after that lands.
