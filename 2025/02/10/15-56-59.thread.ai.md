NFSv4 packfile handling bug report and proposed fix for temporary file permissions during failover. Core issue: Git creates temporary packfiles with O_RDWR flags but 0444 permissions, causing EACCES errors when NFSv4 servers recover state after failover in HA environments. Reproduction shows clone operations failing with "Bad file descriptor" when NFS server restarts mid-operation, with kernel logs showing "state recovery failed". Affected code paths: object-file.c (git_mkstemp_mode for temp file creation) and wrapper.c (underlying open() implementation).

Brian Carlson initially responded to Bryan Maloney's report, confirming the technical behavior but arguing this represents an NFSv4 compliance issue rather than a Git bug, citing POSIX standards that permit opening files with write permissions then changing to read-only. Carlson noted Git's 0444 permissions are intentional to prevent repository corruption, with similar patterns used in zsh and Emacs, and suggested the solution likely requires NFSv4 server changes for proper state synchronization during failover.

Jeff King (peff) has now proposed a concrete Git-side solution: creating tempfiles with 0644 permissions during write operations, then switching to 0444 via fchmod before the final rename into place. This approach would: (1) maintain Git's security model of read-only packfiles while potentially working around NFSv4's permission evaluation timing, (2) add minimal overhead (one extra chmod call) for unaffected systems, and (3) mirror existing permission-adjustment patterns like adjust_shared_perm(). The change would touch object-file.c's tempfile creation logic and potentially wrapper.c's file handling.

Open questions remain about whether this approach would actually resolve the failover issues in practice, and whether NFSv4 server configuration changes could alternatively address the behavior. The discussion has progressed from theoretical concerns to a specific, implementable change that could be tested while maintaining Git's security invariants. All major Git implementations (go-git, libgit2) would need parallel fixes if this change were adopted.
