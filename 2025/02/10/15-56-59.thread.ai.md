NFSv4 packfile handling bug report and proposed fix for temporary file permissions during failover. Core issue: Git creates temporary packfiles with O_RDWR flags but 0444 permissions, causing EACCES errors when NFSv4 servers recover state after failover in HA environments. Reproduction shows clone operations failing with "Bad file descriptor" when NFS server restarts mid-operation, with kernel logs showing "state recovery failed". Affected code paths: object-file.c (git_mkstemp_mode for temp file creation) and wrapper.c (underlying open() implementation).

Brian Carlson has responded to Bryan Maloney's report, confirming the technical behavior but arguing this represents an NFSv4 compliance issue rather than a Git bug, citing POSIX standards that permit opening files with write permissions then changing to read-only. Carlson notes Git's 0444 permissions are intentional to prevent repository corruption, with similar patterns used in zsh and Emacs. He suggests the solution likely requires NFSv4 server changes for proper state synchronization during failover, questioning whether even modifying Git to first open with 0644 then fchmod to 0444 would resolve the issue. The response references POSIX open()/write() specifications and notes all major Git implementations (go-git, libgit2) would need parallel fixes if changed. Current position maintains Git's behavior is standards-compliant, making a Git-side patch unlikely unless a clear POSIX-compliant solution emerges. Open questions remain about whether NFSv4 server configuration changes could address the failover behavior and whether alternative fchmod approach would actually solve the EACCES errors in practice.
