This is a technical follow-up in the ongoing RFC discussion about `git repack`'s promisor pack handling. Han Young points out a flaw in Tomáš Trnka's proposed approach to honor `--keep-pack` and `.keep` files for promisor objects during repacking.

The key observation is that simply copying the keep-pack logic to `repack_promisor_objects()` wouldn't actually prevent keep packs from being repacked, because the current implementation reads all promisor objects first before passing them to pack-objects. Han suggests an alternative approach: filtering keep packs during the `for_each_packed_object()` iteration in `repack_promisor_objects()`.

This email advances the technical discussion by identifying a subtle implementation issue that wasn't caught in earlier reviews. The proposed solution would require deeper changes to the promisor pack handling logic than the initial patch suggested. The thread remains in RFC status while awaiting both the properly formatted resend of the original patch and resolution of this new technical consideration about the keep-pack filtering mechanism.
