Bugfix for Meson cross-compilation shell path issue. Patrick Steinhardt responds to Peter Seiderer's report about the Meson build system incorrectly using the host's shell path (/usr/bin/sh) when cross-compiling, which fails when the target system expects /bin/sh. The problem stems from Meson's `find_program()` not distinguishing between build-time and target executables.

Steinhardt proposes the proper solution: using Meson's `native:` parameter to explicitly specify whether each program is for build or target use. The attached patch demonstrates this by adding `native: true` to build-time tool lookups (like asciidoc and perl) while introducing new `target_*` variables for target executables. This would allow proper cross-compilation when using a cross file to specify target paths.

The patch is currently held up due to conflicts with Steinhardt's in-flight Meson improvements series, but shows the intended direction. This appears to be a well-considered fix for a real cross-compilation pain point, though it will need to wait for the prerequisite series to land first.
