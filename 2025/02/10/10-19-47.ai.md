Key technical details:
- The current error message comes from `git commit`'s `launch_editor()` failure path
- During rebase, using `-m` or `-F` would lose original authorship and message
- The proposed improvement would make the error message rebase-aware
- Current workaround is to use `git commit -m` but this isn't ideal for rebase

The discussion highlights a tension between generic error handling (from `git commit`) and the specific needs of rebase operations. The thread suggests the error message should either:
1) Recommend setting up a working editor when in rebase context, or
