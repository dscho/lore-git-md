This is a follow-up in the ongoing discussion about cross-compilation issues in Git's build systems, specifically regarding how shell paths leak between host and target environments.

Peter Seiderer responds to Junio Hamano's question about whether similar fixes should be made to the make-based build system, given that the issue was originally reported for Meson builds. He suggests that make-based cross-compilation may have worked fine in practice because users were content with the default paths (/bin/sh, /usr/bin/perl) matching between host and target systems, while only native build users tended to customize these paths.

The email doesn't propose any technical changes but provides useful context about historical buildroot usage patterns. It reinforces the pragmatic view that while the issue exists in both build systems, the make-based approach may not need fixing if it hasn't caused problems in practice over many years. The discussion continues to balance between build system parity and practical considerations of what actually needs fixing.
