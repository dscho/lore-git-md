This is a feature patch adding an interactive variant to Git's `--update-refs` rebase option. The patch introduces `--update-refs=interactive` (and corresponding `rebase.updateRefs=interactive` config) which only enables ref updates during interactive rebases, addressing a common pain point in rebase-heavy workflows.

The author notes that while `rebase.updateRefs=true` is useful, it can be dangerous in non-interactive rebases since there's no chance to review which refs will be updated. The new "interactive" mode provides a middle ground by only enabling ref updates when the rebase is explicitly interactive, preventing accidental updates in automated/scripted rebases.

The implementation involves adding a new enum state for the interactive mode, updating option parsing logic, and modifying the documentation. The changes are thorough, touching both user-facing docs and internal handling of the rebase options. The commit message clearly explains the change and its motivation, and the implementation appears careful about backward compatibility and config override behavior.

This seems like a well-considered quality-of-life improvement for users who frequently work with multiple interdependent branches and want more control over ref updates during rebases.
