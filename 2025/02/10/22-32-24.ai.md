Bugfix discussion regarding NFSv4 packfile permissions during failover scenarios. This email from Brian Carlson responds to Bryan Maloney's report about temporary packfiles causing EACCES errors during NFSv4 server failovers. The core issue remains Git creating temp files with O_RDWR flags but 0444 permissions, which NFSv4 re-evaluates during state recovery.

Carlson confirms the problem description is accurate but argues this is an NFSv4 compliance issue rather than a Git bug, citing POSIX standards that explicitly allow this behavior (opening a file with write permissions then changing to read-only). He notes Git intentionally uses 0444 permissions to prevent repository corruption, and that similar behavior exists in other software like zsh and Emacs.

The response suggests the solution likely needs to come from the NFSv4 side, either through server configuration changes to properly synchronize state during failover or by making the implementation more POSIX-compliant. Carlson questions whether even modifying Git to first open with 0644 then fchmod to 0444 would solve the issue, and points out that all major Git implementations would need similar fixes.

Key technical points: the discussion references POSIX open() and write() specifications, mentions alternative Git implementations (go-git, libgit2) that would need parallel fixes, and maintains Git's position that write-then-readonly file handling is standards-compliant behavior. The tone suggests this is unlikely to be addressed via Git patch unless a clear POSIX-compliant solution emerges.
