Platform compatibility fix for the Thunderbird patch processing script, addressing a follow-up concern from the initial bashism fix.

This v2 patch from brian m. carlson builds on the previously accepted POSIX-compliance fix for the `contrib/thunderbird-patch-inline/appp.sh` script. While the initial version replaced the non-portable `echo -e` with `printf`, this iteration adds a missing newline to ensure reliable operation across all POSIX-compliant shells, particularly addressing D. Ben Knoble's observation about `sed` behavior with input lacking final newlines.

The change modifies how Cc and Signed-off-by headers are processed when generating reply emails, now using `printf '%s\n%s\n'` to explicitly add newlines between the `$CMT_MSG` and `$HEADERS` variables before piping to `sed`. The author notes they considered using `'%s\n'` format but chose the current approach for better readability and maintainability.

This represents the completion of the portability fixes for this long-dormant contrib script, with both the original bashism and the subsequent edge case now addressed. The changes remain focused on the script's core functionality of processing patch emails in Thunderbird, specifically the concatenation and parsing of commit messages and email headers. The patch maintains the same simple, single-file modification approach as v1 while adding the additional safety measure for POSIX compliance.
