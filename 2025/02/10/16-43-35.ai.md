This is a continuation of the cross-compilation build system discussion, specifically addressing whether similar fixes should be made to the make-based build system.

Peter Seiderer responds to Junio Hamano's question about whether the Meson build system fixes for cross-compilation (where host and target shell paths differ) should also be applied to the make-based build system. He suggests that make-based cross-compilation may have worked fine in practice because users were content with the hardcoded defaults (like SHELL_PATH=/bin/sh) in the Makefile, while only native build users tended to customize these paths. This implies the issue may not be as pressing for make builds as it is for Meson builds.

The email reinforces the thread's central tension between principle (keeping build systems in parity) and pragmatism (fixing only what's demonstrably broken). Peter's observation about make users' historical satisfaction with defaults provides data supporting Junio's pragmatic inclination to focus the fix on Meson only. The technical specifics remain centered on path handling for shell and other interpreters during cross-compilation, with make using hardcoded defaults while Meson dynamically detects paths.
