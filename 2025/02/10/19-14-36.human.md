This is a feature proposal introducing new configuration and command-line options for `git clean` to better handle excluded files. The series aims to distinguish between different types of exclusions: project-level (`.gitignore`), user-level (`clean.exclude`), and a new "nuclear option" (`--remove-excluded`) to override all exclusions.

The core idea is to protect developer-specific files (like IDE configurations or compilation databases) from accidental removal while still allowing thorough cleaning when needed. The author provides concrete examples of how this would work in practice, showing configuration snippets to protect files like `.idea/` or `compile_commands.json`.

The implementation spans three patches: first adding a string-list pattern helper, then renaming a variable for clarity, and finally introducing the new `clean.exclude` config option and `--remove-excluded` flag. The changes touch documentation, the clean command implementation, and directory handling code.

The proposal appears well-motivated with clear use cases, and the implementation looks thorough with documentation updates matching the code changes. This seems like a practical quality-of-life improvement for developers who frequently need to clean their working trees while preserving certain local files.
