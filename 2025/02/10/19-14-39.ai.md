Feature enhancement for `git clean` adding persistent exclusions and override capability. This final patch in the 3-part series introduces two complementary features: a `clean.exclude` config option for persistent exclusion patterns (equivalent to the `-e` command-line flag) and a `--remove-excluded` flag to bypass all exclusions when needed.

The implementation:
- Adds `clean.exclude` config handling in `builtin/clean.c`, storing patterns in a new `config_exclude_list`
- Introduces `--remove-excluded` flag (no short option) that overrides both command-line and config exclusions
- Updates documentation in both config and command man pages to explain the new options and their interaction with existing flags
- Maintains the existing exclusion hierarchy where `-e`/`clean.exclude` patterns override `-x` behavior
- Cleans up allocated memory for the new exclude list

The commit message provides clear rationale for the feature, distinguishing between project-level ignores (`.gitignore`), user-level persistent exclusions (`clean.exclude`), and the new nuclear option (`--remove-excluded`).

This completes the series' goal of giving users more control over exclusion behavior while maintaining backward compatibility. The implementation appears clean and well-documented, though test coverage isn't visible in the patch (may exist in separate test files). The careful design of the exclusion hierarchy and the intentional lack of a short option for `--remove-excluded` suggest thoughtful consideration of potential footguns.
