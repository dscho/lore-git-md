Cross-compilation fix discussion for Meson build system. Peter Seiderer responds to Patrick Steinhardt's proposed solution for separating build-time and target-time tool paths in Git's Meson build configuration. While Patrick suggested using Meson's `native:` parameter and cross-file configurations, Peter argues this approach may not fully address the issue based on his reading of Meson's cross-compilation documentation, which indicates the `[binaries]` section specifies build-time tools rather than target paths.

Peter identifies a specific bug in Patrick's patch where `perl.found()` is incorrectly used instead of `target_perl.found()` in the template configuration. The discussion continues to focus on proper separation of build-host vs target-host program paths, particularly for shell (`sh`), Perl, Python and other tools where the paths differ between build and target environments. This affects cross-compilation scenarios where host and target paths diverge, originally manifesting when Git 2.48.1's meson.build tried executing non-existent `/usr/bin/sh` on the target.
