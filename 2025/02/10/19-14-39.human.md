Feature enhancement for `git clean` adding persistent exclusions and override capability. This is the final patch in a 3-part series that introduces two new ways to control file exclusions during cleaning operations.

The patch adds a `clean.exclude` config option that works like the existing `-e/--exclude` command-line flag, but persists across invocations. This is intended for user-specific files (like IDE configurations) that should never be cleaned, even when using `-x` for a thorough clean. It also adds a `--remove-excluded` flag (deliberately without a short option) that bypasses all exclusions - both from config and command line - for cases where you really want to remove everything.

The documentation clearly explains the hierarchy of exclusion methods: `.gitignore` for project files, `clean.exclude` for user files, `-x` to ignore project files but keep user files, and `--remove-excluded` to ignore everything. The implementation builds on the preparatory refactorings from earlier patches, adding the new config handling and flag while maintaining backward compatibility.

This appears to be a well-considered addition that fills a clear gap in Git's cleaning capabilities. The commit message provides good rationale for each feature, and the implementation follows established patterns. The only minor question is whether the config option name `clean.exclude` might be too generic given its special behavior compared to other exclusion mechanisms.
