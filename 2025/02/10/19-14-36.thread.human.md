This thread continues the discussion of Ivan Shapovalov's patch series to enhance `git clean` with persistent exclusion patterns. The initial proposal added a `clean.exclude` config option (a persistent version of the existing `-e` flag) and a `--remove-excluded` override flag, maintaining an exclusion hierarchy where command-line `-e` and the config override project-level `.gitignore` rules.

Junio Hamano, the maintainer, raised important design questions in his first response - particularly questioning whether "exclude" was the right terminology and suggesting "precious files" as an alternative concept if the goal was to protect important files. Ivan clarified that this is strictly an extension of the existing exclusion mechanism, not a new category of file handling, and confirmed it wouldn't affect `git status` output.

In the latest message, Junio emphasizes the importance of terminology consistency, agreeing that if this isn't actually about precious files (as Ivan confirmed), then that term should be avoided. He also notes that Ævar Arnfjörð Bjarmason's inclusion was automated via `git-contacts`, which is standard practice.

The discussion remains focused on fundamental design questions: whether to frame this as an exclusion extension or new concept, how to maintain consistency with other Git commands, and the implications for documentation. While the technical implementation is largely settled, the naming and conceptual framing still need resolution between Ivan and Junio before the series can progress.
