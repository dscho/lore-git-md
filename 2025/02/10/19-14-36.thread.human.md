This thread discusses a proposed enhancement to `git clean` that would allow users to persistently specify files to exclude from cleaning operations, rather than having to repeatedly use the `-e` flag. The original patch series from Ivan Shapovalov introduced a `clean.exclude` config option that would work like the existing `-e` flag but persist across invocations, along with a `--remove-excluded` override flag.

Junio Hamano, the Git maintainer, raised significant design questions in his review, suggesting the terminology might need to shift from "exclude" to "precious" to better reflect the concept of protecting valuable content. He also proposed alternative storage locations like `$GIT_DIR/info/precious` rather than using the config system.

In his response, Ivan clarified that his intent was simply to extend the existing exclusion mechanism for convenience, not to introduce new file classification semantics. He provided examples like `config.mak` as cases where persistent exclusions would be useful, and explained that the CC to Ævar Arnfjörð Bjarmason was automated by contribution tooling.

The discussion has now reached a key decision point around several fundamental questions: whether to keep the "exclude" terminology or adopt "precious", where these patterns should be stored (config vs separate file), and how to clearly document the interaction between project-level ignores and user-level exclusions. The thread remains active as participants work through these design considerations before the feature can move forward.
