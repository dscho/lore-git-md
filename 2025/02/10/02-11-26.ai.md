Bugfix for the contrib/subtree script, addressing an edge case when working with new repositories or orphan branches.

This patch fixes a confusing error message in `git subtree add` when run in a repository with an invalid HEAD (such as a newly initialized repo or orphan branch). Currently, the command fails with a misleading "working tree has modifications" message when it actually can't resolve HEAD. The patch adds a preliminary check using `git show-ref --verify` to detect invalid HEAD references and provide a more accurate error message.

The change is straightforward - it inserts a new verification step in the `ensure_clean()` function of `git-subtree.sh` that runs before the existing diff-index check. When HEAD is invalid (like pointing to a non-existent branch), it now fails with a clear message about the HEAD reference problem rather than incorrectly claiming there are working tree modifications.

This appears to be a legitimate bug with a clean fix. The patch is small and focused, touching only the subtree contrib script. The commit message clearly explains both the problem scenario and solution. While simple, this improves the user experience by providing more accurate error diagnostics in edge cases that could reasonably happen during normal use (like starting work in a new repo).
