Performance improvement patch adding progress reporting during MIDX verification's QSORT operation. This is part 1 of a 2-patch series implementing progress meters for multi-pack-index operations.

The patch modifies `midx.c` to show incremental progress during the QSORT phase of MIDX verification, where previously the progress meter would jump from 0% to 100% without intermediate updates. The implementation:

1. Introduces a `sort_progress` static variable and tracking of `last_max_pos` to monitor sorting progress
2. Modifies the `compare_pair_pos_vs_id` comparator to update progress when it encounters new maximum positions
3. Uses a sparse progress update interval (every 4096 items) to balance visibility with performance
4. Maintains the existing MIDX_PROGRESS flag behavior while adding the new reporting

Key technical details:
- Progress updates are triggered during the QSORT operation via the comparator function
- Uses Git's existing progress API with sparse updates for performance
- The progress meter shows "Sorting objects by packfile" during this phase
- Changes are contained to the MIDX verification path in `midx.c`

The implementation appears clean and focused, with the progress reporting logic following Git's existing patterns. The sparse update interval is explicitly noted as an arbitrary choice that could be adjusted. The patch leaves the door open for future improvements while solving the immediate progress visibility issue.
