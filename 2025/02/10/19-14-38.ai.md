Refactoring patch in the `git clean` exclusion patterns series.

This is the second patch in a three-part series enhancing `git clean` with persistent exclusion patterns. It performs a straightforward variable refactoring, renaming the `ignored` flag to `remove_ignored` in the clean command's implementation. The change is purely internal - no behavior is modified. The new name better reflects the variable's purpose (controlling whether ignored files should be removed) and maintains consistency with the existing `ignored_only` flag.

The patch touches only `builtin/clean.c`, updating the variable declaration, its usage in option parsing, and several condition checks. The most notable change is in the option parsing where the `-x` flag's description remains "remove ignored files, too" but now stores its value in the more descriptively named variable.

This appears to be a preparatory change for the series' final patch which will introduce the new `--remove-excluded` flag. The clearer variable naming will likely help when implementing the interaction between these related flags. The change is small and focused, with no apparent impact on the existing functionality.
