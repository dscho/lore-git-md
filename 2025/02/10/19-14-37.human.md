Refactoring patch for the `git clean` exclusion series.

This is the first of three patches introducing new exclusion controls for `git clean`. It's a preparatory refactoring that extracts pattern-list creation from string lists into a new helper function `add_patterns_from_string_list()`. The change:

1. Moves the string-list-to-pattern-list conversion logic from `builtin/clean.c` to a new reusable function in `dir.c`
2. Updates the clean command to use this helper
3. Adds the function declaration to `dir.h` for broader use

The patch appears well-scoped and mechanical, with no behavior changes. It simplifies the upcoming patches that will introduce persistent exclusions via config. The implementation looks clean, though the commit message could better explain why this refactoring is needed (presumably to avoid duplicating this logic when implementing the new config-based exclusions).

This is groundwork for the series' main features - the actual exclusion enhancements will come in subsequent patches. The change touches core directory/file handling code but should be low-risk since it's just reorganizing existing functionality.
