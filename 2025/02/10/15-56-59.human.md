Bugfix for NFSv4 compatibility issue with temporary packfiles during clone.

Bryan Maloney reports a problem where `git clone` fails with "Bad file descriptor" errors when the destination is on an NFSv4 mount and the NFS server restarts during the operation. The root cause lies in how Git creates temporary packfiles - it opens them with O_RDWR but then sets read-only (0444) permissions, which NFSv4's state recovery mechanism rejects after a server restart.

The issue manifests when an NFSv4 server fails over or restarts while a client is in the middle of receiving packfiles. NFSv4 re-evaluates file access during state recovery and denies access since the file's permissions don't match the open mode. The patch identifies the problematic code paths in object-file.c and wrapper.c where the temporary files are created with this inconsistent permission pattern.

The report includes detailed reproduction steps showing how to trigger the error by restarting the NFS server during a clone operation. The error appears in both the Git output ("Bad file descriptor") and kernel logs ("NFSv4: state recovery failed...error = -13"). This looks like a legitimate edge case that would affect users running Git on NFSv4 mounts with high-availability configurations. The analysis appears thorough and the problem well-isolated.
