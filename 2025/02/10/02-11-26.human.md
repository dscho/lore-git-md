This is a bugfix for the `git subtree` contrib command, addressing an edge case when working with new or orphan branches.

The patch fixes a confusing error message that occurs when trying to add a subtree in a repository with an invalid HEAD (such as a newly initialized repo or orphan branch). Currently, the command fails with a misleading "working tree has modifications" message when the real issue is that HEAD doesn't point to a valid commit.

The solution adds a preliminary check using `git show-ref --verify` to validate HEAD before proceeding with the subtree operation. When HEAD is invalid, it now provides a clearer error message explaining that subtree operations can't be performed as the first commit of a branch.

The change is straightforward and well-contained, touching only the `ensure_clean()` function in the subtree shell script. The commit message clearly explains both the problem and solution, including the exact error messages users would see before and after the change. This appears to be a genuine quality-of-life improvement for users working with subtree in these edge cases.
