This is a bug report and proposed fix for an NFSv4 compatibility issue in Git's packfile handling. The core problem occurs when cloning over NFSv4 to an HA filesystem that experiences a failover - Git creates temporary packfiles with read-write flags but read-only permissions, which causes access errors (-13/EACCES) when the NFS server recovers state after a failover.

The issue stems from an inconsistency between how Git opens temporary packfiles (using O_RDWR) and the permissions it sets (0444). While this works initially, NFSv4's state recovery mechanism re-evaluates permissions during failover and rejects the previously valid file handles. The reporter provides clear reproduction steps showing the error occurring during a clone operation when the NFS server is restarted mid-operation.

The affected code paths are in object-file.c (creating temp files with git_mkstemp_mode) and wrapper.c (the underlying open() call). The error manifests as "Bad file descriptor" in Git's output and "state recovery failed" in kernel logs. This specifically impacts HA NFSv4 deployments where failovers are expected behavior.

The report is thorough, with clear error logs, code references, and reproduction steps. The issue appears legitimate and well-documented, affecting a specific but important use case (Git operations on HA NFS shares). The technical analysis suggests this is a real bug rather than a configuration issue, though the impact is limited to NFSv4 environments with failover scenarios.
