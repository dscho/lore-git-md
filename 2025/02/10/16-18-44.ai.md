Cross-compilation build system issue affecting both Meson and make builds.

Junio Hamano responds to Patrick Steinhardt's proposed Meson fix for the cross-compilation shell path issue, raising the broader question of whether similar fixes should be made to the traditional make-based build system. He notes that historically, Git's make build assumed host and target paths would match, making cross-compilation impossible by design. 

The email presents two perspectives: the principled argument that both build systems should be maintained equally (especially since Meson hasn't officially replaced make), versus the pragmatic view that since nobody has seriously complained about make-based cross-compilation limitations in 20 years, it may not be worth fixing. 

This introduces a new dimension to the thread - no longer just about fixing Meson's cross-compilation support, but whether to make parallel changes to make. The discussion now hinges on balancing build system maintenance philosophy against real-world usage patterns, with Junio appearing to lean toward focusing only on the Meson fix given the lack of demand for make-based cross-compilation support.

Key technical context remains the separation of build-time vs target-time tool paths (sh, perl, python etc.), but now with added consideration of build system parity. The thread's open questions now include whether to scope the fix to Meson only or extend it to maintain feature parity between build systems.
