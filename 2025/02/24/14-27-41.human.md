This is a documentation and naming consistency patch in the ongoing series adding signed commit support to git fast-export/import. 

The patch renames the `--signed-tags=warn` option to `warn-verbatim` to better match the existing pattern where `warn-strip` pairs with `strip`. The change makes the behavior more obvious - the "warn" variant will export signatures verbatim while showing a warning, just as "warn-strip" shows a warning while stripping signatures. The old `warn` name is kept as a deprecated synonym for backward compatibility.

The change affects documentation, the enum definition in the code, and adds new test cases to verify both the new name and backward compatibility work correctly. This appears to be a straightforward improvement to the API naming consistency, with proper attention to maintaining compatibility. The patch is well-contained and follows the established pattern in this area of the code.

This is part of the v5 series reviving Luke Shumaker's work on commit signatures in fast-export/import, with Christian Couder shepherding the rebases and cleanups. The series has seen thorough review and appears close to being ready for inclusion.
