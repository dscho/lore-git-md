Security hardening note in remote-object-info implementation.

Jeff King identifies a security vulnerability in the final patch of this series implementing the `remote-object-info` batch command. The current implementation uses a simple `strstr()` check for `%(objectsize)` in the format string, which is insufficient as it doesn't properly validate that *only* the objectsize placeholder is used. This allows malformed format strings containing other placeholders (like `%(objecttype)`) to pass through, leading to segfaults when the unsupported placeholders are processed.

The issue occurs in the `get_remote_info()` function where format string validation happens just before making the object-info request. While the series has extensive security hardening for the protocol and transport layers, this client-side input validation gap was overlooked. The problem demonstrates how even in a mostly-complete implementation, edge cases in user input handling can introduce vulnerabilities.

This feedback comes late in the review cycle (v11 of the series) but addresses a concrete security issue that would affect users trying to use unsupported format options. The fix would need to either properly validate the format string contains only allowed placeholders, or implement support for the additional placeholders being requested. Given the context of the thread summary showing all other security feedback has been addressed, this appears to be the final security-related issue needing resolution before merging.
