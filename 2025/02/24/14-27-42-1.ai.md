Documentation patch clarifying the risks of using 'verbatim' signature handling in git-fast-export.

This patch improves the documentation for the `--signed-tags` option in git-fast-export, making it clearer why the 'verbatim' and 'warn-verbatim' modes may be problematic. The key change is expanding the explanation of why signatures might become invalid - noting that transformations during export (like excluding revisions) can change the hashes being signed, not just post-export transformations. It also adds explicit warnings that these modes should only be used when either no tag-affecting transformations will occur or when signature validity is not a concern.

The patch maintains backward compatibility by keeping the deprecated 'warn' synonym while making the documentation more precise about the risks. This is part of a larger series adding signed commit support to fast-export/import, where signature handling consistency is important. The changes align with the series' goal of providing clear, safe defaults (abort by default) while allowing expert use cases.
