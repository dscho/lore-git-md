This is a v2 cover letter for a 4-patch series converting oid-related unit tests (oid-array, oidmap, oidtree) from custom test code to the Clar framework, part of Git's test modernization effort. The series builds on previous discussion about helper function placement and assertion styles, with Seyi Kuforiji as author and Patrick Steinhardt/Phillip Wood as mentors.

Key changes in v2:
- Keeps helper functions in lib-oid.c (now with `cl_` prefix) rather than moving them to unit-test.c
- Improves commit message clarity
- Refactors code based on review feedback
- Maintains the unresolved debate about assertion styles (`cl_assert()` vs `cl_failf()`)

The series converts three test files (oid-array, oidmap, oidtree) while:
- Preserving test coverage
- Adding Clar setup/teardown functions
- Using new `cl_parse_any_oid()` helper for OID parsing
- Renaming files from t-*.c to u-*.c convention

Notable technical details:
- lib-oid.c remains but with Clar-compatible interfaces (`cl_setup_hash_algo()`, `cl_parse_any_oid()`)
- Tests now stop at first failure rather than accumulating errors
- Some assertions converted to `cl_failf()` in oidmap/oidtree tests despite ongoing style debate
- Build system updated to include lib-oid.o in Clar test builds

The cover letter notes this is part of broader test standardization but doesn't address the unresolved assertion style question from the previous thread. The series appears technically sound but leaves open whether the assertion style compromises will satisfy Phillip Wood's concerns about debuggability.
