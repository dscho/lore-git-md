This is a bugfix patch in the signed commit fast-export/import series, addressing a memory safety issue. The patch fixes a problem where `find_encoding()` was modifying memory from `get_commit_buffer()` despite taking a `const char*` parameter, which violates Git's buffer handling conventions.

The key changes are:
- Replaces the problematic `find_encoding()` helper with `find_commit_header()` from commit.h, which properly handles buffer access
- Restructures the commit parsing logic to avoid double-scanning the buffer
- Introduces a `commit_buffer_cursor` variable to track parsing position
- Updates encoding handling to use length-based string operations rather than null-termination
- Maintains all existing functionality while being more careful with buffer access

This appears to be a well-justified change that addresses a real memory safety issue while keeping the same behavior. The patch is part of Christian Couder's v5 series reviving Luke Shumaker's signed commit support work, and this particular fix responds to earlier review feedback about buffer safety concerns from Junio Hamano. The change is focused and doesn't appear to introduce new risks, while making the code both safer and slightly more readable.
