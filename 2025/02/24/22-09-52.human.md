This is a clarification in the ongoing discussion about HTTP authentication and netrc usage in Git. Brian m. carlson responds to Junio C Hamano's question about whether earlier comments referred to general HTTP netrc usage or specifically the HTTP walker (an older component). 

Carlson confirms the discussion is on netrc usage in HTTP code paths generally, not the HTTP walker. He notes that while some users still rely on the WebDAV-based HTTP protocol, he expresses skepticism about its future viability - particularly pointing out limitations in how it handles packed-refs and its incompatibility with the upcoming reftable backend. 

The exchange highlights the tension between maintaining legacy functionality (netrc support) versus modernizing Git's HTTP stack, with Carlson appearing to lean toward deprecation rather than expanding support for what he sees as a dying protocol. This moves the thread closer to a decision point about netrc's future in Git.
