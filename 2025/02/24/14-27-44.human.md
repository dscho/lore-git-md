This is the final patch in a series adding signed commit support to `git fast-export` and `git fast-import`, mirroring the existing signed tag functionality. The patch implements a new `--signed-commits` option that provides the same handling modes as `--signed-tags` (abort, verbatim, warn-verbatim, strip, warn-strip), with the safer 'abort' as the new default behavior.

The implementation carefully handles commit parsing to properly extract signatures while maintaining compatibility with existing encoding headers. It includes comprehensive tests verifying all signature handling modes and maintains backward compatibility via an environment variable escape hatch for third-party tools. The patch builds on previous work in the series that addressed buffer safety concerns and unified the tag/commit handling code paths.

This appears to be a well-tested and thoughtfully implemented feature, completing the series' goal of bringing signed commit support to the fast-export/import pipeline. The patch maintains the series' high standard of documentation, test coverage, and backward compatibility considerations.
