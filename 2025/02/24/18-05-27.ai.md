This is a technical review comment on patch 6/9 in Patrick Steinhardt's bitmap-accelerated object filtering series. Junio Hamano points out that the patch's bitmap iteration function needs adjustment to account for changes introduced in commit 2189649b ("pack-bitmap.c: keep track of each layer's type bitmaps"), which added type-specific bitmaps to the bitmap_index struct.

The patch in question exposes a new `for_each_bitmapped_object()` function in pack-bitmap.h that allows callers to iterate over all bitmapped objects of a specific type. The implementation refactors the existing type-specific iteration code, adding a payload parameter to the callback signature and introducing helper functions like `ewah_for_type()` to centralize bitmap lookup logic.

Key technical details:
- Modifies callback signatures in builtin/pack-objects.c, builtin/rev-list.c, and reachable.c to accept a payload parameter
- Introduces new internal iteration function `for_each_bitmapped_object_internal()`
- Adds public API `for_each_bitmapped_object()` to pack-bitmap.h
- Maintains existing `show_objects_for_type()` as a wrapper for backward compatibility

The comment suggests the implementation may need updates to properly handle the layered type bitmaps introduced in 2189649b, though the specific concerns aren't detailed in this email. Taylor Blau is CC'd as a likely reviewer familiar with the bitmap changes.

This appears to be a mid-series refinement of the bitmap infrastructure that will be used by subsequent patches for the actual filtering functionality. The changes look focused and well-contained, though the interaction with the newer type-specific bitmaps will need verification.
