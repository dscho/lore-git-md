Jeff King provides a late-stage review of the remote-object-info feature in cat-file, focusing on security considerations in the command parsing. This is part of the v11 series implementing remote object info queries.

King notes he initially misunderstood the security context - the code runs client-side rather than server-side, so some protections may be unnecessary. He suggests simplifying the command parsing by splitting on spaces rather than using the more complex split_cmdline(), since the input format is strictly "remote-object-info <url> <oid>..." with no need for shell-style quoting.

The proposed simplification would:
- Replace split_cmdline() with direct space-based parsing
- Remove the MAX_REMOTE_OBJ_INFO_LINE check
- Handle OIDs by walking the space-separated list directly
- Still properly handle URL encoding requirements

This appears to be a quality-of-implementation suggestion rather than a blocking issue, coming from Git's security-conscious maintainer. The change would make the code both simpler and more robust by removing unnecessary complexity while maintaining the security properties needed for client-side operation.
