This is part 2/5 of a test modernization series converting oid-array tests to the Clar framework. The patch focuses on converting the test assertions and restructuring the test cases to fit Clar's style.

The author responds to reviewer Phillip Wood's feedback about losing debugging information in the conversion. Seyi argues that simpler assertions without custom messages make tests more maintainable, suggesting that debuggers can be used when failures occur. They also note plans to work with Clar upstream to improve assertion messages in the future.

Key technical changes in this patch:
- Replaces custom test assertions with Clar's `cl_assert*` macros
- Moves test input arrays to global scope for reuse
- Introduces `test_oid_array__initialize()` for hash algorithm setup
- Restructures tests into separate functions rather than using macros with descriptions

Phillip had pointed out that the hash algorithm initialization check is redundant (already handled by Clar's infrastructure) and that the loss of detailed failure messages (like which OIDs failed comparison) makes debugging harder. Seyi acknowledges the initialization issue but maintains their position on assertion simplicity.

The conversion appears technically sound but the debate about assertion verbosity remains unresolved. The patch follows the series' pattern of modernization while sparking discussion about test debugging tradeoffs.
