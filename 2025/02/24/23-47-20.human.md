This is a bugfix for the final patch in an 8-part series adding remote object-info functionality to Git. Jeff King points out a security vulnerability in the newly added `remote-object-info` batch command where malformed format strings can cause a segfault.

The issue occurs when users specify format placeholders that aren't actually supported by the remote object-info feature (like `%(objecttype)`). While the code checks for the presence of `%(objectsize)`, it doesn't properly validate against unsupported placeholders, leading to crashes.

This comes as a late-stage review comment on what appears to be a well-tested and security-hardened feature. The series has already gone through 11 iterations with extensive review, including security scrutiny from Jeff King himself. The fact that this edge case slipped through suggests the input validation could use one final tightening before merging.

The patch being discussed is the culmination of significant work to enable querying object sizes from remote repositories without full downloads, with both client and server components now implemented. While this particular issue is serious (a segfault), it appears to be the last remaining bug in an otherwise mature implementation.
