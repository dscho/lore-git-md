This is a feature patch series adding support for signed commits to `fast-export` and `fast-import`, reviving and completing work started by Luke Shumaker in 2021. The series consists of 6 patches - 1 preparatory style fix from Christian Couder and 5 substantive patches from Shumaker that have been rebased and polished by Couder.

The core change adds a new `--signed-commits` option to `fast-export` that mirrors the existing `--signed-tags` functionality, allowing control over how commit signatures are handled during export (abort, strip, warn, etc). The default changes from silently stripping signatures to aborting, with an environment variable escape hatch for backward compatibility. Corresponding import support is added to `fast-import` to handle the signature data.

Key technical details:
- New enum `sign_mode` unifies handling of signed tags and commits
- `find_commit_multiline_header()` helper extracts signature blocks
- Support for both GPG and GPG-SHA256 signature formats
- Memory safety fixes around commit buffer handling
- Comprehensive tests in t9350 covering all modes
- Documentation updates in both fast-export and fast-import manpages

The changes since v4 include rebasing, style fixes, memory leak fixes, test improvements, and addressing Junio's feedback on buffer safety and code organization. Two outstanding items from earlier reviews remain unaddressed: signature validation in fast-import and modernizing test style in t9350, which the authors suggest could be follow-up work.

The series appears well-tested (CI passes) and carefully implemented, with attention to backward compatibility and edge cases. The changes touch core fast-import/export code paths but seem focused and non-disruptive. The most likely discussion points may be around the default behavior change to abort on signed commits and whether the signature validation feature should be included now.
