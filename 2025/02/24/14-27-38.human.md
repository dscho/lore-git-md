This is a feature patch series adding support for signed commits to `fast-export` and `fast-import`. Christian Couder is reviving Luke Shumaker's 2021 work, addressing feedback and polishing the implementation.

The series introduces a new `--signed-commits` option for `fast-export` that mirrors the existing `--signed-tags` behavior, allowing users to control how commit signatures are handled during export (abort, strip, warn, or preserve verbatim). The default changes from silently stripping signatures to aborting when encountering signed commits, with an environment variable escape hatch for backward compatibility.

Key technical details:
- Adds signature handling for both SHA1 and SHA256 GPG signatures
- Includes comprehensive tests covering all signature handling modes
- Makes related improvements to commit buffer handling to avoid memory issues
- Modernizes some test infrastructure along the way

The implementation looks thorough, with careful attention to edge cases and memory safety. The series has been rebased on current master and incorporates feedback from Junio Hamano on earlier versions. While it doesn't implement signature validation in `fast-import` (considered out of scope), it provides a solid foundation for handling signed content during repository transfers.

This appears ready for serious consideration, with the main outstanding question being whether to include a preparatory patch modernizing the test file's style (currently deferred to a potential follow-up series).
