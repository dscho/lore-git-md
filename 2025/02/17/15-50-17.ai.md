Performance optimization in the refs subsystem, specifically targeting `git update-ref`'s object ID parsing. This patch (3/14 in the series) builds on Patrick Steinhardt's refactoring work to introduce the `GET_OID_HASH_SKIP_AMBIGUITY_CHECK` flag, now applying it to `update-ref` operations.

The change modifies `update-ref` to skip expensive refname ambiguity checks when parsing object IDs, since these checks provide little value in this plumbing command. The commit argues this is justified because: (1) `update-ref`'s manpage clearly expects object IDs, making ambiguity unlikely, and (2) as plumbing, interactive warnings are rarely seen anyway. Benchmarks show significant speedups - 1.19x faster for files backend and 2.32x for reftable when creating many refs.

The implementation replaces all `repo_get_oid()` calls in `builtin/update-ref.c` with `repo_get_oid_with_flags()` using the new skip flag. The performance gains are particularly from avoiding repeated ref lookups during bulk operations via `--stdin`. The reftable backend sees greater relative improvement due to its faster baseline disk writes.

This patch demonstrates the first concrete application of the series' new object lookup infrastructure, showing how the flag-based API enables targeted performance optimizations. It maintains the series' pattern of backend-agnostic improvements while showing how reftable can benefit disproportionately from certain optimizations. The change is focused and low-risk, touching only `update-ref`'s object parsing while leaving other commands' behavior unchanged.
