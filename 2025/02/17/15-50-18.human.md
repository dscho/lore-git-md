Performance optimization patch in the refs subsystem, part of a series addressing inefficiencies in refname availability checks. This is the 4th of 14 patches in the series.

Patrick Steinhardt introduces a new function `refs_verify_refnames_available()` that extends the existing single-refname checking logic to handle batches of references. The key change is restructuring the verification code to loop through multiple refnames while maintaining the same validation rules (checking for conflicts with prefixes/suffixes and extras/skip lists). The existing single-refname function is reimplemented as a wrapper around this new batch version.

This is an infrastructure change that enables future optimizations - the commit message notes the current implementation is functionally equivalent but will be tuned in later patches. The change spans both refs.c (where the bulk of the verification logic lives) and refs.h (adding the new public interface).

The patch is part of a larger performance optimization effort that has already shown significant speedups (5-7.5x for reftable backend in earlier patches). This particular change doesn't yet include the performance improvements - it's laying groundwork for them by restructuring the code to handle batches of refnames efficiently. The diff is large but mostly mechanical - moving the existing logic inside a loop while preserving all the validation rules.
