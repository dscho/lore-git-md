This is part 10 of a performance optimization series for the refs subsystem, specifically implementing iterator seeking for the reftable backend. The patch adds seek capability to reftable ref iterators, completing the iterator reseeking work that was previously implemented for other iterator types. The implementation is straightforward since the low-level reftable iterators already support seeking, though it explicitly does not support seeking on reflog iterators (which now BUG() if attempted).

The changes include proper memory management for the prefix string (now allocated/freed rather than borrowed) and adds error checking for `reftable_stack_init_ref_iterator()` that was previously missing. This is a technical but important piece of the larger performance optimization effort, enabling more efficient ref lookups in the reftable backend by allowing iterators to be repositioned rather than recreated.

The patch appears well-contained and properly integrated with the broader series' iterator lifecycle changes. It maintains the pattern seen in the thread of careful error handling and clear ownership of resources. While not a flashy change on its own, it's a necessary component for the performance gains demonstrated elsewhere in the series.
