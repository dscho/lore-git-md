This is a feature patch adding a new "prompt-yes" mode to Git's `help.autocorrect` configuration. The patch builds on the existing "prompt" mode but changes the default response to "Yes" when confirming suggested command corrections, making it more convenient for users who typically want to accept Git's autocorrections.

The implementation introduces a new `AUTOCORRECT_PROMPT_YES` constant (-5) in help.c, updates the config parsing logic in `parse_autocorrect()`, and modifies the interactive prompt handling in `help_unknown_cmd()`. When not in a terminal, "prompt-yes" falls back to immediate execution rather than the "prompt" mode's fallback to doing nothing. The documentation in Documentation/config/help.adoc is updated to describe the new mode alongside the existing options.

This is version 2 of the patch, rebased against master to account for commits e21bf2c and e4542d8. The author notes this is their first Git contribution and acknowledges the lack of tests due to the difficulty of testing interactive prompts. The patch remains coordinated with Scott Chacon's parallel work on boolean config values for `help.autocorrect`, as discussed in the thread.

Key technical details for future reference: the new mode value (-5) is inserted between existing constants, the prompt text changes from "[y/N]" to "[Y/n]", and the non-terminal fallback behavior differs from "prompt" mode. The implementation is contained to the help subsystem with no new exported symbols.
