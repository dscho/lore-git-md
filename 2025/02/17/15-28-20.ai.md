This is the final patch in a bugfix series enhancing `git fsck`'s packed-refs validation. It integrates the new consistency checks (previously implemented in `git refs verify`) into `git fsck` with a new `--[no-]references` option to control the behavior.

The patch adds a `fsck_refs()` function that runs `git refs verify` as a child process, maintaining progress reporting and error handling consistent with fsck's existing behavior. The new `--references` option (on by default) allows users to skip these checks if desired. The implementation includes:

1. A progress indicator showing "Checking ref database" (though currently hardcoded to 1 step since loose ref counting isn't implemented yet)
2. Passing through fsck's `--verbose` and `--strict` flags to the child process
3. Comprehensive tests verifying the option works for both loose and packed ref validation cases
4. Documentation updates for the new command-line option

The changes touch `builtin/fsck.c` (main implementation), `Documentation/git-fsck.adoc` (option documentation), and `t/t0602-reffiles-fsck.sh` (test cases). The tests specifically verify that:
- Ref validation warnings appear with `--references` (default)
- Warnings are suppressed with `--no-references`
- The behavior works consistently for malformed refs with trailing garbage

This completes the series by exposing the previously implemented ref validation checks through fsck's main interface while maintaining backward compatibility and providing user control over the behavior. The implementation follows Git's standard patterns for child process execution and progress reporting.
