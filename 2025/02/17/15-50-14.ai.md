This is a performance optimization series for the refs subsystem, specifically targeting inefficiencies in refname availability checks across both files and reftable backends. The series stems from performance issues in the reftable backend when handling tombstone references, though the author notes the benchmark scenario (deleting and recreating all refs) is somewhat artificial.

The series introduces three main optimizations: (1) skipping redundant object ID ambiguity checks in `git-update-ref`, (2) batching and deduplicating refname prefix checks using a `strset`, and (3) reusing reseekable ref iterators rather than recreating them for nested ref checks. The changes touch core refs infrastructure and all major ref backends (files, packed, reftable).

Key technical details include new functions like `repo_get_oid_with_flags()` and `refs_verify_refnames_available()`, plus iterator reseeking support across all backend types. Benchmarks show significant improvements - up to 7.5x faster for the reftable backend in the deletion/recreation case, and ~5x faster for more realistic scenarios with many preexisting refs. The files backend sees more modest (~15-22%) gains.

The series is well-structured with clear progression: early patches handle the OID checks, middle patches implement batching, and later patches add iterator reseeking support before finally combining them. The extensive benchmark results demonstrate the problem and validate the solutions. This appears to be a thorough optimization effort that maintains compatibility while addressing real performance pain points, particularly for reftable users.
