Performance optimization patch introducing batched refname availability checks as part of the ongoing refs subsystem improvements.

This patch adds a new `refs_verify_refnames_available()` function that performs the same reference conflict checking as the existing `refs_verify_refname_available()`, but operates on a list of references rather than a single one. The implementation currently just loops through individual checks, but lays groundwork for future optimizations by centralizing the checking logic. The existing single-ref function is reimplemented as a wrapper around this new batch version.

Key technical details:
- New function signature in refs.h takes a `string_list` of refnames instead of single string
- Core checking logic moved from single-ref to batch version
- All existing checks preserved (prefix/suffix conflicts, extras/skip lists)
- Error reporting remains identical through `strbuf` parameter
- Single-ref API maintained for backward compatibility

This is part of a larger series (position 4/14) optimizing ref operations, particularly for the reftable backend. While this initial version doesn't yet show performance gains, it enables subsequent patches to optimize the batch case by reducing redundant work across multiple ref checks. The changes span refs.[ch] with significant refactoring of the verification logic but no behavior changes.
