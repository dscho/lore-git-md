This is a follow-up in the thread about `git show --format=email` behavior with `format.from` configuration. Antonin Godard responds to Junio Hamano's skepticism about whether `format.*` configs should apply to `git show` at all.

The key new information is a concrete use case: the b4 patch management tool uses `git show --format=email` internally, and currently doesn't respect users' `format.from` settings when doing so. This provides a practical justification for why someone might want this behavior beyond just theoretical consistency.

Antonin points out that `git_log_config()` already processes other `format.*` variables (like `format.subjectPrefix`) for `git show`, suggesting there's precedent for this configuration scope. The email maintains a constructive tone while pushing back on Junio's position that this might be working as intended.

The discussion remains at a design philosophy level - whether email-formatting configs should be `format-patch`-specific or apply more broadly to email-formatted output from any command. The b4 use case adds weight to the argument for broader applicability, though the thread still awaits either consensus or further technical arguments about configuration scope.
