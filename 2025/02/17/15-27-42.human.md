This is a bugfix patch in a series enhancing `git fsck`'s packed-refs validation. It specifically adds filetype checking for the packed-refs file to ensure it's a regular file (not a symlink or other special file type).

The patch introduces a check using `lstat()` to verify the packed-refs file is a regular file, reporting an error via the existing `FSCK_MSG_BAD_REF_FILETYPE` message if not. The implementation handles the case where packed-refs doesn't exist (ENOENT) gracefully. A new test case verifies the behavior by creating a symlink to simulate an invalid filetype.

This is part of a larger effort (v5 3/8) to add comprehensive validation for packed-refs files, with mentorship from Patrick Steinhardt and Karthik Nayak. The patch follows earlier feedback to use `lstat` instead of `open_nofollow` for filetype checking. The change is well-contained, adding about 30 lines of implementation code and a corresponding test case.

The patch appears technically sound with clear motivation (preventing potential issues from malformed packed-refs files) and maintains backward compatibility by not failing when the file is missing. The test case provides good coverage of the new behavior.
