This is a documentation patch that explains Git's special handling of submodule merge conflicts. Lucas Seiki Oshiro proposes adding a paragraph to `git-merge.adoc` that describes two cases where Git handles submodule conflicts differently than regular file conflicts:

1. When one submodule commit is a descendant of the other, Git will attempt to fast-forward the descendant (for both `ort` and `recursive` merge strategies)
2. When there are possible merge commits in the submodule that could resolve the conflict, Git will suggest one but still mark it as unmerged for user confirmation

The patch comes from the author's personal experience trying to understand why some submodule merges behaved differently on GitHub versus locally. They previously documented this behavior in a blog post and now want to incorporate it into Git's official documentation. The change is small (7 lines added) and focused on the merge documentation, though the author acknowledges it could potentially belong in submodule documentation instead.

The patch appears well-motivated and clearly explains behavior that isn't currently documented but could help users understand submodule merges better. The implementation is straightforward - just adding explanatory text to an existing section about merge conflicts.
