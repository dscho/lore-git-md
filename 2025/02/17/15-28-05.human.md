This is part 6/8 in a bugfix series enhancing `git fsck`'s validation of packed-refs files. The patch focuses on adding detailed consistency checks for individual entries in the packed-refs file.

The patch implements two main validation functions:
1. `packed_fsck_ref_main_line()` checks the main ref entry line (containing the OID and refname), verifying the OID format, proper spacing, and refname validity (including NUL character detection)
2. `packed_fsck_ref_peeled_line()` validates peeled reference lines (those starting with '^'), checking the peeled OID format and trailing content

The implementation adds new error messages to `fsck.h` and documents them, while the test suite is expanded with a comprehensive test case that exercises various invalid packed-refs entry formats. The test verifies detection of:
- Invalid OIDs
- Missing spaces after OIDs
- Malformed refnames
- Invalid peeled references
- Trailing garbage after peeled OIDs

This continues the series' trend of thorough validation, with clear error reporting and comprehensive test coverage. The patch appears well-structured and follows the established pattern from previous patches in the series.
