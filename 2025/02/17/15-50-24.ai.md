Performance optimization series for refs subsystem, implementing iterator seeking for reftable backend.

This patch completes the `.seek` vtable function implementation for reftable iterators, a key piece of the broader refs performance optimization series. It adds seeking capability to the reftable ref iterator while explicitly not supporting it for reflog iterators (which will BUG if attempted). The changes include proper memory management for the prefix string and adds error checking for `reftable_stack_init_ref_iterator()` that was previously missing.

The implementation follows the established pattern seen in other iterator types earlier in the series, with the reftable-specific seeking delegating to the low-level reftable iterator's seek capability. The patch maintains consistency with the series' iterator lifecycle changes by properly freeing the prefix string during both seeking and release operations.

This is one of the final pieces needed to fully enable the reseeking capability across all major iterator types, which provides the foundation for the performance optimizations in nested refname availability checks. The reftable backend changes here complement similar work done earlier for files backend and other iterator types, completing the unified seeking interface across Git's ref storage systems.
