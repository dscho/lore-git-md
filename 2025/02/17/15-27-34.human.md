This is a bugfix patch in a series enhancing `git fsck`'s packed-refs validation. It addresses a potential premature termination issue when checking worktree references.

The patch introduces a new public API `get_worktrees_without_reading_head()` that avoids parsing HEAD information when verifying refs. This prevents the packed-refs validation from dying early if HEAD points to a malformed packed ref, allowing `git refs verify` and `git fsck` to complete their full validation checks.

The change builds on existing functionality from commit 465a22b338 which first introduced HEAD-skipping capability for worktree repairs. The implementation is straightforward - it exposes the internal skip-HEAD flag through a new public function and updates `builtin/refs.c` to use it. The patch has been mentored by two experienced contributors and fits into the larger effort to make packed-refs validation more robust and complete.
