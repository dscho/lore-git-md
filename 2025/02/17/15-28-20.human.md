This is the final patch in a bugfix series enhancing `git fsck`'s validation of packed-refs files. It integrates the new ref consistency checks (developed in previous patches) into `git fsck` by running them via a new `git refs verify` child process.

The patch adds a `--[no-]references` option to control whether ref database checking is performed (enabled by default). The implementation spawns a child process to run the verification, with progress reporting and support for existing `--verbose`/`--strict` flags. Test cases demonstrate the new functionality by verifying that:
- Ref checking works normally with `--references` (default)
- Warnings appear for malformed refs
- Checking can be disabled with `--no-references`

This completes the series by exposing the new validation logic to end users through `git fsck`. The implementation appears thorough, with good test coverage of the new option's behavior. The child process approach keeps the fsck command modular while ensuring the new checks don't break existing functionality.
