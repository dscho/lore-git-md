This is part 4/8 of a bugfix series enhancing `git fsck`'s packed-refs validation. The patch focuses specifically on header consistency checks for packed-refs files.

The key changes in this patch:

1. **Header validation**: Implements strict checking that packed-refs headers must start with "# pack-refs with: " (note the trailing space, fixing an inconsistency from the runtime code). Invalid headers trigger a new `FSCK_MSG_BAD_PACKED_REF_HEADER` error.

2. **New error cases**: Introduces two new fsck error types:
   - `badPackedRefHeader` for malformed headers
   - `packedRefEntryNotTerminated` for lines missing newline terminators

3. **Graceful handling**: Maintains backward compatibility by:
   - Not erroring on missing headers (for older Git versions)
   - Not complaining about unknown traits in valid headers

4. **Implementation details**:
   - Uses `open_nofollow` for TOCTOU safety
   - Adds comprehensive test cases covering valid/invalid headers
   - Follows the same parsing approach as runtime code

The patch aligns with the series' goal of bringing packed-refs validation up to fsck standards while maintaining compatibility. It builds on previous work in the series by adding another layer of validation while being careful not to break existing legitimate uses. The test coverage is thorough, exercising all the new validation cases.
