This is a performance optimization patch completing the ref iterator reseeking implementation for the packed-refs backend, part of a larger series addressing refname availability checks.

The patch implements the `.seek` operation for packed-ref iterators, allowing them to efficiently restart iteration from a new prefix without recreating the iterator. The key changes include:
1. Adding a `prefix` member to track the current search scope
2. Implementing `packed_ref_iterator_seek()` to reposition the iterator using `find_reference_location()`
3. Moving prefix filtering logic into `advance()` to maintain correct iteration bounds
4. Removing the empty iterator optimization since reseeking makes it redundant

The implementation carefully handles edge cases like empty prefixes and maintains the existing prefix matching behavior while enabling the new reseek capability. This completes the iterator reseeking support across all major ref iterator types in the series, with packed-refs being the last remaining backend to receive this optimization.

The changes align with the series' goal of improving ref iteration efficiency, particularly for nested availability checks. By removing the prefix iterator wrapper and empty iterator optimization, the implementation simplifies the control flow while maintaining correctness. The patch builds on prior infrastructure changes in the series (new iterator lifecycle management and seek APIs) to deliver consistent behavior across all ref backends.
