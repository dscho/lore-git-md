This is part of the performance optimization series for refs iterators, specifically implementing seek functionality for ref-cache iterators to complete the iterator reseeking capability across all major iterator types.

The patch extracts most of the seeking logic from `cache_ref_iterator_begin()` into a new `cache_ref_iterator_seek()` function, making the iterator reseekable. This required removing the optimization that returned an empty iterator when no references existed, since that would prevent reseeking to different prefixes. The change maintains proper iterator state tracking with new `cache` and `prime_dir` fields while keeping the same prefix handling behavior.

Key technical details:
- New `cache_ref_iterator_seek()` vtable function implemented
- Iterator state now tracks `cache` and `prime_dir` for reseeking
- Removed empty iterator optimization to enable reseeking
- Early bailout in `advance()` when no levels remain
- Proper prefix state management preserved during seeks
- Files touched: `refs/ref-cache.c`
- Related to: iterator lifecycle changes from earlier in series
- Completes seek implementation for all major iterator types (following debug, empty, prefix, merged, and reftable implementations)

This completes the ref-cache iterator portion of the broader iterator reseeking capability, though as noted in the thread context, reflog iterators still cannot be seeked (would BUG). The change maintains the series' pattern of infrastructure improvements enabling performance optimizations while preserving semantics.
