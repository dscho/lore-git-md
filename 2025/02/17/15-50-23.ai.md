This patch implements seeking capability for merged ref iterators, part of the ongoing performance optimization series for the refs subsystem. It's a technical refactoring that builds on the iterator lifecycle changes introduced earlier in the series.

The change modifies the merged iterator implementation to support the new `.seek` vtable function while maintaining proper iterator lifecycle management. The key changes are:
1. Splitting iterator ownership tracking from active iteration state by introducing `iter0_owned`/`iter1_owned` alongside `iter0`/`iter1`
2. Implementing the new `merge_ref_iterator_seek()` function that resets both underlying iterators and propagates the seek operation to them
3. Updating the release logic to only free the owned iterators
4. Removing premature freeing of exhausted iterators during advancement

The implementation maintains the series' focus on enabling efficient nested refname availability checks while preserving correct iterator semantics. This change is particularly relevant for the reftable backend optimizations where efficient seeking is crucial for performance. The patch follows the established pattern of the series by extending infrastructure capabilities that will be leveraged by higher-level optimizations.
