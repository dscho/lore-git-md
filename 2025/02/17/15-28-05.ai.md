This is part 6/8 of a bugfix series enhancing `git fsck`'s packed-refs validation. The patch adds detailed consistency checking for individual entries in the packed-refs file, building on the earlier header validation work.

The implementation introduces two new validation functions:
1. `packed_fsck_ref_main_line()` checks the main ref line format (oid + refname), including:
   - Valid oid parsing
   - Proper spacing between oid and refname
   - NUL character detection in refnames (using the existing `refname_contains_nul()` helper)
   - Refname format validation

2. `packed_fsck_ref_peeled_line()` validates peeled ref entries (lines starting with '^'), checking:
   - Valid peeled oid parsing
   - Absence of trailing garbage after the oid

Both validations report errors via the new `FSCK_MSG_BAD_PACKED_REF_ENTRY` message ID. The test suite is expanded with a comprehensive test case that exercises all the new validation scenarios, including malformed oids, missing spaces, invalid refnames, and corrupted peeled entries.

The patch integrates with the existing packed-refs validation framework while maintaining the line-by-line processing approach. It follows the series' pattern of thorough validation with detailed error reporting, though some reviewers might want to see the error messages made more actionable for end users. The test coverage appears complete, exercising all the error paths described in the commit message.
