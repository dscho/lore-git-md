Performance optimization in the refs subsystem, part of a series addressing refname availability checks. This patch specifically targets `git update-ref` by skipping redundant ambiguity checks when parsing object IDs.

The change modifies `update-ref` to use the new `repo_get_oid_with_flags()` API with `GET_OID_HASH_SKIP_AMBIGUITY_CHECK`, avoiding expensive DWIM reference resolution for unambiguous object IDs. The author argues this makes sense for `update-ref` since it's a plumbing command primarily dealing with explicit object IDs, and the ambiguity warnings are unlikely to be seen in typical usage.

Benchmarks show significant speedups: 19% faster for the files backend and 2.3x faster for reftable when creating many references. The larger relative improvement for reftable comes from its faster baseline performance. The patch is cleanly implemented with straightforward calls to the new API at all object ID parsing sites in `update-ref.c`.

This builds on Patrick Steinhardt's earlier refactoring that introduced the flag-based object lookup API, now being put to use in Karthik Nayak's performance optimization series. The change is well-motivated and appears to deliver the promised benefits without introducing complexity.
