This is a refactoring patch targeting `builtin/show-branch.c` that converts direct flag access on commit objects to use the commit-slab mechanism instead. The patch introduces `get_commit_flags()` and `set_commit_flags()` helper functions and removes the direct `commit->object.flags` accesses throughout the file. It also properly includes `revision.h` to use the canonical `UNINTERESTING` flag definition rather than a local redefinition.

The change appears to be motivated by a prior review comment from Junio Hamano suggesting the use of commit-slabs to store runtime-computed bitmasks, which would help lift the `MAX_REVS` limitation. The author acknowledges some uncertainty about whether the slab should store just an integer or a more complex struct, and seeks guidance on this point. The patch shows good attention to detail - it maintains all existing flag manipulation logic while just changing the storage mechanism, includes proper initialization/cleanup of the slab, and has been tested via both the test suite and GitHub CI.

Key technical details for future reference: The patch defines a new `commit_flags` slab storing integers, replaces all direct flag checks/sets with the new helper functions, and preserves all existing flag manipulation logic including the `UNINTERESTING`, `REV_SHIFT` and `MAX_REVS` constants. The changes are confined to `builtin/show-branch.c` with no interface changes.
