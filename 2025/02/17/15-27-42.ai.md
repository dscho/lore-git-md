Bugfix patch adding filetype validation for packed-refs, part of the comprehensive packed-refs validation series (v5 3/8). This specific patch ensures the packed-refs file is a regular file, not a symlink or other special file type, using `lstat()` for verification.

The implementation checks the file mode and reports errors via the existing `FSCK_MSG_BAD_REF_FILETYPE` message if packed-refs isn't a regular file, while gracefully handling the case where the file doesn't exist. The change comes with a new test case that verifies the behavior by replacing packed-refs with a symlink. 

This patch represents a security hardening measure, building on earlier feedback that led to using `lstat` instead of the initially proposed `open_nofollow` approach. The validation integrates with the existing fsck infrastructure and maintains backward compatibility with repositories lacking a packed-refs file. The test suite modernization effort continues here with proper subshell isolation in the new test case.

Key technical details for future reference:
- Uses `lstat()` to check file type (not following symlinks)
- Reports via `fsck_report_ref()` with `FSCK_MSG_BAD_REF_FILETYPE`
- Handles ENOENT gracefully (missing file is not an error)
- New test case in t0602-reffiles-fsck.sh verifies symlink detection
- Maintains worktree safety through existing mechanisms
- Part of broader packed-refs validation covering header format, content, and sortedness

The patch has been mentored by both Patrick Steinhardt and Karthik Nayak, with the implementation now matching the preferred approach after review feedback about symlink handling. It fits into the series' goal of comprehensive packed-refs validation while maintaining security and backward compatibility.
