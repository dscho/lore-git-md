Bug report and fix implementation for Git's pickaxe (-S/-G) functionality crashing with empty string arguments. Jared Van Bortel originally reported that `git log -S ""` or `git log -G ""` triggers an assertion failure in diffcore-pickaxe.c (line 241) with a BUG message. The issue occurs when the pickaxe code asserts there must be a search string without proper input validation, affecting Git 2.48.1 and likely other versions.

Brian m. carlson confirmed the bug and proposed rejecting empty arguments entirely rather than treating them as no-ops, arguing empty search strings have no practical use. The discussion reached consensus on this approach. Carlson has now submitted the implementation patch that:

1. Adds explicit validation in diff.c to reject empty strings for -G/-S options
2. Returns appropriate error messages following Git's standard style
3. Uses exit code 129 (usage error) for consistency
4. Includes tests in t4209-log-pickaxe.sh verifying the new behavior

Elijah Newren has reviewed the patch, confirming it is "simple" and "looks good", effectively rubber-stamping the implementation. The review raises no new concerns, indicating the patch is ready to proceed. The changes are minimal and focused - two conditionals in option parsing plus test cases - properly addressing the crash while maintaining all existing functionality for valid inputs. The tests demonstrate correct error output and exit codes for both `-G ""` and `-S ""` cases, following existing patterns in the test file. With this review, the fix appears complete and ready for merging, implementing the solution agreed upon in the thread without broader impacts on pickaxe behavior.
