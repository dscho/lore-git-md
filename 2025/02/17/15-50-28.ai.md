Performance optimization completing the ref iterator reseeking capability series.

This final patch in the series implements iterator reuse during refname availability checks, building on the reseeking infrastructure added in previous patches. The change modifies `refs_verify_refnames_available()` to maintain and reseek a single iterator rather than recreating it for each nested reference check. This optimization is particularly effective for the reftable backend, which can now maintain its batching state across checks.

The patch shows a 1.25x speedup in benchmarks creating 10,000 refs against a 100,000-ref reftable repository. The implementation carefully handles both the initial iterator creation and subsequent reseeks while maintaining all existing error handling. The diff is minimal (7 insertions, 5 deletions) but leverages the comprehensive iterator reseeking support now present across all ref backends.

Key technical points:
- Reuses iterator via new `ref_iterator_seek()` when checking nested refnames
- Maintains backward compatibility with initial iterator allocation
- Preserves all existing error handling and cleanup paths
- Completes the performance optimization arc for refname availability checks
- Builds on the now-universal iterator reseeking capability across all backends

This change demonstrates how the iterator lifecycle and reseeking infrastructure enables targeted optimizations while maintaining backend neutrality. The reftable backend benefits most due to its batching capabilities, but the change improves the abstraction for all backends.
