Bugfix patch (7/8 in series) adding sortedness verification for packed-refs files that declare themselves sorted.

This patch completes the packed-refs validation suite by adding a check for refname sorting when the file's header includes the "sorted" trait. The implementation avoids memory-intensive approaches by re-parsing the file to compare adjacent entries, reusing the existing comparison logic through a new `cmp_packed_refname()` helper extracted from `cmp_packed_ref_records()`. The check reports unsorted refs via a new `FSCK_MSG_PACKED_REF_UNSORTED` error.

Key technical details:
- Header parsing now detects the "sorted" trait via `packed_fsck_ref_header()`
- New `packed_fsck_ref_sorted()` performs the verification pass when needed
- Tests verify both valid and invalid sorted cases, plus proper no-op when "sorted" is absent
- Maintains the series' security focus with careful memory handling and error reporting

The patch fits cleanly into the larger validation framework, using the established reporting mechanism and following the same pattern of comprehensive test coverage seen in earlier series patches. It addresses a clear consistency guarantee implied by the packed-refs format while avoiding performance pitfalls through its streaming verification approach.
