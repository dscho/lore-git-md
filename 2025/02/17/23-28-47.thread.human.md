This thread documents a collaborative effort to properly document Git's submodule merge behavior, initiated by Lucas Seiki Oshiro and refined through discussion with merge expert Elijah Newren. The core issue involves two non-obvious behaviors during submodule operations: automatic fast-forwarding when one commit is a descendant of another, and conflict resolution when merges contain conflicting submodule commits.

Elijah has guided the documentation's technical accuracy and placement, suggesting moving it from git-merge.adoc to merge-strategies.txt since the behavior affects all merge-based commands (rebase, cherry-pick) via the merge_submodule() function (implemented in commit 68d03e4a6e). The latest exchange shows Elijah proposing more general wording that avoids merge-specific terms like MERGE_HEAD while precisely describing the fast-forward condition.

Open questions remain about documentation architecture - particularly how to handle strategy-specific details (as both ort and recursive strategies are affected) and whether to document all merge special cases or focus specifically on submodules. The discussion highlights the challenge of documenting cross-cutting behaviors in Git's technical docs while maintaining accuracy across commands and strategies. Both contributors are thoughtfully considering how to make this subtle but important behavior more discoverable for users and future developers.
