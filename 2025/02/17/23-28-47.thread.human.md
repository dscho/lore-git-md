This thread discusses documenting Git's special handling of submodule conflicts during merges. Lucas Seiki Oshiro started the discussion with an RFC patch proposing to add documentation about two non-obvious behaviors: (1) Git will attempt a fast-forward when one submodule commit is a descendant of another, and (2) when a single merge commit exists containing both conflicting submodule commits, Git suggests it as a resolution while keeping the conflict marked. The patch was motivated by real-world debugging where GitHub showed submodule conflicts that didn't appear locally.

Elijah Newren, the merge machinery expert, agrees the behavior should be documented but questions placing it in `git-merge.adoc`. He points out this behavior applies to all commands using merge machinery (like rebase and cherry-pick), not just `git merge`, and suggests `merge-strategies.txt` might be more appropriate. Newren also provides specific wording improvements and notes the merge_submodule() function has lived in merge code since 2018. The discussion remains open on the best home for this documentation and how to phrase it generically enough for all merge machinery contexts.
