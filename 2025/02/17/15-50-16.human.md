This is a foundational refactoring patch in a performance optimization series for Git's refs subsystem. It introduces a new flag `GET_OID_HASH_SKIP_AMBIGUITY_CHECK` that allows callers to bypass the object ID ambiguity check in the `get_oid()` family of functions. The check, which warns when a reference exists with the same name as an object hash, is sometimes unnecessary overhead.

Patrick Steinhardt's change modifies both the flag definitions in `hash.h` and the ambiguity check logic in `object-name.c`. The patch is part of a larger effort (with Karthik Nayak) to optimize refname availability checks, particularly for the reftable backend. While this commit itself doesn't show performance numbers, it enables follow-up optimizations that will skip these checks in performance-critical paths like ref updates.

The change is cleanly implemented and clearly motivated as preparation for later optimizations. As part of a well-structured series with clear separation between refactoring and optimization commits, this appears to be a solid incremental improvement to Git's object lookup infrastructure.
