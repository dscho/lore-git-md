This is the first patch in a bugfix series enhancing `git fsck`'s packed-refs validation. The patch focuses on improving test reliability by using subshells to ensure working directory changes don't leak between tests.

The change wraps all test cases in `t/t0602-reffiles-fsck.sh` in subshells to properly isolate working directory changes. Previously, tests would `cd repo` but not always return to the original directory, which could cause problems if a test failed before the `cd ..`. The new approach ensures the working directory is always restored, regardless of test success or failure.

The patch is part of a larger series (v5, 8/8) that adds comprehensive validation for packed-refs files, including header format verification, content validation, and sortedness checks. This particular change is a straightforward test improvement that makes the test suite more robust, though it doesn't affect the actual functionality being tested. The diff is large (967 lines) but consists mostly of mechanical wrapping of existing test code in subshells.
