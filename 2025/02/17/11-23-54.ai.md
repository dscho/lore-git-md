Askar Safin points out a discrepancy between the manpage's description and actual behavior - the documentation claims users will be interactively prompted for missing email headers like the subject line, but in practice the command fails with an error when these are absent.

The report provides clear reproduction steps using a simple test file, showing the command fails with "No subject line" rather than prompting as documented. The environment details (Git 2.47.2 on Debian sid via Docker) and relevant configuration are included, though they don't appear to affect the core issue.

This appears to be a straightforward case where either:
1. The documentation needs updating to reflect the actual non-interactive behavior, or
2. The implementation should be modified to match the documented interactive prompting behavior

The reporter doesn't take a position on which solution is preferable, just noting the inconsistency needs resolution. The bug affects basic `git send-email` usage when composing new emails without all required headers specified.
