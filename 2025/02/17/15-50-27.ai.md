Performance optimization series for refs subsystem, completing iterator reseeking support across all backends.

This patch implements seek capability for the files backend's ref iterator, marking the final piece in the series' goal of enabling reseeking across all ref storage backends. The implementation is straightforward since it delegates to the underlying ref-cache iterator which already supports seeking. Notably, the patch maintains consistency with other backends by explicitly preventing seek operations on reflog iterators via a BUG() call, matching the behavior in the reftable backend.

The changes add two key functions: `files_ref_iterator_seek()` for regular ref iteration and `files_reflog_iterator_seek()` that triggers an error for reflogs. Both are wired into their respective vtable structures. This completes the backend coverage for the series' iterator reseeking functionality, which previously added support for packed-refs, reftable, and other iterator types.

The patch fits into the larger performance optimization effort by enabling more efficient nested refname availability checks through reseekable iterators. With this change, all major ref storage backends now support the same seek capability, allowing the batch verification infrastructure (introduced earlier in the series) to work uniformly across implementations. The explicit BUG() for reflog iterators documents a current limitation that may need addressing in future work.
