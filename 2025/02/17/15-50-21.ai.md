Refactoring of the ref iterator lifecycle management, part of the performance optimization series for the refs subsystem.

This patch by Patrick Steinhardt separates iterator lifecycle management from iteration itself, addressing two key issues with the current design. First, it removes the awkwardness around `ref_iterator_abort()` calls by eliminating the need to track whether an iterator is still valid before freeing it. Second, it lays groundwork for potential iterator reuse by detaching deallocation from iteration completion.

The changes introduce a new `ref_iterator_free()` function that callers must explicitly use to clean up iterators, replacing the implicit cleanup that previously happened at iteration end. The patch also removes the return value from `ref_iterator_abort()` since it wasn't meaningfully used, and consolidates cleanup in the new free function rather than having backends handle it.

Key technical changes:
- New `ref_iterator_free()` API replaces `ref_iterator_abort()`
- Iterator vtable gains `release` method instead of `abort`
- All iterator implementations updated to match new lifecycle
- Parallel changes made to `dir_iterator` for consistency
- Call sites updated to explicitly free iterators when done
- Memory management simplified by centralizing cleanup

The changes touch all ref backend implementations (files, packed, reftable) plus supporting infrastructure. While primarily a refactoring, this enables future optimizations like iterator reuse while making the code more maintainable. The patch fits into the larger series by providing cleaner infrastructure for the batch verification optimizations being introduced.
