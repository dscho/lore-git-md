Documentation patch clarifying submodule merge behavior. This RFC proposes adding details to `git-merge.adoc` about how Git handles submodule conflicts differently from regular file conflicts. The author explains two special cases observed in the merge-ort and merge-recursive strategies: (1) when one submodule commit is a descendant of another, Git attempts a fast-forward, and (2) when there's a single merge commit containing both conflicting submodule commits, Git suggests it as a resolution while keeping the conflict marked. 

The patch stems from the author's personal experience debugging why GitHub showed submodule merge conflicts that didn't appear locally. The commit message references a blog post where they originally documented this behavior after examining the merge-ort source code. The change adds a concise technical paragraph to the merge documentation, though the author acknowledges uncertainty about whether this belongs in the submodule or merge docs.

The implementation is straightforward - a 7-line addition to `git-merge.adoc` that precisely describes the observed behavior. The patch appears well-motivated by real user confusion and fills a documentation gap about non-obvious merge strategy behavior. The RFC nature suggests the author is open to feedback on placement and wording.
