Refactoring patch introducing iterator reseeking capability as part of the refs subsystem performance optimization series.

This patch adds infrastructure to allow ref iterators to be reseeked to new prefixes without requiring full iterator recreation, enabling potential performance optimizations by reusing internal state. The key changes are:

1. Adds a new `.seek` vtable function to `struct ref_iterator_vtable` that backends must implement to support reseeking
2. Implements basic seek functionality for debug, empty, and prefix iterators
3. Documents the expected behavior where reseeking should match creating a new iterator with the same prefix
4. The implementation maintains existing iterator semantics while opening the door for backend-specific optimizations (particularly for reftable which already has internal reuse capabilities)

The patch is part of a larger series addressing refname availability checks, with this change specifically enabling infrastructure for future optimizations. It builds on Patrick Steinhardt's earlier iterator lifecycle refactoring work in the series. The implementation is clean and focused, with clear documentation of the new API contract. Subsequent patches will implement the seek functionality for remaining iterator types.
