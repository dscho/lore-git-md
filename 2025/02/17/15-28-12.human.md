Bugfix patch adding sortedness verification for packed-refs files. This is part 7/8 of a series enhancing `git fsck`'s packed-refs validation, with Patrick Steinhardt and Karthik Nayak mentoring.

The patch introduces a check that verifies whether packed-refs entries are properly sorted when the file header includes the "sorted" trait. Rather than storing all refnames for comparison (which would be memory-intensive), it implements a streaming approach that re-parses the file and compares adjacent entries using a refactored comparison function. Unsorted entries trigger a new `FSCK_MSG_PACKED_REF_UNSORTED` error.

Key implementation details:
- Extracts refname comparison logic into new `cmp_packed_refname` helper
- Modifies header parsing to detect "sorted" trait
- Adds new `packed_fsck_ref_sorted` function that performs the verification
- Includes comprehensive tests covering both sorted and unsorted cases

The change maintains the series' focus on thorough validation while being memory-efficient. Test cases demonstrate correct handling of both sorted and unsorted files, including proper behavior when the "sorted" trait is absent. This completes another piece of the comprehensive packed-refs validation being built in the series.
