Performance optimization series for refs subsystem (part 5/14). This patch transitions the reftable backend to use the new batch refname verification API (`refs_verify_refnames_available()`) introduced earlier in the series. 

The change replaces individual refname availability checks during transaction preparation with a batched approach that collects all refnames first and verifies them in one go. While the immediate performance impact is minimal (the patch still effectively performs the same checks), this sets up the infrastructure for more significant optimizations in subsequent patches.

The implementation maintains all existing behavior and error handling, just reorganizing when and how the checks occur. The patch is part of a larger effort to optimize ref operations, particularly benefiting the reftable backend where these checks have been identified as a bottleneck. 

This appears to be a straightforward mechanical conversion that cleanly integrates with the new batch verification API while preserving the reftable backend's existing functionality. The change is well-contained, touching only the reftable backend implementation.
