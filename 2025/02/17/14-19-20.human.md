Feature enhancement to `help.autocorrect` configuration. This is version 2 of Chris Howlett's patch adding a "prompt-yes" mode that makes the interactive confirmation default to "Yes" when Git suggests command corrections. The current "prompt" mode defaults to "No", which the author argues is less optimal since Git's suggestions are usually correct.

The implementation adds a new `AUTOCORRECT_PROMPT_YES` constant and handles it similarly to the existing prompt mode, with the key difference being the default answer. Like other interactive modes, it falls back to immediate execution when not in a terminal. The patch updates both the documentation and the implementation in help.c.

This version rebases against recent changes to the help.autocorrect parsing code. The author notes this is their first Git contribution and acknowledges the lack of tests due to the difficulty of testing interactive prompts. The patch is technically sound but awaits resolution of a parallel change to help.autocorrect's config syntax by Scott Chacon before it can land.
