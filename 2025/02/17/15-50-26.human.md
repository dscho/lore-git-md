Performance optimization for refs subsystem, completing the iterator reseeking implementation for packed-refs backend.

This patch adds seek capability to packed-ref iterators, the final piece in a series that has been systematically implementing reseeking across all ref iterator types. The change allows more efficient nested refname availability checks by letting iterators reposition without restarting from scratch. The implementation required open-coding the prefix matching logic in `advance()` rather than using the prefix iterator helper, since the latter would prevent proper reseeking when switching between empty and non-empty prefixes.

The change follows the pattern seen in earlier patches in this series, with similar adjustments to iterator state management (adding a `prefix` field) and vtable updates. It completes the ref iterator modernization that began with Patrick Steinhardt's foundational iterator lifecycle refactoring and Karthik Nayak's batch verification infrastructure. While the packed-refs backend sees less dramatic performance gains than reftable from these changes, the consistent iterator behavior improves code maintainability and provides a uniform foundation for future optimizations.

This appears to be a well-executed technical change that fits cleanly into the larger performance optimization effort. The commit message could better explain why the prefix iterator helper couldn't be reused, but the code itself is clear and maintains the careful attention to edge cases seen throughout this series.
