This is a bugfix patch in the `git fsck` packed-refs validation series, specifically addressing worktree safety during verification. It introduces a new public API to avoid premature termination when checking refs.

The patch adds `get_worktrees_without_reading_head()` to the worktree API, wrapping the existing `get_worktrees_internal(1)` functionality. This prevents `git refs verify` and `git fsck` from dying when encountering malformed packed-refs files during HEAD verification. The change ensures complete validation continues even if HEAD references would trigger packed-backend's strict snapshot verification.

Key technical points:
- New function exposed in worktree.h with documentation about its HEAD-skipping behavior
- Replaces `get_worktrees()` call in builtin/refs.c with the new variant
- Builds on commit 465a22b338's internal skip-HEAD capability
- Maintains all existing functionality while adding safety for verification scenarios
- The implementation is minimal (5 lines added) and well-documented
- Mentored by Patrick Steinhardt and Karthik Nayak
- Part of broader effort to make packed-refs validation robust and complete

This change enables the subsequent packed-refs validation patches to operate safely across all worktrees without being short-circuited by HEAD parsing issues. The thread context shows this is part of a comprehensive validation suite that has undergone significant review, with maintainer-confirmed design decisions about header handling and other aspects.
