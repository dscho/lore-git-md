This is a bugfix patch for `git merge-tree --stdin` that addresses a deadlock issue, building on previous work in the thread. The patch adds a `maybe_flush_or_die(stdout, "stdout")` call in the stdin processing loop to prevent deadlocks when another process tries to read merge-tree's output before it has finished reading its own input. Phillip Wood provides benchmark data showing the flush operation has negligible performance impact (less than 0.5% difference in runtime).

The change is minimal (just 2 lines added) and well-justified, with Elijah Newren giving his approval. This was the core issue that kicked off the thread, and the solution aligns with the thread's broader goals of improving reliability and maintainability of the stdin mode. The patch maintains the thread's focus on plumbing behavior while fixing a concrete usability problem where scripts could deadlock when processing output incrementally.
