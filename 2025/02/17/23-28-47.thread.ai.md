RFC documentation patch proposing to clarify submodule merge behavior in `git-merge.adoc`. The author identifies two special cases in how merge strategies (merge-ort and merge-recursive) handle submodule conflicts differently from regular files: (1) when one submodule commit is a descendant of another, Git attempts a fast-forward merge, and (2) when a single merge commit exists containing both conflicting submodule commits, Git suggests it as a resolution while keeping the conflict marked. The change adds a 7-line technical paragraph documenting this behavior.

The patch stems from the author's debugging experience with GitHub showing submodule conflicts that didn't appear locally, later documented in a blog post after examining merge-ort source code. The author is uncertain whether this documentation belongs in the merge or submodule documentation, marking it as RFC for feedback on placement and wording. The change addresses a real user confusion point about non-obvious merge strategy behavior with submodules.
