This is part of the performance optimization series for the refs subsystem, focusing on iterator infrastructure. 

Patrick Steinhardt introduces a new capability to reseek ref iterators, which enables reuse of iterator state rather than creating new iterators from scratch. The patch adds a `.seek` method to the ref iterator vtable that allows callers to reset an existing iterator to a new prefix (or the same one), with implementations provided for debug and prefix iterators. 

This change is particularly valuable for the reftable backend, which already has internal reuse capabilities that couldn't previously be exposed. The patch lays groundwork for future optimizations by making iterator reuse possible across all backends while maintaining the same semantics as creating a fresh iterator. 

The implementation is clean and focused, with straightforward additions to the iterator vtable and implementations for basic iterator types. As part of a larger performance series that's already showing significant speedups (particularly for reftable), this infrastructure change enables further optimizations while keeping the door open for backend-specific tuning.
