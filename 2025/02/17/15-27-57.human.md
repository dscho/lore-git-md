Bugfix in the packed-refs validation series, addressing embedded NUL characters in refnames. This is patch 5/8 in v5 of the series.

The patch fixes a subtle corruption case where a packed-refs file could contain NUL bytes embedded in refnames. Currently, the code calculates refname length by pointer subtraction and checks the format, but would miss NULs after a valid prefix. The new `refname_contains_nul()` helper detects these cases and causes the program to die with an error message.

The issue was reported by R. Diez, who found that such corruption could slip through validation. The fix adds a straightforward check using `memchr()` to scan for embedded NULs before proceeding with format validation. The commit message clearly explains the problem and solution, and the patch includes a good explanatory comment.

This continues the series' thorough approach to packed-refs validation, adding another safety check while maintaining the existing behavior for valid refnames. The change is focused and well-contained, touching only the packed-backend code.
