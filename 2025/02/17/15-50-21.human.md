This is a refactoring patch in the performance optimization series for the refs subsystem. It separates iterator lifecycle management from iteration behavior, which enables future optimizations like iterator reuse.

The patch changes how ref iterators are cleaned up by introducing an explicit `ref_iterator_free()` function rather than having cleanup happen automatically when iteration completes. This makes the API more conventional (matching patterns seen elsewhere in Git) and removes awkward cases where callers had to carefully time `ref_iterator_abort()` calls. The change also paves the way for reseekable iterators by keeping the iterator struct alive after iteration completes.

The implementation touches all ref iterator backends (files, packed, reftable) and their callers, updating them to use the new lifecycle model. The diff shows significant simplification in iterator implementations since they no longer need to handle implicit cleanup. The patch maintains all existing behavior while making the code more maintainable and setting up future optimizations.

This is part 7/14 in a series that has already shown substantial performance improvements (up to 7.5x for reftable). While this particular patch doesn't directly impact performance metrics, it enables follow-on work that will further optimize ref lookups. The changes are mechanical but thorough, with test updates showing the new API in action.
