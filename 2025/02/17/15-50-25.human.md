This is a refactoring patch in the performance optimization series for the refs subsystem, specifically implementing seek functionality for ref-cache iterators.

Patrick Steinhardt continues the series' work to enable reseekable iterators by adapting the ref-cache implementation. The patch splits the seeking logic out of `cache_ref_iterator_begin()` into a new `cache_ref_iterator_seek()` function, allowing the iterator to be repositioned after creation. This matches the pattern already established for other iterator types in the series.

A notable tradeoff is that the patch removes the optimization of returning an empty iterator when no references exist, since that would prevent reseeking to a different prefix. The commit message explains this shouldn't significantly impact performance since the iterator will still bail out early during advancement when no more references remain to be searched.

The changes are focused on `refs/ref-cache.c`, restructuring the iterator implementation while maintaining the same functionality. This is part of the broader effort to enable more efficient refname availability checks across both files and reftable backends, with this particular piece completing the foundation for reseekable iterators in the ref-cache implementation.
