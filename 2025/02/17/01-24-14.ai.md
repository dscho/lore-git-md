Bugfix for a crash in pickaxe (-S/-G) functionality when given an empty string argument.

Jared Van Bortel reports that passing an empty string to `git log -S ""` or `git log -G ""` triggers an assertion failure in diffcore-pickaxe.c, resulting in a crash with a BUG message. The backtrace shows the crash originates from line 241 of diffcore-pickaxe.c where the code asserts there should be a needle (search string) present when using -G or -S options.

This appears to be an unhandled edge case where the pickaxe functionality doesn't properly validate its input before processing. The crash occurs during the diffcore processing phase when executing log commands, with the error bubbling up through the log tree and command handling layers.

The report includes detailed backtrace information showing the full call stack from the abort() call through to main(), which should help pinpoint the exact location needing fixing. The issue is reproducible in Git 2.48.1 and likely affects other versions as well.

This seems like a straightforward validation issue where the pickaxe code should either gracefully handle empty strings (perhaps by treating them as no-op) or provide a proper error message rather than crashing. The bug is clearly triggered by user input but currently results in an ungraceful termination.
