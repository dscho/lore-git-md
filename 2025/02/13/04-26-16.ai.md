This is a documentation fix clarifying the behavior of `-S` pickaxe search in Git's diff machinery. The patch corrects the help text in diff.h to more accurately describe how `-S<string>` actually works - it finds filepairs where the number of occurrences of the string differs, rather than the previous wording which suggested it only found cases where the string appeared on one side.

Junio C Hamano notes that while the original wording better reflected the initial intent of the feature (to detect when a unique block of text appears/disappears), the new wording more precisely describes the current implementation's behavior when given non-unique strings. The change is technically correct, though it subtly shifts emphasis from the intended use case to the mechanical behavior.

The patch is part of a larger series (v5 03/10) introducing long option names for pickaxe functionality, but this particular change stands alone as a documentation clarification. The change is minimal (one line in diff.h) but improves accuracy, and Junio explicitly approves it as "a good change" while noting it probably should have been done separately from the main long-options feature work.

Key technical details:
- Updates the short help text for `-S` in diff.h
- Changes description from "only one side contains" to "differ in number of occurrences"
- Maintainer confirms this better matches actual behavior though original wording better reflected design intent
- References original 2005 discussion about pickaxe's purpose in rename detection

The patch appears ready to merge as a straightforward documentation improvement, though it raises an interesting historical note about the gap between the feature's original design intent and its current implementation behavior.
