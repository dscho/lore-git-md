This is a performance optimization patch series for merge-recursive, following up on earlier review discussion. Meet Soni presents two commits that continue the work of reducing quadratic complexity in string list operations, now addressing both `process_renames()` and `get_unmerged()` functions.

The first commit (v2 of a previously submitted patch) optimizes rename processing by replacing O(n²) sorted insertions with O(n log n) append-and-sort, incorporating Elijah Newren's feedback about preserving the FIXME comment's documentation value while making the optimization clearer. The second new commit applies similar optimization logic to the `get_unmerged()` function, suggesting this pattern could be used more widely in the codebase (hence the RFC tag).

The changes are minimal (25 lines total) and focused purely on performance without altering behavior. The author appears responsive to review feedback, having updated both comments and commit messages from the previous version. While merge-recursive is slated for eventual deprecation, these cleanups seem worthwhile as they address long-standing performance bottlenecks in a maintainable way.
