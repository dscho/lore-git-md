Performance optimization for merge-recursive's rename processing. Elijah Newren approves Meet Soni's patch that converts the O(n²) string list construction in `process_renames()` to a more efficient O(n log n) approach by building the list unsorted and sorting afterward. The patch is now considered ready for merging after addressing earlier review comments about documentation and implementation details.

The change replaces direct `string_list_insert()` calls with `string_list_append()` followed by explicit sorting, taking advantage of diffcore_rename's guarantee of no duplicates. This matches the optimization pattern previously discussed in the thread and maintains the same behavior while improving performance. The patch modifies just 15 lines in merge-recursive.c with no functional changes.

This approval marks the first patch in the series as complete, while the second RFC patch applying the same optimization to `get_unmerged()` remains under discussion. The thread has focused on establishing this as a safe pattern for similar cases in merge-recursive, with the implementation now meeting all reviewer expectations.
