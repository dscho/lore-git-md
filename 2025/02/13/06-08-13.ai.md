This is a review comment in the platform compatibility series addressing `-Wsign-comparison` warnings in `apply.c`. Patrick Steinhardt examines patch 2/6 from Zejun Zhao which converts several variables from `int` to `size_t`/`unsigned` to match their usage patterns.

Steinhardt analyzes each change, noting where the new types properly match:
- `len` for `memcpy()` operations
- `ctx` for array indexing against `preimage->line_nr`
- `preimage_limit` storing `struct image::line_nr`
- position variables in `find_pos()` and `update_image()` that handle positive integers

He flags two potentially questionable conversions:
1. The `backwards_lno`/`forwards_lno`/`current_lno` variables in `find_pos()` that store an `int` parameter, though the caller only passes positive values
2. The `lines` variable in `patch_stats()` that sums `int` fields, suggesting the field types might need updating too

The review maintains the series' focus on type safety while identifying areas needing additional scrutiny. Steinhardt's comments demonstrate careful consideration of both the immediate changes and their broader implications in the codebase.
