This is a build system fix addressing a Makefile syntax issue. The patch corrects an accidental use of tab characters in conditional statements within the Makefile, which causes build failures with newer versions of GNU Make (specifically 4.4.90). The issue was introduced in commit b9d6f64393 when adding zlib-ng support, and this change aligns with the earlier standardization effort in 728b9ac0c3 that replaced tabs with spaces in conditionals.

The change is mechanical, replacing tab indentation with 8 spaces in the ZLIB_NG and ZLIB_PATH conditional blocks. This affects the build configuration for zlib backends, though the actual functionality remains unchanged. The fix is straightforward and well-motivated by compatibility requirements with modern Make versions.

Key technical details for future reference:
- Touches the Makefile's zlib configuration section
- Specifically modifies the ZLIB_NG and ZLIB_PATH conditional blocks
- Maintains identical logic while changing only whitespace
- References prior related commits 728b9ac0c3 and b9d6f64393
- Fixes builds on systems with GNU Make 4.4.90+
