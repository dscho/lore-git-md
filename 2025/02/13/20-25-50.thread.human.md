This thread addresses a Makefile syntax issue that causes build failures with GNU Make 4.4.90+. The problem stems from tab characters accidentally being used for indentation in conditional statements within the zlib configuration section, specifically in the ZLIB_NG and ZLIB_PATH blocks. This regression was introduced in commit adding zlib-ng support (b9d6f64393), reverting an earlier standardization (728b9ac0c3) that had replaced tabs with spaces in conditionals.

The fix simply replaces the tab indentation with 8 spaces in these conditional blocks while keeping the logic identical. This maintains compatibility with modern Make versions while conforming to the project's established Makefile style. The change is purely build-system related and doesn't affect runtime behavior. Junio C Hamano has acknowledged the fix, indicating this straightforward mechanical correction will be accepted. No further discussion appears needed as the solution cleanly addresses the compatibility issue while aligning with prior standardization efforts.
