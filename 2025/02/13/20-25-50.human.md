Build system fix addressing a Makefile syntax issue with zlib-ng support.

Taylor Blau fixes a regression introduced in January's zlib-ng compatibility work where tab characters were accidentally used as recipe prefixes in conditional statements. This follows up on an April 2024 change (728b9ac0c3) that prepared Git's Makefiles for stricter GNU Make behavior by replacing tabs with spaces in conditionals. The patch simply converts the problematic tabs to spaces in the ZLIB_NG-related conditionals, matching the established pattern.

The change is straightforward and clearly motivated - it fixes a build failure that occurs with newer versions of GNU Make (4.4.90 is mentioned). The fix aligns with previous work in this area and maintains consistency in the build system's handling of conditional statements. No behavioral changes are introduced beyond making the build work correctly with modern make versions.
