Performance optimization for merge-recursive's rename processing. This is the first of two patches in Meet Soni's series addressing quadratic complexity in string list handling within merge-recursive.

The patch converts `process_renames()` from using `string_list_insert()` (which performs sorting on each insertion, leading to O(n²) complexity) to using `string_list_append()` followed by a single sort (O(n log n)). The change maintains the same sorted output while being more efficient for large inputs. The commit message notes this optimization is safe because diffcore_rename guarantees no duplicates in the processed lists.

The patch is technically sound and has already received positive feedback from Elijah Newren, who confirmed the optimization is worthwhile despite merge-recursive's eventual deprecation. The diff is minimal (15 lines changed) and preserves all existing functionality while improving performance characteristics. The FIXME comment about the time complexity has been removed since it's now addressed by the implementation.

This appears ready for inclusion - it's a clear win with no downsides, and follows the pattern established in previous optimizations to this code. The second patch in the series (marked RFC) explores applying this same optimization more broadly in merge-recursive.
