This thread began with Jacob Keller reporting a segmentation fault in `git check-mailmap` when processing email-only lookups against mailmap entries that contain both name and email mappings. The discussion initially questioned whether the behavior (returning the input email unchanged in such cases) was correct or a side effect of the crash.

Junio Hamano, the Git maintainer, clarified that the current behavior aligns with the documented mailmap semantics: full entries (with both name and email) should only match when both fields are provided, while email-only entries apply more broadly. This established an important design principle for mailmap handling.

With the behavior question resolved, Jacob has now proposed a minimal fix to address just the segmentation fault - passing an empty string instead of NULL for the name parameter in email-only lookups. This maintains the correct behavior while preventing crashes, and he suggests adding a regression test. The fix is straightforward now that the expected semantics are clear, though there may still be value in updating documentation to make the matching rules more explicit. The thread has productively narrowed from initial crash report through behavior discussion to a clean technical solution.
