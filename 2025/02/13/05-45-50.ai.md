This is a refactoring patch in the `git-diff-pairs(1)` series, specifically addressing callback compatibility in the diff queue internals. Patrick Steinhardt responds to Justin Tobler's explanation about preserving the original callback signatures in `diff_options`.

The key point is that the original `diff_addremove()` and `diff_change()` functions must remain unchanged because they are used as callbacks in `diff_options` with fixed `add_remove_fn_t` and `change_fn_t` signatures. Justin explains that modifying these would be problematic since some callers (like pruning operations using `file_add_remove()` and `file_change()`) don't actually queue filepairs, making the `diff_filepair` return value meaningless in those contexts.

Patrick agrees with the approach but suggests this important architectural constraint should be documented in the commit message. The discussion confirms the series' strategy of introducing new functions (`diff_filepair_addremove()` and `diff_filepair_change()`) that return pointers while keeping the original callback signatures intact for compatibility. This maintains the diff subsystem's contract while enabling the new batched processing functionality.

The exchange highlights the careful balance being struck between modernization and backward compatibility in the diff queue internals, with both technical constraints (callback signatures) and documentation needs being addressed as the series progresses toward v3.
