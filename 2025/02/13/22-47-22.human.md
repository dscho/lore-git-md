Bugfix for mailmap handling in `git check-mailmap` when using full mailmap entries.

Jacob Keller reports a segmentation fault and unexpected behavior in `git check-mailmap` when processing full mailmap entries (those with both old and new name/email pairs). The issue occurs when the input contains only an email address - the code passes NULL for the name parameter, which leads to a crash. Even when fixed to pass an empty string instead, the mapping still doesn't work as expected for full mailmap entries.

The patch attempts to fix this by modifying the lookup logic in `map_user()` to better handle cases where there's a single subitem in the mailmap entry but no simple entry. It includes a test case demonstrating the expected behavior. However, the author notes this solution causes another test to fail and admits not fully understanding the mailmap code, marking this as an RFC (Request For Comments) to solicit input from maintainers.

This appears to be a genuine bug affecting users of the mailmap feature, particularly those using the newer sendemail mailmap support. The patch shows good debugging effort but may need refinement from mailmap experts to properly handle all edge cases while maintaining backward compatibility.
