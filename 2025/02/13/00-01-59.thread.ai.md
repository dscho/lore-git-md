Thread summary:

Performance regression in reftable backend during mass ref creation reported by brian m. carlson. Test shows 30x slowdown (57.44s vs 5.5s) when creating 50,000 refs compared to traditional files backend. Test methodology uses controlled synthetic ref creation across multiple namespaces (heads/remotes/tags) on modern Linux systems with Git's 'next' branch, measuring with /usr/bin/time. Memory usage similar (~160MB RSS) between backends. Includes reproduction script that can be modified to use real refs from Linux repo. No root cause analysis yet, but significant performance impact demonstrated for large ref operations. This affects initial push scenarios in repositories with many refs, though common workflow impact unknown. Well-documented report with clear reproduction steps, making it suitable for profiling and investigation.
