Performance optimization for merge-recursive's unmerged entry processing. This is the second patch in Meet Soni's series addressing quadratic complexity in string list operations, following the already-reviewed optimization for `process_renames()`.

The patch applies the same established pattern to `get_unmerged()` in merge-recursive.c, replacing O(n²) `string_list_insert()` calls with O(n) `string_list_append()` followed by a single O(n log n) sort and O(n) deduplication. The change maintains identical behavior while improving asymptotic performance for large index states, particularly benefiting cases with many unmerged entries.

Key technical details:
- Removes pre-insertion `string_list_lookup()` checks since duplicates will be handled by the final deduplication pass
- Preserves the stage data allocation pattern (xcalloc for each entry's util pointer)
- Adds explicit `string_list_sort()` and `string_list_remove_duplicates()` calls after building the complete list
- Modifies 10 lines total (5 insertions, 5 deletions) in merge-recursive.c

The patch is marked RFC to solicit feedback on whether this optimization pattern should be applied more broadly across merge-recursive. It builds on the already-accepted approach from the first patch in the series, but since `get_unmerged()` handles different data flows than `process_renames()`, the author is seeking confirmation that the same optimization is appropriate here. The thread context indicates Elijah Newren has previously endorsed this general approach while emphasizing the need for per-function documentation of the_repository removal.
