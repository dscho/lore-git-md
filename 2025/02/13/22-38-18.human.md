This is a bugfix discussion regarding tag fetching behavior in protocol v2. Taylor Blau confirms Igor Todorovski's report that commit 3f763ddf28 ("fetch: set remote/HEAD if it does not exist") unintentionally broke tag decoration when fetching specific commits with depth limits. The issue manifests as missing tags in `git log --decorate` output for fetched commits.

Blau provides technical analysis tracing the regression to changes in how ref prefixes are handled, particularly around the interaction between HEAD and tags prefixes. He proposes a fix that would unconditionally add the "refs/tags/" prefix when tags are requested, but acknowledges this area is complex and seeks input from the original authors of related commits (CC'd in the thread).

The discussion appears technically sound, with Blau carefully considering the historical behavior and multiple interacting commits. This looks like a legitimate regression that needs addressing, though the exact solution may require more discussion given the subtle interactions between different fetch behaviors.
