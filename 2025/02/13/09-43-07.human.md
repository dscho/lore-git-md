Feature enhancement for `git rebase --update-refs` interactive mode. This email from Phillip Wood responds to Ivan Shapovalov's concerns about branch management workflows, solidifying the design direction for the interactive ref updating feature.

The discussion confirms that simply excluding branches matching HEAD (a previous proposal) is too limited for complex scenarios with interdependent feature branches. Shapovalov's example shows this breaks down when managing parallel versions of related features (like v1/v2 variants of myfeatureA and myfeatureB).

Wood agrees the config-based `rebase.updateRefs=interactive` approach is the right solution, as it preserves flexibility for future enhancements. He wants to keep the command-line interface simple, reserving `--update-refs` arguments for future filtering capabilities (like `--update-refs='*-v2'` to target specific branch patterns). This maintains a clean separation between enabling the feature and configuring its behavior.

The exchange shows the feature has reached consensus on supporting both simple workflows via CLI and complex branch management via config, with all major design questions now resolved. Wood's response indicates the implementation is effectively finalized, with only mechanical work remaining before integration.
