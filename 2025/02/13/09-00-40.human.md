Performance optimization for merge-recursive's unmerged entry processing. This is the second patch in Meet Soni's series addressing quadratic complexity in string list operations, following up on the already-reviewed optimization for rename detection.

The patch applies the same pattern used in the series' first patch to `get_unmerged()` - replacing O(n²) `string_list_insert()` calls with O(n) `string_list_append()` followed by a single O(n log n) sort. The change maintains correctness while improving performance for large index states, particularly benefiting cases with many unmerged entries.

As marked RFC, this patch seeks feedback on whether to apply this optimization pattern more broadly in merge-recursive. The implementation is clean and follows the same proven approach as the first patch, though the commit message could better explain why duplicates can be safely removed (likely because the index guarantees unique paths per stage).

The patch is small (10 lines modified) and low-risk, though some may question investing effort in merge-recursive given its planned deprecation. The optimization could still benefit users during the transition period.
