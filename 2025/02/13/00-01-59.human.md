Performance issue in reftable backend with mass ref creation.

Brian Carlson reports a significant performance regression when creating 50,000 refs using the reftable backend compared to the traditional files backend. In synthetic tests, the reftable backend takes ~57 seconds versus just ~5.5 seconds for files - a 30x slowdown. The test involves deleting all refs then recreating them from a prepared list, simulating a large initial push scenario.

The issue was observed on two different Linux systems (Ubuntu 24.04 and Debian unstable) using Git's `next` branch, suggesting it's not a platform-specific problem. Carlson provides a reproduction script that clones the Linux kernel repo and performs the benchmark, though notes the test could be made faster by using a local clone.

While acknowledging this is a synthetic test, Carlson intended it to model reference update performance during large repository pushes. No root cause analysis is provided yet, but the dramatic difference suggests this would be easy to profile. The email serves primarily to surface the issue rather than propose a solution.
