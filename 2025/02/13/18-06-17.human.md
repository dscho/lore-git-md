This is a maintainer response in a performance optimization thread about reference backend migrations. Junio C Hamano is replying to Karthik Nayak's defense of the `--skip-reflog` flag for `git refs migrate`.

Junio acknowledges the performance benefits of skipping reflog migration during backend changes but questions the architectural approach. He agrees that combining reflog skipping with migration could be more efficient than separate operations, but argues it's premature to add this optimization before implementing a general `git reflog drop` command. His cake analogy suggests they should first build the fundamental reflog management capability before adding migration-specific optimizations.

The exchange shows the discussion has moved beyond technical implementation (which appears sound) to architectural philosophy - whether to prioritize immediate performance gains for a specific operation or first establish more general tooling. Junio isn't rejecting the optimization outright but wants to see it in context of broader reflog management capabilities.
