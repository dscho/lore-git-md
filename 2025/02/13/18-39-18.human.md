This is a platform compatibility discussion in the ongoing series addressing `-Wsign-comparison` warnings in `apply.c`. Junio Hamano responds to Karthik Nayak's review of patch 1/6, which changes type fields in `apply_state` to unsigned.

The conversation focuses on type consistency - Nayak had pointed out that since `max_change` is compared against the sum of `lines_added` and `lines_deleted`, those fields should also be converted to unsigned for consistency. Hamano agrees with the principle of type consistency but raises an alternative possibility of using signed integers throughout if some internal APIs use negative numbers to signal errors.

Hamano also expresses concern about the readability impact of explicit casts (like `(int) max`) that result from using size_t, wondering if unifying on signed integers with range checking might produce cleaner code. This suggests the discussion may expand beyond just warning elimination to consider broader code quality tradeoffs.

The exchange shows the series is in active review with maintainers weighing in on both technical correctness and code maintainability implications. While the core warning-fixing goal remains, the conversation is now exploring related type consistency questions that could affect more of the codebase than originally planned.
