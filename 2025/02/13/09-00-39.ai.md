Performance optimization for merge-recursive's rename processing, now incorporating review feedback. This is the first of two patches in a series addressing quadratic complexity in string list construction.

The patch modifies `process_renames()` in merge-recursive.c to build string lists unsorted and sort them afterward, changing the complexity from O(n²) to O(n log n). The change leverages diffcore_rename's guarantee of no duplicates in the processed lists. The implementation switches from `string_list_insert()` to `string_list_append()` followed by explicit sorting.

Key technical details:
- Maintains the same FIXME comment (now converted to documentation) about the complexity improvement
- Preserves all behavioral guarantees while improving performance
- Modifies two string list constructions (a_by_dst and b_by_dst) with matching patterns
- Adds explicit `string_list_sort()` calls after building each list
- Total diff is minimal (15 lines modified) with no functional changes

The patch appears technically sound, having incorporated Elijah Newren's prior feedback about preserving documentation and clarifying scope.
