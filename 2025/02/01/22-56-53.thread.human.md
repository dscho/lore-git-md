This thread investigates reported performance regressions in Meson-built Git tests on Windows, where certain tests take dramatically longer (from under a second to over a minute) compared to other platforms. The discussion has evolved from initially suspecting Meson/Ninja/MSVC-specific issues to recognizing fundamental Windows platform characteristics.

M Hickford originally reported the slowdowns in tests like t-reftable-stack and t0013-sha1dc, but couldn't provide direct Makefile comparison data due to build difficulties. Initial analysis from Johannes Sixt and Patrick Steinhardt suggested the slowdowns might reflect Windows' inherent process handling rather than Meson-specific problems. Brian m. carlson's recent contribution provides deeper technical context, explaining how Windows' need to emulate Unix fork/exec behavior in the Win32 subsystem creates unavoidable overhead, though WSL offers better performance for those who can use it.

The thread now has consensus that these observations reflect platform limitations rather than build system defects, with historical context about Johannes Schindelin's efforts to port shell scripts to C as a mitigation strategy. While no immediate solutions are proposed, the discussion has helped frame realistic expectations for Windows contributors. The remaining open question is whether build-system-agnostic optimizations could help, though the fundamental architectural differences suggest significant improvements would require moving away from shell-based tests on Windows.
