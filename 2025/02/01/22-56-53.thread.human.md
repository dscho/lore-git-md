This thread investigates performance slowdowns in Git's test suite when built with Meson on Windows. It began with M Hickford reporting some tests taking dramatically longer (jumping from under a second to over a minute) in Meson/Ninja builds using MSVC. Johannes Sixt questioned whether this was truly a Meson regression or just how Windows tests normally behave. Patrick Steinhardt then provided data showing similar performance between Meson and Makefile builds, suggesting the slowdowns might be inherent to Windows test execution patterns rather than build-system specific.

Now, M Hickford has clarified they can't compare to Makefile builds since this was their first successful Windows build attempt (having previously with Makefile and CMake). They're asking whether Windows' known process creation overhead (~10ms per process) explains why integration tests are consistently slower than unit tests on the platform. The discussion has shifted from investigating a potential Meson regression to understanding Windows' general test execution characteristics, particularly for tests like t-reftable-stack and t0013-sha1dc that spawn many processes. While no definitive root cause has been identified, the working assumption is that these observations reflect normal Windows behavior rather than a new problem introduced by Meson. The thread remains open for others to contribute additional performance comparisons between build systems.
