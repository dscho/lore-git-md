This is a test infrastructure discussion about undefined behavior in unit tests, specifically in the reftable test suite. Jeff King points out that the test `t_reftable_invalid_limit_updates()` continues execution after a failed `check()` assertion, which can lead to NULL pointer access if `reftable_new_stack()` fails. He demonstrates how this could cause a segmentation fault, though notes this is a broader pattern seen across many unit tests.

The email raises an important design question about whether test assertions should abort execution (requiring more careful cleanup code) or continue (risking undefined behavior). While the immediate example comes from the recently merged reftable series, the discussion is more about the test framework's behavior than the reftable changes themselves. Jeff doesn't propose a specific solution, but highlights the tradeoffs between robustness and convenience in test writing.
