This is a security-related discussion about warning users when they use the insecure `git-credential-store` helper. Jeff King (peff) responds to M Hickford's RFC patch that proposed showing warnings before password entry when the first credential helper is "store".

Jeff raises several thoughtful points about the current approach's limitations. He notes that the warning would miss cases where "store" isn't the first helper, where it's invoked via shell, or where credentials come from other sources. He suggests alternatives like renaming the helper to be more obviously insecure ("git-credential-plaintext") or requiring explicit user acknowledgment via a config option before allowing insecure storage.

The discussion reveals a tension between security warnings and usability - Jeff questions whether warnings are the right approach at all if users have already explicitly chosen this helper. He floats the idea of eventually deprecating or removing the insecure helper entirely. The technical discussion remains focused on finding the most effective way to prevent accidental insecure credential storage while respecting legitimate use cases.
