This is a test infrastructure discussion about undefined behavior in unit tests, specifically in the reftable test suite. Jeff King points out that the test `t_reftable_invalid_limit_updates()` from the recently approved reftable series has potential undefined behavior if `reftable_new_stack()` fails, since the test continues execution despite the NULL `st` pointer. He demonstrates how this could lead to a segmentation fault in practice.

The core issue is that the test harness's `check()` macro doesn't terminate execution on failure, unlike production code which would typically return early. Jeff notes this is a common pattern across many unit tests, but highlights it here because it's particularly straightforward in this case. He presents two options: either modify the test framework to return on failure (which would require adding cleanup code to avoid leaks), or continue living with the current behavior despite its ugliness.

The email includes a concrete demonstration of the problem via a test modification that forces failure, showing how it leads to a crash.
