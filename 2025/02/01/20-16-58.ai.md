This is the final patch in a series extending `git rev-list`'s missing object reporting capabilities. It adds type information to the `--missing=print-info` output format, completing the feature set that includes path reporting from previous patches.

The patch modifies the `missing_objects_map_entry` struct to track object types alongside paths, updates the printing logic to include `type=<type>` in the output, and adjusts test cases to verify the new behavior. The type information is inferred from the containing object's type when available (for objects referenced by other objects) and omitted for missing tips (where no containing object exists).

Key technical details:
- Adds `type` field to `missing_objects_map_entry` struct
- Modifies `add_missing_object_entry()` to accept and store type information
- Updates `print_missing_object()` to append type info when available
- Maintains backward compatibility - missing tips still print without type info
- Extends test coverage in `t6022-rev-list-missing.sh` to verify type output
- Documents the new `type=<type>` field in `rev-list-options.txt`

This completes the thread's goal of providing comprehensive missing object information through a unified `--missing=print-info` action, with all the quoting stability improvements from earlier patches now applying to type information as well. The implementation follows the thread's consensus to let consumers handle any needed filtering while providing all available attributes in a stable, config-independent format.
