This is a small documentation and implementation patch that adds "show" as a valid value for `help.autocorrect`, completing the set of human-readable boolean alternatives for the configuration option. The change is purely for consistency, mirroring how other boolean-like options in Git accept multiple equivalent forms.

The patch adds "show" to:
1. The documentation listing of equivalent values that trigger showing (but not running) suggested corrections (AUTOCORRECT_SHOW behavior)
2. The `parse_autocorrect()` function's string matching
3. The test case that verifies all show-equivalent values

This comes as a follow-up to the recently finalized v5 series that reworked the autocorrect behavior, where the false/0 vs never distinction was resolved. The change is minimal and uncontroversial, maintaining the established pattern where Git config options often accept multiple synonymous values (like "true"/"on"/"yes"). The author notes this could be dropped if deemed unnecessary, suggesting it's more about completeness than fixing any actual issue.
