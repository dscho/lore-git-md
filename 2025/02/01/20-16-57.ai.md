Feature enhancement for `git rev-list`'s missing object reporting. This patch (3/4 in the series) introduces a new `--missing=print-info` action that extends the existing missing object reporting with path information. The implementation builds on previous thread discussions about stable quoting and config-independent output.

The patch adds path reporting to missing object output in the format `?<oid> path=<quoted-path>`, with paths quoted in C-style when needed (handling spaces and special characters). The implementation uses a new `missing_objects_map_entry` struct to track paths via `oidmap`, replacing the simpler `oidset` used by basic `--missing=print`. Quoting respects the new `QUOTE_PATH_IGNORE_CONFIG` flag to ensure stable output regardless of `core.quotepath` settings.

Key technical details:
- New `MA_PRINT_INFO` enum value alongside existing missing actions
- `add_missing_object_entry()` helper stores path with oid in oidmap
- `print_missing_object()` handles both basic and info-printing modes
- Path quoting uses existing infrastructure with new ignore-config behavior
- Tests verify path reporting for various edge cases (spaces, quotes in filenames)

The changes maintain backward compatibility while providing the extended functionality requested in earlier thread discussion. Test coverage in `t6022-rev-list-missing.sh` exercises the new path reporting with various filename edge cases. The implementation follows the thread's consensus to output all available information (letting consumers filter) rather than baking filtering into Git itself.
