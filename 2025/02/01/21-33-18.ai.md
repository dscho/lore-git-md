This is a follow-up patch in the `help.autocorrect` configuration series, addressing the open question about boolean false vs numeric 0 behavior. The patch implements Junio Hamano's suggestion to make false boolean values ("false"/"off"/"no") behave consistently with 0 by showing suggested commands without running them, while reserving "never" for the absolute no-op case.

The technical changes include:
- Introducing a new `AUTOCORRECT_SHOW` constant (-4) for the show-but-don't-run case
- Modifying `parse_autocorrect()` to return this for both 0 and false booleans
- Updating the documentation to group 0 with false/off/no values
- Adding test coverage for all false-equivalent values
- Preserving the existing behavior where `AUTOCORRECT_NEVER` (-2) remains distinct for "never"

The patch cleanly implements the late-stage refinement discussed in the thread, where Jeff King and Junio Hamano agreed this would be more consistent behavior. It maintains backward compatibility while resolving the semantic inconsistency between numeric 0 and boolean false values. The implementation appears thorough, with clear documentation updates and comprehensive test coverage across all false-equivalent values.
