This is a refactoring patch that's part of a series improving missing object reporting in `git rev-list`. It introduces a new quoting flag to ensure consistent output regardless of user configuration.

The patch adds a `CQUOTE_IGNORE_CONFIG` flag to the C-style quoting functions, making them ignore `core.quotePath` settings and always use the default behavior. This addresses a thread concern about configuration-independent output for machine parsing, particularly important for the `--missing=print-info` feature being developed in the series.

The changes are straightforward - modifying `cq_must_quote()` and related functions to accept the new flag, with corresponding updates to function signatures and call sites. The implementation looks clean and focused, directly addressing the quoting stability issue raised in earlier thread discussion.

This is the first of four patches in v3 of the series, setting up the quoting infrastructure that will be used by the missing object reporting feature in subsequent patches. The change is well-contained to the quoting subsystem with minimal risk of side effects.
