This is a feature patch series (v3) extending `git rev-list`'s missing object reporting capabilities. Justin Tobler proposes adding a new `--missing=print-info` action that provides richer context about missing objects beyond just their OIDs, including path and type information.

The series builds on previous discussion that established consensus around outputting all known attributes (path and type) in a machine-readable format while letting consumers handle filtering. The key changes in v3:
- Reverts to a single `--missing=print-info` action rather than combining flags
- Adds configuration-independent quoting for stable machine parsing
- Drops potentially confusing "attributes" terminology from docs

The implementation now uses `quote_path()` with a new flag to ignore `core.quotePath` settings, ensuring consistent output. The output format remains `?<oid> path=<path> type=<type>` with C-style quoting when needed. While functional, Justin raises valid concerns about parsing complexity and floats the idea of a future `for-each-ref`-style format for easier machine consumption.

This appears to be a well-considered evolution of the feature, with thorough test coverage and attention to interface design. The quoting changes in patches 1-2 seem particularly important groundwork. The series addresses previous feedback while maintaining the thread's technical consensus about output design. Reviewers will likely focus on the quoting implementation details and whether the output format strikes the right balance between human and machine readability.
