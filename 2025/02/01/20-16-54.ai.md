This is a feature patch series (v3) introducing extensible missing object reporting for `git rev-list`, now consolidated under a single `--missing=print-info` action. The series builds on previous discussion that established consensus around recording object attributes upfront while letting consumers handle filtering.

Key changes in v2->v3:
- Reverts to unified `--missing=print-info` action (dropping separate `--missing-info` flag)
- Adds configuration-independent quoting via new flags to `quote_c_style()` and `quote_path()`
- Avoids "attribute" terminology in docs to prevent confusion with gitattributes

Technical implementation now includes:
1. Core quoting improvements (patches 1-2):
   - New `QUOTE_C_IGNORE_QUOTEPATH` flag for stable C-style quoting
   - New `QUOTE_PATH_IGNORE_QUOTEPATH` flag for config-independent path quoting
2. Path reporting (patch 3):
   - Tracks first encountered path per missing object
   - Uses new quoting flags for stable output
3. Type reporting (patch 4):
   - Extends output with inferred object types
   - Maintains format: `?<oid> path=<quoted-path> type=<type>`

The series addresses Junio Hamano's concerns about config-dependent quoting by introducing configuration-immune quoting variants. Justin Tobler raises open questions about machine parsing complexity, suggesting potential future work with null-delimited or for-each-ref-style formatting.

Test coverage in t6022-rev-list-missing.sh appears comprehensive, verifying both path and type reporting. The implementation maintains backward compatibility while providing the extensible missing object reporting discussed in the design phase.
