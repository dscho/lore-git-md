Performance regression investigation for Meson-built Git tests on Windows, originating from M Hickford's report of significant test execution slowdowns (some tests jumping from sub-second to 60+ seconds) with Meson/Ninja/MSVC on Windows. The technical context remains: Windows platform, MSVC compiler, Ninja backend, with affected tests (t-reftable-stack, t0013-sha1dc, t0010-racy-git) showing process spawning overhead. Johannes Sixt sought to determine whether this represents a regression compared to Makefile builds, while Patrick Steinhardt's test results indicated no significant performance difference between Meson and Makefile builds on Windows, suggesting the slowdowns may reflect inherent Windows test execution patterns. M Hickford now clarifies they cannot provide Makefile comparison data (having previously failed to build with Makefile/CMake), and shifts focus to understanding Windows' general test slowness.

Brian m. carlson provides technical context about why shell-based tests are inherently slower on Windows compared to Unix systems, explaining that the process creation overhead stems from Windows' need to emulate Unix fork/exec behavior in the Win32 subsystem. The response clarifies that while Windows does have efficient process creation in its Linux subsystem (WSL), this isn't available for native Win32 builds. The email also notes historical efforts by Johannes Schindelin and others to port shell scripts to C as a mitigation strategy for Windows performance. Key technical points include the fundamental architectural difference in process handling between Unix and Windows, the performance trade-offs of Cygwin's accurate emulation, and the WSL performance alternative (though incompatible with native Windows builds).

The thread's current consensus suggests these observations reflect platform characteristics rather than Meson-specific issues, with brian m. carlson's explanation providing deeper technical grounding for why Windows test execution will remain slower than Unix equivalents when using shell-based tests.
