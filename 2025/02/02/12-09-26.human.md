Test fix addressing a subtle issue with exit code handling in merge-rename test cases.

This patch fixes three test assertions in t6423-merge-rename-directories.sh where Git's exit code was being suppressed by piping its output through `uniq`. The original form `git ls-files | uniq` would mask any failure of the `git ls-files` command, potentially allowing test failures to go unnoticed. The fix separates the operations into two steps, first capturing Git's output to a file and then processing it, which properly preserves the exit status.

The changes are straightforward and focused - each modified test case now uses an intermediate file (`actual`) to store the `git ls-files` output before piping to `uniq`. This is a common pattern in Git's test suite to ensure proper error detection. The patch appears well-scoped and correctly implements the intended behavior change without introducing any new complexity.

While not fixing any runtime behavior, this improves test reliability by ensuring failures in these directory rename scenarios would be properly caught.
