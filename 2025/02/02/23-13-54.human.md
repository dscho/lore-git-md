This is a technical explanation of Windows test performance characteristics in the ongoing thread about Meson test slowness. Brian m. carlson provides context about why Git's shell-based tests are inherently slower on Windows compared to Linux, explaining that the process creation overhead (10+ ms per fork/exec) stems from Windows' need to emulate Unix behaviors that aren't native to the Win32 subsystem. They note this is a long-standing issue that has prompted past efforts to rewrite shell components in C for better Windows performance, while suggesting WSL as a faster alternative (though incompatible with Windows binary testing). The response doesn't address Meson specifically but confirms the thread's emerging consensus that the observed slowness reflects platform constraints rather than build system issues. This authoritative explanation from a core contributor likely moves the discussion toward acceptance of Windows' performance characteristics as unavoidable for shell-heavy tests, though leaves open whether further C conversions might help.
