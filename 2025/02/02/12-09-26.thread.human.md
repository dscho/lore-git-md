This thread addresses a subtle testing issue in Git's merge-rename-directories test script (t6423). The patch fixes three test cases (12i, 12j, and 12k) that were inadvertently masking Git's exit codes by piping `git ls-files` output directly to `uniq`. This could allow test failures to go undetected if the underlying command failed.

The solution modifies each affected test to first capture Git's output to a file before processing it with `uniq`, ensuring proper error detection. While the changes are mechanical, they improve test reliability for directory rename scenarios during merges. The patch appears correct and well-motivated, focusing specifically on the testing infrastructure rather than altering Git's core behavior.
