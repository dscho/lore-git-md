This is the third patch in Usman Akinyemi's series removing `the_repository` usage, focusing on the verify-commit builtin. It's a preparatory refactoring that moves the config loading in `cmd_verify_commit()` to happen after option parsing, which simplifies handling NULL repository contexts when help text is requested.

The change is small (4-line diff) but strategically important - it ensures the config loading won't try to use a NULL repository pointer when `-h` is passed, by moving it after the point where help requests would exit. This follows the same pattern seen in earlier patches of the series, where initialization flows are restructured first before actually removing `the_repository` usage.

The patch is cleanly implemented with a clear commit message explaining both the technical rationale and how this enables the next step in the series. It maintains the project's established patterns for this refactoring effort and has been reviewed by Christian Couder. The change is low-risk since it doesn't modify behavior, just the timing of config loading relative to option parsing.
