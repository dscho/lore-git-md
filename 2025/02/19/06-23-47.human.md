This is a brief follow-up to an already accepted patch series improving `git merge-tree --stdin` reliability. Patrick Steinhardt provides a minor implementation suggestion about the placement of a stdout flush call that was added to prevent deadlocks in the series' first patch. 

He notes that while the flush could theoretically be moved into `real_merge()` (the function that writes the merge results), the current placement is reasonable since the other callsite doesn't need the flush behavior. The comment is more of an observation than a requested change, as he concludes the series looks good overall.
