Performance optimization patch implementing seek capability for files backend iterators.

This is patch 15/16 in a series optimizing refname availability checks across Git's ref storage backends. The patch adds seek functionality to the files backend's ref iterators, following the pattern established for other backends in earlier patches. The implementation is straightforward since it builds on the existing ref-cache iterator which already has seek support.

The change adds a `seek` method to both regular ref iterators and reflog iterators in the files backend. For regular refs, it delegates to the underlying ref-cache iterator. For reflog iterators, it follows the same approach as the reftable backend by explicitly making seek operations invalid (triggering a BUG if called).

This completes the seek implementation across all ref storage backends (files, packed, reftable) and iterator types (regular, ref-cache, merged), enabling the final performance optimizations planned for the series. The patch is small (16 lines) and focused, with no behavioral changes beyond adding the new capability. It maintains consistency with the rest of the series by keeping reflog iterators non-seekable, as established in earlier patches.
