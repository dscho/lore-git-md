This is a coordination discussion about the gitk TCL script refactoring as part of the larger Meson build system integration effort.

Johannes Sixt, the gitk maintainer, responds to Patrick Steinhardt's proposal to move the gitk build changes to a separate submission via Sixt's tree. He agrees with the approach but raises a practical concern about the transition period when Git's repository would expect to build gitk as a subproject before the corresponding Meson instructions are available in the gitk repository.

The email highlights a timing issue in the planned migration path - there would be a window where Git's build system would reference gitk as a subproject while gitk itself hasn't yet been updated with the Meson build instructions. Sixt is asking whether they should proceed with this phased approach or wait until gitk's changes are fully integrated first.

This continues the thread's theme of build system unification while surfacing maintainer coordination challenges. The technical solution (using Meson's subproject mechanism) is agreed upon, but the sequencing needs clarification to avoid broken builds during the transition. The exchange demonstrates the consideration being given to real-world integration impacts beyond just the technical correctness of the changes.
