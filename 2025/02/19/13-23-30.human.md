Performance optimization for `git update-ref` in refs subsystem series (patch 3/16). This patch disables the reference ambiguity check when parsing object IDs in `git update-ref`, building on the new `repo_get_oid_with_flags()` API introduced earlier in the series.

The change makes sense for this plumbing command since: (1) the manpage clearly expects object IDs rather than refnames, and (2) as a non-interactive tool, ambiguity warnings would rarely be seen anyway. The patch shows significant performance improvements - 1.19x faster for files backend and 2.32x for reftable in benchmarks creating 10,000 refs against a 100,000-ref repository. The larger relative gain for reftable comes from its faster baseline performance.

This follows the precedent set by `git cat-file` which made a similar optimization in 2013. The implementation cleanly uses the new `GET_OID_SKIP_AMBIGUITY_CHECK` flag from patch 2/16, modifying four call sites in `builtin/update-ref.c` to use the flag. The change is well-motivated with clear benchmarks and maintains backward compatibility.
