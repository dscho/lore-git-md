This is a technical patch in the bundle-URI HTTPS progress reporting series, specifically addressing a curl signal handling issue.

The patch disables curl's SIGALRM signal handling which conflicts with Git's progress meter system. Jeff King notes that while curl normally sets up SIGALRM handlers, we can safely disable this behavior via CURLOPT_NOSIGNAL. The change is minimal - just a single line addition to http.c's get_curl_handle() function to set this option.

This is part of the v2 series implementing progress reporting for bundle-URI downloads, where clean signal handling is important for proper progress meter operation. The patch comes from Jeff King (peff) and builds on Toon Claes' original work, though it's marked as a new patch in the v2 series rather than a modification of existing code.

Key technical details:
- Location: http.c's curl handle initialization
- Option set: CURLOPT_NOSIGNAL
- Impact: Prevents curl's SIGALRM from interfering with Git's progress meter
- Context: Needed for reliable progress reporting during HTTP bundle downloads

The change is straightforward and appears uncontroversial, with no test changes needed since it's fixing an underlying compatibility issue rather than adding new observable behavior. It's one of several curl-related fixes in the series to ensure clean progress reporting.
