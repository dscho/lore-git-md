This is patch 9/16 in a performance optimization series for the refs subsystem, focusing on iterator lifecycle management. The patch separates iterator lifecycle from iteration itself, introducing a new `ref_iterator_free()` function to explicitly deallocate iterators rather than having them auto-release when exhausted.

Key technical changes:
- Replaces automatic cleanup at iteration end with explicit `ref_iterator_free()` calls
- Introduces `dir_iterator_free()` for the special case of dir_iterator
- Drops the return value from abort functions since it wasn't meaningfully used
- Updates all iterator implementations (files, packed, reftable backends) to use the new pattern
- Modifies call sites to handle the new lifecycle model
- Preserves all existing functionality while making the API more flexible for future reseeking optimizations

The change enables potential future optimizations by allowing iterator reuse (reseeking) while cleaning up the current awkward calling patterns around iterator cleanup. It's a foundational change for the remaining optimizations in the series, particularly the reseeking capability mentioned in later patches. The implementation touches all major ref backends (files, packed, reftable) and their iterator implementations.
