Performance optimization series for refs subsystem, focusing on refname availability checks across all backends (files, packed, and reftable). This is the cover letter for v2 of the series, which builds on previous discussion and benchmarking from brian m. carlson about reftable performance with tombstone references.

The series implements three key optimizations: (1) skipping redundant OID ambiguity checks in `git-update-ref`, (2) batching refname availability checks using a `strset` to avoid re-checking common prefixes, and (3) implementing reseekable iterators across all ref backends to reuse iterator state. Benchmark results show significant speedups - up to 7.56x faster for reftable in edge cases and 1.23-1.27x for files backend, with more realistic scenarios showing 4.78x and 1.23x improvements respectively.

The series is structured in four parts: patches 1-4 handle OID ambiguity checks, 5-8 implement batched checking, 9 deduplicates prefix checks, and 10-16 implement reseeking infrastructure. Notable changes in v2 include improved commit messages, better batching for files backend, and fixes to iterator interface documentation. The cover letter provides detailed benchmark comparisons between backends and revisions.

Key technical components include new APIs (`repo_get_oid_with_flags`, `refs_verify_refnames_available`, `ref_iterator_free`), flag (`GET_OID_SKIP_AMBIGUITY_CHECK`), and iterator behavior changes (reseeking support, clear free/release semantics). The changes maintain compatibility while providing measurable performance benefits, particularly for repositories with many references.
