This is the final patch in a series implementing progress reporting for bundle-URI HTTP downloads, focusing on cleaning up error output handling. The patch addresses a UX issue where both child and parent processes were emitting error messages about failed downloads, creating confusing output like "fatal" from the child followed by "warning" from the parent. The solution redirects stderr to /dev/null in the child process while preserving progress output through a dedicated file descriptor.

Key technical details:
- Adds `progress_set_fd()` API to allow progress output to target a specific descriptor while other stderr messages are suppressed
- Modifies `http.c` to redirect stderr after starting progress meter
- Updates progress display logic in `progress.c` to use the configured fd
- Maintains all existing progress meter functionality while preventing duplicate error messages

The change builds on the series' earlier work integrating curl's progress callbacks with Git's progress meter system, now completing the solution with proper error stream handling. This final piece ensures clean output while preserving all progress reporting capabilities added in previous patches.
