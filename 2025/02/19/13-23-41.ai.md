Performance optimization series for refs subsystem (v2 patch 14/16) implementing packed-ref iterator reseeking capability.

This patch completes the implementation of iterator reseeking for the packed-refs backend, following the pattern established in previous patches for other iterator types. The change removes the previous optimization that used `prefix_ref_iterator_begin()` since it prevented proper reseeking behavior when switching between empty and non-empty prefixes. Instead, the prefix matching logic is now open-coded directly in the `advance()` function.

Key technical details:
- Adds `prefix` field to `packed_ref_iterator` struct to track current search prefix
- Implements new `packed_ref_iterator_seek()` vtable function that:
  - Uses `find_reference_location()` to position iterator at prefix start
  - Updates prefix tracking and position state
- Modifies `advance()` to perform prefix matching inline rather than delegating
- Updates iterator_begin to initialize state without early empty-iterator optimization
- Maintains proper resource cleanup with new `free(iter->prefix)` in release

The implementation follows the same reseeking pattern seen in patches 10-13, though with packed-refs-specific positioning logic. This change enables the series' next phase of performance optimizations by ensuring all ref iterator types (files, reftable, and now packed) properly support the seek operation. The removal of the prefix iterator wrapper simplifies the control flow while maintaining correct prefix matching behavior.
