Performance optimization patch implementing seek capability for files backend iterators in the refs subsystem.

This is patch 15/16 in the v2 series optimizing refname availability checks, specifically completing the implementation of iterator reseeking across all ref backends. The patch adds seek support to the files backend by implementing the underlying vtable functions, following the pattern established for other backends in previous patches. The implementation leverages the existing ref-cache iterator (which already has seek support from patch 13/16) for the main ref iteration case, while explicitly preventing seek operations on reflog iterators (matching the reftable backend's behavior from patch 12/16).

Key technical details:
- Adds `files_ref_iterator_seek()` that delegates to the underlying ref-cache iterator's seek capability
- Implements `files_reflog_iterator_seek()` that BUGs out to prevent invalid usage
- Updates both vtable structures to include the new operations
- Maintains consistency with the series' approach of not supporting reflog iterator seeking
- Completes the cross-backend seek capability needed for the optimization series' next phases

The change is relatively straightforward since it builds on the ref-cache iterator work done earlier, with the main complexity being proper handling of the reflog iterator case. This patch represents the final piece needed to enable full iterator reseeking optimizations across all ref storage backends (files, packed, reftable). The implementation appears clean and consistent with the series' established patterns, though as with previous iterator patches, test coverage for the new seek paths would be valuable.
