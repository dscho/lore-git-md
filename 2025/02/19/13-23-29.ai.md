This is patch 2/16 in a performance optimization series for the refs subsystem, introducing a new flag to skip ambiguity checks in OID lookups.

The patch adds a `GET_OID_SKIP_AMBIGUITY_CHECK` flag to bypass the reference ambiguity check in `get_oid_basic()`. Currently, Git always checks if a hex OID string could also be a refname, which adds overhead even when callers know this check isn't needed. The flag provides an opt-out mechanism for performance-sensitive cases where the check provides little value.

The implementation modifies `hash.h` to define the new flag and updates `object-name.c` to respect it in `get_oid_basic()`. The change is minimal and backward compatible, simply adding a condition before the existing ambiguity check. The commit message notes this will be used by subsequent patches in the series, likely for optimizing ref operations where the ambiguity check is known to be unnecessary.

This is a foundational change enabling later optimizations in the series. The patch follows the established pattern of extending the `get_oid()` family of functions with new flags while maintaining existing behavior by default. The implementation appears straightforward with no obvious issues, though its real impact will be seen when used by the later optimization patches.
