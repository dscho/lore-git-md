Performance optimization for the files ref backend, part of a larger series improving refname availability checks. This patch extends the batching approach from the reftable backend (introduced in patch 5/16) to the files backend, focusing on two key scenarios where batched checks can help: during reference updates and repository initialization.

The patch carefully analyzes five different contexts where refname availability checks occur in the files backend, identifying only two (ref updates and initial repository setup) as suitable for batching. It modifies `lock_raw_ref()` to queue refnames for batched verification rather than checking each immediately, though notes this creates a small race window with packed-refs changes that's accepted as a tradeoff for performance.

Implementation-wise, the changes are clean and focused - adding a `refnames_to_check` string_list parameter through the call stack and consolidating checks into a single `refs_verify_refnames_available()` call. The patch maintains existing behavior while setting up for performance gains that will be realized in later patches (1.58x-7.56x speedups are expected in the full series).

This continues the series' pattern of careful, incremental optimization while maintaining backward compatibility. The technical debt around the packed-refs race is explicitly acknowledged but deferred as a known tradeoff. The patch appears well-considered and builds logically on the infrastructure established in earlier patches.
