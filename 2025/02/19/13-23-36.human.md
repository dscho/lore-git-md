Refactoring patch in a performance optimization series for refs iteration. This is patch 9/16 in a series addressing inefficiencies in refname availability checks across Git's ref backends.

Patrick Steinhardt's patch separates iterator lifecycle management from iteration itself. Currently, ref iterators automatically free themselves when exhausted, which creates awkward calling patterns and prevents iterator reuse. The change introduces explicit `ref_iterator_free()` calls while maintaining the same memory safety guarantees.

Key changes:
- Adds `ref_iterator_free()` and `dir_iterator_free()` functions
- Removes automatic cleanup in `ref_iterator_advance()`
- Simplifies error handling by removing `ref_iterator_abort()` return values
- Updates all ref backend implementations (files, packed, reftable)
- Preserves existing behavior while enabling future reseeking optimizations

The patch is part of a larger effort that has already demonstrated measurable performance improvements (1.58x speedup for reftable in previous commits). This foundational change enables further optimizations in later patches while maintaining backward compatibility. The implementation appears thorough, touching all relevant iterator implementations and their callers.
