Bugfix for curl signal handling in HTTP progress reporting. This patch from Jeff King (part of Toon Claes' v2 bundle-URI progress series) addresses a conflict between curl's SIGALRM handling and Git's progress meter system. The simple but important change tells curl not to use signals (via CURLOPT_NOSIGNAL) when initializing HTTP connections, allowing the progress reporting to work reliably. 

The patch is minimal - just a two-line addition to http.c - but solves a subtle technical incompatibility. It's one of several improvements in this series that make the bundle-URI download progress reporting more robust. The change comes from Jeff King's review feedback on the v1 series, showing how the series is being refined through collaboration. 

This is a low-risk change since it's using a standard curl option to disable behavior that Git doesn't need, and it's well-tested as part of the broader progress reporting work. The patch fits cleanly into the series' goal of providing smooth progress feedback during bundle downloads while maintaining clean error handling.
