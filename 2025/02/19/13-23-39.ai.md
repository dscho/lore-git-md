Performance optimization in the refs subsystem, specifically implementing seek capability for reftable iterators as part of the ongoing series to improve refname availability checks.

This patch 12/16 builds on the iterator reseeking infrastructure introduced in earlier patches, now implementing it for the reftable backend. The changes are relatively straightforward since the low-level reftable iterators already support seeking. Key technical points include:

1. The reftable_ref_iterator now dynamically allocates its prefix string (changed from const char* to char*) to support seek operations, with proper cleanup in the release function.

2. A new reftable_ref_iterator_seek() function implements the vtable seek operation by resetting the iterator's prefix and delegating to the low-level reftable_iterator_seek_ref().

3. The ref_iterator_for_stack() initialization is updated to use the new seek operation rather than directly setting the prefix.

4. Reflog iterators explicitly do not support seeking, with a BUG() trap added to catch any attempted usage.

5. Error handling is improved by properly checking the return value of reftable_stack_init_ref_iterator().

The patch continues the series' pattern of careful resource management, with proper freeing of the prefix string and maintenance of the iterator's state. It sets the stage for further performance optimizations in subsequent patches by completing the seek capability implementation across all iterator types in the reftable backend. The changes are focused and well-contained, touching only reftable-backend.c with 30 lines added and 5 removed.
