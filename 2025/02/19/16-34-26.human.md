This is a proposal for contributor documentation improvements regarding third-party Git projects. Junio Hamano suggests adding a section to Git's maintenance notes that would help direct bug reports and contributions to the appropriate third-party projects rather than the core Git mailing list.

The proposal acknowledges that while the mailing list welcomes non-code contributions, many issues reported there actually belong to related projects like git-scm.com, Git for Windows, or the ProGit book. The patch includes a draft addition to the MaintNotes file that would list these projects with their proper issue trackers and contribution guidelines.

Key discussion points raised:
- Whether maintaining such a list is worthwhile given the maintenance burden
- How to determine which third-party projects should be included
- What the maintenance policy should be for keeping the list up-to-date

The patch itself shows the proposed documentation addition, which currently includes three major Git-related projects with their GitHub issue trackers and contribution guidelines. This appears to be a well-considered documentation improvement that could help route contributor efforts more effectively while being clear about the boundaries of the core Git project.
