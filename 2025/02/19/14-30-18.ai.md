This is a feature patch series introducing progress reporting for bundle-URI HTTP downloads, addressing the current silent waiting period during large bundle transfers. The series builds on previous discussion about clean error handling while showing progress, incorporating feedback from Jeff King.

The v2 series adds three new commits (two from Jeff King and one new fix) to the original five-patch set. Key technical changes include:

1. New progress reporting infrastructure with `progress_set_total()` to dynamically update transfer sizes
2. HTTP layer integration using curl's progress callback mechanism
3. Remote-curl plumbing to optionally enable progress reporting
4. Bundle-URI client wiring to activate progress display
5. Stderr silencing when progress is active to maintain clean error handling

The implementation uses curl's CURLOPT_XFERINFO callback to feed progress data to Git's existing progress meter system. Notable files touched are http.c (curl integration), progress.c (API extensions), and bundle-uri.c (client activation). The series introduces a "Downloading via HTTP" progress meter that shows percentage, transferred bytes, total size, and throughput.

The range-diff shows careful attention to edge cases, including proper cleanup of curl progress settings and removal of an unnecessary fflush(). Test coverage appears thorough with new cases in t5557-http-get.sh and updates to progress display tests.

This represents a mature iteration of the feature, having addressed the original stderr contamination issues while providing the missing user feedback during bundle downloads. The incorporation of Jeff King's older progress meter improvements suggests good attention to code reuse and existing patterns.
