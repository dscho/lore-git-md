Performance optimization patch completing a 16-part series on refname availability checks, specifically implementing iterator reuse for refname checks.

This final installment in the series implements iterator reseeking in `refs_verify_refnames_available()` to avoid reallocating iterators for each reference check. The change builds on the iterator reseeking capability introduced in earlier patches (10-15) across all backend types. The reftable backend shows a 1.25x speedup (39.8ms → 31.9ms) in the benchmark creating 10,000 refs against 100,000 existing refs, while the files backend sees minimal improvement (1.01x) due to its inherent filesystem overhead dominating the runtime.

The patch modifies `refs.c` to conditionally create or reseek the iterator, maintaining it across checks until cleanup. Key technical points:
- Adds conditional iterator creation via `if (!iter)`
- Implements reseeking via `ref_iterator_seek()` when iterator exists
- Preserves existing error handling and cleanup paths
- Maintains compatibility with all iterator types (files, reftable, packed) from prior patches

This completes the series' performance work by applying the reseeking optimization to the final critical path in refname verification. The implementation follows the pattern established in previous patches while focusing on the refs.c core logic. With this change, all iterator types now fully support stateful reuse via seek operations, realizing the series' performance goals.
