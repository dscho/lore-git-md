This is a refactoring patch that's part of a series adding progress reporting for bundle-URI HTTPS downloads. It introduces a new `progress_set_total()` function to Git's progress meter system, allowing the total size to be updated after progress tracking has started.

The change is motivated by the bundle-URI download use case where the total download size isn't known upfront (it comes from HTTP Content-Length headers) but needs to be incorporated into progress reporting once available. The patch adds the core function, exposes it in progress.h, and includes both a test helper update and new test cases to verify the behavior.

The implementation is clean and focused, with thorough test coverage showing the expected output when the total is modified mid-progress. This is the first of seven patches in v2 of the series, building infrastructure that will be used by later HTTP download progress reporting patches. The thread context shows this work has already benefited from review and improvements by Jeff King.
