Foundational patch in a performance optimization series for refs subsystem, introducing a new API function.

This is the first patch in a 16-part series (v2) aimed at optimizing refname availability checks across Git's ref backends. It introduces `repo_get_oid_with_flags()`, a new function that extends `repo_get_oid()` by accepting flags to modify its behavior. The function passes these flags through to `get_oid_with_context()` while maintaining the same basic functionality.

The patch is straightforward - it factors out the existing `repo_get_oid()` implementation to call the new flags-aware version with default flags (0), then adds the new function declaration to the header. The implementation will be used in subsequent patches, particularly for the `GET_OID_HASH_SKIP_AMBIGUITY_CHECK` flag that helps optimize refname checks.

This is a clean preparatory change that follows good practices: it maintains backward compatibility through the original function, adds clear documentation, and keeps the diff minimal. As the first patch in a larger optimization effort, it sets up infrastructure needed for more significant performance improvements to come in the series.
