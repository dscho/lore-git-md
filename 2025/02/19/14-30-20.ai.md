This is a progress meter enhancement patch in the bundle-URI download progress reporting series, specifically addressing throughput display for single-item downloads.

The change improves how Git's progress meter displays throughput when downloading a single large item where object counting isn't meaningful. Currently, the progress meter forces either misleading percentage displays (0/1) or awkward counting displays when total items are unknown. Jeff King's patch modifies the display logic to omit the counter entirely in these cases, showing only the throughput rate (e.g., "22.00 MiB | 10.97 MiB/s") when progress is on the zero-th item of an unknown total.

Key technical changes:
- Modifies `progress.c` to conditionally omit the counter display when `n=0` and total is unknown
- Updates the `throughput_string()` function to check progress state before adding separator
- Adds a new test case in `t0500-progress-display.sh` verifying the pure-throughput display
- Maintains all existing behavior for cases where counting is meaningful

This builds on the series' foundation of clean progress reporting for HTTP bundle downloads, specifically addressing a UX issue that would have made single-file download progress confusing. The implementation is clean and well-tested, with the new behavior clearly demonstrated in the added test case. This appears ready for inclusion as part of the overall bundle-URI progress reporting improvements.
