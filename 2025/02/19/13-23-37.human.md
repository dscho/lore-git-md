Performance optimization patch introducing iterator reseeking capability for refs subsystem.

This is patch 10/16 in a series optimizing refname availability checks, specifically adding infrastructure to allow reusing iterators by reseeking them to new prefixes. Patrick Steinhardt builds on the iterator lifecycle refactoring from patch 9/16 to enable this new capability.

The change introduces a new `.seek` function in the ref iterator vtable that allows callers to reset an iterator to a new prefix without creating a fresh one. This enables potential performance optimizations by reusing internal state - particularly useful for reftable iterators which already support internal reuse but couldn't expose this before. The implementation maintains the same behavior as creating a new iterator but may allow backends to optimize.

The patch adds the core infrastructure first, implementing the seek operation for trivial cases (empty and prefix iterators) while leaving backend-specific implementations for later patches. This follows the series' pattern of incremental, well-factored changes that set up for more substantial optimizations. The change touches iterator internals across debug, base, and prefix iterator implementations while maintaining backward compatibility.

This appears to be a solid technical foundation for the reseeking optimizations promised in later patches, with clean separation of concerns and thorough documentation of the new API. The change is focused and well-contained, suggesting it should integrate smoothly with the rest of the series.
