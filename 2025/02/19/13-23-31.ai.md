Performance optimization patch introducing batched refname availability checks as part of the refs subsystem optimization series.

This patch 4/16 in the foundational work for optimizing refname availability checks across Git's ref backends. It introduces a new `refs_verify_refnames_available()` function that checks for reference conflicts against a list of refnames rather than a single refname, with the existing single-ref function reimplemented as a wrapper. The implementation currently maintains the same logic but processes multiple refname checks in a single pass, setting up for future optimizations in subsequent patches.

Key technical details:
- New API function `refs_verify_refnames_available()` in refs.h
- Maintains identical behavior to existing checks but processes string_list inputs
- Current implementation is functionally equivalent to repeated single checks
- Prepares ground for batching optimizations in later patches
- Modifies refs.c with significant restructuring (169 lines changed)
- Preserves all existing error handling and reporting behavior

The patch is part of a coordinated series where this infrastructure will enable measurable performance gains in later patches through reduced redundant checks and better iterator utilization. The changes are focused on the refs subsystem internals with no direct user-facing impact yet, though the eventual goal is faster reference operations.
