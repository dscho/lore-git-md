This is patch 7/16 in a performance optimization effort for the refs subsystem, specifically extending batched refname availability checks to the files backend's initial transaction handling. The patch builds on the batching infrastructure introduced earlier in the series (patch 4's `refs_verify_refnames_available()` API) and applies it to the special case of initial transactions where references are first created in a repository.

The key change moves from per-ref verification calls to `refs_verify_refname_available()` to collecting refnames in a `refnames_to_check` string_list and verifying them in a single batch. This restructuring doesn't yet show performance benefits - those will come in later patches that build on this foundation. The patch maintains identical error behavior while setting up for future optimizations that will improve performance during repository cloning and reference format migrations.

The implementation modifies `files_transaction_finish_initial()` to:
1. Collect all refnames into `refnames_to_check` during the initial scan
2. Perform batched verification after locking packed-refs but before committing
3. Properly clean up both the new and existing string_lists
4. Preserve all existing error paths and conditions

The changes are relatively contained (23 lines modified) and follow the pattern established in earlier patches of the series. This continues the incremental approach where API changes enable future optimizations while maintaining current behavior. The patch appears well-integrated with the series' overall goal of reducing redundant refname checks, though its performance impact won't be realized until subsequent commits implement the actual batching optimizations.
