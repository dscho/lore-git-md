This is a coordination discussion about integrating gitk's build system changes with the Meson conversion effort, specifically addressing maintenance boundaries.

Johannes Sixt (the gitk maintainer) responds to Patrick Steinhardt's proposal to move the gitk build changes to a separate submission via Sixt's tree. While agreeing to the approach, Sixt raises a practical concern about timing: there could be a transitional period where Git's repository expects to build gitk as a subproject, but the gitk repository hasn't yet been updated with the corresponding Meson build instructions.

The email doesn't propose a specific solution but flags this potential integration challenge for discussion. This comes after earlier discussion where Junio Hamano suggested coordinating with Sixt, recognizing gitk has traditionally been maintained as a subtree with its own maintainership. The thread shows the contributors being careful to respect existing maintenance boundaries while modernizing the build system.
