This is the final patch in a series implementing progress reporting for bundle-URI HTTPS downloads, connecting the client-side capability to the HTTP progress plumbing.

The patch enables progress reporting in the bundle-URI download path by sending the "option progress true" command to git-remote-https. This activates the progress reporting infrastructure built up in previous patches (curl callback integration, progress meter extensions, and remote-curl plumbing). The change is minimal - just adding the progress option while removing an unused err field initialization.

Key technical details:
- Modifies bundle-uri.c's download_https_uri_to_file() function
- Sends "option progress true" to git-remote-https before the get command
- Removes unused cp.err initialization
- Builds on the complete HTTP progress reporting stack established in previous patches

This completes the series by wiring up the client-side activation of the progress reporting that was implemented in the earlier plumbing layers. The result will show users download progress when fetching large bundle files via HTTPS during clone operations.
