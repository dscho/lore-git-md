This thread reports unexpected behavior in Git's automatic garbage collection that's causing excessive pack file regeneration in large repositories. Pierre Ossman observed that `git gc --auto` is repeatedly repacking objects that are already in existing packs, contrary to both documentation and code expectations. This leads to either pack replacement or duplication when `gc.bigPackThreshold` is set, significantly increasing backup sizes.

The core issue appears to be that Git's auto-gc isn't properly respecting existing pack contents when creating new packs, despite configuration options (`gc.autoPackLimit` and `gc.bigPackThreshold`) that should prevent this. The report suggests a discrepancy between the documented behavior (where Git should only pack loose objects or objects not in the largest pack) and what's actually happening in practice.

While the report lacks specific reproduction steps or version details, it raises a potentially significant performance and storage efficiency concern for large repositories, particularly those under backup systems that track file changes. The behavior warrants investigation by Git's packfile experts to determine whether this is a bug, undocumented behavior, or misconfiguration.
