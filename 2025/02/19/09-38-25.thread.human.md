This thread investigates unexpected pack file regeneration during Git's auto-gc, initially reported by Pierre Ossman in large repositories. The discussion has identified two distinct issues: promisor packs in partial clones bypassing keep protections, and unnecessary regeneration of small packs in standard repositories like TigerVNC. Patrick Steinhardt contributed key solution directions, suggesting `git maintenance` with incremental repacking as an alternative to traditional gc, and highlighting `git repack --geometric` as a future solution.

Pierre's latest response shifts the thread into a testing phase, planning to first observe default behavior with reset configurations before evaluating Patrick's maintenance-based approach. While Patrick suggested frequent repository updates might explain some behavior, Pierre remains uncertain this accounts for all observed cases. The thread now awaits empirical results from these tests, which should help determine whether the solution path lies in configuration adjustments, maintenance task adoption, or deeper changes to pack handling logic. Core technical considerations remain the roles of `gc.autoPackLimit`, packfile keep rules, and the tradeoffs between many small packs versus periodic full repacks.
