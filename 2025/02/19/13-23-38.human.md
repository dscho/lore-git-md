Performance optimization for merged ref iterators in refs subsystem. This is patch 11/16 in a series improving refname availability checks, specifically implementing seek capability for merged iterators.

The patch modifies the merged iterator implementation to support seeking, a capability introduced in patch 10/16. The key change is splitting the iterator pointers into owned and working versions - the owned versions persist for the iterator's lifetime while the working versions are reset during seeks. This allows the underlying iterators to be reused rather than freed and recreated.

The implementation is straightforward by:
1. Adding new `iter0_owned`/`iter1_owned` fields to track persistent ownership
2. Implementing `merge_ref_iterator_seek()` to reset working iterators and propagate seeks
3. Updating release logic to free the owned iterators
4. Modifying advance logic to avoid premature freeing of working iterators

This builds on the iterator lifecycle improvements from patch 9/16 and enables the reftable backend to fully leverage its internal optimizations in upcoming patches. The change maintains clean separation of concerns while eliminating redundant iterator recreation during seeks.
