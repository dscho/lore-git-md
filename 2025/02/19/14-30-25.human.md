Final patch in a series improving HTTP bundle download progress reporting. This addresses a user experience issue where error messages from failed bundle downloads would appear duplicated (once as "fatal" from the child process and once as "warning" from the parent). The solution redirects stderr to /dev/null in the child process while preserving progress output through a new `progress_set_fd()` API that lets the progress meter write directly to the original stderr. This maintains clean progress display while eliminating confusing duplicate error messages.

The patch builds on previous work in the series that added curl-based progress reporting for HTTP downloads. It modifies both the HTTP layer (to redirect stderr when progress is enabled) and the progress meter subsystem (to support writing to an arbitrary file descriptor). The implementation is straightforward and maintains all existing functionality while solving the specific UX problem.

This appears to be a well-considered final piece of the bundle-URI progress reporting feature, addressing a real user-facing issue that emerged from the earlier implementation. The changes are focused and the commit message clearly explains both the problem and solution.
