Documentation clarification on pathspec magic word syntax. 

Junio Hamano responds to Anselm Schüler's report about differing behavior between `::file` and `:():file` pathspecs, confirming this is not a bug but rather correct interpretation of the syntax rules. He explains the key distinction: 

The short form (`::file`) uses colons as delimiters where the second colon is optional when unambiguous, while the long form (`:():file`) uses parentheses as strict boundaries - the closing parenthesis terminates the magic word list, making what follows part of the actual pathspec. Thus `:():file` correctly matches a literal `:file` path rather than treating it as a magic-free pathspec like `::file` does.

This follows up on Lucas Oshiro's earlier technical explanation, with Junio providing additional context about when the short form's terminating colon becomes necessary for disambiguation. The thread has established this as a documentation interpretation issue rather than an implementation bug, though the current behavior is technically correct per Git's specs. The discussion may lead to improved documentation to prevent similar confusion.
