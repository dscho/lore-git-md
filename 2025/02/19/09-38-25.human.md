This is a bug report about Git's automatic repacking behavior causing excessive backup sizes. Pierre Ossman reports that `git gc --auto` appears to be unnecessarily recreating pack files containing mostly old objects, contrary to what the documentation and code suggest should happen. 

The core issue is that pack files are being regenerated even when they contain stable, unchanged objects, leading to large backup increments. The team tried using `gc.bigPackThreshold` to mitigate this, but it only resulted in pack duplication rather than proper reuse of existing packs. 

Ossman notes this behavior doesn't match their understanding of when Git should create new packs (which should primarily be for new objects, not repacking existing ones until `gc.autoPackLimit` is reached). The report seeks clarification on why this is occurring and how to properly configure Git to avoid unnecessary repacking of stable objects.

This appears to be a potentially significant issue for teams backing up large repositories, as the current behavior creates unnecessary churn in pack files. The report is well-detailed, citing both observed behavior and documentation expectations, making it a solid starting point for discussion about Git's automatic maintenance behavior.
