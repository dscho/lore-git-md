This is a feature patch in the bundle-URI HTTPS progress reporting series, adding the plumbing to enable progress display for HTTP downloads. It builds on the foundational progress meter changes from earlier in the series.

The patch introduces a new `progress` flag in `struct http_get_options` that callers can use to opt into download progress reporting. When enabled, it wires up curl's `CURLOPT_XFERINFO` callback to feed transfer statistics into Git's progress meter system. The implementation handles both the setup (starting the progress meter and configuring curl callbacks) and cleanup (resetting curl options and stopping the progress display) phases.

Key technical details include:
- New `http_progress_callback()` function that bridges curl's transfer stats to Git's progress API
- Proper initialization of progress meter with "Downloading via HTTP" title
- Careful cleanup to prevent resource leaks
- Integration with the existing HTTP request machinery in http.c
- The callback uses `progress_set_total()` (added in patch 1) to handle dynamic sizing of downloads

This is a core piece of the series that connects the earlier progress meter enhancements to actual HTTP operations. The implementation appears clean and follows Git's existing patterns for progress reporting. With this in place, bundle-URI downloads (and potentially other HTTP operations) can now show useful progress feedback to users while maintaining clean error handling.
