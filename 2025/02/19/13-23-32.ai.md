This is patch 5/16 in a performance optimization series for the refs subsystem, specifically targeting the reftable backend. The patch introduces batching of refname availability checks during transaction preparation.

The change restructures the reftable backend to collect all refnames that need availability verification into a string list first, then performs a single batched check using the new `refs_verify_refnames_available()` API introduced in patch 4/16. While this doesn't yet provide performance benefits (the actual batching optimizations come in later patches), it sets up the infrastructure by changing the call pattern from individual checks to batched verification.

Key technical details:
- Adds a new `refnames_to_check` string_list to collect refnames during transaction preparation
- Replaces individual `refs_verify_refname_available()` calls with string_list appends
- Performs a single batched verification after collecting all refnames
- Maintains identical error behavior and cleanup paths
- Sorts the refnames before verification (likely preparation for future optimizations)
- Properly cleans up the new string_list in the error path

The patch is part of a larger effort to optimize refname availability checks, particularly around tombstone references in the reftable backend. It builds on the API changes from earlier patches and sets the stage for the performance improvements that will be realized in subsequent patches (with expected speedups of 1.58x-7.56x). The change is relatively straightforward, just moving from individual checks to batched verification while maintaining all existing behavior.
