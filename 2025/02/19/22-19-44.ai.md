This is a discussion about the input format and scope limitations for the new `git-diff-pairs` plumbing command, part of the ongoing feature development series. Justin Tobler responds to Junio Hamano's questions about design decisions in the v2 implementation.

The email focuses on three key input format questions:
1. Whether to support both `-z` and normal `--raw` input formats (currently only `-z` is supported)
2. Whether to accept abbreviated object IDs (currently requires full OIDs)
3. Whether to implement pathspec filtering (currently rejects pathspecs)

Justin leans toward keeping the simpler `-z`-only input format for parsing efficiency, requiring full OIDs for explicitness, and deferring pathspec support unless there's clear demand. He acknowledges Junio's point that the command should work with `diff-index --cached` output in addition to `diff-tree`, and commits to updating the documentation accordingly.

The email also notes a documentation build issue where the patch needs rebasing on top of commit 1f010d6b (doc: use .adoc extension), which Justin will address in the next version. This continues the thread's pattern of refining the command's scope and implementation based on maintainer feedback, with the current discussion focusing on input/output contract decisions before finalizing the design.
