This is patch 4/16 in a performance optimization series for the refname availability verification system. The patch introduces a new batch-checking API `refs_verify_refnames_available()` that can verify multiple refnames at once, replacing the existing single-refname `refs_verify_refname_available()` function (which is now reimplemented as a wrapper).

The change is primarily structural at this point - the implementation still performs the same checks, just in a loop over multiple refnames. The real performance optimizations will come in later patches that can take advantage of this batching capability. The diff is large but mostly mechanical, moving the existing logic inside a loop while maintaining all the same validation steps for directory conflicts, extras, and skip lists.

This is part of a larger effort to optimize ref operations, particularly around tombstone references in the reftable backend. The series has already shown promising speedups in earlier patches (1.19x-2.32x), and this infrastructure change enables further optimizations that will be built on top in subsequent patches. The patch appears well-structured and maintains backward compatibility while setting up for more significant changes to come.
