Performance optimization patch implementing reftable iterator seeking as part of a larger refs subsystem optimization series. This is patch 12/16 in v2 of the series, building on the iterator reseeking infrastructure introduced in earlier patches.

The patch adds seek capability to reftable iterators, completing the implementation of the `ref_iterator_seek()` API for the reftable backend. It handles memory management for prefix strings and properly checks initialization success of the underlying reftable iterator. The change is straightforward since the low-level reftable iterators already support seeking, though it explicitly does not support seeking for reflog iterators (which now BUG() if attempted).

This continues the series' pattern of incremental improvements to the refs subsystem, with each patch building on the last. The reftable backend changes here will enable more substantial performance gains in subsequent patches by allowing efficient reuse of iterators during ref operations. The implementation appears clean and well-contained, with proper attention to memory management and error checking.
