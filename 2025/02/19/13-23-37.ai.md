Performance optimization series for refs subsystem (patch 10/16): Introduces iterator reseeking capability as groundwork for further optimizations in the refs backend.

This patch adds infrastructure to allow ref iterators to be reseeked to new prefixes without requiring full reinitialization, enabling potential performance optimizations by reusing internal iterator state. The change introduces a new `.seek` vtable function that backends can implement, with initial implementations provided for the debug and prefix iterator cases. The reftable backend (which already has internal reseeking capability) will be able to expose this optimization in later patches.

Key technical elements:
- New `ref_iterator_seek()` API that mirrors `ref_iterator_begin()` behavior but allows reuse
- Vtable extension with `ref_iterator_seek_fn` callback
- Implementations for:
  - Debug iterator (passes through to underlying iterator)
  - Empty iterator (no-op)
  - Prefix iterator (updates prefix and forwards)
- Documentation clarifying prefix matching semantics (literal string matching)

The change maintains backward compatibility while enabling future optimizations, particularly for the reftable backend which can now avoid recreating iterators. This builds on the iterator lifecycle management from patch 9/16 and sets up for the reseeking optimizations promised in the series overview. The implementation follows the series' pattern of clean, incremental API extensions with thorough documentation.
