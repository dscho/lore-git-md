This is a design discussion email in the ongoing `git-diff-pairs` plumbing command development thread. Junio Hamano responds to Justin Tobler's earlier message about pathspec support, expanding on the architectural considerations for dividing responsibilities should lie in the diff processing pipeline.

The email focuses on where to place the logic for rename detection and pathspec filtering - either in the frontend tools that generate input for `git-diff-pairs`, or within `git-diff-pairs` itself. Junio presents two competing philosophies: either make the frontends simple and put complex logic in the shared backend (making maintenance easier but limiting frontend flexibility), or keep the backend minimal and push complexity to frontends (allowing more customization but requiring more work from tool authors).

This continues the thread's pattern of carefully considering the long-term maintainability and usability tradeoffs for this new plumbing command. The discussion remains at the architectural level rather than addressing specific code changes, suggesting the implementation work in patch 2/3 will need to account for these design decisions before proceeding.
