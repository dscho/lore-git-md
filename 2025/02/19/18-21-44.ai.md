Performance optimization patch in the refs subsystem series, specifically addressing ambiguity checks in `git update-ref`. This is patch 3/16 in the v2 series that has already been merged, with Justin Tobler providing post-merge style feedback.

The patch modifies `builtin/update-ref.c` to skip expensive ambiguity checks during object ID parsing by using the new `repo_get_oid_with_flags()` API with `GET_OID_SKIP_AMBIGUITY_CHECK`. This provides significant performance improvements, particularly for batch operations: 1.19x faster for files backend and 2.32x faster for reftable backend in benchmarks creating 10k refs against 100k existing refs.

Justin's follow-up notes that one remaining use of `repo_get_oid()` in `parse_cmd_symref_update()` wasn't converted to the new API and questions whether this was intentional. The thread context shows this is post-merge feedback on an already-completed series, so this would likely be addressed as a follow-up if needed. The original justification for the optimization (plumbing command usage patterns and performance costs) appears sound, with precedent from a similar change in `git cat-file`.
