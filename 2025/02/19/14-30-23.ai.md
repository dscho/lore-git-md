HTTP progress reporting implementation for remote-curl.

This patch completes the plumbing for HTTP progress reporting in git-remote-curl by wiring up the existing `option progress` capability to the new HTTP progress callback infrastructure. It builds on the earlier patches in the series that implemented curl callback handling and progress meter integration.

The key change is in remote-curl.c where the `parse_get()` function now passes the progress option through to `http_get_file()` via the `http_options` struct. This activates the progress reporting for HTTP downloads when the client has requested it via the `option progress` capability. The patch includes a test case that verifies the progress output appears as expected when downloading a small file.

This is the final piece connecting the client-side progress request through to the curl callback implementation from earlier in the series. The test demonstrates the end-to-end functionality, showing the same "Downloading via HTTP" progress meter that was implemented in previous patches. The implementation maintains backward compatibility by keeping progress reporting opt-in via the existing capability mechanism.
