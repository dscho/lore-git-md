Performance optimization completing the refs subsystem series. This final patch in the 16-part series implements iterator reuse for refname availability checks, building on the reseeking infrastructure added in previous patches. The change allows reusing ref iterators when checking for nested references rather than recreating them each time, yielding a 1.25x speedup for the reftable backend in benchmarks (39.8ms → 31.9ms for creating 10k refs). The files backend sees minimal improvement (1.01x) due to its inherent filesystem overhead. The implementation follows the pattern established in earlier patches, conditionally creating new iterators only when needed and otherwise reseeking existing ones. With this change, all iterator types (files, reftable, ref-cache, and packed) now fully support the seek operation, completing the series' performance optimization goals.
