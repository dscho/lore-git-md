This is a response from Junio Hamano addressing design decisions in the `git-diff-pairs` plumbing command series, specifically regarding input format handling and pathspec restrictions.

Junio strongly advises against Justin Tobler's suggestion to use `--input-format` for future format support, insisting on the conventional `-z` flag instead. He argues for consistency with other Git commands and suggests gracefully handling unsupported formats rather than introducing a new option pattern.

The more substantial feedback concerns pathspec handling. Junio challenges the current strict rejection of pathspecs, arguing this contradicts the command's role as a diff processor backend. He provides historical perspective on the `--raw` format's purpose in Git's diff pipeline and suggests pathspec filtering could be a legitimate use case, giving the example of chained diff commands with different pathspec scopes.

Junio recommends a more permissive approach to unsupported options during initial implementation, allowing the command to evolve toward full diff backend functionality. His comments position this as part of Git's broader diff architecture rather than just a standalone tool, suggesting the implementation should preserve flexibility for future expansion of features like pathspec filtering.

This feedback represents high-level architectural guidance from the Git maintainer, pushing back against premature restrictions that might limit the command's evolution into a full-featured diff backend component.
