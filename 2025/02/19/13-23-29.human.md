Performance optimization series for refs subsystem (patch 2/16). This patch introduces a new flag `GET_OID_SKIP_AMBIGUITY_CHECK` that allows callers to bypass the object ID ambiguity check in the `get_oid()` family of functions. The ambiguity check, which warns when a reference exists with the same name as an object ID, can add runtime overhead without benefit in some cases.

The change is minimal - just adding the flag definition and modifying one condition in `get_oid_basic()`. This appears to be a clean, focused change that maintains backward compatibility while providing the infrastructure needed for subsequent performance optimizations in the series. The commit message explains the motivation clearly: reducing unnecessary checks that add overhead.

This is part of a larger effort to optimize refname availability checks across Git's ref backends, with particular focus on improving reftable performance. The series has already gone through one round of review and this patch builds on the API extension from patch 1/16. The change looks straightforward and well-contained, with no obvious issues in the implementation.
