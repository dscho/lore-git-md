Performance optimization patch implementing ref-cache iterator seeking capability as part of the refs subsystem optimization series. This is patch 13/16 in v2 of the series, building on the iterator reseeking infrastructure introduced in earlier patches.

The patch modifies the ref-cache iterator implementation to support the new `ref_iterator_seek()` API introduced in patch 10/16. Key changes include:
1. Splitting seek logic from `cache_ref_iterator_begin()` into a new `cache_ref_iterator_seek()` function
2. Removing the optimization that returned empty iterators when no references exist (needed for reseeking to different prefixes)
3. Adding new fields to track cache state (`cache` and `prime_dir`) for reseeking
4. Updating the iterator's vtable to include the seek operation
5. Modifying advance logic to handle empty iterator states

The implementation maintains the pattern seen in previous iterator patches (10-12/16) while specializing for the ref-cache backend. It trades a small performance optimization (empty iterator shortcut) for the more important capability of iterator reuse through seeking. The change enables future performance optimizations in the series by completing the seek support across all iterator types.

This continues the series' progression toward its goal of optimizing refname availability checks, with the ref-cache implementation being the last major iterator type to gain seek support. The patch follows the established pattern of careful resource management seen in earlier iterator changes.
