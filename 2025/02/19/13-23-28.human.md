This is the first patch in a performance optimization series for the refs subsystem, introducing foundational infrastructure for later optimizations. Patrick Steinhardt adds a new `repo_get_oid_with_flags()` function that extends the existing `repo_get_oid()` by accepting flags to modify its behavior. The function will be used in subsequent patches to skip unnecessary OID ambiguity checks during refname availability verification.

The change is straightforward - it factors out the existing `repo_get_oid()` implementation to call through to the new flags-aware version, while maintaining backward compatibility. The patch includes proper documentation in the header file and follows Git's established patterns for object ID handling functions.

As the first patch in a larger series that has already seen positive feedback in v2, this appears to be a well-considered building block for the performance improvements to come, particularly around ref iteration and name checking. The series as a whole aims to speed up operations like ref updates by reducing redundant checks, with measured improvements of 1.58x-7.56x in some cases.
