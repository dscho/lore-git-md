Bug report about unexpected pack file regeneration behavior in Git's auto-gc.

Pierre Ossman reports observing Git repeatedly regenerating pack files in large repositories, causing excessive backup increments. This happens despite users not manually running `git gc`, suggesting it's triggered by `git gc --auto`. The behavior contradicts both the documentation and code inspection, which indicate Git should only pack objects not already in existing packs (or at least not those in the largest pack), until `gc.autoPackLimit` is reached.

The report notes that old packs are constantly being replaced by new ones containing mostly old objects, and that setting `gc.bigPackThreshold` only resulted in pack duplication rather than proper reuse. The author seeks clarification as they can't find any documentation or code explaining this behavior.

Key technical details:
- Involves Git's automatic garbage collection (`git gc --auto`)
- Related configuration options: `gc.autoPackLimit` and `gc.bigPackThreshold`
- Behavior appears to ignore existing pack contents when creating new packs
- Results in either pack replacement or duplication depending on settings

The report doesn't include specific reproduction steps or version information, but presents a clear discrepancy between expected and observed behavior that warrants investigation by Git packfile experts. The issue could significantly impact backup systems for large repositories.
