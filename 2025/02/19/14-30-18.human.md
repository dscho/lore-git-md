This is a feature patch series introducing progress reporting for bundle-URI HTTP downloads, addressing a user experience gap where large bundle downloads previously showed no feedback. The v2 series incorporates feedback from Jeff King and adds three new commits to handle edge cases.

The core functionality adds HTTP download progress meters similar to what users see during regular clone operations, showing percentage complete, bytes transferred, and throughput. The implementation uses curl's progress callback mechanism while carefully managing stderr output to avoid mixing progress with error messages.

Key technical changes include:
- New progress.c functions to handle dynamic total sizes
- HTTP layer integration with curl's progress callbacks
- Remote-curl protocol extension to enable/disable progress
- Bundle-URI plumbing to pass progress option to remote-https

The series now includes two commits from Jeff King that help with signal handling and progress meter formatting, plus a new commit to properly silence stderr when progress is enabled. The range-diff shows careful attention to edge cases like proper cleanup of curl options.

This appears to be a well-considered solution to the original problem, with thorough test coverage and clear commit messages explaining each piece. The v2 changes show responsiveness to earlier feedback about implementation details. The progress reporting should significantly improve user experience when cloning from bundle URIs with large downloads.
