Performance optimization patch (part 5/16) for refs subsystem, focusing on reftable backend batching.

This patch continues the series optimizing refname availability checks by introducing batching in the reftable backend. It modifies `reftable_be_transaction_prepare()` to collect all refnames needing verification into a `refnames_to_check` string list before performing a single batched availability check using the new `refs_verify_refnames_available()` API introduced in patch 4/16.

The change is a transitional step - while it restructures the code to use the new batched API, the performance benefits won't be realized until later patches implement the actual batching optimizations. The patch maintains identical error checking behavior while setting up for future speedups. It handles cleanup properly with `string_list_clear()` and preserves all existing error paths.

This is part of the broader effort to optimize ref operations, particularly around tombstone references in the reftable backend. The series has already seen review from multiple contributors, with Patrick Steinhardt now implementing the reftable-specific portions after Karthik Nayak established the core infrastructure in earlier patches. The changes are relatively contained (16 lines net) and focused on the reftable backend implementation details.
