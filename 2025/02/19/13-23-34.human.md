Performance optimization for the files backend's initial ref creation, part of a larger refs subsystem speedup series. This patch (7/16) extends batched refname availability checking to the initial transaction case, where references are first created in a repository. While not yet showing performance gains, it lays groundwork for future optimizations that will speed up operations like cloning repositories with many references.

The change modifies `files_transaction_finish_initial()` to collect refnames into a `refnames_to_check` string list before verification, rather than checking each individually. This matches the batched approach already implemented for the reftable backend in earlier patches. The patch maintains all existing error handling and cleanup paths while adding the new string list management.

As part of the series' careful progression, this patch deliberately keeps the underlying verification logic unchanged - the performance benefits will come in later patches that can now leverage this batched infrastructure. The commit notes this will particularly help cases like mass reference migration between backends or initial repository setup.

The changeset is relatively small (16 lines added, 7 removed) and focused on the files backend's special case for initial transactions. It follows the series' pattern of structural changes enabling future optimizations while preserving current behavior.
