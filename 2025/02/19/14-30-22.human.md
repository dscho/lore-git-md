This is part of a series implementing progress reporting for bundle-URI HTTP downloads, specifically adding the plumbing to enable progress meters for HTTP transfers.

The patch introduces a new `progress` flag in `struct http_get_options` that callers can use to opt into progress reporting. When enabled, it sets up curl's `CURLOPT_XFERINFO` callback to feed download progress data into Git's existing progress meter system, showing percentage complete, bytes transferred, and throughput. The implementation carefully manages the progress meter lifecycle, ensuring proper cleanup even if the transfer fails.

This is the fourth patch in a well-structured v2 series that has incorporated feedback from Jeff King, including signal handling fixes and display optimizations. The change is focused and cleanly implemented, with clear documentation of the new option. It builds on earlier patches that added dynamic progress meter sizing and single-file throughput display improvements.

The patch appears ready for review, completing a key piece of functionality for the bundle-URI feature by giving users feedback during potentially large HTTP downloads. The series as a whole shows thoughtful design and thorough test coverage.
