This is the first patch in a v2 series implementing progress reporting for bundle-URI HTTPS downloads, focusing on extending Git's progress meter system. The patch adds a new `progress_set_total()` function to allow dynamically updating the total size of a progress meter after creation, which is needed because curl may only receive the Content-Length header after the download starts.

The implementation adds the core function in progress.c with its header declaration, plus test coverage through both the test-progress helper and t0500-progress-display.sh. The test demonstrates updating the total mid-operation and verifies the percentage calculations adjust correctly. This foundational change enables the subsequent patches to implement the actual curl integration while maintaining clean progress reporting.

Key technical details:
- New API: `progress_set_total(struct progress *, uint64_t)` in progress.h
- Simple implementation that safely handles NULL progress
- Test case shows percentage recalculates correctly after total update
- Part of broader effort to show bundle download progress via HTTP
- Builds on existing progress meter infrastructure rather than creating parallel system

The patch appears well-contained and properly tested, with clear motivation tied to the series' overall goal. The implementation follows Git's existing patterns for progress meter handling.
