Feature patch enabling progress reporting for bundle-URI HTTPS downloads, part of a series to improve user feedback during large file transfers.

This is the sixth patch in a 7-part series that adds progress reporting for bundle-URI downloads over HTTPS. The series has evolved through multiple iterations with input from Jeff King, addressing technical challenges around clean error handling and signal interference. The current patch is the final plumbing piece that connects the client-side bundle-URI code to the HTTP progress reporting infrastructure established in earlier patches.

The change is minimal but crucial - it adds a "progress true" option to the git-remote-https helper when downloading bundle files. This activates the progress reporting callbacks implemented in previous patches, which show download percentage, bytes transferred, and throughput. The patch removes an unnecessary stderr redirection that could interfere with progress display.

This completes the end-to-end implementation, allowing users to see download progress when cloning with bundle URIs. The series has thorough test coverage and appears well-considered, with careful attention to edge cases like signal handling and cleanup. The progress reporting reuses Git's existing progress meter system while adding new capabilities for single-file downloads.
