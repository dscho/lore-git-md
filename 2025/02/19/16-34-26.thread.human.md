This thread began with a proposal from Git maintainer Junio Hamano to help direct contributors to the right issue trackers for major Git ecosystem projects (git-scm.com, Git for Windows, and the ProGit book) by adding documentation in the maintainer's notes (MaintNotes). The initial patch added a 40-line "Other places" section with specific GitHub links and contribution guidelines.

After receiving no feedback on the proposal, Junio has now followed up to indicate he plans to drop the change unless discussion emerges. He reiterated the open questions about maintenance approach, inclusion criteria, and whether this documentation belongs in maintainer-facing versus user-facing materials. The follow-up includes the full proposed diff that would be reverted and sets a mid-March deadline for feedback before the next edition of the maintainer's notes is published.

The core tension remains between making it easier for contributors to find the right place to report issues versus the ongoing maintenance burden of keeping such a list current. Junio's willingness to let the proposal lapse without community input suggests this is seen as a nice-to-have improvement rather than an urgent need. Unless other maintainers or contributors voice support by mid-March, this documentation change will not move forward.
