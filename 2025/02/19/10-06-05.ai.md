This is a UX suggestion in the ongoing refs migration optimization thread. Toon Claes proposes renaming the `--skip-reflog` flag to `--no-reflog` for the `git refs migrate` command, arguing the current name is misleading about the actual behavior. The flag doesn't just skip migrating reflogs during backend conversion - it actively removes them from the destination repository.

The suggestion comes after the thread has already reached consensus on deferring this optimization until after implementing general reflog management capabilities. The technical implementation remains valid but is now properly sequenced in the development roadmap. Toon's feedback focuses purely on improving the user interface clarity when this feature eventually lands.

Key points in the suggestion:
1. `--no-reflog` better matches Git's established UX patterns for destructive operations
2. The current flag name could mislead users about the actual behavior
3. Documentation (commit message and help text) should more clearly emphasize the reflog removal aspect

This is a relatively minor UX polish suggestion that doesn't affect the underlying technical approach or sequencing. It addresses clarity for end users when the deferred optimization is eventually implemented. The suggestion aligns with Git's principle of clear, predictable command-line interfaces.
