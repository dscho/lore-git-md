This is a follow-up in the git-scm.com documentation link issue thread, where Junio Hamano provides historical context about the `.txt` to `.adoc` transition decision. He confirms Christian Couder's diagnosis that the format change caused the broken links, but reveals deeper considerations: release notes (RelNotes/*) were specifically kept as `.txt` files since they're written as plain text by Junio himself and not processed by AsciiDoc tooling. 

Junio references his earlier mailing list message where he suggested an extended testing period in the 'next' branch to allow ecosystem tools to adapt, implying the git-scm.com maintainers either didn't notice or didn't act on this window. While acknowledging that keeping RelNotes as `.txt` could temporarily solve this specific issue, he argues against creating a permanent exception to the `.adoc` standard, as it would burden downstream consumers with special cases and might need revisiting if release notes ever adopt AsciiDoc formatting.

The email reinforces that this is fundamentally a git-scm.com infrastructure issue requiring their attention to update link generation logic, while providing important context about the intentional differences in release note formatting and the tradeoffs involved in maintaining documentation consistency versus backward compatibility. No new action is proposed for the Git project itself, as the ball remains in git-scm.com's court to adapt to the already-completed format transition.
