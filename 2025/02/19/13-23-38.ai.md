Performance optimization series for refs subsystem (patch 11/16): This patch implements seeking capability for merged reference iterators, building on the iterator reseeking infrastructure introduced in patch 10/16. The change allows merged iterators (which combine results from multiple underlying iterators) to efficiently reposition their iteration state when checking reference availability.

The implementation introduces separate `iter0_owned` and `iter1_owned` fields to track the underlying iterators' lifetime separately from their active state, since they must persist across seek operations. The patch removes premature iterator freeing in the advance operation and adds a new `merge_ref_iterator_seek()` function that resets both underlying iterators and propagates the seek request to them. This maintains consistency with the iterator lifecycle management from patch 9/16 while enabling the performance benefits of reseeking.

Key technical details include:
- New `iter0_owned`/`iter1_owned` fields to track iterator ownership
- Removal of premature `ref_iterator_free()` calls during advancement
- Implementation of `merge_ref_iterator_seek()` vtable function
- Preservation of existing peel and release functionality
- Backward-compatible extension of the merged iterator API

This change is part of the series' broader effort to optimize reference existence checks, particularly for the reftable backend where reseeking provides significant performance benefits. The patch follows the established pattern of cleanly separating iterator state management from iteration logic while maintaining the series' focus on measurable performance improvements.
