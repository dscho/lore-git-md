Performance optimization for packed-refs iterator reseeking. This is patch 14/16 in a series improving refname availability checks across Git's ref backends. The patch implements the `seek` operation for packed-ref iterators, completing the series' goal of adding reseeking capability to all ref iterator types (following earlier patches for reftable and ref-cache iterators).

The implementation handles prefix matching directly in the `advance()` method rather than using a separate prefix iterator, which ensures proper reseeking behavior when switching between empty and non-empty prefixes. The change removes an optimization that previously returned an empty iterator when no matches were found during initialization, as this would prevent later reseeks from working correctly.

Performance impact isn't measured in this patch alone, but it enables the final optimizations planned in patches 15-16. The implementation follows the pattern established in earlier patches, with careful resource management (freeing old prefix strings) and proper integration with the iterator vtable. The change is relatively focused (62 lines modified) and maintains the existing behavior while adding the new capability.
