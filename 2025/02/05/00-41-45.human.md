This is the final version of a feature series adding extended missing object reporting to `git rev-list`. The patches introduce a new `--missing=print-info` option that shows path and type information for missing objects, building on the existing `--missing=print` functionality.

The key changes in v4:
- Dropped earlier patches about `core.quotePath` configuration after discussion established that standard Git plumbing quoting rules should apply
- Now uses Git's standard `quote_path()` behavior (quoting only for LF, quotes, and spaces)
- Output format is `?<oid> path=<quoted-path> type=<type>` when both path and type are available

The implementation tracks missing objects via an `oidmap` in `builtin/rev-list.c` and includes thorough tests in `t6022-rev-list-missing.sh`. The thread shows clear consensus on the technical approach, with Junio Hamano confirming the plumbing conventions and Christian Couder providing style feedback that's been incorporated.

The author raises an open question about whether a more machine-parseable output format (perhaps using null delimiters or `for-each-ref`-style formatting) might be worth considering in a follow-up series, but this version sticks with the standard quoting approach. The series appears ready for final review, with all previous feedback addressed and tests covering the new functionality.
