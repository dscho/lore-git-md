This is a documentation and usability patch proposing more descriptive long option names for `git log -S` and `git log -G`. The patch follows up on earlier discussion about better naming for these pickaxe-related options.

The author proposes `--patch-modifies` as an alias for `-S` (which searches for changes in the number of string occurrences) and `--patch-grep` for `-G` (which searches patch text with regex). These names aim to be more intuitive than the cryptic single-letter options while avoiding implementation details. The patch updates documentation and tests to use the new names alongside the old ones.

The thread shows some debate about naming - Junio Hamano and Jeff King previously suggested alternatives like `--grep-in-patch` for `-G`. The author argues the `--patch-*` prefix creates better consistency between related options. The changes are straightforward documentation and test updates, with no behavioral modifications.

This seems like a well-motivated quality-of-life improvement. The discussion shows thoughtful consideration of naming tradeoffs, and the patch itself is cleanly implemented. The new names could make these powerful but obscure options more discoverable while maintaining backward compatibility.
