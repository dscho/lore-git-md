This is the second and final patch in a series extending `git rev-list`'s missing object reporting capabilities. It adds type information to the output when using the `--missing=print-info` option, following the format `type=<type>` alongside the existing path information.

The patch builds on the v4 series' consensus to use standard Git plumbing conventions, now showing both path and type for missing objects (except for missing tips which still get no type info). The implementation adds a `type` field to the `missing_objects_map_entry` struct and updates the output formatting. Test coverage in t6022 is extended to verify the type information appears correctly.

This completes the series' goal of providing more context about missing objects, with both patches now following the agreed-upon output format `?<oid> path=<quoted-path> type=<type>`. The changes are straightforward and maintain consistency established in the first patch, making this a clean conclusion to the feature implementation.
