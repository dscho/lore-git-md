This is a documentation and refactoring patch in the `git clone --revision` series, now in its final review cycle. The patch inverts the internal handling of tag cloning from `--no-tags` to `--tags` as the default, making the code more straightforward while maintaining identical behavior. The documentation is updated to clarify that `--tags` is now an explicit (though usually redundant) option that can cancel a previous `--no-tags`.

The change is purely internal at this point - since tags are cloned by default, adding `--tags` has no effect unless it's undoing a `--no-tags`. This prepares the codebase for future changes in the series while keeping the current user experience identical. The patch follows the series' pattern of careful, incremental improvements with thorough documentation updates.
