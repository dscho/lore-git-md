This is the final patch in a 7-part series introducing a `--revision` option for `git clone`. The feature allows cloning a specific ref or commit hash without creating remote-tracking branches, with HEAD detached at the requested revision - particularly useful for CI workflows and targeted repository access.

The patch adds the core implementation, including the `option_rev` parameter and `detach` flag to `struct clone_opts`, configures fetch behavior to only retrieve the requested revision, and includes comprehensive tests. Junio C Hamano provides final review feedback, noting the documentation could be clearer about HEAD behavior in bare repositories (it should be detached) and catching a whitespace issue in the code.

The series has undergone extensive review over six versions, with all technical concerns addressed. Key improvements include robust error handling with `lookup_commit_or_die()`, standardized option parsing, and thorough test coverage. The implementation is now ready for merging, having received sign-off from multiple reviewers including Patrick Steinhardt and Toon Claes.
