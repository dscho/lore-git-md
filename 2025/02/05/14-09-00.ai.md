This is the final approval for the `--revision` clone feature series after five iterations. Junio C. Hamano gives the green light to merge the 7-patch series that introduces a new `--revision` option for `git clone`, allowing cloning of specific refs without creating remote-tracking branches while detaching HEAD at the requested revision.

The series has undergone extensive review and refinement, with all major technical concerns addressed across multiple versions. Key changes in v5 include the introduction of a helper function for option validation (`die_for_incompatible_opt2()`), documentation tweaks, type safety improvements in `wanted_peer_refs()`, and switching to `lookup_commit_or_die()` for more robust error handling. The preparatory refactoring work has significantly improved the maintainability of `builtin/clone.c`.

With this final approval, the series is now queued for integration, marking the completion of a feature that will enable more efficient CI workflows and targeted repository access. The implementation includes comprehensive test coverage in `t5621-clone-revision.sh` and handles edge cases like compatibility with `--depth` while preventing incompatible combinations with `--branch` or `--mirror`.
