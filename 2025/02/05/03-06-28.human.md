This is a bugfix patch addressing an inconsistency in how Git's pull command handles rebase configurations. The issue occurs when `pull.ff=only` is set globally but a specific branch has `branch.<name>.rebase=true` - currently this combination fails when branches diverge, even though the user likely intended rebasing to take precedence for this branch.

The patch modifies the configuration parsing logic in `builtin/pull.c` to distinguish between rebase requests coming from branch-specific config versus the global `pull.rebase` setting. It ensures branch-specific rebase settings can bypass `pull.ff=only` restrictions, similar to how explicit `--rebase` flags already do. The change is accompanied by a new test case verifying the fixed behavior.

The author notes this appears to be a safe change since it makes a failing case work as users would expect, and the test suite confirms no existing behavior is broken. They also suggest future documentation could better explain the complex interactions between pull's various configuration options. The implementation splits the rebase config checking into two functions to maintain clear separation between branch-specific and global rebase settings.
