Refactoring of the clone command's ref mapping logic. This is part 3 of a 7-patch series introducing a new `--revision` option for `git clone` that's now awaiting merge.

The patch simplifies the `wanted_peer_refs()` function in `builtin/clone.c`, which handles mapping remote refs to local ones during cloning. The main change consolidates the single-branch and normal cloning paths into a more straightforward flow. Previously, these were separate code paths with duplicated logic and nested conditions. Now, the single-branch case just modifies the refs list before falling through to the common processing code.

The refactoring maintains all existing behavior while making the code easier to understand. It's a clean improvement that fits well with the series' broader goal of making the clone command more maintainable and flexible. Since this is a later version (v6) of the series, the changes have already been reviewed and refined based on feedback from Patrick Steinhardt and others.
