This thread explored how Git handles configuration precedence between the global `pull.ff=only` setting and per-branch `branch.<name>.rebase` options. The discussion began with a report of unexpected behavior when these settings interacted, prompting several proposed solutions including new configuration variables from Alex Henrie and a middle-ground approach from D. Ben Knoble.

Through careful analysis, Knoble discovered that Git already supported the desired behavior - enforcing fast-forward-only pulls for main branches while allowing rebases on topic branches - through the existing combination of `pull.ff=only`, `pull.rebase=true`, and `branch.<name>.rebase=false`. This configuration, implemented since 2011, was verified through test cases in `t/t5520-pull.sh`.

Junio C Hamano confirmed this resolution, noting that while documentation could be improved to make these interactions more discoverable, no code changes were needed. The thread concluded that Git's current behavior adequately addresses the use case, though Henrie's more comprehensive per-branch controls remain a potential future direction if new requirements emerge. The key takeaway is that careful examination of existing configuration options can often solve problems without introducing new complexity.
