This is a follow-up in a user support thread about Git's content filtering during history rewriting operations. Josef Wolf confirms Brian M. Carlson's earlier explanation about the correct usage of renormalization with rebase, while reporting some edge cases in the suggested workflow.

Key technical details include:
- Confirmation that `--strategy ort -X renormalize` works as a valid alternative to the invalid `--strategy renormalize` syntax
- Reports that the suggested `git add --renormalize` approach works but requires manual intervention when filtered files are involved
- Identifies a limitation with the `-x` automation approach - it fails on commits that don't modify filtered files
- Asks if there's a way to conditionally run the renormalization only when needed during rebase

The email doesn't propose any code changes but surfaces real-world usage patterns and edge cases that might inform future documentation improvements about content filtering workflows. The core technical challenge remains the interaction between Git's content filtering system and history rewriting operations, particularly around when and how to trigger renormalization.
