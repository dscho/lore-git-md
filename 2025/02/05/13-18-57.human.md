This is a brief follow-up to the now-completed series adding missing object reporting to `git rev-list`. The thread had already reached consensus with Christian Couder's ack, but Justin Tobler raises one final consideration about machine parsing of the output format.

Justin notes the current quoted format (`?<oid> path=<quoted-path> type=<type>`) may be challenging for machine parsing compared to using null-delimiters, and floats the idea of a future `--missing=print-info:` format similar to `git-for-each-ref`. Junio Hamano responds by suggesting a simpler alternative - using NUL bytes for field separation when in `-z` mode, keeping the format fixed rather than customizable.

This appears to be a minor post-ack refinement discussion rather than reopening the settled design. The core functionality remains approved and ready, with this exchange simply exploring potential future ergonomic improvements to the machine-readable output format. No changes to the current series are implied - any such format adjustments would be deferred to a follow-up.
