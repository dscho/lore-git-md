This is a technical discussion about performance implications of tracking branch timestamps for Git's branch status messages.

Junio Hamano responds to Patrick Steinhardt's scalability concerns about recording timestamps for remote references. He argues that the performance impact would be minimal compared to the existing cost of fetching references, since modern Git protocols already optimize by only advertising relevant references when fetching specific branches. For users tracking many references, the timestamp overhead would be negligible compared to the fetch operation itself. 

Junio notes that the reftable backend could help mitigate any performance concerns, though he doesn't elaborate on how. His response suggests the timestamp tracking proposal remains technically viable despite Patrick's concerns, though he acknowledges it would be part of larger fetch operations rather than an isolated change.

The exchange highlights the ongoing tension between improving user experience and maintaining performance, particularly for large repositories. Junio's response keeps the door open for timestamp-based solutions while acknowledging the technical constraints Patrick raised. This doesn't resolve the core debate but provides a counterpoint to the scalability concerns.
