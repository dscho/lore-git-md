This is a refactoring patch in the `--revision` clone option series, focusing on simplifying the `wanted_peer_refs()` function in `builtin/clone.c`. The patch eliminates duplicate code paths between single-branch and regular clone operations by restructuring the logic to handle both cases through a common flow.

Key technical changes:
- Removes the separate code path for `option_single_branch` by having it modify the `refs` list before falling through to the shared processing logic
- Introduces a `to_free` pointer to properly manage memory for temporary refs
- Consolidates tag fetching logic with a single `get_fetch_map()` call under clearer conditions
- Maintains all existing behavior while reducing nesting and duplication
- The refactoring builds on Patrick Steinhardt's earlier feedback in the series
- Changes are localized to the clone command's ref mapping logic
- Preserves the special handling for mirror clones and tag fetching
- Uses size_t for refspec iteration counter (a minor but correct type change)

The patch represents a clean-up that improves maintainability without altering functionality, part of the broader effort to prepare the codebase for the new `--revision` feature. The changes have already been reviewed and verified through the series' progression to version 6.
