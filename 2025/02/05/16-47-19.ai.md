This is a refactoring patch in the `--revision` clone option series, specifically addressing tag handling in the clone operation. The patch simplifies the code by moving the tags refspec addition earlier in the clone process, combining it with the main fetch refspec processing rather than handling it separately later.

The key changes are:
1. Moves the tags refspec (`TAG_REFSPEC`) addition to happen alongside the main fetch refspec processing in `cmd_clone()` rather than handling it separately in `wanted_peer_refs()`
2. Explicitly sets `option_tags = 0` when `--mirror` is given, since mirror clones already handle all refs including tags
3. Removes now-unnecessary tag-specific code from `wanted_peer_refs()`, including the temporary `tag_refspec` variable and its cleanup
4. Maintains the same behavior while reducing code duplication and simplifying the control flow

The change is part of a larger effort to clean up and refactor the clone code in preparation for the new `--revision` feature. This particular change helps consolidate refspec handling into a single location rather than having it spread across multiple functions. The patch appears well-contained and focused, with clear commit message explaining both the what and why of the change.
