This is part 5/8 of a bugfix series introducing comprehensive packed-refs validation checks. The patch specifically addresses NUL character detection in refnames within packed-refs files.

The technical core of this patch is a new check for embedded NUL characters in refnames, which could bypass existing validation. The current implementation in `next_record()` calculates refname length by pointer subtraction but could miss NULs within the name. The proposed solution adds detection via `memchr()`, with Patrick Steinhardt suggesting a simplification of the implementation.

Key points from the discussion:
- Patrick recommends inlining the NUL check rather than creating a helper function, arguing the logic is simple and unlikely to be reused
- Shejialuo counters that the check will be needed for future packed-refs validation work
- Both agree that modifying `check_refname_format()` directly isn't feasible due to its C-string interface
- The patch maintains the existing behavior of terminating on invalid refnames, just with expanded detection

The debate centers on implementation style (helper function vs inline) rather than the core validation need, with Shejialuo planning to clarify the reuse motivation in the next version. This fits into the series' broader goal of catching packed-refs corruptions that current validation misses.
