Feature patch series introducing extensible missing object reporting for `git rev-list`.

This is the fourth version of a series that enhances `git rev-list --missing=print` to show additional context about missing objects, including their paths and types when available. The implementation has evolved through discussion to use Git's standard quoting behavior rather than introducing new configuration options.

The series now consists of two patches:
1. Adds a new `print-info` action that shows missing object paths, quoted in C-style when needed
2. Extends this to also show object types, with the output format being `?<oid> path=<quoted-path> type=<type>`

Key technical points:
- Uses existing `quote_path()` plumbing with `QUOTE_PATH_QUOTE_SP` flag
- Drops earlier patches that modified quoting configuration behavior
- Output format designed for machine parsing while handling special characters
- Author notes potential future direction with null-delimited or format-specifier output

The thread shows consensus on the technical approach after addressing feedback from Junio Hamano and others. The implementation now strictly follows Git's plumbing conventions for quoting. The author raises an open question about potentially making the output easier to parse in a follow-up series, suggesting a null-delimited format or `for-each-ref`-style specifiers as alternatives to the current quoted-string approach.

Changes in v4 focus on simplifying the quoting behavior to match standard Git conventions rather than introducing new configuration. The series appears ready for final review with all major design questions resolved.
