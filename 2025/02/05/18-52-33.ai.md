Refactoring patch in the OS version capability series (v4). This is the third of six patches in Usman Akinyemi's post-merge refinement series for the already-merged OS version capability feature.

The patch extracts the `uname(2)` system call handling from `builtin/bugreport.c` into a new `get_uname_info()` helper function in `version.c`, making this functionality available to other parts of Git. The new function maintains the same behavior - collecting system name, release, version and machine information - but now returns an error code (-1) on failure and success (0) otherwise, with the output going to the provided strbuf in either case.

Key technical details:
- Moves implementation from bugreport.c to version.c/version.h
- Adds proper error handling with return codes
- Uses the same strbuf output pattern as other version-related functions
- Maintains existing i18n support for error messages
- Follows the series' pattern of modularizing functionality for reuse

This appears to be a straightforward code organization improvement that:
1) Reduces duplication (preparing for reuse in OS version reporting)
2) Improves error handling consistency
3) Keeps the change focused and mechanical
4) Maintains all existing behavior
5) Follows the series' architectural direction of modular components

The patch builds on Christian Couder's mentoring and the v4 series' focus on code quality improvements through standard library adoption and helper function extraction. It doesn't introduce new functionality but enables cleaner reuse of system information gathering in subsequent patches.
