This is a user support response clarifying how to properly handle history renormalization with Git filters. Brian M. Carlson corrects several misconceptions in the original query about rebase strategies and renormalization options, while providing the correct approach.

The email explains that the error "merge-renormalize command not found" occurs because Git attempts to call a non-existent strategy binary when given `--strategy renormalize`. Carlson notes this is a common pitfall, similar to issues seen with Git LFS. They clarify that neither `--strategy renormalize` nor `-c merge.renormalize=true` are valid Git options.

The key solution offered is to use `git add --renormalize .` within an interactive rebase, suggesting the specific command sequence: `git rebase --root -x 'git add --renormalize . && git commit --amend --no-edit'`. As an alternative approach, Carlson mentions `git filter-repo` might handle this more cleanly and has CC'd its maintainer for potential follow-up.
