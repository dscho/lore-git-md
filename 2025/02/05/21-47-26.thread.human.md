The discussion began with a user encountering issues where their clean/smudge filter setup worked for new commits but failed during history rewriting operations. Through detailed analysis by multiple contributors, the thread first resolved a binary file corruption case (turned out to be an attribute ordering issue) and clarified how Git resolves attributes across subprocesses (thanks to D. Now, Josef Wolf has identified a separate but related problem: their CRLF conversion filter isn't being applied during `git rebase --renormalize`, even though the same setup works for new commits. Careful testing shows the filter is properly configured and attributes are being recognized, yet no CRLF conversion occurs in any revision. This suggests either the filter isn't being invoked during renormalization, its output is being discarded, or there's an interaction with the `-text` attribute that's preventing the conversion.

The thread has narrowed to focus on this remaining CRLF timing issue, with the binary file concerns now understood and closed.
