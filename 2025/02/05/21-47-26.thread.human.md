This thread documents Josef Wolf's ongoing investigation into complex Git behavior involving clean/smudge filters, CRLF conversion, and now file collisions during cloning. The core issue began with failed CRLF conversions during `--renormalize` rebase operations, where a clean filter that explicitly enforces CRLF line endings wasn't working as expected. Torsten Bögershausen has been providing diagnostic guidance, confirming the filter is responsible for the CRLF conversion while ruling out attribute processing issues.

The investigation has now uncovered a new dimension: file collision warnings during cloning on case-sensitive filesystems, involving the same *.ets5hash files that were causing renormalization problems. These files contain application-critical hashes and have a complex history - originally committed as binary blobs, later moved to .gitignore with a smudge filter for regeneration, but occasionally still committed as a backup. Josef suspects these collisions may be interacting with the filter pipeline in unexpected ways during renormalization, though a clear reproduction case hasn't been established yet.

While the binary file handling aspect was resolved earlier (it was a configuration issue), the CRLF conversion failure remains unsolved despite extensive diagnostics. The thread shows how multiple Git features - filters, attributes, renormalization, and case handling - can interact in subtle ways, making this a challenging debugging scenario. Josef continues to lead the investigation with Torsten's guidance, now examining how the newly discovered clone collisions might relate to the persistent renormalization issues.
