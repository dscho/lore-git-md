This is a follow-up discussion about potential machine-readable output formats for `git rev-list`'s missing object reporting feature, which was recently finalized in v4 of the patch series.

Justin Tobler responds to Junio Hamano's suggestion about using NUL bytes for machine parsing, agreeing that a fixed format would be simpler than a customizable one. He proposes a concrete output format where each record is terminated by two NUL bytes, with single NULs separating fields within a record. This would work consistently whether showing regular objects (with `--objects`) or missing objects (with `--missing=print-info`).

The proposed format handles edge cases like paths containing spaces (which would be properly quoted) and maintains consistency with Git's existing plumbing conventions. Justin notes this would be slightly unusual for simple `rev-list` output (just OIDs), but suggests the behavior could be made consistent across all modes. He offers to implement this in a follow-up series if the approach seems reasonable.

This discussion is forward-looking - the already-acked v4 series remains unchanged and ready for merging, with any machine-readable format changes to be handled separately. The exchange shows careful consideration of both parsing needs and Git's existing conventions.
