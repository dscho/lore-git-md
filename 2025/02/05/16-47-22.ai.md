This is the final patch in a 7-part series introducing a `--revision` option to `git clone`. The feature enables cloning a specific ref or commit hash without creating remote-tracking branches, detaching HEAD at the requested revision - particularly useful for CI workflows and targeted repository access.

The patch implements the core `--revision` functionality in `builtin/clone.c` with several key components:
- Adds `option_rev` parameter and `detach` flag to `struct clone_opts`
- Modifies `update_head()` to use `lookup_commit_or_die()` for safety
- Introduces `die_for_incompatible_opt2()` helper for option conflict checking
- Configures fetch behavior to only retrieve the requested revision
- Adds comprehensive test coverage in `t/t5621-clone-revision.sh`

The implementation ensures `--revision` is incompatible with `--branch` and `--mirror` options, and works correctly with `--depth` for minimal clones. The tests verify behavior with various ref types (branches, tags, raw commits) and error cases (invalid refs, option conflicts).

This completes the series which has undergone multiple review cycles and technical verification, with all feedback addressed. The feature provides a clean way to clone specific revisions without the overhead of tracking branches, particularly valuable for automated workflows.
