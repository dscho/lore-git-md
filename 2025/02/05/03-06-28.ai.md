This is a bugfix patch addressing an inconsistency in how Git's pull command handles conflicting configuration options. The issue occurs when `pull.ff=only` is set globally but a specific branch has `branch.<name>.rebase=true` - currently this fails to merge divergent branches, though the user likely intended rebase to take precedence for this branch.

The patch splits the rebase configuration checking into two parts: `config_get_rebase_branch()` for branch-specific settings and `config_get_rebase_pull()` for global pull.rebase settings. This allows branch-specific rebase settings to override `pull.ff=only`, matching the behavior of explicit `--rebase` flags. The change is accompanied by a new test case verifying the fixed behavior.

The implementation builds on prior work from 2021 that established precedence rules between `--rebase` and `pull.ff=only`, but didn't properly account for branch-specific rebase configurations. The author notes this change makes previously failing cases work as users would expect, while maintaining existing behavior for other configuration combinations.

Key technical details:
- Modifies `builtin/pull.c` to split rebase config checking logic
- Adds new test in `t/t7601-merge-pull-config.sh`
- Preserves all existing override behaviors while fixing this specific case
- References previous commits e4dc25ed49 and adc27d6a93 that established related precedence rules

The patch appears well-considered with clear motivation and test coverage. The author acknowledges potential follow-up work to better document the complex interaction between various pull configuration options.
