This is the first patch in a two-part series implementing enhanced missing object reporting for `git rev-list`. The patch adds a new `print-info` action to the `--missing` option that provides additional context about missing objects, specifically their paths when available.

The implementation tracks missing objects using an `oidmap` to store path information, with paths being properly quoted using Git's standard `quote_path()` function (resolving earlier discussion about quoting behavior). The output format is standardized as `?<oid> path=<quoted-path>`, with paths containing spaces or special characters being C-style quoted. The patch includes thorough test coverage in `t6022-rev-list-missing.sh` that verifies the path reporting works correctly, including edge cases with spaces and quotes in filenames.

This represents the finalized version of a feature that has gone through several iterations (now at v4) with all design questions resolved. The implementation follows Junio Hamano's guidance to use standard Git plumbing conventions and has incorporated style feedback from Christian Couder. The patch is cleanly focused on the core functionality, with configuration-related changes having been dropped from earlier versions per mailing list consensus.

The second patch in the series will add type information to the missing object reports. This first part establishes the foundation with a well-tested, consensus-backed implementation that appears ready for merging.
