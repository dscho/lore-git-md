This is the final version of a feature series adding `--revision` to `git clone`, now ready for merging after extensive review. The series enables cloning a specific commit or ref without creating remote-tracking branches, detaching HEAD at the requested revision - particularly useful for CI workflows and targeted repository access.

The v6 iteration focuses on final polish: documentation rewrites for `--[no-]tags` interaction, removal of an unneeded conditional in the error handling helper, and a typo fix in code comments. The series has evolved through six versions with significant refactoring of `builtin/clone.c` to improve maintainability, including moving globals into a `struct clone_opts` and careful handling of edge cases like invalid tree hashes.

Reviewers including Patrick Steinhardt and Jean-Noël Avila have validated the implementation, which now includes comprehensive test coverage, robust error checking with `lookup_commit_or_die()`, and clear documentation. The preparatory refactoring commits (1-6) have already improved the codebase while paving the way for this feature, which Junio Hamano has queued for integration. The final version represents a well-executed addition to Git's cloning capabilities.
