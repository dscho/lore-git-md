This is the second and final patch in a series implementing extensible missing object reporting for `git rev-list`. Building on the first patch which added path reporting, this addition introduces type information for missing objects in the format `type=<type>`.

The patch extends the existing `missing_objects_map_entry` structure to track object types and modifies the output formatting to include this information. The implementation follows the same quoting conventions established in the first patch, using standard Git plumbing behavior. Test coverage in `t6022-rev-list-missing.sh` is updated to verify the type information appears correctly in output.

Key technical details:
- Adds `type` field to `missing_objects_map_entry` structure
- Modifies `add_missing_object_entry()` to accept and store type information
- Updates output formatting in `print_missing_object()` to include type when present
- Maintains consistent behavior for missing tips (type omitted when path is NULL)
- Extends test cases to validate type information appears in output

The patch completes the series' goal of providing detailed missing object information while maintaining strict adherence to Git's plumbing output conventions. With both path and type reporting now implemented, the feature provides comprehensive debugging information for missing objects during traversal.
