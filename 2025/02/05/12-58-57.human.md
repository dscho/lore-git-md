Junio Hamano weighs in on the ongoing `-Wsign-comparison` warning fixes in `apply.c`. While acknowledging some of the type changes are correct (like matching system function return types), he questions the value of aggressively chasing these warnings when they require excessive casting. He specifically pushes back on changing `hexsz` to `size_t`, noting hash algorithm sizes will always fit in an unsigned int. The email suggests the project may need to reconsider how strictly it enforces this warning class, as the current approach generates many mechanical changes for questionable benefit. This represents a higher-level design question beyond the specific technical changes Patrick Steinhardt previously reviewed.
