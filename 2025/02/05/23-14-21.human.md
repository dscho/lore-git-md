This is a response in the ongoing discussion about continuous benchmarking infrastructure for Git performance monitoring. Emily Shaffer from Google expresses strong interest in Patrick Steinhardt's proposal, offering several concrete suggestions and potential contributions from Google's perspective.

Shaffer identifies two key areas where Google could help: first by exploring dedicated GCE compute resources to avoid CI noise problem, and second by sharing performance test results from Android's massive repositories (with appropriate data sanitization). She thoughtfully considers what repository metadata would be most useful to share without exposing proprietary content, suggesting metrics like commit count and object size distributions.

The email also proposes an interesting long-term vision for standardized test repositories that model different scaling challenges ("massive object store", "massive history" etc. This would help isolate performance characteristics more systematically than real-world repos where multiple factors interact.

Shaffer strongly endorses the idea of mailing list alerts for performance regressions, suggesting a practical middle ground where only significant deviations trigger notifications. The response shows both enthusiasm for the initiative and a willingness to contribute engineering resources from Google's side, particularly around Android's use cases which have been hit by recent performance regressions.
