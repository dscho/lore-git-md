Performance optimization for commit mark clearing in `commit.c`

René Scharfe follows up on his earlier optimization patch for `clear_commit_marks_many()`, resending it with no changes from the previous version. The patch restructures how parent commits are processed during mark clearing to reduce peak memory usage from O(n) to O(1) by clearing the parent list after each commit rather than letting it accumulate.

The key change moves the parent list declaration inside the processing loop and clears it immediately after handling each commit, rather than building up one large list across all commits. This maintains the same depth-first traversal behavior while reducing memory pressure. In testing, this reduced the maximum parent list length from 12 to 4.

The discussion has established that this provides modest but measurable memory improvements without performance regressions, though the benefits are more pronounced in edge cases with many disjoint commit histories. While not a dramatic improvement for typical use, the change is clean and has no downsides. The thread remains open awaiting maintainer input on whether the demonstrated benefits justify inclusion.
