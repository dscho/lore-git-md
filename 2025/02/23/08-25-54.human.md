This is a performance optimization discussion regarding commit graph traversal memory usage. René Scharfe responds to Patrick Steinhardt's questions about the practical impact of his earlier patch that restructured `clear_commit_marks_many()` to reduce peak memory usage from O(n) to O(1). 

René acknowledges that while the test suite shows only modest improvements (reducing maximum parent list length from 12 to 4), he maintains there are no downsides to the change. He concedes one could construct pathological cases with disjoint histories, but doesn't expect dramatic real-world impact. The exchange highlights the technical correctness of the change while leaving open whether the memory improvements alone justify merging it.

The discussion has reached a point where both agree the change works as intended, differing only on whether the demonstrated benefits warrant inclusion. René's position is that even small improvements with no drawbacks are worth adopting, while Patrick seems to be looking for evidence of more substantial real-world impact before endorsing the change.
