This is a bugfix and documentation cleanup series for `git merge-tree --stdin`. The primary issue addressed is a deadlock that can occur when using the `--stdin` mode due to missing output flushing between merges. The series also includes various code and documentation improvements noticed during the investigation.

The first patch fixes the core issue by ensuring stdout is flushed after each merge operation when processing input via stdin. This prevents deadlocks in scripts that read and process the output incrementally. The remaining patches clean up redundant code, clarify configuration behavior (only using basic merge config), and improve documentation formatting and clarity.

The changes are focused and well-motivated, with each patch addressing a distinct improvement. The series appears to be a straightforward quality-of-life improvement for users of `merge-tree --stdin`, particularly those using it in scripts. The patches touch both implementation (removing redundant code paths) and documentation (clarifying behavior and fixing formatting).

Key technical details include:
- Fixes deadlock by adding `fflush(stdout)` in `merge_tree_stdin()`
- Removes redundant `merge_incore_recursive()` call in `real_merge()`
- Explicitly states that basic merge config is used (ignoring `merge.renames` etc.)
- Documents `--stdin` behavior more clearly in manpages
- Fixes HTML link formatting in documentation
