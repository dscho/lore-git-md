This is a refactoring patch in Phillip Wood's series addressing deadlock issues in `git merge-tree --stdin`. The patch simplifies the code in `builtin/merge-tree.c` by removing redundant error handling for `real_merge()` results, since the function either succeeds (returning 0 or 1) or dies on error rather than returning negative values. The change eliminates an unnecessary variable and conditional check while maintaining the same behavior, as any failure would already have terminated the program via `die()` inside `real_merge()`.

Key technical details:
- Removes the `result` variable and its associated error check in the stdin processing loop
- Keeps the same control flow since `real_merge()` handles all error cases internally
- Maintains the existing `maybe_flush_or_die()` call after each merge operation
- Part of a larger series focused on stdin mode reliability and documentation

The change is straightforward and uncontroversial, aligning with the thread's focus on cleaning up the merge-tree implementation while fixing the core deadlock issue. It follows naturally from the observation that `real_merge()`'s contract guarantees it will either succeed or terminate the program rather than returning error codes.
