This is the third version of a platform compatibility series addressing `-Wsign-comparison` warnings in `apply.c`. The patch set comes from Zejun Zhao as part of their GSOC work, systematically improving type safety in the patch application logic.

The series has evolved through review rounds, with v3 incorporating feedback to:
1. Change `patch::lines_added/deleted` to unsigned
2. Use `unsigned int` consistently instead of just `unsigned`
3. Separate unrelated changes from the loop counter commit

The changes follow a clear strategy for different warning types - casting `ptrdiff_t` to `size_t`, changing `int` lengths to `size_t` where possible, and using `size_t` loop counters. The author maintains the original logic while eliminating warnings, with careful attention to printf formatting requirements and negative value handling.

Review discussion has raised deeper architectural questions about signed vs unsigned type strategy across related fields, but this version shows good responsiveness to feedback. The changes are well-contained (69 lines modified across apply.c/apply.h) and the commit messages clearly explain the rationale. The series appears technically sound and ready for final consideration, though some broader type consistency questions may warrant follow-up work.
