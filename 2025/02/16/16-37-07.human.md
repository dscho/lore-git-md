This is a small but important cleanup patch in the `merge-tree --stdin` series, focusing on proper configuration initialization for plumbing commands. Phillip Wood points out that `git merge-tree` was incorrectly using `init_ui_merge_config()` (meant for porcelain commands) rather than `init_basic_merge_config()` (for plumbing). While this doesn't currently affect behavior since the merge-ort machinery ignores `diff.algorithm`, the change future-proofs the code against potential changes to the UI configuration.

The patch is straightforward - a one-line change in `builtin/merge-tree.c` that aligns with the plumbing/porcelain distinction established by commit 9c93ba4d0ae. It's a logical follow-up to the earlier work in this thread, maintaining consistency with Git's internal architecture. The change is low-risk (behavior remains identical) but improves code correctness by using the appropriate configuration initialization function for a plumbing command.
