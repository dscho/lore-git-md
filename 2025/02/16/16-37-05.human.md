Bugfix for `git merge-tree --stdin` deadlock issue. This is the first patch in a series addressing stdin mode behavior and documentation improvements.

Phillip Wood identifies a deadlock scenario where `git merge-tree --stdin` can hang if a process tries to read its output before closing stdin. The root cause is that merge-tree doesn't flush stdout between merge operations while processing stdin input. The fix adds a `maybe_flush_or_die()` call after each merge operation to ensure output is properly sent to the parent process.

The patch includes benchmark results showing the flush operation has negligible performance impact (less than 1% difference in runtime). The change is minimal - just two lines added to `builtin/merge-tree.c` to include the write-or-die header and add the flush call.

This appears to be a straightforward fix for a real usability issue, coming from an experienced contributor. The patch is based on the maint branch, suggesting it's intended as a stable fix. Given the clear problem description, minimal change, and performance validation, this seems likely to be accepted without controversy.
