This is a feature proposal for adding commit summary formatting to `git blame`, building on a previous discussion thread. The author, Aleks Todorov, presents a working prototype that adds a `-F/--format` option to `git blame` that reuses Git's existing commit message formatting infrastructure from `git log`.

The implementation currently allows format strings like `%h fname (%an %ad line)` to be passed to `git blame`, producing output where each blame line is prefixed with formatted commit metadata. The patch shows this working with real commit data from `builtin/blame.c`.

The main technical question raised is whether to:
1. Fully reuse `git log`'s formatting code (current approach), which requires input sanitization and width-alignment handling
2. Reimplement a subset specifically for blame, avoiding those complications

The prototype demonstrates the first approach, adding a `user_format` option and hooking into `repo_format_commit_message()`. The changes are minimal - about 20 lines touching the emit logic and option parsing in `builtin/blame.c`.

Key considerations for future discussion:
- The format string` parameter name (`-F/--format`) matches `git log`'s convention
- Output alignment requirements differ between blame and log
- Potential need to restrict certain format specifiers that don't make sense for blame
- Whether this feature's benefits justify the added complexity

The implementation appears functional but preliminary, with clear acknowledgement of open design questions. The author is seeking feedback on architectural direction before proceeding further.
