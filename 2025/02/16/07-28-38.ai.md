Platform compatibility patch addressing `-Wsign-comparison` warnings in the patch application subsystem. This is the first of six patches in v3 of a series that systematically improves type safety in `apply.c` and `apply.h`.

The patch converts several `int` fields to more appropriate unsigned types where they are only used as counters or lengths: `max_change` becomes `unsigned int`, `max_len` becomes `size_t`, and `lines_added/deleted` in the patch struct become `unsigned int`. The changes propagate through related functions like `show_stats()` and `patch_stats()`, requiring explicit casts when interfacing with `printf` format strings (safely bounded to 50 characters).

This aligns with the series' strategy of using `size_t` for lengths/memory sizes and `unsigned int` for line counters, while preserving the existing behavior. The author notes the safety of the `printf` casts due to the known upper bound. The changes are localized to type declarations and their immediate usage sites, with no algorithmic modifications.

Key technical details for future reference:
- Modified files: `apply.c` and `apply.h`
- Changed fields: `apply_state::max_change`, `apply_state::max_len`, `patch::lines_added`, `patch::lines_deleted`
- Type strategy: `size_t` for lengths, `unsigned int` for counters
- printf handling: explicit `(int)` casts for `size_t` values with bounded range
- Related functions affected: `show_stats()`, `patch_stats()`

The patch appears technically sound and follows the established pattern from previous iterations, having incorporated review feedback about type consistency between related fields. The broader architectural discussion about signed vs unsigned strategy (initiated by Junio C Hamano) remains open but doesn't block these specific changes.
