Timezone configuration patch to prevent commit date confusion during DST/timezone changes.

This is a feature proposal to address timestamp inconsistencies that can occur when system timezones change, either due to Daylight Saving Time or manual adjustments (like when traveling). The author notes that while workarounds exist (like `export TZ=UTC0` or commit hooks), these have limitations - IDE integrations may ignore shell settings, and hooks can be bypassed.

The patch suggests adding Git configuration to enforce a specific timezone (or at least UTC) for commit timestamps, preventing the confusing situation where newer commits appear older due to timezone shifts. The author references prior discussions about timezone handling in Git, including the `user.hideTimezone` proposal from 2023.

This appears to be a well-motivated quality-of-life improvement targeting a real pain point, particularly for developers who work across timezones or in DST-observing regions. The proposal acknowledges existing solutions while making a case for a more robust, built-in approach. The implementation details aren't specified in this initial email, suggesting this is more of an RFC than a concrete patch submission.
