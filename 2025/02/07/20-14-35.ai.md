Bug report regarding `git clean -Xdf` behavior with ignored parent directories.

Jan Berges reports unexpected behavior when running `git clean -Xdf` in subdirectories of ignored parent directories. The command appears to clean not just the current directory (as documented) but also parent and sibling directories that are listed in `.gitignore`. The report includes a detailed reproduction recipe showing that when `dir1` is ignored, running `git clean -Xdn` in `dir1/sub1` would attempt to clean `dir1/sub2` (a sibling) while running it in `dir2/sub1` (where only `dir1` is ignored) behaves as expected.

The behavior contradicts the man page's statement that cleaning starts from the current directory, suggesting either a documentation inaccuracy or a bug in the implementation. The report is well-documented with clear reproduction steps and expected vs actual behavior, though it doesn't propose a solution. This could affect users who rely on `git clean` in complex directory structures with ignored paths.
