This is a review comment on patch 9/13 of Patrick Steinhardt's Meson build system refactoring series. The patch improves handling of the `sane_tool_path` option by making it an array of paths rather than a string, allowing it to be used more consistently throughout the build process.

Toon Claes points out a practical issue with the change: it breaks existing build directories where `sane_tool_path` was previously configured as a string (now showing as "[]" in the configuration). He questions whether this should be considered a breaking change, noting that Meson isn't yet the official build method for Git.

The concern highlights a real-world migration problem that users would face when updating to this version. While the technical change itself (making the path handling more consistent) is sound, the backward compatibility impact needs consideration. This is the kind of practical feedback that often surfaces during review of build system changes, where existing configurations and workflows can be unexpectedly affected.
