This is a documentation patch in an ongoing thread about converting Git's documentation from `.txt` to `.adoc` extensions. The email from Junio C Hamano provides historical context and analysis of how `SubmittingPatches` and `CodingGuidelines` are currently processed in the build system.

Junio examines the special handling of `SubmittingPatches` which gets copied to a `.txt` version during build (per commit 049e64aa) to maintain backward compatibility with existing links, while noting that `CodingGuidelines` currently has no such processing. He suggests this difference in treatment may need reconsideration as part of the conversion effort.

Key technical points raised:
- The current build creates both `.html` and `.txt` versions of `SubmittingPatches` via a special Makefile target
- `CodingGuidelines` remains unprocessed by the AsciiDoc toolchain
- Historical rationale for the `SubmittingPatches` handling (link preservation) may no longer apply since most links likely point to `.html` versions now
- Potential inconsistency between how these two key developer documents are processed

The email suggests the thread may need to reconsider:
- Whether to maintain the special `SubmittingPatches` handling
- Whether to bring `CodingGuidelines` into the AsciiDoc processing pipeline
- The broader policy for handling developer documentation in the conversion

This moves the discussion forward by providing concrete historical context while questioning whether past rationales still hold, potentially opening the door to simplifying the build system's handling of these files.
