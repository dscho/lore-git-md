This is part of Patrick Steinhardt's ongoing `the_repository` removal effort, specifically targeting repository infrastructure improvements. The patch moves the "core.hooksPath" configuration from a global variable into `struct repo_settings`, continuing the pattern of eliminating global state to support multiple repository instances and libification.

The change removes `git_hooks_path` from environment.c/h and adds it to `repo_settings`, with a new `repo_settings_get_hooks_path()` accessor that lazily loads the value. This requires modifying the `repo_git_path()` family of functions to accept non-const repository pointers since they now may modify the settings when computing paths. The implementation follows the same pattern as previous settings migrations in this series.

Key technical details for future reference:
- Adds `hooks_path` field to `struct repo_settings`
- Introduces `repo_settings_get_hooks_path()` accessor with lazy loading
- Modifies `adjust_git_path()` and all `repo_git_path*()` variants to take non-const repo pointers
- Updates path computation to use repository-specific hooks path
- Includes the new field in `repo_settings_clear()` cleanup
- Maintains same functional hooks path behavior while removing global state

The change is mechanical and follows established patterns from prior patches in the series, with the expected impact being limited to the repository infrastructure refactoring work. The modification to make repository pointers non-const in path functions may be worth watching for in reviews, though it's a necessary change for the lazy loading behavior.
