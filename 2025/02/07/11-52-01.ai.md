This is a refactoring patch in Patrick Steinhardt's v5 series to decouple the reftable library from Git core infrastructure. The patch modifies `reftable_record_cmp()` to return an error code when comparing records of different types, rather than calling `BUG()`. This change aligns with the series' goal of making reftable usable as a standalone library where fatal errors should be handled gracefully rather than aborting.

The key technical changes are:
- `reftable_record_cmp()` now takes an output parameter for the comparison result and returns an error code (-1) for type mismatches
- All callers in merged.c, pq.c, and test files are updated to handle the new return value
- The priority queue implementation in pq.c is modified to propagate comparison errors
- Test cases are updated to verify the new error handling behavior

The changes affect several reftable subsystems:
- Record comparison logic (record.c/record.h)
- Priority queue operations (pq.c/pq.h)
- Merged iterator implementation (merged.c)
- Unit tests for both record comparison and priority queues

This is part of the systematic replacement of Git-specific behaviors (like `BUG()`) with library-friendly error handling. The patch follows the established pattern of the series and appears technically sound, with thorough test coverage of the modified behavior.
