This is a refactoring patch in a series improving Git's reference transaction system to support partial updates. It moves duplicate refname checking from individual backends (files, packed, reftable) into the generic refs layer, centralizing what was previously backend-specific logic.

The key changes:
- Adds a `refnames` string_list to `ref_transaction` to track all references in a transaction
- Modifies backends to use this centralized list rather than their own duplicate checking
- Maintains special handling for symref updates and HEAD while simplifying the overall flow

Patrick Steinhardt provides review feedback, noting:
1. Questions whether string duplication in the refnames list is necessary since ref_updates already maintain the strings
2. Suggests considering a strset for better efficiency (as a future optimization)
3. Asks why certain HEAD/symref tracking is no longer needed in the files backend
4. Notes the reftable backend change moves a check before the ref addition without clear rationale

The patch significantly reduces code (-116/+50 lines) by eliminating backend-specific duplicate checking while maintaining the same functionality. The changes appear correct but Patrick's questions highlight some areas where the reasoning could be clearer in the commit message or implementation. This is part of a larger effort to enable partial reference updates, with this patch establishing the centralized infrastructure needed for that feature.
