This is the third patch in a 6-part series refactoring Git's reference transaction system to support partial updates, primarily targeting the reftable backend. The patch focuses on removing redundant validation in the files backend.

The change eliminates a duplicate reference name check in the files backend's transaction finish phase, since an identical check already occurs during the prepare stage. The patch:
- Removes 6 lines from files-backend.c by deleting the redundant check
- Makes `ref_update_reject_duplicates()` static since it's now only used within refs.c
- Updates the function's documentation to clarify its narrower scope
- Removes the function's declaration from refs-internal.h

This continues the series' pattern of centralizing refname validation logic in the generic refs layer rather than having each implementation duplicate checks. The change maintains all safety guarantees while reducing code duplication, as the prepare-phase check already ensures no duplicates exist before the finish phase begins. The patch is a straightforward cleanup that doesn't affect behavior, just removes unnecessary work.
