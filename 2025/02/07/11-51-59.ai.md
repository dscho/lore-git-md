This is a refactoring patch in Patrick Steinhardt's v5 series (18 patches) to decouple the reftable library from Git core infrastructure. The patch removes dependency on Git's `COPY_ARRAY()` macro in reftable/record.c, replacing it with direct memory operations.

The change does two main things: first, it replaces `COPY_ARRAY()` with an open-coded `memcpy()` equivalent, continuing the series' pattern of removing Git-specific utilities. Second, it adds a guard around the array copy operation to prevent potential NULL pointer issues when dealing with zero-sized arrays, which could previously trigger an out-of-memory error.

The implementation now includes explicit size checking (using `SIZE_MAX` to prevent overflow) and maintains the same error handling semantics through `REFTABLE_OUT_OF_MEMORY_ERROR`. The change is part of the broader architectural effort to make reftable fully independent of Git's core utilities while preserving functionality.

This appears to be a straightforward, well-contained change that follows the established pattern of the series. The added safety check for zero-sized arrays is a clear improvement over the previous implementation.
