Documentation conversion follow-up discussing special cases in the AsciiDoc transition. This email from Junio C Hamano continues the thread about converting Git's documentation from `.txt` to `.adoc` extensions, focusing on two special cases: `SubmittingPatches` and `CodingGuidelines`.

The discussion reveals that `SubmittingPatches` has a unique build process - it's copied to a temporary `.txt` file for processing while keeping the original extensionless, a solution implemented in 2017 to avoid breaking existing links. Junio notes this contrasts with the current mass renaming approach for other docs, but suggests the web-available HTML versions may now make this precaution unnecessary.

For `CodingGuidelines`, which currently has no extension and isn't processed by AsciiDoc, Junio proposes simply renaming it to `.adoc` to bring it into the standard documentation pipeline, though acknowledges others might prefer maintaining the status quo. The email thoughtfully considers the balance between consistency and backward compatibility, suggesting the project may want to revisit these special cases now that most documentation links likely point to HTML versions anyway.

This is a nuanced addition to the ongoing conversion discussion, highlighting how historical decisions about documentation presentation continue to influence current technical choices. The email doesn't propose specific changes but provides important context for maintainers to consider when finalizing the conversion scope.
