This is a feature patch series introducing partial reference transaction support, primarily targeting the reftable backend but with changes across the refs subsystem. The series aims to allow individual reference updates to fail while letting others proceed, addressing limitations of Git's traditional all-or-nothing atomic transactions. The core change adds a new `--allow-partial` flag to `git-update-ref` for stdin mode, enabling graceful handling of batch reference updates where some may fail.

The series begins with preparatory refactoring - removing duplicate checks in the files backend and consolidating refname validation logic at the generic layer. It then restructures the reftable backend's transaction handling to better support partial updates. The main implementation adds infrastructure for tracking and reporting rejected updates while allowing transactions to proceed, modifying all reference backends to support this behavior when enabled.

Key technical details include modifications to `refs.c` and `refs.h` for the new partial update infrastructure, significant restructuring of `refs/reftable-backend.c` to support partial validation, and the new `--allow-partial` flag implementation in `builtin/update-ref.c`. The changes are well-tested with 191 lines of new tests in `t/t1400-update-ref.sh`.

The motivation focuses on efficiency gains for the reftable backend where batching is important, while maintaining atomic transactions as the default behavior for safety. The series appears carefully structured with logical progression from refactoring to implementation to user-facing changes, suggesting thoughtful design. The extensive test coverage and documentation updates indicate this is a production-ready proposal rather than an RFC.
