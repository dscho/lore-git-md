This is part of Patrick Steinhardt's ongoing `the_repository` removal effort, specifically focusing on path-handling functions. The patch refactors the `repo_worktree_path()` family of functions to provide more consistent interfaces for computing paths into worktrees.

The changes introduce two new strbuf-based interfaces while maintaining the same underlying path computation logic: `repo_worktree_path_append()` for incremental path building and `repo_worktree_path_replace()` for complete path replacement. The existing `repo_worktree_path()` function is kept but now internally uses the new infrastructure. The patch updates callers in repository.c to use the new append variant.

Key technical details include:
- The worktree path computation now consistently returns NULL when no worktree exists
- All variants maintain the same printf-style formatting behavior
- The strbuf-based interfaces provide better memory management patterns
- Documentation in path.h is updated to clearly describe the new interfaces
- The changes affect path.c, path.h, and repository.c

This follows the established three-phase approach seen in previous patches: first unifying interfaces while keeping behavior identical, with later phases to follow for dependency removal and internal restructuring. The patch demonstrates clean migration of existing code to the new patterns while maintaining all existing functionality.
