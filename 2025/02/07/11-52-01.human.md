This is part of Patrick Steinhardt's v5 series (6/18) to fully decouple the reftable library from Git's core infrastructure. The patch converts a `BUG()` call in `reftable_record_cmp()` to proper error handling, continuing the series' systematic removal of Git-specific dependencies.

The change makes `reftable_record_cmp()` return an error when comparing records of different types, rather than aborting. This affects several callers up the stack (merged iterator, priority queue operations) which now need to handle the error. The patch includes thorough updates to the test suite to verify the new error paths.

This is a well-motivated change that follows the series' architectural goal of making reftable usable as a standalone library. The implementation looks clean, with all call sites properly updated and tests covering the new behavior. As part of the mature v5 series that has already addressed major feedback, this patch appears ready for inclusion.
