This is part of Patrick Steinhardt's v5 series (18 patches) finalizing the reftable library's architectural separation from Git core infrastructure. The series systematically replaces Git-specific dependencies with self-contained implementations.

The current patch (11/18) introduces a new `reftable_rand()` function to abstract random number generation, completing the isolation of reftable's system dependencies. The implementation:

1. Adds a new `reftable_rand()` interface in system.h that returns a single unsigned integer
2. Provides a default implementation in system.c that currently wraps Git's `git_rand()`
3. Updates two callsites in stack.c that previously used `git_rand()` directly:
   - One for calculating retry delays during stack reloading
   - Another for generating random suffixes in temporary filenames

The change follows the series' pattern of replacing Git-specific utilities with reftable's own interfaces, though the current version still internally uses Git's random number generator as a transitional step. The interface is designed to allow external callers to provide their own seeded RNG implementations.

This is a straightforward refactoring that maintains existing behavior while advancing the series' goal of complete architectural separation. The patch appears cleanly implemented with appropriate documentation and no functional changes to the random number generation itself.
