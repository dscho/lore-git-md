This is part of Patrick Steinhardt's v5 series (16/18) to finalize the architectural separation of the reftable library from Git core infrastructure. The patch focuses on platform compatibility by reorganizing Windows-specific headers.

The change splits the monolithic `git-compat-util.h` into two parts, moving all POSIX-emulation functionality (541 lines) into a new `compat/posix.h` header while leaving Git-specific utilities in the original file. This separation is key for the reftable library's independence since it needs POSIX compatibility but shouldn't pull in Git-specific code. The patch maintains identical functionality while improving code organization, with the new header containing:
- POSIX feature test macros
- Platform-specific defines (Windows, Solaris, etc.)
- Standard POSIX headers and their compatibility wrappers
- Time/date handling utilities
- Filesystem operations
- Network/socket definitions
- The change is mechanical - moving code between files without functional changes
- Build systems were already updated in earlier patches to handle the new organization
- This completes one of the final steps in making reftable truly standalone

The thread context shows this is the last major organizational improvement needed for clean separation of POSIX functionality from Git-specific utilities, with all major technical feedback from reviewers already addressed in previous iterations. The series is now considered technically complete.
