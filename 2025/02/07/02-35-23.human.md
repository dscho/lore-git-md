This is a discussion contribution to the ongoing thread about `pull.ff=only` and branch-specific rebase configuration conflicts. Alex Henrie responds to D. Ben Knoble's proposal with additional thoughts on configuration precedence and suggests a new approach.

Alex acknowledges the complexity in determining which configuration should take precedence when `pull.ff=only` conflicts with `branch.<name>.rebase=true`, noting that both represent specific but different types of configuration. They then propose introducing a new `branch.<name>.ffOnly` option that would allow per-branch fast-forward enforcement, which could be particularly useful for main branches. As an extension, they suggest a `branch.autoSetupFfOnly` option to automatically apply this setting to new branches.

This suggestion offers a third potential solution path in the thread, complementing the two existing proposals (branch-specific rebase override vs. context-aware safety settings). The idea focuses on making fast-forward enforcement more granular at the branch level rather than trying to resolve the precedence conflict between the existing options. The email doesn't include implementation details but presents the concept as a way to give users more precise control over pull behavior per branch.
