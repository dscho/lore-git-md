This is a refactoring patch in Patrick Steinhardt's v5 series to decouple the reftable library from Git core infrastructure. The patch focuses on error handling in `reftable_record_init()`.

The change replaces a `BUG()` call (which would terminate the program) with proper error handling when an unknown record type is encountered. This is part of making the reftable library more self-contained and suitable for use outside Git. The function now returns `REFTABLE_API_ERROR` for invalid types rather than crashing.

The patch updates all callers to check the return value, including in the block, merged, and reader subsystems, plus several test files. The changes are mechanical but thorough, with each caller now properly handling potential initialization failures. This maintains the series' pattern of removing Git-specific dependencies while adding proper error handling at the library boundary.

Key technical details for future reference:
- Modified function signature: `reftable_record_init()` now returns `int` instead of `void`
- Error code: `REFTABLE_API_ERROR` for unknown record types
- Call sites updated in block.c, merged.c, reader.c, and test files
- Tests now verify successful initialization via `check(!reftable_record_init(...))`
- Maintains compatibility with existing record types (REF, LOG, OBJ, INDEX)

This completes another step in the reftable decoupling by removing a Git-specific `BUG()` dependency while adding proper error propagation through the call chain.
