This is a refactoring patch in Patrick Steinhardt's v5 series (18 patches) to decouple the reftable library from Git core infrastructure. The patch introduces a new `REFTABLE_UNUSED` macro to mark unused function parameters, replacing all existing uses of Git's `UNUSED` macro throughout the reftable codebase.

The change is straightforward - it defines `REFTABLE_UNUSED` in basics.h with the same `__attribute__((__unused__))` implementation as Git's `MAYBE_UNUSED`, then updates 22 instances across 5 files (blocksource.c, iter.c, record.c, writer.c) to use this reftable-specific version instead. The patch follows the series' pattern of removing Git-specific dependencies while maintaining identical functionality.

This appears to be the final step in standardizing the reftable library's unused parameter annotations, addressing a question raised by Toon Claes in earlier review rounds about using `REFTABLE_UNUSED` versus `MAYBE_UNUSED`. The change is mechanical and low-risk, with no behavior modifications beyond the macro rename. It completes another small piece of the larger architectural separation effort.
