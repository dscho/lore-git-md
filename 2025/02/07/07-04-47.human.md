This is a follow-up discussion about const-correctness in the submodule path functions from Patrick Steinhardt's large refactoring series that eliminated `the_repository` usage. 

Karthik Nayak points out an inconsistency in the API design where most repository-aware path functions take a `const struct repository*` parameter, but the submodule path functions take a non-const pointer. Patrick explains this is necessary because the submodule path functions ultimately call `repo_read_gitmodules()`, which needs to modify the repository object to cache the gitmodules data.

The exchange highlights one of the careful tradeoffs made in the refactoring - maintaining API consistency where possible while accommodating real implementation constraints. Patrick notes he'll add this rationale to the commit message for future reference. This is a good example of the post-merge review process helping document the reasoning behind design decisions in a complex refactoring.
