This is part of Patrick Steinhardt's ongoing series to fully decouple the reftable library from Git's core infrastructure. The patch focuses on error handling improvements, specifically removing remaining `BUG()` calls in the reftable code.

The changes replace several `BUG()` assertions with proper error returns using `REFTABLE_API_ERROR`, making the library more robust and suitable for standalone use. Key modifications include:
- Removing `BUG()` checks in reference counting functions where the counter would already be invalid
- Converting an unsupported seek operation to return an error code
- Replacing a block size validation `BUG()` with an error return
- Changing a record type mismatch check to return an error rather than aborting

This patch represents the final step in eliminating Git-specific `BUG()` calls from the reftable library, completing the transition to proper error handling throughout the codebase. The changes are straightforward and follow the established pattern of the series, which has already addressed all major technical feedback from reviewers.
