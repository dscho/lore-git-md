Thread summary:

Bug report concerning unexpected behavior in `git clean -Xdf` when operating in subdirectories of ignored parent directories. Jan Berges demonstrates that the command appears to violate its documented behavior of only cleaning from the current directory, instead also affecting parent and sibling directories that are listed in `.gitignore`. The report provides a clear reproduction case showing that when `dir1` is ignored, running `git clean -Xdn` in `dir1/sub1` incorrectly attempts to clean sibling directory `dir1/sub2`, while the same command in `dir2/sub1` (where only `dir1` is ignored) behaves as expected. This discrepancy between documented behavior (cleaning starts from current directory) and actual behavior (cleaning appears to traverse ignored parent directories) suggests either a documentation inaccuracy or an implementation bug in the `clean` command's handling of ignored directory hierarchies. The report is thorough with clear reproduction steps and expected vs actual behavior analysis, though it does not propose a specific fix. This could impact users who rely on `git clean` in complex directory structures with ignored paths, particularly those using the `-X` flag to clean only ignored files.
