Feature patch completing a series to enable partial reference updates. This final patch in Karthik Nayak's 6-part series adds a `--allow-partial` flag to `git update-ref --stdin`, allowing transactions to continue after individual reference update failures. When enabled, failed updates are reported in a structured format while successful ones proceed. The change builds on earlier infrastructure that added partial transaction support across all ref backends (files, packed, reftable).

The implementation includes thorough documentation updates and extensive test coverage (191 new test lines) for various failure scenarios: invalid OIDs, non-commit objects, missing refs, symref edge cases, and incorrect old-OID checks. The patch maintains backward compatibility by keeping atomic transactions as the default behavior.

This completes the series' goal of enabling more efficient batching for the reftable backend while maintaining consistency across all ref storage formats. The changes appear well-considered, with clear output formatting for failures and comprehensive test coverage of the new failure-reporting path.
