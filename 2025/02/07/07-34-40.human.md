Feature implementation for partial reference transactions, part of a series refactoring Git's reference system to support non-atomic updates.

This patch introduces the core infrastructure for partial reference transactions, allowing individual reference updates to fail while others proceed. The change is motivated by efficiency gains in the reftable backend, where batching updates is important. 

Key technical changes include:
- A new `REF_TRANSACTION_ALLOW_PARTIAL` flag to enable the behavior
- Added `rejected` and `rejection_err` fields to track failed updates
- Modifications to all backends (files, packed, reftable) to handle partial failures
- New `ref_transaction_for_each_rejected_update()` API for inspecting failures

The implementation maintains backward compatibility by keeping atomic transactions as the default. This appears to be a well-structured change that builds on the preparatory refactoring done in earlier patches of the series. The next patch will expose this functionality to users via a `--allow-partial` flag in `git-update-ref`.
