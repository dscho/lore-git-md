This is a refactoring patch in Patrick Steinhardt's ongoing `the_repository` removal effort, specifically addressing worktree path handling. The patch changes `get_worktree_git_dir()` to return an allocated string rather than a static/constant one, preparing for the eventual replacement of `git_common_path()` with `repo_common_path()`.

The key technical change is converting the function's return type from `const char*` to `char*` and making all return paths allocate new strings via `xstrdup()`. This requires updating all 16 call sites to free the returned strings. The patch demonstrates the change across several files including branch.c, fsck.c, and worktree.c, showing the systematic nature of the refactoring.

The rationale explains that while the current implementation avoids allocations by using static buffers, this optimization isn't worth maintaining given that none of the call sites are performance-critical. The change enables future migration to repository-aware path handling while maintaining consistent memory ownership semantics.

This patch follows the established pattern seen in previous path-handling refactors in the series, where interface standardization precedes internal restructuring. It touches core worktree operations but doesn't introduce behavior changes - the focus is purely on memory management consistency in preparation for larger architectural changes.
