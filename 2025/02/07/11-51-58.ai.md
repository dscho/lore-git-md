This is part of Patrick Steinhardt's v5 series (18 patches) to finalize the architectural separation of the reftable library from Git core infrastructure. The patch specifically addresses memory mapping independence by removing the Git-specific `xmmap()` function.

The change replaces `xmmap()` with direct `mmap()` calls in `reftable/blocksource.c`, with proper error handling that returns REFTABLE_IO_ERROR on failure rather than dying. This is part of the broader effort to make the reftable library usable outside of Git by removing dependencies on Git-specific infrastructure. The patch modifies `reftable_block_source_from_file()` to properly propagate errors and clean up resources when mmap fails.

Key technical details:
- Removes last dependency on Git's `xmmap()` wrapper
- Uses standard `mmap()` with MAP_FAILED error checking
- Returns REFTABLE_IO_ERROR instead of dying on failure
- Maintains same functionality while being more robust
- Part of systematic removal of Git-specific error handling
- Follows pattern established in previous patches for I/O independence

The change is straightforward and aligns with the series' goal of complete separation. It builds on previous work to make reftable's memory mapping independent while maintaining the same behavior in success cases. The error handling change makes the code more robust by properly propagating failures rather than crashing.
