This is a refactoring patch that's part of a larger series introducing partial reference transaction support. It removes redundant checks and cleanup in the files backend's reference update handling.

The patch eliminates duplicate validation in `split_symref_update()` where reference names were being checked twice - once for existence in `affected_refnames` and again after insertion. The first check already prevents duplicates, making the second check unnecessary. This leads to simplification of the code by removing the `item->util` field manipulation entirely, since it was only used for this redundant validation.

The changes affect three functions in `refs/files-backend.c`:
- `split_head_update()`
- `split_symref_update()`
- `files_transaction_prepare()`

Key technical details:
- Removes 17 lines while adding 3 (net -14)
- Eliminates all usage of `item->util` in these functions
- Maintains the same safety guarantees through the existing first check
- Part of preparatory work for the larger partial reference transactions feature

This appears to be a straightforward cleanup with no behavior change, well-justified by the commit message. The patch follows the series' pattern of first refactoring existing code before introducing new functionality.
