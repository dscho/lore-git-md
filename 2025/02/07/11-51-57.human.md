This is part of Patrick Steinhardt's v5 series (18 patches) to fully separate the reftable library from Git core infrastructure. The series has already addressed most technical concerns through previous iterations and is now in its final stages.

Patch 2/18 replaces Git's `write_in_full()` with a new `reftable_write_data()` implementation in reftable/stack.c. The change follows the series' pattern of removing Git-specific dependencies - in this case by open-coding the write loop with equivalent functionality while maintaining the same error handling semantics (returning REFTABLE_IO_ERROR on failure). The implementation handles EAGAIN/EINTR retries internally, matching Git's behavior but without the Git dependency.

This is a straightforward mechanical change that continues the architectural separation work. The patch appears well-contained, touching only the expected file and maintaining consistent behavior. As with other patches in this mature series, it builds on established patterns from previous iterations and doesn't introduce new technical concerns.
