This is the first patch in Patrick Steinhardt's v5 series (18 patches) to finalize the architectural separation of the reftable library from Git core infrastructure. The patch removes one of the last Git-specific dependencies by open-coding `read_in_full()` in reftable/stack.c rather than using the Git-provided version.

The change replaces `read_in_full()` with a direct implementation that handles the same basic read loop but omits Git-specific error handling for `O_NONBLOCK` since the reftable library doesn't use non-blocking I/O. The new version maintains the same functionality while reducing dependencies, keeping error handling within the reftable error system (REFTABLE_IO_ERROR).

This is part of the broader effort to make the reftable library fully independent of Git's core infrastructure, enabling its use by external projects. The patch follows the established pattern of the series by carefully replacing Git-specific helpers with equivalent functionality while maintaining the same behaviors needed by reftable. The implementation looks straightforward and well-justified, with a clear explanation of what Git-specific behavior was intentionally omitted (non-blocking I/O handling) and why it's safe to do so.
