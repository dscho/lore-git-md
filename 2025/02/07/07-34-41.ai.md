Feature patch completing the partial reference updates series by adding user-facing `--allow-partial` flag to `git-update-ref`.

This final patch in the 6-part series exposes the partial transaction capability through a new `--allow-partial` flag for `git-update-ref`'s stdin mode. When enabled, failed updates are reported in a structured format while allowing successful updates to proceed. The implementation builds on the refactoring done in previous patches, particularly the `REF_TRANSACTION_ALLOW_PARTIAL` flag and rejection tracking infrastructure.

Key technical details:
- Flag only works with `--stdin` mode (enforced with error)
- Rejection output format matches stdin input format (SP or NUL delimited)
- New `print_rejected_refs` helper formats rejection messages consistently
- 191 lines of new tests covering various failure scenarios (invalid OIDs, symrefs, missing refs)
- Documentation updates explain the new flag and output format
- Maintains backward compatibility - atomic remains default behavior

The patch appears well-integrated with the series' earlier work, completing the user-facing side of the previous backend infrastructure changes. Test coverage is thorough, exercising different rejection cases while verifying successful updates still proceed. The implementation cleanly separates the new partial mode from existing behavior.
