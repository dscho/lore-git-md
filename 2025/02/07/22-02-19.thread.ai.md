Thread summary:

Feature proposal to improve timezone handling in Git commit timestamps, initially motivated by concerns about timezone changes causing apparent commit ordering issues. The discussion has established several key technical points:

1. Git fundamentally stores commit timestamps in UTC, making timezone changes (DST transitions or travel) irrelevant for actual commit ordering. This was confirmed by both Andreas Schwab and Junio C Hamano.

2. The original concern about commit ordering was based on a misunderstanding - Git's UTC storage means the core issue doesn't exist. Any display ordering differences can be addressed using existing `--date=local` viewing options.

3. Brian m. carlson identified multiple technical challenges with proposed solutions:
   - Git doesn't guarantee strict timestamp ordering (rebases can reorder commits regardless of time)
   - Platform-specific timezone handling differences (POSIX vs Windows)
   - Thread-safety concerns with tzset()
   - Recommended system-level solutions (GIT_EDITOR configuration, shell settings) over Git config changes
