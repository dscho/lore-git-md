Bug report about `git clean -Xdf` behavior with ignored parent directories.

Jan Berges reports unexpected behavior when running `git clean -Xdf` in subdirectories of ignored parent directories. The command appears to clean not just the current directory (as suggested by the man page) but also parent and sibling directories that are listed in `.gitignore`.

The report includes a clear reproduction recipe showing that when `dir1` is ignored, running `git clean -Xdn` (dry-run mode) in `dir1/sub1` would remove files from both `sub1` and its sibling `sub2`. In contrast, the same command in `dir2/sub1` (where `dir2` isn't ignored) only affects the current directory's contents.

The behavior seems potentially dangerous as it could lead to unintended data loss when working in subdirectories of ignored paths. The report is well-documented with a complete test case and system information, though it's unclear if this is a bug or undocumented behavior. The man page's description ("starting from the current directory") appears to conflict with the observed behavior.
