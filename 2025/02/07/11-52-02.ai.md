Bugfix and refactoring patch in Patrick Steinhardt's reftable decoupling series. This is patch 7/18 in the v5 iteration, which continues the systematic removal of Git-specific dependencies from the reftable library by eliminating remaining `BUG()` calls in favor of proper error handling.

The patch converts three categories of `BUG()` calls to return `REFTABLE_API_ERROR` instead:
1. Unsupported operations in the indexed table iterator's seek function
2. Reference count checks in reader increment/decrement operations (removed entirely since they would indicate already-freed memory)
3. Writer validation for block size limits and record type mismatches

This change follows the pattern established earlier in the series to make the reftable library safe for external use by avoiding program termination via `BUG()`. The modifications are straightforward - replacing abort conditions with error returns where possible, and removing redundant checks where they would indicate already-corrupt state. The patch maintains all existing functionality while making the error handling more library-appropriate.

The changes affect core reftable operations in iter.c (table iteration), reader.c (reference counting), and writer.c (record validation). This completes the conversion of trivial `BUG()` cases as part of the larger architectural goal of making reftable a standalone library. The patch builds on previous work in the series that already addressed more complex error handling cases.
