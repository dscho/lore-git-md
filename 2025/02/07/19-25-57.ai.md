This is a follow-up discussion about privacy controls for Git's agent capability string, which now includes OS information. The thread had previously settled on extending the existing agent string format rather than adding a new capability, with privacy handled via the existing GIT_USER_AGENT environment variable rather than a new config option.

Usman Akinyemi now proposes reconsidering the privacy approach, suggesting a dedicated config option to completely disable the agent capability would be more user-friendly than requiring GIT_USER_AGENT manipulation. He notes that while GIT_USER_AGENT can suppress the information, it cannot be set to an empty string, making it less convenient for privacy-conscious users. The email seeks Junio Hamano's opinion on whether there are strong reasons to maintain the current environment-variable-only approach or if a config option would be preferable.

Key technical points:
- Current implementation requires non-empty GIT_USER_AGENT for privacy
- Proposed alternative would add a config to disable agent capability entirely
- Discussion centers on user experience vs. design principles
- Junio had previously expressed preference for simpler interface without OS-specific config
- Potential future direction could unify privacy controls under a single mechanism

The thread shows openness to evolving the solution while maintaining the protocol extension's core design.
