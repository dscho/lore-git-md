Feature refinement discussion about agent capability privacy controls.

This is a follow-up email from Usman Akinyemi to Junio Hamano regarding the recently merged OS version capability in Git's protocol. The core feature (adding OS info to the agent string) is already implemented, but Usman is now advocating for an additional privacy control mechanism.

Usman agrees with Junio's earlier position that a separate `transfer.advertiseOSInfo` config isn't the right granularity, but suggests going further by adding a config option to completely disable the agent capability (rather than just the OS portion). His rationale is that while `GIT_USER_AGENT` can currently be used to suppress this information, it's cumbersome since it can't be set to an empty string, and a dedicated config would be more user-friendly and future-proof.

The email maintains a constructive tone, with Usman explicitly seeking Junio's opinion on whether there are strong reasons to keep the current environment-variable-only approach. He also suggests waiting for broader community input if needed. This represents a thoughtful post-merge refinement discussion about balancing functionality with privacy controls, where the core technical implementation is settled but the user interface details are still being polished.
