This thread introduces a performance optimization for reference backend migrations by adding a `--skip-reflog` flag to `git refs migrate`, building on commit 246cebe320 which made reflog migration the default behavior. The change targets server repositories that may have accumulated unwanted reflogs (due to bugs, misconfiguration, or debugging) but don't need them, allowing administrators to skip this costly part of migration.

The implementation adds a `REPO_MIGRATE_REF_STORAGE_FORMAT_SKIP_REFLOG` flag bit and modifies `repo_migrate_ref_storage_format()` to conditionally skip reflog migration. The CLI interface in `builtin/refs.c` gains the new `--skip-reflog` option, while tests in `t/t1460-refs-migrate.sh` verify the behavior. Key technical details include:

- The optimization only benefits repositories that actually have reflogs being skipped (not repositories without any reflogs)
- Core changes are in `refs.c` (migration logic) and `refs.h` (flag definition)
- Test coverage verifies reflogs are properly skipped when requested

Patrick Steinhardt reviewed multiple versions, approving the direction while suggesting refinements: clarifying the commit message about server repositories intentionally skipping reflogs (rather than claiming they don't exist), improving test robustness with `test_line_count` and `test_must_be_empty` helpers, and addressing minor implementation details.
