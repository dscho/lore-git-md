This is part of Patrick Steinhardt's v5 series to decouple the reftable library from Git core infrastructure. The patch introduces a new `reftable_rand()` function to abstract random number generation, replacing direct calls to `git_rand()`.

The change follows the series' pattern of removing Git-specific dependencies by introducing reftable-specific implementations. The new function provides a simple interface that returns a single unsigned integer, with the actual implementation (here still using Git's CSPRNG) to be provided by the calling codebase. This makes it easier for external projects to plug in their own random number generators.

Two existing callsites in the reftable stack code are updated to use the new interface - one for backoff delays during retry operations, and another for generating unique filenames. The implementation currently still relies on Git's `git_rand()` internally, though the interface is now properly abstracted for future external use.

This is a straightforward change that continues the architectural separation work, with no apparent controversy or outstanding issues based on the thread context. The series as a whole appears technically complete, with all major feedback from reviewers already incorporated.
