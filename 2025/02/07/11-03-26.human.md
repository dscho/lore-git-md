This is a refactoring patch that's part of the ongoing effort to remove `the_repository` global. It standardizes the API for constructing paths in Git's common directory (shared across worktrees).

Patrick Steinhardt is cleaning up inconsistencies in how paths are constructed for repository common directories. The patch introduces three new consistent function variants:
- `repo_common_path()` returns an allocated string
- `repo_common_path_append()` adds to an existing strbuf
- `repo_common_path_replace()` overwrites a strbuf's contents

The changes make the API more predictable by clearly indicating whether functions modify or replace buffer contents. The patch updates all callers to use these new functions, including code dealing with loose object maps, ref storage, and worktree management. 

This appears to be a well-considered change that improves API clarity while moving toward the larger goal of repository independence. The commit message thoroughly explains the motivation and new patterns, and the changes are consistently applied across multiple files. As the first in a 16-part series, it lays important groundwork for subsequent patches.
