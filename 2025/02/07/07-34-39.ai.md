Refactoring patch in the reftable partial updates series. This is the fourth of six patches preparing the reftable backend to support partial reference updates, where individual reference updates can fail while others proceed.

The patch extracts the core validation and preparation logic from `reftable_be_transaction_prepare()` into a new `prepare_single_update()` function. This new function handles all the per-reference work: object ID verification, HEAD reference handling, symref processing, and update queuing. The change is purely organizational at this stage - no behavior is modified, but the extracted function will make it easier to implement partial update support in the next patch.

Key technical details include:
- The new function takes parameters for all state needed during preparation (transaction, backend, update object, error buffer)
- It maintains all existing validation checks (object existence, branch type verification, symref handling)
- The error messages and return codes remain identical to preserve compatibility
- The patch moves 240 lines into the new function while deleting 231 lines from the original, showing this is a true 1:1 refactoring

This continues the series' pattern of careful preparation before introducing new functionality, following the earlier patches that centralized refname validation. The commit message clearly states this is groundwork for partial updates, with no functional changes yet.
