This is the first patch in Patrick Steinhardt's v5 series (18 patches) that finalizes the architectural separation of the reftable library from Git core infrastructure. The patch removes one of the last Git-specific functions (`read_in_full()`) from the reftable code by open-coding its functionality.

The change replaces `read_in_full()` with a direct implementation that handles the same basic read operation but omits Git-specific error handling for non-blocking I/O (which isn't needed since reftable doesn't use `O_NONBLOCK`). The implementation maintains the same behavior for normal cases while reducing dependencies on Git internals.

This is a straightforward technical change that aligns with the series' overall goal of making reftable a standalone library. The patch appears well-considered - it preserves the essential functionality while cleanly excising Git-specific code, and the commit message clearly explains both the change and why certain Git-specific parts aren't needed. As the first patch in the series, it sets up the pattern we'll see throughout: carefully replacing Git internals with equivalent standalone implementations.
