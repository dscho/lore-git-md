This is the second patch in a 6-part series introducing partial reference transaction support, focusing on refactoring the refs subsystem to reduce code duplication. The patch moves duplicate refname checking from individual backends (files, packed, reftable) into the generic refs layer.

The key change adds a `refnames` string_list field to the `ref_transaction` struct to track all references in a transaction. This centralizes what was previously backend-specific logic for detecting duplicate refnames. The patch updates all three backends to use this shared field, removing over 100 lines of redundant code while maintaining the same safety checks.

The implementation appears clean and well-motivated as part of the larger series goal to support partial reference updates. The changes are primarily internal plumbing with no user-visible behavior changes at this stage. The patch follows the series' logical progression from refactoring toward new functionality, with this step specifically eliminating duplicate validation code before introducing partial transaction support in later patches.
