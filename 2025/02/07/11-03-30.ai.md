This is part of Patrick Steinhardt's ongoing `the_repository` removal effort, specifically focusing on refactoring submodule path-handling functions. The patch introduces a new family of `repo_submodule_path()` functions to replace the existing `git_pathdup_submodule()` and `strbuf_git_path_submodule()` interfaces, bringing them in line with the established pattern seen in previous path-handling refactors.

The key changes include:
- New public interfaces `repo_submodule_path()`, `repo_submodule_path_append()`, and `repo_submodule_path_replace()` that take an explicit `struct repository*` parameter
- Unlike other path functions in this series, the repository parameter is non-const due to potential modifications by `repo_read_gitmodules()` in the call stack
- Updated callers across builtin/submodule--helper.c, t/helper/test-ref-store.c, and worktree.c
- Maintains the same error handling (-1 for invalid submodules) and path resolution logic while improving memory management through strbuf-based interfaces

This follows the same three-phase approach seen in the already-merged repository path handling series and in-progress worktree path refactoring. The changes demonstrate the same attention to detail and consistency with prior work in this systematic removal of global state dependencies.
