This thread proposes adding timezone configuration for Git commit timestamps to address ordering issues caused by timezone changes. The author identifies a real problem where Daylight Saving Time shifts or travel between timezones can make commits appear out of chronological order, with newer commits sometimes showing older timestamps.

Current workarounds like setting `TZ=UTC0` or using hooks have limitations - they may not work with IDEs or can be bypassed. The proposal suggests either configurable timezone settings or at least a way to universally enforce UTC timestamps, aiming to prevent timestamp inconsistencies without relying on environment variable hacks that might affect other processes.

The author has done their homework, referencing prior discussions about `user.hideTimezone` and recognizing the technical constraints. While the initial message doesn't detail implementation specifics, it clearly frames the problem space and motivation, particularly highlighting the IDE integration challenges that existing solutions don't fully address. This looks like a promising starting point for discussion about improving timestamp consistency in Git workflows.
