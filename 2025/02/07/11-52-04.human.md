Refactoring patch in the reftable decoupling series, replacing Git's endian conversion functions with reftable-specific versions.

This is patch 9/18 in Patrick Steinhardt's v5 series to fully separate the reftable library from Git core. The patch systematically replaces Git's big-endian conversion functions (`put_be16`, `put_be24`, etc.) with reftable-specific versions (`reftable_put_be16`, `reftable_get_be24`, etc.) that follow the library's naming conventions. 

The changes are mechanical but thorough, updating all call sites across the reftable codebase (block handling, reader/writer logic, record encoding) and adding comprehensive unit tests. The new functions maintain identical behavior to their Git counterparts but use `void*` parameters for better type safety. This continues the series' pattern of removing Git-specific dependencies while preserving functionality.

The patch appears well-executed, with test coverage verifying the new implementations match the old behavior. As part of the broader reftable decoupling effort that has already addressed major technical feedback, this change seems uncontroversial and aligns with the series' goal of making reftable a standalone library.
