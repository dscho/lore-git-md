This thread examines unexpected behavior in `git clean -Xdf` when run from subdirectories of ignored parent directories. The original report from Jan Berges demonstrated that the command appears to violate its documented scope by affecting parent and sibling directories listed in `.gitignore`, providing clear reproduction steps showing the discrepancy between expected (current-directory-only cleaning) and actual behavior.

Junio Hamano, the Git maintainer, has now provided important context. He acknowledges the behavior difference but explains it stems from Git's design philosophy where most working tree operations (like `status` and `diff`) treat the entire tree as a single unit, with `git grep` being a rare exception. While not dismissing the documentation mismatch, he frames the current `git clean` behavior as a conscious choice for consistency with other commands rather than a bug. For users needing more precise control, he recommends always previewing operations with `-n` and using explicit pathspecs to limit scope.

The discussion now presents a clear choice: either update the documentation to reflect the actual behavior, or consider changing `git clean` to match its documented scope. Given Junio's emphasis on consistency across commands, documentation updates seem the more likely path forward unless strong counterarguments emerge about the impact on existing workflows.
