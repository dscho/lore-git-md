This is a follow-up discussion in the completed `the_repository` removal series for `git difftool`. David Aguilar clarifies the relationship between two symlink-related fields (`has_symlinks` and `symlinks`) in the newly introduced `struct difftool_options`.

The key revelation is that `has_symlinks` serves a distinct purpose beyond just being a default value for the `symlinks` command-line option. In directory-diff mode, Git intentionally reads symlink contents as text (via `readlink(2)`) regardless of the filesystem's symlink capability, ensuring consistent behavior with `git diff` output. This explains why the fields must remain separate.

David provides historical context from an 8-year-old code comment he apparently wrote (though he jokes about not remembering it), showing this behavior is intentional. He concludes the current implementation is correct as-is and doesn't plan a reroll, though he's open to discussion about potentially renaming the struct or its variable for clarity. The thread shows good-natured collaboration between David and reviewer Elijah Newren, with David demonstrating deep knowledge of the code's historical rationale.
