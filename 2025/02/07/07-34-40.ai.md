This is the fifth patch in a 6-part series introducing partial reference transaction support, primarily targeting the reftable backend while maintaining compatibility with other backends. The series aims to allow individual reference updates to fail while letting others proceed, moving away from Git's traditional all-or-nothing atomic transactions.

The patch implements core infrastructure for partial transactions by:
1. Adding a new `REF_TRANSACTION_ALLOW_PARTIAL` flag that enables the behavior
2. Introducing `rejected` and `rejection_err` fields in `struct ref_update` to track failed updates
3. Modifying all three backends (files, packed, reftable) to handle partial failures by calling `ref_transaction_add_rejection()` instead of aborting
4. Adding `ref_transaction_for_each_rejected_update()` for callers to inspect failures

The changes are comprehensive, touching all backend implementations while maintaining the existing atomic behavior as default. The implementation appears well-structured, keeping validation logic centralized while adding the new partial-failure path. The commit message clearly explains the motivation (reftable efficiency gains from batching) and technical approach.

This foundational change enables the final patch in the series which will expose the functionality to users via a `--allow-partial` flag in `git-update-ref`. The implementation looks thorough, with consistent handling across backends and clear error propagation.
