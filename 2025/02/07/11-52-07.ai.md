This patch is part of Patrick Steinhardt's ongoing reftable library decoupling effort (v5 12/18). It continues the series' systematic removal of Git-specific dependencies by replacing the `sleep_millisec()` function with a direct call to `poll()` in the reftable stack implementation.

The change affects the retry mechanism when reloading reftable stacks, where delays between retries are calculated using the newly introduced `reftable_rand()` (from patch 11/18). The patch notes that while poll() isn't the most direct sleep mechanism, it's the closest POSIX-compliant alternative to millisecond-precision sleeping.

This is a straightforward mechanical change that follows the series' established pattern of replacing Git utilities with direct POSIX calls. The modification is minimal (just one line changed) and maintains the same retry delay calculation logic, now using the reftable-specific random number generator. The change is consistent with the series' goal of making the reftable library fully self-contained.
