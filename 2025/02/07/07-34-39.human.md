This is the fourth patch in a series refactoring Git's reference transaction system to support partial updates, primarily targeting the reftable backend. The patch extracts the core logic for preparing individual reference updates from `reftable_be_transaction_prepare()` into a new `prepare_single_update()` function.

The refactoring consolidates all reference update validation (object ID verification, HEAD reference handling, and symref processing) into a single logical block. This improves code maintainability and readability while maintaining the same functionality - the commit explicitly states there are no behavior changes. The restructuring lays groundwork for implementing partial transaction support in the reftable backend, which will come in subsequent patches.

The changes are substantial (240 lines added, 231 removed) but focused entirely on code organization within `refs/reftable-backend.c`. The patch follows the series' pattern of preparatory refactorings before introducing new functionality, maintaining a clear progression toward the goal of partial reference updates.
