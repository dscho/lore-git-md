This is the v5 cover letter for Patrick Steinhardt's series (18 patches) completing the architectural separation of the reftable library from Git core infrastructure. The series has evolved through multiple iterations addressing build system integration, memory safety, and I/O independence, with all major technical concerns now resolved through rigorous review.

The key change in v5 is the reworked implementation of `REFTABLE_UNUSED` to use `__attribute__((__unused__))` instead of introducing a new macro, addressing feedback from Toon Claes. This resolves the last remaining discussion point from v4. The series now cleanly separates reftable from Git's core utilities while maintaining all functionality through the carefully designed system.h interface.

Build system changes include:
- Final exclusion of reftable from Coccinelle semantic patching (patch 18/18)
- Complete removal of git-compat-util.h dependencies
- Platform-specific header reorganization (Windows/MSVC)
- Memory mapping independence via xmmap() removal
- Error handling converted from fatal errors to returns
- Random number generation abstracted via reftable_rand()
- Sleep functionality using direct poll() calls
- SWAP macro replaced with REFTABLE_SWAP
- UNUSED macro now using MAYBE_UNUSED

The changes enable reftable's use by external projects like libgit2 while preserving Git's internal functionality. The series is technically complete with only header inclusion style remaining as an open question deferred from earlier discussion. The implementation represents a significant architectural milestone in making reftable a standalone library.
