This is part of Patrick Steinhardt's v5 series (18 patches) to finalize the architectural separation of the reftable library from Git core infrastructure. The patch continues the effort to remove Git-specific dependencies by replacing `write_in_full()` with a reftable-specific implementation.

The patch introduces `reftable_write_data()`, a direct replacement for `write_in_full()` that handles the same core functionality (writing all data with retries on EAGAIN/EINTR) but reports errors using the reftable-specific REFTABLE_IO_ERROR. The implementation is straightforward - a while loop that accumulates written bytes until completion or error. The change affects three call sites in stack.c where reftable writes to files.

This is a mechanical change that follows the series' pattern of replacing Git utilities with reftable-specific versions. The thread context shows this is part of the final technical changes needed for full separation, with all major feedback from previous iterations already addressed. The only remaining open question appears to be header inclusion style, which this patch doesn't touch.
