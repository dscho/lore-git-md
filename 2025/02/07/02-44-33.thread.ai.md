Git config file race condition on Windows

Bug report from Allen Li describing platform-specific race conditions in Git's config file handling where concurrent reads (e.g. `git rev-parse`) and writes (`git config`) on Windows lead to "Permission denied" errors and fatal "unknown error" messages - behavior not seen on Linux. Patrick Steinhardt clarifies that while his atomic rename work (merged for Git 2.48.0) addressed part of the problem, complete resolution requires two components: POSIX-style rename support and proper file handle sharing flags. The current issue stems from Windows-specific limitations in file handle management where `fopen()` implementations don't use `FILE_SHARE_DELETE`, preventing atomic renames when files are open.

Technical details identified:
- `_wfopen()` lacks `FILE_SHARE_DELETE` support
- Alternative `_wfsopen()` also insufficient for delete sharing mode
- Full solution would require reimplementing file opening using `CreateFileW()`

This is confirmed as a known limitation in Windows implementation rather than a regression, affecting all config file operations where readers might hold open file handles during writes. The path forward involves low-level Windows API work to properly support atomic operations during concurrent access. No immediate solution proposed yet, but the technical constraints are now clearly identified.
