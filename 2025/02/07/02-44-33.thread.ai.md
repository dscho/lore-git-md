Git config file race condition on Windows

Bug report from Allen Li describing platform-specific race conditions in Git's config file handling where concurrent reads (e.g. `git rev-parse`) and writes (`git config`) on Windows lead to "Permission denied" errors and fatal "unknown error" messages - behavior not seen on Linux. The issue persists in Git 2.28 RC despite Patrick Steinhardt's atomic rename work for lockfiles (merged for 2.28), suggesting the atomic rename may still allow readers to see incomplete config states during the operation. Affects all commands reading config, not just the test case shown. Reproduction steps provided demonstrate consistent failure while Linux handles the same concurrent operations correctly. Windows-specific issue with potential impact for any Windows user running concurrent Git operations, though severity is currently unclear. No proposed solution yet - seeking help understanding and fixing the Windows-specific behavior.
