This is part of Patrick Steinhardt's ongoing `the_repository` removal effort, specifically targeting path handling refactoring. The patch removes the `git_common_path()` function in favor of `repo_common_path()` variants, continuing the systematic elimination of implicit `the_repository` dependencies.

Key technical changes:
- Removes `git_common_path()` which used rotating static buffers, replacing it with `repo_common_path()` that returns heap-allocated strings requiring explicit freeing
- Updates 16 call sites across worktree operations to handle new memory management
- Makes `repo_common_pathv()` private since it's no longer needed in the public API
- Maintains identical path computation logic while standardizing allocation patterns
- Follows the established three-phase refactoring approach seen in prior path handling changes

The patch affects worktree operations including locking/unlocking, validation, and path repairs. Callers now must free returned strings, with careful attention to error paths. This continues the pattern seen in earlier path refactors (like `git_pathdup()` removal), demonstrating consistent architectural approach across the codebase.

The changes are mechanical but thorough, with all affected call sites updated to handle memory ownership properly. This represents another incremental step in the larger effort to remove global state dependencies, with worktree operations now aligned with the repository path handling standards established earlier in the series.
