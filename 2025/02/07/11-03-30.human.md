This is part of Patrick Steinhardt's ongoing `the_repository` removal effort, specifically refactoring submodule path-handling functions. The patch continues the systematic approach seen in previous path-handling refactors, now applying it to submodule operations.

The patch introduces new `repo_submodule_path()` family of interfaces that take an explicit `struct repository*` parameter, replacing the old `git_pathdup_submodule()` and `strbuf_git_path_submodule()` functions. The new functions follow the established pattern of providing three variants: one that returns a newly allocated string, and two strbuf-based variants for appending or replacing path components.

A notable difference from other path-handling refactors is that the repository parameter must be non-const, since submodule path computation may need to modify the repository state when reading gitmodules. The patch updates callers across several files while preserving the existing error handling (-1 for invalid submodules) and core path resolution logic.

This appears to be a well-structured continuation of the established refactoring pattern, with careful attention to maintaining behavior while removing implicit dependencies on `the_repository`. The changes are consistent with the already-merged repository path handling series and in-progress worktree path refactoring.
