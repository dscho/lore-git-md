This is a refactoring patch in Patrick Steinhardt's v5 series (18 patches) to decouple the reftable library from Git core infrastructure. The patch specifically targets array allocation utilities in reftable/basics.h.

The change replaces Git's `st_mult()` helper with a new `reftable_alloc_size()` function that performs overflow checking and returns errors rather than dying. This affects three macros: `REFTABLE_ALLOC_ARRAY`, `REFTABLE_REALLOC_ARRAY`, and the inline `reftable_alloc_grow()` function. The new implementation:
- Adds explicit overflow checking via `reftable_alloc_size()`
- Returns NULL with ENOMEM on overflow rather than aborting
- Maintains the same allocation patterns but with error handling
- Preserves the doubling growth strategy in `reftable_alloc_grow()`

This continues the series' pattern of removing Git-specific dependencies while improving error handling. The change is consistent with previous patches that replaced other Git utilities (like `COPY_ARRAY`, `xmmap`, and `BUG()` calls) with reftable-specific implementations. The patch appears technically sound, following the established approach of the series, and doesn't introduce any new patterns or dependencies.

Key technical details for future reference:
- New function: `reftable_alloc_size(nelem, elsize, out)` returns -1 on overflow
- Error handling via NULL return + errno = ENOMEM
- Macros modified: REFTABLE_ALLOC_ARRAY, REFTABLE_REALLOC_ARRAY
- Function modified: reftable_alloc_grow()
- File: reftable/basics.h
- No behavior change when allocations succeed
- Follows series pattern of replacing Git utilities with library-safe versions
