This is a feature series introducing partial reference transaction support to Git's refs subsystem. Karthik Nayak proposes adding a new `--allow-partial` flag to `git-update-ref` that allows some reference updates in a batch to fail while others succeed, rather than requiring all updates to succeed atomically as is currently the case.

The series starts with preparatory refactoring to clean up duplicate reference update checks and consolidate validation logic, particularly in the files and reftable backends. The core change then modifies the refs subsystem to track and report rejected updates while allowing transactions to proceed when partial updates are enabled. The reftable backend sees significant restructuring to support this new capability efficiently.

The final patch exposes this functionality through `git-update-ref --allow-partial` in stdin mode, where batching updates is most useful. The commit messages are thorough and the series includes comprehensive test coverage. This appears to be a carefully constructed enhancement that could benefit tools needing more flexible reference update handling, particularly with the reftable backend where batching provides performance advantages. The changes maintain atomic behavior by default while adding an opt-in mode for partial updates.
