This is a refactoring patch in a series introducing partial reference transaction support, specifically moving duplicate refname checking from individual backends to the generic refs layer. The patch centralizes the tracking of refnames in a new `refnames` string_list field within `ref_transaction`, eliminating redundant validation code across the files, packed, and reftable backends.

Key technical changes include:
- Adding `refnames` to `ref_transaction` to track all references in a transaction
- Modifying `ref_transaction_add_update()` to populate this list (except for REF_LOG_ONLY updates)
- Moving duplicate checking to `ref_transaction_prepare()` in refs.c
- Removing backend-specific duplicate checking from files-backend.c (17 lines removed), packed-backend.c (25 lines removed), and reftable-backend.c (53 lines modified)
- Updating symref and HEAD splitting logic to use the centralized list

The changes maintain all existing safety guarantees while reducing code duplication. The reftable backend sees the most significant restructuring, with its duplicate checking now happening before reference addition rather than after. This appears to be a well-executed preparatory step for the larger partial transaction feature, with thorough updates to all affected backends and no obvious gaps in the validation logic.
