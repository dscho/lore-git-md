Bug report and potential fix for segmentation faults in `git difftool --dir-diff` during hashmap cleanup. The issue manifests in two distinct failure modes (SIGSEGV and SIGABRT with "free(): invalid pointer") occurring in `run_dir_diff()` from `builtin/difftool.c` when `hashmap_clear_()` calls `free_individual_entries()`. Backtraces indicate memory corruption during deallocation in glibc's arena management, reproducible on fresh repositories using Git 2.47.2 from Debian unstable. Christian Couder suggests commit 98e4015593 ("builtin/difftool: initialize some hashmap variables") from v2.48.0 likely fixes this by addressing uninitialized hashmap variables that were causing memory corruption during cleanup. The original reporter's detailed reproduction case (including kernel logs and GDB outputs) showed consistent crashes at the same points in the cleanup path, making this a high-confidence diagnosis. While verification from the original reporter is still needed, this appears to be a straightforward case of initialization oversight now resolved in current releases. The thread demonstrates effective issue tracking from initial report to probable solution, with the fix already merged upstream in v2.48.0. Users experiencing this issue should upgrade to Git 2.48.x or later.
