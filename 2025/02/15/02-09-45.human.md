This is a bug report about segmentation faults in `git difftool --dir-diff`. Christoph Anton Mitterer reports consistent crashes when running the command, both in a fresh empty repository and in a repository with staged changes. The crashes manifest in two ways: either as a SIGSEGV (signal 11) with a backtrace showing memory corruption in libc's free() called from Git's hashmap.c, or as a SIGABRT (signal 6) with "free(): invalid pointer" from the same code path.

The backtraces consistently point to problems during hashmap cleanup in `run_dir_diff()`, specifically when `hashmap_clear_()` calls `free_individual_entries()`. The issue appears immediately reproducible with just `git init` followed by `git difftool --dir-diff`, suggesting a fundamental problem in the command's initialization or cleanup path rather than something specific to the repository contents.

The reporter is using Git 2.47.2 from Debian unstable, and has provided detailed debugging information including kernel logs and GDB backtraces from multiple crash scenarios. The problem looks like a serious memory management bug that could affect any user of `git difftool --dir-diff`, making this a high-priority issue for the Git maintainers to investigate.
