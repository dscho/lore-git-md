Bug report for a segmentation fault in `git difftool --dir-diff`. The reporter observes two related crash scenarios when running the command on fresh repositories: one producing SIGSEGV (signal 11) and another producing SIGABRT (signal 6) with a "free(): invalid pointer" message. Both crashes occur during hashmap cleanup in `run_dir_diff()`, specifically when `hashmap_clear_()` calls through to `free_individual_entries()`.

The backtraces show the crashes originate in glibc's memory management when attempting to free memory, suggesting memory corruption or double-free issues. The reporter provides detailed reproduction steps showing the issue occurs even in an empty repository, and includes kernel logs and GDB session outputs showing the crash occurs consistently at the same points. The crashes happen with Git version 2.47.2 from Debian unstable.

Key technical details for future reference:
- Crash occurs in `builtin/difftool.c`'s `run_dir_diff()` function
- Involves hashmap cleanup operations in `hashmap.c`
- Two distinct failure modes observed: SIGSEGV and SIGABRT with invalid pointer message
- Reproducible on fresh repositories with just `git init`
- Debian package version 1:2.47.2-0.1 affected
- Backtraces consistently show crashes during memory deallocation in glibc's arena management

The report is thorough with multiple reproduction scenarios and debugging outputs, suggesting a genuine memory management issue in the dir-diff implementation that warrants investigation. The fact it crashes on empty repositories makes it particularly concerning as a potential widespread issue.
