This is a build system patch that standardizes default target declarations across Git's Makefiles, following up on earlier discussion about fixing a documentation build regression.

Adam Dinwoodie's v2 patch implements Junio Hamano's suggested approach for making default build behavior more explicit and consistent. The core issue stemmed from commit a38edab7c8 which accidentally changed the Documentation/Makefile's default target to only build config files rather than full documentation. The solution here adds empty `all::` rules at the top of 15 different Makefiles (including the problematic Documentation one) while converting existing single-colon `all:` rules to double-colon form.

The changes are mechanical but important for maintainability - they ensure consistent behavior when running plain `make` across the codebase while following established patterns from t/Makefile and the main Makefile. The patch appears well-scoped, touching only the minimal syntax needed to establish explicit default targets without altering actual build logic. With Junio's prior approval of the approach and no outstanding technical concerns, this looks ready for inclusion.
