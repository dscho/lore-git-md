Bugfix follow-up regarding `git difftool --dir-diff` segfaults. Christian Couder responds to a detailed bug report about segmentation faults occurring during hashmap cleanup in directory diffs, suggesting the issue may already be fixed in Git 2.48.x. The original report showed two distinct crash modes (SIGSEGV and SIGABRT) during `run_dir_diff()` cleanup, with backtraces pointing to memory corruption in glibc's arena management when `hashmap_clear_()` calls `free_individual_entries()`. 

Christian points to commit 98e4015593 ("builtin/difftool: initialize some hashmap variables") from v2.48.0 as the likely fix, recommending the reporter upgrade from their current Debian unstable package (1:2.47.2-0.1). The response doesn't confirm the fix but positions it as the most probable solution given the timing and area of code affected. This appears to be a straightforward case of uninitialized hashmap variables leading to memory corruption during cleanup, now addressed in recent releases. The thread shows good issue tracking from initial report to potential resolution, though verification from the original reporter would be needed to confirm the fix works for their specific case.
