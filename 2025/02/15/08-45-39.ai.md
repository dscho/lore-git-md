Refactoring of refspec matching code with improved naming and documentation. This is the second version of a patch that renames `match_name_with_pattern()` to `match_refname_with_pattern()` and updates parameter names to be more descriptive, following feedback from Junio Hamano in the thread.

Key changes in v2:
- Renamed parameters from `src_pattern/dst_pattern` to `pattern/replacement` to better reflect the function's bidirectional nature (handling both push and fetch operations)
- Updated error messages and documentation comments to match the new terminology
- Maintained all existing functionality while improving clarity

The function remains central to refspec matching logic, handling glob patterns for both push and fetch operations while optionally computing destination refnames. Changes affect refspec.c, refspec.h, and remote.c, with no behavioral modifications - this is purely a naming/documentation improvement.

The thread shows active discussion about optimal terminology, with Hamano previously objecting to "src/dst" as misleading for bidirectional operations and proposing "pattern/refname/replacement" naming instead. This patch incorporates that feedback while maintaining the core goal of making the code's purpose clearer through better naming.
