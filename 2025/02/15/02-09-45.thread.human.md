This thread documents a bug in `git difftool --dir-diff` that caused segmentation faults (SIGSEGV) or abort signals (SIGABRT) during hashmap cleanup, particularly affecting users of Git 2.47.2 from Debian unstable. The issue stemmed from uninitialized hashmap variables in `run_dir_diff()` that led to memory corruption when freeing entries.

Christian Couder initially identified that commit 98e4015593 ("builtin/difftool: initialize some hashmap variables") in Git v2.48.0 likely fixed the problem. René Scharfe has now confirmed this diagnosis, verifying that the fix properly addresses the memory corruption issue. The bug manifested in two distinct failure modes during cleanup, both traceable to the same root cause.

The resolution is straightforward: users experiencing these crashes should upgrade to Git 2.48.0 or later. This thread shows an effective path from detailed bug report (including reproduction cases with kernel logs and GDB outputs) to confirmed solution, with the fix already available in current releases. No further action is needed beyond upgrading for affected users.
