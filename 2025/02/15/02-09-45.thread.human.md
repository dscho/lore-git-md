This thread documents a bug report and potential fix for segmentation faults in `git difftool --dir-diff`. The original reporter encountered two distinct crash modes (SIGSEGV and SIGABRT) during hashmap cleanup in the directory diff implementation, with backtraces pointing to memory corruption in glibc's arena management. The issue was reproducible even in fresh repositories using Git 2.47.2 from Debian unstable.

Christian Couder has suggested the problem may already be resolved in Git 2.48.x, pointing to commit 98e4015593 ("builtin/difftool: initialize some hashmap variables") as the likely fix. This indicates the root cause was uninitialized hashmap variables leading to memory corruption during cleanup. While the fix hasn't been confirmed by the original reporter yet, the timing and code area match the reported symptoms. The thread shows clear progress from detailed bug report to identified solution, with the recommendation being to upgrade to version 2.48.0 or later where the fix is included.
