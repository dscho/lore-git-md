This is a follow-up in the thread about segmentation faults in `git difftool --dir-diff`. René Scharfe confirms that the issue is a known bug that was fixed in commit 98e4015593 ("builtin/difftool: initialize some hashmap variables"), which shipped in Git v2.48.0. The bug caused memory corruption during hashmap cleanup, leading to either SIGSEGV (signal 11) or SIGABRT (signal 6) errors when running directory diffs. The fix addressed uninitialized hashmap variables that were triggering these crashes. This matches the diagnosis previously suggested in the thread by Christian Couder. The solution is straightforward - users experiencing this issue should upgrade to Git 2.48.0 or later. The thread demonstrates effective issue resolution, with the problem being identified, diagnosed, and fixed in a recent release.
