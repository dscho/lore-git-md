This is the final version of a 7-patch series introducing a new `--revision` option for `git clone`. The feature allows cloning a specific ref or commit hash without creating remote-tracking branches, detaching HEAD at the requested revision - particularly useful capability for CI workflows and targeted repository access.

The series has undergone extensive review and refinement over six previous versions, with all substantive feedback addressed. The current version incorporates final documentation improvements suggested by Junio Hamano (clarifying bare repository behavior) and copyediting from Jean-Noël Avila. The implementation includes comprehensive test coverage in t5621-clone-revision.sh and handles edge cases like invalid revisions and option conflicts.

Key technical components include:
- New `struct clone_opts` encapsulating clone state
- Modified `update_head()` using `lookup_commit_or_die()`
- Refactored remote-tracking refspec handling
- New `die_for_incompatible_opt2()` helper for option parsing
- Explicit documentation of behavior with `--[no-]tags` and bare repositories

The preparatory refactoring commits (1-6) systematically improved `builtin/clone.c` maintainability while paving the way for the feature. The final version represents a complete, well-tested implementation that meets Git's standards for both code quality and documentation. The series is now queued for integration by Junio Hamano.
