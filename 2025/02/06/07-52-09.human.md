This is part 7/18 of Patrick Steinhardt's series to fully decouple the reftable library from Git's core infrastructure. The patch continues the effort to remove Git-specific error handling by replacing remaining `BUG()` calls with proper error returns.

The changes focus on three areas: the iterator interface, reader reference counting, and writer validation. In the iterator case, seeking an indexed table now returns `REFTABLE_API_ERROR` rather than aborting. For reader refcounting, the `BUG()` checks are removed entirely since they guarded against cases that would already indicate undefined behavior. The writer validation now returns errors for invalid block sizes and type mismatches rather than aborting.

This patch represents the final removal of `BUG()` from the reftable library, completing the transition to proper error propagation that was started earlier in the series. The changes are straightforward and maintain the same safety properties while making the library more suitable for standalone use. With all major technical concerns already addressed in previous rounds of review, this appears ready for integration.
