This patch continues Patrick Steinhardt's v4 series (11/18) to fully decouple the reftable library from Git core infrastructure. It introduces a new `reftable_rand()` function to replace Git's `git_rand()` calls within the reftable code, maintaining the architectural separation goal.

The change:
- Adds `reftable_rand()` in system.c (with Git's `git_rand()` as initial implementation)
- Updates two callsites in stack.c that previously used for:
  * Exponential backoff delay calculation
  * Random suffix generation in tempfile names
- Follows the established pattern of replacing Git-specific utilities with reftable equivalents

The implementation currently still depends on Git's CSPRNG internally, though the interface is now abstracted to allow future seeding control. This is a straightforward replacement that maintains identical behavior while progressing the series' goal of complete reftable independence. The change is low-risk as it only affects debug/retry paths and tempfile naming.
