This is part 7/8 of a bugfix series adding validation for packed-refs files. The patch implements sortedness verification when the packed-refs file declares itself as sorted in its header.

The change adds a new fsck check that verifies refnames are in sorted order when the "sorted" trait is present in the packed-refs header. The implementation reuses existing comparison logic rather than storing all refnames, keeping memory usage efficient. A new fsck error (FSCK_MSG_PACKED_REF_UNSORTED) reports violations, with tests demonstrating both error cases and proper handling of unsorted files.

The patch builds on previous work in the series by:
1. Extending header parsing to detect the "sorted" trait
2. Adding a new fsck_packed_ref_entry struct to track line numbers
3. Reusing existing refname comparison logic via a new helper function
4. Only performing the check when explicitly requested via the header

Test coverage verifies both error cases (where refs are out of order in a sorted file) and the non-error case (where an unsorted file is allowed to remain unsorted). The implementation appears thorough and well-integrated with the existing packed-refs validation framework.
