This is part 11/18 of Patrick Steinhardt's series to fully decouple the reftable library from Git core infrastructure. The patch introduces a new `reftable_rand()` function to replace Git's random number generation, continuing the pattern of replacing Git-specific utilities with reftable-specific implementations.

The change wraps Git's existing `git_rand()` function in a new reftable-specific interface, with the intention that callers could eventually provide their own RNG implementation. The patch updates two call sites in the reftable stack implementation where random numbers are used - for backoff delays during retries and for generating unique filenames.

This is a straightforward change that follows the established pattern of the series, replacing Git-specific functionality while maintaining the same behavior. The implementation currently still depends on Git's RNG internally, which may be replaced in a future step. The change is low-risk as it only affects debug/auxiliary functionality (retry delays and tempfile naming) rather than core reftable operations.

The series as a whole has been through rigorous review, with all major technical concerns addressed in previous iterations. This patch continues the clean architectural separation work with no new technical concerns raised.
