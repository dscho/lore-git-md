This is a refactoring patch in Patrick Steinhardt's v4 series to fully separate the reftable library from Git core infrastructure. The patch focuses on removing the last Git-specific dependency by eliminating the use of `BUG()` in `reftable_record_init()`.

The change converts the function to return an error code (REFTABLE_API_ERROR) instead of aborting when encountering an unknown record type, which previously caused a hard dependency on Git's error handling infrastructure. The patch updates all call sites to properly handle the potential error condition, including block.c, merged.c, reader.c, and several test files.

This is part of the broader architectural effort to make reftable fully independent of Git's core utilities. The change maintains memory safety while removing one of the final Git-specific dependencies. The patch follows through on the series' goal of making reftable a standalone library by addressing error handling at the API boundary rather than relying on Git's internal abort mechanisms.

The modification is straightforward and mechanical, with each caller now explicitly checking the return value. Test coverage remains intact, with unit tests updated to verify the successful initialization path. This represents another incremental step toward complete reftable independence, with all major technical concerns having been addressed in prior reviews.
