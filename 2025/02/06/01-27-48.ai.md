Bugfix for `git-p4` Python interpreter path issue. This email reports a problem where `git p4` commands fail on systems where Python isn't in the default PATH, due to the script's shebang line pointing to `python` rather than `python3`. The reporter found a workaround by manually changing the shebang to `python3` and suggests this should be updated since Python 3 is now the standard.

The issue manifests when running `git p4 clone`, producing an error suggesting the command is broken when it actually fails due to the missing Python interpreter. The reporter provides clear reproduction steps and system information showing this occurs on a Debian system with Git 2.30.2. While the immediate problem is a PATH issue, the underlying concern is about modernizing the script's Python version dependency.

This appears to be a legitimate compatibility issue that would affect users on systems where `python` isn't symlinked to Python 3 (common in modern distributions). The fix would involve updating the shebang line in `git-p4` to explicitly use `python3`, which would be a straightforward change but may need consideration for backward compatibility with systems still using Python 2.
