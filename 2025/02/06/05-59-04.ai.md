This is part 4/8 of a bugfix series enhancing packed-refs validation, specifically focusing on header consistency checks. The patch introduces validation for the `packed-refs` file header format, ensuring it starts with the correct "# pack-refs with:" prefix if present.

Key technical elements:
- Adds `packed_fsck_ref_header()` to verify header format matches "# pack-refs with:"
- Implements `packed_fsck_ref_next_line()` helper to handle newline termination checks
- Introduces two new fsck error messages: `badPackedRefHeader` and `packedRefEntryNotTerminated`
- Maintains backward compatibility by not requiring headers (supporting older Git versions)
- Adds test cases verifying proper rejection of malformed headers while allowing valid variations

The implementation carefully preserves runtime behavior while adding validation, following the same approach used in `create_snapshot()`. Test coverage includes multiple invalid header patterns to ensure robust validation. This builds on previous feedback from Patrick Steinhardt and Karthik Nayak, with the implementation now handling edge cases like missing newlines while maintaining the series' focus on comprehensive packed-refs integrity checking.
