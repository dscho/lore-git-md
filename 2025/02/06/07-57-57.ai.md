This is the first patch in a 16-part refactoring series targeting path-handling subsystems as part of the broader `the_repository` removal effort. The patch focuses on standardizing the `repo_common_path()` family of functions that handle paths in Git's shared common directory (used across worktrees).

The key technical changes introduce three consistent variants for path operation: `repo_common_path()` (returns allocated string), `repo_common_path_append()` (appends to buffer), and `repo_common_path_replace()` (replaces buffer contents). This replaces the previous inconsistent mix of `strbuf_git_common_path()` and other variants. The changes affect path handling for commondir, gitdir, worktrees and submodules.

The patch modifies 6 files (path.c, path.h being the main ones) with 54 insertions and 27 deletions. Call sites are updated throughout loose object handling, refs, setup, and worktree code to use the new interfaces. The changes are mechanical but widespread, touching core functionality like loose object maps, repository format handling, and worktree management.

This appears to be a well-structured first step in the larger series, establishing consistent patterns that will be used in subsequent patches. The commit message clearly explains the motivation and new patterns, and the changes appear focused and correctly implemented. The patch maintains backward compatibility while setting up for further `the_repository` removal work.
