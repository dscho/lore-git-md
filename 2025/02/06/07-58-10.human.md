This is part of Patrick Steinhardt's ongoing series to remove `the_repository` global by refactoring path-handling functions. Patch 14/16 moves the "core.hooksPath" configuration from a global variable into `struct repo_settings`.

The change addresses two issues: potential incorrect hook paths when working with multiple repositories in one process, and the broader goal of eliminating global state to make Git more library-friendly. The implementation computes and caches the hooks path per-repository when needed, maintaining the same behavior since hooks always run in a repository context.

The patch removes the global `git_hooks_path` variable and its related config handling, adding equivalent functionality to the repo-settings infrastructure. Changes span 6 files with 16 lines added and 10 removed, primarily moving the hooks path storage and access mechanisms while keeping the core logic intact. This continues the series' pattern of methodically converting implicit global state to explicit per-repository storage.
