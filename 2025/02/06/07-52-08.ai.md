This is part 6/18 of Patrick Steinhardt's v4 series to fully decouple the reftable library from Git core infrastructure. The patch focuses on error handling in record comparison operations.

The key change replaces a `BUG()` call in `reftable_record_cmp()` with proper error propagation when comparing records of different types. Previously, the function would abort execution when encountering mismatched record types, which is undesirable for library code. The new implementation returns an error code (`REFTABLE_API_ERROR`) while maintaining the comparison result in an output parameter.

The patch affects several components:
- Modifies `reftable_record_cmp()` signature to return errors and accept a comparison result output parameter
- Updates all call sites (merged.c, pq.c) to handle the new error return
- Adapts the priority queue implementation to propagate comparison errors
- Updates unit tests to verify the new error handling behavior

This change completes the removal of Git-specific error handling (BUG()) from the reftable library while maintaining the same memory safety guarantees. The patch follows the series' architectural goal of making reftable fully independent of Git's infrastructure, with all major technical concerns having been addressed in previous iterations.
