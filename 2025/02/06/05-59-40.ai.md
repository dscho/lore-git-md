Bugfix patch implementing comprehensive packed-refs entry validation as part of the larger fsck series. This is patch 6/8 in v3 of the series, focusing on porting runtime consistency validations into the fsck infrastructure.

The patch introduces two new validation functions in refs/packed-backend.c:
1. `packed_fsck_ref_main_line()` checks OID format, spacing, and refname validity for main ref entries
2. `packed_fsck_ref_peeled_line()` validates peeled references (lines starting with '^')

Key technical elements:
- New FSCK_MSG_BAD_PACKED_REF_ENTRY error type added to fsck.h and documented
- Reuses existing refname_contains_nul() and check_refname_format() checks
- Maintains line-number tracking for precise error reporting
- Comprehensive test case in t0602-reffiles-fsck.sh exercises:
  * Invalid OIDs
  * Missing/malformed spacing
  * Invalid refnames
  * Malformed peeled references
  * Trailing garbage after peeled OIDs

The implementation follows the pattern established in earlier patches of the series, using the fsck_ref_report struct for consistent error reporting. Test coverage is thorough, including edge cases from the runtime validation that was being ported. The patch completes the core validation logic for packed-refs file contents after the header validation added in previous patches.
