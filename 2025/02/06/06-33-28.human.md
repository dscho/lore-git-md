This is the final version of a feature series introducing a `--revision` option for `git clone`. The series has gone through six previous versions with extensive review and refinement, and is now ready for merging.

The key addition is a new `--revision` flag that lets users clone just a specific commit or ref (without remote-tracking branches), detaching HEAD at that point. This is particularly useful for CI workflows where you need just one specific state of the repository. The implementation includes thorough documentation, test coverage, and careful handling of edge cases.

The series starts with six preparatory refactoring commits that improve `builtin/clone.c`'s structure by reducing globals, inverting tag handling flags, and introducing a `struct clone_opts` to better organize the clone state. These changes make the actual feature implementation in the final patch cleaner and more maintainable.

Reviewers including Junio Hamano and Jean-Noël Avila have scrutinized both the code and documentation, with final tweaks addressing their feedback about bare repository behavior and documentation phrasing. The series demonstrates a good model for incremental refactoring while adding features, and the maintainers have now queued it for integration.
