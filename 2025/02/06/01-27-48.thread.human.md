This thread discusses compatibility issues with the Python interpreter path in `git-p4`, where the shebang line currently uses `python` rather than explicitly specifying `python3`. The original report noted failures on systems like Debian where `python` isn't symlinked to Python 3, with a suggested workaround of changing the shebang to `python3`. Maintainer brian m. carlson defended the current approach, citing backward compatibility concerns for systems still using Python 2.7, despite Python 3 being the modern default.

A recent contribution from Illia Bobyr adds nuance to this discussion, pointing out that Ubuntu 24.10 now defaults `python` to Python 3.12.7 through the `python-is-python3` package, while still offering users the option to switch back to Python 2.7 if needed. This challenges the assumption that preserving the unversioned `python` shebang is necessary for compatibility, at least on modern Ubuntu systems. The discussion now centers on whether Git should update its shebang to explicitly request Python 3, given that some major distributions have moved away from Python 2.7 defaults, while others may still rely on the current behavior. No concrete resolution has been proposed yet, but the conversation highlights the ongoing tension between modern Python 3 adoption and legacy system support.
