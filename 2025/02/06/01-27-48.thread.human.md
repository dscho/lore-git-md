This thread examines whether Git's `git-p4` script should update its shebang line from `python` to `python3`, given changing defaults in modern Python distributions. The discussion began with reports of `git p4` failing on systems like Debian where `python` isn't symlinked to Python 3. Maintainer brian m. carlson initially defended the `python` shebang as necessary for Python 2.7 compatibility, suggesting system configuration workarounds.

Illia Bobyr later countered with evidence from Ubuntu 24.10 showing that `python` now resolves to Python 3.12.7 by default, with version-switching packages available for explicit version selection. This challenged the assumption that `python` primarily serves Python 2.7 needs. In the latest response, carlson reaffirmed the maintainer position, stating that while git-p4 works with both Python 2 and 3, the generic `python` shebang will remain for maximum compatibility until Python 2 support is completely dropped. He noted this is ultimately up to the git-p4 maintainers, though no timeline for change was indicated.

The thread reveals an ongoing tension between modern Python ecosystem practices (where `python` increasingly means Python 3) and Git's conservative compatibility approach, particularly for less-maintained components like git-p4. While some distributions have moved on, the project appears to maintain the status quo for now, leaving users to handle any compatibility issues through local configuration.
