This thread reports a compatibility issue with `git-p4` where the script fails on systems where Python 3 isn't accessible via the default `python` command. The reporter encountered this when running `git p4 clone` on a Debian system with Git 2.30.2, finding that the script's shebang line points to `python` rather than explicitly specifying `python3`. They successfully worked around the issue by manually changing the shebang to `python3`, and suggest this should be updated since Python 3 is now the standard. The core problem appears to be a modernization issue - while the immediate symptom is a PATH problem, the underlying concern is about properly declaring the script's Python version dependency. The fix would be straightforward (updating the shebang line) but may need to consider backward compatibility implications for systems still using Python 2.
