This is a platform compatibility discussion about the `git-p4` Python interpreter path. Junio Hamano weighs in on the ongoing thread about whether `git-p4.py` should use `python` or `python3` in its shebang line. He clarifies Git's general build-time approach: the build system hardcodes the Python path specified during configuration (defaulting to `/usr/bin/python` if not specified), rather than using `/usr/bin/env python` to respect the user's PATH. 

Hamano positions this as a build configuration issue rather than a script compatibility problem - if users want to use Python 3 specifically, they should specify that path at build time. He notes this is Git's standard practice to avoid PATH-related surprises, and that the CI already tests `git-p4` with both Python 2 and 3. 

The email reinforces the maintainers' position that the current approach is intentional, though it doesn't directly address the growing ecosystem shift where `python` now often means Python 3 on modern systems. The discussion remains unresolved but clarifies that any change would need to happen at the build configuration level rather than in the script itself.
