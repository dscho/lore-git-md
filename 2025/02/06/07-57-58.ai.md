This is the second patch in Patrick Steinhardt's 16-part series refactoring path-handling functions as part of the `the_repository` removal effort. It focuses on standardizing the `repo_git_path()` family of functions that handle paths within a repository's git directory.

The patch introduces three consistent variants of gitdir path functions, mirroring the pattern established for commondir paths in patch 1: `repo_git_path()` (allocated string), `repo_git_path_append()` (buffer append), and `repo_git_path_replace()` (buffer replace). These replace previous inconsistent variants like `strbuf_repo_git_path()`. The changes affect 5 files (path.c, path.h, editor.c, hook.c, submodule.c) with 35 lines added and 35 removed.

Key technical changes include converting `repo_git_pathv()` to an internal implementation detail (it's only used for `the_repository` compatibility shims and will eventually be removed) and updating call sites to use the new consistent API. The patch demonstrates careful attention to edge cases like path cleaning and maintains the same functionality while improving interface consistency. This continues the series' systematic approach to path handling refactoring, with each patch building on the last's patterns.
