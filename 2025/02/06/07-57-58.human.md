This is the second patch in Patrick Steinhardt's 16-part series refactoring path-handling functions as part of the `the_repository` removal effort. It focuses on standardizing the `repo_git_path()` family of functions, which handle paths within a repository's git directory.

The patch introduces three consistent variants: `repo_git_path()` (returns allocated string), `repo_git_path_append()` (appends to buffer), and `repo_git_path_replace()` (resets then appends buffer). This replaces previous inconsistent variants like `strbuf_repo_git_path()`. The changes affect 5 files (path.c, path.h, editor.c, hook.c, submodule.c) with 35 lines added and 35 removed.

Notably, `repo_git_pathv()` is demoted to an internal implementation detail, as it's only needed for `the_repository` compatibility shims that will eventually be removed. The changes follow the pattern established in patch 1 for common directory paths, continuing the series' systematic approach to path handling standardization.

The patch appears well-structured, with clear mechanical conversions at call sites and careful attention to buffer handling semantics. It's part of the series' first phase (unifying path-access APIs) and maintains the overall quality seen in the initial patch.
