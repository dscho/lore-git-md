This is part 7/8 of a bugfix series adding comprehensive integrity checking for packed-refs files. The patch specifically implements validation of the "sorted" trait in packed-refs headers, ensuring ref entries are properly ordered when the header claims they are sorted.

The key technical elements include:

1. A new `fsck_packed_ref_entry` struct to track line numbers and record positions during validation, avoiding excessive memory usage by reusing existing comparison infrastructure rather than storing all refnames.

2. Refactoring of comparison logic - extracting `cmp_packed_refname()` from `cmp_packed_ref_records()` to enable reuse for validation without requiring a full snapshot.

3. Enhanced header parsing in `packed_fsck_ref_header()` to detect the "sorted" trait and set a flag for subsequent validation.

4. A new `packed_fsck_ref_sorted()` function that:
   - Verifies refname ordering when "sorted" is declared
   - Uses the new `FSCK_MSG_PACKED_REF_UNSORTED` error message
   - Provides detailed error reporting showing the problematic refnames and line numbers

5. Comprehensive test cases verifying:
   - Detection of unsorted entries when "sorted" is declared
   - Proper handling of peeled references in sorted checks
   - No validation when "sorted" is absent from header
   - Clear error messages identifying the first out-of-order pair

The implementation builds on prior work in the series by integrating with the existing packed-refs validation framework while addressing memory efficiency concerns raised in earlier reviews. It completes the core validation architecture by adding this final major check for structural integrity.
