This thread explores how to manage a repository that needs to push to two GitHub remotes with opposite `.gitignore` behaviors - one remote should follow standard ignore rules while another should effectively ignore them. The challenge is maintaining consistent submodule handling across both configurations.

Brian M. Carlson explains that Git's design makes this impossible to achieve directly, as `.gitignore` controls file staging rather than pushing behavior. Once files are tracked, they'll be pushed to all remotes. He proposes an architectural solution using submodules: placing the extra files in a separate submodule that would only be pushed to the second remote, while keeping them ignored in the main repository. This would require additional scripting to handle file placement via copy or symlink operations when the submodule is present.

The discussion has narrowed the possible approaches, ruling out simpler solutions like branch variations or push hooks in favor of a submodule-based design.
