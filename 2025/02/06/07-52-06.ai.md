This is part of Patrick Steinhardt's v4 series (18 patches) to fully decouple the reftable library from Git core infrastructure. The series has already addressed major technical concerns around build system integration, memory safety, and I/O independence through rigorous review.

The current patch removes the final Git-specific dependency on `COPY_ARRAY()` in the reftable record handling code. It replaces this with an open-coded memory copy operation while adding proper bounds checking to avoid potential NULL pointer issues with zero-sized allocations. The change affects `reftable/record.c` where object records are copied, specifically around handling the `offsets` array during record duplication.

Key technical details:
- The patch introduces explicit size checking before allocation (`sizeof(*src->offsets) > SIZE_MAX / src->offset_len`)
- Maintains identical memory safety guarantees through careful error propagation
- Preserves the existing `REFTABLE_ALLOC_ARRAY` macro usage for consistency
- Adds conditional logic to skip copying when `offset_len` is zero

This change represents one of the final steps in eliminating Git utility functions from the reftable codebase, following previous patches that removed dependencies on `read_in_full()`, `write_in_full()`, and other Git-specific helpers. The implementation appears thorough, with proper attention to edge cases and memory safety considerations.
