This is a documentation patch in an ongoing thread about converting Git's documentation from `.txt` to `.adoc` extensions. Junio C Hamano responds to a suggestion about renaming `SubmittingPatches` by proposing a more conservative approach to the conversion.

The key new position is that only files actually processed through the AsciiDoc toolchain (those converted to HTML or manpages) should be renamed in this initial series. This would exclude files like `SubmittingPatches` and `CodingGuidelines` that don't currently go through the AsciiDoc pipeline, though Junio leaves open the possibility of converting them later if they gain AsciiDoc processing.

The email clarifies two distinct phases: (1) immediate conversion of core documentation files with clear toolchain usage, and (2) potential future conversion of other files if they're adapted to use AsciiDoc formatting. The maintainer's position emphasizes minimizing unnecessary changes while still achieving the primary goal of better editor support, suggesting the series may need to be narrowed in scope before proceeding.

This represents a shift from the original broad conversion approach to a more targeted one, with implications for build system changes and coordination with git-scm.com being simpler under this narrower proposal. The thread's open question about `SubmittingPatches` inclusion now hinges on verifying whether it actually uses the AsciiDoc toolchain.
