Bugfix patch adding packed-refs filetype validation. This is part 3/8 of a series improving ref validation, now checking that "packed-refs" is a regular file rather than a symlink or other special file type. The change uses `open_nofollow()` to detect symlinks and reports them via the existing `FSCK_MSG_BAD_REF_FILETYPE` error mechanism. A new test case verifies the behavior by creating a symlink to simulate the invalid case.

The patch is straightforward - it adds the filetype check to the existing `packed_fsck()` function while maintaining all current behavior for valid cases. The implementation handles edge cases like missing files gracefully. The test follows the pattern of other ref validation tests in t0602, using a subshell to avoid polluting the test directory.

This appears to be a well-contained improvement that closes a small but real gap in ref validation.
