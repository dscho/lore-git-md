This is part of Patrick Steinhardt's ongoing series to fully decouple the reftable library from Git core infrastructure. The patch continues the pattern of replacing Git-specific utility functions with direct system calls or reftable-specific implementations.

Patch 12/18 focuses on removing the dependency on `sleep_millisec()` by replacing it with a direct call to `poll()`. The change is minimal - just a single line modification in `reftable/stack.c` where the function is used for exponential backoff delay during retry operations. The commit explains that while poll() isn't the most direct sleep mechanism, it's the POSIX-compliant way to achieve millisecond-level sleeps.

The change follows the series' established approach of carefully replacing each Git utility while maintaining identical behavior. This particular replacement appears straightforward and low-risk, affecting only retry logic in the reftable stack implementation. The patch maintains the same delay calculation and only changes the sleep mechanism itself.

As with previous patches in this well-reviewed series, this change helps achieve the goal of making reftable fully independent of Git's utility functions while preserving all existing functionality.
