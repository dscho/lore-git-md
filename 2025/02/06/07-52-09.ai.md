This patch continues the reftable library's architectural separation from Git core by removing the last remaining trivial uses of `BUG()`. It's part 7/18 in Patrick Steinhardt's v4 series that has already addressed major technical concerns through rigorous review.

The changes replace `BUG()` calls with `REFTABLE_API_ERROR` returns in several key areas:
- The indexed table iterator now returns an error for unsupported seek operations rather than aborting
- Reader reference counting drops assertions about dead readers since the structure would already be invalid
- Writer validation checks for block size limits and record type mismatches now return errors instead of crashing

The patch maintains the series' focus on proper error propagation while eliminating Git-specific behavior. The removal of `BUG()` from reference counting is particularly notable - the rationale explains that these cases would already indicate undefined behavior, making the assertions redundant.

This continues the pattern seen in earlier patches of converting Git-specific error handling to reftable's own error reporting mechanism. The changes are straightforward and maintain existing safety guarantees while further isolating the reftable implementation details from Git's core infrastructure.
