Bugfix series (v3, 8/8) continuing the packed-refs validation work, addressing feedback from Patrick Steinhardt and Junio Hamano. This version focuses on refining implementation details and documentation while maintaining the core validation checks.

Key technical updates in this version:

1. **Header validation simplification** (patch 4/8):
   - Removes unnecessary checks for header presence and exact content matching
   - Now only verifies the header starts with "# pack-refs with:"
   - Drops FSCK_MSG_PACKED_REF_MISSING_HEADER and FSCK_MSG_UNKNOWN_PACKED_REF_HEADER messages

2. **Entry validation improvements** (patches 5-6/8):
   - Adds explicit NUL character detection in refnames via `memchr()`
   - Ports runtime checks from `next_record()` to validation functions
   - Splits validation into `packed_fsck_ref_main_line()` and `packed_fsck_ref_peeled_line()`

3. **Sortedness verification** (patch 7/8):
   - Only checks sortedness when header explicitly declares "sorted" trait
   - Uses new `fsck_packed_ref_entry` struct to track entries for comparison
   - Adds FSCK_MSG_PACKED_REF_UNSORTED for reporting violations

4. **fsck integration** (patch 8/8):
   - Adds `--[no-]references` option to control ref validation
   - Simplifies progress reporting (removes 0/1 counter)
   - Places ref validation first in fsck execution order

The series touches refs/packed-backend.c, builtin/fsck.c, and test infrastructure in t0602-reffiles-fsck.sh. Implementation maintains backward compatibility while adding stricter validation where appropriate. Test coverage is expanded to exercise new checks, including cases with and without the "sorted" trait.
