This is part 14/18 of Patrick Steinhardt's v4 series to fully decouple the reftable library from Git core infrastructure. The patch removes the final dependency on Git's `UNUSED` macro by introducing a reftable-specific `REFTABLE_UNUSED` alternative.

The change affects multiple reftable components (basics, blocksource, iterators, records, writer) by replacing `UNUSED` annotations with explicit `REFTABLE_UNUSED` calls. The new macro provides weaker guarantees than Git's version - it suppresses unused parameter warnings without verifying parameters marked as unused are actually unused. This tradeoff avoids compiler-specific logic while maintaining functionality.

The implementation follows the established pattern seen in previous patches of this series (RNG, sleep functionality, SWAP replacement) where Git-specific utilities are replaced with reftable-specific equivalents. The changes are mechanical but thorough, touching callback functions throughout the codebase that previously relied on Git's annotation.

This continues the series' architectural goal of complete independence from Git's utility macros. With this change, the reftable library no longer depends on Git's `UNUSED` handling, maintaining the separation boundary established by earlier patches in the series. The change is low-risk as it doesn't modify behavior - it only affects internal compiler annotations.
