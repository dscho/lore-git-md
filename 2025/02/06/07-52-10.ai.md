This is a refactoring patch in Patrick Steinhardt's v4 series (18 patches) to fully decouple the reftable library from Git core infrastructure. The patch specifically targets array allocation macros in reftable/basics.h.

The change replaces Git's `st_mult()` helper with a new `reftable_alloc_size()` function that performs manual overflow checking and returns errors rather than dying. This serves two purposes: (1) it removes a Git-specific dependency, and (2) it converts fatal errors into recoverable ones, consistent with the reftable library's error handling approach.

Key technical changes:
- Introduces `reftable_alloc_size()` helper that checks for size_t overflow
- Modifies `REFTABLE_ALLOC_ARRAY` and `REFTABLE_REALLOC_ARRAY` macros to use the new helper
- Updates `reftable_alloc_grow()` to handle allocation failures gracefully
- Maintains the same memory safety guarantees while changing the error behavior
- Returns NULL with ENOMEM on overflow rather than dying

This continues the series' pattern of systematically removing Git-specific utilities while preserving functionality. The change is straightforward and maintains the existing safety checks, just converting them to the reftable error model. It follows naturally from previous patches that removed other Git utilities like `BUG()` and `COPY_ARRAY()`.
