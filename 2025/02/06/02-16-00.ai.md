Platform compatibility update regarding Python interpreter paths in `git-p4`. 

Illia Bobyr provides a counterexample to the earlier claim that most distributions still map `python` to Python 2, demonstrating that on Ubuntu 24.10 the latest release as of this writing `python` resolves to Python 3.12.7 through the `python-is-python3` package. The email notes Ubuntu provides both `python-is-python2` and `python-is-python3` packages to allow users to control which version the unversioned `python` command points to, with version managers offering additional flexibility. This challenges the assumption that preserving `python` in shebangs is necessary for Python 2.7 compatibility, at least on modern Ubuntu systems.

The response doesn't propose a specific solution but provides concrete evidence that the landscape of Python interpreter naming is more nuanced than previously characterized, with some major distributions now defaulting to Python 3 for the unversioned `python` command. The existence of version-switching packages suggests users who need Python 2.7 compatibility could explicitly opt into it rather than requiring the Git project to maintain Python 2.7 compatibility by default. This adds a new dimension to the ongoing discussion about whether the `git-p4` shebang should be updated to explicitly request Python 3.
