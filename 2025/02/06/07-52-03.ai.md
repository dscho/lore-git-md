This is a refactoring patch in Patrick Steinhardt's v4 series to fully decouple the reftable library from Git core infrastructure. The patch removes the last remaining use of `read_in_full()` in the reftable code by open-coding equivalent functionality in `stack.c`.

The change replaces `read_in_full()` with a direct read loop that handles EAGAIN/EINTR retries, while deliberately omitting the `O_NONBLOCK` handling that exists in Git's version since reftable doesn't use non-blocking I/O. The implementation maintains the same error semantics (REFTABLE_IO_ERROR on failure) and properly tracks bytes read via `total_read`.

This is a straightforward mechanical change that follows the series' architectural goal of eliminating Git-specific utility functions. The patch is well-contained (only touching stack.c) and maintains existing behavior while reducing dependencies. Since this is part of the v4 series where major technical concerns were already addressed in earlier iterations, this appears to be a final cleanup of remaining Git-specific code.
