This is part of Patrick Steinhardt's v4 series (18 patches) to finalize the architectural separation of the reftable library from Git core infrastructure. The series has already addressed major technical concerns through rigorous review, with this patch focusing on I/O independence.

The patch replaces Git's `write_in_full()` utility with a reftable-specific `reftable_write_data()` implementation in stack.c. The new function maintains the same error handling semantics (EAGAIN/EINTR retries, error returns) but removes the Git dependency. The change affects three write operations in the reftable stack implementation: table list updates during addition and compaction, plus the core fd_writer interface.

Key technical details:
- New `reftable_write_data()` implements the same write-until-complete loop as `write_in_full()`
- Returns REFTABLE_IO_ERROR on failure (matching existing error handling)
- Preserves EAGAIN/EINTR retry behavior
- Affects critical paths in table list management and compaction

This continues the series' pattern of replacing Git utilities with reftable-local implementations while maintaining identical behavior. The change is straightforward and maintains memory safety (previously acked by Justin Tobler). With this patch, reftable's I/O subsystem becomes fully independent of Git's utility functions.
