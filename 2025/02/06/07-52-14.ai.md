This patch continues Patrick Steinhardt's v4 series (12/18) to fully decouple the reftable library from Git core infrastructure. The change removes the last remaining dependency on `sleep_millisec()` by replacing it with a direct call to `poll()` - the same POSIX function that `sleep_millisec()` was implemented with internally.

The modification occurs in the exponential backoff delay logic within `reftable_stack_reload_maybe_reuse()`, which handles retry behavior when reloading reftable stacks. The change maintains identical functionality while eliminating another Git-specific utility function dependency. This follows the established pattern seen in previous patches of the series (like the RNG abstraction in 11/18).

The patch is minimal (1-line change) and low-risk since:
1. It's mechanically replacing a function with its direct implementation
2. The behavior remains identical (`poll(NULL, 0, ms)` is exactly how `sleep_millisec()` was implemented)
3. It affects only retry paths in stack reload operations

This continues the series' progression toward complete independence from Git's utility functions, with all major technical concerns having been addressed in prior reviews. The change is straightforward and unlikely to require further discussion.
