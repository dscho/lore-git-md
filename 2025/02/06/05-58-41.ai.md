This is a bugfix patch that prevents premature program termination during ref verification by avoiding HEAD parsing in worktrees. It's part of a larger series (v3 2/8) improving packed-refs validation, though it stands alone as a distinct improvement.

The patch addresses a subtle interaction where `git refs verify` or `git fsck` could die unnecessarily while checking packed-refs files. The issue occurs because existing `get_worktrees()` parses HEAD information, which may trigger packed-backend validation that aborts on malformed files (specifically failing the newline check in `verify_buffer_safe`). The solution introduces `get_worktrees_without_reading_head()` to bypass HEAD parsing during verification operations.

Key technical details:
- New function exposed in worktree.h/c that wraps existing `get_worktrees_internal(1)` flag behavior
- Changes `builtin/refs.c` to use this when verifying refs
- Builds on prior work from commit 465a22b338 which introduced the internal flag
- Maintains all existing functionality while avoiding the packed-refs validation trap

The change is well-motivated by the series' goal of comprehensive ref validation without premature failure. It cleanly separates the worktree listing concern from HEAD validation, which isn't needed during consistency checking. The implementation is minimal (12 lines net change) and clearly builds on established patterns in the worktree API.
