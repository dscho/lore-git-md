Bugfix for `git p4` Python compatibility issue. Kapil Somani reports that `git p4` fails when Python interpreter isn't in PATH, due to its shebang line pointing to `python` rather than `python3`. The error manifests when trying to run any `git p4` command, with the system incorrectly suggesting the command might be broken rather than identifying the Python dependency issue. 

The reporter found a simple workaround by manually changing the shebang to `python3`, which worked on their system. They raise the valid question of whether `git p4` should be updated to use `python3` by default, given Python 3 is now the standard. 

This appears to be a straightforward compatibility issue affecting users who either don't have Python in their PATH or only have Python 3 installed. The fix would likely be uncontroversial, though it might warrant checking for backward compatibility with systems still using Python 2 (if any remain supported). The bug report is clear and includes all necessary reproduction details, making it easy to verify.
