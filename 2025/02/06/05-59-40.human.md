This is a bugfix patch in a series improving packed-refs validation. It adds comprehensive consistency checking for individual ref entries in the packed-refs file, porting existing runtime checks into the fsck infrastructure.

The patch introduces two new helper functions: `packed_fsck_ref_main_line()` validates the main ref entry line (checking OID format, spacing, and refname validity), while `packed_fsck_ref_peeled_line()` handles the secondary peeled tag lines. These implement the same checks that `next_record()` performs at runtime, but now report issues through fsck's error reporting system with a new `badPackedRefEntry` message ID.

The test case demonstrates the validation by creating a packed-refs file with various malformed entries (invalid OIDs, bad spacing, problematic refnames, and garbage in peeled lines) and verifies fsck catches each issue with appropriate error messages. The implementation appears thorough, with clear error messages and test coverage for the edge cases.

This is part of a larger effort (now in its third iteration) to validate packed-refs file integrity, with mentoring from Patrick Steinhardt and Karthik Nayak. The patch builds on previous work in the series that added header validation and filetype checking.
