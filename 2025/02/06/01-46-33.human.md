This is a follow-up in the `git-p4` Python interpreter path discussion. Brian Carlson responds to a bug report about `git p4` failing when Python isn't in the default PATH, clarifying that the shebang line intentionally uses `python` rather than `python3` for backward compatibility with systems still using Python 2.7.

The response explains that when compiling Git from source, users should set PYTHON_PATH to ensure the correct interpreter is used, and that distribution maintainers should handle this dependency appropriately in packaged versions. While acknowledging Python 3 is now standard, Carlson notes some users still require Python 2.7 support, which is why the default shebang hasn't been updated.

This maintains the status quo from the maintainer perspective, suggesting the issue should be handled either at compile-time (for distribution packages) or by individual users modifying their PATH/PYTHON_PATH rather than changing Git's default behavior. The response doesn't indicate plans to change the shebang line despite Python 3's prevalence, citing remaining Python 2.7 users as the reason.
