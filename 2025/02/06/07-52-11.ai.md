This patch is part of Patrick Steinhardt's v4 series (9/18) to fully decouple the reftable library from Git core infrastructure. The series has already addressed major technical concerns through rigorous review, with only header inclusion style remaining as an open question.

The current patch focuses on endian conversion functions, replacing Git's `put_be*`/`get_be*` functions with reftable-specific implementations (`reftable_put_be*`/`reftable_get_be*`). It introduces a complete set of inline functions in basics.h for 16/24/32/64-bit big-endian conversions, then updates all callers across the reftable codebase to use these new wrappers. The test suite is expanded to verify the new implementations.

Key technical details:
- New functions follow reftable naming conventions (prefixed with `reftable_`)
- All conversions are implemented as static inline functions
- Includes full test coverage for 16/24/32/64-bit variants
- Updates callers in block.c, reader.c, record.c, writer.c
- Maintains identical behavior to previous Git implementations

This continues the pattern seen in earlier patches of the series where Git-specific utilities are replaced with reftable-local implementations. The change is straightforward and maintains the architectural separation goals of the overall series. No new technical concerns are introduced, and the patch follows the established approach for utility replacement that has already been reviewed and acked in previous iterations.
