**Refactoring patch continuing the `the_repository` removal effort in `difftool`**

This is the second patch in a three-part series refactoring Git's `difftool` command to eliminate use of the global `the_repository` variable. Building on the first patch's introduction of a `difftool_options` struct, David Aguilar now modifies all `difftool` functions to accept an explicit `struct repository` parameter instead of relying on the global.

The changes are mechanical but widespread, touching nearly every function in `builtin/difftool.c` to pass through the repository parameter. Key modifications include updating object parsing to use the repository's hash algorithm, adjusting file operations to use the repository's index, and ensuring all path operations respect the repository's worktree. The patch maintains all existing functionality while removing implicit dependencies on global state.

This continues the series' clean separation of concerns, with each function now explicitly declaring its repository dependencies. The changes are well-contained within `difftool` and don't affect other Git commands. Like the first patch, this appears to be a straightforward refactoring with no behavior changes, keeping the codebase moving toward the eventual goal of eliminating `the_repository` entirely.
