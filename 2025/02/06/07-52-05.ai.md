This is part of Patrick Steinhardt's v4 series (18 patches) to complete the architectural separation of the reftable library from Git core infrastructure. The patch specifically targets the reftable blocksource implementation.

The change removes the last remaining Git-specific memory mapping dependency by replacing `xmmap()` with direct `mmap()` calls in `reftable_block_source_from_file()`. The key technical changes are:

1. The function now properly handles mmap failures by returning a REFTABLE_IO_ERROR instead of dying (as `xmmap()` would)
2. Error handling is fixed to properly bubble up failures through the return value
3. The patch maintains the same memory safety guarantees while removing Git-specific error handling

The implementation still works with Git's `git_mmap()` wrapper on systems lacking native mmap support, preserving cross-platform compatibility. This completes one of the final pieces of I/O independence for the reftable library, following through on the architectural goal of the series.

The change is well-contained (11 lines modified) and follows the established pattern seen in the series for replacing Git-specific utilities with direct system calls or reftable-local implementations. The patch appears ready for integration, having addressed all prior review feedback in the thread.
