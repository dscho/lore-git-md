This is a retrospective review comment on a merged patch from Patrick Steinhardt's `the_repository` removal series. Karthik Nayak points out a minor API consistency issue in the refactored submodule path functions.

The review focuses on const-correctness in the repository parameter for the new `repo_submodule_path()` family of functions. While the patch already converted these functions to take an explicit repository parameter, Karthik notes that unlike other similar functions in the codebase (like `repo_common_pathv()` shown at the end of the diff), these functions take a non-const `struct repository*` rather than a `const struct repository*`. This is purely a type-safety observation with no functional impact.

The context shows the complete conversion of several submodule path functions (`git_pathdup_submodule`, `strbuf_git_path_submodule`) to their repository-aware versions (`repo_submodule_path`, `repo_submodule_path_append`, `repo_submodule_path_replace`). The core change passes the repository parameter through to the internal `do_submodule_path` helper.

This feedback comes after the series was already merged, suggesting it as a potential follow-up cleanup rather than a blocking issue. The observation aligns with the thread's earlier note about const-correctness inconsistencies in the new path API, though this particular case wasn't previously mentioned. The review maintains the constructive tone seen throughout the thread, focusing on API design polish rather than fundamental flaws.
