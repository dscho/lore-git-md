This is part of Patrick Steinhardt's ongoing `the_repository` removal effort, specifically patch 14/16 in the series. The patch moves the "core.hooksPath" configuration from a global variable to being stored in `struct repo_settings`, continuing the systematic conversion of global state to repository-specific storage.

The change addresses two key issues: potential correctness problems when multiple repositories with different hook paths are accessed in the same process, and the broader goal of removing global state to enable Git's libification. The implementation:
- Removes the global `git_hooks_path` variable and related declarations
- Adds a new `hooks_path` field to `struct repo_settings`
- Introduces `repo_settings_get_hooks_path()` to lazily compute and cache the value
- Updates hook path resolution in `path.c` to use the repository-specific version
- Includes the new field in `repo_settings_clear()` for proper cleanup

The patch affects 6 files with 16 lines added and 10 removed, primarily touching configuration handling and path resolution. This continues the series' pattern of methodically converting implicit global state to explicit repository-aware interfaces while maintaining the same behavior. The change is particularly notable as it deals with hook execution paths, though the commit notes this shouldn't affect behavior since hooks are always run in a repository context.
