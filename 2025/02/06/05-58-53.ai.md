Bugfix patch adding packed-refs filetype validation as part of the packed-refs fsck series. This third patch in the 8-part v3 series introduces explicit checking that the packed-refs file is a regular file (not a symlink or other special file type). The change:

1. Modifies `packed_fsck()` in refs/packed-backend.c to:
   - Use `open_nofollow()` to safely check file type
   - Report FSCK_MSG_BAD_REF_FILETYPE when encountering symlinks (ELOOP)
   - Skip validation if file doesn't exist (ENOENT)
   - Maintains existing worktree handling from previous patches

2. Adds new test case in t0602-reffiles-fsck.sh that:
   - Creates a repo with packed refs
   - Replaces packed-refs with a symlink
   - Verifies `git refs verify` fails with correct error
   - Cleans up test state properly

The implementation reuses the existing FSCK_MSG_BAD_REF_FILETYPE message rather than introducing a new one. The change addresses a gap where Git previously didn't verify the packed-refs file type despite expecting it to be a regular file created by `git pack-refs`. The patch follows the series' pattern of adding validation checks while maintaining backward compatibility.

Key technical details for future reference:
- Uses `open_nofollow()` wrapper for safe symlink checking
- Reports via existing fsck_report_ref() infrastructure
- Test case uses SYMLINKS prerequisite
- Error path preserves errno for accurate reporting
- Maintains worktree isolation from previous patches
