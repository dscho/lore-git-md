Feature implementation for `git clone` with new `--revision` option. This is the final patch in a 7-part series that adds the ability to clone a single revision without creating remote-tracking branches, detaching HEAD at the requested commit. The implementation is now complete after six iterations of review and refinement.

The patch introduces the core `--revision` option that accepts either a fully qualified ref (like `refs/pull/123`) or a commit hash. Key behaviors:
- No remote-tracking branches are created
- HEAD is detached at the requested revision
- Works with `--depth` for minimal clones
- Explicitly incompatible with `--branch` and `--mirror`
- Includes comprehensive test coverage in new test file `t5621-clone-revision.sh`

Technical changes include:
- New `detach` flag in `struct clone_opts`
- Modified `update_head()` to use `lookup_commit_or_die()`
- Special handling of refspecs when `--revision` is used
- Server communication optimization to only fetch needed objects
- Documentation of behavior for both bare and non-bare repositories

The implementation has been thoroughly reviewed with all feedback incorporated, including verification from Patrick Steinhardt and final documentation polish from Jean-Noël Avila. The series is now queued for integration by Junio Hamano.
