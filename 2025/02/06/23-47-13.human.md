This is a documentation patch in an ongoing thread about converting Git's AsciiDoc files from `.txt` to `.adoc` extensions. Junio Hamano responds to a suggestion about renaming `SubmittingPatches` by proposing a more conservative approach to the conversion.

The email suggests limiting the extension changes to only files that are definitively processed through the AsciiDoc toolchain to produce HTML or manpages, leaving other documentation files (like `SubmittingPatches` and `CodingGuidelines`) unchanged for now. Junio acknowledges these could be converted later if desired, but wants to avoid unnecessary changes in the current series.

This represents a potential narrowing of scope from the original 5-patch series that would rename all AsciiDoc files. The maintainer's position balances the benefits of editor support against minimizing churn, particularly for files that aren't part of the main documentation build pipeline. The email leaves open whether these additional files might eventually get converted, either for editor support or if they later become part of the AsciiDoc processing pipeline.
