Feature completion for git-clone's new `--revision` option. This is the final patch in a 7-part series that adds the ability to clone a single revision without creating remote-tracking branches, particularly useful for CI workflows.

The patch implements the core functionality of `--revision`, which accepts either a fully-qualified ref (like `refs/pull/123`) or a commit hash. Unlike `--branch`, this option detaches HEAD and creates no tracking branches or fetch refspecs. The implementation includes:

1. New `detach` flag in `struct clone_opts` to control HEAD behavior
2. Modified `update_head()` to use `lookup_commit_or_die()` for better error handling
3. Incompatibility checks with `--branch` and `--mirror` options
4. Comprehensive test coverage in new test script `t5621-clone-revision.sh`

The tests verify various scenarios including branch/tag/commit references, bare repositories, error cases, and interactions with other options like `--depth`. The documentation clearly explains the behavior and limitations with other clone options.

This appears to be a well-considered implementation that has gone through multiple review iterations, with all technical concerns addressed. The feature fills a clear gap in Git's cloning capabilities, particularly for automated workflows that need minimal repository access.
