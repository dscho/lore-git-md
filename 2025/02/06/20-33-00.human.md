This is a follow-up discussion in the ongoing documentation conversion series that's changing Git's AsciiDoc files from `.txt` to `.adoc` extensions. M Hickford suggests an additional file that should be included in the conversion - `SubmittingPatches`, which was converted to AsciiDoc format back in 2017 but still carries the original filename without extension.

The email is a brief but useful catch of an oversight in the large-scale conversion. While the main patch (4/5) already handles renaming 923 files, this points out one more candidate for the extension change. The suggestion appears valid since the file was confirmed as AsciiDoc content years ago, and keeping it consistent with the new naming scheme would provide the same editor support benefits being sought for all documentation files.

This is the kind of minor but important detail that often surfaces during large mechanical conversions, and catching it now would prevent having to make a follow-up patch later. The change would be trivial to incorporate into the current series since all the necessary infrastructure updates (build system changes, include path handling) are already being made in the main conversion patch.
