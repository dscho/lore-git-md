Documentation maintenance: Finalizing AsciiDoc extension conversion

This is part of the ongoing discussion about converting Git's documentation from `.txt` to `.adoc` extensions. The thread has largely reached consensus on the technical merits, with attention now turning to edge cases in the transition.

Junio C Hamano responds to M Hickford's suggestion about renaming the extensionless `SubmittingPatches` file, expressing caution about applying the change too broadly. He questions whether this particular file is actually processed by AsciiDoc (unlike the main documentation files) and suggests limiting the conversion to only those files that are definitively part of the documentation build system.

The exchange reveals an important distinction in Git's documentation ecosystem - while many files use AsciiDoc syntax, not all are processed the same way. Hamano's position reflects a conservative approach to minimize unnecessary churn, particularly for files that may have special handling or historical significance without extensions.

This comes as the final technical clarification needed before the series can proceed, with all major participants now aligned on the core conversion but differing slightly on scope. The discussion has evolved from whether to convert to precisely which files should be included, with maintainers favoring a minimal approach focused only on build-system-processed documentation.
