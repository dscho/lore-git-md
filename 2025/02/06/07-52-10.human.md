This is part 8/18 of Patrick Steinhardt's series to fully decouple the reftable library from Git's core infrastructure. The patch removes the final Git-specific dependency in the array allocation macros by replacing `st_mult()` with a custom overflow-checking implementation.

The change converts three macros (`REFTABLE_ALLOC_ARRAY`, `REFTABLE_REALLOC_ARRAY`, and the inline `reftable_alloc_grow`) to use a new `reftable_alloc_size` helper that performs manual overflow checking. This eliminates the last dependency on Git's `st_mult()` while maintaining the same safety guarantees - now returning errors (via `ENOMEM`) rather than dying on overflow.

The patch continues the series' pattern of methodically replacing Git-specific functionality with reftable-local equivalents, in this case completing the transition for memory allocation utilities. The implementation looks thorough, with proper error handling and the same overflow protection as the original Git version. As with previous patches in the series, this appears ready for integration.
