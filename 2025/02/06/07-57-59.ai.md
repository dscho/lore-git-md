This is the third patch in Patrick Steinhardt's 16-part series refactoring path-handling functions as part of the `the_repository` removal effort. Following the patterns established in the first two patches for `repo_path()` and `repo_git_path()`, this patch standardizes the `repo_worktree_path()` family of functions.

The patch introduces three consistent variants for worktree path handling: `repo_worktree_path()` (allocates new string), `repo_worktree_path_append()` (appends to existing buffer), and `repo_worktree_path_replace()` (replaces buffer contents). It deprecates the older `strbuf_repo_worktree_path()` function in favor of these more clearly named alternatives. The changes affect 3 files (path.c, path.h, repository.c) with 33 insertions and 19 deletions.

Key technical details include:
- All variants now explicitly return NULL when the repository has no worktree
- The `replace` variant resets the strbuf before writing
- The implementation consolidates path construction into a shared `do_worktree_path()` helper
- Updates `repository.c` to use the new `_append` variant for submodule initialization

This continues the series' systematic approach to path API standardization, maintaining the same patterns seen in previous patches while focusing specifically on worktree paths. The changes are mechanical refactors with no intended behavior changes, though they do make the NULL return for no-worktree cases more explicit in the interface.
