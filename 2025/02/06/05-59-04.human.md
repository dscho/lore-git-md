This is part 4 of an 8-part bugfix series improving validation of packed-refs files. The patch adds header consistency checking to the fsck mechanism for packed-refs files.

The change ensures that if a packed-refs file has a header (which is optional for backwards compatibility), it must start with the exact string "# pack-refs with:". Malformed headers will now trigger a new fsck error (FSCK_MSG_BAD_PACKED_REF_HEADER). The implementation also adds detection of unterminated lines in the file, reporting those via FSCK_MSG_PACKED_REF_ENTRY_NOT_TERMINATED.

The patch includes tests that verify the new checks work by deliberately creating packed-refs files with various malformed headers. The implementation follows the same validation pattern already used in create_snapshot(), making the behavior consistent between runtime and fsck operations.

This is a well-contained change that clearly addresses a specific gap in the packed-refs validation. The commit message thoroughly explains the design decisions and edge cases considered. The test coverage appears comprehensive, checking both valid and invalid cases. As part of the larger series addressing packed-refs validation, this patch helps improve the robustness of Git's reference storage.
