Follow-up in `git clean -Xdf` behavior discussion. Jan Berges responds to Junio Hamano's explanation by demonstrating that even with explicit pathspecs (`git clean -Xf -- .`), the command still cleans parent/sibling directories when operating within an ignored hierarchy, contrary to the documented behavior that pathspecs should limit scope. Berges provides a concrete example showing how the current implementation could dangerously clean entire directory trees (like `~/Documents/`) when run in subdirectories of ignored paths, especially with certain Git environment variables set. While noting no actual files were lost in their testing, they reinforce the safety recommendation to always use `-n` for dry runs. This reply highlights the gap between documented behavior (pathspec-limited cleaning) and actual implementation (working-tree-wide cleaning when parent is ignored), with potential safety implications in edge cases. The thread continues to show the tension between Git's working-tree-as-unit principle and user expectations of pathspec-limited operations.
