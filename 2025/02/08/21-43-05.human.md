This is a technical follow-up in the ongoing discussion about Git's renormalization behavior with smudge/clean filters. Elijah Newren responds to Phillip Wood's practical validation of a combined approach using `-X renormalize` and `git add --renormalize` during rebase.

The key new insight is Phillip's addition of `--attr-source=$(git rev-parse HEAD)` to ensure Git can read `.gitattributes` from historical commits during rebase. Elijah confirms this works by checking Git's source code, discovering the attribute source is passed to subprocesses via the `GIT_ATTR_SOURCE_ENVIRONMENT` variable. 

The email also revisits the fundamental limitation that merge renormalization only affects new blobs during three-way merges, not existing content. While the demonstrated workflow works for linear histories, Elijah notes it still requires manual conflict resolution for line-ending differences and may not generalize to more complex cases.

The discussion suggests this solution might warrant documentation in Git's FAQ, though with caveats about its linear history assumption. This represents a practical refinement of earlier technical discussions, showing how to combine multiple Git features to achieve history rewriting with filters, albeit with some remaining edge cases.
