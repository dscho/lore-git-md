This thread investigates a bug in `git log` where mixing `--graph` and `--no-graph` flags causes segmentation faults or memory errors, particularly when combined with formatting options like `--name-status`. Emily Klassen first reported the issue on ARM64 macOS with Git 2.48.1, observing that `--graph` sets internal state that isn't properly cleared by subsequent `--no-graph`. Đoàn Trần Công Danh later confirmed similar problems, including an "Out of memory" error, suggesting the issue involves memory management in the diff machinery.

Emily has now identified the root cause: `revs->diffopt.output_prefix_data` isn't properly cleared when `--no-graph` is processed in `revision.c`. While Danh's case was resolved by the already-merged `jk/combine-diff-cleanup` series, Emily's segmentation fault persists. She's preparing a patch to explicitly null this field during `--no-graph` handling, which may address both failure modes. The thread now awaits her proposed fix to confirm whether it resolves all reported cases of this graph/diff state management issue.
