This thread addresses a memory management bug in Git's revision walking code that causes crashes when mixing `--graph` and `--no-graph` options with certain output formats. The issue, introduced in Git v2.37.0, leads to use-after-free scenarios where graph-related pointers aren't properly cleared. 

Emily Klassen has implemented the core technical solution (nulling the problematic pointers in revision.c and graph.c) which has been confirmed correct by Junio Hamano and other reviewers. The bug's origin was pinpointed through bisection work by D. Ben Knoble and Jeff King, who also documented the non-deterministic nature of the symptoms (sometimes segfaults, sometimes garbage output). The fix will need to be backported to all stable branches since v2.37.0.

The only remaining task is for Emily to add regression tests before resubmitting the final patch series. Junio has acknowledged this plan in the latest email, confirming that the technical discussion is complete and the thread is now just awaiting the test coverage to prevent future regressions. The consensus remains strong on the solution, with no outstanding architectural concerns.
