This is a performance optimization patch in the refs subsystem series, specifically addressing object ID ambiguity checks in `update-ref`. The patch modifies `builtin/update-ref.c` to use the new `GET_OID_HASH_SKIP_AMBIGUITY_CHECK` flag when parsing object IDs, avoiding redundant ambiguity checks that were identified as a performance bottleneck.

The changes occur in three key locations: two within the stdin parsing logic (handling both regular and -z modes) and one in the direct command-line interface path. The patch maintains identical behavior while skipping unnecessary hash ambiguity verifications, as these checks are redundant in the context of ref updates where the OID will be fully verified later.

This builds on Patrick Steinhardt's earlier infrastructure work introducing the `repo_get_oid_with_flags()` API and the ambiguity check optimization flag. The changes are straightforward mechanical conversions from `repo_get_oid()` to the new flag-aware variant, with clear preservation of existing error handling paths.

The patch demonstrates good attention to both code paths - the batch processing via stdin and the direct command-line interface - ensuring consistent behavior across all `update-ref` usage patterns. As part of the larger performance optimization series, this contributes to the measured 1.19x-2.32x speedups mentioned in the thread context, though this particular change's impact would be most noticeable in repositories with many ambiguous object prefixes.
