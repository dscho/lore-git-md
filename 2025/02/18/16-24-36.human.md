Refactoring patch in the `git merge-tree --stdin` cleanup effort.

This is the second patch in Phillip Wood's v2 series addressing stdin processing in `git merge-tree`. It removes redundant error handling code that was checking for negative return values from `real_merge()`. The author explains that this check is unnecessary because: (1) `real_merge()` only returns 0 or 1 (it dies on errors), and (2) the stdin mode always exits with status 0 regardless of merge results (which are reported via stdout instead). The change simplifies the code while maintaining the same behavior, as confirmed by earlier discussion in the thread. This continues the series' theme of streamlining the stdin processing path after earlier patches addressed deadlock issues and documentation clarifications. The patch is small (5 lines removed) and focused, building on the established consensus from previous iterations.
