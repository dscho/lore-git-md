This is a build system fix that concludes a thread about Makefile default target behavior. The patch series, originally from Adam Dinwoodie and now reviewed by Patrick Steinhardt, addresses a regression where documentation builds defaulted to generating only config files after commit a38edab7c8. The solution follows Junio Hamano's guidance to use empty `all::` rules at Makefile starts, consistently applying this pattern across 15 Makefiles in Documentation/ and contrib/ directories.

The changes restore the original behavior of building HTML and man pages by default while establishing a consistent project-wide convention for Makefile target declarations. Patrick has verified the technical correctness of the implementation, confirming all preexisting `all:` targets were properly converted to `all::` with no functional side effects. With both the regression fix and broader consistency improvements completed, Junio indicates the patch is ready to be applied.

Key technical details for future reference: the fix involves (1) adding empty `all::` rules with explanatory comments at file starts, (2) converting existing `all:` to `all::` where present, and (3) preserving all existing build rules. The changes span Documentation/Makefile and various contrib/ Makefiles, maintaining backward compatibility while preventing similar regressions through consistent target declaration patterns.
