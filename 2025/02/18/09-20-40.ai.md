This is a refactoring patch in Patrick Steinhardt's ongoing series to separate the reftable library from Git core dependencies. The change removes usage of Git's `COPY_ARRAY()` macro in favor of direct memory operations with added safety checks.

The patch modifies `reftable/record.c` to replace `COPY_ARRAY()` with explicit memory allocation and bounds checking when copying offset arrays in object records. The new implementation first checks for zero-length arrays to avoid NULL pointer issues, adds an overflow check for the allocation size, and uses direct `memcpy()` instead of the Git helper macro. This maintains the same functionality while eliminating another Git-specific dependency.

The change follows the series' pattern of systematically replacing Git internals with reftable-native or POSIX-compatible alternatives. It includes proper error propagation of reftable-specific error codes (REFTABLE_OUT_OF_MEMORY_ERROR) rather than Git's error handling. The implementation appears thorough, handling edge cases like zero-sized allocations that could previously trigger memory errors.

This is patch 4/18 in the v6 series, which has already received technical approval from multiple core maintainers for its architectural approach. The change is localized to reftable internals and doesn't affect user-facing behavior, representing another incremental step toward making the reftable library usable outside Git core.
