This is the final patch in Patrick Steinhardt's 18-part series to separate the reftable library from Git core dependencies. The patch addresses build system integration by excluding reftable sources from Coccinelle semantic patching.

The change modifies the Makefile to filter out reftable/ sources from COCCI_SOURCES, since the reftable library no longer uses Git's common helper functions that Coccinelle rules typically target. This prevents potential false positives from rules that would suggest converting reftable code to use Git-specific patterns that are no longer applicable.

The patch is a straightforward one-line change that completes the architectural separation work by ensuring the build system treats reftable as an independent component. It follows logically from the previous patches that systematically replaced Git helpers with reftable-native implementations (memory operations, error handling, platform compatibility, etc.).

Key technical points:
- Affects only the Makefile's COCCI_SOURCES definition
- Adds reftable/% to the existing filter-out pattern that already excluded THIRD_PARTY_SOURCES
- Maintains all existing functionality while preventing inappropriate Coccinelle suggestions
- Final step in making reftable truly standalone from Git's infrastructure

This appears to be a clean, well-justified conclusion to the series that has already received significant review and approval from core maintainers. The change is minimal and focused, with no expected impact on build behavior beyond the intended Coccinelle exclusion.
