A regression in Git's HTTP authentication was reported by Peter Georg, affecting versions 2.46 and later. The issue occurs during git-http-push operations when using credentials stored in netrc files. The problem stems from commit 610cbc1dfb ("http: allow authenticating proactively"), which changed how Git handles authentication. 

In current versions, the behavior breaks in two ways: when http.proactiveAuth is unset or "none", Git initially uses netrc credentials but then fails on subsequent connections; when set to "auto" or "basic", Git ignores netrc entirely and prompts for credentials. Peter provided detailed reproduction steps showing the issue disappears when reverting the problematic commit, along with curl logs demonstrating the authentication failures (with sensitive information redacted).

The report is thorough, showing this is a real regression that breaks existing workflows relying on netrc authentication for http-push operations. While the report doesn't propose a specific fix, it provides all the necessary information to diagnose and address the issue, including version comparisons and test cases. The change in behavior appears unintentional given that reverting the commit resolves the problem.
