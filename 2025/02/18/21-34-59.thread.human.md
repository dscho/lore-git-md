This thread addresses a regression in Git's HTTP authentication that broke netrc credential support in Git 2.46 and later. Peter Georg reported that git-http-push fails to use netrc credentials in two scenarios, with Brian m. carlson confirming this was unintended but highlighting a design incompatibility between netrc's password-only approach and proactiveAuth's need for credential-type awareness. A bugfix patch has been submitted that restores WebDAV-specific netrc functionality while surfacing broader questions about netrc's undocumented status in Git.

Junio Hamano, the Git maintainer, has now weighed in seeking clarification on whether the proposed changes affect general netrc usage or just the older HTTP walker component. He expresses surprise that the HTTP walker might still be in use, and signals agreement with carlson's approach of either properly documenting netrc support or removing it in favor of the contrib-based `git-credential-netrc` helper. While the specific path forward remains open, the maintainer's response indicates a preference for resolving the technical debt rather than maintaining the current undocumented state. The core tension persists between preserving existing (but fragile) functionality versus simplifying the codebase through either proper support or removal.
