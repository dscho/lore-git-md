This is a maintainer response to a bugfix series for gitk's Japanese filename encoding issues.

Junio C Hamano provides procedural guidance to the patch author Kazuhiro Kato regarding the gitk contribution workflow. The response notes that gitk patches should be based on Johannes Sixt's separate gitk repository (j6t/gitk) rather than the main Git tree, since gitk is maintained via a subtree merge strategy. Hamano also reminds the author to CC the gitk maintainer (Johannes Sixt) on future submissions.

The response includes references to three previous mailing list threads that establish this workflow convention, suggesting this is a recurring point of clarification for gitk contributors. No technical feedback is given on the actual encoding fixes themselves - the message focuses solely on the submission process requirements.

This administrative note comes after the initial two-part series was submitted, which fixed UTF-8 encoding handling in gitk's merge conflict display (system-wide encoding initialization and specific fixes for filename decoding in merge diffs). The response implies the technical content may be ready for review once the submission logistics are corrected.
