This is a documentation patch adding a comprehensive technical design document for the "Large Object Promisors" (LOP) feature, which is part of the ongoing promisor-remote/LOP series. The 656-line document outlines a system for handling large blobs through dedicated promisor remotes, separate from main repositories.

The design addresses several current pain points with large blob handling in Git, particularly around storage efficiency and server performance. Key aspects include:
- Using special promisor remotes (LOPs) exclusively for large blobs
- Server-side offloading of large blobs to object storage (S3/GCP buckets)
- Protocol v2 capability negotiation for LOP advertisement
- Configurable size thresholds for blob offloading
- Security considerations for LOP acceptance policies

The document carefully delineates scope (focusing on server-side improvements) while acknowledging related but separate efforts like client-side object representation changes. It provides detailed rationale for each design decision and compares the approach to existing solutions like Git LFS. Implementation notes reference existing Git capabilities (partial clones, remote helpers) that can be leveraged.

This appears to be a well-considered design document that builds on the protocol implementation work shown in earlier patches of the series. The thorough FAQ section anticipates many practical deployment questions and edge cases.
