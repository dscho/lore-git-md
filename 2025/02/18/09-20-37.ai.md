This is a refactoring patch in Patrick Steinhardt's ongoing series to reduce the reftable library's dependency on Git-specific utilities. The change replaces a single use of `read_in_full()` with direct file reading logic in `reftable/stack.c`.

The patch open-codes the file reading functionality that was previously handled by `read_in_full()`, though it intentionally omits the `EWOULDBLOCK` handling from Git's `xread()` since the reftable library doesn't use non-blocking I/O. The new implementation maintains the same error handling behavior but does the reading in a loop to handle partial reads, with explicit checks for `EAGAIN` and `EINTR` (though the commit message notes these cases shouldn't occur in practice).

Key technical details for future reference:
- Modifies `fd_read_lines()` in `reftable/stack.c`
- Replaces `read_in_full()` with a manual read loop
- Keeps same error conditions (REFTABLE_IO_ERROR)
- Explicitly skips `EWOULDBLOCK` handling that exists in Git's version
- Maintains same buffer size handling (reads full file contents at once)

This appears to be a straightforward, well-motivated change as part of a larger effort to make the reftable library more self-contained. The commit message clearly explains the rationale and what parts of the original implementation were intentionally left out.
