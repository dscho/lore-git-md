Refactoring patch in the ongoing reftable library separation effort.

This is patch 11/18 in Patrick Steinhardt's series to decouple the reftable library from Git-specific dependencies. The patch introduces a new `reftable_rand()` function to replace direct calls to Git's `git_rand()`, continuing the pattern of creating reftable-native versions of utility functions.

The change affects two call sites where random numbers are used: for backoff delays during stack reloads and for generating unique filenames. The implementation currently still wraps `git_rand()` but provides a clear interface point for future external implementations. This maintains the series' goal of making the reftable library usable outside Git while preserving existing behavior.

The patch is straightforward and follows the established pattern seen in previous patches of the series. It touches only reftable implementation files (stack.c, system.c, system.h) with no user-facing impact. The change appears well-contained and consistent with the series' architectural direction.
