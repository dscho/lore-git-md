This is a feature patch series introducing a "promisor-remote" protocol capability, part of the ongoing effort to improve handling of large files in client-server Git workflows. Christian Couder presents version 5 of this work, which has been refined based on feedback from Junio Hamano, Patrick Steinhardt, and others.

The series implements a protocol extension that allows servers to advertise promisor remotes to clients during clone/fetch operations. This enables clients to fetch missing objects directly from these remotes rather than requiring manual configuration. The implementation includes:

1. A new "promisor-remote" capability in protocol v2
2. Security controls for accepting advertised remotes (None/All/KnownName/KnownUrl)
3. A technical design document explaining the large object promisor (LOP) concept

Key changes in v5:
- Removed utility function patches that proved unnecessary
- Made URL comparisons case-sensitive
- Renamed `strvec_find_index()` to `remote_nick_find()`
- Added documentation references in header files
- Improved test cases by renaming "server2" to "lop" (Large Object Promisor)
- Enhanced the design doc with clarifications about LOP usefulness

The series appears well-tested (all CI passes) and addresses previous feedback about security and code organization. The technical design doc provides useful context about the broader vision for handling large objects, though some aspects like blob offloading will need further discussion.

This represents a significant step toward making promisor remotes more usable in distributed workflows while maintaining security controls. The implementation looks solid, with careful attention to edge cases and configuration options.
