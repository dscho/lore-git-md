This is part of Patrick Steinhardt's ongoing effort to separate the reftable library from Git core dependencies (patch 3/18 in v6). The change replaces Git's `xmmap()` wrapper with direct `mmap()` calls in the reftable blocksource code, continuing the architectural separation work.

The patch addresses two specific issues with `xmmap()`: its fatal error handling (which doesn't suit a library) and its tight coupling to Git internals. The new implementation uses standard `mmap()` with proper error propagation, falling back to Git's `git_mmap()` wrapper where needed for portability. The error handling is now more library-appropriate, returning REFTABLE_IO_ERROR rather than dying on failure.

This is a straightforward technical change that follows the series' established pattern of replacing Git-specific helpers with reftable-native equivalents. The diff shows careful attention to resource cleanup and error paths, maintaining the same functionality while removing the Git dependency. As with previous patches in this well-reviewed effort, the change is focused and unlikely to be controversial.
