This is the second patch in a bugfix series addressing Japanese filename display issues in gitk during merge conflicts. Building on the first patch's UTF-8 encoding system initialization, this change specifically fixes garbled filenames in merge conflict displays by properly converting raw filename encodings.

The patch modifies gitk's Tcl/Tk script to handle filename encoding conversion when parsing merge diffs. It introduces an intermediate `fname_raw` variable to preserve the original encoding before conversion, then uses Tcl's `encoding convertfrom` to properly decode the filename for display. A similar conversion is added for the diff content lines themselves.

The changes are focused and minimal (4 lines added, 2 changed), directly targeting the reported issue. While the patch doesn't include tests, the problem appears well-isolated to the merge conflict display logic. This completes the two-part fix for Japanese filename display issues in gitk's merge conflict interface.
