This is part 7/18 of Patrick Steinhardt's series to decouple the reftable library from Git core, continuing the systematic replacement of Git-specific components. The patch focuses on removing remaining `BUG()` calls in trivial cases, replacing them with `REFTABLE_API_ERROR` returns to indicate API misuse rather than aborting the program.

Key changes:
- Removes `BUG()` checks in `reftable_reader_{inc,dec}ref()` entirely, as the refcount being zero would indicate already-freed memory where behavior is undefined regardless
- Converts `indexed_table_ref_iter_seek()` and block type validation in `writer_add_record()` from `BUG()` to returning `REFTABLE_API_ERROR`
- Updates block size validation in `reftable_writer_new()` to return error rather than `BUG()`

The changes affect the reftable iterator, reader, and writer components (iter.c, reader.c, writer.c), continuing the series' pattern of replacing Git's assertion mechanisms with reftable-native error handling. This maintains the library's safety while further removing Git dependencies, though the author notes some cases (like refcount checks) are being removed rather than converted since they would indicate already-broken invariants.

The patch follows the established approach seen in previous parts of the series, with straightforward mechanical conversions that don't change user-visible behavior but improve the library's self-contained error handling. Test coverage for these error paths was presumably added in earlier patches in the series.
