This is a platform compatibility discussion in the context of the completed series eliminating `-Wsign-comparison` warnings in `apply.c`. Junio C Hamano raises a philosophical question about the type conversion strategy in the final patch, specifically regarding the change of line-number variables in `find_pos()` from `int` to `size_t`.

The key technical point is that while the patch converted `backwards_lno`, `forwards_lno`, and `current_lno` to `size_t`, the `line` parameter they receive remains `int` and can temporarily hold negative values before assignment. Hamano questions whether it's correct to change these variables' types to match other parts of the system that want `size_t` comparisons, suggesting instead that those other parts should be fixed to handle the natural integer types properly.

This discussion doesn't challenge the technical correctness of the series (which has already been reviewed and validated) but probes the underlying design philosophy about when and how to convert between signed and unsigned types in the codebase. The exchange highlights an ongoing tension between warning elimination and type system design that may inform future similar efforts, though it doesn't appear to block the current series from proceeding.
