**Updated AI thread summary:**

Bug report and analysis of HTTP authentication regression in Git 2.46+ introduced by commit 610cbc1dfb ("http: allow authenticating proactively"). Peter Georg reported git-http-push fails to use netrc credentials in two scenarios: (1) with http.proactiveAuth unset/"none", initial connections use netrc but subsequent attempts fail; (2) with proactiveAuth "auto"/"basic", netrc is ignored entirely. The regression affects all versions since 2.46 via HTTPS URLs.

Brian m. carlson confirmed this as unintended but explained the fundamental incompatibility: proactiveAuth is designed for credential helpers that can return non-password credentials (like Bearer tokens), which netrc cannot provide. The documentation specifies netrc is only used when no credentials are provided, and libcurl doesn't expose netrc credential existence, making it impossible to safely use netrc with proactiveAuth's design goal of avoiding 401 responses. While promising further investigation, carlson suggested git-credential-netrc from contrib as a temporary workaround.

A bugfix patch now addresses the WebDAV-specific regression while surfacing broader maintenance questions. The fix modifies `http.c` (3 lines) to restore netrc functionality for WebDAV pushes by adjusting how `curl_empty_auth_enabled()` interacts with proactive authentication - now only setting empty credentials when proactive auth is enabled, allowing libcurl's fallback to netrc. A new test case in `t5540-http-push-webdav.sh` verifies the fix by creating a `.netrc` file and pushing to a password-protected repository.

Maintainer Junio C Hamano engaged seeking clarification on whether carlson's proposal targets general HTTP netrc usage or specifically the HTTP walker (an older component), expressing surprise at potential walker usage. In response, carlson confirms the discussion concerns netrc in HTTP code paths generally, not the HTTP walker, while noting WebDAV's continued but potentially waning relevance given its incompatibility with packed-refs and future reftable migration. Hamano had signaled agreement with the principle of either properly documenting netrc as a first-class citizen or removing it in favor of `git-credential-netrc`, showing maintainer alignment on addressing the technical debt.

Core issues remain unresolved regarding the fundamental mismatch between netrc's password-only capabilities and proactiveAuth's credential-type awareness requirements. The thread now awaits either: (1) concrete proposals for full netrc support (requiring documentation and test coverage expansion) or its deprecation path, or (2) community contributions to expand test coverage, as carlson has indicated he won't pursue this further without them.
