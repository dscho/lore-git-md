Bugfix report for HTTP authentication regression in git-http-push. Peter Georg reports that since Git v2.46 (specifically after commit 610cbc1dfb), git-http-push fails to consistently use credentials from .netrc files when pushing to HTTPS remotes. The issue manifests differently depending on the http.proactiveAuth setting: with it unset or 'none', credentials work initially but fail on subsequent connections; with 'auto' or 'basic', Git falls back to prompting for credentials rather than using the .netrc file.

The reporter has verified that reverting the problematic commit restores the previous working behavior. They've provided verbose curl logs (with sensitive data redacted) showing the authentication failures and note the issue persists in newer Git versions beyond 2.46. The report includes detailed system information showing this occurs on a Linux system with modern curl/OpenSSL versions.

This appears to be a clear regression in authentication behavior that breaks existing workflows relying on .netrc files. The report is thorough, including reproduction steps, version bisecting, and diagnostic logs, making it a strong candidate for prompt attention from HTTP transport maintainers. The reporter offers to assist with testing any fixes.
