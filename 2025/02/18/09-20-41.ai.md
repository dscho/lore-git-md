This is part of Patrick Steinhardt's ongoing reftable library decoupling effort (patch 5/18 in v6), specifically targeting the removal of Git-specific error handling. The patch converts `reftable_record_init()` from using Git's `BUG()` macro to returning a proper error code (REFTABLE_API_ERROR) when encountering unknown record types, making the library more self-contained and suitable for non-Git consumers.

The changes affect record initialization across multiple reftable components (block.c, merged.c, reader.c) and their corresponding unit tests, with all callers now properly checking the return value. The modification follows the series' established pattern of replacing Git-specific constructs with reftable-native equivalents while maintaining the same safety guarantees - in this case, preventing NULL pointer issues through explicit error handling rather than assertions.

Key technical details for future reference:
- The record initialization function signature changes from `void` to `int` return
- New error path returns REFTABLE_API_ERROR for unknown types (previously BUG())
- All 7 modified files are internal reftable implementation details
- Unit tests are updated to expect success (0) from valid initializations
- The change is purely about error handling - no behavioral differences for valid inputs

This continues the architectural separation work that has already received maintainer approval for its core approach, with the series now awaiting final sign-off before merging. The patch maintains the careful balance seen in prior changes: removing Git dependencies while preserving safety and not introducing new failure modes.
