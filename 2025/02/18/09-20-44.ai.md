Refactoring patch in the reftable decoupling series, replacing Git's `st_mult()` with reftable-native overflow-safe allocation helpers.

This patch (8/18 in v6) continues the architectural separation of reftable from Git core by eliminating another Git-specific dependency - the `st_mult()` helper used in array allocation macros. The change introduces a new `reftable_alloc_size()` function that performs manual overflow checking before multiplication, returning an error rather than dying on overflow like `st_mult()` does. The implementation affects three key macros (`REFTABLE_ALLOC_ARRAY`, `REFTABLE_REALLOC_ARRAY`, and the inline `reftable_alloc_grow`) which now handle allocation size calculations internally with proper error propagation.

The changes maintain safety through explicit overflow checks while removing Git dependencies, consistent with the series' goals. The patch touches only `reftable/basics.h`, modifying allocation patterns that are fundamental to the reftable implementation but not affecting external behavior. This is a straightforward technical dependency removal that follows the established pattern of the series, replacing Git helpers with reftable-native equivalents while preserving functionality. The implementation appears thorough, with all allocation paths properly handling the new error case by setting `errno` and returning NULL when overflow occurs.
