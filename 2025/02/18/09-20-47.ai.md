This is part of Patrick Steinhardt's ongoing reftable library decoupling series (v6 11/18), continuing the systematic replacement of Git-specific components with reftable-native implementations. The patch introduces a new `reftable_rand()` function to abstract random number generation, moving away from Git's `git_rand()`.

The change creates a new system-level interface in `reftable/system.h` that returns a single unsigned integer, with the implementation initially still using Git's CSPRNG under the hood. This provides a clear boundary where external users of the reftable library could plug in their own RNG implementations. The patch updates two callsites in `reftable/stack.c` that were previously using `git_rand()` directly - one for backoff delay calculation during stack reloading and another for generating unique filenames.

This follows the series' established pattern of introducing reftable-specific abstractions while maintaining functional equivalence. The change is straightforward with minimal risk, affecting only internal reftable operations. Like previous patches in the series, this moves toward the goal of making the reftable library usable outside Git while preserving all existing behavior. The implementation currently maintains compatibility by wrapping Git's git_rand(), but the interface is now properly abstracted for future externalization.
