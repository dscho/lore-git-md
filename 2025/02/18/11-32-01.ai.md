This is a feature patch series introducing a "promisor-remote" protocol capability for Git's protocol v2, part of ongoing work to improve large object handling in client-server scenarios. The series has evolved through multiple versions with input from several contributors.

The core addition is a new protocol capability that allows servers to advertise promisor remotes to clients during clone/fetch operations. This enables clients to use the same promisor remotes that the server uses, potentially simplifying configuration compared to manually specifying remotes via `-c` options. The implementation includes:

1. Protocol v2 capability advertisement and negotiation
2. Configuration options (`promisor.advertise` and `promisor.acceptFromServer`) to control which remotes are shared
3. Security controls to validate advertised remotes against locally configured ones
4. A new technical document explaining the large object promisor (LOP) concept

Key technical changes in v5 include:
- Removal of earlier utility function patches (redact_non_printables)
- Case-sensitive URL comparison (changed from case-insensitive)
- Renamed `strvec_find_index()` to `remote_nick_find()`
- Test improvements including renaming 'server2' to 'lop' (Large Object Promisor)
- Documentation updates including new sections in the LOP design doc

The series appears well-tested with comprehensive test coverage in t5710, though some security aspects like remote name validation remain open for discussion. The architectural approach balances flexibility (multiple acceptance policies) with security (strict URL matching option). The accompanying design doc provides useful context for the protocol changes while acknowledging areas needing further discussion.
