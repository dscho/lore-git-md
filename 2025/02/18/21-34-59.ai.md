This is a bug report about HTTP authentication regression in Git 2.46+. The reporter Peter Georg identifies that since commit 610cbc1dfb ("http: allow authenticating proactively"), git-http-push fails to properly use credentials from netrc files in certain configurations.

The core issue manifests in two scenarios: when http.proactiveAuth is unset or set to "none", Git initially uses netrc credentials but later connections fail with empty credentials; when set to "auto" or "basic", Git ignores netrc entirely and prompts for credentials. The reporter provides a test case showing the behavior reverts to working properly when rolling back the problematic commit.

Key technical details include the specific error (return code 22 when accessing HTTPS URLs), the credential flow differences between versions, and the inclusion of verbose curl logs (with personal info redacted). The bug appears specific to the http-push operation and affects all versions from 2.46 onward. The reporter offers to assist with testing potential fixes.

This looks like a legitimate regression in HTTP authentication handling that breaks existing workflows relying on netrc files. The report is well-documented with clear reproduction steps, version comparisons, and diagnostic information, making it lacks only a proposed solution. The change in behavior around proactive authentication appears unintentional given it works correctly when reverting the commit.
