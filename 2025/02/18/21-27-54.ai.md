This is a bug report regarding the Git website's documentation links. Bede Skinner-Vennell points out that the release notes link for Git v2.48.1 on git-scm.com is broken because it incorrectly points to a `.txt` file in the `master` branch, which now uses `.adoc` extensions for documentation files after a recent change (commit 1f010d6bdf).

The report identifies two working alternatives: using either the version-tagged `.txt` file (which still exists for the release) or the new `.adoc` file in `master`. This appears to be a straightforward issue where the website's link generation needs updating to account for the documentation format change.

The report is clear and actionable, providing both the problematic URL and working alternatives. This seems like a simple but important fix for the website maintainers, as broken release note links could frustrate users trying to understand what changed in a specific version. The issue stems from an uncoordinated change between the documentation format migration and the website's link generation logic.
