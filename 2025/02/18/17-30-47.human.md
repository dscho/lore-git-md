This is a follow-up discussion about the shell script userdiff pattern enhancement, specifically addressing function body recognition in shell scripts. Eric Sunshine chimes in to clarify a technical point from Johannes Sixt's earlier feedback.

The key point is that POSIX technically allows function bodies to be any compound command (not just the common `{...}` or `(...)` forms), as demonstrated by the example `foo() echo nothing`. However, Eric notes this is likely an uncommon pattern in practice and probably not worth special handling in the diff machinery.

The comment shows the thread's attention to technical accuracy while maintaining practical focus - acknowledging a technically correct but rarely used shell feature that could be safely excluded from the pattern matching. This comes as the patch series (now in v2) nears completion, having already addressed more common shell function variants through earlier review feedback.
