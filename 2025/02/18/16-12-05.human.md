Performance optimization in refs subsystem, part of a series addressing redundant checks during ref updates. This patch specifically tackles the inefficiency of repeatedly verifying common refname prefixes (like "refs/heads/") when checking reference availability during batch operations.

The change introduces a `strset` to track already-verified prefixes, avoiding redundant checks. Benchmarks show a 1.58x speedup for the reftable backend when creating 10,000 references in a repository with 100,000 existing refs. The files backend doesn't see similar gains yet since it still performs per-reference checks, though the infrastructure is now in place to optimize it similarly.

This builds on Patrick Steinhardt's earlier work in the series, with Karthik Nayak now implementing the prefix deduplication. The implementation is clean and focused, maintaining all existing verification semantics while eliminating unnecessary work. The thread discussion suggests this optimization could be extended to the files backend in future work.
