This patch continues the reftable library's architectural separation from Git core by replacing Git's `sleep_millisec()` helper with direct use of POSIX `poll()`. The change appears in `reftable/stack.c` where millisecond delays are needed during retry logic for stack reload operations.

The patch makes a straightforward substitution, replacing one line that called Git's `sleep_millisec(delay)` with an equivalent `poll(NULL, 0, delay)` call. The commit message notes this is the current implementation approach anyway, and that while a more direct millisecond sleep would be ideal, POSIX doesn't provide one. 

This change follows the series' established pattern of removing Git-specific utility functions in favor of POSIX equivalents or reftable-native implementations. It affects the same retry backoff path that was modified in patch 11/18 to use `reftable_rand()` instead of `git_rand()`. The change is minimal (1 line modified) and maintains identical behavior while further reducing Git dependencies in the reftable code.

- Replaces Git's `sleep_millisec()` with POSIX `poll()`
- Affects retry delay logic in `reftable_stack_reload_maybe_reuse()`
- Follows same backoff path modified in previous patch

- Continues systematic removal of Git utility functions
