This is part 2/3 in Christian Couder's v5 series implementing promisor remote advertisement security controls. The patch adds two new security levels to the `promisor.acceptFromServer` configuration option, giving clients more granularity in which advertised remotes they'll accept.

The new "KnownName" mode accepts remotes that match existing client-side remote names (useful in trusted corporate environments where names are stable but URLs might change). The stricter "KnownUrl" mode requires both name and URL to match existing client-side configurations. The patch includes thorough documentation updates explaining the security tradeoffs between these options and the existing "All"/"None" modes.

Implementation-wise, it adds new enum values, refactors the remote filtering logic to check names/URLs against client configuration, and includes comprehensive tests verifying the new behaviors. The changes integrate cleanly with the existing promisor-remote infrastructure while maintaining the thread's focus on security hardening.

This appears to be a well-considered addition to the series, providing meaningful security controls without overcomplicating the interface. The test coverage is particularly thorough, validating both successful acceptance cases and rejection scenarios where names/URLs don't match.
