This is a design documentation update for the Large Object Promisors (LOP) feature, addressing feedback from Junio Hamano about clarifying the practical aspects of object storage usage and client offloading behavior.

Christian Couder responds to concerns about the "magical object storage" characterization by adding concrete examples of existing storage solutions (S3, GCP Bucket, MinIO) and explaining that even suboptimal LOP usage can provide benefits through simplified client-side configuration and reduced server hosting costs. He positions the current document as establishing foundational use cases while deferring deeper performance optimization discussions to the implementation phase.

The email also addresses client-side offloading scenarios, particularly around newly-created objects versus fetched ones. Couder acknowledges the open questions around direct client-to-LOP transfers (bypassing main remote validation) but argues these are premature to resolve in the design phase. He adds clarifying text that marks these as topics for future discussion during implementation, while maintaining the document's focus on establishing the LOP concept's viability.

Key technical points surfaced:
- Explicit linkage between the design doc and real-world object storage backends
- Clearer articulation of LOP's value proposition even without optimization
- Open questions around client-initiated offload security model
- Intent to handle performance optimization details during implementation
- Maintained distinction between current design scope and future refinement needs
