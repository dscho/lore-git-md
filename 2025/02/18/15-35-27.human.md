Shell function recognition improvement for diffs

This is a focused bugfix and feature enhancement to Git's shell script function detection in diffs. Moumita's patch extends the Bash userdiff pattern to better recognize various shell function syntax forms that were previously missed.

The changes address several common shell scripting patterns that weren't properly highlighted in diffs, including `function foo()` declarations, multi-line definitions with backslashes, and functions with extra whitespace in their declarations. The implementation builds on the existing Bash pattern infrastructure in `userdiff.c` rather than creating a new driver, following review feedback from Johannes Sixt.

The 34-line diff shows careful attention to shell syntax variants while maintaining backward compatibility. It now handles both POSIX and Bash/Ksh function declaration styles, along with improved recognition of function bodies that start with subshells or test constructs. The patch also enhances tokenization of shell elements like variables, numbers, and operators to prevent false splits in diffs.

This appears to be a well-considered improvement to Git's shell script diff capabilities, with the author having incorporated technical feedback from an experienced contributor. The changes are contained and focused, though the patch doesn't include tests (which may be coming in a follow-up). Shell script authors working with complex function definitions will likely appreciate the more accurate diff highlighting this enables.
