Shell function recognition improvement for Git diffs

This is a v2 patch from Moumita Dhar that extends Git's shell script function recognition in diffs, following up on Johannes Sixt's detailed review of the initial version. The patch modifies the existing Bash userdiff pattern rather than creating a new shell driver, addressing several limitations in how Git currently detects shell functions in diffs.

The key improvements include:
- Better handling of different function declaration styles (both `foo()` and `function foo` forms)
- Support for multi-line function definitions using backslashes
- More flexible whitespace handling in function declarations
- Recognition of additional shell syntax like command-line options and numeric constants

The implementation remains focused in `userdiff.c` with a 34-line change that both extends the function detection patterns and improves tokenization of shell elements. The commit message has been tightened from v1 to be more technically precise, dropping some marketing language while keeping the essential technical details.

This appears to be a well-motivated improvement to Git's diff capabilities for shell scripts, with the author responding to review feedback by refining both the implementation and documentation. The changes look focused and the testable claims seem reasonable, though the patch would benefit from accompanying test cases to verify the new patterns against various shell dialects and edge cases.
