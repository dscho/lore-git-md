Bugfix for `git merge-tree --stdin` deadlock issue. This is the first patch in Phillip Wood's v2 series addressing stdin processing in merge-tree.

The patch fixes a deadlock that occurs when a process tries to read merge-tree's output before closing its input. The root cause is that merge-tree wasn't flushing stdout between merge operations while processing stdin input. Phillip adds explicit flushing with `maybe_flush_or_die()` after each merge operation.

The commit includes benchmark results showing the performance impact is negligible (less than 0.5% difference between flushing and not flushing). The change enables use cases like cherry-picking sequences of commits via stdin without deadlocking.

This is a straightforward fix that addresses a real usability issue while maintaining performance. The patch is well-documented with clear commit message and benchmark data, and builds on previous discussion in the thread about stdin processing reliability. It's part of a larger series that has already seen thorough review from merge expert Elijah Newren.
