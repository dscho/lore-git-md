This is part 7/18 of Patrick Steinhardt's ongoing series to decouple the reftable library from Git core dependencies. The patch continues the systematic replacement of Git-specific error handling by converting remaining `BUG()` calls in the reftable library to proper error returns.

The changes focus on three areas:
1. Replacing a `BUG()` in the indexed table iterator with `REFTABLE_API_ERROR` when unsupported seek operations are attempted
2. Removing `BUG()` checks in reader reference counting, as the cases they guarded would already indicate undefined behavior
3. Converting writer validation checks to return `REFTABLE_API_ERROR` for invalid block sizes and type mismatches

The patch follows the established pattern of the series by maintaining the same safety guarantees while removing Git-specific assertions. The changes are straightforward and well-contained, touching only internal implementation details with no user-facing impact. As with previous patches in the series, this appears to be a clean, focused change that advances the overall goal of making reftable usable as a standalone library.
