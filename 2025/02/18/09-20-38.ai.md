This is part of Patrick Steinhardt's reftable modularization series (v6 2/18), specifically targeting the removal of Git-specific dependencies from the reftable library. The patch replaces `write_in_full()` with a new `reftable_write_data()` implementation in stack.c, continuing the architectural separation effort.

The new function provides equivalent functionality to `write_in_full()` but is implemented directly in the reftable codebase rather than relying on Git's compat-util.h. It handles partial writes and retries on EAGAIN/EINTR errors, returning reftable-specific error codes (REFTABLE_IO_ERROR). The change affects three write operations in stack.c: two for table list updates and one during compaction.

This is a straightforward refactoring that follows the pattern established in earlier patches of the series. The implementation appears robust, maintaining the same error handling semantics while removing the Git dependency. As with other patches in this series, the change is mechanical and focused - it doesn't introduce new functionality but enables the broader goal of making reftable usable outside Git.

Key technical details for future reference:
- New function: `reftable_write_data()` in stack.c
- Replaces all `write_in_full()` calls in stack.c
- Maintains same write semantics but with reftable error codes
- Part of systematic removal of Git dependencies (compat-util.h, BUG(), etc.)
- Touches core reftable file writing paths but doesn't change behavior
