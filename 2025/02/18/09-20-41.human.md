This is part of Patrick Steinhardt's ongoing reftable library decoupling effort, specifically patch 5/18 in the v6 series. The change removes a dependency on `BUG()` calls within the reftable library by converting `reftable_record_init()` to return an error code (REFTABLE_API_ERROR) when encountering unknown record types, rather than aborting the program. 

The patch modifies the function signature and updates all callers to handle the new error condition, including several test files. This continues the series' pattern of removing Git-specific constructs from the reftable library to make it more self-contained and suitable for use by other projects like libgit2. The changes are straightforward and mechanical, with no user-facing impact.

The patch appears well-executed, with consistent error handling added across all call sites and corresponding test updates. It follows the established approach seen in earlier patches of this series, which has already received positive feedback from multiple core maintainers. This is another incremental but important step toward the goal of a fully standalone reftable implementation.
