This is a technical discussion about cross-compilation path handling in Git's build system, specifically focusing on shell path detection in Meson builds. Eli Schwartz (Gentoo maintainer) weighs in on Patrick Steinhardt's proposed solutions for properly separating host and target paths when cross-compiling Git.

Eli makes several key points: First, he notes that `/bin/sh` is the portable POSIX path that should be used as the default, since it works across both merged- and split-usr systems (unlike `/usr/bin/sh` which fails on split-usr setups). He observes this isn't just a cross-compilation issue - Gentoo encounters the same problem when building binary packages for different filesystem layouts on the same architecture.

Regarding the cross-file approach, Eli argues that if the goal is solely to detect paths for embedding (not execution), then using `find_program(native: false)` with cross files is acceptable since there's no conflict between build-time and runtime paths in this case. However, he suggests that for maximum reliability, the Meson build should simply hardcode `/bin/sh` as the default rather than trying to detect it.

The email also highlights real-world implications for Gentoo packaging, where the current behavior causes `/usr/bin/sh` paths to leak into binary packages built on merged-usr systems. Eli CCs Sam James (another Gentoo maintainer) as this will require packaging adjustments regardless of how the upstream fix is implemented.

This continues the thread's progression toward a solution that handles both cross-compilation and same-architecture packaging cases, with Eli providing practical distribution maintainer perspective on the path standardization needs.
