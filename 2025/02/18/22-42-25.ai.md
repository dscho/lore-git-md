Bugfix for gitk's filename encoding handling, specifically addressing Japanese filenames during merge conflicts. This is the first of two patches in the series from Kazuhiro Kato.

The patch makes a straightforward change to the gitk Tcl/Tk script, forcing the encoding system to UTF-8 by adding `encoding system utf-8` before the existing encoding setup code. This appears to be a foundational fix for the broader issue of garbled Japanese filenames, ensuring Tcl/Tk uses UTF-8 encoding by default rather than potentially falling back to a system default that might not handle the filenames correctly.

The change is minimal (just one line added) and focused on the encoding system initialization. It precedes the existing code that checks and sets the git encoding, suggesting this is establishing a required baseline before the more specific encoding handling that follows. The patch doesn't include tests, which might be worth noting since encoding issues can be platform-dependent.

This appears to be the first step in fixing the reported issue where Japanese filenames appear garbled during merge conflict resolution in gitk. The simplicity of the change suggests the author has identified a clear root cause in the encoding initialization.
