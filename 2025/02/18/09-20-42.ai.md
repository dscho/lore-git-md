This is part of Patrick Steinhardt's ongoing reftable library decoupling effort (patch 6/18 in v6 series), continuing the systematic removal of Git-specific code patterns. The patch converts `reftable_record_cmp()` from using Git's `BUG()` macro to returning an error code when comparing records of different types, making the behavior more library-appropriate by allowing callers to handle errors gracefully.

The change affects several key components:
- Modifies `reftable_record_cmp()` signature to return an error code and take an output parameter for the result
- Updates all callers (merged.c, pq.c) to handle the new error return
- Adapts priority queue operations to propagate comparison errors
- Updates unit tests to verify the new error handling paths

The patch follows the series' established pattern of replacing Git-specific behaviors (in this case, `BUG()`) with reftable-native error handling. It touches core comparison logic used throughout the reftable stack (records, merged iterators, priority queues) but maintains the same comparison semantics when types match. The extensive test updates demonstrate thorough validation of both successful comparisons and error cases.

This is a well-contained change that advances the series' goal of making reftable usable as a standalone library while preserving existing functionality. The modifications are focused and mechanical, with clear correspondence between the API change and its propagation through dependent code.
