This is a discussion about NFSv4 compatibility issues with Git's file permission handling during packfile operations. The thread explores a specific failure case where Git creates temporary packfiles with read-write access (O_RDWR) but then sets them to read-only (0444), which causes problems during NFSv4 state recovery after server failovers.

The key technical details are:
- Git's current behavior of opening files with O_RDWR then setting 0444 permissions is POSIX-compliant
- NFSv4 re-evaluates file access permissions during state recovery, unlike POSIX
- The error manifests as "-13" (access denied) when NFSv4 tries to reopen the file with original permissions
- Similar issues affect other software like zsh and Emacs
- The discussion considers whether changing Git's behavior would help (unlikely) versus fixing NFS server behavior

The conversation suggests this is fundamentally an NFSv4 compliance issue rather than a Git bug, though it impacts Git operations during failover scenarios. The thread references POSIX standards for file operations and consistency guarantees that Git relies upon.
