Refactoring patch in Patrick Steinhardt's reftable separation series, replacing Git's `xmmap()` with direct `mmap()` usage. This continues the architectural work to decouple reftable from Git core dependencies, specifically targeting memory mapping functionality in the blocksource implementation.

The change removes two problematic aspects of `xmmap()`: its fatal error handling (which now properly propagates REFTABLE_IO_ERROR) and its tight coupling to Git internals. The new implementation uses either system `mmap(3p)` or Git's `git_mmap()` wrapper where needed, maintaining compatibility while removing the direct dependency. The patch modifies error handling in `reftable_block_source_from_file()` to clean up resources properly when mapping fails.

This is a straightforward mechanical change within the established pattern of the series, touching only blocksource.c with 11-line modification. It follows the same approach seen in earlier patches (like the write_in_full replacement) where Git-specific helpers are systematically replaced with reftable-native or POSIX-compatible alternatives. The change maintains all existing functionality while progressing the series' goal of making reftable usable by external projects.
