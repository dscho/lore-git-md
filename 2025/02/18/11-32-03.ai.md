This is a feature patch in the promisor-remote/LOP series (v5 2/3) that adds more granular control over which promisor remotes a client will accept from a server. It introduces two new values for the `promisor.acceptFromServer` config option: "KnownName" and "KnownUrl".

The patch extends the existing binary choice (accept all/none) to allow clients to accept remotes that match either just the name ("KnownName") or both name and URL ("KnownUrl") of already-configured remotes. The "KnownUrl" option is positioned as the more secure choice, while "KnownName" is suggested for trusted corporate environments where names are stable but URLs might change.

Implementation-wise, the patch:
- Adds new enum values `ACCEPT_KNOWN_NAME` and `ACCEPT_KNOWN_URL`
- Introduces a `remote_nick_find()` helper for case-insensitive name matching
- Modifies `should_accept_remote()` to implement the new logic
- Updates `filter_promisor_remote()` to handle the new cases
- Adds comprehensive tests in t5710 that verify:
  - Basic acceptance behavior for both new options
  - Rejection when names/URLs don't match
  - Warning messages for URL mismatches

The changes build on the existing promisor remote infrastructure while maintaining the security model established in earlier patches. The test coverage is thorough, exercising both happy paths and edge cases for the new configuration options. This appears to be a well-considered addition to the series that provides more flexibility while preserving security controls.
