Refactoring patch in the `git merge-tree --stdin` series, focusing on code simplification.

This is the second patch in Phillip Wood's v2 series (2/5), continuing the cleanup work on `git merge-tree --stdin` processing. The patch removes redundant error handling in the stdin` path of `cmd_merge_tree()`, where the return value from `real_merge()` was being checked unnecessarily. The author explains that `real_merge()` only returns 0 or 1 (dying on negative values), and the exit status is ignored in `--stdin` mode anyway since status is reported via stdout. The change simplifies the code by:
- Removing the unused `result` variable
- Dropping the dead check for negative return values
- Keeping the existing calls to `real_merge()` but ignoring their return values
- Maintaining the same behavior for non-stdin cases where the return value is still used

The patch builds on previous work in the thread that established `--stdin` mode's exit behavior (always 0) and added stdout flushing between merges. It's a straightforward cleanup that doesn't affect functionality but makes the code more maintainable by removing dead paths. The change is consistent with the series' focus on improving the reliability and clarity of the stdin processing logic while maintaining the separation between plumbing and porcelain behavior.
