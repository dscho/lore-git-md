This is a documentation patch adding a technical design document for the "Large Object Promisors" (LOP) feature, which is part of the ongoing promisor-remote/LOP series (now at v5). The 656-line document outlines a comprehensive approach to handling large blobs in Git repositories by using dedicated promisor remotes.

The design addresses several pain points with large binary files in Git, proposing to store them separately from main repositories while maintaining accessibility. Key aspects include:
- Using special promisor remotes (LOPs) just for large blobs
- Server-side offloading of large blobs to object storage (like S3)
- Protocol negotiation for clients to access LOPs directly
- Configurable size thresholds for blob offloading
- Security considerations for LOP access

The document carefully scopes what's included (server-side improvements) versus what's out of scope (client-side optimizations, storage backend implementations). It provides rationale for each design decision and acknowledges limitations, particularly around backward compatibility with older clients. The FAQ section thoughtfully addresses potential concerns about security, multiple LOP configurations, and performance impacts.

This appears to be a well-considered design document that builds on the protocol v2 capability work from earlier patches in the series. The level of detail suggests serious engineering effort behind the proposal, though actual implementation would need to validate the concepts. The document would serve as valuable reference material for both reviewers and future maintainers of this feature.
