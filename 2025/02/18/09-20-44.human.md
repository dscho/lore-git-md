This is part 8/18 of Patrick Steinhardt's ongoing series to decouple the reftable library from Git core dependencies. The patch focuses on removing Git's `st_mult()` helper from array allocation macros in `reftable/basics.h`.

The change replaces Git's overflow-checking `st_mult()` (which aborts on overflow) with a new `reftable_alloc_size()` function that performs manual overflow detection and returns an error instead. The macros `REFTABLE_ALLOC_ARRAY` and `REFTABLE_REALLOC_ARRAY` are updated to use this new helper, setting `errno` to `ENOMEM` when overflow occurs rather than dying. The `reftable_alloc_grow()` function is similarly modified.

This continues the series' pattern of replacing Git-specific components with reftable-native implementations while maintaining safety. The change is internal to the reftable library and doesn't affect user-facing behavior. The patch appears well-contained, with thorough handling of error cases and no obvious gaps in the overflow protection logic.

As with previous patches in the series, this moves the reftable library closer to being usable as a standalone component outside of Git. The change is relatively straightforward and unlikely to be controversial given the series' momentum and prior approvals from core maintainers.
