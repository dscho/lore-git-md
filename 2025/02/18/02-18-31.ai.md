This is a documentation patch discussion about where to place details on submodule merge behavior. Elijah Newren responds to Lucas Seiki Oshiro's RFC patch that proposed adding documentation about two special submodule merge cases to `git-merge.adoc`. 

Newren agrees the behavior should be documented but questions the placement, noting that:
1) The merge_submodule() function lives in merge code (not submodule code) since 2018
2) The behavior applies to all commands using merge machinery (cherry-pick, rebase, etc.), not just `git merge`
3) The current wording ties too closely to `git merge` specifics (MERGE_HEAD)
4) Suggests Documentation/merge-strategies.txt might be a better home

He provides specific wording improvements for the "referred by it" phrasing and acknowledges the value of documenting this non-obvious behavior that caused real user confusion. The discussion highlights the challenge of documenting merge machinery behavior that spans multiple commands while maintaining accuracy across contexts. The thread remains open on where exactly this documentation should live and how to phrase it generically enough for all merge machinery users.
