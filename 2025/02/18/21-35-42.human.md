This is a discussion about NFSv4 compatibility issues with Git's file permission handling during packfile operations. Bryan Maloney responds to Brian Carlson's analysis of a bug where NFSv4 failovers cause "Bad file descriptor" errors during `git clone`. 

The core issue occurs when Git creates packfiles with read-write permissions (O_RDWR) but then changes them to read-only (0444) for safety. NFSv4's state recovery mechanism re-evaluates file access during failovers, hitting a permission mismatch since it tries to reopen the file with write access. Maloney clarifies this is expected NFSv4 behavior per the spec, not a filesystem-specific quirk.

Carlson had previously noted this violates POSIX guarantees about permission evaluation timing, suggesting the NFS server might need synchronization adjustments. The thread reveals a fundamental tension: Git's security model relies on POSIX semantics (where post-open permission changes shouldn't affect access), while NFSv4's stateful protocol requires revalidation. Both agree the issue affects other software (zsh, Emacs) and alternative Git implementations, making a client-side fix insufficient. The discussion remains open-ended, highlighting a systemic compatibility gap between POSIX expectations and NFSv4's design.
