This is a refactoring patch in the performance optimization series for the refs subsystem, specifically addressing iterator lifecycle management. The patch separates iterator lifecycle from iteration by introducing `ref_iterator_free()` to replace `ref_iterator_abort()`, allowing for potential iterator reuse and simplifying calling patterns. The changes affect multiple backend implementations (files, packed, reftable) and related infrastructure.

Key technical details:
- New `ref_iterator_free()` API replaces `ref_iterator_abort()`, with corresponding changes to all iterator_vtable implementations
- Similar changes made to `dir_iterator` infrastructure (though not explicitly mentioned in commit message)
- Iterator implementations now use `release` vtable method rather than `abort`
- Return value of abort functions removed since they were unused
- Base iterator cleanup consolidated in `ref_iterator_free()` rather than backend-specific code
- Changes visible in files-backend.c, packed-backend.c, reftable-backend.c, and iterator infrastructure files

The patch appears to be a clean implementation of the iterator lifecycle changes discussed earlier in the thread, though Karthik Nayak notes some minor questions about the dir_iterator changes and a potential optimization in packed-backend.c. The changes align with the series' goal of enabling iterator reuse for performance while simplifying the calling patterns.
