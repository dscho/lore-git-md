This is a refactoring patch in a performance optimization series for the refs subsystem, specifically addressing iterator lifecycle management. The patch separates iterator lifecycle from iteration, replacing the automatic cleanup at iteration end with explicit `ref_iterator_free()` calls. This change enables future iterator reuse and simplifies calling patterns by removing the need for careful `ref_iterator_abort()` timing.

The patch touches multiple iterator implementations across different backends (files, packed, reftable) and also updates the related `dir_iterator` code. Karthik Nayak provides review feedback, noting the cleaner implementation but questioning some details like the `dir_iterator` changes not being mentioned in the commit message and a potential optimization in `packed-backend.c`.

The changes appear well-motivated and technically sound, though Karthik's comments suggest some minor documentation and implementation tweaks could improve clarity. This is part of a larger effort to optimize refname availability checks, with this particular change laying groundwork for iterator reseeking capabilities mentioned in the thread context.
