This is a documentation clarification in the final patch of the OS version advertisement feature series. Junio Hamano points out that while the patch updates the byte range notation in gitprotocol-v2.txt from "32 < x < 127" to "33 <= x <= 126", it accidentally drops the "except space" qualifier that was present in the original text. He notes this is purely a documentation nit since the actual byte range restrictions haven't changed - spaces (32) are still excluded from the allowed characters in agent capability strings. The maintainer considers this minor enough that a resend isn't required, effectively giving his approval while noting the small oversight.

The thread context shows this comes after extensive review of the feature that adds OS information to Git's protocol capability string (format "package/version-os"). The implementation has already addressed all major technical concerns including string sanitization, platform-specific handling, and test coverage. This final patch focuses on updating the protocol documentation to reflect the new format, with Junio's comment being the only remaining minor clarification needed.
