This is the second patch in a bugfix series addressing Japanese filename encoding issues in gitk's merge conflict display. Building on the first patch's UTF-8 encoding system initialization, this change specifically handles filename conversion during merge conflict parsing.

The patch modifies `gitk-git/gitk` to properly decode filenames when processing merge diffs. Key changes include:
1. Splitting the filename handling into raw and decoded versions, using `encoding convertfrom` to properly handle UTF-8 filenames
2. Applying the same conversion to diff content lines
3. Maintaining the raw filename for internal processing while displaying the decoded version

The changes are focused on the `parseblobdiffline` procedure which handles merge conflict display. The author maintains the existing logic structure while inserting the encoding conversion at key points where filenames and content are displayed. No test coverage is included, which may be notable given the platform-specific nature of encoding issues.

This completes the two-part fix for the reported issue where Japanese filenames appeared garbled during merge conflicts.
