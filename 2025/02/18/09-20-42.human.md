This is part 6/18 of Patrick Steinhardt's series to decouple the reftable library from Git core, continuing the architectural separation effort. The patch converts `reftable_record_cmp()` from using Git's `BUG()` macro to returning an error code when comparing records of different types, making the behavior more library-friendly.

The change affects several components that use record comparison, including the priority queue implementation in `pq.c` and the merged iterator in `merged.c`. The patch does thorough updates to callers to properly handle the new error returns, along with corresponding test updates to verify the new behavior.

This follows the series' pattern of replacing Git-specific error handling with reftable-native approaches while maintaining safety through explicit checks. The change is well-contained within the reftable implementation with no user-facing impact, and includes comprehensive test coverage of the modified error paths.

The patch appears technically sound and aligns with the series' goal of making reftable usable as a standalone library. It addresses a real limitation in the error handling while maintaining the same comparison semantics when types match.
