This is part of Patrick Steinhardt's ongoing series to decouple the reftable library from Git core dependencies. Patch 10/18 continues the architectural separation by removing the last remaining use of Git's `ARRAY_SIZE()` macro in the reftable reader.

The change is straightforward - it replaces `ARRAY_SIZE(sections)` with the standard C idiom `sizeof(sections) / sizeof(*sections)` in a debug printing function. This affects only one location in `reftable/reader.c` where the code iterates through an array of section types. The patch maintains identical functionality while eliminating another Git-specific helper.

This follows the series' established pattern of systematically replacing Git infrastructure with standard C or reftable-native equivalents. While minor, it contributes to the overall goal of making the reftable library usable outside Git by removing dependencies on Git's compatibility utilities. The change is low-risk as it touches only debug code and uses a well-established C pattern for array iteration.

Key technical details for future reference:
- Removes final `ARRAY_SIZE()` usage in reftable
- Replaces with standard C array size calculation
- Affects debug printing path in `reftable_reader_print_blocks()`
- Maintains same iteration behavior over `sections` array
- Part of broader effort to eliminate Git-specific code from reftable
