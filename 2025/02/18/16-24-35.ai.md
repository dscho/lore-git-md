This is a bugfix patch in Phillip Wood's v2 series addressing deadlock issues in `git merge-tree --stdin`. The patch specifically fixes a scenario where a process reading merge-tree's output could deadlock if it tries to read before merge-tree closes its input. The root cause is that merge-tree wasn't flushing stdout between merge operations while processing stdin input.

The solution adds a `maybe_flush_or_die()` call after each merge operation in stdin mode, ensuring output is flushed before reading the next input line. The commit includes benchmarking data showing the performance impact is negligible (less than 0.5% difference), with the safety improvement coming at effectively no cost. The change is minimal - just two lines added to `builtin/merge-tree.c` - but solves a real usability issue where scripts couldn't reliably process merge-tree's output while feeding it input.

This patch builds on the thread's established context of improving merge-tree's stdin handling, with Elijah Newren having previously confirmed the deadlock issue. The v2 iteration maintains all previous fixes while incorporating feedback about documentation and behavior. The change is straightforward and well-justified, with clear performance data showing the fix doesn't introduce overhead.
