Review feedback on worktree HEAD-reading behavior in fsck validation series.

This is part of the ongoing bugfix series enhancing `git fsck`'s packed-refs validation (currently at v5). Karthik Nayak provides review feedback on patch 2/8, which aims to avoid premature termination during ref verification by skipping HEAD parsing.

The patch introduces `get_worktrees_without_reading_head()` to prevent `git refs verify` from dying when encountering malformed packed-refs during HEAD checks. While the technical approach (using an existing internal function) is sound, Karthik notes the commit message could better explain:
1) How this fits into the larger validation effort
2) What specific failure cases it prevents (like newline checks in packed-refs)
3) The consistency guarantees being preserved

The review suggests clarifying both the commit message and function documentation to explicitly state that skipping HEAD parsing allows complete ref verification without being interrupted by HEAD-related packed-refs issues. This is a documentation-focused refinement of an otherwise technically complete patch in a mature series.
