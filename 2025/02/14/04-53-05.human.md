Bugfix patch adding packed-refs entry validation to `git fsck`. This is part 6/8 in a series hardening `git fsck`'s validation of packed-refs files, now focusing on individual entry validation.

The patch introduces detailed checks for each line in packed-refs files:
- Main ref lines must have a valid OID followed by whitespace and a proper refname
- Peeled lines (starting with '^') must contain a valid OID with no trailing garbage
- Refnames are checked for NUL bytes and proper formatting

The implementation adds two new helper functions (`packed_fsck_ref_main_line` and `packed_fsck_ref_peeled_line`) that perform these validations and report errors through the existing fsck infrastructure. A new `FSCK_MSG_BAD_PACKED_REF_ENTRY` error type is introduced for reporting malformed entries.

Test coverage is expanded with a comprehensive test case that exercises various invalid packed-refs entry formats, including:
- Short/invalid OIDs
- Missing whitespace after OID
- Malformed refnames
- Invalid peeled references
- Trailing garbage in peeled lines

The patch appears well-structured and thorough, with clear error messages that will help users diagnose packed-refs corruption. It builds logically on the previous patches in the series that added header validation and NUL character detection. The implementation follows Git's existing patterns for ref validation and error reporting.
