The thread addresses a build system regression affecting Git's documentation. A December 2024 commit (a38edab7c8) inadvertently changed the default behavior in Documentation/Makefile - instead of building full documentation (HTML and man pages), it would only generate configuration files. This happened because the commit placed config file targets above the 'all' target definition, causing make to use the first target as default.

Adam Dinwoodie submitted a straightforward fix that moves the 'all: html man' declaration back to the top of the Makefile, restoring the expected documentation build behavior. The change is minimal (4 lines) and well-explained, clearly identifying both the regression and its cause. This correction will help anyone building Git's documentation locally get the complete output they expect.
