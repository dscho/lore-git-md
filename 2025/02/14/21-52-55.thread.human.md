This thread addresses a regression in Git's documentation build system where a recent change inadvertently modified the default build target behavior. Adam Dinwoodie identified that commit a38edab7c8 (December 2024) caused the Documentation/Makefile to only produce configuration files by default, rather than building the full documentation (HTML and man pages) as intended. The issue occurred because config file targets were placed above the 'all' target definition.

Maintainer Junio Hamano has reviewed the proposed fix and agrees with the functional goal of restoring complete documentation builds. However, he suggests an implementation refinement to follow project conventions: using an empty double-colon `all::` rule at the file's start (a pattern seen in t/Makefile and the main Makefile) rather than simply moving the target definition. This approach makes the default target explicit and helps prevent similar regressions. Junio provided a concrete diff showing both the new empty rule and the conversion of the existing single-colon rule to double-colon syntax.

The change affects anyone building Git's documentation locally, with no technical objections remaining. The thread now awaits Adam's revised patch incorporating Junio's feedback about the Makefile rule syntax. This appears to be a straightforward documentation build system improvement that maintains backward compatibility while adopting more robust project conventions for phony targets.
