Refactoring patch in the packed-refs validation series, addressing worktree safety during verification.

This patch modifies how worktrees are accessed during `git refs verify` to avoid triggering packed-refs validation prematurely. Currently, `get_worktrees()` reads HEAD information which may cause the program to die if the packed-refs file has formatting issues (specifically missing newlines), even though the verification process should continue checking other parts of the file. The solution introduces `get_worktrees_without_reading_head()` which uses an existing internal function to skip HEAD parsing.

The change is minimal (12 lines total) but important for the series' goal of comprehensive packed-refs validation. It builds on commit 465a22b338 which originally added the internal skip-HEAD capability. Reviewer Karthik Nayak suggests improving the explanation of why skipping HEAD matters for consistency checking, particularly in the new function's documentation.

Key technical points:
- Adds new public API `get_worktrees_without_reading_head()`
- Modifies `builtin/refs.c` to use this when verifying refs
- Preserves all existing functionality while avoiding premature validation failures
- Part of ensuring worktree safety in the packed-refs verification pipeline

The patch appears well-contained and addresses a specific technical requirement of the larger series. The reviewer's documentation suggestions would help future readers understand the context better, but the core technical change seems sound.
