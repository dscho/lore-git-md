Bugfix patch (v4 3/8) in the `git fsck` packed-refs validation series, focusing on filetype verification. This patch adds explicit checks that the packed-refs file is a regular file, not a symlink or other special file type.

The implementation uses `open_nofollow()` to detect symlinks (though Windows compatibility remains an open question), reporting errors via the existing `FSCK_MSG_BAD_REF_FILETYPE` mechanism. The test suite is updated with a symlink test case, though the author acknowledges a typo in the test filename ("packed-refs-bak" vs "packed-refs-back") that will be fixed in the next version.

Key technical points:
- Adds filetype validation to the packed-refs fsck checks
- Uses `open_nofollow()` for symlink detection (with Windows limitations)
- Maintains existing behavior for missing files (ENOENT)
- Reports errors through fsck's reporting infrastructure
- Includes test case for symlink detection

The patch is part of a larger series adding comprehensive validation to packed-refs, with this component specifically addressing filetype safety. Reviewer Karthik Nayak has provided feedback on the test case accuracy and error reporting scope, which the author plans to address in the next iteration. The implementation builds on previous work in the series while maintaining backward compatibility.
