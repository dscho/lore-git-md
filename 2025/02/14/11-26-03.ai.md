This is a technical discussion about enabling progress reporting in the bundle-uri HTTPS downloads while handling error output cleanly. The thread continues Toon Claes' earlier patch series that attempted to show progress during bundle downloads by letting git-remote-https write to stderr. Jeff King had pointed out this causes test failures because fatal errors from the child process (when bundles are missing) now appear in the output when they were previously suppressed.

The current email explores potential solutions to this dilemma:
1. Filtering child stderr to suppress fatal errors (considered hacky)
2. Overriding die() in the child (deemed impractical)
3. Jeff's suggestion of machine-readable progress over stdout with formatted output by the parent

Toon proposes two possible machine-readable formats for progress reporting:
- A structured "progress <size> <total> <throughput>" approach
- A "log"-prefixed text approach where the parent handles formatting

The core challenge is maintaining clean error handling while enabling progress reporting, with the discussion focusing on stdout-based solutions that would require protocol changes between parent and child processes. The email seeks clarification on implementation details and asks for examples of similar solutions.
