This is a bugfix patch (6/8 in the series) that adds consistency checking for individual entries in packed-refs files. It builds on the previous work to validate packed-refs headers and file types, now focusing on the content of each reference entry.

The patch introduces two new helper functions (`packed_fsck_ref_main_line` and `packed_fsck_ref_peeled_line`) that validate:
1. Main reference lines (checking OID format, spacing, and refname validity)
2. Peeling lines (verifying the peeled OID format and absence of trailing garbage)

Key technical additions include:
- New `FSCK_MSG_BAD_PACKED_REF_ENTRY` error type
- Integration with the `fsck` infrastructure to report malformed entries
- Comprehensive test coverage of various invalid cases (short OIDs, missing spaces, bad refnames, garbage after peeled OIDs)

The implementation follows the pattern established earlier in the series, using line-number tracking and detailed error reporting. The test cases demonstrate detection of:
- Invalid OIDs
- Missing spaces between OID and refname
- Malformed refnames (trailing dots, extra spaces)
- Invalid peeled OIDs
- Trailing garbage after peeled OIDs

This patch completes the core validation logic for packed-refs content, working in conjunction with the earlier header and filetype checks. The series appears technically sound with thorough test coverage, addressing all known edge cases for packed-refs corruption detection.
