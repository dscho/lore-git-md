Feature implementation: OS version in agent capability string

This is the final patch in Usman Akinyemi's series to include OS information in Git's protocol capability string. The implementation extends the existing `agent` capability format from "package/version" to "package/version os" (e.g., "git/1.8.3.1 Linux"), using the system's `uname(2)` call to get the OS name.

The patch handles several technical considerations:
- Maintains backward compatibility while adding the new information
- Documents the change in gitprotocol-v2.txt
- Adds Windows-specific test handling since Windows has different outputs between `uname(1)` and `uname(2)`
- Introduces a new `test_redact_non_printables` helper for test sanitization
- Implements OS info caching in `version.c` with proper string sanitization

The implementation follows Junio Hamano's guidance to use `GIT_USER_AGENT` for privacy control rather than adding a new config option. While the patch is now merged, there's ongoing discussion about potentially adding a dedicated config option for complete agent capability suppression in the future.

This appears to be a well-considered implementation with thorough test coverage and documentation updates. The Windows test workaround is pragmatic given the platform differences. The code organization into reusable functions in `version.c` looks clean and maintainable.
