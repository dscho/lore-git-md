Bugfix patch adding packed-refs header validation to `git fsck`, part of a larger series improving reference verification.

This patch introduces strict validation of the `packed-refs` file header format when checking references via `git fsck`. The key changes are:

1. Adds a new `badPackedRefHeader` fsck message (ERROR level) for malformed headers that don't match the expected "# pack-refs with: " prefix
2. Introduces a `packedRefEntryNotTerminated` fsck message (ERROR level) for lines missing terminating newlines
3. Implements header parsing logic in `packed_fsck_ref_content()` that:
   - Skips validation if no header exists (backward compatible with old Git versions)
   - Validates the exact prefix format
   - Allows any content after the prefix (maintaining extensibility)
4. Adds comprehensive tests in `t0602-reffiles-fsck.sh` covering:
   - Various malformed header cases
   - Missing headers (valid case)
   - Unknown traits in valid headers (valid case)

The patch builds on existing packed-refs handling in `create_snapshot()` but adapts it for fsck purposes with more rigorous error reporting. It's part of a larger effort (v5 series) to strengthen reference validation, with this piece specifically addressing header format verification.

Technical details:
- New functions: `packed_fsck_ref_next_line()`, `packed_fsck_ref_header()`, `packed_fsck_ref_content()`
- Touches: `refs/packed-backend.c` core logic, fsck message definitions, test infrastructure
- Maintains backward compatibility while adding stricter validation
- Follows established patterns from other reference validation code
