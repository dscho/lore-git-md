Maintainer feedback on documentation build system fix. Junio Hamano responds to Adam Dinwoodie's patch that fixed a regression where `make` in the Documentation/ directory stopped building full documentation. While agreeing with the functional fix, Hamano suggests a more robust approach following project conventions: adding an empty `all::` (double-colon) rule at the file's start, similar to patterns in t/Makefile and the main Makefile. This makes the default target explicit and prevents similar regressions. He notes that phony targets should always use double-colon rules, and provides a sample diff showing both the new empty rule and the moved target. The change maintains the same end result (restoring complete documentation builds by default) while better aligning with Git's Makefile conventions. No technical objections remain - this appears ready for Adam to submit a revised patch incorporating the suggested style change.
