Performance optimization patch for merge-recursive's rename processing, now approved and ready for merging. This is the final version of a patch that was part of a two-patch series, with the second patch (`get_unmerged` optimization) having been dropped based on maintainer feedback.

The patch changes `process_renames()` in merge-recursive.c to build string lists more efficiently by first appending all items unsorted and then sorting them once, reducing the time complexity from O(n²) to O(n log n). The change replaces `string_list_insert()` calls with `string_list_append()` followed by explicit sorting. The commit message notes this optimization is safe because diffcore_rename guarantees no duplicates in the paths being processed.

This version shows no changes from v1 (as indicated by the range-diff showing identical hashes), confirming all feedback was addressed in the initial submission. The patch has received explicit approval from Elijah Newren, who confirmed its value as an isolated improvement to legacy merge-recursive code while recommending against further optimizations in favor of focusing on merge-ort. The thread established this as the only remaining optimization worth applying to merge-recursive, with all other work to be directed toward the newer merge-ort implementation.
