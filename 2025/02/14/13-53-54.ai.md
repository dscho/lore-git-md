Bugfix discussion for tag fetching regression in protocol v2. This is a follow-up in an ongoing thread about a regression where tags are no longer fetched when fetching specific commits with depth limits, caused by commit 3f763ddf28 ("fetch: set remote/HEAD if it does not exist"). Bence Ferdinandy, the author of the original commit, confirms Taylor Blau's analysis and notes this issue has come up before in another thread.

Key technical points in this response:
- Bence acknowledges the same issue was previously reported but remains unresolved due to uncertainty about the underlying behavior
- He references two experimental approaches tried in his own repository:
  1. Removing the `ref_prefixes` empty check entirely (which broke many things)
  2. Reversing the order of operations (which worked but felt like a band-aid)
- The core mystery remains why these approaches have different effects when they seem logically equivalent
- Bence defers to others with deeper protocol v2 knowledge to explain the underlying behavior

The thread remains in a holding pattern awaiting input from protocol experts to determine the proper fix that maintains both the intended optimizations from e70a3030e7 and the expected tag-fetching behavior. The regression affects shallow fetches of specific commits where tag decoration is expected but missing in the output of `git log --decorate`.
