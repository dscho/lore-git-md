This is a feature patch proposing to add From header support in `git show --format=email` when format.from and format.forceInBodyFrom are configured. The author notes this currently doesn't work despite existing infrastructure in log-tree.c that appears designed to handle it.

The patch adds a `from` member to struct log_config and reads user configuration to populate rev.from_ident, reusing the existing force_in_body_from variable. The implementation is marked as RFC because the author acknowledges it may not be the best solution - they're specifically questioning whether their expectation of seeing the From field in this context is correct, given the redundancy with struct format_config.

The change affects builtin/log.c, adding 21 lines to handle the format.from and format.forceinbodyfrom configurations and populate the rev.from_ident field. The author includes a signed-off-by but explicitly flags this as an RFC seeking feedback on both the behavioral expectation and implementation approach.

Key technical details for future reference:
- Adds `from` to struct log_config
- Reads format.from and format.forceinbodyfrom configs
- Populates rev.from_ident via split_ident_line()
- Sets rev.force_in_body_from
- Affects email format output in `git show`
