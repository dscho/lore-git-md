This is the final patch in a bugfix series integrating comprehensive packed-refs validation into `git fsck`. The patch adds a new `--[no-]references` option to `git fsck` that controls whether to check reference database consistency via a new `git refs verify` child process.

The implementation introduces a `fsck_refs()` function that runs `git refs verify` as a child process with appropriate verbosity and strictness flags. The check is performed early in `git fsck`'s execution sequence to avoid interference with existing implicit reference checks. Progress reporting is implemented with a simple single-step progress meter since the total number of loose refs isn't known in advance.

The patch adds documentation for the new option and includes tests verifying that:
1. The `--references` option enables ref checking (default behavior)
2. The `--no-references` option disables ref checking
3. Trailing garbage in refs is properly detected when checking is enabled
4. No warnings are emitted when checking is disabled

This completes the series' goal of integrating all packed-refs validation (including the newly added sortedness verification from patch 7/8) into Git's standard fsck workflow while maintaining backward compatibility and providing user control over the checks. The implementation follows the series' design philosophy of keeping verification paths separate from normal operation and maintaining memory-efficient operation.
