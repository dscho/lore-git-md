This is part 7/8 of a bugfix series adding comprehensive validation for packed-refs files. The patch focuses specifically on verifying that packed-refs entries are properly sorted when the file's header includes the "sorted" trait.

The patch introduces a new validation step that checks refname ordering when the "packed-refs" file claims to be sorted. It avoids memory-intensive approaches by re-parsing the file to check ordering rather than storing all refnames, and reuses existing comparison logic by extracting a helper function `cmp_packed_refname()` from `cmp_packed_ref_records()`. A new fsck error `packedRefUnsorted` is added to report violations.

The implementation includes thorough test coverage showing:
- Correct handling when no sorting is claimed
- Detection of out-of-order refs in simple cases
- Proper behavior with peeled references
- No false positives when sorting is correct

This appears to be a well-considered addition to the packed-refs validation series, with clear motivation, careful memory management, and comprehensive tests. The patch builds logically on prior work in the series while introducing new validation capabilities.
