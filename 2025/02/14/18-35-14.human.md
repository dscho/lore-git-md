Bugfix discussion for tag fetching regression in protocol v2. Junio Hamano weighs in on Taylor Blau's proposed fix for the issue where tags stopped being fetched in certain shallow fetch scenarios. The regression was introduced by changes to how remote HEAD references are handled.

Junio notes that Taylor's proposed change would always request tags when tags are enabled, rather than only when other prefixes exist. While this might fix the immediate issue, Junio expresses concern about the broader implications - this could break any code that relies on the current behavior of not requesting tags when no prefixes exist. He suggests the deeper issue may be with the fragile, incremental way ref prefixes are built up in the code.

The discussion highlights how the original code made assumptions that were broken when HEAD handling was added, and that a more robust solution might involve restructuring how the prefix logic works to accommodate multiple possible prefixes (tags, HEAD, and potentially others in future). Junio defers to the original authors and protocol v2 experts for the final solution, noting he hasn't had time to deeply analyze the interactions himself.
