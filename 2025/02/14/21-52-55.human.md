This is a bugfix for the documentation build system. Adam Dinwoodie noticed that since commit a38edab7c8 in December 2024, running `make` in the Documentation/ directory no longer builds the documentation by default - instead it just generates some config files. This happened because the `all` target (which builds both HTML and man pages) was moved below some configuration targets in the Makefile.

The patch simply moves the `all` target definition back up near the top of the Makefile, restoring the expected behavior where `make` builds the docs. The change is straightforward - just two lines moved with no functional changes beyond fixing the default target behavior. The commit message clearly explains both the problem was and how this change fixes it, referencing the specific commit that introduced the regression.

This appears to be a clean, well-motivated fix for a minor but annoying build system quirk that would affect anyone trying to build Git's documentation locally. The author also includes an apology for a duplicate email send due to a DMARC configuration issue.
