Bugfix patch adding header validation for packed-refs files. This is part 4/8 in a series improving packed-refs validation in `git fsck`.

The patch focuses on validating the header line in packed-refs files, which must start with "# pack-refs with: " (note the trailing space). It introduces two new fsck error messages:
- `badPackedRefHeader` for malformed headers
- `packedRefEntryNotTerminated` for lines missing newline terminators

Key behaviors:
- Older Git versions without headers are still allowed (no error)
- Only the prefix is checked, not the full header content (to maintain extensibility)
- The validation matches what's already done in `create_snapshot()`

The implementation reads the packed-refs file and checks the first line if present. Test cases verify various edge cases including missing headers, malformed prefixes, and valid variations. The patch appears well-considered with thorough test coverage and maintains backward compatibility while adding stricter validation where appropriate.
