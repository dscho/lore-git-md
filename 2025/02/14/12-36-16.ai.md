This is the core implementation patch in a series adding OS version capability to Git's protocol. The patch extends the existing `agent` capability string to include OS information in a "package/version os" format (e.g., "git/1.8.3.1 Linux") rather than introducing a new capability. The OS name comes from the `sysname` field of `uname(2)` (or equivalent on Windows where Git fakes this system call).

Key technical details:
- The implementation builds on preparatory refactoring from earlier patches (string sanitization, `uname` handling)
- Windows testing is handled specially due to differences between `uname(1)` and `uname(2)` outputs
- Privacy controls remain via `GIT_USER_AGENT` environment variable (which takes precedence)
- New helper functions in version.c: `os_info()` for cached/sanitized OS name, integrated with existing `git_user_agent_sanitized()`
- Documentation updates in gitprotocol-v2.txt clarify the new format
- Test changes include Windows-specific handling and a `test_redact_non_printables()` helper

The patch maintains backward compatibility while adding the new information. The thread context shows this was the final implementation approach after discussion, though post-merge there's now debate about improving privacy controls via a dedicated config option.
