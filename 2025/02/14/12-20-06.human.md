This is a bugfix patch in the ongoing `git fsck` packed-refs validation series (part 8/8). It addresses a subtle interaction between worktree HEAD checking and packed-refs verification.

The patch introduces `get_worktrees_without_reading_head()` to avoid triggering packed-refs validation prematurely during `git refs verify` operations. Currently, checking worktree HEADs can cause the program to abort if the packed-refs file has formatting issue (like a missing final newline), even though the verification command is meant to report rather than fail on such issues.

The change builds on existing worktree infrastructure (465a22b338) that already supports skipping HEAD reads. The implementation is straightforward - exposing the internal skip-HEAD capability through a new public function and using it in `builtin/refs.c`. 

Reviewer Karthik Nayak suggests improving the documentation to better explain the consistency checking context, which the author agrees to address in the next version. The patch appears technically sound and fits well with the series' goal of making packed-refs validation more robust and user-controllable.
