Test infrastructure patch in a series improving packed-refs validation.

This is the first patch in v4 of an 8-part series that adds `git fsck` integration for packed-refs validation. The patch focuses on improving test reliability by wrapping test cases in subshells to ensure working directory changes don't leak between tests. 

The change converts all test cases in t0602-reffiles-fsck.sh to use subshells for any operations that change directories, preventing test pollution if a test fails mid-execution. The tests verify various ref validation scenarios including:
- Invalid ref names (containing dots, tildes, spaces)
- Malformed ref content (bad hashes, missing newlines, trailing garbage)
- Symlink validation (both textual and symbolic link symrefs)
- Worktree-specific ref handling

The patch maintains all existing test coverage while making the tests more robust. It's a straightforward mechanical change that doesn't modify any actual validation behavior, just the test scaffolding. The subshell approach follows Git's standard test pattern for directory-changing operations.

This is part of a larger effort to add comprehensive validation of packed-refs files through `git fsck --references`, with this test file being a key component of the verification infrastructure. The series has already incorporated feedback from Junio Hamano and Patrick Steinhardt in previous iterations.
