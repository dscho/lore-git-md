This is a bugfix series (v4) finalizing packed-refs validation checks and integrating them with `git fsck` via a new `--[no-]references` option. The series builds on previous iterations that established the reference verification architecture, with v4 specifically addressing feedback from Junio and Patrick Steinhardt.

Key changes in this version:
1. **Header validation refinements** (patch 4): Now strictly enforces the single space after colon in "# pack-refs with:" prefix while maintaining compatibility with headerless files and unknown but properly formatted traits. Fixes an unrelated bug in `create_snapshot()` that accepted malformed headers.

2. **Memory optimization** (patches 6-7): Replaces greedy name calculation with lazy computation when errors occur, and avoids storing states by re-parsing the file to check sortedness. Uses HERE docs to improve test scripts.

3. **FSck integration** (patch 8): Adds `git refs verify` as a child process to `git fsck`, controlled by new `--[no-]references` option (enabled by default). Includes tests exercising the new functionality.

The series touches core refs handling in `refs/packed-backend.c`, adds new fsck messages, and significantly expands test coverage in `t/t0602-reffiles-fsck.sh`. The implementation appears thorough, with careful attention to backward compatibility and memory efficiency. The changes maintain the permissive approach for unknown capabilities/headerless files while enforcing stricter validation of known format requirements.

Technical details for future reference:
- New fsck messages: `badPackedRefHeader`, `packedRefUnsorted`
- Key functions modified: `packed_fsck_ref_header()`, `packed_fsck_ref_sorted()`
- Behavior changes: `create_snapshot()` now rejects malformed headers, `git fsck` gains ref verification
- Test coverage includes: malformed headers, valid headerless files, unknown capabilities, sortedness checks, trailing garbage detection
