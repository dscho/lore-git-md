Feature implementation for `git clone` with significant preparatory refactoring.

This is version 5 of a series introducing a new `--revision` option to `git clone` that allows cloning a single commit or ref without creating branches or remote-tracking refs, detaching HEAD at the requested revision. The series has undergone extensive review and refactoring through 4 previous versions, with this iteration addressing feedback from multiple reviewers.

The preparatory work includes major structural improvements to `builtin/clone.c`:
- Reducing global variables by moving them into `cmd_clone()`'s scope
- Inverting tag handling from `--no-tags` to `--tags` (with documentation fixes)
- Refactoring `wanted_peer_refs()` to simplify branch/tag logic
- Moving tag refspec handling earlier in the clone process
- Introducing a `struct clone_opts` to better organize options

The core `--revision` feature:
- Accepts both ref names and commit hashes
- Creates a detached HEAD without branches or tracking refs
- Works with `--depth` for shallow clones
- Explicitly incompatible with `--branch` and `--mirror`
- Includes comprehensive tests in new file `t5621-clone-revision.sh`

Reviewers (Patrick Steinhardt, Jean-Noël Avila, and Junio C. Hamano) have provided detailed feedback on code quality, documentation, and implementation consistency. This version addresses most concerns, including:
- A new helper function `die_for_incompatible_opt2()`
- Type safety improvements (using `size_t` for loop counters)
- Better commit messages explaining refactoring
- Removal of debug artifacts
- Documentation clarifications about tag handling

The series appears well-tested and thoughtfully designed, with some remaining minor style and documentation polish needed per reviewer comments. The preparatory refactoring makes the actual feature implementation clean and maintainable. This would be particularly useful for CI systems and other automated workflows that need minimal clones of specific revisions.
