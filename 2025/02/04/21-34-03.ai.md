This is a refactoring patch in the `git clone` series introducing the `--revision` option. It simplifies tag refspec handling by moving the tags refspec addition earlier in the clone process, addressing feedback from Patrick Steinhardt in previous versions.

The patch modifies the clone process to append the `TAG_REFSPEC` to `remote->fetch` before calling `refspec_ref_prefixes()`, rather than handling tags separately in `wanted_peer_refs()`. This eliminates the need for temporary tag refspec handling in `wanted_peer_refs()` and reduces code by 16 lines. The change also properly sets `option_tags = 0` when `--mirror` is given, as mirror clones already handle all refs including tags.

Key technical changes include:
- Removal of `tag_refspec` handling from `wanted_peer_refs()`
- Early addition of `TAG_REFSPEC` to `remote->fetch` when tags are requested
- New logic to disable tag handling for mirror clones
- Updated comments explaining when tags refspec is added
- Maintained behavior while simplifying the code path

The change builds on previous preparatory work in the series and helps pave the way for the final `--revision` implementation by cleaning up the refspec handling infrastructure. The patch appears well-considered, with clear commit message explaining the rationale and proper handling of edge cases like mirror clones.
