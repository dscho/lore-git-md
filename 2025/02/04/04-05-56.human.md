This is part 3/5 of Meet Soni's refactoring series to centralize refspec handling, now in its final v4 iteration. The patch renames three key refspec-related functions to better reflect their purposes and maintain consistency with the new `refspec_` prefix convention established for the subsystem. The changes are mechanical renames with no behavior modifications: `query_refspecs()` becomes `refspec_find_match()`, `query_refspecs_multiple()` becomes `refspec_find_all_matches()`, and the static helper `query_matches_negative_refspec()` becomes `refspec_find_negative_match()`.

The series has already gone through multiple rounds of review addressing technical structure, documentation, and naming conventions, with this version incorporating all agreed-upon changes. The renaming here follows Patrick Steinhardt's earlier suggestion to use subsystem-prefixed names consistently. Updates span `remote.c`, `remote.h`, and `builtin/push.c` to reflect the new names while maintaining identical functionality.

As part of a Google Summer of Code project, this patch represents the final naming refinements before the actual code movement in subsequent patches. The changes are straightforward and uncontroversial at this point, having been thoroughly vetted in prior iterations. The patch keeps all BUG() assertions and error handling behavior exactly as before, just updating the function names in those messages.
