Junio C Hamano provides a detailed technical analysis of the proposed "last checked" timestamp feature for branch status messages. He explains why both the original `.git/FETCH_HEAD` approach and his earlier suggested reflog-based alternative have significant limitations.

The key insight is that neither method reliably tracks when a specific remote branch was last checked. FETCH_HEAD gets overwritten by unrelated fetches, while remote branch reflogs don't record no-op fetches where the branch didn't change. Even examining FETCH_HEAD contents to map specific fetches would fail when subsequent fetches overwrite the file.

This response effectively puts the proposal on hold until someone can devise a way to reliably track per-branch fetch timestamps. The discussion reveals deeper technical challenges than initially apparent, suggesting the feature may require more fundamental changes to Git's fetch infrastructure if pursued further. For now, the status quo remains the only fully reliable option, despite its UX shortcomings.
