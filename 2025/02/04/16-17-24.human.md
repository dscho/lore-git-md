CI infrastructure fix for GitLab CI whitespace/style checks. This is a follow-up to Justin Tobler's patch that fixes an edge case in how base commits are determined for GitLab CI jobs. The original patch correctly identified that shell parameter expansion was failing to properly handle null values of CI_MERGE_REQUEST_TARGET_BRANCH_SHA/DIFF_BASE_SHA variables, using `${var-default}` syntax that doesn't fall back when the first variable is null.

Toon Claes responds with approval, noting they weren't previously aware of the colon-less parameter expansion behavior. They confirm the fix makes sense to handle both unset and null cases by changing to `${var:-default}` syntax in two places in .gitlab-ci.yml. The response includes appreciation for identifying and submitting this minimal but important fix (just adding two colons) that resolves CI failures. Successful CI runs with the fix are referenced in the original patch. This appears to be a straightforward, well-justified improvement to the CI infrastructure.
