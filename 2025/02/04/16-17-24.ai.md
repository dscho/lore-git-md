CI infrastructure fix addressing shell parameter expansion in GitLab CI jobs. This is a follow-up to Justin Tobler's patch that fixed how base commits are determined for whitespace/style checks in GitLab pipelines. The original issue involved `${var-default}` syntax not properly handling null values of CI_MERGE_REQUEST_TARGET_BRANCH_SHA/CI_MERGE_REQUEST_DIFF_BASE_SHA variables. Toon Claes confirms the fix (changing to `${var:-default}` syntax) is correct, citing the Bash manual to explain the difference between testing for unset vs. null variables. The response includes approval of the patch and appreciation for the fix, noting it resolves the edge case where variables could be set but null. The change affects two locations in .gitlab-ci.yml where the check-whitespace and check-style jobs determine their base commit. Successful CI runs with the fix were previously demonstrated in the original patch submission.
