This is part 6/8 of a bugfix series introducing comprehensive packed-refs validation checks, specifically focusing on entry-level consistency verification. The patch adds detailed validation for individual ref entries in packed-refs files, mirroring the checks performed by `next_record()` during normal operation.

The key technical elements in this patch are:
1. Two new validation functions: `packed_fsck_ref_main_line()` for regular ref entries and `packed_fsck_ref_peeled_line()` for peeled refs (those with '^' prefix)
2. Checks include:
   - Valid OID format verification
   - Proper spacing after OIDs
   - Correct refname formatting
   - Newline termination validation
3. Error reporting through the existing fsck infrastructure with new FSCK_MSG_BAD_PACKED_REF_ENTRY message

The discussion with Patrick Steinhardt reveals several implementation details needing refinement in the next version:
- The `start` pointer increment in `packed_fsck_ref_peeled_line()` needs better documentation of its purpose (skipping the '^' character while maintaining pointer consistency)
- Unnecessary braces around single-line return statements will be removed
- Clarification that error checking continues through the entire file rather than stopping at first error

The patch maintains the series' approach of thorough validation while keeping the fsck integration clean. The author acknowledges the need to better explain the motivation (porting existing runtime checks to validation) in the next revision. This continues the series' progression toward comprehensive packed-refs validation while addressing reviewer feedback on implementation details.
