This is a refactoring patch in a 7-part series introducing a `--revision` option for `git clone`. The patch introduces a `struct clone_opts` to consolidate clone-related state currently stored in global variables, starting with a `wants_head` field that tracks whether the remote HEAD should be fetched (false when both `--single-branch` and `--branch` are specified).

Key technical changes:
- Adds `struct clone_opts` with `wants_head` field initialized to true by default
- Modifies `wanted_peer_refs()` to take the opts struct and use `wants_head` to control HEAD fetching behavior
- Makes `tail_link_ref()` non-static by moving it from remote.c to remote.h with documentation
- Updates clone logic to set `wants_head = 0` when both `--single-branch` and `--branch` are used
- The change is part of a larger effort to eliminate global variables in clone.c
- Follows earlier preparatory work moving variables to local scope
- Maintains existing behavior while providing cleaner foundation for future changes
- The patch appears well-structured with:
  - Clear commit message explaining motivation
  - Focused scope (just introducing the struct`)
  - Proper documentation for the new public function
  - No behavior changes beyond the intended HEAD-fetching control

This continues the series' pattern of careful refactoring before implementing the new `--revision` feature, with all v4 feedback addressed. The changes are mechanical but important for the feature's clean implementation.
