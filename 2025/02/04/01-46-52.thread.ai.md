Thread summary:

This thread addresses platform compatibility fixes for the Thunderbird patch processing script `contrib/thunderbird-patch-inline/appp.sh`, which had contained a bashism (`echo -e`) for 9 years since its last modification. The original patch from brian m. carlson replaced this with POSIX-compliant `printf` to ensure proper operation on systems using dash as /bin/sh, specifically affecting how Cc and Signed-off-by headers are processed when generating reply emails (handling the concatenation of `$CMT_MSG`, `$HEADERS`, and `$DIFF` variables).

D. Ben Knoble reviewed and confirmed the technical correctness of the initial change while noting an observation about `sed`'s behavior with input lacking final newlines. brian m. carlson acknowledged this as a valid concern, noting that while GNU/BSD `sed` handle such cases, POSIX doesn't guarantee this behavior. The v2 patch now adds explicit newlines using `printf '%s\n%s\n'` between the `$CMT_MSG` and `$HEADERS` variables before piping to `sed`, completing the portability fixes. The author considered alternative formatting approaches but chose this solution for better readability and maintainability.

Junio C Hamano has accepted the initial patch into Git's codebase, observing the script appears to see little usage given how long the bug went unfixed, and that none of the original authors are still involved in the project. The technical changes are straightforward - first replacing the non-portable `echo -e` with `printf`, then adding the additional newline safety measure. This represents the full resolution of portability concerns for this long-dormant contrib script, with both the original bashism and subsequent edge cases now addressed. The thread demonstrates careful attention to edge cases in shell scripting portability, progressing from the initial fix to addressing more subtle concerns, while maintaining the script's core functionality of processing patch emails in Thunderbird. The changes mark the first significant update to this script since 2014 when the issue was first reported as Debian bug #772238.
