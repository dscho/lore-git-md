Bugfix for `git repack --keep-unreachable` edge case with no existing packs. This is the second version of a two-patch series that fixes a bug where `--keep-unreachable` would fail to pack loose objects when no preexisting packfiles exist in the repository.

The patch corrects the logic in `builtin/repack.c` that determines when to pass `--pack-loose-unreachable` to `git-pack-objects`. The original code incorrectly required existing packfiles for this option, despite loose objects being packable regardless. The fix separates this condition from the packfile check, now only requiring that `--keep-unreachable` is active, redundant objects are being deleted (as documented), and we're not creating a cruft pack.

A new test case in t7701-repack-unpack-unreachable.sh verifies the fix by creating a repository with only loose objects and confirming they are properly packed. The change is minimal (5 lines modified) but important for the documented behavior of `--keep-unreachable`.

The patch has already received positive feedback from Jeff King (original author of the feature) and Junio Hamano, with all technical concerns addressed. This version incorporates test improvements suggested in v1 review, merging the tests into the existing t7701 file rather than creating a new one.
