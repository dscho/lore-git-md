This is a refactoring patch in a series introducing a new `--revision` option for `git clone`. The patch inverts the internal handling of tag cloning from a `--no-tags` flag to a default-enabled `--tags` flag, though the user-visible behavior remains unchanged.

The change simplifies the code by making the default case (cloning tags) the positive case rather than tracking the negative. The documentation is updated to properly show both `--tags` and `--no-tags` as options, though `--tags` is effectively a no-op since tags are cloned by default. This is preparatory work for later patches in the series that will introduce the new `--revision` functionality.

The patch follows good practices by including a clear rationale in the commit message, linking to prior discussion, and maintaining consistent behavior while making the internal representation more logical. The changes are straightforward - flipping a boolean default and updating all related conditionals - and the patch has already been reviewed in previous iterations of the series.
