This is the fifth version of a feature series introducing a `--revision` option to `git clone`. The series has undergone significant refactoring groundwork in previous versions and now focuses on finalizing the implementation.

The key changes in v5 include:
1. Adding a separate commit for the new `die_for_incompatible_opt2()` helper function
2. Documentation tweaks for `--[no-]tags` and `--revision` options
3. Improved commit message explaining the `wanted_peer_refs()` refactoring
4. Type safety fix changing loop counter from `int` to `size_t`
5. Using `lookup_commit_or_die()` for simpler error handling
6. Added explanatory code comments
7. Various stylistic cleanups (removing debug artifacts, empty lines)

The series maintains its core functionality: allowing cloning of a specific revision (ref or hash) without creating tracking branches, with HEAD pointing directly to the requested commit. This is particularly useful for CI workflows where only a specific commit is needed.

Review feedback from v4 has been addressed, including:
- Junio C. Hamano's concerns about option handling consistency
- Patrick Steinhardt's suggestions about commit lookup simplification
- Jean-Noël Avila's documentation improvements

The preparatory refactoring (patches 1-5) has stabilized, with the main discussion now focused on the final implementation (patch 7). The series appears ready for integration pending any final review comments on the latest changes.
