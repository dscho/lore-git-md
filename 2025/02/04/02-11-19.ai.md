Platform compatibility fix for a long-dormant contrib script. This is a follow-up to brian m. carlson's patch that replaced a bash-specific `echo -e` with POSIX-compliant `printf` in the Thunderbird patch processing script `appp.sh`. The change affects how Cc and Signed-off-by headers are concatenated when generating reply emails, specifically in the pipeline that processes `$CMT_MSG` and `$HEADERS` variables.

D. Ben Knoble confirms the technical correctness of the change, noting their own experience with POSIX shell compatibility challenges. They raise an interesting side observation about `sed`'s behavior with input lacking final newlines, though this doesn't affect the core fix. The script remains otherwise unchanged, continuing its limited maintenance status as evidenced by the 9-year gap since its last modification and inactive original authors.

The patch thread demonstrates consensus on the technical solution while highlighting the script's niche status in the Git ecosystem. The change is minimal (one-line substitution) but important for systems using dash as /bin/sh, completing a fix that was first reported as a Debian bug in 2014. No controversy or further changes are anticipated given the straightforward nature of the POSIX compliance fix.
