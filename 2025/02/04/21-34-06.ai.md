This is the final implementation patch (7/7) in a series introducing a `--revision` option to `git clone`. The feature enables cloning a specific ref or commit hash without creating remote-tracking branches, detaching HEAD at the requested revision. The series has undergone extensive preparatory refactoring across 5 versions, with all preparatory work now completed as noted in the thread summary.

The patch adds the `--revision` option which accepts either a fully qualified reference (like `refs/pull/123`) or a hexadecimal commit ID. Key behaviors:
- Creates no remote-tracking branches
- Writes no fetch refspecs
- Detaches HEAD at the requested revision
- Works with `--depth` for minimal clones (useful for CI)
- Incompatible with `--branch` and `--mirror` (validated via new helper from patch 6/7)

Implementation details:
- Adds `detach` flag to `struct clone_opts`
- Modifies `update_head()` to handle detached HEAD case
- Updates refspec handling to skip remote-tracking setup when using `--revision`
- Includes comprehensive tests in new `t5621-clone-revision.sh` covering:
  - Branch/tag/commit/HEAD revisions
  - Edge cases (short hashes, trees, parent refs)
  - Incompatibility scenarios
  - Combination with `--depth` and `--bare`
