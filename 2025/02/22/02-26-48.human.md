Bugfix for NULL pointer dereference in `git check-mailmap` when processing email-only inputs. This follows up on recent sendemail mailmap support work where passing just an email address (like "bugs@company.xx") would segfault due to passing NULL for the name parameter to map_user().

The v2 patch takes a minimal approach, changing the NULL to an empty string when no name is present. Junio Hamano confirms this is correct after auditing all map_user() callers, noting that other callers use an "ident" struct that would never be NULL. The fix maintains existing behavior while preventing the crash.

A new test case verifies the fix works when checking an email address against a mailmap entry that maps between addresses. The test shows the expected output format when looking up "bugs@company.xx" with a mailmap entry mapping "Bug Reports <bugs-new@company.xx>" to "Bugs <bugs@company.xx>".

The patch is now queued for inclusion. While the map_user() calling convention could be better, that's considered out of scope for this immediate fix. This appears to be a straightforward, well-justified fix for a real crash bug with proper test coverage.
