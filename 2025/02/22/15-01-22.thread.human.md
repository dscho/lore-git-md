This thread discusses a bug report and proposed fix regarding Git's behavior when using `--filter=blob:none` with servers that don't support object filtering. John Giorshev reports that Git currently falls back silently to downloading full blobs in this case, which caused unexpected performance issues in their repository scanning tool. They've proposed making this a hard error instead, as this would break existing workflows that may rely on the silent fallback behavior. The discussion is currently weighing whether this breaking change would be acceptable or if the behavior should be made opt-in via a new flag or configuration option. The patch modifies `fetch-pack.c` to check filter capability negotiation and fail explicitly when requested filters can't be honored. This touches on protocol negotiation behavior in Git's fetch/push subsystem and would affect users trying to use filtering with older servers or proxies.
