Bugfix proposal for `--filter=blob:none` behavior when server lacks support.

John Giorshev reports that Git currently silently falls back to downloading full blobs when using `--filter=blob:none` with a server that doesn't support filtering, contrary to user expectations. This caused performance issues in their repository scanning tool. They propose making this an error condition rather than a silent fallback.

The proposed patch would change this to fail explicitly when the server lacks filtering support, but this would break backward compatibility. The email asks for guidance on whether this breaking change is acceptable or if the behavior should be controlled via a new CLI flag or config option instead.

The issue appears legitimate - silently ignoring a user's explicit request to avoid downloading blobs could cause real problems for tools relying on this optimization. However, the compatibility implications need careful consideration since some existing workflows might depend on the fallback behavior. The patch itself is minimal (just a few lines changing the error handling) but the policy question about backward compatibility is the key discussion point.
