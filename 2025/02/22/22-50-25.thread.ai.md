[PATCH] git gc --auto heuristics may miss large reflog cleanup. Markus Gerstel reports a repository where automatic garbage collection failed to clean up an excessively large reflog (180MB with 823,921 entries) over 6 years despite standard configuration (logallrefupdates=true). Observed with Git 2.36.6, though unconfirmed whether fixed in later versions. Manual gc worked, suggesting a gap in the auto-gc heuristics for very large reflogs. The immediate workaround was adding explicit gc to cronjobs, but the behavior warrants investigation as it may indicate either a long-standing edge case or a regression since fixed. Key details: version 2.36.6, reflog size threshold missed (180MB/823k entries), standard config that should maintain reflogs.
