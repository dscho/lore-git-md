Bugfix proposal for `--filter=blob:none` behavior when server lacks filtering support.

John Giorshev reports that Git currently silently falls back to downloading full blobs when using `--filter=blob:none` with servers that don't support filtering, contrary to user expectations. This caused performance issues in their repo scanning use case. They propose making this a hard error rather than a silent fallback, providing a sample implementation that would fail the clone when filtering is requested but unavailable.

The proposed change would break backward compatibility, as some existing workflows might rely on the silent fallback behavior. Giorshev is seeking guidance on whether this breaking change would be acceptable or if the behavior should be made opt-in via a new CLI flag or config option. The patch modifies `fetch-pack.c` to check filter capability negotiation and error out when requested filters can't be honored.

This touches on protocol negotiation behavior in the fetch/push subsystem, specifically around the relatively new filtering capabilities. The change would affect any user trying to use `--filter` with older servers or proxies that don't support the capability. The Stack Overflow link shows this has caused real-world problems for the reporter's repository scanning tool.
