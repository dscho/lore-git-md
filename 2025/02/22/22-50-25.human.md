Bugfix report about `git gc --auto` not triggering for large reflogs.

Markus Gerstel reports encountering a repository where `git gc --auto` failed to clean up an excessively large reflog (180MB with over 800,000 entries) despite running daily for 6 years via cron. The repository had standard configuration with `logallrefupdates` enabled, running Git 2.36.6. 

The issue was resolved by manually running `git gc`, which successfully cleaned up the reflog. The reporter has since modified their cronjob to explicitly run `git gc` rather than relying on the auto mode. 

While the report doesn't include analysis of why the auto-gc didn't trigger, it highlights a real-world case where the automatic cleanup mechanism failed to address significant repository bloat. The reporter notes they can't test with newer Git versions to see if this has been fixed, but the case may warrant investigation into the auto-gc heuristics for reflog size detection. 

This appears to be a genuine issue report rather than a patch submission, serving as useful feedback about gc behavior in long-running repositories. The tone is observational and good-natured ("slightly surprised and amused"), suggesting this isn't a critical problem for the reporter but may indicate an edge case the gc maintainers should be aware of.
