Bugfix patch in a series adding packed-refs validation to `git fsck`. This is patch 7/8 in v3 of the series, focusing specifically on checking whether packed-refs files marked with the "sorted" capability are actually sorted.

Patrick Steinhardt provides a code review suggesting several improvements to the implementation. He notes the patch should use "capabilities" rather than "traits" terminology, and proposes optimizing the sortedness check by comparing each entry to the previous one rather than storing all entries in an array. He also suggests simplifying the test cases by using HERE documents for the packed-refs file contents.

The patch adds validation that enforces the sortedness guarantee when a packed-refs file declares the "sorted" capability, with tests verifying both the positive case (correctly reporting unsorted refs) and negative case (not checking when "sorted" isn't declared). The implementation tracks line numbers for error reporting and handles both regular and peeled references.

This continues the series' thorough approach to packed-refs validation, with Patrick's review helping refine both the implementation details and test presentation. The changes appear well-contained within the packed-backend.c file and its test counterpart.
