This is a follow-up discussion about the first patch in the `git-diff-pairs` series, which refactors diff queue internals. Justin Tobler suggests simplifying the API by replacing the existing `diff_addremove()` and `diff_change()` functions with the new variants that return `diff_filepair` pointers, rather than maintaining both sets of functions. He notes there are only a few callers that would need updating, making this a feasible cleanup. The patch itself looks sound, but Justin raises two points for consideration: whether the dual-function approach is necessary, and whether the new functions should include descriptive comments. The discussion appears constructive, with no major objections to the technical approach - just potential refinements to the API design.
