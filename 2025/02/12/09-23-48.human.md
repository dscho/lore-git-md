This is the third and final patch in a series adding the new `git-diff-pairs` plumbing command, which enables batch processing of blob diffs. The patch adds explicit control over when diffs are output by allowing a NUL byte to trigger immediate output rather than waiting for end-of-input.

Patrick Steinhardt provides a detailed technical review, focusing on documentation and implementation polish. He suggests avoiding internal jargon like "flushing" and "diff queue" in user-facing docs, preferring descriptions of observable behavior. He also notes several small code improvements like using `fputc()` instead of `fprintf()` for single-character output, and consistently using "NUL" rather than "nul" or "null" in documentation and tests.

The patch itself adds the flush control feature while maintaining all existing functionality. It includes comprehensive tests showing both regular and NUL-terminated output modes work correctly. This completes the series' goal of enabling server-side parallel diff processing by providing both batch input and controlled output capabilities.

The review feedback is constructive and focused on making the interface more user-friendly and the implementation more polished. The changes suggested are relatively minor and don't affect the core functionality, which appears well-designed and thoroughly tested. This looks ready to proceed with some documentation tweaks and minor code cleanups.
