This is the second patch in a 3-part series introducing a new `git-diff-pairs` plumbing command for batch blob diff generation. The command takes raw diff format input (from e.g. `git diff-tree -z`) and produces formatted diffs, enabling server-side parallel processing of large change sets to avoid timeouts.

The patch adds the core implementation of `git-diff-pairs` as a builtin command. It processes null-terminated raw diff input, handles all standard diff statuses (adds, deletes, modifications, renames, copies), and can output in various formats. The implementation includes thorough error checking for malformed input and preserves rename/copy information from the raw diff.

Key aspects:
- Designed to work with the existing diff machinery while enabling parallel processing
- Handles the full range of diff statuses including renames with similarity scores
- Includes comprehensive tests verifying behavior matches regular diff output
- Documents the command's purpose and limitations in a new man page

The implementation looks solid, building on Jeff King's prior work and following Git's established patterns. The test coverage is particularly thorough, verifying both basic functionality and edge cases like split input processing. This appears ready for review as part of the series' goal of enabling efficient server-side diff processing.
