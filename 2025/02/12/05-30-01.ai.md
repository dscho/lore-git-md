Memory management fix for revision walking with mixed graph options.

This email thread confirms the root cause and timeline of a memory management bug in Git's revision walking code when mixing `--graph` and `--no-graph` options with certain output formats. Jeff King provides important technical context about the bug's behavior - while it manifests as a use-after-free, the actual symptoms can vary (segfaults, garbage output) depending on memory state. He recommends using address sanitizer builds (SANITIZE=address,undefined) for reliable detection during bisection, which confirms the bug was introduced in v2.37.0 with commit 087c745833 adding `--no-graph` support.

The discussion highlights the non-deterministic nature of memory corruption bugs and the importance of proper tooling for reliable bisection. Patrick Steinhardt's brief response acknowledges the bisection work, indicating consensus on the root cause. The thread establishes that the fix will need to be backported to all stable branches since v2.37.0. Key technical details include the interaction between revision.c and graph.c, particularly around `output_prefix` and `output_prefix_data` pointer management during mixed graph/non-graph operation modes.
