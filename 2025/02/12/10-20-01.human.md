Bugfix patch (7/8) in a series adding packed-refs validation to `git fsck`. This specific patch implements sortedness checking for packed references when the "sorted" capability is declared in the packed-refs header.

The patch adds logic to verify that references are properly sorted when the packed-refs file includes the "sorted" capability. It introduces a new `fsck_packed_ref_entry` struct to track line numbers and reference positions, though reviewer Patrick Steinhardt suggests optimizing this to use pairwise comparison rather than storing all entries. The validation only runs when the header explicitly declares the file should be sorted, maintaining backward compatibility with unsorted packed-refs files.

Test cases verify both the positive case (detecting unsorted references when "sorted" is declared) and the negative case (not enforcing sorting when the capability is absent). The author acknowledges reviewer feedback about using HERE documents for test setup and terminology consistency ("capabilities" vs "traits"), promising to address these in the next version.

This is part of a larger effort to validate packed-refs files end-to-end, with previous patches in the series handling other aspects like header validation and content checks. The implementation appears thorough but could benefit from the memory optimization suggested by the reviewer.
