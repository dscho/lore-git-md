This is a documentation bugfix in the pickaxe options series, correcting the help text for `-S` in `diff.h`. 

The patch fixes an inaccurate description of `-S`'s behavior in the short help text. Previously it suggested `-S` only finds filepairs where one side contains the string, when in fact it detects changes in the number of occurrences (not just presence/absence). The new wording matches the actual functionality, which counts string occurrences rather than just detecting presence.

This change is part of the larger series introducing long option names for pickaxe search (`--patch-modifies` for `-S` and `--patch-grep` for `-G`). While most of the series adds new functionality, this particular patch focuses on correcting existing documentation that had misleading wording. The fix is straightforward - just a one-line change to the help text string in `diff.h`.

The patch appears well-justified and uncontroversial, aligning the help text with the actual behavior that has been in Git for years. It's a small but meaningful improvement to accuracy, especially since this help text is what users see when running `git diff -h`. The change maintains consistency with the more detailed man page descriptions of `-S`'s behavior.
