This is a refactoring patch in the `git-diff-pairs` series, addressing callback compatibility in the diff queue internals. Justin Tobler responds to Karthik Nayak's suggestion about simplifying the API changes, explaining why the original `diff_addremove()` and `diff_change()` functions must remain alongside the new variants. The key technical points are:

1. The patch preserves callback function types (`add_remove_fn_t` and `change_fn_t`) in `diff_options`, which require the original non-returning signatures. New functions `diff_filepair_addremove()` and `diff_filepair_change()` are introduced to provide access to queued `diff_filepair` structs needed for future modifications.

2. Justin notes that `file_add_remove()` and `file_change()` callbacks (also in `diff_options`) don't queue file pairs, making return values inappropriate there. He confirms Patrick Steinhardt's earlier suggestion to add explicit `diff_queue_struct` parameters in the next version while maintaining backward compatibility.

3. Karthik's documentation nit about adding function comments is acknowledged and will be addressed in v3. The thread shows careful evolution of diff queue internals to support both existing callback contracts and new batched processing needs, with the series progressing toward explicit queue parameterization while preserving stable interfaces.
