Refactoring patch in the `git-diff-pairs` series, addressing callback compatibility. This is part 1 of 3-patch series to enable batch blob diff processing while modernizing diff queue internals.

Justin Tobler responds to Karthik Nayak's review of the v2 patch that introduces new diff queue helper functions returning `diff_filepair` pointers. The key points are:

1. The patch keeps the existing `diff_addremove()` and `diff_change()` functions (which don't return values) for backward compatibility with `diff_options` callback types, while adding new variants that do return the filepair.

2. Karthik had suggested replacing the old functions entirely, but Justin explains this would break callback contracts in `diff_options`. The new approach preserves the existing callback architecture while adding explicit queue control.

3. For v3, Justin plans to incorporate Patrick Steinhardt's suggestion to make the queue parameter explicit in the new functions (naming them `diff_queue_addremove()` etc.), while still maintaining the callback-compatible versions.

4. Justin acknowledges Karthik's documentation nit and commits to adding function comments in the next version.

This continues the careful balancing act between modernizing the diff queue API and maintaining backward compatibility, with all feedback from previous reviews being incorporated. The thread shows steady progress toward the series' aim of enabling high-volume diff processing while evolving core diff internals.
