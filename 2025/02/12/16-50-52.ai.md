This is a review response regarding the `git-diff-pairs` plumbing command implementation, focusing on documentation and implementation limitations. Junio C Hamano raises several questions about the current constraints of the command, particularly around input format restrictions and compatibility with other diff commands.

The review notes that many of the documented limitations (only accepting `-z` input, rejecting abbreviated SHA1s, not handling pathspecs) appear to be implementation choices rather than fundamental constraints. The reviewer questions why the command is specifically limited to `diff-tree` output and whether it could potentially work with `diff-index --cached` as well. There's particular interest in understanding whether the command could handle tree expansion itself or if it requires the `-r` flag.

Additionally, the review points out a technical issue with the patch series - it doesn't apply cleanly to the current master branch due to recent changes in how documentation files are named (the switch to .adoc extensions). The reviewer requests that future versions of the series clearly indicate what base commit they're built upon when not targeting the latest master.

This feedback comes after the patch has already incorporated several rounds of review, including documentation refinements from Karthik Nayak and Jean-Noël Avila. The core functionality appears sound, but the review is now focusing on clarifying the command's scope and ensuring proper integration with Git's evolving codebase. The questions raised suggest potential areas for future expansion of the command's capabilities beyond its current server-focused use case.
