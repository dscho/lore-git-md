Documentation polish for the new `git-diff-pairs` command. Jean-Noël Avila points out two small but important formatting issues in the manpage draft for this new plumbing command, which is part of a series enabling batch blob diff processing.

First, they note the SYNOPSIS section should use the standard `[synopsis]` marker rather than `[verse]`, and include angle brackets around the optional `diff-options`. Second, they suggest avoiding future tense ("will reformat") in the DESCRIPTION section in favor of present tense to match Git's documentation conventions.

These are minor but correct observations about documentation style that don't affect the functionality of the patch series, which has already gone through extensive review. The series as a whole introduces a useful new command for server-side diff processing, with this particular patch (v2 2/3) implementing the core `diff-pairs` command after incorporating prior feedback from Karthik Nayak and others.
