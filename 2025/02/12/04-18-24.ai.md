Feature implementation adding a new plumbing command for batch blob diff processing.

This is patch 2/3 in a series introducing `git-diff-pairs(1)`, a new command designed to efficiently process batches of blob diffs in server-side contexts where large change sets might otherwise cause timeouts. The command takes raw diff format (-z) input (typically piped from `git diff-tree`) and produces unified diffs or other formats, maintaining the same rename/copy detection as the original diff but allowing progressive processing.

The implementation:
- Adds a new builtin command with full documentation
- Processes raw diff input line-by-line, handling all diff statuses (add/delete/modify/rename/copy/typechange)
- Preserves rename detection information from input when not re-running detection
- Includes comprehensive tests verifying:
  - Raw diff recreation
  - Unified diff (-p) output
  - Non-recursive mode
  - Split input processing across multiple invocations

The design builds on Jeff King's prior work and the preparatory refactoring from patch 1, exposing diff queue internals while maintaining existing behavior. The implementation appears thorough, with careful handling of edge cases and a complete test suite covering the main use cases. The documentation clearly explains both capabilities and intentional limitations (like requiring -z input and not handling pathspecs).

This patch represents the core functionality of the series, with the final patch expected to add explicit queue flushing control. The changes are well-contained to the new command implementation without broader architectural impacts.
