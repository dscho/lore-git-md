This is a process discussion in the ongoing thread about adding long option names for Git's pickaxe functionality (`-S`/`--patch-modifies` and `-G`/`--patch-grep`). Junio Hamano responds to Illia Bobyr's v5 patch series, focusing on how to handle documentation cleanups that were noticed during the development of the feature.

Key points:
- Junio suggests separating documentation fixes (like standardizing `<regex>` vs `<regular-expression>` terminology) from the main feature work, either doing them as preliminary cleanups or as follow-ups after the main series lands
- He reiterates that test modernization to use long options is unnecessary churn since the short forms are well-established after 20 years
- The response maintains the position that the series should focus narrowly on the core feature addition while keeping peripheral documentation fixes separate

The exchange shows the maintainer's preference for minimal, focused patch series and reluctance to mix feature work with incidental cleanups. This continues the thread's evolution from technical implementation to process refinement, with the technical aspects now complete and attention turning to how to handle related-but-separable documentation issues.
