This is a refactoring patch in the `git-diff-pairs` series, addressing internal diff queue handling. Justin Tobler responds to Patrick Steinhardt's review of the first patch, which introduced new functions to expose `diff_filepair` access while maintaining the old API.

The key points are:
1. Justin explains why he kept the old functions (`diff_addremove`/`diff_change`) alongside new ones - they're used as callbacks in `diff_options` where returning a `diff_filepair` wouldn't make sense.
2. He acknowledges Patrick's suggestion about passing the `diff_queue` explicitly rather than using a global queue, agreeing this would aid libification and promising to implement it in the next version.

The discussion shows careful consideration of API design tradeoffs between backward compatibility and cleaner internals. Justin demonstrates willingness to revise the approach based on feedback, particularly around making the changes more useful for Git's ongoing libification efforts. This patch remains focused on the plumbing needed for the larger `git-diff-pairs` feature while addressing architectural concerns raised in review.
