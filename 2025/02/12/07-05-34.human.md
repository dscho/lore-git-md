Performance optimization discussion regarding commit graph traversal memory usage. This is a follow-up to René Scharfe's patch that restructured `clear_commit_marks_many()` to reduce peak memory usage from O(n) to O(1) by processing parent commits immediately rather than accumulating them in a list.

Patrick Steinhardt acknowledges the technical merit of the change but raises two thoughtful points: (1) the modification effectively changes the traversal order from depth-first to breadth-first, which could theoretically perform worse in certain merge-heavy repository structures, and (2) he requests real-world performance measurements to validate the improvement. The discussion remains constructive, with Patrick recognizing the potential benefits while seeking empirical evidence of the optimization's impact.

The exchange highlights a common pattern in performance optimization reviews - theoretical improvements are welcome but often require concrete benchmarking data to assess their practical value. The patch itself remains small (4-line change) and focused, maintaining the original functionality while attempting to reduce memory pressure during graph operations.
