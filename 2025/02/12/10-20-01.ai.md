This is a bugfix patch in the packed-refs validation series, specifically addressing sortedness verification in packed-refs files. The patch implements conditional checking of ref ordering based on the presence of the "sorted" capability in the packed-refs header.

Key technical elements:
- Introduces `fsck_packed_ref_entry` struct to track line numbers and ref positions
- Adds `packed_fsck_ref_sorted()` function that performs pairwise comparison of refnames
- Only validates sorting when "sorted" capability is present in header (checked via `unsorted_string_list_has_string()`)
- Includes comprehensive test cases in t0602-reffiles-fsck.sh for both sorted and unsorted scenarios
- Maintains backward compatibility by not enforcing sorting when header lacks the capability

The implementation currently stores all entries in an array for comparison, though Patrick Steinhardt suggests optimizing this to only remember the last entry for pairwise comparison. The author (shejialuo) acknowledges this feedback and plans to address it in the next version, along with converting test file construction to use HERE documents as previously suggested.

This patch completes the sortedness verification component of the packed-refs validation system, working in conjunction with the earlier header validation and content checking patches in the series. The error reporting includes specific line numbers and refnames when sortedness violations are detected.
