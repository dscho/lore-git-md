Bugfix follow-up confirming bisect methodology. Patrick Steinhardt acknowledges Jeff King's analysis that the original bisect script wasn't reliably detecting the use-after-free issue in the revision walking code. The problem, which causes either segfaults or garbage output when combining `--graph` and `--no-graph` options, is now confirmed to originate from commit 087c745833 in v2.37.0. Jeff King's suggestion to use `SANITIZE=address,undefined` builds provides more reliable detection of the memory corruption. This thread appears to be wrapping up technical discussion about the bug's origin, with consensus on both the root cause and the fix (nulling freed pointers). The main remaining work seems to be adding regression tests to prevent future occurrences.
