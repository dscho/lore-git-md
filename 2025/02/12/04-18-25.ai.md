This is the final patch in a 3-part series introducing the new `git-diff-pairs` plumbing command, focusing on explicit queue control. The patch adds the ability to force a diff queue flush before reaching EOF by sending a NUL byte between file pairs, with output separated by a line terminator between flushes.

The implementation modifies the diff-pairs command to recognize NUL byte as a flush trigger, maintaining the existing behavior while adding this new control mechanism. When encountered, it flushes the queued diffs and adds a separator line (using the configured line terminator) between batches. The patch includes comprehensive tests verifying both regular and NUL-terminated output modes when using explicit flushes.

The changes are well-contained, touching only the command implementation, documentation, and test files. The documentation clearly explains the new flush behavior alongside the existing EOF-based flushing. Test coverage is thorough, checking both the basic functionality and edge cases like NUL-terminated output mode.

This completes the series' goal of providing flexible diff processing capabilities, particularly useful for server-side operations where controlled batch processing can help avoid timeouts. The implementation appears clean and consistent with the rest of the series, maintaining the careful attention to edge cases and documentation seen in previous patches.
