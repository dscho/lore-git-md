This is the first patch in a 3-part series introducing plumbing for batch blob diff generation, specifically refactoring diff queue internals to enable post-queue modification of `diff_filepair` structs.

The patch splits the existing `diff_addremove()` and `diff_change()` functions into two layers: the original functions now become thin wrappers around new `diff_filepair_addremove()` and `diff_filepair_change()` variants that return pointers to the queued `diff_filepair` structs. This allows callers to access and modify the queued pairs after creation, which will be needed in subsequent patches for the `git-diff-pairs` command.

Key technical changes:
- Adds new public API functions in diff.h returning `diff_filepair*`
- Preserves all existing behavior through wrapper functions
- Maintains identical error handling (returning NULL for ignored submodules/prefix mismatches)
- Keeps the same parameter lists but reorders them slightly for consistency
- Updates both .c and .h files with comprehensive changes

The refactoring is mechanical and well-contained, touching only diff.c and diff.h. The commit message clearly explains the motivation (needing to modify queued pairs) and the approach taken. This appears to be a clean preparatory change for the series' main functionality.
