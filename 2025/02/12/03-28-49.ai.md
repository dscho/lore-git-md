This is a follow-up discussion in the ongoing thread about adding long option names for Git's pickaxe functionality (`-S`/`--patch-modifies` and `-G`/`--patch-grep`). The email primarily addresses process feedback from Junio Hamano regarding patch submission practices.

The author, Illia Bobyr, acknowledges two key process issues with their v4 submission: (1) they had accidentally rebased on `next` instead of `master`, making the patches unapplicable to the expected base, and (2) they didn't properly reference the previous version in the thread. Both issues have been corrected in v5, which is now properly based on `master` and includes the appropriate thread references.

The exchange highlights some Git contribution norms:
- The importance of clearly stating the base branch when not using `master`
- The convention of maintaining reference links to previous versions in the thread
- The preference for replying directly to review messages rather than starting new threads

This is purely a process discussion - no technical changes to the pickaxe functionality are being debated here. The thread shows the v5 series is now properly positioned for maintainer consideration, having addressed both the technical aspects (as detailed in the thread summary) and these process requirements.
