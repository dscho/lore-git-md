This is a bug report about cross-compilation issues in Git's Meson build system. Peter Seiderer reports that when cross-compiling Git 2.48.1 using Meson (as opposed to autoconf), the resulting binary incorrectly hardcodes the host system's shell path (`/usr/bin/sh`) rather than the standard `/bin/sh`, causing `git fetch` to fail on the target system where that path doesn't exist.

The key difference is that Meson's `find_program('sh')` picks up the host's shell location during build, while autoconf apparently defaults to `/bin/sh`. The reporter suggests either hardcoding `/bin/sh` or making the shell location configurable via a Meson option when cross-compiling.

This appears to be a genuine cross-compilation pitfall that could affect anyone building Git with Meson for deployment on different systems. The report is clear and includes diagnostic details (strace output showing the failed execve call), though it doesn't propose a specific patch - just two possible solution approaches. The issue seems straightforward to reproduce and verify, making it a good candidate for maintainer attention.
