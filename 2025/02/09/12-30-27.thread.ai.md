Cross-compilation issue in Meson build system where host's shell path (/usr/bin/sh) leaks into target builds, causing git fetch failures when target expects /bin/sh. Originally reported by Peter Seiderer while converting Buildroot package from autoconf to Meson for Git 2.48.1. Problem stems from `find_program('sh')` calls not distinguishing build-time vs target-time executables.

Patrick Steinhardt proposes solution using Meson's `native:` parameter to properly separate paths - adding `native: true` to build-time tool lookups (asciidoc, perl, python) while introducing new `target_*` variables (target_shell, target_perl etc.) for target-side paths. Changes span multiple meson.build files to modify tool path detection, with target paths used where binaries run on target system. This maintains existing functionality while properly supporting cross-compilation.

The fix conflicts with Patrick's in-flight meson improvements series, so will be submitted after that lands. Key technical details: original issue manifests in meson.build lines 186 (shell detection) and 685 (SHELL_PATH definition), causing ENOENT when target lacks /usr/bin/sh. Solution involves proper separation of build-host vs target-host program paths configurable via cross files. Affects any cross-compiled Meson build where host and target paths differ.
