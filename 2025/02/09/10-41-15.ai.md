Performance optimization patch targeting commit graph traversal memory usage.

René Scharfe proposes a small but impactful change to `clear_commit_marks_many()` in commit.c that reduces peak memory usage during commit graph operations. The current implementation builds up a list of higher-numbered parents while clearing marks from commits, keeping this list growing until all commits are processed. The patch restructures this to clear the parent list after processing each commit, preventing unnecessary memory accumulation.

The change moves the `commit_list` declaration inside the processing loop and processes each commit's parents immediately rather than deferring them. This maintains the same functionality while reducing the maximum size of the parent list from potentially O(n) to O(1) in the worst case. The diff shows straightforward changes to the control flow with no behavioral side effects.

This appears to be a well-motivated optimization targeting a specific memory usage pattern in commit graph traversal. The patch is small (4 line changes) and focused, with a clear explanation of the benefit. It touches core commit processing code but the change is localized to mark-clearing operations. The approach seems sound and unlikely to introduce regressions given its simplicity.
