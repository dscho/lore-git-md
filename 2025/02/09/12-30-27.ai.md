Platform compatibility issue in Meson build system affecting cross-compilation.

This is a cross-compilation bug report where the Meson build system incorrectly leaks the host system's shell path (`/usr/bin/sh`) into the target build, causing `git fetch` to fail when the target system expects `/bin/sh`. The reporter, Peter Seiderer, encountered this while converting a Buildroot package from autoconf to Meson for Git 2.48.1. The autoconf build correctly uses `/bin/sh` while the Meson build hardcodes the host's shell path found via `find_program('sh')`.

The key technical details are in `meson.build` lines 186 and 685, where the shell path is discovered and then passed via `-DSHELL_PATH`. The reporter suggests either hardcoding `/bin/sh` or making this configurable via a Meson option for cross-compilation scenarios. The bug manifests as an ENOENT error when Git tries to execute the non-existent `/usr/bin/sh` on the target system.

This appears to be a genuine cross-compilation issue that would affect any Meson-built Git when the host and target systems have different shell paths. The report includes clear reproduction steps, strace output showing the difference between working and failing cases, and points directly to the problematic code. The solution would likely require Meson build system changes to properly handle shell path detection during cross-compilation.
