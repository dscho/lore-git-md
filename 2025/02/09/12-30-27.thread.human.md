This thread addresses a cross-compilation issue in Git's build system where the host's shell path (`/usr/bin/sh`) incorrectly leaks into target builds, causing failures when the target expects `/bin/sh`. The problem was first reported by Peter Seiderer while converting Buildroot's Git package from autoconf to Meson for Git 2.48.1.

Patrick Steinhardt proposed an initial solution for the Meson build system, introducing a separation between build-time and target-time tool paths using Meson's `native:` parameter and new `target_*` variables. However, Peter raised concerns about this approach based on Meson's documentation, identifying a specific bug in the implementation.

Junio Hamano has now expanded the discussion by questioning whether similar fixes should be made to the traditional make-based build system. He notes that Git's make build has historically assumed matching host and target paths, effectively making cross-compilation impossible by design. The thread now balances two perspectives: maintaining parity between build systems versus focusing only on Meson given the lack of demand for make-based cross-compilation support over the past two decades.

The core technical issue remains properly separating build-host and target-host paths for tools like `sh`, Perl, and Python. However, the discussion has broadened to consider build system maintenance philosophy, with Junio leaning toward limiting the fix to Meson due to practical usage patterns. The open question is whether to scope the solution to Meson alone or extend it to maintain feature parity between build systems.
