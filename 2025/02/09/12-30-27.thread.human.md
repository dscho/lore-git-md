This thread examines a cross-compilation issue in Git's build systems where the host's shell path (/usr/bin/sh) leaks into target builds, causing failures when the target expects /bin/sh. Originally reported by Peter Seiderer during a Buildroot package conversion from autoconf to Meson for Git 2.48.1, the problem affects both Meson and make builds differently.

Patrick Steinhardt proposed an initial Meson solution using `native:` parameters, but Peter raised documentation compliance concerns. Junio Hamano then questioned whether similar fixes should apply to make-based builds, given their historical lack of cross-compilation support. Peter's latest input suggests make users have generally accepted the hardcoded /bin/sh default, making this less urgent for the make build system.

Junio's most recent response acknowledges Peter's practical experience but maintains that the underlying technical issue - the lack of proper host-vs-target path separation in make - remains unresolved regardless of user acceptance. The discussion is converging toward addressing the issue in Meson first while leaving make's behavior unchanged for now, as Peter's observations indicate most make users are satisfied with the current defaults. The thread involves Peter Seiderer as reporter, Patrick Steinhardt as patch author, and Junio Hamano as maintainer weighing technical correctness against real-world usage patterns.
