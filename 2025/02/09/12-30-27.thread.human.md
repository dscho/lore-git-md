This thread examines how Git's build systems handle shell and interpreter paths during cross-compilation, particularly when the host's paths (like `/usr/bin/sh`) leak into target builds. The issue originally surfaced during Buildroot's conversion from autoconf to Meson for Git 2.48.1, where `git fetch` would fail on targets expecting `/bin/sh`.

Patrick Steinhardt initially proposed a Meson solution using `native:` parameters, while Peter Seiderer noted that Makefile users have historically relied on defaults like `SHELL_PATH=/bin/sh` without issues. Junio Hamano raised architectural concerns about Make's lack of proper host-vs-target path separation, regardless of autoconf usage.

In the latest update, Peter provides concrete evidence from Buildroot and Yocto projects. While Buildroot confirms SHELL_PATH defaults work fine, Yocto requires special handling for PERL_PATH during cross-compilation—including path rewriting via STAGING_BINDIR_NATIVE. This validates Junio's technical concerns about path separation while acknowledging Peter's practical observations. The discussion now converges on implementing proper path separation in Meson, with Makefile's technical debt left as a known (but deferred) issue. Key participants—Patrick, Peter, and Junio—remain engaged, balancing architectural principles with real-world deployment data.
