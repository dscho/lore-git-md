This thread reports a cross-compilation issue in Git's Meson build system where the host system's shell path (`/usr/bin/sh`) is incorrectly hardcoded into the target build, causing `git fetch` to fail when the target expects `/bin/sh`. The reporter, Peter Seiderer, encountered this while converting a Buildroot package from autoconf to Meson for Git 2.48.1. The autoconf build handles this correctly, but the Meson build discovers and hardcodes the host's shell path via `find_program('sh')` in `meson.build`, passing it via `-DSHELL_PATH`. This manifests as an ENOENT error when Git tries to execute the non-existent `/usr/bin/sh` on the target system. The reporter suggests either hardcoding `/bin/sh` or making this configurable via a Meson option for cross-compilation scenarios. The report includes clear reproduction steps and strace output showing the difference between working and failing cases, directly pointing to the problematic code in `meson.build` lines 186 and 685. This appears to be a genuine cross-compilation issue affecting any Meson-built Git when host and target systems have different shell paths.
