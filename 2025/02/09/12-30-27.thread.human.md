The thread addresses a cross-compilation issue in Git's Meson build system where the host system's shell path (/usr/bin/sh) was incorrectly being used for target builds, causing failures when the target system expected /bin/sh. Peter Seiderer originally reported this while working on Buildroot packaging for Git 2.48.1.

Patrick Steinhardt proposed a solution using Meson's `native:` parameter to properly separate build-time and target-time tool paths, introducing new `target_*` variables for paths that should run on the target system. However, Peter has raised concerns that this approach may not fully align with Meson's cross-compilation documentation, which suggests the `[binaries]` section specifies build-time tools. He also identified a specific bug in Patrick's patch where `perl.found()` was incorrectly used instead of `target_perl.found()`.

The discussion continues to focus on properly separating paths for shell, Perl, Python and other tools between build and target environments - a critical issue for cross-compilation scenarios where these paths differ. The original problem manifested when Git's meson.build tried executing a non-existent /usr/bin/sh on the target system. While the technical solution is being refined, the fix is expected to land after Patrick's in-flight Meson improvements series.
