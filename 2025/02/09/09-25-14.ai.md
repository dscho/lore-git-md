Platform compatibility issue with Git attributes and line endings. Josef Wolf reports unexpected behavior where Git appears to ignore explicit CRLF settings in `.gitattributes` for certain files, despite proper configuration. The issue manifests when checking line endings via `git ls-files --eol`, which shows LF line endings for files that should have CRLF according to the attributes.

The affected files are XML and text files from a proprietary application that randomly reorders XML elements, requiring a custom clean/smudge filter (`etsfile`). The setup includes careful `.gitattributes` rules to handle different file types, with explicit CRLF settings for text files and filters for XML processing, while excluding binaries.

This appears to be a specific interaction between the text conversion and filter attributes, where the filter may be interfering with the expected line-ending conversion. The issue occurs consistently across both Linux and Windows+MSYS2 environments, with no overriding configurations in info/attributes or global gitconfig.
