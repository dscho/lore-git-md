This is a bug report in the ongoing investigation of Git's attribute processing and CRLF conversion behavior. Josef Wolf reports a new and concerning issue where a `.store` file marked as binary in `.gitattributes` is being checked out as an empty file, despite containing data in the repository. The file shows up with index hash `e69de29b` (Git's special empty blob) in the working tree, while the repository version contains actual content (`4TamRjep...`).

The problem persists even after attempts to fix it with `git reset --hard` and removing/re-checking out the directory. The `git ls-files --eol` output confirms the file is properly marked with `-text` attribute, yet the content disappears during checkout. This appears to be a serious bug in Git's handling of binary files when combined with the complex filter/attribute setup being used (which includes both CRLF conversion rules and custom smudge/clean filters for XML files).

The report adds to the growing list of edge cases in Git's text processing pipeline, now showing that binary file preservation can fail in ways that make recovery difficult. This is particularly concerning as it affects actual repository content rather than just line ending conversions.
