Binary file corruption investigation update (attribute ordering issue).

Josef Wolf identifies the root cause of the binary file corruption case previously reported - it stems from an ordering problem in `.gitattributes` rules. The key finding is that a later rule (`*/P-* filter=etsfile`) was overriding an earlier rule (`*.store -filter -text`) that was meant to mark `.store` files as binary. This explains why the binary file was being incorrectly processed by filters despite being explicitly marked as binary.

The email retracts the previous report of a binary file corruption bug, clarifying this was actually a configuration error rather than a Git bug. The issue occurred because attribute rules are processed in order, with later rules taking precedence over earlier ones when they overlap. This is standard `.gitattributes` behavior, though the interaction with binary file handling can be subtle.

This resolves one of the two main issues in the thread (the binary file corruption case), leaving only the CRLF conversion timing anomalies still under investigation. The discovery demonstrates the importance of proper `.gitattributes` rule ordering when dealing with binary files and filter pipelines.
