René Scharfe proposed a memory optimization for commit graph traversal in `clear_commit_marks_many()`, restructuring the code to process parents immediately rather than accumulating them in a list. This reduces peak memory usage from O(n) to O(1) with minimal code changes. While the theoretical improvement is clear, Patrick Steinhardt has raised important considerations about the practical impact. He notes that the change effectively switches from depth-first to breadth-first traversal, which could perform worse in repositories with complex merge histories ("branch thickets"). Steinhardt is asking for real-world performance measurements to validate whether the memory savings outweigh any potential slowdowns in edge cases.
