Performance optimization patch targeting commit graph traversal memory usage.

René Scharfe proposes a small but effective change to `clear_commit_marks_many()` that reduces peak memory consumption during commit graph operations. The current implementation builds up a list of parent commits that grows with each processed commit before finally clearing them. The patch restructures this to clear the parent list after processing each individual commit instead.

The change is straightforward - it moves the parent list declaration inside the processing loop and clears it immediately after each commit rather than accumulating all parents first. This should reduce memory pressure when working with large commit graphs, though the commit message doesn't provide specific benchmark numbers.

The patch is cleanly implemented with minimal changes (4 lines modified) to the commit.c file. It follows the existing pattern while improving the memory usage characteristics. Given the author's track record with performance optimizations and the non-controversial nature of the change, this seems like a solid incremental improvement.
