Performance optimization for `git refs migrate` with new `--skip-reflog` flag.

This is a follow-up to the patch introducing a `--skip-reflog` option for `git refs migrate`, addressing review feedback from Justin Tobler. The original patch aimed to optimize reference backend migrations for server repositories where reflogs are unnecessary, building on commit 246cebe320 which made reflog migration the default behavior.

Karthik Nayak clarifies in this response that the performance improvement only applies to repositories that actually have reflogs - repositories without reflogs won't see any speedup from using the new flag. This answers Justin's question about the optimization's scope and confirms the flag is specifically useful when skipping existing reflogs during migration.

The technical implementation remains unchanged from the initial submission, which added a `REPO_MIGRATE_REF_STORAGE_FORMAT_SKIP_REFLOG` flag and modified the core migration logic in `refs.c` to conditionally skip reflog migration.
