Performance optimization patch for merge-recursive's rename processing.

This patch addresses a known quadratic complexity issue in the merge-recursive code when building sorted string lists for rename detection. The current implementation uses `string_list_insert()` which maintains sorting during insertion (O(n²)), while the patch switches to `string_list_append()` followed by a single sort (O(n log n)).

The change is straightforward - it removes the FIXME comment about the performance issue and replaces the insertion calls with appends, adding explicit sorting steps afterward. The commit message correctly notes this is safe because diffcore_rename guarantees no duplicates in these lists. The patch touches only merge-recursive.c, modifying the process_renames() function where two string lists (a_by_dst and b_by_dst) are constructed.

This appears to be a clean, well-motivated optimization that follows the documented best practices from string-list.h. The change is minimal (4 insertions, 10 deletions) and focused purely on the algorithmic improvement without introducing new behavior. The commit message could perhaps be more detailed about the real-world impact (merge performance on repositories with many renames), but the technical content is sound.
