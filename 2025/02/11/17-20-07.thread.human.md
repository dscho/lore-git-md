This thread addresses a documentation inconsistency in how Git's man pages describe boolean values. Junio Hamano noticed that different parts of the documentation listed varying sets of accepted true/false variants (like "yes", "no", "on", "off", 1, 0) without a single authoritative source.

The proposed patch establishes git-config(1) as the canonical reference for boolean value syntax. It expands git-config's `--type=bool` documentation to comprehensively list all valid variants, then updates git.txt and pretty-formats.txt to reference this definition rather than maintaining separate, incomplete lists. This change improves documentation quality by giving users one place to look for this information while eliminating redundancy.

The patch modifies text originally written by Taylor Blau but does so in a way that maintains all existing functionality while making the documentation more consistent. The changes are straightforward and uncontroversial, addressing a clear documentation gap without introducing any technical complexity.
