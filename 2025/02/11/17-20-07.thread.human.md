This thread documents an effort to standardize how Git's man pages describe boolean value syntax, with Junio Hamano proposing to consolidate the definitions under git-config(1) as the canonical reference. The initial patch expanded git-config's documentation to list all accepted boolean variants (like "true"/"false", "yes"/"no", etc.) while removing redundant definitions from other man pages.

Taylor Blau, who originally documented some of the boolean syntax in pretty-formats.txt, has weighed in with an important clarification. While Git accepts various boolean spellings as input, it always normalizes the output to "true" or "false" - a behavior the documentation should make explicit. He provided a test case showing that setting a config value to "yes" returns as "true" when queried. This nuance wasn't fully captured in the initial documentation.

The only other feedback so far was a minor grammatical tweak from Eric Sunshine to the commit message, which Junio has accepted. The discussion remains focused on documentation precision rather than any disagreement about the standardization effort itself. The next version of the patch will likely incorporate both the grammatical fix and Taylor's clarification about boolean normalization behavior.
