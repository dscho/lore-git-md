This is a discussion about configuration precedence between pull.ff and branch.rebase settings, continuing the thread about balancing safety and workflow flexibility.

Alex Henrie responds to D. Ben Knoble's proposal for a new `pull.ff=onlyUnlessOverridden` option, arguing instead for implementing per-branch fast-forward controls (`branch.<name>.ff` and `branch.autoSetupFf`).

The key points are:
1. Alex believes the configuration matrix is already complex enough and adding another pull.ff variant would make it worse
2. They advocate for a more comprehensive solution with per-branch ff settings that could address multiple use cases beyond just this one
3. The proposed branch-level controls would allow:
   - Setting fast-forward behavior per-branch (true/false/only)
   - Automatic ff configuration for new branches
   - More flexible workflows than the targeted onlyUnlessOverridden approach

Alex acknowledges the implementation would be more work but argues it's a better long-term investment, offering to help guide the implementation by pointing to existing branch.rebase code as a model.

This represents a shift in the thread from looking for a minimal fix to considering more fundamental configuration system changes. The discussion continues to grapple with how to balance safety (preventing accidental merges) with workflow flexibility while keeping the configuration system understandable.
