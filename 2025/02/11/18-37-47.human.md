This is a discussion thread about the proposed `git clean` exclusion patterns enhancement, with Junio C Hamano raising important conceptual questions about the design.

Junio engages with Ivan Shapovalov's patch series that adds persistent exclusion patterns to `git clean`. While acknowledging the cleverness of using the config system to introduce what appears to be a new "precious files" concept, Junio expresses several concerns:

1. **Terminology confusion**: He questions whether "precious" is being used consistently with Git's historical context, where ignored files were considered expendable rather than precious.

2. **Potential regression**: Junio warns that if this turns existing ignored files into protected "precious" files by default, it could be a serious usability regression.

3. **Design alternatives**: He suggests alternative implementations like using `clean.precious` config or `$GIT_DIR/info/precious` file instead of overloading the exclusion concept.

4. **Documentation clarity**: Junio notes the explanation could better distinguish between project-wide (.gitignore) and personal (clean.exclude) patterns if they're meant to have different semantic meanings.

The exchange highlights the careful balance needed when extending established Git behaviors, especially when introducing what might effectively be a new class of file treatment. Junio's questions suggest the patch may need clearer motivation and terminology before proceeding, though he acknowledges the backward-compatible nature of the changes is a positive aspect.
