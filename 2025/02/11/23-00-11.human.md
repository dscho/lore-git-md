Maintainer feedback on `git clean` exclusion patterns design.

Junio Hamano responds to Ivan Shapovalov's patch adding persistent exclusion patterns to `git clean`, building on their ongoing discussion. While appreciating the technical approach of using a new config variable to avoid backward compatibility issues, Junio raises several substantive concerns about the design:

1. **Terminology and semantics**: He questions classifying command-line `-e` patterns as "precious" by default, arguing this breaks existing expectations. The current behavior treats excluded files as expendable across Git commands.

2. **Broader integration**: The current implementation only affects `git clean`, while a true "precious files" concept would need integration with `git add`, `git switch`, and other commands that interact with the working tree.

3. **Project vs personal scope**: Junio notes that some precious files (like `config.mak`) should be project-wide rather than user-specific, suggesting the need for both config-based and repository-tracked pattern sources.

4. **Naming concerns**: The proposed `clean.exclude` name is problematic because (a) the behavior should affect more than just `clean`, and (b) "exclude" doesn't properly convey the "precious" protection concept.

The feedback suggests the patch needs significant redesign to properly implement the precious files concept across Git's ecosystem, with attention to both technical integration and clear, consistent terminology. Junio seems open to the general direction but wants a more comprehensive solution.
