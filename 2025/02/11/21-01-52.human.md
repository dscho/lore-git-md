This is a documentation patch clarifying the behavior of Git's merge renormalization feature. 

Elijah Newren updates the documentation for the `-X renormalize` option and `merge.renormalize` config to make it clearer that renormalization only applies to files needing three-way content merges, not all files in the tree. The change comes in response to user confusion where some thought renormalization was applied more broadly.

The patch makes small but precise wording changes across three documentation files (merge.txt, gitattributes.txt, and merge-strategies.txt) to consistently emphasize that renormalization happens specifically for files requiring three-way merges. The commit message notes there's technically also renormalization for modify/delete conflicts to handle normalization-only changes, but intentionally leaves this out of the docs to avoid overcomplicating the explanation.

The changes are straightforward and well-motivated by actual user confusion. The patch maintains the existing documentation's style while making the scope of renormalization more precise. This should help users better understand when and why to use this merge option.
