Performance optimization in merge-recursive's rename processing.

Meet Soni contributes a straightforward optimization to the merge-recursive code that handles rename detection. The patch changes how two string lists (`a_by_dst` and `b_by_dst`) are constructed during rename processing. Previously, these lists were built in sorted order using `string_list_insert()`, which results in O(n²) complexity. The new approach uses `string_list_append()` to build the lists unsorted, then sorts them afterward with `string_list_sort()`, reducing the complexity to O(n log n).

The change is small (4 lines added, 10 removed) and well-contained, touching only the rename processing logic in merge-recursive.c. The commit message explains the performance rationale clearly, and the diff removes an outdated FIXME comment that had noted the quadratic complexity issue. This appears to be a clean, focused optimization that should provide measurable benefits during merges with many renames, though the impact would depend on the number of renames in a given merge operation.
