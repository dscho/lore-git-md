This is a bugfix for interactive rebase's reword operation, specifically addressing empty commits that were fast-forwarded. Phillip Wood's v2 patch follows up on Junio Hamano's request to add an explanatory comment about the flags handling in the rebase machinery.

The key changes in this version:
1. Adds the requested comment explaining why a fixed set of commit flags (including ALLOW_EMPTY) is used when rewording, rather than building incrementally
2. Maintains the same core fix from v1 - always passing --allow-empty when rewording non-merge commits
3. Preserves the special case for merge commits which don't need --allow-empty
4. Includes the same test coverage from v1 (34 lines across two test files) verifying both regular empty commits and empty merge commits

The implementation now properly documents the flags handling pattern deviation while keeping the functional fix for rewording fast-forwarded empty commits. The test coverage appears thorough, checking both the basic case and merge commit edge case. With the maintainer's requested comment added, this appears ready for inclusion.
