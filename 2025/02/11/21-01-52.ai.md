Documentation patch clarifying the behavior of merge's renormalize option. This addresses confusion about when exactly Git applies line-ending normalization during merges.

The patch updates three documentation files to make clear that the `-X renormalize` option (and corresponding `merge.renormalize` config) only applies normalization to files that require a three-way content merge, not to all files in the tree. The commit message notes this corrects a common misconception while deliberately omitting discussion of the more obscure case of modify/delete conflicts where normalization is also applied.

The changes are straightforward documentation tweaks to `Documentation/config/merge.txt`, `Documentation/gitattributes.txt`, and `Documentation/merge-strategies.txt`, consistently adding the qualifier about three-way merge cases. The commit references a previous discussion thread (linked via lore.kernel.org) that presumably surfaced the confusion this aims to resolve. The patch appears well-scoped and uncontroversial, focused solely on improving documentation clarity without changing any behavior.
