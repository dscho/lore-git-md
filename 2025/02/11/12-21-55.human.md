Performance optimization for reference backend migrations with final review approval.

Patrick Steinhardt gives the final sign-off on Karthik Nayak's patch adding a `--skip-reflog` flag to `git refs migrate`. This builds on earlier work that made reflog migration the default behavior, now giving server administrators an escape hatch when migrating repositories that have accumulated unwanted reflogs (from bugs, misconfigurations, or temporary debugging).

The patch has gone through two rounds of review, with all technical feedback addressed - including test improvements to use more robust Git test helpers and clarifications about the optimization's scope (it only benefits repositories that actually have reflogs being skipped). The implementation adds a new flag bit to the migration API and exposes it through the CLI interface while maintaining safety.

With this final approval from a core Git maintainer, the patch appears ready for inclusion in the next cycle. The change is narrowly scoped but provides meaningful performance benefits for server administrators migrating large repositories where skipping unnecessary reflog processing could save significant time and I/O.
