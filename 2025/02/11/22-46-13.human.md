Brian Carlson responds to Jeff King's proposed workaround for the NFSv4 packfile permissions issue, expressing cautious support but with concerns about broader implications. This is part of an ongoing discussion about how Git handles temporary file permissions during packfile operations on NFSv4 systems.

Carlson acknowledges that King's suggestion to create tempfiles with 0644 permissions and later chmod to 0444 might work for this specific case, but worries it could mask deeper issues with NFSv4's permission re-checking behavior during failover scenarios. He notes this particular bug is especially problematic because it can surface mid-operation rather than failing immediately.

The response highlights two key reservations: first, that similar fixes might be needed across other software (like zsh and Emacs) if this is truly an NFSv4 server issue, and second, that they want to avoid scattering NFS-specific workarounds throughout Git's codebase. Carlson also shares an anecdote suggesting this NFS behavior would break other proprietary software that uses similar open/fchmod patterns.

While not outright rejecting the proposal, Carlson's tone suggests this solution should be carefully considered and limited in scope, given the difficulty of testing such edge cases and the potential for this to be just one symptom of broader NFSv4 server issues. The discussion remains open about whether this specific workaround is the right path forward.
