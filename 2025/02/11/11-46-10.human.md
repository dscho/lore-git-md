Feature: Shell script function recognition in diffs

This patch adds built-in shell script function recognition to Git's diff machinery, improving hunk header display for shell scripts. The change introduces regex patterns in `userdiff.c` to detect both POSIX-style (`function_name()`) and Bash/Ksh-style (`function name`) function definitions while avoiding false matches on shell keywords like `if` or `for`. The implementation also includes tokenization support for common shell elements like variables, numeric constants, and operators.

As a GSoC 2025 contribution, this appears to be a focused, self-contained change that fills a gap in Git's language support. The implementation shows attention to detail with explicit exclusions for shell keywords and support for multiple function syntax variants. However, the commit message doesn't explain why this wasn't previously supported or what specific pain points it addresses. The change lacks test coverage, which would be valuable given shell's syntactic complexity and the potential for edge cases in pattern matching.

The patch could significantly improve the experience of reviewing shell script changes in Git repositories, though reviewers may want to verify the pattern completeness against real-world shell scripts and consider adding tests. This represents a straightforward quality-of-life improvement that aligns well with Git's existing userdiff capabilities.
