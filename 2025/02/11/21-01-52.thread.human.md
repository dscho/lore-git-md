This thread documents a clarification to Git's merge behavior regarding line-ending normalization. The initial patch updates three documentation files to make clear that the `-X renormalize` option (and corresponding `merge.renormalize` config setting) only applies line-ending normalization to files that require a three-way content merge, not to all files in the repository. This corrects a common misconception while deliberately avoiding discussion of the more obscure modify/delete conflict case where normalization also applies.

The changes are straightforward documentation tweaks to `config/merge.txt`, `gitattributes.txt`, and `merge-strategies.txt`, consistently adding this clarification. The patch references a previous discussion that identified this point of confusion. As a documentation-only change that improves accuracy without altering behavior, this appears uncontroversial and well-scoped.
