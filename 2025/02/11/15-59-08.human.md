Bugfix for interactive rebase's reword operation on fast-forwarded empty commits.

Phillip Wood's patch fixes an edge case where rewording an empty commit that was fast-forwarded during an interactive rebase would fail. The issue occurs because the rebase`--allow-empty` flag wasn't being passed to `git commit --amend` in this specific code path. The fix modifies `sequencer.c` to always include `ALLOW_EMPTY` when rewording non-merge commits, since we know the commit was already successfully picked.

This version (v2) addresses Junio Hamano's feedback from the initial submission by adding a clear comment explaining why the patch overwrites the flags variable rather than incrementally building it - an intentional choice to maintain consistency regardless of how the commit was picked. The patch includes thorough test coverage with new cases in both `t3404-rebase-interactive.sh` and `t3430-rebase-merges.sh` that verify the fix works for regular commits while preserving the special handling of merge commits (which don't need `--allow-empty`).

The change is small (12 lines modified) but addresses a real pain point for users trying to reword empty commits during rebase. With the maintainer's requested documentation improvement now included, this appears ready for inclusion.
