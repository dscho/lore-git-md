Performance optimization for reference backend migrations. This is the second version of a patch adding a `--skip-reflog` flag to `git refs migrate`, addressing review feedback from Patrick Steinhardt and Justin Tobler.

The change allows server repositories to skip reflog migration when changing reference backends, which can improve performance since server repos typically don't need reflogs (though some may have them due to historical reasons). The implementation adds a new flag bit `REPO_MIGRATE_REF_STORAGE_FORMAT_SKIP_REFLOG` and modifies the migration logic to conditionally skip reflog processing.

Version 2 incorporates several test improvements suggested by reviewers, replacing fragile `wc -l` checks with Git's `test_line_count` and `test_must_be_empty` helpers. The commit message has also been clarified to better explain that the optimization targets server repositories where reflogs exist but aren't needed, rather than claiming servers never have reflogs.

The patch appears well-tested and addresses all technical feedback from the previous round. It's a focused optimization that maintains the default reflog migration behavior for client repositories while giving server admins a way to skip this step when appropriate.
