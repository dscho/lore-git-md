This is a discussion about a proposed workaround for NFSv4 packfile handling issues, continuing the thread about temporary file permissions during failover scenarios. Brian Carlson responds to Jeff King's suggestion of creating tempfiles with 0644 permissions initially and then switching to 0444 before finalizing.

Carlson expresses cautious support for the proposed solution but raises concerns about potential edge cases where files might silently get reopened with rechecked permissions, which could lead to hard-to-reproduce failures. He notes this particular NFSv4 behavior is more problematic than standard permission-check failures because it can occur mid-operation. While not opposed to a targeted fix, Carlson warns against scattering multiple NFS-specific workarounds throughout the codebase, suggesting any solution should be limited to this specific case.

The response highlights broader implications, noting that similar fixes would be needed in other software (like go-git and libgit2) and that this NFSv4 behavior would likely break various proprietary applications that use open/fchmod sequences. Carlson's position reflects a balance between addressing the immediate issue and maintaining Git's long-term maintainability, while acknowledging the practical challenges of testing such filesystem-specific behavior.
