This is a discussion thread about the proposed `git clean` exclusion patterns enhancement, with Junio C Hamano providing feedback on the design and terminology.

Junio raises several important points about the patch series' conceptual model and naming choices. He questions whether the term "precious" aligns with Git's historical terminology, where "ignored" files were considered expendable rather than valuable. He expresses concern that treating existing ignored files as precious by default could be a usability regression.

The email suggests alternative approaches to the proposed `clean.exclude` configuration:
1. Using `clean.precious` as a more semantically accurate name if the intent is to protect valuable files
2. Storing personal precious patterns in `$GIT_DIR/info/precious` rather than config
3. Clarifying that project-wide expendables belong in `.gitignore` while personal expendables can use `$GIT_DIR/info/exclude`

Junio also notes the cleverness of leveraging Git's project-vs-personal configuration distinction to implement the precious files concept, while maintaining backward compatibility. He raises a side question about why Ævar Arnfjörð Bjarmason was CC'd on the original series.

Key technical points discussed:
- The distinction between project-level (`.gitignore`) and user-level (`clean.exclude`) patterns
- Semantic implications of calling files "precious" vs "excluded"
- Alternative storage locations for precious patterns
- Need for clearer documentation about the different exclusion classes

This email doesn't propose concrete changes to the patch series but surfaces important design considerations that will likely shape the ongoing discussion about the implementation approach.
