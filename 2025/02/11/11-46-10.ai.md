Feature addition to Git's userdiff subsystem for shell script function recognition.

This patch introduces a new built-in userdiff driver for shell scripts, expanding Git's diff hunk header capabilities to properly identify function definitions. The implementation handles both POSIX-style (`function_name()`) and Bash/Ksh-style (`function name`) syntax while explicitly excluding shell keywords that could be mistaken for functions. The regex patterns also improve tokenization for common shell elements like variables, numeric constants, operators, and grouping symbols.

The change is focused and well-scoped, touching only `userdiff.c` with a 20-line addition. The commit message clearly documents the supported syntax variants and the rationale for keyword exclusion. The implementation appears thorough, covering major shell syntax elements that would be useful for diff context. However, the patch lacks test coverage - no new tests are included to verify the pattern matching behavior against edge cases or different shell dialects.

This appears to be a standalone contribution rather than part of a larger series, building on Git's existing userdiff infrastructure. The change could significantly improve diff readability for shell script contributors, though reviewers may want to examine the regex patterns for potential edge cases in shell syntax handling. The exclusion of shell keywords is particularly thoughtful, preventing false positives in function detection.
