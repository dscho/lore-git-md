This is a refactoring patch in a series about partial reference transactions, specifically moving duplicate refname checking from individual backends to the generic refs layer. The patch centralizes refname tracking by adding a `refnames` string_list to `ref_transaction` that gets populated when updates are added, eliminating redundant checks in the files, packed, and reftable backends.

Key technical details:
- Adds `refnames` field to `ref_transaction` initialized with `string_list_init_dup()`
- Modifies `ref_transaction_add_update()` to populate the list (except for `REF_LOG_ONLY` updates)
- Moves duplicate checking to `ref_transaction_prepare()` using the centralized list
- Removes backend-specific duplicate checking code (-116 lines)
- Maintains special handling for symrefs/HEAD in backends
- Keeps string duplication in the list for memory safety (though reviewer questions if this is necessary)

The patch sparked discussion about:
1) Whether string duplication in the list is needed (reviewer suggests ref_updates may keep strings alive)
2) Potential future optimization using strset instead of string_list
3) Why symref handling can't be fully moved to generic layer yet - deemed too complex for current series
4) Clarification needed around when refnames get added to the list (particularly for symref cases)

The author agrees to add more explanation in the commit message about the symref handling and the timing of refname list population. While not strictly required for the partial transactions feature, this refactoring simplifies the code and makes future changes easier.
