This is version 4 of the patch series introducing long option names for Git's pickaxe search functionality (`--patch-modifies` for `-S` and `--patch-grep` for `-G`). The series has been significantly restructured from v3 based on Junio Hamano's feedback, now split into 10 focused patches that can be reviewed and merged independently.

The first 4 patches are minor cleanups fixing documentation inconsistencies and typos in pickaxe-related help text. Patch 5 standardizes placeholder names in gitdiffcore. Patch 6 is the core change adding the new long option names while maintaining backward compatibility. Patch 7 adds bash completion support. The final 3 patches (8-10) incrementally update tests, CLI help text, and documentation to use the new long names where the author believes they improve readability.

Key changes from v3:
- Split monolithic patch into logical units
- Kept core functionality changes minimal in patch 6
- Moved documentation updates to later patches for easier review/rejection
- Fixed whitespace and indentation issues
- Addressed Junio's concern about documentation churn by introducing long forms alongside rather than replacing short forms
- The gitk integration mentioned in earlier versions has been removed from this series

Open questions:
- Whether to adopt the long-form updates in tests/docs (patches 8-10) or keep them minimal
- Terminal width concerns with expanded help text
- Whether to maintain consistency between `<regex>` vs `<regular-expression>` placeholders

The technical implementation appears sound, with all tests passing for both short and long option forms. The series shows good responsiveness to review feedback while maintaining the author's goal of improved readability through long option names.
