This is a documentation patch that standardizes and centralizes the documentation of boolean value spellings across Git's documentation.

Junio Hamano noticed that Git's documentation inconsistently describes the various ways to spell boolean values (`true`, `yes`, `on`, etc.) across different man pages. Currently, the git(1) man page assumes readers already know how boolean config variables work, while git-config(1) only briefly mentions canonicalization without listing all accepted values. The pretty-formats documentation also has its own incomplete list with an ambiguous "etc.".

The patch makes git-config(1) the canonical source by explicitly listing all accepted boolean value spellings there (including numeric values like `0` and `1`), then updates git(1) and pretty-formats.txt to reference this central definition rather than maintaining their own partial lists. The changes are straightforward documentation improvements that don't affect actual behavior, just making the docs more complete and consistent.

This appears to be a well-justified cleanup that addresses a real documentation gap. The patch is cleanly focused and references a related recent discussion (though no thread context was provided here). As documentation from the project maintainer, it's authoritative and likely to be accepted.
