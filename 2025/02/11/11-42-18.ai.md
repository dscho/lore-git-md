Performance optimization for reference backend migrations with a new `--skip-reflog` flag. This is the second version of a patch that builds on commit 246cebe320 which made reflog migration the default behavior for `git refs migrate`. The change targets server repositories that may have accumulated reflogs (due to bugs, misconfiguration, or debugging) but don't need them, allowing administrators to skip this costly part of the migration.

The implementation adds a `REPO_MIGRATE_REF_STORAGE_FORMAT_SKIP_REFLOG` flag bit and modifies `repo_migrate_ref_storage_format()` to conditionally skip reflog migration when requested. The CLI interface in `builtin/refs.c` gains the new `--skip-reflog` option, while tests in `t/t1460-refs-migrate.sh` verify the behavior using more robust test helpers (`test_line_count` and `test_must_be_empty`) as suggested in review feedback.

Key technical details for future reference:
- The optimization only benefits repositories that actually have reflogs being skipped (not repositories without any reflogs)
- The test helper `test_migration()` was enhanced to accept additional options while maintaining shell arithmetic functionality
- Core changes are in `refs.c` (migration logic) and `refs.h` (flag definition)
- Test coverage includes verification that reflogs are properly skipped when requested

All review feedback from Patrick Steinhardt has been addressed in this version, including clarification of the optimization's scope (targeting server repositories where reflogs exist but are unwanted) and improved test robustness. The patch appears ready for final consideration.
