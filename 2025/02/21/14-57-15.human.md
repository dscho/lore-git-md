This is a bugfix series addressing edge cases in `git add -p`'s hunk splitting behavior. Phillip Wood fixes two issues that can occur when splitting hunks that have already been selected or edited, which he noticed while working on test cases for another feature.

The first patch ensures that when a hunk is split, the resulting sub-hunks are marked as "undecided" rather than inheriting the parent hunk's selection state. The second patch makes sure the splitability status of hunks is properly updated after editing them. Both changes come with new test cases to verify the fixes.

The changes are focused and well-explained, touching only the interactive add functionality. The test coverage looks thorough, exercising both the split-after-selection and split-after-edit scenarios. These appear to be straightforward quality-of-life improvements for a commonly used interactive command.
