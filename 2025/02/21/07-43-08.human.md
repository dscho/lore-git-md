This is a technical discussion about progress reporting improvements in the bundle-URI HTTPS download feature, specifically focusing on the `progress_set_total()` API.

Jeff King (Peff) is responding to Toon Claes's patch that adds a function to dynamically set the total size of a progress meter after it's been started. This is needed for HTTP downloads where the total size isn't known until after the transfer begins (when the Content-Length header arrives).

Peff confirms the basic approach makes sense but raises a subtle question about whether we should immediately update the progress display when the total is set, rather than waiting for the next progress update. He notes this might be tricky to implement cleanly since we'd need to know which display mode (percentage or throughput) to use, and concludes it's probably not worth the complexity given that HTTP downloads update frequently anyway.

The discussion is part of a larger v2 series (7 patches) improving progress reporting for bundle downloads, with Peff providing review feedback on implementation details. This particular exchange shows the careful consideration being given to edge cases in the progress meter behavior.
