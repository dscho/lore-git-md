This is a feature patch adding object filtering capability to `git cat-file`'s batch mode, part of a larger series (2/9). The patch introduces a new `--objects-filter` option that will allow filtering objects by type and size, though the actual filtering functionality is not yet implemented (to come in later patches).

The patch wires up the option parsing infrastructure, reusing the same filter syntax as `git rev-list --filter` but with a different option name (`--objects-filter` instead of `--filter`) to avoid confusion with the existing `--filters` option. Currently it just validates and rejects all filter specifications with appropriate error messages, which are tested in the new test cases.

Key technical details:
- Adds `objects_filter` field to `struct batch_options` initialized with `LIST_OBJECTS_FILTER_INIT`
- Uses `opt_parse_list_objects_filter` callback for option parsing
- Rejects all non-disabled filter choices with BUG/usage errors for now
- Includes comprehensive tests for error cases (unknown/unsupported filters)
- Notes that future bitmap integration could improve performance, though current implementation will still need to scan packfiles

The implementation carefully handles memory management with `list_objects_filter_release()` and maintains existing behavior when no filter is specified. The commit message clearly explains the design decisions around naming and performance characteristics.
