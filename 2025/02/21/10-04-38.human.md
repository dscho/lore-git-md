This is a review comment on patch 3/5 in the series converting oid-related tests to the Clar framework, focusing on the oidmap conversion. Phillip Wood provides detailed feedback on both the commit message and implementation.

The review notes that the commit message's explanation about `cl_parse_any_oid` is unclear - it doesn't specify what checks are performed or how they help the test. Phillip also questions the claim that using global state makes tests more self-contained, pointing out this is actually a limitation of Clar's setup/teardown functions.

The main technical feedback concerns the assertion quality in the diff. Phillip suggests using `clar_fail_f()` instead of `cl_assert_equal_i()` to preserve the helpful error messages from the original test. He also notes the change in behavior from detecting all errors to failing on first error, which should be documented in the commit message.

While the overall conversion approach is sound, this patch needs revision to maintain test quality - particularly in error reporting - and clearer commit message explanations. The feedback continues the thread's theme of balancing modernization with preserving test robustness.
