This is part 5/9 in Patrick Steinhardt's series enhancing `git cat-file` with object filtering capabilities, specifically focusing on type-based filtering. The patch adds support for the "object:type=" filter, which allows users to restrict output to only objects of a specified type (blob, commit, tag, or tree).

The implementation is straightforward - it checks each object's type against the requested type and skips non-matching objects. The change touches documentation, core filtering logic in builtin/cat-file.c, and adds comprehensive tests covering all supported object types. This builds on previous patches that added blob filtering capabilities.

As part of a well-structured series addressing real performance pain points in large repositories, this patch appears cleanly implemented with proper test coverage. The type filtering functionality will be particularly useful for workflows that need to process only specific object types, avoiding the overhead of processing irrelevant objects. The series as a whole shows careful attention to both functionality and performance implications.
