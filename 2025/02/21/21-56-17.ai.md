This is a documentation patch clarifying submodule merge behavior, now in its second iteration. The patch adds explanation of two special submodule conflict resolution cases that were previously only visible in the merge-ort.c and merge-recursive.c source code. The text describes how Git attempts a fast-forward when one submodule commit is a descendant of another, and how it suggests a common descendant as resolution while keeping the status as unmerged for user confirmation.

Elijah Newren, who originally suggested moving this documentation from git-merge.adoc to merge-strategies.adoc, now raises a broader documentation organization concern. He notes this information actually applies to all merge-machinery-using commands (cherry-pick, rebase, revert, etc), not just `git merge`, but there's currently no ideal place in the documentation structure that covers all these commands. While he acknowledges the current placement in merge-strategies.adoc is workable, he invites other reviewers to suggest better solutions, with the caveat that a comprehensive documentation reorganization shouldn't block this small but useful clarification.

The technical content of the documentation itself appears settled after previous review rounds, with the remaining discussion focused purely on documentation structure. The patch maintains identical text in both the 'ort' and 'recursive' strategy sections since both implementations share this behavior. This follows up on earlier feedback from D. Ben Knoble about the text duplication and Jean-Noël Avila's suggestion to use AsciiDoc attributes to avoid repetition, though Junio C Hamano expressed reservations about that approach's maintainability.
