Bug report about `git diff` behavior during merges. Yurii Kartsev reports that when merging a branch into main, `git diff` fails to show one of the expected diffs (specifically changes from a "Version update" commit), though the changes do appear later in `git diff --cached` after staging the file. The report includes detailed reproduction steps and a sample repository to demonstrate the issue.

The behavior appears to be a potential bug in how `git diff` displays merge conflicts, where it's omitting some changes that should be visible. The reporter is using Git 2.39.5 on macOS) and notes they couldn't test with a newer version due to build issues. The report is well-structured with clear reproduction steps and test data, making it easy for maintainers to investigate. This seems like a legitimate issue worth looking into, particularly for users who rely on `git diff` during merge operations.
