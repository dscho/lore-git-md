This is a Windows-specific bugfix for `git mv` symlink handling that has been accepted for merging. The patch addresses a regression where Windows would incorrectly rename symlink targets instead of the symlinks themselves, caused by missing `FILE_FLAG_OPEN_REPARSE_POINT` in the Windows API calls. The fix is minimal (one line) but important for Windows users working with symlinks created either through Git or other means.

The thread shows consensus that this should be upstreamed regardless of ongoing work to improve Windows symlink support. Existing tests (t7001-mv.sh tests 38-39) already catch this issue when run on Windows with symlink capabilities. Junio Hamano has reviewed and marked it for inclusion in the 'next' branch, indicating the fix is technically sound and ready for wider testing.

The patch comes from Git for Windows maintainer Johannes Schindelin, who notes this is separate from his broader symlink support work. The change maintains backward compatibility while fixing the specific symlink renaming behavior, with no outstanding objections remaining in the discussion.
