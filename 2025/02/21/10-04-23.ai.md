Performance optimization for reference backend migrations with a new `--no-reflog` flag. This is the fifth iteration of a patch that has already been technically approved and is now in its final documentation polish phase.

The patch adds a `--no-reflog` option to `git refs migrate` that allows skipping reflog migration, which is particularly useful for server-side repositories where reflogs are typically unnecessary. The implementation includes:
- A new `REPO_MIGRATE_REF_STORAGE_FORMAT_SKIP_REFLOG` flag in refs.h
- Modified migration logic in refs.c to conditionally skip reflog transfer
- CLI handling in builtin/refs.c
- Comprehensive documentation updates in git-refs.txt
- Additional test cases in t/t1460-refs-migrate.sh

Key technical details:
- The flag name `--no-reflog` was explicitly approved by Junio C Hamano
- Documentation uses "convert" terminology as suggested by Junio
- Parseopt API properly handles the double-negative case (`--no-no-reflog`)
- Tests verify both default and flag-specified behavior
- Performance impact is significant for large repositories with millions of refs
