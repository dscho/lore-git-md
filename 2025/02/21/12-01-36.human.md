This is a bugfix for Windows platform compatibility, specifically addressing an issue with renaming symbolic links. The patch corrects a regression where `git mv` on Windows would incorrectly rename the symlink's target rather than the symlink itself. This happened because the Windows API call `CreateFileW` was missing the `FILE_FLAG_OPEN_REPARSE_POINT` flag needed to properly handle symlinks (which Windows treats as reparse points).

The fix is straightforward - adding the missing flag to the file opening operation. The change is safe because the flag is ignored for non-reparse-point files. The regression was detectable in existing tests (`t7001-mv.sh` tests 38 and 39) when run on Windows with proper symlink creation capabilities.

Johannes Schindelin notes this should be upstreamed even though full symlink support for Windows is still in progress, since symlinks can be created through other means besides Git. The patch appears well-justified with clear documentation references and test coverage.
