This thread addresses a build issue on OpenBSD where clang 19's stricter warnings exposed a missing `getdelim()` declaration due to insufficient `_XOPEN_SOURCE` settings in `git-compat-util.h`. The problem emerged through nixpkgs builds, though the root cause lies in OpenBSD's headers requiring `_XOPEN_SOURCE 700` (rather than 600) to expose this function.

Audrey Dutcher initially proposed adjusting the `_XOPEN_SOURCE` value, while Junio suggested restructuring the platform-specific defines to handle OpenBSD separately. Jeff King later clarified why this issue only surfaced now: Git's build system typically enables `getdelim()` by default only for Linux and macOS, with other platforms relying on autoconf detection. Since most developers don't use autoconf builds, the warning went unnoticed until nixpkgs (using clang 19's default warnings) hit it.

The discussion has moved from diagnosis to solution design, with two main approaches under consideration: modifying the existing platform handling or creating a dedicated OpenBSD block. Jeff also suggested potentially adding OpenBSD to the default `HAVE_GETDELIM` list in `config.mak.uname`. The thread remains focused on OpenBSD's case but has provided valuable insights into Git's build system behaviors and feature detection mechanisms.
