Performance optimization follow-up in git bisect thread.

Christian Couder responds to Junio Hamano's experimental patch that dramatically improved `git bisect` performance by implementing midpoint merge traversal. The original patch showed a 30x speedup (20min→30sec) while maintaining comparable bisection accuracy (19 vs 17,871 commits from theoretical halfway in test case).

Couder agrees the core optimization (#1 - midpoint traversal) is sufficient, while offering nuanced feedback on the two experimental approaches Junio left commented out:

1. For the "loosened halfway threshold" approach (#2), Couder suggests it could still be useful as an optional mode if implemented to work even on small candidate sets, noting the tradeoff between precision and speed might appeal to some users.

2. Regarding the "early discard" optimization (#3), Couder proposes that implementing a first-parents-first bisection option would be more generally useful than this approach.
