This thread introduces performance optimizations for `git cat-file`'s batch mode, specifically adding object type filtering capabilities. The motivation comes from GitLab's real-world need to efficiently list objects of specific types in large repositories, where current shell-based workarounds are prohibitively slow (taking 100 seconds to scan Chromium's 50GB packfile).

The series adds three filter types matching `git rev-list` syntax: "blob:none", "blob:limit=", and "object:type=". The key innovation is leveraging bitmap indices when available to avoid full packfile scans, showing dramatic speedups - filtering tags becomes ~4000x faster (20ms vs 82s) and commits see a 75x improvement. The implementation comes in two phases: first adding basic filtering (patches 1-5), then optimizing with bitmaps (patches 6-9).

The changes touch core object iteration logic in `builtin/cat-file.c` and bitmap handling in `pack-bitmap.*`, with comprehensive tests added. Benchmarks show the filters scale with the number of matching objects rather than total repository size, solving a clear performance pain point while maintaining backward compatibility.
