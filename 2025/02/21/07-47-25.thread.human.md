Patrick Steinhardt's series to enhance `git cat-file` with object filtering capabilities continues to progress, with the second patch now focusing on the command-line interface plumbing. The series, now in its second iteration, aims to significantly speed up object filtering operations by leveraging Git's bitmap infrastructure when available.

The current patch establishes the `--filter` option interface for `git cat-file batch` mode, matching the syntax used by `git rev-list`. While the actual filtering logic will come in later patches, this change sets up the necessary scaffolding by adding filter options parsing and error handling. The implementation includes comprehensive test coverage for the various filter types (blob:none, blob:limit, object:type) even though they currently just return errors.

The series as a whole has already demonstrated impressive performance gains in benchmarks, showing a 41x speedup (from 86 seconds to 2 seconds) for commit filtering in the Chromium repository when using the bitmap-optimized path. Junio Hamano has approved the naming convention, and Patrick is actively coordinating with Taylor Blau on prerequisite bitmap work that needs to land first. The implementation maintains a dual-path architecture that will work with both traditional packfile scanning and the optimized bitmap traversal. With 8 more patches to come in this series, the project is methodically building toward its goal of fast, flexible object filtering in `git cat-file`.
