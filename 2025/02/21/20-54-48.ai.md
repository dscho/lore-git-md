Platform compatibility follow-up discussing OpenBSD's `getdelim()` build issue, with additional context about build configurations.

Jeff King provides important technical background about why this OpenBSD compilation issue only surfaced recently, despite the OpenBSD headers not changing. The key insight is that Git's build system only enables `getdelim()` by default for Linux and macOS in `config.mak.uname`, while other platforms (including OpenBSD) would only get it via autoconf detection. Since most Git contributors don't use autoconf builds, the warning wasn't caught until nixpkgs (which uses clang 19's stricter warnings by default) encountered it.

The email suggests two potential follow-up actions: making the autoconf test more strict about warning-free builds (though notes this isn't common practice), and proposing that OpenBSD could have `HAVE_GETDELIM` enabled by default in `config.mak.uname` if an OpenBSD maintainer wants to submit that change. While supporting the current warning-fix patch, this response helps explain the broader build system context that led to the issue's discovery.

Key technical details for future reference: the role of `config.mak.uname` vs autoconf in feature detection, the default `HAVE_GETDELIM` settings for different platforms, and the distinction between regular developer builds (usually without autoconf) and nixpkgs builds (with stricter warnings). The discussion remains focused on OpenBSD's specific case while providing useful context about Git's build system behaviors.
