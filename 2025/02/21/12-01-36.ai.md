This is a bugfix for Windows platform compatibility, specifically addressing symlink handling in the `git mv` command. The patch corrects a regression where renaming a symlink would incorrectly rename its target instead of the symlink itself.

The issue stems from Windows API behavior where `CreateFileW` would dereference symlinks (which are reparse points) unless explicitly told not to with `FILE_FLAG_OPEN_REPARSE_POINT`. The fix adds this flag alongside the existing `FILE_FLAG_BACKUP_SEMANTICS`, ensuring proper symlink handling while maintaining compatibility with regular files and directories.

The regression is detectable by existing tests in `t7001-mv.sh` (tests 38 and 39), but only when run on Windows with proper symlink creation capabilities. The commit message provides thorough background, including links to prior related commits, Windows API documentation, and the original bug report.

The change is minimal (a single line modification in `compat/mingw.c`) but impactful for Windows users working with symlinks. Johannes Schindelin notes this should be upstreamed regardless of ongoing symlink support work, as symlinks can be created through other means besides Git. The patch appears well-researched and addresses a clear behavioral bug with a focused solution.
