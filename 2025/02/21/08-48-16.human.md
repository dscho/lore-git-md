# Performance benchmarking infrastructure discussion

This is a follow-up in the ongoing discussion about establishing continuous performance benchmarking for Git. Patrick Steinhardt (GitLab) responds to Emily Shaffer's (Google) suggestions about potential Google contributions to the effort.

Patrick agrees that Google Cloud-hosted benchmarking could help solve the "noisy neighbors" problem in CI environments, though notes that even nightly runs would be an improvement over current inconsistent CI performance. He raises concerns about the actionability of performance reports from proprietary repositories like Android's, having experienced difficulties diagnosing issues without reproducible test cases.

The discussion converges on two promising directions: developing standardized test repositories with specific characteristics (massive history, large objects, etc.) that could serve as canonical benchmarks, and establishing alert thresholds that only report significant deviations rather than daily "all clear" messages. Patrick confirms that false alerts from flaky infrastructure are currently a problem that dedicated hardware could help address.

Emily's participation brings concrete use cases from Google's massive-scale deployments and potential infrastructure support, while Patrick maintains focus on making any reporting actionable for the wider Git community. The exchange shows growing momentum for the benchmarking initiative, with both corporate contributors aligning on core needs while working through practical implementation challenges.
