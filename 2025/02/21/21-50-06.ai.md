This is a technical discussion about repository history management, specifically addressing the graft/replacement commit approach for repository splitting that was mentioned earlier in the thread.

Elijah Newren weighs in on Konstantin Ryabitsev's suggestion about using graft commits to split repository history into "epochs". While confirming the technical feasibility of this approach (creating a parentless graft at the desired cutoff point and rewriting history to make it permanent), Newren expresses strong reservations about promoting this method. He notes this is a recurring request in git-filter-repo issues, but cautions that most users don't understand the implications of breaking Git's hash-chain integrity that Brian M. Carlson previously explained.

The email provides concrete technical details about the graft-based approach: creating replacement refs to make desired commits appear parentless, rewriting history to bake in the change, and optionally maintaining a separate graft to the original history. Newren mentions this is documented in git-filter-repo's examples but positioned with warnings about history destruction.

Key technical points:
- Graft mechanics for repository splitting are technically possible using replace refs
- Process involves making target commits appear parentless, then rewriting history
- git-filter-repo has documented this approach but discourages its use
- Maintains strong preference against history rewriting that breaks hash-chain integrity

The response reinforces the thread's emerging consensus that partial clones are preferable, while providing technical clarification about an alternative that should generally be avoided. Newren's position as a git-filter-repo maintainer lends authority to both the technical explanation and the cautionary stance.
