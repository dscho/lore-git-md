This is a code review comment on the oid test conversion series, specifically addressing patch 1/5's implementation of helper functions for OID parsing in the unit test framework.

Phillip Wood provides a focused suggestion to improve error reporting in the `cl_parse_oid()` helper function. The current implementation separates the OID parsing call from its assertion check, which would make test failures less informative. Phillip recommends combining the `get_oid_hex_algop()` call with its assertion check so that test failures will clearly indicate which function call failed. This is part of the ongoing discussion about assertion quality in the test conversions.

The suggestion aligns with the thread's focus on improving test error reporting, specifically addressing one of the open issues noted in the thread summary about assertion verbosity. This is a straightforward implementation improvement that doesn't require broader discussion, as the thread has already established consensus on keeping helper functions in lib-oid.c with the `cl_` prefix naming convention. The change would make test failures more debuggable while maintaining the same functionality.
