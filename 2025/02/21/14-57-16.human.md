Bugfix for `git add -p` hunk splitting behavior. This is the first patch in a two-part series addressing edge cases in interactive patch selection.

Phillip Wood fixes an issue where splitting a previously selected hunk would automatically mark all resulting sub-hunks as selected, bypassing user confirmation. The patch changes this to mark split hunks as "undecided", forcing the interface to prompt the user about each sub-hunk. This matches the expected workflow where splitting implies the user wants finer-grained control.

The change is small (3 lines in `add-patch.c`) but comes with a thorough test case that verifies the new behavior. The test creates a scenario where only some parts of a split hunk should be staged, confirming the interface now properly prompts for each segment.

This appears to be a well-justified improvement to the interactive interface, building on Phillip Wood's deep expertise in this area. The commit message clearly explains both the problematic behavior and the solution. The patch is part of ongoing refinements to hunk handling that stem from practical issues encountered during related feature development.
