Performance optimization for reference backend migrations. This is version 5 of Karthik Nayak's patch to allow skipping reflog migration during reference storage format conversions, now awaiting only the prerequisite implementation of `git reflog drop` before merging.

The patch adds a `--no-reflog` flag to `git refs migrate` that lets administrators discard reflogs during backend transitions, which is particularly useful for server repositories where reflogs are typically unnecessary. The implementation includes thorough test coverage and documentation updates, with all technical details and naming choices (including Junio C Hamano's suggested "convert" terminology) now finalized.

This version includes minor documentation cleanups but avoids rebasing on master where `git-refs.txt` was renamed to `.adoc`, noting this could be handled later if needed. The patch has received multiple rounds of review with all feedback addressed, and represents a performance optimization that will save significant time when migrating repositories with millions of references. The only remaining blocker is the architectural prerequisite of implementing `git reflog drop` first, which Karthik has committed to working on next.
