This is a Windows-specific bugfix for symlink handling in `git mv`, now being queued for integration into the `next` branch. The patch addresses a long-standing issue where Windows' `CreateFileW` API would incorrectly dereference symlinks during rename operations unless explicitly told not to with the `FILE_FLAG_OPEN_REPARSE_POINT` flag. 

The fix is minimal (a one-line change in `compat/mingw.c`) but has significant impact for Windows users working with symlinks created outside Git. Junio Hamano has reviewed the patch and is moving it forward in the integration process, indicating it meets Git's quality standards. 

The change is detectable by existing tests 38 and 39 in `t7001-mv.sh` when run on Windows systems with symlink creation capabilities. While this fix is independent of Johannes Schindelin's ongoing work to fully support symlink creation on Windows, it solves an immediate correctness issue for existing symlink usage scenarios. The patch includes thorough background documentation linking to Windows API references and prior related commits.
