Performance optimization for Git's cat-file object filtering using bitmaps, completing Patrick Steinhardt's series to enhance object type filtering capabilities. This final patch leverages bitmap indexes to dramatically speed up type-based filtering when processing large repositories.

The implementation introduces bitmap-accelerated iteration paths in `builtin/cat-file.c` that handle both single-type filters (`object:type=`) and the special `blob:none` case. When bitmaps are available (either per-pack or via MIDX), the code now uses the new `for_each_bitmapped_object()` infrastructure from earlier patches to iterate only objects of the requested type(s), falling back to full packfile scans for packs without bitmap coverage.

Benchmarks on Chromium's 50GB repository (25M objects) show massive speedups: 4000x faster for tags (20ms vs 82s), 75x for commits, and significant improvements for other types. The optimization is particularly effective for sparse object types where the bitmap can skip scanning most of the packfile. The patch maintains the series' focus on I/O-bound operations, with benchmarks confirming the CPU overhead remains minimal.

Key technical elements:
- New `batch_one_object_bitmapped()` callback adapter
- Dual-path iteration in `batch_each_object()` that dispatches to bitmap or traditional scanning
- `bitmap_index_contains_pack()` checks to handle mixed bitmap/non-bitmap pack scenarios
- Special handling for `blob:none` as a multi-type filter (commits, tags, trees)

This completes the series' performance story, building on the earlier refactoring and bitmap infrastructure work to deliver the promised speedups for large-repository operations. The implementation cleanly integrates with the existing filter framework while maintaining backward compatibility.
