This thread addresses a NULL pointer dereference bug in `git check-mailmap` that causes a segfault when processing email-only inputs (like "bugs@company.xx") without a name component. The issue stems from the code passing NULL for the name parameter to map_user().

The v2 patch takes a minimal approach, changing the NULL to an empty string in builtin/check-mailmap.c while preserving existing mailmap behavior. It includes a test case in t4203-mailmap.sh that verifies email-only input works with mailmap address translations. Maintainer Junio C Hamano reviewed the fix and confirmed it's correct after auditing all map_user() callers, noting they consistently use valid string pointers. While he observed that map_user()'s calling conventions could be better documented, he agreed that improvement is out of scope for this immediate fix.

With the maintainer's approval and no outstanding objections, this straightforward fix is now queued for inclusion. The thread shows consensus on addressing just the NULL pointer issue rather than the broader mailmap resolution modifications attempted in the initial version. This resolves a real bug while maintaining backward compatibility with existing behavior.
