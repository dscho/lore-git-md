This is a user support response regarding repository history management. Brian m. carlson replies to Jamenson Espindula's inquiry about pruning old commits from a repository while preserving newer history.

The response clearly states that Git does not support direct truncation of repository history due to its cryptographic integrity model. Instead, carlson suggests two alternative approaches for reducing local storage usage: shallow clones (which download only recent history) or partial clones (which fetch objects on demand). The reply also provides helpful context about Git's scalability, noting that 23,500 commits is well within Git's comfortable operating range by comparing to much larger repositories like Git itself and the Linux kernel.
