This is a refactoring patch in the remote object-info series, generalizing packet-writing functionality for protocol v2 commands. The patch moves and renames `write_fetch_command_and_capabilities()` from fetch-pack.c to connect.c as the more generic `write_command_and_capabilities()`, making it reusable for other protocol v2 operations beyond fetch (like the new object-info command being added in this series).

Key technical changes:
- The function now takes an explicit `command` parameter instead of hardcoding "fetch"
- Session ID advertisement (`advertise_sid`) handling is simplified since protocol v1 concerns can be ignored
- The implementation remains largely the same, writing command, capabilities (agent, session-id, server-options), and object-format negotiation
- All existing fetch callers are updated to use the new generalized version
- The change enables future protocol v2 commands to reuse this capability-writing logic

The patch maintains all existing functionality while making the code more extensible. It's part of the broader effort to support remote object queries, with this particular change preparing the transport layer infrastructure. The refactoring was reviewed by Jonathan Tan and Christian Couder, with Calvin Wan as the original author (though Eric Ju is submitting this version).

This is a straightforward infrastructure change that doesn't introduce new behavior but enables the subsequent patches in the series to implement the actual remote object-info functionality. The move to connect.c is logical since this is transport-layer functionality that shouldn't be fetch-specific.
