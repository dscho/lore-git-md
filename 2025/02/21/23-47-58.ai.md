Bugfix for a NULL pointer dereference in `git check-mailmap` when processing email-only inputs. This is a follow-up to a recent addition of sendemail mailmap support.

The patch fixes a segmentation fault that occurs when `git check-mailmap` is passed just an email address (like "bugs@company.xx") without a name component. The crash happens because the code passes NULL for the name parameter to map_user() in this case. The fix changes this to pass an empty string instead, which is a valid pointer but still indicates no name is present.

The v2 iteration simplifies the approach from v1 by just fixing the NULL pointer issue rather than attempting broader mailmap resolution changes. The patch includes a new test case that verifies the fix works when checking an email address against a mailmap entry that maps between email addresses (Bug Reports <bugs-new@company.xx> to Bugs <bugs@company.xx>).

Key technical details for future reference:
- Fixes builtin/check-mailmap.c by changing NULL to "" for name parameter
- Adds test case in t/t4203-mailmap.sh for email-only input with mailmap
- Related to recent sendemail mailmap support functionality
- Maintains existing behavior otherwise, just prevents the segfault
