This is part 7/8 of a feature series implementing remote object-info functionality, focusing on the client-side transport layer implementation. The patch adds core client support for querying object sizes from protocol v2 servers without full downloads, completing the end-to-end capability introduced in earlier server-side work.

The key technical additions are:
- New `fetch-object-info.[ch]` files implementing the client protocol interaction
- `fetch_object_info()` function that handles capability negotiation, request formatting, and response parsing
- Transport layer integration via new `object_info` flag in `git_transport_options`
- Protocol v2 enforcement with clear error messages for v0/v1 attempts
- Request buffering approach matching `send_fetch_request()` patterns
- Size feature support with proper memory allocation and error handling
- Transport helper updates to reject object-info on incompatible protocols

The implementation builds on Calvin Wan's server-side work and incorporates feedback from Jonathan Tan and Christian Couder. It follows the established pattern of protocol v2 capability negotiation while adding specific handling for the object-info command. The patch is well-integrated with existing transport mechanisms and includes error handling for various failure modes.

This completes the client-side piece of the remote object-info functionality, working in concert with the server capability advertisement added in earlier patches. The implementation is thorough, with attention to protocol version handling, memory management, and transport layer integration.
