This is a refinement to the Git 3.0 breaking changes thread, specifically the documentation around the deprecation of legacy "branches/" and "remotes/" directories. Jakub Wilk points out that Patrick Steinhardt's claim that these directories are not found in modern repositories is inaccurate, since the "branches/" directory was part of the default template until recently. He suggests more precise wording acknowledging that while these directories are common in existing repositories, they are unlikely to be actively used in modern workflows.

The correction focuses on documentation accuracy rather than the technical implementation of the deprecation warnings or build system changes that have been the main thread topics. This is a minor but important clarification about the actual state of repositories in the wild versus the intended state, which could affect user expectations during migration. The thread's core technical components (warning infrastructure, CI validation, and build flags) remain unchanged by this observation.
