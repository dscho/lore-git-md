Performance optimization for packed-refs backend, part of a series improving refname availability checks. This patch (14/16) implements seek capability for packed-ref iterators, completing the cross-backend iterator optimization work started in earlier patches.

The change modifies the packed-ref iterator to support seeking to specific prefixes, similar to what was done for reftable and ref-cache backends in previous patches. The implementation had to handle a special case where the prefix iterator couldn't be reused for reseeking, so the prefix matching logic was moved into the `advance()` function directly. This maintains consistency with the iterator API changes introduced earlier in the series while accounting for packed-refs' specific requirements.

The patch follows the established pattern from previous iterator optimizations, including proper memory management for the prefix string and careful handling of iterator state. It completes the cross-backend implementation of seek capabilities, which should enable future optimizations where iterators can be reused rather than recreated. The changes are focused and well-contained, building on the infrastructure introduced in earlier patches of this performance optimization series.
