This is a discussion about Git's behavior when `--filter=blob:none` is requested but the server doesn't support filtering. Jeff King (Peff) responds to John Giorshev's proposal to make this a hard error rather than the current silent fallback to full downloads.

Peff considers both sides of the argument: maintaining backward compatibility versus failing fast when the optimization can't be honored. He notes that Git already fails hard when a server explicitly disallows a filter type, suggesting the current warning-only behavior for unsupported filters might be inconsistent. 

The email explores several scenarios, including how Git handles different filter types (like `sparse:oid`) when they're not supported. Peff ultimately leans toward the view that worrying about backward compatibility might not be necessary, given that Git already fails hard in similar cases. 

This moves the discussion forward by providing concrete examples of existing filter behavior and questioning whether the current warning-only approach is actually useful or just an oversight. The thread remains open on whether to implement John's proposal as-is or introduce configurability.
