This is patch 2/3 in a series introducing the new `git-diff-pairs` plumbing command, following up on feedback from Karthik Nayak. The thread has already established consensus on key design points including NUL-delimited input/output, full OID requirements, and explicit rejection of tree objects (rather than silent pass-through).

The patch implements the core `diff-pairs` command which takes raw diff format input (from `git diff-tree -z`) and produces formatted diffs. Key technical details:
- Input parsing handles all diff statuses (added, deleted, modified, renamed, copied) except unmerged files (intentionally excluded)
- Rename detection is frontend-handled as previously agreed
- Includes comprehensive tests verifying raw and patch output formats, non-recursive mode, and split input processing
- Documentation has been reworked to focus on user-facing behavior rather than implementation details

The implementation addresses Karthik's feedback by:
- Renaming `parse_oid()` to `parse_oid_or_die()` for consistency
- Simplifying documentation to avoid discussing internal queuing
- Renaming test setup step to 'setup' for better test harness compatibility

Open questions from the thread that remain to be addressed in future versions:
- Final wording for tree rejection error messages
- Output synchronization test coverage
- Rename pair input format specification
- Documentation rebase verification against current standards
