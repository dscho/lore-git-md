This is the core implementation patch for the new `git-diff-pairs` plumbing command, part of a series that has been through extensive design discussion and refinement. The command enables batch processing of blob diffs by accepting NUL-delimited raw diff format input (like from `git diff-tree -z -r`) and producing patch or raw output. This allows splitting the diff pipeline into stages, which is particularly useful for server-side operations where processing large diffs in one go may time out.

The patch introduces the command with comprehensive documentation and test coverage. Key features include:
- Strict NUL-delimited input/output requirement (-z mode)
- Support for all diff statuses except unmerged files
- Handling of rename/copy pairs from frontend input
- Explicit rejection of tree objects and pathspecs
- Preservation of rename detection when not re-running it

The implementation builds on prior refactoring work (patch 1/3) and appears thorough, with clear behavioral contracts. The documentation explains the motivation (batch processing) and provides usage examples. Test coverage verifies all major scenarios including edge cases. This looks like a well-crafted addition to Git's diff tooling that has benefited from extensive review.
