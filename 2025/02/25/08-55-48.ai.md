This is part of a performance optimization series for the refs subsystem, specifically patch 2/16 in v3. The patch introduces infrastructure for skipping ambiguity checks during object ID lookups, which will be used by later optimizations in the series.

The patch adds a new flag `GET_OID_SKIP_AMBIGUITY_CHECK` to the `get_oid()` family of functions. Currently, these functions always check whether an object ID is ambiguous (when a reference with the same name exists), which adds runtime overhead. The new flag allows callers to opt out of this check when they know it's unnecessary.

The implementation modifies `get_oid_basic()` to respect this new flag, maintaining all existing behavior when the flag isn't set. The change is minimal - just adding a condition before the ambiguity check - but provides the foundation for significant performance improvements in later patches that will use this flag to skip unnecessary checks during ref operations.

This is a well-contained infrastructure change that follows the series' pattern of introducing API foundations before optimization patches. The commit message clearly explains the motivation and ties it to the broader performance goals of the series. The implementation is straightforward and maintains backward compatibility while enabling future optimizations.
