Performance optimization patch implementing seek capability for files backend iterators, completing the cross-backend iterator consistency work in this series.

This patch adds seek functionality to the files backend's ref iterators, following the same pattern established for reftable and packed-refs backends in previous patches. The implementation is straightforward since it delegates to the underlying ref-cache iterator's seek capability (added in patch 13/16). The patch explicitly does not implement seeking for reflog iterators, maintaining consistency with the reftable backend's approach.

Key technical details:
- Adds `files_ref_iterator_seek()` that delegates to the wrapped ref-cache iterator
- Updates the iterator vtable to include the seek operation
- Explicitly BUG()s on attempts to seek reflog iterators
- Follows the same pattern as patches 12-14 for other backends
- Completes the seek capability implementation across all major ref backends

This is the penultimate patch in the series, with all iterator optimizations now implemented across files, reftable, and packed-refs backends. The implementation maintains careful attention to memory safety and interface consistency while avoiding reflog iterator changes, keeping the scope focused on the core ref iteration optimization goals.
