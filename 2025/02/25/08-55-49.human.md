Performance optimization for `git-update-ref` in the refs subsystem series. This is patch 3/16 in v3 of Patrick Steinhardt's series addressing refname availability checks across Git's storage backends.

The patch disables object ID ambiguity checks in `git-update-ref`, similar to what was previously done for `git-cat-file`. The checks (which warn when an object ID could also be interpreted as a refname) are deemed unnecessary for this plumbing command since: (1) the manpage clearly expects object IDs, and (2) as a plumbing command, warnings would rarely be seen interactively. The change provides measurable speedups - 1.19x faster for the files backend and 2.32x for reftable in benchmarks creating 10,000 refs against a 100,000-ref repository.

The implementation uses the new `GET_OID_SKIP_AMBIGUITY_CHECK` flag introduced earlier in the series, replacing `repo_get_oid()` calls with `repo_get_oid_with_flags()`. The change is straightforward but touches several call sites in `builtin/update-ref.c` to ensure consistent behavior. This builds on the series' broader goal of optimizing ref operations while maintaining that the default `repo_get_oid()` behavior remains unchanged when flags=0.
