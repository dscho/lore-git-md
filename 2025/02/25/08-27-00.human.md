This is a minor review comment on a bugfix patch in the packed-refs validation series.

Patrick Steinhardt points out a small formatting issue in the error message from the packed-refs file validation code. The current implementation doesn't quote the filename in the error message when `lstat()` fails, which could make the output less clear if the path contains spaces or special characters. He suggests wrapping the `%s` format specifier in quotes to improve readability.

The comment is specifically about patch 3/8 in the v5 series, which adds filesystem checks for the packed-refs file. This is part of the larger effort to enhance `git fsck`'s validation of packed references, but the review focuses narrowly on this one-line message formatting improvement.

The change is trivial and uncontroversial - it's the kind of minor polish that often comes up in code review rounds. Since this is the fifth iteration of the series and the maintainer has already been involved, this small suggestion will probably be incorporated quickly.
