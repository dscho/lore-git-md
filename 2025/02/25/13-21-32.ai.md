This is a bugfix patch in the final v6 series enhancing `git fsck`'s packed-refs validation. It adds filetype checking for the packed-refs file to ensure it's a regular file rather than a symlink or other special file type.

The patch introduces `lstat()` verification of the packed-refs file in `packed_fsck()`, reusing the existing `FSCK_MSG_BAD_REF_FILETYPE` message for reporting non-regular files. The implementation handles cases where the file doesn't exist (not an error) versus invalid file types (reported as errors). A new test case in t0602-reffiles-fsck.sh verifies the behavior by creating a symlink to simulate an invalid packed-refs file.

Key technical details:
- Adds filetype validation while maintaining the existing packed-refs checks
- Uses `lstat()` to check file mode before processing
- Skips validation if file doesn't exist (ENOENT)
- Reports errors through existing fsck infrastructure
- Includes a SYMLINKS test case to verify the new validation
- Part of the comprehensive packed-refs validation series addressing CVE-2024-32465

The patch appears well-integrated with the series' goals, maintaining the strict validation approach while adding another safety check. The implementation follows the pattern established in earlier patches, with clear error handling and appropriate test coverage.
