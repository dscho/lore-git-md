Performance optimization series for refs subsystem (v3, patch 1/16). This is the first patch in Patrick Steinhardt's v3 series optimizing refname availability checks across Git's ref backends. It introduces a new API function `repo_get_oid_with_flags()` that extends the existing `repo_get_oid()` by accepting flags to pass through to the lower-level `get_oid_with_context()` function.

The patch is a straightforward refactoring that:
1. Splits `repo_get_oid()` into a new `repo_get_oid_with_flags()` that takes flags parameter
2. Makes `repo_get_oid()` a thin wrapper calling the new function with flags=0
3. Updates both the implementation and header file with the new function
4. Adds documentation for the new function matching the style of existing docs

This appears to be infrastructure work needed for subsequent optimizations in the series, particularly around refname ambiguity checks. The commit message is minimal but clear about the purpose - this is plumbing for later changes rather than an optimization itself. The implementation looks clean and maintains the existing behavior while adding the new capability.

Key technical details for future reference:
- New function: `repo_get_oid_with_flags(r, name, oid, flags)`
- Maintains same behavior as `repo_get_oid()` when flags=0
- Passes flags through to `get_oid_with_context()`
- Will be used for skipping ambiguity checks in later patches
- Part of broader ref backend optimization work touching object-name.[ch]
