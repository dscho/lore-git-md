Performance optimization patch in the refs subsystem series (patch 3/16 in v3). This patch specifically targets `git-update-ref` by disabling reference ambiguity checks during object ID parsing, building on the new `GET_OID_SKIP_AMBIGUITY_CHECK` flag introduced in patch 2/16.

The change makes sense for this plumbing command since (1) its manpage is explicitly structured around object IDs rather than refnames, and (2) as a plumbing command, ambiguity warnings would rarely be seen by users anyway. The performance impact is significant: benchmarks show a 1.19x speedup for the files backend and 2.32x for reftable when creating 10,000 refs against a 100,000-ref repository. The larger relative improvement for reftable comes from its faster disk writes.

The implementation replaces all `repo_get_oid()` calls in `builtin/update-ref.c` with `repo_get_oid_with_flags()` using the new skip flag. This follows the precedent set by `git-cat-file`'s similar optimization in 2013. The patch maintains all existing behavior except for suppressing the ambiguity warning, which was deemed unnecessary for this plumbing command.

This is part of the broader refs optimization series that has been through multiple iterations, with Patrick Steinhardt now leading the effort after taking over from Karthik Nayak. The series has shown consistent performance improvements across all ref backends, with this patch specifically addressing a bottleneck in the update-ref plumbing command.
