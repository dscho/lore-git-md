Performance optimization series for refs subsystem (v3 11/16) implementing seek capability for merged iterators.

This patch extends the iterator refactoring work by adding seek functionality to merged iterators, which combine results from two underlying iterators. The key change is splitting the iterator pointers into active and owned variants (iter0/iter1 vs iter0_owned/iter1_owned) to prevent premature deallocation of exhausted iterators that might need to be reused during seeks. The implementation provides a straightforward seek operation that resets both underlying iterators and propagates the seek request to each.

The patch builds on the iterator lifecycle refactoring from patch 10/16, maintaining consistency with the new seek capability while preserving memory safety. Performance impact isn't measured directly here, but this enables future optimizations where iterators can be reused rather than recreated - particularly valuable for the reftable backend where iterator creation is expensive. The changes maintain the series' focus on clean internal interfaces while expanding optimization opportunities.

Technical details include:
- New `iter0_owned`/`iter1_owned` fields to track lifetime separately from active iteration
- `merge_ref_iterator_seek()` implementation that resets state and propagates to children
- Removal of premature iterator freeing in `advance()` to support reuse
- Preservation of all existing iterator semantics and error handling
- Part of the broader ref iterator optimization work enabling reseek capability
- Follows the pattern established in patch 10/16 for iterator vtable extensions
- Maintains memory safety by properly tracking ownership via _owned fields
- Sets stage for reftable-specific optimizations in later patches
