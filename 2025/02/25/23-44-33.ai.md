This is a bug report about inconsistent handling of backspace (`\b`) escape sequences in Git's configuration system. Yaakov Smith reports that while `git fetch` renders the backspace character as a question mark when it appears in a remote URL, `git config --list` outputs the raw escape sequence, which can be misleading or potentially used to mask configuration values.

The key observations are:
1. A remote URL containing `\b` causes `git fetch` to show a question mark in its error message
2. The same escape sequence in a config value (like `"true\b\b\b\bfalse"`) gets rendered literally by `git config --list`, effectively hiding the original value by overwriting it with backspaces
3. The behavior differs between these two commands despite both dealing with configuration values

The report suggests this might be a security or usability issue, as the raw backspace output could be used to obscure actual configuration values. The email includes reproduction steps and system information block showing the behavior occurs on Git 2.34.1 on Linux/WSL2. No patch is proposed - this appears to be an initial report seeking discussion about whether this behavior should be changed.
