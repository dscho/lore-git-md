This is a bugfix patch in the final v6 series enhancing `git fsck`'s packed-refs validation. It specifically adds strict header format checking for packed-refs files, requiring the exact string "# pack-refs with: " (including trailing space) when a header is present.

The patch introduces two new fsck error messages: `badPackedRefHeader` for malformed headers and `packedRefEntryNotTerminated` for lines missing newline terminators. The implementation carefully follows the same validation logic used in runtime operations, including:
- Using `open_nofollow` to safely open packed-refs files
- Adding a line parsing helper function `packed_fsck_ref_next_line`
- Explicit header validation in `packed_fsck_ref_header`
- Comprehensive test coverage for various header scenarios

Key technical details:
- The validation maintains compatibility with older Git versions that didn't write headers
- Unknown header traits are intentionally allowed (matching runtime behavior)
- The implementation handles edge cases like missing newlines and TOCTOU races
- Tests verify correct behavior for valid headers, missing headers, malformed headers, and unknown traits

This completes the series' goal of comprehensive packed-refs validation by adding the final header format checks, with all prior reviewer feedback incorporated. The changes are minimal but important for consistency with Git's own packed-refs generation and most third-party implementations.
