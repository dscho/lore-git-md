This is a performance optimization patch in the refs subsystem, part of a larger series (v3 04/16) addressing refname availability checks. The patch introduces a batched version of refname verification to optimize operations that need to check multiple references.

The key change is the introduction of `refs_verify_refnames_available()`, which performs the same conflict checks as the existing `refs_verify_refname_available()` but operates on a list of references rather than a single one. The implementation currently maintains the same logic (checking for prefix/suffix conflicts against existing refs, extras, and skip lists) but processes all refnames in a single pass. The existing single-ref function is reimplemented as a wrapper around this new batch function.

The technical details show:
- The core verification logic is moved into a loop over the input refnames
- String buffers (`dirname`, `referent`) are reused across checks
- The same error conditions and messages are preserved
- The diff is structured to minimize changes (best viewed with `--ignore-space-change`)

This is a foundational change that enables future optimizations - the commit message notes this will be tuned in subsequent commits. The patch maintains exact behavior equivalence while setting up for performance improvements in later parts of the series. It builds on the thread's established context of optimizing ref operations across all backends (files, packed, reftable).
