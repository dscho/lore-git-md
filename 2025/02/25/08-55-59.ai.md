Performance optimization series for refs subsystem (v3, patch 13/16) implementing seek capability for ref-cache iterators. This patch extends the iterator reseek infrastructure introduced in earlier patches to the ref-cache backend, completing the cross-backend consistency for iterator operations.

The key change splits the seeking logic from `cache_ref_iterator_begin()` into a new `cache_ref_iterator_seek()` function, allowing iterator reuse rather than recreation. This matches the pattern already implemented for reftable iterators in patch 12/16. The implementation requires dropping the empty-ref-iterator optimization since reseeking might need to find references under different prefixes, though the commit notes this shouldn't significantly impact performance due to early bailout in `advance()`.

Technical details include:
- New `cache_ref_iterator_seek()` function handling prefix-based seeking
- Modified iterator state tracking with `prefix` now stored as mutable string
- Added `cache` and `prime_dir` fields to iterator struct for reseek context
- Updated initialization logic in `cache_ref_iterator_begin()`
- Careful handling of prefix states (PREFIX_WITHIN_DIR/PREFIX_CONTAINS_DIR)
- Memory management for prefix strings during reseek operations

The patch maintains consistency with the series' iterator lifecycle improvements while addressing ref-cache specifics. It follows the established pattern from earlier patches but requires different handling of the ref-cache directory structure compared to reftable's flat storage. The implementation appears thorough, with proper cleanup and error handling, though it does slightly complicate the iterator state machine by removing the empty-iterator optimization.
