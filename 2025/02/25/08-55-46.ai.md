Performance optimization for refs subsystem (v3 series). This is the cover letter for the third version of Patrick Steinhardt's series optimizing refname availability checks across Git's ref backends. The work originated from performance issues with reftable tombstone references but has expanded to address broader inefficiencies in ref operations.

The series implements three key optimizations:
1. Skipping redundant ambiguity checks in `git-update-ref` since it's plumbing and object IDs are its primary input
2. Batching refname prefix checks using a `strset` to avoid re-checking common prefixes
3. Reusing ref iterators rather than recreating them for nested ref checks, with new iterator reseeking infrastructure

Performance improvements are significant, especially for reftable:
- Files backend: 1.23-1.27x speedup in realistic cases
- Reftable backend: 4.78-7.56x speedup, now 15x faster than files backend for normal operations
- Packed-refs implementation now properly handles prefix matching in `advance()`

The v3 changes focus on polish:
- Better documentation of iterator reseeking constraints
- Fixed memory leak in ref-cache iterator
- Added error handling for `packed_ref_iterator_seek()`
- One additional case of skipped ambiguity checks in update-ref

The series builds on earlier work by Karthik Nayak and has been benchmarked by brian m. carlson, with shejialuo reviewing the packed-refs implementation details. All backend implementations (reftable, ref-cache, packed-refs, files) now support iterator reseeking, completing the cross-backend optimization effort.
