This is a follow-up to Scott Chacon's patch that widened bundle reference copying from just `refs/heads/` to all `refs/` to improve fetch negotiation. The discussion has revealed deeper design questions about how bundle references should be handled. Stolee notes the original intention was to avoid modifying tag refs directly, suggesting tags should be peeled to commits and fake branches created instead. He also highlights the need for tests demonstrating repo behavior when `refs/bundles/tags/` references exist.

Junio Hamano's earlier concerns about reference overwrites between bundles and backward compatibility remain open questions. Stolee is open to relaxing the refspec matching but questions why bundles couldn't be created with `refs/heads/` references in the first place. The thread shows this simple performance tweak has uncovered non-trivial design questions about reference management in the bundle-uri system that may require more substantial changes to resolve cleanly.
