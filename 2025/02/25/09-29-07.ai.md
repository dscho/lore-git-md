This is a refactoring patch in the ongoing series to enable partial reference updates in Git. It extracts the core logic for preparing individual reference updates from `reftable_be_transaction_prepare()` into a new `prepare_single_update()` function. The new function handles all validation and preparation steps including object ID verification, HEAD reference handling, and symref processing.

The change consolidates reference update validation into a single logical block, improving code maintainability and readability. While there are no functional changes in this commit, the restructuring explicitly prepares for implementing partial transaction support in the reftable backend, which will follow in subsequent patches. The patch moves 226 lines into the new function while adding 11 new lines, resulting in a net reduction of 215 lines in the transaction preparation code.

Key technical details include:
- The new `prepare_single_update()` function takes parameters for the ref store, transaction data, update being processed, and various buffers/state
- It maintains all existing validation checks including OID verification, symref handling, and HEAD updates
- Error handling remains consistent with the files backend for compatibility
- The function returns early for no-op updates to avoid unnecessary work
- The refactoring preserves all existing behavior while making the code more modular

This is part of the larger effort to support partial reference updates across Git's reference backends, with the reftable implementation being prepared in this patch. The changes demonstrate careful attention to maintaining existing behavior while improving the code structure for future enhancements.
