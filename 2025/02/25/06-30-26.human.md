Bugfix for zlib inflation handling in Git's object reading code. This is patch 5/10 in a series addressing zlib-related issues in Git's object handling.

The patch fixes a case where malformed object input could trigger a BUG() when zlib requests a dictionary (Z_NEED_DICT status). Normally Git never uses zlib dictionaries, but corrupt input could cause this case to occur. The issue stems from zlib's behavior of not updating its total_in counter when returning Z_NEED_DICT, which violated Git's internal sanity checks.

Jeff King (with co-author Taylor Blau) proposes modifying the zlib_post_call() helper to skip the problematic check specifically for Z_NEED_DICT cases, while maintaining it for all other statuses. This approach keeps git_inflate() closely matching zlib's behavior while fixing the immediate issue. The change is accompanied by a new test case that verifies Git handles dictionary-tagged input gracefully (by failing with a clear error rather than hitting the BUG()).

The patch is part of a larger effort to harden Git's zlib handling against malformed input, with previous patches in the series having addressed infinite loops and other edge cases. The changes are focused and well-explained, with clear rationale for the chosen solution among several alternatives.
