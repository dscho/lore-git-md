This is a discussion about edge cases in Git's object handling, specifically around the `OBJECT_INFO_ALLOW_UNKNOWN_TYPE` flag. Patrick Steinhardt is responding to Jeff King's patch that adds a `BUG()` when trying to inflate content with unknown object types.

The key points:
- Jeff's patch prevents out-of-bounds reads when handling unknown object types by adding a safety check
- Both developers question the usefulness of the `OBJECT_INFO_ALLOW_UNKNOWN_TYPE` feature, noting it seems incomplete (you can create such objects but not properly read or transfer them)
- Patrick confirms the technical need for keeping the header buffer (`hdrbuf`) while agreeing with restricting content access
- The discussion suggests this might be a candidate for removal if no real-world use cases exist

This is part of a larger series hardening Git's zlib inflation handling against edge cases. The exchange shows two maintainers converging on the view that this particular feature may not be worth maintaining.
