This is the second patch in a 16-part performance optimization series for Git's refs subsystem, introducing a new API capability to skip ambiguity checks during object ID lookups.

The patch adds a new `GET_OID_SKIP_AMBIGUITY_CHECK` flag that can be passed to the `get_oid()` family of functions. Normally these functions check whether a given object ID string could also be a reference name (which could cause ambiguity), but this check adds runtime overhead. The flag allows callers to skip this check when they know it's unnecessary, which will be used in later patches in the series to optimize ref-related operations.

The change is minimal but foundational - it modifies just two files (`hash.h` and `object-name.c`) to add the flag and implement the skipping behavior. This appears to be a well-constructed patch that maintains backward compatibility (the check remains enabled by default) while providing the infrastructure needed for the performance optimizations to come in the rest of the series.
