This is a historical context email in the ongoing refactoring of `show-branch.c` to use commit-slab storage. Jeff King provides additional background on the `commit_slab_with_stride` mechanism, confirming it was designed for exactly this type of per-commit bit storage problem. He references a 2014 attempt to use this approach in `paint_down_to_common()` that never fully materialized, though parts of that work were merged.

King notes that while the full 2014 series wasn't completed due to unresolved edge cases, the bitset API from that work could be directly useful for the current `show-branch` effort. He also acknowledges subsequent work by other contributors in this area, suggesting the historical approach may need evaluation against more recent developments. The email serves to connect the current discussion to prior technical explorations while leaving the implementation details to the current contributors.
