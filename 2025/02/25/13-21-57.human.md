Bugfix in the packed-refs validation series addressing NUL character corruption. This is part of the final v6 series that enhances `git fsck`'s packed-refs validation, now complete with all reviewer feedback addressed.

The patch specifically fixes a case where embedded NUL characters in refnames could bypass validation. Currently, the packed-refs parser calculates refname length by pointer subtraction but doesn't detect if the refnames contain internal NULs. This could allow corrupted refnames to pass validation if the portion before the first NUL happens to be valid.

The solution introduces a new `refname_contains_nul()` helper that scans for embedded NULs in refnames. When found, it triggers an error during packed-refs parsing. This complements the series' broader validation improvements by catching another form of corruption that could previously slip through.

The implementation is straightforward - a simple memchr scan through the refname buffer - and comes with clear documentation explaining the edge case it addresses. This appears to be a well-justified addition to the validation suite, closing a subtle but real security gap in refname handling.
