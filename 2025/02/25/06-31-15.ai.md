Bugfix in zlib inflation handling for loose objects. This patch is part of Jeff King's ongoing series addressing zlib-related edge cases in Git's object handling.

The change fixes an error reporting issue in `unpack_loose_rest()` where the function could silently fail to report corruption when encountering certain zlib status codes. The function checks both for Z_STREAM_END status and complete byte consumption when unpacking loose objects, but its error reporting used a numeric comparison that could incorrectly handle non-error status codes like Z_NEED_DICT (status code 2). The patch replaces the numeric check with an explicit comparison against Z_STREAM_END to ensure proper error messages for all non-success cases.

The issue was discovered during a systematic review of git_inflate() callers following similar fixes in `unpack_loose_header()`. While the commit notes this case is hard to trigger in practice (requiring a loose object that requests a zlib dictionary mid-stream), the change improves consistency in error handling. The patch maintains the series' focus on robust zlib status code handling while being minimally invasive - just a one-line change to the condition check.

This complements other patches in the series that address zlib edge cases, though unlike some other changes in the series, this one doesn't add new test coverage since constructing a test case would require specially crafted objects that trigger Z_NEED_DICT during content inflation rather than header parsing. The change demonstrates careful attention to error reporting paths that might not be immediately visible in normal operation but could affect diagnostics in edge cases.
