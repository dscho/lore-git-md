This is a bugfix patch in the final v6 series enhancing `git fsck`'s packed-refs validation. It specifically addresses a corner case where embedded NUL characters in refnames could bypass validation checks.

The patch introduces a new helper function `refname_contains_nul()` that detects embedded NUL bytes in refnames, which the existing `check_refname_format()` would miss if the portion before the first NUL was valid. When found, this triggers a fatal error with a descriptive message. The change plugs a security hole where malformed refnames could potentially be processed incorrectly.

The implementation is straightforward - it uses `memchr()` to scan the refname buffer for NUL bytes. The commit message clearly explains the vulnerability (reported by R. Diez) and how the new check complements the existing validation. The patch integrates this check into the packed-refs iterator's `next_record()` function where refnames are processed.

This appears to be a well-justified and cleanly implemented security hardening measure. The patch follows the series' pattern of adding specific validation checks while maintaining the existing error handling flow. The commit message provides good context about the vulnerability and rationale for the solution.
