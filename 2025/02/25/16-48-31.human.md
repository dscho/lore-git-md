This is a follow-up discussion about the signed commits feature in git fast-export/import, specifically addressing future directions beyond the current implementation.

Elijah Newren clarifies a point about the scope of Christian Couder's v5 patch series, noting that while it handles existing signatures (via abort/verbatim/strip modes), it doesn't yet implement the separate feature Junio Hamano suggested for adding new attestation signatures during import. Patrick Steinhardt confirms their interest in this future capability for git-filter-repo use cases, explaining they revived this effort specifically to address customer needs around signed commits.

The exchange serves as both a reality check about the current series' limitations and continued validation of the roadmap. While the v5 patches are production-ready for handling existing signatures, this thread confirms there's still demand for the next logical extension - the ability to re-sign commits during filtering operations. The discussion remains constructive, with clear alignment between the Git maintainers and git-filter-repo developers about the long-term vision.
