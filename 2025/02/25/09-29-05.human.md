This is part 2/7 of a refactoring series to enable partial reference updates in Git. The patch moves duplicate refname checking from individual backends (files, packed, reftable) into the generic refs.c layer, centralizing what was previously duplicated logic.

The key changes are:
1. Adds a `refnames` string_list to the ref_transaction struct to track all references in a transaction
2. Updates this list automatically in ref_transaction_add_update()
3. Modifies all three backends to use this centralized list instead of their own implementations
4. Adjusts the reftable backend to check for duplicates before rather than after adding updates

The change reduces code duplication and makes future modifications easier by handling this logic in one place. It's a clean refactoring that maintains all existing behavior while simplifying the backend implementations. The patch fits well with the series' goal of standardizing reference transaction handling across backends.
