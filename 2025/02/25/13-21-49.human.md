This is a bugfix patch in the final v6 iteration of a series enhancing `git fsck`'s packed-refs validation. The patch specifically focuses on header format verification in packed-refs files.

The patch adds strict validation for the "# pack-refs with: " header line in packed-refs files, ensuring it matches the exact expected format (including the trailing space). It introduces two new error messages: one for malformed headers and another for unterminated lines. The implementation carefully handles edge cases - it doesn't complain about missing headers (for backward compatibility) or unknown traits in valid headers.

The changes include:
1. New functions to parse and validate packed-refs content line-by-line
2. TOCTOU-safe file handling using `open_nofollow`
3. Comprehensive test cases covering valid/invalid headers and edge cases
4. Documentation updates for the new fsck error messages
