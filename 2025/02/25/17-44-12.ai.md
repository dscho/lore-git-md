This is a review comment from Junio Hamano on patch that adds filetype checking for packed-refs files in the packed-backend.

The patch (v6 3/9 in the series) introduces validation that packed-refs files must be regular files, not symlinks or directories. Junio suggests optimizing the check sequence - rather than doing an upfront lstat(), he proposes first trying to open_nofollow() (which handles symlinks safely), then only falling back to lstat() if the open fails. This would be more efficient for the common case where the file exists and is a regular file.

The key technical points are:
- Current patch uses lstat() to check file mode upfront
- Junio suggests moving the check after open_nofollow() attempt
- Proposed flow: try open, if that fails use lstat to diagnose why
- Maintains same security properties (still checks for symlinks via open_nofollow)
- More efficient for normal case where file exists and is regular

This is a refinement to the implementation approach rather than a fundamental issue with the patch's purpose. The change would maintain all the validation goals while optimizing performance. The thread context shows this is part of a comprehensive packed-refs validation series that's nearing completion.
