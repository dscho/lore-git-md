Performance optimization for the files backend, part of a larger series improving refname availability checks. This patch (7/16) focuses on batching refname checks during initial transactions in the files backend, which is particularly relevant for operations like cloning or format migration.

The change refactors the initial transaction logic to collect all refnames first and verify them in a batch, rather than checking each one individually. While the immediate performance impact is minimal (the underlying verification still happens in a loop), this sets up future optimizations that will show benefits when cloning repositories with many references or converting between ref storage formats.

The patch maintains all existing behavior and error handling, including proper cleanup paths and packed-refs transaction management. It builds on the batched verification API introduced earlier in the series (patch 4/16) and follows similar optimizations already made for the reftable backend (patch 5/16).
