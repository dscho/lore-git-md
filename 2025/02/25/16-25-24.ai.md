This is a documentation refinement for the signed commits feature in git fast-export/import. The email captures a brief discussion between Elijah Newren and Junio Hamano about improving the documentation clarity for the `--signed-commits` option.

The key point is that while the documentation patch (from Christian Couder's v5 series) describes the behavior modes for signed commit handling (verbatim, warn-verbatim, warn-strip, strip, abort), it doesn't explicitly state that 'abort' is the default behavior. Both participants agree this should be made explicit in the docs, even though experienced developers might assume this default, as it matches the sensible design choice and parallels the behavior of `--signed-tags`.

This is a minor polish to the otherwise complete v5 series implementing signed commit support, which has already addressed all technical issues including memory safety and test coverage. The discussion shows the maintainers' attention to documentation quality and user experience, ensuring the behavior is clear even to those less familiar with Git's design patterns. No code changes are needed - just a small doc clarification to make the default behavior obvious.
