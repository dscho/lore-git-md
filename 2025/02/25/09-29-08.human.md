This is part 5 of a 7-patch series refactoring Git's reference transaction system to support partial updates, introducing a new `--allow-partial` flag for `git update-ref`. The patch converts preprocessor-defined transaction error codes into a strongly-typed `transaction_error` enum, improving type safety and making error handling more explicit. It defines seven distinct error conditions (like name conflicts, nonexistent refs, incorrect old values) that can occur during reference transactions.

The change touches all major ref backends (files, packed, reftable) to adopt the new enum-based error reporting. While this is primarily a refactoring, it lays important groundwork for the partial transaction support coming in later patches by making error conditions more precisely identifiable. The implementation looks thorough, with consistent error handling across all backends and clear commit message explaining the motivation. This appears to be a well-executed step in the larger series.
