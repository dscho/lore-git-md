Final patch in the partial reference updates series, adding user-facing `--allow-partial` flag to `git update-ref`. This feature enables partial success when updating multiple references via stdin, where previously any single error would abort the entire transaction. The patch:

1. Introduces the `--allow-partial` flag (restricted to stdin mode) that allows individual reference updates to fail while others proceed
2. Implements error reporting for failed updates in both human-readable and `-z` machine-readable formats
3. Maps backend error types (from the new enum system) to user-friendly rejection reasons
4. Adds extensive test coverage for various failure scenarios (invalid OIDs, missing refs, symref conflicts, etc.)
5. Documents the new behavior and output format in `git-update-ref.adoc`

The implementation builds on all prior infrastructure from the series:
- Uses the REF_TRANSACTION_ALLOW_PARTIAL flag added in earlier patches
- Leverages the new error classification system
- Integrates with the rejection tracking infrastructure (patch 6)
- Maintains backend-specific atomicity characteristics (files vs reftable)

Key technical details:
- System errors (I/O failures) still abort entire transaction
- User errors (invalid refs, bad OIDs) are skippable
- F/D conflicts handled differently by backend (files: per-ref, reftable: batched)
- Output format matches existing update-ref conventions
- Test cases verify both successful partial updates and proper error reporting

This completes the series' goal of enabling controlled partial reference updates while maintaining safety and providing clear feedback about failures. The implementation appears thorough, with careful attention to edge cases and integration with the ref transaction system's new capabilities.
