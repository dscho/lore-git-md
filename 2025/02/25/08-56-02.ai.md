Performance optimization patch completing the refs iterator reseek capability series. This is the final patch (16/16) in Patrick Steinhardt's v3 series optimizing refname availability checks across Git's ref backends. The patch modifies `refs_verify_refnames_available()` in refs.c to reuse existing iterators via the new `ref_iterator_seek()` API rather than recreating them for each check. This builds on the iterator reseek infrastructure added in earlier patches (10-15/16).

Key technical changes:
- Modifies the refname availability check to conditionally create or reseek iterators
- Maintains the iterator across checks when possible rather than freeing/recreating
- Handles seek failures by jumping to cleanup
- Preserves all existing error handling and skip-list functionality

Performance impact:
- Reftable backend shows 1.25x speedup (39.8ms → 31.9ms) in synthetic benchmark creating 10k refs
- Files backend sees minimal improvement (1.01x) due to its inherent filesystem overhead
- Completes the cross-backend iterator optimization pattern established in patches 12-15

The patch follows the established approach from earlier iterator optimizations while focusing specifically on the refname availability verification path. It represents the culmination of the series' iterator lifecycle improvements, demonstrating measurable gains in the reftable backend where iterator reuse provides the most benefit. The files backend sees less impact as expected given its different performance characteristics.
