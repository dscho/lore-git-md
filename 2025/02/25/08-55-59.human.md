Performance optimization for ref-cache iterators in the refs subsystem. This is patch 13/16 in Patrick Steinhardt's series improving refname availability checks across Git's ref backends.

The patch implements seek capability for ref-cache iterators, completing the iterator optimization work started in earlier patches. It splits the seeking logic out from `cache_ref_iterator_begin()` into a new `cache_ref_iterator_seek()` function for reuse. A small tradeoff is made where empty ref iterators are no longer returned when no references exist, as this would prevent reseeking to different prefixes, though the impact is minimal due to early bailout in the `advance()` path.

This continues the series' pattern of adding seek support to all iterator types (following patches 10-12 which did this for reftable and merged iterators), maintaining consistent behavior while enabling future optimizations through iterator reuse. The implementation carefully handles prefix management and directory priming while preserving memory safety and interface contracts established in previous patches.
