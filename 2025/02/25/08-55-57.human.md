Performance optimization series for refs subsystem (v3, patch 11/16) implementing seek capability for merged iterators. This patch builds on the iterator refactoring from patch 10/16, now adding the ability to seek (reset position) in merged iterators that combine results from multiple underlying iterators.

The key change is separating iterator ownership from active iteration state - the merged iterator now keeps track of both the active iterators (`iter0`, `iter1`) and the owned iterators (`iter0_owned`, `iter1_owned`) that need cleanup. This allows seeking by resetting the active iterators to their initial owned state and re-seeking both. The implementation carefully maintains the existing error handling and cleanup paths while adding the new capability.

This is part of a larger performance optimization series that has already shown significant speedups (4.78-7.56x for reftable backend). The iterator reseek capability introduced here enables future optimizations where iterators can be reused rather than recreated, particularly important for the reftable backend. The patch appears well-contained and follows the established pattern from earlier iterator refactoring work in the series.
