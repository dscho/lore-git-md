Refactoring patch in a zlib inflation cleanup series. This is part of Jeff King's 11-patch series addressing zlib-related object handling issues in Git.

The patch simplifies ownership semantics around zlib stream cleanup in `unpack_loose_rest()` and related functions. Previously, these functions would sometimes clean up the zstream and sometimes not, leading to confusion and a past memory leak. The change makes cleanup consistently the caller's responsibility, which actually simplifies calling code by allowing cleanup in common paths.

Key changes:
- `unpack_loose_rest()` and `check_stream_oid()` no longer call `git_inflate_end()`
- `read_loose_object()` gains a new cleanup label for inflate-specific teardown
- The change fixes a potential leak in `check_stream_oid()` error paths

This is a pure refactoring with no intended behavior change, though it does fix a subtle resource management issue. The patch follows logically from earlier work in the series to make zlib error handling more robust. While the author notes this could be seen as churn, the simplification of ownership semantics appears worthwhile.
