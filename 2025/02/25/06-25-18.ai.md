This is a cover letter for a series of bugfix and refactoring patches addressing zlib inflation issues in Git's object handling. The series contains 10 patches, with the core fixes in patches 4 and 5, surrounded by related cleanups and improvements.

The main issues addressed are: (1) an infinite loop that could occur when inflating broken zlib input in `unpack_loose_header()`, though this requires local repo writes and uncommon commands; and (2) a case where specially crafted packs could trigger a BUG() during push operations. The rest of the series includes preparatory cleanups and follow-up refactoring to make the code more robust and readable, particularly around zlib status handling and error cases.

Key technical points for future reference: The series touches `git-zlib.c` and `object-file.c`, modifying how zlib inflation handles error cases and status codes. It introduces more robust handling of Z_NEED_DICT cases and removes numeric comparisons of zlib status codes in favor of symbolic constants. The test additions in `t1006-cat-file.sh` verify the fixed behaviors. Notable changes include preventing infinite loops on bad input, removing unsafe cleanup of zstream in error paths, and clarifying return value handling in `unpack_loose_rest()`.
