This is the 6th patch in a 7-part series implementing partial reference transaction support across Git's ref backends. It introduces the core infrastructure for allowing individual reference updates to fail while others proceed, controlled by the new `REF_TRANSACTION_ALLOW_PARTIAL` flag.

The patch adds several key components:
- A `rejection_err` field in `struct ref_update` to track failed updates
- A `ref_transaction_set_rejected()` function to mark updates as failed
- A `ref_transaction_for_each_rejected_update()` iterator for examining failures
- Backend-specific handling in files, packed, and reftable backends to support partial transactions

The implementation distinguishes between user-facing errors (which can be skipped) and system errors (which still abort the whole transaction). Each backend is modified to use the new rejection mechanism when the partial flag is set, while maintaining their existing atomicity characteristics (files backend being less atomic than reftable).

This builds on the error typing system introduced earlier in the series, using the `enum transaction_error` values to classify failures. The changes are comprehensive across all major ref backends (~350 lines modified) while maintaining backward compatibility. The next patch will expose this to users via a `--allow-partial` flag for `git update-ref`.

The implementation appears thorough, with clear attention to maintaining safety while adding flexibility. It follows the design consensus established in earlier discussion, particularly around error classification and the distinction between skippable and fatal errors. The changes are well-contained within the refs subsystem, with no unexpected side effects visible in the diff.
