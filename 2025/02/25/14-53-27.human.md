Bugfix for memory leak in signed commit export feature.

Phillip Wood points out a memory leak in Christian Couder's v5 series adding signed commit support to `git fast-export`. The issue stems from a change that converted a static buffer to dynamically allocated memory in `find_commit_multiline_header()` but didn't update callers to free the returned string. The leak occurs when handling signed commits in `handle_commit()`.

The patch series, which revives Luke Shumaker's 2021 work, had otherwise received thorough review and was considered production-ready. This appears to be a last-minute oversight in the final version. The fix would involve either:
1. Adding `free((char *)signature)` calls where needed (as Phillip shows in one location)
2. Reverting to the static buffer approach if the allocation pattern doesn't fit well

Given the series' maturity and the straightforward nature of the fix, this shouldn't delay merging but does need addressing. The thread context shows this is part of a larger effort to properly handle signed commits during export/import operations, with future work planned for attestation signatures.
