Junio Hamano's response to the bundle-uri reference negotiation optimization patch. This is a discussion about potential edge cases in the proposed performance improvement.

The email acknowledges Scott Chacon's findings that copying all references (not just heads) significantly reduces redundant downloads (from 32% to 1% in the GitLab OSS case). However, Hamano raises several technical concerns about the implementation:

1. The ref mapping changes from `refs/heads/foo`→`refs/bundles/foo` to `refs/heads/foo`→`refs/bundles/heads/foo`, which might affect existing users who rely on the old structure.

2. A more serious issue emerges with multiple bundles - later bundles could overwrite references from earlier ones, potentially leaving objects from earlier bundles unanchored and subject to garbage collection. Hamano illustrates this with an example where a final bundle could wipe out all previously imported references.

3. The variable name `branch_name` becomes misleading since it now holds the full reference path after "refs/".

Hamano CC's Derrick Stolee (the original bundle-uri designer) for input, noting this touches code from commit 53a50892 (2022). While the performance benefits are clear, these edge cases suggest the simple one-line change might need more comprehensive handling of reference naming and bundle interaction. The discussion appears to be shifting from the performance optimization itself to broader design questions about how bundle references should be managed.
