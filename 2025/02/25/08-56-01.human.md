Performance optimization patch completing the refs iterator seek capability implementation for the files backend.

This is patch 15/16 in Patrick Steinhardt's series optimizing refname availability checks across Git's ref storage backends. The patch adds seek capability to the files backend's ref iterator, following the same pattern already implemented for reftable and packed-refs backends in previous patches. 

The implementation is straightforward since the files backend uses a ref-cache iterator internally - it simply delegates the seek operation to that underlying iterator. The patch also explicitly disables seeking for reflog iterators (with a BUG() if attempted), maintaining consistency with the reftable backend's approach.

This completes the cross-backend consistency for iterator operations in the series, with all three major backends (files, reftable, packed-refs) now supporting seek operations. The seek capability enables future performance improvements where iterators can be reused rather than recreated. 

The changes are cleanly implemented following the established pattern from earlier patches in the series, with proper vtable setup and clear error handling. The patch appears well-tested as part of the larger series which has already demonstrated significant performance gains (1.23-1.27x speedup for files backend operations).
