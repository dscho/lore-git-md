This is a refactoring patch in Patrick Steinhardt's performance optimization series for the refs subsystem (patch 9/16). It decouples iterator lifecycle management from iteration itself, addressing two key issues with the current implementation.

The patch changes how ref iterators are managed by introducing explicit `ref_iterator_free()` and `dir_iterator_free()` functions rather than having iterators auto-free when exhausted. This makes the API more consistent with Git's general patterns and enables potential future optimizations like iterator reuse. The changes touch all iterator implementations across files, packed, and reftable backends.

The implementation is thorough, updating all iterator types and their callers to use the new lifecycle model. It also drops the return value from abort operations since it wasn't meaningfully used. The changes appear well-contained within the iterator abstraction layer, maintaining existing behavior while making the API more robust.

This is a foundational change that enables future optimizations in the series, particularly around repeated reference searches. While not directly performance-impacting itself, it's a necessary step for the batched verification optimizations that follow. The patch maintains careful attention to memory safety and transaction semantics throughout the refactoring.
