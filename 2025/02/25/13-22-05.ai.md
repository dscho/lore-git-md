This is part 7/9 of a bugfix series enhancing `git fsck`'s packed-refs validation. The patch implements detailed consistency checking for individual ref entries in packed-refs files, building on the earlier header validation work.

The patch adds two new validation functions:
1. `packed_fsck_ref_main_line()` checks main ref lines (oid + refname), verifying:
   - Valid OID format
   - Proper spacing between OID and refname
   - Refname format validity (including NUL detection via existing helper)
2. `packed_fsck_ref_peeled_line()` validates peeled ref lines (^ + OID), checking:
   - Valid peeled OID format
   - Absence of trailing garbage after OID

A new `badPackedRefEntry` error type is introduced in `fsck-msgids.adoc` and `fsck.h` to report these issues. The test suite (`t0602-reffiles-fsck.sh`) is expanded with a comprehensive test case that exercises various malformed ref entries, verifying the new validation catches:
- Invalid OIDs
- Missing spaces after OID
- Malformed refnames
- Invalid peeled OIDs
- Trailing garbage in peeled lines

The implementation integrates with the existing `packed_fsck_ref_content()` flow and maintains all prior validation checks. This completes the core ref entry validation portion of the series, working in concert with the earlier header validation and NUL detection patches. The code follows established patterns from the series, using similar error reporting structures and test isolation techniques seen in previous iterations.
