This is the final patch (8/9) in a bugfix series enhancing `git fsck`'s packed-refs validation. It adds sorting verification when the packed-refs file declares itself as sorted in its header.

The patch introduces a new fsck error `packedRefUnsorted` that triggers when refs are out of order in a file marked with the "sorted" trait. Key technical details:

- Extracts refname comparison logic from `cmp_packed_ref_records()` into a new `cmp_packed_refname()` helper for reuse
- Modifies `packed_fsck_ref_header()` to detect the "sorted" trait
- Adds new `packed_fsck_ref_sorted()` that performs a second pass over the file to verify ordering when needed
- Includes comprehensive tests in t0602-reffiles-fsck.sh covering:
  - Valid sorted files
  - Out-of-order refs (both simple and with peeled tags)
  - Files without the sorted trait (which skip verification)
  - Error message formatting

The implementation avoids storing all refnames by doing a second pass and comparing adjacent entries, keeping memory usage constant. This completes the series' goal of comprehensive packed-refs validation by adding the last major check - proper sorting when claimed.
