Bugfix addressing an infinite loop in zlib inflation when processing malformed loose objects. This is patch 4/10 in a series dealing with zlib-related object handling issues.

The patch fixes a specific infinite loop scenario in `unpack_loose_header()` that occurs when processing truncated loose files with unknown object types. The loop previously continued indefinitely on Z_BUF_ERROR (when zlib runs out of input), but now properly terminates when not seeing Z_OK progress. The change is minimal (one line in `object-file.c`) but critical for handling corrupt objects safely.

A new test case demonstrates the fix by:
1. Creating an object with an artificially long type name
2. Truncating its on-disk representation
3. Verifying `git cat-file --allow-unknown-type` fails cleanly rather than hanging

The security implications are limited since the bug requires both:
- Access to a maliciously crafted loose object (unlikely in normal fetches/pushes)
- Use of the rarely-used `--allow-unknown-type` option

The patch builds on earlier refactoring in the series (particularly patch 2/10's zstream buffer management changes) and maintains the thread's focus on robust zlib error handling. It touches the same core files (`object-file.c`, `t1006-cat-file.sh`) as other patches in the series while addressing a distinct edge case.
