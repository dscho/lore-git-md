Feature and bugfix integration completing the `git fsck` packed-refs validation series. This final patch in the v6 series adds a `--[no-]references` option to `git fsck` that controls whether to perform the new refs database consistency checks via a child `git refs verify` process. The implementation includes progress reporting (currently showing 1/1 task since loose ref counting isn't implemented yet) and runs early in fsck's execution to avoid interference with existing implicit ref checks.

The patch adds documentation for the new option and test cases verifying the option's behavior with various trailing garbage scenarios in refs. The child process inherits fsck's verbosity and strictness settings. This completes the integration of the comprehensive packed-refs validation (header format, NUL detection, entry validation, and now sorting verification when declared) into Git's standard fsck workflow while maintaining backward compatibility through the opt-out flag.

Key technical details include the new `fsck_refs()` function in builtin/fsck.c that spawns the child process, the `check_references` flag controlling the feature, and test coverage in t0602-reffiles-fsck.sh that exercises both the positive and negative cases of the new option. The implementation preserves all security hardening from earlier in the series while making the checks available through Git's main consistency verification tool.
