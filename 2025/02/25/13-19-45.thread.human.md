This thread discusses a performance optimization for Git's bundle-uri functionality, which currently has suboptimal reference negotiation behavior after downloading bundles. The root issue is that only refs under `refs/heads/` are copied to `refs/bundles/`, causing Git to miss many objects already present in bundles during subsequent fetches.

The proposed solution widens the reference matching pattern from `refs/heads/` to just `refs/`, allowing all references in the bundle to be copied. Benchmark results from the GitLab OSS repository show dramatic improvements - downloaded objects drop from 32% of total to just 1%, with corresponding clone time reductions. The change is implemented as a minimal one-line modification in bundle-uri.c.

While clearly beneficial for the author's use case, the patch notes raise the question of whether there might be unintended consequences from this broader reference copying. The submission appears intended to start discussion about the current behavior's limitations rather than for immediate merging. The thorough benchmarking data provides strong evidence for the performance impact, particularly in repositories where important references live outside `refs/heads/`.
