This thread discusses a performance optimization for bundle-uri reference negotiation during fetches. Scott Chacon proposed changing the refspec pattern from copying just `refs/heads/` references to copying all `refs/` references to `refs/bundles/`, demonstrating dramatic improvements - reducing redundant object downloads from 32% to 1% in the GitLab OSS repository case.

Junio Hamano has responded with important technical concerns about the change. While acknowledging the performance benefits, he points out that the new reference mapping structure (`refs/heads/foo`→`refs/bundles/heads/foo`) could break existing users. More critically, he identifies a potential issue where multiple bundles could overwrite each other's references, possibly causing objects to become unanchored and subject to garbage collection. Hamano has CC'd Derrick Stolee, the original bundle-uri designer, for input on these design questions.

The discussion started as a straightforward performance optimization but has now shifted to broader questions about reference management in the bundle-uri system. The performance gains are clear, but the implementation may need more comprehensive changes to handle these edge cases safely.
