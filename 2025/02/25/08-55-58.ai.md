Performance optimization series for refs subsystem (v3 12/16) implementing seek capability for reftable iterators. This patch builds on the iterator refactoring from previous entries in the series, specifically extending the seek functionality introduced in patches 10-11 to the reftable backend.

The implementation adds a `seek` method to the reftable ref iterator vtable, allowing efficient repositioning of iterators without recreation. Key technical changes include:
- Adding `reftable_ref_iterator_seek()` that duplicates and stores the prefix string
- Modifying `ref_iterator_for_stack()` to use the new seek method during initialization
- Properly handling memory management for the prefix string
- Explicitly marking reflog iterators as non-seekable with a BUG() trap
- Adding error checking for `reftable_stack_init_ref_iterator()`

The patch notes two intentional limitations: reflog iterators are explicitly not made seekable (as their use case for seeking is unclear), and the implementation builds on the low-level reftable iterator seek support that already exists. This completes the reftable-specific portion of the iterator optimization work, with the changes maintaining consistency with the files backend implementation from earlier in the series.

The changes are relatively straightforward given the preparatory work in previous patches, with the main complexity being proper memory management of the prefix string. This enables future optimizations where reftable iterators can be reused rather than recreated, particularly important for the performance-sensitive reftable backend.
