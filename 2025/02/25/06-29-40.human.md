This is a bugfix patch in a series addressing zlib inflation issues in Git's object handling. It corrects the error reporting when reading malformed loose object headers that lack a terminating NUL byte.

Currently, when reading a header with `--allow-unknown-type`, Git keeps reading until it finds a NUL or hits the end of the zlib stream. The stream ending first currently returns ULHR_TOO_LONG, which is misleading since there's no length limit in this mode. The patch changes this to return ULHR_BAD, more accurately indicating malformed input. While both codes make Git reject the object, this provides a more precise error message.

The change is minimal (one line in object-file.c) and part of a larger effort to harden Git's zlib handling. The author notes this case is hard to test directly, but the next patch in the series will introduce testable cases. This appears to be a straightforward correctness fix in preparation for more substantial changes to come in the series.
