This is the final patch in a bugfix series that completes `git fsck`'s validation of packed-refs files, now including verification of sorting when the "sorted" trait is declared. The series has gone through multiple rounds of review and addresses security concerns around packed-refs validation.

The patch integrates the new ref validation checks into `git fsck` by adding a `--references` option (enabled by default) that runs `git refs verify` as a child process. This provides users with a way to check ref database consistency through the familiar `fsck` interface while keeping the implementation cleanly separated. The patch includes:

1. A new `fsck_refs()` function that spawns `git refs verify` with appropriate options
2. A `--[no-]references` flag to control this check
3. Basic progress reporting (though the total work is hard to estimate)
4. Test cases verifying the new option works as expected

The implementation is straightforward and builds on the thorough validation work done in earlier patches. The author has incorporated feedback from multiple reviewers (Patrick Steinhardt and Karthik Nayak are credited as mentors) and the patch appears production-ready. This completes the series' goal of comprehensive packed-refs validation in `git fsck`, addressing security concerns while maintaining compatibility.
