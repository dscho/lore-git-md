Bugfix addressing an infinite loop in zlib object header parsing. This is patch 4/10 in a series dealing with zlib inflation issues in Git's object handling.

Jeff King and Taylor Blau fix a case where `unpack_loose_header()` could enter an infinite loop when processing truncated loose objects with unknown types. The issue occurs when zlib returns Z_BUF_ERROR (indicating no progress can be made) but the code keeps retrying indefinitely. The fix changes the loop condition to only continue on Z_OK status, properly bailing out when no forward progress is possible.

The patch includes a test that creates a truncated object with a long type name and verifies Git correctly fails rather than hanging. The security implications appear limited since the bug requires both specially crafted objects and use of the rarely-used `--allow-unknown-type` flag. The change is minimal (one line in `object-file.c`) but important for robustness against malformed input.

This builds on earlier refactoring in the series (patch 2/10) that simplified zstream buffer management, making this fix more straightforward. The test demonstrates the fix works for the specific failure case while the commit message explains why other zlib status codes don't need special handling here.
