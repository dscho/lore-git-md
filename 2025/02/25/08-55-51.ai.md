Performance optimization patch in the refs subsystem series, specifically targeting the reftable backend's refname availability checks. This is patch 5/16 in v3 of Patrick Steinhardt's optimization series, building on the batched verification infrastructure introduced in patch 4/16.

The patch modifies the reftable backend to collect refnames needing availability checks into a string list (`refnames_to_check`) during transaction preparation, then verifies them all at once using the new `refs_verify_refnames_available()` function. This replaces the previous per-ref `refs_verify_refname_available()` calls. The change doesn't yet improve performance (as noted in the commit message) but sets up the structure for future optimizations in subsequent patches.

Key technical changes include:
- Introduces a new `refnames_to_check` string list to accumulate refnames
- Removes individual `refs_verify_refname_available()` calls in favor of batched verification
- Maintains the same error handling and transaction flags behavior
- Adds proper cleanup of the new string list in the error path
- The patch touches only `refs/reftable-backend.c`, modifying the transaction preparation logic
- Preserves all existing functionality while changing the verification mechanism
- Follows the series' pattern of preparing infrastructure first, then optimizing

This is a transitional patch that enables the performance improvements promised in the series overview, particularly the 4.78-7.56x speedup for reftable operations mentioned in the thread context. The actual performance gains will come in later patches that build on this batched verification approach.
