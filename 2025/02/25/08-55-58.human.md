Performance optimization series for refs subsystem (part 12/16) implementing seek capability for reftable iterators. This patch builds on the iterator refactoring work from previous patches to add seek functionality specifically for the reftable backend's reference iterators.

The implementation is straightforward since the low-level reftable iterators already support seeking. The patch makes two notable design choices: (1) it explicitly does not implement seeking for reflog iterators since there's no clear use case yet, and (2) it adds proper error checking for `reftable_stack_init_ref_iterator()` which was previously missing.

The changes involve adding a seek vtable function that handles prefix string duplication and cleanup, modifying the iterator initialization to use the new seek function, and properly freeing the prefix string in the release function. For reflog iterators, the patch adds a seek function that explicitly BUGs out since seeking isn't supported there.

This is part of a larger performance optimization series that has already shown significant speedups (4.78-7.56x for reftable backend). The patch appears well-crafted with clear commit message explanations and maintains consistency with the series' focus on iterator lifecycle improvements. It sets up infrastructure that will enable further optimizations in later patches.
