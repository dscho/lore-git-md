This documentation patch has now been finalized after three revisions as part of a GSoC project, with approval from both the maintainer and the merge strategy expert. The patch clarifies how Git handles submodule merges in two specific cases: when one submodule commit is a descendant of another (Git will attempt a fast-forward), and when merge commits exist that contain both conflicting submodule commits (Git will suggest these as resolution options but leave the submodule unmerged). These behaviors are consistent between both the modern 'ort' and legacy 'recursive' merge strategies, though the implementations differ.

Junio Hamano has given his approval with only one minor formatting question remaining - whether to add a blank line before a continuation marker in the recursive strategy section. The patch incorporates prior feedback from both Hamano and Elijah Newren, who is the foremost expert on Git's merge machinery. The documentation now accurately reflects behavior that has been in the code since commit 68d03e4a6e, providing users with clear expectations about how submodule conflicts will be handled during merges. This completes the GSoC effort to document this subtle but important aspect of Git's merge behavior.
