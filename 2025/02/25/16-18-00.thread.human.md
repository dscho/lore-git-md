This documentation patch clarifies how Git handles submodule merges during conflicts, particularly for the 'ort` and 'recursive' merge strategies. The patch, now in its third revision as part of a GSoC project, adds clear explanations of two key scenarios: when one submodule commit is a descendant of another (where Git attempts a fast-forward), and when merge commits exist containing both conflicting submodule commits (where Git suggests a resolution but leaves it unmerged).

The patch has benefited from review by core maintainers Junio C Hamano and submodule/merge expert Elijah Newren. Version 3 maintains the same technical content while improving documentation formatting and removing redundant information about the recursive strategy. The changes are well-focused, with the commit message clearly referencing the implementation commit (68d03e4a6e44) that introduced this behavior. This represents a straightforward but valuable improvement to Git's merge strategy documentation.
