This is a performance optimization discussion for bundle-uri reference handling, with input from the original bundle-uri designer Derrick Stolee. The thread concerns Scott Chacon's proposed change to copy all references (not just heads) from bundles to improve fetch negotiation, which showed dramatic performance improvements in testing (32% to 1% object downloads).

Stolee confirms this exposes an unconsidered edge case in the original design, particularly around tag handling. He notes the original intention was to avoid modifying tag refs directly, suggesting tags should be peeled to commits and represented as fake branches instead. This maintains the fetch advertisement behavior while still enabling the performance benefits.

The discussion highlights two key technical issues: (1) the reference mapping change from `refs/heads/foo`→`refs/bundles/foo` to `refs/heads/foo`→`refs/bundles/heads/foo` could break existing users, and (2) multiple bundles could overwrite references, leaving objects unanchored for GC. Stolee focuses on testing requirements, wanting to verify repository usability when `refs/bundles/tags/` references exist.

While open to relaxing the refspec matching as proposed, Stolee questions whether the bundle creation process could be modified to use `refs/heads/` references instead. The thread remains focused on finding a solution that preserves the performance gains while properly handling edge cases around tag references and multiple bundle interactions.
