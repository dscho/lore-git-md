This is a performance optimization patch in the refs subsystem, part of a larger series (v3, 16 patches) addressing refname availability checks. Patch 7/16 focuses on the files backend's initial transaction handling, building on the batched verification infrastructure introduced in earlier patches.

The change modifies `files_transaction_finish_initial()` to collect all refnames needing verification into a `refnames_to_check` string list before performing a single batched availability check, rather than checking each reference individually. While the immediate performance impact is neutral (the underlying verification still happens in a loop), this sets up for future optimizations that will benefit cloning and reference format migration operations.

Key technical details:
- Introduces `refnames_to_check` string list to accumulate references
- Moves verification to happen after packed-refs locking but before transaction commit
- Maintains existing error handling semantics (TRANSACTION_NAME_CONFLICT)
- Cleans up both `affected_refnames` and new `refnames_to_check` lists
- Preserves special handling for symbolic refs, root refs, and reflogs

This patch represents a transitional step in the optimization series, with the actual performance gains to come in subsequent commits that will leverage this batched verification approach. The change is focused on the initial transaction case where references are first being written to the repository.
