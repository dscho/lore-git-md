Performance optimization patch in the refs subsystem series. This is patch 5/16 in v3 of Patrick Steinhardt's series addressing refname availability checks across Git's ref backends. The patch focuses on the reftable backend, refactoring it to batch refname availability checks rather than verifying them one by one.

The change introduces a new `refnames_to_check` string list that collects all refnames needing verification during transaction preparation. Instead of immediately calling `refs_verify_refname_available()` for each ref, it now accumulates them and performs a single batched check using the new `refs_verify_refnames_available()` function introduced in patch 4/16. The patch maintains all existing error handling and cleanup paths while adding the new string list to the cleanup section.

While this patch itself doesn't yet show performance improvements (as noted in the commit message), it lays the groundwork for optimizations in subsequent patches by enabling batched processing. The change is part of a larger effort that has already demonstrated significant speedups (4.78-7.56x for reftable backend in previous patches). The implementation appears clean and maintains the existing behavior while preparing for future optimizations.
