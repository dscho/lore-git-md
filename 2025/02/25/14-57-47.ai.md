This is a feature implementation patch in the ongoing ref transaction partial updates series. Phillip Wood responds to Karthik Nayak's patch implementing core support for partial reference transactions via the new `REF_TRANSACTION_ALLOW_PARTIAL` flag.

The patch under discussion introduces the core infrastructure for partial transactions, including:
- A `rejection_err` field in `struct ref_update` to track failed updates
- Backend modifications (files, packed, reftable) to handle partial failures
- A `ref_transaction_for_each_rejected_update()` iterator for examining failures
- Preserved atomicity for system errors while allowing user errors to be skipped

Phillip suggests two potential interface improvements:
1. Having `ref_transaction_commit()` directly signal when there were ignored errors, rather than requiring explicit iteration
2. Passing the rejection callback through `ref_transaction_begin()` when partial transactions are enabled

The discussion continues the thread's pattern of refining the error handling design, now focusing on the best way to expose partial failure information to callers. This builds on prior consensus around enum-based error classification and backend implementation details while maintaining the core transaction safety guarantees.
