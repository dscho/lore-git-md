This is the final version (v6) of a bugfix and security enhancement series adding comprehensive validation of packed-refs files in `git fsck`. The series has undergone multiple rounds of review and now addresses all feedback, with only minor documentation tweaks remaining.

The key changes in v6 focus on polish and clarity: improved commit messages explaining the stricter header format validation, better quoting of filenames in error messages, and enhanced comments. The technical implementation remains robust, with all core validation checks preserved:

1. Filetype verification via `lstat()` (now with properly quoted filenames in errors)
2. Strict header format checking (requiring "# pack-refs with: " with trailing space)
3. NUL character detection in refnames
4. Entry syntax validation matching packed-backend.c's parsing rules
5. Sortedness verification when declared
6. TOCTOU mitigation via `open_nofollow`

The series integrates these checks into `git fsck` through a new `git refs verify` subprocess, maintaining progress reporting and honoring `--verbose`/`--strict` flags. Test coverage in t0602-reffiles-fsck.sh verifies all validation cases while maintaining test hygiene standards.
