Git thread summary:

Bug report regarding inconsistent handling of backspace (`\b`) escape sequences in Git's configuration system. Yaakov Smith observes that `git fetch` renders backspace as a question mark in remote URL error messages, while `git config --list` outputs raw backspace sequences, potentially allowing configuration values to be obscured (e.g., `"true\b\b\b\bfalse"` displays as "false" by overwriting). The discrepancy occurs between these commands despite both dealing with configuration values, raising potential security/usability concerns. Reproduction provided on Git 2.34.1 (Linux/WSL2). No patch yet - initial report seeks discussion about whether this behavior warrants changes. Key technical details involve config value parsing/display in `fetch` versus `config` commands. Open question: should Git normalize escape sequence handling across commands, and if so, which behavior (raw vs sanitized) is preferred?
