Performance optimization in the refs subsystem, part 8/16 of Patrick Steinhardt's series addressing refname availability checks. This patch specifically targets redundant verification of common reference prefixes during batch operations.

The change introduces a `strset` to track already-verified directory prefixes in `refs_verify_refnames_available()`, avoiding repeated checks for common paths like "refs/heads/" when processing multiple references. Benchmarks show significant improvements: 1.58x faster for reftable backend when creating 10k new refs (63.1ms → 40.0ms), and more modest 1.03x for files backend. Reference migration between backends also sees ~1.1x speedup due to reduced string list lookups.

Key technical details:
- Adds `struct strset dirnames` to track verified prefixes
- Skips re-checking directories already in the set
- Maintains existing error semantics and transaction safety
- Preserves behavior for both initial and non-initial transactions
- Cleans up allocated strset memory properly

The implementation builds on previous infrastructure changes in the series (patches 1-7) and demonstrates the expected gains from the batched verification approach. The reftable backend benefits more substantially due to its different performance characteristics compared to files backend. This represents another incremental step in the overall optimization effort, with more gains expected in subsequent patches.
