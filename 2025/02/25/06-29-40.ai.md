Bugfix in the zlib inflation series, addressing malformed loose object headers.

This patch fixes an error handling case in `unpack_loose_header()` where the function would incorrectly return ULHR_TOO_LONG when hitting the end of a zlib stream without finding a NUL terminator in the header. The change makes it return ULHR_BAD instead, which more accurately reflects that the object is malformed (missing required NUL terminator) rather than just being too long. The practical impact is minimal since both error codes would make Git reject the object, but this provides more accurate error reporting.

The change is small (just one line in `object-file.c`) and part of a larger series addressing zlib inflation edge cases. The author notes they're deferring test coverage to the next patch in the series which will make testing this case easier. This appears to be a straightforward correctness fix that better matches the function's intended error handling semantics.

- Modifies error return path in `unpack_loose_header()`
- Changes ULHR_TOO_LONG to ULHR_BAD for NUL-less headers
