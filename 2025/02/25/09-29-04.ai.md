Refactoring patch in the files ref backend, part of a larger series on partially atomic ref updates (1/7). This patch removes redundant duplicate-checking logic in `split_symref_update()` and related functions. The code previously had two safety checks when adding refnames to the `affected_refnames` list: one upfront check for duplicates via `string_list_has_string()`, and a later BUG() assertion that the newly inserted item's `util` field was NULL. The patch recognizes that the first check makes the second one redundant, since `string_list_insert()` will never encounter a preexisting entry when the list is already verified duplicate-free. The change simplifies three functions (`split_head_update`, `split_symref_update`, and `files_transaction_prepare`) by removing the now-unnecessary `util` field assignments and related checks. This appears to be a straightforward cleanup with no behavior change, though reviewers may want to verify that the removed BUG() checks weren't serving some subtle safety purpose. The patch is part of a larger series (v2) about atomic ref updates, but this particular change stands alone as a code simplification.
