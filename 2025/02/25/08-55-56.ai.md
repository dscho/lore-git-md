This is a refactoring patch in the performance optimization series for the refs subsystem, introducing iterator reseek capability.

Patch 10/16 adds infrastructure to allow ref iterators to be reseeked to new prefixes without requiring full reinitialization. The primary motivation is enabling potential performance optimizations in the reftable backend, which could reuse internal state when reseeking. The patch introduces a new `.seek` vtable function that mirrors `refs_ref_iterator_begin()` behavior but operates on existing iterators.

Key technical details:
- New `ref_iterator_seek()` API function and corresponding vtable entry
- Implementation for empty and prefix iterators (debug wrapper also updated)
- Seeks maintain all original parameters except prefix
- Documentation specifies NULL/empty prefix resets to initial state
- Follow-up patches will implement backend-specific versions

The change is infrastructure-only at this stage, with no direct performance impact yet. It builds on the iterator lifecycle refactoring from patch 9/16 and enables future optimizations where iterators can be reused rather than recreated. The implementation maintains the existing iterator contract while adding the new capability.
