This is part 10/16 of Patrick Steinhardt's performance optimization series for the refs subsystem, focusing on iterator infrastructure. The patch introduces a new capability to re-seek ref iterators without recreating them, which could enable future performance optimizations by reusing internal iterator state.

The change adds a new `.seek` function to the ref iterator vtable that allows callers to reset an iterator to a new prefix (or the same one) while maintaining other iterator parameters. This is particularly useful for reftable iterators which currently must be scrapped after use, despite having reusable internal state. The implementation includes the basic infrastructure and implements the callback for trivial cases (empty and prefix iterators), with other iterators to follow in later patches.

This is an infrastructure change that doesn't directly impact benchmarks but enables potential future optimizations. The patch maintains careful attention to interface consistency and memory safety seen throughout the series. It's a logical next step after the iterator lifecycle refactoring in patch 9/16, further cleaning up and extending the iterator API.
