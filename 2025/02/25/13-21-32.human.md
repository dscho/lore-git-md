This is a bugfix patch in the final v6 series enhancing `git fsck`'s packed-refs validation. It adds a check to verify that the "packed-refs" file is a regular file (not a symlink or other special file type), closing a potential security gap in ref validation.

The patch introduces an `lstat()` check in `packed_fsck()` to validate the file type, reusing the existing `FSCK_MSG_BAD_REF_FILETYPE` error message when the file isn't regular. The change is well-motivated by the need to ensure packed-refs files are properly formed and not manipulated via symlinks. A new test case verifies the behavior by creating a symlink to packed-refs and checking the error output.

This is part of a mature series that has already addressed all reviewer feedback (from Patrick Steinhardt and Karthik Nayak) and appears ready for merging. The implementation is clean, with proper error handling and test coverage, maintaining the series' high quality standards. The patch fits naturally into the broader effort to harden packed-refs validation against various corruption and security issues.
