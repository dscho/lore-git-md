This is a review comment from Junio Hamano on patch 3/9 of the packed-refs validation series, focusing on filetype checking implementation details.

Junio suggests optimizing the filetype verification logic to handle the common case (regular files) more efficiently. Currently, the patch uses `lstat()` to check the file mode before opening, but Junio proposes doing the check *after* attempting to open the file with `open_nofollow()`. This would avoid an extra syscall in the happy path where the file exists and is regular.

The suggested approach would first try to open the file, then only perform the `lstat()` if the open fails, followed by a `fstat()` on the opened file descriptor to verify it's a regular file. This maintains all the security checks while being more efficient for normal cases.

This is a minor implementation refinement to an otherwise complete patch series that adds comprehensive validation of packed-refs files, including this new filetype checking. The series as a whole is in its final form (v6) and ready for merging, with this being one of the last polish suggestions from the maintainer.
