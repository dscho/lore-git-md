Core implementation of the new `git-diff-pairs` plumbing command for batch blob diff generation.

This patch introduces the main implementation of `git-diff-pairs(1)`, a new plumbing command that processes NUL-delimited raw diff format input to generate various diff outputs (patch format by default). The command enables splitting the traditional diff pipeline into stages, where frontend commands like `git-diff-tree` can compute file pairs and rename information, while `diff-pairs` handles the actual blob content comparison.

Key technical details:
- Input must be NUL-delimited raw diff format (rejects non-`-z` mode)
- Explicitly rejects tree objects and pathspec arguments
- Handles all diff statuses (added, modified, deleted, renamed, copied, typechanged)
- Preserves rename/copy information from frontend via standardized format
- Includes comprehensive test coverage in t4070-diff-pairs.sh
- Documentation in git-diff-pairs.adoc explains usage and limitations

The implementation builds on the refactored diff queue infrastructure from patch 1/3, using the new `diff_queue_addremove()` and `diff_queue_change()` functions while maintaining all existing behavior. The command is designed to work with the finalized interface contracts established in the thread discussion, including strict input validation and clear error messaging.

This represents the core functionality of the series, with all major design decisions (NUL-delimited I/O, tree rejection, rename handling) now implemented and tested. The patch addresses previous feedback by renaming `parse_oid()` to `parse_oid_or_die()` and ensuring robust error handling.
