This is a refactoring patch that's part of a larger series improving `git fsck`'s packed-refs validation. The patch addresses a subtle interaction where `git refs verify` and `git fsck` could prematurely fail when checking worktree HEAD references that point to malformed packed-refs entries.

The change introduces a new function `get_worktrees_without_reading_head()` that avoids parsing HEAD references when examining worktrees. This prevents strict packed-refs validation from kicking in too early during repository verification, allowing the full fsck process to complete rather than dying on the first malformed packed-ref that happens to be referenced by a worktree HEAD.

The patch builds on prior work from commit 465a22b338 that first introduced the ability to skip HEAD parsing. The implementation is straightforward - it exposes the existing internal skip-HEAD functionality through a new public API and updates `builtin/refs.c` to use it. The change is well-motivated and fits cleanly into the larger fsck validation effort, with clear mentorship from Patrick Steinhardt and Karthik Nayak noted in the sign-off.
