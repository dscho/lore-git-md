This is a documentation patch that clarifies submodule merge behavior in Git's merge strategies documentation. It's part of a GSoC (Google Summer of Code) project, now in its third revision.

The patch adds two paragraphs to Documentation/merge-strategies.adoc explaining how Git handles submodule merges in conflict cases. The first paragraph describes two special cases: when one submodule commit is a descendant of another (Git attempts a fast-forward), and when there are merge commits containing both conflicting submodule commits (Git suggests a resolution but leaves it unmerged). The second paragraph notes that the older 'recursive' strategy handles submodules the same way as the newer 'ort' strategy.

The patch appears well-considered, with help from core Git maintainers Junio C Hamano and Elijah Newren. The v3 maintains the same technical content as v2 while improving the documentation formatting and removing a redundant paragraph about the recursive strategy. The changes are focused and clearly explained in the commit message, which references the relevant commit (68d03e4a6e44) that introduced this behavior.
