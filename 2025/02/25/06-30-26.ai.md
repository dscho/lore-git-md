This is a bugfix patch in the zlib inflation series, addressing a specific edge case where malformed object input could trigger a BUG() in git-zlib.c. The issue occurs when processing zlib streams that request a dictionary (Z_NEED_DICT status), which Git doesn't support but could encounter with corrupt input.

The patch modifies `zlib_post_call()` to skip its `total_in` sanity check when zlib returns Z_NEED_DICT, since zlib doesn't update `total_in` in this case while still consuming input bytes. The author considered three approaches and chose the one that maintains git_inflate() as a thin wrapper around zlib's inflate(), keeping the door open for potential future dictionary support. The change requires passing the zlib status through to `zlib_post_call()`, affecting all zlib wrapper functions in git-zlib.c.

A new test case demonstrates the fix by creating an object compressed with a zlib dictionary (simulated via direct binary manipulation since Git doesn't support dictionary compression). The test verifies Git fails cleanly with an error message rather than hitting the BUG() when encountering such input. This complements the series' focus on hardening Git's handling of malformed zlib streams, though the scenario requires specially crafted input to trigger.
