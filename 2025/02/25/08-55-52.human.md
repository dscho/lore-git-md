Performance optimization for the files ref backend, part of a larger series improving refname availability checks. This patch (6/16 in v3) extends the batched verification approach from the reftable backend to the files backend, though with some complications due to the files backend's more varied call patterns.

The patch focuses on two key call sites where batching makes sense: during normal reference updates and repository initialization. The main change queues up refnames for checking rather than verifying each immediately, then performs a single batched check before proceeding with the transaction. The author notes this introduces a small race window with packed-refs changes, but avoids changing locking semantics that users might depend on.

This continues the series' pattern of introducing infrastructure (patches 1-4), then implementing it in each backend (reftable in patch 5, files here in 6). The files backend changes are more complex than reftable's due to its multiple verification contexts, but the patch carefully maintains existing behavior while still enabling the batching optimization where it matters most. The implementation appears thorough, with clear explanations of the tradeoffs involved.
