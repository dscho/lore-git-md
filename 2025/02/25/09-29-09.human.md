This is the 6/7 patch in a series implementing partial reference transaction support in Git. The patch introduces core infrastructure to allow some reference updates to fail while others proceed, controlled by a new `REF_TRANSACTION_ALLOW_PARTIAL` flag.

The change modifies all three ref backends (files, packed, reftable) to handle partial transactions by tracking rejected updates with specific error codes rather than failing the entire transaction. A new `rejection_err` field in `struct ref_update` records why an update failed, and a `ref_transaction_for_each_rejected_update()` function lets callers inspect which updates failed.

The implementation distinguishes between user-facing errors (like reference conflicts) that can be skipped, and system errors (like I/O failures) that still abort the entire transaction. This maintains safety while adding flexibility, particularly benefiting the reftable backend where batched updates are more efficient.

The patch appears well-constructed with thorough modifications across the refs subsystem. It builds on previous patches in the series that introduced error classification and refactored backend code. The next patch will expose this functionality to users via a `--allow-partial` flag for `git update-ref`.
