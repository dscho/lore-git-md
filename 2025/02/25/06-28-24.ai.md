This is a preparatory patch in a 10-part series addressing zlib inflation issues in Git's object handling. The patch focuses on a theoretical memory safety issue in `loose_object_info()` when handling objects with unknown types under the `OBJECT_INFO_ALLOW_UNKNOWN_TYPE` flag.

The core problem involves how `unpack_loose_rest()` calculates content bytes to copy when processing objects with unknown types. The calculation could lead to an out-of-bounds read due to incorrect buffer size assumptions, though the author notes this cannot currently be triggered in practice due to other constraints in the object handling code. The patch adds a `BUG()` assertion to prevent any potential exploitation of this edge case.

Key technical details include:
- The issue stems from interaction between `unpack_loose_header()` and `unpack_loose_rest()` when processing objects with unknown types
- Only affects code paths using `OBJECT_INFO_ALLOW_UNKNOWN_TYPE`, which is limited to `git cat-file -t/-s` operations
- The patch modifies `object-file.c` to explicitly fail if content unpacking is attempted for unknown types
- The author questions the utility of the unknown type feature altogether, suggesting it may be vestigial

This appears to be a defensive change preparing for later patches in the series, though it stands on its own as a safety measure. The patch is well-motivated and includes thorough analysis of why the issue cannot currently be triggered, making the BUG() addition a reasonable approach.
