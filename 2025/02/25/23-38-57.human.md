Feature implementation for a new `git-diff-pairs` plumbing command, part of an ongoing series to enable batch blob diff generation. This patch introduces the core command that takes NUL-delimited raw diff input (from `git diff-tree -z`) and produces formatted diffs, allowing server-side workflows to process diffs incrementally rather than all at once.

The implementation handles all standard diff statuses (adds, deletes, modifications, renames, copies) while explicitly rejecting tree objects per recent thread consensus. It includes thorough tests verifying raw diff recreation, patch output generation, and split-input handling. Documentation has been made more user-focused based on Karthik Nayak's feedback, though some details around tree rejection messages remain to be finalized.

This represents a key piece of infrastructure for server-side diff processing, with the design now solidified through mailing list discussion. The patch appears well-constructed with comprehensive test coverage and clear documentation, though it awaits final tweaks to error messaging before potential merge.
