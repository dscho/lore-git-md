This thread examines a subtle but potentially security-relevant inconsistency in how Git handles backspace escape sequences (`\b`) in configuration output. The discussion began when Yaakov Smith reported that `git fetch` sanitizes these sequences while `git config --list` shows them raw, which could allow configuration values to be obfuscated. Jeff King clarified this is intentional - human-facing commands sanitize while programmatic ones preserve raw output.

The conversation expanded to examine pager behavior, where maintainers initially considered modifying Git's default `$LESS` settings to make control characters visible, but rejected this approach after Jeff King's analysis showed it would negatively impact tab display in diffs. The current consensus is to preserve diff readability as the higher priority, leaving the backspace handling inconsistency unresolved at the Git level.

Kyle Lippincott's latest contribution suggests a user-side workaround using `LESSKEY_CONTENT` to conditionally apply modern `less` features (`--PROC-BACKSPACE` in version 632+) that can handle control characters without affecting tab display. While this doesn't resolve the core inconsistency between Git commands, it provides a viable path for users who need to inspect configuration with control characters while maintaining readable diffs. The thread remains open to alternative solutions that could standardize behavior without compromising diff quality.
