This is part 5 of a 7-patch series refactoring Git's reference transaction system to support partial updates, introducing a new `--allow-partial` flag for `git update-ref`. The series has evolved through review feedback, with this version (v2) adding improved documentation, test coverage, and code deduplication.

This specific patch introduces an enum-based system for transaction error types, replacing the previous preprocessor-defined error codes. The new `transaction_error` enum provides strongly-typed error classification with clear categories like `TRANSACTION_NAME_CONFLICT`, `TRANSACTION_CREATE_EXISTS`, and `TRANSACTION_INCORRECT_OLD_VALUE`. The change improves type safety, makes error handling more explicit, and maintains backward compatibility while adding new error cases.

The patch touches all major ref backends (files, packed, reftable) to convert their error handling to use the new enum. Key functions affected include `refs_verify_refname_available()`, `ref_update_check_old_target()`, and various backend-specific operations like `lock_raw_ref()` and `write_with_updates()`. The enum definitions and function signatures are updated in refs.h and refs-internal.h, with corresponding implementation changes across ~350 lines of modified code.

This foundational change enables more robust error handling for the upcoming partial transaction support, where different types of errors may need different handling (e.g., some being skippable while others abort the entire transaction). The typed errors will help distinguish user-facing issues (like name conflicts) from system-level problems.
