This is a performance optimization discussion regarding bundle-uri negotiation. Junio C Hamano is responding to Scott Chacon's patch that widens the refspec pattern in bundle-uri.c from `refs/heads/` to `refs/` to improve fetch negotiation efficiency.

The discussion highlights several key points: Junio agrees with the performance benefits shown (reducing downloaded objects from 32% to 1% in test cases), but raises thoughtful questions about potential edge cases. He notes the change alters the reference mapping scheme (now putting heads under `refs/bundles/heads/` rather than directly in `refs/bundles/`), which might affect existing users who rely on the old structure.

Junio identifies a deeper architectural concern: when processing multiple bundles, later bundles could overwrite references from earlier ones, potentially leaving objects without references and subject to garbage collection. He suggests the solution might need to create unique names rather than relying on the original reference names.

The response is constructive but cautious, acknowledging the performance win while flagging areas needing more consideration.
