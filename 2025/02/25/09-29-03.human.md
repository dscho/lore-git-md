This is a feature patch series introducing partial reference transaction support, culminating in a new `--allow-partial` flag for `git update-ref`. The series builds on prior work to enable individual reference updates to fail while allowing others to proceed, particularly useful for the reftable backend where batching updates is more efficient.

The 7-patch series starts with preparatory cleanups to refname checking logic, then introduces enum-based error types to distinguish user-facing errors (which can be skipped) from system errors (which remain fatal). The core implementation adds infrastructure to track and report rejected updates while allowing transactions to proceed when the new `REF_TRANSACTION_ALLOW_PARTIAL` flag is set. The final patch exposes this via `git update-ref --stdin --allow-partial`, with thorough test coverage.

The implementation handles all three ref backends (files, packed, reftable) while preserving their atomicity characteristics - files backend remains non-atomic while reftable maintains atomicity. Error reporting uses a callback mechanism to output rejected updates in a standardized format. The series has evolved through review to refine the error taxonomy and interface naming (e.g., `ref_transaction_set_rejected`).

This provides valuable flexibility for tools that need to batch reference operations while handling failures gracefully. The careful progression from backend changes to user interface, along with comprehensive tests and documentation, suggests this is a well-considered addition to Git's ref transaction system.
