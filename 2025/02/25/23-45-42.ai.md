Documentation refinement for Git 3.0 breaking changes. This patch from Junio Hamano incorporates Jakub Wilk's observation about the precise state of legacy "branches/" and "remotes/" directories in modern repositories. The change clarifies that while these directories may exist (having been part of default templates until recently), they are unlikely to be actively used. This replaces the previous wording which incorrectly stated the directories wouldn't be found at all in modern repositories.

The patch updates Documentation/BreakingChanges.txt with more accurate language about the distinction between directory presence versus usage, maintaining the overall deprecation rationale while being factually correct about repository states. The change is straightforward - a two-line modification to the documentation file with updated wording that better reflects the historical context of these legacy features.

This represents the final documentation refinement in the breaking changes series, addressing the last open consideration from the thread summary. The patch carries both Jakub's Reported-by tag and Patrick Steinhardt's Acked-by, indicating consensus on the improved wording. The change doesn't affect any code or build infrastructure - it purely improves the accuracy of user-facing documentation about the legacy directory deprecation.
