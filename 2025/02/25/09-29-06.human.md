This is a refactoring patch in Karthik Nayak's series to enable partial reference updates. It removes a redundant duplicate-refname check in the files backend that was already being performed during the transaction's prepare phase. 

The change is straightforward: since the refnames list doesn't change between prepare and finish phases, there's no need to check for duplicates twice. The patch makes the duplicate-checking function static since it's now only used in refs.c, and removes its declaration from the internal header. 

This is part of a larger effort to clean up and centralize reference transaction logic across Git's backends. The series has already established consensus on the core design, and this patch demonstrates the maintainability benefits by eliminating 16 lines of code while preserving all existing functionality. The change is well-contained and unlikely to be controversial, as it simply removes redundant work without changing behavior.
