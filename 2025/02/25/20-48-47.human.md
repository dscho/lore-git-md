This is a test infrastructure patch addressing a bug in how unit tests are run. Michael Gruber noticed that unit tests currently execute in the user's environment, including their Git configuration, which can interfere with test assumptions (he hit this with `t-trailer` tests failing due to his personal config). 

The patch proposes creating a clean test environment for unit tests, similar to what's already done for regular tests. It introduces a new `unittest-lib.sh` (a trimmed-down version of `test-lib.sh`) and modifies the test runner to source it. The changes ensure unit tests run in an isolated environment with standardized settings.

Gruber marks this as a WIP/POC - it solves his immediate problem but notes the implementation could be refined (perhaps merging the lib into `run-test.sh`) and doesn't cover direct test invocations. The patch looks like a solid start at fixing a real issue, though the approach may need discussion about how much test infrastructure to share between regular and unit tests.
