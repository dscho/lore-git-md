This is a feature patch (part 7/7) in a series adding partial transaction support to `git update-ref`. Phillip Wood provides review feedback on Karthik Nayak's implementation of the `--allow-partial` flag for stdin mode.

Key technical points raised:
1. Suggests making partial failure configurable per-transaction (via "start" command) rather than globally via `--allow-partial`, similar to how `no-deref` works
2. Questions the inconsistency in output format between normal and `-z` modes, noting `-z` is documented as only affecting input
3. Agrees with Patrick Steinhardt's earlier comment that error messages should not be translated for this plumbing command
4. Notes unnecessary stdout flushing after each rejected ref output
5. Approves of the error reporting approach where "commit: ok" signals completion

The patch under discussion implements:
- `--allow-partial` flag for `update-ref --stdin`
- Rejection reporting via new `print_rejected_refs()` callback
- Comprehensive tests covering various failure modes (invalid refs/oids, conflicts, etc.)
- Preserved atomicity for successful updates when others fail

Phillip's feedback focuses on interface polish and consistency rather than core functionality, continuing the thread's pattern of refining the user-facing aspects while accepting the underlying transaction model. The discussion remains focused on finalizing the error reporting mechanism and output format details.
