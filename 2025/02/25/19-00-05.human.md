This is a minor test style discussion in Jeff King's zlib inflation series, which is on hardening Git's object parsing against malformed input.

Eric Sunshine responds to Patrick Steinhardt's suggestion about test cleanup ordering in patch 04/10. The patch originally queues the cleanup (`mv` restoration) after the destructive operation, which Patrick notes goes against the modern convention of declaring cleanup first. 

Eric argues the current ordering makes sense here because the cleanup only has meaning if the initial `mv` succeeds. He points out that reversing the order would require additional error handling (`||:`) to prevent the cleanup itself from failing unnecessarily, making the code more complex for no real benefit.

This is a small stylistic debate within a larger series that's systematically improving zlib error handling. The exchange shows careful attention to test hygiene, even for cases where the practical difference is negligible. The thread continues to focus on hardening edge cases while maintaining clean code practices.
