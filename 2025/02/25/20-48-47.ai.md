This is a test infrastructure patch addressing an isolation issue in Git's unit tests. The problem stems from unit tests running in the user's environment, including inheriting their Git configuration, which can cause test failures when config values interfere with test assumptions (as happened with the t-trailer test in the author's case).

The patch introduces a new `unittest-lib.sh` that establishes a clean test environment similar to what regular Git tests use, including:
- Sanitized environment variables
- Isolated trash directory
- Controlled Git config and template settings
- Standardized terminal and locale settings

The implementation currently:
1. Modifies the Makefile to route unit test execution through `run-test.sh`
2. Adds the new `unittest-lib.sh` (a trimmed-down version of `test-lib.sh`)
3. Updates `run-test.sh` to source the new library

The author notes this is more proof-of-concept than polished work, acknowledging that:
- The library could likely be further simplified
- The Makefile change might not catch all test invocation methods
- The issue primarily affects local development (CI environments are already clean)

Key technical details:
- New file `t/unittest-lib.sh` with 385 lines of environment setup code
- Modifies test execution path in `t/Makefile`
- Adds library sourcing to `t/run-test.sh`
- Uses same isolation patterns as main test suite (trash directories, config sanitization)

This appears to be a legitimate isolation problem in the test infrastructure, though the solution may need refinement around edge cases and direct test invocations. The approach aligns with Git's existing test patterns but introduces new complexity for unit tests specifically.
