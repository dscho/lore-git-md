Refactoring patch in a zlib inflation improvement series. This is patch 2/10 in Jeff King's series addressing zlib handling issues in Git's object reading code. The change simplifies the buffer management in `unpack_loose_header()` by moving the `next_out` pointer initialization inside the inflation loop rather than resetting it after each iteration.

The patch makes three improvements: (1) reduces code duplication, (2) makes it clearer that each inflation call gets a fresh buffer (preventing potential Z_BUF_ERROR confusion), and (3) leaves the zlib stream state in a more consistent position after the loop. While not fixing any active bugs, the author notes this will make reasoning about subsequent fixes in patch 4 easier.

The change is small (4 lines removed, 3 added) and focused entirely on the object-file.c implementation. It's a clean preparatory refactoring that doesn't change behavior but improves code clarity and maintainability for the more substantive zlib fixes coming later in the series.
