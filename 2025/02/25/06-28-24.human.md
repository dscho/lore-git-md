This is the first patch in a 10-part series addressing zlib inflation issues in Git's object handling. The patch focuses on a potential memory safety issue when handling objects with unknown types.

The core problem involves how `unpack_loose_rest()` processes object content after header inflation when the `OBJECT_INFO_ALLOW_UNKNOWN_TYPE` flag is set. The current implementation could theoretically lead to an out-of-bounds read due to miscalculating buffer offsets for large unknown-type headers. However, the author (Jeff King) notes this scenario cannot actually be triggered in practice due to other constraints in the code.

Rather than attempting a complex fix for an untestable edge case, the patch takes a conservative approach by adding a `BUG()` check to explicitly prevent the unsafe condition. The commit message provides a thorough analysis of why the issue can't currently be triggered and raises broader questions about the utility of the unknown-type feature itself, suggesting it may be worth deprecating entirely.
