Refactoring of the refs subsystem's iterator lifecycle management, part of Patrick Steinhardt's performance optimization series (v3, 09/16). This patch decouples iterator lifecycle from iteration completion, replacing the automatic cleanup at exhaustion with explicit `ref_iterator_free()` calls.

The change addresses two key issues with the current design: awkward cleanup patterns when aborting iteration early, and the impossibility of reusing iterators for repeated searches. The patch introduces `ref_iterator_free()` as the unified cleanup mechanism, replacing all backend-specific `abort` implementations with `release` methods. Notable technical changes include:
- Removal of `ref_iterator_abort()` return values (now void functions)
- Conversion of `dir_iterator_abort()` to `dir_iterator_free()`
- Centralized cleanup in `ref_iterator_free()` that handles base iterator freeing
- Updates to all iterator implementations (files, packed, reftable backends) to match new interface
- Fixes call sites that previously relied on implicit cleanup

The change maintains all existing functionality while providing a foundation for potential future iterator reuse optimizations. As part of a larger performance series, this refactoring doesn't directly impact benchmarks but cleans up infrastructure used by other optimizations in the series. The patch touches core iterator interfaces and all major ref backends, requiring careful review of memory management patterns.
