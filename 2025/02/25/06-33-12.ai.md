This is a refactoring patch in Jeff King's zlib inflation series, focusing on cleanup semantics in object-file.c. The patch standardizes zstream ownership by making `unpack_loose_rest()` and `check_stream_oid()` never clean up their zstream parameter, pushing that responsibility to callers. This resolves an inconsistency where some error paths would clean up while others wouldn't, which previously led to memory leaks like the one fixed in aa9ef614dc.

The key changes are:
1. Removing `git_inflate_end()` calls from the success paths of `unpack_loose_rest()` and `check_stream_oid()`
2. Adding a new `out_inflate` label in `read_loose_object()` to handle stream cleanup consistently
3. Moving the cleanup to a single point in the caller's error handling path

The patch maintains all existing functionality while making the ownership rules clearer. Though the author notes this could be seen as churn, it prevents subtle bugs by establishing a simple rule: callers always own cleanup. The change affects three main functions (`unpack_loose_rest`, `check_stream_oid`, and `read_loose_object`) and their interaction with zlib stream handling during object reading. This is part of a broader effort to harden Git's zlib inflation code against edge cases and memory issues.
