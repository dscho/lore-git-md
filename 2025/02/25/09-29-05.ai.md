This is a refactoring patch in the partial reference updates series, moving duplicate refname checking from individual backends to the generic refs layer. The patch centralizes the tracking of refnames in a new `refnames` string_list field within `ref_transaction`, eliminating duplicate code across the files, packed, and reftable backends.

Key technical changes:
- Adds `refnames` field to `ref_transaction` struct to track all references in a transaction
- Updates `ref_transaction_add_update()` to automatically populate this list (except for REF_LOG_ONLY updates)
- Removes backend-specific duplicate checking code from files-backend.c (67 lines deleted), packed-backend.c (25 lines deleted), and reftable-backend.c (54 lines deleted)
- Preserves special handling for HEAD and symref updates while using the centralized list
- Maintains the same error messages and behavior for duplicate refnames

The change simplifies future maintenance by having one canonical implementation of duplicate checking rather than three slightly different versions. It's a clean mechanical transformation that doesn't introduce new functionality but makes the codebase more maintainable. The patch fits well with the series' goal of standardizing reference transaction handling across backends.
