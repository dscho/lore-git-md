This is the final patch in a 7-part series introducing partial reference updates to Git. It adds a user-facing `--allow-partial` flag to `git update-ref --stdin` that enables the partial transaction functionality built in the previous patches.

The flag allows reference updates to continue even when some individual updates fail due to user errors (like invalid OIDs or missing references), while still aborting for system errors. Failed updates are reported in a structured format showing the refname, old/new values, and rejection reason. The patch includes extensive documentation of the new behavior and adds 216 lines of tests covering various error scenarios.

The implementation builds on the refactored reference transaction backend from earlier patches, using the new rejection tracking infrastructure (added in patch 6) to report failures. The tests demonstrate how the feature handles cases like invalid OIDs, non-existent refs, symref conflicts, and name collisions, with special handling for files vs reftable backend differences in atomicity guarantees.

This completes the series' goal of enabling more flexible reference updates while maintaining safety, with all design questions from earlier discussion now implemented. The patch appears well-tested and integrates cleanly with the refactored transaction system.
