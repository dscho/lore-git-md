This is a performance optimization patch in the refs subsystem series, implementing seek capability for packed-ref iterators. It's patch 14/16 in v3 of Patrick Steinhardt's series addressing refname availability checks across Git's ref backends.

The patch adds seek functionality to packed-ref iterators, completing the cross-backend iterator optimization work started earlier in the series. The implementation follows the pattern established in previous patches (12-13/16) for reftable and ref-cache iterators, but with packed-ref-specific considerations. The key changes include:

1. Adding a `prefix` field to track the current seek position
2. Implementing `packed_ref_iterator_seek()` to reposition the iterator
3. Moving prefix filtering into `advance()` rather than using a separate prefix iterator
4. Careful handling of empty vs non-empty prefix transitions
5. Proper memory management of the prefix string

The implementation maintains the series' focus on performance by avoiding iterator recreation and enabling reuse through seek operations. It includes safety checks like a BUG() for invalid iterator states and proper NULL/empty prefix handling. The patch builds on the iterator lifecycle refactoring from earlier in the series (patches 9-11) while addressing packed-ref-specific behaviors around snapshot positioning and prefix matching.

This completes the seek capability implementation across all major ref backends (files, reftable, packed-refs), establishing consistent iterator behavior that enables future optimizations. The change is part of the broader effort to optimize refname availability checks that has shown significant performance improvements (4.78-7.56x for reftable, 1.23-1.27x for files backend).
