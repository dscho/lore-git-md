Documentation patch clarifying submodule merge behavior. This is the third version of a patch that adds documentation about how Git handles submodule conflicts during merges, specifically for the `ort` and `recursive` strategies.

The patch describes two special cases Git considers when submodule merges conflict: (1) one submodule commit is a descendant of the other (where Git will attempt a fast-forward), and (2) when there exists a common descendant commit that could serve as a resolution suggestion. These behaviors were introduced in commit 68d03e4a6e but weren't previously explained in the documentation.

Version 3 maintains the same technical content as v2 but improves the formatting by using proper AsciiDoc paragraph syntax and removes a redundant explanation from the `recursive` strategy section, instead noting that it behaves the same as `ort` for submodule merges. The patch has been reviewed by Junio Hamano and Elijah Newren, suggesting it's technically sound.

This is a straightforward documentation improvement that fills a gap in explaining behavior that's been in Git for some time. The changes are well-contained and the commit message clearly explains both the what and why of the changes.
