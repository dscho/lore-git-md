Performance optimization in refs subsystem (patch 4/16 in v3 series). This patch introduces a batched version of refname availability checking to optimize operations that need to verify multiple references at once.

The existing `refs_verify_refname_available()` function checks for conflicts when updating a single reference, but requires redoing several checks for each reference. The new `refs_verify_refnames_available()` function performs the same validation for a list of references, with the existing single-ref function reimplemented as a wrapper around it.

The implementation currently maintains the same logic but processes multiple refs in a loop, setting up for future optimizations in subsequent patches. The diff is large but mostly structural - moving the existing logic inside a loop while preserving all the same checks for directory conflicts, extras, and skip lists.

This is part of Patrick Steinhardt's ongoing series to optimize refname availability checks across Git's storage backends, building on earlier work to improve performance with tombstone references in reftable. The batched checking should particularly help operations that update multiple references at once, though the full performance impact will come in later patches that build on this infrastructure.
