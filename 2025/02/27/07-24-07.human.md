This is a bug report about inconsistent behavior of `transfer.hideRefs` between packed and loose refs in the upload-pack process. The reporter (SURA) observes that after a server-side `git gc`, clients see different sets of refs because packed refs are excluded by front match while loose refs use full match (with the expected prefix match when `transfer.hideRefs` ends with '/'). 

The issue appears to have been introduced by commit 59c35fa during optimizations to `git for-each-ref`, though the report doesn't provide specific details about the regression. The reporter suggests the problem may require reverting that commit rather than a simple fix.

This seems like a potentially serious issue for server operators using `transfer.hideRefs` for access control, as the visibility of refs could change unexpectedly after garbage collection. The report is brief but identifies a clear behavioral inconsistency that warrants investigation by the refs subsystem maintainers.
