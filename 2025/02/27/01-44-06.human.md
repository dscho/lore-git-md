This is a documentation patch clarifying submodule merge behavior, submitted as part of Google Summer of Code (GSoC). The patch adds explanation of two special cases Git handles during submodule merge conflicts: (1) when one submodule commit is a descendant of the other (Git attempts a fast-forward), and (2) when there exists a common descendant commit (Git suggests it as resolution while keeping the conflict marked). The behavior was introduced in commit 68d03e4a6e but wasn't previously documented.

The patch adds this explanation to both the 'ort' and 'recursive' strategy sections in merge-strategies.adoc, noting they handle submodules the same way. The patch has been through several iterations (v4) with help from Junio Hamano and Elijah Newren, suggesting it's been carefully reviewed. The current version is just removing an extra blank line from v3.

This is a straightforward documentation improvement that fills a clear gap - explaining behavior that was previously only visible in the merge strategy implementations. The change is well-contained and unlikely to be controversial.
