A bug report highlights an inconsistency in how `upload-pack` handles ref filtering between packed and loose refs when `transfer.hideRefs` is configured. The issue stems from commit 59c35fa (from the `git for-each-ref` optimization series), which unintentionally changed the matching behavior for packed refs to use front matching while loose refs correctly use full/prefix matching. This creates a discrepancy where clients see different refs before and after a server runs `git gc`, potentially exposing refs that should be hidden. The reporter suggests this may require reverting the problematic commit rather than a simple fix, indicating it's a non-trivial regression affecting server operations. The bug was observed on Git v2.48.1 running on Linux Mint 22, though the underlying issue would affect all platforms. No patch has been proposed yet - this appears to be the initial report of the problem.
