A bug report was filed about inconsistent behavior in `transfer.hideRefs` where packed and loose refs were being filtered differently, potentially causing clients to see different refs before and after a server-side `git gc`. The initial report suggested this was a regression introduced by commit 59c35fa (which optimized `git for-each-ref`) and might require reverting that change.

Taylor Blau, the Git maintainer, has now responded with a technical clarification. He explains that the current behavior is actually by design - loose refs and packed refs are intentionally handled differently at the filesystem level, with filtering happening later in `upload-pack`. He points out that the behavior change actually came from commit 18b6b1b5c5, not 59c35fa as originally claimed. While acknowledging that the loose refs implementation could theoretically be optimized to skip excluded directories earlier, he maintains this isn't a bug but rather an implementation detail. Taylor has asked for a reproduction script to better understand the specific issue, keeping the discussion open for further investigation if concrete examples can be provided.
