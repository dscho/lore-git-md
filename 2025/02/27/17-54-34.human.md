Refactoring patch to improve config handling in non-repository contexts.

This patch modifies `repo_config()` to gracefully handle NULL repository arguments by falling back to `read_very_early_config()`, which reads system and global configs. Currently, the function fails when called outside a repository context, which can happen with certain builtin commands.

The change is straightforward - just a NULL check and fallback - but addresses a real limitation in Git's config handling. The patch comes with clear documentation updates explaining the new behavior. It's part of Git's ongoing effort to better handle non-repository cases, with mentorship from Christian Couder and suggestion from Junio Hamano.

The implementation looks clean and focused, touching only the necessary files (config.c and config.h) with minimal changes. The commit message could benefit from a concrete example of where this would be useful, but the technical approach seems sound.
