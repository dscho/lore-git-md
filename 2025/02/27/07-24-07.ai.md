Bugfix targeting ref filtering in upload-pack. This reports an inconsistency in how `transfer.hideRefs` handles packed versus loose refs, where packed refs incorrectly use front matching while loose refs properly use full/prefix matching. The issue appears to have been introduced by commit 59c35fa during optimizations to `git for-each-ref`, causing clients to see different refs before and after a server-side `git gc`. The reporter suggests the problem may require reverting the offending commit rather than a simple fix, indicating this could be a non-trivial regression in ref visibility behavior that affects server operations. The bug manifests when using Git v2.48.1 on Linux Mint 22, though the underlying issue would presumably affect other platforms as well. No proposed patch is included - this appears to be an initial bug report rather than a solution attempt.
