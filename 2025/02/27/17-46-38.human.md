This is a bug report about bash completion behavior for `git diff` when run from outside the working tree. Junio Hamano notes that while `git add` and `git status` properly complete filenames (including untracked files) when using `-C` to specify the repository location, `git diff` fails to complete any filenames in this scenario. The completion works fine when run from within the working tree, suggesting the issue lies specifically with how `__git_complete_revlist_file` handles the `-C` flag.

The report provides clear reproduction steps showing the discrepancy between commands, and identifies the current behavior as particularly frustrating for common workflows like checking diffs in documentation files. While acknowledging some debate about ideal completion behavior (whether to show all files or just modified ones), Hamano emphasizes that the current outside-worktree behavior is strictly worse than the default filesystem completion.

The email specifically calls for help from contributors familiar with the bash completion script, having CC'd those who've recently worked on that part of the codebase. This appears to be a genuine usability pain point rather than a theoretical concern, given Hamano's note about encountering the issue multiple times daily.
