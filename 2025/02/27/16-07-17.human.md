This is part 7 of a 9-part series improving `git fsck` validation for packed-refs files, focusing on entry consistency checks. The patch adds detailed validation of individual ref entries in packed-refs files, catching several types of malformed entries that could previously slip through.

The changes introduce two new helper functions that validate the main ref entry line (oid + refname) and any following peeled line (for annotated tags). The validation catches:
- Invalid OIDs (too short, malformed hex)
- Missing space between OID and refname
- Bad refname formatting (including embedded NULs)
- Invalid peeled OIDs in tag entries
- Trailing garbage after peeled OIDs

The implementation follows the series' established pattern of thorough validation while maintaining backward compatibility. New test cases verify the checks work as expected, including edge cases like short OIDs and malformed tag entries. The patch adds a new `badPackedRefEntry` fsck message ID to report these issues.

This continues the series' methodical approach to strengthening packed-refs validation, now covering the actual ref entries themselves after previous patches handled header validation. The changes are well-documented and tested, with clear error messages that will help diagnose corrupt packed-refs files. The patch appears ready for review, though the series as a whole still awaits feedback from maintainers.
