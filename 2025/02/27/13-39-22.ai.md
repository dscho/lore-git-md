This is a CI/build system fix addressing a Windows-specific issue in GitLab's test runner. The patch corrects a problem where the "msvc-meson" test job would incorrectly report success even when tests failed, due to PowerShell 5.1's handling of error codes in command pipelines.

The issue stems from PowerShell's `ForEach-Object` loop not properly propagating error codes from the `meson test` command in GitLab's Windows runners, which use PowerShell 5.1. This differs from GitHub Actions' behavior where the same tests fail as expected, likely due to its use of PowerShell 7.4. The fix explicitly checks the `$?` variable after each test run and exits with the proper error code if tests fail.

The change is minimal - a one-line modification to `.gitlab-ci.yml` that adds an error check in the PowerShell pipeline. The author notes this is a temporary workaround until Meson 1.8's test slicing feature makes the custom PowerShell script unnecessary. The patch references both a discussion thread and a failed test run as evidence of the issue.

Key technical details for future reference: the fix involves the `$?` and `$LASTEXITCODE` PowerShell variables, the `ForEach-Object` cmdlet behavior, and the specific test command pipeline in the GitLab CI configuration. The underlying issue appears specific to PowerShell versions below 7.3 where `PSNativeCommandUseErrorActionPreference` isn't available.
