This is a bugfix patch in the packed-refs validation series, specifically addressing NUL character detection in refnames.

The patch adds validation to catch corrupted packed-refs entries where NUL bytes appear in the middle of a refname. Currently, the packed-backend code calculates refname length by pointer subtraction and would accept such corrupt refnames if the portion before the first NUL happens to be valid. The new `refname_contains_nul()` helper detects these cases by scanning for embedded NULs, causing the program to die with an error message when found.

The change is well-motivated by a real-world report showing this could be a security issue, with clear explanation of the problem and solution in the commit message. The implementation adds a focused check with its own documentation block, maintaining the existing error handling pattern. This continues the series' pattern of methodically strengthening packed-refs validation while preserving backward compatibility.

Key technical details for future reference:
- New function `refname_contains_nul()` scans for embedded NULs in refnames
- Integrated into `next_record()` alongside existing format checks
- Maintains same error handling pattern as other validation failures
- Documents the edge case in code comments
- References original bug report and maintains attribution
