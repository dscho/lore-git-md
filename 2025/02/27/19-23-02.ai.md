This is a refactoring patch in a series about cruft pack handling during repacks. It simplifies the logic for aggregating small cruft packs when using `--max-cruft-size` by removing the complex size-based sorting and accumulation approach in favor of simply combining all packs smaller than the threshold size.

The patch removes significant code from `builtin/repack.c` including a comparison function and size-tracking logic, replacing it with a straightforward check against each pack's size. This results in a behavioral change where packs are now combined more opportunistically rather than in size-sorted order, which the author argues is a simpler and equally valid approach. The corresponding test case that verified the old size-sorted behavior is removed as it's no longer relevant.

The change appears well-justified and cleanly implemented, with a minor wording clarification suggested in the commit message. This is the first patch in a two-part series addressing cruft pack handling, with the second patch focusing on object freshening behavior in multi-cruft pack scenarios. The simplification here was discovered while investigating the core issue addressed in patch 2.
