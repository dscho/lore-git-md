This is a follow-up in the thread about upload-pack's handling of hidden refs, where SURA responds to Patrick Steinhardt's request for more context about their proposed change. The patch had removed an optimization that filtered hidden refs early during reference iteration, which Patrick noted was important for performance in large repositories.

SURA now provides the missing motivation: they observed inconsistent behavior where `transfer.hideRefs` treats packed and loose refs differently (prefix matching vs full matching), causing clients to see different refs before and after a server-side `git gc`. They reference an older commit (59c35fa) that appears to have introduced this inconsistency while optimizing `git for-each-ref`.

The response suggests SURA believes the optimization is fundamentally flawed and that reverting the original commit might be necessary, though they don't propose a specific solution yet. The thread now has clearer technical context about the behavior discrepancy that motivated the change, though the performance implications Patrick raised remain unaddressed. This appears to require deeper discussion about whether to prioritize correctness (consistent ref visibility) or performance (the current optimization).
