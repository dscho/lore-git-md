Feature enhancement for `git fsck` packed-refs validation, specifically adding header format checking. This is part of an ongoing series (now at v8) to strengthen validation of packed-refs files.

The patch introduces two new fsck checks for packed-refs headers: `badPackedRefHeader` for malformed headers (not matching the exact "# pack-refs with: " prefix) and `packedRefEntryNotTerminated` for lines missing newline terminators. The implementation carefully follows the runtime behavior of Git's packed-refs handling - it only enforces the header prefix check while allowing older headerless files and ignoring unknown traits (like "foo" in the header line).

Key technical details:
- Adds new fsck message IDs in `Documentation/fsck-msgids.adoc` and `fsck.h`
- Implements `packed_fsck_ref_next_line()` helper to check line termination
- Adds `packed_fsck_ref_header()` to validate the header prefix
- Updates `packed_fsck()` to read and validate the packed-refs content
- Includes comprehensive tests in `t/t0602-reffiles-fsck.sh` covering:
  - Various malformed header cases
  - Headerless files (allowed for backward compatibility)
  - Files with unknown traits (allowed for forward compatibility)

The patch maintains the series' pattern of focused, well-tested changes while addressing a specific validation gap. The implementation appears thorough, with careful consideration of backward compatibility and real-world usage patterns. The tests provide good coverage of both error cases and allowed variations.
