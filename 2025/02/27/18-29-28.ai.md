This is a refactoring patch that simplifies cruft pack aggregation logic in `builtin/repack.c`. It's the first of a two-patch series addressing object freshening behavior in multi-cruft pack scenarios.

The patch replaces a more complex implementation for combining small cruft packs under `--max-cruft-size` with a simpler approach. The original code tried to aggregate packs while keeping their combined size under the threshold, maintaining a running total and sorting packs by size. The new version simply combines all cruft packs smaller than the threshold individually, letting `pack-objects` handle splitting the result if needed.

This change results in a minor behavioral difference - instead of combining packs first to stay under the size limit, it now opportunistically combines all eligible small packs. The author notes this makes a specific test case (which verified the old size-based aggregation order) no longer relevant, so that test is removed along with the now-unused sorting logic.

The changes are focused in `builtin/repack.c` with corresponding test updates in `t/t7704-repack-cruft.sh`. While this is primarily a code simplification, it was discovered while investigating the core issue addressed in patch 2 of the series. The implementation appears clean and well-justified, with the behavioral change being an acceptable tradeoff for the code simplification.
