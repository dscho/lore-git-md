This is a refactoring patch in a series about cruft pack handling during repacks. Elijah Newren is reviewing Taylor Blau's simplification of how small cruft packs are aggregated when using `--max-cruft-size`.

The patch replaces a complex size-based aggregation algorithm (which would combine packs in sorted order until reaching the size limit) with a simpler approach that just combines all packs smaller than the threshold in one go. This results in deleting 38 lines of sorting and tracking code from `builtin/repack.c` and removing a now-irrelevant test case that verified the old sorting behavior.

Newren approves the change overall, noting the code deletion is a clear win, but points out one potentially misleading phrase in the commit message that could be clarified. The behavioral change is minor - packs will now be combined more opportunistically rather than in strict size order - but this doesn't affect correctness. The patch maintains all other existing functionality while significantly simplifying the implementation.
