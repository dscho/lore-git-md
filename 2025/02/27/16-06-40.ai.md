This is a bugfix patch in the ongoing `git fsck` packed-refs validation series, specifically addressing header format enforcement. The patch tightens the validation of packed-refs file headers to require exactly one space after "# pack-refs with:" to match Git's actual writing behavior and third-party library expectations.

The change modifies `refs/packed-backend.c` to enforce that packed-refs headers must include the trailing space that Git always writes in practice. The author investigated several major Git implementations (libgit2, JGit, gitoxide, go-git) and found they either expect or are compatible with this stricter format. The patch prevents potential compatibility issues where malformed headers might slip through validation.

This is part of the larger series systematically strengthening packed-refs validation, following previous patches that added filetype checking and worktree handling fixes. The change is small but important for consistency, with clear justification based on real-world implementation behavior. The patch maintains the series' pattern of thorough research and careful consideration of compatibility impacts.
