This is part 8/9 of a bugfix and validation series for `git fsck`'s packed-refs handling, specifically adding sorting verification when the "sorted" trait is present in the packed-refs header.

The patch implements sorting validation for packed-refs files that declare themselves as sorted in their header. It introduces a new fsck error message "packedRefUnsorted" and adds comprehensive tests. The implementation avoids memory bloat by re-parsing the file to check ordering rather than storing all refnames, and reuses existing comparison logic by factoring out a new `cmp_packed_refname` helper.

Key aspects:
- Only validates sorting when the header explicitly includes "sorted"
- Handles both regular refs and peeled tags correctly
- Includes extensive test cases covering sorted/unsorted scenarios
- Maintains backward compatibility with unsorted packed-refs files

This continues the series' methodical approach to packed-refs validation, now covering one of the last major verification gaps. The patch appears well-constructed with thorough test coverage and careful attention to edge cases. As with previous patches in the series, it awaits reviewer feedback.
