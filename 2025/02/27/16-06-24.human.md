Bugfix and validation enhancement for packed-refs filetype checking in `git fsck`. This is part 3 of a 9-part series improving packed-refs validation.

The patch adds filetype verification for the packed-refs file, ensuring it's a regular file (not a symlink or directory) when checked by `git fsck` or the packed-refs backend. The author notes that while existing checks validate content, the filetype itself was never been verified. The implementation uses `open_nofollow()` to safely check for symlinks and `fstat()` to confirm regular file status, reusing the existing `FSCK_MSG_BAD_REF_FILETYPE` error message for consistency.

The change includes comprehensive tests that verify the behavior when packed-refs is replaced with a symlink or directory. The implementation appears careful about edge cases - it properly handles missing files (ENOENT) and uses appropriate error handling. The patch builds on previous work in the series that modernized test infrastructure and fixed worktree interaction issues.
