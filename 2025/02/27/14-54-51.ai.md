Refactoring of upload-pack's hidden ref handling with performance concerns raised.

Patrick Steinhardt responds to SURA's patch that removes conditional exclude pattern setup in upload-pack's namespaced ref iteration. The original patch simplified the logic by always passing NULL for exclude patterns to `refs_for_each_namespaced_ref()`, letting the refs backend handle visibility. However, Patrick points out this change removes an important performance optimization for large repositories where excluding hidden refs early avoids unnecessary work. He requests the patch author provide context about what problem this solves and why removing the optimization is justified, as the current commit message lacks this rationale.

Key technical details: The change affects how upload-pack processes `transfer.hideRefs` configuration during reference iteration. The original code conditionally set exclude patterns based on `allow_hidden_refs()`, while the patch unconditionally passes NULL. The performance impact stems from potentially iterating over hidden refs that could have been filtered out earlier. This touches core reference handling in upload-pack.c, specifically around the interaction between `for_each_namespaced_ref_1()` and the refs backend's visibility logic. The thread now awaits clarification from the original author about the motivation and whether alternative solutions could preserve the optimization while addressing their concern.
