Junio Hamano responds to Brian Carlson's suggestion about human-readable config output with control character escaping. This is part of the ongoing discussion about backspace (`\b`) handling in Git's output.

Hamano explores whether `isatty(1)` could reliably detect when Git output is going directly to a terminal (human-readable context) versus being captured for programmatic use. If this detection works, Git could automatically apply escaping or redaction of control characters in terminal output while keeping raw output for scripts.

The email suggests two possible output formats for human-readable mode: C-style escaping (like `\010` for consistency with Git's existing conventions, or simpler `?` substitution that loses some information but ensures terminal safety. This builds on Carlson's earlier proposal while considering implementation feasibility.

The discussion continues to balance the needs of machine-readable output (important for tools like Git LFS) against human readability and terminal safety concerns. Hamano's response indicates openness to Carlson's suggestion but seeks to validate the technical approach before implementation.
