Bugfix and compatibility patch for packed-refs header validation in Git's refs backend.

This patch tightens the validation of packed-refs file headers to require exactly one space after "# pack-refs with:" when reading the file. While Git has always written headers this way, the validation check in `create_snapshot()` was previously more lenient, missing the trailing space. The author investigated several third-party Git implementations (libgit2, JGit, gitoxide, and go-git) and found most expect this formatting, making this change important for compatibility.

The change is minimal - just adding a space to the string comparison in `refs/packed-backend.c`. The commit message provides thorough justification by surveying how other implementations handle this case, showing this aligns with existing practice while preventing potential compatibility issues. This is part of a larger series (v8 4/9) improving packed-refs validation, with previous patches having established test infrastructure and fixed related issues.

The patch appears well-researched and low-risk, maintaining consistency with how Git already writes these files while better matching expectations of other implementations. It continues the series' pattern of careful, incremental improvements to packed-refs handling.
