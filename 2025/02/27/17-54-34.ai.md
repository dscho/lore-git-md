This is a refactoring patch that's part of the ongoing effort to handle repository-less cases more gracefully in Git. The change modifies `repo_config()` to accept NULL repository pointer by falling back to `read_very_early_config()`, which reads only system and global configurations. This makes the function more flexible when commands are run outside any repository context.

The patch is small (7 lines added across config.c and config.h) but touches core configuration machinery. It follows a suggestion from Junio Hamano and has mentoring from Christian Couder, suggesting it's part of a guided effort. The implementation is straightforward - when `repo` is NULL, it bypasses the repository-specific config lookup entirely. The header comment is updated to document this new behavior.

Key technical details for future reference: The change affects the config reading path when no repository is present, specifically making `repo_config()` work like `git_config()` in repository-less contexts. It uses the existing `read_very_early_config()` infrastructure rather than introducing new mechanisms. The patch maintains all existing behavior when `repo` is non-NULL.

This appears to be a well-scoped, focused change that aligns with Git's ongoing efforts to reduce assumptions about always having a repository context. The change is small enough that it's unlikely to introduce subtle bugs, though reviewers might want to verify there aren't any callers that currently depend on the NULL case failing.
