This is a follow-up discussion about test output handling in the `git-diff-pairs` series, which introduces a new plumbing command for batch blob diff generation.

Justin Tobler responds to Phillip Wood's suggestion about improving test output readability by replacing NUL bytes in test comparisons. Phillip had proposed using `tr` to convert NULs to 'Q' or newlines, but noted this wouldn't significantly improve readability of the raw diffs.

Justin expresses a preference for keeping the tests validating the actual NUL-delimited output as-is, suggesting that while the binary comparison output ("Binary files expect and actual differ") isn't particularly readable, it accurately reflects the command's real behavior. He's open to adapting the approach if the maintainers prefer Phillip's suggestion, but questions whether the readability tradeoff is worth deviating from testing the exact output format.
