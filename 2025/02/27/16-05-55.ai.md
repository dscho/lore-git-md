This is the first patch in a 9-part series that refactors and enhances `git fsck`'s packed-refs validation. The patch focuses on test modernization, specifically ensuring working directory consistency in the test suite.

The patch converts all test cases in `t/t0602-reffiles-fsck.sh` to use subshells when changing directories, rather than relying on explicit `cd` commands. This ensures the working directory is properly restored even if a test fails mid-execution. The change is purely mechanical - it wraps all test blocks in `( cd repo && ... )` subshells while preserving all existing test logic and assertions.

The test file contains extensive validation checks for ref names and content, including:
- Invalid ref name formats (leading dots, tildes, spaces)
- Malformed ref content (invalid hashes, missing newlines, trailing garbage)
- Symref validation (both textual and symbolic link forms)
- Worktree-specific ref handling
- Various error and warning message formats

This is part of a larger effort to strengthen `git fsck`'s validation of packed refs, with subsequent patches adding new checks for NUL characters, header format enforcement, and sorting verification. The test changes here provide a solid foundation for those enhancements while improving test reliability through proper working directory management.

Key technical details:
- Affects only test file `t/t0602-reffiles-fsck.sh`
- Maintains all existing test assertions and error/warning messages
- Uses subshells to isolate directory changes
- Preserves test coverage for ref validation edge cases
- Part of multi-patch series (1/9) with cover letter providing context
