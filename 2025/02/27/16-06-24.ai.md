This is a bugfix and validation enhancement for the packed-refs backend, part of a larger series improving `git fsck` validation. The patch adds filetype checking for the packed-refs file to ensure it's a regular file (not a symlink or directory) when being verified.

The change introduces explicit validation that packed-refs is a regular file, using `open_nofollow()` to safely check symlinks and `fstat()` to verify the file type. It reuses the existing `FSCK_MSG_BAD_REF_FILETYPE` error message for consistency. The implementation handles three cases: missing files (allowed), symlinks (error), and non-regular files (error).

The patch includes comprehensive tests that verify the behavior with both symlinked and directory-packed-refs cases, ensuring the proper error messages are shown. This builds on the test infrastructure established in earlier patches of the series, maintaining the subshell isolation approach.

This is a focused but important validation that plugs a hole in the packed-refs verification - while previous checks validated content, they didn't verify the container file was of the expected type. The change is well-contained, with clear error reporting and thorough test coverage of the new behavior.
