This is the final patch in a series (v8 9/9) integrating packed-refs validation into `git fsck`, completing the feature implementation.

The patch adds a `--[no-]references` option to `git fsck` that controls whether to perform reference database consistency checks via a new `git refs verify` child process. The implementation:

1. Introduces a `fsck_refs()` function that spawns `git refs verify` with appropriate verbosity and strictness flags matching the parent fsck process
2. Adds progress reporting (currently showing 1/1 task since loose ref counting isn't implemented yet)
3. Places the reference check early in fsck execution to fail fast before other operations
4. Includes comprehensive tests verifying the new option works with both loose and packed ref validation
5. Maintains backward compatibility by defaulting to checking references

Key technical details:
- New configurable: `check_references` flag in fsck
- Child process integration via `struct child_process`
- Progress reporting through existing Git progress API
- Test coverage for:
  - Trailing garbage detection in loose refs
  - Option toggling behavior (`--references`/`--no-references`)
  - Error message propagation

The patch completes the series' goal of bringing systematic packed-refs validation into core Git operations while maintaining the careful backward compatibility and thorough testing seen throughout the series. With this final integration point, users can now validate their reference databases alongside other fsck checks.
