Documentation patch clarifying submodule merge behavior. This is v4 of a patch that adds documentation about Git's special handling of submodule conflicts during merges. The patch describes two cases: when one submodule commit is a descendant of the other (triggering a fast-forward attempt), and when there exists a common descendant that can be suggested as a resolution. The text is added to both the 'ort' and 'recursive' strategy sections, noting they handle submodules the same way. The change references commit 68d03e4a6e44 which introduced this behavior. The patch has been reviewed by Junio Hamano and Elijah Newren, and this version only removes an extra blank line from v3. The documentation explains behavior that was previously only visible in the merge-ort and merge-recursive source code, making it more accessible to users who encounter submodule conflicts. The patch touches only Documentation/merge-strategies.adoc, adding about 10 lines of explanatory text. The content appears technically accurate and well-integrated with the existing documentation structure.
