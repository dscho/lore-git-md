Refactoring and bugfix for `git fsck` packed-refs validation. This is part 5/9 in a series improving validation of packed-refs files, now focusing on header format checking.

The patch adds strict validation for the "# pack-refs with: " header line in packed-refs files. It will now error if the header exists but doesn't exactly match the expected format (case 2 in the analysis), while remaining silent for missing headers (case 1) or unknown traits (case 3) to maintain backward compatibility. The implementation introduces two new fsck error messages - `badPackedRefHeader` for malformed headers and `packedRefEntryNotTerminated` for lines missing newlines.

The changes are well-considered, with the author demonstrating awareness of backward compatibility needs and real-world usage patterns. The patch includes comprehensive tests covering all three cases analyzed, showing the validation behaves correctly for both valid and invalid headers. This continues the series' pattern of focused, well-tested improvements to packed-refs validation.

The implementation follows the established pattern in the series, using `open_nofollow` for safe file access and building on the fsck reporting infrastructure. The changes are localized to `packed-backend.c` with corresponding documentation and test updates.
