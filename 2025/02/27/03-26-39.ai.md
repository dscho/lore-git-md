Documentation patch finalizing the submodule merge behavior explanation for both 'ort' and 'recursive' strategies. This v4 iteration removes a single blank line from v3, representing the final form of the patch after review by both the Git maintainer (Junio Hamano) and merge strategy expert (Elijah Newren).

The patch documents two specific submodule conflict resolution behaviors that were previously only visible in the merge-ort and merge-recursive source code (introduced in commit 68d03e4a6e44). First, when one submodule commit is a descendant of another, Git attempts a fast-forward. Second, when there exists a common descendant of the conflicting submodule commits, Git suggests it as a resolution while still marking the conflict as unmerged for user confirmation.

The documentation addition appears in parallel sections for both merge strategies, with the 'recursive' section getting a shorter note referencing the more detailed explanation in the 'ort' section. The patch maintains consistency between the documentation of these two strategies while accurately reflecting their identical handling of submodule conflicts.

With positive reviews from both key domain experts and no outstanding requested changes, this patch appears ready for inclusion in the Git documentation. The change is purely additive and does not modify any actual merge behavior, only making existing functionality more discoverable to users.
