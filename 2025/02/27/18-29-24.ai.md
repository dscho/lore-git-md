This is a cover letter for a bugfix series addressing an issue with multi-cruft packs. The two-patch series corrects how Git handles object freshening when repacking with multiple cruft packs.

The first patch simplifies cruft pack aggregation logic in `builtin/repack.c`, removing some redundant checks when combining small cruft packs under the `--max-cruft-size` threshold. While this changes behavior slightly, the author notes it's not functionally significant and was discovered while working on the main fix.

The core issue, addressed in the second patch, involves objects that are unreachable but exist in retained cruft packs with freshened mtimes. Previously, `want_found_object()` would discard any object appearing in a surviving pack regardless of mtime. The new logic preserves objects when they appear in cruft packs only if their mtime is older than the version being packed, while still always keeping objects from non-cruft packs. This affects `builtin/pack-objects.c`'s handling of object retention during repacks where some cruft packs remain.

The changes are accompanied by extensive test updates in `t/t7704-repack-cruft.sh` covering various edge cases. The author acknowledges the mental complexity of the fix and requests review to confirm the approach, particularly around the mtime comparison logic for cruft pack objects. The series touches core packing functionality but appears focused and well-tested, with changes concentrated in the packing subsystem's object retention rules.
