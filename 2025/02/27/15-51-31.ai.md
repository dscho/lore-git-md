This is a follow-up in the thread about upload-pack's handling of hidden refs during namespaced reference iteration. SURA responds to Patrick Steinhardt's performance concerns by providing the missing motivation for their earlier patch that removed hidden refs exclude patterns.

The key new information is that SURA observed inconsistent behavior between packed and loose refs when using `transfer.hideRefs` - packed refs use front matching while loose refs use full matching, causing clients to see different refs before and after a server-side GC. They trace this to commit 59c35fa which optimized `git for-each-ref` but apparently broke upload-pack's behavior. SURA suggests the only solution may be to roll back that commit.

This email provides the crucial context that was missing from the original patch, explaining the actual problem being addressed (inconsistent ref visibility after GC) and its origin (a side effect of the 59c35fa optimization). The discussion now has clearer technical grounding, though the performance implications Patrick raised about removing the exclude patterns optimization remain unresolved. The thread appears to be at a point where participants must weigh the correctness fix against the performance impact.
