This is part 8/9 of a bugfix and validation enhancement series for `git fsck`'s packed-refs checking. The patch adds sorting verification for packed-refs files that declare themselves as sorted in their header.

The key technical additions are:
- Extracts the refname comparison logic from `cmp_packed_ref_records()` into a new `cmp_packed_refname()` helper for reuse
- Modifies `packed_fsck_ref_header()` to detect the "sorted" trait in packed-refs headers
- Adds a new `packed_fsck_ref_sorted()` function that performs a second pass through the file to verify sorting when the header claims it
- Introduces a new `packedRefUnsorted` fsck error message
- Includes comprehensive tests showing:
  - Detection of unsorted refs when "sorted" trait is present
  - Proper handling of peeled tags during sorting checks
  - No false positives when "sorted" trait is absent

The implementation avoids memory bloat by doing the sorting check in a second pass rather than storing all refnames. It maintains compatibility with existing packed-refs files while enforcing stricter validation for those declaring themselves sorted. The patch continues the series' pattern of thorough test coverage and careful backward compatibility.
