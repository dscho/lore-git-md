This is a documentation patch (v4) clarifying submodule merge behavior in Git's merge strategies. The patch adds explicit documentation for two special cases of submodule conflict resolution that were previously only visible in the merge-ort and merge-recursive source code.

The documentation now explains that when merging submodules: 1) Git will attempt a fast-forward if one commit is a descendant of the other, and 2) when conflicts occur, Git may suggest a common descendant commit as a resolution while still marking it as unmerged for user confirmation. The same behavior is noted for both the modern 'ort' strategy and legacy 'recursive' strategy.

This final version of the patch series has already received positive reviews from both the Git maintainer (Junio Hamano) and merge strategy expert (Elijah Newren). The only change from v3 is the removal of an extra blank line, indicating the series is now in its final polished form. The patch provides valuable documentation for users encountering submodule merge conflicts, making existing behavior more discoverable without changing any actual merge functionality.
