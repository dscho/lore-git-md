This is the final patch in a series (v8 9/9) that enhances `git fsck` with comprehensive packed-refs validation. The patch adds integration with the new `git refs verify` command to check reference database consistency.

The patch introduces a `--[no-]references` option to `git fsck` that controls whether to perform these reference checks (enabled by default). It implements this by spawning a child process to run `git refs verify`, with progress reporting and proper error handling. The implementation maintains backward compatibility while adding the new validation layer.

The changes include:
- Documentation updates for the new option
- Core implementation in builtin/fsck.c
- Tests verifying the option's behavior with various malformed refs

This completes the series' goal of strengthening reference validation, building on previous patches that added checks for NUL characters, header formats, sorting, and other consistency issues. The implementation appears thorough, with careful attention to user interface (progress reporting) and backward compatibility. The test coverage is extensive, exercising both the positive and negative cases for the new option.
