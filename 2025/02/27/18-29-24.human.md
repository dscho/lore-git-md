This is a bugfix series addressing an issue with object freshening in multi-cruft pack scenarios. Taylor Blau identifies and fixes a subtle edge case that occurs when using `git repack --max-cruft-size` where unreachable objects in retained cruft packs weren't properly respecting mtime freshening.

The first patch simplifies cruft pack aggregation logic in `repack.c`, which Taylor notes was a preparatory cleanup that became apparent while working on the main fix. The second patch is the substantive change, modifying `pack-objects.c` to properly handle object freshening when some cruft packs are being retained. The new logic ensures objects are only discarded from the new pack if they exist in either a surviving non-cruft pack or a cruft pack with an older mtime.

Taylor acknowledges the mental complexity of the fix and expresses confidence in the test coverage while inviting review. The changes touch core packing logic and come with significant test updates, suggesting this could benefit from careful scrutiny from packing experts. The patch appears well-motivated by real-world usage at GitHub and thoughtfully addresses a subtle edge case in the relatively new multi-cruft pack feature.
