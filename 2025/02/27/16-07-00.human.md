Bugfix patch for packed-refs validation in `git fsck`, part of an ongoing series to strengthen ref storage integrity checks.

This patch addresses a specific corruption case in packed-refs files where embedded NUL characters in refnames could bypass validation. The issue was reported by R. Diez, who found that while `check_refname_format()` validates refnames, it could be fooled by NUL bytes that truncate the apparent refname while leaving a valid prefix. The patch adds a new `refname_contains_nul()` helper that scans for embedded NULs before validation.

The change is well-contained, adding about 20 lines to `packed-backend.c` with clear documentation explaining the edge case. It maintains the existing behavior of terminating with an error when corruption is detected, which is appropriate for this low-level storage validation. The patch fits naturally into the broader series' goal of systematic packed-refs validation, though it focuses specifically on-disk format rather than the fsck integration seen in earlier patches.

This appears to be a robust solution to a real-world corruption case, with good test coverage implied by the series context (though no new tests are added in this specific patch). The implementation is straightforward and unlikely to be controversial, continuing the series' pattern of careful, incremental improvements to ref storage safety.
