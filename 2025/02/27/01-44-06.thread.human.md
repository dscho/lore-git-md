This thread documents Git's behavior when resolving submodule conflicts during merges, specifically for the 'ort' and 'recursive' strategies. The patch series, now in its fourth iteration, clarifies two scenarios: when Git attempts a fast-forward if one submodule commit is a descendant of another, and when it suggests a common descendant as a resolution while still requiring user confirmation. These behaviors were previously only visible in the source code (commit 68d03e4a6e44).

The documentation addition appears in parallel sections for both merge strategies, with the 'recursive' section referencing the more detailed explanation in the 'ort' section. The latest version (v4) removes a single blank line from v3, representing the final form after thorough review. Both Junio Hamano (maintainer) and Elijah Newren (merge strategy expert) have reviewed the patch positively, with no outstanding changes requested. The change is purely additive, making existing functionality more discoverable without modifying any actual merge behavior. With all feedback addressed, this documentation improvement appears ready for inclusion.
