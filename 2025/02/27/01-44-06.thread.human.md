This thread documents Git's behavior when merging conflicting submodule references, a subtle aspect of the merge machinery that was previously explained only in the source code. The patch series, now at v4, adds clear documentation to `merge-strategies.adoc` describing two key scenarios: when one submodule commit is a descendant of the other (triggering an automatic fast-forward attempt) and when Git can suggest a common descendant as a resolution candidate. Both the 'ort' and 'recursive' merge strategies handle submodules identically in this regard, as noted in the documentation.

The patch has received thorough review from both Elijah Newren (the merge strategy expert who implemented this behavior in commit 68d03e4a6e) and maintainer Junio Hamano. The current iteration is nearly identical to v3, with only a minor whitespace adjustment. This documentation will help users understand and resolve submodule conflicts without needing to dig into the merge-ort or merge-recursive implementation details. The change is ready for merging, having addressed all prior feedback.
