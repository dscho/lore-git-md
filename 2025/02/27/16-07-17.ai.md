This is part 7 of a 9-part series strengthening `git fsck` validation of packed-refs files, focusing on entry-level consistency checks.

The patch adds comprehensive validation of individual packed-refs entries, implementing checks that mirror Git's runtime parsing logic. It introduces a new `badPackedRefEntry` fsck message ID and implements three key validations:

1. Main line validation (oid + refname):
   - Verifies the oid is properly formatted
   - Ensures proper whitespace between oid and refname
   - Checks refname format (reusing existing `check_refname_format()`)
   - Detects NUL bytes in refnames (building on previous patch's infrastructure)

2. Peeled line validation (for annotated tags):
   - Verifies the peeled oid format
   - Checks for trailing garbage after the peeled oid

3. Structural validation:
   - Maintains the line-by-line checking from previous patches
   - Handles the alternation between main and peeled lines

The implementation splits these checks into focused helper functions (`packed_fsck_ref_main_line`, `packed_fsck_ref_peeled_line`) called from the main content checker. Error reporting uses the established pattern of including line numbers and specific failure details.

The accompanying test creates a packed-refs file with various malformed entries (invalid oids, missing spaces, bad refnames, garbage in peeled lines) and verifies fsck catches each case with appropriate error messages. The test cases demonstrate both the new checks and integration with existing refname validation.

This continues the series' pattern of methodical, well-tested validation additions while maintaining backward compatibility. The patch appears carefully implemented with thorough test coverage, though reviewers may want to scrutinize the error message wording and whether any edge cases were missed in the test matrix.
