This is a patch in Patrick Steinhardt's series enhancing `git cat-file` with bitmap-accelerated object filtering, specifically addressing the command-line interface design for the new filtering capability.

The patch introduces an `--objects-filter` option to `git cat-file` batch mode, adopting similar filtering syntax to `git rev-list` but with a different option name to avoid confusion with the existing `--filters` flag. The initial implementation simply rejects filter arguments (to be properly implemented in later patches), with the commit message noting that real performance benefits will only come with the bitmap integration planned for subsequent changes.

The patch is part of an active discussion about interface design, where Toon Claes has advocated for using `--filter=` (matching `rev-list`) rather than the proposed `--objects-filter`. The commit message defends the naming choice by citing potential confusion with the existing `--filters` option, though this remains an open discussion point in the thread.

While the patch itself is straightforward plumbing work, it sits at the intersection of several ongoing technical discussions: the core bitmap integration work (awaiting Taylor Blau's input), the CLI naming debate, and the newly raised question about supporting combined filters (LOFC_COMBINE) for future extensibility. The implementation appears clean and well-explained, though its ultimate usefulness depends on the bitmap acceleration work that follows.
