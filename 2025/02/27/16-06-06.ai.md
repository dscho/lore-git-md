This is a bugfix patch in the ongoing `git fsck` packed-refs validation series. It addresses an issue where `git refs verify` and `git fsck` could prematurely die when checking packed-refs files due to HEAD parsing.

The patch introduces `get_worktrees_without_reading_head()` to avoid triggering packed-refs validation when getting worktree information. The core problem occurs because existing `get_worktrees()` would parse HEAD references, which for packed refs would invoke strict validation checks in `packed-backend.c` that could die on malformed files. The new function builds on previous work (465a22b338) that added internal infrastructure to skip HEAD reading.

Key technical changes:
- Adds new public API `get_worktrees_without_reading_head()` in worktree.[ch]
- Modifies `builtin/refs.c` to use this when verifying refs
- Preserves all existing functionality while avoiding the packed-refs validation trap
- Maintains the same worktree iteration behavior but skips HEAD parsing

This is patch 2/9 in the series, following the test infrastructure improvements from patch 1. It addresses a concrete issue that would interfere with the planned packed-refs validation enhancements, ensuring the verification commands can complete their checks even when encountering malformed files. The change is narrowly scoped and builds logically on existing worktree infrastructure.
