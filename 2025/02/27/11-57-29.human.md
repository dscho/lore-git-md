This is a follow-up discussion in the performance optimization series for the refs subsystem, specifically addressing the behavior of `git-update-ref`'s object ID parsing. 

Patrick Steinhardt responds to Junio Hamano's clarification about `git-update-ref` accepting extended SHA-1 expressions (like "~" and "^2") and references, despite the manpage not documenting this capability. Junio confirmed this was the original 2005 design intent, though the documentation could be clearer about what input formats are accepted.

Patrick acknowledges the behavior is intentional but notes the documentation gap could confuse users who only see the manpage's reference to "oid" (which implies full hexadecimal object names). He agrees documentation improvements would be valuable but suggests handling them separately from the current performance optimization series, marking it as a #leftoverbits item for future work.

The exchange doesn't change the technical approach of the series (which includes suppressing ambiguity warnings for this plumbing command) but highlights an orthogonal documentation issue to address later. The thread remains focused on finalizing the performance optimizations while identifying this as a minor but separate documentation cleanup task.
