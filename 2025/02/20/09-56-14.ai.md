Performance optimization for reference backend migrations with finalized UX decisions.

This is Karthik Nayak's v4 patch implementing the `--no-reflog` flag for `git refs migrate`, following the thread's consensus to rename it from `--skip-reflog` to better clarity about its destructive nature. The patch allows skipping reflog migration when moving between reference backends, which is particularly useful for server-side repositories where reflogs are typically unwanted. The implementation adds a new `REPO_MIGRATE_REF_STORAGE_FORMAT_SKIP_REFLOG` flag, modifies the migration logic in `refs.c` to conditionally skip reflog processing, and includes comprehensive tests in `t/t1460-refs-migrate.sh`.

Key technical details:
- The flag name change to `--no-reflog` (from `--skip-reflog`) was approved by Junio as more accurately conveying the operation's destructive nature
- When used, the flag causes all existing reflogs to be permanently dropped during migration
- Tests verify both the preservation of reflogs by default and their removal when the flag is specified
- The implementation touches `builtin/refs.c` (CLI), `refs.c` (migration logic), `refs.h` (flag definition), and test files

While the patch is technically complete and has received positive feedback, Junio has indicated a preference for implementing a general `git reflog drop` command first before merging this optimization. The thread has reached consensus on all technical and UX aspects, with the implementation now being deferred pending that prerequisite work. Karthik has committed to working on the reflog deletion functionality after completing current work on partial transactions.
