Performance issue report regarding `git bisect` initialization time.

Uwe Kleine-König reports unexpectedly long execution times (18+ minutes on an SSD system, nearly an hour on HDD) for the initial step of `git bisect` in a large kernel repository (572k revisions). The report includes specific hardware configurations and Git version (2.47.1), comparing against past experiences where this step was faster. The email questions whether this is a regression or if the expectation is incorrect, but provides no specific reproduction steps beyond the basic bisect command shown.

The report focuses on the initial revision selection phase before any testing begins, suggesting this may be related to commit graph traversal or working directory operations rather than the test phase itself. No analysis of potential causes is provided, leaving this as an open question for maintainers to investigate whether this represents normal behavior for large histories or a genuine performance regression.
