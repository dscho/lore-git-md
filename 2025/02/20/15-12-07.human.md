This is a documentation patch that describes Git's special handling of submodule merge conflicts. Lucas Seiki Oshiro adds clear explanations of two submodule merge behaviors to the `merge-strategies.adoc` file, covering both the modern `ort` and legacy `recursive` strategies.

The patch documents two special cases that were introduced in commit 68d03e4a6e44: (1) when one submodule commit is a descendant of another, Git will fast-forward; (2) when there's a merge commit that contains both conflicting submodule commits, Git suggests it as a resolution while still marking it as unmerged for user confirmation. The documentation is added to both strategy sections since the behavior applies to both.

This is version 2 of the patch, which moves the documentation from `git-merge.adoc` to the more appropriate `merge-strategies.adoc` and incorporates feedback to improve clarity. The change is straightforward and well-motivated, filling a gap in the documentation about submodule merge behavior that was previously only visible in the source code.
