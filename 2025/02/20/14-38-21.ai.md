Refactoring patch in a test modernization series, with reviewer feedback.

Phillip Wood responds to Seyi Kuforiji's patch that moves oid helper functions from lib-oid.{c,h} to unit-tests.{c,h} as part of converting oid-related tests to the Clar framework. While supporting the overall test modernization effort, Phillip raises a technical concern about the implementation approach. He notes that placing these oid-specific functions in the shared unit-tests.{c,h} would force all unit tests to link against strbuf.o and hex.o dependencies, even when they don't need oid functionality. Instead, he suggests keeping the functions in lib-oid.c temporarily and removing them when no longer needed.

The patch in question (1/5 in the series) implements `get_oid_arbitrary_hex()` and `init_hash_algo()` in the shared unit-test infrastructure, which would be used by subsequent patches converting oid-array, oidmap, and oidtree tests. Phillip's feedback indicates this architectural decision may need reconsideration to avoid unnecessary dependencies in the test framework. The discussion highlights the balance between code deduplication and minimizing dependencies in test infrastructure modernization.
