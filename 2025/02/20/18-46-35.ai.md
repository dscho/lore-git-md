This is a documentation patch clarifying submodule merge conflict handling, now in its second version. The patch documents two special cases of submodule conflict resolution that were previously only visible in the source code (merge-ort.c and merge-recursive.c), both implementing behavior introduced in commit 68d03e4a6e44. The documentation explains that Git will attempt a fast-forward when one submodule commit is a descendant of the other, and when they have a common descendant, will suggest that as a resolution while still marking it as unmerged for user confirmation.

D. Ben Knoble reviews the v2 patch, acknowledging its improved clarity over v1, but raises a concern about the duplicated documentation text between the 'ort' and 'recursive' strategy sections. The identical explanatory paragraph appears in both sections since both strategies share this behavior. Knoble suggests exploring ways to avoid this duplication, either through text reuse or cross-referencing between the sections.

The patch appears technically sound and well-motivated, with no substantive objections raised in the thread. The remaining discussion point is purely about documentation organization rather than the content itself.
