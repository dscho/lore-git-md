Implementation refinement for the `git diff-pairs` plumbing command. Justin Tobler proposes tightening the behavior around tree objects in the input stream for this new diff-generation tool.

The discussion has settled on keeping the initial implementation simple, with tree objects passed through unexpanded (as established in previous design decisions). Justin now suggests going a step further - rather than silently passing through tree objects or omitting them from patch output, the command should explicitly fail when encountering any tree object in its input. This conservative approach would:

1. Make the behavior more predictable and explicit
2. Prevent any ambiguity in output when tree objects are present
3. Reserve space for a future `-r` expansion option without worrying about backwards compatibility
4. Align with the "simple backend" design principle that's emerged in the thread

This change would affect patch 2/3 in the series, which implements the core `diff-pairs` command. The proposal appears well-considered, building on the established design direction while adding an extra guardrail. It maintains the command's positioning as a focused, predictable plumbing component that leaves more complex operations (like tree expansion) to frontends.
