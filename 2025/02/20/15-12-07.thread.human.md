Lucas Seiki Oshiro submitted a patch (now at v2) that adds explanatory text to both the 'ort' and 'recursive' merge strategy documentation, describing two special cases of submodule conflict resolution that were implemented in commit 68d03e4a6e44 but never properly documented.

The documentation explains that when merging submodules, Git will attempt to resolve conflicts in two specific ways: first by checking if one commit is a descendant of the other (allowing a fast-forward), and second by looking for a common descendant of the two conflicting commits. Elijah Newren provided feedback on the initial version, leading to improved clarity in v2 and moving the documentation to a more appropriate location in merge-strategies.adoc.

The patch fills a clear documentation gap by making this behavior visible to users who encounter submodule conflicts, rather than leaving it buried in the implementation code. The change is straightforward and uncontroversial, with the identical text in both strategy sections reflecting that this behavior is shared between the ort and recursive implementations.
