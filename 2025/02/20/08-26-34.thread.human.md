The thread began with a bug report about `git clone --shallow-exclude` failing in Git 2.45.2 with two different error cases - one when excluding by branch name ("no commits selected") and another when excluding by commit hash ("ambiguous deepen-not"). The reporter provided clear reproduction steps but no analysis of the root causes.

Elijah Newren has now responded with important clarifications. He explains that these are actually two separate situations with different expected behaviors. The branch name case is working as designed - the "no commits selected" error is intentional when excluding a branch that doesn't meet certain criteria. However, the commit hash case was indeed a bug that's since been fixed in Git 2.48, both in the error messaging (commit 5a875ff7fbd) and documentation (00e10e07510).

The key takeaway is that one case was user error (with appropriate feedback) while the other was a genuine bug that's already addressed in newer releases. Users experiencing these issues should upgrade to Git 2.48 or later rather than expecting fixes to be backported to the 2.45.x releases. No further action is needed from the reporter since the problems have been properly categorized and resolved in current versions.
