Test modernization patch in ongoing oid test conversion series, with review feedback about debug information loss.

This is the second patch in Seyi Kuforiji's 5-part series converting Git's oid-related tests (oid-array, oidmap, oidtree) from custom test framework to Clar. The patch specifically handles the oid-array test conversion, moving test data to global scope and using Clar assertions.

Phillip Wood acknowledges the technical correctness of the conversion but raises concerns about degraded debugging experience. The main issue is that replacing custom test assertions with basic Clar assertions (`cl_assert`) loses valuable failure context - when an OID comparison fails, the test output won't show which OIDs mismatched or at what index. Similar debugging information loss occurs in the bounds checking assertions.

The patch also duplicates some hash algorithm initialization that Phillip notes is already handled by `init_hash_algo()` in unit-test.c. The conversion otherwise follows the established pattern of moving test data to file scope and splitting test cases into separate Clar test functions.

This continues the thread's key discussion about balancing test modernization with maintainability - while the conversion is mechanically sound, Phillip's feedback suggests the series may need to either enhance Clar's assertion capabilities or preserve more debugging context during the transition. The author will need to address whether to modify this patch or handle the debugging improvements separately.
