Performance optimization follow-up addressing a missed conversion in the refs subsystem.

This is a brief response from Patrick Steinhardt to Justin Tobler's review of patch 3/16 in the performance optimization series for refs. The original patch converted most `repo_get_oid()` calls in `builtin/update-ref.c` to use the new `repo_get_oid_with_flags()` API with `GET_OID_SKIP_AMBIGUITY_CHECK` flag, but missed one instance in `parse_cmd_symref_update()`. 

Patrick confirms this was an oversight and indicates the conversion should be made there as well, though the actual fix isn't shown in this email. This relates to the series' broader goal of optimizing refname availability checks by skipping unnecessary ambiguity checks during ref updates. The thread context shows this is part of a completed v2 series that achieved measurable performance improvements (1.19x-2.32x speedups in ref creation benchmarks), with this being minor post-merge cleanup.
