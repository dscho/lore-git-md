Git bisect performance investigation thread summary:

Uwe Kleine-König reported severe performance degradation in `git bisect` initialization (18+ minutes SSD/1 hour HDD) with Linux kernel repository (572k revs) on Git 2.47.1. Junio C Hamano has now provided an experimental patch addressing this known bottleneck through three potential optimizations, implementing midpoint merge traversal which shows dramatic improvement (20min→30sec in tests). The patch restructures bisection logic in `bisect.c` to process merges from middle outward rather than commit-list order, while maintaining comparable bisection accuracy (19 vs 17,871 commits from theoretical halfway). Two additional experimental approaches (loosened halfway threshold and early discard) remain commented out but may warrant future exploration.

- Midpoint traversal implemented via array collection and middle-out processing
