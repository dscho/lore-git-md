Performance optimization for reference backend migrations, now with finalized naming. This is Karthik Nayak's v4 patch adding a `--no-reflog` flag to `git refs migrate`, allowing server-side repositories to skip reflog migration (and thus permanently drop existing reflogs) when changing reference storage formats.

The patch has evolved through discussion to use the clearer `--no-reflog` name (rather than the original `--skip-reflog`) to better indicate the destructive nature of the operation. The implementation is straightforward - it adds a flag bit that bypasses the reflog migration step in `repo_migrate_ref_storage_format()`. Test coverage verifies that reflogs are indeed dropped when the flag is used.

While the technical implementation is complete, Junio has indicated a preference for implementing a general `git reflog drop` command first before merging this optimization. Karthik has accepted this sequencing and notes he'll work on the more foundational reflog deletion capability after his current partial transactions work. The patch appears well-crafted with thorough test coverage, but its merging is likely deferred until the prerequisite work is done.
