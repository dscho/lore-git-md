Build system integration follow-up. Ramsay Jones responds to Patrick Steinhardt's Meson build system patch series by noting several static analysis and documentation test targets that are currently missing from the Meson integration. The thread has been focused on adding Meson support for Git's contrib components, with recent work completing credential helper integration and resolving gitk coordination.

Jones specifically points out that the current Meson implementation lacks equivalents for several Makefile targets used in CI pipeline scripts: `coccicheck` (already mentioned in the series), `hdr-check`, `check-pot`, `check-builtins`, `check-docs`, and coverage-related targets. These are part of the static analysis and documentation verification that Jones regularly runs as part of development workflow. The comment suggests these should be considered for inclusion in the Meson build system to maintain parity with the existing Makefile-based infrastructure.

The email doesn't propose specific solutions but serves as a reminder of additional build system functionality that needs to be addressed, particularly for developers who rely on these targets for code quality checks. This comes as the Meson integration work nears completion, with most major contrib components already wired up. The thread context shows this is part of an ongoing effort to unify build systems across platforms while maintaining all existing development workflows.
