This is part 4/9 of a finalized v7 bugfix series enhancing `git fsck`'s packed-refs validation. The patch tightens header format checking in the packed-refs backend to require a space after "# pack-refs with:", aligning with Git's actual output and most third-party implementations' expectations.

The change modifies `create_snapshot()` to explicitly check for the space character that Git has always included in practice. The commit message provides a thorough ecosystem analysis showing this won't break compatibility: libgit2 and gitoxide already expect the space, JGit handles it equivalently through its peeled capability parsing, and go-git doesn't use the header by default. The change prevents potential interoperability issues if Git were to accidentally stop writing the space.

This patch builds on Patrick Steinhardt's earlier review feedback to strengthen the header validation rationale, now framing it as both a compatibility measure and an ecosystem consistency safeguard. The implementation is minimal (a one-character change to the prefix check) but carries significant weight for maintaining cross-implementation consistency of the packed-refs format.

The series as a whole has addressed all reviewer feedback and appears production-ready, with this patch representing one of several security-focused validations being added to packed-refs handling. The change is low-risk given the ecosystem analysis and maintains backward compatibility while preventing format drift.
