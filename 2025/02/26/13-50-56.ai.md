This is part 8/9 in a bugfix series enhancing `git fsck`'s validation of packed-refs files, specifically adding sorting verification when the "sorted" trait is present in the header.

The patch introduces a new check that verifies packed-refs entries are properly sorted when the file header includes the "sorted" trait. It avoids storing all refnames in memory by re-parsing the file to compare adjacent entries, reusing the existing comparison logic through a new `cmp_packed_refname` helper function extracted from `cmp_packed_ref_records`. A new fsck error `packedRefUnsorted` is added to report violations.

Key technical changes:
- Extracts refname comparison logic into new `cmp_packed_refname` function
- Modifies `packed_fsck_ref_header` to detect "sorted" trait
- Adds new `packed_fsck_ref_sorted` function that performs the verification pass
- Introduces new `PACKED_REF_UNSORTED` fsck message ID
- Includes comprehensive tests covering sorted/unsorted cases with various ref types

The implementation follows the series' pattern of adding strict validation while maintaining backward compatibility, here specifically checking sorting only when explicitly requested via the header trait. The approach balances thoroughness with memory efficiency by avoiding storing all refnames.
