Bugfix patch (7/9 in v7 series) implementing packed-refs entry validation for `git fsck`.

This patch ports the existing packed-refs parsing checks from `next_record()` into the new validation framework, adding comprehensive error reporting through `fsck`. It introduces two new helper functions:

1. `packed_fsck_ref_main_line()` validates the main ref line format (oid + refname), checking for:
   - Valid OID format
   - Proper whitespace separation
   - Valid refname format (reusing existing `check_refname_format()`)
   - NUL character detection in refnames (using new `refname_contains_nul()` helper)

2. `packed_fsck_ref_peeled_line()` validates peeled ref lines (those starting with '^'), checking for:
   - Valid peeled OID format
   - Absence of trailing garbage

The patch adds a new `FSCK_MSG_BAD_PACKED_REF_ENTRY` error type and includes extensive test coverage that exercises various malformed packed-refs cases:
- Invalid OIDs
- Missing whitespace
- Trailing garbage
- Invalid refnames
- Malformed peeled refs

This completes the core validation logic for packed-refs files, working in conjunction with the earlier header validation patch. The implementation maintains the same strictness as the runtime parser but adds proper error reporting through the fsck framework. Test cases demonstrate the validation catches all expected error conditions while allowing valid packed-refs files to pass.
