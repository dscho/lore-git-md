This is the final patch in Patrick Steinhardt's Meson build system refactoring series, addressing a CI optimization issue specific to Windows builds.

The patch tackles a practical problem with GitLab's Windows CI runners, which have only 7.5GB of RAM. The Microsoft Visual Studio's linker ("link.exe") is memory-intensive when running with multiple threads, leading to out-of-memory failures. The solution is straightforward - limit concurrent linker jobs to 1 via Meson's `-Dbackend_max_links=1` configuration.

The change is narrowly scoped, only affecting the GitLab CI configuration for MSVC builds, while leaving GitHub Actions untouched (which has more RAM available). This appears to be a well-justified optimization based on observed CI failures, completing the series' goal of build system improvements with a practical fix for real-world infrastructure constraints.

The patch follows the series' pattern of careful, incremental improvements and has already received positive feedback in previous iterations. As the final patch in a well-reviewed series, it seems ready for inclusion.
