This is a build system patch in Patrick Steinhardt's ongoing Meson refactoring series (v3, patch 12/13). It focuses on documentation build tool resolution in the Meson build system.

The patch standardizes how documentation tools (asciidoc, asciidoctor, xmlto, xsltproc) are located during the build process. On Windows systems, these tools need to be found in Git for Windows' custom program path, but the current implementation wasn't consistently using this path. The change ensures all tool lookups respect the custom program path, which is particularly important for Windows builds where tools may be in non-standard locations.

The changes are straightforward - each `find_program()` call is updated to include the `dirs: program_path` parameter. The patch also removes redundant `required: true` arguments since they're the default behavior. The modifications affect the documentation build configuration in `Documentation/meson.build`, touching the tool resolution logic for both asciidoc and asciidoctor backends, plus the XML processing tools.

This is a small but important consistency fix that follows the series' theme of build system simplification and Windows compatibility improvements. It builds upon previous patches in the series that addressed similar tool path resolution issues (like patch 10/13 for `sed` optimization and patch 11/13 for Git executable naming). The change is low-risk as it maintains existing functionality while making the behavior more consistent across platforms.
