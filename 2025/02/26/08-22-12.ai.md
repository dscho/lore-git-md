This is a build system patch fixing OpenSSL fallback behavior in the Meson build system, part of Patrick Steinhardt's larger Meson refactoring series (v3, patch 2/13). The change addresses a specific issue where the OpenSSL subproject wrapper wasn't being used as a fallback when OpenSSL was set to 'auto' detection mode, particularly affecting Windows builds where system OpenSSL is typically unavailable.

The patch modifies the OpenSSL dependency lookup in meson.build to properly allow fallback to the subproject wrapper in two cases: when OpenSSL is explicitly required (for cryptographic operations) or when the HTTPS backend is set to 'auto'. It also fixes an oversight where the HTTPS backend wasn't properly reported as 'none' when no backend was found or requested.

This appears to be a straightforward technical correction to ensure consistent behavior between the Makefile and Meson build systems regarding OpenSSL handling. The change is narrowly scoped to the dependency resolution logic and maintains the existing behavior for all other cases. As part of the well-reviewed v3 series, this patch builds on prior consensus about Windows build requirements and OpenSSL fallback strategies.
