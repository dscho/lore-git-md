Final patch in the packed-refs validation series, integrating ref consistency checks into `git fsck` with a new `--[no-]references` option. This patch completes the v7 series by wiring up the previously implemented ref validation logic (for both files and packed backends) into `git fsck` via a new `fsck_refs()` function that spawns a `git refs verify` child process. The implementation includes progress reporting (though currently limited to a single progress tick since loose ref counting isn't implemented yet) and preserves all existing fsck behavior while adding the new checks first in the execution sequence.

Key technical details:
- New `check_references` boolean and `--[no-]references` CLI option (defaults to on)
- `fsck_refs()` function that runs `git refs verify` with appropriate verbosity/strictness flags
- Progress reporting integration showing "Checking ref database"
- Test cases verifying the new flag's behavior with trailing garbage in refs
- Maintains backward compatibility by running before existing fsck checks that might implicitly validate refs

The patch follows the series' pattern of strict validation while maintaining runtime compatibility, and includes test coverage for the new CLI option. It represents the final piece connecting the comprehensive ref validation work to Git's main consistency checking tool.
