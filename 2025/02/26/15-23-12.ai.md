This is a follow-up discussion about the `git cat-file` filtering enhancement series, specifically regarding the implementation of object type filtering. Toon Claes raises a question about the intentional omission of support for combining multiple filters (LOFC_COMBINE) in the current implementation.

The email references Patrick Steinhardt's patch that adds "object:type=" filtering capability to `git cat-file`, which would allow filtering objects by their type (tag, commit, tree, or blob). The implementation adds the filter type to the existing LOFC_* enum and updates both documentation and the batch object writing logic to handle the new filter type.

Toon's question focuses on whether the series should support combining multiple filters from the start, noting that LOFC_COMBINE isn't currently implemented. This relates to the ongoing discussion about filter syntax (--filter= vs --objects-filter) and the broader goal of maintaining consistency with `git rev-list`'s filtering capabilities.

The thread context shows this is part of a larger performance optimization effort for GitLab's large repositories, with bitmap acceleration work still pending resolution of type-specific bitmap handling. This particular discussion represents a secondary but important design consideration about the filter interface's completeness and future extensibility.
