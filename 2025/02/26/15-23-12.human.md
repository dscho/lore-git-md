This is a follow-up discussion about the object filtering feature in `git cat-file`, specifically regarding the implementation of type-based filtering ("object:type="). Toon Claes raises a question about whether the patch should also support combining multiple filters (LOFC_COMBINE), noting its absence in the current implementation.

The patch itself adds support for filtering objects by type (tags, commits, trees, or blobs) through a new `--filter=object:type=` option, similar to existing blob size filters. The implementation touches documentation, the core filtering logic in `builtin/cat-file.c`, and tests.

Toon's question suggests the feature might benefit from supporting combined filters from the start, unless there are technical reasons not to. This appears to be a design consideration rather than a blocking issue, as the core functionality works as implemented. The discussion continues the broader thread about refining the filtering interface, which has included debates about option naming consistency with `git rev-list`.
