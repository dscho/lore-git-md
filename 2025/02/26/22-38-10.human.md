This is a documentation clarification in response to a minor formatting inconsistency noted in the Git v2.49.0-rc0 release notes.

Junio Hamano responds to D. Ben Knoble's observation about mixed formatting styles for config variables in the release notes (some using "section.key" while others use "[section] key"). Hamano clarifies that while the documentation may show "[help] autocorrect" style, the actual config syntax must use "help.autocorrect" - you can't literally write "[help] autocorrect=1" in config files or command line arguments.

He suggests two alternative phrasings that would be more technically precise when discussing config values in documentation: either describing the literal config file syntax ("[help]\n\tautocorrect = 1") or using a more conversational form ("setting help.autocorrect to 1"). This is a minor but precise clarification about documentation accuracy rather than any functional change to Git itself.
