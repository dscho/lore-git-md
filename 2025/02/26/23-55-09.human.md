Maintainer follow-up on config output escaping discussion.

Junio Hamano provides historical context for Git's existing octal escaping behavior in `core.quotePath`, linking to a 2007 thread where Linus Torvalds explained the choice of octal over hex escapes was intentional to match C language conventions. This reinforces Brian Carlson's observation about POSIX `printf` compatibility while clarifying the design rationale.

The email is brief but significant as it:
1) Confirms the octal escaping approach has precedent and deliberate design backing
2) Provides authoritative historical reference for the current behavior
3) Indirectly supports Carlson's proposal to extend similar escaping to config output
4) Maintains the thread's technical focus on preserving programmatic compatibility

This moves the discussion forward by establishing that any new human-readable output mode would likely follow the same octal escaping scheme already used elsewhere in Git, rather than introducing a new format. The reference to Linus's original explanation suggests this approach has stood the test of time despite being "ugly" (as Carlson noted).

The email doesn't resolve all open questions but provides important design context that will inform the implementation details of any proposed solution.
