This is the final patch in Patrick Steinhardt's Meson build system refactoring series, addressing CI optimization for Windows builds. The patch specifically targets memory constraints in GitLab's Windows CI environment by limiting concurrent linker jobs to prevent out-of-memory situations. 

The change modifies the GitLab CI configuration to set `backend_max_links=1` for MSVC builds, restricting the linker (`link.exe`) to a single concurrent job. This addresses observed memory starvation issues on GitLab's Windows runners which have only 7.5GB RAM, compared to GitHub Actions' more generous 16GB allocation where the problem hasn't surfaced. The patch makes a minimal change to the `.gitlab-ci.yml` file, adding just one Meson configuration parameter while maintaining all other build settings.

This completes the series' Windows-specific optimizations that began with PATH handling improvements (patch 8/13) and `sane_tool_path` refinements (patch 9/13). The solution is narrowly scoped to the specific CI constraint without affecting other platforms or build configurations. The series has now addressed all technical aspects from core architectural changes to platform-specific optimizations, with this final CI tuning adjustment.
