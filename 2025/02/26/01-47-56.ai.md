This is a discussion about potentially deprecating Git's support for unknown object types, arising from Jeff King's zlib inflation hardening series. Junio Hamano responds to Jeff's observation that the `--literally` flag (which allows creating objects with arbitrary types) has limited utility since such objects can't be packed, transferred, or have their content retrieved.

Junio confirms that `--literally` was primarily a debugging tool meant to test how Git handles corrupt objects with unrecognized types, not for actually supporting new object types. He suggests this feature should not be carried forward into Git 3.0, implying it may be a candidate for deprecation.

The exchange continues the thread's examination of edge cases in Git's object handling, now considering whether certain rarely-used features should be removed rather than maintained. This aligns with the series' broader goal of systematically reviewing and hardening zlib-related code paths. The discussion suggests the community may be moving toward simplifying the codebase by removing underutilized functionality like `OBJECT_INFO_ALLOW_UNKNOWN_TYPE` and `--literally` support.
