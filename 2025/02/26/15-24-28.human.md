This is the third patch in a series refactoring reflog expiration code to make it usable by Git's maintenance subsystem. It continues the work of eliminating global state by moving per-reflog expiry dates (previously stored in a global linked list) into the `reflog_expire_options` struct.

The patch introduces a new `reflog_expire_entry_option` struct to hold the pattern-matching expiry rules that were previously managed globally. The key changes include:
- Replacing the global `reflog_expire_cfg` list with entries stored in the options struct
- Updating all related functions to work with the new structure
- Adding the new fields to `reflog_expire_options` in reflog.h

This is a mechanical but important change that makes the expiration logic more self-contained and reusable. The patch follows logically from the previous ones in the series, which first renamed the main struct and then moved the default expiry times out of global variables. The changes are focused and well-contained, touching only the reflog expiration internals.
