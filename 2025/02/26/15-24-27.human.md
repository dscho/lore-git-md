This is the second patch in a series refactoring reflog expiration code to make it usable by Git's maintenance subsystem. The patch moves default reflog expiry dates from global variables into the `reflog_expire_options` struct, which is part of preparing the expiration logic to be reusable outside of `builtin/reflog.c`.

The change eliminates two static global variables (`default_reflog_expire` and `default_reflog_expire_unreachable`) by adding corresponding fields to the options struct and initializing them with a new `REFLOG_EXPIRE_OPTIONS_INIT` macro. The config parsing callback is updated to store values directly in the struct rather than the globals.

This is a straightforward refactoring with no behavior change, continuing the series' work to remove global state from the reflog expiration code. The patch follows logically from the first patch's renaming work and sets up for subsequent patches that will further modularize the expiration logic. The implementation looks clean and maintains the existing default expiry periods (30 days for unreachable entries, 90 days otherwise).
