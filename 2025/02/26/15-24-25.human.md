This is a feature patch series introducing a new "reflog-expire" maintenance task, part of the ongoing effort to make Git's maintenance more flexible and potentially replace `git gc`.

Patrick Steinhardt proposes adding a dedicated reflog expiration task to `git maintenance`, addressing a current gap where reflogs aren't expired when the gc task is disabled. The series builds on previous discussions about making maintenance more modular. The author suggests this could be a step toward eventually making the "incremental" strategy the default.

The technical implementation involves significant refactoring of reflog expiration code - moving away from global state and making internal functions public to support the new maintenance task. The series touches core reflog handling code, maintenance documentation, and adds new tests.

The patch set appears well-structured, with preparatory refactoring patches leading up to the main feature addition. The commit messages are detailed and the changes seem focused on the stated goal. This looks like a substantive contribution to Git's maintenance infrastructure that could help users customize their maintenance strategies more precisely.
