Security/behavior discussion regarding backspace escape handling in Git output.

Jeff King responds to Yaakov Smith's report about inconsistent backspace (`\b`) handling between `git fetch` (which sanitizes to '?') and `git config --list` (which shows raw sequences). He explains the difference in purpose: error messages need human-readable sanitization, while config output must preserve raw values for programmatic consumption. 

Key technical observations: `git config` already uses a pager (less) by default, but less's default behavior interprets adjacent backspaces as formatting commands (underlining/overstriking) rather than showing them literally. The email demonstrates this with `LESS=FRXU` showing control characters (`^H`).

The discussion expands to consider Git's default pager behavior, noting that `git show` also respects backspaces for formatting effects. King suggests potentially modifying Git's default `$LESS` variable to include the 'U' flag (which makes less show control characters literally) as a security hardening measure against potentially misleading output.

This advances the thread by clarifying the intentional design difference between the commands while opening a new discussion point about whether Git should modify its pager defaults to make control sequences more visible. The technical details about less's formatting rules and Git's pager invocation become important context for any follow-up patches or configuration changes.
