This is a discussion about naming consistency for filter options in `git cat-file`, part of Patrick Steinhardt's series to add bitmap-accelerated object filtering.

Toon Claes responds to Patrick's patch that introduces an `--objects-filter` option to `git cat-file`, arguing for consistency with other Git commands that use `--filter=` (via `OPT_PARSE_LIST_OBJECTS_FILTER`) rather than inventing a new name. While Patrick had chosen `--objects-filter` to avoid confusion with the existing `--filters` option (which takes no argument), Toon points out that having both `--filters` and `--filter=` is common in Git and would be more consistent with other commands.

The exchange highlights a minor but potentially important naming decision in the larger filtering feature series. Toon's feedback suggests the current naming might need reconsideration to maintain consistency across Git's interface, though the core functionality of the patch remains uncontested. This is the kind of naming discussion that often comes up during review of new features, where interface consistency can outweigh local naming preferences.
