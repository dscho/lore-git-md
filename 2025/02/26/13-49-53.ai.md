This is a bugfix patch (part 3/9 in the v7 series) that adds filetype validation for packed-refs files. The patch ensures packed-refs is a regular file rather than a symlink or directory, addressing a potential security issue where malicious symlinks could be used to bypass validation.

The key changes:
- Introduces `open_nofollow` + `fstat` check sequence to robustly verify filetype
- Handles ELOOP errors for symlink detection
- Reuses existing `FSCK_MSG_BAD_REF_FILETYPE` error reporting
- Adds comprehensive tests for both symlink and directory cases
- Maintains backward compatibility (silently skips if file doesn't exist)

The implementation builds on the series' security hardening theme by preventing symlink attacks while maintaining the existing validation workflow. The test cases verify both detection of symlinks (using `ln -sf`) and directories, with proper error message formatting. This complements the series' broader packed-refs validation goals while specifically addressing filetype concerns that could bypass other checks.

The patch shows careful attention to edge cases (ENOENT handling, proper fd cleanup) and follows the series' pattern of thorough test coverage. It integrates with the existing fsck infrastructure while adding a new layer of filesystem-level validation.
