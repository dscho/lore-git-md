This is a follow-up in the ongoing Meson build system thread, addressing newly discovered incremental build fragility issues. Patrick Steinhardt confirms Jeff King's findings that switching between 'next' and 'master' branches triggers Meson build failures unless doing a full rebuild (`rm -rf build`). The root cause is identified as a backwards-incompatible change in the "sane_tools_path" option type (from string to array) in the current patch series.

Patrick acknowledges this is problematic for bisection workflows but considers it acceptable during Meson's experimental phase, which he proposes should end with Git v2.49's release. The email suggests this particular issue stems from growing pains in the Meson transition rather than a fundamental flaw, though it does highlight real workflow friction for developers switching branches.

The response maintains the thread's technical focus while providing useful context about the project's Meson adoption timeline. It doesn't offer an immediate solution for the incremental build problem but sets expectations about when such breakages should stop occurring.
