This is part 5/9 in a bugfix series enhancing `git fsck`'s validation of packed-refs files, specifically focusing on header format consistency checks. The patch introduces strict validation for the packed-refs header format while maintaining backward compatibility with older Git versions that didn't write headers.

The key technical changes include:
1. Adding a new `badPackedRefHeader` fsck error for malformed headers that don't start with "# pack-refs with: "
2. Creating helper functions `packed_fsck_ref_next_line` (for newline termination checks) and `packed_fsck_ref_header` (for header validation)
3. Explicitly allowing missing headers (for backward compatibility) and unknown traits (for forward compatibility)
4. Adding comprehensive tests covering valid/invalid header formats, missing headers, and unknown traits

The implementation uses `open_nofollow` for safe file access and integrates with the existing fsck infrastructure. The validation logic aligns with runtime behavior in `create_snapshot` while adding stricter checks where appropriate. Test cases verify the new validation rules handle edge cases like malformed headers while permitting valid variations.

This patch represents a middle ground in the series' validation strictness - more rigorous than the runtime code (which ignores bad headers) but not overly restrictive (allowing future extensions via unknown traits). The changes are well-contained within the packed-refs backend while adding new fsck message IDs and documentation.
