This is a security hardening patch in a finalized bugfix series (v7 3/9) that adds filetype validation for packed-refs files. The patch ensures packed-refs is a regular file rather than a symlink or directory, preventing potential security issues from malformed ref storage.

The change introduces robust checking using `open_nofollow` for secure symlink detection followed by `fstat` to verify the file is regular. It reuses the existing `FSCK_MSG_BAD_REF_FILETYPE` error message for consistency. The implementation handles edge cases like ELOOP (symlink loops) and ENOENT (missing file) appropriately.

New tests verify the behavior with both symlinked and directory-packed-refs cases, ensuring proper error messages are shown. The patch is well-integrated with the existing fsck infrastructure and maintains the series' focus on comprehensive packed-refs validation. This appears production-ready with thorough test coverage and clear error reporting.

The change builds on earlier work in the series by Patrick Steinhardt and Karthik Nayak, addressing a subtle security gap in ref validation while maintaining the project's security standards for filesystem interactions.
