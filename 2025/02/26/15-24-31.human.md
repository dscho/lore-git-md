This is the final patch in a series introducing a new "reflog-expire" maintenance task to Git. The patch adds the actual task implementation after the preparatory refactoring in earlier patches.

The new task addresses a gap where reflog entries wouldn't expire when users disable the "gc" maintenance task. It provides two modes:
1. Direct execution runs `git reflog expire --all` (same as gc)
2. Auto mode uses a heuristic based on HEAD reflog entries (configurable via `maintenance.reflog-expire.auto`)

The implementation is thorough, including:
- Documentation updates for both config and command
- A new condition function that checks reflog entry counts
- Tests verifying both direct and auto modes
- Integration with the existing maintenance task framework

The patch builds on the previous refactoring work to create a clean, standalone solution. The auto mode's HEAD-focused heuristic is a pragmatic choice to avoid scanning all reflogs during frequent auto runs. This completes the series' goal of making reflog expiration available as a first-class maintenance task.
