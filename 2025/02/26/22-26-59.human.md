Junio Hamano responds to Patrick's patch that proposed skipping ambiguity checks when parsing object IDs in `git-update-ref`. While agreeing with the behavioral change (silencing warnings about ambiguous references), Junio provides important context about Git's historical intent regarding object ID parsing. He notes that while the documentation currently suggests only full hexadecimal object names are accepted, the command was always designed to handle extended SHA-1 expressions (those with suffixes like "~" or "^2") and even references.

Junio suggests Patrick update the manual page to better reflect this behavior, while still encouraging the use of full hexadecimal object IDs where appropriate. The discussion confirms that silencing the ambiguity warning is reasonable for this plumbing command, since users can always disambiguate references explicitly and the warning would rarely be seen in typical non-interactive use.
