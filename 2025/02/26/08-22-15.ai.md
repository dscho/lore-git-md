This is part of Patrick Steinhardt's Meson build system refactoring series (v3, patch 5/13), focusing on curl-related build dependencies. The patch introduces a new `libgit_curl` dependency that consolidates common curl-related source files (`http.c` and `http-walker.c`) and their linkage requirements.

The build system previously handled curl-related executables (`git-remote-http`, `git-http-fetch`, etc.) with repetitive declarations of the same source files and dependencies. The new approach bundles these into a single `libgit_curl` dependency that includes both the common sources and the existing `libgit_commonmain` dependency. This change affects several curl-related commands while maintaining identical build behavior.

A notable technical detail is that curl itself isn't directly included in `libgit_curl` - it's pulled in transitively through `libgit`, which the commit message notes is suboptimal and will be addressed in the next patch. The change also simplifies the handling of curl-related aliases (`git-remote-https`, etc.) by having them all depend on `libgit_curl` rather than sharing object files from `git-remote-http`.

The patch continues the series' theme of build system simplification by eliminating repetitive declarations and creating more logical dependency groupings. It builds on the `libgit_commonmain` consolidation from patch 4/13 while setting up for further curl-related cleanup in the following patch.
