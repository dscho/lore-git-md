This is a follow-up in the ongoing Meson build system thread, specifically addressing incremental build fragility issues. Jeff King confirms Patrick Steinhardt's explanation about the root cause being a backwards-incompatible change to the `sane_tools_path` option type (string to array) in the Meson configuration. The key technical detail is that this causes Meson to fail during incremental builds when comparing arrays at line 215 of meson.build, though full rebuilds work around the issue.

Patrick has established that such breaking changes will be acceptable only during Meson's experimental phase, with stability commitments kicking in after Git v2.49 is released. Jeff acknowledges this timeline as reasonable, noting it's good to know the issue is understood and under control rather than being some deeper Meson limitation.

The exchange confirms that while ccache helps mitigate rebuild costs, there's no current solution for the fundamental incremental build fragility until after v2.49 when backwards compatibility requirements will be enforced. This leaves bisection workflows as an ongoing pain point in the interim period.
