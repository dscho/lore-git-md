This is the final patch in a bugfix series that integrates packed-refs validation into `git fsck`. The patch adds a new `--[no-]references` option to `git fsck` that controls whether to check reference database consistency by running `git refs verify` as a child process. The validation includes the comprehensive checks implemented earlier in the series (header format, NUL character detection, sorting verification, etc.).

The implementation creates a new `fsck_refs()` function that spawns a child process to run `git refs verify`, with progress reporting. The check runs early in `git fsck`'s execution sequence to avoid interference with existing implicit reference checks. Tests verify that the new option properly enables/disables reference checking, including detection of trailing garbage in refs.

This completes the series' goal of bringing rigorous packed-refs validation into Git's standard fsck workflow while maintaining backward compatibility. The patch appears well-tested and follows the established pattern of the series, with clear commit message and appropriate documentation updates. The implementation has been reviewed and mentored by multiple Git contributors.
