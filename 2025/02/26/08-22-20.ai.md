This is a build system optimization patch in Patrick Steinhardt's Meson refactoring series (v3, patch 10/13). The change eliminates redundant searches for the `sed` executable during the build process.

The patch series has been progressively simplifying Git's Meson build system, with previous patches addressing static library consolidation, Windows PATH handling, and dependency management. This particular patch follows the architectural principle of declaring build tools once at the top level rather than repeatedly searching for them.

The technical change moves the `sed` executable lookup from multiple locations to a single declaration in the root `meson.build` file, then references this cached version in the documentation build process. This avoids repeatedly searching for `sed` in the `program_path` directories. The change also removes `sed` from the sanity-check loop that verifies required tools exist, since it's now handled separately.

The modification touches two files:
- `meson.build` gains the `sed` declaration alongside other tool declarations
- `Documentation/howto/meson.build` switches from `find_program('sed')` to using the pre-declared `sed` variable

This appears to be a straightforward optimization that follows the series' pattern of build-time simplifications. The change is small and focused, with no apparent behavioral impact beyond making the build slightly more efficient. It builds on previous infrastructure changes in the series (particularly the consolidated `program_path` handling) and maintains consistency of the build system architecture.
