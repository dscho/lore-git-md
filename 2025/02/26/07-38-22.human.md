This is a discussion about Git's handling of control characters in configuration output, specifically focusing on backspace (`\b`) sequences. Jeff King responds to Yaakov Smith's report about inconsistent behavior between `git fetch` (which sanitizes backspaces in error messages) and `git config --list` (which shows raw backspaces, potentially allowing misleading output like `"true\b\b\b\bfalse"` displaying as "false").

Jeff argues that `git config` should continue showing raw output since its purpose is to faithfully represent configuration data, though he notes the pager (`less`) could be configured to show control characters more visibly. He discovers that `less` has special handling for backspaces by default (using them for underlining/bolding), and suggests Git might consider modifying its default `$LESS` options to make control characters more obvious.

The thread highlights a tension between accurate data representation and human-readable output, with implications for both usability and potential security (where backspaces could obscure configuration values). No immediate changes are proposed, but Jeff's exploration of pager behavior suggests a possible avenue for improvement.
