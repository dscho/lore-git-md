This is a v7 bugfix series completing the `git fsck` packed-refs validation work, now with improved filetype checking and commit message refinements. The series builds on the previously finalized v6 version that implemented comprehensive packed-refs validation including header format checks, entry validation, and sorting verification.

Key changes in v7:
1. **Filetype checking enhancement** (Patch 3/9) replaces `lstat` with `open_nofollow` + `fstat` for more robust symlink detection, adding explicit ELOOP handling and improved test coverage for both symlinks and directories.
2. **Commit message refinement** (Patch 4/9) strengthens the justification for strict header format checking, now explicitly documenting the ecosystem-wide consistency rationale after Patrick's review.

The series maintains all previously implemented validation:
- Strict "# pack-refs with: " header format (with space)
- NUL character detection in refnames
- Comprehensive entry validation
- Sorting verification when "sorted" trait present
- Memory-efficient two-pass implementation
- Integration with `git fsck` via `--[no-]references` option

Technical details:
- New `open_nofollow` usage prevents TOCTOU races in filetype checking
- Adds explicit ELOOP handling for symlinks
- Expands test coverage for edge cases (symlinks, directories)
- Preserves all prior optimizations (Junio's filetype check sequence)
- Maintains compatibility with major Git implementations (libgit2, JGit, gitoxide)
