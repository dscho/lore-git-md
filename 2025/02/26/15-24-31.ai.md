This is the final patch in a 6/6 series introducing a new "reflog-expire" maintenance task, completing the refactoring work from previous patches to make reflog expiration usable outside of `git gc`.

The patch adds a new maintenance task that expires reflog entries, addressing the gap where reflogs would grow indefinitely when `gc` is disabled. The implementation has two modes:
1. Direct execution runs `git reflog expire --all` (same as `git gc`)
2. Auto mode uses a heuristic checking if HEAD's reflog has at least N (default 100) expirable entries before running, configurable via `maintenance.reflog-expire.auto`

Key technical details:
- Adds new `TASK_REFLOG_EXPIRE` enum and task struct
- Implements `reflog_expire_condition()` for auto mode using the refactored reflog infrastructure from earlier patches
- Uses `REFLOG_EXPIRE_OPTIONS_INIT` and related helpers moved in previous patches
- Adds tests verifying both direct execution and auto mode behavior
- Documentation updates for both config and command references
- Maintains same error handling as `git gc` (dies on failure)

The change is well-contained, building on the systematic refactoring done in patches 1-5 while adding the new maintenance integration point. The auto mode heuristic is intentionally lightweight to avoid performance impact during frequent maintenance runs.
