Security discussion follow-up regarding backspace escape handling in Git config output.

Brian Carlson agrees with Jeff King's position that `git config --list` should continue showing raw output to maintain compatibility with programs like Git LFS that parse this output. The thread has established this as the consensus position after considering security implications versus programmatic use cases.

Carlson suggests a potential enhancement: introducing a human-readable output option that would escape control characters, similar to how `core.quotePath` handles special characters. This would provide an optional middle ground between raw output and the current sanitized error message format. The proposal notes that octal escaping (as used in `core.quotePath`) has the advantage of working correctly with POSIX `printf`, though acknowledges it may be less readable than hex escapes.

The email reinforces the technical constraints that make changing the default output format undesirable, while proposing a possible optional feature that could satisfy users wanting more readable output without breaking existing tooling. This builds on the thread's earlier conclusion that core behavior should remain unchanged while exploring user-configurable solutions.
