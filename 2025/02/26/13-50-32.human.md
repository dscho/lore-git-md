This is part 7/9 of a bugfix series enhancing `git fsck`'s validation of packed-refs files. The patch adds detailed consistency checking for individual ref entries in packed-refs, building on earlier patches that validated the file's header format.

The patch introduces two new helper functions (`packed_fsck_ref_main_line` and `packed_fsck_ref_peeled_line`) that verify:
1. Each main ref line has a valid OID followed by proper spacing and a well-formed refname
2. Any following "^" peeled lines contain valid OIDs without trailing garbage
3. Refnames don't contain NUL characters (using the `refname_contains_nul` helper from an earlier patch)

The implementation includes comprehensive test cases that exercise various malformed packed-refs entries, including:
- Invalid OIDs
- Missing spaces after OIDs
- Bad refnames (with trailing spaces or invalid characters)
- Invalid peeled OIDs
- Trailing garbage after peeled OIDs

This is a well-structured patch that completes the series' goal of rigorous packed-refs validation. The code follows established patterns from earlier patches in the series and includes thorough test coverage.
