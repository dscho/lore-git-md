This thread introduces a new "reflog-expire" maintenance task to Git, addressing the gap where reflog entries wouldn't expire when "gc" maintenance is disabled. The 6-patch series systematically refactors reflog expiration internals to make them reusable by maintenance.

The first five patches laid the groundwork by restructuring the expiration code to remove global state and make it more modular. They renamed structures to better reflect their purpose, moved configuration into proper options structs, exposed key functions via reflog.h, and extracted the expiration logic from builtin/gc.c into standalone functions.

The final patch, just submitted, completes the series by adding the actual maintenance task. It implements two modes: a straightforward execution that mirrors git gc's behavior by running `git reflog expire --all`, and an auto mode that uses a lightweight heuristic (checking if HEAD's reflog has at least 100 expirable entries) to avoid unnecessary work. The implementation builds cleanly on the refactored infrastructure from earlier patches while maintaining the same error handling behavior as git gc.

This change provides a solution for users who disable gc maintenance but still want to control reflog growth, with the auto mode offering a performance-conscious default. The series appears well-structured, with each patch building logically on the last to achieve the final integration.
