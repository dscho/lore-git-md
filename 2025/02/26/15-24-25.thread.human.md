This thread introduces a 6-patch series that refactors Git's reflog expiration code to make it usable by the maintenance subsystem, addressing the gap where reflog entries wouldn't expire when "gc" maintenance is disabled. The series is methodically converting global state into instance state to enable this new functionality.

The first two patches established the foundation: Patch 1 renamed the core expiration structure to better reflect its purpose, while Patch 2 moved the default expiration times (30 days for unreachable entries, 90 days for all entries) from static variables into a structured options format. 

The third patch, just submitted, continues this refactoring by eliminating another set of global variables - the per-reflog expiry dates that were previously stored in a global linked list. It introduces a new structure to hold these patterns and dates, moving the configuration storage into the main options struct. The changes are mechanical but important, maintaining existing behavior while making the code more modular in preparation for the maintenance integration.

The series is building logically toward its goal, with each patch carefully preparing the ground for the next. The later patches will split the expiration logic from builtin/gc.c and finally add the new "reflog-expire" maintenance task. So far the thread has seen only the initial submissions with no review feedback yet.
