This is part 5/9 of a bugfix series enhancing `git fsck`'s validation of packed-refs files. The patch focuses specifically on header format validation.

The patch adds strict checking for the format of the "# pack-refs with: " header line in packed-refs files. It introduces two new fsck error messages: `badPackedRefHeader` for malformed headers and `packedRefEntryNotTerminated` for lines missing newline terminators. The validation is designed to be consistent with Git's runtime behavior - it allows missing headers (for backward compatibility) and unknown traits, but enforces the exact header prefix format.

The implementation reads the packed-refs file using `open_nofollow` for safety, then parses the first line to verify it either matches the expected header format or is absent. The patch includes comprehensive tests that verify the behavior with various valid and invalid header formats.

This appears to be a well-constructed patch that completes an important piece of the larger packed-refs validation effort. The commit message clearly explains the design decisions and the test coverage looks thorough. The changes align with the series' goal of bringing packed-refs validation up to the same standard as loose ref validation.
