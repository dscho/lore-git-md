This is a follow-up in the ongoing security discussion about backspace escape sequence handling in Git's output. Jeff King tests the proposal to modify Git's default `$LESS` variable to include the 'U' flag (which would show control characters literally) and finds it problematic. The 'U' flag makes tabs display as control characters too, ruining source code diff readability. 

King identifies two newer `less` options (`--proc-tab` and `--PROC-BACKSPACE`) that could solve this, but notes they were only added in very recent `less` versions (632+). He links to the upstream `less` issue that motivated these features, showing this is a known problem in terminal display handling. 

The email effectively closes the door on changing Git's default pager behavior as a solution to the backspace display issue, since the required `less` features aren't widely available enough. Instead, King suggests users with modern `less` versions could configure these options themselves. This leaves the original security concern about misleading backspace handling unresolved, but clarifies the constraints around potential pager-based solutions.
