This is the second patch in a 6-part series refactoring reflog expiration to support a new maintenance task. The patch focuses on eliminating global state in the reflog expiration code.

The change moves the default reflog expiry dates (30 days for unreachable entries, 90 days for all entries) from being stored as static variables in builtin/reflog.c to being part of the reflog_expire_options struct. This includes:
- New default_expire_total and default_expire_unreachable fields in struct reflog_expire_options
- A REFLOG_EXPIRE_OPTIONS_INIT macro to initialize these defaults
- Updates to reflog_expire_config() to store defaults in the options struct
- Removal of the static default_reflog_expire variables

The patch is a straightforward mechanical change that continues the series' goal of making reflog expiration logic more modular and reusable. It touches the same files as patch 1 (builtin/reflog.c and reflog.h) and follows logically from the struct renaming done there. The changes are well-contained and maintain the same behavior while removing global state - a key requirement for making this code usable by the maintenance subsystem in later patches.
