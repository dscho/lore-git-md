Refactoring patch in a series to make reflog expiration code reusable for maintenance tasks.

This is the third patch in a 6-part series that moves reflog expiration functionality out of global variables to make it usable by Git's maintenance subsystem. The patch continues the refactoring work from previous patches by eliminating another set of global variables - this time the per-reflog expiry dates that were previously stored in a global linked list (`reflog_expire_cfg`).

The key changes are:
1. Introduces a new `struct reflog_expire_entry_option` to hold per-reflog expiry patterns and dates
2. Moves the expiry configuration storage into `struct reflog_expire_options` via new `entries` and `entries_tail` fields
3. Updates all related functions to operate on the options struct rather than global state
4. Maintains the same behavior while making the code more modular

The patch is mechanical in nature, systematically converting global state to instance state in preparation for the later patches that will expose this functionality to the maintenance task system. The changes are focused in builtin/reflog.c and reflog.h, with no functional changes to the expiration logic itself. This continues the series' pattern of careful, incremental refactoring to enable the new maintenance feature.
