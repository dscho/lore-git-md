This is a refactoring patch that's part of a larger series (v7 2/9) improving packed-refs validation in `git fsck`. The patch addresses a subtle interaction between worktree handling and packed-refs validation that could cause premature program termination during verification.

The key change introduces `get_worktrees_without_reading_head()`, a variant of `get_worktrees()` that skips parsing HEAD information. This prevents validation tools like `git refs verify` and `git fsck` from potentially short-circuiting when they encounter malformed packed-refs files while checking HEAD references. The patch builds on prior work (commit 465a22b338) that first introduced the internal capability to skip HEAD parsing.

The implementation exposes the new API in worktree.h while modifying only `builtin/refs.c` to use it, keeping the change focused. The commit message clearly explains the problematic interaction where `create_snapshot()` in packed-backend.c would die on certain packed-refs file validation failures during HEAD parsing, even when the immediate goal was just to list worktrees.

This appears to be a well-considered change that:
1. Maintains backward compatibility (original `get_worktrees()` remains unchanged)
2. Has clear motivation explained in the commit message
3. Follows existing patterns (building on `get_worktrees_internal()`)
4. Is part of a larger effort to make ref validation more robust

The patch touches worktree handling (worktree.[ch]) and ref verification (builtin/refs.c), with the main new symbol being `get_worktrees_without_reading_head()`. It's a focused change that properly isolates the HEAD-parsing concern while maintaining all other worktree functionality.
