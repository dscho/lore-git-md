This is a security-adjacent discussion about Git's configuration output handling, specifically regarding backspace escape sequences. Brian M. Carlson weighs in on Jeff King's earlier response to Yaakov Smith's bug report about inconsistent backspace handling between `git fetch` and `git config --list`.

Carlson strongly agrees with King's position that `git config --list should not sanitize its output, noting this would break tools like Git LFS that parse the raw config values. However, he suggests adding an optional human-readable output format that could escape control characters, similar to how core.quotePath handles special characters. He points out this could help with tricky edge cases like config values containing newlines, though acknowledges the current octal escaping format isn't ideal for readability.

The email reinforces the thread's emerging consensus that the raw output must remain unchanged for machine parsing, while leaving open the possibility of adding a new output format option. Carlson's suggestion builds on existing Git conventions rather than proposing radical changes, aligning with the thread's cautious approach to modifying this sensitive behavior.
