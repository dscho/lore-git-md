This is a follow-up in the ongoing discussion about backspace escape sequence handling in Git's output.

Jeff King reports back from testing the proposed solution of adding 'U' to Git's default `$LESS` variable to make control characters visible. He found this makes tabs display as control characters too, which creates ugly output for source code diffs. While newer versions of `less` offer workarounds (`--proc-tab` and `--PROC-BACKSPACE` options), these are only available in very recent releases (less 632+), making them unsuitable as default behavior.

The email effectively closes the door on modifying Git's default pager settings as a solution to the backspace visibility issue, while pointing advanced users with modern `less` versions toward manual configuration options. This leaves the original problem - potential security implications of obscured configuration values via backspace sequences - still needing alternative solutions, though none are proposed here. The thread remains open for other approaches to address the core issue while maintaining good output formatting.
