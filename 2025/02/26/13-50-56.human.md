This is part 8/9 of a bugfix series enhancing `git fsck`'s validation of packed-refs files. The patch specifically adds sorting verification when the "sorted" trait is present in the packed-refs header.

The patch introduces a new check that verifies refnames are properly sorted when the packed-refs file declares itself as sorted. Rather than storing all refnames for comparison (which would be memory-intensive), it implements a streaming approach that compares each entry with the previous one during parsing. A new fsck error `packedRefUnsorted` is added to report violations.

Key implementation details:
- Extracts refname comparison logic into a reusable `cmp_packed_refname` function
- Adds a new `packed_fsck_ref_sorted` function that performs the streaming check
- Only activates the "sorted" check when the header explicitly includes the trait
- Includes comprehensive tests covering both sorted and unsorted cases

This completes one of the final planned validation checks for the packed-refs format, ensuring files marked as sorted actually maintain that property. The approach is memory-efficient and reuses existing comparison logic where possible. The patch has been reviewed by multiple mentors and fits into the larger series' goal of rigorous packed-refs validation.
