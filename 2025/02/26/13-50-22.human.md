Bugfix in the packed-refs fsck series, addressing embedded NUL characters in refnames.

This patch (6/9 in v7 series) fixes a subtle corruption case where a packed-refs file could contain refnames with embedded NUL characters. The current code would only validate the portion of the refname before the first NUL, potentially allowing dangerous refnames to slip through. The fix adds a new `refname_contains_nul()` helper that scans the entire refname length for NULs, dying if any are found.

The issue was reported by R. Diez, who noticed the validation gap. The solution builds on existing validation infrastructure while adding this specific check. The patch includes clear documentation of the edge case being fixed and integrates smoothly with the packed-ref iterator's existing error handling.

This is part of the larger fsck packed-refs validation series that's nearing completion (now at v7). The change is focused and well-justified, with test coverage presumably handled elsewhere in the series. The implementation looks solid, using standard Git string handling patterns.
