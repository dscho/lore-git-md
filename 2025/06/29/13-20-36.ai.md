Documentation patch converting line range format documentation to new AsciiDoc style, part of the git-log man page standardization series (v2, patch 4/9).

This patch mechanically converts the line range format documentation in `line-range-format.adoc` to the project's new standardized format. It replaces angle-bracket placeholders (`<start>`, `<end>`) with underscore-wrapped versions (`_<start>_`, `_<end>_`), and wraps regex patterns and offset syntax in backticks for better rendering. The content remains technically identical while adopting the project's documentation style guidelines.

Key changes include:
- Placeholder formatting standardized to `_<name>_` pattern throughout
- Regex patterns like `/<regex>/` and `^/<regex>/` now backtick-wrapped
- Offset notation (`+<offset>`, `-<offset>`) similarly marked up
- Function name references in `:<funcname>` syntax consistently formatted
- Line breaks and section organization preserved exactly

The patch follows the same mechanical transformation pattern used in earlier patches of this series, maintaining all technical content about line range specifications while standardizing the presentation. This includes details about absolute line numbers, regex-based line selection, offset ranges, and function name matching behavior. The changes are purely presentational, with no alterations to the documented functionality of `-L` line range options.

As with the rest of the series, this conversion has been reviewed and approved by Junio Hamano, confirming the markup changes correctly represent the original content while improving readability in rendered documentation. The patch fits into the broader effort to standardize Git's man page formatting, with this portion specifically addressing the line range syntax documentation.
