Documentation patch converting commit range notation in `rev-list-description.adoc` to use backticks for better rendering. This is part of the larger v2 series standardizing Git documentation format.

The patch mechanically changes single-quoted commit range notations like `'<commit1>..<commit2>'` to backtick-wrapped format `\<commit1>..<commit2>\` throughout the file. This includes both the two-dot and three-dot range syntaxes, as well as the equivalent caret notation. The change affects both the explanatory text and the example commands shown.

Junio Hamano has already reviewed and approved this change in the context of the full series, confirming the backtick-wrapped format produces better visual impact in colorized viewers. The patch maintains all technical content while standardizing the presentation to match the project's documentation style guidelines.

This conversion is part of the ongoing effort to standardize Git's documentation using AsciiDoc markup, with particular attention to making the syntax render well across different viewing tools. The commit range notation is a frequently referenced part of Git's documentation, so its clear presentation is important for users.
