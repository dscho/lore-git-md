This is a refactoring patch in the string-list modernization series, specifically addressing an internal API quirk. The change simplifies how string-list handles insertion of existing elements by directly returning the index rather than using a negative encoding scheme.

The patch removes a legacy behavior from 2006 where `add_entry()` would return `-1 - index` when an element already existed, which `string_list_insert()` would then immediately convert back to the positive index. The new version simply returns the index directly, making the code more straightforward while maintaining identical behavior.

The author notes this is a safe change since callers don't actually use the negative-index signaling - they just want the position. If signaling becomes needed later, a cleaner approach (like an `exact_match` out-parameter) could be added. This is part of a larger effort to modernize string-list's implementation while converting its tests to C unit tests, with all reviewer feedback from previous versions already addressed.
