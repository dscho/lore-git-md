This is a refactoring patch that improves type precision handling in Git's parse-options infrastructure, specifically for PARSE_OPT_CMDMODE options. It's the first in a 6-part series focused on making the option parsing system more type-safe.

The patch builds on previous work that added precision handling for OPTION_INTEGER by extending similar support to PARSE_OPT_CMDMODE options. The key changes include:

1. Requiring explicit precision specification (size of the target variable) for CMDMODE options
2. Modifying the internal get_value() function to properly handle different integer sizes when checking for conflicting mode changes
3. Adding proper type casting through a new get_int_value() helper
4. Updating call sites like builtin/am.c and test-parse-options.c to specify their precision

The changes maintain backward compatibility while adding stronger type safety. The implementation appears careful and well-tested, with modifications to both core parse-options logic and real-world usage sites. This is an internal improvement with no user-facing changes, but it helps prevent subtle bugs by ensuring option values are handled with their proper sizes throughout the parsing process.
