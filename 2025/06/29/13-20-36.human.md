This is the 4th patch in a 9-part documentation series converting Git's man pages to a standardized AsciiDoc format. The series has already been reviewed and approved by Junio Hamano.

The patch focuses on updating the line range format documentation in `line-range-format.adoc` to match the project's new documentation style. It makes mechanical conversions:
- Replaces `<placeholder>` with `_<placeholder>_` syntax
- Wraps commands and complex options in backticks
- Maintains all technical content while improving visual presentation

The changes affect how line range specifications are documented for commands like `git log -L`, including absolute line numbers, regex patterns, offsets, and function name matching. The patch follows the same transformation pattern successfully applied to other parts of Git's documentation in this standardization effort.

As with the other patches in this series, the changes are purely presentational - the actual behavior and meaning of the documented features remains unchanged. The patch has already been reviewed and approved as part of the complete series.
