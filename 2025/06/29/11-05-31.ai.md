Documentation patch addressing formatting and consistency issues in `git-for-each-ref` man page. This is part of the ongoing review process for the `git refs list` proposal, where Jean-Noël Avila provides follow-up improvements to the documentation that both commands share.

The patch makes several stylistic adjustments to the `git-for-each-ref.adoc` file, standardizing option syntax and improving clarity. Key changes include: fixing spacing around pipe characters in option alternatives (like `--shell | --perl`), making `--format` and merged/contains options consistently use `[=...]` syntax, and rewording descriptions to be more concise and imperative (e.g., changing "If `--stdin` is supplied" to "The list of patterns is read"). The `--exclude` option documentation is enhanced with clearer parameter naming (`<excluded-pattern>`) and markup.

These changes align with the maintainer's earlier suggestion to improve the source documentation directly rather than just modifying the new `git-refs.adoc` file. The patch demonstrates the parallel documentation work happening alongside the technical discussion about command consolidation strategy. While small in scope, these documentation improvements would benefit both `for-each-ref` and the proposed `refs list` command by establishing clearer, more consistent man page conventions.
