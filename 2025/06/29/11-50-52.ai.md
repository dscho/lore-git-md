This is the third patch in a refactoring series improving type precision in Git's parse-options infrastructure, specifically targeting OPTION_BIT handling. The patch extends the precision-based approach introduced earlier to OPTION_BIT options, requiring explicit precision specification and adding bounds checking.

The changes introduce type-safe handling for bit flags by:
1. Adding precision field initialization in builtin/write-tree.c for the --ignore-cache-tree flag
2. Modifying OPTION_BIT handling in parse-options.c to use the new get_int_value/set_int_value helpers
3. Including OPTION_BIT in the precision validation checks in parse_options_check()
4. Updating the OPTION_BIT macro in parse-options.h to automatically set precision

The implementation maintains backward compatibility while adding stricter type safety, similar to previous patches in the series. The changes affect write-tree.c's flag handling and the core parse-options machinery, with no user-facing impact. This continues the series' pattern of incremental improvements to specific option types while maintaining the existing API.

Key technical details for future reference:
- Uses same precision mechanism as OPTION_SET_INT (int8_t through int64_t)
- Adds bounds checking via signed_int_fits()
- Requires explicit precision specification with optbug()/BUG() checks
- Modifies bit operations to work through the new value helpers
- Updates OPTION_BIT macro to automatically set precision based on target variable size

The patch follows the series' established approach and appears well-contained, focusing solely on OPTION_BIT while leaving other option types for future patches.
