This is the final patch in a refactoring series improving type precision in Git's parse-options infrastructure, specifically targeting OPTION_COUNTUP handling. The patch extends the precision-based approach established in previous patches to OPTION_COUNTUP options, which are used for counting invocations (like `-v` flags). Key technical changes include:

1. Replacing direct int pointer manipulation with get_int_value/set_int_value helpers that respect the specified precision (size of the target variable)
2. Adding bounds checking to prevent overflow, with an error message if the count exceeds the type's maximum value
3. Automatically setting precision in the OPTION_COUNTUP macro based on the target variable's size
4. Adding OPTION_COUNTUP to parse_options_check() validation to ensure defval fits
5. Updating test cases to explicitly set precision for countup options

The implementation maintains backward compatibility while adding type safety through:
- Explicit precision specification (CHAR_BIT * sizeof(type))
- Bounds checking via INTMAX_MAX calculations
- Error reporting for overflow conditions
- Preservation of existing counting behavior (reset to 0 when unset, increment otherwise)

This completes the series' systematic conversion of all integer-based option types to use precise type handling, following the same pattern established for PARSE_OPT_CMDMODE, OPTION_SET_INT, OPTION_BIT, OPTION_NEGBIT, and OPTION_BITOP in previous patches. The changes are internal implementation improvements with no user-facing behavior changes.
