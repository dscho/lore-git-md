This is part 2 of a refactoring series improving type precision handling in Git's parse-options infrastructure. The patch extends the precision handling added earlier for `OPTION_INTEGER` to also cover `OPTION_SET_INT` options that set integer values when triggered.

The key changes include:
1. Requiring explicit precision specification for `OPTION_SET_INT` options
2. Adding bounds checking to ensure values fit in the specified type
3. Refactoring the integer casting logic into a reusable `set_int_value()` helper
4. Updating call sites in `update-index.c` and test code to specify precision

The changes maintain backward compatibility while adding stricter type safety. Most of the changes are mechanical updates to existing `OPTION_SET_INT` declarations to add precision information. The patch touches core parse-options logic and several builtin commands, with `update-index.c` seeing the most updates as it makes heavy use of these options.

This continues the series' focus on internal code quality improvements with no user-facing behavior differences. The implementation carefully handles real-world usage while preparing for future patches to extend the precision handling to other option types.
