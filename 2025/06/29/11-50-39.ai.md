This is part 2/6 in a refactoring series improving type precision handling in Git's parse-options infrastructure, specifically addressing OPTION_SET_INT. The patch extends the precision handling mechanism introduced earlier for OPTION_INTEGER to OPTION_SET_INT, requiring explicit precision specification and adding bounds checking.

Key technical changes include:
- Introduces set_int_value() helper function to handle type-precise value setting, factoring out common logic from OPTION_INTEGER handling
- Adds signed_int_fits() to validate that values fit within specified integer sizes
- Updates builtin/update-index.c to specify precision for all OPTION_SET_INT uses (mark_valid_only, mark_skip_worktree_only, mark_fsmonitor_only)
- Modifies parse-options.h macros to automatically set precision for OPTION_SET_INT definitions
- Adds test coverage in test-parse-options.c

The changes maintain backward compatibility while enforcing stricter type safety, with BUG()/optbug() checks for invalid configurations. The implementation carefully handles real-world usage sites, with update-index.c seeing the most external changes (6 precision additions). The patch follows the series' pattern of incremental improvements to specific option types while maintaining the existing API.
