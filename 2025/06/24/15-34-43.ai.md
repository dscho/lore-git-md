Signal handling refactoring in the Git daemon series, part 1/3. This patch centralizes SA_RESTART handling by moving platform-specific definitions from compiler flags in config.mak.uname into compat/posix.h. The change removes custom COMPAT_CFLAGS entries for NonStop and QNX while maintaining their SA_RESTART=0 behavior through a new fallback definition in the compatibility header.

The technical change adds a conditional SA_RESTART definition to compat/posix.h that defaults to 0 when not provided by the system, covering NonStop and QNX cases that previously used custom compiler flags. This prepares for subsequent patches that will use SA_RESTART in the daemon's signal handling. The patch removes the now-redundant SA_RESTART-related COMPAT_CFLAGS from config.mak.uname for both NonStop and QNX platforms.

Junio C Hamano notes in his review that this change makes SA_RESTART available everywhere via the fallback, potentially allowing Git to build on additional platforms that previously lacked the definition. He observes that while the resulting binary may not work correctly on such platforms yet, this is no regression from the current state. The review also points out a grammatical error in the commit message ("where" instead of "are") that should be corrected.

This is a foundational change for the series, establishing the centralized SA_RESTART handling that subsequent patches will build upon. The removal of platform-specific compiler flags in favor of a header-based solution follows Git's pattern of consolidating compatibility code. The patch appears straightforward and well-contained, though as noted in the thread summary, the relationship between this change and the overall daemon fixes could be more clearly explained.
