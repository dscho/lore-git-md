Bugfix patch in the Git daemon signal handling series, specifically addressing the debate around using `sigaction()` versus the deprecated `siginterrupt()` for SIGCHLD handling. This is a response to Junio C Hamano's suggestion to simplify the approach.

Carlo Marcelo Arenas Belón defends the `sigaction()` approach from patch 2/3, noting that while `siginterrupt()` would work on OpenBSD, it's been deprecated in POSIX since 2018 and fails to build on modern Linux systems with deprecation warnings. The response includes a concrete build failure example showing the compiler rejecting `siginterrupt()` with a recommendation to use `sigaction()` with SA_RESTART instead.

The technical points made include:
- Most systems now implement `signal()` via `sigaction()` internally
- Solaris and similar systems require direct `sigaction()` calls for reliable flag control
- The patch's approach provides consistent BSD semantics across platforms
- Build system evidence (GitHub Actions log) shows real-world impact of the deprecation

This moves the architectural discussion forward by providing concrete technical constraints that favor the more modern `sigaction()` approach, while acknowledging Junio's preference for minimal changes. The response maintains the series' focus on cross-platform reliability while addressing the specific build compatibility issue raised by the deprecation.
