This is a bugfix discussion for the MIDX and cruft pack interaction series, specifically addressing an issue with incremental MIDX handling. Jeff King reports a test failure when running with GIT_TEST_MULTI_PACK_INDEX_WRITE_INCREMENTAL=1, where cruft packs unexpectedly appear in the MIDX due to the current implementation not accounting for multi-layered MIDX structures.

Taylor Blau confirms this is a real bug and provides a fix that modifies the pack gathering loop in builtin/repack.c to properly traverse all layers of an incremental MIDX. The patch changes the allocation size to account for base MIDX packs and adds a nested loop to traverse the MIDX chain via m->base_midx.

Jeff King acknowledges the fix looks reasonable but raises two important considerations: 1) the broader issue of incremental MIDX handling potentially affecting other callers, suggesting the public-facing API might benefit from abstracting this complexity, and 2) whether a test should be added to cover this case in normal test runs, not just the specialized linux-TEST-vars build. The discussion highlights an implementation detail where the fix works around rather than fundamentally solving the incremental MIDX representation issue, while maintaining the series' goal of properly excluding cruft packs from MIDX generation where possible.
