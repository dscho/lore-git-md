This is a review response in the ongoing Git daemon signal handling bugfix series. Junio C Hamano questions the approach taken in patch 2/3, which converts signal() to sigaction() for installing the child handler. He suggests that using siginterrupt() might be a simpler solution that would work on platforms where it's available, rather than the current approach of switching to sigaction().

The discussion centers around platform-specific signal handling behavior, particularly around whether system calls should be interrupted when SIGCHLD is received. Junio notes that the sigaction() conversion doesn't seem to provide clear benefits for the series' goals, which are primarily about fixing zombie process cleanup on OpenBSD and crashes on AIX.

This email represents a key design discussion point in the series, where the maintainer is pushing back on the implementation approach and suggesting an alternative that might simplify the changes. The outcome of this discussion will likely influence whether patch 2/3 remains in its current form or gets replaced with a different solution.
