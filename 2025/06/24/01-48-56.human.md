This is part 2 of a 3-part bugfix series improving the git-credential-netrc helper's handling of port numbers in netrc files. The patch focuses on error reporting.

The helper now warns when encountering invalid port specifications in netrc files, rather than silently ignoring them. The change maintains the existing behavior of only using numeric ports (dropping non-numeric ones) but adds a warning message to alert users when this happens. The implementation is straightforward - it wraps the port validation check in a conditional that prints to STDERR when the port doesn't match the numeric pattern.

This patch represents a middle ground in the ongoing discussion about how to handle symbolic port names. While the series as a whole implements full symbolic port resolution via getservbyname, this particular part keeps the numeric-only validation but makes the behavior more transparent to users. The change is small and focused, with clear test coverage in the series' other patches. It follows Junio Hamano's earlier feedback to simplify the implementation while maintaining robust behavior.
