Security vulnerability in Git's Bash completion allowing shell command injection via branch names containing special characters (specifically `>` redirection operator). Reported by Ondrej Pohorelsky. When creating and switching to branches with `>` in their names, Bash tab completion interprets the character as a shell redirection operator rather than part of the branch name, leading to unintended file creation (demonstrated with `>/tmp/dangerfile`). The branch creation itself works but creates unusual ref paths. Zsh properly escapes special characters during completion. Exact location in Git's completion code requiring fix not yet identified. Affects Git 2.49 on Fedora, likely impacts other versions/distributions using Bash completion. Reproduction steps provided showing branch name misinterpretation as shell command with redirection.
