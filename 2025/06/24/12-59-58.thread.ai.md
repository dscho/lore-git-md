Security vulnerability in Git's Bash completion allowing shell command injection via branch names containing special characters (specifically `>` redirection operator). Reported by Ondrej Pohorelsky. When creating and switching to branches with `>` in their names, Bash tab completion interprets the character as a shell redirection operator rather than part of the branch name, leading to unintended file creation (demonstrated with `>/tmp/dangerfile`). The branch creation itself works but creates unusual ref paths. Zsh properly escapes special characters during completion. Kristoffer Haugsbakk proposes extending `git-check-ref-format` to optionally disallow `>` characters in refnames entirely as a hardening measure beyond just fixing the Bash completion issue. This would be an opt-in feature to maintain backward compatibility while preventing shell injection vectors at the refname validation level. The suggestion shifts focus from completion-specific escaping to broader refname validation policy. No implementation details or patch provided yet. Reproduction steps show branch name misinterpretation as shell command with redirection. Affects Git 2.49 on Fedora, likely impacts other versions/distributions using Bash completion. Exact location in Git's completion code requiring fix not yet identified.
