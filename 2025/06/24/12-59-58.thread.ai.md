Security vulnerability in Git's Bash completion allowing shell command injection via branch names containing special characters (specifically `>` redirection operator). Reported by Ondrej Pohorelsky. When creating and switching to branches with `>` in their names, Bash tab completion interprets the character as a shell redirection operator rather than part of the branch name, leading to unintended file creation (demonstrated with `>/tmp/dangerfile`). The branch creation itself works but creates unusual ref paths. Zsh properly escapes special characters during completion.

Kristoffer Haugsbakk initially suggested extending `git-check-ref-format` to disallow `>` characters in refnames as hardening measure, but later clarified this was merely an aside after Phillip Wood and Junio Hamano established the root issue lies in the completion script's failure to properly quote refnames containing shell metacharacters. Junio Hamano firmly settled the architectural debate, confirming the fix should focus on proper shell metacharacter escaping in `git-completion.bash` rather than changing Git's flexible refname validation rules which already permit numerous other potentially problematic characters (`<`, `$`, `&`, `;`, etc.).

The thread has reached clear consensus that the solution requires modifying the Bash completion script to escape special characters during tab completion operations, particularly for branch switching scenarios. The vulnerability remains unpatched but the implementation path is now well-defined as a completion script update. Reproduction shows the issue affects Git 2.49 on Fedora and likely other versions/distributions using Bash completion. No patches have been proposed yet, with the specific location in the completion code still to be identified for the actual fix.
