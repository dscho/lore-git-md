This is a technical discussion in the ongoing Git daemon signal handling bugfix series, specifically about the implementation approach for SIGCHLD handling. Carlo Marcelo Arenas Belón responds to Junio C Hamano's suggestion to use the simpler `siginterrupt()` function instead of the current `sigaction()` approach from patch 2/3.

Carlo acknowledges that `siginterrupt()` would work functionally (as tested on OpenBSD) but argues against it because the function has been deprecated in POSIX since 2018, showing a compilation error it causes on modern Linux systems. He notes that while most systems implement `signal()` with `sigaction()` internally, some platforms like Solaris require direct `sigaction()` usage for reliable behavior.

The exchange highlights a key architectural decision point in the series: whether to use the deprecated-but-simpler `siginterrupt()` or the more modern-but-complex `sigaction()` approach. Carlo's response provides concrete technical justification for the current implementation path while acknowledging the validity of Junio's concern about complexity.
