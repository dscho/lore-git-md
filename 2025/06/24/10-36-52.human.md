This is a performance discussion follow-up in the test infrastructure series adding `test_seq -f` functionality.

Jeff King responds to Eric Sunshine's performance concerns about using shell-based `test_seq` versus `awk` for generating large sequences in tests. While Eric had previously suggested similar shell-based changes that were rejected due to performance, Jeff's measurements show the shell implementation actually wins at 10,000 items (though `awk` may be better at 50,000+). He notes the differences are in the noise (milliseconds) and argues readability improvements outweigh micro-optimizations here.

The exchange highlights an interesting implementation tradeoff - the shell version eliminates a process spawn but may have higher per-item overhead. Jeff maintains the current approach is reasonable given the test suite context, suggesting any serious optimization efforts would be better focused elsewhere. The discussion remains collegial, with both sides acknowledging valid points while Jeff stands by his design choice prioritizing code clarity.
