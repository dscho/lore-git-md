This thread reports a security vulnerability in Git's interaction with Bash tab completion when switching branches. Ondrej Pohorelsky discovered that branch names containing shell special characters (like `>`) can be misinterpreted as shell commands during tab completion in Bash, potentially creating unintended files. For example, attempting to tab-complete a branch named `>/tmp/dangerfile` causes Bash to create that file rather than completing the branch name.

The issue is specific to Bash's completion behavior - Zsh properly escapes special characters. While Git itself correctly creates branches with these unusual names, the security risk emerges during the completion phase. The reporter hasn't yet pinpointed the exact location in Git's code that needs fixing, but has provided clear reproduction steps showing the problem on Git 2.49 under Fedora. This appears to be a legitimate security concern that could affect other versions and distributions when using Bash completion.
