This thread addresses a security vulnerability in Git's Bash completion that allows shell command injection when branch names contain special characters like `>`. The issue was reported by Ondrej Pohorelsky, demonstrating that creating and switching to branches with `>` in their names causes Bash to interpret it as a redirection operator, potentially creating unintended files.

Kristoffer Haugsbakk initially suggested hardening Git by extending `git-check-ref-format` to disallow `>` characters in refnames entirely. Phillip Wood countered that the real issue lies in the completion script's failure to properly quote refnames containing shell metacharacters, not in the refname format itself. Wood noted Git already permits many potentially problematic characters in refnames, and proper escaping in the completion layer would be more appropriate than restricting the data model.

Junio Hamano has now weighed in, firmly agreeing with Wood's position. The maintainer characterized this as purely a completion script bug, not a refname validation issue, and made clear the fix should focus on proper quoting in `git-completion.bash`. This maintains backward compatibility while addressing the security concern. While no patches have been proposed yet, the architectural direction is now settled: the completion script needs to properly escape special characters during tab completion. The issue remains open for implementation, with the fix expected to target the completion script's handling of refnames containing shell metacharacters.
