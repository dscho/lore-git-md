This is the final patch in a series addressing signal handling issues in the Git daemon, specifically targeting OpenBSD zombie process cleanup. The patch focuses on ensuring proper EINTR handling during poll() operations when SIGCHLD signals are received.

The key technical change is the introduction of explicit SA_RESTART flag management around poll() calls in daemon.c. The patch adds a new NO_SIGINTERRUPT build flag for platforms that either lack siginterrupt() functionality or where signal(SIGCHLD) doesn't set SA_RESTART. This affects Windows and some Unix-like systems (NonStop, QNX, MINGW) which are marked in config.mak.uname.

The implementation maintains backward compatibility by keeping the old signal() handler behavior for NO_SIGINTERRUPT platforms while using proper sigaction() with SA_RESTART toggling on modern systems. The patch touches multiple build system files (Makefile, config.mak.uname, configure.ac, meson.build) to support the new flag and adds conditional compilation paths in daemon.c to handle both scenarios.

This completes the series' solution for OpenBSD zombie processes by ensuring poll() can be interrupted for child reaping, while maintaining the AIX crash fix from earlier patches. The changes are well-contained to daemon.c's service loop and signal handling setup, with careful attention to platform differences in signal behavior.
