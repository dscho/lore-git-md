This is a bug report about shell command injection vulnerability in Git's branch switching behavior when using Bash completion.

Ondrej Pohorelsky reports that when creating and switching branches with special characters (specifically the `>` redirection operator) in their names, Bash's tab completion can lead to unintended file creation. The issue demonstrates how a branch name containing `>/tmp/dangerfile` gets interpreted as a shell redirection command when tab-completing the branch name, creating the specified file rather than switching branches.

The report shows that this behavior is Bash-specific - Zsh properly escapes the special characters. The branch creation itself works (though creates an unusual ref path structure), but the tab completion in Bash causes the security issue. The reporter notes they haven't identified the exact location in Git's code where this needs to be fixed.

This appears to be a legitimate security concern where Git's interaction with shell completion could be tricked into performing file operations. The report includes clear reproduction steps showing how the branch name gets misinterpreted as a shell command with redirection. The issue affects Git 2.49 on Fedora, but the underlying problem likely exists in other versions and distributions when using Bash completion.
