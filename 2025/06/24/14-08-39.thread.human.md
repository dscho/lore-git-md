This thread addresses a complex signal handling issue in the Git daemon that affects multiple platforms, particularly causing zombie processes on OpenBSD and crashes on AIX. The discussion has evolved through several versions of the patch series, with v1 initially proposing SA_RESTART centralization and v2 moving toward a more portable sigaction()-based solution.

The key participants are Carlo Marcelo Arenas Belon (the patch author) and Junio C Hamano (the maintainer), with valuable historical context provided by Chris Torek. The technical debate initially centered around whether to use the deprecated siginterrupt() function versus modern sigaction(), with Carlo providing compelling evidence that sigaction() is the only reliable cross-platform solution. This was further supported by Chris Torek's explanation of Unix signal handling evolution.

The current sticking points are primarily about code organization and naming - specifically how to reconcile the NO_SIGINTERRUPT naming (from the deprecated interface) with the new sigaction() implementation, and how to reduce conditional compilation complexity. Junio has accepted the technical necessity of the approach but continues to push for cleaner abstraction and implementation aesthetics.

The series is now technically sound across all targeted platforms (Windows, NonStop, QNX, MINGW, AIX, OpenBSD, Solaris) with demonstrated fixes for the original issues. The remaining work focuses on polishing the code organization before potential merging, with decisions needed on final abstraction boundaries and naming conventions. The discussion has been productive, moving from technical justification to implementation refinement, with all substantive technical questions now resolved.
