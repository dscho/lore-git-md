This thread addresses signal handling issues in the Git daemon, specifically around zombie process cleanup on OpenBSD and crashes on AIX. The discussion has evolved through multiple patch versions (now at v3) with contributions from Carlo Marcelo Arenas Belón, Junio C Hamano, Phillip Wood, and Chris Torek.

The core problem involves platform-specific behavior around interrupted system calls during signal handling, particularly with SA_RESTART in poll() operations. The current solution uses sigaction() modernization with a new set_sa_restart() helper for dynamic SA_RESTART control, addressing issues across multiple platforms (Windows, NonStop, QNX, MINGW, AIX, OpenBSD, Solaris). Chris Torek provided valuable historical context about Unix signal evolution that supported the technical approach.

A significant development is Phillip Wood's proposal of the self-pipe technique as an alternative architecture. This approach would create a dedicated file descriptor that the signal handler writes to, waking the event loop without platform-specific SA_RESTART handling. Junio has validated this as technically sound, noting it could solve both the original OpenBSD issue and a newly discovered race condition between check_dead_children() and poll() calls.

The thread now faces a key architectural decision between:
1. The nearly complete SA_RESTART toggling approach (with set_sa_restart() helper)
2. The self-pipe model (newly validated, requiring pipe setup but potentially simpler)

Junio continues to review implementation details carefully, recently focusing on code organization and naming conventions for platform-specific handling. While the technical issues are largely resolved, the choice between these two approaches remains open, with tradeoffs in portability, resource usage, and code complexity to consider.
