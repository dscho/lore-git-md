This thread addresses a subtle signal handling bug in Git's daemon mode that was causing zombie processes on OpenBSD and crashes on AIX. The core issue involves platform-specific behavior around interrupted system calls during signal handling, particularly with the SA_RESTART flag in poll() operations.

Carlo Marcelo Arenas Belon has led the technical work through three iterations of the patch series, with Junio C Hamano providing careful review. The discussion has evolved from initial technical justification to implementation refinement. While the sigaction() modernization approach is now accepted as technically necessary (with evidence showing siginterrupt() is deprecated in POSIX since 2018), Junio continues to advocate for cleaner code organization and naming.

The latest email resolves one key question: Carlo explains why the empty child_handler() must remain, despite appearing redundant. Removing it would break EINTR behavior in poll() on certain systems, demonstrating the complex platform-specific nuances involved. The series now has complete cross-platform coverage (Windows, NonStop, QNX, MINGW, AIX, OpenBSD, Solaris) and maintains backward compatibility.

Outstanding issues include reconciling the NO_SIGINTERRUPT naming (from the deprecated interface) with the modern sigaction() implementation, reducing conditional compilation complexity, and finalizing code organization. The technical solutions are sound, but some aesthetic and structural polish remains before Junio is likely to merge the series.
