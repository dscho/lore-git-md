This thread explores a redesign of git-daemon's child process tracking, originally prompted by platform-specific signal handling issues (particularly on Windows). The discussion has evolved through three competing approaches: Carlo Marcelo Arenas Belon's original SA_RESTART toggling solution, Phillip Wood's documentation-only proposal, and now a new pipe-based tracking mechanism that avoids signals entirely.

The latest development is a two-part RFC series implementing the pipe-based approach, where each child process gets a pipe that automatically closes on exit, allowing the parent to detect termination via poll() rather than signals. The second patch just landed completes the core mechanism, removing the SIGCHLD handler entirely and tracking children through pipe file descriptors instead. While functional, the current implementation has some inefficiencies (notably O(n) child scanning) and excludes Windows support for now.

Key participants remain divided: Phillip Wood advocates for minimal changes with clear documentation of platform behaviors, while Carlo pushes for more robust architectural changes (first with SA_RESTART, now with pipes). Junio Hamano initially favored Phillip's view but is observing the technical debate unfold. Windows-specific quirks remain a parallel concern, though the pipe approach could potentially sidestep many signal handling issues if proven portable.

The thread now has concrete code to evaluate for the pipe-based approach alongside the earlier proposals. Open questions remain about performance at scale, Windows compatibility, and whether this architectural shift is justified given the other options. The discussion awaits further testing data and may benefit from Windows expertise (potentially from Johannes Schindelin) to assess the pipe approach's viability across all supported platforms.
