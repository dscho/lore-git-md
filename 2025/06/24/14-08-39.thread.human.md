The Git daemon signal handling thread has progressed through three versions of a patch series addressing zombie process cleanup on OpenBSD and crashes on AIX. The core issue involves platform-specific behavior around interrupted system calls during signal handling, particularly with SA_RESTART in poll() operations. Carlo Marcelo Arenas Belon has been driving the technical implementation while Junio Hamano has provided rigorous review, initially questioning the approach but gradually accepting its technical necessity.

The discussion has evolved from basic fixes to a deeper architectural debate about POSIX compliance versus code cleanliness. Key technical points now settled include: the need for an empty handler function (confirmed as required for correct EINTR behavior on some platforms), the deprecation of siginterrupt() in favor of sigaction(), and comprehensive cross-platform coverage. Chris Torek recently contributed valuable historical context explaining why the current implementation reflects decades of Unix signal handling evolution, further validating the technical approach.

While the technical solution is now well-justified, the thread remains open as Junio pushes for cleaner abstraction of the conditional compilation and naming (the NO_SIGINTERRUPT flag still references the deprecated interface). The series appears ready for merging once these final aesthetic concerns are addressed, with all substantive technical questions now resolved through extensive platform testing and historical evidence.
