This thread addresses a bug in Git's daemon signal handling that causes zombie processes on OpenBSD and crashes on AIX. The discussion has evolved through three versions of a patch series from Carlo Marcelo Arenas Belon, with input from Junio Hamano, Phillip Wood, and Chris Torek. The core issue involves platform-specific signal handling behaviors during poll() operations, particularly around the SA_RESTART flag.

Two viable solutions have emerged: the current approach that toggles SA_RESTART (nearly complete but platform-specific code), and a proposed self-pipe alternative (more portable but requiring new implementation). The self-pipe method would create dedicated file descriptors to wake the event loop during signals, eliminating the need for SA_RESTART toggling entirely. Phillip Wood has confirmed this would work consistently across both poll() and select().

The latest email clarifies a technical detail in the existing implementation - an empty #ifdef block that verifies SA_RESTART's presence in signal.h, important for platforms like QNX and Windows that lack this POSIX flag. While this doesn't change the architectural decision, it helps maintainers understand the current code's portability considerations.

Junio has previously validated the self-pipe approach, giving it significant weight, though the SA_RESTART solution remains functional. The thread now awaits a decision between these two options, weighing factors of portability, implementation effort, and long-term maintenance. The choice will determine the final direction for fixing these signal handling issues across multiple platforms.
