This thread continues the discussion about fixing signal handling in git-daemon, particularly around how it cleans up child processes on various platforms. The core issue involves platform-specific behaviors when system calls are interrupted by signals, with OpenBSD and AIX showing different symptoms. 

Carlo Marcelo Arenas Belon originally proposed a series that toggles the SA_RESTART flag around poll() calls to handle these platform quirks. Phillip Wood has been advocating for a simpler approach that would document the platform behaviors rather than adding complex SA_RESTART manipulation code. The discussion has now narrowed to Windows-specific implementation details of their sigaction() wrapper - while Carlo's patch makes it return -1 (POSIX-style) instead of SIG_ERR, Phillip suggests also setting errno=EINVAL for better error reporting consistency, even though current callers ignore the return value.

Junio Hamano has previously validated both the SA_RESTART approach and Phillip's simpler alternative. The Windows sigaction() return value discussion represents a minor implementation detail that doesn't change the fundamental architectural choice between these approaches. Phillip's case for simplicity remains strong, though both solutions would leave an underlying race condition between child process cleanup and poll() operations unresolved. The thread is at a point where the next step would be for Junio to decide which direction to take the series.
