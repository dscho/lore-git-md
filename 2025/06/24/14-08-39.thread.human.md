This thread addresses signal handling in git-daemon, specifically how to handle interrupted system calls (EINTR) during process cleanup on various platforms. The discussion began with Carlo Marcelo Arenas Belón's patch series proposing to toggle the SA_RESTART flag to prevent zombie processes on OpenBSD and crashes on AIX. 

The conversation evolved with Phillip Wood advocating for a simpler approach - removing the SA_RESTART manipulation entirely and instead documenting platform behaviors, arguing git-daemon's existing EINTR handling is sufficient. Junio Hamano supported this view, validating the original design assumptions. However, Carlo has now raised concerns that 20 years of code changes (including run_command integration) may have invalidated those assumptions, citing a past bug as evidence. He argues maintaining the SA_RESTART toggling is safer despite being more complex.

Key participants are divided: Phillip and Junio favor the minimal documentation approach, while Carlo maintains the original SA_RESTART solution provides better safety. The discussion now hinges on whether historical signal behavior changes justify keeping the more involved solution versus adopting the simpler approach. While technical consensus seemed near, this latest response has reopened debate about the robustness of git-daemon's EINTR handling across the evolving codebase.
