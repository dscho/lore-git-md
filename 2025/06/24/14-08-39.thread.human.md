This thread addresses a complex signal handling issue in Git's daemon, particularly around zombie process cleanup on OpenBSD and crashes on AIX. The discussion has evolved through multiple patch versions (now at v3) with contributions from Carlo Marcelo Arenas Belón, Junio C Hamano, Phillip Wood, and Chris Torek.

The core problem involves platform-specific behavior of interrupted system calls during signal handling, particularly around SA_RESTART in poll() operations. The series has introduced several technical improvements: transitioning from siginterrupt() to sigaction(), adding a USE_NON_POSIX_SIGNAL build flag, and implementing new helper functions like set_signal_handler() and set_sa_restart(). Chris Torek provided valuable historical context about Unix signal evolution that helped justify the technical approach.

Junio initially questioned some implementation choices but has now accepted the technical necessity of the sigaction() modernization while pushing for cleaner code organization. The latest review focuses on moving signal-handling code together to reduce #ifdef pollution, indicating the architectural discussion is settling. Meanwhile, Phillip Wood has proposed an alternative "self-pipe" approach that could avoid platform-specific SA_RESTART handling entirely, though this would require additional file descriptors.

The series has made concrete progress in fixing the original issues (OpenBSD zombies and AIX crashes) while maintaining cross-platform compatibility. With the core technical decisions now resolved, the remaining work involves final code organization improvements and deciding whether to stick with the current SA_RESTART approach or switch to the self-pipe model. The thread demonstrates Git's careful approach to platform-specific issues, balancing technical correctness with code maintainability.
