This thread addresses a complex signal handling issue in the Git daemon that affects process cleanup on OpenBSD and causes crashes on AIX. The discussion has evolved through multiple patch versions (now at v3) with contributions from Carlo Marcelo Arenas Belon, Junio C Hamano, Phillip Wood, and Chris Torek.

The core problem involves platform-specific behavior around interrupted system calls during signal handling, particularly with SA_RESTART in poll() operations. The current solution approach has focused on modernizing signal handling through sigaction() with proper SA_RESTART toggling, supported by historical context from Chris Torek about Unix signal evolution. The series has introduced new infrastructure including a USE_NON_POSIX_SIGNAL build flag and helper functions like set_signal_handler() and set_sa_restart().

A significant development came from Phillip Wood, who proposed an alternative "self-pipe" approach that would avoid platform-specific SA_RESTART handling entirely by using a pipe for signal delivery. Junio has now acknowledged this as a potentially viable alternative that could solve both the zombie process issue and a newly identified race condition between check_dead_children() and poll() calls.

The thread now stands at an architectural decision point between:
1. Continuing with the well-developed SA_RESTART toggling approach
2. Switching to Phillip's self-pipe model which may offer simpler cross-platform handling

Junio's openness to the self-pipe approach suggests the discussion may take a new direction, though the current signal handling implementation remains functional and nearly complete. The decision will likely hinge on which approach offers better long-term maintainability and portability, with tradeoffs around code complexity versus additional file descriptor usage.
