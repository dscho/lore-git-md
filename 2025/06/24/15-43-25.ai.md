This is the third patch in a series addressing signal handling issues in the Git daemon, specifically focusing on EINTR handling during poll() operations. The patch introduces a NO_SIGINTERRUPT build flag for platforms lacking proper siginterrupt() support (Windows, NonStop, QNX, MINGW) and implements platform-specific workarounds.

Junio C Hamano reviews the implementation, pointing out two main concerns: First, he notes that the signo parameter in child_handler() is unused on NO_SIGINTERRUPT systems and suggests better abstraction to avoid scattered #ifdef directives. Second, he implicitly questions the need for the empty handler function now that the series has removed the manual rearming requirement for SysV systems (a point he raised in the previous patch's review).

The patch's technical changes include:
- Conditional compilation paths for NO_SIGINTERRUPT systems in service_loop()
- Platform-specific signal handler setup (signal() vs sigaction())
- Dynamic toggling of SA_RESTART flag around poll() operations on systems with proper siginterrupt support
- Maintenance of the empty child_handler() function with conditional rearming for backward compatibility

Key unresolved questions from the review:
- Whether the empty handler function is still necessary given the series' other changes
- How to better abstract the platform-specific signal handling code to reduce #ifdef clutter
- The relationship between this EINTR handling and the broader signal handling modernization in the series

This patch completes the platform-specific solutions for OpenBSD zombie processes and AIX crashes, but Junio's feedback suggests the implementation could be cleaner. The review continues the thread's pattern of incremental improvements to the signal handling code, with particular attention to cross-platform compatibility and code maintainability.
