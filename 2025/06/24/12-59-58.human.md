This is a bug report about shell command injection when switching branches with special characters in branch names. Ondrej Pohorelsky describes a security issue where creating a branch with a `>` character followed by a filename (like `issue#1234>/tmp/dangerfile`) can cause unintended file creation when using bash tab completion.

The problem occurs because bash doesn't properly escape the `>` character during tab completion, causing it to be interpreted as a shell redirection operator. This leads to Git seeing an invalid branch name while simultaneously creating the specified file. The reporter notes this only happens in bash - zsh handles the escaping correctly.

While no patch is provided, this appears to be a legitimate security concern where Git could be tricked into file creation through branch name manipulation. The issue affects Git 2.49 on Fedora, and the reporter suggests Git should prevent this behavior regardless of which shell is being used. This would likely require changes to both Git's completion script and possibly Git's branch name validation.
