This is a style review in the ongoing Git daemon signal handling series. Junio C Hamano provides coding guideline feedback on Carlo Marcelo Arenas Belón's patch that introduces SA_RESTART fallback definitions in compat/posix.h.

The review focuses on two specific style violations in the proposed code:
1. Multi-line comments should have their opening/closing delimiters on separate lines from the comment text (current version puts opening delimiter on same line)
2. Nested preprocessor directives require indentation (current version lacks proper indentation for the #define inside #ifndef)

These are minor formatting issues that don't affect functionality but align with Git's documented coding conventions. The feedback continues Junio's pattern of close attention to code quality in this series, though this particular exchange is more about style than the core signal handling architecture being discussed elsewhere in the thread.

The review doesn't address the broader architectural questions about sigaction() vs siginterrupt() that are still open in the thread, nor does it comment on the technical merits of the SA_RESTART fallback itself. This appears to be a focused style check on a patch that's otherwise technically sound.
