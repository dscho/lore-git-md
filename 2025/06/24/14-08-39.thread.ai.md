Git daemon signal handling bugfix series (v1) addressing zombie process cleanup on OpenBSD and crashes on AIX. Core issue involves interrupted system calls during signal handling with platform-specific behavior around SA_RESTART.

Series structure:
1. Moves platform-specific SA_RESTART definitions from compiler flags in config.mak.uname into centralized compat/posix.h, removing custom COMPAT_CFLAGS entries for NonStop and QNX while maintaining their SA_RESTART=0 behavior via fallback definition
2. Adds SA_RESTART behavior tracking infrastructure in compat/posix.h (build system changes in Makefile, config.mak.uname, configure.ac, meson.build)
3. Modernizes daemon.c signal handling by replacing signal() with sigaction() for child_handler(), fixing known AIX crash (now includes SA_NOCLDSTOP and SA_RESTART flags, removes manual rearming requirement for SysV systems)
4. Explicitly handles EINTR during poll() operations, solving OpenBSD zombie process issue

Technical changes:
- New platform behavior tracking for SA_RESTART in compat/ with fallback definitions
- Signal handling modernization in daemon.c (child_handler()) using proper sigaction() setup
- Explicit EINTR handling for poll() loop
- Cross-platform fixes for OpenBSD (zombie processes) and AIX (crashes)
- Build system updates for new compatibility checks and centralized SA_RESTART handling

Implementation details:
- daemon.c changes now use sigemptyset() for signal mask initialization
- Removes legacy signal handler rearming in child_handler()
- Maintains backward compatibility while adopting POSIX signal handling patterns
- SA_RESTART flag usage in daemon.c may need clarification regarding platform-specific handling from patch 1
