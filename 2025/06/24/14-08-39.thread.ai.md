Git daemon signal handling bugfix series (v4) addressing zombie process cleanup on OpenBSD and crashes on AIX, with architectural discussion between Carlo Marcelo Arenas Belon, Junio C Hamano, Phillip Wood, and Chris Torek. Core issue involves interrupted system calls during signal handling with platform-specific behavior around SA_RESTART in poll() operations, plus race condition between check_dead_children() and poll().

Current implementation uses SA_RESTART toggling approach with set_sa_restart() helper wrapping poll() calls in daemon.c service loop. Phillip Wood strongly advocates for alternative minimal approach that would drop SA_RESTART manipulation entirely, remove patches 1 and 4, document platform behaviors, acknowledge remaining race condition, and align with git-daemon's original EINTR assumptions. Junio Hamano initially endorsed Phillip's observation that git-daemon's code paths are designed to handle EINTR properly, but Carlo Marcelo Arenas Belon now counters this by pointing to historical changes (including run_command integration) that may invalidate original assumptions, citing a specific bug as evidence of EINTR fragility.

Carlo Marcelo Arenas Belon now proposes an RFC patch implementing a self-pipe mechanism to address the race condition between SIGCHLD delivery and poll() interruption, representing a significant architectural shift from the SA_RESTART-focused approach. The implementation adds a pipe to the poll set with signal handler writing to it when SIGCHLD is received, ensuring the daemon checks for dead children even if poll() wasn't interrupted. Technical details include new global poll_pipe[2] array, modified child_handler(), expanded pollfd array, and non-blocking pipe configuration with CLOEXEC flag. The author notes this may double event handling in some cases and suggests a periodic poll() timeout might be more efficient, while mentioning a more radical prototype that could eliminate the signal handler entirely.
