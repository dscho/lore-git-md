Git daemon signal handling bugfix series (v1) addressing zombie process cleanup on OpenBSD and crashes on AIX. Core issue involves interrupted system calls during signal handling with platform-specific behavior around SA_RESTART.

Series structure:
1. Moves platform-specific SA_RESTART definitions from compiler flags in config.mak.uname into centralized compat/posix.h, removing custom COMPAT_CFLAGS entries for NonStop and QNX while maintaining their SA_RESTART=0 behavior via fallback definition - Junio C Hamano reviewed, noting this makes SA_RESTART available everywhere via fallback (potentially enabling builds on additional platforms) and identified grammatical errors in commit messages ("where" -> "are", "hs" -> "has") to fix
2. Modernizes daemon.c signal handling by replacing signal() with sigaction() for child_handler(), fixing known AIX crash (now includes SA_NOCLDSTOP and SA_RESTART flags, removes manual rearming requirement for SysV systems) - Junio questions continued need for empty handler function now that rearming is unnecessary, implementation uses sigemptyset() for signal mask initialization, Carlo Marcelo Arenas Belon submitted fixup adding UNUSED attribute to signo parameter in child_handler() to match implementation and prevent compiler warnings
3. Adds SA_RESTART behavior tracking infrastructure in compat/posix.h (build system changes in Makefile, config.mak.uname, configure.ac, meson.build)
4. Explicitly handles EINTR during poll() operations with new NO_SIGINTERRUPT build flag for platforms lacking siginterrupt() or where signal(SIGCHLD) doesn't set SA_RESTART (Windows, NonStop, QNX, MINGW), completing OpenBSD zombie process solution

- New platform behavior tracking for SA_RESTART in compat/ with fallback definitions (now reviewed by Junio with commit message fixes)

- Cross-platform fixes for OpenBSD (zombie processes) and AIX (crashes)
