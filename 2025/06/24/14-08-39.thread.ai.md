Git daemon signal handling bugfix series (v1->v3) addressing zombie process cleanup on OpenBSD and crashes on AIX, with architectural discussion between Carlo Marcelo Arenas Belon, Junio C Hamano, Phillip Wood, and Chris Torek. Core issue involves interrupted system calls during signal handling with platform-specific behavior around SA_RESTART in poll() operations, plus race condition between check_dead_children() and poll().

Current implementation includes SA_RESTART toggling with set_sa_restart() helper, while validated alternative is self-pipe approach (Junio-confirmed). Technical clarifications reveal:
- Flawed SA_RESTART detection in compat/posix.h (empty `#ifdef` block doesn't validate POSIX compliance as intended)
- Actual compilation failures come from `siginterrupt()` deprecation warnings
- Confirmed intentional behavior for platforms lacking SA_RESTART (QNX, NonStop, Windows)
- USE_NON_POSIX_SIGNAL flag documentation insufficient - now clarified it handles both missing SA_RESTART and Windows compatibility
- AIX crashes identified as consequence of current signal() fallback approach

Self-pipe implementation would:
- Create pipe2() file descriptors
- Add read end to poll()'s monitored fds
- Write to pipe in signal handlers to wake event loop
- Eliminate all SA_RESTART toggling infrastructure
- Solve both OpenBSD zombies and race condition (Phillip Wood confirmed works for poll()/select())
- Avoid platform-specific signal handling complexities entirely

Current architectural decision points:
1. SA_RESTART toggling (requires fixing platform detection, build system integration, documentation)
2. Self-pipe (more portable but needs new implementation)

Technical tradeoffs:
- Self-pipe: Eliminates platform code, robust race handling, simpler maintenance, avoids signal() fallback issues
- SA_RESTART: Already implemented, no extra fds, follows existing patterns but carries technical debt
