Git daemon signal handling and child process tracking redesign (v4/RFC) with three competing approaches under evaluation: SA_RESTART toggling (original series), documentation-only (Phillip Wood), and new pipe-based tracking (RFC). Core issue involves platform-specific signal handling behaviors (SA_RESTART, EINTR) and race conditions in child process cleanup, with Windows SIGCHLD inconsistencies adding complexity.

Current technical landscape:
1. Original SA_RESTART approach (Carlo Marcelo Arenas Belon):
   - set_sa_restart() helper in daemon.c
   - Platform-specific handling for poll() interruptions
   - Windows sigaction() behavior debates (errno=EINVAL vs matching signal())
   - Now includes autoconf detection for SA_RESTART support (new patch)
     - AC_CACHE_CHECK test for SA_RESTART in signal.h
     - Sets NO_RESTARTABLE_SIGNALS=UnfortunatelyYes when unavailable
     - Junio noted variable naming inconsistency (ac_cv_siginterrupt vs NO_RESTARTABLE_SIGNALS)

2. Minimal documentation approach (Phillip Wood):
   - Remove SA_RESTART manipulation
   - Document platform behaviors
   - Rely on git-daemon's EINTR handling (contested by Carlo)

3. New pipe-based tracking RFC (now two patches landed):
   - Introduces `parent_ipc_in` field in `struct child_process`
   - Child closes pipe descriptor to notify parent of exit
   - Parent monitors pipes via poll() in signal-free design
   - Dynamic pollfd array management with O(n) child scanning
   - Windows currently excluded due to pipe differences
   - Removes SIGCHLD handler entirely
