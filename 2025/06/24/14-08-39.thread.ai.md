Git daemon signal handling bugfix series (v4) addressing zombie process cleanup on OpenBSD and crashes on AIX, with architectural discussion between Carlo Marcelo Arenas Belon, Junio C Hamano, Phillip Wood, and Chris Torek. Core issue involves interrupted system calls during signal handling with platform-specific behavior around SA_RESTART in poll() operations, plus race condition between check_dead_children() and poll().

Current implementation uses SA_RESTART toggling approach with set_sa_restart() helper wrapping poll() calls in daemon.c service loop. Phillip Wood now strongly advocates for alternative minimal approach that would:
- Drop SA_RESTART manipulation entirely as unnecessary complexity
- Remove patches 1 and 4 from current series
- Document platform-specific behaviors (Solaris handler reset, AIX recursion) in commit messages
- Acknowledge remaining race condition that self-pipe would solve
- Align with git-daemon's original EINTR handling assumptions

Technical components under discussion:
- SA_RESTART flag necessity vs documentation-only approach
- Windows sigaction() return value consistency (SIG_ERR vs -1)
- Platform support matrix (Solaris, AIX, QNX, NonStop, Windows)
- Build system impacts (NO_RESTARTABLE_SIGNALS, configure.ac)
- Long-term maintenance tradeoffs (platform code vs self-pipe)
- Original design assumptions about EINTR handling in git-daemon

Participant positions:
- Phillip Wood: Strongly advocates for minimal solution, argues SA_RESTART manipulation solves non-problem, notes self-pipe remains viable alternative
- Carlo Marcelo Arenas Belon: Implemented current SA_RESTART solution with comprehensive platform support
- Junio C Hamano: Previously validated both approaches, identified SA_RESTART detection flaws

Open questions:
- Whether to adopt Phillip's simplified approach (now strongly advocated) or maintain SA_RESTART toggling
- Resolution of Windows sigaction() return value consistency
- Documentation of platform-specific behaviors and limitations
- Future direction regarding self-pipe implementation
- Validation of git-daemon's original EINTR handling assumptions

The series stands at critical decision point between existing SA_RESTART implementation and Phillip's proposed minimal approach. Phillip's latest email strengthens the case for simplicity by questioning the fundamental need for SA_RESTART manipulation, framing it as potentially solving a non-problem while adding platform-specific complexity. Both solutions address immediate platform issues while leaving race condition unresolved, but design philosophy divergence has become more pronounced.
