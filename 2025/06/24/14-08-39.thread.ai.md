Git daemon signal handling bugfix series (v4) addressing zombie process cleanup on OpenBSD and crashes on AIX, with architectural discussion between Carlo Marcelo Arenas Belon, Junio C Hamano, Phillip Wood, and Chris Torek. Core issue involves interrupted system calls during signal handling with platform-specific behavior around SA_RESTART in poll() operations, plus race condition between check_dead_children() and poll().

Final implementation adopts SA_RESTART toggling approach with new set_sa_restart() helper wrapping poll() calls in daemon.c service loop. Technical components include:
- SA_RESTART flag manipulation around poll() operations
- Conditional compilation via NO_RESTARTABLE_SIGNALS for platform support
- Maintained error handling for non-EINTR poll() failures
- Preserved socket event processing logic
- Windows compatibility through mingw-posix.h SA_NOCLDSTOP definition
- SIGCHLD handling standardized on sigaction() with BSD semantics
- Build system improvements for SA_RESTART detection (configure.ac, Makefile, meson.build)
- Validated alternative remains self-pipe approach (Junio-confirmed) which would:
  - Use pipe2() file descriptors
  - Add read end to poll()'s monitored fds
  - Write to pipe in signal handlers
  - Eliminate SA_RESTART toggling
  - Solve both OpenBSD zombies and race condition

Platform-specific resolutions:
- Fixed SA_RESTART detection in compat/posix.h
- Addressed siginterrupt() deprecation warnings
- Confirmed behavior for platforms lacking SA_RESTART (QNX, NonStop, Windows)
- USE_NON_POSIX_SIGNAL renamed to NO_RESTARTABLE_SIGNALS
- AIX crashes resolved via signal() fallback approach
- Windows sigaction() support added for SIGCHLD

Participant positions:
- Phillip Wood: Confirmed self-pipe technical viability
- Junio C Hamano: Validated both approaches, identified SA_RESTART detection flaws
- Carlo Marcelo Arenas Belon: Implemented SA_RESTART solution with comprehensive platform support

Final decision favors SA_RESTART toggling due to:
- Lower implementation complexity for current issues
- Maintains existing patterns
- Windows compatibility now properly handled
- Leaves door open for future self-pipe transition

Remaining considerations:
- Long-term maintenance of platform-specific signal code
- Potential future transition to self-pipe
- Documentation of signal handling behaviors
- Resource impact comparison (file descriptors vs platform code)

The series concludes with a working solution that addresses the immediate platform-specific issues while acknowledging the technical merits of the alternative approach. The final patch's set_sa_restart() helper provides a clean abstraction point should future migration to self-pipe be pursued.
