This is the third patch in a series fixing signal handling issues in the Git daemon, specifically addressing OpenBSD zombie processes and AIX crashes. Junio C Hamano is reviewing Carlo Marcelo Arenas Belón's implementation of explicit EINTR handling during poll() operations.

The patch introduces platform-specific handling via a new NO_SIGINTERRUPT flag for systems lacking proper signal interruption control (Windows, NonStop, QNX, MINGW). Junio raises two key concerns: First, he questions whether the signo parameter should be marked UNUSED on NO_SIGINTERRUPT systems where it's not actually used. Second, he criticizes the proliferation of conditional compilation (#ifdef) blocks, suggesting the code could be abstracted more cleanly.

The changes involve toggling SA_RESTART flags around poll() operations on platforms that support sigaction(), while maintaining the signal handler rearming behavior on legacy systems. This completes the series' solution for OpenBSD zombie processes by ensuring proper EINTR handling during the daemon's main service loop.

Junio's review focuses on code quality rather than functionality, indicating the technical approach is sound but could benefit from cleaner implementation. The patch appears ready for finalization pending resolution of these stylistic concerns.
