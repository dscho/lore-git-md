This is a reply in the ongoing discussion about making `make coccicheck` fail when Coccinelle suggests code changes. Jeff King (peff@peff.net) weighs in to support the original proposal from Junio Hamano.

The thread began with a patch to modify the build system so that `make coccicheck` would fail when Coccinelle semantic patches suggest modifications, rather than silently succeeding while generating patch files. Currently, developers might miss these suggested improvements since the command succeeds regardless of output.

Jeff King confirms the practical need for this change, noting that he's personally been surprised when `coccicheck` didn't fail despite suggesting changes. His brief reply indicates agreement with the original proposal, suggesting this straightforward build system improvement may gain quick acceptance. The change would help ensure developers don't overlook Coccinelle's suggestions when they do run the checks.

The discussion appears to be in early stages, but this endorsement from a core contributor suggests the change has merit and may proceed without significant debate. The patch would affect developers who use Coccinelle for code analysis, making the tool's feedback more visible in the build process.
