This is a discussion about port handling in Git's credential system, specifically regarding symbolic vs numeric port names. The thread has evolved from a specific bugfix for the git-credential-netrc helper to broader questions about credential protocol design.

Brian Carlson responds to Maxim Cournoyer's earlier email about symbolic port handling, making several key points. First, they argue that numeric ports should be used consistently throughout Git's credential protocol, with any conversion from symbolic names (like "smtps") to numbers (like 465) happening before credential requests are made. They cite git-credential(1) documentation which specifically mentions "port number" rather than "symbolic port" as supporting evidence.

The email also notes that the netrc format itself is underspecified regarding ports, with most tools (including libcurl) not supporting ports at all. Brian suggests that if symbolic ports are to be accepted in netrc files, the conversion to numeric ports should happen before sending data over the credential protocol, and mentions that Perl's `getservbyname` could be used for this purpose.

This continues an ongoing architectural discussion about where port resolution should happen (in helpers vs calling code) and whether Git should follow Emacs' exact-match model or implement system-level resolution. The email doesn't propose new code but reinforces the need for consistent behavior across Git's credential system.
