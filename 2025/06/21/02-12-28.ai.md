Regression fix for submodule remote refactoring series. This email from Lidong Yan identifies and proposes a solution for the segfault in t5582 tests that was introduced by patch 1/7 of the submodule remote lookup series. The issue stems from the removal of `branch->merge_name` in v3 while some code paths still relied on its null-check behavior.

The core problem manifests as null pointer dereferences in `builtin/fetch.c` when checking merge configurations. Yan's analysis shows the v3 changes broke the convention where `branch_has_merge_config()` would return false for null `branch->remote_name`. The proposed fix has two parts: updating `branch_has_merge_config()` to check `branch->set_merge` instead of `branch->merge`, and using `FREE_AND_NULL` in `merge_release()` to prevent double-free issues.

This is a focused technical correction to the earlier refactoring that removed `branch->merge_name`. The changes are minimal (2 lines in remote.c) but address a critical regression. The fix maintains the series' goal of simplifying the branch merge configuration while preserving the expected null-check behavior. Yan reports the solution passes t5582 tests locally, though the broader test suite would need verification. The patch doesn't affect the conceptual approach of the larger submodule remote lookup improvements but ensures stable operation of existing fetch behavior during the transition.
