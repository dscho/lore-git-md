This is a technical follow-up in the ongoing discussion about symbolic port handling in git-credential-netrc. Maxim Cournoyer responds to Andreas Schwab's RFC6335 reference by proposing a more robust port validation approach using Scheme's `getservbyname` system call, which would properly resolve symbolic port names (like "smtps") to their numeric equivalents (465).

The proposed solution demonstrates a working Scheme implementation that:
1. Validates numeric ports are within proper TCP range (1-65535)
2. Attempts to resolve symbolic names via `getservbyname`
3. Returns either the numeric port or false for invalid inputs

This moves beyond the previous regex-based validation (which only checked character sets) toward actual system-level resolution of service names. The example shows successful resolution of "smtps" to 465 while rejecting invalid cases like "unknown" and out-of-range numbers.

The email doesn't directly address the broader architectural questions raised in the thread (where port resolution should occur in Git's credential system), but provides a concrete example of how a helper might implement proper symbolic port handling. This implementation could inform either of the two proposed approaches - whether port resolution happens in the helper or calling code.

Key technical details:
- Uses POSIX `getservbyname` system call via Scheme's FFI
- Maintains backward compatibility with numeric ports
- Follows RFC6335 service name standards
- Demonstrates proper error handling for invalid cases

The response keeps the thread moving forward with a technically sound example, though the core design decision about responsibility for port resolution remains open.
