This is a bugfix for a regression in the submodule remote lookup series. Lidong Yan identifies and fixes a segfault in the test suite that emerged after Jacob Keller's v3 patch removed `branch->merge_name` while some code paths still depended on it.

The issue manifests as null pointer dereferences in `builtin/fetch.c` when checking merge configurations. Yan's analysis shows the problem stems from `branch_has_merge_config()` not being updated to use the new `set_merge` flag that replaced `merge_name`. The fix is straightforward - update the function to check `set_merge` instead of the old pointer check, plus a defensive `FREE_AND_NULL` change to prevent potential double-frees.

This appears to be a well-analyzed and narrowly scoped fix for a regression that was holding up the otherwise-approved submodule remote series. The change is minimal (just 2 lines) and comes with clear reproduction steps and test verification. Since the maintainer had already acked v3 pending this fix, this patch should unblock the series' application.
