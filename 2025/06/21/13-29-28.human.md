This is a follow-up in the ongoing discussion about symbolic port handling in git-credential-netrc, which touches on broader credential system design questions.

Maxim Cournoyer responds to Brian Carlson's architectural concerns about port name/number consistency across Git's credential system. The email provides a concrete data point from Emacs' auth-source library (which uses netrc format) showing that symbolic ports must match exactly - it doesn't automatically translate between names like "smtps" and numbers like 465. 

Cournoyer suggests Git could improve on this by having the credential helper itself convert between symbolic and numeric port representations, which would handle mismatched configurations (like having "smtps" in netrc but 465 in git config). This differs from Carlson's earlier suggestion that `git send-email` should do the conversion before credential lookup.

The exchange highlights the complexity of the issue - while the original patch was a straightforward regex fix for RFC6335 compliance, it's now clear the solution needs to consider system-wide credential matching behavior. Cournoyer acknowledges being new to Git's credential system and seems open to design guidance, while providing useful real-world context from Emacs' implementation.

This moves the discussion forward by:
1. Confirming symbolic/numeric port mismatches are problematic in practice
2. Proposing credential helper-side conversion as an alternative to caller-side resolution
3. Keeping focus on making the behavior intuitive for users while maintaining system consistency

The thread remains active with important design questions unresolved, particularly around where port resolution should happen in the credential lookup flow.
