Feature: First patch in a 2-part series introducing a new `git refs list` subcommand to consolidate ref listing functionality.

This patch lays the foundation for a new `git refs list` command that aims to eventually replace `git show-ref` (and potentially parts of `git for-each-ref`). The initial implementation focuses on core functionality, supporting basic filtering with `--head`, `--tags`, and `--branches` flags, plus pattern matching that mirrors `git show-ref`'s behavior. The implementation includes thorough documentation and appears well-structured, using Git's existing ref iteration APIs.

The patch is part of a Google Summer of Code project and comes with multiple mentor sign-offs, suggesting it has undergone some review. The author explicitly states this is just the first step, with plans to add more features incrementally based on community feedback. Key open questions remain about whether to keep the show-ref-style pattern matching as default or switch to for-each-ref patterns, and how to handle backward compatibility - these will likely generate discussion in the thread.

The technical implementation looks solid, with 95 lines of tests (not shown in the diff) providing good coverage. This appears to be a thoughtful start to what could become a significant refactoring of Git's ref listing functionality, though the long-term vision for replacing existing commands will need careful consideration.
