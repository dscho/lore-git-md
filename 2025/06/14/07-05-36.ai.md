Test patch for new `git refs list` subcommand. This is the second patch in a 2-part RFC series introducing a new subcommand to consolidate ref listing functionality currently split between `git show-ref` and `git for-each-ref`. The patch adds comprehensive tests (95 lines) verifying the new command's behavior and its parity with `git show-ref` for supported flags.

The test script `t1461-refs-list.sh` exercises all implemented features: filtering with `--branches`, `--tags`, and `--head` flags, pattern matching behavior, and combinations thereof. It establishes a test repository with annotated tags and multiple commits across branches to create a non-trivial ref namespace. The tests verify both the new command's standalone behavior and its backward compatibility with equivalent `show-ref` invocations.

Key test cases include: verifying correct output for individual filter flags, combined filters, pattern matching that returns both branch and tag refs (like "B"), and the default unfiltered behavior matching `show-ref`. The tests use Git's standard test infrastructure (`test_cmp`, `test_expect_success`) and follow project conventions for test organization.

This test coverage addresses one of the open questions from the RFC - how to ensure backward compatibility during the transition from `show-ref`. The thoroughness suggests serious consideration of the migration path, though future patches would need to test additional `show-ref` features (like `--abbrev`) as they're implemented. The test file is added to Meson's test suite configuration, ensuring it runs in CI.
