This is a feature proposal introducing a new `git refs list` subcommand, part of a Google Summer of Code project aiming to consolidate ref listing functionality. The RFC comes from Meet Soni and presents an initial implementation that mirrors `git show-ref` behavior while opening discussion about potentially adopting `git for-each-ref`'s more flexible matching semantics long-term.

The patch series (2 parts) establishes basic functionality with branch/tag/head filtering and pattern matching compatible with `show-ref`, while explicitly leaving room for future expansion of additional flags from both commands. The accompanying tests verify the core behavior matches expectations.

Key discussion points raised include whether to default to `for-each-ref` style matching (with a compatibility flag), which features from both commands to preserve, and how to handle backward compatibility. The author appears thoughtful about the design tradeoffs and is seeking early feedback before committing to an approach.

The implementation looks like a solid starting point - the commit adds proper documentation and thorough tests, and the cover letter clearly frames the open questions. This seems like a promising consolidation effort that could simplify Git's ref inspection interface, though the discussion around matching semantics will likely need careful consideration to avoid breaking existing scripts.
