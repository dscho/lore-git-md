This is a feature proposal introducing a new `git refs list` subcommand, part of a Google Summer of Code project aiming to consolidate ref listing functionality currently split between `git-show-ref` and `git-for-each-ref`. The RFC seeks feedback on design decisions before proceeding with implementation.

The patch series (2 parts) creates a new subcommand that initially mirrors `git-show-ref` behavior with support for basic filtering (--branches, --tags, --head) and pattern matching. The author acknowledges `git-for-each-ref` offers superior pattern matching but starts with show-ref compatibility, explicitly asking whether to switch defaults with a compatibility flag. Future work would add more show-ref options (--abbrev, --quiet, etc.) and potentially incorporate for-each-ref features.

Key discussion points raised: which matching style should be default, which existing features to preserve/drop from both commands, and backward compatibility strategy. The implementation appears thorough with documentation and 95 lines of new tests. This looks like a well-scoped GSoC project with clear technical questions for reviewers, though the long-term vision of fully replacing two existing commands with one may prove controversial. The patches themselves focus narrowly on core functionality while explicitly deferring many design decisions to community feedback.
