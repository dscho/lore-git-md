This RFC thread introduces a new `git refs list` subcommand that aims to consolidate the ref listing functionality currently split between `git show-ref` and `git for-each-ref`. The initial proposal comes as part of a Google Summer of Code project, with a 2-patch series implementing basic functionality and comprehensive tests.

The first patch established the core command with filtering options (`--branches`, `--tags`, `--head`) and show-ref-style pattern matching, while intentionally omitting some features for incremental review. The second patch, which just arrived, adds thorough testing - a 95-line test script that verifies all implemented functionality and ensures backward compatibility with `git show-ref` behavior. The tests create a non-trivial repository setup and systematically verify filtering combinations and pattern matching.

Open questions remain about the long-term direction, including whether to keep show-ref-style matching as default, how to handle backward compatibility with existing scripts, and which features to ultimately preserve from both commands. The technical foundation appears solid, with clean integration into the refs command framework and test coverage that demonstrates serious consideration of the migration path. Future work would expand the command to include more show-ref options and potentially incorporate for-each-ref features.
