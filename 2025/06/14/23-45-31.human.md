This is a response from Junio Hamano to an RFC proposing a new `git refs list` subcommand that would consolidate functionality from `git show-ref` and `git for-each-ref`. The response questions the fundamental premise of the proposal.

Hamano expresses skepticism about the need for a new command, noting that he primarily uses `show-ref` only for checking single refs in scripts (where its exit status is useful), and otherwise prefers `for-each-ref`. He suggests that even the exit-status checking could be handled by `rev-parse --verify`. His position is that rather than creating a new command, the project should be content with the existing tools.

The response doesn't engage with the technical implementation details of the RFC (which had shown a working implementation with comprehensive tests), but instead challenges whether the consolidation effort is worthwhile at all. This suggests the proposal may face significant resistance unless the author can make a stronger case for why the unification is needed beyond what the existing commands provide.

The tone is constructive but firm, coming from Git's maintainer, which means this feedback will likely need to be addressed before the proposal can move forward. The response focuses on the high-level design question rather than the specifics of the implementation.
