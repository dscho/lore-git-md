Feature implementation for refs consolidation effort. This is the first of two patches introducing a new `git refs list` subcommand as part of a GSoC project to unify reference handling. The patch establishes basic functionality mirroring `git show-ref`'s core features: listing refs with optional filtering by branches, tags, or HEAD, plus pattern matching that follows show-ref's suffix-based matching behavior.

The implementation adds a new `list` subcommand to `builtin/refs.c` with corresponding documentation. Key technical details: it uses `refs_for_each_*` iterators internally, maintains show-ref's exact pattern matching semantics (matching from refname end with complete path components), and includes object existence verification. The patch preserves show-ref's default behavior of showing all refs (tags, heads, remotes) when no filters are given.

This initial version intentionally omits some show-ref features (--abbrev, --quiet) for incremental review, as noted in the commit message. The implementation includes thorough error handling and matches show-ref's exit code behavior (1 when no refs match). The code structure suggests easy extensibility for future additions, with a clear `list_options` struct to hold additional parameters.

Open questions from the RFC context remain unresolved in this patch: whether to keep show-ref-style matching as the default long-term versus switching to for-each-ref patterns, and broader questions about the eventual relationship between this new command and the existing tools it aims to consolidate. The technical foundation appears solid, with clean integration into the existing refs command framework and comprehensive documentation.
