This is a documentation clarification regarding pre-built Git documentation repositories. 

Junio Hamano responds to Kristoffer Haugsbakk's patch that suggested adding explicit clone instructions for the gitster repositories (git-htmldocs and git-manpages) in Documentation/Makefile. While Kristoffer's patch aimed to help users avoid confusion with differently-named repositories in the git organization, Junio expresses clear disagreement with this approach, stating "I'd rather not see people do that."

The response is brief but significant as it indicates the maintainer's preference against directing users to clone from personal repositories (gitster) rather than the official git organization repositories. This suggests the original patch may need reconsideration or that there are unstated reasons why the gitster repositories shouldn't be the recommended source.

The thread had previously established that the gitster repositories follow more consistent naming conventions, but Junio's response now introduces a maintainer perspective that wasn't present in the initial technical discussion. This appears to be a turning point where the practical solution may need to yield to project policy.
