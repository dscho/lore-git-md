This is a response in the Git refs list RFC thread, questioning the fundamental premise of the proposed `git refs list` subcommand. Junio C Hamano expresses skepticism about the need to unify `git-show-ref` and `git-for-each-ref`, suggesting the project might be better served by letting `show-ref` remain as-is and using existing tools (`for-each-ref` or `rev-parse --verify`) for other use cases.

The response focuses on the core question of whether unification is desirable at all, noting that `show-ref`'s primary advantage (exit status checking for single refs) can already be achieved with `rev-parse --verify`. Hamano suggests the project might avoid adding a new command and instead work with the existing tools, implying the RFC's technical implementation may be solving a problem that doesn't need solving.

This challenges the RFC's foundational assumption and shifts the discussion from implementation details to project philosophy - whether Git benefits from command consolidation in this case. The response doesn't engage with the specific technical merits shown in the patches (thorough test coverage, clean implementation) but questions their necessity. Future discussion in the thread will need to address this higher-level concern before proceeding with feature details.
