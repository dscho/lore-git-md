Git refs list RFC: Initial proposal and first implementation patch for new `git refs list` subcommand to consolidate ref listing functionality (currently split between `git-show-ref` and `git-for-each-ref`). Part of a Google Summer of Code project. Current implementation (2-patch series) introduces basic `git refs list` with `--branches`/`--tags`/`--head` filtering and show-ref-style pattern matching (suffix-based from refname with complete path components). Implementation adds new `list` subcommand to `builtin/refs.c` using `refs_for_each_*` iterators, includes object existence verification, and preserves show-ref's default behavior of showing all refs when unfiltered. 

The second patch adds comprehensive tests (95 lines in `t1461-refs-list.sh`) verifying the new command's behavior and its parity with `git show-ref` for supported flags. Tests exercise all implemented features: filtering with `--branches`, `--tags`, and `--head` flags, pattern matching behavior, and combinations thereof. Test cases verify correct output for individual filter flags, combined filters, pattern matching that returns both branch and tag refs (like "B"), and the default unfiltered behavior matching `show-ref`. The test repository setup includes annotated tags and multiple commits across branches to create a non-trivial ref namespace. Tests use Git's standard infrastructure (`test_cmp`, `test_expect_success`) and follow project conventions.

Open questions remain from RFC: (1) whether to keep show-ref-style matching as default long-term or switch to for-each-ref patterns, (2) how to handle backward compatibility with existing scripts (partially addressed by test coverage showing show-ref parity), (3) which features to ultimately preserve from both commands, and (4) long-term vision for potentially replacing both existing tools. Technical foundation appears solid with clean integration into refs command framework and thorough test coverage, but consolidation of two established commands may generate discussion about necessity and transition path. Future work would add more show-ref options (like `--abbrev`) and potentially incorporate for-each-ref features, with code structure (`list_options` struct) designed for easy extensibility. The test file is added to Meson's test suite configuration, ensuring it runs in CI.
