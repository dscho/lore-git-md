This is a technical discussion about signature handling in Git's fast-export/import functionality, specifically addressing design questions raised about the v4 patch implementation. Christian Couder responds to Elijah Newren's concerns about the complexity of the current approach that adds explicit hash algorithm and signature format metadata ("gpgsig <hash-algo> <format>").

The email clarifies several key points: the signature format field was added based on brian m. carlson's earlier recommendation to help tools processing the output; the implementation supports dual signatures (SHA-1 and SHA-256) per commit as suggested by brian; and the hash algorithm field helps fast-import correctly reconstruct gpgsig/gpgsig-sha256 headers. Christian remains open to simplifying the approach if consensus favors it, but notes the current design follows prior technical guidance.

Unresolved issues include how to test dual-signature commits and whether to support unlimited signatures rather than the current two-signature limit. The discussion reveals differing perspectives on how much metadata is truly needed versus maintaining simplicity, with Christian leaning toward providing more information while acknowledging it may not all be strictly necessary. Documentation improvements are promised to better explain the fields' purposes.

This exchange represents a critical design checkpoint where the patch's technical approach is being reevaluated before finalization, with the author demonstrating willingness to adapt based on maintainer feedback while defending the current implementation's rationale.
