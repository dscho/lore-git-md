This is a follow-up discussion in the SHA-256 default hash transition series, focusing on test coverage for backward compatibility. The email responds to Junio C Hamano's inquiry about testing Git's ability to work with historical SHA-1 repositories when SHA-256 is the default.

Author brian m. carlson confirms that while dedicated interoperability tests for SHA-1/SHA-256 interaction will come later with the interoperability code, current test coverage for SHA-1 compatibility is already extensive but distributed across the test suite. They note that many existing tests implicitly verify SHA-1 compatibility through operations like cloning, submodule handling, and push/pull across various protocols (local, HTTP, SSH). The author acknowledges that some tests do explicitly test different hash algorithms, but emphasizes that the most thorough verification comes from running the entire test suite in SHA-1 mode to catch subtle edge cases.

The email also mentions ongoing work on SHA-256 interoperability (currently in a separate branch) that will eventually include comprehensive testing of same-hash, different-hash, and dual-hash scenarios. The author plans to add a CI job for this using their GIT_DEFAULT_HASH=sha256:sha1 test configuration. This response provides important context about the testing strategy but doesn't introduce new code changes - it's primarily addressing verification concerns about the existing patch series.
