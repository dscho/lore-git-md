This thread began as a bugfix for the git-credential-netrc helper's handling of symbolic port names (like "smtps") in netrc files, which was silently ignoring them despite git-send-email's support. The initial regex fix to follow RFC6335 standards was technically approved by Junio, but Brian Carlson raised broader concerns about consistency across Git's credential system.

The discussion has since evolved into a design question about where port resolution should occur - in the credential helper itself or in the calling code like git-send-email. Maxim Cournoyer, the original patch author, has been actively exploring solutions. His latest contribution demonstrates a robust Scheme implementation using `getservbyname` to properly resolve symbolic ports to numbers (e.g., "smtps" → 465), showing how either architectural approach could work technically.

Key participants include Maxim driving the implementation, Brian advocating for system-wide consistency, and Junio who approved the initial fix but left the larger design questions open. The thread now stands at a decision point: either document the current exact-match behavior (following Emacs' auth-source model) or make architectural changes to standardize where port resolution happens. Maxim's working example provides a concrete foundation for either path forward.
