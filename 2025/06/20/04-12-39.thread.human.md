This thread centers on how Git's credential helper system should handle symbolic port names (like "http" or "smtp") in netrc files. The discussion began with a simple regex fix but expanded into a design debate about where port resolution should happen - in the helper script itself or before the credential protocol is invoked.

Maxim Cournoyer has completed a v2 patch set that robustly implements helper-side resolution using the system's getservbyname() function. The series now includes all requested technical improvements: portable shebang handling, shared validation logic with git-send-email, support for hyphenated service names, and comprehensive test coverage. Brian Carlson raised an important design question by pointing out that the credential protocol documentation specifies "port number" (implying numeric-only), though existing practice in git-send-email accepts symbolic names.

Junio Hamano initially approved a simpler regex-based approach, but the thread now presents three complete technical options: the original regex, Maxim's helper-side resolution, or moving resolution entirely to the caller side (per Brian's interpretation of the protocol). The implementation work is done; what remains is for Junio to decide whether to accept symbolic port support (and if so, where the resolution should occur) or to enforce numeric-only ports as the protocol currently states. The decision will affect both the credential helper and may require updates to protocol documentation.
