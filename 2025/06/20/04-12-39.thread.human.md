This thread discusses how Git should handle symbolic port names (like "smtps") in credential helpers, particularly git-credential-netrc. The discussion began when Maxim Cournoyer proposed allowing symbolic ports in netrc files, which led to a deeper design question about where port resolution should happen - in the helper itself or by the caller before invoking the credential protocol.

Junio Hamano initially approved a simple regex change to accept symbolic ports, but Brian Carlson pointed out that the credential protocol documentation specifies "port number" (implying numeric-only). Maxim then sent a v2 patch series demonstrating helper-side resolution via getservbyname, with the third and final patch now implementing full support. The implementation is technically sound, adding a new Git::is_port() helper function used by both the credential helper and git-send-email, with proper test coverage.

However, the core design question remains unresolved: should helpers support symbolic ports at all given the protocol wording? Brian advocates for numeric-only based on the docs, while Maxim's implementation shows helper-side resolution works well in practice. The ball is in Junio's court to decide whether to accept this approach despite the protocol wording, update the protocol docs, or stick with numeric-only. The high-quality implementation makes this a policy decision rather than a technical one.
