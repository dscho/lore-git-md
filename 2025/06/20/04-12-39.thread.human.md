This thread addresses how Git's credential system should handle symbolic port names (like "smtps") in netrc files, prompted by a discrepancy where git-send-email documents support for such ports but git-credential-netrc silently ignores them. The discussion has evolved from a simple regex fix to a deeper design question about where port resolution should occur in Git's architecture.

Junio Hamano initially approved a regex change to validate symbolic ports per RFC6335 standards, but Brian Carlson raised system-wide concerns about consistency. Maxim Cournoyer then demonstrated a Scheme implementation using POSIX getservbyname for proper system-level resolution, providing a concrete alternative approach. The latest development comes from Carlson, who points to git-credential protocol documentation that refers only to "port numbers" (not symbolic names), arguing this suggests resolution should happen before the credential system gets involved - likely in calling code like git-send-email.

Three technical approaches are now on the table: the original regex validation, helper-side resolution (as Cournoyer showed), or caller-side resolution (Carlson's preference). The discussion has uncovered that libcurl doesn't support ports in netrc files at all, making this a somewhat unique case for the netrc helper. While the technical options are clear, the architectural decision about where to handle the conversion remains open, with Carlson's protocol documentation citation adding weight to moving resolution earlier in the call chain.
