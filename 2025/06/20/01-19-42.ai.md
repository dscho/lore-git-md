This is the final patch in a series preparing Git's transition to SHA-256 as the default hash algorithm. The patch enables SHA-256 as the built-in default when Git is compiled with the WITH_BREAKING_CHANGES flag, implementing the planned breaking change for Git 3.0. The change is minimal - just two files modified to switch the default hash algorithm definition in hash.h and update the test suite's default hash setting in t/test-lib.sh.

The patch maintains backward compatibility by keeping SHA-1 as the default when the breaking changes flag isn't set. The test suite is updated to automatically use SHA-256 when testing with breaking changes enabled, ensuring tests pass in this configuration. This completes the technical groundwork for the SHA-256 transition while allowing gradual adoption - users can test the new default by opting in via the build flag, while production builds remain on SHA-1 by default until Git 3.0.

The changes are straightforward mechanical updates that build on the extensive preparatory work in earlier patches to make Git's internals hash-agnostic. The patch follows the series' consistent approach of maintaining clear separation between legacy SHA-1 requirements (marked with GIT_HASH_ORIGINAL) and the new default hash algorithm. With this patch, the series appears complete and well-tested, providing a clear path for the SHA-256 transition while minimizing disruption to existing workflows.
