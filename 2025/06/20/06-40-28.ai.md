This is a feature patch in the ongoing `imap-send` authentication improvements series, adding PLAIN authentication support to the OpenSSL backend. The patch implements RFC 4616-compliant PLAIN authentication for OpenSSL, which was only available via libcurl previously. It introduces a new `plain_base64()` helper function that properly constructs the PLAIN authentication string (formatted as `\0user\0pass` per RFC) and base64 encodes it, plus an `auth_plain()` function that handles the protocol exchange. The implementation follows the same pattern as other auth methods in the series, using the existing `try_auth_method()` infrastructure.

Key technical details include:
- New `AUTH_PLAIN` capability flag added to enum CAPABILITY
- Documentation updated to list PLAIN as supported for both backends
- Memory-safe string handling via `strbuf` in `plain_base64()`
- Error handling matches other auth methods (returns NULL on encoding failure)
- Uses OpenSSL's `EVP_EncodeBlock()` for base64 encoding
- Follows the series' pattern of NULL function pointers when OpenSSL is unavailable

The change is well-contained and consistent with the architecture of the larger series, which has already addressed review feedback across multiple iterations. This fills a gap where PLAIN auth (commonly used with app passwords) was only available via libcurl, making the feature available regardless of transport backend.
