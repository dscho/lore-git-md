This is a follow-up in the ongoing discussion about the `RemoveBracesLLVM` clang-format rule for Git's code style. The thread has revealed that this experimental CI rule, which removes braces from single-statement conditional bodies, produces undesirable formatting in some real-world cases like `builtin/receive-pack.c`.

Junio Hamano weighs in on a specific example where the rule would remove braces from a `for` loop that most developers would prefer to keep braced for clarity. While he doesn't object strongly to either style, he notes there's no significant improvement from removing braces in this case. His pragmatic stance is that existing code shouldn't be churned to match this style, but new code could optionally follow it.

The discussion suggests this rule may not be ready for promotion to Git's main style guidelines, as it fails to consistently produce better formatting in practice. This aligns with earlier concerns about clang-format's limited ability to understand code semantics when making formatting decisions. The thread appears to be moving toward abandoning this particular style rule rather than adopting it more widely.
