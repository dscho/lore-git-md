This is a technical discussion about repository initialization behavior in the SHA-256 transition series. Junio C Hamano raises concerns about edge cases in the handling of version-less repositories (where core.repositoryformatversion is unset). The key point is whether clearing the repository format when version == -1 (which happens both for missing config files and for config files without a version) could unintentionally discard valid configuration.

The author, brian m. carlson, explains the current behavior is intentional for missing config files, noting that nearly all repositories since Git 0.99.3 include the version field. However, Junio points out this creates a subtle behavior change - extensions in version-less config files would now be ignored where they were previously honored. The discussion suggests this change might be acceptable given how rare such repositories are, but notes the documentation should be updated to reflect the new behavior.

This exchange shows careful attention to backward compatibility details in the SHA-256 transition work, with both parties agreeing the current approach is reasonable but needing documentation updates. The thread demonstrates the project's thoroughness in considering edge cases during major internal changes.
