Bugfix for `imap-send`'s CRAM-MD5 authentication handling, part of a larger series improving IMAP functionality. This patch specifically addresses a user experience issue where attempting to use CRAM-MD5 authentication without OpenSSL would result in a hard `die()` rather than a graceful error message.

The change moves the OpenSSL availability check earlier in the authentication flow and introduces a new `try_auth_method()` helper that centralizes error handling. When CRAM-MD5 is requested without OpenSSL support, users now get a clear error message explaining the dependency requirement before any connection attempt is made. This is part of broader improvements to authentication handling in the IMAP code that includes new OAuth2.0 support and fixes for PLAIN authentication.

The patch appears well-integrated with the rest of the series, which has undergone extensive review. It's a straightforward improvement that makes the failure mode more user-friendly while maintaining all existing functionality when OpenSSL is available.
