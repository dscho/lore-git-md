This is a bugfix follow-up to part 1 of the submodule remote lookup series, addressing a regression introduced in v3. Maintainer Junio C Hamano reports that the removal of `branch->merge_name` (a v3 simplification that replaced it with a `set_merge` flag) causes test t5582 to segfault. The original patch from Jacob Keller had removed this field as part of cleaning up duplicate merge name storage, but the crash indicates some code path still depends on the field being present.

The patch touches several key remote-handling files (remote.h, branch.c, builtin/pull.c, remote.c) with significant changes to the latter (42 lines modified). While the thread context shows the overall series is maintainer-acked and ready for application, this specific regression needs to be addressed before the series can proceed. The crash in t5582 (a pull/fetch test) suggests the issue manifests during common remote operations, making it a blocker for the otherwise-approved series.

This illustrates the careful balance in refactoring - while the removal of `branch->merge_name` was conceptually clean and reduced duplication, real-world usage patterns revealed an overlooked dependency. The fix will need to either restore the field with proper lifecycle management or adjust the crashing code path to use the new `set_merge` flag approach. Given the series' position in the `the_repository` removal effort and its maintainer approval, this is likely a minor adjustment rather than a fundamental rethink.
