This is the final patch in the SHA-256 default transition series, responding to Junio C Hamano's review about testing legacy SHA-1 repository compatibility. The author confirms they've already verified backward compatibility with version-less SHA-1 repositories, noting that test failures would be immediately obvious during development due to the extensive test coverage of basic operations like clone/fetch/push. The response highlights that the test suite already exercises both old-style format version 0 repositories and even no-config-file scenarios, having caught and fixed one bug during development. The author suggests that when Git 3.0 ships, the GIT_TEST_DEFAULT_HASH variable could be flipped to sha1 to maintain ongoing verification of SHA-1 compatibility. This addresses the core concern raised in review while also revealing the extensive test coverage that exists for legacy repository formats, including edge cases that predate explicit repository format version declarations. The response builds confidence in the transition by pointing to concrete testing mechanisms rather than theoretical assurances.
