This is a bugfix patch for the git-credential-netrc helper, addressing an issue with symbolic port handling. The patch modifies the Perl script to properly accept symbolic port names (like "submission" or "smtps") in addition to numeric ports, aligning with git-send-email's documented behavior. The change involves relaxing the port validation regex from `^\d+$` to `^[[:alnum:]]+$` and adding a clarifying comment.

The fix is straightforward - just a few lines changed in the credential helper script. The commit message clearly explains the problem (silent dropping of symbolic ports) and provides documentation evidence that symbolic ports are a supported use case. The patch appears well-scoped and correctly implements the described functionality without introducing obvious side effects.

Key technical details for future reference: the change affects `contrib/credential/netrc/git-credential-netrc.perl`, specifically the port validation logic in the `load_netrc` subroutine. The new regex pattern will match both numeric and alphabetic port names while maintaining the same basic validation structure. The patch preserves the existing behavior of deleting the port from `$nentry` after validation.
