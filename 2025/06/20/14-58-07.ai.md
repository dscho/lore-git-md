This is the final patch in the SHA-256 default transition series, implementing the actual switch to SHA-256 as the default hash algorithm when built with WITH_BREAKING_CHANGES. The patch modifies hash.h to conditionally define GIT_HASH_DEFAULT as either SHA-256 (with the flag) or SHA-1 (without), following the series' preparation work to distinguish between default/legacy hash usage via GIT_HASH_DEFAULT and GIT_HASH_ORIGINAL constants.

Junio C Hamano provides a minor style correction, pointing out that nested preprocessor directives should be indented per Git's coding guidelines (one space per nesting level after the #). The implementation itself appears sound, building on the extensive groundwork laid in previous patches to handle repository initialization, legacy format compatibility, and test suite adjustments.

The patch completes the technical implementation of SHA-256 as default while maintaining the transitional period where users can opt-in via WITH_BREAKING_CHANGES. This aligns with the project's documented plan to make SHA-256 the default in Git 3.0, providing an important security upgrade path. The only outstanding matter from earlier discussion remains the eventual renaming of GIT_HASH_ORIGINAL to a more explicitly SHA-1-specific identifier.
