This thread discusses transitioning Git to use SHA-256 as the default hash algorithm when built with the WITH_BREAKING_CHANGES option, targeting Git 3.0. The series, authored by brian m. carlson, builds on prior work to make Git's internals hash-algorithm-agnostic. The current version (v2) introduces clear semantic constants to distinguish between explicit SHA-1 usage (GIT_HASH_SHA1) and legacy SHA-1 fallback behavior (GIT_HASH_SHA1_LEGACY), with SHA-256 becoming the new default (GIT_HASH_DEFAULT).

The latest patch adds the GIT_HASH_SHA1_LEGACY constant to formally represent cases where SHA-1 is required for compatibility with older formats like bundle v1/v2, rather than being explicitly chosen. While currently identical in value to GIT_HASH_SHA1, this distinction is crucial for the transition's clarity. The change is minimal but foundational, establishing vocabulary for subsequent patches that will update actual usage sites.

Junio C Hamano has approved the technical approach, and naming discussions have been resolved. However, one key debate remains unresolved: whether commands run outside any repository should use the new SHA-256 default (brian's preference) or fall back to SHA-1 for script compatibility (Patrick Steinhardt's position). The series is otherwise complete with comprehensive test coverage, though some documentation updates and CI job details remain to be addressed. This work is separate from the ongoing SHA-256 interoperability effort.
