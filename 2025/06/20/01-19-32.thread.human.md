This thread documents the final technical approval of a major change to make SHA-256 the default hash algorithm in Git when built with the WITH_BREAKING_CHANGES flag, targeting Git 3.0. The series, authored by brian m. carlson, builds on years of work to make Git's internals hash-algorithm-agnostic.

The v2 series has now addressed all technical feedback from both maintainer Junio C Hamano and reviewer Patrick Steinhardt. Key changes include renaming constants for clarity (GIT_HASH_ORIGINAL → GIT_HASH_SHA1_LEGACY), improving test infrastructure to dynamically detect hash algorithms, and expanding documentation. Kristoffer Haugsbakk's range-diff shows the clean rebase work responding to this feedback.

While the technical implementation is now complete, two items remain: documentation for handling version 0 repositories needs updating, and there's an unresolved debate about whether external commands should use the new GIT_HASH_DEFAULT (SHA-256) or fall back to GIT_HASH_SHA1_LEGACY for compatibility. Patrick Steinhardt advocates the conservative SHA-1 fallback approach, while the author maintains the position for using SHA-256 as the new default.

This change represents a significant milestone in Git's evolution, though the full transition - including SHA-256/SHA-1 interoperability - remains future work. The series is now presumably queued for inclusion in Git 3.0 whenever that release is scheduled.
