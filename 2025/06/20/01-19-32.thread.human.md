This thread covers brian m. carlson's series to prepare Git for transitioning to SHA-256 as the default hash algorithm when built with WITH_BREAKING_CHANGES, targeting Git 3.0. The changes introduce new constants (GIT_HASH_DEFAULT and GIT_HASH_ORIGINAL) to distinguish between default/legacy hash usage, with 11 files updated to handle the transition while maintaining backward compatibility with SHA-1 repositories.

Junio C Hamano has reviewed and approved the technical implementation after examining edge cases in repository initialization, suggesting only a style correction to preprocessor indentation. He maintains that while GIT_HASH_ORIGINAL works as a transitional name, it should eventually be renamed to something explicitly mentioning SHA-1 (like GIT_HASH_MUST_BE_SHA1) for long-term clarity. 

In a final review comment, Junio raises an important practical consideration about ensuring comprehensive testing of backward compatibility, particularly with version-less historical SHA-1 repositories. While not blocking the series, this serves as a reminder to validate that Git remains fully functional with all existing repositories regardless of their format version status. The series is now complete from a technical standpoint, with SHA-256 becoming the default when WITH_BREAKING_CHANGES is set, though some naming decisions and interoperability work remain as follow-ups.
