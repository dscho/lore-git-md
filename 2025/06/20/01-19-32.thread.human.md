brian m. carlson has proposed a series to prepare Git for SHA-256 as the default hash algorithm, targeting Git 3.0 when built with WITH_BREAKING_CHANGES. The changes introduce new constants (GIT_HASH_DEFAULT for SHA-256 and GIT_HASH_ORIGINAL for SHA-1) to clearly distinguish between default/legacy usage, updating repository setup and legacy format handling across 11 files. The test suite has been adjusted to be hash-algorithm-agnostic.

Junio C Hamano has raised concerns about the GIT_HASH_ORIGINAL constant, questioning whether it adds meaningful documentation value beyond the existing GIT_HASH_SHA1. He argues that the name might misleadingly suggest the constant could change in the future, when in fact these legacy formats will always require SHA-1. This touches on an architectural decision about how to document and maintain the distinction between SHA-1 usage by default versus historical necessity.

The series is technically complete and tested, but this discussion may lead to revisions in how the hash algorithm constants are named and documented. The broader SHA-256 interoperability work remains ongoing as a separate effort.
