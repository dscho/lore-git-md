This thread documents the final stages of implementing SHA-256 as Git's default hash algorithm when built with the WITH_BREAKING_CHANGES flag, targeting Git 3.0. Authored by brian m. carlson, the series builds on years of work to make Git's internals hash-algorithm-agnostic. The v2 patches have been technically approved by both maintainer Junio C Hamano and reviewer Patrick Steinhardt, with Kristoffer Haugsbakk providing a range-diff showing clean rebase work.

The key change makes SHA-256 the default while maintaining backward compatibility through clear constants (GIT_HASH_DEFAULT for SHA-256, GIT_HASH_SHA1_LEGACY for fallback cases). The test infrastructure was improved to dynamically detect the hash algorithm rather than relying on build flags. While most technical issues are resolved, some documentation updates remain, and the Git 3.0 release timing hasn't been addressed.

The most recent discussion focused on how commands like `index-pack` and `ls-remote` should behave outside repositories. Patrick Steinhardt, while initially advocating for SHA-1 fallback behavior, has softened his position and now accepts brian m. carlson's argument that these commands should use GIT_HASH_DEFAULT (SHA-256) for long-term usability, despite some short-term transition pain. This marks significant progress on the last major point of contention in the series.

With both technical and behavioral questions largely settled, the series appears ready for merging pending final documentation updates. The SHA-256 interoperability work remains as follow-up work separate from this initial default transition.
