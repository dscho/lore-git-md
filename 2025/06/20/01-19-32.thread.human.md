This thread centers on preparing Git for a transition to SHA-256 as the default hash algorithm, targeting Git 3.0 when built with the WITH_BREAKING_CHANGES option. The series, authored by brian m. carlson, introduces new constants (GIT_HASH_DEFAULT for SHA-256 and GIT_HASH_LEGACY_SHA1 for SHA-1) to clearly distinguish between default/legacy versus intentional SHA-1 usage. The technical implementation has been thoroughly reviewed by Junio C Hamano, who approved the approach after examining edge cases. The series includes comprehensive test coverage for backward compatibility with SHA-1 repositories and handles subtle initialization behaviors.

In a recent follow-up, Patrick Steinhardt validated the design's semantic distinction between explicit SHA-1 selection (GIT_HASH_SHA1) and format-implied legacy behavior (GIT_HASH_ORIGINAL/LEGACY_SHA1). He provided a concrete example from the reftable format, showing how version 1 implicitly uses SHA-1 while version 2 explicitly specifies the hash algorithm. This discussion reinforced the value of the constants' design for clarifying previously ambiguous cases in the codebase.

The series is now complete with only minor documentation updates remaining. The broader SHA-256 interoperability work remains a separate effort, and Git 3.0 release timing has not yet been addressed. The technical consensus appears strong, with both the maintainer and other domain experts supporting the approach.
