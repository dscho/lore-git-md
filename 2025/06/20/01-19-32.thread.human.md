This thread documents the implementation of SHA-256 as Git's default hash algorithm when built with the WITH_BREAKING_CHANGES flag, targeting Git 3.0. The series, authored by brian m. carlson, builds on years of work to make Git's internals hash-algorithm-agnostic. The key innovation is distinguishing between three cases: SHA-256 as the new default (GIT_HASH_DEFAULT), explicit SHA-1 selection (GIT_HASH_SHA1), and legacy SHA-1 fallback behavior (GIT_HASH_SHA1_LEGACY).

The 11-part series has progressed through careful technical review, with Junio C Hamano approving the overall approach. The final patch makes SHA-256 the conditional default in hash.h and updates the test suite to automatically detect the active hash algorithm via `git version --build-options`. This completes the core implementation while maintaining backward compatibility - a significant milestone given the sensitivity of hash algorithm changes.

One open debate remains regarding whether commands outside a repository should use GIT_HASH_DEFAULT (brian's position) or GIT_HASH_SHA1_LEGACY (Patrick Steinhardt's preference) for script compatibility. Documentation updates and final CI job configurations are still needed, but the technical foundation is now in place for Git 3.0's planned breaking change. The series represents a major step toward SHA-256 adoption while carefully preserving compatibility with existing SHA-1 repositories.
