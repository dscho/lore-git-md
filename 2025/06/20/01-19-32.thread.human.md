This thread documents the final steps in preparing for Git's transition to SHA-256 as the default hash algorithm when built with the WITH_BREAKING_CHANGES option (targeting Git 3.0). brian m. carlson, who previously led the hash-algorithm-agnostic internals work, has implemented a series that introduces new constants (GIT_HASH_DEFAULT and GIT_HASH_ORIGINAL) to distinguish between default/legacy vs intentional SHA-1 usage across the codebase.

The technical implementation is now complete after extensive review, with the final patch conditionally defining GIT_HASH_DEFAULT as SHA-256 when breaking changes are enabled. Junio C Hamano provided the last required feedback - a style correction regarding preprocessor indentation - which the author will incorporate. The series has been thoroughly tested for backward compatibility with legacy repositories, including tricky version-less SHA-1 cases.

The only remaining open question is the long-term naming of the SHA-1 constant (currently GIT_HASH_ORIGINAL), with Junio suggesting a future rename to something more explicit like GIT_HASH_MUST_BE_SHA1 for clarity. This can be addressed post-transition. The SHA-256 interoperability work remains a separate effort. With comprehensive test coverage confirmed and Junio's approval of the technical approach, this foundational change appears ready for inclusion in Git's path toward 3.0.
