This thread introduces a major change coming in Git 3.0: making SHA-256 the default hash algorithm when built with the WITH_BREAKING_CHANGES flag. The series, sent as a cover letter with multiple patches, prepares for this transition by introducing new constants (GIT_HASH_DEFAULT and GIT_HASH_ORIGINAL) and updating the codebase to handle the concept of a default hash algorithm. 

The author has structured the work to clearly distinguish between legacy SHA-1 usage and intentional SHA-1 cases, with particular attention paid to repository setup and test suite adjustments. Testing across different configurations (no default hash, SHA-1, and SHA-256) has shown the changes to be stable. While SHA-256 interoperability work remains ongoing, this series focuses specifically on establishing SHA-256 as the default when explicitly enabled, requiring surprisingly few code changes thanks to good prior architectural decisions. The author acknowledges the SHA-1 constant addition might be controversial but argues it serves an important documentation purpose for future maintainers.
