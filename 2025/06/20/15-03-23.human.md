This is a follow-up discussion on the SHA-256 default transition series, specifically addressing testing concerns for backward compatibility. Junio C Hamano responds to the final patch that enables SHA-256 as the default hash algorithm when built with WITH_BREAKING_CHANGES.

The core concern raised is ensuring robust backward compatibility - that Git will still properly handle existing SHA-1 repositories even when SHA-256 is the default. Junio specifically calls out untested edge cases around repositories that don't declare a format version, which have been in use for years. This is a critical verification point before the SHA-256 default can ship in Git 3.0.

The response comes from the project maintainer and indicates general approval of the technical approach (as seen in the thread context), while surfacing important real-world testing considerations. The series appears technically sound but needs additional validation of legacy repository handling, particularly for version-less repos that predate the repository format versioning system. This is the kind of subtle interoperability issue that often surfaces late in major transitions.
