This is a discussion about the ongoing SHA-256 transition effort, specifically addressing the naming of constants for hash algorithm selection. Junio C Hamano responds to brian m. carlson's patch that replaces SHA-1 references with GIT_HASH_ORIGINAL in legacy format handling code.

The email acknowledges the value of GIT_HASH_ORIGINAL as a transitional marker to distinguish between "not-yet-updated" and "must-stay-SHA-1" code locations. However, Hamano suggests that once the transition is complete, the constant should be renamed back to something explicitly mentioning SHA-1 (like GIT_HASH_MUST_BE_SHA1) for long-term clarity, since developers shouldn't need to remember the historical context of "original" meaning SHA-1.

This continues the thread's debate about constant naming philosophy - whether to prioritize transitional documentation (ORIGINAL) or long-term explicitness (SHA-1). Hamano's response indicates approval of the technical approach while questioning the naming strategy's long-term implications.
