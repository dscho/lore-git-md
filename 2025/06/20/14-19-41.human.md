This is part of the ongoing SHA-256 transition series, specifically addressing how Git commands behave when operating outside a repository. Patch 3/10 in the series updates several builtin commands (`apply`, `diff`, `hash-object`, etc.) to use `GIT_HASH_DEFAULT` rather than hardcoded `GIT_HASH_SHA1` when no repository context is available.

The change is straightforward - eight commands that can operate outside a repository now default to whatever hash algorithm is configured as the system default (currently SHA-1, but this prepares for SHA-256 becoming the default). Junio C Hamano notes this demonstrates the value of having a `GIT_HASH_DEFAULT` constant, though he's previously questioned the utility of the related `GIT_HASH_ORIGINAL` constant elsewhere in the series.

The patch is cleanly implemented with minimal changes to each command - just swapping one constant for another. The commit message clearly explains the change and its future-proofing purpose. This appears to be a non-controversial piece of the larger SHA-256 transition work.
