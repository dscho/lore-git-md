This is a bugfix patch in the ongoing `imap-send` series, specifically addressing a memory leak in the CRAM-MD5 authentication path. The patch fixes a case where the `response` buffer allocated in `auth_cram_md5()` would not be freed if the subsequent `socket_write()` operation failed. The fix adds the missing `free(response)` call in the error path before returning.

The change is small but important - it plugs a memory leak that would occur during failed authentication attempts when using CRAM-MD5. The patch maintains the existing behavior where successful writes still free the buffer after use. This is part of a larger series that has undergone extensive review, with this particular fix being a straightforward improvement to the error handling path.

The patch touches only the CRAM-MD5 authentication code in `imap-send.c`, modifying the error path to properly clean up allocated memory. It follows the pattern seen elsewhere in the series of improving memory management and error handling. The change is minimal and focused, with no apparent impact on other authentication methods or IMAP functionality.
