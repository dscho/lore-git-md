This is the final patch in a series implementing SHA-256 as Git's default hash algorithm when built with WITH_BREAKING_CHANGES, preparing for Git 3.0. The patch makes the actual switch by conditionally defining GIT_HASH_DEFAULT as SHA-256 when the breaking changes flag is set, while maintaining SHA-1 as the default otherwise.

Junio C Hamano approves the change with a minor style correction, pointing out that nested preprocessor directives should be indented according to Git's coding guidelines (one space per nesting level after the #). The author had used a different indentation style in the original patch.

The change is straightforward - it simply flips the default hash algorithm when the breaking changes mode is enabled. The accompanying test suite updates ensure everything continues to work with the new default. This represents the culmination of the series' technical work after earlier patches established the infrastructure and handled edge cases.

With this patch, users can now test SHA-256 as the default algorithm by building with WITH_BREAKING_CHANGES, while production builds continue using SHA-1 by default until Git 3.0. The only remaining discussion point from the thread is the long-term naming of the SHA-1 constant (currently GIT_HASH_ORIGINAL), which Junio suggests should eventually be renamed to something more explicitly SHA-1-specific.
