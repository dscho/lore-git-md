This is a bugfix patch addressing a segfault in the files backend's batched reference updates, part of the v5 series that was recently merged. The patch fixes a critical issue where failed updates weren't being properly skipped in two loops within `files_transaction_finish()`, which could lead to crashes. The fix adds checks for `update->rejection_err` in both loops to ensure failed updates are skipped as intended.

The patch includes three new test cases in `t/t1400-update-ref.sh` that verify the fix handles various error cases correctly: deleting a symbolic ref pointing to a non-existent ref, deleting with an incorrect old_oid, and deleting a non-existent ref. These tests ensure the batched update mechanism properly reports errors without crashing.

This was the first of two patches in the final v5 series that addressed production issues with batched reference updates. The changes build on commit 23fc8e4f61 which originally introduced batched reference update support. The patch is well-contained, focusing specifically on the segfault issue while maintaining the existing behavior where some updates in a batch can fail while others succeed.

The technical changes are straightforward - adding two `continue` statements when `rejection_err` is set - but the test coverage is thorough, exercising different failure modes. This matches the series' goal of making batched updates production-ready while maintaining their performance benefits. The patch has already undergone multiple rounds of review and was approved by both Christian Couder and Junio Hamano before merging.
