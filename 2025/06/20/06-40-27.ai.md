Feature patch adding OAuth2.0 authentication support for `imap-send`, part of a larger series (v19 04/10) that has been through extensive review. This specific patch implements both RFC-standard OAUTHBEARER and Google's XOAUTH2 mechanisms for both OpenSSL and libcurl backends.

The implementation adds new authentication functions `oauthbearer_base64()` and `xoauth2_base64()` that construct the proper protocol-specific strings (with proper escaping and base64 encoding) from user credentials. The patch documents the new auth methods in both config and command documentation, with specific guidance for Gmail and Outlook users. For libcurl, it uses `CURLOPT_XOAUTH2_BEARER` which automatically handles both protocols.

Key technical details: The OAUTHBEARER implementation follows RFCs 5801 and 7628 for GS2 header construction, while XOAUTH2 matches Google's proprietary spec. Both methods use the existing credential system but treat the password field as an access token. The patch maintains backward compatibility by falling back to basic auth when OAuth isn't specified. Documentation explains the tradeoffs between OAuth and app-specific passwords for services like Gmail.

This appears to be a well-considered implementation with thorough documentation updates. The thread context shows this has been refined through 19 versions with input from multiple maintainers, suggesting the approach is now technically sound. The only notable limitation is that host/port fields are omitted from OAUTHBEARER requests per RFC7628, which might affect some enterprise configurations.
