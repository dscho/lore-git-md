This is a follow-up in the ongoing discussion about the `RemoveBracesLLVM` clang-format rule. Junio Hamano responds to Karthik Nayak's example from `builtin/receive-pack.c` where the rule removes braces from a multi-line `for` loop body, which goes against Git's typical style of keeping braces in such cases.

Junio takes a pragmatic stance - while he doesn't object strongly to the specific formatting change shown, he notes it doesn't provide significant improvement either. He distinguishes between existing code (where such changes aren't worth the churn) and new code (where following the suggested style might be reasonable). This reinforces his earlier concerns about the rule's limitations in semantic analysis.

The email suggests the rule may be too blunt an instrument, as it can't distinguish between simple one-liners (where brace removal might be fine) and more complex cases (where braces aid readability). This aligns with the thread's growing skepticism about promoting the rule to Git's main formatting configuration. The discussion appears to be moving toward either keeping the rule as a non-blocking CI suggestion or abandoning it entirely.
