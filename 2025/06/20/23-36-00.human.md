Maintainer follow-up on submodule remote refactoring series. Junio C Hamano reports a test failure (segfault in t5582) introduced by Jacob Keller's patch that removes the `branch->merge_name` field as part of the submodule remote lookup improvements. The patch was part of v3 of the series, which had otherwise been acked by Junio.

This is a bugfix follow-up to what was previously considered a clean simplification - replacing the dual storage of merge names with a single `set_merge` flag. The segfault suggests there's an edge case where the removed field was still being accessed, likely during branch operations. Since this is part of a larger, maintainer-acked series that's otherwise ready to go, the issue will presumably be addressed quickly, either with a fix from Jacob or guidance from Junio.

The context shows this was part of preparatory work for the URL-based remote lookup changes in later patches, so resolving this regression is important for the overall series' stability. Test t5582 appears to be catching a real problem that wasn't surfaced in the submodule-specific tests (t7406) that were the focus of most verification in this series.
