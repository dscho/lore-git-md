This is a feature series preparing for Git 3.0's planned breaking change to make SHA-256 the default hash algorithm. Brian Carlson proposes making this behavior testable now via a new build option (WITH_BREAKING_CHANGES), allowing users to validate their environments before the official switch.

The series introduces two symbolic hash identifiers - one for the new default algorithm and one specifically marking SHA-1 usage for backward compatibility (which the author notes as potentially controversial but useful for documentation). Most patches then update various code paths to use these constants appropriately, with surprisingly few changes needed due to good prior design. The testsuite is adapted to handle different default algorithms, and the final patch enables SHA-256 by default when the breaking changes flag is set.

Carlson reports thorough testing across multiple configurations and notes significant progress (though not completion) on SHA-256 interoperability work. The changes appear well-considered and minimally invasive, with the author crediting previous contributors for making this transition smoother than expected. The series seems ready for review, though the SHA-1 documentation constant may spark discussion about its necessity versus verbosity.
