This is a refactoring patch that's part of a larger series (3/10) to handle hash algorithm defaults more consistently. The patch changes several builtin commands to use `GIT_HASH_DEFAULT` instead of hardcoding `GIT_HASH_SHA1` when operating outside a repository. 

The key technical change is replacing explicit SHA-1 references with the default hash algorithm in 8 different builtin commands (`apply`, `diff`, `hash-object`, `index-pack`, `ls-remote`, `patch-id`, `shortlog`, and `show-index`). The commit message explains this is a no-op currently since the default is still SHA-1, but prepares for potential future hash algorithm changes. 

Each change follows the same pattern - when a command runs outside a repository (`nongit` is true) and no hash algorithm is set, it now uses the system default rather than explicitly falling back to SHA-1. The patch includes comments explaining the rationale for each case, with some commands needing the hash for object processing while others use it for compatibility with remote repositories.

This appears to be a well-considered change that maintains current behavior while making the code more future-proof. The patch is cleanly focused on its stated goal and touches only the relevant parts of each command. The changes are mechanical but important for the larger transition away from SHA-1 assumptions in the codebase.
