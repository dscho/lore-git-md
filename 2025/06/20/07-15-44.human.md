Bugfix for batched reference updates in the files backend. This is the first of two patches in the final v5 series addressing edge cases in batched reference updates, now merged to master.

The patch fixes a segfault that could happen when processing failed updates in batched mode. The issue occurs in `files_transaction_finish()` where two loops weren't properly skipping updates that had already failed (marked with `rejection_err`). The fix adds the missing skip checks in both loops.

Three new test cases verify the fix handles different failure scenarios correctly: deleting a symbolic ref pointing to a non-existent ref, deleting with an incorrect old OID, and deleting a non-existent ref. The tests confirm the proper error messages are shown without crashing.

This was the more straightforward of the two issues in the series, with the second patch handling the more complex directory/file conflict case. The changes here are clean and well-tested, addressing a clear bug in the original batched updates implementation from commit 23fc8e4f61.
