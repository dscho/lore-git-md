This is a patch series improving error messages in `git imap-send`, building on the ongoing discussion about IMAP functionality. The series comes from a new contributor (Jörg Thalheim) and addresses two specific UX issues that emerged from Aditya Garg's earlier work on IMAP error reporting.

The first patch fixes confusing terminology in an error message, changing "store" to the more accurate "folder" when referring to IMAP configuration. The second patch enhances error messages by using Git's `advise()` API to show users example `git config` commands when required settings are missing. Both patches represent incremental improvements to the user experience while the broader IMAP functionality questions (raised by Junio Hamano) remain under discussion elsewhere.

The series is rebased on the `ag/imap-send-resurrection` branch as requested, showing awareness of the parallel IMAP work. The changes are small (9 lines total) but focused on concrete pain points users encounter. The switch from direct `fprintf` to `error()`/`advise()` follows Git's standard patterns for message handling. While this doesn't address the deeper IMAP implementation questions, it provides immediate value by making configuration problems more diagnosable.
