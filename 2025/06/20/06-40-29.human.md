Feature patch adding command-line folder specification to `git imap-send`. This is part of a larger v19 series improving IMAP functionality, with this patch introducing a new `--folder` option to override the default IMAP destination folder set in config.

The change allows users to specify a target folder directly via `-f` or `--folder` when running `git imap-send`, with the command-line value taking precedence over the `imap.folder` config setting. The documentation is updated to clarify this precedence and to fix some minor formatting inconsistencies (switching quotes to backticks for command/field references).

Implementation is straightforward - adds a new `opt_folder` string variable populated via `OPT_STRING`, which when set replaces the config-derived `server.folder` value. The patch maintains the existing memory management pattern of using `xstrdup` for the folder string.

This appears to be a well-contained quality-of-life improvement that aligns with the series' broader goal of making `imap-send` more flexible and user-friendly. The change is small but meaningful for users who frequently need to send patches to different IMAP folders.
