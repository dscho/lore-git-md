This is a naming discussion in the ongoing SHA-256 transition series, specifically about how to label the constant representing SHA-1 usage in legacy formats.

Junio C Hamano and brian m. carlson are finalizing the name for the SHA-1 constant used when handling pre-hash-aware Git formats (like bundle v1/v2). The current name `GIT_HASH_ORIGINAL` is being reconsidered to make the SHA-1 relationship more explicit. 

Carlson proposes `GIT_HASH_LEGACY_SHA1` as an alternative, rejecting his earlier idea of an obscure ext2 filesystem reference (`GIT_HASH_GOOD_OLD_REV`) as too cryptic. Junio agrees that including "SHA1" in the name is the key requirement, and finds the legacy naming acceptable.

This wraps up one of the last open questions in the series, which had previously addressed technical concerns about repository initialization edge cases and test coverage. The discussion confirms the maintainer and author are aligned on both the technical approach and now the naming convention for this important constant in the SHA-256 transition work.
