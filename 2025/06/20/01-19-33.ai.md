This is a refactoring patch that's part of a larger series (1/10) preparing for potential future hash algorithm changes. The patch introduces a new constant `GIT_HASH_DEFAULT` set to `GIT_HASH_SHA1`, which will be used throughout the codebase to represent the default hash algorithm rather than directly using `GIT_HASH_SHA1`.

The change is motivated by the possibility that Git may switch default hash algorithms in the future (from SHA-1 to something else). By centralizing the default hash reference through this constant, future transitions would only require updating this single definition rather than numerous direct SHA-1 references across the codebase.

The implementation is straightforward - it simply adds the new constant definition in hash.h alongside other hash-related constants. The patch appears well-scoped and focused, though as the first in a series, its full impact will depend on subsequent patches that actually use this constant. The commit message clearly explains the rationale and the mechanical nature of the change.
