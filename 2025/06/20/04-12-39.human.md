This is a bugfix for the git-credential-netrc helper, addressing an inconsistency with symbolic port names. The patch fixes a case where the Perl-based netrc credential helper would silently drop symbolic port names (like "submission" or "smtps") while numeric ports worked fine. The change aligns the helper's behavior with git-send-email's documented support for symbolic ports.

The fix is straightforward - it modifies the port number validation regex to accept alphanumeric strings rather than just digits. The patch includes a clarifying comment noting that ports can be either numeric or symbolic. This appears to be a well-scoped change that properly addresses the documented use case without introducing new complexity.

The change affects only the contrib/credential/netrc helper script, so it's low-risk for core Git functionality. The patch follows Git's coding style and includes a clear commit message referencing the relevant documentation. This seems like a reasonable quality-of-life improvement for users who rely on symbolic ports in their netrc files.
