This is a technical discussion clarifying the distinction between SHA-1 usage types in Git's hash algorithm transition work. The email is part of brian m. carlson's series preparing for SHA-256 as the default hash algorithm when built with WITH_BREAKING_CHANGES.

The discussion focuses on the meaning of two constants: GIT_HASH_SHA1 (explicit SHA-1 usage) versus GIT_HASH_ORIGINAL (legacy/implicit SHA-1 usage). Junio C Hamano questions whether GIT_HASH_ORIGINAL is necessary if it will always equal SHA-1. brian m. carlson explains the distinction is about intent - GIT_HASH_ORIGINAL represents cases where SHA-1 is used by historical necessity (like bundle v1/v2 formats), while GIT_HASH_SHA1 represents explicit user/format decisions to use SHA-1.

The exchange provides important context for the series by clarifying the semantic difference between these constants, even though they currently have the same numeric value. This helps reviewers understand why both constants exist in the codebase and when each should be used. The discussion appears to reach consensus that the distinction is valuable for documenting different types of SHA-1 usage in the code.
