This is a bugfix and refactoring patch in the `imap-send` series, specifically addressing CRAM-MD5 authentication handling. The patch improves error handling when CRAM-MD5 is requested without OpenSSL support available.

Previously, attempting CRAM-MD5 auth without OpenSSL would trigger a hard `die()` call. The patch replaces this with graceful failure by:
1. Moving the OpenSSL availability check into a new `try_auth_method()` helper that handles all auth methods consistently
2. Making `auth_cram_md5` NULL when OpenSSL is unavailable (via `#define` rather than a stub function)
3. Providing clear error messages about missing OpenSSL support

The implementation centralizes authentication failure handling in `try_auth_method()`, which checks both server capabilities (via `CAP()`) and method availability (via the function pointer check). For CRAM-MD5 specifically, it now properly reports that OpenSSL is required rather than crashing.

This change is part of the broader `imap-send` improvements adding OAuth2.0 support and fixing authentication edge cases. The patch appears well-integrated with the existing code, maintaining the same error handling patterns used elsewhere in the file while making the CRAM-MD5 behavior more robust. The use of a shared helper function (`try_auth_method()`) suggests this pattern may be reused for other auth methods in future patches.
