This is a naming discussion within the SHA-256 transition series, specifically about the constant for SHA-1 usage in legacy formats. The thread has established that there needs to be a distinction between GIT_HASH_SHA1 (explicit SHA-1 selection) and a constant representing mandatory SHA-1 usage in pre-hash-aware formats. 

Junio C Hamano expresses satisfaction with brian m. carlson's suggestion of GIT_HASH_LEGACY_SHA1 as the name for this constant, having previously proposed GIT_HASH_MUST_BE_SHA1. The author had considered but rejected the obscure historical reference GIT_HASH_GOOD_OLD_REV (from ext2 filesystem terminology) as too esoteric. The key requirement is that the name must include "sha1" to be clear about its purpose.

This email resolves one of the open questions from the thread about naming conventions, leaving only minor documentation updates and CI configuration details as remaining loose ends before the series can proceed. The discussion confirms the technical approach while settling on clear, descriptive naming that maintains the historical context of SHA-1's mandatory usage in legacy formats.
