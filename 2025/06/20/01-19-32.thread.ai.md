Thread identity: Cover letter for a series preparing Git's transition to SHA-256 as the default hash algorithm, targeting Git 3.0 when built with WITH_BREAKING_CHANGES. Authored by brian m. carlson, who previously led the hash-algorithm-agnostic internals work.

Core problem/goal: Implement SHA-256 as the built-in default hash algorithm while maintaining backward compatibility, allowing testing before Git 3.0 release. The series introduces constants (GIT_HASH_DEFAULT for SHA-256, GIT_HASH_ORIGINAL for SHA-1) to distinguish between default/legacy vs intentional SHA-1 usage.

Key technical details:
- New hash.h constants GIT_HASH_DEFAULT (now conditionally SHA-256 with WITH_BREAKING_CHANGES) and GIT_HASH_ORIGINAL (SHA-1)
- Clarification that GIT_HASH_ORIGINAL represents historical SHA-1 usage in pre-hash-aware formats (bundle v1/v2) while GIT_HASH_SHA1 represents explicit SHA-1 selection
- 11 files updated to use new constants for repository setup and legacy format handling
- Test suite adjusted with GIT_TEST_BUILTIN_HASH variable and --hash=builtin test_oid option
- DEFAULT_HASH_ALGORITHM test prerequisite added
- 8 commands updated to use GIT_HASH_DEFAULT when operating outside repository
- Repository initialization logic modified in setup.c/setup.h to handle new vs existing repos
- Final patch implements conditional GIT_HASH_DEFAULT definition with corrected preprocessor indentation per Junio's review
- Comprehensive testing confirms backward compatibility with version-less SHA-1 repositories
- Detailed edge case handling for repository initialization when no hash algorithm is specified
- Version-less repositories default to SHA-1 via GIT_HASH_ORIGINAL for backward compatibility
- clear_repository_format() called when no config file exists to ensure clean state
- v1-only extensions like objectFormat properly rejected in v0 repos via verify_repository_format()
- Config parsing order and version compatibility checks carefully considered
- Test coverage for SHA-1 compatibility spans multiple test files including version 0 format cases
- Some tests verify behavior without any config file present
- Previously undiscovered bug in this area was fixed before submission
