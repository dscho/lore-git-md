Thread identity: Cover letter for a series preparing Git's transition to SHA-256 as the default hash algorithm, targeting Git 3.0 when built with WITH_BREAKING_CHANGES. Authored by brian m. carlson, who previously led the hash-algorithm-agnostic internals work.

Core problem/goal: Implement SHA-256 as the built-in default hash algorithm while maintaining backward compatibility, allowing testing before Git 3.0 release. The series introduces clear constants (GIT_HASH_DEFAULT for SHA-256, GIT_HASH_ORIGINAL for SHA-1) to distinguish between default/legacy vs intentional SHA-1 usage.

Key technical details:
- New hash.h constants GIT_HASH_DEFAULT and GIT_HASH_ORIGINAL
- GIT_HASH_ORIGINAL explicitly marks SHA-1 usage required for older formats (bundle v1/v2) that hardcode SHA-1
- Repository setup and legacy format handling updated to use new constants (11 files changed across patches: receive-pack, bundle, transport, connect.c, fetch-pack.c, setup.c, setup.h)
- Test suite adjusted with new GIT_TEST_BUILTIN_HASH variable and --hash=builtin test_oid option to handle future hash algorithm changes
- DEFAULT_HASH_ALGORITHM test prerequisite added to check hash algorithm matches built-in default
- WITH_BREAKING_CHANGES build flag activates SHA-256 default
- Minimal code changes required due to prior hash-agnostic design work
- Current patch makes mechanical GIT_HASH_SHA1 -> GIT_HASH_ORIGINAL substitutions in legacy protocol/format code
- Latest patch updates repository initialization to use GIT_HASH_DEFAULT for new repos while maintaining GIT_HASH_ORIGINAL for existing ones
- REPOSITORY_FORMAT_INIT macro and read_repository_format function modified to handle hash algorithm defaults properly

Current status: Series appears complete and well-tested across configurations (no default hash, SHA-1, SHA-256). Second patch adds GIT_HASH_ORIGINAL constant. Latest patch updates legacy format handling to use new constant and modifies repository initialization behavior. Test infrastructure patch prepares suite for SHA-256 default transition. Final patch enables SHA-256 default when WITH_BREAKING_CHANGES is set.

Open questions/loose ends:
- SHA-256 interoperability work mentioned as ongoing but separate
- Potential controversy around GIT_HASH_ORIGINAL constant addition (documentary-only at this stage)
- Final Git 3.0 release timing not addressed

Participant positions: Only brian m. carlson so far as author.
