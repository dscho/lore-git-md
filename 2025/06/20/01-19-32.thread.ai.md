Thread identity: Cover letter for a series preparing Git's transition to SHA-256 as the default hash algorithm, targeting Git 3.0 when built with WITH_BREAKING_CHANGES. Authored by brian m. carlson, who previously led the hash-algorithm-agnostic internals work.

Core problem/goal: Implement SHA-256 as the built-in default hash algorithm while maintaining backward compatibility, allowing testing before Git 3.0 release. The series introduces constants (GIT_HASH_DEFAULT for SHA-256, GIT_HASH_ORIGINAL for SHA-1) to distinguish between default/legacy vs intentional SHA-1 usage, with ongoing debate about their documentation value.

Key technical details:
- New hash.h constants GIT_HASH_DEFAULT and GIT_HASH_ORIGINAL under review
- GIT_HASH_ORIGINAL intended to explicitly mark SHA-1 usage required for older formats (bundle v1/v2) that hardcode SHA-1
- Repository setup and legacy format handling updated to use new constants (11 files changed across patches)
- Test suite adjusted with GIT_TEST_BUILTIN_HASH variable and --hash=builtin test_oid option
- DEFAULT_HASH_ALGORITHM test prerequisite added
- Final patch enables SHA-256 as default when WITH_BREAKING_CHANGES is set
- New patch updates 8 commands (apply, diff, hash-object, index-pack, ls-remote, patch-id, shortlog, show-index) to use GIT_HASH_DEFAULT when operating outside a repository
- Changes are mechanical one-line replacements of GIT_HASH_SHA1 with GIT_HASH_DEFAULT
- Minimal code changes required due to prior hash-agnostic design work
- Repository initialization updated to use GIT_HASH_DEFAULT for new repos while maintaining GIT_HASH_ORIGINAL for existing ones
- REPOSITORY_FORMAT_INIT macro and read_repository_format function modified
- Test infrastructure updated in multiple test files to use --hash=builtin
- t/test-lib.sh updated to set GIT_TEST_BUILTIN_HASH based on WITH_BREAKING_CHANGES

Current status: Series implements SHA-256 as default when WITH_BREAKING_CHANGES is set. Latest patch updates commands to use GIT_HASH_DEFAULT outside repository context, which Junio C Hamano explicitly approves as demonstrating the constant's value. Original debate about GIT_HASH_ORIGINAL remains unresolved.

Open questions/loose ends:
- Whether to keep GIT_HASH_ORIGINAL constant or revert to GIT_HASH_SHA1 in legacy code
- SHA-256 interoperability work mentioned as ongoing but separate
- Final Git 3.0 release timing not addressed

Participant positions:
- brian m. carlson (author) maintains GIT_HASH_ORIGINAL provides useful documentation of SHA-1 requirements in legacy formats
- Junio C Hamano questions the constant's value but approves GIT_HASH_DEFAULT usage in new patch, praising its implementation

Related work: Builds on brian m. carlson's prior hash-algorithm-agnostic internals work. SHA-256 interoperability effort is a known follow-up.
