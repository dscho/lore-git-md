This is part of the SHA-256 default transition series, specifically handling repository initialization behavior. The patch updates two key components in the setup code to properly handle hash algorithm defaults during repository creation and reading.

The main change switches repository format initialization from hardcoded SHA-1 to using GIT_HASH_DEFAULT, which will be SHA-256 when built with WITH_BREAKING_CHANGES. However, it maintains backward compatibility by explicitly setting GIT_HASH_ORIGINAL (SHA-1) when reading existing repositories that don't specify a hash algorithm, ensuring they continue to work as before.

The changes are mechanical but important for the transition:
1. setup.h's REPOSITORY_FORMAT_INIT macro now uses GIT_HASH_DEFAULT instead of GIT_HASH_SHA1 for new repositories
2. setup.c's read_repository_format function ensures GIT_HASH_ORIGINAL is set when reading existing repos, both in the initial clear and if version check fails

This aligns with the series' goal of making SHA-256 the default while maintaining SHA-1 compatibility where needed. The patch is straightforward and well-contained, just updating the initialization paths to use the new constants introduced earlier in the series. It maintains the existing behavior for SHA-1 repos while preparing for the SHA-256 default transition.
