This is a technical clarification in the ongoing bugfix thread about symbolic port name validation in git-credential-netrc.

Andreas Schwab provides authoritative input on the valid character set for symbolic port names, citing RFC6335 which governs service name registration. The key clarification is that hyphens are permitted in service names while underscores are not. This directly addresses Junio Hamano's earlier question about whether the alphanumeric character class (`[[:alnum:]]`) proposed in the original patch might be too restrictive.

The email establishes that while the current patch's alphanumeric-only approach would reject some valid service names (those containing hyphens), it correctly excludes invalid ones (those with underscores). This suggests the validation regex should be updated to `^[[:alnum:]-]+$` to fully comply with RFC6335.

This authoritative reference from the RFC should help settle the open question about character class permissibility, allowing the patch author to make an informed adjustment to the validation rules. The maintainer had specifically requested documentation of the validation rules, and this email provides the necessary standards reference to satisfy that requirement.
