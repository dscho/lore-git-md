This is the final patch in a series preparing Git's transition to SHA-256 as the default hash algorithm. The patch enables SHA-256 by default when Git is built with the WITH_BREAKING_CHANGES flag, which aligns with the project's plan to make this the default in Git 3.0. The change is minimal - just a few lines in hash.h to set GIT_HASH_DEFAULT to SHA-256 when the flag is present, plus a corresponding update to the test infrastructure to use SHA-256 in test runs with breaking changes enabled. 

This builds on the previous work in the series that introduced the GIT_HASH_DEFAULT and GIT_HASH_ORIGINAL constants and updated various parts of the codebase to handle hash algorithm selection properly. The patch appears straightforward and well-tested, with the test suite already prepared by earlier patches to work with either SHA-1 or SHA-256 as the default. 

The change allows early testing of the SHA-256 default before it becomes mandatory in Git 3.0, while maintaining backward compatibility for those not using the breaking changes flag. This seems like a carefully considered step in the long-planned transition away from SHA-1.
