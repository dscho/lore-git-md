This is a cover letter for a feature series preparing for Git's transition to SHA-256 as the default hash algorithm. The series implements a key breaking change planned for Git 3.0 by introducing SHA-256 as the default when built with WITH_BREAKING_CHANGES, allowing testing before the actual release.

The series starts by adding two new hash constants: one for the default algorithm (SHA-256) and one for SHA-1, with the latter intended to clearly document legacy SHA-1 usage versus intentional SHA-1 cases. The bulk of the patches update various parts of the codebase to use these constants appropriately, with particular attention to repository setup and legacy format handling. The test suite is also adjusted to handle the new default algorithm concept, now called "built-in algorithm" to avoid confusion with existing test terminology.

The final patch enables SHA-256 by default when WITH_BREAKING_CHANGES is set. The author notes this required surprisingly little code, crediting good prior design decisions. Testing was done across multiple configurations (no default hash, SHA-1, SHA-256) with all passing. The cover letter also mentions ongoing but incomplete work on SHA-256 interoperability, though this is not part of the current series.

Key technical points for future reference: new hash.h constants GIT_HASH_DEFAULT and GIT_HASH_ORIGINAL, test suite changes to handle "built-in" hash algorithm, and the WITH_BREAKING_CHANGES build flag activation. The SHA-1 constant addition is noted as potentially controversial but defended as useful documentation. The series appears well-tested and thoughtfully structured, with interoperability work acknowledged as a separate but related effort.
