This is a discussion about naming conventions in Git's ongoing SHA-256 transition effort, specifically focusing on the `GIT_HASH_ORIGINAL` constant introduced in patch 4/10 of the series.

Junio Hamano responds to brian m. carlson's patch that replaces explicit SHA-1 references with `GIT_HASH_ORIGINAL` in legacy format handling code. While Hamano had previously questioned the value of this constant, he now acknowledges its transitional usefulness for distinguishing between "not-yet-updated" code and "must-stay-SHA-1" code. However, he suggests that once the transition is complete, the constant should be renamed back to something explicitly mentioning SHA-1 (like `GIT_HASH_MUST_BE_SHA1`) for long-term clarity.

The exchange highlights an important design decision in the SHA-256 transition - how to clearly mark code that must remain SHA-1 compatible versus code that could eventually support other hashes. Hamano's suggestion would avoid a future rename step but might make the transitional state less clear. The discussion remains open-ended, with no resolution yet on the final naming approach.
