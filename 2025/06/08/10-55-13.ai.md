This is a feature patch adding OAuth2.0 authentication support to `imap-send`, part of a larger series (v15 04/10) that modernizes IMAP functionality. The patch implements both RFC-standard OAUTHBEARER and Google-proprietary XOAUTH2 mechanisms, with support for both OpenSSL and libcurl backends.

The implementation adds new helper functions `oauthbearer_base64()` and `xoauth2_base64()` to construct the proper authentication strings, following RFC specifications for OAUTHBEARER and Google's documentation for XOAUTH2. The authentication flow is integrated into the existing `try_auth_method()` framework, with new capability flags (AUTH_OAUTHBEARER, AUTH_XOAUTH2) added to the IMAP protocol handler. For libcurl, the patch leverages `CURLOPT_XOAUTH2_BEARER` which automatically selects the appropriate OAuth variant.

Documentation updates explain the new authentication methods, with specific configuration examples for Gmail and Outlook. The Gmail example now includes guidance about OAuth2.0 being more secure alternative to app-specific passwords, while the Outlook example notes its OAuth2.0-only requirement. The patch maintains backward compatibility by falling back to password authentication when OAuth isn't specified.

Key technical details for future reference: new config option values "OAUTHBEARER" and "XOAUTH2" for `imap.authMethod`, new capability flags in `enum CAPABILITY`, the base64 encoding helpers' string construction format (including GS2 header for OAUTHBEARER), and the libcurl integration's automatic protocol selection via `CURLOPT_XOAUTH2_BEARER`. The changes span configuration parsing, authentication handlers, and documentation while maintaining the series' focus on comprehensive IMAP support.
