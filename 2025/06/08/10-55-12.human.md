This is a bugfix and platform compatibility patch in the ongoing `imap-send` improvement series. It addresses how CRAM-MD5 authentication fails when OpenSSL isn't available during compilation.

The patch changes the code to fail gracefully with an informative error message when CRAM-MD5 is requested without OpenSSL support, rather than crashing with `die()`. The implementation introduces a new `try_auth_method()` helper that centralizes authentication failure handling, though currently it's only used for CRAM-MD5. The error messages are now more consistent with other authentication failures in the codebase.

This is part of a larger effort to make `imap-send` more robust, particularly around authentication methods. The change is straightforward and well-contained, just moving the OpenSSL check earlier in the process and improving the error reporting. Since CRAM-MD5 is the only authentication method that requires OpenSSL, this patch specifically handles that case while leaving the door open to handle other methods similarly in the future.

The patch has been through multiple revisions in this series and appears ready for inclusion, following Junio Hamano's request to position the CRAM-MD5 changes early in the series. It complements other authentication improvements in the series like OAuth2.0 support and PLAIN authentication fixes.
