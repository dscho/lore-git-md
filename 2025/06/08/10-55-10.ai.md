Bugfix for `imap-send` configuration parsing that corrects a regression introduced in Git 2.46.0. This is the first patch in a 10-part series that overhauls IMAP functionality, but stands alone as a critical fix for a broken configuration parser.

The patch fixes a bug where `cfg->folder` was incorrectly being NULLed out when processing unrelated configuration variables like `imap.user` or `imap.pass`. This regression made `imap-send` completely unusable since Git 2.46.0, as the folder field would be cleared even when setting other configuration values. The fix is straightforward - each configuration variable now properly clears its own corresponding field rather than incorrectly clearing the folder field.

The bug originated from commit 6d1f198f34 ("imap-send: fix leaking memory in `imap_server_conf`") and went unnoticed for some time, likely because most users prefer `git send-email`. The patch modifies `imap-send.c` to ensure proper field-specific cleanup, with changes limited to the configuration parsing logic. This is a targeted fix that maintains all existing behavior while correcting the memory management issue.

As the first patch in the series, this provides the foundation for subsequent IMAP improvements by restoring basic functionality. The thread context shows this bugfix was identified as a critical issue in the larger IMAP overhaul, and this patch resolves it cleanly with minimal changes to the codebase.
