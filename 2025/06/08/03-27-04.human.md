This is the first patch in a 2-part series improving submodule configuration handling, specifically addressing path reuse cases. The patch prevents silent overwriting of `.gitmodules` entries when adding a new submodule at a path that previously hosted a different submodule.

The change modifies `module_add()` in `builtin/submodule--helper.c` to check if the computed submodule name already exists in the repository's config. If the name is still in use (even if the submodule was moved elsewhere), the operation will now fail by default, preserving the existing configuration. Users can override this with `--force` to auto-increment the submodule name (e.g., appending numbers until finding a unique name).

The implementation includes thorough test coverage in t7400-submodule-basic.sh, demonstrating the failure case and verifying the force behavior. This patch has already been reviewed and approved by Junio C Hamano in previous iterations, with the conflict handling via `submodule_from_name()` deemed correct. The patch appears ready for merging as part of the series' goal to improve submodule configuration safety.
