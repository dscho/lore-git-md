This is a bugfix and refactoring patch in the `imap-send` series, specifically addressing CRAM-MD5 authentication handling when OpenSSL is unavailable. 

The patch improves error handling for CRAM-MD5 authentication by first checking OpenSSL availability before attempting authentication, rather than failing with a `die()` call. The key changes include:

1. Replacing the unconditional `die()` in the non-OpenSSL CRAM-MD5 path with a graceful error message by making `auth_cram_md5` NULL when OpenSSL is unavailable, detected via a new `NOT_CONSTANT` check in the refactored `try_auth_method()` helper.

2. Introducing a new `try_auth_method()` function that consolidates authentication method validation and error handling, used for CRAM-MD5 but structured to potentially handle other methods. This function checks both server support (via CAPABILITY) and implementation availability before attempting authentication.

3. The changes maintain backward compatibility while providing clearer error messages when CRAM-MD5 is requested without OpenSSL support, matching the series' goal of robust error handling. The patch follows the maintainer's request to keep CRAM-MD5 changes early in the series (positioned as patch 3/10).

The implementation is clean and focused, with the new helper function reducing code duplication while improving error reporting. This is part of the broader effort to make `imap-send` more robust, particularly around authentication methods and error handling. The changes are limited to the OpenSSL-dependent paths in `imap-send.c` and don't affect other authentication methods or the libcurl backend.
