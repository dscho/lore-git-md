Bugfix for a memory leak in `imap-send`'s CRAM-MD5 authentication. This is part of a larger v15 series that overhauls IMAP functionality, with this particular fix addressing a case where the `response` buffer wasn't freed if socket writing failed during authentication. The change is straightforward - it ensures cleanup happens on the error path by moving the `free(response)` call before returning. While small, it plugs a real leak in a security-sensitive code path. The patch is well-contained and clearly motivated, fitting cleanly into the series' broader work on authentication reliability. No behavioral changes beyond the memory management fix.
