Bugfix for `git stash` branch name display in submodule contexts. This patch addresses the issue where stashing changes in a superproject would incorrectly show the submodule's branch name in the stash message. The root cause was buffer reuse in `refs_resolve_ref_unsafe()` corrupting the branch name during submodule operations.

K Jayatheerth's solution introduces a `branch_name_buf` to preserve the superproject's branch name via `xstrdup()`, while maintaining the existing "(no branch)" fallback behavior. The patch now includes all requested improvements from earlier reviews: proper memory management with `free(branch_name_buf)`, consistent indentation, and a new test case verifying the fix works in submodule scenarios.

The test creates a superproject with a submodule, switches branches in both, and confirms the stash message correctly shows the superproject's branch name rather than the submodule's. This completes the fix for the originally reported issue where stashing in a `bugfix_bar` superproject branch would show the submodule's `feature_sdk_foo` branch instead.

With these changes, the patch appears ready for inclusion, having addressed all technical concerns raised during review while maintaining the existing behavior for non-submodule cases. The thorough test case provides confidence the fix works as intended.
