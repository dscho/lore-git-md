Bugfix addressing a memory leak in the submodule update machinery. The patch fixes a case where `remote_name` could leak when `remote_submodule_branch()` fails in `update_submodule()` in `builtin/submodule--helper.c`. The leak occurs due to missing cleanup of the string allocated by `get_default_remote_submodule()` during early return. The fix adds a `free(remote_name)` call at the error path while maintaining existing successful behavior. The change is small (4 lines) and focused on proper memory management in the submodule helper code, specifically around the `remote_name` and `branch` variables in the error handling path after `remote_submodule_branch()`. While the commit notes this failure case is unlikely (since we'd already successfully obtained a remote ref name), it provides proper cleanup.
