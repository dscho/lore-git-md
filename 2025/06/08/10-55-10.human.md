Bugfix for a critical regression in `imap-send` that made the command unusable since Git 2.46.0. The issue stems from commit 6d1f198f34 which incorrectly freed and NULLed the `cfg->folder` field when processing unrelated configuration variables like `imap.user` or `imap.pass`. This patch fixes the bug by properly freeing the correct struct fields for each configuration option.

The regression was particularly problematic because it affected basic functionality - users couldn't send mail via IMAP at all if they had these common configuration settings. The patch is straightforward, correcting the `FREE_AND_NULL` calls to target the appropriate struct members rather than incorrectly clearing the folder field in all cases.

This is the first patch in a larger series (v15) that adds OAuth2.0 support and other IMAP improvements, but this particular fix stands on its own as an urgent correction to a broken feature. The change is minimal (just 4 lines modified) but crucial for restoring basic IMAP functionality.
