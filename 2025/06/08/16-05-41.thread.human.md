Junio Hamano proposed a new `--compact-summary` option for `git merge` and `git pull` that would enhance their output with `(new)` and `(gone)` annotations to better indicate file operations while maintaining the compactness of the diffstat format. The initial implementation builds on existing diffstat infrastructure with minimal code changes.

D. Ben Knoble has now raised questions about the design approach, suggesting that a more general solution might be preferable. He wonders whether this specific output format should be baked into the merge/pull commands, or if users could instead be directed to run `git diff --compact-summary HEAD^` after merging. While not objecting to the code quality, he's probing whether a more flexible configuration system for diff output formats might be a better long-term solution than adding this specific variant. The discussion remains open on whether to proceed with the current focused implementation or consider broader output customization options.
