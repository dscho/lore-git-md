This is the final patch in a 15-part series adding IMAP folder management capabilities to `git imap-send`. The patch introduces a new `--list` option that displays available IMAP folders, addressing the common issue where different providers (Gmail, Outlook, etc.) use varying naming conventions for standard folders like Trash or Drafts.

The implementation, the patch adds a `list_folders` flag and corresponding CLI option, with separate handler functions for OpenSSL (`list_imap_folders()`) and libcurl (`curl_list_imap_folders()`) backends. The OpenSSL version uses RFC6154-compliant IMAP LIST commands, while the libcurl version follows the library's documented example. Output shows raw IMAP protocol responses including provider-specific folder names and attributes, which helps users identify the correct folder names to use with `--folder`.

Key technical details include:
- New `list_folders` static variable and `--list` option added to `imap-send.c`
- OpenSSL implementation via new `list_imap_folders()` function issuing "LIST \"\" \"*\"" command
- Libcurl implementation via new `curl_list_imap_folders()` using modified URL handling
- Output shows RFC-compliant folder listings with attributes like `\HasNoChildren`
- Documentation updates in `git-imap-send.adoc` explaining the new option
- Conditional compilation preserved for both backends

The patch completes the series' goal of comprehensive IMAP folder management, following through on the earlier `--folder` option by helping users discover valid folder names. It maintains consistency with the series' approach of parallel OpenSSL/libcurl implementations and follows the established pattern for credential handling and error reporting.
