This is the second patch in a 2-part series improving submodule configuration management, specifically addressing redundant `submodule.<name>.active` entries when paths match existing patterns. The patch modifies `configure_added_submodule()` in `builtin/submodule--helper.c` to avoid writing explicit active entries when the submodule path is already covered by a `submodule.active` pattern.

The implementation introduces wildcard pattern matching via `wildmatch()` to check if the new submodule's path matches any existing active patterns. Only when no match is found does it write an explicit active entry. This maintains the same activation behavior while reducing config file clutter. The change is tested in t7413-submodule-is-active.sh with a new case verifying no redundant entry is created when adding a submodule under a covered path pattern.

This version represents the culmination of extensive discussion with Junio Hamano, now taking a focused approach that handles edge cases while avoiding broader infrastructure changes. The patch includes thorough coverage of both the happy path (skipping redundant entries) and edge cases (correct behavior when no global config exists). The implementation appears technically sound with clean diffs and passing CI (except a known osx-gcc issue). This is now in a state where maintainers must decide whether to accept this solution or request alignment with Junio's earlier suggested approach involving `is_submodule_active()`.
