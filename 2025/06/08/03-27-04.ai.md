Bugfix for submodule configuration management in `git submodule add`. This is patch 1/2 in K Jayatheerth's v8 series, addressing a specific edge case where adding a new submodule at a path that previously hosted another submodule could silently overwrite the original submodule's configuration in `.gitmodules`.

The patch modifies `module_add()` in `builtin/submodule--helper.c` to detect when a submodule name derived from the path is already in use elsewhere in the repository. In such cases, it now either errors out (default behavior) or auto-increments the name when `--force` is used. The implementation checks for existing submodule configurations via `submodule_from_name()` and handles conflicts by either dying with an informative message or generating a new unique name (e.g., appending a number).

Test coverage in t7400-submodule-basic.sh demonstrates the fix by creating a scenario where: 1) a submodule is added and moved, 2) a new submodule is attempted at the original path, and 3) the operation correctly fails unless forced. The implementation has been reviewed and approved by Junio C Hamano in previous iterations, with the conflict handling deemed correct.

This patch stands independently from patch 2/2 in the series (which handles redundant `.active` config entries) and remains unchanged from previous versions. The changes are confined to the submodule addition logic with clear backward compatibility, making it a low-risk improvement to prevent configuration loss during submodule operations.
