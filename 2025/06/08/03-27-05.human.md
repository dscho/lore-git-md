This is the second patch in a 2-part series improving submodule configuration management, now at version 8. The patch focuses on eliminating redundant `submodule.<name>.active` entries when a submodule's path is already covered by existing patterns in `submodule.active`.

The change modifies `configure_added_submodule()` in `builtin/submodule--helper.c` to skip writing an explicit active entry when the submodule's path matches any pattern in `submodule.active`. The implementation uses wildmatch pattern matching and includes a new test case in t7413 that verifies the behavior when adding a submodule under a path already covered by a pattern.

The patch has undergone extensive review and iteration, with Junio Hamano, and now presents a focused solution that maintains backward compatibility while avoiding configuration bloat. Test coverage appears thorough, with the new test case specifically targeting the redundant-entry scenario. The implementation is technically sound and the patch appears ready for consideration, though there remains some discussion about whether maintainers might prefer a different approach to the pattern matching logic.

This patch builds on the first (already-approved) patch in the series, together addressing two distinct submodule configuration issues: preventing overwrites when adding moved submodules and now eliminating redundant active entries.
