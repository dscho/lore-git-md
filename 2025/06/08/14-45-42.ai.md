Bugfix for `git stash` branch name corruption in submodule contexts. This is the final revision of K Jayatheerth's patch addressing an issue where stashing changes in a superproject would incorrectly show the submodule's branch name in the stash message. The root cause was buffer reuse in `refs_resolve_ref_unsafe()` corrupting the branch name during submodule operations.

The solution uses `xstrdup()` to preserve the superproject's branch name, with proper memory management via a new `branch_name_buf` variable that gets freed appropriately. The patch maintains the existing "(no branch)" fallback behavior while fixing the corruption case. Key technical improvements in this version include simplified control flow (reducing nested if/else blocks), proper whitespace formatting, and a comprehensive test case verifying the fix works when stashing in a superproject while a submodule is checked out to a different branch.

The test creates a multi-repo scenario with distinct branches in superproject and submodule, stashes changes in the superproject, and verifies the stash message correctly shows the superproject's branch name. All prior review feedback from Junio C Hamano and René Scharfe has been incorporated, including memory leak fixes, indentation corrections, test formatting improvements, and code style refinements. The patch is now in its polished form with maintainer approval expected.
