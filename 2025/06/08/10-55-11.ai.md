Bugfix for the `imap-send` authentication code, specifically addressing a memory leak in the CRAM-MD5 authentication path. This is part of the larger v15 series improving IMAP functionality, where CRAM-MD5 authentication was moved to the start of the series per maintainer request.

The patch fixes a case where the `response` buffer allocated by `cram()` would leak if `socket_write()` failed. The fix adds the missing `free(response)` call in the error path before returning. This is a straightforward memory management correction that ensures proper cleanup when network operations fail during authentication.

The change is minimal (just 3 lines added around the error handling) and focused specifically on the CRAM-MD5 authentication flow.
