Thread identity: Feature patch introducing `--compact-summary` option for `git merge` and `git pull` from maintainer Junio Hamano.

Core problem/goal: Enhance merge/pull output with more context about file operations by adding `(new)`/`(gone)` annotations to the existing diffstat format, creating a more informative summary without significantly increasing output size.

Current status: Initial version implementing the feature with symmetric support in both commands. Junio Hamano has now proposed extending the existing `merge.stat` configuration to support the new format as an alternative to command-line flags. This responds to D. Ben Knoble's earlier architectural questions while maintaining backward compatibility.

Key technical details:
- New `--compact-summary` option documented in both commands
- Proposed extension to `merge.stat` config (boolean or 'compact-summary' string)
- Uses `MERGE_SHOW_COMPACTSUMMARY` flag (value 2) alongside existing `MERGE_SHOW_DIFFSTAT`
- Uses `DIFF_FORMAT_DIFFSTAT` with `stat_with_summary` flag when compact mode selected
- Touches merge.c, pull.c, and documentation
- Test cases verify `(new)` marker appears

Open questions/loose ends:
- Whether to adopt the config-based approach alongside/instead of command-line flags
- Potential interaction with other diff output configuration
- Alternative approach of running `git diff --compact-summary HEAD^` post-merge remains unaddressed

Participant positions:
- Junio Hamano: Author of initial implementation, now proposing config-based evolution
- D. Ben Knoble: Originally questioned architectural direction, suggesting more flexible output control

Related work: Builds on existing diffstat infrastructure. Discussion now includes evolution of `merge.stat` config while avoiding broader output format redesign.
