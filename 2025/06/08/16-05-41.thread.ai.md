Thread identity: Feature patch introducing `--compact-summary` option for `git merge` and `git pull` from maintainer Junio Hamano.

Core problem/goal: Enhance merge/pull output with more context about file operations by adding `(new)`/`(gone)` annotations to the existing diffstat format, creating a more informative summary without significantly increasing output size.

Current status: Initial version implementing the feature, with symmetric support in both commands. No version iterations yet. D. Ben Knoble has raised design questions about whether a more general solution for output format control might be preferable.

Key technical details:
- New `--compact-summary` option documented in both commands
- Adds `MERGE_SHOW_COMPACTSUMMARY` flag (value 2) alongside existing `MERGE_SHOW_DIFFSTAT`
- Uses `DIFF_FORMAT_DIFFSTAT` with `stat_with_summary` flag when compact mode selected
- Touches merge.c, pull.c, and documentation
- Test cases verify `(new)` marker appears for created files

Open questions/loose ends:
- Whether this specific output format should be baked into merge/pull commands
- Potential for more general "diff options" configuration to handle multiple output formats
- Alternative approach of running `git diff --compact-summary HEAD^` post-merge

Participant positions:
- Junio Hamano: Author of initial implementation
- D. Ben Knoble: Questions architectural direction, suggests exploring more flexible output control

Related work: Builds on existing diffstat infrastructure rather than introducing new formatting systems. Discussion touches on broader themes of command output configurability.
