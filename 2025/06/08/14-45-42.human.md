Bugfix for `git stash` branch name display in submodule contexts. This is the final version of a patch that fixes a case where stashing changes in a superproject would incorrectly show the submodule's branch name in the stash entry rather than the superproject's branch name.

The issue occurs because `refs_resolve_ref_unsafe()` uses a static buffer that gets overwritten when resolving the submodule's branch. The solution duplicates the superproject's branch name using `xstrdup()` to preserve it through submodule operations. The patch now includes all requested improvements from reviewers:

1. Proper memory management with `free()` to prevent leaks
2. Cleaned up control flow and indentation
3. A comprehensive test case verifying the fix works
4. Maintained the existing "(no branch)" fallback behavior

The changes are minimal and focused - just adding a buffer to store the branch name and freeing it later. The test case clearly demonstrates the problem by creating a superproject with a submodule, switching branches in both, and verifying the stash message shows the correct superproject branch name.

This appears to be a solid fix for a real bug, with all review feedback addressed. The patch is ready for merging.
