Bugfix addressing a memory leak in the submodule update machinery. This patch fixes a case where `remote_name` could leak when `remote_submodule_branch()` fails in `update_submodule()`. The leak occurs because the function would return early without freeing the string allocated by `get_default_remote_submodule()`.

The change is straightforward - it adds a `free(remote_name)` call at the early exit point. While the commit message notes this failure case is unlikely (since we'd already successfully obtained a remote ref name), it's a proper cleanup that follows good memory management practices. The patch is small (4 lines changed) and focused on this specific issue in the submodule helper code.

For future reference in thread summaries: The fix touches `builtin/submodule--helper.c`'s `update_submodule()` function, specifically around the error handling path after `remote_submodule_branch()`. The key variables involved are `remote_name` (which was leaking) and `branch`. The patch maintains the same behavior when successful but ensures proper cleanup on failure.
