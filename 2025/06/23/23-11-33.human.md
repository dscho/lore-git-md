This is part 5 of a 7-part series refactoring submodule remote lookup logic, continuing the broader effort to remove `the_repository` global usage. The patch focuses on improving the fallback behavior when determining a submodule's default remote name.

Currently, when a submodule is in detached HEAD state, the code hardcodes "origin" as the fallback. This patch introduces a more robust approach by reusing the logic from `remotes_remote_for_branch()`, which first checks for a branch's configured remote, then falls back to using the sole remote if only one exists, before finally defaulting to "origin". The change is implemented by adding a new `repo_default_remote()` helper function in remote.c that encapsulates this logic.

The patch includes test coverage demonstrating the improved behavior when a submodule's remote has been renamed. While not a complete solution for all remote renaming cases, it handles the common scenario where users rename "origin" without adding other remotes. The changes are mechanical but well-contained, touching only the remote lookup logic while maintaining the existing memory management patterns (xstrdup'ing returned strings).

This continues the series' pattern of careful refactoring while making incremental improvements to functionality. The changes align with the overall goal of making submodule remote handling more robust and repository-agnostic.
