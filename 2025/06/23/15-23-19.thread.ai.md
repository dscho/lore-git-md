Bug report regarding Git bundle functionality with shallow repositories. The core problem is that cloning from a bundle created from a shallow (--depth=1) repository fails with "remote did not send all necessary objects" when traversing grafted commits (specifically commit 47f57af... in the example), despite direct cloning from the original shallow repository working correctly. The issue occurs in bundle.c when creating bundles with --all from shallow clones.

Key technical details:
- Reproduction path: shallow clone -> create bundle with --all -> attempt clone from bundle
- Failure occurs during parent traversal of grafted commits
- Bundle creation appears to mishandle shallow repository metadata that the direct clone transport protocol processes correctly
- Error suggests missing parent objects that should be present

Open questions:
- Exact technical difference between bundle creation and direct clone transport in handling shallow grafts
- Whether this affects other bundle creation modes beyond --all
- Expected behavior for bundle creation from shallow repositories
