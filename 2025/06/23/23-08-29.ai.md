This is a performance optimization patch in Taylor Blau's ongoing series to improve pack maintenance, specifically focusing on delta compression for loose objects. The patch modifies `add_loose_object()` to treat loose commits as traversal tips when a `rev_info` struct is provided, which should produce more efficient deltas by establishing better path-from-root relationships.

The change builds on previous refactoring that moved `rev_info` handling out of `read_packs_list_from_stdin()`. By adding loose commits to the pending list in the traversal, objects reachable from them will get better delta-base candidates during packing. Junio Hamano confirms the approach makes sense, noting it effectively treats loose commits as branch tips to improve path awareness.

The implementation is minimal - just a conditional addition to `add_loose_object()` that checks for both the presence of `revs` and commit objects. This fits into the series' broader goal of optimizing pack-objects behavior, particularly benefiting repositories with many unreachable objects. The change maintains the existing behavior when `revs` is NULL while enabling the improved delta compression when used with the new --stdin-packs=follow mode being introduced later in the series.

This patch has already received positive feedback from reviewers, with Junio Hamano explicitly approving the approach. It represents one of several incremental improvements in the series that collectively provide measurable performance gains (5-20% in GitHub's production environment) for pack maintenance operations.
