This is a follow-up in the resolved thread about historical fsck warnings during git.git cloning. Junio Hamano builds on Jeff King's explanation of the harmless "badFilemode" and "missingTaggerEntry" warnings, offering more precise mitigation strategies for Git developers.

The email provides two approaches to handle these warnings: a simple but broad config-based suppression (which risks masking new issues) versus a more surgical fsck.skiplist method that exempts only the known problematic objects. Junio notes there are 98 bad tree objects and 1 bad tag in Git's history, and provides the complete list of their hashes for inclusion in a skip list. 

A technical observation is made that while `git ls-tree` normalizes the mode bits (hiding the 100664 vs 100644 discrepancy), the raw object data via `git cat-file` still shows the original non-standard values. The email serves as both a practical guide for Git contributors and a documentation of these historical artifacts, though it doesn't propose any changes to Git's behavior.
