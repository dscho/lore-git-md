This is a follow-up in the Bulgarian localization thread, focusing on technical workflow improvements for translation files. Johannes Sixt confirms acceptance of Alexander Shopov's proposal to voluntarily omit location comments from future translation submissions, which will make diffs cleaner and reduce repository growth. Sixt notes this information isn't runtime-critical and can be regenerated from pot-files when needed.

The discussion also clarifies that while string ordering in po-files can't be perfectly stabilized due to gettext tool limitations (with -s/--sort-output being deprecated), the current -F/--sort-by-file approach combined with `--color-moved` diffs provides reasonable reviewability. Sixt points out that the file list passed to xgettext is already stable through sorted wildcards.

Sixt endorses Shopov's plan to submit future gitk/git-gui translations without location info and suggests updating the Makefile rules to support this new workflow via `make update-po`. This represents concrete progress on one of the two open issues from the format discussions, with string ordering stability remaining as the outstanding item.
