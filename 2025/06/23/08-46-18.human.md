This is a proposal about Git's `.clang-format` configuration, specifically addressing line wrapping issues. Karthik Nayak responds to Junio Hamano's earlier investigation into the `git clang-format` tool's effectiveness, focusing on the challenges of automated line wrapping.

The key observation is that Git's code style prioritizes readability over strict 80-character line limits, which is difficult to enforce mechanically through `.clang-format`'s penalty system. Karthik references their earlier attempt to adjust these penalties in commit 5e9fa0f9fa, which proved unsuccessful at producing satisfactory results.

The concrete proposal is to remove line wrapping rules from `.clang-format` entirely and potentially move them to `.editorconfig` instead, while making the `RemoveBracesLLVM` rule permanent. This would acknowledge that human judgment is currently better than automated tools at handling Git's nuanced line wrapping preferences.

This suggestion comes amid an ongoing thread where participants are debating the tradeoffs between mechanical consistency (via tools) and human-readable formatting. Karthik's position leans toward reducing false positives by removing problematic rules rather than trying to perfect them, which aligns with some of Christian Couder's earlier concerns about tool limitations. The patch would represent a practical step forward while the broader discussion about clang-format's role in Git development continues.
