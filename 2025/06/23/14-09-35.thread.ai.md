Platform compatibility issue affecting FreeBSD builds when libsysinfo (GNU libc sysinfo port) is installed, first reported in Git 2.50.0. The problem occurs when configure detects libsysinfo but fails to add `-lsysinfo` to LDFLAGS, causing linker errors about undefined `sysinfo` symbols during build (affecting `scalar.o` and others). Renato Botelho (FreeBSD ports maintainer) and Eric Sunshine have been working on solutions, with Ramsay Jones now proposing a third approach.

Three distinct solution paths are now detailed: (1) minimal configure.ac fix using AC_LINK_IFELSE instead of AC_COMPILE_IFELSE for sysinfo checks, (2) comprehensive solution adding NEEDS_LIBSYSINFO to Makefile and config.make.uname, and (3) Ramsay Jones' new approach modifying both configure.ac and meson.build to make HAVE_SYSINFO conditional on BSD sysctl availability (preferring native sysctl when present).

Jones' patch restructures detection logic to check sysctl first, only defining HAVE_SYSINFO if HAVE_BSD_SYSCTL is unset, avoiding linker flag modifications entirely. The change maintains build system consistency but lacks FreeBSD testing and commit message justification. This approach differs architecturally by solving through preprocessor logic rather than build system modifications.

Technical considerations remain open:
- Need verification that Jones' approach resolves original linker errors
- Confirmation it maintains functionality across FreeBSD versions
- Architectural preference between preprocessor-based vs build-system solutions
- Potential interaction with existing ports system workarounds

Sunshine's earlier technical guidance on implementation patterns (NEEDS_* variables, config.make.uname) remains relevant for approaches (1) and (2). No maintainer input yet on preferred solution path. The thread now presents three technically distinct options with tradeoffs between invasiveness, platform coverage, and maintenance burden.
