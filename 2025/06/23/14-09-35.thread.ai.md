Platform compatibility issue affecting FreeBSD builds when libsysinfo (GNU libc sysinfo port) is installed, first reported in Git 2.50.0. The problem occurs when configure detects libsysinfo but fails to add `-lsysinfo` to LDFLAGS, causing linker errors about undefined `sysinfo` symbols during build (affecting `scalar.o` and others). Renato Botelho, the FreeBSD ports maintainer, is now actively seeking guidance on the preferred upstream solution.

Two potential approaches are under consideration: (1) making libsysinfo linking conditional (matching the FreeBSD ports workaround where the dependency is configurable with proper LDFLAGS handling), or (2) implementing FreeBSD-specific detection logic. Botelho has offered to implement either solution but awaits maintainer direction on the architectural preference before submitting a formal proposal.

The FreeBSD ports system currently uses a local workaround (approach #1) that proves the conditional linking method works in practice. The thread remains blocked on maintainer input regarding which solution aligns with Git's platform compatibility philosophy - whether to support libsysinfo linking when detected or explicitly handle FreeBSD as a special case. No technical objections to either approach have been raised yet; the decision point centers on project policy for handling such platform-specific build configurations.
