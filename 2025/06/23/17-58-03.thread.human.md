This thread investigates a performance anomaly in `git rev-list --changed-paths` when filtering by multiple paths in the Go repository. Kai Koponen reports that querying two paths together (`src/clean.bash` and `src/Make.dist`) takes 650ms, while querying them individually sums to only 190ms - a significant discrepancy that persists across different count limits (-1, -10, unlimited) in Git 2.50.0. The slowdown suggests inefficient handling of multiple-path filtering in the commit-graph's early termination logic, as the combined query should theoretically benefit from shared traversal work rather than performing worse than the sum of individual queries.

The issue appears fundamental to the commit-graph implementation rather than being environment-specific, as Koponen's detailed system configuration (GCC 14.2, glibc 2.41, OpenSSL 3.4.1 on x86_64) shows no platform-specific factors at play. While the thread has established clear reproduction steps and quantified the performance gap, no solutions or workarounds have yet been proposed. The core question remains why the path filtering implementation scales worse than linearly when multiple paths are queried simultaneously, particularly given the presence of count limits that should enable early termination.
