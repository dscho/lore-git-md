This is part 4 of a 7-part series refactoring submodule remote lookup logic, with a focus on removing `the_repository` dependencies. The patch continues the series' work to make remote handling code repository-agnostic by passing `struct repository*` instead of `struct remote_state*` through several internal functions.

The key changes in this specific patch modify `remote.c` to:
- Update `read_remotes_file()` and `read_branches_file()` to take a `struct repository*` parameter instead of `struct remote_state*`
- Modify `remotes_remote_get_1()` and related functions to use the repository parameter
- Change `set_merge()` to work with repository pointers
- Update callers like `branch_get()` and `branch_get_push_1()` to pass through the repository

The changes are mechanical but important for the series' goal of making these functions usable in contexts without `the_repository` (particularly for submodule handling). The patch maintains existing behavior while removing implicit global state dependencies. It builds on previous memory management fixes in the series and prepares for later patches that will introduce URL-based remote lookup for submodules.

- Functions modified: `read_remotes_file`, `read_branches_file`, `remotes_remote_get_1`, `remotes_remote_get`, `remotes_pushremote_get`, `set_merge`, `branch_get_push_1`

- Maintains same file operations and remote/branch config parsing logic
- Touches same areas as previous patches (remote.c, branch handling)
