Performance issue with `git rev-list --changed-paths` path filtering in commit-graph. Kai Koponen initially reported and analyzed a performance anomaly where querying multiple paths (`src/clean.bash` and `src/Make.dist`) in the Go repository took 650ms while individual queries summed to 190ms. Junio C Hamano clarified this is expected behavior - the commit-graph's bloom filters are intentionally disabled for multiple pathspecs as documented, enforced by `forbid_bloom_filters()` in revision.c (lines 674-686). 

Kai Koponen acknowledged this design but suggested potential for sequential bloom filter checks per path. Junio Hamano responded with technical analysis, identifying `prepare_to_use_bloom_filter()` and `forbid_bloom_filters()` as key functions needing modification. He noted the existing `bloom_keys[]` array structure (using two keys per path - directory and full path) could theoretically accommodate multiple paths by adding more keys, but cautioned this may involve deeper complexity than initially apparent. Junio invited review from bloom filter experts, keeping open the possibility of future optimization while maintaining awareness of current design constraints. The discussion frames this as a potential feature request requiring careful implementation to preserve single-path optimization benefits, with technical details now more precisely identified for future work.
