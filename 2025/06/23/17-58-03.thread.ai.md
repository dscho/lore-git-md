Performance issue with `git rev-list --changed-paths` path filtering in commit-graph. Kai Koponen initially reported and analyzed a performance anomaly where querying multiple paths (`src/clean.bash` and `src/Make.dist`) in the Go repository took 650ms while individual queries summed to 190ms, with the discrepancy persisting across Git versions and count limits. Junio C Hamano clarified this is expected - the commit-graph's bloom filters are intentionally disabled for multiple pathspecs as documented, explaining the lack of early termination optimizations in multi-path queries. The restriction is enforced by `forbid_bloom_filters()` in revision.c (lines 674-686). While this settles the current behavior as by design, it leaves open whether the implementation could be extended to handle multiple paths more efficiently. The thread establishes the technical rationale behind the observed performance characteristics while providing clear reference points (code location, design constraints) for any future work on optimizing multi-path queries.
