Test infrastructure improvement with a safety suggestion.

Todd Zullinger responds to Jeff King's patch adding a `-f` format option to the `test_seq` helper function, which had already received positive reviews from Junio C Hamano and Justin Tobler. While agreeing this is a nice improvement, Todd raises a potential edge case where someone might accidentally pass a number as the format string (e.g., `test_seq -f 1 5`).

He proposes adding a check to verify the format string contains a `%` specifier, which would catch such mistakes early with a BUG() message. Todd acknowledges this might be overkill since tests would fail anyway with incorrect output, but the suggestion aims to make failures more obvious. He also notes that Justin's earlier suggestion to document the `-f` option in the usage note would help prevent another common mistake of cuddling the format string against the flag.

This is a thoughtful but non-blocking suggestion to an otherwise ready-to-merge patch. The concern is valid but minor, and the current implementation's behavior (while potentially confusing) would still lead to test failures that reveal the problem. The discussion shows careful consideration of real-world usage patterns in the test suite.
