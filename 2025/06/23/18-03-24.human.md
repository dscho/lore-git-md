This is a bugfix and enhancement to the git-credential-netrc helper, now in its v2 series with maintainer feedback. Junio Hamano is reviewing the final patch which adds symbolic port name support via getservbyname() resolution in the Perl helper.

The patch centralizes port validation logic in a new Git::is_port() utility, shared between git-credential-netrc and git-send-email. It handles both numeric ports and service names like "imap" (converted to 143) while maintaining backward compatibility. The implementation appears robust with thorough test coverage, though Junio notes some naming and implementation details that could be polished - suggesting "port_num" might be a better name than "is_port", and observing the getservbyname() return could be simplified.

The thread has reached a technical conclusion with this v2 series, having explored three approaches to port resolution. The remaining question is whether to accept this helper-side resolution despite protocol documentation suggesting numeric-only ports, or whether to enforce numeric-only behavior. Junio's feedback here focuses on final polish rather than fundamental objections, suggesting the series is likely nearing acceptance pending any protocol documentation updates.
