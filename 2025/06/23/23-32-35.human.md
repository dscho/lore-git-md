This is a performance optimization thread for `git fetch --prune` with a focus on output formatting details.

Jacob Keller responds to Phil Hord's latest patch that modifies the warning message format for dangling refs during pruning. The discussion has evolved from the original performance optimization (reducing O(N^2) to O(N*logN)) to finer points of user experience. 

Phil's new patch changes the dangling ref warning to explicitly state which deletion will cause the dangling state (e.g., "origin/HEAD will become dangling after origin/master is deleted"). Jacob points out a minor wording inconsistency - the message uses future tense ("will become") even though the deletion has already occurred when the message is printed. 

This represents the final polishing of an otherwise settled optimization. The core technical approach has already received positive feedback from multiple reviewers (Jeff King, Junio Hamano), with consensus that the performance gains justify the minor output ordering changes. The current discussion is purely about making the new warning messages as clear as possible.

The thread shows how even after technical consensus is reached, Git contributors carefully consider user-facing messaging. While the wording quibble is minor, it demonstrates the project's attention to detail in both performance and usability.
