Performance optimization patch series addressing quadratic-time bottleneck in `git fetch --prune` when checking for dangling refs during pruning operations. Current implementation makes O(N^2) string comparisons when pruning many refs (e.g., 2.6-3.6 billion strcmp calls when pruning 15k-28k refs from 126k-174k total). Solution replaces nested loop with O(N*logN) approach from `git remote prune` by first sorting prune list to enable binary search. Second patch will remove now-unused old implementation of dangling ref warning. Changes touch fetch and remote builtins plus refs.c (29 lines net reduction across series). Performance impact dramatic - from 410-470 seconds to under 1 second in test cases. Output formatting improved to show both dangling ref and what it pointed to (with "refs/remotes/" prefix stripped for readability), maintaining clarity despite changed ordering. Solution borrows proven approach from related functionality in `git remote prune`. Includes Reviewed-by from Jacob Keller. First patch modifies `prune_refs()` in builtin/fetch.c to collect refs in sorted string_list before checking for dangling refs, while second patch will clean up old implementation.
