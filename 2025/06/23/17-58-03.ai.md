Performance bug report about `git rev-list` path filtering with commit-graph. Kai Koponen demonstrates that when querying multiple paths with `--changed-paths` enabled in the commit-graph, the runtime scales worse than linearly - a query for two paths takes 3x longer than the sum of individual path queries, even with a `-n` limit that should allow early termination. The test case uses the Go repository with commit-graph enabled, showing 90ms and 100ms for individual path queries versus 650ms for the combined query. The expectation is that combined path queries should take no more than the sum of individual queries, and potentially less due to early termination opportunities. The issue appears consistently across different count limits (-1, -10, and unlimited). This suggests an optimization opportunity in how commit-graph handles multiple-path filtering, particularly around early termination logic when multiple paths are involved. The report provides clear reproduction steps and performance measurements but does not propose a solution.
