Test infrastructure improvement adding format option to test_seq helper.

This is the second patch in a series enhancing the test suite's `test_seq` helper function. Building on the first patch's cleanup of t7422, this change adds a `-f` format option to `test_seq` that mimics GNU `seq -f` behavior, allowing printf-style formatting of sequence numbers. The patch converts 9 test files to use this new capability, eliminating verbose shell loops and awk invocations while maintaining identical functionality.

The implementation is careful to match existing test needs: it uses `%d` rather than `seq`'s `%g` since Git only needs integer sequences, and automatically appends newlines like `seq` does. The commit message thoughtfully explains edge cases considered (like multiple format specifiers) and why they weren't implemented. The changes are focused and mechanical, touching only test files with straightforward substitutions that improve readability.

This represents a quality-of-life improvement for test writers, reducing boilerplate in several subsystems (reftable, submodules, merges). The patch is well-considered with clear commit message documentation of design decisions and limitations. As test-only changes with no behavior impact, it appears low-risk for inclusion.
