This is the final patch in Maxim Cournoyer's v2 series implementing helper-side resolution of symbolic port names in git-credential-netrc. The patch completes the implementation by:

1. Adding a new `Git::is_port()` utility function that validates both numeric ports and symbolic service names via `getservbyname()`, returning the numeric port or undef
2. Modifying the netrc helper to use this function and properly handle the port conversion
3. Updating tests to verify the new behavior
4. Adding a test case for invalid SMTP ports in git-send-email

Junio Hamano's review raises several technical questions about the implementation:
- Suggests renaming `is_port()` to `port_num()` to better reflect its dual validation/conversion purpose
- Questions whether intermediate variable in `is_port()` is necessary
- Asks whether tests should preserve both ":port"-less and "host:port" cases
- Notes the function could be simplified by directly returning `getservbyname()` result

The patch appears technically sound and completes the v2 series as requested, though Junio's suggestions could lead to minor refinements. The core design question remains unresolved - whether helper-side resolution should be allowed despite the credential protocol specifying "port number" (numeric). This patch provides a robust implementation of the helper-side approach should that decision go in its favor.
