This is a follow-up in the resolved thread about fsck warnings during git.git clones. Junio Hamano acknowledges Jeff King's solution of using `fetch.fsck` config to ignore the historical "badFilemode" and "missingTaggerEntry" warnings, but cautions that this blanket approach isn't suitable for Git developers working on new objects. He provides a more precise alternative: listing the 98 problematic tree objects and 1 tag in a `fsck.skiplist` file, which exempts only the known historical objects while still catching new issues. 

The email includes the complete list of object hashes to populate the skip list. Junio notes an interesting implementation detail - while `git cat-file` can see the original problematic modes, `git ls-tree` normalizes them, showing how Git handles these legacy cases internally. 

This adds a maintainer-oriented refinement to the earlier resolution, preserving fsck's protective role for new contributions while accommodating Git's historical quirks. The thread appears effectively closed with this practical guidance for different user roles.
