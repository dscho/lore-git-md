This is the final patch in a v2 series addressing symbolic port handling in git-credential-netrc, implementing helper-side resolution via getservbyname. The thread has explored three technical approaches to handling symbolic ports in credential helpers, with this version representing the most comprehensive solution.

The patch series now includes:
1. A portable shebang change (split into its own commit)
2. Warnings for invalid ports
3. A new Git::is_port() utility function that validates both numeric and symbolic ports using getservbyname
4. Shared validation between credential helper and git-send-email
5. Comprehensive test coverage

The implementation handles edge cases like hyphenated service names (e.g. "re-mail-ck") and maintains backward compatibility. While technically robust, there remains an open design question about whether supporting symbolic ports contradicts the credential protocol's specification of "port number" (numeric only). The ball is now in the maintainer's court to decide between accepting this helper-side resolution, enforcing numeric-only ports, or updating the protocol documentation.

The patch author has addressed all previous feedback, making this a complete technical solution regardless of the eventual design decision. The changes are well-motivated by git-send-email's existing support for symbolic ports and include thorough validation that improves on the original silent-dropping behavior.
