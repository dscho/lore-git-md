This is a bug report about cloning from shallow ("grafted") repositories when using bundles. Andrey Butirsky reports that while direct cloning from a shallow repository works fine, creating a bundle from that same repository and then trying to clone from the bundle fails with an error about missing objects.

The reproduction steps clearly show the issue: after creating a shallow clone (--depth=1), the repository can be cloned directly, but when converted to a bundle first, the subsequent clone fails with "fatal: remote did not send all necessary objects". The error specifically mentions being unable to traverse parents of a grafted commit.

This appears to be a legitimate bug in Git's bundle handling when dealing with shallow repositories. The report is well-structured with clear reproduction steps and error messages, making it easy to verify. The issue seems to affect the interaction between Git's bundle creation and shallow clone functionality, potentially missing some object references that are present in the original shallow clone but not properly preserved in the bundle.

Given that shallow clones are a common workflow and bundles are often used for offline repository transfer, this could impact users who need to work with shallow repositories in disconnected environments. The bug report doesn't propose a solution, but provides all the necessary information for someone to investigate further.
