This is a refactoring patch that standardizes how `pack-objects` handles incompatible command-line options. It's the first in a 9-part series optimizing MIDX and cruft pack interactions during repacking.

The patch replaces several ad-hoc checks for mutually exclusive options with calls to the standard `die_for_incompatible_opt2()` function. This brings consistency to error messages when users supply incompatible combinations like `--stdin-packs` with `--filter` or `--keep-unreachable` with `--unpack-unreachable`. The change affects both the implementation and test expectations - one test in t5331 needed updating to match the new standardized error message format.

While this is primarily a code cleanup, it sets the stage for later patches in the series by establishing consistent error handling patterns. The change is straightforward and low-risk, touching only option validation logic without modifying core functionality. The patch has already been reviewed and approved as part of the larger series.
