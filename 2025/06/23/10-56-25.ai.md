This is the second patch in a two-part series enhancing the `test_seq` helper function in Git's test infrastructure. The patch adds a `-f` format option to `test_seq` that mimics GNU `seq -f` behavior, allowing printf-style formatting of sequence numbers directly within the helper.

The change eliminates the need for verbose shell loops or awk invocations in 9 test files across multiple subsystems (reftable, submodules, merges, etc.), replacing them with simpler `test_seq -f` calls. The implementation uses `%d` format specifiers (rather than `seq`'s `%g`) since `test_seq` only handles integers. Like `seq`, it automatically appends newlines to the output.

Key technical details include:
- The format string parsing is simple - it doesn't support multiple `%d` specifiers in one format string
- One test case in t7422 still requires a shell loop because it needs to include the sequence number twice in output
- The patch converts several test patterns:
  - Shell loops with printf piped to test_seq
  - Awk script generating sequence numbers
  - Manual printf sequences with test_seq

The changes are focused on test readability and maintainability, with no functional impact on the tests themselves. The patch follows logically from the first in the series (which cleaned up t7422) and completes the effort to modernize sequence generation in the test suite. The implementation appears careful and well-considered, with clear limitations documented in the commit message.
