Performance issue in `git rev-list --changed-paths` with multiple path filters. Kai Koponen follows up on their initial report with additional system information and version details (Git 2.50.0.714 built with GCC 14.2/glibc 2.41). The core observation remains that querying multiple paths together takes significantly longer than the sum of individual path queries, even with early termination via `-n` limit. The provided reproduction case in the Go repository shows a 2-path query taking 650ms versus 90ms+100ms for individual queries, suggesting inefficient handling of multiple-path filtering in the commit-graph's early termination logic. No solution is proposed yet, but the clear reproduction steps and version information should help others investigate. This appears to be a genuine performance regression in path filtering that warrants attention from commit-graph maintainers.
