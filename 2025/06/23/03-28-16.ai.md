This is the third and final patch in Maxim Cournoyer's v2 series implementing symbolic port resolution in git-credential-netrc. The patch completes the helper-side resolution approach by:

1. Introducing a new `Git::is_port()` utility function in Git.pm that uses `getservbyname` to validate both numeric and symbolic port names
2. Updating git-credential-netrc to use this shared validation logic
3. Adding comprehensive test coverage for the new behavior
4. Maintaining backward compatibility with existing numeric ports

The implementation now properly handles edge cases like hyphenated service names (e.g. "re-mail-ck") that were missed in earlier regex-based approach. The patch also addresses Junio Hamano's earlier feedback by:

- Splitting the shebang change into a separate commit (already sent as first patch in v2)
- Adding port validation warnings (second patch in v2)
- Using proper port validation instead of regex matching

Key technical details:
- The new `Git::is_port()` function will be shared with git-send-email
- Validation follows POSIX `getservbyname` behavior
- Test cases cover both numeric and symbolic port scenarios
- Maintains the credential helper's existing behavior when ports are undefined

The patch series is now technically complete, but the fundamental design question remains unresolved - whether supporting symbolic ports in credential helpers contradicts the protocol's "port number" wording. The implementation demonstrates that helper-side resolution is feasible and robust, but awaits maintainer guidance on whether this approach aligns with protocol intentions.
