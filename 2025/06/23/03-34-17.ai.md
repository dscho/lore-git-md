Completion of v2 patch series for git-credential-netrc symbolic port support.

This email marks the completion of Maxim Cournoyer's v2 patch series addressing symbolic port handling in the git-credential-netrc Perl helper. The series now includes all requested changes from maintainer feedback:

1. The shebang change (/usr/bin/env) was split into a separate commit for better portability while maintaining build system compatibility
2. Added comprehensive port validation via a new Git::is_port() utility function that uses getservbyname(3) for proper service name resolution
3. Expanded the port pattern matching to handle hyphenated service names (like "re-mail-ck")
4. Added warning messages for invalid port specifications
5. Includes proper sign-off as requested

The implementation now shares validation logic with git-send-email and handles edge cases missed by the simpler regex approach. The technical work is complete with thorough test coverage and backward compatibility maintained.

However, the fundamental design question remains unresolved - whether supporting symbolic ports contradicts the credential protocol's specification of "port number" (Brian Carlson's earlier point). The thread now contains all technical implementations needed for a final decision between:
- Accepting helper-side resolution despite protocol wording
- Rejecting in favor of numeric-only ports per protocol
- Potentially updating protocol documentation

The ball is now in Junio Hamano's court to make this design decision, as the implementation work for all proposed approaches is complete. The v2 series demonstrates robust helper-side resolution while maintaining compatibility with existing numeric port usage.
