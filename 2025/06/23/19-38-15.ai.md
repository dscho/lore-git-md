This is the first patch in a finalized v4 series refactoring the promisor-remote protocol infrastructure. The patch converts the internal representation of promisor remotes from using separate `strvec` arrays for names and URLs to a dedicated `struct promisor_info` managed via `string_list`. 

The key changes are:
- Introduces `struct promisor_info` with explicit `name` and `url` members
- Uses `string_list` to manage promisor_info instances with name as key and struct as util
- Adds cleanup helpers and renames lookup function to `promisor_info_find()`
- Maintains identical external functionality while improving internal type safety
- Prepares for future extension to support additional fields

Justin Tobler provides minor review feedback on naming ("config_info" could be more specific) and error message clarity (suggesting "empty URL" instead of "invalid URL"), but these are small nits on an otherwise solid refactoring. The changes align with the series' goal of making the protocol more extensible while maintaining backward compatibility. 

This foundational patch enables the subsequent protocol enhancements in the series (field advertisement and validation) by providing a cleaner data structure to work with. The implementation appears thorough, with comprehensive cleanup handling and preserved behavior.
