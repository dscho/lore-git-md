This is a refactoring patch that cleans up memory management in the branch merge configuration handling, part of a larger series improving submodule remote lookup logic.

The patch addresses several memory management issues in the branch structure's merge configuration handling. Currently, branch->merge_name and branch->merge duplicate merge information, leading to confusing ownership and cleanup problems. The patch eliminates branch->merge_name entirely, moving all merge configuration storage into branch->merge (an array of refspec_items). It introduces a merge_clear() helper to properly free all merge-related resources and adds a set_merge flag to track initialization state.

Key technical changes include:
- Removing branch->merge_name field and all its uses
- Moving merge array allocation from set_merge() to add_merge()
- Adding merge_clear() to properly free merge resources
- Introducing set_merge flag to track initialization
- Updating all callers to use merge[i]->src instead of merge_name[i]
- Fixing memory leaks in branch_release() and set_merge()

The changes affect remote.h, branch.c, builtin/pull.c and remote.c, with callers updated to use the new structure. The patch builds on previous work referenced in [1] but takes a more comprehensive approach to cleaning up the memory management rather than just fixing individual leaks. This appears to be preparatory work for the larger submodule remote lookup improvements in the series.
