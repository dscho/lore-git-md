This is a feature proposal discussion for the new `repo-info` plumbing command, focusing on output format design considerations. Phillip Wood weighs in with several technical suggestions and concerns about the current implementation.

The key points center around output format choices for this plumbing command. Phillip argues that NUL-terminated output (similar to `git config --list -z`) would be more practical for script processing than the current LF-terminated key=value format, especially when handling paths. He also raises important questions about JSON encoding of non-UTF8 paths and suggests the command should require explicit format specification rather than having defaults.

Phillip extends the discussion to potential future functionality, proposing integration of features currently spread across `git rev-parse`, `git var`, and `git config`. He specifically suggests including `--git-path`-style path resolution in `repo-info`'s capabilities. The email also highlights the need to carefully consider path encoding in JSON output given Git's handling of arbitrary byte sequences.

This represents a substantive addition to the ongoing interface design discussion, bringing practical scripting concerns to the table. Phillip's suggestions about output formats and path handling will likely require consideration alongside the existing opt-in/opt-out debate between Junio and Karthik. The proposal to expand the command's scope to subsume other info-gathering commands suggests this could grow into a more comprehensive repository introspection tool.
