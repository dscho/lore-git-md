This is the third and final patch in Maxim Cournoyer's v2 series addressing symbolic port handling in git-credential-netrc. The patch completes the implementation of helper-side resolution for symbolic port names (like "smtps") by adding a new `Git::is_port()` utility function and integrating it with the credential helper.

The key technical changes include:
- Moving port validation logic to a shared Git.pm function
- Supporting hyphenated service names (like "re-mail-ck") via getservbyname
- Maintaining backward compatibility
- Adding comprehensive test coverage

The implementation is technically sound and aligns with git-send-email's existing symbolic port support. However, as noted in the thread context, there remains an open design question about whether supporting symbolic ports at all conflicts with the credential protocol's specification of "port number" (Brian Carlson has argued it does, while Maxim's implementation shows it can work in practice.

This patch series now presents a complete solution awaiting maintainer guidance on whether the approach aligns with protocol intentions. The ball is in Junio Hamano's court to decide between accepting helper-side resolution, enforcing numeric-only ports, or proposing protocol documentation updates.
