Performance optimization patch that dramatically speeds up `git fetch --prune` by eliminating a quadratic-time bottleneck in dangling ref detection. The current implementation makes O(M*N) string comparisons when pruning M refs from a repository with N refs (e.g., 3.6 billion strcmp calls when pruning 28k refs from 126k total). The patch replaces this with an O(N*logM) approach borrowed from `git remote prune` by first sorting the prune list to enable binary search.

Key changes:
- Modifies `prune_refs()` in builtin/fetch.c to collect refs in a string_list and sort it before checking for dangling refs
- Updates the dangling ref warning message format in both fetch.c and remote.c to show both the dangling ref and what it pointed to (with "refs/remotes/" prefix stripped for readability)
- Adjusts the warning output in refs.c to handle the new two-argument message format
- Maintains identical functionality while reducing runtime from 410 seconds to under 1 second in the test case

The patch is part of a 2-patch series (this being the first) that will ultimately remove the now-unused old implementation. The approach is proven from similar functionality in `git remote prune`, and includes a Reviewed-by from Jacob Keller. The changes touch fetch and remote builtins plus refs.c, with a net reduction of 13 lines.
