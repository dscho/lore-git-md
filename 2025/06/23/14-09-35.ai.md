Platform compatibility fix for FreeBSD builds when libsysinfo is present.

This email reports a build failure on FreeBSD systems where the libsysinfo package (a GNU libc sysinfo port) is installed. The issue occurs in Git 2.50.0 where the configure script detects libsysinfo but fails to add `-lsysinfo` to LDFLAGS, resulting in linker errors about undefined `sysinfo` symbols. 

The reporter notes that the FreeBSD ports system has already applied a local patch to work around this by adding a user option to enable/disable libsysinfo dependency and properly handle LDFLAGS when enabled. However, they're unsure what the best upstream solution would be for the Git project itself.

Key technical details: The build fails during linking with `scalar.o` and other objects, specifically complaining about the missing `sysinfo` symbol. The FreeBSD ports patch modifies `configure.ac` to properly handle the libsysinfo case. The reporter doesn't propose a specific solution for upstream Git, instead opening the question of how the project would prefer to handle this platform-specific build dependency.

This appears to be a genuine platform compatibility issue affecting real users, though the reporter hasn't provided a proposed patch for upstream consideration yet. The solution will likely involve either properly detecting and linking against libsysinfo when present, or explicitly disabling its use in the build configuration.
