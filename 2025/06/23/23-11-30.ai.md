This is a memory management bugfix in the remote handling code, part of a larger series improving submodule remote lookup logic.

The patch fixes a memory leak in `remote_clear()` where the function was failing to free the `push` and `fetch` refspec fields of the `struct remote`. While the leak wasn't caught by sanitizers when using `the_repository` (since those values never went out of scope), it would become apparent when the planned changes introduce submodule repository handling.

The change is straightforward - it adds calls to `refspec_clear()` for both refspec members. This is a preparatory cleanup for the series' later patches that will modify remote handling to work with repository pointers rather than relying on `the_repository`. The fix touches only `remote.c` with a simple 3-line addition.

As part of the v4 iteration of the patch series, this appears to be addressing a technical debt issue that was uncovered during the refactoring work. The change is small but important for proper memory management, especially as the code moves away from global state.
