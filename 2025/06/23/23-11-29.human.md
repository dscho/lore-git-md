Refactoring patch in a series improving submodule remote lookup. This is the first of seven patches that ultimately aims to make submodule remote URL matching more robust by removing assumptions about `the_repository`.

Jacob Keller cleans up the branch structure's merge tracking in `remote.c`, eliminating the dual storage of merge names in both `branch->merge_name` and `branch->merge`. The patch fixes several memory leaks in `branch_release()` and simplifies the logic tracks whether `set_merge()` has been called by introducing a new `set_merge` flag. The changes make the code more maintainable by clearly defining memory ownership and ensuring the merge array is always allocated when `merge_nr` is non-zero.

This appears to be a well-considered change that addresses long-standing technical debt. The commit message thoroughly explains the problems being fixed and the solution approach, including a link to previous discussion. The patch touches several files but focuses on internal remote handling code, so it unlikely to affect end users directly. As the first in a series, it sets up cleaner infrastructure for the subsequent functional changes.
