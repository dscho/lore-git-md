This is the first patch in a finalized v4 series enhancing the promisor-remote protocol. The series adds configurable validation of remote attributes during clone/fetch operations.

The patch refactors promisor-remote internals to replace `struct strvec` with a new `struct promisor_info` that stores name/URL pairs, managed via `string_list`. This provides better type safety and prepares for future addition of more fields. The changes are purely internal - external behavior remains identical.

Justin Tobler provides minor review feedback, noting:
- A typo in the commit message ("use use" -> "use")
- Suggests "promisor_info_list" might be clearer than "config_info" as a variable name
- Questions whether trailing semicolons in the protocol output would be acceptable
- Notes the BUG() message for invalid URLs could be more precise

The changes look clean and well-justified, with all functionality preserved. This foundational refactoring enables the subsequent patches in the series to add new promisor-remote capabilities. The series has already been approved by Christian Couder and is ready for merging.
