This is a regression fix for the submodule remote lookup series, specifically addressing a segfault in part 1 of the v3 series. The issue was introduced when Jacob Keller removed `branch->merge_name` in favor of using `branch->merge` directly, but didn't properly update the null-check behavior in `branch_has_merge_config()`.

Lidong Yan identified that the segfault occurred in fetch operations when checking merge configurations, because the new code didn't preserve the null-check behavior that existed when checking `branch->merge_name`. The fix is minimal but critical - it updates `branch_has_merge_config()` to check `branch->set_merge` instead of `branch->merge`, and improves memory safety by using `FREE_AND_NULL` in `merge_release()`.

The changes are focused in remote.c` with just two line modifications. The first ensures proper null-check behavior by checking the `set_merge` flag that was introduced in v3, while the second prevents potential double-free issues. Lidong verified the fix passes the failing t5582 tests locally.

This completes the regression fix needed for the maintainer to apply the v4 series. The solution maintains the original goals of simplifying the branch merge configuration while restoring the expected null-check behavior that some fetch code paths depended on. The fix is minimal and targeted, showing good responsiveness to the regression report.
