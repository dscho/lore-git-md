This is a follow-up discussion in the performance optimization thread for `git fetch --prune`. The conversation focuses on refining the wording of warning messages about dangling symrefs that result from pruning operations.

Junio C Hamano responds to Jacob Keller's observation about the current warning message being temporally confusing in `--dry-run` mode. The current output says a symref "will become dangling after" a ref is deleted, which doesn't match the actual state during a dry run where no deletions have occurred yet. Junio suggests that without `--dry-run`, the message should use present tense ("is now dangling") to accurately reflect the post-deletion reality.

This represents the final polish on an otherwise well-received optimization series that dramatically improves `git fetch --prune` performance (410s to 4s in test cases). The core technical approach has already been validated by multiple reviewers, with only this minor wording issue remaining before likely acceptance. The discussion shows attention to detail in ensuring clear user messaging while maintaining the significant performance gains.
