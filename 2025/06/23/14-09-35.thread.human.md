This thread addresses a FreeBSD build compatibility issue that emerged in Git 2.50.0, where builds fail when the GNU libc sysinfo compatibility library (libsysinfo) is installed but not properly linked. The problem manifests as undefined symbol errors during linking, particularly affecting `scalar.o`. Renato Botelho, the FreeBSD ports maintainer, initially reported the issue and has been working with Eric Sunshine to develop solutions.

Three distinct approaches have now emerged: (1) a minimal configure.ac fix to prevent HAVE_SYSINFO definition when linking fails, (2) a comprehensive solution adding proper NEEDS_LIBSYSINFO support throughout the build system, and now (3) Ramsay Jones' new proposal that restructures the detection logic to prefer BSD's native sysctl interface when available, only falling back to sysinfo when necessary. Jones' approach modifies both configure.ac and meson.build to maintain consistency between build systems, though it still needs verification from FreeBSD users.

Eric Sunshine has provided detailed technical guidance on implementing either of the first two approaches while leaving the architectural choice to Botelho. The discussion remains technically focused on build system conventions and backward compatibility, with no maintainer input yet on which direction to take. The thread now presents three viable paths forward, each with different tradeoffs between complexity, functionality, and platform coverage.
