This thread addresses a FreeBSD build compatibility problem that emerged in Git 2.50.0, where the build system incorrectly handles systems with GNU libc's sysinfo port (libsysinfo) installed. The issue manifests as linker errors when building `scalar.o` and other components. Renato Botelho (FreeBSD ports maintainer), Eric Sunshine, and Ramsay Jones have proposed three distinct solutions with different architectural approaches.

Ramsay Jones' latest solution - which suppresses HAVE_SYSINFO when native BSD sysctl is available - has now been confirmed by Renato Botelho to work correctly on FreeBSD with libsysinfo installed, though meson build testing remains pending. This preprocessor-based approach avoids modifying linker flags entirely, differing from earlier proposals that involved build system changes.

The discussion has now expanded beyond the immediate fix to consider broader build system strategy. Key open questions include whether FreeBSD ports should transition from autotools to meson builds, and how this aligns with Git's long-term build system direction. While the technical solution appears validated for the autotools case, the meson build verification and these higher-level questions about build system evolution remain outstanding. The thread now presents both a working solution to the original problem and important strategic considerations for FreeBSD packaging going forward.
