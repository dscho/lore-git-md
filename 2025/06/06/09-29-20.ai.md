Platform compatibility patch series addressing cURL type mismatches on macOS, building on prior work by Jeff King. This is version 2 of a series that now incorporates King's earlier fixes (jk/curl-easy-setopt-typefix) while adding macOS-specific cases that weren't caught by those changes.

The core issue stems from cURL 8.14.0's stricter type checking in `curl_easy_setopt()` calls, where Git was passing `int` values where `long` was expected. While King's patches addressed Debian build failures, Schindelin's work here catches additional macOS-specific cases found during Git for Windows release testing. The changes are mechanical type casts (`1` -> `1L`) and explicit `(long)` conversions for enum values, with no runtime behavior changes.

Key technical details: The patch touches four files (`http-push.c`, `http.c`, `imap-send.c`, `remote-curl.c`) and handles three categories of fixes: integer constants (adding `L` suffix), variables (explicit `(long)` cast), and symbolic constants (enum values needing casting). Schindelin verified completeness by manually checking all 23 `curl_easy_setopt()` calls in the codebase against the new stricter requirements.
