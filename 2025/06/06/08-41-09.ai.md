This is a v3 bugfix series addressing edge cases in batched reference updates, building on Patrick Steinhardt's earlier work. The series now consists of two patches that fix production issues found when running Git's `next` branch in GitLab's Gitaly service.

The first patch fixes a segfault in the files backend by properly skipping failed updates during batched operations, adding test coverage in `t/t1400-update-ref.sh`. The second patch restructures `git receive-pack` to handle reference deletions separately from other updates to avoid filesystem directory/file conflicts, mirroring a similar fix previously applied to `git fetch`. The implementation now uses an enum for clearer phase separation and only creates transactions when needed, addressing Karthik's own review feedback from v2.

Key technical changes in v3 include cleaning up stale comments, making transaction creation lazy (only when updates exist), and fixing a typo ("s1tart" -> "start"). The test coverage in `t/t5516-fetch-push.sh` and `t/t1416-ref-transaction-hooks.sh` verifies the behavior, including proper hook ordering. While this approach may use up to two transactions (for deletions and other updates), it remains more efficient than the pre-batched implementation which used at least two transactions.

The series appears ready for integration with all major issues addressed and thorough test coverage. The changes are focused and well-motivated by real-world production needs, with clear progression from the v1 and v2 iterations based on reviewer feedback.
