This is a feature and bugfix series for `imap-send`, now in its 14th iteration, that restores functionality broken since Git 2.46.0 and adds OAuth2.0 support. The series has undergone extensive review and refinement, with v14 addressing final design questions about authentication method handling.

The patch series fixes a critical configuration parsing bug that made `imap-send` unusable by incorrectly NULLing the folder field. It implements OAuth2.0 authentication (both OAUTHBEARER and XOAUTH2) and PLAIN authentication, with proper compile-time guards for OpenSSL dependencies. The latest version introduces `try_auth_method()` to reduce code duplication in authentication handling and adds clarifying comments about libcurl's password handling for OAuth methods.

New user-facing features include command-line folder specification (`--folder`) and folder listing (`--list`). The series also improves logging consistency, adds destination folder visibility during sending, and shows port numbers in credential prompts. Memory management is tightened, particularly around CRAM-MD5 authentication when OpenSSL is unavailable.

Key technical points in v14:
- Adds `try_auth_method()` helper to consolidate authentication attempts
- Documents rationale for not using `CURLOPT_PASSWORD` with OAuth2.0
- Maintains backward compatibility while adding new features
- Standardizes error message formatting throughout the code

The implementation spans configuration parsing, authentication handlers, and IMAP protocol handling. The series has been reviewed by multiple Git maintainers, with v13 having already addressed the critical OAuth logic error identified by Jeff King. The current discussion focuses on code organization and maintainability rather than functional issues, suggesting this is likely nearing final approval.
