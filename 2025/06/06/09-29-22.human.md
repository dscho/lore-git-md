This is part 2 of a 4-part bugfix series addressing compiler warnings from cURL 8.14.0's stricter type checking. While the first patch handled integer literals, this one focuses on variables passed to `curl_easy_setopt()` calls in `imap-send.c`.

The patch adds explicit `(long)` casts for three variables where cURL expects `long` values but Git uses `int` or `bool`-like types. The author explains the tradeoffs of changing the variable types themselves versus adding casts, noting that while declaring them as `long` would work, it would feel conceptually wrong for values like port numbers (which are conceptually `short`) and boolean flags. The changes are straightforward and match existing casting patterns in the code.

This continues the coordinated effort to fix platform-specific compiler warnings across the codebase, with all changes being compile-time only and verified by manual inspection. The patch is low-risk and maintains the existing behavior while satisfying the stricter type requirements.
