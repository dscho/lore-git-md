This is a bugfix series addressing edge cases in batched reference updates, now at v3. The patches were originally developed by Patrick Steinhardt based on GitLab's production experience, with Karthik Nayak now carrying them forward with refinements.

The series fixes two critical issues that emerged when using batched updates in production. First, the files backend could segfault when failing to properly skip already-failed updates. Second, `git receive-pack` handled directory/file conflicts differently in batched mode versus sequential mode, causing pushes that worked before to fail. The solution mirrors an earlier `git fetch` fix by separating reference deletions into their own transaction phase.

Version 3 makes two key improvements: it cleans up stale comments and now only creates transactions when actually needed (avoiding empty transactions). The implementation maintains the safety of using two transactions (one for deletions, one for other updates) while being more efficient than the pre-batched approach. Test coverage in t1400-update-ref.sh and t5516-fetch-push.sh verifies the fixes.

The changes look well-considered, with clear commit messages and thorough testing. The v3 refinements address all outstanding review feedback, making this series ready for integration. These are important fixes for anyone using the batched reference updates feature in Git 2.45+.
