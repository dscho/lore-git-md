This is a bugfix patch addressing a critical regression in `imap-send`. The patch corrects a configuration parsing bug introduced in commit 6d1f198f34 that caused `cfg->folder` to be incorrectly NULLed out when processing unrelated configuration variables like `imap.user`, `imap.pass`, `imap.tunnel`, and `imap.authmethod`. This regression has made `git-imap-send` completely unusable since Git 2.46.0.

The fix is straightforward - it changes the `FREE_AND_NULL` operations to target the correct struct fields (user, pass, tunnel, auth_method) rather than incorrectly freeing the folder field in all cases. The patch maintains the same memory management approach but applies it to the proper fields. This matches the thread context which identified this as a critical regression that needed fixing.

The bug appears to have gone unnoticed for some time, likely because most users prefer `git-send-email` over `imap-send`. The patch is part of a larger v14 series that adds OAuth2.0 support and other improvements to `imap-send`, but this particular fix stands alone as a critical correction of broken functionality. The change is minimal (4 lines modified) and clearly targeted at the specific regression.
