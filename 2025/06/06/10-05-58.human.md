This is the final patch in a series addressing cURL type mismatch warnings, specifically focusing on remaining boolean/numeric flags that needed `long` casting on macOS builds.

Jeff King (Peff) responds to Johannes Schindelin's patch that adds `L` suffixes to integer literals in `curl_easy_setopt()` calls for options like `CURLOPT_NOBODY` and `CURLOPT_POST`. While agreeing the changes are correct, Peff questions the explanation about different build options being the issue, noting these same changes were needed when building against a custom libcurl on Debian. He points out the root cause of why some builds catch these warnings while others don't remains unclear.

Peff also notes the audit command used might miss some variable cases, but given the comprehensive coverage across the series (including his earlier patches for Debian), he suggests the current state is good enough - any remaining issues can be fixed if they surface. The exchange highlights how different build environments revealed different instances of the same underlying type mismatch, leading to a more complete solution overall.
