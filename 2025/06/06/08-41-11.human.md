Bugfix for batched reference updates in `git receive-pack`, addressing F/D conflicts. This is the second patch in Patrick Steinhardt's v3 series, now with Karthik Nayak as the submitter after review iterations.

The patch fixes an edge case where batched updates could fail when pushing a mix of reference deletions and creations that would create filesystem directory/file conflicts (like deleting `refs/heads/branch/conflict` while creating `refs/heads/branch`). The solution mirrors an earlier `git fetch` fix by splitting deletions into a separate transaction phase, ensuring they're processed first. 

Key changes include:
- Introducing explicit `PHASE_DELETIONS` and `PHASE_OTHERS` processing phases
- Lazy transaction creation (only when updates exist)
- Updated test coverage in `t/t5516-fetch-push.sh` with a new F/D conflict scenario

The implementation maintains the performance benefits of batched updates while fixing the conflict case, using at most two transactions (still better than the pre-batched minimum of two). The patch appears well-tested and addresses all prior feedback, making it likely ready for integration.
