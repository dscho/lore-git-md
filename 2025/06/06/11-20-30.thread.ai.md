Thread identity: Bug report about Git branch deletion behavior on Windows, reported by Ondra Medek. Initially thought to be a Windows-specific ref handling issue, but ultimately resolved as a configuration error.

Core problem: The thread investigated why `git push origin :branch1` would successfully delete remote refs but incorrectly report "remote ref does not exist" on Windows (Git 2.49.0). The root cause was duplicate `url` entries in `.git/config` under `[remote "origin"]`, causing the erroneous error message after successful ref deletion.

Current status: Resolved. Ondra Medek identified the configuration error after earlier speculation about repository corruption. The issue was specific to clones with duplicate remote URLs in config, not a general Windows bug. Solution is to remove duplicate URL lines from config.

Key technical details:
- Affected both branch and custom ref deletions
- Windows environment with Git 2.49.0 (though config error could affect any platform)
- Fresh clones worked correctly because they didn't inherit duplicate config
- Earlier `git gc --aggressive --prune` attempts didn't help because issue was config-based
- Error manifested as successful deletion followed by incorrect "does not exist" message
- Root cause: duplicate `url` entries in remote configuration

Open questions: None - root cause identified and resolved.
