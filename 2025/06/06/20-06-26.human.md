Bugfix in the `imap-send` series addressing a memory leak in CRAM-MD5 authentication. This is part of a larger v14 series that adds OAuth2.0 support and fixes several IMAP-related issues.

The patch fixes a case where memory allocated for the CRAM-MD5 challenge response would leak if the socket write operation failed. The fix is straightforward - freeing the response buffer in the error path before returning. This matches the pattern used in the success path where the buffer is always freed.

While small, this is a proper fix for a real issue in the authentication flow. The change is well-contained and follows the established error handling patterns in the code. It's one of several memory management improvements in the series, which has undergone extensive review from multiple Git maintainers.
