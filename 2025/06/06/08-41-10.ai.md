This is a bugfix patch in the batched reference updates series, addressing a segfault in the files backend when handling failed updates. It's the first of two patches in v3 of this series.

The patch fixes a critical issue where the files backend could segfault when processing batched reference updates that included failed operations. The problem occurs in `files_transaction_finish()` where two loops weren't properly skipping updates that had already failed (marked with `rejection_err`). The fix adds the missing checks in both loops that handle reference deletions and directory cleanup.

The patch includes three new test cases in `t/t1400-update-ref.sh` that verify the fix works for different failure scenarios: deleting a symbolic ref pointing to a non-existent ref, deleting with an incorrect old OID, and deleting a non-existent ref. These tests ensure the batched update mechanism properly handles failures without crashing.

This builds on commit 23fc8e4f61 which introduced batched reference updates. The changes are focused on the test coverage is thorough, exercising the edge cases that could trigger the segfault. The implementation matches the thread's earlier discussion about properly handling failed updates in batched operations, and appears ready for integration after multiple rounds of review.

Key technical details: The fix modifies `refs/files-backend.c` to check `update->rejection_err` before processing updates in both loops. The test additions demonstrate the failure cases that would previously crash, now properly reporting errors instead. This maintains the batched update behavior where some operations can fail while others succeed.
