Platform compatibility fix completing the curl_easy_setopt() type mismatch series.

This final patch in Johannes Schindelin's 4-part series addresses remaining `int`-to-`long` conversion warnings in `curl_easy_setopt()` calls, specifically those found in macOS builds with cURL 8.14.0. The changes mirror the pattern established in earlier parts - adding `L` suffixes to integer literals passed to cURL options like `CURLOPT_UPLOAD`, `CURLOPT_NOBODY`, and `CURLOPT_HTTPGET`. 

The patch touches three files (`http-push.c`, `http.c`, `remote-curl.c`) with mechanical conversions of boolean flags and numeric options. Schindelin notes these were caught by Homebrew's cURL update but not by earlier Debian-focused fixes, demonstrating how different build configurations surface different instances of the same underlying type mismatch. A manual audit confirms all 23 `curl_easy_setopt()` calls in the codebase now properly pass `long` values where expected.

This completes the coordinated effort to eliminate compiler warnings from cURL's stricter type checking while maintaining runtime behavior. The series combines Jeff King's initial Debian fixes with Schindelin's comprehensive coverage across platforms, establishing a consistent pattern for handling literals, variables, and now the remaining constants. With all identified cases addressed and no outstanding objections in the thread, this appears to be the final piece of the type safety improvements.
