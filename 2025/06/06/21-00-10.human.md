This is an RFC proposal for a new experimental tool called `rebase--` that aims to improve conflict resolution during rebases by leveraging information from original merge commits. The tool is positioned as a complementary approach to `git rebase` rather than a replacement, focusing specifically on non-interactive rebases involving merges.

Edmundo Carmona Antoranz presents a Python/pygit2-based script that performs rebases in-memory without touching the working tree. The key innovation is attempting to reuse original merge resolutions when possible, avoiding redundant conflict resolution for cases where the same conflicts were already solved in the original history. The tool demonstrates success on a Linux kernel repository test case where standard `git rebase` fails, though it still hits limitations on more complex merges (shown in the mm/page_alloc.c example).

The current implementation handles blobs atomically rather than attempting partial merges, which Carmona notes as a planned enhancement. Other next steps include adding working tree updates and reference adjustments. The tool is available on GitHub for testing, with Carmona inviting feedback from the community. This appears to be a thoughtful exploration of previous discussions about improving rebase's merge handling, though as an external Python tool it would need significant work to integrate with core Git's C codebase.
