Bug report about Git branch deletion behavior on Windows. Ondra Medek reports that when deleting a remote branch via `git push origin :branch1`, Git first successfully deletes the branch but then fails with "remote ref does not exist" error. The issue appears specific to one local repository clone - a fresh clone works correctly. The reporter mentions this also occurs with custom refs, suggesting it may be related to ref handling rather than just branches. 

The key technical details are: Git version 2.49.0 on Windows, error occurs during ref deletion where the operation succeeds but reports failure, problem persists after `git gc --aggressive --prune`, and is resolved by cloning fresh. The reporter is asking whether this is a known bug and if there are repair options beyond recloning. 

This appears to be a repository corruption issue affecting ref deletion, though the exact nature isn't clear from the report. The fact that it affects both branches and custom refs suggests a problem with Git's ref handling machinery rather than branch-specific code. The working/not-working comparison between old and new clones points to local repository state rather than a general Windows bug.
