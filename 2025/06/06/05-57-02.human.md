Bugfix for git-gui's build system that prevents accidental deletion of source files during NO_TCLTK builds. This is part of the critical regression fix for Git 2.50.0-rc1 where TCL source files were being deleted during builds without TCL/Tk support.

Johannes Sixt provides the proper fix for the issue first reported by Randall Becker, where the `generate-tclindex.sh` script was incorrectly expanding `$@` to delete all TCL source files rather than just the intended `lib/tclIndex` file. The problem originated when build infrastructure was converted from Makefile rules to a shell script in March 2025, but one `$@` reference wasn't properly converted to the hardcoded filename.

The patch is straightforward - it replaces the problematic `rm -f $@` with `rm -f lib/tclIndex` to ensure only the index file gets removed when auto-indexing fails. This matches the original intended behavior and prevents the destructive file deletion that was occurring in 2.50.0-rc1 builds.

This appears to be the definitive fix for the regression, addressing the root cause rather than just providing workarounds (like the temporary `NO_TCLTK=NoThanks` solution). The change is minimal and focused, with a clear explanation of both the problem was and how this solution corrects it. Given the critical nature of the regression and the clean fix, this will likely be fast-tracked into the final 2.50.0 release.
