This is a feature patch in the ongoing `imap-send` authentication series, adding PLAIN authentication support for the OpenSSL backend. The patch follows the established pattern from earlier authentication methods in the series, implementing RFC 4616-compliant PLAIN authentication that was previously only available with libcurl.

The implementation introduces a new `AUTH_PLAIN` capability flag and a `plain_base64()` helper function that constructs the proper authentication string (NUL-separated user and password) before base64 encoding. The `auth_plain()` handler performs the actual IMAP protocol exchange. The documentation is updated to reflect that PLAIN is now available for both backends.

The patch fills a gap where OpenSSL users couldn't use PLAIN authentication despite it being a common method (especially with app passwords). The implementation matches the existing style of the other authentication methods in the codebase, using similar memory management patterns and error handling. This is part of the broader effort to make `imap-send` fully functional with both OpenSSL and libcurl backends, addressing a regression from Git 2.46.0 while adding modern authentication methods.

Key technical details include the RFC 4616-compliant string construction in `plain_base64()`, the new capability flag, and integration with the existing `try_auth_method()` framework. The patch maintains the series' pattern of compile-time guards (with `#define auth_plain NULL` for non-OpenSSL builds) and consistent error handling.
