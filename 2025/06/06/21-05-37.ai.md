This is a refactoring patch addressing byte-order handling in `compat/bswap.h`, with follow-up review from Junio Hamano. The original patch by Sebastian Siewior moved macro definitions for `ntohl`/`htonl` conversions to ensure they're only redefined on little-endian systems where `bswap` functions are available, fixing incorrect redefinitions on big-endian systems introduced by commit 6547d1c9cb.

Junio's review focuses on improving the commit message quality, suggesting it should clearly state: (1) the problem (broken tests on s390x due to incorrect macro redefinitions on big-endian systems), (2) the faulty assumption (that `bswap` macros would only be defined on little-endian), and (3) the solution (moving the redefinitions after byte-order detection). He provides concrete examples of how the message could be structured.

The technical review notes that while the patch improves the situation, the resulting code still has an odd asymmetry: the 64-bit macros (`ntohll`/`htonll`) are unconditionally redefined (to identity on big-endian), while the 32-bit versions (`ntohl`/`htonl`) are only redefined when `bswap32` exists. This suggests the refactoring might need further refinement to achieve complete consistency in the handling of different bit-width conversions.

Key technical details include: conditional macro reordering in `compat/bswap.h`, interaction between built-in `bswap` functions and manual byte-swapping logic, and platform-specific behavior differences between little-endian and big-endian systems. The discussion references test failures (including `t1234-be.sh`) that motivated the fix, though the original patch didn't document these.
