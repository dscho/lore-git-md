A contributor has proposed a new tool called `rebase--` that aims to improve conflict resolution during non-interactive rebases involving merge commits. Unlike standard `git rebase`, this experimental tool attempts to reuse objects from original merge commits when resolving conflicts, potentially automating some cases that currently require manual intervention. The author demonstrates successful rebases in the Linux kernel repository where traditional rebase fails, showing identical results while operating quickly in-memory.

Currently implemented as a Python tool using pygit2, `rebase--` has some limitations - it only handles whole-blob resolutions rather than partial merges, and lacks working tree integration. The author outlines plans to expand its capabilities and invites community testing and feedback. While not yet ready for production use, this represents an interesting technical exploration of an idea previously discussed on the list, offering a complementary approach to Git's existing rebase machinery for certain conflict scenarios.
