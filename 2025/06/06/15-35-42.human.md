This is the final patch in a series addressing platform-specific compiler warnings from cURL 8.14.0's stricter type checking. The patch completes the effort to fix all remaining cases where Git passes `int` values to `curl_easy_setopt()` where `long` is expected.

The changes convert numeric constants in `http-push.c`, `http.c`, and `remote-curl.c` to use `L` suffixes (e.g. changing `1` to `1L`). While earlier patches in the series handled integer literals and variables, this one focuses on boolean flags and numeric options that were missed initially. The author manually verified all 23 `curl_easy_setopt()` calls to ensure completeness.

Junio Hamano notes that this matches the remaining cases identified in previous discussion, though he questions whether the verification command might have missed some symbolic constants. The patch builds on Jeff King's earlier fixes while addressing additional cases that surfaced in macOS builds due to different compiler options.
