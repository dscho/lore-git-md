This is a technical discussion about deterministic Change-ID generation in Git commits, part of an ongoing thread about standardizing change identifiers.

Toon Claes responds to Brian Carlson's proposal for deterministic Change-ID generation (using SHA-256 hashes of commit data) by initially questioning whether determinism is truly achievable since the underlying commit can change. However, he then acknowledges that some determinism could be useful for interoperability between tools generating Change-IDs for the same commit.

The email also notes agreement with Brian's suggestion for a config option to opt out of Change-ID generation for privacy reasons. This continues the thread's exploration of balancing technical implementation with user control and metadata adoption concerns. The exchange remains focused on technical feasibility while acknowledging the social factors (like privacy preferences) that affect real-world usage.
