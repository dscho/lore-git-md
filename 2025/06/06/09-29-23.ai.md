This is part 3 of a 4-part series addressing type mismatch warnings in cURL calls, specifically focusing on symbolic constants. The patch modifies `http.c` to explicitly cast cURL's own symbolic constants (like `CURLSSLOPT_NO_REVOKE` and various `CURLPROXY_*` values) to `long` when passed to `curl_easy_setopt()`, matching the stricter type checking introduced in cURL 8.14.0.

The changes are mechanical and consistent with cURL's documented examples, though Jeff King notes it's odd that cURL doesn't define these constants as `long` to begin with. The patch handles proxy type settings (`SOCKS5`, `HTTPS` etc.) and SSL options, with each case getting the same `(long)` cast treatment. This follows the established pattern from parts 1-2 (integer literals and variables), completing the third category of fixes (symbolic constants).

The changes are low-risk (compile-time only) and maintain compatibility with existing cURL versions. With this patch, the series now covers all three identified cases where Git passes `int` values where cURL expects `long`. The remaining part 4/4 will presumably address any remaining enum cases, as indicated in the thread summary.
