Bugfix patch in the `imap-send` series, improving error handling for CRAM-MD5 authentication when OpenSSL is unavailable. This is part of a larger v14 series adding OAuth2.0 support and fixing various IMAP-related issues.

The patch changes how `imap-send` handles CRAM-MD5 authentication attempts when built without OpenSSL support. Previously, it would crash with a `die()` call when users tried to use this authentication method without OpenSSL. The new behavior checks for OpenSSL availability upfront and provides a graceful error message instead.

The implementation moves the CRAM-MD5 authentication logic into a dedicated function and properly integrates it with the existing authentication framework. This matches the pattern used for other auth methods in the codebase. The change is particularly important because CRAM-MD5 is the only authentication method in this series that requires OpenSSL - other methods like PLAIN, OAUTHBEARER and XOAUTH2 work with libcurl alone.

This appears to be a straightforward improvement that completes the authentication method handling in the IMAP code. It's part of a well-reviewed series that has addressed several edge cases around IMAP authentication and configuration. The patch follows the established patterns in the codebase and maintains consistency with how other auth methods are handled.
