Bugfix addressing the critical build system regression in git-gui's TCL file handling. This patch fixes the issue where `generate-tclindex.sh` was incorrectly deleting source TCL files during NO_TCLTK builds due to a misinterpretation of `$@` in the shell script context.

The root cause was introduced in commit 2cc5b0facfa4 which converted Makefile commands to a shell script but missed properly translating the `$@` variable reference in the error cleanup path. Instead of removing just the target `lib/tclIndex` file as intended, the script was expanding `$@` to all command line arguments (the source TCL files) and deleting them. Johannes Sixt's fix explicitly specifies the correct target file path.

This is the proper solution to the regression first reported by Randall S. Becker and analyzed in depth in the thread, where it was identified as causing source file deletion during builds without TCL/Tk support. The patch cleanly addresses the core issue that was previously worked around via the `NO_TCLTK=NoThanks` temporary mitigation. The change is minimal and focused, directly correcting the problematic `rm` command while maintaining all other behavior of the TCL index generation script.

Key technical details for future reference:
- Fixes interaction between NO_TCLTK builds and TCL index generation
- Corrects behavior introduced in 2cc5b0facfa4 (git-gui: extract script to generate "tclIndex")
- Changes `rm -f $@` to `rm -f lib/tclIndex` in error path
- Preserves all other aspects of the index generation logic
- Follows from earlier analysis showing ALL_LIBFILES emptiness triggering the issue

The patch represents the definitive solution to this critical regression that must be included in Git 2.50.0's final release. It has clear provenance from the original reporter through the technical analysis to this final fix.
