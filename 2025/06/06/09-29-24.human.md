This is the final patch in a 4-part series addressing platform-specific compiler warnings from cURL 8.14.0's stricter type checking. The series systematically fixes cases where Git passes `int` values to `curl_easy_setopt()` where `long` is expected.

This fourth part handles the remaining cases where integer constants (like `0` and `1`) were being passed directly to `curl_easy_setopt()` calls. The patch mechanically converts these to `long` by adding an `L` suffix (e.g. `1` becomes `1L`). The changes span three files (`http-push.c`, `http.c`, `remote-curl.c`) and touch common cURL options like `CURLOPT_UPLOAD`, `CURLOPT_NOBODY`, and `CURLOPT_HTTPGET`.

The author notes they manually verified all 23 `curl_easy_setopt()` calls in the codebase to ensure complete coverage, building on previous work that addressed similar issues on Debian systems. The changes are compile-time only and maintain existing behavior while satisfying the stricter type checking in newer cURL versions.

This concludes the coordinated effort to resolve these warnings across all affected platforms, with the series combining fixes for macOS-specific cases with earlier Debian-focused work. The approach is now comprehensive and consistent, with no outstanding type mismatch issues remaining.
