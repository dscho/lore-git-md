This is a bugfix patch for the files backend's batched reference updates functionality, part of Patrick Steinhardt's v3 series addressing production issues in GitLab's Gitaly service.

The patch fixes a segfault that could occur when processing failed updates in batched reference transactions. The issue stems from two loops in `files_transaction_finish()` that weren't properly skipping updates marked with `rejection_err`, which could lead to null pointer dereferences. The fix adds the missing checks in both loops.

Karthik Nayak (taking over from Patrick for this patch) includes three new test cases in `t/t1400-update-ref.sh` that verify the fix by exercising different failure scenarios: deleting symbolic refs pointing to non-existent targets, deleting refs with incorrect old OIDs, and deleting non-existent refs. The tests confirm the system correctly handles these error cases without crashing.

This appears to be a straightforward and well-tested fix for a clear bug. The changes are minimal (just two condition checks) but important for stability, and the test coverage is thorough. The patch builds on the batched reference updates feature introduced in commit 23fc8e4f61, and is part of a series that has already undergone multiple rounds of review.
