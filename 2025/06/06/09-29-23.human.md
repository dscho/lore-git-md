Platform compatibility fix for cURL type checking in Git's HTTP code. This is part 3 of a 4-part series addressing stricter type requirements in cURL 8.14.0's `curl_easy_setopt()` calls.

Jeff King's patch focuses on cases where Git passes cURL's own symbolic constants (like `CURLSSLOPT_NO_REVOKE` and various proxy types) that need explicit casting to `long`. The changes are mechanical but necessary to avoid compiler warnings and potential undefined behavior. The patch notes it's somewhat odd that cURL doesn't define these constants as `long` to begin with, but follows cURL's documented practice of casting at call sites.

The changes affect `http.c`, modifying several `curl_easy_setopt()` calls related to SSL options, redirect behavior, and proxy type configuration. All modifications follow the same simple pattern of adding `(long)` casts. The patch is low-risk as it only affects compile-time behavior, not runtime functionality.

This continues the coordinated effort with Johannes Schindelin's series, now handling the enum/constant cases after previous patches addressed integer literals and variables. The changes are straightforward and unlikely to be controversial, completing another piece of the comprehensive type-safety update for cURL interactions.
