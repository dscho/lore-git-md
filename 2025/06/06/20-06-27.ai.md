This is a bugfix patch in the `imap-send` series, specifically addressing CRAM-MD5 authentication behavior when OpenSSL is not available. The patch improves error handling by checking for OpenSSL support upfront rather than failing during authentication.

The change moves the CRAM-MD5 authentication logic into a dedicated `auth_cram_md5()` function and makes it NULL when OpenSSL is unavailable, consistent with how other auth methods are handled. This replaces the previous behavior where attempting CRAM-MD5 without OpenSSL would trigger a `die()` call. The patch also simplifies the authentication flow by using the existing `try_auth_method()` helper rather than custom CRAM-MD5 handling code.

Key technical details:
- Adds proper compile-time guards for CRAM-MD5 support
- Standardizes the auth method handling to match other methods (PLAIN, OAUTHBEARER)
- Maintains the same memory management pattern (freeing response buffers)
- Uses existing error reporting infrastructure rather than direct stderr writes

This appears to be a straightforward improvement that completes the authentication method handling standardization in the series. The change is consistent with the overall goal of making `imap-send` more robust and maintainable while preserving all existing functionality. The patch follows the established patterns seen in other parts of the series and doesn't introduce any new concepts or dependencies.
