This is a refactoring patch addressing byte-order handling in `compat/bswap.h`, with follow-up review from Junio Hamano. The original patch from Sebastian Siewior fixed incorrect redefinitions of `ntohl`/`htonl` macros on big-endian systems by moving their conditional definitions to only apply on little-endian systems where `bswap` functions are available.

Junio's review focuses on improving the commit message, suggesting it should clearly state: (1) the problem (broken tests on s390x due to incorrect macro redefinitions), (2) the faulty assumption (that `bswap` macros would only exist on little-endian systems), and (3) the solution (moving the redefinitions to only apply on little-endian). He also notes an oddity in the resulting code where 64-bit macros are handled differently from 32-bit ones, though he agrees the patch is an improvement overall.

The technical change involves moving 21 lines of macro definitions in `compat/bswap.h` to ensure proper conditional logic while maintaining identical behavior. The patch has been tested on both s390x (big-endian) and x86-64 (little-endian) platforms with passing test suites. This builds on commit 6547d1c9cb which originally added built-in bswap support.
