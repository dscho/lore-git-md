This is an RFC proposal for a new tool called `rebase--` that aims to improve conflict resolution during rebases by leveraging information from original merge commits. The tool is positioned as a complementary approach to `git rebase` rather than a replacement, focusing specifically on non-interactive rebases involving merges.

The key innovation is that `rebase--` attempts to reuse existing objects (trees/blobs) from the original commits when resolving conflicts, potentially avoiding user intervention for simple cases. The author demonstrates successful rebases in the Linux kernel repository where standard `git rebase` fails, showing identical diffs between the original and rebased versions. The tool operates in-memory without touching the working tree or references, completing operations quickly (under 0.4s in the example).

Current limitations include only handling whole-blob resolutions rather than attempting partial merges, and lacking working tree integration. The author outlines next steps to implement blob merging capabilities and working tree support. The implementation uses pygit2 and is available on GitHub, with the author inviting testing and feedback from the community.

This appears to be a serious technical exploration of an idea previously discussed on the list, though as an external Python tool rather than a core Git feature. The approach seems promising for certain conflict scenarios but would need significant work to handle more complex cases and integrate with Git's existing rebase machinery.
