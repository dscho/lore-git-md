This is a platform compatibility fix addressing compiler warnings from cURL 8.14.0's stricter type checking. Jeff King's patch fixes integer constant type mismatches in `curl_easy_setopt()` calls by adding `L` suffixes to make them explicitly `long` values, as required by cURL's API.

The changes are mechanical but important - they ensure Git properly follows cURL's documented API requirements where integer options must be passed as `long` values. The warnings appeared with cURL 8.14.0's new type-checking macros, particularly when compiling with -O2 optimizations.

The patch touches three files (`http-push.c`, `http.c`, and `remote-curl.c`), converting integer literals used in various cURL options (like SSL verification settings, HTTP methods, and timeouts) to their long equivalents. While these worked in practice, the changes make the code technically correct and warning-free.

This is part of a coordinated effort with Johannes Schindelin to address platform-specific warnings, with this version representing a comprehensive fix that subsumes prior work. The changes are straightforward with no behavior impact, just making implicit assumptions explicit.
