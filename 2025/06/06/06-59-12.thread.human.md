This thread focuses on adding OAuth2.0 authentication support to `imap-send`, part of a larger 10-patch series (v13) improving IMAP functionality. The core challenge is properly handling different authentication methods in the curl configuration, particularly when to use CURLOPT_PASSWORD versus CURLOPT_XOAUTH2_BEARER.

Aditya Garg, the series author, has been working through compiler warnings that appear differently depending on whether OpenSSL is present. The discussion has centered on how to handle unsupported authentication methods like CRAM_MD5, with Junio Hamano suggesting three possible approaches: strict failure via BUG()/die(), falling back to plain password with a warning, or restructuring the code to clearly show supported methods.

In the latest email, Aditya clarified that the Waddress compiler warning occurs when building without NO_OPENSSL, correcting a misunderstanding from earlier in the thread. The discussion continues to weigh the tradeoffs between strict failure versus graceful fallback behavior, with particular attention to how these choices interact with different build configurations. The implementation details in imap-send.c remain the focus as the thread works toward consensus on the most robust way to dispatch between authentication methods.
