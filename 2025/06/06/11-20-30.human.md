Bug report about `git push` attempting to delete a branch twice, resulting in a confusing error message. Ondra Medek reports that when deleting a branch with `git push origin :branch1`, Git first successfully deletes the branch but then fails with "remote ref does not exist" - essentially complaining about its own successful deletion. The issue appears specific to one local working tree, as cloning the repository fresh works correctly.

The reporter mentions this originally occurred with custom refs in their application before testing with regular branches, suggesting it may be related to ref handling rather than a branch-specific issue. They've tried `git gc --aggressive --prune` without success, and are asking whether this is a Git bug or if there's a way to fix the local working tree without resorting to a fresh clone.

The behavior looks like a legitimate bug in Git's ref deletion logic, where it's not properly tracking the state changed by its own operation. The working tree corruption appears persistent, making this potentially more serious than a simple race condition. The fact that it reproduces with standard branch operations (not just custom refs) increases its general relevance to Git users.
