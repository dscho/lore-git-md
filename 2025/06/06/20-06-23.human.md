Bugfix for `imap-send` configuration parsing that has been broken since Git 2.46.0. This is the first patch in a larger series adding OAuth2.0 support and other improvements to IMAP functionality.

The patch fixes a critical regression introduced in commit 6d1f198f34 where the `cfg->folder` field was incorrectly NULLed out when processing unrelated configuration variables like `imap.user` or `imap.pass`. This made `git-imap-send` completely unusable since Git 2.46.0, though the bug went unnoticed for some time as most users prefer `git-send-email`.

The fix is straightforward - it changes the `FREE_AND_NULL` calls to target the correct struct fields (`user`, `pass`, etc.) rather than incorrectly clearing the `folder` field. The patch is small (4 line changes) but important, addressing a clear regression that broke core functionality.

This appears to be a well-justified fix that should be uncontroversial, especially since it's part of a larger series that has undergone extensive review. The commit message clearly explains both the problem and its impact, though it doesn't mention test coverage (which may be covered elsewhere in the series).
