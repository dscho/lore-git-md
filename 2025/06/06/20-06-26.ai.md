This is a bugfix patch in the ongoing `imap-send` series, specifically addressing a memory leak in the CRAM-MD5 authentication path. The patch adds a missing `free(response)` call in the error path when socket writing fails during authentication. The change is minimal but important - it plugs a memory leak that would occur if the IMAP server response couldn't be fully written to the socket.

The fix is straightforward and follows the pattern already established in the function where `response` is freed on the success path. The patch adds symmetric cleanup for the error case, ensuring no memory is leaked regardless of whether the socket write succeeds. This appears to be a clear-cut case of completing error handling that was accidentally omitted in the original implementation.

This is part of a larger series (v14 04/10) that has been thoroughly reviewed and addresses various issues in `imap-send`, including authentication methods and configuration handling. The specific fix here is one of several memory management improvements in the series, though it stands alone as a simple, focused change. The patch maintains the existing behavior while just adding the missing cleanup.
