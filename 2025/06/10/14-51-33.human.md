Junio Hamano responds to the ongoing discussion about tag idempotency with a concrete implementation proposal. This is a behavioral change to `git tag` that would make lightweight tag creation idempotent when pointing to the same commit, while still requiring `--force` for annotated tags or when changing the commit.

The patch modifies `builtin/tag.c` to only error when either: (1) creating an annotated tag (which always requires `--force` if the tag exists), or (2) the new lightweight tag would point to a different commit than the existing one. The test changes verify this new behavior - lightweight tags can be recreated on the same commit, but still fail when changing the target or creating annotated tags.

This represents a middle ground between the current behavior (always failing) and Hilco Wijbenga's more comprehensive proposal (full attribute comparison). Junio's approach is simpler to implement while still addressing the core use case of safely retrying tag creation. The implementation notably doesn't include the enhanced error messaging Mirth Hickford suggested, focusing instead on the behavioral change itself.

While Junio states he's "not convinced (yet) this is a good idea," the patch serves as a concrete starting point for further discussion, showing what a minimal idempotency implementation would look like. The change is relatively small and focused, touching only the core validation logic and corresponding tests.
