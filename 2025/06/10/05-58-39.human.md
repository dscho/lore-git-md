This is a final follow-up bugfix in Lidong Yan's series addressing memory leaks in pack-bitmap.c's boundary traversal code. The patch removes a conditional `bitmap_free()` that was only cleaning up on failure paths, leaving the `roots_bitmap` allocated when `cascade_pseudo_merges_1()` succeeds. 

Junio Hamano notes the fix makes the cleanup unconditional but questions how this leak was introduced in the first place. Yan explains it was an oversight similar to another leak Patrick Steinhardt fixed in a related function, and that the test suite didn't catch it because t5333 doesn't exercise boundary traversal cases.

The change is straightforward - removing the conditional check to ensure `roots_bitmap` is always freed. This completes the series' work to ensure proper memory management in all execution paths of the bitmap boundary traversal code. With this final edge case addressed and the earlier main series already merged, the memory safety work in this area appears complete.
