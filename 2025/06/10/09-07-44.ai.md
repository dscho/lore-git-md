Feature enhancement to `git branch --force` allowing multiple branch moves in a single command. This patch extends the `--force` option of `git branch` to accept multiple source branches followed by a single destination, similar to `cp` command semantics. Previously, `--force` could only move one branch at a time (either to a named branch or to HEAD). The change modifies the documentation, core branch creation logic, and adds a test case.

Key technical details:
- Updates the command syntax in `builtin/branch.c` to handle multiple branch names before the target
- Modifies the branch creation loop to process each source branch with the same target
- Adds test coverage in `t/t3200-branch.sh` for the new multi-branch case
- Follows existing `cp`-like semantics rather than alternative interpretations
- Does not affect other branch operations like move/copy which would error on duplicate names anyway

The implementation appears straightforward and maintains consistency with existing behavior while adding useful functionality. The commit message clearly explains the design choice to follow `cp` semantics rather than other possible approaches.
