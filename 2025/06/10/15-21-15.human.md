Feature implementation in the `git repo-info` series. This is patch 3/5 in the RFC series introducing a new command to expose repository metadata, splitting functionality from `git rev-parse`.

The patch adds the first concrete field to the new command: `references.format`, which reports the repository's ref storage format (either "files" or "reftable"). This matches what `git rev-parse --show-ref-format` currently provides. The implementation includes:

1. Core field handling infrastructure with category/field enums and parsing
2. JSON and plaintext output formatters for the ref format field
3. Tests verifying both storage formats and default field output
4. Memory management for the field list

The code follows established Git patterns, using the json-writer API for JSON output and adding comprehensive tests. This represents the first actual metadata reporting in the series, building on the scaffolding from earlier patches. The implementation looks clean and well-tested, with clear room for adding more fields in future patches as indicated by the category/field enum structure.

The patch maintains the series' gradual approach, delivering one well-contained piece of functionality while keeping the door open for the broader metadata reporting vision. The choice to start with ref storage format makes sense as it's a simple, well-defined piece of data that already has an equivalent in rev-parse.
