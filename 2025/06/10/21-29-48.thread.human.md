This thread explores how to list commits between two revisions that are directly pointed to by branch refs while preserving commit order. D. Ben Knoble presents three different approaches, each having distinct advantages and limitations. The first method uses `join` with sorted rev-list and for-each-ref output but loses topological sequence. The second approach post-processes `git name-rev` output to validate branch names, which works but is somewhat inelegant. The third and most promising method combines `rev-list --simplify-by-decoration` with `name-rev`, though the documentation warns this might be unreliable in some cases.

The discussion focuses on whether there's a canonical Git way to achieve this filtered branch-pointed commit list while maintaining proper ordering. The author appears to be seeking either validation of their approaches or suggestions for better alternatives. Notably, the question intentionally ignores tag handling, concentrating solely on branch refs through the `refs/heads/*` pattern matching.
