Feature implementation for the new `git repo-info` command, adding shallow repository detection as the final piece in this RFC series. This patch completes the core metadata reporting functionality by implementing `layout.shallow` field support, mirroring `git rev-parse --is-shallow-repository`.

The implementation follows the established pattern from previous patches, adding:
- New `FIELD_LAYOUT_SHALLOW` enum value
- JSON and plaintext output handlers using `is_repository_shallow()`
- Comprehensive tests for both output formats
- Inclusion in default field output (now 3 fields total)

Test coverage includes:
- Direct shallow status verification
- JSON parsing validation
- Default field count checks
- Both true/false shallow states via clone --depth

The patch maintains consistency with the series' technical approach:
- Uses existing `shallow.h` API
- Follows the category/field organization
- Extends the test suite incrementally
- Preserves JSON schema structure

This completes the initial set of repository metadata fields proposed in the RFC, demonstrating the command's ability to cleanly separate metadata reporting from `rev-parse`. The implementation quality appears solid, with thorough testing and careful attention to the established patterns from earlier patches in the series.
