Feature implementation in the ongoing `git repo-info` GSoC project series. This is patch 3/5, adding the first concrete metadata field - reference storage format reporting - to the new command.

The patch implements the `references.format` field, which exposes the same information as `git rev-parse --show-ref-format` but through the new structured output system. Key technical aspects:

1. Introduces field categorization with `CATEGORY_REFERENCES` and field type enums
2. Adds parsing infrastructure for field specifications (currently only handles "references.format")
3. Implements both JSON and plaintext output formats using the repository's `ref_storage_format` value
4. Sets "references.format" as the default field when no fields are specified
5. Includes tests verifying correct output for both files and reftable backends
6. Adds memory management with `repo_info_release()`

The implementation follows the series' incremental approach, building on the scaffolding patches while maintaining the established patterns (json-writer.h, standard CLI parsing). Test coverage is thorough, validating both explicit field requests and default behavior. The patch keeps the scope narrow - just one well-defined metadata field - while demonstrating how additional fields would be added in future patches.

Open questions from the RFC remain about the field specification syntax and JSON schema design, but this patch makes concrete progress on the core functionality while leaving those higher-level design questions for later discussion. The choice to make "references.format" the default field suggests this may be considered particularly important repository metadata.
