This is a follow-up review comment on Patrick Steinhardt's Perl removal series, specifically addressing patch 12/20 which converts Perl-based test helpers to shell/awk/sed alternatives. SZEDER Gábor identifies two issues with the conversions:

1. In t4150-am.sh, the awk conversion triggers a gawk warning about the `\@` escape sequence being treated as a plain `@`. While this doesn't break the test, it's a stylistic concern that could be cleaned up.

2. In t5333-pseudo-merge-bitmaps.sh, the sed conversion for tag creation has a syntax error (unterminated `s` command) that should cause the test to fail, yet the test still passes - suggesting either the test isn't properly validating the output or the error isn't being caught by the test framework.

The review comes after the series has already been merged to 'next', so these are post-merge observations rather than blocking issues. The feedback focuses on specific technical details of the shell script conversions, particularly around edge cases in awk/sed syntax handling. The issues don't appear to affect the overall correctness of the Perl removal effort, but highlight areas where the test conversions could be made more robust.

- sed commands require proper termination (missing closing delimiter in this case)
