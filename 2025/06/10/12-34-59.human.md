Feature patch adding `--trailer` option to `git rebase` (part 2/2 of series). This implements the user-facing CLI integration for the in-process trailer handling added in the first patch.

The patch adds a `--trailer` option to `git rebase` that appends specified trailers to each rebased message, with behavior matching `git interpret-trailers`. Key behaviors:
- Only works with merge/interactive backends (rejected early for apply backend)
- Automatically enables `--force-rebase` when trailers are present
- Validates trailer syntax before starting rebase
- Includes comprehensive tests covering CLI/config interactions, conflict handling, and edge cases

This builds on Phillip Wood's RFC feedback by implementing early validation and maintaining consistent behavior with the standalone trailer tool. The implementation looks thorough, with careful attention to state management and error handling. The test suite is particularly robust, covering all major use cases and failure modes.

The patch appears production-ready - it's well-documented, properly integrated with existing rebase machinery, and maintains backward compatibility while adding the new functionality. The automatic force-rebase behavior may warrant discussion as it changes default behavior when trailers are used.
