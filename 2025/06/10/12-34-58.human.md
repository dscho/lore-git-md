Feature patch introducing in-process trailer handling for Git commands. This is the first of two patches in a series adding `--trailer` support to `git rebase`, but it stands alone as a general improvement to trailer handling across Git.

The patch eliminates the need to fork an external `git interpret-trailers` process when appending trailers (like Signed-off-by) to commit messages. Instead, it implements `amend_strbuf_with_trailers()` to handle everything in-memory, which is particularly beneficial for operations modifying many commits (like large rebases or filter-repo runs).

The new function carefully replicates all edge cases from the external helper:
- Respects trailer.ifexists configs
- Handles messages with RFC-2822 separators
- Preserves comment sections from `git commit --verbose`
- Maintains the same CLI-then-config trailer ordering

The implementation touches `trailer.c` and `trailer.h`, adding 147 lines while removing just 9. It's a well-structured change that clearly separates concerns between the new in-memory operation and the existing file-based wrapper. The commit message thoroughly documents the behavior and edge cases, suggesting careful consideration of the problem space.

This appears to be a solid technical foundation for the rebase trailer functionality coming in patch 2/2, while also providing general performance benefits to other trailer-using commands. The change is well-motivated and the implementation looks thorough.
