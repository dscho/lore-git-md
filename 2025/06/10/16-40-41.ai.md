This is a feature proposal for the new `git repo-info` command, now in its final RFC discussion phase. Junio C Hamano provides feedback on the output format design, focusing on robustness concerns with the plaintext format while endorsing JSON as the initial baseline.

Key technical points raised:
- The JSON output structure (with nested objects for categories like "references" and "layout") is deemed acceptable despite minor comma consistency issues
- The proposed line-based plaintext format raises concerns about handling pathnames containing newlines, which could break the one-line-per-field assumption
- When querying specific fields (`objects.format references.format`), the plaintext output becomes problematic for multiple values while the JSON version remains sound
- Suggests starting with JSON as the primary format due to its widespread support and ability to handle arbitrary byte sequences, deferring alternative formats (gitconfig syntax, NUL-terminated) until after establishing the schema

The feedback indicates the core JSON implementation is on solid ground while cautioning against potential pitfalls in the plaintext output design. Junio's comment about "loathing JSON" while acknowledging its practicality suggests the format choice may not be controversial despite personal preferences. The thread appears to converge on finalizing the JSON schema first before exploring alternate output formats.
