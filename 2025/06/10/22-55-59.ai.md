This is a follow-up discussion in the concluded thread about trailing whitespace in Git editor templates, specifically examining the behavior of `git commit -v` templates. Junio C Hamano confirms D. Ben Knoble's observation that `git commit -v` does introduce trailing whitespace on blank lines in the commit message template, contrary to earlier assumptions in the thread. 

Hamano notes there is a configuration option (`diff.suppressBlankEmpty=yes`) that can suppress this whitespace, but cautions it might affect other tools' patch parsing compatibility, though `git apply` has long supported this format. This exchange serves as documentation of the broader whitespace-in-templates issue while maintaining the thread's conclusion that the notes-specific fix (already merged) was the right approach. The discussion provides concrete evidence that `git commit -v` exhibits similar whitespace behavior to the original notes template issue, though no action is proposed here - it simply records this as a known behavior for future reference.
