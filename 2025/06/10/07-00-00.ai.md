This is a follow-up in the ongoing discussion about tag idempotency and error messaging. Mirth Hickford responds to Junio Hamano's skepticism about showing full commit hashes in tag existence errors by proposing a simpler middle ground - keeping the current message for same-commit cases while adding "but points at a different commit" only when the tag would overwrite an existing one with a different target.

The key technical point is that this maintains the current behavior's simplicity while still providing the critical distinction between harmless (same commit) and potentially dangerous (different commit) tag collisions. This addresses Junio's concern about hash readability by avoiding raw hash display while still giving users actionable information about overwrite risks.

The proposal represents a compromise between:
1. The original detailed hash display
2. Junio's preference for minimal messaging
3. Hilco's comprehensive idempotency approach

Implementation would require modifying `builtin/tag.c` to compare target commits when a tag exists, but wouldn't need the full tag attribute comparison of Hilco's proposal. The change focuses specifically on the error messaging rather than behavioral changes to tag creation.

This keeps the discussion alive by offering a lighter-weight alternative that might satisfy the original use case (warning about dangerous overwrites) without the complexity of full idempotency. It remains to be seen whether this middle path will gain traction with either Junio (who seems to favor the status quo) or Hilco (whose approach is more comprehensive but complex).
