Feature patch discussion follow-up regarding `--compact-summary` option for merge/pull.

D. Ben Knoble raises questions about the design approach of Junio Hamano's proposed `--compact-summary` feature for `git merge` and `git pull`. The core suggestion is whether a more general solution might be preferable - either a "diff options" configuration that could handle multiple output formats, or simply encouraging users to run `git diff --compact-summary HEAD^` after the merge operation.

The email does not propose specific code changes but rather questions the architectural direction, suggesting the current implementation might be too narrowly focused on one output format variant. The author notes the code itself appears reasonable but is probing the motivation behind baking this specific output format into the merge/pull commands rather than providing more flexible diff output control.

This follows Junio's initial patch which added the `--compact-summary` flag to show `(new)`/`(gone)` annotations in merge/pull output by leveraging existing diffstat infrastructure with a new `MERGE_SHOW_COMPACTSUMMARY` flag and `stat_with_summary` option. The discussion opens up potential design considerations around command output configurability without rejecting the current implementation.
