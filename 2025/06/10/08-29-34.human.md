Bugfix for gitk's external diff handling of renamed files, now at v5. This final version addresses a long-standing issue where gitk would fail to properly locate files for external diff viewing when they were renamed between commits. The solution has been refined through multiple rounds of review with gitk maintainer Johannes Sixt.

The patch replaces the previous regex-based approach with direct use of `git diff --find-renames` to detect file renames, making the code both more robust and more maintainable. It handles both forward and backward rename cases (when either the old or new filename is selected) and gracefully falls back to normal behavior when no rename is detected. The implementation now fully complies with Tcl style conventions as requested by the maintainer.

This version incorporates all feedback from previous iterations, including switching to git-native rename detection, adopting Tcl's `ne` operator, removing unnecessary parentheses, and using shorter variable names. The changes are focused entirely on gitk's Tcl script (44 lines added, 2 modified) with no impact on Git's core functionality. The patch appears ready for inclusion, representing a clear improvement to gitk's usability when working with renamed files.
