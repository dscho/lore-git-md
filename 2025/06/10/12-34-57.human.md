This is a feature patch series introducing a new `--trailer` option to `git rebase`, along with necessary plumbing changes to handle trailers in-process rather than using the external `interpret-trailers` helper.

The series comes from Li Chen, building on feedback from Phillip Wood during an earlier RFC discussion. The first patch moves all trailer handling into Git's core by implementing an in-memory trailer append operation, eliminating fork/exec overhead. The second patch then adds the new `--trailer` option to `git rebase`, which forces use of the merge backend (since the apply/am backends lack message filtering) and automatically enables `--force-rebase` to ensure trailers are added even to fast-forwarded commits. The implementation includes proper state tracking for interrupted rebases and comes with a comprehensive test suite (t3440) covering various scenarios.

The changes touch several areas including rebase internals, sequencer operations, and trailer handling, with corresponding documentation updates. The implementation appears thorough, with clear motivation explained in the cover letter and test coverage for edge cases. This looks like a well-prepared contribution that could be useful for workflows wanting to systematically add trailers (like Signed-off-by) during rebase operations. The prior RFC discussion suggests the design has already benefited from review feedback.
