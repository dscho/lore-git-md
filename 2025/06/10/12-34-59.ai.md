Feature patch implementing the `--trailer` option for `git rebase`, completing the series that moves trailer handling into the main rebase process. This second patch focuses on the user-facing CLI integration and validation logic.

The patch adds the `--trailer` option to `git rebase` which appends specified trailers to each rebased commit, with automatic force-rebase behavior when trailers are present. Key implementation details include:
- Rejects the apply backend early since it lacks message filtering capabilities
- Validates trailer syntax before starting rebase operations
- Preserves CLI-then-config trailer ordering semantics
- Includes comprehensive tests covering edge cases (empty trailers, duplicate handling, conflict scenarios)
- Modifies sequencer to process trailers during commit operations

The implementation builds on the foundation from patch 1/2, using the new `amend_strbuf_with_trailers()` function while adding the necessary rebase-specific integration. Test coverage is thorough, verifying behavior across different rebase modes (interactive, exec, root) and includes validation of the force-rebase auto-enable behavior.

This appears to be a well-considered implementation that addresses all feedback from the RFC phase, with careful attention to edge cases and backward compatibility. The test suite provides confidence in the behavior, particularly around conflict resolution and trailer ordering semantics.
