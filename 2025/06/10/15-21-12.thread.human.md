Lucas Seiki Oshiro (mentored by Karthik Nayak and Patrick Steinhardt) has proposed a new `git repo-info` command to report repository metadata, now in its third iteration. The v3 series implements all three planned metadata fields - reference storage type (`references.format`), bare repository status (`layout.bare`), and shallow clone status (`layout.shallow`) - with support for both JSON and null-terminated output formats. The implementation appears complete with thorough test coverage and documentation.

A new architectural discussion has emerged about how this command should relate to Justin Tobler's in-progress `git-survey` work, which will eventually replace `git-sizer` for repository analysis. Patrick Steinhardt cautions against merging the two tools too closely, noting they serve different purposes: `repo-info` focuses on lightweight metadata queries while `survey` will perform potentially expensive computations. The current thinking favors organizing both as subcommands under a shared `git repo` namespace (e.g., `git repo info`, `git repo survey`) to maintain logical grouping while preserving their distinct identities and performance characteristics.

Several design questions remain open, including JSON schema details, field architecture implementation, and how to handle path resolution. The thread shows the project carefully considering both technical implementation and user experience as these new repository interrogation tools take shape.
