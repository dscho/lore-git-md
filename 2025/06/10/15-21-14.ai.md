Feature implementation for the new `git repo-info` command (part 2/5 of series). This patch adds core output formatting capabilities to the previously scaffolded command, introducing two key flags:

1. `--format` to select between JSON and plaintext output formats (defaulting to JSON)
2. `--allow-empty` to suppress output when no fields are requested

The implementation establishes the basic printing infrastructure with empty JSON/plaintext formatters (to be populated by later patches), adds comprehensive tests verifying the format selection and empty-output behavior, and integrates with the test suite via a new t1518-repo-info.sh. The code follows Git's established patterns for command-line parsing and JSON output (using the existing json-writer.h utilities).

Key technical details for future reference:
- Output format is stored in a new `repo_info` struct that will carry state through the series
- JSON output uses the standard `json-writer` API with an initially empty object
- Test cases validate both format options and the `--allow-empty` behavior through Perl-based JSON parsing
- The patch maintains the series' focus on splitting metadata functionality out of `git rev-parse`

This is a straightforward implementation of the output machinery promised in the RFC cover letter, with no major surprises or deviations from the proposed design. The empty formatters indicate this is still early in the series' progression, with actual metadata reporting coming in subsequent patches.
