This is a feature proposal introducing a new `git repo-info` command as part of a GSoC project. The patch series (5 parts) aims to create a dedicated command for repository metadata that currently lives in `git rev-parse`, following Git's pattern of splitting overloaded commands (like `checkout` into `switch`/`restore`).

The command would output repository information (object format, paths, ref storage, etc.) in either JSON or plaintext formats, with field selection capabilities. The RFC specifically asks for feedback on:
1. Output formats (JSON vs alternatives like gitconfig syntax)
2. Field specification syntax (currently "category.field" like JSON paths)
3. JSON schema design
4. Potential additional metadata to include beyond current rev-parse capabilities

The implementation so far covers object format, bare/shallow status, with tests. Files touched include a new builtin, test script, and build system updates. The proposal is well-structured with clear motivation and examples, though the actual implementation is still partial (only 3 of the planned fields are implemented in this series).

Key technical details for future reference:
- New command: `git repo-info` with `--format` option
- JSON output uses nested objects for "objects", "references", "path", "layout"
- Field selection via dot notation (e.g. "objects.format")
- Initial fields implemented are objects.format, layout.bare, layout.shallow
- Test file at t/t1518-repo-info.sh
- Potential points for discussion: output format choices, field naming scheme, schema extensibility
