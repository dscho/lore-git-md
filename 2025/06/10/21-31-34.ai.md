This is a post-merge technical review of two Perl-to-shell conversion issues in Patrick Steinhardt's Perl removal series, which has been merged to 'next'. SZEDER Gábor identifies two problems in patch 12/20:

1. An awk warning about an unnecessary `\@` escape sequence in email header generation, where the backslash can be removed since `@` has no special meaning in awk strings (unlike in Perl). This is a harmless warning but suggests the conversion could be cleaner.

2. A more serious issue in the pseudo-merge bitmap test where a sed conversion is both syntactically incorrect (missing terminator) and semantically wrong - it changes the test's behavior from creating numbered tags to trying to create hex-based tags. The test still passes because the broken sed command produces no output, causing subsequent steps to work with empty data rather than failing as they should.

Junio notes the test's success is misleading - it's passing because the broken conversion accidentally creates an empty input file, and the test's final validation (checking for duplicate lines) trivially passes on empty input. This reveals the test wasn't properly validating the intermediate steps.

These issues highlight two categories of post-merge concerns: minor cosmetic warnings in awk usage, and more importantly, test conversions that can mask broken behavior if the test's validation isn't thorough enough. The findings suggest the test framework may need enhanced output validation for helper script conversions, particularly for cases where silent failures could go undetected.
