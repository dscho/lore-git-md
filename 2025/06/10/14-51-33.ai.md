Junio Hamano proposes a technical implementation for tag idempotency, taking a different approach from the ongoing discussion about error messages. This is a refactoring that changes tag creation behavior rather than just improving warnings.

The patch makes lightweight tag creation idempotent when pointing to the same commit, allowing repeated `git tag T O` without `--force` if T already points to O. However, it maintains the existing behavior for annotated tags (still requiring `--force`) and when tags would point to different objects. The implementation is minimal - just modifying the object comparison logic in `builtin/tag.c` and updating tests in `t/t7004-tag.sh`.

Key technical details:
- Lightweight tags now succeed if identical (same name pointing to same commit)
- Annotated tags still fail (preserving their stricter semantics)
- Different-target cases still fail with existing error message
- Tests verify both the new allowed case and maintained restrictions

This differs from Mirth Hickford's message-only proposal and Hilco Wijbenga's full attribute comparison approach. Junio's version offers partial idempotency with minimal code changes, though it introduces an asymmetry between lightweight and annotated tag behavior. The patch appears cleanly implemented but notably doesn't address the original thread's focus on improving error messaging for dangerous overwrites.
