This thread addresses a bug in `git pull --prune` where case-conflicting references (like `origin/TOM/b2` and `origin/tom/b2`) cause pruning to fail entirely on case-insensitive filesystems (default on macOS and Windows). The issue stems from how `refs_delete_refs()` currently batches deletions in a single transaction, aborting all operations if any single deletion fails due to filesystem case conflicts.

The original reporter, ryenus, proposed modifying the deletion logic to handle each reference individually, allowing successful deletions to proceed even if others fail. brian m. carlson provided practical testing guidance for case-insensitive environments, suggesting methods like JFS partitions on Linux loopback devices or APFS/HFS disk images on macOS. Jayatheerth K has now acknowledged this guidance, indicating the next step is for the original author to verify the proposed solution works as intended in these test environments. The core challenge remains the filesystem interaction where differently-cased refs map to the same underlying file, but the path forward for validation is now clearer.
