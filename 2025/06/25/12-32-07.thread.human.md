This thread addresses a bug in `git pull --prune` where case-conflicting references (like `origin/TOM/b2` and `origin/tom/b2`) cause pruning to fail entirely on case-insensitive filesystems, which are the default on macOS and Windows. The original report from ryenus identified the issue in `refs.c`, where batch reference deletions abort if any case conflicts exist. The proposed fix would modify `refs_delete_refs()` to handle deletions individually rather than in a batch, allowing successful deletions to proceed even if others fail.

A key challenge has been testing the fix, as many contributors lack access to case-insensitive filesystems. brian m. carlson has now provided practical guidance for setting up test environments on both Linux (using JFS partitions) and macOS (via APFS/HFS disk images), which should help validate the proposed changes. While the technical solution appears sound in theory, this testing capability is crucial before the patch can move forward. The thread remains open for someone to implement and verify the fix using these testing approaches.
