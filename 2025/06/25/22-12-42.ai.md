This is a status update in the ongoing "SHA-256 by default" feature series, which aims to make SHA-256 the default hash algorithm when Git is running in breaking changes mode (3.0+). The original 10-commit series from brian m. carlson (submitted 2025-06-19) prepares for this fundamental change by:

1. Modifying test scripts to properly handle hash algorithm selection
2. Updating repository initialization to use the default algorithm
3. Adding constants for hash algorithm identification
4. Ensuring legacy formats retain original hash behavior

Junio Hamano had flagged the series as "Needs review" in his "What's cooking" report. brian m. carlson now responds that a v2 addressing Junio's comments is forthcoming, though delayed slightly due to concurrent work on SHA-256 interop in `index-pack`. The v2 is expected by the weekend unless additional feedback emerges in the interim.

Key technical points for future reference:
- Series touches core hash algorithm infrastructure (`hash.h`, `setup.c`)
- Modifies multiple test scripts (`t5300`, `t4042`, `t1007`) to handle hash selection
- Introduces constants `GIT_HASH_ORIGINAL` and `GIT_HASH_DEFAULT`
- Changes behavior when outside repository context to use default hash
- Maintains backward compatibility for legacy repository formats

This represents a major step in Git's SHA-256 transition, following years of preparatory work. The v2 will incorporate maintainer feedback, suggesting the initial submission had some issues needing resolution before potential inclusion. The concurrent `index-pack` work mentioned hints at broader SHA-256 integration efforts underway.
