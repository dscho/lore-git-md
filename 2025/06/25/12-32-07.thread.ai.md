Bug report and proposed fix for `git pull --prune` failure on case-insensitive filesystems when pruning case-conflicting references. Originated by ryenus, the issue occurs in refs.c (lines 2863-2895) where batch reference deletions fail entirely if any case-conflicting refs (e.g. `origin/TOM/b2` vs `origin/tom/b2`) are present on case-insensitive filesystems (macOS/Windows default). 

The proposed solution modifies `refs_delete_refs()` to handle each reference deletion in a separate transaction rather than batching, preventing single case conflicts from aborting all pruning. Key changes would: process deletions individually, count failures while allowing successes, and report overall status. brian m. carlson provided practical testing guidance for case-insensitive environments (JFS on Linux via loopback, APFS/HFS disk images on macOS via `hdiutil`), addressing the original author's inability to test the fix directly. The solution approach (individual transactions) remains technically sound but now has clearer validation path through the provided testing methods.
