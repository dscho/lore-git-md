Bug report for `git pull --prune` failing on case-insensitive filesystems when pruning references with case-conflicting names. Originated by ryenus, this documents a transaction rollback issue in refs.c (lines 2863-2895) where the code assumes reference deletions cannot fail when processed together. On case-insensitive systems (common for macOS/Windows), attempting to delete references with names differing only in case (e.g. `origin/TOM/b2` vs `origin/tom/b2`) causes the entire transaction to fail, preventing any pruning. The report clearly identifies the filesystem interaction as the root cause and provides specific reproduction scenario. No proposed fix yet, but the technical details are complete enough to begin investigation - this affects core reference handling on platforms where case-insensitivity is the default.
