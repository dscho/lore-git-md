Performance optimization for Git's pathspec bloom filters (part 2/2). This patch completes the series by enabling bloom filter acceleration for multiple pathspec queries (like `git log -- file1 file2`), building on the `bloom_keyvec` infrastructure introduced in patch 1/2.

The key changes remove the previous restriction that disabled bloom filters for multiple pathspecs, wrapping the bloom key initialization and checking in loops to handle each pathspec. A new `release_revisions_bloom_keyvecs()` function properly cleans up the vector storage. The test suite is updated to verify bloom filter usage with multiple pathspecs and wildcards.

This appears to be a well-executed implementation of the optimization proposed in the thread, with thorough test coverage. The changes are focused and maintain the existing fast path for single pathspecs while adding the new capability. The patch follows naturally from the preparatory work in part 1, completing the performance improvement for the case originally reported by Kai Koponen where combined pathspec queries were slower than separate invocations.
