This is the 4th patch in a finalized 5-patch series enhancing the promisor-remote protocol with configurable field validation. The patch implements client-side validation of advertised remote attributes (partialCloneFilter and token) against local configuration.

The core addition is a new `promisor.checkFields` config that specifies which fields to validate. The validation occurs in three scenarios: when the field exists in local config, when the server advertises it, and when values match exactly (case-sensitive for values, case-insensitive for field names). The patch includes comprehensive documentation explaining the validation rules and use cases for both filter consistency and authentication verification.

Implementation-wise, it introduces:
- `fields_checked()` to parse the checkFields config
- `all_fields_match()` as the core validation logic
- `match_field_against_config()` helper for individual field checks
- Integration with existing promisor-remote acceptance flow
- Test coverage verifying field transmission and validation behavior

The validation is gated by `promisor.acceptFromServer` not being "None", maintaining backward compatibility. The implementation builds on the series' earlier refactoring (struct promisor_info, field advertisement) while adding the client-side verification layer. Test cases demonstrate both successful validation and rejection scenarios.

This completes the security-oriented portion of the series by allowing clients to enforce policy on remote attributes they receive, particularly important for authentication tokens and filter specifications. The patch appears well-integrated with the series' architecture and maintains the established patterns for field handling.
