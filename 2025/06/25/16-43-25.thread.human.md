This thread introduces a 4-patch series to improve Git's clang-format integration and code style enforcement. The goal is to reduce formatting noise by making coordinated changes to style configuration and tooling while maintaining backward compatibility. Key changes include removing clang-format's ColumnLimit (letting developers handle line-wrapping), adding a 120-character line length limit in .editorconfig, making the RemoveBracesLLVM rule permanent, and adding meson build system support.

The final patch, just submitted, completes the series by adding a 'style' target to meson.build that mirrors the existing Makefile functionality. It runs `git clang-format` with the same parameters (showing diffs rather than modifying files, limited to .c/.h files) and only activates when clang-format is available. The changes touch .clang-format, .editorconfig, meson.build and ci/run-style-check.sh, with sample diffs showing reduced formatting noise in builtin/diff.c and pathspec.h.

The series follows prior discussion with Junio Hamano and could eventually lead to making style-check CI required, though that remains future work. So far there have been no reviews or objections - this is the initial submission of the complete series. The implementation appears careful and maintains consistency across build systems while reducing false positives in automated formatting.
