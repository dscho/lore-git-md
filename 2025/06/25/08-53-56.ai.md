Security vulnerability follow-up regarding refname validation. Kristoffer Haugsbakk responds to Ondrej Pohorelsky's report about shell command injection via branch names containing `>`, suggesting a hardening approach beyond just fixing the Bash completion issue. The email proposes extending `git-check-ref-format` to optionally disallow the `>` character in refnames entirely, which would prevent the underlying issue at the refname validation level rather than just fixing the completion layer. This would be an opt-in feature, suggesting backward compatibility concerns. The proposal doesn't include implementation details but indicates the direction of validating refnames more strictly to prevent shell injection vectors. The suggestion builds on the original vulnerability report but shifts focus from completion-specific escaping to broader refname validation policy. No patch is provided in this email - it's a conceptual suggestion for hardening Git's refname handling.
