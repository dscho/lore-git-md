This is a feature patch in the v5 series enhancing the promisor-remote protocol, specifically focusing on server-side advertisement of additional remote attributes. The patch introduces a new `promisor.sendFields` config variable that lets servers specify which remote-related fields (currently only `partialCloneFilter` and `token`) should be advertised to clients during clone/fetch operations.

Junio Hamano raises several thoughtful questions about the design and documentation. He suggests the commit message should better motivate why we want to advertise these fields (the "Y" behind the "X" of implementation). He also questions the wisdom of allowing both comma and space delimiters in the config, noting this complicates parsing. The documentation could more clearly explain how advertised fields map to server-side remote.* config variables.

The protocol design discussion reveals deeper considerations: how to group fields per remote when advertising multiple remotes (using semicolons), whether to enforce field ordering rules in the BNF grammar, and whether the protocol should support mandatory-to-understand fields (currently all fields are optional). Junio also wonders if the BUG() check for NULL URLs is truly necessary given string_list lookup guarantees.

This patch appears technically sound but the discussion highlights some philosophical protocol design questions worth resolving before finalizing. The series is otherwise ready for merging, having addressed all previous feedback and passed CI. This email represents one of the final rounds of review before potential integration.
