Performance investigation of `git log --follow` slowness with small files. Kai Koponen reports that `git log --follow` takes significantly longer (2.3s) than expected when tracing history of a small file (12-line test/index0.go in golang/go repo) compared to basic `git rev-list` (0.07s). The test case shows the slowdown persists even when using commit-graph with changed-path Bloom filters.

Key observations suggest the performance gap may come from: 1) unnecessary rename/copy detection being performed even for small, non-creation diffs, 2) potential lack of commit-graph optimization for `--follow`, 3) possible failure to respect `--max-count` or format options to limit work. The email provides a reproducible test case using golang/go repository at a specific commit, with file statistics showing the target diff is just 1 line modified.

This appears to be a genuine performance investigation with clear reproduction steps and thoughtful analysis of potential causes. The issue could affect any `--follow` usage on repositories with commit-graph enabled, making it relevant for users who rely on file history traversal. The analysis suggests several plausible optimization opportunities in Git's rename detection heuristics and commit-graph integration.
