This is a contributor housekeeping patch that adds a maximum line length setting to Git's `.editorconfig` file. It's part of a 4-patch series (position 1/4) though the cover letter context isn't provided here.

The patch sets a 120-character line length limit for various source files (C, shell, Perl, Makefiles etc.) in the editor configuration. This is presented as a soft guideline for editors to follow, not an enforced rule like `.clang-format` settings. The commit notes this provides flexibility beyond the documented 80-character recommendation while still preventing excessively long lines.

Key technical details for future reference:
- Affects `.editorconfig` with a new `max_line_length = 120` setting
- Applies to C, shell, Perl, text, docs and Makefiles
- Explicitly notes this is editor-specific and not CI-enforced
- References EditorConfig's property documentation
- Follows Git's existing pattern of using tabs (8-width) for indentation
