This is a contributor housekeeping patch that proposes a new editor configuration setting. Karthik Nayak suggests adding a maximum line length of 120 characters to Git's `.editorconfig` file for various source code file types.

The change acknowledges that while Git's coding guidelines recommend 80-character lines, there are cases where longer lines improve readability. The 120-character limit would serve as a soft guideline for editors (not enforced by CI), giving developers more flexibility while still maintaining reasonable line lengths. The patch notes this setting is only supported by certain editors, with a link to the relevant documentation.

The change is straightforward and well-explained, though it's worth noting this won't affect actual code formatting (which is handled by `.clang-format`) - it's purely an editor hint. This appears to be the first of a 4-part series, though the cover letter wasn't provided in this input.
