Bugfix in the ongoing Git daemon signal handling series. Phillip Wood points out a remaining race condition in the v2 patch series that aims to fix zombie process cleanup on OpenBSD and crashes on AIX. The current approach uses SA_RESTART flag toggling around poll() calls, but Phillip notes this still leaves a window where a child exiting between check_dead_children() and poll() would not be collected until the next event. He suggests an alternative approach using the self-pipe trick described in select(2) man pages, which would avoid the need for SA_RESTART manipulation entirely.

This is a substantive technical critique of the current implementation approach, though it comes late in the review cycle after significant discussion and multiple iterations. The self-pipe technique is a more robust Unix pattern for signal handling in event loops, but would require restructuring the daemon's I/O handling. The comment doesn't propose specific code changes, but raises an important architectural consideration that may warrant revisiting the design before finalizing the series.

The discussion has now moved from platform-specific signal handling details to broader design choices for reliable child process management in the daemon.
