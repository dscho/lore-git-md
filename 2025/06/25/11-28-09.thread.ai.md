Performance regression in `git for-each-ref --merged` with large tag sets. Andrzej Debski reports significant slowdown when processing ~65K tags, comparing Git 2.39.5 (fast) to 2.40.0+ (slow). Root cause traced to `tips_reachable_from_bases` function introduced in cbfe360b140, where execution time scales with tag count. Regression impacts Dropbox's monorepo workflows using Go tooling. Issue persists through Git 2.50. Key technical details: regression manifests specifically with `--merged` filtering on large tag sets, performance impact directly correlated with tag count, original faster behavior existed prior to reachability checking changes in cbfe360b140.
