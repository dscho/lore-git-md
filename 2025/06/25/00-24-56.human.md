This is a process clarification email in the thread about git-credential-netrc's port handling and patch submission format.

Junio Hamano responds to Maxim Cournoyer's question about whether submitting a properly-threaded patch series requires two separate `git send-email` invocations. Junio indicates this isn't necessary, pointing to the `--in-reply-to`, `--thread`, and `--no-chain-reply-to` options in `git send-email` that can handle the threading automatically. He provides a clear example from the documentation showing how these options create the desired thread structure where the cover letter replies to the previous iteration's cover letter, and all patches reply to their own cover letter.

The email serves as a workflow clarification rather than introducing any technical changes to the already-merged port handling functionality.
