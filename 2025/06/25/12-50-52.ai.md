This is the second patch in a finalized 5-part series extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The patch focuses on server-side functionality.

The patch introduces a new `promisor.sendFields` configuration variable that allows servers to advertise additional remote-related fields beyond just name and URL. Currently supported fields are `partialCloneFilter` (specifying the remote's partial clone configuration) and `token` (for authentication credentials). The field values are pulled from the server's remote configuration.

Key implementation details:
- Field names are case-insensitive in comparisons
- Values are URL-encoded when transmitted
- Empty field values are silently filtered out
- The protocol documentation is updated with BNF notation and detailed field specifications
- Comprehensive tests verify field transmission, including handling of URL encoding and config parsing edge cases

The patch maintains backward compatibility while preparing for future extensions. It builds on the refactoring from patch 1 (which introduced `struct promisor_info`) and sets up for patch 4's client-side validation. Documentation follows project standards with clear explanations of the protocol changes.

This appears to be a well-considered implementation with thorough test coverage. The changes are focused and maintainable, with clear boundaries between server and client responsibilities. The series has gone through multiple review iterations (now at v5) with all feedback addressed.
