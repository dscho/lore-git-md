This is a technical clarification in the ongoing Git daemon signal handling discussion. Carlo Marcelo Arenas Belon responds to Junio C Hamano's question about the purpose of an empty `#ifdef SA_RESTART` block in the build system check. He explains that the construct serves to verify `SA_RESTART` is defined in `signal.h`, which would fail on platforms like QNX, NonStop and Windows that lack this POSIX signal flag.

The exchange occurs within the broader context of choosing between two approaches for handling interrupted system calls in the Git daemon: the current SA_RESTART toggling method (which this build check supports) versus the proposed self-pipe alternative. While this particular email doesn't advance the architectural decision, it provides important clarification about platform compatibility testing in the existing implementation. The response confirms the intentionality behind the seemingly empty preprocessor check, which helps maintainers understand the code's portability considerations.
