This is the cover letter for a finalized 5-patch series enhancing the promisor-remote protocol with configurable validation of remote attributes during clone/fetch operations. The series is now in its fifth iteration and ready for merging, having addressed all reviewer feedback.

The core change allows servers to advertise additional fields (currently limited to `partialCloneFilter` and `token`) via a new `promisor.sendFields` config, while clients can validate these against local expectations using `promisor.checkFields`. The implementation maintains backward compatibility while adding security-conscious field handling.

Key technical improvements in this version include:
- Better commit message explanations about why `struct strvec` was replaced
- More precise BUG() message wording
- Additional code comments explaining field parsing logic
- Documentation of the new empty field filtering behavior

The series has undergone thorough review from multiple maintainers (Patrick Steinhardt, Junio Hamano, Karthik Nayak, Justin Tobler) with all feedback incorporated. Christian Couder notes the changes since v4 are minimal and the CI tests are passing. This represents the culmination of work that began with internal refactoring in patch 1/5 and progressed through server advertisement, client validation, and finally code cleanup with string constants.

The patchset is part of Git's broader "Large Object Promisors" (LOP) effort and builds on existing partial clone infrastructure while improving type safety and maintainability. With no outstanding issues remaining, this is likely the final version before merging.
