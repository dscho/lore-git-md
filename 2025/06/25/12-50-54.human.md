This is the 4th patch in a finalized 5-part series enhancing the promisor-remote protocol with configurable field validation. The patch implements client-side checking of additional remote attributes (partialCloneFilter and token) that were previously made available through server advertisement in earlier patches.

The core addition is a new `promisor.checkFields` configuration that lets clients verify advertised field values against their local configuration before accepting a promisor remote. The validation is strict - all specified fields must be present in both configurations with matching values (case-sensitive for values, case-insensitive for field names). The patch includes thorough documentation of the validation rules and comprehensive test coverage showing both successful and rejected cases.

This completes the security-oriented portion of the series, ensuring clients can enforce consistency in critical remote attributes like filtering behavior and authentication tokens. The implementation builds cleanly on the refactored infrastructure from earlier patches and maintains backward compatibility. With CI passing and all reviewer feedback addressed, this appears ready for merging as part of the finalized v5 series.
