Performance regression investigation in `git for-each-ref --merged`. Kristoffer Haugsbakk forwards Andrzej Debski's report of a significant slowdown when processing large tag sets (65K+ tags) in Git versions 2.40.0 and later compared to 2.39.5. The regression stems from the `tips_reachable_from_bases` function introduced in cbfe360b140, where execution time scales linearly with tag count. This impacts Dropbox's monorepo workflows that use Go tooling to query tags. The email provides detailed reproduction steps showing the command `git for-each-ref --format="%(refname)" refs/tags --merged HEAD` becomes progressively slower as tag count increases. System info confirms the issue persists in Git 2.46.0. Key technical details include the regression's appearance specifically with `--merged` filtering, its correlation with tag count growth, and the known faster behavior prior to the reachability checking changes in cbfe360b140. The thread now awaits input from the original author of the problematic commit.
