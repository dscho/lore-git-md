This is a performance optimization patch series targeting Git's bloom filter implementation. The cover letter explains that Git currently doesn't use bloom filters when given multiple pathspecs (like `git log -- file1 file2`), making such queries significantly slower than running separate single-pathspec queries.

The issue was originally reported by Kai Koponen, showing that combining pathspecs could be much slower than running them separately. The proposed solution involves restructuring the bloom filter code to handle multiple pathspecs efficiently. The first patch introduces a new `bloom_keyvec` struct to manage multiple bloom keys, while the second patch implements the actual optimization by checking if any pathspec's bloom filter matches a commit.

The author provides a concrete performance example showing the improvement - a combined pathspec query becomes as fast as running the individual queries separately. The changes touch core bloom filter code in bloom.[ch] and revision.[ch], plus test updates. This appears to be a well-motivated optimization with clear performance benefits for a real-world use case.
