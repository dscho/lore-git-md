Junio C Hamano responds to Phillip Wood's suggestion about using the self-pipe trick for signal handling in the Git daemon. This is part of the ongoing discussion about platform-specific signal handling issues that affect zombie process cleanup and race conditions.

Junio acknowledges that Phillip's proposed self-pipe approach (writing to a pipe from signal handlers rather than toggling SA_RESTART flags) could potentially solve both the OpenBSD zombie process issue and the race condition between check_dead_children() and poll(). He notes the technique should work equally well for poll()-based service loops as it does for select().

This email represents a potential turning point in the architectural discussion, as Junio (the Git maintainer) appears open to considering the self-pipe alternative that would avoid the platform-specific SA_RESTART handling that has been the focus of the patch series so far. The self-pipe approach would require restructuring the daemon's event loop to monitor an additional pipe file descriptor but could provide more robust signal handling across all platforms.

Key technical points:
- The race condition occurs when a child exits between check_dead_children() and poll()
- Self-pipe would eliminate need for USE_NON_POSIX_SIGNAL flag
- Would require modifying signal handlers to write to pipe
- Poll() would need to monitor pipe alongside other fds
- Junio indicates the approach is technically sound for poll() loops

This moves the discussion toward evaluating two competing solutions:
1. The current SA_RESTART toggling approach (already well-developed in the series)
2. Phillip's self-pipe proposal (potentially simpler but requiring different changes)

The thread now faces a key architectural decision point between these approaches, with Junio's response suggesting the self-pipe idea merits serious consideration.
