This is the first patch in a 5-part series refactoring the promisor-remote protocol to support configurable validation of remote attributes. The series is now in its final v5 version and ready for merging.

The patch replaces the existing `struct strvec`-based storage of promisor remote information with a new `struct promisor_info` that explicitly stores name and URL fields. This is a preparatory refactoring that makes it easier to add support for additional fields in subsequent patches while maintaining type safety. The change introduces proper cleanup helpers and moves to a `string_list` for managing the promisor info instances.

The implementation looks thorough, with careful attention to memory management and backward compatibility. The commit message clearly explains the motivation and design choices. This foundational change enables the more substantive protocol extensions that follow in the series, which will add server advertisement and client validation of additional remote attributes.
