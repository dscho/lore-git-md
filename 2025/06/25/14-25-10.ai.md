This is a bugfix patch in the git-credential-netrc series, adding validation for invalid port numbers in netrc files. The patch changes the behavior when encountering non-numeric port specifications - instead of silently dropping them, it now emits a warning message to STDERR while still ignoring the invalid value.

The technical change modifies the Perl script's port handling logic to first check if the port is defined, then validate it contains only digits before processing. Invalid ports trigger a warning message with the problematic value while maintaining the existing behavior of not using the invalid port. The warning helps users identify configuration issues that were previously invisible.

This builds on the v3 series' port handling infrastructure which already included numeric validation and symbolic port resolution via getservbyname. The change is focused on improving user feedback rather than altering core functionality. The patch maintains all existing test coverage from previous versions while adding this new warning behavior.

The implementation follows the established pattern from the rest of the series, using Perl's printf for the warning message and keeping the same code structure for port processing. This appears to be a straightforward quality-of-life improvement that makes invalid configurations more visible to users.
