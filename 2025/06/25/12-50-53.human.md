This is the third patch in a 5-part series enhancing the promisor-remote protocol with configurable validation of remote attributes. The series is now in its final v5 version with all CI passing and ready for merging.

The patch refactors how advertised fields from promisor remotes are parsed, centralizing the logic into a new `parse_one_advertised_remote()` function that populates a `struct promisor_info`. This prepares for upcoming additions that will parse more fields (like filters and tokens) from server advertisements. The changes make the code more maintainable by:

1. Moving field parsing into a dedicated function that returns a populated promisor_info struct
2. Passing the complete struct to `should_accept_remote()` rather than individual fields
3. Adding proper memory management via `promisor_info_free()`

The refactoring maintains all existing behavior while making the codebase more robust for future extensions. As part of the final v5 series, this patch has already addressed all reviewer feedback and integrates cleanly with the surrounding changes to support dynamic field validation in the promisor-remote protocol.
