Git daemon signal handling architectural proposal. Phillip Wood follows up on his earlier suggestion to use the "self-pipe trick" as an alternative to the current SA_RESTART-based approach for handling signals in the Git daemon. He confirms that this technique would apply equally to poll()-based service loops, addressing both the original OpenBSD zombie process problem and a race condition between child process checking and poll() calls.

The self-pipe approach would involve creating a dedicated file descriptor pair, modifying signal handlers to write to the pipe, and monitoring the pipe alongside other file descriptors in the poll() call. This would eliminate the need for platform-specific SA_RESTART handling and the recently introduced USE_NON_POSIX_SIGNAL build flag.

Junio C Hamano had previously validated this approach as technically sound, noting it could solve both the OpenBSD issue and the race condition more robustly. The discussion now appears to be shifting toward evaluating this alternative against the nearly-complete SA_RESTART-based solution, with the self-pipe method offering potential advantages in platform independence and race condition handling at the cost of requiring an additional file descriptor.
