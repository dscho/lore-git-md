Refactoring patch (1/5) in the finalized promisor-remote protocol enhancement effort. This initial patch restructures the internal data handling for promisor remotes, replacing the previous `struct strvec` approach with a new `struct promisor_info` that explicitly stores name and URL fields. The change enables cleaner extension for future protocol fields while maintaining identical external behavior.

Key technical changes:
- Introduces `struct promisor_info` with dedicated `name` and `url` members
- Uses `string_list` to manage promisor_info instances, with `item->string` pointing to the name and `item->util` to the struct
- Adds `promisor_info_list_clear()` helper for cleanup
- Replaces `remote_nick_find()` with direct `string_list_lookup()`
- Updates all related functions to use the new structure
- Maintains same URL encoding/decoding behavior and config handling

The refactoring prepares for subsequent patches that will add field validation capabilities, with this change establishing the foundation for cleanly handling additional fields like `partialCloneFilter` and `token`. The commit message clearly explains the motivation for moving away from the strvec approach and toward explicit struct members for type safety and documentation purposes.
