This thread discusses a series of patches to modify Git's clang-format configuration, with the main goal of making the formatter more usable by removing strict line length enforcement. The second patch in the series (2/4) proposes disabling the 80-character column limit entirely by setting `ColumnLimit: 0` in `.clang-format`. The commit message explains that while 80 characters remains the recommended line length in Git's CodingGuidelines, the automated enforcement has caused problems - sometimes unnecessarily concatenating short lines and producing many false positives. Two previous attempts to adjust line break penalties (in 2017 and 2024) didn't fully resolve these issues.

The change is presented as a pragmatic solution, removing all line-wrapping-related penalty settings while keeping other formatting rules intact. A NEEDSWORK comment suggests the long-term goal is to find better settings that might allow re-enabling the limit. This follows an earlier patch in the series that set a more lenient 120-character guideline in `.editorconfig`. The discussion so far appears focused on technical tradeoffs of automated formatting, with the current patch representing a significant but well-justified relaxation of the previous strict line length enforcement.
