Here's a human-readable summary of the thread so far:

The thread documents a performance regression in `git for-each-ref --merged` when processing large sets of tags (65,000+). Andrzej Debski first reported that this operation became significantly slower starting with Git 2.40.0 compared to 2.39.5, particularly affecting Dropbox's monorepo workflows that use Go tooling to query tags. The slowdown stems from changes in commit cbfe360b140 which introduced the `tips_reachable_from_bases` function - its execution time scales linearly with the number of tags.

Kristoffer Haugsbakk has since confirmed the issue persists in Git 2.46.0, providing detailed reproduction steps showing how `git for-each-ref --format="%(refname)" refs/tags --merged HEAD` becomes progressively slower as tag count increases. The regression specifically manifests when using the `--merged` filtering option, while the pre-2.40.0 behavior was notably faster. The thread is now waiting for input from the author of the original commit that introduced this behavior to determine next steps for addressing the performance impact.
