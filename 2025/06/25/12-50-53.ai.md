Refactoring patch in the promisor-remote protocol enhancement series. This is the third of five patches in the v5 series that adds configurable validation of remote attributes during clone/fetch operations.

The patch centralizes the parsing of advertised promisor-remote fields into a new `parse_one_advertised_remote()` function that populates a `struct promisor_info`. This replaces the previous ad-hoc parsing that handled name and URL fields separately. The refactoring also modifies `should_accept_remote()` to take the full promisor_info struct rather than individual name/url parameters.

Key technical changes include:
- New `promisor_info_free()` helper for consistent cleanup
- Consolidated field parsing that handles URL decoding internally
- More robust error handling for malformed remote advertisements
- Preserved memory management responsibilities (caller must free the returned promisor_info)
- Maintained existing behavior while making the code more extensible

The changes prepare for subsequent patches that will add support for parsing additional fields (filter and token) from server advertisements. The refactoring follows the series' pattern of improving type safety and maintainability while keeping backward compatibility. Test coverage for the modified parsing logic appears in later patches of the series.
