This is a follow-up discussion on a patch from the clang-format integration series, specifically about setting line length limits in .editorconfig. Junio Hamano questions whether setting the max_line_length to 120 characters (rather than the documented 80-character guideline) is the right approach, since it might result in awkward wrapping where a single 125-character line becomes a 100-character line plus a short remainder. He suggests 80 might be more appropriate as a soft suggestion to editors, though acknowledges uncertainty.

The original patch from Karthik Nayak had argued that since .editorconfig provides editor guidance rather than enforcement (unlike .clang-format), the 120-character limit gives developers more flexibility while still preventing extremely long lines. The patch references editorconfig's max_line_length property support and includes a link to related discussion about visual rulers in editors.

Key technical details mentioned:
- The change adds `max_line_length = 120` to .editorconfig for C, shell, Perl, and Makefile-related files
- Junio raises concerns about potential suboptimal wrapping behavior
- The thread includes reference to GitHub issue #89 about editor "rulers" (visual line length indicators)

This appears to be a style preference discussion rather than a technical objection, with Junio playing devil's advocate about whether the chosen value optimally serves the project's documented 80-character guideline. The exchange is constructive but doesn't yet reach a resolution.
