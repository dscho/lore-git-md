This is a CI/build system patch series aimed at improving Git's clang-format integration. Karthik Nayak proposes four changes to reduce false positives in automated code formatting:

1. Removing clang-format's ColumnLimit rule to stop automatic line wrapping, putting that responsibility on developers instead
2. Adding a 120-character line length limit in .editorconfig for editor-based wrapping
3. Making the RemoveBracesLLVM formatting rule permanent
4. Adding a meson build target for running clang-format

The patch includes example diffs showing how these changes affect formatting, particularly around line wrapping and brace placement. The changes appear well-motivated by prior discussion about clang-format's effectiveness in the project. The implementation looks clean and focused, with each commit addressing a specific aspect of the formatting configuration.

While the series doesn't propose making the style check required in CI yet, it lays the groundwork for that possibility by making the formatting rules more predictable and less prone to false positives. The changes should make automated formatting more useful while giving developers clearer control over line wrapping decisions.
