Performance optimization completing the bloom filter pathspec series. This second patch removes the restriction that prevented bloom filters from being used with multiple pathspecs (like `git log -- file1 file2`), implementing the actual performance improvement promised by the series.

The key changes are:
1. Removing the `spec->nr > 1` check in `forbid_bloom_filters()`
2. Modifying `prepare_to_use_bloom_filter()` to initialize a `bloom_keyvec` for each pathspec rather than just the first one
3. Updating `check_maybe_different_in_bloom_filter()` to check all pathspecs' bloom keys (returning true if any match)
4. Adding a new cleanup function release_revisions_bloom_keyvecs()`
5. Updating t4216 tests to verify bloom filter usage with multiple pathspecs

The implementation follows logically from the infrastructure changes in patch 1, converting the single-pathspec special case into a loop over all pathspecs while maintaining the same underlying bloom filter checking logic. Test changes confirm the new behavior works as intended.
