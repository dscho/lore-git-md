**Thread Summary: Investigating `git log --follow` Performance Issues**

Kai Koponen has identified a significant performance discrepancy when using `git log --follow` to trace the history of a small file in the golang/go repository. While a basic `git rev-list` completes in 0.07 seconds, the `--follow` variant takes 2.3 seconds - over 30x slower - despite the file being just 12 lines with a single-line modification.

The investigation suggests several potential causes for this unexpected slowdown. First, Git may be performing unnecessary rename/copy detection even for trivial diffs where such analysis isn't needed. Second, the commit-graph's changed-path Bloom filters - which normally accelerate history queries - might not be properly leveraged for `--follow` operations. Third, there could be inefficiencies in how `--follow` respects options like `--max-count` that should limit the work performed.

The report includes a reproducible test case using a specific commit from the golang/go repository, making this a concrete performance issue that could affect any user relying on `--follow` for file history traversal. The analysis points to clear optimization opportunities in Git's rename detection heuristics and commit-graph integration that could substantially improve this common workflow.
