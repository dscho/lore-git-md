This is the final patch in a 5-patch series enhancing the promisor-remote protocol with configurable validation of remote attributes. The series is now complete and ready for merging.

The patch introduces string constants for the mandatory "name" and "url" fields in the promisor-remote protocol, following the same pattern established in previous patches for "partialCloneFilter" and "token". This change eliminates string literals scattered through the code, centralizing the field names in one place for better maintainability and consistency.

The implementation is straightforward - it adds the new constants at the top of the file and updates all references to use them instead of hardcoded strings. The changes touch both the server-side advertisement generation and client-side parsing code paths, ensuring all existing functionality remains identical while improving the code structure.

As with the rest of the series, this patch has been through multiple review iterations and has final approval from the maintainers. It represents the last piece of a well-considered enhancement to the promisor-remote protocol that adds important validation capabilities while maintaining backward compatibility.
