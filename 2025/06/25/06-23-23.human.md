This is a bugfix for gitk's external diff functionality, now at version 6 of the patch series. The maintainer Johannes Sixt provides detailed review of Tobias Boesch's solution for handling renamed files in gitk's external diff view.

The core issue remains unchanged: gitk needs to properly locate renamed files when launching an external diff tool. While v6 switched from regex parsing to using `git diff --find-renames`, the maintainer suggests this might be overkill - he believes the rename information could be extracted more efficiently from gitk's existing patch text panel data rather than spawning a new Git process.

The review identifies several technical concerns with the current implementation: unnecessary use of porcelain commands (`git diff` instead of plumbing commands), questionable regex handling of filenames with spaces, variable naming inconsistencies, and potential parsing vulnerabilities. Johannes provides specific suggestions for improvement, particularly around using null-terminated output (-z) for unambiguous parsing.

This represents a significant maintainer review rather than a final approval. While the thread has seen productive collaboration through six versions, Johannes clearly expects further refinement before merging. The patch remains focused on gitk's Tcl code with no architectural impact, but needs to address the maintainer's style and implementation concerns around command choice, parsing robustness, and code consistency.
