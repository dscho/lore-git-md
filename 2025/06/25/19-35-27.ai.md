This is a technical discussion about signal handling approaches in the Git daemon, specifically comparing the current SA_RESTART-based solution with Phillip Wood's proposed self-pipe alternative.

Phillip Wood confirms that the self-pipe technique (previously suggested in the thread) works equally well with poll()-based service loops as it does with select(). The approach involves creating a pipe, monitoring its read end via poll(), and writing to the pipe in signal handlers to wake the event loop. This would avoid both the OpenBSD zombie process problem and the newly identified race condition between check_dead_children() and poll() calls.

The email serves as a direct response to Junio C Hamano's validation that the self-pipe principle applies to poll()-based loops. Phillip clarifies the implementation details, noting the pipe would be added to the monitored file descriptors and written to on signal receipt. This reinforces the technical viability of the alternative approach that could potentially replace the current SA_RESTART toggling infrastructure.

Key technical points for future reference:
- Self-pipe would require adding pipe read end to poll()'s monitored fds
- Signal handlers would write to pipe write end to wake event loop
- Would eliminate need for USE_NON_POSIX_SIGNAL flag and SA_RESTART manipulation
- Solves both original OpenBSD zombie issue and newly discovered race condition
- Junio has already acknowledged this approach as technically sound for poll() loops
