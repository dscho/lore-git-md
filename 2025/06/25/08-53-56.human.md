Security vulnerability follow-up regarding branch name validation. Kristoffer Haugsbakk responds to Ondrej Pohorelsky's report about Bash completion interpreting `>` in branch names as shell redirection. While the immediate issue is the completion vulnerability, Haugsbakk points to a deeper problem: Git's ref format validation currently allows `>` characters in branch names at all. 

The email suggests adding an opt-in extension to `git-check-ref-format` that would prohibit `>` characters, which would prevent such branch names from being created in the first place. This would complement any fixes to the Bash completion code by addressing the root cause rather than just the symptom. 

The proposal is framed as a potential hardening measure rather than a direct fix for the immediate vulnerability. It represents a shift from treating this as purely a completion issue to considering broader refname safety. The tone suggests this might be worth discussing as part of the security response, though no specific implementation is proposed yet.
