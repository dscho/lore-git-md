Signal handling refinement discussion in Git daemon series. Junio C Hamano responds to Phillip Wood's suggestion about using the "self-pipe trick" to handle signals in the Git daemon's event loop, rather than the current approach of toggling SA_RESTART flags around poll() calls.

Phillip had pointed out that the current implementation still has a race condition where child processes might not be cleaned up promptly if they exit at just the wrong time between checks. His proposed alternative - writing to a pipe from the signal handler and monitoring that pipe alongside other file descriptors - would both eliminate this race and avoid the platform-specific SA_RESTART handling that has been the focus of much discussion in this thread.

Junio concisely agrees that the technique (well-documented in the select(2) man page) should work equally well with poll() as with select(). This brief exchange represents a potential architectural pivot point for the series, as the self-pipe approach could simplify the implementation by removing the need for the USE_NON_POSIX_SIGNAL infrastructure while also solving the remaining race condition more robustly. The discussion continues to balance technical correctness with implementation cleanliness.
