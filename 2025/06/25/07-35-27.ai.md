This is a bugfix patch in the ongoing Git daemon signal handling series, specifically addressing platform-specific signal handler behavior. The patch modernizes signal handling by replacing `signal()` with `sigaction()` where possible, while maintaining compatibility with systems that require the older approach.

The key technical changes include:
- Introducing a new `set_signal_handler()` function that uses `sigaction()` with `SA_RESTART` flag for POSIX-compliant systems
- Maintaining the empty `child_handler()` but removing the unconditional rearming call that could cause crashes on AIX
- Using conditional compilation with `USE_NON_POSIX_SIGNAL` to preserve legacy `signal()` behavior where needed
- Adding proper signal mask initialization via `sigemptyset()`

The patch builds on previous discussion that established the necessity of using `sigaction()` for reliable behavior across platforms, particularly addressing issues on OpenBSD (zombie processes) and AIX (crashing). The implementation now properly handles the tension between POSIX compliance and platform quirks, with the empty handler remaining as confirmed by historical Unix signal behavior.

This represents concrete progress in the series by:
1. Implementing the agreed-upon `sigaction()` approach
2. Resolving the AIX crash risk from handler rearming
3. Maintaining backward compatibility through the build flag
4. Cleaning up the signal setup code while preserving cross-platform behavior
