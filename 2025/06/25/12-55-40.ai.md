Performance optimization patch introducing a new data structure for pathspec bloom filters. This is part 1 of a 2-part series addressing the performance limitation where Git's bloom filters only accelerate single pathspec queries.

The patch introduces `struct bloom_keyvec` to manage multiple bloom keys, replacing the direct use of `struct bloom_key *` in `rev_info`. Each `bloom_keyvec` corresponds to a single pathspec, with the array `bloom_keyvecs` in `rev_info` handling multiple pathspec cases. New helper functions (`bloom_keyvec_init`, `bloom_keyvec_clear`, `bloom_keyvec_at`, `bloom_keyvec_empty`) are added to manage these structures, along with `bloom_filter_contains_vec` for checking multiple keys against a filter.

The implementation modifies bloom.c/h and revision.c/h, updating the bloom filter handling while maintaining the single-pathspec fast path. The changes are mechanical but thorough, converting all bloom key handling to use the new vector structure. The patch appears well-structured with clear commit message explaining the motivation and changes. This foundational change enables the performance optimization in patch 2/2 where multiple pathspec queries will be properly accelerated.
