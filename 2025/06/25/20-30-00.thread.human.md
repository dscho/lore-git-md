This thread explores how to exclude tagged commits from `git log` output between versions v2.3.0 and v2.4.0. M Hickford initially asked about using `--exclude=ref/tags/v*`, but Junio C Hamano explained this doesn't work as intended because `--exclude` affects reference selection for reachability calculations rather than filtering the final output. He described Git's revision model as fundamentally operating on reachability between commit sets, making it impossible to arbitrarily exclude intermediate commits like tags while maintaining proper history traversal. The current workaround uses `--decorate` with grep filter to remove tag lines, though this loses formatting.

Jacob Keller's follow-up probes for the underlying use case, suggesting the grep approach may remain the only practical solution unless there's an unstated need that could be addressed differently. The discussion has clarified this isn't a missing feature but a conceptual limitation in Git's design. Unless Hickford provides additional context about their specific requirements, the thread appears resolved with the understanding that tag exclusion in this manner isn't supported by Git's revision selection model.
