Performance optimization series for Git's pathspec bloom filters addressing Kai Koponen's report of combined pathspec queries being slower than separate invocations. The completed v6 series from Lidong Yan introduces `struct bloom_keyvec` to manage multiple bloom keys, replacing direct `struct bloom_key *` usage in `rev_info` and enabling bloom filter optimization for multiple literal pathspecs through a finalized implementation.

Key technical components:
1. Core architectural change replacing `struct bloom_key *` with `struct bloom_keyvec` in `rev_info` to support multiple pathspec queries with strict "for every" matching requirement (ALL pathspec items must report "definitely not changed")
2. Finalized `forbid_bloom_filters()` behavior now iterating through all pathspec items to allow bloom filter usage when all items are literal (removing count check) while rejecting wildcards/non-literal magic bits (PATHSPEC_FROMTOP, MAXDEPTH, GLOB, EXCLUDE, ATTR)
3. Dedicated `convert_pathspec_to_bloom_keyvec()` helper extracting pathspec-to-bloom-key conversion logic (path normalization via `xmemdupz`, trailing slash handling, empty path checking) into standalone function with error return (-1 for empty paths)
4. Comprehensive test coverage in t4216-log-bloom.sh for multiple literal pathspecs (including -- file4 A/file1 and glob patterns resolving to literals like -- *), wildcard fallback, escaped wildcards, case sensitivity, and single-pathspec backward compatibility - now with final test patch verifying: a) result equivalence between bloom-optimized and non-optimized pathspec queries b) correct bloom filter behavior when any pathspec contains non-literal elements
5. Verified performance improvements: 1.33x speedup in Git repo (55.1ms vs 73.1ms) and 7.5x in LLVM repo (263ms vs 1.4s) using hyperfine output format (benchmarks provided by Derrick Stolee)
6. Complete `struct bloom_keyvec` abstraction with lifecycle functions `bloom_keyvec_new()` (including key filling and path component counting) and `bloom_keyvec_free()`
7. `bloom_filter_contains_vec()` for checking all keys in a keyvec against a bloom filter (requires ALL pathspecs to match)
8. Updated `prepare_to_use_bloom_filter()` now using keyvec API through new helper function with loop initialization of all items, with cleanup of unused variables
9. `release_revisions_bloom_keyvecs()` helper for cleaning up all bloom keyvecs in `rev_info`
10. Consistent function renaming completed: `fill_bloom_key()` -> `bloom_key_fill()`, `clear_bloom_key()` -> `bloom_key_clear()` (mechanical changes across bloom.c/h, revision.c, blame.c, line-log.c, test-bloom.c)
11. Preserved single-pathspec fast path while adding multi-pathspec support
12. Test infrastructure improvements: `murmur3_seeded_v2()` made static with new test wrapper `test_bloom_murmur3_seeded()` that handles both v1 and v2 hash versions
