Optimization series for Git's pathspec bloom filters addressing Kai Koponen's performance report, now finalized with v6 from Lidong Yan introducing `struct bloom_keyvec` to manage multiple bloom keys. The series replaces direct `struct bloom_key *` usage in `rev_info` and enables bloom filter optimization for multiple literal pathspecs through a complete implementation with all feedback addressed.

Key technical components:
1. Core architectural change to `struct bloom_keyvec` in `rev_info` supporting multiple pathspec queries with strict "for every" matching (ALL pathspec items must report "definitely not changed")
2. Finalized `forbid_bloom_filters()` behavior iterating through all pathspec items, allowing bloom filter usage when all items are literal while rejecting wildcards/non-literal magic bits (PATHSPEC_FROMTOP, MAXDEPTH, GLOB, EXCLUDE, ATTR)
3. Dedicated `convert_pathspec_to_bloom_keyvec()` helper extracting pathspec-to-bloom-key conversion logic (path normalization, trailing slash handling, empty path checking)
4. Comprehensive test coverage in t4216-log-bloom.sh for multiple literal pathspecs, wildcard fallback, escaped wildcards, case sensitivity, and single-pathspec backward compatibility
5. Verified performance improvements: 1.33x speedup in Git repo (55.1ms vs 73.1ms) and 7.5x in LLVM repo (263ms vs 1.4s)
6. Complete `struct bloom_keyvec` abstraction with lifecycle functions and `bloom_filter_contains_vec()` for checking all keys
7. Updated `prepare_to_use_bloom_filter()` using keyvec API through new helper function with loop initialization
8. Consistent function renaming completed across bloom.c/h, revision.c, blame.c, line-log.c
9. Preserved single-pathspec fast path while adding multi-pathspec support
