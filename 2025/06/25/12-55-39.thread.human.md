This thread focuses on optimizing Git's pathspec bloom filters to handle multiple pathspec queries efficiently, addressing a performance limitation where combined pathspecs (like `git log -- file1 file2`) were slower than separate invocations. The series originated from Kai Koponen's report and is being developed by Lidong Yan.

The first version introduced `struct bloom_keyvec` to manage multiple bloom keys while preserving the single-pathspec fast path. Junio Hamano provided detailed feedback on the implementation, suggesting API improvements like using FLEX_ARRAY for better memory locality, tightening variable scoping, and fixing style issues. The second patch completed the optimization by enabling bloom filter usage with multiple pathspecs in revision traversal.

In the latest exchange, Lidong Yan acknowledges Junio's review points and commits to implementing all suggested changes in v2, including the FLEX_ARRAY switch and tighter scoping. The discussion has moved into polishing territory, with the core approach validated and only implementation refinements remaining. Junio had earlier emphasized the need for additional test coverage to verify correctness with multiple pathspecs, particularly guarding against false negatives, which Lidong agrees to address. The series appears technically sound and is nearing readiness for merging after these final adjustments to implementation details and test coverage.
