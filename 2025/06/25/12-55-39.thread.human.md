This thread focuses on optimizing Git's pathspec bloom filters to handle multiple pathspecs efficiently. The current implementation only accelerates single pathspec queries (like `git log -- file1`), causing combined pathspec queries (`git log -- file1 file2`) to be slower than running separate commands. 

Kai Koponen originally reported this performance issue, prompting Lidong Yan to propose a solution in a two-patch series. The first patch introduces `struct bloom_keyvec` to manage multiple bloom keys, replacing the direct `struct bloom_key *` usage. This refactoring maintains the existing single-pathspec optimization while preparing for multi-pathspec support. Junio Hamano reviewed the initial version, suggesting API refinements that were incorporated in v2 - using FLEX_ARRAY for keys, tighter variable scoping, and improved naming.

The second patch (not yet summarized here) will build on this foundation to actually enable multi-pathspec bloom filter checking. Benchmark results show the optimized version now matches the performance of separate single-pathspec invocations. The main remaining work is expanding test coverage, particularly to guard against false negatives where commits might be incorrectly skipped. Junio has confirmed the core approach is sound but wants additional test cases before merging. The thread is in its final stages, with the technical implementation validated and only test expansion needed.
