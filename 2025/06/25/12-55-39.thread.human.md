Lidong Yan's performance optimization series for Git's pathspec bloom filters has reached its final form with this v4 patch. The thread began with Kai Koponen's report that combined pathspec queries were slower than separate invocations, and this series introduces a new `struct bloom_keyvec` abstraction to address that.

The key technical achievement is enabling bloom filter optimization for multiple literal pathspec items during revision traversal, while carefully maintaining the existing fast path for single pathspecs. The final patch modifies the pathspec checking logic to allow multiple literal pathspecs to use bloom filters, adds cleanup helpers for the keyvecs, and verifies the behavior through updated tests. Wildcard pathspecs continue to bypass bloom filters as before.

Throughout the series, Lidong has incorporated feedback from Junio Hamano on API naming and test boundaries, Patrick Steinhardt's suggestions on type usage, and addressed various implementation details raised in review. The changes touch bloom filter handling in revision.c and test verification, without modifying core bloom filter data structures. Some optimizations like case sensitivity handling and nowildcard_len improvements remain as future work, but the core functionality is now complete and ready for merging.
