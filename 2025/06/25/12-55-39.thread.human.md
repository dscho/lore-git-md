This thread has completed a performance optimization series for Git's pathspec bloom filters, addressing a reported slowdown when using combined pathspec queries compared to separate invocations. Lidong Yan led the implementation, which introduces a new `struct bloom_keyvec` to manage multiple bloom keys, replacing direct `struct bloom_key *` usage in `rev_info`. The key improvement enables bloom filter optimization for multiple literal pathspecs while maintaining the strict requirement that all pathspec items must report "definitely not changed" for the optimization to apply.

The final patch modifies `forbid_bloom_filters()` to properly evaluate all pathspec items, removing the previous count check and only rejecting pathspecs containing non-literal elements like wildcards or magic bits. Comprehensive test cases verify correct behavior across various scenarios, including glob patterns that resolve to literals and proper fallback for actual wildcards. Performance benchmarks show significant improvements - 1.33x faster in the Git repository and 7.5x faster in the LLVM repository for multi-pathspec queries.

The series has undergone multiple review rounds with feedback incorporated from Junio Hamano (API consistency), Patrick Steinhardt (type usage), and Derrick Stolee (semantic clarification). With Reviewed-by tags from both Derrick Stolee and Junio Hamano, the implementation is now complete and ready for merging. The changes touch several core files including bloom.c/h and revision.c while maintaining backward compatibility and adding comprehensive test coverage. Future work may explore case sensitivity optimizations and nowildcard_len improvements, but the current series provides a robust solution for the immediate performance issue.
