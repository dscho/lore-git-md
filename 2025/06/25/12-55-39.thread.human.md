This thread focuses on optimizing Git's pathspec bloom filters to handle multiple pathspecs efficiently (like `git log -- file1 file2`), addressing a performance limitation where combined pathspec queries were slower than separate invocations. The two-part series from Lidong Yan introduces `struct bloom_keyvec` to manage multiple bloom keys (patch 1) and modifies bloom filter checking to use this while preserving the single-pathspec fast path (patch 2).

Junio Hamano provided detailed review feedback on the initial version, leading to API refinements in v2: using FLEX_ARRAY for keys, tighter variable scoping, and improved terminology. The implementation now correctly handles multiple pathspecs while maintaining performance parity with separate single-pathspec queries, as confirmed by benchmarks. Test coverage in t4216 has been updated to verify the optimization activates properly for multiple pathspec cases.

The series appears technically sound after Junio's review, with test coverage being the final consideration before merging. The changes touch bloom.c/h and revision.c/h, extending bloom filter functionality without regressing the existing fast path. This optimization should significantly improve performance of multi-pathspec queries in repositories using bloom filters.
