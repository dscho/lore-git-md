This thread covers a performance optimization series for Git's pathspec bloom filters, addressing a report that combined pathspec queries were slower than separate invocations. The series, authored by Lidong Yan, introduces a new `struct bloom_keyvec` abstraction to manage multiple bloom keys efficiently.

The key technical change is moving from checking pathspecs individually to evaluating them collectively - now requiring ALL pathspecs to match (not just ANY) to skip tree traversal. The implementation maintains a fast path for single pathspec cases while significantly improving performance for multiple pathspecs (0.24s vs 2.36s on the LLVM repo in v5 measurements).

The series has undergone thorough review from Derrick Stolee, Patrick Steinhardt, and Junio Hamano. Key feedback addressed includes:
- Clarifying evaluation semantics
- Improving memory management with `CALLOC_ARRAY()`
- Cleaning up API boundaries between test and production code
- Adding comprehensive documentation
- Reorganizing functions for better readability

The v5 iteration merges key-filling into creation, improves parameter ordering, and includes performance measurements showing the optimization's impact. While the core approach is stable, some minor organizational suggestions remain open. The changes touch bloom filtering logic across multiple files while maintaining backward compatibility.

Future work may address case sensitivity optimizations (currently filters are case-sensitive regardless of `core.ignorecase`) and `nowildcard_len` improvements, but these are deferred from the current series which focuses on the keyvec abstraction and multi-pathspec evaluation.
