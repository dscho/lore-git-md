Performance optimization introducing bloom_keyvec for multiple pathspec support. This is the first patch in a series addressing the limitation where Git's bloom filters only accelerated single pathspec queries.

The patch introduces a new `struct bloom_keyvec` to manage bloom keys for multiple pathspecs, replacing the direct `bloom_key*` array in `struct rev_info`. Each keyvec corresponds to one pathspec, with the array `bloom_keyvecs` holding all pathspec keys. New helper functions (`bloom_keyvec_init`, `bloom_keyvec_clear`, etc.) handle initialization and cleanup, while `bloom_filter_contains_vec()` checks if all keys in a keyvec are contained in a bloom filter.

The changes touch bloom.c/h and revision.c/h, updating the bloom filter checking logic while maintaining the single-pathspec fast path. The implementation appears thorough, with clear memory management and assertions for safety. This foundational change enables the subsequent patch to optimize combined pathspec queries (`git log -- file1 file2`) to match the performance of separate invocations.
