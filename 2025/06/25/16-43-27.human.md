This is a refactoring patch adjusting Git's clang-format configuration. It's part of a 4-patch series (position 2/4) aimed at making clang-format more usable for Git development.

The patch removes the hard 80-character line limit (ColumnLimit) from Git's clang-format configuration, setting it to 0 instead. The author explains that while 80 characters remains the recommended limit in CodingGuidelines, enforcing it via clang-format has caused problems - both by forcing undesirable line concatenation and producing many false positives. Previous attempts to tweak line break penalties (in 2017 and 2024) didn't fully solve these issues.

The change makes line wrapping the developer's responsibility rather than clang-format's, while still providing guidance through a 120-character limit in .editorconfig (added in the previous patch). The commit message notes this is a pragmatic solution until better penalty settings can be found to properly enforce the 80-character guideline.

The patch appears well-reasoned and addresses a known pain point in Git's code formatting workflow. The commit message provides good historical context and clear motivation for the change. This seems like a practical improvement that should make clang-format more useful for contributors.
