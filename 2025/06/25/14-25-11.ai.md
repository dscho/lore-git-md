Bugfix and feature enhancement for git-credential-netrc and git-send-email, completing the v4 series on symbolic port name handling. This final patch introduces validation and conversion of symbolic port names while maintaining backward compatibility.

The patch makes several coordinated changes across multiple Perl scripts to properly handle symbolic port names like "smtps" in netrc files. The main changes include:

1. Adds a new `port_num` helper function in perl/Git.pm that validates both numeric ports (checking 16-bit range) and symbolic names (using getservbyname), returning undef for invalid values.

2. Modifies git-credential-netrc to use this helper, properly separating port numbers from protocol values in the credential matching logic. This fixes cases where symbolic ports like "smtps" were incorrectly treated as protocols.

3. Updates git-send-email to validate SMTP server ports using the same helper, providing better error messages for invalid ports.

4. Adjusts test cases to verify the new behavior, including a new test for invalid SMTP port handling. The test changes reflect the corrected credential matching where ports are now properly separated from protocols.

The implementation maintains all existing functionality while adding the new validation layer. Invalid ports generate warnings (for netrc) or errors (for send-email) but don't break existing workflows. The changes are well-tested with updates to both the netrc test suite and send-email tests.

This completes the series that began with basic symbolic port support in v3, adding the final validation and error handling components. The patch follows established patterns from earlier review feedback and maintains the series' focus on backward-compatible improvements to port handling.
