This is a maintainer review response in the gitk external diff bugfix thread. Johannes Sixt provides detailed technical feedback on Tobias Boesch's v6 patch that aims to fix gitk's handling of renamed files in external diffs. While acknowledging the patch's goal of using `git diff --find-renames` to properly locate renamed files, Sixt suggests an alternative approach that would parse rename information directly from gitk's diff text panel rather than invoking an external Git command.

Key technical points raised:
- Recommends using plumbing commands (`diff-tree`, `diff-index`, `diff-files`) instead of porcelain `git diff`
- Questions the use of `--stat` and suggests `--numstat` might be easier to parse
- Notes issues with the current regex parsing of `--raw` output, suggesting `-z` for unambiguous null-byte separation
- Points out variable naming inconsistencies and style deviations from gitk's Tcl conventions
- Suggests investigating use of the existing `difffilestart` variable to parse rename info from diff text

The review maintains the thread's productive tone while providing concrete technical guidance. Sixt leaves open the possibility of accepting the current approach if the parsing alternative proves unworkable, but clearly prefers avoiding the external process invocation. This represents the final round of review feedback before potential acceptance of the long-running rename detection fix.
