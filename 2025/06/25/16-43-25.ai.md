This is a CI/build system patch series aimed at improving Git's clang-format integration. The 4-part series addresses issues with false positives in automated code formatting by making several coordinated changes to the project's style enforcement infrastructure.

The key changes proposed are: removing clang-format's ColumnLimit (shifting line-wrapping responsibility to developers), adding a 120-character line length limit in .editorconfig, making the RemoveBracesLLVM rule permanent in .clang-format, and adding a meson build target for running clang-format. The author shows sample diffs demonstrating reduced formatting noise, particularly around line wrapping and brace placement in several files including builtin/diff.c and pathspec.h.

The changes appear well-motivated by prior discussion (referencing a thread with Junio Hamano) and the implementation looks technically sound. The series maintains backward compatibility while making the formatting tool more predictable. The author suggests these changes could eventually allow making the style-check CI job required, though that's deferred for future consideration. The patches touch configuration files (.clang-format, .editorconfig), build system (meson.build), and CI scripts (ci/run-style-check.sh).
