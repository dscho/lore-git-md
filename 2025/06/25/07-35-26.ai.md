This is a platform compatibility patch in the ongoing Git daemon signal handling series. It introduces a new `USE_NON_POSIX_SIGNAL` build flag to systematically handle systems lacking `SA_RESTART` support, replacing previous ad-hoc compiler flag approaches.

The patch centralizes `SA_RESTART` handling by:
1. Adding a fallback definition in `compat/posix.h` when not provided by the system
2. Introducing the new `USE_NON_POSIX_SIGNAL` Makefile variable
3. Updating platform-specific configurations (Windows, NonStop, QNX, MINGW) to use the new flag
4. Adding autoconf and meson build system support to detect `SA_RESTART` availability

Key technical changes include removing the `SA_RESTART` definition from `compat/mingw-posix.h` since it's now handled centrally, and converting platform-specific `-DSA_RESTART=0` compiler flags to the new `USE_NON_POSIX_SIGNAL` approach. The patch maintains backward compatibility while providing a cleaner abstraction for the signal handling work in subsequent patches.

This is part of a larger effort to fix zombie process cleanup on OpenBSD and crashes on AIX by properly handling interrupted system calls during signal handling. The thread history shows extensive discussion about the correct approach between Carlo Marcelo Arenas Belón and Junio C Hamano, with this version representing a refinement based on that feedback - particularly around naming (`USE_NON_POSIX_SIGNAL` replacing the previous `NO_SIGINTERRUPT` flag).
