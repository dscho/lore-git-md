Performance regression report in `git for-each-ref` with large tag sets. Andrzej Dębski reports a significant slowdown in `git for-each-ref --format="%(refname)" refs/tags --merged HEAD` operations when processing repositories with ~65K tags, comparing Git 2.39.5 (fast) to 2.40.0+ (slow). The performance degradation appears linked to the `tips_reachable_from_bases` function introduced in commit cbfe360b140, where execution time scales with tag count. The report comes from Dropbox's monorepo environment where this impacts Go tooling workflows. The email questions whether this constitutes a regression worth fixing, given the command's previous faster behavior. System details show the issue persists through at least Git 2.50. Key technical points for future reference: the problematic commit added reachability checking for merged refs, the regression manifests specifically with `--merged` filtering on large tag sets, and the performance impact is directly correlated with tag count.
