This is a bugfix discussion in the ongoing Git daemon signal handling series. Phillip Wood points out a race condition in the current approach where a child process exiting between `check_dead_children()` and `poll()` would not be reaped until another event occurs. He suggests using the self-pipe trick (described in select(2)) as an alternative that would avoid the need for platform-specific SA_RESTART handling and the new USE_NON_POSIX_SIGNAL flag.

The email references Carlo Marcelo Arenas Belón's v2 patch series which:
1. Centralizes SA_RESTART definitions
2. Modernizes signal handling with sigaction()
3. Explicitly allows EINTR during poll()

Phillip's critique focuses on the architectural level rather than implementation details, proposing a different solution that would handle the race condition more robustly while potentially simplifying the platform-specific code. This represents a significant new consideration in the thread, as previous discussion had focused on refining the SA_RESTART approach rather than questioning its fundamental suitability.

The self-pipe approach would involve:
- Creating a pipe solely for signal delivery
- Writing to it from the signal context
- Monitoring it alongside other fds in poll()
This would make the signal delivery synchronous with the event loop rather than relying on interrupted system calls.

Key technical points for future reference:
- Race condition exists between check_dead_children() and poll() calls
- Self-pipe trick would require additional file descriptor
- Would eliminate need for SA_RESTART toggling
- May provide more deterministic behavior across platforms
- Current implementation uses set_sa_restart() helper for dynamic SA_RESTART control

This suggestion introduces a new architectural direction to consider alongside the ongoing refinement of the SA_RESTART approach, potentially affecting the series' final design.
