Security bugfix follow-up regarding shell command injection in Bash completion. Kristoffer Haugsbakk clarifies their earlier comment about restricting `>` in refnames was just an offhand remark, not a serious proposal, after Phillip Wood and Junio Hamano both emphasized the real issue is the completion script's failure to properly escape shell metacharacters. The thread has clearly established consensus that the fix belongs in `git-completion.bash` rather than changing Git's refname rules, which intentionally allow many special characters for backward compatibility. No patch has been submitted yet, but the discussion has narrowed the solution path to proper quoting during tab completion operations. The vulnerability remains open but now with clear technical direction.
