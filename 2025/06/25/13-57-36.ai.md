Security discussion about shell-injection-safe refnames. Phillip Wood responds to Kristoffer Haugsbakk's suggestion to modify `git-check-ref-format` to disallow special shell metacharacters in branch names. While acknowledging the security concern, Wood argues the root issue lies in the completion script's failure to properly quote refnames containing shell metacharacters, rather than in the refname format itself. He notes Git's ref format already permits numerous other potentially problematic characters (`<`, `$`, `&`, `;`, etc.) that would similarly need escaping when used in shell contexts. The response suggests fixing the completion script's quoting behavior is the more appropriate solution compared to restricting refname characters at the validation level. This maintains backward compatibility while addressing the immediate security issue. The exchange highlights the tension between security hardening and maintaining Git's flexible refname conventions, with Wood advocating for proper escaping in the specific context where shell interpretation occurs rather than changing the underlying ref format rules. No patch is proposed in this message, but it clarifies the architectural position that shell safety should be handled at the interface layer (completion scripts) rather than the data model layer (refname validation).
