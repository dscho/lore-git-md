This is a cover letter for the final v5 version of a feature series enhancing the promisor-remote protocol with configurable field validation. The series is now fully approved and ready for merging, addressing all previous feedback.

The core change extends the promisor-remote protocol to support dynamic advertisement and validation of remote attributes (currently limited to partialCloneFilter and token) during clone/fetch operations. The server-side `promisor.sendFields` config controls which fields are advertised, while `promisor.checkFields` enables client-side validation against local configuration. The implementation maintains backward compatibility while adding security through strictly constrained field handling.

Key technical improvements in v5 are minimal, consisting mostly of documentation clarifications and minor code tweaks: better commit message explanations in patch 1, improved BUG() message wording, and added code comments in patch 2's field parsing logic. The series has undergone thorough review from multiple maintainers (Patrick Steinhardt, Junio Hamano, Karthik Nayak, Justin Tobler) with all feedback incorporated. Christian Couder confirms CI tests are passing and considers this version final.

The changes build on significant internal refactoring from earlier versions, including the introduction of `struct promisor_info` to replace `strvec` storage, centralized field parsing, and string constant usage for maintainability. Test coverage verifies field transmission, client validation, URL encoding handling, and config parsing edge cases. Documentation includes BNF notation for the protocol and clear explanations of the new validation rules.

This work is part of Git's "Large Object Promisors" (LOP) effort and represents a foundation for future protocol extensions while immediately enabling more robust partial clone configurations. The series demonstrates careful, incremental development with thorough review and testing - a model contribution ready for integration.
