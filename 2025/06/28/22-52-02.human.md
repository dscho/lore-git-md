This is a bugfix series addressing long-standing issues with `git apply --intent-to-add`. The cover letter explains that this flag has been broken since its introduction in Git 2.19, failing to properly handle existing index entries when applying patches. The current behavior creates an empty index except for new files, making the option nearly useless outside of empty repositories.

The series consists of five patches that first add error checking for invalid usage, then fix the core functionality to properly read and preserve the existing index while marking new files as intent-to-add. It includes new tests to verify the corrected behavior and updates the documentation to better explain the flag's purpose.

The author references two previous discussion threads about this issue, suggesting this has been a known pain point for several years. The changes appear focused and well-motivated, with clear test coverage added to prevent regression. This looks like a solid quality-of-life improvement for users who need to stage patch content with proper intent-to-add handling.
