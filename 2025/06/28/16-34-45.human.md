This is a bugfix patch in a series implementing diff context configuration support for interactive patch commands. It addresses a gap where the add-patch infrastructure (used by commands like `git add -p`) wasn't properly respecting the user's diff.context and diff.interHunkContext settings.

The patch makes several key changes:
1. Adds context and interhunk context fields to the add_i_state struct
2. Reads these config values during initialization, with the same validation (rejecting negative values) used elsewhere
3. Passes the values through to the underlying diff command via -U and --inter-hunk-context options
4. Adds tests verifying the config is respected and negative values are rejected

This completes the config support that was already implemented for command-line options in earlier patches. The implementation is thorough, with clear test coverage for both the happy path and error cases. The changes are well-contained to the interactive add infrastructure.

This is part of a larger effort to make all interactive patch commands (add/checkout/commit/reset/restore/stash) consistently respect diff context settings. The series appears mature, with multiple rounds of review addressing test organization, edge cases, and documentation. This particular patch fills the last remaining gap in the plumbing layer.
