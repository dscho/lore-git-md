This is a safety check patch in the `git apply --intent-to-add` bugfix series. It prevents using the `--intent-to-add` (`-N`) option outside a Git repository, which was silently ignored before but makes no logical sense since intent-to-add requires an index to modify.

The change modifies `apply.c` to explicitly check for repository context when `--intent-to-add` is used, matching the existing behavior for `--cached`. Instead of silently disabling the flag (as the old code did), it now errors out with a clear message. The patch is based on prior work by Johannes Altmanninger and appears straightforward, though it doesn't yet have test coverage (which likely comes in a later patch in the series).

Key technical details for future reference: The change affects the `check_apply_state()` function in `apply.c`, specifically the handling of the `state->ita_only` flag. It introduces a new error path that mirrors the existing `--cached` check, using the same error message format. The patch maintains the existing behavior of disabling `ita_only` when `check_index` is set, just now with more explicit conditions.
