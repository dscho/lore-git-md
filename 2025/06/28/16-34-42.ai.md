This is a feature patch series (v3) improving diff context configuration support for interactive patch commands (`add`, `checkout`, `commit`, `reset`, `restore`, and `stash` with `--patch`). The series builds on earlier work to make these commands respect `diff.context` and `diff.interHunkContext` configs consistently with other diff-generating commands.

The main changes in this version:
1. Adds command-line options `-U`/`--unified` and `--inter-hunk-context` that override config values
2. Implements validation to reject negative context values
3. Updates tests to use modern `test_grep` and `test_config` utilities
4. Drops the interactive subcommand feature from earlier versions as too complex for now
5. Adds comprehensive documentation in `diff-context-options.adoc`

Key technical details:
- New options use `OPT_DIFF_UNIFIED` and `OPT_DIFF_INTERHUNK_CONTEXT` macros
- Validation occurs early in command execution
- Tests verify CLI-over-config precedence across all commands
- Edge cases tested include negative values and `-U0` behavior
- Documentation clarifies precedence rules and default values

The implementation appears thorough with good test coverage. The series has evolved through several rounds of review addressing:
- Test organization (now consolidated in t3701)
- Edge case handling (negative values, stash validation timing)
- Code style (semicolon placement in config validation)
- Documentation decisions (separate from git-diff docs)

The only remaining discussion point is test organization strategy (multi-command vs single-command verification), with Phillip Wood requesting reference to an earlier suggestion about this. The series otherwise looks ready for inclusion.
