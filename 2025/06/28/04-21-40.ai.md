Performance optimization patch extending Git's pathspec bloom filters to handle multiple pathspecs efficiently. This is the second patch in a series addressing Kai Koponen's report about combined pathspec queries being slower than separate invocations.

The patch modifies `revision.c` to:
1. Remove the `spec->nr > 1` check in `forbid_bloom_filters()`, allowing bloom filter usage with multiple pathspecs
2. Add comprehensive checking of all pathspec items' magic bits (not just the first item)
3. Implement per-pathspec bloom key initialization in `prepare_to_use_bloom_filter()`
4. Update `check_maybe_different_in_bloom_filter()` to check all pathspecs' bloom keys (returning true if any match)
5. Add cleanup function `release_revisions_bloom_keyvecs()`

Test changes in t4216-log-bloom.sh verify:
- Bloom filters are now used with multiple literal pathspecs (flipping previous "not used" expectations)
- Proper handling of escaped wildcards (ensuring filters aren't used when pathspecs contain actual wildcards)
- Backward compatibility is maintained through careful use of `eval` in test helpers

The implementation follows the approach established in patch 1/2, maintaining the single-pathspec fast path while extending support for multiple pathspecs. All review feedback from Junio Hamano appears addressed, including proper magic bit checking and test coverage improvements. The changes touch bloom.c/h and revision.c/h with corresponding test updates.
