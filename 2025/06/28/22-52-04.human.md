Bugfix for `git apply --intent-to-add` index handling. This is the core patch in a series fixing a long-standing issue where `-N` (intent-to-add) mode fails to properly read the index, making the feature effectively unusable except in empty repositories.

The patch modifies `apply.c` to ensure the index is read whenever it will be checked *or* updated, fixing the fundamental issue where intent-to-add operations were working without proper index state. The change is minimal (a one-line condition modification) but crucial for correct behavior.

Raymond E. Pasco's commit message clearly explains the three main apply modes and how `--intent-to-add` was supposed to work as a variant of worktree-only application. The patch builds on prior work by Johannes Altmanninger and addresses a bug report from Ryan Hodges.

This appears to be a well-motivated fix for a known limitation, with the real test coverage coming in later patches of the series. The change is surgical and maintains the existing code structure while fixing the core issue.
