This is a feature patch series that improves context line configuration for interactive patch commands (`add -p`, `commit -p`, etc.). The series is now in its third iteration, having evolved from earlier versions that included an interactive subcommand feature (later dropped due to complexity).

The key changes in this version:
1. Adds support for `diff.context` and `diff.interHunkContext` configs in interactive patch commands
2. Introduces `--unified` and `--inter-hunk-context` command-line options that override configs
3. Validates negative values for both config and command-line options
4. Includes comprehensive test coverage and documentation

The implementation appears thorough, with careful attention to edge cases and validation. The series has undergone significant review and refinement, with notable input from Phillip Wood and Junio C Hamano. The current discussion focuses on test organization strategy (multi-command vs single-command verification), representing the final point of clarification in an otherwise complete implementation.

The changes affect multiple commands (`add`, `checkout`, `commit`, `reset`, `restore`, `stash`) and touch core interactive components while maintaining backward compatibility. The documentation is centralized in a new `diff-context-options.adoc` file rather than being merged with `git-diff` docs due to organizational differences.

This looks like a well-considered improvement to Git's interactive patch interface, addressing a real inconsistency in how diff context is handled across commands. The extensive test coverage and documentation suggest it's ready for serious consideration.
