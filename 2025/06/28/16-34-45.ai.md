This is a bugfix patch in the ongoing series to make interactive patch commands respect diff context configurations. It addresses a gap where the add-patch infrastructure wasn't properly reading and applying the diff.context and diff.interHunkContext settings.

The patch modifies the add-interactive infrastructure to:
1. Add context and interhunkContext fields to struct add_i_state
2. Read and validate these config values during initialization (rejecting negative values)
3. Pass the values through to the diff command via --unified and --inter-hunk-context options

Key technical details:
- New fields in add_i_state default to -1 (unset)
- Config validation matches behavior elsewhere in the series (rejects negative values with die() message)
- The diff command line is modified to include the context parameters when set
- Tests verify:
  * Basic functionality with diff.context=5
  * Inter-hunk context merging with diff.interHunkContext=2
  * Negative value rejection

This completes the implementation of config support for all interactive commands, fixing the inconsistency where plumbing commands used by add-patch weren't reading these settings. The patch builds on previous test infrastructure modernization in the series and adds new test cases specifically for the add-patch path.

The implementation follows the established pattern from earlier patches in the series, with consistent validation and error messaging. This was the last major piece needed for full config support across all interactive commands.
