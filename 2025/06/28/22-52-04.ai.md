This is the core bugfix patch in a series addressing `git apply --intent-to-add` functionality. The patch fixes the fundamental issue where the index wasn't being read in intent-to-add mode, which made the feature effectively non-functional except in empty repositories.

The change modifies `apply.c` to read the index whenever it will be either checked or updated, rather than just when checking. This is necessary because intent-to-add operations (marked by `state->update_index`) need the index contents to properly handle the special index entries they create, even when not doing a full index check. The one-line diff changes the condition for calling `read_apply_cache()` to include both `check_index` and `update_index` cases.

The patch builds on prior work by Johannes Altmanninger and addresses a long-standing issue reported by Ryan Hodges. The commit message clearly explains the three main apply modes and how `--intent-to-add` fits into this model, while also detailing why the previous implementation was insufficient.
