This is the first patch in a performance optimization series for Git's pathspec bloom filters, introducing infrastructure to support multiple pathspec items. The patch replaces the direct `struct bloom_key *` usage in `rev_info` with a new `struct bloom_keyvec` that can manage multiple bloom keys per pathspec item.

The key changes include:
- Adding `struct bloom_keyvec` with a flexible array of bloom keys and count
- Introducing new functions: `create_bloom_keyvec()`, `destroy_bloom_keyvec()`, `fill_bloom_keyvec_key()`, and `bloom_filter_contains_vec()`
- Converting `rev_info` to use `bloom_keyvecs` and `bloom_keyvecs_nr` instead of direct bloom key arrays
- Maintaining the single-pathspec fast path by keeping `bloom_keyvecs_nr` as 0 or 1 in this patch

The implementation follows Junio Hamano's v2 review suggestions by using FLEX_ARRAY for keys and tightening variable scoping. The changes touch bloom.c/h and revision.c/h, with corresponding updates to the bloom filter preparation and checking logic. While this patch only enables single pathspec optimization, it lays the groundwork for the follow-up patch that will handle multiple pathspecs.

The technical approach appears sound, with proper memory management and clean API boundaries. The patch maintains all existing functionality while preparing for the multi-pathspec optimization, making it a safe incremental change. The use of assertions and careful error handling suggests attention to robustness.
