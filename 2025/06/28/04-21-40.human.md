Performance optimization patch completing the series to enable bloom filter acceleration for multiple literal pathspecs. This is the second and final patch in Lidong Yan's series addressing Kai Koponen's report that combined pathspec queries (`git log -- file1 file2`) were slower than separate invocations.

The patch removes the `spec->nr > 1` check in `forbid_bloom_filters()` and modifies the bloom filter preparation and checking logic to handle multiple pathspecs. Each pathspec now gets its own `bloom_keyvec` structure, and the bloom filter check returns true if any pathspec matches. The implementation includes proper cleanup via a new `release_revisions_bloom_keyvecs()` function.

Test changes verify the optimization works for multiple literal pathspecs while maintaining the existing behavior that bloom filters aren't used for non-literal pathspecs (like those containing wildcards). The patch appears well-tested and addresses all feedback from Junio Hamano's review of earlier versions, including proper handling of escaped wildcards in test cases.

This completes the series' goal of extending bloom filter optimizations beyond single pathspec cases while maintaining the fast path for that common scenario. The changes are focused in revision.c with corresponding test updates in t4216-log-bloom.sh.
