This thread addresses a bugfix series for `git apply --intent-to-add` (`-N` flag) that has been non-functional since Git 2.19. Ryan Hodges is fixing incorrect index handling that made the feature work only in empty repositories. The series consists of four patches so far: the first ensures safety checks, the second fixes index reading in intent-to-add mode, the third properly limits intent-to-add markers to new files, and this latest patch adds test coverage for more complex scenarios.

The new test cases verify correct interaction between intent-to-add and existing index entries, including handling patches that mix modifications to tracked files with new intent-to-add files. The tests use standard Git verification patterns and expand coverage while maintaining consistency with the existing test approach. The series modifies `apply.c` to properly handle index reading and writing in intent-to-add mode, and adds a dedicated test file (`t4140-apply-ita.sh`) with now 61 lines of coverage. While the technical approach appears sound, the series is still awaiting review feedback from the community. The work builds on previous discussions about `--intent-to-add` behavior but has no direct dependencies on other in-flight topics.
