This thread addresses a bug in `git apply --intent-to-add` that has made the feature non-functional since Git 2.19, except in empty repositories. Ryan Hodges originally reported the issue, and Raymond Pasco has posted a five-patch series to restore proper behavior. The core problem is that the command fails to correctly read and update the index, only handling new files properly.

The series includes fixes for both index reading (patch 2) and writing (patch 3), along with expanded test coverage (patch 4) and documentation updates (patch 5). Lidong Yan has replied, confirming the core issue and agreeing with the solution. They highlight that patch 2 properly fixes the index reading problem, while patch 3 aligns the behavior with `git add --intent-to-add` by ignoring intent-to-add operations for files already in the index. This ensures consistency between the two commands.

The technical changes modify `apply.c` and add new test cases to verify the fixes work with complex scenarios involving existing index entries and mixed modification/new-file patches. While the series appears technically sound, it's still awaiting broader review from the community. The discussion so far suggests the approach is on the right track, with Yan's reply providing helpful context about how the patches relate to existing Git behavior.
