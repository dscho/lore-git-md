Here's the updated human-readable thread summary:

This thread addresses a long-standing bug in `git apply --intent-to-add` (or `-N`) that has been broken since Git 2.19. The feature, which should allow applying patches while preserving intent-to-add status for new files, was failing to handle the index reading and writing properly, making it effectively non-functional except in empty repositories.

Raymond Pasco has sent a v3 series of four patches that comprehensively fixes the issue. The first patch corrects index reading behavior to prevent clobbering existing entries, while this second patch (the focus of the latest email) precisely fixes when intent-to-add entries should be written to the index. The series also includes expanded test coverage and documentation updates.

The technical changes are well-considered, with clear explanations in the commit messages about the index handling decisions. The patches modify `apply.c` and add tests in `t4140-apply-ita.sh` to verify the fixes work in various scenarios, including mixed modification cases. Junio Hamano's earlier architectural concerns appear fully addressed in v2, and the thread has reached consensus on the silent ignore behavior outside gitdir.

The only remaining open question is whether to backport the fix, given that the original test infrastructure didn't exist in 2018. The series otherwise appears technically complete and ready for integration. This work builds on prior reports from Ryan Hodges and Johannes Altmanninger, restoring functionality that has been broken for nearly six years.
