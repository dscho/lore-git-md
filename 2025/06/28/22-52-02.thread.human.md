This thread addresses a bug in `git apply --intent-to-add` (`-N`) that has made the feature non-functional since Git 2.19. Raymond Pasco's five-patch series fixes incorrect index handling to properly support applying patches while preserving intent-to-add state. The patches modify core index reading/writing logic in `apply.c`, add comprehensive tests, and update documentation.

The discussion has focused on two key design questions. First, whether `-N` should error out (Raymond's initial approach) or silently ignore (Junio's preference) when used outside a Git repository. Raymond is reconsidering his position after Junio noted `-N` signals weaker repository awareness than flags like `--index`. Second, Junio raised architectural questions about whether writing only intent-to-add entries is conceptually correct, though he agrees the technical implementation works for the current design.

The series is currently at version 1 with active review. Patch 1 (repository check) remains debated, patch 2 (index reading) has Junio's conditional approval pending the conceptual discussion, and patch 3 (index writing) needs refinement around flag interactions. Lidong Yan has confirmed the solution approach aligns with `git add --intent-to-add` behavior. The thread shows healthy technical discussion between Raymond and Junio, with Raymond demonstrating willingness to adapt his approach based on feedback.
