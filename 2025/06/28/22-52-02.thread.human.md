This thread addressed a long-standing bug in `git apply --intent-to-add` (`-N`) where the flag failed to properly handle the index, making the feature effectively non-functional except in empty repositories. Raymond Pasco's patch series fixed both the index reading and writing behaviors while preserving the intent-to-add state.

The v3 series, now acked by Junio Hamano for integration, consists of four well-documented patches: core fixes for index operations, precise conditions for ITA entry creation, comprehensive test coverage including mixed modification scenarios, and documentation updates clarifying flag interactions. The expanded commit messages provide detailed technical rationale, particularly around the exact conditions for ITA entry creation (`check_index || (ita_only && is_new)`).

All architectural concerns raised earlier in the thread were addressed, and the test coverage now verifies behavior with committed files. While backporting considerations were discussed (noting the test infrastructure didn't exist in 2018), this was left as a non-blocking issue. With Junio's approval, this fixes a subtle but important bug that had persisted since Git 2.19.
