This thread addresses a bugfix series for `git apply --intent-to-add` that restores functionality broken since Git 2.19. The original report identified incorrect index handling that made the feature non-functional in non-empty repositories. Ryan Hodges has contributed a four-patch series that: (1) adds safety checks, (2) fixes index reading logic, (3) corrects intent-to-add marker writing, and (4) expands test coverage with complex scenarios. The most recent addition is a documentation patch that clarifies the `--intent-to-add` option's behavior in light of these fixes, removing confusing double negatives and properly distinguishing between `--index` and `--cached` modes.

The technical changes focus on `apply.c`, introducing proper handling of intent-to-add mode in both reading and writing the index, while limiting markers to new files. A new test file (`t4140-apply-ita.sh`) verifies the fixes against various edge cases. The documentation update completes the series by reflecting the corrected behavior where `--intent-to-add` now properly affects only working tree operations. While the series appears technically sound, it awaits review from the community - particularly from experts in the apply machinery like Johannes Altmanninger, whose prior work this builds upon. The changes maintain consistency with existing error handling patterns and don't appear to conflict with other in-flight topics.
