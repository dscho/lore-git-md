This is a design clarification in the ongoing `the_repository` removal effort, specifically addressing the sparse-checkout configuration refactoring. Junio Hamano provides explicit guidance on two valid patterns for accessing repository settings, resolving previous confusion in the thread.

The email establishes clear architectural principles for handling repository configuration variables. For rarely-used settings, lazy loading via getter/setter pairs is appropriate, where the getter handles initialization. For commonly-used settings like `core.sparsecheckout`, direct access after initialization in `prepare_repo_settings()` is preferred since the cost is already paid during config reading.

Junio explains that the current sparse-checkout case falls into the "commonly used" category, as it was previously loaded globally via `git_default_config`. This justifies the direct access pattern rather than the getter/setter approach implemented in the patch. The clarification corrects a previous comment from Patrick Steinhardt that had conflated the two approaches.

The guidance provides a framework for future similar migrations in the repository settings work, though it doesn't request immediate changes to the current patch. The rules establish consistency patterns that will affect how other globals are migrated, including the remaining `core_sparse_checkout_cone` work mentioned in earlier discussion.
