This is the second patch in a two-part CI/Windows Coverity build fix series. It adds build log output when Coverity's analysis fails, making it easier to diagnose issues when they occur.

The patch modifies `.github/workflows/coverity.yml` to show the contents of `cov-int/build-log.txt` if the `cov-build` step fails. This is a straightforward quality-of-life improvement that will help maintainers understand exactly what went wrong when Coverity encounters problems analyzing the code, rather than just seeing a generic failure.

The change is minimal and well-contained - it simply wraps the existing `cov-build` command in a conditional that outputs the log before exiting on failure. This complements the first patch in the series (which addressed PATH ordering issues causing DLL conflicts on Windows) by improving debuggability of any future Coverity build problems.

Given that this is a resolved thread where Junio Hamano has already approved the approach, and the change is clearly beneficial with no apparent downsides, this patch appears ready to merge as part of the complete solution. The series as a whole fixes Windows-specific Coverity build issues while adding this helpful debugging aid.
