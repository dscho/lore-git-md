This is a platform compatibility patch that's part of a 6-part series (currently at v2, patch 3/6). The change targets MSVC compiler support by explicitly setting endianness definitions when compiling on Windows.

The patch addresses a gap where Microsoft's Visual C++ compiler doesn't define standard endianness macros like `__BYTE_ORDER__`. Since MSVC-supported architectures (x86 and arm64) are all little-endian, the patch hardcodes `GIT_BYTE_ORDER` to little-endian for MSVC builds. It does this by adding new definitions before the existing fallback logic in `compat/bswap.h`.

Key technical details for future reference:
- Adds explicit `GIT_LITTLE_ENDIAN`/`BIG_ENDIAN` constants (1234/4321)
- Sets `GIT_BYTE_ORDER` to little-endian for MSVC
- Preserves existing behavior for other platforms via `#elif !defined(GIT_BYTE_ORDER)`
- Touches the byte-swapping compatibility layer (`compat/bswap.h`)

The change appears straightforward and well-justified, as it codifies what's already true about MSVC's supported architectures. This is likely non-controversial but important for proper compilation on Windows. The patch is part of a larger series, so its impact should be considered in that broader context.
