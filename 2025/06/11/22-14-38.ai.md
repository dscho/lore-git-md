Platform compatibility patch adding support for `__BYTE_ORDER__` macro in `compat/bswap.h`. This is part of a 6-patch series (position 2/6), though no cover letter context is provided.

The change adds a new fallback path for detecting byte order when neither the platform-specific nor libc-provided macros are available. The commit explains that `__BYTE_ORDER__` is supported by GCC (since ~4.6), Clang (since ~3.2), and ICC (since ~16.0.3), but not by MSVC as of version 19.43. The existing `__BYTE_ORDER`/`BYTE_ORDER` macros are noted as being libc-specific and unavailable on some platforms like MinGW.

The implementation adds a new conditional block that defines Git's internal `GIT_BYTE_ORDER`, `GIT_LITTLE_ENDIAN`, and `GIT_BIG_ENDIAN` constants in terms of the compiler's `__BYTE_ORDER__`, `__ORDER_LITTLE_ENDIAN__`, and `__ORDER_BIG_ENDIAN__` macros when available. This appears to be a straightforward platform compatibility improvement with clear motivation and limited scope (only `compat/bswap.h` is modified). The change maintains the existing fallback to hardcoded values when no byte order detection is available.
