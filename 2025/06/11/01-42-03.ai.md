Bugfix for `git stash` branch name corruption in submodule contexts. This final version of the patch addresses a subtle issue where stashing changes in a superproject would sometimes incorrectly display the submodule's branch name in the stash message rather than the superproject's branch name. The root cause was buffer reuse in `refs_resolve_ref_unsafe()` - subsequent calls would overwrite the static buffer containing the branch name before it was used in the stash message.

The solution introduces heap allocation via `xstrdup()` to preserve the superproject's branch name through submodule operations, with proper memory management via a new `branch_name_buf` variable that gets freed before function exit. The patch maintains the existing "(no branch)" fallback behavior while fixing the corruption case. 

Key technical changes include:
- Modified `do_create_stash()` in `builtin/stash.c` to duplicate the branch name immediately after resolution
- Added corresponding `free(branch_name_buf)` to prevent memory leaks
- Simplified control flow by removing redundant else clauses
- Added comprehensive test case (`t/t3903-stash.sh`) that creates a multi-repo scenario with distinct branches to verify the fix

The patch has undergone multiple review rounds with Junio C Hamano and others, incorporating all requested improvements around memory management, test coverage, indentation, and stylistic refinements. The test case demonstrates the fix by:
1. Creating separate superproject (`main_project`) and submodule (`sub_project`) repos
2. Establishing distinct branches in each (`work_branch` and `feature_sub`)
3. Verifying the stash message correctly shows the superproject's branch name

This represents the final polished version of the fix, having addressed all technical and stylistic feedback from the mailing list discussion. The patch is ready for integration with no outstanding issues.
