This is the second patch in a finalized 5-part series extending the promisor-remote protocol to support for configurable remote attribute validation. The patch implements server-side advertisement of additional fields beyond just name/url.

The key addition is a new `promisor.sendFields` config option that lets servers specify which remote attributes to advertise to clients. Currently only two fields are supported: `partialCloneFilter` (showing the remote's filter specification) and `token` (for authentication credentials). The implementation:
- Defines allowed field names in a static array with case-insensitive matching
- Adds configuration parsing for `promisor.sendFields`
- Extends the promisor_info struct to store filter/token values
- Modifies the protocol documentation to specify field ordering rules and encoding requirements
- Includes comprehensive tests verifying field transmission and URL encoding behavior

The patch builds on the structural foundation from patch 1 (which introduced promisor_info) and will be followed by client-side validation in patch 4. Documentation is thorough, with BNF notation for the protocol and clear explanations of field purposes. Test coverage verifies both happy paths and edge cases like unknown field handling.

All reviewer feedback from previous versions appears addressed, with cleanups to test cleanup handling and terminology standardization. The implementation maintains backward compatibility while providing the extension mechanism needed for future protocol additions.
