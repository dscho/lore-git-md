Bugfix in remote.c addressing a crash during repository teardown when handling uninitialized branch merge state. This is part 3/6 in Jacob Keller's series refactoring submodule remote lookup logic.

The patch fixes a subtle issue in `branch_release()` where the function would access `branch->merge` array without checking if it was initialized, assuming `merge_nr` being non-zero implied valid merge data. However, the remote state initialization path can create branches with non-zero `merge_nr` but NULL `merge` array, leading to crashes during repository cleanup. The fix adds a NULL check before accessing the merge array.

This is a preparatory change enabling safer submodule repository initialization where `read_config()` may create such partially-initialized branch states. The modification is minimal (adding a NULL check with proper array cleanup) and maintains existing behavior while preventing crashes. The commit message clearly explains the problematic state transition and how the fix addresses it, though the issue would only manifest in the upcoming submodule helper changes rather than current code paths.
