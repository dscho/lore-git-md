This is the third patch in a 5-part series enhancing the promisor-remote protocol with configurable validation of remote attributes. The series is now at version 4 with all major design points settled.

The patch refactors how advertised fields from promisor remotes are parsed, extracting the logic into a new `parse_one_advertised_remote()` function that populates a `struct promisor_info`. This prepares for upcoming additions that will parse more fields (like filters and tokens) from server advertisements. The changes include:

1. Moving field parsing into a dedicated function that returns a populated promisor_info struct
2. Simplifying memory management with a new `promisor_info_free()` helper
3. Updating `should_accept_remote()` to take the struct directly rather than individual fields
4. Cleaning up the main filtering logic to use the new parsing function

The refactoring maintains all existing behavior while making the code more maintainable for the planned extensions. The changes are straightforward and well-contained, with clear memory handling. This appears to be a solid preparatory step in the series, building on the structural improvements from earlier patches.
