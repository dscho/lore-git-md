This is patch 4/6 in a performance-oriented refactoring series addressing byte-order handling in Git's bswap.h, specifically focusing on making ntohl/ntohll macro behavior consistent across platforms.

The patch standardizes the definitions of ntohl/htonl/ntohll/htonll macros by always redefining them after determining system endianness, rather than having conditional definitions scattered through the file. On big-endian systems, these become no-ops (just returning the input value), while on little-endian systems they use either optimized bswap operations (when available) or fall back to default byte-swapping implementations. The changes create a more symmetrical setup where all four related macros follow the same pattern of definition.

Key technical points for future reference:
- Centralizes macro redefinitions after endianness detection (GIT_BYTE_ORDER)
- Maintains optimization paths via bswap32/bswap64 when available
- Uses default_swab32/default_bswap64 as the fallback implementations
- Affects network-to-host and host-to-network conversions for both 32-bit and 64-bit values
- Part of broader effort to fix big-endian system handling while maintaining performance

The changes are focused entirely on compat/bswap.h, with 26 lines added and 28 removed in a net simplification. This continues the series' pattern of carefully restructuring byte-swapping infrastructure while preserving optimization opportunities.
