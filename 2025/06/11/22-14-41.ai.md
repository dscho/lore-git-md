This is a refactoring patch that removes platform-specific optimizations for byte swapping operations on x86 architectures. The patch is part of a series (position 5/6) and follows up on compiler optimization analysis.

The author demonstrates through testing that modern compilers (GCC 4.5+, Clang 3.0+, and recent MSVC versions) can optimize the generic shift-based implementations of `default_swab32()` and `default_bswap64()` to use efficient CPU instructions automatically. The patch therefore removes the hand-optimized x86 assembly implementations from `compat/bswap.h`, leaving only the MSVC-specific path which uses compiler intrinsics.

Key technical details include:
- Removes 40 lines of x86-specific inline assembly code
- Keeps the MSVC intrinsic path for _byteswap_ulong/_byteswap_uint64
- Maintains the fallback to generic shift-based implementations
- Affects the `bswap32` and `bswap64` macros used throughout Git's codebase

The change appears well-motivated by compiler advancement evidence and simplifies the codebase by removing now-redundant optimizations. The commit message provides thorough compiler version testing results to justify the removal. This aligns with Git's general trend of relying more on compiler optimizations rather than hand-written assembly where possible.
