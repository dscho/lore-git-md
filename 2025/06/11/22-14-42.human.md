Performance refactoring in the byte-swapping infrastructure, part 5/6 of a series fixing endianness handling. This patch removes x86-specific inline assembly implementations of `bswap32` and `bswap64` in favor of letting modern compilers optimize the generic shift-based versions.

The author demonstrates through compiler version testing that current compilers (GCC 4.5+, Clang 3.0+, MSVC 19.20+) successfully optimize the shift operations into efficient machine code, making the hand-written assembly redundant. The patch simplifies the code by deleting 40 lines of x86-specific implementations while keeping the MSVC path that uses built-in functions.

This change continues the series' theme of cleaning up byte-order handling while maintaining performance. The commit message provides thorough evidence that the optimization is no longer needed, suggesting this is a well-considered simplification rather than a performance trade-off. The patch follows logically after the standardization work in patch 4/6.
