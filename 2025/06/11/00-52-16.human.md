Refactoring patch in the submodule remote lookup series, part 2/6. This change removes `the_repository` dependencies from several functions in remote.c to prepare for future use in submodule--helper. The patch modifies functions like `read_remotes_file()`, `read_branches_file()`, and `remotes_remote_get()` to accept a `struct repository*` parameter instead of directly using the global `the_repository`. This is infrastructure work that enables later patches to use these functions with submodule repositories.

The changes are mechanical but thorough, touching core remote-handling logic while maintaining existing behavior. The commit message clearly explains the motivation - these functions currently can't be used with non-default repositories, which blocks planned submodule functionality. While this patch doesn't yet expose the repository-aware versions to callers (that comes later in the series), it lays important groundwork by eliminating implicit global state dependencies in the remote lookup code.
