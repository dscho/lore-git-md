This is the first patch in a 5-part series enhancing the promisor-remote protocol with configurable validation of remote attributes. The series is now at v4 with all major design points settled.

Patch 1/5 refactors the internal data structures used by promisor-remote functionality, replacing the use of `struct strvec` with a new `struct promisor_info` stored in a `string_list`. The change provides better type safety and clearer field documentation while preparing for future protocol capabilities that will need to handle additional remote attributes beyond just names and URLs.

The patch introduces a clean abstraction where each promisor remote's information is stored in a dedicated struct with explicit members (`name` and `url`), rather than parallel string vectors. This makes the code more maintainable and self-documenting, especially as the series will later add more fields. The implementation includes proper memory management with a new `promisor_info_list_clear()` function.

This foundational change appears well-executed, with thorough updates to all affected code paths and no behavior changes. It's part of a mature series that has already gone through several rounds of review, with all previous feedback addressed. The patch stands on its own merits while clearly serving the larger goal of making the promisor-remote protocol more flexible and secure.
