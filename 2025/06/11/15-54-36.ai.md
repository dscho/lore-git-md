CI/Windows Coverity build fix series v2)

This is a two-patch series addressing Windows-specific Coverity build failures, following up on previous discussion in the thread. The core issue stems from DLL name conflicts between Coverity 2025.3 binaries and Git for Windows SDK, where Coverity's DLLs were incorrectly overriding system ones due to PATH ordering.

The first patch modifies the GitHub Actions workflow to append rather than prepend Coverity's bin directory to PATH, resolving the DLL conflict. Version 2 removes an unnecessary `cygpath` conversion that was flagged in review as non-portable, since `RUNNER_TEMP` already provides Unix-style paths in this context. The second patch (unchanged from v1) adds build log output on failure to aid debugging.

The changes are now properly confined to the CI configuration (`coverity.yml`) with no source code impact. The thread discussion has resolved all technical concerns, with Junio Hamano's portability questions addressed by removing the problematic `cygpath` call while maintaining the working PATH append solution. The series appears ready for merging, representing a straightforward fix to restore Windows Coverity builds without introducing new issues.
