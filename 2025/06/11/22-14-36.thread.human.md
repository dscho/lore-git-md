This thread focuses on modernizing Git's byte-order handling in `bswap.h`, addressing a regression on big-endian systems while improving performance. Sebastian Andrzej Siewior's six-patch series reverts a problematic change, updates endianness detection using `__BYTE_ORDER__`, fixes MSVC detection, standardizes swap functions, removes redundant x86 optimizations, and reintroduces built-in bswap support with compiler checks.

Brian m. carlson provided performance analysis showing modern compilers optimize shift-based swaps, and suggested optional support for C23's `<stdbit.h>` as a future enhancement. Collin Funk has now added to this discussion by noting POSIX.1-2024's `<endian.h>` as another emerging standard, though like C23, it's too new for immediate adoption. Both suggestions are informational - the core series remains focused on the current `__BYTE_ORDER__` approach while keeping the door open for future standards adoption. The discussion highlights the careful balance needed when updating platform-specific code to support both current and future compiler environments.
