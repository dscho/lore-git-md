Sebastian Andrzej Siewior's performance refactoring of Git's bswap.h has reached a holding pattern. The series addresses byte-order handling regressions on big-endian systems, with patch 1 already accepted as a critical fix for Git 2.50. This patch corrects incorrect ntohl() behavior that was particularly problematic on big-endian platforms.

The remaining patches (2-6), which focus on optimizations and modernization (including __BYTE_ORDER__ support and MSVC handling), are now in limbo. While technically sound, they've been deferred to Git 2.51 as they represent performance improvements rather than correctness fixes. Junio Hamano has marked the topic as "Stalled" in the development status report, as the author hasn't yet responded to accumulated feedback - including documentation typos spotted by Kristoffer Haugsbakk and performance analysis from Brian m. carlson showing compiler optimizations already handle many key cases.

The core technical work remains focused on compat/bswap.h, with the critical regression now resolved but the optimization-focused improvements awaiting the author's engagement to address remaining discussion points before they can progress further.
