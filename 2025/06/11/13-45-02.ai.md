This is the first patch in a 5-part series refactoring the promisor-remote protocol to support configurable validation of remote attributes. The series is now at v4 with all major design points settled.

The patch replaces the existing `struct strvec` implementation for storing promisor remote information with a new `struct promisor_info` that explicitly tracks name and URL fields. This provides better type safety and clearer field documentation compared to the previous generic string vector approach. The change prepares for future protocol additions by making the struct extensible for new fields while maintaining backward compatibility.

Key technical changes include:
- Introduces `struct promisor_info` with explicit `name` and `url` members
- Uses `string_list` to manage promisor_info instances with names as keys
- Adds `promisor_info_list_clear()` for proper memory cleanup
- Updates all related functions to use the new structure
- Maintains identical external behavior while improving internal type safety

The refactoring enables the subsequent patches in the series to cleanly add support for validating additional remote attributes like `partialCloneFilter` and `token`. The implementation follows the project's preference for explicit field handling over generic key-value stores when the field set is well-defined.

This foundational change has already undergone multiple rounds of review, with all feedback addressed in previous versions. The v4 iteration includes final refinements like standardized terminology and improved test cleanup.
