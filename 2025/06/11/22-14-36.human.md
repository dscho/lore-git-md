This is a refactoring series focused on improving byte-order handling in Git's bswap.h implementation. The series addresses issues with ntohl() macros on big-endian machines that were introduced by earlier optimizations.

The first patch reverts a problematic change that broke ntohl() on big-endian systems. Subsequent patches then systematically improve the situation by:
1. Adding proper __BYTE_ORDER__ support
2. Explicitly defining endianness for MSVC
3. Making ntohl/ntohll macros consistently available
4. Removing x86-specific optimizations that compilers now handle better
5. Providing built-in compiler versions where possible

The author notes that modern compilers are smart enough to optimize manual byte-swapping operations, making some of Git's custom optimizations redundant. However, they keep the optimized versions for musl libc compatibility and Windows' ntohll() implementation.

The changes are focused on the compat/bswap.h file, with significant code reduction (74 lines removed vs 44 added). The series appears well-motivated by real-world compiler behavior and platform compatibility needs, though the impact on performance would need to be measured across different platforms.
