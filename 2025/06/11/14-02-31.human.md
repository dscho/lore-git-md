This is a CI/build system patch that fixes Coverity scan builds on Windows. It's part of a 2-patch series (though we haven't seen the second patch yet).

The patch addresses a subtle but critical issue where Coverity's toolchain DLLs were interfering with Git for Windows SDK's compiler when the tools were placed at the start of PATH. The symptom was cryptic build failures where header files couldn't be found, ultimately caused by the wrong DLLs being found first in the search path.

Johannes Schindelin explains that while the current Azure Pipeline worked fine, it was based on older Coverity recommendations. The current documentation suggests putting the tools at the end of PATH instead, which this patch implements. The change is minimal - just moves the path addition from prefix to suffix position - but essential for successful Windows builds.

The patch appears well-motivated and clearly explains both the symptom and root cause, including sample error output. It follows current Coverity recommendations and maintains the existing functionality while fixing the Windows-specific issue. The change is low-risk as it only affects the Coverity CI workflow.
