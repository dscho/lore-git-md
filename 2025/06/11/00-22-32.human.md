This is a feature proposal for `git branch` that would enable batch repointing of branches to a new commit. The discussion has evolved from an initial `--force`-based approach to considering a new `--point-to` flag that would more precisely express the operation.

Junio C Hamano responds to Andrea Stacchiotti's proposal by suggesting an alternative approach: using `update-ref --stdin` instead of extending `git branch`. This brief comment implies that the existing plumbing command might already satisfy the use case without needing new porcelain functionality. The suggestion raises the question of whether this workflow belongs in the plumbing layer rather than as a user-facing branch operation.

The thread has been exploring how to best support GitOps workflows that need to efficiently manage multiple environment branches. While the original proposal focused on `git branch` extensions, Junio's response indicates a preference for leveraging existing low-level tools where possible. This could significantly simplify the implementation if `update-ref` proves sufficient.

The discussion remains open on whether the use case warrants new porcelain commands or can be adequately served by existing plumbing. The key tradeoff appears to be between user convenience (a dedicated `branch` subcommand) and maintaining command orthogonality (using separate tools for reference updates versus branch management).
