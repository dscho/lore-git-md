This is part 2 of a 5-patch series enhancing the promisor-remote protocol with configurable validation of remote attributes. The series is now at v4 with all major design points settled.

The current patch introduces server-side advertisement of additional remote attributes beyond just name and URL. It adds a new `promisor.sendFields` config that lets servers specify which extra fields to send (currently supporting `partialCloneFilter` and `token`). The fields are looked up in the remote's config and included in the protocol capability string if set.

The implementation is thorough, with:
- Field name validation against a whitelist
- URL encoding of values
- Documentation updates explaining the new capability format
- Tests verifying field transmission

This builds on the structural foundation from patch 1 and will be used by patch 4's client-side validation. The changes look well-considered, with clear documentation and test coverage. The patch appears ready for merging as part of the finalized series.
