Part 4/6 of the submodule remote lookup refactoring series, focusing on improving fallback remote name logic. This patch addresses how submodule--helper determines the default remote when the submodule is in a detached HEAD state, moving away from hardcoding "origin" as the fallback.

The key change introduces a new `repo_default_remote()` helper in remote.c that reuses the existing `remotes_remote_for_branch()` logic. This provides more robust fallback handling by first checking the branch's configured remote, then looking for a single remote, before finally falling back to "origin". The submodule--helper code is simplified to use this new helper rather than implementing its own similar-but-different logic.

The patch includes a new test case in t7406 that verifies the behavior works when a renamed remote exists in the submodule. While not a complete solution for all remote renaming scenarios, this improves the common case where users have renamed the default remote but not added additional remotes.

This continues the series' pattern of careful refactoring while maintaining behavior - the changes are preparatory for later URL-based remote lookup improvements. The patch touches remote.h, remote.c, submodule--helper.c, and adds test coverage, following the series' established pattern of moving functionality from submodule-specific code to more general remote-handling infrastructure.
