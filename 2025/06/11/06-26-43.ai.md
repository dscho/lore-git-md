Bugfix for mailmap handling in `git cat-file`. This patch addresses two related issues in the mailmap application logic when processing commit and tag objects where author and committer identities differ.

The core problem stems from incorrect newline handling in `apply_mailmap_to_header()`. The function fails to properly advance past newlines after processing identity lines, causing subsequent header parsing to fail. Additionally, it doesn't properly handle buffer reallocation that may occur during mailmap rewriting, potentially leading to invalid memory access.

The fix modifies `ident.c` to:
1. Properly skip newlines after processing each identity line
2. Recompute buffer pointers after potential reallocations during mailmap application

The patch includes two new test cases in `t4203-mailmap.sh` that verify correct behavior when:
- Only the committer needs mailmap translation
- Both author and committer identities require mapping

The changes are small but critical for correct mailmap functionality, particularly in scenarios where author and committer differ. The patch has been reviewed by Christian Couder and addresses a real-world issue reported by Vasilii Iakliushin. The test coverage appears thorough for the described bug.
