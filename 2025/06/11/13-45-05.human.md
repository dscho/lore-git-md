This is the 4/5 patch in a v4 series enhancing the promisor-remote protocol with configurable field validation. The series is now finalized with all major design points settled through review.

The patch introduces client-side validation of additional promisor-remote fields (partialCloneFilter and token) that were previously added to the protocol. A new `promisor.checkFields` config lets clients specify which fields to verify against local configuration before accepting a promisor remote. The validation ensures three conditions: local config must exist for the field, the server must advertise it, and values must match exactly.

The implementation handles case-insensitive field names but case-sensitive value matching. Documentation clearly explains the validation rules and use cases - ensuring filter consistency and verifying authentication tokens. Tests verify the new behavior works as expected while maintaining backward compatibility.
