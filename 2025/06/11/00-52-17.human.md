This is a bugfix patch in the ongoing submodule remote lookup refactoring series. It addresses a crash that can occur when tearing down a repository after initializing remote state for submodules.

The patch fixes an unsafe assumption in `branch_release()` where the function would access the `merge` array based on `merge_nr` being non-zero, without checking if `merge` was actually initialized. Jacob Keller explains that `merge_nr` can be set via `add_merge()` before `set_merge()` initializes the array, leading to crashes during repository teardown.

The change is straightforward - it adds a NULL check for `branch->merge` before attempting to clear and free the array. This makes the code robust against the case where `merge_nr` is non-zero but `merge` is NULL, which will occur in the upcoming submodule remote state initialization changes.

This is a necessary preparatory fix for the larger series, ensuring the infrastructure is solid before adding new functionality. The patch is small and focused, with a clear explanation of both the problem and solution. It maintains the series' high quality with careful attention to edge cases in the remote state handling code.
