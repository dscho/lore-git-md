This is part 4 of a 6-part series refactoring Git's submodule remote lookup logic. The patch improves how submodules determine their default remote name when in a detached HEAD state.

Currently, submodules in detached HEAD state always fall back to "origin" as the remote name, which can break for users who have changed their remote names. The patch reuses existing logic from `remotes_remote_for_branch()` that first checks for a configured remote, then falls back to the sole remote if only one exists, and only then uses "origin". This is exposed via a new `repo_default_remote()` helper function in remote.c.

The change is well-motivated and cleanly implemented, moving shared logic to a central location while maintaining the same behavior in most cases. It includes a new test case verifying the behavior works with renamed remotes. This continues the series' pattern of careful, incremental improvements to submodule remote handling.
