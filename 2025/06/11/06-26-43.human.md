Bugfix for `git cat-file --mailmap` handling of different author/committer identities.

This patch fixes two related issues in how `git cat-file --mailmap` processes commit and tag objects when the author and committer are different people. The main problem occurs in `apply_mailmap_to_header()` where the code fails to properly handle newlines after processing each identity line, causing it to miss the committer field when scanning the buffer. Additionally, the function wasn't properly handling cases where `rewrite_ident_line()` reallocates the buffer during operation.

The fix ensures mailmap transformations are correctly applied to both author and committer fields by properly advancing past newlines and recomputing buffer positions after potential reallocations. The patch includes new test cases that verify the fix works for commits where either just the committer needs mapping, or both author and committer need mapping.

The patch appears well-constructed with a clear commit message explaining both the problem and solution, and includes comprehensive test coverage. It has already been reviewed by Christian Couder and addresses a real issue reported by a GitLab user. This would be particularly relevant for projects that make heavy use of mailmap functionality with multiple contributors.
