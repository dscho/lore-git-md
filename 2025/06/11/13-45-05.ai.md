This is the 4th patch in a 5-part v4 series enhancing the promisor-remote protocol with configurable validation of remote attributes. The series is now finalized with all major design points settled through extensive discussion.

The patch implements client-side validation of advertised promisor-remote fields, building on the server-side advertisement capability added earlier in the series. It introduces a new `promisor.checkFields` configuration that lets clients verify specific field values (currently `partialCloneFilter` and `token`) match their expectations before accepting a promisor remote. The validation is strict - all specified fields must be present, locally configured, and have matching values (case-sensitive for values, case-insensitive for field names). The implementation handles both the `ACCEPT_ALL` and per-remote acceptance cases, integrating cleanly with the existing promisor-remote infrastructure.

Key technical details:
- Adds `fields_checked()` helper to parse the new config
- Implements `all_fields_match()` core validation logic
- Extends `should_accept_remote()` to incorporate field checks
- Documents validation rules and use cases in promisor.adoc
- Adds comprehensive tests verifying field matching behavior
- Maintains backward compatibility when checkFields isn't set
- Integrates with existing promisor_info struct and parsing logic

The patch follows the series' established patterns for field handling and builds on the refactored parsing infrastructure from patch 3. Test coverage verifies both successful matches and rejection cases, including URL encoding behavior. Documentation clearly explains the validation rules and interaction with other promisor-remote configurations.
