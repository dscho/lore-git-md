This is a follow-up feature patch extending the new `--compact-summary` functionality for `git merge` and `git pull` to be configurable via `merge.stat`. The patch comes from maintainer Junio Hamano as part 2 of the series, though it's numbered "2/1" to indicate it builds on the initial standalone implementation.

The change makes `merge.stat` accept either a boolean (maintaining backward compatibility) or the new "compact" string value to enable the condensed summary format showing `(new)`/`(gone)` annotations. The implementation handles all three cases (false/nothing, true/regular diffstat, compact/summary) through a new config parser switch in merge.c, with corresponding test coverage.

This addresses the architectural question raised earlier in the thread about configuration options versus command-line flags, opting to extend the existing `merge.stat` mechanism rather than introduce new config variables. The patch maintains clean backward compatibility while providing the new functionality through a natural extension of the existing interface.

The implementation looks solid with thorough documentation updates and a new test case verifying the config-driven behavior matches the command-line `--compact-summary` option. This completes the feature by making the compact summary format available as both a runtime option and persistent configuration setting.
