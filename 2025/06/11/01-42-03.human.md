Bugfix for `git stash` branch name corruption in submodule contexts. This is the final version of a patch that fixes an issue where stashing changes in a superproject would incorrectly show the submodule's branch name in the stash message rather than the superproject's branch.

The root cause was buffer reuse in `refs_resolve_ref_unsafe()` - when resolving branch names in sequence (first superproject, then submodule), the static buffer would get overwritten. The solution uses `xstrdup()` to preserve the superproject's branch name before any submodule operations occur. The patch includes proper memory management with a corresponding `free()` and adds a comprehensive test case that verifies the fix works in multi-repo scenarios.

This version incorporates all feedback from multiple review rounds, including:
- Memory management fixes
- Test improvements (removed `-q` flags, better test structure)
- Stylistic refinements (indentation, control flow simplification)
- A clearer test title ("submodules does not affect the branch recorded in stash message")

The patch has received maintainer approval after addressing all technical and stylistic concerns. It cleanly solves the reported issue while maintaining the existing "(no branch)" fallback behavior. The test case provides good coverage scenario for this edge case in submodule workflows.
