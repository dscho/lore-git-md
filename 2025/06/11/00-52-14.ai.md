This is a refactoring and improvement series for Git's submodule remote lookup logic. The patch series consists of 6 parts that progressively enhance how Git determines the default remote for submodules, with some preparatory cleanups first.

The series begins with some infrastructure work: moving helper functions to a shared header (dir.h), making remote.c functions repository-aware, and fixing a potential NULL dereference in branch_release(). These changes enable the subsequent submodule improvements.

The core changes refactor the remote lookup logic in submodule--helper.c to use new helpers in remote.c. The key improvement is having Git first try to match submodule remotes by their configured URL (from the parent project's config) before falling back to the previous behavior of checking the branch's remote or defaulting to "origin". This makes the system more robust against remote renames and multiple remotes.

The changes touch several key files: dir.h gets new shared utilities, remote.c gains repository-aware versions of its functions plus the new URL-based lookup, and submodule--helper.c sees significant logic changes. The series includes new tests in t7406 to verify the improved behavior.

This appears to be a well-structured series that addresses a real pain point in submodule remote handling. The commit messages clearly explain the motivation and approach, and the changes are accompanied by test coverage. The refactoring steps are logically ordered, with each patch building on the last. The URL-based lookup in particular seems like a sensible default that should reduce configuration headaches for submodule users.
