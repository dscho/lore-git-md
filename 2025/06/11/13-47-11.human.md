This is a refactoring patch that's part of a completed 5-patch series enhancing the promisor-remote protocol. The series adds configurable validation of remote attributes during clone/fetch operations.

This particular patch responds to Junio Hamano's feedback from v3, replacing a custom linked list implementation with Git's standard `string_list` type for managing promisor remote information. The new implementation uses the remote nickname as the key and stores a pointer to the promisor_info struct as the value. The string_list is kept sorted when beneficial for lookups.

The change improves code maintainability by using a more familiar data structure that's well-tested in the codebase. The patch also renames `remote_nick_find()` to the more accurate `promisor_info_find()` to better reflect its purpose.

As part of the finalized v4 series, this patch has already addressed all review feedback and appears ready for merging. The series as a whole enhances protocol security while maintaining backward compatibility, with comprehensive test coverage and documentation.
