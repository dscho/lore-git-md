Platform compatibility patch adding support for `__BYTE_ORDER__` in `bswap.h`. This is part of a 6-patch series (position 2/6) though we haven't seen the cover letter to understand the broader context.

The change adds a fallback path for determining byte order when the traditional `BYTE_ORDER` macros aren't available, which happens on some platforms like mingw. The new code checks for compiler-provided `__BYTE_ORDER__` (supported by gcc, clang, and icc but not MSVC) and uses that to define Git's internal byte order constants.

The patch is straightforward and appears well-motivated - it clearly identifies the platforms that will benefit and notes where the feature isn't available (MSVC). The implementation is a simple addition to the existing conditional logic in the header file. This looks like a solid incremental improvement to platform compatibility.
