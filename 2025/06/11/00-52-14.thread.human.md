This thread documents a 6-part series refactoring Git's submodule remote lookup logic. The work began with infrastructure improvements - consolidating helper functions and removing `the_repository` dependencies. Subsequent patches fixed a branch teardown crash and improved fallback logic when submodules are in detached HEAD state, moving away from hardcoding "origin" as the default remote.

The final patch introduces URL-based remote matching as the primary lookup method before falling back to existing heuristics. It adds a new `repo_remote_from_url()` helper that scans a repository's remotes to find one matching a given URL, addressing cases where users rename their default remote (e.g., via `clone.defaultRemoteName`). The implementation maintains all existing fallback paths for backward compatibility while providing more robust handling of renamed remotes and relative URLs.

The series touches multiple subsystems (dir.h, remote.c, submodule--helper.c) and includes comprehensive test coverage in t7406. It represents a significant improvement to submodule remote handling, building carefully from infrastructure work through to the new URL-based resolution logic while preserving backward compatibility.
