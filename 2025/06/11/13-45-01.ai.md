This is a v4 cover letter for a completed 5-patch series extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series has undergone extensive review and all major design points are settled.

The core enhancement allows servers to advertise additional remote fields (currently "partialCloneFilter" and "token") via a new `promisor.sendFields` config, while clients can validate these fields using `promisor.checkFields`. This provides better security and consistency between server-advertised and client-configured remote attributes.

Key technical changes in v4:
- Replaced the `struct strvec` approach with `struct promisor_info` stored in a `string_list` per Junio's suggestion
- Improved documentation formatting with bullet points
- Added `string_list_remove_empty_items()` to handle empty fields
- Switched to `test_config` for cleaner test cleanup
- Standardized terminology to use "field name" consistently
- Patch 1 refactors the internal data structures
- Patch 2 implements server-side field advertisement
- Patch 3 improves advertised field parsing
- Patch 4 adds client-side field validation
- Patch 5 introduces string constants for field names

The series builds on existing promisor-remote infrastructure and aligns with broader codebase efforts to improve type safety. All reviewer feedback from Patrick Steinhardt, Karthik Nayak, and Junio Hamano has been addressed across previous iterations. CI tests are passing. This appears ready for final review and merging.
