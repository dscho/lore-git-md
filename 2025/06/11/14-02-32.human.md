This is a CI/build system patch that makes Coverity Scan's error output more useful when the analysis fails. 

The patch modifies GitHub's Coverity workflow to show the full build log when `cov-build` fails. Currently, the workflow silently fails without showing what went wrong, making debugging difficult. The change simply adds error handling that dumps `cov-int/build-log.txt` before exiting when the build fails.

This is a straightforward quality-of-life improvement for maintainers. The change is small and focused, with a clear motivation stated in the commit message. It's part of ongoing CI maintenance work rather than a larger initiative. The patch fails the build explicitly after showing the log, maintaining the existing error behavior while adding visibility.

The change touches only the Coverity-specific workflow file and doesn't affect any other part of Git's infrastructure. It follows the pattern of other CI improvements where build failures are made more debuggable by showing relevant logs.
