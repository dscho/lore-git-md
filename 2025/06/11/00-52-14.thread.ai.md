Refactoring and improving Git's submodule remote lookup logic through a 6-part series. The changes begin with infrastructure work: moving helper functions to dir.h (starts_with_dot_slash() and starts_with_dot_dot_slash() helpers consolidated from submodule--helper.c and submodule-config.c into dir.h as static inline functions with PATH_MATCH_XPLATFORM support). Part 2 focuses on removing `the_repository` dependencies from remote.c functions, converting `read_remotes_file()`, `read_branches_file()`, `remotes_remote_get_1()`, and related functions to accept a `struct repository*` parameter instead of using the global `the_repository`. This makes them usable in submodule contexts needing to operate on non-default repositories. The modifications are mechanical but important for enabling future work where submodule code needs to query remote information from different repository contexts. Core improvements will follow to refactor submodule--helper.c to use new remote.c helpers, introducing URL-based remote matching (checking parent project's submodule config before falling back to branch remote or "origin"). Touches dir.h, remote.c, submodule--helper.c, submodule-config.c, with new tests in t7406. The series is well-structured with clear commit messages and logical progression from preparatory changes (helper consolidation and repository-awareness) to URL-based lookup enhancement. No behavior changes in these initial patches - purely code organization to enable later functionality.
