Refactoring and improving Git's submodule remote lookup logic through a 6-part series, addressing memory leaks and architectural organization of remote name fallback implementation. The series progresses from infrastructure cleanups to URL-based remote matching enhancement, with all technical revisions complete except for final verification of memory leak fixes.

Core changes include consolidating helper functions in dir.h, removing `the_repository` dependencies from remote.c, fixing `branch_release()` crashes, and improving fallback remote logic via new `repo_default_remote()` helper. Part 6 introduces URL-based remote matching through `repo_remote_from_url()`, which Junio C Hamano's CI testing revealed had memory leaks in config parsing paths during submodule operations with invalid commits (1049 bytes across 6 objects in test t1013-read-tree-submodule.sh #52).

Jacob Keller's follow-up addresses memory management gaps in `branch_release()` and `remote_clear()` discovered when properly enabling LeakSanitizer detection. While these fixes target repository teardown paths related to the reported leaks, verification is needed to confirm they fully cover the original leak scenarios in `repo_remote_from_url()`'s error paths during config parsing (`read_config()`, `refspec_append()`, and `add_merge()` allocations).

Technical details:
- New `repo_remote_from_url()` with URL matching capability (leak fixes in progress)
- Modified `repo_get_default_remote()` with new `const char *url` parameter
- Consolidated path helpers in dir.h (starts_with_dot_slash/dot_dot_slash)
- Tests in t7406 for renamed/multiple remote scenarios
- Changes span dir.h, remote.c, submodule--helper.c, submodule-config.c

Architectural decisions are settled:
- `repo_default_remote()` remains in remote.c for generic remote logic
- `repo_get_default_remote()` stays in submodule--helper.c for submodule cases
- This separation supports future enhancements while maintaining clear boundaries
