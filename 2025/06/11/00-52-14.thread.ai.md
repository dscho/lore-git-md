Refactoring and improving Git's submodule remote lookup logic through a 6-part series, now addressing critical memory leaks discovered during integration testing. The series progresses from infrastructure cleanups to URL-based remote matching enhancement, with all technical revisions for repository parameterization, crash fixes, and build system corrections complete except for newly identified memory management issues.

Core changes include preparatory work moving helper functions to dir.h (starts_with_dot_slash() and starts_with_dot_dot_slash() consolidated from submodule--helper.c and submodule-config.c into dir.h as static inline functions with PATH_MATCH_XPLATFORM support). Part 2 removes `the_repository` dependencies from remote.c functions, converting several functions to accept explicit `struct repository*` parameters. Part 3 fixes a crash in `branch_release()` during repository teardown when handling uninitialized branch merge state. Part 4 improves fallback remote name logic for submodules in detached HEAD state via new `repo_default_remote()` helper in remote.c, replacing hardcoded "origin" fallback with configuration-aware logic.

The key change in part 6 introduces URL-based remote matching via new `repo_remote_from_url()` helper before falling back to existing heuristics, modifying `repo_get_default_remote()` to accept optional URL parameter. However, Junio C Hamano's CI testing revealed memory leaks in this new path when running under LeakSanitizer, specifically in test t1013-read-tree-submodule.sh #52, showing 1049 bytes across 6 objects leaked through `repo_remote_from_url()`'s config parsing path (`read_config()`, `refspec_append()`, and `add_merge()` allocations via `xrealloc`, `xstrdup`, and `xstrndup`). The leaks occur during submodule update operations when resetting to invalid commits, indicating missing cleanup in error paths of the remote configuration handling - a real-world scenario making this a blocking issue.

Technical details:
- New `repo_remote_from_url()` scans `repo->remote_state->remotes` for URL matches but leaks config allocations
- Modified `repo_get_default_remote()` signature adds `const char *url` parameter
- `get_default_remote_submodule()` resolves relative URLs when needed
- Tests in t7406 verify renamed/multiple remote scenarios
- Changes span dir.h, remote.c, submodule--helper.c, submodule-config.c
- LeakSanitizer reports show config parsing allocations not freed during error conditions

The series was previously ready for resubmission after release freeze, but must now address these memory leaks first. The CI failure provides concrete reproduction details via GitHub Actions logs, with leaks occurring in both test and real-world submodule update scenarios when handling invalid commits. Lidong Yan had earlier suggested considering inlining `repo_default_remote()` into `repo_get_default_remote()`, but this remains an open design question separate from the memory management issue. The build system correction to patch 4/6 (adding missing `struct repository` forward declaration in `remote.h`) remains valid and necessary for `make hdr-check` compliance.
