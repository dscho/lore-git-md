This is part 2 of a 6-part series refactoring Git's submodule remote lookup logic, specifically focusing on removing `the_repository` dependencies from remote.c functions. The patch modifies several internal functions in remote.c to accept a `struct repository*` parameter instead of directly using the global `the_repository`, making them usable in contexts that need to operate on non-default repositories (like submodules).

Key changes include converting `read_remotes_file()`, `read_branches_file()`, `remotes_remote_get_1()`, and related functions to take a repository parameter. The modifications are mechanical but important for enabling future work where submodule code needs to query remote information from different repository contexts. The patch maintains existing behavior while removing implicit global state dependencies.

This is a preparatory change for later patches in the series that will introduce URL-based remote matching for submodules. The changes are focused and well-contained, with clear commit messages explaining the motivation. The diff shows careful attention to repository parameter passing while preserving all existing functionality.
