This is a refactoring and improvement series for Git's submodule remote lookup logic. Jacob Keller proposes several changes to make submodule remote handling more robust, particularly when remotes have been renamed or when multiple remotes exist.

The series starts with some preparatory cleanups: moving helper functions to a shared header, making remote functions work with submodule repositories, and fixing a potential NULL dereference in branch handling. The core improvement comes in two parts. First, the submodule remote lookup logic is refactored to try finding remotes based on the checked-out branch, then falling back to a single remote or "origin". Then, a more sophisticated approach is added that first tries to match remotes by their URL (as stored in the parent repository's config) before falling back to the previous logic.

The changes appear well-motivated, addressing real pain points in submodule remote handling. The commit messages are detailed and the series includes test updates to verify the new behavior. This looks like a solid improvement to submodule functionality that should make remote operations more reliable, especially in complex scenarios with renamed remotes. The changes touch several files but appear focused and maintainable.
