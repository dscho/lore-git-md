This is the third patch in a v4 series enhancing the promisor-remote protocol with configurable validation of remote attributes. The patch focuses on refactoring the parsing logic for advertised fields from promisor servers.

The key change extracts the field parsing code into a new `parse_one_advertised_remote()` function that populates a `struct promisor_info` with parsed name and URL values. This prepares for future addition of more fields (like filter and token) while making the code more maintainable. The patch also modifies `should_accept_remote()` to take the full promisor_info struct rather than individual name/url strings.

Technical improvements include:
- New `promisor_info_free()` helper for consistent cleanup
- More robust error handling for malformed remote info
- URL decoding moved into the parsing function
- Cleaner memory management through centralized freeing
- The changes maintain all existing functionality while making the codebase more extensible for the planned filter and token support in subsequent patches.
