This is a bug report about unexpected behavior during an interrupted rebase. Grant Birchmeier reports that `git checkout -b` (create and switch to new branch) succeeds while in the middle of a rebase, when it should fail like a regular `git checkout` would in this state.

The key issue is that creating a new branch from` the mid-rebase state leaves the original branch ("ilogger") in an unrecoverable state - the user cannot switch back to it and must complete the rebase on the new branch ("net5") instead. This contradicts the expected behavior where Git should prevent branch operations that could corrupt an in-progress rebase.

The report is clear and reproducible, showing a real inconsistency in Git's handling of interrupted operations. This appears to be a legitimate bug in the rebase state detection logic that fails to account for branch creation during an active rebase. The behavior difference between `git checkout` and `git checkout -b` suggests the check for rebase state is being bypassed in the branch creation case.
