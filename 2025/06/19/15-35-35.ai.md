This is a build system patch proposing a change to the Coccinelle checking infrastructure. The patch makes `make coccicheck` fail when the semantic patches suggest any changes, rather than silently succeeding while generating patch files.

Currently, when developers run `make coccicheck`, it generates patch files in contrib/coccinelle/ with suggested changes from the semantic patches, but the make command still exits successfully even if changes are suggested. This makes it easy to miss when Coccinelle finds potential improvements. The patch modifies the Makefile to explicitly check that the generated patch files are empty (using `test -s` and `wc -c`), causing make to fail if any changes were suggested.

The change affects both the case where all Coccinelle rules are processed together (SPATCH_CONCAT_COCCI) and when they're processed individually. The implementation is straightforward - just adding two test commands to verify the patch files are empty. This should help surface potential code improvements that might otherwise go unnoticed since developers would now have to address the suggested changes before the command succeeds.
