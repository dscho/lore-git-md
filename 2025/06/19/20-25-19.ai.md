This is a follow-up discussion about the ongoing experiment with the `RemoveBracesLLVM` clang-format rule, which removes braces from single-statement conditional bodies. The thread examines whether to promote this from CI-only testing to Git's main `.clang-format` configuration.

Karthik Nayak responds to Junio Hamano's inquiry about moving the experimental rule into the main configuration. He reports that while discussing clang-format with Christian Couder, they identified at least one case where the rule produces undesirable formatting - in `builtin/receive-pack.c`, it removes braces from a `for` loop that should arguably keep them for clarity. This confirms the original concern about clang-format's limited semantic analysis leading to incorrect formatting.

Regarding adoption patterns, Karthik notes that contributors rarely use `git clang-format` before submission due to the high rate of false positives in the current configuration. This suggests limited real-world testing of the experimental rule outside CI. The technical implementation remains unchanged from the original patch - the rule is still applied via a temporary `/tmp/clang-format-rules` file that combines the main configuration with the experimental `RemoveBracesLLVM: true` setting.

Key points for future discussion tracking:
- Concrete example of problematic formatting found in `builtin/receive-pack.c`
- Low contributor adoption of `git clang-format` in practice
- The rule continues to use the same temporary file mechanism from the original patch
- Maintainer's original concerns about semantic analysis limitations appear validated

The discussion suggests the rule may not yet be ready for main configuration inclusion, though the CI experiment has successfully identified both the rule's limitations and adoption challenges.
