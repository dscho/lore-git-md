This is a discussion about the output ordering implications of Phil Hord's performance optimization for `git fetch --prune`. Jeff King (peff) responds to Jacob Keller's earlier comment about the output ordering changes in the patch series.

The key points raised:
- Jeff explains the original output ordering had semantic value by showing which deletion caused each ref to become dangling, using a more realistic example with `origin/HEAD`
- He acknowledges the current dangling messages have existed for 15 years but aren't widely known/used
- Proposes two alternative solutions if preserving the ordering is desired:
  1. Two-pass approach to maintain deletion-to-dangling relationship
  2. Modified message format that includes the deleted target (e.g. "points to now-deleted origin/main")
- Ultimately seems ambivalent about the change, suggesting users who need the info can query it manually

This discussion follows Jacob Keller's review approval of the first patch and Junio's positive reaction to the second.
