This thread discusses a build system improvement to make `make coccicheck` fail when Coccinelle suggests code changes, rather than silently succeeding while generating patch files. The original patch modified the Makefile to check for non-empty patch files, with Jeff King (Peff) and Carlo Arenas Belón supporting the change while discussing shell syntax details (`=` vs `-eq` for numeric comparisons).

Eric Sunshine then pointed to Junio Hamano's historical preference for `=` in such tests. Junio has now weighed in directly, confirming his preference for `=` while suggesting an even better approach using `grep -q` to check for non-empty files - this would be more efficient than counting bytes with `wc -c` since it can short-circuit after finding the first non-empty file. The discussion has progressed from the core idea (which has consensus) to increasingly refined implementation details, with the maintainer now providing both stylistic guidance and a technical optimization. The thread appears to be converging on a solution that combines the original goal with Junio's suggested improvements.
