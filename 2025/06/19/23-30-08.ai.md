This is a refactoring patch that standardizes incompatible option handling in `pack-objects`. It's the first in a 9-part series optimizing MIDX and cruft pack interactions during repacking.

The patch replaces several ad-hoc checks for mutually incompatible command-line options with calls to the standard `die_for_incompatible_opt2()` function. This change:
- Simplifies the code by removing custom error messages
- Makes error output consistent across different incompatible option pairs
- Updates one test that expected the old error message format

The changes affect option pairs like `--exclude-promisor-objects`/`--exclude-promisor-objects-best-effort`, `--keep-unreachable`/`--unpack-unreachable`, and `--stdin-packs`/`--filter`. The behavior remains the same - these options still can't be used together - but now fail with standardized error messages.

This foundational change enables later patches in the series to build on this standardized error handling. The test update in t5331-pack-objects-stdin.sh shows the new error format while maintaining the same semantic check. The patch is straightforward with no apparent controversy, serving as clean groundwork for the more substantial optimizations that follow in the series.
