This is a refactoring patch that's part of a completed 5-patch series enhancing the promisor-remote protocol. The series adds configurable validation of remote attributes during clone/fetch operations.

Patch 1/5 (this email) restructures the internal data representation for promisor remotes, replacing a custom linked list with a more maintainable `struct promisor_info` and `string_list` combination. Christian Couder provides a review noting the patch looks good but suggests the commit message could better explain why the current `strvec` approach doesn't scale well for future protocol extensions.

The refactoring introduces explicit type safety by storing name and URL in dedicated struct members rather than generic string arrays, making the code more maintainable as new fields are added. This foundational change enables the subsequent patches in the series to add field validation capabilities while maintaining backward compatibility.

The series has already gone through extensive review (v4) with all major design points settled, and this particular refactoring was suggested by Junio Hamano. The patch appears ready for merging as part of the complete series.
