This is a discussion about the output ordering implications of Phil Hord's performance optimization for `git fetch --prune`. Jeff King (Peff) responds to Jacob Keller's earlier comment about the changed output format.

Peff points out that the current interleaved output (where dangling messages appear immediately after the deletion that caused them) provides useful context about which deletion triggered each dangling state. He provides a concrete example showing how deleting `origin/main` makes `origin/HEAD` dangle, which is clearer in the current output format.

However, Peff acknowledges this isn't critical functionality - he wasn't even aware of these dangling messages before, despite them existing for 15 years. He suggests two potential ways to preserve the information if needed: (1) a two-pass approach to reconstruct the relationship, or (2) modifying the dangling message to explicitly state what the symref pointed to before deletion. But he concludes that users who really need this information can always check with `git symbolic-ref` themselves.

The discussion shows general approval for the performance improvement while exploring edge cases around output formatting. Peff's technical analysis confirms the optimization is sound, and his pragmatic conclusion suggests the output ordering change is likely acceptable despite the minor information loss.
