Performance optimization for pack-objects delta compression. This is part 5/9 of Taylor Blau's series improving MIDX and cruft pack interactions during repacking.

The patch fixes an oversight in how `--unpacked` mode handles loose objects during delta compression. Previously, loose objects weren't included in the name-hash traversal used to find good delta candidates, which could result in suboptimal delta compression. The change passes the `rev_info` struct to the loose object handling code so these objects can participate in the traversal.

While this doesn't affect the correctness of the resulting pack (objects still get packed), it should produce slightly more efficient packs by finding better delta relationships. Junio Hamano has already praised this optimization in earlier reviews. The change is a natural extension of the refactoring done in patches 3/9 and 4/9, moving the `rev_info` struct to be more widely accessible.

The implementation is straightforward - modifying the loose object callback to optionally add commits to the revision walk when a `rev_info` struct is provided. All callers are updated to pass either NULL or the appropriate `rev_info`. This patch continues the series' trend of careful, production-validated improvements to Git's packing behavior.
