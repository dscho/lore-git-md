This is a feature patch improving signature handling in Git's fast-export/fast-import, part of an ongoing thread about supporting multiple signature formats and hash algorithms. The patch builds on previous iterations (v1-v3) to enhance the signature output format while maintaining backward compatibility.

The key changes in v4:
- Introduces a new "gpgsig <hash-algo> <format>" syntax where format can be "openpgp", "x509", "ssh" or "unknown"
- Supports exporting/importing both SHA-1 and SHA-256 signatures from the same commit
- Adds warnings when multiple signatures are found for the same hash type
- Documents the new format in fast-export/fast-import man pages
- Includes test cases for X.509 and SSH signatures (though still lacks dual-signature test)

Technical implementation details:
- New gpg-interface helpers: get_signature_format(), valid_signature_format()
- Signature storage in fast-import tracks both algorithm and format
- Warning system for multiple signatures per hash type
- Maintains experimental status in documentation
- Test coverage for OpenPGP/X.509/SSH formats (t9350)

The patch fixes test issues from v3 related to SHA-256 object format handling. It follows the approach from v1 (adding format info to gpgsig command) while incorporating lessons from v2's exploration of signature checking. The author notes remaining work needed for testing commits with both SHA-1 and SHA-256 signatures.

This continues the thread's progression from policy discussions to implementation, with all CI tests now passing. The changes maintain backward compatibility while adding the promised signature format support, though the experimental warnings remain as the feature matures.
