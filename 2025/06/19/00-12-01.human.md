This is a bug report about unexpected behavior during an interrupted rebase. Grant Birchmeier reports that Git allowed creating and switching to a new branch with `git checkout -b` while in the middle of a rebase, which they argue should be prevented just like a regular `git checkout` would be in this situation.

The issue occurs when attempting to create a new branch (`net5`) from a branch (`ilogger`) that's mid-rebase. While Git normally prevents switching branches during a rebase, the `-b` flag appears to bypass this protection. This leaves the user in an awkward state where they can't return to the original rebase branch and must complete the rebase on the newly created branch instead.

The report is clear and provides straightforward reproduction steps. The behavior does seem inconsistent with Git's usual protections around interrupted operations. This could potentially cause data loss or confusion for users who accidentally create branches during rebases.

The report doesn't suggest a specific fix but clearly documents the discrepancy between expected and actual behavior. This looks like a legitimate issue that maintainers would want to address to maintain consistent safeguards during operations that modify repository state.
