This thread examines an inconsistency in Git's behavior where `git checkout -b` succeeds during a rebase while a regular `git checkout` would fail, potentially leaving the original branch in an unrecoverable state without workarounds. Grant Birchmeier reported the issue, noting that creating a new branch mid-rebase caused problems with the original "ilogger" branch. Jacob Keller provided effective recovery methods (using `git rebase --abort` and `git reflog`), though they require sacrificing partially completed rebase work. Phil Hord observed that both branches would eventually point to the rebased tip, but Grant questioned whether this justifies the inconsistent behavior.

While not directly addressing the core issue, this reinforces concerns about rebase's current behavior leading to user errors.
