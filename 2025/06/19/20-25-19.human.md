This is a follow-up discussion about the experimental `RemoveBracesLLVM` clang-format rule, part of the ongoing evaluation of whether to promote it from CI-only testing to Git's main formatting configuration.

Karthik Nayak responds to Junio Hamano's inquiry about whether the experimental period has provided enough confidence to move the rule into the main `.clang-format` file. While Nayak expresses general optimism about the rule's safety, he identifies a specific case in `builtin/receive-pack.c` where the rule incorrectly suggests removing braces that Git's style generally keeps - a `for` loop containing multiple conditionally-assigned statements.

The exchange reveals two key insights: First, that the rule still produces some undesirable formatting changes despite the experimental period. Second, that contributors rarely use `git clang-format` before submission due to existing false positives. This suggests the CI-based testing may not have caught as many edge cases as hoped.

Nayak's original implementation (from v6 patch) used a temporary `/tmp/clang-format-rules` file to test the brace-removal rule without affecting users' local configurations. The current discussion shows this experimental approach successfully identified at least one problematic case, though it remains unclear whether this represents an isolated incident or a broader pattern.
