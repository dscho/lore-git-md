This is the final patch (9/9) in Taylor Blau's performance optimization series for MIDX and cruft pack interaction during repacking. The patch introduces a new config option `repack.midxMustContainCruft` (defaulting to true) that allows excluding cruft packs from the MIDX when they aren't needed for reachability guarantees.

The key technical change is that when the config is false and packs are generated with `--stdin-packs=follow`, Git can avoid including cruft packs in the MIDX if it can verify that all reachable objects are already covered by other packs. This reduces MIDX bloat and improves lookup performance since cruft packs typically contain many rarely-accessed objects. The patch includes extensive logic to determine when it's safe to exclude cruft packs, handling edge cases like no-op repacks where existing packs might still depend on cruft objects.

The implementation adds a `midx_has_unknown_packs()` helper to check if any existing MIDX packs won't be represented in the new MIDX, requiring cruft pack inclusion for safety. The patch also adds comprehensive tests in t7704-repack-cruft.sh covering various scenarios: when exclusion is possible, when forced inclusion is requested, and when geometric repacking encounters edge cases.

This completes the series' goal of optimizing pack maintenance by reducing unnecessary cruft pack inclusion in MIDX files while maintaining correctness. The production-validated changes show 5-20% speed improvements, with all edge cases addressed through the v1-v5 iteration process.
