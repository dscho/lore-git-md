This is a build system patch that changes how `make coccicheck` behaves. Currently, the Coccinelle semantic patch checker runs and generates suggested fixes in `.patch` files, but the `make` command still exits successfully even when there are suggested changes. Junio Hamano proposes making `make coccicheck` fail when the Coccinelle checker finds issues that need fixing, which would make it harder for developers to accidentally ignore its output.

The patch modifies the Makefile to check whether the generated patch files are empty (using `test -s` and `wc -c`), failing the build if they contain any content. This is a straightforward change that aligns with Git's general philosophy of surfacing potential issues rather than silently continuing. Since Coccinelle checks are already part of Git's CI pipeline, this change would make local development behavior match what happens in automated testing.
