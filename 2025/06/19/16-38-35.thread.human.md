This thread examines Git's use of `clang-format` for code formatting, sparked by Junio Hamano's analysis showing the tool produces mixed results - some helpful alignments but also disruptive changes, particularly in signature handling and fast-import/export code. Christian Couder and others confirmed many outputs are false positives, with line wrapping emerging as the most problematic area.

The discussion has crystallized around several key positions: Brian m. carlson advocates for comprehensive standardization (similar to Rust/Go's strict formatting), while Karthik Nayak and Christian Couder favor a more surgical approach that preserves human judgment, especially for line wrapping. Jeff King proposed a practical middle ground using `git rebase -x` with `clang-format`, which Junio endorsed while acknowledging the tool's limitations.

In the latest exchange, Karthik responds to Junio's conditional approval of either refining or removing line wrapping rules, agreeing that complete removal from `clang-format` (while potentially handling it via `.editorconfig`) may be the most practical solution. Karthik plans to send patches implementing this change, moving the discussion from theory to concrete action. The core tension remains between automation benefits and readability concerns, with line wrapping proving particularly resistant to satisfactory automated handling.
