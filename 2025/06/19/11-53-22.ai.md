This is a refactoring patch (1/5) in a completed series enhancing the promisor-remote protocol. The email contains Christian Couder's review of Karthik Nayak's patch that replaces the previous `struct strvec` implementation with a more scalable `struct promisor_info` approach.

The key technical change in this patch is the introduction of `struct promisor_info` with explicit `name` and `url` members, stored in a `string_list` (replacing the custom linked list as suggested by Junio Hamano). This provides better type safety and prepares for future protocol extensions by making it easier to add new fields. The review confirms the approach but suggests the commit message could better explain why the old `strvec` approach didn't scale well.

This patch was part of the v4 series that has already addressed all major review feedback, with all implementation details finalized. The series as a whole adds configurable validation of remote attributes (partialCloneFilter and token) during clone/fetch operations while maintaining backward compatibility. This particular patch lays the structural foundation for those later protocol enhancements.
