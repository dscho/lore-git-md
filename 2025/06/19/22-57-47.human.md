This is the third patch in a series introducing the new `git repo-info` command, adding plaintext output format support. The patch adds a `FORMAT_PLAINTEXT` option alongside the existing JSON format, though the actual content output is just a placeholder for now returning empty output. The implementation follows the same pattern as the JSON format, with format detection, a print function stub, and a basic test case that verifies empty output.

The plaintext format will eventually output key-value pairs (like `layout.bare=true`) but this initial patch just establishes the scaffolding. The test infrastructure from the previous patches is extended with a new test case that checks the empty output behavior for plaintext format, similar to the existing JSON test.

This continues the careful, incremental approach seen in earlier patches, with clean separation of format handling and matching test coverage. The patch is part of a mentored GSoC project to split repository metadata functionality out from `git rev-parse`.
