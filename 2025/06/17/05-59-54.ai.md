Feature patch adding SHA256 repository support to gitk. This is version 2 of a patch that enables the Git graphical viewer to work with both SHA1 and SHA256 repositories. The main changes involve adjusting field widths and validation checks to accommodate SHA256's 64-character hashes versus SHA1's 40-character hashes.

Key technical points:
- Introduces a `hashlength` variable set to 40 or 64 based on repository format
- Updates numerous hardcoded length checks (40 -> `$hashlength`)
- Modifies UI elements like entry fields to accommodate longer hashes
- Shares auto-selection length configuration between SHA1/SHA256 (a simplification from v1)
- Leaves many "sha1" references in the code for minimal changes
- Based on prior work by Rostislav Krasny, refreshed and extended

The patch appears thorough, touching all the obvious places where hash length matters. The author notes they considered separate configs for SHA1/SHA256 lengths but opted for simplicity. Some technical debt remains with "sha1" terminology that could be confusing but was left to minimize changes.
