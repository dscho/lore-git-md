This is a refactoring patch in the ongoing `the_repository` removal effort, specifically improving submodule remote name fallback logic while advancing repository parameterization.

The patch replaces the submodule-specific `repo_get_default_remote()` with a more robust implementation using `remotes_remote_for_branch()` logic, which provides better handling of remote name determination in detached HEAD states. The new `repo_default_remote()` function centralizes this logic in remote.c while properly taking a repository parameter, moving away from `the_repository` usage.

Key technical changes include:
- Removal of the old `repo_get_default_remote()` function from submodule--helper.c
- Introduction of `repo_default_remote()` in remote.c that uses the repository parameter
- Updates to callers in submodule--helper to use the new function
- Addition of `repo_branch_get()` as a repository-aware version of `branch_get()`
- Maintenance of the existing `branch_get()` interface for compatibility

The changes improve remote name resolution by:
- Using branch-configured remotes when available
- Falling back to the single remote if exactly one exists
- Only using "origin" as a last resort
- Properly handling detached HEAD states

The patch continues the thread's theme of repository parameter propagation while improving submodule remote handling. It builds on previous work to make remote.c functions repository-aware and represents another step toward removing `the_repository` dependencies. The implementation carefully maintains backward compatibility while introducing the more robust remote selection logic.
