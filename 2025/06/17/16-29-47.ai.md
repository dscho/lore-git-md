This is a refactoring patch (part 2/3) in the series eliminating sparse-checkout-related global variables as part of the `the_repository` removal effort. The patch moves the `core_sparse_checkout_cone` configuration from a global variable to the `repo_settings` struct.

Junio Hamano's review focuses on initialization safety, pointing out that while the patch follows the established pattern of moving config to `repo_settings`, it needs to ensure `prepare_repo_settings()` is called before accessing the new location. He identifies specific files (`builtin/grep.c`, `builtin/mv.c`, `dir.c`, `sparse-index.c`) where this initialization may be missing or need verification, contrasting them with `builtin/sparse-checkout.c` which correctly calls it early.

The key technical concern is maintaining the same correctness guarantees as the original global variable access pattern - where config was always loaded before access. The review suggests the author needs to audit all call paths to ensure proper initialization sequencing, particularly for helper functions that may be called from multiple contexts. This echoes similar concerns raised about patch 1 in the series, indicating a consistent review focus on initialization safety across the migration effort.
