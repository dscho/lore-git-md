Bugfix needed for memory leaks in submodule remote lookup series. Junio C Hamano reports that when testing Jacob Keller's 6-part submodule remote lookup improvement series (merged to 'jch' branch), several tests fail and LeakSanitizer detects multiple memory leaks totaling 1049 bytes across 6 allocations. The leaks occur during submodule update operations, originating from the new `repo_from_url()` helper and propagating through the remote configuration handling chain.

The failure manifests in test t1013-read-tree-submodule.sh #52 ("modified submodule does not update submodule work tree to invalid commit"), with stack traces showing allocations in refspec handling and remote configuration that aren't being freed. The leaks appear to the new URL-based remote matching logic introduced in part 6 of the series, though the exact fix point isn't immediately clear from the backtraces.

This comes as Jacob was preparing to resend the series after the release freeze period, having previously addressed other technical issues like header dependencies and repository parameterization. The series had appeared ready for consideration, but these memory leaks will need to be resolved first. Junio's request to run with LeakSanitizer before resending has successfully caught these issues early.
