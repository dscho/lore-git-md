Bugfix for Windows terminal handling in `compat/terminal.c`. This is a follow-up to James Duley's patch that fixed an assertion failure when toggling DUPLEX mode during interactive operations like `git add -p`. Junio Hamano is now helping route the patch for review, noting it touches Windows-specific terminal code originally introduced in commit e22b245e.

The core issue involves how terminal state is saved and restored when switching between DUPLEX and non-DUPLEX modes. The original fix changed the condition in `restore_term()` to check `hconout` handle validity directly rather than relying on `cmode_out`, which could be uninitialized in non-DUPLEX mode. The change is minimal (3 lines modified) but critical for correct terminal behavior on Windows.

Junio suggests involving both the original author of the terminal handling code and Git-for-Windows maintainers for review, as this is platform-specific functionality. The patch has already been published via GitGitGadget as PR #2000 with a clean diff that removes the problematic assertion while maintaining the same safety checks through direct handle validation.

Key technical details for future reference: the fix centers around `hconout` handle validation in `restore_term()`, removing dependency on the potentially uninitialized `cmode_out` variable. The bug manifested when alternating between DUPLEX and non-DUPLEX modes during interactive sessions, particularly after editing hunks in `git add -p`. The change aligns better with Windows console API expectations while preserving the intended safety checks.
