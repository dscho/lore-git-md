Dense thread summary:

Bugfix for Windows terminal handling when toggling DUPLEX mode in `compat/terminal.c`. The issue causes an assertion failure in `restore_term()` during interactive operations like `git add -p` when alternating between DUPLEX and non-DUPLEX modes. Root cause is `save_term()` not setting `cmode_out` in non-DUPLEX mode while `restore_term()` checked this uninitialized value. The fix modifies 3 lines to check `hconout` handle validity directly instead, properly aligning with Windows console API expectations. The change is minimal but critical for correct terminal behavior during interactive sessions on Windows.
