Bugfix for Windows terminal handling in `compat/terminal.c` addressing assertion failure when toggling DUPLEX mode during interactive operations like `git add -p`. Original report and fix by first-time contributor James Duley identified root cause: `save_term()` not setting `cmode_out` in non-DUPLEX mode while `restore_term()` checked this uninitialized value. The 3-line fix modifies `restore_term()` to check `hconout` handle validity directly. Carlo Arenas Belón proposed additional refinement - explicitly initializing `cmode_out` to 0 in non-DUPLEX cases within `save_term()`. James responds with technical rationale against zero-initialization, noting: 1) `restore_term()` only follows successful `save_term()`, 2) `hconout` starts invalid, and 3) zero could be valid console mode.
