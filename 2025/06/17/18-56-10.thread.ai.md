Dense thread summary:

Bugfix for Windows terminal handling in `compat/terminal.c` addressing assertion failure when toggling DUPLEX mode during interactive operations like `git add -p`. Original report and fix by James Duley identified root cause: `save_term()` not setting `cmode_out` in non-DUPLEX mode while `restore_term()` checked this uninitialized value. The 3-line fix modifies `restore_term()` to check `hconout` handle validity directly instead, properly aligning with Windows console API expectations. Junio Hamano is now shepherding the patch through review, suggesting involvement of original terminal code author (commit e22b245e) and Git-for-Windows maintainers given platform-specific nature. Patch published via GitGitGadget PR #2000 with clean diff removing problematic assertion while maintaining safety through direct handle validation. Technical details: fix centers on `hconout` validation in `restore_term()`, eliminating dependency on potentially uninitialized `cmode_out`. Bug manifested when alternating DUPLEX/non-DUPLEX modes during interactive sessions, particularly after hunk editing in `git add -p`. Change preserves intended safety checks while better matching Windows console API behavior.
