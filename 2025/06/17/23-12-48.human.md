This is a refactoring patch that improves submodule remote name resolution as part of the ongoing `the_repository` removal effort. It's the fourth in a six-part series that aims to provide better remote URL handling for submodules while modernizing the codebase.

The patch replaces the existing `repo_get_default_remote()` function in submodule--helper with logic borrowed from `remotes_remote_for_branch()`, which provides more robust fallback behavior. The new approach first checks for a branch-configured remote, then looks for a single configured remote before finally falling back to "origin" - a more comprehensive strategy than the previous simple "use origin" fallback for detached HEAD states.

Key technical changes include:
- Removal of `repo_get_default_remote()` in favor of the new `repo_default_remote()`
- Introduction of `repo_branch_get()` as a repository-aware version of `branch_get()`
- Updates to callers to use the new functions
- Preservation of existing behavior for non-submodule cases through wrapper functions

The changes maintain backward compatibility while moving toward the series' goal of proper repository parameterization. Junio notes the clean design and approves of how the patch lifts `the_repository` dependencies while retaining the same interface for existing callers. This represents another step in the broader effort to improve submodule remote handling and remove global state dependencies.
