Bugfix for Windows terminal handling when toggling DUPLEX mode. This patch addresses an assertion failure that occurs in `compat/terminal.c` when `restore_term()` is called after alternating between DUPLEX and non-DUPLEX mode operations. The issue manifests during interactive operations like `git add -p` when editing hunks, where subsequent key presses trigger the assertion.

The root cause is that `save_term()` doesn't set `cmode_out` in non-DUPLEX mode, yet `restore_term()` was checking this uninitialized value. The fix changes the condition to check `hconout` directly instead, which is the proper indicator of whether stdout console mode restoration is needed. The change is minimal (3 lines modified) but critical for correct terminal handling on Windows.

The patch appears well-motivated with a clear reproduction scenario (`git add -p` editing flow) and a straightforward technical explanation. The fix aligns with Windows console API expectations by using handle validity as the restoration trigger rather than the mode value. This could be relevant for other Windows terminal interactions beyond just `git add -p`.
