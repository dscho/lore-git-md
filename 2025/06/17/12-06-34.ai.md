This is the first patch in a v4 series refactoring sparse-checkout configuration as part of the `the_repository` removal effort. It migrates the `core.sparsecheckout` setting from the global variable `core_apply_sparse_checkout` to the `repo_settings.sparse_checkout` field.

The patch updates 15 files to use the new access pattern via `repo->settings.sparse_checkout` after calling `prepare_repo_settings()`. Key changes include removing the global variable declaration, moving config parsing to `repo-settings.c`, and eliminating a `USE_THE_REPOSITORY_VARIABLE` workaround in `builtin/backfill.c`. The commit notes this is not lazily loaded since the setting is commonly used.

The changes follow the established pattern for repository settings migration - initialize once in `prepare_repo_settings()` then access directly. This maintains the same sparse-checkout behavior while improving code modularity. The patch demonstrates clean mechanical conversion of all access points across commands like `clone`, `mv`, `sparse-checkout`, and `worktree`.

This appears to be a well-executed refactoring that completes one piece of the sparse-checkout configuration migration, with the second variable (`core_sparse_checkout_cone`) handled in the next patch. The changes are focused and consistent with prior work in this area.
