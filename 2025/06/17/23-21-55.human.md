This is a refactoring patch that improves submodule remote name fallback logic while advancing `the_repository` removal efforts. Jacob Keller updates the submodule helper to use the more sophisticated remote selection logic from `remotes_remote_for_branch()` rather than always falling back to "origin" in detached HEAD state. The new approach first checks the branch-configured remote, then looks for a single remote if no branch is configured, and only uses "origin" as a last resort.

The patch introduces `repo_default_remote()` as a repository-aware replacement for the removed `repo_get_default_remote()`, with the new function calling into the existing `remotes_remote_for_branch()` logic. It also adds `repo_branch_get()` as a repository-aware version of `branch_get()`, maintaining the old function as a wrapper for compatibility.

Junio Hamano has reviewed the changes and approves of both the architectural approach and implementation details, noting the careful handling of repository initialization and the tasteful design of the fallback chain. The changes are part of a larger series improving submodule remote handling while removing `the_repository` dependencies, with this patch specifically focusing on making the default remote selection more robust.
