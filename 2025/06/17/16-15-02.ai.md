This is a review response from Junio Hamano on the first patch of Ayush Chandekar's v4 series refactoring sparse-checkout configuration. The patch moves `core_apply_sparse_checkout` from a global variable to `repo_settings`.

Junio raises important technical concerns about initialization timing. He notes that while the original code relied on `git_default_core_config()` being made early to initialize globals, the new approach requires explicit `prepare_repo_settings()` calls before accessing the settings. He specifically questions whether this initialization has occurred in several key locations (`builtin/clone.c`, `builtin/mv.c` and similar paths) where the settings are now accessed directly.

The review highlights a subtle but important architectural requirement for the refactoring: the need to ensure `prepare_repo_settings()` is called before any access to the repository settings. This wasn't an issue with globals but becomes critical with the new approach. Junio suggests the mechanical replacement of global variable access with struct member access isn't sufficient by itself - the initialization sequence must also be verified and potentially modified.

This feedback will likely require Ayush to audit all access points in the patch to ensure proper initialization sequencing, potentially adding `prepare_repo_settings()` calls where needed. The issue demonstrates the complexity involved in removing global variables while maintaining correct initialization behavior across Git's codebase.
