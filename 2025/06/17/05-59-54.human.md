This is a feature patch adding SHA-256 repository support to gitk, the Git repository browser. The patch updates gitk's Tcl/Tk code to handle the longer (64-character) hash IDs used in SHA-256 repositories while maintaining compatibility with existing SHA-1 repositories.

The changes are mostly mechanical - replacing hardcoded assumptions about 40-character hashes with a variable `hashlength` that's set based on the repository's object format. The patch also adjusts UI elements like entry field widths to accommodate the longer hashes. One notable compromise is that the auto-selection length setting is shared between SHA-1 and SHA-256 repositories, meaning users may see abbreviated SHA-256 hashes by default.

The patch appears well-considered, building on prior work by Rostislav Krasny. The author acknowledges some remaining technical debt (like shared configuration and lingering "sha1" variable names) but has chosen simplicity over completeness for this initial implementation. The changes are focused and the commit message clearly explains both the approach and its limitations.
