This is a review comment on patch 4/10 in the `imap-send` OAuth2.0 authentication series. Phillip Wood raises two technical concerns about the implementation:

1. **String construction safety**: The `oauthbearer_base64()` and `xoauth2_base64()` functions use fragile `snprintf()` calls with manually calculated buffer sizes. Phillip suggests using `strbuf` or `xstrfmt()` for safer string construction, noting this applies to other similar cases in the patch series.

2. **Missing host/port fields**: The comment for `oauthbearer_base64()` describes including host and port in the OAUTHBEARER string per RFCs 5801/7628, but the actual implementation omits these fields. This appears to be a documentation/implementation mismatch.

The comment is narrowly focused on these specific implementation details rather than the broader OAuth2.0 feature being added. It comes late in the review cycle (v18) as final polish is being applied before integration. Phillip notes he's not actively following the list but spotted these issues while checking the "What's cooking" status.

Key technical details referenced:
- The OAUTHBEARER implementation currently builds strings with `snprintf()` and manual length calculations
- RFCs 5801/7628 specify including host/port in the OAUTHBEARER string
- Similar string construction patterns appear in other parts of the patch series
- The review suggests using Git's standard string utilities (`strbuf`, `xstrfmt`) instead
