Memory leak discovery in submodule remote lookup series. Junio C Hamano reports that when testing Jacob Keller's 6-part submodule improvement series, LeakSanitizer detected memory leaks in test t1013-read-tree-submodule.sh. The leaks occur in the new URL-based remote matching logic introduced in part 6 of the series, specifically when handling submodule commits during error conditions. 

This comes after earlier discussion about the series facing poor timing due to the release freeze and summer slowdown. While the series had been planned for resubmission unchanged after the freeze, these newly discovered leaks - affecting real-world submodule update scenarios - must now be addressed first. The leaks stem from config parsing allocations not being freed during error paths in the `repo_remote_from_url()` function.

The series had previously undergone several refinements including repository parameterization, crash fixes, and build system corrections. The core improvements to submodule remote lookup logic remain sound, but this memory management oversight blocks final acceptance. Jacob Keller will need to examine the LeakSanitizer results and fix the cleanup paths before resubmitting.
