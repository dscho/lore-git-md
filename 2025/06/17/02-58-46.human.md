Refactoring patch improving submodule remote name fallback logic. This is part 4 of a 6-part series modernizing Git's submodule remote handling, specifically addressing how submodules in detached HEAD state determine their default remote.

The patch replaces the hardcoded "origin" fallback with more robust logic that first checks the branch configuration. It introduces a new `repo_default_remote()` helper in remote.c that reuses existing `remotes_remote_for_branch()` logic, which considers both the branch's configured remote and cases where there's only one remote available. The change maintains backward compatibility while providing better behavior for users who rename their remotes.

The implementation touches remote.c, submodule--helper.c, and adds test coverage in t7406 to verify the renamed remote scenario. Lidong Yan suggests inlining the new helper function since it's only used in one place, though this appears to be a minor stylistic point rather than a technical concern. The patch appears well-tested and follows the series' pattern of cleaning up submodule remote handling.
