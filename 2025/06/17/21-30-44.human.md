This is part 4 of a 6-part series improving submodule remote URL handling, building on preparatory work to make remote.c functions repository-aware and fix memory leaks.

The patch refactors how submodule--helper determines the default remote name when updating submodules. Currently, it defaults to "origin" in detached HEAD states, which fails when users rename their remotes. The new approach reuses existing logic from remotes_remote_for_branch() that first checks the branch's configured remote, then falls back to the sole remote if only one exists, before finally using "origin".

Key changes:
- Introduces repo_default_remote() in remote.c to centralize this logic
- Replaces repo_get_default_remote() calls with the new helper
- Maintains backward compatibility by still xstrdup'ing the result
- Adds a test case verifying behavior with renamed remotes

The change is part of the broader effort to make remote handling more robust for submodules while removing dependencies on the_repository. The implementation looks solid, with clear commit messages and a new test covering the renamed-remote scenario. While not a complete solution for all remote renaming cases, it improves the common situation where users have only renamed the default remote.
