Cover letter for a submodule remote lookup improvement series. This is a multi-patch effort to make Git's submodule remote handling more robust, particularly when users rename remotes or have multiple remotes configured.

The series starts with some preparatory cleanups: fixing memory leaks in branch and remote handling code, moving some path utility functions to a shared location, and making remote.c helpers work with submodule repositories. The main change introduces a new strategy for finding submodule remotes - instead of just looking for "origin" as a fallback, it first tries to match remotes by their URL (which is stored in the parent repository's config). This is more reliable since users are less likely to change both the remote name and URL simultaneously.

The v2 changes show good attention to detail - removing a now-unneeded function entirely, fixing leaks found by sanitizer checks, and keeping the commit history clean. The test additions in t7406 suggest thorough validation. This looks like a well-considered improvement to an area that has historically caused user confusion, with a clear progression from cleanup through to the new functionality.
