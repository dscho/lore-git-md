This is a bugfix for Windows terminal handling that addresses an assertion failure when using interactive commands like `git add -p`. The issue occurs when switching between DUPLEX and non-DUPLEX terminal modes, where an old console mode value could cause the program to incorrectly check an invalid handle. 

James Duley reports encountering this specifically when editing hunks during `git add -p` - after editing in vim, subsequent key presses would trigger the assertion. The fix changes the condition in `restore_term()` to check the console handle validity directly rather than relying on the console mode value.

It appears well-motivated by a concrete user experience problem and includes a clear explanation of both the faulty behavior and the solution. The change makes logical sense given the described interaction between terminal modes.
