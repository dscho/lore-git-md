This is a review comment on patch 4/10 in the `imap-send` OAuth2.0 authentication series. Phillip Wood points out two potential issues with the string handling in the OAuth2 implementation:

1. The string construction in `oauthbearer_base64()` and `xoauth2_base64()` appears fragile, using manual `snprintf()` calls with calculated lengths. He suggests using `strbuf` or `xstrfmt()` for safer string building, noting this applies to other similar patches in the series.

2. The comment in `oauthbearer_base64()` mentions including host and port in the OAuth string, but the actual implementation omits these fields. This could be either a documentation error or an implementation gap.

The review is constructive but brief, coming from someone who isn't actively following the thread (Phillip notes he's "not really on the list at the moment"). The feedback focuses on code safety and accuracy rather than the overall approach, which appears to be well-established in this v18 iteration of the series. The patch being reviewed implements OAuth2.0 support for both RFC-standard OAUTHBEARER and Google's XOAUTH2 protocols across OpenSSL and libcurl backends.
