Feature patch adding SHA-256 support to git-gui. This modifies the TCL-based Git GUI to properly handle SHA-256 repositories by making hash length detection dynamic rather than hardcoded to SHA-1's 40 characters. The changes span four files that deal with hash IDs:

1. The main git-gui.sh now detects the repository's object format (sha1/sha256) via `git rev-parse --show-object-format` and sets a global `hashlength` variable (40 or 64 chars)
2. Blame view, repository selection, and remote branch deletion interfaces are updated to use regex patterns that respect the detected hash length via TCL's `string map` substitution
3. The null SHA1 constant becomes a dynamically-sized null hash based on the repository format

The implementation appears thorough, touching all the key places where hash IDs are displayed or processed. The patch maintains backward compatibility with SHA-1 repositories while cleanly adding SHA-256 support. This aligns with Git's ongoing work to support multiple hash algorithms, though the commit message could better explain why git-gui needs this change now versus waiting for broader SHA-256 adoption.
