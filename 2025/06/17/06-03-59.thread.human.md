This thread introduces SHA-256 support to git-gui, the TCL-based Git graphical interface. The patch makes git-gui's hash handling dynamic rather than hardcoding assumptions about SHA-1's 40-character length. Key changes include detecting the repository's object format via `git rev-parse`, updating regex patterns for blame views and branch operations, and replacing the null SHA1 constant with a format-aware null hash. The implementation appears comprehensive, touching all interfaces where hash IDs are processed while maintaining backward compatibility with SHA-1 repositories. The changes span git-gui's core script and several interface components that display or manipulate commit hashes. While the technical implementation looks solid, the rationale for prioritizing this change now - versus waiting for broader SHA-256 adoption - could be more clearly explained in the commit message.
