Bugfix for Windows terminal handling in interactive operations. This patch addresses an assertion failure that occurs when toggling between DUPLEX and non-DUPLEX modes during commands like `git add -p`. The issue stems from `save_term()` not initializing `cmode_out` in non-DUPLEX mode while `restore_term()` was checking this uninitialized value.

The fix is minimal but important - it modifies the condition in `restore_term()` to check `hconout` handle validity directly rather than relying on `cmode_out`. This better aligns with Windows console API expectations and prevents the assertion failure when editing hunks interactively.

Junio C Hamano notes this is a Windows-specific change and suggests involving the original author of the terminal handling code and Git-for-Windows maintainers for review. The patch appears well-scoped with a clear explanation of both the problem and solution, though it would benefit from Windows-specific testing validation.
