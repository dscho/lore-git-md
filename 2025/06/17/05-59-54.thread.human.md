This thread concerns a patch series adding SHA-256 repository support to gitk, Git's graphical history viewer. The current version (v2) from Takashi Iwai introduces a flexible `hashlength` variable that adapts to either SHA-1 (40-character) or SHA-256 (64-character) hashes based on the repository's object format. The approach simplifies the v1 design by unifying configuration paths rather than maintaining separate SHA-1/SHA-256 code branches.

Johannes Sixt (Hannes), who maintains gitk, has acknowledged the patch and plans to merge it with one minor adjustment: moving the `hashlength` initialization to follow the `gui_encoding` setup for better code organization. This change doesn't affect functionality—gitk will still auto-detect the hash length via `git rev-parse --show-object-format` and handle both hash types appropriately. The patch appears ready to go in with this small tweak, marking a step toward full SHA-256 compatibility in Git's ecosystem.
