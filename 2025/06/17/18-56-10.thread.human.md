This thread addresses a Windows-specific bug in terminal handling that causes assertion failures during interactive operations like `git add -p` when toggling between DUPLEX and non-DUPLEX modes. The root issue was in `compat/terminal.c`, where `save_term()` wasn't setting `cmode_out` in non-DUPLEX mode while `restore_term()` checked this uninitialized value.

James Duley's original fix modified just three lines to check `hconout` handle validity directly instead, properly aligning with Windows console API expectations. Junio Hamano is now shepherding the patch through review, suggesting involvement from both the original terminal code contributor and Git-for-Windows maintainers given the platform-specific nature of the change. The patch has been submitted via GitGitGadget as PR #2000 with a clean diff that maintains safety checks while removing the problematic assertion. The fix is minimal but critical for correct terminal behavior on Windows during interactive sessions.
