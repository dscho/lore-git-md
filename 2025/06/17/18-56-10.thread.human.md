This thread addresses a Windows-specific bug in Git's terminal handling code (`compat/terminal.c`) where toggling DUPLEX mode during interactive operations like `git add -p` could trigger an assertion failure. First-time contributor James Duley identified the root cause: `save_term()` wasn't properly initializing `cmode_out` in non-DUPLEX mode, while `restore_term()` later checked this uninitialized value.

The discussion has converged on a three-part solution: 1) James's original fix to make `restore_term()` check `hconout` handle validity directly, 2) Carlo Arenas Belón's suggestion to initialize `cmode_out` to 0 in non-DUPLEX cases, and 3) Phillip Wood's recommendation to also set `hconout` to `INVALID_HANDLE_VALUE` in non-DUPLEX mode for complete state cleanup. Phillip has provided clear reproduction steps and emphasized documenting this edge case in the commit message.

In the latest email, Phillip clarifies technical details about handle invalidation and confirms that checking handle validity directly is preferable to relying on `cmode_out` being zero. He strongly advocates submitting the fix upstream to core Git rather than to Git-for-Windows, as the bug exists in shared code. This aligns with Carlo's earlier suggestion to split the fixes between upstream and downstream where appropriate. The discussion appears technically settled, with the remaining question being the submission path for the patch. Junio Hamano is shepherding the review, and the patch exists as GitGitGadget PR #2000.
