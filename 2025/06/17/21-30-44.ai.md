This is part 4 of a 6-patch series improving submodule remote URL handling, continuing the refactoring of remote.c to be repository-aware while removing `the_repository` usage.

The patch refactors how submodule--helper determines the default remote name when working with submodules. Previously, it would always fall back to "origin" when in HEAD-detached state, ignoring cases where users might have renamed their default remote. The new implementation reuses the more sophisticated logic from remotes_remote_for_branch(), which first checks the branch's configured remote, then looks for a single remote, before finally falling back to "origin".

Key technical changes:
- Introduces repo_default_remote() in remote.c as a repository-aware replacement for repo_get_default_remote()
- Uses remotes_remote_for_branch() logic which better handles renamed remotes
- Maintains xstrdup() behavior for compatibility with existing callers
- Adds a test case verifying behavior with renamed remotes
- Continues the series' pattern of making remote.c functions repository-aware

The change is part of the broader effort to improve submodule remote handling while removing `the_repository` usage. The test demonstrates the improved behavior by showing successful operation after renaming "origin" to "upstream" in a submodule. The patch maintains careful memory management with proper string duplication and follows the series' established patterns for repository parameter propagation.
