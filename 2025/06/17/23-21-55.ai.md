This is a refactoring patch that improves submodule remote name fallback logic while advancing `the_repository` removal efforts. It's part of a larger series (v2 4/6) that enhances submodule remote URL handling.

The patch replaces the custom `repo_get_default_remote()` function in submodule--helper with a call to the more robust `repo_default_remote()` that reuses existing logic from `remotes_remote_for_branch()`. The new approach provides a better fallback chain: first trying the branch-configured remote, then checking for exactly one remote, and only falling back to "origin" as a last resort. This is particularly useful for submodules in detached HEAD state.

Key technical changes include:
- Removal of `repo_get_default_remote()` and its two callers
- Introduction of `repo_default_remote()` in remote.c that uses `remotes_remote_for_branch()`
- Creation of `repo_branch_get()` as a repository-aware version of `branch_get()`
- Maintenance of backward compatibility via the original `branch_get()` wrapper

The changes continue the series' pattern of making remote.c functions repository-aware while preserving existing behavior for callers not yet updated. Junio has reviewed the changes positively, noting the good design taste in reusing existing logic and the clean handling of the repository parameter propagation. The patch maintains the one-to-one repository/remote_state relationship established earlier in the series.

This represents incremental progress in both improving submodule remote handling and removing `the_repository` dependencies, with the remaining callers to be updated in future work as they gain repository parameter support.
