Repository-aware refactoring in submodule helper functions.

This patch is part 5/6 in a series improving submodule remote URL handling while advancing `the_repository` removal efforts. It performs a pure code movement of `get_default_remote_submodule()` to position it after `resolve_relative_url()` in builtin/submodule--helper.c. The change is preparatory for future work that will make `get_default_remote_submodule()` depend on `resolve_relative_url()`.

The patch maintains all existing functionality, just reorganizing the code to make subsequent changes easier to review. The moved function continues to:
- Initialize a submodule repository using `repo_submodule_init()`
- Retrieve the default remote via the new `repo_default_remote()` function
- Clean up the temporary repository with `repo_clear()`
- Return error messages on failure

This is a mechanical change with no behavior modification, keeping the same memory management patterns (xstrdup for the returned remote name) and error handling. The relocation follows the series' pattern of making incremental, reviewable changes to submodule remote handling while progressing toward repository parameterization.

The patch demonstrates the series' careful approach to refactoring - making small, isolated changes that pave the way for more substantial functionality improvements in the architecture. It maintains compatibility with the surrounding code's use of `the_repository` while moving toward repository-aware alternatives.
