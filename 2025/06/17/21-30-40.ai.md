This is a cover letter for a patch series improving submodule remote lookup logic, with elements of refactoring, bugfix, and feature improvement. The series aims to make submodule remote detection more robust by first checking URLs before falling back to name-based lookup.

The series starts with preparatory cleanups: fixing memory leaks in branch_release() and remote_clear() functions, moving utility functions to shared headers, and making remote.c helpers repository-aware. The core change introduces repo_default_remote() to replace repo_get_default_remote(), with improved logic that doesn't blindly fall back to "origin". The key innovation is repo_remote_from_url() which matches remotes by URL - more reliable since submodule URLs are stored in the parent project's config. The series maintains fallback behavior but makes URL matching the primary lookup method.

Technical details include changes to remote.c's internal APIs, moving functions between submodule--helper.c and remote.c, and adding tests in t7406. The v2 changes remove the old repo_get_default_remote() entirely and fix leaks found by sanitizer checks. This appears to be a well-structured series addressing a real pain point in submodule workflows where renamed remotes cause problems. The commit messages clearly explain the motivation and changes, and the tests demonstrate the improved behavior.
