This thread has finalized the implementation of FreeBSD support policies through build system changes, focusing on modernizing compatibility requirements. The discussion began as a platform compatibility debate but has now reached completion with a two-patch series that Junio Hamano has reviewed and approved.

The key changes establish FreeBSD 12+ as the baseline for native `memmem()` support while removing obsolete compatibility code dating back to FreeBSD 4.x. The first patch makes `NO_MEMMEM` conditional on versions older than 12, while the second cleans up outdated flags like `NO_UINTMAX_T` across all build systems (Makefile, autoconf, and meson). The implementation maintains flexibility by allowing manual overrides of `NO_MEMMEM` and preserving Git's fallback implementation for older systems.

Junio has given his approval, noting the changes appear reasonable though untested on his end. The series received positive feedback throughout from contributors including Carlo Arenas (who proposed the version-checked approach) and security-conscious reviewers like brian m. carlson. The only remaining considerations are whether documentation updates are needed and when to integrate these changes with Git's release cycle. This work sets a precedent for how Git can handle version-specific platform support policies going forward.
