This thread has been discussing FreeBSD version support policies, particularly around the `memmem()` implementation and broader platform compatibility concerns. The discussion started with technical considerations about `memmem()` behavior across FreeBSD versions but has expanded to address security implications of end-of-life systems and documentation practices.

Junio C Hamano has been guiding the conversation toward documenting version requirements in Documentation/technical/platform-support.adoc. Technical analysis from Carlo Arenas revealed that while FreeBSD 12+ fixed major `memmem()` issues, some edge cases remain in older versions - though Git doesn't currently trigger these cases. The thread has separated three key considerations: security support timelines, implementation correctness, and performance tradeoffs between system-provided versus Git's own implementations.

A new patch has now landed that takes a first concrete step by removing special build settings for very old FreeBSD versions (4.x and earlier) from config.mak.uname. The change allows unconditional use of the system's `memmem()` while dropping several obsolete defines (NO_MEMMEM, NO_UINTMAX_T, NO_STRTOUMAX) and pthread library special-casing. The patch establishes FreeBSD 12 as the practical cutoff point, noting that all pre-12 versions are now end-of-life (with FreeBSD 11.4 EOL in 2021 and 10.4 in 2018). While this doesn't yet address the broader policy questions around documentation or build enforcement, it implements part of the emerging consensus in a conservative way.

Key participants have staked out positions: Brad Smith initially advocated broader version support, Carlo Arenas has cautioned about implementation quality, brian m. carlson emphasizes security risks of EOL systems, and Junio is framing the discussion around documentation and policy balance. The remaining open questions center on whether to set the minimum at FreeBSD 12 (technically sound) or 13.4 (security-supported), whether to actively block older versions, and how to document these decisions.
