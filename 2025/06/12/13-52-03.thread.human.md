This thread has reached consensus on modernizing Git's FreeBSD support by removing obsolete compatibility code while maintaining support for current FreeBSD versions (12+). The two-patch series implements this through build system changes.

The first patch introduced version-aware handling of `memmem()`, setting `NO_MEMMEM=UnfortunatelyYes` for FreeBSD versions before 12 (where the system `memmem()` had known issues). The second patch, just posted, completes the cleanup by removing all traces of `NO_UINTMAX_T` support, which was needed for FreeBSD 4.x compatibility but is now obsolete since Git requires C99 (which guarantees `uintmax_t`). The changes affect all three build systems (Makefile, autoconf, and meson) in parallel.

The implementation follows discussion among several contributors, including Carlo Arenas (who proposed the version-checked approach), Brian m. carlson (emphasizing security considerations for EOL systems), and Brad Smith (providing FreeBSD version specifics). Junio Hamano had previously endorsed enforcing these policies through the build system. The changes simplify maintenance while keeping Git working on supported FreeBSD versions, setting a precedent for future platform support decisions.
