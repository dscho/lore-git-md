This is a follow-up discussion in the Solaris build compatibility thread, focusing on the broader implications of requiring GNU tools. Collin Funk responds to Eli Schwartz's skepticism about mandating GNU sed (`gsed`) on Solaris systems, clarifying that while GNU sed is commonly available on Solaris machines he uses, it's not part of the default installation. The discussion reinforces the value of Junio's earlier patch that avoided the need for GNU sed by using basic regex (BRE) instead of extended regex (ERE), maintaining portability across platforms. 

Funk acknowledges Solaris's non-standard tools (like its `date` command) have caused similar issues in the past, but agrees with Schwartz that requiring GNU tools would be an unattractive solution. The exchange serves as post-resolution commentary validating the chosen approach, with both participants implicitly endorsing the portable solution over mandating GNU utilities. No new technical changes are proposed - this is primarily a discussion of the philosophical approach to platform compatibility, with consensus clearly favoring solutions that work with native tools rather than requiring GNU alternatives.
