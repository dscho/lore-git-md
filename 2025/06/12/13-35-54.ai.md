Platform compatibility follow-up discussing shell script portability best practices. Paul Smith responds to Eric Sunshine's suggestion about using `echo` instead of `printf` in the Solaris build fix, cautioning that `echo` has portability issues across different Unix implementations. He notes that while `printf` requires explicit newline handling, it's more standardized and safer for cases where the output might contain special characters or start with hyphens. The email serves as a post-resolution commentary reinforcing why the `printf`-based solution (as implemented in Junio's patch) was the more robust choice despite being slightly more verbose. This doesn't propose any code changes but provides broader context about shell scripting practices that could inform future similar fixes. The discussion remains relevant to the Git project's ongoing efforts to maintain compatibility across diverse Unix-like platforms, particularly where GNU vs. non-GNU toolchain differences come into play.
