This thread addresses sed portability issues in Git's build system, specifically for Solaris compatibility where older sed implementations lack the -E flag and handle files without trailing newlines differently. The original report came from Brad Smith, with Collin Funk providing initial review and Jeff King (peff) conducting thorough technical analysis.

The patch makes two key changes: modifying GIT-VERSION-GEN to ensure input ends with a newline before sed processing (fixing a regression from v2.49.0), and updating generate-configlist.sh to use basic regex instead of extended regex (-E) for Solaris. While Jeff King noted some stylistic reservations about the sed approach, he confirmed the technical correctness of the solution. Junio Hamano has indicated this will be fast-tracked to master before the next release, as it fixes real build issues on Solaris.

The thread demonstrates clear consensus that the practical fix outweighs aesthetic concerns, with all reviewers agreeing the solution works as needed for platform compatibility. With Jeff King's technical approval and no outstanding objections, the patch is now cleared for inclusion in the upcoming 2.50 release cycle.
