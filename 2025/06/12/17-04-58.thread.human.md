This thread addresses sed portability issues in Git's build system, specifically targeting Solaris compatibility where older sed implementations lack the -E flag and handle files without trailing newlines differently. The original patch, reported by Brad Smith and reviewed by Collin Funk, modifies two build scripts to ensure compatibility: GIT-VERSION-GEN now guarantees newline-terminated input for sed processing, and generate-configlist.sh replaces extended regex syntax with basic regex patterns.

Junio Hamano initially approved the solution despite some stylistic reservations about the sed approach, indicating it might be fast-tracked given its importance for platform compatibility. Jeff King (peff) has now reviewed the changes in detail, confirming they properly handle both the newline issue and regex conversion while maintaining functionality. While both reviewers note the sed patterns could be more elegantly written in an ideal world, they agree the technical solution is sound and ready for inclusion before the 2.50 release. With no outstanding objections, this platform compatibility fix appears set to proceed.
