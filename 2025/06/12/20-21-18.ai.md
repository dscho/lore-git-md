This is a maintainer decision email in the performance-oriented bswap.h refactoring thread. Junio Hamano indicates he will only take patch 1 (the big-endian regression fix) for the upcoming Git 2.50 release, deferring the remaining optimization patches to the next cycle. 

The decision reflects a conservative approach - while patches 2-6 contain valuable architectural improvements (as noted in the thread summary's analysis of compiler optimizations and platform handling), they aren't strictly necessary for correct functionality. The regression fix in patch 1 addresses the immediate issue where big-endian systems were broken by the __builtin_bswap changes, while the status quo remains acceptable for other platforms (they'll just use slightly less optimized code paths).

Junio's phrasing ("pure regression fix", "worst is that they fall back") shows this is a risk/reward calculation favoring stability over optimization for the imminent release. The remaining patches' technical merits (standardized macros, MSVC support, built-in bswap reintroduction) will presumably be considered for 2.51 after more bake time. This maintains the series' trajectory while avoiding last-minute changes in a release candidate period.
