This is a platform compatibility patch adjusting FreeBSD build configuration, part of the ongoing discussion about FreeBSD version support policies.

The patch removes special-case build settings for older FreeBSD versions (4.x and earlier) from config.mak.uname, allowing Git to unconditionally use the system's memmem() implementation. The commit message explains the rationale: while FreeBSD's memmem() had performance and correctness issues until version 12, all versions before 12 are now end-of-life (with FreeBSD 11.4 EOL in 2021 and 10.4 in 2018), so users shouldn't be running them. 

The change is conservative - it doesn't actively prevent building on older FreeBSD versions or document the 12+ requirement in platform-support.adoc yet, but establishes that version 12 is the practical cutoff. The patch drops several legacy defines (NO_MEMMEM, NO_UINTMAX_T, NO_STRTOUMAX) and pthread library special-casing that were only needed for very old FreeBSD versions.

This represents a concrete step in implementing the thread's consensus around FreeBSD version support, though the broader policy questions (documentation, build enforcement) remain open. The patch itself is straightforward build system cleanup with a well-documented rationale drawing from the thread's technical analysis of memmem() behavior across versions.
