This is a platform compatibility patch addressing Solaris sed issues. Junio C Hamano responds to Brad Smith's report of two Solaris build problems with proposed fixes. For the version-def.h generation warning about missing newlines, he suggests adding an explicit newline in the printf call. For the more serious config-list.h error about the unsupported `-E` flag, he provides a detailed rewrite of the sed expression to use basic regex (BRE) instead of extended regex (ERE), removing the `-E` flag dependency.

The patch modifies two files: GIT-VERSION-GEN (adding the newline) and generate-configlist.sh (rewriting the sed expression). The changes appear carefully considered - the regex rewrite maintains the same matching behavior while avoiding extended regex features, and Junio notes the BRE version may actually be more permissive in practice. This builds on the earlier thread where Brad Smith and Collin Funk diagnosed the Solaris sed limitations, particularly around ERE support.

The solution avoids the `gsed` detection question raised earlier in the thread by making the existing sed usage more portable. This appears to be a complete technical solution to both reported issues, though it remains to be seen if Solaris users will test and confirm the fixes work in practice. The patch maintains the same output format and sorting behavior while removing platform-specific dependencies.
