This is a refactoring patch that introduces a new `GET_OID_GENTLY` flag for reflog error handling, part of the v8 stash import/export series. The change modifies `get_oid_basic()` in `object-name.c` to allow callers to handle reflog history exhaustion errors programmatically rather than having the function die or exit quietly.

The patch addresses a subtle inconsistency where `get_oid` functions would die or exit on reflog history exhaustion despite appearing to return errors. The new flag (0100000) enables graceful error handling for cases like the stash export/import feature where callers need to manage this condition themselves. The implementation preserves backward compatibility since many existing callers rely on the current behavior.

Key technical details:
- Adds the flag definition in `hash.h` alongside other `GET_OID_*` flags
- Modifies `get_oid_basic()` to check the flag before dying/exiting
- Includes proper cleanup (freeing `real_ref`) in the error path
- Maintains existing behavior as the default to avoid breaking tests

This change directly supports the stash export/import functionality by enabling proper error handling during reflog traversal, while being careful not to disrupt other parts of the codebase. The patch has already been reviewed and approved as part of the larger series, with all feedback addressed in previous iterations.
