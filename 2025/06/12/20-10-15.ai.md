This is a refactoring patch in Sebastian Andrzej Siewior's series modernizing Git's byte-order handling. The patch adds support for compiler-provided `__BYTE_ORDER__` macros (available in GCC, Clang, and ICC) as a fallback when libc's `BYTE_ORDER` macros are unavailable (e.g. on MinGW). The change introduces new `GIT_*` constants that abstract away the underlying macro implementations.

Junio Hamano suggests simplifying the commit message by either removing or rephrasing the note about MSVC's lack of support, since MSVC is handled separately in patch 3 of the series. The actual code change is straightforward - adding a new conditional block that maps the compiler's endianness macros to Git's internal constants while maintaining the existing fallback definitions.

The patch represents part of a broader effort to make Git's byte-swapping infrastructure more robust across platforms while maintaining compatibility. It follows patch 1 (already applied) which fixed a regression on big-endian systems, and precedes patch 3 which specifically addresses MSVC compatibility. The series has attracted discussion about potential future directions (C23's `<stdbit.h>` and POSIX.1-2024's `<endian.h>`) but this particular patch focuses on the immediate goal of supporting modern compiler intrinsics.
