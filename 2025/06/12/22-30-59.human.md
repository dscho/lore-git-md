This is a platform compatibility discussion about FreeBSD version support policies, specifically regarding the `memmem()` implementation.

Carlo Arenas responds to Junio Hamano's suggestion about documenting FreeBSD version requirements by proposing a more concrete approach. He suggests modifying the build system to actively prevent using the system `memmem()` on FreeBSD versions below 12 (where it was known to be buggy), while still allowing the build to proceed with Git's compatibility implementation. His patch would add a check that sets NO_MEMMEM for FreeBSD < 12, maintaining the current behavior but making the version cutoff explicit in the build configuration.

The email continues the thread's theme of balancing technical correctness with practical considerations. Arenas notes this change wouldn't break builds (since Git would fall back to its own implementation), but would make the version-based policy more visible in the code. This contrasts with the thread's earlier discussion about whether to completely block builds on unsupported versions versus just documenting requirements.

The proposal shows the ongoing tension between wanting to support older systems versus maintaining code quality and security. Arenas' approach represents a middle ground - not blocking old systems entirely, but ensuring they get known-good implementations of problematic functions. The thread remains open on whether this should be the final policy or if more aggressive version requirements should be adopted.
