This thread addressed Solaris build compatibility issues with `sed`, where two problems emerged: a benign warning about a missing newline in version-def.h generation, and a more serious error about the unsupported `-E` flag in config-list.h generation (introduced by commit e1b81f54da). Brad Smith initially reported the issues, and Collin Funk confirmed them, noting the `-E` flag was problematic as Solaris' native `sed` lacked extended regex support. Junio C Hamano provided a patch that resolved both issues by adding an explicit newline and rewriting the `sed` expression to use basic regex (BRE) instead of extended regex (ERE), removing the `-E` dependency while preserving functionality.

Brad Smith verified the fix worked, and Collin Funk confirmed successful builds on both Solaris 10 and Linux, adding a Reviewed-by. Eli Schwartz and others later discussed the availability of GNU `sed` (`gsed`) on Solaris, noting it was only a third-party option on older versions. In a follow-up, Brad Smith clarified that while Solaris 11 includes GNU `sed` in its base OS, earlier versions like Solaris 10 do not, reinforcing the decision to avoid mandating GNU tools. The discussion concluded with consensus favoring Junio's portable solution, which ensures compatibility across all Solaris versions without requiring additional dependencies. The fix has been merged, and the thread serves as documentation of the rationale behind avoiding non-portable `sed` features.
