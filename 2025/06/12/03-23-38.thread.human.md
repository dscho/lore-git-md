This thread addressed Solaris build compatibility issues involving sed, where two problems emerged: a non-critical warning about missing newlines in version-def.h generation, and a more serious error about Solaris' native sed lacking the `-E` flag for extended regex support. Junio C Hamano provided a portable solution that rewrote the sed expressions to use basic regex and added explicit newlines via `printf`, which Brad Smith and Collin Funk confirmed worked across both Solaris 10 and Linux builds. 

The discussion then turned to broader portability practices, with Eric Sunshine and Paul Smith debating the tradeoffs between `echo` and `printf` (ultimately agreeing `printf` is safer despite being more verbose). Jean-Noël Avila raised the question of preventing future regressions through CI testing, prompting Collin Funk to respond that while Solaris CI via GitHub Actions is possible, it may not catch all subtle portability issues like the sed behavior differences. He noted Solaris packagers are accustomed to such quirks, reinforcing the thread's consensus that portable solutions are preferable to mandating GNU tools. The exchange highlights the balance between proactive testing and practical constraints in maintaining cross-platform compatibility.
