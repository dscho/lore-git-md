Feature implementation (stash import/export) - Final version addressing last review feedback items

This is the eighth and final version of the stash import/export feature series, now addressing the two remaining issues from Phillip Wood's review of v7. The core functionality remains unchanged - it enables bidirectional transfer of stashes between repositories via new `git stash export` and `import` subcommands, storing commit chains under `refs/stash-export/`.

The key changes in this version are focused on the two blocking items from v7 review:
1. Ownership semantics in `write_commit_with_parents()` are now clarified by having the caller (who allocated the objects) handle freeing rather than the helper function
2. Invalid argument combinations for `export` (like `--print` and `--to-ref` together) are now properly handled with tests added

The implementation spans `builtin/stash.c`, `object-name.c`, and `reflog-walk` infrastructure, with 268 lines of test coverage in `t/t3903.sh`. Notable technical components include:
- Phillip Wood's topology validation via `commit_list`
- Standardized `refs_for_each_reflog_entry*` traversal
- New `GET_OID_GENTLY` flag (0100000) in `hash.h` for reflog error handling
- Extracted `parse_stash_revision()` helper
- Import functionality that preserves original messages and validates commit chains

Documentation in `git-stash.adoc` has been refined for consistency, particularly around option descriptions. The series has received positive feedback from multiple reviewers (Junio Hamano, Phillip Wood, Ramsay Jones, Kristoffer Haugsbakk) across its seven previous iterations, with all major technical concerns now addressed.

The changes from v7 are minimal but critical - resolving the last two items that were blocking final approval. The author (brian m. carlson) has maintained consistent engagement through all review cycles, incorporating feedback across platform compatibility, API design, and documentation style. With these final fixes, the series appears ready for merging into mainline Git.
