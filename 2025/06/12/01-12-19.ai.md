This is the third patch in a 4-part series implementing stash export/import functionality, focusing specifically on the export mechanism. The patch introduces `git stash export` with two modes: `--print` to output commit hashes and `--to-ref` to store exported stashes under a specified ref.

The implementation handles both exporting all stashes (walking the reflog) and specific stash references. It creates a chain of commits where each exported stash commit maintains the original stash content as its second parent while linking to previous exports via first-parent relationships. The base of this chain is a predictable empty commit for reproducibility.

Key technical components include:
- New `write_commit_with_parents()` helper to reconstruct stash commits with modified parent relationships
- `check_stash_topology()` validation (from Phillip Wood) to ensure stash integrity
- Reflog traversal via `refs_for_each_reflog_ent_reverse`
- The `parse_stash_revision()` helper (new in v8) with quiet error handling
- Documentation updates in `git-stash.adoc` covering both subcommands and new options

The patch builds on infrastructure established in earlier versions (GET_OID_GENTLY flag, topology validation) while adding the core export logic. It maintains cross-platform compatibility and includes tests for the new functionality (though the test file isn't shown in this diff). All reviewer feedback from previous iterations appears addressed, with Phillip Wood and Junio Hamano having signed off on the approach.

This represents the export half of the bidirectional transfer capability, with the import functionality coming in the next patch. The implementation is now fully reviewed and ready for merging as part of the complete series.
