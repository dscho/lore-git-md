This is a follow-up discussion on patch 2/6 of Sebastian Andrzej Siewior's performance refactoring series for Git's byte-order handling. Brian m. carlson suggests an optional enhancement to the compiler feature detection in bswap.h by proposing support for C23's `<stdbit.h>` when available (with `__STDC_VERSION__ >= 202311L`). The suggestion would add detection of `__STDC_ENDIAN_*` macros as an alternative to `__BYTE_ORDER__` for compilers that support the newer C standard.

The email notes this is purely optional and specifically mentions it might help with "esoteric compilers" that support standards compliance but aren't GCC/clang-compatible. The suggestion doesn't challenge the core approach of using `__BYTE_ORDER__` as the primary detection method, but offers a forward-looking alternative that could provide better standards compliance. No implementation is provided - this is presented as a consideration for the maintainer to evaluate.

This discussion occurs in the context of the series' broader goal to modernize endianness detection while maintaining compatibility across diverse platforms (GCC, clang, MSVC, mingw). The suggestion aligns with the series' technical direction but isn't critical path material, representing more of a "nice to have" that could be considered for future iterations.
