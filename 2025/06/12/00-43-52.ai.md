Follow-up discussion on byte-order detection modernization in bswap.h series.

Collin Funk responds to Brian m. carlson's suggestion about C23's `<stdbit.h>` by noting another emerging standard: POSIX.1-2024's `<endian.h>` which defines `BYTE_ORDER` macros. While acknowledging this is also too new for widespread adoption, he points out some systems (notably glibc-based ones) already implement similar functionality historically. This adds another potential future-proofing avenue alongside the series' current `__BYTE_ORDER__` approach and Brian's C23 suggestion, though neither would replace the core detection method being implemented.

The exchange highlights the careful balancing act in platform compatibility work - supporting modern standards while maintaining broad compiler compatibility. Collin's reference to glibc's historical behavior suggests the POSIX approach might have slightly better real-world penetration than C23's features among existing systems, though both remain supplementary to the immediate changes in the patch series. No code changes are proposed; this remains an informational note about alternative standards landscape.
