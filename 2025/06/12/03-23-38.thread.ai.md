Thread summary:

Solaris build compatibility issues with sed, focusing on two problems: (1) non-critical warning about missing newline in version-def.h generation, and (2) error about unsupported `-E` flag in config-list.h generation (introduced by e1b81f54da). Brad Smith initially reported the issues and Collin Funk confirmed them, noting the newline warning is likely harmless while the `-E` flag error is more serious due to Solaris' native sed lacking extended regex support prior to POSIX.1-2024. Brad expressed doubts about Collin's suggestion to check for `gsed` (GNU sed) as a solution, citing inconsistent availability of GNU tools across Solaris installations.

Junio C Hamano has now responded with a patch addressing both issues. For the version-def.h warning, he adds an explicit newline in the printf call in GIT-VERSION-GEN. For the config-list.h error, he rewrites the sed expression in generate-configlist.sh to use basic regex (BRE) instead of extended regex (ERE), removing the `-E` flag dependency while maintaining the same matching behavior. The solution avoids the `gsed` detection question by making the existing sed usage more portable. The patch appears to be a complete technical solution, though Solaris users still need to test and confirm the fixes work in practice. The changes maintain the same output format and sorting behavior while removing platform-specific dependencies. The commit e1b81f54da remains relevant as the source of the original `-E` flag requirement that needed adaptation. Key open questions are now resolved, with the thread moving from diagnosis to implementation.
