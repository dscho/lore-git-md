This is a platform compatibility patch continuing the discussion about FreeBSD build configuration cleanup. Brad Smith responds to Collin Funk's review of their earlier patch that removed NO_MEMMEM for FreeBSD (which Collin had approved with a Reviewed-by tag). 

Brad provides additional historical context about memmem() availability, noting that while Gnulib's documentation claims it exists since FreeBSD 5.2.1, their source code inspection shows it only appearing in FreeBSD 6. This doesn't affect Git since they're already requiring FreeBSD 6+, but clarifies the historical record.

The more substantive part addresses Collin's question about removing FreeBSD 4.x-specific conditionals (PTHREAD_LIBS and integer type definitions). Brad confirms this was intentional - since the patch series establishes FreeBSD 6 as the minimum supported version, the 4.x-specific code (dating back to 2000) can be removed. He acknowledges this rationale should have been in the commit message.

The exchange shows good technical diligence from both contributors - verifying historical facts about API availability while keeping the focus on practical impact for Git's build requirements. The thread appears to be converging on a clean solution for modernizing FreeBSD support.
