This thread introduces and refines a new compact summary format for merge/pull operations via a two-patch series from the Git maintainer. The core change adds both CLI (`--compact-summary`) and config (`merge.stat=compact`) options to modify diffstat output, better showing created/deleted paths during merges by explicitly marking new files with "(new)" suffix.

The implementation spans builtin/merge.c, builtin/pull.c, diff.c and their documentation, with tests covering both CLI and config-driven behavior. The first patch implemented the CLI interface through a new `MERGE_SHOW_COMPACTSUMMARY` flag, while the second extended `merge.stat` config to support tri-state values (`false`, `true`, `compact`) using `git_parse_maybe_bool_text()`.

Kristoffer Haugsbakk has contributed multiple rounds of documentation improvements:
1. Initially suggested changing "compactstat" to "compact stat" in CLI help text
2. Identified several documentation refinements for the merge.stat config:
   - Questions whether `diffstat` should alias `true` while acknowledging backward compatibility constraints
   - Corrects the documentation's reference to invalid `--diffstat` option (should be `--stat`)
   - Proposes simplifying default value phrasing from "If this variable is left unspecified..." to "Defaults to `true`"

Junio Hamano has now responded to finalize the documentation:
- Agrees "compactstat" is unclear but prefers "compact summary" over "compact stat" to match the `--compact-summary` option name
- Confirms adding `diffstat` as a `true` alias could be considered later but isn't required now
- Notes stylistic preference for including introductory phrases like "if not specified" before defaults, despite logical redundancy, citing existing documentation patterns

The series remains complete with no outstanding technical questions, providing consistent compact summary output through both CLI and configuration interfaces. The core functionality - showing created/deleted paths with "(new)" markers whether activated via command line or configuration - remains unchanged, now with progressively refined documentation and help text. All discussion has shifted to final wording polish rather than technical substance.
