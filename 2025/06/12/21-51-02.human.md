This is a platform compatibility patch adjusting FreeBSD build settings, part of the ongoing discussion about FreeBSD version support policies. Junio C Hamano submits Brad Smith's patch (v3) that removes special casing for older FreeBSD versions in `config.mak.uname`, specifically dropping `NO_MEMMEM` and version 4.x workarounds.

The commit message explains the rationale: while FreeBSD 6+ had `memmem()`, it was buggy until FreeBSD 12. Given that FreeBSD 11.4 (last of the 11.x series) reached end-of-life in 2021, the patch establishes FreeBSD 12 as the new practical baseline, allowing unconditional use of the platform's `memmem()`. The change removes several legacy workarounds while maintaining other FreeBSD-specific settings.

Notably, this doesn't yet document the version requirement in `platform-support.adoc` or enforce build failures on older systems, leaving those as potential future steps. The patch appears well-justified, citing security support timelines and implementation history, though some may question whether the line should be drawn at FreeBSD 13.4 (currently security-supported) instead of 12. The technical change itself is straightforward - removing obsolete build configuration - but represents a policy decision in the broader platform support discussion.
