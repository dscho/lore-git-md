This is a bugfix report regarding type safety in Git's curl integration. Peter Michael Green reports that Git passes incorrect types to `curl_easy_setopt()` calls when building against curl 8.14, triggering compiler warnings. The issue affects multiple files (`imap-send.c`, `http-push.c`, `remote-curl.c`, `http.c`) where integer values are passed without proper type casting or literal suffixes.

While these warnings only recently appeared with curl 8.14, Green notes the underlying issue has always existed - `curl_easy_setopt()` is variadic and type-unsafe, meaning wrong parameter types could potentially cause crashes or misbehavior depending on architecture and compiler behavior. The immediate concern was discovered in Debian's build system where `-Werror` turns these warnings into errors.

Green suggests the solution would be to add proper type casts and literal suffixes to ensure correct parameter types are passed, but is seeking feedback from Git maintainers familiar with the codebase before proposing specific fixes. This appears to be a legitimate type safety issue that should be addressed, though the current impact seems limited to compiler warnings rather than runtime failures.
