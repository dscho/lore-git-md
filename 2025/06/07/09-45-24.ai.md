This is a bugfix patch series addressing issues with `git stash -p` option parsing, now in its third version. The series has already been reviewed and queued by the maintainer with positive feedback from Martin Ågren.

The first patch fixes a regression from 2020 where `git stash -p <pathspec>` stopped working due to incorrect argv handling in the option parsing logic. The fix changes one line in builtin/stash.c to properly check argv[1] for the -p flag. The test cases have been strengthened in v3 to better verify interactive patch selection behavior by setting up a scenario with multiple changes and only stashing some hunks.

The second patch extends this to allow more flexible option ordering with `--patch`, removing the previous restriction that -p/--patch must come first. It uses PARSE_OPT_STOP_AT_NON_OPTION to maintain safety while accepting reasonable variations like `git stash -m <message> --patch <pathspec>`. The test case was updated to use --patch explicitly while maintaining support for both forms.

The changes are focused and well-tested, touching only builtin/stash.c and t/t3903-stash.sh. The v3 updates respond to Martin Ågren's feedback by making the tests more rigorous, particularly around verifying the interactive patch selection behavior. The series has clear technical approval and addresses a real regression while improving usability, making it likely to be merged soon.
