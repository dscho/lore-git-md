This is the second patch in a bugfix series improving `git stash`'s option parsing behavior around the `-p/--patch` flag. The patch relaxes overly strict assumptions about option ordering when using `--patch` with `git stash`.

Currently, Git only assumes a "push" operation when `-p` is given as the first option (e.g. `git stash -p <pathspec>`), rejecting reasonable variations like `git stash -m <message> -p <pathspec>`. Phillip Wood's solution modifies the option parsing logic to use `PARSE_OPT_STOP_AT_NON_OPTION` when push is being assumed, then sets `force_assume` if `--patch` was present. This maintains safety against subcommand typos while accepting more natural command-line orderings.

The patch includes test updates to verify the new behavior, changing an existing test to use `--patch` explicitly while maintaining support for both forms. This follows up on Martin Ågren's review feedback from earlier versions, strengthening the test coverage. The implementation is straightforward, touching just 10 lines across `builtin/stash.c` and the test file.

This change builds on the first patch's fix for `git stash -p <pathspec>` behavior and has already received positive feedback from reviewers. The series appears ready for merging, addressing clear usability issues while maintaining backward compatibility.
