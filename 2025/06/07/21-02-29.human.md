This is a follow-up in the byte-order handling refactoring thread, reporting a build breakage on Windows. Junio Hamano notes that Sebastian Siewior's recent patch to move the `ntohl`/`htonl` macro definitions is causing significant Windows build failures, as evidenced by GitHub Actions logs. The patch has been reverted from Junio's tree pending investigation.

The issue appears to be to the platform-specific nature of the changes - while the original fix addressed big-endian systems (s390x), it inadvertently broke Windows builds. This highlights the delicate balance required when modifying low-level compatibility code that must work across diverse platforms. The thread continues to track the technical challenges of byte-order handling while now adding Windows compatibility to the list of concerns alongside the original big-endian focus.
