Bugfix for git stash's -p/--patch option handling, addressing a regression from 2020. This first patch in a two-part series fixes a case where "git stash -p <pathspec>" stopped working after commit 8c3713cede7 due to incorrect argv index checking. The issue occurred when the code was moved to push_stash() but kept checking argv[0] for "-p" after "push" had been prepended to argv.

The fix changes one line in builtin/stash.c to check argv[1] instead of argv[0] when looking for the -p flag. Phillip Wood adds two test cases in t3903-stash.sh to verify the behavior: one confirming that "stash -p <pathspec>" works as expected (including interactive patch selection), and another ensuring that "stash <pathspec> -p" is properly rejected with an error message. The test scenario involves stashing only some changes to a file while leaving others, verifying the interactive selection works correctly.

This patch has already been reviewed by Martin Ågren, who suggested test improvements that were incorporated in v3. The change is focused and maintains backward compatibility while fixing a clear regression in the stash command's option parsing. The test coverage appears thorough, including both the happy path and error cases.
