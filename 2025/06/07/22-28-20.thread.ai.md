Thread identity: Bug report about type safety issues in Git's curl interactions, affecting multiple components that use libcurl (imap-send.c, http-push.c, remote-curl.c, http.c). Originating from Peter Michael Green's report of compiler warnings when building against curl 8.14.

Core problem: Type mismatches in curl_easy_setopt() calls where numeric values (ports, boolean flags, sizes) are passed without proper casting to match the expected types for specific curl options. While these warnings are new in curl 8.14, the underlying type safety issues have always existed and could potentially cause crashes or misbehavior depending on architecture and parameter types.

Key technical details: The problematic calls involve frequently used curl options including CURLOPT_HTTPGET, CURLOPT_SSL_VERIFYPEER, CURLOPT_SSL_VERIFYHOST, and CURLOPT_PORT. The issue spans multiple Git components that interface with libcurl.

Current status: The issue has been reported but not yet fixed. The warnings currently break builds using -Werror (like Debian's packaging environment) but affect mainline Git as well. The current behavior might work by accident on some architectures but is technically undefined.

Open questions: The reporter (Peter Michael Green) has suggested adding proper casts and literal suffixes but is seeking review from Git maintainers familiar with the codebase before proceeding with fixes. The fix would require mechanical but careful type adjustments across multiple curl interaction points.
