Bugfix and refactoring patch in the `imap-send` series, addressing CRAM-MD5 authentication handling when OpenSSL is unavailable. This is patch 5/10 in v14 of the series.

The patch improves error handling for CRAM-MD5 authentication, which requires OpenSSL (unlike other auth methods that work with libcurl). Previously, attempting CRAM-MD5 without OpenSSL would crash with a die() error. The new version checks for OpenSSL availability first and provides a graceful error message if it's missing.

Junio Hamano notes this improvement would have been better placed earlier in the series (perhaps after patch 1/10) since it establishes better foundational behavior for authentication handling. The current placement works but creates a slightly awkward series flow. The patch itself is well-contained and does what it claims - replacing a crash with proper error handling while refactoring the CRAM-MD5 logic into a cleaner structure.

This continues the series' trend of improving both robustness and user experience in `imap-send`, though as Junio observes, the sequencing could have been more logical. The change is non-controversial and appears ready for inclusion.
