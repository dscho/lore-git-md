Cover letter for a bugfix series improving `git stash -p` behavior.

This is the third version of Phillip Wood's two-patch series addressing issues with `git stash`'s handling of the `-p/--patch` option with pathspecs. The first patch fixes a regression from 2020 where `git stash -p <pathspec>` stopped working due to incorrect argument parsing. The second patch extends this to allow more flexible option ordering, letting users combine `--patch` with other options like `-m` in any order.

The changes are focused and well-tested, with Phillip incorporating feedback from Martin Ågren to strengthen the test cases. The tests now better verify interactive patch selection by stashing only some hunks from a file while leaving others. The series has already received positive reviews and been queued by the maintainer, with this version tightening up the test coverage as suggested.

These are straightforward improvements to a common workflow that had regressed, fixing real pain points while maintaining backward compatibility. The patches modify `builtin/stash.c`'s option parsing and add test cases in `t3903-stash.sh`. Given the clear need and thorough review, this series is likely to be merged soon.
