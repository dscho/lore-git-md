Bugfix and refactoring patch in the `imap-send` series, addressing CRAM-MD5 authentication handling when OpenSSL is unavailable. This patch modifies the authentication flow to gracefully fail when CRAM-MD5 is requested without OpenSSL support, replacing the previous behavior which would attempt authentication and die with an error.

The technical changes move CRAM-MD5 logic into a dedicated `auth_cram_md5()` function that is NULL when OpenSSL is unavailable, with proper compile-time guards. This follows the pattern established earlier in the series for other authentication methods. The implementation removes 41 lines of code while adding 20, showing significant simplification through this refactoring.

Junio Hamano notes this improvement would have been better placed earlier in the series (after patch 01/10) when introducing the `try_auth_method()` helper, as it would have provided a cleaner foundation for subsequent authentication method additions. However, the change is well-contained and maintains consistency with the series' overall authentication architecture.

This patch completes the CRAM-MD5 handling work that was partially addressed in earlier versions of the series, ensuring all error paths are properly covered and OpenSSL availability is checked before attempting CRAM-MD5 authentication. The change aligns with the series' broader goals of robust authentication handling and graceful failure modes.
