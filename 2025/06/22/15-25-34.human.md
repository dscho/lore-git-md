This is part 2 of a 3-patch series improving the git-credential-netrc helper's handling of port numbers in netrc files. The patch adds a warning when invalid port numbers are encountered, rather than silently dropping them as before.

The change is straightforward - it modifies the Perl script to print a warning to STDERR when a port value exists but isn't numeric. This improves debugging by making it clear when malformed port values are being ignored. The warning follows the pattern of other credential helper messages.

This patch builds on the ongoing discussion about how to handle symbolic port names in credential helpers. While the larger thread debates whether to support symbolic ports at all (versus requiring numeric ports as the credential documentation suggests), this particular change is a clear improvement to the current behavior regardless of that design decision.

The implementation looks clean and focused, with a clear warning message and minimal code changes. It's part of a well-structured series that includes tests for the new behavior. The patch doesn't resolve the larger protocol questions, but provides better user feedback for invalid ports in the meantime.
