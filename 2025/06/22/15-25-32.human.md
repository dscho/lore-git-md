This is a patch series addressing symbolic port name support in the git-credential-netrc helper, continuing the ongoing thread about credential system design. Maxim Cournoyer follows up on previous discussion with three concrete changes to improve port handling while maintaining compatibility.

The series starts with a minor portability fix to the helper's shebang line, then adds explicit warnings when invalid ports are encountered in netrc files. The main change in patch 3 enhances symbolic port support by resolving names to numbers using Perl's getservbyname, similar to the Scheme implementation Cournoyer previously demonstrated. The changes touch git-send-email's Perl code to maintain consistent behavior.

The series appears well-tested with both automated tests and manual verification, including sending the patches themselves. It represents a practical implementation of the "helper-side resolution" approach discussed in the thread, contrasting with Brian Carlson's preference for numeric-only credential protocol. The changes don't yet resolve the fundamental design question about where port resolution should happen, but provide a working implementation of one side of the discussion.
