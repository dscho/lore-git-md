This is a follow-up in the git-gui localization thread, focusing on the ongoing po-file technical discussions after the Bulgarian translation was accepted. Alexander Shopov responds to Johannes Sixt's questions about stable string ordering in .pot/.po files.

Shopov explains that gettext's sorting options (-s/--sort-output) are deprecated and counter-productive, while the default -F/--sort-by-file option still allows some string position jumping when strings move between files. He notes line number changes in location comments also disrupt diff stability regardless of sorting.

The key new development is Shopov's proposal to voluntarily remove location comments from future git-gui/gitk translation submissions, interpreting Sixt's earlier messages as being open to this workflow change. He outlines the benefits: shorter diffs, more readable commits, and reduced repository growth, while noting the runtime-unused location data remains recoverable via pot-file regeneration.

This moves the format discussion forward by offering a concrete, translator-driven implementation path for the location comment removal idea, though the string ordering stability question remains unresolved. The email maintains the thread's split between completed translation work (bg.po) and ongoing infrastructure improvements (po-file formats).
