This is a bug report about warning messages appearing during Git repository cloning. Kryzet reports seeing numerous "badFilemode" warnings and one "missingTaggerEntry" warning when cloning git/git from GitHub. The warnings appear to be related to object validation during the clone operation.

The email consists almost entirely of a long list of warning messages, each referencing a specific Git object by hash and indicating either invalid file modes or a missing tagger line. The sheer volume of these warnings (over 60 instances) suggests this is a systematic issue rather than isolated corruption.

No patch or proposed solution is included - this appears to be purely an observational report. The warnings don't prevent the clone from completing successfully, but their presence suggests some underlying data integrity questions that might warrant investigation by repository maintainers. The report would benefit from additional context about Git versions used and whether this occurs consistently across different environments.
