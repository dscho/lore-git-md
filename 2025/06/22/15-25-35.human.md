This is the third and final patch in a bugfix series addressing symbolic port name handling in the git-credential-netrc helper. The patch implements helper-side resolution of symbolic port names (like "smtps") to numeric values using getservbyname, while maintaining backward compatibility with numeric ports.

The change fixes a specific issue where symbolic ports in netrc files were incorrectly treated as protocols, breaking git-send-email's credential lookup. The patch adds port validation in git-send-email.perl and introduces a new Git::is_port helper function that handles both numeric and symbolic ports. Test coverage is included to verify the new behavior.

The implementation appears technically sound, with careful approach to backward compatibility and proper error handling. However, this remains somewhat controversial as it diverges from the credential protocol's documented numeric-only port specification. The patch series provides a working solution while the larger design question (helper vs caller-side resolution) remains open for maintainer decision.

This completes the v2 series that began with shebang updates and warning additions, now delivering the core functionality change. The patch is well-structured with clear commit message, code changes, and test updates, though its ultimate acceptance depends on resolution of the protocol design question raised earlier in the thread.
