This is a bugfix discussion regarding the first patch in a series addressing `git apply --intent-to-add` behavior. Junio Hamano questions whether the patch's approach of erroring out when using `--intent-to-add` outside a Git repository is the right solution, suggesting that silently ignoring the flag (as the current code does) may be more appropriate when Git is being used as "a better GNU patch" tool.

The core disagreement centers on whether invalid usage should trigger an error or be silently ignored. Hamano points out that the patch's justification ("it makes no sense") could equally support the current behavior of ignoring the flag, and that the patch doesn't sufficiently explain why an error is better than silent ignoring. This suggests the patch may need stronger rationale before being accepted.

The discussion is part of a larger series (5 patches) fixing `--intent-to-add` functionality that has been broken since Git 2.19. While this first patch is relatively simple (6 lines changed in `apply.c`), the philosophical question it raises about error handling could influence the rest of the series' approach to invalid usage scenarios.
