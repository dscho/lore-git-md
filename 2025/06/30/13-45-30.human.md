This is a bug report about credential helper behavior during failed operations. Michal Suchánek reports that when a push operation fails (in this case while testing AGit with an OAuth helper), Git appears to discard previously stored credentials, forcing repeated authentication requests even for repositories where access should already be authorized.

The issue was encountered while working with Gitea's AGit interface and the git-credential-oauth helper. After an initial authentication failure, subsequent pushes to authorized repositories unexpectedly required re-authentication, suggesting Git is clearing valid credentials after any failed operation.

The report suggests this behavior is undesirable and asks whether credentials could be preserved across failed operations. While the description is clear about the symptom, it doesn't specify whether this affects all credential helpers or just the OAuth one in this particular setup. The impact appears significant for workflows involving multiple authentication attempts, but we'd need to see whether this reproduces with standard credential helpers to assess how widespread the issue might be.
