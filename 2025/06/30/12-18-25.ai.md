This is a follow-up discussion in the Git daemon signal handling bugfix thread, focusing on implementation details and platform-specific behavior of waitpid().

Carlo Marcelo Arenas Belón responds to Phillip Wood's review comments about their earlier patch to fix EINTR handling in git-daemon's child process reaping. The discussion centers on two technical points: first, whether waitpid() with WNOHANG can actually return EINTR (contrary to Linux manpage claims), and second, the proper way to format pid_t values in error messages.

On the waitpid() behavior, Carlo acknowledges the Linux manpage note about WNOHANG preventing EINTR but couldn't find similar documentation elsewhere. They suggest the issue might be implementation-dependent and worth addressing in run_command.c as well if problematic. Regarding pid_t formatting, Carlo defends their use of uintmax_t casting for printing PIDs, citing historical precedent in Git's codebase (since 2008) and noting that while pid_t is signed, actual PIDs are positive values.

The exchange reveals platform-specific considerations - Carlo mentions AIX's 4-byte pid_t and Solaris's 8-byte long PIDs, though both appear to stay within INT_MAX bounds. The thread continues to explore edge cases in signal handling implementation while maintaining the original bugfix's correctness.
