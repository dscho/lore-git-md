This thread is discussing whether to explicitly prohibit AI-generated contributions in Git, following QEMU's recent policy change. The initial proposal received broad support for the principle of banning AI content due to legal uncertainties around copyright and the Developer Certificate of Origin, but questions emerged about how broadly the prohibition should apply.

The discussion has now narrowed to two key distinctions: First, whether the ban should cover only AI-generated code (where legal risks are clearest) or extend to other content like commit messages and documentation. Second, how to distinguish between prohibited generative uses and permitted AI-assisted review tools. Junio Hamano, the Git maintainer, has weighed in supporting the inclusion of commit messages in the prohibition while agreeing that tools used only for checking or proofreading should remain allowed.

The thread shows consensus on the core prohibition but awaits revised wording that better defines these boundaries. Christian Couder suggested aligning more closely with QEMU's narrower, code-focused approach, while others like Brian M. Carlson maintain strong support for broader protections. The next steps will likely be a revised patch that tightens the language while addressing these scope questions, possibly after consulting with the Software Freedom Conservancy's legal team given Git's shared affiliation with QEMU.
