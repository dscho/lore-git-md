This is a user-facing behavior change report regarding `git branch -a` output.

Olaf Hering reports that between Git 2.43 and 2.50, the output of `git branch -a` started including additional lines showing remote HEAD references (like "remote/HEAD -> remote/branch") when listing remote branches. This change is breaking their script that parses the branch output, as it to only contain simple "remote/branch" names.

The issue appears related to the presence of `.git/refs/remotes/${remote}/HEAD` files in the repository - these exist on the newer system but not the older one. The commit message doesn't specify whether this is an intentional Git change or just a side effect of different repository states, but it's clearly causing real-world compatibility issues.

Olaf asks if there's a configuration option to suppress these HEAD reference lines, noting that none is documented in git-branch(1). The question implies they'd prefer a built-in solution rather than having to add filtering logic to their script. This seems like a reasonable request that might warrant either documentation clarification or a new configuration option if the behavior change was intentional.
