Bugfix clarification regarding `--filter` vs `--filters` option behavior. Phillip Wood points out that the reported regression in `git cat-file --filter` is actually due to a misunderstanding of the option name - the correct long option has always been `--filters`, and prior versions were accepting the abbreviated form `--filter` which is no longer working in Git 2.50. This explains why commands like `git cat-file --filter "HEAD:changelog.md"` now fail with "fatal: invalid filter-spec".

The key technical detail is the distinction between the full option name `--filters` and its previously-accepted abbreviation `--filter`. The change in behavior appears to be intentional rather than a bug, as Phillip notes that while abbreviated options are useful interactively, they should be avoided in scripts for stability. This clarifies that the issue reported by Dan Pristupov is not actually a regression from commit eb83e4c64b as initially thought, but rather a case of relying on an abbreviated option name that is no longer accepted. The email serves to correct the technical understanding of the situation while providing guidance about best practices for option naming in scripts versus interactive use.
