This is a follow-up to the ongoing clang-format improvements series, focusing on reducing false positives in code formatting. The 3-patch series makes three key changes:

1. Removes ColumnLimit from clang-format, shifting line-wrapping responsibility to developers rather than the tool. This addresses the majority of false positives seen in formatting diffs.

2. Makes the RemoveBracesLLVM rule permanent by moving it into the main .clang-format configuration. This was previously a temporary workaround.

3. Adds a meson build target ('meson compile style') to run git-clang-format, making it easier to use the Git-specific wrapper. The v2 version specifically checks for git-clang-format rather than just clang-format.

The cover letter shows sample diffs demonstrating reduced formatting noise, particularly in builtin/diff.c and pathspec.h. Notably, v2 drops the controversial patch that would have set a 120-character line length in .editorconfig, as it was found to cause undesirable editor behavior (actively reformatting text rather than just limiting line length).

The changes appear well-considered, with clear motivation and evidence of testing. The series builds on previous discussion about line length philosophy while avoiding the editor-specific pitfalls that emerged in v1. The meson integration looks solid, and the formatting changes shown in the diffs appear reasonable.
