This is a bugfix discussion for case-insensitive filesystem handling in Git's reference pruning. Karthik Nayak responds to Jayatheerth K's analysis of the `git pull --prune` issue where case-conflicting refs cause batch deletions to fail entirely. While agreeing with the technical analysis, Karthik notes that the proposed solution of individual transactions would cause significant performance degradation, especially for the reftable backend.

Karthik suggests two alternative approaches: a short-term fix that would skip duplicate refs in case-insensitive mode (shown in a diff that filters out case-conflicting refs before deletion), and a longer-term solution involving proper conflict resolution in reference transactions. The latter would enable proper batching while handling case conflicts, aligning with ongoing work on batched updates in git-fetch.

Key technical points: the current workaround separates pruning from updates due to transaction limitations, the performance impact of per-ref transactions, and the connection to the `kn/fetch-push-bulk-ref-update` series. The discussion highlights the tension between correctness and performance in filesystem edge cases, with the proposed short-term solution being a pragmatic stopgap until transaction conflict handling can be improved.
