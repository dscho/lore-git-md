This is a discussion about the ongoing bugfix for comment character selection in Git commit messages, specifically regarding the architectural approach to handling the `core.commentChar="auto"` feature.

Phillip Wood responds to Ayush Chandekar's experimental refactoring attempt to centralize comment character state management. Wood expresses skepticism about Chandekar's approach of creating a single function to handle both auto and non-auto cases, noting it breaks the "last one wins" behavior between `core.commentChar` and `core.commentString` and could lead to poor user experience in some edge cases. 

Wood reveals he's working on a patch to deprecate the `core.commentChar="auto"` feature entirely, citing its many problematic cases. He suggests an alternative approach of storing the parsed comment character in `struct repository` while acknowledging this would need to consider commands that run without a repository.

The email highlights the architectural complexity of this seemingly small feature and shows the maintainers considering more radical solutions (deprecation) rather than incremental fixes. This suggests the issue may lead to significant changes in how Git handles comment characters, though Wood's deprecation proposal would likely be controversial given it would break existing configurations.
