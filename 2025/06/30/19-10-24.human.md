Documentation patch standardizing terminology in git-config man page. This is part 2 of a 5-patch series updating the config documentation following recent subcommand changes.

The patch addresses an inconsistency in how the `--value` option is described in the man page. While the option was introduced with both `--value=<value>` and `--value=<pattern>` forms used in different sections, this change standardizes on `--value=<pattern>` throughout. The rationale is that "pattern" better describes the general case behavior, since the option can accept regular expressions when used with `--regexp`.

The changes are mechanical, touching only the synopsis section of git-config.adoc to make all three occurrences of the option (`get`, `set`, and `unset` subcommands) use the `<pattern>` form. The patch builds on previous work from the ps/config-subcommands series merged in May 2024.

This appears to be a straightforward documentation cleanup with no behavioral implications. The change aligns with the thread's overall goal of polishing the config documentation after recent feature additions.
