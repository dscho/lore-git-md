Thread identity: Bug report about credential helper behavior in Git, specifically regarding credential persistence after failed push operations. Originating from a Gitea/AGit workflow using git-credential-oauth helper.

Core problem: Git's credential helper interface appears to clear stored authentication tokens after failed push operations, forcing unnecessary re-authentication even when credentials remain valid. This creates friction particularly in OAuth flows where re-authentication is disruptive. The issue affects all credential helpers but is particularly noticeable in OAuth-based workflows like AGit with Gitea.

Current status: Initial report only - no patches or solutions proposed yet. The reporter references Gitea issue #34583 documenting the behavior but indicates this is a Git-level issue.

Key technical details: Behavior occurs during push operations when authentication fails - credential helpers appear to clear stored tokens rather than preserving them for subsequent attempts. The git-credential-oauth helper is specifically mentioned but the issue would affect any credential helper integration.

Open questions: Should Git modify credential persistence behavior during failed operations? How should credential helpers handle failed authentications - preserve credentials or clear them? What would be the security implications of preserving credentials after failures?

Related work: Gitea issue #34583 documents the observed behavior in AGit workflows but identifies the root cause as being in Git's credential helper interface.
