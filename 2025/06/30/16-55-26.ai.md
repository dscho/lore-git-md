This is a bugfix patch in the ongoing series to implement diff context configuration support for interactive patch commands. The patch focuses specifically on making the add-patch infrastructure respect `diff.context` and `diff.interHunkContext` configurations, which were previously ignored since the plumbing commands (diff-files, diff-index) don't read these configs by design.

Junio C Hamano provides detailed review feedback on the implementation. He notes that the commit message could better explain why this change is needed (users expect consistent diff context behavior) and suggests clearer phrasing. He questions the use of temporary variables in the config reading code, proposing direct assignment to struct fields instead. The patch adds new fields to `struct add_i_state` and passes the configured values to the underlying diff commands via `--unified` and `--inter-hunk-context` options.

The technical changes include:
- Adding `context` and `interhunkcontext` fields to `struct add_i_state`
- Reading and validating these values in `init_add_i_state()`
- Passing the values through to diff commands in `parse_diff()`
- Rejecting negative values with appropriate error messages

Junio's review focuses on code clarity and commit message quality rather than functional issues. He suggests simplifying the variable flow and making the rationale more explicit. The patch appears technically sound but could benefit from incorporating these style and documentation improvements before final acceptance. This is part of the final polishing phase of a comprehensive series that has already addressed test modernization, documentation, and edge case handling.
