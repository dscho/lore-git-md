Bugfix discussion regarding `git branch -a` output format compatibility. Kristoffer Haugsbakk responds to Olaf Hering's report about unexpected "remote/HEAD -> remote/branch" lines appearing in `git branch -a` output since Git 2.50. The thread previously established this as a behavioral change affecting parsing scripts, tied to the presence of `.git/refs/remotes/${remote}/HEAD` files.

Haugsbakk proposes an alternative command (`git for-each-ref --format='%(refname:short)' --exclude='**/HEAD'`) as a stable workaround that avoids the problematic HEAD references. This suggestion directly addresses the script compatibility issue while sidestepping the need for configuration options or manual filtering of the `git branch` output. The response focuses on practical mitigation rather than debating the behavior change itself, suggesting the thread may be moving toward resolution with this workaround. The proposed solution uses existing Git plumbing commands with stable output formats, making it robust against future changes in `git branch` output formatting.
