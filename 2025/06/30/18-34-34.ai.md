Junio Hamano responds to the first patch in Raymond Pasco's series fixing `git apply --intent-to-add` behavior. This is a safety check that prevents using `--intent-to-add` outside a Git repository.

Hamano questions the patch's rationale, noting that the current behavior of silently ignoring `-N` (intent-to-add) when used outside a repository (or without `--index`/`--cached`) as a "better GNU patch" mode also makes sense. He suggests the justification "it makes no sense" doesn't necessarily lead to the conclusion that we should error out rather than silently ignore.

The technical change modifies `check_apply_state()` in `apply.c` to return an error when `--intent-to-add` is used outside a Git directory, while maintaining the existing behavior of turning off `ita_only` when used with `--check-index`. The patch builds on Johannes Altmanninger's prior work but may need stronger justification for changing from silent ignore to error behavior.

This appears to be the first review feedback on the series, focusing on the design rationale rather than implementation correctness. The discussion may need to address whether erroring out provides better UX than silent ignore for this edge case.
