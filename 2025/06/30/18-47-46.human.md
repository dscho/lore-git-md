This is a technical discussion about patch 2/5 in the `git apply --intent-to-add` bugfix series. Junio Hamano, Git's maintainer, is responding to Raymond Pasco's patch that fixes how `git apply -N` reads the index.

The core issue is that `--intent-to-add` mode wasn't properly reading the index before making changes, which made the feature effectively broken except in empty repositories. Raymond's patch changes `read_apply_cache()` to read the index whenever it will be either checked or updated, not just when checking (the original behavior).

Junio agrees with the technical approach but raises a conceptual question about whether writing only intent-to-add entries to the index makes sense at all, hinting this might need deeper consideration. He also notes he's the original author of the related `git add -N` feature, lending weight to his perspective.

This exchange shows the patch is moving forward technically but may need additional justification for its design choices. The discussion is focused and constructive, with Junio acknowledging the technical soundness while flagging potential higher-level concerns.
