This is a follow-up in the thread about `git branch -a` output format differences. Junio C Hamano clarifies that the appearance of "remote/HEAD -> remote/branch" lines is not a version difference between Git 2.43 and 2.50, but rather depends on whether `.git/refs/remotes/${remote}/HEAD` exists in the repository. He suggests testing this by using `git remote set-head origin -a` in the older repository to see if the behavior matches.

The email reinforces that `git branch` output is meant for humans and subject to change, recommending scripts use `git for-each-ref` instead for stable parsing. This aligns with Kristoffer Haugsbakk's earlier proposed solution in the thread. The discussion appears to be converging on the position that this isn't a bug to fix in `git branch`, but rather a case where scripts should use plumbing commands rather than porcelain output. No new technical details or proposals are introduced in this message - it primarily serves to confirm the behavioral root cause and reiterate the porcelain/plumbing distinction.
