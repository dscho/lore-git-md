This is a bugfix addressing a memory leak in `send-pack`'s handling of the `extra_have` oid array, following up on Jacob Keller's original patch. The leak occurs when pushing to repositories that use alternate object stores, where certain objects are marked as "extra" to help with common ancestor calculation.

Junio C Hamano confirms the fix is correct and provides additional context about when the `extra_have` array gets populated - specifically when pushing to repositories created with `--reference` that borrow objects from another local repository. He also suggests enhancing the test suite to catch similar issues by having tests push into such repositories.

The patch itself is minimal - just adding a single `oid_array_clear()` call alongside existing cleanup code for the similar `shallow` array. While the fix is straightforward, the discussion highlights an interesting gap in test coverage that allowed this leak to go unnoticed. The exchange demonstrates good collaboration, with the maintainer both validating the fix and thinking about how to prevent similar oversights in the future.
