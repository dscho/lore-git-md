This thread discusses a compatibility issue in `git branch -a` output that emerged between Git 2.43 and 2.50, where the command now includes "remote/HEAD -> remote/branch" lines when showing remote branches. The change affects scripts that parse this output, as the new format wasn't documented in the man pages and provides no configuration option to suppress these lines.

Kristoffer Haugsbakk has proposed a practical workaround using `git for-each-ref` with specific formatting to exclude HEAD references entirely, which provides stable output for scripting purposes. This approach sidesteps the need for configuration changes or manual filtering of `git branch` output. While the behavioral change in `git branch` itself remains unaddressed, the thread appears to be converging on this plumbing-based solution as the recommended way forward for affected scripts. The discussion has remained focused on practical mitigation rather than debating the merits of the original change.
