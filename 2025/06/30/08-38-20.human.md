This is a refactoring patch that modifies Git's clang-format configuration to disable automatic line wrapping. It's part of a series improving Git's code formatting tools.

The patch removes the 80-character ColumnLimit from .clang-format, acknowledging that while 80 columns is the project's guideline, strict enforcement creates too many false positives and undesirable line concatenation. The author notes past attempts to tweak line break penalties (in 2017 and 2024) didn't fully solve the problem.

By setting ColumnLimit to 0, line wrapping responsibility shifts to developers rather than the formatter. The patch keeps the 80-character recommendation in Documentation/CodingGuidelines while removing the automated enforcement. A NEEDSWORK comment suggests future work to find better penalty settings that could allow re-enabling the limit.

The change is well-motivated and follows discussion in the thread about making clang-format more usable while maintaining code quality. The patch is straightforward, only modifying the .clang-format configuration file with clear explanatory comments.
