This is a feature patch series introducing a new `git last-modified` command, which tracks when files were last modified in the repository history. The series represents a rebased and refined version of earlier work from GitHub engineers, now submitted by Toon Claes.

The command provides path modification tracking by walking history backwards, with several notable characteristics:
- Non-recursive by default (use `-r` for recursion)
- Uses Bloom filters when available for significant performance gains (50%+ speedup in some cases)
- Has comprehensive test coverage including merge scenarios
- Marked as experimental in documentation

Key changes in this v3:
- Renamed from `blame-tree` to `last-modified` based on mailing list feedback
- Removed some performance patches that showed inconsistent results
- Improved error handling and memory management
- Added Bloom filter optimization (5-7x speedup in testing)
- Cleaned up code organization and documentation

The series is in good technical shape with active review discussion ongoing. The experimental marker remains while final polish is applied, particularly around documentation and some Bloom filter edge cases. Performance looks promising but some scenarios still need optimization work. This appears ready for serious consideration as a new plumbing command once the remaining review feedback is addressed.
