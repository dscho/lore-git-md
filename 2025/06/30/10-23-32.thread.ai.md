Bug report and discussion regarding `git branch -a` output format change between Git 2.43 and 2.50, where the command now includes "remote/HEAD -> remote/branch" lines when showing remote branches. The change affects parsing scripts that expect the older format, with the behavior tied to `.git/refs/remotes/${remote}/HEAD` files and undocumented in git-branch(1). Kristoffer Haugsbakk proposes a stable workaround using `git for-each-ref --format='%(refname:short)' --exclude='**/HEAD'` to avoid the problematic HEAD references, providing a robust solution that sidesteps the need for configuration options or manual filtering. The thread appears to be moving toward resolution with this plumbing-based approach, which offers predictable output formatting unaffected by future changes to `git branch` behavior. No core changes or configuration options have been proposed yet to modify the default `git branch -a` output.
