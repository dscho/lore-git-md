Bug report and discussion about `git branch -a` output format variations, where "remote/HEAD -> remote/branch" lines appear only when `.git/refs/remotes/${remote}/HEAD` files exist. Junio C Hamano identified this as the root cause, disproving the initial theory about Git version differences between 2.43 and 2.50. Olaf Hering confirmed the diagnosis by reproducing the behavior in an older repository using `git remote set-head origin -a` to create the missing remote HEAD reference. The thread establishes that `git branch` is porcelain (human-oriented) output subject to change, while scripts must use plumbing commands like `git for-each-ref` for stable parsing. Kristoffer Haugsbakk's solution using `git for-each-ref --format='%(refname:short)' --exclude='**/HEAD'` remains the recommended approach, with Hering reporting successful adoption in their scripts. No changes to `git branch` behavior are proposed - the resolution path is firmly established as using plumbing commands when programmatic parsing is required. The discussion is effectively closed with consensus on the porcelain/plumbing distinction and workaround implementation.
