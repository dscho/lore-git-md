Bugfix for Git daemon's socket handling during interrupted system calls (EINTR). This is the final approval for the patch series that fixes how the Git daemon handles interrupted `accept()` calls. The patch has gone through three iterations with feedback from reviewers, and now Phillip Wood has given his approval with "This looks good". Junio C Hamano is ready to mark the topic for inclusion in the 'next' branch.

The fix addresses a long-standing issue dating back to 2005 when IPv6 support was added. Previously, when `accept()` was interrupted (EINTR), the daemon would incorrectly move to the next socket instead of retrying the same one. The current version implements a retry mechanism (3 attempts) while maintaining the existing error fallthrough logic.

All requested changes from previous rounds have been incorporated, including unified variable declarations and reordered error handling that puts EINTR first. While there was one remaining technical question about SA_RESTART interaction, it appears this won't block merging. The patch is focused and makes just 12-13 line changes to daemon.c's service_loop() function.

With Phillip Wood's approval and all stylistic refinements addressed, this bugfix appears ready for merging into the Git codebase.
