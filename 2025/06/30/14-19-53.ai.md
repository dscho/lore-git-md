Follow-up confirmation in the `git branch -a` output format thread. Olaf Hering confirms Junio Hamano's earlier diagnosis that the presence of "remote/HEAD -> remote/branch" lines in `git branch -a` output depends on whether `.git/refs/remotes/${remote}/HEAD` files exist, not on version differences between Git 2.43 and 2.50 as originally suspected. The behavior discrepancy was due to an older repository clone lacking default branch configuration rather than a Git version change.

Hering reports successfully reproducing the output format behavior in the older repository by using `git remote set-head origin -a` as suggested, which creates the missing remote HEAD reference. The email concludes with Hering stating they've modified their script to use `git for-each-ref` instead of `git branch -a`, adopting the plumbing command approach previously recommended in the thread for stable script parsing. This confirms the thread's resolution path of using plumbing commands rather than modifying porcelain behavior.
