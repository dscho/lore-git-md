Documentation patch improving style and consistency in `git-for-each-ref` manpage. This is part of the ongoing documentation standardization effort that runs parallel to the `git refs list` command proposal discussion.

Junio C Hamano reviews Jean-Noël Avila's patch that cleans up the `git-for-each-ref` documentation, noting it makes several clear improvements while pointing out some remaining inconsistencies. The changes include standardizing option syntax (adding spaces between grouped options, using `_<placeholder>_` convention), tightening wording (removing redundant explanations), and fixing a stray space in `--format[=<format>]` syntax.

The maintainer observes the patch stops short of fully converting to the newer `[synopsis]` format and leaves some opportunities for further standardization, like consistently using `_<count>_` notation. However, he acknowledges these are follow-up opportunities rather than flaws, and the current changes are all positive. The review suggests this is part of a broader documentation polish that's proceeding independently of the `git refs list` command design discussion.
