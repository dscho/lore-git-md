This is a follow-up in the `git branch -a` output format discussion. Olaf Hering confirms Junio Hamano's earlier explanation that the presence of "remote/HEAD -> remote/branch" lines depends on whether `.git/refs/remotes/${remote}/HEAD` files exist, not Git version differences. 

Hering notes that in his older repository, the remote HEAD wasn't initially set (possibly due to being cloned long ago before default branches were automatically configured). He has updated his script to use `git for-each-ref` as recommended, which provides stable output unaffected by porcelain command variations.

The thread has effectively concluded with this confirmation, establishing that the original behavior was expected and that scripts should use plumbing commands rather than parsing `git branch` output. No further action appears needed beyond the documented workaround.
