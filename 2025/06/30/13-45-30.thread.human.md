This thread discusses Git's behavior of clearing stored credentials after failed operations, which causes friction in OAuth workflows like those used with Gitea/AGit. The original reporter highlighted how this forces repeated authentication when operations fail for non-credential reasons. Maintainer Brian M. Carlson confirmed this is intentional security design to prevent lockouts from persistent bad credentials, suggesting a custom credential helper as the only viable workaround.

In a follow-up, Michal Suchánek clarifies that their credentials remain valid - it's the operations that fail, not the authentication. They argue against the custom helper solution, wanting a simpler way to preserve valid credentials without additional complexity. The discussion reveals a fundamental tension: Git's security model treats any failure as potentially credential-related, while users want to distinguish between authentication failures (where clearing makes sense) and operation failures (where it doesn't).

The thread remains at an impasse between security requirements and workflow needs. While the maintainer position is clear - the current behavior is working as designed - the user perspective highlights real usability pain points, particularly for OAuth flows. No technical solution has emerged that satisfies both security constraints and user convenience.
