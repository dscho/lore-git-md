This thread addresses a subtle bug in Git's daemon process that could leave zombie processes unreaped under certain signal timing conditions. The issue dates back to 2008 when the child reaping logic was moved out of the SIGCHLD handler, and persisted through a 2010 refactoring.

The patch fixes the problem by properly handling EINTR (interrupted system call) errors from waitpid(), which could previously prevent cleanup of zombie processes. The solution maintains the existing behavior for successful cases while adding explicit EINTR handling and converting other waitpid() errors into BUG() reports to catch programming mistakes. The change makes the daemon more robust against signal interruptions while improving debuggability for unexpected conditions.

The technical modifications focus on daemon.c, carefully preserving correct behavior for normal cases (pid > 0 or pid == 0) while adding proper error handling for the EINTR case that could occur in normal operation. Other error conditions now trigger BUG() reports with descriptive messages including the problematic PID.
