This thread addresses a long-standing bug in git-daemon's signal handling where interrupted `waitpid()` calls (EINTR) could leave zombie processes. The original patch from Carlo Marcelo Arenas Belón modifies `daemon.c` to properly retry on EINTR while treating other errors as bugs, fixing an issue that persisted since 2008.

Phillip Wood has reviewed the patch and agrees with the technical approach but suggests several refinements: improving style consistency by adding braces to match Git's guidelines, reconsidering the unsigned cast for `pid_t` given POSIX specifications, and clarifying in the commit message whether EINTR with WNOHANG is platform-specific behavior (as Linux's manpage claims it shouldn't occur). The core fix remains sound, but these observations highlight areas where the implementation could be made more robust or better documented.

The discussion remains focused on technical correctness, with no outstanding objections to the fundamental change. The author will likely send a v2 addressing these review points while maintaining the patch's core behavior of proper EINTR handling and debuggable error reporting.
