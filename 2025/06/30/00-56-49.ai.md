This is a technical clarification in the `git apply --intent-to-add` bugfix thread. Raymond Pasco responds to Lidong Yan's observation about patch 3/5's behavior aligning with `git add --intent-to-add`, providing deeper rationale for the current implementation.

The email explains two key reasons why the test in `create_file()` must ignore existing index entries: First, because the filesystem already contains the file (making creation impossible), and second because the intent-to-add mode should generally avoid modifying the index except for new files. The example given shows that without this check, applying a mixed patch (modifying existing file A while creating new file B) would incorrectly update the index entries for both files when it should only affect B.

This reinforces the technical correctness of patch 3/5's approach while providing additional context about the index interaction constraints. The explanation ties back to the series' core goal of properly isolating intent-to-add behavior to new files while maintaining index consistency. No new changes are proposed - this is purely an explanatory follow-up confirming the design decisions in the patch series.
