This is a bugfix patch addressing signal handling in the Git daemon's child process reaping logic. The change focuses on properly handling EINTR (interrupted system call) errors from waitpid() that could prevent timely cleanup of zombie processes.

The patch fixes a long-standing issue dating back to 2008 when the child reaping logic was moved out of the SIGCHLD handler. While the 2010 refactoring to use run-command API reproduced the bug, it remained unnoticed that a badly timed signal could cause waitpid() to fail with EINTR, potentially leaving a single process unreaped. The solution adds proper error handling for EINTR while also converting other waitpid() errors into BUG() reports to catch programming mistakes.

The technical changes modify daemon.c to:
1. Preserve the existing behavior for successful waitpid() calls (pid > 0) and no-child cases (pid == 0)
2. Explicitly handle EINTR by retrying the waitpid() (implied by the control flow)
3. Treat all other errno values as bugs with a descriptive message including the problematic PID

The patch appears well-motivated by historical context and makes a focused, defensive change to improve reliability. The BUG() addition provides better debuggability for unexpected conditions while maintaining the original behavior for the EINTR case that could occur in normal operation.
