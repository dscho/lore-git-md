Documentation patch standardizing terminology in git-config.adoc. This is part 2 of a 5-patch series updating the config documentation following the ps/config-subcommands merge.

The patch addresses an inconsistency in how the `--value` option is described in the man page. While the option was introduced with two different phrasings (`--value=<value>` in the synopsis vs `--value=<pattern>` in deprecated modes), this change standardizes on the latter form throughout. The rationale is that `pattern` better reflects the option's behavior since it can accept regex patterns, not just literal values.

The changes are mechanical, touching only the synopsis section of git-config.adoc to update three instances where `--value=<value>` appeared. The patch references the original introduction of these options in fe3ccc7aab (Merge branch 'ps/config-subcommands') as historical context.

This is a straightforward documentation cleanup that aligns with the thread's overall goal of polishing the config subcommand documentation. The change doesn't affect functionality, only terminology consistency. The patch follows the series' pattern of focused, non-controversial doc improvements verified against actual behavior.
