Performance test addition for the new `git last-modified` command. This is part of the v3 series implementing a plumbing command to track file modification history. The patch adds a basic performance test script that measures three scenarios: simple top-level operation, recursive traversal, and subdirectory-specific checks. 

The tests are designed to catch performance changes between versions rather than test correctness (which is covered elsewhere). The scenarios are well-chosen to exercise different aspects of the command's operation - from basic functionality to path handling. 

This follows the pattern of other performance tests in the Git test suite, with simple but representative cases. The implementation is straightforward, using existing test infrastructure (`perf-lib.sh`) and standard Git test patterns. The patch builds on prior work from Jeff King and fits cleanly into the existing test framework.

As part of the ongoing series, this helps ensure the command's performance characteristics remain stable as the implementation evolves. The test will be particularly valuable for monitoring the impact of the Bloom filter optimizations introduced earlier in the series.
