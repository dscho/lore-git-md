Platform compatibility response from Git for Windows maintainer Johannes Schindelin regarding the DFS-mounted network drive issue. This follows up on Erwan Leroy's report of "Permission denied" errors when writing config files on DFS paths in Git versions 2.36+, working fine on direct UNC paths and in Git <=2.21.

Schindelin notes the error message ("Permission denied") is unexpected given his initial suspicion about Git's POSIX-semantics rename() emulation on Windows, since the issue predates that feature's introduction. He provides resources to help investigate: a complete archive of pre-compiled Git for Windows versions at gitforwindows.org/git-snapshots/ (though acknowledges finding specific versions is cumbersome), and pointers to both Git's and Git for Windows' release notes (RelNotes directory and ReleaseNotes.md respectively).

Key technical details emerging: the issue specifically manifests when accessing through DFS but not direct UNC paths, with Schindelin seeking clarification on whether the `Y:\` drive vs `\\atl-xx\Basecamp` paths in the DFS/UNC distinction. The response maintains focus on Windows-specific filesystem behavior while providing investigation tools, though no immediate solution is proposed beyond the previously mentioned WSL workaround. The thread remains open with the core issue still not root-caused.
