This thread started with Dan Pristupov reporting what appeared to be a regression in Git 2.50 for Windows, where `git cat-file --filter "HEAD:changelog.md"` stopped working with a "fatal: invalid filter-spec" error. The initial suspicion was that this stemmed from a recent commit handling NULL object_context.path cases.

Phillip Wood has since clarified that this isn't actually a regression, but rather a case of an abbreviated option name (`--filter`) no longer being accepted where it once was. The correct long form has always been `--filters` (plural), and while the abbreviated version worked in earlier releases, scripts should use the full option name for stability. This explains the behavior change without needing to attribute it to any particular commit. The takeaway is that users should update their scripts to use `--filters` rather than `--filter` going forward.
