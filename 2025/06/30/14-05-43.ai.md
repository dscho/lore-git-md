This is a maintainer response in the ongoing `git refs list` command consolidation discussion. He draws parallels to how `git branch` and `git tag` listing modes already reuse `for-each-ref` infrastructure while providing more discoverable command organization.

The email responds to a previous unclear statement from shejialuo about potentially replacing `for-each-ref` entirely, with Hamano emphasizing that wrapper-style implementation would satisfy the discoverability goal without disrupting existing users. This reinforces his earlier concerns about feature divergence while offering a concrete technical path forward that maintains compatibility.

Key technical points include the precedent of other commands (`branch`, `tag`) using this wrapper pattern, and the implication that `refs list` could similarly delegate to `for-each-ref` while presenting a more organized command structure. The response continues the thread's focus on interface design philosophy rather than implementation details, with Hamano steering toward solutions that don't create maintenance burdens through code duplication.
