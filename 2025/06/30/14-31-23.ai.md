This is a bugfix addressing a memory leak in `send-pack`'s handling of the `extra_have` oid array, following up on Jacob Keller's original patch. The thread has established that this is a genuine leak (2160-byte allocation) that occurs during push operations when the `extra_have` array gets populated, though existing tests in t5539 don't exercise this path.

Junio C Hamano confirms the correctness of Jacob's fix, which mirrors the cleanup pattern used for the shallow oid array. He also provides useful context about when `extra_have` gets populated - specifically when pushing to repositories that use alternate object stores (created via `--reference` clones), where refs from the alternate that point to objects not in the target repository are considered "extra" objects. This explains why the leak wasn't caught by tests, as standard test scenarios don't typically involve such alternate configurations.

The discussion suggests a potential test improvement - modifying t5539 to push into a repository with an alternate object store to properly exercise this code path. However, the immediate patch is straightforward and correct, just adding the missing `oid_array_clear(&extra_have)` alongside the existing cleanup code in `cmd_send_pack`. The fix is uncontroversial and addresses a real issue that would affect users performing pushes in repositories with alternate object stores.
