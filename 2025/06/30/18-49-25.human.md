Performance optimization for the experimental `git last-modified` command. This third patch in the v3 series adds Bloom filter support to skip unnecessary diff computations during the revision walk. When checking if a commit modified any tracked paths, it first consults the commit's Bloom filter - if the filter indicates no possible changes, it can skip the expensive diff entirely.

The patch shows significant speedups in the performance tests: 50% faster for top-level checks and 36% faster for subdirectory checks. The recursive case sees minimal improvement since it still needs to walk subtrees. The implementation adds Bloom key management to the path tracking structures and introduces a new `maybe_changed_path()` helper to consult the filters.

This builds on Taylor Blau's prior Bloom filter work and represents one of the final optimizations for the command. The changes are focused and well-contained, touching only `last-modified.c` with clear memory management for the new Bloom keys. With this addition, the series appears technically complete, though still marked EXPERIMENTAL pending documentation polish.
