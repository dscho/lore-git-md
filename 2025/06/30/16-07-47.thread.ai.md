Bug report for `git cat-file --filter` vs `--filters` behavior change in Git 2.50 on Windows. Dan Pristupov initially reported the command fails with "fatal: invalid filter-spec" when using `--filter "HEAD:changelog.md"`, working in 2.47.1.windows.2 but broken in 2.50.0.windows.1. Phillip Wood clarifies this is not a regression from commit eb83e4c64b as suspected, but rather a change in accepting abbreviated options - the correct long option has always been `--filters`, and prior versions were lenient in accepting `--filter` which is no longer working in Git 2.50. Key technical details: the command format must use `--filters` (plural) rather than `--filter`, error message remains "fatal: invalid filter-spec", affected versions 2.50.0.windows.1 vs working 2.47.1.windows.2. Phillip notes that while abbreviated options are useful interactively, scripts should use full option names for stability. This appears to be an intentional tightening of option parsing rather than a bug, though the change in behavior affects real usage scenarios on Windows. The thread has shifted from investigating a regression to documenting an intentional change in option parsing behavior.
