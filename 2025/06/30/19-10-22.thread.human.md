This thread documents post-merge cleanup of the `git-config` subcommands series, focusing on terminology inconsistencies between documentation and implementation. The original 5-patch series standardized command-line options in the man page but missed some test t0450.142, which checks synopsis consistency between documentation and `-h` help output. 

Kristoffer Haugsbakk, the documentation contributor, has acknowledged they didn't run t0450 during preparation, which allowed a terminology mismatch to slip through: the documentation now uses `--value=<pattern>` while the help text still shows `--value=<value>`. This came to light when the test failed after the changes were merged. 

The series built on three key commits (4e513890008, d4770964d50, fe3ccc7aab) and documented several new options including `--[no-]show-names` and `--url`. While most instances were updated from `value-pattern` to `--value=<pattern>`, some `--value=<value>` references remain in the docs. Eric Sunshine previously noted a minor formatting issue in the series.

The core question now is which terminology to standardize on - updating either the help text to match the documentation's `<pattern>` or vice versa. This serves as a case study in how testing gaps can allow inconsistencies to persist, even in mechanical documentation updates. The thread remains open pending resolution of this terminology question.
