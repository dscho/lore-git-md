This is the first patch in a v3 series introducing a new `git last-modified` command, which tracks when paths in a tree were last changed. The command works similarly to `git blame` but operates at the tree level rather than line-by-line. The implementation walks commits backwards to find when each path transitioned to its current state.

The patch establishes the core functionality with:
- A new `last-modified.[ch]` library handling the revision walking logic
- The `builtin/last-modified.c` command interface
- Comprehensive tests in `t/t8020-last-modified.sh` covering basic cases, recursion, subdirectories, revision ranges, and merge scenarios
- Documentation marked as EXPERIMENTAL

The command supports recursive traversal (-r) and showing tree entries (-t). Performance optimizations using Bloom filters (added in later patches) show 2-5x speedups. The implementation appears solid with thorough test coverage, though some documentation and style nits remain to be addressed in review.

This builds on prior work from Jeff King and Ævar Arnfjörð Bjarmason, with the series now in its third revision after community feedback renamed it from `blame-tree` to `last-modified`. The patch looks production-ready aside from the experimental marker and minor polish items noted in the thread.
