This is a bug report concerning credential helper behavior in Git. The reporter describes an issue where failed push operations appear to clear previously stored authentication tokens from credential helpers, forcing unnecessary re-authentication. The specific scenario involves using AGit (a Gitea workflow) with the git-credential-oauth helper, where multiple authentication prompts occur even when pushing to repositories where access should already authorized.

The core problem seems to be that Git's credential helper interface may be too aggressive in clearing credentials after failed operations, rather than preserving them for subsequent attempts. This behavior is particularly problematic for OAuth flows where re-authentication creates friction. The reporter suggests preserving credentials across failed operations would be more user-friendly.

The report references a specific Gitea issue (#34583) documenting this behavior, though the underlying problem appears to be in Git's credential helper handling rather than Gitea-specific. No patch is provided - this is purely an issue report seeking discussion about whether and how to modify credential persistence behavior during failed operations. The behavior described would affect any credential helper integration, not just OAuth-based ones.
