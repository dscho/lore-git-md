This is the first patch in a v3 series introducing a new `git last-modified` plumbing command, part of a feature implementation that has evolved through multiple revisions with significant community input. The command tracks file modification history by walking commits backwards to find when each path last changed to its current state.

The patch establishes core functionality in `last-modified.[ch]` with:
- A `last_modified_entry` struct for path tracking via hashmap
- Command interface in `builtin/last-modified.c`
- Initial test coverage in `t/t8020-last-modified.sh` (basic cases, recursion, subdirectories, revision ranges)
- Documentation in `Documentation/git-last-modified.adoc` marked as EXPERIMENTAL

Key behaviors shown in tests:
- Non-recursive mode shows only direct modifications
- `-r` recurses into subtrees
- `-t` includes tree entries themselves
- Handles merge commits and conflict resolutions
- The implementation uses diff callbacks to track path changes during revision walks
- Error handling for invalid arguments and multiple tree cases
- Memory management via `last_modified_release()`

The patch builds on prior work from Jeff King and Ævar Arnfjörð Bjarmason, with the thread history showing this is part of an active discussion about performance optimizations (particularly Bloom filter integration) and documentation practices. The experimental marker remains while the implementation stabilizes.
