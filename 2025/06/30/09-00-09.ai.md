This is a review response in the ongoing git-daemon signal handling bugfix thread. Phillip Wood agrees with Carlo Marcelo Arenas Belón's analysis of the EINTR handling issue in child process reaping but raises several technical points about the implementation:

1. Style consistency: Notes that Git's style guidelines require braces on all if-clauses when any one has them, suggesting the patch should add braces to the `else if (!pid)` case.

2. Platform considerations: Questions whether the unsigned cast (PRIuMAX) for pid_t is appropriate since POSIX specifies pid_t as signed, and wonders about portability implications for platforms with unusually wide pid_t types.

3. Error handling approach: While agreeing BUG() is correct for non-EINTR errors, Phillip suggests the commit message could clarify that Linux's waitpid() manpage claims EINTR can't occur with WNOHANG, and questions whether this holds across other platforms.

The review maintains the thread's technical focus on robust signal handling while surfacing specific implementation details that may need addressing. Phillip's comments indicate the patch is fundamentally sound but could benefit from minor refinements in style consistency and platform-aware coding.
