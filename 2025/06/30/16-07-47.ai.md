Bugfix for `git cat-file --filter` regression in Git 2.50.

Dan Pristupov reports a regression where `git cat-file --filter` stopped working in Git 2.50.0.windows.1, while it previously worked in 2.47.1. The command now fails with "fatal: invalid filter-spec" when given a path like "HEAD:changelog.md". The regression appears to have been introduced in commit eb83e4c64b ("cat-file: handle NULL object_context.path", 2024-05-20) and merged via a271b05066.

The report provides clear reproduction steps showing the behavior difference between versions, but doesn't analyze the root cause or propose a fix. The commit mentioned (eb83e4c64b) was part of a series to handle NULL object_context.path cases, suggesting the filter parsing may have been unintentionally affected. This appears to be a genuine regression that breaks existing functionality, though the impact seems limited to Windows users based on the version strings shown.

Key technical points for future reference:
- Broken command: `git cat-file --filter "HEAD:path"`
- Working version: 2.47.1.windows.2
- Broken version: 2.50.0.windows.1
- Suspect commits: eb83e4c64b and a271b05066
- Error message: "fatal: invalid filter-spec"

The report is straightforward but lacks analysis of why the filter spec parsing fails or whether there are workarounds. The regression appears significant enough to warrant attention from Windows users and maintainers familiar with the cat-file and object context handling code.
