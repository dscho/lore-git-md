Bugfix/behavior change report regarding `git branch -a` output format.

This email reports an observable change in behavior between Git 2.43 and 2.50 where `git branch -a` now includes "remote/HEAD -> remote/branch" lines in its output when showing remote branches. The reporter notes this is causing issues for scripts that parse the output, as their system with Git 2.50 shows these additional lines while their older Git 2.43 system does not.

The key technical details are:
- The change appears related to the presence of `.git/refs/remotes/${remote}/HEAD` files
- The reporter confirms this isn't documented in git-branch(1) manpage
- No configuration option exists to suppress these lines
- Current workaround would require manual filtering

This appears to be either an undocumented behavior change or potentially a side effect of repository format differences between the two systems. The reporter is specifically looking for either a way to suppress these lines through configuration or confirmation that manual filtering is necessary. The issue affects script compatibility but doesn't appear to be a bug per se - rather a behavioral difference between versions that breaks existing parsing logic.
