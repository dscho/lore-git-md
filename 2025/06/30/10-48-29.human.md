Windows DFS-mounted network drive regression investigation. Johannes Schindelin responds to Erwan Leroy's report of "Permission denied" errors when writing Git config files on DFS paths in Git 2.36+. 

Schindelin notes the error message is unexpected given his initial suspicion about Git's POSIX-style `rename()` emulation on Windows, since the issue predates that feature. He provides useful resources for further investigation: a repository of pre-compiled Git for Windows versions to help pinpoint the regression, and pointers to the Git and Git for Windows changelogs.

Key new information emerges from the problem only manifests with DFS paths, not direct UNC paths, suggesting a filesystem-specific issue. Schindelin seeks clarification on whether the `Y:\` drive mapping (which shows DFS-related errors) versus direct `\\atl-xx\` UNC paths exhibit different behavior. 

The response moves the investigation forward by providing concrete tools for version testing and narrowing the focus to DFS-specific behavior, while maintaining that the root cause remains unclear. The tone is helpful and engaged, characteristic of Schindelin's maintainer role in Git for Windows.
