Signal handling refactoring in the Git daemon, part 3 of a 4-patch series addressing platform-specific signal behavior. This patch transitions from `signal()` to `sigaction()` for installing the SIGCHLD handler, preparing for future flag modifications while also simplifying the handler by removing the manual rearming requirement (previously needed for SysV compatibility).

The change introduces BSD semantics consistently by using `sigaction()` with `SA_NOCLDSTOP` and `SA_RESTART` flags, eliminating the need for the handler to re-register itself. The empty handler remains as documentation that system calls should be interrupted upon signal receipt. This builds on the series' architectural improvements to signal handling while maintaining compatibility across platforms.

Key technical details:
- Replaces `signal(SIGCHLD, child_handler)` with full `sigaction()` setup
- Sets `SA_NOCLDSTOP` to avoid notifications for stopped (vs terminated) children
- Retains `SA_RESTART` flag for consistent behavior with series' approach
- Removes handler's signal rearming code (now handled by BSD semantics)
- Modifies only `daemon.c`, specifically the service loop initialization
- Prepares for subsequent flag changes in the series

This patch represents an incremental improvement within the broader signal handling discussion, implementing one of the agreed-upon technical changes (standardizing on `sigaction()`) while leaving the higher-level architectural decision (SA_RESTART toggling vs self-pipe) for later resolution. The implementation appears clean and focused, with the commit message clearly explaining both the immediate benefit and future-proofing aspect of the change.
