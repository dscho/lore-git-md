Bugfix for commit message comment character selection during rebase conflicts. This is a follow-up to Ayush Chandekar's initial patch that addressed how Git handles auto-selected comment characters when conflict markers are present.

Junio C Hamano reviews the patch, confirming it correctly modifies `adjust_comment_line_char()` in builtin/commit.c to ignore trailing comment blocks (like conflict sections) when selecting a comment character. The change prevents Git from unnecessarily switching comment characters when it encounters conflict markers, which could otherwise cause those markers to appear in final commit messages.

The review notes the patch builds on two historical changes: 84c9dc2c which introduced auto-selection of comment characters, and a6c2654 which introduced the bug by adding conflict comments to rebase messages. The implementation adds a cutoff point using `ignored_log_message_bytes()` to properly scope the character scanning.

Junio describes the patch as "straight-forward" and gives it a positive review with no suggested changes. The fix maintains backward compatibility while solving a specific edge case in rebase operations where users have `core.commentChar` set to "auto". The patch appears ready for inclusion with its existing test coverage.
