Windows platform compatibility patch for SIGCHLD signal handling in the ongoing Git daemon signal handling series.

This patch enables `sigaction()` support for SIGCHLD on Windows (mingw) in preparation for future changes to the Git daemon's signal handling. The current implementation returns -1 for SIGCHLD (matching the behavior of `signal()` which returns SIG_ERR) while maintaining existing SIGALRM functionality. It also adds the SA_NOCLDSTOP flag definition needed for proper signal handling infrastructure.

The changes are minimal but important for Windows compatibility in the broader signal handling rework, touching both the mingw POSIX compatibility header and implementation file. This appears to be a straightforward technical prerequisite for the architectural decision between SA_RESTART toggling and self-pipe approaches discussed in the thread.

Key technical details for future reference:
- Adds SA_NOCLDSTOP constant (1) in mingw-posix.h
- Modifies sigaction() in mingw.c to handle SIGCHLD with -1 return
- Maintains existing SIGALRM behavior
- Follows same error pattern as signal() (returns -1 without setting errno)
- Part of building blocks for Windows support in either signal handling approach

The patch is narrowly focused on Windows compatibility and doesn't take a position in the ongoing architectural discussion. It appears technically sound for its stated purpose, with the simple addition and modification following established mingw compatibility patterns.
