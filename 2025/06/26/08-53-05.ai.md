This is a platform compatibility patch in the ongoing Git daemon signal handling series, specifically focusing on SA_RESTART detection and configuration. The patch introduces a systematic way to track systems lacking SA_RESTART support through a new NO_RESTARTABLE_SIGNALS Makefile variable, replacing previous ad-hoc approaches.

The changes standardize SA_RESTART handling across platforms by:
1. Adding a proper SA_RESTART fallback definition in compat/posix.h (0 when undefined)
2. Introducing NO_RESTARTABLE_SIGNALS build flag for affected platforms
3. Updating platform-specific configurations (Windows, NonStop, QNX) to use the new variable
4. Adding SA_RESTART detection to configure.ac with a compilation test
5. Mirroring the detection in meson.build

Key technical details include:
- Removes Windows' SA_RESTART definition from mingw-posix.h (now handled via NO_RESTARTABLE_SIGNALS)
- Marks NonStop and QNX as "UnfortunatelyYes" for NO_RESTARTABLE_SIGNALS
- Adds proper compilation test in configure.ac to detect SA_RESTART support
- Maintains backward compatibility while cleaning up platform-specific workarounds

This patch provides foundational infrastructure for the signal handling fixes discussed in the thread, particularly important for the ongoing debate between SA_RESTART toggling and self-pipe approaches. The changes are well-contained and focused on build system improvements rather than runtime behavior, with thorough updates across all build systems (Makefile, configure.ac, meson.build).
