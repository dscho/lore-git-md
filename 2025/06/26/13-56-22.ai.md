This is a technical discussion about Windows signal handling implementation details in the git-daemon signal handling series. Phillip Wood follows up on Carlo Marcelo Arenas Belon's patch that makes Windows' sigaction() implementation return -1 (like POSIX) rather than SIG_ERR (the function pointer type returned by signal()). 

Phillip initially questioned why the patch uses -1 instead of SIG_ERR to match signal()'s behavior. Carlo clarified that while the types differ (function pointer vs int), the values would be equivalent when cast, and current callers ignore the return value anyway. Phillip now suggests additionally setting errno = EINVAL for consistency with how the function handles other unsupported signals, noting that future callers might want to check errno even if current ones don't.

The exchange represents a micro-optimization in the Windows compatibility layer that doesn't fundamentally impact the ongoing architectural debate about SA_RESTART handling approaches. Both participants agree the current behavior is functionally equivalent, but Phillip advocates for making the error reporting more complete and future-proof. This refinement would maintain consistency with the function's existing error handling patterns while preserving the original goal of making Windows behave like POSIX for SIGCHLD setup.
