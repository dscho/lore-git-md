This is a proposed bugfix for the git-daemon's signal handling, introducing a "self-pipe" mechanism to address a race condition in child process reaping. The patch comes from Carlo Marcelo Arenas Belón as part of the ongoing discussion about zombie process cleanup on various platforms.

The change implements Phillip Wood's suggestion to use a pipe to reliably wake up the daemon's poll() loop when SIGCHLD arrives, closing a timing gap between status checks and signal delivery. The implementation adds a pipe to the poll set and has the signal handler write to it, ensuring the main loop will wake up even if the signal arrives between check_dead_children() calls.

Carlo notes some tradeoffs: this doubles the number of events handled per child process in many cases, and he suggests a periodic poll() timeout might be more efficient. He mentions having a more radical prototype that could eliminate the signal handler entirely, which he may share later.

The patch appears carefully implemented with proper pipe cleanup and non-blocking I/O setup, though it's marked as RFC (Request For Comments) indicating it's still under discussion. This comes at a key moment in the thread where Phillip Wood has been advocating for simpler solutions while Carlo has been defending the need for more robust signal handling. The self-pipe approach represents a middle ground between their positions.
