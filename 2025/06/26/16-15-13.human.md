Bugfix for Git daemon's socket handling during interrupted system calls (EINTR). This is a follow-up email in the thread, with Kristoffer Haugsbakk providing minor typo corrections to Carlo Marcelo Arenas Belón's initial patch.

The original patch addresses a long-standing issue where the Git daemon would incorrectly advance to the next socket when accept() is interrupted (EINTR), potentially leaving clients waiting. The fix adds EINTR-specific retry logic with a maximum of 2 attempts before falling back to the old behavior, while also ensuring child process reaping happens between retries.

Kristoffer points out two small typos in the commit message: "childs" should be "children" and "unlilely" appears to be a misspelling of "unlikely". These are straightforward editorial corrections that don't affect the technical content of the patch.

The patch itself appears to be a focused, well-motivated fix for a clear bug with historical context tracing back to 2005. The changes are minimal (14 lines) and specifically target the service_loop() error handling in daemon.c. No substantial technical concerns have been raised in the thread so far.
