This is a technical patch in the ongoing Git daemon signal handling series, specifically addressing how SIGCHLD signals are handled. It's part of a larger effort to fix zombie process cleanup on OpenBSD and crashes on AIX, with architectural discussions around signal handling approaches.

The patch switches from using the older `signal()` function to `sigaction()` for installing the SIGCHLD handler in the Git daemon. This change enables more precise control over signal handling flags (like SA_RESTART) which will be needed in future changes. The patch also removes the need to manually rearm the signal handler after each invocation, as `sigaction()` with BSD semantics handles this automatically.

The implementation sets SA_NOCLDSTOP (to avoid getting signals for stopped children) and SA_RESTART (to automatically restart interrupted system calls) flags. The empty signal handler remains, as its main purpose is to interrupt system calls rather than perform any cleanup.

This appears to be a well-justified change that modernizes the signal handling while maintaining the same behavior. It's part of a carefully considered series that has seen multiple iterations and thorough discussion about platform compatibility and architectural tradeoffs between different signal handling approaches.
