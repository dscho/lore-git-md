This is the second patch in a two-part RFC series proposing a pipe-based alternative to signal handling for tracking child processes in git-daemon. It builds on the first patch's introduction of `parent_ipc_in` in `struct child_process` to implement a "poor man's pidfd" approach using pipes.

The patch modifies git-daemon to create a pipe for each child process, with the parent monitoring the read end via poll(). When a child exits, the OS closes all its file descriptors, causing the pipe to close and triggering a POLLHUP event. This allows the parent to detect child termination without relying on SIGCHLD signals. The implementation currently scans all children when a pipe closes (an acknowledged inefficiency) to minimize initial changes.

Key technical aspects include:
- Pipe creation and management integrated into the existing child process handling
- Pollfd array dynamically extended for each new child
- Windows compatibility guarded by `#ifndef GIT_WINDOWS_NATIVE`
- Removal of the previous SIGCHLD signal handler entirely

The approach aims to be more portable than signal-based solutions, particularly for Windows, though the patch notes this is a proof-of-concept with known optimization opportunities. The changes are focused on daemon.c, modifying child process tracking while maintaining the same external behavior.

This represents a significant architectural shift from the thread's other proposed solutions (SA_RESTART toggling or documentation-only approaches), moving entirely away from signal handling for child tracking. The implementation appears technically sound but awaits performance evaluation, particularly Windows testing given the conditional compilation. As an RFC, it invites discussion about whether this pipe-based direction is preferable to refining the signal handling approaches.
