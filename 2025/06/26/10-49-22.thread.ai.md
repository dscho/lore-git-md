Git thread summary:

Bug report about interactive rebase (`git rebase -i`) failing in secondary worktrees with false "local changes would be overwritten" errors, while non-interactive rebase works correctly. The issue is intermittent and depends on commit history, making it hard to reproduce. Affects Git 2.49.0 on Darwin/arm64. Key symptoms: failure only in secondary worktrees created via `git worktree add`, with the error incorrectly claiming local modifications exist. The problem appears to be in how interactive rebase handles worktree state during its multi-step operation, possibly involving race conditions or improper bookkeeping of temporary checkouts. The reporter has observed this behavior for months but cannot provide a minimal test case due to the complex interactions required to trigger it.
