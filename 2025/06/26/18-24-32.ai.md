This is a proposed bugfix for the git-daemon's signal handling, introducing a self-pipe mechanism to address the race condition between SIGCHLD delivery and poll() interruption. The patch comes from Carlo Marcelo Arenas Belón as an RFC (Request For Comments) in the ongoing discussion about daemon signal handling.

The patch implements Phillip Wood's earlier suggestion to use a self-pipe - a common Unix pattern where a signal handler writes to a pipe that's included in the poll() set, ensuring the event loop wakes up promptly when children exit. The implementation adds a pipe to the poll set, with the signal handler writing to it when SIGCHLD is received. This guarantees the daemon will check for dead children even if poll() wasn't interrupted by the signal.

Key technical details include:
- New global poll_pipe[2] array to hold pipe file descriptors
- Modified child_handler() to write to the pipe when signaled
- Expanded pollfd array to include the pipe read end
- Additional logic in service_loop() to handle pipe events and maintain correct event counting
- Non-blocking pipe configuration with CLOEXEC flag

The author notes this doubles event handling in some cases and suggests a periodic poll() timeout might be more efficient. He mentions having a more radical prototype that could eliminate the signal handler entirely, which he may share later. The current implementation is marked as optional and self-healing, acknowledging the race condition being fixed is rare.

This represents a significant architectural shift from the previous SA_RESTART-focused approach, though the author still seems somewhat ambivalent about whether this is the best solution. The patch's effectiveness hinges on whether it truly closes the race window while not introducing new performance bottlenecks from the additional pipe I/O.
