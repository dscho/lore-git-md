This is a technical clarification in the ongoing Git daemon signal handling discussion, specifically about build-time checks for POSIX signal handling support.

Junio C Hamano questions the purpose of an empty `#ifdef SA_RESTART` block in the build configuration test, noting that it shouldn't affect compilation. Carlo Marcelo Arenas Belón had included this to detect platforms lacking `SA_RESTART` support (like QNX, NonStop, and Windows), but Junio points out that the compilation failure would actually come from the subsequent `siginterrupt()` call, not the empty preprocessor check.

The exchange highlights careful attention to portability details in the signal handling implementation, though it doesn't directly affect the core architectural decision between the SA_RESTART toggling approach and the self-pipe alternative. This is a minor but important clarification about how the current implementation verifies POSIX compliance across platforms.
