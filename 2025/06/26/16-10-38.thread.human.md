This thread addresses a bug in Git's daemon where interrupted system calls (EINTR) during socket acceptance could incorrectly advance to the next socket, potentially leaving clients waiting. The issue dates back to a 2005 commit introducing IPv6 support. Carlo Marcelo Arenas Belón submitted the initial patch, which adds EINTR-specific retry logic (with a 2-attempt limit) in daemon.c's service_loop() while preserving existing error handling, along with calls to check dead child processes between retries.

Kristoffer Haugsbakk provided the first feedback, noting two minor typos in the commit message ("childs" → "children" and "unlilely" → "unlikely") but not questioning the technical approach. The patch appears to be a straightforward, focused fix for a real reliability issue, though it hasn't yet received substantive technical review beyond this editorial feedback. The change is small (14 lines) and well-contained to the socket handling logic.
