This thread addresses a bug in Git's daemon where interrupted system calls (EINTR) during socket acceptance could incorrectly advance to the next socket, potentially leaving clients waiting. The issue dates back to 2005 when IPv6 support was introduced.

Carlo Marcelo Arenas Belón proposed the initial fix, which adds EINTR-specific retry logic in service_loop() with a maximum of 2 attempts. Kristoffer Haugsbakk provided minor editorial feedback on the commit message wording, which Carlo incorporated in v2. The updated version now includes 3 retry attempts, moves EINTR handling earlier in the error flow, and maintains the existing process cleanup between attempts.

The patch is focused (13 lines modified) and maintains all existing behavior for non-EINTR cases while solving this specific edge case. With the editorial feedback addressed and no outstanding technical concerns raised, this appears ready for maintainer review. The change is a straightforward bugfix that improves reliability without introducing new complexity.
