This thread addresses a bug in Git daemon's socket handling where it incorrectly advances to the next socket when interrupted by a system call (EINTR). The issue dates back to 2005 when IPv6 support was introduced. Carlo Marcelo Arenas Belón has submitted a patch series to implement proper EINTR handling with retries while maintaining the existing error fallthrough logic.

The discussion has progressed through three versions, with the latest incorporating most feedback. Key changes include unified variable declarations before accept() calls (as Junio Hamano suggested), a retry count of 3 attempts, and reordered error handling that prioritizes EINTR. The core technical solution appears settled, though some stylistic refinements continue - Junio now expresses mild discomfort with how the variables are grouped despite having originally requested the unified declaration style.

Two open questions remain: Phillip Wood's technical question about SA_RESTART interaction still needs addressing, and there's ongoing discussion about the placement of check_dead_children() calls between retry attempts. While Hridoy Ahmed voiced disagreement with the declaration style change, the project appears to be adopting Junio's preferred approach. The patch seems nearly ready for merging once these final details are resolved.
