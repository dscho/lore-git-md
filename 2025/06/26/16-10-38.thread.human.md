This thread addresses a bug in Git's daemon mode where interrupted system calls (EINTR) during socket acceptance could incorrectly advance to the next socket, leaving clients waiting. The issue dates back to 2005 when IPv6 support was introduced.

Carlo Marcelo Arenas Belón submitted the initial fix, which was refined in v2 based on Kristoffer Haugsbakk's editorial feedback. The current version adds a three-attempt retry loop for EINTR cases (up from two in v1) and reorders error handling while preserving existing behavior for other conditions. The changes are focused on the service_loop() function in daemon.c.

Phillip Wood has now reviewed v2, raising two technical points for clarification. He questions whether calling check_dead_children() between retry attempts is necessary given potential SA_RESTART behavior, and notes an inconsistency in variable declaration placement. These are implementation-level questions rather than objections to the overall approach. The patch appears technically sound otherwise, with no other concerns raised since the v1 feedback was addressed.

The thread remains focused on these final details, with the core solution well-established. Carlo will likely need to respond to Phillip's specific questions before the patch can be considered ready for merging.
