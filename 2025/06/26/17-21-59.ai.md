This is a bugfix for the Git daemon's socket handling during interrupted system calls (EINTR). The patch addresses a long-standing issue where the daemon would incorrectly advance to the next socket when accept() is interrupted, potentially leaving clients waiting. The problem dates back to 2005 when IPv6 support was introduced.

The v2 patch modifies service_loop() in daemon.c to add EINTR-specific retry logic. Key changes include:
- Introducing a retry counter (3 attempts) before falling through to socket advance
- Moving EINTR handling before EAGAIN/ECONNABORTED in the switch statement
- Adding check_dead_children() between retry attempts
- Keeping the existing fallthrough behavior for other error cases

The implementation is focused and maintains the original error handling flow while fixing the EINTR case. The commit message explains the historical context and rationale clearly. This appears to incorporate Kristoffer Haugsbakk's feedback from v1 about commit message wording ("childs"->"children", "unlilely"->"unlikely").

The change is relatively small (13 lines modified) and well-contained to the socket acceptance logic. It preserves all existing behavior for non-EINTR cases while solving a specific edge case that could cause client connection delays. The patch looks technically sound and ready for review.
