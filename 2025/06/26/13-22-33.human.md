Bugfix for the `core.commentChar=auto` behavior when handling rebase conflict markers. This patch addresses an issue where Git would incorrectly change the comment character when encountering leftover conflict comments (like "# Conflicts:") in commit messages during a rebase. The fix modifies the comment character selection logic to ignore these trailing conflict markers, ensuring the original comment character (typically "#") is preserved.

The problem was introduced in commit a6c2654 (rebase -m: fix --signoff with conflicts) and affects rebase operations where conflict markers remain in the message. The patch adds a test case in t/t3418-rebase-continue.sh that verifies the comment character remains unchanged when core.commentChar is set to "auto" during a conflicted rebase.

The change is minimal (6 lines modified in builtin/commit.c) and comes with a robust test case (18 lines added). The patch helps maintain consistency in commit message formatting during rebase operations.
