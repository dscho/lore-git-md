This is a response to a user question about `git log` decoration behavior regarding bisect refs. Jeff King explains that the change in behavior (where bisect refs no longer show by default) was introduced in commit 92156291ca ("log: add default decoration filter", 2022-08-05). While that commit didn't specifically mention bisect refs, he points to a sub-thread discussing potential for cleaner ways to include them in the default set.

The response provides a simple workaround: setting `log.initialDecorationSet` to "all" in Git config will restore the previous behavior where bisect refs are shown. This is a straightforward solution for users who want the old behavior back, though the underlying discussion suggests there may be more elegant solutions possible for handling these special ref namespaces.

The response is helpful and authoritative, coming from a core Git contributor, and directly addresses both the technical cause and a practical solution for the reported issue. It doesn't resolve whether this should be considered a bug or intentional behavior, but provides enough context for the user to understand the change's origin.
