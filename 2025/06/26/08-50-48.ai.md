This is a technical clarification in the ongoing Git daemon signal handling discussion, specifically addressing the `USE_NON_POSIX_SIGNAL` build flag and platform-specific signal behavior. Carlo Marcelo Arenas Belón responds to Junio C Hamano's concerns about the flag's naming and purpose, providing important context about the actual signal handling issues in the codebase.

The email clarifies that:
1. The core problem isn't with `sigaction(2)` itself (which works correctly on platforms that support it), but rather with Git's workarounds for platforms lacking `SA_RESTART` support
2. Windows compatibility requires special handling since it lacks native `sigaction()`
3. The current fallback to `signal()` causes crashes on AIX and other SysIII-derived systems due to implementation differences

Key technical points for future reference:
- The `USE_NON_POSIX_SIGNAL` flag currently serves two purposes: working around missing `SA_RESTART` and Windows compatibility
- The email reinforces that `sigaction()` is preferred when available, but platform-specific quirks complicate the implementation
- AIX crashes are specifically mentioned as a consequence of the current approach

This moves the architectural discussion forward by:
- Confirming the technical validity of both approaches (SA_RESTART toggling vs self-pipe)
- Highlighting specific pain points in the current implementation
- Providing concrete platform-specific behavior details that must be addressed regardless of solution path

The email doesn't advocate for either solution but provides important technical context that favors approaches (like the self-pipe) that would avoid these platform-specific signal handling complexities altogether.
