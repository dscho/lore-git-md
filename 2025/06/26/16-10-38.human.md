This is a bugfix for the Git daemon's socket handling. The patch addresses an issue where the daemon would incorrectly advance to the next socket when encountering an EINTR (interrupted system call) during accept(), rather than retrying the same socket. This could leave clients waiting unnecessarily.

The fix makes three key changes:
1. It properly retries the accept() call on EINTR up to two times before falling back to the old behavior
2. It adds child process reaping during the retry attempts
3. It maintains the existing behavior for other soft errors like EAGAIN and ECONNABORTED

The change appears well-contained and focused, touching only the socket handling logic in daemon.c. The commit message clearly explains both the historical context (dating back to 2005) and the current problem being solved. The patch is small (14 lines changed) and seems unlikely to introduce new issues while fixing a subtle edge case in the daemon's network handling.
