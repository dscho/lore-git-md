Thread identity: Bugfix for commit message comment character selection when core.commentChar="auto", affecting rebase operations with conflicts.

Core problem: When auto-selecting a comment character during commit message editing, Git incorrectly considers conflict markers (like "<<<<<<<") as candidate comment characters, potentially causing these markers to appear in final commit messages. This occurs during rebase operations when resolving conflicts.

Current status: Patch v2 with all reviewer feedback addressed, now in final polishing stage with mentoring credits and acknowledgments added. The technical solution modifies `adjust_comment_line_char()` in builtin/commit.c to skip conflict marker sections when auto-selecting comment characters by using the existing `ignored_log_message_bytes()` helper. Builds on two historical changes: 84c9dc2 (auto-selection feature) and a6c2654 (introduced the bug).

Key technical details:
- Core change in builtin/commit.c adds cutoff calculation using ignored_log_message_bytes()
- Preserves original comment character (#) when conflict markers are present
- Improved test case in t/t3418-rebase-continue.sh verifies stable comment character selection during rebase with conflicts
- Uses direct output capture with `GIT_EDITOR="cat >actual"` and anchored grep patterns (`test_grep` with `^$`)
- Maintains existing behavior for non-conflict cases
