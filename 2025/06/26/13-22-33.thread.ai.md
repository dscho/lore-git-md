Thread identity: Bugfix for commit message comment character selection when core.commentChar="auto", affecting rebase, cherry-pick, revert, and merge operations with conflicts. Original patch by Ayush Chandekar with mentoring from Ghanshyam Thakkar, now at v3 with test optimizations and Phillip Wood's latest suggestions.

Core problem: When auto-selecting a comment character during commit message editing, Git incorrectly considers conflict markers (like "<<<<<<<") as candidate comment characters, potentially causing these markers to appear in final commit messages. The issue spans multiple operations and involves deep architectural questions about state management and configuration precedence, particularly between `core.commentChar="auto"` and `core.commentstring`.

Current status: Chandekar's v3 patch implements a surgical fix using ignored_log_message_bytes() to calculate a cutoff point before scanning for comment characters, with optimized test case in t/t3418-rebase-continue.sh. Phillip Wood now suggests an additional change to reset comment_line_str to '#' when core.commentString is "auto", building on his earlier deprecation proposal that Junio Hamano acknowledged has consistency benefits. This represents an incremental step toward potential future simplification while maintaining backward compatibility.

Key technical details:
- Core change in builtin/commit.c adds cutoff calculation using ignored_log_message_bytes()
- Modifies character scanning loop to stop at cutoff point
- Preserves original comment character (#) when conflict markers are present
- Test case in t/t3418-rebase-continue.sh optimized to reuse existing files
- Wood's new suggestion would reset comment_line_str to '#' when core.commentString is "auto"
- Fixes regression from a6c2654f83 (rebase -m: fix --signoff with conflicts)
- Wood's latest suggestion aligns with his earlier proposal to hardcode `comment_line_str` to '#' in auto mode

  - Auto mode test failures
  - Broken configuration precedence between core.commentChar and core.commentString
  - Changed error handling timing (delayed errors until commit message editing)

- Problem affects rebase, cherry-pick, revert, and merge operations
