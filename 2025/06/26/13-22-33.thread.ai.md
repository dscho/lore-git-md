Thread identity: Bugfix series for commit message comment character selection when core.commentChar="auto", affecting rebase, cherry-pick, revert, and merge operations with conflicts. Core problem: When auto-selecting a comment character during message editing, Git incorrectly considers conflict markers (like "<<<<<<<") as candidates, potentially causing these markers to appear in final commit messages. The issue spans multiple operations and involves architectural questions about state management and configuration precedence of `core.commentChar="auto"` versus `core.commentstring`.
