Thread identity: Bugfix for commit message comment character selection when core.commentChar="auto", affecting rebase operations with conflicts.

Core problem: When auto-selecting a comment character during commit message editing, Git incorrectly considers conflict markers (like "<<<<<<<") as candidate comment characters, potentially causing these markers to appear in final commit messages. This occurs during rebase operations when resolving conflicts.

Current status: Patch v1 proposed and reviewed by Junio C Hamano, who confirms the technical solution appears correct. The patch modifies `adjust_comment_line_char()` in builtin/commit.c to skip conflict marker sections when auto-selecting comment characters.

Key technical details:
- Fix modifies builtin/commit.c to preserve original comment character (#) when conflict markers are present by using existing `ignored_log_message_bytes()` helper
- Adds test case in t/t3418-rebase-continue.sh to verify behavior
- Builds on two historical changes: 84c9dc2 (auto-selection feature) and a6c2654 (introduced the bug)
- Maintains backward compatibility while fixing edge case
- Solution handles conflict markers from rebase operations without introducing new complexity
