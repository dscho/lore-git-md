Thread identity: Bugfix for commit message comment character selection when core.commentChar="auto", affecting rebase operations with conflicts.

Core problem: When auto-selecting a comment character during commit message editing, Git incorrectly considers conflict markers (like "<<<<<<<") as candidate comment characters, potentially causing these markers to appear in final commit messages. This occurs during rebase operations when resolving conflicts.

Current status: Patch is in final refinement stage with all substantive technical feedback addressed. The solution modifies `adjust_comment_line_char()` in builtin/commit.c to skip conflict marker sections when auto-selecting comment characters by using the existing `ignored_log_message_bytes()` helper. Builds on two historical changes: 84c9dc2 (auto-selection feature) and a6c2654 (introduced the bug). Final test optimizations being implemented per Phillip Wood's suggestions.

Key technical details:
- Core change in builtin/commit.c adds cutoff calculation using ignored_log_message_bytes()
- Preserves original comment character (#) when conflict markers are present
- Test case in t/t3418-rebase-continue.sh being optimized to reuse existing files rather than create new commits
- Test_grep patterns made more robust by removing trailing ':' anchor that could cause false negatives
- Uses direct output capture with `GIT_EDITOR="cat >actual"` and grep patterns
- Maintains existing behavior for non-conflict cases
- Commit message includes proper historical references using `git log -1 --format=reference` style
