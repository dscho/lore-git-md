Bugfix for commit message comment character selection during rebase conflicts, now with improved test verification.

This is the final version of Ayush Chandekar's patch addressing an edge case where Git's auto-selection of comment characters could incorrectly incorporate conflict markers into commit messages during rebase operations. The fix modifies `adjust_comment_line_char()` in builtin/commit.c to properly ignore conflict marker sections when choosing a comment character.

The patch has gone through review with Junio C Hamano confirming the technical approach and Kristoffer Haugsbakk suggesting test enhancements. Chandekar has incorporated these suggestions, improving the test in t/t3418-rebase-continue.sh to use direct output capture with `GIT_EDITOR="cat >actual"` and more precise `test_grep` validations. These changes make the test more robust while maintaining the same core fix.

The solution builds on two historical changes - the original auto-selection feature from 2014 and a later change that introduced this edge case. It maintains backward compatibility while cleanly solving the specific problem of conflict markers being misinterpreted during comment character selection. With all reviewer feedback addressed and no outstanding technical concerns, this appears ready for inclusion.
