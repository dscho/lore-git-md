This is a platform compatibility patch in the ongoing git daemon signal handling series, specifically addressing Windows signal handling behavior. Carlo Marcelo Arenas Belón responds to Phillip Wood's suggestion about error reporting consistency in the Windows `sigaction()` implementation.

The discussion focuses on whether the Windows `sigaction()` compatibility wrapper should set `errno = EINVAL` when returning -1 for unsupported signals (like SIGCHLD), to match the behavior pattern used for other unsupported signals in the same function. While the current callers ignore the return value, Phillip argues for future-proofing by maintaining consistent error reporting.

Carlo confirms Windows' `signal(SIGCHLD)` doesn't set errno as documented, possibly due to SIGCHLD being a bogus signal number in Windows headers. He initially preferred matching `signal()`'s behavior (no errno set) but acknowledges the merit in Phillip's suggestion for consistency with the function's existing error patterns. This represents a minor refinement to the Windows signal handling implementation that doesn't affect the core SA_RESTART architectural debate but improves internal consistency.

Key technical details:
- Windows `sigaction()` wrapper in `compat/mingw.c`
- SIGCHLD signal handling compatibility
- Return value behavior (SIG_ERR vs -1 with errno)
- Microsoft documentation vs observed behavior mismatch
- The patch doesn't change core functionality but refines error reporting
- Part of broader signal handling improvements for git-daemon
- Follows established pattern for unsupported signal handling in the codebase
