This is a technical discussion thread about signature handling in Git's fast-export/fast-import functionality, specifically addressing the representation of multiple signature support across different hash algorithms. Elijah Newren responds to Christian Couder's v4 patch with a detailed analysis after gaining a better understanding of the signature handling mechanics through direct discussion with brian m. carlson.

Key technical points clarified:
- Signatures can exist for both SHA-1 and SHA-256 versions of the same commit object (not just signatures matching the commit's own hash format)
- The `gpgsig <git-hash-algo> <signature-format>` syntax serves to distinguish between signatures of the commit vs its compatibility object
- Signature format metadata (OpenPGP/X.509/SSH) is retained for tool convenience despite being derivable from ASCII armor
- Current implementation limits to one signature per hash algorithm due to broader Git limitations

Implementation implications noted:
- Fast-import will need to handle signature types differently based on repository configuration
- Signature verification requires knowing which object (original or compatibility) was signed
- Documentation needs clarification around dual-signature cases
- Test coverage gaps remain for multiple signature scenarios
