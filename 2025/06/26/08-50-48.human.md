This is a technical clarification in the ongoing Git daemon signal handling discussion, specifically addressing the `USE_NON_POSIX_SIGNAL` build flag confusion. Carlo Marcelo Arenas Belón responds to Junio C Hamano's concerns about the flag's naming and purpose, explaining that the real issues stem from Git's own workarounds rather than platform limitations.

The email clarifies two key points: First, that `sigaction(2)` itself works fine across platforms when available, and the problems come from Git's SA_RESTART workaround hack for platforms that don't support it. Second, that Windows lacks `sigaction()` entirely, requiring compatibility code. Carlo notes that falling back to `signal()` is problematic (causing crashes on AIX) and likely unnecessary.

This moves the thread forward by disentangling the actual platform limitations from Git's own workarounds, which helps frame the ongoing architectural decision between the SA_RESTART toggling approach and the proposed self-pipe solution. The technical precision here should help inform the final decision on which path to take for fixing the daemon's signal handling issues.
