This is the second patch in a two-part RFC series proposing a pipe-based child process monitoring approach for git-daemon, as an alternative to signal handling. The patch implements the core mechanism where each child process gets a pipe, with the parent monitoring the read end via poll() to detect when the child exits (indicated by pipe closure).

The implementation creates pipes for each child (except on Windows), with the write end automatically closed in the child process. The parent tracks these pipes in its poll() set alongside the main sockets. When POLLHUP is detected on a pipe, the parent scans its child list to find and clean up the terminated process. The patch removes the previous SIGCHLD handler entirely, moving to a signal-free design.

Key technical aspects include:
- New `parent_ipc_in` field in `struct child_process` carries the pipe fd
- Dynamic reallocation of the pollfd array as children are added/removed
- Windows exclusion for now due to pipe implementation differences
- Current inefficiency in scanning all children on any pipe event
- Integration with existing max_connections throttling

This represents a significant architectural shift from the signal-based approaches previously debated in the thread. The implementation appears functional but has clear optimization opportunities noted by the author, particularly around the O(n) child scanning. Windows support remains an open question that would need to be addressed for full portability. The patch provides concrete code for evaluation alongside the ongoing discussions about SA_RESTART and documentation-only approaches.
