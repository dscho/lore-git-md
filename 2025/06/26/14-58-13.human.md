This is a platform compatibility patch in the ongoing git-daemon signal handling discussion, specifically addressing Windows behavior for SIGCHLD handling.

Carlo Marcelo Arenas Belón responds to Phillip Wood's suggestion about error handling consistency in Windows' sigaction() implementation. The exchange clarifies that while both signal() and sigaction() return error indicators (SIG_ERR and -1 respectively), neither currently sets errno=EINVAL on Windows for unsupported signals like SIGCHLD, despite POSIX requiring it. 

The discussion reveals platform-specific quirks: Windows lacks a native SIGCHLD definition (Git uses its own compat numbers), and Microsoft's documentation claims signal() should set errno but doesn't in practice. Carlo agrees with Phillip that future-proofing suggests setting errno=EINVAL would be better, but opts to initially match signal()'s current behavior for consistency.

This is a technical refinement to patch 2/4 in the series, addressing a Windows-specific edge case that doesn't affect the core SA_RESTART debate. The change is well-reasoned but represents a minor implementation detail in the larger signal handling architecture discussion.
