This is a bugfix patch for git-daemon's networking code, removing an obsolete FD_SETSIZE check that became unnecessary after the 2005 switch from select() to poll().

Phillip Wood replies to Carlo Marcelo Arenas Belón's initial patch submission, giving a positive review. The original patch proposed removing a validation check in setup_named_sock() that enforced socket file descriptors to be below FD_SETSIZE - a restriction that was needed for select() but became irrelevant when the code switched to poll() in 2005 (6573faff34). Phillip confirms the patch looks good, indicating likely acceptance of this straightforward cleanup.

The technical change is minimal - just removing 5-line validation block in daemon.c that would reject sockets with descriptors >= FD_SETSIZE. The patch doesn't change any functionality since poll() has been handling these descriptors fine for nearly 20 years. The removal affects both IPv4 and IPv6 socket creation paths.

This appears to be a well-justified cleanup of historical cruft, with clear commit message references to the relevant historical commits (df076bdbcc introducing the check and 6573faff34 making it obsolete). The change is low-risk as it removes code that hasn't been functionally relevant for decades.
