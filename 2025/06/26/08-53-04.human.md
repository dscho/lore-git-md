This is a bugfix series (v3) addressing signal handling in Git's daemon mode, specifically targeting zombie process cleanup on OpenBSD and crashes on AIX. The core issue stems from platform-specific behavior around interrupted system calls during signal handling, particularly with SA_RESTART in poll() operations.

The series makes several key changes from previous versions:
1. Renames USE_NON_POSIX_SIGNAL to NO_RESTARTABLE_SIGNALS for clarity
2. Adds Windows compatibility by allowing sigaction(SIGCHLD)
3. Replaces signal() with sigaction() for child process handling
4. Explicitly handles EINTR during poll() operations

The implementation now cleanly separates platform-specific concerns while maintaining the same BSD semantics. The changes affect multiple build systems (Makefile, meson) and touch core signal handling infrastructure across several platforms (Windows, NonStop, QNX).

This version appears more polished than previous iterations, with better variable naming and reduced use of siginterrupt(). The commit messages clearly explain the technical rationale, though the series still represents a complex solution to a subtle platform compatibility issue. The discussion thread suggests a self-pipe approach might be a simpler long-term solution, but this series provides a robust fix for the immediate problems.
