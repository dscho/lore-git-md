Bugfix for interactive rebase failing in secondary worktrees.

Denilson Sá Maia reports a persistent issue where `git rebase -i` fails in secondary worktrees with spurious "local changes would be overwritten" errors, while non-interactive rebase works fine. The problem appears intermittently, depending on the state of commits across worktrees, making it hard to reproduce consistently. The reporter suspects this is a worktree-specific bug in the interactive rebase codepath.

The error occurs when trying to rebase a branch in a secondary worktree against either a historical commit or the main branch, despite no actual local changes being present. Notably, the same operation succeeds when performed in the main worktree, strongly suggesting a worktree-handling issue rather than a general rebase problem.

This has been affecting the reporter for several months across Git 2.49.0 on macOS (ARM64). The report includes detailed system information but lacks a minimal reproduction case due to the intermittent nature of the issue. The problem appears serious enough to warrant investigation by worktree/rebase maintainers, as it affects a core workflow in multi-worktree environments.
