This is a bugfix patch for Git's commit message handling when `core.commentChar` is set to "auto". The issue occurs during rebase operations with conflicts, where Git might incorrectly treat conflict markers as comment characters, potentially leaving them in the final commit message.

The patch modifies `adjust_comment_line_char()` in builtin/commit.c to skip scanning conflict marker sections when auto-selecting comment characters. This ensures Git maintains the original comment character (#) when appropriate, keeping commit messages clean. The solution builds on existing infrastructure by using the `ignored_log_message_bytes()` helper function.

A new test case in t/t3418-rebase-continue.sh verifies the fix by simulating a rebase conflict and checking that the comment character remains unchanged. The test uses direct output capture with `GIT_EDITOR="cat >actual"` and anchored grep patterns for reliability.
