This is a bugfix series (v3) addressing signal handling issues in the Git daemon, particularly around zombie process cleanup on OpenBSD and crashes on AIX. The series represents the SA_RESTART toggling approach in the ongoing architectural discussion between this and the self-pipe alternative.

Key technical changes in v3:
- Renames `USE_NON_POSIX_SIGNAL` to clearer `NO_RESTARTABLE_SIGNALS` throughout build system
- Adds Windows-specific sigaction() support for SIGCHLD (new patch 2)
- Improves SA_RESTART detection logic in configure.ac with proper compilation test
- Maintains platform-specific handling for NonStop, QNX, Windows where SA_RESTART is unavailable
- Adds explicit EINTR handling during poll() with new `set_sa_restart()` helper

The implementation now properly tracks platforms lacking SA_RESTART support while fixing the signal handler installation to use sigaction() where available. The series reveals deeper technical debt in the current approach - the SA_RESTART detection was previously flawed (empty `#ifdef` block) and Windows needed special casing for sigaction().

Compared to the self-pipe alternative discussed in the thread, this approach:
- Keeps existing file descriptor count
- Requires more platform-specific code
- Still carries signal() fallback risks (AIX crashes)
- Needs careful SA_RESTART toggling around poll()

The changes touch core signal handling infrastructure across multiple files (Makefile, config.mak.uname, configure.ac, meson.build) and daemon.c's event loop. Platform-specific adjustments affect Windows, NonStop, QNX, and MINGW builds. The series appears technically sound but reinforces the architectural tradeoffs between this approach and the self-pipe solution.
