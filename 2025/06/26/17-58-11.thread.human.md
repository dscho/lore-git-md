Here's the updated human-readable summary:

The thread began with a user noticing that `git log --decorate` no longer shows bisect references (`refs/bisect/`) in its output, though it used to a few years ago. They found a workaround using `--decorate-refs=refs/*` but this had unwanted side effects by showing too many other references.

Jeff King (Peff) identified the exact commit (92156291ca) from 2022 that changed this behavior as part of making reference decoration filtering more configurable. While the change was intentional, the exclusion of bisect refs appears to have been an oversight rather than a deliberate choice. He provided a clean solution - setting `log.initialDecorationSet=all` in the config restores the previous behavior where bisect refs were included.

The response clarifies this isn't a bug but rather a documented (if not optimally communicated) behavior change. While there was past discussion about explicitly including bisect refs in the default set, no immediate plans exist to modify the current behavior. Users who need bisect refs displayed can use the config workaround or explicitly specify the bisect refs they want to see.
