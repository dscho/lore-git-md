This is a bugfix for the Git daemon's socket handling when system calls are interrupted (EINTR). The patch addresses a long-standing issue dating back to 2005 when IPv6 support was added, where the daemon would incorrectly move to the next socket when accept() was interrupted, potentially leaving clients waiting.

The v2 patch from Carlo Marcelo Arenas Belón makes two key improvements: it adds a retry loop (with a maximum of 3 attempts) for EINTR errors before moving to the next socket, and ensures child processes are reaped between retries. The change is focused and well-contained (13 lines modified in daemon.c), preserving the existing behavior for other error cases like EAGAIN and ECONNABORTED.

This appears to be a straightforward and well-justified fix for a subtle edge case. The commit message clearly explains both the historical context and the current problem, and the implementation looks clean with appropriate safeguards against potential busy loops. The patch has already incorporated minor editorial feedback from Kristoffer Haugsbakk in this revision.
