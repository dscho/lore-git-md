This is a bugfix for the Git daemon's socket handling. The patch addresses an issue where the daemon would incorrectly advance to the next socket when encountering an EINTR (interrupted system call) during accept(), rather than retrying the same socket. This could leave clients waiting unnecessarily.

The change modifies the error handling loop in `daemon.c` to:
1. Retry the accept() call up to 2 times when EINTR occurs
2. Reap any completed child processes between retries
3. Only advance to the next socket if retries are exhausted or other soft errors (EAGAIN/ECONNABORTED) occur

The patch appears well-motivated, tracing the issue back to a 2005 commit that introduced the problematic behavior. The solution is straightforward and includes a reasonable retry limit to prevent busy looping. The change is minimal (14 lines modified) and focused on the specific issue.

- Modifies the service_loop() function in daemon.c
- Introduces a retry counter and goto-based retry logic
- Calls check_dead_children() between retry attempts
- Maintains existing behavior for other error cases
