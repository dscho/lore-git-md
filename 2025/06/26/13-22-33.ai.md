Bugfix targeting the commit message comment character selection when core.commentChar is set to "auto". This patch addresses an issue where Git would incorrectly consider conflict markers (like those from a rebase) when auto-selecting a comment character, potentially causing those markers to appear in the final commit message.

The fix modifies `adjust_comment_line_char()` in builtin/commit.c to skip scanning trailing comment blocks (like conflict sections) when choosing a comment character. This ensures Git can safely reuse the original comment character (#) even when conflict markers are present, maintaining clean commit messages. The change is tested via a new case in t/t3418-rebase-continue.sh that verifies the comment character remains unchanged after a conflicted rebase.

The patch identifies two relevant historical changes: 84c9dc2 which introduced the auto-selection feature, and a6c2654 which introduced the bug by adding conflict comments to the message file. The fix is cleanly implemented with a small code change and thorough test coverage, suggesting it's a well-considered solution to a real-world problem that could affect users during rebase operations.
