This is the final patch in a bugfix series addressing signal handling issues in the Git daemon, specifically around zombie process cleanup on OpenBSD and crashes on AIX. The series has evolved through three versions with significant architectural discussion around two approaches: toggling SA_RESTART flags versus using a self-pipe mechanism.

The current patch explicitly disables SA_RESTART around poll() calls in the daemon's service loop to ensure EINTR interrupts can occur, which are necessary for proper child process cleanup. It introduces a new `set_sa_restart()` helper function that safely toggles the flag while accounting for platforms that don't support restartable signals (handled via the NO_RESTARTABLE_SIGNALS build flag added earlier in the series).

This represents the SA_RESTART toggling approach that has been refined throughout the thread, with Windows support added in v3. While technically sound, the discussion has revealed this solution carries more platform-specific complexity than the alternative self-pipe approach, which Junio Hamano and Phillip Wood have validated would solve both the zombie process and race condition issues more cleanly.

The patch itself is well-crafted and completes the current implementation path, though the thread remains at a decision point between competing architectural approaches. Readers interested in daemon reliability or cross-platform signal handling should review the full thread to understand the tradeoffs between these solutions.
