Thread summary:

This thread examines a change in `git log` decoration behavior regarding bisect refs, where `--decorate` no longer shows `refs/bisect/` references by default. Jeff King identified commit 92156291ca ("log: add default decoration filter") as the source of this change, which was part of making reference decoration filtering more configurable. The current behavior is intentional but may not be optimally documented.

The thread reveals that bisect refs were unintentionally excluded from the new default set during this refactoring. A workaround exists by setting `log.initialDecorationSet=all` to restore pre-2022 behavior. While there was previous discussion about explicitly including bisect refs in the default set, this wasn't implemented in the original change.

Key technical details:
- Behavior change originated in commit 92156291ca
- Workaround: `git config log.initialDecorationSet all`
- Related discussion exists about potentially adding bisect refs to default set
- Current behavior is considered intentional (though perhaps not well-documented)
- No immediate plans to change default behavior

The thread provides historical context for the change and a clear solution for users needing the previous behavior. This appears to be a case where a refactoring for configurability had unintended consequences for specific use cases involving bisect refs. The response from Jeff King moves the discussion forward by identifying both the root cause and a practical workaround.
