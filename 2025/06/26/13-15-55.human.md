This is a technical discussion about Windows signal handling consistency in the ongoing git-daemon signal handling series. Carlo Marcelo Arenas Belón responds to Phillip Wood's question about why the patch returns -1 rather than SIG_ERR when matching Windows signal() behavior. 

Carlo clarifies that while signal() returns SIG_ERR (a function pointer) and sigaction() returns an int, both approaches effectively produce an error return value without setting errno to EINVAL as POSIX requires. He notes the irony that sigaction() could technically return SIG_ERR cast to an int, but since Git's code ignores the return value anyway, the distinction makes no practical difference.

This exchange represents a minor implementation detail in the broader debate about the SA_RESTART approach versus Phillip Wood's proposed minimal solution. The discussion remains technical and collegial, focused on platform-specific behavior rather than the core architectural disagreement. The patch itself appears to be a straightforward compatibility shim, though its necessity may be questioned if Phillip's simpler approach is adopted.
