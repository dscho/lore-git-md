This thread addresses a bug where Git's auto-selection of commit message comment markers could incorrectly include conflict markers (like "<<<<<<<") during rebase operations, potentially leaving them in final commit messages. The fix modifies the comment character selection logic in `builtin/commit.c` to properly skip conflict sections.

Ayush Chandekar's patch has gone through two iterations, with v2 incorporating all substantive feedback. The solution builds on existing infrastructure (`ignored_log_message_bytes()`) and includes a test case in `t3418-rebase-continue.sh`. Key reviewers Junio C Hamano, Phillip Wood, and Kristoffer Haugsbakk have validated the approach, with Junio and Christian Couder providing final polish on commit message formatting and catching a typo.

The latest discussion notes an interesting edge case regarding `core.commentstring` configuration interacting with the auto-selection behavior, though this doesn't affect the current fix. Phillip Wood suggested optimizing the test case by reusing existing files rather than creating new commits, and making the test pattern more robust - suggestions Junio endorsed. With these final test refinements, the patch appears ready for inclusion. Phillip Wood had previously raised a broader question about the auto-comment feature's design, which may be addressed separately in future work.
