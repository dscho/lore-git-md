Thread identity: Bugfix for Git daemon's socket handling during interrupted system calls (EINTR).

Core problem: The daemon incorrectly advances to next socket on EINTR during accept(), potentially leaving clients waiting. Root cause traced to 2005 behavior when IPv6 support was introduced.

Current status: Second patch version incorporating initial feedback, now using 3 retry attempts (was 2 in v1) with reordered error handling. Phillip Wood's review raises two implementation questions needing clarification.

Key technical details:
- Adds EINTR-specific retry loop (3 attempts) before socket advance in service_loop()
- Reorders switch to handle EINTR before EAGAIN/ECONNABORTED
- Calls check_dead_children() between retry attempts (questioned by reviewer)
- Variable declaration placement inconsistency noted (incoming vs retry)
- Preserves existing fallthrough for other error conditions
- 13-line change focused on service_loop() error handling

Open questions:
- Justification needed for check_dead_children() placement in retry sequence
- Clarification requested on variable declaration ordering
- Potential interaction with SA_RESTART signal handling
