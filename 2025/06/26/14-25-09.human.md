This is a continuation of the discussion about line length limits in Git's code style configuration. Junio Hamano responds to Karthik Nayak's willingness to change the proposed 120-character limit down to 80 characters in the context of editor-based line wrapping.

Junio frames the discussion around three key points: Git's documented 80-column guideline, the practical reality that slightly longer lines can sometimes improve readability, and the need for some absolute maximum to prevent excessively long lines. He asks where the boundary should be drawn between acceptable "slightly over 80" cases and truly excessive line lengths, suggesting this could inform where to set the hard limit that prevents wrapping from creating overly long lines.

The email shows Junio thinking through how to balance the project's style guidelines with practical coding realities, seeking a solution that maintains readability while giving developers some flexibility. This follows the earlier consensus that neither .editorconfig nor .clang-format currently support ideal wrapping behavior, with both parties referencing GitHub issue #89 about editor "rulers" as a potential future enhancement.
