This is a technical discussion about signal handling in the Git daemon, specifically around patch 4/4 in a series addressing zombie process cleanup. Phillip Wood questions the core approach of the series, arguing that the Git daemon was designed to handle EINTR interruptions and thus shouldn't need SA_RESTART manipulation at all.

Phillip's email is a direct response to Carlo Marcelo Arenas Belón's patch that adds SA_RESTART toggling around poll() calls in the daemon's service loop. The patch introduced a new set_sa_restart() helper function to enable/disable SA_RESTART flag around poll() operations. Phillip contends this complexity is unnecessary since the daemon should already be prepared to handle interrupted system calls.

The exchange represents a key decision point in the thread - whether to keep the current SA_RESTART toggling approach or simplify the solution by removing this mechanism entirely. Phillip's position aligns with his earlier proposal for a minimal solution that would drop several patches from the series while acknowledging the remaining race condition could be better solved with a self-pipe approach.

This email doesn't introduce new code but rather challenges the fundamental design direction of the series, suggesting the maintainers reconsider whether the SA_RESTART manipulation is actually needed given the daemon's original design assumptions.
