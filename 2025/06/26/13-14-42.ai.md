This is a technical discussion in the ongoing git-daemon signal handling thread, specifically addressing patch 4/4 from Carlo Marcelo Arenas Belón's v3 series. Phillip Wood questions the fundamental approach of using SA_RESTART in the signal handling implementation.

Phillip argues that since git-daemon was designed to handle EINTR from system calls, the SA_RESTART manipulation (which prevents EINTR in some cases) is unnecessary complexity. The patch in question adds explicit SA_RESTART toggling around poll() calls via a new set_sa_restart() helper function, but Phillip suggests this may be solving a non-problem while adding platform-specific code.

Key technical elements mentioned:
- The SA_RESTART flag behavior during poll() operations
- The NO_RESTARTABLE_SIGNALS build-time configuration
- The existing assumption in git-daemon about EINTR handling
- The set_sa_restart() helper function that toggles the flag

This email represents Phillip's pushback against the architectural direction of the series, favoring a simpler approach that aligns with git-daemon's original design assumptions rather than adding new platform-specific signal handling logic. The discussion continues to weigh the tradeoffs between comprehensive platform support (Carlo's approach) and minimalism (Phillip's preference).
