This is the final version (v4) of Patrick Steinhardt's series addressing race conditions in Git's maintenance tasks, particularly around reference locking during detached operations. The series has evolved through review iterations with input from Kristoffer Haugsbakk and Karthik Nayak, refining both implementation and documentation.

The core problem fixes races that could occur when auto-maintenance repacked references while other operations were in progress. The solution introduces a clear split between foreground tasks (like packing refs) that must complete before detaching, and background tasks that can run afterward. The series systematically refactors the maintenance task system to support this while improving code quality through:
- Elimination of global state
- Standardized error handling via `die(NULL)`
- Type-safe function pointers
- Clearer terminology (foreground/background phases)
- Thorough test coverage

Notable changes in v4 include final documentation polish around error handling terminology (settling on "magic numbers" phrasing) and commit message clarifications distinguishing reference packing from reflog expiration. The series touches `builtin/gc.c` extensively, with supporting changes to several other builtins and test scripts.

This appears to be a well-considered, thoroughly reviewed series that solves real race conditions while improving the codebase's maintainability. The careful attention to documentation and naming suggests it will integrate cleanly. Readers interested in maintenance operations or reference handling should examine the implementation details, while those focused on code quality patterns may find the error handling and state management changes broadly instructive.
