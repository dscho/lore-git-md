This is a refactoring patch in Patrick Steinhardt's v3 series (12 patches) that improves Git's error handling infrastructure. The patch introduces the ability to call `die(NULL)` as a cleaner alternative to `exit(128)` when code needs to terminate after already having emitted an error message.

The change modifies `usage.c` to make `die_message_builtin()` handle NULL error strings gracefully (printing nothing while still exiting with code 128). This eliminates magic numbers in the codebase and provides a more consistent way to terminate with an error status after custom error reporting. The patch demonstrates the new pattern by converting several builtins to use `die(NULL)` instead of direct `exit(128)` calls.

This is part of the series' broader effort to standardize error handling and reduce global state. While a small change, it contributes to the overall code quality improvements by providing a more maintainable pattern for error termination. The patch maintains existing behavior while making the code more self-documenting.
