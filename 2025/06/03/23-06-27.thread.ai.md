Thread identity: Bug report and feature proposal regarding submodule behavior when `clone.defaultRemoteName` differs from "origin", reported by Jacob Keller, with Junio Hamano, Patrick Steinhardt, and others involved in the discussion.

Core problem: Submodule operations fail when `clone.defaultRemoteName` is configured to something other than "origin" due to hardcoding in `builtin/submodule--helper.c`. The discussion has expanded to address both the immediate configuration issue and deeper architectural challenges in remote handling code, particularly around repository awareness in deprecated functions that will be removed in Git 3.0.

Current status: Patrick Steinhardt has formally endorsed Junio Hamano's position that modifying the deprecated `read_remotes_file` and `read_branches_file` functions to properly accept repository pointers is the correct path forward. This maintainer alignment resolves a key open question about architectural direction. Jacob Keller's technical investigation had previously identified concrete obstacles in the URL-based solution path, finding these functions incorrectly assume `the_repository` despite being called with repository context.

Key technical details: The issue involves multiple layers: (1) `repo_get_default_remote`'s hardcoded "origin" behavior, (2) deprecated config-reading functions in `remote.c` that incorrectly use `the_repository`, and (3) broader questions about parameter passing between repository and remote_state structures. Patrick Steinhardt emphasizes the value of incremental, motivated changes in the broader effort to eliminate `the_repository`, providing maintainer approval for modifying these specific functions while cautioning against large-scale changes made purely for removal's sake. Changes would affect submodule initialization, update, and fetch workflows.

Open questions: Implementation details remain to be worked out for passing repository parameters to the deprecated functions while maintaining stability. The discussion continues to balance immediate submodule functionality needs against the broader architectural evolution of remote handling code. Other code paths that might need similar attention before Git 3.0 remain to be identified.

Participant positions: Strong consensus now exists between Junio Hamano and Patrick Steinhardt on modifying the deprecated functions to be properly repository-aware. Jacob Keller continues technical investigation with maintainer support. The alignment between these key figures signals this approach will be adopted, though the exact implementation path remains open for discussion.

Related work: Deeply connected to the `the_repository` removal effort and Git 3.0's planned deprecations. The discussion influences both submodule remote handling and broader modernization of `remote.c`, serving as a case study in Git's ongoing codebase evolution.
