Refactoring patch in Patrick Steinhardt's maintenance task series that introduces a foreground/background split for maintenance operations. This is part of the broader effort to resolve race conditions in Git's maintenance system, particularly around lockfile contention for the "packed-refs" file.

The patch restructures the `maintenance_task` struct to separate operations that must run in the foreground (to avoid extended lockfile holds) from those that can safely run in the background. It introduces:
- New `foreground` and `background` function pointers in the task struct
- A `task_phase` enum to track execution context
- Modified `maybe_run_task()` helper that respects the execution phase
- Split execution in `maintenance_run_tasks()` to run foreground tasks before detaching

Key technical changes:
- All existing tasks are initially assigned to `background` only (no behavior change yet)
- Trace2 regions now distinguish between foreground and background operations
- The task execution flow now has two distinct passes (foreground pre-detach, background post-detach)
- Prepares for follow-up patches that will assign specific tasks to foreground phase

This is a foundational change in the series that enables the actual lockfile safety fixes coming in later patches. The implementation maintains all existing behavior while establishing the architectural framework needed to properly split maintenance operations by their locking requirements.
