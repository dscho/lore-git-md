This is a bugfix patch addressing array access issues in MIDX (multi-pack-index) bitmap handling, part of an ongoing series to improve MIDX chain safety. The patch introduces a new helper function `nth_midxed_pack_name()` to safely access pack names across MIDX chains, fixing potential out-of-bounds array accesses when dealing with incremental MIDX files.

The key technical changes:
- Replaces direct `pack_names[i]` array accesses with the new helper function
- Fixes two bugs in `pack-bitmap.c` where original code could access out-of-bounds when `i` exceeded `num_packs` in chained MIDX scenarios
- Updates test helper code to use the new helper, though these changes are cleanups rather than bugfixes
- Maintains same behavior for non-chained MIDX cases

The patch responds to Junio Hamano's review questioning whether the original accesses were correct in chained MIDX scenarios. Taylor Blau confirms these were indeed bugs in the bitmap handling code, not just cleanups as originally framed. The new helper properly handles pack ID translation between global and local indices in chained MIDX scenarios.
