Refactoring patch in Patrick Steinhardt's maintenance task execution series (v4 3/12). This change centralizes the configuration logic for explicitly requested maintenance tasks (`--task=` option) while eliminating global state modifications during option parsing.

The patch moves task selection state management out of `task_option_parse()` (which previously modified the global `tasks[]` array directly) into a new centralized `initialize_task_config()` function. Key changes:
- `task_option_parse()` now collects selected tasks in a string list without modifying global state
- Task ordering logic moves to `initialize_task_config()` which processes the collected selections
- Eliminates duplicate initialization of `selected_order` fields
- Uses `string_list` to track selections during parsing

This is part of the series' broader effort to eliminate global state and improve code organization around maintenance task execution. The change doesn't modify behavior but makes the control flow clearer by:
1. Separating option parsing from configuration
2. Grouping all task configuration logic in one place
3. Preparing for complete removal of global state (to come in later patches)

The patch touches `builtin/gc.c` exclusively, modifying how the `--task` option processing interacts with the maintenance task array. It maintains all existing functionality while making the code more maintainable and setting up for subsequent global state elimination.
