This is a refactoring patch in Patrick Steinhardt's maintenance task execution series (v4 04/12). It enforces mutual exclusivity between incompatible `git maintenance run` options and modernizes the error handling for these cases.

The patch makes two key changes to option validation in `builtin/gc.c`:
1. Explicitly marks `--task=` and `--schedule=` as incompatible options since they represent fundamentally different approaches to task selection (explicit vs strategy-based)
2. Converts the existing `--auto`/`--schedule=` incompatibility check to use the standard `die_for_incompatible_opt2()` helper function for consistency

The implementation updates both the core logic and test suite:
- Replaces direct `die()` with the structured helper function
- Adds a new test case for the `--task`/`--schedule` conflict
- Updates the existing test for `--auto`/`--schedule` to expect the new error message format

This change fits into the series' broader goals of improving code quality and consistency while maintaining the same behavior. The use of `die_for_incompatible_opt2()` follows Git's standard patterns for option validation, making the code more maintainable. The test updates ensure the new validation behaves as expected while preserving backward compatibility with existing error handling expectations.
