This is a small but useful ergonomic improvement to Git's error handling infrastructure, proposed as part of Patrick Steinhardt's larger maintenance task refactoring series.

The patch allows `die(NULL)` to be called when code has already printed an error message but wants to exit with the standard Git error code (128). Previously this required manually calling `exit(128)`, which was error-prone and left magic numbers in the code. The change is simple but meaningful - it standardizes error exits while maintaining compiler safety (the `printf` format attribute still works despite the NULL format string).

Junio Hamano notes some initial surprise that compilers accept NULL as a format string given the printf attribute, but confirms this works across supported compilers. The change appears well-considered and fits naturally with the series' broader goal of standardizing error handling patterns. While small, it's the kind of quality-of-life improvement that makes the codebase more maintainable over time.
