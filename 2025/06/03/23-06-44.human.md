Compiler warning fix for reftable subsystem, addressing a use-after-free warning in `parse_names()` function.

This is the second patch in a 4-part series (no cover letter seen yet) that silences a GCC warning about potential use-after-free in the reftable code. The warning occurs at `-O3` optimization level when freeing elements of the `names` array in the error path of `parse_names()`. The compiler's analysis suggests the array elements might be accessed after being freed, though the actual control flow makes this impossible.

The fix wraps the cleanup code in a `names != NULL` check, which maintains the same behavior while making the control flow more explicit to the compiler. This follows the pattern from the first patch in the series (which addressed a similar warning in parse-options.c). The change is minimal and low-risk, touching only the error handling path in reftable's basics.c file.

The patch appears straightforward and well-justified, following the same defensive programming approach as the previous warning fix in the series. The commit message could be slightly more detailed about why this particular warning is a false positive, but the technical content of the change itself looks correct.
