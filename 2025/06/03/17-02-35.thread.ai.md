Git v2.50.0-rc1 release candidate from Junio C Hamano, first preview of upcoming Git 2.50.0 version. Contains 592 non-merge commits from 84 contributors (33 new). Release highlights: new diff filters, cruft pack handling, TCP keepalive config, multi-pack index updates. Performance work includes repository instance usage improvements, fsck enhancements, refname optimization, merge-recursive deprecation. Build system updates. Critical build system regression affecting NonStop systems when building without TCL/Tk (NO_TCLTK). Build system bug where `generate-tclindex.sh` incorrectly interprets `$@` as shell script syntax (expanding to all arguments) rather than Makefile syntax (target file reference) during NO_TCLTK builds, causing deletion of TCL files from git-gui/lib. Root cause analysis by Johannes Sixt shows behavior changed from Git 2.49 due to new TCL index generation infrastructure. Two potential fixes identified: modify `rm` to target only `lib/tclIndex` or remove the line entirely. Temporary workaround confirmed by Junio Hamano: pass `NO_TCLTK=NoThanks` as command-line argument to `make` (or set in config.mak), which skips building gitk and git-gui. This provides immediate relief while proper fix is finalized for 2.50.0 release.

Regression investigation history: Randall S. Becker initially reported missing TCL files, with Patrick Steinhardt finding discrepancy between `git ls-tree` (showing files present) and tarball contents. Analysis shifted from tarball corruption suspicion to build process itself, specifically NO_TCLTK interaction with new TCL processing. Johannes Sixt previously noted issue occurs when ALL_LIBFILES is empty. Junio Hamano acknowledges the oversight in review, noting the issue was "right in front of all of us" but went unnoticed. The bug affects all platforms building without TCL/Tk support and represents clear behavior change from Git 2.49, causing data loss (deleting source files) during builds. Consensus remains on root cause and solution approaches, with the thread now addressing immediate user impact while the core fix is finalized for 2.50.0 release. The regression is considered critical and must be addressed before final release.

Todd Zullinger provides Fedora-specific packaging context, reinforcing Junio's recommendation to use `make NO_TCLTK=NoThanks` as a command-line argument rather than modifying config.mak. Highlights packaging consideration of consistent make flags across build stages to avoid unnecessary rebuilds. Fedora's approach of writing flags to config.mak via heredoc (with rpm macro expansion) serves as practical example, though immediate workaround remains command-line NO_TCLTK setting. This is supporting packaging perspective rather than technical advancement of core issue.
