Git v2.50.0-rc1 release candidate from Junio C Hamano, first preview of upcoming Git 2.50.0 version. Contains 592 non-merge commits from 84 contributors (33 new). Release highlights: new diff filters, cruft pack handling, TCP keepalive config, multi-pack index updates. Performance work includes repository instance usage improvements, fsck enhancements, refname optimization, merge-recursive deprecation. Build system updates. Critical build system regression affecting NonStop systems when building without TCL/Tk (NO_TCLTK). Build system bug where `generate-tclindex.sh` incorrectly interprets `$@` as shell script syntax (expanding to all arguments) rather than Makefile syntax (target file reference) during NO_TCLTK builds, causing deletion of TCL files from git-gui/lib. Root cause analysis by Johannes Sixt shows behavior changed from Git 2.49 due to new TCL index generation infrastructure. Johannes Sixt's fix addresses the core issue by correcting the problematic `rm` command in `generate-tclindex.sh` - changing `rm -f $@` to `rm -f lib/tclIndex` in the error path, directly fixing the source file deletion while preserving all other index generation behavior. This resolves the regression introduced in commit 2cc5b0facfa4 which converted Makefile commands to shell script but missed proper `$@` translation.

Regression investigation history: Randall S. Becker initially reported missing TCL files, with Patrick Steinhardt finding discrepancy between `git ls-tree` (showing files present) and tarball contents. Analysis shifted from tarball corruption suspicion to build process itself, specifically NO_TCLTK interaction with new TCL processing. Johannes Sixt previously noted issue occurs when ALL_LIBFILES is empty. Junio Hamano acknowledges the oversight in review, noting the issue was "right in front of all of us" but went unnoticed. The bug affected all platforms building without TCL/Tk support and represented clear behavior change from Git 2.49, causing data loss (deleting source files) during builds. The definitive fix now exists and must be included in Git 2.50.0's final release. Temporary workaround (passing `NO_TCLTK=NoThanks` to make) remains available but is no longer necessary with this patch.

Randall Becker confirms successful builds on NonStop systems after applying Johannes Sixt's fix, verifying the regression is fully resolved. Todd Zullinger provides additional Fedora packaging context, explaining how rpm macros can generate config.mak contents programmatically for consistent builds, though command-line make variables remain preferred for one-off builds. The discussion clarifies that while config.mak modifications are useful for packaging systems needing consistent flags across multiple make steps, the core issue is now properly fixed at the source through Johannes Sixt's patch. This closes the loop on the build system regression before the final 2.50.0 release, with all affected platforms (including NonStop) confirmed working as expected.
