This is a documentation patch that's part of a bugfix series addressing memory leaks in bitmap loading. The patch clarifies misleading comments in `test_bitmap_commits()` that incorrectly suggested the function could avoid reading commit data entirely when printing bitmap-selected commits.

The original comment claimed the commit table didn't need to be read, but in reality the function must load bitmap entries to obtain commit IDs for printing. The new wording more accurately that while the commit lookup table is bypassed, bitmap entries are still eagerly loaded when needed. This is the second of three patches in the series, serving as preparatory work for the test infrastructure improvements that follow.

The change is straightforward - just rewording a comment to better match the actual code behavior. While small, it helps future readers understand why the bitmap loading occurs in this function. The patch has Lidong Yan's sign-off and appears ready for inclusion, having gone through multiple review iterations in the series.
