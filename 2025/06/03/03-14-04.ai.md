This is the third and final patch in a bugfix series addressing memory leaks in pack-bitmap.c's bitmap loading paths. The patch adds comprehensive test coverage for corrupt bitmap handling, building on the previous two patches that addressed the memory leaks themselves.

The key technical additions are:
1. A new `map_pos` field in `struct stored_bitmap` to track each bitmap's position in the bitmap file
2. A `test_bitmap_commits_with_offset()` function that outputs structured data about bitmap positions (commit OID, commit index position, xor offset, flags, and EWAH bitmap positions)
3. A corresponding `test-tool bitmap list-commits-with-offset` helper command
4. A test case in t5310 that intentionally corrupts the xor_offset field of the first bitmap entry and verifies behavior

The test infrastructure allows precise corruption injection by knowing the byte offsets of key bitmap fields. The test case demonstrates this by modifying the xor_offset field while verifying the bitmap still produces correct object lists. The implementation builds on the series' earlier work by:
- Using the centralized `free_bitmap_index()` cleanup approach established in patch 1
- Relying on the clarified bitmap lookup table comments from patch 2
- Providing reusable instrumentation for future bitmap corruption testing

The patch completes the series' goal of fixing memory leaks while improving test coverage for corrupt bitmap handling. The test helper's structured output format (commit OID + field positions) provides a foundation for testing other bitmap corruption scenarios.
