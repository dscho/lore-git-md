This is a follow-up in the platform-specific `-Wunreachable-code` warnings thread, confirming the resolution of a Windows-specific build issue. Mike Hommey reports that Junio Hamano's suggested solution using the `NOT_CONSTANT()` pattern successfully suppresses the warning for the `create_ref_symlink()` case in `refs/files-backend.c`.

The issue stems from Windows platforms defining `NO_SYMLINK_HEAD``, which makes `create_ref_symlink()` always return -1, creating dead code that triggers the warning. The solution wraps the condition in `if (NOT_CONSTANT(!create_ref_symlink(...)))`, matching the established pattern previously used for `sigfillset()` cases. This maintains the code's cross-platform correctness while avoiding compiler warning noise.

Mike notes this fix has been included in a larger warning-fix patch series he's submitted.
