Jacob Keller's bug report about submodule failures when `clone.defaultRemoteName` differs from "origin" has evolved into a deeper discussion about modernizing Git's remote handling code. The core issue stems from `repo_get_default_remote` hardcoding "origin", but investigation revealed broader architectural challenges in `remote.c` - particularly with deprecated functions that incorrectly assume `the_repository` global variable despite being called with repository context.

Junio Hamano has now weighed in strongly in favor of modifying these deprecated functions (`read_remotes_file` and `read_branches_file`) to properly accept repository pointers before their planned removal in Git 3.0. He sees this as both generally beneficial for code quality and specifically valuable for Jacob's submodule use case. Junio has specifically asked for Patrick Steinhardt's input, recognizing this change may impact areas he maintains.

The thread now balances two timelines: the immediate need to fix submodule operations broken by non-default remote names, and the longer-term goal of properly modernizing remote handling code. The solution will likely involve making these deprecated functions repository-aware while also addressing the original submodule issue, with both changes serving Git's ongoing architectural evolution away from global variables.
