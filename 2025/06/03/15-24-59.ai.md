This is a discussion about error handling standardization in Patrick Steinhardt's maintenance refactoring series, specifically addressing the `die(NULL)` pattern introduced in patch 10/12.

Junio Hamano notes that while the `die(NULL)` approach provides cleaner error handling by avoiding magic numbers from direct `exit(128)` calls, it's surprising that compilers don't warn about passing NULL to a printf-format function (given the `__attribute__((format (printf, 1, 2)))` annotation). The patch demonstrates converting cases where error messages is already printed to use `die(NULL)` instead of `exit(128)`, as seen in the example where patch format detection fails.

The discussion highlights an implementation detail about compiler behavior with NULL format strings in printf-style functions, while acknowledging the ergonomic improvement this change brings to error handling standardization. This fits into the series' broader goal of cleaning up error handling patterns while eliminating global state. The exchange suggests the approach is sound as long as supported compilers handle NULL format strings appropriately.
