Platform compatibility patch addressing compiler warnings on macOS and Windows.

Mike Hommey follows up on Jeff King's earlier discussion about `-Wunreachable-code` warnings, noting another instance where platform-specific behavior triggers the warning. The original issue arose when enabling this compiler flag in `config.mak.dev`, which caught a `die_errno()` call after `sigfillset()` that would never execute on macOS due to platform implementation details.

Hommey points out a similar case in `refs/files-backend.c` where `create_ref_symlink()` is defined to always return -1 on Windows (via `NO_SYMLINK_HEAD`), making the conditional `continue` unreachable code. This continues the thread's theme of platform-specific compiler warnings that stem from legitimate but platform-dependent code patterns.

The discussion highlights the tension between writing portable code that follows POSIX specifications and compiler optimizations that can detect platform-specific dead code. While these are valid warnings from the compiler's perspective, the code is intentionally written this way for cross-platform compatibility. The thread shows developers working through the practical implications of enabling stricter compiler warnings across Git's multi-platform codebase.
