Maintainer approval for config variable documentation policy. This is the final step in a thread addressing portability issues with OpenBSD's sed implementation during config-list.h generation.

Junio C Hamano gives his approval to Collin Funk's v2 patch that adds a new section to CodingGuidelines, formalizing the one-config-variable-per-line documentation style. The patch was previously reviewed by Jacob Keller and incorporates Junio's suggested example format. The change establishes project policy to avoid comma-separated config variable listings in documentation, which had caused build problems on OpenBSD systems.

The new guidelines provide clear before/after examples showing the preferred formatting for related config variables, with rationale emphasizing both portability (avoiding sed line continuation issues) and improved greppability. This completes the solution that began with Collin's restructuring of config.adoc files in an earlier patch series.

The thread demonstrates effective collaboration between the maintainer and contributor, with Junio providing the initial suggestion and Collin implementing both the technical fix and policy documentation while offering co-authorship credit for the final wording. The change maintains compatibility with parallel documentation standardization work by Jean-Noël Avila.
