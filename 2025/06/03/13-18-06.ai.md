This is a refactoring patch that's part of the `the_repository` removal effort. It moves the `core.sparsecheckout` configuration from a global variable `core_apply_sparse_checkout` to being stored in the `repo_settings` struct, with new getter/setter functions `repo_settings_get_apply_sparse_checkout()` and `repo_settings_set_apply_sparse_checkout()`.

The patch updates 14 files to use the new accessors instead of the global variable, including core commands like `clone`, `mv`, `sparse-checkout`, and `worktree`. A notable change is removing the `USE_THE_REPOSITORY_VARIABLE` macro from builtin/backfill.c since it's no longer needed to access the setting.

The changes are mechanical but widespread, touching sparse-checkout related code across multiple subsystems. The patch follows the established pattern for moving configuration into repo_settings, similar to other recent refactorings. The commit message clearly states this is part of the ongoing effort to eliminate globals and improve modularity.

Key technical details for future reference:
- The setting is now stored in `repo_settings.core_apply_sparse_checkout`
- Access requires a repository handle via the new getter/setter functions
- The config parsing was moved from config.c to repo-settings.c
- All callers needed updates to pass the repository parameter
- The change enables removing one more global variable from environment.h
