This is a documentation policy refinement in the ongoing thread about config variable formatting conventions. Collin Funk responds to Junio C Hamano's feedback on the proposed CodingGuidelines update regarding how to document multiple related config variables.

The discussion centers on two key points: First, whether config variable names in documentation should be marked up with backticks (like `` `core.var1` ``) even though the current config.adoc files don't consistently use this style. Second, whether to emphasize the greppability benefits of the one-variable-per-line format in addition to the script compatibility rationale.

Collin notes the inconsistency with existing documentation style and seeks clarification before sending a v2 patch. Junio had suggested showing both incorrect (comma-separated) and correct (separate-line) examples with literal backtick markup, while also proposing to highlight the greppability advantage of the new format. The thread appears to be converging on a solution that will both fix the OpenBSD sed compatibility issue and improve documentation practices going forward.
