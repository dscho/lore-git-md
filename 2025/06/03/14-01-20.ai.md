This is the final patch in Patrick Steinhardt's v4 series refactoring Git's maintenance task execution to eliminate race conditions and improve code quality. The patch specifically addresses a locking race in the "gc" task by splitting it into foreground and background phases, completing the series' systematic approach to race condition prevention.

The key technical changes in this patch:
- Renames `gc_before_repack()` to `gc_foreground_tasks()` to better reflect its purpose
- Splits the "gc" task into separate foreground and background implementations
- Foreground phase handles ref packing and reflog expiration (critical for lock safety)
- Background phase runs the actual GC with a new `--skip-foreground-tasks` flag
- Updates all test cases to account for the new flag
- Maintains the same behavior while making the execution flow more explicit

The patch builds on previous work in the series that established the foreground/background split framework and addressed similar races in "pack-refs" and "reflog-expire" tasks. It completes the systematic elimination of lockfile races across all maintenance operations while maintaining backward compatibility.

Subsystems modified:
- `builtin/gc.c`: Implements the phase split for GC task
- `t/t7900-maintenance.sh`: Updates tests to verify new behavior

This represents the culmination of the series' three-track approach (race fixes, terminology improvements, and code quality refactoring), with all maintenance tasks now properly split between phases and all known lockfile races addressed. The implementation maintains test coverage while making the control flow more explicit and type-safe.
