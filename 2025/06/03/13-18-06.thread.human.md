Ayush Chandekar's sparse-checkout refactoring series, which moves configuration from global variables to the `repo_settings` struct as part of the broader `the_repository` removal effort, remains in limbo. The v5 series addressed all prior technical concerns about initialization safety and config handling, but has been back-burnered while the author works on other patches. 

In a status update, Ayush clarified some implementation details that weren't fully explained in the original commits: the series actually introduced two new `prepare_repo_settings()` calls in the first patch (not one), with others being reorganized, while the second patch added just one new call. The author confirmed the remaining global could now safely move to `repo_settings` given the proper initialization patterns are in place.

Junio Hamano had raised questions about the UX of accepting invalid config input mid-operation rather than failing fast at startup, and noted the series might need to be temporarily dropped from the 'seen' branch to avoid conflicts with other changes. Ayush has given Junio permission to do so if needed, while taking responsibility for the delayed response. The technical work appears complete, but the series awaits either a final decision on config validation timing or further author input before proceeding. This represents one of the more substantial remaining pieces of the `the_repository` globals removal effort for sparse-checkout.
