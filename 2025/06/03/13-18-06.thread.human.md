This thread follows Ayush Chandekar's v6 patch series that moves sparse-checkout configuration from global variables into the `repo_settings` struct, completing an important piece of the `the_repository` removal effort. The series has addressed all technical concerns from previous rounds, with all three settings (`core.sparsecheckout`, `core.sparsecheckoutcone`, and `sparse.expectfilesoutsideofpatterns`) now properly migrated and validated.

Junio Hamano has now raised two higher-level architectural questions that go beyond the immediate implementation. First, he suggests reconsidering where `prepare_repo_settings()` calls should live - possibly centralizing them in `run_builtin()` for commands with `RUN_SETUP` - though this would require performance evaluation since config parsing wasn't traditionally part of repository setup. Second, he follows up on Phillip Wood's earlier concern about late config parsing in the final patch, asking whether any user-facing behavior regression remains. 

While not blocking the technically complete series, Junio also requests clearer documentation of why these settings belong in `repo_settings` rather than directly in `struct repository`. This discussion is now exploring broader patterns for future configuration migrations, even as the current work stands ready for integration. The thread remains active as these design considerations are worked through.
