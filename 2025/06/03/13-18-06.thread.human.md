This thread continues Ayush Chandekar's work to refactor Git's sparse-checkout configuration by moving three global variables (`core.sparsecheckout`, `core.sparsecheckoutcone`, and `sparse.expectfilesoutsideofpatterns`) into `struct repository`. The effort is part of the broader project to eliminate the `the_repository` global variable.

Following architectural guidance from Derrick Stolee, the work is now proceeding in two clear phases: first a mechanical move of the globals to `the_repository->sparse_checkout[_cone]` while preserving current behavior, followed by proper per-repository configuration handling. This phased approach addresses earlier concerns from Junio Hamano about more invasive proposals.

Chandekar's latest update shows active experimentation with different implementation approaches for phase one, testing variations in how the values are stored (int vs boolean) and initialized. Some test failures have surfaced when changing initialization behavior, highlighting the need for careful verification. The update confirms the team is aligned on Stolee's recommended path forward while working through the technical details of the first phase.

Key open items include finalizing the storage approach, verifying behavior preservation through testing, and documenting the changes. The second phase - implementing true per-repo configuration - remains future work that will build on these initial changes. This refactoring serves as both an immediate improvement and a model for future configuration system changes.
