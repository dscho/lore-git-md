This is a patch in Patrick Steinhardt's maintenance task refactoring series that improves option validation. The change marks `--task=` and `--schedule=` as mutually incompatible options in `git maintenance run`, since they represent fundamentally different ways to select which tasks to run (explicit selection vs. following the configured strategy).

The patch also modernizes the existing check between `--auto` and `--schedule=` to use the standard `die_for_incompatible_opt2()` helper function, making the error handling more consistent. The test suite is updated to verify both cases produce clear error messages.

This is a straightforward improvement that prevents nonsensical combinations of options while cleaning up the code. It's part of the larger effort to systematically improve the maintenance command's internals, though this particular change stands on its own as a clear correctness fix. The patch is small, focused, and well-tested - exactly what you'd want in a series that's already gone through several rounds of review.
