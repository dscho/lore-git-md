Documentation policy update codifying the config.adoc formatting convention established in the recent OpenBSD sed compatibility fix. This patch adds a section to CodingGuidelines mandating that related `git config` variables must be listed one-per-line rather than comma-separated in documentation, as required by the generate-configlist.sh script's parsing logic.

The change formalizes the solution implemented in Collin Funk's v3 patch (previously reviewed by Jacob Keller and accepted by Junio C Hamano) that restructured gitcvs.adoc and http.adoc to work around OpenBSD sed limitations. The new guideline section provides both the correct format example and explicitly states the requirement is for config-list.h generation compatibility. This prevents regression to the problematic comma-separated format while documenting the project's chosen solution pattern.

The patch follows the exact formatting style used elsewhere in CodingGuidelines, with proper asciidoc syntax for config variables and script references. As the final piece of the resolved thread, it establishes clear policy for future contributors while maintaining the portable build solution's effectiveness. No technical changes are needed beyond the documentation addition since the actual implementation was already merged.
