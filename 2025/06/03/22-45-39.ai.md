Documentation update finalizing the config variable formatting policy that emerged from the OpenBSD sed compatibility fix. This v2 patch adds a section to CodingGuidelines mandating one-config-variable-per-line documentation format, with Junio C Hamano's suggested-by attribution indicating maintainer approval of the approach.

The patch provides both anti-pattern (comma-separated) and correct (line-separated) examples, formalizing the style used in the earlier solution for gitcvs.adoc and http.adoc. The wording avoids making this a blanket prohibition on commas in documentation, focusing specifically on config variable listings where the format impacts both script parsing and human greppability.

This represents the documentation policy counterpart to the technical solution already merged (restructuring config.adoc files to avoid sed line continuation issues). The thread shows consensus on the technical merits, with current discussion focused on optimal policy presentation. The patch follows the incremental standardization approach acknowledged in the thread, where backtick formatting improvements are being handled separately by Jean-Noël Avila's ongoing documentation work.

Key elements include the clear before/after examples and placement within the existing "Documentation" section of CodingGuidelines. The change is narrowly scoped to address the immediate portability problem's root cause while establishing guardrails against similar issues, without disrupting parallel documentation standardization efforts.
