Error handling standardization patch in Patrick Steinhardt's maintenance refactoring series.

This patch (10/12) introduces a cleaner way to handle fatal errors in Git commands by allowing `die(NULL)` to exit with status 128 without printing a redundant error message. The change addresses cases where code paths already printed their own error messages but needed to exit with Git's standard error code. Previously this required using the magic number `exit(128)`, which was both opaque and easy to get wrong.

The implementation modifies `die_message_builtin()` to silently exit when passed NULL, then updates several builtins (`am`, `checkout`, `fetch`, and `submodule--helper`) to use the new pattern. The changes are mechanical but improve code clarity and maintainability by eliminating magic numbers and centralizing error handling behavior.

This is part of the broader maintenance task refactoring effort to improve code quality and eliminate race conditions, though the change stands on its own as a general improvement to Git's error handling infrastructure. The patch follows the series' pattern of methodical, focused changes that maintain backward compatibility while cleaning up technical debt.
