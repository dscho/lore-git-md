This is the final patch in Patrick Steinhardt's v4 series refactoring Git's maintenance task execution to eliminate race conditions. The patch specifically addresses a locking race in the "gc" task by splitting its execution between foreground and background phases, similar to the earlier fixes for "pack-refs" and "reflog-expire" tasks.

The key change moves the `gc_before_repack()` logic (renamed to `gc_foreground_tasks()`) to run in the foreground phase, while the actual GC runs in the background with a new `--skip-foreground-tasks` flag to prevent duplicate execution. This maintains the same behavior as regular `git gc` while preventing lock contention.

The patch is well-integrated with the series' broader goals of eliminating global state and standardizing task execution patterns. It includes test updates to verify the new behavior and follows the established pattern of using `die(NULL)` for error handling. As the concluding patch in this substantial refactoring effort, it completes the systematic approach to safer maintenance task execution.
