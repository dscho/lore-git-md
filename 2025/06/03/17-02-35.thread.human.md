The Git 2.50.0-rc1 release candidate had a critical build system regression where `generate-tclindex.sh` was incorrectly deleting source TCL files during NO_TCLTK builds. This was first reported by Randall S. Becker and analyzed by Johannes Sixt and Patrick Steinhardt, who traced it to a misinterpretation of `$@` in the script's error cleanup path. Junio Hamano confirmed a temporary workaround (using `NO_TCLTK=NoThanks`) while the proper fix was developed.

Johannes Sixt has now provided the definitive solution - a minimal patch that corrects the problematic `rm` command to explicitly target only `lib/tclIndex` rather than expanding `$@` to all arguments. This cleanly fixes the regression introduced in commit 2cc5b0facfa4 while preserving all other index generation behavior. The patch represents the culmination of the thread's technical analysis and will be included in Git 2.50.0's final release, resolving the critical issue that affected all platforms building without TCL/Tk support.
