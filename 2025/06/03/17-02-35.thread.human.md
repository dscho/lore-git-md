The thread concerns a critical build system issue in Git 2.50.0-rc1 that breaks builds on NonStop and other platforms without TCL/Tk support (NO_TCLTK). Initially, Randall Becker identified the problem as missing TCL files in the release tarball's git-gui/lib directory, causing build failures when the system attempted to process non-existent files. Further investigation by Patrick Steinhardt revealed the files should be present according to the Git tree, suggesting a tarball generation issue.

Randall has now provided new evidence that the problem occurs during the build process itself - the TCL files exist initially but are being deleted when the new `generate-tclindex.sh` script fails (as expected in NO_TCLTK builds). This points to a regression in the build system's handling of TCL dependencies, where the script incorrectly modifies source files even when TCL support is disabled. The behavior changed from Git 2.49, implicating recent build system changes that weren't properly tested in NO_TCLTK configurations. Junio had previously expressed concern about these changes needing more review. The issue now appears to be a build system bug rather than a packaging problem, affecting all platforms building without TCL/Tk support.
