This thread began with Junio Hamano announcing Git v2.50.0-rc1, which included a critical build system regression affecting NonStop systems when building without TCL/Tk support. Johannes Sixt identified and fixed the issue, which was causing TCL files to be incorrectly deleted during builds, and Randall Becker confirmed the fix worked on NonStop systems.

Now Johannes Sixt has followed up with a major modernization of git-gui, building on his earlier fix. The series updates git-gui's minimum requirements to Tcl/Tk 8.6 and Git 2.36, removing decades-old compatibility code while adding support for modern features like SHA-256 repositories. The changes include significant refactoring of process handling (led by Mark Levedahl) and a Bulgarian translation update. This cleanup removes technical debt while maintaining functionality, with the changes already tested against Git 2.50.1. The modernization appears thorough and well-considered, touching nearly all git-gui components but focused on removing obsolete code paths rather than changing behavior.
