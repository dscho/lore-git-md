This is a refactoring patch in Patrick Steinhardt's v4 series (5/12) that eliminates global state in Git's maintenance task execution. The patch focuses on cleaning up how maintenance tasks are configured and selected, moving from a system that directly modifies a global array of tasks to one that computes the task list in a self-contained way.

The patch removes three problematic global state fields from the `maintenance_task` struct (`enabled`, `schedule`, and `selected_order`) and instead builds the list of tasks to run in the options structure passed through functions. This makes the logic more contained and easier to follow, as the decision about which tasks to run is now centralized in `initialize_task_config()` rather than being spread across multiple functions that modify global state.

The changes include:
- Moving task selection state into `struct maintenance_run_opts`
- Introducing a new `maintenance_strategy` struct to cleanly represent different maintenance configurations
- Simplifying the task execution loop to just iterate through the pre-computed task list
- Better separation between scheduled and explicitly requested maintenance runs

This is a key step in the series' goal of making maintenance task execution more robust by eliminating race conditions and global state. The patch maintains all existing behavior while making the code more maintainable. It follows naturally from the earlier patches that established cleaner initialization patterns and removed variable duplication.
