Bugfix addressing a memory leak in pack-bitmap.c's bitmap loading paths. This is the first patch in a v5 series that consolidates earlier work on fixing memory leaks when loading corrupt bitmaps.

The patch removes redundant cleanup code in `load_bitmap()` that was causing memory leaks of EWAH bitmaps when loading failed partway through. The key insight is that callers (`prepare_bitmap_walk()` and `prepare_bitmap_git()`) already call `free_bitmap_index()` on failure, making the per-error-path cleanup in `load_bitmap()` both redundant and harmful (as it NULLs pointers before the centralized cleanup can access them).

The change replaces all `goto failed` jumps with direct `return -1` statements, removing ~17 lines of error-handling code while maintaining safety. This simplification was reviewed and confirmed correct by Jeff King in earlier iterations. The patch carries sign-offs from both Taylor Blau (who implemented the fix) and Lidong Yan (who originally reported the issue).

This is a clean, focused change that eliminates a memory leak while reducing code complexity - a rare case where fixing a bug actually removes code rather than adding it. The patch touches only pack-bitmap.c, modifying the `load_bitmap()` function's error handling paths. It builds on the thread's established consensus to use centralized `free_bitmap_index()` cleanup rather than per-error-path handling.
