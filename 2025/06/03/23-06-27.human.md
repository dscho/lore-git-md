This is a bug report and potential feature proposal regarding submodule behavior when `clone.defaultRemoteName` is set to something other than "origin". Jacob Keller encountered an issue where submodule operation failed because `submodule--helper` hardcodes "origin" as the remote name, ignoring the configured default.

The problem manifests when fetching submodules in a repository where the main remote isn't named "origin", causing Git to fail with confusing error messages. Keller proposes several potential solutions, including checking for a single remote first, respecting `clone.defaultRemoteName`, and possibly adding a new submodule-specific config option to control this behavior.

The patch appears well-motivated by a real-world usability issue, though the exact solution isn't yet determined. The proposal thoughtfully considers backward compatibility by suggesting fallbacks to existing behavior. This seems like a straightforward quality-of-life improvement that would make Git more consistent with its own configuration options.
