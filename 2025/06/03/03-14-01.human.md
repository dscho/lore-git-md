This is version 5 of a bugfix series addressing memory leaks in pack-bitmap.c, with the main fix coming from Taylor Blau and test infrastructure from Lidong Yan. The series has evolved through multiple rounds of review, with the current version incorporating feedback on commit messages and test improvements.

The core fix prevents memory leaks when `load_bitmap()` fails by removing redundant cleanup code and relying on callers' `free_bitmap_index()` for uniform cleanup. This actually removes code (~17 lines) while making the error handling more robust. The patch has been reviewed by Jeff King and Junio C Hamano, with technical consensus that this is the right approach.

Lidong Yan contributes two supporting patches:
1. A comment reword in `test_bitmap_commits()` to clarify behavior
2. A new test case that uses a `test-tool bitmap` helper to deliberately corrupt bitmaps and verify the leak fix works. The test infrastructure has been refined through review iterations, with improvements like:
   - Simplified data structures (removing `stored_bitmap_tag_pos`)
   - More reliable test verification using sorted full object lists
   - Better naming (`list-commits-with-offset` instead of `list-commits-offset`)

The series appears ready for merging, with all technical feedback addressed and only minor commit message refinements requested by Junio remaining. The patches demonstrate good test coverage and careful attention to edge cases in bitmap handling. This is a solid example of collaborative debugging, with clear problem identification, thorough testing, and clean solutions.
