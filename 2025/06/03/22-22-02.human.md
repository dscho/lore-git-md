This is a bugfix patch in the multi-pack-index (MIDX) subsystem, addressing potential array underflow issues when accessing pack names in chained MIDX files. The patch introduces a new helper function `nth_midxed_pack_name()` to safely access pack names across MIDX chain boundaries.

Taylor Blau confirms that several direct accesses to `pack_names[i]` in the original code were indeed buggy when MIDX files are chained, particularly in the bitmap handling code where array indices could exceed valid bounds. The new helper function properly handles pack ID translation between global and local indices in chained MIDX scenarios.

The patch fixes three specific bugs:
1. In `open_midx_bitmap_1()` where warning messages could access out-of-bounds pack names
2. In `reuse_partial_packfile_from_bitmap()` for similar warning messages
3. In `read_midx_preferred_pack()` for preferred pack name access

Junio Hamano's review correctly identified these as potential bugs rather than just cleanups, and Taylor confirms this assessment. The changes maintain the same behavior for non-chained MIDX files while fixing the chained case. This is part of ongoing work to make MIDX chain handling more robust, building on previous performance optimizations in this area.
