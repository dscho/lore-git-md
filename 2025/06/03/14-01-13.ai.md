This is a refactoring patch in Patrick Steinhardt's v4 series (5/12) that eliminates global state modifications in Git's maintenance task execution. The patch focuses on cleaning up how maintenance tasks are configured and selected.

The maintenance subsystem previously used three different fields (`enabled`, `selected_order`, `schedule`) spread across global state to determine which tasks should run, making the logic hard to follow. This patch centralizes the task selection logic in `initialize_task_config()`, storing the selected tasks in the options structure rather than modifying global arrays. The key changes include:

1. Making the `tasks` array `const` to prevent modification
2. Introducing a new `maintenance_strategy` struct to cleanly represent task configurations
3. Moving all task selection logic into `initialize_task_config()` which populates a task list in the run options
4. Simplifying the execution path in `maintenance_run_tasks()` to just iterate the pre-selected tasks

The patch maintains all existing behavior while making the code more maintainable. It builds on earlier infrastructure work in the series (like the task label enum from patch 1) and prepares for later patches that will handle race conditions. The changes are mechanical but important for eliminating global state and making the task selection logic more transparent.
