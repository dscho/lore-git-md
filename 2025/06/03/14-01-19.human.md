This is a refactoring patch in Patrick Steinhardt's maintenance task execution series (v4 11/12). It eliminates a static flag in `gc_before_repack()` that was used to prevent duplicate execution, replacing it with explicit control via the `opts.detach` flag.

The change makes the control flow more transparent by removing hidden state - the function now returns an error code rather than calling `die()` directly, and the caller decides whether to run it based on the detachment status. This matches the series' broader goal of eliminating global state and making execution flow more explicit.

The patch also converts the function's error handling to use the new `die(NULL)` pattern introduced earlier in the series (patch 10/12), maintaining consistency with the standardized error reporting approach. While this is a small change, it's part of the systematic cleanup of the maintenance task infrastructure to make it more maintainable and race-condition resistant.
