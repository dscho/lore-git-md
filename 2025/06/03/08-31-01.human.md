This is a refactoring patch that's part of Patrick Steinhardt's larger series (v3, 12 patches) addressing race conditions in Git's task execution system. The patch focuses on improving error handling by introducing a cleaner way to terminate with an error status when an error message has already been printed.

The change allows `die(NULL)` to be called as a shorthand for exiting with error code 128 when the error message has already been displayed elsewhere. This eliminates the need for direct `exit(128)` calls that were previously scattered through the code. The patch demonstrates the new pattern by converting several existing builtins to use it.

This is a small but thoughtful quality-of-life improvement that fits into the series' broader goals of code standardization and maintainability. As part of the larger refactoring effort, this change helps reduce magic numbers and makes error handling more consistent.
