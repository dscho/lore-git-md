This is a documentation patch that formalizes the solution from the recent OpenBSD sed compatibility issue into the project's CodingGuidelines. It concludes the thread by establishing a new formatting rule for documenting related config variables.

The patch adds a clear specification that when documenting multiple related config variables in AsciiDoc files, they should be listed one-per-line rather than comma-separated. This format is required for the generate-configlist.sh script to work correctly across all platforms, as discovered through the OpenBSD build issues. The example shows the preferred format with core.var1 and core.var2 each on their own line followed by a shared description.

This change codifies what was already implemented in gitcvs.adoc and http.adoc as part of the fix, making it project policy going forward. The patch carries both Junio's Suggested-by and Collin's Signed-off-by, indicating maintainer approval of this documentation addition. With this patch, the thread reaches full resolution by both implementing the technical solution and documenting it to prevent regression.
