Performance/CI investigation for the `--skip-connectivity-check` patch series, focusing on a test hang specific to Windows+Meson environments.

Patrick Steinhardt reports further investigation into the Windows+Meson test hang issue affecting the `receive-pack` connectivity check bypass tests. The problem appears consistently in both GitHub and GitLab CI when testing the series, but remains unreproducible locally despite attempts to match CI environments. The hang occurs specifically in the test that pipes `send-pack` output through `tee` to `receive-pack`.

The proposed fix replaces the direct `tee | git-receive-pack` pipe with a wrapper script approach, aligning with how other tests inject custom receive-pack commands. While this resolves the hang, the root cause remains unclear - the fix works but isn't yet understood. The issue seems tied to Windows process/pipe handling in Meson builds, as it doesn't affect Git for Windows' VS-based tests.

Key technical details:
- Problem manifests in both test cases using the tee pipe pattern in t5410-receive-pack.sh
- Fix involves creating receive-pack-wrapper scripts for both test scenarios
- Issue appears related to commit aa550efd0bb but exact interaction is unclear
- Windows+Meson CI environments show the hang while local Windows setups don't

The investigation continues to focus on why the direct pipe approach fails in CI but works locally, and why only under Meson builds. The core functionality of the `--skip-connectivity-check` feature remains unaffected, with the issue being purely test infrastructure related.
