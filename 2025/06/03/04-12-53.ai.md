Platform compatibility patch addressing header handling for OpenBSD/NetBSD systems. This is a follow-up to previous work treating these BSD variants similarly to FreeBSD/DragonFly in terms of `_XOPEN_SOURCE` definitions.

The patch removes `_XOPEN_SOURCE` requirements for OpenBSD/NetBSD, noting that OpenBSD specifically would need it set to 700 but opting for simplicity by not setting it at all. This resolves a compilation warning about implicit `getdelim` function declarations on these platforms. The change modifies `compat/posix.h` to include these BSD variants in the exclusion list where `_XOPEN_SOURCE` isn't set, while maintaining the 600 value for other systems that still it (with a slightly cleaned up comment).

The technical changes involve:
- Adding `__NetBSD__` and `__OpenBSD__` to the condition checking which platforms skip `_XOPEN_SOURCE` definition
- Reorganizing the conditional for better readability
- Removing the now-redundant note about OpenBSD needing 600 for S_ISLNK() from the comment
- Keeping the 600 value requirement for other platforms like glibc2 and AIX

This appears to be a straightforward platform-specific adjustment following the pattern established for similar BSD systems, though the commit message could benefit from more detail about why these platforms don't need the definition (beyond just being "simpler"). The change is narrowly scoped to the compatibility layer and shouldn't affect other systems.
