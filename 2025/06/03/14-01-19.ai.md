This is part 11/12 of Patrick Steinhardt's series refactoring Git's maintenance task execution to eliminate race conditions and improve code quality. The patch focuses on eliminating global state pattern in `gc_before_repack()`.

The change removes a static `done` flag that was being used to prevent duplicate execution of `gc_before_repack()` when the `--detach` flag was passed. Instead, it now makes the function return an error code and lets the caller decide whether to run it based on `opts.detach`. The function signature changes from `void` to `int` to propagate errors properly.

Key technical changes:
- Removes static `done` flag from `gc_before_repack()`
- Converts function to return `int` instead of `void`
- Changes error handling from `die()` to `error()` in the function
- Updates callers to check return value and use new `die(NULL)` pattern
- Adds explicit guard using `opts.detach` to prevent duplicate execution
- Maintains same behavior while making control flow more explicit

This continues the series' theme of eliminating global state and improving error handling patterns. The change is mechanical but makes the code's behavior more transparent by moving the execution control decision to the caller rather than hiding it behind a static variable. The patch builds on the error handling standardization introduced in patch 10/12 by using the new `die(NULL)` pattern.
