Bugfix addressing a memory leak in pack-bitmap.c's bitmap loading paths. This is the first patch in a v5 series that has been through several rounds of review, with consensus reached on the technical approach.

The patch fixes a case where partially-loaded bitmap entries would leak memory if `load_bitmap()` encountered an error. The solution removes redundant cleanup code in `load_bitmap()` and relies instead on the caller's `free_bitmap_index()` to handle cleanup uniformly. This actually simplifies the code by removing 17 lines of error-handling while maintaining safety.

The change has been reviewed by Jeff King and others, with Lidong Yan (who originally reported the issue) signing off. The patch appears well-considered, removing duplicate cleanup paths while ensuring all bitmap resources are properly freed. This is part of a broader effort to improve bitmap handling reliability, with follow-up patches adding test coverage for such cases.
