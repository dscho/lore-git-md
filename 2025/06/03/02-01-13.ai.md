This is the first patch in a 2-part series addressing memory leaks and BUG() message standardization in the sequencer. The patch converts an error() call to BUG() in update_squash_messages() since the function's contract specifies it should only receive FIXUP or SQUASH commands. The change enforces this API boundary more clearly while eliminating a potential memory leak path where the error return could skip buffer cleanup.

The technical change replaces a translated error message (which could leak memory if the function was called incorrectly) with an untranslated BUG() assertion that immediately terminates execution. The BUG() message follows the project's standardization by being untranslated and explicitly stating the expected command types. The patch includes a new early validation check using is_fixup() before any buffer operations begin.

This change is part of a larger effort to standardize BUG() messages across Git while fixing subtle resource management issues. The patch maintains the same behavior for valid inputs while making invalid usage immediately obvious during development. The v4 iteration incorporates feedback to improve the BUG() message wording to clearly document the API contract.
