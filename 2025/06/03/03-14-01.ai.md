This is version 5 of a bugfix series addressing memory leaks in pack-bitmap.c's bitmap loading paths. The series now consists of three patches (down from four in previous versions), with the key changes being:

1. Taylor Blau's patch fixing the core memory leak by removing redundant cleanup code in `load_bitmap()`, now with Lidong Yan's sign-off added. The patch simplifies error handling by relying on callers' `free_bitmap_index()` rather than duplicate cleanup paths.

2. A new patch from Lidong Yan rewording comments in `test_bitmap_commits()` to better explain the bitmap lookup table behavior. This appears to be preparatory work for the test infrastructure.

3. Lidong Yan's test case for corrupt bitmap loading, which has been significantly refactored from v4. The test helper has been renamed from `list-commits-offset` to `list-commits-with-offset` and simplified by:
   - Removing the separate `stored_bitmap_tag_pos` structure in favor of adding `map_pos` directly to `stored_bitmap`
   - Using file-based output capture instead of pipes
   - Adding full object list verification rather than just commit counts
   - Sorting outputs for reliable comparison

The test now injects corruption at specific offsets in the bitmap file and verifies the full object list remains correct, providing more thorough validation of the leak fixes. The changes address previous feedback about test infrastructure placement and commit message structure while maintaining the core technical approach that received positive reviews from Jeff King and Junio Hamano.

Key files affected remain pack-bitmap.c and t5310-pack-bitmaps.sh, with the test helper in t/helper/test-bitmap.c now providing reusable instrumentation for future bitmap corruption testing. The series appears ready for merging pending final review of the commit message improvements requested by Junio.
