Refactoring patch addressing lockfile race conditions in maintenance tasks. This is patch 9/12 in Patrick Steinhardt's series to improve Git's maintenance task execution.

The patch moves the "pack-refs" and "reflog-expire" maintenance tasks from background to foreground execution to prevent lockfile races, mirroring git-gc(1)'s established behavior. The change ensures these operations complete before any potential process detachment occurs, avoiding the race conditions around reference and reflog lockfiles that could occur when running in background mode. The modification is straightforward - simply changing the `background` field assignments to `foreground` in the task definitions for these two operations.

The commit notes that the "gc" task has similar lockfile concerns but requires more extensive changes that will be handled in a subsequent patch. The diff shows the minimal but impactful changes to the task struct array in `builtin/gc.c`, switching the function pointers for these two tasks from their background to foreground variants while keeping all other properties (names, auto-conditions) unchanged.

This patch builds on the foreground/background phase framework established earlier in the series (patch 8/12) to systematically address race conditions in maintenance operations. The change maintains all existing functionality while making the execution safer, with no user-visible behavior changes beyond the elimination of potential race conditions.
