This is a documentation patch that formalizes the project's policy on formatting related Git config variables in documentation, following the recent technical solution to OpenBSD sed compatibility issues.

The patch adds a new section to CodingGuidelines mandating that related config variables should be listed one-per-line rather than comma-separated. This change codifies the approach used in the recent fix for OpenBSD build issues, where restructuring config.adoc files to avoid problematic sed line continuations proved necessary. The patch includes clear before-and-after examples showing the preferred formatting style.

The change has already been reviewed and suggested by Junio C Hamano, indicating it aligns with maintainer expectations. This follows earlier technical approval from Jacob Keller for the implementation changes. The documentation update serves both to prevent future regressions and to standardize documentation practices, with the dual benefit of improving script compatibility and greppability.

While the technical solution has already been merged, this patch represents the final piece in formalizing the new convention. The discussion thread shows consensus around the approach, with ongoing refinement focused on optimal wording rather than substantive disagreement. The patch appears straightforward and well-justified, completing the documentation side of a resolved portability issue.
