This is a documentation patch in a bugfix effort addressing memory leaks in bitmap loading. It's the second of three patches in v5 of the series, focusing on clarifying misleading comments in `test_bitmap_commits()`.

The patch rewrites comments that incorrectly suggested the commit table could be skipped entirely when printing bitmap-selected commits. The new comments accurately explain that while the function bypasses the commit lookup table (if present), it must still load bitmap entries to obtain the commit IDs for output. The change is purely textual - no functional modifications are made to the code itself.

This appears to be preparatory work for the test infrastructure improvements in the subsequent patch (3/3), helping future readers understand why bitmap entries are loaded in this test helper. The correction is straightforward and aligns with the series' broader goal of improving bitmap handling reliability. The patch has Lidong Yan's sign-off and builds on previous reviews from Taylor Blau and Jeff King.
