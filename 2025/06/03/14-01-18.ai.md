Error handling standardization patch in Patrick Steinhardt's maintenance refactoring series.

This patch (10/12 in v4) introduces a new error handling pattern by modifying `die_message_builtin()` in `usage.c` to accept NULL as an error string, allowing callers to exit with the standard error code 128 without duplicating an error message. The change eliminates magic numbers in error paths while maintaining consistent behavior when code needs to die after already having printed its own error message.

The patch updates several builtins (`am`, `checkout`, `fetch`, and `submodule--helper`) to use this new pattern, replacing direct `exit(128)` calls with `die(NULL)`. The implementation is straightforward - when passed NULL, `die_message_builtin()` simply returns without printing anything, while still triggering the standard error handling path through `die()`.

This change is part of the series' broader effort to standardize error handling and eliminate global state. It follows the pattern established in earlier patches of using Git's existing infrastructure more consistently. The modification affects multiple subsystems but is purely an internal refactoring with no user-visible behavior changes. The patch maintains all existing functionality while making the codebase more maintainable by removing hardcoded exit codes.
