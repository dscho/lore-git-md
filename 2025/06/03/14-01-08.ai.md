This is a v4 patch series (12 patches) addressing race conditions in Git's maintenance tasks, particularly around ref and reflog locking during detached operations. The series builds on previous iterations that have been refined through review feedback, with the latest changes focusing on documentation clarity and commit message improvements.

The core issue fixes races that occur when auto-maintenance repacks references while other operations are in progress. The solution introduces a foreground/background task split in git-maintenance(1) to match git-gc(1)'s existing behavior, ensuring ref and reflog operations complete before detaching. Key technical changes include:

- Complete phase split now includes the "gc" task (final patch)
- Renamed `gc_before_repack()` to `gc_foreground_tasks()`
- Added `--skip-foreground-tasks` flag to `git gc`
- Split `maintenance_task_gc()` into separate phase handlers
- Standardized error handling via `die(NULL)` pattern (patch 10/12)
- Eliminated global state in task configuration
- Introduced `maybe_run_task()` helper for modular task execution

The series touches multiple subsystems including `builtin/gc.c`, test scripts, and `usage.c`, with careful attention to backward compatibility and test coverage. Documentation refinements from Kristoffer Haugsbakk and Karthik Nayak have been incorporated, particularly around error handling terminology.

This represents the final iteration of a well-structured series that systematically addresses race conditions while improving code quality through global state reduction, phase separation, and standardized error handling. The implementation appears thorough with comprehensive test coverage and careful attention to review feedback.
