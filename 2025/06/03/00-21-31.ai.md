This is a documentation patch that concludes a thread about portability fixes for config-list.h generation. The discussion has now shifted to documenting the new formatting conventions for config.adoc files.

The thread had previously resolved the technical issue of sed portability across platforms (particularly OpenBSD) by restructuring config.adoc files to list related configuration variables on separate lines rather than comma-separated. This solution was implemented in v3 of the patch and received maintainer approval from Junio C Hamano.

In this follow-up email, Junio agrees with Jacob Keller's suggestion to document the new convention that comma-separated entries in config.adoc are now forbidden, despite being technically allowed by AsciiDoc processors. He proposes adding this documentation to the CodingGuidelines file, specifically in the section that already covers markup conventions.

This represents the final administrative step in the thread - establishing where to document the new formatting rules that were introduced to solve the build portability issues. The technical solution is already settled, and this email focuses purely on the documentation policy aspect.
