This is the third and final patch in a bugfix series addressing memory leaks in pack-bitmap.c. It adds comprehensive test coverage for corrupt bitmap handling, building on the previous fixes.

The patch introduces a new test helper `test-tool bitmap list-commits-with-offset` that reports the exact file positions of key bitmap fields (commit index position, xor offset, flags, and EWAH bitmap data). This enables targeted corruption testing by knowing precisely where to modify the bitmap file. The test case demonstrates this by intentionally corrupting the xor_offset field of the first entry and verifying Git can still function.

The implementation tracks bitmap positions by adding a `map_pos` field to `stored_bitmap` and passing it through the bitmap loading process. This is a clean solution that builds on the series' earlier work to centralize cleanup in `free_bitmap_index()`. The test infrastructure is well-designed for reuse in future bitmap corruption testing scenarios.

With this addition, the series now provides both the memory leak fixes (patches 1-2) and robust test coverage (patch 3) for handling bitmap corruption cases. The implementation has been through multiple rounds of review and appears ready for merging.
