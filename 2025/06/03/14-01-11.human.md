This is part 3 of Patrick Steinhardt's 12-patch series refactoring Git's maintenance task execution to fix race conditions and improve code quality. The series systematically addresses core race conditions while improving terminology and internal quality.

This particular patch focuses on cleaning up how maintenance tasks are configured when explicitly requested via `--task` options. Currently, the code modifies global state during option parsing and spreads task configuration logic across multiple functions. The patch centralizes this by:

1. Making `task_option_parse()` collect tasks into a string list without modifying global state
2. Moving the actual task ordering configuration to `initialize_task_config()`
3. Using the string list to properly track selected tasks

The changes are mechanical but improve code organization and lay groundwork for further global state reduction (which the commit message notes will come in a later patch). The diff shows straightforward conversions from direct array manipulation to using the string list helpers, with careful maintenance of the same behavior.

This is a well-contained refactoring that makes the code more maintainable while being part of a larger, carefully structured series addressing both immediate race conditions and long-term code quality in the maintenance subsystem.
