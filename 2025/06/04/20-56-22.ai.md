This is the third and final patch in a bugfix series addressing compiler warnings in Git's curl integration code. It completes the work started in the first two patches by handling symbolic constants passed to `curl_easy_setopt()`.

The patch adds explicit `(long)` casts to curl's own symbolic constants when they're passed to `curl_easy_setopt()`, matching the API's expectation for `long` parameters. Changes are focused in `http.c`, affecting several curl options:
- SSL options (`CURLSSLOPT_NO_REVOKE`)
- Redirect behavior (`CURL_REDIR_POST_ALL`)
- Proxy type settings (multiple `CURLPROXY_*` constants)

The author notes the inconsistency that curl defines these constants as `int` rather than `long` despite their exclusive use with `curl_easy_setopt()`, but pragmatically follows curl's documented usage patterns. The changes are mechanical and maintain existing behavior while silencing the new warnings from curl 8.14.

This completes the series' systematic approach: first handling literal constants, then variables, and now symbolic constants. The patch follows the same clean, focused style as the previous ones, with a clear commit message explaining the technical rationale.
