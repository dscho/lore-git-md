Bugfix patch addressing curl API type mismatches for integer constants.

This is the first of three patches fixing compiler warnings that appeared with curl 8.14's stricter type checking. The issue stems from passing plain `int` constants to `curl_easy_setopt()` where the API expects `long` values. While this worked in practice, it was technically incorrect and could potentially trigger undefined behavior.

The patch systematically adds `L` suffixes to integer constants passed to various curl options across three files (`http.c`, `http-push.c`, `remote-curl.c`). Affected options include common settings like `CURLOPT_HTTPGET`, `CURLOPT_SSL_VERIFYPEER`, and `CURLOPT_POSTFIELDSIZE`. The changes are straightforward and mechanical, with each instance simply getting the proper type suffix.

The commit message clearly explains the technical background, noting this was exposed by curl's improved type checking in version 8.14 (specifically commit 79b4e56b3) and that the warnings only appear with `-O2` optimization. The fix aligns Git's usage with curl's documented API requirements.

This appears to be a well-scoped and necessary fix, with clean separation from the other type-mismatch cases that will be addressed in subsequent patches (variables and symbolic constants). The changes are minimal and focused, touching only the type annotations while preserving all existing behavior.
