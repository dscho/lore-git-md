This thread addresses a resource leak in the commit-graph writing functionality when reading commits from stdin. The bug occurs in `graph_write()` where a progress meter would leak if `read_one_commit()` failed, as the error path lacked a `stop_progress()` call. Lidong Yan submitted a patch adding this cleanup, following established patterns for progress meter management.

Patrick Steinhardt reviewed the patch, confirming its correctness and noting that `stop_progress()` doesn't need an explicit NULL check since the underlying function handles that. While suggesting that similar fixes could be grouped together in future series, he acknowledged this particular fix stands complete as-is. The change is small but important for preventing resource accumulation during repeated failed commit-graph operations.
