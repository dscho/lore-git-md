This is the first patch in a two-part series adding GPG signing support to `git subtree`. It's a refactoring change that prepares the script for handling optional parameters more cleanly.

The patch switches `git-subtree.sh` to use `--stuck-long` mode when parsing arguments with `git rev-parse --parseopt`. This changes the argument handling to consistently use long-option-with-equals syntax (like `--message=msg` instead of mixing short/long forms and separate arguments. The mechanical changes involve:

1. Adding `--stuck-long` to the `rev-parse` invocation
2. Removing redundant `shift` operations that were previously needed for separate argument values
3. Converting option handling to use parameter extraction from ${opt#*=} syntax
4. Updating all option cases to match the new long-form style

The commit message frames this as general preparation for future optional parameters (following Junio's feedback in v1), though the immediate follow-up patch will use this for GPG signing support. The changes are purely mechanical - no behavior changes are introduced. The diff shows 21 lines removed and 13 added, with the bulk being removal of now-unnecessary `shift` operations and consolidation of option handling.

This appears to be a clean, focused refactoring that follows Git's conventions. The change is well-contained to the argument parsing logic and maintains all existing functionality while enabling cleaner handling of future optional parameters like the GPG signing flags coming in patch 2/2.
