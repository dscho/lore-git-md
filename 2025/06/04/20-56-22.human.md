This is the third and final patch in a bugfix series addressing compiler warnings in Git's curl integration code. It completes the work started in the first two patches by fixing type mismatches when passing curl's own symbolic constants to `curl_easy_setopt()`.

The patch adds explicit `(long)` casts to curl constants like `CURLSSLOPT_NO_REVOKE` and various `CURLPROXY_*` values in `http.c`. While the author notes it's odd that curl doesn't define these constants as longs given their purpose, they follow curl's documented practice of casting at the call site. The changes are straightforward and maintain existing behavior while silencing new warnings from curl 8.14.

This concludes a cleanly organized series that methodically addressed three categories of type mismatches (constants, variables, and now symbolic constants). The patches appear well-justified and uncontroversial, with each change clearly motivated by the curl API requirements.
