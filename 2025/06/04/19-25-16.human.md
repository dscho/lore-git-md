This is a platform compatibility discussion about build system issues in Git 2.50.0-rc1, specifically around TCL/Tk handling. Johannes Sixt responds to Junio Hamano's concerns about extensive git-gui build changes that went directly into the release candidate without normal review cycles.

The core issue is that the build system fails when TCL/Tk is not present (NO_TCLTK), as it still tries to process TCL files that don't exist. Johannes confirms Junio's analysis that the problem occurs when `$(wildcard lib/*tcl)` expands to nothing, which shouldn't happen in a proper checkout. He asks Randall Becker to investigate why this wildcard expansion fails on the NonStop platform specifically.

The exchange reveals that git-gui and gitk development has historically followed an informal process outside Git's main review workflow, with Johannes maintaining unofficial testing branches. This appears to be a case where the build system's handling of optional dependencies needs improvement, particularly for platforms where TCL/Tk isn't available. The discussion remains technical and collaborative, with both parties trying to diagnose the root cause.
