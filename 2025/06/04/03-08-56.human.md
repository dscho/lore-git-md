This is a straightforward bugfix addressing a memory leak in the revision walking code. Lidong Yan identifies that `prepare_show_merge()` in revision.c allocates memory for the `prune` array but fails to free it before returning. The patch adds the missing `free(prune)` call.

The change is small (just one line added) and clearly correct - the memory allocation happens earlier in the function via `parse_pathspec()`, and since that function's documentation doesn't indicate it handles freeing the input array, the caller needs to clean it up. This appears to be a genuine leak rather than a theoretical one, as the function is called during revision walking operations like `git log --merge`.

The patch follows standard formatting and includes a clear commit message explaining both the problem and solution. It's the kind of small but important fix that often gets picked up quickly during review cycles.
