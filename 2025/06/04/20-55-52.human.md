Bugfix patch addressing curl type mismatches for variables. This is the second in a three-part series fixing compiler warnings that appeared with curl 8.14, where Git was passing `int` values to `curl_easy_setopt()` where `long` is expected.

The patch focuses on variables rather than constants (which were handled in part 1). It adds explicit `(long)` casts to three calls in `imap-send.c` where variables are passed to curl options: the IMAP port number and SSL verification flags. The author explains that while these variables could be declared as `long` from the start, their current types make more logical sense in context (port numbers as `short`-like and SSL flags as boolean), so casting at the call sites is clearer.

The changes are straightforward and maintain existing behavior while silencing the new compiler warnings. The patch follows the same pattern as earlier fixes in the series, and the author's previous work on curl-related code suggests these changes are well-considered. The third patch in the series will handle symbolic constants.
