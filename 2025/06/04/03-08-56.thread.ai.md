Memory leak fix in revision walking code, originally reported by Lidong Yan, with follow-up test coverage discussion. The core fix addresses a straightforward memory leak in `prepare_show_merge()` in revision.c where an array `prune` was allocated but not freed after being passed to `parse_pathspec()`. 

Patrick Steinhardt raised concerns about test coverage gaps that allowed this leak to go undetected, prompting discussion of Git's testing procedures. Junio Hamano now proposes a comprehensive test case for `git show --merge` functionality that would have caught the leak. The test creates an artificial unmerged index state with conflicting blobs using `MERGE_HEAD`, generates blob objects with different permissions, sets up index entries manually via `update-index --index-info`, and verifies `show --merge` handles this conflicted state correctly. This exercises the previously untested code path where the leak occurred.
