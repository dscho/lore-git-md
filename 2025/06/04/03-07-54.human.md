This is a bugfix patch addressing a memory leak in `builtin/fetch-pack.c`. 

Lidong Yan identifies a case where `cmd_fetch_pack()` could return an error from `finish_connect()` without properly cleaning up allocated memory. The patch adds a `cleanup` label before the existing memory-freeing operations and ensures the function jumps to this label when `finish_connect()` fails, rather than returning immediately.

The change is straightforward - just 5 lines modified to add the cleanup path. The patch appears well-scoped and correctly targets a specific leak scenario. While small, such fixes are important for long-running processes that might hit this error path repeatedly. The commit message clearly explains both the problem was and how the solution works, though it might benefit from mentioning which specific allocations would have been leaked (the `sought_to_free` array and its entries).
