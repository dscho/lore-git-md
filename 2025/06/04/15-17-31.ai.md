Platform compatibility issue in Git 2.50.0-rc1 build system affecting NonStop systems. The problem stems from extensive changes to the git-gui build infrastructure between rc0 and rc1, particularly the introduction of new build scripts and meson support. The key issue is that the `generate-tclindex.sh` script fails when `$(wildcard lib/*.tcl)` expands to nothing, which shouldn't happen in a proper checkout. This suggests either a broken tarball extraction or an incomplete source tree on NonStop systems.

Junio Hamano notes the significant changes to git-gui's build system (115 lines modified in Makefile, plus new scripts and meson files) and expresses concern that such impactful changes should have gone through the normal review cycle before rc0. The error occurs when building without TCL/Tk (NO_TCLTK), where the build system still attempts to process TCL files that don't exist. The thread participants are investigating whether this is a regression in Git's build logic or an environmental issue specific to NonStop systems.

The changes include new build scripts (generate-tclindex.sh, generate-git-gui.sh), meson build files, and significant Makefile restructuring. The immediate problem manifests when ALL_LIBFILES expands to empty, causing generate-tclindex.sh to fail with a usage message since it requires at least one LIBFILE argument. This appears to be a build system regression that affects platforms where TCL is unavailable, with the fix likely involving proper handling of NO_TCLTK cases in the new build infrastructure.
