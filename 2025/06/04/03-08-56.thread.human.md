This thread addresses a memory leak in Git's revision walking code. The original report identified that `prepare_show_merge()` in revision.c allocates a `prune` array but fails to free it before returning. The function passes this array to `parse_pathspec()`, which doesn't take ownership of the memory, leaving the caller responsible for cleanup.

The fix is straightforward - a single line adding `free(prune)` at the end of the function. The patch is well-formed with a clear commit message explaining both the issue and solution. While this leak likely wasn't causing major problems (since `prepare_show_merge()` isn't in a hot code path), it's a clean and correct improvement to Git's memory hygiene. The change follows standard contribution practices with proper sign-off.
