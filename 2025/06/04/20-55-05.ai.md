This is a bugfix series addressing compiler warnings in the curl integration code. The patches fix type mismatches when calling `curl_easy_setopt()` that became more visible with curl 8.14's improved compiler warnings. The issue stems from passing `int` values where `long` is expected, which has always been technically incorrect but only now triggers warnings.

The series is cleanly split into three logical parts: fixing integer constants (1/3), integer variables (2/3), and symbolic constants (3/3). Each patch touches multiple files (`http.c`, `http-push.c`, `imap-send.c`, `remote-curl.c`) that use curl functionality. The changes are straightforward type casts to `long` to match curl's API expectations.

The cover letter provides useful context about the Debian unstable rollout of curl 8.14 exposing these warnings, and acknowledges this was always technically wrong but previously not caught. The patches appear well-scoped and mechanical - each focuses on one category of fixes with clear commit messages explaining the changes. This looks like a solid maintenance series addressing a real (if minor) compatibility issue.
