Bugfix patch addressing curl type mismatches for integer variables, part 2 of a 3-part series. This follows the first patch which handled integer constants, now focusing on variables passed to `curl_easy_setopt()` that need explicit `long` casting.

The patch modifies `imap-send.c` to cast three variables when passed to curl: `srvc->port` (for `CURLOPT_PORT`) and `srvc->ssl_verify` (for both `CURLOPT_SSL_VERIFYPEER` and `CURLOPT_SSL_VERIFYHOST`). The author explains these variables have logical types that differ from curl's API requirements - `port` is conceptually a short (though stored as int) and `ssl_verify` acts as a bool. Rather than changing their declarations to `long`, the patch opts for explicit casting at the call sites to maintain clarity about the type conversion.

This continues the series' consistent approach of fixing curl 8.14's new warnings about type mismatches while preserving existing behavior. The changes are minimal and focused, with clear justification in the commit message about why type declarations weren't changed. The patch appears technically sound and follows the same pattern as the first in the series, suggesting it will likely be uncontroversial.
