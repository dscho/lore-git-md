This is the first patch in a bugfix series addressing compiler warnings in Git's curl integration code. Jeff King fixes type mismatches when calling `curl_easy_setopt()` by ensuring integer constants are explicitly marked as `long` with an "L" suffix, matching curl's API expectations.

The issue became visible as warnings with curl 8.14's improved type checking, though the underlying type mismatches were always technically incorrect. The patch makes straightforward changes across `http.c`, `http-push.c`, and `remote-curl.c`, converting bare integer constants (like `0` and `1`) to their long equivalents (`0L`, `1L`).

This appears to be a well-scoped, mechanical change that follows curl's documented API requirements. The commit message clearly explains both the technical background and the specific curl change that exposed the issue. As the first of three patches in the warning-fix series, it handles the simplest case of integer constants before moving on to more complex cases in subsequent patches.
