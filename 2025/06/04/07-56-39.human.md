Memory leak fix with suggested refactoring. Patrick Steinhardt reviews Lidong Yan's patch that fixes memory leaks in `repo_logmsg_reencode()` callers in `shortlog.c` and `replay.c`. While agreeing with the fixes, Steinhardt suggests a cleaner approach for the `shortlog.c` change - converting the early returns to use a `goto out` pattern to centralize resource cleanup. The original patch correctly addresses the leaks but the proposed version would make the cleanup path more maintainable by having a single exit point. This appears to be a straightforward improvement to an already solid fix.
