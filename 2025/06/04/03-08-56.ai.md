Bugfix addressing a memory leak in the revision walking code.

This patch fixes a straightforward memory leak in `prepare_show_merge()` in revision.c, where an array `prune` is allocated but not freed. The function calls `parse_pathspec()` with this array, but since `parse_pathspec()` doesn't take ownership of the memory, the caller remains responsible for freeing it. The patch adds the missing `free(prune)` call at the end of the function.

The change is minimal (a single line addition) and clearly correct - the array is allocated earlier in the function and only used within this scope. The commit message clearly explains the issue and solution. This appears to be a genuine memory leak that should be fixed, though it's likely not a major one since `prepare_show_merge()` isn't called in performance-critical paths. The patch follows standard Git contribution practices with proper sign-off and references.
