This is a platform compatibility discussion about build system issues in Git 2.50.0-rc1, specifically around TCL/Tk handling. Johannes Sixt responds to Junio Hamano's analysis of the git-gui build failure on NonStop systems, where `$(wildcard lib/*tcl)` expands to an empty list despite TCL files existing in the source tree.

The email confirms Junio's diagnosis that the root issue appears when `ALL_LIBFILES` is empty during the `generate-tclindex.sh` execution, but notes this shouldn't happen in a proper checkout. Johannes suggests this might be a platform-specific path expansion problem on NonStop systems and directly asks Randall Becker to investigate why the wildcard expansion fails in that environment.

Key technical details: the failure occurs in `git-gui/Makefile` line 200 when processing TCL files, with the `generate-tclindex.sh` script receiving insufficient arguments. The discussion highlights an apparent disconnect between the build system's expectations and NonStop's filesystem behavior regarding wildcard expansion. This follows earlier concerns about significant git-gui build infrastructure changes (including new scripts and meson support) being introduced late in the rc cycle.
