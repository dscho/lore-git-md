This is a bugfix patch addressing a resource leak in the commit-graph writing code. The issue occurs when `read_one_commit()` fails during commit-graph generation - the progress meter allocated by `start_delayed_progress()` would leak since there was no corresponding `stop_progress()` call in the error path.

The patch is straightforward, adding a single line to clean up the progress meter before jumping to the cleanup section when `read_one_commit()` fails. The change affects `builtin/commit-graph.c` specifically in the `graph_write()` function where commit data is read from stdin.

While small, this fixes a real resource leak that could accumulate during repeated failed commit-graph operations. The fix follows the established pattern seen elsewhere in the codebase where progress meters are properly cleaned up in all code paths. The patch appears well-targeted and correctly implements the fix described in the commit message.

Key technical details for future reference: the leak occurs in the stdin-reading loop of `graph_write()`, specifically when processing commit IDs from stdin. The progress meter variable is named `progress` and is passed to `read_one_commit()`. The fix ensures it's properly stopped before the error-handling `goto`.
