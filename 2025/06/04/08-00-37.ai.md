This is a feature request/bug report regarding Git's progress output handling during checkout operations. The email describes an inconsistency between how `git clone` and `git checkout` handle progress output when redirecting to a variable while also displaying to the user.

Nathan Royce reports that while redirecting `git clone` output to a variable while simultaneously displaying progress works (using `2>&1 | tee /dev/stderr`), the same technique fails with `git checkout`. The use case stems from wanting to both show progress to users and capture output for programmatic error handling, particularly when working with blobless clones of large repositories like texlive where only specific paths are needed.

The email includes test commands demonstrating the behavior difference and mentions discussions from IRC channels #git and #bash where contributors like JAA and jast helped investigate. While `GIT_TRACE=1` was suggested as an alternative, it doesn't provide the specific path-level information needed for this use case. The core issue appears to be that checkout progress output isn't properly captured in the same way clone progress is, suggesting either a bug in output handling or a missing feature in the checkout command's progress reporting.
