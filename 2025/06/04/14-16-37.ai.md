This is the second patch in a two-part series adding GPG signing support to `git subtree`. The implementation matches core Git's signing behavior, addressing a functionality gap where subtree operations couldn't produce signed commits.

The patch adds `-S/--gpg-sign` options to all commit-creating subtree operations (add, merge, split, pull, push). It passes signing flags through to both `git commit-tree` (for split/add operations) and `git merge` (for merge/pull operations). The implementation supports optional key IDs and `--no-gpg-sign` override, maintaining consistency with Git's existing signing behavior.

Key technical details:
- Adds `arg_gpg_sign` variable to store signing options
- Modifies command invocations to pass signing flags to underlying Git commands
- Updates documentation to reflect new options
- Includes 113 lines of tests covering:
  - Basic signing with various flag combinations
  - Explicit key IDs
  - Interaction with `--squash`
  - Verification of signed commits
  - All major subtree operations

The changes span `contrib/subtree/git-subtree.sh`, its documentation, and test files. The implementation appears thorough, with comprehensive test coverage exercising both happy paths and edge cases. This builds on the preparatory refactoring in patch 1/2 that cleaned up option parsing.

The patch follows standard conventions and has already incorporated review feedback from v1, including documentation clarifications requested by Junio Hamano. The author has shown responsiveness to review and received workflow guidance from Kristoffer Haugsbakk regarding minor documentation updates.
