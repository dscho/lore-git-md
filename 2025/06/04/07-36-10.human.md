This is the fourth and final patch in a series addressing compiler warnings, specifically targeting an unreachable code warning from clang on Windows in the files backend. The warning occurs when `NO_SYMLINK_HEAD` is defined, making `create_ref_symlink()` expand to a constant `-1` that triggers clang's unreachable code detection for the following `continue` statement.

Patrick Steinhardt suggests a more targeted fix than Mike Hommey's original patch - rather than wrapping the call site in `NOT_CONSTANT`, he proposes modifying the macro definition itself to suppress the warning at its source. This approach would maintain the same behavior while being more maintainable, as it localizes the warning suppression to the macro rather than scattering `NOT_CONSTANT` wrappers throughout the code.

The patch continues the series' theme of carefully distinguishing between real bugs and compiler limitations, with this case being clearly the latter.
