Memory leak fix in fetch-pack when finish_connect() fails. The patch addresses a case where cmd_fetch_pack() would return an error from finish_connect() without freeing the sought_to_free array and its contents. The solution adds a cleanup label before the existing memory freeing operations and makes the error path jump there. The change is minimal (5 lines in builtin/fetch-pack.c) and focused on the leak without introducing new complexity. Patrick Steinhardt reviewed the patch, confirming all variables being freed in the cleanup path are properly initialized (either NULL or zero), which provides additional safety validation. His review endorses the approach and appears to be the final approval needed for this straightforward bugfix. The commit message clearly explains the issue and solution, though doesn't specify how the leak was discovered (likely code inspection).
