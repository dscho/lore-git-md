Thread summary:

This thread concerns progress output handling in Git's checkout operation compared to clone. Nathan Royce reports that while `git clone` output can be both captured in a variable and displayed to the user simultaneously (via `2>&1 | tee /dev/stderr`), `git checkout` fails to maintain this behavior. The use case involves blobless clones of large repositories (e.g. texlive) where users need both real-time progress display and captured output for programmatic error handling. Initial investigation with help from IRC contributors JAA and jast suggests the issue stems from checkout's progress reporting implementation differing from clone's. `GIT_TRACE=1` was considered but rejected as insufficient for the path-level detail required. The thread opens with this behavioral discrepancy report, seeking either bugfix or feature enhancement to align checkout's progress capture with clone's capabilities. No patches or maintainer responses are included in this initial report.
