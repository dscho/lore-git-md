This is a bugfix addressing a resource leak in the commit-graph writing functionality. The email is a review response to Lidong Yan's patch that fixes a progress meter leak when reading commits from stdin fails. Patrick Steinhardt confirms the correctness of the fix and notes that the `stop_progress()` call doesn't need a NULL check since `stop_progress_msg()` handles that internally.

The patch specifically targets the `graph_write()` function in `builtin/commit-graph.c`, where a progress meter allocated via `start_delayed_progress()` would leak if `read_one_commit()` failed. The fix adds the missing `stop_progress()` call before jumping to error handling. Patrick suggests that related memory leak fixes could be grouped together in future patch series for easier review, though this particular fix stands on its own as correct and complete.

Key technical details for future reference: the progress meter variable is named `progress`, the leak occurs during stdin processing in commit-graph writing, and the fix follows established patterns for progress meter cleanup seen elsewhere in the codebase. The change is small but important for preventing resource accumulation during repeated failed operations.
