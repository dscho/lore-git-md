Feature patch series adding GPG signing support to `git subtree`. This is version 2 of a two-patch series that enables commit signing for subtree operations, addressing a functionality gap where subtree commits were being created unsigned even when `commit.gpgSign` was configured.

The first patch (unchanged from v1) refactors argument parsing to use `--stuck-long` mode, which was a preparatory change needed for clean handling of optional parameters like GPG signing. The second patch implements the actual signing support, adding `-S/--gpg-sign` options that work consistently with other Git commands by passing signing flags through to both `git commit-tree` and `git merge` operations.

The changes since v1 are minor - the commit message for the first patch was adjusted to be more general about preparing for future optional parameters rather than specifically mentioning GPG signing. The implementation appears thorough, with comprehensive test coverage (113 new test lines) that verifies signing works across all major subtree operations and handles edge cases like explicit key IDs and interaction with `--squash`.

This addresses a real pain point for repositories that require signed commits, bringing `git subtree` behavior in line with core Git commands. The series has already incorporated feedback from reviewers in v1 and appears ready for consideration.
