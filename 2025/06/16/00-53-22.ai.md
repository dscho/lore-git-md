This is a follow-up discussion in the `the_repository` removal effort, specifically about the historical context of repository initialization behavior changes in `run_builtin()`. The email clarifies several key points about the evolution of `get_git_dir()` and `repo_get_git_dir()` behavior.

Junio Hamano corrects the attribution of behavior changes from 246deeac to 73f192c9, which was the commit that actually stopped lazy initialization of repository state. He explains that the original comment in a9ca8a85 was about checking `startup_info->have_repository` before calling `trace_repo_setup()` (which uses `get_git_dir()`), not about avoiding `get_git_dir()` calls altogether. The comment's meaning became obscured when e5b17bda moved code around in 2021.

The discussion reveals that while the patch's main goal was removing `the_repository` usage, there was some confusion about documenting historical behavior changes. Hamano suggests that any comment improvements should be done separately, as they're not the focus of this patch. The thread shows careful attention to Git's historical evolution and accurate documentation of behavior changes, though concludes these details don't affect the validity of the merged patch series.
