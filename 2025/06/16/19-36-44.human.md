Bug report about incorrect path display with `--work-tree` when worktree is an ancestor directory.

Serdar Sanli reports unexpected behavior when using `git --work-tree` with ancestor paths. When checking status from a repository at `/tmp/dir2/path/to/repo` with `--work-tree` set to `/tmp/dir1`, it correctly shows `foo.txt` as untracked. However, when using `--work-tree /tmp/dir2` (an ancestor directory of the repository), it shows the path as `../../../foo.txt` instead of the expected `foo.txt`.

The behavior appears inconsistent between these two scenarios, and the reporter notes this isn't documented in the worktree documentation. This looks like a legitimate bug in how Git handles path display when the worktree is an ancestor of the repository location. The report is clear and provides a minimal reproduction case, making it easy to verify.
