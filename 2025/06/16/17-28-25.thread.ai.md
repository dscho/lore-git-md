Git project development process and community reference. Originated by maintainer Junio C Hamano, this authoritative document establishes the canonical workflow for Git development. Core infrastructure includes the git@vger.kernel.org mailing list (moderated for spam) with IRC channels (#git-devel on Libera) and multiple public mirrors. The repository uses four integration branches: master (next release), maint (current release), next (testing candidate topics), and seen (all in-flight work). Versioning follows X.Y.Z scheme with feature releases (2.50.0) and maintenance updates (2.50.1). Security issues should be reported privately to git-security@googlegroups.com. Patch submission requires mailing list review with clear commit messages and proper formatting (git format-patch). Subsystems with separate maintainers include git-gui (Johannes Sixt), gitk (Johannes Sixt), and l10n translations (Jean-Noel Avila for French, Jiang Xin for Chinese). References provided to supplemental resources: Git Rev News newsletter, Code of Conduct, git-scm.com documentation, and Git for Windows fork. The document serves as both onboarding guide and workflow reference, emphasizing mailing list participation as the primary collaboration mechanism while acknowledging alternative channels for non-core components.
