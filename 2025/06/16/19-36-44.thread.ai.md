Thread identity: Bug report about path handling with `--work-tree` when worktree is an ancestor directory of the repository.

Core problem: When using `--work-tree` with a directory that contains the repository (rather than being a sibling or unrelated path), Git shows relative paths with excessive `../` components instead of simple filenames. For repository at `/tmp/dir2/path/to/repo` and `--work-tree=/tmp/dir2`, `git status` incorrectly shows `../../../foo.txt` rather than `foo.txt`.

Current status: Initial bug report with reproduction case. No patches or solutions proposed yet.

Key technical details: Issue affects Git's path normalization logic when calculating relative paths between worktree and repository locations. Behavior is correct when worktree is unrelated path (`--work-tree=/tmp/dir1` shows `foo.txt`), but incorrect when worktree is ancestor directory.

Open questions: Whether this is intended behavior (undocumented) or a bug. No maintainer response yet.
