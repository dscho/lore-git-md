Bugfix and feature enhancement for `git cat-file`'s submodule handling in batch mode.

This third patch in the series improves `git cat-file --batch[-check]`'s handling of submodule references, distinguishing between truly missing objects and valid submodule entries. The key change replaces the generic "missing" error message with a specific "<oid> submodule" response when a path refers to a submodule whose commit isn't present locally. The patch maintains the existing behavior of showing full object content when the submodule commit is available.

The implementation checks the `S_IFGITLINK` mode flag to identify submodules, then reports their OIDs directly rather than using the input specification. Documentation updates clearly explain the new output format. Test cases verify both the new submodule reporting and the existing behavior for present submodule objects, including handling of the compatibility object format configuration.

This change provides better tooling integration by allowing callers to distinguish submodules from missing paths without spawning additional processes. The patch builds on the series' earlier work with objectmode handling and completes the batch mode improvements with comprehensive submodule support. Test coverage appears thorough, including edge cases around hash compatibility.
