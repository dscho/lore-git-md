Bugfix and refactoring patch addressing lock contention in Git's maintenance "gc" task. This is the final patch in Patrick Steinhardt's 12-part series restructuring Git's task execution to eliminate race conditions.

The patch fixes a locking race in the garbage collection task similar to those previously addressed for "pack-refs" and "reflog-expire". The solution splits the "gc" task into foreground and background phases, with lock-sensitive operations (like `gc_before_repack()`) moved to the foreground. The renamed `gc_foreground_tasks()` handles these operations before detaching, while a new hidden `--skip-foreground-tasks` flag allows the background process to skip them.

Key changes include:
- Splitting the GC task into separate foreground/background functions
- Adding the new flag to control foreground task execution
- Updating test expectations to account for the new flag
- Renaming functions for clarity (`gc_before_repack` -> `gc_foreground_tasks`)

This completes the series' work on lock contention issues while maintaining the established pattern of separating foreground and background operations. The changes are well-contained, with test updates verifying the new behavior matches expectations. The patch builds logically on the previous work in the series and appears ready for consideration.
