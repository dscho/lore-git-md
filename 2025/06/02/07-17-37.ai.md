This is a refactoring patch in Patrick Steinhardt's v3 series on maintenance task execution, specifically addressing global state elimination in `gc_before_repack()`. The patch removes a static `done` flag that was preventing duplicate execution of the function, replacing it with explicit control via the `opts.detach` parameter. 

The changes convert `gc_before_repack()` to return an error code rather than calling `die()` directly, allowing the caller to handle failures consistently using the new `die(NULL)` pattern introduced earlier in the series. The function now returns 0` on success or `-1` when pack-refs or reflog-expire tasks fail, with the caller responsible for fatal termination.

Key technical modifications:
- Removal of static `done` variable from `gc_before_repack()`
- Conversion of `die(FAILED_RUN,...)` calls to `error(FAILED_RUN,...)` returns
- Changed function signature to return `int` instead of `void`
- Added explicit `opts.detach` check in `cmd_gc()` to prevent duplicate execution
- Updated call sites to use new error handling pattern with `die(NULL)`

The patch maintains the same behavioral guarantees while making the control flow more explicit and eliminating global state, consistent with the series' broader goals. It builds on previous work standardizing error handling and continues the systematic removal of implicit state from the maintenance task infrastructure. The changes are localized to `builtin/gc.c` and don't require test updates since they preserve existing functionality while improving implementation hygiene.
