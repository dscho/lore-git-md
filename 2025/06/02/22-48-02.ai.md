Platform compatibility patch addressing Cygwin test failures in t6137-pathspec-wildcards-literal.sh, following up on initial investigation.

Ramsay Jones reports that 11 tests in t6137 fail on Cygwin due to its treatment of backslashes in quoted glob patterns (like `\*`) as path separators, where the tests expect them to escape glob characters literally. He demonstrates the root cause with a temporary hack that disables backslash path separator handling in `is_absolute_path()` and `normalize_path_copy_len()`, though this was just for diagnosis.

The actual patch marks all affected tests with the `!CYGWIN` prerequisite rather than modifying core path handling. It also fixes some test titles for accuracy. The changes focus on pathspec scenarios where wildcards should be treated literally via escaping, including tests for `\*`, `\?`, `\[abc\]` patterns in both add and commit operations.

Notably, Jones expresses surprise that this wasn't caught earlier in Windows CI, suggesting the issue may have been silently failing there. The solution follows Git's typical approach for platform-specific test accommodations rather than trying to normalize behavior across platforms. The patch appears straightforward and well-targeted to the known issue.
