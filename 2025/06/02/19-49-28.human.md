This is a follow-up discussion about a portability fix for OpenBSD's sed implementation affecting config-list.h generation.

Jean-Noël Avila confirms that Collin Funk's v2 patch passes tests when integrated into GitGitGadget's CI system, though notes the resulting code isn't very readable. He points out two issues with the commit message: the incorrect capitalization of "Make" in the subject line, and that the underlying bug predates the recent regression (dating back to 3ac68a9 when generate-configlist.sh was first introduced).

Avila suggests an alternative approach - reformatting the documentation source files to put each config variable on its own line rather than modifying the sed script. This would avoid the sed portability issues entirely while also making the source documentation more readable. The discussion remains focused on finding the cleanest solution that works across all platforms while maintaining correct output formatting.

The thread shows progress toward resolution, with the v2 patch working technically but still some open questions about the ideal long-term solution. The maintainers will need to weigh in on whether to accept the current portable-but-less-readable sed solution or pursue documentation reformatting instead.
