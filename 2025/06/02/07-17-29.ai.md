Refactoring patch in Patrick Steinhardt's v3 series on maintenance task execution. This is patch 3/12 in the effort to resolve race conditions in Git's maintenance framework while improving code quality.

The patch centralizes configuration logic for explicitly requested maintenance tasks (via `--task=` flags) by:
1. Moving task selection state from global modification in `task_option_parse()` to a collected `string_list` of selected tasks
2. Deferring the actual task ordering to `initialize_task_config()`
3. Using the option callback's `value` field to pass the selection list through parse_options

Key technical details:
- Replaces direct modification of `tasks[i].selected_order` with string list collection
- Adds `selected_tasks` parameter to `initialize_task_config()`
- Maintains same external behavior while making execution flow clearer
- Part of broader effort to reduce global state modifications
- Follow-up will address remaining global state issues (mentioned in commit message)

The changes improve maintainability by:
- Making task selection logic more linear and localized
- Reducing cross-function dependencies
- Preparing for further state reduction
- Keeping all configuration steps in one place (`initialize_task_config`)

This is a preparatory refactoring that enables subsequent patches to clean up global state while maintaining the same functionality. The patch fits into the series' pattern of incremental quality improvements alongside the core race condition fixes.
