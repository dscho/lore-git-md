Bugfix patch in the `imap-send` series, addressing a critical regression introduced in Git 2.46.0 that made the command unusable. The issue stems from commit 6d1f198f34 which incorrectly cleared the `cfg->folder` field when processing unrelated configuration variables (`imap.user`, `imap.pass`, `imap.tunnel`, and `imap.authmethod`). The patch corrects this by properly clearing the corresponding field for each config variable rather than incorrectly clearing the folder field in all cases.

The regression had gone unnoticed likely because most users prefer `git send-email` over `imap-send`. The fix is straightforward - replacing the incorrect `FREE_AND_NULL(cfg->folder)` calls with the proper field-specific cleanup for each configuration variable. This is the first patch in a 10-part series that significantly improves `imap-send` functionality, with this particular fix being critical as it restores basic usability that was broken for nearly a year since Git 2.46.0.

The patch modifies only `imap-send.c`, changing 4 lines to fix the field-specific cleanup. This is part of a larger effort that includes OAuth2.0 support and folder management improvements, but this specific patch focuses solely on fixing the configuration parsing regression. The change is minimal and targeted, with no new functionality or behavioral changes beyond fixing the broken cleanup logic.
