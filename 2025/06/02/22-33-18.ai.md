This is a platform compatibility patch addressing test failures on Cygwin. The issue stems from Cygwin treating backslashes in quoted glob patterns (like `\*`) as path separators, causing 11 tests in t6137-pathspec-wildcards-literal.sh to fail. Ramsay Jones reports this was observed during v2.25.0-rc0 testing.

The patch demonstrates the root cause with a quick hack that disables backslash path separator handling in `is_absolute_path()` and `normalize_path_copy_len()`, though this isn't proposed as the actual solution. Instead, the proper fix marks all affected tests with the `!CYGWIN` prerequisite to skip them on Cygwin, along with some test title corrections. The changes focus on tests dealing with literal glob characters (like `\*`, `\?`, `\[abc\]`) in pathspecs.

Key technical details: The issue affects path normalization functions in abspath.h and path.c, where backslash handling differs between platforms. The test modifications touch various pathspec scenarios involving wildcards being treated literally via escaping. The patch suggests this behavior has likely been failing Windows CI for some time, though the exact duration isn't specified.
