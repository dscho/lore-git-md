This is part of Patrick Steinhardt's ongoing series to remove `the_repository` global from the object database (ODB) subsystem, enabling pluggable ODB backends. Patch 7/17 focuses on converting `odb_mkstemp()` to take an explicit `object_database` parameter instead of relying on `the_repository`.

The patch mechanically updates all callers of `odb_mkstemp()` to pass `the_repository->objects` (or the appropriate repository's objects field) as the first parameter. The function implementation is updated to use the passed ODB's `repo` field rather than `the_repository` when calling helper functions like `repo_git_path_replace()` and `safe_create_leading_directories()`.

Key technical details:
- The function signature changes from `int odb_mkstemp(struct strbuf*, const char*)` to `int odb_mkstemp(struct object_database*, struct strbuf*, const char*)`
- Call sites updated in `builtin/fast-import.c`, `builtin/index-pack.c`, `bundle-uri.c`, `pack-bitmap-write.c`, `pack-write.c`
- The ODB header documentation is updated to clarify the function operates on the primary alternate's directory
- No functional changes - this is purely an API refactoring

This continues the established pattern seen in previous patches: adding an ODB parameter, updating the implementation to use it, and converting all callers. The changes are straightforward and maintain consistency with the series' goal of removing `the_repository` dependencies from the ODB subsystem.
