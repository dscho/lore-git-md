Platform compatibility fix for OpenBSD's sed implementation. This patch addresses a build failure on OpenBSD systems where the `sed` command doesn't support `\n` escape sequence for newlines in expressions. The error manifests when generating `config-list.h` from documentation files, causing compilation to fail with an undeclared identifier error.

The solution introduces a shell variable `$nl` containing an actual newline character, then uses this variable in the sed pattern instead of the non-portable `\n` escape. The change is minimal - just 4 lines added and 1 modified in `generate-configlist.sh`. The regression was introduced in commit e1b81f54da from March 2025, which added formatting backtick handling for completion options.

This appears to be a straightforward and correct fix for the specific portability issue. The patch maintains the same output format while working around OpenBSD's sed limitations. The commit message clearly explains both the problem and solution, though it might benefit from mentioning whether other BSD variants are similarly affected by this sed behavior.
