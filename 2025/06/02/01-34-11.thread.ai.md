Thread identity: Platform compatibility patch fixing physical memory detection on OpenBSD/NetBSD systems, affecting `builtin/gc.c` memory calculations for garbage collection heuristics.

Core problem: On OpenBSD and NetBSD systems with >=4GB RAM, `HW_PHYSMEM` sysctl incorrectly reports physical memory (capping at 4GB or showing partial amounts), causing inaccurate GC auto-packing threshold calculations. The fix replaces it with `HW_PHYSMEM64` which correctly reports full system memory.

Current status: Patch has reached consensus with Junio C Hamano acknowledging Collin Funk's verification. Ready for integration with no outstanding issues. Collin confirmed correct behavior on both NetBSD 10.0 and OpenBSD 7.6 through testing.

Key technical details: Changes sysctl constant from `HW_PHYSMEM` to `HW_PHYSMEM64` in `builtin/gc.c` for BSD platforms, maintaining same structure but fixing memory reporting. Affects GC heuristics that scale based on available RAM. No behavioral changes beyond accurate memory detection.
