Windows/Meson test hang investigation for receive-pack connectivity check bypass.

This is a follow-up in the finalized series adding `--skip-connectivity-check` to `git receive-pack`, where Justin Tobler responds to Johannes Schindelin's report of test hangs in Windows+Meson CI environments. The issue appears specific to the test infrastructure's use of `tee` pipes in the Windows+Meson combination on GitHub's CI, while working fine in other Windows test environments.

The problematic test verifies that `receive-pack` correctly bypasses connectivity checks when the new flag is used, by capturing `send-pack` output with `tee` and replaying it. Johannes notes the test passes quickly in Git for Windows' VS-based tests but hangs indefinitely in GitHub's Meson-based Windows CI. The test methodology was previously approved after consolidation in patch 1 of this series.

Justin acknowledges the report but does not yet have a root cause, indicating he will investigate further. The core functionality (the connectivity check bypass) is not in question - this appears to be a platform-specific test infrastructure issue. The response suggests the test's pipe handling may interact poorly with Meson's process management on Windows, though this remains speculative until further debugging.

Key technical details for future reference:
- Test file: `t/t5410-receive-pack.sh`
- Failing test: 'receive-pack missing objects bypasses connectivity check'
- Specific command chain: `send-pack` piped through `tee` to `receive-pack`
- Environment specificity: Windows + Meson build on GitHub CI only
- Related infrastructure: GitLab CI (not affected), Git for Windows VS tests (not affected)

This leaves open whether the test methodology needs adjustment for Windows+Meson or if there's a deeper issue in Git's process handling on that platform. The series remains otherwise approved, with this being a CI-specific test execution problem rather than a functional defect.
