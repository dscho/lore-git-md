This is a refactoring patch in Patrick Steinhardt's v3 series addressing maintenance task race conditions. The patch centralizes the configuration logic for explicitly requested maintenance tasks (via `--task` flags) that was previously spread across multiple functions.

The key change moves task selection state management from `task_option_parse()` (which previously modified global state) to `initialize_task_config()`. Now the option callback just collects requested tasks into a string list, while the actual configuration happens in one place later. This makes the flow clearer and reduces global state modification - though the author notes full removal of global state will come in a later patch.

The changes are mechanical but improve maintainability by:
1. Making task configuration more linear and centralized
2. Preparing for complete removal of global state modifications
3. Keeping the same behavior (tasks still execute in order specified by `--task` flags)

This is part of the series' broader effort to fix reference locking races during maintenance by restructuring task execution. The patch appears well-contained with no behavior changes, just internal reorganization to support the larger architectural improvements.
