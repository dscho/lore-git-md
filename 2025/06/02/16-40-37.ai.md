This is a feature patch series adding GPG signing support to `git subtree`. The cover letter explains that `git subtree` currently doesn't honor commit signing configurations, which causes problems for repositories requiring signed commits. The implementation makes `-S/--gpg-sign` work consistently with other Git commands by passing the flag through to `git commit-tree` and `git merge`.

The series consists of two patches: first a preparatory change to use `--stuck-long` for argument parsing (likely to handle the new option cleanly), followed by the main feature adding GPG signing support. The changes touch documentation, the shell script implementation, and add substantial test coverage (113 lines of new tests).

The author notes this iteration incorporates feedback from Junio Hamano on a previous attempt. The motivation is clear - enabling GPG signatures in subtree operations for repositories with signing requirements - and the implementation appears thorough with documentation updates and comprehensive tests. This seems like a well-considered addition that fills a gap in `git subtree`'s functionality while maintaining consistency with Git's existing signing behavior.
