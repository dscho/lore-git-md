This is a refactoring patch in Patrick Steinhardt's series addressing maintenance task race conditions. It splits maintenance tasks into foreground and background phases to prevent locking issues, particularly with the packed-refs file.

The patch introduces a clear division between tasks that should run before detaching (foreground) and those that can run after (background). This is motivated by historical problems where long-running background tasks could lock critical files, blocking other Git operations. The change prepares for future fixes by restructuring the task execution flow while maintaining current behavior.

Key changes include:
- Adding separate function pointers for foreground/background task execution in the `maintenance_task` struct
- Introducing a `task_phase` enum to track execution phase
- Modifying `maybe_run_task()` to handle both phases with appropriate Trace2 regions
- Running foreground tasks before attempting to daemonize

The patch is part of a larger effort to make maintenance tasks more robust while improving code structure. It follows the series' pattern of careful, incremental changes that maintain backward compatibility while setting up for more significant fixes. The implementation looks thorough, with clear documentation of the phase separation rationale.
