This is a test infrastructure patch in Patrick Steinhardt's Meson test integration series (v4 08/10). It changes how the test suite handles unexpectedly passing tests marked with `test_expect_failure`.

The patch makes the test suite fail when a test marked as expected-to-fail (`test_expect_failure`) actually passes, which differs from the current behavior where such cases only produce a warning. This change aligns Git's test runner with Meson's TAP parser behavior (which treats unexpected passes as failures) and makes it easier to notice when previously broken functionality starts working, especially across different platforms.

Key technical changes include:
- `t/test-lib.sh` to exit with status 1 when `test_fixed` is non-zero (indicating unexpected passes)
- `t/t0000-basic.sh` test cases to use `write_and_run_sub_test_lib_test_err` instead of `write_and_run_sub_test_lib_test` for TODO test verification
- The exit code handling logic to prioritize unexpected pass detection over `--invert-exit-code` functionality

The change affects test output formatting in prove(1), producing "Dubious" status reports when unexpected passes occur, but maintains clear messaging about the root cause. This is part of the broader effort to ensure consistent test behavior between prove(1) and Meson's TAP parser while improving visibility of test status changes.
