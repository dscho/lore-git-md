This is a platform compatibility patch addressing header handling for OpenBSD and NetBSD systems. The change simplifies the `_XOPEN_SOURCE` definition logic in `compat/posix.h` by treating OpenBSD and NetBSD similarly to FreeBSD and DragonFlyBSD - systems where this macro doesn't need to be set explicitly.

The patch removes the special case that previously set `_XOPEN_SOURCE` to 600 for OpenBSD (needed for `S_ISLNK()` support) and instead groups these BSD variants together in the exclusion list. It also cleans up some redundant macro definitions, removing `_NETBSD_SOURCE` which appears unnecessary.

The commit message notes this fixes a compilation warning about `getdelim()` being undeclared on OpenBSD, suggesting the current header configuration may be causing issues with function visibility. The change appears straightforward and focused, though it might be worth checking if any OpenBSD-specific functionality (like symlink handling) still works correctly without the explicit `_XOPEN_SOURCE` setting.
