This is part of Patrick Steinhardt's ongoing series to remove `the_repository` global from the object database (ODB) subsystem, specifically converting functions that manage temporary primary object stores. The patch continues the mechanical conversion pattern established in previous patches: adding explicit ODB parameters and renaming functions with the `odb_` prefix.

The key changes in this patch convert `set_temporary_primary_odb()` to `odb_set_temporary_primary_source()` and `restore_primary_odb()` to `odb_restore_primary_source()`, both now taking an explicit `object_database` parameter. The functions handle swapping the primary object store with a temporary one (used in operations like `tmp_objdir`) and restoring the original state. The implementation ensures the temporary store's alternates are properly initialized and maintains the linked list of ODB sources.

The patch updates callers in `tmp-objdir.c` to use the new API, including migration and cleanup paths. The changes are straightforward - each caller now passes the repository's ODB explicitly through `t->repo->objects`. The BUG() checks remain but now operate on the passed ODB rather than `the_repository`.

This continues the series' systematic elimination of `the_repository` from ODB operations while maintaining identical functionality. The changes follow the established pattern seen in previous patches (6-9/17) and complete the conversion of primary ODB management functions. No functional changes or new edge cases are introduced - the patch simply makes the repository dependency explicit in the API.
