This is a refactoring series that carves out the object database subsystem from Git's object store to make it more self-contained and remove dependencies on `the_repository`. The series is part of the ongoing effort to remove global state from Git.

The key changes include:

1. Renaming structures and files to better reflect their purpose (`struct raw_object_store` → `struct object_database`, `object-store.c` → `odb.c` etc.)
2. Introducing parent pointers between object databases and their owning repositories
3. Removing `the_repository` dependencies by passing object databases explicitly
4. Renaming functions to use an `odb_` prefix consistently
5. Reorganizing the code to follow patterns similar to the refs subsystem

The series has gone through several iterations (v4 now) with discussions around naming choices (settling on `odb_source` for the alternate object store concept). It has received positive reviews from Junio Hamano and Derrick Stolee on foundational patches.

The changes are mechanical refactorings with no functional changes, preparing the codebase for future work on pluggable object backends by establishing clear boundaries and removing the last `the_repository` dependencies in the ODB subsystem.

The naming discussion around `odb_alternate` vs `object_source`/`odb_source` exemplifies Git's careful approach to API design decisions that will shape long-term maintenance. The technical implementation remains ready with positive reviews while the naming discussion continues.
