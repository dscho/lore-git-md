This is a documentation and behavior adjustment patch in the ongoing signature handling discussion for `fast-export`/`fast-import`. Christian Couder is responding to Junio Hamano's patch that marks the signature handling feature as experimental and reverts the default behavior to stripping signatures rather than aborting.

The key changes in Junio's patch are:
1. Adding explicit warnings that the signature handling is experimental and may change incompatibly in future versions
2. Changing the default `--signed-commits` behavior from 'abort' back to 'strip' to match pre-feature behavior
3. Removing the `FAST_EXPORT_SIGNED_COMMITS_NOABORT` environment variable escape hatch

Christian agrees with the approach but suggests two minor clarifications in the documentation and tests to indicate that the default behavior itself might still change in the future. The patch appears to be a measured response to the earlier discussion, balancing feature development with stability concerns while leaving the door open for future improvements. The changes are well-contained, touching documentation, code, and tests consistently.
