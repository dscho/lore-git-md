This is a review comment on the `imap-send` authentication series, specifically addressing the PLAIN authentication implementation in patch 3/9. Junio Hamano points out two consistency issues in the error messaging and authentication flow:

1. The error message for the PLAIN authentication stub function (when built without OpenSSL) should mirror the CRAM-MD5 version's phrasing, saying "If you want to use PLAIN..." rather than the current "You are trying to use PLAIN...". This maintains consistency with how other authentication methods report missing OpenSSL support.

2. The authentication flow still doesn't verify local support for the method before attempting authentication, despite earlier discussion about this design inconsistency. The patch checks server capabilities (via CAP(AUTH_PLAIN)) but doesn't confirm the local build has the required OpenSSL support first, which could lead to less graceful failures. This matches a pattern Junio previously noted where the code checks server capabilities but not local implementation support.

The review focuses on maintaining consistency in both user-facing messages and internal error handling patterns across the authentication methods. While the technical implementation of PLAIN auth itself is sound (with proper base64 handling, socket writing, and memory management), these polish issues remain before finalizing the series. The comments suggest straightforward textual fixes for the error message and a more structural consideration about authentication flow consistency.
