Bugfix patch in the `imap-send` series addressing a memory leak in CRAM-MD5 authentication. This is part of a larger v12 series that adds OAuth2.0 support and fixes various IMAP-related issues.

The patch specifically fixes a case where the `response` allocated in `auth_cram_md5()` would leak if `socket_write()` failed. The fix is straightforward - adding a `free(response)` call in the error path before returning. This matches the existing cleanup that happens on the success path.

This appears to be a clean, focused fix for a real issue, though it's worth noting the context that this is one of several authentication-related fixes in the series (which also includes OAuth2.0 support and other auth method improvements). The change is minimal and clearly correct, addressing a specific leak while maintaining the existing behavior otherwise.
