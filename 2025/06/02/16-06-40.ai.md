This is a follow-up in the finalized `--skip-connectivity-check` patch series, specifically addressing a Windows+Meson CI test hang issue. The email focuses on troubleshooting why the new test case in `t5410-receive-pack.sh` hangs specifically in GitHub's Windows+Meson CI environment while working fine in other Windows test setups.

The problematic test verifies that `receive-pack` correctly bypasses connectivity checks when given the new `--skip-connectivity-check` flag. The test uses a `tee` pipe to capture `send-pack` output before piping to `receive-pack`, which appears to trigger the hang only in this specific CI configuration. Johannes Schindelin reports the test passes quickly in Git for Windows' VS tests but consistently hangs in GitHub's Windows+Meson jobs, suggesting an environment-specific interaction with process management or pipe handling.

Justin Tobler acknowledges the issue and commits to investigating, though no root cause is identified yet. The core functionality of the patch remains unaffected - this is purely a test infrastructure issue. The thread context shows this was the last remaining blocker for the series, which had otherwise received approval for its implementation of a hidden flag to support GitLab's Gitaly service while maintaining proper documentation about corruption risks when bypassing connectivity checks.
