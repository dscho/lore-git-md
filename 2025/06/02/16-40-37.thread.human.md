This thread introduces a two-patch series that adds GPG signing support to `git subtree`, bringing it in line with core Git commands that already support commit signing. The first patch was a preparatory refactoring of the option parsing code to use `--stuck-long` mode, making it easier to handle optional parameters like signing flags. This change was reviewed by D. Ben Knoble and Patrik Weiskircher, with Kristoffer Haugsbakk providing workflow guidance.

The second patch, which just arrived, implements the actual signing functionality. It adds `-S/--gpg-sign` options to all commit-creating operations (add, merge, split, pull, push), passing the signing flags through to the underlying Git commands. The implementation is thorough, supporting optional key IDs and `--no-gpg-sign` overrides, and includes extensive tests covering various scenarios. Junio Hamano had previously requested documentation clarifications, which have been addressed in this version.

The series appears ready for merging, with all review feedback incorporated and comprehensive test coverage. The changes maintain backward compatibility while filling a notable functionality gap in the subtree command. The author has been responsive to feedback throughout the review process.
