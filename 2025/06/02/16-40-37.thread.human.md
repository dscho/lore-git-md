This thread introduces a two-patch series adding GPG signing support to `git subtree`, addressing a current limitation where commit signing configurations were ignored. The first patch refactored the argument parsing to use `--stuck-long` mode, cleaning up the option handling in preparation for the new signing feature. The second patch, now submitted, implements the actual signing support by adding `-S/--gpg-sign` options to all commit-creating operations (add, merge, split, pull, push), matching core Git's behavior.

The implementation passes signing flags through to both `git commit-tree` and `git merge` as appropriate, with comprehensive test coverage (113 new test lines) verifying various signing scenarios including explicit key IDs, `--squash` interactions, and commit verification. The changes maintain consistency with Git's existing signing conventions while filling a clear functionality gap in the subtree command. The series appears well-structured and thorough, though it hasn't yet received review feedback. The author is currently the sole participant in the thread.
