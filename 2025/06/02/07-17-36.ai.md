This is a refactoring patch in Patrick Steinhardt's v3 series on maintenance task execution, though it stands somewhat apart from the main thread's focus on race conditions and task phases. The patch introduces a new way to handle fatal errors in Git's error reporting system.

The change allows calling `die(NULL)` to exit with status 128 without printing an additional error message, addressing cases where the error has already been reported but the program needs to exit with Git's standard error code. This replaces several instances of direct `exit(128)` calls that were previously scattered through the codebase. The patch demonstrates the new pattern by converting existing `exit(128)` calls in several builtins (`am`, `checkout`, `fetch`, and `submodule--helper`) to use `die(NULL)` instead.

The implementation modifies `die_message_builtin()` in `usage.c` to skip message printing when passed a NULL error string, while maintaining all other die() behavior. This provides a cleaner, more consistent way to handle fatal errors where the message has already been shown, eliminating magic numbers and centralizing error handling.

While not directly related to the maintenance task refactoring that dominates the rest of the series, this change aligns with the overall quality improvement goals by standardizing error handling patterns. The patch is narrowly focused and appears mechanically sound, touching only the specific error cases it aims to convert without introducing new behavior beyond the NULL handling.
