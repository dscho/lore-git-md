This is a test infrastructure patch in Patrick Steinhardt's Meson test integration series (v4 03/10). It converts an ad-hoc filesystem capability check in t9822 (git-p4 path encoding tests) into a proper test prerequisite to maintain TAP output compliance.

The test previously used a direct filesystem check for ISO-8859-1 filename support, which could emit error output to stderr when failing - violating TAP format requirements. The patch replaces this with `test_lazy_prereq` and `test_have_prereq` calls that properly handle output redirection. The actual test logic remains unchanged - it still verifies filesystem support by attempting to create and remove a file with ISO-8859-1 encoded characters (a-ä_o-ö_u-ü.txt).

This change aligns with the series' broader goal of TAP compliance and test modernization. It follows the pattern seen in other patches of the series (like the prerequisite announcement cleanup in t0050/t3600/t4000/t9500/t9903) by formalizing ad-hoc test setup into proper prerequisite declarations. The implementation is straightforward and maintains the test's original functionality while fixing the TAP output issue.

Key technical details for future reference:
- Introduces `FS_ACCEPTS_ISO_8859_1` prerequisite
- Affects t9822-git-p4-path-encoding.sh
- Uses `test_lazy_prereq` pattern matching other conversions in the series
- Preserves original test behavior while fixing TAP output compliance
