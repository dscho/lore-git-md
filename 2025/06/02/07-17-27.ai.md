Refactoring patch in Patrick Steinhardt's maintenance task race condition series (v3 1/12). This initial patch converts the maintenance task array in `builtin/gc.c` to use designated field initializers rather than positional initialization. The change affects all maintenance tasks (prefetch, loose-objects, gc, commit-graph, etc.), explicitly naming each struct field (`name`, `fn`, `auto_condition`, `enabled`) rather than relying on order.

This is a pure code quality improvement that makes the code more maintainable by:
- Making field assignments explicit rather than positional
- Allowing future struct field additions without modifying every task entry
- Maintaining identical runtime behavior (verified by unchanged test suite)

The patch touches only `builtin/gc.c`, modifying the static `tasks[]` array initialization. It serves as groundwork for later patches in the series that will build on this structure to implement the foreground/background task execution model for race-free maintenance operations. The change aligns with the series' broader goals of improving code quality while fixing reference locking races during garbage collection.
