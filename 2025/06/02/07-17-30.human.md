This is a refactoring patch in Patrick Steinhardt's ongoing series to improve Git's maintenance task execution. The patch focuses on making command-line option validation more consistent and explicit.

The change marks `--task=` and `--schedule=` as mutually incompatible options in `git maintenance run`, since they represent fundamentally different ways to select tasks (explicit selection vs. repository-configured strategy). The patch also modernizes the existing check between `--auto` and `--schedule=` to use the same `die_for_incompatible_opt2()` helper function, making the code more uniform.

The implementation is straightforward - it adds the new validation check and updates the corresponding test to verify both cases now produce the same style of error message. This appears to be a clean, focused improvement that maintains backward compatibility while making the code more maintainable. The change fits well with the series' broader goals of improving code quality and reducing potential error cases in the maintenance command.
