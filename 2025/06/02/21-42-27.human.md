This is a discussion about portability fixes for config-list.h generation, with a proposed alternative approach to restructuring documentation.

Jacob Keller weighs in on Collin Funk's demonstration of an alternative solution to the OpenBSD sed portability issue. Rather than modifying the sed script (as in the v2 patch), Collin has shown how restructuring the config.adoc documentation to put each config variable on its own line could eliminate the need for complex line continuation handling. This matches the style used in pretty-options.adoc.

Jacob explicitly endorses this documentation restructuring approach, calling it simpler than the current sed-based solution. The thread is now waiting for broader feedback, particularly from maintainers, on which direction to pursue for v3. The documentation approach would require changes to gitcvs.adoc and http.adoc but would produce cleaner output without the "$nl" markers seen in the sed solution.

This email moves the discussion forward by providing a clear endorsement of one solution path, though the final decision still awaits maintainer input. The patch author (Collin) remains neutral but has demonstrated both approaches are viable.
