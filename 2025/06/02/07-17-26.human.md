This is a v3 patch series (12 patches) addressing race conditions in Git's maintenance tasks, particularly around reference locking during garbage collection. The series completes Patrick Steinhardt's refactoring of the task execution framework to safely handle concurrent operations.

The main focus is fixing races that occur when maintenance tasks like `pack-refs`, `reflog-expire`, and `gc` run simultaneously. The solution splits tasks into foreground (locking operations) and background (long-running work) phases, ensuring proper sequencing. Key changes in v3 include:

1. Renaming the task phases from "before/after detach" to "foreground/background" for clarity
2. Adding a hidden `--skip-foreground-tasks` flag to `git gc` to prevent duplicate work
3. Completing the GC task integration into the phase-split model

The series maintains backward compatibility while systematically eliminating race conditions. It follows a careful, incremental approach that has already been reviewed in previous iterations (v1 and v2). The changes are minimal (final patch adds just 15 net lines) and maintain existing behavior while fixing the races.

For maintainers, this represents the completion of the architectural work started in earlier patches. The series is well-tested and appears ready for inclusion, with all originally targeted races now resolved. The changes are robust and maintain compatibility, making this a low-risk but high-value improvement to Git's maintenance infrastructure.
