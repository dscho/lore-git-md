This is the final version of a bugfix patch addressing an issue with `git refs verify` in older-format worktrees. The patch modifies the files backend to gracefully handle missing refs directories in linked worktrees created with Git v2.43.0 or older, while maintaining strict error checking for other cases.

The key technical change is in `files_fsck_refs_dir()` where it now specifically ignores ENOENT errors for linked worktrees. The test case in t0602-reffiles-fsck.sh has been refined through multiple iterations, now using proper test isolation with subshells and correct path resolution via `git rev-parse --git-dir` rather than hardcoded paths. The test safely removes the refs directory with `rmdir` to ensure it's testing the empty-directory case specifically.

The patch represents the culmination of discussion and testing from multiple contributors, with all feedback incorporated. Kristoffer Haugsbakk identified the original issue, Shejialuo developed the fix, and Eric Sunshine provided key test improvements. The solution maintains compatibility between v2.48.0+ ref backend changes and pre-v2.43.0 worktree formats while being careful about error handling safety.

All open questions from earlier versions have been resolved, with consensus reached on the implementation approach. The patch is now in its final form, ready for submission, with all test isolation requirements validated and safety considerations addressed. The commit message has been updated to properly reference both the commit that introduced the behavior change (7c78d819e6a) and the original worktree refs commit (8f4c00de95).
