This is a test reliability report for the recently approved `--skip-connectivity-check` feature in `git receive-pack`. Johannes Schindelin reports that the new test case occasionally hangs in Windows CI environments when using Meson builds, specifically in GitHub Actions jobs (though not in GitLab or VS test jobs).

The test verifies that `receive-pack` can skip connectivity checks when the new `--skip-connectivity-check` flag is used, while still ensuring the repository remains in a consistent state. The intermittent hang appears to be platform-specific to Windows/Meson/GitHub combinations, suggesting a possible interaction between the test's pipe handling (`tee` usage) and the Meson build environment on Windows.

The report provides detailed links to CI runs showing the behavior, noting that the same test completes quickly in other Windows test configurations. This appears to be a test infrastructure issue rather than a problem with the core functionality, which has already been approved after thorough review. The author is seeking input from the patch author (Justin Tobler) about potential causes.
