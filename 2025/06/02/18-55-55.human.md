This is the third patch in a series improving `git cat-file`'s batch mode, specifically focusing on submodule handling. The change makes it easier to distinguish between truly missing objects and submodule entries by having `cat-file` output "<oid> submodule" when encountering a submodule whose commit isn't present locally, rather than the generic "missing" message.

The patch completes the series by addressing a specific pain point in submodule inspection. Previously, batch mode couldn't distinguish between a missing path and a submodule reference, forcing callers to spawn additional Git processes (like `ls-tree`) to check. Now the command provides this information directly, with clear documentation of the new output format.

Implementation-wise, the change is relatively small but well-tested, adding a special case for the S_IFGITLINK mode in the batch object writer. The tests verify both the new submodule case and ensure existing behavior remains correct when the submodule commit does exist locally. The patch appears to be in good shape, building on the earlier infrastructure changes in the series.
