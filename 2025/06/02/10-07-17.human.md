Bugfix discussion regarding pathspec handling in empty repositories with `git add --update`. Phillip Wood responds to Piotr Siupa's regression report about duplicate error messages when using exclude patterns in empty repos (introduced in Git 2.45.0).

Phillip agrees the behavior is inconsistent but suggests the real issue might be that Git *should* error when exclude patterns match nothing - the current behavior with tracked files might be the bug. He provides examples showing how `git add -u` handles non-existent paths (errors) versus exclude patterns that match nothing (silently succeeds), arguing the empty repo case might actually be exposing a more general inconsistency in pathspec validation.

The discussion shifts from treating this as a regression to considering whether the empty-repo behavior is correct and the non-empty behavior needs fixing. Phillip's response indicates this may require deeper pathspec semantics discussion rather than a simple revert of the 2.45.0 change.
