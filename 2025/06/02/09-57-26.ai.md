This is the third patch in a bugfix series addressing edge cases in batched reference updates, specifically focusing on `git receive-pack` behavior. The patch handles a filesystem directory/file (F/D) conflict case that arises when batched updates process both deletions and creations simultaneously.

The core issue occurs when pushing operations that delete a reference (like `refs/heads/branch/conflict`) while creating another that would conflict with it (like `refs/heads/branch`). In sequential processing, these would succeed, but batched updates fail due to the F/D conflict. The fix mirrors a previous solution for `git fetch` by separating deletions into their own batch transaction before processing other updates.

Key technical changes include modifying `execute_commands_non_atomic()` to accept an `only_deletions` flag and splitting the batched processing in `execute_commands()` into two phases - first handling deletions, then other updates. The patch adds test coverage in `t/t5516-fetch-push.sh` that verifies this behavior works correctly with the new batching approach.

This completes the series addressing production issues GitLab encountered with batched reference updates. The changes maintain backward compatibility while fixing the F/D conflict case, and include appropriate test coverage. The implementation follows the same pattern as the earlier `git fetch` fix, suggesting a consistent approach to this class of problem.
