This is a refactoring patch in Patrick Steinhardt's series to improve Git's maintenance task execution. It extracts the task-running logic into a separate `maybe_run_task()` function, which will be reused in later patches that split maintenance tasks between foreground and background phases.

The change is straightforward - it moves the core task execution logic (including auto-condition checking, Trace2 regions, and error handling) out of the main loop and into a dedicated function. This makes the code more modular and prepares for the upcoming phase-split work where the same execution logic will need to be called from multiple places.

The patch maintains all existing behavior while making the code more maintainable. It's part of a larger effort to resolve race conditions in maintenance operations and improve the code quality of this subsystem. Since this is a pure refactoring with no behavior change, it doesn't require test updates.
