Feature implementation adding GPG signing support to `git subtree`. This is the second and final patch in the series, building on the preparatory argument parsing changes from patch 1/2.

The patch introduces `-S/--gpg-sign` options to all `git subtree` commands that create commits (add, merge, split, pull, push), matching the behavior of core Git commands. The implementation passes the signing flag through to both `git commit-tree` (used in split/add operations) and `git merge` (used in merge/pull). The documentation is updated to reflect the new options, which support optional key IDs and `--no-gpg-sign` to override earlier settings.

Key technical details:
- The `arg_gpg_sign` variable stores the signing option from command line parsing
- Signing is implemented for all commit-creating operations by passing the option to the underlying Git commands
- 113 lines of new tests verify signing behavior with various combinations of flags and configurations, including:
  - Basic signing with `-S` and `--gpg-sign`
  - Explicit key IDs
  - Interaction with `--squash`
  - Verification of signed commits
  - All major subtree operations (add, merge, split, pull)

The implementation appears thorough, with comprehensive test coverage that exercises both the happy path and edge cases. The changes maintain consistency with Git's existing signing behavior while filling a functionality gap in `git subtree`. The patch feedback from the first part of the series suggests this approach aligns with Git's conventions.
