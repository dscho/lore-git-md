Bugfix patch in the `imap-send` series addressing a memory leak in CRAM-MD5 authentication. This is part of a larger v12 series that adds OAuth2.0 support and fixes various IMAP-related issues.

The patch specifically fixes a case where the `response` buffer allocated in `auth_cram_md5()` would leak if `socket_write()` failed. The fix adds proper cleanup by freeing the buffer before returning the error. This completes the memory management for CRAM-MD5 authentication paths that was started in earlier series iterations.

The change is minimal and focused - just adding the missing `free()` call in the error path while maintaining the existing successful path cleanup. This follows the pattern seen elsewhere in the series where error paths were being audited for proper resource cleanup. The patch appears straightforward and uncontroversial, addressing a clear memory leak without introducing new complexity.

This is one of several authentication-related fixes in the series, which has already seen extensive review over 12 iterations. The change aligns with the series' broader goal of making `imap-send` more robust, particularly around authentication handling and resource management.
