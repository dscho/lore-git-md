This is a technical discussion about patch 1/3 in the batched reference updates bugfix series, focusing on the files backend segfault issue. Karthik Nayak responds to Patrick Steinhardt's review questions about why existing tests didn't catch the segfault and why the reftable backend doesn't need similar changes. The key points are:

1. The edge case requires a very specific scenario - a deletion request with an expected old OID where the reference doesn't exist - which wasn't covered in existing tests. Karthik's patch adds this test case.

2. The reftable backend handles failed updates differently through its `queue_transaction_update()` mechanism, which acts as a single gatekeeper checking rejections before queuing updates, making it immune to this particular issue.

3. Patrick notes a test suite style point about not silencing `test_grep` output, which Karthik acknowledges will be fixed.

The discussion reveals an implementation difference between the files and reftable backends in how they handle failed updates during batched transactions. While the files backend needs explicit checks in multiple places, the reftable backend's architecture naturally prevents this issue through its centralized update queuing mechanism. This exchange helps validate the technical approach taken in the patch while identifying a minor test style improvement.
