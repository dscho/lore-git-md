Thread identity: Platform compatibility discussion about Cygwin test failures in t6137-pathspec-wildcard-literal.sh, originating from Ramsay Jones's report during v2.50.0-rc0 testing (corrected from initial v2.25.0-rc0 reference by Kristoffer Haugsbakk).

Core problem: Cygwin's path normalization interprets backslashes in quoted glob patterns (e.g. `\*`) as path separators rather than literal escapes, causing 11 test failures. This conflicts with Git's expected behavior where backslashes should escape glob characters literally in pathspec operations (add/commit). The issue stems from `is_absolute_path()` and `normalize_path_copy_len()` behavior in abspath.h/path.c, exacerbated by recent ec727e18 ("dir.c: literal match with wildcard in pathspec should still glob").

Current status: Maintainer Junio C Hamano proposes reverting ec727e18 during the v2.50.0 release freeze period. Ramsay Jones's follow-up reveals the issue wasn't caught by Windows CI due to `FUNNYNAMES` test skipping on MINGW/Gfw but not Cygwin, with historical precedent (Patrick Steinhardt's 5f8af25ff9) for long-term Cygwin test skips. Discussion now considers whether permanent test skipping on Cygwin is preferable to reverting the change.
