This is the second patch in a two-part series adding GPG signing support to `git subtree`. The first patch refactored the argument parsing to prepare for this change, and now this patch implements the actual signing functionality.

The patch adds `-S/--gpg-sign` options to all `git subtree` commands that create commits (add, merge, split, pull, push), matching the behavior of other Git commands. The implementation passes the signing flag through to the underlying `git commit-tree` and `git merge` calls. The documentation is updated to reflect the new option, and the patch includes extensive test coverage (113 new test lines) verifying signing works in various scenarios including with specific key IDs, squash merges, and the `--rejoin` option.

The change addresses a real gap in functionality - repositories requiring signed commits currently cannot use `git subtree` properly. The implementation looks clean and consistent with Git's existing signing behavior, building on the preparatory work in the first patch. The thorough test coverage gives confidence in the implementation. This appears to be a well-crafted addition that fills a legitimate need while maintaining compatibility with existing workflows.
