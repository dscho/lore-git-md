Platform compatibility issue report regarding the recently approved `--skip-connectivity-check` feature in `git receive-pack`. Johannes Schindelin identifies an intermittent test hang specific to the Windows+Meson test environment on GitHub Actions, while noting the same test passes reliably in other Windows test configurations (Git for Windows' VS-based tests and GitLab CI).

The problematic test verifies the connectivity check bypass by:
1. Capturing `git send-pack` output via `tee`
2. Replaying it to a new repo with `--skip-connectivity-check`
3. Validating the object exists but connectivity is broken

Key observations:
- Failure occurs only in GitHub's Windows+Meson matrix jobs
- Test completes successfully in Git for Windows' VS-based environment
- Hangs manifest as 4+ hour timeouts
- Test isolation appears intact (no cross-test contamination)

The report suggests investigating potential interactions between:
- Windows process management
- Meson's test execution environment
- GitHub Actions' Windows container setup
- The `tee` pipe methodology used in the test

No functional issues with the core feature are indicated - this appears to be a CI-specific test harness problem. The report seeks input from Justin Tobler (patch author) on potential Windows/Meson-specific factors.
