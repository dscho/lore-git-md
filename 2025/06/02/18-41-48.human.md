This is a platform compatibility patch fixing a build issue on OpenBSD. The problem occurs because OpenBSD's `sed` doesn't support `\n` for newlines in expressions, causing a compilation failure when generating `config-list.h` for the completion system.

The patch replaces the problematic `\n` with a shell variable `$nl` that contains an actual newline character, making the sed command portable across different BSD and GNU sed implementations. The issue was introduced in commit e1b81f54da from March 2025, which added formatting backticks for completion options.

The fix is straightforward and well-contained, touching only the `generate-configlist.sh` script. It includes a clear explanation of both the problem and solution, along with the error message that motivated the change. This appears to be a solid, focused fix for a real portability issue.
