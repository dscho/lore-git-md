This is part 8/17 of Patrick Steinhardt's series to remove `the_repository` global from Git's object database (ODB) subsystem, continuing the mechanical conversion of ODB-related functions to use explicit `object_database` parameters.

The patch focuses on alternate object store handling, converting functions like `prepare_alt_odb()`, `has_alt_odb()`, `add_to_alternates_file()`, and `add_to_alternates_memory()` to take an explicit `object_database` parameter and renaming them with the `odb_` prefix (e.g. `odb_prepare_alternates()`). The changes follow the established pattern from previous patches in the series: adding the ODB parameter, renaming with prefix, and updating all callers.

Key technical details:
- The alternate-related functions now operate on a specific `object_database` instance rather than implicitly using `the_repository->objects`
- Call sites updated across 14 files including `builtin/` commands (`clone`, `fsck`, `repack`), core object handling code, and test helpers
- The patch notes this is an intermediate state where paths still come from the repository, but prepares for future where paths will be stored in the ODB itself
- Maintains all existing functionality while removing the last `the_repository` dependencies from alternate handling

This continues the systematic conversion of the ODB subsystem to support Patrick's planned pluggable backend work, with the changes being mechanical and well-contained following the established pattern from earlier patches in the series.
