This is part of Patrick Steinhardt's ongoing series to remove `the_repository` global state from Git's object database (ODB) subsystem, enabling pluggable ODB backends. Patch 11/17 specifically addresses submodule object access during operations like `git grep --recursive`.

The patch moves submodule ODB tracking from a global string list to being repository-specific by storing submodule paths in the `object_database` struct. Key changes include:
- Adds `submodule_source_paths` string list to `struct object_database`
- Renames functions with new `odb_` prefix convention (`add_submodule_odb_by_path` -> `odb_add_submodule_source_by_path`)
- Removes global `added_submodule_odb_paths` list and related functions from submodule.c
- Updates callers in `builtin/grep.c` and `submodule-config.c` to use new API
- Maintains same behavior while eliminating `the_repository` dependency

The change is mechanical but important for libification - it removes one of the last global state dependencies in submodule ODB handling while preserving the existing functionality where submodule objects are accessed via alternates when needed. The patch follows the established pattern of the series by adding explicit ODB parameters and using the new naming conventions.
