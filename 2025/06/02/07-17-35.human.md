This is a bugfix patch in Patrick Steinhardt's ongoing series to resolve race conditions in Git's maintenance tasks. It addresses a specific locking race that can occur when packing refs and reflogs during maintenance.

The patch moves the "pack-refs" and "reflog-expire" maintenance tasks from running in the background to running in the foreground. This prevents a race condition where these operations could conflict with lockfiles if they ran while detached. The change matches git-gc's existing behavior of packing refs before detaching.

The commit notes that a similar fix is needed for the "gc" task but will come in a later patch. This appears to be a straightforward, focused change that builds on the foreground/background task framework introduced earlier in the series. The implementation is minimal - just two line changes to switch the function pointers from background to foreground handlers.

This is part of a larger effort (v3, patch 9/12) to systematically eliminate race conditions while improving maintenance task architecture. The change demonstrates the series' approach of using the new foreground/background split to solve concrete problems while maintaining clean code structure.
