This is a refactoring patch in Patrick Steinhardt's v3 series (6/12) that continues the maintenance task execution improvements. The patch extracts the task execution logic into a new `maybe_run_task()` helper function, which will be reused in upcoming patches that split task execution between foreground and background phases.

The new function encapsulates:
- Auto-condition checking (via `auto_condition` callback)
- Trace2 region instrumentation
- Task execution (via `fn` callback)
- Error handling and reporting

Key technical details:
- The function takes `task`, `repo`, `opts`, and `cfg` parameters
- Returns 0 on success, 1 on failure
- Maintains existing Trace2 instrumentation boundaries
- Preserves all existing behavior including auto-condition checks
- The extracted logic is used unchanged in the main task loop

This is a straightforward code organization change that:
- Reduces duplication in preparation for the phase split
- Makes the task execution flow more modular
- Keeps all task-running logic in one place
- Maintains identical behavior (verified by unchanged tests)

The change fits into the series' broader goals of:
- Improving code structure for the foreground/background split
- Reducing global state usage
- Making maintenance execution more maintainable

No new tests are needed since this is purely a refactoring with no behavior change. The patch follows the series' pattern of careful, incremental improvements to the maintenance infrastructure.
