Bugfix for `git refs verify` with older worktree formats. This is the final version of a patch that fixes an issue where `git refs verify` would incorrectly fail (with exit code 255) when checking worktrees created with Git v2.43.0 or older that lack worktree-specific refs.

The problem stems from a behavior change in Git v2.48.0 that made `git refs verify` check worktree refs, which fails when encountering older-format worktrees missing expected `refs` directories. The fix modifies `files_fsck_refs_dir()` to ignore ENOENT errors specifically for linked worktrees while maintaining error reporting for other cases.

The patch has gone through several iterations with input from multiple contributors. Key improvements in this version include using subshells for better test isolation, avoiding hardcoded paths in tests, and safer directory removal with `rmdir` instead of `rm -rf`. The test case in `t/t0602-reffiles-fsck.sh` now properly simulates the old directory layout and verifies the fix works as expected.

All feedback from the mailing list discussion has been incorporated, and the patch appears ready for inclusion. The change maintains compatibility between newer Git versions and older worktree formats while preserving the safety checks introduced in v2.48.0.
