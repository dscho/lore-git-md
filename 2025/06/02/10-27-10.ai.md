This is part of Patrick Steinhardt's ongoing series to remove `the_repository` global from the object database (ODB) subsystem, enabling pluggable ODB backends. Patch 9/17 focuses on converting iterator-style functions that operate on alternate object stores.

The patch renames and refactors three key functions to take explicit `object_database` parameters instead of relying on `the_repository`:
- `foreach_alt_odb()` becomes `odb_for_each_alternate()`
- `for_each_alternate_ref()` becomes `odb_for_each_alternate_ref()`
- Updates their callback typedefs to new `odb_for_each_alternate_fn` and `odb_for_each_alternate_ref_fn`

The changes follow the established pattern seen in previous patches: adding the ODB parameter, renaming with `odb_` prefix, and updating all callers. The patch touches 8 files including core ODB handling in `odb.c`/`odb.h` and updates call sites in commands like `count-objects`, `receive-pack`, and `fetch-pack`.

Key technical details:
- Maintains same callback semantics but with explicit ODB context
- Preserves all existing functionality for alternate ref iteration
- Updates internal helper functions like `read_alternate_refs()` to use new types
- Follows the series' convention of passing repository context via `object_database->repo` rather than `the_repository`

This continues the mechanical but systematic conversion of ODB-related functions to the global-free API, building on prior infrastructure changes. The changes are straightforward with no functional impact, keeping with the series' goal of enabling future pluggable backends while maintaining current behavior.
