Bugfix for batched reference updates in the files backend. This is the first patch in a series addressing production issues found in GitLab's use of the recently added batched ref updates feature.

The patch fixes a segfault that could occur when processing failed updates in `files_transaction_finish()`. The function wasn't properly skipping updates that had already failed (marked with `rejection_err`), which could lead to null pointer dereferences. The fix adds the missing skip checks in two loops that handle deletions and directory cleanup.

A new test case verifies the fix by attempting to delete a non-existent ref in batch mode, which would have triggered the segfault before. The test confirms the operation fails gracefully with the expected error message rather than crashing.

This appears to be a straightforward and well-justified fix for a real production issue. The patch is cleanly focused on the test provides clear regression protection. As the first in a series addressing batched ref update problems, it sets up for the subsequent patches that handle directory/file conflict resolution.
