This is a technical clarification in the ongoing discussion about signature handling in Git's fast-export/fast-import functionality. brian m. carlson responds to Christian Couder's earlier proposal about representing signature algorithms, making an important distinction about what hash algorithm information actually matters for Git's purposes.

The key point is that carlson emphasizes the need to track the hash algorithm used in the Git object itself, rather than the algorithm used within the signature protocol (OpenPGP, X.509, etc.). This is because a single commit can contain multiple signatures with different hash algorithms (like both SHA-1 and SHA-256 signatures), and the Git object's hash is what's critical for repository integrity.

This email represents a refinement of the technical requirements for signature handling feature, though it doesn't propose any code changes. The discussion appears to be converging toward a more precise understanding of what information needs to be preserved during export/import operations, which will be important for any future implementation work on this experimental feature.
