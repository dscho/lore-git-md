This is a refactoring patch in Patrick Steinhardt's v3 series on maintenance task execution. It addresses command-line interface consistency by making `--task=` and `--schedule=` mutually exclusive options in `git maintenance run`, similar to how `--auto` and `--schedule=` already were.

The change replaces an ad-hoc error check with the standard `die_for_incompatible_opt2()` helper for both the existing `--auto`/`--schedule` conflict and the new `--task`/`--schedule` conflict. The rationale is that `--task` explicitly selects tasks while `--schedule` relies on repository configuration, making their combination nonsensical.

The patch modifies `builtin/gc.c` to implement the new check and updates `t/t7900-maintenance.sh` with a test verifying the behavior. The test output changes from "at most one" to "cannot be used together" to match the helper's standard phrasing. This continues the series' pattern of improving code quality through consistent error handling while maintaining backward compatibility.

The change is straightforward and well-contained, affecting only option validation logic. It fits naturally with the series' broader goals of cleaning up maintenance task execution while fixing subtle issues. The test coverage is appropriate for the change, verifying both the new conflict case and maintaining existing validation behavior.
