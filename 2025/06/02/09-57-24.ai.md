This is a bugfix patch addressing a segfault in the files backend's batched reference updates, part of a series fixing production issues encountered with GitLab's Gitaly service.

The patch fixes a critical issue where the files backend (`refs/files-backend.c`) wasn't properly skipping failed updates during batched reference transactions. The original batched updates implementation (23fc8e4f61) correctly marked failed updates with `rejection_err`, but two loops in `files_transaction_finish()` neglected to check this flag before processing deletions. This could lead to segfaults when attempting to process updates that had already failed.

The fix adds the missing `rejection_err` checks in both loops that handle deletion operations. The patch also includes a new test case in `t/t1400-update-ref.sh` that verifies the fix by attempting to delete a non-existent reference in batch mode, ensuring the operation fails gracefully rather than crashing. The test follows the pattern of existing batched update tests while specifically targeting the segfault scenario.

This is the first of three patches addressing production issues with batched reference updates. The changes maintain the performance benefits of batching while fixing a clear correctness issue in error handling. The fix is narrowly targeted and comes with direct test coverage, suggesting it's a well-scoped solution to a real problem encountered in production use.
