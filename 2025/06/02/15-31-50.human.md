Junio Hamano responds to Phillip Wood's proposal about pathspec error handling in `git add --update`. This is part of an ongoing discussion about whether Git should error when exclude patterns match nothing, particularly in empty repositories where the behavior regressed in Git 2.45.0.

Junio disagrees with Phillip's suggestion that Git should error when exclude patterns match all files, arguing that negative patterns (like `:!pattern`) are fundamentally different from positive ones. He compares it to `.gitignore` patterns, where we wouldn't want warnings about unused patterns. The core of his argument is that exclude patterns are meant to filter, not select, so their non-matches shouldn't be treated as problematic.

This response shifts the discussion from a potential behavior change back toward maintaining the status quo, though the empty-repo case remains unresolved. Junio's perspective as Git's maintainer carries significant weight in this technical debate about pathspec semantics. The thread now has two clear positions: Phillip advocating for more strict/explicit behavior versus Junio favoring the current (more permissive) approach to exclude patterns.
