Platform compatibility fix addressing both OpenBSD sed limitations and dash shell variable expansion issues in config-list.h generation.

This v2 patch from Collin Funk builds on previous discussion to resolve build failures on OpenBSD systems where sed doesn't support \n escape sequences, while also addressing dash shell compatibility problems identified in testing. The malformed output was causing config options to appear incorrectly concatenated with "$nl" literals in the generated header file.

The solution replaces the problematic newline escape sequence with a backslash followed by a literal newline in the sed expression. This maintains the same output format while working across different sed implementations. The change remains focused on generate-configlist.sh, which processes documentation to create completion options, with the regression originally introduced in commit e1b81f54da.

Key technical details include the specific sed pattern modification that now uses a backslash-newline sequence instead of \n, and the continued need to handle both OpenBSD sed limitations and dash shell variable expansion rules. The patch demonstrates awareness of the multi-platform constraints while keeping the change minimal and targeted.

The commit message could better highlight the dash shell compatibility aspect that emerged in thread discussion, though the technical solution appears sound. Testing across different shell/sed combinations (particularly OpenBSD, dash, and bash) remains an important consideration, with gitgitgadget's multi-platform CI potentially helping validate the fix.
