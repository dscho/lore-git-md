This is a polish patch in the ongoing `imap-send` series, specifically addressing minor logging inconsistencies. The patch standardizes error message formatting by:

1. Converting error messages to start with lowercase (e.g., "Error: unable" -> "error: unable")
2. Removing periods from error messages while keeping them in informational messages
3. Ensuring protocol terms like "IMAP" and status indicators like "OK" are consistently uppercase
4. Making progress messages more consistent (e.g., "sending" -> "Sending")

The changes touch various parts of `imap-send.c` including connection handling, authentication flows, and message sending routines. While purely cosmetic, these changes bring consistency to the user-facing output and align with Git's style guidelines for error messages. The patch is straightforward and unlikely to be controversial, representing final polish on the extensive `imap-send` improvements in this series.

Key technical details for future reference:
- Changes affect socket connection messages (`ssl_socket_connect`, `imap_open_store`)
- Updates authentication error reporting (`auth_cram_md5`, login handling)
- Modifies progress output during message sending (`append_msgs_to_imap`, `curl_append_msgs_to_imap`)
- Standardizes initial error checks in `cmd_main` (missing folder/host/messages)
