This is a platform compatibility patch that fixes physical memory detection on OpenBSD and NetBSD systems. The patch changes `builtin/gc.c` to use `HW_PHYSMEM64` instead of `HW_PHYSMEM` when querying system memory on these BSD variants, since the latter incorrectly reports values for systems with >=4GB RAM.

The email provides verification from another contributor (Collin Funk) who confirms the fix works and includes test program output demonstrating the issue. On both NetBSD 10.0 and OpenBSD 7.6, `HW_PHYSMEM` shows incorrect values (either capping at 4GB or reporting partial amounts) while `HW_PHYSMEM64` correctly reports the full physical memory. The patch is straightforward - a 4-line change that replaces one sysctl constant with another while maintaining the same basic structure.

This affects Git's garbage collection heuristics which use system RAM size to determine auto-packing thresholds. The fix ensures these calculations work properly on modern BSD systems with large memory configurations. The verification from another BSD user and clear demonstration of the problem make this a well-justified change likely to be accepted.
