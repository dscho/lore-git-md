This thread addresses a platform-specific issue where OpenBSD and NetBSD systems with 4GB or more RAM incorrectly report available memory through the `HW_PHYSMEM` sysctl, causing Git's garbage collection heuristics to calculate suboptimal packing thresholds. Brad Smith proposed replacing this with `HW_PHYSMEM64` in `builtin/gc.c`, which correctly reports full system memory on these BSD variants.

Collin Funk verified the fix works as intended by testing on both NetBSD 10.0 and OpenBSD 7.6, confirming the patch resolves the memory reporting issue. Junio Hamano has now acknowledged the successful review and testing, indicating the patch will likely be integrated. The change is straightforward - a simple constant replacement with clear evidence of correctness - and no further discussion is needed. Junio also took the opportunity to thank Collin for reviewing an unrelated `online_cpus()` patch in the same message.
