This is part of Patrick Steinhardt's ongoing series to remove `the_repository` global state from Git's object database (ODB) subsystem, specifically focusing on submodule object access. The patch moves submodule ODB tracking from a global string list to being repository-specific by storing the paths in the `object_database` struct.

The change affects how `git grep --recursive` and submodule config loading access submodule objects. Previously, these operations relied on global state to track which submodule ODBs to use as alternates. Now the paths are stored per-repository, allowing proper isolation while maintaining the same behavior since submodule access was already effectively repository-scoped in practice.

Key changes include:
- Adding a `submodule_source_paths` string list to `struct object_database`
- Renaming functions to use the new `odb_` prefix convention (`add_submodule_odb_by_path` -> `odb_add_submodule_source_by_path`)
- Moving implementation from `submodule.c` to `odb.c` where it logically belongs
- Updating callers in `builtin/grep.c` and `submodule-config.c`

The patch follows the established pattern of the series by being a mechanical conversion that maintains existing behavior while removing global state. It's a straightforward piece of the larger ODB refactoring effort that has received positive review feedback on earlier versions, and helps enable future pluggable ODB backends.
