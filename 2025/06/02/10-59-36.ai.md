Bugfix patch in the `imap-send` series, specifically addressing CRAM-MD5 authentication when OpenSSL is unavailable. This is part of the larger v12 series that adds OAuth2.0 support and fixes various IMAP authentication issues.

The patch improves error handling for CRAM-MD5 authentication by checking for OpenSSL availability upfront rather than failing during the authentication attempt. Previously, attempting CRAM-MD5 without OpenSSL would trigger a `die()` call. The patch moves the CRAM-MD5 implementation earlier in the file and adds a compile-time check (`NO_OPENSSL`) that provides a clear error message and graceful exit when OpenSSL is unavailable.

Key technical changes include:
- Moves `auth_cram_md5()` function definition before its first use
- Adds `#ifdef NO_OPENSSL` check before attempting CRAM-MD5 authentication
- Replaces `die()` with a more graceful `fprintf(stderr)` message
- Maintains the same memory management (freeing response buffers) in error paths
- Keeps the function signature consistent with other auth methods (taking `ctx` and `prompt` parameters)

This change completes the CRAM-MD5 memory management work from earlier in the series while making the OpenSSL dependency explicit. The error message matches the style of other authentication failure messages in the codebase. The patch fits into the series' broader goal of making authentication methods more robust and properly handling their dependencies.
