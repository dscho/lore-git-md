Refactoring patch in Patrick Steinhardt's maintenance task execution series (5/12). This change eliminates global state manipulation in Git's maintenance task configuration system.

The patch addresses a maintenance task selection system that was spread across multiple fields (`enabled`, `selected_order`, `schedule`) with logic distributed through several functions. The new approach centralizes task selection in `initialize_task_config()`, storing the results in the options structure rather than modifying global state. This makes the flow more linear and self-contained.

Key changes include:
- Moving from global task array modification to local computation in options
- Consolidating task selection logic that previously used three separate fields
- Introducing a `maintenance_strategy` struct to better organize configuration
- Maintaining the same behavior while making the code more maintainable

This is part of a larger effort to fix race conditions in maintenance tasks while improving code quality. The change doesn't introduce new functionality but makes the existing behavior more robust and easier to reason about. The patch follows the series' pattern of careful refactoring with clear commit messages explaining both the problem and solution.
