This is a feature patch series enhancing `git cat-file`'s batch mode capabilities, with additional test improvements. It's a revised version of a previous proposal that didn't merge.

The series adds two main features to `git cat-file --batch`: a new `%(objectmode)` format atom to show file permissions, and better handling of submodule entries in trees (now showing their OIDs with a clear error message rather than empty content). The motivation is to expose more internal object information efficiently, avoiding the performance hit of spawning multiple processes when examining tree entries.

The first patch updates tests to better handle object specifications with spaces, revealing and documenting a known issue with the `%(rest)` atom. The second adds the mode display capability essentially as previously proposed, while the third takes a new approach to submodule handling based on prior feedback.

The changes appear well-considered, with thorough test coverage and clear responses to previous review comments. The performance argument for batch processing versus multiple `ls-tree` calls is compelling for workflows examining many tree entries. This seems like a useful, focused improvement to Git's plumbing capabilities.
