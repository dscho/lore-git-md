This is the third and final patch in a bugfix series addressing edge cases in batched reference updates. It fixes a filesystem directory/file (F/D) conflict issue in `git receive-pack` when handling mixed delete/create operations in batched mode.

The patch modifies `builtin/receive-pack.c` to separate reference deletions into their own batch when processing non-atomic updates. This matches the behavior already implemented in `git fetch` and ensures compatibility with the sequential processing behavior that existed before batched updates. The core change adds an `only_deletions` parameter to `execute_commands_non_atomic()` and runs it twice - first for deletions only, then for non-deletions.

The fix is well-motivated by a concrete production scenario where pushing both a branch deletion and creation (like deleting `refs/heads/branch/conflict` while creating `refs/heads/branch`) would fail in batched mode but succeed sequentially. The patch includes test coverage in `t/t5516-fetch-push.sh` to verify this case, along with some test output ordering adjustments to accommodate the new batching behavior.

This completes the series addressing real-world issues GitLab encountered with batched reference updates. The changes are focused and appear to maintain backward compatibility while fixing the F/D conflict case. The patch builds on the previous two in the series (which fixed a segfault and prepared test infrastructure) to provide a complete solution.
