This is a bugfix series addressing issues in Git's batched reference updates feature, which was recently introduced to optimize reference operations. The patches come from Karthik Nayak and target problems discovered during real-world testing at GitLab.

The series fixes two main issues. First, the files backend could segfault by not properly skipping failed updates during batched operations. Second, `git-receive-pack` could encounter file/directory conflicts when processing mixed delete/create operations in a single transaction (like deleting `refs/heads/branch/conflict` while creating `refs/heads/branch`). The solution mirrors a previous fix for `git-fetch` by separating deletion operations into their own batch.

The changes include test coverage for both scenarios and some test cleanup (converting single quotes to double quotes where variables are used). The patches appear well-motivated by actual production issues and include appropriate test coverage. This seems like an important stabilization of the new batched reference update feature, particularly for users pushing to repositories with complex ref hierarchies.
