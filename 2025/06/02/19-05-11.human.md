Platform compatibility fix for OpenBSD's sed implementation in config generation.

Brad Smith acknowledges Collin Funk's patch that fixes a build failure on OpenBSD where the system's sed doesn't support \n escape sequences. The issue was introduced in March 2025 when backtick handling for completion options was added (commit e1b81f54da), causing malformed output in config-list.h that broke compilation.

The proposed solution (which Brad appears to accept) uses a shell variable containing an actual newline character instead of the \n escape sequence in generate-configlist.sh. This maintains the same output format while being portable to OpenBSD's stricter sed implementation. The change is minimal - just 4 lines added/modified in the script that processes documentation into a header file.

While the thread shows consensus on this specific fix, it doesn't address whether other BSD variants might have similar sed limitations. The patch appears technically sound for its stated purpose, with a clear connection to the regression it fixes.
