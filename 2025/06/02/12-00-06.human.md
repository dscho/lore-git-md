This is a bugfix patch addressing a segfault in the files backend for batched reference updates. It's part of a series fixing production problems GitLab encountered with the recently added batched updates feature.

The patch adds missing checks in `files_transaction_finish()` to skip updates that have already been marked with errors, preventing potential segfaults. Patrick Steinhardt confirms the fix but questions why existing tests didn't catch this issue. He also notes that the reftable backend handles this case differently (and correctly) by filtering failed updates earlier in the process.

A new test case is added to `t1400-update-ref.sh` to verify the fix handles deletion of non-existent references properly. Patrick suggests the test should not silence `test_grep` output, following Git's testing conventions. The change is straightforward and clearly motivated by real-world crashes, though the discussion reveals some gaps in test coverage that might need follow-up attention.
