This is a follow-up discussion about a portability fix for OpenBSD's sed implementation affecting config-list.h generation.

Jean-Noël AVILA reports that Collin Funk's proposed solution, while avoiding an additional process spawn, doesn't work correctly on Debian systems using dash. The patch intended to fix OpenBSD's sed limitation by using a shell variable with literal newline instead of \n escape sequences, but appears to produce malformed output on dash, with literal "$nl" appearing in the generated file and some lines being incorrectly concatenated.

The email suggests testing the patch more widely via gitgitgadget's CI infrastructure, which would automatically verify the fix across multiple platforms. This surfaces an important consideration - while the original patch solved the OpenBSD issue, it may introduce new portability problems on other systems. The discussion highlights how shell script portability often requires solutions that work across diverse environments.

The thread remains focused on finding a robust solution to the sed portability issue introduced by e1b81f54da, with no immediate resolution proposed in this email. The interaction demonstrates the value of cross-platform testing for such fixes.
