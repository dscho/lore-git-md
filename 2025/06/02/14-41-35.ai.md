This is a bugfix patch addressing a compatibility issue in `git fsck` with older worktree directories. The patch fixes a regression where `git refs verify` would fail on worktrees created by Git versions prior to 2.43.0, which didn't automatically create the `refs` directory in worktree gitdirs. The error occurred because newer code (since commit 7c78d819e6) assumed this directory would always exist.

The solution modifies `files_fsck_refs_dir()` in refs/files-backend.c to ignore ENOENT errors specifically for linked worktrees, maintaining backward compatibility. The change is accompanied by a new test case that verifies the fix by manually removing the refs directory from a worktree and confirming `git refs verify` still works.

Key technical details:
- The fix checks for `errno == ENOENT` combined with `!is_main_worktree(wt)` before reporting directory errors
- The test case uses `git worktree add` to create a test scenario, then manually removes the refs directory to simulate the old layout
- The issue was reported by Kristoffer Haugsbakk and relates to changes introduced in commits 8f4c00de95 and 7c78d819e6

This appears to be a well-justified and cleanly implemented fix for a real compatibility problem, with appropriate test coverage. The patch targets the refs/files-backend.c component and affects how Git handles worktree ref directories during verification.
