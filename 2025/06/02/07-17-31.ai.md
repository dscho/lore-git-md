This is a refactoring patch in Patrick Steinhardt's v3 series (12 patches) addressing race conditions in Git's maintenance task execution. Patch 5/12 specifically tackles the problematic use of global state in task configuration.

The patch removes direct modification of the global `tasks[]` array, which previously tracked task execution state through three separate fields (`enabled`, `selected_order`, and `schedule`). Instead, it introduces a new approach where task configuration is computed once during initialization and stored in the options structure. Key changes include:

1. The `maintenance_task` struct is simplified to be immutable (removing state-tracking fields)
2. Task selection logic is centralized in `initialize_task_config()`
3. Selected tasks are stored in `opts->tasks` array rather than modifying global state
4. Strategy patterns (`none_strategy`, `default_strategy`, `incremental_strategy`) replace ad-hoc configuration
5. Memory management is added via `maintenance_run_opts_release()`

The refactoring makes the code more maintainable by:
- Eliminating global state mutations
- Localizing task selection logic
- Making execution flow more linear and predictable
- Maintaining the same behavior while being more type-safe

This change is part of the series' broader effort to fix race conditions while improving code quality. It doesn't change user-visible behavior but provides a cleaner foundation for the subsequent race condition fixes in later patches. The patch follows the series' pattern of careful, systematic refactoring with clear separation of concerns.
