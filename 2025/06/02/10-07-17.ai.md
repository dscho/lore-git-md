Bugfix discussion regarding pathspec handling in empty repositories with `--update` flag. Phillip Wood responds to Piotr Siupa's regression report about `git add --update -- ':(exclude)foo'` showing duplicate errors in empty repos (introduced in 2.45.0). Phillip agrees the behavior is inconsistent but suggests the real issue might be that Git *should* error when exclude patterns match nothing, even in non-empty repos. He contrasts current behavior where `git add -u does-not-exist` errors but `git add -u ':(exclude)*'` silently succeeds when excluding all files. The discussion shifts from fixing a regression to potentially changing the expected behavior - suggesting pathspec matching should consistently error when no files remain after exclusions, regardless of repository state. This reframes the issue from a bug to a potential behavior improvement, though the empty-repo case remains uniquely problematic due to its interaction with the implicit '.' pathspec.
