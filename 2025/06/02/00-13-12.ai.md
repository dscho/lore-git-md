This is a feature patch adding OAuth2.0 authentication support to `imap-send`, specifically implementing both the standard OAUTHBEARER and Google-proprietary XOAUTH2 mechanisms. The patch is part of a larger v11 series that has already seen extensive review, with this particular piece introducing the core authentication handlers and documentation updates.

The implementation adds new enum values and capability strings for the OAuth2 methods, along with base64 encoding helper functions (`oauthbearer_base64()` and `xoauth2_base64()`) and authentication handlers (`auth_oauthbearer()` and `auth_xoauth2()`). The documentation updates explain how to configure OAuth2 with Gmail, noting it as more secure than app-specific passwords and not requiring MFA. The patch also references credential helpers from `git-send-email` as a way to manage OAuth2 tokens.

Junio Hamano's review identifies a design inconsistency in how authentication method support is checked - while the code verifies server support via CAPABILITY checks, it doesn't similarly verify local implementation support before attempting authentication. This leads to potential die() calls from the base64 helpers when methods are unsupported, rather than graceful early failure. The review suggests restructuring to check for local support at the same level as server support checks, following a more consistent pattern that could also improve the existing CRAM-MD5 implementation.

The patch represents a significant security and usability improvement for `imap-send`, but the authentication checking flow needs refinement to match Git's error handling patterns. The implementation currently assumes OpenSSL support (with stubs that die() when unavailable), while the series as a whole supports both OpenSSL and libcurl backends. The documentation additions are thorough but could benefit from minor reformatting to maintain line length conventions.
