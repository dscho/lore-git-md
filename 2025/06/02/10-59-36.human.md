Bugfix for `imap-send`'s CRAM-MD5 authentication when built without OpenSSL. This is part of a larger v12 series that adds OAuth2.0 support and fixes various IMAP authentication issues.

The patch addresses a specific edge case where CRAM-MD5 authentication would crash when attempted without OpenSSL support (unlike other auth methods that either work without OpenSSL or fail gracefully). The fix moves the OpenSSL availability check earlier in the process and provides a clear error message before attempting authentication.

Key changes:
- Moves the `auth_cram_md5` function definition before its first use
- Adds a compile-time guard (`NO_OPENSSL`) check when CRAM-MD5 is requested
- Preserves the same error message but displays it more gracefully via `fprintf` rather than `die()`

This is a straightforward improvement that makes the behavior consistent with other authentication methods in the series. The patch appears well-contained and properly handles the error case while maintaining all existing functionality when OpenSSL is available.
