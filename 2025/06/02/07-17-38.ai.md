This is the final patch in Patrick Steinhardt's v3 series addressing race conditions in Git's maintenance task execution, specifically focusing on the "gc" task. The patch completes the series' work of splitting maintenance tasks into foreground/background phases to prevent lockfile contention.

The key change splits the "gc" task implementation similarly to how "pack-refs" and "reflog-expire" were handled in previous patches. The foreground phase now runs `gc_foreground_tasks()` (renamed from `gc_before_repack()`) which handles ref and reflog operations, while the background phase runs the actual GC with a new `--skip-foreground-tasks` flag to avoid duplicate work. This matches git-gc(1)'s own behavior and prevents the same lockfile races seen with other tasks.

Implementation details include:
- Renames `gc_before_repack()` to `gc_foreground_tasks()` for clarity
- Adds hidden `--skip-foreground-tasks` flag to `git gc`
- Splits `maintenance_task_gc()` into separate foreground/background functions
- Updates task array to use both phase handlers
- Modifies tests to expect the new `--skip-foreground-tasks` flag

The changes maintain all existing behavior while fixing the race condition, completing the series' systematic approach to lockfile safety. Test coverage remains strong, verifying the new execution flow through existing subcommand checks. This patch represents the culmination of the series' three-track approach - fixing races, improving interfaces, and refactoring internals - now fully applied to the "gc" task.
