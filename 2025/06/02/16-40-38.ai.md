This is the first of two preparatory patches in a series adding GPG signing support to `git subtree`. The patch refactors the argument parsing in `git-subtree.sh` to use `--stuck-long` mode, which is necessary for cleanly handling the optional parameter of the upcoming `-S/--gpg-sign` option.

The changes convert the script from short-option-with-separate-argument style (e.g., `-m message`) to long-option-with-equals style (e.g., `--message=message`). This affects several existing options including `--annotate`, `--branch`, `--prefix`, `--message`, and `--onto`. The patch removes redundant shift operations since `--stuck-long` handles parameter consumption automatically.

Key technical details: The core change is adding `--stuck-long` to the `git rev-parse --parseopt` invocation. The rest of the changes adapt the option handling code to match this style. The patch maintains all existing functionality while preparing for the GPG signing addition in patch 2/2. The changes are mechanical and focused on the argument parsing logic, with no behavior changes to the actual subtree operations.

This is a clean preparatory change that follows Git's standard argument parsing conventions. The commit message clearly explains the change's purpose in relation to the series' GPG signing goal. The diff shows careful attention to maintaining compatibility while modernizing the parsing approach.
