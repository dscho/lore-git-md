This thread began with a build failure on OpenBSD caused by limitations in its `sed` implementation when processing line continuations in config.adoc files during `config-list.h` generation. Collin Funk proposed and implemented a solution (now merged) that restructures the documentation to list related config variables on separate lines, following the style used in `pretty-options.adoc`. This approach avoids the problematic `sed` expressions while preserving the necessary formatting.

With the technical solution in place, the discussion has shifted to finalizing the documentation policy in `CodingGuidelines`. The current debate centers on wording details - specifically whether to require consistent backtick markup for all config variable names (despite existing inconsistencies) and how prominently to emphasize greppability as a benefit alongside the primary script compatibility rationale. Junio C Hamano has acknowledged that Jean-Noël Avila is already incrementally updating config files to the new style, balancing consistency work with other ongoing documentation efforts.

The thread appears to be nearing resolution, with the key participants (Collin Funk, Jacob Keller, and Junio) converging on a policy that will document both the required format (one variable per line) and its rationale. Once the final wording is settled, this will establish clear expectations for contributors while preventing regression to the problematic comma-separated format that caused the original build issues.
