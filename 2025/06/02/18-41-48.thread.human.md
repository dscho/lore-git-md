The thread addresses a build failure on OpenBSD and dash shell systems caused by sed's handling of newlines during config-list.h generation. Initially, Collin Funk proposed a sed-based workaround (v1-v2) that functioned across platforms but left visible "$nl" markers in the output. During discussion, Jean-Noël Avila and Jacob Keller advocated for an alternative approach: restructuring the documentation source files to naturally break lines at option boundaries, following the precedent of pretty-options.adoc.

Collin has now submitted v3, implementing the documentation restructuring approach. The patch modifies gitcvs.adoc and http.adoc to split related configuration variables (gitcvs.dbUser/dbPass and http.lowSpeedLimit/lowSpeedTime) onto separate lines, eliminating the need for sed line continuation entirely. This produces cleaner output while maintaining readability and solves the original portability issue more elegantly than the sed workaround.

The solution has evolved through active discussion, with contributors converging on the documentation restructuring approach as preferable to the sed workaround. The patch appears well-executed and focused, addressing the core issue while maintaining consistency with existing documentation style. It now awaits maintainer consideration, having addressed all technical concerns raised during the thread's progression from sed-based to documentation-based solutions.
