This thread addressed a build issue on OpenBSD caused by limitations in its `sed` implementation when processing comma-separated configuration variables in Git's documentation. Collin Funk proposed restructuring the affected config.adoc files to list variables one-per-line, which resolved both the OpenBSD build failure and a related dash shell issue. Jacob Keller reviewed the solution, and Junio C Hamano accepted it after testing.

The thread concluded with a documentation policy update, now added to CodingGuidelines, that formalizes the one-variable-per-line format as a project requirement. This prevents regression to the problematic comma-separated format while documenting the portable solution pattern. The change affects how future contributors must document related configuration variables, ensuring continued compatibility with the generate-configlist.sh script's parsing logic across all platforms.
