This thread addressed a build issue on OpenBSD caused by limitations in its `sed` implementation when processing comma-separated config variable listings in documentation files. Collin Funk first restructured the affected config.adoc files to list variables on separate lines (following the existing pretty-options.adoc style), which resolved the immediate problem with Jacob Keller's review. 

The discussion then turned to documenting this as a project-wide policy in CodingGuidelines to prevent similar issues. Collin proposed wording that Junio C Hamano refined, resulting in a clear policy section with before/after examples showing the preferred one-variable-per-line format. The final patch carries both Collin's sign-off and Junio's suggested-by tag, reflecting their collaboration. 

The solution serves dual purposes: it fixes the OpenBSD build while improving greppability, and it does so without conflicting with Jean-Noël Avila's parallel documentation standardization work. With the maintainer's acceptance of the policy addition, this thread is now that both the technical fix and documentation update are complete.
