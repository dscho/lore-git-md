This thread addressed a build issue on OpenBSD caused by limitations in its `sed` implementation when processing line continuations in `config-list.h` generation. The problem stemmed from how configuration variables were documented in `config.adoc` files, with multiple variables listed on a single line separated by commas. Collin Funk proposed restructuring the documentation to place each variable on its own line, eliminating the need for complex line continuation handling in `generate-configlist.sh`. Jacob Keller reviewed and approved the approach, suggesting the new convention be documented as project policy.

Junio C Hamano accepted the technical solution in v3 of Collin's patch, which modified `gitcvs.adoc` and `http.adoc` to follow the style already used in `pretty-options.adoc`. The thread concluded with a discussion of how to document this new policy in `CodingGuidelines`. Junio suggested two refinements: consistently marking config variables as literal strings (wrapped in backticks) and framing the rationale in terms of greppability benefits rather than just script compatibility. This brings the policy in line with how negatable options are documented elsewhere.

The solution resolves both the OpenBSD build issue and a related dash shell problem, while establishing clear documentation standards going forward. The changes have been merged, with the new policy preventing regression of the problematic format. Participants included Collin Funk (author), Jacob Keller (reviewer), Junio C Hamano (maintainer), Brad Smith (OpenBSD confirmation), and Jean-Noël Avila (documentation support). The thread is now fully resolved.
