This thread addresses a series of bugfixes for batched reference updates, a feature recently integrated into `git fetch` and `git receive-pack` that GitLab encountered production issues with. The core problems involved segfaults in the files backend during failed updates, test cleanup needs, and inconsistent handling of directory/file conflicts between batched and sequential modes in `receive-pack`.

Patrick Steinhardt submitted the three-patch series based on GitLab's production experience. The first patch fixes a segfault in the files backend during batched deletions, while the third modifies `receive-pack` to handle F/D conflicts by splitting deletions into a separate transaction first. Karthik Nayak has reviewed the changes, raising a minor concern about output ordering (deletions now appearing before creations) but agreeing the core solution is sound. 

The discussion has revealed architectural differences between the files and reftable backends, with the reftable backend's design naturally preventing this class of issues. While the output ordering change isn't ideal, both maintainers acknowledge there was never a formal guarantee about ordering. Karthik indicates he may look into preserving the previous pattern, though this would require non-trivial changes. With the technical approach settled and only minor polish remaining, this series appears ready for integration once the final output ordering question is resolved.
