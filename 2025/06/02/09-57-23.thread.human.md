This thread covers Patrick Steinhardt's series fixing edge cases in batched reference updates, now at v3. The changes address production issues encountered in GitLab's Gitaly service, particularly around segfaults in the files backend and directory/file conflicts during batched operations.

The first patch fixes a files backend segfault by properly handling failed updates during batched operations, with new test coverage. The second patch restructures `git receive-pack` to process deletions separately from other updates, avoiding filesystem conflicts while maintaining efficiency. This mirrors a similar fix previously applied to `git fetch`. The v3 iteration incorporates Karthik Nayak's feedback by making transaction creation lazy (only when needed) and cleaning up stale comments.

Reviewers including Junio Hamano and Eric Sunshine have shaped the series through multiple iterations, with v1's unnecessary test changes dropped and v2's phase-based approach refined. The current version has thorough test coverage across multiple scenarios and appears ready for integration. While the solution may use up to two transactions in some cases, this remains more efficient than the pre-batched implementation. The changes are well-motivated by real-world production needs and have been carefully reviewed.
