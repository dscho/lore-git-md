This thread addresses critical bugfixes for Git's batched reference updates feature, which was recently integrated into `git fetch` and `git receive-pack`. The patches stem from GitLab's production experience with their Gitaly service. The core issues involve segfault fixes in the files backend, test cleanup, and resolving filesystem directory/file (F/D) conflict handling differences between batched and sequential modes.

Patrick Steinhardt's v1 series provides three fixes: preventing segfaults during failed batched deletions, improving test descriptions, and modifying `receive-pack` to handle F/D conflicts by splitting deletions into a separate transaction first. While the technical solution is functionally complete, discussion has revealed a subtle behavioral change - hook notifications now show deletions before updates rather than maintaining the original push order.

Junio Hamano has weighed in, acknowledging this output ordering change as potentially noticeable to human operators, though hook scripts themselves lack the context to detect it. The core two-transaction approach remains sound, but Junio agrees the ordering difference warrants consideration. Karthik Nayak had previously reviewed the solution, agreeing with the approach while noting the output ordering change.

The thread is now focused on polishing this edge case - whether and how to preserve the original output ordering pattern while maintaining the F/D conflict safety. Junio has also suggested expanding test coverage for cases where a deletion with an expected old OID fails on a non-existent reference. The series remains production-proven but may see minor adjustments to address these final concerns.
