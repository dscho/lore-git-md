This thread addresses critical bugfixes for Git's batched reference updates feature, which was recently integrated into `git fetch` and `git receive-pack`. The issues were discovered through GitLab's production use of the feature.

The series consists of three patches from Patrick Steinhardt. The first fixed a segfault in the files backend when handling failed updates during batched transactions. The second prepared test infrastructure by cleaning up test descriptions in the push/fetch test suite. The newly arrived third patch resolves a key compatibility issue where batched updates handled directory/file conflicts differently than sequential processing, which could break existing workflows.

The solution mirrors an earlier fix for `git fetch` - it separates deletions into their own batch transaction before processing other updates. This maintains backward compatibility while fixing the edge case. The patch modifies `execute_commands_non_atomic()` to support this two-phase approach and adds comprehensive test coverage.

With all three patches now submitted, the series addresses the production issues GitLab encountered. The changes touch core reference handling code in `refs/files-backend.c` and `builtin/receive-pack.c`, with corresponding test updates. While the patches appear well-reasoned and tested, the thread hasn't yet seen review feedback from other contributors familiar with this area of the codebase.
