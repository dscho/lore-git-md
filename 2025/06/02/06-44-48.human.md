This is a test infrastructure patch in Patrick Steinhardt's series to integrate TAP output parsing with Meson builds. It changes how the test suite handles tests marked with `test_expect_failure` that unexpectedly pass.

Currently, when a test passes despite being marked as an expected failure, Git merely notes the discrepancy but still considers the overall test run successful. This patch makes such cases fail the test suite entirely, bringing Git's behavior in line with Meson's TAP parser (which already treats unexpected passes as failures). The change helps catch regressions that might otherwise go unnoticed, especially across different platforms where tests may pass in some environments but not others.

The implementation modifies the test-lib.sh infrastructure to exit with a failure code when fixed tests are detected, and updates t0000-basic.sh to verify this new behavior. While this produces slightly awkward output in prove(1) (which still shows all tests passing but notes the unexpected success), it provides consistent behavior between different test runners and makes unexpected passes more visible to developers.

This is part of a larger effort to make Git's test infrastructure work reliably with Meson builds while maintaining compatibility with existing tools. The patch appears well-considered, with clear justification for the behavior change and appropriate test coverage.
