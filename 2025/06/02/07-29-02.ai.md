This is a platform compatibility patch addressing header handling for OpenBSD and NetBSD systems. The change aligns their treatment with FreeBSD/DragonFly by removing explicit `_XOPEN_SOURCE` definitions for these platforms, while maintaining the existing behavior for other systems. The patch also cleans up some legacy defines, removing `_NETBSD_SOURCE` which appears no longer needed.

The technical changes modify `compat/posix.h` to:
1. Add `__NetBSD__` and `__OpenBSD__` to the list of platforms excluded from the `_XOPEN_SOURCE 600` definition
2. Remove the standalone `_NETBSD_SOURCE` define
3. Reorganize the conditional logic for better readability
4. Update the comment about OpenBSD's S_ISLNK() requirement which is now handled differently

The commit message notes this fixes a compilation warning about `getdelim()` being undeclared on OpenBSD, suggesting the current approach of not setting `_XOPEN_SOURCE` for BSD variants is preferable to trying to set it to 700 (which would be OpenBSD's requirement). The change appears straightforward and focused, though it might be worth verifying whether the removed `_NETBSD_SOURCE` define was serving any purpose not evident from the diff.
