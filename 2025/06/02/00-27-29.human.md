This is a review comment on the `imap-send` authentication series, specifically addressing the PLAIN authentication implementation. Junio Hamano points out two consistency issues in the v11 patch:

1. The error message for missing OpenSSL support in the PLAIN authentication stub function should match the style used for CRAM-MD5, making it clear this is a build-time configuration issue ("If you want to use PLAIN...") rather than a runtime limitation.

2. The authentication flow still doesn't verify local support for authentication methods before attempting them, despite gracefully checking server support. This was previously noted as a design inconsistency in the thread, and Junio observes the same pattern persists in the PLAIN implementation.

The feedback is constructive and focused on maintaining consistency - both in error messaging and in the authentication flow design. This comes late in the series (v11) and addresses relatively minor polish issues, suggesting the core functionality is otherwise sound. The changes requested would align the PLAIN implementation with the established patterns seen in CRAM-MD5 and the rest of the authentication system.
