This is a follow-up discussion about the OpenBSD sed portability fix for config-list.h generation. The thread began with Collin Funk's patch to address OpenBSD's sed not supporting \n escape sequences by using a shell variable with a literal newline. While Brad Smith confirmed it fixed the OpenBSD build, Jean-Noël Avila now reports the solution doesn't work on Debian with dash, showing malformed output where "$nl" appears literally in the generated file rather than expanding to a newline.

The key technical issue is that the shell variable expansion approach, while avoiding an extra process spawn, fails on dash due to different quoting behavior. The problematic output shows config options incorrectly concatenated with "$nl" strings instead of proper newline-separated entries. Jean-Noël suggests testing via gitgitgadget to validate across platforms, hinting the solution may need adjustment for broader shell compatibility.

This reveals the patch isn't yet fully portable despite solving the original OpenBSD issue. The discussion now shifts to finding a solution that works across both OpenBSD's sed limitations and dash's quoting behavior, with gitgitgadget's multi-platform CI suggested as a validation mechanism. The core challenge remains maintaining the config-list.h format while accommodating diverse shell/sed implementations.
