Bugfix for a critical regression in `imap-send` that made the command unusable since Git 2.46.0. The patch fixes a configuration parsing bug introduced in commit 6d1f198f34 where the wrong field (`cfg->folder`) was being cleared when processing unrelated IMAP configuration variables like `imap.user` or `imap.pass`. This caused the folder setting to be incorrectly NULLed out, breaking basic functionality.

The fix is straightforward - each configuration variable now properly clears its own corresponding field rather than incorrectly clearing the folder field. The patch is part of a larger v12 series that adds OAuth2.0 support and other IMAP improvements, but this particular change stands alone as a critical bugfix that should be considered for backporting.

The regression appears to have gone unnoticed for some time, likely because most users prefer `git send-email` over `imap-send`. The patch is well-contained (just 4 lines changed) and clearly corrects the intended behavior. Given its impact on basic functionality and the clean fix, this seems like an important change that should be merged quickly.
