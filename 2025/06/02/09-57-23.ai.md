This is a bugfix series addressing issues in the batched reference updates feature, which was recently integrated into `git fetch` and `git receive-pack`. The series comes from GitLab's production experience with the `next` branch of Git.

The first patch fixes a files backend issue where failed updates weren't properly skipped during batched operations, which could lead to segfaults. The second is a minor test cleanup. The third addresses a filesystem directory/file conflict case in `git receive-pack` where batched updates could fail differently than sequential updates - it separates reference deletions into their own batch to maintain compatibility with the old behavior.

The changes touch core reference handling in the files backend and receive-pack, with corresponding test updates. The issues appear to be real production problems encountered at GitLab (specifically in their Gitaly service), suggesting these are important fixes for anyone using the new batched reference feature. The patches include tests for both the segfault case and the F/D conflict scenario.

This builds on the recent batched reference work (23fc8e4f61) and specifically addresses edge cases that only appeared when the feature was put into production use. The fixes maintain the performance benefits of batching while ensuring correct behavior in error cases.
