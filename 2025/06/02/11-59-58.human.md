This is a bugfix patch addressing filesystem directory/file (F/D) conflicts in batched reference updates for `git receive-pack`. It's the third and final patch in a series based on GitLab's production experience with the batched refs feature.

The patch modifies `execute_commands_non_atomic()` in `builtin/receive-pack.c` to handle F/D conflicts by splitting deletions into a separate batch transaction first, mirroring the solution previously implemented for `git fetch`. While this adds a second transaction in conflict cases, it maintains compatibility with the sequential behavior users expect. The change comes with test updates in `t/t5516-fetch-push.sh` to verify the behavior.

Patrick Steinhardt notes that while the solution works (and is production-proven at GitLab), it's not ideal that the reference transaction itself doesn't handle these conflicts natively. He also points out a subtle behavioral change in hook output ordering (deletes now appear before updates) that wasn't explicitly guaranteed before but might surprise some users. The patch appears technically sound but may need discussion about whether the ordering change is acceptable.
