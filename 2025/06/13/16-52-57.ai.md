This is a bugfix patch addressing a memory leak in the mailinfo subsystem. The patch fixes a case where `handle_content_type()` would allocate memory for a boundary string but fail to free it when hitting the maximum number of boundaries limit.

The issue occurs in `mailinfo.c` when processing email content types. The function allocates memory for a new boundary using `xmalloc()`, but if the boundary count exceeds `MAX_BOUNDARIES`, it would return without cleaning up the allocation. The patch adds proper cleanup by calling `strbuf_release()` and `free()` on the boundary object before returning in this error case.

The fix is straightforward and clearly correct - it adds the missing cleanup for an error path that was previously overlooked. The patch is small (3 lines added) and focused, touching only the specific error handling case where the leak occurs. The commit message clearly explains both the problem and solution.

Key technical details for future reference:
- File modified: `mailinfo.c`
- Function: `handle_content_type()`
- Memory management issue with `boundary` allocation when `mi->content_top >= &mi->content[MAX_BOUNDARIES]`
- Fix adds `strbuf_release()` and `free()` calls before early return
- Related to boundary handling in email content parsing
