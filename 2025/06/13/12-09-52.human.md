This is a follow-up discussion on the merge.stat configuration patch, focusing on documentation improvements and potential aliases.

Kristoffer Haugsbakk raises three points about the documentation for the new `merge.stat` configuration that controls merge summary output. First, they suggest considering `diffstat` as an alias for `true` since that's the historical behavior, though they acknowledge this might not be necessary given backward compatibility is already maintained. 

Second, they note that the documentation refers to `git diff --diffstat` which isn't actually a valid command (it should be `git diff --stat`). This appears to be a minor documentation error in the patch.

Third, they propose simplifying the default value description from "If this variable is left unspecified, it defaults to `true`" to just "Defaults to `true`", noting this matches most other documentation while pointing out one exception (`merge.renameLimit`).

These are all documentation-focused suggestions that don't affect the functionality of the already-merged compact summary feature. The thread shows careful attention to detail in the documentation wording and consistency with existing Git conventions.
