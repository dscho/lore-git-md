This is a final review comment on the second patch of Patrick Steinhardt's bugfix series for batched reference updates, now at v4. Junio Hamano acknowledges the patch's approach to handling D/F conflicts in `git receive-pack` by splitting deletions into a separate transaction phase, but raises important concerns about the long-term solution.

The patch addresses a specific edge case where batched updates would fail on directory/file conflicts that sequential updates handled correctly. While the current two-phase approach (deletions first, then other updates) improves the situation, Junio notes it's not a true transactional solution since partial failures can still occur. He suggests adding a NEEDSWORK comment to document this limitation and proposes a test_expect_failure case to track the known issue.

Key technical points: The patch modifies `execute_commands_non_atomic()` in `builtin/receive-pack.c` to use separate PHASE_DELETIONS/PHASE_OTHERS phases, building on similar fixes made earlier for `git fetch`. Test coverage is added to validate the behavior, though Junio suggests additional test documentation of the remaining limitation.

The review confirms the patch is ready to merge (Junio states "Will queue") but flags the transactional behavior as an area needing future work. This aligns with the thread's earlier discussions about differences between files and reftable backends in batched transactions. The comment references prior commits 9d2962a7c4 and related work, maintaining context with the series' goal of making batched updates production-ready.
