This is a platform compatibility discussion following up on the Solaris sed build problems that were recently fixed. Collin Funk responds to Jean-Noël Avila's suggestion about setting up Solaris CI testing to catch similar portability issues earlier. 

Collin downplays the severity of the recent Solaris build regressions, noting that Solaris packagers are accustomed to dealing with such portability quirks. He suggests that while GitHub Actions could theoretically test on Solaris/illumos systems using the vmactions provider, he's uncertain whether it would have caught the specific sed issues since the build still completed (albeit with warnings/errors). 

The response reflects the practical reality that while CI testing on non-Linux platforms is possible, it may not catch all portability issues, especially subtle ones like the sed behavior differences. Collin's perspective aligns with the thread's earlier consensus that portable solutions (like Junio's BRE sed rewrite) are preferable to requiring GNU tools, though he doesn't strongly advocate for implementing Solaris CI at this time. The exchange continues the thread's theme of balancing portability concerns with practical development constraints.
