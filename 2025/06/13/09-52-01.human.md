This is a discussion about marking the new `git last-modified` command as experimental in its documentation. The thread context shows this is part of an ongoing series implementing a command to track file modification history, now in its final polishing stages.

Kristoffer Haugsbakk weighs in on Toon Claes' documentation patch that added an "EXPERIMENTAL" label to the command's manpage. While Patrick Steinhardt had questioned the label by comparing to `git-switch` and `git-restore`, Claes defended it by pointing to `git-replay`'s precedent, noting the lack of interface feedback so far.

Haugsbakk supports keeping the experimental marker, arguing it provides important signaling to users about interface stability. They note that while core developers are actively reviewing the implementation, broader user experience testing (from those who can't contribute code) is still needed before committing to a stable interface. The experimental label would allow interface changes while protecting script users from unexpected breakage.

This is a relatively minor documentation discussion in an otherwise technically mature patch series. The exchange highlights differing perspectives on when to remove the experimental label - whether to follow the precedent of similar plumbing commands (`git-replay`) or porcelain commands (`git-switch`). Haugsbakk's perspective as a user focused on interface stability adds useful context beyond the core developer discussion.
