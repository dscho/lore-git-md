This is the first patch in a two-part bugfix series addressing edge cases in batched reference updates, now at version 4. The patch fixes a segfault in the files backend when processing failed updates in batched transactions.

The core issue stems from commit 23fc8e4f61 which introduced batched reference updates but missed skipping failed updates in two loops within `files_transaction_finish()`. The patch adds proper checks for `update->rejection_err` in both loops - one handling reference updates and another for directory cleanup. This prevents segfaults when processing failed updates.

The patch includes three new test cases in `t/t1400-update-ref.sh` that validate the fix by exercising different failure scenarios: deleting a symbolic ref pointing to a non-existent ref, deleting with an incorrect old OID, and deleting a non-existent ref. These tests confirm the backend properly skips failed updates while continuing to process the batch.

This is a straightforward fix that addresses a clear production issue discovered in GitLab's Gitaly service. The changes are minimal and focused, with comprehensive test coverage added. The patch builds on prior work in the thread where the terminology and structure were refined through multiple review rounds, and now appears ready for integration.
