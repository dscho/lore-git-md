This is a bugfix patch addressing a memory leak in the notes subsystem. The change moves the allocation of a `note_msg` struct in `parse_reuse_arg()` to after several operations that could trigger fatal errors (`repo_get_oid()` and `repo_read_object_file()`). Previously, memory would be leaked if these operations failed since the `msg` allocation and `strbuf_init()` happened before the error checks.

The patch affects `builtin/notes.c`, specifically the logic for reusing existing note content. The key changes are:
1. Moving the `xmalloc` and `msg` struct initialization after the error-prone operations
2. Simplifying the error handling by removing redundant cleanup when encountering non-blob objects
3. Maintaining the same functionality while eliminating potential leaks on error paths

The fix is straightforward and appears correct - it follows the common pattern of deferring allocations until after operations that could fail. The commit message clearly explains the problem and solution. This seems like a low-risk improvement to error handling in the notes code.
