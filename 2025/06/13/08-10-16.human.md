Bugfix series addressing edge cases in batched reference updates, now at v4. This continues Patrick Steinhardt's earlier work (23fc8e4f61) with fixes for issues found when running GitLab's Gitaly service with batched updates enabled.

The first patch fixes a segfault in the files backend by properly skipping failed updates during batched operations. The second patch modifies `git receive-pack` to handle reference deletions separately from other updates, mirroring a similar fix previously applied to `git fetch`. This prevents directory/file conflicts that could occur when pushing combinations like deleting `refs/heads/branch/conflict` while creating `refs/heads/branch`.

Changes in v4 focus on terminology consistency (switching from "F/D" to "D/F" conflict notation) and minor cleanup. The implementation now only creates transactions when needed and includes thorough test coverage. The thread history shows this has undergone multiple rounds of review addressing feedback from Junio Hamano, Eric Sunshine, and Christian Couder. The current version appears well-polished and ready for integration.
