Bugfix for mailmap handling in `git cat-file` when processing commit/tag objects with differing author/committer identities. This is the final version of a patch that fixes two specific issues in `ident.c`'s to mailmap application, with all review feedback incorporated and ready for merging.

The patch addresses incorrect newline handling and buffer management in `apply_mailmap_to_header()`, which caused parsing failures after mailmap rewrites and potential invalid memory access. The core issues were:
1. Missing newline advancement after processing identity lines, causing subsequent headers to be misparsed
2. Incorrect buffer pointer handling after mailmap-induced reallocations

The fix recomputes buffer positions after rewrites and properly advances past newlines. Two new test cases in `t4203-mailmap.sh` verify the behavior for both committer-only mapping and cases where both author and committer need mapping. The bug originated in commit e9c1b0e3's rewrite of `commit_rewrite_person()`.
