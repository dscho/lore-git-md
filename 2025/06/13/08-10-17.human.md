Bugfix for batched reference updates in the files backend. This is the first patch in a v4 series addressing production issues found in GitLab's Gitaly service.

The patch fixes a segfault that could occur when processing failed updates in batched reference transactions. The issue was that two loops in `files_transaction_finish()` weren't properly skipping updates that had already failed (marked with `rejection_err`). The fix adds the missing checks in both loops.

Three new test cases are added to `t/t1400-update-ref.sh` to verify the fix handles different failure scenarios correctly: deleting a symbolic ref with incorrect old OID, deleting with wrong old value, and deleting non-existent refs. These tests would have caught the original segfault.

This appears to be a straightforward and well-tested fix for a real production issue. The patch builds on prior work from Patrick Steinhardt's batched reference updates series (commit 23fc8e4f61) and has undergone multiple rounds of review. The test coverage is thorough, exercising edge cases that could trigger the original bug.
