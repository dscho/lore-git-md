This is a bugfix patch addressing a memory leak in the notes subsystem. The change moves memory allocation for note messages in `parse_reuse_arg()` to after potentially fatal operations, preventing leaks when error conditions occur.

The patch fixes a case where `xmalloc()` and `strbuf_init()` were called before checking if the referenced object exists and is a blob. If either check failed, the allocated memory would leak during the `die()` calls. The new version delays allocation until after these checks pass, ensuring no resources are held when errors occur.

The change is straightforward and mechanical - it simply reorders operations without changing any behavior in the success case. The diff shows the memory management is now properly paired with the error handling paths. This appears to be a clean fix for a real issue, though likely not a major leak in practice, follows good defensive programming practices.
