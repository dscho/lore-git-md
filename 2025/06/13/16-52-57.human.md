Bugfix addressing a memory leak in mailinfo's content type handling. 

Alex Guo reports and fixes a case where `handle_content_type()` in mailinfo.c could leak memory when hitting the MAX_BOUNDARIES limit. The function allocates a strbuf for boundary handling but would return without freeing it if the boundaries array was full. The patch adds proper cleanup before the early return.

This is a straightforward fix that adds the missing `strbuf_release()` and `free()` calls. The change is small and focused, directly addressing the leak with clear mechanics. While the error case being fixed appears to be rare (requiring an unusually high number of boundaries), the fix follows good practice for resource cleanup. The patch applies cleanly to the mailinfo subsystem with no apparent side effects.
