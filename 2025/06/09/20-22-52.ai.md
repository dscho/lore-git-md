This is a feature patch in the ongoing `imap-send` series, adding folder listing capability to help users discover available IMAP folders with their server-specific naming conventions. The patch introduces a `--list` option that executes the RFC6154-standard IMAP LIST command, showing folder hierarchies and attributes (e.g., `\Drafts`, `\Trash` flags).

For the OpenSSL backend, it implements direct IMAP protocol handling via new `list_imap_folders()`, while the libcurl version uses documented curl_easy_perform patterns in `curl_list_imap_folders()`. The output shows both folder paths and IMAP attributes (e.g., `[Gmail]/Trash` with `\HasNoChildren`). The implementation shares the existing connection/auth infrastructure but skips message upload setup when listing.

Key technical points for future reference:
- Adds `list_folders` static variable and `--list` CLI option
- Modifies `buffer_gets()` to show LIST responses when in list mode
- Implements backend-specific listing:
  - OpenSSL: Issues raw `LIST "" "*"` command via `imap_exec()`
  - libcurl: Uses clean-slate curl setup without upload options
- Documents the feature and suggests it as troubleshooting for folder naming issues
- Maintains existing auth/connection flows while bypassing folder validation for listing

The patch fits into the series' broader authentication/configuration improvements by helping users identify correct folder names for use with other features. It handles both backends consistently and includes appropriate error paths, though it doesn't add new tests.
