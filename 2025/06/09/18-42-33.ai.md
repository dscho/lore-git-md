This is a response in the ongoing discussion about improving error messages for duplicate tag creation. Junio Hamano pushes back against the proposed change to distinguish between same-commit and different-commit tag conflicts in the error message. 

The response argues that the current generic "tag already exists" message is sufficient because: (1) the tag isn't actually modified when the error occurs, giving users a chance to investigate manually, and (2) showing raw commit hashes in the error wouldn't provide immediate clarity since users would need to cross-reference them with known tags anyway (like comparing v1.9.5 to the existing tag's commit). 

This counters the original proposal's position that distinguishing these cases would help users recognize harmless duplicates versus potentially dangerous overwrites. The response suggests users can perform their own investigation (like using `git range-diff`) when needed, implying the additional complexity in the error message isn't justified by the marginal benefit. 

The exchange highlights differing perspectives on error message design - whether to provide more context upfront versus keeping messages minimal and letting users investigate further when needed. The thread now has clear opposing viewpoints on whether the change would meaningfully improve the user experience.
