This is a bugfix patch for the `imap-send` functionality, specifically addressing a critical configuration parsing regression introduced in Git 2.46.0. The patch corrects a memory management issue where unrelated configuration options (`imap.user`, `imap.pass`, `imap.tunnel`, `imap.authmethod`) were incorrectly NULLing out `cfg->folder` due to copy-paste errors in the `git_imap_config()` function. This made `git-imap-send` completely unusable when these configuration options were set.

The fix is straightforward - it properly NULLs out the correct struct fields for each configuration option rather than incorrectly clearing `cfg->folder` in all cases. The patch is part of a larger v18 series that introduces OAuth2.0 support and other improvements to `imap-send`, but this particular change stands alone as a critical bugfix that has been broken since Git 2.46.0.

The commit message notes the regression was unnoticed for some time, likely due to `git-send-email` being a more popular alternative. The change is minimal (4 line changes) and focused specifically on fixing the memory management issue without introducing any new functionality. The patch has already undergone review as part of the larger series and addresses a clear bug that was making the feature unusable.
