Bugfix for interactive rebase state cleanup when instruction format is invalid. This patch addresses an edge case where an invalid `rebase.instructionFormat` configuration leaves the repository in a confusing half-initialized state during an interactive rebase failure.

The core issue occurs when `get_commit_format()` dies due to an invalid format string, but only after `init_basic_state()` has already set up rebase metadata files. The patch reorders operations in `do_interactive_rebase()` to validate the instruction format and generate the todo list *before* initializing the rebase state, preventing the inconsistent state.

Key changes:
- Moves `sequencer_make_script()` call before `init_basic_state()`
- Restructures control flow with early `goto cleanup` when script generation fails
- Adds a test case verifying the rebase-merge directory isn't created for invalid formats

The solution is surgical but effective - it avoids the bad state without requiring deeper changes to `get_commit_format()`'s error handling. The test addition in t3415 provides clear regression protection. The diff shows some code motion that improves logical flow (dedenting the success path) while maintaining all existing functionality.
