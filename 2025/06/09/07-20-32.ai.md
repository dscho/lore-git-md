Bugfix patch for `imap-send` configuration handling, part of a larger series introducing OAuth2.0 support and folder management. This first patch in the v16 series fixes a critical regression introduced in Git 2.46.0 where the configuration parser would incorrectly NULL out the `cfg->folder` field when processing unrelated IMAP configuration variables (`imap.user`, `imap.pass`, etc.). The bug made `git-imap-send` completely unusable since that release.

The fix is straightforward - changing four instances where `FREE_AND_NULL(cfg->folder)` was incorrectly used to instead free the correct field (`user`, `pass`, `tunnel`, or `auth_method`). The regression originated from commit 6d1f198f34 which attempted to fix memory leaks but introduced this incorrect cleanup behavior. The patch maintains the same memory management pattern but applies it to the correct struct fields.

This is a foundational fix for the larger series, as the subsequent authentication and folder management features depend on proper configuration parsing. The thread context shows this series has undergone extensive review, with this particular bugfix being one of the earlier resolved issues. The patch is small (4 line changes) but critical, addressing a complete breakage that went unnoticed likely due to `git-send-email` being more commonly used.
