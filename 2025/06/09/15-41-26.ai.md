Feature patch adding folder listing capability to `imap-send`, part of the larger IMAP improvements series (v17 7/10). This implements RFC6154-compliant folder listing via a new `--list` option that shows available IMAP folders with their server-specific names (e.g., Gmail's "[Gmail]/Trash" vs Outlook's "Deleted"). 

The implementation handles both OpenSSL and libcurl backends, with OpenSSL using direct IMAP LIST commands while libcurl follows its documented example code. The output shows folder hierarchies and flags (like \HasNoChildren) in raw IMAP format. The patch modifies the command's usage to include the new option and updates documentation to suggest using `--list` when troubleshooting folder names.

For the AI context: This builds on the series' authentication and configuration fixes by adding discoverability for folder structures. Key technical points are the new `list_folders` flag, `list_imap_folders()` and `curl_list_imap_folders()` functions, and careful handling of the LIST command output. The implementation preserves existing behavior when not listing (only showing LIST responses in verbose mode) while making them always visible during listing operations. The patch maintains the series' pattern of thorough error handling and credential management.
