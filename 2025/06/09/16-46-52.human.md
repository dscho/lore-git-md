Feature proposal for a confirmation prompt on `git push -f`.

Aditya Garg suggests adding an interactive confirmation prompt when users run `git push -f` to prevent accidental force pushes. The proposal comes from personal experience with the destructive potential of force pushes when used at the wrong time. The email notes that a quick code review suggests this warning isn't currently implemented.

This would be a user-facing safety feature similar to confirmation prompts in other destructive operations. The proposal is light on implementation details but suggests the basic concept is technically feasible. The motivation is clear - force pushes can cause data loss if used carelessly, and an extra confirmation could prevent accidents.

The suggestion appears well-intentioned though somewhat naive in its current form - there's no discussion of how this might interact with scripting/automation or whether it should be configurable. The idea seems worth discussing, particularly around edge cases like non-interactive use and whether this should be opt-in or opt-out behavior.
