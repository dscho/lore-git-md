Bugfix for `imap-send`'s CRAM-MD5 authentication handling. This patch is part of a larger v18 series improving IMAP functionality, with this specific change focusing on graceful failure when CRAM-MD5 is requested without OpenSSL support.

The patch improves error handling by checking for OpenSSL availability upfront when CRAM-MD5 authentication is requested, rather than attempting and failing mid-process. It introduces a new `try_auth_method()` helper that centralizes authentication failure logic, providing clearer error messages when the required library support is missing. The change makes the behavior consistent with other authentication methods in the series (PLAIN, XOAUTH2, OAUTHBEARER) that already had proper library dependency checks.

This appears to be a well-contained change that addresses a specific edge case in the authentication flow. The implementation is clean, moving the OpenSSL check into the new helper function while maintaining the existing behavior when OpenSSL is available. The patch follows the pattern established by earlier work in the series and has been through multiple rounds of review.
