This is a feature patch in the ongoing `imap-send` improvement series (patch 7/10). It adds a new `--list` option to `git imap-send` that displays all available IMAP folders on the server, showing their exact names and attributes. This helps users navigate server-specific folder naming conventions (like Gmail's "[Gmail]/Trash" vs Outlook's "Deleted").

The implementation works for both OpenSSL and libcurl backends, following RFC6154 for the OpenSSL path and libcurl's documented example for the curl implementation. The output shows folder flags (like `\HasNoChildren`) and hierarchy markers, which is particularly useful for servers like Gmail that use nested folder structures.

The patch is well-integrated with the existing codebase, adding the new option to both documentation and the option parser while maintaining backward compatibility. It's part of a mature series that has undergone extensive review, with this particular functionality being one of the final features awaiting final review before merging. The implementation looks solid, with proper error handling and consistent behavior across backends.
