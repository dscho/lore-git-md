Summary of thread: This thread discusses improving Git's tag creation error messages to distinguish between cases where a tag already exists pointing to the same commit versus a different commit. The current behavior shows a generic "tag already exists" message for both scenarios, while the proposed change would include the existing tag's commit hash in the error message. The modification would affect `builtin/tag.c`, specifically the `create_tag()` function, and would need to handle both lightweight and annotated tags. The improvement would help users and scripts better understand and handle tag conflicts, particularly distinguishing between harmless duplicate operations and potentially serious overwrite attempts. The suggestion is well-presented with clear examples of current and proposed behaviors, addressing a real usability pain point in tag management.
