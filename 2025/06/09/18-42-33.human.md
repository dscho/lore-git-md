Maintainer response to tag error message improvement proposal. Junio Hamano rejects the suggestion to enhance Git's tag creation error messages to distinguish between same-commit and different-commit tag conflicts. The original proposal argued that showing the existing tag's commit hash would help users distinguish harmless duplicates from potentially serious overwrites. 

Hamano's position is that the current behavior is sufficient because the tag isn't actually modified when the error occurs, leaving users free to investigate the existing tag's relationship to their intended target. He questions the practical value of showing raw commit hashes, noting users would likely need to do additional investigation (like using `git range-diff`) regardless of whether the hash is shown in the error message.

This appears to close the discussion unless other contributors want to argue for the change's merits. The maintainer's stance suggests this usability improvement, while well-intentioned, doesn't provide enough practical benefit to justify changing the established behavior. The rejection is characteristically direct but not hostile, focusing on the end-user experience rather than implementation concerns.
