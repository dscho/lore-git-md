This is a bugfix patch addressing a memory leak in the pack-bitmap code, specifically in the `find_boundary_objects()` function. It's the seventh iteration of a series that has already been merged into master, with this version containing final wording improvements.

The patch fixes a case where `roots_bitmap` would leak when `cascade_pseudo_merges_1()` succeeds, since the cleanup was previously only happening on failure paths. The solution is straightforward - always free `roots_bitmap` after calling `cascade_pseudo_merges_1()`, since that function doesn't take ownership of the bitmap.

A new test case is added to t5333 that demonstrates the leak scenario by creating two commits (A and B), adding A to a pseudo-merge, then performing a boundary traversal from A to B. This test would catch the leak under ASAN. The test also verifies the bitmap traversal works correctly by checking the commit count.

This appears to be the final polish on a well-reviewed series - the change is small and focused, the commit message clearly explains the issue and solution, and the test provides good coverage. The only change from v6 is improved wording in the commit message to better explain the ownership semantics. The patch has already gone through extensive review and is now just getting its final documentation improvements before being merged.
