Bugfix for a memory leak in revision walking code, now with comprehensive test coverage. This is the final version of a patch that fixes a leak in `prepare_show_merge()` where an allocated array wasn't being freed. The fix itself is straightforward - just adding a `free(prune)` call.

What makes this patch notable is the test case that accompanies it, which was the subject of discussion in the thread. The test creates a realistic merge conflict scenario with three branches (base, hello, goodbye) that modify the same file in conflicting ways, then verifies `git show --merge` behavior in this conflicted state. This approach was praised by Junio Hamano as being more thorough than a minimal test that just triggered the leaky codepath.

The patch appears well-considered, with the test covering not just the memory leak but also exercising the `--merge` flag's behavior during actual conflicts. The thread shows consensus has been reached on both the technical fix and testing approach, making this likely to be merged soon.
