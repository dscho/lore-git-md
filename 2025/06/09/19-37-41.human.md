This is a discussion about tag creation behavior in Git, specifically whether duplicate tag attempts should be treated differently based on whether they point to the same commit. Hilco Wijbenga responds to Junio Hamano's position that the current "tag already exists" error is sufficient by proposing an alternative approach: making tag creation idempotent when the same commit is tagged again.

The key new idea is that if a user tries to create a tag that already exists pointing to the same commit, Git could silently succeed as a no-op rather than failing. This would automatically resolve the original issue by only failing when there's a true conflict (tagging a different commit). The email questions whether the first example (duplicate same-commit tag) should really be considered an error case at all.

This suggestion shifts the discussion from improving error messages to changing the fundamental behavior of tag creation. It presents a third option beyond the original proposal (enhanced errors) and Junio's preference (status quo). The thread now has three distinct positions on how Git should handle duplicate tags, with no clear consensus yet.
