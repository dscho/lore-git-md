This is a bugfix and user experience improvement for the `imap-send` authentication system, part of the larger v17 series adding OAuth2.0 support and fixing configuration parsing issues. The patch specifically addresses CRAM-MD5 authentication when OpenSSL is not available.

The change moves the OpenSSL availability check from a hard `die()` in the CRAM-MD5 implementation to a graceful failure path in the new `try_auth_method()` helper. When CRAM-MD5 is requested without OpenSSL support compiled in, users now get a clear error message rather than an abrupt crash. The implementation consolidates authentication failure handling by reusing the existing `try_auth_method()` infrastructure introduced earlier in the series.

Key technical changes include:
- Removes the `die()` path from the `cram()` function (now only compiled when OpenSSL is available)
- Makes `auth_cram_md5` NULL when OpenSSL is unavailable via `#define`
- Extends `try_auth_method()` to handle the OpenSSL dependency case with a clear error message
- Updates the CRAM-MD5 authentication path in `imap_open_store()` to use the new failure handling
