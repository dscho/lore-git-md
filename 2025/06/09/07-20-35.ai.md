This is a feature patch adding OAuth2.0 authentication support to `imap-send`, part of a larger series that has already received extensive review. The patch introduces two OAuth2.0 authentication methods (RFC-standard OAUTHBEARER and Google-proprietary XOAUTH2) with implementations for both OpenSSL and libcurl backends.

The technical implementation adds new helper functions `oauthbearer_base64()` and `xoauth2_base64()` that construct and encode the authentication strings according to their respective specifications. The patch handles both the direct OpenSSL-based IMAP connection path (with new authentication handlers) and the libcurl path (using `CURLOPT_XOAUTH2_BEARER`). Documentation is updated to explain OAuth2.0 usage for both Gmail and Outlook, including notes about credential helper integration.

Key technical details include:
- New `AUTH_OAUTHBEARER` and `AUTH_XOAUTH2` capability flags
- RFC5801/RFC7628 compliant OAUTHBEARER implementation with proper GS2 header formatting
- Google's XOAUTH2 protocol support with correct message formatting
- Shared credential handling between authentication methods
- Documentation updates showing configuration examples for both providers
- Backward compatibility maintained for existing auth methods

The patch builds on the series' earlier authentication framework work and appears well-integrated with the existing codebase. It follows the pattern established by the CRAM-MD5 implementation while adding the OAuth2-specific protocol handling. The documentation provides clear guidance for users transitioning to OAuth2.0 authentication.
