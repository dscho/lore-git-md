This is a follow-up bugfix in the pack-bitmap memory leak series that was recently merged. The patch addresses a remaining edge case where `roots_bitmap` could leak when `cascade_pseudo_merges_1()` succeeds, since the cleanup was previously only done on failure path. The fix unconditionally calls `bitmap_free(roots_bitmap)` after the cascade operation.

The patch adds a new test case in t5333 that specifically triggers this scenario by creating two commits (A and B), adding A to a pseudo-merge, then performing a boundary traversal from A to B. This exercises the success path where the leak would occur without the fix. The test verifies the commit count via `git rev-list --count` with bitmap traversal enabled.

This appears to be the final polish in the series, with the commit message receiving one last wording improvement (clarifying that `cascade_pseudo_merges_1()` uses the bitmap as a mutable reference without taking ownership). The change is straightforward and maintains the established pattern for ASAN-based leak detection in the test suite. With this fix, all identified memory leak cases in the boundary traversal code should now be properly handled.
