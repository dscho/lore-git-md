This is a bugfix for interactive rebase that addresses a confusing state when an invalid rebase.instructionFormat is provided. 

The patch fixes an issue where providing an invalid format string for rebase.instructionFormat would leave the repository in a half-initialized rebase state. Currently, when this happens, `git status` shows both normal branch status and confusing rebase state messages, even though the rebase failed immediately due to the invalid format.

The solution moves the script generation step (which validates the instruction format) before initializing the rebase state. This ensures that if the format is invalid, the rebase fails cleanly without leaving any state behind. The code restructuring is mostly straightforward, though the author notes the diff looks messy due to necessary control flow changes.

The patch includes a new test case that verifies the repository isn't left in a rebase state when an invalid instructionFormat is provided. The change appears well-considered and addresses a real usability issue, though the author acknowledges that a deeper fix might involve changing how get_commit_format() handles errors (currently it calls die()).
