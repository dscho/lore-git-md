This is a follow-up in the ongoing discussion about making tag creation idempotent when the requested tag already points to the same commit. Hilco Wijbenga clarifies their earlier proposal, explaining they intended Git to only silently succeed when the new tag request is *exactly* identical to the existing tag in all aspects (including tag type - lightweight vs annotated). This addresses Junio Hamano's concern about silently converting between tag types.

The email shows Hilco acknowledging they hadn't fully considered all tag functionality initially ("Clearly, I have not used everything that 'git tag' offers"). They refine their position to suggest that Git should perform a strict equality check on the entire tag specification before allowing idempotent behavior, which would prevent unintentional type conversions.

Junio's quoted response indicates he's not fundamentally opposed to the idempotency idea but highlights implementation challenges, particularly around annotated tags. The discussion remains focused on finding a technically sound solution that maintains consistent behavior across different tag types while improving the tagging experience. This refinement of the proposal moves the conversation forward by addressing the tag type preservation concern directly.
