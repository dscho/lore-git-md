Memory leak fix in the `imap-send` authentication flow. This patch addresses a specific memory leak in the CRAM-MD5 authentication path where the `response` buffer wasn't being freed if the socket write operation failed. The fix adds the missing `free(response)` call in the error path before returning, matching the existing cleanup that happens on the success path.

The change is straightforward - wrapping the error return with the memory cleanup. This is part of the larger `imap-send` series that has already seen extensive review, with this particular patch focusing on hardening the error handling. The fix maintains the existing behavior while properly cleaning up resources in all code paths.

Key technical details:
- Fixes a leak in `auth_cram_md5()` when `socket_write()` fails
- Affects only the OpenSSL backend's CRAM-MD5 implementation
- Follows the pattern already established in the success path
- Part of broader authentication method improvements in the series
