This is a bugfix patch in the `imap-send` authentication series, specifically addressing CRAM-MD5 handling when OpenSSL is not available. The patch improves error handling for CRAM-MD5 authentication by failing gracefully with a clear error message when OpenSSL support is missing, rather than attempting to proceed and dying.

The change moves the OpenSSL dependency check into a new `try_auth_method()` helper function that centralizes authentication failure handling. When CRAM-MD5 is requested without OpenSSL, it now prints an informative error and exits cleanly instead of crashing. The implementation maintains the existing behavior when OpenSSL is available while adding proper error paths for the unsupported case.

Key technical details include:
- Introduces `try_auth_method()` helper to consolidate authentication error handling
- Replaces direct `die()` with graceful error reporting via `fprintf(stderr)`
- Preserves all existing successful CRAM-MD5 paths when OpenSSL is present
- Maintains backward compatibility with the authentication flow
- Follows the series' pattern of hardening error handling in the IMAP authentication code

This patch builds on the series' ongoing work to standardize and improve authentication handling in `imap-send`, particularly around the OpenSSL-specific CRAM-MD5 method. It addresses a specific edge case that was previously handled poorly while keeping the core functionality intact.
