Memory leak fix in revision walking code with comprehensive test coverage. This v2 patch from Lidong Yan finalizes the solution for a memory leak in `prepare_show_merge()` where the `prune` array wasn't being freed after `parse_pathspec()`. The core fix remains unchanged from v1 - adding the missing `free(prune)` call in revision.c.

The significant addition in v2 is the comprehensive test case that exercises the `--merge` flag behavior during merge conflicts, following the approach that received Junio Hamano's explicit approval in the thread discussion. The test creates a realistic merge conflict scenario with:
- A three-branch setup (base, hello, goodbye) with conflicting changes
- A failed merge between hello and goodbye branches
- Verification of `git show --merge` behavior in this conflicted state

The test implementation uses modern Git commands like `git switch` for branch operations and explicitly checks merge states, providing thorough coverage of the codepath where the leak occurred. This addresses the earlier discussion about test methodology by moving beyond minimal reproduction to realistic usage patterns.

With both the technical fix and comprehensive test now in place, this patch appears ready for inclusion, having addressed all feedback from the previous round. The test case in particular serves as a model for future testing of merge-related functionality in the revision walking code.
