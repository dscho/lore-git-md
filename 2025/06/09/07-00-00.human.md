This is a user experience improvement suggestion for the tagging functionality in Git. Mirth Hickford points out that when attempting to create a tag that already exists, Git currently gives the same generic error message regardless of whether the new tag would point to the same commit as the existing one or a different one.

The current behavior simply says "fatal: tag 'hello' already exists" in both cases. The proposal suggests distinguishing these scenarios with more informative messages that show the commit hash the existing tag points to, making it immediately clear whether this is a harmless retagging attempt or a potentially problematic attempt to move the tag to a different commit.

This seems like a straightforward quality-of-life improvement that would help users better understand what's happening when they encounter tag conflicts. The change would be particularly useful in scripts or automated workflows where the distinction between same-commit and different-commit retagging might require different handling. The suggestion appears well-motivated and technically sound, though it would need to be implemented carefully to maintain backward compatibility with any scripts that might parse the error messages.
