Bugfix for a memory leak in `imap-send`'s CRAM-MD5 authentication. This is part of a larger series (v16) improving IMAP functionality, but stands alone as a straightforward fix.

The patch addresses a case where the `response` buffer allocated during CRAM-MD5 authentication wasn't being freed if the socket write operation failed. The fix adds the missing `free()` call in the error path, matching the existing cleanup that happens on the success path. While simple, it plugs a real memory leak that could occur during authentication failures.

This change fits into the series' broader work on authentication reliability (item #4 in the thread summary). The patch is small and focused, with a clear explanation of what it fixes. Since the core authentication changes have already received maintainer approval, this minor cleanup should be uncontroversial.
