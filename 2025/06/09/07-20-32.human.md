Bugfix for `imap-send` configuration parsing that has rendered the command unusable since Git 2.46.0. This is the first patch in a larger series adding OAuth2.0 support and folder management features to `imap-send`.

The patch fixes a regression introduced in commit 6d1f198f34 where the wrong struct field (`cfg->folder`) was being freed and NULLed when processing unrelated configuration variables like `imap.user` and `imap.pass`. This caused `git-imap-send` to fail completely for any configuration that set these common options. The fix properly clears each configuration field individually rather than incorrectly clearing the folder field in all cases.

The bug went unnoticed for some time, likely because most users prefer `git send-email` for mail sending. The patch is straightforward, correcting four instances of the same copy-paste error where `FREE_AND_NULL(cfg->folder)` was used instead of freeing the appropriate field (`user`, `pass`, `tunnel`, or `auth_method`).

This is a critical fix that should be merged quickly since it affects basic functionality. The rest of the series builds on this foundation to add new features, but this patch stands alone as a necessary bugfix regardless of whether the new functionality is adopted.
