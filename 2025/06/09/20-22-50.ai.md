This is a feature patch in the ongoing `imap-send` authentication improvements series (v18 05/10). It adds PLAIN authentication support for the OpenSSL backend, completing parity with the existing libcurl implementation.

The patch implements RFC 4616-compliant PLAIN authentication by adding a new `plain_base64()` helper that properly formats the NUL-delimited "user\0pass" string before base64 encoding. It introduces an `AUTH_PLAIN` capability flag and wires up the authentication flow through `auth_plain()` and `try_auth_method()`. The implementation handles memory allocation carefully with proper cleanup paths.

Key technical details include:
- New `AUTH_PLAIN` capability constant and string in `cap_list[]`
- `plain_base64()` helper implementing RFC 4616 format
- `auth_plain()` function integrating with the existing authentication framework
- Documentation update to list PLAIN as supported for both backends
- Memory safety with proper `xmallocz` allocations and `free()` calls

The change makes PLAIN authentication consistently available regardless of whether OpenSSL or libcurl is used, addressing a gap where OpenSSL previously only supported the basic IMAP LOGIN command. This is particularly useful for services that provide app passwords using PLAIN auth. The implementation follows the same pattern as other auth methods in the series, maintaining consistency with the existing codebase.
