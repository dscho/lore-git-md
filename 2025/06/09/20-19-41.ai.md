This is a technical discussion about tag creation behavior, specifically addressing whether to make tag operations idempotent when the target commit matches. Junio Hamano responds to Hilco Wijbenga's proposal to silently succeed when re-tagging the same commit, noting a key technical complication: the approach would need to handle differences between lightweight and annotated tags.

The email highlights that while lightweight tag idempotency would be straightforward, annotated tags introduce complexity because they contain additional metadata (signatures, messages) that would be silently discarded if the operation succeeded. This creates an inconsistency where `git tag` would behave differently for lightweight versus annotated tags, potentially violating user expectations.

Junio maintains a neutral stance on the proposal itself but surfaces this important technical consideration that wasn't fully addressed in previous discussion. The response implicitly suggests that any idempotency implementation would need to either:
1. Handle tag type matching (failing if types differ)
2. Clearly document the behavioral difference between lightweight and annotated cases
3. Or reconsider whether the complexity justifies changing the current behavior

The email moves the discussion forward by identifying a concrete technical hurdle for the idempotency proposal while remaining open to the general direction. It focuses specifically on implementation constraints rather than rehashing the philosophical debate about error messaging versus behavior changes.
