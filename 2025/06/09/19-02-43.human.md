This is a follow-up discussion in the ongoing `imap-send` feature series, specifically about the UX improvement to show port numbers in credential requests. The patch in question (v16 08/10) originally proposed always showing host:port combinations in credential prompts, even for default ports (993 for IMAPS, 143 for IMAP). Junio Hamano suggests this adds noise when the port is either unspecified (and thus using defaults) or explicitly set to the default value.

Aditya Garg clarifies their intent was to consistently show ports like `send-email` does, but acknowledges the explanatory note about default ports was confusing. The discussion now centers on how to implement Junio's suggestion to only show non-default ports in the host:port display. There's some back-and-forth about edge cases where users might explicitly specify default ports, with Junio proposing a conditional check that would omit the port displays in those cases.

This is a minor polish to an otherwise complete feature series, addressing how credential helpers display connection information to users. The change doesn't affect functionality, just the verbosity of the UI. The thread shows the typical Git project attention to detail in user experience, even for edge cases.
