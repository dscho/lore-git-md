This is a feature patch in the ongoing `imap-send` authentication improvements series, specifically adding PLAIN authentication support for the OpenSSL backend. The patch implements RFC 4616-compliant PLAIN authentication, which was previously only available when using libcurl.

The implementation introduces a new `plain_base64()` helper function that properly formats credentials in the NUL-delimited "user\0pass" format before base64 encoding, along with an `auth_plain()` handler that integrates with the existing authentication framework. The documentation is updated to reflect that PLAIN is now available for both backends.

Key technical details include:
- New `AUTH_PLAIN` capability flag in the IMAP protocol handling
- Proper memory management in `plain_base64()` with error checking
- Integration with the existing `try_auth_method()` framework
- Backward-compatible behavior when OpenSSL support is compiled out

This completes the PLAIN authentication support that was partially implemented (curl-only) in earlier versions of the series. The patch follows the established pattern seen in other authentication methods in the series (CRAM-MD5, OAUTHBEARER, XOAUTH2) while implementing the specific requirements of RFC 4616. The change is well-contained and maintains consistency with the broader authentication improvements being made to `imap-send`.
