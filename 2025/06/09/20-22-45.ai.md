This is the v18 cover letter for a feature and bugfix series targeting `imap-send`, now rebased on master to resolve a merge conflict. The series has undergone extensive review and iteration, with all technical issues addressed. Key components include:

1. **Critical bugfix** for a configuration parser regression since Git 2.46.0 that NULLed out `cfg->folder` when processing unrelated options (patch 1/10). This made `git-imap-send` unusable in affected versions.

2. **OAuth2.0 authentication support** via RFC-standard OAUTHBEARER and Google-proprietary XOAUTH2 protocols (patch 4/10), with proper credential handling for both OpenSSL and libcurl backends. Includes new helper functions `oauthbearer_base64()` and `xoauth2_base64()` implementing RFC5801/RFC7628 standards.

3. **PLAIN authentication** now properly implemented for OpenSSL backend (patch 5/10) using RFC4616-compliant NUL-delimited format.

4. **New features**:
   - `--folder` CLI option to override config (patch 6/10)
   - `--list` to show available IMAP folders (patch 7/10)
   - Destination folder display during send (patch 9/10)
   - Port numbers in credential prompts (patch 8/10)

5. **Memory leak fixes** in CRAM-MD5 authentication paths (patch 2/10) and error message corrections (patch 10/10). The series also standardizes error message formatting and adds graceful failure for unsupported auth methods.

The v18 rebase incorporates final fixes from Junio Hamano's review:
- Removes unnecessary variable initializations
- Fixes CRAM-MD5 error message to show auth method rather than host
- Cleans up port display logic in credential prompts

Technical implementation spans configuration parsing, authentication handlers, base64 utilities, and IMAP protocol handling. The series is now ready for integration with all review feedback addressed.
