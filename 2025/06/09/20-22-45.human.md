This is the v18 cover letter for a feature and bugfix series that makes `imap-send` usable again and adds OAuth2.0 support. The series has undergone extensive review over 18 iterations and is now ready for integration.

The patch series fixes several critical issues in `imap-send`, including a configuration parser regression introduced in Git 2.46.0 that made the command unusable (now fixed in patch 1). It also adds comprehensive OAuth2.0 authentication support (patches 4-5) for both RFC-standard OAUTHBEARER and Google's XOAUTH2 protocols, implemented for both OpenSSL and libcurl backends.

Other notable improvements include:
- New `--folder` command-line option to override the default IMAP folder (patch 6)
- `--list` option to show available IMAP folders (patch 7)
- Better user experience with destination folder display during send (patch 9)
- More informative credential prompts showing non-default ports (patch 8)
- Various memory leak fixes and error handling improvements

The series has been thoroughly reviewed by multiple Git maintainers including Junio Hamano, Jeff King, and Eric Sunshine. All technical issues have been resolved, and the v18 iteration incorporates final tweaks like fixing an error message that incorrectly referenced the host instead of the authentication mechanism. This represents a significant modernization of `imap-send` that makes it work reliably with modern email providers while maintaining backward compatibility.
