This is a final polish patch in the long-running `imap-send` series, addressing minor logging inconsistencies. The changes focus on error message formatting and capitalization:

1. Standardizes error messages to start with lowercase and omit periods (matching Git's style), while ensuring protocol names like "IMAP" and status codes like "OK" remain uppercase. For example, changes "Error: unable to connect to server." to "error: unable to connect to server".

2. Fixes an authentication error message that incorrectly showed the hostname instead of the auth method when an unknown mechanism is encountered, now properly displaying "unknown authentication mechanism: [method]".

3. Improves clarity in specific error cases, like changing "IMAP error: sending response failed" to specify it's the CRAM-MD5 response that failed.

The patch touches various parts of `imap-send.c` but makes no functional changes - it's purely about message formatting. As the final patch in the v18 series, it follows through on earlier review feedback about consistent messaging, complementing the major authentication and configuration fixes that were the focus of previous patches. The changes are straightforward and unlikely to be controversial given they align with established Git conventions.
