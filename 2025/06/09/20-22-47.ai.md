Bugfix in the `imap-send` series addressing a memory leak in CRAM-MD5 authentication. This is part of a larger v18 series that introduces OAuth2.0 support and fixes various IMAP-related issues.

The patch specifically fixes a case where memory allocated for the CRAM-MD5 response would leak if the socket write operation failed. The `response` buffer is now properly freed in the error path before returning. This complements earlier memory management improvements in the series, particularly around authentication handling.

The change is small but important - it plugs a leak that could occur during failed authentication attempts. The fix follows the pattern established elsewhere in the code where resources are cleaned up before error returns. This patch maintains the series' focus on robust error handling and memory management in the IMAP authentication pathways.

Technical details: The leak occurs in `auth_cram_md5()` when `socket_write()` fails to send the full response. The patch adds the missing `free(response)` in this error path, matching the cleanup that already happens in the success path. The change affects the OpenSSL backend's CRAM-MD5 implementation.
