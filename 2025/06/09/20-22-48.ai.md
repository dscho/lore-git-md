This is part of the ongoing `imap-send` feature and bugfix series, specifically addressing CRAM-MD5 authentication handling. The patch improves error handling when CRAM-MD5 authentication is requested without OpenSSL support available.

The change moves the OpenSSL availability check from a compile-time error (via `die()`) to a runtime check that gracefully fails with an informative message. The key technical changes are:

1. Replaces the `cram()` function's `die()` with a NULL `auth_cram_md5` function when OpenSSL is unavailable
2. Introduces a new `try_auth_method()` helper that centralizes authentication failure handling
3. Updates the CRAM-MD5 authentication path to use this helper, which now properly checks both server capabilities and OpenSSL availability

The patch maintains the existing behavior when OpenSSL is present while providing clearer error messages when it's not. This is part of a larger effort to make `imap-send` more robust and user-friendly, particularly around authentication methods. The change is well-contained and follows the pattern established by other authentication methods in the series.
