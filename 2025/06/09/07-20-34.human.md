This is a bugfix patch in the `imap-send` authentication series, specifically addressing CRAM-MD5 support when OpenSSL is not available. 

The change improves error handling when users attempt CRAM-MD5 authentication without OpenSSL compiled in. Previously, this would trigger a fatal `die()` call, but now it provides a graceful error message and exits cleanly. The patch factors out authentication method checking into a new `try_auth_method()` helper function that handles both capability checking and OpenSSL availability.

This is part of a larger v16 series that adds OAuth2.0 support and improves IMAP functionality. The change is straightforward and well-contained, just moving some error handling logic around while maintaining the same behavior when OpenSSL is present. The patch has a clear commit message explaining the motivation and maintains backward compatibility.

The implementation looks solid - it removes the old direct `die()` call and replaces it with proper error path handling that matches the rest of the authentication flow. This is a small but meaningful improvement in user experience for those who might accidentally configure CRAM-MD5 without the required OpenSSL support.
