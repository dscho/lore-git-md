This thread discusses improving Git's tagging functionality by making error messages more informative when attempting to create a tag. The current behavior shows a generic "tag already exists" message regardless of whether the existing tag points to the same commit or a different one. The proposed change would modify the error message to include the commit hash the existing tag references, helping users distinguish between harmless duplicates and potentially serious conflicts.

The suggestion specifically targets the tag creation logic in `builtin/tag.c`, likely requiring changes to the `create_tag()` function. The improvement would be particularly useful in scripts and automated workflows where the distinction between duplicate operations and actual conflicts matters. The proposal appears well-considered and addresses a clear pain point in tag management without introducing obvious downsides.
