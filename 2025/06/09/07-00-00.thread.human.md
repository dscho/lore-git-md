The thread explores how Git should handle attempts to create duplicate tags, with three approaches under consideration. The original proposal suggested showing more detailed error messages to distinguish between harmless duplicates (same commit) and dangerous ones (different commits), but Junio Hamano argued the current simple "tag exists" message is adequate since users can investigate manually. Hilco Wijbenga then proposed making tag creation idempotent when the tag already points to the same commit, which sparked discussion about how this would interact with annotated tags (which carry additional signatures and messages).

Hilco has now refined the idempotency proposal to require exact matches - including matching tag types and, for annotated tags, all metadata - addressing Junio's concern that the original approach might silently convert between tag types. This makes the proposal more robust but also more complex to implement. Junio maintains that the current behavior may be sufficient, while the discussion continues to weigh the tradeoffs between improved error messages, idempotent behavior with exact matching, and the status quo. The key question remains whether the added complexity of full tag comparison justifies changing the current behavior, particularly for scripting use cases that may rely on the existing error handling.
