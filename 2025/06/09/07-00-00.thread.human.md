This thread explores how Git should handle attempts to create duplicate tags, with three main approaches under discussion. The focus began with improving error messages to better distinguish between harmless (same commit) and dangerous (different commit) tag overwrites, but has expanded to consider deeper behavioral changes.

Junio Hamano, the Git maintainer, has now proposed a technical solution that makes lightweight tag creation idempotent - allowing repeated creation of identical tags without requiring --force, while maintaining the existing stricter behavior for annotated tags. This represents a middle path between Mirth Hickford's simpler error message improvements and Hilco Wijbenga's more comprehensive attribute comparison approach.

Key points:
- Junio's patch implements partial idempotency with minimal code changes, focusing only on lightweight tags pointing to the same commit
- The solution introduces an asymmetry between lightweight and annotated tag behavior
- It doesn't address the original goal of improved error messaging for dangerous cases
- The implementation appears clean and well-tested, though it represents a behavioral change rather than just message improvements

The discussion continues to weigh these tradeoffs: whether to focus on clearer warnings (Mirth), implement partial idempotency (Junio), or pursue comprehensive tag equivalence checking (Hilco). Junio's proposal may represent a pragmatic compromise, though it notably shifts the thread's direction from messaging to behavior changes.
