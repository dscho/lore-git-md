The thread explores making lightweight tag creation idempotent - allowing recreating tags pointing to the same commit without requiring `--force`. The core implementation (a small 2-line change plus tests) has been proposed based on Junio Hamano's technical rationale that lightweight tags can safely be recreated since they store no metadata, while annotated/signed tags must still require `--force` due to their timestamp and identity information.

Randall Becker supports this approach for his workflow needs, and Junio endorses the technical distinction. However, Justin Tobler raises a new consideration: while technically sound, the change might remove useful feedback for users who want to know whether a tag was actually created versus already existing, particularly in automation scenarios like conditional tag pushing. This doesn't challenge the technical merits but highlights a workflow impact that wasn't previously discussed.

The original goal of improving error messages for duplicate tags (distinguishing same-commit vs different-commit cases) remains unaddressed by this lightweight idempotency implementation. The thread now balances three considerations: the technical correctness of the idempotency approach, the original error message improvements, and this new feedback about scriptability impacts. The patch itself appears ready from a technical standpoint, leaving open questions of whether to combine it with message improvements and how to handle the newly raised workflow consideration.
