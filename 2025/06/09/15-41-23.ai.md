Feature patch adding OAuth2.0 authentication support to `imap-send`. This is patch 4/10 in the v17 series, which has already addressed most review feedback and is in final stages. The patch implements both RFC-standard OAUTHBEARER and Google-proprietary XOAUTH2 authentication mechanisms, with support for both OpenSSL and libcurl backends.

The implementation introduces two new helper functions: `oauthbearer_base64()` for RFC5801/RFC7628 compliant OAUTHBEARER tokens and `xoauth2_base64()` for Google's XOAUTH2 format. Both handle proper base64 encoding of the authentication strings with NUL delimiters. The patch updates documentation to explain OAuth2.0 usage for both Gmail and Outlook, noting that Outlook only supports XOAUTH2. It also adds proper credential handling in the libcurl backend via `CURLOPT_XOAUTH2_BEARER`.

Key technical details include the new `AUTH_OAUTHBEARER` and `AUTH_XOAUTH2` capability flags, the auth method dispatch in `imap_open_store()`, and the careful handling of password vs. token credentials in `setup_curl()`. The documentation changes provide clear examples for both authentication methods and note the interaction with credential helpers. This appears to be a well-considered implementation of a modern authentication protocol, completing the authentication method coverage started with earlier patches in the series.
