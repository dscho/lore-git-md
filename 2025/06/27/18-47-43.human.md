This is a response to a Windows DFS network drive regression report, pointing the original reporter toward existing Git-for-Windows resources.

Brian m. carlson responds to Erwan Leroy's report of Git failing with "Permission denied" errors when writing config files on DFS-mounted network drives in Git versions 2.36+. While acknowledging the Windows-specific nature of the issue, carlson notes they cannot personally help as a non-Windows user. 

The response suggests checking the Git for Windows issue tracker, specifically pointing to issue #3825 as potentially relevant case. As an alternative workaround, carlson proposes using Windows Subsystem for Linux with Unix metadata support, which might handle the DFS paths more reliably than MSYS2. The reply helpfully directs the reporter toward the Windows-specific channels (Git for Windows tracker and maintainer) while providing one potential technical workaround path. The tone is supportive while appropriately deferring to Windows experts for the core issue resolution.
