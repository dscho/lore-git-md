Performance optimization patch introducing infrastructure for multi-pathspec bloom filters. This is the first of two patches in a series addressing the limitation where Git's bloom filters only accelerate single pathspec queries (like `git log -- file1`). The patch introduces `struct bloom_keyvec` to manage multiple bloom keys, replacing the direct `struct bloom_key *` usage in `rev_info`. New helper functions handle keyvec creation/destruction and multi-key bloom filter checking while maintaining the existing single-pathspec optimization path.

The changes are well-contained to bloom.c/h and revision.c/h, with careful attention to memory management and API design. The implementation follows Junio Hamano's feedback from v1, using FLEX_ARRAY for keys and tightening variable scoping. While this patch only enables single pathspec optimization (with bloom_keyvec_nr limited to 0 or 1), it lays the groundwork for the follow-up patch that will handle multiple pathspecs. The changes appear thorough and maintain the existing performance characteristics while enabling future improvements.
