Windows regression investigation update showing version-specific failures. Jörg Hohwiller reports that downgrading to Git 2.46.0 resolves multiple issues that persisted through newer versions (2.48.1 and 2.50.0), including: (1) `git clone` failures with "connection reset by peer" errors at random progress points (34-60% completion), (2) continued ref lock errors during `remote update` operations showing SHA mismatches, and (3) installation problems with the Git for Windows SDK. The working 2.46.0 version successfully cloned the problematic repository on first attempt, while newer versions consistently failed across 20+ attempts. Hohwiller suspects either bundled OpenSSL issues or repository corruption from prior failed operations as potential causes, though the version-specific reproducibility points to a regression. The investigation remains hampered by inability to collect debug traces due to build system issues (missing Makefile despite config.mak) and the destructive nature of the workaround (fresh clone losing diagnostic state). This adds to the thread's known issues with lock files, reflog failures, and ref updates, now with version-boundary clarity.
