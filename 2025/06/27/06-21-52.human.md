This is a performance optimization patch series for Git's pathspec bloom filters, addressing the limitation where bloom filters currently only accelerate single pathspec queries. The series builds on previous discussion and implements Junio Hamano's suggested improvements from v1.

The cover letter explains the motivation well: while Git currently optimizes revision traversal for single pathspec elements (like `git log -- file1`), multiple pathspecs (`git log -- file1 file2`) don't get the same bloom filter acceleration. The series introduces a `bloom_keyvec` structure to manage multiple bloom keys and modifies the bloom filter checking logic to handle them while preserving the fast path for single pathspecs.

The key improvement over v1 is adopting Junio's API suggestions - using FLEX_ARRAY for cleaner memory management, tighter variable scoping, and fixing style issues. Performance testing shows the optimized version now matches the speed of running separate single-pathspec queries. The implementation looks solid, with thorough test updates in t4216-log-bloom.sh.
