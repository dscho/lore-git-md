Performance optimization for bloom filters in revision traversal, part 2/2 of a series addressing multiple pathspec handling. This patch removes the restriction that prevented bloom filters from being used with multiple pathspecs (like `git log -- file1 file2`), completing the optimization work started in patch 1/2.

The key changes include:
- Removing the `spec->nr > 1` check in `forbid_bloom_filters()`
- Modifying `prepare_to_use_bloom_filter()` to initialize a `bloom_keyvec` for each pathspec item
- Updating `check_maybe_different_in_bloom_filter()` to check all pathspecs' bloom keys (returning true if any match)
- Adding `release_revisions_bloom_keyvecs()` cleanup function
- Updating t4216 tests to verify bloom filter usage with multiple pathspecs

The implementation follows Junio Hamano's feedback from v1, with proper memory management and test coverage. The test changes flip expectations from "not used" to "used" for multiple pathspec cases, verifying the optimization activates correctly. Benchmark results in the cover letter show this achieves performance parity with separate single-pathspec invocations.

This completes the technical implementation of the series, with test coverage being the primary remaining consideration before merging. The changes touch core bloom filter handling in revision.c and the associated test file, maintaining the single-pathspec fast path while extending support to multiple pathspecs.
