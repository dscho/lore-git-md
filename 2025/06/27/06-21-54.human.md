Performance optimization patch completing a series to enable Git's pathspec bloom filters for multiple pathspec queries (like `git log -- file1 file2`). This second patch removes the restriction that previously prevented bloom filter usage with multiple pathspecs, modifying the bloom filter preparation and checking logic to handle multiple pathspec items efficiently.

The changes include:
- Removing the `spec->nr > 1` check that disabled bloom filters for multiple pathspecs
- Adding loops to initialize and check bloom filters for each pathspec item
- Introducing a cleanup function `release_revisions_bloom_keyvecs()` to manage memory
- Updating tests to verify bloom filter usage with multiple pathspecs matches non-bloom results

This builds on the `bloom_keyvec` infrastructure introduced in patch 1/2, with the implementation having already incorporated Junio Hamano's feedback from v1 regarding API design and test coverage. Benchmark results show the optimized version now matches the performance of separate single-pathspec invocations. The patch appears well-tested and completes the performance improvement goal identified in the original report.
