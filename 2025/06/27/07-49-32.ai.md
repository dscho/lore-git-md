This is a feature proposal introducing a new `git refs list` subcommand as part of a broader effort to consolidate ref-related operations under a unified `git refs` command. The RFC comes from a GSoC participant and presents the first step in what appears to be a planned multi-phase refactoring of Git's reference handling.

The patch series creates a new `git refs list` command that currently mirrors `git for-each-ref` exactly, reusing its internal implementation while providing a new entry point under the proposed consolidated namespace. The author emphasizes this is a conservative first step that maintains full backward compatibility while establishing the architectural pattern for future consolidation. A test file `t/t1461-refs-list.sh` verifies the new command's behavior matches `for-each-ref` by running the existing test suite with command substitution.

Key technical details include the new subcommand being implemented in `builtin/refs.c` with corresponding documentation in `Documentation/git-refs.adoc`. The proposal explicitly leaves `for-each-ref` untouched for now, positioning this as groundwork for potential future evolution where the consolidated interface could be refined by deprecating legacy options or adding new features that wouldn't fit the old command structure.

The RFC invites discussion about which `for-each-ref` features should carry over to the new interface and what improvements might be worth considering, particularly seeking feedback from users who rely on the command in scripts. The approach appears well-considered, with clear attention to backward compatibility and testing, though the long-term vision for ref command unification remains open for community input.
