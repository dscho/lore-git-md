- Minimal `cmd_refs_list()` implementation (8 lines) directly wrapping shared helper
- Current wildcard behavior inherited from `for-each-ref` where `**` not between slashes (`refs/heads/m**`) silently converts to single `*` (matching only top-level branches starting with 'm')

Open questions and new discussion points:
- Wildcard matching behavior shows inherent ambiguity in pattern matching rules (WM_PATHNAME mode in wildmatch.c)
- Phillip Wood identifies key limitation: current behavior makes it impossible to predict from pattern alone whether matching will be prefix-based or exact
- No syntax exists to force exact matching (while trailing slash can force prefix matching)
- This creates problems for scripting use cases needing deterministic behavior
- Discussion confirms this is a known limitation of the current `for-each-ref` compatibility approach
- Team previously agreed to maintain current behavior for compatibility, but this exchange documents practical consequences
- No concrete changes proposed yet - discussion serves to document edge case behavior
