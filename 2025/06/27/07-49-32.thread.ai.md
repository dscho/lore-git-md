RFC patch series proposing ref` command consolidation via `git refs list` with performance considerations. Authored by GSoC participant Meet Soni with mentoring. Initial version (205 lines) establishes `builtin/refs.c` reusing ref-filter logic from `git for-each-ref` with all existing functionality plus `--include-root-refs` for HEAD/pseudorefs. Test infrastructure runs existing suite via `GIT_REFS_LIST_CMD=refs list`.

Maintainer Junio C Hamano questions justification, advocating wrapper implementation (like `git branch`/`tag`) to avoid code duplication. Meet Soni defends discoverability through `git refs` hierarchy. Hamano remains skeptical about adding potentially divergent commands, citing `git checkout` split precedent. Shejialuo agrees with wrapper approach, requiring redesign.

Patrick Steinhardt introduces performance critique: demonstrates 6.65x speed difference in Chromium repo when omitting `%(objecttype)` from default format (150ms -> 22ms), arguing new command could optimize this while maintaining shared infrastructure. Benchmark shows ODB lookups for object types are often unnecessary overhead.

Documentation improvements (Jean-Noël Avila) proceed independently, with initial minimal docs expanded via follow-ups standardizing option syntax. Hamano reviews `git-for-each-ref` man page focusing on consistency (`_<placeholder>_` convention), Jean-Noël Avila to address remaining style in v2.
