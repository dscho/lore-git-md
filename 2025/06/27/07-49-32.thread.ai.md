RFC patch series proposing `git refs list` subcommand as first step in ref command consolidation effort. Authored by GSoC participant Meet Soni with mentoring from experienced contributors. Initial version exactly mirrors `git for-each-ref` functionality (205 lines added) while establishing new `builtin/refs.c` infrastructure, reusing ref-filter logic with all existing features: pattern matching, sorting, formatting, and filters (`--points-at`, `--merged`, `--contains`). Includes `--include-root-refs` flag for HEAD/pseudoref handling. Test infrastructure in second patch runs existing `for-each-ref` suite against new command via `GIT_REFS_LIST_CMD=refs list`.

Maintainer Junio C Hamano questions justification for new command, suggesting wrapper implementation (like `git branch`/`tag` listings) could achieve discoverability without code duplication. Author Meet Soni clarifies primary motivation is improved discoverability through `git refs` hierarchy, walking back earlier rationales about legacy options or new features. Maintainer emphasizes wrapper approach would satisfy discoverability while avoiding maintenance burden of parallel implementations. Open questions center on interface design philosophy - whether consolidation under `git refs` justifies new command given maintainer preference for wrapper pattern.
