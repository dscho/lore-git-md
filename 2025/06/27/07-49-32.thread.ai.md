RFC patch series introducing `git refs list` as a thin wrapper around `git for-each-ref`, authored by GSoC participant Meet Soni with mentoring. Current v2 redesign addresses maintainer Junio C Hamano's concerns by eliminating code duplication from v1 while preserving discoverability goals. Implementation forwards all arguments through new `cmd_refs_list` in `builtin/refs.c` to `cmd_for_each_ref`, ensuring identical behavior.

Technical changes include significant documentation restructuring with shared options extracted to `refs-list-options.adoc` for consistency between commands. New `REFS_LIST_USAGE` constant defines syntax while modified `cmd_for_each_ref` detects wrapper invocation. Preserves all existing functionality including `--include-root-refs` for HEAD/pseudorefs. Test suite reuses existing `for-each-ref` tests via `GIT_REFS_LIST_CMD` substitution.

Performance considerations from Patrick Steinhardt (6.65x speed difference when omitting `%(objecttype)`) remain deferred. Documentation standardization progresses with Jean-Noël Avila addressing shared option syntax and man page conventions (`_<placeholder>_`). Maintainer skepticism about command proliferation appears addressed by wrapper pattern.

Open questions: whether future iterations should optimize defaults (reducing ODB lookups) while preserving `for-each-ref` behavior, and potential migration of additional ref-related commands under `git refs` hierarchy. Current approach establishes namespace infrastructure without breaking changes, positioning wrapper for controlled behavioral divergence where justified. Final maintainer evaluation pending.
