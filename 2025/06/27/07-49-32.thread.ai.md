RFC patch series introducing `git refs list` as a thin wrapper around `git for-each-ref`, now at v5 in final polishing stage. Authored by GSoC participant Meet Soni with mentoring from Patrick Steinhardt, the series consolidates ref listing functionality under `git refs` while preserving behavior through shared core logic.

Implementation establishes architectural foundation with:
- New `for-each-ref.h` header containing shared `for_each_ref_core()` helper and `COMMON_USAGE_FOR_EACH_REF` macro
- Both `cmd_for_each_ref()` and new `cmd_refs_list()` as thin wrappers calling the shared helper
- Usage string synchronization via header-based sharing
- Follows Junio Hamano's preferred helper function pattern with usage strings passed as parameters
- Documentation refactoring moving option descriptions to shared `for-each-ref-options.adoc` (79 lines) via Asciidoc include, maintaining identical rendered output

Key technical elements:
- Core ref listing logic in `for_each_ref_core()` with `strvec` argument construction
- `COMMON_USAGE_FOR_EACH_REF` macro consolidates shared option documentation
- Test infrastructure (t1461-refs-list.sh) with shared `for-each-ref-tests.sh` library
- Fixed pre-existing man page inconsistency for `for-each-ref` via patch 2/6 which:
  - Moves full option list into `COMMON_USAGE_FOR_EACH_REF` macro
  - Updates usage string array to use macro
  - Removes 'known breakage' marker from t0450 documentation test
- Resolved t0450 documentation test breakage (now split into separate commit in v5)
- Replaces hardcoded `git for-each-ref` calls with `$git_for_each_ref` variable in tests

Series structure in v5:
1. Documentation refactoring - extracts option documentation into shared `for-each-ref-options.adoc` via include directive
2. New commit fixing `for-each-ref` usage string alignment with man page
3. Core logic extraction to `for_each_ref_core()` helper
4. `refs list` command implementation
5-6. Test refactoring (shared infrastructure) and new tests for `refs list`

Pattern matching behavior remains settled with single-asterisk (`*`) semantics as "anchored at hierarchy boundary" (e.g., `refs/heads/m*` matches `morning` but not `mid/night`), preserving `for-each-ref` compatibility. Double-asterisk (`**`) support for cross-hierarchy matching explicitly deferred to future work per agreement between Junio Hamano and Phillip Wood.

Current status shows all major architectural issues resolved across five versions. Changes since v4:
- Split test fix into separate commit (patch 2/6) as requested in reviews
- Maintained all architectural improvements from previous iterations
- No new technical concerns raised in this version
