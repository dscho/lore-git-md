RFC patch series introducing `git refs list` as a thin wrapper around `git for-each-ref`, now at v4 with all major architectural issues resolved and in final review. Authored by GSoC participant Meet Soni with mentoring from Patrick Steinhardt, the series consolidates ref listing functionality under `git refs` while preserving behavior through shared core logic.

Implementation establishes architectural foundation with:
- New `for-each-ref.h` header containing shared `for_each_ref_core()` helper and `COMMON_USAGE_FOR_EACH_REF` macro
- Both `cmd_for_each_ref()` and new `cmd_refs_list()` as thin wrappers calling the shared helper
- Usage string synchronization via header-based sharing
- Follows Junio Hamano's preferred helper function pattern with usage strings passed as parameters

Key technical elements:
- Core ref listing logic in `for_each_ref_core()` with `strvec` argument construction
- `COMMON_USAGE_FOR_EACH_REF` macro consolidates shared option documentation
- Test infrastructure (t1461-refs-list.sh) with shared `for-each-ref-tests.sh` library
- Fixed pre-existing man page inconsistency for `for-each-ref`
- Resolved t0450 documentation test breakage
- Replaces hardcoded `git for-each-ref` calls with `$git_for_each_ref` variable in tests

Series structure in v4:
1. Documentation refactoring - extracts option documentation into shared `for-each-ref-options.adoc`
2. Core logic extraction to `for_each_ref_core()` helper
3. `refs list` command implementation
4. Test refactoring (shared infrastructure)
5. New tests for `refs list`

Pattern matching behavior conclusively settled with single-asterisk (`*`) semantics remaining as "anchored at hierarchy boundary" (e.g., `refs/heads/m*` matches `morning` but not `mid/night`), preserving `for-each-ref` compatibility. Double-asterisk (`**`) support for cross-hierarchy matching explicitly deferred to future work per agreement between Junio Hamano and Phillip Wood, with Meet Soni confirming this separation of concerns.
