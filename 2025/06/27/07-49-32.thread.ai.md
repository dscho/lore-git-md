RFC patch series proposing `git refs list` subcommand as first step in ref command consolidation effort. Authored by GSoC participant with mentoring from experienced contributors, this initial version exactly mirrors `git for-each-ref` functionality while establishing new `builtin/refs.c` infrastructure (205 lines added across two files). Implementation reuses `for-each-ref` ref-filter logic, supporting all existing features: pattern matching, sorting, formatting, and filters (`--points-at`, `--merged`, `--contains`). Introduces `--include-root-refs` flag for explicit HEAD/pseudoref handling.

Test infrastructure added in second patch creates `t/t1461-refs-list.sh` that runs existing `for-each-ref` test suite against new command via `GIT_REFS_LIST_CMD=refs list` parameterization. Documentation review from Jean-Noël Avila provides detailed feedback on man page formatting, with follow-up patch now improving `git-for-each-ref.adoc` directly: standardizing option syntax (fixing spacing around pipe characters in alternatives like `--shell | --perl`), making `--format` and merged/contains options consistently use `[=...]` syntax, and rewording descriptions to be more concise and imperative (e.g., changing "If `--stdin` is supplied" to "The list of patterns is read"). Maintainer Junio C Hamano had previously suggested these upstream documentation improvements would benefit both commands.
