Documentation review follow-up in the `git refs list` RFC thread. Jean-Noël Avila points out a formatting issue in the new command's man page where alternative options (`--shell|--perl|...`) should have spaces around the pipe characters. Maintainer Junio C Hamano notes this appears to be copied from `git for-each-ref` documentation and suggests the reviewer submit a correction patch against the original source file rather than just commenting on the new command's docs.

This is a minor documentation nit in the context of the larger discussion about whether the new `git refs list` command should exist at all. The maintainer's response reinforces his earlier skepticism about the value of duplicating `for-each-ref` functionality, implying the documentation issues might be better addressed at the source rather than in a new command's man page. The exchange shows the RFC is receiving detailed review but also facing significant questions about its fundamental premise.
