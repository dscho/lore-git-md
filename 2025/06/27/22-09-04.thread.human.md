This thread addressed a memory leak in Git's `send-pack` command, specifically in how it handles the `extra_have` oid array during push operations. The issue was originally reported by Jacob Keller, who identified that pushes involving alternate object stores (created via `--reference` clones) could leak a 2160-byte allocation when processing remote refs pointing to objects not in the target repository.

The initial fix added cleanup for the `extra_have` array, mirroring existing patterns for similar resources. Junio C Hamano then refined this by pointing out that the cleanup needed to cover early exit paths when `match_push_refs()` fails. His solution consolidated all resource release under a single `cleanup` label, ensuring proper handling of the `extra_have` array along with refs, refspecs, and shallow arrays in all scenarios. Jacob Keller confirmed this refinement as correct and complete, noting it maintains the same observable behavior while being more robust.

While test coverage for alternate-store push scenarios remains outstanding (and was acknowledged as out of scope for this fix), the technical discussion has reached consensus. The thread demonstrates Git's careful attention to resource management, with both the original reporter and maintainer collaborating to ensure comprehensive cleanup paths.
