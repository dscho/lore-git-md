This thread addressed a memory leak in Git's `send-pack` command, where the `extra_have` oid array wasn't being properly freed during push operations involving alternate object stores (created via `--reference` clones). The issue was originally reported by Jacob Keller, who identified a 2160-byte allocation leak when processing remote refs pointing to objects not in the target repository.

The fix followed a thorough review process with contributions from multiple experienced developers. The initial solution added cleanup for the `extra_have` array, mirroring existing patterns for the shallow oid array. Junio C Hamano then refined this by proposing consolidated resource cleanup under a single label to handle all exit paths, including early failures in `match_push_refs()`. Jeff King (Peff) later verified that this approach was safe, confirming that `remote_refs` remains valid for cleanup even after `match_push_refs()` fails, as it's initialized earlier by `get_remote_heads()`. Jacob Keller's latest message reinforces this analysis, providing final confirmation of the solution's correctness.

While all agree that expanded test coverage for alternate-store push scenarios would be beneficial, the core fix has now been thoroughly vetted. The thread demonstrates Git's collaborative review culture, with multiple experts examining edge cases to ensure robust memory management in this corner of the push machinery.
