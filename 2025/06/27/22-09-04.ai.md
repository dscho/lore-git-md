Bugfix addressing a memory leak in `send-pack`'s extra_have oid array. This follows up on a previous cleanup that missed freeing this array while handling the shallow oid array. The leak was detected during routine use with sanitizers enabled, showing a 2160-byte allocation from `oid_array_append` during remote ref processing. The patch adds a single `oid_array_clear(&extra_have)` call alongside the existing cleanup code.

The commit notes this wasn't caught by t5539 tests likely because they don't exercise the code paths that populate extra_have. The stack trace shows the allocation originates in `process_ref` during remote head processing, flowing through `cmd_send_pack`. The fix is straightforward - mirroring the existing shallow array cleanup pattern - though the author didn't investigate why tests don't trigger this path. This appears to be a genuine leak that would affect real-world usage when the extra_have array gets populated during push operations.
