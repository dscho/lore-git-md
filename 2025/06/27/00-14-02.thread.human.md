This thread reports a regression in Git versions 2.36+ where operations fail with "Permission denied" when writing config files on Windows DFS-mounted network drives, while working correctly on direct UNC paths and in Git 2.21 and earlier. The issue occurs during lock file operations when renaming `.git/config.lock` to `.git/config`.

Erwan Leroy originally reported the problem, with Brian m. carlson suggesting it might relate to Git for Windows issue #3825 and recommending engagement with Git for Windows maintainer Johannes Schindelin (Dscho) or using WSL as a workaround. D. Ben Knoble contributed by pointing to Git's release notes to help investigate changes in the regression window between 2.21 and 2.36.

Schindelin has now responded, noting the "Permission denied" error is unexpected given the timing of Git's POSIX-semantics rename() emulation on Windows. He provided investigation resources including archived Git for Windows versions and release notes, while seeking clarification on whether the issue specifically occurs with DFS paths (like `Y:\` drive) versus direct UNC paths (`\\atl-xx\Basecamp`). The core issue remains unresolved, with the WSL workaround still the only immediate solution while investigation continues into the Windows-specific filesystem behavior causing this regression.
