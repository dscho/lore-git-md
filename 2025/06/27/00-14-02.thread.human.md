This thread documents a Windows-specific regression where Git versions 2.36+ fail with "Permission denied" errors when writing config files on DFS-mounted network drives, while working correctly on direct UNC paths and in Git 2.21 and earlier. The issue occurs during the final step of config file operations when renaming `.git/config.lock` to `.git/config`.

Erwan Leroy originally reported the problem, with Brian m. carlson suggesting it might relate to Git for Windows issue #3825 (though not confirming it's the same root cause) and proposing to engage Git for Windows maintainer Johannes Schindelin through their issue tracker. D. Ben Knoble has since contributed by pointing to Git's release notes as a resource for investigating changes between the affected versions, though no root cause has been identified yet. 

The discussion remains focused on Windows-specific behavior, with the Git for Windows issue serving as a reference point. While no solution has been proposed, participants are working to narrow down the regression window and gather information that could help diagnose the underlying problem. The thread remains open with the DFS config file locking issue unresolved.
