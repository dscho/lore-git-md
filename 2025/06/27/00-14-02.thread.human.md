This thread reports a Windows-specific regression where Git versions 2.36 and above fail with "Permission denied" errors when writing to config files on DFS-mounted network drives, while versions 2.21 and below work correctly. The issue occurs during operations that create lock files, specifically when renaming `.git/config.lock` to `.git/config`. 

Erwan Leroy, the reporter, has provided clear reproduction steps showing the problem occurs consistently on multiple Windows workstations when using DFS paths, though direct UNC path access still works. The regression window has been narrowed to changes made between Git 2.21 and 2.36, but the exact cause remains unknown - it may relate to changes in Git's filesystem handling on Windows or its interaction with DFS path resolution and locking mechanisms. No workaround has been identified yet, and the report is seeking input from Windows filesystem experts to diagnose the root cause.
