This thread reports a regression in Git versions 2.36+ where operations fail with "Permission denied" errors when writing config files on Windows DFS-mounted network drives, while working fine with direct UNC paths and in Git 2.21 and earlier. The issue appears during lock file operations when renaming `.git/config.lock` to `.git/config`.

Erwan Leroy originally reported the problem, which seems specific to DFS path resolution and locking behavior on Windows. Brian m. carlson has responded by pointing to a potentially related Git for Windows issue (#3825) and suggested two possible next steps: either engaging with Git for Windows maintainer Johannes Schindelin (Dscho) through their issue tracker, or as a temporary workaround using Windows Subsystem for Linux (WSL) with Unix metadata support to bypass the problematic MSYS2 path handling.

The thread remains open with no definitive solution yet, but now has a concrete reference point in the Git for Windows tracker for further investigation. The response notes this appears to be Windows-specific behavior rather than a core Git issue, though the exact root cause remains unidentified.
