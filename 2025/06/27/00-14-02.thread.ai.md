Windows DFS-mounted network drive regression report from Erwan Leroy: Git versions 2.36+ fail with "Permission denied" when writing config files on DFS paths (while working on direct UNC paths and in Git <=2.21). The issue manifests during lock file operations when renaming `.git/config.lock` to `.git/config`, with the regression window between 2.21 and 2.36. Brian m. carlson responded by pointing to Git for Windows issue #3825 as a potentially related DFS problem, though not confirming it's the same root cause. Suggested paths forward include engaging Git for Windows maintainer Johannes Schindelin (Dscho) through their issue tracker, or using WSL with Unix metadata as a workaround to bypass MSYS2 path handling. The response notes this appears Windows-specific rather than a core Git issue, but provides no definitive solution. The thread remains open with the Git for Windows issue reference as a starting point for further investigation. No root cause identified yet for the config file locking behavior on DFS paths.
