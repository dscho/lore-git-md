Windows DFS-mounted network drive regression report from Erwan Leroy: Git versions 2.36+ fail with "Permission denied" when writing config files on DFS paths (while working on direct UNC paths and in Git <=2.21). The issue manifests during lock file operations, specifically when renaming `.git/config.lock` to `.git/config`. The regression window is between 2.21 and 2.36, reproducible across multiple Windows workstations. The problem appears specific to DFS path resolution and locking behavior, though the root cause (whether in Git's Windows filesystem handling or network configuration) remains unidentified. No workaround provided yet.
