Windows DFS-mounted network drive regression report from Erwan Leroy, with follow-up from Git for Windows maintainer Johannes Schindelin (Dscho). Core issue: Git versions 2.36+ fail with "Permission denied" when writing config files on DFS paths (working on direct UNC paths and in Git <=2.21), specifically during lock file operations renaming `.git/config.lock` to `.git/config`. Regression window identified between 2.21 and 2.36.

Technical investigation status: Schindelin provided investigation resources (pre-compiled Git for Windows version archive at gitforwindows.org/git-snapshots/, both Git and Git for Windows release notes) while noting the "Permission denied" error is unexpected given his initial suspicion about POSIX-semantics rename() emulation. Key open question: whether the issue manifests differently with `Y:\` drive mappings versus `\\atl-xx\Basecamp` UNC paths in DFS scenarios.

References in play: Git for Windows issue #3825 (originally linked by brian m. carlson) remains primary reference. D. Ben Knoble previously contributed Git release notes pointers. Current workarounds: use WSL or pre-2.21 versions. No root cause identified yet; thread remains open with focus on Windows-specific filesystem behavior differences between DFS and direct UNC paths. Next steps likely involve further version bisection using provided resources to narrow the regression window.
