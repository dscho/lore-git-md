Performance optimization patch introducing `struct bloom_keyvec` to enable future multi-pathspec bloom filter support. This is the first of two patches in a series addressing performance limitations where Git's bloom filters currently only accelerate single pathspec queries.

The patch replaces direct `struct bloom_key *` usage in `rev_info` with a new `struct bloom_keyvec` that can hold multiple bloom keys. Each keyvec corresponds to one pathspec item, with the current implementation still limited to one pathspec (so `bloom_keyvecs_nr` is 0 or 1). New helper functions include `create_bloom_keyvec`, `destroy_bloom_keyvec`, `fill_bloom_keyvec_key`, and `bloom_filter_contains_vec` for checking multiple keys against a bloom filter. The changes touch bloom.c/h and revision.c/h, with corresponding updates to the bloom filter initialization and checking logic in revision.c.

This refactoring maintains the existing single-pathspec optimization while laying groundwork for the second patch that will enable multi-pathspec support. The implementation follows Junio Hamano's v1 feedback by using FLEX_ARRAY for keys, tightening variable scoping, and improving API naming. The patch appears well-structured with clear commit message explaining the motivation and changes, though as noted in the thread, additional test coverage for multi-pathspec cases will be needed in follow-up work.
