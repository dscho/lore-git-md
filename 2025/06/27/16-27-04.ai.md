This is a documentation review for the new `git refs list` subcommand proposal. Jean-Noël Avila provides detailed feedback on the man page formatting and content for the RFC patch series introducing this `for-each-ref`-compatible command.

The review focuses on improving the command's documentation syntax and clarity, noting several formatting issues in the SYNOPSIS section (spacing around pipes in option lists, bracket placement) and suggesting more precise wording throughout. Key points include clarifying the meaning of ellipses in option syntax, standardizing option description phrasing to use imperative mood, and questioning whether `--include-root-refs` should list root refs "along with" rather than "apart from" regular refs.

The reviewer confirms the technical accuracy of the documentation while suggesting stylistic improvements to match Git's documentation conventions. The feedback maintains the patch's technical approach while refining its presentation, particularly around command syntax documentation and option descriptions. No fundamental design issues are raised - the suggestions are all about improving clarity and consistency in the existing implementation's documentation.
