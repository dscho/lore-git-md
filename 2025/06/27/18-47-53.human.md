This is a documentation review of patch 2/5 in the promisor-remote protocol enhancement series. Jean-Noël Avila provides several style and formatting suggestions for the documentation changes in Christian Couder's patch that adds configurable field advertisement to the promisor-remote protocol.

The review focuses on improving the technical writing quality, suggesting:
1. Using description lists (with `::` syntax) instead of bullet points for field definitions
2. Removing spaces in placeholder names (e.g. `<field-name>` instead of `<field name>`)
3. Avoiding unnecessary future tense ("will") in favor of present tense for clearer technical writing
4. Maintaining consistent underline lengths in AsciiDoc headings
5. Considering whether to standardize on BNF or synopsis format for protocol syntax definitions
6. Applying plain language principles to make the docs more accessible to non-native English speakers

The reviewer also raises the broader question of whether Git should establish a documentation style guide to help non-native English speakers contribute more easily. While these are all valid editorial suggestions, they don't affect the technical correctness of the patch, which has already been through multiple rounds of review and is considered final by the author.

This appears to be a thoughtful late-stage polish of the documentation aspects, though some suggestions (like the BNF vs synopsis question) might be better addressed in a follow-up patch since the series is otherwise ready for merging.
