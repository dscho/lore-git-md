This RFC thread introduces `git refs list` as a new command to consolidate ref listing functionality, now in its fourth iteration with mentoring from Patrick Steinhardt. The series establishes shared core logic between this new command and `git for-each-ref`, with all major technical concerns addressed. 

The current discussion focuses on pattern matching behavior inherited from `git for-each-ref`, where Phillip Wood raised concerns about potentially confusing semantics (e.g., `refs/h*` returning nothing while `refs/heads/m*` works). Junio Hamano has weighed in, explaining that the current hierarchical matching is intentional - it allows listing main branches without showing nested topic branches. He suggests keeping this behavior but potentially adding support for double-asterisk (`**`) to enable cross-hierarchy matching when explicitly requested.

The main outstanding question is whether to maintain the current pattern matching behavior (as Junio prefers) or modify it for more intuitive prefix matching. Given Junio's position as maintainer and his rationale about hierarchical usefulness, this seems likely to be the direction taken, possibly with the addition of `**` syntax for more flexible matching when needed.
