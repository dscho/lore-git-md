Meet Soni's `git refs list` series, now at v5, introduces a new command that wraps `git for-each-ref` functionality while sharing core logic and test infrastructure. The series has evolved through multiple versions with input from Patrick Steinhardt (mentor), Junio Hamano, and documentation reviewers Eric Sunshine and Jean-Noël Avila. The current implementation maintains strict compatibility with `for-each-ref`'s behavior, including its wildcard matching semantics.

A recent discussion between Phillip Wood and Junio has surfaced an inherent limitation in the current wildcard matching behavior inherited from `for-each-ref`. The matching rules make it impossible to predict from the pattern alone whether matching will be prefix-based or exact, which could complicate scripting use cases. While adding a trailing slash can force prefix matching, there's no syntax to enforce exact matching. Phillip notes this as a practical limitation, though not necessarily a critical one, given that most use cases can work around it by parsing the `%(refname)` output.

The series appears ready for final review, with all architectural components in place and comprehensive test coverage added in v5. The wildcard behavior discussion has reinforced the design decision to maintain compatibility with `for-each-ref`, while documenting its limitations for future consideration. The team seems to be converging on accepting the current behavior as good enough for now, with potential enhancements scoped as future work.
