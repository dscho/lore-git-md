This RFC patch series introduces `git refs list` as a thin wrapper around `git for-each-ref`, now in its fourth iteration with all major architectural refinements addressed. The series, authored by GSoC participant Meet Soni under Patrick Steinhardt's mentorship, consolidates ref listing functionality while maintaining behavior through shared core logic.

The implementation establishes a solid foundation with a new `for_each_ref_core()` helper function that both commands use, along with synchronized documentation and test infrastructure. Recent discussion has focused on the pattern matching behavior inherited from `for-each-ref`, where single asterisks (`*`) match within a single hierarchy level (e.g., `refs/heads/m*` matches `morning` but not `mid/night`). 

Junio Hamano has weighed in that this hierarchical matching is intentional and useful for common workflows like listing main branches without showing topic branches. While Phillip Wood found this behavior confusing, the discussion is converging on maintaining the current semantics while considering double-asterisk (`**`) syntax as a future enhancement for cross-hierarchy matching. 

Only minor polishing remains: some documentation tweaks, commit organization improvements, and finalizing the pattern matching decision (likely keeping current behavior with potential future `**` support). The architectural approach has received broad approval, with the shared implementation between commands working as intended. Key participants include the author and mentor (Meet Soni and Patrick Steinhardt), along with Junio Hamano, Phillip Wood, and documentation experts Eric Sunshine and Jean-Noël Avila. The series appears ready for final review and potential merging once these last details are addressed.
