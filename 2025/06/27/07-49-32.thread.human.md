This RFC thread explores the proposal for a new `git refs list` command, initially framed as the first step in consolidating ref-related commands under a `git refs` hierarchy. The series, authored by GSoC participant Meet Soni with mentoring from experienced contributors, mirrors `git for-each-ref` functionality while establishing new infrastructure in `builtin/refs.c`. Maintainer Junio C Hamano has questioned whether a wrapper approach (like `git branch`/`tag`) might better serve the discoverability goal without duplicating functionality.

The discussion has now expanded to include documentation improvements, with Jean-Noël Avila submitting patches to standardize the `git-for-each-ref` man page. Junio reviewed these documentation changes, praising the consistency improvements while noting opportunities for further standardization in synopsis styling, placeholder markup, and option references. These documentation refinements proceed in parallel with the core debate about command organization.

The key open question remains whether the project should adopt a new `git refs list` command or prefer wrapper implementations that reuse existing commands. Junio-maintained thread has shifted from implementation details to interface philosophy, with the maintainer consistently advocating for approaches that minimize long-term maintenance burden while still improving user discoverability. The technical foundation (via ref-filter reuse) remains uncontested, keeping the discussion focused on project policy rather than code quality.
