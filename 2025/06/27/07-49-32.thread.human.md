This RFC thread proposes introducing a new `git refs list` subcommand as the first step in consolidating Git's reference-related commands. The initial patch, from a GSoC participant with mentor guidance, creates the basic infrastructure in `builtin/refs.c` and mirrors all functionality of `git for-each-ref` exactly, including pattern matching, sorting, and filtering capabilities. It adds an `--include-root-refs` flag for better pseudoref handling while maintaining strict backward compatibility.

The second patch adds testing infrastructure by parameterizing the existing `for-each-ref` test suite to run against both commands, ensuring the new implementation behaves identically. This establishes a solid foundation for future evolution while allowing the discussion to focus on the long-term vision for ref command unification. The thread remains open for feedback, particularly from users who rely on these commands in scripts, about potential migration paths and which `for-each-ref` features should be carried forward or modified in the new interface.
