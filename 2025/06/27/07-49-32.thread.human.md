This RFC thread explores introducing a new `git refs list` command as part of a broader ref command consolidation effort. The initial proposal, from a GSoC participant with mentor guidance, presents a technically sound implementation that mirrors `git for-each-ref` functionality while establishing new infrastructure in `builtin/refs.c`. The series includes comprehensive tests and documentation, with Jean-Noël Avila providing detailed formatting feedback on the man pages.

Maintainer Junio C Hamano has raised fundamental concerns about the proposal's justification, questioning whether creating a parallel command would actually simplify maintenance or just duplicate it. In the latest response, the author acknowledges this concern, conceding that feature divergence between the commands could lead to backport pressure rather than consolidation. This leaves the thread at an impasse - while the implementation is solid, the strategic rationale hasn't convinced the key decision-maker. 

The discussion now hinges on project philosophy questions: is command consolidation valuable enough to justify maintaining parallel implementations during a transition, or should alternative approaches be explored? Participants looking to move this forward will need to address Junio's skepticism about the migration path or propose different strategies that might satisfy his concerns about long-term maintainability.
