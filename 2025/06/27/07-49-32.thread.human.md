This RFC proposes a new `git refs list` command that would initially mirror `git for-each-ref` functionality, with mentoring from experienced contributors. The implementation reuses the existing ref-filter logic and includes comprehensive test coverage, but maintainer Junio C Hamano has raised concerns about the justification for creating a parallel command rather than improving the existing one. The discussion has evolved into two parallel tracks: the technical implementation (which is sound) and the strategic rationale (which remains unconvincing to the maintainer).

Meanwhile, Jean-Noël Avila has been leading documentation improvements to the shared man page content, with follow-up patches that standardize formatting and improve clarity. These changes address Junio's earlier suggestion to improve the source documentation directly. While the core debate about command consolidation strategy continues, these documentation refinements will benefit both commands regardless of how the larger design question is resolved. The thread remains open with the key question being whether the project should maintain two commands with identical functionality or find an alternative path to ref command consolidation.
