This RFC patch series proposes introducing a new `git refs list` command as part of a broader ref command consolidation effort, with parallel documentation improvements. The initial implementation by GSoC participant Meet Soni (mentored by experienced contributors) mirrors `git for-each-ref` functionality while establishing new infrastructure in `builtin/refs.c`. Maintainer Junio Hamano has questioned whether a new command is justified, suggesting a wrapper approach (like `git branch`/`tag`) might achieve the same discoverability benefits without code duplication.

While the technical discussion about command design continues, Jean-Noël Avila has been leading documentation improvements to standardize the `git-for-each-ref` man page. In response to Hamano's review of their initial patch, Avila acknowledges more work is needed to fully align with project documentation standards and commits to sending a v2 that addresses remaining style issues like section headers and placeholder formatting. These documentation changes are proceeding smoothly and independently of the ongoing debate about the new command's design.

The key open question remains whether the proposed `git refs list` command's improved discoverability justifies its maintenance cost, or if a wrapper approach would be preferable. The technical foundation (reusing ref-filter logic) is sound, but the project must weigh the tradeoffs between user experience and long-term maintainability. Meanwhile, the documentation standardization work continues to make steady progress.
