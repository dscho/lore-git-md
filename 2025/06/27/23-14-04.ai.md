This is a bugfix patch for Git's daemon mode, addressing incorrect socket handling during interrupted system calls (EINTR). The patch is now in its third version, incorporating feedback from previous rounds.

The core issue stems from a 2005 change that introduced IPv6 support, where EINTR errors during accept() would incorrectly advance to the next socket rather than retrying. The current implementation adds a retry mechanism (3 attempts, up from 2 in v1) before falling back to the old behavior. The diff shows the key changes in daemon.c's service_loop() function, where a retry counter and goto label have been added to handle EINTR cases properly.

Notable technical details include:
- Maintains existing fallthrough behavior for EAGAIN/ECONNABORTED after EINTR retries
- Reordered switch statement places EINTR first
- Variable declarations now unified before accept() call as suggested by Junio Hamano
- Still preserves the check_dead_children() call between retries (an open question from earlier discussion)

The patch appears well-focused (12-line change) and addresses a clear race condition in the daemon's socket handling. The commit message provides historical context tracing back to the original 2005 commit that introduced the issue. While the variable declaration style discussion from v2 has been resolved, Phillip Wood's question about SA_RESTART interaction remains unaddressed in this version.
