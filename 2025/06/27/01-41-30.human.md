This is a technical discussion about signal handling compatibility in the Git daemon, specifically around the SA_RESTART detection mechanism. Junio Hamano is reviewing a patch from Carlo Marcelo Arenas Belón that adds autoconf checks for SA_RESTART support.

The patch introduces a compile-time check to detect whether SA_RESTART is defined in the system's signal.h. The implementation uses AC_COMPILE_IFELSE to test the presence of SA_RESTART, setting NO_RESTARTABLE_SIGNALS=UnfortunatelyYes when SA_RESTART is not available. Junio notes the somewhat confusing naming where the autoconf cache variable (ac_cv_siginterrupt) doesn't change between versions, while the user-facing variable does.

This is part of the ongoing debate about how to handle platform-specific signal behaviors in the Git daemon, where different approaches (SA_RESTART toggling, documentation-only, and pipe-based tracking) are being evaluated. The discussion here focuses on the technical details of the SA_RESTART detection mechanism, which would be used in one of the proposed solutions. Junio's comments suggest careful attention to the implementation details and naming consistency issues in the autoconf setup.
