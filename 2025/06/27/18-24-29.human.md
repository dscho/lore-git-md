This is a bug report thread about severe Windows-specific issues in recent Git versions (2.48.1-2.50.0). Jörg Hohwiller provides new test results showing that downgrading to Git 2.46.0 resolves multiple problems that were blocking his workflow, including clone failures and ref lock errors.

The key findings are: fresh clones consistently fail with "connection reset by peer" errors in newer Git versions (2.48.1-2.50.0) but work with 2.46.0, suggesting a regression. Even after downgrading, some repository corruption appears to persist, as `git remote update` still fails in the previously broken clone. The reporter suspects bundled OpenSSL or general QA issues in recent Windows releases, though this remains speculative.

This continues the thread's pattern of uncovering progressively worse problems - from initial lock file errors to complete clone failures. The workaround (downgrading) comes at the cost of losing access to newer features, and the reporter notes this may not fully resolve underlying repository corruption. The thread remains important for Windows users experiencing similar issues, though root cause analysis is still needed.
