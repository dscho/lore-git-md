Performance optimization patch series extending Git's pathspec bloom filters to handle multiple pathspec elements efficiently. This v2 cover letter from Lidong Yan addresses Junio Hamano's feedback on the initial submission while maintaining the core approach of using a new `bloom_keyvec` structure to manage multiple bloom keys.

The series aims to fix the performance gap identified by Kai Koponen, where combined pathspec queries (`git log -- file1 file2`) were slower than separate invocations. The solution involves hashing each pathspec element separately and checking all bloom filters before deciding whether to skip a commit during revision traversal. Benchmark results show the optimized version now matches the performance of separate invocations.

Key changes in v2 incorporate Junio's suggestions: using FLEX_ARRAY for key storage (eliminating separate allocations), tighter variable scoping, and terminology refinements. The cover letter also acknowledges Junio's request for additional test coverage to guard against false negatives, though it doesn't detail what specific new tests will be added.

The technical approach remains unchanged from v1 - patch 1 introduces the `bloom_keyvec` infrastructure while patch 2 modifies the revision traversal logic to use it.
