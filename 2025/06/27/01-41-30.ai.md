This is a technical follow-up in the ongoing Git daemon signal handling redesign thread, focusing on build system changes for SA_RESTART detection. Junio Hamano is reviewing Carlo Marcelo Arenas Belón's patch that adds autoconf detection for SA_RESTART support, which is relevant to the signal handling approaches under discussion.

The patch introduces an AC_CACHE_CHECK test that compiles a program checking for SA_RESTART definition in signal.h. The test sets NO_RESTARTABLE_SIGNALS=UnfortunatelyYes when SA_RESTART is not available, with the variable name indicating this is an undesirable condition. Junio notes the compilation failure occurs when SA_RESTART is defined (due to the malformed "restartable signals supported" text), while successful compilation indicates SA_RESTART is undefined.

A key observation is that the cached autoconf variable (ac_cv_siginterrupt) retains its original name through multiple revisions, which Junio questions regarding visibility to end users. This suggests potential maintainability concerns about variable naming consistency between the cached autoconf state and the derived NO_RESTARTABLE_SIGNALS makefile variable.

The email doesn't introduce new technical approaches but examines implementation details of the SA_RESTART detection mechanism that would be needed for either the original SA_RESTART toggling approach or Phillip Wood's documentation-based solution. The review focuses on build system correctness rather than the broader architectural debate, indicating this patch may be preparatory work regardless of which signal handling approach is ultimately chosen.
