This is a technical discussion about the pipe-based approach to child process tracking in git-daemon, part of the ongoing thread about signal handling redesign. Phillip Wood provides a detailed code review of Carlo Marcelo Arenas Belón's RFC patch that implements a self-pipe mechanism to notify the parent when children exit.

Phillip acknowledges the patch addresses several issues (race conditions, poll() interruptions, AIX recursion) but raises multiple implementation concerns. Key points include: the pipe naming ("poll_pipe" vs "signal_pipe"), error handling around pipe writes, proper draining of the signal pipe, and the timing of SIGCHLD handler re-arming. He suggests structural improvements like extracting the pipe setup into a helper function and handling pipe failures more robustly.

The review maintains a constructive tone while identifying concrete technical issues that would need resolution before this approach could be merged. Phillip positions this as an alternative to both the original SA_RESTART approach and his own documentation-only proposal, though he expresses reservations about the direction of injecting file descriptors into child processes. The exchange shows active collaboration to refine the pipe-based solution while the broader architectural debate between the three approaches continues.
