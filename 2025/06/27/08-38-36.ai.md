This is a technical review of the pipe-based child process tracking implementation for git-daemon, part of the ongoing signal handling redesign discussion. Phillip Wood provides detailed feedback on Carlo Marcelo Arenas Belón's RFC patch that introduces a self-pipe mechanism to notify the parent when children exit, addressing race conditions in child reaping.

Key technical points raised:
1. Implementation concerns about the pipe handling:
   - Suggests renaming `poll_pipe` to `signal_pipe` for clarity
   - Notes missing error handling around `write()` in signal handler
   - Recommends moving SIGCHLD handler re-arming to event loop to fix AIX recursion
   - Proposes extracting pipe setup into a helper function to reduce indentation

2. Behavioral improvements:
   - Suggests draining the signal pipe completely (until EAGAIN) rather than single-byte reads
   - Recommends handling pipe setup failure by dying rather than continuing
   - Points out need to properly close pipes if FD_CLOEXEC setting fails

3. Architectural observations:
   - Questions the efficiency of adding an fd per child process
   - Notes this approach could solve both the race condition and AIX recursion issues
   - Mentions historical context (race introduced in 2008 commit 695605b5080)

The review maintains a constructive tone while identifying several areas needing improvement in the pipe-based approach. Phillip acknowledges this as an alternative solution to the signal handling problems while raising concerns about implementation details and potential performance implications. The feedback focuses on making the pipe mechanism more robust rather than rejecting the approach outright.
