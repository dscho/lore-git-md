Bugfix for `imap-send` configuration parsing that corrects a regression introduced in Git 2.46.0. The patch fixes a critical issue where the `cfg->folder` field was incorrectly being NULLed out when processing unrelated configuration variables (`imap.user`, `imap.pass`, `imap.tunnel`, and `imap.authmethod`). This made `imap-send` completely unusable since the folder field would be cleared even when trying to set other configuration values.

The root cause was in `git_imap_config()` where the wrong field (`cfg->folder`) was being freed and NULLed for all configuration cases, rather than freeing the specific field being set. The fix properly clears each config field individually - `cfg->user` for `imap.user`, `cfg->pass` for `imap.pass`, etc. The regression originated from commit 6d1f198f34 ("imap-send: fix leaking memory in `imap_server_conf`") which introduced the incorrect cleanup pattern.

This is the first patch in the v11 series that provides comprehensive fixes and improvements to `imap-send`, including OAuth2.0 support and folder management features. The bug was likely unnoticed for some time due to most users preferring `git send-email` over `imap-send`. The fix is straightforward and focused, changing only the field-specific cleanup in `imap-send.c` while maintaining the same memory management pattern.
