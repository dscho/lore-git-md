This is the third patch in a 4-part series implementing stash export/import functionality, focused on the `git stash export` subcommand that converts stashes into transferable refs. The patch adds core functionality to:

1. Export stash entries (either all or specified ones) as a chain of commits under `refs/stash-export/`, with each commit preserving the original stash content while linking to previous exports via parent pointers. The chain starts from an empty base commit for reproducibility.

2. Support two output modes via flags: `--print` writes the commit hash to stdout for scripting use, while `--to-ref` stores to a specified ref. The implementation includes topology validation via `check_stash_topology()` to ensure exported commits maintain proper stash structure (2-3 parents with specific relationships).

3. Handle both bulk export (walking the entire stash reflog) and selective export of specific stash references. The code uses the new `GET_OID_GENTLY` flag (introduced in this series) for quiet failure when checking reflog history.

Key technical components:
- New `write_commit_with_parents()` helper reconstructs stash commits with modified parent chains
- `collect_stash_entries()` callback processes reflog entries during bulk export
- Shared empty commit generation using `repo->hash_algo->empty_tree`
- Integration with existing stash reference parsing via `parse_stash_revision()`

The patch demonstrates thorough handling of edge cases (invalid stash topology, missing entries) and maintains original commit metadata (author, committer, messages) while adding "git stash:" prefixes for clarity. Documentation updates in `git-stash.adoc` explain the new subcommand and its options.

This represents the final implementation after seven review rounds, with all feedback incorporated and no outstanding technical issues. The changes are performance-optimized (using commit lists instead of OID arrays) and maintain platform compatibility (Windows/NonStop considerations preserved from earlier versions).
