Feature implementation for stash export/import functionality.

This patch introduces `git stash export`, the third in a four-part series that enables transferring stashes between repositories via refs. The implementation allows users to either print the exported stash chain's hash (for scripting) or store it under a specified ref (like `refs/stash-export/`). 

The core functionality creates a commit chain where each stash entry becomes a commit with two parents: one linking to the previous stash (or an empty base commit for the first item) and the other preserving the original stash commit. This maintains stash topology while making the data pushable/pullable. The implementation includes:

- Validation of stash commit structure via `check_stash_topology()`
- Reflog traversal to collect all stashes when none are specified
- Preservation of original author/committer info in commit messages
- A reproducible empty base commit using fixed timestamps
- New `--print` and `--to-ref` options mirroring `commit-tree` behavior

The patch appears well-considered, with thorough test coverage (94 new tests in the series) and clear documentation updates. It addresses a real pain point for developers using multiple machines or ephemeral environments. The implementation builds on established Git APIs and follows the project's preferred patterns, as evidenced by the v7 iteration incorporating feedback from core maintainers.
