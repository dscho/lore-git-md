This is the final patch in a 10-part series enhancing `imap-send` with new features and bugfixes. It adds a `--list` option to display available IMAP folders, addressing the common issue where different servers (like Gmail vs Outlook) use different naming conventions for standard folders (e.g., "[Gmail]/Trash" vs "Deleted").

The implementation handles both OpenSSL and libcurl backends, following RFC6154 for OpenSSL and libcurl's example code for the curl implementation. The output shows folder names and hierarchy markers like `\HasNoChildren`. The patch includes documentation updates and modifies the command's usage string to include the new option.

Key technical details:
- Adds `list_folders` static variable and `--list` option
- Implements `list_imap_folders()` for OpenSSL backend using IMAP LIST
- Adds `curl_list_imap_folders()` for libcurl backend
- Modifies buffer handling to show LIST responses when in list mode
- Updates documentation with usage instructions and example
- Makes folder specification optional when using `--list`

This completes the series' goal of improving `imap-send`'s usability with comprehensive folder management capabilities alongside the previously added OAuth2.0 support and configuration fixes. The implementation appears thorough, with proper error handling and consistent behavior across both backends.
