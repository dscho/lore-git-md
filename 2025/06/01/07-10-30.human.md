Bugfix patch in the `imap-send` series addressing a memory leak in CRAM-MD5 authentication. This is part of a larger v10 series that adds OAuth2.0 support and fixes several IMAP-related issues.

The patch specifically plugs a memory leak in the `auth_cram_md5` function where an allocated response buffer wasn't being freed if the socket write operation failed. The fix is straightforward - adding a `free(response)` call in the error path before returning. This matches the existing cleanup that was already happening in the success path.

The change is small (just 3 lines added) but important for proper resource management. It's one of several memory-related fixes in this series, which has undergone extensive review from multiple Git maintainers. The patch appears technically sound and uncontroversial, addressing a clear oversight in the error handling path.

This continues the series' pattern of thorough attention to both functionality and robustness in the IMAP implementation. Readers interested in the broader context can look to the other patches in the series for the more substantial OAuth2.0 and configuration parsing improvements.
