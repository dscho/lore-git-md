This is the cover letter for v7 of a feature series introducing `git stash export` and `import` subcommands, completing a multi-year effort to enable stash transfer between repositories. The series has undergone extensive review over seven iterations, with all major technical concerns now resolved.

The core functionality allows stashes to be converted to a chain of commits under `refs/stash-export/`, making them portable across machines via push/fetch/bundle. Each exported stash commit has two parents - one linking to the next stash in the chain, and another containing the actual stash data. The implementation builds on existing reflog traversal APIs rather than exposing new low-level internals, following project consensus.

Key changes in v7 include adopting Phillip Wood's `commit_list` optimization for topology validation, finalizing the reflog API approach (dropping the earlier `read_complete_reflog` exposure), and polishing error messages. The series now has robust test coverage (94 new lines in t3903) and handles platform-specific concerns like Windows casting.

With Junio Hamano's approval and Phillip Wood's sign-off, this appears merge-ready after addressing all substantive feedback across seven versions. The implementation demonstrates careful attention to Git's API design principles while solving a real workflow limitation - the inability to transfer stashes between repositories. For users who maintain stashes across multiple machines, this will be a valuable addition to the stash toolkit.
