This is the final patch in a feature series adding folder listing capability to `imap-send`. The patch introduces a new `--list` option that shows available IMAP folders, addressing the common problem where different servers (Gmail, Outlook, etc.) use different naming conventions for standard folders like Trash or Drafts.

The implementation provides RFC6154-compliant LIST command handling for both OpenSSL and libcurl backends, with proper hierarchy marker display and server-specific folder name handling. The OpenSSL path uses `list_imap_folders()` while libcurl uses `curl_list_imap_folders()`. The output shows folder flags (like `\HasNoChildren`) and paths in a format matching server responses, which helps users identify the correct folder names to use in configuration.

Key technical details include:
- New `list_folders` flag and `--list` option added to command-line parsing
- Modified `buffer_gets()` to show LIST responses when in list mode
- Separate code paths for OpenSSL and libcurl implementations
- Proper credential handling during folder listing operations
- Documentation updates explaining the new option and its use case

The patch follows the series' established patterns for command-line handling and memory management. It completes the feature set by providing visibility into server folder structures, which complements the earlier `--folder` option for runtime folder specification. The implementation appears thorough, with consistent error handling and output formatting that matches the rest of the series' polished user experience.
