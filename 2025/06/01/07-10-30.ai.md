Bugfix patch in the ongoing `imap-send` series, addressing a memory leak in CRAM-MD5 authentication. This is part of a larger v10 series that introduces OAuth2.0 support and fixes various IMAP-related issues.

The patch specifically fixes a case where the `response` buffer allocated in `auth_cram_md5()` would leak if the socket write operation failed. Previously, the function would `free(response)` only on success paths, but if `socket_write()` returned an error (indicating it wrote fewer bytes than expected), the function would return without freeing the buffer. The fix adds the missing `free(response)` in the error path.

The change is minimal (3 lines added, 1 line modified) and clearly correct - it follows the established pattern of freeing allocated resources before returning from the function. This completes the memory leak fixes for CRAM-MD5 authentication that were part of the series' goals. The patch maintains consistency with the series' focus on robust error handling and memory management across all authentication methods.

Technical details: The fix occurs in `imap-send.c`'s `auth_cram_md5()` function, which handles the CRAM-MD5 challenge-response authentication flow. The `response` buffer contains the base64-encoded authentication response generated by the `cram()` helper function. The patch ensures this buffer is properly freed in all code paths, matching the memory management approach used elsewhere in the series.
