Bugfix patch for `imap-send` addressing a critical regression introduced in Git 2.46.0 that made the command unusable. The issue stems from commit 6d1f198f34 which incorrectly freed and NULLed the `cfg->folder` field when processing unrelated configuration variables (`imap.user`, `imap.pass`, `imap.tunnel`, and `imap.authmethod`). The fix properly clears each config field individually rather than incorrectly clearing the folder field in all cases.

This is the first patch in a v10 series that primarily focuses on adding OAuth2.0 support and other IMAP improvements. The regression had gone unnoticed likely because most users prefer `git send-email`. The fix is straightforward - changing four instances of `FREE_AND_NULL(cfg->folder)` to properly clear the corresponding config fields (`user`, `pass`, `tunnel`, and `auth_method`). The patch maintains the same memory management pattern but applies it to the correct fields.

The thread context shows this bug was identified early in the series' development and has been thoroughly reviewed. This particular fix appears uncontroversial and necessary to restore basic `imap-send` functionality before adding new features. The patch is small (4-line change) and focused, with no apparent test updates needed since it's fixing clearly incorrect behavior rather than changing intended functionality.
