Platform compatibility patch fixing physical memory detection on OpenBSD/NetBSD systems with >=4GB RAM.

The patch modifies the memory detection logic in `builtin/gc.c` to properly handle systems with large amounts of physical memory. Currently, the code uses `HW_PHYSMEM` on BSD systems, which doesn't correctly report memory amounts above 4GB. The change adds support for `HW_PHYSMEM64` which properly handles larger memory configurations, while maintaining backward compatibility with the existing `HW_MEMSIZE` (used on some BSD variants) and `HW_PHYSMEM` fallback.

The change is straightforward - it simply adds another condition to check for `HW_PHYSMEM64` in the sysctl memory detection path. The patch maintains the existing fallback behavior while adding the new capability. This affects Git's auto-detection of system memory, which is used by various components including the garbage collector for determining appropriate memory limits.

The commit message clearly identifies the problem (incorrect memory reporting on >=4GB systems) and the BSD variants affected (OpenBSD/NetBSD). The change is minimal and focused, touching only the necessary conditional logic while preserving all existing behavior for other platforms and configurations. The patch appears technically sound for its stated purpose.
