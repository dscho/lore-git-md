This is a follow-up discussion in the completed curl warning fix series, providing historical context about curl's API design.

Jeff King and Daniel Stenberg (curl's creator) discuss the root cause of the type mismatch warnings that prompted the patch series. Stenberg confirms the issue stems from curl's historical API design oversight where symbolic constants weren't originally defined as `long` types despite being used with `curl_easy_setopt()`. He acknowledges this was an omission and plans to fix it in future curl versions, though notes this won't help Git for backward compatibility reasons.

The exchange serves as post-facto validation of the series' approach - while the patches are already approved and ready for merging, this discussion provides useful background about why the warnings appeared and why Git must maintain its casting solution. King accepts that Git will need to keep the explicit casts for the foreseeable future, even as curl improves its API.

No new action is required from the Git side - this is purely informational discussion that reinforces the technical decisions made in the series. The thread remains fully resolved with all patches ready for integration.
