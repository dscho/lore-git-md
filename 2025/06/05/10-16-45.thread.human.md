This thread addresses a CI/build system problem where certain test patterns involving `tee | git receive-pack` hang indefinitely on Windows/Meson environments due to a known MSYS2 runtime bug in Git for Windows v2.49.0. The issue stems from faulty signal handling in a specific MSYS2 runtime version (3.5.7-463ebcdc.x86_64) that prevents `tee` processes from properly receiving SIGPIPE when `git receive-pack` terminates.

Johannes Schindelin proposed a solution introducing a `TEE_DOES_NOT_HANG` prerequisite that detects the problematic runtime via `uname -a` and skips two affected tests in `t5410-receive-pack.sh`. While Patrick Steinhardt considered alternative approaches like rewriting the tests to avoid the problematic pattern, both he and Junio Hamano agreed the current solution is appropriate given the temporary nature of the issue - the underlying bug is already fixed in Git for Windows v2.50.0.

Junio has now reviewed and approved the patch, noting it properly addresses the root cause rather than working around timing issues. He observed the specific version check provides good documentation value while maintaining test integrity across the full CI matrix. The patch will be queued, providing a temporary workaround until GitHub runners update to the fixed runtime version. This concludes the immediate discussion about the test hang issue.
