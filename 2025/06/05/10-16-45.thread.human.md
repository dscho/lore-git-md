This thread addresses a CI/build system issue where certain tests involving `tee | git receive-pack` hang indefinitely on Windows/Meson environments when using Git for Windows v2.49.0. The root cause is a known MSYS2 runtime bug (version 3.5.7-463ebcdc.x86_64) that prevents proper SIGPIPE handling, causing `tee` processes to deadlock.

Johannes Schindelin proposed a temporary solution by introducing a `TEE_DOES_NOT_HANG` prerequisite that detects the problematic runtime via `uname -a` and skips two affected tests in `t5410-receive-pack.sh`. Patrick Steinhardt has weighed in, agreeing this is a sensible approach given the issue will resolve itself once CI runners update to Git for Windows v2.50.0 where the runtime bug is fixed. While Patrick briefly considered restructuring the tests to avoid the problematic pattern entirely, both maintainers seem content with the current workaround for this transitional period.

The tests continue running in other Windows CI jobs (`win test` and `vs test`) where the issue doesn't occur, maintaining coverage across the full CI matrix. This follows Git's established pattern of handling platform-specific test issues while waiting for underlying fixes to propagate through the ecosystem.
