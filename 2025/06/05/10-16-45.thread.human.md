This thread addresses a CI test hang specific to Windows environments using Meson builds with Git for Windows v2.49.0. The issue stems from a bug in the MSYS2 runtime (version 3.5.7-463ebcdc.x86_64) where `tee` processes don't properly receive SIGPIPE signals when the receiving `git receive-pack` terminates, causing two specific tests in `t5410-receive-pack.sh` to hang indefinitely.

The patch introduces a temporary workaround by adding a `TEE_DOES_NOT_HANG` prerequisite that detects the problematic runtime version and skips the affected tests. The author notes this is a stopgap measure until GitHub runners update to Git for Windows v2.50.0, which includes a fixed runtime. The tests continue running in other Windows CI configurations where the bug is already resolved.

Patrick Steinhardt suggested an alternative approach that wasn't detailed in this particular patch. The change follows Git's established pattern of handling platform-specific test issues while maintaining coverage across the full CI matrix. The affected test patterns were introduced in commit 68cb0b5253a0.
