This is a refactoring patch in Patrick Steinhardt's maintenance task series, specifically addressing error handling standardization. The patch introduces `die(NULL)` as a cleaner alternative to `exit(128)` when code needs to terminate after already printing an error message, eliminating magic numbers from the codebase.

Junio Hamano raised a concern about potential compiler warnings since `die()` is declared with printf-style format checking, but Patrick confirms testing shows no warnings with `-Wformat=2` and no CI issues. The approach is deemed safe for now, with a straightforward fallback option (`die_silent()`) available if compiler issues arise later.

This is a small but thoughtful quality-of-life improvement that fits into the series' broader error handling standardization effort. The change is low-risk (already tested in CI) and maintains the series' high standard of careful refactoring. With the compiler behavior verified, this appears ready to proceed as part of the overall maintenance task improvements.
