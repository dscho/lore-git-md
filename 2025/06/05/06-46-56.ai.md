This is part of Patrick Steinhardt's ongoing series to remove `the_repository` global state from Git's object database subsystem. Patch 6/17 continues the mechanical conversion work by making `assert_oid_type()` repository-agnostic.

The patch renames `assert_oid_type()` to `odb_assert_oid_type()` and modifies it to take an explicit `object_database` parameter instead of implicitly using `the_repository`. The function verifies that a given object ID matches the expected type (commit, tree, etc.), and this change maintains that behavior while removing another dependency on global state. The implementation now uses the repository pointer stored in the passed `object_database` struct.

Three call sites are updated to pass `the_repository->objects` as the new parameter: two in commit-related code (`builtin/commit-tree.c` and `commit.c`) and the header declaration in `odb.h`. The changes are straightforward mechanical conversions that don't alter functionality, just the way the ODB is accessed.

This follows the established pattern in the series of methodically converting functions to use explicit ODB parameters while maintaining the `odb_` naming convention. The patch is small (7 lines changed across 4 files) and focused, continuing the series' careful approach to this architectural refactoring. With the core infrastructure changes already reviewed in earlier patches, this appears ready for inclusion.
