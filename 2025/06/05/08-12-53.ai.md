This is a bugfix patch in the OAuth2.0 authentication support series for `imap-send`. The patch addresses a logic error in the libcurl setup code where the password would incorrectly be set for OAuth methods due to flawed `strcmp()` conditions using OR operators instead of AND.

Jeff King identified that the current implementation would always evaluate to true because `srvc->auth_method` cannot simultaneously be both "XOAUTH2" and "OAUTHBEARER". The intended behavior is to skip setting the password when using either OAuth method, which requires using AND operators with negated `strcmp()` results rather than the current OR implementation.

The fix is straightforward but important for correct OAuth2.0 authentication behavior in the libcurl backend. This completes the OAuth2.0 implementation that was a major focus of the v12 series, following earlier patches that introduced the authentication handlers, base64 encoding utilities, and documentation. The series has already addressed other technical aspects of OAuth support including compile-time guards and OpenSSL verification.
