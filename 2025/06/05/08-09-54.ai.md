Platform compatibility issue in Git v2.50.0-rc1 build system, specifically affecting NonStop systems when building without TCL/Tk (NO_TCLTK). Randall Becker provides critical debugging information showing the root cause: the `$(wildcard lib/*tcl)` expansion in git-gui/Makefile returns empty because no .tcl files exist in the git-gui/lib directory of the official 2.50.0-rc1 tarball, contrary to expectations. This contradicts earlier assumptions that the files should exist in an unmodified checkout.

The email reveals three key findings: 1) Examination of all 'lib' directories in the release shows no .tcl files present, 2) The git-gui/lib directory contains only non-TCL files (git-gui.ico, meson.build, tclIndex, win32_shortcut.js), and 3) The build environment uses standard tools (GNU Make 4.2.1 with bash). This confirms the build failure occurs because the Makefile unconditionally tries to process TCL files that don't exist in the release, rather than being a platform-specific wildcard expansion issue as previously hypothesized.

This represents a clear regression in the build system's handling of optional TCL/Tk dependencies, where the new generate-tclindex.sh script is being invoked with insufficient arguments when ALL_LIBFILES is empty. The problem appears to stem from build infrastructure changes that weren't properly tested in NO_TCLTK configurations before being included in the release candidate. Randall's findings shift the focus from platform-specific behavior to a more general build system bug that needs addressing before final release.
