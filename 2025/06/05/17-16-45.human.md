This is a follow-up discussion in the ongoing `imap-send` feature series, specifically addressing design questions about the OAuth2.0 authentication implementation. Aditya Garg responds to Junio Hamano's concerns about two aspects of the code.

First, regarding the `#ifdef NO_OPENSSL` directives in the authentication flow, Garg explains that while Hamano's suggested approach would eliminate the conditional compilation, it would trigger compiler warnings when built without OpenSSL. The current implementation appears to be the least bad option given these constraints.

Second, Hamano questioned the maintainability of the password-setting logic that specifically excludes XOAUTH2 and OAUTHBEARER methods. Garg clarifies that `CURLOPT_PASSWORD` is only for plain/login authentication, and that other methods (like CRAM-MD5) are handled separately. The current implementation matches curl's default behavior when no auth method is specified.

The exchange highlights some remaining design tensions in the otherwise mature patch series - while the OAuth2.0 functionality works correctly after the v13 fixes, there are open questions about code organization and future maintainability. Garg's responses suggest the current implementation may represent a pragmatic compromise between correctness and cleanliness. The thread shows the series is in its final polishing stages, with the maintainer focusing on long-term code quality rather than functional issues.
