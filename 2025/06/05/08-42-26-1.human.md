This is a bugfix patch in the `imap-send` series, specifically addressing a memory leak in the CRAM-MD5 authentication path. The patch is part of a larger v13 series that adds OAuth2.0 support and fixes various IMAP-related issues.

The change is small but important - it fixes a case where the `response` buffer would leak if `socket_write()` failed during CRAM-MD5 authentication. The fix adds a `free(response)` call in the error path before returning. This completes the memory management for the CRAM-MD5 implementation that was already being handled in the success path.

While simple, this patch demonstrates good attention to detail in cleaning up all error paths, which is particularly important in the security-sensitive authentication code. It follows the pattern of other fixes in the series that have been carefully reviewing all memory management in the IMAP subsystem. The change is straightforward and unlikely to be controversial, just closing a small gap in the error handling.
