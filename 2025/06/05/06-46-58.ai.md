This is patch 8/17 in Patrick Steinhardt's ongoing series to refactor Git's object database (ODB) subsystem to remove `the_repository` global state. The patch focuses on alternates handling, converting functions that manage alternate object directories to explicitly take an `object_database` parameter rather than relying on `the_repository`.

The key changes rename and update several alternates-related functions to use the new `odb_` prefix convention:
- `prepare_alt_odb()` -> `odb_prepare_alternates()`
- `has_alt_odb()` -> `odb_has_alternates()`
- `add_to_alternates_file()` -> `odb_add_to_alternates_file()`
- `add_to_alternates_memory()` -> `odb_add_to_alternates_memory()`

The patch updates 14 files with mechanical conversions of call sites, mostly in builtin commands (clone, fsck, grep, repack) and core object handling code (commit-graph, loose objects, packfiles). The changes follow the established pattern from earlier patches in the series, maintaining the same function signatures but requiring explicit ODB parameters.

One notable implementation detail mentioned in the commit message is that the path handling still indirectly uses the repository's path, though this is acknowledged as temporary with plans to store the path directly in the ODB structure. The changes are straightforward mechanical conversions without behavioral changes, continuing the series' methodical approach to removing global state.

The patch builds on the infrastructure established in earlier patches (renamed structs, new header locations, repository tracking) and follows the same review-approved pattern. It touches a moderate number of files (14) but all changes are predictable given the series' established conventions.
