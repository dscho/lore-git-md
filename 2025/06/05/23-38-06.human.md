This is a follow-up discussion about the critical build system regression in Git 2.50.0-rc1 affecting NO_TCLTK builds. Todd Zullinger shares Fedora's packaging approach as a best practice example for handling build flags consistently across multiple make invocations.

The email reinforces Junio Hamano's suggested workaround (using `make NO_TCLTK=NoThanks`) by showing how Fedora packages Git using a `config.mak` file to maintain consistent build flags. This prevents unnecessary rebuilds when different flags are used between build and install phases in packaging recipes. The context is particularly relevant as the community works to mitigate the regression where NO_TCLTK builds were accidentally deleting TCL files.

Zullinger provides a concrete example from Fedora's RPM spec file showing how they centralize build configuration (including V=1 for verbose builds and compiler flags) in a `config.mak` file. This doesn't introduce new technical information about the regression itself, but offers practical packaging wisdom that could help others implement the workaround more cleanly while waiting for the proper fix to land.
