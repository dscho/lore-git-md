This is part of Patrick Steinhardt's ongoing series to refactor Git's object database (ODB) subsystem, specifically patch 4/17 in the v5 iteration. The patch introduces parent pointers between ODB components to enable repository access when needed during the transition away from `the_repository` global.

The change adds two key relationships:
1. `struct object_database` now tracks its owning `struct repository` via a `repo` pointer
2. `struct odb_source` (previously `object_directory`) gets an `odb` pointer to its parent object database

These pointers allow code paths that need repository access (like config reading) to traverse from an ODB instance back to its repository context. The patch updates all ODB initialization and alternate-handling code to maintain these relationships, including modifications to `link_alt_odb_entry()` and related functions to pass through the ODB context.

The changes are mechanical but important for maintaining functionality during the global state removal. The patch follows the series' pattern of careful, incremental refactoring with thorough updates to all affected call sites. As with previous patches in the series, this appears well-executed and maintains backward compatibility while progressing the architectural goal.
