This is a bugfix for a build system regression affecting NO_TCLTK configurations. Johannes Sixt identifies the root cause in the `generate-tclindex.sh` script, which incorrectly uses `$@` (Makefile syntax for targets) in a shell script context where it evaluates to all arguments. This causes the script to delete all TCL source files when `tclsh` is not found, rather than just cleaning up the index file as intended.

The issue was first reported by Randall Becker during Git 2.50.0-rc1 testing, showing TCL files disappearing during builds without TCL/Tk support. Johannes's analysis shows the problematic line was likely copied from Makefile syntax without proper adaptation for shell script context. He suggests either fixing the `rm` command to target only `lib/tclIndex` or removing it entirely since the file gets overwritten anyway.

For immediate workarounds, Johannes recommends setting `NO_TCLTK=NoThanks` in config.mak. This appears to be a straightforward but impactful bug that slipped through build system changes, affecting all platforms building without TCL/Tk support. The fix should be relatively simple once properly reviewed.
