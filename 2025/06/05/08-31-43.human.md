This is a platform compatibility patch addressing a build issue with cURL 8.14.0 on macOS. The patch changes how integer values are passed to `curl_easy_setopt()` calls throughout Git's codebase to explicitly use `long` types instead of `int`.

The issue surfaced in Git's CI when Homebrew updated to cURL 8.14.0, which introduced stricter type checking in its headers. The compiler warnings indicate that cURL's API expects `long` parameters for certain options, but Git was passing `int` values. The patch systematically updates all affected calls across four files (`http-push.c`, `http.c`, `imap-send.c`, and `remote-curl.c`), adding `l` suffixes to numeric literals and explicit `(long)` casts where needed.

The change appears straightforward and well-scoped, addressing a clear compatibility issue. While the patch touches many lines, the modifications are mechanical and consistent. The commit message provides good context with links to both the failing CI run and cURL's release notes documenting the stricter type checking. This seems like a necessary update to keep Git building cleanly with newer cURL versions.
