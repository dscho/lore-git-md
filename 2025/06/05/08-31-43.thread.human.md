This thread addresses compiler warnings from cURL 8.14.0's stricter type checking, where Git passes `int` values where `long` is expected. Johannes Schindelin (Dscho) led a comprehensive 4-part series fixing these issues across multiple files, with Jeff King (Peff) contributing earlier Debian-focused fixes and reviewing the final work.

The solution involved three approaches: adding `L` suffixes to integer literals, explicit `(long)` casts for variables, and handling symbolic constants. The final patch focused on boolean/numeric flags in `http-push.c`, `http.c`, and `remote-curl.c`, completing coverage across all 23 `curl_easy_setopt()` calls in the codebase.

Peff raised an interesting observation in the final discussion - while the issues were first noticed on macOS, they actually affect all platforms, though different build configurations (Debian-packaged vs custom libcurl) surface different warnings. He approved the technical approach while noting the audit command might miss some edge cases with variables and symbolic constants. With no outstanding objections and all known cases addressed, this coordinated effort between Dscho and Peff has resolved the type safety warnings while maintaining runtime behavior. The thread demonstrates how platform-specific builds can reveal different facets of the same underlying issue.
