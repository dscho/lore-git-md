This is a follow-up in the ongoing `imap-send` feature/bugfix series, specifically addressing a critical logic error in the OAuth2.0 implementation that was caught during review. The issue was in the libcurl setup code where the password option was being incorrectly set for OAuth methods due to a flawed condition using `||` instead of `&&` when checking authentication methods. 

The patch in question (v12 02/10) contained a problematic condition that would always evaluate to true because `srvc->auth_method` couldn't match both "XOAUTH2" and "OAUTHBEARER" simultaneously. Jeff King identified this as a Coverity-reported issue where the logic would incorrectly set passwords for OAuth methods when it should skip password setup for these authentication types.

Aditya Garg confirms the fix was already incorporated into v13 of the series, which Junio Hamano had indicated he wouldn't merge until corrected. The corrected version properly uses `&&` to ensure the password is only set when the authentication method is neither XOAUTH2 nor OAUTHBEARER, maintaining the intended security boundary for OAuth flows.

This exchange shows the series undergoing rigorous review, with v13 now addressing all identified issues including this critical authentication logic fix. The thread context indicates the OAuth2.0 implementation is otherwise complete with both standard OAUTHBEARER and Google-proprietary XOAUTH2 protocols supported across OpenSSL and libcurl backends.
