This is part of Patrick Steinhardt's ongoing series to refactor Git's object database subsystem to remove `the_repository` global state. Patch 5/17 continues the mechanical conversion work by eliminating `the_repository` usage in `find_odb()`.

The patch renames `find_odb()` to `odb_find_source()` and changes its signature to take an `object_database` parameter instead of a `repository` pointer. This aligns with the series' goal of making ODB operations repository-agnostic. The function now operates directly on the object database structure that was passed in, rather than implicitly using `the_repository->objects`.

Three call sites are updated to use the new API - two in commit-graph operations and one in midx handling. Each now passes `the_repository->objects` explicitly rather than the repository itself. The function's behavior remains unchanged - it still locates an ODB source by path and dies if not found - but now does so without relying on global state.

The changes are straightforward mechanical conversions, following the pattern established in earlier patches. The commit message is concise but clear about the motivation (removing `the_repository` dependency) and effect (API change with caller updates). No new tests are added since this is a refactoring that maintains existing behavior.

This patch continues the series' systematic approach, tackling another piece of global state removal while maintaining backward compatibility through careful API evolution. The changes are limited to the ODB subsystem and its direct callers, keeping the scope well-contained.
