This is a review comment on the OAuth2.0 authentication support in the `imap-send` series. Junio Hamano raises two main concerns about the implementation details in patch 02/10:

First, he objects to the use of `#ifdef` preprocessor directives in the middle of the authentication flow logic, calling it "ugly" and criticizing the indentation style that attempts to hide them. This is a code organization issue that affects readability.

Second, he questions the logic for password handling in OAuth flows, pointing out that the current approach of explicitly excluding XOAUTH2 and OAUTHBEARER may not scale well as more authentication methods are added. He suggests adding a clarifying comment and raises concerns about future maintenance when new auth methods are introduced.

These are design-level critiques rather than functional issues - the patch already correctly implements the critical OAuth2.0 support that was missing in earlier versions. The concerns focus on long-term code maintainability and clarity rather than immediate functionality. The thread context shows this is part of a mature series (v13) that has already addressed several rounds of review feedback, with this being one of the final polish items before potential merging.
