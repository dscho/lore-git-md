This is a bugfix patch in the pack-bitmap subsystem, finalizing a v5 series that has already received maintainer approval. The patch addresses a memory leak in `find_boundary_objects()` where `roots_bitmap` wasn't being freed when `cascade_pseudo_merges_1()` succeeded. The fix unconditionally calls `bitmap_free(roots_bitmap)` after the cascade operation, since the bitmap is only used as a mutable reference.

The patch includes a new test case in t5333 that triggers the leak scenario by creating two commits (A and B), adding A to a pseudo-merge, then performing a boundary traversal from A to B. The test verifies the bitmap traversal works while implicitly checking for leaks under ASAN. The test setup has been simplified from v4 by removing redundant config settings and using direct numeric comparison.

Key technical details:
- Removes conditional `bitmap_free()` in pack-bitmap.c
- Adds test case demonstrating the leak scenario
- Uses `pack.useBitmapBoundaryTraversal` config
- Verifies commit count via direct numeric comparison (`test 1 -eq "$nr"`)
- Maintains ASAN leak detection capability

The patch represents the final approved version of this fix, having addressed all prior review feedback including shell portability concerns and test methodology validation. It's now in merge-ready state with consensus from all reviewers.
