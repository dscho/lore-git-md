This is a bugfix in the ongoing `imap-send` OAuth2.0 authentication series. Jeff King identifies a logic error in the libcurl setup code for OAuth authentication methods. The problematic condition would always evaluate to true due to incorrect use of `strcmp()` with OR (`||`) instead of AND (`&&`), meaning the password would incorrectly be set for OAuth methods where it shouldn't be.

The issue affects the handling of OAuth2.0 authentication methods (both OAUTHBEARER and XOAUTH2) in the libcurl backend. When either of these methods is specified via `srvc->auth_method`, the code should skip setting the CURLOPT_PASSWORD option since OAuth uses bearer tokens instead. The current implementation would incorrectly set the password in all cases due to the flawed logic.

This appears to be a straightforward fix that needs to adjust the condition to properly check that the auth method is neither XOAUTH2 nor OAUTHBEARER before setting the password. The patch is part of a well-reviewed series that has gone through 12 iterations, with this being a late-stage polish issue caught by static analysis (Coverity). The impact is limited to OAuth authentication scenarios in the libcurl backend of `imap-send`.
