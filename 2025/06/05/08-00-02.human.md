This is a bugfix in the ongoing `imap-send` OAuth2.0 authentication series. Jeff King (peff) points out a logical error in the OAuth2 authentication handling for the curl backend. The current code incorrectly uses `||` between two `strcmp()` checks, which means the condition will always evaluate to true (since `auth_method` can't simultaneously be both "XOAUTH2" and "OAUTHBEARER"). 

The fix needs to either:
1. Use `!strcmp()` for both checks if the intent is to match either OAuth method, or
2. Use `&&` between the comparisons if the goal is to match neither method

This appears to be a straightforward logic error in the OAuth2 implementation that was introduced in the series. While small, it's important to fix since it affects the core authentication flow when using OAuth with the curl backend. The issue was caught by Coverity static analysis, showing the value of automated code checking tools.

This patch is part of a larger v12 series that has already seen extensive review, with this being one of the final polish items before potential inclusion. The series as a whole adds comprehensive OAuth2 support to `imap-send`, including both standard OAUTHBEARER and Google's XOAUTH2 methods.
