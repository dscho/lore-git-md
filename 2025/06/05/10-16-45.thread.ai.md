Thread summary:

This thread addresses a CI/build system issue where certain test patterns involving `tee | git receive-pack` hang indefinitely on Windows/Meson environments due to a known MSYS2 runtime bug in Git for Windows v2.49.0. The core problem stems from faulty signal handling in MSYS2 runtime version 3.5.7-463ebcdc.x86_64, causing `tee` processes to not properly receive SIGPIPE when the receiving `git receive-pack` terminates, creating deadlock.

The solution introduces a `TEE_DOES_NOT_HANG` prerequisite that detects the problematic runtime via `uname -a` output and skips two affected tests in `t5410-receive-pack.sh`: `receive-pack missing objects fails connectivity check` and `receive-pack missing objects bypasses connectivity check`. This is a temporary workaround until GitHub runners update to Git for Windows v2.50.0 where the runtime bug is fixed.

Patrick Steinhardt initially reviewed Johannes Schindelin's patch, agreeing the current solution is sensible but briefly considering an alternative approach of rewriting tests to generate packfiles directly. Junio Hamano has now weighed in, endorsing the specific runtime version check as properly addressing the root cause rather than working around timing issues. Junio notes the lazy prerequisite provides good documentation value and indicates he will queue the patch, concluding this phase of discussion.

Technical context includes commit 68cb0b5253a0 which introduced one of the problematic test patterns. The solution follows Git's pattern of test skipping for platform-specific issues while maintaining coverage across the full CI matrix. The prerequisite check specifically targets MSYS2 runtime version 3.5.7-463ebcdc.x86_64, with the understanding this is temporary until the fixed Git for Windows v2.50.0 becomes standard in CI environments.
