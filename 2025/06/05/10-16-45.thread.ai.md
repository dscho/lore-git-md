Thread summary:

This thread addresses a CI/build system issue where certain test patterns involving `tee | git receive-pack` hang indefinitely on Windows/Meson environments due to a known MSYS2 runtime bug in Git for Windows v2.49.0. The core problem stems from faulty signal handling in MSYS2 runtime version 3.5.7-463ebcdc.x86_64, causing `tee` processes to not properly receive SIGPIPE when the receiving `git receive-pack` terminates, creating deadlock.

The current solution introduces a `TEE_DOES_NOT_HANG` prerequisite that detects the problematic runtime via `uname -a` output and skips two affected tests in `t5410-receive-pack.sh`: `receive-pack missing objects fails connectivity check` and `receive-pack missing objects bypasses connectivity check`. This is a temporary workaround until GitHub runners update to Git for Windows v2.50.0 where the runtime bug is fixed.

Patrick Steinhardt has reviewed Johannes Schindelin's patch and agrees the current approach is sensible given the temporary nature of the issue. While Patrick briefly considered an alternative approach of rewriting the tests to generate packfiles directly rather than using the problematic `tee | git receive-pack` pattern, he questions whether this would be worthwhile since the underlying MSYS2 runtime bug will be fixed in v2.50.0. The discussion leaves open the possibility of future test restructuring but confirms the immediate solution of skipping the affected tests when the faulty runtime is detected.

Technical context includes commit 68cb0b5253a0 which introduced one of the problematic test patterns. The change follows Git's established pattern of test skipping for platform-specific issues while maintaining coverage across the full CI matrix. The `TEE_DOES_NOT_HANG` prerequisite check specifically looks for the problematic MSYS2 runtime version (3.5.7-463ebcdc.x86_64) to determine when to skip the tests.
