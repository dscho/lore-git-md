Bugfix patch in the `imap-send` series, specifically addressing CRAM-MD5 authentication behavior when OpenSSL is unavailable. This patch modifies the error handling for CRAM-MD5 authentication in `imap-send.c` to fail early with a clear error message when OpenSSL support is not compiled in, rather than attempting authentication and dying. The change moves the CRAM-MD5 implementation earlier in the file and adds a compile-time check that gracefully exits if OpenSSL is missing (`NO_OPENSSL` defined).

The technical changes include:
- Moving the `auth_cram_md5()` function definition before its first use
- Adding an early exit path with a descriptive error message when OpenSSL is unavailable
- Setting `auth_cram_md5` to NULL in the non-OpenSSL case (matching the pattern used for other auth methods)
- Removing the old `cram()` function that would die() when called without OpenSSL

This completes the memory management fixes for CRAM-MD5 authentication that were started in earlier patches, ensuring all error paths are properly handled. The change is particularly relevant for users who might have CRAM-MD5 configured but build Git without OpenSSL support. The patch maintains consistency with the series' approach of improving error handling and user feedback.
