This is a bugfix addressing a build system regression in Git 2.50.0-rc1 that affects platforms building without TCL/Tk support (NO_TCLTK). The issue causes the build process to incorrectly delete all TCL files from git-gui/lib when tclsh is not found, rather than just cleaning up the intended tclIndex file.

The root cause was identified as a shell script syntax misunderstanding - the `$@` in generate-tclindex.sh was being interpreted as a shell variable (expanding to all arguments) rather than the intended Makefile syntax (referring to the target file). This behavior changed from Git 2.49 due to new TCL index generation infrastructure.

Junio Hamano confirms Johannes Sixt's analysis of the problem, noting the oversight was obvious in hindsight but missed during review. The fix will need to either modify the `rm` command to target only lib/tclIndex or remove the line entirely since the subsequent command overwrites the file anyway. This is a critical regression that affects all NO_TCLTK builds, with a temporary workaround available by setting NO_TCLTK=NoThanks in config.mak.

The patch appears well-analyzed and addresses a clear regression, though it's notable this build system change slipped through without normal review prior to rc0. The fix should be straightforward for maintainers to evaluate and merge.
