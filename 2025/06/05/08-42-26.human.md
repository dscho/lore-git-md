This is a feature and compatibility patch in the ongoing `imap-send` series, adding PLAIN authentication support for the OpenSSL backend. The patch fills a gap where PLAIN authentication (via RFC 4616) was only available when using libcurl, despite being a common method used by email providers for app passwords.

The implementation follows the same pattern as other auth methods in the series, adding a new `plain_base64()` helper function to construct the credentials string and an `auth_plain()` handler. The documentation is updated to reflect that PLAIN is now available for both backends. The change is cleanly integrated with the existing capability detection system via a new `AUTH_PLAIN` flag.

This is part of a larger effort (now at v13) to modernize `imap-send` with previous patches having added OAuth2.0 support and fixed critical bugs. The implementation looks solid, matching the style of other auth methods in the codebase and including proper error handling. Since PLAIN is a simpler protocol than OAuth or CRAM-MD5, this patch is relatively straightforward compared to others in the series, but completes an important piece of standard IMAP functionality.
