This is part of Patrick Steinhardt's ongoing series to remove `the_repository` global state from Git's object database subsystem, specifically focusing on submodule object access.

Patch 11/17 refactors how submodule object databases are handled when using `git grep --recursive`. Previously, submodule paths were tracked in a global string list, with special handling for `the_repository`. The patch moves this tracking into the `object_database` struct itself, making the mechanism repository-aware rather than relying on global state.

Key changes:
- Adds `submodule_source_paths` field to `struct object_database`
- Renames functions to use `odb_` prefix (`odb_add_submodule_source_by_path`)
- Removes global `added_submodule_odb_paths` list and related functions from submodule.c
- Updates callers in `builtin/grep.c` and `submodule-config.c`

The patch follows the established pattern from earlier in the series, maintaining the same behavior while removing global state dependencies. It's a straightforward mechanical conversion that builds on the infrastructure established in previous patches. The changes are well-contained and the commit message clearly explains the motivation and approach.
