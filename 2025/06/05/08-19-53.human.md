This is a v2 bugfix series addressing edge cases in batched reference updates, following up on Patrick Steinhardt's earlier work. The series has been simplified from v1 by Karthik Nayak after review feedback.

The first patch fixes a segfault in the files backend by properly skipping failed updates during batched transactions, with expanded test coverage in t1400-update-ref.sh that now includes more edge cases like deleting symbolic refs and refs with incorrect old OIDs. The tests no longer use quiet grep (-q) to ensure failures are properly detected.

The second patch restructures receive-pack's non-atomic execution to handle directory/file conflicts by processing deletions in a separate batch transaction first. This matches the approach used in git-fetch and resolves compatibility issues between batched and sequential updates. The implementation has been improved from v1 by replacing an XOR check with clearer phase-based processing (deletions first, then other updates).

Notably, the series drops v1's second patch about test description quotes after Eric Sunshine pointed out it was unnecessary. The changes maintain the safety of batched updates while fixing production issues encountered at GitLab, though they do mean receive-pack will now use exactly two transactions (still better than pre-batched behavior). Test coverage appears thorough, addressing both the segfault and F/D conflict scenarios.
