This is a critical bugfix in the ongoing `imap-send` OAuth2.0 authentication series, specifically addressing a logic error in the libcurl setup for OAuth methods. The issue was identified by Jeff King via Coverity static analysis and confirmed by Aditya Garg.

The problem stems from an incorrect logical operator in the password-setting condition for OAuth authentication methods. The current code uses `||` between strcmp() checks for "XOAUTH2" and "OAUTHBEARER", which would always evaluate to true (since auth_method can't be both simultaneously). Junio Hamano questions the underlying design, noting it's unclear whether the intent is to match either OAuth method (which would require !strcmp) or exclude both (which would need `&&`).

This patch is part of the broader effort to add OAuth2.0 support to `imap-send`, but the discussion reveals deeper design questions about how authentication methods should be handled. The current approach of special-casing OAuth methods may not scale well as new authentication mechanisms are added. The thread shows this is being treated as a blocking issue before the series can be merged, with Junio Hamano explicitly noting the need for correction.

Technical details: The fix involves modifying the condition in `setup_curl()` that determines when to set the CURLOPT_PASSWORD option. The incorrect version could potentially leak passwords into OAuth flows, while the corrected version (using `&&`) would properly exclude both OAuth methods from password-based authentication. This touches core security boundaries in the authentication flow between `imap-send` and libcurl.
