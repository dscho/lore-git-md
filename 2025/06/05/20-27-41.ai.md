This is a build system regression investigation, continuing the thread about missing TCL files in Git 2.50.0-rc1 tarballs. Randall Becker provides new evidence that the issue stems from the build process itself deleting the TCL files rather than a tarball generation problem. 

The key observation is that while `git ls-tree` shows the TCL files should exist in the git-gui/lib directory, they disappear during the build process when `generate-tclindex.sh` runs. The script fails with "tclsh: command not found" (expected in NO_TCLTK builds) and appears to be removing the source files as a side effect. This behavior changed from Git 2.49, suggesting the new generate-tclindex.sh script introduced in the build system changes may be responsible.

The technical details show the build command explicitly setting SHELL=/usr/coreutils/bin/bash and various compilation flags, but the critical failure occurs in the TCL index generation step. The error suggests the build system isn't properly handling the NO_TCLTK case, attempting to process TCL files that should be skipped entirely when TCL support is disabled.

This shifts the focus from the earlier theories about tarball corruption or wildcard expansion to a clear build system bug where the new TCL processing infrastructure is incorrectly modifying source files during a NO_TCLTK build. The regression affects all platforms building without TCL/Tk support.
