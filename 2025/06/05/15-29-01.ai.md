This is the final v5 patch in a series addressing memory leak fixes in pack-bitmap.c, specifically in the `find_boundary_objects()` function. The patch removes a conditional check before calling `bitmap_free(roots_bitmap)` to ensure cleanup happens regardless of whether `cascade_pseudo_merges_1()` succeeds or fails. The original code would only free the bitmap on failure, leading to leaks when the function succeeded.

The patch includes a new test case in t5333 that demonstrates the leak scenario by creating commits A and B, setting up a pseudo-merge configuration, and verifying boundary traversal behavior. The test uses `pack.useBitmapBoundaryTraversal` config and validates the commit count via `git rev-list --count`.

Junio Hamano notes the patch appears to fix what was likely an oversight in commit 11d45a6e, where the original code's conditional freeing logic suggested an intent to leak on success. The test methodology uses a temporary repository with simple configuration, which reviewers found clear and appropriate.

The series has completed full review with maintainer approval, addressing all technical concerns including shell portability and test validation. This represents the final merge-ready version of the fix, establishing a pattern for ASAN-based leak detection in bitmap-related tests.
