This is part of Patrick Steinhardt's ongoing refactoring series to remove `the_repository` global state from Git's object database (ODB) subsystem (patch 4/17 in v5). The patch introduces parent pointers between ODB components to maintain repository relationships without relying on globals.

The key technical changes are:
1. Adds `repo` pointer to `struct object_database` to track owning repository
2. Adds `odb` pointer to `struct odb_source` to track owning object database
3. Modifies `odb_new()` to require and store the repository parameter
4. Updates alternate ODB handling functions (`link_alt_odb_entry`, `read_info_alternates` etc.) to propagate the ODB pointer through call chains
5. Ensures parent pointers are properly initialized when creating new ODB sources

The changes affect core ODB operations like alternate handling and repository initialization, with modifications to `odb.c`, `odb.h`, and `repository.c`. The patch maintains backward compatibility while enabling future work to access repository-specific configuration without `the_repository`.

This is a mechanical but important step in the larger refactoring, establishing the pointer relationships needed to fully eliminate global state dependencies in subsequent patches. The changes are straightforward and well-contained within the ODB subsystem.
