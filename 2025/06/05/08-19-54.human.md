This is a bugfix patch for the files backend's batched reference updates, part of a v2 addressing production issues found by GitLab's Gitaly service. The patch fixes a segfault that could occur when processing failed updates in batched transactions.

The core issue is that two loops in `files_transaction_finish()` weren't properly skipping updates that had already failed (marked with `rejection_err`), which could lead to crashes. The fix adds the missing skip checks in both loops that handle reference deletions and directory cleanup.

The patch includes three new test cases in `t1400-update-ref.sh` that verify the fix works for different failure scenarios: deleting a symbolic ref pointing to a non-existent target, deleting a ref with an incorrect old OID, and deleting a non-existent ref. The tests explicitly check the error output rather than using quiet grep flags, making failures more visible.

This appears to be a straightforward and well-tested fix for a real production issue. The changes are minimal and focused, just adding the missing skip conditions where they logically belong. The test coverage is thorough, exercising the failure cases that could trigger the segfault. As part of the v2 series that has already addressed reviewer feedback, this patch seems ready for inclusion.
