This is a bugfix in the ongoing `imap-send` OAuth2.0 authentication series. Jeff King spotted a logic error in the libcurl setup code where the password option was being set incorrectly for OAuth methods. The condition intended to skip password setting for OAuth2.0 methods (XOAUTH2/OAUTHBEARER) was flawed - it would always evaluate to true due to using OR (`||`) instead of AND (`&&`) between the comparisons. Aditya Garg confirms this was meant to avoid setting passwords for OAuth flows and will fix the logic in the next version.

Junio Hamano notes he'll hold off merging until the corrected version arrives. This is a straightforward fix for a clear-cut issue caught by static analysis, and since it's part of the well-reviewed v12 series (now at v13), the resolution should be uncontroversial. The patch maintains the series' goal of proper OAuth2.0 support while fixing an implementation bug in the libcurl backend.
