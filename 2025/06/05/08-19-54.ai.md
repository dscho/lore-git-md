Bugfix for batched reference updates in the files backend. This is the first patch in a two-part series addressing production problems with batched ref updates (23fc8e4f61), now at v2.

The patch fixes a segfault in `refs/files-backend.c` where failed updates in batched transactions weren't properly skipped during two critical loops in `files_transaction_finish()`. The fix adds checks for `update->rejection_err` in both the directory cleanup and lock release phases, ensuring failed updates are consistently skipped.

Test coverage is expanded in `t/t1400-update-ref.sh` with three new scenarios: deleting an incorrect symbolic ref, deleting with wrong old_oid, and deleting non-existent refs. The tests verify error messages are properly surfaced rather than causing crashes. This builds on the thread's earlier discussion about ensuring complete test coverage for batched update edge cases.

The changes are straightforward and address a clear production issue, with the test additions matching the pattern established in the thread for validating batched update behavior. The patch maintains the existing transaction semantics while fixing the crash risk. This appears ready for integration as part of the v2 series.
