This is a CI/build system patch addressing a test hang specific to Windows/Meson environments. The patch works around a known MSYS2 runtime bug in Git for Windows v2.49.0 that causes certain `tee | git receive-pack` test patterns to hang indefinitely in CI.

The issue stems from faulty signal handling in the MSYS2 runtime (version 3.5.7-463ebcdc.x86_64) where `tee` processes don't properly receive SIGPIPE when the receiving `git receive-pack` terminates. This creates a deadlock situation where the test hangs until CI timeout. The patch introduces a `TEE_DOES_NOT_HANG` prerequisite that detects the problematic runtime and skips two affected tests in `t5410-receive-pack.sh` that use this pattern.

The author notes this is a temporary workaround until GitHub runners update to a newer Git for Windows version (expected with v2.50.0). The tests still run in other CI configurations (`win test` and `vs test` jobs) where the runtime bug is already addressed. The change follows a pattern of test skipping for platform-specific issues while maintaining coverage across the full CI matrix.

Key technical details for future reference:
- Tests affected: `receive-pack missing objects fails connectivity check` and `receive-pack missing objects bypasses connectivity check`
- Detection mechanism: Checks `uname -a` output for the specific buggy MSYS2 runtime version string
- Related commit: 68cb0b5253a0 which introduced one of the problematic test patterns
- Alternative approach considered (from Patrick Steinhardt) referenced but not detailed in this patch
