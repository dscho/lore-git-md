This is a bugfix in the ongoing `imap-send` OAuth2.0 authentication series, specifically addressing a logic error in the libcurl setup code. The issue was identified by Jeff King and confirmed by Aditya Garg - the condition to skip password setting for OAuth methods was incorrectly written using `||` between `strcmp()` checks, making it always true since the auth method can't match both strings simultaneously. The correct logic should use `&&` to properly skip password setting when the method is either XOAUTH2 or OAUTHBEARER.

The patch is part of v12 of the series (now at v13) that introduces comprehensive OAuth2.0 support to `imap-send`. This particular fix ensures proper credential handling when using OAuth authentication methods with the libcurl backend. Junio Hamano notes he'll hold off merging until the corrected version is submitted, indicating this is a critical fix that needs to be addressed before the series can proceed.

The thread context shows this is one of several authentication-related fixes in the series, which also includes OpenSSL backend support, memory management improvements, and new user-facing features like folder listing. The OAuth2.0 implementation supports both RFC-standard OAUTHBEARER and Google's XOAUTH2 methods, making this a significant enhancement to Git's email sending capabilities.
