Memory leak fix follow-up with test coverage proposal. Junio Hamano responds to Patrick Steinhardt's question about why CI didn't catch the `prepare_show_merge()` memory leak by proposing a new test case for `git show --merge` functionality. The test creates an artificial unmerged index state with conflicting blobs and verifies `git show --merge` can handle it, which would exercise the previously untested code path where the leak occurred.

The proposed test demonstrates Git's test infrastructure capabilities by:
1. Creating merge state without an actual merge using `MERGE_HEAD`
2. Generating multiple blob objects with different permissions
3. Setting up index conflicts manually via `update-index --index-info`
4. Verifying `show --merge` works in this conflicted state

This moves the thread forward from just fixing the leak to addressing the test coverage gap that allowed it to go unnoticed. The test case serves both as a regression test for the fixed leak and as documentation of expected `show --merge` behavior with unmerged changes. The technical focus remains on revision.c's merge handling while expanding to test infrastructure considerations.
