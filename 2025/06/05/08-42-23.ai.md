This is a feature and bugfix series for `imap-send`, now in its 13th iteration, that makes the command usable again after configuration parsing regressions and adds OAuth2.0 authentication support. The series has undergone extensive review and refinement, with v13 fixing a critical logic error in the OAuth2.0 authentication check that was using incorrect OR operators instead of AND in the libcurl setup code.

The series addresses multiple aspects of IMAP functionality:
1. Fixes the configuration parser bug that made `imap-send` unusable since Git 2.46.0 by incorrectly NULLing the folder field
2. Implements OAuth2.0 support via both OAUTHBEARER and XOAUTH2 protocols for OpenSSL and libcurl backends
3. Adds PLAIN authentication method for OpenSSL
4. Fixes memory leaks in CRAM-MD5 authentication
5. Introduces new `--folder` command-line option to override configuration
6. Adds `--list` option to show available IMAP folders
7. Includes various UX improvements like showing port numbers in credential prompts and destination folder during sending

The technical changes span configuration parsing, authentication handlers, IMAP protocol handling, and new folder listing functionality. The series touches `imap-send.c` extensively, along with documentation updates for both config and command usage. The v13 change specifically corrects the authentication method check that could incorrectly set passwords for OAuth methods due to flawed `strcmp()` conditions.

This appears to be the final polished version of a comprehensive improvement to `imap-send`, having addressed all major review feedback over 12 previous iterations. The changes are focused on correctness (fixing the critical auth logic error), completeness (all authentication methods now properly guarded), and consistency (documentation formatting, error message style). The series is likely ready for final consideration with all outstanding technical issues resolved.
