This is part 12/17 of Patrick Steinhardt's series to remove `the_repository` global from Git's object database subsystem. The patch continues the mechanical conversion work by eliminating remaining internal uses of `the_repository` in odb.c, allowing the removal of the `USE_THE_REPOSITORY_VARIABLE` preprocessor define.

The changes are straightforward plumbing - functions that previously relied on the global now take an explicit `struct repository *` parameter. Key conversions include:
- `fill_alternate_refs_command()` now uses `repo_config_get_value()` instead of the config global
- `read_alternate_refs()` passes through the repository parameter
- Object parsing functions now use the repository's hash algorithm
- Several helper functions like `oidclr()` and `convert_object_file()` now use the passed repository

The patch follows the established pattern from earlier in the series, completing the conversion of odb.c to be fully repository-aware. With this change, the object database subsystem no longer depends on `the_repository` at all. The changes are mechanical but important for the larger goal of removing global state and enabling pluggable ODB backends.

This continues the series' steady progress - the changes are uncontroversial and follow the same approach reviewers have already blessed in previous patches. The removal of the preprocessor define marks a notable milestone in eliminating this global dependency.
