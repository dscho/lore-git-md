This is the final patch in a 13-part series adding OAuth2.0 support and other improvements to `imap-send`. It introduces a new `--list` option that shows available IMAP folders, addressing the common problem where different servers (Gmail, Outlook, etc. use different naming conventions for standard folders like Drafts and Trash.

The implementation works for both OpenSSL and libcurl backends, following RFC6154 for OpenSSL and libcurl's example code for its implementation. The output shows folder flags (like `\HasNoChildren`) and paths, helping users identify the correct folder names to use in configuration. The patch includes documentation updates and handles the case where no folder is specified when listing.

Key technical details:
- Adds `list_folders` flag and `--list` option to command-line interface
- Implements `list_imap_folders()` for OpenSSL backend using IMAP LIST command
- Implements `curl_list_imap_folders()` for libcurl backend
- Modifies `buffer_gets()` to show LIST responses when in verbose mode or listing folders
- Updates documentation with usage and example output
- Maintains backward compatibility with existing folder specification behavior when not listing

This completes the series' goal of providing comprehensive IMAP functionality, with this patch solving the practical problem of discovering server-specific folder names that was previously only documented through trial-and-error.
