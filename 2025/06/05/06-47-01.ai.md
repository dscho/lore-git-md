This is part of Patrick Steinhardt's ongoing series to remove `the_repository` global state from Git's object database subsystem (patches 11/17). The patch focuses on submodule object source handling during operations like `git grep --recursive`.

The change moves submodule ODB tracking from a global string list in `submodule.c` to being repository-specific by storing the paths in the `object_database` struct itself. Key changes include:
- Adds `submodule_source_paths` string list to `struct object_database`
- Introduces `odb_add_submodule_source_by_path()` to replace `add_submodule_odb_by_path()`
- Implements `register_all_submodule_sources()` to replace `register_all_submodule_odb_as_alternates()`
- Removes the old global implementations and their declarations from submodule.{c,h}

The patch maintains the same behavior while eliminating global state - submodule paths are still registered as alternates when objects can't be found, just now via the repository's ODB rather than a global list. The change affects several call sites including `builtin/grep.c` and `submodule-config.c`.

This continues the series' pattern of methodically converting global ODB access to repository-specific handling while maintaining backward compatibility. The changes are mechanical but important for the larger goal of enabling pluggable ODB backends.
