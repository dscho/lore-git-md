This is a v2 bugfix series addressing edge cases in batched reference updates, following up on Patrick Steinhardt's earlier work. The series now contains two patches after dropping an unnecessary test description change from v1.

The first patch fixes a segfault in the files backend by properly skipping failed updates during batched transactions. It adds new test cases in `t/t1400-update-ref.sh` covering deletion of symbolic refs and refs with incorrect old OIDs, removing the quiet grep flag from earlier tests to make failures more visible.

The second patch modifies `execute_commands_non_atomic()` in `builtin/receive-pack.c` to handle file/directory conflicts by splitting deletions into a separate batch transaction first. The implementation has been restructured from v1's XOR-based approach to use explicit phase-based processing (deletions first, then other updates), addressing readability concerns raised about the `only_deletions` flag. The commit message notes this now uses exactly two transactions, maintaining the safety benefits of batching while fixing the F/D conflict issue.

Key technical changes include:
- New test cases for files backend edge cases in `t1400-update-ref.sh`
- Restructured transaction handling in `builtin/receive-pack.c` using `PHASE_DELETIONS`/`PHASE_OTHERS` phases
- Removal of the `only_deletions` flag in favor of explicit phase-based processing
- Confirmation that the two-transaction approach is still better than pre-batching behavior

The series builds on commits 23fc8e4f61 (original batched refs) and 9d2962a7c4 (batched updates in receive-pack), with test coverage expanded in `t1400-update-ref.sh`, `t5516-fetch-push.sh`, and `t1416-ref-transaction-hooks.sh`. The changes address real production issues encountered at GitLab while maintaining the performance benefits of batched updates.
