This is a platform compatibility patch addressing a build issue with cURL 8.14.0 on macOS. The patch changes how integer parameters are passed to `curl_easy_setopt()` calls, explicitly converting them to `long` type to match cURL's expectations.

The issue surfaced in Git's CI when Homebrew updated to cURL 8.14.0, which introduced stricter type checking in its headers. The compiler warnings indicate `curl_easy_setopt()` expects `long` arguments, but Git was passing `int` values. The patch systematically updates all affected calls across four files (`http-push.c`, `http.c`, `imap-send.c`, and `remote-curl.c`), adding `l` suffix to integer literals and explicit `(long)` casts where needed.

Key changes include updating boolean flags (0/1 to 0l/1l), numeric parameters like port numbers and timeouts, and enum values used with cURL options. The patch appears straightforward and mechanical, directly addressing the compiler warnings without introducing functional changes. The commit message provides clear context linking the change to specific cURL version changes and includes a reference to the failing CI run.

This is a maintenance change that will be important for anyone building Git with newer cURL versions, particularly on macOS, but doesn't affect runtime behavior. The patch is narrowly focused and appears to be correctly implemented based on the cURL API requirements.
