Bugfix follow-up to already-merged memory leak series in pack-bitmap.c. This is a minor post-merge correction to the v5 series that fixed bitmap boundary traversal leaks, now addressing a remaining conditional-free issue that slipped through initial review.

The patch removes a problematic conditional in `find_boundary_objects()` that only freed the `roots_bitmap` when `cascade_pseudo_merges_1()` failed. Since the function uses the bitmap as a mutable reference without taking ownership, this created a memory leak on success paths. The fix makes `bitmap_free(roots_bitmap)` unconditional, matching the established pattern from the main series.

A new test case in t5333 demonstrates the leak scenario by creating commits A and B, adding A to a pseudo-merge, then performing a boundary traversal A..B. This exercises the success path where the leak would occur. The test validates both the leak fix and correct traversal behavior by checking the commit count.

This appears to be a straightforward cleanup of an oversight in the original implementation. The change is minimal (2-line code change) and well-justified, with the new test providing clear validation. Since the core approach was already reviewed and merged in v5, this follow-up seems uncontroversial. The patch maintains all the series' established patterns including ASAN leak detection and repository config usage.
