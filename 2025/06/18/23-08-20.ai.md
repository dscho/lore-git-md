Refactoring patch in a series improving submodule remote lookup logic, specifically moving a function to enable future changes. This is part 6/7 of Glen Choo and Jacob Keller's ongoing work to make submodule remote handling more robust, particularly around renamed remotes and `the_repository` removal.

The patch relocates `get_default_remote_submodule()` in `builtin/submodule--helper.c` to appear after `resolve_relative_url()`. The commit message explains this is preparatory work for a future refactor where `get_default_remote_submodule()` will depend on `resolve_relative_url()`, which itself depends on `get_default_remote()`. The change is purely code movement with no functional modifications - the function's implementation remains identical, just positioned differently in the file.

Key technical details:
- Moves `get_default_remote_submodule()` function definition down in the file
- Keeps all existing functionality including:
  - Submodule initialization via `repo_submodule_init()`
  - Default remote lookup via `repo_default_remote()`
  - Memory management with `xstrdup()` and `repo_clear()`
- Maintains same error handling for failed submodule initialization
- Preserves surrounding context including `each_submodule_fn` typedef and other helper functions

This appears to be a straightforward preparatory change that enables cleaner future patches in the series. The commit message clearly explains the motivation for the move, and the patch itself is minimal and focused. As part of the larger series, it contributes to the goal of improving submodule remote handling while removing `the_repository` dependencies.
