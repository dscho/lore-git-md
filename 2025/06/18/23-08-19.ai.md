This is part 5 of a 7-patch series improving submodule remote lookup logic, focusing on refactoring the fallback remote name determination. The patch comes from Jacob Keller and builds on Glen Choo's broader submodule remote handling improvements.

The change refactors how submodule--helper determines the default remote name when no branch-specific remote is configured. Previously, it would always fall back to "origin", which could break if users renamed their remotes. The new approach reuses the more robust logic from remotes_remote_for_branch(), which first checks for a single remote before falling back to "origin". This is implemented via a new repo_default_remote() function in remote.c that properly handles repository parameterization.

Key technical changes include:
- Adds repo_default_remote() to remote.h/remote.c that uses remotes_remote_for_branch() logic
- Replaces repo_get_default_remote() calls in submodule--helper.c with the new function
- Introduces repo_branch_get() helper to support repository parameterization
- Maintains xstrdup behavior for compatibility with existing callers
- Adds a test case in t7406 verifying behavior with renamed remotes

The patch continues the series' theme of making remote handling more robust while removing the_repository dependencies. It's a focused improvement that handles an edge case better while maintaining backward compatibility. The test coverage is thorough, including a scenario with renamed remotes.
