Refactoring patch in the submodule remote lookup series, focusing on branch merge configuration cleanup. This is part 1/7 of v3, building on previous work to improve submodule remote handling reliability.

The patch addresses memory management issues in the branch struct's merge configuration handling. Currently, branch->merge_name duplicates information stored in branch->merge, leading to confusion and potential crashes when branch_release() assumes merge is always set when merge_nr is non-zero. The solution removes merge_name entirely, consolidating all merge tracking into the merge array of refspec_items.

Key technical changes:
- Removes branch->merge_name field, replacing with set_merge flag
- Moves merge array allocation from set_merge() to add_merge()
- Adds merge_clear() helper to properly free all merge-related memory
- Updates all callers to use merge[i]->src instead of merge_name[i]
- Fixes memory leaks in branch_release() and set_merge() paths
- Maintains backward-compatible behavior while simplifying the code

The changes affect remote.c, remote.h, branch.c, and builtin/pull.c, with callers updated to use the new consolidated merge tracking approach. This appears to be a well-considered cleanup that addresses both memory safety and code clarity issues in the branch merge configuration system.
