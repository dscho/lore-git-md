This is the second patch in a performance optimization series for `git fetch --prune`. It follows up on the first patch's refactoring by removing now-unused code.

The patch removes `refs_warn_dangling_symref()`, a helper function that checked for dangling symrefs one ref at a time. This function became obsolete after the first patch changed the implementation to use a more efficient batch approach with `string_list` operations. The removal is straightforward - just deleting the function and cleaning up related data fields that are no longer needed.

This is a clean-up change that depends on the first patch's restructuring of the prune operation. The series as a whole aims to dramatically improve performance when pruning many refs (from O(N^2) to O(N*logN)), with the tradeoff of slightly changing the output format (grouping warnings together rather than interleaving them with deletion messages). The performance gains are substantial (410s -> 4s in one test case), making this likely worth the output format change.

The patch appears well-contained and mechanically correct, removing only code that is confirmed unused after the first patch's changes. It continues the thread's focus on simplifying the ref handling code while improving performance.
