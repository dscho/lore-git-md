This thread covers a patch series by Glen Choo (with contributions from Jacob Keller) that improves submodule remote lookup logic, particularly when dealing with renamed remotes. The series transitions from name-based to URL-based remote matching where possible, since parent projects already know submodule URLs from .gitmodules and config files. This is part of Git's broader effort to remove reliance on the `the_repository` global variable.

The series went through several iterations, with v3 representing a significant simplification by completely removing the `branch->merge_name` field. Junio C Hamano has now acknowledged the series, indicating he will apply it to the main tree with his brief "Sounds nice. Will replace." comment. The final version (v4) introduced `repo_remote_from_url()` for URL-based remote lookup while maintaining all fallback paths, and modified `get_default_remote_submodule()` to try URL matching first before falling back to name-based logic.

The changes make submodule remote handling more robust, especially in scenarios involving renamed remotes, while aligning with Git project's direction of reducing name dependencies. The series has seen smooth progress through review, with Jacob Keller contributing several patches in the later versions. With Junio's ack, this work is now complete and will be part of an upcoming Git release.
