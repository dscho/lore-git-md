This thread covers a patch series by Glen Choo (with contributions from Jacob Keller) that improves submodule remote lookup logic, particularly when dealing with renamed remotes. The series transitions from name-based to URL-based remote lookups where possible, since parent projects already know submodule URLs from .gitmodules. This is part of the broader effort to remove reliance on the `the_repository` global variable.

The v4 series is complete and had been acked by maintainer Junio Hamano after v3, pending resolution of a regression found in t5582 pull/fetch tests. The regression stemmed from patch 1/7's removal of `branch->merge_name` while some code paths still depended on its null-check behavior. Lidong Yan has now identified and proposed a fix for this issue - updating `branch_has_merge_config()` to check `branch->set_merge` instead and using proper memory management in `merge_release()`. The fix is minimal (just 2 lines) but critical, and Yan reports it resolves the t5582 test failures locally.

The series includes 7 parts plus this regression fix, with the final patch introducing `repo_remote_from_url()` for URL-based remote lookup while maintaining all fallback paths. Previous parts refactored remote.c to remove `the_repository`, improved memory management, and added robust fallback behavior. With this regression addressed, the series appears ready for final application by Junio.
