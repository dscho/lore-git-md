Glen Choo's submodule remote lookup series has reached its final form after addressing a regression. The v4 patch set improves how Git handles submodule remotes, particularly when remotes have been renamed, by transitioning from name-based to URL-based lookups where possible. This is part of the broader effort to remove reliance on the `the_repository` global variable.

The series was nearly ready after Jacob Keller contributed parts 5-7 and Junio Hamano acked v3, but a segfault was discovered in fetch operations during testing. Lidong Yan diagnosed the issue - part 1's removal of `branch->merge_name` didn't properly maintain null-check behavior that some code paths still needed. His fix is minimal but effective: checking the `set_merge` flag instead and improving memory safety with `FREE_AND_NULL`. With this regression resolved, the maintainer can now apply the complete v4 series, which includes URL-based remote matching, better fallback behavior, and various refactorings to make submodule remote handling more robust.
