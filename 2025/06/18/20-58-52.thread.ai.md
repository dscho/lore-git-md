Reftable performance investigation: network clone bottleneck due to 4KB block writes. Haylin Moore reports observing suboptimal performance during clones over network mounts, tracing to reftable_writer using DEFAULT_BLOCK_SIZE (4096) for small serial operations (~3ms per write). The reftable.adoc documentation mentions block size in a way that suggests configurability, but current code lacks visible configuration mechanism. Open question whether this is intentional limitation or oversight - no clear path exists to adjust block sizes for network optimization scenarios. Investigation focuses on understanding current behavior before proposing changes, with potential directions being either documentation clarification or enhancement to support configurable sizes.
