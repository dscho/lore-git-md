Feature and bugfix patch completing a series to improve submodule remote handling. This is the final patch (7/7) in Jacob Keller's v3 series addressing fragility in submodule remote lookups, particularly when users rename remotes.

The patch introduces URL-based remote lookup as the primary method for submodules, falling back to name-based lookup only when needed. It adds a new `repo_remote_from_url()` helper that finds remotes by matching their configured URLs against the submodule's known URL (from .gitmodules or config). This is more robust than the previous name-based fallback to "origin", which would fail if the remote was renamed.

The change maintains backward compatibility by keeping the existing fallback logic (via `repo_default_remote()`) for cases where URL matching fails, such as when users manually change submodule URLs. Tests verify the new behavior works with renamed remotes and multiple remote configurations.

This completes the series' transition from name-based to URL-based submodule remote resolution, making the system more resilient to common configuration changes while remaining part of the broader `the_repository` removal effort. The implementation is clean with thorough test coverage, addressing a real pain point for users who rename their default remotes.
