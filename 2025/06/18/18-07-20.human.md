CI / build system patch that improves platform compatibility for dirent handling.

This patch from Junio C Hamano adds a new Coccinelle rule to catch direct accesses to the `d_type` member in `struct dirent`, which isn't portable across all platforms. The rule enforces use of the `DTYPE()` macro instead, with exceptions for emulation code paths that specifically handle platforms where the member exists.

The change is narrowly focused on this portability issue, explicitly excluding two functions (`finddata2dirent` and `precompose_utf8_readdir`) that are part of platform-specific emulation code. The commit message notes this might not be sufficient to catch all cases where fallback code would be needed, suggesting this could be an initial step toward more robust handling.

This appears to be a straightforward improvement to make Git's build system more portable, though the author acknowledges it may need follow-up work to handle all edge cases. The patch is cleanly implemented as a new Coccinelle rule that should help prevent future direct `d_type` accesses from being introduced.
