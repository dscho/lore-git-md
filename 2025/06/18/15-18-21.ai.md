This is a feature patch improving signature handling in Git's fast-export/fast-import, specifically addressing limitations in the output format for signed commits. It builds on the experimental signature support added in d9cb0e6ff8.

The patch enhances the signature format to include both the Git object hash algorithm (SHA-1/SHA-256) and the signature type (OpenPGP/X.509/SSH/unknown). Key changes include:

1. Support for exporting/importing both SHA-1 and SHA-256 signatures from the same commit
2. Warning messages when multiple signatures of the same hash type are found
3. Clear documentation of the new "gpgsig <hash-algo> <format>" syntax
4. New helper functions in gpg-interface.{c,h} to identify signature formats
5. Test cases for X.509 and SSH signatures (though no test yet for dual SHA-1/SHA-256 signatures)

The implementation handles signatures more robustly while maintaining backward compatibility with the experimental warning. The author notes this is a refinement of earlier approaches (v1 focused just on format, v2 attempted signature checking) and acknowledges help from brian m. carlson and Elijah Newren.

Technical details for future reference:
- New gpg-interface functions: get_signature_format(), valid_signature_format()
- Signature storage struct in fast-import.c with hash_algo/sig_format fields
- Warning system for multiple signatures per hash type
- Documentation updates in both fast-export and fast-import manpages
- Test coverage for OpenPGP/X.509/SSH formats (t9350)
- Outstanding question about generating test commits with dual signatures

The patch appears well-constructed with thorough documentation and test coverage, though the lack of a test for the dual-signature case (a key feature) is noted as a current limitation. The changes align with the thread's focus on proper hash algorithm representation while expanding signature format support.
