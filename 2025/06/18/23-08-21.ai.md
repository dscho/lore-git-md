Final patch in a series improving submodule remote lookup logic, focusing on URL-based remote matching. This is part of the ongoing effort to make submodule remote handling more robust, particularly when users rename remotes.

The patch introduces `repo_remote_from_url()` which looks up remotes by URL rather than name, addressing cases where the default remote name has been changed (e.g. via `clone.defaultRemoteName`). The modified `get_default_remote_submodule()` first tries URL-based matching before falling back to the existing name-based logic, maintaining backward compatibility while fixing the renamed-remote case. The change ensures submodule updates continue working even when remotes are renamed.

Key technical details:
- New `repo_remote_from_url()` helper iterates remotes to find URL matches
- `get_default_remote_submodule()` now:
  1. Gets submodule URL from .gitmodules/config
  2. Tries URL-based lookup via new helper
  3. Falls back to existing name-based logic (branch-specific -> single-remote -> "origin")
- Handles relative URLs by resolving them first
- Includes test case verifying behavior with renamed remotes
- Maintains existing remote ref updates rather than direct URL fetching

This completes the series' transition from name-based to URL-based submodule remote resolution where possible, while preserving all existing fallback paths. The implementation builds on previous patches that refactored remote handling and moved path-checking utilities.
