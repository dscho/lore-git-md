This is a platform compatibility fix addressing a regression in `diff --no-index` behavior on systems without `d_type` in `struct dirent`. Junio Hamano identifies a critical flaw in the previously proposed solution - while using the `DTYPE()` macro allows compilation on AIX/NonStop, it incorrectly reports all entries as non-directories (since `DTYPE()` returns `DT_UNKNOWN` on these platforms). This would break pathspec matching against directories.

The proposed fix introduces proper directory detection by:
1. First trying the direct `d_type` if available
2. Falling back to `lstat()` when `d_type` is unavailable
3. Maintaining the existing pathspec matching logic but with accurate directory information

The change affects `diff-no-index.c` where filesystem entries are examined during pathspec-limited diff operations. This is a more robust solution than the original `DTYPE()` wrapper approach, though it comes with the cost of additional system calls on platforms without `d_type`. The thread shows consensus on the technical problem but now reveals this deeper behavioral issue that needs addressing.
