Bugfix targeting remote.c memory management, part of Glen Choo's submodule remote lookup series (v3). This patch fixes a memory leak in `remote_clear()` where the `push` and `fetch` refspec fields weren't being freed. The issue becomes visible when `remote_clear()` is called for submodule repositories (as planned in later patches) rather than just `the_repository` where the values never go out of scope.

The change is straightforward - adding `refspec_clear()` calls for both refspec fields. While this leak wasn't caught by sanitizers in the main repository case, it would be detected when used with submodule repositories. The fix is minimal (3 lines added) and clearly correct, maintaining consistency with how other remote struct fields are handled.

This appears to be preparatory work for the larger series' goal of making submodule remote handling more robust. The patch doesn't directly implement new functionality but cleans up infrastructure that will be used by subsequent patches. The commit message clearly explains both the current benign-but-wrong state and why the change is needed for future work.
