Performance investigation regarding reftable block size limitations during network operations.

Haylin Moore reports observing suboptimal performance during Git clones over network mounts, tracing the issue to small 4KB write operations. The investigation points to the reftable_writer using DEFAULT_BLOCK_SIZE (4096) as its default block size, though the code path setting this value isn't immediately clear. The email questions whether this block size is configurable, noting that reftable.adoc documentation mentions the block size in a way that suggests possible configurability, though it's unclear if this is just for internal development purposes.

Key technical details include:
- The performance bottleneck manifests as many small serial writes (each taking ~3ms)
- The reftable_writer appears to default to 4KB blocks
- The configuration documentation in reftable.adoc ambiguously references block size
- No clear configuration mechanism is currently visible in the code

This appears to be a legitimate performance investigation that could lead to either a documentation clarification or a potential enhancement to make block sizes configurable for network operations. The email doesn't propose a specific patch but rather seeks clarification about current behavior and possible configuration options.
