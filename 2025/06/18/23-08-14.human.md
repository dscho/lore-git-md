This is a feature and refactoring series improving submodule remote lookup logic. Jacob Keller proposes several changes to make submodule remote handling more robust, particularly when users rename remotes from the default "origin".

The series starts with some preparatory cleanups: fixing memory leaks in remote/branch handling, moving utility functions to shared headers, and making remote.c functions work with submodule repositories. The main improvement comes in later patches where the logic first tries to match submodule remotes by their configured URL (which is stored in the parent project) before falling back to name-based lookup. This makes the system more reliable when users rename remotes.

The changes appear well-considered, with thorough commit messages explaining each step. The v3 iteration simplifies the branch->merge_name handling and fixes all identified memory issues. Test coverage looks solid with new cases in t7406. This seems like a worthwhile improvement to submodule usability, especially for users who customize their remote names. The approach of preferring URL matching over name matching is sensible given how submodules are typically configured.
