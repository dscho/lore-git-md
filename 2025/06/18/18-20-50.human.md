This is a bugfix discussion about portability issues in `diff --no-index` on platforms without `d_type` in `struct dirent`. Junio Hamano responds to Carlo Marcelo Arenas Belón's proposed fix, pointing out a deeper issue with the solution.

The thread had previously settled on a simple fix replacing `e->d_type` with the portable `DTYPE()` macro, which was sufficient to make the code compile on AIX. However, Junio notes this creates a functional problem: on platforms without `d_type`, `DTYPE()` always returns `DT_UNKNOWN`, causing the code to incorrectly report directories as non-directories to `match_leading_pathspec()`.

Junio proposes a more thorough solution that:
1. First tries to use the available `dtype` if not `DT_UNKNOWN`
2. Falls back to manually checking directory status via `lstat()` when needed
3. Maintains the same behavior for platforms that do have `d_type`

This shows the original fix was incomplete despite passing compilation and initial review. The discussion has moved from a simple portability tweak to addressing a subtle behavioral regression that could affect directory matching on certain platforms. Junio's response suggests the fix needs deeper consideration of the actual filesystem behavior rather than just making the code compile.
