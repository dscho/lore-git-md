This is a refactoring patch that simplifies the branch merge tracking logic in Git's remote handling code. It's part of a larger series improving submodule remote lookup, though this particular patch focuses on cleaning up the core branch structure.

The patch removes the dual storage of merge information in `branch->merge_name` and `branch->merge`, consolidating everything into the `branch->merge` array of refspec items. The change fixes several memory leaks in branch cleanup and makes the ownership of strings clearer by having `add_merge()` handle its own allocations rather than relying on callers to provide pre-allocated strings.

Key improvements include:
- Eliminating a potential crash when `branch_release()` assumed `branch->merge` was always set
- Properly freeing all allocated memory through a new `merge_clear()` function
- Adding a `set_merge` flag to track initialization state more clearly
- Updating all callers to use the consolidated storage

The change appears well-motivated and carefully implemented, with thorough updates to all affected code paths. While it touches core remote handling code, the changes are localized to branch management and don't affect user-facing behavior. This looks like a solid cleanup that paves the way for the subsequent submodule improvements in the series.
