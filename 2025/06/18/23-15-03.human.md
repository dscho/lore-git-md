This is a follow-up discussion in the performance optimization thread for `git fetch --prune`. Jacob Keller weighs in on the output ordering change proposed in Phil Hord's patch series.

The key point of discussion is whether it's acceptable to group dangling ref warnings at the end of the output rather than interleaving them with deletion messages. Jacob expresses a clear preference for the new grouped output format, stating he sees no reason why anyone would need the current interleaved ordering for scripting purposes.

This reinforces the case for accepting the performance optimization as-is, since the output change appears to be a cosmetic rather than functional difference. Jacob's perspective as an experienced contributor (and Intel's Git maintainer) lends weight to the argument that the ordering change is harmless. The comment suggests the patch series is moving toward consensus, with no formal Ack yet but growing support for the simpler implementation that enables dramatic performance gains.
