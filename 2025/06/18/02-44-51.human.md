This is a bugfix patch addressing memory safety in the remote configuration handling, specifically around branch->merge initialization. It's part of an ongoing thread focused on cleaning up branch struct memory management while removing `the_repository` dependencies.

Lidong Yan proposes initializing branch->merge entries during config reading rather than waiting for branch_get() calls, which would ensure merge arrays are always properly sized when merge_nr is non-zero. The change would make the state more predictable by eliminating cases where merge_nr is set but merge is NULL. The patch shows a straightforward implementation that iterates through branches after config parsing to apply set_merge().

The suggestion comes in response to Jacob Keller's earlier analysis of branch struct initialization states, where they identified potential inconsistencies in how merge arrays are populated. This appears to be a logical next step in the thread's progression toward robust memory handling, though it may need validation that the early initialization doesn't introduce other edge cases. The change is small and focused, touching only remote.c's config reading logic.
