This is a cover letter for a patch series improving submodule remote lookup logic, combining refactoring, bugfixes, and feature improvements. The series aims to make submodule remote handling more robust by:

1. First performing cleanup work: fixing memory leaks in branch and remote struct teardown, moving utility functions to shared headers, and removing `the_repository` usage from remote.c functions to enable submodule repository handling.

2. Replacing the existing `repo_get_default_remote()` with a more robust `repo_default_remote()` that properly handles single-remote cases without always falling back to "origin".

3. Adding URL-based remote lookup as the primary method, since the parent project already knows the submodule's URL from .gitmodules or config. This is more reliable than name-based lookup when users rename remotes.

The series progresses logically from preparatory cleanups to the core improvements. Tests in t7406 verify the new behavior. The v3 changes notably simplify the branch->merge_name handling completely rather than just fixing its leaks. This appears to be a well-structured series addressing a real pain point in submodule configuration handling, with thorough attention to memory management and test coverage.
