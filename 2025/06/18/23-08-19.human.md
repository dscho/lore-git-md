Refactoring patch in the submodule remote lookup series, focusing on default remote name handling. This is part of the ongoing effort to improve submodule remote robustness, particularly when users rename remotes.

Jacob Keller refactors the logic for determining a submodule's default remote name, moving from a custom implementation in submodule--helper to reusing the more robust `remotes_remote_for_branch()` function from remote.c. The new approach first checks for the branch's configured remote, then falls back to the sole remote if only one exists, before finally defaulting to "origin". This provides better handling for cases where users rename their default remote but don't add additional remotes.

The patch introduces a new `repo_default_remote()` helper in remote.c that encapsulates this logic and replaces direct calls to the old `repo_get_default_remote()`. Test coverage is added to verify the behavior works with renamed remotes. This change maintains backward compatibility while providing more flexible remote name handling, though it doesn't fully solve all edge cases with custom remote configurations.

The implementation looks clean and well-tested, building on previous refactoring work in the series to remove `the_repository` dependencies. It's a logical step toward the series goal of making submodule remote handling more robust.
