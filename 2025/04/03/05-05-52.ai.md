This is the first patch in Patrick Steinhardt's 20-part series to remove Perl as a mandatory dependency from Git's test suite. The patch focuses on the chainlint script, which verifies proper '&&' chaining in test files and currently requires Perl.

The change makes chainlint automatically disable when PERL_PATH is unset (indicating no Perl available), while still allowing explicit control via GIT_TEST_CHAIN_LINT. If a developer specifically requests chainlint (GIT_TEST_CHAIN_LINT=1) but lacks Perl, the test suite will bail out with an error message. This provides a smoother experience for Perl-less environments while maintaining the ability to enforce chainlint when desired.

Key technical details:
- Modifies t/test-lib.sh to check PERL_PATH
- Handles three cases for GIT_TEST_CHAIN_LINT: unset (auto-disable), 0 (explicit disable), or other (require Perl)
- Preserves existing chainlint behavior when Perl is available
- Part of broader effort to make 97% of tests Perl-free

The patch demonstrates careful consideration of backward compatibility and developer experience, typical of the series' approach. It addresses a specific pain point (manual chainlint disabling) that would otherwise affect developers working without Perl.
