This is a status update on GitLab's planned migration to `git-replay` in relation to change ID preservation. Patrick Steinhardt confirms GitLab's intention to adopt `git-replay` (which preserves commit headers) after discussions with Chris, citing the change ID standardization effort as additional motivation. The email references prior reports from GitButler and Jujutsu about header preservation issues during rebase operations, noting that while GitHub preserves headers via `git-replay`, GitLab and Forgejo currently drop them. Steinhardt cautions that while the work is prioritized, no concrete timeline is committed.

Key technical points for future reference:
- Current GitLab/Forgejo behavior drops unknown headers during rebase operations
- `git-replay` (used by GitHub) preserves headers, making it the target implementation
- The change ID standardization effort provides additional impetus for this migration
- No implementation timeline yet, but work is being scheduled

This represents progress on one of the open questions from the thread regarding edge case handling during history rewriting, with GitLab now actively planning to address the header preservation issue at the infrastructure level. The response aligns with the empirical data from Jujutsu and GitButler while moving the discussion toward concrete platform changes.
