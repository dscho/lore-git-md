This is a discussion about standardizing change IDs across Git tooling, specifically focusing on header preservation during operations like rebase and cherry-pick.

Elijah Newren responds to Martin von Zweigbergk's proposal for a unified change ID format (32-character reverse-hex in a `change-id` header) by raising practical concerns about uniqueness and performance. He questions how commands like `git rebase main <change ID>` would work given that change IDs are preserved across rewrites, potentially leading to duplicates. Newren also probes whether implementations maintain a separate lookup table to handle this efficiently.

The email highlights an important philosophical alignment - Newren agrees that change IDs should be preserved during cherry-picks by default, drawing a parallel to how Git already preserves authorship information during these operations. While supportive of the standardization effort, he notes that Git would eventually need modifications to properly handle these headers during commit rewrites and import/export operations.

Newren's perspective is particularly informed by his evolving stance - while previously skeptical of change IDs (especially as commit trailers), he's now more favorable due to wider adoption and better understanding of use cases. The exchange shows healthy technical scrutiny of the proposal while acknowledging its growing ecosystem support.
