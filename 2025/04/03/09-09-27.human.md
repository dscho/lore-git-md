Feature proposal: Native Git support for standardized change IDs

Patrick Steinhardt responds to Martin von Zweigbergk's proposal for standardizing change IDs across Git tools (Gerrit, GitButler, Jujutsu), strongly endorsing the concept while suggesting deeper Git integration. He outlines several practical benefits change IDs would provide beyond the current trailer-based approaches, including better tracking of evolving patches, improved cherry-pick detection, and easier history rewriting.

While accepting the proposed 32-character reverse-hex format, Steinhardt argues that commit trailers are suboptimal for change ID storage due to their loose format and performance implications for graph operations. He proposes concrete Git enhancements that would make change IDs first-class citizens: generation support in commit/merge commands, rewrite-aware operations in cherry-pick/rebase, and revision syntax for change ID addressing. These would be optional initially, with indexing as a future optimization.

The email raises important considerations about backward compatibility (acknowledging existing tools' experience) and positions this as an opportunity for Git to learn from Jujutsu's innovations. Steinhardt offers to contribute to implementation efforts if the community supports the direction, signaling serious technical engagement with the proposal while avoiding format debates. The response advances the discussion from standardization between tools to potential core Git integration.
