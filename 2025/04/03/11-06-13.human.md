This is a technical discussion about change ID preservation during Git operations, particularly focusing on GitLab's planned migration to `git-replay`.

Patrick Steinhardt confirms GitLab's intention to migrate to `git-replay` for handling rebase operations, which would preserve change IDs in commit headers (unlike GitLab/Forgejo's current behavior). This comes in response to Remo Senekowitsch's report about Jujutsu and GitButler's experiences with header preservation across different Git hosting platforms.

The email notes that while GitHub already preserves headers via `git-replay`, GitLab currently drops unknown headers during rebase-merge operations. Steinhardt mentions coordination with Chris (likely Chris Torek) on this migration but cautions that no specific timeline is promised for the change.

This moves the broader change ID effort forward by addressing one of the key technical hurdles identified earlier - header preservation during platform-side operations.
