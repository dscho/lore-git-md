This is a feature patch introducing a new `--no-hooks` global option to disable hook execution. The patch comes from Derrick Stolee and follows the model of the existing `--no-advice` option.

The change adds a new command-line flag that sets a `GIT_HOOKS` environment variable, which is checked in `run_hooks_opt()` to skip hook execution. The motivation cites cases where users currently work around slow hooks by either deleting them (safe but manual) or setting `core.hooksPath` to invalid paths (unsafe). The new option provides a supported way to temporarily disable hooks.

Implementation touches several files:
- Documents the new option in git.adoc
- Adds `GIT_HOOKS` to environment.h
- Modifies git.c to handle the new flag
- Updates hook.c to check the environment variable
- Includes tests verifying both the command-line option and environment variable work

The patch appears well-constructed with thorough documentation and test coverage. It addresses a real pain point for users who need to occasionally bypass hooks, particularly in performance-sensitive scenarios. The implementation follows existing patterns in the codebase for similar global options.
