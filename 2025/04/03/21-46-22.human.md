This is a technical discussion about change ID implementation strategies in Git-related tools, specifically focusing on Jujutsu's approach. Martin von Zweigbergk responds to Elijah Newren's question about how change IDs are resolved in Jujutsu, contrasting it with Git's commit graph model.

The email explains Jujutsu's multi-layered approach to change ID resolution: it maintains a persistent index of change IDs to commit IDs (similar to Git's commit graph) but with additional in-memory indexes for currently reachable commits. The system also supports configurable prioritization rules - for example, giving shorter prefixes to commits not yet pushed to remotes. This enables very short identifiers even in massive repositories like Google's monorepo.

The response highlights key differences from Git's model, particularly around visibility rules and prefix resolution. While not directly proposing changes to Git, this contributes concrete implementation details to the ongoing cross-tool discussion about standardizing change ID behaviors.
