This is a refactoring patch in Patrick Steinhardt's reftable API series, specifically addressing how restart points are tracked in reftable blocks. Karthik Nayak provides a review of Patch 4/16, which simplifies the tracking of restart points by eliminating redundant variables.

The patch removes the `block_len` and `restart_bytes` fields in favor of tracking just the restart offset (`restart_off`), since the other values can be derived from this. Karthik notes this is a good simplification but points out two minor documentation nits: (1) the commit message could be clearer about removing both variables rather than just `block_len`, and (2) the variable name `restart_off` might be better spelled as `restart_offset` for consistency with `header_off`.

The changes are mechanical and affect three files (`block.c`, `block.h`, and `table.c`), with straightforward updates to use the new offset-based approach. Karthik confirms the technical approach is sound with "The patch looks good" while providing these minor documentation improvements. This continues the series' pattern of positive reviews focused on small clarity improvements rather than implementation concerns.
