Here's a bug report exposing an issue with the refs optimization series. Elijah Newren encountered a crash in the packed-refs backend when fetching from a repository containing branch names (specifically one with a shaved-ice emoji). The error occurs in the new prefix comparison logic added in patch 14/16 of the performance optimization series.

The problem manifests when comparing UTF-8 characters in refnames, where signed character comparisons fail for bytes above 127. Newren provides detailed debugging showing how the comparison fails both with the original code and when attempting to cast to unsigned char. The error suggests the prefix comparison logic needs more robust handling of Unicode characters in refnames.

This appears to be a real-world validation of edge cases the optimization series needs to handle. While the series has received positive reviews and appears ready for integration, this report indicates one more corner case requiring attention, particularly for repositories using non-ASCII refnames. The bug is serious enough to cause fetch operations to abort with a signal 6 (SIGABRT).
