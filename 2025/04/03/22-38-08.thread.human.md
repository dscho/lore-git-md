This thread discusses Derrick Stolee's proposal to add a `--no-hooks` global option and `GIT_HOOKS` environment variable, providing a supported way to disable Git hooks. The initial patch implements this feature similarly to `--no-advice`, touching documentation, core code, and tests.

Brian M. Carlson provided thoughtful feedback, noting the feature would improve upon current workarounds like setting `core.hooksPath=/dev/null`, but raised concerns about silent hook disabling potentially breaking Git LFS integration and masking security issues. Stolee has now responded, clarifying the intended use cases while acknowledging risks. He agrees some hooks are essential (like Microsoft's VFS for Git hooks) but emphasizes the feature primarily targets read-only operations and optional hooks where experts may need to skip checks. Stolee remains open to strengthening documentation warnings and welcomes further input on balancing flexibility with safety.

The discussion has surfaced important considerations around repository integrity versus performance needs, with key questions remaining about whether silent bypass is preferable to explicit failures in security-sensitive contexts. Both contributors agree the feature has value but differ slightly on implementation philosophy, with Carlson advocating for more visible failure modes and Stolee focusing on documented expert use cases. The thread remains open for additional community feedback on these design tradeoffs.
