Derrick Stolee's thread about adding a `--no-hooks` option has concluded with a documentation-only resolution. After maintainer Junio C Hamano firmly rejected the new option on architectural grounds, Stolee has instead submitted a patch documenting the existing `core.hooksPath=/dev/null` workaround. This approach preserves Git's design philosophy while giving users an officially documented way to disable hooks when needed.

The documentation patch adds a brief explanation to `core.adoc` noting that setting the hooks path to `/dev/null` will disable all hooks, with a recommendation to use this via `git -c` for specific commands rather than globally. This behavior has been testable since commit c8f6478 but was not previously documented for end users. The change cleanly implements the fallback position that emerged from the thread after the feature proposal was rejected.

The thread serves as a clear example of Git's maintainer prioritizing architectural consistency over workflow convenience. While npm/husky workflow issues remain unaddressed in core, the project's direction is now clearly documented: such problems should be solved either via existing mechanisms (now better documented) or through refactoring porcelain commands into more flexible plumbing.
