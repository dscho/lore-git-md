This is the first patch in a 2-part series that enhances `git version --build-options` to report which SHA implementations Git was built with. The patch is now in its third version with all technical details settled.

The change adds SHA-1 and SHA-256 backend information to the version output, showing which cryptographic library is being used (OpenSSL, Apple CommonCrypto, etc.). For SHA-1 backends that lack collision detection (marked as "No collision detection"), the documentation includes a security warning about potential vulnerability to known attacks.

The implementation defines standardized `SHA1_BACKEND` and `SHA256_BACKEND` symbols in hash.h that each backend must provide, then includes these in the version output. The approach maintains compile-time safety while eliminating duplicate detection logic. The documentation clearly explains the security implications of non-collision-detecting SHA-1 implementations.

This appears to be a well-considered change that provides useful diagnostic information while properly warning about security trade-offs. The thread history shows the implementation and documentation wording have been thoroughly reviewed and agreed upon by multiple contributors. The patch is ready for merging as part of the complete series.
