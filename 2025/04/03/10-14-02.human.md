This is feedback on a GSoC project proposal for a new `git metadata` command. Patrick Steinhardt responds to Lucas Oshiro's initial submission with suggestions to refine the scope and approach.

Patrick notes the current description seems too broad, trying to cover all repository information, when the real need is for a better home for core repository metadata currently scattered in `git-rev-parse`. He provides concrete examples of the type of low-level repository information that would be more appropriate to include (object hash, ref database format, directory locations).

The key suggestion is to restructure the development plan into smaller, independently submitable batches rather than one large deliverable at the end. Patrick warns that the current approach risks delaying all feedback until the project's conclusion, making course corrections difficult. This is practical mentoring advice from someone familiar with Git's patch submission process.

The email also requests Lucas to clarify the status of his prior contributions (merged, in discussion, etc.), showing Patrick is reviewing the student's background and engagement with the project. The tone is constructive and focused on helping shape the proposal that would both benefit Git and give the student a successful GSoC experience.
