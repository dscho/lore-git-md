This is the final version of a bugfix for `git blame`'s porcelain output mode, addressing an inconsistency where ignored/unblamable line markers weren't being shown in porcelain format despite being documented as working with all output modes.

The patch adds new "ignored" and "unblamable" metadata lines in porcelain output when the corresponding config options are enabled, maintaining backward compatibility with existing parsers. Key technical details include:

- New `emit_porcelain_per_line_details()` function in `builtin/blame.c` handles the per-line metadata emission
- Uses `fputs()` to avoid newline duplication issues identified in earlier iterations
- Documentation updated in both `blame-options.adoc` and `git-blame.adoc`
- Comprehensive tests in `t8013-blame-ignore-revs.sh` now use fully portable heredoc sed scripts with literal tabs, addressing the final round of review feedback about POSIX compliance

The implementation follows the thread's consensus to:
1. Preserve strict SHA-1 line format compatibility
2. Extend porcelain format via new metadata lines rather than modifying existing fields
3. Maintain clear distinction between `--porcelain` and `--line-porcelain` modes
4. Include robust test verification via `test_cmp` with preprocessed expected output

This represents the culmination of extensive review and refinement, with all identified issues (output formatting, test portability, documentation clarity) now resolved. The changes are well-contained to blame's porcelain output handling while maintaining the expected behavior for existing use cases.
