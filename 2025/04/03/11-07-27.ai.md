This is a discussion about a bug in `git-interpret-trailers` regarding its handling of trailer keys containing periods. The thread began with a bug report showing that periods in trailer keys (like "My-6.11-Version") cause the entire trailer block to fail parsing, despite no documentation of this restriction.

Christian Couder responds to the current behavior, confirming that the parser is intentionally strict about trailer key formats to avoid misinterpreting regular text as trailers. He acknowledges the documentation could be clearer about these restrictions. While recognizing the use case for more lenient parsing (particularly for version tracking in kernel development), he expresses concern about potential abuse if the parser becomes too permissive. 

Key technical details for future reference:
- The issue affects trailer block parsing when any key contains a period
- Current implementation deliberately rejects non-standard keys to prevent false positives
- Possible solutions mentioned: documentation clarification or adding a config option for more lenient parsing
- The discussion highlights tension between strict parsing (for reliability) and flexible parsing (for real-world use cases)

The response leaves the door open for patches to either document the current restrictions more clearly, or potentially add configurability, while noting the maintainer's concerns about making the parser too permissive.
