Feature proposal response regarding configurable default partial clone filters. Brian m. carlson responds to Sylvain Fardeau's RFC about making `--filter=blob:none` the default clone behavior via config. While acknowledging the potential utility for binary-heavy workflows, they note this would be Git's first configurable default clone behavior and raises several concerns that would need addressing in any implementation: accidental partial clones causing connectivity issues, script compatibility problems, and parallels to why shallow clones aren't configurable defaults either. The response maintains Git's typical stance of evaluating features only when concrete patches exist, but leaves the door open for future consideration if the technical and usability challenges can be addressed. No outright rejection, but clear signals about what hurdles a patch series would need to overcome.
