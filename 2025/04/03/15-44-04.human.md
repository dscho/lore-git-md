This is a technical design discussion for the `git-refs` GSoC project, focusing on how to implement reference listing functionality. Zheng Yuting presents two approaches for unifying `git-for-each-ref` and `git-show-ref` features under the new `git-refs` command.

The email analyzes existing filtering and formatting options from both commands, proposing either (1) a unified `list` subcommand handling both, or (2) splitting into separate `filter` and `show` subcommands. Approach 1 risks complexity and performance issues, while Approach 2 would require careful code sharing between subcommands. Zheng leans toward starting with Approach 2 by implementing the simpler `show` first, then building `filter` to reuse its formatting logic.

This continues the project's refinement phase after Patrick Steinhardt's earlier technical review. The discussion shows Zheng thoughtfully considering implementation tradeoffs while adhering to the project's constraints (no command modifications, backward compatibility). The proposal demonstrates growing familiarity with Git's codebase by referencing analogous shared functionality in `git-add`/`git-restore`.
