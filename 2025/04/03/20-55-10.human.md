Feature proposal for configurable partial clone filters.

Sylvain Fardeau proposes adding a way to configure `--filter=blob:none` as the default clone behavior in Git's configuration files. This would make partial clones (which omit blob objects to save bandwidth and disk space) more convenient for developers working with repositories containing binary files.

The email references two Stack Overflow posts - one asking how to make this the default behavior (currently not possible), and another discussing the benefits of filtering binary files from repository history. The proposal appears motivated by real-world use cases where partial clones would be particularly helpful.

This seems like a reasonable quality-of-life improvement for users who regularly work with binary-heavy repositories. The request is clearly stated and includes references to existing community discussions about the problem space. However, the email doesn't include any concrete implementation suggestions or address potential downsides (like confusing behavior for users unfamiliar with partial clones).
