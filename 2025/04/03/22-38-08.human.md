Feature: New `--no-hooks` global option to disable Git hooks

Derrick Stolee proposes adding a `--no-hooks` global flag that allows users to temporarily bypass all Git hooks, similar to the existing `--no-advice` option. The patch addresses cases where users currently resort to unsafe workarounds like deleting hooks or setting `core.hooksPath` to bogus values when they need to skip hooks for performance or other reasons.

The implementation introduces both a command-line option and a corresponding `GIT_HOOKS=0` environment variable, which propagates to subprocesses. The hook execution logic in `run_hooks_opt()` checks this variable via a static int for efficiency. The change includes documentation updates and tests verifying both the command-line and environment variable behaviors.

The commit message makes a reasonable case for the feature, noting that hooks are opt-in functionality and some expert users need a supported way to disable them temporarily. The implementation appears straightforward, following the established pattern of other global options, and includes tests covering the new functionality. This seems like a well-considered addition that could benefit users who work with performance-intensive hooks.
