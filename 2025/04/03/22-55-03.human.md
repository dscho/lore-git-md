This is a response to Derrick Stolee's proposed `--no-hooks` global option feature. Brian M. Carlson provides thoughtful commentary on the patch, acknowledging its utility while raising important considerations about potential misuse and unintended consequences.

Carlson notes that Jenkins CI system currently uses `/dev/null` as `core.hooksPath` for security reasons, and points out that while this new option would serve a similar purpose, it could make Git LFS failures less detectable. They draw parallels to other potentially dangerous expert features like `git reset --hard`, suggesting that while powerful tools can be misused, they still have value for experienced users.

The response highlights both sides of the convenience for expert workflows (particularly with pre-commit hooks) versus the risk of silently breaking functionality that depends on hooks. Carlson expresses a slight preference for the feature but explicitly invites broader discussion, positioning this as a thoughtful middle ground in what may become a more contentious debate about the tradeoffs involved.
