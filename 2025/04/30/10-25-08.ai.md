Refactoring patch in the worktree maintenance series, extracting worktree name retrieval into a reusable helper function.

This patch introduces `get_worktree_names()` in worktree.[ch] to centralize the logic for reading worktree names from the ".git/worktrees" directory. The function returns the names via a `strvec` and handles error cases including missing directories. The implementation replaces direct directory handling in `builtin/worktree.c`'s pruning logic with calls to this new helper.

Key technical details:
- New `get_worktree_names()` function in worktree.h API
- Returns 0 on success (including empty worktrees dir), negative on errors
- Replaces manual directory handling in `prune_worktrees()`
- Maintains same behavior while making code more reusable
- Part of preparation for standalone maintenance task implementation
- Follows pattern of previous refactoring in the series

The change is a straightforward code organization improvement that doesn't modify behavior but enables cleaner reuse of worktree listing functionality. This supports the series' goal of separating worktree pruning from `git gc` by making the underlying operations more modular. The patch fits naturally with the series' incremental refactoring approach.
