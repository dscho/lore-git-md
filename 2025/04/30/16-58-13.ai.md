This is a refactoring patch in Patrick Steinhardt's series to complete the decomposition of `git gc` functionality. The patch splits `rerere_gc()` into three phases (collect stale entries, prune them, clean empty directories) and exposes the collection phase via a new `rerere_collect_stale_entries()` function. This enables the upcoming maintenance task to count stale entries before deciding whether to run full garbage collection.

Junio Hamano, the original author of this code, approves the correctness of the refactoring but questions whether the performance overhead of counting entries (which requires checking each one's staleness) justifies the new auto-execution threshold feature. He suggests measuring whether the counting phase is significantly cheaper than the actual pruning before committing to this design.

Key technical details:
- New `rerere_collect_stale_entries()` function in rerere.h
- Extracted `is_stale()` helper from `prune_one()`
- Maintains same staleness thresholds (15/60 days) and config handling
- Preserves existing `rerere_gc()` behavior while adding new API
- Adds infrastructure for future maintenance task to check entry count
- Includes error handling for rr-cache directory access

The patch appears well-constructed with thorough test coverage, though the performance implications raised by Junio remain an open question that may need addressing before final merge. This is part of the final steps to make all `git gc` functionality available via granular maintenance tasks.
