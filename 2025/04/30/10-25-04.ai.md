This is a feature patch series completing the maintenance task decomposition from `git gc`. The v2 series from Patrick Steinhardt implements the final two standalone tasks needed to fully replace `git gc` functionality - worktree pruning and rerere garbage collection - while adding new configuration options and test coverage.

The series builds on previous discussion that identified key requirements: maintaining behavioral parity with `git gc` while improving efficiency, particularly on Windows), proper config handling, and thorough test coverage. The v2 changes introduce two new config options (`maintenance.worktree-prune.auto` and `maintenance.rerere-gc.auto`) to control auto-execution thresholds, add tests for `gc.worktreePruneExpire` handling, and refactor test logic to be less fragile.

Technical implementation details include:
- New `get_worktree_names()` helper in worktree.h
- Optimized `worktree_prune_condition()` avoiding process overhead
- New `rerere_collect_stale_entries()` function
- Direct implementation in maintenance builtin rather than spawning processes
- Configurable thresholds for both tasks (defaulting to 1 stale worktree and 20 stale rerere entries)
- Comprehensive test coverage including edge cases

The series appears well-structured with clear commit separation and thorough testing. With these changes, all technical prerequisites for replacing `git gc` are now implemented, though the actual deprecation remains future work. The discussion indicates consensus on the approach while focusing on implementation refinements.
