This is a feature patch implementing the "worktree-prune" maintenance task as part of Patrick Steinhardt's series to complete the decomposition of `git gc` functionality. The patch introduces a new maintenance task that prunes stale worktrees, matching the behavior of `git gc` but with configurable auto-execution thresholds. Key technical elements include:

- New `maintenance.worktree-prune.auto` config option (default 1) controlling when the task runs automatically
- Implementation in `builtin/gc.c` via new `worktree_prune_condition()` and integration with the maintenance task framework
- Comprehensive test coverage in t/t7900-maintenance.sh verifying:
  - Basic pruning behavior
  - Auto-execution threshold logic (positive/zero/negative values)
  - Interaction with existing `gc.worktreePruneExpire` config
  - Correct handling of multiple stale worktrees

The implementation builds on existing worktree infrastructure, using `get_worktree_names()` and `should_prune_worktree()` while adding the new auto-condition logic. The tests demonstrate careful attention to edge cases and config precedence, with the task honoring both its own auto-threshold and the existing worktree expiration setting. This represents the fifth patch in an 8-part series that's nearing completion, with strong technical consensus already established in prior review.
