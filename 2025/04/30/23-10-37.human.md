This is a follow-up discussion in the bugfix series addressing `git mv` assertion failures. Junio C Hamano responds to Patrick Steinhardt's patch converting `assert()` to `BUG()` in the move command's error handling code.

The email confirms the technical approach of using `BUG()` instead of `assert()` for more consistent behavior across build configurations. Junio notes this aligns with previous work to eliminate asserts from the codebase. He also observes that the CI tests pass without needing a controversial parallel patch that would make asserts no-ops in Windows/Meson builds.

The key new discussion point is whether to drop that parallel "build in release mode" patch entirely. Junio argues that failing tests (even if they hang) are preferable to silently ignoring assertion failures in CI, as they at least alert developers to problems. He invites other maintainers to weigh in on this policy question before finalizing the series.

This represents the final polish phase of the series - the core technical solution is approved, and the remaining question is about broader build system implications rather than the `git mv` fixes themselves.
