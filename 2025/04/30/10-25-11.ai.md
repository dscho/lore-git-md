Refactoring patch in the gc-to-maintenance conversion series. This is patch 7/8 in v2 of Patrick Steinhardt's series to complete the decomposition of `git gc` functionality into standalone maintenance tasks. The patch extracts rerere garbage collection from `cmd_gc()` into a new `maintenance_task_rerere_gc()` function, following the same pattern used earlier in the series for worktree pruning.

The change moves the rerere GC logic into a standalone function that can be called either from `git gc` or the new maintenance task being introduced in the series. The implementation remains functionally identical - it still spawns a `git rerere gc` child process - but the refactoring enables the maintenance command to invoke it directly. The patch removes the now-unnecessary `rerere_cmd` variable from `cmd_gc()` and updates the error handling to use the new function.

This is a straightforward structural change that continues the series' pattern of incrementally refactoring `gc.c` to support maintenance task extraction. The actual rerere GC behavior remains unchanged, maintaining compatibility with existing `git gc` usage while preparing for the new maintenance task implementation that will follow in patch 8/8. The change is well-contained, touching only `builtin/gc.c` with minimal code movement and no functional changes.
