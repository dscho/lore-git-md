This is a refactoring patch in Patrick Steinhardt's series to complete the decomposition of `git gc` functionality into standalone maintenance tasks. It prepares for adding rerere garbage collection as a configurable maintenance task by splitting the existing `rerere_gc()` function into three distinct phases.

The key change extracts the logic for identifying stale rerere entries into a new `rerere_collect_stale_entries()` function, which will be used by the upcoming maintenance task to check whether garbage collection is needed (based on configurable thresholds). The patch maintains the same behavior while making the internals more modular - stale entries are first collected, then pruned, then empty directories are removed.

This is a well-structured change that follows the pattern seen elsewhere in the series, with clear phases and no behavior changes. The new function is properly documented in rerere.h and will enable the maintenance task to efficiently check whether garbage collection is warranted before doing the (potentially expensive) actual pruning work. The patch fits naturally into the larger effort to make maintenance tasks more granular and configurable.
