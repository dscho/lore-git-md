Junio C Hamano proposes a documentation style unification for negated options in Git's manpages. This responds to an ongoing discussion about whether to document `--[no-]` options as combined entries or separate sections, sparked by Lino Haupt's `git-clone` documentation patch.

The proposal establishes three key principles: (1) list positive and negative forms as separate headline items (enabling better grep-ability), (2) provide unified descriptions explaining behavior for all three states (enabled, disabled, default), and (3) consistently use backticks for literal command-line inputs. Hamano provides concrete counts showing the current documentation uses both styles (189 instances of separate `--no-` entries vs 80 combined `--[no-]` forms).

This would systematically resolve the `git-clone` case while creating project-wide consistency, addressing Kristoffer Haugsbakk's concerns about deviating from established patterns. The suggested format includes specific markup conventions and explanatory structure that would require updates to approximately 80 existing documentation entries if adopted. The proposal doesn't directly reject Haupt's discoverability goal but recontextualizes it within broader documentation norms.
