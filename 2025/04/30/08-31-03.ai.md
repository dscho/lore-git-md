This is a transitional patch in the `git send-email` Outlook Message-ID handling series, showing the evolution from a simple boolean toggle to the eventual tri-state configuration. The v4 version introduces key internal changes while maintaining backward compatibility with the boolean CLI.

The patch adds automatic detection for Outlook SMTP servers (smtp.office365.com and smtp-mail.outlook.com) while preserving the `--[no-]outlook-id-fix` boolean interface. Internally, it implements string-based control with an 'auto' mode that coexists with the boolean override. The `is_outlook()` helper function now respects both automatic detection and manual override cases.

This version incorporates Junio Hamano's feedback from v3 about documentation structure, particularly around clarifying the relationship between automatic detection and manual override behavior. The help text has been reorganized to make the default hostname detection behavior more prominent while still allowing explicit boolean control.

The implementation maintains backward compatibility when the new option isn't used, serving as a bridge between the initial boolean-only approach and the eventual tri-state configuration that will appear in later versions. The patch shows the technical transition point where string-based internal control is introduced while keeping the simpler boolean interface exposed to users.

Key technical details include the modified `is_outlook()` function logic and the internal representation change to support both 'auto' mode and boolean overrides. The documentation improvements address earlier confusion about the "irrespective of SMTP server" phrasing by better separating the description of automatic detection from manual control cases.
