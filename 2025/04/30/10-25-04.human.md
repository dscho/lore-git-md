This is a feature patch series completing the decomposition of `git gc` functionality into granular maintenance tasks. Patrick Steinhardt's v2 series adds the final two missing components - worktree pruning and rerere garbage collection - bringing the maintenance command to full parity with `git gc`.

The series introduces two new maintenance tasks with configurable auto-run thresholds:
- `worktree-prune` (default: run when 1+ stale worktree exists)
- `rerere-gc` (default: run when 20+ stale rerere entries exist)

Key improvements from v1 include:
- Added `maintenance.worktree-prune.auto` and `maintenance.rerere-gc.auto` config options
- Better test coverage for config handling, including verification of `gc.worktreePruneExpire` compatibility
- More robust test helpers to check maintenance subprocess execution
- Optimized condition checking that avoids unnecessary work

The implementation maintains behavioral parity with `git gc` while providing more control. Worktree pruning honors the existing `gc.worktreePruneExpire` config, and both tasks now have sensible auto-run thresholds to prevent unnecessary overhead. The series builds on Derrick Stolee's prior maintenance work and represents the last technical prerequisite for eventually deprecating `git gc`, though that transition is left for future work. 

With thorough test coverage and careful attention to performance (especially on Windows), this looks like a well-executed completion of the maintenance task decomposition effort. The configurable auto-run thresholds in particular show good consideration for real-world deployment needs.
