This thread discusses adding a `--no-maintenance` flag to Scalar's repository setup commands (`scalar register` and `scalar clone`) to prevent maintenance.lock conflicts in automated environments. The initial implementation added the flag by modifying the shared `register_dir()` function, but Junio Hamano raised architectural concerns about whether maintenance control belongs at that level versus in the individual command handlers.

Derrick Stolee, the series author, has now responded to Junio's feedback. He acknowledges the issue with `cmd_reconfigure()`'s unconditional maintenance enabling and agrees it needs fixing. While Stolee sees value in keeping maintenance configuration centralized in `register_dir()` (as it handles other "recommended settings"), he's open to restructuring the code to better separate concerns. The discussion remains in the design phase, with key questions about responsibility boundaries and future extensibility still open. Stolee plans to explore restructuring options for v2 while preserving the flag's core functionality. The test coverage from the initial implementation remains valid but may need expansion for any new code paths.
