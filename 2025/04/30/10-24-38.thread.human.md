This thread discusses a two-part Scalar patch series introducing a `--no-maintenance` flag for `scalar register` and `scalar clone` commands. The feature allows skipping background maintenance setup in automated environments to prevent maintenance.lock conflicts, particularly useful for disk image creation scenarios. The initial patches implemented this by modifying `register_dir()` to accept the flag, with thorough test coverage and documentation.

Junio Hamano has now raised architectural concerns about the implementation approach. While agreeing with the feature's motivation, he questions whether maintenance control belongs at the `register_dir()` level rather than being handled by the calling commands (`cmd_register()`/`cmd_clone()`). He points out inconsistencies with `cmd_reconfigure()` (which still unconditionally enables maintenance) and suggests the current design conflates directory registration with maintenance setup. 

The discussion has shifted from implementation details to broader design principles, indicating the patches may need restructuring to better separate concerns. The core functionality appears sound, but the code organization might change to move maintenance control up the call stack. This leaves open whether `cmd_reconfigure()` should also gain the flag or stop managing maintenance entirely. The series remains technically complete but may see revisions to align with Git's architectural patterns before integration.
