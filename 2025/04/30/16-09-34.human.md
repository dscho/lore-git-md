This is a documentation patch proposing improvements to the `git-clone` man page to make the `--no-single-branch` option more discoverable. The author notes that currently the option is only mentioned within the `--depth` paragraph and uses a non-intuitive `--[no]-single-branch` search pattern.

The patch suggests splitting the documentation into two clear paragraphs - one for `--single-branch` and one for `--no-single-branch` - to make both forms easier to find via search. It also explicitly spells out the behavior of each option rather than relying on users to deduce what the "no-" prefix negates.

The change appears well-motivated by real user experience (the author themselves was confused) and targets a genuine discoverability issue in the documentation. The proposed rewrite maintains all the technical accuracy while improving clarity. This seems like a straightforward quality-of-life improvement for users trying to understand clone options.
