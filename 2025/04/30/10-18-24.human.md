This is a user question about Git's behavior rather than a patch submission. The email comes from someone encountering unexpected behavior when using `git commit` with a filename argument.

Marcin Mikłas observes that when running `git commit file.txt` (without `-a`), Git commits changes to file.txt even if those changes weren't staged first. They're asking if there's a way to make this behave like plain `git commit` (without filename arguments), which would only commit staged changes.

The question reveals a subtle but important distinction in Git's behavior: when you specify filenames to `git commit`, it implicitly stages those files' changes before committing, unlike the no-arguments form which strictly requires explicit staging. This isn't a bug but rather an intentional (if perhaps surprising) design choice in Git's CLI.
