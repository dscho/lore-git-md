This is a refactoring patch in Patrick Steinhardt's series to decompose `git gc` functionality into standalone maintenance tasks. It extracts the rerere garbage collection logic from `cmd_gc()` into a new `maintenance_task_rerere_gc()` function, following the same pattern used earlier in the series for worktree pruning.

The change is straightforward - it moves the rerere GC code into a dedicated function while maintaining identical behavior. This prepares for the next patch which will add rerere GC as a configurable maintenance task. The implementation still uses a child process to run `git rerere gc`, though the series' thread context indicates this may be optimized to a direct implementation later.

This continues the series' clean separation of concerns, with each `git gc` sub-task getting its own clearly defined function. The patch appears well-contained and low-risk, touching only the expected parts of `builtin/gc.c` without introducing new behavior. It's part of the final steps to make all `git gc` functionality available through the more granular maintenance command.
