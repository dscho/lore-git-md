Feature proposal for interactive patch commands, continuing discussion on diff context configuration.

Leon Michalak responds to feedback from Junio C Hamano and Jeff King regarding adding diff context configuration to interactive patch commands (`git add -p` and similar). The thread has previously explored three approaches: adding command-line flags, making `diff.context` apply universally, or creating a new `interactive.context` setting.

Michalak now proposes a hybrid approach that would:
1. Inherit `diff.context` and `diff.interhunkcontext` as defaults for interactive commands
2. Allow overriding these via existing `-U<n>` and `--inter-hunk-context=<n>` flags

This addresses both permanent configuration needs and per-invocation flexibility. Michalak acknowledges the technical constraints around dynamic context changes during an interactive session (as noted by Junio) and explicitly states no need for mid-session adjustments. The proposal leans toward Jeff King's preference for config inheritance while maintaining Junio's suggested flag-based override mechanism. Michalak defers consideration of other diff-related configs (like `diff.colormoved`) for future work, focusing first on context lines.

Key technical points for future reference:
- Would modify `run_add_p()` infrastructure
- Affects all commands using interactive patch mode
- Maintains backward compatibility through config inheritance
- Explicitly avoids dynamic context changes during hunk tracking
- Leaves door open for future inclusion of other diff UI configs

The discussion appears to be converging on this hybrid approach, though implementation details remain to be worked out. The proposal shows good awareness of both user experience concerns (consistent porcelain behavior) and technical constraints (plumbing command limitations).
