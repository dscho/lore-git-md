This is a follow-up review in the `git mv` bugfix thread. Junio Hamano provides additional feedback on Patrick Steinhardt's patch that prevents moving both a directory and its child simultaneously.

The review notes two technical details that were missed in earlier rounds:
1. A missing initialization in the modes array that's now properly set with `MOVE_VIA_PARENT_DIR` flag
2. The hashmap lookup for detecting parent-child moves is correctly implemented

Junio suggests enhancing the test cases to verify that:
- The index remains unchanged after a failed move operation
- The working tree paths stay intact when the move is rejected

He also observes that the simpler case of `git mv a a/b` is already handled by existing code and won't hit this new codepath, indicating the test coverage is already comprehensive.

The feedback is minor and constructive, focusing on test completeness rather than any fundamental issues with the approach. The core solution - using a hashmap to track moved directories and explicitly rejecting parent-child moves - remains sound and was previously approved. This appears to be final polish before the series can be merged.
