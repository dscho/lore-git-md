This is a refinement of Patrick Steinhardt's ongoing patch series to fix parent/child directory move conflicts in `git mv`. The discussion with Junio Hamano has identified several edge cases in the implementation, which Patrick is now addressing.

The patch introduces a `MOVE_VIA_PARENT_DIR` flag to properly handle directory moves that would otherwise trigger false positives in the parent/child conflict detection. It also fixes a missing `strbuf_reset()` and acknowledges the asymmetry in how `git mv -k` handles argument ordering (`a/ a/b` vs `a/b a/`). The core approach using a hashmap to track moved directories remains validated, but the implementation is being tightened based on Junio's review.

Notably, the discussion reveals deeper issues with `git mv`'s error handling semantics, particularly around the `-k` flag's behavior. While the current patch maintains existing behavior for compatibility, there's agreement that the flag's semantics around "nonsensical" moves (like moving both a parent and child directory) may need tightening in future work.

This represents careful iteration on a tricky edge case in the `git mv` command, with maintainer guidance helping shape a robust solution. The patch appears technically sound and addresses the specific issues raised in review, though some broader questions about `git mv`'s behavior remain open for future consideration.
