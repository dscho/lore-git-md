This appears to be a bug report regarding unexpected behavior in `git stash` when used with submodules. The issue occurs when running `git stash push -m` in a repository with submodules - the stash message incorrectly gets prepended with "On master:" even when the current branch is not master. The reporter notes this happens specifically on Git for Windows 2.49.0.

The bug manifests differently between basic `git stash` (which correctly shows "WIP on <current branch>") and `git stash -m` (which wrongly shows "On master:"). This causes confusing output in `git stash list` since the branch information is incorrect. The reporter indicates this only happens when submodules are present and configured to track "master", suggesting the submodule configuration may be interfering with the main repository's stash message generation.

This seems like a legitimate bug that could affect users working with submodules, particularly on Windows. The report is clear and reproducible, though it would benefit from more technical details about the submodule configurations and whether the issue persists in newer Git versions. The behavior difference between the message-handling paths in `git stash` warrants investigation.
