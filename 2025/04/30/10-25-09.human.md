Feature patch implementing worktree pruning as a standalone maintenance task. This is part 5/8 of Patrick Steinhardt's series to complete the decomposition of `git gc` functionality into granular maintenance tasks.

The patch adds a new "worktree-prune" task to `git maintenance` that handles stale worktree cleanup, matching the behavior of `git gc`'s worktree pruning. Key aspects include:

- New config option `maintenance.worktree-prune.auto` to control automatic execution (defaults to pruning when 1 stale worktree exists)
- Direct implementation in the maintenance builtin rather than spawning `git worktree prune`
- Honors existing `gc.worktreePruneExpire` config for backwards compatibility
- Comprehensive test coverage for auto-execution thresholds and expiry handling

The implementation appears solid, building on previous refactoring work in the series. The tests verify all the expected behaviors including config handling and edge cases. This continues the pattern of moving `git gc` functionality into the more modular maintenance framework while maintaining behavioral parity.
