This is a feature patch series adding a new option to Scalar commands. The series introduces a `--no-maintenance` flag for both `scalar register` and `scalar clone` to allow disabling automatic maintenance startup in automated environments.

The motivation comes from scenarios where Scalar is used to set up repositories in disk images for later use. The current behavior of automatically starting maintenance can interfere with subsequent automation steps that try to run specific maintenance tasks, as they may conflict with the background maintenance process holding a maintenance.lock file.

The implementation maintains the current default behavior (with maintenance enabled) while providing an opt-out mechanism. The changes touch documentation, core scalar functionality, and add tests in both the basic scalar test suite and the clone-specific tests. The author positions this as balancing Scalar's goal of recommending best practices for typical users while allowing customization for expert use cases.

Key technical details:
- Adds `--no-maintenance` option to both commands
- Modifies `scalar.c` to handle the new flag
- Updates documentation in `scalar.adoc`
- Adds test coverage in `t9210-scalar.sh` and `t9211-scalar-clone.sh`
- Maintains backward compatibility by keeping maintenance enabled by default

The changes appear well-considered with clear motivation, thorough documentation updates, and appropriate test coverage. The use case for automation environments seems valid, and the implementation follows Git's pattern of providing sensible defaults while allowing expert customization.
