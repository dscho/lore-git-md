This is the final patch in Patrick Steinhardt's series to complete the decomposition of `git gc` functionality into standalone maintenance tasks, focusing on rerere garbage collection. The patch introduces a new "rerere-gc" task for `git maintenance` that mirrors the rerere cleanup previously only available through `git gc`.

The implementation adds configurable auto-execution thresholds via `maintenance.rerere-gc.auto` (defaulting to 20 stale entries) and includes comprehensive tests verifying the auto-execution logic. The task checks for stale rerere entries (older than 60 days by default) and only runs when the threshold is met, unless forced. The patch follows the same pattern as previous maintenance tasks, with direct implementation in the maintenance builtin rather than spawning separate processes.

This completes the technical prerequisites for fully replacing `git gc` with granular maintenance tasks. The patch appears well-tested and consistent with the series' established patterns, including thorough documentation updates and test coverage for various config scenarios (positive/zero/negative threshold values). With both worktree pruning and rerere GC now implemented, the series achieves its goal of providing all `git gc` functionality through the maintenance command.
