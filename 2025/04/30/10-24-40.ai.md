This is the second patch in a two-part series extending the `--no-maintenance` flag to Scalar commands, completing the feature by adding it to `scalar clone`. The patch follows the same pattern as the first one for `scalar register`, providing an opt-out mechanism for background maintenance in automation scenarios like VM image preparation.

The implementation adds the new flag to `cmd_clone()` in scalar.c, passing the maintenance setting through to `register_dir()`. Documentation updates in scalar.adoc explain the default behavior (enabled) and the new option. A test case in t9211-scalar-clone.sh verifies the flag prevents maintenance setup without triggering the "could not turn on maintenance" warning seen in the scheduler tests.

The changes are minimal and consistent with the first patch's approach, maintaining backward compatibility while addressing the same automation use case. The test coverage demonstrates attention to edge cases where maintenance would normally fail to schedule. With this patch, both major Scalar repository setup commands now support disabling maintenance, completing the series' goal of supporting automated environments where background jobs could interfere with subsequent steps.
