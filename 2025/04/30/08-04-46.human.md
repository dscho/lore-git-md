This is a feature proposal for interactive patch commands (like `git add -p`) to better handle diff context lines. Leon Michalak is responding to feedback from Junio C Hamano and Jeff King about how to implement unified diff context support in these commands.

The current discussion favors making interactive commands respect the existing `diff.context` and `diff.interhunkcontext` config settings by default, while still allowing command-line overrides via `-U<n>` and `--inter-hunk-context=<n>`. This approach balances user expectations (since these are interactive, user-facing commands) with implementation feasibility.

Leon agrees with Jeff King's suggestion to start with just the context line settings before considering other diff-related configs like `diff.colormoved`. The proposal appears well-considered, building on maintainer feedback while keeping the initial scope manageable. The thread shows healthy technical discussion about porcelain vs plumbing behavior and backward compatibility considerations.

This would be a welcome quality-of-life improvement for users who work frequently with interactive patch commands, eliminating the current need for `GIT_DIFF_OPTS` workarounds. The incremental approach (starting with context lines before potentially adding other diff features) seems sensible.
