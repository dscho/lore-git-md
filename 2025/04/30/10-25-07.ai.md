This is a refactoring patch in Patrick Steinhardt's series to decompose `git gc` functionality into standalone maintenance tasks. The patch extracts worktree pruning logic from `cmd_gc()` into a new `maintenance_task_worktree_prune()` function, preparing for its future use as a standalone maintenance task.

The change is straightforward - it moves the existing worktree pruning code that spawns `git worktree prune` into a dedicated function with the same behavior. The function takes the same configuration parameters (prune expiration time) and maintains the same error handling. This is purely structural preparation with no functional changes.

This patch follows the established pattern in the series of incrementally extracting `git gc` components into reusable functions before making them available as maintenance tasks. The worktree pruning functionality will be used in the next patch which introduces the actual maintenance task. The change is small and focused, with clear test coverage since it's just relocating existing well-tested code.

Key technical details:
- New function `maintenance_task_worktree_prune()` in builtin/gc.c
- Takes `maintenance_run_opts` and `gc_config` parameters
- Maintains identical behavior to original inline implementation
- Still spawns `git worktree prune` as child process
- Same error handling via `die()` on failure
- Part of preparing worktree pruning for standalone maintenance task use
