This is the final patch in Patrick Steinhardt's v2 series completing the decomposition of `git gc` functionality into standalone maintenance tasks, specifically implementing rerere garbage collection. The patch introduces a new `rerere-gc` task for `git-maintenance` that mirrors the rerere cleanup previously only available through `git gc`.

The implementation adds a new `maintenance.rerere-gc.auto` config option (defaulting to 20 stale entries) to control automatic execution thresholds, matching the pattern established by other maintenance tasks. The core logic splits into three phases: checking if rerere is enabled via the rr-cache directory, collecting stale entries using the new `rerere_collect_stale_entries()` function from earlier in the series, and conditionally pruning based on the threshold. The patch includes comprehensive tests verifying:
- Basic task execution without --auto
- Auto-execution threshold behavior (default 20 entries)
- Config override handling (negative/zero/positive values)
- Edge cases around directory existence and error conditions

This completes the technical prerequisites for fully replacing `git gc` with granular maintenance tasks, with all functionality now available through `git-maintenance`. The implementation follows the series' established patterns of direct builtin execution (avoiding process overhead) while maintaining compatibility with existing rerere GC behavior. Test coverage is thorough, including verification of the new config option's interaction with auto-execution.
