Refactoring patch in the maintenance task decomposition series, introducing a new helper function for rerere garbage collection. This is patch 6/8 in v2 of Patrick Steinhardt's series to complete the standalone maintenance tasks needed to replace `git gc`.

The patch splits `rerere_gc()` into three phases and exposes the first phase (collecting stale entries) as a new public function `rerere_collect_stale_entries()`. This enables future callers (like the maintenance task being added in this series) to check whether garbage collection is needed before actually performing it. The function returns arrays of prunable entries and directories through output parameters.

Key technical changes:
- New `rerere_collect_stale_entries()` function in rerere.h
- Extracted `is_stale()` helper from `prune_one()`
- Modified `rerere_gc()` to use the new collection function
- Maintains same garbage collection logic (15/60 day thresholds for unresolved/resolved conflicts)
- Preserves config handling for `gc.rerereresolved` and `gc.rerereunresolved`
- Includes error handling for rr-cache directory access

The refactoring is behavior-preserving but enables the maintenance task to implement configurable auto-execution thresholds (added in earlier patches) by checking the stale entry count before running GC. The patch follows the series' pattern of structural preparation before adding new functionality.
