A bug report has been filed regarding `git stash` behavior with submodules on Windows. When using `git stash push -m` in a repository containing submodules, the stash message incorrectly gets prefixed with "On master:" regardless of the actual current branch. This only occurs when explicitly providing a message via `-m` - the default `git stash` behavior correctly shows "WIP on <current-branch>".

The reporter observes this specifically in Git for Windows 2.49.0 and notes the issue only manifests when submodules are present and configured to track the "master" branch. This suggests the submodule configuration may be interfering with the main repository's stash message generation logic. The bug creates confusion in `git stash list` output since the branch information is incorrect.

While the report is clear and reproducible, additional details would be helpful - particularly whether this affects newer Git versions and more specifics about the submodule configurations that trigger the issue. The discrepancy between the message handling paths in `git stash` (working correctly without `-m` but failing with it) points to a likely bug in the stash message generation code when submodules are involved.
