Scalar feature patch series introducing `--no-maintenance` flag for repository setup commands, now under design review regarding architectural placement of maintenance control. Original implementation added the flag to both `scalar register` and `scalar clone` by modifying `register_dir()`'s function signature to accept maintenance preferences, with complete test coverage in t9210-scalar.sh and t9211-scalar-clone.sh.

Junio Hamano's review raises architectural concerns about responsibility boundaries, suggesting maintenance toggling belongs at command level (`cmd_register()`/`cmd_clone()`) rather than in `register_dir()`. Key issues identified: (1) inconsistency with `cmd_reconfigure()`'s unconditional maintenance enabling, (2) misplaced control flow where directory registration and maintenance setup are conflated, and (3) need for clearer separation of concerns in the implementation.

The series remains functionally complete for its stated purpose - preventing maintenance.lock conflicts in automated environments by allowing maintenance opt-out during repository setup. However, the feedback implies required restructuring to: move maintenance control up to command-level callers, reconsider `cmd_reconfigure()`'s behavior, and refine `register_dir()` to handle only core registration duties. No changes to the flag's behavior or backward compatibility are suggested, but the implementation approach may shift significantly before integration. Test coverage for the existing functionality remains valid but may need expansion for any restructured code paths.
