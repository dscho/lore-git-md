Refactoring patch in the gc-to-maintenance conversion series.

This patch simplifies the command-line argument handling in `builtin/gc.c` by removing unnecessary global variables that were used to store subprocess arguments. The change eliminates three global `strvec` variables (`prune`, `prune_worktrees`, and `rerere`) that were only used in single locations, instead constructing the command arguments directly in the child process setup. The `repack` strvec remains as a global since it's used in multiple places.

The refactoring maintains identical behavior while making the code more straightforward by:
1. Removing global state that served no reuse purpose
2. Constructing command arguments inline where they're used
3. Keeping the same command sequences and error handling
4. Preserving all existing functionality including quiet mode and promisor remote handling

This is a preparatory cleanup as part of the larger effort to decompose `git gc` into standalone maintenance tasks, though it stands alone as a straightforward code quality improvement. The changes are mechanical and don't affect the actual gc operations - they just make the implementation more direct and easier to follow. The patch follows the series' pattern of incremental improvements while working toward the eventual gc replacement goal.
