This thread began with Lino Haupt proposing to improve `git-clone` documentation by splitting the combined `--[no-]single-branch` option description into separate sections for better discoverability. Kristoffer Haugsbakk raised concerns about deviating from Git's established `--[no-]` documentation convention, citing `gitcli(7)` and widespread usage across other commands.

Junio C Hamano has now weighed in with a comprehensive proposal to standardize how negated options are documented project-wide. His solution would: (1) list positive and negative forms as separate items (addressing Haupt's discoverability goal), (2) provide unified descriptions covering all three states (enabled/disabled/default), and (3) enforce consistent backtick usage for command-line literals. The approach would resolve the immediate `git-clone` question while systematically updating ~80 existing documentation entries to match.

The proposal effectively reconciles the competing concerns - maintaining Kristoffer's emphasis on consistency while achieving Lino's UX improvements through a standardized format. As the maintainer, Junio's position carries significant weight, making this likely to become the new norm unless substantive objections emerge. The discussion has now shifted from whether to change the documentation style to how best implement Junio's proposed format across the codebase.
