This thread discusses standardizing how Git's manpages document negated command-line options (like `--[no-]` prefixes). It began with Lino Haupt proposing separate documentation for positive and negative forms to improve discoverability, while Kristoffer Haugsbakk emphasized maintaining consistency with existing patterns. Junio C Hamano then proposed a comprehensive solution that would list forms separately for searchability while keeping unified coverage of all states (enabled/disabled/default) and standardizing backtick usage.

D. Ben Knoble's recent response supports Junio's approach by sharing real-world evidence: his personal vim configuration had to implement special regex patterns (`/^\C\v\s*(-[^,]*,\s*)?--(\[no-\])?`) to work around the current documentation format's limitations. He references prior related changes (commit 4ad47d2de3 about command-line precedence) without raising new objections, effectively validating the proposal's goal of improving searchability. The discussion now awaits feedback from documentation maintainers like Jean-Noël Avila, with about 80 existing entries potentially needing updates if the proposal moves forward. The outcome may also influence broader documentation standards beyond just negated options.
