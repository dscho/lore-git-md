Bug report thread summary:

Ludo Pulles reports a bug where Git incorrectly persists in rebase state after interrupting `git am` with Ctrl-C. The sequence involves initializing a repo, running `git am` without arguments, interrupting it, and observing incorrect rebase state in `git status` with failed attempts to continue via `git rebase --continue`. The system remains stuck until manually removing `.git/rebase-apply`. Reproduced on Git 2.49.0/Linux with no hooks mentioned. Core issue appears to be incomplete cleanup of apply/rebase state files after interruption. Well-documented report with clear reproduction steps and workaround.
