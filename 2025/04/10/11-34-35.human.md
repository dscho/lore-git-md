Performance test infrastructure fix with regression report.

This is a follow-up to Patrick Steinhardt's patch that enabled out-of-tree builds for Git's performance benchmarks. Toon Claes reports a regression has appeared when running the `p0005-status.sh` test through the traditional `t/perf/run` script. The error occurs during result aggregation, where the script fails to find the test results file.

The original patch modified `perf-lib.sh` to properly handle build directories outside the source tree, including Windows path conversion via `cygpath`. While the core functionality works (tests execute successfully in both in-tree and out-of-tree scenarios), the aggregation step fails with "No such file or directory" when trying to process the results.

This appears to be a path resolution issue in the Perl aggregation script, though the exact relationship to the build directory changes isn't immediately clear from the error. The reporter doesn't propose a fix but provides a clear reproduction case using the standard benchmark workflow. The problem manifests after both test runs complete successfully, suggesting the issue lies in post-processing rather than test execution itself.

Given this is part of a series adding Meson support to the performance infrastructure, the regression may indicate a subtle interaction between the new build directory handling and the existing result aggregation path assumptions. The report provides enough detail for the original author to investigate whether the path calculations need adjustment or if additional directory creation is needed before aggregation.
