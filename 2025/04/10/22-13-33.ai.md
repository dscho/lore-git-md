This is a security-related follow-up in the `safe.directory` wildcard behavior thread. Brian m. carlson adds a third workaround to the two previously identified by Jeff King for the intentional security behavior where `safe.directory = *` doesn't propagate during local clones.

The new suggestion is to use `git clone --no-local` with recent Git versions, which triggers the untrusted repository security model where the wildcard setting would apply. This builds on the established understanding that the current behavior is a deliberate security measure due to process separation during clones, with the wildcard only working in single-process operations like `git status`.

Key technical details include:
- `--no-local` flag as alternative solution
- Maintains connection to the thread's core security discussion
- References "untrusted-repository semantics" as the operative mechanism
- Implicitly confirms the behavior is version-dependent

The email doesn't introduce new controversy but rather expands the solution space while accepting the security rationale. It suggests the thread may be approaching resolution with multiple workarounds now documented.
