This is a discussion about Meson benchmark integration in the ongoing performance test infrastructure series.

Toon Claes responds to Patrick Steinhardt's patch 4/5 that wired up benchmarks in Meson, noting a usability issue with the current implementation. While appreciating the effort, Toon points out that running benchmarks via Meson (`meson test --benchmark`) currently provides minimal output - just a pass/fail status without the detailed performance metrics that `t/perf/run` normally shows. The full results are written to a log file, but this isn't as convenient as the direct output from the traditional script.

The email also explores alternatives for cross-version benchmarking, which the patch explicitly notes isn't supported by the Meson integration. Rather than fully integrating Meson into the existing `t/perf/run` and `aggregate.perl` scripts (which Patrick acknowledged would be complex), Toon suggests a middle path: modifying the scripts to work with pre-built binaries from Meson directories. This would allow running benchmarks across different builds while maintaining the existing result aggregation and comparison features.

Key technical points:
- Current Meson benchmark output lacks detailed performance metrics in console
- Cross-version benchmarking remains a gap in Meson integration
- Proposal to adapt `t/perf/run` to accept Meson build directories as input
- Maintains separation between Meson's single-version benchmarking and `t/perf/run`'s comparison capabilities
- The discussion highlights a practical usability concern (output verbosity) and proposes a potential solution for cross-version testing that could be implemented separately from the current series.
