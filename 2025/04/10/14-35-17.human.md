Bug report: Git gets stuck in rebase state after interrupted `git am`

Ludo Pulles reports a case where Git incorrectly persists in rebase mode after a user interrupts `git am` with Ctrl-C. The sequence is: (1) initialize a repo and make a commit, (2) run `git am` and interrupt it, (3) observe that `git status` incorrectly reports being in a rebase, and (4) find that `git rebase --continue` fails with a warning about missing rebase metadata.

The key issue is that Git leaves the `.git/rebase-apply` directory in place after the interrupted `git am`, but without the proper metadata files that would allow either continuing or aborting the operation. The workaround is to manually remove this directory, but this shouldn't be necessary - Git should clean up properly after itself when operations are interrupted.

This appears to be a real bug in Git's state management, though the impact is limited since it only affects cases where `git am` is run inappropriately (without patches to apply) and then interrupted. The report includes clear reproduction steps and system information, making it easy to verify. The bug persists in Git 2.49.0.
