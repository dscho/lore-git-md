The issue appears specific to how quoted passwords are handled in the config parsing.

The problem occurs with Git 2.39.5 on Debian Linux, using ASCII printable characters in passwords under 20 characters long. Notably, this configuration was working correctly just five weeks ago, suggesting either a subtle regression in Git or some environmental change affecting config parsing. The report doesn't include specific reproduction steps yet, but provides enough technical details about the failure mode for others to begin investigating. The key question is whether this is a genuine bug in `git send-email`'s config handling or some interaction with the local Perl installation or environment.
