Jérôme Pouiller reported that `git send-email` is truncating SMTP passwords containing special characters like # and $ when read from Git config, though they work correctly when passed via `--smtp-pass` or viewed with `git config --list`. The behavior appears in Git 2.39.5 on Debian Linux, but worked correctly five weeks prior. 

Christian Couder has now responded, suggesting this might be a regression introduced in Git 2.39.5, which included send-email changes from 2.39.4. He recommends testing with older versions (2.39.4 or 2.39.0) to confirm whether the issue disappears, which would help isolate whether this is a version-specific regression. The core problem remains focused on quoted passwords with special characters being truncated when read from config, while the version history angle provides a new troubleshooting path. No other contributors have yet confirmed whether they can reproduce the issue.
