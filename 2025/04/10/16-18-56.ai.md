This is a discussion about patch tracking mechanisms in the context of code review workflows, specifically responding to Theodore Ts'o's proposal for "patch set IDs" as an alternative to full Change-IDs.

Junio Hamano agrees with the general concept of tracking patch iterations but describes his current workflow using Message-IDs from cover letters as a practical solution. He explains how maintaining proper email threading conventions (each cover letter responding to the previous iteration's cover letter) provides sufficient tracking through lore.kernel.org's interface and `b4 am` tooling. The system allows seeing discussion activity, iteration freshness, and scope changes at a glance.

Key technical details include:
- Current practice uses cover letter Message-IDs as de facto patch set identifiers
- Requires strict adherence to email threading conventions (reply-to chains between iterations)
- `b4 am` tool leverages this structure to fetch latest patches automatically
- Provides visibility into discussion heat, iteration age, and topic scope evolution

The email suggests the existing email-based workflow may already satisfy many of the needs that patch set IDs would address, though it doesn't reject the concept outright. This continues the thread's exploration of lightweight alternatives to Change-IDs while raising questions about how much additional value formal patch set IDs would provide over current practices.
