Technical contribution to the working directory dirtiness detection discussion, providing a shell snippet alternative to the discrete commands previously suggested.

Brian M. Carlson offers a concise shell-based solution to Ross Goldberg's query about detecting working directory dirtiness through exit codes. Their approach uses `git status --porcelain` in a shell test (`[ -z ... ]`) to produce the desired exit code behavior (0 for clean, non-zero for dirty). This differs from Junio Hamano's earlier enumeration of discrete `git diff` variants by providing a single-command solution that catches all dirtiness types (staged, unstaged, and untracked files) at once.

The solution makes two key assumptions: (1) the directory is known to be a non-bare working tree, and (2) the user wants to consider all types of dirtiness (no selective filtering). While not introducing new Git command functionality, this demonstrates how existing porcelain output can be repurposed for scripting needs. The approach is notably simpler than combining multiple `git diff` invocations but lacks the granularity of checking specific dirtiness types separately.

This email expands the technical options available in the thread while implicitly supporting the case for a unified dirtiness check - though presented as a shell workaround rather than a feature request. The solution's tradeoffs (simplicity vs. configurability) mirror the tension in the thread between scripting convenience and Git's design philosophy of discrete, composable commands.
