Thread continuation in the Change-ID standardization debate, focusing on practical patch tracking alternatives.

Junio Hamano responds to Theodore Ts'o's proposal for "patch set IDs" as a lighter alternative to full Change-IDs. While agreeing that tracking patch iterations is valuable, Hamano notes the mailing list workflow already has effective conventions that serve this purpose. He describes how Message-IDs of cover letters, when properly threaded by contributors, provide sufficient tracking through tools like lore.kernel.org and `b4 am`.

The response highlights several practical aspects of the current system: it shows discussion activity levels, iteration freshness, and topic scope changes. Hamano acknowledges the theoretical value of formal patch set IDs but suggests the existing conventions work well enough in practice, especially when contributors follow the established norms of threading cover letters and marking iterations clearly.

This moves the discussion toward evaluating whether the proposed patch set IDs would provide enough additional benefit over current practices to justify their implementation. Hamano's perspective as the Git maintainer carries weight here - his satisfaction with the status quo suggests any new mechanism would need clear advantages over the Message-ID based approach. The email doesn't reject the idea outright but provides a real-world counterpoint about what already works in the mailing list workflow.
