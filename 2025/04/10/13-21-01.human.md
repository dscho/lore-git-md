Security issue report about `safe.directory` behavior inconsistency. Nikolaus Rath reports that while `git status` respects the `safe.directory = *` wildcard configuration to bypass ownership checks, `git clone` operations still fail with ownership warnings despite the setting. This creates an unexpected inconsistency in security policy enforcement between different Git operations.

The report shows a concrete reproduction case where a repository can be examined with `git status` but cannot be cloned from, both with the same ownership situation and the same `safe.directory` configuration. The behavior suggests either a bug exists in how `clone` command handles the safe directory checks, or that this is an intentional but undocumented difference in security policy between read operations and clone operations.

This appears to be either a bug report or a request for clarification about security policy design. The reporter has provided version information (Git 2.43.0) and clear reproduction steps, making this a well-formed issue report. The inconsistency between commands is notable enough to warrant attention from security-conscious users and maintainers.
