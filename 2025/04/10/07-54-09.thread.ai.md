[PATCH] Proposal: Add commit.signoff config option for automatic Signed-off-by

Thread identity: Feature proposal for adding automatic Signed-off-by trailer generation via git config, originating from developer workflow pain points around consistent signoff across tools and repositories.

Core problem: Developers need to manually add Signed-off-by trailers to commits, particularly when using various tools that may not pass --signoff. Current solutions (aliases, hooks) have limitations in coverage and maintainability.

Proposed solutions:
1. New commit.signoff config option (preferred approach)
2. Extend commit.gpgsign with third value
3. Change commit.gpgsign semantics to include signoff
4. Status quo relying on developer discipline

Technical considerations:
- Aliases cannot directly override git commit behavior
- Hook solutions don't scale well across multiple repositories
- Clear distinction between GPG signing (security) and signoff (attestation)
- Backward compatibility critical for existing commit.gpgsign usage

Open questions:
- Preferred implementation path among the options
- Potential interaction with other commit.* config options
- Whether to support per-branch or per-repository configuration
- Impact on tooling that may expect manual --signoff

Participant positions:
- Original author favors new commit.signoff option as cleanest solution
- No reviews or alternative positions yet (thread root)
