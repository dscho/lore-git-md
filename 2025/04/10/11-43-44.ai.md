This is a follow-up discussion about patch 2/5 in the Meson benchmark infrastructure series, focusing on Perl script execution in performance tests. Toon Claes raises a question about documentation consistency regarding direct Perl script execution.

The original patch by Patrick Steinhardt modified `t/perf/perf-lib.sh` and `t/perf/run` to use the configured `PERL_PATH` from `GIT-BUILD-OPTIONS` rather than hardcoding `/usr/bin/perl`, improving compatibility with systems like NixOS where Perl may be installed elsewhere. 

Toon points out that while the patch addresses script execution within the test framework, the `t/perf/README` still shows examples of running `aggregate.perl` directly without specifying the Perl interpreter. He suggests either updating the documentation to explicitly show using `perl ./aggregate.perl` or making an assumption that users will know to use their system's Perl when needed.

This is a documentation refinement suggestion that would make the instructions more complete for users on non-standard systems, though the core functionality addressed in the patch (automatic Perl path handling within the test framework) remains sound. The question doesn't indicate any technical problem with the patch itself, but rather seeks to improve user guidance around edge case usage.
