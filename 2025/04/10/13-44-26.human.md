This is a philosophical debate about tracking commit identity in Git, with Theodore Ts'o weighing in on the Change-ID proposal.

Ts'o draws a parallel between the Change-ID concept and inode numbers for files, arguing that both introduce similar complexities around tracking identity through operations like splits and merges. He acknowledges that proponents of code review systems like Gerrit may see Change-IDs as more valuable than file identity tracking, but remains unconvinced the complexity is worthwhile. The email frames this as a values-based design choice rather than a purely technical one, comparing it to historical debates about Git's handling of file renames versus systems like Perforce.

While skeptical of Change-IDs, Ts'o suggests an alternative "patch set ID" concept that would group related commits together, which he believes could benefit both web-based and mailing list review workflows. This appears to be a compromise position that addresses some of the use cases motivating Change-IDs while potentially avoiding their distributed systems complications.

The email doesn't directly engage with Junio Hamano's recent technical critiques of the Change-ID approach, instead focusing on the higher-level philosophical debate about when and how Git should track identity beyond its core object model. It keeps the discussion open while maintaining Ts'o's position that Git's current simplicity has value.
