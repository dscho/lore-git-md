Performance test infrastructure improvement with a focus on Perl path portability.

This is a follow-up discussion in the Meson benchmark integration series, specifically addressing patch 2/5 which makes Perl script execution in performance tests more portable by using the configured `PERL_PATH` rather than hardcoding `/usr/bin/perl`. 

Toon Claes raises a good point about documentation in `t/perf/README` - while the patch updates the execution of Perl scripts within the test infrastructure, the README still shows examples of running `aggregate.perl` directly without specifying the Perl interpreter. He suggests either updating the documentation to explicitly show using `perl ./aggregate.perl` or making an assumption that users without Perl at the default location will know to adjust the command themselves.

The discussion highlights an attention to detail in making the performance test infrastructure fully portable, not just in the implementation but also in its documentation. The original patch author Patrick Steinhardt had focused on the technical implementation within the test scripts themselves, while Toon is looking at the broader user-facing aspects of the change.

This is a relatively minor point in the context of the larger Meson integration series, but shows careful review of both implementation and documentation consistency. The question doesn't indicate any problems with the actual patch functionality, but rather seeks to ensure the user experience is complete and clear.
