Bug report: `git send-email` truncating SMTP passwords containing special characters.

Jérôme Pouiller reports that `git send-email` is failing with authentication errors, showing through debug output that the configured SMTP password is being truncated when it contains special characters like '#' and '$'. The password works correctly when passed directly with `--smtp-pass` and appears properly in `git config --list`, suggesting the issue is specific to how `send-email` processes the configuration value.

The report notes this was working correctly 5 weeks ago, though no clear changes (to Git, Perl packages, or the password itself) seem to explain the regression. The password meets reasonable complexity requirements (under 20 ASCII printable characters) and requires quoting due to special characters, which was previously handled correctly.

System information shows this is occurring on a Debian Linux system with Git 2.39.5 (a relatively recent but not cutting-edge version). The report lacks specific reproduction steps or a minimal test case, but describes a clear behavioral change that appears to be a regression in password handling. Maintainers will likely need more information to reproduce and diagnose the issue.
