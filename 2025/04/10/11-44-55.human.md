This is a follow-up discussion about the Meson benchmark integration patch (patch 4/5 in the series). Toon Claes provides feedback on the current implementation's limitations while suggesting a potential improvement path.

The email highlights a practical usability issue: when running benchmarks through Meson (`meson test --benchmark`), the output lacks the detailed performance metrics that users expect from Git's benchmark system. While the tests complete successfully, the summary only shows pass/fail status and duration, not the actual benchmark measurements that would help evaluate performance.

Toon acknowledges the current limitation where Meson benchmarks only work for the current build, with cross-version comparisons still requiring the traditional `t/perf/run` script. Rather than full Meson support in those scripts, they propose a middle ground - modifying `t/perf/run` to accept pre-built binaries from Meson directories, allowing users to compare performance between different builds without requiring the script to handle Meson's build process directly.

This suggests the Meson benchmark integration, while technically working, currently falls short of providing the full benchmarking experience Git developers rely on. The discussion points toward potential future work to bridge this gap, either by enhancing Meson's output or adapting the existing benchmark infrastructure to work with Meson-built binaries. The tone is constructive, recognizing the complexity while proposing a practical incremental improvement.
