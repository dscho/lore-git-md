This is a feature proposal for a new config option to automatically add Signed-off-by trailers to commits.

Oliver Gondža proposes adding a `commit.signoff` configuration option that would make `git commit` always behave as if `--signoff` was passed. The motivation comes from working with projects that require both GPG signing and Signed-off-by trailers for contributions. While GPG signing can be configured globally via `commit.gpgsign`, there's currently no equivalent for signoffs.

The email outlines several current workarounds and their limitations: manually passing `--signoff` is error-prone, aliases can't override `git commit` directly, and custom hooks are cumbersome to maintain across multiple repositories. The proposal suggests this could be implemented either as a new standalone config option or by extending the existing commit.gpgsign option.

The patch appears well-motivated and addresses a real workflow pain point, particularly for developers working across multiple projects with contribution requirements. The author thoughtfully considers backward compatibility implications and presents multiple implementation approaches for discussion. This seems like a practical quality-of-life improvement that would be particularly valuable for developers in corporate or open source environments with strict contribution guidelines.
