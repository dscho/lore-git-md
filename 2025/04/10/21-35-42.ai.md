This is a security-related clarification about `safe.directory` behavior in Git operations. Jeff King responds to Nikolaus Rath's report about inconsistent wildcard behavior between `git status` and `git clone` operations, explaining the underlying mechanism.

The key technical detail is that Git clears environment variables (including `GIT_CONFIG_*`) when switching repositories during clone operations. This explains why the `safe.directory = *` setting works for `git status` (which operates in a single repository context) but fails for `git clone` (which spawns a child process for `upload-pack` in the source repository). The behavior is intentional to maintain consistency with non-local transports that don't pass environment variables.

Jeff suggests two workarounds: setting the config globally in `~/.gitconfig` or explicitly passing the config to the upload-pack command via the clone invocation. The response implies this isn't a bug but rather a design choice with security implications, though it acknowledges the usability impact. The explanation references historical debates about environment variable handling in Git, suggesting this is a known tradeoff between security and convenience.
