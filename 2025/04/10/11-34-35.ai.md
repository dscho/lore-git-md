This is a bug report regarding the Meson benchmark infrastructure patch series. Toon Claes reports a regression occurs when running the `p0005-status.sh` performance test after applying patch 3/5 of the series, which added out-of-tree build support to `t/perf/perf-lib.sh`.

The issue manifests when running cross-version comparisons via `t/perf/run`, where the test completes successfully but fails during result aggregation with the error "cannot open test-results/p0005-status.subtests". The error suggests the test results directory path resolution is broken after the build directory handling changes in patch 3.

Key technical details:
- The failure occurs in `aggregate.perl` when trying to read test results
- The test itself runs successfully in both current and comparison builds
- The regression appears specific to cross-version benchmarking scenarios
- The error suggests path resolution between build directories and test results is not properly handled
- The report includes full build output showing successful compilation but failed result collection

This appears to be an unintended side effect of the build directory detection changes in patch 3, which modified how `GIT_BUILD_DIR` and `GIT_SOURCE_DIR` are handled in `perf-lib.sh`. The error indicates the test results path calculation needs adjustment to account for the new out-of-tree build support while maintaining compatibility with the `t/perf/run` script's cross-version comparison functionality.

The report provides a clear reproduction case and shows the problem occurs in real usage, though the exact relationship to the specific changes in patch 3 isn't fully diagnosed yet. This will likely require investigation into how test result paths are constructed and accessed during the aggregation phase of cross-version benchmarking.
