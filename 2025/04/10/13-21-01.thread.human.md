This thread examines an inconsistency in Git's security policy enforcement regarding repository ownership checks. The reporter discovered that while `git status` correctly honors the `safe.directory = *` wildcard setting (which relaxes ownership verification), `git clone` operations from local repositories still enforce strict ownership checks. This creates a security policy gap where read operations succeed but write operations fail under the same configuration.

The issue was demonstrated using Git 2.43.0, showing that a repository accessible via `git status` with the wildcard setting could not be cloned locally due to ownership verification failures. The core question is whether this represents a bug (with clone operations incorrectly bypassing the wildcard exception) or an intentional design choice that needs documentation clarification. The thread awaits maintainer input to determine if this behavior requires code changes or simply better documentation of security policy boundaries between different Git operations.
