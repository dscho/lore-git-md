Bug report about Git getting stuck in rebase state after interrupted `git am`.

Ludo Pulles reports a case where Git incorrectly persists in rebase mode after interrupting `git am` with Ctrl-C. The sequence that triggers the bug is:
1. Initialize a repo and make one commit
2. Run `git am` (with no arguments) and interrupt it
3. Git status incorrectly shows rebase state
4. Attempting `git rebase --continue` fails with a warning about missing rebase metadata

The system remains stuck in this state until manually removing the `.git/rebase-apply` directory. The bug occurs with Git 2.49.0 on Linux. The report includes full system info but doesn't mention any custom hooks that might affect behavior.

This appears to be a state management bug where Git fails to clean up properly after an interrupted `git am` session, incorrectly leaving behind rebase state files. The report is well-documented with clear reproduction steps and expected/actual behavior, making it easy to verify. The workaround (manual directory removal) suggests the core issue lies in incomplete cleanup of the apply/rebase state.
