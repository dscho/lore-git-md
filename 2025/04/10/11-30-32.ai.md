Build system refactoring for header handling in meson builds. This is part 2/4 of Karthik Nayak's series to implement header checking in meson, building on the thread's established consensus about variable naming and build system organization.

The patch centralizes header definitions by moving `coccinelle_headers` and `third_party_sources` from contrib/coccinelle/meson.build to the root meson.build, renaming the former to just `headers` to reflect its broader use. The change prepares for upcoming header checking functionality while improving build system structure. The coccinelle-specific path handling is kept local to its build file, while the root definitions become more general-purpose.

Key technical changes:
- Moves `third_party_sources` exclusion list to root meson.build
- Renames `coccinelle_headers` to `headers` in root scope
- Keeps path prefixing logic in coccinelle-specific code
- Maintains same header collection logic using `git ls-files`
- Preserves all existing exclusions (compat/, tests/, etc.)

This refactoring enables the subsequent patches to implement header checking while following the thread's agreed practices for variable naming and scope management. The change is purely organizational with no functional difference yet - the actual header checking comes in later patches. The patch demonstrates careful attention to build system hygiene by properly scoping variables and avoiding namespace pollution.
