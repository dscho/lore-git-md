Promisor-remote refactoring to support extended remote attributes.

This is the second patch in a 4-part series enhancing promisor-remote capability to support additional remote configuration fields. The patch refactors the internal representation of promisor remotes from using separate `strvec`s for names and URLs to a more flexible linked list of `promisor_info` structs, each containing a `string_list` of field name/value pairs.

Key technical changes:
- Introduces `struct promisor_info` containing a `string_list fields` member to store arbitrary remote attributes (currently just "name" and "url")
- Replaces `promisor_info_vecs()` with `promisor_info_list()` building the new structure
- Updates all related functions (`promisor_remote_info()`, `remote_nick_find()`, `should_accept_remote()`) to use the new representation
- Maintains same external interface while changing internal storage
- Includes thorough cleanup via `free_info_list()`

The refactoring enables the planned extension (in subsequent patches) to handle additional remote attributes beyond just name/URL pairs. The patch appears well-structured with clear commit message explaining the motivation and approach. Test coverage isn't shown in the diff but would be handled in the series' test file (t5710-promisor-remote-capability.sh).

This is a foundational change for the series' goal of supporting configurable validation of remote attributes during clone/fetch operations. The case sensitivity issue noted in the thread summary isn't addressed here but will presumably be handled in later patches.
