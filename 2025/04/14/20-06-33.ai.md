Performance optimization for MIDX and cruft pack interaction during repacking. This is the final patch in Taylor Blau's 8-part series improving pack maintenance behavior, specifically addressing how cruft packs interact with multi-pack indexes (MIDX) during geometric repacking.

The patch introduces a new config option `repack.midxMustContainCruft` (defaulting to true for backward compatibility) that allows excluding cruft packs from the MIDX when they're not needed for reachability closure. This addresses a performance issue where MIDX would unnecessarily track many rarely-accessed objects from cruft packs, bloating the index and slowing down lookups.

Key technical details:
- New `midx_has_unknown_packs()` function determines when cruft packs must be included for reachability guarantees
- Uses the `--stdin-packs=follow` mode introduced in patch 7/8 to ensure geometric repacks properly track resurrected objects
- Comprehensive test coverage in `t7704-repack-cruft.sh` verifies three scenarios: exclusion when possible, forced inclusion via config, and automatic inclusion when necessary
- Maintains backward compatibility while providing path for more efficient repacking in repositories with many unreachable objects

The implementation spans `builtin/repack.c` with config documentation updates and tests. This completes the series' goal of optimizing pack maintenance by giving more control over cruft pack handling while maintaining reachability guarantees needed for bitmaps. The solution is particularly valuable for repositories with large numbers of unreachable objects that are rarely pruned.
