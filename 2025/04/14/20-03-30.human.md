Platform compatibility update in the build system alignment series, specifically addressing Cygwin regex support.

This email from Ramsay Jones responds to Patrick Steinhardt's question about maintaining compatibility with Cygwin 1.7 (from 2013) in the Git build system. The discussion stems from a patch that would only set NO_REGEX for Cygwin 1.7, allowing newer versions to use the platform's improved regex library.

Jones reveals he actually has a more aggressive patch that would drop support for pre-v2.x Cygwin entirely, as Cygwin considers itself a rolling release distribution. However, he's deferring to maintainer Adam Dinwoodie to make that compatibility policy decision. The email notes that even with the existing configuration, it's unclear whether pre-v2.x versions would still compile successfully.

This exchange highlights an ongoing tension in the build system work between maintaining backward compatibility and simplifying the codebase by dropping support for very old platforms. The technical details about Cygwin's regex evolution (from failing tests in 1.7 to passing them after importing FreeBSD's implementation) provide useful background for understanding the change.
