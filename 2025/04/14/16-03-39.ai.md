This is a feature patch series extending the promisor-remote capability to support additional remote configuration fields. The series allows servers to advertise extra remote attributes (like partial clone filters) and clients to validate them against local configuration.

The key changes introduce two new config options: `promisor.sendExtraFields` on the server side to specify which remote attributes to advertise, and `promisor.checkExtraFields` on the client side to validate them. The implementation replaces the existing `strvec` usage with more flexible `string_list` structures, addressing prior review feedback.

Technical details include:
- New config helper `is_config_key_char()` moved to config.h for shared use
- Server-side advertising of specified remote fields in capability response
- Client-side validation of advertised fields against local config
- Current case-sensitive comparison of field names (acknowledged as a bug to be fixed in next iteration)
- New tests in t5710-promisor-remote-capability.sh
- Documentation updates in config/promisor.adoc and protocol-v2.adoc

The series appears well-structured with clear commit messages and test coverage planned. The author notes some remaining work (case sensitivity fix, additional tests) for a future iteration. This builds on prior promisor-remote work while maintaining backward compatibility - the extra information is only used for remote validation, not stored or used for other purposes.
