Junio Hamano responds to Theodore Ts'o's Patch Set ID proposal in the ongoing discussion about tracking patch series relationships in Git. This is a thoughtful technical discussion about implementing native patch series tracking.

Hamano expresses general approval for Ts'o's proposed approach, particularly appreciating how it naturally handles both single-commit and multi-commit series cases. The proposal introduces a `--series` flag for `git commit` that would establish parent-child relationships between patches, with the relationships preserved through rebases and cherry-picks.

The maintainer raises one significant concern about the proposal's ability to track the history of iterations within a patch series. While the system could identify different strands of commits sharing a patch set ID, it might not clearly show the temporal ordering between iterations or distinguish between independent rewrites of the same series. Hamano notes this might rely too heavily on commit timestamps.

Overall, the response is positive but cautious, with Hamano valuing the clear semantics and natural design of Ts'o's approach while flagging one area that might need more consideration. The discussion continues to focus on practical implementation details that would work well with Git's existing workflows.
