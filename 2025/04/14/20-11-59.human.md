This is a bugfix patch addressing platform-specific behavior in Git's memory calculation for `git gc` auto-detection. The patch corrects how Git calculates total RAM on Cygwin systems where `sysinfo()` reports memory in 4K pages rather than bytes (with `mem_unit=4096`). The fix multiplies the reported memory by `mem_unit` when it's greater than 1, ensuring accurate RAM detection for `git gc`'s auto-tuning behavior.

Ramsay Jones provides evidence from testing on Cygwin showing the current implementation underreports available memory by a factor of 4096. While Linux systems show `mem_unit=1` (making the change a no-op there), the patch makes the behavior correct for both platforms. Patrick Steinhardt reviews the change and suggests the guard clause checking `mem_unit > 1` might be unnecessary since all systems should have proper `mem_unit` values, though Jones opts to keep it for caution.

This is part of a larger series (v2 10/13) improving build system alignment and platform compatibility, with this particular fix addressing a Cygwin-specific quirk in memory reporting. The change is straightforward and well-justified by platform testing, though there's minor discussion about defensive programming practices versus assuming sane system behavior.
