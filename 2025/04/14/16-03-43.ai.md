Feature patch completing the promisor-remote capability extension by adding client-side validation of extra fields. This is the final patch in a 4-part series that enhances the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations.

The patch introduces a new `promisor.checkExtraFields` configuration variable that lets clients specify which additional fields (beyond the mandatory "name" and "url") should be validated against local remote.* config values before accepting a promisor remote. The validation occurs when `promisor.acceptFromServer` is not set to "None". 

Key implementation details:
- New `extra_fields_checked()` helper parses the config into a string_list
- `check_extra_field*()` functions implement the validation logic
- `should_accept_remote()` updated to incorporate extra field checks
- New test case in t5710 demonstrates the validation flow
- Documentation added to promisor.adoc explaining the new config option

The validation works by comparing server-advertised field values (sent via `promisor.sendExtraFields` from patch 3) against corresponding `remote.<name>.<field>` config values. If any specified field doesn't match, the remote is rejected. The implementation maintains backward compatibility - older clients will ignore extra fields they don't understand.

This completes the series' goal of configurable promisor-remote validation while addressing the case sensitivity issue noted in earlier patches by using case-sensitive string comparisons throughout. The test coverage is thorough, showing both successful validation and proper rejection of mismatched fields.
