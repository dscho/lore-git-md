This is a platform compatibility fix for Cygwin's memory reporting in the `git gc` auto-detection logic. The patch corrects RAM calculation when using `sysinfo()` by properly handling the `mem_unit` field, which differs between platforms (1 on Linux vs 4096 on Cygwin).

The technical change modifies `total_ram()` in builtin/gc.c to multiply `totalram` by `mem_unit` when the latter is greater than 1. This addresses a discrepancy where Cygwin reports memory in 4K pages rather than bytes. Ramsay Jones provided test results showing Cygwin's behavior, and Patrick Steinhardt confirms the findings while suggesting the guard clause for `mem_unit > 1` could potentially be removed since all systems should have a proper `mem_unit` value.

This is part of the larger build system alignment series (v2 patch 10/13) that's been focusing on platform-specific fixes, particularly for Cygwin. The change is straightforward and well-justified by the platform behavior differences, with both authors verifying the issue exists on Cygwin while maintaining Linux compatibility. The patch represents a small but important piece of the series' goal to ensure consistent behavior across platforms.
