This thread covers a completed v2 patch series enhancing Git's promisor-remote protocol to support configurable validation of remote attributes (specifically `partialCloneFilter` and `token`) during clone and fetch operations. The series addresses both server-side advertisement and client-side verification while maintaining backward compatibility.

Christian Couder authored the series, which has evolved through review feedback. The current version strictly limits the supported fields to just these two with well-defined semantics, addressing earlier concerns about protocol safety and interoperability. Key technical changes include refactoring the internal representation using `string_list`, adding server-side configuration via `promisor.sendFields`, and implementing client validation through `promisor.checkFields`. The implementation maintains case-sensitive value comparison, preserves URL encoding, and includes comprehensive test coverage.

Patrick Steinhardt provided review feedback that was incorporated, particularly around naming consistency and memory safety. Junio C Hamano raised protocol design concerns that have now been addressed through this constrained field approach. The series appears technically complete, with the main remaining question being whether these two fields will suffice for future needs or if protocol extensions might later be required. The thread is now awaiting final maintainer review before potential merging.
