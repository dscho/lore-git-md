This thread documents the finalization of a 5-patch series enhancing Git's promisor-remote protocol to support configurable validation of remote attributes during clone and fetch operations. The series, now at version 5, has received thorough technical scrutiny and is considered ready for merging, with Christian Couder confirming passing CI tests.

The implementation introduces structured handling of remote attributes like partialCloneFilter and token, with both server-side advertisement (controlled by promisor.sendFields) and client-side validation (via promisor.checkFields). Key technical changes include refactored data structures, robust field parsing, and centralized string constants. All substantive feedback from reviewers like Karthik Nayak and Justin Tobler has been addressed, leaving only minor documentation polish and one philosophical question about NULL check handling in the error path.

Jean-Noël Avila's recent review focuses exclusively on documentation improvements for patch 2, suggesting style changes to align with Git's documentation conventions. His feedback targets readability for non-native English speakers and consistency in formatting protocol specifications, though these suggestions don't affect the already-finalized technical implementation. With all major technical issues resolved and only documentation polish remaining, this series appears ready for Junio Hamano to pick up in the next integration cycle.
