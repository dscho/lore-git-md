This thread covers a finalized 5-patch series that enhances Git's promisor-remote protocol to support configurable validation of remote attributes during clone and fetch operations. The changes allow servers to advertise specific fields (like partialCloneFilter and authentication tokens) while letting clients verify these attributes against their local configuration.

The series has reached its fifth iteration with all feedback addressed and CI passing. Christian Couder has given final approval, indicating it's ready for merging. The implementation introduces several technical improvements: a new `struct promisor_info` for better data handling, server-side field advertisement controlled by `promisor.sendFields` config, and client-side validation via `promisor.checkFields`. The validation is case-insensitive for field names but case-sensitive for values, with comprehensive test coverage for various scenarios.

This work builds on Git's existing promisor-remote infrastructure and aligns with broader efforts to improve type safety. It's part of the "Large Object Promisors" initiative and maintains backward compatibility while adding these security-focused validations.
