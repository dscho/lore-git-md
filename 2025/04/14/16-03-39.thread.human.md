This thread covers a 5-patch series (now at v3) that enhances Git's promisor-remote protocol to support configurable validation of remote attributes during clone and fetch operations. The changes allow servers to advertise specific attributes (like partialCloneFilter and token) while enabling clients to verify them, all while maintaining backward compatibility.

The first patch in v3 series introduces a key refactoring, replacing the existing string-based storage with a new `struct promisor_info` linked list. This foundational change, suggested by Patrick Steinhardt during v2 review, improves type safety and prepares for adding new fields. The series has already addressed extensive feedback from Patrick Steinhardt, Karthik Nayak, and Christian Couder, with only Junio C Hamano's final review remaining.

The implementation includes comprehensive documentation updates and expanded test coverage. The changes follow Git's protocol evolution patterns while ensuring unknown fields are properly ignored for forward compatibility. All major design decisions appear settled, with the series now in its final review stage before potential merging.
