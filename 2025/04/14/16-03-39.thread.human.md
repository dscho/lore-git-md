This thread discusses a 4-patch series extending Git's promisor-remote capability to support configurable validation of remote attributes during clone and fetch operations. The series introduces bidirectional field handling between servers and clients, with server-side advertisement of attributes via `promisor.sendExtraFields` and client-side validation through `promisor.checkExtraFields`. The implementation includes refactored config validation helpers, a new linked-list storage structure, and comprehensive test coverage.

Junio C Hamano, the Git maintainer, has now reviewed patch 3/4 and raised important protocol documentation concerns. He argues that the protocol should precisely define all supported fields rather than using an open-ended mechanism, as protocol specifications require clear interoperability standards. He also expresses security concerns about handling arbitrary fields without proper quoting/escaping rules. Hamano suggests treating these fields as first-class protocol features with well-defined purposes, implying the current documentation and possibly the design need revision.

The series now stands at a crossroads - while technically complete and well-tested, it faces significant design feedback from the maintainer that may require substantial changes. The author will need to address whether to enumerate supported fields formally or establish rigorous field-handling rules. As the first review in the thread, Hamano's comments carry considerable weight and will likely shape the series' next iteration. The security considerations raised could prove pivotal in determining whether and how this functionality lands in Git.
