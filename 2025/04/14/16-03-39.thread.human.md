This thread discusses a 5-patch series extending Git's promisor-remote protocol to support configurable validation of remote attributes (like partialCloneFilter and token) during clone and fetch operations. The series is now at version 6, with all implementation work complete and only final documentation refinements remaining before merge.

The core innovation allows servers to verify additional remote fields via `promisor.sendFields` while letting clients validate these against their `promisor.checkFields` configuration. This enables more granular control over promisor remote acceptance while maintaining backward compatibility. The latest patch (4/5) implements the client-side validation, introducing a `promisor.checkFields` config that enforces three conditions for each field: the local config must be set, the server must advertise the field, and values must match exactly.

Key participants include Karthik Nayak (primary implementer), Christian Couder (CI verification), Jean-Noël Avila (documentation polish), and Junio Hamano (final review). The implementation builds on Git's existing promisor-remote infrastructure and aligns with broader type safety efforts. All technical work is now complete, with the series ready for integration pending final documentation verification. This represents a significant step forward in Git's Large Object Promisors (LOP) effort, providing end-to-end validation capability while maintaining the protocol's flexibility.
