This thread covers a finalized 5-patch series (now at v4) that enhances the promisor-remote protocol with configurable validation of remote attributes like `partialCloneFilter` and `token` during clone and fetch operations. The changes allow servers to advertise these fields and clients to verify them, improving protocol security while maintaining backward compatibility.

The series has undergone thorough review, with all major feedback addressed. Christian Couder has given final approval, and the patches are now ready for merging into Junio's integration branches. The implementation includes server-side field advertisement controlled by `promisor.sendFields` config, client-side validation via `promisor.checkFields`, and comprehensive test coverage. Key contributors include Karthik Nayak (implementation), Patrick Steinhardt (review), and Justin Tobler (review).

In the latest follow-up, Justin noted a small improvement in how empty entries are handled when parsing field lists, suggesting adding a clarifying note about this behavior. This doesn't require a re-roll, as the series is otherwise complete. The change ensures robust handling of mixed comma/space delimiters in field specifications while maintaining the protocol's security properties.
