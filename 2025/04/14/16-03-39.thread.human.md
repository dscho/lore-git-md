This thread covers a completed 5-patch series (now at v4) that enhances the promisor-remote protocol to support configurable validation of remote attributes during clone and fetch operations. The changes introduce both server-side advertisement and client-side verification of fields like partialCloneFilter and token, while maintaining backward compatibility. The series was extensively reviewed, with all major design points settled and feedback from Junio Hamano, Christian Couder, Patrick Steinhardt, and Justin Tobler addressed.

The latest discussion focuses on a minor test refinement for patch 2/5, where Christian Couder suggests expanding test coverage to explicitly verify both comma-separated and space-separated field lists in the promisor.sendFields configuration. While the code already handles both formats internally, adding these test cases would make that support more visible. This is a straightforward documentation improvement for the otherwise complete series, which appears ready for merging with all open questions resolved. The core team (Junio, Christian, Patrick, and Justin) have all signed off on the approach, with Karthik Nayak implementing the structural changes. The series builds on existing promisor-remote infrastructure while aligning with broader codebase efforts toward type safety and maintainability.
