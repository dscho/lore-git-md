This thread has finalized a 5-patch series that enhances Git's promisor-remote protocol with configurable validation of remote attributes during clone and fetch operations. The changes allow servers to advertise specific attributes (like partial clone filters and tokens) while enabling clients to verify them, all while maintaining backward compatibility.

The discussion reached consensus on the technical implementation through several iterations, with key contributions from Patrick Steinhardt, Karthik Nayak, and Christian Couder. Junio Hamano provided final guidance on naming the helper function that finds promisor_info instances, suggesting either `promisor_info_find()` or `find_promisor_info()`. Christian Couder has now agreed to this naming in the latest email, resolving one of the last open items. While Junio raised the possibility of optimizing with strmap, Christian explained that the current linear search is sufficient given the expected small number of promisor remotes, making this a non-blocking future optimization.

The series introduces a new `struct promisor_info` to replace the previous strvec implementation, adds comprehensive documentation, and expands test coverage. All major design decisions have been settled, with the patches now in their final form pending Junio's review. The changes maintain Git's protocol security while preparing for future extensions, following the project standards for protocol specifications and type safety improvements.
