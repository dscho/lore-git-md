This thread centers on extending Git's promisor-remote protocol to support configurable validation of remote attributes like partialCloneFilter and token during clone/fetch operations. The 5-patch series, now at v7, has reached technical completion with all implementation feedback addressed, CI passing, and comprehensive test coverage. The core work introduces `struct promisor_info` to replace parallel strvec arrays, providing type safety and clearer structure.

The latest patch (4/5) implements client-side validation through a new `promisor.checkFields` config, requiring advertised fields to match locally configured values through case-sensitive comparison. This completes the client counterpart to the server-side field transmission added earlier, particularly useful for ensuring filter consistency and verifying authentication tokens. The implementation includes new helper functions and maintains the series' approach to case sensitivity (strict protocol-level comparisons but case-insensitive config parsing).

Junio Hamano has approved most technical aspects but maintains a preference for "configuration variable" terminology over "field," while Christian Couder (who implemented parsing improvements in v7) defends the "field" terminology but remains open to change. The only remaining open items are this terminology decision and determining an error handling strategy for malformed percent-encoded input - neither of which block the series' core functionality. With Jean-Noël Avila having finalized documentation and Karthik Nayak confirming implementation completeness, this appears ready for merging pending those final discussions.
