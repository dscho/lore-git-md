This thread covers a finalized 5-patch series that enhances Git's promisor-remote protocol to support configurable validation of remote attributes during clone and fetch operations. The changes allow servers to advertise additional fields (currently `partialCloneFilter` and `token`) and clients to verify these attributes, improving protocol security while maintaining backward compatibility.

The series has progressed through four iterations, with all major design points settled and all reviewer feedback addressed. Key changes in v4 include implementation refinements like better empty field handling, standardized terminology ("field name" consistently using `test_config` for test cleanup, and passing CI tests. The structural foundation was established in patch 1 with the introduction of a `promisor_info` struct, while patch 2 (the focus of this email) implements server-side field advertisement through a new `promisor.sendFields` config option.

Reviewers including Junio Hamano, Christian Couder, and Karthik Nayak have engaged with the series, suggesting improvements to documentation formatting and implementation details that have all been incorporated. The patches now appear ready for merging, with comprehensive test coverage verifying field transmission, client acceptance/rejection behavior, and edge cases like URL encoding and unknown field handling. This work aligns with broader codebase efforts to improve type safety while preparing for future protocol extensions.
