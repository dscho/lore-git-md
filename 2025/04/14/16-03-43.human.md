Feature patch completing the promisor-remote extension series, adding client-side validation of extra fields. This is the final patch in Christian Couder's 4-part series enhancing the promisor-remote protocol to support configurable remote attributes.

The patch introduces a new `promisor.checkExtraFields` configuration that lets clients validate additional fields (like partial clone filters) advertised by servers against their local configuration. When enabled, the client will reject promisor remotes whose advertised fields don't match the local values. The implementation handles the validation while maintaining backward compatibility - older clients will simply ignore the extra fields.

Key technical aspects:
- New config option takes a space/comma-separated list of fields to validate
- Validation occurs during remote acceptance checks
- Fields are matched against corresponding `remote.<name>.<field>` configs
- Works in conjunction with the server-side `promisor.sendExtraFields` from patch 3
- Includes test demonstrating validation of `partialCloneFilter` field

The patch appears well-integrated with the series' earlier work, completing the client-side counterpart to the server capabilities added previously. Test coverage is thorough, showing both successful validation and proper packet tracing. The implementation maintains the case sensitivity behavior established earlier in the series (an acknowledged limitation the author plans to address separately).

This concludes the core functionality for configurable promisor-remote attributes, providing a foundation for future extensions while keeping backward compatibility. The series appears ready for review, with the outstanding case sensitivity question noted as follow-up work.
