This is a discussion follow-up in the ongoing thread about multi-remote synchronization workflows in Git. D. Ben Knoble responds to Klaus Frank's concerns about the fragility of using a local repository as the source of truth for multi-remote sync.

The exchange focuses on the tradeoffs between local-source control versus remote-to-remote synchronization. Knoble suggests that pushing to multiple remotes from a local repository effectively creates automatic backups, addressing Frank's concern about notebook fragility. He also notes that using SSH-based workflows (rather than hosted forges) could simplify cron-based synchronization when working with a local copy.

The discussion highlights the core tension in this thread: local-source approaches provide control but require persistent state management, while remote-to-remote sync would better handle stateless CI environments but appears more complex to implement. Knoble's response reinforces the local-source position while acknowledging the practical backup considerations raised by Frank.
