Maintainer feedback on promisor-remote field advertisement protocol.

Junio Hamano responds to Christian Couder's patch that would allow servers to advertise arbitrary additional fields with promisor remotes. While acknowledging the technical approach works, he raises two significant concerns about the protocol design:

First, he argues the protocol documentation should precisely define all supported fields and their semantics rather than presenting this as an open-ended extension mechanism. The current "extra fields" framing suggests these are optional additions when they should be treated as core protocol elements with well-defined meanings.

Second, he warns about security implications of an unconstrained field mechanism. Without strict definitions of allowed fields and value formats, the protocol could introduce parsing vulnerabilities. He suggests limiting the attack surface by enumerating supported fields rather than allowing arbitrary key-value pairs.

This feedback comes as the final patch in a 4-part series that otherwise appeared ready for merging. The maintainer isn't rejecting the approach outright but is requesting tighter protocol specifications before accepting this extension mechanism. The discussion may require revisions to both the implementation and documentation to address these interface design concerns.
