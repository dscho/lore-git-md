Progress feedback and filter interaction issues in `git clone --bundle-uri`. This is a response to Xavier Morel's report about two UX problems with the bundle-uri feature, confirming the issues and providing historical context about attempted fixes.

Toon Claes acknowledges the lack of progress feedback during bundle processing (particularly for local files) is a known UX problem. They reference several past attempts to address it, including a v2 patch series [1] that faced technical challenges [2], and an alternative approach [3] that remains unimplemented due to unresolved technical details [4]. The response makes clear this is an acknowledged gap but currently lacks an active maintainer working on it.

Regarding the `--filter` interaction, Claes confirms this is a broader design limitation in the current bundle-uri implementation. The client cannot know if advertised bundles match the provided filter, and filtering only applies to the post-bundle reconciliation fetch. This matches Xavier's experimental findings that the combination yields both slower performance and larger repository size.

The email provides useful historical links to previous discussion threads and patch attempts, showing this isn't a newly discovered issue but rather a known limitation that has resisted clean solutions. The technical challenges appear non-trivial, particularly around progress reporting during bundle application. The filter interaction issue seems more fundamental to the bundle-uri design and may require protocol-level changes to properly support.
