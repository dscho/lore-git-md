This is a technical refinement in the ongoing Meson build system thread about implementing header checking functionality. Toon Claes suggests two alternative approaches for generating the list of header files to check, building on Karthik Nayak's implementation.

The first proposal dynamically collects header files by scanning through source lists (`builtin_sources`, `libgit_sources`, `third_party_sources`) rather than maintaining a static list. This would automatically include any new headers added to these source categories. The second, more conservative suggestion shows how to explicitly add headers when they're created via `custom_target()` calls, which might be more maintainable than a standalone list.

The suggestion comes after earlier discussion in the thread had already settled on using the variable name `generated_headers` (rather than `headers_generated`) and proper handling of third-party sources. Toon's feedback focuses specifically on reducing maintenance burden of the header lists while keeping the functionality robust.
