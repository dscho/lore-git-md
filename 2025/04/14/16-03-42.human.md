This is the third patch in a 4-part series extending promisor-remote capabilities to support additional remote configuration fields. The series aims to let servers advertise extra remote attributes (like partial clone filters) and allow clients to validate them against local configuration.

The current change introduces server-side support for advertising additional fields through a new `promisor.sendExtraFields` config option. When set, the server will include specified remote config values (like `partialCloneFilter`) alongside the standard `name` and `url` fields in its promisor-remote capability advertisement. The patch includes thorough documentation updates and tests showing the new behavior in action.

Key technical details:
- New config option accepts comma/space-separated field names
- Fields must correspond to valid `remote.<name>.*` config keys
- Server validates field names using the recently refactored `is_config_key_char()`
- Maintains backward compatibility - existing clients ignore extra fields
- Includes test case demonstrating partial clone filter advertisement

The implementation looks solid, with careful attention to config validation and URL encoding. The test coverage is good, showing both the advertisement format and end-to-end clone behavior. The next patch in the series will implement client-side validation of these extra fields.

This continues the series' pattern of well-structured changes with clear documentation and testing. The only minor note is that case sensitivity in field name comparison (mentioned in earlier thread context) remains to be addressed in future work.
