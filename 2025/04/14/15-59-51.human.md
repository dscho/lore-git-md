Bug report regarding UTF-8 BOM handling on Windows. Messester reports that when cloning a specific repository (infinilore.cs.git), Git shows all files as deleted and re-added due to an apparent automatic conversion from UTF-8-BOM to plain UTF-8 encoding. The issue occurs with Git for Windows 2.49.0.windows.1 and appears related to the user's configuration where `core.autocrlf=true` is set.

The report suggests this may be a Windows-specific behavior where Git is silently modifying file encodings during checkout. The provided patch file (attached) demonstrates the encoding change, though the exact mechanism isn't fully diagnosed. This could potentially affect users working with BOM-marked files in mixed-platform environments.

The reporter is primarily seeking an explanation of the behavior rather than proposing a fix. The issue appears to be a genuine edge case in Git's text handling that warrants investigation, particularly for Windows users dealing with UTF-8-BOM files. The thorough configuration details provided should help in reproducing the issue.
