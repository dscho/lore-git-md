This thread investigates text encoding and line ending issues causing unexpected file modifications after cloning, primarily affecting Git for Windows v2.49.0. The original report (from messester) demonstrated UTF-8-BOM to UTF-8 conversion problems, with test repository https://github.com/NinekoTheCat/infinilore.cs.git showing issues under Windows-specific configurations (core.autocrlf=true, core.symlinks=false). Analysis by Lucas Seiki Oshiro identified two distinct problems: Windows-specific BOM handling and cross-platform line ending conversion issues.

The community has now reached consensus on the line ending aspect - Torsten Bögershausen confirmed these can be resolved through standard Git mechanisms (.gitattributes declarations plus git add --renormalize), with Junio C Hamano recently acknowledging this solution. Attention now focuses exclusively on the remaining BOM conversion issue, which appears to be Windows-specific. The thread has progressed from initial diagnosis to recognizing these as distinct problems with different solution paths - one resolved, one still under investigation. Next steps will likely involve deeper analysis of Windows' text processing behavior regarding BOMs.
