This is a set of responses to the Git 20th anniversary community interview, providing personal perspectives on Git usage and evolution. Lucas Seiki Oshiro shares thoughtful answers across several categories:

The contributor highlights Git's code archaeology tools (`git bisect`, `git log -S/-G`, etc.) as their favorite underappreciated features, noting how these debugging tools consistently impress colleagues. They recount a practical disaster scenario where an accidentally created `master` tag disrupted deployments, solved with a simple `git push` refspec deletion.

On design changes, Oshiro suggests restructuring Git's CLI to follow Docker's more hierarchical pattern (e.g., `git branch add/delete/list`), arguing this would improve consistency. They identify squash merges and submodules as commonly misunderstood features, while advocating for better utilization of commits as documentation.

Looking forward, the contributor predicts Git will remain dominant but sees potential for more Git-based version control systems (like jujutsu), drawing parallels to languages built on the JVM. The responses show a clear appreciation for Git's core design while suggesting usability improvements, from someone who came to Git after it was already established. The answers are practical and grounded in real-world experience, though the contributor declines to comment on historical comparisons due to their relatively recent adoption.
