This is a platform compatibility discussion within the build system alignment series, specifically addressing Cygwin regex support. Patrick Steinhardt questions why Git still maintains compatibility with Cygwin 1.7 (released before 2015) in the NO_REGEX configuration, given that modern Cygwin has had working regex support for nearly a decade.

The technical context shows that:
- Cygwin 1.7's regex implementation failed certain tests (t4018, t4034)
- Modern Cygwin (2.0+) uses FreeBSD's regex and passes all tests except t7815.12 (NUL character matching)
- The patch proposes limiting NO_REGEX to only Cygwin 1.7 while adding a CYGWIN exclusion for t7815.12

Patrick raises a strategic question about backward compatibility - whether supporting such old Cygwin versions is still necessary, suggesting users would typically update their installations. This introduces a potential simplification opportunity for the build system by dropping legacy support, though the thread hasn't yet addressed whether there are valid use cases for maintaining 1.7 compatibility. The discussion may influence whether to keep the version-specific check or remove Cygwin 1.7 support entirely.
