This is a maintainer confirmation in the ongoing discussion about GPG signing in Git's email workflows. Junio C Hamano reinforces the technical distinction between transport authentication (for email) and object signing (for commits/tags), agreeing with previous technical analysis that commit signatures cannot be preserved through patch workflows due to committer identity changes.

The email clarifies that transport-level signing (via S/MIME or PGP) would be the appropriate layer for email authentication, but notes this is currently outside `git send-email`'s capabilities. Hamano suggests this could be a worthwhile area for future development, implicitly validating the direction of the discussion while indicating the solution would need to be implemented at the email transport layer rather than trying to preserve commit signatures.

Key technical points confirmed:
1. Commit signatures are fundamentally incompatible with patch workflows (reiterating Matt Hunter's point)
2. Email authentication would need to happen at the transport level (MUA/MSA)
3. `git send-email` currently lacks this capability
4. Such functionality would constitute a separate development effort

This maintains the thread's technical consensus while gently steering discussion toward implementation possibilities for transport authentication, having established the fundamental constraints. The email serves as both a technical confirmation and a subtle call for potential contributors to work on email signing integration, without prescribing any particular solution.
