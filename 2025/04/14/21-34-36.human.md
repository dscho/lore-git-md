This is a discussion about change IDs in Git commit messages, focusing on implementation challenges and problem definition. Nico Williams responds to Ben Knoble's questions about using URIs as change IDs, particularly the practical difficulties of attaching review URIs to local commits before they exist in a code review system.

The email explores several key points: the need for local tooling to attach change IDs (possibly built into Git itself), the distinction between review URIs and simpler ticket IDs, and examples from projects like Illumos that enforce strict ticket ID formats. Williams acknowledges the chicken-and-egg problem of creating review URIs for local commits but suggests ticket systems might offer a simpler alternative.

The discussion touches on whether change IDs would actually solve core problems like commit evolution tracking or just paper over UI limitations in tools like GitHub. Williams concedes that better web UIs (like Gerrit's interdiff support) might reduce the need for change IDs, but notes this doesn't help with GitHub's current limitations.

This continues the thread's trend of questioning whether the proposed technical solutions (Change-IDs and Patch Set IDs) are addressing the right problems, with Williams providing concrete examples of existing practices while acknowledging the complexity of some proposals.
