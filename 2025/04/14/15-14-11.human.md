This is a discussion about GPG signing in Git's email workflow, focusing on clarifying the distinction between transport authentication and commit signature preservation. Junio C Hamano (Git's maintainer) responds to Konstantin Ryabitsev's explanation of the Linux kernel's patatt solution, which provides an alternative approach to patch signing.

The key point is that there are two distinct authentication needs when working with patches: transport authentication (ensuring patches aren't modified in transit) and commit signature preservation (which is fundamentally incompatible with patch workflows due to committer identity changes). The Linux kernel's patatt solution addresses transport authentication through a DKIM-like header approach that supports multiple signing algorithms (PGP, SSH, ed25519).

This email thread represents an important clarification in the ongoing discussion, with the maintainer acknowledging the distinction between these two use cases. The patatt solution from the kernel community serves as a production-proven example of how transport authentication can be handled separately from commit signing. The discussion appears to be moving toward recognizing header-based approaches like patatt as a viable solution for transport authentication in Git's email workflow.
