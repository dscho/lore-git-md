Refactoring patch in a series extending promisor-remote capabilities.

This is the second patch in Christian Couder's 4-part series to enhance the promisor-remote protocol. The series aims to allow servers to advertise additional remote configuration fields (beyond just name and URL) and enable clients to validate them against local configuration.

This particular change replaces the existing `struct strvec` storage for promisor remote information with a new `struct promisor_info` linked list containing a `string_list` of fields. The author explains this is necessary to better handle the planned expansion of supported fields, as the strvec approach doesn't scale well for multiple field types.

The implementation:
- Introduces `struct promisor_info` to store remote attributes as key-value pairs
- Maintains the same functionality but with a more flexible data structure
- Preserves the existing case-sensitive comparison behavior (though the author notes this will be addressed in a later iteration)
- Includes thorough updates to all related functions to use the new structure

The change appears well-contained and mechanical, focused purely on the internal data structure without modifying external behavior. It follows logically from the first patch's refactoring of config helper functions, setting up for the actual capability extensions to come in subsequent patches.
