Performance optimization patch in Taylor Blau's MIDX/cruft pack series (v2 6/8). This patch improves delta compression efficiency when repacking with `--unpacked` by properly including loose objects in the name-hash traversal.

The change modifies `add_unreachable_loose_objects()` to accept a `rev_info` struct, allowing loose objects (particularly commits) to be added as reachability tips during traversal. This was previously impossible because the `rev_info` was scoped too narrowly in the original implementation. While not affecting correctness, the oversight made delta compression less effective for loose objects.

Key technical changes:
- Adds `rev_info` parameter to `add_unreachable_loose_objects()`
- Modifies `add_loose_object()` to add commits as pending objects when `revs` is non-NULL
- Updates all callers to pass either NULL or the appropriate `rev_info`
- Maintains existing behavior for non-commit objects and when `revs` is NULL

The patch builds on earlier refactoring in the series (particularly v2 5/9 which moved `rev_info` declaration) and demonstrates the preparatory work paying off. Test coverage appears to be handled by the existing `t/t7704-repack-cruft.sh` and `t/t5331-pack-objects-stdin.sh` tests mentioned in the thread context.

This is a focused optimization that should produce slightly better packed output sizes when repacking with loose objects, though the thread notes real-world performance data from GitHub's deployment is still pending. The change is well-contained and follows the series' pattern of incremental improvements to the pack-objects machinery.
