This is a feature patch series extending the promisor-remote capability to support additional configuration fields. The series allows servers to advertise extra remote configuration fields (like partial clone filters) and clients to validate these fields against their local configuration.

Christian Couder proposes enhancing the promisor-remote protocol capability to transmit more than just remote names and URLs. The server can now advertise additional fields to send (via promisor.sendExtraFields config), while clients can verify these fields (via promisor.checkExtraFields). For example, a server could include partialCloneFilter settings when advertising remotes.

The implementation involves significant refactoring, replacing 'struct strvec' with 'struct string_list' for more flexible string handling, following up on previous review feedback. The author notes a current limitation where field name comparisons are case-sensitive (which they plan to fix in a future iteration) and mentions more tests are coming.

This appears to be a well-motivated extension to the promisor remote functionality, with the author clearly identifying both the use case and current limitations. The patch series touches protocol documentation, config handling, and the promisor-remote implementation itself, suggesting it will need careful review from those familiar with partial clone and promisor remote internals.
