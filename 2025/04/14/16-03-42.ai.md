This is the third patch in a 4-part series extending promisor-remote capabilities, focusing on server-side advertisement of additional remote configuration fields. The patch introduces a new `promisor.sendExtraFields` config option that lets servers specify which remote attributes (like partial clone filters) should be advertised to clients during clone/fetch operations.

The implementation:
- Adds `promisor.sendExtraFields` config documentation in promisor.adoc
- Updates protocol-v2.adoc to specify the extended capability format
- Introduces validation helpers for field names (using the refactored `is_config_key_char` from earlier patches)
- Implements server-side field collection via `extra_fields_sent()` and `append_extra_fields()`
- Adds test coverage in t5710 demonstrating field transmission

Key technical points:
- Fields must match remote.* config keys (alphanumeric with hyphens)
- Server always sends mandatory "name" and "url" fields
- New test verifies transmission of "partialCloneFilter" and custom fields
- Maintains backward compatibility - clients ignore unknown fields (for now)

The patch builds on the series' foundation (struct promisor_info refactored config helpers) and sets up for the final patch which will implement client-side validation. The implementation appears thorough with documentation updates, input validation, and test coverage. One notable limitation is that field name case sensitivity remains unaddressed (acknowledged as a known issue from earlier thread context).
