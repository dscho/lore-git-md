This is the seventh patch in Patrick Steinhardt's 13-part series refactoring the object store subsystem, continuing the conversion of object existence checks to use the new `has_object()` API with explicit flags.

The patch focuses on `builtin/index-pack.c`, specifically the collision check performed when indexing packed objects. The current implementation uses `repo_has_object_file_with_flags()` with `OBJECT_INFO_QUICK`, which unintentionally fetches promisor objects even though we only need to check for object existence. The change replaces this with `has_object()` with no flags, which by default avoids both packfile reloading and promisor object fetching - more appropriate behavior for this collision check case.

Key technical details:
- Changes the collision check in `sha1_object()` to use `has_object(..., 0)`
- Removes the `OBJECT_INFO_QUICK` flag which was triggering unwanted promisor fetches
- Maintains the same read lock/unlock pattern around the existence check
- Part of the systematic conversion from `repo_has_object_file*` to `has_object()`
- Follows the pattern established in earlier patches where the default `has_object()` behavior (no flags) is preferred when we just need a quick existence check

This appears to be a straightforward improvement that prevents unnecessary object fetches during index-pack operations. The change is small (3 lines modified) and focused, continuing the series' pattern of methodical API updates. The commit message clearly explains the problematic behavior and why the new approach is better.
