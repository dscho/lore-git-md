This is a technical discussion about Change-ID requirements in the context of patch-based code review workflows. Remo Senekowitsch responds to Nico Williams' claim that GitLab's force-push detection demonstrates Change-IDs are unnecessary for tracking patch evolution.

The email provides a detailed analysis of GitLab's actual capabilities, showing that while it can show interdiffs between whole-branch versions when commenting on full diffs, it fails to track individual patch evolution when commenting on specific commits. Senekowitsch demonstrates this through practical testing, noting GitLab simply marks comments on commit changes as "outdated" without showing patch evolution.

Key technical observations include the distinction between whole-branch interdiffs (which GitLab handles) versus per-patch evolution tracking (which it doesn't), and the specific UI limitations when commenting on individual commits versus full diffs. The analysis reinforces the thread's core requirement that true patch-based review needs explicit Change-ID tracking to follow individual patch evolution across versions.

This response advances the thread by providing concrete evidence that similarity-based approaches (like GitLab's) don't fully meet the evolution tracking requirements previously established in the discussion. It strengthens the case for Change-IDs by showing practical gaps in existing implementations that rely solely on force-push detection and similarity matching.
