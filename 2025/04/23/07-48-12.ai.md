This is the second patch in Patrick Steinhardt's 13-part refactoring series cleaning up the object store subsystem, part of the ongoing `the_repository` removal effort.

The patch removes the `loose_object_path()` function, which was a thin wrapper around `odb_loose_path()` that always operated on the primary object database of a given repository. The change inlines the functionality at all call sites, directly using `odb_loose_path()` with `the_repository->objects->odb` instead. This simplification affects several files that handle loose object paths, including HTTP-related code and object-file operations.

The change is mechanical and doesn't modify behavior - it just removes an unnecessary layer of indirection. The patch updates 6 files (removing 18 lines while adding 10) and includes a documentation comment for `odb_loose_path()` that was previously only on the wrapper function. This continues the series' theme of cleaning up object storage APIs and reducing unnecessary abstractions.

Key technical details:
- Removed function: `loose_object_path()` from object-store.[ch]
- Replacement: Direct calls to `odb_loose_path()` with explicit ODB access
- Affected subsystems: HTTP transport, loose object writing
- Documentation preserved by moving comment to `odb_loose_path()` declaration

This change is straightforward and uncontroversial, following logically from the header reorganization started in patch 1. It helps reduce the object-store interface surface area while making the code's object database access patterns more explicit.
