This is the fifth patch in Patrick Steinhardt's 13-part series refactoring the object store subsystem, continuing the preparation for `the_repository` removal. The patch introduces a new flag `HAS_OBJECT_FETCH_PROMISOR` to control object fetching behavior in partial clones.

The change modifies `has_object()` to optionally fetch missing promisor objects when the new flag is set, while maintaining the default behavior of not fetching. This addresses a gap where some callers need fetch capability during the transition from `repo_has_object_file()` to `has_object()`. The implementation flips the logic of `OBJECT_INFO_SKIP_FETCH_OBJECT` to be the default unless explicitly overridden by the new flag.

Key technical details:
- Adds `HAS_OBJECT_FETCH_PROMISOR` bitflag alongside existing `HAS_OBJECT_RECHECK_PACKED`
- Restructures flag handling in `has_object()` to make fetch behavior explicit
- Updates documentation to clarify default non-fetch behavior
- Modifies object-store.c and object-store.h (91 lines net reduction in header so far)
- Part of broader promisor object handling changes hinted at in earlier patches

The patch appears well-contained, with clear motivation stated in the commit message about supporting necessary fetch behavior during the transition. It maintains backward compatibility while adding the new capability. Reviewers will likely examine whether all call sites needing fetch behavior have been identified and whether the flag naming properly reflects its promisor-specific nature.
