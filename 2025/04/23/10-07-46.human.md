This is a refactoring patch in Patrick Steinhardt's series to modernize Git's object storage code, specifically part of the effort to remove `the_repository` global. The patch introduces a new flag `HAS_OBJECT_FETCH_PROMISOR` to the `has_object()` function, allowing callers to optionally fetch missing objects from promisor remotes in partial clones.

Karthik Nayak reviews the change positively, noting the improved readability of the flag handling logic. The patch maintains the default behavior of not fetching promisor objects (preserving security and performance characteristics) while providing an opt-in mechanism for cases where fetching is desired. This change enables future conversion of remaining callsites still using the older `repo_has_object_file()` API.

The modification is clean and focused - it touches just two files with a net addition of 7 lines while improving the organization of related flags into an enum. The commit message clearly explains the motivation and maintains backward compatibility. This appears to be a well-considered step in the larger object store cleanup effort.
