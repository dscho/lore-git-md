This is the ninth patch in Patrick Steinhardt's 13-part refactoring series cleaning up Git's object store subsystem, part of the larger `the_repository` removal effort. The patch modifies `ref_resolves_to_object()` to stop automatically fetching promisor objects when validating references, continuing the series' theme of removing unwanted object fetches.

The change replaces `repo_has_object_file()` with `has_object()` using the `HAS_OBJECT_RECHECK_PACKED` flag, which maintains the same validation behavior but skips promisor object fetching. The rationale is straightforward: references pointing to non-existent objects are inherently broken and should be reported as such, rather than triggering a fetch attempt.

This follows the pattern seen in previous patches of the series, where similar conversions were made across various subsystems. The change is small (just one line modified) but aligns with the series' broader goals of cleaning up object handling and reducing unnecessary indirection. The patch maintains error reporting for invalid references while removing behavior that could silently trigger object fetches during reference validation.
