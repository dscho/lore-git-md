This is the eighth patch in Patrick Steinhardt's 13-part series refactoring the object store subsystem, continuing the effort to remove `the_repository` global usage and clean up object file handling.

The patch modifies `builtin/show-ref.c` to change how it checks for object existence when printing references. Previously it used `repo_has_object_file()` which would automatically fetch missing promisor objects (objects promised by a remote but not yet locally available). The patch switches to `has_object()` with `HAS_OBJECT_RECHECK_PACKED` flag, which maintains the packed object check but skips promisor object fetching.

The rationale is that reference validation shouldn't need to fetch objects - references should never point to missing objects in the first place. This aligns with the series' broader goal of making object existence checks more precise about when they should trigger fetches. The change is straightforward, just replacing one function call with another while preserving the error handling behavior when objects are truly missing.

This continues the pattern seen in previous patches of converting object existence checks to avoid unwanted promisor fetches. It affects the reference listing functionality but not the core reference database operations. The patch maintains the same error reporting when references point to invalid objects, just without the side effect of potentially fetching objects unnecessarily.

Technical details to note for future discussion tracking:
- Uses `HAS_OBJECT_RECHECK_PACKED` flag to maintain packed object checking
- Preserves existing error message format when objects are missing
- Touches same object existence check pattern being standardized across codebase
- Part of systematic conversion from `repo_has_object_file()` to more precise alternatives
- No performance impact expected since it removes an unnecessary fetch path
- Maintains compatibility with partial clone functionality while being more precise
- Follows same conversion pattern as previous patches in the series
