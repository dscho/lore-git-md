This is a technical discussion about Change-ID semantics in the ongoing standardization effort. Remo Senekowitsch responds to Nico Williams' suggestion of using ticket IDs as Change-IDs by drawing a clear distinction between free-form commit message metadata and structured commit headers. The key technical point is that while Git tolerates arbitrary text in commit messages, putting unrelated metadata in structured headers like Change-ID could break functionality, analogous to misusing the parent header. Senekowitsch argues for keeping Change-IDs semantically pure rather than overloading them with unrelated information like ticket IDs, suggesting such metadata should go in dedicated headers if not in the free-form message body. The exchange highlights the tension between practical conventions (like ticket IDs in subjects) and maintaining clean semantic boundaries in commit metadata structures.
