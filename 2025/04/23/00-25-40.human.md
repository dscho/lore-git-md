This is a technical discussion about Change-ID requirements for patch-based code review systems, specifically responding to claims that GitLab's approach demonstrates sufficient functionality without Change-IDs.

Remo Senekowitsch analyzes GitLab's interdiff capabilities and finds them lacking for true patch-based review. While GitLab can show diffs between whole-branch versions when commenting on the entire diff, it fails to track individual patch evolution - when commenting on a specific commit, it simply marks comments as outdated without showing how that particular patch changed. This reinforces the argument that proper Change-IDs are needed to track patch evolution across revisions.

The email provides concrete testing results showing GitLab's limitations, countering Nico Williams' suggestion that GitLab's approach proves similarity checks are sufficient. Senekowitsch maintains that without Change-IDs, tools cannot properly show interdiffs for individual evolving patches, only for whole-branch states. The analysis is thorough and grounded in practical testing, strengthening the case for standardized Change-IDs in the ongoing discussion.
