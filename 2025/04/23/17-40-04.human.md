Bugfix for `index-pack`'s REF_DELTA chain handling, completing Patrick Steinhardt's series. This patch fixes a long-standing issue where `index-pack` incorrectly fails on valid packfiles containing multi-hop REF_DELTA chains (A->B->C) when intermediate objects (B) exist in the local repository. The problem stems from overly cautious cycle detection logic that dates back to 2014.

The fix modifies `threaded_second_pass()` to properly handle cases where REF_DELTAs reference objects already present locally, skipping already-processed deltas rather than failing. The changes are careful to maintain thread safety and proper memory management during pack processing. Accompanying test updates demonstrate the corrected behavior, converting previous `test_expect_failure` cases to success tests.

This addresses a real-world scenario that can occur during fetches when servers use REF_DELTAs (rather than the more common OFS_DELTAs) and clients have partial object graphs. The solution is well-considered, preserving the important cycle detection for actual cycles while allowing valid multi-hop references. The patch builds on the new test infrastructure from earlier in the series to verify the fix.
