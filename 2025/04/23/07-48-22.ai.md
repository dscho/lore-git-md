This is the 12th patch in Patrick Steinhardt's 13-part series refactoring the object store subsystem, continuing the effort to remove `the_repository` global usage and clean up object file handling. The patch focuses on the bulk-checkin mechanism used during object writing.

The change modifies how bulk-checkin handles promised objects (from partial clones) when checking if an object already exists. Previously it would fetch promised objects via `repo_has_object_file()`, but now uses `has_object()` with `HAS_OBJECT_RECHECK_PACKED` to avoid these fetches. The rationale is that it's more efficient to use locally-written objects than fetching from promisor remotes, and that hash collisions (while theoretically possible) are both unlikely and would represent a security issue regardless since the user has write access.

The patch touches the `already_written()` function in bulk-checkin.c, changing just one line to use the new API. This continues the series' pattern of converting object existence checks while avoiding unwanted promisor fetches. The change aligns bulk-checkin behavior with other writing paths like `write_loose_object()` that don't protect against hash collisions either.

Key technical points for future reference:
- Converts another `repo_has_object_file()` callsite to `has_object()`
- Uses `HAS_OBJECT_RECHECK_PACKED` flag to skip promisor fetches
- Affects bulk-checkin's object writing path
- Maintains series' theme of reducing promisor fetches during writes
- Minimal change (1 line) but with detailed rationale about hash collision tradeoffs
