This is a test case addition as part of a bugfix series for `git index-pack`'s handling of REF_DELTA chains. The patch adds a failing test that demonstrates how `index-pack` incorrectly rejects valid packfiles containing certain REF_DELTA chains.

The test creates a scenario where a thin packfile has a REF_DELTA chain A->B->C, with C not included in the packfile but present in the client repository. The test shows that `index-pack` fails when it encounters this valid case, mistakenly treating it as a cycle when resolving the deltas in a particular order. The test is marked as `test_expect_failure` since it documents the current broken behavior that the next patch in the series will fix.

The test setup is thorough, creating a server with multiple commits, extracting tree objects to form the delta chain, and using the new `test-tool pack-deltas` helper from the previous patch to generate the problematic packfile. This appears to be a well-constructed test that precisely targets the edge case the series aims to fix. The commit message clearly explains both the current incorrect behavior and what correct behavior should look like.
