This is a technical discussion about Outlook-specific Message-ID handling in `git send-email`, part of a larger patch series adding OAuth2 support. Brian Carlson responds to Aditya Garg's patch that retrieves Message-IDs from Outlook SMTP server responses to maintain thread continuity.

Carlson acknowledges that while Outlook's Message-ID replacement behavior is standards-compliant, it does cause practical problems for email threading. He raises concerns about the current implementation's hostname-based detection (`is_outlook()` function), suggesting it might miss some Outlook-hosted configurations (like CNAME aliases).

The response proposes a more flexible approach: adding a configuration option to control Message-ID handling with three modes - default behavior, auto-detection (current Outlook check), and always using server-provided IDs. This would make the solution more robust against different hosting setups while maintaining the thread-fixing benefits.

This discussion represents ongoing refinement of patch 2/3 in the series, which Junio Hamano had previously approved with minor documentation tweaks. Carlson's feedback suggests the Outlook detection logic may need to be more flexible before final acceptance.
