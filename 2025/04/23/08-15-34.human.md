This is a CI/build system patch that addresses a workflow issue in GitHub Actions. It's part of Karthik Nayak's v5 series implementing header checking in Meson builds, specifically focusing on ensuring Git is available before repository checkout.

The patch fixes a subtle but important CI behavior where GitHub Actions would fetch the repository as a tarball (via REST API) when Git wasn't installed, rather than doing a proper clone. This created inconsistencies with GitLab CI and didn't match real-world development scenarios. The solution installs Git explicitly before checkout using a cross-distro compatible approach (supporting apt, dnf, and apk package managers) that also updates package caches where needed.

The change is well-motivated by the thread discussion, particularly feedback from Phillip Wood who helped identify this issue. The implementation is thorough, handling multiple package managers and including cache updates to prevent installation failures. This ensures the subsequent Meson-based header checks (the main focus of the series) will work reliably in CI environments.

The patch demonstrates good attention to real-world build scenarios while maintaining consistency across different CI platforms. It's a focused improvement that solves a concrete problem in the broader header checking implementation.
