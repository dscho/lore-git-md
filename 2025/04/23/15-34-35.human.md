This is a follow-up discussion in the ongoing series adding Outlook compatibility to `git send-email`, specifically about the Message-ID handling patch. Junio Hamano clarifies his earlier confusion about the patch's timing - the commit message originally suggested the Outlook-assigned Message-ID would be inserted into the current email's headers, but in reality it's stored for use in future replies' In-Reply-To fields. Aditya Garg confirms this is the intended behavior and agrees to update the commit message to better reflect the actual flow: Outlook discards Git's Message-ID, assigns its own during transmission, and Git captures that ID from the SMTP response to maintain threading in subsequent messages.

The exchange reveals the subtle but important distinction between modifying outgoing headers versus preserving threading information for replies. While the core mechanism remains unchanged (extracting the Outlook-assigned ID from the SMTP response when using Office365/Outlook servers), the discussion leads to clearer documentation of the behavior. This refinement addresses the last remaining point of confusion in an otherwise well-received series that adds OAuth2 support and Outlook compatibility to Git's email subsystem.
