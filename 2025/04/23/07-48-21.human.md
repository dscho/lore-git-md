This is the 11th patch in Patrick Steinhardt's 13-part series refactoring the object store subsystem, part of the ongoing `the_repository` removal effort. The patch clarifies the logic around excluding promisor objects in `list-objects.c` when the `--exclude-promisor-objects` flag is used.

The current code checks for missing promisor blobs using `repo_has_object_file()`, which seems problematic since that function would normally fetch missing promisor objects. However, the patch explains this isn't actually broken because `fetch_if_missing` gets disabled when the exclusion flag is set. Still, the current implementation is confusing and potentially fragile.

The patch replaces `repo_has_object_file()` with the more appropriate `has_object()` call, explicitly passing the `HAS_OBJECT_RECHECK_PACKED` flag. This makes the intention clearer and better matches the actual behavior, while maintaining the same exclusion logic. The change is small (just 3 lines modified) but improves code clarity in an area that handles partial clone behavior.

This continues the series' pattern of converting object existence checks to use the new `has_object()` API while cleaning up confusing or redundant code paths. The change appears straightforward and well-justified, with no obvious downsides.
