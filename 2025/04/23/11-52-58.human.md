This is part of an ongoing test modernization series converting string-list tests from shell scripts to C unit tests. The email is a follow-up suggestion to patch 2/5, which moves the "test_split" functionality into the new unit test framework.

Patrick Steinhardt suggests simplifying the test helper `t_string_list_split()` by having it accept expected strings as varargs rather than requiring a pre-built string_list. This would make the test cases more concise by eliminating the need to explicitly create and populate an expected_strings list before each test.

The suggestion comes in response to seeing the test setup code where `t_create_string_list_dup()` is called to build expected results before passing them to the split test helper. The series as a whole is in good shape, with maintainer feedback being incorporated, and this appears to be an optional refinement that could make the test code cleaner.
