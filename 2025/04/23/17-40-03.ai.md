This is the second patch in a bugfix series addressing `index-pack`'s incorrect handling of REF_DELTA chains. The patch adds a failing test case that demonstrates the issue where `index-pack` falsely detects a cycle when processing a valid packfile with a REF_DELTA chain A->B->C, where B and C already exist in the client repository.

The test creates a server repository with 4 commits, then constructs a thin packfile containing REF_DELTAs from A to B and B to C. After resetting the server to exclude C object, it clones the repository and attempts to index the pack, which currently fails despite being a valid scenario. The test is marked as `test_expect_failure` to document the current broken behavior.

The test relies on the new `test-tool pack-deltas` helper introduced in the first patch of the series to generate the specific packfile structure needed to reproduce the issue. This demonstrates good test design by building on the new infrastructure to precisely target the edge case.

The commit message clearly describes the expected behavior (successful indexing) versus current behavior (false cycle detection), setting up for the fix in the next patch. The test case is thorough, covering the multi-hop delta chain scenario with objects existing in different locations (packfile vs client repository).
