This is the first patch in a series adding OAuth2 support to `git send-email`, specifically implementing SMTP bearer authentication. The patch comes from Julian Swagemakers with co-authorship from Aditya Garg, and represents the fourth iteration of this work.

The core change implements direct SMTP AUTH handling for OAuthBEARER and XOAUTH2 authentication types, which aren't supported by Perl's Authen::SASL module. The implementation follows RFC standards (5801 and 7628) for bearer token handling, requiring TLS encryption and properly formatting the authentication strings. The patch includes two helper functions to generate the correct authentication strings for each protocol variant.

Documentation is updated to explain that when using these auth types, the bearer token must be provided via `--smtp-pass` or a credential helper, and TLS encryption is mandatory. Example configurations are provided for both Gmail and Office 365 accounts, showing how to integrate with the git-credential-oauth helper.

The implementation looks thorough, with clear attention to protocol specifications and security requirements. The patch has been tested by the git-credential-oauth maintainer, suggesting real-world validation of the approach. This appears to be a well-considered solution to enable Git email submission through modern OAuth2-protected email services.
