Platform compatibility patch in a series enabling Windows/ARM64 support, specifically addressing memory allocator selection.

This patch modifies the build configuration to disable the nedmalloc allocator specifically for CLANGARM64 builds on Windows. The rationale is that nedmalloc fails to compile on ARM64 and has been effectively unmaintained since 2017, with no expectation of fixes. The change preserves nedmalloc usage for other Windows platforms while excluding it for the new ARM64 target.

The technical change is straightforward - wrapping the `USE_NED_ALLOCATOR` setting in a conditional that checks for the CLANGARM64 MSYSTEM environment. This follows the pattern established in earlier patches of the series for platform-specific configuration. The patch maintains compatibility with existing Windows builds while accommodating the ARM64 architecture's requirements.

This is part of a broader effort to enable Git on Windows/ARM64 systems, building on Git for Windows' existing ARM64 support. The series has already received maintainer approval for its general approach in v1, with v2 incorporating style fixes and additional platform accommodations. The allocator strategy connects to ongoing discussions about memory management in Git, though this patch focuses narrowly on the immediate compilation issue for ARM64.
