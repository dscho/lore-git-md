This is the 11th patch in Patrick Steinhardt's 13-part refactoring series cleaning up the object store subsystem, part of the `the_repository` removal effort. The patch focuses on clarifying promisor object handling in the list-objects machinery.

The patch addresses a potentially confusing interaction in `process_blob()` where `repo_has_object_file()` was being used to check for blob existence while excluding promisor objects. While this appears problematic since `repo_has_object_file()` would normally fetch missing promisor objects, the code actually works because `fetch_if_missing` is disabled when `--exclude-promisor-objects` is set. The patch makes this behavior more explicit by using the new `has_object()` API with `HAS_OBJECT_RECHECK_PACKED` flag instead, which doesn't fetch promisor objects by default.

Key technical details:
- Changes the object existence check in `process_blob()` from `repo_has_object_file()` to `has_object()` with `HAS_OBJECT_RECHECK_PACKED`
- Maintains the same behavior but makes the non-fetching nature explicit
- Part of the broader conversion from old object store APIs to new ones
- Touches the list-objects subsystem which handles `--exclude-promisor-objects` filtering
- Follows the pattern seen in previous patches (8-10) of converting object existence checks

The change is straightforward and maintains existing behavior while making the code's intent clearer. This continues the series' theme of removing indirect API layers and making object handling more explicit. The patch doesn't introduce new functionality but improves code clarity around promisor object handling, which could help prevent future bugs in this subtle area.
