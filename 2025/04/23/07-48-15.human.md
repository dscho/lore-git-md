This is the fifth patch in Patrick Steinhardt's 13-part series refactoring the object store subsystem, part of the ongoing effort to remove `the_repository` global. The series has been cleaning up object storage code through header reorganization and API modernization.

This patch introduces a new flag `HAS_OBJECT_FETCH_PROMISOR` for the `has_object()` function, which will eventually replace `repo_has_object_file()`. The key change allows controlled fetching of promisor objects (objects that may be lazily fetched from a remote) when explicitly requested, while maintaining the default behavior of not fetching. This addresses a gap where some callers actually want to fetch missing promisor objects, while others don't.

The implementation modifies the internal flag handling in `has_object()` to conditionally set `OBJECT_INFO_SKIP_FETCH_OBJECT` based on the new flag. The patch is small and focused (13 lines changed across two files), continuing the series' pattern of incremental, well-explained changes. It appears to be a thoughtful preparation for the eventual removal of `repo_has_object_file()`, though reviewers may want to verify the promisor object fetching behavior matches expectations across all call sites.
