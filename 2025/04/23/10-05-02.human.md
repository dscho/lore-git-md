This is a CI/build system patch in Karthik Nayak's ongoing series to port header checking to Meson builds. Phillip Wood provides review feedback on the first patch, which ensures Git is installed before repository checkout in GitHub CI workflows to maintain consistency with GitLab CI behavior.

The patch addresses an issue where GitHub Actions would fall back to tarball extraction when Git isn't available during checkout, rather than doing a proper clone. Phillip suggests minor wording improvements to the commit message but approves the technical approach. The implementation handles multiple package managers (apk, dnf, apt-get), updating caches where needed.

Phillip clarifies that the current behavior isn't strictly cloning when falling back to tarball extraction, and suggests using "source tree" instead of "repository" when referring to the checked-out code without a .git directory. The changes look solid and maintain consistency across CI systems while providing a more realistic build environment.
