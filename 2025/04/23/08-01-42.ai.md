Platform compatibility cover letter for Windows/ARM64 support series (v2). This is the second iteration of a 6-patch series co-authored by Dennis Ameling and Johannes Schindelin, building on Git for Windows' existing ARM64 support and addressing feedback from the initial submission.

The series enables Git to build and pass tests on Windows/ARM64 systems, taking advantage of newly available GitHub Actions runners for this architecture. Key changes include compiler support in bswap.h and config.mak.uname, disabling the unmaintained nedmalloc allocator specifically for Windows/ARM64 builds, MSVC compatibility fixes, path adjustments for system config files, and reducing max tree depth to prevent stack overflows on this platform.

The v2 revision contains a single code style improvement in patch 6, replacing an #else #if construct with #elif as suggested in v1 feedback. The series remains otherwise unchanged from its initial submission, which maintainer Junio Hamano had already acknowledged as "cleanly structured". 

Technical details carried forward from v1 include:
- Built-in bswap detection for ARM64 (bswap.h)
- CLANGARM64 build support (config.mak.uname)
- Stack depth reduction for Windows/ARM64 clang builds (environment.c)
- Continued use of mimalloc (already adopted by Git for Windows) instead of nedmalloc
- MSYS2-specific stack overflow handling (exit code 127)
- Path adjustments for /etc/git* locations on Windows/ARM64

The series appears ready for integration pending verification on actual ARM64 Windows runners, with allocator strategy and recursive tree traversal remaining as known architectural considerations for future work. The minimal changes in v2 suggest the technical approach remains sound while addressing a straightforward style nit from the initial review.
