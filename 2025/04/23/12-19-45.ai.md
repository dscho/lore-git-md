Feature patch implementing OAuth2 authentication for `git send-email`, part of a series addressing modern email provider compatibility. This is the first of three patches in v4 of the series, focusing specifically on SMTP bearer authentication support.

The patch adds direct OAuth2 bearer token authentication to `git-send-email.perl`, bypassing Perl's Authen::SASL module which lacks support for OAUTHBEARER and XOAUTH2 mechanisms. It implements two authentication string formats (OAUTHBEARER per RFCs 5801/7628 and XOAUTH2 for Google's protocol) and enforces TLS encryption as required by the standards. The implementation includes proper error handling with dummy request fallback per RFC 7628.

Key technical additions include new helper functions `generate_oauthbearer_string` and `generate_xoauth2_string` to format the tokens, plus `smtp_bearer_auth` to handle the authentication flow. The documentation is updated to specify that OAuth2 requires TLS and can use either direct token passing or credential helpers. The patch shows integration with git-credential-oauth for token management, though that requires external modifications.

This appears to be a well-researched implementation with clear references to relevant RFCs and proper security considerations (TLS enforcement). The patch includes real-world configuration examples for both Gmail and Office 365, suggesting practical testing. As the first in a coordinated series with multiple sign-offs, it represents a serious effort to modernize Git's email sending capabilities.
