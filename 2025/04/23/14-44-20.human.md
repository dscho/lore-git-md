This is a follow-up discussion in the ongoing thread about integrating Git's benchmark infrastructure with Meson. Christian Couder raises a specific UX concern about error handling when the `time` command is missing during benchmark execution.

The current behavior (printing "No tests defined") is technically correct but not very user-friendly. Christian suggests a more direct error message similar to how Meson handles missing dependencies elsewhere in the build system. This would immediately alert users that benchmarking requires the `time` command rather than silently failing.

Patrick Steinhardt had previously acknowledged this as the last remaining UX issue in the otherwise complete benchmark integration. He had proposed a future enhancement to list available benchmarks during build setup for better discoverability, but Christian's suggestion offers a simpler immediate solution that matches Meson's existing error patterns.

The thread shows the technical implementation is largely settled, with reviewers now focusing on final polish items. Toon Claes has already approved the series, suggesting this remaining discussion is about optional improvements rather than blocking issues.
