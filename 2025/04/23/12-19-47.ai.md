Feature patch adding dynamic OAuth2 token generation to `git send-email`, part of the v4 series improving Outlook/OAuth2 compatibility. This is the third and final patch in the series, introducing a new `smtp-passeval` option that executes a user-specified command to generate OAuth2 tokens at runtime.

The patch adds configuration support for dynamically generating OAuth2 tokens via external scripts, similar to msmtp's `passwordeval`. When set, `smtp-passeval` runs the specified command and uses its output as the SMTP password, overriding any static `smtpPass` value. The implementation includes error handling for failed script execution and updates both the man page and Perl script.

Key technical details:
- Adds `--smtp-passeval` command-line option and `sendemail.smtpPassEval` config
- Executes the specified command in a shell context and captures stdout as the password
- Overrides any static password from `smtpPass` when set
- Includes documentation showing example usage with M365-IMAP token generation script
- Modifies `smtp_auth_maybe()` in `git-send-email.perl` to handle dynamic token generation
- Maintains security by requiring TLS encryption (enforced by earlier patches in series)

The patch completes the OAuth2 support by addressing the token refresh workflow, though reviewers may want to scrutinize the security implications of arbitrary command execution. The example shows integration with an external Python script (`refresh_token.py`), suggesting this is meant to work with credential helpers like git-credential-oauth.
