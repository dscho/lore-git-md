This is the second patch in a series adding Outlook compatibility fixes to `git send-email`, specifically addressing Message-ID handling issues. The patch focuses on Outlook's nonstandard behavior where it discards the original Message-ID header and generates its own, which breaks in email threading.

The technical solution adds an `is_outlook()` helper to detect Outlook SMTP servers (office365.com/outlook.com domains) and extracts the server-assigned Message-ID from the SMTP response string "2.0.0 OK <Message-ID>". When detected, it updates the local `$message_id` variable to match Outlook's assigned ID, ensuring proper threading in follow-up replies. The implementation includes both success reporting and fallback warning when extraction fails.

Junio Hamano's review approves the approach while suggesting minor documentation clarifications about how the updated Message-ID flows into reply headers. He also recommends omitting discussion of Outlook's proprietary X-Microsoft-Original-Message-ID header since it's not actionable. The patch appears technically sound with proper error handling and i18n support via `__()` wrappers.

Key technical elements:
- New `is_outlook()` hostname matcher
- Message-ID extraction from SMTP response via regex capture
- Updates `$message_id` in-place when successful
- Maintains existing behavior for non-Outlook servers
- Includes user-visible feedback about ID reassignment
- Preserves all existing error handling flows

This complements the series' OAuth2 authentication work by addressing another Outlook-specific interoperability issue. The solution is narrowly scoped to the threading problem while being robust against extraction failures. No outstanding technical concerns remain beyond Junio's minor documentation suggestions.
