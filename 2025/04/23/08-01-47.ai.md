Platform compatibility patch in the Windows/ARM64 support series (v2 5/6), addressing config file locations. This follows up on an earlier change that moved Git for Windows system config files from `/mingw64/etc/` to the more standard `/etc/` location, but the original condition didn't account for ARM64 builds using the `/clangarm64/` prefix.

The patch modifies `config.mak.uname` to handle both MINGW and CLANGARM64 prefixes by normalizing them to `mingw64` before comparison. This ensures ARM64 builds also use the system config files from `/etc/` rather than the less discoverable `/clangarm64/etc/`. The change is motivated by GitHub issue #5431 and maintains consistency with the user experience on x86_64 Windows systems.

Key technical details:
- Build system change only affecting Windows platforms
- Modifies two identical conditions in `config.mak.uname` (lines 489 and 749)
- Uses `subst` to normalize both `mingw` and `clangarm` prefixes to `mingw`
- Maintains same config file paths (`../etc/gitconfig` and `../etc/gitattributes`)
- Follows from fb5e3378f8 which originally introduced the `/etc/` move

This appears to be a straightforward fix that aligns ARM64 behavior with existing x86_64 behavior, though it may warrant verification that the ARM64 build process properly handles the `/etc/` path resolution. The patch is narrowly scoped to the build system configuration without introducing new platform-specific behavior.
