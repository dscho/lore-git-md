Aditya Garg and Julian Swagemakers are collaborating on a series to modernize `git send-email` for contemporary email providers. The v5 patchset adds OAuth2 authentication support (needed as providers like Microsoft/Outlook phase out traditional passwords) and fixes Outlook-specific Message-ID handling quirks. The implementation takes a direct approach to OAuth2 by bypassing Perl's Authen::SASL module limitations, supporting both standard OAUTHBEARER and Google's XOAUTH2 formats with enforced TLS encryption.

Junio Hamano has reviewed the series: he's approved the Outlook Message-ID handling patch (with minor doc tweaks), but wants security review for the dynamic token generation feature and Authen::SASL maintainer Greg Kroah-Hartman's input on bypassing the SASL module. Brian M. Carlson raised concerns about Outlook detection robustness in enterprise environments where SMTP endpoints might use custom CNAMEs. The authors have demonstrated successful real-world usage by sending the v5 patches from an Outlook account using the new functionality, with M Hickford confirming it works.

Key remaining questions center on security implications of executing token generation commands and whether the direct SMTP bearer auth approach is technically sound. The authors have engaged Greg Kroah-Hartman for his expert review on the SASL module question. The patches include comprehensive documentation updates and example configurations for common providers.
