This thread has addressed a long-standing issue with `git send-email`'s handling of Message-IDs when sending through Outlook SMTP services. The core solution (v6) by Aditya Garg, now queued by Junio Hamano, detects standard Outlook hosts by their domain names and adjusts Message-ID generation accordingly. A subsequent v7 patch added enterprise configurability via a tri-state option (`--[no-]smtp-outlook-id-tweak`) to handle custom domains, addressing Greg Kroah-Hartman's use case. The solution cleanly separates from authentication concerns, with OAuth2 support now available in the released Authen-SASL 2.1800.

In recent discussion, Aditya has responded to Yao Zi's proposal for more generalized runtime detection of SMTP quirks, explaining why this isn't practical given fundamental differences in how providers like Outlook (which includes Message-IDs in responses) and Gmail (which doesn't) behave. The current hostname-based approach with configurable overrides remains the most reliable solution, though the door is open to future expansion if other providers' behaviors can be reliably characterized. Documentation updates are complete per Eric Sunshine's review, with only minor final tweaks pending. The thread is effectively resolved with the core solution ready for inclusion in an upcoming release.
