This thread has successfully addressed a long-standing issue with `git send-email`'s handling of Outlook Message-IDs, which was breaking email threading. Aditya Garg led the effort with a v6 patch series that detects Outlook SMTP servers via hostname (smtp.office365.com/smtp-mail.outlook.com) and properly preserves Message-IDs. The solution was later extended in v7 to support enterprise configurations through a tri-state configuration option (`--[no-]smtp-outlook-id-tweak`), addressing Greg Kroah-Hartman's use case. Junio Hamano has queued the core solution, and the enterprise extension is implemented.

The discussion recently turned to whether a more generic runtime detection approach could handle other problematic providers like Tencent mail. Yao Zi initially proposed this but, after technical discussion with Aditya, acknowledged that Outlook's non-standard SMTP responses make runtime detection impractical - Outlook includes Message-IDs with angle brackets while Gmail omits them entirely. The consensus is that the current hostname-based approach is the most reliable solution for Outlook, though the door remains open for future work on other providers.

All technical issues appear resolved, with only final polish remaining on documentation about credential helper OAuth2 usage (now supported in the released Authen-SASL 2.1800). The solution maintains backward compatibility and cleanly separates the Message-ID handling from authentication concerns. While focused on Outlook, the implementation leaves room for potential future support of other providers with similar quirks, should someone contribute the necessary detection logic.
