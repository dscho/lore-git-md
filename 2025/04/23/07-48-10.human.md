This is a cover letter for a 13-patch series focused on cleaning up the object store subsystem, with an eye toward eventually removing `the_repository` global. The series comes from Patrick Steinhardt and builds on recent preparatory work in the object-file area.

The main thrust is simplifying and modernizing the object store interface. Several functions are being moved to more logical homes (like `struct packed_git` to packfile.h), while others like `loose_object_path()` are being dropped entirely. The most significant change is deprecating `repo_has_object_file()` in favor of `has_object()`, which provides more explicit control over packfile reloading and promisor object fetching behavior. The commit message notes this makes behavior more predictable when checking for object existence.

The series includes treewide updates to callers of the deprecated functions, touching areas from index-pack to http-walker to bulk-checkin. These changeset appears thorough, updating all relevant call sites while maintaining consistent behavior. The changes are framed as preparatory work for the larger `the_repository` removal effort, suggesting this is part of an ongoing architectural cleanup rather than a one-off.

The patch count is high but the individual changes look focused and mechanical - mostly moving or renaming functionality rather than introducing new complexity. Given the author's track record with object store changes and the clear motivation tying into broader architectural goals, this seems like a well-considered cleanup worth reviewing for anyone working in the object storage layer.
