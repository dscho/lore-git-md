This is a platform compatibility patch in a series adding Windows/ARM64 support, specifically addressing the memory allocator choice. 

The change disables the nedmalloc allocator for Windows/ARM64 builds when using the CLANGARM64 toolchain, since nedmalloc doesn't compile on this platform and appears unmaintained since 2017 (with no fixes expected). The patch modifies `config.mak.uname` to make this conditional, keeping nedmalloc enabled for other Windows builds.

This is part of a v2 series that builds on maintainer-approved v1 patches while adding style fixes and compiler feature detection. The series aims to enable Git to build and pass tests on Windows/ARM64 systems using new GitHub Actions runners. The allocator choice connects to broader discussions about memory management on Windows, where Git for Windows currently uses Microsoft's mimalloc instead.

The patch is straightforward and well-justified, maintaining compatibility while removing a non-working component. It follows the series' pattern of careful platform-specific adjustments without disrupting other configurations.
