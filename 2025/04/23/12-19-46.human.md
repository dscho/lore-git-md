This is the second patch in a 3-part series improving `git send-email` compatibility with Outlook, specifically addressing Message-ID handling. The patch fixes thread tracking issues that occur when sending emails through Outlook's SMTP servers.

The core issue is that Outlook discards the Message-ID header generated by `send-email` and replaces it with its own random ID, storing the original in a proprietary header. This breaks email threading since replies reference the original (now discarded) Message-ID rather than Outlook's replacement. The patch solves this by extracting the server-assigned Message-ID from the SMTP response and using it for subsequent replies.

The implementation adds an `is_outlook()` helper to detect Outlook servers and modifies the message sending flow to parse the new Message-ID from the server response. The change is Outlook-specific and doesn't affect other email providers. The patch includes clear warning messages if the ID extraction fails.

This appears to be a well-motivated change with a specific, real-world compatibility problem. The implementation is focused and includes appropriate error handling. As part of a larger series adding OAuth2 support and Outlook compatibility, this patch handles the threading aspect of the integration.
