This is a discussion about build system modernization, specifically around qsort() behavior detection in the Meson transition.

Patrick Steinhardt responds to Eli Schwartz's concerns about detecting qsort() performance characteristics at build time. The core debate is whether to maintain platform-specific knowledge about qsort() implementations (as historically done in the Makefile) or to use generic detection in Meson and only add platform exceptions if problems arise.

Steinhardt takes a pragmatic stance, questioning whether the O(n^2) qsort() issue is still relevant today. He suggests treating this as a "canary" - if no users report problems with the simpler generic approach, the project could eventually remove this legacy complexity altogether. This reflects a broader philosophy of periodically reassessing old infrastructure as the ecosystem matures.

The exchange highlights an ongoing tension in the build system modernization effort between preserving historical platform-specific knowledge versus simplifying maintenance with more generic approaches. Steinhardt leans toward the latter unless concrete evidence emerges that platform-specific handling is still needed.
