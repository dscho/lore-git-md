Patrick Steinhardt's object store refactoring series continues to progress, now at version 2 with patch 5/13. The thread focuses on modernizing Git's object storage code as part of the broader effort to remove the `the_repository` global variable. Karthik Nayak has already reviewed and approved the approach in earlier patches, with Patrick addressing all feedback in this revision.

The latest patch introduces finer control over how Git handles promisor objects (used in partial clones) through a new flag system. It adds `HAS_OBJECT_FETCH_PROMISOR` to complement the existing `HAS_OBJECT_RECHECK_PACKED`, allowing callers to explicitly opt into fetching missing promisor objects when needed while keeping the default behavior of skipping such fetches. The 13-line change modifies `oid_object_info_extended()` to respect these flags, converting a single `#define` into an enum for better maintainability. This addresses a key gap that was preventing full conversion from the older `repo_has_object_file()` API.

The series has already seen significant header reorganization in earlier patches, moving function declarations to more appropriate subsystem-specific headers and reducing `object-store.h` by 91 lines. With patches 1-4 reviewed and approved, the thread now turns to these more subtle behavioral changes around object fetching. The remaining patches in the series will handle edge cases in HTTP transport and other subsystems, building toward the larger goal of cleaner, more maintainable object storage code.
