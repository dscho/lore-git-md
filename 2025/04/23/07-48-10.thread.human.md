Patrick Steinhardt has sent a v2 of his 13-patch series modernizing Git's object storage code as part of the ongoing object-file-cleanup effort. The series prepares for eventual removal of the `the_repository` global variable by cleaning up APIs and removing unnecessary indirection layers. The key technical change replaces `repo_has_object_file()` with a more explicit `has_object()` API that provides better control over promisor object fetching and packfile reloading.

Karthik Nayak has already reviewed and approved patches 3-9 from v1, with all minor feedback addressed. The remaining patches (10-13) will address edge cases in HTTP transport, list-objects filtering, and bulk-checkin operations. Notable technical improvements include new flags for controlling promisor object behavior, optimized index-pack collision checks that avoid unnecessary promisor fetches, and a 31-line reduction in object-store.h through proper header reorganization.

This work connects to several larger efforts including the ODB abstraction work and René Scharfe's `the_repository` removal initiative. The series maintains backward compatibility while touching core functionality across multiple subsystems, with particular attention paid to preserving partial clone workflows. The v2 changes are minor commit message improvements, keeping the technical approach consistent from the well-reviewed v1.
