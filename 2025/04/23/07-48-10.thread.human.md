Patrick Steinhardt's 13-patch series refactoring Git's object store subsystem has progressed with Karthik Nayak reviewing patch 05/13, which introduces promisor object handling to the `has_object()` function. This change is part of the larger effort to remove deprecated functions like `repo_has_object_file()` and clean up object storage code in preparation for eliminating the `the_repository` global variable.

The series has already achieved significant cleanup, reducing object-store.h by 31 lines and converting object existence checks across 22 files. The latest patch adds a new `HAS_OBJECT_FETCH_PROMISOR` flag to control promisor object fetching behavior, inverting the default to skip fetching unless explicitly requested. Karthik approved the implementation, noting its improved readability and that it maintains existing packed-recheck capabilities.

This work builds on previous object-file cleanup efforts and connects to broader initiatives like the ODB abstraction work. The systematic conversion touches multiple subsystems including partial clone functionality, packfile operations, and HTTP transport. With Karthik's review of patch 05/13, the series continues moving toward its goal of modernizing Git's object storage internals while maintaining security and performance characteristics.
