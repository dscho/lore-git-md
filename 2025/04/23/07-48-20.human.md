This is the 10th patch in Patrick Steinhardt's 13-part series refactoring the object store subsystem, part of the ongoing effort to remove `the_repository` global. The patch focuses on the HTTP walker component, which handles object fetching via the dumb HTTP protocol.

The change prevents unnecessary duplicate fetches when checking for object existence. Currently, the HTTP walker first checks if an object exists locally using `repo_has_object_file()`, which may trigger a promisor remote fetch - but this is wasteful since the walker is already about to fetch the object itself. The patch replaces this with `has_object()` using the `HAS_OBJECT_RECHECK_PACKED` flag, which skips promisor fetches while still properly checking packed objects.

The modification is straightforward, touching just two callsites in http-walker.c with identical changes. This continues the series' pattern of converting object existence checks to avoid unwanted promisor fetches, following similar changes made to show-ref.c and refs.c in earlier patches. The change should be uncontroversial as it removes redundant network operations without changing observable behavior.
