This is the fourth patch in a 6-part series refactoring Git's Meson build system, focusing on networking library dependencies. The patch adds checks for `-lnsl` and `-lsocket` alongside the existing `-lresolv` check, standardizing how these networking libraries are handled across platforms.

The change is motivated by existing platform-specific handling in `config.mak.uname` and `configure.ac`, particularly for SunOS systems where these libraries are commonly needed. The patch consolidates the checks into a single array-based approach similar to the function availability checks addressed in earlier patches of the series.

The implementation is straightforward - it replaces the individual `resolv` check with an array that includes all three networking libraries, each marked as optional. This maintains compatibility while ensuring all potentially needed libraries are checked for consistently. The Windows-specific handling remains unchanged in a separate branch of the conditional.

This appears to be a logical continuation of the series' goal to standardize build system checks. The change is small and focused, though it might benefit from mentioning any specific platforms where these additional libraries are known to be required (beyond the general SunOS reference). The patch follows the series' established pattern and doesn't introduce any obvious technical concerns.
