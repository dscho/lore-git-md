This is the third patch in a 6-part series refactoring Git's Meson build system to standardize function availability checks. The patch specifically addresses the detection of sysinfo() functionality.

The change replaces a simple header existence check for `sys/sysinfo.h` with a more precise check that verifies the header actually contains the `struct sysinfo` with the `totalram` member that Git's garbage collection code uses. This fixes a portability issue where Solaris has a completely different `sys/sysinfo.h` with incompatible contents, despite the header existing.

The commit message explains that Solaris's sysinfo() has a different signature and purpose (querying hardware provider information) compared to Linux's memory statistics functionality. The new check ensures we only enable the feature when the specific struct member we need is available, rather than assuming the header's presence implies compatibility.

The patch moves the sysinfo check to group it with other struct member checks in the meson.build file, maintaining the series' goal of organizing these tests more clearly. The change is straightforward - removing the old header check and adding a new member check with the same `-DHAVE_SYSINFO` define to preserve compatibility with existing code.

This appears to be a well-justified change that properly handles a real portability issue, though it leaves the Solaris implementation unaddressed (as noted by the author, who explicitly states they're not invested in Solaris support). The patch maintains consistency with the series' approach while fixing a specific detection problem.
