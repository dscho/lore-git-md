This is the fifth patch in a 6-part series refactoring Git's Meson build system to standardize function availability checks. The patch fixes a typo in the networking function checks where `strerror` was incorrectly listed instead of `hstrerror`.

The correction aligns with the series' goal of properly handling networking-related dependencies. While `strerror` is a standard C library function for general error reporting, `hstrerror` is specifically for network-related error codes (part of the same networking stack as `inet_ntop` and `inet_pton` that are already being checked). The commit notes we never actually used `NO_STRERROR` in the codebase, making this a clear mistake rather than an intentional check.

The change maintains the pattern established in previous patches where missing functions trigger corresponding `NO_` compile-time defines. This particular check was likely overlooked during the initial Meson port since the incorrect function name wouldn't have caused build failures - it just meant we weren't properly detecting `hstrerror` availability on platforms where it might be missing.

The patch is straightforward with a single-line change to the `meson.build` file, continuing the series' incremental improvements to build system reliability. No behavioral changes result from this fix since we weren't using the incorrect define, but it properly enables the intended portability check for future use.
