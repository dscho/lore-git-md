This is a CI/build system discussion in the ongoing thread about implementing header checking in Meson builds. Junio C Hamano responds to Phillip Wood's discovery that GitHub Actions is extracting tarballs rather than doing a proper Git checkout, which breaks the new header checking functionality that relies on `git ls-files`.

1. Junio expresses surprise that CI jobs use tarball extraction rather than Git checkouts, noting this contradicts the expected behavior of the `actions/checkout` workflow.
2. He acknowledges the importance of supporting tarball builds but questions whether GitHub Actions' tarball extraction properly represents real-world tarball usage, since Git's release tarballs are built with `make dist` rather than `git archive`.
3. The discussion reveals a tension between the new Meson implementation (which requires Git) and the Makefile's fallback to `find` when Git isn't available.

This email doesn't propose concrete solutions but highlights an important architectural consideration for the Meson migration - the need to properly handle non-Git build environments while maintaining consistency with release processes.
