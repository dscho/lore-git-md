Final patch in the Meson build system refactoring series, focusing on Windows-specific networking symbol handling and compatibility implementations.

This patch completes the standardization of networking function checks by addressing Windows platform specifics. It makes two key changes: first, it stops checking for networking symbols (`inet_ntop`, `inet_pton`, `hstrerror`) on Windows entirely, noting these functions don't exist there (contrary to CMake's "incompatible" claim). Second, it adds the corresponding compatibility implementations from `compat/` when these symbols are missing on non-Windows systems, matching the Makefile's behavior.

The change follows the series' pattern of aligning Meson with existing build system behavior while improving maintainability. The author notes this may slightly speed up Windows builds by skipping unnecessary compiler checks. The patch maintains the existing `networking_dependencies` array handling from previous patches while adding the missing compatibility source file linkage.

Technical details include:
- Windows-specific conditional (`host_machine.system() != 'windows'`)
- Maintained symbol list: `inet_ntop`, `inet_pton`, `hstrerror`
- New source file additions via `libgit_sources += 'compat/' + symbol + '.c'`
- Preserved NO_* flag behavior for non-Windows platforms
- Unchanged IPv6 handling (`getaddrinfo` check remains unconditional)

The patch concludes the series' networking function standardization without introducing new dependencies or platform-specific exceptions beyond the existing Windows handling. It leaves open whether future work might revisit CMake compatibility claims or further optimize symbol checks.
