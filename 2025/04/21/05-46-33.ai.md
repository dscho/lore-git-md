This is a bugfix for macOS launchctl maintenance scheduling, following up on the earlier thread about incorrect calendar intervals. The patch specifically addresses the root cause of the scheduling issues by replacing the `Day` key with `Weekday` in the launchctl plist configuration, which is the proper way to specify days-of-week scheduling according to launchd.plist(5) documentation.

The change modifies two lines in builtin/gc.c's `launchctl_schedule_plist` function, correcting both daily and weekly schedule templates. For daily jobs, this ensures they run every day rather than just the first six days of each month. For weekly jobs, using `Weekday` with value 0 properly implements weekly scheduling instead of the previous daily behavior caused by the undocumented `Day:0` specification.

Josh Heinrichs provides additional context that while the behavior of `Day:0` was undocumented in launchd's man pages, their testing showed it behaved equivalently to omitting the Day specification entirely (resulting in daily runs). The switch to `Weekday` is a clear improvement that properly implements the intended scheduling behavior through documented mechanisms.

The patch is narrowly focused and builds on the thread's established context about macOS scheduling problems. It maintains the same approach of direct fixes without introducing new complexity or affecting other platforms. The change appears technically sound and well-justified by both documentation and testing evidence.
