This is the third patch in a 6-part series refactoring Git's Meson build system to standardize function availability checks. The focus here is improving the detection of `sysinfo()` functionality, particularly for Solaris compatibility.

The patch replaces a simple header check for `sys/sysinfo.h` with a more precise test that verifies the header actually contains the specific `struct sysinfo` with the `totalram` member that Git's garbage collection code needs. This addresses a real portability issue - Solaris has a completely different `sysinfo.h` with incompatible function signatures, so the old check could give false positives.

The change is well-motivated by the commit message's clear explanation of the Solaris incompatibility and reference to Oracle's documentation. The implementation looks straightforward, just moving the existing check to group with similar structure member tests later in the file. As with the rest of the series, this appears to be a thoughtful improvement to build system reliability without introducing new complexity.
