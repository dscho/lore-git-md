Platform compatibility patch adding ARM64 bswap support via compiler built-ins. This is the first of six patches in a series enabling Windows/ARM64 support, specifically targeting CLANGARM64 builds on Windows.

The patch modifies `compat/bswap.h` to use compiler built-in byte swap functions (`__builtin_bswap32`/`__builtin_bswap64`) when available (GCC 10+ or Clang 10+), falling back to existing implementations otherwise. This is particularly important for Windows/ARM64 builds where the current x86-specific inline implementations wouldn't work.

Key technical details:
- Adds detection for compiler built-in bswap functions using `__has_builtin`
- Maintains backward compatibility with older compilers
- Preserves existing x86-specific inline assembly fallback
- Only touches the bswap implementation, no behavior changes for existing platforms

The change is low-risk as it:
1. Only affects platforms where the built-ins are available
2. Maintains identical behavior through the abstraction
3. Is part of a focused platform enablement effort (Windows/ARM64)
4. Doesn't modify any core Git logic beyond byte swapping

The patch appears well-constructed with:
- Compiler version compatibility notes
- Clear fallback logic
- Maintained documentation
- Minimal scope (just the bswap.h changes needed for ARM64)

This establishes the foundation for subsequent Windows/ARM64 patches in the series by ensuring basic byte swapping operations work correctly on the new platform.
