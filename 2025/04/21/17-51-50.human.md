This is the final patch in a 6-part series refactoring Git's Meson build system to standardize function availability checks. The series has been consolidating ad-hoc checks into a more maintainable array-based approach.

The patch focuses on networking symbol checks (`inet_ntop`, `inet_pton`, `hstrerror`), making two key changes: First, it skips these checks entirely on Windows since the functions don't exist there anyway (matching CMake's behavior). Second, it properly adds compatibility implementations from the `compat/` directory when functions are missing on other platforms.

The author notes this both simplifies the Windows build (avoiding unnecessary compiler checks) and aligns with CMake's approach, though they correct CMake's misleading documentation about Windows "incompatibility" - the functions simply aren't present. The change is small (13 lines modified) but completes the series' goal of consistent networking dependency handling across build systems.

As the series finale, this appears to wrap up the networking checks portion of the refactoring. The patch maintains the same careful attention to cross-platform compatibility seen throughout the series, though like previous patches it hasn't yet received review feedback. The changes seem straightforward and low-risk, primarily aligning Meson with existing Makefile/CMake behavior.
