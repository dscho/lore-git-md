Refactoring patch making usage strings and string tables consistently `const` across Git's codebase, originally submitted by Ahelenia Ziemiańska. The mechanical changes add `const` to declarations in 15 files - primarily builtin commands (`blame.c`, `commit-graph.c`, `fast-export.c`, `mktree.c`, `pack-objects.c`, `show-branch.c`) and test programs (`test-bloom`, `test-date`, `test-find-pack`, `test-getcwd`, `test-pack-mtimes`, `test-proc-receive`, `test-rot13-filter`, `test-submodule`, `test-windows-named-pipe`). Modifications follow a consistent pattern: converting `static char foo[]` to `static const char foo[]` and `static const char *foo[]` to `static const char *const foo[]`.

Junio C Hamano reviewed the initial submission, confirming technical correctness of making both strings and array pointers immutable. He validated the stricter approach as a consistency improvement aligned with existing patterns like `parse_revision_opt()`'s `const char *const usagestr[]` parameter types. A follow-up addressed a minor compiler error encountered during implementation - a type mismatch where a `const char **` variable was assigned to a `const char *const *` array, which Ahelenia corrected in the resubmission.

The discussion notes that while static const declarations in library functions could enable compiler optimizations (like `.rodata` placement), those cases would need more analysis. The current patch focuses only on clearly identifiable command usage strings and string tables. The exchange with Junio established that the stricter const qualification improves consistency without introducing issues, and the successful build verification confirms the type fix resolves the edge case. The refactoring appears ready for inclusion as part of Git's ongoing const-correctness efforts.
