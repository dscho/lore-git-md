This is a CI/build system discussion in the ongoing thread about implementing header checking in Meson builds. Junio C Hamano responds to Karthik Nayak's analysis of why the CI was failing, noting that GitHub Actions was using a tarball extraction method that doesn't match real-world release tarballs.

Junio suggests documenting the CI fix in the commit message for future reference. He raises an important point about testing fidelity - the CI was testing an artificial scenario (tarball extraction without .git directory) that doesn't reflect how users actually build from release tarballs (created by `make dist`). While testing release tarball builds is valuable, Junio questions the usefulness of testing this particular GitHub Actions edge case.

The email doesn't propose any code changes but highlights a broader consideration about CI testing strategy. It shows the careful thought being given to ensuring the Meson build system properly handles both repository and tarball builds while maintaining testing relevance.
