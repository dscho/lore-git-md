Platform compatibility patch adjusting Windows/ARM64 system config locations, part of the Windows/ARM64 support series (5/6).

This patch modifies the detection logic for system configuration file locations on Windows to properly handle the new clangarm64 toolchain. The change ensures that Windows/ARM64 builds using clangarm64 will place system config files (gitconfig and gitattributes) in the more standard `/etc/` directory rather than the toolchain-specific `/clangarm64/etc/`.

The patch builds on previous work from 2021 that moved these files from `/mingw64/etc/` to `/etc/` for better discoverability. The current change extends that logic by normalizing the clangarm64 prefix to match the mingw64 pattern before checking the path, effectively treating both toolchains equivalently for config file placement.

Key technical details:
- Modifies `config.mak.uname` in two sections (Windows and MINGW) with identical changes
- Uses string substitution (`subst clangarm,mingw`) to normalize the prefix before comparison
- Maintains the existing behavior of placing files in `/etc/` while fixing the ARM64 case
- References GitHub issue #5431 in Git for Windows as the motivation

This appears to be a straightforward fix that follows the established pattern for Windows configuration handling. The change is narrowly scoped to the build system configuration without affecting runtime behavior beyond fixing the config file locations. As part of the larger Windows/ARM64 support effort, it helps ensure consistent behavior across different Windows toolchains and architectures.
