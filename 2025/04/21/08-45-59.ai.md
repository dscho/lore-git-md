This is a CI/build system discussion in the ongoing thread about implementing header checking in Meson builds. Phillip Wood identifies the root cause of the CI failure in the linux-meson job: the GitHub Actions workflow is extracting a tarball rather than cloning a Git repository, causing `git ls-files` to fail since Git isn't available in the environment. This explains why the issue only appears in CI and not in local testing.

The key technical observation is that the checkout action defaults to using the REST API (tarball extraction) when Git isn't installed in the CI environment, rather than performing a proper Git clone. Phillip suggests installing Git via `apt-get` before the checkout step as a potential solution. This is the last remaining blocker for merging the otherwise-complete Meson header checking implementation.

The thread context shows this is the final issue after extensive technical refinements to the implementation, including target naming standardization, dependency chaining, and exclusion handling. All substantive code changes have been addressed through multiple rounds of review with contributions from several maintainers. The current discussion focuses purely on the CI-specific environmental problem rather than any design or implementation concerns with the patch series itself.
