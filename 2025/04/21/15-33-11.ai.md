This is a CI/build system patch addressing the final blocking issue in Karthik Nayak's series to implement header checking in Meson builds. The thread has already resolved all technical aspects of the header check implementation, with only a CI-specific regression remaining.

The email identifies the root cause of the CI failure in GitHub Actions: when Git isn't installed, the workflow defaults to downloading a tarball via REST API instead of doing a proper Git checkout, which breaks `git ls-files` calls in the new header checking code. Karthik proposes installing Git explicitly before the checkout step, with platform-appropriate package manager commands (apt/dnf/apk) and proper workspace configuration.

The proposed solution:
1. Adds a pre-checkout step to install Git in the CI container
2. Handles different Linux distributions (Alpine, RHEL, Debian-based)
3. Configures the workspace as a safe directory
4. Maintains the existing workflow structure otherwise

This follows Phillip Wood's diagnosis and represents the last remaining piece before the series can be merged. The patch shows the implementation has been tested locally and on GitLab CI (where the issue doesn't manifest), with GitHub Actions being the only remaining platform needing this workaround. The change is narrowly scoped to fix the immediate CI problem while preserving all the header checking functionality implemented in previous patches.
