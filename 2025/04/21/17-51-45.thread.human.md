This thread centers on modernizing Git's build system by transitioning from autoconf to Meson, with a particular focus on standardizing how system capabilities are detected and configured. The current 6-patch series has evolved to address several technical nuances uncovered during review, including Windows networking verification and now historical macro naming conventions.

Junio Hamano recently clarified the longstanding distinction between `HAVE_FOO` and `NO_FOO` macros - they serve different purposes rather than being simple opposites. While `HAVE_FOO` reflects actual system capability detection, `NO_FOO` allows deliberately opting out of features (like mmap or regex) even when available. This insight helps frame decisions about how to structure the new Meson-based checks. Junio has indicated openness to simplifying to just `HAVE_FOO` with manual overrides, despite some transitional complexity.

The discussion remains active around several technical points: how to handle qsort() verification (generic detection versus platform-specific exceptions), whether to unify macro naming despite interface constraints, and the proper verification of networking libraries. Patrick Steinhardt has been the primary advocate for maintaining a generic verification approach, while Eli Schwartz has raised important questions about build system consistency and spotted several implementation details needing correction. The series appears close to finalization, with the macro naming discussion being one of the last conceptual hurdles before potential merging.
