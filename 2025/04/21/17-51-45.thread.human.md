This thread documents ongoing work to modernize Git's build system, particularly the transition to Meson while maintaining cross-platform compatibility. The discussion has covered two related efforts: a completed 6-patch series addressing Windows-specific handling (including getpagesize() and networking functions), and a new approach for standard library function verification.

The most recent patch focuses on Solaris compatibility, fixing how Git checks for `sysinfo` availability. Rather than just verifying the header exists, it now specifically checks for the `totalram` struct member that Git actually uses in `builtins/gc.c`. This prevents incorrect enablement on platforms like Solaris where the header exists but provides incompatible functionality. The change moves the check later in `meson.build` and uses a more precise verification method, maintaining Linux compatibility while properly handling Solaris.

The Windows-focused series is now complete, with all solutions merged including the final getpagesize() handling. Meanwhile, the new array-based approach for standard function verification (covering strcasestr, memmem, etc.) represents the next phase of build system modernization. Patrick Steinhardt has maintained technical consistency across both efforts, with Junio Hamano previously engaging on the Windows-specific issues and Eli Schwartz driving the getpagesize() implementation. The changes collectively advance Git's transition from Makefile to Meson while preserving cross-platform support.
