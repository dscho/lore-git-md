This is a follow-up discussion in the Meson header checking thread, focusing on CI environment issues. Phillip Wood responds to Junio C Hamano's question about why `git ls-files` fails in CI when checking out the repository, noting this wasn't previously observed in other series.

The key technical points are:
1. The current implementation in `contrib/coccinelle/meson.build` requires a Git checkout (via `.git` existence check) to run Coccinelle and header checks
2. The Makefile has a fallback to `find` when `git ls-files` fails, suggesting two potential solutions:
   - Skip header/Coccinelle checks entirely when not in a Git repo (current Meson approach)
   - Implement a `find` fallback similar to Makefile
3. The root issue stems from GitHub Actions extracting a tarball rather than cloning when Git isn't installed

This email doesn't propose a specific fix but clarifies the behavior difference between Makefile and Meson approaches while maintaining that the build should remain configurable even without Git. The discussion continues the thread's theme of aligning Meson behavior with Makefile while handling edge cases.
