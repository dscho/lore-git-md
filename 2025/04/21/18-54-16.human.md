This is a CI/build system discussion about header checking in Meson builds, following up on Karthik Nayak's series to implement Makefile-equivalent functionality.

Phillip Wood responds to Junio C Hamano's observation about CI failures when `git ls-files` can't find a repository. The issue arises because GitHub Actions' checkout defaults to tarball extraction when Git isn't installed, which breaks header checking that assumes a full Git checkout. 

Phillip notes that the existing Coccinelle check already handles this case by requiring a Git checkout, suggesting the header check could follow a similar pattern - either skipping checks when not in a Git repository (like the Coccinelle check does) or falling back to `find` (as the Makefile does). The discussion shows attention to maintaining build system robustness across different environments while preserving the new Meson functionality.

The exchange demonstrates the careful consideration being given to edge cases in the transition from Makefile to Meson builds, particularly around CI environments. Phillip's response keeps the focus on practical solutions while acknowledging the tradeoffs between strict checking and build flexibility.
