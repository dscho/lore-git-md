This is the fourth patch in a 6-part series refactoring Git's Meson build system, focusing on networking library dependencies. The patch standardizes the handling of additional networking libraries (`-lnsl` and `-lsocket`) alongside the existing `-lresolv` check, particularly for SunOS/Solaris systems where these libraries are commonly needed.

The change moves from a single optional `resolv` check to a consolidated array of networking library checks, making the build system more consistent with the existing `config.mak.uname` and `configure.ac` configurations. The patch notes these libraries are often required on SunOS, though the implementation remains portable by keeping the checks optional (`required: false`).

Key technical details include:
- Maintains Windows-specific handling via `winsock` (unchanged)
- Preserves the existing `networking_dependencies` array structure
- Adds `nsl` and `socket` libraries to the same dependency collection that already included `resolv`
- Keeps the same conditional structure (non-Windows branch)

The change appears straightforward and well-motivated by existing platform support requirements. As with previous patches in the series, this continues the pattern of standardizing ad-hoc checks into a systematic approach. No Solaris-specific logic is introduced beyond what's already present in the autoconf build system. The patch doesn't address why these libraries weren't included in the initial Meson port, but the commit message references their presence in the traditional build system as justification.
