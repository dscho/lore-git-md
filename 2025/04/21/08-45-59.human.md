This is a CI/build system discussion about a regression in the Meson build system's header checking functionality. Phillip Wood identifies the root cause of the failing linux-meson CI job: the test environment lacks Git itself when extracting the source from a tarball, causing `git ls-files` to fail during the header check.

The issue occurs because GitHub Actions is using a tarball extraction method rather than a Git clone when Git isn't installed in the environment. This affects Karthik Nayak's series implementing Meson equivalents of Makefile's header checking, which otherwise appears technically complete after multiple rounds of review.

Phillip suggests installing Git via `apt-get` before the checkout action as a potential fix, though leaves the final solution open for discussion. This is the last remaining blocker for merging the otherwise-ready series that has already addressed naming conventions, dependency chaining, and other technical feedback from multiple contributors.
