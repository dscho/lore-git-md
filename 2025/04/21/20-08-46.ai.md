CI / build system: This email from Karthik Nayak provides a detailed analysis of the CI failure encountered in the Meson header checking implementation. The core issue stems from GitHub Actions' checkout behavior when Git isn't installed - it defaults to tarball extraction rather than cloning, which breaks subsequent `git ls-files` operations in the build process.

The email explains the CI workflow sequence: (1) initial checkout without Git installed (using REST API tarball), (2) dependency installation including Git, (3) build setup where `git ls-files` fails due to missing `.git` directory. This creates a chicken-and-egg problem where Git is available but the repository metadata isn't.

Karthik confirms Phillip Wood's diagnosis that Git needs to be installed before the checkout step. The analysis reveals this is a subtle interaction between GitHub Actions' default behavior and Git's build requirements, not a flaw in the Meson implementation itself. The thread context shows this completes the technical resolution of the header checking feature, though it surfaces an interesting divergence from Makefile behavior (Makefile falls back to `find` when Git isn't available).

This email doesn't introduce new code changes but provides important operational understanding for the CI integration. The solution path (installing Git earlier) maintains the design choice to rely on Git rather than implementing a `find` fallback like Makefile does, keeping with the project's Meson migration direction while documenting this behavioral difference.
