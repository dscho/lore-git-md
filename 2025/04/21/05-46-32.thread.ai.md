Key changes: Corrects launchctl calendar specifications for daily/weekly maintenance jobs on macOS by replacing Day with Weekday keys

The thread addresses incorrect scheduling intervals for Git maintenance jobs when using launchctl on macOS. The original bug caused daily jobs to run only on the first six days of each month (from malformed "*-*-* 1..6:0:0" spec) and weekly jobs to run daily instead of weekly (from "*-*-*" spec). The initial fix updated these to "*-*-* 0:0:0" for daily and "*-*-1..7" for weekly schedules.

The new patch from Josh Heinrichs identifies the root cause as incorrect use of the `Day` key in launchctl plist configuration. It replaces `Day` with `Weekday` in `launchctl_schedule_plist` function, which is the documented way to specify days-of-week scheduling according to launchd.plist(5). This ensures daily jobs run every day and weekly jobs properly run weekly (using `Weekday:0`). Josh confirms through testing that while `Day:0` was undocumented, it behaved like omitting Day entirely, resulting in daily runs.

Technical impact remains limited to macOS users employing launchctl for maintenance scheduling. The changes modify only the scheduling templates in builtin/gc.c, maintaining the same approach of direct fixes without introducing new complexity or affecting other platforms.
