This thread continues the effort to add Windows/ARM64 support to Git, with Dennis Ameling and Johannes Schindelen (Dscho) co-authoring the patch series. The current v4 iteration builds on earlier versions by adding MSVC toolchain compatibility while maintaining the core technical approach. Key changes include compiler feature detection, config file path normalization, and reducing stack depth for clang/ARM64 builds to prevent overflows.

Junio Hamano has now pointed out a minor but important style issue in two patches from v2 - they incorrectly used tabs instead of spaces for Makefile conditionals, violating a longstanding convention. The fixup adjusts indentation in `config.mak.uname` for both the nedmalloc exclusion and MSVC toolchain handling while preserving the substantive changes. This appears to be the final polish before the series can be queued, as the technical approach has already received maintainer approval and addresses earlier architectural questions from Patrick Steinhardt.

The series remains focused on enabling Git to build and pass tests on Windows/ARM64 systems across multiple toolchains, with particular attention to memory allocators, compiler features, and recursive tree traversal. Open questions around optimal stack depth and allocator strategy may warrant follow-up work, but the current changes represent a significant step forward for ARM64 compatibility.
