This thread concerns a patch series (now at v2) adding Windows/ARM64 support, co-authored by Dennis Ameling and Johannes Schindelin. The core work enables Git to build and pass tests on Windows/ARM64 systems using new GitHub Actions runners, addressing compiler compatibility, memory allocators, and build system adjustments. 

The latest patch specifically handles memory allocator selection by disabling nedmalloc for CLANGARM64 builds, as this allocator fails to compile on ARM64 and has been unmaintained since 2017. The change preserves nedmalloc for other Windows platforms while excluding it for ARM64 via a conditional check in the build configuration. This follows the series' established pattern for platform-specific adjustments.

Maintainer Junio Hamano approved the v1 approach, and v2 has incorporated style fixes and additional accommodations like compiler feature detection and CLANGARM64 MSYSTEM support. The series builds on Git for Windows' existing ARM64 work while maintaining compatibility with other platforms. Outstanding considerations include verifying test results on ARM64 runners, potential follow-up for platform quirks, and longer-term questions about allocator strategy and recursive tree traversal handling. The changes align with GitHub's new Windows/ARM64 runner availability and connect to broader discussions about Git's memory management.
