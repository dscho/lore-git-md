This thread concerns a patch series adding Windows/ARM64 support to Git, co-authored by Dennis Ameling and Johannes Schindelin (Dscho). The current version (v4) builds on earlier iterations that introduced compiler feature detection, build system changes, and config file path handling. The latest patch specifically addresses a stack overflow issue in clang-based Windows/ARM64 builds during `git archive` operations, reducing the maximum tree depth from 2048 to 1280 to prevent test failures.

The series has evolved through multiple versions with input from the maintainers, now covering both MINGW and MSVC toolchains. Key technical considerations include memory allocator selection (disabling nedmalloc for ARM64), config file path normalization, and now stack depth management. While the core architectural approach from early versions remains, each iteration has refined platform-specific behaviors - most recently focusing on test stability.

Several open questions remain about long-term solutions for recursive tree traversal and allocator strategy, particularly as the project moves toward Meson builds. The patches have drawn constructive review from maintainers, with Junio Hamano approving the overall direction and Patrick Steinhardt raising architectural considerations that were subsequently addressed. The work ties into broader platform compatibility efforts while remaining distinct from other large-scale changes like ODB abstraction or Rustification.
