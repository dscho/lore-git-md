This thread began as a focused effort to add Windows/ARM64 support to Git, with Dennis Ameling and Johannes Schindelin (Dscho) submitting a cleanly structured 6-patch series that Junio Hamano has already acknowledged as ready for integration. The patches handle various build system adjustments, compiler support, and stack overflow mitigation specifically for the new ARM64 Windows platform, building on Git for Windows' existing work.

The discussion has now taken an interesting turn with Patrick Steinhardt raising a broader architectural question about nedmalloc's future in Git. While the original patch simply disabled nedmalloc for Windows/ARM64 builds due to compilation failures, Steinhardt points out that nedmalloc has been effectively unmaintained since 2017, suggesting this might be an opportunity to reconsider Git's memory allocation strategy more broadly. This introduces a new dimension to the conversation that could potentially affect all Windows builds and possibly other platforms.

The core Windows/ARM64 support work appears ready to move forward, but this new discussion thread about allocator strategy may warrant separate consideration. Maintainers will need to decide whether to treat these as distinct topics or combine them into a larger discussion about Git's memory management approach. For now, the original platform support work remains on track while this new architectural question begins to percolate.
