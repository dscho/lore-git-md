This thread focuses on adding Windows/ARM64 support to Git, with initial patches from Dennis Ameling and Johannes Schindelin (Dscho). The maintainer Junio Hamano has acknowledged the clean structure of the initial 6-patch series, which includes build system changes and stack depth adjustments for Windows/ARM64 builds. A key technical challenge involves recursive tree traversal, which currently requires a temporary stack depth adjustment but will need architectural changes in the future.

The discussion has expanded to consider broader memory allocator strategy, prompted by Patrick Steinhardt's questions about the unmaintained nedmalloc allocator. Johannes Schindelen notes that Git for Windows has already switched to Microsoft's mimalloc, which shows promising performance, but cautions that older Windows versions may still need custom allocator support. He suggests systematically upstreaming mimalloc before removing nedmalloc, rather than making piecemeal changes.

Key open questions include verifying test pass rates on actual ARM64 Windows runners, benchmarking allocator performance across different Windows versions, and developing a long-term solution for recursive tree traversal. While the immediate Windows/ARM64 support work appears ready for integration, the allocator discussion may lead to separate follow-up work. The thread reflects Git's careful approach to platform support, balancing immediate needs with long-term architectural considerations.
