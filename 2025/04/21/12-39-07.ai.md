Platform compatibility patch (part 3/6 in Windows/ARM64 support effort) disabling nedmalloc for Windows/ARM64 builds.

This patch modifies `config.mak.uname` to skip using the nedmalloc allocator when building for CLANGARM64 (Windows/ARM64) targets. The change is motivated by two factors: nedmalloc fails to compile on this platform, and the project appears unmaintained since at least 2017 (with no expectation of future fixes). The patch maintains nedmalloc usage for other Windows builds while excluding it specifically for the ARM64 case.

The technical change is straightforward - wrapping the `USE_NED_ALLOCATOR` assignment in a conditional that checks for the CLANGARM64 MSYSTEM. This follows the pattern seen elsewhere in the file for platform-specific configuration. The patch doesn't introduce new build-time dependencies or affect runtime behavior beyond using the system allocator instead of nedmalloc on Windows/ARM64.

This appears to be a pragmatic solution to an immediate build problem, though it does mean Windows/ARM64 builds will use a different memory allocator than other Windows platforms. The commit message provides clear justification for the change, citing both technical incompatibility and maintenance concerns. As part of the larger Windows/ARM64 support series, this helps achieve the goal of making Git buildable on the new platform.
