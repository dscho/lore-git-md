Thread identity: Platform compatibility patch series introducing Windows/ARM64 support, authored by Dennis Ameling and Johannes Schindelin (Dscho). Current version is initial submission (v1), now with maintainer acknowledgment.

Core problem or goal: Enable Git to build and pass tests on Windows/ARM64 systems, particularly targeting newly available Windows/ARM64 GitHub Action runners. The work builds on Git for Windows' existing ARM64 support.

Current status: Initial 6-patch series has been acknowledged by maintainer Junio Hamano as cleanly structured and ready for integration. Patches cover:
1. ARM64 bswap support in bswap.h via compiler built-ins with fallbacks
2. clangarm64 support in config.mak.uname (CLANGARM64 MSYSTEM detection, prefix/path settings)
3. Disabling nedmalloc for Windows/ARM64 builds due to compilation failures
4. MSVC ARM64 build handling mirroring MINGW support
5. mingw/arm64 config file location normalization
6. Stack overflow mitigation for clang/ARM64 via reduced max_tree_depth (1280)

Key technical details:
- Files modified: bswap.h (built-in detection), config.mak.uname (CLANGARM64 support), environment.c (max_tree_depth adjustment)
- Build system changes follow established Windows toolchain patterns
- bswap.h uses __has_builtin while maintaining x86 fallback
- Nedmalloc disabled only for Windows/ARM64 via CLANGARM64 check
- MSVC support mirrors MINGW approach for consistency
- Config file path normalization via string substitution
- Stack overflow fix targets clang/ARM64 specifically with GIT_WINDOWS_NATIVE + __clang__ + __aarch64__ guards
- Test coverage implied by GitHub Action runner targeting but not shown in patches
