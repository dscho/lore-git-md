This is a follow-up discussion in the ongoing thread about implementing header checking in Meson builds, specifically addressing CI environment issues. Junio C Hamano responds to Phillip Wood's discovery that GitHub Actions was failing because it was extracting a tarball rather than using a git checkout, which broke the `git ls-files` command needed for header checking.

Key technical points in this email:
- Junio expresses surprise that CI uses tarball extraction rather than git checkout, despite using actions/checkout@v4
- Notes the existing check in contrib/coccinelle/meson.build that requires .git directory presence
- Contrasts this with Makefile's fallback to `find` when git isn't available
- Raises concerns about testing with tarball extraction not matching real release tarballs built with `make dist`

The discussion reveals an important divergence between CI behavior and expected build environments, with Junio questioning the value of testing against tarball extraction when it doesn't match the project's actual release process. This adds context to the earlier CI resolution that required explicit Git installation in the workflow.
