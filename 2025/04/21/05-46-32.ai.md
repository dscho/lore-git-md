This is a bugfix patch targeting the macOS launchctl scheduler integration in Git's maintenance functionality. The patch addresses incorrect calendar interval settings that cause maintenance jobs to run at unintended frequencies - daily jobs running only on the first six days of the month and weekly jobs running daily instead of weekly.

The issue was discovered while integrating Git maintenance with home-manager on macOS. The author verified the behavior by manually adjusting system time and checking logs. The commit changes two lines in builtin/gc.c to correct the launchctl calendar specifications. 

The patch appears straightforward and well-motivated, fixing clearly incorrect behavior. The author notes the impact is likely minimal since Git maintenance is a niche feature on macOS, and doesn't propose any migration path for existing incorrect configurations. The change is contained to the macOS-specific launchctl scheduling code with minimal risk of wider impact.

Key technical details for future reference:
- Modifies the `get_schedule_cmd` function in builtin/gc.c
- Changes launchctl calendar specifications from "*-*-*" to "*-*-1..7" for weekly
- Changes from "*-*-* 1..6:0:0" to "*-*-* 0:0:0" for daily
- Affects only macOS users who use launchctl for maintenance scheduling

The patch appears uncontroversial and correctly targeted, addressing a clear bug in platform-specific scheduling behavior without introducing new complexity.
