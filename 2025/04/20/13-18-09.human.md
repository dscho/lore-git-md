This is a bug report about an unexpected interaction between `git stash` and `git cherry-pick --abort` that can lead to data loss. Markus Raab demonstrates a sequence where:
1. Files are stashed
2. A failing cherry-pick is attempted
3. The stash is popped
4. The cherry-pick is aborted

The expected behavior would be to either preserve the stashed files or warn about potential data loss. Instead, the files from the stash are silently lost during the cherry-pick abort operation.

The report includes clear reproduction steps and version information (Git 2.39.5 on Linux). While the commit message doesn't propose a fix, it effectively documents a real issue where Git's conflict resolution flow can unexpectedly discard working directory changes. This appears to be a genuine bug rather than user error, as the behavior contradicts Git's usual safety mechanisms around stashed changes.
