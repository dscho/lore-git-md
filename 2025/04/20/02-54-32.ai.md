Refactoring patch removing redundant NULL check in `builtin/add.c`.

This is the first of two mechanical patches following up on Patrick Steinhardt's suggestion to clean up redundant NULL checks after commit f29f1990b5 made `repo_config()` NULL-safe. The change removes an if statement that previously guarded a `repo_config()` call in `cmd_add()`, since the function now handles NULL repositories internally. The diff shows a straightforward 3-line change where the conditional is removed while keeping the `repo_config()` call intact.

The patch is part of an ongoing effort to eliminate now-unnecessary NULL checks after making repository-related functions NULL-tolerant. As noted in the thread summary, these are safe deletions that don't require test changes since they don't modify behavior - they simply remove code made redundant by the earlier `repo_config()` modification. The patch follows the same pattern as will be seen in the second patch for `builtin/difftool.c`.

Key technical details for future reference: The change affects `builtin/add.c`'s `cmd_add()` function, specifically around line 386 where it calls `repo_config()` with the `add_config` callback. The removed check was verifying `repo` wasn't NULL before the call, which is now handled internally by `repo_config()`. The patch maintains the same function call and parameters, just without the now-redundant conditional.
