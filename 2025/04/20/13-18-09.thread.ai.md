Bug report thread about data loss when combining `git stash` and `git cherry-pick --abort`. Markus Raab reports files being silently lost in a specific sequence: (1) stash changes, (2) attempt cherry-pick that fails, (3) pop stash, (4) abort cherry-pick. The test case demonstrates losing files a and b on Git 2.39.5/Linux. The core issue is an interaction between stash state management and cherry-pick's abort mechanism where popped stashed changes aren't preserved during abort. This qualifies as a data-loss bug affecting users combining these operations, with no proposed solution yet. The minimal reproduction case clearly demonstrates the issue in established functionality.
