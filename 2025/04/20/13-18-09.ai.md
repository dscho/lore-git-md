Bug report about data loss when combining `git stash` and `git cherry-pick --abort`. 

Markus Raab reports a case where files can be silently lost when certain Git operations are combined in sequence. The problematic workflow involves: (1) stashing changes, (2) attempting a cherry-pick that fails, (3) popping the stash, and (4) aborting the cherry-pick. The expected behavior would be to either preserve the stashed files or warn about potential data loss, but instead the files are permanently deleted.

The specific test case shows this with two files a and b being lost after the sequence completes. The report includes full system information showing this occurs on Git 2.39.5 running on Linux. The bug appears to be an unintended interaction between stash's state management and cherry-pick's abort mechanism, where the abort operation doesn't properly account for stashed changes that were popped during the conflicted cherry-pick.

This qualifies as a data-loss bug that could affect users who combine these operations. The report is clear and provides a minimal reproduction case, though it doesn't propose a solution. The issue appears to be in the interaction between two well-established Git commands rather than in new or experimental functionality.
