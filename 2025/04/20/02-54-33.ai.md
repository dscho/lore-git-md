Refactoring patch removing redundant NULL checks after `repo_config()` changes.

This is the second of two mechanical patches cleaning up NULL checks around `repo_config()` calls in builtin commands, following Patrick Steinhardt's suggestion after commit f29f1990b5 made `repo_config()` NULL-safe. The change follows the same pattern as the first patch in the series (which modified `builtin/add.c`), removing an if statement that guarded a `repo_config()` call in `cmd_difftool()`.

The patch modifies line 750 in `builtin/difftool.c`, replacing the conditional `if (repo) repo_config(...)` with a direct `repo_config()` call. The change is behavior-preserving since `repo_config()` now handles NULL repositories internally. The commit message cites the same background commit (f29f1990b5) as the first patch and carries matching attribution lines.

This continues the systematic cleanup of redundant NULL checks across the codebase, with `difftool` being the second target after `add`. The change is straightforward and low-risk, affecting only the configuration loading path in the difftool command. Like the first patch, this requires no test modifications since it's purely removing now-unnecessary defensive programming.
