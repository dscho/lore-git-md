This is a philosophical debate about metadata recording in Git, specifically around Change-IDs and file rename heuristics. Nico Williams responds to Junio Hamano's earlier arguments about Git's design philosophy regarding recorded versus derived metadata.

Nico clarifies that his original mention of file rename heuristics wasn't meant to debate that specific implementation, but rather to argue against adding more similarity-based heuristics for other purposes like Change-IDs. He maintains that user-expressed intent (like explicitly recording renames or Change-IDs) would be valuable when available, even if imperfect, because software can't perfectly infer human intention.

The exchange highlights a fundamental tension in Git's design - between recording explicit metadata that might be wrong versus relying on heuristics that can improve over time. Nico suggests that while Linus Torvalds' original decision to avoid metadata recording may have been for simplicity, there might now be value in allowing some user-expressed metadata where appropriate.

This continues a nuanced discussion about where Git should draw the line between recording versus deriving information, with Nico advocating for more flexibility to record certain types of metadata when users want to. The thread remains at a philosophical level rather than addressing specific technical implementations of Change-IDs.
