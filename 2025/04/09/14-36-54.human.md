This is a follow-up discussion about a refactoring patch that was already merged as part of Patrick Steinhardt's series to reorganize Git's object-file subsystem. The patch in question (3/9) moved the `xmmap()` family of functions from object-file.c to wrapper.c, as they were deemed to be generic utilities rather than object-file-specific code.

Elijah Newren points out a minor grammatical issue in the commit message ("got" vs "has"), but the main focus of his email is to continue the discussion from his earlier question about the rationale for grouping certain directory utilities together in dir.c. While this email doesn't directly address that question, it shows ongoing engagement with the refactoring work even after its merge.

The patch itself is a straightforward code movement - relocating 48 lines of mmap-related functions that handle memory mapping with platform-specific error handling and size limits. The functionality remains identical, just better organized in wrapper.c where similar low-level operations live. This was one of several similar moves in the series to create clearer subsystem boundaries in preparation for future object storage backends.

The discussion highlights how even after a major refactoring is merged, there can be valuable post-merge review and clarification about the architectural decisions made. The series has already achieved its primary goal of separating concerns between object storage, index operations, and generic utilities, with this being part of the latter category.
