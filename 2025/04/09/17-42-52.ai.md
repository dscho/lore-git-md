This is a follow-up discussion in the ongoing thread about Meson build system changes for shell completion script installation. Junio Hamano responds to Todd Zullinger's suggestion about using `pkg-config` for path resolution.

The key new points are:
- Junio confirms the current approach (using `$datadir`) was deliberately chosen in the Makefile system to avoid complexity around per-user vs system-wide installations
- He notes that distributions already customize paths appropriately for their environments
- Suggests that if Git were to handle this directly, it would likely need a dedicated configuration variable for completion script locations rather than trying to auto-detect via `pkg-config`
- Implies the current patch's approach (using standard paths) is reasonable as a default, with distros free to override as needed

The discussion highlights the tension between automatic path detection (which could be fragile across different installation scenarios) and explicit configuration (which adds complexity). Junio's position favors the simpler, more predictable approach while acknowledging distros will customize paths regardless. This doesn't introduce new technical changes to the patch but provides important maintainer perspective on the design tradeoffs.
