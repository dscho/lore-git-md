This is a follow-up discussion in the ongoing thread about Meson build system improvements for shell completion script installation.

Junio C Hamano responds to Todd Zullinger's suggestion about using `pkg-config` for path resolution, explaining why the project has historically avoided this approach. The key points are:

1. The Makefile intentionally doesn't use `pkg-config` for completion script paths because different distributions have different needs, and there's no one-size-fits-all solution that works for both system-wide and per-user installations.

2. While distros can customize paths for their environments, a general solution would likely require introducing new build variables specifically for completion script locations, defaulting to `$datadir` unless a better system-specific setting exists.

The discussion continues to explore the tradeoffs between standardization and flexibility in path resolution, with Junio expressing skepticism that `pkg-config` can solve the problem cleanly for all use cases. This maintains the thread's technical depth while highlighting the maintainer's perspective on configuration complexity.
