Follow-up discussion on a refactoring patch from Patrick Steinhardt's merged series. Elijah Newren questions the relationship between two directory-creation functions moved together in this patch.

This email is part of the now-merged 9-patch series that restructured Git's object-file subsystem. Patch 1/9 moved several directory-creation utilities from object-file.c to dir.c, where they better belong since they're generic filesystem operations rather than object-specific code. The patch touched 13 files, updating includes and moving the implementations.

Elijah Newren raises a specific question about the patch's description, which referred to `safe_create_leading_directories()` and its "relatives" being moved together. He notes that while the move itself makes sense, he can't see how `mkdir_in_gitdir()` (one of the moved functions) is actually related to the others beyond also being a directory utility. The rest of the patch appears correct, but this phrasing caused some initial head-scratching.

The thread context shows this was the first patch in a major architectural change that has since been completed, so this is post-merge discussion rather than pre-merge review. The question doesn't suggest any functional problems with the code - it's more about documentation clarity in the commit message.
