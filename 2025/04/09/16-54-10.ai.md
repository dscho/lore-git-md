This is a technical proposal in the ongoing Change-ID standardization discussion, where Nico Williams responds to Theodore Ts'o's concerns about metadata semantics while advancing concrete specifications for how Change-IDs should behave in Git commits.

Nico builds on Theodore's observations about problematic Change-ID usage patterns (random values, cherry-pick modifications) by proposing specific behavioral rules: Change-IDs must be preserved across cherry-picks and rebases, with clear distinctions between patch series IDs (non-unique) and commit-specific IDs (branch-unique). The proposal introduces multiple header types (series ID, commit ID, derivation chain) that would be multi-valued to handle complex operations like squashes.

Key technical aspects include:
- Explicit rejection of Change-ID modification during cherry-picking
- Distinction between free-form and URI-based ID formats
- Optional indexing via refs to commit lists rather than direct refs (since IDs aren't globally unique)
- Allowance for similarity heuristics when commit IDs are missing but series IDs exist

Nico engages with Theodore's comparison to Git's rename tracking philosophy, acknowledging the complexity of heuristics while maintaining that properly constrained Change-IDs serve a valuable purpose. The response subtly challenges Junio Hamano's earlier invocation of Git's simplicity principles by arguing that some metadata (like Change-IDs) can enable workflows that pure content-addressability cannot easily support.

This moves the discussion toward concrete technical specifications while still needing to address the core philosophical objections raised earlier in the thread. The proposal's multi-header approach and indexing suggestions provide specific targets for both implementation discussion and philosophical debate about what constitutes "essential" metadata.
