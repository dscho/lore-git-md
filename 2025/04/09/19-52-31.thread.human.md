This thread began with Junio Luan Pereira reporting a certificate verification failure when updating Git for Windows on a Brazilian Portuguese locale system, displaying corrupted Portuguese error text. Initial investigation by Johannes Schindelin identified the issue in the `git-update-git-for-windows` script and proposed a curl workaround (`--ssl-revoke-best-effort`) to relax certificate checks while maintaining security. The discussion initially focused on locale handling and schannel configuration.

The thread has concluded with Junio identifying the root cause as an interaction with Norton Antivirus's "Safe Web" feature, which was interfering with curl's access to Let's Encrypt certificates when using schannel. Disabling this feature resolved the issue completely, though attempts to use a non-schannel curl build were unsuccessful, confirming schannel's hardcoded use in Git for Windows. This shifts the context from being a Git-specific issue to an environmental conflict with third-party security software. The matter is now considered resolved through local configuration changes, with no further action needed from the Git project.
