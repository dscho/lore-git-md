This is a bugfix discussion regarding git-gui's commit message validation. 

Eric Sunshine responds to Lauri Reilson's report about git-gui rejecting commit messages containing "#" characters, which the reporter uses for task tracking. The reporter expected to commit using messages formatted as "<#task-id message>", but git-gui incorrectly treated the "#" as a comment marker and rejected the input.

Sunshine points to a March 2025 patch by Oswald Buddenhagen that appears to address this exact issue, suggesting this may be a known problem with a solution already in progress. The thread shows a common pain point where git-gui's strict message formatting assumptions conflict with real-world workflows that use "#" for purposes other than comments.

The exchange highlights how seemingly small interface behaviors can create meaningful workflow obstacles, and demonstrates the value of connecting new bug reports with existing solutions. No maintainer response yet indicates this may be an issue awaiting review or merge of the referenced patch.
