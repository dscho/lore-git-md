[Git for Windows] Certificate verification failure traced to Norton Antivirus interaction

User Junio Luan Pereira initially reported CRYPT_E_NO_REVOCATION_CHECK errors (0x80092012) in Brazilian Portuguese locale, with corrupted error text suggesting locale handling issues. Investigation progressed through multiple hypotheses: first locale-specific text corruption, then certificate revocation strictness in the `git-update-git-for-windows` script (with Johannes Schindelin proposing a `--ssl-revoke-best-effort` curl workaround). The root cause is now confirmed as Norton Antivirus's "Safe Web" feature interfering with schannel's access to Let's Encrypt certificates. Disabling Safe Web resolved the issue completely, though attempts to use non-schannel curl builds were unsuccessful, indicating schannel is hardcoded in Git for Windows' distribution.

Key technical details preserved: schannel as SSL backend, Let's Encrypt certificates as affected CA, Norton Safe Web as interfering component. The thread has effectively closed with this environmental explanation, shifting from Git-specific bug to third-party security software interaction. No further Git-side action needed; workarounds documented include both the earlier curl flag approach and the definitive Norton configuration change. Original Windows 11/pt_BR locale context remains for historical reference but is no longer considered relevant to the root cause.
