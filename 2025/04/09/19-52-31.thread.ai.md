[Git for Windows] Certificate verification failure traced to Norton Antivirus interaction with schannel backend

Root cause analysis confirmed Norton Antivirus's "Safe Web" feature interferes with schannel's access to Let's Encrypt certificates in Git for Windows installations. Original Windows 11/pt_BR locale context and CRYPT_E_NO_REVOCATION_CHECK errors (0x80092012) were ultimately unrelated to the core issue. Final diagnostic from Johannes Schindelin confirms the technical distinction between WinSSL (schannel) and OpenSSL backends, with configuration stored in `C:\Program Files\Git\etc\install-options.txt` under "CURL option". 

Two documented workarounds remain valid: 1) temporary `--ssl-revoke-best-effort` curl flag for affected operations, or 2) definitive solution of disabling Norton's Safe Web feature. Thread is fully resolved with no Git-side changes required, as the behavior stems from third-party security software interaction rather than Git or Git for Windows code. All technical details preserved for future reference include schannel as default SSL backend, Let's Encrypt certificates as affected CA, and Norton Safe Web as interfering component.
