[Git for Windows] Certificate verification failure traced to Norton Antivirus interaction with schannel backend

Root cause analysis confirms Norton Antivirus's "Safe Web" feature interferes with certificate verification in Git for Windows, with technical details now fully clarified. Johannes Schindelin's analysis establishes: 1) Git for Windows deliberately forces WinSSL/schannel backend regardless of install-options.txt settings (PR #4410 design choice to avoid OpenSSL dependencies), 2) curl.exe always shows Schannel support in --version output, explaining Junio Luan Pereira's observations, 3) the issue persists across all configurations due to this mandatory Schannel usage. Let's Encrypt certificates remain the affected CA context.

Two validated workarounds stand: temporary --ssl-revoke-best-effort curl flag or disabling Norton's Safe Web feature. Thread conclusively establishes the interaction pattern: security software intercepts Schannel traffic regardless of user-facing configuration options. Preserved technical specifics include: WinSSL as enforced backend, CRYPT_E_NO_REVOCATION_CHECK error code (0x80092012) as symptom, and the architectural rationale behind Git for Windows' backend selection. This thread now serves as complete reference for both the Norton interaction issue and Git for Windows' SSL backend implementation details, with all investigative paths exhausted.
