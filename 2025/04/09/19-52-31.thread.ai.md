[Git for Windows] Certificate verification failure traced to Norton Antivirus interaction with schannel backend

Root cause analysis confirmed Norton Antivirus's "Safe Web" feature interferes with certificate verification in Git for Windows, regardless of SSL backend selection (WinSSL/schannel or OpenSSL). Original Windows 11/pt_BR locale context and CRYPT_E_NO_REVOCATION_CHECK errors (0x80092012) were unrelated to the core issue. Johannes Schindelin's technical analysis established the problem persists across backend choices, as demonstrated by reporter Junio Luan Pereira's follow-up showing cURL 8.12.1 retains Schannel support even when OpenSSL is selected in `C:\Program Files\Git\etc\install-options.txt`.

Two workarounds remain valid: 1) temporary `--ssl-revoke-best-effort` curl flag, or 2) disabling Norton's Safe Web feature. Thread conclusively establishes the issue stems from third-party security software interaction rather than Git or Git for Windows code. Preserved technical details include: WinSSL as default backend, Let's Encrypt certificates as affected CA, Norton Safe Web as interfering component, and the ineffectiveness of backend switching due to cURL's retained Schannel support. Discussion serves as definitive reference for future cases of security software interfering with Git's certificate verification on Windows.
