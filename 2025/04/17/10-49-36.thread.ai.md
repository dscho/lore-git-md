Patch series v4 1/7 fixing integer parsing in `git_parse_signed()`. The function in `parse.c` validates signed integers from config/options but had an off-by-one error in minimum value checking - it used `-max` as lower bound when it should be `-max - 1` to properly handle full signed integer range (minimum is `-2^(N-1)`, maximum is `2^(N-1)-1`). The one-line fix correctly accounts for signed integer asymmetry. This affects all code paths using `git_parse_signed()` with large negative values. The patch is minimal and well-explained, addressing a subtle edge case in integer validation.
