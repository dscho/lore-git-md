This is the final patch in a build system alignment series, focusing on cryptographic random number generation (CSPRNG) standardization across platforms. The patch sets Linux's CSPRNG method to `getrandom` in Makefile builds, matching meson's preference for kernel-based random number generation while maintaining compatibility with all supported distros (including RHEL 8).

The discussion clarifies that while newer Linux distributions could technically use `arc4random` (added in glibc 2.36), there's no performance benefit on Linux since all methods ultimately use the same kernel CSPRNG. The maintainers agree this is the right approach, with Junio Hamano praising Ramsay Jones' clear technical explanation. 

This completes the series' CSPRNG standardization effort, which previously added `arc4random` support for Cygwin. The patch appears well-justified and low-risk, with Linux builds already confirmed working. Cygwin testing is still ongoing (taking 6+ hours to complete), but previous versions had already passed testing. The series as a whole has maintainer approval and is ready for merging once final testing completes.
