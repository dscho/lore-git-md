Platform compatibility patch finalizing Linux CSPRNG standardization in the build system alignment series. This patch sets `CSPRNG_METHOD = getrandom` in the Linux section of `config.mak.uname`, completing the cross-platform cryptographic random number generation standardization effort.

Ramsay Jones provides detailed rationale for preferring `getrandom` over other available methods (`arc4random`, `getentropy`, `/dev/urandom`) on Linux systems. Key points include:
- All supported distributions (including RHEL 8 with glibc 2.28) have `getrandom`/`getentropy` (glibc 2.25+)
- While `arc4random` exists in newer glibc (2.36+), it offers no performance benefit on Linux since all methods ultimately use the same kernel CSPRNG
- The change aligns Makefile builds with meson's preference for kernel interfaces
- Current `csprng_bytes()` usage isn't performance-sensitive

Junio Hamano confirms the technical explanation is clear and correct, noting this resolves the last inconsistency in CSPRNG method selection across build systems. The patch is a straightforward one-line addition to `config.mak.uname` that maintains compatibility while standardizing on the most widely available kernel interface. This change was anticipated in the series' overall CSPRNG standardization plan and follows similar platform-specific CSPRNG method selections already made for other systems (like `arc4random` for Cygwin).
