This is a refactoring patch in Patrick Steinhardt's v4 series hardening Git's integer parsing. Patch 2/7 converts all parse-options initializations to use designated initializers rather than positional ones.

The change improves code maintainability by making option definitions more self-documenting and resilient to future struct changes. Each field is now labeled (like `.type = OPTION_CALLBACK`), eliminating the need to track field positions. The patch touches 24 files with mechanical conversions of option struct initializations, mostly in builtin commands.

The conversion follows Git's existing style where designated initializers are already used in parts of the codebase. While purely mechanical, this change will make subsequent patches in the series easier to review by clearly showing which fields are being set in each option definition.

This is part of the larger effort to improve type safety and error handling in Git's option parsing, but focuses specifically on code structure rather than behavior changes. The patch appears thorough, with consistent formatting across all conversions.
