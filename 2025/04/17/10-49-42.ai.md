This is the final patch (7/7) in Patrick Steinhardt's integer parsing hardening series, adding compile-time signedness validation to the parse-options API. The patch addresses a systemic issue where mismatched signedness between option declarations and their backing variables could cause subtle bugs, particularly on big-endian systems. It introduces two new build-time checks (`BARF_UNLESS_SIGNED` and `BARF_UNLESS_UNSIGNED`) that trigger compiler errors when an option's type doesn't match its variable's signedness.

The change catches several existing mismatches across the codebase, including in `git-backfill` (where the original bug report occurred), `git-apply`, `git-column`, and `git-grep`. Each case is fixed by aligning the option type (`OPT_INTEGER` vs `OPT_UNSIGNED`) with the actual variable type being used. The patch maintains the series' focus on type safety while preserving backward compatibility.

This completes the technical work of the series, with all prior feedback addressed and consensus reached on the design. The only remaining loose end is minor documentation updates, which were noted as non-blocking in previous discussion. The series as a whole now provides comprehensive integer parsing safety for both signed and unsigned values throughout Git's command-line option handling.
