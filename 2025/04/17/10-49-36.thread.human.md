This thread addresses a bug in Git's integer parsing logic. The first patch in a series (v4, patch 1/7) fixes an off-by-one error in `git_parse_signed()` where the minimum value check was incorrectly calculated as `-max` instead of `-max - 1`. This subtle edge case affects how Git validates configuration values and command-line options that accept signed integers, particularly with large negative values. The fix is minimal (a one-line change) and well-explained, properly accounting for the full range of signed integers. The patch appears correct and addresses a real though likely rare issue in integer validation.
