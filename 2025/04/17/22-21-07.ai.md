This is a test cleanup patch in the ongoing series about enabling bitmap lookup tables by default. The patch removes redundant performance tests that previously compared bitmap behavior with and without lookup tables, since the lookup table version is now the default and has proven consistently faster.

Junio C Hamano raises concerns about removing test coverage for the non-default case, questioning whether we should still maintain some performance testing of the lookup-table-disabled scenario since the code still technically supports both configurations. He notes that while performance tests may be less critical than correctness tests, completely removing coverage for a supported mode might be premature.

The discussion highlights a tension between test suite maintenance (removing redundant tests) and ensuring continued coverage of all supported code paths. This follows up on Junio's earlier feedback about test philosophy in this series, where he suggested modifying rather than removing tests to maintain distinct coverage scenarios. The patch currently takes the more aggressive approach of removing the non-default test cases entirely.

Key technical details:
- Removes duplicate performance test invocations that ran with `pack.writeBitmapLookupTable=false`
- Justified by lookup tables now being the default and showing consistent performance wins
- Tests being removed were comparing performance with/without lookup tables
- Junio questions whether we should maintain some performance testing of the non-default path
- Related to earlier test cleanup in the series (p5312 removal)
- Connects to the series' broader goal of simplifying tests now that lookup tables are default
- Open question remains about appropriate test coverage for supported but non-default code paths
