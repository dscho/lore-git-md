This is a performance-focused patch that changes the default behavior for bitmap lookup tables in Git's pack-bitmap functionality. It's the first in a 4-part series by Taylor Blau.

The patch explains that bitmap lookup tables, introduced in 2022, provide measurable performance improvements by avoiding full bitmap file reads during operations. The commit includes benchmark numbers showing speedups across various operations like clone, fetch, and rev-list when using lookup tables. GitHub has been using this feature successfully in production for nearly three years without issues.

The change flips the default value of `pack.writeBitmapLookupTable` from false to true, and updates both the multi-pack-index and pack-objects code paths to enable lookup tables by default. The documentation is also updated to reflect this new default.

This appears to be a well-justified change with clear performance benefits and extensive real-world testing. The patch is cleanly implemented with minimal code changes, just flipping the default flags in three places. As the first in a series, it sets up the main behavioral change while subsequent patches will handle related test suite maintenance.
