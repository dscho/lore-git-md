This is a v4 patch series (7 patches) from Patrick Steinhardt that hardens integer handling in Git's parse-options infrastructure. The series builds on previous discussions and iterations, with key changes in this version:

1. The series now extends `OPTION_INTEGER` to support unit factors (k/m/g suffixes) rather than introducing a separate `OPTION_UNSIGNED` type, reducing API surface while maintaining functionality.

2. It renames `OPTION_MAGNITUDE` to `OPTION_UNSIGNED` to better reflect its purpose after the consolidation.

3. The bounded integer options proof-of-concept patch has been dropped from the series.

4. A fix for an off-by-one error in signed value parsing is included.

The technical improvements focus on:
- Type safety through precision handling (supporting different integer sizes)
- Better error handling for overflow/underflow cases
- Unit factor support for both signed and unsigned integers
- Build-time validation of signedness
- Comprehensive updates to callers throughout the codebase

The series appears well-tested with extensive test updates in t0040-parse-options.sh. All prior feedback from maintainers (Junio C Hamano, Phillip Wood, René Scharfe) has been addressed, and the design questions around bounded options and unsigned parsing have been resolved through consensus.

This represents a significant hardening of Git's option parsing infrastructure with no outstanding technical issues - only documentation clarifications remain as a minor loose end. The changes are backward-compatible while providing better safety guarantees.
