This is a build system patch standardizing cryptographic random number generation (CSPRNG) methods on Linux. It completes the CSPRNG alignment work across build systems by setting `CSPRNG_METHOD = getrandom` in the Linux section of `config.mak.uname`, matching meson build's preference for kernel-based random number generation.

Ramsay Jones explains that while newer Linux distributions could technically use `arc4random` (available since glibc 2.36), there's no performance benefit on Linux since all methods ultimately use the same kernel CSPRNG syscall. The `getrandom` method (available since glibc 2.25) is preferred for broader compatibility, working even on older-but-still-supported distros like RHEL 8 (glibc 2.28). This change brings Makefile builds in line with meson's existing behavior while maintaining security and compatibility.

Junio Hamano confirms the rationale is sound, noting the clear explanation of why `arc4random` makes sense on BSD/Cygwin (where it avoids kernel switches) but not Linux. The patch is a simple one-line addition with no functional impact on current users, just aligning default behavior between build systems. This was the last remaining inconsistency in the cross-platform CSPRNG standardization effort.
