This is part 6/7 of Patrick Steinhardt's series hardening Git's integer parsing in the parse-options infrastructure. Following the previous patch that added precision handling for signed integers, this patch does the equivalent for unsigned integers.

The changes mirror the signed integer work: the patch adds precision-aware parsing for unsigned values (8/16/32/64-bit variants) with proper range checking and error messages. It updates the same set of builtin commands (fmt-merge-msg, merge, show-branch, tag) and adds new test cases specifically for 16-bit unsigned validation. The implementation uses `git_parse_unsigned()` instead of `strtoul()` for safer parsing.

This continues the series' pattern of making integer parsing more robust while maintaining backward compatibility. The changes are well-tested and consistent with the design decisions already reviewed in earlier patches. As with the rest of the series, this appears ready for merging with only minor documentation polish remaining as a loose end.
