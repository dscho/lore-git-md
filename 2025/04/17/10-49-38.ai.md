This is a feature patch in Patrick Steinhardt's integer parsing hardening series (v4 3/7). It extends `OPT_INTEGER()` to support unit factors (k/m/g suffixes) while maintaining its signed integer parsing capability, bringing consistency with `OPT_MAGNITUDE()` (now renamed to `OPT_UNSIGNED` in this series).

The patch modifies the underlying implementation to use `git_parse_int()` instead of `strtol()`, which provides unit factor support while preserving all existing validation. The documentation is updated to reflect that `OPT_INTEGER()` now accepts suffixes, and tests are added to verify negative values with unit factors work correctly.

Key technical points:
- Changes affect `parse-options.c`'s core parsing logic
- Updates API documentation in `api-parse-options.adoc`
- Adds test cases in `t0040-parse-options.sh` for kilo-suffixed values
- Maintains backward compatibility while extending functionality
- Part of unifying integer parsing behavior across signed/unsigned variants

This change enables fixing callsites that incorrectly use `OPT_INTEGER` for unsigned values (addressed in later patches) without introducing behavior inconsistencies. The implementation follows the series' design consensus and addresses no outstanding technical objections from prior reviews.
