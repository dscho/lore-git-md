This is a follow-up in the ongoing Meson build system thread about installing shell completion scripts. Eli Schwartz provides detailed analysis of path resolution complexities for Bash and Zsh completions, highlighting key differences in how each shell handles installation locations.

For Bash, the completion system is robust with multiple fallback paths (XDG directories, PATH-derived locations) that make it virtually impossible to misplace the completion script. The current Meson approach of installing to `/usr/share/bash-completion/completions` works well since distros can easily override via standard build variables.

Zsh presents more challenges - its default paths are rigid (`/usr/local/share/zsh/site-functions` and `/usr/share/zsh/site-functions`), doesn't respect PATH for discovery, and has Debian-specific deviations where completions must go to `vendor-completions` instead. This creates portability issues, particularly for non-standard installations and Debian systems.

Schwartz suggests the Bash completion installation is safe to proceed with, but recommends deferring Zsh support until the path handling can be properly resolved, possibly requiring distro-specific workarounds. This aligns with Junio Hamano's earlier position favoring simple, predictable paths over complex auto-detection, while acknowledging the Zsh situation may need special consideration.

The email provides important technical context about:
- Bash's multi-tiered completion path resolution
- Zsh's rigid path requirements
- The Debian-specific `vendor-completions` divergence
- Why Bash completion is more reliably installable than Zsh
- The practical implications for non-standard install prefixes

This moves the discussion forward by concretely demonstrating why Zsh completion installation is problematic while validating the Bash approach, supporting the maintainer's preference for straightforward path handling where possible.
