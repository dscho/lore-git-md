Feature patch enabling bitmap lookup tables by default, part of Taylor Blau's series to finalize this optimization.

This first patch in the 4-part series changes the default behavior for bitmap lookup tables, which were introduced in 2022 as an opt-in performance optimization. The lookup tables store commit positions and bitmap offsets to avoid reading entire bitmap files during operations. The commit provides detailed performance numbers from 2022-era kernel tests showing consistent improvements across clone, fetch, rev-list and other operations when lookup tables are enabled (e.g. rev-list(commits) improving from 0.78s to 0.56s).

The patch makes three key modifications: updating the pack.writeBitmapLookupTable config default to true, adding the lookup table flag to multi-pack-index writes, and including it in pack-objects' default bitmap options. Taylor notes these tables have been used successfully in production at GitHub for nearly three years without issues, justifying the default change.

Technical details include the specific bitmap flags being modified (MIDX_WRITE_BITMAP_LOOKUP_TABLE and BITMAP_OPT_LOOKUP_TABLE) and the affected components (multi-pack-index and pack-objects). The performance data shows the optimization is particularly effective for rev-list operations, with smaller gains in clone/fetch scenarios. This builds on the original lookup table implementation (a7975c7) and is part of Taylor's ongoing bitmap/pack optimization work.

The patch appears well-justified with production experience and performance data. As the first in the series, it establishes the core behavioral change that subsequent patches will build upon by updating tests and removing now-redundant test coverage.
