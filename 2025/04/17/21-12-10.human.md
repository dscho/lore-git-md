This is a cover letter for a performance-focused patch series that makes bitmap lookup tables the default and cleans up related test infrastructure. The series comes from Taylor Blau and appears to be a spin-off from a larger effort around delta reuse optimizations.

The main change enables bitmap lookup tables by default, which should improve performance for most users since the feature has been stable for some time. The lookup tables help speed up bitmap operations by providing an index into the bitmap data. The remaining three patches are test cleanups that remove now-redundant performance test scripts and adjust others to account for lookup tables being the new default.

The changes touch core bitmap handling code in `pack-bitmap.c` and several performance test scripts. The test changes are mostly deletions and simplifications since some test scenarios (like testing without lookup tables) no longer need separate coverage. The series builds on established functionality rather than introducing new concepts, so while the performance impact should be positive, there's little risk of behavior changes.

This looks like a straightforward quality-of-life improvement that follows the natural progression of a performance feature - first introduced as opt-in, now mature enough to be the default. The test cleanups are a logical follow-up to avoid maintaining redundant test paths. Reviewers will likely want to verify the performance claims, but the changes appear well-motivated and cleanly implemented.
