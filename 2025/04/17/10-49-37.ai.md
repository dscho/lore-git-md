This is patch 2/7 in Patrick Steinhardt's v4 series refactoring Git's parse-options infrastructure. The series focuses on hardening integer parsing while maintaining backward compatibility.

The current change is a refactoring patch that converts all parse-options initializations to use designated initializers rather than positional initialization. This affects 24 files across the codebase, primarily builtin commands that use parse-options. The key improvements are:

1) Better readability by explicitly naming each struct member being initialized
2) More maintainable code since new fields can be added without breaking existing initializations
3) Clearer defaults as zero-initialized fields no longer need to be explicitly set

The changes are mechanical but extensive, touching options initialization in commands like `git commit`, `git merge`, `git fetch`, and many others. Each option struct member is now explicitly named (`.type`, `.long_name`, `.value`, etc.) rather than relying on positional ordering.

This refactoring supports the series' broader goal of making the parse-options infrastructure more robust by:
- Enabling safer future modifications to the option struct
- Reducing cognitive overhead when reading option definitions
- Providing better foundation for subsequent integer parsing improvements

The patch maintains all existing functionality while making the code more maintainable. It follows the established pattern of using designated initializers that's already present in parts of the codebase.
