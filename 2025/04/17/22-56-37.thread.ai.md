Thread subject: [PATCH] help: fix missing hyphen in "No manual entry" error  
Thread type: bugfix  
Author: Keith Thompson  

Core issue: The `git help` command displays incorrect formatting in error messages for nonexistent subcommands, omitting the hyphen between "git" and the subcommand name (e.g. "gitnosuchcommand" vs correct "git-nosuchcommand"). This contradicts Git's man page naming conventions where subcommands are hyphenated while documentation topics are unhyphenated.  

Current status:  
- Initial simple hyphenation fix proposed by Keith Thompson  
- Junio C Hamano identified additional complexity regarding documentation guides  
- Jeff King provided comprehensive technical analysis of documentation system constraints  
- Maintainer has acknowledged this analysis as persuasive  

Key technical details:  
- Bug location: `cmd_to_page()` in builtin/help.c  
- Current behavior uses "git%s" format for all lookups  
- Fundamental constraints prevent clean solution:  
  * Cannot reliably distinguish command vs guide lookups  
  * Documentation viewers (man/info/HTML) have inconsistent behavior  
  * `man` command provides limited formatting control  
  * Pre-checking would require maintaining static topic lists  

Solution options evaluated:  
1. Default to hyphenated format for unknown arguments (author's preference)  
2. Complex dual-format error message (rejected as impractical)  
3. Standardize all man page names to use hyphens (breaks existing practice)  
4. Create symlinks for topic man pages (too confusing)  

Participant positions:  
- Keith Thompson (author):  
  * Initially proposed simple fix  
  * Now favors solution 1 as most practical despite imperfection  
- Jeff King (Peff):  
  * Detailed analysis showed system limitations make perfect solution impossible  
- Junio C Hamano (maintainer):  
  * Initially raised concern about new inconsistencies  
  * Has now acknowledged technical constraints via brief response  

Resolution outlook:  
Discussion appears to be concluding with recognition that:  
- Current behavior may be the least bad option  
- Any change would introduce tradeoffs without solving core limitations  
- Maintainer seems inclined to accept technical reality after Peff's analysis  

The thread has evolved from a simple formatting bug to a deeper examination of documentation system constraints, with the consensus forming that fundamental limitations may make the current behavior the most practical option despite its minor inconsistency with man page naming standards.
