This is part 3/7 of Patrick Steinhardt's series hardening Git's integer parsing in the parse-options infrastructure. The patch extends `OPT_INTEGER()` to support unit factors (k/m/g suffixes) just like `OPT_MAGNITUDE()` does, eliminating an inconsistency between signed and unsigned integer parsing.

The change makes sense because there was no good reason to restrict unit factors to unsigned integers only. The patch refactors the parsing to use `git_parse_int()` which already handles unit factors, while maintaining all existing behavior. This also helps with upcoming fixes where some callers incorrectly use `OPT_INTEGER()` for unsigned values - now they can be fixed without introducing new inconsistencies.

The implementation touches the parse-options core, updates documentation to reflect the new capability, and adds tests for the extended functionality including negative values with unit suffixes. This is a clean, well-motivated change that fits naturally into the series' goal of making integer parsing more consistent and robust.
