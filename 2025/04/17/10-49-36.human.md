This is a bugfix for integer parsing in Git's option handling. Patrick Steinhardt identifies and fixes an off-by-one error in `git_parse_signed()` where the minimum value check was incorrectly calculated. The function was using `-max` as the lower bound when checking negative numbers, but for signed integers the true minimum is actually `-max - 1` (e.g., for 32-bit ints, INT_MAX is 2^31-1 while INT_MIN is -2^31).

The patch is straightforward - a one-line change to the bounds checking logic. It's part of a larger 7-patch series (this being the first), though the cover letter isn't provided here to see the broader context. The fix appears correct and well-justified by the commit message's explanation of integer representation. This seems like a subtle but important correction to edge-case number parsing that could affect any Git command using signed integer options.
