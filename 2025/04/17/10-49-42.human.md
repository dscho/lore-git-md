This is the final patch in Patrick Steinhardt's series hardening Git's integer parsing in the parse-options infrastructure. The patch addresses a subtle but serious issue where some options were incorrectly using `OPT_INTEGER()` with unsigned variables, which worked by accident on little-endian systems but failed on big-endian architectures like s390x and sparc64.

The fix introduces compile-time assertions (`BARF_UNLESS_SIGNED` and `BARF_UNLESS_UNSIGNED`) that enforce proper signedness matching between option macros and their backing variables. This catches mismatches at build time rather than allowing silent failures. The patch updates several affected call sites in `apply.c`, `backfill.c`, `column.c`, and `grep.c` to use the correct option type for their variables.

The change is particularly well-motivated by a real-world failure in `t5620-backfill.sh` where `--min-batch-size` wasn't working correctly on big-endian systems. The solution maintains backward compatibility while preventing similar issues through stronger type checking. This completes the series' goal of making integer option parsing more robust across all platforms.
