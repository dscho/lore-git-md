This is a v4 patch series (7 patches) from Patrick Steinhardt that continues the work on hardening integer handling in Git's parse-options infrastructure. The series builds on previous discussions and feedback, with several key changes from v3:

The most notable change is the decision to extend `OPTION_INTEGER` to support unit factors (like k/m/g suffixes) rather than introducing a new `OPTION_UNSIGNED` type. This simplifies the API while maintaining all the desired safety improvements. The series also drops the bounded integer options proof-of-concept that was in v3, as it was deemed not immediately necessary.

The patches systematically improve option parsing safety by:
1. Adding precision awareness for different integer sizes (8/16/32/64-bit)
2. Introducing proper signedness validation
3. Improving error handling for overflow cases
4. Modernizing the initialization syntax
5. Fixing an off-by-one error in signed value parsing

The changes touch many builtin commands to update their option declarations, along with the core parse-options machinery. Test coverage is expanded to verify the new behaviors.

This appears to be in final form, with all major design questions resolved through maintainer-contributor consensus. The only remaining item is some documentation clarification. The series demonstrates careful attention to backward compatibility while making meaningful safety improvements to Git's option parsing.
