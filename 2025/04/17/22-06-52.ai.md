This is the final patch in a build system alignment series focusing on cryptographic random number generation (CSPRNG) standardization across platforms. The patch sets `CSPRNG_METHOD = getrandom` for Linux in `config.mak.uname`, completing the series' goal of aligning Makefile behavior with meson's preference for kernel-based random number generation while maintaining compatibility with all supported distros (including RHEL 8).

The email exchange confirms successful Cygwin testing (a 6+ hour `make test` run completed without issues) and resolves a minor typo (`ar4random_buf` -> `arc4random_buf`) that Junio Hamano will fix locally rather than requiring a v4 resend. This indicates the series is now ready for integration, having addressed all technical concerns raised during review.

Key technical context from earlier in the thread includes the rationale that all supported Linux distributions (including RHEL 8 with glibc 2.28) have `getrandom`/`getentropy` (glibc 2.25+), and while `arc4random` exists in newer glibc (2.36+), it offers no performance benefit on Linux since all methods ultimately use the same kernel CSPRNG. The change represents the final piece in standardizing CSPRNG methods across build systems, following earlier patches that enabled `arc4random` for Cygwin.
