Bugfix targeting the `git help` command's error messaging. The patch corrects a minor but noticeable discrepancy in how nonexistent subcommands are reported to users.

The issue occurs when running `git help` for a nonexistent command. Currently, the error message shows "No manual entry for gitnosuchcommand" (without a hyphen), while the correct man page naming convention would include a hyphen as in "git-nosuchcommand". The error originates from the `cmd_to_page()` function in builtin/help.c which formats the man page name.

The proposed change is straightforward - it modifies the string formatting in `cmd_to_page()` to insert a hyphen between "git" and the subcommand name. The patch is minimal (a single character change) and well-contained, only affecting this specific error message path. The commit message clearly explains both the current behavior and the expected behavior.

This appears to be a genuine inconsistency rather than a deliberate design choice, as evidenced by the fact that the man page system itself expects hyphenated names. The fix aligns with Git's established conventions for man page naming. The patch is technically sound and unlikely to introduce any regressions given its limited scope.
