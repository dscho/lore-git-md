Performance test optimization in the bitmap test suite, part of Taylor Blau's series to enable bitmap lookup tables by default.

This email contains Junio C Hamano's review of the fourth patch in the series, which optimizes the test harness by changing a setup-phase repack operation from `test_perf` to `test_expect_success` in the `test_pack_bitmap()` helper function. The change makes sense since the repack operation is idempotent setup that doesn't need performance measurement, and repeating it multiple times (as `test_perf` would do) provides no benefit while slowing down test runs.

The patch is straightforward - a one-line change to the lib-bitmap.sh test library. Junio's response ("OK.") indicates approval of this specific change, though the thread context shows he has raised broader questions about other aspects of the series, particularly around maintaining test coverage for non-default configurations and the architectural concern about parallel flag systems for bitmap lookup tables in different subsystems.

This appears to be a clean optimization that stands on its own regardless of the ongoing discussion about the series' larger changes. The modification aligns with good test suite practices by separating setup from actual performance measurement.
