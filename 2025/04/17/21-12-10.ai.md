This is a cover letter for a series of patches related to bitmap lookup tables in Git's pack-bitmap functionality. The series has two main components: changing the default behavior for bitmap lookup tables, and cleaning up related performance test scripts.

The first patch makes bitmap lookup tables enabled by default when writing bitmaps, marking a shift from their previous opt-in status. The commit suggests this change is motivated by sufficient time having passed since their introduction and observed performance benefits during testing of a larger (unrelated) delta reuse feature.

The remaining three patches are maintenance-oriented:
- Removing a redundant performance test script (p5312) that duplicated functionality now covered by other tests
- Updating remaining performance tests to avoid testing bitmap configurations without lookup tables
- Tweaking test infrastructure to avoid using `test_perf` during setup phases

The changes touch several performance test scripts (p5310, p5311, p5326) and their supporting library, with one script being deleted entirely. The modifications appear focused on streamlining the test suite to match the new default behavior while maintaining coverage.

Key technical details for future reference:
- Changes default behavior in `pack.writeBitmapLookupTable` config
- Affects bitmap writing in both `multi-pack-index` and `pack-objects`
- Removes p5312 test script which tested rev-list with bitmaps
- Updates other tests to explicitly test with lookup tables
- Modifies lib-bitmap.sh to avoid performance measurements during setup

The series seems well-motivated and technically sound, with the default change following a reasonable deprecation period for the lookup table feature. The test cleanups appear to be straightforward maintenance following this behavioral change.
