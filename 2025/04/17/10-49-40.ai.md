Feature and safety improvement for parse-options integer handling. This patch (5/7 in the series) introduces precision-aware integer parsing for `OPTION_INTEGER` options, completing the integer parsing hardening work.

The change adds a new `precision` field to track the size of integer variables passed via `OPT_INTEGER_F()`, enabling proper range checking for different integer types (int8_t through int64_t). The implementation switches from `strtol()` to `strtoimax()` to handle values beyond `LONG_MAX` and adds comprehensive bounds checking. Several builtin commands (`fmt-merge-msg`, `merge`, `show-branch`, `tag`) are updated to include the new precision field.

Key technical details:
- New test cases verify 16-bit integer range enforcement
-i16 option added to test helper for validation
- Error messages now show exact valid range when bounds are exceeded
- Maintains backward compatibility while fixing potential overflow issues
- Follows the series' pattern of using designated initializers
- Builds on previous patches' unit factor support and API naming changes

The patch demonstrates careful handling of edge cases and maintains the series' focus on type safety. It represents a significant step in hardening Git's option parsing against integer overflow vulnerabilities while preserving the existing API surface.
