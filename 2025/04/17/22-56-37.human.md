This is a bugfix for a minor inconsistency in `git help`'s error message formatting. When looking up a non-existent command (like `git help nosuchcommand`), the current error message omits the hyphen between "git" and the command name, though the actual manpage naming convention includes it.

Keith Thompson reports that the man command would show the error as "No manual entry for gitnosuchcommand" when it should say "git-nosuchcommand" to match the actual manpage naming convention. The one-line patch modifies `builtin/help.c` to insert the missing hyphen in the error message format string.

The fix is straightforward and appears correct - it simply changes `xstrfmt("git%s", git_cmd)` to `xstrfmt("git-%s", git_cmd)` in the `cmd_to_page` function. While this is a very minor cosmetic issue, it does make the error message more accurate and consistent with Git's manpage naming conventions. The patch is small, focused, and comes with clear reproduction steps and rationale.
