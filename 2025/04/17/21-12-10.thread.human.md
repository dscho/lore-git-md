Taylor Blau has proposed enabling bitmap lookup tables by default, marking the stabilization of an optimization that has been opt-in since its introduction in 2022. These tables improve performance by storing commit positions and bitmap offsets to avoid reading entire bitmap files during operations. The first patch in his series changes the default value of `pack.writeBitmapLookupTable` to true, adds the lookup table flag to multi-pack-index writes, and includes it in pack-objects' default options. 

Taylor provides performance data from kernel repository tests showing consistent improvements, particularly for rev-list operations (0.78s to 0.56s), with smaller gains in clone and fetch scenarios. He notes these tables have been used successfully in production at GitHub for nearly three years without issues. The patch modifies specific bitmap flags (`MIDX_WRITE_BITMAP_LOOKUP_TABLE` and `BITMAP_OPT_LOOKUP_TABLE`) in the multi-pack-index and pack-objects components.

This initial patch sets the stage for follow-up changes that will update tests and remove redundant coverage, as the optimization is now considered stable enough to be the default. Taylor, a recognized expert in Git's pack and bitmap subsystems, is driving this effort as part of his ongoing work on storage optimizations. No reviews have been posted yet, but discussion may emerge around performance verification or backward compatibility considerations.
