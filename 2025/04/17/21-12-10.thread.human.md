Taylor Blau's patch series proposes enabling bitmap lookup tables by default, reflecting their stable status after years of production use at GitHub. The initial version included test suite maintenance to remove redundant performance tests and optimize the test harness. Junio C Hamano raised several points: he approved the test harness optimization but expressed concerns about maintaining parallel flag systems between the multi-pack-index and pack-objects subsystems, and questioned whether completely removing performance tests for the non-default (lookup-table-disabled) configuration was premature.

Jeff King (Peff) has now responded with a technical solution to the flag synchronization issue. He proposes unifying the bitmap options handling by adding a new `bitmap_options` field to the midx struct and removing the separate MIDX_WRITE_BITMAP flags entirely. While this would require plumbing changes through several midx-related functions, it would eliminate the manual synchronization problem Junio identified. Peff remains neutral on whether this refactoring's complexity is justified given how rarely these defaults change.

The discussion continues to balance several considerations: the desire to simplify the codebase by removing old paths, the need to maintain test coverage for supported configurations, and the architectural cleanliness of the bitmap options handling. Junio has drawn parallels to the recursive/ORT merge strategy transition, suggesting a conservative approach to removing old code paths until the new ones are universally proven superior.
