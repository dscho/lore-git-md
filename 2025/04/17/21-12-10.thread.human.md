Taylor Blau's patch series to enable bitmap lookup tables by default has reached technical consensus on the key architectural question of flag synchronization between subsystems. Jeff King (Peff) and Taylor agree that forcing synchronization between the pack-bitmap and midx flags isn't necessary, as mismatched settings wouldn't cause functional issues. Taylor outlined alternative synchronization approaches that were considered but ultimately deemed too fragile or complex given the lack of practical need.

The discussion has now shifted from technical implementation to test coverage philosophy. Junio Hamano has approved the test harness optimizations but questions whether completely removing performance tests for non-default configurations is premature, suggesting they could serve as an "escape hatch" for debugging. Peff counters that version comparisons provide sufficient baseline data and the runtime improvements (cutting test times from 60 to 30 minutes) justify the tradeoff. Meanwhile, Peff's deeper analysis has revealed measurement validity issues in the test_pack_bitmap() helper that affect both this series and related multi-pack-index tests, indicating more fundamental test infrastructure work may be needed.

The series remains at v1 while these test-related discussions continue. Junio has suggested minor commit message fixes and proposed modifying rather than removing some performance coverage. The core technical change - enabling lookup tables by default - appears uncontested now that the flag synchronization question is resolved.
