Completion of Linux CSPRNG standardization in build system series.

This is the final patch in a 22-part series aligning cryptographic random number generation across Git's build systems. It standardizes Linux builds to use `getrandom()` in the Makefile, matching meson's preference for kernel-based random number generation while maintaining compatibility with all supported distros (including RHEL 8). 

The email confirms successful Cygwin testing (a 6+ hour `make test` run completed without issues) and resolves a minor typo (`ar4random_buf` -> `arc4random_buf`) that Junio Hamano noted but will fix locally rather than requiring a v4 resend. 

This change completes the CSPRNG standardization effort that previously added `arc4random` support for Cygwin. The technical rationale (confirmed by maintainers) is that all supported Linux distributions have `getrandom`/`getentropy`, and while newer glibc versions include `arc4random`, it provides no performance benefit on Linux since all methods ultimately use the same kernel CSPRNG.

The series appears ready for integration with maintainers aligned on the technical direction. This final patch represents a low-risk adjustment that brings Makefile behavior in line with meson's existing implementation while maintaining compatibility across all supported platforms.
