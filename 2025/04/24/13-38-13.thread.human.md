This thread addresses improvements to shell path detection in Git's Meson build system, motivated by real-world issues encountered at GitLab and previously reported by Debian. The two-patch series aims to make Git's shell detection more reliable across different host systems, particularly in cross-compilation scenarios where build and target environments differ.

The first patch, now under discussion, adds diagnostic reporting of detected runtime executable paths (Perl, Python, and shell) in the Meson build summary output. This 6-line change makes the build system more transparent by showing which paths Meson's `find_program()` has autodetected via PATH lookup. The second patch, not yet sent, will modify the shell detection logic itself to prefer the POSIX-specified /bin/sh path over PATH-based lookup for improved reliability.

The changes are minimal and focused, addressing a specific pain point where Git could fail to find its shell when built with Meson due to PATH lookup reliance. The series builds on prior issue reports and appears well-motivated by concrete problems in production environments. The first patch serves as groundwork for the more substantial shell detection change to follow, while providing immediate value for build system debugging.
