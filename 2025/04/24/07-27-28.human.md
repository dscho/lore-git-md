This is a bug report about HTTP/2 support in Git for Windows. Lars Eriksen reports that after upgrading to Git for Windows 2.49.0, the bundled cURL no longer supports HTTP/2 when authenticating against their corporate backend, despite this working in version 2.39.0. The system info shows cURL 8.12.1 is being used with OpenSSL 3.2.4.

The issue appears to be a regression in the Windows build configuration, as `curl --version` confirms HTTP/2 support is missing in the current version. This is problematic for the reporter since they cannot install a custom cURL on their corporate network and rely on Git's bundled version for their maintenance scripts.

The report provides clear reproduction steps and version information, making it easy to verify. The impact is significant for users who depend on HTTP/2 for authentication with their Git servers. This seems like a legitimate regression that Windows maintainers would want to investigate, though we'd need to see if others can reproduce it and whether this was an intentional build configuration change.
