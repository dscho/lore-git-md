This is a follow-up patch in the signature handling thread, refining the algorithm name identification in `git fast-export` and `git fast-import`. The patch builds on the recently merged signed commit support, addressing the previous limitation where all signatures were labeled as "sha1" regardless of their actual type.

The key technical changes include:
- `fast-export` now uses new `gpg-interface` functions (`get_signature_name()`) to properly identify signature types (OpenPGP, X509, SSH) rather than hardcoding "sha1"
- `fast-import` validates algorithm names via `valid_signature_name()` while preserving unknown ones with warnings
- Documentation is updated to clarify supported signature types and their stream format
- New tests verify X.509 and SSH signature handling

Elijah Newren's review raises several questions about edge cases and implementation details:
- Asks for clarification about the handling of `--reencode` and whether signature preservation works when commit content is modified
- Questions whether the tests should cover cases where the exported commit doesn't exactly match the original
- Notes ambiguity in the commit message's description of future verification work
- Expresses some confusion about the signature validation logic (though acknowledges unfamiliarity with GPG details)

The patch appears technically sound with thorough test coverage, but the review suggests some areas that may need clarification in either the implementation or documentation before final merging. The changes maintain backward compatibility while improving accuracy of signature type reporting.
