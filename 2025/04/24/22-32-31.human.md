This is a discussion probe about Git's handling of symlinked `.git` internals, prompted by compatibility issues with Git LFS and the Android `repo` tool. Brian M. Carlson reports that Git LFS fails when `.git/objects` or other internal directories are symlinks, which happens in repositories created by Android's `repo` tool. The email asks whether the Git project considers this symlink usage acceptable and whether it should be fixed.

The core issue appears to be path canonicalization problems when operations are run from symlinked directories, causing `.git` directory detection to fail. While symlinking the `hooks` directory is known to be semi-supported, the status of other directories like `objects` is unclear. Carlson notes they haven't tested how alternative Git implementations handle this case.

The email poses this as an open question to the community: should Git work to support this symlink usage (which would require adding tests), or should it actively discourage the practice (perhaps through warnings)? The discussion will likely need input from both Git maintainers and users of tools like Android's `repo` to determine whether this is a bug to fix or an unsupported configuration to document.
