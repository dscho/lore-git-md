Windows bug report update on phantom lock files and GUI client issues. Jörg Hohwiller confirms the previously reported lock file error persists even after testing the latest Git for Windows snapshot (2.49.0.windows.1.7.g4ca71ba531), definitively ruling out the initial ReFS drive regression connection. The error manifests as spurious reports of non-existent `.lock` files (e.g., `refs/remotes/origin/bugfix/XY-74488.lock`) during `git pull` operations. Hohwiller notes the issue affects both command-line usage and GUI clients like git-fork and IntelliJ, with git-fork frequently stalling and requiring process termination. Johannes Schindelin's suggested workaround of manually removing the non-existent lock files remains the only known mitigation, though Hohwiller finds this solution impractical for regular workflow. The thread shows progression from initial hypothesis testing to confirmation of a distinct, persistent issue, though root cause analysis remains blocked without additional system diagnostics. Key technical details still missing include complete GIT_TRACE output and FSCache configuration verification. The GUI client freezing behavior represents a new symptom potentially related to the underlying lock file issue.
