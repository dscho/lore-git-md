Thread identity: Bug report about HTTP/2 support regression in Git for Windows 2.49.0, reported by Lars Eriksen, with technical responses from Johannes Schindelin (Git for Windows maintainer). The issue has expanded to cover both Git's internal HTTP operations and the standalone `curl.exe` bundled with Git for Windows.

Core problem: Two distinct but related HTTP/2 support regressions in Git for Windows 2.49.0:
1. Git's internal HTTP operations no longer support HTTP/2 depending on configured SSL backend (`openssl` supports it, `schannel` does not)
2. The bundled `curl.exe` command-line tool (used by corporate deployment scripts) has lost HTTP/2 support entirely, regardless of SSL backend configuration

Key technical details:
- For internal Git operations: `http.sslBackend` configuration controls HTTP/2 capability (openssl=yes, schannel=no)
- For standalone curl.exe: HTTP/2 support appears completely absent in recent builds, regardless of SSL backend
- Original workaround (setting `http.sslBackend = openssl`) only addresses the first issue
- System info shows libcurl 8.12.1 and OpenSSL 3.2.4, but HTTP/2 support varies by component
- Build logs at specific Actions URLs demonstrate capability differences
- `/etc/install-options.txt` contains default SSL backend choice

Current status:
- Root cause identified for both components
- Partial workaround exists for Git's internal operations
- No solution yet for standalone curl.exe HTTP/2 regression
- Bug reporting template improvement suggested to include SSL backend info

Open questions:
- Does the `http.sslBackend` workaround resolve any part of the reporter's workflow?
- Why was HTTP/2 support removed from the standalone curl.exe build?
- Can HTTP/2 support be restored to the bundled curl.exe without violating corporate security policies?
- Should Git for Windows reconsider default build options for both components?

Participant positions:
- Lars Eriksen: Reported regression, provided crucial clarification about standalone curl.exe usage
- Johannes Schindelin: Identified root causes, proposed initial workaround, suggested template improvement

Impact: Serious regression affecting both Git operations and deployment scripts in corporate environments where HTTP/2 is required and alternative tools cannot be installed. The thread has evolved from initial diagnosis to uncovering a more complex situation than originally understood, with one partial solution identified but a major outstanding issue remaining.
