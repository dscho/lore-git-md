Thread identity: Bug report about HTTP/2 support regression in Git for Windows 2.49.0, reported by Lars Eriksen, with technical response from Johannes Schindelin (Git for Windows maintainer).

Core problem: After upgrading to Git for Windows 2.49.0, the embedded cURL no longer supports HTTP/2, breaking authentication against corporate backends that require HTTP/2. This worked in version 2.39.0.windows.2. The regression stems from Git for Windows shipping two cURL builds with different SSL backends - OpenSSL (supports HTTP/2) and Secure Channel (lacks HTTP/2).

Key technical details: 
- System info shows libcurl 8.12.1 and OpenSSL 3.2.4, but HTTP/2 support depends on configured SSL backend
- `http.sslBackend` configuration controls which cURL version is used (openssl vs schannel)
- Build logs at specific GitHub Actions URLs demonstrate the HTTP/2 capability difference
- `/etc/install-options.txt` contains the default SSL backend choice
- Reporter provided clear reproduction steps and version information

Current status: 
- Root cause identified as backend-specific HTTP/2 support
- Workaround proposed: test with `http.sslBackend = openssl` configuration
- Bug reporting template improvement suggested to include SSL backend info

Open questions:
- Does the workaround resolve the issue for the reporter?
- Should Git for Windows default to OpenSSL backend when HTTP/2 is required?
- Will the bug reporting template be updated to capture SSL backend info?

Participant positions:
- Lars Eriksen: Reported regression with detailed environment info
- Johannes Schindelin: Identified root cause, proposed workaround, suggested template improvement

Impact: Breaks existing functionality that worked in previous versions (2.39.0.windows.2), with potential workaround via configuration change if corporate policies allow it. The thread has progressed from initial report to technical diagnosis and proposed solution.
