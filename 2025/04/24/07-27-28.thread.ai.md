Thread identity: Bug report about HTTP/2 support regression in Git for Windows 2.49.0, reported by Lars Eriksen, with technical analysis from Johannes Schindelin (Git for Windows maintainer). The thread covers three distinct but related issues: Git's internal HTTP operations, the standalone `curl.exe` bundled with Git for Windows, and the project's philosophy around bundled tools.

Core problem: Three aspects of HTTP/2 support in Git for Windows 2.49.0:
1. Git's internal HTTP operations: HTTP/2 support depends on `http.sslBackend` configuration (openssl=yes, schannel=no)
2. Bundled `curl.exe`: HTTP/2 support completely absent regardless of SSL backend
3. Project scope: Git for Windows maintains that bundled `curl.exe` is only for Git's internal use, not as a general-purpose tool

Key technical details:
- Internal Git operations: `http.sslBackend=openssl` enables HTTP/2 (partial workaround)
- Standalone curl.exe: HTTP/2 capability removed in recent builds with no technical explanation provided
- Project stance: Bundled tools are dependencies, not features - users needing full curl should use system version or MSYS2
- Original reporter's corporate environment constraints made alternative installations difficult but they found a workaround

Current status:
- Root cause identified for internal Git operations (SSL backend dependency)
- No technical resolution for curl.exe regression, maintainer considers it out of scope
- Reporter Lars Eriksen has implemented a corporate-approved workaround using a separately built curl executable
- Philosophical disagreement about responsibility for bundled tools' functionality remains
- Thread effectively closed from reporter's perspective with workaround in place

Open questions:
- Will Git for Windows reconsider restoring HTTP/2 to bundled curl.exe given user impact?
- Should future releases more clearly document limitations of bundled tools?
- Is there a middle ground between full support and complete removal of features?

Participant positions:
- Lars Eriksen: Reported regression, highlighted corporate deployment constraints, found approved workaround
