This is a Windows-specific bug report about phantom lock files and GUI client freezes after upgrading to Git 2.48.1. Jörg Hohwiller confirms the issue persists even with the latest Git for Windows snapshot (2.49.0.windows.1.7), disproving the initial hypothesis that it was related to ReFS drives. The core problem remains that Git reports non-existent `.lock` files during operations like `git pull`, with the files never actually appearing on disk despite the error messages.

The issue affects both command-line Git and GUI clients like git-fork and IntelliJ, with the latter frequently freezing and requiring process termination. While Johannes Schindelin suggested manually removing the non-existent lock files as a workaround, Jörg notes this isn't practical as the files don't actually exist to be removed. The thread has established this is a distinct issue from the previously known ReFS regression (PR5515), but root cause analysis remains stalled without additional diagnostic information.

A secondary issue about missing status output (previously resolved in 2.47.1) appears less critical compared to the workflow-blocking lock file errors. The report indicates the problem is repository-specific, affecting only one of Jörg's repos despite being 387 commits behind origin with one untracked file. The thread shows progression from initial report through hypothesis testing, but remains unresolved pending more system details from affected environments.
