This is a discussion about the third patch in the v5 series adding OAuth2 support to `git send-email`, focusing on whether to keep the dynamic token generation mechanism or rely on Git's existing credential helper system.

The exchange suggests the patch may be dropped, but leaves open whether the series should instead add documentation improvements showing how to use credential helpers for OAuth2 token generation. This connects to the thread's open question about the final token generation approach, with the credential helper solution now appearing favored over the original `smtp-passeval` proposal.

Key technical points mentioned:
