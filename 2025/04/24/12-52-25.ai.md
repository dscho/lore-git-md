This is a technical response in the HTTP/2 support regression thread for Git for Windows. Johannes Schindelin provides key insights about the underlying issue and suggests a workaround.

The email clarifies that Git for Windows builds cURL with two different SSL backends - OpenSSL (with HTTP/2 support) and Secure Channel (without HTTP/2). The observed behavior depends on which backend is configured. Johannes points to specific build logs showing the HTTP/2 capability difference between backends and asks the reporter to test with `http.sslBackend = openssl` configuration.

The response also notes an improvement opportunity in the bug reporting template, suggesting it should include the SSL backend configuration from `/etc/install-options.txt`. This would help diagnose similar issues more quickly in the future.

Key technical details for future reference:
- Two cURL builds in Git for Windows: OpenSSL-backed (supports HTTP/2) and Secure Channel-backed (lacks HTTP/2)
- Configuration setting `http.sslBackend` controls which version is used
- Build logs at specific GitHub Actions URLs show the compilation differences
- `/etc/install-options.txt` contains the default SSL backend choice

The email advances the thread by identifying the root cause (backend-specific HTTP/2 support) and proposing a concrete test to verify if switching backends resolves the issue, while also suggesting a template improvement for future bug reports.
