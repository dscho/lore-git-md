Bugfix investigation for Windows-specific Git issues. Jörg Hohwiller reports a new symptom in the ongoing investigation of Git 2.48.1 upgrade problems on Windows - a "failed to run reflog" error with "task 'gc' failed" appearing during `git pull` operations. While the pull still completes, this suggests additional underlying issues beyond the previously reported spurious lock file errors and missing status output.

The thread context shows this is part of a complex Windows-specific regression where lock files are incorrectly reported as existing when they don't, affecting both command-line and GUI clients. Johannes Schindelin had previously suggested testing with a Git for Windows snapshot (2.49.0.windows.1.7) and manually removing .lock files as a workaround, but the core issue persists.

The new gc/reflog error indicates the problems may extend deeper into Git's housekeeping operations on Windows. This comes on top of the existing workflow-blocking issues where GUI clients like IntelliJ and git-fork either show errors or freeze entirely. The investigation remains hampered by lack of complete system diagnostics (exact Windows version, GIT_TRACE output, FSCache configuration) from the reporter.

The thread shows steady progression from initial report through hypothesis testing (ReFS connection was disproven) to identifying workarounds, but root cause analysis remains incomplete. The new gc/reflog error suggests the underlying filesystem interaction problems may affect more Git subsystems than initially apparent.
