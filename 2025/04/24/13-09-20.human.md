Bugfix and Outlook compatibility patch in the ongoing `git send-email` OAuth2 series. This is the second patch in the fifth iteration of a series adding OAuth2 support and Outlook compatibility fixes to `git send-email`. The patch addresses Outlook's nonstandard behavior where it discards client-generated Message-IDs and creates its own, breaking email threading.

Greg Kroah-Hartman raises a valid concern about the Outlook detection logic, noting that many organizations run their own Outlook-compatible SMTP servers that might exhibit the same behavior but wouldn't be caught by the current hardcoded hostname check. He suggests making this configurable rather than relying on hardcoded hostnames.

The patch itself modifies `git-send-email.perl` to extract the server-assigned Message-ID from Outlook's SMTP response and use it for threading, along with adding an `is_outlook()` detection function. While the technical solution appears sound, Greg's comment highlights a potential limitation in the detection approach that might need addressing before final merge.

This is part of a larger effort to make `git send-email` work reliably with modern email providers, with the first patch handling OAuth2 authentication and this one fixing Outlook-specific threading issues. The series has seen several iterations with active discussion about implementation details.
