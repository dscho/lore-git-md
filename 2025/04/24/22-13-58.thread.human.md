This thread addresses an immediate CI outage affecting Git's Linux test jobs, where downloads of external dependencies (particularly JGit from repo.eclipse.org) were failing and causing the entire CI run to abort. The discussion started with Junio Hamano proposing a targeted fix to make JGit downloads optional, since the test framework already knows how to skip tests when JGit is missing.

The solution has now expanded to handle all external dependencies (Perforce, Git-LFS, and JGit) consistently. The updated patch modifies the dependency installation script to make downloads of all three optional, with proper cleanup when downloads fail. Each operation now includes error handling that removes partially downloaded files and emits a warning while allowing the script to continue. This matches the test framework's existing ability to skip tests when dependencies are missing.

Junio initially floated the idea of removing "set -e" from the script entirely as a future maintainability improvement, but the current approach takes a more surgical route - keeping "set -e" while adding proper error handling just for the dependency downloads. The change appears well-scoped and consistent with existing patterns. No objections or alternative approaches have been raised, and the patch seems likely to be backported to unblock CI while the repo.eclipse.org outage persists.
