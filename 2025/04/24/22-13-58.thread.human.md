This thread addresses CI stability issues by making external dependency downloads (JGit, Perforce, Git-LFS) optional with proper failure handling in Git's Linux CI jobs. The discussion has evolved from the core solution to nuanced implementation details, with maintainers Patrick Steinhardt, Junio Hamano, and Johannes Schindelin collaborating on refinements.

The current approach uses `wget && chmod || rm` chains to handle download failures as atomic operations, with consensus that this sufficiently prevents harmful leftover files. While Patrick suggested more explicit if-else structures for empty file cleanup, Junio maintains the current pattern expresses intent clearly without unnecessary verbosity. Johannes contributed insights about platform-specific warning markers and alternative download sources.

Key technical focus remains on wget's behavior (which creates empty files on failure) and its interaction with CI's `set -e` behavior. The maintainers agree the solution should treat the entire download operation (wget + chmod) as succeeding or failing together, prioritizing practical impact over precise error diagnosis. The discussion shows convergence on keeping the current approach unless wget's behavior changes significantly, with the core patches already fast-tracked to master for immediate CI stability.
