This thread has evolved into a discussion about improving Git's CI infrastructure to handle external dependencies more reliably. The original series addressed immediate CI outages by making dependency downloads (JGit, Perforce, Git-LFS) optional with proper failure handling. Core error handling patches have already been merged, and subsequent refinements implemented GitHub Actions warning formatting and updated the JGit download source to Maven Central.

The current focus is on developing a caching strategy to avoid redundant downloads across CI jobs, following Junio Hamano's recommendation for once-per-platform caching. Jialuo has been investigating practical approaches, and now Patrick Steinhardt has proposed a Docker-based solution. His suggestion involves pre-seeded platform-specific Docker images containing all external dependencies, rebuilt only when dependencies change, and made available via container registry. This would provide both caching benefits and improved reproducibility of CI failures, though implementation details around image building and registry access remain to be worked out.

Key participants include Junio Hamano (maintainer, advocating the caching approach), Johannes Schindelen (who suggested the warning format now implemented), Matthias Sohn (JGit maintainer who recommended Maven Central), and Jialuo (leading the caching investigation). The discussion continues to balance reliability, efficiency, and maintainability in Git's CI infrastructure.
