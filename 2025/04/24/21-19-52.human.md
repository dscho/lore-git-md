This is a follow-up patch in the signature handling thread, addressing feedback on the recently merged signed commit support in `git fast-export`/`git fast-import`. Christian Couder improves the signature algorithm name handling to properly distinguish between OpenPGP, X.509, and SSH signatures rather than labeling everything as "sha1".

The patch introduces more precise signature type detection in `fast-export` using gpg-interface functions, and adds validation in `fast-import` while preserving unknown signature types with warnings. Documentation is updated to clearly enumerate supported signature algorithms.

Junio raises several concerns in his review:
1. Questions why the original implementation's shortcomings weren't caught earlier
2. Notes some documentation could be clearer by listing algorithms explicitly
3. Points out potential backward compatibility issues with existing fast-export streams
4. Expresses confusion about the special handling of sha256 versus other algorithms

The technical changes appear sound, but Junio's review suggests the patch may need revision to address backward compatibility and clarify the sha256 special case. The discussion highlights the challenges of evolving signature handling while maintaining compatibility with existing workflows.
