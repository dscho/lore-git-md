Maintainer response in symlink support discussion. Junio C Hamano weighs in on the ongoing discussion about symlinking `.git` internals, clarifying the project's stance on different symlink patterns.

The email confirms that symlinking individual subdirectories (as done by `git-new-workdir`) is an existing practice, though not officially supported. However, it draws a clear distinction between this and symlinking the entire `.git` directory itself, which is not intended to be supported. The response notes that Git's multiple worktree support uses a different mechanism (`.git` as a regular file) that shouldn't be confused with direct symlinking.

The message strongly agrees with Brian Carlson's suggestion that the project should take a clear position - either properly support the pattern with tests or explicitly discourage it with warnings. This moves the discussion forward by establishing that some symlinking patterns are more acceptable than others, while leaving open the project's ultimate decision about whether to formalize support for any of them. The response comes from a position of authority but doesn't dictate a solution, instead endorsing the need for clarity through either testing or warnings.
