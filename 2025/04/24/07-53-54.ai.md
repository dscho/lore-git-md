This is patch 2/3 in the v5 series adding OAuth2 support and Outlook compatibility fixes to `git send-email`. The patch specifically addresses Outlook's nonstandard Message-ID handling behavior.

The core issue is that Outlook discards client-generated Message-IDs and replaces them with its own, breaking email threading when replies reference the original (now discarded) ID. The patch implements a workaround by extracting the server-assigned Message-ID from the SMTP response (which follows the format "2.0.0 OK <Message-ID>") and using that for subsequent replies.

Key technical elements:
- New `is_outlook()` helper function checks for known Outlook SMTP endpoints (smtp.office365.com, smtp-mail.outlook.com)
- Message-ID extraction via regex from SMTP response after sending
- Updates `$message_id` variable to use server-assigned ID when detected
- Includes warning if ID extraction fails
- Maintains backward compatibility with non-Outlook providers

The patch builds on the thread's broader goal of improving `send-email` compatibility with modern email providers, specifically addressing Outlook's proprietary behavior around message threading. It follows the approach Junio Hamano approved in earlier review rounds, with more precise commit message wording in this v5 iteration. The Outlook detection mechanism remains a point of discussion (Brian M. Carlson raised concerns about enterprise CNAMEs), but the core Message-ID handling logic appears straightforward.
