This is the third patch in a v4 submission adding OAuth2 support and Outlook compatibility fixes to `git send-email`. The patch focuses on dynamic OAuth2 token generation via a new `smtp-passeval` option.

The patch adds a command execution path where `git send-email` can run a user-specified command to generate OAuth2 tokens on the fly. The implementation follows the same security model as existing command execution paths like `sendmailcmd`, though Junio Hamano raises valid concerns about command injection risks. The author argues this matches Git's existing trust model for config/command execution while acknowledging the inherent security tradeoffs for OAuth2 workflows.

Key technical details include:
- New mandatory `--smtp-passeval=<command>` option (documentation fixed to remove misleading optional brackets)
- Command output captured and used as the SMTP password
- Implementation parallels other command execution paths in send-email
- Security considerations around command injection acknowledged but deemed consistent with Git's existing model
- Documentation updated to clarify the option's mandatory nature

The patch appears ready technically but the security implications remain an open discussion point. Junio has approved the approach pending resolution of documentation inconsistencies and with explicit awareness of the command execution risks. This ties into the broader series' goal of enabling OAuth2 workflows while working within Git's security model.
