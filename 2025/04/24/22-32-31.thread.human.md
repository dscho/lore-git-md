This thread discusses the handling of symlinks in `.git` internals, particularly `objects/`, prompted by compatibility issues between Git LFS and Android's `repo` tool which creates such symlinks. The current behavior causes problems with path resolution when operations run from symlinked directories.

Junio C Hamano has now weighed in, clarifying that while symlinking individual subdirectories (as done by `git-new-workdir`) is an existing practice, symlinking the entire `.git` directory itself is not intended to be supported. He strongly agrees with Brian Carlson's position that the project should take a clear stance - either properly support the pattern with tests or explicitly discourage it with warnings. This moves the discussion forward by distinguishing between more and less acceptable symlinking patterns, though the final decision on formal support remains open.

The thread remains focused on determining whether Git should officially support this usage (requiring test coverage), explicitly discourage it, or maintain the current ambiguous state. Technical considerations involve filesystem edge cases and compatibility impacts on tools like Git LFS, with the maintainer now signaling that some clarity is needed.
