Bugfix discussion for Windows-specific lock file issue. Johannes Schindelin responds to Jörg Hohwiller's ongoing problem with spurious lock file errors during `git pull` operations on Windows, which persists even after testing the latest Git for Windows snapshot (2.49.0.windows.1.7). The key new information is a workaround: Johannes clarifies that users need to manually remove the non-existent `.lock` file before retrying the operation. This confirms the issue is distinct from the previously suspected ReFS drive regression (PR5515). The thread shows steady progress in diagnosing this workflow-blocking issue, though the root cause remains unclear. The discussion remains focused on Windows-specific behavior, with Johannes providing direct troubleshooting guidance while the investigation continues.
