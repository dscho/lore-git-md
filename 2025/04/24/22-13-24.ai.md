This is a bug report about credential prompt display issues during HTTPS clone operations, particularly when Git LFS is involved.

The reporter, Tom S, describes a scenario where a second credential prompt appears during a clone operation but gets partially obscured by progress output. The visible symptom is a truncated prompt (".ocal':") appearing mid-line during the "Updating files" phase, which they believe may be related to Git LFS authentication. The reporter had to manually type their username to reveal the hidden password prompt, noting that the authentication does work when properly entered.

The issue occurs with Git 2.49.0 on Fedora 42 using Gnome Terminal with tmux. The bug manifests when cloning an HTTPS repository from a local GitLab server, with the key problematic output showing the credential prompt interleaved with progress meters. The reporter suggests that if multiple prompts are necessary, they should appear cleanly on separate lines without being overwritten by other output.

This appears to be a UI/UX issue in Git's credential handling during clone operations, particularly when secondary authentication (likely for LFS) is required. The core problem seems to be about output buffering or synchronization between progress meters and interactive prompts. The report includes a complete reproduction scenario with redacted paths but maintains the relevant output structure that demonstrates the issue.
