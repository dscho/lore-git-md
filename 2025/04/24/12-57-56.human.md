Windows-specific SSL regression workaround suggestion from Johannes Schindelin.

This is a follow-up in the ongoing thread about Git for Windows SSL/cloning issues with Azure DevOps. Johannes Schindelin suggests trying an alternative SSL backend as a potential workaround for the regression where Git for Windows 2.44.0+ fails to clone from Azure DevOps with SSL errors, while older versions (2.30.2-2.43) work fine.

The proposed solution is to explicitly use Windows' native Schannel SSL backend instead of OpenSSL by passing `-c http.sslbackend=schannel` during clone operations. This is a targeted suggestion that may help users affected by the OpenSSL-related failures while the root cause is being investigated.

The email doesn't address whether this is a permanent fix or just a temporary workaround, nor does it explain why the Schannel backend might work where OpenSSL fails. However, it provides a concrete action for the reporter to test while the underlying issue remains under investigation in the Git for Windows issue tracker. The suggestion aligns with the Windows-specific nature of the problem previously identified in the thread.
