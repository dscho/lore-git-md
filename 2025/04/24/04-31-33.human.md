This is a follow-up discussion in the ongoing thread about integrating Git's performance benchmarks with the Meson build system. The core technical implementation is complete, and the conversation now focuses on the user experience when the required `time` command is missing.

Patrick Steinhardt responds to Christian Couder's suggestion to explicitly error out when `time` command is unavailable for benchmarks. Patrick argues against making this a hard requirement by default, noting that most developers only run tests and shouldn't need `time` installed for normal workflows. He proposes a compromise solution: making benchmarks an optional feature that auto-disables when `time` is missing, but can be explicitly enabled (with failure if `time` is unavailable) via a build option.

The discussion highlights a philosophical difference in approach - Christian prefers explicit errors for missing dependencies (following the pattern used for internationalization support), while Patrick advocates for a more permissive default that won't disrupt most developers' workflows. This appears to be the final UX decision point before the series can be merged, as all technical concerns have already been addressed.
