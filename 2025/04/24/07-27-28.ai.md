This is a bug report about HTTP/2 support in Git for Windows. The reporter, Lars Eriksen, notes that after upgrading to Git for Windows 2.49.0, the embedded cURL no longer supports HTTP/2, breaking authentication against their corporate backend which requires HTTP/2. This worked in version 2.39.0.windows.2. The reporter cannot install a custom cURL due to corporate restrictions.

The key technical details are that the system info shows libcurl 8.12.1 and OpenSSL 3.2.4, but `curl --version` indicates HTTP/2 support is missing. This appears to be a regression in the Windows build configuration, as the functionality worked in earlier versions. The reporter is constrained by corporate policies that prevent installing alternative cURL, making this a significant blocker for their workflow.

The bug report follows the standard format with clear reproduction steps and version information, making it easy to verify. The impact is well-explained - this breaks existing functionality that worked in previous versions, with no workaround available in the reporter's environment. The issue appears specific to the Windows build's cURL configuration rather than being a general Git bug.
