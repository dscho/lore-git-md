This is a follow-up discussion in the ongoing `git send-email` OAuth2 support series, specifically about the `smtp-passeval` option introduced in patch 3. Julian Swagemakers suggests an alternative approach to dynamic OAuth2 token generation using Git's existing credential helper mechanism, rather than adding a new `smtp-passeval` option.

The proposed alternative would configure a custom credential helper that executes the same token generation command, but through Git's standard credential infrastructure. This maintains the security model of credential helpers while achieving the same functionality. The example shows how to set this up with a shell function that runs the Python script when credentials are requested.

This raises an interesting architectural question about whether to extend `send-email` with new options or leverage existing Git mechanisms. The thread context shows Junio Hamano had security concerns about the `smtp-passeval` approach, so this alternative might address those while keeping the same end-user functionality. The discussion continues to refine the best way to handle dynamic OAuth2 tokens in a secure and maintainable way.
