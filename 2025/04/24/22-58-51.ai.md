This is a policy discussion about backward compatibility in the ongoing signature handling improvements for `git fast-export`/`fast-import`. Junio Hamano responds to Elijah Newren's question about whether compatibility is needed for the unreleased d9cb0e6ff8 (signed commit support).

The email reinforces the project's implicit compatibility policy - changes in 'master' should maintain backward compatibility, even for features not yet appear in official release. This positions the signature work as needing to handle both the technical representation challenges (protocol vs hash algorithm) while preserving compatibility with existing streams, regardless of release status.

The discussion highlights the tension between technical evolution and stability guarantees, with Junio advocating for a conservative approach that considers real-world usage patterns beyond just official releases.
