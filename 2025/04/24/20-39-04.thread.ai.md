This thread introduces and refines improvements to signature handling in `git fast-export` and `git fast-import`, building on the recently merged signed commit support (d9cb0e6ff8). The core problem is accurately identifying and preserving different signature types (OpenPGP, X.509, SSH) during fast-import/export operations, where previous implementations simply labeled everything as "sha1".

Key technical changes:
- `fast-export` now uses gpg-interface functions to properly identify signature types rather than hardcoding "sha1"
- `fast-import` validates signature algorithm names while preserving unknown ones with warnings
- New public functions `get_signature_name()` and `valid_signature_name()` in gpg-interface.h provide shared infrastructure for signature type handling
- Documentation updates clarify supported signature types and their stream format
- New tests verify X.509 and SSH signature handling

Junio Hamano's review feedback raises several technical concerns:
- Questions the special-casing of sha256 while sha1 is now handled generically
- Expresses concern about backward compatibility with existing fast-export streams using "sha1" algorithm names
- Notes potential line length issues in the fast-export.c changes
- Suggests improving documentation consistency by either listing all algorithms or cross-referencing between documents

The changes maintain backward compatibility while improving accuracy and laying groundwork for future signature verification support. The discussion indicates the patch needs clarification on sha1/sha256 handling strategy and backward compatibility implications, suggesting another revision may be needed before merging. The patch appears well-constructed with thorough test coverage and documentation updates, logically extending the signature infrastructure without introducing verification at this stage.
