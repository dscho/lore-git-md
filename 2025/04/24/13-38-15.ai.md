This is the second patch in a two-part series improving shell path detection in Meson builds, specifically addressing reliability issues when build and target host environments differ. The patch modifies the shell detection logic to prefer the POSIX-specified `/bin/sh` path over PATH-based lookups, which solves real-world problems encountered at GitLab and Debian where Git would fail to find its shell due to environment differences.

The change is minimal (just 1 line modified in meson.build) but strategically important - it appends `/bin` to the search path for the target shell while maintaining user configurability via `-Dsane_tool_path=`. The patch explains the rationale clearly: PATH lookups can lead to subtly broken Git distributions when build and target hosts have different shell locations, while `/bin/sh` is guaranteed by POSIX. The solution preserves backward compatibility by keeping the existing program path configuration while adding the POSIX path as a fallback.

This completes the series that began with diagnostic improvements in patch 1 (showing detected paths in build output). Together they address a specific cross-platform build pain point with a surgical change that follows Git's pattern of minimal, well-motivated build system improvements.
