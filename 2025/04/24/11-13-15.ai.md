This is a UX refinement discussion for the Meson benchmark integration series, focusing on the handling of the `time` command dependency.

Junio Hamano responds to Patrick Steinhardt's proposal for handling the `time` command requirement in the Meson build system's benchmark support. The discussion clarifies that shell built-in `time` commands won't satisfy the requirement (which needs GNU time's specific features), and solidifies consensus around Patrick's feature option approach.

The proposed solution offers three states via `-Dbenchmarks=`:
- `auto` (default) - silently disables benchmarks if `time` is missing
- `enabled` - requires `time` and errors if missing
- `disabled` - explicitly turns off benchmarks

Junio explicitly endorses this approach as sensible, noting it balances convenience (most developers won't run benchmarks) with strictness when explicitly requested. This resolves the final UX question in the series, with all technical implementation already complete. The thread shows clear technical consensus, leaving only documentation updates and minor CI issues (header checking and Windows asyncio problems) as remaining work items.
