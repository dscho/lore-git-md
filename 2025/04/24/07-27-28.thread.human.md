Here's the updated human-readable thread summary:

Lars Eriksen reported a regression in Git for Windows 2.49.0 where HTTP/2 support disappeared, breaking authentication against corporate backends that require it. This worked in version 2.39.0.windows.2, and the reporter can't install alternative cURL versions due to corporate restrictions. Initial investigation showed the system had libcurl 8.12.1 and OpenSSL 3.2.4 but no HTTP/2 capability.

Johannes Schindelin (Git for Windows maintainer) has now explained the root cause: Git for Windows ships with two cURL builds - one using OpenSSL (with HTTP/2) and another using Windows' Secure Channel (without HTTP/2). The behavior depends on which SSL backend is configured. He provided specific build logs showing the HTTP/2 capability difference and asked the reporter to test setting `http.sslBackend = openssl` as a potential workaround. Johannes also suggested improving the bug report template to include the SSL backend configuration from `/etc/install-options.txt` to help diagnose similar issues faster in the future.

The thread remains open while waiting for confirmation whether the OpenSSL backend workaround resolves the issue for Lars. If it does, this would point to a documentation need around SSL backend selection rather than a code-level regression.
