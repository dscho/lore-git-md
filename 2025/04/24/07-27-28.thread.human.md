This thread began as a bug report about HTTP/2 support regressions in Git for Windows 2.49.0, with Lars Eriksen reporting issues with both Git's internal HTTP operations and the standalone `curl.exe` bundled with the distribution. Johannes Schindelin, the Git for Windows maintainer, clarified that while the internal Git operations' HTTP/2 support depends on the SSL backend configuration (`http.sslBackend=openssl` works, `schannel` does not), the bundled `curl.exe` is intentionally limited as it's considered a dependency rather than a supported feature.

The discussion revealed a philosophical divide about the project's responsibility for bundled tools, with Johannes maintaining that users needing full `curl` functionality should use system versions or MSYS2, while Lars highlighted corporate environment constraints that make alternative installations difficult. The thread has now reached a practical resolution, with Lars reporting they've worked around the issue by having their server team install a separately built `curl` executable, though this required organizational intervention. While this addresses Lars' immediate needs, the broader questions about the scope of bundled tools in Git for Windows remain open, with the maintainer's position unchanged. The case illustrates the tension between user expectations and maintainer priorities in distribution packaging decisions.
