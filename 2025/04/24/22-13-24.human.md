This is a bug report about credential prompting behavior during Git LFS operations. Tom S reports that when cloning an HTTPS repository that uses Git LFS, a second credential prompt appears but gets partially obscured by progress output, making it easy to miss. The prompt only becomes visible after typing a username, which could lead to failed clones if users don't realize they need to provide credentials again.

The issue occurs specifically during the "Updating files" phase of the clone, where the LFS objects would be fetched. While the credentials do work when provided, the poor visibility of the prompt creates a poor user experience. The reporter suggests that such prompts should appear on their own line without being overwritten by other output.

This appears to be a UI/UX issue in Git's interaction with credential helpers during LFS operations, though the core functionality works correctly once credentials are provided. The report includes detailed reproduction steps and environment information (Git 2.49.0 on Fedora 42 with Gnome Terminal and tmux), making it easy to investigate. The behavior seems particularly problematic for automated or headless environments where obscured prompts could cause silent failures.
