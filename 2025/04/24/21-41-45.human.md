This is a bugfix patch addressing `git index-pack`'s overly strict cycle detection in REF_DELTA chains, completing a series that has undergone several rounds of review. The patch modifies the delta resolution algorithm to properly handle cases where REF_DELTAs point to bases existing locally, fixing false cycle detection failures.

The core change allows valid REF_DELTA chains (A->B->C where B and C exist in the client repo) to be processed correctly while still preventing actual cycles. Derrick Stolee asserts the resulting packfiles will remain cycle-free since REF_DELTAs are forbidden in the on-disk format. Junio Hamano raises important security considerations, questioning how the loosened checks would still protect against malicious packdata containing unresolvable cycles.

The discussion shows careful balancing between fixing legitimate cases and maintaining security guarantees. The patch builds on earlier work that added test infrastructure (a `test-tool pack-deltas` helper) and test cases demonstrating the issue. While the technical solution appears sound, Junio's probing questions suggest the security implications may need further explanation or verification before final acceptance.
