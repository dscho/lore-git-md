CI/build system patch to make Git's CI more resilient to external dependency failures. This is an immediate fix for an ongoing outage affecting JGit downloads from repo.eclipse.org, but the changes apply more broadly to all optional dependencies in the CI setup.

The patch modifies `ci/install-dependencies.sh` to gracefully handle failures when downloading Perforce, Git-LFS, and JGit binaries. Previously, the script would fail completely due to `set -e` if any download failed, even though the test suite is designed to skip tests when these optional tools are unavailable. The new version continues with a warning when downloads fail, properly cleaning up partial downloads and matching the test suite's existing fallback behavior.

Junio Hamano notes this is particularly important for JGit, where a failed download could still pass the `type jgit` check but then fail when actually running `jgit version`. The changes are minimal but carefully handle cleanup after failures while maintaining the same successful path behavior.

This appears ready for immediate merging as it addresses a real CI outage with a straightforward solution. The patch follows existing patterns in the code and includes proper cleanup for all three optional dependencies. While the immediate motivation is the JGit outage, the change improves CI robustness more generally by properly treating these as optional components.
