This is a follow-up in the Meson benchmark integration thread, specifically addressing Junio Hamano's question about shell built-in `time` commands. Patrick Steinhardt confirms that the implementation intentionally excludes shell built-ins, requiring GNU `time`` specifically for its richer output capabilities. He notes this matches the existing `USR_BIN_TIME` prerequisite in the test infrastructure, though observes this is currently only used by one test.

The email reveals two technical details: first, that the Meson implementation maintains the same GNU `time` requirement as the existing test infrastructure, and second, that there's potential (though low-priority) to refactor the `USR_BIN_TIME` prerequisite to be more portable. Patrick seems ambivalent about whether this refactor is worth the effort given its limited current usage.

This response solidifies the technical rationale behind the GNU `time` requirement while leaving open a minor implementation detail about test prerequisites. The core consensus from earlier in the thread remains unchanged - the feature option approach for `time` command handling has maintainer approval and this email simply clarifies one of its technical constraints.
