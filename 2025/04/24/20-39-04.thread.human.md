This thread has evolved into a deep technical discussion about how Git's `fast-export`/`fast-import` should handle signatures during the SHA-1 to SHA-256 hash transition. The core challenge is properly representing signatures that may exist for both hash versions of the same commit, while maintaining cryptographic correctness.

The current implementation (v4 patch from Christian Couder) introduces explicit syntax (`gpgsig <hash-algo> <format>`) to distinguish between signatures for different hash versions and formats (OpenPGP/X.509/SSH). While this seemed overly complex to some initially, Elijah Newren's latest analysis - informed by direct discussion with brian m. carlson - confirms the technical necessity. Signatures can legitimately exist for both SHA-1 and SHA-256 versions of a commit, not just matching the commit's own hash format, and the metadata helps tools process them correctly.

Key technical takeaways:
- The implementation must handle signatures for compatibility objects (SHA-1 versions of SHA-256 commits and vice versa)
- Signature format metadata, while derivable from the signature itself, provides important context for tools
- Current Git limitations mean only one signature per hash algorithm is supported
- Fast-import will need repository-specific handling based on the target repo's hash algorithm

Open questions center on documentation clarity and test coverage, particularly for dual-signature scenarios. The discussion has revealed the problem's complexity goes beyond initial assumptions, with cryptographic requirements driving much of the design. While some (like Newren) initially advocated for a simpler passthrough approach, the technical realities of hash transition compatibility appear to justify the current implementation's complexity.

Junio Hamano continues to mark this as experimental while emphasizing the need for precise tests and clear technical ownership of design decisions. The thread shows how Git's hash transition affects even seemingly peripheral features like signature handling in unexpected ways.
