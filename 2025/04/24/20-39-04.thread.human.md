This thread continues the discussion about improving signature handling in Git's `fast-export` and `fast-import` commands, focusing on how to properly represent cryptographic signatures when moving commits between repositories. The current implementation, now at version 4 of the patch series, introduces explicit syntax ("gpgsig <hash-algo> <format>") to distinguish between Git's object hash algorithms (SHA-1/SHA-256) and signature formats (OpenPGP/X.509/SSH).

Christian Couder has responded to Elijah Newren's critique of the design's complexity, defending the approach by citing brian m. carlson's technical guidance about properly separating hash algorithms from signature protocols. The additional metadata fields aim to make the format more parseable for tools while correctly reconstructing signature headers during import. However, Newren's concerns about over-engineering remain unresolved, particularly regarding whether simpler passthrough of raw data might suffice.

Key open questions center on the value of the extra metadata versus implementation complexity, how to test commits with both SHA-1 and SHA-256 signatures, and whether Git's general signature handling should dictate the export format. While Couder-brian axis favors the explicit format for technical correctness, Newren advocates for simplicity. Junio Hamano has flagged the need for more precise test assertions, and the lack of dual-signature test cases remains a notable gap. The discussion has reached an architectural crossroads, with the next steps likely involving either stronger justification for the current design or simplification in response to Newren's feedback.
