This thread has been exploring how Git's `fast-export` and `fast-import` commands should handle cryptographic signatures, particularly in repositories using both SHA-1 and SHA-256 hash algorithms. The technical discussion has progressed through several iterations, with Christian Couder leading the implementation of a format that explicitly tracks both the Git object hash algorithm and the signature protocol's internal format (like OpenPGP or X.509). The current design allows handling multiple signatures on a single commit while maintaining backward compatibility.

The debate has centered on whether this metadata-rich approach is necessary versus a simpler "passthrough" method that would just preserve the signatures without interpreting them. Christian has defended the current design by citing cryptographic best practices from brian m. carlson, while Elijah Newren has advocated for simplification. Test coverage, particularly for commits with multiple signatures, remains incomplete.

Junio Hamano, as maintainer, has now weighed in with process guidance, reminding contributors that while technical input from experts like brian is valuable, patch submitters should fully understand and be able to explain their design choices independently. He's keeping the feature marked as experimental while this discussion continues. The thread is at a point where the technical direction needs either clearer justification or simplification before the implementation can be finalized. Key next steps include completing the test cases and resolving whether the additional metadata provides enough value to justify the implementation complexity.
