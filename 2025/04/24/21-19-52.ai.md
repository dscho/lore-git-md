This is a follow-up patch in the signature handling thread, addressing feedback on the recently merged signed commit support in `git fast-export`/`git fast-import`. The patch improves signature algorithm name handling by:

1. Making `fast-export` properly identify signature types (OpenPGP, X.509, SSH) using gpg-interface functions rather than defaulting to "sha1"
2. Having `fast-import` validate algorithm names while preserving unknown ones with warnings
3. Updating documentation to clearly enumerate supported signature types
4. Maintaining backward compatibility while improving accuracy

Junio raises several technical concerns in the review:
- Questions why sha256 remains special-cased while sha1 is now handled generically
- Expresses concern about backward compatibility with existing fast-export streams that used "sha1" algorithm names
- Notes potential line length issues in the fast-export.c changes
- Suggests improving documentation consistency by either listing all algorithms or cross-referencing between documents

The patch appears technically sound but needs clarification on the sha1/sha256 handling strategy and backward compatibility implications. The discussion suggests this may need another revision to fully address these concerns before merging.
