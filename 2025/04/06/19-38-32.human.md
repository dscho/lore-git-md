This is a build system documentation patch in a larger series about Makefile/meson alignment. It adds a clarifying note about `NO_STRLCPY` configuration for Linux systems in `config.mak.uname`.

Ramsay Jones explains that while modern Linux distributions (Ubuntu 24.04, RHEL 10 beta) with glibc 2.38+ now include `strlcpy()` natively, older supported distributions still need Git's compatibility version. The patch adds a comment prompting Makefile users to override `NO_STRLCPY` in their local config if they're on a newer system, since meson/autoconf builds will automatically detect the system's `strlcpy` while Make builds default to the compat version.

This is a small but thoughtful addition to the ongoing build system modernization effort, helping users avoid unnecessary compatibility code when their system already provides the function. The change is straightforward and well-explained, though it might have been worth mentioning whether there are any plans to make the Makefile build automatically detect this like meson does.
