This is a bugfix patch in the build system alignment series, specifically addressing RAM calculation in `git gc` when using `sysinfo()` on Cygwin. The patch corrects the `total_ram()` function in `builtin/gc.c` to properly handle systems where memory sizes are reported in multiples of `mem_unit` rather than bytes.

The key technical details are:
- The current implementation assumes `sysinfo()` always reports memory sizes in bytes (or that `mem_unit` is 1)
- Cygwin's implementation uses `mem_unit=4096`, causing incorrect RAM calculations
- The fix multiplies `totalram` by `mem_unit` when the latter is greater than 1
- The change maintains backward compatibility with Linux systems where `mem_unit=1
- The commit includes test results showing Cygwin reporting correct 8GB RAM after the fix (though slightly less than actual due to system overhead)

This is a straightforward platform-specific correction that aligns behavior between Linux and Cygwin builds. The change is minimal (7 lines added, 2 changed) and well-justified by the test results shown in the commit message. As part of the larger build system series, it helps ensure consistent behavior across platforms for memory-sensitive operations like garbage collection.
