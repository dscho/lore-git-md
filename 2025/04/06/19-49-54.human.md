**Build system fix with meson quoting issue**

This is a follow-up in the build system alignment series, specifically addressing patch 3/13 which aimed to make meson build variables more minimal by only setting them for non-default values. Ramsay Jones identifies a significant problem with the implementation: it fails to properly handle values containing quotes, backslashes, or spaces, which are common in real-world editor/pager paths (like `"C:\Program Files\Vim\gvim.exe" --nofork`).

The issue manifests when comparing meson's behavior to the Makefile build, which correctly escapes such paths. The meson version currently produces malformed compiler arguments (e.g., breaking quoted Windows paths into separate tokens) and inconsistently converts path separators in documentation generation. Jones spent considerable effort trying to fix this but hit meson's limitations in handling quoted values, prompting a call for meson experts to intervene.

This isn't just theoretical — it directly impacts Windows users with spaces in their editor paths. While the rest of the series progresses well, this particular change needs reworking before it can safely land. The thread context shows this is part of a broader effort to align Makefile and meson behaviors, making the fix important for cross-platform consistency.
