This is a platform compatibility patch that completes the build system alignment series by standardizing cryptographic random number generation (CSPRNG) method selection between Makefile and meson builds on Linux.

The patch sets `CSPRNG_METHOD = getrandom` in the Linux section of `config.mak.uname`, bringing Makefile builds in line with meson's behavior. The commit explains that while newer Linux distributions could technically use `arc4random` (available since glibc 2.36), there's no performance benefit on Linux since all methods ultimately use the same kernel syscall. The `getrandom` choice is preferred for broader compatibility, working on all supported distributions (glibc ≥2.25).

Key technical details include: Linux's three available CSPRNG backends (`arc4random`, `getrandom`, `getentropy`) all map to the same kernel interface, unlike BSD/Cygwin where `arc4random` provides userspace ChaCha20 implementation. The change affects non-hot-path usage in `csprng_bytes()` helper introduced in 2022. The patch maintains consistency with the series' theme of platform-specific configuration while avoiding functional changes to Linux behavior.

This appears to be a well-justified, minimal change that completes the series' CSPRNG standardization work after the earlier Cygwin arc4random enablement (12/13). The commit message thoroughly documents the rationale and version compatibility considerations.
