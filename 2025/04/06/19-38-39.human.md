Platform compatibility patch (13/13 in series) standardizing cryptographic random number generation on Linux builds. This final patch in Ramsay Jones's build system alignment series addresses a discrepancy between Makefile and meson builds regarding CSPRNG backend selection.

The change sets `CSPRNG_METHOD = getrandom` for Linux in `config.mak.uname`, matching the behavior already implemented in meson builds. The commit explains that while newer Linux distributions could use `arc4random` (available since glibc 2.36), `getrandom` (available since 2.25) offers wider compatibility across currently supported distributions with no performance penalty, since all Linux implementations ultimately use the same kernel syscall.

The patch maintains consistency with the series' theme of platform-specific configuration while resolving a minor build system divergence. The change is low-risk as the CSPRNG usage isn't in performance-critical paths, and the rationale clearly weighs compatibility over theoretical advantages. This completes the series' work on Cygwin and Linux platform support modernization.
