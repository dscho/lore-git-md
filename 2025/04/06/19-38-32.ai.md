Build system documentation update regarding strlcpy compatibility on Linux. This patch adds a comment to `config.mak.uname` explaining that users building with make on Linux systems with glibc ≥2.38 (which now provides strlcpy) should override the default `NO_STRLCPY` setting in their local `config.mak`. 

The change acknowledges that while newer distributions (like Ubuntu 24.04 and RHEL 10 beta) have the system strlcpy, older supported versions still need Git's compat implementation. The note highlights an inconsistency where meson/autoconf builds automatically detect and use the system strlcpy when available, while the make build defaults to the compat version unless manually configured. 

This is part of Ramsay Jones' larger build system alignment series (now at v2 06/13) that modernizes platform-specific configurations. The change is purely documentation - it doesn't modify behavior but helps users understand when they might want to adjust the build configuration. The commit references historical context (2006's strlcpy adoption) and recent glibc changes (2023's strlcpy addition in v2.38).
