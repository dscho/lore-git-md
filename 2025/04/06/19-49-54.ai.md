Build system alignment issue in meson configuration for editor/pager paths. This is a follow-up to patch 3/13 in the build system alignment series, where Ramsay Jones identifies a significant limitation in the meson build system's handling of complex default editor/pager paths containing quotes or backslashes.

The core problem lies in how meson processes and passes through quoted strings containing special characters (', ", \) when setting DEFAULT_EDITOR and DEFAULT_PAGER. While simple values like 'vim' work fine, Windows-style configurations with spaces and quotes (e.g., "C:\Program Files\Vim\gvim.exe" --nofork") break compilation due to improper string escaping. The meson implementation currently cannot match the Makefile's robust handling of such cases.

Key technical details:
- Makefile correctly escapes paths with backslashes and quotes (converting \\ to / for asciidoc)
- Meson passes the raw string without proper escaping, leading to empty string interpretation
- Directory separators are inconsistently handled between build systems
- The issue affects both compilation (-DDEFAULT_EDITOR) and documentation generation (-a git-default-editor)

This appears to be a genuine meson limitation rather than an implementation error in the patch. Ramsay notes extensive but unsuccessful attempts to solve it, suggesting the need for meson expertise to properly handle Windows path quoting scenarios. The problem doesn't block the series but highlights an important functional gap in meson's path handling compared to the Makefile system.
