This thread began with a proposal to make `blame.ignoreRevsFile` more forgiving when specified configuration files don't exist, currently causing blame to fail. The original patch took a blame-specific approach, but Junio C Hamano objected, arguing for a general solution instead. 

The discussion has now shifted to considering a Git-wide `:(optional)` prefix mechanism for file paths, which Eric Sunshine notes was previously implemented in Junio's "seen" branch but dropped due to lack of review rather than technical issues. This historical context suggests the approach is viable and could be revived. 

Key open questions remain about how to implement this generally - through the parse-options API for command-line flags and git_config_pathname() for configurations - while maintaining strict checking by default. The thread has effectively moved from a specific blame usability issue to designing infrastructure that could benefit many Git commands needing optional file handling. With evidence that the core idea has already been prototyped, the path forward may involve resurrecting and refining that earlier work.
