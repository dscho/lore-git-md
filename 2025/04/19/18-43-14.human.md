This is a bugfix patch for `git blame`'s related to the handling of ignore-revs files. The current behavior exits with an error if a file specified in `blame.ignoreRevsFile` doesn't exist, which makes it problematic to use this config option for optional ignore files (like GitHub's standard `.git-blame-ignore-revs`). 

The patch changes the behavior to silently skip nonexistent files when they're specified in the config (while still erroring for command-line specified files). This maintains backward compatibility while solving the practical use case of having optional ignore files. The implementation splits the ignore file handling into two paths - one for config-specified files (which can be missing) and one for command-line files (which must exist).

The changes include documentation updates, core logic changes in `builtin/blame.c`, a new `oidset_parse_filep_carefully()` function to handle already-opened files, and a new test case. The patch appears well-structured with clear commit message explaining the motivation and implementation approach.
