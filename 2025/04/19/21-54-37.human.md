This is a response to a bugfix patch about `blame.ignoreRevsFile` behavior, where Junio C Hamano provides substantial feedback on the proposed solution. The original patch aimed to make config-specified ignore files optional while keeping command-line files mandatory, addressing a real-world use case where global configs might not apply to all repositories.

Junio acknowledges the problem but rejects the current implementation for several reasons: it duplicates code, removes existing typo protection without opt-in, creates inconsistency between config and command-line handling, and doesn't solve the general case of optional paths in Git. He suggests a more comprehensive approach using a `:(optional)` prefix that could work across all Git commands and configs, proposing updates to `parse-options.c` and `git_config_pathname()`.

The response indicates this patch needs significant redesign to be acceptable, moving from a blame-specific solution to a more general Git mechanism for handling optional paths. This will likely require more discussion about the proposed `:(optional)` syntax and its implementation details.
