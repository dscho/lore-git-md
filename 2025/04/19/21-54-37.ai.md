This is a response to the initial bugfix patch about `blame.ignoreRevsFile` behavior, proposing an alternative design approach. Junio C Hamano rejects the current implementation's approach of treating config-specified files differently from command-line files, citing several concerns:

1. The patch duplicates file-processing logic unnecessarily
2. It removes existing typo protection without opt-in mechanism
3. Creates inconsistency between config and command-line handling
4. The optional-file need isn't blame-specific and deserves a general solution

The counter-proposal suggests a unified syntax for marking files as optional across Git:
- Prefix paths with `:(optional)` in both command-line options and config
- Would work automatically for all parse-options commands via OPTION_FILENAME updates
- Would extend to config variables via git_config_pathname() changes
- Maintains strict checking by default while allowing explicit opt-in to lenient behavior

The response indicates this is a broader design problem that shouldn't be solved piecemeal in the blame command alone. The suggested approach would provide a consistent mechanism applicable to any Git command or config that accepts file paths, while preserving the existing strict checking behavior by default. This positions the issue as requiring infrastructure-level changes rather than a blame-specific fix.
