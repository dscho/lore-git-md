This is a refactoring patch in Patrick Steinhardt's ongoing object storage modularization series (v3, patch 3/10). It moves the platform-agnostic `git_open_cloexec()` function from object-file.c to compat/open.c, where it better belongs alongside other compatibility wrappers.

The change makes logical sense - `git_open_cloexec()` is a general file-opening utility that happens to be used by the object subsystem, not something inherently object-specific. The patch also makes the function available unconditionally rather than only when OPEN_RETURNS_EINTR is defined, while keeping the EINTR-specific retry logic conditionally compiled.

The implementation is clean and thorough, updating all build systems (Makefile, meson.build) and removing now-unnecessary includes of object-file.h from several files that only needed it for this function. This continues the series' trend of carefully separating concerns between subsystems while maintaining all existing behavior.

As part of a larger refactoring effort that has already addressed all prior architectural feedback, this change appears non-controversial and well-executed. It helps advance the goal of better organized, more modular code while touching only the expected set of files.
