This is a bug report about email header compatibility in `git send-email`. The reporter, windowsair, has found that since Git v2.41.0, their email provider (exmail.qq.com) corrupts the Message-ID header when it's formatted as "Message-ID" (the RFC2822-compliant spelling) rather than the previously used "Message-Id".

The issue manifests as the email server prepending extra characters to the Message-ID, making it look like "<C627A112429DDE18+20250415123427.20834-3-dev@airkyi.com>" instead of the clean "<20250415123238.17341-3-dev@airkyi.com>" format that worked before. The reporter traces this to commit 647a2bb3ffc0 which standardized the header capitalization to match RFC2822.

This appears to be a server-side compatibility issue rather than a Git bug per se, but it's worth documenting as it could affect others using the same email provider. The reporter isn't proposing a fix, just raising awareness of the behavioral difference. The report is clear and well-documented with before/after examples, though it doesn't include steps to reproduce or test coverage.
