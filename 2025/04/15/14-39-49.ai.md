This is a bug report about email header compatibility issues with `git send-email`. The reporter, windowsair, identifies a problem where certain email servers (specifically exmail.qq.com) modify the Message-ID header when it uses the RFC2822-compliant "Message-ID" capitalization introduced in Git v2.41.0, while leaving it unchanged when using the non-standard "Message-Id" form from earlier versions.

The issue stems from commit 647a2bb3ffc0 which standardized the header capitalization to match RFC2822. The reporter shows examples of corrupted vs. intact Message-IDs, demonstrating that their email provider alters the ID when the standardized form is used. This appears to be a server-side compatibility issue rather than a Git bug per se, but it's notable as it affects email threading and tracking.

The email serves primarily as documentation of this edge case rather than proposing a fix. The reporter doesn't suggest reverting the RFC compliance change or adding workarounds, but rather wants to record the behavior for others who might encounter it. This could be useful context if similar reports surface from users of the same email provider.

Key technical details for future reference: the problematic commit is 647a2bb3ffc0, the affected field is the Message-ID header capitalization, and the issue manifests specifically with exmail.qq.com's email servers. The behavior change occurred in Git v2.41.0 when the project standardized on RFC2822 header formatting.
