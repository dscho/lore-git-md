This is a discussion thread in the ongoing build system alignment series, specifically about Cygwin regex compatibility. 

Patrick Steinhardt and Ramsay Jones are discussing whether to maintain support for very old Cygwin versions (pre-2.0 from 2015) in the Git build system. The current patch would limit the `NO_REGEX` flag to only Cygwin 1.7, but Ramsay indicates he has a more aggressive patch ready that would drop all pre-2.x Cygwin support entirely. 

The discussion reveals that Cygwin's regex implementation has improved significantly since version 2.0 (now passing most tests), though there remains one test case (t7815.12 involving NUL character matching) that still fails and would need to be skipped on Cygwin. Both contributors seem to defer the decision about dropping old Cygwin versions to Adam Dinwoodie, the series author.

This exchange shows the careful consideration being given to backward compatibility versus maintenance burden in the build system work. The technical details are well understood (regex test behavior across Cygwin versions), but there's a policy question about how far back to support that's being deliberately left for the series maintainer to decide.
