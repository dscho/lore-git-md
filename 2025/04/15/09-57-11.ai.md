This is the final patch in Eric Wong's series to make Perl optional, specifically targeting the command list generation in documentation builds. Patrick Steinhardt contributes this conversion of `cmd-list.perl` to a shell script (`cmd-list.sh`), completing the documentation system's independence from Perl.

The new shell implementation maintains identical functionality to the Perl version, extracting command names, manpage sections, and descriptions from `.adoc` files to generate categorized command lists for git(1). Key technical aspects include:
- Preserves the same output format (`linkgit:name[section]:: description`)
- Handles deprecated command markers identically
- Uses shell I/O redirection and pattern matching instead of Perl's File::Compare
- Updates both Makefile and meson build systems to use the new script

The conversion comes with a performance tradeoff - benchmarks show the shell version is about 7x slower (74ms vs 10ms). However, the patch argues this is acceptable since documentation builds are infrequent and the benefit of removing a Perl dependency outweighs the minor build-time penalty. The change also updates `meson.build` to no longer require Perl just for documentation builds, though Perl remains required for gitweb and netrc credential helper functionality.

This patch fits cleanly into the series' overall goal of eliminating mandatory Perl dependencies, following similar conversions of `git-filter-branch` and `git-request-pull`. The implementation appears thorough, maintaining all existing behavior while using more portable shell constructs. The performance impact is clearly measured and justified in the commit message.
