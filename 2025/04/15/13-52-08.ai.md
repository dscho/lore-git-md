Maintainer response to Python merge bug report.

Junio Hamano explains that the reported behavior where Git misplaces a Python method during merge is actually expected, though unfortunate. He clarifies that Git's line-based merge algorithm is language-agnostic and operates without understanding Python's class structure. The issue occurs because the merge anchor points (the blank line after User class definition) changed between branches, leaving Git with only the post-context anchor (Product class) to position the method addition.

Key technical points:
- Merge was asked to replay feature1's changes (adding user_method) on feature2's state
- Feature2 removed the blank line that served as pre-context anchor
- Git only had the Product class lines as reliable post-context
- The algorithm chose what it considered the "most natural" position given the available anchors

This response suggests the behavior is working as designed rather than being a bug, though the outcome is clearly wrong from a Python semantics perspective. The explanation implies this is fundamental to Git's merge approach rather than something easily fixed without language-specific merging support. No solutions or workarounds are proposed, but the maintainer's framing suggests this would require significant changes to Git's merge machinery to handle properly.
