This is the third patch in Patrick Steinhardt's v2 series hardening integer handling in Git's parse-options infrastructure, specifically focusing on `OPTION_MAGNITUDE` precision handling. The patch mirrors the approach taken for `OPTION_INTEGER` in the previous patch, applying similar type safety improvements to magnitude options.

The key technical changes introduce precision-aware parsing for magnitude options, with:
- Range checking based on the specified precision (1/2/4/8 bytes)
- Proper handling of unsigned values with new upper bound calculations
- Type-safe storage into the correct sized variable (uint8_t/16_t/32_t/64_t)
- New test cases for 16-bit magnitude options and range validation

The implementation maintains backward compatibility while adding safety through:
- The same precision field mechanism introduced in patch 2/5
- Careful handling of unset/optional cases
- Clear error messages for out-of-range values
- New test coverage in t0040-parse-options.sh

This continues the series' systematic approach to type safety, with `OPTION_MAGNITUDE` now receiving the same precision handling as `OPTION_INTEGER`. The patch demonstrates good test coverage and maintains the series' architectural consistency while addressing a distinct but related option type.
