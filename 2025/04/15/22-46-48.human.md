This is a refactoring patch that's part of Taylor Blau's performance optimization series for MIDX and cruft pack interaction during repacking (v3, 1/9).

The patch standardizes how `pack-objects` handles incompatible command-line options by replacing several custom error checks with calls to the shared `die_for_incompatible_opt2()` function. This change makes the code more consistent with Git's standard practices for option validation and ensures uniform formatting of error messages across different incompatible option pairs.

The refactoring touches option checks like `--exclude-promisor-objects` vs `--exclude-promisor-objects-best-effort`, `--keep-unreachable` vs `--unpack-unreachable`, and `--stdin-packs` vs `--filter`. One test in t5331 had to be updated to expect the new standardized error message format.

As the first patch in a larger series, this appears to be preparatory work that cleans up the codebase before introducing new functionality in later patches. The changes are straightforward and well-contained, with minimal test impact. The commit message clearly explains both the motivation (standardizing error handling) and the implementation approach.
