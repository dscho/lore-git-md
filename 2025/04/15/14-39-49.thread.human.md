This thread documents a compatibility issue with `git send-email` when using certain email providers, particularly exmail.qq.com. The problem stems from Git's move to RFC2822-compliant header capitalization in v2.41.0 (commit 647a2bb3ffc0), where "Message-ID" (standard) replaced "Message-Id" (legacy). While this change was correct from a standards perspective, it unexpectedly breaks email threading on some servers - the qq.com provider modifies the standardized header while leaving the legacy form intact.

The reporter, windowsair, has provided clear examples showing how the Message-ID gets corrupted with the RFC-compliant form but remains usable with the old capitalization. This appears to be purely a server-side compatibility issue rather than a Git bug, but it's noteworthy as it affects email tracking and threading for users of these services. The thread currently serves as documentation of this edge case rather than proposing solutions, though it may inform future decisions if similar reports emerge from other providers.
