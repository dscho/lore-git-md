This is part 8/10 of Patrick Steinhardt's ongoing refactoring series to reorganize Git's object storage code. The patch moves several object store management functions from object.c to the new object-store.c file, continuing the architectural separation of concerns established in earlier patches.

The changes relocate core object store lifecycle functions including `raw_object_store_new()`, `free_object_directory()`, and `raw_object_store_clear()`. These handle initialization, cleanup, and memory management for Git's object storage subsystem. The patch also moves related helper functions and updates header includes accordingly.

This continues the series' pattern of logically grouping related functionality while maintaining all existing behavior. The changes are mechanical - no new functionality is introduced, just better organization. The patch builds on previous work that established object-store.c as the home for object storage management code, with object.c now focused more narrowly on object type handling.

As with earlier patches in the series, this appears to be a well-executed refactoring that advances the project's architectural goals. The changes are focused and the commit message clearly explains the motivation. This patch represents another incremental step in the larger effort to improve Git's internal code organization.
