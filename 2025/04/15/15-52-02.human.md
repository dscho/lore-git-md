This is a feature patch adding unsigned integer parsing to Git's option handling infrastructure, part of Patrick Steinhardt's series hardening numeric option parsing. The patch introduces `OPTION_UNSIGNED` as a middle ground between existing `OPTION_INTEGER` (signed) and `OPTION_MAGNITUDE` (unsigned with unit suffixes).

Phillip Wood's review acknowledges the usefulness of the addition but raises two concerns: negative values that parse as small positive numbers should be explicitly rejected (matching `git_parse_ulong()`'s behavior), and the patch needs to incorporate the overflow detection fix from patch 2/5 in the series. The implementation handles width-specific bounds checking (like rejecting 65536 for 16-bit values) and includes test coverage for the new type.

The change affects parse-options internals (adding 43 lines to the core parsing logic) while maintaining the existing API surface. It's a well-motivated addition to the option parsing toolkit, though the review points out some edge cases that should be addressed before finalizing.
