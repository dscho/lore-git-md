This is a technical discussion about virtual object storage in Git's ongoing libification effort, specifically addressing Junio Hamano's concerns about cross-repository sharing of cached objects.

Patrick Steinhardt responds to Junio's architectural question about whether virtual objects (used for operations like creating fake commits in git-blame) should be repository-specific or globally shared. He argues that making them repository-specific now provides more flexibility - while some future use cases might want global sharing, the current git-blame usage doesn't need it, and repository-specific storage would allow both approaches. 

The discussion highlights an important tension in the libification work: as Git moves away from global state (like `the_repository`), developers need to consider how functionality that was previously implicitly shared (like these virtual objects) should behave when multiple repository instances exist. Patrick acknowledges this will require more careful design as libification progresses, but believes the current change is safe since git-blame's usage is repository-local.

This exchange represents the kind of forward-looking architectural discussion that often happens during major refactoring efforts, where changes that are correct today need to be evaluated for how they'll interact with future capabilities. The patch itself seems sound for current needs while raising important questions about future design directions.
