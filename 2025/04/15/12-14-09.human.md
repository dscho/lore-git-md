Bugfix and type safety improvement for parse-options infrastructure. This final patch in Patrick Steinhardt's v2 series addresses a subtle but serious type mismatch issue in Git's option parsing. The problem was discovered when `--min-batch-size` in `git-backfill` failed on s390x and sparc64 systems due to incorrectly using `OPT_INTEGER()` with a `size_t` parameter instead of an `int`.

The patch introduces compile-time assertions (`BARF_UNLESS_SIGNED` and `BARF_UNLESS_UNSIGNED`) to catch such type mismatches early. It then updates several commands (`backfill`, `apply`, `column`, `grep`) that were passing unsigned variables to signed option parsers. The changes are straightforward - switching from `OPT_INTEGER` to `OPT_UNSIGNED` where appropriate.

This completes the series' goal of hardening integer handling in parse-options, building on earlier patches that added precision tracking and bounds checking. The solution is elegant, catching the root cause rather than just fixing symptoms, and the patch includes helpful context about the big-endian platforms where the issue manifested. The changes are well-contained and unlikely to be controversial given they fix actual bugs found in the wild.
