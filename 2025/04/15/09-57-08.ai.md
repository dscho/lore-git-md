Perl dependency removal in git-filter-branch's state-branch feature. This patch converts the Perl-based implementation of `--state-branch` functionality in `git-filter-branch` to pure shell scripting, addressing two specific issues with the current Perl usage: it bypasses the configured `PERL_PATH` and fails completely when Perl is unavailable.

The changes replace two Perl snippets that handle object ID mapping state:
1. State loading (reading `filter.map` from a previous run) now uses shell I/O redirection and string manipulation with `${line%:*}` and `${line#*:}` for parsing
2. State saving (writing new mappings) uses shell globbing and `git hash-object` piped input

Key technical details:
- Maintains identical file format (`from_commit:to_commit` lines in `filter.map`)
- Preserves all error handling (die on invalid format or I/O failures)
- Changes file handling from Perl's directory operations to shell glob (`../map/*`)
- Still uses same underlying Git plumbing (`git show`, `git hash-object`, `git mktree`)

This appears to be a straightforward conversion that maintains functionality while removing a Perl dependency, aligning with the series' goal. The patch is focused (only touching `git-filter-branch.sh`) and includes a clear commit message explaining both the problem and solution.
