Git mentoring programs and project-wide AI-spam guidelines discussion thread summary:

Christian Couder initially reported a surge in AI-generated spam proposals for Git's 2025 mentoring programs (GSoC/Outreachy), with 71 of 79 GSoC submissions being low-quality AI content. In response, mentors implemented anti-AI-spam guidelines documented in GitHub PR #771, linked from Git's General Application Information page, which have shown effectiveness in reducing spam volume for program applications.

Patrick Steinhardt has now weighed in on the discussion, responding to Christian's email about potentially expanding these guidelines project-wide. While acknowledging the success of the mentoring program-specific measures (where 90% of proposals were AI-generated spam this year), Patrick argues against broader implementation at this time. His position is based on the observation that the Git mailing list hasn't yet experienced problematic levels of AI-generated patches, making project-wide policies premature. However, he leaves open the possibility of reevaluation if the situation changes and invites alternative perspectives from other list participants.

The thread highlights two distinct contexts: the high-volume, low-quality mentoring program applications (where immediate action was necessary) versus the currently manageable flow of patches to the development list. The discussion remains open for others to contribute perspectives on whether Git should proactively establish AI content policies or maintain its current reactive approach. The GitHub PR (#771) containing the implemented mentoring program guidelines serves as a reference point for any future policy discussions.
