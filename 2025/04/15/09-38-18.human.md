This is part 5/10 in Patrick Steinhardt's v3 series refactoring Git's object storage subsystem. The patch splits out object store management functions from object-file.c into a new object-store.c file, continuing the architectural separation between low-level object I/O and higher-level storage management.

The change moves about 1000 lines of code while maintaining all existing functionality. Key functions relocated include:
- Alternate object database handling (prepare_alt_odb, link_alt_odb_entries)
- Object lookup and caching (oid_object_info_extended, pretend_object_file)
- Object existence checks (has_object, repo_has_object_file)
- Utility functions for object paths and temporary files

The patch updates 20 files to account for the new organization, mostly adjusting includes. This is a mechanical split that doesn't change behavior - it just moves code to better reflect the logical separation between the object-file layer (raw I/O operations) and object-store layer (storage management).

This continues the series' goal of modularizing Git's object storage by:
1. Keeping object-file.c focused on loose object I/O
2. Moving higher-level management to object-store.c
3. Better separating concerns between the two layers

The change is well-contained and builds on previous patches in the series that established this architectural split. It demonstrates careful attention to maintaining all existing behavior while improving code organization.
