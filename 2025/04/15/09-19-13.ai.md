This is a technical discussion about the placement of virtual objects in Git's object storage system, part of Patrick Steinhardt's refactoring series to eliminate global state. The email responds to Junio Hamano's concerns about cross-repository sharing of virtual objects (used for operations like creating fake commits in git-blame).

Patrick acknowledges Junio's point about potential issues when multiple repository instances are involved, particularly with submodules. He argues that while global sharing might be needed in some cases, making virtual objects repository-specific is more flexible since it allows both approaches (global sharing can be built on top if needed, but not vice versa). He notes that current usage in git-blame doesn't involve submodules, and if it did, separate fake commits per repository would likely be desired.

The discussion highlights an important architectural consideration emerging from the `the_repository` removal effort: as Git moves away from global state, developers will need to be more deliberate about handling multiple repository instances, particularly for features that might cross repository boundaries. Patrick views this as part of a broader challenge in Git's libification process that will need ongoing attention as more sophisticated use cases emerge.

Key technical points:
- Virtual objects moved from global array to raw object store
- Current usage limited to git-blame's fake working tree commits
- No current submodule interaction with this mechanism
- Future-proofing consideration: repository-specific storage allows both per-repo and global sharing patterns
- Part of larger `the_repository` elimination effort with implications for multi-repo handling

The exchange shows the series is progressing with careful consideration of edge cases, with this particular change being seen as safe for now while flagging important design questions for future work.
