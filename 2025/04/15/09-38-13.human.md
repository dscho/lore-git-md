This is a refactoring series that continues Patrick Steinhardt's work to split up the monolithic object-file.c into more focused subsystems. The v3 series incorporates feedback from previous discussions, particularly around function placement and naming.

The key changes in this version:
- Directory-related functions (`safe_create_leading_directories` and renamed `safe_create_dir_in_gitdir`) are now moved to path.c rather than dir.c, requiring repository parameterization
- The index-related functions that were controversial in v2 have been dropped from the series
- The virtual objects cache is now stored per-repository rather than globally, with expanded rationale about future flexibility
- The object-store headers have been consolidated

The series touches a massive 150 files, but the changes are largely mechanical movements of code between files with minimal behavior changes. The most notable behavioral impact is making virtual objects repository-specific rather than global, which better supports future libification efforts.

This appears to be a well-considered iteration that addresses previous feedback while maintaining the series' goals. The changes are clearly explained in the cover letter and commit messages, and the scope remains focused on code organization rather than introducing new functionality. The series seems ready for review, with the most discussion likely around the virtual objects cache changes.
