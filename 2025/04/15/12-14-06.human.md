This is the second patch in Patrick Steinhardt's v2 series hardening integer handling in Git's parse-options infrastructure. The patch focuses on improving precision handling for `OPTION_INTEGER` options to prevent integer overflow and out-of-bounds writes.

The key changes introduce a new `precision` field that tracks the size of integer values passed to options, allowing proper range checking. The patch converts the parsing logic from `strtol()` to `strtoimax()` to handle larger values, and adds bounds checking based on the declared precision. Several commands (`fmt-merge-msg`, `merge`, `show-branch`, `tag`) are updated to include the new precision field.

The implementation demonstrates careful attention to backward compatibility while adding safety checks. The test suite is expanded to verify the new bounds checking works correctly, including a new test case for 16-bit integers. This is a well-motivated change that addresses real potential issues in the option parsing code, though the impact is mostly internal (the user-facing behavior remains the same when values are in the expected ranges).

The patch builds on the foundational refactoring from part 1/5 and sets the stage for subsequent patches that will add signedness verification and unsigned integer support. The changes are well-contained and the commit message provides clear technical rationale for each modification.
