This is a technical discussion contribution about patch series tracking solutions, specifically comparing Change-ID and Patch Set ID approaches. Remo Senekowitsch raises concerns about Theodore Ts'o's proposed Patch Set ID mechanism, arguing it shares similar ambiguity problems to Change-IDs while being less flexible and more complex.

The email makes several key points: First, it questions whether Patch Set IDs truly solve the ambiguity problems they claim to address, noting they can still be affected by operations like cherry-picking between patch sets. Second, it suggests Change-IDs could serve as natural Patch Set IDs when used with cover letters, providing equivalent functionality without requiring new Git infrastructure. Third, it argues Change-IDs offer more tracking capability by allowing observation of individual commit evolution within a series.

Notable technical details include the cover letter's role in b4's workflow, the distinction between Git's native commit model versus proposed patch set concepts, and the specific operations (cherry-picking, squashing) that challenge both tracking approaches. The email positions Change-IDs as a more Git-native solution that could achieve similar ends without introducing new abstractions.

This contribution shifts the discussion toward workflow considerations and conceptual minimalism, challenging some assumptions about the Patch Set ID proposal's advantages. It introduces new evaluation criteria about what constitutes a "natural" extension to Git's model and questions whether the additional complexity of Patch Set IDs is justified given existing Change-ID capabilities. The arguments suggest deeper philosophical differences about how tightly patch tracking should be integrated into Git versus building on existing commit semantics.
