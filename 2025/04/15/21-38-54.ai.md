This is a feature proposal discussion about patch series tracking in Git, specifically comparing Change-ID and Patch Set ID approaches. Jacob Keller weighs in on Theodore Ts'o's earlier proposal for a Patch Set ID system, expressing support for treating patch series as single entities rather than individual reviews (as Gerrit does with Change-IDs).

Key technical points from this email:
- Keller prefers Ts'o's Patch Set ID approach where a series shares one ID, finding it more natural for workflow than Gerrit's per-commit Change-IDs
- Notes the "reverse hex" encoding suggestion from earlier in thread as a good visual distinguisher
- Observes that Ts'o's proposal would make singleton commits automatically get their commit ID as the patch set ID
- Suggests tooling could emerge to retroactively assign patch set IDs to existing branches

The email reinforces the technical direction Ts'o proposed while adding practical workflow perspective from Gerrit experience. It doesn't introduce new technical elements but provides validation of the Patch Set ID approach from a user perspective. The discussion continues to focus on balancing automated tracking with flexible workflow needs.
