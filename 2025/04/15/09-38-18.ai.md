This is part 5/10 of Patrick Steinhardt's v3 series refactoring Git's object storage subsystem, specifically splitting object store functionality from object-file.c into a new object-store.c file.

The patch moves all object store management functions from object-file.c to the new object-store.c, including:
- Alternate ODB handling (prepare_alt_odb, link_alt_odb_entries, etc.)
- Object lookup and caching (oid_object_info_extended, pretend_object_file)
- Object existence checks (has_object, repo_has_object_file)
- Object reading utilities (repo_read_object_file, read_object_with_reference)

Key technical details:
- Maintains all existing behavior while improving code organization
- object-file.c now focuses on loose object I/O
- object-store.c handles higher-level object store management
- Updates 20 files to include the correct headers
- Adds object-store.c to Makefile and meson.build
- Preserves all function signatures and behavior

The change follows the architectural decisions finalized in earlier patches of this series, continuing the separation of concerns between low-level object operations and object store management. This is part of the broader effort to modularize Git's object storage subsystem.

The patch-specific changes include moving ~1000 lines of code while maintaining exact behavior, with comprehensive updates to callers across builtins and other subsystems. This builds on previous patches in the series that relocated directory utilities to path.c and memory mapping functions to wrapper.c.
