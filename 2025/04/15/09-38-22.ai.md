This is part of Patrick Steinhardt's ongoing object storage refactoring series (v3 09/10), focusing on removing global state as part of the `the_repository` removal effort. The patch moves cached/virtual object storage from a global array to being repository-specific in the raw object store.

Key technical details:
- Removes global `cached_objects` array and moves storage to `raw_object_store` struct
- Updates `pretend_object_file()` to take repository parameter and use per-repo storage
- Modifies `find_cached_object()` to operate on a specific object store
- Adds proper cleanup in `raw_object_store_clear()`
- Updates blame.c caller to pass repository parameter
- Maintains all existing functionality while making it repository-aware

The commit message provides a thorough rationale for repository-specific storage, noting that while git-blame is currently the only user (creating fake working tree commits), this change enables future flexibility. It specifically considers hypothetical submodule scenarios, concluding per-repo storage would better support potential future cross-repo use cases while preventing surprising interactions between repositories in a libified context.

The implementation touches:
- object-store-ll.h (adds cached_object_entry to raw_object_store)
- object-store.c (moves implementation to use per-repo storage)
- blame.c (updates caller to pass repository parameter)

This continues the series' pattern of methodically eliminating global state while maintaining behavior, with all prior architectural decisions (like keeping index functions in object-file.c) remaining unchanged. The change is well-contained, updating only 3 files while comprehensively handling memory management and interface changes.
