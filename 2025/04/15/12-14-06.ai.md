This is the second patch in Patrick Steinhardt's v2 series hardening integer handling in Git's parse-options infrastructure. The patch introduces precision handling for `OPTION_INTEGER` to address several safety issues with the current parsing of integer options.

The key changes are:
- Adds a new `precision` field to track the size of integer values being passed (1, 2, 4 or 8 bytes)
- Uses `strtoimax()` instead of `strtol()` to properly handle values larger than `LONG_MAX`
- Implements range checking based on the precision to prevent integer overflows
- Updates callers to specify precision via `sizeof()` when using `OPT_INTEGER_F()`
- Adds tests for the new 16-bit integer option type and its range checking

The patch affects multiple builtin commands (`merge`, `tag`, `show-branch` etc.) that use integer options, though the behavior remains compatible. It's part of a systematic effort to make option parsing more type-safe, building on the v2 series' foundational refactoring to designated initializers. The implementation shows careful attention to backward compatibility while adding the new safety checks.
