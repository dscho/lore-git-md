This is part of Patrick Steinhardt's ongoing refactoring series to modularize Git's object storage system (v3 09/10). The patch moves cached/virtual objects from a global array to being repository-specific in the raw object store structure.

The change primarily affects git-blame's fake working tree commits, which use virtual objects to represent uncommitted changes without writing to disk. While the current implementation works globally, the patch argues that repository-specific storage is more future-proof - particularly for hypothetical cross-repository workflows and libification efforts. The commit notes this could matter if Git ever needs to handle submodule boundaries differently in blame operations.

The implementation:
- Adds cached object storage fields to `raw_object_store`
- Updates all related functions (`find_cached_object`, `pretend_object_file`) to take repository parameters
- Includes cleanup of cached objects during store teardown
- Modifies blame.c to use the new repository-aware interface

This continues the series' pattern of removing global state while maintaining existing behavior. The change is well-motivated and carefully implemented, with clear consideration of both current needs and future flexibility. As with earlier patches in the series, it advances Git's libification goals without introducing functional changes.
