Refactoring patch in Patrick Steinhardt's object storage modularization series (v3 04/10). This moves the `xmmap()` family of functions from object-file.c to wrapper.c, continuing the effort to better organize Git's codebase by subsystem.

The patch relocates three related functions: `xmmap()`, its gentler variant `xmmap_gently()`, and the error helper `mmap_os_err()`, along with their shared `mmap_limit_check()` helper. These are general-purpose memory mapping utilities that don't specifically relate to object storage, making wrapper.c (which already declares similar low-level utilities) a more logical home. The implementation remains unchanged - this is purely an organizational improvement.

This change follows the same pattern as previous patches in the series that moved other non-object-specific utilities (git_open_cloexec in 03/10, directory utilities earlier) to more appropriate homes. The move helps keep object-file.c focused on its core responsibility of loose object I/O while grouping platform-interfacing utilities together in wrapper.c.

Key technical details preserved in the move:
- The ENOMEM error message specialization for Linux systems
- The GIT_MMAP_LIMIT environment variable handling
- The gentle vs strict variants of the mapping function
- All existing call sites will continue working unchanged since the functions' signatures remain the same

This is a straightforward code reorganization with no behavior changes, continuing the series' trend of improving subsystem boundaries while advancing the broader `the_repository` removal effort through better code organization.
