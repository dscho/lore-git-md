This is the third patch in Patrick Steinhardt's v2 series hardening integer handling in Git's parse-options infrastructure, focusing on magnitude options. Following the same pattern as the previous patch for `OPTION_INTEGER`, it introduces precision handling for `OPTION_MAGNITUDE` to prevent overflow and ensure type safety.

The patch adds range checking for magnitude options (unsigned values with k/m/g suffixes) based on their declared precision (1, 2, 4, or 8 bytes). It includes tests for 16-bit magnitudes and verifies that values exceeding the type's maximum (like 65536 for uint16_t) are properly rejected. The implementation maintains backward compatibility while adding safety checks.

This continues the series' methodical approach to type safety, with similar benefits to the integer handling improvements in patch 2/5. The changes are well-contained to the parse-options machinery and include thorough test coverage, including edge cases. The patch appears technically sound and follows the established pattern from the previous work in the series.
