This is a discussion contribution to the ongoing thread about patch series tracking in Git, specifically comparing Change-ID and Patch Set ID approaches. Jacob Keller weighs in with a thoughtful analysis of the challenges in creating a unified solution that satisfies different workflows.

Keller acknowledges the complexity of the problem space, noting that different tools (Gerrit, GitButler, Jujutsu) have similar-but-not-identical needs for tracking commit evolution. He agrees with the thread's general direction toward a built-in Git solution but highlights the difficulty in designing something general enough to cover all use cases.

The email also responds to D. Ben Knoble's point about interdiffs potentially reducing the need for change IDs. While Keller agrees interdiffs are valuable for understanding commit evolution, he notes that implementing good web UI for them presents its own technical challenges, particularly around edge cases.

This contribution helps advance the discussion by validating the complexity of the problem while maintaining focus on practical implementation concerns. Keller's perspective as someone familiar with these systems lends weight to the emerging consensus around Theodore Ts'o's Patch Set ID proposal, though he doesn't explicitly endorse any particular solution in this message.
