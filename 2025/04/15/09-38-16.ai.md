This is a refactoring patch in Patrick Steinhardt's ongoing object storage modularization series (v3 03/10). The change moves the platform-agnostic `git_open_cloexec()` function from object-file.c to compat/open.c, where it better belongs with other cross-platform compatibility code.

The patch makes several technical adjustments:
1. Unconditionally compiles compat/open.c (previously conditional on OPEN_RETURNS_EINTR)
2. Wraps only the EINTR-specific `git_open_with_retry()` in conditional compilation
3. Updates build systems (Makefile, meson.build) to reflect the new compilation unit
4. Removes now-unnecessary object-file.h declarations and updates includes in several files that no longer need object-file.h just for this function

The change is part of the broader effort to better organize Git's code by moving functions to more logical locations. This particular move separates a general file-opening utility from object-specific code, following the architectural decisions established earlier in the series. The patch appears mechanically sound, with all build systems updated and no behavior changes beyond the intended relocation.
