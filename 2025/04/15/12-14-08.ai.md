This is patch 4/5 in Patrick Steinhardt's v2 series hardening integer handling in Git's parse-options infrastructure, introducing a new `OPTION_UNSIGNED` type for unsigned integer parsing without magnitude suffixes.

The patch adds a middle ground between existing `OPTION_INTEGER` (signed) and `OPTION_MAGNITUDE` (unsigned with k/m/g suffixes). The new type follows the same precision-based approach as previous patches, supporting 1/2/4/8 byte unsigned integers with proper bounds checking. Key implementation details include using `strtoumax()` for parsing, upper bound calculation based on precision, and type-safe storage into correctly sized variables.

The changes span parse-options.c/h with the core implementation, plus test updates in t/helper/test-parse-options.c and t/t0040-parse-options.sh. New test cases verify the 16-bit unsigned variant (`--u16`) handles values up to 65535 and rejects larger numbers. The patch maintains consistency with the series' architectural approach while filling a clear gap in the option parsing API.

This continues the methodical progression seen in patches 1-3, now providing the unsigned counterpart to the earlier signed integer improvements. The implementation appears thorough, with test coverage matching what was added for other numeric types in previous patches.
