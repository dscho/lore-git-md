This is a feature patch introducing unsigned integer parsing to Git's parse-options infrastructure, part of Patrick Steinhardt's v2 series hardening integer handling. The patch adds a new `OPTION_UNSIGNED` type to fill the gap between existing `OPTION_INTEGER` (signed) and `OPTION_MAGNITUDE` (unsigned with suffixes). 

Phillip Wood's review identifies two potential improvements: (1) negative values should be explicitly rejected (currently they may parse as large positive numbers for narrower types), and (2) the patch needs the same overflow detection fix from patch 2/5 (using `errno` checks with `strtoumax`). The implementation handles precision-aware parsing for 1/2/4/8-byte unsigned integers and includes comprehensive test coverage demonstrating range enforcement.

The patch follows the series' architectural approach of compile-time type safety while maintaining API compatibility. Phillip's feedback suggests tightening validation to match Git's existing `git_parse_ulong()` behavior for negative numbers, which would make the new unsigned option type more robust before finalizing the series.
