Feature addition to Git's parse-options infrastructure, introducing unsigned integer parsing.

This is the fourth patch in Patrick Steinhardt's v2 series hardening integer handling in Git's option parsing. It introduces a new `OPTION_UNSIGNED` type to fill a gap between the existing `OPTION_INTEGER` (signed) and `OPTION_MAGNITUDE` (unsigned with unit suffixes). The new type provides clean unsigned integer parsing without magnitude suffixes, maintaining the series' precision-aware approach with proper range checking.

The implementation follows the established pattern from previous patches, adding type-safe storage for 1/2/4/8 byte unsigned integers with bounds checking. Test coverage includes both successful parsing and proper error handling for out-of-range values. The patch is well-contained, touching only the parse-options subsystem and its tests, and maintains consistency with the series' architectural approach.

This appears to be a straightforward addition that completes the type system for numeric options, though some reviewers may want to discuss whether the magnitude suffix handling could be made optional rather than requiring a separate type. The implementation looks solid with comprehensive tests showing both the happy path and error cases.
