This is a bugfix and refactoring patch that removes Perl dependencies from `git filter-branch`'s `--state-branch` feature. It's part of Eric Wong's broader series to make Perl optional in Git, though this specific contribution comes from Patrick Steinhardt.

The patch addresses two concrete problems with the current Perl-based implementation: it doesn't respect the system's configured `PERL_PATH`, potentially using the wrong Perl version, and fails entirely when Perl isn't available. The solution replaces the Perl code with equivalent shell scripting that reads and writes the object ID mapping files directly.

The changes are straightforward - converting Perl file operations to shell equivalents while maintaining the same functionality. The new version uses basic shell constructs like `while read` loops and `case` statements to parse the map file, and replaces Perl's directory handling with shell globbing. The patch touches only `git-filter-branch.sh`, with 19 lines added and 18 removed.

This appears to be a clean, focused improvement that aligns with the series' goal of Perl removal. The commit message clearly explains the motivation and the changes preserve all existing behavior while removing a dependency. Since `git filter-branch` is already a shell script, this change makes it more self-contained.
