This is a platform compatibility discussion about Cygwin regex support in the ongoing build system alignment series. The email continues a thread about whether to maintain compatibility with Cygwin 1.7's broken regex implementation (which required NO_REGEX) or drop support for pre-2.0 Cygwin versions now that the platform's regex library has been fixed.

Ramsay Jones indicates he has a patch ready to remove all pre-v2.x Cygwin support entirely, noting Cygwin considers itself a rolling release distribution, but defers the decision to Adam Dinwoodie as maintainer. Patrick Steinhardt agrees dropping pre-2.0 support would be reasonable given Git's recent trend of dropping ancient platform versions, but is fine with postponing that decision.

Key technical context: The current patch (v2 07/13) makes NO_REGEX conditional on Cygwin 1.7 while adding a CYGWIN-specific skip for test t7815.12 (NUL character matching), which the modern Cygwin regex library fails despite passing other previously problematic tests. The discussion reveals deeper questions about how aggressively to prune legacy platform support, with Cygwin's rolling release model suggesting older versions may not need prolonged maintenance.
