This is part of Patrick Steinhardt's ongoing object storage refactoring series (v3 06/10), focusing on cleaning up flag usage in object-file operations. The patch disentangles the shared `HASH_*` flags that were being reused across `hash_object_file()`, `write_object_file()`, and `index_fd()` into separate, function-specific flag sets.

Key technical changes:
- Introduces new flag namespaces: `INDEX_*` for index-related functions, `WRITE_OBJECT_FILE_*` for write operations, and keeps `HASH_OBJECT_*` for hash-object specific flags
- Updates flag handling in 9 files including builtins (hash-object, replace, update-index), bulk-checkin, cache-tree, and notes-merge
- Maintains all existing behavior while making the flag usage more type-safe and self-documenting
- Splits the flags to match their actual usage patterns (e.g., `HASH_WRITE_OBJECT` becomes `INDEX_WRITE_OBJECT` for index operations and `WRITE_OBJECT_FILE_PERSIST` for write operations)

The changes are mechanical but improve code organization by making flag dependencies explicit. This continues the series' theme of better separation of concerns in the object storage code. The patch follows the established pattern from previous series iterations by maintaining behavior while improving internal structure.
