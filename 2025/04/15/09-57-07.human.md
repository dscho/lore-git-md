This is a cover letter for a patch series continuing the effort to make Perl an optional dependency in Git. Patrick Steinhardt follows up on his previous work removing Perl from the test suite, now targeting three more areas: `git-filter-branch`, `git-request-pull`, and documentation building.

The series would leave only a few non-critical features requiring Perl (gitweb, repository import scripts, git-send-email, Perl bindings, and the netrc credential helper). The changes involve converting Perl scripts to shell equivalents across multiple files, with significant line count changes (191 insertions vs 160 deletions across 10 files).

The work appears well-motivated and builds on established momentum - the cover letter references prior successful Perl-removal patches and positions this as a natural next step. The scope is clearly defined, focusing on specific subsystems rather than attempting to eliminate all Perl usage at once. The implementation looks thorough, with parallel shell versions replacing the Perl scripts rather than quick hacks.

This continues an important modernization effort for Git's build and runtime requirements. The changes are likely to be uncontroversial as they maintain functionality while reducing dependencies, though reviewers will want to verify the shell implementations are robust equivalents of the Perl originals.
