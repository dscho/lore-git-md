This thread is about making Perl optional in Git by converting remaining Perl scripts to shell, specifically targeting `git-filter-branch`, `git-request-pull`, and documentation building infrastructure. Eric Wong leads the effort, with Patrick Steinhardt contributing to the command list generation portion. The series is now at version 2 and appears merge-ready, having incorporated all feedback from the initial version.

The latest patch focuses on converting `git-filter-branch`'s `--state-branch` feature from Perl to shell, solving two key issues: it now properly respects `PERL_PATH` and works on systems without Perl installed. The implementation uses shell I/O redirection and `git hash-object` while maintaining the same file format for compatibility. Junio Hamano has already approved the approach in version 1, and version 2 addresses his stylistic suggestions along with some optional refinements to the request-pull conversion.

All components have been reviewed, with the documentation build system conversion now using `awk` instead of Perl, and the request-pull script's ref matching behavior exactly matching the original Perl implementation. While the shell version of command list generation is about 7x slower (74ms vs 10ms), this performance difference has been deemed acceptable. The series leaves other Perl dependencies like gitweb and send-email for future work, but these changes represent significant progress in reducing Git's footprint.
