This thread documents the final steps in removing Perl as a hard requirement for building Git, focusing on converting the last major Perl scripts to shell. Eric Wong's four-part series targets `git-filter-branch`, `git-request-pull`, and the documentation build system (including command list generation), with Patrick Steinhardt contributing the command list conversion. 

The technical work is now complete across all components: filter-branch's state handling has been reimplemented in shell using I/O redirection and `git hash-object`; request-pull's ref matching logic works in shell with only minor optional refinements possible; and the documentation system's `fix-texi` script and command list generator now run without Perl. Junio Hamano has reviewed each piece, approving the filter-branch conversion outright, suggesting an optional refinement for request-pull's ref matching, and accepting the documentation changes despite a 7x performance penalty (74ms vs 10ms for command list generation) as a worthwhile tradeoff for eliminating the Perl dependency.

With all conversions technically validated and no blocking issues remaining, the series appears merge-ready. This concludes the removal of Perl dependency from core Git operations, though Perl remains required for ancillary components like gitweb and send-email. The changes align with broader build system modernization efforts while maintaining compatibility with existing documentation formats and command behaviors.
