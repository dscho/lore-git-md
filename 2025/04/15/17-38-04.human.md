This is a review comment on patch 4/5 of Patrick Steinhardt's series hardening integer handling in Git's parse-options infrastructure. René Scharfe points out a technical correction needed in the implementation of the new `OPTION_UNSIGNED` type.

The patch introduces unsigned integer parsing without magnitude suffixes (like "k" or "g"), filling a gap between existing `OPTION_INTEGER` (signed) and `OPTION_MAGNITUDE` (unsigned with suffixes). The implementation handles different integer sizes (8, 16, 32, 64 bits) through a precision parameter.

Scharfe catches that the code incorrectly casts the unsigned values to signed integer types (`int8_t`, `int16_t`, etc.) when storing them, which would defeat the purpose of having an unsigned option type. This is a straightforward fix - the casts should use the corresponding unsigned types (`uint8_t`, etc.) instead.

The review is concise and focused, identifying a clear technical issue in an otherwise approved approach. This follows the thread's pattern of rigorous technical review, with Phillip Wood having previously identified overflow detection gaps and Junio Hamano focusing on documentation clarity. The series appears to be in its final stages, with this being one of the last implementation details to clean up.
