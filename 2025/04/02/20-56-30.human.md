This is a refactoring patch in Patrick Steinhardt's reftable API series (patch 10/16). The change simplifies the block iterator implementation by storing a pointer to the entire `reftable_block` rather than copying individual fields like `block_len` and `hash_size`.

Justin Tobler reviews the change positively, noting it makes the code "much simpler" and "nice!" The patch eliminates redundant storage and bookkeeping while making the relationship between the iterator and its underlying block more explicit. This is part of the series' broader goal to improve reftable's API design and standalone usability.

The technical changes are minimal but meaningful - replacing three fields with a single pointer to the block structure in `reftable/block.h`, with corresponding simplifications in `reftable/block.c`. The change paves the way for future work to decouple the iterator's lifetime from seeking operations.

This appears to be a straightforward improvement that follows the series' pattern of thoughtful API refinements, with Justin's review confirming the technical soundness of the approach.
