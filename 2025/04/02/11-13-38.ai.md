This is a feature patch from Patrick Steinhardt's v3 series enhancing `git cat-file` with object filtering capabilities, building toward the final v6 resolution documented in the thread summary.

The patch introduces the `--filter` option to `git cat-file`'s batch modes, matching the syntax used in `git rev-list`. Currently it only implements the option parsing and validation, explicitly rejecting all filter types with appropriate error messages. The actual filtering logic will come in later patches. The implementation:
- Adds documentation for the new option and its output format when objects are filtered
- Extends the `batch_options` struct to hold filter configuration
- Validates filter options and rejects unsupported types with clear error messages
- Includes comprehensive tests verifying error handling for various filter types

Key technical details for future reference:
- Uses `list_objects_filter_options` infrastructure from `list-objects-filter-options.h`
- Maintains compatibility with existing batch modes (`--batch`, `--batch-check`, `--batch-all-objects`)
- Introduces "excluded" output status for filtered objects in input modes
- Properly cleans up filter resources on exit
- Tests cover all error cases including invalid specs and unsupported filter variants

The patch lays groundwork for the performance improvements mentioned in the thread (41x speedup with bitmaps), though the current implementation doesn't yet realize those gains since it must still scan all objects. This was an uncontroversial early step in the series that established the basic filtering architecture later refined in v6.
