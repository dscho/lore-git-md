This is a follow-up discussion in the rebase status reporting improvements thread, specifically addressing patch 3/3 about merge instruction messaging. Phillip Wood clarifies Johannes Schindelin's question about authorship preservation during rebase operations.

The exchange reveals that using `git commit` to conclude a conflicted rebase operation (whether from a `pick` or `merge` instruction) always loses the original authorship information, contrary to Johannes' assumption. This confirms the behavior is consistent across operation types, though the architectural question remains about whether this could/should be changed.

The discussion doesn't introduce new changes to the patch series but provides important clarification about the underlying behavior that motivated the original patch (which aimed to suggest `git rebase --continue` rather than `git commit` for merge resolutions). Phillip's response indicates the authorship loss is a broader issue than just merge operations during rebase.

Key technical detail for future reference: The current implementation loses authorship information whenever `git commit` is used directly during a conflicted rebase, regardless of whether the operation was initiated via `pick` or `merge`. This affects both the immediate patch (which improves messaging) and potential future work on authorship preservation.
