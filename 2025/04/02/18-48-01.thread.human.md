Martin von Zweigbergk has announced a collaboration between Gerrit, GitButler, and Jujutsu to standardize how change IDs are implemented across Git-related tools. Change IDs are metadata that persist with commits through operations like rebasing, helping tools track changes across history rewrites. Currently, each tool handles this differently: Gerrit uses a 40-digit hex `Change-Id` trailer, GitButler uses a UUID format in a `gitbutler-change-id` trailer, while Jujutsu stores the IDs externally using a custom "reverse hex" encoding.

The group is standardizing on Jujutsu's 32-character reverse-hex format (where 'z'=0 to 'k'=15) as a new `change-id` header, chosen for its CLI usability with distinct prefixes. While they've documented edge cases like cherry-pick behavior in Gerrit's design docs, this initial email is primarily to inform the Git project about the cross-tool standardization effort rather than propose specific changes. If widely adopted, these standardized change IDs could enable useful workflows like rebasing by ID rather than hash and improve code review integration with Git forges.
