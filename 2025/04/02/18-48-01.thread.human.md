This thread continues the discussion about standardizing Change-IDs in Git commit messages, now examining both technical implementation and philosophical questions about their purpose. The discussion now spans both practical concerns (how forges implement tracking) and conceptual ones (what Change-IDs fundamentally represent in the development history).

Participants are grappling with how to standardize Change-ID behavior while accommodating different workflows - from email-based patch submission to GitLab's MR system - and considering whether the same rules should apply in all contexts. The thread remains active with no clear consensus yet, as contributors weigh the tradeoffs between strict uniqueness requirements and the potential value of using Change-IDs to indicate logical relationships between changes.
