This thread examines proposals for standardizing Change-IDs in Git to better track evolving patches. The discussion has evolved through several phases:

Initially, the conversation compared formal patch set IDs (proposed by Ted Ts'o) against Git's existing email-based tracking using Message-IDs. Junio Hamano highlighted how current tools like `b4 am` and lore.kernel.org already leverage email headers effectively for patch management, raising questions about whether additional identifiers would provide sufficient benefit.

Martin von Zweigbergk's latest contribution brings perspective from Jujutsu (jj), where Change-IDs serve as stable references to evolving commits. He clarifies this is distinct from the broader "Git Evolve" proposal, focusing instead on local workflow efficiency through features like prefix-based commit referencing and automatic descendant updates. The email notes key differences from Git's model, particularly how Jujutsu's detached-HEAD workflow enables behaviors that might not translate directly to Git's branch-based approach.

The thread now presents three distinct perspectives: Ts'o advocating for structured patch set IDs, Hamano emphasizing the adequacy of current email practices, and von Zweigbergk demonstrating an alternative implementation from Jujutsu. Open questions remain about whether Git's workflow constraints would limit the benefits of Change-IDs, and whether the core problem might be better addressed through improved tooling around existing mechanisms rather than new standards.
