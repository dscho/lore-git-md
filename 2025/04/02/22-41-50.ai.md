Maintainer response regarding core.symlinks behavior. This is a clarification about the intended use of the symlink configuration setting.

Brian m. carlson responds to Andrej Zhilenkov's question about toggling core.symlinks, explaining this is not a supported workflow. The configuration is described as a one-time hint to Git about filesystem capabilities (similar to core.filemode and core.ignorecase), not as a runtime-switchable setting. The response directly addresses the original question by stating there is intentionally no built-in way to convert between symlinks and regular files when this setting changes.

Key technical points:
- core.symlinks is compared to core.filemode and core.ignorecase in behavior
- Described as being set at repository creation time
- Explicitly not designed for user modification after creation
- No automatic conversion mechanism exists by design

The response shifts focus to understanding the use case, suggesting the maintainer may be open to discussing alternative solutions if the underlying need is explained. This leaves the thread open for further discussion about either documenting the behavior more clearly or potentially revisiting the design if compelling use cases emerge.

The email maintains the technical focus of the thread while providing authoritative guidance about expected behavior. It doesn't address whether the workarounds mentioned earlier are appropriate, instead focusing on the configuration's intended usage pattern.
