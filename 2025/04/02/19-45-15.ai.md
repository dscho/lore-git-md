This is a clarification about existing change-id usage in the ongoing discussion about standardizing change IDs across Git tools.

Konstantin Ryabitsev notes that the b4 tool (used for working with mailing list patches) already employs a "change-id" concept, but with different semantics than those being standardized. While the Gerrit/GitButler/Jujutsu effort focuses on commit-level identifiers that persist through rewrites, b4 uses change-ids at the patch series level, strictly in email footers without embedding them in commits. The b4 implementation treats these as arbitrary unique strings rather than following any particular format.

This contribution highlights an existing use of similar terminology in the mailing list workflow ecosystem, though one that operates at a different granularity (series vs commit) and with different persistence characteristics. The note serves to prevent potential namespace collisions or confusion as the standardization effort progresses, particularly for tools that interface with both mailing list and code review workflows. The casual mention of the format being "an arbitrary unique string" contrasts with the structured 32-character encoding proposed in the standardization effort.
