Documentation refinement for SHA implementation reporting in `git version --build-options`. This is part of the ongoing discussion about how to best document the non-crypto SHA-1 variants in the version output.

Christian Couder proposes expanding the warning text in git-version.adoc to provide more context about the SHA implementation reporting. The new text would explain that the output shows which libraries are used for SHA-1 and SHA-256 implementations, while specifically noting that certain SHA-1 variants (APPLE, OPENSSL, BLK) lack collision detection. The proposal includes a reference to Wikipedia's SHA-1 article for further reading about potential vulnerabilities.

This follows Patrick Steinhardt's concern that the original note was too terse and might confuse readers. Christian's suggestion aims to strike a balance between technical accuracy and approachability, while maintaining the maintainer-approved symbol-based reporting approach. The discussion continues regarding the exact phrasing, with Patrick having previously suggested "SHA-1 without collision detection" as an alternative to "non-crypto-SHA-1".

The patch series itself is already complete and approved, with this being the final documentation polish. The technical implementation using backend-defined symbols in hash.h remains unchanged.
