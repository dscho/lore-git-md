This thread explores Git's behavior when handling symlinks after changing the `core.symlinks` configuration. Andrej Zhilenkov demonstrates through a test case that toggling `core.symlinks` between true and false doesn't automatically convert existing symlinks to regular files (or vice versa) during operations like checkout or reset. The only reliable methods to update the filesystem representation are either checking out a commit from before the symlink was introduced or manually removing and re-checking out the affected files.

The test case clearly shows that Git preserves the existing symlink state regardless of the current `core.symlinks` setting, which may surprise users expecting automatic conversion. While the manual approaches work, the thread raises the question of whether this behavior is intentional (and perhaps undocumented) or represents a limitation in Git's handling of symlink state changes. No responses or solutions have been proposed yet in the thread.
