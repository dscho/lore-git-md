The thread began with Andrej Zhilenkov asking about Git's behavior when toggling the `core.symlinks` configuration, specifically whether Git should automatically convert between symlinks and regular files when this setting changes. Maintainer brian m. carlson clarified that `core.symlinks` is designed as a one-time filesystem capability hint (similar to `core.filemode` and `core.ignorecase`), not as a runtime toggle, and that automatic conversion between representations isn't supported.

In a follow-up, brian expanded on this position by drawing parallels to similar challenges in Git LFS, where transitioning between pointer files and actual objects presents comparable difficulties. While maintaining that the current behavior is intentional, they suggested this might point to a broader need for re-evaluating checkout behavior more generally. The maintainer explicitly stated they don't plan to implement such functionality themselves but would welcome contributions addressing both the symlink case and potentially this wider pattern of forcing re-evaluation of checked-out objects.

The discussion remains open with several key questions: whether documentation should be enhanced to clarify this behavior, if there are valid use cases that might justify revisiting the design, and whether the identified workarounds (like checking out a pre-symlink commit and re-checking out) should be officially recommended. brian has expressed particular interest in better understanding the original use case that prompted the question.
