This is a refactoring patch in Patrick Steinhardt's reftable API series, specifically addressing block reading responsibilities. The patch moves block reading logic from the table subsystem into the block reader subsystem, clarifying ownership and reducing awkward block passing between components.

The key technical changes involve modifying `block_reader_init()` to take a block source and offset rather than a pre-read block, making the block reader fully responsible for its own block ownership. The implementation now handles block size detection internally, including a fallback to `DEFAULT_BLOCK_SIZE` when unspecified, and includes logic to re-read blocks when the initial size guess proves insufficient.

Justin Tobler's review confirms the technical soundness of the approach, noting the improved ownership model and self-contained block reading behavior. He asks one clarifying question about when the table wouldn't know the block size (triggering the fallback to `DEFAULT_BLOCK_SIZE`), but otherwise finds the changes logical and well-executed.

The changes affect `reftable/block.[ch]` and `reftable/table.c`, with corresponding test updates in `t/unit-tests/t-reftable-block.c`. This continues the series' pattern of technical simplifications following the initial mechanical changes (patches 1-3). The review process remains positive, with no technical concerns raised about this patch's implementation.
