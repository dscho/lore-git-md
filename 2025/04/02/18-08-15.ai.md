Refactoring of reftable block restart point tracking (patch 4/16 in series).

Justin Tobler reviews Patrick Steinhardt's patch that simplifies how restart points are tracked in reftable blocks. The original implementation maintained three related variables (`block_len`, `restart_count`, and `restart_bytes`) where some values could be derived from others. The patch eliminates redundancy by:

1. Replacing the `restart_bytes` pointer with a `restart_off` offset into the block data
2. Removing the separate `block_len` tracking since it was always equivalent to the restart offset
3. Updating all related calculations to use the new offset-based approach

The changes affect several functions in `reftable/block.c` and the `block_reader` struct definition in `reftable/block.h`. Justin confirms the logic makes sense and approves the technical approach, noting the improved consistency in naming (`restart_off` vs previous `restart_start`). The patch is part of a larger series refactoring the reftable API for better external usability and lower-level access.

Key technical points for future reference:
- Restart points mark uncompressed records for binary search
- Block structure now tracks only `restart_count` and `restart_off`
- All length calculations now derive from `restart_off`
- Changes are mechanical with no behavior differences
- Affects block reader initialization, iteration, and seek operations
