This is a performance optimization patch that completes the bitmap integration for `git cat-file`'s object type filtering functionality, building on the refactoring work from earlier in the series.

The patch introduces bitmap acceleration for object type filtering in `git cat-file --batch` mode. When a bitmap is available (either per-pack or via MIDX), it uses the type-specific bitmaps to directly iterate only objects of the requested type, rather than scanning the entire packfile. The implementation:
- Adds a new `batch_one_object_bitmapped` callback handler that adapts the bitmap traversal interface to the existing callback infrastructure
- Modifies `batch_each_object()` to first try bitmap traversal when possible, falling back to full pack scans for packs without bitmaps
- Maintains the existing behavior when no bitmap is available
- Shows dramatic performance improvements (41x faster) when filtering commits in a large repository (Chromium's 50GB pack with 25M objects)

The changes integrate with the series' earlier work by:
- Using the `for_each_bitmapped_object()` infrastructure added in v3
- Leveraging the refactored `batch_each_object()` interface from patch 10/11
- Maintaining compatibility with the existing filter options and callback chains

Key technical points:
- New `batch_one_object_bitmapped` callback bridges bitmap and batch interfaces
- `batch_each_object()` now takes `struct batch_options` parameter to access filter config
- Careful resource management with `prepare_bitmap_git()`/`free_bitmap_index()`
- Fallback path preserves behavior for non-bitmapped packs
- Performance impact is neutral when no filters are used (as expected)

This represents the final technical piece enabling efficient type-based filtering in batch mode, completing the performance story that was hinted at in earlier series versions. The implementation maintains the series' careful approach to backward compatibility and fallback paths while delivering on the promised speedups.
