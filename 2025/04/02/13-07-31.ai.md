Final test portability fix for `git blame` porcelain output patch series.

This email from Phillip Wood addresses the last remaining test portability issue in the long-running thread about marking unblamable/ignored lines in `git blame` porcelain output. The discussion has narrowed to a very technical point about POSIX sed compatibility, specifically around inserting newlines before matching patterns.

The key issue is that different sed implementations handle the 'i' (insert) command differently - some require the inserted text to be on the same line after a backslash, while others (like macOS) treat each '-e' argument as a separate line. Karthik Nayak had proposed using a heredoc for the sed script as a portable solution, which Phillip Wood agrees is the best approach given the constraints.

This represents the final refinement to the test suite for this feature, following earlier fixes for newline handling in output and tab character portability. The thread has now addressed all identified issues including output formatting, test robustness, and cross-platform compatibility. With this resolution, the patch series appears ready for final approval and merging.
