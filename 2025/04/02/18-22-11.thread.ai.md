Thread identity: GSoC project proposal for a new `git metadata` command to output structured repository information in JSON format, authored by Lucas Oshiro.

Core problem: Currently, Git repository metadata (branches, tags, remotes, submodules) is only available through multiple disparate commands with inconsistent output formats. This proposal aims to provide a unified, machine-readable interface for programmatic consumption by tools, IDEs, and researchers.

Key technical details:
- New `builtin/metadata.c` implementing `git metadata` command
- JSON output schema showing branch names/upstreams, tag names/pointers, remote URLs/fetch specs, submodule paths/URLs
- Optional filtering via flags like `--submodule`
- Two-phase implementation: first internal data structures, then CLI/JSON serialization

Current status: Initial proposal stage with detailed development schedule outlined. No reviews or feedback yet recorded.

Participant positions:
- Lucas Oshiro (author) has relevant prior Git experience including documentation contributions and a Haskell Git implementation

Related work: Builds on existing Git plumbing commands but provides unified structured output. Potential users include IDE developers and research teams needing repository metadata.
