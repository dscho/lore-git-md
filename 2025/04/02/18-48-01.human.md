Collaboration proposal for standardized "change-id" commit footer

This email announces a collaboration between Gerrit, GitButler, and Jujutsu to standardize how they track "change-id" metadata in commits. Currently each tool uses different formats and storage methods (Gerrit uses a `Change-Id` trailer, GitButler uses a UUID-style footer, Jujutsu stores externally), which creates interoperability challenges.

The proposed standard would use a new `change-id` header with a 32-character "reverse hex" format (using letters z-k to represent 0-15). This format was chosen for its ability to avoid collisions with commit hashes while remaining human-readable. The change-id would persist through commit rewrites like rebases and amends, enabling useful workflows like `git rebase main <change-id>` without needing to track hash changes.

Martin von Zweigbergk positions this as an informational heads-up rather than an immediate request for Git project changes. The email links to a design document detailing Gerrit's migration plan and considerations around edge cases like cherry-picking. The proposal appears well-considered, with clear benefits for cross-tool workflows and code review tracking, though it would introduce new metadata that core Git would need to preserve during operations.
