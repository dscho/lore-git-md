This is a feature proposal for standardizing change IDs across Git-related tools. Martin von Zweigbergk announces that Gerrit, GitButler, and Jujutsu are collaborating to unify their different implementations of change IDs - metadata that follows commits through rewrites like rebases. The current implementations differ in format and storage location (Gerrit uses `Change-Id` trailer with 40 hex digits, GitButler uses `gitbutler-change-id` in UUID format, Jujutsu stores externally with a custom "reverse hex" encoding).

The group proposes standardizing on a new `change-id` header using Jujutsu's 32-character reverse-hex format (with 'z'=0 to 'k'=15), which provides good CLI usability through distinct prefixes. The email references a Gerrit design doc discussing edge cases like cherry-pick behavior, though the immediate goal is just to notify the Git project of this cross-tool standardization effort rather than request specific changes. The change IDs would enable useful workflows like rebasing by ID rather than hash, and could facilitate code review integration if adopted by forges.
