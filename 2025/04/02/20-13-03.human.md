This is a technical refactoring patch in Patrick Steinhardt's reftable API series (patch 5/16). Justin Tobler provides a review that confirms the changes improve code organization while maintaining technical correctness.

The patch moves block reading responsibilities fully into the block reader subsystem, eliminating awkward ownership transfers between components. Instead of passing around block ownership, the block reader now takes a block source and offset, reading the block itself. This makes the ownership model clearer and more self-contained.

Justin notes several improvements in the block reader now:
- Handles its own block reading rather than relying on pre-read blocks
- Includes logic to verify and re-read blocks if the initial size guess is wrong
- Maintains cleaner separation of concerns between subsystems

The review confirms the technical approach is sound, with only minor questions about edge cases (when table_block_size might be unknown). The changes primarily affect `reftable/block.c` and `reftable/table.c`, with corresponding test updates. This continues the series' trend of improving API clarity while maintaining functionality.
