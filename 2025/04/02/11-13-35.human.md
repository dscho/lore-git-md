This is a feature patch series introducing object filtering to `git cat-file`'s batch modes, with significant performance improvements when using bitmaps.

Patrick Steinhardt presents version 3 of his series that adds object filtering capabilities to `git cat-file`'s batch operations. The motivation comes from GitLab's need to efficiently list objects of specific types in large repositories like Chromium, where current workarounds (piping through grep/cut) take 80-100 seconds due to I/O bottlenecks.

The series adds three filter types matching `git rev-list`'s syntax: `blob:none`, `blob:limit=<size>`, and `object:type=<type>`. The real performance win comes from integrating with bitmap indices, allowing direct lookup of filtered objects rather than scanning entire packfiles. Benchmarks show a 41x speedup for filtering commits in the Chromium repo (from ~86s to ~2s).

Changes in v3 include better documentation of filter behavior across batch modes, explicit handling of filtered objects in `--batch` output, added `--no-filter` testing, and using the standard `OPT_PARSE_LIST_OBJECTS_FILTER` option parser. The implementation now cleanly separates the bitmap integration from the regular filtering logic.

The series appears well-considered, with thorough test coverage and clear performance benefits for large repositories. The bitmap integration in particular makes this a compelling feature for users needing to efficiently query repository object stores. The changes are focused and the commit messages clearly explain both the what and why of each change.
