This is a follow-up discussion in the build system fixes series, specifically about the gitweb JavaScript generation patch. Patrick Steinhardt responds to Johannes Schindelin's suggestion to use `$(filter-out %.sh,$^)` instead of `$(filter %.js,$^)` for the gitweb.js build rule.

Patrick acknowledges both approaches have tradeoffs: filtering by extension requires updates if files are renamed, while filtering out shell scripts requires remembering to exclude new dependencies. He argues the extension-based approach is slightly better since file renames already require build system updates, whereas new dependencies might be overlooked. However, he notes the lack of tests for this build step makes either solution imperfect.

The discussion remains open-ended, with Patrick indicating he'll implement Johannes' preferred approach if Johannes still favors the `filter-out` method after considering these points. This is a minor technical refinement to an otherwise straightforward build system fix that already had positive reviews.
