This is a continuation of the meson build system discussion about shell completion script installation, focusing on distribution-specific path standardization.

Patrick Steinhardt responds to Todd Zullinger's Fedora packaging insights by questioning whether per-shell path configuration options are truly necessary. He observes that if packagers must manually specify paths anyway, they could just as well copy the files directly, since no build step is involved. Steinhardt suggests that bash and zsh locations appear stable enough across distributions to justify hardcoding paths without options, proposing to start with sensible defaults and only add configurability if concrete problems emerge.

The email highlights two key technical points: Fedora's tcsh completion has remained unchanged in `/usr/share/git-core/contrib/completion/` since 2013 without user complaints, and zsh completions are omitted from Fedora packages due to existing upstream zsh coverage. Steinhardt also confirms Git lacks fish shell completions, clarifying the scope of the discussion.

This moves the thread toward a potential resolution - default installation paths for bash and zsh (using Fedora's `/usr/share/bash-completion/completions` and `/usr/share/zsh/site-functions` as models) while leaving tcsh handling unchanged. The meson build system would gain automatic installation capability for shells with stable paths, reducing packager burden while maintaining flexibility through manual file copying where needed.
