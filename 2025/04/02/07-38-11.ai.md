This is a follow-up discussion on the SHA implementation reporting feature, specifically addressing documentation and implementation details of the non-crypto SHA-1 variants.

The email responds to Justin Tobler's proposed documentation changes for the SHA-1 variants in git-version.adoc. Patrick Steinhardt raises concerns that the warning about collision detection lacks context for readers unfamiliar with Git's SHA-1 implementation choices. He suggests either expanding the explanation or removing it entirely.

The technical discussion focuses on three key files:
1. Documentation/git-version.adoc - where the warning about non-collision-detecting SHA-1 variants is being added
2. hash.h - which now contains the SHA*_BACKEND symbol definitions with explicit "(No collision detection)" warnings
3. help.c - where the SHA implementation reporting function was added

Patrick notes that while the new `get_sha_impl()` function in help.c isn't strictly necessary, he doesn't object to its inclusion. The thread has already settled on using compile-time symbols (SHA1_BACKEND, SHA1_UNSAFE_BACKEND, SHA256_BACKEND) as the mechanism for reporting implementations, with maintainer approval of this approach.

This discussion represents final polish on the feature's documentation and presentation, following the core technical decisions that were already approved in earlier thread exchanges. The conversation shows the project's attention to both technical correctness and user-facing clarity when exposing implementation details through the version reporting mechanism.
