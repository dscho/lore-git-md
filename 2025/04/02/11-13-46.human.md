Performance optimization for `git cat-file`'s using bitmaps to filter by object type. This is the final patch in a series that adds filtering capabilities to `git cat-file --batch`, now leveraging bitmap indexes for dramatic speed improvements when filtering by object type.

The patch modifies the object iteration infrastructure to first check for available bitmaps. When present, it uses the type-specific object lists in the bitmap to directly access objects of the requested type, falling back to the full packfile scan only for packs without bitmaps. Benchmark results show a 41x speedup when filtering commits in a large repository (Chromium's 50GB packfile with 25M objects), while unfiltered performance remains unchanged as expected.

The implementation builds on previous patches in the series that introduced the filtering infrastructure and type-specific iteration. It maintains the same careful approach to resource management and error handling seen throughout the series, with proper cleanup of bitmap resources. The change is focused on the bitmap integration while preserving the existing behavior for non-bitmap cases.

This completes the technical implementation of the filtering feature, with all prior review feedback addressed. The performance gains make type-based filtering practical even for very large repositories where scanning the entire packfile would be prohibitively expensive.
