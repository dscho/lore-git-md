Refactoring in Patrick Steinhardt's reftable API series (patch 11/16). This change makes block iterators reseekable by separating initialization from seeking operations. The key modification stores the block pointer in the iterator during initialization, allowing subsequent seeks to reuse it rather than requiring the block to be passed each time.

Justin Tobler reviews the patch positively, noting the simplification ("Nice!") while catching a minor typo in the commit message ("ever" → "every"). He also questions why some test cases still call `block_iter_seek_start()` after initialization when `block_iter_init()` already performs this operation, suggesting potential redundancy.

The changes affect several files in the reftable implementation but maintain the same behavior while improving the API design. This continues the series' trend of cleaning up the reftable internals for better standalone usability and preparing for future iterator interface improvements. The review interaction shows the series is maturing well, with feedback now focused on small refinements rather than fundamental issues.
