This is a refactoring patch in Patrick Steinhardt's reftable API series, specifically addressing how restart points are tracked in reftable blocks. 

Justin Tobler provides a review of patch 4/16, which simplifies the tracking of restart points in reftable blocks. The original implementation tracked three related variables (block length, restart count, and restart bytes location), but Patrick's patch consolidates this by using just the restart offset, since the other values can be derived from it. 

Justin confirms the technical approach makes sense - instead of tracking both `restart_bytes` and `restart_start`, the patch now just tracks `restart_off` (renamed from `restart_start` for consistency). He notes this eliminates the confusing `block_len` variable and reduces bookkeeping. 

The review finds the changes sound, with Justin only pointing out one minor naming clarification about why `block_len` was renamed to `restart_off`. The patch touches three files (block.c, block.h, and table.c) with straightforward mechanical changes to implement the simplified tracking approach. 

This appears to be a clean, well-justified refactoring that's part of the larger reftable API improvements. Justin's review suggests the technical implementation is solid, with no substantive issues found.
