Refactoring in Patrick Steinhardt's reftable API series (patch 11/16). This change modifies the block iterator interface to make it reseekable by storing the block pointer during initialization rather than passing it with each seek operation.

The key technical changes:
- Splits iterator initialization (`block_iter_init`) from seeking (`block_iter_seek_start` and `block_iter_seek_key`)
- Stores `const struct reftable_block *block` in the iterator struct
- Updates all callers to use the new initialization+seek pattern
- Removes redundant block parameter from seek operations
- Updates unit tests to match new API

Justin Tobler's review notes:
- Approves the change with "Nice!" comment
- Catches a minor typo in commit message ("ever" -> "every")
- Questions why some test cases call `block_iter_seek_start()` after `block_iter_init()` when the latter already performs the seek
- The change affects `reftable/block.[ch]` primarily, with ripple effects in iterator and table code

This continues the series' pattern of simplifying the reftable internals while maintaining the same behavior. The change prepares for future work exposing a `reftable_iterator` interface for blocks. All feedback so far has been minor documentation/typo issues rather than technical concerns.
