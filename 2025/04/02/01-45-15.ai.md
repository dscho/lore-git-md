This is a bugfix patch addressing a potential security issue in the column formatting code. The patch prevents a size_t overflow that could occur when the indent length exceeds the specified width in `print_columns()` and `run_column_filter()`. 

The issue stems from an unsigned underflow when calculating column counts, which could lead to either excessive memory allocation or crashes. The fix adds an early check that fails with a clear error message when the indent is too long, preventing the underflow condition. The change also makes the code more robust by ensuring column counts remain positive and removes the need for signed-unsigned comparison warnings.

The patch includes two new test cases that verify the error conditions: one for the indent-width validation and another confirming that padding validation takes precedence. The author notes this was initially reviewed by the security team (Patrick Steinhardt) who confirmed the limited attack surface (only affecting `git-branch`, `git-tag`, and `git-column` with explicit --column` options) and suggested using `die()` instead of `BUG()` for user-controlled input validation.

Key technical details for future reference:
- Affects `column.c` functions `print_columns()` and `run_column_filter()`
- Adds validation for `opts->indent` length vs `opts->width`
- Maintains existing behavior where padding validation happens first
- Introduces new test cases in `t/t9002-column.sh` covering both error conditions
- Error message: "length of indent cannot exceed width"
