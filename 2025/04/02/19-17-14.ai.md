This is a technical discussion in Patrick Steinhardt's ongoing series to eliminate Perl dependencies from Git's test suite (specifically patch 13/20 about textconv scripts). The exchange clarifies a design decision around test expectations in t4030-diff-textconv.sh.

Johannes Schindelin questions why the patch uses `tr` for binary-to-text conversion rather than the existing `test-tool hexdump`. Patrick explains this was deliberate - while `test-tool hexdump` would be more "correct", its output differs from the original Perl script's behavior, requiring extensive test expectation updates that would introduce awkward artifacts (trailing whitespace, seemingly unrelated changes). The `tr` approach maintains existing test behavior with minimal churn.

Key technical points:
- Original Perl script converted bytes to decimal ordinals (despite "hexdump" name)
- New `tr` version only handles NUL and SOH (sufficient for test cases)
- `test-tool hexdump` would require cascading test expectation changes
- Decision prioritizes test stability over technical purity

The discussion reveals the practical tradeoffs in test modernization - sometimes simpler solutions that preserve existing behavior are preferable to more "correct" ones that would ripple through many tests. Johannes accepts this rationale, noting the explanation is sufficient without requiring another patch revision. This exemplifies the careful balancing act in large-scale test refactoring between correctness, maintainability, and reviewer burden.
