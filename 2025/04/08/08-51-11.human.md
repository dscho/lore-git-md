This is the final implementation patch in Karthik Nayak's series enabling batched reference updates with partial failure support. The patch focuses on handling file/directory (F/D) conflicts during batch operations.

The change modifies `refs_verify_refnames_available()` to support per-update rejection when F/D conflicts occur, rather than failing the entire transaction. Key changes include:

1. Adding transaction context to track rejected updates via `ref_transaction_maybe_set_rejected()`
2. Moving the function to refs-internal.h since it's now backend-specific
3. Updating both files and reftable backends to use the new rejection mechanism
4. Adding a `conflicting_dirnames` strset to efficiently track problematic paths

The patch maintains atomicity guarantees while allowing graceful handling of user-input errors. It completes the series' goal of supporting partial failures in batched reference operations, with all technical aspects having been reviewed and approved by maintainers. The implementation is thorough, with careful attention to memory management and error handling throughout.
