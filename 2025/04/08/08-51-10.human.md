Feature implementation for batched reference updates with partial failure support. This is the core implementation patch in Karthik Nayak's v6 series, introducing atomic reference updates that can gracefully handle partial failures.

The patch adds a new `REF_TRANSACTION_ALLOW_FAILURE` flag that lets reference updates continue even if some individual updates fail (except for system errors which still abort the whole transaction). Key components include:
- A `rejection_err` field in `ref_update` to track per-update failures
- A `ref_transaction_rejections` struct to aggregate failed updates
- Backend modifications (files, packed, reftable) to use `ref_transaction_set_rejected()` for partial failures
- A new `ref_transaction_for_each_rejected_update()` iterator for examining failures

The implementation is thorough, touching all major ref backends while maintaining atomicity guarantees. This enables more efficient batched updates, particularly beneficial for the reftable backend. The patch follows the series' established patterns and has already undergone extensive review, with no outstanding technical concerns noted. A follow-up will expose this via a `--batch-updates` flag in `git-update-ref`.
