Refactoring patch in the reflog expiration series, focusing on naming improvements.

This is the first patch in a 6-part series that refactors reflog expiration code to remove global state, as part of the broader maintenance task system work. The patch renames `struct cmd_reflog_expire_cb` to `struct reflog_expire_options` since the structure will be exposed via "reflog.h" and used beyond just callback contexts. The new name better reflects its role as a container for expiration parameters.

The changes are mechanical but widespread, updating all references to the renamed struct across builtin/reflog.c, reflog.c, and reflog.h. Key fields like `expire_total`, `expire_unreachable`, and `stalefix` remain unchanged but are now accessed through the renamed struct. The patch maintains all existing functionality while improving the API's clarity for future use in the maintenance system.

This prepares for subsequent patches that will move reflog expiration defaults from global variables into this options struct, as part of eliminating global state. The change is straightforward with no behavior modifications, just improved naming for a structure that will have broader visibility.
