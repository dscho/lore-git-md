This is part 2 of a 6-patch series refactoring reflog expiration to remove global state, specifically focusing on moving default expiry dates into the reflog_expire_options struct. The patch eliminates two global variables (`default_reflog_expire` and `default_reflog_expire_unreachable`) by adding them as fields to `struct reflog_expire_options` alongside a new initialization macro `REFLOG_EXPIRE_OPTIONS_INIT` that sets the standard 30/90 day defaults. The config callback is updated to write directly to these struct fields rather than the removed globals.

Key technical changes include:
- Added `default_expire_total` and `default_expire_unreachable` fields to `struct reflog_expire_options`
- Introduced `REFLOG_EXPIRE_OPTIONS_INIT` macro with hardcoded 30/90 day defaults
- Updated `reflog_expire_config()` to write to struct fields instead of globals
- Modified `cmd_reflog_expire()` to use the new initialization pattern
- Kept all existing expiration logic intact while changing the storage mechanism

This continues the series' incremental approach to state management improvements, following patch 1's renaming of the callback struct. The changes are mechanical but move important configuration into a more encapsulated form, addressing part of the state management concerns raised in earlier review discussion while leaving some architectural questions about runtime vs configuration state for potential future work.
