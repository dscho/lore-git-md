Patrick Steinhardt's ongoing refactoring of Git's object-file subsystem has reached its third patch in the v2 series, focusing on relocating memory-mapping utilities. The initial groundwork established by the first two patches - which moved directory utilities to dir.c - has now been followed by this logical next step: moving mmap-related functions to wrapper.c.

The current patch cleanly transfers three core mmap functions (`xmmap`, `xmmap_gently`, and `mmap_os_err`) along with their size-limit checker to wrapper.c, where they join similar low-level system wrappers. This maintains the series' pattern of pure relocation without functional changes, keeping all implementations identical while improving code organization. The functions provide essential memory mapping operations with error handling, including platform-specific considerations like Linux's memory limits.

This continues the architectural separation between core object storage logic (remaining in object-file.c) and general utilities. The thread shows steady progress toward clearer subsystem boundaries, with each patch building on the last while maintaining the non-disruptive approach that earned Junio Hamano's approval for the initial changes. The series appears on track to achieve its goal of establishing better organized foundations for future object storage improvements.
