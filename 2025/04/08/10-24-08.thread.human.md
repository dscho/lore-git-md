Patrick Steinhardt continues his methodical refactoring of Git's object-file subsystem with this 9-patch series aimed at enabling future modular object storage backends. The latest patch (4/9) represents a significant architectural shift by moving core object store functionality from the monolithic object-file.c into a new object-store.c file. This addresses a long-standing mixing of concerns where object store operations were improperly located in object-file.c despite having their own header.

The changes are extensive, touching 20 files and moving over 1000 lines of code. Key functions relocated include object database management (like odb_mkstemp), alternate object database handling (prepare_alt_odb), and core object reading utilities (repo_read_object_file). This builds on previous patches that moved directory creation utilities to dir.c and file opening functions to compat/open.c.

The series maintains all existing behavior while establishing cleaner architectural boundaries - a prerequisite for Patrick's ongoing ODB abstraction work that will enable pluggable storage backends. Reviewers should pay special attention to the object database and alternate handling code, as these are critical infrastructure components. The changes are carefully structured to avoid behavior changes, with each patch focusing on clearly separable components. Future patches in the series will continue this systematic reorganization of the object-file subsystem.
