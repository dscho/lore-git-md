This thread documents Patrick Steinhardt's ongoing effort to refactor Git's object storage subsystem, now at its third iteration (v3). The series aims to better organize the code by separating low-level object operations from higher-level object store management. 

The latest patch (5/10) moves all object store management functions from object-file.c to a new object-store.c, including alternate ODB handling, object lookup/caching, existence checks, and reading utilities. This maintains existing behavior while creating clearer separation - object-file.c now focuses on loose object I/O while object-store.c handles store management. The change updates 20 files' headers and build configurations.

This builds on previous decisions in the series that relocated directory utilities to path.c and memory mapping functions to wrapper.c. All architectural questions from earlier versions appear resolved, with Junio Hamano's note about cross-repository sharing of virtual objects being the only remaining open consideration. The series has incorporated feedback from Eric Sunshine (path utilities placement) and Jeff King (keeping index-related functions in object-file.c).

With over 150 files modified across the series, this latest patch continues the comprehensive reorganization while preserving all functionality. The changes advance both the object storage modularization and the broader `the_repository` removal effort through added repository parameters. The series appears ready for integration, representing a significant step in improving Git's internal structure.
