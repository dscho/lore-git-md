This is patch 4/9 in Patrick Steinhardt's series refactoring Git's object-file subsystem, continuing the architectural cleanup to enable future modular object storage backends. The patch moves functions related to the object store subsystem from object-file.c to a new object-store.c file, addressing the current mixing of concerns where most object store functionality was improperly located in object-file.c despite having a dedicated object-store.h header.

The changes are extensive, touching 20 files with 1041 lines removed from object-file.c and 972 lines added to the new object-store.c. Key functions relocated include:
- Object database management (odb_mkstemp, odb_pack_keep)
- Alternate object database handling (prepare_alt_odb, link_alt_odb_entries)
- Object existence checking (has_object, repo_has_object_file)
- Object reading utilities (repo_read_object_file, read_object_with_reference)
- Object info and type checking (oid_object_info_extended, assert_oid_type)

The patch maintains all existing behavior while better organizing the code. It follows the established pattern of the series: identifying generic utilities in object-file.c, verifying they're truly non-object-specific, then relocating them with minimal changes. This structural work is prerequisite for future pluggable storage backends, though the current focus remains on establishing clean architectural boundaries.

Reviewers should pay particular attention to the object database and alternate handling code paths, as these are critical infrastructure components. The changes complement Patrick Steinhardt's ongoing ODB abstraction work, though explicit coordination confirmation would be valuable. Subsequent patches will need to maintain this careful separation between generic utilities and object-specific code.
