Refactoring patch in a series reorganizing Git's object-file subsystem. This is patch 3/9 in Patrick Steinhardt's series to split up the monolithic object-file.c into more logically organized components.

The patch moves the `xmmap()` family of functions from object-file.c to wrapper.c, where they more naturally belong as general-purpose memory mapping utilities rather than object-storage specific code. The functions include `xmmap()`, `xmmap_gently()`, `mmap_os_err()`, and their supporting `mmap_limit_check()` helper. The implementation remains exactly the same - this is purely a code relocation.

This continues the series' pattern of identifying generic utilities embedded in object-file.c and moving them to more appropriate homes. The change is straightforward with no intended behavior changes, just updating the file locations while maintaining all existing functionality including platform-specific error messages (like the ENOMEM handling for Linux) and memory limit checks via GIT_MMAP_LIMIT.

The patch follows the same clean approach as previous ones in the series, with a simple cut-and-paste move of the code and no other modifications. Reviewers should verify the relocation makes sense architecturally and that no subtle dependencies on object-file internals were overlooked, though the change appears well-scoped.
