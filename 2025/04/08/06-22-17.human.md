Feature: Final patch in a series adding reflog expiration to Git's task-based maintenance system.

This is the sixth and final patch in Patrick Steinhardt's series to integrate reflog expiration into Git's maintenance framework. The patch introduces a new "reflog-expire" maintenance task that can be run either manually or automatically, mirroring the functionality currently provided by `git gc`.

The task behaves differently in manual vs. auto modes:
- Manual runs (`git maintenance run --task=reflog-expire`) simply execute `git reflog expire --all`
- Auto runs use a heuristic based on the HEAD reflog - by default running only when there are at least 100 expirable entries (configurable via `maintenance.reflog-expire.auto`)

The implementation is thorough, including:
- Documentation updates for both the config option and task description
- A new condition function that efficiently checks reflog state
- Comprehensive tests verifying both manual and auto behavior

This completes the series' goal of moving reflog expiration out of `git gc` and into the more flexible maintenance task system. The patch builds on the refactoring work done in previous patches to remove global state from the reflog expiration code. The implementation appears clean and well-tested, with clear documentation of the new feature's behavior.
