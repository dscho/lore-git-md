Feature proposal feedback on GSoC project to extract repository info from `rev-parse`

Karthik Nayak provides constructive feedback on Moumita Dhar's GSoC proposal to create a new `git repo-info` command. The proposal aims to move non-revision-parsing functionality (like `--is-bare-repository`, `--git-dir` etc.) from `git rev-parse` into a dedicated tool with structured output.

Key points in Karthik's feedback:
- Suggests expanding the scope to include all "Options for Files" from `rev-parse`
- Requests more technical details about the new interface design (naming, default output, justification for command name)
- Recommends involving the mailing list early for design feedback
- Notes the importance of incremental development with each patch being merge-ready (code+tests+docs) rather than one big series at the end
- Questions some timeline specifics (like late documentation) and terminology ("dispatcher")
- Overall supportive but emphasizes Git's development practices around small, complete patch submissions

The feedback shows engagement with the proposal while setting clear expectations about Git's workflow. Karthik positions this as part of an ongoing effort to improve Git's command structure, noting similar discussions in another proposal thread [2].
