This is the final implementation patch in Karthik Nayak's series adding batched reference updates with partial failure support, now in its sixth iteration. The patch introduces core infrastructure for allowing reference updates to partially succeed when `REF_TRANSACTION_ALLOW_FAILURE` is set, while maintaining atomicity for system errors.

Key technical components added:
- New `rejection_err` field in `ref_update` to track per-update failure reasons
- `ref_transaction_rejections` struct to aggregate failed updates for iteration
- Backend-specific handling through `ref_transaction_maybe_set_rejected()`
- Iteration API `ref_transaction_for_each_rejected_update()` for callers
- Modified backend logic (files, packed, reftable) to use the new rejection mechanism

The implementation distinguishes between system errors (which still abort the entire transaction) and user-input errors (which can be selectively rejected). The packed backend sees the most significant changes to its update handling logic. All backends now consistently use the new rejection mechanism when the allow-failure flag is set.

This builds on the earlier patches' work to centralize refname checking and standardize error types, completing the technical foundation for the upcoming user-facing `--batch-updates` flag. The changes maintain backward compatibility while adding the new partial-failure capability.
