Refactoring patch in the reflog expiration series. This is the first of six patches that restructure reflog expiration to remove global state as part of adding it as a maintenance task.

The patch renames `struct cmd_reflog_expire_cb` to `struct reflog_expire_options` to better reflect its purpose now that it will be exposed more widely (specifically to `builtin/gc.c`). The commit explains that the current name was awkward since the struct contains general expiration options rather than being callback-specific.

This is a straightforward mechanical change that updates all references to the renamed struct across three files (`builtin/reflog.c`, `reflog.c`, and `reflog.h`). The changes are consistent and well-contained, with no behavior modifications - this is purely a naming improvement to prepare for the subsequent patches in the series.

The patch follows the incremental refactoring approach discussed in the thread, where Patrick Steinhardt is breaking down the reflog expiration changes into manageable steps. This first change is low-risk and unlikely to be controversial, serving as groundwork for the more substantive changes that follow.
