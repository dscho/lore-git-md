Maintainer feedback on meson headers-check implementation.

Junio C Hamano responds to Karthik Nayak's patch adding 'headers-check' functionality to meson builds, which aimed to match Makefile's 'hdr-check' target. While agreeing with the goal of porting this header validation capability, Junio raises concerns about the naming divergence between the Makefile's established 'hdr-check' and meson's proposed 'headers-check'.

The key technical point is that introducing a new name without maintaining backward compatibility could create confusion for developers with existing build setups. Junio suggests a transitional approach where both names would work in both build systems, with 'hdr-check' eventually being phased out after giving users time to update their workflows. This reflects Git's typical deprecation policy for non-user-facing features.

The feedback focuses specifically on the naming convention rather than the implementation details of the header checking itself, which the thread summary indicates was uncontroversial. Junio's response shows particular attention to maintaining consistency across build systems and minimizing disruption for contributors, even for internal build targets. The naming discussion appears to be the final point needing resolution before this series can be considered complete.
