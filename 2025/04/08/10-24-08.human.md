This is a major refactoring effort targeting the object-file subsystem, splitting up the monolithic "object-file.c" into more logically organized components. Patrick Steinhardt proposes moving various functions to more appropriate homes:

1. Directory handling functions go to "dir.c"
2. Memory mapping utilities move to "wrapper.c"
3. File opening functions relocate to "compat/open.c"
4. Index-related functions shift to "read-cache.c"
5. Object store management gets its own new "object-store.c"

The end result leaves "object-file.c" focused specifically on loose object I/O, while the new "object-store.c" handles higher-level object directory management. This appears to be part of a broader architectural cleanup, building on previous work to reduce reliance on `the_repository` global.

The patch series is substantial (9 patches touching 145 files) but appears carefully constructed, with each commit focusing on a logical grouping of functionality. The changes are primarily code movement rather than behavior modification, suggesting this is preparatory work for future improvements to the object storage architecture.
