This is Junio Hamano's technical proposal for a DAG-based predecessor-successor relationship model as an alternative to Change-IDs in the ongoing standardization discussion. The email presents a concrete design that would track commit evolution through explicit trailer relationships rather than persistent identifiers.

Key technical aspects of the proposal:
- Introduces a "predecessor" trailer that parallels Git's parent-child relationships but for tracking patch evolution
- Handles four evolution scenarios: new changes (1), refined/merged changes (2), split changes (3), and optimized queries (4)
- Avoids centralized ID assignment by using direct commit references
- Maintains Git's distributed nature while providing explicit evolution semantics
- The model would form a parallel graph structure to the commit ancestry DAG
- Includes consideration for auxiliary data structures (similar to reachability bitmaps) for efficient traversal

The proposal directly addresses Martin von Zweigbergk's concern about Change-IDs not handling complex distributed cases well, while avoiding the need for heuristic matching that Theodore Ts'o's series ID approach would require. However, it introduces new implementation complexity around graph traversal and tooling support.

This represents a significant architectural shift in the discussion from ID-based approaches to relationship-based modeling. The proposal is technically elegant but would require substantial implementation work and tooling changes compared to the alternatives. It notably doesn't address migration paths from existing Change-ID systems, which remains an open question in the thread.
