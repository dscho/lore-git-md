This is a refactoring patch in Karthik Nayak's batched reference updates series (v6 2/8), moving duplicate refname checking from individual backends to the generic refs layer. The change centralizes what was previously redundant logic across the files, packed, and reftable backends.

The key technical elements are:
- Adds a `refnames` string_list to `ref_transaction` to track all references in a transaction
- Updates are automatically added to this list in `ref_transaction_add_update()`
- Backends now check for duplicates using this centralized list rather than maintaining their own
- Special handling remains for HEAD/symref updates to maintain atomicity guarantees
- The reftable backend moves its duplicate check before adding updates to avoid false positives

The patch removes ~114 lines of backend-specific code while maintaining all safety checks. This follows the series' pattern of consolidating backend logic where possible. The changes have been reviewed by Patrick Steinhardt and others, with the reftable adjustments being the last major backend integration needed for this feature.

This is a straightforward infrastructure improvement that doesn't change user-visible behavior but makes the codebase more maintainable. The centralized checking will make future ref transaction changes easier to implement consistently across all backends.
