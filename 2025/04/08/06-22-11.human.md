This is a feature patch series introducing a new "reflog-expire" maintenance task, continuing the broader effort to modernize Git's maintenance system. The series refactors reflog expiration internals to remove global state before adding the functionality to `git maintenance`.

The key technical changes move reflog expiration configuration from global variables into a proper `reflog_expire_options` struct, making the code more maintainable and encapsulated. The final patch then exposes this as a new maintenance task, addressing a gap where reflog entries couldn't be expired when `git gc` was disabled.

Patrick Steinhardt positions this as part of the long-term transition from `git gc` to the more flexible maintenance subsystem, suggesting a phased rollout: first enabling the new task for the "incremental" strategy, then making that strategy experimental, and eventually the default. The series has already undergone technical review, with consensus emerging around the incremental approach despite some acknowledged architectural tradeoffs.

The changes are well-contained (6 patches touching 7 files) and build on prior discussion about maintenance system design. This appears to be a thoughtful, incremental improvement that moves Git toward more configurable maintenance while cleaning up some technical debt in the reflog expiration code.
