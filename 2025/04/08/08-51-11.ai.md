This is the final implementation patch in Karthik Nayak's series enabling batched reference updates with partial failure support. The patch focuses on integrating the rejection mechanism into the filesystem directory (F/D) conflict checking logic.

The key change modifies `refs_verify_refnames_available()` to support per-update rejection when checking for F/D conflicts, rather than failing the entire transaction. The function now:
- Takes a `ref_transaction` parameter to track rejected updates
- Uses `ref_transaction_maybe_set_rejected()` to mark individual conflicted updates
- Maintains a `conflicting_dirnames` set to efficiently track already-rejected paths
- Preserves the original error reporting behavior when not in batched mode

The patch also:
- Moves `refs_verify_refnames_available()` from refs.h to refs-internal.h since it's now backend-internal
- Updates both files and reftable backends to pass transaction context
- Adds proper memory management for the string_list utilities tracking update positions
- Files backend changes include:
  * Modified `lock_raw_ref()` to track update indices
  * Updated `lock_ref_for_update()` to pass through the index
  * Proper cleanup of the refnames_to_check list

- Reftable backend changes mirror the files backend:
  * `prepare_single_update()` now tracks update indices
  * Proper cleanup of refnames_to_check list

This completes the core rejection infrastructure for the last major case (F/D conflicts) while maintaining the atomicity guarantees of reference updates. The changes are consistent with the series' goal of allowing partial failures while keeping the transaction atomic where needed.
