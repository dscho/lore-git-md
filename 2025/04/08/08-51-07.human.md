This is a refactoring patch in Karthik Nayak's batched reference updates series (v6 3/8). It removes redundant duplicate reference name checking in the files backend, since the same check is already performed during the transaction's prepare phase. The patch makes the code more efficient by eliminating unnecessary work while maintaining the same safety guarantees.

The change consists of:
1. Removing the duplicate check from `files_transaction_finish_initial()`
2. Making `ref_update_reject_duplicates()` static since it's now only used within refs.c
3. Moving the function's documentation to its new location

This is a straightforward cleanup that follows the series' earlier work to centralize refname duplicate checking in the generic refs layer. The patch is in its sixth iteration and has been thoroughly reviewed, with no technical concerns remaining. It's a small but meaningful optimization that removes about 16 lines of code while improving maintainability.
