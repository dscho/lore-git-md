Performance optimization for bundle creation's O(N^2) refname duplicate checking. This is the second version of a two-patch series that addresses a scalability issue where bundle creation time grows quadratically with the number of references. The problem was identified through benchmarking showing a 2200x slowdown at 100k refs compared to 100 refs.

The series first adds comprehensive test coverage in t6020-bundle-misc.sh, including discovery of a previously missed edge case. The main optimization replaces the quadratic `object_array_remove_duplicates()` with an O(1) `strset`-based solution in `write_bundle_refs()`, achieving a 6x speedup (14.6s → 2.4s at 100k refs) and restoring linear scaling. The v2 change is minimal - switching from explicit `strset_init()` to the `STRMAP_INIT` macro as suggested in review. The implementation has been verified to correctly handle both same-refname cases (regardless of object identity) and exclusion patterns.

The thread shows consensus on the solution's correctness, with the only remaining style point addressed in this revision. The changes affect bundle.c, object.c, and object.h, with the latter two seeing deletions of now-unneeded code. A potential merge conflict with ps/object-wo-the-repository is noted as easily resolvable. This appears ready for merging as a clear performance win with thorough test coverage.
