Refactoring patch splitting object store functionality from object-file.c.

This is patch 4/9 in Patrick Steinhardt's series to reorganize Git's object-file subsystem. The patch moves object store-related functions from object-file.c to a new object-store.c file, continuing the architectural cleanup to enable future modular object storage backends.

The changes are mechanical - functions are relocated with minimal modifications, maintaining all existing behavior. Key functionality moved includes:
- Alternate object database handling (prepare_alt_odb, link_alt_odb_entries, etc.)
- Object lookup and caching (oid_object_info_extended, repo_read_object_file)
- Object existence checks (has_object, repo_has_object_file)
- Temporary object store management (set_temporary_primary_odb)

The patch touches 20 files, with nearly 1000 lines moved from object-file.c to the new location. Header files are updated to reflect the new organization. This is a significant but straightforward relocation that follows the pattern established in earlier patches of the series.

Reviewers should verify the moves didn't introduce any subtle behavior changes, particularly around platform-specific error cases. The changes align with the series' goal of separating generic utilities from object-specific code.
