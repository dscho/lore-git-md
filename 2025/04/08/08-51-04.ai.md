Feature enhancement for batched reference updates with partial failure support (v6 cover letter).

This is the sixth version of Karthik Nayak's series introducing batched reference updates with partial failure support, now with final documentation formatting fixes. The series builds on Patrick Steinhardt's earlier optimizations and has undergone extensive review, with all major technical questions resolved and explicit approvals from key maintainers.

The core change enables reference updates to proceed partially when some updates fail, while still using the transaction infrastructure for optimization. This is exposed through a new `--batch-updates` flag for `git update-ref --stdin`. The implementation includes:

1. Refactoring of reference update checking logic, moving duplicate checks to the generic layer
2. Reftable backend restructuring to extract transaction preparation code
3. Introduction of typed transaction errors via `enum ref_transaction_error`
4. Core infrastructure for tracking and reporting rejected updates while allowing transactions to proceed
5. Backend support across files, packed, and reftable storage
6. User-facing `--batch-updates` flag with comprehensive test coverage

The v6 changes focus on documentation formatting, ensuring the `git-update-ref` manpage synopsis properly shows distinct command forms (each prefixed with "git update-ref") rather than appearing as continuation lines. This follows Jean-Noël Avila's and Junio C Hamano's documentation review and Karthik's confirmation of the whitespace fixes.

Key technical aspects preserved from previous versions:
- Strongly-typed error handling system
- Centralized refname duplicate checking
- Files backend optimizations (strbuf usage, strset for conflict detection)
- Complete NUL-terminated input/output behavior
- Special handling for HEAD/symref updates
- Minimal performance impact (~2% degradation for 100k refs)

The series is now fully vetted and ready for merging, with all architectural elements approved and documentation conforming to project standards. The changes are particularly valuable for tools and workflows needing to handle reference update failures gracefully while maintaining transaction optimizations.
