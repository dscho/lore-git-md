Refactoring patch in Patrick Steinhardt's object-file.c split series (6/9). This moves index-related functionality from object-file.c to read-cache.c, continuing the architectural separation between object storage and index operations.

The patch relocates several key functions for indexing files and memory buffers into the index subsystem:
- `index_mem()` - core function for hashing/writing objects from memory
- `index_fd()` - handles different file types (regular, symlink, pipe)
- `index_path()` - public interface for indexing filesystem paths
- Supporting functions like `index_stream_convert_blob()` and `index_core()`

The changes include moving flag definitions (`INDEX_WRITE_OBJECT`, etc.) to read-cache.h and updating includes in 10 affected files. The implementation remains functionally identical - this is purely an organizational change to group index-related code together.

Key technical details preserved:
- All conversion logic (EOL, filters) via `get_conv_flags()`
- Special handling for large files via `index_blob_stream()`
- Error reporting through `hash_format_check_report()`
- Platform-specific behaviors around mmap and file handling

This continues the series' pattern of methodically separating concerns while maintaining exact behavior. Reviewers should verify the moved code integrates cleanly with existing index operations and that no subtle platform-specific behaviors were affected by the relocation. The changes support the larger goal of modular object storage by clarifying index/object-store boundaries.
