Feature patch completing a series to add reflog expiration as a standalone maintenance task. This final patch in the 6-part series introduces the actual "reflog-expire" task to git-maintenance, allowing it to replace the reflog expiration functionality previously only available through `git gc`.

The implementation provides both direct execution (running `git reflog expire --all`) and auto-mode behavior with configurable thresholds. The auto-mode uses a lightweight heuristic checking only the HEAD reflog for expired entries, with the threshold controlled by `maintenance.reflog-expire.auto` (default 100). Negative values force execution, zero disables auto-mode, and positive values set the minimum number of expirable entries required.

The patch includes thorough documentation updates and tests verifying both direct execution and auto-mode behavior. It builds on the refactoring work from previous patches that moved reflog expiration logic out of global variables and into proper structures, now making that logic available to both `git gc` and the new maintenance task.
