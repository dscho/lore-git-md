Refactoring patch in the reflog expiration series. This is the third patch in a 6-part series that moves reflog expiration state out of global variables and into a proper options structure.

The patch continues the work of encapsulating reflog expiration state by moving the per-reflog expiry dates (previously stored in a global linked list) into the `reflog_expire_options` struct. It introduces a new `reflog_expire_entry_option` struct to hold the pattern-matching expiry rules and updates all related functions to use this new structure.

The changes are mechanical but important for making the reflog expiration code more maintainable and suitable for the new maintenance task system. The patch maintains all existing behavior while improving the code structure. This follows the incremental approach discussed earlier in the thread, where some architectural tradeoffs were acknowledged but deemed acceptable for this stage of the work.

The implementation looks clean and well-contained, with corresponding updates to both the implementation in builtin/reflog.c and the interface in reflog.h. This continues the series' pattern of careful, focused refactoring steps toward the larger goal of making reflog expiration work as a maintenance task.
