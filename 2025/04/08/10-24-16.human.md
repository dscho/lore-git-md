This is patch 8/9 in Patrick Steinhardt's series refactoring Git's object storage system, moving the global cached objects array into the raw object store structure. The patch eliminates a global variable that was used to store temporary "fake" objects (like those created during git-blame operations) by moving the storage into the repository-specific object store. This continues the series' goal of making the object database more library-friendly by removing global state.

The changes are straightforward but touch several key areas: the cached object lookup logic now takes the object store as a parameter, the pretend_object_file() interface is updated to accept a repository parameter, and proper cleanup is added for cached objects when the object store is cleared. The implementation maintains all existing functionality while better encapsulating the cached object state.

This is a well-contained change that follows the series' established pattern of methodically moving global state into repository-specific storage. The patch appears carefully implemented with proper memory management and maintains thread safety by keeping the cached objects tied to their repository instance. It's another solid step toward the series' ultimate goal of enabling pluggable object storage backends.
