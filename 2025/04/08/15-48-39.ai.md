This is part of the major refactoring series to remove the legacy merge-recursive implementation in favor of merge-ort. Patch 5/8 focuses on converting the remaining callers in `builtin/merge.c` and `sequencer.c` to use `merge_ort_recursive()` instead of the old `merge_recursive()`.

The changes are straightforward mechanical conversions:
1. In `builtin/merge.c`, the conditional calling either ort or recursive is replaced with a direct call to `merge_ort_recursive()`
2. In `sequencer.c`, the similar conditional is removed in favor of always using ort
3. A test script (`t7615`) is updated to remove the explicit `GIT_TEST_MERGE_ALGORITHM=recursive` setting since it's no longer needed

The patch maintains all existing behavior while removing the merge-recursive code path. The sequencer changes include updating a comment to reference `merge_ort_recursive()` instead of the old function. This continues the systematic approach seen in previous patches of the series, with the test changes verifying we don't regress existing functionality.

Key technical details for future reference:
- Files modified: `builtin/merge.c`, `sequencer.c`, `t/t7615-diff-algo-with-mergy-operations.sh`
- Functions changed: `try_merge_strategy()`, `do_merge()`
- Test changes: Removal of `GIT_TEST_MERGE_ALGORITHM=recursive` in t7615
- Behavior remains identical, just with the underlying implementation switched

This patch represents one of the final steps in eliminating merge-recursive, with all major callers now converted to use merge-ort exclusively. The changes are low-risk since merge-ort has been the default merge strategy since Git 2.33.0.
