Feature completion for batched reference updates with partial failure support. This is the final patch in Karthik Nayak's series implementing atomic reference updates with graceful partial failure handling across all Git ref backends.

The patch adds a `--batch-updates` flag to `git update-ref --stdin` that allows transactions to continue even when individual reference updates fail, reporting rejected updates in a standardized format. This builds on the infrastructure added in previous patches, including strongly-typed error codes and backend-specific handling. The implementation distinguishes between system errors (which still abort the entire transaction) and user-input errors (which can be rejected individually).

The patch includes thorough documentation updates and extensive test coverage (233 lines) for various failure scenarios: invalid OIDs, non-existent refs, dangling symrefs, refname conflicts, and incorrect old values. The tests verify that valid updates succeed while rejected ones are properly reported without affecting other updates in the batch.

This completes the series which has already received positive technical reviews from Patrick Steinhardt and others, with all architectural questions resolved. The feature provides a robust solution for scripts and tools that need to attempt multiple reference updates while handling partial failures gracefully.
