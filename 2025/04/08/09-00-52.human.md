Test coverage for bundle refname deduplication.

This is the first patch in a two-part performance optimization effort addressing O(N^2) scaling in bundle creation. Karthik Nayak lays groundwork by adding comprehensive test coverage for how Git currently handles duplicate refnames during bundle creation, documenting both correct behavior and known limitations.

The new tests in t6020-bundle-misc.sh verify four scenarios: direct duplicate refnames, duplicates when using --all alongside manual references, exclusion patterns (main^!), and short/long refname variants. The tests confirm that while some duplicates are properly filtered (like simple duplicates and exclusion patterns), others slip through (notably short/long name variants and certain --all cases).

The commit message clearly ties this to historical context (commit b2a6d1c686) and positions these tests as prerequisite validation for the upcoming optimization. The test suite appears thorough, with clear expectations and comments flagging current buggy behavior that the next patch will address. This is a solid foundation for the performance work to follow.
