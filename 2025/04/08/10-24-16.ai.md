This is patch 8/9 in Patrick Steinhardt's series refactoring Git's object storage subsystem, moving away from global variables toward repository-specific storage. The patch relocates the management of cached objects (temporary in-memory objects like those used by `git blame`) from a global array to being repository-specific within the `raw_object_store` structure.

The changes involve:
1. Moving the `cached_objects` array and its management fields (`cached_object_nr`, `cached_object_alloc`) into `struct raw_object_store`
2. Updating all related operations to work with the repository-specific storage
3. Adding proper cleanup in `raw_object_store_clear()`
4. Modifying `pretend_object_file()` to take a `repository` parameter
5. Updating `blame.c` to pass the repository parameter

Key technical details include:
- The cached object system allows creating temporary objects without writing to disk (used by `git blame` for working tree files)
- Thread safety is maintained as the storage is now repository-specific
- The empty tree object handling remains special-cased
- All memory management is properly handled during store clearance
- The change touches core object lookup paths (`find_cached_object`, `do_oid_object_info_extended`)

This continues the series' pattern of methodically eliminating global state while maintaining all existing functionality. The patch appears thorough, with proper memory management and updates to all affected callers. The changes are focused and well-contained within the object storage subsystem refactoring effort.
