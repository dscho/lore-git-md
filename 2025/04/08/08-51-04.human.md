This is a feature patch series introducing batched reference updates with partial failure support, now in its 6th iteration. The series is effectively complete, having received explicit approval from key reviewers and documentation polish from multiple contributors.

The core functionality allows `git update-ref --stdin` to process multiple reference changes while gracefully handling individual failures via a new `--batch-updates` flag. This maintains transaction infrastructure's optimizations while relaxing the all-or-nothing requirement. The implementation spans all ref backends (files, packed, reftable) with comprehensive error handling through a new `enum ref_transaction_error` type system.

Version 6 focuses solely on final documentation formatting, fixing how the `git-update-ref` manpage presents alternative command forms. Each invocation pattern now properly repeats the command name per standard conventions, addressing whitespace issue noted in v5. The technical implementation remains unchanged from the v5 version that Patrick Steinhardt approved, which included:
- Centralized refname duplicate checking
- Optimized directory conflict detection
- Strongly-typed error classification
- Backend-specific handling for partial failures
- Careful preservation of atomic behavior for critical system errors

The series builds on earlier work to batch refname availability checks and has undergone extensive review, including input from Patrick Steinhardt on the reftable backend, Jean-Noël Avila on documentation, and Junio Hamano on architectural decisions. With all technical questions resolved and documentation now properly formatted, this appears ready for merging.
