This is part of the ongoing `the_repository` removal effort and the larger merge-ort migration series. The patch focuses on the sequencer component, specifically the `do_recursive_merge()` function which despite its name handles non-recursive merges.

The change removes the legacy merge-recursive backend code path from `do_recursive_merge()`, hardcoding it to always use merge-ort. This is a safe change since merge-ort has been the default backend for non-recursive merges for a long time. The patch simplifies the function by eliminating the conditional logic that previously allowed selecting between merge-recursive and merge-ort backends.

Key technical details include:
- Removal of 22 lines handling the merge-recursive path
- merge_incore_nonrecursive()` is now the only merge backend called
- The TODO comment about index/working tree updates remains unchanged
- The change maintains all existing merge result handling and output behavior

This is patch 4/8 in v3 of the series, following the earlier conversions of checkout.c and builtin/merge-recursive.c to merge-ort. The change is mechanical and low-risk, being part of the final cleanup phase where merge-recursive support is being completely removed from the codebase. The patch maintains behavioral compatibility while simplifying the code.
