This is part of the ongoing merge-ort migration series, specifically converting the builtin/merge-recursive.c caller to use merge-ort instead of the legacy merge-recursive backend. The patch makes a straightforward function substitution from merge_recursive_generic() to merge_ort_generic() while maintaining identical parameters and error handling.

The bulk of the changes are test updates reflecting merge-ort's different behavior in several areas: improved directory/file conflict handling (t6430), proper rename/delete conflict resolution (t6434), and removal of merge-recursive's special toplevel tree matching check (t6424). The test changes align with known merge-ort improvements documented in prior commits (ef527787089c, 1f3c9ba707, 727c75b23f).

Key technical details include the direct function swap in builtin/merge-recursive.c and the test adjustments that verify merge-ort's different (but improved) handling of edge cases. The patch removes one test case (merge-recursive's base tree name tracking) that was specific to merge-recursive's implementation and not relevant to merge-ort. This continues the series' pattern of mechanical conversions while updating tests to expect merge-ort's behavior.

The change is low-risk as it follows the established pattern from previous conversions in the series, with test coverage verifying the behavior matches expectations. This represents another step toward the series' ultimate goal of completely removing merge-recursive.[ch].
