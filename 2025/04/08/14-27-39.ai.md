This is a conceptual proposal in the ongoing Change-ID standardization discussion, where Junio Hamano suggests an alternative approach to tracking commit evolution in distributed workflows.

Junio proposes replacing Change-IDs with explicit predecessor-successor relationships recorded in commit trailers, drawing parallels to Git's existing parent-child commit structure. The proposal outlines four key scenarios this would support: (1) new standalone changes, (2) refined/merged changes, (3) split changes, and (4) efficient querying via auxiliary data structures. The approach aims to avoid Change-ID collision issues while maintaining distributed workflow compatibility.

The email directly addresses Martin von Zweigbergk's earlier point about Change-IDs being insufficient for complex distributed cases, offering a more Git-native solution than either the Change-ID or patch series ID proposals. Junio's suggestion introduces a new concept of "predecessor" trailers that would form a directed acyclic graph of change evolution, similar to Git's commit DAG but tracking logical change relationships rather than ancestry.

This represents a significant new direction in the thread, moving beyond the Change-ID vs patch series ID debate to propose a fundamentally different metadata model. The approach would require tooling changes to interpret the new predecessor relationships but avoids centralized ID assignment. The proposal doesn't address implementation details or migration paths from existing Change-ID systems, focusing instead on the core conceptual model.
