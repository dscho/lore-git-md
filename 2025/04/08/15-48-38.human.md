This is part of the major refactoring series to fully replace the legacy merge-recursive implementation with merge-ort. Patch 4/8 focuses on the sequencer component, specifically the `do_recursive_merge()` function which despite its name handles non-recursive merges.

The patch simplifies the sequencer's merge logic by removing the now-unused code path for the recursive backend, since merge-ort has been the default for years. The change is straightforward - it eliminates the conditional that previously allowed selecting between backends, keeping only the merge-ort implementation. A TODO remains about optimizing when to update the index/working tree during rebase operations, but this doesn't block the current change.

This continues Elijah Newren's systematic approach to removing merge-recursive, with each patch carefully converting one component at a final cleanup patch that will remove the old implementation entirely. The change is well-contained and builds on the established pattern seen in earlier patches of the series.
