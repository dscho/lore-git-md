This is a refactoring patch from Karthik Nayak's batched reference updates series (v6 2/8), moving duplicate refname checking from individual backends to the generic refs layer. The change centralizes what was previously redundant logic across the files, packed, and reftable backends.

The patch adds a new `refnames` string_list to the `ref_transaction` struct to track all reference names in a transaction. The list is populated automatically in `ref_transaction_add_update()` (except for log-only updates) and used for duplicate detection. Each backend is updated to use this centralized list rather than maintaining their own tracking, with careful attention to the order of operations in the reftable backend where the check must happen before adding the update.

The changes are mechanical but thorough, removing over 100 lines of redundant code while maintaining all safety checks. This is part of the final cleanup for the series after extensive review, with all technical aspects already approved by maintainers. The patch follows the established pattern of the series by keeping behavior identical while simplifying the implementation.
