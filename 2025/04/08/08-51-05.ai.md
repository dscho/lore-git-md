Refactoring patch in the batched reference updates series. This is the first of eight patches in v6 of the series, which has already undergone extensive review and is now focused on final documentation and code cleanups.

The patch removes redundant duplicate-checking logic in the files backend's reference update handling. The key changes are:

1. Eliminates a second check for duplicate refnames in `split_symref_update()` since the initial `string_list_has_string()` call already prevents duplicates.
2. Simplifies related code in `split_head_update()` and `files_transaction_prepare()` by removing now-unnecessary `item->util` assignments that were only used for duplicate checking.
3. Maintains the same safety guarantees while reducing code complexity - the BUG() checks for unexpected duplicates remain in place through other mechanisms.

This cleanup builds on the series' earlier work to centralize refname duplicate checking in refs.c. The changes are straightforward and maintain all existing functionality while removing now-redundant code paths. The patch aligns with the series' overall goal of optimizing reference transaction handling while preserving atomicity guarantees.
