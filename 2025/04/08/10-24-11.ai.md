Refactoring patch in the ongoing object-file.c split series. This is patch 3/9 in Patrick Steinhardt's series to reorganize Git's object storage code, moving the `xmmap()` family of functions from object-file.c to wrapper.c.

The patch relocates three related functions: `xmmap()` (the main wrapper that dies on error), `xmmap_gently()` (its non-fatal variant), and `mmap_os_err()` (a Linux-specific error message helper). The functions are moved verbatim with no changes to their implementation, just a change of file location. The commit notes this is appropriate since these are general-purpose memory mapping utilities rather than object-file-specific code.

Key technical details: The functions handle memory mapping with size limits (via GIT_MMAP_LIMIT), include platform-specific error handling for Linux ENOMEM cases, and maintain the same behavior where zero-length mappings return NULL rather than MAP_FAILED. The move follows the series' pattern of identifying generic utilities in object-file.c and relocating them to more appropriate homes.

This continues the architectural cleanup needed for future pluggable object storage backends. The change is straightforward and low-risk since it's a pure code movement with no behavior changes. Reviewers should verify the Linux-specific error handling remains properly scoped and that no subtle platform differences exist in the new location.
