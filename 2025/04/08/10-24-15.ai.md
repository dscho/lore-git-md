This is part 7/9 of Patrick Steinhardt's series refactoring Git's object-file subsystem, specifically focusing on moving object store management functions from object.c to object-store.c. The patch continues the architectural cleanup by relocating core object store lifecycle functions.

The changes move several key object store management functions to their logical home in object-store.c:
- `free_object_directory()` and its helper `free_object_directories()`
- `raw_object_store_new()` for initialization
- `raw_object_store_clear()` for cleanup
The patch maintains all existing functionality while better organizing the code. The moved functions handle:
- Object directory lifecycle (creation, destruction, cleanup)
- Packfile management
- Commit-graph handling
- Alternate object database management
- Key data structures affected:
  - `struct object_directory`
  - `struct raw_object_store`
  - `struct packed_git`

The changes touch core object store management paths but are straightforward relocations with no behavior modifications. This continues the series' pattern of methodically separating concerns between object storage management (now in object-store.c) and object handling logic (remaining in object.c). Reviewers should verify the moves didn't accidentally alter any error handling or cleanup behaviors, particularly around:
- Thread safety (note the `replace_mutex` handling)
- Resource cleanup paths
- Packfile and commit-graph management

This patch builds on the previous separation work and maintains the careful attention to platform-specific behaviors seen throughout the series. The changes are mechanical but important for the overall goal of cleaner subsystem separation.
