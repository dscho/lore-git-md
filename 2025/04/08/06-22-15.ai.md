Refactoring patch in the reflog expiration series, moving configuration handling functions to shared location.

This is patch 4/6 in Patrick Steinhardt's series to add reflog expiration as a maintenance task. The patch relocates three key functions from `builtin/reflog.c` to `reflog.c` and exposes them via `reflog.h`:

1. `find_cfg_ent()` - Manages the linked list of per-ref expiration patterns
2. `reflog_expire_config()` - Handles configuration parsing for expiration settings
3. `reflog_expire_options_set_refname()` - Applies expiration rules to specific refs

The changes include:
- Moving 111 lines from builtin to shared location while preserving all functionality
- Adding corresponding declarations to `reflog.h` with documentation
- Replacing magic numbers with named constants (`REFLOG_EXPIRE_TOTAL`/`UNREACH`)
- Updating call sites to use the new public API

This is a straightforward code movement that enables future patches to use these functions outside the reflog builtin. The thread context shows this is part of a larger effort to make reflog expiration usable by the maintenance subsystem while removing global state. Previous discussion established consensus on this incremental approach despite some architectural limitations in the current design.
