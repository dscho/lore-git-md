Refactoring patch in the object-file subsystem reorganization series. This is patch 2/9, moving the architectural cleanup forward by relocating the `git_open_cloexec()` function from object-file.c to compat/open.c.

The change recognizes that `git_open_cloexec()` is a general-purpose file opening utility (providing cross-platform O_CLOEXEC support) rather than being object-storage specific. The implementation remains functionally identical but now lives in a more logical location. The patch makes compat/open.c unconditionally compiled (previously it was conditional on OPEN_RETURNS_EINTR systems) while keeping the EINTR-retry logic gated by that same flag.

The mechanical changes include:
- Moving the function implementation to compat/open.c
- Updating Makefile and meson.build to always compile compat/open.o
- Removing the conditional COMPAT_OBJS assignment for open.o
- Removing now-unnecessary #includes of object-file.h from 6 files that only needed git_open_cloexec()
- Adding the declaration to git-compat-util.h

This follows the pattern established in patch 1/9 (directory utilities move) and aligns with the series' goal of disentangling generic utilities from object-file.c. The change appears straightforward with no intended behavior modification, though reviewers should verify the platform-specific aspects (O_CLOEXEC fallback handling) remain correct across systems.
