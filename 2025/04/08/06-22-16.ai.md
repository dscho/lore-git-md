Refactoring patch in the reflog-expire maintenance task series.

This is patch 5/6 in Patrick Steinhardt's series to add reflog expiration as a maintenance task. The patch extracts the reflog expiration logic from `cmd_gc()` into a new `maintenance_task_reflog_expire()` function, making it reusable by both `git gc` and the upcoming maintenance task. The change removes the global `reflog` strvec and replaces its direct use with the new function call.

The implementation is straightforward - it creates a child process to run `git reflog expire --all` with the same behavior as before. The patch maintains all existing functionality while improving code organization. This follows the series' pattern of incrementally refactoring reflog expiration to remove global state while preparing for maintenance task integration.

The thread context shows this is part of a broader effort to modernize Git's maintenance system, with previous patches having already refactored reflog expiration's configuration handling. Reviewers have noted some architectural tradeoffs in the approach, but consensus seems to favor this incremental improvement over a more disruptive redesign.
