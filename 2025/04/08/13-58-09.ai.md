Feature proposal feedback on the `git repo-info` command extraction from `rev-parse`.

Karthik Nayak provides detailed feedback on Moumita Dhar's GSoC proposal to create a new `git repo-info` command that would house non-revision-parsing functionality currently in `git rev-parse`. The feedback focuses on several key areas that need clarification or improvement in the proposal.

First, Karthik suggests expanding the scope to include all "Options for Files" from `rev-parse`'s manpage and requests more technical details about the new command's design - specifically its naming justification, default output format, and option migration strategy. He emphasizes the importance of early mailing list engagement for design feedback.

The timeline critique notes that the current plan appears to batch work for a single large submission at the end, whereas Git's workflow favors smaller, merge-ready patch series with integrated documentation and tests for each component. Karthik questions several technical terms used ("dispatcher", "unification") that lack clear definitions in the Git context.

Key implementation questions include the use of `json-writer.[c,h]` for structured output and whether tests are being written incrementally. Karthik stresses that documentation should accompany each functional change rather than being deferred to the end. The feedback concludes by appreciating the proposal while underscoring Git's iterative development culture where each patch series should be independently reviewable.
