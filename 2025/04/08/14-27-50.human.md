This is a technical proposal in the ongoing Change-ID standardization discussion, where Junio Hamano introduces a novel DAG-based model for tracking commit evolution.

Junio responds to Martin von Zweigbergk's observation about the limitations of Change-IDs in distributed workflows by proposing a predecessor-successor relationship model that mirrors Git's existing commit ancestry DAG. The key idea is to replace persistent Change-IDs with explicit trailer relationships between commits, forming a parallel graph that tracks how changes evolve. The proposal outlines four scenarios this would handle: new standalone changes (root nodes), refined/merged changes (merge-like), split changes (multiple successors), and efficient querying via auxiliary data structures.

The approach aims to solve the distributed workflow challenges Martin identified while avoiding the need for centralized ID assignment. Junio suggests this would be more Git-native than the existing Change-ID or series ID proposals, though it would require implementing new graph traversal logic. The email doesn't address implementation details but presents the conceptual framework as a potential direction that might unify the thread's competing proposals.

This represents a significant evolution in the technical discussion, moving from ID-based tracking to relationship-based evolution modeling. The proposal appears well-considered and directly targets the distributed workflow limitations that have been a sticking point in previous discussions, though its implementation complexity would likely be higher than the alternatives.
