This is a refactoring patch in Karthik Nayak's batched reference updates series, converting preprocessor-defined transaction error codes into a strongly-typed enum `ref_transaction_error`. The change improves type safety and makes error handling more explicit while maintaining all existing error cases.

The patch introduces a new `enum ref_transaction_error` in refs.h with seven distinct error codes covering various failure scenarios like name conflicts, existence checks, and value mismatches. It then updates all backend implementations (files, packed, reftable) and callers (like builtin/fetch.c) to use these typed errors instead of the old integer constants. The error handling logic remains functionally equivalent but becomes more self-documenting through the enum names.

Key technical details include:
- New error codes like `REF_TRANSACTION_ERROR_NAME_CONFLICT`, `REF_TRANSACTION_ERROR_CREATE_EXISTS`, and `REF_TRANSACTION_ERROR_INCORRECT_OLD_VALUE`
- Updates to all refs backend interfaces to return the enum type
- Consistent error mapping across files, packed, and reftable backends
- Preservation of existing error messages and behavior
- Preparation for future batched update error handling

The changes are mechanical but touch many files (7 modified, 207 insertions, 186 deletions) as they propagate the enum through the refs subsystem. This is part of the larger effort to support atomic reference updates with partial failure handling, with all technical aspects already reviewed and approved in previous iterations.
