This is a status update on the `kn/non-transactional-batch-updates` feature series, which introduces best-effort batched reference updates. The series allows performing multiple reference updates where some can fail without aborting the entire batch, unlike the current all-or-nothing transactional approach.

Karthik Nayak confirms the series is nearly ready for merging, needing only a squash commit as previously noted by Junio Hamano. The 10-commit series includes core refs infrastructure changes to support partial success in batch updates, optimizations from the `ps/refname-avail-check-optim` branch, and a new `--batch-updates` flag for `git update-ref`. 

The work appears well-integrated with both files and reftable backends, having gone through multiple iterations (v5 was referenced). Junio's "What's cooking" report indicates this is expected to be a final reroll before potential merging, suggesting the technical approach has been vetted and the remaining work is minor cleanup. This represents a notable enhancement to reference operations, particularly for use cases where partial failures are acceptable.
