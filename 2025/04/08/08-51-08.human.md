Refactoring patch for the reftable backend in Karthik Nayak's batched reference updates series. This is patch 4/8 in the final v6 iteration of the work to implement atomic reference updates with partial failure support.

The patch extracts the core logic for preparing individual reference updates from `reftable_be_transaction_prepare()` into a new `prepare_single_update()` function. This consolidation moves all validation and preparation steps (object ID verification, HEAD reference handling, symref processing) into a single logical block, improving code organization. The change is purely structural with no functional modifications - it's groundwork for upcoming batched update support in the reftable backend.

The refactoring follows the pattern established in earlier patches of this series, continuing the effort to streamline the transaction preparation code. Reviewers have already approved the architectural approach in previous iterations, and this change maintains all existing behavior while making the code more maintainable. The patch touches only the reftable backend implementation file with significant line changes (237 insertions, 226 deletions) that are straightforward code motion.
