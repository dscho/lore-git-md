Feature completion for batched reference updates with partial failure support. This is the final patch in Karthik Nayak's series, adding the user-facing `--batch-updates` flag to `git update-ref --stdin` that enables partial failure handling for reference updates.

The patch introduces a new `--batch-updates` flag that modifies `--stdin` mode to continue processing updates even when individual ones fail due to user input errors (like invalid OIDs or refname conflicts), while still aborting for system errors. Failed updates are reported in a standardized format showing the refname, old/new values, and rejection reason. The implementation uses the `REF_TRANSACTION_ALLOW_FAILURE` flag and hooks into the rejection infrastructure built in previous patches.

Key components:
- New `print_rejected_refs()` callback formats error output consistently
- Error reporting covers all 7 `ref_transaction_error` cases with human-readable messages
- Extensive test coverage (233 lines) verifies behavior for various failure modes:
  - Invalid new OIDs (non-commits, malformed)
  - Nonexistent refs
  - Symref vs regular ref mismatches
  - Incorrect old values
  - Refname conflicts
- Documentation updates explain the new flag and output format

The patch completes the series' goal of atomic batched updates with graceful partial failure handling, maintaining all safety guarantees while providing better usability for scripts. With all technical questions resolved and comprehensive test coverage, this is ready for merging as the final piece of the batched updates feature.
