This is a conceptual proposal in the ongoing Change-ID standardization discussion, where Junio Hamano suggests an alternative approach to tracking commit evolution in distributed workflows.

Junio builds on Martin von Zweigbergk's observation that Change-IDs alone can't fully represent distributed evolution history. He proposes modeling predecessor-successor relationships directly in commit metadata, similar to how parent-child relationships work in Git's DAG. The proposal outlines four cases: root changes (no predecessors), refinements (one predecessor), squashed changes (multiple predecessors), and split changes (shared predecessor).

The key advantage over Change-IDs is avoiding global uniqueness requirements while still capturing evolution history. Junio suggests this could work with auxiliary data structures for efficient querying, similar to reachability bitmaps. The approach appears more Git-native than either Change-IDs or Theodore Ts'o's patch series ID proposal, though it would require new metadata handling.

This represents a significant third path in the standardization debate, offering a distributed solution that aligns with Git's existing commit graph model. However, like other proposals, it would need to demonstrate practical implementation feasibility and tooling integration. The idea seems particularly relevant for complex distributed workflows where multiple contributors might evolve changes independently.
