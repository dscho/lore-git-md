Refactoring patch introducing strongly-typed error handling for reference transactions. This is part 5/8 of Karthik Nayak's series implementing batched reference updates with partial failure support, now in its sixth iteration.

The patch replaces preprocessor-defined error codes (-1, -2, -3) with an explicit `enum ref_transaction_error` that documents all possible failure modes. The new enum includes clear cases for common scenarios like name conflicts, existence checks, and value mismatches. This improves type safety and makes error handling more discoverable while maintaining all existing error cases.

The change touches all major ref backends (files, packed, reftable) and updates callers like `builtin/fetch.c` to use the new enum values. The implementation looks thorough, with careful attention to maintaining backward compatibility in error reporting behavior. This appears to be a well-executed refactoring that paves the way for the series' upcoming batched update functionality while improving code clarity.
