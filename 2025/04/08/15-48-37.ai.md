This is a refactoring patch in the ongoing merge-ort migration series, specifically addressing diff algorithm handling parity between merge-ort and the legacy merge-recursive backend.

The patch makes merge-ort respect diff algorithm selection by removing its hardcoded histogram diff algorithm in merge_start() and moving the default to init_merge_options(). This change aligns merge-ort's behavior with merge-recursive's ability to use different diff algorithms, though merge-ort still defaults to histogram diff while merge-recursive defaults to myers. The documentation is updated to reflect that both strategies now accept the same diff algorithm options, removing merge-recursive-specific notes about this feature.

Key technical changes include:
- Removal of hardcoded DIFF_WITH_ALG(HISTOGRAM_DIFF) in merge-ort.c
- Addition of histogram diff as the default in init_merge_options() (shared by both backends)
- Documentation updates in merge-strategies.adoc to unify the option descriptions
- The change technically affects merge-recursive too, but this is noted as acceptable since those callers will be removed soon

This is a straightforward mechanical change that follows the series' pattern of aligning merge-ort's capabilities with merge-recursive's before removing the latter. The patch maintains consistency with the overall goal of making merge-ort a complete replacement while preserving existing functionality where appropriate. The documentation updates help users understand the now-unified diff algorithm options across both strategies.
