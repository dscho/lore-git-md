Refactoring patch moving directory creation utilities from object-file.c to dir.c, as part of a larger series splitting object-file.c into logical components.

This first patch relocates the `safe_create_leading_directories()` family and `mkdir_in_gitdir()` from object-file.c to dir.c, along with their associated enum and declarations. The commit message explains this is because they provide generic directory functionality unrelated to object storage. The changes are mechanical - moving code while updating 13 files' includes to point to dir.h instead of object-file.h where these utilities are now exposed.

The patch appears well-scoped and correctly implemented, with no behavior changes. It touches a moderate number of files (13) but all changes are straightforward header adjustments. This aligns with the series' goal of architectural cleanup by placing directory utilities in the more appropriate dir.c location. The move could help future efforts to modularize object storage by reducing object-file.c's scope.

Key technical details for future reference: moved functions are `safe_create_leading_directories()`, `safe_create_leading_directories_no_share()`, `safe_create_leading_directories_const()`, and `mkdir_in_gitdir()`, along with the `scld_error` enum. The implementation remains identical, just in a new file location. This is purely an organizational change with no functional impact.
