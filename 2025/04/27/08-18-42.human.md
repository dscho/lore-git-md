**Feature request for bisect workflow improvement**

Victor Engmark describes a workflow challenge when using `git bisect` with test files from a different branch. The current solution requires manually copying test files from the feature branch at each bisect step, which is cumbersome. The proposed workaround involves a shell script that extracts the test files from `my-test-branch` before each test run, then cleans up afterward.

The core issue is whether Git could provide a more native way to maintain certain files unchanged during bisection, particularly when those files are part of the test infrastructure rather than the code being bisected. The email doesn't propose a specific Git feature change, instead asking if there's a better existing approach.

This appears to be a genuine workflow pain point for testing scenarios where the test infrastructure evolves separately from the code being tested. The question is well-posed with a concrete example, making it easy to understand the use case. The solution might involve either documentation of existing features or consideration of new bisect functionality.
