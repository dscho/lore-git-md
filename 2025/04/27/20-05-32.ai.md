This is a discussion follow-up in the `git send-email` Outlook Message-ID handling thread, responding to Yao Zi's proposal for runtime detection of SMTP quirks rather than hardcoding Outlook-specific behavior. Aditya Garg explains why automatic detection isn't feasible across providers, noting key differences in SMTP responses between Outlook (which includes Message-IDs in responses) and Gmail (which provides only opaque strings). The email highlights Microsoft's non-standard behaviors (like using XOAUTH2 instead of OAUTHBEARER) as justification for the current hardcoded approach.

Technical points raised include: the impossibility of reliably comparing intended vs actual Message-IDs across providers, lack of standardization in SMTP server responses, and uncertainty about corporate email infrastructure variations. The response maintains that the current solution (hostname-based Outlook detection with configurable override) is the most practical approach, while leaving open the possibility of future expansion if Tencent or other providers' behaviors can be reliably characterized. The thread remains technically resolved with the core solution queued, but this exchange documents the rationale against more generalized detection approaches.
