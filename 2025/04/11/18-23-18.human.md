Bug investigation follow-up: This is a response to Ludo Pulles's bug report about Git incorrectly persisting in rebase state after interrupting `git am`. D. Ben Knoble confirms the behavior but suggests the issue might lie with `git status`'s detection mechanism rather than the core `git am` functionality. They note their shell prompt (using a contrib script) correctly shows "AM/REBASE" status, allowing them to use `git am --abort` to recover, while `git status` misreports the state as a rebase. The response raises an interesting question about potential divergence between how different parts of Git detect in-progress operations, though it doesn't propose a specific fix. The exchange highlights a real inconsistency in Git's state management that could confuse users.
