Here's a human-readable summary of the thread so far:

The thread discusses two significant UX issues with `git clone --bundle-uri`. Xavier Morel reported that when cloning large repositories (5M objects, ~10GB), there's no progress feedback during bundle processing - even with --verbose or --progress flags - making it hard to track progress. Additionally, when combined with --filter, the filters only apply to the post-bundle fetch, resulting in both slower performance and less space savings than expected.

Toon Claes confirmed these are known limitations. For the progress feedback issue, there have been multiple attempted fixes (including a v2 patch series and another approach), but technical challenges prevented them from being completed. The filter interaction problem appears more fundamental - the current bundle-uri design can't verify if advertised bundles match the filter criteria, so filtering only happens during the final fetch phase. 

While these issues are acknowledged, there doesn't appear to be active work addressing them currently. The progress reporting problem seems technically challenging but potentially solvable, while the filter interaction may require deeper design changes to the bundle-uri protocol itself. The thread provides links to past discussions for anyone interested in picking up this work.
