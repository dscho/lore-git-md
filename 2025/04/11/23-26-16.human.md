This is a cover letter for a patch series proposing a performance optimization for Git's repacking mechanism, specifically around how cruft packs interact with multi-pack indexes (MIDX).

Taylor Blau introduces an RFC series that aims to avoid including cruft packs in MIDX files when repacking, which could improve performance. The key idea is a new `--stdin-packs=follow` mode for `pack-objects` that ensures geometrically-repacked packs remain closed under reachability without needing to track cruft packs in the MIDX. The approach involves modifying how namehash traversal works during packing to include reachable objects not present in the included/excluded packs.

The 8-part series includes preparatory refactoring of `pack-objects` code, introduces the new `follow` mode, and modifies `repack` to leverage this for MIDX optimization. The changes touch core packing logic, repack behavior, and add new tests. Blau notes they've tested the approach but are seeking feedback on the fundamental soundness of the idea before diving into code review details.

This appears to be a well-motivated optimization from an experienced Git contributor, with thorough test coverage (adding 170+ lines of tests) and careful preparatory refactoring. The RFC nature suggests the author wants conceptual validation before implementation polish, making this likely to spark technical discussion about packing strategies.
