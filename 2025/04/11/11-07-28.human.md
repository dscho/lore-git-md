This is a feature proposal regarding UX improvements for `git clone --bundle-uri`. Xavier Morel reports that the command currently provides no progress feedback during bundle operations, even with `--verbose` or `--progress` flags, which is particularly noticeable when cloning large repositories (5M objects, ~10GB). They suggest adding progress indicators for the bundle download/application phase, similar to regular clone operations.

The email also raises a secondary point about potentially warning users when combining `--bundle-uri` with `--filter`, as their testing shows this combination results in both larger repositories and slower performance compared to using the bundle alone. The rationale is that filtering likely only applies to the post-bundle reconciliation fetch, which is small compared to the bundle transfer.

This appears to be a well-motivated UX improvement suggestion from someone who has tested the feature with real-world repository sizes. The lack of progress feedback seems like a genuine usability gap for a feature designed to handle large transfers, and the filter interaction warning could prevent suboptimal usage patterns. The proposal doesn't include implementation details but clearly identifies the problems and their impact.
