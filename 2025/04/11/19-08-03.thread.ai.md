Summary of git add pathspec matching bug:

Bug report from Piotr Siupa regarding unexpected wildcard matching behavior in `git add`. When a repository contains both a literal file named `f*` and another file matching the wildcard pattern `f*` (e.g. `foo`), the first `git add 'f*'` command only stages the literal `f*` file, failing to match `foo` as expected. The behavior corrects on subsequent runs where `foo` then gets staged. Reproducible in both stable (2.43.2) and development (2.49.0.805.g082f7c87e0) versions, indicating a longstanding issue rather than regression.

Technical details:
- Affects pathspec handling in `git add` when literal and wildcard matches coexist
- First run fails to match pattern-expanded files, subsequent runs succeed
- Minimal reproduction requires just two files: literal `f*` and matching `foo`
- Suggests caching or state issue in pathspec interpretation logic
- No data loss, just incomplete staging behavior violating user expectations

The well-formed report includes clear reproduction steps and version verification. The behavior contradicts expected wildcard matching semantics where `f*` should match both literal `f*` and pattern-matched `foo` simultaneously.
