This is patch 6/9 in Patrick Steinhardt's v2 series refactoring Git's object-file subsystem, specifically moving index-related functions to their proper home in read-cache.c. The patch relocates 225 lines of index-related functionality from object-file.c to read-cache.c while maintaining all existing behavior.

Key technical details:
- Moves core index operations like `index_mem()`, `index_fd()`, and `index_path()` to read-cache.c
- Transfers related helper functions including:
  * `index_stream_convert_blob()` for filtered content
  * `index_pipe()` for non-regular files
  * `index_core()` for regular file handling
  * `index_blob_stream()` for large blobs
- Updates flag definitions (`INDEX_WRITE_OBJECT` etc.) and moves them to read-cache.h
- Maintains all existing functionality including:
  * EOL conversion handling
  * fsck validation
  * Bulk checkin integration
  * Platform-specific considerations
- Requires updating includes in 6 files that previously used object-file.h for index operations

The relocation follows the series' architectural goal of separating index operations (now in read-cache.c) from core object operations (remaining in object-file.c). This continues the pattern established in earlier patches of moving memory-mapping utilities to wrapper.c and object store operations to object-store.c. The changes are purely organizational with no functional modifications.
