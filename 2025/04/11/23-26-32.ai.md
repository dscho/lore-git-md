This is the fifth patch in Taylor Blau's RFC series optimizing cruft pack and MIDX interactions during repacking. The patch focuses on improving delta compression for loose objects when using `--unpacked` with `--stdin-packs`.

The key technical change modifies how loose objects are handled during pack creation. Previously, loose objects added via `--unpacked` were excluded from the name-hash traversal used for delta compression. The patch now passes the `rev_info` struct to `add_unreachable_loose_objects()`, allowing loose commit objects to be included as tips in the traversal. This doesn't affect pack correctness but should produce better deltas.

The implementation involves:
1. Modifying `add_loose_object()` to optionally add commit objects to the revision walk when a `rev_info` struct is provided
2. Updating all callers of `add_unreachable_loose_objects()` to pass either a `rev_info` struct or NULL
3. Maintaining the existing behavior for non-commit objects and when no `rev_info` is provided

This change builds on the refactoring in patch 4/8 which moved the `rev_info` declaration outside `read_packs_list_from_stdin()`. The patch touches only `builtin/pack-objects.c`, with mechanical changes to function signatures and callsites.

The commit message clearly explains both the oversight in the original implementation and the expected benefit (tighter packs through better delta compression). This appears to be a well-contained, low-risk change that logically follows the preparatory refactoring in earlier patches. The change maintains all existing functionality while adding the new optimization path.
