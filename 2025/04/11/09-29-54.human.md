Refactoring patch in Patrick Steinhardt's object-file subsystem reorganization series (v2 5/9). This change splits up the overloaded `HASH_*` flags that were being reused across multiple object-file functions (`hash_object_file()`, `write_object_file()`, `index_fd()`), creating separate flag namespaces for each function family.

The patch introduces new enum-based flags:
- `INDEX_*` flags for index-related operations (replacing `HASH_WRITE_OBJECT`, `HASH_FORMAT_CHECK`, `HASH_RENORMALIZE`)
- `WRITE_OBJECT_FILE_*` flags for object writing operations
- `HASH_OBJECT_*` flags specific to `hash-object` functionality

The changes are mechanical but widespread, touching 9 files to update all flag references. The commit message explains this reduces confusion since different functions were previously using overlapping subsets of the same flags. No behavior changes are introduced - this is purely a code organization improvement.

This continues the series' pattern of carefully separating concerns while maintaining functionality. The change appears well-executed with thorough updates to all affected call sites. It's part of the larger effort to clarify Git's object-file subsystem boundaries.
