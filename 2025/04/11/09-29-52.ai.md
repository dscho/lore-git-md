Refactoring patch in Patrick Steinhardt's object-file subsystem reorganization series. This is patch 3/9 in v2 series, moving memory-mapping utilities from object-file.c to wrapper.c as part of establishing clearer subsystem boundaries.

The patch relocates three mmap-related functions (`xmmap()`, `xmmap_gently()`, and `mmap_os_err()`) along with their helper `mmap_limit_check()`. These are general utility functions that handle memory mapping operations with error checking and environment-based size limits, making wrapper.c a more logical home since it already contains similar low-level system wrappers. The move is a pure code relocation with no functional changes - all implementations remain identical, just in a new file location.

Key technical details for future reference:
- `xmmap()` provides a die-on-error wrapper around system mmap
- `xmmap_gently()` is a non-fatal variant that returns NULL on failure
- `mmap_os_err()` provides OS-specific error messages (Linux-only ENOMEM hints)
- `mmap_limit_check()` enforces GIT_MMAP_LIMIT environment variable
- The functions handle platform-specific considerations like Linux's max_map_count

This continues the architectural goal of separating core object storage logic (object-file.c) from general utility functions. The patch follows the established pattern from earlier in the series where directory utilities were similarly moved to dir.c. All 48 lines are cleanly moved with no modifications beyond the file location change.
