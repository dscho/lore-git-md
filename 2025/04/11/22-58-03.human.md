Refactoring patch with potential implications for submodule handling. This is part 8/9 of Patrick Steinhardt's series to remove global state from Git's object storage system, specifically targeting the array of cached "virtual" objects used by commands like `git blame`.

The patch moves cached objects from a global variable into the raw object store structure, continuing the series' libification direction. However, Junio Hamano raises an important concern about how this change might interact with submodules. He questions whether repository-specific storage is the right approach, since virtual objects (like fake commits) may need to be shared across superprojects and their submodules when operations cross repository boundaries.

While the current implementation is safe because it still relies on `the_repository`, Junio notes this could become problematic if/when Git fully removes the global repository variable. The discussion highlights an architectural consideration that needs resolution before the series can be considered complete - whether virtual objects should indeed be repository-specific or require some cross-repository sharing mechanism.

This represents a thoughtful maintainer review catching a subtle edge case that wasn't fully considered in the original patch. The core refactoring remains sound, but the submodule interaction needs clarification or adjustment before finalization.
