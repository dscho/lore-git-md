This is part of Patrick Steinhardt's refactoring series to reorganize Git's object-file subsystem, specifically moving platform-specific code to more appropriate locations. The patch relocates `git_open_cloexec()` from object-file.c to compat/open.c, as this cross-platform file-opening utility doesn't logically belong in the object storage subsystem.

The change makes `git_open_cloexec()` always compiled (previously it was only conditionally compiled when OPEN_RETURNS_EINTR was defined) while keeping the EINTR-handling wrapper conditional. The patch updates 11 files - removing includes from object-file.h where no longer needed, adding the function to compat/open.c, and adjusting build systems (Makefile and meson.build).

Key technical details for future reference:
- The function provides platform-agnostic O_CLOEXEC support with fallbacks
- Moved from object-file.[ch] to compat/open.c and git-compat-util.h
- Build system changes ensure the function is always available
- Several object-related files no longer need to include object-file.h
- Maintains all existing functionality while improving code organization

This is a straightforward relocation as part of the larger architectural effort to separate concerns between object storage and platform compatibility code. The change is well-contained and follows the established pattern of the series.
