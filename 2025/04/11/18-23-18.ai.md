This is a follow-up discussion in the bug report thread about Git incorrectly persisting rebase state after interrupting `git am`. D. Ben Knoble responds to Ludo Pulles' original bug report with additional observations about the behavior.

The email notes that `git am` does warn about reading from stdin, and suggests pressing Ctrl-D (EOF) would exit normally rather than leaving the system in a bad state. Knoble observes that while their shell prompt (using a contrib script) correctly shows "AM/REBASE" state, `git status` incorrectly reports a rebase state, suggesting this may be a `git-status` detection issue rather than purely an `am` cleanup problem. They confirm that `git am --abort` works to clean up the state, unlike the failed `git rebase --continue` attempt mentioned in the original report.

The response highlights a potential discrepancy between how different parts of Git (the prompt script vs. `git status`) detect and report interrupted `am` operations, which may point to where the cleanup logic needs to be fixed. The email doesn't propose a solution but helps narrow the investigation by distinguishing between the actual state (AM) and what `git status` incorrectly reports (REBASE).
