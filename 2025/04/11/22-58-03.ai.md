This is a refactoring patch in Patrick Steinhardt's ongoing object-store cleanup series, specifically addressing the global array of cached objects. The patch moves cached objects storage from a global variable to the raw object store as part of libification efforts.

Junio Hamano raises an important architectural consideration about the placement of these virtual objects. He questions whether the object store is truly the right home for them, particularly in scenarios involving submodules where virtual objects might need to be shared across repository boundaries. While acknowledging the current approach won't break anything (since `the_repository` still maintains the global nature), he flags a potential future issue when `the_repository` usage is fully eliminated.

The discussion highlights a subtle but important distinction between repository-specific storage and cross-repository virtual objects. Junio suggests that virtual objects used across repository boundaries (like in submodule operations) might need a different storage solution than per-repository object stores. This could become problematic when call chains start passing repository instances rather than relying on the global `the_repository`.

This email represents a maintainer-level design consideration rather than a blocking concern, as the current implementation remains safe. However, it surfaces an architectural question that may need addressing as the libification effort progresses, particularly around submodule handling and the eventual removal of `the_repository` usage. The thread continues to demonstrate careful consideration of both immediate refactoring goals and long-term architectural soundness.
