Refactoring patch splitting object-file functionality into object-store.c.

This is patch 4/9 in Patrick Steinhardt's v2 series reorganizing Git's object-file subsystem. The patch moves object store-related code from object-file.c to a new object-store.c file, continuing the architectural separation established in earlier patches. 

Key changes:
- Creates new object-store.c with 972 lines moved from object-file.c
- Updates Makefile and meson.build to include the new file
- Adjusts includes in 15 files that need both object-file.h and object-store.h
- Preserves all existing functionality while better organizing the code

The moved code includes core object store operations like:
- Alternate ODB handling (prepare_alt_odb, link_alt_odb_entries)
- Object lookup and caching (oid_object_info_extended, find_cached_object)
- Object existence checks (has_object, repo_has_object_file)
- Object reading (repo_read_object_file, read_object_with_reference)

This follows the pattern established in previous patches, with object-file.c focusing on loose object operations while object-store.c handles the broader object storage subsystem. The changes are mechanical code movement with no functional changes, maintaining all existing behavior including error handling paths and platform-specific considerations.

The patch continues the series' goal of defining clearer subsystem boundaries, here separating the object storage layer from lower-level file operations. It touches many call sites but the changes are straightforward header/include updates to accommodate the new file organization.
