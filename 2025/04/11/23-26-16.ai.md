This is a cover letter for an RFC patch series proposing changes to how Git handles cruft packs and MIDX (multi-pack index) during repacking. The series comes from Taylor Blau and represents ongoing discussions with Peff (Jeff King) about optimizing pack maintenance.

The core proposal introduces a new `--stdin-packs=follow` mode for `pack-objects` that modifies how objects are selected during repacking. The key innovation is ensuring the resulting pack is "closed under reachability" - meaning it contains not just the direct objects from specified packs but also any objects reachable from them. This allows Git to safely exclude cruft packs from the MIDX while maintaining correctness, potentially improving performance by reducing MIDX size and complexity.

The 8-part series includes preparatory refactoring of `pack-objects` code, the new `follow` mode implementation, and repack integration that tracks MIDX'd packs to enable the optimization. Changes touch core packing logic in `builtin/pack-objects.c` and `builtin/repack.c`, with corresponding documentation updates and new tests in `t/t5331-pack-objects-stdin.sh` and `t/t7704-repack-cruft.sh`.

Technical points to note for future reference:
- New `--stdin-packs=follow` option behavior differs from standard mode by including reachable objects not in input packs
- The approach maintains geometric repacking properties while excluding cruft packs from MIDX
- Changes require careful handling of name-hash traversal during packing
- Series includes significant test coverage for both pack-objects changes and repack integration

The author presents this as an RFC due to uncertainty about edge cases, seeking conceptual review before detailed code feedback. The changes appear well-structured with logical progression from refactoring through to feature introduction and integration.
