Feature/bugfix hybrid regarding `git clone --bundle-uri` progress feedback and filter interaction.

Xavier Morel reports on UX issues with `git clone --bundle-uri` when working with large repositories (~5M objects). The main concern is the complete lack of progress feedback during bundle processing, even with `--verbose` and `--progress` flags, which contrasts with the detailed feedback during normal clone operations. This is particularly problematic since bundle-uri is primarily targeted at large repositories where operations take noticeable time.

The email also raises a secondary issue about potentially misleading behavior when combining `--bundle-uri` with `--filter`. Experiments suggest filters only apply to the reconciliation fetch (post-bundle), making the combination both slower and less space-efficient than expected. The author suggests emitting a warning about this potentially counterproductive combination.

Key technical details for future reference:
- Affects local file bundle URIs specifically
- Progress reporting appears completely absent during bundle phase
- Filter application seems limited to post-bundle reconciliation
- Repository size context: ~10GB fresh clone, ~2GB after aggressive GC

This appears to be a legitimate UX gap in the bundle-uri feature, particularly for large repository workflows. The progress feedback issue seems like a clear oversight, while the filter interaction might require either documentation improvements or behavioral changes.
