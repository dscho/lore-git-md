Security clarification follow-up in the `safe.directory` thread.

This email from Nikolaus Rath confirms understanding of the security behavior differences between single-process operations (like `git status`) and multi-process operations (like `git clone`) when using `safe.directory = *` via environment variables. The key technical point is that Git clears environment variables (including `GIT_CONFIG_*`) when spawning subprocesses during clone operations, which explains why the wildcard setting works for status but not clone.

The exchange serves as a confirmation of the security model rather than introducing new information - Nikolaus verifies their test case matches Jeff King's explanation about environment variable clearing during repository switching. The email reinforces the thread's established conclusion that this is intentional security behavior, with Nikolaus acknowledging the explanation resolves their confusion.

No new workarounds or technical details are added beyond what was previously established in the thread (global config, explicit config passing, or `--no-local` clones).
