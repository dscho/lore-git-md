Bugfix addressing pathspec wildcard matching inconsistency in `git add`.

Piotr Siupa reports a reproducible bug where `git add` with a wildcard pathspec (`f*"`) fails to match files on the first attempt when both a literal match (`f*`) and wildcard match (`foo`) exist. The behavior is inconsistent - the second invocation correctly picks up the wildcard match. The issue persists in both stable (2.43.2) and development (2.49.0) versions.

The minimal test case shows this clearly: after creating files 'foo' and 'f*', `git add 'f*'` only stages the literal 'f*' file initially, requiring a second run to catch 'foo'. This suggests a flaw in the pathspec matching logic where exact matches may be incorrectly prioritized over wildcard expansion in certain cases.

The report is well-formulated with clear reproduction steps and version testing, making it easy to verify. This appears to be a legitimate bug in core pathspec handling that could affect any command using similar wildcard matching, though currently demonstrated only with `git add`. The inconsistent behavior between first and subsequent runs suggests it may involve some caching or state tracking issue in the matching machinery.
