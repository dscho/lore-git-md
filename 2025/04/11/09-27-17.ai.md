This is a follow-up clarification in the now-merged object-file refactoring series. Patrick Steinhardt responds to Elijah Newren's question about the relationship between `safe_create_leading_directories()` and `mkdir_in_gitdir()` in the first patch of the series.

The exchange clarifies that while these functions aren't directly related through call hierarchy (as Elijah initially assumed), they are conceptually similar as generic directory-creation utilities. Patrick maintains that grouping them together in dir.c makes sense because they provide general-purpose functionality unrelated to Git's object storage specifics.

This is a minor post-merge clarification that doesn't affect the technical implementation, which has already been validated and merged. The thread shows the careful attention to architectural grouping decisions that characterized this refactoring effort, even after the main technical work was completed. The response confirms the original rationale while acknowledging the valid question about terminology ("relatives" vs "siblings").
