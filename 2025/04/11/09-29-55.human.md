This is patch 6/9 in Patrick Steinhardt's v2 series refactoring Git's object-file subsystem, focusing on separating index-related functionality. The patch moves index-specific functions from object-file.c to read-cache.c, continuing the architectural cleanup established in earlier patches.

The changes relocate several key functions that handle indexing files and blobs into the object database, including `index_mem()`, `index_fd()`, and `index_path()`. These are core operations that convert file contents to Git objects while handling various edge cases (regular files, symlinks, directories) and conversion filters. The patch also moves related flag definitions (`INDEX_WRITE_OBJECT`, etc.) to read-cache.h where they more logically belong.

This is a mechanical move with no behavior changes - all 225 lines moved from object-file.c appear verbatim in read-cache.c, with appropriate header adjustments in the 10 affected files. The change helps disentangle the object-file subsystem from index operations, making the codebase's architecture clearer. As with previous patches in the series, this appears carefully done with thorough testing implied by the lack of functional changes.

The patch continues the series' pattern of methodically separating concerns while maintaining all existing functionality. Readers interested in Git's object storage internals or ongoing code organization efforts will want to examine the changes, though most can safely treat this as internal plumbing work.
