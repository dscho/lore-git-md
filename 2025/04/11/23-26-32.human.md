Performance optimization in the ongoing cruft/MIDX repacking series. This is patch 5/8 in Taylor Blau's RFC series to improve how cruft packs interact with MIDX during repacking.

The patch fixes an oversight where loose objects` (those not in any pack) were being added to the output pack without being considered as reachability tips for delta compression. While this didn't affect correctness, it missed opportunities for better delta compression. The change passes the `rev_info` struct to the loose object handling code so these objects can participate in the name-hash traversal used for delta selection.

The implementation modifies `add_unreachable_loose_objects()` to accept the `rev_info` parameter and updates all callers. The key change is in `add_loose_object()` which now adds commit objects to the pending list when a `rev_info` is provided. This builds on the refactoring in earlier patches that moved the `rev_info` declaration outward.

This appears to be a straightforward improvement to pack quality with minimal risk, continuing the series' pattern of careful refactoring before introducing new functionality. The change is well-contained to `builtin/pack-objects.c` and maintains the existing behavior when no `rev_info` is passed (as in the cruft object enumeration case).
