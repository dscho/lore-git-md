Bugfix for `--left-only`/`--right-only` behavior with unrelated histories, now marked for inclusion in Git's 'next' branch. This patch from Matt Hunter fixes an edge case where these revision walker options would fail to properly limit commits when comparing histories with no common ancestor. The solution mirrors an existing fix for `--cherry-pick` by setting `revs->limited = 1` in the option parser.

The patch has gone through several iterations with input from multiple contributors, particularly around test portability and methodology. The current version uses sorted temporary files and `test_line_count` assertions rather than Bash process substitution, making it work across platforms while properly verifying the core invariant that the two sides of the comparison should have no commits in common.

Junio C Hamano has reviewed the final version and found it sound, indicating it will be included in the next development cycle.
