Performance optimization patch completing Taylor Blau's series on cruft pack and MIDX interaction during repacking. This final patch implements the core optimization teased in earlier preparatory work: excluding cruft packs from MIDX when possible to reduce MIDX bloat and improve lookup performance, while maintaining correctness through reachability closure.

The patch builds on the `--stdin-packs=follow` mode introduced in patch 6/8, using it to ensure geometrically-repacked packs contain copies of any once-unreachable objects that become referenced. This allows safely omitting cruft packs from the MIDX when no existing MIDX already includes them (detected via the tracking infrastructure from patch 7/8). The implementation adds `existing_has_cruft_in_midx()` to check this condition and modifies `midx_included_packs()` and the repack command construction to handle both cases.

Key technical details:
- New helper `pack_is_in_midx()` checks the PACK_IN_MIDX flag set by previous patch
- `existing_has_cruft_in_midx()` scans cruft packs for MIDX presence
- Modified `midx_included_packs()` branches logic based on whether MIDX needs cruft packs for reachability closure
- Repack command uses `--stdin-packs=follow` only when safe (no existing MIDX cruft packs)
- Comprehensive tests in t7704 verify both exclusion and required-inclusion scenarios

The change addresses the dual problems noted in commit ddee3703b3: MIDX bloat from rarely-accessed cruft objects, and the performance overhead of searching them during lookups. The solution maintains bitmap generation correctness by leveraging the reachability guarantees of `--stdin-packs=follow` packs. The patch completes the series' goal while demonstrating thorough test coverage of edge cases.
