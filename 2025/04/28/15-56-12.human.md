This is the second patch in a 3-part series improving gitk's Tk interface, specifically addressing color handling with themed widgets. The patch stops gitk from applying custom foreground/background colors when using themed Tk (TTk), as these were causing inconsistent widget coloring - some widgets would get the custom colors while others kept the theme defaults, resulting in a messy appearance with mismatched gray shades.

The change is straightforward: it adds a check for `$use_ttk` alongside the existing Windows-specific check, making both platforms skip the custom color application when using themed interfaces. This builds on the series' goal of making gitk's UI more consistent across different theming scenarios. The patch appears well-scoped, touching only the color-setting logic while leaving other behavior unchanged.

This is one of those subtle UI polish changes that won't dramatically change functionality but should make the application look more professional by avoiding visual inconsistencies. The commit message clearly explains the motivation and observed problems, and the change itself is minimal and focused.
