CI / build system patch adjusting GitLab CI configuration to ensure the MSVC-based Meson build job runs by default rather than requiring manual triggering.

This patch removes the `when: manual` directive from the `test:msvc-meson` job in `.gitlab-ci.yml`, making it execute automatically like its GitHub Workflows counterpart. The change addresses an inconsistency where breakages in this configuration were only be caught on GitHub, potentially missing issues that only manifest in the GitLab CI environment. The motivation stems from commit 7304bd2bc39 which originally introduced the MSVC Meson build but only made it automatic on GitHub. The patch follows up on a previous proposal (referenced as [1]) and includes a test run link showing the modified pipeline working. The change is straightforward - a one-line deletion that removes the manual trigger requirement while keeping all other job parameters (6h timeout and build dependency) intact. This appears to be a logical consistency improvement for the CI infrastructure, ensuring both CI systems test the same configurations by default.
