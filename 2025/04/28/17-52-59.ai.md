This is the final patch in the `git send-email` Outlook Message-ID handling series, implementing enterprise configurability as a follow-up to the core solution already queued by Junio Hamano. The patch adds a tri-state `--smtp-outlook-id-tweak` option (`always|never|auto`) to handle custom domains and enterprise configurations that mimic Outlook's SMTP behavior while maintaining backward compatibility.

The implementation modifies the `is_outlook()` helper to respect the new configuration, which defaults to 'auto' (the existing hostname-based detection for `smtp.office365.com` and `smtp-mail.outlook.com`). The 'always' mode forces the Outlook Message-ID workaround for any SMTP server, while 'never' disables it entirely. Documentation clearly explains each mode's use case, with special emphasis that 'always' should only be used for Microsoft email providers.

This completes the enterprise use case requirements raised earlier in the thread, building on the v6 core solution that Junio has already queued. The patch follows Junio's feedback to use string values ('auto', 'always', 'never') rather than numeric -1/0/1 for clearer configuration. With this addition, the series now comprehensively addresses both standard Outlook SMTP services and enterprise configurations while cleanly separating the Message-ID handling from authentication concerns (now handled by the released Authen-SASL 2.1800).
