This is a refactoring patch that's part of a series improving gitk's Tk interface. It modifies the text wrapping preferences UI to work consistently across both themed and unthemed Tk widgets.

The patch replaces direct combobox widget creation with calls to `makedroplist` for the comment and text wrapping options. This change affects two UI elements in gitk's preferences dialog where users can select between "none", "char", or "word" wrapping modes. The modification ensures the same widget behavior regardless of whether gitk is using themed Tk widgets or not.

The change is straightforward, replacing two nearly identical combobox creation blocks with calls to a helper function. This appears to be a clean refactoring that doesn't change the actual functionality but makes the code more maintainable and consistent. The patch is part of a larger effort to improve gitk's theming support, building on previous work (PR #1835).

Key technical details for future reference:
- Modifies the preferences page setup code in gitk's Tcl/Tk script
- Affects the `wrapcomment` and `wrapdefault` UI controls
- Uses existing `makedroplist` helper function instead of direct widget creation
- Maintains same three wrapping options ("none", "char", "word")
- Part of making gitk's UI behave consistently with/without Tk theming

The patch appears well-contained and focused on its stated goal of fixing text wrapping preferences for unthemed Tk. It's a small but logical step in the broader theming improvements series.
