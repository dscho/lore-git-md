Bug report regarding shallow submodule checkout behavior with GitHub repositories. Pavel Pavlov demonstrates an issue where submodule checkouts from non-default GitHub branches unexpectedly fetch full history instead of performing a shallow clone. The report includes two test repositories (submodule-test-ok and submodule-test-bad) that are identical except for their submodule references - one works as expected (2.9MB checkout) while the other fetches the entire history (34MB). The key difference appears to be whether the submodule points to a default branch or not on GitHub. The report doesn't propose a fix but clearly demonstrates the problem with reproducible test cases, suggesting this may be either a Git or GitHub-specific issue related to branch handling during shallow clones. The impact is significant for users in bandwidth-constrained environments where shallow clones are specifically used to save time and bandwidth.
