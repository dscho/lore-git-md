Bugfix discussion regarding object existence checks in pack-objects.

This email continues a thread about a bug where `should_include_obj()` in builtin/pack-objects.c is being called on non-existent objects. Jonathan Tan, the original author of the code in question, acknowledges the issue but can't recall why he originally assumed the function would only be called on existing objects. He traces the problem to `process_tree()` in list-objects.c where missing objects are handled after `should_include_obj()` is called.

The proposed fix is to modify `should_include_obj()` to return 0 for absent objects. However, Tan notes the lack of a reproducible test case and asks Nik (the original bug reporter) to contribute a regression test similar to the 'after fetching descendants of non-promisor commits' test in t5616. The thread reference [1] shows this dates back to earlier work on promisor remotes, though the specific assumption about object existence wasn't discussed there.

Key technical details: The issue involves interaction between pack-objects.c and list-objects.c, specifically around handling missing objects during tree processing. The fix would affect object inclusion logic during packing operations. The suggested test location (t5616) indicates this relates to partial clone/promisor remote functionality.
