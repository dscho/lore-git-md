This thread documents a bug in `git rebase --rebase-merges` where uninitialized memory was being written to reflog action fields during merge operations. Kristoffer Haugsbakk originally reported seeing corrupted binary data in reflog entries instead of expected text like "rebase (continue)". After initial debugging showed the issue was intermittent and hard to reproduce, Jeff King (Peff) suggested using address and undefined behavior sanitizers, which Kristoffer used to confirm a heap-use-after-free issue. The root cause was that `ctx->reflog_message` in the sequencer was holding a stale pointer to freed memory after strbuf reallocation during merge operations.

Jeff King has now proposed a fix that changes how the sequencer manages reflog message strings. The solution modifies the `reflog_message` field to track ownership properly, using `xstrdup()` and `free()` to ensure strings remain valid throughout rebase operations. A test case has been added to demonstrate the issue reliably. While this addresses the immediate problem, Jeff notes there may be broader refactoring needed around how static strbuf contents are handled in the codebase. The patch appears complete but awaits testing confirmation from Kristoffer and Phillip Wood, who have been closely involved in diagnosing the issue. This fix should resolve the corruption seen in real-world rebase operations involving multiple merges.
