This thread discusses a 3-patch series improving gitk's Tk interface, with a focus on making themed and unthemed usage more consistent. The series builds on prior theming work (PR #1835) to address several quality-of-life issues in gitk's graphical history viewer.

The first patch refactors text wrapping preferences to use a common helper function for both themed and unthemed widgets, ensuring consistent behavior for the wrapping options in gitk's preferences dialog. The second patch, which just arrived, fixes inconsistent widget coloring by preventing gitk from overriding foreground/background colors when using themed Tk - extending existing Windows-specific logic to all themed cases. The third patch (not yet seen) will add visible sash handles between panes when using themed Tk.

These changes address minor but noticeable UI inconsistencies rather than fixing bugs, with each patch cleanly handling a specific aspect of theming behavior. The series appears well-motivated by real-world usage problems, particularly around color consistency in themed environments. The refactoring in the first patch also makes the code more maintainable while preserving existing functionality.
