This is the final patch in Aditya Garg's series addressing Outlook's Message-ID handling in `git send-email`. The patch adds a tri-state configuration option (`--smtp-outlook-id-tweak=always|never|auto`) to control when Git should attempt to retrieve the Message-ID from Outlook SMTP servers, which normally discard and replace Message-IDs, breaking email threads.

The default 'auto' mode maintains the existing behavior of only applying the workaround for known Outlook domains (smtp.office365.com and smtp-mail.outlook.com). The new 'always' and 'never' options allow enterprise users with custom domains or those needing to force-disable the behavior to do so explicitly. The implementation is clean, with clear documentation warning about the risks of using 'always' mode with non-Outlook servers.

This completes the solution that was partially queued in v6 (hostname-based detection) by adding the enterprise configurability requested in earlier reviews. The patch follows Junio Hamano's suggestion to use string values rather than booleans for the configuration. With this and the recently released Authen-SASL 2.1800 handling OAuth2 authentication, the Outlook integration appears fully addressed.
