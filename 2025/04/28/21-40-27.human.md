This is a review comment on patch 6/13 of Patrick Steinhardt's object store cleanup series, which is part of the larger `the_repository` removal effort. Junio Hamano points out that the commit message's justification for the new `has_object()` API being "better" than the deprecated `repo_has_object_file()` is unclear.

The core issue is that the commit message claims the new defaults are better (not fetching from promisor remotes and not reloading packfiles by default) but doesn't explain why this constitutes an improvement. Hamano suggests concrete ways to strengthen the rationale - for example, by showing that most callers don't want these behaviors and would otherwise need to pass flags to disable them, or that the new design better separates concerns by letting callers explicitly request lazy fetching when needed.

This is a documentation-level critique rather than a technical objection to the changes themselves, which have already been reviewed and approved by Karthik Nayak. The series remains in good shape overall, but this feedback could help future readers understand the design decisions better if incorporated into the commit message.
