This is a discussion follow-up in Patrick Steinhardt's object store refactoring series, specifically about patch 10/13 which deals with the HTTP walker's object fetching behavior.

Junio Hamano agrees with the patch's rationale for changing how the HTTP walker checks for existing objects. The original code would unnecessarily fetch objects from promisor remotes during a check, even though the HTTP walker was already in the process of fetching those same objects. Junio notes this is different from the earlier discussion about promisor objects in collision checks (patch 7/13), where the justification was less clear. Here, the reasoning holds up - avoiding redundant fetches when you're already fetching the object makes obvious sense.

The exchange shows progress in resolving Junio's earlier questions about the series' promisor object handling. While questions remain about other parts of the series (particularly around show-ref and reference validation), this particular patch's approach now has Junio's approval. The discussion helps clarify the boundaries between cases where promisor fetching is appropriate versus wasteful.
