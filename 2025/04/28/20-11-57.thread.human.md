This thread discusses improving the output messages for `git branch -f` to make them more informative. Junio Hamano identified that the current behavior redundantly shows "set up to track" messages even when no tracking configuration changes, while failing to clearly indicate when the branch tip actually moves - which is often the more operationally significant information.

The proposal suggests three key changes: only showing tracking messages when the relationship actually changes, enhancing messages to show previous tracking config (when available), and adding explicit "Reset branch" output for tip movement similar to `git checkout -B`. D. Ben Knoble has engaged with the proposal, raising thoughtful concerns about whether suppressing tracking messages might confuse users accustomed to seeing them, and suggesting that enhanced messages showing both old and new tracking configs might be preferable.

The discussion is currently focused on design considerations rather than implementation, weighing tradeoffs between verbosity and information clarity, parallels to similar commands like `git checkout -B`, and broader UX principles around force flags. No patches have been submitted yet as participants work to refine the desired behavior before implementation. The changes would affect output formatting in branch.c while maintaining backward compatibility for scripts and tools.
