CI/build system proposal for Docker-based caching in CI jobs. Patrick Steinhardt responds to the ongoing discussion about caching external dependencies in Git's CI pipeline by suggesting a Docker-based approach. Building on Junio Hamano's earlier recommendation for once-per-platform caching and Jialuo's investigation, Patrick proposes using pre-seeded Docker images that would be built once and reused across CI jobs.

The key technical aspects of this approach would involve:
- Creating platform-specific Docker images containing all external dependencies (JGit, Perforce, Git-LFS)
- Only rebuilding images when dependencies change
- Making the images available via container registry for local reproduction of CI failures

This builds on the existing work that implemented atomic downloads and warning systems while addressing the wastefulness concern raised in the thread. The Docker approach would provide both caching benefits and improved reproducibility, though it would require setting up image building infrastructure and registry access. The proposal doesn't yet address implementation details like how often to rebuild images or how to include in the existing GitHub Actions workflow.
