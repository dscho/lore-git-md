Bugfix for gitk's external diff functionality when handling renamed files. This v4 patch follows up on previous iterations (v1-v3) that introduced and refined rename detection for external diffs in gitk. The key change is a new `check_for_renames_in_diff` procedure that parses "rename from"/"rename to" markers from diff output using Tcl/Tk text widget regex searches to correctly identify both original and renamed file paths, regardless of which file is selected in the UI. The implementation handles markers in either order and applies to both renamed and moved files (which Git treats identically).

The patch evolved through four versions, with v4 incorporating Johannes Sixt's style feedback: using present tense for behavior descriptions, imperative mood for changes, and removing bullet points from the commit message. Earlier versions had included an experimental GUI toggle (removed in v2) and underwent variable renaming and selection case fixes. The current implementation maintains the existing external diff interface while fixing the path resolution logic, with no outstanding technical objections raised in the thread.

The changes are narrowly focused on gitk's external diff functionality, touching only the gitk Tcl script with 43 lines added and 2 modified. The solution appears robust, handling both forward and backward searches for rename markers and falling back gracefully when no rename is detected. With the style adjustments addressed, this looks ready for final review by the gitk maintainer.
