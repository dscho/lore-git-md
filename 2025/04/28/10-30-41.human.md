This is a CI/build system discussion about implementing Docker-based caching for Git's CI jobs. Jialuo responds to Patrick Steinhardt's proposal to use pre-seeded Docker images for external dependencies, agreeing it would solve the current inefficiency of downloading dependencies in every job. The main open question is where to host the container images, with GitHub's container registry being the suggested free option for public repositories. Jialuo notes they'll need help from Git organization members to implement this since they don't have access to push images. The Docker approach would both improve CI efficiency and make it easier to reproduce CI failures locally by using the exact same containerized environment. This builds on the thread's earlier work to make CI more resilient to external dependency outages.
