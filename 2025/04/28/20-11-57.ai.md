This is a bugfix proposal addressing confusing output from `git branch -f`. Junio Hamano identifies an issue where the command redundantly reports "set up to track" messages even when no tracking configuration has changed, while failing to report the more important information about branch tip movement.

The core problem occurs when using `git branch -f` to reset an existing branch that already tracks a remote branch. Currently, Git always prints the tracking setup message regardless of whether the tracking relationship changed, which is both misleading and distracting. The message also omits the more relevant information that the branch tip was moved.

Hamano suggests three potential improvements: (1) only show tracking messages when the tracking relationship actually changes, (2) enhance tracking messages to show previous tracking configuration (though notes this information may already be lost), and (3) add new output when resetting branch tips, possibly modeled after `git checkout -B`'s "Reset branch" message. The changes would affect branch.c's behavior and output formatting.

This appears to be a well-motivated quality-of-life improvement for a common workflow, particularly affecting users who frequently use `git branch -f`. The suggested changes maintain backward compatibility while making the output more precise and actionable. The thread appears to be seeking feedback and potential implementers for these enhancements.
