This is a discussion thread about patch 7/13 in Patrick Steinhardt's object store cleanup series, focusing on promisor object handling during index-pack collision checks. Karthik Nayak provides feedback on the patch's explanation and behavior.

The conversation clarifies that the collision check in `git-index-pack` verifies whether objects being indexed have the same content as any preexisting objects with matching OIDs. The current implementation unnecessarily fetches promisor objects during the initial existence check, even though the fetch would happen again later if a content comparison is actually needed.

Patrick explains this creates a redundant fetch scenario where we might fetch a promisor object just to verify it matches the object we're already receiving via the index-pack operation. Karthik suggests improving the commit message wording to better distinguish between checking for OID existence versus content comparison.

The discussion confirms the technical approach in the patch is sound - avoiding promisor fetches during the initial existence check while maintaining the full content comparison when needed. This aligns with the series' broader goal of making object existence checks more precise about when they should trigger promisor fetches.
