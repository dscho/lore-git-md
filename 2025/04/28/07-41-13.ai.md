Technical discussion response about bisect workflow with external test files.

Christian Couder responds to Victor Engmark's question about maintaining consistent test files during bisect operations. The core suggestion is to use `git worktree` to maintain parallel checkouts - one for the bisect operation and another for the stable test files. This would allow copying the test files via `cp -a` rather than the current manual `git show` extraction approach.

The response makes two key technical points: (1) worktrees could provide a cleaner solution than the current file extraction method, and (2) suggests this is more properly a build/test system responsibility than a core SCM concern. The worktree approach would require proper setup of all needed files/directories in the secondary worktree.

This moves the discussion forward by proposing a concrete alternative to the manual file management approach, while also noting the conceptual boundary between SCM and build/test responsibilities. The suggestion doesn't address all edge cases mentioned in the thread (like path/perm issues) but provides a clear direction for experimentation.
