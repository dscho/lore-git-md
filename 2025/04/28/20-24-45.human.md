Bugfix for `index-pack`'s REF_DELTA chain handling. This is the final patch in Patrick Steinhardt's series addressing incorrect cycle detection in thin packfiles with REF_DELTA chains. The core issue was that `index-pack` would falsely reject valid packfiles containing inter-pack REF_DELTA references (like A->B->C where B and C exist client-side), even though the packfile format permits this.

The patch modifies `threaded_second_pass()` in `builtin/index-pack.c` to:
- Skip already-processed REF_DELTAs rather than failing
- Handle NULL child states properly
- Maintain correct child object retention
- Convert test expectations from failure to success

The changes are careful to preserve the threading model while fixing the core issue. Test updates in t5309-pack-delta-cycles.sh now expect success for cases that were previously marked as failures, including the key scenario where a thin pack contains A->B->C with B already on disk. The implementation maintains all security properties - it still rejects truly unresolvable REF_DELTAs and prevents on-wire attacks via missing base rejection.

This completes the series that introduced new test infrastructure (`test-tool pack-deltas`) and fixes a long-standing issue that could affect fetches from servers using REF_DELTAs. The patch shows thorough attention to edge cases and maintains the code's thread-safety while resolving the core problem.
