Git thread summary:

Bug report and proposal to improve `git branch -f` output clarity. Junio Hamano identifies confusing behavior where the command redundantly reports "set up to track" messages even when no tracking configuration changes, while failing to indicate branch tip movement - the more operationally significant information.

Current behavior in branch.c always shows tracking setup messages for branches with existing remote tracking, creating noise. Three specific improvements proposed: (1) only show tracking messages when relationship actually changes, (2) enhance messages to show previous tracking config (though may be limited by available info), and (3) add explicit "Reset branch" output for tip movement, similar to `git checkout -B`.

The changes would affect output formatting logic in branch.c while maintaining backward compatibility. The thread seeks feedback on the proposal and potential implementers for this quality-of-life improvement affecting users who frequently reset branches with `-f`. No patches submitted yet; discussion focuses on nailing down the desired behavior before implementation.
