This is a bugfix proposal for `git branch -f` behavior regarding tracking branch messages. Junio Hamano identifies an issue where the command redundantly reports "set up to track" messages even when no tracking relationship has changed, which can be confusing. He suggests three potential improvements:

1. Only show the tracking message when the tracking relationship actually changes
2. Enhance the message to show what was tracked before (when changing tracking)
3. Add a new message when resetting a branch's commit (similar to `git checkout -B`'s behavior)

The proposal is well-motivated by real user confusion scenarios and offers clear, actionable suggestions. This would be a quality-of-life improvement for users who frequently use `git branch -f` with tracking branches. The changes would make the command's output more precise and less potentially misleading.
