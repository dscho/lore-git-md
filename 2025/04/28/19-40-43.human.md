Bugfix for uninitialized reflog action strings during rebase with merges.

Kristoffer Haugsbakk reports a bug where `git rebase --rebase-merges` on a branch containing merge commits (particularly backmerges) can result in corrupted reflog entries showing uninitialized memory instead of the expected action string (like "continue"). The issue appears intermittently and only affects certain merge commits, with the garbage values changing between runs.

The problem bisects to commit d188a60d722 ("sequencer: stop exporting GIT_REFLOG_ACTION", 2022-11-09). A backtrace shows the issue occurs during merge commit processing in the sequencer. While the reporter couldn't reproduce with a simple test case, they provide detailed reproduction steps from their real-world scenario involving a branch with backmerges that was rebased before merging into main.

This appears to be a genuine bug in the rebase/merge interaction logic, though the exact conditions triggering it remain unclear. The report includes thorough debugging information (bisection, backtrace, version info) but lacks a minimal reproduction case, which may make it harder to verify a fix. The impact seems limited to cosmetic reflog corruption rather than functional issues.
