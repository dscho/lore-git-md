CI/build system: Patrick Steinhardt suggests using pre-seeded Docker images as a caching solution for CI dependencies, building on the ongoing discussion about optimizing external dependency handling in Git's CI pipeline.

This email responds to Junio Hamano's suggestion about once-per-platform caching and Jialuo's investigation into implementation approaches. Steinhardt proposes a Docker-based solution that would create pre-built with all dependencies, which could then be reused across CI jobs and even shared with developers for debugging.

The approach offers two key advantages: it would eliminate redundant downloads by caching the entire environment in a container image, and it would provide exact environment reproducibility for debugging CI failures locally. This builds on the series' existing work around atomic downloads and warning presentation while exploring a more comprehensive caching strategy.

The suggestion appears technically sound and aligns with the thread's direction toward more efficient CI resource usage. It represents a natural evolution from the current per-job dependency handling toward a more maintainable system-level solution. The proposal doesn't include implementation details but provides a clear conceptual direction that could complement or replace the file-level caching being investigated.
