This is a bugfix patch in Patrick Steinhardt's object store cleanup series, specifically addressing index-pack's collision check behavior. The patch changes how index-pack verifies whether incoming objects collide with existing ones, switching from `repo_has_object_file_with_flags()` (which could trigger unwanted promisor object fetches) to the new `has_object()` API that avoids such fetches by default.

Junio Hamano questions the characterization of the current behavior as "highly dubious," suggesting the reasoning could be clearer. He probes whether the underlying principle is that we shouldn't trust promisor objects more than the pack we're actively indexing - if we're verifying the pack's contents, we shouldn't implicitly fetch potentially untrustworthy objects during that verification.

The change itself is minimal (3 lines removed, 1 added) but meaningful, removing the `OBJECT_INFO_QUICK` flag in favor of the new API's default behavior. This fits with the series' broader goal of cleaning up object storage APIs and removing promisor-related side effects where they're not explicitly wanted. The patch has already been reviewed and approved by Karthik Nayak as part of the complete series.
