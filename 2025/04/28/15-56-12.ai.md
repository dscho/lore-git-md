This is the second patch in a 3-part series improving gitk's Tk interface, specifically addressing color handling with themed widgets. The patch modifies gitk's color scheme logic to skip foreground/background color adjustments when using themed Tk (TTk), not just on Windows as before.

The change prevents inconsistent widget coloring that occurred when gitk's default uicolor didn't match the theme's background, which could result in a messy UI with some widgets showing different background/foreground colors than others. The patch simply adds an early return in the `setui` proc when `use_ttk` is true, letting the theme handle colors uniformly rather than gitk trying to override them.

This builds on the thread's established context about gitk's theming improvements, specifically addressing a case where themed widgets were getting partial color overrides that created visual inconsistencies. The change is straightforward and appears well-motivated by real UI problems observed with themed Tk usage. The patch maintains the existing Windows-specific skip while extending the logic to all themed Tk cases.
