This is a bugfix series addressing `git index-pack`'s incorrect cycle detection in REF_DELTA chains, along with test infrastructure improvements. The series builds on previous discussion that refined the test helper's interface and fixed memory leaks.

The cover letter explains that `index-pack` was incorrectly failing on valid packfiles containing inter-pack REF_DELTA references (where a delta chain like A->B->C exists but B and C are already present client-side). The series introduces a new `test-tool pack-deltas` helper for constructing test packs with specific delta structures, and fixes the cycle detection logic in `builtin/index-pack.c`.

Key changes in v2:
- The test helper now uses Git's standard `parse_options()` interface with an explicit `--num-objects` parameter instead of a positional argument
- Fixed a memory leak in the test helper
- Simplified the test script by feeding input directly to the helper rather than using a temporary file

The test helper (140+ lines in `t/helper/test-pack-deltas.c`) allows precise construction of packfiles with specific delta relationships. The main fix modifies `threaded_second_pass()` to properly handle REF_DELTAs pointing to local bases by skipping already-processed REF_DELTAs rather than failing, while maintaining safety checks for truly unresolvable deltas.

The series appears well-tested with converted `test_expect_failure` cases now passing, and has undergone thorough review from multiple core contributors regarding both the bugfix and test infrastructure aspects. The v2 changes address previous feedback about CLI design and memory management.
