This is a bug report about uninitialized memory being written to reflogs during rebase operations with merge commits. The issue occurs specifically with `git rebase --rebase-merges` on branches containing merge commits, where some merge operations end up writing corrupted binary data to the reflog's action field instead of the expected text (like "rebase (continue)").

The reporter provides a detailed backtrace showing the issue originates in the sequencer code during merge operations, bisecting the problem to commit d188a60d722 ("sequencer: stop exporting GIT_REFLOG_ACTION"). The bug appears intermittently - while the reporter couldn't reproduce it with a simple test case, they observed it in a real-world scenario involving backmerges between branches. The corrupted reflog entries only appear for some merge commits, not all, and not for backmerges.

Key technical details for future reference:
- Affects sequencer.c's merge handling (do_merge -> run_git_commit)
- Corrupted data appears in reflog action field
- Bisected to GIT_REFLOG_ACTION export removal
- Only manifests in complex merge/rebase scenarios
- Backtrace shows execution path through rebase -> sequencer -> merge operations

The report is thorough, including reproduction attempts, system info, and clear before/after examples of the corrupted reflog entries. The inability to create a simple reproduction case may make this harder to debug, but the bisection provides a solid starting point.
