This is a refactoring patch in Patrick Steinhardt's object store cleanup series, specifically addressing reference validation behavior regarding promisor objects. The patch changes `ref_resolves_to_object()` to use the new `has_object()` API with only the `HAS_OBJECT_RECHECK_PACKED` flag, explicitly avoiding promisor object fetching during reference validation. Junio Hamano questions whether this maintains sufficient validation guarantees, pointing out that the definition of "broken reference" may now be incomplete since it doesn't account for objects that could be obtained from promisor remotes.

The technical change is minimal (a one-line flag adjustment in refs.c), but the conceptual impact is significant - it represents a deliberate choice to not consult promisor remotes during reference validation. This continues the series' principle that write operations and reference validation shouldn't trigger promisor fetches, but Junio probes whether this assumption holds for all cases where integrity validation is needed.

The discussion highlights a key design decision in the series: whether reference validation should be treated as a "write-like" operation (where avoiding promisor fetches is preferred) or whether it should maintain the most complete possible object existence check. This connects to broader questions about the trust model between locally available objects and those in promisor remotes.
