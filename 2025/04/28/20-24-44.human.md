This is a test case addition as part of a bugfix series addressing incorrect cycle detection in `git index-pack`. The patch adds a failing test that demonstrates how `index-pack` currently rejects valid thin packfiles containing REF_DELTA chains (A->B->C) when intermediate objects (B) exist in the client repository. 

The test creates a server repository with commits, then constructs a thin pack where object A depends on B, and B depends on C. After removing C from the server, it shows that `index-pack` incorrectly fails when processing this valid delta chain, mistaking the dependency structure for a cycle. The test uses the new `test-tool pack-deltas` helper introduced earlier in the series to generate the test packfile.

This test is specifically designed to verify the fix that will come in the next patch, which will modify `index-pack` to properly handle such cases. The test currently expects failure (marked with `test_expect_failure`) but will be updated to expect success once the fix is applied. The test setup is thorough, creating both server and client repositories to properly simulate the real-world scenario where this bug occurs.
