This is a test case addition as part of Patrick Steinhardt's bugfix series for `git index-pack`'s REF_DELTA cycle detection. The test demonstrates the specific failure scenario where `index-pack` incorrectly rejects a valid thin pack containing a REF_DELTA chain (A->B->C) when intermediate objects (B and C) exist in the client repository. 

The test uses the new `test-tool pack-deltas` helper introduced earlier in the series to construct a thin pack with the problematic delta structure. It sets up a server repository with commits, then creates a client clone that already has some objects. The test attempts to index a pack where object A depends on B, and B depends on C - a valid case that current Git incorrectly flags as a cycle.

The test is marked as `test_expect_failure` since it documents the known-bad behavior that the next patch will fix. The test infrastructure demonstrates proper use of the new `pack-deltas` tool with its `--num-objects` parameter to create the test packfile. This maintains the series' focus on replacing older test methods with more maintainable infrastructure while precisely targeting the bug scenario.

The test case validates that the fix will properly handle cases where:
1. REF_DELTA chains can be resolved using objects already present locally
2. Intermediate resolution steps don't trigger false cycle detection
3. The threading model remains intact during multi-pass delta resolution

This patch continues the series' pattern of thorough test coverage for the cycle detection bug, with the test designed to flip from failure to success when the actual implementation fix is applied in the following patch.
