This is a bugfix for gitk's external diff functionality, now in its fourth iteration. The patch addresses a specific issue where gitk fails to properly handle renamed files when launching an external diff tool, whether the user selects the original or renamed version of the file. The solution introduces a new `check_for_renames_in_diff` procedure that parses "rename from"/"rename to" markers from the diff output to correctly identify both file versions.

The patch has evolved through several versions based on feedback from the gitk maintainer Johannes Sixt. Earlier versions included an experimental GUI toggle that has since been removed, and the latest iteration improves variable naming and commit message style (now using present tense and imperative mood as requested). The implementation handles both renamed and moved files consistently, since Git treats them the same way internally.

The changes are narrowly focused on the external diff functionality, adding about 40 lines of Tcl/Tk code to parse rename markers from the diff output while maintaining the existing interface. The patch appears well-tested and addresses a clear usability issue, though the maintainer hasn't yet given final approval. This version incorporates all requested stylistic changes from previous rounds, suggesting it may be nearing readiness for inclusion.
