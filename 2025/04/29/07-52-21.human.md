Final patch in a refactoring series removing deprecated object-file APIs. This is the seventh and concluding patch in Patrick Steinhardt's v3 series cleaning up the object store implementation, part of the ongoing `the_repository` removal effort.

The patch 6/7 (summarized in the thread context) already converted all callers from `repo_has_object_file()` to the newer `has_object()` API. This final patch simply removes the now-unused functions `repo_has_object_file()` and `repo_has_object_file_with_flags()` from object-store.[ch], completing the transition. The changes are straightforward deletions with no behavior impact, as all callers were migrated in prior patches.

The series has progressed methodically through header reorganization, API simplification, and utility function migration before tackling this final cleanup. Earlier feedback from Karthik Nayak approved the technical direction, and Junio Hamano's concerns appear addressed by the conservative conversion approach. This marks another step in reducing global state usage while maintaining promisor object fetching capabilities through the new `HAS_OBJECT_FETCH_PROMISOR` flag introduced earlier in the series.
