Refactoring patch in Patrick Steinhardt's object-store cleanup series (3/7). This patch moves a generic file creation helper function out of the object store code and into the path utilities.

The patch renames `odb_pack_keep()` to the more descriptive `safe_create_file_with_leading_directories()` and relocates it from object-store.[ch] to path.[ch]. The function's behavior remains the same - it attempts to create a file, and if that fails due to missing directories, creates them and retries. The key improvement is removing its dependency on `the_repository` by accepting a repository parameter.

This is a straightforward mechanical change that continues the series' goal of cleaning up object store interfaces. The patch updates two callers in fast-import.c and index-pack.c to use the new function name and pass the repository parameter. The changes look correct and maintain existing behavior while improving code organization.

This is part of the larger effort to remove `the_repository` global and clean up object store interfaces, following the uncontroversial header reorganization in patch 1/7 and API simplification in patch 2/7. The series has already received positive feedback on its technical approach from Karthik Nayak.
