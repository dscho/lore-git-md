This is a bugfix proposal for the long-standing `git mv` issue that was previously only demonstrated (not tested) in t7001-mv. Patrick Steinhardt follows up on Junio Hamano's historical context about the problematic test case by proposing an actual fix for the underlying issue in builtin/mv.c.

The patch introduces a hashmap-based mechanism to track moved directories and prevent simultaneous moves of parent and child paths. When detecting such invalid moves, it now fails with a clear error message ("cannot move both parent directory X and its child Y") rather than triggering an assertion. The implementation adds a new `pathmap_entry` struct and uses the existing hashmap infrastructure to track directory moves during operation.

Key technical details include: new hashmap initialization in cmd_mv(), tracking of moved directories during the initial pass, and a second validation pass that checks for parent-child conflicts. The patch handles edge cases like submodule paths and maintains proper cleanup with hashmap_clear(). While marked as incomplete (failing some cases and needing polish), it demonstrates a viable approach to resolving the core issue that has existed since test t7001-mv was added 9 months ago.

This represents significant progress from merely discussing CI workarounds (Release mode builds) to addressing the root cause. The proposed solution aligns with Git's error handling patterns by replacing an assertion with proper user-facing error reporting. If completed, this would allow keeping t7001-mv as a proper regression test rather than just a bug demonstration.
