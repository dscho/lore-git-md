This is a refactoring series (v3) from Patrick Steinhardt that continues the cleanup of the object store subsystem, part of the ongoing `the_repository` removal effort. The series builds on previous work to modernize object storage code by reorganizing headers, removing deprecated functions, and introducing clearer APIs.

The key change in this version is the removal of `repo_has_object_file()` in favor of the new `has_object()` function. The new API provides more explicit control over promisor object fetching and packfile reloading behavior through flags. The series now takes a more conservative approach by doing straightforward 1:1 conversions of callers rather than trying to optimize promisor fetching behavior, which will be addressed separately.

Notable changes in v3 include:
- Moving `hash_object_file()` to the proper header
- Clarifying the motivation for deprecating `repo_has_object_file()`
- Dropping some optimization patches that were in v2 to keep this series focused on the API transition

The series has been reviewed by Karthik Nayak and addresses feedback from Junio Hamano about commit message clarity. It touches 41 files with a net reduction in code, primarily by removing the old API and reorganizing header includes. The changes are mechanical but important groundwork for future work on the object store.

This appears ready for merging as it maintains current behavior while cleaning up technical debt. The remaining open questions about promisor object handling in certain cases have been deferred to future discussions.
