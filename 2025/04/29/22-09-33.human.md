This is a discussion about improving interactive patch commands' context line handling. Jeff King (Peff) weighs in on Leon Michalak's proposal to make `--patch` commands respect diff context configuration.

Peff supports the idea of having interactive patch commands like `git add -p` respect the existing `diff.context` setting by default, arguing that since these are user-facing commands, changing their output wouldn't break scripts. He notes that other porcelain-level configurations like colorization are already respected in these commands.

The email suggests the current limitation exists because the interactive code is built around plumbing commands that avoid certain config options. Peff points out this could extend beyond just context lines - other diff-related configurations like `diff.interhunkcontext` and potentially `diff.colormoved` might also be candidates for inclusion, though he suggests focusing on context lines first.

This continues the thread's exploration of how to best implement context line configuration for interactive patch commands, with Peff providing a maintainer's perspective favoring the simpler approach of respecting existing diff configurations rather than introducing new interactive-specific settings.
