This is the third and final patch in a v2 series enhancing the promisor-remote protocol with configurable field validation. It completes the client-side implementation by adding field checking against server-advertised values.

The patch introduces a new `promisor.checkFields` configuration that lets clients validate specific fields (currently only "partialCloneFilter" and "token") against local expectations before accepting a promisor remote. When configured, the client will reject remotes where field values don't match between server advertisements and local configuration. This provides security and consistency guarantees, particularly important for authentication tokens and partial clone filters.

Key implementation details:
- New `fields_checked()` function mirrors the server-side `fields_sent()` from earlier in the series
- Field validation happens in `should_accept_remote()`, integrated with existing name/URL checks
- Values are compared case-sensitively while field names remain case-insensitive
- Comprehensive test case verifies filter validation and proper protocol transmission
- Documentation covers configuration syntax and security implications

The implementation cleanly builds on the series' foundation, using the same `string_list` patterns established in earlier patches. Test coverage is thorough, exercising both happy paths and edge cases. The documentation clearly explains the security model and interaction with other promisor-remote configurations.

This completes the series' goal of adding controlled, validated field passing to the promisor-remote protocol while maintaining backward compatibility. The constrained approach (limiting to specific fields) addresses earlier protocol design concerns, and the implementation follows established Git patterns.
