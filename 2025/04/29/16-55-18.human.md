This is a bugfix for the hashmap implementation, specifically addressing an issue with `hashmap_clear()` that could prevent hashmap reuse. The patch comes from Elijah Newren as a follow-up to earlier hashmap changes merged in 2020.

The core issue is that `hashmap_clear()` was completely zeroing the hashmap structure, including essential function pointers and operational state that are needed for reuse. The fix modifies the clearing behavior to only reset the table-related fields (`tablesize` and `private_size`) while preserving the comparison function (`cmpfn`), user data pointer (`data`), and item counting flag (`do_count_items`).

Junio C Hamano acknowledges the fix as correct and plans to apply it to the main branch, though he notes it likely doesn't need to be backported to older Git versions (specifically mentioning Git 2.30). The change is small (just 3 lines modified), clean, and addresses a latent correctness issue in the hashmap implementation.

This appears to be a well-justified and straightforward fix to a subtle problem in a core data structure. While the bug wasn't causing immediate issues (since most code uses `hashmap_partial_clear()` instead), the correction ensures proper behavior for cases where hashmap reuse after clearing might occur.
