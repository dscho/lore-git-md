This is the second patch in a 3-part series extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The patch focuses on server-side functionality, allowing servers to advertise additional fields beyond just "name" and "url" when describing promisor remotes to clients.

The key addition is a new `promisor.sendFields` config option that lets servers specify which additional fields to include (currently limited to "partialCloneFilter" and "token"). The implementation uses a string_list to manage allowed fields and includes case-insensitive comparison for field names. Server-side, it looks up configured values for these fields under the remote's namespace (e.g., `remote.<name>.partialCloneFilter`).

The patch includes comprehensive documentation updates in both promisor.adoc and protocol-v2.adoc, clearly specifying the protocol changes and field constraints. It also includes a new test case in t5710 that verifies proper transmission of configured fields. The implementation maintains backward compatibility while adding the new functionality, with careful attention to URL encoding requirements and field validation.

This builds on the foundation established in patch 1/3 (which introduced the string_list-based internal representation) and sets up for patch 3/3 that will handle client-side validation of these fields. The changes are well-contained, with clear documentation and test coverage for the new functionality.
