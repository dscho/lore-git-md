This is a technical discussion about collision checks in the index-pack process, specifically regarding promisor objects, as part of Patrick Steinhardt's object store refactoring series.

The email clarifies Patrick's reasoning for excluding promisor objects from index-pack collision checks, addressing Junio Hamano's earlier question about why this behavior is "highly dubious". Patrick explains there are two possible trust models for object verification: trust-on-first-use (where the initially seen object is considered correct) or consensus-based (where all remotes must agree). The current implementation inconsistently treats the promisor remote as more trusted than others without clear justification.

Patrick argues that fetching promisor objects for collision checks is likely unintentional and wasteful, since the promisor remote is often the same as the fetch source. He concludes that these checks should be removed from the series for now, prioritizing the broader refactoring work over fixing what he sees as clearly broken behavior.
