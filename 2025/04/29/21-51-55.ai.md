This is a debugging suggestion in the ongoing investigation of reflog corruption during `git rebase --rebase-merges`. Jeff King (peff@peff.net) proposes using address and undefined behavior sanitizers (SANITIZE=address,undefined) to help detect memory issues that might explain the intermittent corruption of `ctx->reflog_message` in the sequencer.

The key technical hypothesis is that the static strbuf used for reflog messages might be getting reallocated while `ctx->reflog_message` still holds an old pointer, leading to use-after-free scenarios. This would explain why the corruption appears intermittently and is hard to reproduce under GDB (where memory behavior can differ due to debugger overhead).

The suggestion builds on prior debugging by Kristoffer Haugsbakk and Phillip Wood, who identified the problematic code path in sequencer.c involving `do_merge()` -> `run_git_commit()` where the reflog action string sometimes contains garbage memory. The SANITIZE build would help verify if memory management issues are indeed the root cause.

This email doesn't propose a fix but offers a concrete next step that could help confirm or rule out a specific class of memory bugs in the complex interaction between the sequencer's merge handling and reflog message management.
