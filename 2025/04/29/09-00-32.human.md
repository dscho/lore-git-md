This is a performance optimization patch for xdiff's `--minimal` mode, now in its second revision with suggested improvements incorporated. Phillip Wood provides final review feedback, confirming the changes look good and echoing Junio Hamano's earlier suggestion to include performance numbers in the commit message.

The patch modifies xdiff's `cleanup_records` heuristic to skip marking lines as changed when they're surrounded by many changes, but only when `--minimal` is explicitly requested. This produces shorter diffs in about 1.3% of cases without measurable performance impact (benchmarks show `2.363s ± 0.023s` vs `2.362s ± 0.035s` for `git log -p -3000 --minimal`).

The implementation now properly derives `need_min` from `cf->flags` (as Phillip suggested in v1) and includes a new test script `t4071-diff-minimal.sh` that verifies unchanged lines surrounded by changes don't appear in minimal diffs. The discussion has reached consensus that this is the right behavior for `--minimal` mode, where shortest-possible diffs are explicitly requested.
