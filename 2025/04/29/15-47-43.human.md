Bugfix for hashmap reuse after clear(). This patch fixes a latent issue where calling `hashmap_clear()` would make the hashmap unusable for future operations due to zeroing out critical function pointers. The problem was discovered when attempting to reuse a strmap/strset after clearing, leading to a NULL pointer dereference.

Elijah Newren explains that while `hashmap_partial_clear()` was designed for reuse cases, the regular `hashmap_clear()` inadvertently made the structure unusable by wiping all fields rather than just the essential ones. The fix preserves the comparator function and other necessary fields while still properly clearing the hash table itself.

The commit message notes this was a discovered-but-untriggered bug in the wild, as most code paths use `hashmap_partial_clear()` when reuse is needed. The change is minimal (3 lines modified) and focused on the core issue, leaving grow/shrink thresholds to be naturally recalculated on subsequent inserts.

This appears to be a straightforward correction of an oversight in the original implementation, with clear negative consequences for anyone who might try to reuse a cleared hashmap. The fix aligns with the intended behavior while maintaining safety.
