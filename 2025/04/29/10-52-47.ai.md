This is an earlier version (v3) of the Outlook Message-ID handling patch for `git send-email`, showing the evolution of the solution that was later finalized in v6/v7. The patch introduces a boolean `--[no-]outlook-id-fix` option to control Message-ID retrieval from Outlook SMTP servers, before the design evolved into the tri-state configuration that was ultimately accepted.

The v3 patch implements a boolean toggle that either forces the Message-ID fix on or off, with automatic detection still happening when unspecified (checking for known Outlook hostnames). The documentation explains Outlook's Message-ID behavior and warns about using the forced mode with non-Microsoft providers. The implementation modifies the `is_outlook()` helper to respect this configuration.

Key technical details include:
- Boolean option (`--[no-]outlook-id-fix`) controlling Message-ID retrieval
- Default 'auto' behavior checking for `smtp.office365.com`/`smtp-mail.outlook.com`
- Modified `is_outlook()` function that respects the configuration
- 15 lines of documentation explaining the Outlook behavior and option usage
- Maintains backward compatibility when option isn't specified

This version shows the intermediate state before Junio Hamano's feedback led to the tri-state design (`always|never|auto`) in the final version. The thread context shows this boolean approach was Junio's stylistic preference, though he ultimately accepted the string-based version for better enterprise configurability. The patch is cleanly implemented with proper documentation, showing the solution evolving through community feedback.
