This is a feature proposal for improving the `--patch` interactive commands in Git. The author Leon Michalak notes that while `git diff` and related commands respect the `diff.context` configuration for controlling the number of context lines shown, the `--patch` variants (like `git add -p`) do not have an easy way to configure this. Currently the only workaround is using the environment variable `GIT_DIFF_OPTS=-u<number>`, which is inconvenient.

The email suggests three potential solutions: 1) adding `-U/--unified` command-line options to all interactive patch commands, 2) making `diff.context` apply to these commands (though noting this might surprise users), or 3) introducing a new `interactive.context` setting specifically for patch commands. The author is seeking feedback on whether this feature would be welcome and which approach might be best before submitting a patch.

Key technical points for future reference: The change would affect all builtins using `run_add_p()`, the current workaround uses `GIT_DIFF_OPTS`, and the proposed solutions involve either new command-line flags or configuration options (`diff.context` or new `interactive.context`). The discussion will likely weigh the convenience of unified configuration versus the potential surprise of changing existing behavior.
