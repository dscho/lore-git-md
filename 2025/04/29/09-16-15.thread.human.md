This thread discusses a proposal to improve context line control in Git's interactive patch commands (`git add -p` and similar). Leon Michalak points out that while regular `git diff` respects the `diff.context` configuration, the interactive variants don't have a straightforward way to configure this - currently requiring the awkward `GIT_DIFF_OPTS` environment variable workaround.

Three potential solutions are on the table: adding new `-U/--unified` flags to the interactive commands, making them respect the existing `diff.context` setting (though this might surprise some users), or introducing a new `interactive.context` configuration specifically for these cases. The author is soliciting feedback on which approach would be most appropriate before proceeding with an implementation.

The change would affect all commands using Git's `run_add_p()` infrastructure, and the discussion will likely center around balancing convenience with backward compatibility - whether to extend existing configuration or introduce new dedicated controls for interactive use.
