Leon Michalak's proposal to improve interactive patch commands (`git add -p` and similar) is gaining clarity. The thread began with three possible approaches to make these commands respect diff context configuration (currently requiring awkward `GIT_DIFF_OPTS` workarounds). After feedback from both Junio Hamano (favoring command-line flags) and Jeff King (preferring config inheritance), Michalak now suggests a hybrid solution: default to `diff.context` and `diff.interhunkcontext` settings while still allowing per-invocation overrides via `-U` and `--inter-hunk-context` flags.

This middle ground addresses both permanent configuration needs and temporary adjustments, while explicitly avoiding the technical complexity of mid-session context changes (which Junio noted would require major architectural work). The proposal focuses first on context lines, deferring other diff-related configurations for potential future inclusion. Implementation would modify the shared `run_add_p()` infrastructure used by all interactive patch commands, maintaining backward compatibility. The discussion appears to be converging on this approach, with the main technical work remaining in adapting the plumbing-level code to respect porcelain configurations.
