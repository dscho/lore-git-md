Leon Michalak has proposed improving how interactive patch commands like `git add -p` handle diff context, with discussion now converging on a hybrid approach. The solution would inherit standard diff context settings from diff.context and diff.interhunkcontext configurations while still allowing per-command overrides via -U and --inter-hunk-context flags. This satisfies both technical constraints (maintaining stable hunk tracking during sessions) and user experience needs (consistent porcelain behavior).

Junio Hamano recently weighed in, agreeing with the technical approach while noting that interactive commands may benefit from different context settings than batch diffs - users often need more context when processing hunks one at a time. This observation validates the design choice to make these configurations available while keeping them distinct from core diff machinery.

The thread shows consensus on modifying the shared run_add_p() infrastructure to implement this change across all interactive commands (add -p, checkout -p, etc.), maintaining backward compatibility. While some implementation details remain to be worked out, the core approach addresses both maintainer concerns about feasibility and user needs for flexible context control. The solution leaves room for future extension to other diff-related configurations once this foundational change is in place.
