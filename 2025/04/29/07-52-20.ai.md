This is patch 6/7 in Patrick Steinhardt's refactoring series to clean up object file handling, continuing the ps/object-file-cleanup effort. The patch systematically replaces all remaining calls to the deprecated `repo_has_object_file()` and `repo_has_object_file_with_flags()` functions with the newer `has_object()` API across 23 files.

The changes are mechanical conversions that maintain identical behavior by mapping the old flag combinations to equivalent `has_object()` flags:
- The basic `repo_has_object_file()` becomes `has_object()` with both `HAS_OBJECT_RECHECK_PACKED` and `HAS_OBJECT_FETCH_PROMISOR` flags set
- Various `_with_flags()` combinations translate to specific flag patterns in the new API
- All conversions are verified to be functionally equivalent

Key technical aspects:
- Touches core object handling in `object-store.c`, `fetch-pack.c`, `http-walker.c`
- Updates ref-related code in `refs.c`, `reflog.c`, `remote.c`
- Modifies several builtins including `cat-file`, `fetch`, `clone`, `index-pack`
- Preserves promisor object fetching behavior via flag mappings
- Maintains existing collision detection in `index-pack.c` and `bulk-checkin.c`

The patch follows the series' conservative approach by keeping all existing behavior while removing the deprecated API surface. It builds on the earlier patches that established the new flag-based API (patch 5/7) and reorganized headers. The changes are widespread but straightforward, with each conversion clearly matching the documented flag equivalences from the commit message.
