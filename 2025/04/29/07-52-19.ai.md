This is patch 5/7 in Patrick Steinhardt's refactoring series to clean up object store APIs, specifically introducing promisor object fetching capability to `has_object()` as part of transitioning away from `repo_has_object_file()`.

The patch adds a new `HAS_OBJECT_FETCH_PROMISOR` flag that allows `has_object()` to fetch missing objects from promisor remotes when requested, matching functionality currently provided by `repo_has_object_file()`. The implementation modifies the internal flag handling in `has_object()` to conditionally set `OBJECT_INFO_SKIP_FETCH_OBJECT` based on the new flag, while maintaining the existing `HAS_OBJECT_RECHECK_PACKED` behavior for packed object checking.

Key technical changes include:
- Conversion of `HAS_OBJECT_RECHECK_PACKED` from a macro to an enum flag
- New flag architecture that preserves all existing behavior by default
- Updated documentation in object-store.h clarifying the default non-fetching behavior
- Mechanical changes to object-store.c's flag handling logic

This continues the series' conservative approach to API migration, ensuring no behavior changes unless explicitly requested via flags. The patch follows the established pattern from earlier in the series of maintaining exact functionality while cleaning up the implementation, with the promisor fetch capability being the last major piece needed before fully removing the deprecated functions in subsequent patches.
