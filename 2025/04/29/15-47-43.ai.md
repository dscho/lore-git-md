This is a bugfix for the hashmap implementation that addresses a latent issue with `hashmap_clear()`. The patch ensures hashmap structures remain reusable after being cleared, fixing a potential NULL pointer dereference when attempting to reuse cleared maps.

The issue stems from `hashmap_clear()` zeroing out the entire hashmap structure, which inadvertently clears essential function pointers (`cmpfn`) and other fields needed for proper operation. The fix modifies the clearing logic to only reset the table-related fields (`tablesize` and `private_size`) while preserving the function pointers and other operational state.

The commit message provides useful context about the bug's discovery during work on strmap/strset functionality, though it notes this wasn't triggering issues in current code since most reuse cases use `hashmap_partial_clear()` instead. The change is minimal (3 lines modified) but important for correctness when reusing cleared maps.

Key technical details for future reference:
- Preserved fields: `cmpfn`, `data`, `do_count_items`
- Reset fields: `table` (freed), `tablesize`, `private_size`
- Related functions: `hashmap_partial_clear()`, `hashmap_clear_and_free()`
