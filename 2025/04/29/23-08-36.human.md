This is a transitional patch in the `git send-email` Outlook Message-ID handling series, showing the shift from a simple boolean toggle to a more flexible string-based control while maintaining backward compatibility.

The patch introduces a `--[no-]outlook-id-fix` option to handle Microsoft Outlook's non-standard Message-ID behavior, where Outlook SMTP servers discard the original Message-ID and assign a new one, breaking email threads. The option provides explicit control over whether to use its Outlook-specific workaround to retrieve the server-assigned Message-ID.

Notably, this v4 iteration maintains automatic detection for standard Outlook domains (smtp.office365.com and smtp-mail.outlook.com) while introducing the boolean interface for manual override. The documentation has been improved from earlier versions, now clearly explaining both the automatic behavior and manual control cases.
