This is the second patch in a 3-part series extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series builds on earlier work to limit the protocol to specific predefined fields for security and maintainability.

The patch introduces a new `promisor.sendFields` configuration that lets servers advertise additional remote attributes beyond just name and URL. Currently only "partialCloneFilter" and "token" fields are supported - the former for partial clone configuration and the latter for authentication. The implementation uses case-insensitive comparison for field names and includes comprehensive tests showing the new field transmission works as expected.

The changes touch protocol documentation, configuration handling, and the core promisor-remote logic while maintaining backward compatibility. Documentation updates clearly explain the new capability and its constraints. The implementation appears solid, with careful attention to memory management and proper use of Git's string_list patterns as suggested in previous review feedback.

This continues the series' progression toward allowing clients to make more informed decisions about which promisor remotes to use, while keeping the protocol constrained to prevent arbitrary data transmission. The next patch will implement client-side validation of these fields.
