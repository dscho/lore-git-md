This is part 5 of Patrick Steinhardt's refactoring series to clean up the object store API, specifically introducing promisor object fetching capability to the new `has_object()` function.

The patch adds a new `HAS_OBJECT_FETCH_PROMISOR` flag that allows `has_object()` to fetch missing objects from promisor remotes when requested. This is a key step in the deprecated `repo_has_object_file()` removal effort, as it provides equivalent functionality for partial clone cases. The change is minimal (13 lines net) and focused - it just adds the flag and adjusts the object info flags accordingly while maintaining the existing default behavior of not fetching.

This continues the series' careful approach of maintaining all existing promisor behavior while modernizing the API. The implementation looks straightforward and builds on the earlier uncontroversial mechanical changes in patches 1-4. As with previous patches, this appears to be a well-considered incremental change that moves toward the series' goal without introducing new behavior.
