This is the third and final patch in a v2 series extending the promisor-remote protocol to support configurable validation of remote attributes. The series adds client-side field checking to complement the server-side field advertisement introduced in patch 2/3.

The patch introduces a new `promisor.checkFields` configuration that lets clients verify specific fields (currently only "partialCloneFilter" and "token") match local expectations before accepting a promisor remote. This provides security and consistency guarantees - for example, ensuring a server's partial clone filter matches what the client expects, or that authentication tokens are correct.

The implementation builds on the series' foundation of using `string_list` for field handling, with case-insensitive comparisons and proper memory management. It includes comprehensive tests showing the validation in action, rejecting mismatched fields while preserving the existing promisor-remote behavior. Documentation explains the new config option and its interaction with the server-side `promisor.sendFields` from patch 2/3.

This completes the series' goal of safely extending promisor-remote capabilities while maintaining backward compatibility. The implementation looks solid, with thorough test coverage and clear documentation. The constrained approach (limiting to specific fields) addresses earlier protocol design concerns from the discussion.
