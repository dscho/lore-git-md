This is a follow-up discussion on a previously accepted static analysis fix for `diff.c`. Jeff King (peff) agrees with Johannes Schindelin's patch to reorder a bounds check to satisfy CodeQL's static analysis, but suggests a more comprehensive solution that would future-proof against similar false positives.

The original patch addressed a CodeQL false positive in `fill_es_indent_data()` by moving the `off < len - 1` check before the array access. Peff notes this works for the current false positive but points out the same pattern exists for other character checks (`\f` and `\v`), suggesting a more robust solution that would protect all array accesses with a single bounds check.

This is a refinement discussion rather than a new proposal - the core patch has already been accepted and is in the 'seen' branch. Peff's suggestion is framed as a potential improvement to consider, noting that while the current solution works for today's CodeQL version, future versions might flag similar patterns. The thread demonstrates Git maintainers' careful consideration of static analysis integration, balancing tool accommodation with code robustness.
