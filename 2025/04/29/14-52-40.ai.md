This is a feature patch series extending the promisor-remote protocol capability to support configurable validation of remote attributes during clone/fetch operations. The series is at v2 with 3 patches, building on previous discussion about protocol design and implementation concerns.

The core change allows servers to advertise additional remote attributes (currently just "partialCloneFilter" and "token") beyond just name/URL, and lets clients validate these against their local configuration. The implementation replaces strvec with string_list for more flexible field handling and adds case-insensitive field name comparison.

Key technical changes in v2:
- Limited allowed field names to predefined values ("partialCloneFilter" and "token") rather than arbitrary config keys
- Renamed config variables from "sendExtraFields"/"checkExtraFields" to "sendFields"/"checkFields"
- Improved documentation of protocol field semantics
- Fixed memory leaks and improved cleanup logic
- Added case-insensitive field name comparison
- Strengthened BUG() checks for field positions

The series appears well-crafted with thorough test coverage and documentation updates. It addresses previous feedback by constraining the protocol to specific fields rather than arbitrary config keys, which should help with security and compatibility. The implementation follows Git's string_list patterns and includes comprehensive tests in t5710.

Open questions from v1 about protocol-level field definition appear resolved by limiting to specific fields. The case sensitivity fix mentioned in the cover letter (comparing field names case-insensitively) has already been implemented in this version.
