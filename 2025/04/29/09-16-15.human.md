This is a feature proposal for improving the interactive patch commands in Git. Leon Michalak notes that while `git diff` and related commands respect the `diff.context` configuration for controlling the number of context lines shown, the interactive `--patch` variants (like `git add -p`) do not offer an easy way to configure this. Currently, users must resort to the clunky `GIT_DIFF_OPTS` environment variable workaround.

The email suggests three potential solutions: adding `-U/--unified` command-line options to these commands, extending `diff.context` to cover interactive patches (though this might surprise users), or introducing a new `interactive.context` setting specifically for patch commands. The author is seeking feedback on whether this feature would be welcome and which approach might be best.

The proposal seems well-motivated by a real workflow pain point, and the author appears open to implementing it pending community input. The options presented cover both backward-compatible approaches (new config/CLI options) and more invasive changes (modifying existing behavior). This could spark an interesting discussion about UI consistency versus backward compatibility in Git's interactive commands.
