This is a feature series extending the promisor-remote protocol capability to support configurable validation of remote attributes during clone/fetch operations. The v2 series addresses feedback from v1 by limiting allowed fields to "partialCloneFilter" and "token" for clearer semantics and security.

The series refactors the internal representation from strvec to string_list for flexibility, then adds server-side advertisement of additional fields via `promisor.sendFields` and client-side validation via `promisor.checkFields`. The implementation maintains backward compatibility while allowing servers to advertise and clients to verify remote properties like partial clone filters and authentication tokens.

Key changes in v2 include:
- Renamed config variables from "sendExtraFields"/"checkExtraFields" to simpler "sendFields"/"checkFields"
- Limited allowed fields to just "partialCloneFilter" and "token" for well-defined semantics
- Added case-insensitive field name comparison
- Improved documentation and commit messages
- Fixed memory leaks and simplified cleanup logic
- Added more comprehensive tests

The series appears well-considered, with thorough test coverage and clear documentation updates. The protocol design questions raised in v1 about field handling semantics appear addressed by limiting to specific fields. The implementation follows Git conventions and handles edge cases properly. This looks ready for serious consideration, though the security implications of token handling may warrant additional discussion.
