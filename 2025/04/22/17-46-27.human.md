Performance optimization for the new `git-blame-tree` command. This is the 4th patch in a 5-part RFC series introducing a tree-level blame capability.

The patch implements a significantly faster algorithm for tracking path modifications across commits. The original approach performed a full revision walk and diff at each step, which could be slow for paths with long histories. The new version uses a priority queue and Bloom filters to:

1. Only process "active" paths that haven't been assigned to a commit yet
2. Skip unnecessary diffs when Bloom filters indicate paths definitely weren't modified
3. Propagate path states efficiently between parent commits

Performance improvements are dramatic - up to 52x faster on the kernel repository when using Bloom filters (9.8x without). The implementation maintains all existing functionality while adding proper cleanup of resources.

The patch builds on earlier work in the series, particularly the Bloom filter integration from Taylor Blau. It includes comprehensive changes to the core blame-tree logic while keeping the same external interface. The implementation appears production-ready, though marked as RFC" to gather feedback on the performance characteristics.
