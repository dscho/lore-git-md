This is a cover letter for a feature proposal introducing a new `git-blame-tree` command, representing a second attempt to upstream this functionality after incorporating changes from GitHub's implementation. The series consists of 5 patches (3 from other contributors, 2 from the submitter) that implement a command to track changes across directory trees rather than individual files.

Key technical aspects include:
- New `blame-tree.c` and `builtin/blame-tree.c` implementing the core functionality
- Optional Bloom filter optimization (from Taylor Blau's implementation)
- Non-recursive by default (`-r` flag required for recursion)
- Removed `USE_THE_REPOSITORY_VARIABLE` usage
- New test suite in t/t8020-blame-tree.sh
- Performance benchmarking script in t/perf/p8020-blame-tree.sh

The cover letter notes several deliberate exclusions from this submission: caching layer implementation (`.git/blame-tree/<hash>.btc` files), `--max-depth` functionality, and some GitHub-specific optimizations that didn't show clear performance benefits in the submitter's testing. The author positions this as an RFC seeking feedback before further refinement.

The implementation appears to be a serious effort with multiple contributors' work integrated, though the author notes some uncertainty about performance characteristics and requests review of attribution in commit messages. The test coverage and benchmark infrastructure suggest this is being developed with production use in mind.
