CI infrastructure fix addressing the git-p4 test execution gap.

This patch from Patrick Steinhardt resolves the root cause of why git-p4 tests weren't running in GitHub Actions CI, despite dependencies being installed. The issue stemmed from path inconsistency between installation (as root, using `$HOME/path`) and test execution (as unprivileged user with different `$HOME`). The solution matches GitLab CI's approach by hardcoding `/custom` as `CUSTOM_PATH` in GitHub Actions workflow configuration, ensuring p4d and p4 binaries are found during test runs. This directly addresses the CI coverage gap that allowed the t9811 test modernization regressions to go undetected. The patch is minimal (single-line addition to .github/workflows/main.yml) and builds on existing infrastructure patterns, making it low-risk to apply. Junio has indicated he will queue it, suggesting this is considered the proper fix for the immediate CI problem while the underlying test issues continue to be investigated separately.
