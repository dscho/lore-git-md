This is a technical follow-up in the Meson build system refactoring series, specifically addressing function availability checks.

Patrick Steinhardt responds to Eli Schwartz's suggestion about improving the `sysinfo.h` detection in the Meson build configuration. The discussion centers around commit c9a51775a36 which introduced usage of `struct sysinfo::mem_unit` for RAM calculation in `builtin/gc.c`. 

The key change moves from a simple header presence check to verifying actual struct member availability via `compiler.has_member()`, though Patrick notes they only need to check one member (choosing `totalram`) rather than all used members. This maintains the build system's robustness while keeping the check simple.

The exchange demonstrates the series' ongoing refinement of function detection mechanisms, with Patrick accepting the technical improvement while making a practical judgment call about the scope of verification needed. This fits into the broader thread's focus on standardizing and improving build system checks during the autoconf-to-Meson transition.
