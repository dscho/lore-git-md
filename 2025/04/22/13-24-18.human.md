This is a CI/build system discussion in the ongoing thread about implementing header checking in Meson builds. Phillip Wood responds to Karthik Nayak's CI workflow changes with two suggested improvements.

Phillip proposes making the Git installation step in GitHub Actions more robust by detecting package managers via `command -v` rather than checking for distribution-specific files in `/etc`. His version would first check if Git is already installed, then try package managers in order (apk, dnf, apt-get) without worrying about cache updates since those happen elsewhere in the workflow.

He also questions whether GitHub's checkout action might be causing the repository detection issues, suggesting instead an explicit `git clone` that would guarantee working from a proper Git repository rather than a tarball extraction. This addresses the core problem the thread has been discussing - ensuring the header checks can run in CI environments where Git metadata is needed.

The suggestions show Phillip's attention to making the solution both more maintainable (avoiding distribution-specific checks) and more reliable (ensuring proper Git repository setup). The thread has already seen extensive discussion about CI environment quirks, and these proposals would further refine the approach.
