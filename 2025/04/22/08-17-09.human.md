Platform compatibility discussion about memory allocators on Windows, specifically regarding the future of nedmalloc.

This email from Johannes Schindelin responds to Patrick Steinhardt's question about whether to keep nedmalloc in Git's codebase. Schindelin strongly favors removing the unmaintained nedmalloc but notes there are complications. He explains that while Windows 11's default allocator performs well, older Windows versions still need a custom allocator. 

The email reveals that Git for Windows has already switched to mimalloc (Microsoft's allocator) and Schindelin would like to upstream this change before removing nedmalloc. He references past performance tests showing Windows allocators have improved significantly since nedmalloc was first integrated. The discussion ties back to the ongoing Windows/ARM64 support work where nedmalloc currently doesn't compile.

This is part of broader architectural considerations about memory management in Git, with implications for both performance and maintenance burden. The tone suggests this will require careful coordination, particularly around supporting older Windows versions, before nedmalloc can be fully removed.
