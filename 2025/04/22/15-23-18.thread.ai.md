Git send-email OAuth2 and Outlook compatibility series (v3) by Aditya Garg and Julian Swagemakers. Adds SMTP bearer authentication (OAuth2) support via OAUTHBEARER and XOAUTH2 mechanisms (RFCs 5801 and 7628), implemented directly in `git-send-email.perl` since Perl's Authen::SASL lacks support. Includes new helper functions (`generate_oauthbearer_string`, `generate_xoauth2_string`) and main `smtp_bearer_auth` function that enforces TLS encryption. Also fixes Outlook-specific Message-ID handling where Outlook replaces the original Message-ID with its own proprietary header and server-generated ID, modifying `git-send-email.perl` to extract the Outlook-assigned Message-ID from the SMTP server response (appearing in `<...>` wrapper) when sending through Office365/Outlook SMTP servers (`smtp.office365.com`, `smtp-mail.outlook.com`). The retrieved ID replaces the locally-generated one to maintain thread continuity, with regex capture from `$smtp->message` response, error handling for failed extraction, and debug output showing the retrieved ID. Introduces `--generate-password` option for OAuth2-like token generation and new `--smtp-passeval` option that allows dynamically generating OAuth2 tokens or passwords via external scripts (e.g., Python `refresh_token.py` for Outlook OAuth2 refresh tokens), implemented with new `$smtp_authpasseval` variable and logic in `smtp_auth_maybe()` to execute user-specified commands and capture output as authentication tokens. The changes modify both implementation (~120+ lines added across series) and documentation, with example configurations for Gmail and Office 365 setups using git-credential-oauth. Tested-by from git-credential-oauth maintainer confirms real-world validation. Currently being used by authors to send from Outlook. The series now provides complete Outlook SMTP compatibility by addressing both protocol support (XOAUTH2/OAUTHBEARER) and dynamic credential generation needs while maintaining security (TLS enforcement) and integrating cleanly with Git's existing SMTP auth flow. Open questions may include maintainability tradeoffs of Outlook-specific behaviors versus broader standards compliance, though the solution remains well-scoped with Outlook behavior clearly gated behind server-domain checks.
