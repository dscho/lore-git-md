Git send-email OAuth2 and Outlook compatibility series (v4) by Aditya Garg and Julian Swagemakers. Adds SMTP bearer authentication (OAuth2) support via OAUTHBEARER and XOAUTH2 mechanisms (RFCs 5801 and 7628), implemented directly in `git-send-email.perl` since Perl's Authen::SASL lacks support. Includes new helper functions (`generate_oauthbearer_string`, `generate_xoauth2_string`) and main `smtp_bearer_auth` function that enforces TLS encryption. Also fixes Outlook-specific Message-ID handling where Outlook replaces the original Message-ID with its own proprietary header and server-generated ID, modifying `git-send-email.perl` to extract the Outlook-assigned Message-ID from the SMTP server response (appearing in `<...>` wrapper) when sending through Office365/Outlook SMTP servers (`smtp.office365.com`, `smtp-mail.outlook.com`). The retrieved ID replaces the locally-generated one to maintain thread continuity in future replies via In-Reply-To headers, with regex capture from `$smtp->message` response, error handling for failed extraction, and debug output showing the retrieved ID. Introduces `--generate-password` option for OAuth2-like token generation and new `--smtp-passeval` option that allows dynamically generating OAuth2 tokens or passwords via external scripts (e.g., Python `refresh_token.py` for Outlook OAuth2 refresh tokens), implemented with new `$smtp_authpasseval` variable and logic in `smtp_auth_maybe()` to execute user-specified commands and capture output as authentication tokens.

Junio Hamano's technical concerns from v3 have been fully addressed in v4: (1) the Message-ID handling patch now accurately describes the sequence where Outlook replaces the ID during transmission and Git captures the new ID from the SMTP response solely for future replies, (2) the `--smtp-passeval` option now correctly documents its mandatory argument requirement. Aditya implemented Junio's suggested improvements: (1) extracted Outlook domain check into a helper function, (2) clarified debug output to show Outlook is reassigning the ID, (3) maintained user-visible messaging about ID reassignment. The core mechanism remains unchanged but is now precisely documented - capturing the Outlook-assigned ID from the SMTP server response (in `<...>` format) when using Office365/Outlook SMTP servers, with the update happening after message transmission to affect future replies only.

The discussion has reached consensus that the implementation is sound, with v4 providing accurate documentation of the behavior: Git sends with its own Message-ID, Outlook replaces it during transmission, and Git retrieves the new ID from the SMTP response solely for threading future replies. No further code changes are needed beyond the v4 documentation improvements. The solution remains well-scoped with Outlook behavior gated behind server-domain checks. The broader OAuth2 authentication changes in the series appear uncontested while the Message-ID handling is now fully documented with accurate technical details about the Outlook interaction sequence.
