Git send-email OAuth2 and Outlook compatibility series (v3) by Aditya Garg and Julian Swagemakers. Adds SMTP bearer authentication (OAuth2) support via OAUTHBEARER and XOAUTH2 mechanisms (RFCs 5801 and 7628), implemented directly in `git-send-email.perl` since Perl's Authen::SASL lacks support. Includes new helper functions (`generate_oauthbearer_string`, `generate_xoauth2_string`) and main `smtp_bearer_auth` function that enforces TLS encryption. Also fixes Outlook-specific Message-ID handling where Outlook replaces the original Message-ID with its own proprietary header and server-generated ID, modifying `git-send-email.perl` to extract the Outlook-assigned Message-ID from the SMTP server response (appearing in `<...>` wrapper) when sending through Office365/Outlook SMTP servers (`smtp.office365.com`, `smtp-mail.outlook.com`). The retrieved ID replaces the locally-generated one to maintain thread continuity, with regex capture from `$smtp->message` response, error handling for failed extraction, and debug output showing the retrieved ID. Introduces `--generate-password` option for OAuth2-like token generation and new `--smtp-passeval` option that allows dynamically generating OAuth2 tokens or passwords via external scripts (e.g., Python `refresh_token.py` for Outlook OAuth2 refresh tokens), implemented with new `$smtp_authpasseval` variable and logic in `smtp_auth_maybe()` to execute user-specified commands and capture output as authentication tokens.

Junio Hamano has raised technical concerns about two aspects: (1) the Message-ID handling patch (v3 2/3) has a discrepancy between implementation and commit message - the patch updates `$message_id` after email headers are sent (affecting future replies) rather than the current message's headers as claimed, requiring commit message clarification and potential extraction of Outlook domain check into a helper function; (2) the `--smtp-passeval` option documentation in patch 3/3 fails to specify behavior when the command argument is omitted, with Junio questioning the utility of making the argument optional at all since both `--smtp-passeval` and `--smtp-passeval=` forms without a command seem meaningless for password generation. These critiques focus on documentation clarity and edge case handling rather than fundamental objections to the features.

The changes modify both implementation (~120+ lines added across series) and documentation, with example configurations for Gmail and Office 365 setups using git-credential-oauth. Tested-by from git-credential-oauth maintainer confirms real-world validation. Currently being used by authors to send from Outlook. Open questions include maintainability tradeoffs of Outlook-specific behaviors versus broader standards compliance, clarification needed for both the Message-ID modification timing in the email flow and the `--smtp-passeval` optional argument behavior. The solution remains well-scoped with Outlook behavior gated behind server-domain checks, now awaiting documentation refinements in response to Junio's specific wording suggestions.
