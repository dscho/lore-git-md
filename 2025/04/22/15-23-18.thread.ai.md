Git send-email OAuth2 and Outlook compatibility series (v3) by Aditya Garg and Julian Swagemakers. Adds SMTP bearer authentication (OAuth2) support via OAUTHBEARER and XOAUTH2 mechanisms (RFCs 5801 and 7628), implemented directly in `git-send-email.perl` since Perl's Authen::SASL lacks support. Includes new helper functions (`generate_oauthbearer_string`, `generate_xoauth2_string`) and main `smtp_bearer_auth` function that enforces TLS encryption. Also fixes Outlook-specific Message-ID handling where Outlook replaces the original Message-ID with its own proprietary header and server-generated ID, modifying `git-send-email.perl` to extract the Outlook-assigned Message-ID from the SMTP server response (appearing in `<...>` wrapper) when sending through Office365/Outlook SMTP servers (`smtp.office365.com`, `smtp-mail.outlook.com`). The retrieved ID replaces the locally-generated one to maintain thread continuity, with regex capture from `$smtp->message` response, error handling for failed extraction, and debug output showing the retrieved ID. Introduces `--generate-password` option for OAuth2-like token generation and new `--smtp-passeval` option that allows dynamically generating OAuth2 tokens or passwords via external scripts (e.g., Python `refresh_token.py` for Outlook OAuth2 refresh tokens), implemented with new `$smtp_authpasseval` variable and logic in `smtp_auth_maybe()` to execute user-specified commands and capture output as authentication tokens.

Junio Hamano raised technical concerns about two aspects: (1) the Message-ID handling patch (v3 2/3) had a discrepancy between implementation and commit message - the timing of `$message_id` updates (affecting future replies rather than current message headers as originally claimed), which Aditya Garg has now confirmed is the intended behavior and will be clarified in the commit message; (2) the `--smtp-passeval` option documentation in patch 3/3 incorrectly suggested the command argument was optional, which Aditya has confirmed is mandatory (both `--smtp-passeval` and `--smtp-passeval=` forms without arguments are invalid). Aditya agrees to implement Junio's suggested improvements for the Message-ID patch: (1) extracting the Outlook domain check into a helper function for maintainability, (2) rewording the debug output to clarify Outlook is reassigning the ID rather than Git retrieving it, and (3) keeping some form of message about the ID reassignment for user visibility. The core mechanism remains unchanged - capturing the Outlook-assigned ID from the SMTP server response (in `<...>` format) when using Office365/Outlook SMTP servers, with the update happening after message transmission to affect future replies.

The follow-up discussion clarified that Outlook actively replaces the original Message-ID header with its own server-generated value during transmission, and Git's post-transmission capture of this ID (from `$smtp->message` response in `<...>` format) is solely for threading future replies via In-Reply-To headers. Junio provided precise commit message wording to describe this sequence, which Aditya will incorporate. No code changes are needed beyond documentation fixes, as the core mechanism is sound. The changes modify both implementation (~120+ lines added across series) and documentation, with example configurations for Gmail and Office 365 setups using git-credential-oauth. Tested-by from git-credential-oauth maintainer confirms real-world validation. Currently being used by authors to send from Outlook. The solution remains well-scoped with Outlook behavior gated behind server-domain checks, now with clarified mandatory argument requirement for `--smtp-passeval` and pending documentation/structural improvements to the ID handling patch in response to Junio's feedback. The broader OAuth2 authentication changes in the series appear uncontested while the Message-ID handling reaches consensus on implementation approach pending final documentation refinements.
