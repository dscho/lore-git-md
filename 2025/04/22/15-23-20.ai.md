This is the second patch in a 3-part series adding Outlook compatibility to `git send-email`, specifically addressing Message-ID handling. The patch fixes a thread-reply issue where Outlook replaces the original Message-ID with its own proprietary header and server-generated ID.

The change modifies `git-send-email.perl` to extract the Outlook-assigned Message-ID from the SMTP server response (which appears in a `<...>` wrapper) when sending through Office365/Outlook SMTP servers. The retrieved ID then replaces the locally-generated one, maintaining thread continuity. The implementation includes error handling for failed extraction and debug output showing the retrieved ID.

Key technical details for future reference:
- Targets specific Outlook SMTP domains (`smtp.office365.com`, `smtp-mail.outlook.com`)
- Uses regex capture from `$smtp->message` response
- Maintains backward compatibility when extraction fails
- Adds localized warning/status messages
- Part of broader OAuth2/Outlook compatibility work

The patch appears well-scoped to solve a specific interoperability issue, with the Outlook-specific behavior clearly gated behind server-domain checks. The solution follows the pattern established in the series of working within Outlook's constraints while maintaining standards compliance elsewhere.
