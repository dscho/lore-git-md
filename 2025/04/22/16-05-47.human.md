Bugfix for wildcard pathspec handling in `git add` and `git commit`. This patch addresses an issue where commands like `git add f*` would skip files like 'foo' if a literal file named 'f*' existed in the directory. The fix ensures proper wildcard expansion while maintaining the ability to match literal files by escaping the wildcard (e.g., `f\*`).

The change is small but impactful - modifying a single condition in `dir.c` to properly handle the `nowildcard_len` case. The patch comes with extensive test coverage in a new test script `t6137-pathspec-wildcards-literal.sh` that verifies both wildcard and literal matching behavior for various patterns (*, ?, [abc], etc.) across both `add` and `commit` commands. The tests are skipped on Windows due to filename limitations.

This appears to be a well-constructed fix for a real usability issue, with thorough test coverage demonstrating both the problem and solution. The patch is mentored by Jeff King and addresses a reported bug, suggesting it has already gone through some review. The Windows test exclusion is noted as expected given platform filename constraints.
