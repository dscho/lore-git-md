This is a technical discussion about Change-ID semantics in the ongoing thread about standardizing change tracking across VCS implementations. Junio C Hamano responds to Nico Williams' position on Change-ID uniqueness requirements, while advancing his own perspective on semantic requirements.

Hamano makes several key points in this reply: First, he acknowledges the practical benefits of Williams' position that Change-IDs need not be strictly unique, but counters with the advantages of using commit object names as Change-IDs - this provides both uniqueness (via Git's object naming) and the ability to directly reference the original change. He suggests this could be implemented with some encoding scheme if UI differentiation from regular object names is desired.

The email strongly emphasizes Hamano's view that the critical semantic requirement for Change-IDs is their ability to track the evolution of changes through multiple iterations. He explicitly rejects any scheme that cannot show the original change and its evolutionary path, framing this as a non-negotiable aspect of useful change tracking. This builds on but sharpens his earlier content-based generation position by tying it directly to evolution tracking capabilities.

Technically, the email introduces the idea of using commit object names (possibly encoded) as Change-IDs, which would automatically provide both uniqueness and evolution tracking through Git's existing object model. This contrasts with both random generation approaches and workflow-derived methods discussed earlier in the thread. The implementation would need to handle UI presentation concerns while maintaining the semantic link to the original change.

This response moves the thread forward by:
1) Rejecting uniqueness relaxation while offering a technical solution that provides it anyway
2) Elevating evolution tracking as a core semantic requirement
3) Proposing a concrete generation method that satisfies both technical and semantic needs
4) Setting up potential implementation questions about encoding schemes and UI integration

The discussion now has clearer technical alternatives to evaluate against the growing set of requirements, with Hamano's position representing a content-based approach that specifically addresses the newly emphasized semantic purity concerns around evolution tracking.
