This is a follow-up discussion in the Windows/ARM64 compatibility patch series, specifically about patch 3/6 which disables nedmalloc for Windows/ARM64 builds.

Patrick Steinhardt questions whether nedmalloc should be kept in the Git codebase at all, given that it fails to compile on Windows/ARM64 and appears to be unmaintained (as noted in the original patch's commit message). The original patch from Johannes Schindelin cited a 2017 GitHub issue showing the project's inactivity, but Patrick's email suggests this might be an opportunity to consider removing nedmalloc entirely rather than just disabling it for one platform.

The thread context shows this is part of a well-received series to enable Git on Windows/ARM64, with maintainer Junio Hamano already planning to integrate it. The nedmalloc question appears to be a new consideration raised by Patrick that wasn't part of the original series discussion. The original patch took a conservative approach of only disabling nedmalloc where necessary (Windows/ARM64), but Patrick's question might prompt a broader discussion about the allocator's future in Git.
