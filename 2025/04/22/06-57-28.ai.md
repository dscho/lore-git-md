This is a follow-up discussion in the ongoing thread about implementing header checking in Meson builds, specifically addressing the handling of non-Git repository scenarios. Patrick Steinhardt responds to Phillip Wood's observations about the CI environment where `git ls-files` fails due to tarball extraction.

The key points center around two approaches for handling missing Git repositories: 1) simply disabling header/coccinelle checks when Git isn't available (Patrick's preference), versus 2) implementing a `find` fallback like the Makefile does (Phillip's alternative suggestion. Patrick argues the fallback adds unnecessary overhead since most users would have Git available, with CI being the main exception that could be fixed by installing Git first.

The discussion reveals an important implementation detail - the current Meson setup already has logic to skip coccinelle checks when not in a Git checkout (via the `coccinelle_opt` check), suggesting a precedent for this approach. Patrick positions distributors and developers as the primary users who would need these checks, implying CI can be treated as a special case.

This exchange continues the thread's theme of balancing Makefile parity with Meson design decisions, now focusing on the tradeoffs between compatibility and simplicity in repository detection. The technical solution remains unchanged from the series, but the discussion clarifies the rationale behind not implementing the `find` fallback.
