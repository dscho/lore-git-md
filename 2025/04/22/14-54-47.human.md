This is the first patch in a 5-part series refactoring string_list implementation and tests, focusing on fixing signed/unsigned comparison warnings. The patch addresses compiler warnings in string-list.c by changing loop iterator types from `int` to `size_t` where appropriate, and removes an unused `insert_at` parameter that was causing a tricky signed/unsigned comparison.

The key change is simplifying the `add_entry()` function by removing its unused `insert_at` parameter, which was the only place where negative values (other than -1) could cause problems with unsigned comparisons. The author notes this parameter was never actually used for its intended purpose - all callers just use -1. The rest of the changes are straightforward type fixes for loop variables to match the unsigned `list->nr` type.

This appears to be a clean, focused change that eliminates compiler warnings while maintaining existing behavior. The patch is part of a larger effort to modernize string_list tests by converting them from shell to C unit tests, but this first piece is purely about fixing type safety issues in the core implementation. The changes are mechanical but well-explained in the commit message.
