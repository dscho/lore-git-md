This is a feature proposal introducing a new `git-blame-tree` command, submitted as an RFC (Request For Comments) by Toon Claes. The command appears to be a tree-aware version of `git blame` that can track changes across directory structures, building on work originally from GitHub's Taylor Blau.

The cover letter explains this is a revised version that:
1. Excludes some GitHub-originated features like caching and max-depth controls for later consideration
2. Makes recursion optional via `-r` flag rather than default
3. Addresses technical debt by removing `USE_THE_REPOSITORY_VARIABLE` and fixing memory leaks
4. Combines some intermediate commits from GitHub's version for cleaner history

The author notes some uncertainty around performance claims from the original work, as their benchmarks didn't show the same improvements. They're explicitly seeking feedback on this RFC before proceeding further.

The series includes 5 patches:
- Core command implementation (Toon)
- Bloom filter optimization (Taylor)
- Performance algorithm (Taylor)
- Test infrastructure (Jeff King)
- Revision walk initialization fix (Toon)

This looks like a serious proposal with thorough test coverage (new perf tests and functional tests), though the performance discrepancies and caching question suggest there may be open design discussions ahead. The exclusion of GitHub's caching layer indicates this is being deliberately scoped to core functionality first.
