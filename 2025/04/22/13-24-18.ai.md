This is a CI/build system discussion in the ongoing thread about implementing header checking in Meson builds. Phillip Wood responds to Karthik Nayak's CI workflow changes with two technical suggestions for improving the Git installation and repository setup in GitHub Actions.

Phillip proposes:
1. A more robust package manager detection approach using `command -v` checks rather than distribution-specific file checks, which would make the CI script more maintainable across different Linux distributions. He suggests simplifying the installation commands by removing package cache updates since those are handled elsewhere.

2. Replacing GitHub's checkout action with an explicit `git clone` command to ensure the build always starts from a proper Git repository rather than potentially a tarball extraction. This would address the thread's earlier concerns about repository detection and the chicken-egg problem of needing Git installed to check out the code.

The email continues the thread's focus on making the header checking workflow reliable across different CI environments while maintaining simplicity. Phillip's suggestions aim to reduce distribution-specific knowledge in the CI scripts while ensuring consistent repository access - both key requirements for the Meson header checking implementation being discussed.
