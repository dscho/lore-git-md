Thread identity: Bugfix patch addressing wildcard pathspec handling in Git commands, reported by Piotr Siupa and mentored by Jeff King. Focuses on `git add` and `git commit` behavior with wildcard pathspecs.

Core problem: When a literal file named like a wildcard pattern exists (e.g. `f*`), commands like `git add f*` incorrectly skip matching files (e.g. `foo`). The patch ensures proper handling of escaped wildcards (e.g. `f\*` for literal matching) by modifying `do_match_pathspec` in `dir.c` to correctly handle the `nowildcard_len` case.

Current status: Revised version submitted with improved test structure and commit message clarity following maintainer feedback. The one-line change in `dir.c` adds a condition checking if `nowildcard_len` equals the full pathspec length. Comprehensive test coverage in new file `t6137-pathspec-wildcards-literal.sh` verifies all major wildcard types (`*`, `?`, `**`) and their escaped variants, with isolated test cases using subshells and proper Git conventions (tab indentation, HERE-DOC formatting). Windows-specific tests are skipped via `FUNNYNAMES` prerequisite.

Key technical details: Tests cover both `git add` and `git commit` scenarios with `test_cmp` verification, added to meson.build. The implementation builds on existing pathspec handling infrastructure while fixing the specific edge case of literal wildcard-named files. Both positive (wildcard matching) and negative (literal matching via escapes) cases are covered.
