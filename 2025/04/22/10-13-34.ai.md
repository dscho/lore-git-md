This is a review response in the ongoing promisor-remote refactoring series, specifically addressing patch 2/4 which replaces strvec with a more flexible linked list structure. Patrick Steinhardt raises several technical points about the implementation details.

The key observations focus on naming conventions, memory management patterns, and structural assumptions in the new promisor_info linked list implementation. Patrick suggests the free function should follow subsystem-first naming (promisor_info_list_free rather than free_info_list) and questions why the cleanup uses a trailing pointer (p) rather than the head pointer (info_list).

He identifies potential fragility in the new implementation's handling of field ordering, noting the code makes assumptions about "name" and "url" fields appearing at specific indices (0 and 1) without explicit lookup. This is enforced via assert/BUG checks that weren't present in the original strvec version. Patrick suggests adding proper field lookup functions rather than relying on positional assumptions.

The review doesn't challenge the overall approach of moving from strvec to a more flexible linked list structure, but focuses on implementation rigor - particularly around memory management patterns and field access safety. These are implementation-level concerns rather than protocol design issues, distinct from the broader protocol questions Junio raised about the series' approach to field handling.
