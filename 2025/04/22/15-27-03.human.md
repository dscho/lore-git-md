This is a build system patch in the ongoing Meson modernization series, specifically addressing Windows platform handling for networking functions.

Eli Schwartz responds to Patrick Steinhardt's feedback on patch 6/6, which originally proposed skipping networking symbol checks on Windows entirely. The discussion centers around whether to maintain platform-specific handling for Windows or use a more generic approach. Eli points out that Windows has special considerations for hstrerror() compatibility that while the function exists in the compat directory, it shouldn't be used on Windows.

The technical debate focuses on:
1. Whether to skip networking checks on Windows (Eli's position) or perform them with special handling (Patrick's initial suggestion)
2. Correct handling of hstrerror() compatibility on Windows
3. The presence of compat implementations for inet_ntop/pton but special behavior needed for hstrerror

Eli provides concrete evidence that hstrerror.c exists in compat/ (contrary to Patrick's initial comment) but maintains that Windows should still be treated specially. The patch itself modifies the Meson build to skip networking function checks on Windows while adding the appropriate compat implementations for other platforms.

This appears to be a well-reasoned technical discussion between two build system experts, with Eli providing clear justification for the Windows-specific approach while addressing Patrick's concerns about maintainability. The patch seems ready for inclusion pending final agreement on the Windows handling strategy.
