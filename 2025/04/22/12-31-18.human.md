This is a bugfix report for a test failure on s390x systems related to partial clone backfilling. The issue occurs when running tests involving the `--min-batch-size` parameter in the backfill command, where the value gets corrupted on big-endian systems.

The root cause appears to be a type mismatch: `min_batch_size` is declared as `size_t` but parsed using `OPT_INTEGER`, leading to incorrect value assignment on s390x (a big-endian architecture). The reporter suggests two potential fixes - either using `OPT_MAGNITUDE` instead of `OPT_INTEGER`, or changing the variable type to `int` if the values won't exceed integer limits.

The bug report is thorough, including system details and compiler information, though the reporter notes they're new to open source contributions. The issue seems legitimate and well-analyzed, with clear reproduction steps and two proposed solutions that would need review from maintainers familiar with the backfill implementation and cross-platform considerations.
