This is a bugfix and refinement to the Meson build system networking checks, part of the ongoing build system modernization effort.

Patrick Steinhardt responds to Eli Schwartz's patch that aimed to skip networking function checks on Windows, pointing out a flaw in the implementation. While Eli's patch correctly notes that Windows doesn't have these functions and proposes skipping the checks, Patrick observes that the patch would try to use a non-existent compatibility implementation for `hstrerror()` if the check failed.

The discussion reveals some nuances in how different build systems handle these networking functions - CMake checks only for `hstrerror()` while skipping Windows, whereas the Meson implementation was checking multiple functions. Patrick suggests keeping the checks even on Windows for simplicity, though the current focus is fixing the immediate issue with the missing `hstrerror.c` compat file.

This exchange comes as part of final review for a 6-patch series standardizing function availability in the Meson build system, where networking function handling has emerged as a particularly tricky area requiring platform-specific attention. The thread shows careful attention to cross-platform compatibility details as the project moves toward deprecating autoconf.
