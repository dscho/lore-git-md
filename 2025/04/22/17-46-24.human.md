Feature introduction: First patch in a series adding `git-blame-tree` command.

This initial patch introduces the core functionality for a new `git-blame-tree` command that tracks changes across directory trees rather than individual files. The implementation includes new files `blame-tree.c` and `builtin/blame-tree.c` with basic tree-walking capabilities. The command works by expanding a tree at a given commit and walking backwards through history to find when each path last changed.

The patch shows signs of careful development, with contributions from Jeff King and Ævar Arnfjörð Bjarmason incorporated. It includes comprehensive test coverage in `t/t8020-blame-tree.sh` that verifies both recursive and non-recursive operation, subdirectory handling, and merge scenarios. The implementation avoids using `the_repository` global variable, aligning with current Git codebase practices.

While positioned as an RFC, the patch appears production-ready with thorough test infrastructure. The author seeks feedback on the approach before further refinement, particularly around performance characteristics and commit message handling. This is the foundational patch in a 5-part series that aims to provide GitHub-like tree blame functionality in core Git.
