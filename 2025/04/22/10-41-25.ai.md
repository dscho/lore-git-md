This is a follow-up in the ongoing thread about fixing `GIT_PERF_*` environment variable handling in Git's performance test infrastructure. Jeff King points out that a recent merge commit (e8cf2b99cd) introduced a regression by incorrectly reordering the sequence of operations in `t/perf/perf-lib.sh`.

The original fix (from Johannes Schindelin) worked by:
1. Stashing `GIT_PERF_*` variables
2. Sourcing `test-lib.sh` (which could override them)
3. Restoring the stashed values

However, the merged version now:
1. Sources `GIT-BUILD-OPTIONS` and `test-lib.sh` first
2. Then stashes and restores variables (which is ineffective since the damage is already done)

The core issue remains the interaction between build-time configuration in `GIT-BUILD-OPTIONS` and runtime environment variables for performance testing. While this thread previously established that the patch was an acceptable temporary fix, this merge error shows how fragile the solution is. The email serves as a heads-up about the regression and clarifies the correct ordering needed for the variable preservation to work as intended.

Key technical details:
- The problematic merge is e8cf2b99cd (Merge branch 'ps/meson-build-perf-bench')
- The fix requires moving the `git_perf_settings` capture before sourcing both `GIT-BUILD-OPTIONS` and `test-lib.sh`
- The `eval` restoration must remain after the sourcing operations

This continues the theme from earlier in the thread that this is a band-aid solution while deeper issues with variable handling in the test infrastructure remain unresolved.
