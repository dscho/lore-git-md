Performance optimization for the new `git-blame-tree` command. This patch from Toon Claes (with code originally by Taylor Blau) adds Bloom filter support to skip unnecessary diff computations during the revision walk. When Bloom filters indicate a path wasn't modified in a commit, the command can bypass the expensive diff calculation.

The implementation adds Bloom key handling to the `blame_tree_entry` struct and introduces a new `maybe_changed_path()` function to consult the filters. Benchmark results show dramatic improvements - from 5.1s to 0.75s when testing on the kernel repository with optimized builds. The patch appears well-integrated with the existing blame-tree infrastructure, properly cleaning up Bloom keys when entries are removed.

This is part of the ongoing RFC series introducing the new git-blame-tree command, with this optimization building on prior work by Taylor Blau. The performance gains make the feature much more practical for large repositories, though the series remains marked RFC to gather feedback on the overall approach.
