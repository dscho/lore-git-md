Performance optimization patch for the new `git-blame-tree` command, implementing a faster algorithm that avoids unnecessary diff computations. This is part of the RFC series introducing tree-level blame functionality.

The patch rewrites the core algorithm to use a priority queue of commits sorted by generation number, propagating "active" paths (those not yet associated with a commit) up through parent commits. Key optimizations include:

1. Truncated revision walks that only process active paths
2. Bloom filter integration to skip first-parent diffs when paths definitely haven't changed
3. New data structures including a commit slab for tracking active paths and a priority queue

Performance improvements are dramatic:
- 2.78-9.81x faster with Bloom filters
- 1.58-4.81x faster without filters
- Up to 52x faster than original implementation in some cases (Linux kernel repo)

The implementation handles all existing functionality while adding:
- Proper cleanup of new data structures
- Boundary commit handling
- Parent diff optimizations
- Path tracking via diff indices

Co-authored-by credit goes to Derrick Stolee for contributions to the algorithm. The patch maintains all test coverage from previous iterations while delivering substantial performance gains, making the command more practical for large repositories.
