This thread introduces two improvements to `git send-email` to better support Microsoft email services. The first patch, originally by Julian Swagemakers and expanded by Aditya Garg, adds OAuth2 authentication support (required by Microsoft's recent security changes) with proper TLS encryption and integration with the `git-credential-oauth` helper. The second patch, new in this series, fixes a thread continuity issue specific to Outlook servers, which handle Message-IDs differently than standard email servers by storing the original ID in a proprietary header and generating their own.

Aditya Garg has tested both changes in real-world use by sending this patch series using the modified `send-email` itself. The OAuth2 implementation follows RFC standards (5801 and 7628) while the Outlook fix specifically targets their nonstandard behavior - checking for known Microsoft domains and extracting the server-assigned Message-ID from the SMTP response. The relationship between the two patches isn't fully explained, but together they address key barriers to using `git send-email` with Microsoft's email services. No review feedback has been posted yet since the series is newly submitted.
