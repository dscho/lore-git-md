This is a technical discussion about qsort() verification in Git's build system, part of the ongoing Meson refactoring series. Eli Schwartz and Patrick Steinhardt are debating how to handle platform-specific qsort() performance issues in the transition from autoconf to Meson.

Eli argues that rather than checking for qsort() availability at build time (which Meson does), Git should explicitly list known-bad platforms (like Windows and AIX) that need the internal qsort implementation due to performance problems. He points to existing platform-specific configurations in config.mak.uname and suggests the CMake build's unconditional use of internal qsort may reflect Windows-specific needs.

Patrick prefers maintaining a generic detection system that checks for qsort() availability, arguing it's simpler to maintain and that platform-specific issues can be addressed if they arise. The core disagreement centers on whether to encode platform knowledge (Eli's position) or rely on generic detection (Patrick's preference).

This discussion is part of the broader build system modernization effort, with the qsort() question being one of several platform-specific verification issues being worked through.
