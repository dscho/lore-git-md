This is a bugfix patch addressing wildcard pathspec handling in Git commands, accompanied by comprehensive new tests. The patch fixes an issue where `git add f*` would skip files like 'foo' if a literal file named 'f*' existed, and ensures proper handling of escaped wildcards (like `f\*` for literal matching).

The core change is in `dir.c`, modifying the `do_match_pathspec` function to properly handle the `nowildcard_len` case. The bulk of the patch consists of a new test file `t6137-pathspec-wildcards-literal.sh` that thoroughly tests wildcard and literal pathspec behavior with both `git add` and `git commit`. The tests cover various wildcard patterns (`*`, `?`, `**`) and their escaped variants, verifying correct expansion and literal matching.

The patch was reported by Piotr Siupa and mentored by Jeff King. It skips Windows-specific testing due to filename limitations. The test file follows Git's standard test structure with clear setup/teardown and uses `test_cmp` for verification. The changes appear well-considered with a focused scope (just the pathspec matching logic) and comprehensive test coverage.
