This thread addresses a bug in how `git add` and `git commit` handle wildcard pathspecs when literal files exist with names that look like wildcards (e.g., a file named `f*`). The original report from Piotr Siupa, with mentoring from Jeff King, identified that commands would incorrectly skip matching files in such cases. The fix modifies `dir.c` to properly handle escaped wildcards (like `f\*`) while maintaining normal glob expansion for unescaped patterns.

After initial review, Junio Hamano suggested improvements to the test structure and commit message clarity, which have now been incorporated. The current version includes comprehensive tests in `t6137-pathspec-wildcards-literal.sh` covering all major wildcard types (`*`, `?`, `**`) and their escaped variants, with proper isolation and Git test conventions. The implementation itself is a focused one-line change that checks path lengths before skipping matches.

The patch appears ready for merging, with all technical feedback addressed. The only remaining note is a minor formatting observation about how the patch displays in email clients, which doesn't affect the functionality. This small but well-tested change cleanly fixes an edge case in Git's pathspec handling.
