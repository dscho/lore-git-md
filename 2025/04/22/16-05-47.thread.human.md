This thread addresses a bug in Git's wildcard pathspec handling, where commands like `git add f*` would incorrectly skip files like 'foo' if a literal file named 'f*' existed. The patch, reported by Piotr Siupa and mentored by Jeff King, fixes this in `dir.c` by correcting the `do_match_pathspec` function's handling of `nowildcard_len`.

The solution comes with extensive test coverage in a new file `t6137-pathspec-wildcards-literal.sh`, which verifies correct behavior for various wildcard patterns (`*`, `?`, `**`) and their escaped variants (`f\*`). The tests cover both `git add` and `git commit` operations, though Windows-specific cases are skipped due to filename limitations. The changes are well-contained and thoroughly validated, focusing specifically on the pathspec matching logic without broader side effects.
