This is a code review response in the ongoing promisor-remote refactoring series. Patrick Steinhardt provides feedback on Christian Couder's patch that replaces strvec usage with a linked list of promisor_info structs.

Patrick raises several specific technical concerns about the implementation details. He questions the naming of the free_info_list() function, suggesting it should follow the subsystem-first naming convention. More substantially, he points out what appears to be an incorrect memory management pattern where the wrong pointer (p instead of info_list) is being freed in promisor_remote_info().

The review also notes potential fragility in the new implementation's assumptions about field ordering, suggesting the code should look up fields by name rather than assuming fixed positions. Patrick questions the use of assert() where BUG() might be more appropriate and expresses general concern about the hardcoded field positions in the new linked list structure.

This feedback comes as part of the broader discussion about extending promisor-remote capabilities, where Junio C Hamano has already raised protocol design concerns that may require series rework. Patrick's comments focus specifically on implementation details of the refactoring rather than the higher-level protocol questions.
