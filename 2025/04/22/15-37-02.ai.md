Bugfix for performance test variable handling regression. This email from Junio Hamano acknowledges Jeff King's explanation of why the recent merge commit (e8cf2b99cd) broke the GIT_PERF_* variable handling fix. The issue stems from incorrect ordering of operations in the test infrastructure - the variable stashing now happens after sourcing GIT-BUILD-OPTIONS and test-lib.sh, making the restoration ineffective. 

King's analysis clearly shows the problematic sequence change: the code now sources build configuration first (GIT-BUILD-OPTIONS) and test infrastructure (test-lib.sh) before attempting to preserve the runtime GIT_PERF_* variables, when it should do the stashing first. This confirms the regression is purely an ordering issue rather than a new underlying problem.

The thread continues to treat this as part of a larger test infrastructure issue with environment variable handling, with this being a specific manifestation that needs fixing while broader solutions are considered. The consensus remains that the original approach (stash before sourcing, restore after) is correct for this immediate fix, though the fragility of the solution highlights deeper architectural concerns about how build-time and runtime variables interact in Git's test framework.
