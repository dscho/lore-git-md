CI infrastructure fix addressing a critical gap in Perforce test coverage.

This patch from Patrick Steinhardt resolves a long-standing issue where Git's Perforce integration tests weren't actually running in CI, despite the dependencies being installed. The root cause was a path mismatch - the p4d and p4 binaries were being installed to `$HOME/path` during the privileged installation phase, but tests run as an unprivileged user with a different `$HOME` couldn't find them.

The solution aligns GitHub Actions configuration with GitLab CI by hardcoding `/custom` as the installation path. This follows the same approach that works in GitLab CI and ensures the binaries remain accessible across different execution contexts. The change is minimal (just one line added to the workflow file) but critical for proper test coverage.

Junio has reviewed and approved the fix, indicating it will be queued for merging. This addresses one of the systemic issues exposed by the recent git-p4 test modernization effort, where test failures went undetected due to the silent skipping of these tests in CI.
