This RFC thread introduces `git-blame-tree`, a new command that tracks modifications across directory trees rather than individual files. The series has evolved through six patches, with core functionality implemented in new source files and comprehensive test coverage. The command now features two major performance optimizations: Bloom filter integration (from Taylor Blau's work that reduced runtime significantly, and a priority queue algorithm co-developed with Derrick Stolee that provides additional speedups.

The latest patch further optimizes performance by streamlining revision walk initialization, building on earlier work to remove dependencies on `log_tree_commit()`. By setting `rev.no_walk = 1`, the command avoids unnecessary initialization work while maintaining all existing functionality. The change does lose the revision machinery's automatic validation of non-commit inputs, but this appears non-critical as the command's own logic likely handles validation.

Key contributors include the primary author, Jeff King and Ævar Arnfjörð Bjarmason for review feedback, Taylor Blau for Bloom filter foundations, and Derrick Stolee for co-developing the priority queue algorithm. The command now appears production-ready with demonstrable scalability for large repositories, though it remains marked as RFC to gather feedback on behavioral defaults and optional features.
