The `git last-modified` series, which tracks file modifications at the tree level with Bloom filter optimizations, is nearing completion after several iterations. The core functionality—including path handling, performance improvements (50%+ speedups for common cases), and integration with Git's Bloom filters—is solid and well-tested. Recent versions renamed the command from `blame-tree`, aligned with `git diff-tree` conventions, and added structured metadata output.

The remaining discussion centers on the `--extended` output format's implementation. Junio C Hamano has identified fundamental issues with the current approach of reusing `pretty_print_commit()`, which performs unwanted text transformations. In the latest email, he highlights specific problems with the test suite: hardcoded SHA-1 hashes (incompatible with future SHA-256 repositories), fragile timestamp dependencies, and inconsistent display of commit versus tree hashes. Toon Claes, the primary implementer, had already acknowledged the format's limitations and suggested either deferring the feature or clearly documenting its constraints.

Key participants include Junio (interface concerns), Patrick Steinhardt (architecture review), and Taylor Blau (Bloom filters). The series appears ready to merge once the team decides whether to: (1) drop the `--extended` format for now, (2) fix the test suite while keeping the current implementation, or (3) redesign the output format entirely. Given Toon's earlier comment that the basic output meets their needs, the first option seems likely. Performance benchmarks and core functionality are otherwise complete, making this one of the final polish steps before integration.
