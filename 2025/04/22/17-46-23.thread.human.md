This thread discusses the development of a new `git last-modified` command, which tracks file modifications at the tree level (rather than line-by-line like `git blame`). The v6 series, led by Toon Claes with contributions from several core developers, has reached its final form with comprehensive functionality and performance optimizations.

The command now includes Bloom filter integration to skip unnecessary diff computations when checking path modifications, showing significant speedups (50-55% faster for focused checks) while maintaining accuracy. The implementation handles merge commits properly and includes extensive test coverage across different usage patterns. Key contributors like Junio Hamano, Patrick Steinhardt, and Jeff King have reviewed the design, particularly around interface decisions and performance measurement methodology.

While the core functionality is complete, some areas remain for future work - notably optimizing recursive checks (which currently show minimal improvement) and potentially adding a caching layer. The series has addressed all major technical concerns through six iterations, with the final version dropping controversial features like the `--format` option while solidifying the performance test suite and Bloom filter integration. This positions `last-modified` as a specialized but robust tool for forge-style use cases where tree-level change tracking is needed.
