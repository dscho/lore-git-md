This thread discusses a proposed `git-blame-tree` command that tracks modifications across directory trees rather than individual files. The RFC series has evolved through 7 patches with substantial performance optimizations, including Bloom filter integration (from Taylor Blau's work) and priority queue algorithms (co-developed with Derrick Stolee), reducing runtime significantly in benchmarks. The command offers both recursive and non-recursive modes while maintaining a simple output format of commit-hash and path.

As the feature nears finalization, Marc Branchaud has raised concerns about the name, suggesting it either be integrated into `git blame` as a new mode (e.g. `--latest`) or given a completely different name to avoid confusion with the existing blame command. This naming discussion comes after extensive technical development, with the series having already incorporated feedback from Jeff King, Ævar Arnfjörð Bjarmason, and others. The core functionality appears production-ready, but the naming question remains open alongside earlier discussions about default behavior and input validation tradeoffs.
