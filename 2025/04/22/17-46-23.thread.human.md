The `git last-modified` command, now in its third revision, has seen substantial technical refinement with Bloom filter optimizations yielding 36-50% performance gains in common cases. The command tracks file modification history by walking commits backward, with core functionality established and comprehensive test coverage added. Key contributors including Patrick Steinhardt, Taylor Blau, and Toon Claes have shaped its architecture, while Kristoffer Haugsbakk has led documentation improvements.

A new discussion has emerged about the command's path handling behavior. Kristoffer notes that without the `-r` flag, the command shows directories rather than individual files in subdirectories - a departure from most Git commands' default behavior. For example, querying `t/*` displays just the directory name unless recursion is explicitly enabled. The command does support pathspec magic like exclusions (`:^`), but the output format may confuse users expecting file-level granularity by default. There's also a minor issue with error message ordering for unknown options.

These interface considerations come as the series enters its polishing phase. The technical foundation is solid, with optimizations validated and memory management refined. Documentation has been updated to clarify traversal scope and modernize terminology, though the command remains marked EXPERIMENTAL. The current discussion highlights how subtle UX choices - like default recursion behavior - can significantly impact usability, even for a plumbing command. Contributors are now weighing whether to adjust the defaults to match user expectations from other Git commands, or maintain the current behavior with clearer documentation.
