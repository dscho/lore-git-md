The `git last-modified` command series, which implements a tree-level path tracker with Bloom filter optimizations, is in its final polishing phase after being approved by Junio Hamano. While the core functionality is stable, the discussion has shifted to refining the interface details and documentation.

A key remaining question is the naming of the recursive tree handling option. The original `--tree-in-recursive` name was questioned by Patrick Steinhardt, with Toon Claes proposing `--recursive-with-trees` as an alternative. In the latest email, Junio Hamano suggests `--show-trees-in-recursive` as a clearer option that better follows Git's established naming patterns (similar to `git ls-tree -t`). This proposal adds an explicit verb to better describe the action is being performed during recursive traversal.

The series has already addressed several implementation details in post-merge review, including memory management fixes, removal of unnecessary operations, Bloom filter edge cases, and type system improvements (converting flags to `bool`). Documentation has been updated to clarify behavior and match Git's style guide, with additional CodingGuidelines clarification about resource cleanup functions.

Primary contributors in this phase include Toon Claes (implementation and documentation), Patrick Steinhardt (bug discovery and API feedback), Christian Couder (type system improvements), and Junio Hamano providing maintainer guidance. The discussion demonstrates Git's characteristic attention to detail in finalizing interfaces, even after technical approval. The remaining work is limited to finalizing the option name and updating documentation accordingly.
