This thread tracks the development of `git last-modified`, a new plumbing command that identifies when files were last modified by walking commits backward. The third revision (v3) of the implementation is now in its final polishing stages, with core functionality complete and performance optimizations yielding 2-5x speedups in most cases.

The latest patch from Taylor Blau adds Bloom filter support, skipping unnecessary diff computations when the filters indicate a path couldn't have changed. Benchmarks show dramatic improvements - 50% faster for top-level checks and 36% for subdirectories - though recursive traversal sees minimal benefit as it still examines most commits. The implementation builds on existing Git infrastructure and falls back gracefully when filters aren't available.

Key contributors have shaped the command's evolution: Jeff King and Ævar Arnfjörð Bjarmason provided foundational work, Patrick Steinhardt guided the architecture, while Toon Claes and Justin Tobler refined implementation details. The series has progressed through several optimizations - removing generation number checks, improving traversal, and now adding Bloom filters - while maintaining a focus on code quality. Documentation remains marked as EXPERIMENTAL (following `git-replay` precedent) while final polish is applied to hashmap style, error handling, and merge commit handling. With performance tests now in place and major bottlenecks addressed, the command appears ready for wider testing once these last items are resolved.
