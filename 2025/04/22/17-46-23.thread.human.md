This thread documents the evolution of a new `git last-modified` plumbing command, which tracks when paths were last modified in a repository's history (operating at tree-level rather than line-by-line like `git blame`). The series has gone through several iterations, with v4 addressing key review feedback and settling on a design that follows `git diff-tree` behavior for path handling, as confirmed by maintainer Junio C Hamano.

The implementation is technically complete, with core functionality in `builtin/last-modified.c`, comprehensive test coverage, and documented performance improvements (50% speedup with Bloom filters for top-level checks). Key contributors include Toon Claes (implementation), Patrick Steinhardt (architecture review), and Taylor Blau (Bloom filter integration). All major design decisions have been resolved with maintainer approval.

The latest update notes an upcoming but non-urgent Bloom filter API change that will require a trivial 3-line adjustment in the implementation when rebased. Junio suggests keeping the topics independent for now, as the changes are purely mechanical (renaming functions and adjusting parameter order) and don't affect the command's functionality. This marks the final loose end for a series that has addressed all substantive feedback and is ready for integration.
