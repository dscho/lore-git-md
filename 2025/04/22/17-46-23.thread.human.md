This RFC thread introduces `git-blame-tree`, a new command that tracks modifications across directory trees rather than individual files. The initial 5-patch series implemented core functionality with test coverage and basic performance benchmarks, featuring contributions from Jeff King, Ævar Arnfjörð Bjarmason, and Taylor Blau (who provided Bloom filter foundations). The command processes tree diffs using custom path-tracking structures and handles both recursive and non-recursive modes, with the latter being the default - a point still open for discussion.

The latest performance optimization patch, co-authored by Derrick Stolee, rewrites the core algorithm to be dramatically faster. By using generation-number-sorted priority queues and propagating only active paths up through history, it achieves speedups of 2.78-9.81x with Bloom filters and up to 52x in some cases. The implementation maintains all existing functionality while adding proper cleanup of new data structures and improved parent diff handling. 

With these optimizations, the command now appears production-ready, though it remains marked as RFC to gather final feedback. The remaining open questions center on whether to keep the non-recursive default behavior and whether to incorporate any GitHub-specific caching features that were prototyped but excluded from this version. The comprehensive test suite and performance benchmarks demonstrate the command's readiness for large repositories like the Linux kernel.
