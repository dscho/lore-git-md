This thread explores a proposed new `git-blame-tree` command for tracking modifications across directory trees, with recent discussion focusing on how to integrate it with the existing `git blame` command. The 7-patch series implements core functionality with performance optimizations (Bloom filters, priority queues) and handles path states via `blame_tree_entry` structs.

The debate has centered on three approaches: full integration into `git blame`, a split plumbing/public design, or keeping it as a separate command. Junio Hamano has clarified key constraints - notably that `git blame path/to/file` must maintain its current line-by-line behavior to avoid breaking expectations. Recent discussion with Marc Branchaud has refined the UI considerations, particularly around recursion behavior for directories. While Junio initially saw recursive output (like `git ls-files`) as natural, Marc advocates for non-recursive by default with an option to recurse, citing performance concerns. Both agree the behavior should be configurable.

Open questions remain about merge commit handling (needing test coverage) and the final command structure decision. The integration path now has clearer constraints, with Junio emphasizing backward compatibility. Key contributors include the primary author, Jeff King (technical review), Taylor Blau (Bloom filters), Derrick Stolee (priority queues), and Marc Branchaud (integration advocate). The RFC status continues as the thread works through these design questions.
