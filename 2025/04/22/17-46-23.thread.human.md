This RFC thread explores a new `git-blame-tree` command for tracking modifications across directory trees, with robust performance optimizations already implemented. The core functionality is production-ready, featuring Bloom filters, priority queues, and custom traversal logic that delivers significant speedups. 

The discussion has centered on two key questions: how to handle merge commits (where Junio Hamano and Toon Claes identified edge cases needing test coverage) and whether to integrate the functionality into `git blame` rather than creating a new command. Junio has weighed in favor of integration, suggesting either an explicit `--mode` flag or automatic path-based selection. Marc Branchaud strongly advocates for unification, while Kristoffer Haugsbakk's latest email counters that Git's existing command proliferation (with many niche `-tree` commands) hasn't caused major confusion in practice.

With the technical implementation solid, the thread now focuses on finalizing the user interface - whether to proceed with Junio's preferred integration path or maintain a separate command. The merge behavior test cases remain the primary technical loose end before this RFC can graduate from proposal status. Contributors including Jeff King, Derrick Stolee, and Taylor Blau have provided foundational work and reviews, while Marc and Kristoffer's exchange represents the ongoing debate about command design philosophy.
