This thread covers the development of a new `git last-modified` command that tracks when paths in a repository were last changed. The v2 series has established core functionality through extensive review process, with major architectural questions now resolved. The command walks history backwards to find the most recent modification for each path, with comprehensive test coverage and performance optimizations including Bloom filters and priority queue traversal.

The latest patch adds Bloom filter support to skip unnecessary diff computations, showing significant speed improvements (5x faster in benchmarks). While the optimization design is sound, Patrick Steinhardt's review identified several implementation details needing cleanup, including a questionable generation number check and some coding style issues. This follows his earlier thorough review of the command's architecture, where he raised concerns about input validation and suggested various code quality improvements.

Multiple reviewers have contributed to shaping this feature: Patrick on architecture and optimization, Justin Tobler on documentation, Toon Claes on performance, Jeff King on naming, Taylor Blau on Bloom filters, and Derrick Stolee on the priority queue implementation. The series is marked as experimental, allowing future refinement while the core functionality appears ready for merging pending resolution of the remaining code quality issues. The most recent discussion focuses on polishing the Bloom filter optimization before final integration.
