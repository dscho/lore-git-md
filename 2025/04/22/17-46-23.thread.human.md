This thread explores adding directory-level blame functionality to Git, with active debate about whether to create a new `git-blame-tree` command or extend the existing `git blame`. The RFC series implements core functionality with impressive performance optimizations (Bloom filters, priority queues) that reduce runtime from 5.1s to 0.75s in benchmarks. 

The discussion has crystallized around two key issues: technical implementation and user experience. On the technical side, Junio Hamano and Toon Claes have raised important questions about merge commit handling that need test coverage before finalizing the behavior. The user experience debate has grown more nuanced, with Marc Branchaud making a strong case against command proliferation, arguing that directory-blame belongs in `git blame` for discoverability. D. Ben Knoble offers a middle path - keeping `blame-tree` as plumbing while making `git blame <dir>` work seamlessly. 

The thread shows consensus that the functionality is valuable, with disagreement primarily about how to expose it. Performance work appears production-ready, while the RFC status remains pending resolution of merge behavior tests and final decisions about command structure. The discussion remains productive, with contributors thoughtfully considering both technical purity and end-user experience.
