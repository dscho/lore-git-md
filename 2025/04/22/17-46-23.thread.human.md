This thread explores adding directory-level blame functionality to Git, with active debate about whether to create a new `git-blame-tree` command or integrate the feature into `git blame`. The RFC series implements core functionality with impressive performance optimizations (Bloom filters, priority queues) that show 1.58-9.81x speedups in benchmarks.

Key discussion points include:
1. **Merge behavior**: Junio Hamano and Toon Claes identified edge cases needing test coverage, particularly around merge commits where paths may differ across parents. The author acknowledges these need addressing before finalizing.

2. **Command structure**: Three approaches have emerged:
   - Full integration into `git blame` (Marc Branchaud's preference)
   - A plumbing/public split like `diff`/`diff-tree` (D. Ben Knoble's suggestion)
   - Keeping a separate command (original approach)

Marc's latest email proposes concrete UI behaviors for integration, suggesting:
- A `--latest` flag to show only the last modifying commit per file
- Implicit directory handling where `git blame dir/` shows non-recursive last commits
- Explicit recursion control

Junio has indicated a leaning toward integration, provided the distinction between line-level and directory-level blame remains clear. The discussion now focuses on practical UI design questions, with contributors weighing discoverability concerns against command proliferation. The RFC remains pending resolution of merge test cases and final architectural decisions, but the performance optimizations and core functionality appear production-ready.
