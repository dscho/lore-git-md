Bugfix for Windows networking function verification in Meson build system.

This email addresses a bug in the networking function verification logic for Windows platform in the ongoing Meson build system refactoring series. Patrick Steinhardt points out that while Eli Schwartz's patch correctly identifies the need to add compatibility implementations for `inet_ntop` and `inet_pton`, it incorrectly includes `hstrerror` in the same check. The key issue is that while compatibility implementations exist for the first two functions, there is no `compat/hstrerror.c` file, which would cause the build to fail if the function wasn't found.

The discussion reveals a difference in approach between the contributors - Eli suggests skipping function checks entirely on Windows for simplicity and performance, while Patrick prefers maintaining consistent checks across platforms for better maintainability. The patch itself modifies the Meson build file to only perform these networking symbol checks on non-Windows systems, while adding the appropriate compatibility sources when functions are missing.

This ties into the broader thread about standardizing function availability verification in the Meson transition, specifically around networking dependencies. The bugfix ensures proper handling of platform-specific cases while maintaining the series' goal of moving from ad-hoc checks to a more systematic approach. The email also references how CMake handles similar cases, though notes CMake's implementation differs in only checking `hstrerror` and excluding it on that platform with potentially misleading comments.
