Performance test fix for p5332-multi-pack-reuse.sh, addressing the reported failures in the 1-pack bitmap setup scenario. Jeff King identifies that the test was incorrectly prefixing pack names with "+" when feeding them to `git multi-pack-index write --stdin-packs`, a vestige from an earlier version of the multi-pack reuse feature that supported "disjoint" packs (marked with "+"). The current implementation no longer handles this prefix, causing the command to fail with an empty pack list.

The patch simplifies the sed invocation to just strip directory paths from pack filenames, removing the problematic "+" prefix. This matches the current behavior expected by read_packs_from_stdin(). King provides sample output showing the test now produces expected performance metrics comparing single-pack vs multi-pack reuse across different scenarios (1-pack, 10-pack, 100-pack), demonstrating the CPU/size tradeoffs the test was designed to measure.

The fix is narrowly scoped to the test script's pack name formatting, with no changes to core Git functionality. The commit message thoroughly explains both the technical cause and historical context of the issue, tracing it back to a dropped feature from the original patch series (ba47d88795). This appears to be the root cause of the failures Philippe Blain observed across multiple platforms.
