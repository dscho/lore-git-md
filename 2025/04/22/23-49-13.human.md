Junio C Hamano weighs in on the ongoing Change-ID semantics discussion, emphasizing two key technical preferences. He advocates for using commit object names (potentially in encoded form) as Change-IDs, arguing this provides both uniqueness guarantees and direct traceability to the original change. The email also establishes Hamano's position that any viable Change-ID system must maintain clear evolution tracking - he explicitly rejects schemes that don't preserve the relationship between different versions of a change.

This contribution moves the discussion forward by:
1) Proposing a concrete implementation path (commit object names as IDs)
2) Adding the requirement for visible change evolution as a success criterion
3) Questioning the value of random generation when content-based alternatives exist

The email doesn't directly address the semantic purity concerns raised earlier, instead focusing on practical implementation benefits. Hamano's position appears to favor technical robustness over workflow convenience, though he leaves room for encoding schemes that might bridge UI needs. This sets up an interesting tension with previous arguments about semantic independence, as his proposal inherently ties Change-IDs to Git's object model.
