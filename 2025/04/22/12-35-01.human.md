Bugfix for partial clone backfill command's option parsing on s390x systems. This is a follow-up to an earlier bug report that identified a type mismatch when parsing the `--min-batch-size` option, where `OPT_INTEGER` was writing to a `size_t` field, causing corruption on big-endian architectures.

The patch proposes changing `OPT_INTEGER` to `OPT_MAGNITUDE` in `builtin/backfill.c`, which properly handles `size_t` values. The author had previously considered (and included in the thread) an alternative approach of changing the field type to `int`, but now focuses on the `OPT_MAGNITUDE` solution as the cleaner fix.

The issue was originally discovered through a test case failure in Debian's s390x builds, where the option value was being corrupted due to the type size mismatch. The patch appears straightforward and well-motivated, addressing a subtle platform-specific issue that could affect partial clone operations. The author demonstrates good debugging skills in tracing the root cause to the parse-options.c internals.
