This is a refactoring patch that fixes sign comparison warnings in string-list.c, part of a 5-patch series modernizing string_list tests and implementation.

The patch addresses compiler warnings from `-Wsign-compare` by changing loop iterators from `int` to `size_t` where appropriate. The key change is removing the unused `insert_at` parameter from `add_entry()`, which was always called with `-1` and could potentially cause issues if passed other negative values. The author explains this is a safe change since the only caller (`string_list_insert`) always passes `-1`, and future needs could be addressed differently.

The changes are mechanical type conversions except for the `add_entry()` modification, which simplifies the interface while maintaining behavior. The patch removes the `DISABLE_SIGN_COMPARE_WARNINGS` define since the warnings are now properly fixed. All string_list functionality remains identical - this is purely a code quality improvement.

For future reference, the patch touches core string_list operations including insertion, iteration, filtering and cleanup. Key changes include:
- Removed `insert_at` parameter from `add_entry()`
- Changed loop variables in `remove_duplicates()`, `for_each_string_list()`, `filter_string_list()`, and clear functions to `size_t`
- Added cast when comparing `index` with `list->nr` in `add_entry()`
- The changes maintain all existing behavior while eliminating compiler warnings
