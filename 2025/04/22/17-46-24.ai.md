Feature implementation introducing `git-blame-tree` command, part of a 5-patch RFC series.

This initial patch introduces the core functionality for `git-blame-tree`, a new command that tracks modifications across directory trees rather than individual files. The implementation includes new files `blame-tree.[ch]` and `builtin/blame-tree.c`, with comprehensive test coverage in `t/t8020-blame-tree.sh`. The command works by expanding a tree at a given commit, recording each path's state, then walking history backwards to find modification points.

Key technical details include:
- Uses a `blame_tree_entry` struct with path and oid tracking
- Implements hashmap-based path tracking with custom comparison
- Handles both recursive (`-r`) and non-recursive modes
- Processes diffs via callback functions `add_from_diff` and `blame_diff`
- Includes boundary commit handling and path filtering
- Outputs in format "commit-hash\tpath" (or NUL-terminated)
- Test suite covers basic functionality, subdirectory handling, merge scenarios, and error cases

The implementation appears production-ready with thorough test coverage, though positioned as an RFC to gather design feedback. Notable design choices include being non-recursive by default (unlike `git-blame`) and not including GitHub's caching layer or max-depth functionality from the reference implementation.
