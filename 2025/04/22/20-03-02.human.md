This is a follow-up discussion in the thread about configuration precedence between `pull.ff=only` and branch-specific rebase settings. D. Ben Knoble responds to Alex Henrie's suggestion to implement per-branch fast-forward controls (`branch.<name>.ff`), explaining why they're hesitant to pursue that approach.

Knoble initially started documenting how the new configuration would work but found the decision matrix of how various config options interact during `git pull` operations to be overwhelmingly complex. They note that while spelling out this matrix would be useful (perhaps in a blog post), they don't want to be the one to implement additional configuration complexity in Git itself.

The email reinforces the thread's earlier conclusion that existing configuration (`pull.ff=only` combined with `branch.<name>.rebase` settings) provides sufficient control without needing new knobs. Knoble's practical experience trying to document the proposed changes validates the thread's resolution that simpler is better in this case.
