This is a technical discussion about Change-ID implementation approaches in the context of Git tooling. Junio C Hamano responds to Remo Senekowitsch's report about Jujutsu's successful implementation of random Change-IDs by raising concerns about collision probability and suggesting an alternative approach using commit object names.

The exchange highlights two competing perspectives: Senekowitsch's practical experience showing the random-hex approach works in production versus Hamano's theoretical concern about long-term uniqueness guarantees. Hamano proposes using commit object names as Change-IDs for original commits and inheriting them for derived commits, arguing this would provide better uniqueness through Git's cryptographic hashing.

This reply moves the discussion from implementation reports back to design fundamentals, questioning whether random generation is truly preferable to content-derived identifiers despite Jujutsu's positive field experience.
