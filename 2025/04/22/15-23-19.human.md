Feature patch adding OAuth2 authentication support to `git send-email`. This is the first of three patches in a series that enables Git to work with modern email providers like Gmail and Office 365 that require OAuth2 authentication.

The patch implements SMTP bearer authentication (OAUTHBEARER and XOAUTH2) by manually handling the authentication flow, since Perl's Authen::SASL module doesn't support these methods. It includes proper TLS enforcement (required by RFC 7628) and generates the correct authentication strings following the relevant RFCs. The implementation has been tested with both Gmail and Office 365 configurations.

The changes modify `git-send-email.perl` to handle the new authentication types and update the documentation to explain the new functionality. Users will need to configure their credential helper to provide the OAuth2 token (the patch references git-credential-oauth as one option) and set `smtpEncryption=tls`.

This appears to be a well-researched implementation with clear references to relevant RFCs and real-world testing. The patch is part of a larger effort to improve Git's email sending capabilities for modern email providers, particularly Outlook/Office 365.
