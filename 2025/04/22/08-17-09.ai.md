This is a discussion about memory allocator strategy in the context of the Windows/ARM64 support series. Johannes Schindelin responds to Patrick Steinhardt's question about whether to keep the unmaintained nedmalloc allocator in Git's codebase.

The email reveals several key technical details about allocator history and current state:
- Nedmalloc is confirmed unmaintained since 2017
- Git for Windows has already switched to mimalloc (Microsoft's allocator)
- Performance tests suggest modern Windows allocators may be sufficient
- Older Windows version support complicates dropping custom allocators
- Johannes proposes upstreaming mimalloc first before removing nedmalloc

The discussion connects to the ongoing Windows/ARM64 work through:
- Current patch disabling nedmalloc specifically for Windows/ARM64 builds
- Broader allocator strategy questions raised by platform-specific builds
- Historical context of allocator choices in Git for Windows

Open questions and potential follow-ups include:
- Whether/when to upstream mimalloc support
- Performance impact on older Windows versions
- Whether to maintain multiple allocator options long-term
- How this aligns with Meson build system adoption

The email suggests this allocator discussion may spawn separate work from the immediate Windows/ARM64 support goal, with Johannes indicating a preference for systematic allocator transition rather than piecemeal removal.
