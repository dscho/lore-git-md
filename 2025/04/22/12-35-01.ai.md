Bugfix for partial clone backfill command's option parsing on s390x systems, following up on earlier discussion about type mismatches in big-endian architectures. The patch proposes using OPT_MAGNITUDE instead of OPT_INTEGER for the --min-batch-size parameter in builtin/backfill.c, addressing the issue where OPT_INTEGER's 4-byte write to a size_t field caused corruption on s390x (where size_t is 8 bytes).

The email corrects an earlier diff submission and confirms the OPT_MAGNITUDE solution works on both x86 and s390x test systems. However, it notes this might not be universally portable if size_t isn't unsigned long on some platforms. The alternative approach of changing min_batch_size's type to int is mentioned but left open pending clarification about practical value ranges.

The original bug report details remain relevant, showing how strtol() through OPT_INTEGER only initializes the first 4 bytes of the size_t field, causing large values on big-endian systems. System configuration details are provided showing 8-byte size_t on s390x. The thread continues to weigh the tradeoffs between the two solution approaches (parser change vs type change) for this and potentially similar cases elsewhere in the codebase.
