This is a follow-up in the ongoing Meson benchmark integration thread, addressing a final edge case about error handling when the `time` command is missing. Patrick Steinhardt responds to Christian Couder's earlier question about what happens when benchmarks are run without `time` available in the system.

The current behavior is that Meson simply prints "No tests defined" in this case, which isn't particularly helpful. Patrick suggests improving discoverability by listing benchmarks as part of the auto-detected features during build setup, which would make it clearer when benchmarks are disabled due to missing dependencies.

This appears to be the last remaining open question in the otherwise complete benchmark integration effort. The series has already addressed all other technical concerns raised in previous rounds, including path resolution, error message consistency, and documentation. The response suggests the patch series is in good shape, with this being a minor usability polish that could be addressed either now or in a follow-up.
