Performance optimization patch for the new `git-blame-tree` command, part of the RFC series. This fifth patch in the series removes unnecessary initialization work from the revision walk machinery now that the command no longer relies on `log_tree_commit()`. The change sets the `no_walk` flag to avoid redundant processing while maintaining the same functionality.

The patch demonstrates careful attention to performance details, showing the command's continued refinement. It builds on Taylor Blau's earlier work and maintains all existing test coverage. The only behavioral change noted is that non-commit inputs will now be silently ignored rather than triggering an error, which the author acknowledges as a trade-off for the performance gain.

This appears to be a well-considered optimization that fits naturally with the series' focus on making `git-blame-tree` practical for large repositories. The implementation looks clean and maintains the command's core functionality while trimming unnecessary overhead.
