Feature addition to the Git send-email OAuth2/Outlook compatibility series. This final patch in the v3 series introduces a new `--smtp-passeval` option that allows dynamically generating OAuth2 tokens or passwords via external scripts, specifically targeting Outlook's OAuth2 requirements. The implementation adds ~23 lines across documentation and code, with the key addition being a new `$smtp_authpasseval` variable and corresponding logic in `smtp_auth_maybe()` to execute the user-specified command and capture its output as the authentication token.

The patch enables configurations where tokens must be freshly generated (like Outlook's OAuth2 refresh tokens) by supporting command execution similar to msmtp's `passwordeval`. The example shows integration with a Python script (`refresh_token.py`) that presumably handles the OAuth2 token refresh flow. Error handling ensures failed executions are fatal, and debug output shows the command being run. The documentation clearly notes this overrides any static password configuration.

This completes the series' goal of full Outlook SMTP compatibility by addressing the token generation side of OAuth2 authentication, complementing the earlier XOAUTH2/OAUTHBEARER protocol support and Outlook Message-ID handling. The implementation is narrowly scoped to the credential generation problem while maintaining the series' security focus (TLS remains enforced for bearer auth). The approach mirrors established patterns in other mail clients while integrating cleanly with Git's existing SMTP auth flow.
