This thread began with a performance test failure in p5332-multi-pack-reuse.sh, which was introduced in Git 2.44.0. Jeff King diagnosed and fixed the issue - the test was incorrectly using "+" prefixes for pack names, a remnant from an earlier version of the multi-pack reuse feature that had been removed before merging. Taylor Blau, who originally implemented the feature, reviewed and approved the fix.

The discussion then turned to process improvements. Junio Hamano suggested better change-tracking tools might help catch such oversights, but Jeff King countered that the real issue was insufficient test coverage rather than change tracking. He noted that performance tests like these are rarely run, making them prone to bit rot, though he questioned whether the overhead of CI integration for perf tests would be worthwhile. Both agreed the impact was limited since the bug wasn't affecting production code.

The thread also revealed broader CI infrastructure problems where GitHub Actions containers lack Git installations, causing test failures. While the immediate test script issue is resolved, these CI configuration challenges remain open. The exchange highlights ongoing tensions between thorough testing and practical constraints, particularly for less-frequently-run test suites.
