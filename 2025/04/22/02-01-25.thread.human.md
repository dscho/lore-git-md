This thread addressed a performance test failure in p5332-multi-pack-reuse.sh, which was introduced in commit ba47d88795. The test was failing consistently on macOS and Linux when using --immediate due to incorrect "+" prefixes being added to pack names when feeding them to `git multi-pack-index write --stdin-packs`. Jeff King identified and fixed the issue, tracing it back to leftover syntax from an earlier version of the feature that supported "disjoint" packs (marked with "+"), which had been removed before merging.

Taylor Blau, the original author of the multi-pack reuse feature, has now acknowledged Jeff's fix with an Acked-by tag, confirming that the one-line change to simplify the sed invocation correctly maintains test functionality while removing obsolete syntax. The fix is narrowly scoped to the test script and doesn't affect core multi-pack-index behavior.

While this specific test issue is now resolved, the thread also surfaced broader CI infrastructure problems where GitHub Actions containers lack Git installation, causing additional test failures. Junio Hamano noted this as part of a recurring pattern of missing test dependencies that needs a systematic solution. These CI configuration issues remain open, but the immediate performance test failure has been properly addressed with Taylor's approval of Jeff's fix.
