This thread began with Philippe Blain reporting consistent failures in the performance test p5332-multi-pack-reuse.sh, which tests multi-pack bitmap reuse scenarios. The failures occurred on both macOS and Linux, including in Git 2.44.0 where the test was first introduced. The discussion initially expanded to include CI infrastructure problems that were preventing proper Linux testing on GitHub Actions.

Jeff King has now identified and fixed the root cause: the test was incorrectly prefixing pack names with "+" when feeding them to `git multi-pack-index write --stdin-packs`. This was a leftover from an earlier version of the feature that supported "disjoint" packs (marked with "+"), but the current implementation no longer handles this prefix. King's fix simplifies the test to just strip directory paths from pack filenames, matching what the current code expects. The fix is narrowly targeted to the test script and doesn't require changes to core Git functionality.

With this fix, the test now properly measures the performance tradeoffs between single-pack and multi-pack reuse across different scenarios (1-pack, 10-pack, 100-pack) as originally intended. While the immediate test failure is resolved, the broader CI infrastructure issues around test dependencies that were raised earlier in the thread remain as a separate concern that may need follow-up.
