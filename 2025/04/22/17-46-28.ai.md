This is a performance optimization patch for the new `git-blame-tree` command, part of the RFC series introducing tree-level blame tracking. The patch focuses on streamlining revision walk initialization now that the command no longer relies on `log_tree_commit()`.

The key change is setting `rev.no_walk = 1` before `prepare_revision_walk()`, which avoids unnecessary initialization work since the command handles its own commit traversal logic. This builds on earlier optimizations in the series that removed dependency on the revision walk machinery's full initialization. The patch includes a tradeoff - while it speeds up initialization, it loses the revision machinery's automatic validation of non-commit inputs, which now silently pass through.

Technical details show the command now processes boundary commits directly from `rev.commits` list rather than `rev.pending`, with proper commit parsing. The diff shows careful handling of the Bloom filter integration and path tracking that was added in earlier patches. Taylor Blau is credited for the original approach this builds upon.

This appears to be a well-justified optimization that fits with the series' focus on performance. The loss of input validation is noted in the commit message but doesn't appear critical since the command's own logic likely validates inputs elsewhere. The change maintains all existing functionality while reducing overhead, consistent with the series' goal of making the command practical for large repositories.
