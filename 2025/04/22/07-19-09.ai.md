Feature patch adding OAuth2/SMTP bearer authentication to `git send-email`, specifically targeting Microsoft and Google email services. This is the first of a 2-patch series addressing Microsoft ecosystem email compatibility.

The patch implements direct SMTP AUTH handling for OAUTHBEARER and XOAUTH2 authentication types, bypassing Perl's Authen::SASL module which lacks support for these methods. The implementation includes RFC-compliant string generation for both protocols (RFC5801/RFC7628 for OAUTHBEARER, Google's XOAUTH2 spec) with proper error handling and TLS enforcement. Configuration requires setting `smtpEncryption=tls` and providing the bearer token either via `smtpPass` or through the git-credential-oauth helper (with example configurations shown for both Gmail and Office 365).

Key technical details include new functions `generate_oauthbearer_string()` and `generate_xoauth2_string()` that format the authentication payloads, plus `smtp_bearer_auth()` that handles the SMTP protocol exchange including error cases. The patch modifies both the Perl implementation (64 lines) and documentation (5 lines) to explain the new authentication requirements. Testing was performed by M Hickford using git-credential-oauth, though the commit doesn't detail test coverage for edge cases.

This appears to be a rebased version of prior work, now combined with Aditya Garg's Outlook Message-ID fixes in patch 2/2. The implementation looks thorough with proper RFC citations, but reviewers may want to verify compatibility with various OAuth2 providers beyond the tested Gmail/Office365 cases. The credential helper integration (via git-credential-oauth) remains external to core Git, requiring users to install it separately.
