This is the second patch in a series improving `git send-email` compatibility with Microsoft email services, specifically addressing Outlook's non-standard Message-ID handling.

The patch fixes a threading issue where Outlook discards the original Message-ID header and replaces it with its own proprietary X-Microsoft-Original-Message-ID header plus a randomly generated Message-ID. This breaks email threading when replying to patches. The solution extracts the server-assigned Message-ID from SMTP response strings (which follow the format "2.0.0 OK <Message-ID> [Hostname=...]") and uses that instead of the locally generated one.

The implementation specifically targets Office 365 and Outlook SMTP servers (smtp.office365.com and smtp-mail.outlook.com), adding a new block to parse the server response after sending the email. It includes both success logging and a fallback warning if parsing fails. The change is narrowly scoped to Outlook's behavior while maintaining existing functionality for other email providers.

Key technical details include the regex pattern matching the Message-ID between angle brackets in the SMTP response, and the conditional execution only for Microsoft's known SMTP endpoints. The patch demonstrates practical testing by being sent through the modified send-email itself (as evidenced by the Outlook-originated Message-ID in the email headers).

This complements the series' first patch (OAuth2 authentication) to provide full Outlook compatibility. While focused on Microsoft's ecosystem, the change follows the pattern of previous email provider-specific adjustments in send-email.perl. The warning message suggests the authors considered edge cases where parsing might fail, though the patch doesn't specify recovery behavior beyond the warning.
