This is the second patch in a series improving `git send-email` compatibility with Microsoft email services. It specifically addresses Outlook's non-standard handling of Message-IDs, which was breaking email threading functionality.

The patch modifies the Perl script to extract the correct Message-ID from Outlook's SMTP server response, where it appears in angle brackets after a "2.0.0 OK" status. Outlook replaces user-provided Message-IDs with its own proprietary format, storing the original in an X-Microsoft header. The change only activates for Office365/Outlook SMTP servers and includes both success logging and fallback warnings.

This appears to be a well-scoped fix for a specific interoperability issue, complementing the OAuth2 authentication changes in the first patch of the series. The implementation is straightforward - parsing the server response pattern that Outlook reliably generates. While Outlook-specific, the change is clearly marked and shouldn't affect other email providers. The patch maintains the series' focus on making `send-email` work smoothly with Microsoft's email ecosystem.
