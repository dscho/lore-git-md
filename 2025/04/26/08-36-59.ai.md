This is a feature patch adding configurability to the Outlook Message-ID handling in `git send-email`. Aditya Garg builds on Junio Hamano's earlier proposal for enterprise Outlook deployments by implementing a new `--[no-]smtp-outlook-id-tweak` option and corresponding configuration.

The patch adds a tri-state control for Outlook's Message-ID behavior: automatic detection (current default based on hostname matching `smtp.office365.com` or `smtp-mail.outlook.com`), forced enable, or forced disable. This addresses enterprise cases where Outlook SMTP servers use custom domains while still exhibiting the Message-ID rewriting behavior. The implementation uses a new `$outlook_id_tweak` variable (-1 for auto, 0/1 for forced states) and modifies the `is_outlook()` helper to respect this setting.

Documentation explains the option's purpose and warns about only using the forced mode with Microsoft email providers. The patch maintains backward compatibility while providing explicit control that was discussed earlier in the thread. Aditya confirms successful testing of Junio's prototype and offers to submit it officially, seeking confirmation on sign-off requirements.

This represents the final piece of the Outlook SMTP integration, complementing the already-queued hostname-based solution and the separately released OAuth2 authentication work in perl-authen-sasl. The implementation is clean and focused, adding about 25 lines total (11 code, 15 docs) while preserving all existing behavior when the new option isn't used.
