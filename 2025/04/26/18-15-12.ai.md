This is a bugfix patch for `git send-email` that strengthens validation of Fully Qualified Domain Names (FQDNs) in SMTP connections. The current implementation only checks for the presence of a dot and rejects `.local` domains on macOS, while the new version enforces RFC1035 rules: requiring at least one dot, 1-63 character labels, alphanumeric start/end of labels, and no consecutive dots.

The patch modifies the `valid_fqdn` function in `git-send-email.perl` to use a more comprehensive regex that rejects invalid cases like domains starting/ending with hyphens, labels over 63 chars, and double dots. The author encountered this when their Ubuntu system generated an invalid "MacBook.." domain that passed the old check but failed SMTP handshakes, while the new validation properly catches such cases.

Key technical details for future reference:
- The new regex pattern enforces: `^(?!-)[A-Za-z0-9-]{1,63}(?<!-)(\.[A-Za-z0-9-]{1,63})+$`
- Maintains the existing macOS `.local` exclusion
- Fixes a real-world issue where malformed hostnames caused SMTP failures
- Changes are minimal (3 lines) but significantly improve validation strictness
