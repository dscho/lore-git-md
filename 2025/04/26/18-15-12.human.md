This is a bugfix for `git send-email` that tightens validation of Fully Qualified Domain Names (FQDNs) in SMTP connections. The current implementation only checks for a dot in the domain name (and rejects `.local` domains on macOS), which allowed invalid domains like "MacBook.." to pass through, causing connection failures.

Aditya Garg encountered this when `git send-email` failed on Ubuntu because it was using an invalid domain name. The patch implements stricter validation per RFC1035, ensuring domains:
- Contain at least one dot
- Have labels (between dots) that are 1-63 characters
- Start and end with alphanumeric characters
- Only contain alphanumerics and hyphens

The commit includes clear examples of valid and invalid domains, plus before/after SMTP logs showing the fix working. The change is minimal (3 lines modified) and well-motivated by both standards compliance and real-world breakage. This should prevent similar SMTP connection issues for others while maintaining compatibility with properly formatted domains.
