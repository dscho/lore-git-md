Feature enhancement for `git send-email` with Outlook SMTP servers. This is the final piece of a longer thread addressing Outlook's nonstandard Message-ID handling, now adding explicit configuration options for enterprise deployments.

Aditya Garg and Junio Hamano collaborate on adding a `--[no-]smtp-outlook-id-tweak` option to `git send-email`, allowing users to explicitly control whether to retrieve Message-ID from the SMTP server. This builds on the earlier solution that automatically handled standard Outlook domains (`smtp.office365.com` and `smtp-mail.outlook.com`), now extending it for custom domains and enterprise deployments where the hostname check isn't sufficient.

The patch adds documentation explaining when to use each option: `--smtp-outlook-id-tweak` for Microsoft email providers (including custom domains), `--no-smtp-outlook-id-tweak` to disable the behavior entirely, and the default automatic mode for standard Outlook domains. The implementation maintains backward compatibility while adding the new tri-state configuration (-1 for auto, 0 for off, 1 for on).

This appears to be the final piece of the puzzle after the OAuth2 authentication work was successfully released in Authen-SASL 2.1800. The patch is well-documented and follows the established pattern from earlier iterations, suggesting it's ready for inclusion. Aditya offers to formally submit it with Junio's sign-off if desired.
