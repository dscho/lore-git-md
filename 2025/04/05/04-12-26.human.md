Feature proposal to enhance `git stash list` output with more descriptive metadata.

Yuri proposes making `git stash list` more informative by adding several useful metrics to each WIP stash entry. Currently, the output only shows the commit subject line, which the stash was created, which often doesn't adequately describe the stash contents. The proposal suggests adding: the number of added/removed lines (+/- diff stats), count of affected directories and files, and the age of the stash.

This would transform entries from showing just commit subjects to including concrete metrics about the stash's scope and recency. For example, rather than just "WIP on main: [commit subject]", it would show "+20, -5, 3 dirs, 5 files, 17 days ago". These additions would help users better understand what's in their stashes at a glance.

The change seems well-motivated - commit subjects alone are often too vague to remember what work was stashed, especially for older entries. The proposed metrics would provide objective data about the stash's size and age. No implementation is provided in this initial proposal, but the concept appears straightforward and potentially quite useful for anyone who uses `git stash` regularly.

This seems like a thoughtful quality-of-life improvement that could make stash management more intuitive. The proposal is clear and focused, though it might benefit from discussing how this affects performance (if at all) when listing many stashes.
