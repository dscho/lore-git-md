This is a feature inquiry about remote repository synchronization without full clones. Klaus Frank is looking for ways to keep multiple Git remotes (GitHub, GitLab instances) in sync without having to a local checkout first, particularly for CI environments where disk space is limited.

The email describes two current approaches that are unsatisfactory: (1) a full mirror clone and push, which wastes bandwidth and server resources, and (2) a more complex fetch-and-hack-refs approach that is fragile and still consumes too much disk space. Neither handles cases where changes might come from any remote, not just a designated source.

Klaus asks if Git has advanced capabilities (like alternate object databases) that could enable "impersonation" of remotes—where Git would treat a remote's objects as local without downloading them all upfront, only fetching what's needed for push operations. The email is exploratory, seeking solutions from others who might have tackled similar multi-remote sync challenges. The problem space touches on CI constraints, LFS handling, and the growing complexity of decentralized hosting (GitHub migrations, corporate forks). No patch is proposed; this is purely a discussion starter.
