This thread explores the challenges of maintaining consistent Git repositories across multiple remotes (like GitHub, GitLab, and internal servers), particularly for CI environments that lack persistent local storage. The discussion has crystallized around two main approaches: automated remote-to-remote synchronization versus using a local repository as the single source of truth.

D. Ben Knoble and Klaus Frank have been key participants, with Knoble advocating for the local-source model while Frank raises concerns about its fragility when the local machine fails. In the latest exchange, Knoble suggests that disciplined pushing to all remotes from the local source could mitigate backup concerns, though this still doesn't address stateless CI environments. Frank has proposed SSH-based workflows as an alternative to complex multi-remote setups.

The core tension remains unresolved: remote-to-remote sync handles CI needs but is complex to implement, while local-source approaches are simpler but require persistent state and don't solve the stateless CI case. Technical hurdles around force-push handling, branch authority rules, and object transfer efficiency remain open questions. The discussion has broadened to consider SSH workflows and static site generation, though these don't directly address the original CI use case that sparked the thread.
