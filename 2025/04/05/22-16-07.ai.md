This is the first patch in a major refactoring series to remove the legacy merge-recursive implementation in favor of merge-ort. The patch converts checkout.c to use the merge-ort equivalent of merge_trees() as part of systematically transitioning all callers before removing merge-recursive entirely.

The change is mechanical - it simply replaces calls to merge_trees() from merge-recursive with merge_ort_nonrecursive() from merge-ort-wrappers, updating the include statement accordingly. The parameters and calling convention remain identical, just routed through the new backend. This is a straightforward substitution with no behavior changes, as merge-ort has been designed to be a drop-in replacement.

The patch affects the checkout command's working tree merging logic, specifically the merge_working_tree() function that handles the case where a branch switch requires merging local changes. The change is part of the final phase of a multi-year effort to replace merge-recursive, with merge-ort having been the default backend since Git 2.33.0.

This initial patch demonstrates the series' approach - methodically updating each caller before removing the old implementation. The v2 iteration indicates the technical content is stable, with only minor documentation fixes from v1. The change appears well-contained and low-risk, touching only the checkout command's merge integration while maintaining identical behavior through the new backend.
