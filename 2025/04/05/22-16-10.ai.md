This is patch 4/8 in Elijah Newren's series to fully remove the merge-recursive backend in favor of merge-ort. The patch focuses on converting the sequencer's non-recursive merge operations to exclusively use merge-ort.

The change removes the conditional logic in `do_recursive_merge()` that previously allowed selecting between merge-recursive and merge-ort backends. Despite the function's misleading name (it actually performs non-recursive merges), it had maintained this dual-backend support even though merge-ort has been the default for years. The patch simplifies the code by eliminating the merge-recursive path entirely, leaving only the merge-ort implementation.

Key technical details:
- Removes 22 lines of conditional backend selection code while keeping 13 lines of merge-ort-specific logic
- Maintains the same merge result handling and output behavior
- Preserves an existing TODO comment about potential optimizations for working tree updates
- Affects sequencer operations during rebase and cherry-pick that use non-recursive merges

The change is straightforward since merge-ort has been the default backend for this operation already, making this a mechanical cleanup rather than a functional change. This patch continues the systematic elimination of merge-recursive references throughout the codebase as part of the final removal effort.
