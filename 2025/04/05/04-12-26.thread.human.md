This thread discusses a proposal to enhance `git stash list` output with additional metadata like line changes, affected files, and stash age. The original suggestion was to modify stash.c to display this information by default in a format like `stash@{N}: WIP on branch: [subject] (+X, -Y, D dirs, F files, T ago)`.

Lucas Seiki Oshiro first responded by pointing out that existing `git log --stat` and `--pretty=reference` flags can provide similar information without code changes. Now, maintainer Junio Hamano has weighed in, agreeing with this perspective. He emphasized that stash messages are meant to be lightweight memory aids rather than comprehensive reports, since stashes often contain unrelated work while related changes typically get committed directly.

The discussion now leans toward documenting the existing log formatting options rather than implementing new functionality. Junio's response suggests a philosophical stance favoring composability (using existing flags) over specialized stash formatting, noting that stashes' transient nature justifies keeping the default output minimal. While no final decision has been made, the thread appears to be moving toward a resolution that would involve improved documentation of current capabilities rather than code changes.
