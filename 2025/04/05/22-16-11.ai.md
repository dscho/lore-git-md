This is patch 5/8 in Elijah Newren's series to completely remove the merge-recursive backend in favor of merge-ort, representing a major milestone in the multi-year merge-ort migration effort.

The patch focuses on converting the remaining recursive merge calls in builtin/merge.c and sequencer.c from merge_recursive() to merge_ort_recursive(). The changes are straightforward mechanical replacements, removing conditional logic that previously selected between the two backends. The sequencer.c changes preserve an existing TODO comment about potential optimizations for working tree updates.

A test modification removes the GIT_TEST_MERGE_ALGORITHM=recursive setting from t7615, as this test no longer needs to specify the backend now that merge-ort is the only option. The test continues to verify diff algorithm behavior but does so exclusively through merge-ort.

Key technical details:
- Removes final #include "merge-recursive.h" from builtin/merge.c
- Simplifies both merge.c and sequencer.c by eliminating backend selection logic
- Updates sequencer.c comments to reference merge_ort_recursive() instead of merge_recursive()
- Maintains all existing functionality while removing 24 lines of code
- Part of systematic elimination of merge-recursive infrastructure (5000+ lines total being removed)

This patch follows the established pattern in the series, with no functional changes beyond the backend switch. The v2 iteration incorporates minor typo fixes from v1 feedback but makes no technical modifications. The changes are low-risk as merge-ort has been Git's default merge strategy since 2.33.0 and has undergone extensive testing.
