This is the first patch in a major refactoring series to completely remove the legacy merge-recursive implementation in favor of merge-ort. The patch converts one of the final remaining callers of merge-recursive to use merge-ort instead.

The change is mechanical and straightforward: it replaces a call to `merge_trees()` from merge-recursive with the equivalent `merge_ort_nonrecursive()` call in the checkout code path. The patch updates the include statement and swaps the function call while keeping all other parameters identical. This is part of the systematic transition of all callers before the actual deletion of merge-recursive.[ch] in later patches.

The patch appears well-contained and low-risk, with no functional changes intended - it's purely a backend swap. This is a key step in the larger effort to eliminate merge-recursive entirely, which has been the project's goal since merge-ort became the default in Git 2.33.0. The v2 iteration suggests the change has already undergone review with only minor typo fixes needed since the initial submission.
