Feature proposal for `git stash list` output enhancement.

This email proposes making `git stash list` output more informative by adding metadata to WIP stash entries. Currently these entries only show the commit subject line, which often doesn't adequately describe the stash contents. The proposal suggests adding: line changes (+/- counts), affected directories/files counts, and stash age.

The suggested new format would look like: `stash@{10}: WIP on main: [commit-subject] (+20, -5, 3 dirs, 5 files, 17 days ago)`. This would help users better understand what's in each stash without having to inspect them individually.

The change would affect the stash.c implementation where the list formatting occurs. Key metrics to expose would be the diff statistics (already available via diff machinery) and stash creation time (already stored in the reflog). The proposal doesn't include implementation details but focuses on the user-facing benefit.

This appears to be a well-motivated quality-of-life improvement that could help users manage their stashes more effectively. The change seems non-controversial but would need discussion around: exact format choices, performance impact of gathering additional data during listing, and whether to make this behavior configurable.
