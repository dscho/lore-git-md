This is a cover letter for a two-patch series addressing shell path detection in Meson builds, continuing the thread about cross-compilation reliability issues. The series has been refined through multiple rounds of feedback and now appears complete.

The core issue stems from Meson builds looking up the shell via PATH, which can differ between build and target hosts, causing failures at GitLab and Debian. The solution hardcodes `/bin/sh` preference while maintaining override capability via `program_path`, matching Makefile's `SHELL_PATH` behavior through Meson-native mechanisms.

Key technical points in this version:
- Simplified diagnostic output format for detected runtime paths (Perl/Python/shell)
- Added explicit comment explaining the `/bin/sh` path priority rationale
- Maintains backward compatibility via `program_path` configuration
- Resolves original cross-build discrepancies while preserving POSIX compliance
