This is a v2 cover letter for a 13-patch refactoring series in the ongoing object-file-cleanup effort, preparing for `the_repository` removal. The series modernizes object storage code through API cleanup and removal of unnecessary indirection layers.

The key technical focus is replacing `repo_has_object_file()` and its `_with_flags()` variant with `has_object()`, which provides more explicit control over promisor object fetching and packfile reloading. The series systematically converts callers across multiple subsystems (refs, index-pack, show-ref, http-walker, etc.) to use the new API while maintaining existing behavior where needed.

Changes in v2 are minor commit message improvements, with the technical approach remaining consistent from v1. The series has already received positive review for patches 3-9 from Karthik Nayak, with all minor nits addressed. The remaining patches (10-13) handle edge cases in HTTP transport, list-objects filtering, and bulk-checkin operations.

Notable technical details include:
- Introduces `HAS_OBJECT_FETCH_PROMISOR` flag (bit 1) for explicit promisor control
- Maintains `HAS_OBJECT_RECHECK_PACKED` capability (bit 0) for packfile checking
- Improves index-pack collision checks by avoiding unnecessary promisor fetches
- Updates ref subsystem to explicitly exclude promisor fetching in `ref_resolves_to_object()`
- Reduces object-store.h by 31 lines through proper header reorganization
- Affects multiple subsystems: refs, packfile operations, HTTP transport, list-objects filtering

The series builds on previous object-file-cleanup work and connects to broader efforts around ODB abstraction and `the_repository` removal. It touches core functionality while maintaining backward compatibility, with particular attention to partial clone workflows.
