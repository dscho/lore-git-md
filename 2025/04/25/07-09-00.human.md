This is patch 9/13 in Patrick Steinhardt's refactoring series cleaning up the object store subsystem, part of the ongoing `the_repository` removal effort. The patch modifies `ref_resolves_to_object()` to prevent promisor object fetches during reference validation, similar to changes made in previous patches.

The change replaces `repo_has_object_file()` with the new `has_object()` API, explicitly using only the `HAS_OBJECT_RECHECK_PACKED` flag. This ensures broken references (those pointing to missing objects) are properly reported as invalid without attempting to fetch them from promisor remotes. The rationale is straightforward - a reference pointing to a non-existent object is inherently broken, so fetching shouldn't be attempted.

This continues the series' pattern of making object existence checks more precise by controlling promisor fetching behavior. The change is minimal (just a 1-line modification) but aligns with the broader goal of cleaning up object storage APIs. The patch follows the same approach as earlier approved changes in the series, maintaining consistency in how object existence checks are handled across the codebase.

The series has been reviewed up to this point by Karthik Nayak with positive feedback, and this patch appears to follow the same well-reasoned approach as previous ones in the sequence. It's part of the systematic conversion of object existence checks to use the new flag-based API.
