Refactoring patch in the maintenance task decomposition series. This is patch 3/7 in Derrick Stolee's effort to extract all `git gc` functionality into standalone maintenance tasks, specifically targeting worktree pruning.

The patch moves the worktree pruning logic from `cmd_gc()` into a new `maintenance_task_worktree_prune()` function. The new function maintains identical behavior, executing `git worktree prune --expire` with the configured expiration time, but now in a form that can be called independently by the maintenance command. The change is purely structural - no behavior modifications or new functionality is introduced here.

Key technical details:
- New function `maintenance_task_worktree_prune()` in builtin/gc.c
- Takes same parameters as other maintenance task functions (`opts` and `cfg`)
- Uses same child_process setup as original code
- Preserves error handling via `die()` on failure
- Part of preparing for new "worktree-prune" maintenance task in subsequent patch

This continues the pattern seen in earlier patches of the series where gc functionality is extracted into standalone, reusable components. The patch appears straightforward and well-contained, with no obvious issues in the conversion.
