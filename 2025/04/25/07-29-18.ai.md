This is a refactoring patch in Derrick Stolee's series to decompose `git gc` functionality into granular maintenance tasks. The patch comes from Patrick Steinhardt and focuses on code hygiene in builtin/gc.c rather than the main maintenance task decomposition effort.

The patch removes several global variables (`prune`, `prune_worktrees`, `rerere`) that were used to assemble command-line arguments for subprocesses in `git gc`. These variables were only used in single locations, so the patch inlines their initialization directly into the child process setup code where they're needed. The `repack` global variable is kept since it's used in multiple places.

The changes are mechanical and straightforward - each removed global is replaced with direct `strvec_pushl()` calls when setting up the corresponding child process. The patch maintains all existing functionality while reducing the visibility of these temporary argument arrays. This appears to be a clean improvement that makes the code's data flow more obvious by keeping related operations together.

This is a minor cleanup that happens to be included in Stolee's series but isn't directly related to the maintenance task decomposition work. The changes touch the same gc.c file but focus on internal implementation details rather than the higher-level goal of extracting worktree pruning and rerere garbage collection as standalone tasks.
