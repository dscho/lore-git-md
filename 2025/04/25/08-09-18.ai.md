This is a follow-up discussion in the Meson benchmark integration thread, focusing on documentation clarity around parallel execution behavior.

Christian Couder raises a concern about potential ambiguity in the meson.build comments regarding parallel execution applies to tests but not benchmarks. The current wording could be misinterpreted to suggest benchmarks also run in parallel by default, despite the commit message explicitly stating they do not. Patrick Steinhardt defends the current phrasing as sufficiently clear due to the distinction between "test" and "benchmark" terminology, but remains open to alternative wording suggestions. Christian proposes a more explicit formulation that directly contrasts test execution (parallel) with benchmark execution (serial).

The exchange highlights one of the final documentation polish items for this otherwise complete feature implementation. The technical implementation itself is not in question - the thread summary confirms benchmarks are correctly wired with non-parallel execution via Meson's benchmark() function. This is purely about ensuring the user-facing documentation accurately reflects the behavior. The proposed clarification would make the distinction more immediately obvious to readers scanning the meson.build comments.
