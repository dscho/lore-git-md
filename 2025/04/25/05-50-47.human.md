Bug report about Windows case-sensitivity and branch switching issues. Justin Golden reports a series of confusing behaviors when dealing with file casing changes (Button vs button) on Windows, where Git shows inconsistent file states and prevents branch switching despite a clean status. The issue appears to stem from Windows' case-insensitive filesystem interacting with Git's case-sensitive tracking, compounded by the `core.ignorecase` setting being toggled during troubleshooting.

Key symptoms include:
- Git showing phantom changes and incorrect file states
- Inability to switch branches due to "untracked" files that shouldn't exist
- The `git clean -fdx` command unexpectedly deleting `node_modules` contents
- Only resolved by manually deleting the problematic file in Windows Explorer

The report includes detailed reproduction steps and command outputs showing the inconsistent behavior. While some aspects may be expected Windows+Git interactions, the inability to switch branches with a clean status and the phantom file changes suggest there may be a genuine bug in how Git handles these edge conditions on Windows. The reporter is using Git 2.36.1 on Windows 10.
