Eli Schwartz responds to Junio's concern about users potentially wanting different shells for interactive vs scripted use. He argues that users who set `/bin/sh` to bash are already comfortable with it being used everywhere, and that Git's scripts work fine with bash. He also notes that users running bash interactively would explicitly invoke `bash` rather than `sh`.

The email then addresses the feature parity question by demonstrating that Meson already supports shell path overriding through its native configuration system (`paths.ini`), showing how to explicitly set the shell to bash while maintaining the same diagnostic output format. While acknowledging that a dedicated build option might be more discoverable, Schwartz confirms the current system provides the necessary flexibility.
