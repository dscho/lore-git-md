This thread discusses a performance optimization for Git's xdiff algorithm, specifically using the `--minimal` flag. The patch modifies the `cleanup_records` heuristic to skip marking lines as changed when they're surrounded by many changed lines, but only when `--minimal` is explicitly requested. The change addresses a case where the current heuristic can produce longer-than-necessary diffs in about 1.3% of cases when minimal diffs are specifically asked for.

The patch is well-constructed with clear technical changes: it adds a new `need_min` parameter to control the behavior, modifies the cleanup logic accordingly, and includes a new test script (`t4071-diff-minimal.sh`) that verifies the specific case of unchanged lines surrounded by changes. The commit message clearly explains the tradeoff being made and provides measured impact data.

While diff quality can sometimes be subjective, the change is narrowly scoped to only affect `--minimal` mode where users are already explicitly asking for the shortest possible output. The patch appears ready for consideration, though there may be discussion about whether the 1.3% improvement justifies the change or if there are edge cases where the new behavior might produce less intuitive diffs.
