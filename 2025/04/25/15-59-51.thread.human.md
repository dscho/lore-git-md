This thread discusses a performance optimization for Git's `--minimal` diff mode, which aims to produce the shortest possible diff output. Niels Glodny proposed modifying xdiff's internal `cleanup_records` heuristic to skip marking lines as changed when they're surrounded by many changes, but only when `--minimal` is explicitly requested. The change affects about 1.3% of diffs in Git's history where the heuristic previously produced longer-than-necessary output.

Phillip Wood reviewed the initial version, agreeing with the optimization goal but suggesting implementation improvements: using existing test helpers for robustness and deriving the minimal flag from existing context rather than passing it through functions. The v2 patch incorporates these suggestions while keeping the core optimization intact. The test case verifies that unchanged lines surrounded by changes don't appear in minimal diffs.

The discussion has focused on implementation refinements rather than fundamental approach, with consensus that `--minimal` should produce truly minimal diffs when explicitly requested, even if that comes at some readability cost. The patch remains narrowly scoped to only affect `--minimal` output where shortest-possible diffs are the expected behavior. While no specific performance measurements have been shared, the change appears clean and ready for consideration.
