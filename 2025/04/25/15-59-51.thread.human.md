This thread discusses a performance optimization for Git's `--minimal` diff mode, which aims to produce the shortest possible diff output. The original patch from Niels Glodny modified xdiff's heuristic to skip marking lines as changed when they're surrounded by many changes, but only when `--minimal` is explicitly requested. This affects about 1.3% of diffs where the previous heuristic produced unnecessarily long output.

Phillip Wood has now weighed in, agreeing with the fundamental premise that `--minimal` should prioritize minimal output size over readability. He suggests several code improvements to make the patch more robust and maintainable, including using existing test helpers and deriving the `need_min` parameter from existing flags rather than passing it through multiple functions. The technical approach of forcing certain line markings when minimal diffs are requested remains uncontested.

The discussion remains focused on implementation details, with no objections to the optimization's goal. The changes are narrowly scoped to only affect `--minimal` output where users already expect the shortest possible diffs. While no performance impact numbers have been shared yet, the optimization appears sound and likely to be accepted with Phillip's suggested improvements.
