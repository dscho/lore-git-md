This thread discusses a performance optimization for Git's `--minimal` diff mode, which produces the smallest possible diffs by avoiding unnecessary line changes. Niels Glodny proposed modifying xdiff's `cleanup_records` heuristic to skip marking lines as changed when they're surrounded by many changes, but only when `--minimal` is explicitly requested.

The patch has gone through three iterations, with Phillip Wood and Junio C Hamano providing key feedback. The current version cleanly implements the optimization by checking the `XDF_NEED_MINIMAL` flag and adjusting the marking logic accordingly. Benchmarking shows the change reduces diff sizes by 1.3% in Git's history with no measurable performance impact (about 2.36s for large diffs either way).

A new test script (`t4071-diff-minimal.sh`) verifies the behavior using Git's test helpers. The thread has reached technical consensus, with all reviewers satisfied after seeing the benchmark results and implementation refinements. The patch now only needs final commit message polishing before likely being merged by Junio.
