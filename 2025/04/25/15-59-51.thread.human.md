This thread discusses a performance optimization for Git's `--minimal` diff mode, which affects how xdiff library marks changed lines when producing minimal diffs. The patch from Niels Glodny modifies the `cleanup_records` heuristic to skip marking certain lines as changed when they're surrounded by many changes, but only when `--minimal` is explicitly requested. The change reduces diff size in about 1.3% of cases while benchmark tests confirm there's no measurable runtime impact.

The technical implementation derives a `need_min` flag from `cf->flags` and modifies the marking logic accordingly, with test coverage added in a new `t4071-diff-minimal.sh` script. Phillip Wood initially suggested the implementation approach in v1 and has now given his approval to the refined version, while Junio Hamano confirmed the performance measurements and recommended including them in the commit message. The discussion has reached clear consensus that this optimization properly implements the goal of producing truly minimal diffs when explicitly requested via `--minimal`, with all technical concerns addressed. The patch remains narrowly focused on this specific case where shortest-possible diffs are the expected behavior.
