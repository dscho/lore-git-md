This is a follow-up in the Meson build system thread, specifically about simplifying the executable path reporting output.

Patrick Steinhardt acknowledges Eli Schwartz's suggestion to streamline the diagnostic output in meson.build by removing redundant ternary checks for Perl and Python paths. The original patch had explicit checks for `target_perl.found()` and `target_python.found()`, but Eli pointed out that Meson's built-in summary display already handles this more elegantly by showing "NO" in red for missing dependencies. 

The change is purely cosmetic and doesn't affect functionality, but makes the build output more consistent with Meson's conventions. This addresses one of the open questions from the thread about output simplification. The core issue of reliable shell path detection in cross-build scenarios remains unchanged by this refinement.

Key technical detail preserved is that `target_shell` (the focus of the original reliability fixes) still shows its full path unconditionally, as the earlier patches ensured it would always be found via the `/bin/sh` fallback. The thread continues to show collaborative refinement of the solution with input from multiple contributors.
