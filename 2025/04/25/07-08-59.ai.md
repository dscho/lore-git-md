This is patch 8/13 in Patrick Steinhardt's series refactoring the object store subsystem, continuing the work to replace `repo_has_object_file()` with the new `has_object()` API. The patch modifies `builtin/show-ref.c` to prevent unnecessary promisor object fetches during reference validation.

The change replaces `repo_has_object_file()` with `has_object()` in `show_one()`, explicitly using only the `HAS_OBJECT_RECHECK_PACKED` flag (bit 0) to maintain the existing behavior of checking packed objects while avoiding promisor fetches (bit 1). The rationale is that reference validation shouldn't trigger background fetches since references should never point to missing objects in the first place.

The implementation is straightforward - a one-line change that maintains the same error handling behavior when objects are missing, just without the promisor fetch side effect. This aligns with the series' goal of making object existence checks more explicit about when they should fetch from promisors. The patch follows the pattern established in earlier patches of the series for similar conversions.

This continues the systematic conversion of object existence checks across the codebase, with `show-ref` being another case where promisor fetching is undesirable. The change is consistent with the series' architectural direction and doesn't appear to introduce any new edge cases.
