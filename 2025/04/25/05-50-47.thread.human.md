This thread reports a persistent Windows-specific case-sensitivity issue where Git gets stuck in an inconsistent state with files like `Tabs.svelte`/`tabs.svelte`. Despite Git reporting a clean working tree, branch switching is blocked by phantom untracked files - a catch-22 situation where the system appears broken. The reporter has exhaustively tried standard fixes (`git checkout -- .`, `git rm --cached`, `git clean -fdx`, index resets) and even system restarts without success. The only workaround found is manually deleting the problematic files via Windows Explorer, which suggests deeper filesystem interaction issues. The problem occurs when switching between branches (like `design-system` to `dev`) and persists across Git operations, indicating this isn't just a transient glitch but a genuine edge case in Git's Windows case-sensitivity handling (`core.ignorecase`). The reporter is using Git 2.36.1.windows.1 and has provided detailed reproduction steps, though a minimal test case would help Windows maintainers like Johannes Schindelin or Johannes Sixt investigate further. This appears to be a real bug where Git's working tree and index tracking get out of sync with the Windows filesystem's case behavior.
