This is patch 9/13 in Patrick Steinhardt's refactoring series cleaning up the object store subsystem, part of the `the_repository` removal effort. The patch modifies reference validation behavior to prevent promisor object fetches.

The change replaces `repo_has_object_file()` with the new `has_object()` API in `ref_resolves_to_object()`, specifically using only the `HAS_OBJECT_RECHECK_PACKED` flag (bit 0) while omitting `HAS_OBJECT_FETCH_PROMISOR` (bit 1). This maintains the packed object recheck behavior while explicitly preventing promisor fetches during reference validation.

The rationale follows the same principle established in earlier patches (particularly patch 8 for `show-ref`): reference validation should not trigger object fetches because a reference pointing to a missing object is fundamentally broken. The error handling remains identical - it will report invalid objects with the same error message.

This continues the series' systematic conversion of object existence checks to the new flag-based API while maintaining consistent behavior across the codebase. The change is minimal (1-line modification) and focused, building on the infrastructure introduced in earlier patches. The thread context shows this approach has already been reviewed and approved by Karthik Nayak for similar changes in other subsystems.
