This is a follow-up discussion in the `git send-email` Outlook Message-ID handling thread, now focusing on the distribution timeline for the newly released Authen-SASL 2.1800 module.

Junio Hamano acknowledges the official CPAN release of Authen-SASL 2.1800 (which includes the OAuth2/XOAUTHBEARER support that was a prerequisite for the Outlook SMTP work) but raises a practical concern about distribution lag. He specifically asks about when major Linux distributions might package this updated version, as Git's email infrastructure needs to account for users who rely on system packages rather than direct CPAN installations.

The question reflects a common deployment consideration in open source - the gap between upstream releases and distribution packaging. This is particularly relevant here since the OAuth2 authentication support was split out to Authen-SASL as an architectural decision, making the module's availability a dependency for the full solution. The thread had previously established that the Message-ID handling in Git itself is now finalized (v6 patch), but authentication remains dependent on this external component.

No specific timeline is provided in this email - it's posed as an open question to Erik Huelsmann and the broader community about when distros might pick up Authen-SASL 2.1800. This information would help set expectations for when the complete Outlook SMTP solution (Message-ID handling + OAuth2 auth) will be broadly available to users across different environments.
