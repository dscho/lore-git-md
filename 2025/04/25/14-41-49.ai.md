This is a CI/build system discussion about refining warning visibility in Git's CI scripts for optional dependency downloads.

Junio Hamano responds to Johannes Schindelin's suggestion about making CI warnings more prominent with platform-specific markers like GitHub's `::warning::` syntax. While acknowledging the potential value of such markers, Junio argues they should be placed differently in the script - specifically at the final check for missing dependencies rather than during the initial download failure handling.

The key technical point is about maintaining the current error handling flow where failed downloads (via wget) are silently cleaned up, with warnings only appearing later when the script explicitly checks for missing dependencies. This preserves the existing behavior where the script continues running despite optional download failures, while still eventually notifying users about missing components.

Junio notes the current implementation already has logic to warn about missing JGit at script end, and that adding warnings during download failures could create misleading messages if the cleanup occurs. The discussion remains focused on CI output presentation rather than the core download handling logic that was previously settled.

This continues the thread's progression from basic error handling implementation to finer-grained presentation details, with maintainers now discussing where and how to surface non-fatal warnings most effectively in CI environments.
