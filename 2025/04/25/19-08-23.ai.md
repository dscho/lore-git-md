This is a follow-up discussion in the `git send-email` Outlook Message-ID handling thread, focusing on distribution timelines for the newly released Authen-SASL 2.1800 with OAuth2 support.

The email exchange clarifies that while the OAuth2 authentication work is now officially released in Authen-SASL 2.1800 (commit 958a3aa), distribution to major Linux packages like Debian may take approximately 2 years. Erik Huelsmann suggests runtime probing of OAuth2 support via Perl's `eval`/`require` mechanism as an interim solution, since the API remains compatible between versions 2.1700 and 2.1800.

Aditya Garg notes that even if Git's `send-email` script were updated to support for the new features, slow-moving distributions would delay availability regardless. The discussion highlights the practical deployment timeline challenges despite the technical solution being complete and released upstream.

Key technical details mentioned include the probing mechanism (`eval { require Authen::SASL::Perl::XOAUTH2; 1 }`) and the unchanged API between Authen-SASL versions, allowing for graceful degradation. The thread continues to maintain clean separation between the Outlook Message-ID threading solution (handled in Git) and authentication concerns (handled in perl-authen-sasl).
