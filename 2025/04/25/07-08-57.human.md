This is patch 6/13 in Patrick Steinhardt's refactoring series to clean up the object store subsystem, part of the larger `the_repository` removal effort. The patch systematically converts calls to the deprecated `repo_has_object_file()` and its variants to use the new `has_object()` API instead.

The conversion maintains existing behavior but makes the promisor object fetching and packfile reloading controls more explicit through flag parameters. The patch shows the direct mapping between old and new calls - for example, the common `repo_has_object_file()` becomes `has_object()` with both `HAS_OBJECT_RECHECK_PACKED` and `HAS_OBJECT_FETCH_PROMISOR` flags set. The changes touch 17 files across various subsystems including fetch, push, shallow handling, and object storage.

The author notes that while this initial conversion preserves current behavior by keeping promisor fetching enabled where it was before, some of these cases may not actually need promisor fetching. Those will be addressed in subsequent patches. This appears to be a straightforward mechanical conversion that builds on the API groundwork laid in earlier patches, with careful attention to maintaining existing functionality while moving to the new interface.
