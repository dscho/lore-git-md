This is a follow-up in the Git for Windows HTTP/2 support thread, where the original reporter Lars Eriksen is closing out their inquiry. The email represents a resolution to one aspect of the broader discussion about bundled tools in Git for Windows.

Lars reports they've found a workaround for their corporate environment by having their server team install a separately built curl executable, acknowledging that the curl bundled with Git for Windows is primarily intended for Git's internal use. This addresses their immediate need for HTTP/2 support in scripts, though it required organizational intervention to implement.

The email thread shows the maintainer Johannes Schindelin's position remains unchanged - that Git for Windows bundles tools only as dependencies for Git's operation, not as general-purpose utilities. The suggested alternatives (system curl or MSYS2) remain the official recommendations for users needing full curl functionality.

Key technical points from this exchange:
- The reporter confirms their issue was specifically with the standalone curl.exe's HTTP/2 support, not Git's internal HTTP operations
- Their corporate environment constraints required an approved installation path rather than using system tools
- The workaround demonstrates that some organizations can accommodate the regression through internal processes

This appears to conclude Lars' participation in the thread, having found a solution that works within their constraints while accepting the maintainer's position on the scope of bundled tools. The underlying philosophical disagreement about responsibility for bundled utilities' functionality remains unresolved, but this particular case has reached a practical resolution.
