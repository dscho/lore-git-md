Performance optimization for bundle-uri reference handling. This is the first of two patches in v4 of a series that improves how Git handles references when downloading bundles.

The patch expands bundle-uri's reference handling from just `refs/heads/` to all `refs/` namespaces while preserving hierarchy (e.g., `refs/tags/` becomes `refs/bundles/tags/`). The core change is a one-line modification in `bundle-uri.c` to remove the `heads/` restriction from the `skip_prefix` check. The bulk of the patch updates the extensive test suite (172 line changes in `t/t5558-clone-bundle-uri.sh`) to account for the new reference hierarchy.

The motivation is to make subsequent fetch operations more efficient by including more references in the negotiation phase. The commit message notes this provides significant improvements, though specific numbers from earlier versions (32% to 1% object downloads) aren't repeated here. The test changes are comprehensive, covering path-based and HTTP bundles, various failure modes, and non-default hash algorithms.

This iteration appears technically sound, with all reviewer feedback from earlier versions incorporated. The only outstanding item from the thread is documentation updates, which will presumably be addressed separately. The changes are focused and well-tested, making this a solid step toward merging the bundle-uri improvements.
