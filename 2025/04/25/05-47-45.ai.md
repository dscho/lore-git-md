This is the second patch in a two-part series improving shell path detection in Meson builds, specifically addressing cross-compilation reliability issues. The patch modifies the shell detection logic to prefer `/bin/sh` (the POSIX-specified location) over PATH lookups, while still allowing user overrides via `program_path`.

The technical change appends `/bin` to the search path rather than prepending it, ensuring user-configured paths in `-Dsane_tool_path=` take precedence. The commit explains this maintains compatibility while solving the original problem where build/target host PATH discrepancies could lead to broken installations. The implementation matches the Makefile's `SHELL_PATH` behavior but through Meson-native mechanisms.

Key details include:
- The search order is now explicitly documented in the code
- The change affects only the runtime shell detection (via `target_shell`) while leaving build-time detection unchanged
- Maintains backward compatibility with existing configuration options
- Follows POSIX standards for shell location

This patch concludes the series after incorporating all feedback from previous rounds, including diagnostic output improvements and clearer documentation of path search priorities. The solution has achieved consensus with no remaining open questions.
