Feature patch completing the `git gc` decomposition effort by adding rerere garbage collection to `git maintenance`.

This is the final patch in a series by Patrick Steinhardt and Derrick Stolee that implements the last two standalone maintenance tasks needed to fully replace `git gc` functionality. While the actual deprecation of `git gc` isn't part of this series, this patch adds the "rerere-gc" task to handle garbage collection of the rerere cache, matching the behavior previously done by `git gc`.

The implementation includes:
- New `maintenance_task_rerere_gc()` function that runs `git rerere gc` as a child process
- A `rerere_gc_condition()` helper that checks if garbage collection is needed by looking for entries in the rr-cache directory
- Documentation updates and tests verifying both manual and auto-triggered behavior

The patch follows the same pattern as the earlier worktree-prune task in the series, completing the decomposition of `git gc` into granular maintenance tasks. The code is cleanly integrated with the existing maintenance framework and includes proper error handling. With both worktree pruning and rerere GC now implemented as standalone tasks, this series provides all the technical pieces needed for a future transition away from `git gc`.
