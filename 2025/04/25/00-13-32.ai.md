This is a build system patch addressing platform compatibility, specifically for Solaris systems where `sys/sysinfo.h` differs significantly from Linux's implementation. It's part of a completed 6-patch series focused on Windows-specific handling in the Meson build system.

The patch changes how Git verifies `sysinfo` availability by checking for the specific struct member (`totalram`) we actually use in `builtins/gc.c`, rather than just checking for header existence. This correctly fails on systems like Solaris where the header exists but provides incompatible functionality. The old approach could incorrectly enable `HAVE_SYSINFO` on platforms where the struct layout differs.

The technical change moves the `sysinfo` check later in `meson.build` and replaces a simple header check with a more precise `has_member` verification of the struct field we need. This maintains the same functionality on Linux while properly handling Solaris and similar platforms where the header exists but isn't compatible. The commit message provides clear rationale about Solaris's different `sysinfo()` implementation and leaves room for future Solaris-specific implementations if needed.
