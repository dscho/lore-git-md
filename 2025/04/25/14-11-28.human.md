This is part of a series improving shell path detection in Meson builds, specifically addressing cross-compilation reliability issues. The patch focuses on making the build system more transparent by reporting detected paths for key executables (Perl, Python, and the system shell) in the Meson summary output.

The change is straightforward - it adds a new section to Meson's build summary that displays the paths found for these runtime dependencies. This helps developers understand which executables are being used, particularly useful when debugging cross-compilation issues where the build and target environments may differ.

The patch is well-contained, touching only the Meson build file to add this diagnostic output. It's the first of two patches in this series, with the second patch (not shown here) modifying the actual shell detection logic. The series has gone through three iterations with all technical feedback addressed, and appears ready for merging.

This is a small but practical improvement to Git's build system that follows Meson conventions while maintaining compatibility with Git's existing behavior. The change is particularly well-motivated by real-world issues encountered at GitLab and Debian with cross-compilation environments.
