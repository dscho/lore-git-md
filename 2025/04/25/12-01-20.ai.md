This is a follow-up discussion in the ongoing CI/build system thread about handling external dependency downloads in Git's CI scripts. Johannes Schindelin responds to Patrick Steinhardt's refinement of Junio Hamano's original patch that made Perforce, Git-LFS, and JGit downloads optional with proper failure handling.

The email focuses on two specific improvements to the approach: First, Johannes agrees with Patrick's suggestion to only handle wget failures (not chmod) since chmod shouldn't fail if wget succeeds. Second, he proposes making the failure warnings more visible in CI output by using platform-specific warning markers (`::warning::` for GitHub Actions).

Johannes also mentions an alternative JGit download URL from the JGit maintainer that could avoid some CI failures, though he notes this is somewhat orthogonal since the patch has already been fast-tracked to master. The discussion remains focused on refining the error handling patterns while maintaining the core approach of optional downloads with proper cleanup.

Key technical details mentioned:
- Suggestion to scope error handling specifically to wget failures
- Proposal to use CI platform-specific warning markers for visibility
- Alternative JGit download URL from Maven repository
- Confirmation that the core patch approach has been accepted

The exchange shows the maintainers collaboratively refining implementation details after agreeing on the fundamental solution, with attention to both technical correctness and developer experience in CI output.
