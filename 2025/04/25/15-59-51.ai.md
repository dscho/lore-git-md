This is a performance and behavior patch for the xdiff diff algorithm, specifically targeting the `--minimal` mode. The patch modifies the `cleanup_records` heuristic in xdiff to skip marking lines as changed when they're surrounded by many changed lines, but only when `--minimal` is specified. The rationale is that while this heuristic is generally a good optimization, it can produce longer-than-necessary diffs in about 1.3% of cases when minimal diffs are explicitly requested.

Key technical changes:
- Adds a new `need_min` parameter to `xdl_cleanup_records()` and `xdl_optimize_ctxs()`
- Modifies the logic in `xdl_cleanup_records()` to skip marking lines as changed when `need_min` is true
- Adds a new test script `t4071-diff-minimal.sh` that verifies unchanged lines surrounded by changes aren't marked in minimal diffs
- The test case specifically checks that unchanged "x" lines don't appear in the diff output when surrounded by changes

The patch appears well-constructed with:
- Clear commit message explaining the tradeoff
- Measured impact (1.3% of diffs affected)
- New test coverage for the specific behavior
- Minimal code changes focused just on the `--minimal` case

This could be slightly controversial since diff quality is somewhat subjective, but the patch is narrowly scoped to only affect explicitly requested minimal diffs where the expectation is already for the shortest possible output.
