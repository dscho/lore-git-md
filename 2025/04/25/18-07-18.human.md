This is a technical clarification in the ongoing Meson build system thread about shell path detection. Eli Schwartz responds to Junio Hamano's question about supporting non-standard shell names by explaining POSIX requirements and real-world shell implementations.

Eli clarifies that while POSIX doesn't specify an absolute path for `sh`, it does require the command name to be "sh" (though implementations may vary underneath). He lists common shell implementations that provide `/bin/sh` symlinks (bash, dash, ksh, etc.) and explains why having a POSIX-compliant `sh` in PATH is fundamental for any Unix-like system.

The response notes that even Solaris, which famously has a non-POSIX `/bin/sh`, provides a compliant version elsewhere in PATH. This addresses Junio's concern about non-standard shell names, confirming that the current Meson implementation (which looks for `sh`) is sufficient since all compliant environments must provide it under that name.

The email reinforces that the patch series' approach is sound, though Eli does acknowledge that if Git wanted to allow experimentation with different shells for internal scripts (which he doubts is useful), that would be a separate consideration. This appears to be the final technical clarification needed in the thread, which has already incorporated all other feedback through three iterations.
