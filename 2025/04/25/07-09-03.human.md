This is patch 12/13 in Patrick Steinhardt's series refactoring the object store subsystem, specifically addressing the bulk-checkin mechanism. The patch prevents promisor object fetches during bulk-checkin operations, continuing the series' theme of making object existence checks more explicit and controlled.

The change modifies `already_written()` in bulk-checkin.c to use the new `has_object()` API with only the `HAS_OBJECT_RECHECK_PACKED` flag, avoiding promisor fetches. The rationale is that when writing objects locally, it's better to use the just-written object rather than fetching from a promisor remote, even if this could theoretically lead to hash collisions. The commit message provides a thorough analysis of why this tradeoff makes sense, noting that other writing paths like `write_loose_object()` don't protect against this scenario either.

This is a logical extension of the series' approach seen in previous patches (8-11), applying the same principle to bulk-checkin operations. The change is small (just 2 lines modified) but meaningful, completing the systematic conversion of object existence checks across Git's codebase. With this patch, the performance impact validation (patch 13) remains as the final step in the series.
