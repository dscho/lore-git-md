This is a follow-up discussion in the ongoing CI/build system thread about making external dependency downloads optional in Git's CI jobs.

Johannes Schindelin responds to Patrick Steinhardt's suggestion about refining the error handling in the CI script. He agrees with Patrick's point that the script should only handle wget failures (not chmod failures) since chmod shouldn't fail if wget succeeds. Johannes also suggests making the warning messages more prominent in CI output by using platform-specific markers like `::warning::` for GitHub.

Additionally, Johannes shares an alternative JGit download link recommended by JGit maintainer Matthias Sohn that might help avoid some of the CI failures. He notes this could provide a temporary workaround while the more comprehensive solution is being refined, though he acknowledges the patch has already been fast-tracked to master.

The discussion continues to focus on practical improvements to the CI system's handling of optional dependencies, with maintainers collaborating to find the right balance between strictness and resilience. The tone remains constructive, building on Junio Hamano's original patch while considering refinements from multiple contributors.
