Bug report clarification about HTTP/2 support in Git for Windows' bundled cURL.

Lars Eriksen follows up to clarify that their issue isn't with Git's HTTP/2 support itself, but rather with the standalone `curl.exe` command bundled with Git for Windows. Their deployment scripts rely on this command (not Git's internal HTTP operations) to POST data, and the recent version no longer supports HTTP/2 as it did in Git for Windows 2.39.0.

This refines the scope of the original bug report - while Johannes Schindelin's workaround of setting `http.sslBackend = openssl` would address HTTP/2 for Git operations, it wouldn't help for standalone cURL usage. The thread now reveals two distinct but related to HTTP/2 support: one for Git's internal operations (already diagnosed) and one for the bundled cURL.exe (newly clarified).

The core issue remains that Git for Windows ships two cURL builds with different capabilities, but the impact now extends beyond Git operations to external scripts using the bundled cURL. This may require a different solution than the configuration workaround proposed earlier. The discussion continues to explore how to restore full HTTP/2 support across all components.
