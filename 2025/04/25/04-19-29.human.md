This is a follow-up discussion on a CI/build system patch series that makes external dependency downloads optional in Git's Linux CI jobs. Patrick Steinhardt responds to Junio Hamano's patch that expanded the approach from just JGit to also handle Perforce and Git-LFS downloads more gracefully.

Patrick agrees with the overall direction but suggests a refinement: the error handling should only catch failures from the `wget` network operations, not subsequent commands like `chmod` that should never fail if the download succeeded. He argues for being "as strict as possible" while still allowing network-related failures.

The exchange shows consensus on the core approach of making downloads optional with proper cleanup, but with Patrick proposing tighter error handling boundaries. This appears to be a minor optimization to Junio's already-accepted solution for CI reliability during external service outages. The thread continues productively with this technical refinement suggestion.
