Refactoring patch in a series to decompose `git gc` functionality into granular maintenance tasks. This is the third patch in a 7-part series by Derrick Stolee (with this specific part authored by Patrick Steinhardt) that aims to make worktree pruning available as a standalone maintenance task.

The patch extracts the worktree pruning logic from `cmd_gc()` into a new `maintenance_task_worktree_prune()` function. This is a straightforward code movement that prepares for the next patch which will expose this as a first-class maintenance task. The behavior remains identical - it still runs `git worktree prune --expire` with the configured expiration time - but now the logic is properly encapsulated.

This continues the project's long-term effort to break up the monolithic `git gc` command into smaller, more focused components that can be run independently via `git maintenance`. The change appears cleanly implemented with no functional changes, just moving code to a more modular structure. The series as a whole is part of making maintenance operations more configurable and composable.
