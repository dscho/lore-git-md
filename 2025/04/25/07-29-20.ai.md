This is a refactoring patch in Derrick Stolee's series to decompose `git gc` functionality into granular maintenance tasks. Patrick Steinhardt contributes a helper function extraction that supports the worktree pruning task implementation.

The patch introduces `get_worktree_names()` in worktree.[ch] to centralize directory scanning for worktree names under ".git/worktrees". This replaces direct directory handling in `prune_worktrees()` with a cleaner interface that populates a strvec`. The function handles edge cases like missing directories gracefully (returning success with empty results) and properly cleans up resources.

Key technical changes:
- New `get_worktree_names()` function in worktree.c with corresponding declaration in worktree.h
- Modified `prune_worktrees()` in builtin/worktree.c to use the new helper
- Maintains same behavior while simplifying the pruning logic
- Proper resource cleanup with `strvec_clear()` and error handling

This appears to be a straightforward quality-of-life improvement that makes the worktree pruning code more maintainable by separating concerns. The change is well-contained and doesn't affect user-facing behavior. It fits naturally into the larger series' goal is to extract gc functionality into standalone maintenance tasks.
