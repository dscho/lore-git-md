This is patch 11/13 in Patrick Steinhardt's series refactoring the object store subsystem, part of the ongoing `the_repository` removal effort. The patch clarifies how promised blobs are excluded when using `--exclude-promisor-objects`.

The patch addresses a potentially confusing implementation detail in `process_blob()` where `repo_has_object_file()` was being used to check for blob existence, which could trigger promisor object fetches. While this wasn't actually broken (because `fetch_if_missing` gets unset in this case), the current implementation is counterintuitive and could mislead future maintainers.

Steinhardt replaces this with the new `has_object()` API (introduced earlier in the series) using only the `HAS_OBJECT_RECHECK_PACKED` flag, which makes the no-fetch behavior explicit. This maintains the same functionality while being more transparent about the intended behavior.

The change is small (just 2 lines modified) but meaningful, continuing the series' theme of making object existence checks more precise and intentional. This follows the pattern established in patches 8-10 of avoiding unnecessary promisor fetches during operations where they shouldn't occur.
