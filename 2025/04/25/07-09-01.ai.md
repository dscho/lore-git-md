This is part 10 of Patrick Steinhardt's ongoing refactoring series to clean up the object store subsystem, specifically addressing HTTP walker behavior. The patch modifies the HTTP transport layer to prevent unnecessary promisor remote fetches during object existence checks.

The HTTP walker currently checks for local object existence using `repo_has_object_file()` before fetching objects via dumb HTTP protocol. This could trigger redundant promisor fetches even when the walker is already about to fetch the object itself. The patch replaces this with the new `has_object()` API using only the `HAS_OBJECT_RECHECK_PACKED` flag, which maintains the same object existence checking behavior but explicitly avoids promisor fetches.

The change affects two locations in `http-walker.c` where object existence is checked during the fetch process. Both checks now use the same conservative flag pattern seen in earlier patches (8/13 and 9/13) for consistency. The modification is straightforward - a simple function call replacement with the appropriate flag parameter - and maintains all existing error handling and state transitions.

This continues the series' principle that operations which are already fetching objects shouldn't trigger additional promisor fetches. The change is particularly relevant for partial clone workflows where HTTP transport is used, though the impact should be minimal since the redundant fetch would have been harmless (just inefficient). The patch follows the same pattern already reviewed and approved in earlier parts of the series.
