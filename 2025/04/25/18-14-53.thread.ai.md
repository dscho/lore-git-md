This thread addresses a bug in `pack-objects` where `should_include_obj()` (line 4310 in `builtin/pack-objects.c`) incorrectly processes non-existent objects during promisor pack operations, triggering a BUG() assertion. Nikolas Garza originally reported the issue occurring after upgrading from Git v2.47 to v2.49, with the root cause traced to commit c08589efdc5 ("index-pack: repack local links into promisor packs") from v2.48.0. Jonathan Tan identified the problematic commit introduced an assumption that `should_include_obj()` would only be called on existing objects, proposing to fix this by making the function return 0 for absent objects. 

Garza is working to create a reliable test case from random CI failures, as the intermittent nature of the issue complicates reproduction. The current blocker is establishing regression prevention through a test case. Key technical elements remain the promisor pack handling in `builtin/pack-objects.c` and object existence checking in `should_include_obj()`. The thread shows active collaboration between the reporter (Garza), original commit author (via CC), and Tan to both diagnose and fix the issue.
