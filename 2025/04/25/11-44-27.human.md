This is a response in the ongoing thread about HTTP/2 support regressions in Git for Windows. Johannes Schindelin clarifies the intended scope of Git for Windows' bundled `curl.exe`, which was raised as problematic in the thread since it lost HTTP/2 support in recent versions.

The key point is that Git for Windows includes `curl.exe` incidentally rather than as a primary component, and Schindelin suggests alternatives: either using the system's built-in `curl.exe` (if available) or switching to MSYS2 for proper `curl` distribution. This positions the bundled `curl.exe` as a lower-priority issue compared to Git's core HTTP functionality, where HTTP/2 support can be restored via SSL backend configuration.

The response doesn't offer a path to restore HTTP/2 in the bundled `curl.exe`, instead treating it as out of scope for Git for Windows' main purpose. This may disappoint users relying on the bundled version for deployment scripts, but provides clear direction toward alternative solutions. The thread remains unresolved for users who cannot easily switch to system curl or MSYS2.
