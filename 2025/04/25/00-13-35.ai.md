This is the final patch in a 6-part series standardizing platform-specific handling in Git's Meson build system, specifically addressing networking function checks and compatibility implementations. The patch focuses on Windows platform behavior and corrects the approach for checking networking symbols.

The key change modifies the Meson build to skip checking for networking functions (inet_ntop, inet_pton, hstrerror) on Windows entirely, rather than attempting to verify their availability. This matches CMake's behavior and avoids unnecessary compiler checks on Windows where these functions don't exist. The patch also properly adds compatibility implementations (from compat/*.c) when functions are missing on non-Windows systems.

Technical details include:
- Conditional check based on host_machine.system() to exclude Windows
- Maintains the existing pattern of NO_ macro generation for missing functions
- Adds proper compat/ source file inclusion when functions are unavailable
- Preserves the networking_dependencies handling from previous patches
- Aligns with CMake's approach while correcting its misleading "incompatible" comment

The change is straightforward and completes the platform-specific handling work in the series. It follows the established patterns from previous patches while fixing the Windows-specific case. The patch appears well-considered, referencing both Makefile and CMake behaviors to justify its approach.
