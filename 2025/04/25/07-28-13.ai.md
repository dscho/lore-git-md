Performance fix for benchmark infrastructure with alternate repository formats.

This patch fixes an issue in Git's performance benchmark infrastructure where repository formats (SHA256 object format and reftable ref format) weren't properly preserved when copying test repositories. The benchmark setup intentionally skips copying repository configuration to avoid performance impacts from stray configs, but this was inadvertently dropping format information too.

The solution extracts the source repository's ref and object formats using `rev-parse --show-ref-format` and `--show-object-format`, then passes them explicitly to `git init` when creating the test copy. This maintains the benchmark's isolation principle while correctly handling alternate formats.

Key technical details:
- Modifies `t/perf/perf-lib.sh`'s `test_perf_create_repo_from` function
- Adds two new `rev-parse` calls to capture formats
- Passes formats via `--ref-format` and `--object-format` to `git init`
- Preserves all other isolation measures (hook disabling, config skipping)

This is part of Patrick Steinhardt's v4 series integrating perf tests with Meson, though the fix is independent of the build system changes. The change is narrowly scoped to maintain benchmark accuracy when testing with non-default repository formats, which was previously broken. The implementation matches Git's existing format handling conventions.
