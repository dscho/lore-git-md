This thread addresses a bug in `pack-objects` where `should_include_obj()` incorrectly processes non-existent objects during promisor pack operations, triggering a BUG() assertion. Originally reported by Nikolas Garza after upgrading to Git v2.49, the issue stems from commit c08589efdc5 in v2.48.0 which introduced an assumption that `should_include_obj()` would only handle existing objects.

Sam Estep has now provided a reliable reproduction case using Git v2.51.0 with a large Nixpkgs repository clone, demonstrating the bug occurs consistently during `git fetch --no-show-forced-updates` operations. The error manifests when repacking local links into promisor packs, validating the issue persists across versions and architectures (x86_64-linux and aarch64-darwin).

Jonathan Tan's earlier proposed solution - modifying `should_include_obj()` to return 0 for absent objects - remains the likely fix path. With the reproduction case now established, the thread has moved from diagnosis to implementation readiness, though confirmation is still needed on whether Tan's approach fully addresses the issue. The key technical focus remains on promisor pack handling in `builtin/pack-objects.c` and proper object existence checking.
