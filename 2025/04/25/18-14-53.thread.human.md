This thread addresses a bug in `pack-objects` where the `should_include_obj()` function incorrectly processes non-existent objects during promisor pack operations, triggering a BUG() assertion. Nikolas Garza originally reported encountering this issue after upgrading from Git v2.47 to v2.49, with Elijah Newren confirming the bug was introduced in commit c08589efdc5 ("index-pack: repack local links into promisor packs") from v2.48.0.

Garza has followed up noting the intermittent nature of the issue in their CI system, making it difficult to create a reliable reproduction case, though they are analyzing existing failures to try to produce one. Jonathan Tan has identified the root cause - the commit assumed `should_include_obj()` would only be called on existing objects - and proposed a fix to make the function return 0 for absent objects. However, the lack of a reproducible test case is currently blocking progress on the fix. The discussion shows active collaboration between the reporter and involved developers to both diagnose the issue and establish regression prevention measures. The key technical elements remain the promisor pack handling in `builtin/pack-objects.c` and the object existence checking behavior in `should_include_obj()`.
