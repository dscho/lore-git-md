Refactoring patch in Patrick Steinhardt's object store cleanup series (v2 5/13). This patch introduces a new flag `HAS_OBJECT_FETCH_PROMISOR` to control promisor object fetching behavior in the `has_object()` API, which is replacing the older `repo_has_object_file()`.

The change makes promisor object fetching opt-in rather than the default behavior, addressing a key limitation that was preventing full adoption of `has_object()`. The patch modifies both the implementation in `object-store.c` and the header declarations, adding the new flag while maintaining the existing `HAS_OBJECT_RECHECK_PACKED` functionality.

This is part of the larger effort to modernize Git's object storage code and remove the `the_repository` global. The change is relatively small (13 lines net) but strategically important for the series, as it enables conversion of remaining callsites that need promisor fetching capability. The implementation looks clean and maintains backward compatibility while providing more explicit control over object fetching behavior.
