This is a feature patch introducing a new "worktree-prune" maintenance task, part of Derrick Stolee's series to decompose `git gc` functionality into granular maintenance tasks. Patrick Steinhardt contributes this patch implementing the worktree pruning component.

The patch adds a new `worktree-prune` task to `git-maintenance` that mirrors the worktree pruning functionality from `git gc`. It introduces a `maintenance_task_worktree_prune()` function that calls `git worktree prune` with a 3-month expiry threshold, matching gc's behavior. The implementation includes a new `worktree_prune_condition()` helper that checks for prunable worktrees using the existing `should_prune_worktree()` logic.

Key technical details:
- New `TASK_WORKTREE_PRUNE` enum and task definition in builtin/gc.c
- Uses `get_worktree_names()` helper from previous patch to scan worktrees
- Maintains same 3-month expiry period as gc's worktree pruning
- Adds tests verifying both manual and auto-triggered pruning behavior
- Documents the new task in git-maintenance.adoc

The implementation appears thorough, with test coverage for both direct invocation and auto-mode behavior where pruning only occurs when stale worktrees are detected. This completes one of the two remaining gc functions (alongside rerere gc) needed to fully replace gc with maintenance tasks. The patch builds cleanly on the refactoring work from earlier in the series.
