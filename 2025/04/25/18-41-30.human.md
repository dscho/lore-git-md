This is a feature request for `git blame` to better handle ignored revisions. The author, Michael Grosser, wants to be able to set a global configuration for `.git-blame-ignore-revs` files that would work across all repositories, even when the file doesn't exist in some of them.

Currently, if you configure a blame ignore file globally but it's missing in a particular repository, Git fails with an error. The proposal suggests two alternative solutions: either make `git blame` automatically look for `.git-blame-ignore-revs` by default (similar to how it handles `.gitignore`), or add a new config option `blame.ignoreMissingFile` that would suppress the error when the file is absent.

The change would be particularly useful for developers who work with many repositories and want consistent blame behavior without having to create empty ignore files everywhere. The request seems straightforward and addresses a real pain point in workflow configuration, though it would need to be evaluated for potential edge cases in the blame functionality.
