This is the first patch in a two-part series improving shell path detection in Meson builds, specifically addressing cross-compilation reliability issues. The patch focuses on making detected runtime executable paths (Perl, Python, and shell) visible in the build summary output. 

The change adds a new section to Meson's summary output that reports the detected paths for these key executables. This provides better visibility into what paths are being used, which was previously only implicitly determined by Meson's `find_program()` lookup. The implementation exposes three pre-existing variables (`target_perl`, `target_python`, and `target_shell`) in the build summary.

This is a straightforward quality-of-life improvement that helps developers understand their build configuration at a glance. The patch follows the thread's established direction of maintaining functional equivalence with Makefile behavior while using Meson-native mechanisms. It implements Eli Schwartz's earlier suggestion to simplify diagnostic output for detected paths.

The change is minimal (6 lines added) and focused solely on reporting, not altering the detection logic itself. The second patch in the series will handle the actual shell path detection improvements. This first patch appears well-contained and non-controversial, serving as a foundation for the more substantive changes to follow.
