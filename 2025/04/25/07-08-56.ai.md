This is part of Patrick Steinhardt's ongoing object store refactoring series (v2, patch 5/13) preparing for `the_repository` removal. The patch introduces explicit control over promisor object fetching in the new `has_object()` API that's replacing `repo_has_object_file()`.

The key change adds a `HAS_OBJECT_FETCH_PROMISOR` flag (bit 1) to complement the existing `HAS_OBJECT_RECHECK_PACKED` (bit 0). This allows callers to opt into fetching missing promisor objects when needed, while maintaining the default behavior of skipping such fetches. The implementation modifies `oid_object_info_extended()` flags based on these bits, with `OBJECT_INFO_SKIP_FETCH_OBJECT` being set unless `HAS_OBJECT_FETCH_PROMISOR` is specified.

The patch updates both the implementation in `object-store.c` and the interface declaration in `object-store.h`, converting the single `#define` into an enum for better flag management. The commit message notes this addresses a gap preventing full conversion from `repo_has_object_file()`, as some legitimate use cases do require promisor fetching. The changes are relatively small (13 lines net) but strategically important for the series' goal of modernizing object storage access patterns.

This continues the thread's technical focus on explicit control flows and API cleanup, with Karthik Nayak having already reviewed and approved the approach in earlier patches. The change maintains compatibility with partial clone workflows while giving more precise control to callers about when promisor fetches should occur.
