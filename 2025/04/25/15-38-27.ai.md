CI/build system patch updating JGit download source as part of ongoing CI dependency handling improvements.

This second patch in a 2-part series changes the JGit download location from eclipse.org to Maven Central, following a recommendation from JGit maintainer Matthias Sohn. The change is straightforward - a single URL update in ci/install-dependencies.sh that points to the same JGit version (6.8.0.202311291450-r) but hosted on Maven instead. Johannes Schindelin provided a Helped-by for this change.

The patch maintains all existing CI infrastructure patterns including the atomic download-cleanup approach and error handling established in previous work. This appears to be a maintenance update rather than a functional change, aligning with the project's preferred artifact hosting while keeping the same version and behavior. The change fits naturally with the series' goal of making external dependency handling more robust, though it doesn't directly relate to the warning presentation refinements discussed in the thread.

Key technical details:
- Updates JGITWHENCE variable in install-dependencies.sh
- Same JGit version (6.8.0.202311291450-r)
- New source: repo1.maven.org instead of repo.eclipse.org
- Maintains existing download pattern and safety mechanisms

The patch seems uncontroversial and well-justified by the JGit maintainer's recommendation. It's a small piece of the larger CI dependency handling improvements, with the more complex warning system changes already handled in the first patch of the series.
