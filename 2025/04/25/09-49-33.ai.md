This is a follow-up in the CI/build system thread about making external dependency downloads optional in Git's CI jobs. Junio Hamano responds to Patrick Steinhardt's suggestion to tighten error handling by only allowing network operations (wget) to fail while keeping local operations (like chmod) strict.

The key technical point is that wget's behavior when failing creates a subtle issue - it leaves behind an empty file, which causes subsequent type checks to incorrectly think the dependency is present. This leads to failures later when trying to execute the empty file. The current approach handles this by allowing the entire download-and-setup chain to fail gracefully, including the chmod step, to ensure proper cleanup.

Junio acknowledges Patrick's suggestion in principle ("as strict as possible") but explains the practical reality of wget's behavior requires the broader error handling approach. This maintains consistency with how the test framework already handles missing dependencies while preventing partial-download side effects from causing CI failures.

The exchange shows alignment on the core goal (optional downloads with proper failure handling) while working through implementation nuances. Junio's response suggests the current approach is the pragmatic solution given wget's behavior, though the thread remains open for further discussion about potential refinements.
