This is a follow-up in the ongoing discussion about HTTP/2 support in Git for Windows' bundled curl.exe. Lars Eriksen reports they've found a workaround by having their server team install a separate curl build, acknowledging that the Git-bundled version is primarily meant for Git's internal use. He withdraws his earlier request for HTTP/2 support in the bundled curl.

The exchange highlights the tension between users repurposing bundled tools and the maintainers' view of them as implementation details. While the immediate issue is resolved for Lars through an alternative installation, the underlying philosophical disagreement remains - with Johannes Schindelin reiterating that Git for Windows isn't intended as a general software distribution channel. The thread appears to be winding down with this practical resolution, though the broader questions about bundled tool expectations in enterprise environments remain open.
