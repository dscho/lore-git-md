This is patch 7/13 in Patrick Steinhardt's series refactoring the object store subsystem, part of the `the_repository` removal effort. It focuses on index-pack's collision check behavior with promisor objects.

The patch modifies `builtin/index-pack.c` to avoid unnecessarily fetching promisor objects during collision checks. Currently, when checking if an object exists (to determine if a collision check is needed), the code uses `repo_has_object_file_with_flags()` with `OBJECT_INFO_QUICK`, which may still trigger promisor object fetches unless explicitly told not to. This leads to the counterintuitive behavior of potentially downloading an object just to verify it doesn't collide with one being indexed.

The change replaces this with the new `has_object()` API (introduced earlier in the series) which by default neither reloads packfiles nor fetches promisor objects. The flags parameter is set to 0, meaning it will only check local objects without any special handling. This matches the intended behavior for collision checks, where we only care about objects already present in the local repository.

The change is small (4 lines modified) but addresses a subtle behavioral issue in partial clone scenarios. It follows the pattern established in patch 6/13 of systematically converting deprecated object existence checkers to the new API while maintaining careful behavioral equivalence where needed. This particular case is one where promisor fetching is clearly undesirable, as noted in the open questions from the thread summary.
