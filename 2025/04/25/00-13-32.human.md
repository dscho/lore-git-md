This is a build system patch addressing platform compatibility, specifically for Solaris systems. It's part of a 6-patch series focused on Windows-specific handling in the Meson build system, though this particular patch deals with Solaris quirks.

The patch changes how Git checks for `sysinfo()` availability during compilation. The current check only verifies the header exists, which is insufficient on Solaris where the header exists but provides a completely different `sysinfo()` function with different semantics. The new approach verifies the actual struct field (`totalram`) that Git uses in `builtins/gc.c` is present, which will correctly fail on Solaris systems that don't provide the Linux-compatible version.

The change is straightforward - it moves the simple header check and replaces it with a more precise struct member verification. This maintains compatibility with Linux systems while properly handling Solaris's different implementation. The patch appears well-justified and narrowly focused, completing the series' goal of robust platform-specific handling in the Meson build system.
