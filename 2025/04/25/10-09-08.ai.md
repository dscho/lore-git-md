This is a revised version of the `git send-email` patch series focusing on Outlook compatibility, now reduced to just the Message-ID handling patch (previously patch 2 in the series). The OAuth2 authentication and dynamic token generation patches have been dropped based on prior discussion.

The remaining patch addresses Outlook's nonstandard Message-ID behavior by retrieving the server-assigned Message-ID from the SMTP response when sending through Outlook servers. This prevents thread breaks caused by Outlook rewriting Message-IDs with its own proprietary format. The implementation adds 21 lines to `git-send-email.perl` to parse the SMTP response for the Outlook-assigned ID.

Key technical details:
- Detects Outlook servers (currently by hostname matching `smtp.office365.com` or `smtp-mail.outlook.com`)
- Parses SMTP response for "250 2.0.0 OK" followed by Message-ID
- Updates the local message with Outlook's assigned ID
- Maintains backward compatibility with non-Outlook servers

The patch builds on the v5 version with improved commit message clarity and documentation. The removal of the other patches reflects consensus to:
1. Use the upstreamed Authen::SASL OAuth2 implementation (now in perl-authen-sasl PR #19)
2. Rely on Git's credential helper system instead of adding `smtp-passeval`

Open questions from the thread remain around enterprise Outlook detection (Greg Kroah-Hartman's config variable suggestion) and documentation improvements for credential helper usage (per Junio Hamano's feedback). The series now represents a focused fix for the Message-ID issue while deferring broader authentication changes to the upstream Perl module and credential helper system.
