This is a performance and behavior tweak to Git's diff algorithm. The patch disables the `cleanup_records` heuristic when `--minimal` is specified, as this heuristic can sometimes mark unchanged lines as changed when they're surrounded by many actual changes. While this heuristic is generally a good optimization, it can produce slightly longer diffs than necessary - which goes against the explicit goal of `--minimal` to produce the shortest possible diff.

The change affects the xdiff internals, modifying how line changes are classified before the actual diff algorithm runs. A new test case verifies that unchanged lines surrounded by changes aren't marked as changed in minimal diff mode. The author notes this produces shorter diffs in about 1.3% of cases in Git's history, with negligible performance impact.

The implementation is straightforward - it passes through the `need_min` flag to skip the heuristic's aggressive marking when minimal diffs are requested. The patch appears well-constructed with a clear commit message explaining both the problem and solution, and includes a targeted test case. This seems like a reasonable refinement to Git's diff behavior when minimal output is explicitly requested.
