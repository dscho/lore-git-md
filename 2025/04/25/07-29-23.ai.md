Feature patch completing the maintenance task decomposition series by adding rerere garbage collection.

This is the final patch in a 7-part series that implements the last two standalone maintenance tasks needed to fully replace `git gc` functionality - worktree pruning and rerere garbage collection. While the series doesn't actually deprecate `git gc` yet, it completes the technical prerequisites by providing granular alternatives for all its components.

The patch introduces a new `rerere-gc` maintenance task that performs the same function as `git rerere gc`, cleaning up stale entries in the rerere cache. The implementation:
- Adds a new `TASK_RERERE_GC` enum and task definition
- Implements `maintenance_task_rerere_gc()` which runs `git rerere gc` as a child process
- Includes `rerere_gc_condition()` to check if garbage collection is needed
- Preserves the existing error handling via `FAILED_RUN`
- Updates documentation in git-maintenance.adoc
- Adds tests verifying both manual and auto-triggered behavior

The task only runs when the rr-cache directory exists and contains entries, matching the original gc behavior. Tests confirm the proper subcommand execution and auto-condition checking. This completes the functional parity between maintenance tasks and git-gc, though the series stops short of actually deprecating gc itself.

The patch follows the same pattern as the earlier worktree-prune task in the series, maintaining consistency in how maintenance tasks are structured. With both components now implemented as standalone tasks, this series represents a major milestone in the long-term effort to replace the monolithic gc command with granular maintenance operations.
