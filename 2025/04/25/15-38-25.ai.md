Cover letter for a CI/build system patch series that updates the handling of unavailable external dependencies in Git's CI infrastructure. This follows up on the fast-tracked changes made to address eclipse.org outages, incorporating Johannes Schindelin's suggestions.

The series makes two specific changes to the CI dependency handling that was recently patched in the maint branch. First, it updates the warning message shown when third-party software is unavailable to be more informative. Second, it changes the JGit download source from eclipse.org to Maven Central, which was previously discussed as a more reliable alternative source.

These changes build on the established pattern of atomic download-cleanup operations with proper error handling that was already agreed upon in the thread. The series maintains the core approach of treating wget+chmod as an atomic operation while improving the user-facing messaging and source reliability. This appears to be a straightforward refinement of the existing solution rather than introducing new architectural changes.

The thread context shows this is part of an ongoing discussion that has expanded to consider both warning presentation (where Junio and Johannes have slightly different preferences) and caching approaches (which are being explored as a complementary improvement). This particular patch set focuses on the immediate messaging and source URL improvements while leaving the caching exploration for potential future work.

Technical details show the changes are limited to ci/install-dependencies.sh, with a net reduction in lines of code. The switch to Maven Central for JGit downloads was previously noted by Johannes as a viable alternative source, and the updated warning messages likely address his concerns about making CI failures more visible to developers.
