This thread explores ways to improve `git blame`'s handling of missing `.git-blame-ignore-revs` files, addressing a usability pain point for developers who maintain this configuration across multiple repositories. Michael Grosser initiated the discussion by proposing two potential solutions: either automatically checking for the file in each repository without explicit configuration, or adding a `blame.ignoreMissingFile` option to suppress fatal errors when the file is absent.

Eric Sunshine has since contributed important context by linking to prior discussions about this functionality, including a GitHub pull request and a thread from Junio Hamano in October 2024. These references suggest the community has previously considered related aspects of the ignore-revs feature, though the current focus on global configuration usability appears to be a new angle.

The core issue remains the strict current behavior where a missing file causes `git blame` to fail, forcing users to either maintain per-repository configurations or create empty files in repositories that don't need them. The discussion is still in early stages, with no implementation patches or detailed technical proposals yet, but the prior art Eric surfaced may help inform the solution's direction.
