Here's a human-readable summary of the thread so far:

Michael Grosser has proposed making `git blame` handle missing ignore-revs files more gracefully. Currently, when users set a global blame.ignoreRevsFile configuration pointing to `.git-blame-ignore-revs`, Git fails with a fatal error if that file doesn't exist in a particular repository. This creates friction for users who maintain ignore-revs files across multiple repositories.

Grosser suggests two potential solutions: either have `git blame` automatically check for `.git-blame-ignore-revs` in each repository without requiring explicit configuration, or add a new `blame.ignoreMissingFile` option that would suppress the error when the configured file is absent. Both approaches would maintain backward compatibility while solving the usability issue where users currently need to either configure each repository individually or create empty ignore files in repositories that don't need them.

This is currently just a feature proposal - no implementation has been shared yet. The suggestion appears well-motivated by real-world workflow pain points around maintaining ignore-revs files across multiple repositories.
