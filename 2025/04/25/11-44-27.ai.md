This is a response in the ongoing HTTP/2 support regression thread, where Johannes Schindelin clarifies the intended scope of Git for Windows' bundled tools. The email makes two key points about the standalone `curl.exe` issue: first, that Git for Windows is not meant to be a general-purpose distribution channel for `curl.exe` (it's included only as a dependency for Git operations), and second, that users needing full `curl.exe` functionality should either use the system version or install MSYS2 for proper software distribution.

The response notably does not address the technical regression (HTTP/2 support being removed from the bundled `curl.exe`), instead focusing on the philosophical question of what Git for Windows should provide. This suggests the maintainer views the `curl.exe` regression as out of scope for Git for Windows' core mission, though the practical impact on users remains unaddressed. The suggestion to use system `curl.exe` or MSYS2 may not help corporate environments with strict installation policies that originally relied on the Git for Windows-bundled version.
