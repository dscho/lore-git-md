This is a follow-up in the Git for Windows certificate verification thread, where the original issue involved CRYPT_E_NO_REVOCATION_CHECK errors during updates in Brazilian Portuguese locales. 

Junio Luan Pereira reports they've identified the root cause: Norton Antivirus's "Safe Web" feature was blocking curl's access to Let's Encrypt-validated sites when using the schannel backend. Disabling this antivirus feature resolved the update issues completely. 

The email suggests the problem was environmental (antivirus interference) rather than a Git or curl bug, though the earlier proposed workaround of modifying the update script with `--ssl-revoke-best-effort` would likely have worked around the issue as well. The thread appears resolved with this antivirus discovery, though it highlights how security software can unexpectedly interfere with Git's update mechanism on Windows.
