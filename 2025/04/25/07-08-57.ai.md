This is patch 6/13 in Patrick Steinhardt's v2 series refactoring the object store subsystem as part of the `the_repository` removal effort. The patch systematically converts calls to the deprecated `repo_has_object_file()` and its variants to use the new `has_object()` API introduced earlier in the series.

The conversion follows clear mapping rules:
- Plain `repo_has_object_file()` becomes `has_object()` with both `HAS_OBJECT_RECHECK_PACKED` and `HAS_OBJECT_FETCH_PROMISOR` flags set
- Calls with `OBJECT_INFO_QUICK|OBJECT_INFO_SKIP_FETCH_OBJECT` become flagless `has_object()`
- Calls with just `OBJECT_INFO_SKIP_FETCH_OBJECT` use only `HAS_OBJECT_RECHECK_PACKED`

The patch touches 17 files across various subsystems including builtins (cat-file, clone, fetch), ref handling (reflog, notes), network operations (http-push, upload-pack), and object storage internals. Each conversion maintains existing behavior but makes the promisor object fetching policy more visible through explicit flags.

The author notes that some callsites where promisor fetching is clearly undesirable are intentionally left unconverted - these will be handled separately in upcoming patches. The changes are mechanical but thorough, with careful attention to maintaining equivalent behavior while removing deprecated API usage.
