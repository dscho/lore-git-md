Build system refactoring: First patch in a series standardizing Meson function availability tests.

This patch introduces a more maintainable approach to checking for standard library function availability in Git's Meson build system. Instead of individual ad-hoc checks for each function, it consolidates them into an array-based system that automatically handles the common pattern of defining `NO_` macros and including compatibility implementations when needed. The change affects checks for functions like `strcasestr`, `memmem`, `strlcpy`, and several others, while maintaining special handling for platform-specific cases (like Windows' `mmap`).

Key technical details:
- Introduces a `checkfuncs` array containing standard functions to verify
- Automatically generates `NO_` macros for missing functions (e.g., `NO_STRCASESTR`)
- Looks for corresponding implementations in `compat/` when available
- Preserves special cases like Windows-specific handling via `USE_WIN32_MMAP`
- Maintains existing behavior for functions not yet converted (like `sync_file_range` and `qsort`)
- Reduces code duplication while keeping the same functionality

The patch is part of a larger effort to modernize Git's build system infrastructure, with this particular change focusing on making the function availability checks more maintainable and consistent. It follows the pattern established in the thread of standardizing build system checks while addressing platform-specific concerns.
