This is part 2/7 of Patrick Steinhardt's series hardening integer handling in Git's parse-options infrastructure, specifically addressing overflow detection in integer parsing.

The patch fixes a subtle bug where `strtol()` was used to parse integer options without checking `errno`, meaning overflow conditions could go undetected. The code properly checks for `ERANGE` and other error conditions now, providing clear error messages when values exceed `LONG_MIN`/`LONG_MAX` or fail to parse. A new test case verifies the overflow detection works by attempting to parse a value too large for a long`.

This is a straightforward safety improvement that plugs a real hole in the option parsing logic. The change is well-contained (just 10 lines of core changes plus tests) and builds on the series' goal of making numeric option handling more robust. The commit message clearly explains both what's fixed here and what limitations remain (the subsequent type truncation issue to be addressed in later patches).
