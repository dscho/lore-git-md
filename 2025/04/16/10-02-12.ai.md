This is patch 3/7 in Patrick Steinhardt's v3 series hardening integer handling in Git's parse-options infrastructure. The patch focuses on precision handling for `OPTION_INTEGER` options.

The key technical changes introduce a new `precision` field in the option struct that tracks the byte size of the integer being stored (1, 2, 4, or 8 bytes). This allows proper range checking when parsing values and prevents integer truncation. The patch:

1. Adds `precision` field initialization in `OPT_INTEGER_F()` macro and updates callers in `builtin/fmt-merge-msg.c`, `builtin/merge.c`, `builtin/show-branch.c`, and `builtin/tag.c`
2. Replaces `strtol()` with `strtoimax()` to handle values beyond `LONG_MAX`
3. Implements proper range checking based on the precision/size of the target integer
4. Adds tests for 16-bit integer handling in `t/helper/test-parse-options.c` and `t/t0040-parse-options.sh`
5. Documents the new `precision` field in `parse-options.h`

The changes address potential integer overflow/truncation issues that could occur when:
- Callers passed values too large for the target integer type
- Values exceeded `LONG_MAX` during parsing
- Implicit casts occurred between different integer sizes

The test additions verify proper handling of 16-bit integers, including rejection of out-of-range values (both positive and negative). This builds on the overflow detection added in patch 2/7 by adding precision/size awareness to the integer parsing logic.

The patch maintains backward compatibility while providing stronger safety guarantees. It represents one layer in the series' multi-pronged approach to integer handling safety, with subsequent patches handling signedness validation and other aspects.
