Feature enhancement completing Patrick Steinhardt's integer parsing safety series. This final patch (7/7) introduces bounded integer options to Git's parse-options infrastructure, allowing option definitions to specify custom value ranges beyond just type constraints.

The patch adds `OPT_*_BOUNDED()` variants for integer, unsigned, and magnitude options that can enforce user-defined minimum/maximum values. This eliminates manual bounds checking in callers while maintaining all the type safety improvements from earlier patches. The implementation includes:

- New `lower_bound` and `upper_bound` fields in `struct option`
- Range validation during option parsing with user-friendly error messages
- Compile-time checks ensuring bounds fit the declared precision
- Test coverage demonstrating valid and invalid cases
- Backward-compatible API additions

This completes the series' goal of hardening integer handling throughout Git's option parsing. The change is well-considered, with careful attention to edge cases and thorough testing. As the last piece of a multi-patch effort that has already addressed reviewer feedback, it appears ready for inclusion.
