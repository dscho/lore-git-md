This is the final patch (7/7) in Patrick Steinhardt's v3 series hardening integer handling in Git's parse-options infrastructure, introducing bounded integer options as a proof-of-concept extension to the core safety improvements.

The patch adds `OPT_*_BOUNDED()` variants for integer, unsigned, and magnitude options that allow callers to specify custom value ranges beyond the basic type safety provided by the earlier patches. Key technical aspects:

- New `lower_bound` and `upper_bound` fields in `struct option` to store range constraints
- Validation logic in `do_get_value()` that checks values against bounds before assignment
- Three new macro families: `OPT_INTEGER_BOUNDED[_F]`, `OPT_UNSIGNED_BOUNDED[_F]`, and `OPT_MAGNITUDE_BOUNDED`
- Comprehensive test coverage in t0040 verifying:
  - Rejection of values below/above bounds
  - Acceptance of values at boundary edges
  - Proper error messages for out-of-range values
- Maintains all prior safety checks (signedness validation from patch 6, precision handling from patches 3-5)

The implementation handles edge cases like:
- Invalid bound specifications (triggering BUG())
- Negative bounds for unsigned types (caught via BUG())
- Maintaining existing PARSE_OPT_NONEG behavior for magnitude options
- Integration with optional arguments (--option vs --option=value)

As noted in the commit message, this is positioned as an optional extension rather than a required change - the core safety work is complete without it, but the bounded variants provide a cleaner pattern for options that naturally have constrained value sets. The patch completes the series' vision of comprehensive integer handling safety while leaving room for future adoption of bounded options where appropriate.
