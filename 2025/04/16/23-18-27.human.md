This is a build system documentation patch in the ongoing Makefile/meson alignment series. It addresses a compatibility issue with the `strlcpy()` function on Linux systems.

The patch adds a comment to `config.mak.uname` noting that Linux users with glibc 2.38 or newer (like Ubuntu 24.04 and RHEL 10 beta) can override the default `NO_STRLCPY` setting to use the system's `strlcpy()` instead of Git's compat version. This brings the Makefile build in line with how meson and autoconf already handle this case.

The change is straightforward but highlights an important build system inconsistency: while newer build systems automatically detect and use the system `strlcpy()`, the Makefile build still defaults to the compat version. The comment serves as a helpful reminder for users on modern systems to update their configuration.

This is a small but thoughtful addition to the larger build system modernization effort, ensuring users get optimal builds while maintaining compatibility with older Linux distributions still in their support windows.
