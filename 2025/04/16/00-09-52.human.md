This is a discussion about patch tracking mechanisms in Git, specifically comparing Patch Set IDs versus Change-IDs. Junio Hamano responds to Remo Senekowitsch's point that Patch Set IDs share the same ambiguity problems as Change-IDs when commits are split, merged, or cherry-picked between patch sets.

Hamano acknowledges the validity of the concern but still prefers Patch Set IDs over Change-IDs as the lesser of two imperfect solutions. He suggests that to truly resolve these ambiguities, Git would need a more comprehensive approach that records change evolution relationships - tracking not just parent-child commit relationships but also how commits are derived from their predecessors.

The exchange highlights the ongoing tension in the thread between different approaches to patch tracking, with Hamano weighing in on the side of Patch Set IDs while recognizing their limitations. The discussion continues to explore fundamental questions about how Git should model and track changes across patch series versions.
