This is the first patch in Patrick Steinhardt's v3 series hardening integer handling in Git's parse-options infrastructure. It's a refactoring patch that converts all manual struct initializations of parse-options structures to use designated initializers instead.

The patch modernizes 24 files across the codebase, touching commands like `git commit`, `git merge`, `git fetch`, and many others. The key changes are:

1. Replaces positional struct initialization with named field initialization (e.g. `{ OPTION_STRING, 'S', "gpg-sign", &sign_commit, ... }` becomes `{ .type = OPTION_STRING, .short_name = 'S', ... }`)
2. Updates macro definitions like `OPT_CALLBACK_VALUE` and `_OPT_MERGED_NO_MERGED` to use designated initializers
3. Maintains all existing functionality while making the code more maintainable

The commit message explains this helps with code clarity, reduces distraction from zero-initialized fields, and makes future struct changes easier. The changes are mechanical but extensive, touching 443 lines while removing 158 lines of old-style initializations.

This foundational refactoring enables the subsequent patches in the series which add safety checks for integer handling. The patch appears well-executed with no behavior changes, just modernization of the initialization style. It was previously reviewed in v2 and remains unchanged in v3.
