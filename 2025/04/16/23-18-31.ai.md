This is a bugfix patch in the build system alignment series, specifically addressing RAM calculation in `git gc` when using Cygwin's `sysinfo()` implementation. The patch corrects an assumption that memory sizes are always reported in bytes, which doesn't hold true on Cygwin where `mem_unit` may be greater than 1 (4096 in the test case shown).

The key technical details are:
- Linux's `sysinfo()` typically reports sizes in bytes (`mem_unit=1`), but Cygwin uses page-sized units (`mem_unit=4096`)
- The current `total_ram()` function in `builtin/gc.c` doesn't account for `mem_unit`, leading to incorrect RAM calculations on Cygwin
- The fix multiplies `totalram` by `mem_unit` when `mem_unit > 1`, preserving the existing behavior on Linux while fixing Cygwin
- The patch includes test results showing Cygwin reporting 8GB RAM as 2074637*4096=8497713152 bytes (close to actual 8GB)

This is part of the broader Cygwin compatibility work in the series, specifically addressing one of the open questions from earlier in the thread about whether to handle `mem_unit > 1`. The solution maintains compatibility with both Linux and Cygwin implementations of `sysinfo()`. The patch is well-motivated with clear test evidence and maintains the existing behavior on platforms where `mem_unit=1`.
