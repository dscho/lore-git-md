This is a build system patch completing the cryptographic random number generation (CSPRNG) standardization effort in the ongoing Makefile/meson alignment series. It sets `CSPRNG_METHOD = getrandom` for Linux builds in `config.mak.uname`, bringing Makefile behavior in line with meson's preference for kernel-based random number generation.

The patch explains that while newer glibc versions (≥2.36) support `arc4random`, there's no performance benefit on Linux since all methods ultimately use the same kernel syscall. The choice of `getrandom` over `/dev/urandom` (current Makefile default) or `arc4random` (meson default) is motivated by wider availability (works on all supported distros including RHEL 8) and consistency with the kernel's preferred interface.

Key technical details: Linux's `getrandom()` has been available since glibc 2.25 (2017), covers all current distros, and matches the kernel's CSPRNG syscall behavior. The change affects `csprng_bytes()` helper usage, though not in performance-critical paths. This completes the CSPRNG standardization that previously added `arc4random` support for Cygwin in patch 19/19.

The patch maintains the series' theme of build system rationalization while making a practical choice between technically equivalent options based on availability rather than theoretical preferences. It resolves the last inconsistency in CSPRNG method selection across build systems, with meson already defaulting to kernel interfaces on Linux. The change is low-risk since all methods ultimately use the same kernel CSPRNG, just through different interfaces.
