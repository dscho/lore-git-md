This is patch 3/7 in Patrick Steinhardt's series hardening integer handling in Git's parse-options infrastructure. The patch focuses on improving precision handling for `OPTION_INTEGER` options, which currently use a simple `int` type that can lead to integer wraparound or out-of-bounds writes when storing values.

The key changes introduce a new `precision` field that tracks the size of the integer being stored, allowing proper range checking for different integer sizes (8-bit, 16-bit, etc.). The parsing is also upgraded from `strtol()` to `strtoimax()` to handle values beyond `LONG_MAX`. The patch includes updates to several builtin commands (`fmt-merge-msg`, `merge`, `show-branch`, `tag`) to use the new precision field, plus new test cases verifying the range checking works correctly.
