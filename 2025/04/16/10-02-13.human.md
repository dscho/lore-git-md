This is part 4/7 of Patrick Steinhardt's series hardening integer handling in Git's option parsing, focusing on magnitude options (`OPTION_MAGNITUDE`). Following the pattern established in patch 3/7 for integer options, this patch adds precision handling for magnitude values that specify sizes with k/m/g suffixes.

The key changes introduce:
- Size validation for magnitude values based on the target variable's precision (1/2/4/8 bytes)
- Proper bounds checking to prevent overflow when storing to smaller integer types
- A new test case for 16-bit magnitude values
- Backward-compatible behavior for existing magnitude options

The implementation mirrors the integer handling from the previous patch but works with unsigned values. It adds a test verifying that 16-bit magnitude values are properly constrained to 0-65535. The changes affect core parsing logic in `parse-options.c` while maintaining the existing API.

This continues the series' systematic approach to making option parsing more robust, now covering both signed and unsigned numeric values. The patch appears well-tested and follows the same careful pattern as the rest of the series.
