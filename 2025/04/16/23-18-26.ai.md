This is a build system cleanup patch removing obsolete platform compatibility code. It's part of Ramsay Jones' ongoing series to modernize and align the Makefile and meson build systems.

The patch removes the NEEDS_LIBRT build variable and associated linking logic, which was originally added in 2016 to support older Linux systems (notably Debian 7 with glibc 2.13) that required linking with librt for clock_gettime functionality. The commit message provides detailed timeline showing this is now obsolete, as all supported Linux distributions (Debian 8+, RHEL 8+, Ubuntu 16.04+) have shipped glibc 2.17+ since 2013-2016, which includes clock_gettime in libc without needing librt.

The change removes the variable definition from both the Makefile documentation section and the Linux-specific config.mak.uname settings. This continues the series' trend of removing legacy platform support while maintaining current functionality. The patch is straightforward with no expected controversy, as it simply removes code that's been unnecessary for years across all supported platforms.
