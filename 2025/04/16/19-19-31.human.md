This is a discussion about the final patch in Patrick Steinhardt's v3 series hardening integer handling in Git's parse-options infrastructure. The patch introduces bounded integer options that allow callers to specify value ranges for validation.

Junio C Hamano raises concerns about whether this feature is actually needed (YAGNI - "You Aren't Gonna Need It"). He notes there don't appear to be any existing callers that would use this functionality, as evidenced by the lack of conversions in the diffstat. He also questions some design choices, like whether the bounds should include 0, and suggests the feature might be premature without concrete use cases.

The patch itself would add range validation to integer options, allowing both lower and upper bounds to be specified. It modifies the parse-options machinery and adds tests, but as Junio observes, doesn't actually convert any existing options to use the new functionality. This comes at the end of a series that has otherwise focused on more fundamental integer handling safety improvements.

The discussion highlights a tension between proactive API improvements and waiting for demonstrated need. While the rest of the series addresses clear safety issues, this final patch represents more of an enhancement whose value depends on future usage patterns.
