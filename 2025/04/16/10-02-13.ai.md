This is patch 4/7 in Patrick Steinhardt's series hardening integer handling in Git's parse-options infrastructure, focusing on `OPTION_MAGNITUDE` precision handling. Building on the previous patch's work for `OPTION_INTEGER`, this extends the same precision/size awareness to magnitude options (unsigned values with k/m/g suffixes).

The key technical changes include:
- Adding precision-based range checking for magnitude values via a new `upper_bound` calculation
- Proper type handling for 1/2/4/8 byte storage through the precision field
- Conversion from `unsigned long` to specific uint*_t types based on precision
- New test cases for 16-bit magnitude handling (including range validation)
- Maintains backward compatibility while adding safety checks

The patch updates the same core files as previous patches (`parse-options.[ch]`, test files) and follows the same pattern of:
1) Validating input ranges
2) Properly storing values based on declared size
3) Comprehensive test coverage
4) Clear error messages for out-of-range values

This completes the magnitude handling portion of the integer safety work, parallel to the signed integer improvements in patch 3/7. The changes are consistent with the series' overall approach of adding compile-time and runtime validation while maintaining the existing API.
