This is a review comment from Junio C Hamano on patch 5/7 of Patrick Steinhardt's series hardening integer handling in Git's parse-options infrastructure. The patch introduces a new `OPTION_UNSIGNED` type for parsing numbers without suffixes, filling a gap between existing `OPTION_INTEGER` (signed) and `OPTION_MAGNITUDE` (unsigned with suffixes).

Junio questions the design direction, suggesting an alternative approach: rather than adding a new unsigned-only type, we could extend `OPTION_INTEGER` to optionally support scaling suffixes. He challenges whether there are compelling use cases that truly need to reject both signs and suffixes, implying the new type might be unnecessary complexity.

The comment comes late in a well-reviewed series where most technical aspects (overflow handling, type safety, etc.) have already been vetted. Junio's focus here is narrowly on the API design choice rather than implementation correctness. This appears to be the last open discussion point before the series could be considered for merging, with all other feedback having been addressed across three iterations.
