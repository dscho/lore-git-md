Maintainer discussion on patch tracking approaches. Jacob Keller responds to Remo Senekowitsch's defense of Change-IDs in the ongoing debate about native Git patch series tracking. The exchange focuses on whether Change-IDs or Patch Set IDs better handle patch evolution tracking.

Keller acknowledges that Change-IDs could theoretically serve as patch set identifiers if cover letters (which typically have stable Change-IDs) are committed. However, he notes this approach has limitations since cover letter commits aren't preserved after merging. The discussion highlights differing views on whether tracking individual commit evolution (Change-ID's strength) is more valuable than tracking patch sets as units (Patch Set ID's focus).

The thread continues to explore fundamental tension between these approaches, with Keller suggesting the choice depends on what users actually need from the tracking system. His measured response keeps both options in play while questioning whether either fully satisfies the use cases motivating this discussion.
