This is the first patch in a series to make Perl optional in Git, specifically converting `git-filter-branch`'s state handling from Perl to shell. The patch removes the script's dependency on Perl for its `--state-branch` feature, which tracks object ID mappings during branch rewriting.

The conversion addresses two issues: first, that the script was calling Perl directly without respecting the system's configured `PERL_PATH`, potentially using the wrong version; second, that the feature would fail entirely on systems without Perl installed. The new implementation uses shell I/O redirection and `git hash-object` to handle the state mapping, maintaining the same `from_commit:to_commit` format in the state file.

The changes are straightforward - replacing Perl file operations with shell equivalents while keeping the same error handling rigor. This patch was already approved in v1 of the series and remains unchanged in v2, indicating it's considered ready for merging. It's part of Git's broader effort to reduce Perl dependencies, following similar conversions in the test suite.
