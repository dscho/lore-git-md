This is patch 5/7 in Patrick Steinhardt's series hardening integer handling in Git's parse-options infrastructure, focusing on unsigned integer parsing.

The patch introduces a new `OPTION_UNSIGNED` type to handle unsigned integers without magnitude suffixes (unlike `OPTION_MAGNITUDE` which handles k/m/g suffixes). It follows the same precision-based approach as previous patches, with proper bounds checking and type safety. The implementation includes:

- Core parsing logic in parse-options.c that rejects negative values and validates ranges
- New `OPT_UNSIGNED` and `OPT_UNSIGNED_F` macros in parse-options.h
- Test coverage in t/helper/test-parse-options.c and t/t0040-parse-options.sh
- 16-bit unsigned integer support with explicit range checking (0-65535)
- Consistent error handling for invalid inputs (negative numbers, out-of-range values)

The patch completes the type safety work for unsigned values, complementing the earlier signed integer and magnitude handling patches. It maintains the series' pattern of compile-time type safety while adding runtime validation. The tests verify both successful parsing and proper rejection of invalid cases (negative numbers, values exceeding 16-bit bounds).

This is a well-contained addition that fills a gap in the parse-options API while maintaining consistency with the series' overall approach to integer handling safety. The implementation appears thorough, with clear error messages and comprehensive test coverage matching the patterns established in previous patches.
