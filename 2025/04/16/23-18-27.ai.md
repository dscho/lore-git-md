This is a build system patch addressing platform compatibility, specifically around the `strlcpy()` function availability on Linux systems. 

The patch adds a comment to `config.mak.uname` noting that Linux users with glibc ≥2.38 (which added native `strlcpy()` support) should override the default `NO_STRLCPY` setting in their local `config.mak`. This brings the Makefile build in line with behavior already handled automatically by meson/autoconf builds, which detect and use the system's `strlcpy()` when available. The change helps avoid unnecessary use of Git's compatibility function on modern systems while maintaining backward compatibility for older distributions still within their support windows (like those using glibc <2.38).

Key technical points for future reference:
- Affects Linux builds using Make (meson/autoconf already handle this dynamically)
- Glibc 2.38+ provides native `strlcpy()` (Ubuntu 24.04 LTS, RHEL 10 beta have 2.39)
- Makefile users must manually override `NO_STRLCPY` in `config.mak` to use system version
- Original compat function remains default in Makefile for older systems
- Related to 2006's 817151e61a which introduced the `NO_STRLCPY` variable
- No functional change - purely a documentation addition to guide users
- Part of broader build system alignment effort (Makefile/meson consistency)
