This is patch 2/7 in Patrick Steinhardt's v3 series hardening integer handling in Git's parse-options infrastructure, specifically addressing overflow detection in integer parsing. The patch focuses on adding proper `errno` checking when parsing integer options via `strtol()`, which was previously missing. This prevents silent failures when parsed values exceed `long` range limits. The implementation now explicitly checks for `ERANGE` and other `errno` conditions, providing appropriate error messages when values are out of bounds or unparseable. 

The changes affect the core option parsing logic in `parse-options.c`, adding validation that catches both overflow conditions and general parsing failures. A new test case verifies the overflow detection by attempting to parse a value (9223372036854775808) that exceeds `long` maximum. The patch notes this is only part of the solution, as subsequent patches will handle the additional issue of `int` truncation when assigning the `long` result.

This addresses feedback from Phillip Wood about proper overflow detection and integrates with the series' broader goal of making numeric option handling more robust. The changes maintain backward compatibility while adding important safety checks that were previously missing. The test coverage demonstrates the new validation in action, ensuring invalid inputs are properly rejected.
