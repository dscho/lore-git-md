Regex compatibility patch in the build system alignment series, focusing on Cygwin-specific behavior. This patch (7/13 in v3) narrows the `NO_REGEX` setting to only apply to Cygwin 1.7, as newer versions (2.0+) have imported FreeBSD's regex implementation that passes Git's tests. The change aligns Makefile behavior with autoconf/meson builds which already use the platform regex library on modern Cygwin.

Key technical details:
- Modifies `config.mak.uname` to conditionally set `NO_REGEX` based on Cygwin version (`1.7.*` pattern match)
- Adds `!CYGWIN` prerequisite to test t7815.12 (NUL character matching) which still fails on Cygwin despite the regex improvements
- Documents historical context: Cygwin's regex was problematic in 1.7 (2013) but fixed by 2.0 (2015)
- Notes test t7815.12 remains an open issue - originally marked `test_expect_failure` in 2010 without clear rationale, and still fails on Cygwin

This continues the series' theme of modernizing platform-specific build logic while maintaining compatibility where needed. The patch cleanly handles the version transition while documenting the remaining test discrepancy, leaving the door open for future investigation of the NUL-matching behavior.
