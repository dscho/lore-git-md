Thread identity: Bug report regarding cloning failures from Azure DevOps with Git for Windows versions 2.44.0 and above, reported by Kitty Chang from Cathay Financial Holdings.

Core problem: Regression where cloning succeeds with Git for Windows 2.30.2 through 2.43 but fails with 2.44.0-rc0 and later versions, showing SSL-related RPC failures (curl 56 OpenSSL SSL_read: SSL_ERROR_SYSCALL, errno 0). Affects both SourceTree and command line usage with Azure DevOps repositories.

Current status: Unresolved regression. brian m. carlson suggests this is likely Windows-specific or related to libcurl versions bundled with Git for Windows, recommending reporting to Git for Windows issue tracker (github.com/git-for-windows/git/issues). Potential relation to issue #4997 noted. Reporter currently needs to stay on older versions (2.30.2-2.43) to maintain functionality.

Key technical details:
- Failure occurs during large transfers (one case shows failure after 2.18 GiB transferred)
- SSL/network layer issue during clone operations
- Specific to Git for Windows builds (not core Git issue per brian m. carlson)
- Affects Azure DevOps repository access
- May relate to libcurl versions bundled with Git for Windows

Open questions:

- Can issue #4997 provide relevant clues to this regression?
- What additional diagnostic information would help (exact versions, network traces)?
