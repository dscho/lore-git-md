Thread identity: Bug report regarding cloning failures from Azure DevOps with Git for Windows versions 2.44.0 and above, reported by Kitty Chang from Cathay Financial Holdings.

Core problem: Regression where cloning succeeds with Git for Windows 2.30.2 through 2.43 but fails with 2.44.0-rc0 and later versions, showing SSL-related RPC failures (curl 56 OpenSSL SSL_read: SSL_ERROR_SYSCALL, errno 0). Affects both SourceTree and command line usage with Azure DevOps repositories.

Current status: Unresolved regression. Reporter currently needs to stay on older versions (2.30.2.43) to maintain functionality. No known workarounds or fixes yet identified for 2.44.0+.

Key technical details:
- Failure occurs during large transfers (one case shows failure after 2.18 GiB transferred)
- SSL/network layer issue during clone operations
- Specific to Git for Windows builds (not yet confirmed if core Git issue or Windows-specific)
- Affects Azure DevOps repository access

Open questions:
- Is this a core issue or Windows build/OpenSSL configuration specific?
- What changed in 2.44.0 that might have introduced this regression?
- Are there workarounds available for newer versions?

Participant positions:
- Kitty Chang (reporter): Provided clear version boundaries and reproduction cases showing the regression

Related work:
- Git for Windows version history (2.30.2-2.43 work, 2.44.0+ fail)
- Azure DevOps repository access patterns
- OpenSSL/network layer changes in recent Git versions
