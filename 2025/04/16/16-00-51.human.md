Bugfix investigation into pathspec behavior expands with command-specific findings.

Junio C Hamano responds to Lucas Seiki Oshiro's discovery that wildcard pathspec handling differs across Git commands. While `git ls-files` and `git grep` correctly expand wildcards like `f*`, commands like `add`, `commit`, and `rm` still prioritize literal matches over expansion - confirming this is not just a pathspec issue but depends on command implementation.

Hamano speculates this divergence may stem from `git add`'s unique need to handle paths not yet in the index, recalling an early design choice to favor exact matches for paths containing glob characters. He suggests there may now be multiple code paths with inconsistent behavior - some updated to modern expectations while older implementations remain unchanged.

This moves the discussion beyond the original `git add` focus toward understanding architectural decisions in pathspec handling across Git's command spectrum. The response implies the fix may need to consider both historical compatibility and modern need for consistent behavior, particularly for commands interacting with the working tree versus the index.
