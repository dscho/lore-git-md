This is a bugfix patch in the build system alignment series, specifically addressing RAM calculation on Cygwin systems. The patch corrects how `git gc` calculates total system memory when using the `sysinfo()` function, which is particularly relevant for Cygwin where memory sizes are reported in units of 4096 bytes rather than single bytes.

The issue stems from Cygwin's `sysinfo()` implementation returning memory sizes in multiples of `mem_unit` (4096 in the example), while the existing code assumed either byte counts or `mem_unit=1`. Ramsay Jones provides clear evidence of the discrepancy through a test program showing an 8GB system reporting 2074637 units that need to be multiplied by 4096 to get the correct total. The fix is straightforward - multiply by `mem_unit` when it's greater than 1 - and maintains compatibility with Linux systems where `mem_unit` remains 1.

The patch is narrowly focused (just 9 lines changed in `builtin/gc.c`) and includes a real-world test case from Cygwin. It fits naturally into the series' broader theme of platform-specific build system improvements, particularly around Cygwin compatibility. The change is low-risk since it only affects memory calculation for `git gc`'s auto-tuning behavior and has been verified to work correctly on both Linux and Cygwin systems.
