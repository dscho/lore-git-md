This is patch 5/7 in Patrick Steinhardt's series hardening integer handling in Git's parse-options infrastructure. It introduces a new `OPTION_UNSIGNED` type to complement the existing signed integer (`OPTION_INTEGER`) and magnitude-with-suffixes (`OPTION_MAGNITUDE`) options.

The patch fills a gap in the parse-options API by providing direct support for unsigned integers without magnitude suffixes. Like the other numeric options in this series, it includes precision handling (supporting 8/16/32/64-bit values), proper error checking for out-of-range values, and explicit rejection of negative numbers. The implementation follows the same pattern as the earlier patches, using `strtoumax()` for parsing with full `errno` handling.

Test coverage verifies the new option type works as expected, including range validation (rejecting values above 65535 for 16-bit) and negative number rejection. The changes touch core parse-options files and add corresponding test cases while maintaining backward compatibility.

This is part of the series' systematic approach to numeric option safety - having addressed signed integers in patch 3 and magnitudes in patch 4, this completes the trio with proper unsigned support. The implementation looks thorough, with clear error messages and comprehensive tests matching the quality seen in previous patches.
