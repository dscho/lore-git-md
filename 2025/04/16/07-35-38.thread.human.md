This thread documents a regression in Git for Windows where cloning from Azure DevOps fails with SSL errors in versions 2.44.0 and above, while working fine in 2.30.2 through 2.43. Kitty Chang from Cathay Financial Holdings reported the issue, noting failures during large transfers (one case failing after 2.18 GiB) with curl 56 OpenSSL SSL_read errors.

brian m. carlson initially responded that this appears to be a Windows-specific issue, likely related to libcurl versions bundled with Git for Windows, and suggested reporting it to the Git for Windows issue tracker. He also noted potential relation to issue #4997.

Johannes Schindelin (Dscho), the Git for Windows maintainer, has now provided a specific workaround suggestion: trying the clone operation with `http.sslbackend=schannel` to switch from OpenSSL to Windows' native Schannel SSL backend. This targeted suggestion could either work around the issue or help confirm it's OpenSSL-specific. The thread remains in troubleshooting mode, with the root cause still unknown but now with a concrete diagnostic path forward. Users currently need to stay on Git for Windows 2.43 or earlier to maintain functionality.
