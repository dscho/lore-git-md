Feature patch in Patrick Steinhardt's reftable API refactoring series (v2 patch 12/16). This exposes a generic iterator interface for reftable records at the block level, building on earlier block API improvements in the series.

The patch introduces `reftable_block_init_iterator()` which creates a `reftable_iterator` that can traverse records within a single block. This is implemented via a new vtable that adapts the existing block iterator operations (`seek`, `next`, `close`) to the generic iterator interface. The implementation includes thorough unit tests verifying iteration works across all record types (refs, logs, objects) and handles edge cases like seeking to non-existent keys.

This change serves two purposes: (1) it provides the building block for an upcoming table-level block iterator (hinted at in the commit message), and (2) enables the fine-grained control needed for future reftable consistency checks. The implementation is clean and well-tested, with the tests demonstrating both happy-path iteration and edge case handling.

As part of the broader series that has already received positive reviews, this patch appears ready for inclusion, continuing the trend of improving reftable's API while maintaining functionality.
