This is a refactoring patch in Patrick Steinhardt's reftable API cleanup series (v2, patch 10/16). The change simplifies the block iterator implementation by storing a direct pointer to the underlying `reftable_block` rather than copying out individual fields. 

The patch eliminates redundant storage of block data (pointer, length, hash size) in the iterator, since these are already available in the block itself. This makes the code more straightforward by removing the needless field duplication and inconsistent naming between the block and iterator structures. The change also better reflects the iterator's natural lifetime dependency on the block it's traversing.

While this is primarily a code organization improvement, it also sets up for future work to decouple the iterator's lifetime from seeking operations. The implementation appears clean and maintains all existing functionality while reducing complexity. This continues the series' pattern of thoughtful API refinements for the reftable backend.
