This is part 3 of Patrick Steinhardt's reftable API refactoring series, focusing on code consolidation and cleanup. The patch moves all block source handling code into a dedicated `reftable/blocksource.[ch]` pair, improving organization and making the functionality easier to locate.

The changes are primarily mechanical:
- Moves functions like `block_source_read_block()` and `block_source_size()` from `table.c` to the new location
- Renames `reftable_block_done()` to the more precise `block_source_return_block()`
- Updates all callers across the codebase to use the new location and names
- Adds proper documentation for the block source API in the header file

The patch is well-contained and follows the series' goal of improving the reftable code structure. Reviewers have already approved the technical approach in previous iterations, with this version incorporating minor naming improvements. The changes are straightforward and maintain existing functionality while making the codebase more maintainable.
