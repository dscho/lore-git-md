This is a technical clarification in Patrick Steinhardt's reftable API refactoring series (patch 10/16). The discussion focuses on a minor wording issue in the commit message for a block iterator optimization.

Patrick responds to Justin Tobler's suggestion to change "into" to "in" in the commit message's description of pointer storage. Patrick maintains that "into" is technically correct as it describes pointers that point *into* the block data structure, not pointers stored *in* the block. He proposes adding "pointing" to make the phrasing clearer: "pointing into" rather than just "into".

The change is purely about documentation clarity for a patch that has received positive technical reviews. The underlying implementation (which replaces copied block data with direct block pointers in the iterator) remains unchanged and has been approved as a simplification that reduces storage and bookkeeping. This exchange represents the final polish on a patch that is otherwise ready for inclusion in the series.
