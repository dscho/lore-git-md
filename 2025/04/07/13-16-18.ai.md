Refactoring patch in Patrick Steinhardt's reftable API series (v2 6/16). This change renames `struct reftable_block` to `struct reftable_block_data` to better reflect its role as a simple data container holding byte slices without access semantics. The rename cascades through the codebase with corresponding updates to function names (`block_source_return_block` → `block_source_release_data`, `read_block` → `read_data` etc.) and field references. This is part of the broader effort to clarify the reftable API's naming and responsibilities, preparing for subsequent changes that will rename `reftable_block_reader` to `reftable_block` in the next patch. The changes are mechanical but improve the distinction between data containers and accessor structures.
