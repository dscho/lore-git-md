API refactoring in the reftable subsystem. This is patch 15/16 in Patrick Steinhardt's series to improve the reftable API for external consumers and enable future verification work.

The patch moves the reftable block type constants (`BLOCK_TYPE_REF`, `BLOCK_TYPE_LOG`, etc.) from an internal header to the new public `reftable-constants.h`. This change is necessary now that the public API allows direct block access, as callers need to distinguish between block types. The implementation updates all internal references to use the new prefixed constant names (`REFTABLE_BLOCK_TYPE_*`).

This is a straightforward mechanical change that completes the API exposure work started earlier in the series. The patch touches nearly every reftable source file to update constant references, but the changes are consistent and well-contained. Test files are updated in parallel to maintain consistency.

The change follows the established pattern in this series of carefully exposing internals needed for verification while maintaining clean API boundaries. With this patch, the structural pieces for block-level access are now complete.
