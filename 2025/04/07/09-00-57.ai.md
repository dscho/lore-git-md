This is an RFC (Request for Comments) proposing a conceptual framework for adding trust and provenance layers to Git, rather than a direct code contribution. The email comes from a digital trust specialist marking Git's 20th anniversary with a thought-provoking proposal about repository integrity.

The Open Integrity Project is presented as a proof-of-concept that builds on Git's existing commit signing and SSH authentication to create structured ways to track repository ownership and key transitions over time. The approach uses shell scripts and Git aliases rather than modifying Git internals, focusing on "inception commits" (asserting initial control) and "trust transition commits" (documenting maintainership changes). Key technical elements include preserving SSH signatures across branch operations and establishing cryptographic chains of custody.

The author explicitly states this isn't a patch submission, instead inviting discussion about whether Git's tooling could better support trust workflows. They provide extensive background materials including a GitHub repository, problem statement document, and example implementation. Open questions include handling signature preservation during merges and awareness of prior art in this space.
