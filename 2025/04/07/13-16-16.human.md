This is a refactoring patch in Patrick Steinhardt's reftable API improvement series, specifically focusing on how restart points are tracked in reftable blocks. 

The patch simplifies the bookkeeping for restart points (which enable binary search within compressed blocks) by eliminating redundant tracking. Previously, the code maintained three separate variables to track restart point locations, but the author realized these could be derived from each other. The key change replaces a pointer to restart data with an offset, allowing removal of the `block_len` field while maintaining the same functionality.

The changes are mechanical but meaningful - they reduce the cognitive overhead of understanding the block structure while making the code more maintainable. The patch touches several files (`block.c`, `block.h`, `table.c`) but follows a clear pattern of replacing pointer arithmetic with offset calculations.

This is part of a well-reviewed series that's now on its second version, with the overall aim of making the reftable API more consistent and usable. The changes here are non-controversial and appear to be a straightforward improvement to the code's internal structure.
