Reftable API refactoring patch exposing block type constants. This is part of Patrick Steinhardt's v2 series to improve the reftable API for external consumers and enable future verification work.

The patch moves the block type constants (`BLOCK_TYPE_REF`, `BLOCK_TYPE_LOG`, etc.) from an internal header to the new public `reftable-constants.h`. This is needed now that the API allows direct block access, as callers need to distinguish between block types. The change is mechanical but wide-ranging, updating all internal references to use the new prefixed constants (`REFTABLE_BLOCK_TYPE_*`).

The implementation:
- Creates new `reftable-constants.h` with prefixed constants
- Updates all internal usage across 14 files (block handling, iterators, writers, tests)
- Maintains identical behavior while making types part of the public contract
- Includes comprehensive test updates to verify the changes

This completes the block-level API exposure started in earlier patches, providing the final pieces needed for external verification tools to inspect reftable files at the block level. The changes are straightforward and maintain compatibility while properly namespacing the constants for public use.
