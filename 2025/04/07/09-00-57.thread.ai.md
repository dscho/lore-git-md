RFC Proposal: Open Integrity Project - Trust and Provenance Layers for Git

This thread introduces a conceptual framework for enhancing repository integrity tracking in Git, proposed by a digital trust specialist. The Open Integrity Project suggests building on Git's existing commit signing and SSH authentication to create structured methods for tracking repository ownership and key transitions over time, without modifying Git internals.

Core proposal establishes two new commit types:
- "Inception commits" assert initial control of a repository
- "Trust transition commits" document maintainership changes

Technical approach uses shell scripts and Git aliases to:
- Preserve SSH signatures across branch operations
- Establish cryptographic chains of custody
- Add metadata layers to existing signing infrastructure

Current status is RFC stage with:
- GitHub repository available for review
- Detailed problem statement document
- Example implementation demonstrating the concept

Key technical considerations raised:
- Signature preservation during merge operations
- Metadata storage strategies
- SSH vs. GPG suitability for trust workflows
- Integration with existing signing practices

Open questions and discussion points:
- Handling of signature preservation in complex operations
- Prior art review in the trust/provenance space
- Potential future directions for Git tooling support
- Community interest in standardizing such approaches

The proposal explicitly avoids immediate code changes to Git itself, instead inviting discussion about whether and how Git's tooling could better support trust workflows. Future emails may address implementation details, alternative approaches, or community reception of the concept.
