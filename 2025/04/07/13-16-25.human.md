This is a refactoring patch in Patrick Steinhardt's reftable API series, moving internal implementation details into the public interface to support upcoming consistency checks. 

The patch relocates the `reftable_table` structure definition from an internal header to the public "reftable-table.h" file. This structure contains metadata about the reftable file including block sizes, hash types, and offset information for different record types (refs, objects, logs). The change is motivated by the need for external access in a future series that will implement reftable backend verification.

As part of a well-reviewed v2 series that has already addressed feedback, this patch appears straightforward and mechanically sound. It maintains all existing functionality while exposing the necessary internals for upcoming work. The commit message clearly explains the change's purpose without introducing new behavior or complexity.
