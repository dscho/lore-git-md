Refactoring of reftable block iterators to support reseeking.

This patch (11/16 in Patrick Steinhardt's reftable API refactoring series) separates block iterator initialization from seeking operations. The key change stores the block pointer during initialization rather than passing it with each seek operation, making the iterator reseekable by design. This is achieved by:

1. Introducing `block_iter_init()` to store the block reference
2. Modifying `block_iter_seek_start()` and `block_iter_seek_key()` to operate on pre-initialized iterators
3. Updating all callers to use the new initialization pattern
4. Adjusting unit tests to match the new API

The changes maintain all existing functionality while enabling cleaner reseeking behavior, which will be useful for the upcoming `reftable_iterator` interface for blocks mentioned in the commit message. The patch follows the series' pattern of improving API clarity and usability while preparing for future verification work. All test cases are updated to verify the new behavior works correctly across different block types (ref, log, obj, index).
