This is part 6/16 of Patrick Steinhardt's reftable API refactoring series, focused on improving naming clarity in the block handling code. The patch renames `struct reftable_block` to `struct reftable_block_data` to better reflect that this structure only holds raw block contents without any access logic. 

The change is mechanical but meaningful - it clarifies the separation between data storage (`reftable_block_data`) and access logic (which will be renamed to `reftable_block` in the next patch). The rename cascades through the codebase, updating all related function names (`block_source_return_block` → `block_source_release_data`, `read_block` → `read_data`, etc.) and their callers.

This continues the series' pattern of improving API design for better standalone usability by external projects. The changes are straightforward and well-contained, with thorough updates to all affected test cases. As with previous patches in the series, this appears to be a thoughtful refinement rather than a functional change.
