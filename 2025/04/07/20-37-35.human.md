This is a maintainer response in the ongoing discussion about git-interpret-trailers' handling of trailer keys with periods.

Junio Hamano weighs in on Christian Couder's earlier summary, strongly agreeing that maintaining strict parsing rules for trailer keys is the right approach. He expresses concern that even the existing special case for #BUGID syntax may have been a mistake, as it deviates from the email-header-like format that trailers were originally designed to follow. 

The response clearly signals that the project will not be adding configurability for more lenient parsing of trailer keys, seeing this as potentially harmful to the ecosystem. Instead, the path forward will focus on improving documentation to make the current restrictions clearer. This effectively closes the door on implementing configurable leniency while leaving room for documentation patches.

The exchange shows the maintainers prioritizing parser reliability and consistency over accommodating edge cases, even when those use cases are valid (like version tracking in kernel development). The decision reflects a conservative approach to changes that might increase false positives in trailer parsing.
