Feature/RFC patch for preserving extra commit headers during rebase.

This patch from Phillip Wood proposes partial support for preserving extra commit headers (like those added by tools such as GitButler) during `git rebase -m` operations. The current implementation only works for conflict-free rebases, as the sequencer uses `commit_tree_extended()` in these cases rather than forking `git commit`. The patch explicitly excludes GPG signature headers from being copied.

The changes modify the sequencer to pass through extra headers when creating new commits, with test coverage added to verify header preservation across different rebase operations (pick, fixup, reword, edit, squash). The author acknowledges this is an incomplete solution - merge conflicts still lose headers, and cherry-pick operations aren't addressed - but argues it's still valuable for server-side operations where conflicts are typically rejected anyway.

The implementation touches core sequencer logic in `sequencer.c`, adding new parameters to propagate headers through the commit creation process. The test file `t3404` gets a new test case that verifies header preservation through various rebase operations. The author notes this is in response to prior discussion about header preservation and positions it as a stepping stone until `git replay` (which already preserves headers) sees wider adoption.
