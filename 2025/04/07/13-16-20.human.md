Refactoring patch in Patrick Steinhardt's reftable API series (8/16). This change standardizes the codebase to use `struct z_stream_s` instead of the typedef `z_stream` for zlib compatibility. The motivation comes from upcoming work to expose `struct reftable_block` publicly - since public headers shouldn't depend on internal implementation details like "reftable/system.h", we need to use the actual type name rather than the typedef.

The patch makes mechanical changes across several files:
- Updates variable declarations in documentation examples
- Modifies the zlib-ng compatibility layer to map `z_stream_s` instead of `z_stream`
- Changes the `git_zstream` struct to use the explicit type
- Updates reftable block handling code to use `struct z_stream_s` pointers

This is a straightforward change that improves header independence while maintaining identical functionality. It's part of the larger effort to make the reftable API more suitable for external consumption. The patch follows the series' pattern of careful, mechanical refactoring with clear justification.
