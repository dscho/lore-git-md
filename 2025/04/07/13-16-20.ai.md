Refactoring patch in the reftable API series, focusing on zlib compatibility. This patch changes the codebase to use `struct z_stream_s` directly instead of the `z_stream` typedef, preparing for future public exposure of `struct reftable_block` which contains a zlib stream pointer. The change ensures headers won't need to pull in internal implementation details when the reftable API becomes public.

Key technical changes:
- Replaces all `z_stream` typedef usage with explicit `struct z_stream_s`
- Updates zlib-ng compatibility layer to map `z_stream_s` to `zng_stream_s`
- Removes unnecessary forward declaration of `struct z_stream` from reftable/block.h
- Updates documentation example code to match new style
- Affects git-zlib.h internals and reftable block writing/reading components

The change is mechanical but important for API hygiene, continuing the series' pattern of improving header dependencies and forward-declarability. It maintains all existing functionality while better supporting the planned public exposure of reftable structures. The patch fits cleanly into the broader reftable refactoring effort by addressing a technical dependency that would otherwise complicate later patches.
