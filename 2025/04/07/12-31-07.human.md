This is a refactoring patch in Patrick Steinhardt's reftable API series, specifically addressing how restart points are tracked in reftable blocks. The patch simplifies the code by eliminating redundant tracking of block length and consolidating restart point information into a single offset value.

The change removes the `block_len` variable since its information can be derived from the restart offset (`restart_off`), which is renamed from `restart_bytes` to better reflect its purpose. This reduces bookkeeping while maintaining the same functionality. The patch touches three files with mostly straightforward mechanical changes.

Karthik Nayak raised two minor points in review: clarifying that both variables aren't being removed (just `block_len`), and suggesting `header_offset` would be clearer than `header_off`. Patrick agrees with the latter point but prefers keeping the abbreviated form for consistency with existing code.

This is part of a larger, well-reviewed series (now at v1) that's improving the reftable API for both Git and external consumers. The change appears clean and focused, with all technical aspects already approved by reviewers.
