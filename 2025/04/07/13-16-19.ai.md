Refactoring patch in Patrick Steinhardt's reftable API series, renaming internal structures for consistency. This is patch 7/16 in v2 of the polishing series.

The change renames `struct block_reader` to `struct reftable_block` to better reflect its role as the primary access structure for reftable blocks, following the naming pattern established by other structures like `reftable_table`. The commit explains this will be useful for external users implementing consistency checks that need direct block access, though the public interface exposure is deferred to a later patch.

The mechanical changes are extensive but straightforward - all `block_reader` references become `reftable_block`, with corresponding function renames (`block_reader_init` → `reftable_block_init`, etc.). The patch updates all callers across the codebase including tests, maintaining identical functionality while improving naming consistency. This continues the series' pattern of structural renames that clarify the distinction between data containers and accessor structures.

The changes appear well-contained and maintain existing behavior, with test coverage verifying the renamed functions work identically. This is part of the broader effort to make the reftable API more consistent and usable by external projects like libgit2.
