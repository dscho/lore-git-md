This is part of Patrick Steinhardt's reftable API refactoring series (patch 14/16), introducing a new block iterator interface for the reftable backend. The patch adds a public `reftable_table_iterator` that allows callers to examine individual blocks within a reftable, exposing previously internal implementation details.

The new iterator provides three key operations: initialization, iteration (`next`), and cleanup. This low-level access will be used by upcoming consistency checks for the reftable backend and will also replace the existing `reftable_table_print_blocks()` implementation. The patch includes comprehensive unit tests that verify the iterator works correctly across different block types (ref, index, and object blocks) with specific validation of block headers, restart counts, and record counts.

This change fits into the series' broader goals of improving the reftable API for external consumers while enabling new verification capabilities. The implementation appears clean and well-tested, with the tests covering both happy paths and edge cases. As with previous patches in this mature series, the change is technically sound and moves the reftable implementation toward its final architectural shape.
