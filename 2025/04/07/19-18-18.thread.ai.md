[GSoC proposal] git metadata: machine-readable repository information query tool by Lucas Oshiro. Proposal for a new `git metadata` command to output structured repository information in JSON format, consolidating functionality currently spread across `git rev-parse` flags. Key metadata to include: object format, Git directory paths, ref storage type, superproject status, and repository type (bare/shallow). Goals: provide tool-friendly interface while reducing `rev-parse` scope creep, following pattern of `git switch`/`git restore` split from `git checkout`. Implementation plan involves new `builtin/metadata.c` and `json.c` files, with work divided between data gathering (using existing Git internals) and JSON serialization (careful schema design needed). Author Lucas Oshiro has prior documentation contributions and small code patches to Git, demonstrates familiarity with codebase through specific internal function references, and shows awareness of community process with plans for iterative feedback on schema/CLI design. Project schedule structured with requirements gathering, community bonding, and four coding phases (CLI design, JSON serialization, test coverage, documentation).
