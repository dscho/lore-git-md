This is a refactoring patch in Patrick Steinhardt's reftable API refactoring series (v2, patch 13/16). The change moves the `reftable_table` structure definition from an internal header to the public-facing `reftable-table.h`, making it as part of the public API.

The key technical details are:
- The entire `struct reftable_table` definition is relocated, including all fields (name, block source, size parameters, hash ID, offsets for ref/obj/log sections)
- A new `struct reftable_table_offsets` is also moved to the public header
- The change enables future work on reftable backend consistency checks that will need direct access to this structure
- The patch maintains all existing functionality while exposing the previously internal details

This is a straightforward mechanical change that completes the API exposure work started earlier in the series. It follows the pattern seen in previous patches of moving implementation details to public headers to support external consumers like libgit2 and future verification tools. The patch appears cleanly implemented with no behavior changes beyond the intended visibility modification.
