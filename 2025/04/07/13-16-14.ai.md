This is a refactoring patch in Patrick Steinhardt's reftable API series (v2, patch 2/16). The change renames `struct reftable_reader` to `struct reftable_table` to better reflect its purpose of handling individual reftable files rather than just reading them. The commit explains that the old name was unclear about what the structure actually represents, while the new name aligns with other structures in the codebase like `reftable_merged_table` and `reftable_stack`.

The patch makes extensive mechanical changes across the codebase to update all references to the renamed structure and its associated APIs. Key changes include:
- Renaming `reader.c` to `table.c` and updating all function names from `reader_*` to `table_*`
- Updating struct field names from `readers` to `tables` where appropriate
- Modifying test files to use the new naming scheme
- Preserving all existing functionality while making the API naming more consistent

This change is part of a larger effort to improve the reftable library's standalone usability for external projects like libgit2. The patch appears well-contained and focused purely on the naming change, with no functional modifications. It follows the pattern established by earlier patches in the series that standardize naming conventions across the reftable codebase.
