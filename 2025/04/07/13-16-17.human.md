Refactoring patch in Patrick Steinhardt's reftable API cleanup (part 5/16). This change clarifies ownership and responsibility for block reading in the reftable implementation.

The patch moves block reading logic entirely into the block reader subsystem, eliminating awkward block ownership transfers between the table and block subsystems. Instead of passing around block ownership, the block reader now takes a block source and offset, managing the block itself from initialization. This makes the code clearer and reduces error-prone ownership handoffs.

The changes affect several key files:
- `reftable/block.c` gains a new `read_block()` helper and refactors `block_reader_init()`
- `reftable/table.c` simplifies significantly by removing its block reading logic
- Unit tests are updated to use the new initialization pattern

This is part of a larger series improving the reftable API's clarity and standalone usability. The implementation appears clean and maintains all functionality while making the code more maintainable. Reviewers have already given positive feedback on earlier versions of this series.
