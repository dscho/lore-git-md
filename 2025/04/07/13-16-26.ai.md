This is part of Patrick Steinhardt's reftable API refactoring series (v2 patch 14/16), introducing a new block iteration interface for the reftable backend. The patch adds a `reftable_table_iterator` that provides direct access to individual blocks within a reftable, exposing previously internal implementation details.

The new iterator interface consists of three main functions: `reftable_table_iterator_init()` to start iteration, `reftable_table_iterator_next()` to advance through blocks, and `reftable_table_iterator_release()` for cleanup. Each iteration step returns a pointer to a `reftable_block` structure containing the block's type, header offset, restart count, and other metadata.

The implementation includes comprehensive unit tests in `t-reftable-table.c` that verify the iterator works correctly across different block types (ref, index, and obj blocks). The test creates a sample reftable with 500 ref records, then verifies the iterator correctly traverses all blocks and reports their metadata. The test also cross-validates the block contents by using the new iterator in conjunction with the existing record-level iterator.

This change serves two purposes: it enables future consistency checks for the reftable backend (mentioned as coming in a follow-up series), and it will allow reimplementing the debug-oriented `reftable_table_print_blocks()` function. The patch maintains the series' pattern of careful API exposure while adding necessary testing coverage.
