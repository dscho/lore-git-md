Refactoring in Patrick Steinhardt's reftable API series (patch 11/16). This change makes block iterators reseekable by separating initialization from seeking operations.

The patch modifies the block iterator interface to store the block pointer during initialization rather than during seeking. This allows the same iterator to be reused for multiple seek operations without reinitializing, which will be useful for exposing a public block iterator interface in a later patch. The key changes are:
- New `block_iter_init()` function that takes the block pointer
- Modified `block_iter_seek_*` functions that operate on an already-initialized iterator
- Updated callsites throughout the reftable codebase
- Adjusted unit tests to use the new API

This is part of a larger effort to improve the reftable implementation's standalone usability and prepare for future verification work. The change maintains all existing functionality while making the API more flexible. The implementation looks clean and well-tested, with all affected callers updated appropriately. This continues the series that has already received positive reviews from other contributors.
