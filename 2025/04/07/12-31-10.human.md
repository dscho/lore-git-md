This is a technical clarification in Patrick Steinhardt's reftable API refactoring series (now at 16 patches). The email responds to Justin Tobler's question about block size handling in the reftable format.

Patrick explains there are two modes for reftable blocks: aligned (the default) and unaligned. Aligned blocks use padding to match disk sector sizes (4KB by default in Git) and track their size in the footer. Unaligned blocks omit padding and indicate this with a block size of 0 in the header/trailer, requiring the code to fall back to a default size guess.

The exchange is part of Patch 5/16, which moves block handling into a dedicated block reader. This is part of a larger effort to improve reftable's API for external consumers and enable future verification features.
