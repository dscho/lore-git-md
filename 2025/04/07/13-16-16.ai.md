This is a refactoring patch in Patrick Steinhardt's reftable API improvement series, specifically focusing on how restart points are tracked in reftable blocks. The patch simplifies the internal bookkeeping by eliminating redundant tracking of block length and restart point locations.

The key change replaces three separate variables (`block_len`, `restart_count`, and `restart_bytes`) with a more streamlined approach using just `restart_count` and `restart_off`. The commit explains that these values were derivable from each other, making the previous tracking redundant. The new `restart_off` field now serves as the single source of truth for the offset where restart points begin in the block.

The implementation touches core block reading functionality in `reftable/block.c`, updating all affected functions to use the new scheme. The changes are mechanical but thorough, updating block iteration, seeking, and printing logic. The patch maintains all existing functionality while reducing internal complexity.
