This is a refactoring patch in Patrick Steinhardt's reftable API series, specifically focusing on the block iterator implementation. The change simplifies the block iterator by storing a direct pointer to the underlying `reftable_block` rather than copying individual fields (block data pointer, length, and hash size) into separate iterator members.

The patch eliminates redundant storage and bookkeeping while making the relationship between iterators and blocks more explicit. The key changes are:
1. Replaces three iterator fields (`block`, `block_len`, `hash_size`) with a single `block` pointer to the full `reftable_block` structure
2. Updates all iterator operations to access block data through this pointer
3. Maintains the same functionality while reducing memory usage and improving code clarity

This change also sets up for future work to decouple the iterator's lifetime from seeking operations, as noted in the commit message. The implementation appears clean and well-motivated, with thorough updates to all iterator operations and no behavioral changes. This continues the series' pattern of improving the reftable implementation's clarity and maintainability.
