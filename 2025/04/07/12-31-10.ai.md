This is a technical clarification in Patrick Steinhardt's reftable API refactoring series (patch 5/16). The email explains when reftable blocks might not have a known size, addressing Justin Tobler's question about the `DEFAULT_BLOCK_SIZE` fallback in the block reader initialization.

The key technical points are:
- Normally reftable blocks are padded and aligned (default 4KB in Git), with size tracked in the footer
- An alternative "unaligned" mode exists where padding is omitted, indicated by block size 0 in header/trailer
- The `DEFAULT_BLOCK_SIZE` fallback handles this unaligned case when initializing the block reader

This is part of the larger effort to improve reftable's standalone usability and prepare for future verification features. The exchange shows active review engagement, with Patrick providing clear technical explanations to reviewer questions. The implementation remains unchanged from the original patch - this is purely an explanatory follow-up to aid understanding of the design choices.
