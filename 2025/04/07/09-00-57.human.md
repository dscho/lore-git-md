This is an RFC (Request for Comments) proposing a conceptual framework for adding trust and provenance layers to Git, rather than a direct code contribution. Christopher Allen, a digital trust architect with standards background, introduces the Open Integrity Project - an experimental approach to track repository ownership and maintainer transitions using Git's existing signing capabilities (commit signing and SSH auth) without modifying Git itself.

The proposal centers around two key concepts: "inception commits" to cryptographically establish original control, and "trust transition commits" to document maintainership changes. The current implementation is purely script-based (shell scripts and Git aliases), deliberately not requiring any Git modifications. The author provides links to detailed problem statements, a proof-of-concept GitHub repository, and example commits.

This appears to be an early-stage proposal seeking community feedback rather than proposing specific Git changes. The author specifically asks about: 1) whether the problem space is worth discussing, (2) potential improvements to Git's trust workflow support, and (3) pointers to related past discussions. The technical approach seems carefully considered to work within Git's current capabilities while addressing long-term repository trust challenges. Given the author's standards background and the non-invasive implementation approach, this could spark interesting discussion about Git's role in trust and provenance systems.
