Test improvement patch modifying Perforce integration tests to better capture command exit codes. This is the first of three patches in a v2 submission that follows up on review feedback from Patrick Steinhardt.

The patch addresses a common test pattern where piping `git tag` output to `grep` would mask the exit code of the `git tag` command. The changes replace these pipe chains with temporary file redirection, writing the tag output to a file first before grepping it. This ensures test failures will properly propagate the exit code of the original Git command rather than just the grep result.

Two test cases are modified:
1. The 'two labels on same changelist' test now checks tags via a single `git tag >output` followed by multiple greps
2. The 'git config for tag import/export' test similarly redirects output before grepping

The changes are mechanical but important for test reliability, following Git's test writing guidelines about proper exit code handling. This version incorporates v1 review feedback about standardizing grep usage patterns (-q where output isn't needed) while maintaining the core approach of avoiding pipes in test assertions. The patch is focused and well-contained, touching only the test file with 6 insertions and 4 deletions.
