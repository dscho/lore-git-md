This is a refactoring patch in Patrick Steinhardt's reftable API series, specifically addressing naming consistency. The patch renames `struct block_reader` to `struct reftable_block` and updates all related functions to match this new naming scheme. 

The change follows Justin Tobler's earlier suggestion about field naming, though Patrick notes that using "data" would have created awkward nested references (`block->data.data`). Instead, he settles on `block_data` as a clearer alternative. 

This is part of the broader effort to improve the reftable API's usability for external projects by making type names more consistent and self-documenting. The change is purely mechanical - no behavior is altered - and fits naturally with the series' progression of API cleanups. Justin Tobler had previously reviewed and approved the general direction of these naming changes.
