This is part of Patrick Steinhardt's reftable API refactoring series (v2), specifically exposing lower-level block iteration capabilities. The patch introduces a generic iterator interface for reftable records within individual blocks, making it part of the public API.

The key technical changes include:
- Adds `reftable_block_init_iterator()` to create an iterator from a block
- Implements the iterator vtable with `seek`, `next`, and `close` operations
- Handles all reftable record types (ref, log, obj) through the generic interface
- Includes comprehensive unit tests verifying iteration across 20 sample refs
- Tests seek behavior for both existing and non-existent keys
- Maintains compatibility with existing block iteration while exposing new functionality

The implementation builds on previous block iterator improvements in the series (Patches 10-11) and prepares for upcoming table-level iteration. The exposed functionality will be used for reftable backend consistency checks requiring fine-grained data access. The patch follows the series' pattern of careful refactoring with thorough test coverage, maintaining all existing behavior while extending capabilities.
