This is a feature patch proposing partial support for preserving extra commit headers during rebase operations. Phillip Wood addresses a limitation where tools like GitButler lose custom commit headers when users run `git rebase`. The patch only handles the conflict-free case, as preserving headers during conflicted rebases would require more extensive changes.

The implementation modifies the sequencer to copy extra headers (excluding GPG signatures) when creating new commits during an interactive rebase. The patch includes tests verifying header preservation across various rebase operations like pick, reword, edit, and squash. Notably, it doesn't yet handle cherry-pick operations or conflicted rebases.

The author acknowledges this is an incomplete solution but argues it's still valuable for server-side forges that typically reject conflicted rebases anyway. The patch appears well-constructed with thorough test coverage, though marked as RFC since the approach of partial support may be controversial. It builds on prior discussion about preserving commit metadata during history rewriting operations.
