This is a clarification in the reftable API refactoring series (Patch 4/16) regarding tracking restart points in reftable blocks. The patch originally aimed to simplify how restart points (used for binary search in blocks) are tracked by eliminating redundant variables, specifically removing `block_len` while keeping `restart_bytes` (renamed to `restart_off`).

Karthik Nayak pointed out that the commit message was slightly misleading, making it seem like both `block_len` and `restart_bytes` would be removed when in fact only `block_len` is being dropped. Patrick Steinhardt clarifies that `restart_bytes` is retained but renamed to `restart_off` to better reflect its purpose as an offset rather than a pointer. He also addresses a minor style nit about variable naming (`restart_off` vs `restart_offset`), opting to keep the abbreviated form for consistency with existing code (`header_off`).

The technical change itself remains sound, with the refactoring reducing bookkeeping by deriving the block length from the restart offset rather than tracking it separately. This is part of the broader effort to clean up and standardize the reftable API for better external usability.
