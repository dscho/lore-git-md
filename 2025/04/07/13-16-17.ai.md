Refactoring of reftable block reading responsibilities (Patch 5/16 in v2 series).

This patch centralizes block reading logic in the block subsystem by moving responsibility for reading from the table layer to the block reader. Previously, the table layer would read blocks and pass ownership to the block reader, creating awkward handoffs. The new approach has the block reader directly read from the block source using an offset, maintaining ownership throughout.

Key changes:
- Introduces new `read_block()` helper in block.c to handle block reading
- Modifies `block_reader_init()` to take block source + offset instead of pre-read block
- Simplifies table.c by removing its block reading functions
-table_get_block()` and `extract_block_size()`
- Updates all test cases to use new initialization pattern
- Adds proper cleanup in error paths via `block_reader_release()`

The change improves separation of concerns while making ownership patterns clearer. The patch follows naturally from the earlier block source consolidation (Patch 3) and sets up for subsequent optimizations in the block iterator interface. Review feedback from v1 has been incorporated, making this a mature technical refinement in the overall reftable API improvement effort.
