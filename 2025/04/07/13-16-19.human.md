This is part 7/16 of Patrick Steinhardt's reftable API refactoring series, focusing on naming improvements for better standalone usability. The patch renames `struct block_reader` to `struct reftable_block` to better reflect its purpose as the structure providing access to parsed reftable block data.

The change follows the naming pattern established earlier in the series (like `reftable_table`) and prepares for exposing this functionality in the public API in a subsequent commit. The commit explains that while currently internal, this structure's block access capabilities would be useful for external users implementing consistency checks.

The patch makes mechanical changes across the codebase to update all references to the renamed structure and its associated functions (e.g., `block_reader_init` → `reftable_block_init`). Test files are updated accordingly. This continues the series' pattern of improving API clarity while maintaining all existing functionality.

As with previous patches in this well-reviewed series, the changes are straightforward and maintain technical correctness while improving the codebase's long-term maintainability and usability. The series has already addressed reviewer feedback from Justin Tobler and Karthik Nayak in this v2 submission.
