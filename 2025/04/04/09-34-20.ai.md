This is a technical discussion about change-ID implementation approaches in Git, specifically addressing Nico Williams' refs-based proposal.

Patrick Steinhardt argues against using Git refs (`refs/change-IDs/<change-ID>`) for tracking change IDs, citing two key mismatches: First, refs are mutable by users while change IDs should remain stable. Second, refs can only point to a single commit, whereas change IDs may not be unique (multiple commits could share the same change ID). 

He suggests instead using an auxiliary data structure for caching change ID information, mentioning two possible implementations: integrating this into commit graphs or creating a separate change-ID-specific index.
