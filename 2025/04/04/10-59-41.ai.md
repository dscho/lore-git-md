Bugfix for UTF-8 comparison issue in packed-ref iterator, part of the performance optimization series for refs subsystem.

This email contains a fix for a bug discovered in patch 14/16 of the refs optimization series, where UTF-8 character handling in the packed-ref iterator was causing a BUG() when processing refnames containing Unicode characters (like emojis). The issue occurs because the comparison in `packed_ref_iterator_advance()` was using signed char comparison, while `cmp_packed_refname()` uses unsigned char casts, leading to mismatches for bytes with the high bit set (values >127).

The fix aligns the comparison behavior between these two functions by using unsigned char casts in the iterator. Patrick Steinhardt has provided a test case demonstrating the issue with a Unicode refname (U+E3FF) and a prefix search. The fix maintains all the performance optimizations from previous versions of the series (1.25x reftable speedup, 1.58x prefix verification improvement).

This is a follow-up to Elijah Newren's report of the bug triggering during a `git pull` operation in a repository with Unicode refnames. The fix is being sent for verification before being incorporated into the main series. The thread shows ongoing discussion about whether to add expanded Unicode test coverage, though this particular fix appears to address the immediate issue.
