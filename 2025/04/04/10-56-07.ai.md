This is a bugfix patch addressing an issue with performance test environment variables. The change affects the `t/perf/perf-lib.sh` script in Git's test infrastructure.

The patch fixes a regression where `GIT_PERF_*` environment variables set at runtime were being overridden by values from `GIT-BUILD-OPTIONS` that were recorded during compilation. This became problematic after commit 4638e8806e3a changed the behavior to always write these variables to `GIT-BUILD-OPTIONS`, even when empty. The fix preserves runtime `GIT_PERF_*` settings by stashing them before sourcing `test-lib.sh` and restoring them afterward using `eval`.

The technical solution involves:
1. Capturing all `GIT_PERF_*` environment variables before they get overwritten
2. Escaping single quotes in the values to make them eval-safe
3. Restoring the variables after `test-lib.sh` is sourced

The commit message notes this is likely just the first of several similar fixes needed for `GIT_TEST_*` variables, but focuses specifically on the performance test case due to time constraints. The change is well-motivated with a practical example of how users typically override these settings when benchmarking large repositories.
