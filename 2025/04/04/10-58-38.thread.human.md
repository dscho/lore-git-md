This thread addresses a bug in Git's packed-refs backend that causes a crash when handling repositories containing refs with Unicode characters (like emojis) in their names. The issue was introduced in commit 22600c04529, which added seeking capability for packed-ref iterators but incorrectly compared refnames using signed character pointers, leading to incorrect comparisons for UTF-8 characters (where bytes have the high bit set).

The fix, proposed in this patch, mirrors the correct approach already used in `cmp_packed_refname()` by explicitly comparing unsigned character values. The change is minimal (just two lines modified) but important for users working with Unicode refnames. The patch includes a new test case that creates a repository with a Unicode-named ref ("") and verifies proper iteration over packed refs, demonstrating the specific failure scenario where such refs would previously trigger a BUG() when compared against ASCII refnames.

The solution appears well-constructed with a clear commit message tracing the issue to its root cause and providing reproduction steps. The test case directly exercises the problematic code path and confirms the correction works as intended. This should prevent crashes for users dealing with repositories containing Unicode refnames.
