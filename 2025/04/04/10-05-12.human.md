Bugfix for UTF-8 comparison in packed-ref iterator. This is a follow-up to Patrick Steinhardt's performance optimization series for the refs subsystem, specifically addressing a critical regression in patch 14/16 that was discovered by Elijah Newren.

The issue occurs when handling Unicode refnames (like emoji branch names) during operations like `git pull`. The current implementation incorrectly compares UTF-8 characters as signed chars, causing a BUG() when encountering bytes with the high bit set (common in Unicode). Patrick has reproduced the issue and proposes a simple fix - casting to unsigned char before comparison to match how refnames are sorted elsewhere in the code.

The proposed change is minimal and focused, just modifying the comparison in `packed_ref_iterator_advance()`. While this fixes the immediate issue, there's ongoing discussion about whether to add more comprehensive Unicode test coverage (including emoji cases) to prevent similar issues. The fix doesn't affect the performance improvements from the original optimization series, which remain valid.

Patrick is asking Elijah to verify the fix works in his real-world scenario before submitting a formal patch. This appears to be a straightforward and necessary correction to make the refs iterator properly handle Unicode refnames while maintaining the series' performance gains.
