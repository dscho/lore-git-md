This is a bugfix addressing a UTF-8 handling issue in the packed-refs backend. The patch fixes a BUG() that triggers when fetching from repositories containing branch names with Unicode characters (like emojis), where the comparison of refnames incorrectly treats high-bit UTF-8 bytes as negative values.

The issue was reported by Elijah Newren and bisected to a recent change (22600c04529) that implemented seeking for packed-ref iterators. The bug manifests when comparing refnames containing Unicode characters (like the "shaved ice" emoji) against ASCII prefixes, causing the comparison to fail due to signed character handling. The fix mirrors the correct unsigned comparison already used elsewhere in the codebase.

The patch includes both the code fix and a new test case that verifies the packed-refs backend can properly handle refs with Unicode characters. The solution is straightforward - casting characters to unsigned before comparison - and the test coverage gives confidence in the fix. This appears to be a well-constructed patch addressing a real-world issue that could affect users with Unicode branch names.
