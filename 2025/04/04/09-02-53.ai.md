This is a bugfix series addressing zlib corner cases in Git's loose object handling. Jeff King's `jk/zlib-inflate-fixes` series (10 commits) improves error handling and correctness when dealing with malformed zlib-compressed objects. The changes touch core inflation logic in `unpack_loose_rest()` and related functions, fixing issues like infinite loops on bad input and cleaning up status code handling.

The series has been marked as "ready for next" after discussion, though Jeff notes two broader context points: (1) some cleanup ideas for `cat-file` were deemed out of scope for this series, and (2) there's potential future work to drop support for non-standard headers entirely (which would make some of these fixes obsolete) but that would be a backwards-incompatible change requiring separate consideration. 

Key technical changes include: fixing infinite loops on broken zlib input, properly handling headers without NUL terminators, simplifying zstream cleanup, and adding a BUG() for unknown object types during inflation. The work focuses on the zlib interaction layer in `git-compat-util.h` and loose object handling paths, with careful attention to error propagation and resource management.

This appears to be a well-reasoned series addressing real edge cases in object handling, now ready for integration while leaving room for future simplification of the zlib interface. The changes are narrowly focused on correctness rather than performance, with clean commit messages documenting each improvement.
