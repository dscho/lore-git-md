Patrick Steinhardt weighs in on how Git could handle ambiguous change-IDs by extending its existing ambiguous hash resolution mechanism. He suggests modeling change-ID ambiguity after how Git currently handles short object IDs - when multiple matches exist, Git would show an error listing the candidate commits with their metadata (date, subject) to help disambiguation.

The proposal aligns with Martin von Zweigbergk's clarification about Jujutsu's behavior (throwing errors when commands can't handle multiple matches) and Elijah Newren's earlier suggestion to treat change-IDs like abbreviated hashes. Patrick provides a concrete example of how this might look in Git's output format, showing it would be a natural extension of existing behavior.

This represents a practical step forward in the broader discussion about change-ID standardization, focusing specifically on the user experience when dealing with non-unique identifiers.
