This is a bugfix series addressing zlib corner cases in Git's loose object handling.

Jeff King's zlib-inflate-fixes series (10 commits) improves error handling and correctness when dealing with malformed zlib-compressed loose objects. The changes include fixing an infinite loop on bad input, better header validation, and cleanup of zstream handling. The series has been under discussion since February but appears to have reached consensus, with King now recommending it for inclusion in 'next'.

While these fixes are ready to merge, King notes there's a larger discussion about completely removing support for non-standard headers - a backward-incompatible change that would make some of these fixes obsolete. However, he argues these improvements are still worth merging in the interim since the bigger change would take more time and discussion.

The series touches core object storage code (unpack_loose_header() and related zlib handling), with each commit carefully isolating specific improvements to error cases and code clarity. The changes appear well-reasoned and focused on edge cases that could lead to crashes or infinite loops when processing corrupted repositories.
