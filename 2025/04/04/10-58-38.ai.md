Bugfix for packed-refs backend handling UTF-8 characters. This patch addresses a crash that occurs when fetching from repositories containing refs with Unicode characters (like emojis) in their names. The issue manifests as a BUG() when comparing refnames with signed character pointers, causing incorrect comparisons for bytes with the high bit set (like UTF-8 characters).

The problem stems from commit 22600c04529 which introduced seeking for packed-ref iterators. The comparison logic in `packed_ref_iterator_advance()` fails to properly handle UTF-8 characters because it treats bytes as signed values. The fix mirrors the approach used in `cmp_packed_refname()` by explicitly comparing unsigned character values.

The patch includes a new test case that verifies the fix by creating a repository with a Unicode-named ref ("") and ensuring proper iteration over packed refs. The test demonstrates the specific failure scenario where a ref with a high-byte Unicode character would previously trigger the BUG() when compared against an ASCII refname ("z").

This appears to be a well-constructed fix with clear commit message tracing the issue to its root cause and providing reproduction steps. The test case directly exercises the problematic code path and verifies the correction. The change is minimal (just 2 lines modified) but impactful for users dealing with Unicode refnames.
