This is a bugfix for Git's performance testing infrastructure. The patch addresses an issue where `GIT_PERF_*` environment variables couldn't be overridden at runtime if they were set (even to empty values) during build time. This became problematic after a Makefile change in December 2024 that started writing these variables to `GIT-BUILD-OPTIONS` unconditionally.

The fix works by stashing any runtime `GIT_PERF_*` environment variables before `test-lib.sh` sources `GIT-BUILD-OPTIONS`, then restoring them afterward. This restores the expected behavior where developers can specify performance test parameters like `GIT_PERF_LARGE_REPO` when running tests, which is particularly useful for benchmarking against large repositories.

The patch is narrowly focused on `GIT_PERF_*` variables, though the commit message notes there may be similar issues with `GIT_TEST_*` variables that could be addressed separately. The change is well-motivated and clearly demonstrates the problem was introduced by a specific commit (4638e8806e3a making the fix easy to verify. The implementation uses careful shell scripting to properly handle variable values containing special characters.
