1. Preserving change IDs by default in both rebase and cherry-pick is essential for backport/forward-port workflows (citing OpenSSL, PostgreSQL, and Illumos as examples)

3. Change IDs should function as lineage markers rather than strictly unique identifiers
4. Real-world maintenance scenarios (security fixes, package maintenance) require duplicate change IDs across branches
5. Git's unified --abort/--continue/--skip interface across commands is a positive example of reducing cognitive load

Nico provides concrete examples of cherry-pick use cases that would break with Jujutsu's current model:

- Cross-upstream commit integration

- Research branch maintenance
