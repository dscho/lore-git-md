This is a review response in the ongoing approxidate bugfix series, specifically addressing the second patch which handles date-based specials ("now", "today", "yesterday") with explicit day components.

Jeff King (Peff) provides detailed technical review of the proposed changes to fix how approxidate handles day specifications with "now" and "yesterday" specials. He confirms the core issue - that time-based specials like "noon" set tm_mday which then prevents "today"/"yesterday" from overriding it - but identifies a month/year rollover edge case when processing dates near month boundaries. The current patch's approach of resetting just tm_mday could cause incorrect month calculations (e.g., "noon today" on April 1st incorrectly returning March 1st).

Peff suggests two potential solutions: either resetting all date fields (tm_mday, tm_mon, tm_year) directly to the reference date's values, or keeping the update_tm() call but with clearer field management. He also reiterates test improvements from his review of patch 1, recommending adding rather than replacing test cases and avoiding subshells for test setup. The review maintains the thread's technical focus while highlighting remaining implementation questions around DST edge cases and the most robust way to handle date field overrides.
