This thread addresses a performance test environment variable handling issue in Git's test infrastructure, specifically affecting `t/perf/perf-lib.sh`. The problem originated when commit 4638e8806e3a caused runtime `GIT_PERF_*` variables to be incorrectly overridden by compilation-time values from `GIT-BUILD-OPTIONS`. Johannes Schindelin proposed a solution that stashes these variables before sourcing `test-lib.sh` and restores them afterward using careful `eval` handling with sed-based quote escaping.

The fix has now been verified by both Derrick Stolee and Jeff King (Peff), confirming it correctly handles not just `GIT_PERF_LARGE_REPO` but also other performance variables like `GIT_PERF_REPEAT_COUNT`. While the technical approach is validated as correct, Peff noted additional issues with default values in the `run` script that still need addressing. The thread recognizes this as an important but incremental fix for benchmarking workflows, particularly when testing large repositories where these variables are routinely customized. Participants agree the solution's backslash-heavy quoting is complex but necessary, and that similar issues with `GIT_TEST_*` variables remain as future work, part of a broader pattern needing systematic attention across Git's test infrastructure.
