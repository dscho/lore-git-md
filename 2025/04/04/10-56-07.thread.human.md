This thread addresses a bug in Git's performance test infrastructure where runtime `GIT_PERF_*` environment variables were being incorrectly overridden by values from `GIT-BUILD-OPTIONS` recorded during compilation. The regression was introduced by commit 4638e8806e3a and particularly impacts users who override these variables when benchmarking large repositories.

Johannes Schindelin proposed a fix that preserves runtime settings by stashing all `GIT_PERF_*` variables before sourcing `test-lib.sh` and restoring them afterward with careful `eval` handling to properly escape values. Derrick Stolee has now confirmed the patch works as intended, noting it correctly handles not just `GIT_PERF_LARGE_REPO` but also other performance-related variables like `GIT_PERF_REPEAT_COUNT`. The solution involves a sed pipeline to escape single quotes and format variables as eval-safe assignments.

While this fix addresses the immediate issue for performance tests, the original patch noted similar handling may be needed for `GIT_TEST_*` variables in future work. With Stolee's verification, the thread appears to be converging on this being the right solution for the performance test case.
