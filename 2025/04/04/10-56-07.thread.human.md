This thread addresses a regression in Git's performance test infrastructure where `GIT_PERF_*` environment variables were being incorrectly overridden by `GIT-BUILD-OPTIONS` values from compilation time. Johannes Schindelin proposed a fix that carefully preserves runtime variables by stashing them before sourcing `test-lib.sh` and restoring them afterward, with proper handling of quoted values. The solution was verified by both Derrick Stolee and Jeff King, though King noted remaining issues with default value handling in the `run` script.

Junio Hamano has now acknowledged the patch was overlooked, recognizing it as addressing a symptom of a larger systemic issue with `GIT-BUILD-OPTIONS` behavior introduced in commit 4638e8806e3a. While accepting the current fix as valid for the immediate problem, Hamano characterizes this as "whack-a-mole" - the patch solves the specific performance test case but leaves broader test infrastructure problems unaddressed. The discussion highlights two potential directions for a more comprehensive solution: either modifying the `run` script's fallback logic or changing how `GIT-BUILD-OPTIONS` handles unset variables.

The thread reflects consensus that this is part of a pattern affecting multiple test areas, with references to similar challenges in the interop test suite. While the immediate fix is technically sound and will be applied, participants agree the underlying variable handling issues in Git's test framework need systematic attention.
