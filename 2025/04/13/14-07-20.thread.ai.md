Git difftool bug report: `git difftool --tool=meld -d` fails to preserve files copied via meld's "Copy To Right" function during diff viewing. Reproduction sequence: (1) create/commit file, (2) remove in second commit, (3) run difftool to view deletion, (4) use meld's copy function to restore file - the copied file disappears from working directory after quitting rather than being preserved. Issue occurs in Git 2.49.0 on Linux, with root cause traced to Git's temporary directory handling (/tmp/git-difftool.*/right/) rather than meld's behavior.

Jayatheerth confirms this is working as designed - `git difftool -d` intentionally operates on temporary directories that are cleaned up after session completion, meaning GUI tool operations like meld's "Copy To Right" won't persist. They acknowledge this behavior is counter-intuitive for users expecting interactive modifications to affect the working directory, as evidenced by related meld bug reports (including #555 which was misattributed to meld when the cleanup is actually Git-side). The response maintains this as a safety mechanism and suggests improving documentation in `git-difftool(1)` to clarify the limitation, recommending standard Git commands (`git restore`/`git checkout`) as the proper way to restore files rather than using the diff tool's UI. The technical core remains Git's temp dir handling in `/tmp/git-difftool.*/` where the right directory represents working state but gets discarded by design.
