This is a bug report about `git difftool` losing copied files when using the Meld visual diff tool. 

The reporter uses `git difftool --tool=meld -d HEAD^` to compare changes, then copies a deleted file from the old version to the new version using Meld's "Copy To Right" function. However, the copied file doesn't appear in the working directory after quitting Meld, despite the operation appearing successful in the UI.

The issue appears to stem from how Git handles temporary directories during difftool operations - the copied file gets lost in `/tmp/git-difftool.*/right/` rather than being properly transferred to the working directory. The reporter notes this was previously reported as a Meld bug but believes it's actually a Git issue with how it manages these temporary files.

The bug is well-documented with clear reproduction steps and system information. It affects a common workflow (using visual difftools to recover deleted files) and appears to be a genuine data-loss scenario, making it worth attention from maintainers. The reporter helpfully links to the related Meld issue for context.
