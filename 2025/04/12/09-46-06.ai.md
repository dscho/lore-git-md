Bugfix for `git add` wildcard pathspec handling when literal matching filenames exist.

This patch addresses an edge case in `git add` where a wildcard pathspec (like 'f*') would fail to properly expand when there's an exact filename match (a file literally named 'f*'). The current behavior incorrectly prioritizes the literal match over wildcard expansion on the first run. The fix ensures wildcards expand consistently regardless of exact filename matches, while still allowing users to target the literal file by escaping the wildcard (e.g., `git add 'f\*'`).

The change is minimal (3 lines in dir.c) but impactful, modifying how pathspecs are processed when both literal and wildcard matches are possible.
