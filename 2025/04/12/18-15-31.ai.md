Performance test fix for scalar clone behavior in detached HEAD state. This is the second patch in a 3-patch series addressing test suite issues, specifically targeting the p9210-scalar.sh performance test.

The patch fixes a test failure that occurs when running 'scalar clone' from a detached HEAD state. The test clones a local copy of git.git ('to-clone') but fails when the original repository is in detached HEAD because scalar clone's branch detection logic falls back to the current branch name, which may not exist. The fix adds an explicit branch creation ('git checkout -B test-branch') during test setup to ensure consistent behavior regardless of HEAD state.

This change is minimal (3 lines) and has already received explicit approval from Patrick Steinhardt as "an easy and pragmatic fix" in the thread context. The patch makes no changes to scalar's actual behavior - it only ensures the test works reliably by establishing a known branch state before testing the clone operation. The fix is straightforward and uncontroversial, addressing a clear edge case in test execution environment setup rather than modifying core functionality.

Key technical details for future reference: the test modifies p9210-scalar.sh to create 'test-branch' in the 'to-clone' repository before running the scalar clone performance test. This ensures scalar.c:remote_default_branch will find a valid branch name when determining what to check out in the cloned repository. The change affects only test infrastructure, not production code paths.
