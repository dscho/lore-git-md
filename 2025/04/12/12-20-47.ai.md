Documentation modernization patch focusing on `git-mv` synopsis standardization, part of a 7-patch series converting command documentation to modern AsciiDoc format. This specific patch (4/7 in v2) restructures the `git-mv` man page by moving command variants from the DESCRIPTION section into the proper SYNOPSIS section, while maintaining identical functionality. The change aligns with the series' goal of consistent documentation presentation across Git commands.

The patch modifies both the documentation (`git-mv.adoc`) and the built-in command help text (`builtin/mv.c`) to show two distinct invocation forms: single-source rename and multiple-source move-to-directory patterns. Options (`-v`, `-f`, `-n`, `-k`) are now consistently listed in both locations. The changes follow the established pattern seen in earlier patches for `git-reset` and `git-rm`, completing the trio of command conversions in this series.

Technical details include:
- Standardized option formatting with brackets (`[-v]`)
- Clear separation of command variants in SYNOPSIS
- Matching updates between documentation and runtime help text
- Preservation of all existing functionality while improving presentation
- Follows the project's evolving documentation standards for placeholder notation and option formatting

This patch demonstrates the same attention to detail seen in the rest of the series, with no substantive behavior changes - only presentation improvements to help users more clearly understand command syntax. The dual updates (documentation + built-in help) ensure consistency across all user-facing command references.
