Bugfix for `git add` wildcard handling when literal matching filenames exist.

This patch addresses a subtle edge case in `git add` where a wildcard pathspec (e.g., 'f*') would fail to properly expand if there happened to be a file with the exact name 'f*' in the repository. In such cases, Git would incorrectly only add the literal file matching 'f*' on the first run, skipping the wildcard expansion entirely.

The fix ensures wildcard expansion works consistently regardless of whether a file exists that literally matches the wildcard pattern. The commit notes that users who actually want to add just the literal file (not the wildcard expansion) should quote the wildcard character (e.g., `git add 'f\*'`).

The change is minimal (just 3 lines in dir.c) and appears well-targeted to the described issue. This seems like a straightforward improvement to pathspec handling that could affect users who work with oddly-named files containing wildcard characters. The patch doesn't include tests, but the behavior being fixed is clearly specified.
