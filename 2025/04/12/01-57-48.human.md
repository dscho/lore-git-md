Bugfix analysis for `git add` pathspec matching issue.

K Jayatheerth provides a detailed technical analysis of the wildcard matching bug reported by Piotr Siupa. The issue occurs when `git add 'f*'` fails to match both a literal file named `f*` and pattern-matched files like `foo` on the first run, though subsequent runs work correctly.

The analysis traces the problem to an optimization in `do_match_pathspec` that prematurely stops checking for matches once an exact match is found. When the pathspec `'f*'` first encounters the literal `f*` file, it marks this as an exact match and skips checking other files against the same pattern, even though the wildcard should also catch `foo`. The second run works because only `foo` remains untracked, so the optimization doesn't interfere.

This appears to be a longstanding issue in the pathspec matching logic rather than a regression. The proposed solution would involve modifying either how exact matches are determined when glob patterns are involved or adjusting the optimization check in `do_match_pathspec`. The analysis is thorough and well-reasoned, suggesting the reporter has a solid understanding of Git's internals. This looks like a legitimate bug worth fixing, though the solution may need careful consideration to avoid breaking other pathspec use cases.
