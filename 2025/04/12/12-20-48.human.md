This is part 5/7 of Jean-Noël Avila's documentation modernization series, focusing on converting `git-mv` to the new AsciiDoc format. The patch standardizes the command's documentation with consistent formatting while addressing a known ambiguity in the three-dot notation.

The changes include:
1. Restructuring the SYNOPSIS section to use the new synopsis block format, which automatically applies proper styling to placeholders and keywords
2. Updating option descriptions to use backticks for command-line options (`-f`, `-n`, etc.) and italics for placeholders
3. Aligning submodule documentation with the new config key formatting (`submodule.<name>.path`)
4. Synchronizing the built-in command help text with the man page changes

A notable challenge mentioned is the dual meaning of the ellipsis (`...`) in Git documentation - it can indicate either repeatable options or commit ranges. The patch acknowledges this as an unresolved rendering limitation that the current toolchain cannot distinguish.

This continues the series' high-quality documentation conversion work, maintaining consistency with the earlier `git-reset` and `git-rm` conversions while keeping all substantive content intact. The changes are purely presentational, with no functional impact on `git-mv`'s behavior.
