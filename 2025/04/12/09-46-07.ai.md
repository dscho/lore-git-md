Bugfix for `git add` wildcard pathspec handling when literal filenames match the wildcard pattern. This patch addresses an edge case where pathspecs like 'f*' would incorrectly prioritize a literal file named 'f*' over wildcard expansion, causing inconsistent behavior between first and subsequent invocations.

The fix modifies the pathspec matching logic in dir.c to prevent premature short-circuiting when exact matches are found, while maintaining backward compatibility. The key change is adding a check for `nowildcard_len` to ensure wildcard evaluation isn't skipped when the literal filename happens to match the wildcard pattern. Users can still explicitly target literal files by escaping the wildcard (e.g., 'f\*').

This preserves the existing behavior for escaped pathspecs while fixing the wildcard expansion case.
