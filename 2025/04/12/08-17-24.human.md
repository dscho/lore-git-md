This is a refactoring patch in Patrick Steinhardt's ongoing series to reorganize Git's object-file subsystem. Jeff King provides thoughtful technical feedback on patch 6/9, which moves index-related functions from object-file.c to read-cache.c.

King notes that while these functions (all prefixed with "index_") take an index_state parameter, their core purpose is actually about computing object hashes rather than index operations. He traces their history from early Git versions where they didn't even use the index, through gradual additions of index functionality for CRLF conversion and attributes. The key insight is that these are fundamentally object-creation utilities that happen to use the index incidentally.

The feedback suggests the current split might not be the most logical organization, since these functions would be equally out of place in read-cache.c. King doesn't oppose the refactoring but raises the architectural question of whether there might be a better home for these utilities that reflects their true purpose in the object creation pipeline.

This is a nuanced technical discussion that shows the careful consideration being given to the large-scale reorganization. While not blocking the series, it highlights an area where the subsystem boundaries might benefit from further refinement. The patch remains valid but may prompt additional discussion about the most appropriate location for these hybrid index/object functions.
