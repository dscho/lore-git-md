Windows path handling bug response. Johannes Schindelin confirms Milan AJDINOVIC's analysis of the branch name issue on Windows, where directory names ending with dots are prohibited by the Windows filesystem. The response provides a workaround using Git's refspec configuration to map the problematic branch name to a valid alternative locally. Key technical details include: the specific filesystem restriction documented by Microsoft, the limitation in Git's refs backend implementation that relies on filesystem paths, and the note that while cloning might appear to work, subsequent fetches would fail. The suggested solution involves adding custom fetch refspecs to rename the branch locally while maintaining the original remote reference. This is a direct response to the original bug report with no new patches proposed, focusing instead on immediate mitigation for affected users. The underlying platform-specific nature of the issue remains, with no discussion yet of potential fixes to Git's core ref handling for Windows.
