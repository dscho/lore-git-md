This thread discusses Karthik Nayak's performance optimization series addressing a significant O(N^2) scaling issue in Git bundle creation. The problem stems from inefficient duplicate refname checks that cause severe slowdowns in repositories with large numbers of references (demonstrating a 2200x slowdown at 100k refs in benchmarks).

The series consists of two well-structured patches. The first established comprehensive test coverage in t6020-bundle-misc.sh, documenting current limitations while explicitly marking known edge cases where short/long refname variants weren't properly deduplicated. The second patch, now under discussion, delivers the actual optimization by replacing the quadratic algorithm with an O(1) strset-based solution in `write_bundle_refs()`, yielding a 6x speedup (14.6s → 2.4s at 100k refs). The implementation cleanly handles both identical refnames pointing to the same object (like "master" and "refs/heads/master") and those pointing to different objects (from exclusion patterns), while removing the now-unneeded `object_array_remove_duplicates()` function entirely.

The changes span bundle.c, object.c and object.h, with test updates confirming the fix works for the previously failing edge cases. The technical approach appears sound, with benchmarks demonstrating the optimization achieves linear scaling where the original showed quadratic growth. This improvement will be particularly valuable for repositories maintaining large numbers of references.
