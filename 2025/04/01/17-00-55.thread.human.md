Karthik Nayak has completed a performance optimization series that fixes an O(N^2) scaling issue in bundle creation, where duplicate refname checks were causing significant slowdowns. The solution replaces the quadratic `object_array_remove_duplicates()` with an O(1) `strset`-based approach in `write_bundle_refs()`, achieving a 6x speedup (from 14.6s to 2.4s for repositories with 100k refs). The changes also fix previously undetected bugs where duplicates could slip through with `--all` and when handling short/long refname variants.

The series went through multiple iterations, with version 2 incorporating stylistic improvements like using the `STRMAP_INIT` macro. The implementation touches bundle.c, object.c, and object.h while adding 57 lines of test coverage across four scenarios in t6020-bundle-misc.sh. Toon Claes, who previously worked on bundle race conditions, confirmed the patches perform well in real-world repositories of varying sizes with no regressions. Both Karthik and Toon are now satisfied with the solution's correctness and performance characteristics.

The only remaining hurdle is resolving a simple merge conflict with the ps/object-wo-the-repository series before the changes can be integrated. With comprehensive benchmarking showing linear scaling where the original implementation was quadratic, and all edge cases properly handled, this optimization appears ready for merging.
