This thread introduces a proposal from Ramkumar Ramachandra to optimize the rebase process for large codebases like LLVM, where timestamp changes during rebase trigger unnecessary rebuilds. The core issue is that current rebase operations update file timestamps even when there are no actual conflicts, forcing expensive CMake reconfigurations.

Ramachandra suggests adding a new `git rebase-checkout` command that would avoid this by creating a fresh branch from main, cherry-picking the original commits (preserving their timestamps), then replacing the old branch. This approach would maintain the logical history rewrite of rebase while preventing the timestamp churn that causes rebuilds.

The proposal acknowledges this could be implemented as a script using existing Git plumbing, but explores whether the workflow improvement is significant enough to warrant inclusion as a core feature. The thread appears to be seeking feedback on both the technical approach and the general usefulness of such a command for developers working with large projects where rebuild costs are substantial.
