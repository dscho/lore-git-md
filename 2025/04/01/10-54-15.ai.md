This is a feature proposal addressing a workflow pain point in large codebases. Ramkumar Ramachandra describes a common scenario when working with LLVM where rebasing outdated branches triggers unnecessary rebuilds due to timestamp changes, even when there are no actual conflicts. The current workflow forces a full rebuild because CMake reconfiguration occurs when file timestamps change during rebase.

The proposal suggests adding a new `git rebase-checkout` command that would avoid this issue by creating a new branch based on main, cherry-picking commits from the outdated branch, and then renaming the new branch to replace the old one. This approach would preserve file timestamps from the original commits rather than updating them as a regular rebase does.

The email positions this as a potential core Git feature that could benefit developers working with large projects where rebuild cost is significant, though acknowledges it could theoretically be implemented as a script using existing plumbing commands. The proposal is framed as an exploration of whether this workflow optimization would be generally useful enough to warrant inclusion in Git proper.
