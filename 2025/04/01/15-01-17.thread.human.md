This thread introduces a refactoring series to improve Git's integer option parsing infrastructure, addressing safety and correctness issues. The current implementation has several problems: it doesn't verify buffer sizes, potentially truncates values when casting from `long` to `int`, and lacks support for larger integers even when the underlying variable could handle them.

The second patch in the series (of five) introduces a `precision` field to track integer sizes (1, 2, 4, or 8 bytes) and switches to `strtoimax()` for parsing with proper range checking. Several builtin commands (`fmt-merge-msg`, `merge`, `show-branch`, `tag`) are updated to use the new precision field, and tests verify the improved 16-bit integer handling. The changes maintain backward compatibility while fixing real safety concerns, with a follow-up planned to address signedness verification. The implementation appears thorough, with both code updates and test coverage.
