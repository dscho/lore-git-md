This is part of a bugfix series addressing a Cygwin regression in gitk's command execution path handling, specifically targeting Windows security changes that broke Cygwin compatibility. The patch modifies gitk's Tcl code to scope its PATH search overrides exclusively to Windows systems, undoing changes from commit 4cbe9e0e2 that inadvertently affected Cygwin. The original change was meant to address CVEs (CVE-2023-23618, CVE-2022-41953) by preventing unsafe PATH lookups on Windows, but incorrectly applied these protections to Cygwin which follows Unix path conventions.

Key technical changes include removing Cygwin-specific path conversion code that became obsolete after Cygwin switched to Unix pathnames in 2012, and wrapping all PATH search overrides in an `is_Windows` conditional. The patch eliminates 88 lines of unnecessary code while maintaining Windows security protections. The changes affect gitk's command execution pipeline including the `_which` helper, `exec`/`open` overrides, and PATH sanitization logic.

This first patch in the v2 series follows Johannes Sixt's review feedback from v1, focusing solely on the platform-specific scoping fix. The subsequent patches will introduce further optimizations (relative path handling) and apply the same pattern to git-gui. The solution preserves Windows security while restoring Cygwin's pre-regression behavior, resolving an infinite recursion issue where `_which` and wrapped `exec` functions called each other.
