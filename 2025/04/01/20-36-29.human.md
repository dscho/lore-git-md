Feature enhancement for `git version --build-options` reporting SHA implementations. This is the first patch in a 2-part series that has already received maintainer approval for its technical approach.

The patch adds SHA implementation details to Git's version output when using `--build-options`. It works by defining standardized symbols (`SHA1_BACKEND` and `SHA256_BACKEND`) in hash.h that each backend must provide, then displaying these in the version info. The implementation follows Patrick Steinhardt's approved architecture that centralizes backend detection at compile time.

Notable aspects include:
- Clear warnings for non-cryptographic SHA-1 implementations ("No collision detection")
- Support for all major backends (OpenSSL, Apple, DC, BLK for SHA-1; Nettle, Gcrypt, OpenSSL, BLK for SHA-256)
- Documentation updates explaining the new output
- Zero runtime overhead since everything is determined at compile time

The patch appears well-crafted with thorough coverage of all SHA variants. It addresses a real gap in version diagnostics while maintaining the project's security transparency goals. With maintainer approval already secured and only minor presentation details still under discussion, this seems ready for finalization.
