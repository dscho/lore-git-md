Thread summary:

Bug report and discussion about git-interpret-trailers' handling of trailer keys containing periods (e.g. "My-6.11-Version"). Original report demonstrated that periods in keys cause silent failure of entire trailer block parsing, despite no documentation of this restriction. Use case involves version tracking of backported commits in kernel development. Christian Couder confirms current strict parsing behavior is intentional to prevent false positives, though acknowledges documentation could be clearer. Technical constraints noted: parser deliberately maintains strict key format requirements (alphanumeric + hyphen) to avoid misinterpreting regular text as trailers. While recognizing valid use cases for more flexible parsing (particularly version strings), expresses concern about potential abuse if parser becomes too permissive. Two potential solution paths identified: 1) better document current restrictions, or 2) introduce configurable parsing strictness. Maintainer preference leans toward documentation clarification while keeping strict default behavior, but leaves door open for patches proposing controlled flexibility. Key open questions: whether to maintain current behavior with better docs, or implement configurable leniency; if pursuing configurability, what safeguards would prevent abuse. Test case remains available for any proposed solution evaluation.
