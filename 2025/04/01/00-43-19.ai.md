This is a response to a bug report about `--reset-author` timezone handling in post-commit hooks. The responder confirms the reported behavior where environment variables from the initial commit persist into the hook context, causing the author date to retain its original timezone while only the committer date gets reset to UTC0. 

The technical explanation reveals that `git commit` sets `GIT_AUTHOR_*` environment variables (including the timezone) which then get inherited by the hook's subsequent commit operation. The responder suggests examining `/tmp/foo` from an `env` dump in the hook to verify this behavior. 

While acknowledging the bug's reproducibility, the response strongly discourages this hook usage pattern, calling it brittle and unintended. Two alternative solutions are proposed: unsetting the problematic environment variables in the hook, or better yet, using an alias with `TZ=UTC0` for the initial commit instead of trying to fix it after the fact. 

The response also warns about additional hook-related pitfalls with this approach, noting that `prepare-commit-msg` and `commit-msg` hooks would still execute during the amend operation, potentially causing further issues. The tone suggests this is more of a workflow design problem than a bug needing fixing in Git itself.
