Feature patch introducing unsigned integer parsing in Git's parse-options infrastructure.

This is the fourth patch in Patrick Steinhardt's series hardening integer handling in Git's option parsing. It adds a new `OPTION_UNSIGNED` type to complement the existing `OPTION_INTEGER` (signed) and `OPTION_MAGNITUDE` (unsigned with unit suffixes). The new option fills a gap by providing unsigned parsing without unit interpretation.

The implementation includes proper bounds checking based on the variable's size (1, 8, 16, 32, or 64 bits) and adds corresponding test cases in t0040-parse-options.sh. The patch follows the same pattern as the existing integer parsing code, with careful handling of edge cases like overflow and invalid inputs.

This appears to be a well-constructed addition to the parse-options API, with thorough test coverage. The change is part of a larger effort to make Git's option parsing more type-safe and robust against integer-related bugs.
