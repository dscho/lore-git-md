Feature enhancement to parse-options machinery, specifically for OPTION_MAGNITUDE handling. This is part 3 of a 5-patch series (preceded by similar changes for OPTION_INTEGER) that adds precision-aware bounds checking for magnitude options.

The patch introduces precision handling for OPTION_MAGNITUDE similar to what was done for OPTION_INTEGER in the previous patch. It adds bounds checking based on the size of the target variable (1, 2, 4, or 8 bytes) to prevent overflow when parsing magnitude values (numbers with k/m/g suffixes). The implementation calculates the maximum allowed value for each precision level and rejects inputs that exceed it.

Key technical details:
- Adds a new test case `--m16` to demonstrate 16-bit magnitude handling
- Includes tests verifying proper bounds checking (rejects 65536 for 16-bit)
- Modifies the OPT_MAGNITUDE macro to automatically set precision based on target variable size
- Maintains all existing magnitude parsing behavior (k/m/g suffixes, optional args) while adding the new bounds checking

The changes touch parse-options.c (core logic), parse-options.h (macro update), and add test coverage in both the test helper and t0040 test script. The implementation carefully handles edge cases like calculating maximum values without overflow.
