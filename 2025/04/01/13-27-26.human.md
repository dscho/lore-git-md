Bugfix report regarding `git interpret-trailers` behavior with period characters in trailer keys. Brendan Jackman encountered an issue where trailer parsing stops when encountering a key containing a period (like "My-6.11-Version"), despite this not being documented as invalid in the man page. The problem appears when mixing trailers with and without periods - the parser seems to recognize the trailer block as invalid once it hits a period-containing key, even though the documentation doesn't prohibit this character.

The reporter provides clear reproduction steps showing that a commit message with a simple trailer ("My-Footer") parses correctly, but when adding a version-style trailer with periods, the parsing fails. This appears to be an undocumented limitation in the trailer parsing logic, though the reporter notes they might be missing something in the documentation.

The issue affects their use case where they need to track version information in trailers (like Linux kernel version numbers). The report is well-formulated with concrete examples and version information (Git 2.49.0 with Google's internal monitoring additions, which shouldn't affect this behavior). This looks like a legitimate bug report that warrants investigation into whether the period restriction is intentional or an implementation oversight.
