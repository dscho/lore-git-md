This is a technical response in the `git rebase-checkout` feature proposal thread, suggesting an alternative approach using existing Git functionality.

Brian M. Carlson points out that the proposed `git rebase-checkout` behavior - creating a new branch with cherry-picked commits while preserving timestamps - might already be achievable using the experimental `git replay` command. They note that `git replay` functions as a non-interactive rebase that specifically avoids modifying the working tree or index (which would address the timestamp issue) and is designed to work with `git update-ref` for branch updates.

The response positions `git replay` as a potentially more flexible solution since it separates the replay operation from reference updates, though it comes with the caveat that the command is still experimental. This suggests the proposed `rebase-checkout` functionality could be implemented today by combining existing plumbing commands, though with some additional complexity compared to a dedicated porcelain command.

The email doesn't take a position on whether the new command should be added, but provides useful context about similar existing capabilities that could influence the discussion.
