This is part 4/5 of Patrick Steinhardt's series hardening integer handling in Git's parse-options infrastructure, introducing a new `OPTION_UNSIGNED` type.

The patch adds a new unsigned integer option type to fill a gap between existing `OPTION_INTEGER` (signed) and `OPTION_MAGNITUDE` (unsigned with unit suffixes). The implementation includes:
- Core parsing logic in parse-options.c with bounds checking
- New `OPT_UNSIGNED` and `OPT_UNSIGNED_F` macros in parse-options.h
- Test coverage in t/helper/test-parse-options.c and t0040-parse-options.sh
- Range validation matching the specified precision (8/16/32/64-bit)

The change is well-contained and follows the established pattern of the existing integer options, with thorough test coverage including edge cases. This appears to be a straightforward addition that cleanly fits into the series' goal of making integer handling in parse-options more robust. The implementation handles all the expected cases (unset, optional, required) with proper error messages, and the tests verify both successful parsing and bounds enforcement.
