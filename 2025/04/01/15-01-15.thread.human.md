This thread covers Patrick Steinardt's ongoing work to harden integer handling in Git's option parsing infrastructure. The v2 series builds on previous discussions about making option parsing more type-safe, particularly for integer values.

The first patch in the series (already submitted) performed a mechanical conversion of parse-options struct initializations to use designated initializers across 24 files, touching core commands like commit, merge and grep. This foundational refactoring enables the subsequent safety improvements while maintaining exact behavior.

The second patch, which just arrived, introduces precision handling for OPTION_INTEGER to address safety issues. It adds a precision field to track integer sizes (1, 2, 4 or 8 bytes), uses strtoimax() for better large value handling, implements range checking to prevent overflows, and updates callers to specify precision via sizeof(). The changes affect commands like merge, tag and show-branch while maintaining backward compatibility. New cases for 16-bit integers have been added to the test suite.

Looking ahead, the series will introduce a dedicated OPTION_UNSIGNED type, build-time assertions for signedness checking, and real-world fixes in several commands. The work demonstrates careful attention to both safety and compatibility, with each change building systematically on the last. Review feedback from René Scharfe has been incorporated, particularly around using maximum_signed_value_of_type for compile-time checks. The series continues to refine Git's option parsing with a focus on type safety while preserving existing behavior where needed.
