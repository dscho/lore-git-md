This is a technical discussion about error handling in the HTTP keepalive configuration series.

Jeff King suggests refactoring the new `set_long_from_env()` helper function to reuse Git's existing parsing infrastructure from parse.[ch] rather than implementing custom strtol() handling. His proposed changes would:

1. Add a new `git_parse_long()` function to parse.[ch] to complement the existing `git_parse_ulong()`
2. Simplify the HTTP code by using this shared implementation
3. Gain support for unit suffixes (like "K") that the parse functions provide
4. Also clean up the legacy low speed limit parsing to use the new helper

The suggestion comes with two implementation options - either keep the current warning-based approach using the new parse function, or potentially switch to the die()-on-error `git_env_long()` pattern (though this would require adjusting the calling convention).

This builds on the v2 series' improvements to error handling while further reducing code duplication. The suggestion appears compatible with the series' goals and the positive feedback it has received so far, though it would require extending the scope slightly to modify parse.[ch]. The discussion focuses on implementation details rather than core functionality, suggesting the series is nearing finalization.
