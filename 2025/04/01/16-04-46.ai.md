This is a refactoring patch for git-gui that removes obsolete Tcl compatibility code. The patch simplifies the `_open_stdout_stderr` function by eliminating a workaround for older Tcl (pre-8.4.7) that didn't support the `2>@1` stderr redirection syntax. The workaround was originally needed for Cygwin's outdated Tcl version, but git-gui now requires Tcl ≥8.5 which universally supports this syntax.

The change reduces 21 lines of conditional logic down to just 2 lines, removing the fallback path that would execute commands twice in certain cases. The author (Mark Levedahl) tested the simplified version on current Linux, Cygwin and Git for Windows Tcl implementations. Johannes Schindelin is checking if the patch is still relevant and bringing it to Johannes Sixt's attention, suggesting this might be a follow-up to previous cleanup work (7145c65) that missed this particular case.

Key technical details for future reference:
- Removes compatibility code for Tcl versions <8.4.7
- Simplifies `_open_stdout_stderr` function in git-gui.sh
- Changes how command execution handles stderr redirection
- Follows up on earlier Cygwin-specific cleanup (7145c65)
- Affects Tcl command execution pipeline construction
