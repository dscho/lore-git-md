This is a follow-up discussion in the "rebase status reporting improvements" series, specifically addressing test hygiene concerns around the `FAKE_LINES` environment variable usage in patch 1/3.

Johannes Schindelin responds to Eric Sunshine's review about proper `FAKE_LINES` handling in the test case for the patch that fixes merge commit creation after empty conflict resolution in interactive rebase. While Eric had suggested using `env` to avoid polluting the test environment, Johannes goes further by acknowledging the fundamental limitations of the `FAKE_LINES` approach itself.

He proposes a more robust alternative that would write the pick instructions to a file in the repository's git directory rather than using environment variables, with the fake editor script reading and then cleaning up this file. This would prevent any potential environment pollution between tests while also being more deterministic.

The exchange shows the careful attention being paid to test reliability in this series, with both reviewers (Eric and now Johannes) offering concrete improvements to the testing approach. Johannes's suggestion represents a more architectural solution that could potentially be adopted beyond just this test case.
