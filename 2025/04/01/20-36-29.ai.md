This is the first patch in a 2-part series enhancing `git version --build-options` to report SHA implementations, now at version 2. The patch implements the core technical approach approved by the maintainer - using backend-defined symbols in hash.h to report the actual SHA implementations used at build time.

The changes add SHA1_BACKEND and SHA256_BACKEND symbol definitions in hash.h for each possible implementation (OpenSSL, Apple CommonCrypto, SHA1DC, etc.), with explicit "(No collision detection)" warnings for non-crypto variants. The help.c changes then consume these symbols to display the implementation details when `--build-options` is used.

Key technical details:
- Defines standardized SHA*_BACKEND strings in hash.h for all implementations
- Adds SHA implementation reporting to help.c's version output
- Documents the SHA1 variants in git-version.adoc
- Maintains compile-time safety by using preprocessor symbols
- Follows the maintainer-approved approach of centralized symbol definitions

The implementation is clean and focused, touching only the three necessary files (hash.h, help.c, git-version.adoc). The v2 changes from the previous version include updated terminology ("non-crypto" instead of "unsafe") and clearer warning messages about collision detection.
