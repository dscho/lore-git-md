Performance optimization for bundle creation with many refs. This is a two-patch series addressing quadratic time complexity in bundle creation when checking for duplicate refnames.

Karthik Nayak from GitLab reports that creating bundles shows non-linear performance degradation as the number of references grows, with a 100,000-ref repository taking over 9 seconds to bundle. The root cause is an O(N²) duplicate refname check. The series first adds test coverage (including an edge case the current implementation misses), then replaces the quadratic check with an `strset`-based approach that provides 6x speedup for large repositories.

The changes touch bundle.c and test infrastructure, with some object.* file cleanups. The author notes a simple conflict with the ongoing `the_repository` removal work in 'seen'. The benchmark data shows compelling improvements, making this worth reviewing for anyone working with repositories containing many references.
