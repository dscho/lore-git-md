This is a cover letter for a 2-patch series enhancing `git version --build-options` output with SHA implementation details, now at version 2. The series adds reporting of which SHA-1, SHA-256, and non-crypto-SHA-1 implementations Git was built with, primarily for diagnostic purposes.

The v2 changes reflect maintainer feedback and thread discussion, moving to a symbol-based approach where backends define `SHA1_BACKEND`, `SHA1_UNSAFE_BACKEND`, or `SHA256_BACKEND` macros that get reported directly. The output now uses these symbol names rather than human-readable labels, with explicit "(No collision detection)" warnings on non-crypto SHA-1 variants. The terminology has also shifted from "unsafe-SHA-1" to "non-crypto-SHA-1" in the displayed output.

The implementation touches three files: adding macro definitions in hash.h, output logic in help.c, and documentation updates in git-version.adoc. The approach has maintainer approval for its technical simplicity and compile-time safety, with the thread now focused on final presentation details like warning phrasing. The series remains narrowly scoped to version reporting without broader codebase impact.

Key technical details for future reference:
- Backend selection is determined by preprocessor symbols (SHA1_BACKEND etc.)
- Non-crypto variants get explicit collision detection warnings
- Output format uses raw symbol names (e.g. "SHA1_OPENSSL")
- DC_SHA1 variant display remains an open question for final formatting
- Changes are contained to version reporting with no runtime overhead

The series appears well-considered, with clear evolution from v1 based on list feedback and maintainer guidance. The remaining discussion points seem minor, suggesting this is likely nearing final form.
