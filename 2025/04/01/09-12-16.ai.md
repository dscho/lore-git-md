Refactoring patch in HTTP keepalive series with maintainer approval.

This is the third patch in a four-part series introducing TCP keepalive configuration for HTTP operations. The patch inlines the now-simplified `set_curl_keepalive()` function directly into `get_curl_handle()`, removing what has become unnecessary indirection after version compatibility code was dropped in a previous cleanup (f7c094060c). The change is straightforward - moving the three curl_easy_setopt() calls for TCP keepalive parameters from the helper function to the main handle setup routine.

Jeff King, the original author of the keepalive functionality being modified, explicitly approves the change while noting it would have been ideal to include this simplification in the earlier version compatibility cleanup. The patch maintains all existing functionality while making the code more direct and self-contained within the curl handle setup logic.

Key technical details carried forward from the thread context:
- The series introduces configurable TCP keepalive settings (idle time, interval, count)
- Environment variables can override config values
- Version checking remains for CURLOPT_TCP_KEEPCNT (curl 8.9.0+)
- The change fits within the series' broader goal of cleaning up HTTP keepalive infrastructure

This appears to be a non-controversial cleanup that has maintainer approval, with no outstanding technical questions or concerns from reviewers. The change is small and focused, following naturally from previous work to modernize curl version support.
