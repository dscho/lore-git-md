This is a GSoC proposal for a refactoring/feature project to consolidate Git's reference-related commands into a unified `git-refs` command. The proposal comes from Meet Soni, who has already contributed several merged patches to Git (including refspec consolidation and performance optimizations) and is currently working on a reftable error handling series.

The core idea is to create a new `git refs` command with subcommands (`list`, `exist`, `show`, `resolve`, `pack`, `write`, `check-format`) that would absorb the functionality currently spread across `git update-ref`, `git show-ref`, `git for-each-ref`, and `git pack-refs`. The proposal includes detailed mapping of existing flags to new subcommand options and discusses configuration sharing via a structured approach with common and subcommand-specific options.

Key technical aspects include maintaining backward compatibility during transition, comprehensive test coverage, and documentation updates. The proposal references prior similar consolidations (`git switch`, `git restore`) and includes a proof-of-concept implementation for the `list` subcommand. Stretch goals include absorbing `git symbolic-ref` and `git check-ref-format`.

The timeline proposes three phases (one per major command being consolidated) during GSoC's coding period, with documentation and testing integrated throughout. The applicant demonstrates familiarity with Git's development process through their prior contributions and proposes bi-weekly progress blogging. The proposal is thorough, showing both technical understanding of the refs subsystem and awareness of the project's design challenges.
