This is a cover letter for a patch series that hardens integer handling in Git's parse-options infrastructure, addressing previously reported issues. The series falls into both the "bugfix" and "feature" categories, fixing potential problems while also adding new capabilities.

The core issue being addressed is that `OPT_INTEGER()` and `OPT_MAGNITUDE()` currently make assumptions about the size and signedness of the variables they operate on, which could lead to subtle bugs. The series introduces several key improvements: tracking integer precision to support arbitrary-sized integers, adding signedness verification via build asserts, and introducing a new `OPT_UNSIGNED()` type for cases where unsigned values are needed.

The changes are quite extensive, touching 31 files with 671 insertions and 189 deletions. The modifications span across many builtin commands (clone, commit, fetch, grep, etc.) and core infrastructure files. The series appears well-motivated by prior discussions (referenced as [1] and [2] in the cover letter) and takes a thorough approach to the problem.

For future reference in thread summaries, key technical points include:
- New precision handling in `OPTION_INTEGER` and `OPTION_MAGNITUDE`
- Introduction of `OPTION_UNSIGNED` type
- Build-time signedness verification
- Widespread changes to builtin commands to use proper integer types
- Test updates in t0040-parse-options.sh
- The changes affect how numeric command-line options are processed throughout Git

The series looks like a well-considered improvement to Git's option parsing safety, though the wide scope means it will need careful review to ensure no regressions in the many modified commands. The use of build-time asserts is particularly notable as a proactive measure against future misuse.
