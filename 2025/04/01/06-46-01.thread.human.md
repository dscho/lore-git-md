Here's a human-readable summary of the thread so far:

The thread began with a report that tcsh completion files built with meson's `-Dcontrib=completion` flag weren't being automatically installed, unlike bash completions. Patrick Steinhardt confirmed this matches the existing Makefile behavior but acknowledged it's not ideal, highlighting the lack of standardized completion paths across different shells (bash, tcsh, zsh) and distributions as the root issue.

Akshay Hegde then proposed extending meson's configuration to allow specifying per-shell completion directories, which would enable automatic installation when paths are provided. This shifted the discussion from identifying a problem to considering a technical solution that could work across different environments.

Todd Zullinger's recent contribution adds important real-world context from Fedora's packaging perspective. He reveals that Fedora currently handles completions inconsistently: bash uses standard paths, tcsh uses a non-standard location requiring manual configuration (unchanged since 2013), and zsh completions aren't installed at all since upstream zsh already provides them. This concrete data shows how completion practices vary even within a single distribution.

The thread has evolved from a build system quirk to a broader discussion about shell completion deployment strategies. While Hegde's proposal offers a flexible technical solution, Zullinger's input suggests some shells may not need automatic installation as urgently as others. The discussion now has both technical and packaging perspectives, though we're waiting to hear from maintainers of other distributions about their practices.
