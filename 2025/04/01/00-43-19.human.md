Bugfix response regarding timezone handling in post-commit hooks with `--reset-author`. Brian m. carlson confirms the reported issue where `--reset-author` fails to normalize the author date to UTC0 when used in a post-commit hook, while the committer date is adjusted correctly. They identify the root cause: environment variables (`GIT_AUTHOR_*`) set by the initial commit persist into the hook's execution context, overriding the intended UTC0 behavior for the author date.

The response strongly discourages this hook usage pattern, calling it brittle and unintended. Instead, they recommend either unsetting the problematic environment variables in the hook or (preferably) using a different approach like a commit alias that sets `TZ=UTC0` directly. The note also warns about potential side effects from other hooks (`prepare-commit-msg` and `commit-msg`) being re-triggered during the amend operation.

This appears to be a valid bug report with a clear technical explanation, though the maintainer suggests the solution lies in avoiding this hook pattern rather than changing Git's behavior. The response leaves open whether Git should document this limitation or handle the environment variables more robustly in hook contexts.
