Refactoring patch converting parse-options initializations to use designated initializers.

This is the first patch in a 5-part series from Patrick Steinhardt that aims to harden integer handling in Git's parse-options infrastructure. The series addresses unsafe assumptions about variable sizes and signedness in `OPT_INTEGER()` and `OPT_MAGNITUDE()`.

This specific patch is a pure refactoring that converts all manual struct initializations of parse-options to use designated initializers. The commit message explains three key benefits:
1. Eliminates need to specify values for default-initialized fields
2. Makes the field assignments self-documenting
3. Allows easier reordering/insertion of new fields

The changes touch 24 files (443 insertions, 158 deletions) across builtin commands and core infrastructure. The patch converts both simple cases (like `OPTION_STRING`) and more complex ones (like `OPTION_CALLBACK` and `OPTION_LOWLEVEL_CALLBACK`). It also updates macro definitions like `OPT_CALLBACK_VALUE` and `_OPT_MERGED_NO_MERGED` to use the new style.

The changes are mechanical but wide-ranging, affecting option parsing in commands like `commit`, `fetch`, `grep`, and many others. The patch appears well-executed with consistent formatting and no functional changes - just improved initialization syntax. This groundwork will make the subsequent integer-handling changes easier to implement and review.
