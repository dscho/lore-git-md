Bugfix targeting Windows path handling for branch names containing dots.

Milan AJDINOVIC reports a Windows-specific issue where Git fails to create or switch to branches containing a dot at the end of a path component (e.g., "features/team1/feature./1.0/main"). The error occurs when Git attempts to create the directory structure for the ref under `.git/refs/heads/`, with Windows rejecting directory names ending in dot. The issue is reproducible with Git 2.42.0.windows.2 on Windows 10.

The bug manifests when trying to fetch and switch to such branches, with Git failing to create the necessary directory structure due to Windows filesystem restrictions. While the report focuses on the immediate symptom (inability to create directories), the underlying issue likely involves Git's path handling on Windows not properly sanitizing or working around Windows' filename restrictions.

This appears to be a legitimate platform compatibility issue that affects real-world workflows, particularly in GitHub Enterprise environments where such branch naming conventions might be used. The report provides clear reproduction steps and system information, though it doesn't include any proposed solution or analysis of where in Git's codebase the sanitization should occur. The bug is Windows-specific and doesn't affect other platforms where such filenames are permitted.
