This is the final patch in a series fixing Cygwin-specific regressions in gitk and git-gui. The patch optimizes PATH searching behavior in gitk to match POSIX/Tcl standards, completing the Windows/Cygwin compatibility work.

The change makes gitk only search PATH for bare executable names (like "git") rather than relative paths (like "foo/bar"), aligning with how Tcl behaves on all platforms. This matches a similar change previously made to git-gui (commit 3f71c97e) and fixes a discrepancy where gitk was unnecessarily searching PATH for relative paths. The implementation is simple - just checking if the command has any path components via `[file split]` rather than checking if it's absolute.

This is a straightforward, well-motivated change that follows established patterns from git-gui.
