Bugfix for Windows branch creation with trailing dots in names.

Milan Ajdinovic reports a Windows-specific issue where Git fails to create or switch to branches containing a dot at the end of a path component (like `features/team1/feature./1.0/main`). The error occurs when Git attempts to create the corresponding `.git/refs/heads` directory structure, as Windows prohibits directory names ending with dots.

The bug is reproducible with Git for Windows 2.42.0 and appears to be a filesystem limitation rather than a Git logic issue. The report includes clear reproduction steps showing the `fatal: cannot lock ref` error when attempting to switch to such branches.

This affects users on Windows systems who follow naming conventions that include trailing dots in branch path components. While the workaround would be to avoid such names, the report suggests this may be problematic when interacting with remote repositories (like GitHub Enterprise) where such branch names already exist.

The bug report is well-structured with clear expected/actual behavior comparison and includes relevant system information. This appears to be a legitimate platform-specific limitation that may require either documentation of the restriction or code changes to handle the Windows filesystem constraints.
