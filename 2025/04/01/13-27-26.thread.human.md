This thread began as a bug report about `git interpret-trailers` silently rejecting trailer keys containing periods (like "My-6.11-Version"), which Junio Hamano confirmed was intentional behavior for reliability. Kristoffer Haugsbakk then submitted an 11-patch documentation series (now merged to `master` as `kh/doc-trailers`) that comprehensively overhauls the `git-interpret-trailers` man page to clarify the strict parsing rules and improve usability.

The series explicitly defines valid trailer keys as ASCII alphanumeric characters plus hyphens only, standardizes terminology ("trailer block," "metadata" singular), removes outdated RFC 822 references, and provides clear examples of valid and invalid usage. Key improvements include structural reorganization for better narrative flow (like grouping contiguous explanations of trailer addition), explicit clarification that the command operates on any text (not just commit messages), and detailed documentation of comment handling via `core.commentString`.

This ninth patch in the series (v5) focuses on cementing the "trailer block" terminology by systematically replacing looser phrasing throughout the DESCRIPTION section. It resolves ambiguity about blank line insertion (now clearly tied to creating new trailer blocks) and clarifies that trailer blocks always appear at the end of input, either before a `---` line or at the very end. The series was merged after minor procedural hiccups (including a missing Message-ID in v4 and a "What's cooking" oversight) and a final trivial v5 iteration addressing a grammatical nit. The thread is now effectively closed, with only low-priority stylistic debates remaining open for potential future adjustment.
