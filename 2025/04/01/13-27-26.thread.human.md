This thread addressed a bug report about `git-interpret-trailers` failing silently when trailer keys contained periods (like "My-6.11-Version"), which some kernel developers use for version tracking. The discussion revealed this strict parsing (alphanumeric + hyphen only) was intentional to prevent false positives, though undocumented. Maintainer Junio Hamano firmly supported keeping the strict rules, rejecting configurable leniency due to reliability concerns.

Kristoffer Haugsbakk's documentation patch series (now in v2) explicitly documents the allowed key characters, resolving the original issue. The latest exchange refines presentation details: replacing a Unicode symbol with ASCII alternatives and discussing how best to explain the colon delimiter format. While Junio suggested referencing email-header conventions for context, Kristoffer argues the current normalized `:SP` form is clearer. The thread is now in its final polishing stage, with all substantive decisions settled—strict key parsing stays, but with proper documentation. The version-tracking use case remains valid but would need alternative solutions that don't relax the parser's rules.
