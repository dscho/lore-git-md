This is a bugfix series for gitk, part of the ongoing effort to resolve Cygwin-specific regressions caused by Windows security changes. The patches follow up on previous discussion about stack exhaustion issues in Cygwin environments, where Windows-specific PATH search overrides were incorrectly affecting Cygwin's POSIX-like behavior.

The series restricts Tcl's exec/open overrides to Windows-only operation, which both fixes the Cygwin breakage and prevents similar issues on other non-Windows platforms. The changes maintain Windows security protections (addressing CVEs from 2022-2023) while restoring proper behavior elsewhere. 

Key improvements in v2 include fixing a commit reference, improving commit messages, and adding two new patches: one to remove a now-redundant `_search_exe` variable (following Johannes Sixt's suggestion), and another to optimize PATH searching by skipping it for relative paths like "foo/bar". The changes are focused and well-motivated, with clean 88/58 line diff showing substantial code simplification.

This appears ready for final review, with parallel git-gui changes likely to follow the same pattern. The solution preserves security where needed while properly isolating platform-specific behavior.
