This is a technical review comment in the ongoing series about bitmap acceleration for `git cat-file` batch operations. Toon Claes raises a question about pointer comparison in the newly introduced `bitmap_index_contains_pack()` function, which checks whether a pack is bitmapped.

The function currently compares pack objects by their memory addresses rather than by some more stable identifier. Toon questions whether this is standard practice in the Git codebase and whether it might cause issues, particularly with the ongoing effort to remove `the_repository` global variable usage. This appears to be a careful, thoughtful review point rather than a criticism - Toon is asking for clarification about a design choice that might have subtle implications.

The question comes in the context of a well-developed series that has already seen significant review and iteration (now at v6), with demonstrated performance improvements of up to 41x for certain operations. The specific patch being discussed is an earlier foundational piece (v2 08/10) that introduced core bitmap checking functionality.
