This is a follow-up discussion on a build system fix for gitweb's JavaScript generation, part of Patrick Steinhardt's v2 build system fixes series. The original patch (v2 2/5) corrected a Makefile rule that was incorrectly including the build script itself in the concatenated JavaScript output by using `$(filter %.js,$^)`.

Johannes Schindelin suggests a more robust approach: using `$(filter-out %.sh,$^)` instead. His reasoning is forward-looking - this would prevent potential issues if JavaScript files were ever renamed with extensions other than `.js` (like `.cjs`), while still excluding the `.sh` build script. The comment maintains the patch's purpose while proposing a more maintainable solution that anticipates possible future changes to file naming conventions.

The exchange shows careful consideration of edge cases in build system maintenance, with an experienced contributor offering a subtle improvement to an already-solid fix. This level of attention to detail is characteristic of Git's build system discussions, where even one-line changes receive thorough review for long-term maintainability.
