This is a technical suggestion in the ongoing HTTP keepalive configuration series. Jeff King (Peff) proposes refactoring the new `set_long_from_env()` helper function to reuse Git's parsing infrastructure from parse.[ch] rather than implementing custom strtol() handling. 

The suggestion would extend parse.[ch] with a new `git_parse_long()` function, providing more robust parsing (including unit support like "K" for kilobytes) while simplifying the HTTP code. Peff notes this would also clean up some legacy speed limit parsing code. He considers but rejects using `git_env_long()` due to its die()-on-error behavior being too harsh for this case.

This comes as a well-reasoned refinement to patch 2/4 in the series, which had already received positive feedback from other reviewers. The suggestion maintains the series' goals while improving code reuse and parsing robustness. It represents the kind of final polishing this mature patch series is undergoing before merging.
