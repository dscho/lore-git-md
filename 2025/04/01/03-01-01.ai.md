This is part 2/3 of Mark Levedahl's patch series addressing Cygwin-specific regressions in gitk, following up on the thread about Windows security changes affecting Cygwin. The patch removes the now-unnecessary `_search_exe` variable from gitk's Tcl code.

The change simplifies the executable search logic by eliminating a variable that was only needed when supporting both Windows and non-Windows platforms in the same code path. Since the previous patch in the series restricted the Windows-specific overrides to actual Windows systems (excluding Cygwin), the variable becomes redundant - we can just hardcode `.exe` for Windows systems directly where needed.

The technical change is straightforward: removing the global variable declaration, its initialization, and replacing its one usage with the literal `.exe` suffix. This affects the `_which` function that handles executable lookup on Windows, part of gitk's command execution pipeline. The patch maintains all existing functionality while reducing complexity.

This cleanup was made possible by the series' earlier separation of Windows and Cygwin handling, demonstrating how the architectural change in patch 1/3 enables these simplifications. The change is small (5 lines modified) and focused, with no behavior change for Windows users while removing obsolete code paths.
