Performance optimization patch addressing O(N^2) scaling in bundle creation. This is the second part of Karthik Nayak's series, following the test coverage patch.

The patch replaces the quadratic duplicate-checking algorithm in `object_array_remove_duplicates()` with an O(1) `strset`-based solution in `write_bundle_refs()`. The change yields a dramatic 6x speedup in repositories with many refs (benchmarked at 100k refs, going from ~14.6s to ~2.4s). The optimization works by tracking seen refnames in a string set rather than comparing each ref against all others.

The commit explains why checking just refnames (without object comparisons) is sufficient for bundle creation, covering cases like duplicate refs, exclusion patterns (`master^!`), and short/long name variants. The patch removes the now-unused `object_array_remove_duplicates()` function entirely and updates tests that previously expected duplicate refs in the bundle output.

This appears to be a well-considered optimization with clear performance benefits, thorough explanation of the approach, and matching test updates. The series as a whole addresses a known scaling pain point for repositories with large numbers of references.
