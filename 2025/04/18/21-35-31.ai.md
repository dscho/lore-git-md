This is a test modernization patch that has introduced a regression in the Git-P4 integration tests. The patch in question (aw/t9811-modernize) added more precise tag import verification to t9811, including a negative test case expecting that a Perforce tag (TAG_F1_ONLY) would not be imported by git-p4. However, the test is now failing on both macOS CI and Linux systems with p4 installed, as the tag is actually being imported successfully.

The test's original comment suggests this tag type wasn't expected to be importable "at least not easily", implying this might represent either a bug fix in git-p4 (now correctly importing previously unhandled tags) or an unintended behavior change. Jeff King suggests reverting the failing portion of the test until the git-p4 maintainers can investigate further, noting this isn't his area of expertise. The patch had been marked for merging to 'next' in Junio's "What's cooking" update, but this newly discovered issue may delay that.

Key technical details: The failing test checks for absence of refs/tags/TAG_F1_ONLY via `git show-ref --verify`, but finds the tag present. This relates to git-p4's tag import behavior, though it's unclear whether the current behavior is correct or buggy. The test file is t/t9811-git-p4-import-tags.sh, part of the Perforce integration test suite.
