This is a follow-up in the bugfix thread about `git help` error message formatting. Keith Thompson acknowledges Junio C Hamano's point that the issue is more nuance than initially thought - while subcommand man pages use hyphens (git-add), documentation guides don't (gitglossary). The error message can't know whether a nonexistent argument was meant as a command or guide.

Thompson explores four potential approaches, favoring the simplest - always assuming unknown arguments are subcommands and hyphenating them, despite occasional incorrect guesses. The other options (dual-format error messages, changing guide naming conventions, or creating symlinks) are deemed either impractical or not worth the complexity for this minor cosmetic issue.

The thread shows the patch evolving from a straightforward fix to recognizing a documentation system design constraint, with the author now leaning toward a pragmatic compromise that will be correct most but not all of the time. The discussion remains technical and constructive, with no clear resolution yet.
