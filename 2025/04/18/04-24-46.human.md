This is a discussion thread about test coverage for bitmap lookup tables in Git's performance test suite. Junio C Hamano responds to Taylor Blau's patch series that removes performance tests for bitmap configurations without lookup tables (now the default).

Junio expresses reservations about completely removing tests for the non-default configuration, comparing the situation to the ongoing recursive-ort transition. He suggests that while removing underperforming variants is good long-term (as with recursive/ort), we should maintain test coverage for escape-hatch configurations until we're fully confident in the new default. His tone is constructive but firm, emphasizing that if we still support both code paths, we should test both.

The exchange highlights an important philosophical question about test maintenance - when to remove redundant tests versus keeping coverage for supported-but-non-default configurations. Junio's position leans toward conservatism, wanting to ensure the escape hatch remains functional if needed. This continues the thread's broader discussion about balancing test suite cleanliness with comprehensive coverage.
