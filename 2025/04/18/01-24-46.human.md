This is a discussion about a proposed bugfix for `git help`'s error message formatting. Junio Hamano responds to Keith Thompson's report about the missing hyphen in "No manual entry" errors for nonexistent commands.

The core issue is whether `git help` should always use hyphens in its error messages (e.g. "git-nosuchcommand") to match subcommand man page conventions, or whether it should sometimes omit them to match documentation pages like "gitglossary". Hamano points out the ambiguity - when users type `git help foo`, Git can't know if they wanted a subcommand (which would be hyphenated) or a concept guide (which wouldn't).

The response suggests this isn't a straightforward bugfix, as the current behavior is actually correct in some cases. This appears to be more of a design question about how to handle the ambiguity in `git help`'s interface rather than a simple formatting error. The discussion seems likely to continue as participants weigh the tradeoffs between consistency and accuracy in different scenarios.
