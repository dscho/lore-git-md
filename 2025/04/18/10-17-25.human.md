This is a technical discussion about performance test optimization in the ongoing bitmap lookup tables series.

Jeff King (Peff) responds to Taylor Blau's patch that removes `test_perf` from the setup phase of bitmap performance tests. While agreeing with the general direction, Peff points out deeper issues with how the tests currently measure bitmap writing performance. He notes that the current approach of reusing the same pack across test runs may skew results by measuring mostly no-op repacks rather than the initial bitmap generation.

Peff references prior work (commit 775c71e) that addressed similar measurement problems by resetting repo state between runs, though he doesn't propose a specific solution here. He also notes that the same issue exists in t5326's multi-pack-index bitmap tests, suggesting any fix should be consistent across both test files.

The discussion continues the challenge of accurately measuring performance in Git's test suite, particularly for operations that mutate repository state. While Peff doesn't object to the immediate change, he provides important context about the limitations of the current approach and potential blind spots in performance measurement.
