This is a discussion about performance test coverage for bitmap lookup tables in the ongoing series to make them default. Jeff King (Peff) responds to Junio Hamano's concerns about removing tests for the non-default (no lookup table) configuration.

Peff argues that performance tests differ from correctness tests in that their value comes from comparing versions rather than individual runs. He suggests the current approach - testing only the new default configuration - is sufficient because:

1. The key performance comparison (old vs new behavior) is already captured when testing the patch series itself
2. Future regressions will be caught by testing the default configuration
3. The cost of maintaining dual-configuration tests is high (doubling test runtime)
4. The non-default path is unlikely to regress in ways that wouldn't also affect the default path

He acknowledges this creates a "blind spot" for non-default configurations but notes this is already a general limitation of the performance test framework. The time savings are substantial - from 60 minutes down to 30 for some tests.

This continues the thread's discussion about balancing test coverage with maintenance burden, with Peff taking a pragmatic stance favoring reduced test overhead now that lookup tables are becoming the default.
