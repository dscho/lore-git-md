This is a follow-up in the ongoing discussion about `git help` error message formatting. Jeff King (Peff) responds to Keith Thompson's proposed solutions for the hyphenation inconsistency in "No manual entry" errors.

Peff identifies the core challenge: Git doesn't actually know whether an argument is meant to be a command or topic when passing it to `man`, since it lacks a complete list of documentation topics. He analyzes several technical constraints:

1. The error message comes from `man` itself, making direct control difficult
2. `man` exit codes might not be reliable across implementations
3. Alternative documentation viewers (HTML, info) complicate error detection
4. Pre-checking topic existence would require maintaining a static list and wouldn't handle third-party docs

Peff suggests but rejects the idea of showing intermediate warnings about the lookup attempt, as they would create noise for successful lookups. He also notes the impracticality of dynamically detecting available documentation topics like Git does for commands.

The response highlights the tension between precise error messages and the realities of documentation system integration, suggesting the problem may not have a clean solution that satisfies all constraints. Peff's analysis implies the current behavior, while imperfect, may be the least bad option given the technical limitations.
