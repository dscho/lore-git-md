This is a follow-up in the bugfix thread about `git help` error message formatting. Keith Thompson responds to Junio Hamano's observation that the issue is more complex than initially thought, as `git help` handles both subcommands (which use hyphenated man page names like `git-add`) and documentation topics (which use unhyphenated names like `gitglossary`).

The email explores four potential solutions to the hyphenation inconsistency in error messages for nonexistent help topics:
1. Default to assuming unknown arguments are subcommands (hyphenated), accepting some incorrect messages for actual topics
2. Attempt to cover both cases in the error message (rejected as too complex)
3. Standardize all man page names to use hyphens (acknowledged as breaking long-standing practice)
4. Create symlinks for topic man pages (considered too confusing and not worth the effort)

Key technical points:
- The current behavior stems from `git help` not knowing whether an unknown argument was meant as a command or topic
- The error message comes directly from the `man` command, limiting formatting options
- The author leans toward solution #1 as the most practical despite its imperfections

The discussion reveals this is more a design tradeoff than a straightforward bug, weighing consistency against practicality. The thread shows no clear consensus yet, with the maintainer having raised concerns about creating new inconsistencies while the original reporter acknowledges the complexity.
