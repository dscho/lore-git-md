This is a technical discussion about performance test coverage for bitmap lookup tables, continuing the thread about Taylor Blau's series to enable them by default.

Jeff King responds to Junio C Hamano's concerns about removing performance tests for the non-default (no lookup table) configuration. He makes several key points: performance tests derive their value from comparisons between versions rather than absolute timings, so the important baseline is already captured by comparing pre- and post-lookup-table versions. Going forward, the test suite will naturally exercise the new default configuration, while still allowing custom configurations via repo settings. 

King acknowledges this creates a potential blind spot if nobody tests non-default configurations, but argues this is a general limitation of the perf suite given the combinatorial explosion of possible configurations. He notes the significant time savings from removing duplicate test runs - up to halving the runtime for some tests like p5310 from 60 to 30 minutes with default settings.

The discussion touches on the broader philosophy of test coverage versus maintenance burden, with King taking a pragmatic stance that the perf improvements justify focusing on the default path. This continues the thread's theme of balancing architectural concerns with practical optimization, now specifically addressing test suite design rather than the core bitmap implementation changes.
