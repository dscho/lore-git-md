This is a technical discussion about maintaining consistency between bitmap flags in Git's multi-pack-index and pack-objects subsystems. Jeff King responds to Junio Hamano's concern about keeping the MIDX_WRITE_BITMAP_* and BITMAP_OPT_* flags synchronized when changing defaults.

Jeff explains that while the flags don't technically need to be identical, in practice they should stay aligned since there's no current reason for divergence. He proposes a refactoring that would separate bitmap options from other midx flags, allowing both subsystems to share a common definition. The included patch demonstrates this by:
- Adding a bitmap_options field to the midx opts struct
- Modifying config handling to use BITMAP_OPT_* flags directly
- Plumbing the new parameter through all midx-related functions

The change is conceptually clean but requires touching many midx functions. Jeff acknowledges this might be overkill for something that rarely changes, though it would eliminate the translation layer in write_midx_bitmap(). The discussion continues the thread's theme of ensuring robust maintenance as bitmap features evolve.
