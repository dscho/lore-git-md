This is a bugfix patch for the files backend that addresses a security issue with symbolic reference validation.

The patch fixes a case where malformed symbolic references (like "refs/../HEAD") could be created, potentially allowing reference and lock files to be written outside the intended refs/ directory. The provided example demonstrates how this could lead to confusing error messages about lock file conflicts when in fact the issue is an invalid reference path.

The fix adds validation in the files backend to check symbolic reference names before updates, preventing creation of references with paths attempting to escape the refs directory. The change is relatively small (10 lines added) and focused on the files-backend.c file.

This appears to be a legitimate security hardening measure that closes a potential vector for repository corruption or confusion. The commit message clearly explains the issue and provides a concrete reproduction case from a bug report. The fix seems straightforward and targeted at the core issue without introducing significant complexity.
