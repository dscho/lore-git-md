Refactoring patch in the `git-history` series that improves commit parsing safety in shared replay infrastructure.

This patch modifies `replay_pick_regular_commit()` in `replay.c` to explicitly parse commits before accessing their fields. The change makes the function more robust when called from external code paths by ensuring commit objects are fully populated before use. While existing call paths already implicitly parsed commits, this hardening prevents potential issues as the function becomes part of shared infrastructure.

The change is small (3-line addition) but meaningful for API safety, particularly as this code moves toward being reusable infrastructure. It follows good practice of explicit parsing before commit access, similar to patterns seen elsewhere in Git's codebase. The patch continues the series' trend of improving the robustness and shareability of the history editing components.

Key technical details:
- Adds `repo_parse_commit()` call at start of `replay_pick_regular_commit()`
- Protects against unparsed commit access when called from new contexts
- Maintains existing behavior for current callers (who already parsed commits)
- Part of making replay infrastructure more robust and reusable
- Follows established Git patterns for commit object access

This change aligns with the series' broader goal of building reliable shared infrastructure for history operations while being a straightforward improvement that reviewers are likely to accept.
