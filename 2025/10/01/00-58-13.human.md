This is an RFC proposal for extending Git's tree format to handle mixed-hash submodules and conflicts, presented as a discussion starter rather than a serious implementation plan.

Brian M. Carlson shares a prototype exploring a potential tree format extension that came up during Contributor Summit discussions. The proposal aims to address two needs: supporting submodules with different hash algorithms than their parent repository, and potentially first-class conflict handling. The email includes a shell script demonstrating how current Git would interpret such an extended tree entry, where a submodule entry contains additional metadata about its hash algorithm.

The patch itself adds documentation (a new asciidoc file) describing this hypothetical extended tree format. Carlson is clear this is just a thought experiment - the script is intentionally "a little gross" and triggers `git fsck` warnings as expected. The author emphasizes they're not planning to implement this seriously, but wants to gauge community reaction to this approach for handling hash algorithm transitions in submodules.

This appears to be an early-stage exploration of how Git might evolve to handle repositories with mixed hash algorithms, particularly focusing on the submodule case. The tone suggests the author expects some controversy around the approach but wants to make the discussion concrete.
