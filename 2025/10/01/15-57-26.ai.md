This is a feature patch series introducing a new `git-history` command for history editing operations, now at v4 with twelve patches. The series has been significantly slimmed down from previous versions based on discussions at the Git Contributor's Summit, focusing only on non-conflicting operations and dropping the `reword` implementation in favor of future sequencer-based approaches.

Key changes in v4:
- Rebased to resolve conflicts with Jeff King's add-i color work
- Reworked to use same infrastructure as `git-replay`
- Dropped hook execution handling (to be backfilled later)
- Removed `commit.verbose` handling (to be reconsidered)
- Keeps only the `reword` and `split` subcommands from the original proposal

The series introduces infrastructure for in-memory index manipulation and tree writing, then implements two subcommands:
1. `reword` to rewrite commit messages while preserving other commit details
2. `split` to interactively split a commit into two by selecting hunks

The implementation builds on Git's sequencer infrastructure while taking inspiration from Jujutsu's history editing capabilities. The patches show careful attention to edge cases like empty commits and merge conflicts, with thorough test coverage.

Notable technical details:
- New `wt-status` function to expose status for trees
- Extracted commit picking logic from replay
- Added in-memory index patching support
- `cache-tree` extension for writing in-memory indexes
- Careful handling of worktree/index state during operations

The series appears well-structured and the implementation looks solid, though some design questions remain about how these operations will integrate with the broader Git ecosystem. The decision to defer hook execution and some other features suggests this may see further refinement in future iterations.
