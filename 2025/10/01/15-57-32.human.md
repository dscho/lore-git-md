Feature implementation for the new `git-history` command's "reword" subcommand, part of Patrick Steinhardt's ongoing series to provide flexible history editing operations. This patch introduces the first user-facing subcommand that rewrites commit messages while preserving all other commit details (author, date, tree).

The implementation builds on shared infrastructure from earlier patches in the series, particularly the replay functionality. The "reword" command works similarly to an interactive rebase with a single "reword" instruction, but operates directly without requiring a rebase todo list. It handles edge cases like empty commit messages and merge commits (which it rejects), and includes thorough test coverage.

Key technical aspects include:
- Preserving worktree/index state during the operation
- Proper handling of commit ranges and ancestry checks
- Integration with the editor for interactive message editing
- Reuse of the shared replay infrastructure for applying rewritten commits
- Comprehensive test suite covering basic usage, edge cases, and hook behavior
