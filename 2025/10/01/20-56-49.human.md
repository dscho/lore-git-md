This is a documentation patch that clarifies how URL prefix matching works in Git's credential configuration. 

The patch updates the `gitcredentials` documentation to more accurately describe how path components are matched when configuring credentials for partial URLs. The key change is that paths are now matched as prefixes rather than requiring exact matches. For example, a credential configured for `https://example.com/bar/baz.git` will now match requests for `https://example.com/bar`, whereas before the documentation suggested this wouldn't work.

The commit notes this corrects documentation that has been inaccurate since commit 9a121b0d226 in 2020. The patch includes accompanying test updates that verify the documented behavior, adding more test cases to cover various URL prefix matching scenarios. The tests check both positive cases (where prefixes should match) and negative cases (where they shouldn't).

The changes appear straightforward and well-justified, with clear test coverage to prevent future regressions. This is a useful clarification for users configuring credential helpers, as the previous documentation didn't accurately reflect the actual matching behavior.
