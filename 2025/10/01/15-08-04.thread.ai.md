Thread identity: Bugfix patch addressing symbolic reference validation security issue in the files backend, now in discussion phase between Han Young, Junio C Hamano, Karthik Nayak, and Patrick Steinhardt.

Core problem: Malformed symbolic references (e.g. "refs/../HEAD") could bypass validation when manually editing `.git/HEAD`, allowing reference and lock files to be written outside intended directories. The issue is limited to manual repository edits since Git commands already validate refnames via `check_refname_format()`.

Current status: Architectural consensus fully established to centralize reference validation in `git refs verify` as the canonical source, with `git fsck` delegating to it while maintaining detection capabilities. Patrick Steinhardt provides additional justification for this pattern by comparing to similar verification commands in other Git subsystems (`commit-graph verify`, `multi-pack-index verify`, `bundle verify`). The immediate files-backend.c fix for symbolic reference validation will align with this broader change, implementing runtime validation in `split_symref_update()` to mirror fsck checks.

Key technical details: Fix targets `files-backend.c` in `split_symref_update()`, incorporating both `refname_is_safe()` and fsck's reference checking via `refs_resolve_ref_unsafe()`. The restructured validation hierarchy moves fsck's symbolic reference checks into `git refs verify` as single source of truth, following the established pattern of subsystem-specific verification commands. Solution maintains validation parity between runtime operations and repository checking tools.
