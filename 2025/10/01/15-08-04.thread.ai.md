Thread identity: Bugfix patch addressing symbolic reference validation security issue in the files backend, now in discussion phase between Han Young, Junio C Hamano, Karthik Nayak, and Patrick Steinhardt.

Core problem: Malformed symbolic references (e.g. "refs/../HEAD") could bypass validation when manually editing `.git/HEAD`, allowing reference and lock files to be written outside intended directories. The issue is limited to manual repository edits since Git commands already validate refnames via `check_refname_format()`.

Current status: Architectural consensus exists on centralizing reference validation logic, but command interface design remains under discussion. Junio Hamano suggests implementing verification as fsck sub-options (`git fsck --refs-only`) rather than standalone commands (`git refs verify`), drawing a distinction between independently verifiable artifacts (bundles) and repository-internal components (refs). Patrick Steinhardt maintains that subsystem verification commands follow established patterns seen with `commit-graph verify` and `multi-pack-index verify`. The immediate files-backend.c fix for symbolic reference validation will proceed regardless of this interface discussion.

Solution maintains validation parity between runtime operations and repository checking tools regardless of final command structure.
