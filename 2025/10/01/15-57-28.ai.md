This is a refactoring patch in the `git-history` command series, specifically extracting commit-picking logic from `builtin/replay.c` into a new shared `replay.c` file. The change prepares for reuse by the upcoming `git-history` command while maintaining existing `git-replay` functionality.

The patch moves three key functions from the replay builtin to the new shared file:
1. `short_commit_name()` - Gets abbreviated commit hashes
2. `create_commit()` - Handles commit object creation
3. `pick_regular_commit()` (renamed to `replay_pick_regular_commit()`) - Core logic for selecting and replaying commits

The extraction follows clean separation of concerns, with the builtin now calling the shared `replay_pick_regular_commit()` function through the new `replay.h` interface. The implementation appears technically sound, maintaining all existing behavior while adding proper subsystem prefixes to the moved functions. Build system files (Makefile, meson.build) are updated to include the new source file.

This change is part of the larger effort to share infrastructure between `git-replay` and the proposed `git-history` command, as discussed in the thread. The patch shows good attention to detail with:
- Preserved functionality through careful function migration
- Clear subsystem boundaries via the `replay_` prefix
- Minimal diff noise by keeping the original logic intact
- Proper build system integration

The change is purely structural with no behavior modifications, making it a low-risk preparation step for the series. Future patches will build on this shared infrastructure for the new history editing commands.
