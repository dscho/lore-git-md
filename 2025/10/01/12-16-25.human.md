This is a discussion contribution about worktree status performance implications in Git.

Ben Knoble weighs in on the ongoing thread about whether Git should hide worktree directories from status output. The discussion has centered around whether reading worktree lists during status operations would create noticeable performance overhead. While Michal Suchánek argued the impact would be minor since status operations are already non-trivial, Knoble points out that status information is often used for shell prompts, where performance is particularly sensitive.

The email doesn't introduce new technical details but highlights an important real-world use case (shell prompt integration) that could be affected by any changes to status behavior. This reinforces the need to carefully consider performance implications before modifying how worktrees are handled in status output. The contribution helps ground the theoretical discussion in practical user experience concerns.
