This is a workflow discussion email from Junio C Hamano in response to Henrique Soares's question about Git maintainer patch review practices. The thread has previously covered historical workflows (Jeff King's 2016 approach) and modern tooling (`b4`).

Junio emphasizes that patches are primarily a transmission medium, not the review medium. He suggests applying patches locally (either to a topic branch or detached HEAD) to enable using normal development tools for review. This addresses the core challenge of reviewing changes that span long functions or have wide-ranging effects.

Key technical aspects:
- Implicit endorsement of local patch application as fundamental to review
- Neutral stance on specific tools (branch vs detached HEAD)
- Focus on understanding change propagation through code flow
- Contrast with email-only review limitations

The email advances the thread by providing the maintainer perspective that review fundamentally happens in the local Git environment rather than in email clients, while remaining tool-agnostic about the exact workflow. This positions the earlier `b4` discussion as one possible way to get patches into that local environment.
