This is a technical clarification in the ongoing Git 3.0/SHA-256 interoperability discussion. Brian m. carlson responds to Michal Suchánek's questions about the practical necessity of SHA-1/SHA-256 interoperability work, explaining the key use cases where it matters.

The email clarifies that interoperability is primarily needed for converting repositories between hash algorithms or working across repositories using different algorithms. Brian notes that if users are content working within a single algorithm (either SHA-1 or SHA-256), the interoperability work isn't strictly necessary, as SHA-256 repositories have been properly supported since Git 2.29/2.30.

Brian also addresses a specific concern about cloning behavior, confirming that repositories will always clone using their existing hash algorithm, and that the default change for new repositories (via `git init`) won't affect existing ones. This provides concrete technical details to complement the broader strategic discussion about release timing and ecosystem readiness.

The response helps ground the abstract planning discussion in practical user scenarios, though it doesn't advance the core debate about whether to delay Git 3.0 for this work. The tone is informative and patient, clearly explaining concepts that may not be obvious to all users following the thread.
