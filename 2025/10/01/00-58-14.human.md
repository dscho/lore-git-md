This is an RFC proposal for an extended tree format in Git, building on the earlier discussion about hash algorithm interoperability. Brian Carlson proposes a new tree entry format using mode 130000 to store additional metadata in a backwards-compatible way, primarily targeting two use cases: conflict tree representation and extended submodule support (particularly for mixed-hash scenarios like SHA-256 submodules in SHA-1 repositories).

The patch adds documentation for the proposed format, which would encode extra information by carefully crafting tree entries that older Git versions would interpret as slightly malformed (due to non-zero bytes in what they'd consider part of the filename). The specification describes a modified BER encoding scheme and defines object types for conflict trees and extended submodules, along with criticality flags.

The proposal is intentionally designed to be minimally incompatible while exploring Git's extensibility boundaries. It's presented as a thought experiment rather than an implementation plan, with the documentation serving as a concrete starting point for further discussion about how Git might handle these advanced use cases. The technical details are well-specified, showing careful consideration of backwards compatibility and parsing requirements.
