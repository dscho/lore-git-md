Refactoring patch in the `git-history` series, focusing on the interactive add/patch infrastructure. This is patch 09/12 in v4 of the series.

The patch removes the dependency of `add-patch.c` on the `add-interactive` subsystem by directly managing the interactive configuration within `add_p_state` rather than inheriting it from `add_i_state`. Key changes include:

- Replaces the embedded `add_i_state` struct with direct `repository*` and `interactive_config` members in `add_p_state`
- Updates all references from `s.s.cfg.*` to `s.cfg.*` throughout the code
- Changes initialization from `init_add_i_state()` to `interactive_config_init()`
- Updates cleanup to use `interactive_config_clear()` instead of `clear_add_i_state()`
- Maintains all existing functionality while reducing subsystem coupling

The refactoring is part of the broader effort to support the new `git-history` command's `reword` subcommand while improving code organization. This change follows the preparatory work in patch 08/12 that split out the shared interactive configuration. The patch appears thorough, with consistent updates to all affected code paths and no obvious omissions in the conversion.

Technical details affected:
- `struct add_p_state` layout change
- Color handling paths (`error_color`, `reset_color_interactive`, etc.)
- Diff configuration (`context`, `interhunkcontext`, `diff_algorithm`)
- Index operations now use direct `r` pointer
- Prompt and help text display logic
- Patch application workflow

The change is a structural improvement that reduces cross-component dependencies while maintaining identical behavior. It represents another step in the series' goal of building flexible history editing operations on cleaner internal abstractions.
