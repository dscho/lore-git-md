This is a refactoring patch in Patrick Steinhardt's ongoing `git-history` series (v4 10/12). It adds support for applying patches to an in-memory index rather than always using the repository's main index, a capability needed for the upcoming history editing functionality.

The patch introduces a new `run_add_p_index()` function that mirrors the existing `run_add_p()` but operates on a caller-provided index state and index path. The implementation carefully maintains the same behavior while allowing the index operations to target an alternate location. The changes include updates to index handling throughout the patch application process and proper cleanup of temporary state.

This appears to be a well-constructed piece of infrastructure work - the commit message clearly explains the change, the implementation follows existing patterns, and it maintains backward compatibility. The patch is part of a larger effort to build robust history editing tools, with this particular piece enabling more flexible index manipulation that will be used in subsequent commits.
