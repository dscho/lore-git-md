This is a feature patch adding a "split" subcommand to the proposed `git-history` command, completing the v4 series. The new subcommand simplifies splitting a commit into two by interactively selecting which changes to move to a new parent commit.

The patch implements a workflow that currently requires multiple rebase steps into a single `git history split $COMMIT` command. Users interactively select hunks to split out (using the same interface as `add -p`), then provide a commit message for the new commit. The original commit is rewritten to sit atop the new split-out commit, preserving the remaining changes.

Key technical details:
- Uses the interactive add-patch infrastructure refactored earlier in the series
- Handles edge cases (empty splits, merge commits, root commits)
- Preserves authorship and timestamps
- Includes comprehensive tests covering various split scenarios
- Integrates with the series' existing commit rewriting machinery

The implementation appears thorough, with careful attention to edge cases and user experience. The 432-line test file provides extensive coverage of the functionality.
