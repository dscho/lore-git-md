This is a documentation patch that clarifies URL prefix matching behavior in Git credentials configuration, accompanied by corresponding test updates.

The patch corrects and expands the documentation in gitcredentials.adoc regarding how partial URL patterns match against credential configurations. The key change is clarifying that path components must match as prefixes - so `https://example.com/bar` will match a config entry for `https://example.com/bar/baz.git` but not for `https://example.com/barry/repo.git`. This fixes inaccuracies introduced in commit 9a121b0d226 from 2020.

The accompanying test changes in t/t0300-credentials.sh significantly expand the test cases to verify the prefix matching behavior works as documented. It adds positive test patterns that should match (like various prefix forms of the URL) and negative cases that shouldn't (like partial path segments or incorrect prefixes). The test uses a credential helper that simply echoes a password to verify matches.

The patch appears well-constructed with a clear commit message linking to the original bug, focused documentation changes, and thorough test coverage of the documented behavior. The changes are limited to documentation and tests, with no implementation changes needed since the behavior was already working as now documented.
