This patch implements the "reword" subcommand for the new `git-history` command, which allows rewriting commit messages while preserving all other commit metadata. It's part of the v4 series introducing history editing operations inspired by Jujutsu.

The implementation handles both direct message specification via `-m` and interactive editing when no message is provided. It properly maintains the commit chain by:
1. Validating the target commit is reachable from HEAD
2. Collecting all commits that would need to be reapplied
3. Creating a new commit with the updated message
4. Replaying subsequent commits on top of the rewritten one

The patch includes thorough test coverage for various scenarios:
- Rewording tip, middle, and root commits
- Merge commit detection
- Worktree/index state handling
- Empty message prevention
- Editor interaction

Key technical details:
- Uses shared `replay.c` infrastructure from earlier patches
- Introduces `wt_status_collect_changes_trees()` for tree-to-tree diffs
- Maintains original authorship and parent relationships
- Handles edge cases like empty commits
- Explicitly avoids hook execution (for now)

The implementation appears robust with careful error handling and thorough test coverage. It builds on the series' shared infrastructure while cleanly implementing the specific reword operation. The documentation clearly explains the command's behavior and limitations.
