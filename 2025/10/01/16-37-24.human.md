This is a technical discussion about the proposed extended tree format specification, focusing on implementation details and potential edge cases. Junio C Hamano responds to Brian Carlson's RFC with several thoughtful questions about the design.

The email examines three key aspects of the proposal: the BER-like encoding scheme for extended tree entries, sorting behavior of these entries, and future extensibility concerns. Hamano questions whether the prepended binary data affects tree entry sorting (it shouldn't, per the design) and expresses reservations about using BER encoding for debuggability. He also explores how the format would handle complex merge cases like criss-cross merges with multiple stage entries.

The discussion remains constructive but surfaces important technical considerations that would need resolution before implementation. Hamano's closing remark ("it does look ugly") suggests the format may need refinement despite solving real problems.
