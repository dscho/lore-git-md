This is a continuation of the ongoing discussion about git-worktree behavior and UX, specifically addressing the mental model differences between worktrees and submodules. Junio Hamano responds to Jakub T. Jankiewicz's comparison of worktree and submodule directory structures, reinforcing the fundamental design philosophy of worktrees.

The email clarifies that worktrees are intentionally designed to appear outside the primary working area, serving as separate instantiations of the project rather than being tied to the main repository like submodules. Junio emphasizes this distinction is core to worktrees' purpose - allowing parallel work on different branches without affecting the primary checkout.

Key technical clarification includes:
- Worktrees are meant to materialize branch contents in separate filesystem locations
- This differs fundamentally from submodules which are bound to the superproject
- The design assumes worktrees will be peers rather than nested under the main worktree

The response maintains Junio's consistent position on worktree design while addressing a specific point of user confusion. It highlights the ongoing challenge of communicating worktree/submodule differences to users, which has been a recurring theme in this thread. No new technical proposals are made, but the exchange reinforces the need for clearer documentation about worktree philosophy and usage patterns.
