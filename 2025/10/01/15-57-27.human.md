Infrastructure patch for the `git-history` series, adding tree diff functionality to wt-status.

This is the first patch in Patrick Steinhardt's v4 series introducing the new `git-history` command. It adds a new function `wt_status_collect_changes_trees()` that diffs two arbitrary trees and formats the changes in the same style as working tree status output. While this stretches the "working tree" status concept slightly, it avoids duplicating diff formatting logic that will be needed for the upcoming history editing operations.

The implementation builds on existing wt-status infrastructure, reusing the callback mechanism from working tree status collection. The new function will be used in later patches for the `reword` and `split` subcommands of `git-history`. This appears to be a clean, focused addition that properly extends rather than duplicates existing functionality.

As an infrastructure patch, it doesn't yet implement any user-facing features, but provides necessary plumbing for the series. The commit message clearly explains the motivation and how this fits into the larger effort. The implementation looks straightforward and well-contained, with proper header file declarations and no obvious technical issues.
