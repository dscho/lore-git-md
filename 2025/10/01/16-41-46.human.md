Maintainer workflow discussion: Junio Hamano responds to questions about patch review practices with practical advice about applying patches locally.

Junio Hamano (Git's lead maintainer) provides a straightforward perspective on reviewing patches, emphasizing that the email format is just a transmission medium. He notes that even small patches can be challenging to review in isolation when they affect complex code flows. His key advice is to apply patches locally (either to a topic branch or detached HEAD) where reviewers can use their normal development tools for inspection.

This continues the thread exploring maintainer workflows, but where previous responses focused on specific tools (like `b4`), Junio takes a more philosophical approach - treating patches as input to be moved into a developer's normal working environment. The response suggests that while tooling helps, the core review process remains fundamentally about applying changes and examining them with standard code navigation techniques. This perspective from the project's lead maintainer carries weight, though it doesn't introduce new concrete tools or methods beyond what was previously discussed in the thread.
