Feature patch series implementing configuration value parsing in Rust libgit implementation, now at v4 with platform-specific type handling discussion.

Phillip Wood provides review feedback on the v4 patch adding boolean, unsigned long, and pathname parsing to the Rust libgit ConfigSet API. The main technical concern raised is about platform-specific handling of `c_ulong` types in Rust versions prior to 1.64 (specifically Debian oldstable's Rust 1.63). The current implementation assumes `u64` for the fallback `c_ulong` definition, which may not match C's platform-dependent `ulong` size.

Wood suggests splitting the change into two parts: first updating the existing fallback definitions to use `std::os::raw` types (which were available before Rust 1.64's `std::ffi` additions), then adding `c_ulong` support in a separate change. This would maintain compatibility while properly handling platform-specific type sizes. The reviewer also notes it would be helpful to document why path parsing requires UTF-8 encoding in the commit message.

The feedback indicates general approval of the implementation ("apart from that I think this looks good") while focusing on this remaining technical refinement needed for proper cross-platform support. The thread shows the patch series has addressed previous concerns about documentation separation, symbol exports, and commit organization, with this platform-specific type handling being the primary outstanding issue.
