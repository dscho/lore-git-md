Feature patch for Rust libgit configuration parsing, now addressing platform-specific type handling.

Phillip Wood provides a review of the v4 patch adding boolean, unsigned long, and pathname parsing to the libgit-rs ConfigSet API. While generally approving the implementation, he identifies one remaining issue with platform-specific handling of `c_ulong` types in Rust versions before 1.64 (specifically Debian oldstable's Rust 1.63).

The key technical concern is that the current fallback definition assumes `c_ulong` is always 64-bit, which isn't true across all platforms. Phillip suggests splitting this into two patches: first updating the existing fallback definitions to use `std::os::raw` types (which were available before Rust 1.64), then adding the new `c_ulong` support separately.

This represents the last significant feedback point for this otherwise well-reviewed series. The author has already addressed all prior concerns, including separating out documentation fixes and consolidating to a single commit. The pathname UTF-8 encoding rationale is noted as something that could be better explained in the commit message.

The patch appears ready for merging once this final platform-compatibility issue is resolved, with Phillip's suggestion providing a clean solution that maintains compatibility with older Rust versions while correctly handling platform-specific type sizes.
