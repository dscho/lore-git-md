This is the first patch in a 12-part series introducing new history editing functionality. It adds infrastructure to support the planned `git-history` command by extending the `wt-status` subsystem.

The patch introduces a new function `wt_status_collect_changes_trees()` that diffs two arbitrary trees (rather than comparing against the working tree/index as existing status functions do). This will be used by subsequent patches to show changes between commits during history editing operations. The implementation reuses the existing diff callback infrastructure from working tree status collection.

Key technical details:
- New function takes two tree OIDs and collects changes between them
- Uses same callback mechanism as working tree status
- Preserves existing rename detection configuration
- Part of building blocks for `git-history` command's `reword` and `split` subcommands
- Follows same pattern as existing status collection but generalized for arbitrary trees

The change is cleanly implemented and well-motivated as infrastructure for the larger series. It maintains consistency with existing status collection while extending it for the new use case. The patch appears ready for review with no obvious issues.
