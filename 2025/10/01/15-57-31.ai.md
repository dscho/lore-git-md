This is the fifth patch in Patrick Steinhardt's v4 series introducing a new `git-history` command, which provides imperative history editing operations building on Git's sequencer infrastructure. The patch establishes the basic command skeleton and documentation.

The implementation adds the core command structure with a minimal implementation that currently just handles argument parsing and basic error cases. The documentation positions `git-history` as an experimental alternative to `git-rebase` for specific common operations like reordering, splitting, dropping, and squashing commits, though the actual subcommands will be implemented in later patches. The doc explicitly notes current limitations (no merge support) and experimental status.

Key technical additions include:
- New `builtin/history.c` implementing the command skeleton
- Documentation in `Documentation/git-history.adoc`
- Build system integration (Makefile, meson.build)
- Basic test cases in `t/t3450-history.sh` verifying argument handling
- The command is marked as experimental in its documentation
- Currently only handles basic argument validation
- Will be extended with actual functionality in subsequent patches
- Shares infrastructure with `git-replay` via `replay.c` (added in earlier patches)

This patch follows the series' pattern of incremental development, first establishing the command framework before adding functionality. The implementation approach appears solid, with proper integration into Git's build and test infrastructure from the start. The documentation clearly communicates the experimental nature and current limitations, setting appropriate expectations.
