This is a refactoring patch in Patrick Steinhardt's `git-history` series (v4 10/12), adding support for in-memory index patching to the interactive add/patch infrastructure. The patch introduces a new `run_add_p_index()` function that allows applying changes to a specified in-memory index rather than always using the repository's index. This builds on previous refactoring in the series to reduce coupling between components.

The key technical changes include:
- Adding `index` and `index_file` fields to `struct add_p_state` to track the target index
- Modifying index operations to use the specified index rather than `r->index`
- Implementing new `run_add_p_index()` with same interface as `run_add_p()` but accepting explicit index parameters
- Maintaining existing behavior when operating on the repository's index
- Adding proper index initialization/cleanup paths for the new function

The changes are part of the broader effort to support the `git-history reword` command by enabling more flexible index manipulation during history editing operations. The patch maintains backward compatibility while extending functionality, with careful handling of edge cases like binary files and empty changesets. The implementation shares infrastructure with existing commands (`add`, `checkout`, `commit`, etc.) while enabling new use cases that require working with temporary in-memory indexes.
