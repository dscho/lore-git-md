Extended RFC proposal for Git tree format modifications to support mixed-hash submodules and conflict markers, originating from Contributor Summit discussions. Author brian m. carlson has progressed from initial prototype to formal specification (`gitformat-extended-tree.adoc`), proposing backwards-compatible extension mechanism via mode 130000 tree entries with BER-like encoding (bit-flipped for non-zero bytes) for length/type/flag fields. 

Core design includes two object types: conflict trees for merge representation and extended submodules for mixed-hash scenarios (SHA-256 submodule in SHA-1 parent). XOR-based encoding handles OID differences between parent/child hash algorithms, with criticality flags controlling unknown extension handling. Format triggers git fsck warnings in older clients while remaining parseable, maintaining minimal incompatibility - older Gits see entries as malformed due to apparent tree sorting issues.

Maintainer Junio C Hamano engages with technical specifics, raising key questions: how length-prefixed extended data interacts with tree entry ordering requirements (pathname sorting despite binary metadata), debugability concerns of BER encoding, and extensibility tradeoffs that could lead to non-canonical representations. Specific attention given to sort ordering for conflict tree entries in complex merge scenarios (criss-cross/octopus merges with multiple stage entries). Junio acknowledges proposal's inherent ugliness while constructively vetting its interaction with Git's core invariants around tree ordering and object identity.

Open questions expand to include:
- Pathname sorting implications of binary metadata prefixes
- Debugging strategies for BER-encoded tree entries
- Canonical representation risks from uncontrolled extension types
- Behavior in complex merge scenarios not yet fully specified
- Interaction with other in-flight hash transition efforts

Proposal remains in specification phase with no implementation timeline, serving primarily to explore Git's extensibility limits regarding hash interoperability and conflict representation. Maintainer engagement signals serious consideration of the technical tradeoffs involved in introducing new on-disk formats.
