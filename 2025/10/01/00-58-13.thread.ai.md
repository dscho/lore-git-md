Extended RFC proposal for Git tree format modifications to support mixed-hash submodules and conflict markers, originating from Contributor Summit discussions. Author brian m. carlson has progressed from initial prototype to formal specification (`gitformat-extended-tree.adoc`), proposing backwards-compatible extension mechanism via mode 130000 tree entries with BER-like encoding. Jeff King (peff) now engages with alternative approaches that trade compatibility, visibility, and complexity differently.

Core design considerations now include:
- Two competing encoding strategies: original BER-like binary encoding (bit-flipped for non-zero bytes) vs peff's ASCII-based filename encoding ("sha1-<hash>-path")
- Two mode proposals: original 130000 vs peff's S_IFGITLINK with sentinel OID (000...1) for better backward compatibility
- Sorting implications for both approaches: pathname-based (breaks older clients) vs prefix-based (complicates diff display)
- Diverging solutions for mixed-hash submodules (peff's ASCII encoding preferred) vs conflict markers (may need separate mechanism)

Technical tradeoffs clarified:
- BER encoding maintains cleaner user-facing paths but raises debugability and filesystem compatibility concerns
- ASCII encoding improves debuggability but introduces visible ugliness requiring diffcore post-processing
- Mode 130000 enables unified solution but risks older client breakage; S_IFGITLINK approach safer but submodule-specific

Maintainer Junio C Hamano's prior concerns about tree entry ordering and debugability now addressed through peff's concrete alternatives, though new questions emerge:
- Exact diff display behavior with ASCII-encoded paths
- Filesystem portability of non-UTF-8 names in peff's approach
- Whether conflict markers warrant a separate encoding mechanism
- Implementation complexity of diffcore cleanup for ASCII encoding

The discussion has narrowed focus to mixed-hash submodules as primary use case, with conflict markers potentially deferred. Peff's suggestions shift the design toward favoring backward compatibility and debuggability over theoretical purity, though no consensus yet reached on-disk format. Maintainer engagement continues to probe edge cases around Git's core invariants of tree ordering and object identity, with both encoding strategies now under parallel consideration.
