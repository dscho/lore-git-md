This is a refactoring patch in the `git-history` command series, specifically patch 2/12 in v4. The change extracts commit-picking logic from `builtin/replay.c` into a new `replay.c` file to share functionality between `git-replay` and the upcoming `git-history` command.

The patch moves several key functions:
- `pick_regular_commit()` (now renamed to `replay_pick_regular_commit()` with a subsystem prefix)
- Supporting functions like `create_commit()`, `get_author()`, and `mapped_commit()`
- The commit creation and tree manipulation logic needed for replay operations

The changes are mechanical - no behavior is altered, just reorganized. The new `replay.[ch]` files are added to the build system (Makefile and meson.build). This is groundwork for the subsequent patches that will build the `git-history` command on this shared infrastructure.

The implementation looks clean and focused, with clear separation of concerns. The commit message explains the motivation well - preparing for code sharing between commands. This is a typical mid-series refactoring patch that enables later functionality while keeping the diff manageable.
