This is a technical clarification in the ongoing Git 3.0 release planning thread, specifically addressing SHA-256 interoperability concerns. Brian m. carlson responds to Michal Suchánek's questions about the practical necessity of SHA-256 interoperability work, explaining that while it's a major planned feature, it's only needed for specific use cases involving repository conversion or working across different hash algorithms.

Key technical points clarified: SHA-256 repositories have been supported since Git 2.29/2.30 for users content to work within a single hash algorithm context. The interoperability work specifically enables cross-algorithm operations. Brian confirms that cloning behavior won't change for existing repositories - it will always use the repository's original hash, while the default for new repositories (via `git init`) would switch to SHA-256 in Git 3.0.

The email reinforces that the interoperability work is not universally required, but serves specific migration and cross-compatibility scenarios. This helps narrow the scope of the SHA-256 discussion from abstract concerns to concrete use cases where the feature would (and wouldn't) be necessary. The response maintains the thread's technical focus while providing clearer boundaries around the interoperability feature's actual impact on users.
