This thread explores proposed extensions to Git's tree format to support mixed-hash submodules and conflict markers, stemming from discussions at the Contributor Summit. brian m. carlson initially proposed the changes, with Jeff King (peff) now leading implementation refinements. The core debate has evolved from encoding strategies (BER-like binary vs ASCII) to concrete challenges around index representation and hash algorithm compatibility, where Junio Hamano has emphasized the need to either formalize or reject the current undocumented behavior allowing SHA-1/SHA-256 submodule mixing.

A new dimension emerged with Elijah Newren's critique of the conflict marker proposal. He argues that representing conflicts via special tree entries would unnecessarily impact `git log` performance for all users, even those not using conflict features. Newren suggests following the approach of tools like jj and GitButler, where conflicts are tracked at the commit level rather than in trees, and recommends temporarily removing conflicted tree support from the proposal. This shifts the discussion toward balancing new functionality with Git's performance characteristics and ecosystem alignment, while the mixed-hash submodule use case remains the primary focus. The thread now spans both technical fronts: hash algorithm interoperability and conflict representation tradeoffs.
