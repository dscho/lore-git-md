This thread explores an RFC proposal to extend Git's tree format to support mixed-hash submodules and conflict markers, originating from Contributor Summit discussions. The original proposal introduced a prototype using mode 130000 for submodules with additional metadata, framed as a thought experiment about Git's extensibility limits.

The latest contribution formalizes this exploration with a detailed technical specification in a new `gitformat-extended-tree.adoc` document. It proposes a backwards-compatible extension mechanism featuring a BER-like encoding scheme, two initial object types (conflict trees and extended submodules), and criticality flags for handling extensions. The specification includes concrete examples of representing SHA-256 submodules in SHA-1 repositories using XOR-based encoding.

While still positioned as exploratory, the discussion has progressed from prototype demonstration to a well-considered technical specification. The proposal carefully addresses backwards compatibility, with older Git versions seeing the extended entries as malformed rather than crashing. The thread remains focused on informing future discussions about hash algorithm interoperability and conflict representation, without committing to an implementation timeline.
