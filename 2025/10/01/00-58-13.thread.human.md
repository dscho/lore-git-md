This thread explores a proposed extension to Git's tree format to support repositories with mixed hash algorithms (e.g., SHA-1 and SHA-256) in submodules. The discussion originated from Contributor Summit talks and has progressed from initial RFC to implementation details, with brian m. carlson driving the design and Jeff King (peff) focusing on practical constraints.

The core challenge is representing submodule hashes when the main repository and submodule use different algorithms. Early proposals considered various encoding schemes, but implementation experiments revealed fundamental problems with transforming paths in the index. The emerging consensus is to keep the index clean (storing real hashes) while limiting transformations only to tree serialization. A race condition in submodule resolution was also identified as a blocker.

In the latest exchange, peff responds to brian m. carlson's position that Git should explicitly reject mismatched hashes until proper support is implemented, even though this breaks some undocumented existing behavior. While acknowledging the tradeoffs, peff indicates tests and a cleaned-up implementation are coming soon. The discussion has solidified index consistency as the non-negotiable priority, even if it means a temporary regression for edge cases during the transition.
