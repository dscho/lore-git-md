Junio C Hamano has engaged with Brian Carlson's proposal for extending Git's tree format to support mixed-hash submodules and conflict markers, marking a shift from conceptual discussion to technical vetting. The RFC, which grew out of Contributor Summit conversations, outlines a backwards-compatible mechanism using specially encoded tree entries to handle scenarios like SHA-256 submodules in SHA-1 repositories. 

The maintainer's response focuses on practical implementation concerns, particularly around how the proposed BER-like encoding would interact with Git's strict tree entry sorting requirements. Junio questions whether pathnames would remain properly ordered when prefixed with binary metadata and raises debugability concerns about the encoding scheme. He also probes edge cases in merge scenarios, asking how conflict tree entries would sort in complex criss-cross and octopus merges. While acknowledging the proposal's inherent complexity, his engagement signals serious consideration of the design's technical merits.

This exchange moves the thread into a new phase where the theoretical specification meets Git's real-world constraints. The open questions now center on canonical representation and sort ordering rather than the high-level concept, suggesting the next steps will involve refining the encoding scheme to address these concerns while maintaining the proposal's core goals around hash algorithm interoperability.
