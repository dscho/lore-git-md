The thread continues to refine Git's approach to handling submodules across different hash algorithms (SHA-1 and SHA-256). What began as an RFC for extended tree formats has evolved into focused discussions about index validation and migration strategies.

Jeff King (peff) proposed adding explicit validation in `add_to_index()` to reject submodules with incompatible hash algorithms, which would break the current accidental compatibility that works through hash truncation and zero-padding. brian m. carlson agrees this stricter approach is needed during the transition, despite disrupting some existing workflows. Both acknowledge that while the current behavior "works" in some cases, it's undocumented and submodules are known to be problematic in interop scenarios.

The discussion has shifted from theoretical encoding strategies to concrete implementation concerns, with consensus forming around:
1. Temporarily enforcing single-hash-algorithm consistency for submodules
2. Planning for proper cross-algorithm support in the extended tree format work
3. Prioritizing data integrity over preserving accidental compatibility

Junio Hamano's earlier maintainer concerns about relying on undocumented behavior appear to be guiding this direction. The thread shows the project carefully balancing strict validation against real-world usage while preparing for more robust multi-hash support in the future. Performance considerations around conflict representation (raised earlier by Elijah Newren) remain an open question but are being addressed separately from the immediate hash validation changes.
