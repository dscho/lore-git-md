The thread explores a proposed extension to Git's tree format to support mixed-hash submodules (like SHA-256 submodules in SHA-1 repositories) and improved conflict markers. brian m. carlson's RFC proposes a BER-like encoding in tree entries, which maintainer Junio C Hamano has been carefully vetting for its impact on Git's core invariants around tree ordering and object identity.

Jeff King (peff) has now joined the discussion with alternative suggestions that prioritize backward compatibility. He proposes using existing S_IFGITLINK mode with a sentinel OID rather than introducing new modes, and favors ASCII-based encoding in filenames over the original BER approach - citing debuggability and filesystem compatibility concerns. The conversation has narrowed to focus first on the mixed-hash submodule case, acknowledging that conflict markers may need separate treatment.

Key open questions now include how to balance pathname sorting requirements with the new encoding schemes, whether to accept some user-visible ugliness for implementation simplicity, and how to handle diff display of these special entries. The maintainer's continued engagement suggests this RFC is being seriously considered, though no implementation timeline has been set.
