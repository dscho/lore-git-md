This thread documents and clarifies how Git matches URLs in credential configuration, specifically that path components must match as prefixes. The original patch (v1) updated gitcredentials.adoc to correct inaccuracies from a 2020 change, showing that `https://example.com/bar` matches `https://example.com/bar/baz.git` but not `https://example.com/barry/repo.git`. It also added extensive test coverage in t/t0300-credentials.sh to verify this behavior and edge cases.

The v2 patch incorporates minor wording improvements to emphasize that the pattern must include protocol and host to match as a prefix. brian m. carlson has reviewed the changes positively, noting the improved description and test coverage. The changes are documentation and test updates only, as the implementation already behaved correctly. With no outstanding objections and thorough test coverage, this appears ready for merging.
