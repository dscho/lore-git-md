This thread addresses documentation improvements for Git's credential configuration URL matching behavior. The original patch clarifies how partial URL patterns work when matching against credential configurations, specifically that path components must match as prefixes. For example, `https://example.com/bar` will work with a config entry for `https://example.com/bar/baz.git` but not for `https://example.com/barry/repo.git`.

The patch corrects inaccuracies that were introduced in a 2020 commit (9a121b0d226) and provides significantly expanded test coverage in t/t0300-credentials.sh. The tests verify both positive cases (where URLs should match) and negative cases (where they shouldn't), using a simple credential helper that echoes passwords. The changes are limited to documentation and tests, as the implementation was working correctly - this just makes the behavior properly documented.
