This is a technical discussion about Git's handling of mixed-hash submodules, continuing the extended tree format RFC thread. Jeff King (peff) shares findings from experimenting with submodules that use different hash algorithms than their parent repositories.

The email reveals two key insights from testing: First, the current system accidentally works with mixed hashes by either truncating SHA-256 hashes or zero-padding SHA-1 hashes, though this behavior appears fragile. Second, the index would need similar handling as trees for foreign hashes, presenting design tradeoffs between index-tree and index-filesystem consistency.

Peff proposes a potential safety check that would explicitly block mixed-hash submodules, though acknowledges this would break current accidental functionality. The discussion highlights how Git's recent zero-padding change for object IDs unexpectedly enables this mixed-hash scenario, though the behavior seems more like a happy accident than intentional design.

The email advances the thread by grounding the theoretical discussion in concrete implementation concerns, particularly around the index handling. It suggests the solution space may need to consider both the tree format extension and index modifications, while acknowledging the current accidental functionality as a baseline that some users already rely on.
