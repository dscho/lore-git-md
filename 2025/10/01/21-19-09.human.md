This is a technical discussion about Git's handling of mixed-hash submodules, specifically around the accidental compatibility between SHA-1 and SHA-256 repositories. Junio C Hamano is responding to Jeff King's findings about how Git currently (but accidentally) handles submodule hash algorithms.

The key point is that Git currently ignores the hash algorithm field when reading submodule commits, allowing SHA-1 commits to work in SHA-256 repositories (via zero-padding) and vice versa (via truncation). Jeff King proposes adding explicit validation in `add_to_index()` to reject incompatible hash algorithms, though this would break the current accidental compatibility.

1. Whether to formalize or reject the current cross-algorithm behavior
2. Where to place validation logic (with `add_to_index()` being a likely candidate)
3. How to handle the transition if stricter validation is implemented
