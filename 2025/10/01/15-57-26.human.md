This is a feature patch series (v4) introducing a new `git-history` command for history editing operations, now rebased and reworked to integrate with `git-replay` infrastructure as discussed at the Contributor's Summit.

Patrick Steinhardt presents a significantly slimmed-down version of 12 patches (down from 18 in v3), focusing on the `reword` and `split` subcommands while dropping other planned functionality to reduce scope. The series builds on recent work in the `replay` infrastructure and avoids conflicts with Jeff King's add-i color changes in the 'seen' branch.

Key changes in v4:
- Rebased onto recent `replay-atomic-ref-updates` work
- Dropped `reword` implementation in favor of future sequencer-based approach
- Removed hook execution handling (to be addressed later)
- Simplified command structure based on Summit discussions
- Added new `split` subcommand for interactive commit splitting
- Improved test coverage for both subcommands

The `reword` subcommand allows modifying commit messages while keeping other metadata intact, with editor support when no message is provided. The new `split` subcommand interactively divides a commit into two parts by selecting hunks, with safeguards against creating empty commits. Both operations rewrite descendant commits automatically.

The implementation shares infrastructure with `git-replay` and includes preparatory refactoring of the add-patch subsystem to support in-memory index operations. While this version is more focused, it still represents a significant new capability for Git's history editing tools, inspired by features from Jujutsu (jj).

The patch quality appears high, with thorough documentation and testing. The series has evolved through multiple rounds of review and incorporates feedback from the Git community. The decision to defer some functionality (like hooks and `commit.verbose` handling) suggests a pragmatic approach to incremental development.
