This thread addresses a security hardening patch for Git's files backend that prevents symbolic references with malformed paths (like "refs/../HEAD") from bypassing validation checks. The original patch from Han Young added validation in `split_symref_update()` to stop these problematic references from being created, which could otherwise lead to repository corruption or misleading error messages.

Junio Hamano, the maintainer, has now weighed in with two important refinements: he suggests aligning the validation logic with what `git fsck` would consider invalid to maintain consistency across Git's codebase, and requests test coverage to verify the new protection works as intended. While there's no disagreement about the security issue's importance or the general approach, these changes will be needed before the patch can be merged. The discussion remains focused on the technical implementation in `refs/files-backend.c`, with both participants recognizing the need to close this validation gap while maintaining Git's existing error handling patterns.
