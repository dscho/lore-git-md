This is a technical clarification in the ongoing Git 3.0 release planning discussion, specifically addressing SHA-256 interoperability workflows. Brian m. carlson responds to Junio C Hamano's question about handling unpublished work in SHA-1 repositories when a project migrates to SHA-256.

The key clarification is that while Git currently lacks the ability to add an algorithm to an existing repository (a desired future feature), there are workarounds for moving SHA-1 work into a SHA-256 repository. The main limitation is that pushes must use the server's primary algorithm due to protocol constraints - protocol v2 doesn't support pushes, and protocol v0 doesn't allow algorithm selection for pushes.

Brian explains that the current workflow would require creating a SHA-256/SHA-1 clone from the server, then pulling changes from the SHA-1 repository rather than pushing to it. They explicitly state no plans to expand protocol v2 to support pushes, as this would significantly increase the project scope. The response provides important technical boundaries for the SHA-256 transition discussion while maintaining focus on the core interoperability goals.
