This is a technical implementation exploration in the ongoing extended tree format discussion, focusing on index representation challenges for mixed-hash submodules. Jeff King shares experimental code modifying `add_to_index()` to handle foreign-hash submodules by generating special path names (like "sha1-<hash>-path") when the submodule's algorithm differs from the repository's.

The patch demonstrates a working approach but reveals significant complexity in the lookup side, where code would need to handle both normal and special-case paths. King notes this creates ugliness in reading operations, as the index wouldn't know whether to use the original or transformed path for lookups without already having the hash.

Key technical points:
- Current implementation modifies paths in `add_to_index()` when encountering foreign-hash submodules
- Uses a sentinel OID (all zeros with last byte as 1) for the index entry
- Identifies race condition in double submodule resolution
- Reveals lookup ambiguity that would require speculative dual-path checking

The email marks a pivot point in the discussion, with King now leaning toward keeping the index clean (storing real hashes) and limiting the path-munging to tree serialization. This maintains index consistency while still allowing cross-algorithm submodule support, though it means trees and index would diverge in their representation. The exploration confirms the technical feasibility but raises questions about whether the complexity justifies the feature.
