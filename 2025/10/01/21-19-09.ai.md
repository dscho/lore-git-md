Feature proposal discussion on mixed-hash submodule handling, focusing on index validation.

Junio Hamano responds to Jeff King's findings about the current accidental compatibility between SHA-1 and SHA-256 submodules in Git repositories. The discussion centers around whether to formalize or reject the existing behavior where submodule hashes of one algorithm (e.g., SHA-1) work when embedded in repositories using another algorithm (SHA-256) through zero-padding or truncation.

Key technical details include:
- Current implementation ignores the hash algorithm field in submodule object IDs, allowing cross-algorithm operation
- Jeff King proposes adding explicit validation in `add_to_index()` to reject incompatible hash formats
- The proposed check would compare `oid.algo` against the repository's `hash_algo`
- This would break existing workflows relying on the accidental compatibility

The thread reveals tensions between:
- Preserving undocumented but working behavior vs enforcing strict algorithm matching
- Whether to handle conversion at the `add_to_index()` level
- How this interacts with the broader extended tree format proposal for mixed-hash support

This email advances the discussion by:
- Confirming awareness of the cross-algorithm edge case
- Surfacing maintainer concerns about relying on accidental behavior
- Identifying `add_to_index()` as a key validation point
- Highlighting migration challenges for existing users of mixed-hash submodules

The conversation remains focused on implementation tradeoffs rather than encoding strategies, with Junio's response indicating maintainer preference for stricter validation unless compelling use cases emerge for preserving the current behavior.
