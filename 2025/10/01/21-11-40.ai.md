This is a technical follow-up in the extended tree format discussion, focusing on practical implementation challenges for mixed-hash submodules. Jeff King (peff) shares findings from experimenting with cross-algorithm submodule scenarios, revealing two key insights:

First, the proposed tree format extension must also handle index entries, not just trees. Peff explores tradeoffs between matching index-to-tree (with foreign hash encoding) versus index-to-filesystem, leaning toward the latter for implementation simplicity given filesystem unpredictability.

Second, current Git accidentally handles mixed-hash submodules through hash truncation/zero-padding, though this relies on undocumented behavior. Peff demonstrates this with test cases showing SHA-256 submodules in SHA-1 repos (truncated hashes work) and vice versa (zero-padding works). He proposes a stricter check in `add_to_index()` to reject incompatible hash algorithms, though acknowledges this would break current accidental compatibility.

The email surfaces important implementation considerations:
- Index representation must align with either tree or filesystem formats
- Current hash handling relies on padding behavior from c98d762ed9
- `add_to_index()` would be the natural hook for any future algorithm conversion
- There's tension between strict validation and preserving accidental interop

This moves the discussion from theoretical encoding strategies to concrete migration challenges, highlighting that the solution must address not just tree storage but also index consistency and existing quasi-working edge cases. The findings suggest the ASCII encoding approach may need to handle more cases than originally scoped.
