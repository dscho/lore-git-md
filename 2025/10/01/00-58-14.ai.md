Technical documentation proposal for an extended tree format, continuing the RFC discussion about hash algorithm interoperability and conflict representation. This patch adds a new documentation file `gitformat-extended-tree.adoc` that formally specifies a backwards-compatible extension mechanism for Git trees using mode 130000 entries.

The proposed format introduces several key concepts:
1. A BER-like encoding scheme (with bit flips to ensure non-zero bytes) for length, type, and flag fields
2. Two initial object types: conflict trees (for merge conflicts) and extended submodules (for mixed-hash scenarios)
3. Criticality flags to control handling of unknown extensions
4. Special encoding rules for submodule OIDs when parent/child repositories use different hash algorithms

The documentation includes a concrete example showing how a SHA-256 submodule would be represented in a SHA-1 repository, with XOR-based encoding for the extra hash bytes. The format is designed to be minimally incompatible - older Git versions would see the entries but consider them malformed due to apparent tree sorting issues.
