This is a bugfix patch for the files backend that prevents symbolic references from being created outside the intended refs/ directory. The issue was reported by a user who found that Git would incorrectly create reference and lock files in the repository's root directory when given a malformed symref path like "refs/../HEAD".

The patch adds validation to check symbolic reference names before updates, preventing paths that would escape the refs hierarchy. The commit demonstrates the problem with a clear reproduction case where creating a symref to "refs/../HEAD" causes confusing lock file conflicts and could potentially create reference files in unintended locations.

The fix appears straightforward - adding 10 lines of validation code to the files backend. While the impact is limited to edge cases involving malformed symrefs, the potential for creating files in wrong locations makes this a worthwhile security hardening measure. The patch includes no tests, which might be worth requesting in follow-up discussion, but the core fix looks correct and narrowly targeted.
