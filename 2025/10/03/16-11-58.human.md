Bugfix follow-up discussion for interactive add hunk selection.

Junio C Hamano responds to René Scharfe's fix for the `git add --interactive` hunk behavior, agreeing with the solution but pointing out a deeper, long-standing issue in the hunk selection logic. While the immediate patch correctly handles undecided hunks during rollover, Junio notes that the underlying code has a more fundamental problem with permission flag management that affects multiple interactive commands.

The core issue is that permission flags (like ALLOW_SPLIT) accumulate across hunk navigation rather than being reset per-hunk. This causes several anomalies: non-splittable hunks can appear splittable after visiting a splittable one, and navigation commands like 'k' (previous hunk) stop validating bounds after first use. Junio traces this to the 2019 C rewrite of the interactive add code.

Interestingly, this bug accidentally created a useful feature - allowing wrap-around navigation with 'j' at the last hunk, which the original code prevented. The discussion suggests that while René's specific fix is correct and ready, there's a larger architectural issue that may need addressing separately. The thread shows maintainer approval of the immediate fix while identifying an area for potential future improvement.
