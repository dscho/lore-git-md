This is a documentation and test update clarifying URL prefix matching behavior in Git credential configuration. The patch corrects inaccuracies introduced in commit 9a121b0d226 (2020) by explicitly documenting that path components must match as prefixes - so `https://example.com/bar` matches `https://example.com/bar/baz.git` but not `https://example.com/barry/repo.git`.

The changes include both documentation updates to gitcredentials.adoc and expanded test coverage in t/t0300-credentials.sh. The tests now verify prefix matching through both positive cases (various valid prefix forms) and negative cases (partial segments, incorrect prefixes). The test uses a credential helper that echoes a password to confirm matches.

This is version 2 of the patch, with minor wording improvements from the first version to clarify that the pattern must include protocol and host to match as a prefix. The changes remain documentation and test-only, as the implementation already behaved as now documented. The commit message clearly links to the original bug and provides focused documentation improvements with thorough test coverage.
