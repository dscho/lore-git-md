This is a discussion thread about Julia Evans's documentation patch introducing a new `gitdatamodel.adoc` man page. Kristoffer Haugsbakk provides detailed feedback on the proposed content, focusing on several key aspects:

The feedback questions whether packed refs should be mentioned at all (contrary to Julia's note about them), and strongly advocates for including the `refs/heads/main` naming convention as it's user-facing. Kristoffer agrees with avoiding `.git` directory details but notes this becomes complicated with the upcoming reftable backend.

Technical suggestions include:
- Spelling out small numbers ("two or more" instead of "2+")
- Possibly moving `git gc` discussion to a section about unreachable objects
- Being cautious about implementation details like packfiles
- Using "typically" instead of "often" for tag object references
- Considering more cross-references to other man pages

Kristoffer praises the overall effort while raising thoughtful questions about scope and presentation, particularly around what level of implementation detail belongs in this conceptual document. The feedback maintains a constructive tone while identifying several areas where the documentation could be refined or expanded.
