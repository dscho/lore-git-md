This is a follow-up in the SHA-1/SHA-256 interoperability series, specifically addressing test infrastructure for compatibility mode. The email responds to Junio C Hamano's positive feedback on the `BROKEN_OBJECTS` prerequisite handling in compatibility mode testing.

The key technical point is that broken object tests need special handling in compatibility mode because the object mappings required to rewrite objects don't exist in this scenario. The `BROKEN_OBJECTS` prerequisite (defined in terms of `COMPAT_HASH`) properly detects when these tests should be disabled.

The author notes this was one of the major sources of test failures in compatibility mode, but relatively straightforward to identify and fix. The exchange confirms the technical approach to handling these edge cases in the test infrastructure, which completes an important piece of the broader hash interoperability work.

This appears to be a minor but important refinement to the test infrastructure that was already well-received in the previous version of the patch series. The discussion here serves as final confirmation that this aspect of the testing strategy is sound before the series moves forward.
