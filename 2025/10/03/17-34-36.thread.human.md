This thread documents Julia Evans' effort to create an authoritative explanation of Git's data model through a new `gitdatamodel.adoc` man page, now in its seventh iteration. The series has undergone extensive review from technical (Patrick Steinhardt, D. Ben Knoble) and documentation (Kristoffer Haugsbakk) perspectives, with Junio Hamano providing maintainer guidance. All technical aspects are resolved, including storage-layer accuracy, build system integration, and terminology standardization around concepts like file types and reference naming.

The discussion has narrowed to one final question: how to document Git's branch terminology. Julia maintains the documentation should focus strictly on branches as mutable references under `refs/heads/`, drawing on her teaching experience and citing Mark Dominus' analysis of Git's conceptual/implementation mismatch. Junio suggested briefly noting that refs under `refs/heads/` point only to commits, while Chris Torek's new email reinforces Julia's position by detailing how "branch" ambiguously refers to either the ref name or an ill-defined commit sequence. Chris' analysis of this inherent terminology complexity supports keeping the documentation's narrow technical focus, as broader concepts would introduce confusion rather than clarity.

With all other issues settled and the pedagogical approach validated by multiple contributors, this series appears ready for merging with Julia's preferred branch definition - a significant addition to Git's documentation that fills a long-standing gap in explaining its core concepts.
