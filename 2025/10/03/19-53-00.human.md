Bugfix follow-up addressing interactive add command permissions.

René Scharfe responds to Junio Hamano's review of the interactive hunk selection fix, agreeing that the documentation's description of 'j/J/k/K' as "leave this hunk undecided" is misleading since these commands preserve prior decisions. He suggests simplifying the help text to focus on navigation ("go to next/previous hunk").

The main technical contribution is a new patch that fixes the command permission system in `add-patch.c`, where the `permitted` bitmask wasn't being reset between hunk evaluations. This caused commands like split ('s') to remain available on hunks where they shouldn't be. The fix moves the `permitted` declaration inside the hunk loop so it resets properly each time.

The patch includes a new test verifying invalid commands are properly rejected, catching cases like trying to split unsplittable hunks or navigate beyond bounds. Junio had noted this bug accidentally created a useful wrap-around navigation feature, but René's implementation maintains stricter bounds checking while still allowing rollover for core commands like 'y/n'. 

This appears to be a well-considered follow-up that addresses both the immediate permission system bug and improves test coverage, while leaving open the question of whether to preserve some of the accidental navigation features that users may have come to rely on.
