Bugfix for interactive add command's hunk navigation and permission system.

René Scharfe follows up on Junio Hamano's identification of deeper issues in `git add --interactive`'s command handling. The core problem is that the `permitted` bitmask tracking available commands (split, navigation, etc.) isn't properly cleared between hunk evaluations, causing commands to remain available when they shouldn't be. This dates back to the 2019 C rewrite of interactive add.

The proposed fix moves the `permitted` variable inside the hunk processing loop so it resets properly for each hunk. This prevents invalid operations like trying to split unsplittable hunks or incorrect navigation commands from being accepted. The patch includes a new test case verifying rejection of invalid commands (split on unsplittable hunks, navigation beyond bounds).

Junio had noted this bug accidentally created a useful feature - allowing wrap-around navigation with 'j/J' even when not explicitly offered. René's implementation removes this side effect, restoring strict bounds checking. The discussion suggests this may warrant separate consideration as a potential feature.

Key technical elements:
- Moves `permitted` bitmask into loop scope in `patch_update_file()`
- Adds test verifying rejection of invalid split/navigation attempts
- Affects command availability flags: `ALLOW_SPLIT`, `ALLOW_GOTO_*` navigation bits
- Maintains existing hunk state handling from previous fix (`UNDECIDED_HUNK`)

This addresses the immediate architectural issue while preserving the earlier hunk rollover fix. The changes are focused and well-tested, though the discussion hints at potential follow-up work to intentionally support wrap-around navigation if desired.
