Documentation update clarifying URL prefix matching in Git credential configuration. This is the second version of a patch that fixes inaccuracies in the gitcredentials.adoc documentation since commit 9a121b0d226 in 2020.

The patch makes two key improvements: First, it clarifies that path components in credential URLs must match as prefixes (so `https://example.com/bar` matches `https://example.com/bar/baz.git` but not `https://example.com/barry/repo.git`). Second, it adds extensive test coverage in t/t0300-credentials.sh to verify this behavior through both positive and negative test cases.

The changes are purely documentation and test-related, as the implementation already behaved as now documented. The v2 revision improves the wording slightly by changing "prefix path" to "path prefix" in the documentation. The patch has already received positive review from brian m. carlson for its improved description and test coverage. This appears to be a well-justified documentation fix with thorough testing to prevent future confusion.
