This is a bug report about performance issues with the untracked files cache when using `--untracked-files`. The submitter observes that while the untracked files cache works as expected for normal `git status` operations (resulting in faster subsequent runs), the cache does not appear to be utilized when explicitly using `--untracked-files=all`, causing repeated slow performance. The issue is demonstrated on Windows (git version 2.51.0.windows.1) where a status operation takes ~3 seconds without cache utilization versus ~0.7s when the cache is working.

The report includes verification steps showing the untracked cache is properly configured (`git update-index --test-untracked-cache` succeeds) and that the performance difference is specifically tied to the `--untracked-files` flag. The submitter notes this is particularly problematic as many tools and IDEs hardcode this flag, making the performance impact widespread. No patch is provided, but the report clearly identifies what appears to be a caching inconsistency in the status machinery.
