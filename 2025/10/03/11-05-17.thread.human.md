This thread examines a performance issue where Git's untracked files cache is bypassed when `--untracked-files=all` is explicitly specified, despite working normally for default `git status` operations. The problem particularly affects tools and IDEs that hardcode this flag. Initial Windows testing showed a significant slowdown (0.7s vs 3s), and Matthew Hughes has now confirmed the behavior on Linux with a test case demonstrating a 1.25s vs 0.38s difference. 

The root cause appears to be that commit e6a653554b made the cache work with `--untracked-files=all` only when `status.showUntrackedFiles=all` is also set in the config. This creates a performance cliff where tools specifying the flag without matching config don't benefit from caching. Hughes' test with 100k files across nested directories shows the cache provides a 3x speedup, but only when config and flag align. While no patch has been proposed yet, the concrete reproduction steps should help diagnose why the cache is bypassed when flags override defaults, which isn't the behavior users or tool authors might expect.
