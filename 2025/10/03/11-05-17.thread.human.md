This thread examines performance issues in `git status` related to the untracked files cache behavior. The original report showed that the cache is bypassed when using `--untracked-files=all` unless `status.showUntrackedFiles=all` is also set, creating a significant performance difference (3x slower without the cache). Both Windows and Linux users confirmed this behavior.

New findings from Devste Devste reveal additional complexity: while the config/flag symmetry is one factor, certain common command-line combinations (like those used in IDEs and GUIs) can also prevent cache updates. The cache exhibits "sticky" behavior - once created with the right config, subsequent commands may use it regardless of current settings. Timing data shows the performance impact remains substantial (3.4s vs 0.8s) in these scenarios. The exact combination of flags causing issues isn't yet isolated, but porcelain mode and other status options appear to be involved. The thread has documented clear reproduction steps but hasn't yet proposed a solution to this caching inconsistency in the status machinery.
