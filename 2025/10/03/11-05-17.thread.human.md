This thread reports a performance issue with Git's untracked files cache when using the `--untracked-files=all` flag. The submitter demonstrates that while normal `git status` operations benefit from caching (dropping from ~3s to ~0.7s on subsequent runs), explicitly specifying `--untracked-files=all` bypasses the cache entirely, maintaining the slower performance. This is particularly impactful because many tools and IDEs hardcode this flag in their Git integrations. 

The issue has been verified on Windows (Git 2.51.0) with proper untracked cache configuration, suggesting a caching inconsistency in Git's status machinery. No patch has been proposed yet, but the report clearly isolates the flag as the trigger for cache bypass. The performance impact could affect many users who rely on tools that use this flag.
