The thread investigates performance issues in `git status` related to the untracked files cache, particularly when using `--untracked-files=all` alongside other flags. Originally reported as a config/flag mismatch problem causing 3x slowdowns, further analysis by Devste Devste revealed more complexity - the cache becomes "sticky" once established, and common flags like `--porcelain` might interfere with cache updates.

Matthew Hughes has now pinpointed `--no-optional-locks` as the specific flag causing cache update failures when combined with `--untracked-files=all`. His timing data shows commands with this flag take over 1 second while subsequent runs without it drop to ~300ms. The issue stems from `repo_update_index_if_able()` only executing when optional locks are enabled, directly linking lock behavior to cache updates. While this explains part of the "sticky cache" phenomenon, questions remain about whether this lock dependency is intentional design, and how other flags might interact with the cache mechanism. The findings provide a clear path for further investigation and potential fixes to this performance-critical issue affecting IDEs and GUIs.
