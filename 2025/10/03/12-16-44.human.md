Bugfix for `git add --interactive` hunk selection behavior.

René Scharfe addresses a regression reported by Ulrich Windl where `git add -p` would incorrectly restart hunk selection from the beginning after using the "J" (join) command, even for hunks that had already been decided. The fix modifies the hunk iteration logic to skip over already-decided hunks when rolling over to the next undecided one.

The patch changes `add-patch.c` to scan for the first undecided hunk when reaching the end of the list, rather than always resetting to hunk 0. Two new test cases verify the corrected behavior for different hunk selection sequences. The tests demonstrate that the interface now properly remembers prior decisions when cycling through hunks.

This appears to be a straightforward and well-tested fix for the reported regression. The commit message clearly explains both the problem and solution, and the test cases cover the specific scenarios where the bug manifested. The change is small and focused, touching only the necessary logic in the hunk selection loop.
