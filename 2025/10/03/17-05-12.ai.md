Junio C Hamano provides review feedback on patch 5/9 of brian m. carlson's SHA-1/SHA-256 interoperability series, focusing on the new loose object storage documentation. The patch adds `gitformat-loose.adoc` to formally specify Git's loose object format.

Key technical details covered in the documentation:
- Loose object file structure: `<type> <size>\0` prefix followed by zlib-compressed data
- Object ID computation from uncompressed data using repository's hash algorithm
- Storage path pattern: `$GIT_DIR/objects/[0-9a-f][0-9a-f]/*` with sharding to avoid filesystem performance issues
- Concrete examples showing empty tree and simple blob storage

Junio approves the v2 improvements, noting the documentation is now "much easier to follow" with the added explanations. The review highlights two specific improvements from v1:
1. Clearer description of the loose-to-packed object lifecycle
2. More detailed explanation of the object file naming scheme and its rationale

The patch also includes the necessary meson.build update to install the new manpage. This documentation completes the storage format specifications in the series, complementing the previously reviewed pack format documentation.
