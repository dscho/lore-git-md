Bugfix for `git add --interactive` hunk selection behavior.

This patch addresses the regression reported by Ulrich Windl where `git add -p` would incorrectly reprocess already-decided hunks when using the "J" (join) command. The fix modifies the hunk selection logic in `add-patch.c` to skip over hunks that have already been decided (either accepted or rejected) when rolling over to the next undecided hunk after reaching the end of the list.

The core change is in `patch_update_file()` where instead of always resetting to hunk 0, it now scans forward to find the first undecided hunk (marked with `UNDECIDED_HUNK`). Two new test cases verify the fixed behavior: one where the join command is used first, and another where it follows an initial acceptance. The tests check the hunk sequence numbers to ensure only undecided hunks are reprocessed.

The patch appears well-targeted to the reported issue, with clear test coverage for both the original failure case and related scenarios. The change is minimal (9 lines added, 1 removed) and focused on the specific regression without broader refactoring. The commit message directly references the bug report and explains the behavioral change concisely.
