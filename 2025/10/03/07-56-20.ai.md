Feature/bugfix hybrid: Removal of obsolete `validate_submodule_git_dir()` function as part of the submodule gitdir path encoding series.

This patch removes the now-unnecessary `validate_submodule_git_dir()` function, which was previously used to detect path conflicts in submodule gitdirs. With the new URL-style encoding scheme for submodule paths (introduced earlier in the series), such conflicts are structurally prevented, making this validation redundant. The removal is part of Adrian Ratiu's ongoing work to modernize submodule path handling.

The patch follows up on Kristoffer Haugsbakk's typo correction ("purpouse"->"purpose") in the commit message, which Adrian acknowledges will be fixed in v3. This continues the pattern of documentation polish seen throughout the series. The removal is technically straightforward but represents an important conceptual shift - moving from runtime conflict detection to structurally guaranteed conflict avoidance through the encoding scheme.

Key technical points:
- Function was previously in `submodule.c` and used to validate submodule gitdir paths
- Became obsolete after introduction of RFC 3986 URL encoding for paths in patch 1/10
- Removal is part of broader effort to prevent filesystem conflicts in submodule gitdir paths
- Maintains all existing test coverage while eliminating now-redundant code
- Follows earlier typo fixes from Kristoffer Haugsbakk (this time correcting "purpouse" to "purpose")

The change is well-justified within the context of the larger path encoding work, which has seen extensive review and iteration. The series as a whole is approaching maturity, with v3 expected to incorporate remaining typo fixes and potentially address some of the open questions around path length validation and directory structure. This particular patch is a clean-up that logically follows from the core encoding work.
