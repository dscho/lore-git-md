Untracked files cache performance issue with explicit `--untracked-files=all`. Thread reports that while normal `git status` operations benefit from untracked cache (demonstrating 0.7s vs 3s performance difference on Windows), the cache is not utilized when `--untracked-files=all` is explicitly specified. This affects tools/IDEs that hardcode the flag. Verified via `git update-index --test-untracked-cache` showing cache is properly configured but bypassed in this case. Windows-specific timings provided (git 2.51.0.windows.1). No patch yet - issue appears to be a caching inconsistency in status machinery when flags override default behavior.
