Thread examining performance impact of untracked files cache behavior when `--untracked-files=all` is specified. Original report showed Windows-specific case where cache is bypassed despite being configured (git 2.51.0.windows.1), with Matthew Hughes now confirming same behavior on Linux (1.25s vs 0.38s difference). Key finding: commit e6a653554b makes cache work with `--untracked-files=all` only when `status.showUntrackedFiles=all` is also set, creating unexpected performance cliff for tools hardcoding the flag. Test case demonstrates 3x speedup when config/flag align (100k files scenario), revealing current implementation requires symmetry between runtime flag and config for cache activation. No patch yet - issue remains a caching inconsistency in status machinery when flags override defaults, with reproduction steps now clearly showing the config-dependent behavior. Windows and Linux timings both confirm the performance impact, suggesting cross-platform relevance.
