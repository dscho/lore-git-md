This is the second patch in a refactoring series for `git add -p`'s exit handling, now being approved by Junio C Hamano. The patch makes EOF conditions (like Ctrl-D) trigger immediate exit from the interactive interface, matching the behavior of the 'q' command that was cleaned up in the first patch.

Junio confirms the technical correctness of the change, noting it improves behavior for users with `interactive.singlekey` enabled (who previously saw an error message) while maintaining the same end-state for files. The patch eliminates unnecessary output by preventing display of subsequent files' hunks after EOF. Junio suggests but does not insist on potentially echoing 'q' to match explicit quit command behavior, ultimately accepting the patch as-is.

Key technical details:
- Modifies `patch_update_file()` in add-patch.c to handle EOF via same `quit` flag as 'q'
- Includes test in t3701 verifying EOF exits without showing subsequent files' diffs
- Preserves all non-exit command behaviors
- Maintains identical hunk application results despite earlier exit

The change completes the series' goal of consistent exit handling, with both patches now approved for merging. The small, focused improvements clarify internal behavior without affecting functionality, continuing Git's pattern of incremental code quality improvements.
