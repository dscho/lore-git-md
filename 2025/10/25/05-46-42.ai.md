This is a refactoring patch targeting the interactive patch selection interface (`git add -p`). The change simplifies the handling of the 'q' (quit) command by removing redundant processing of undecided hunks.

The patch observes that when quitting interactive patch selection, the code was marking all remaining undecided hunks as skipped before exiting. However, this marking was unnecessary because undecided and skipped hunks are treated identically by the rest of the code. The only functions that distinguish between UNDECIDED_HUNK and SKIP_HUNK are internal helpers that don't relevant after quitting.

The change separates the 'q' command handling from 'd' (skip) command handling, making 'q' immediately exit without processing remaining hunks. This is a clean simplification that doesn't change observable behavior since the skipped/undecided distinction wasn't meaningful at quit time anyway. The patch is small and focused, touching only the core hunk processing logic in add-patch.c.

Key technical details:
- Modifies the patch_update_file() function in add-patch.c
- Removes the special case where 'q' would first mark undecided hunks as SKIP_HUNK
- Keeps identical behavior for 'd' (skip) command
- Maintains all existing control flow for other commands (K, j, etc.)
- The change is purely internal - no user-visible behavior or interface changes
