This thread covers a refactoring of `git add -p`'s interactive interface to simplify exit handling, particularly for quit commands ('q') and EOF conditions (Ctrl-D). The two-patch series, already approved by maintainer Junio C Hamano, cleans up how these exit paths work by making them immediately terminate without processing remaining hunks or files. The first patch separates 'q' command handling from skip operations, while the second extends this behavior to match EOF conditions.

René Scharfe recently weighed in on a minor user experience question Junio raised - whether EOF should explicitly echo a 'q'-like message when exiting. René argues that silent exit aligns with Unix conventions (like `cat` behavior) and maintains the current implementation's approach. This appears to be the final point of discussion on an otherwise settled series, with no changes expected to the approved patches. The improvements provide cleaner internal handling while maintaining stable behavior for this core interactive command.
