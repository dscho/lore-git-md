Refactoring patch for `git add -p`'s EOF handling. This is the second patch in a series simplifying the interactive patch selection interface.

The patch makes `git add -p` quit immediately when it encounters EOF (like when a user presses Ctrl-D), matching the existing behavior for the 'q' command. Previously, the code would break out of the input loop but continue processing, which was unnecessary since no further user input would be available. The change is small and focused, touching just the input handling logic in `add-patch.c` while adding a test case to verify the new behavior.

The patch maintains consistency with the first patch in the series (which simplified quit handling for the 'q' command) and continues the theme of cleaning up the interactive patch selection code. The test case demonstrates the new behavior by showing that only the first file's prompt appears before the EOF-triggered quit, while the second file is never reached.

This is a straightforward improvement that makes the code's behavior match user expectations - when input ends unexpectedly, the interface should exit cleanly rather than continuing pointlessly. The change is low-risk and well-tested, with a clear commit message explaining the rationale.
