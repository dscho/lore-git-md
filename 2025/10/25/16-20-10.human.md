This is the second patch in a refactoring series for `git add -p`'s exit handling, now approved by Junio C Hamano. The change makes EOF conditions (like Ctrl-D) trigger immediate exit just like the 'q' command does, cleaning up inconsistent behavior.

The patch was already well-explained by René Scharfe, showing how EOF previously caused useless prompts for subsequent files. Junio confirms the technical correctness, noting it particularly improves behavior for users with `interactive.singlekey` enabled who previously saw confusing error messages. The change also eliminates unnecessary diff output for files that won't be processed after EOF.

Junio considers but ultimately decides against adding an explicit 'q' echo when EOF is detected, though he leaves the door open for future discussion on that point. The patch maintains all existing functionality while making the exit path more consistent. With both patches now approved, this completes the series' goal of simplifying `git add -p`'s exit handling.
