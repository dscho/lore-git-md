This is a refactoring patch for the interactive patch selection interface (`git add -p`). 

René Scharfe simplifies the handling of the 'q' (quit) command in the interactive patch loop. Currently, 'q' implicitly marks all remaining undecided hunks as skipped before quitting, but this behavior is unnecessary since the code treats skipped and undecided hunks identically after the loop. 

The change makes 'q' quit immediately without the extra step of marking hunks, making the code more straightforward. The patch is small (9 lines changed) and focused, touching only the hunk selection logic in `add-patch.c`. 

This appears to be a clean, logical simplification with no behavior change visible to users - undecided hunks will remain undecided rather than being marked as skipped when quitting, but since they're treated the same way, there's no practical difference. The change is well-explained in the commit message and the implementation looks correct. This is part 1 of a 2-patch series (though the cover letter isn't provided here).
