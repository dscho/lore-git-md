This is a documentation discussion thread about `git log` format strings and notes display.

Junio C Hamano responds to Ben Knoble's suggestion that `--oneline --notes` may be a sufficient workaround for displaying notes compactly. He agrees that notes formatting is inherently challenging since notes can contain arbitrary text, unlike commit messages which have structured subject/body separation via %s/%b placeholders.

The response highlights a fundamental limitation in Git's current format language - it lacks conditional formatting or text manipulation capabilities that would be needed to reliably extract just the first line of notes. Junio notes this could theoretically be addressed by unifying Git's format languages across commands (like `git log` and `git for-each-ref`), but clarifies this isn't an active development effort despite past discussions.

The exchange reinforces that the documentation gaps identified earlier (format string equivalences, notes formatting limitations) reflect real technical constraints rather than just documentation oversights. Junio's response suggests these issues may persist until there's broader format language unification work.
