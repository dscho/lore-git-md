This is a documentation discussion thread regarding `git log` format strings and notes display. Junio Hamano responds to Ben Knoble's suggestion about using `--oneline --notes` as a workaround for displaying notes in compact format.

The email clarifies several technical points about the current limitations of format strings. Hamano notes that while commit messages have distinct placeholders for subject (%s) and body (%b), notes only have a single %N placeholder with no way to extract just the first line. This makes inline notes formatting difficult without controlling note content.

Hamano mentions the long-discussed but unimplemented unification of format languages between `git log` and `git for-each-ref`, which could potentially provide conditional formatting capabilities needed for better notes display. However, he confirms this unification effort is currently inactive despite being a past mentoring topic.

The response reinforces that until such format language improvements materialize, the `--oneline --notes` approach remains the most practical solution for compact notes display, though it doesn't fully address the original documentation requests about format string equivalences. The email provides important context about why certain format limitations exist while keeping the documentation discussion grounded in current implementation realities.
