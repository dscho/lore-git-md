This is a follow-up discussion in the `git add -p` refactoring thread about EOF handling behavior. René Scharfe responds to Junio C Hamano's question about whether EOF (Ctrl-D) should produce output similar to the 'q' command when exiting the interactive interface.

The key technical point is whether the silent EOF exit (added in patch 2/2) provides sufficient user feedback compared to the explicit 'q' command output. René argues that silent EOF matches common Unix conventions (like `cat` behavior) and expresses personal preference against echoing 'q' for EOF cases. This maintains the current behavior where EOF exits immediately without processing remaining files, as established in the approved patch.

The discussion touches on the `interactive.singlekey` mode implication - while 'q' shows its command letter when typed, EOF remains silent in both singlekey and regular modes. No code changes are proposed here; this is purely about user experience expectations for the silent exit case. The thread remains settled on the technical implementation from the patches, with this being a minor UX consideration that doesn't appear to require further changes.
