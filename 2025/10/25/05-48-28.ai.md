This is the second patch in a refactoring series for `git add -p`'s interactive interface, focusing on handling EOF conditions similarly to quit commands. The patch makes the interface immediately exit when receiving EOF (like Ctrl-D input) rather than continuing to prompt for input that will never come.

The change is small but logical - when `read_single_character()` returns EOF, it now sets the same `quit` flag that the 'q' command uses, triggering immediate exit. This matches user expectations since further interaction would be impossible. The patch includes a new test case verifying that:
1. The first file's diff is shown (proving the interface started)
2. The second file's diff is not shown (proving EOF caused immediate exit)

Technical details:
- Modifies the same `patch_update_file()` function as patch 1/2
- Adds EOF handling alongside existing 'q' command logic
- Introduces new test in t3701 to verify EOF behavior
- Maintains all other existing command behaviors
- No config or interface changes

This completes the series' goal of simplifying quit/exit handling in the interactive patch interface. Like the first patch, this is a clean, focused change with clear motivation and test coverage. The two patches together remove subtle inconsistencies in how different exit conditions were handled.
