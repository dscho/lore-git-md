This is a documentation patch in the SHA-1/SHA-256 interoperability series, specifically addressing tag signature handling. It corrects the documentation to match the implementation that shipped in Git 2.29, where the current hash algorithm's signature appears in the tag body while the alternate algorithm's signature uses a header field (`gpgsig` or `gpgsig-sha256`).

The patch updates `hash-function-transition.adoc` to clarify that dual-signed tags contain both an in-body signature (for the current algorithm) and a header signature (for the alternate algorithm), rather than the originally documented scheme where SHA-256 signatures were meant to always use headers. The new text explains the signed payload calculation excludes both signature fields and the PGP delimiter.

This change aligns the documentation with reality after a missed patch in Git 2.29 resulted in the current behavior differing from the original design. The update simplifies the description of signing options from three cases (SHA-1 only, dual-signed, SHA-256 only) to a more accurate "one or both algorithms" model. The patch maintains technical precision while making the actual behavior clearer to readers working with signed tags during the hash transition.
