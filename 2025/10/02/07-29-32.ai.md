Policy documentation patch formalizing the Rust adoption timeline in Git's build process. This is the 7/9 patch in the v8 series introducing Rust infrastructure to Git core.

The patch adds a detailed section to `BreakingChanges.adoc` announcing that Rust will become mandatory in Git 3.0 (estimated H2 2026), following a phased transition period. The current optional Rust support (introduced in Git 2.49) serves as a test balloon for distributors. The document outlines three key milestones: initial auto-detection in 2.52, default-enabled in 2.53, and mandatory in 3.0. It includes escape clauses allowing deferral if significant downstream impact is observed, and establishes a long-term support release (the last pre-3.0 version) with extended maintenance.

The policy addresses ecosystem concerns by providing explicit transition path and safety nets, while acknowledging platform challenges (bootstrapping, toolchain availability). The document specifies build flags (`WITH_RUST=YesPlease`, `-Drust=enabled`) and maintenance commitments (4 cycles for bug fixes, 6 for security). This formalizes the governance aspects of the Rust transition that were demonstrated technically in earlier patches of the series, particularly the varint subsystem implementation.
