This is a refactoring patch in the Rust infrastructure series, specifically preparing the varint subsystem for Rust implementation by standardizing integer types.

The patch changes the varint encoding/decoding functions to use explicit integer widths (`uint64_t` for values, `uint8_t` for lengths) instead of platform-dependent types like `uintmax_t` and `int`. This makes the code more portable and provides a cleaner foundation for the Rust implementation that follows in the next patch. The changes touch several files that use varint encoding, including dir.c (untracked cache handling) and read-cache.c (index operations).

The refactoring is straightforward and mechanical, with each change clearly mapping to the new type signatures. The commit message explains the rationale well - varints have known maximum sizes (16 bytes encoded), so we can safely use fixed-width types. This is part of Patrick Steinhardt's larger effort to introduce Rust into Git core, with this particular change suggested by Ezekiel Newren.

The patch appears carefully done, with thorough updates to all callers of the varint functions. As part of the well-reviewed v8 series that Junio Hamano has signaled readiness to merge, this change seems uncontroversial and serves as useful groundwork for the Rust implementation.
