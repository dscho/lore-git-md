This is a follow-up in the ongoing discussion about commit graph handling in the pluggable ODB effort. Patrick Steinhardt responds to Junio Hamano's critique of treating commit graphs as backend-specific optimizations, proposing a middle path.

Steinhardt suggests decoupling the cache implementation from the object backend entirely, making the cache itself pluggable at the repository level. This would allow different cache representations while maintaining repository-wide access to graph data, addressing Junio's concern about core operations needing consistent graph access. He cites a Git Merge conversation with an unnamed JJ developer as inspiration for this approach.

The key proposal is to merge the first six patches of the series (which refactor commit graph handling without the controversial backend-specific changes) and drop the seventh patch that moved commit graphs into ODB sources. This would allow the architectural debate to continue separately from the immediate improvements.

The email shows Steinhardt adapting his position in response to Junio's critique while still maintaining the goal of making caching strategies flexible. The discussion remains unresolved but appears to be moving toward a compromise that preserves both pluggability and repository-wide graph semantics. The tone is collaborative, with Steinhardt explicitly seeking feedback on whether this approach addresses concerns before proceeding.
