This is a documentation patch in the SHA-1/SHA-256 interoperability series, specifically clarifying aspects of the pack file documentation that were previously ambiguous or incomplete. The patch focuses on three key areas of pack format documentation that have caused confusion:

1. CRC32 checksum details - Explicitly states that CRC32 checksums cover the entire packed object (header, base object name/offset, and compressed data) and specifies the zlib algorithm is used, addressing potential ambiguity given multiple CRC32 variants.

2. Object encoding - Clarifies that packed objects don't store the loose object-style "<type> <size>\0" prefix in their compressed form, though this prefix is still used for object ID computation. This resolves a common misconception about pack storage format.

3. Size field interpretation - Documents that size fields in packs always represent uncompressed sizes (of either raw objects or deltas), explicitly distinguishing this from offset encoding and noting that base object references aren't included in size calculation.

The changes are well-motivated by the need to help both Git contributors and alternative implementation developers correctly understand these subtle aspects of the pack format. The documentation additions are precise and address real points of confusion that could lead to implementation errors. As part of the broader hash transition work, these clarifications become particularly important as developers work with both old and new pack formats.
