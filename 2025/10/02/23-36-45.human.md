This is a follow-up discussion in the atomic ref updates patch series for `git replay`. Siddharth Asthana responds to Kristoffer Haugsbakk's suggestion about adopting a `--format` approach similar to `git-for-each-ref` for better composability.

The core discussion revolves around whether `git replay` should output in a flexible format that users could parse for various purposes (like triggering hooks or custom ref updates), rather than the current direct `update-ref --stdin` compatibility. Siddharth acknowledges the merit of the idea for future client-side features but explains that the current focus is on the simpler atomic update case for server-side workflows. He notes that adding `--format` now would require users to transform the output back to `update-ref` format for the most common use case, adding unnecessary complexity.

The exchange highlights an interesting design tension between immediate server-side needs (where atomic transactions are the priority) and potential future client-side functionality (where hook integration and output flexibility may become important). Siddharth leaves the door open for revisiting this approach when expanding `git replay` toward interactive rebase use cases. The discussion remains constructive, with both participants focused on long-term command design rather than immediate changes to the current patch series.
