This is a discussion contribution in the ongoing Git 3.0 release planning thread, focusing on SHA-256 interoperability challenges. Michal Suchánek responds to Junio C Hamano's analysis of roadmap-based planning for SHA-256 adoption, particularly regarding hosting provider incentives and user mobility constraints.

The email reinforces Junio's points about real-world adoption barriers while adding nuance about existing partial SHA-256 support. Michal notes that some users already create SHA-256 repositories on supporting forges when the feature is merely "nice to have," suggesting adoption could accelerate if SHA-256 becomes essential. However, they acknowledge the lock-in effects of non-Git tooling (issue trackers, CI) and network effects that limit user mobility between hosting providers, even when technical migration is possible.

Key technical context includes the current state where SHA-256 works in some forges but isn't default, and the observation that forge-to-forge migration tools exist but vary in quality. The discussion highlights the tension between technical capability (Git's SHA-256 implementation) and ecosystem factors (provider incentives, user workflows) that complicate any coordinated transition timeline. This continues the thread's progression from pure protocol constraints to analyzing the broader adoption landscape.
