This is the final patch in a 5-part series addressing Windows CI reliability and test improvements. It fixes a flaky test in t8020-last-modified.sh that was failing intermittently due to ambiguous tag sorting.

The test was originally written to catch a bug in `git-last-modified` related to criss-cross merges, but the author discovered the test was actually triggering the bug for a different reason - modifications to files in the same directory during a merge. The test was also problematic because it relied on tag names that could resolve ambiguously (both "k2" and "km2" pointed to the same commit), causing non-deterministic failures.

The patch rewrites the test to be more precise by:
1. Creating a standalone repository to avoid interference
2. Explicitly testing the directory modification case rather than the misleading criss-cross merge scenario
3. Removing a problematic `test_when_finished` call that didn't work in subshells

This change makes the test more reliable while still catching the original bug. The patch maintains the series' focus on CI stability, though this particular fix benefits all platforms rather than being Windows-specific. The author has validated the changes through GitLab pipeline runs.
