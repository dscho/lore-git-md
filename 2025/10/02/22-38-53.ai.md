This is a bugfix and documentation patch in the SHA-1/SHA-256 interoperability series, specifically addressing GPG signature header validation in tags. The patch enhances `fsck` to properly handle `gpgsig` and `gpgsig-sha256` headers in tag objects, which were previously ignored by default but could trigger errors in strict checking modes.

The changes introduce new error messages (`FSCK_MSG_BAD_GPGSIG` and `FSCK_MSG_BAD_HEADER_CONTINUATION`) for malformed signature headers, documented in `fsck-msgids.adoc`. The implementation validates both the initial signature line and continuation lines, ensuring proper formatting while allowing either signature type regardless of the repository's hash algorithm. Test cases verify acceptance of valid signature headers and rejection of malformed ones, including cases with trailing junk after headers.

Technical details include:
- New fsck message IDs for signature validation failures
- Header parsing logic in `fsck.c` that checks for proper line continuation formatting
- Test cases using `test_oid_cache` to handle algorithm-specific header names
- Validation of both complete and truncated signature headers
- Documentation of the new error conditions

The patch fits into the larger series by ensuring proper handling of signature headers during hash algorithm transitions, particularly important for tags that may contain signatures from both algorithms. It addresses a specific edge case in object validation while maintaining backward compatibility with existing tag formats.
