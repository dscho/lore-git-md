This is a test infrastructure patch in the SHA-1/SHA-256 interoperability series, adding support for testing compatibility hash scenarios. The patch introduces several key testing components:

The main addition is support for specifying a compatibility hash via `GIT_TEST_DEFAULT_HASH="sha256:sha1"` syntax, which will be used to test repositories where SHA-256 is the primary hash but SHA-1 compatibility is enabled. The patch splits this into two variables - `test_compat_hash_algo` for individual test cases and `test_repo_compat_hash_algo` for repository-wide settings.

Two new test prerequisites are introduced: `COMPAT_HASH` detects when tests are running in compatibility mode (SHA-256 with SHA-1 compatibility), while `BROKEN_OBJECTS` checks whether deliberately broken objects can be created (not possible in compatibility mode since there's no mapping for nonexistent objects). The implementation modifies `test-lib-functions.sh` to parse the new hash syntax and `test-lib.sh` to define the prerequisites.

This builds on the series' work around hash interoperability by enabling proper testing of scenarios where repositories operate with both hash algorithms. The changes are focused on test infrastructure rather than core functionality, with careful consideration given to how tests should behave differently in compatibility mode (like skipping tests that rely on older pack formats). The patch appears well-integrated with the series' broader goals and maintains the careful attention to testing edge cases seen in previous patches.
