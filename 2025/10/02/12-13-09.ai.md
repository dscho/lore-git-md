This is a discussion about SHA-256 interoperability challenges in the Git 3.0 release planning thread. Michal Suchánek responds to brian m. carlson's explanation of SHA-256 use cases by highlighting two concrete pain points that the current interoperability work doesn't address.

First, they note that Python tooling using pygit won't benefit from the SHA-1/SHA-256 compatibility layer, as pygit won't implement it. While a conversion scheme might be theoretically possible, its practicality is questionable. Second, they point out that mixed-hash repositories (containing both SHA-1 and SHA-256 submodules/subtrees) currently don't work together, and while the compatibility code could help here, it would render repositories unusable by forges and other tooling that lacks the compatibility layer.

The email underscores real-world adoption barriers beyond the core protocol limitations previously discussed, particularly around ecosystem fragmentation where some tools implement the compatibility layer while others don't. This adds to the growing list of practical considerations affecting the SHA-256 transition timeline and Git 3.0 planning. The response maintains the thread's focus on concrete workflow constraints rather than abstract migration concerns.
