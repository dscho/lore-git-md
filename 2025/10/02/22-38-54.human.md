This is a test infrastructure patch in the SHA-1/SHA-256 interoperability series, adding support for testing compatibility hash scenarios.

The patch introduces a way to specify compatibility hash algorithms in the test suite using `GIT_TEST_DEFAULT_HASH="sha256:sha1"` syntax, which will be important for testing repositories that use SHA-256 but maintain SHA-1 compatibility. The implementation handles both the primary storage hash and compatibility hash separately, with distinct variables (`test_hash_algo` and `test_compat_hash_algo`) for test scripts to use.

Two new test prerequisites are added: `COMPAT_HASH` detects when tests are running in compatibility mode, and `BROKEN_OBJECTS` determines whether tests can safely create deliberately broken objects (which isn't possible in compatibility mode since there's no way to map broken objects between hash algorithms). The patch also notes that some tests will need to be adjusted to account for compatibility mode constraints, like skipping older pack index formats that don't support multiple algorithms.

This appears to be a well-considered addition to the test infrastructure, building on previous work in the series to properly handle hash algorithm interoperability testing. The implementation is clean and the commit message clearly explains both the motivation and technical approach.
