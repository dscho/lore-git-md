This is part 2 of Ezekiel Newren's 3-patch series restructuring Git's static library build process, focusing on removing the XDIFF_LIB static library and folding its objects directly into LIB_OBJS. The change aligns with the meson build system's approach and supports future integration with Rust by avoiding naming conflicts with a planned 'xdiff' Rust crate.

The patch removes the xdiff-objs target, which Patrick Steinhardt questioned in his review. Newren explains this target was originally meant to ensure xdiff/lib.a was built, but becomes unnecessary when xdiff objects are directly included in libgit.a. He commits to updating the commit message to clarify this rationale.

The technical changes involve:
- Removing XDIFF_LIB from the build system
- Folding XDIFF_OBJS into LIB_OBJS
- Eliminating the now-redundant xdiff-objs target
- Updating GITLIBS references

This continues the series' pattern of simplifying the build system by eliminating intermediate static libraries while maintaining the same functionality. The discussion reveals an implementation detail about build targets that wasn't initially documented, showing the value of peer review in surfacing implicit knowledge. The change remains purely build-system focused with no impact on xdiff functionality or behavior.

The thread's open question about whether to maintain separate *_OBJS variables versus direct inclusion in LIB_OBJS remains unresolved, though this patch currently follows Junio Hamano's preference for keeping the intermediate variables for organizational purposes. The series appears ready to proceed pending Newren's commit message update regarding the xdiff-objs target removal.
