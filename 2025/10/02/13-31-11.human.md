This is a discussion about Git 3.0 release planning and SHA-256 interoperability challenges. Patrick Steinhardt responds to concerns raised by Taylor Blau and Luca Milanesio about ecosystem readiness for SHA-256 support.

Patrick argues that the project needs concrete roadmaps from Git implementations (like JGit) and hosting providers to set a realistic timeline for the Git 3.0 release with SHA-256 support. Without these roadmaps, the project faces an impossible choice between indefinite waiting (which removes pressure for adoption) or setting arbitrary deadlines that may be unrealistic. He suggests actively soliciting these roadmaps from known projects to inform the release planning process.

The email highlights the broader coordination challenge beyond just the core Git implementation work - database migrations at hosting providers and other ecosystem components need to be considered. Patrick's position emphasizes the need for concrete commitments from the wider Git ecosystem before proceeding with breaking changes in Git 3.0.

This continues the thread's progression from technical implementation concerns to ecosystem coordination challenges, now focusing on the practical process of gathering commitments from dependent projects. The discussion remains unresolved, with no clear consensus yet on how to balance technical readiness with ecosystem adoption timelines.
