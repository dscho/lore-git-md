This is a documentation patch that follows up on the ongoing worktree discussion thread, specifically addressing the agreed-upon need to improve `git worktree add` documentation regarding worktree placement.

The patch makes two key changes to the git-worktree documentation:
1. Adds a recommendation in the `git worktree add` section to place new worktrees outside the repository and existing worktrees, linking to the EXAMPLES section
2. Adds an anchor (`[[EXAMPLES]]`) to the EXAMPLES section to enable direct linking

This directly implements part of the thread's consensus around documenting best practices for worktree placement, particularly warning against nested worktree creation which was identified as a common user pitfall. The patch maintains the technical approach favored in the discussion - improving documentation rather than changing behavior - while addressing the specific need to guide users toward sibling directory layouts.

The changes are minimal and focused, targeting exactly the area of the manual that was under discussion. The patch doesn't attempt to resolve all open questions from the thread (like documenting the bare repository pattern), but provides a clear incremental improvement to the most pressing documentation gap identified. The implementation is straightforward and unlikely to be controversial given the prior discussion.
