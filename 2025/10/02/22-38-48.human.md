This is a documentation patch in brian m. carlson's SHA-1/SHA-256 interoperability series, specifically updating the pack index v3 format documentation. The change clarifies that offset values in the pack index should be looked up by pack order rather than object ID order, which better matches how Git's internals actually use this data.

The patch explains that the current dual-ordering (some data by object ID, some by pack order) creates inefficiencies, requiring multiple lookups to find an object's pack offset. The new design allows direct lookup by pack order index, which is more cache-friendly and eliminates the need for a reverse index with pack index v3.

The documentation update is straightforward, changing just a few lines to reflect that offset values are now indexed by pack order. This appears to be a well-justified change that aligns the documentation with practical implementation needs, continuing the series' careful attention to technical accuracy in the hash transition work.
