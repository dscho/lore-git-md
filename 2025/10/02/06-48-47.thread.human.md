The thread discusses the planned deprecation and potential removal of `git whatchanged`, a legacy command that shows commit logs with diff output. While functionally similar to `git log -p`, it has different defaults and is now redundant enough that maintainers want to remove it to reduce maintenance burden. A deprecation warning was added in Git 2.43.0 requiring users to pass `--i-still-use-this` if they still need the command.

Jiří Bašek provided the first concrete evidence of active usage, suggesting the command still serves a purpose for some workflows. In response, Kristoffer Haugsbakk offered detailed migration guidance, showing how to replace `git whatchanged` invocations with equivalent `git log --no-merges --raw` commands (or `--stat`/`--name-only` for human-readable output). This reinforces that the deprecation path remains the preferred direction, though the discussion remains open for additional user feedback that might justify keeping the command.

The thread now has both sides represented: a real-world case for keeping the command, and clear instructions for those who need to transition. The next steps likely depend on whether more users come forward with concrete use cases, or if maintainers consider the migration path sufficient to proceed with removal.
