Documentation patch adding formal specification for Git's loose object storage format, part of brian m. carlson's SHA-1/SHA-256 interoperability series (v2 5/9). This patch introduces `gitformat-loose.adoc` to document the previously unspecified format of loose objects.

The new documentation covers:
- Storage location (`$GIT_DIR/objects/[0-9a-f][0-9a-f]/*`) with sharding rationale
- Object file structure: type/size prefix followed by object data, all zlib-compressed
- Object ID computation from uncompressed data (works for both SHA-1 and SHA-256)
- Concrete examples showing empty tree and simple blob storage
- Relationship to packfiles in repository maintenance lifecycle

The patch integrates cleanly with existing documentation system, adding the new file to both Makefile and meson.build. The content appears technically accurate and fills a notable documentation gap, particularly relevant for the hash algorithm transition work where understanding object storage details becomes more critical. The examples help illustrate both the format and the SHA-256 case specifically.

This is a straightforward documentation improvement that builds on the series' goal of properly specifying Git's object storage formats. It follows the pattern seen in earlier patches of the series where implementation details that were previously only in code or implied by behavior are being formally documented.
