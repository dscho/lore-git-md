Maintainer perspective on patch review workflows. Junio C Hamano responds to Henrique Soares' question about how maintainers review patches, clarifying his earlier explanation about local patch application.

Hamano explains that experienced reviewers develop an intuition for when they can assess a patch directly from email versus when they need to apply it locally first. For small, straightforward patches, he can often review them just by reading the email. For more complex changes, he'll apply the patch to a temporary branch and use Git tools like `git log -p` with wider context or `git show` to examine specific file states at different points in the history.

The response emphasizes that the workflow isn't strictly linear - experienced maintainers fluidly move between email review and local Git tools depending on the patch's complexity. Hamano notes that while deep analysis requiring local application isn't needed for every patch, it's a common enough occurrence for non-trivial changes. This provides useful context about the practical realities of maintainer workflows beyond the theoretical ideal.
