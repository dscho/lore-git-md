This is a test infrastructure patch in the SHA-1/SHA-256 interoperability series, specifically addressing how broken object tests work in compatibility mode.

The patch modifies `t1010-mktree.sh` to properly handle tests involving broken objects when hash compatibility mode is active. The key change is wrapping broken object creation in a `BROKEN_OBJECTS` prerequisite check, since these tests can't work in compatibility mode where objects must be mappable between hash algorithms.

The author explains that broken objects can't be properly mapped between hash algorithms in compatibility mode, so these tests need to be disabled in that scenario. The changes are straightforward - test cases that create or use broken objects are now properly guarded by the prerequisite, and one test is explicitly marked with the prerequisite.

This appears to be a well-justified change that maintains test coverage while respecting the constraints of hash compatibility mode. It's the final patch in a larger series that has received thorough review, and this particular change seems uncontroversial - just ensuring tests behave correctly in all configurations.
