This is a documentation patch clarifying the `--merge-base` option for `git merge-tree`. 

Elijah Newren improves the man page by splitting a long sentence into two for better readability and adding important context about limitations. The key clarification explains that when merging branches with multiple merge bases, using `--merge-base` with a single base may produce different results than a regular `git merge`, potentially losing some changes from one side of history. 

The patch also makes it clearer that when using `--merge-base`, the input arguments can be trees rather than commits. The changes are straightforward and uncontroversial, addressing documentation gaps that could confuse users about edge cases in merge behavior.
