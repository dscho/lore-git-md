This is a documentation patch addressing the ongoing discussion about `git worktree` behavior and UX. It's the first of two patches from Michal Suchánek implementing the documentation improvements discussed in the thread.

The patch makes two concrete changes to the `git-worktree` man page:
1. Adds a new paragraph advising users to place new worktrees outside existing repositories and worktrees, linking to the EXAMPLES section
2. Adds an anchor (`[[EXAMPLES]]`) to the EXAMPLES section so it can be directly referenced

This directly addresses the thread's consensus that we should document best practices around worktree placement (specifically avoiding nested worktrees) rather than changing behavior. The change is minimal but important, as it helps prevent the common pitfall of creating worktrees inside other worktrees while maintaining the current technical behavior.

The patch appears well-formed and focused, implementing one of the agreed-upon documentation improvements from the discussion. It doesn't attempt to solve all the open questions from the thread, but makes a clear step forward on the nested worktree warning aspect.
