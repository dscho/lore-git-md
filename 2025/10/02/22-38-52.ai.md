Feature patch adding compatibility hash reporting to `git rev-parse` as part of the SHA-1/SHA-256 interoperability series.

This patch extends `git rev-parse --show-object-format` with a new `compat` mode to report the compatibility hash algorithm when one is configured (via `extensions.compatobjectformat`). The implementation handles cases where no compatibility hash exists by outputting a newline, maintaining unambiguous output when multiple format options are used together.

Key technical details:
- Adds `compat` option alongside existing `storage`, `input`, and `output` modes
- Uses `the_repository->compat_hash_algo` to check for configured compatibility hash
- Includes comprehensive tests covering:
  - SHA-256 repo with SHA-1 compatibility mode
  - SHA-256 repo without compatibility mode
  - Error cases for invalid mode names
- Updates documentation to explain the new mode and its empty output behavior

The change fits into the broader hash interoperability work by providing plumbing to query the compatibility hash algorithm, which is important for tools that need to handle objects in both formats during transitions. The test cases demonstrate the expected behavior in both compatibility and non-compatibility scenarios, including verification of empty output when no compatibility hash is configured.

This appears to be a straightforward addition with clear documentation and thorough test coverage. The implementation matches the pattern established by the existing hash format reporting modes while cleanly handling the case where no compatibility hash exists.
