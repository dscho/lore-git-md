This is a documentation patch in the SHA-1/SHA-256 interoperability series, specifically updating the pack index v3 format specification. The patch changes the pack index format to use 8-byte offsets instead of 4-byte ones to accommodate repositories with extremely large numbers of objects (beyond 67 million), which some users are already approaching with 55+ million commit repositories.

The changes also clarify checksum handling: the trailer will now use the repository's "full main hash" (32-byte SHA-256 or 20-byte SHA-1) rather than always assuming SHA-256. This maintains consistency with the packfile checksums and avoids potential security compliance issues from hash truncation. The documentation makes it explicit that the checksum algorithm matches the repository's primary hash function.

The patch is well-motivated with clear reasoning about both the technical limitations (32-bit offset constraints) and policy considerations (security compliance). As the first in a 9-part series, it sets up foundational documentation for future pack index v3 implementation work. The changes appear straightforward and uncontroversial, focusing purely on documentation updates for a not-yet-implemented format.
