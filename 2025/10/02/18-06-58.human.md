Maintainer feedback on worktree documentation patch. This is Junio Hamano's review of the second patch in Michal Suchánek's series improving `git worktree` documentation. The patch adds an example showing how to set up parallel branch checkouts from a bare repository.

Hamano suggests two key improvements to the example: First, he recommends against naming the bare repository `.git` to avoid confusion with non-bare repositories. He provides an alternative example using `bunny.git` that makes the setup clearer. Second, he questions whether the bare repository approach is actually better than the more conventional workflow with a primary non-bare worktree, offering a contrasting example of that style.

The review maintains a constructive tone while raising important usability concerns. Hamano's feedback suggests the example needs clearer motivation for why someone would choose the bare repository approach over the more common primary-worktree pattern. This follows up on Kristoffer Haugsbakk's earlier suggestion to better explain the use case.

The patch remains under discussion, with the maintainer flagging these as areas for potential revision before final acceptance. The feedback continues the thread's focus on making worktree documentation both technically accurate and practically useful for common workflows.
