Documentation update for pack index v3 format as part of SHA-1/SHA-256 interoperability work.

This patch updates the documentation for the proposed pack index v3 format, focusing on two key changes from v2: expanding offset fields from 4 to 8 bytes to support repositories with extremely large numbers of objects, and clarifying checksum handling for the new format. The technical rationale explains that 4-byte offsets would constrain repositories to about 67 million objects, which some users already approach with "high score" repositories containing 55+ million commits. The checksum discussion notes that while truncated hashes would work, using full-length SHA-256 checksums (32 bytes) matches existing packfile handling and avoids potential security compliance concerns.

The documentation specifies that the trailer checksum will use the repository's primary hash algorithm (SHA-1 or SHA-256) at full length, with explicit clarification added about what constitutes the "full main hash." This change aligns with the broader hash transition work while maintaining backward compatibility. The patch is part of a larger series establishing foundations for hash algorithm interoperability, with this particular piece focusing on documentation updates before implementation.
