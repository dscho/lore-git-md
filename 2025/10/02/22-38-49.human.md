This is a documentation patch in the SHA-1/SHA-256 interoperability series, specifically addressing tag signature formats. The patch corrects the documentation to match the actual behavior that shipped in Git 2.29, where the current hash algorithm's signature appears in the tag body while the alternate algorithm's signature appears in a header (either `gpgsig` or `gpgsig-sha256`).

The change clarifies that dual-signed tags will contain both an in-body signature and a header signature, with the placement determined by which algorithm is active. This replaces the previous documentation that incorrectly described the SHA-256 signature as always appearing in a header. The new wording better reflects the code's actual behavior while maintaining the same flexibility for single or dual signatures.

The patch is straightforward and well-justified, fixing a documentation discrepancy that arose from an earlier implementation change. As part of the larger hash transition work, this helps ensure the documentation accurately describes how signature verification works across hash algorithms. The change is limited to one file and focuses purely on documentation accuracy without introducing any new behavior.
