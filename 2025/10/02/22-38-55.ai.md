This is a test infrastructure patch in the SHA-1/SHA-256 interoperability series, specifically addressing test behavior in compatibility hash scenarios.

The patch modifies `t1010-mktree.sh` to properly handle broken object tests when hash compatibility mode is enabled. The key change is wrapping test cases that create broken objects (like missing objects) with the `BROKEN_OBJECTS` prerequisite, which was introduced earlier in the series to detect when such tests should be skipped.

Technical details:
- Moves the broken object creation (`git update-index --add --info-only` and related commands) inside a `test_have_prereq BROKEN_OBJECTS` conditional
- Adds the `BROKEN_OBJECTS` prerequisite to the test case checking `--missing` behavior
- Maintains all existing test logic but makes it conditional on the test supporting broken objects

The change reflects the series' ongoing work to ensure tests properly account for hash algorithm compatibility constraints, where broken SHA-1 objects cannot be reliably mapped to SHA-256. This is the final patch in the 9-part series, focusing on test suite adjustments to support the new compatibility mode infrastructure.
