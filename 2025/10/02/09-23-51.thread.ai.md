Interactive add navigation behavior fixes and improvements (v3 series):

This thread addresses a regression in `git add --interactive` hunk selection and improves interface consistency across all navigation commands. The v3 series from René Scharfe builds on previous work to unify circular roll-over behavior, now extending it to 'a' and 'd' commands while refining error messages, test coverage, and documentation.

Core changes in v3:
1. Extended roll-over to 'a' (add) and 'd' (don't add) commands, making them behave like 'y' and 'n' by seeking next undecided hunk after action
2. Direction-neutral error messages replacing "No next/previous hunk" with "No other [undecided] hunk" consistently across all commands
3. New `get_first_undecided()` helper centralizing undecided hunk logic
4. Expanded test coverage in `t/t3701-add-interactive.sh` including:
   - New test case for 'J' command roll-over behavior
   - Updated command lists to include 'J' in all relevant tests
5. Documentation and help text improvements:
   - Explicitly stating 'J' roll-over behavior in `git-add.adoc` and in-program help
   - Clarifying navigation commands (j/J/k/K) as pure movement operations
6. Implementation refinements:
   - Condition change to show 'J' command option when there's more than one hunk
   - Maintained all v2 improvements including circular navigation helpers and state management
