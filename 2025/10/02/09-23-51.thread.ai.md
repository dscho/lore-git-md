Interactive add bug report and fix summary:

Ulrich Windl reported a regression in `git add --interactive` hunk selection behavior in Git 2.51.0 where the "J" (join) command would incorrectly reprocess already-decided hunks after mixed "y"/"n" responses. The bug was in `add-patch.c`'s `patch_update_file()` function handling hunk state transitions during join operations.

René Scharfe submitted a fix modifying `patch_update_file()` to properly skip decided hunks (marked with `UNDECIDED_HUNK`) when rolling over to the next undecided hunk. The 10-line change introduces logic to find the first undecided hunk rather than resetting to hunk 0, with two new test cases verifying join-first and join-after-accept scenarios.

In response to Phillip Wood's (interactive add maintainer) review raising concerns about array bounds safety and test redundancy, René clarified that: 1) the loop only modifies `hunk_index` when finding an undecided hunk, maintaining existing out-of-bounds protection when no undecided hunks remain, and 2) both test cases serve distinct purposes - the second verifies the core functionality while the first specifically catches the regression scenario that motivated the fix. René noted the first test caught an earlier incorrect implementation attempt, justifying its inclusion.

The technical discussion has addressed the maintainer's concerns about edge case handling and test coverage rationale. The implementation appears sound with the bounds checking behavior now explicitly documented and test case purposes differentiated. The thread is nearing resolution with no outstanding technical objections, suggesting the fix is likely ready for integration pending any final maintainer approval. Key details remain the `UNDECIDED_HUNK` state handling in `patch_update_file()` and the two complementary test scenarios covering both regression prevention and core functionality verification.
