Interactive add navigation behavior fixes and improvements (v2 series):

This thread addresses a regression in `git add --interactive` hunk selection and broader interface design questions around navigation commands. The core issue involves incorrect hunk state transitions in `add-patch.c`'s `patch_update_file()` during join operations with mixed "y"/"n" responses. René Scharfe's v2 series expands the initial bugfix to improve navigation consistency across all commands (j/J/k/K/y/n/e).

The series now includes:
1. Documentation and behavior formalization (patches 1-2):
   - Explicitly documented and implemented roll-over for 'J' (next hunk) command
   - Modified hunk navigation to check `file_diff->hunk_nr > 1` for roll-over
   - Added test case verifying 'J' roll-over behavior
   - Updated existing tests to include 'J' in command lists
   - Leverages existing `permitted` bitmask behavior for roll-over

2. Forward navigation unification (patch 3):
   - Introduced `inc_mod()` helper for circular hunk navigation
   - Made y/n/j/e commands consistently seek first undecided hunk when wrapping
   - Updated documentation and test cases

3. Backward navigation symmetry (patch 4):
   - Added `dec_mod()` helper mirroring `inc_mod()`
   - Extended roll-over to backward commands (k/K)
   - 'k' rolls to last undecided hunk when at first hunk
   - 'K' rolls to last hunk when at first hunk
   - Junio Hamano noted implementation asymmetry between 'J' and 'K' commands

4. State management fix (patch 5):
   - Moves `permitted` bitmask declaration inside hunk processing loop
   - Prevents state leakage between hunks
   - Test case for invalid command rejection

5. Documentation polish (new patch):
   - Simplifies help text for j/J/k/K commands
   - Removes redundant state change language
   - Open question about extending clarity to y/n commands

Key technical aspects:
- Navigation behavior now fully symmetric between forward/backward movement
- `inc_mod()`/`dec_mod()` helpers implement circular navigation logic
- `permitted` bitmask handling refined to prevent state leakage
- Test coverage expanded for all roll-over scenarios
- Documentation accurately reflects command behaviors

Junio Hamano and Phillip Wood have provided feedback throughout, with all major concerns addressed. Remaining minor points include:
- Implementation asymmetry between 'J' and 'K' commands
- Potential redundancy in overflow checking
- Error message wording for single-hunk case
- Documentation clarity for y/n commands

The series maintains focus on fixing the core issue while systematically improving the interactive add interface's consistency, with each patch building on the last to create a cohesive solution.
