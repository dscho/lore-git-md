Interactive add navigation behavior fixes and improvements:

This thread addresses both a regression in `git add --interactive` hunk selection (reported by Ulrich Windl) and broader interface design questions around hunk navigation commands. The core issue involves incorrect hunk state transitions in `add-patch.c`'s `patch_update_file()` function during join operations, particularly with mixed "y"/"n" responses.

René Scharfe's v2 patch series expands beyond the initial bugfix to improve navigation consistency across all commands (j/J/k/K/y/n/e). Key technical aspects:

1. Navigation behavior unified:
   - All commands now consistently roll over to next undecided hunk
   - Added roll-over support for backward movement ('k'/'K') matching forward ('j'/'J')
   - `permitted` bitmask reset at loop start prevents state leakage
   - `UNDECIDED_HUNK` state handling refined in `patch_update_file()`

2. Implementation changes:
   - Split roll-over behavior for 'j' into dedicated patch
   - Modified hunk_index handling to improve navigation symmetry
   - Maintained backward compatibility while making interface more predictable

3. Testing and documentation:
   - Expanded test coverage for wrap-around scenarios
   - New cases verify all navigation command behaviors
   - Documentation clarifies 'j' (next undecided) vs 'J' (next hunk) distinction

The discussion with Junio Hamano and Phillip Wood has evolved from fixing the immediate regression to addressing deeper design questions:
- Navigation symmetry between forward/backward movement
- Consistent treatment of decided vs undecided hunks
- State management during hunk transitions
- size_t vs signed integer for hunk_index
- Formalizing hunk state reversion mechanism

Open technical considerations:
1. Whether to intentionally support wrap-around navigation
2. Handling of backward navigation edge cases
3. Distinction between "view all hunks" (J/K) and "next undecided hunk" (j/k) behaviors
4. Documentation accuracy for state transitions
5. Array bounds safety in hunk navigation

The series appears technically sound, with Phillip Wood having reviewed earlier versions regarding test redundancy and bounds safety. Junio's input has expanded the scope to include navigation symmetry and type safety. The v2 changes address many of these concerns while maintaining focus on the core regression fix.
