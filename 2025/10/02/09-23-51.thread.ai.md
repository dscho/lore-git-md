Interactive add bug report and fix summary:

Ulrich Windl reported a regression in `git add --interactive` hunk selection behavior in Git 2.51.0 where the "J" (join) command would incorrectly reprocess already-decided hunks after mixed "y"/"n" responses. The bug was in `add-patch.c`'s `patch_update_file()` function handling hunk state transitions during join operations.

René Scharfe submitted a fix modifying `patch_update_file()` to properly skip decided hunks (marked with `UNDECIDED_HUNK`) when rolling over to the next undecided hunk. The 10-line change introduces logic to find the first undecided hunk rather than resetting to hunk 0, with two new test cases verifying join-first and join-after-accept scenarios. Phillip Wood (interactive add maintainer) reviewed the patch, raising concerns about array bounds safety and test redundancy that René addressed through detailed technical explanations of the bounds protection and distinct test case purposes.

Junio C Hamano has now responded, confirming René's fix is correct for the specific hunk rollover case but identifying a deeper architectural issue in the command permission system affecting multiple interactive add operations. The `permitted` bitmask (controlling commands like split 's') isn't properly reset between hunk evaluations, causing commands to remain available when they shouldn't be. This dates back to the 2019 C rewrite of interactive add. Junio notes this bug accidentally created a useful feature - allowing wrap-around navigation with 'j/J' even when not explicitly offered - which may be worth preserving while fixing the underlying permission system issues.

The thread shows the immediate hunk rollover fix is technically sound and ready for integration, but has uncovered broader interactive add issues that may require follow-up work. The permission system bugs affect multiple commands (split, navigation) and represent technical debt from the C conversion. Key technical details remain the `UNDECIDED_HUNK` state handling in `patch_update_file()`, the two complementary test scenarios, and the newly identified `permitted` bitmask reset issue in the interactive add command architecture.
