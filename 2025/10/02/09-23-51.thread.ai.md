Interactive add bug report and fix summary:

Ulrich Windl reported a regression in `git add --interactive` hunk selection behavior in Git 2.51.0 where the "J" (join) command would incorrectly reprocess already-decided hunks after mixed "y"/"n" responses, unlike the correct behavior in Git 2.26.2. The bug was in `add-patch.c`'s handling of hunk state transitions during join operations.

A fix has been submitted that modifies `patch_update_file()` in `add-patch.c` to properly skip decided hunks (marked with `UNDECIDED_HUNK`) when rolling over to the next undecided hunk. The 10-line change (9 added, 1 removed) introduces targeted logic to find the first undecided hunk rather than resetting to hunk 0. Two new test cases verify the fix: one testing join-first behavior and another testing join-after-accept scenarios, both checking hunk sequence numbers to confirm only undecided hunks are reprocessed.

The patch directly addresses the reported regression with minimal changes and comprehensive test coverage. The commit message references Windl's report and clearly explains the behavioral correction. No other participants have commented on the thread yet, and no open questions remain regarding this specific fix. The change appears ready for integration pending review from the interactive add maintainers (historically Phillip Wood has been active in this area).
