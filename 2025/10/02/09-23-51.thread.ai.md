Interactive add navigation behavior fixes and improvements (v2 series):

This thread addresses both a regression in `git add --interactive` hunk selection (reported by Ulrich Windl) and broader interface design questions around hunk navigation commands. The core issue involves incorrect hunk state transitions in `add-patch.c`'s `patch_update_file()` function during join operations, particularly with mixed "y"/"n" responses.

René Scharfe's v2 patch series expands beyond the initial bugfix to improve navigation consistency across all commands (j/J/k/K/y/n/e). The series progresses through five key areas, with the final patch addressing state management:

1. Documentation and behavior formalization (patches 1-2):
   - Clarified help text for hunk navigation commands (j/J/k/K)
   - Explicitly documented and implemented roll-over behavior for 'J' (next hunk) command
   - Established test coverage for wrap-around scenarios

2. Forward navigation unification (patch 3):
   - Introduced `inc_mod()` helper for circular hunk navigation
   - Made y/n/j/e commands consistently seek first undecided hunk when wrapping around
   - Updated documentation to clarify j's behavior
   - Added test cases verifying roll-over with different command sequences

3. Backward navigation symmetry (patch 4):
   - Added `dec_mod()` helper mirroring `inc_mod()` for circular navigation
   - Extended roll-over behavior to backward commands (k/K)
   - 'k' now rolls to last undecided hunk when at first hunk
   - 'K' now rolls to last hunk when at first hunk
   - Updated documentation strings for backward commands
   - Expanded test coverage for backward roll-over scenarios
   - Junio Hamano suggests improving error message semantics ("No other hunk(s)" vs "No previous hunk")
   - Notes implementation asymmetry where 'J' doesn't use `inc_mod()` while 'K' uses `dec_mod()`
   - Questions whether overflow check is still needed with circular navigation helpers
   - Praises overall code quality as "a very pleasant read"

4. State management fix (patch 5):
   - Moves `permitted` bitmask declaration inside hunk processing loop
   - Prevents state leakage between hunks that could allow invalid operations
   - test case verifying rejection of invalid 's' command
   - Maintains ALLOW_GOTO_* flags while fixing accumulation issue
   - Completes series' focus on consistent state transitions

Key technical aspects of the full series:
1. Navigation behavior unified:
   - All commands now consistently roll over to next/last undecided hunk
   - Complete symmetry between forward ('j'/'J') and backward ('k'/'K') movement
   - 'J'/'K' commands formally wrap to first/last hunk when at boundary
   - `permitted` bitmask now properly reset at loop start
   - `UNDECIDED_HUNK` state handling refined in `patch_update_file()`
   - New `inc_mod()`/`dec_mod()` helpers implement circular navigation logic
   - Open question about error message wording for single-hunk case
   - Implementation asymmetry between 'J' and 'K' commands

2. Implementation changes:
   - Split roll-over behavior into dedicated patches for forward/backward movement
   - Modified hunk_index handling to improve navigation symmetry
   - Changed hunk count check from `hunk_index + 1 < file_diff->hunk_nr` to `file_diff->hunk_nr > 1` for roll-over
   - Maintained backward compatibility while making interface more predictable
   - Final patch ensures clean state per hunk via loop-local `permitted`
   - Overflow check may be redundant with circular navigation helpers

3. Testing and documentation:
   - Expanded test coverage for wrap-around scenarios including new tests for 'J'/'K' roll-over
   - New cases verify all navigation command behaviors including y/n/e roll-over
   - Added test for invalid command rejection via proper `permitted` handling
   - Documentation clarifies 'j'/'k' (next/last undecided) vs 'J'/'K' (next/last hunk) distinction
   - Help text updated to accurately reflect navigation command behavior
   - Updated existing tests to include full command set in expected output
