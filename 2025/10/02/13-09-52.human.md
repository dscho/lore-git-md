This is a technical discussion about SHA-1/SHA-256 interoperability challenges in the Git 3.0 release planning thread.

Michal Suchánek responds to brian m. carlson's explanation of SHA-256 interoperability use cases by highlighting two concrete problems: Python's pygit won't support the compatibility layer, and mixed-hash repositories (containing both SHA-1 and SHA-256 submodules) fail without universal tooling support. He notes that while the compatibility code could theoretically help with submodules, most forges currently lack this capability.

The email proposes a potential workaround where a compatibility-capable client could upload repositories to both SHA-1 and SHA-256 forges simultaneously, making both hash versions available. Michal acknowledges this wouldn't work in all cases but suggests it could be practical solution for mirroring scenarios where dual publication is already part of the workflow.
