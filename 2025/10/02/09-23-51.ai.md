This is a bug report regarding the interactive add feature in Git. Ulrich Windl reports unexpected behavior when using the "J" (join) hunk command in `git add --interactive`.

The issue occurs when selectively staging hunks: after answering some with "y" (yes), some with "n" (no), and one with "J" (join), Git incorrectly asks about both the joined hunk and the previously rejected hunk, rather than just the joined hunk as expected. The reporter notes this behavior differs from older Git versions (specifically mentioning 2.26.2).

The bug appears in Git 2.51.0 on a Linux system with standard tooling (GCC 7.5, glibc 2.38). The report follows the Git bug template format but doesn't include reproduction steps beyond the basic command sequence, nor does it specify which file types or diff contexts trigger the issue. The behavior suggests a regression in the hunk selection logic of the interactive add interface, particularly around the handling of joined hunks in relation to previously rejected ones.
