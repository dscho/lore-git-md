This is a follow-up in the ongoing discussion about commit graph storage in Git's pluggable object database (ODB) effort. Patrick Steinhardt responds to Junio Hamano's concerns about making commit graphs backend-specific by proposing a compromise approach.

The key shift is separating the cache mechanism from the object storage backend entirely. Steinhardt now suggests:
1. Merging the first 5 patches (which improve current behavior)
2. Dropping the controversial patch that tied commit graphs to ODB sources
3. Making the cache itself pluggable at the repository level

This aligns better with Junio and Taylor Blau's position that graph data should remain repository-wide accessible while still allowing flexibility in cache implementations. The proposal references discussions at Git Merge about making caches pluggable independent of storage backends.

The email shows Steinhardt adapting his approach based on feedback, moving from a backend-specific model to one where cache representation can be swapped while maintaining consistent repository-level access. The discussion appears to be moving toward resolution, though details of the cache pluggability interface remain to be worked out. The tone is collaborative, with Steinhardt seeking confirmation that this new direction addresses the core concerns raised.
