This is a refactoring patch in the Rust infrastructure series, specifically preparing the varint subsystem for Rust implementation by standardizing integer types.

The patch changes the varint encoding/decoding functions and their callers to use explicit-width integer types (`uint64_t` for values, `uint8_t` for lengths) instead of platform-dependent types like `uintmax_t` and `int`. This ensures consistent behavior across platforms and makes the C/Rust interface cleaner since Rust requires explicit widths. The changes touch four files:
- `varint.[ch]`: Core function signatures now use `uint64_t`/`uint8_t`
- `dir.c`: Updates call sites in untracked cache handling
- `read-cache.c`: Adjusts name field decoding in index handling

The refactor is motivated by both platform independence and the upcoming Rust reimplementation, where the explicit types will simplify FFI boundaries. The patch maintains identical behavior while making the theoretical limits clearer (16-byte varint maximum). All callers are updated to match the new types, including some adjacent cleanups like consistent `uint64_t` usage for length fields.

This is a straightforward technical prerequisite with no behavior change, clearing the way for the Rust implementation in the next patch. The changes are mechanical but thorough, updating all related code paths. The explicit widths will help prevent any platform-specific surprises during the Rust transition.
