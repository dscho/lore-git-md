Documentation patch refining worktree examples, addressing maintainer feedback.

This is the second patch in a series improving `git worktree` documentation, specifically focusing on examples of branch checkout patterns. The patch responds to Junio Hamano's feedback about repository naming conventions in the bare repository example.

The updated version now shows two approaches: a bare-centric layout (using `project.git` naming) and a primary-worktree approach. The author explains this is meant to demonstrate a workflow with one worktree per branch (avoiding branch switching), contrasting with ephemeral worktree use cases.

The discussion reveals differing opinions on repository layout philosophies - some prefer all worktrees being equal (bare-centric), while others favor a primary worktree model. The patch maintains a neutral stance by showing both patterns.

This continues the thread's theme of addressing worktree UX concerns through documentation rather than behavior changes. The patch appears ready for inclusion pending minor refinements to example formatting and motivation text suggested by other reviewers.
