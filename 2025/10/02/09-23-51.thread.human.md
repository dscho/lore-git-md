Here's a human-readable summary of the thread so far:

Ulrich Windl reported a regression in `git add --interactive` where using the "J" (join) command after mixed "y"/"n" responses would incorrectly reprocess already-decided hunks, unlike the correct behavior in Git 2.26.2. This affected the hunk selection logic when joining hunks with prior rejections.

A fix has now been proposed that modifies `add-patch.c` to properly skip already-decided hunks when rolling over to the next undecided hunk. The patch adds specific verification for this case, including tests that confirm the fixed behavior when joining hunks both before and after initial acceptances. The change is minimal and focused, directly addressing the reported issue while maintaining the existing workflow. The tests provide clear coverage of both the original failure case and related scenarios to prevent regression.
