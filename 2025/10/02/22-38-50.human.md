This is a documentation patch in brian m. carlson's SHA-1/SHA-256 interoperability series, focusing on clarifying the pack file specification. The patch addresses several ambiguities in the pack format documentation that could confuse contributors or alternative implementations.

The changes provide three key clarifications: First, it specifies that CRC32 checksums cover the entire packed object (including headers and deltas) and confirms Git uses zlib's CRC32 algorithm. Second, it explains that packed objects omit the type/size prefix found in loose objects, though this prefix is still used for object ID computation. Third, it clarifies that size fields in packs always refer to uncompressed sizes - for undeltified objects this means the full object size, while for deltas it's the delta size alone.

The patch is well-motivated by real implementation questions and fills genuine documentation gaps. The explanations are clear and technical without being overly verbose. As part of the larger hash transition work, these documentation improvements help ensure consistent behavior across implementations when dealing with pack files in both SHA-1 and SHA-256 repositories.
