Documentation patch in the `git worktree` UX improvement series, addressing feedback on the second patch about bare repository examples.

Junio Hamano provides maintainer feedback on Michal Suchánek's patch adding a bare repository worktree example. The core suggestion is to avoid naming the bare repository `.git` as it creates confusion with regular non-bare repositories. Instead, Junio proposes naming it after the project (e.g., `bunny.git`) for clarity. He demonstrates two alternative layouts:

1. The originally proposed bare-centric approach (now with clearer naming):
   - Creates a project directory
   - Clones bare repo into `project.git`
   - Adds worktrees from there

2. An alternative primary-worktree approach:
   - Creates project directory
   - Clones regular repo into `main`
   - Adds worktrees as siblings

Junio notes philosophical differences in these approaches (equal worktrees vs primary+ephemeral model) but doesn't reject either. The feedback focuses on making the example clearer while acknowledging both patterns exist in practice. This continues the thread's documentation-focused approach to worktree usage patterns rather than changing behavior.

Key technical points:
- Example currently shows bare clone into `.git` (problematic)
- Suggested change: use `project.git` naming
- Alternative workflow shown using primary worktree
- Both approaches remain valid, just need clearer documentation
- Maintains thread's documentation-only scope
- Builds on prior discussion of worktree layout patterns
- Follows from Kristoffer's earlier suggestion to simplify example

The patch will likely be revised to incorporate this naming clarification while keeping its core demonstration of parallel branch checkouts. This maintains the series' goal of documenting worktree patterns without prescribing one true way.
