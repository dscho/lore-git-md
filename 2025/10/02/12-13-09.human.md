This is a discussion about SHA-256 interoperability challenges in the context of Git 3.0 release planning. Michal Suchánek responds to brian m. carlson's explanation of SHA-256 use cases by pointing out real-world limitations that aren't addressed by the current interoperability work.

The email highlights two specific pain points: First, tooling like pygit that won't support the new hash algorithm won't benefit from the interoperability work, as there's no practical way to make these tools work with SHA-256 repositories. Second, mixed hash environments (where some repositories use SHA-1 and others SHA-256) create problems with submodules and subtrees, and while interoperability might help here, it would make repositories unreadable to forges and other tooling that lacks the compatibility code.

The tone suggests skepticism about how practical the interoperability solution will be for actual workflows, particularly when dealing with existing toolchains and forges. This adds another dimension to the ongoing discussion about whether to delay Git 3.0 until SHA-256 work is more complete, as it questions whether the current implementation will truly solve users' problems.
