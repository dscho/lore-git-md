This is a documentation patch in brian m. carlson's SHA-1/SHA-256 interoperability series, adding formal documentation for Git's loose object storage format. The patch introduces a new `gitformat-loose.adoc` man page that clearly explains how loose objects are structured and stored on disk.

The documentation covers several key aspects: the object file naming convention (sharded by first two hex digits of the hash), the object prefix format (`<type> <size>\0`), the zlib compression process, and how this differs from packed objects. It includes concrete examples showing both SHA-1 and SHA-256 object IDs and their storage paths, like the empty tree object.

This fills a notable gap in Git's documentation - while loose objects are a fundamental storage mechanism, their format wasn't previously formally documented. The patch is well-structured with clear examples and ties into the broader hash algorithm work by explicitly mentioning both SHA-1 and SHA-256 cases. As part of the larger interoperability series, it provides important baseline knowledge that will help developers understand how objects are handled during hash transitions.
