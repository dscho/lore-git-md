This is a documentation patch clarifying the `--merge-base` option in `git-merge-tree`. The changes improve readability and add important context about limitations.

The patch makes three main improvements to the `--merge-base` documentation in `git-merge-tree.adoc`:
1. Splits a long initial sentence into two for better readability
2. Explicitly states that using `--merge-base` with multiple possible merge bases may produce different results than `git merge`, potentially losing some changes
3. Clarifies that trees (rather than commits) are sufficient when using this option

The changes are straightforward documentation improvements that don't affect functionality. The added warning about multiple merge bases is particularly useful as it explains a non-obvious behavioral difference from regular merges. The patch comes from an established contributor (Elijah Newren) and follows standard documentation formatting.
