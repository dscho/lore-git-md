Test fix restoring GPG configuration persistence in t1016-compatObjectFormat.sh.

This email from Todd Zullinger confirms Junio Hamano's fix for a test regression in t1016-compatObjectFormat.sh. The issue stemmed from commit c348192a (2024-10-22) accidentally changing a persistent `git config` call to ephemeral `test_config` when setting gpg.program, breaking test dependencies where later tests relied on configuration from earlier ones.

Zullinger reports that the fix resolves test failures observed in CI and Fedora builds. He shares his debugging journey, noting he had suspected GPG wrapper issues earlier but didn't connect it to this configuration persistence problem. The email includes the minimal one-line diff reverting to `git config` for gpg.program setup.

The discussion reveals this was a subtle issue that evaded detection for nearly a year, with multiple contributors missing the root cause during debugging. While the fix itself is straightforward, the thread highlights how test infrastructure changes can have unexpected consequences when assumptions about configuration persistence aren't carefully maintained.
