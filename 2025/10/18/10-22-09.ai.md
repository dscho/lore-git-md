This is a follow-up in the ongoing discussion about modifying `git grep`'s default behavior regarding binary files. Jeff King (Peff) responds to Junio Hamano's objections by shifting the focus from binary files specifically to a more general solution for excluding unwanted files from grep results.

Key technical points:
- Notes that `git grep` differs from regular grep in defaulting to searching all repository files, making unwanted matches more common
- Suggests the binary file discussion is a subset of a larger problem - users often want to exclude certain files (text or binary) from grep results
- Points out existing attribute-based filtering via `:(attr:!binary)` syntax, but notes this is cumbersome
- Proposes a more general configuration mechanism to exclude files based on attributes by default

The email references a 2012 thread about similar functionality, indicating this is a long-standing pain point. While not directly addressing the binary file default debate, it offers a potential path forward that could satisfy both sides - allowing users to configure exclusions without changing defaults.

This moves the discussion toward a more flexible attribute-based solution rather than focusing solely on binary files. The proposal would require changes to how `git grep` handles attributes and configuration, potentially touching `grep.c` and related attribute-handling code.
