This is the second patch in a series to make `git add` respect the `ignore=all` submodule configuration consistently with other commands. The patch implements the core logic to skip submodules marked with `ignore=all` unless explicitly forced with `--force`.

The change modifies `read-cache.c` to check submodule ignore settings during index updates. When encountering a submodule with `ignore=all`, it will:
- Skip silently if not explicitly mentioned in the pathspec
- Show a warning and skip unless `--force` is used when the submodule is in the pathspec
- Maintain existing behavior for non-submodule files and submodules without `ignore=all`

The commit message explains this brings `git add` behavior in line with `git status` and `git diff`, creating a more consistent workflow for users tracking submodule branches rather than specific commits. The implementation appears thorough, adding proper submodule checks while preserving the existing force mechanism used for ignored files.

This is a logical next step after the first patch's API changes, cleanly implementing the promised behavior while maintaining backward compatibility. The patch includes trace statements for debugging but no test updates yet - those will presumably come in later patches of the series.
