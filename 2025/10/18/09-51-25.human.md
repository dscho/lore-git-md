Security vulnerability note in ongoing SSH agent test discussion.

Jeff King confirms Junio C Hamano's observation about a potential security vulnerability in how the test harness evaluates `ssh-agent` output. The unquoted evaluation of paths containing spaces could allow command injection if an attacker controls the $HOME environment variable, though Jeff notes this would likely be part of a broader compromise scenario.

This brief exchange highlights the security implications of the previously identified test setup issues, adding urgency to finding a robust solution that properly quotes paths. The discussion remains focused on test infrastructure rather than the core SSH signing functionality, but the security angle may influence how similar test patterns are handled elsewhere in the codebase.
