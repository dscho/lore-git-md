This is a reply in the ongoing discussion about making `git grep` ignore binary files by default. The email from Randall Becker supports maintaining the current behavior where `git grep` searches binary files by default, citing practical use cases like searching quasi-binary SQL files. He echoes concerns raised earlier by Brian m. carlson and Junio C Hamano about script compatibility and legitimate use cases for searching binary files, particularly where files contain embedded text metadata or are technically binary but still searchable.

The reply reinforces the thread's emerging consensus against changing the default behavior, while acknowledging the original motivation (user convenience when manually grepping). It doesn't introduce new technical arguments but strengthens the case for preserving backward compatibility, especially for professional workflows involving mixed file types. The discussion appears to be shifting toward either keeping the status quo or exploring more flexible attribute-based filtering as suggested by Jeff King, rather than a binary-specific default change.
