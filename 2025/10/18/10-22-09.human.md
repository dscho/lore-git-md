This is a discussion about extending `git grep`'s file filtering capabilities, building on the earlier thread about ignoring binary files by default.

Jeff King (Peff) responds to Junio Hamano's concerns about changing `git grep` defaults by proposing a more general solution. He notes that while binary files are one source of noise, the real issue is that `git grep` searches everything by default, unlike regular grep which requires explicit file selection. He suggests a configuration option to exclude files based on attributes (not just binary status) would be more flexible.

The email references a 2012 discussion about similar functionality and notes that while attribute-based filtering exists today via `:(attr:!binary)`, it's cumbersome to use. Peff advocates for making such filtering configurable by default, without breaking existing scripts. This shifts the discussion from binary-specific filtering to a more general attribute-based approach that could address multiple use cases while maintaining backward compatibility.

The proposal appears technically sound and builds on existing Git infrastructure, though it doesn't directly address Junio's concerns about configuration bloat. It offers a potential middle ground that could satisfy both sides of the original debate.
