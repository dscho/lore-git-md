This is a documentation refinement in the final stages of Julia Evans' `git-reset` man page restructuring series. Junio Hamano provides detailed feedback on wording of the `--soft`, `--hard`, and `--merge` mode descriptions, suggesting several precision improvements.

For `--soft`, Junio notes the current description could mislead readers about what gets staged when resetting multiple commits back, and suggests clarifying that both working tree and index remain unchanged. He also points out the squashing example works even with local changes since it doesn't use `-a`.

The `--hard` section could better explain that tracked files not present in the target commit will be removed. For `--merge`, Junio questions whether recommending `git merge --abort` is universally appropriate, since some unmerged states don't originate from merges. He approves removing the outdated `read-tree` comparison.

These suggestions continue Junio's pattern of ensuring technical precision matches the improved clarity of Julia's rewrite. The feedback focuses on edge cases and mental model accuracy rather than structural changes, indicating the series is nearly ready to merge pending these final wording tweaks.
