This is a test patch in a series making `git add` respect submodule `ignore=all` settings. It adds comprehensive tests for the new behavior introduced in the previous patches.

The new test script `t2206-add-submodule-ignored.sh` verifies that submodules with `ignore=all` are properly skipped by `git add` unless explicitly forced, matching the behavior of `git status` and `git diff`. The tests cover various scenarios including:
- Basic setup with submodule commits
- Behavior with default vs `ignore=all` configuration
- Status reporting with and without submodule ignoring
- Different `git add` invocations (normal, with `--force`, with explicit pathspecs)
- Edge cases like directory-style pathspecs (`./sub/`)

The tests appear thorough, checking both the expected silent skipping behavior and the explicit `--force` override path. They also verify the integration with other commands like `git status` and `git log`. The test structure follows Git's standard patterns and includes trace logging to help debug the ignore logic.

This patch completes the testing side of the series that aims to align `git add` behavior with other commands regarding ignored submodules. The tests look well-constructed and should help prevent regressions in this area.
