This is the first patch in a series to make `git add` respect the `ignore=all` submodule configuration consistently with other commands. The patch modifies core read-cache functionality to support this change.

The key change here is adding an `ignored_too` parameter to `add_files_to_cache()`, which will be used to force-add ignored submodules (similar to how `--force` works for regular ignored files). The parameter is plumbed through several callers in builtin commands (add, checkout, commit) and the function's signature is updated in read-cache-ll.h.

The implementation appears straightforward - it's primarily plumbing the new parameter through the call chain. The patch maintains backward compatibility by defaulting to the current behavior (0/false) at all call sites. This is a foundational change that enables the subsequent patches in the series to implement the actual ignore=all behavior.

As the first in a series, this patch focuses on the infrastructure changes without yet implementing the full feature. The thread context indicates this is part of a well-motivated effort to align `git add` behavior with `status` and `diff` when dealing with submodules configured with `ignore=all`.
