This thread discusses making `git add` respect the `ignore=all` submodule configuration consistently with `status` and `diff` commands. The original patch series proposed modifying `git add` to treat `ignore=all` submodules like regular ignored files - they wouldn't appear in diffs or be added without `--force`. The implementation touches core read-cache functionality across several commands.

Phillip Wood raised significant concerns about the approach, noting historical reasons why `git add` and `git reset` were deliberately made to ignore submodule config differently from `diff`. He questioned the use of `--force` as the override mechanism and suggested simpler implementation alternatives.

Claus Schneider's recent response shifts the discussion to user experience, arguing that from an end-user perspective, `ignore=all` should behave consistently across all commands that interact with submodules. He acknowledges documentation gaps around `reset`'s behavior and suggests potentially introducing new configuration values to clarify the semantics. While maintaining that the current patch's approach aligns with how ignored files work generally, he agrees `reset` would need similar treatment if `add` is changed.

The core debate now centers on whether to: 1) proceed with making `add` respect `ignore=all` as proposed, 2) maintain the historical divergence between viewing and action commands, or 3) explore new configuration options to better express the desired semantics. Technical concerns about implementation approach and backward compatibility remain unresolved, but the discussion has broadened to include clearer user-facing design considerations.
