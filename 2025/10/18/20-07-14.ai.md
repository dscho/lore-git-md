This is a feature patch series addressing submodule behavior, specifically making `git add` respect the `ignore=all` submodule setting consistently with how `status` and `diff` already handle it.

The cover letter explains that currently `git add` ignores the `ignore=all` configuration, which creates inconsistency with other commands and causes unnecessary friction when tracking submodule branches. The series makes `git add` treat `ignore=all` submodules like regular ignored files - they won't show in diffs or be added unless `--force` is used. This aligns with how tools like repo tool work and reduces accidental submodule updates.

The implementation touches core read-cache functionality, modifying how files are added to the index to account for ignored submodules. It includes comprehensive test coverage with a new test file (t2206) and updates to existing tests that previously added submodules without `--force`. Documentation updates clarify the new behavior for both `git-add` and gitmodules config.

Key technical points for future reference:
- Modifies `add_files_to_cache()` to take `ignored_too` parameter (equivalent to `--force`)
- Updates read-cache logic to check submodule ignore settings
- New test file t2206 specifically tests ignore=all scenarios
- Changes affect multiple builtins (add, checkout, commit) that use the modified cache functions
- Documentation updates explain the force requirement for ignore=all submodules

The changes appear well-motivated and the implementation seems thorough, with tests covering the new behavior and updates to maintain existing test suite compatibility. The documentation updates help users understand the new expectations.
