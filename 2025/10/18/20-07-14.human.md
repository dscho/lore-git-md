This is a feature patch series addressing submodule behavior, specifically making `git add` respect the `ignore=all` submodule configuration consistently with how `git status` and `git diff` already handle it.

The series aims to reduce friction when working with submodules configured with `branch=` and `ignore=all`. Currently, developers can unintentionally add submodule updates they meant to ignore, leading to unnecessary conflicts. The changes make `git add` treat `ignore=all` submodules like regular ignored files - they won't show in diffs or be added unless `--force` is used. This brings behavior in line with tools like repo and makes branch-based submodule workflows more reliable.

The implementation touches core read-cache functionality and updates several commands (`add`, `checkout`, `commit`) to handle the new behavior. It includes thorough test coverage with a new test script and updates to existing tests that previously added submodules without `--force`. Documentation for both `git-add` and gitmodules is also updated.

The changes appear well-motivated and carefully implemented, addressing a real pain point in submodule workflows. The patch series is complete with tests and documentation updates, suggesting it's production-ready. Submodule users, particularly those using branch tracking, will likely appreciate this improvement.
