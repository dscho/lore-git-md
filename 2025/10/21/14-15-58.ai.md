This is a refactoring patch in Patrick Steinhardt's `git-history` series, introducing in-memory index patching support to the add-patch infrastructure.

The patch adds a new `run_add_p_index()` function that allows applying changes to an arbitrary in-memory index rather than always using the repository's main index. This extends the existing `run_add_p()` functionality which was limited to working with the repository's index. The implementation involves modifying the `add_p_state` struct to track both the repository and index state separately, with careful handling of index reading/writing operations to maintain consistency.

Key technical details:
- New `index` and `index_file` fields added to `struct add_p_state`
- `run_add_p_index()` takes explicit `index_state` and `index_file` parameters
- Uses `read_index_from()` instead of `repo_read_index()` when working with alternate indexes
- Maintains same prompt strings and user interface as existing add-patch
- Handles binary files and empty changesets consistently with existing code
- Preserves all existing functionality when operating on the main repository index

The change is part of the larger effort to support `git-history`'s in-memory operations, with this infrastructure needed for subsequent patches. The implementation appears thorough, maintaining all existing behavior while adding the new capability. The patch follows the series' pattern of careful refactoring with clear boundaries between components.
