This is the final patch in a series introducing a new "geometric" maintenance strategy for Git repositories. The strategy aims to provide a better alternative to both the traditional "gc" and "incremental" approaches, particularly benefiting large repositories.

The geometric strategy performs all the standard cleanup tasks (reflog expiration, worktree pruning, etc.) but differs in its repacking approach. Instead of always doing full repacks like "gc" or limited incremental repacks, it uses Git's geometric repacking infrastructure. This means it only performs full repacks when repository growth warrants it, otherwise doing more efficient geometric repacks. When a full repack is needed, it generates a cruft pack to handle unreachable objects.

The patch adds documentation explaining the new strategy and its tradeoffs (notably that unreachable objects may persist longer than with "gc"), updates the strategy parsing code to recognize "geometric", and extends the test suite to verify the new behavior. The implementation appears thorough, with clear test coverage showing both manual and scheduled maintenance scenarios.

This completes the series' goal of providing a configurable maintenance system that can better scale to large repositories while maintaining data integrity. The approach has been reviewed by multiple Git maintainers and appears ready for consideration.
