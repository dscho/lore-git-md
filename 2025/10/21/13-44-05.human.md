This is a design discussion about the `--all` flag implementation for `git repo info`. Junio Hamano agrees with Patrick Steinhardt's suggestion to make `--all` and key arguments mutually exclusive, reversing his earlier position that allowing both was "most logical". 

The key points are:
- The current implementation allows combining `--all` with specific keys, producing all fields first followed by any specified keys (including duplicates)
- Patrick argued this leads to inconsistent output ordering and unclear use cases for duplicates
- Junio now agrees the command should match the synopsis and reject combinations, citing awkward output ordering as the reason

This resolves the open design question from the previous discussion, favoring interface consistency over flexibility. The change will make the implementation match the documented behavior where `--all` and key arguments are presented as mutually exclusive options.
