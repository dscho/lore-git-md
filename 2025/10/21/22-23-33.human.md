Follow-up technical clarification from Junio C Hamano on offline repository migration.

This is a brief but important technical correction to the previous advice about using `git bundle` for offline repository transfers. Junio Hamano points out that while `git bundle` is indeed designed for offline sharing of commit history, it doesn't handle repository configuration or hooks. For a complete repository migration (including these components), he recommends using direct filesystem operations like `rsync` or `cp` instead.

The email serves as a refinement to the earlier suggestions, steering the solution toward the more comprehensive approach when the goal is to replicate the entire repository environment, not just its commit history. This is particularly relevant for the original poster's scenario of migrating from a failing server where preserving the complete working state is likely important.

The thread now has two clear options presented: `git bundle` for history-only transfer when that suffices, and filesystem copy operations for complete repository migration. No new questions are raised here, but this clarification helps future readers understand the tradeoffs between the approaches.
