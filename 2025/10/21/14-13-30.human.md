This is a patch in the geometric repacking strategy series that makes the "gc" maintenance strategy explicitly configurable. It addresses two limitations in the current implementation where the gc strategy couldn't be explicitly selected and wasn't available for scheduled maintenance.

The patch modifies the maintenance strategy configuration to:
1. Document the "gc" strategy option alongside existing strategies
2. Allow the gc task to run for both manual and scheduled maintenance (previously only manual)
3. Update tests to verify the gc strategy works in both contexts

The changes are straightforward - renaming `default_strategy` to `gc_strategy` and adding the appropriate type flags. This completes the unification of strategy handling that was a key goal of the series, while maintaining backward compatibility (the gc strategy remains the default for manual maintenance).

This appears to be a well-justified change that cleanly addresses the identified limitations. The patch follows the established pattern from earlier in the series and includes appropriate test coverage. It represents the final piece needed for full strategy configurability across all maintenance types.
