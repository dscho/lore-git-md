Feature introduction: This is the foundational patch for a new `git-history` command, part of Patrick Steinhardt's v5 series to add more intuitive history editing capabilities to Git. The command aims to simplify common history rewriting operations like reordering, splitting, and squashing commits that currently require interactive rebase workflows.

The patch adds the basic plumbing for the command: a new `builtin/history.c` implementation, documentation stub marking it as status, build system integration, and minimal tests verifying basic invocation. The documentation positions this as an experimental alternative to `git-rebase` for non-merge histories, with subcommands to be added in subsequent patches (though none are implemented here yet).

This appears to be well-structured groundwork - the commit properly integrates with Git's build systems, includes basic smoke tests, and sets clear documentation expectations about the experimental nature of the feature. The implementation follows Git's established patterns for new commands, though the actual functionality will come in later patches of the series. As the first user-visible piece of this effort, it cleanly sets up the framework for the more complex history editing operations to follow.
