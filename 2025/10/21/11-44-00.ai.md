Refactoring patch in the `git-history` series, addressing code organization in the add-patch subsystem. This responds to Karthik Nayak's review of patch 08/12 in the v4 series, which splits out `struct interactive_options` from the add-patch implementation.

The patch introduces two new structs in `add-patch.h`:
- `interactive_options` (migrated from `add_p_opt`) for basic patch options
- `interactive_config` for color settings and interactive diff configuration

Patrick Steinhardt justifies keeping the current naming and location (rather than moving to `add-interactive.h` or adding `add_` prefixes) despite acknowledging `add_patch_interactive_config` would be more precise. The implementation includes initialization and cleanup functions for the new config struct.

This change supports the series' broader goal of refactoring interactive components for the history editing commands, though the immediate discussion focuses narrowly on naming and location tradeoffs. The response indicates the author considers this an incremental improvement worth keeping as-is despite the naming being slightly imperfect. No functional changes are proposed beyond the structural reorganization already shown to work with the `reword` and `split` subcommands.
