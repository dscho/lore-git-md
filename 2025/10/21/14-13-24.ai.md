This is a refactoring patch in the geometric repacking strategy series, specifically modifying how loose object threshold checking works in `gc.c`.

The patch simplifies the `too_many_loose_objects()` function by having it take a direct integer threshold parameter rather than requiring the full `gc_config` struct. This change prepares for future use cases where different thresholds may be needed, particularly for the new geometric repacking maintenance tasks being introduced in this series.

Key technical details:
- Changes the function signature from `too_many_loose_objects(struct gc_config *)` to `too_many_loose_objects(int)`
- Updates all callers to pass `cfg->gc_auto_threshold` directly
- Maintains identical behavior while making the function more flexible
- Part of broader refactoring to support configurable maintenance strategies

The change is straightforward and builds on prior review consensus about modularizing gc.c internals. It follows the series' pattern of making components more reusable while maintaining backward compatibility. This particular modification was previously discussed and approved by Junio C Hamano in earlier versions of the series.
