This is a cover letter for the fifth version of a feature series introducing a new `git-history` command for history editing operations. The series builds on Git's sequencer infrastructure and draws inspiration from Jujutsu's history editing capabilities, now narrowed to focus on non-conflicting operations after Git Contributor Summit discussions.

The v5 series includes twelve patches implementing two subcommands (`reword` and `split`) along with supporting infrastructure changes. Key technical components include:
- New `builtin/history.c` implementing both subcommands
- Shared `replay.c` infrastructure integration
- Add-patch refactoring with new structs (`interactive_options`, `interactive_config`)
- Cache-tree modifications for in-memory operations
- Commit validation and message handling improvements
- Test coverage in `t/t3450-history.sh`, `t/t3451-history-reword.sh`, and `t/t3452-history-split.sh`

Notable changes in v5:
- Rebased onto latest `seen` branch with sa/replay-atomic-ref-updates
- Fixed descendant checks to properly verify HEAD reachability
- Improved commit message hint text
- Deduplicated subcommand usage strings
- Added tests for reachability validation
- Various commit message and style improvements

The series has addressed all technical review feedback from previous iterations and appears ready for integration, with only minor open questions remaining about future UX extensions. The implementation avoids merge commits and focuses on atomic operations that don't create conflicts, making it a focused starting point for history editing capabilities in Git.
