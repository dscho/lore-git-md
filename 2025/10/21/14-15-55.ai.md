Refactoring patch in the `git-history` series, focusing on code organization between add-patch and add-interactive subsystems.

This patch (7/12 in v5 series) splits the `add-patch` related declarations from `add-interactive.h` into a new `add-patch.h` header. The change clarifies subsystem boundaries by moving structs (`add_p_opt`, `add_p_mode`) and functions (`run_add_p`) that are specific to patch application logic. The original `add-interactive.h` retains interactive mode declarations while including the new header.

Key technical details:
- Creates new `add-patch.h` with all patch-specific declarations
- Keeps `add-interactive.h` focused on interactive mode management
- Maintains backward compatibility through header inclusion
- Updates `add-patch.c` to include its new header
- Preserves all existing functionality while improving code organization

The change supports the series' broader goal of refactored add-patch infrastructure needed for `git-history`'s interactive editing capabilities. This is a clean separation that follows established patterns for subsystem boundaries in Git's codebase. The patch appears straightforward with no behavior changes, just improved code organization.
