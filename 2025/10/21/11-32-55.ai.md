Technical discussion about type choices in xdiff refactoring.

Phillip Wood questions the use of `ssize_t` for the `dstart` and `dend` fields in `xdfile_t` in the first patch of the completed xdiff modernization series. He suggests `ptrdiff_t` might be more appropriate since these fields represent pointer offsets, noting that `ssize_t` isn't guaranteed to match `size_t` width and is POSIX-specific rather than standard C. He references a past issue where this caused problems.

This follows earlier discussions about type safety in the series, where other participants examined hash field types and memory impacts. The current exchange focuses specifically on the technical merits of pointer-relative offset types, an important consideration for the cross-language compatibility goals of the refactoring. Phillip's comment doesn't challenge the overall approach but seeks clarification on this specific type choice, suggesting the thread may prompt additional documentation about the rationale for `ssize_t` versus alternatives.
