This thread discusses whether to enable Git's `rerere` (reuse recorded resolution) feature by default, which currently requires explicit configuration. While the technical implementation is mature, several usability concerns have emerged that could trip up users if enabled without warning.

The core issue is that `rerere` silently reuses past conflict resolutions, which can surprise users when outdated resolutions get reapplied. Key pain points include unclear messaging about reused resolutions, a non-intuitive workflow for correcting bad cached resolutions (requiring manual `git rerere forget` during a conflict state), and complete lack of support for delete/modify conflicts. Johannes Sixt raised concerns about novices struggling with incorrect cached resolutions, while Junio Hamano and Ben Knoble have identified specific gaps in the user experience.

The latest email from Junio highlights that delete/modify conflicts represent another sharp edge - the feature currently ignores these cases entirely rather than providing even basic handling. This leaves users to resolve such conflicts manually without realizing `rerere` won't help. The discussion now centers on whether to: 1) document these limitations clearly if enabling soon, 2) improve the feature to handle more cases before enabling, or 3) wait until Git 3.0 to make the change while addressing all known issues. The technical consensus is that `rerere` works as designed, but the user-facing experience needs polish regardless of when the default flips.
