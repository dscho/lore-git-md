This thread discusses whether to change the default setting of `rerere.enabled` from off to on, recognizing that while the technical implementation is mature, several usability issues need addressing. The conversation began with Junio Hamano suggesting Git 3.0 as a natural point for this change, but others like Taylor Blau argue it could happen sooner given rerere's stability. Kristoffer Haugsbakk and Johannes Sixt highlighted key pain points: unclear messaging about reused resolutions, a counterintuitive workflow for correcting cached resolutions, and insufficient documentation.

Recent contributions from Ben Knoble and Johannes Sixt have shifted the focus toward compiling a list of specific usability improvements needed before flipping the default. These include better status reporting to make reused resolutions more visible and a more intuitive than the current `git rerere forget` workflow that requires recreating conflict states. While the technical core of rerere is sound, there's growing consensus that these user-facing issues should be addressed—either before enabling it by default or soon after. The discussion remains open on whether to proceed with the change in Git 2.x with follow-up fixes or wait until 3.0 with a more polished experience. The thread is now converging on identifying concrete action items to improve rerere's usability regardless of the timing decision.
