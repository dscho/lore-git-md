The thread discusses a proposal to enable Git's rerere (reuse recorded resolution) feature by default, which currently requires explicit configuration. While the technical implementation is considered stable after years of opt-in use, significant usability concerns have emerged that may delay the change.

Key participants including Kristoffer Haugsbakk, D. Ben Knoble, and now Johannes Sixt have identified several pain points: confusing output messages, misalignment with git-status reporting, and particularly the cumbersome workflow for correcting wrong resolutions in the rerere cache. Hannes' latest contribution emphasizes how this could frustrate novice users, as incorrect resolutions persist and require restarting merges to fix via `git rerere forget`.

Junio Hamano initially suggested Git 3.0 as the target version for this change, while Taylor Blau argued it could happen sooner given rerere's maturity. The discussion has evolved to focus on necessary UI improvements, with Hannes proposing a technical solution - allowing the cache to update after resolution reuse - that could make the feature more user-friendly.

The core question remains whether to enable rerere by default now (potentially in Git 2.52) with known UX issues, or wait until after improvements are made (possibly for Git 3.0). There's growing recognition that some UI work may need to proceed in parallel with or after the default-flip rather than strictly before it.
