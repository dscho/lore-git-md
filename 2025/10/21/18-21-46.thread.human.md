This thread discusses the default enablement of Git's `rerere` (reuse recorded resolution) feature, currently off by default despite being considered mature. The conversation has evolved from initial timing questions (whether to enable in Git 2.x or wait for 3.0) to focusing on several usability concerns that should ideally be addressed first.

Key issues identified include: unclear messaging when resolutions are reused, non-intuitive workflows for managing incorrect cached resolutions (particularly the requirement for conflict state to use `git rerere forget`), and a significant gap in handling delete/modify conflicts where `rerere` provides no assistance at all. Johannes Sixt proposed an alternative cache update mechanism, while D. Ben Knoble has been compiling a list of "sharp edges" needing attention, including improved status reporting to make reused resolutions more visible.

The latest email confirms understanding of Junio Hamano's clarification about delete/modify conflicts being completely unsupported rather than just suboptimally handled - a distinct usability issue forcing manual resolution. The group is now weighing whether these interface problems require solutions before flipping the default, or if the core functionality's benefits justify enabling first with fixes to follow. While technical implementation is solid, the discussion shows consensus that the user experience needs polish regardless of timing.
