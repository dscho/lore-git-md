The thread continues to explore whether and when to enable Git's `rerere` (reuse recorded resolution) feature by default, with recent discussion focusing on refining the list of usability concerns that should be addressed first. 

Junio Hamano originally proposed making `rerere.enabled` default to on, possibly in Git 3.0, given the feature's maturity. Several contributors identified rough edges in the current implementation: confusing messages when resolutions are reused, a non-intuitive workflow for correcting bad cached resolutions (requiring recreating the conflict state to use `git rerere forget`), and limitations around delete/modify conflict handling where Git conservatively refuses to record resolutions that discard modifications.

D. Ben Knoble is now working to clarify and expand this list of concerns. In the latest email, he suggests concrete improvements to status reporting that would make reused resolutions more visible and actionable for users. He also seeks to better understand Junio's point about delete/modify conflicts - where Git's safety mechanisms sometimes conflict with what users expect to do (like resolving by deletion). 

The discussion has moved from whether `rerere` is technically ready (consensus is yes) to precisely what user experience issues should be solved before flipping the default. Options include improving messaging, redesigning the forget workflow, addressing delete/modify cases, or some combination. The thread remains active as contributors work to define the remaining hurdles before this long-standing feature becomes the default behavior.
