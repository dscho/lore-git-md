This is a feature patch in the geometric repacking series, adding configurable split factors for the maintenance task.

Patrick Steinhardt's patch introduces a new configuration option `maintenance.geometric-repack.splitFactor` that allows users to adjust the geometric sequence factor used during repacking. The default remains 2 (meaning each pack must be at least twice as large as the previous one), but now users can set this higher for very large repositories where they want to reduce the frequency of pack merges.

The implementation adds the config option to both the main geometric repack task and its auto-condition check, ensuring consistent behavior between manual and automatic runs. The patch includes thorough test coverage in t7900-maintenance.sh that verifies the configuration is properly honored, with test cases showing how different split factors affect pack merging decisions.

This change builds on the well-reviewed geometric repacking infrastructure from earlier in the series, maintaining the same clean code style and test rigor. The motivation is clear - giving administrators more control over repacking behavior in large repositories - and the implementation looks solid, with appropriate documentation updates and test coverage. As part of the mature v2 series, this appears ready for inclusion.
