This is a refactoring patch in Patrick Steinhardt's `git-history` series, adding support for in-memory index patching to the add-patch infrastructure. 

The patch introduces a new `run_add_p_index()` function that allows applying changes to an arbitrary in-memory index rather than always operating on the repository's main index. This is a key capability needed for the history editing operations being developed in the series, where operations like rewording commits may need to work with temporary in-memory states.

The implementation builds on the existing `run_add_p()` infrastructure but adds new parameters to specify the target index and its file location. The changes are mostly straightforward plumbing - adding index state tracking to the `add_p_state` struct and adjusting the diff application logic to use the specified index rather than always using `r->index`. The patch maintains all existing functionality while adding the new capability.

This appears to be a well-constructed change that cleanly extends the add-patch system's capabilities without disrupting its current uses. The commit message clearly explains the purpose and the implementation approach. As part of the larger `git-history` effort, this helps enable the more sophisticated history editing operations the series is working toward.
