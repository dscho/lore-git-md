This is a refactoring patch in Patrick Steinhardt's `git-history` series, specifically addressing the working tree status infrastructure. Junio Hamano provides a review of the new `wt_status_collect_changes_trees()` function, which exposes diff capabilities between arbitrary trees (rather than just between HEAD and the working tree).

The function is modeled after existing index comparison code but adapted for tree-to-tree diffs. Junio notes the implementation correctly reuses the `wt_status_collect_updated_cb` callback and handles rename detection parameters consistently. He suggests adding clarifying documentation since the function records changes as "staged" (index-side) by convention, which isn't immediately clear from the implementation alone.

This change supports the series' broader goal of enabling in-memory index operations for history editing commands. The review is positive overall, with only minor documentation improvements requested before this infrastructure piece can be considered complete. The patch appears ready for integration once these small clarifications are added.
