This is a cover letter for v5 of a feature series introducing a new `git-history` command for history editing operations, now focused on non-conflicting `reword` and `split` subcommands after community feedback. The series builds on Git's sequencer infrastructure while drawing inspiration from Jujutsu's history editing capabilities.

The v5 iteration incorporates several refinements:
- Rebased onto latest `seen` with Siddharth Asthana's replay updates
- Fixed descendant checking to properly verify HEAD ancestry
- Improved commit message hints and subcommand usage strings
- Addressed Karthik Nayak's review comments on documentation and style
- Added new tests for edge cases like unrelated commits

The implementation introduces:
- `builtin/history.c` with `reword` and `split` subcommands
- Shared `replay.c` infrastructure now including `replay.defaultAction` config
- Refactored add-patch subsystem with new structs (interactive_options, interactive_config)
- Cache-tree modifications for in-memory operations
- Comprehensive test coverage in t/t3450-history.sh and related files

The series appears technically sound with all major review feedback addressed, though some future UX considerations remain open around multi-way splits and hook integration. The minimal rebase conflicts and focused discussion suggest the feature is ready for integration.
