This is a refactoring patch in Patrick Steinhardt's `git-history` series, continuing the separation of the add-patch subsystem from add-interactive. 

The patch removes the last direct dependency between `add-patch.c` and the `add-interactive` subsystem by eliminating the use of `struct add_i_state` in favor of directly embedding and initializing the shared `struct interactive_config`. This follows from the previous patch's consolidation of interactive configuration handling. The changes are mechanical but thorough - every reference to `s->s` (the old `add_i_state`) is updated to use `s->cfg` (the new `interactive_config`), and initialization is updated to use the new `interactive_config_init()` function.

Key technical details:
- Replaces `struct add_i_state s` with direct `struct interactive_config cfg` in `struct add_p_state`
- Updates all color/config access to use new paths (`s->cfg.error_color` instead of `s->s.cfg.error_color`)
- Changes initialization from `init_add_i_state()` to `interactive_config_init()`
- Maintains identical functionality while removing the subsystem coupling
- Updates index handling to use direct `s->r` repository pointer rather than `s->s.r`
- Preserves all existing behavior including color handling, diff options, and interactive prompts

The changes are straightforward and maintain backward compatibility while cleaning up the architecture. This appears to be the final step in separating these subsystems after the preparatory work in earlier patches. The patch fits cleanly into the series' progression toward cleaner boundaries between components.
