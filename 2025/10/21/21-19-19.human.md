This is a discussion about the user experience design for the `git history split` subcommand in Patrick Steinhardt's proposed `git-history` feature series. The thread focuses on how commit messages should be handled when splitting commits.

D. Ben Knoble joins an existing discussion about whether split commits should preserve the original message in the first or second commit. While Karthik Nayak suggested keeping the original message in the first commit (C0') and putting new content in the split-out commit (S0), Patrick notes this has been debated before and proposes alternatives like supporting multiple message flags or requiring editor input.

Knoble's contribution suggests the radical approach of not supporting `-m` flags at all, forcing users to edit messages interactively. This would simplify the interface but reduce scripting capabilities. The exchange shows ongoing UX design work for this new history-editing feature, with multiple reasonable approaches still under consideration. The discussion remains constructive, with participants exploring tradeoffs between flexibility and simplicity.
