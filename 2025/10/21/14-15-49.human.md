This is a refactoring patch that introduces infrastructure for the upcoming `git-history` command series. It adds a new function `wt_status_collect_changes_trees()` to the working tree status subsystem that can diff and format changes between two arbitrary trees, rather than just comparing the working tree or index/HEAD as the existing functions do.

The patch is the first in a 12-part series that will implement history editing commands inspired by Jujutsu's capabilities. While this particular change doesn't yet use the new function, it lays groundwork needed for subsequent patches that will implement `reword` and `split` subcommands. The implementation follows Git's existing patterns for tree diffs and status collection, properly handling rename detection limits and recursive behavior.

The change is cleanly scoped - just 24 lines of new code plus header declarations - and maintains backward compatibility. It's a typical infrastructure patch that extracts and generalizes existing functionality to support new features. Given this is v5 of the series and the maintainer has already confirmed architectural alignment, this foundational piece appears technically sound.
