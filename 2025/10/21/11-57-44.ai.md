This is a refinement patch in the submodule gitdir path encoding series, addressing feedback on the config-based approach. Adrian Ratiu responds to Patrick Steinhardt's review of v3, agreeing to several implementation improvements for the upcoming v4.

Key changes agreed upon:
1. Switching to `repo_config_get_string_tmp()` for cleaner config value lifetime management in `submodule.c`
2. Fixing heredoc indentation style in the new test helper script
3. More tightly coupling the `submodule.<name>.gitdirpath` config with the `extensions.submoduleEncoding` extension, per Junio's and Patrick's suggestion that the config should only be honored when the extension is active

The email confirms alignment with the series' now-settled design where gitdir paths will be authoritatively managed via config when the encoding extension is enabled. This addresses Patrick's concern about the config being recognized prematurely before the extension is in use.

Adrian plans to restructure the commits in v4 to reflect these changes, particularly ensuring the config override functionality is properly gated behind the extension flag. The exchange demonstrates the series maturing from an optional override mechanism to a fully integrated part of the encoding system, with all key contributors now in agreement on the architecture.
