This is a design discussion about the behavior of the `--all` flag in the experimental `git repo info` command. Patrick Steinhardt responds to Lucas Seiki Oshiro's patch that implemented combined `--all` and key arguments functionality.

Patrick argues against the current implementation where `--all` can be combined with specific keys, pointing out two main issues: the documentation synopsis doesn't match the actual behavior (implying mutual exclusivity when none exists), and the combined mode creates inconsistent output ordering where some keys follow command-line order while `--all` keys don't. He suggests making `--all` and key arguments mutually exclusive instead, noting there's no clear use case for duplicate key output.

The discussion reveals an implementation detail - when using `--all` with keys, the command first outputs all fields unconditionally before processing the additional keys, creating an ordering inconsistency. Patrick believes this makes the interface less predictable. While acknowledging Junio Hamano's previous preference for the combined approach, Patrick maintains that mutual exclusivity would be cleaner and more consistent.

This email doesn't propose code changes but rather reopens the design discussion about the command's interface contract. The test cases from the original patch (showing duplicate key output and invalid key handling with `--all`) are cited as evidence that the current behavior may not be the most intuitive design.
