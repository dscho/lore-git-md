This thread investigates a platform-specific bug in Git's notes functionality on NonStop systems (big endian x86), where `git notes show HEAD` returns an anomalous exit code -12 (037777777764 octal) while direct invocation of `git show $(git notes list HEAD)` works correctly. Randall Becker (NonStop port maintainer) initially reported the issue in Git 2.51.0, observing bash truncates negative exit codes to 0xFF (interpreted as 0). Jeff King (Peff) analyzed the execution path, ruling out pager interaction (`--no-pager` has no effect) and focusing on `execv_git_cmd()`'s process execution plumbing.

Debugger observations show registers rsx and rsi containing 12 at git.c:982 during the failing `git notes show` path, suggesting uninitialized return value propagation. The working direct invocation versus broken wrapper path indicates the issue lies in Git's process execution machinery on NonStop rather than the notes functionality itself. Current evidence points to platform-specific handling in `execv_git_cmd()` where exit codes and register behavior differ from direct command invocation. Key technical details include the exact exit code (-12), NonStop big endian context, bash truncation behavior, and debugger register observations. Open questions remain about why the process execution path differs between direct and wrapped invocation on this platform, with Jeff King suggesting further debugging by tracing through to the exec system call and following into the exec'd process image.
