This thread investigates a platform-specific bug in Git's notes functionality on NonStop systems (big endian x86), where `git notes show HEAD` fails with exit code -12 (037777777764 octal) while direct `git show $(git notes list HEAD)` works correctly. The investigation has progressed through multiple stages of analysis, with Randall Becker (NonStop port maintainer) and Jeff King (Peff) collaborating to isolate the issue to the notes subsystem's command conversion logic.

Key findings:
- Debugging confirms `git notes show HEAD` incorrectly converts to `git show` with hash 1aa950256... (invalid notes blob) instead of actual HEAD commit 3fc1917e0...
- NonStop's execvp() fails immediately with error -12 when given this invalid input
- Manual execution of the same command in bash properly reports "no note found" (exit 1)
- Debugger output shows exact argv array passed to execvp() in git.c:982
- The issue is isolated to builtin/notes.c's command construction logic

Technical details:
- Notes subsystem incorrectly uses notes blob hash instead of commit hash
- NonStop-specific execvp() behavior with invalid paths
- Bash's handling of negative exit codes (-12 wrapped vs exit 1)
- Big-endian x86 architecture considerations
- Debugger observations of registers rsx/rsi during failure
- Platform-specific aspects:
  * NonStop's immediate execvp() failure
  * Bash exit code truncation
  * Notes command conversion path

Current status:
- Randall Becker provided definitive debugger output showing:
  * Exact malformed command being generated (["git", "show", "1aa950256...", NULL])
  * Immediate execvp() failure with -12
  * Discrepancy between automatic and manual execution
- Jeff King analyzing notes-to-show command construction path, questioning whether manual test used correct command
- Focus on hash generation logic in builtin/notes.c

Open questions:
- Precise location in notes.c where hash conversion fails

- Whether this could affect other platforms differently
- Need to examine:
