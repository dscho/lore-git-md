Git notes show exit code anomaly on NonStop platform. Thread investigates unexpected exit code -12 (037777777764 octal) from `git notes show HEAD` after adding a note, observed on Git 2.51.0 running on big endian x86 NonStop architecture. Randall Becker (NonStop port maintainer) confirmed this is specifically about process exit codes, not shell tab completion, and provided details about bash truncating negative exit codes to 0xFF (interpreted as 0). Jeff King (Peff) suggests the anomaly may originate from `git show` called via `execv_git_cmd()` in the notes implementation, rather than the notes subsystem directly, with potential involvement of `show_blob_object()`'s error paths or pager exit code handling (suggesting testing with `--no-pager`). The command internally runs `git show $(git notes list HEAD)`, and standard cases should return 0 when successfully showing the blob. Original reporter verified behavior in gdb and created a standalone test program using !!fn construct. Current understanding points to either platform-specific process execution/exit code plumbing in Git or pager interaction, with the notes subsystem being the observable symptom rather than root cause. Key tracking details: affected command chain (`git notes show` -> `git show`), exact exit code (-12/037777777764), NonStop big endian context, Git version 2.51.0, bash truncation behavior (0xFF mask), potential pager complication, unsuccessful debugging attempts via gdb and standalone test. Problem remains unsolved but now includes broader consideration of Git's process execution infrastructure on this platform.
