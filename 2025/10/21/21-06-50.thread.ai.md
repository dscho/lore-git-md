Git notes show exit code anomaly on NonStop platform, originally observed in Git 2.51.0 on big endian x86 NonStop architecture. Thread investigates unexpected exit code -12 (037777777764 octal) from `git notes show HEAD` after adding a note. Randall Becker (NonStop port maintainer) confirmed this is specifically process exit code related, not shell tab completion, with bash truncating negative exit codes to 0xFF (interpreted as 0). Jeff King (Peff) initially suggested the anomaly may originate from `git show` called via `execv_git_cmd()` in notes implementation, with potential involvement of `show_blob_object()`'s error paths or pager exit code handling. Debugging update shows `--no-pager` does not change behavior, ruling out pager interaction. Randall observes direct `git show $(git notes list HEAD)` works correctly while `git --no-pager notes show HEAD` still returns -12, with debugger showing registers rsx and rsi containing 12 at git.c:982, possibly indicating uninitialized return value propagation. Current evidence points to platform-specific process execution plumbing in Git's `execv_git_cmd()` path on NonStop, where exit codes and register handling differ from direct command execution. Key technical details: affected command chain (`git notes show` -> `git show`), exact exit code (-12/037777777764), NonStop big endian context, Git version 2.51.0, bash truncation behavior (0xFF mask), debugger register observations, working direct invocation versus broken notes-wrapper path. Open question remains why process execution path differs between direct and wrapped invocation on this platform.
