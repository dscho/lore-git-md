This is a discussion about optimizing the reference counting implementation in the new `git repo structure` command. Justin Tobler responds to Patrick Steinhardt's suggestion to improve memory efficiency by using `refs_for_each_ref()` with direct counting in the callback, rather than storing all references in an array first.

The current implementation in patch 4/7 collects all refs into an array before counting, which Patrick notes is memory-intensive and makes progress reporting less useful (since progress only shows after enumeration). Justin agrees with the optimization approach but notes that the current `filter_refs()` setup provides flexibility for future reference filtering options. He plans to modify the implementation to count references and prepare OIDs in a single pass while maintaining the ability to add filtering later.

The tradeoff is losing exact progress percentage during enumeration, but both agree this is acceptable. This discussion represents a refinement of the already-merged reference counting functionality, showing the series is now focusing on optimization opportunities after establishing core features.
