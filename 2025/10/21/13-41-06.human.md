This is a discussion about type safety and casting in the ongoing xdiff refactoring series for Rust FFI compatibility. Junio C Hamano responds to Phillip Wood's concerns about the proliferation of `(long)` casts in the code despite converting struct members to `size_t`. 

Junio acknowledges Phillip's point about avoiding type mismatches but notes the practical challenges of converting all existing code from signed to unsigned types. He suggests there needs to be a balance between type purity and the scope of changes, implying that completely eliminating all casts may require more extensive changes than the current series aims to accomplish.

The exchange highlights an ongoing tension in the refactoring effort between achieving clean type boundaries for Rust interoperability and maintaining practical maintainability of the existing C codebase during the transition period. This appears to be one of the remaining open questions in the otherwise largely completed xdiff modernization effort.
