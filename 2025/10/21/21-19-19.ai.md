1. The current implementation's behavior where the split-out commit gets the new message
2. Karthik Nayak's alternative proposal to put the new message on the modified original commit
3. Patrick's consideration of future multi-split capabilities that would complicate numbered message parameters
4. The tradeoffs between command-line message specification (`-m`) versus editor-based editing
