This is a proposal to change the default behavior of the `rerere.enabled` config setting. Junio Hamano suggests flipping its default from off to on when Git reaches version 3.0, arguing that the feature has matured enough through years of opt-in usage to warrant being enabled by default.

The email notes that `rerere` (reuse recorded resolution) was initially kept opt-in to allow early adopters to help polish the feature, but the project never established formal graduation criteria to determine when it should become the default. Hamano positions this as a natural evolution point for Git's major version bump, implying the feature has proven stable through real-world use.

The proposal doesn't include specific data about current adoption rates or bug reports, but frames the change as addressing user expectations - newcomers discovering the feature's benefits might reasonably wonder why such a useful tool isn't enabled by default if it's considered stable. The 3.0 version boundary is suggested as a logical point to make this behavioral change, though no specific timeline is mentioned beyond the version number.
