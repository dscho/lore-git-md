This is a technical review in the ongoing hook subsystem refactoring series, focusing on naming conventions in the parallel process output capture API.

Patrick Steinhardt responds to Adrian Ratiu's patch that introduces a `consume_sideband_fn` callback for handling collated output from parallel processes. While agreeing with the interface design, Patrick suggests the name is too specific to the hook use case. He proposes renaming it to `consume_output_fn` to better reflect its general purpose of processing any collated output, not just sideband data from hooks.

The feedback continues Patrick's pattern of reviewing for API consistency across the hook conversion series. This particular suggestion aims to make the callback's name more accurately represent its functionality while maintaining the same underlying behavior. The change would be a straightforward rename with no expected impact on the series' core functionality.
