Refactoring patch in the `git-history` series, focusing on the interactive add-patch subsystem.

This is patch 8/12 in Patrick Steinhardt's v5 series implementing the new `git-history` command. The patch refactors the shared code between `git add -p` and `git add -i` by introducing new `struct interactive_options` and `struct interactive_config` to better organize the color and configuration settings that were previously tangled between the two subsystems.

The changes move color handling and configuration into the new `interactive_config` struct while maintaining all existing functionality. This is part of the larger effort to clean up the interactive add code in preparation for the new history editing features. The patch touches multiple files but is mechanical in nature, mostly moving code between files and updating callers to use the new structures.

The changes appear well-contained and maintain backward compatibility needed by existing commands like `git add -p` while making the codebase more maintainable for the new `git-history` functionality. The commit message clearly explains the motivation and notes that further detangling will come in subsequent patches.
