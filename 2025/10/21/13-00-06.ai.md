Performance optimization for `git last-modified` with benchmark results on linux.git.

This email from Toon Claes provides additional benchmark data for the ongoing `git last-modified` performance optimization work, specifically testing the new algorithm on the larger linux.git repository. The results show dramatic improvements across all configurations, with the new implementation (HEAD) being 7.9x faster than the old implementation (master) when both use Bloom filters, and 111.7x faster in the no-Bloom-filter case.

Key technical details from the benchmarks:
- The new algorithm with Bloom filters completes in just 110ms (mean) compared to 1.536s for the old implementation with Bloom filters
- Even without Bloom filters, the new version (868.7ms) outperforms the old Bloom-enabled version
- System time is significantly reduced in all cases, suggesting more efficient resource usage

This data addresses Taylor Blau's request for benchmarks on a larger repository, confirming the performance benefits scale well beyond git.git. The results validate the effectiveness of the priority queue approach and path activity tracking optimizations discussed in the thread. No new technical changes are proposed in this email - it serves to strengthen the case for the already-discussed algorithm by demonstrating its real-world impact on a large codebase.
