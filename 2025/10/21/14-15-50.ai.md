Refactoring patch in the git-history command series, extracting shared commit-picking logic from `git-replay` into new `replay.c` infrastructure.

This second patch in the v5 series moves the core commit selection and replay logic from `builtin/replay.c` into a new `replay.c` file to enable sharing with the upcoming `git-history` command. The extracted functionality includes commit mapping, tree comparison, and new commit creation, now exposed via the new `replay_pick_regular_commit()` function. 

Key technical details:
- Creates new `replay.[ch]` files with extracted logic
- Maintains identical behavior while adding subsystem prefix (`replay_`)
- Preserves all existing functionality including commit author handling and merge result processing
- Updates build systems (Makefile and meson.build) to include new files
- Keeps `USE_THE_REPOSITORY_VARIABLE` macro for now (relevant to ongoing `the_repository` removal effort)
- Leaves FIXME comment about potential CLI signing requirements

The patch is a straightforward code movement with no behavior changes, cleanly separating concerns in preparation for the `git-history` implementation. It follows the series' architectural approach of building on `git-replay` infrastructure while maintaining clear subsystem boundaries. The changes align with previous technical review feedback about code organization.
