This is a proposal to change the default behavior of Git's rerere (reuse recorded resolution) feature. Junio Hamano suggests flipping the default of `rerere.enabled` from off to on when Git reaches version 3.0.

The email explains that rerere was initially opt-in because it was a new and potentially buggy feature, allowing early adopters to help polish it. However, the project never established formal criteria for when it would be considered stable enough to enable by default. Hamano notes that many users who discover rerere's usefulness wonder why it isn't enabled automatically, and proposes that the major version bump to 3.0 would be an appropriate time to make this change.

The proposal is framed as an RFC (Request for Comments), indicating the author is seeking feedback from the mailing list before proceeding. No technical implementation details are provided since this is purely about changing a default configuration value. The change would affect all Git users by automatically recording and reusing conflict resolutions, which could be particularly helpful for those who frequently deal with merge conflicts but may not be aware of the feature.
