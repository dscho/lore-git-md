This is a refactoring patch in Patrick Steinhardt's v5 series introducing the `git-history` command, specifically addressing commit parsing safety in the replay infrastructure.

The patch fixes a potential issue where the `replay_pick_regular_commit()` function could dereference unparsed commit objects. While existing callers already parsed commits before calling this function, the change makes the API more robust as it's now exposed to external users. The fix is straightforward - adding a `repo_parse_commit()` check at the start of the function.

This is a small but meaningful improvement to the shared replay infrastructure that underpins the new history editing commands. It follows good defensive programming practices by making the function more self-contained and less dependent on its callers' behavior. The change aligns with the series' overall goal of building reliable history manipulation tools while maintaining compatibility with existing code.
