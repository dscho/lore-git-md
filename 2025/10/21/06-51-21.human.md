This is a follow-up discussion in the ongoing thread about refactoring strbuf usage in gpg-interface.c. Christian Couder corrects his own earlier suggestion regarding memory management in the patch that simplifies SSH key fingerprint extraction.

Christian had previously suggested eliminating the `fingerprint_ret` variable by directly returning the result of `xmemdupz()`. However, he now realizes this would be incorrect because the memory for `fingerprint_stdout` needs to be released first. The current approach of storing the result in `fingerprint_ret` before releasing the strbuf is actually the correct sequence.

This is a minor technical clarification that doesn't affect the overall approach of the patch series, which has already been positively reviewed.
