Bugfix follow-up regarding `protocol.file.allow` behavior in submodules, focusing on documentation gaps. The email from fence.borrowing375@passmail.net acknowledges Jeff King's explanation about why local config isn't inherited during submodule operations, but raises two new points. First, they question whether protocol-related config keys would be appropriate candidates for inheritance if submodules ever did honor local config. Second, they identify a documentation issue - while the git-submodule manpage mentions some cases where local config is used (like default remote settings), it doesn't clearly state that local config is generally ignored for most purposes during submodule operations. This creates confusion for users expecting consistent behavior between different submodule operations. The email suggests this omission might constitute a documentation bug worth addressing, even if the underlying technical behavior remains unchanged. The thread continues to explore the tension between user expectations and Git's architectural constraints around config inheritance.
