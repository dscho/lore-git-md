This is a technical proposal in the ongoing discussion about making `git grep` more configurable for file exclusions. Jeff King (Peff) suggests an implementation approach using a `grep.defaultpathspec` configuration option that would let users specify default path exclusions, while still allowing overrides by explicitly providing pathspecs.

The key idea is to modify `grep.c` to support a configurable default pathspec that gets used when no explicit pathspec is provided. This would allow users to exclude certain files (like binary files or translation files) by default while maintaining backward compatibility, since scripts could still override the behavior by specifying pathspecs explicitly.

Peff demonstrates how this could work to exclude translation files (`:^po`) while still allowing matches in other files. He notes some potential rough edges in the implementation, particularly around how the default pathspec interacts with explicit pathspec arguments. As an alternative, he points out that similar functionality could be achieved today using aliases, though that requires user discipline.

This proposal represents a middle ground in the discussion - it doesn't change default behavior but provides a configurable mechanism for users who want to exclude certain files. The approach appears technically sound and considers backward compatibility concerns that have been central to the thread. It builds on earlier discussions about attribute-based filtering while offering a simpler configuration interface than some other proposals.
