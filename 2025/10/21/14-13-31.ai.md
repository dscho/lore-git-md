This is the final patch in a series introducing a new geometric repacking strategy for Git maintenance, completing the strategy configuration options. The patch adds the "geometric" strategy as a full replacement for both the traditional "gc" and "incremental" approaches, particularly targeting large repositories.

The geometric strategy combines the benefits of both existing strategies while addressing their shortcomings. It performs all the cleanup tasks of `git gc` (pruning reflogs, rerere caches, and stale worktrees) while using geometric repacking for packfile maintenance. The key innovation is automatically switching to full repacks with cruft packs when geometric repacking would merge all packfiles anyway, thus periodically cleaning up unreachable objects while avoiding the overhead of frequent full repacks.

The implementation adds a new strategy definition in `builtin/gc.c` that schedules various maintenance tasks (commit-graph, geometric repack, pack-refs, etc.) with appropriate frequencies. Documentation is updated to explain the strategy's behavior and recommend it for large repositories. Tests verify the strategy's behavior for both manual and scheduled maintenance runs.

Technical details include:
- New `geometric_strategy` struct mirroring the existing strategy patterns
- Integration with the existing `parse_maintenance_strategy()` function
- Comprehensive test coverage in t7900-maintenance.sh (now testing all three strategies)
- Documentation explaining the tradeoffs around unreachable object retention
- Backward compatibility maintained with existing strategy options

The patch completes the series' goal of providing a maintenance strategy that better serves monorepo use cases while maintaining Git's data integrity guarantees. It represents the culmination of earlier refactoring work and incorporates feedback from multiple reviewers (Taylor Blau, Justin Tobler, Junio C Hamano) throughout the thread.
