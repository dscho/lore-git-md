This is the final patch in the `git repo structure` series, adding progress reporting to the new repository analysis subcommand. The patch implements progress meters for both the reference counting and object counting phases, with automatic TTY detection and explicit `--[no-]progress` options.

The implementation adds progress tracking to both major operations:
- Reference counting now uses `start_delayed_progress()`/`display_progress()` to show counts during ref enumeration
- Object counting similarly shows progress during path-walk operations
- Progress is enabled by default when run interactively (isatty(2)) but can be forced on/off with CLI flags
- The progress messages are internationalized with gettext wrappers
- New tests verify both the progress output and the option behavior

Key technical details:
- Adds `progress.h` include and integrates progress API throughout counting logic
- Introduces new `count_objects_data` struct to carry progress state
- Modifies both `structure_count_references()` and `structure_count_objects()` to accept progress parameters
- Updates the command's option parsing to handle `--progress`/`--no-progress`
- Adds comprehensive tests in t1901-repo-structure.sh verifying:
  - Progress appears with `--progress` and TTY
  - Progress can be suppressed with `--no-progress`
  - Output remains correct in both cases
- Preserves all existing functionality while adding the new feature

This completes the core functionality of the `git repo structure` command, which now provides both comprehensive repository metrics and user feedback during potentially long-running operations. The progress reporting follows Git's standard patterns and integrates cleanly with the existing counting infrastructure.
