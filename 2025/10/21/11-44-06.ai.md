This is the final patch in Patrick Steinhardt's v4 series implementing the `git history` command, specifically adding the `split` subcommand. The patch builds on earlier infrastructure work and responds to Karthik Nayak's review of the initial implementation.

The discussion focuses on two main aspects: the commit message placement strategy during splits and some implementation details around commit validation. Patrick agrees with Karthik that the current ancestor check is incorrect (it verifies if a commit is its own descendant rather than checking if HEAD descends from the split commit) and plans to fix this while removing a redundant check in `collect_commits()`. 

Regarding message placement, Patrick acknowledges prior discussion about whether the split-out commit (S0) or modified original (C0') should receive the new message. He considers alternatives like multiple `-m` flags for multi-commit splits but notes this would complicate the interface. The current implementation uses a single `--message` parameter while leaving open the possibility of future extensions for multi-way splits.

Technical details show the command enforces several constraints: no merge commits, reachability from HEAD, and proper commit parsing. The implementation uses temporary indexes and builds on shared `replay.c` infrastructure. While most technical concerns from Karthik's review have been addressed, this final patch clarifies some remaining edge cases in the validation logic.
