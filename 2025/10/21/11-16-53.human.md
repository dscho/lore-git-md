This is a technical follow-up in the xdiff refactoring thread, specifically addressing memory usage concerns from the field-splitting changes in patch 5/9. Chris Torek responds to Phillip Wood's question about the memory impact of adding a second hash field (`minimal_perfect_hash`) alongside the existing `line_hash` in the xdiff data structures.

The response provides a concrete calculation: memory overhead scales linearly with the total number of lines in the files being compared (M+N lines), with an estimated maximum impact of "a few megabytes" for typical files under a million lines. This suggests the change has negligible practical impact for normal Git usage while providing clearer type safety for the Rust FFI work.
