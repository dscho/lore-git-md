Refactoring patch in the `git-history` series, focusing on add-patch/add-interactive separation.

This patch (8/12 in v5) continues the infrastructure work for the new `git-history` command by refactoring the shared code between `add-patch` and `add-interactive`. It introduces a new `struct interactive_options` to replace the previous `struct add_p_opt`, which was confusingly reused across both subsystems. The change better separates concerns while maintaining functionality.

Key technical changes:
- New `struct interactive_options` in `add-patch.h` replaces `struct add_p_opt`
- New `struct interactive_config` consolidates color/config settings previously scattered in `add_i_state`
- Moves color/config initialization logic from `add-interactive.c` to new `interactive_config_init()` in `add-patch.c`
- Updates all callers across builtin commands (add, checkout, commit, reset, stash) to use the new struct
- Maintains backward compatibility through header inclusion and struct initialization macros
- The patch touches 10 files with 270 insertions and 239 deletions
- Changes are mechanical but wide-ranging, affecting interactive patch application across several commands
- Follows the header split in patch 7/12 and precedes further detangling work mentioned in the commit message

The refactoring appears well-executed, with thorough updates to all affected commands. The commit message clearly explains the motivation (reducing confusion between subsystems) and notes this is an intermediate step before full separation. The changes align with the series' goal of building robust infrastructure for `git-history` while improving existing interactive add/patch functionality.
