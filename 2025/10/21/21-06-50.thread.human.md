This thread investigates an unusual exit code (-12, shown as 037777777764 in octal) from `git notes show HEAD` on the NonStop platform (big endian x86) with Git 2.51.0. The anomaly appears when showing a note that was successfully added, with the command internally running `git show` on the note's blob. Initial debugging ruled out shell tab completion issues, with Randall Becker (NonStop port maintainer) confirming bash truncates negative exit codes to 0xFF.

Jeff King (Peff) suggested the problem might lie in Git's process execution plumbing rather than the notes subsystem itself, possibly involving `show_blob_object()` error paths or pager interaction. New debugging shows that while directly running `git show $(git notes list HEAD)` works correctly, the same operation through `git notes show` fails with the -12 code even with `--no-pager`, eliminating pager as the culprit. Debugger traces show register values containing 12 at a key point in git.c, hinting at an uninitialized return value being propagated.

The thread has narrowed the focus to Git's process execution infrastructure on NonStop, particularly why the same underlying operation succeeds when run directly but fails when invoked through `execv_git_cmd()`. The exact mechanism by which the platform handles exit codes and register values appears central to the mystery.
