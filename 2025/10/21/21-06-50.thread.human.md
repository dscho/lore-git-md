This thread investigates a platform-specific bug where `git notes show HEAD` returns an unexpected exit code -12 (037777777764 octal) on NonStop big endian systems, first observed in Git 2.51.0. Randall Becker, the NonStop port maintainer, confirmed this is a process exit code anomaly where bash truncates negative exit codes to 0xFF. Initial debugging ruled out pager interaction and shell tab completion as causes.

The key finding is that while directly running `git show $(git notes list HEAD)` works correctly, the `git notes show` wrapper path still produces the wrong exit code. Debugger observations show registers rsx and rsi containing 12 at git.c:982, suggesting uninitialized return value propagation. Jeff King (Peff) suspects the issue lies in Git's process execution plumbing on NonStop, specifically in `execv_git_cmd()`, where exit code handling may differ from direct command execution. The discussion is now focused on tracing through to the exec system call to understand how the process image differs between direct and wrapped invocations on this platform.
