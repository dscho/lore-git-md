This thread investigates a platform-specific bug in Git's notes functionality on NonStop systems (big endian x86), where `git notes show HEAD` returns an anomalous exit code -12. Randall Becker, the NonStop port maintainer, initially reported the issue, observing that bash truncates negative exit codes. Jeff King (Peff) analyzed the execution path, ruling out pager interaction and focusing on process execution plumbing.

New debugging findings from Randall reveal the root cause: `git notes show` is incorrectly converting to a `git show` command with the wrong object hash (1aa950256... instead of the actual HEAD (3fc1917e0...). On NonStop, this causes `execvp()` to fail immediately with error -12, while direct invocation with the correct hash properly reports "no note found" with exit code 1. The -12 error was a red herring - the real issue lies in how `git notes` constructs the show command. The investigation now shifts from general process execution problems to examining the notes subsystem's hash handling during command conversion. Next steps would involve verifying and fixing the notes-to-show command construction logic.
