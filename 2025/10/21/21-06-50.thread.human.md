This thread has uncovered a platform-specific bug in Git's notes subsystem that manifests on NonStop (big endian x86) systems, where `git notes show HEAD` fails with an unusual exit code (-12) while manually running the equivalent `git show` command works. Randall Becker, the NonStop port maintainer, provided crucial debugger output showing the notes subsystem incorrectly constructs a command using a notes blob hash (1aa950256...) instead of the expected commit hash (3fc1917e0...). 

Jeff King (Peff) analyzed the findings and confirmed the notes command conversion is broken, though he found Randall's observation that the malformed command works manually somewhat inconsistent with Git's expected behavior. The discrepancy suggests either a testing artifact or deeper platform-specific behavior in how execvp() handles invalid commands. The core issue remains in builtin/notes.c's hash selection logic, which incorrectly passes the notes blob hash rather than the commit hash to the underlying `git show` command. While NonStop's immediate execvp() failure helped surface the bug, the root cause appears to be in Git's notes implementation rather than being platform-specific. The next steps involve tracing exactly where the hash conversion goes wrong and why manual execution shows different behavior than the automatic path.
