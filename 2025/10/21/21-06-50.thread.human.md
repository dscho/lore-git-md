This thread investigates a puzzling platform-specific bug where `git notes show HEAD` fails with an unexpected exit code (-12) on NonStop systems, while direct `git show $(git notes list HEAD)` works correctly. The issue was originally reported by Randall Becker, the NonStop port maintainer, and has drawn detailed analysis from Jeff King (Peff).

The investigation has systematically ruled out potential causes, narrowing the problem to Git's notes subsystem command conversion logic. Debugging revealed that `git notes show HEAD` incorrectly converts to a `git show` command with the wrong blob hash (1aa950256... instead of the correct 3fc1917e0...). On NonStop systems, this triggers an immediate execvp() failure with the unusual -12 exit code, while other platforms might handle this differently. The latest email focuses on clarifying testing methodology to ensure accurate reproduction of the issue, particularly around whether the "no note found" error originates from `git show` or `git notes show` in manual testing. While the platform-specific execvp behavior helped surface the issue, the core problem appears to be in the portable notes subsystem code that generates incorrect command conversions. The next steps involve deeper examination of the notes command construction path in builtin/notes.c to identify where the hash conversion goes wrong.
