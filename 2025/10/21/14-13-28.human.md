This is part of the ongoing geometric repacking strategy series, specifically focusing on maintenance task execution contexts. The patch introduces a distinction between manual maintenance (run directly or via `--auto`) and scheduled maintenance (run via `--schedule`), allowing different strategies to be applied in each context.

The key change replaces a simple `enabled` flag with a bitmask (`maintenance_type`) that tracks which tasks should run in which context. The patch maintains backward compatibility by mapping the existing default strategy to manual runs and the incremental strategy to scheduled runs. This prepares for future changes where strategies can specify which contexts they should apply to.

The implementation is clean and focused, converting the boolean `enabled` field to a bitmask while preserving all existing behavior. This is clearly a preparatory step for the geometric repacking work that follows in the series, and it demonstrates careful attention to maintaining compatibility with current usage patterns. The changes are well-contained within `builtin/gc.c` and follow the established patterns of the maintenance code.
