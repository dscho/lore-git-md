This is a follow-up discussion in the submodule gitdir path encoding series, focusing on the config-based path mapping approach. Patrick Steinhardt strongly supports Junio Hamano's proposal to make `submodule.<name>.gitdirpath` the authoritative source of truth when the `extensions.submoduleEncoding` config is enabled, rather than just an override mechanism.

Key points in this email:
- Patrick outlines several advantages of the authoritative config approach: clearer state management (either all paths come from config or none do), easier error detection (missing config entries indicate repository corruption), and simpler migration (just write gitdir configs when enabling the extension)
- He particularly highlights the flexibility this provides for future encoding scheme changes, since the config would insulate users from internal encoding algorithm modifications
- The discussion represents final alignment on the config-based design after earlier iterations, with Patrick's support reinforcing the consensus between Adrian Ratiu and Junio

This email doesn't introduce new technical elements but solidifies the architectural decision to use config entries as the single source of truth for encoded submodule paths. The thread has now reached clear agreement on all major design aspects of the submodule encoding system.
