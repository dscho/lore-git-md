This is a follow-up discussion in the submodule gitdir path encoding series, specifically about handling path length limits. Adrian Ratiu is responding to Patrick Steinhardt's feedback on a now-dropped patch that would have provided custom error messages for overly long submodule paths.

The key points:
1. The discussion confirms there's no need for the `_PC_NAME_MAX` compatibility shim since POSIX requires both `pathconf()` and `_PC_NAME_MAX` to be available together.
2. Adrian agrees to drop this patch from the next version (v4) of the series, as Junio Hamano and Jeff King (Peff) had suggested, since it only provided cosmetic error message improvements without solving the underlying length limitation.
3. The functionality might be revived later if the project implements path sharding or trimming to handle long paths, which would make the error handling more meaningful.

This represents a minor cleanup in the series, removing non-essential code while keeping the door open for more substantial length-handling improvements later. The core submodule encoding design remains unchanged.
