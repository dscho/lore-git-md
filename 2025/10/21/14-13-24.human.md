This is a refactoring patch in the geometric repacking strategy series, specifically modifying how loose object counting works in `gc.c`.

The patch simplifies the `too_many_loose_objects()` function by having it take just the threshold value directly rather than requiring the entire `gc_config` struct. This makes the function more flexible for future callers that might want to use different threshold values, which will be needed for the geometric repacking strategy being developed.

The change is straightforward - the function signature is updated and all callers are modified to pass just the threshold value they want to use. This is part of a larger effort to make the GC internals more modular in preparation for the new geometric repacking functionality. The patch appears clean and focused, with no behavior changes beyond the interface simplification.

This is patch 2/9 in the v2 series, building on earlier refactoring work to enable the geometric repacking strategy that will come in later patches. The change has already been reviewed and approved by Junio C Hamano in previous iterations of the series.
