This is a user experience note about `git clone --shallow-exclude` behavior in CI workflows, adding another data point to the ongoing discussion about shallow clone limitations.

Erik Cervin Edin shares their experience trying to use `--shallow-exclude` in GitHub Actions to run commit linters on PRs, similar to Philipp Hahn's earlier GitLab CI use case. They report inconsistent behavior when excluding different branches: excluding `master` fails with a connection error, while excluding `maint` works as expected, fetching 43 commits. The failure mode differs from the previously discussed "ambiguous deepen-not" error, suggesting a different server-side issue.

The email doesn't propose any solutions but provides valuable real-world testing data showing that even within the supported use case of branch name exclusion, behavior can vary unexpectedly between branches. This reinforces the thread's emerging consensus that blobless clones may be more reliable alternative for CI workflows needing commit history access. The note serves as a useful cautionary example about the current implementation's edge cases.
