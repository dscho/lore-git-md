Feature introducing geometric repacking strategy for Git maintenance. This patch (v2 3/9) adds a new "geometric-repack" maintenance task that implements a hybrid approach combining geometric repacking with periodic full repacks using cruft packs. The strategy addresses a key limitation of pure geometric repacking (which packs all loose objects unconditionally) by switching to full repacks when packs would be consolidated, allowing unreachable objects to be properly expired.

The implementation introduces:
- New `maintenance.geometric-repack.auto` config (default 100 loose objects) to control auto-execution
- Core logic in `maintenance_task_geometric_repack()` that decides between geometric repack (`--geometric=2`) and full repack with cruft packs
- Auto-condition checking in `geometric_repack_auto_condition()` that triggers based on pack geometry or loose object count
- Extensive test coverage in t7900-maintenance.sh (139 new lines) verifying:
  - Basic geometric repack behavior
  - Auto-condition triggering
  - Interaction with loose objects
  - Cruft pack generation
  - Edge cases around empty repos and config values

The patch builds on prior refactoring work in gc.c and represents a key piece of the overall geometric repacking strategy, particularly valuable for monorepo maintenance. It follows the hybrid approach used in production at GitHub, balancing performance (geometric repacks) with proper object expiration (periodic full repacks). The implementation appears thorough, with clear commit message explanation and comprehensive test coverage.
