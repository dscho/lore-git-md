This is a refactoring patch in the `git-history` command series that also advances the `the_repository` removal effort. It's patch 4/12 in v5 of the series.

The change modifies the `replay_pick_regular_commit()` function in `replay.c` to explicitly parse commits before accessing their fields. While existing call paths already implicitly parsing commits made this safe before, now that the function is exposed to external callers (as part of the new replay infrastructure), this becomes a potential footgun. The patch adds a `repo_parse_commit()` call at the start of the function, returning NULL if parsing fails.

This is a small but important robustness improvement to the shared replay infrastructure that the `git-history` command series is building. It follows good practice for commit object handling while maintaining the function's existing behavior when commits are already parsed. The change aligns with the series' broader goals of creating reliable infrastructure for history editing operations while also making incremental progress on removing `the_repository` usage (note the proper `repo` parameter passing).

The patch is straightforward with clear motivation explained in the commit message. It touches only the replay infrastructure component of the series, adding a single safety check without changing any existing functionality. This continues the pattern seen in previous patches of methodically improving the underlying infrastructure before implementing the user-facing history editing commands.
