Feature implementation for `git-history`'s "split" subcommand, completing the v5 series. This patch adds interactive commit splitting functionality to the new `git-history` command, allowing users to split a single commit into two by interactively selecting which changes to move to a new parent commit.

The implementation builds on the series' infrastructure work, using the interactive add-patch interface to let users select hunks for the new commit. It handles the full workflow: creating a temporary index, running the interactive selection, validating the split (ensuring neither commit becomes empty), creating the new commits (with proper parent relationships and preserved authorship), and rewriting subsequent history. The patch includes extensive test suite (447 lines) covering edge cases like merge commits, empty splits, pathspec filtering, and worktree state preservation.

Key technical details:
- New `cmd_history_split()` implementing the subcommand
- `split_commit()` helper handles core logic with temporary index manipulation
- Uses existing `run_add_p_index()` from earlier patches for hunk selection
- Validates split commits aren't empty by comparing tree OIDs
- Preserves original commit author and handles message editing
- Integrates with series' `apply_commits()` for history rewriting
- Adds `t/t3452-history-split.sh` with 18 test cases
- Documents behavior in `Documentation/git-history.adoc` with examples
- Follows series pattern of avoiding hooks during history operations

The implementation appears thorough and well-tested, completing the `git-history` command's initial feature set alongside the previously implemented `reword` subcommand.
