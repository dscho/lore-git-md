This is a discussion about optimizing the reference counting implementation in the `git repo structure` feature series. Patrick Steinhardt identified that the current approach in patch 4/7 (reference counting) unnecessarily stores all references in memory before counting them, which is inefficient and makes progress reporting less useful. He suggests using `refs_for_each_ref()` with a callback to count references directly during iteration.

Justin Tobler acknowledges the memory waste but notes the current `filter_refs()` approach provides flexibility for future reference filtering options. He agrees to implement Patrick's suggestion in the next version, using a single iteration to both count references and prepare OIDs for the path walk. They both accept the tradeoff of losing exact progress percentage reporting in exchange for better memory efficiency.

The exchange confirms the technical direction while preserving future extensibility - Justin plans to maintain the ability to add reference filtering later by potentially exposing `do_filter_refs()` from ref-filter.h. This keeps the door open for planned features while immediately addressing the memory usage concern. The discussion shows consensus on optimizing the current implementation while maintaining the series' architectural goals.
