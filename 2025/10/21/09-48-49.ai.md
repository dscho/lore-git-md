This is a maintenance update to keep Git's Unicode character width tables in sync with the latest Unicode standard. The patch updates `unicode-width.h` to reflect changes in Unicode 17, which was recently released (as noted in the linked Unicode Consortium blog post).

The changes consist of adjustments to the `zero_width` and `double_width` interval tables, which are used to determine how many terminal columns various Unicode characters should occupy. The diff shows numerous small adjustments to the ranges of characters that should be treated as zero-width or double-width, including both additions of new ranges and extensions of existing ones. For example, several new zero-width characters are added in the 0x1B60-0x1B66 range, and the double-width range for emoji characters is expanded in several places (0x1F6D5-0x1F6D8 and others).

This appears to be a routine update from a maintainer who has handled similar Unicode version updates in the past. The changes are mechanical and focused solely on keeping the width tables current with the Unicode standard. No behavioral changes or new features are introduced beyond the updated character width mappings. The patch is small (21 insertions, 12 deletions) and focused on a single file.
