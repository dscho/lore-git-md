This is a design discussion follow-up in the `git repo info --all` feature thread. Junio Hamano responds to Patrick Steinhardt's concerns about the command's interface consistency, agreeing to make `--all` and key arguments mutually exclusive.

The discussion centers on resolving the discrepancy between the documentation's synopsis (which implies mutual exclusivity) and the current implementation (which allows combining `--all` with specific keys). Junio acknowledges Patrick's point that allowing both creates awkward output ordering questions and lacks clear use cases for duplicate key output.

Junio had previously favored the more flexible combined approach but now concurs that enforcing mutual exclusivity (as originally documented) would be better. This resolves the interface inconsistency while eliminating the problematic behavior of outputting all fields first followed by any specified keys (including duplicates).

The agreement represents a design pivot from the current implementation in patch 2/2, which will need modification to either: 1) enforce mutual exclusivity at parse time, or 2) update the synopsis to accurately reflect the combined behavior. Given Junio's approval of Patrick's suggestion, the former approach (mutual exclusivity) appears to be the likely resolution.

This moves the thread toward consensus on the core design question, though the actual implementation change remains pending. The series' mechanical soundness remains unaffected, but the interface will become more constrained and predictable.
