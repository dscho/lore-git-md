This is a feature patch series introducing a new geometric repacking strategy for Git maintenance, building on prior work to improve repository maintenance for monorepos. The series represents version 2 of the proposal, incorporating feedback from previous reviews.

The patch series addresses two key limitations of current maintenance approaches: the inability to apply strategies to manual maintenance runs, and the lack of an efficient repacking strategy that balances geometric repacking with periodic full repacks for object cleanup. The solution introduces:

1. A new "geometric-repack" maintenance task that uses geometric repacking by default but falls back to full repacks with cruft packs when needed (mirroring GitHub's production setup)
2. Extension of maintenance strategies to cover both manual and scheduled runs
3. Configurable geometric split factor via `maintenance.geometric-repack.splitFactor`
4. Backward compatibility handling for existing "incremental" strategy users

Key technical details include:
- New config options: `maintenance.geometric-repack.auto` (default 100 loose objects) and `maintenance.geometric-repack.splitFactor`
- Hybrid repacking approach that uses geometric repacks until they would collapse all packs, then does a full repack with cruft packs
- Comprehensive test coverage in t7900-maintenance.sh (246 new lines)
- Refactored gc.c internals to support the new functionality

The series has evolved from v1 based on feedback, notably adding configurable split factor and addressing line length/style issues in tests. It builds on prior work reviewed by Justin Tobler and Taylor Blau, with current discussion focusing on optimization opportunities for reachability marking and future configurability of the split factor. The implementation appears thorough and well-tested, with clear motivation for monorepo use cases.
