This is a refactoring patch in the `git-history` series, adding tree-to-tree diff functionality to the wt-status subsystem. Junio Hamano provides a review comment on Patrick Steinhardt's patch that introduces `wt_status_collect_changes_trees()`, a new function that compares two arbitrary trees and records the differences as staged changes in the status structure.

The review focuses on documentation clarity, noting that while the function reuses the existing `wt_status_collect_updated_cb` callback (originally written for index comparisons), this connection isn't immediately obvious to readers. Junio suggests adding an explicit comment explaining that the function records changes as staged (index-side) modifications, since this behavior is currently only inferable by tracing through the callback usage.

The function itself wraps Git's diff machinery to compare two arbitrary tree objects, with configurable rename detection parameters inherited from the status struct. This infrastructure supports the `git-history` command's in-memory index operations for history editing, though the review doesn't touch on those higher-level use cases - it stays focused on this specific helper function's interface clarity.

No technical concerns are raised about the implementation itself, just the documentation gap regarding how the diffs are categorized (as staged changes). The change appears straightforward and well-contained within the wt-status subsystem while supporting the larger history editing feature.
