This is the final patch in Patrick Steinhardt's v4 series introducing the `git history` command, specifically implementing the `split` subcommand. The patch allows interactively splitting a commit into two by selecting which hunks to move into a new commit that becomes the parent of the modified original commit.

The email shows Patrick responding to Karthik Nayak's review feedback. Key points addressed:

1. **Commit message placement**: Karthik questioned whether the split-out commit (S0) should contain the original message while the modified commit (C0') gets the new message, rather than the current approach. Patrick notes this was previously discussed and suggests allowing editing both messages, though the interface for this needs thought (possibly multiple `-m` flags).

2. **Redundant checks**: Karthik pointed out duplicate validation for merge commits and ancestry checks. Patrick confirms these can be removed, and fixes an incorrect ancestry check that was testing if a commit was its own descendant rather than checking HEAD's ancestry.

The implementation uses temporary indexes and builds on the series' earlier infrastructure work. While the core functionality appears solid, the discussion reveals some UX considerations around message handling that may need refinement. The patch maintains the series' high quality with thorough error checking and clean integration with the existing `git-replay` infrastructure.
