This is a refactoring patch in the geometric repacking strategy series, introducing maintenance task execution control based on invocation type. The patch distinguishes between manual (run/--auto) and scheduled (--schedule) maintenance operations, converting the previous boolean `enabled` field into a bitmask to track which tasks should run in each context.

Key technical changes include:
- New `enum maintenance_type` with `MAINTENANCE_TYPE_SCHEDULED` and `MAINTENANCE_TYPE_MANUAL` flags
- Conversion of `enabled` field to `type` bitfield in `maintenance_strategy` struct
- Updated strategy definitions (none/default/incremental) to use new type-based activation
- Modified `initialize_task_config()` to handle type-based task filtering
- Preserved existing behavior where default strategy only runs manually and incremental only runs scheduled

The changes maintain backward compatibility while preparing for future patches that will expand strategy handling. The patch touches core maintenance infrastructure in builtin/gc.c, particularly around task initialization and strategy application. It builds on prior refactoring work in the series to support the upcoming geometric repacking functionality while keeping the existing incremental strategy behavior intact.

This is a foundational change that enables the subsequent geometric strategy implementation to properly handle different invocation contexts. The patch maintains the series' high code quality with clear type definitions and straightforward logic changes, though it doesn't yet implement the geometric strategy itself - that comes in later patches.
