This is the first patch in Patrick Steinhardt's v5 series introducing the `git-history` command, focusing on infrastructure refactoring in the wt-status subsystem. The patch adds a new function `wt_status_collect_changes_trees()` that diffs two arbitrary trees and formats the status output, similar to how wt-status normally handles working tree/index changes. While the function isn't used yet in this patch, it will support the upcoming history editing commands by providing tree-to-tree diff capabilities.

The implementation wraps existing diff machinery with wt_status-specific formatting callbacks, maintaining consistency with the subsystem's existing behavior for rename detection and other diff options. The function signature takes two treeish OIDs and a wt_status struct to store results, following the pattern of related wt_status_collect_* functions. 

This appears to be a well-contained preparatory change that cleanly extends existing functionality without modifying behavior for current users of wt-status. The commit message clearly explains the motivation (supporting upcoming history editing features) while acknowledging the slight conceptual mismatch with wt-status's working tree focus. The patch includes both implementation and header updates with appropriate documentation.
