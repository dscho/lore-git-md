This is part of the ongoing SHA-1/SHA-256 interoperability work introducing Rust code to Git (patch 4/14 in the series). The email responds to Patrick Steinhardt's review of the `ObjectID` struct implementation, which provides a Rust representation of Git object IDs that must work across the C/Rust FFI boundary.

The key discussion point here is the choice between using a Rust enum (which would provide better type safety) versus the current struct design (which uses a `u32` algorithm field with a fixed-size hash array). The author explains that while an enum would be preferable in pure Rust code, the current struct design is necessary for FFI compatibility with existing C code. They indicate this is a temporary measure until all C code using this type can be converted.

This exchange shows the careful balancing act required when introducing Rust to Git's codebase - maintaining FFI compatibility with existing C code while still trying to leverage the language's safety features where possible. The response is brief but directly addresses the technical tradeoff raised in the review.
