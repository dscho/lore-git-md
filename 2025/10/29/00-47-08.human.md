This is a follow-up discussion in the ongoing SHA-1/SHA-256 interoperability patch series introducing Rust code to Git. The email addresses a question about Rust project structure from Junio C Hamano.

Brian M. Carlson explains that `src/` is the standard directory for Rust source files in projects using Cargo (Rust build system), with `Cargo.toml` at the root and build output in `target/`. They note this structure affects module import paths in Rust (`crate::hash` for `src/hash.rs`). While C files could technically live in `src/`, Cargo ignores them unless explicitly compiled via build scripts.

The response provides practical context about Rust conventions but doesn't introduce new technical changes to the patch series. It's a minor clarification in the broader discussion about Git's first major Rust integration, which remains focused on the FFI design and hash algorithm interoperability work.
