This is a technical discussion about naming and safety design in the Rust hashing implementation, part of the ongoing SHA-1/SHA-256 interoperability work (patch 11/14). The exchange focuses on two key aspects of the `Hasher` implementation in Rust:

1. **Naming**: Ezekiel Newren suggests avoiding `Hasher` due to potential confusion with Rust's standard library `std::hash::Hasher`, proposing alternatives like `CryptoHasher` or `SecureHasher`. Brian m. carlson acknowledges the concern but notes Rust's common practice of reusing names like `Result` in different contexts, while remaining open to renaming.

2. **Safety distinction**: The discussion clarifies the purpose of querying whether a hasher is "safe" - referring not to Rust's `unsafe` keyword but to whether the SHA-1 implementation uses collision detection (SHA-1-DC). Brian explains this allows runtime verification when handling untrusted data, contrasting with faster but potentially unsafe hardware-accelerated SHA-1 variants. The current design uses a single type with a safety query method rather than separate types, as it better accommodates code paths that may handle both variants.
