This is a cover letter for a 10-part refactoring series targeting the xdiff subsystem, focused on type safety and Rust FFI compatibility. The series builds on two previously merged cleanup efforts (en/xdiff-cleanup and am/xdiff-hash-tweak) and represents the second phase of xdiff modernization.

The key technical changes include:
- Adding new `Documentation/technical/unambiguous-types.adoc` establishing cross-language type mapping conventions
- Converting all xrecord_t and xdfile_t fields to unambiguous types (uint8_t*, size_t, uint64_t, etc.)
- Splitting the `ha` field into `line_hash` (uint64_t) and `minimal_perfect_hash` (size_t)
- Renaming `rindex` to `reference_index` for clarity
- Using ptrdiff_t for `dstart`/`dend` (changed from ssize_t in v1 based on feedback)
- The series affects core diff algorithms across xdiff/xdiffi.c, xdiff/xprepare.c, and other xdiff components
- Introduces platform-portable hash guarantees via uint64_t in xdl_hash_record()
- Documents memory management boundaries for FFI interactions

The v2 changes address mailing list feedback by:
- Adding comprehensive type mapping documentation
- Switching from ssize_t to ptrdiff_t for line position tracking
- Clarifying the safety boundaries of the `rindex` type change
- Adding commit message details about casting requirements for the uint8_t* transition

This series represents the culmination of the xdiff type safety work, establishing project-wide conventions for Rust interoperability through fixed-width types, documented memory boundaries, and standardized FFI practices. With all technical decisions now resolved in the thread discussion, the series is ready for final review.
