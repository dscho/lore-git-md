This is a technical discussion about the object map format design in the ongoing SHA-1/SHA-256 interoperability patch series, specifically addressing naming and structural questions raised in previous reviews.

Patrick Steinhardt engages with brian m. carlson's responses to his earlier concerns about the binary loose object map format (patch 12/14). The discussion settles on dropping "loose" from the name, making it simply "object map" to better reflect its general purpose beyond loose objects. The exchange clarifies that the format maintains determinism by sorting entries according to the first object format, with Patrick accepting this design choice after understanding the lookup mechanics through offset tables.

Key technical points confirmed:
- The format resembles pack index v3 in its deterministic output requirements
- Full object IDs are stored once with mapping offsets between algorithms
- Streamability is impractical due to sorting requirements
- Header-first layout (vs trailer) is preferred for parsing simplicity

Patrick suggests adding ASCII diagrams to document the format's structure, noting they helped his own comprehension. This marks progress toward finalizing the object map design, with the main outstanding question being whether to include such documentation in this patch or a follow-up. The discussion of alternative approaches (like those used in reftables) has concluded with acceptance of the current design's tradeoffs.
