This is a follow-up discussion in the ongoing SHA-1/SHA-256 interoperability patch series introducing Rust code to Git. The email specifically addresses a question about Rust source code organization raised by Junio C Hamano regarding patch 4/14 (the ObjectID struct implementation).

The discussion focuses on Rust source file location conventions. Brian m. carlson explains that `src/` is the standard directory for Rust source files in projects using Cargo`, with `Cargo.toml` at the root and build output in `target/`. They note that while C files could technically live in `src/`, Cargo ignores them unless explicitly compiled via `build.rs`, and share an anecdote about a C-to-Rust migration project that successfully used this structure.

This is a minor organizational point in the larger series, but clarifies an implementation detail that could affect future Rust code layout in the Git project. The response draws on both Rust community conventions and practical experience with mixed C/Rust codebases, suggesting the current approach is both standard and workable. The exchange doesn't raise any new technical concerns about the core FFI design or ObjectID implementation that were the focus of earlier discussion.
