This is a design discussion email in the ongoing refs-migrate worktree support thread, focusing on two key questions about the migration behavior with worktrees.

Patrick Steinhardt responds to Junio Hamano's questions about allowing mixed ref storage formats (reftable in main repo + files in worktrees) and automatic worktree switching during migration. He explains that mixed formats would require backwards-incompatible changes to how `extensions.refStorage` works across worktrees, and while theoretically desirable, the current implementation assumes uniform storage across all worktrees. The discussion reveals this architectural constraint is deeply embedded in Git's worktree handling.

Regarding automatic worktree switching, Patrick expresses concerns about surprising users by implicitly affecting the main repository's refs when run from a linked worktree. He suggests the current explicit requirement to run from the main worktree serves as a safeguard, though acknowledges the UX tradeoff. The email also touches on whether to document this as a "limitation" versus a "protection mechanism" in the command's documentation.

The exchange highlights fundamental design tensions between flexibility and safety in the context of ref storage migration, with implications for both implementation complexity and user expectations. These decisions will affect how future worktree-related ref operations are implemented and documented.
