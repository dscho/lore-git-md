This is a technical discussion about the binary object mapping format in the ongoing SHA-1/SHA-256 interoperability work, specifically focusing on patch 12/14 in the series introducing Rust infrastructure to Git.

Junio C Hamano provides detailed review comments on the proposed binary format specification, focusing on documentation clarity and format design. Key points include:

1. **Documentation improvements**:
   - Suggests stating network-byte order requirement earlier in the format description
   - Recommends clearer terminology ("unique prefix" instead of "shortened object names")
   - Requests better explanation of how tables are used together for object lookup

2. **Format design questions**:
   - Questions the need for "chunk" terminology which may conflict with Git's existing chunk format
   - Suggests simplifying the reserved/future-use section of the header
   - Notes potential alignment issues with padding between sections

3. **Implementation feedback**:
   - Points out hard-to-maintain magic numbers in the Rust implementation
   - Questions whether padding calculations are properly documented in relation to section lengths

The review maintains a constructive tone while thoroughly examining the technical details. It doesn't reject the approach but seeks to refine both the specification and implementation before this becomes part of Git's object storage system. The discussion remains focused on this specific patch while acknowledging it as part of the larger interoperability effort.
