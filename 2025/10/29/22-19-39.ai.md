This is a documentation patch establishing cross-language type mapping conventions for Git's Rust FFI compatibility efforts, part of a larger 10-part refactoring series modernizing xdiff data structures. The patch introduces `Documentation/technical/unambiguous-types.adoc` which provides detailed specifications for type conversions between C and Rust, with notes about platform-specific considerations and potential pitfalls.

The document covers boolean, integer, floating-point, size, and enum types, with particular attention to problematic areas like character types (where C's `char` doesn't cleanly map to Rust) and Rust's `std::ffi::c_*` types. It warns against using Rust enums across FFI boundaries due to ABI instability and documents platform-specific behaviors in Rust's type mappings across different compiler versions.

Key technical points include:
- Standardized mappings for primitive types (uint8_t <-> u8, size_t <-> usize, etc)
- Warnings about floating-point IEEE-754 assumptions
- Detailed analysis of problems with Rust's `c_char` type
- Platform-specific behaviors in Rust's type definitions across versions
- Enum type limitations in FFI contexts

The documentation serves as a reference for the type safety changes being made throughout the xdiff refactoring series and establishes patterns for future cross-language work in Git.
