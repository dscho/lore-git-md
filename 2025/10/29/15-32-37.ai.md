This is a documentation patch that follows up on the recent discussion about backslash handling in Git's pattern matching. Jeff King adds explicit clarification to the gitignore documentation about how backslashes work in patterns, addressing two specific cases that caused confusion:

1. Backslashes escape any character (even non-metacharacters), unlike some other systems that might include the backslash itself or forbid it
2. A trailing backslash is invalid, which differs from pathspec matching behavior where it's treated literally

The patch adds both documentation in gitignore.adoc and a test case in t3070-wildmatch.sh to verify the behavior. The test shows the wildmatch behavior (used by gitignore) differs from pathspec matching for trailing backslashes - wildmatch rejects them while pathspec accepts them.

This builds on the recent thread about pattern matching correctness, where the team confirmed Git follows POSIX fnmatch behavior. The documentation helps users understand the sometimes unintuitive rules, particularly around escape sequences requiring double backslashes (`\\`) and invalid trailing backslashes. The patch is well-formed with both docs and tests, addressing a real pain point that confused both users and JGit implementers.
