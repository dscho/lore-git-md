This is a follow-up discussion in the Rust CI infrastructure thread, focusing on the line length formatting rules for Rust code.

SZEDER Gábor weighs in on the ongoing debate about whether to use Rust's default 100-character line length or maintain Git's traditional 80-character limit across all languages. The discussion originated from Patrick Steinhardt's patch implementing Rust formatting checks, where Junio Hamano suggested following Rust's conventions rather than Git's general formatting rules.

SZEDER argues strongly for maintaining the 80-column limit consistently across all file types, citing practical workflow benefits on laptop displays where three 80-column editor windows can fit side-by-side, while 100-column windows would reduce this to two. This echoes Junio's earlier concern about readability for those with aging vision, though Junio had expressed openness to language-specific defaults.

The exchange reveals a tension between two valid perspectives: language ecosystem conventions versus project-wide consistency. While the technical implementation of the Rust CI checks is settled (the series has been accepted), this stylistic question remains open for community consensus. SZEDER's position represents the "uniformity" camp, while Patrick and Junio had previously leaned toward "language-appropriate" defaults for Rust specifically.

Key terms referenced:
- rustfmt (Rust's formatting tool)
- 80 vs 100 character line length debate
- Editor window layout constraints
- Cross-language consistency arguments

This sub-thread doesn't introduce new technical changes but surfaces an important ergonomic consideration that may influence future formatting policy decisions, both for Rust and potentially other languages in the Git codebase.
