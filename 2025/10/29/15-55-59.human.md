This is a documentation follow-up to the recent pattern matching fixes. Jeff King notes that while his earlier patch documented backslash behavior in `.gitignore` patterns, the same rules implicitly apply to `.gitattributes` since it references gitignore's pattern format. He considered but decided against duplicating the documentation there, as gitattributes already points readers to gitignore(5) for pattern details.

The email also raises (but doesn't resolve) whether the gitglossary should clarify pathspec's different backslash handling compared to gitignore patterns. This remains an open question, though Jeff suspects pathspec users are less likely to use exotic patterns requiring such documentation.

The note serves as a thoughtful postscript to the comprehensive pattern-matching fixes, ensuring the documentation coverage is complete where it matters most while acknowledging edge cases that might not warrant equal attention. The core solution remains solid - the implementation fixes are merged, tests are in place, and the main documentation is now explicit about backslash behavior.
