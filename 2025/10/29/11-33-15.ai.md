This is a design discussion email in the ongoing thread about worktree support for `git refs migrate`. Kristoffer Haugsbakk responds to Patrick Steinhardt and Junio C Hamano's earlier exchange about the user experience of requiring the command to be run from the main worktree.

The email focuses on user perspective concerns rather than technical implementation. Haugsbakk argues that the "main worktree" concept is an implementation detail that shouldn't burden users, comparing it to how `git gc` operates uniformly across worktrees. They question the need for different ref storage formats per worktree, seeing it as a technical artifact rather than a useful feature. The discussion reveals a tension between technical constraints (backwards compatibility of `extensions.refStorage`) and user expectations (commands behaving consistently regardless of worktree context).

Key points raised include: the artificial nature of "main worktree" from a user's perspective, potential confusion caused by worktree-specific behavior for repository-wide operations, and skepticism about practical use cases for mixed ref storage formats. Haugsbakk suggests the current design feels like accommodating technical limitations rather than serving user needs.

The email doesn't propose concrete changes but provides important user experience perspective to balance against the architectural constraints discussed earlier in the thread. It highlights that while the technical solution may be sound, the user-facing aspects (error messages, documentation framing) will need careful attention to avoid confusion.
