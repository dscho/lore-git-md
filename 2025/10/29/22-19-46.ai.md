This is part 8/10 of Ezekiel Newren's refactoring series to modernize xdiff data structures for Rust FFI compatibility. The patch converts `xdfile_t.nreff` from `long` to `size_t` since it tracks the number of elements in the `rindex` array (which was already converted to `size_t` in earlier patches).

The change involves:
1. Updating the type declaration in `xtypes.h`
2. Removing the temporary `nreff` variable in `xprepare.c` and directly using `xdf->nreff` for array indexing
3. Initializing `nreff` to 0 before the counting loops rather than after

This follows the same pattern as previous patches in the series, continuing the transition to type-safe sizes for memory-related quantities. The commit message notes this is consistent with `nreff`'s role in tracking array elements, matching similar changes made to `nrec` in patch 7/10. The implementation maintains all existing behavior while using more appropriate types for the memory indexing operations.

The patch is part of the broader effort to establish unambiguous type mappings between C and Rust, with all prior patches in the series already having consensus and approvals. This change appears straightforward and well-contained, following the established patterns from earlier conversions in the series.
