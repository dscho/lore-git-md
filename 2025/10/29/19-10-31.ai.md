This is a bugfix addressing a memory leak in test infrastructure. The patch fixes a `strbuf` leak in the `test-delete-gpgsig` helper tool that was introduced in commit 7673ecd2dc but only became visible after GPG test infrastructure improvements in 6cd8369ef3 made the tests run more reliably. The leak occurs when reading input into a `strbuf` that wasn't being freed, causing failures in `SANITIZE=leak` mode for test t1016.

The fix adds proper cleanup by releasing the `strbuf` in all code paths, including an early return case for the "trailer" pattern. The changes are straightforward - adding a `goto out` label for the early return case and ensuring `strbuf_release()` is called before exiting. The patch is well-contained, touching only the test helper code, and appears to properly address the issue with no obvious side effects.

This relates to ongoing work around GPG test infrastructure (the `tz/test-prepare-gnupghome` series mentioned in the thread) that exposed this previously hidden issue. The fix is small and focused, with clear motivation and proper attribution to the original problematic commit.
