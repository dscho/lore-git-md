This is a design discussion email in the ongoing thread about worktree support for `git refs migrate`. Kristoffer Haugsbakk weighs in on the debate about whether the command should require running from the main worktree and whether different worktrees should be able to use different ref storage backends.

The email makes several key points from a user perspective: the "main worktree" concept feels like an implementation detail rather than something users should need to know about, and having different backends for different worktrees would be confusing. Haugsbakk compares this to `git gc` which operates on the repository as a whole regardless of which worktree it's run from.

The discussion reveals a tension between technical constraints (the current architecture requires uniform ref storage across worktrees) and user experience (users shouldn't need to think about which worktree is "main"). While acknowledging the technical limitations, Haugsbakk argues the current design feels unnecessarily user-hostile by making worktree location matter for the migration command.

This continues the thread's exploration of how to balance safety (preventing surprising behavior) with convenience (not requiring users to understand internal worktree implementation details). The email doesn't propose concrete changes but provides valuable user perspective on the ongoing design decisions.
