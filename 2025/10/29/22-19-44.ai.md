Refactoring patch in the xdiff type safety series, splitting a dual-purpose hash field for clarity.

This is patch 6/10 in Ezekiel Newren's series modernizing xdiff's data structures for Rust FFI compatibility. The change splits the `ha` field in `xrecord_t` into two distinct fields: `line_hash` (a simple content hash) and `minimal_perfect_hash` (a unique identifier assigned during classification). This clarifies the code by separating concerns that were previously conflated - the first is used for initial line comparisons while the second ensures unique identification across files.

The patch updates all xdiff algorithms (myers, histogram, patience) to use the new field names, with the most changes in `xprepare.c` where the classification logic lives. The split helps document that line comparisons actually use `xdl_recmatch()` as a fallback when hashes collide, despite appearances from the old single-hash approach. The type changes align with the series' broader goals - `line_hash` becomes `uint64_t` while `minimal_perfect_hash` uses `size_t`.

This continues the series-wide pattern of making implicit behaviors explicit through type safety and better naming. The change is mechanical with no algorithm modifications, just clearer expression of existing logic. All test suites pass with the updated code, confirming behavioral preservation. The patch follows the established approach of comprehensive cross-file updates to maintain consistency across xdiff's subsystems.
