This is part 5/10 of a refactoring series modernizing xdiff's data structures for Rust FFI compatibility, specifically focusing on type safety in the `xdl_hash_record()` function family.

The patch converts all type signatures and implementations in the hash record functions to use unambiguous fixed-width types: `char*` becomes `uint8_t*` to match Rust's byte-oriented memory model, and `unsigned long`/`long` become `uint64_t` for consistent hash values across platforms. The `flags` parameter is also upgraded to `uint64_t` to prevent high-bit truncation on 32-bit systems. These changes affect the core hashing functions (`xdl_hash_record_verbatim`, `xdl_hash_record_with_whitespace`, and their inline wrapper) along with their call sites in `xdiff-interface.c` and `xprepare.c`.

Key technical details include:
- The hash algorithm (djb2) remains unchanged but now operates on `uint8_t` bytes
- All hash variables (`ha`) and bit operations use `uint64_t` consistently
- Boolean flags are converted to proper `bool` type where applicable
- Casting patterns standardized to `(uint64_t)` for character values
- The whitespace-handling logic in `xdl_hash_record_with_whitespace` maintains identical behavior despite type changes

The changes propagate through several subsystems:
- Diff generation (via `xdiff-interface.c`'s string hashing wrapper)
- File preparation (`xprepare.c`'s line classification)
- Core comparison utilities (`xutils.c`)
- Header declarations (`xutils.h`)

This builds on prior patches' type safety work and aligns with the series' documentation in `unambiguous-types.adoc`, particularly regarding FFI-compatible type mappings. The patch includes necessary casting at interface boundaries while maintaining the existing algorithmic behavior, completing another step toward Rust interoperability.
