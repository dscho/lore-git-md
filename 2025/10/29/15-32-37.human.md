This is a documentation patch that clarifies backslash handling in `.gitignore` patterns, following up on the recent discussion about `**` pattern matching behavior.

Jeff King adds explicit documentation about how backslashes work in gitignore patterns, which use fnmatch(3) under the hood. The patch explains two key behaviors: (1) backslashes escape any character (even non-special ones), and (2) trailing backslashes make the pattern invalid. This was a point of confusion with JGit's implementation, though Git's behavior correctly follows POSIX fnmatch standards.

The patch includes both documentation updates and a test case showing the difference between wildmatch (used by gitignore) and pathspec matching when dealing with trailing backslashes. While this is a small clarification, it addresses a subtle but important corner case that could trip up users and implementers alike. The change is well-justified by the recent discussion and provides clear value in documenting behavior that was previously only implied by the fnmatch reference.
