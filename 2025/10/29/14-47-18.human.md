This is a discussion clarification in the ongoing refs migration with worktrees thread. Junio C Hamano responds to Patrick Steinhardt's technical point about backwards compatibility of `extensions.refStorage` across worktrees, agreeing that the current design requiring uniform ref storage is justified. 

The key insight is that Git has long assumed all worktrees share the same ref backend, making mixed storage formats fundamentally incompatible. Junio notes this simplifies implementation by eliminating edge cases where different backends might overlap. He also observes that while the current "main worktree" requirement serves as a safeguard, it reveals a documentation gap - users may not intuitively understand the shared-backend constraint.

The exchange moves the thread toward resolution on one of its major open questions, suggesting the series should: 1) maintain the uniform storage requirement as a technical necessity, (2) clearly document this constraint, and (3) use the main-worktree check as both a safety mechanism and educational opportunity. This provides clear direction for finalizing both the implementation and user-facing messaging.
