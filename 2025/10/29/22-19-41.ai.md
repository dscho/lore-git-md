This is part 3/10 of a refactoring series modernizing xdiff's data structures for Rust FFI compatibility. The patch changes the `xrecord_t.ptr` field from `char*` to `uint8_t*` to better match Rust's byte-oriented memory model (`u8`), since these pointers reference raw bytes rather than Unicode characters. 

The change requires casting to `char*` at all usage sites to maintain compatibility with existing xdiff functions that expect character pointers, avoiding a broader refactoring of the xdiff subsystem. The patch updates 7 files with these casts, primarily in functions dealing with line comparison, regex matching, and diff output generation. 

This aligns with the series' goal of establishing unambiguous type mappings between C and Rust, as documented in the new `unambiguous-types.adoc` file. The change is mechanical but important for cross-language interoperability, maintaining behavior while making the byte-oriented nature of the data explicit. The casting approach was chosen to minimize disruption to xdiff's extensive codebase while still achieving the type safety goals.
