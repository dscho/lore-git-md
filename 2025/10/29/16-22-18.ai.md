This is a discussion about the user experience of the `git refs migrate` command's worktree handling, following up on Junio and Patrick's earlier technical consensus about uniform ref storage across worktrees.

Ben Knoble responds to Kristoffer Haugsbakk's UX concerns about requiring the command to be run from the main worktree. While Patrick had expressed concerns about surprising users by automatically switching worktrees, Ben argues that minimizing user-managed concepts is preferable. He suggests that having the command automatically switch to the main worktree (with trace output for transparency) would provide a smoother experience, though acknowledges this could be addressed later in the stabilization process.

The email reinforces the thread's emerging UX challenge: how to reconcile the technical requirement of uniform storage (which necessitates main-worktree operations) with intuitive command behavior. Ben's position aligns with Kristoffer's earlier argument that worktree location shouldn't matter to users, though he frames it more as a polish issue for future rather than an immediate blocker. This keeps the discussion moving toward eventual UX solutions while the implementation details are being worked out.
