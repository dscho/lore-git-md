Bugfix for `git diff --quiet` regression in v2.51.1, addressing incorrect output with newly staged files. This is a direct follow-up to the thread where Jake Zimmerman reported the issue and Jeff King confirmed it was introduced by commit b55e6d36eb.

Jeff's patch takes a conservative approach to fix the regression by restoring the pre-b55e6d36eb redirection of output to /dev/null when `diff_from_contents` is active in quiet mode. The change affects `diff.c`'s handling of the `DIFF_FORMAT_NO_OUTPUT` case, specifically around the `diff_flush` function. The patch includes a new test case in t4035 that verifies the fix using `diff-tree -w` to trigger the same underlying issue.

Key technical points:
- The regression occurred when porcelain diff's default `--ext-diff` setting triggered content-level diffs via `diff_from_contents`
- Original fix attempted to use a `dry_run` flag but missed some output paths (particularly creation/deletion diffs)
- New solution provides defense-in-depth by forcing output to /dev/null while longer-term fixes are considered
- External diff programs are confirmed to handle quiet mode correctly via existing `cmd.no_stdout` checks

The patch represents a minimal, low-risk fix suitable for maint branches while leaving open the possibility of more comprehensive solutions that properly respect `dry_run` throughout the diff machinery. Jeff acknowledges this isn't the most elegant solution but prioritizes correctness and safety for the regression.
