This is the foundational patch in Adrian Ratiu and Emily Shaffer's hook subsystem refactoring series (v2, 10 parts), introducing stdin handling for parallel processes. The patch adds a new `feed_pipe_fn` callback to `run_processes_parallel()` that enables streaming large inputs to child processes without buffering everything in memory, addressing a key limitation in the parallel execution API.

The implementation adds three main components:
1. A `pp_buffer_stdin()` helper that manages the stdin pipe feeding process using the new callback
2. Consolidated I/O handling in `pp_handle_child_IO()` that sequences stdin feeding before stderr collection
3. SIGPIPE handling to prevent crashes when children close their stdin early

The changes touch core parallel execution logic in `run-command.c`, extending the API in `run-command.h` with documentation for the new callback contract. Test coverage includes a new stdin feeding test in `t0061-run-command.sh` that verifies the streaming behavior works across multiple parallel processes.

Key technical details:
- Callback returns <0 (error), 0 (more data), or >0 (complete)
- Maintains backward compatibility when no callback is provided
- Handles both grouped and ungrouped output modes
- Includes edge case handling for EPIPE when children exit early

This establishes the infrastructure needed for subsequent patches to convert hooks like pre-push to use parallel processing with streaming input. The implementation follows patterns seen in `transport.c`'s pre-push hook handling but generalizes them into reusable API components.
