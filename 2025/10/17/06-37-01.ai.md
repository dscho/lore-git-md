Performance optimization follow-up for `git last-modified` command.

Jeff King (peff) provides a small code review suggestion for Toon Claes's performance optimization work on the `git last-modified` command. The patch implements a faster algorithm using path activity bitmaps and priority queues to find the most recently modified commits for given paths.

The specific suggestion relates to memory management of diff filepairs during the path processing. peff points out that the current implementation manually frees each filepair individually before clearing the diff queue, while the queue's clear function would handle this cleanup automatically. He proposes removing the redundant manual freeing and letting `diff_queue_clear()` handle all cleanup, which would make the code more idiomatic.

This is a minor implementation detail in the context of the larger performance work, which has already seen significant discussion about bitmap vs char* path tracking, flag usage, and correctness edge cases. The thread has established that the new algorithm provides 2.6x-5.3x speed improvements while maintaining correctness parity with `git log --max-count=1` behavior. peff's suggestion doesn't challenge the core approach but offers a small cleanup to match Git's typical diff handling patterns.
