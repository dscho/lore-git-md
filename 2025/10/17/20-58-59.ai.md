Feature patch introducing `commitGraph.changedPaths` config option for commit-graph Bloom filters, with Scalar integration. This is Emily Yang's second version of the patch, incorporating feedback to clarify the config behavior documentation.

The patch adds persistent configuration for writing changed-path Bloom filters during `git commit-graph write`, with three key behaviors: when set to `true`, it acts like `--changed-paths`; when `false` or unset, it preserves existing filters but doesn't write new ones unless they already exist. Command-line options always take precedence over the config. The change includes thorough test coverage in t5318-commit-graph.sh that verifies the config interactions with command-line flags and existing filter state.

The patch also makes this config an optional recommended setting in Scalar (`commitGraph.changedPaths=true`), targeting large monorepos like Microsoft's Office monorepo where Emily works. The implementation builds on the existing `enable_changed_paths` field in `struct commit_graph_opts` using -1/0/1 values to represent the three states.

Documentation updates clearly differentiate between command-line flag behavior (where `--no-changed-paths` removes filters) versus config behavior (where `false` preserves existing filters). The commit message and documentation now explicitly state that config precedence doesn't trigger filter removal when overriding `true` with `false`. This addresses previous confusion about the asymmetric design rationale that Derrick Stolee had justified in earlier discussion.
