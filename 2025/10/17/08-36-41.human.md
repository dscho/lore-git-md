Bugfix for `git diff --quiet` regression in v2.51.1. Jeff King proposes a targeted fix to restore silent behavior when comparing HEAD to index with newly staged files, which broke in commit b55e6d36eb. The regression occurs because porcelain diffs enable external diff checking by default, triggering content-level comparisons that weren't properly silenced in quiet mode.

The patch takes a conservative approach by restoring output redirection to /dev/null in `diff_flush()` when both `--quiet` and content comparison flags are active. This provides defense-in-depth while a more comprehensive fix for the dry_run handling could be developed later. The change comes with a new test case using `diff-tree -w` to verify the behavior.

Jeff acknowledges this may not be the most elegant solution but argues it's the safest approach for a maintenance release, noting the original issue was caught despite lacking test coverage for this specific `git-diff` scenario. The patch maintains all existing functionality while preventing any output leakage in quiet mode, whether from internal diff generation or (theoretically) external diff programs.
