Hook subsystem refactoring series (part 7/10) - output capture for parallel processes

This patch from Emily Shaffer and Adrian Ratiu adds a new capability to the parallel process execution infrastructure, allowing callers to capture and redirect the output that would normally go to stderr. The primary use case is for server-side hooks that need to relay output to clients over a network transport.

The implementation introduces a new `consume_sideband` callback in `run_process_parallel_opts` that receives output via a strbuf. This avoids the need for temporary pipes while still giving callers flexibility - the callback is invoked even when there's no output, enabling keepalive mechanisms. The patch includes a BUG() check to prevent incompatible combinations with the existing `ungroup` option.

Test coverage shows the new functionality working with a simple example that redirects output to a file. The changes are focused on `run-command.c` and its header, with the test helper and existing test script extended to exercise the new feature.

This appears to be a well-considered addition to the parallel execution API, with clear documentation of the new callback's purpose and behavior. The implementation follows established patterns from earlier patches in the series while addressing a specific need for server-side hook handling.
