Bugfix for `git diff --quiet` regression when new files are staged.

Jake Zimmerman reports that Git 2.51.1 introduced a regression where `git diff --quiet HEAD` prints diff output for newly staged files, despite the `--quiet` flag explicitly promising to disable all output. This behavior differs from Git 2.51.0 and earlier versions, and contradicts the documented purpose of `--quiet`.

The issue is reproducible with a simple test case: creating a new repository, adding an empty file, and running the command. The bisect points to commit b55e6d36eb ("diff: ensure consistent diff behavior with ignore options") as the likely culprit.

This appears to be a straightforward bug where the quiet flag's output suppression isn't being properly respected in all cases. The patch doesn't propose a fix but clearly identifies the regression and its trigger, making it easy for maintainers to investigate. Given the clear reproduction steps and bisect result, this seems like a strong candidate for a quick fix in the next release.
