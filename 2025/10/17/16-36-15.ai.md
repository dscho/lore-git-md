This is a refinement of the first patch in the two-part series restoring gitk's window geometry persistence. Johannes Sixt updates the commit message for the main window revert patch based on historical context provided by Mark Levedahl.

The revised commit message now better explains the 2008 compromise (b9bee11526ec) that only saved window size, not position, due to multi-monitor complaints. It acknowledges this was a workaround for Cygwin's outdated Tcl/Tk 8.4.1, which became obsolete in 2011 when Cygwin switched to X11/Tcl/Tk 8.6. The message makes the author's personal preference clear - restoring full geometry is more user-friendly for single-monitor setups, though multi-monitor behavior remains untested.

Key technical details remain unchanged from v3: the patch still reverts to storing complete main window geometry in `geometry(main)` and removes the size-only restrictions. The discussion confirms architectural consensus on this change, with the commit message now providing clearer historical context about the original multi-monitor concerns that led to the size-only compromise.

This appears ready for inclusion, completing the first half of the window persistence modernization alongside the already-refined Tags/Heads window solution in patch 2/2. The thread shows all technical issues have been addressed, with only this final documentation polish remaining.
