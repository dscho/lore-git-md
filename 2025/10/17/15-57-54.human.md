Bugfix confirmation for promisor pack object handling. Sam Estep reports hitting the same `should_include_obj()` BUG() assertion that Nikolas Garza originally encountered, providing a more reliable reproduction recipe using a large Nixpkgs repository. The failure occurs during `git fetch --no-show-forced-updates` when processing promisor packs, consistently across x86_64-linux and aarch64-darwin platforms.

Estep's reproduction steps involve cloning a filtered mirror of nixpkgs.git followed by repeated fetch operations, which eventually trigger the assertion when `pack-objects` encounters non-existent objects. The error manifests identically to Garza's report, confirming this is not an isolated incident but a recurring issue affecting real-world usage of promisor packs.

The email serves both as a bug confirmation and a gentle nudge to Jonathan Tan about the proposed fix from April - returning 0 for absent objects in `should_include_obj()`. While not proposing new solutions, this report adds weight to the original diagnosis by demonstrating the problem affects multiple users across different environments (Git 2.51.0 via Nixpkgs, in addition to the original 2.49 report).

The reproduction case may help overcome the previous blocker of creating a reliable test, as it requires working with a very large repository (nixpkgs) which might complicate inclusion in the test suite. The report maintains the collaborative tone seen throughout the thread while providing valuable new data points about the bug's behavior.
