This thread addresses a bug where `git diff --dry-run` inconsistently suppresses output - while commit b55e6d36eb silenced content comparisons, it still showed file deletions, mode changes, and (as later discovered) unmerged path notifications. The current patch series aims to make dry-run behavior fully consistent by suppressing all diff output types.

The technical solution modifies `run_extern_diff()` and `emit_diff_symbol_from_struct()`, though a newly identified edge case shows unmerged path notifications still leak via `fprintf()` in `run_diff_cmd()`. Both Johannes Schindelin (Git for Windows maintainer) and Junio Hamano (Git maintainer) agree the patch is technically sound but needs improvements: better commit message context, documentation of missed cases, additional test coverage for `--quiet` and unmerged paths, and consideration of Jeff King's alternative implementation approach.

In the latest exchange, Junio suggests delaying inclusion until Git for Windows v2.51.2 to allow time to either incorporate Jeff King's approach or refine the current patch further. Johannes had already released v2.51.1 with unrelated CVE fixes before this discussion, making v2.51.2 the logical target. The thread remains focused on achieving complete dry-run consistency while coordinating with release cycle realities.
