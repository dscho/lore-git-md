Bugfix targeting Git's protocol.file.allow configuration behavior.

This bug report identifies an inconsistency in how Git handles the `protocol.file.allow` configuration when applied locally versus globally. The reporter demonstrates that setting `protocol.file.allow=always` with `--local` does not properly enable file protocol access for submodule operations, while the same setting works as expected when applied globally with `--global`.

The issue manifests when trying to add or update submodules using local file paths, with Git incorrectly rejecting the file transport protocol despite the local repository configuration explicitly allowing it. The reporter provides clear reproduction steps showing the failure case (local config) versus the working case (global config), and notes the behavior is consistent across Git versions 2.39.5 through 2.51.1.

The security implications are noted - the reporter wants to restrict file protocol access system-wide while enabling it for specific repositories, which should be possible via local configuration but currently isn't. The bug affects core submodule operations (`submodule add` and `submodule update`) when using local file paths.

Key technical details:
- Configuration setting: `protocol.file.allow`
- Affected commands: `git submodule add`, `git submodule update`
- Behavior difference between `--local` and `--global` config scopes
- Security context: file protocol restrictions are important for safety
- Version range: at least 2.39.5 through 2.51.1

This appears to be a legitimate configuration handling bug that prevents users from applying security policies with appropriate granularity. The report is well-documented with clear reproduction steps and version information.
