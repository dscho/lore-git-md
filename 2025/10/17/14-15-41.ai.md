Feature enhancement in the hook subsystem refactoring series (v2 7/10) introducing output capture capability for parallel processes. This patch adds a new `consume_sideband` callback to `struct run_process_parallel_opts`, allowing callers to intercept and process output that would normally go to stderr. The primary use case is server-side hooks needing to relay output to clients, but the mechanism is general enough for any parallel process management.

Key technical changes include:
- New `consume_sideband_fn` typedef and field in run-command.h
- Modified output handling in run-command.c to use the new callback when present
- Explicit BUG check preventing simultaneous use of `ungroup` and sideband capture
- Test helper implementation writing to a "sideband" file
- New test case in t0061 verifying the diversion behavior

The implementation maintains backward compatibility by defaulting to stderr output when no callback is provided. The callback receives a strbuf` containing output, allowing zero-copy processing without temporary files or descriptors. The patch includes a test demonstrating the capture mechanism while preserving the existing test suite's coverage.

This builds on previous work in the series by providing more flexible output handling for parallel processes, particularly relevant to hook implementations. The change is well-contained, touching only the parallel process infrastructure without modifying existing hook callers. The test coverage appears adequate for the new functionality, though reviewers may want to verify edge cases around partial output and error conditions.
