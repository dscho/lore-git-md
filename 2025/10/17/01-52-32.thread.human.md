This thread examines test failures in `t7528-signed-commit-ssh.sh` related to SSH agent setup, with the core issue being that test directories containing spaces cause silent failures in the test harness. The discussion has evolved through several key insights.

Xi Ruoyao initially reported the test failing due to socket path length limitations (ENAMETOOLONG), which Collin Funk confirmed as a system constraint. Jeff King then identified a more serious issue: the test's unquoted evaluation of `ssh-agent` output causes silent failures when test paths contain spaces, with the test improperly falling back to external SSH_AUTH_SOCK. King proposed using relative paths (`./agent.sock`) to address length issues while highlighting the need for robust space-handling solution.

Lauri Tirkkonen has now added important historical perspective, explaining that OpenSSH's behavior changed in version 10.1 when it moved the default socket location from `/tmp` to `$HOME`. This explains why the space issue went unnoticed - older versions avoided the problem by using `/tmp`. The email also reveals Alpine Linux CI encountered this and worked around it with `ssh-agent -T`, though this solution won't work for pre-10.1 OpenSSH.

The thread now faces the challenge of designing a solution that handles both path length constraints and space-containing paths across different OpenSSH versions, while maintaining test isolation. The SSH signing functionality itself remains unaffected - this is purely a test infrastructure issue.
