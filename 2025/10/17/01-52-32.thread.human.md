This thread addresses a test failure in `t7528-signed-commit-ssh.sh` that has exposed both reliability and security issues in Git's test suite. The core problem involves SSH agent setup during tests, where path length limitations, unquoted path evaluation (now confirmed as a command injection vulnerability), and OpenSSH version differences (pre-10.1 vs newer) all contribute to test failures. While the SSH signing functionality itself works fine, the test infrastructure needs hardening.

Jeff King and Brian Carlson have been leading the discussion on solutions. Carlson confirmed failures on Debian unstable, particularly with spaces in paths, and prefers a fallback approach using `ssh-agent -T`. Jeff acknowledges the security risk but considers it low-priority since an attacker would need control of $HOME. He's now also highlighting a separate issue where the current `eval $(ssh-agent)` pattern silently fails when `ssh-agent` isn't installed, suggesting this warrants a prereq check.

Junio Hamano has confirmed the command injection vulnerability, though the practical risk is limited. The discussion now balances immediate fixes (Carlson's fallback approach vs Jeff's preference for explicit socket paths with `-a`) with broader test infrastructure improvements. Carlson has also reported the OpenSSH behavior to Debian, which may influence future versions. The thread shows consensus on fixing these issues but ongoing discussion about implementation scope - whether to focus narrowly on the immediate test failure or also improve general test harness robustness around SSH setup.
