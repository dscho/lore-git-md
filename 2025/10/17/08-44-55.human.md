Bugfix for inconsistent color handling in `git status --short -z` output. This patch resolves an odd case where modified files showed colored markers but untracked files did not in the NUL-separated short format.

Jeff King explains that while `-z` typically indicates machine-readable output (and defaults to `--porcelain` mode which suppresses colors), the explicit combination of `-z --short` is a special case requesting human-readable output with NUL separators. The current behavior was inconsistent, coloring some markers but not others. The fix makes untracked file markers (`??`) respect colors like other status indicators in this mode.

The change is minimal - moving the color application in `wt_shortstatus_other()` before the null-termination check to match the pattern used elsewhere. A new test verifies the behavior by converting NULs to newlines for comparison with existing color output tests. The patch appears well-considered with clear rationale and test coverage, addressing a minor but genuine inconsistency in a rarely-used output mode.
