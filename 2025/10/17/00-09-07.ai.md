Bugfix targeting `git diff --quiet` behavior regression.

This email reports a regression in Git v2.51.1 where `git diff --quiet HEAD` produces output for newly staged file when it should remain silent according to the `--quiet` flag's promise to "Disable all output of the program." The reporter, Jake Zimmerman, provides a clear reproduction recipe showing the difference between v2.51.0 (silent) and v2.51.1 (outputs diff header for new file).

The bisect points to commit b55e6d36eb ("diff: ensure consistent diff behavior with ignore options") as the likely culprit. This appears to have unintentionally changed the behavior of `--quiet` when showing diffs for new files. The patch doesn't propose a fix but establishes the regression clearly with version comparisons and bisect results.

Key technical details for future reference:
- Affects `builtin/diff.c` behavior with `--quiet` flag
- Regression introduced in v2.51.1 by b55e6d36eb
- Specifically manifests when diffing HEAD against index with new staged files
- Expected behavior (silence) documented in man pages

The report is well-researched and clearly demonstrates a deviation from documented behavior, making it a strong candidate for fixing. The regression appears unintentional based on the commit that introduced it, suggesting this would be uncontroversial to address.
