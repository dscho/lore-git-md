Bugfix for promisor pack object handling in `pack-objects`. This email provides a reliable reproduction case for the intermittent BUG() assertion in `should_include_obj()` when processing non-existent objects during promisor pack operations. Sam Estep demonstrates the issue occurring consistently with Git v2.51.0 when performing a `git fetch --no-show-forced-updates` on a large Nixpkgs repository clone, showing the same failure pattern originally reported by Nikolas Garza.

The reproduction steps involve cloning a Nixpkgs mirror with tree filtering, then repeatedly fetching updates until the BUG() triggers. The error manifests when `pack-objects` attempts to repack local links into promisor packs, hitting the assertion that `should_include_obj()` should only process existing objects. Estep's configuration includes `fetch.all=true` and `fetch.prune=true`, though it's unclear if these settings affect the bug's occurrence.

The email references Jonathan Tan's earlier proposed fix to make `should_include_obj()` return 0 for absent objects, asking for confirmation this remains the correct approach. This provides valuable validation of both the bug's persistence across Git versions and its reproducibility on different architectures (x86_64-linux and aarch64-darwin), moving the thread closer to having a testable fix. The key technical elements remain the promisor pack handling in `builtin/pack-objects.c` and the object existence checking logic in `should_include_obj()`.
