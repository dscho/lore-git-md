This is patch 5/10 in a series refactoring Git's hook subsystem to use a new callback-based API, converting away from direct `child_process` management. The patch focuses on the reference-transaction hook, which fires during ref updates.

The conversion follows the established pattern from earlier patches: replacing manual process setup with a `feed_pipe_fn` callback (`transaction_hook_feed_stdin`) that streams ref update data to the hook. Each callback invocation processes one ref update, formatting the old/new OIDs or symbolic ref targets into a strbuf before writing to the hook's stdin. The implementation maintains the same EPIPE error handling semantics while eliminating explicit SIGPIPE management.

The change removes 48 lines of process/signal handling code while adding 53 lines of callback logic, with the net effect being cleaner hook execution through the centralized `run_hooks_opt` API. Performance appears adequate with per-ref streaming, though the commit message notes batching could be added later if needed. Existing hook tests continue passing, though no new tests are added here.

This continues the series' steady progress in standardizing hook execution while addressing reviewer feedback from earlier versions. The patch appears well-structured and follows the established conversion pattern, suggesting it's on track for eventual inclusion.
