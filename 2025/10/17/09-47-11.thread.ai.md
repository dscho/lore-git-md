Thread summary:

Bug report regarding commit-graph segfault with alternate object stores. The thread root describes a segmentation fault that occurs when writing commit-graphs in repositories configured with alternates, particularly after the referenced repository's commit-graph files become inaccessible. The crash happens in `write_graph_chunk_data()` when processing NULL tree hashes during commit-graph generation.

Core technical details:
- Failure occurs during `cmd_fetch` when `fetch.writeCommitGraph` is enabled
- Specific crash point is NULL pointer dereference in `write_graph_chunk_data()`
- Reproducible with repositories cloned with `--reference` when upstream commit-graphs are removed
- Affects Git 2.43.0 on Linux with glibc 2.39
- Commit-graph chain files show divergence between normal and alternate-enabled repos

Proposed solutions from reporter:
1. Detect/handle missing alternate commit-graphs by rebuilding from scratch
2. Warn users about commit-graph limitations with alternates and suggest disabling `fetch.writeCommitGraph`
