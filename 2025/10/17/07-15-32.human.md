This is a response to a bug report about `protocol.file.allow` configuration behavior with submodules. Jeff King explains why setting `protocol.file.allow=always` locally doesn't work for submodule operations - when Git clones a submodule, it creates a new repository that doesn't inherit the parent repository's local configuration. 

He confirms the reporter's observation that global configuration works, and suggests two alternative approaches: using the global config or passing the setting via command line with `-c`. He also notes this is a known design limitation rather than a bug, mentioning past discussions about inheriting superproject config and the complications involved.

The response provides useful technical background for users encountering this behavior, though it doesn't propose any immediate changes to Git's behavior. The explanation helps clarify the security implications of the current design, where submodule operations require explicit protocol permissions rather than inheriting them from the parent repo.
