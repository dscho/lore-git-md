This is a response in the ongoing discussion about making `git grep` ignore binary files by default. Junio C Hamano pushes back against Eloy's proposal to add a `grep.ignoreBinary` config option and potentially change the default behavior in Git 3.0.

The response argues against the change on three grounds: historical precedent (the existing `-I` and `-a` flags have sufficed for nearly 20 years), consistency with GNU grep's behavior, and backward compatibility concerns. Hamano emphasizes that changing the default would likely break existing scripts that rely on the current behavior.

This appears to be a significant objection from the Git maintainer, suggesting the proposal may face an uphill battle unless stronger use cases or mitigation strategies for backward compatibility are presented. The response doesn't completely close the door, but sets a high bar for justifying such a change.
