Documentation patch continuing Julia Evans' series to improve `git-reset` man page clarity, focusing on mode explanations.

This third patch in the 4-part series addresses specific user confusion points about `git reset` modes by restructuring their descriptions. Key changes include: standardizing "index" terminology (removing "index file" variants), reordering modes to put `--mixed` first as the default, and restructuring explanations to consistently describe working directory impact first. The patch makes notable improvements to `--merge` by explicitly recommending `git merge --abort` as the preferred alternative, and adds a concrete example for `--soft` showing commit squashing.

The technical changes (22 insertions, 20 deletions) maintain all existing functionality while improving clarity. The new structure emphasizes safety considerations (highlighting `--hard`'s destructive nature) and better explains the unusual behavior of `--soft` leaving the index unchanged. The patch continues the series' pattern of preserving technical accuracy while making the documentation more approachable, building on the previous patches' reorganization work. No new functionality is introduced - this is purely a documentation improvement targeting common pain points identified from user feedback.
