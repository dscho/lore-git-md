Feature patch adding stdin callback support to Git's hook system, part of Adrian Ratiu and Emily Shaffer's hook refactoring series (v2, patch 2/10). This builds on the parallel process stdin handling introduced in the previous patch.

The change adds a new `feed_pipe` callback mechanism to the hook API, allowing hooks to receive stdin data via direct streaming rather than file-based input. This is more efficient for large data volumes since it avoids filesystem roundtrips. The implementation enforces mutual exclusivity between the new callback and existing `path_to_stdin` file-based approach via `BUG()` assertions.

Key technical additions include:
- `feed_pipe_fn` callback and associated context pointers in `struct run_hooks_opt`
- Pipe initialization logic in `pick_next_hook()`
- Documentation of ownership rules for the pipe context

The patch appears well-integrated with the series' broader goals of modernizing hook infrastructure. It maintains backward compatibility while introducing the streaming capability needed for subsequent parallel hook execution work. The implementation is clean with clear error handling and thorough documentation of the new API surface.
