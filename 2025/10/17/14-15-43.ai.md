This is part 9/10 of the hook subsystem refactoring series, converting receive-pack's update and post-update hooks to the new callback-based API. The patch builds on the sideband output handling introduced in patch 8/10, applying it to two key receive-pack hooks.

The changes replace direct `child_process` usage with the new `run_hooks_opt` API, including the sideband output callback when `use_sideband` is enabled. The update hook conversion maintains the same argument passing (ref name, old/new OIDs) while the post-update hook collects all updated refs before execution. Both hooks retain their sequential execution via `processes=1`.

Key technical details include:
- New `hook_output_to_sideband` helper function that pipes hook output through `send_sideband`
- Removal of manual `find_hook()` and `child_process` setup in favor of `run_hooks_opt`
- Preservation of sideband behavior through `opt.consume_sideband` assignment
- Continued use of `the_repository` (not yet converted in this series)

The patch follows the established pattern of the series by providing a thin wrapper over the core run-command functionality while maintaining backward compatibility. It demonstrates the API's flexibility by handling both single-ref (update) and multi-ref (post-update) hook cases with similar structure. The changes are focused on receive-pack.c with no modifications to the underlying hook infrastructure.

This appears to be a straightforward application of the new API to existing hooks, though it doesn't yet address the series' open questions around parallel execution or grouping behavior for these specific hooks. The implementation looks clean and maintains all existing functionality while removing boilerplate code.
