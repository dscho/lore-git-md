This is a performance optimization patch for the `git last-modified` command, building on prior work by Taylor Blau and Derrick Stolee. The patch introduces a new algorithm that significantly speeds up finding the most recent commit modifying each path, particularly for rarely-modified files where the old implementation was slowest.

The key improvements include using generation-sorted commits in a priority queue, path activity tracking via EWAH bitmaps, and Bloom filter optimizations to skip unnecessary diffs. Benchmark results show 2.6x speedup on git.git and 5.3x for extreme cases like checking rarely-modified files. The new implementation also fixes a correctness issue where the old version could produce different results than `git log --max-count=1` in some merge scenarios.

Taylor Blau provided code review feedback, identifying a segfault when handling NULL oids (now fixed) and suggesting additional benchmarking on larger repos like linux.git. There's ongoing discussion about implementation details like bitmap vs char* storage for path tracking and proper flag documentation. The core algorithm has consensus but needs some refinement before merging.
