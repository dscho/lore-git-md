Cover letter for a hook subsystem refactoring series (v2). This 10-part patch series by Adrian Ratiu and Emily Shaffer completes the conversion of Git's remaining hooks to the new `hook.h` API, following up on extensive v1 feedback. The series modernizes hook infrastructure with stdin callbacks (`feed_pipe_fn`), output capture (`consume_sideband_fn`), and batched processing while maintaining backward compatibility.

Key technical changes in v2 include: added ungroup option override mechanism, stricter `BUG()` enforcement for mutually exclusive stdin methods, simplified post-rewrite and pre-push callbacks with strbuf reuse, reference-transaction callback redesign to match pre-push patterns, and removal of problematic keepalive logic in update hooks. The implementation spans `run-command.c` parallel process handling, `hook.c` API extensions, and conversions in `receive-pack.c`, `sequencer.c`, and `transport.c`.

Notable unresolved items from v1 feedback: file descriptor `0` vs `-1` convention remains unchanged due to `run-command.h` API constraints, and SIGPIPE handling stays outside `pp_buffer_stdin()` to avoid excessive calls. The series prepares for future work on config-based hooks and parallel execution by establishing consistent callback patterns and resource ownership rules (now explicitly documented for `feed_pipe_ctx`).

Testing shows some unrelated CI failures (Win+Meson and doc builds), with all hook-specific tests passing. Reviewers have largely approved the architectural approach, with remaining feedback addressed through callback simplifications and documentation improvements. The series appears ready for final review pending resolution of minor test failures in patch 6's sideband handling.
