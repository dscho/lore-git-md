Performance optimization follow-up for `git last-modified` algorithm.

Jeff King (peff) provides a small but thoughtful code review suggestion for Toon Claes' performance optimization work on the `git last-modified` command. The patch series aims to make the command faster by using generation-sorted commits and path activity bitmaps.

The specific suggestion relates to memory management of diff filepairs. Peff points out that the current patch manually frees individual filepairs before clearing the diff queue, while the queue's clear function would handle this cleanup automatically. He proposes removing the redundant free operations to make the code more idiomatic.

This is a minor refinement to an otherwise substantial performance improvement series that has seen detailed technical discussion about bitmap implementations, flag usage, and edge case handling. The thread has been productive, with multiple contributors analyzing the approach and identifying both correctness issues and optimization opportunities.
