Thread identity: Regression report for `git diff --quiet` behavior in v2.51.1, originating from Jake Zimmerman. Thread type: bug report.

Core problem: `git diff --quiet HEAD` incorrectly produces output for newly staged files in v2.51.1 when it should remain silent as documented, violating the `--quiet` flag's explicit requirement to "Disable all output of the program." The regression stems from commit b55e6d36eb ("diff: ensure consistent diff behavior with ignore options"), which also broke `-I` (ignore-matching-lines) functionality by allowing bogus output during content-diff applicability checks.

Current status: Jeff King (Peff) implemented a conservative fix redirecting output to /dev/null when `diff_from_contents` is active in quiet mode, now expanded to cover both `--quiet` and `-I` regressions by moving the `/dev/null` redirection into `diff_flush_patch_quietly()`. Junio Hamano has endorsed this approach for deployment to `maint` while leaving room for future optimization work. The solution maintains the dry-run optimization path while ensuring complete output suppression.

Key technical details:
- Affects `builtin/diff.c` and `diff.c` handling of `--quiet` and `-I` flags
- Regression occurs when comparing HEAD to index with newly staged files
- Original change triggered content-level diffs via `diff_from_contents` breaking both quiet mode and `-I` behavior
- Current solution forces /dev/null output via `DIFF_FORMAT_NO_OUTPUT` in `diff_flush_patch_quietly()`, covering both regression cases
- `dry_run` mode's `quick_consume()` preserved for performance but may become redundant
- `options->color_moved = 0` maintained as optimization for moved line detection
- `use_color` deemed irrelevant with `/dev/null` output
- Test coverage added via t4035, with style suggestion to use `test_must_be_empty`
- External diff programs correctly handle quiet mode via `cmd.no_stdout`
- Original commit b55e6d36eb had three components, with only the third (converting `--quiet` to use `dry_run`) causing regression
- Junio's latest refinement moves output suppression to cover both exit-status calculation loop and `--name-status` case

Open questions:
- Long-term viability of maintaining both safety mechanisms (`/dev/null` and `dry_run`)

- Need for additional guarding in `run_diff_cmd()` for unmerged paths
- Potential to simplify diff output control system by removing `dry_run` optimizations
- Final evaluation timeline for determining if `dry_run` infrastructure can be safely removed
