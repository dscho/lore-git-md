Thread identity: Regression report for `git diff --quiet` behavior in v2.51.1, originating from Jake Zimmerman. Thread type: bug report.

Core problem: `git diff --quiet HEAD` incorrectly produces output for newly staged files in v2.51.1 when it should remain silent as documented, violating the `--quiet` flag's explicit specification to "Disable all output of the program."

Current status: Jeff King (Peff) has proposed and implemented a conservative fix for the regression introduced by commit b55e6d36eb ("diff: ensure consistent diff behavior with ignore options"). The solution redirects output to /dev/null when `diff_from_contents` is active in quiet mode, restoring pre-regression behavior. A new test case in t4035 verifies the fix using `diff-tree -w` to trigger the underlying issue.

Key technical details:
- Affects `builtin/diff.c` and `diff.c` handling of `--quiet` flag
- Specifically manifests when comparing HEAD to index with newly staged files
- Regression occurred when porcelain diff's default `--ext-diff` setting triggered content-level diffs via `diff_from_contents`
- Original fix attempt using `dry_run` flag missed some output paths (creation/deletion diffs)
- Jeff's solution modifies `diff_flush` function's interaction with `DIFF_FORMAT_NO_OUTPUT` to force output to /dev/null
- External diff programs correctly handle quiet mode via existing `cmd.no_stdout` checks
- Test suite now includes coverage for this `git-diff` scenario via new t4035 test
