Thread identity: Regression report for `git diff --quiet` behavior in v2.51.1, originating from Jake Zimmerman. Thread type: bug report.

Core problem: `git diff --quiet HEAD` incorrectly produces output for newly staged files in v2.51.1 when it should remain silent as documented, violating the `--quiet` flag's explicit requirement to "Disable all output of the program." The regression stems from commit b55e6d36eb ("diff: ensure consistent diff behavior with ignore options").

Current status: Jeff King (Peff) has implemented and Junio C Hamano strongly endorses a conservative fix redirecting output to /dev/null when `diff_from_contents` is active in quiet mode, restoring pre-regression behavior. The solution modifies `diff_flush` to force /dev/null output with `DIFF_FORMAT_NO_OUTPUT` while maintaining exit status checking. Jeff now clarifies the relationship between this safety mechanism and the existing `dry_run` optimization infrastructure, proposing to maintain both approaches for correctness and performance. Lidong Yan suggests moving the `/dev/null` redirection logic to `diff_flush_patch_quiet()` for more uniform coverage, which Peff confirms would work while preserving the `dry_run` optimization path.

Key technical details:
- Affects `builtin/diff.c` and `diff.c` handling of `--quiet` flag
- Regression occurs when comparing HEAD to index with newly staged files
- Original change triggered content-level diffs via `diff_from_contents` breaking quiet mode
- Current solution forces /dev/null output via `DIFF_FORMAT_NO_OUTPUT` in `diff_flush` (or potentially `diff_flush_patch_quiet()`)
- `dry_run` mode's `quick_consume()` provides performance benefits by allowing low-level optimizations
- Original commit b55e6d36eb had three components, with only the third (converting `--quiet` to use `dry_run`) causing regression
- External diff programs correctly handle quiet mode via `cmd.no_stdout`
- Test coverage added via t4035
- Johannes Schindelin identified potential gaps in `run_diff_cmd()` for unmerged paths

Open questions:
- Whether to maintain both safety mechanisms (`/dev/null` and `dry_run`) long-term
- Need for additional guarding in `run_diff_cmd()` for unmerged paths
- Potential to simplify diff output control system in future
- Final placement of `/dev/null` redirection logic (`diff_flush` vs `diff_flush_patch_quiet`)
