Thread identity: Regression report for `git diff --quiet` behavior in v2.51.1, originating from Jake Zimmerman. Thread type: bug report.

Core problem: `git diff --quiet HEAD` incorrectly produces output for newly staged files in v2.51.1 when it should remain silent as documented, violating the `--quiet` flag's explicit requirement to "Disable all output of the program." The regression stems from commit b55e6d36eb ("diff: ensure consistent diff behavior with ignore options"), which also broke `-I` (ignore-matching-lines) functionality by allowing bogus output during content-diff applicability checks.

Current status: Junio Hamano has extended the fix to cover `--name-status` output paths while maintaining the core approach of `/dev/null` redirection with state restoration in `diff_flush()`. The solution now handles both `--quiet` and `--name-status` cases through unified state management in the main diff processing loop, though the maintainer continues to express concerns about the efficiency of per-path redirections. The implementation remains focused on correctness while leaving optimization opportunities for future work.

Key technical details:
- Affects `builtin/diff.c` and `diff.c` handling of `--quiet`, `-I`, and `--name-status` flags
- Regression occurs when comparing HEAD to index with newly staged files
- Solution forces /dev/null output via `DIFF_FORMAT_NO_OUTPUT` in main diff processing loop
- Extended to cover `DIFF_FORMAT_NAME_STATUS` path with same state preservation
- Current implementation saves/restores `o->file` and `o->color_moved` in `diff_flush()`
