Thread identity: Regression report for `git diff --quiet` behavior in v2.51.1, originating from Jake Zimmerman. Thread type: bug report with ongoing design discussion.

Core problem: `git diff --quiet HEAD` incorrectly produces output for newly staged files in v2.51.1 when it should remain silent as documented, violating the `--quiet` flag's explicit requirement to "Disable all output of the program." The regression stems from commit b55e6d36eb ("diff: ensure consistent diff behavior with ignore options"), which also broke `-I` (ignore-matching-lines) functionality by allowing bogus output during content-diff applicability checks.

Current status: The discussion has converged on a refined fix that moves `/dev/null` redirection inside the content-diff check loop while preserving output for actual diff generation. Junio Hamano has approved Jeff King's approach as appropriately scoped for a bugfix while leaving room for future architectural improvements. Recent discussion with Lidong Yan confirmed the necessity of per-iteration output suppression to maintain diff applicability checks. The solution elements:
- Maintains a single `dev_null` filehandle reused across iterations
- Preserves/restores `options->file` pointer around each quiet diff operation
- Keeps color_moved state restoration at outer scope
- Specifically targets `diff_from_contents` cases while allowing normal diff output for changed pairs
- Rejects alternative approaches that would break path-by-path diff format evaluation

Key technical details:
- Affects `builtin/diff.c` and `diff.c` handling of `--quiet`, `-I`, and `--name-status` flags
- Regression occurs when comparing HEAD to index with newly staged files
- Final fix approach:
  - Moves output suppression precisely around content-diff applicability checks
  - Preserves all diff options (file handle, color_moved, dry_run)
  - Solves t4013 test failures by proper output suppression scoping
  - Avoids broader changes to static filehandle caching
- Architectural considerations remain for future NULL-based approaches
- Both approaches must handle:
  - `o->file` destination management
  - `color_moved` state preservation
  - External diff program integration (`cmd.no_stdout`)
- Test coverage in t4035 with `test_must_be_empty` verification

Open questions:
