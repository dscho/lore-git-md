Thread identity: Regression report for `git diff --quiet` behavior in v2.51.1, originating from Jake Zimmerman. Thread type: bug report.

Core problem: `git diff --quiet HEAD` incorrectly produces output for newly staged files in v2.51.1 when it should remain silent as documented, violating the `--quiet` flag's explicit requirement to "Disable all output of the program." The regression stems from commit b55e6d36eb ("diff: ensure consistent diff behavior with ignore options"), which also broke `-I` (ignore-matching-lines) functionality by allowing bogus output during content-diff applicability checks.

Current status: Implementation of the fix is in final refinement stage with consensus on using `/dev/null` redirection in `diff_flush_patch_quietly()` to cover both `--quiet` and `-I` regressions. Jeff King (Peff) and Lidong Yan are working through edge cases in file handle and diff option restoration after redirection, with Junio Hamano now validating the state management approach. The solution preserves the existing dry-run optimization path while adding proper cleanup of `o->file` and `o->color_moved` state. Peff suggests potential future simplification for `master` where `o->color_moved` could be skipped during dry runs.

Key technical details:
- Affects `builtin/diff.c` and `diff.c` handling of `--quiet` and `-I` flags
- Regression occurs when comparing HEAD to index with newly staged files
- Solution forces /dev/null output via `DIFF_FORMAT_NO_OUTPUT` in `diff_flush_patch_quietly()`
- Requires careful restoration of `o->file` and `o->color_moved` after redirection, now under maintainer review
- Current implementation has awkward duplicate calls to quiet-flush helper due to loop structure
- `dry_run` mode's `quick_consume()` preserved but may become redundant
- Test coverage added in t4035 with `test_must_be_empty` verification
- External diff programs correctly handle quiet mode via `cmd.no_stdout`
- Original commit b55e6d36eb had three components, with only the third (converting `--quiet` to use `dry_run`) causing regression
