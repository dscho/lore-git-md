Thread identity: Regression report for `git diff --quiet` behavior in v2.51.1, originating from Jake Zimmerman. Thread type: bug report with ongoing design discussion.

Core problem: `git diff --quiet HEAD` incorrectly produces output for newly staged files in v2.51.1 when it should remain silent as documented, violating the `--quiet` flag's explicit requirement to "Disable all output of the program." The regression stems from commit b55e6d36eb ("diff: ensure consistent diff behavior with ignore options"), which also broke `-I` (ignore-matching-lines) functionality by allowing bogus output during content-diff applicability checks.

Current status: The discussion has progressed from architectural alternatives to concrete implementation fixes. Jeff King has refined his approach to use a static `/dev/null` filehandle cache within `diff_flush_patch_quietly()`, preserving diff options (file handle, color_moved state, dry_run flags) around quiet operations. This addresses Lidong Yan's t4013 test failures where `git show -w --name-status` incorrectly emitted diff headers. Jeff also raises a fundamental design question about whether `/dev/null` redirection could be replaced by NULLing `o->file` for more robust output suppression.

Key technical details:
- Affects `builtin/diff.c` and `diff.c` handling of `--quiet`, `-I`, and `--name-status` flags
- Regression occurs when comparing HEAD to index with newly staged files
- Jeff's refined fix:
  - Implements static `dev_null` FILE pointer cache in `diff_flush_patch_quietly()`
  - Preserves and restores all diff options (file handle, color_moved, dry_run)
  - Solves t4013 test failures by proper output suppression scoping
- Architectural considerations:
  - Potential long-term solution via NULLing `o->file` instead of redirection
  - Would fail visibly (via segfault) rather than silently produce wrong output
  - Requires careful handling of `dry_run` flag throughout diff machinery
- Both approaches must handle:
  - `o->file` destination management
  - `color_moved` state preservation
  - External diff program integration (`cmd.no_stdout`)
- Test coverage in t4035 with `test_must_be_empty` verification

Open questions:
- Tradeoffs between static filehandle cache vs NULL-based approach
- Long-term architectural direction for output suppression
- Verification of all file handle restoration paths
- Potential simplification via pre-flushing content diffs
- Streamlining `color_moved` during dry-run operations
