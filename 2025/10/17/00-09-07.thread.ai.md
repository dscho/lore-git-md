Thread identity: Regression report for `git diff --quiet` behavior in v2.51.1, originating from Jake Zimmerman. Thread type: bug report.

Core problem: `git diff --quiet HEAD` incorrectly produces output for newly staged files in v2.51.1 when it should remain silent as documented, violating the `--quiet` flag's explicit requirement to "Disable all output of the program." The regression stems from commit b55e6d36eb ("diff: ensure consistent diff behavior with ignore options").

Current status: Jeff King (Peff) implemented a conservative fix redirecting output to /dev/null when `diff_from_contents` is active in quiet mode, restoring pre-regression behavior. Junio Hamano now provides architectural guidance for deployment: the immediate fix will go to `maint` while leaving room for future optimization work. The solution modifies `diff_flush` to force /dev/null output with `DIFF_FORMAT_NO_OUTPUT`, making `diff_flush_patch_quietly()` redundant. The `dry_run` optimization infrastructure may eventually be removed if the `/dev/null` approach proves reliable, but will remain protected by a `NEEDSWORK` comment until thoroughly validated.

Key technical details:
- Affects `builtin/diff.c` and `diff.c` handling of `--quiet` flag
- Regression occurs when comparing HEAD to index with newly staged files
- Original change triggered content-level diffs via `diff_from_contents` breaking quiet mode
- Current solution forces /dev/null output via `DIFF_FORMAT_NO_OUTPUT` in `diff_flush`
- `dry_run` mode's `quick_consume()` provides performance benefits but may become redundant
- Original commit b55e6d36eb had three components, with only the third (converting `--quiet` to use `dry_run`) causing regression
- External diff programs correctly handle quiet mode via `cmd.no_stdout`
- Test coverage added via t4035
- Johannes Schindelin identified potential gaps in `run_diff_cmd()` for unmerged paths

Open questions:
