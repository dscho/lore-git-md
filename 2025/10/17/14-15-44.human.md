This is the final patch in a 10-part series converting Git's hook subsystem to a new callback-based API. It tackles the receive-pack hooks (update and post-update), completing the migration of all remaining hooks to the new system.

The patch replaces manual child process management in receive-pack.c with the standardized hook API, bringing benefits like automatic signal handling, built-in hook path discovery, and preparation for future configurable hooks. A key optimization batches hook input in 500-line chunks to avoid performance degradation from the run-command polling loop when processing many small inputs.

The implementation preserves existing sideband output behavior through a new `hook_output_to_sideband` helper and maintains sequential execution for these hooks. It carefully handles push certificates and options while cleaning up the previous custom process-spawning code. The series has seen steady progress through multiple versions, with this final patch representing the culmination of the hook API conversion work. Reviewers have generally approved the direction while noting some remaining edge cases to address.
