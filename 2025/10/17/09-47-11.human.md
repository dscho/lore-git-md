Bugfix for commit-graph corruption when using alternates with fetch.writeCommitGraph.

Philipp Hahn reports a segmentation fault that occurs when fetching into a repository that uses an alternate object store (via `--reference`) while `fetch.writeCommitGraph` is enabled. The crash happens when Git tries to write a new commit-graph after fetching, attempting to access a NULL tree object pointer.

The issue manifests after the alternate repository has been updated (in this case, after 14 days of upstream activity). The repository with alternates has commit-graph files referencing objects that may no longer exist in the updated alternate, leading to the crash when Git tries to write new graph data.

The expected behavior would be for Git to either:
1. Detect the missing commit-graph references and rebuild a complete new graph
2. Warn about incompatibility between alternates and commit-graphs
3. Recommend disabling `fetch.writeCommitGraph` for repositories used as alternates

The backtrace shows the crash occurs in `write_graph_chunk_data()` when trying to write a NULL tree hash. This appears to be a serious bug that could affect any repository using alternates with commit-graphs enabled. The reporter provides detailed reproduction steps and system information, making this a well-documented issue that warrants prompt attention from the commit-graph maintainers.
