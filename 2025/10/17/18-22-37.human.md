Bugfix for `git diff --quiet` regression in v2.51.1, with Junio Hamano's review.

This is Jeff King's proposed fix for the regression where `git diff --quiet` incorrectly produced output for newly staged files. The patch redirects diff output to /dev/null when in quiet mode with `diff_from_contents` active, restoring the documented silent behavior. Junio strongly endorses this conservative approach as it prioritizes correctness while being minimal for a regression fix.

The patch includes a test case in t4035 that verifies the fixed behavior when using `git diff-tree -w`. Junio notes this solution may allow future simplification by removing now-redundant dry-run mode handling, but agrees the current minimal fix is appropriate for stabilization.

Technical discussion confirms external diff programs are already properly silenced via `cmd.no_stdout`, making this additional protection layer safe. The fix touches core diff machinery in `diff.c` while maintaining the original optimization goals of the regression-causing commit. Junio suggests this may lead to broader simplifications in diff output control, though that work would come later.
