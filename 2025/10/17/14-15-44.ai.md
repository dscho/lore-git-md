Hook subsystem refactoring (final patch in series) - receive-pack hook conversion with performance optimization.

This is the 10th and final patch in v2 of the hook API refactoring series, converting receive-pack's hooks to use the new callback-based API. The patch focuses on the receive hooks while introducing a batching optimization to maintain performance.

Key technical changes:
- Replaces manual `child_process` setup with `run_hooks_opt` API
- Implements `feed_receive_hook_cb` to batch 500 lines of input at once, avoiding per-line overhead in run-command's ppoll loop
- Maintains sideband output via `hook_output_to_sideband` callback
- Preserves push certificate handling by moving env setup to `prepare_push_cert_sha1`
- Keeps sequential execution (`processes=1`) for compatibility
- Adds proper cleanup of hook state data

The patch addresses a performance regression discovered when processing large hook inputs line-by-line. The 500-line batching maintains throughput while keeping the conversion transparent to hook implementations. The changes follow the series pattern of thin wrapper APIs over run-command functionality.

This completes the receive-pack hook conversions after previous patches handled update/post-update hooks (9/10). The implementation remains focused on receive-pack.c without modifying core hook infrastructure. Test coverage appears limited to the batching mechanism itself rather than receive-pack-specific cases.

Open items from earlier in the series (fd conventions, test failures, parallel execution) remain unaddressed here as they're outside this patch's scope. The change appears well-contained and builds on established patterns from prior conversions in the series.
