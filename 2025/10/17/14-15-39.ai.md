This is patch 5/10 in the hook subsystem refactoring series, converting the reference-transaction hook to use the new callback-based API. The patch focuses on `refs.c`, replacing manual `child_process` setup with a `transaction_hook_feed_stdin` callback that processes one update per call.

Key technical details: The new implementation introduces a `transaction_feed_cb_data` struct to track state across callback invocations, using a `strbuf` to format each ref update (handling both OID and symbolic ref cases). The callback skips `REF_LOG_ONLY` updates and maintains EPIPE error semantics without explicit SIGPIPE handling. The conversion removes 48 lines of process management code while adding 53 lines of callback logic, following the pattern established in earlier patches.

Behavior changes are minimal - the hook still receives the same ref update data, just via the new streaming mechanism. The commit notes potential for batching updates (though currently processing one per call) and mentions no observed performance degradation. Testing relies on existing reference-transaction hook tests rather than adding new ones.

This continues the series' technical progression by applying the callback pattern to another hook type, further eliminating manual process/signal handling while maintaining the same core functionality. The patch appears well-structured with clear data flow between the hook runner and callback, though reviewers may want to verify the EPIPE handling matches the old behavior exactly.
