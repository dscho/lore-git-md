This is a feature patch introducing a new `commitGraph.changedPaths` config option for controlling Bloom filter behavior in commit-graph writes, with specific application to large monorepos like Microsoft's Office repository.

Emily Yang (a new contributor) proposes adding persistent configuration option for changed-path Bloom filters, which currently require explicit `--changed-paths` flags. The config has three states: `true` enables filter writing (like `--changed-paths`), `false`/unset preserves existing filters without adding new ones, and command-line flags always take precedence. The patch includes thorough documentation updates and test coverage in t5318-commit-graph.sh.

The change is motivated by Microsoft Office monorepo needs, where background maintenance could benefit from this persistent setting. The patch builds on prior discussion about config vs flag behavior, with Derrick Stolee providing guidance. The implementation is clean, with clear docs explaining the subtle difference between config `false` (preserves) vs `--no-changed-paths` (removes) behaviors.
