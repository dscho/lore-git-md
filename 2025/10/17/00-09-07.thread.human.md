This thread addresses a regression in Git v2.51.1 where `git diff --quiet HEAD` incorrectly produced output for newly staged files, violating the documented behavior of the `--quiet` flag. The issue stems from commit b55e6d36eb, which changed how diff handles ignore options.

Jeff King (Peff) has implemented a fix that redirects output to /dev/null when in quiet mode, restoring the expected silent behavior while maintaining proper exit status checking. The solution preserves both correctness and performance by keeping the existing `dry_run` optimization path that uses `quick_consume()`. Junio C Hamano strongly supports this approach.

In the latest exchange, Lidong Yan suggested moving the output suppression logic to `diff_flush_patch_quiet()` for more uniform coverage. Peff agrees this would work and is conceptually reasonable, though his original patch maintained the pre-regression code location. The discussion confirms the need for both safety mechanisms (output suppression) and performance optimizations (`dry_run`), with consensus forming around Yan's suggested refactoring while keeping all existing functionality.

The fix has test coverage in t4035, and while some edge cases around unmerged paths were noted by Johannes Schindelin, the core solution is ready for merging with potential follow-ups for optimizations and additional guarding.
