Jake Zimmerman reported a regression in Git 2.51.1 where `git diff --quiet HEAD` incorrectly produced output for newly staged files, violating the documented behavior of the `--quiet` flag. Jeff King (Peff) quickly identified the cause in commit b55e6d36eb and implemented a conservative fix that forces output to /dev/null in quiet mode, restoring the expected behavior. Junio Hamano has endorsed this approach, with the immediate fix going to the maint branch while leaving room for future optimization work.

The discussion has now turned to implementation details. Johannes Schindelin has raised questions about some protective measures in the fix, particularly the unexplained zeroing of `color_moved` settings. He suggests using GitHub's CodeQL for systematic analysis of all potential output paths during quiet mode, sharing a complex query he developed that currently only flags the `run_diff_cmd()` path. While the core fix remains uncontested, Schindelin is pushing for more rigorous validation and documentation of the solution's components, as well as advocating for automated tools to maintain consistency. A minor style inconsistency in the test code was also noted, with a recommendation to use `test_must_be_empty` instead of explicit line counting. The thread shows the project's characteristic attention to both immediate correctness and long-term maintainability.
