This thread addresses a regression in `git diff --quiet` behavior in Git v2.51.1, where the command incorrectly produces output for newly staged files despite the `--quiet` flag's documented promise of silence. Jake Zimmerman originally reported the issue with bisect results pinpointing commit b55e6d36eb as the culprit. Jeff King (Peff) responded with a conservative fix that redirects output to /dev/null when `diff_from_contents` is active in quiet mode, restoring the expected behavior. A new test in t4035 verifies the solution.

Johannes Schindelin has now contributed a deeper analysis of the fix's coverage, identifying potential gaps where the `dry_run` flag might not fully suppress output. While most cases appear harmless, he notes that `run_diff_cmd()`'s handling of unmerged paths could still leak output, suggesting the fix may need refinement. The discussion remains technical and focused on correctness, with participants weighing whether to merge the current solution as a stopgap or pursue more comprehensive changes to the diff machinery's quiet mode handling. The thread demonstrates Git's careful approach to regression fixes, balancing immediate correctness against future maintainability.
