Review feedback on SSH fingerprint parsing conversion.

Christian Couder responds to Junio Hamano's technical question about the patch converting `strbuf_split_max()` to `string_list_split()` in SSH key fingerprint parsing. The key issue is whether the original code's lenient acceptance of 2-token output (rather than requiring 3 tokens) was intentional or should be tightened.

Couder analyzes the expected `ssh-keygen -l` output format (key size, fingerprint hash, and optional key comment) and concludes the stricter 3-token check is actually correct, though the patch could alternatively preserve the original lenient behavior by checking for `> 1` instead. He notes the commit message should better explain this validation logic.

This continues the thread's focus on carefully preserving behavior while modernizing string splitting APIs in security-sensitive code. The exchange highlights the importance of documenting validation expectations when changing parsing code, even in mechanical conversions. No resolution yet on whether to keep the stricter check or revert to the original behavior.
