This is the first patch in Adrian Ratiu and Emily Shaffer's v2 series refactoring Git's hook subsystem. It introduces a new stdin callback mechanism for parallel processes, laying groundwork for modernizing hook infrastructure.

The patch adds a `feed_pipe_fn` callback to `run_processes_parallel()`, allowing callers to incrementally feed input to child processes' stdin pipes rather than buffering everything at once. This solves memory and pipe buffer limitations when processing large inputs. The implementation handles pipe feeding, cleanup, and SIGPIPE signals consistently across parallel processes.

Key changes include:
- New `pp_buffer_stdin()` helper to manage stdin feeding
- Consolidated I/O handling in `pp_handle_child_IO()`
- SIGPIPE handling during parallel execution
- Test coverage for stdin feeding behavior

The patch appears well-constructed with thorough test coverage. It's a foundational change enabling the hook conversion work that follows, addressing a real limitation in the parallel process API while maintaining backward compatibility. The commit message clearly explains the motivation and relates it to existing code (the pre-push hook implementation in transport.c).
