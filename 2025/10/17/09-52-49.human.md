This is a follow-up in the ongoing discussion about SSH agent test failures in `t7528-signed-commit-ssh.sh`. Lauri Tirkkonen provides historical context explaining why the space-handling issue in test paths only recently became apparent.

The key insight is that OpenSSH changed its default socket location behavior in version 10.1 (2020), moving from `/tmp` to `$HOME/.ssh`. This explains why the space-handling problem in test paths wasn't caught earlier - older OpenSSH versions would create sockets in `/tmp` by default, avoiding the space-containing `$HOME` path entirely.

Tirkkonen shares a real-world example from Alpine Linux's CI, where they worked around the issue by using `ssh-agent -T` to force the socket into `/tmp`. However, as noted, this solution wouldn't work for systems running pre-10.1 OpenSSH versions.

This email helps explain the test's surprising resilience to the space-handling bug and provides useful context about when and why the issue manifests. The information about Alpine's workaround may inform potential solutions, though the discussion about backward compatibility with older OpenSSH versions suggests a more comprehensive fix may be needed.
