This thread discusses a surprising behavior in Git's `protocol.file.allow` configuration when working with submodules. The original report found that setting `protocol.file.allow=always` in a repository's local config doesn't enable file protocol access for submodule operations, while the same setting works when applied globally. Jeff King (Peff) clarified that this is expected behavior - when Git clones a submodule, it creates a new repository that doesn't inherit the parent's local configuration. 

Peff confirmed this is a known limitation with architectural roots, explaining that while some configuration inheritance from superprojects to submodules has been discussed, it's non-trivial to determine which settings should propagate. He suggested two practical workarounds: either use the global configuration or pass the setting via command-line with `-c protocol.file.allow=always`. The response indicates this behavior is unlikely to change in the near term, as it reflects a deliberate (if sometimes unintuitive) design choice about configuration scoping in submodule operations.
