This thread examines the behavior of `protocol.file.allow` configuration in submodule operations, where local settings don't propagate as users might expect. Jeff King clarified that this is intentional - when creating submodules via `git-clone`, the parent repository's local configuration isn't inherited, meaning `protocol.file.allow=always` set locally won't enable file protocol access for submodule operations. He offered workarounds using global config or command-line options.

A follow-up from fence.borrowing375@passmail.net has shifted focus to documentation gaps. While accepting the technical explanation, they note the git-submodule manpage doesn't clearly state that local config is generally ignored during submodule operations, even though it mentions some exceptions. This creates confusion when users expect consistent behavior across different submodule commands. The discussion now considers whether protocol-related settings would be appropriate for inheritance if the behavior were to change, while acknowledging the deeper architectural challenges around selective config propagation. The immediate action item appears to be improving documentation to set clearer expectations, even if the underlying technical behavior remains unchanged.
