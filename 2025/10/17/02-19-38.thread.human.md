This thread reports a bug in Git's handling of the `protocol.file.allow` configuration when applied at repository scope versus globally. The reporter demonstrates that setting `protocol.file.allow=always` locally fails to enable file protocol access for submodule operations (`submodule add` and `submodule update`), while the same setting works as expected when applied globally. 

The issue affects Git versions 2.39.5 through 2.51.1 and has security implications - users cannot properly implement granular security policies where file protocol access is restricted system-wide but enabled for specific repositories. The reporter provides clear reproduction steps showing the inconsistent behavior between local and global configurations. This appears to be a legitimate bug in how Git processes the protocol.file.allow setting at different configuration scopes during submodule operations.
