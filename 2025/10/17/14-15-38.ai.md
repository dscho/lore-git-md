Hook subsystem refactoring (part 4/10) converting the pre-push hook to the new callback-based API. This patch follows the established pattern from earlier in the series, moving the pre-push hook implementation in `transport.c` from manual child process management to the new `run_hooks_opt` infrastructure.

The key changes replace the direct `child_process` setup with a `pre_push_hook_feed_stdin` callback that handles ref data streaming via the new `feed_pipe` mechanism. The callback filters refs that shouldn't be processed (REJECT_NONFASTFORWARD, UPTODATE, etc.) and formats them into the hook's stdin using a strbuf. The implementation maintains the same behavior of ignoring EPIPE errors when the hook doesn't read all input.

The conversion eliminates 46 lines of manual process and signal handling code while adding 37 lines of callback-based implementation. Like previous conversions in the series, this removes explicit SIGPIPE management while keeping the same error handling semantics. The patch demonstrates the series' pattern of moving hook-specific logic into focused callbacks while centralizing process management in the hook API.

Testing appears covered by existing pre-push hook tests, though the patch doesn't add new test cases. The implementation follows the same approach as the post-rewrite hook conversion in patch 3/10, suggesting the architectural pattern is now well-defined for the series.
