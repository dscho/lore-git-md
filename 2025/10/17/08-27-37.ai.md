This is part 8 of Adrian Ratiu's hook subsystem refactoring series, focusing on converting receive-pack's 'update` hook to use the new `hook.h` infrastructure. The patch introduces sideband output handling via a new `hook_output_to_sideband` callback, replacing direct child process management with the unified `run_hooks_opt` API.

Key technical elements include:
- New `hook_output_to_sideband` callback function with keepalive handling (currently implementing three modes: never, always, after-NUL)
- Maintains same hook arguments (refname, old_oid, new_oid) through `run_hooks_opt.args`
- Removes direct child process management in favor of the new hook API
- The main discussion point is around the newly introduced keepalive functionality, which wasn't present in the original implementation. Emily Shaffer raised concerns about this being an undocumented behavior change that might affect sideband consumers not expecting keepalive packets. Adrian acknowledges this as a valid concern and plans to remove the keepalive functionality in v2 since it's unnecessary for this short-lived hook.

The patch represents a significant architectural shift in how the update hook is handled, moving it into the unified hook processing framework while maintaining the same external behavior (minus the keepalive change that will be reverted). The implementation appears technically sound but needs this one behavior adjustment to avoid introducing undocumented side effects.

This continues the series' pattern of methodically converting individual hooks to the new system while addressing reviewer feedback - in this case recognizing and correcting an overreach in functionality that wasn't part of the original hook contract. The resolution path is clear (removing keepalive) and doesn't appear to require deeper architectural changes.
