This thread explores whether `git grep` should ignore binary files by default, evolving into a broader discussion about attribute-based file exclusion. The original proposal from Eloy suggested a binary-specific config, but Junio Hamano opposed this as too narrow, instead endorsing Jeff King's 2012 "filetype" concept for more flexible attribute-based filtering. While this approach could handle binaries alongside other exclusions (like generated files), concerns remain about implementation complexity and script compatibility.

Key participants have highlighted competing needs: Brian m. carlson and Randall S. Becker provided real-world examples where binary file searching is necessary (legal compliance, SQL environments), while others argue most users would benefit from skipping binaries by default. Thomas Braun's latest contribution underscores the tension between convenience and compatibility, questioning whether even an attribute-based solution would fully resolve environment inconsistencies. The thread has identified technical challenges around quasi-binary files (PostScript, PDFs with searchable content) and the potential difficulty of implementing a comprehensive attribute system now versus in 2012.

The discussion remains unresolved but has shifted toward finding a general mechanism that could satisfy both binary exclusion needs and compatibility requirements, though no clear implementation path has yet emerged that addresses all concerns.
