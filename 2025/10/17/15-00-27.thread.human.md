This thread explores whether `git grep` should ignore binary files by default, a proposal that has evolved into a broader discussion about file filtering mechanisms. The original suggestion from Eloy to add binary-specific configuration has met resistance from maintainer Junio Hamano and others concerned about breaking existing scripts. Jeff King's 2012 "filetype" proposal for attribute-based filtering has emerged as a promising alternative that could handle binary files alongside other exclusions without compatibility risks.

Current discussion focuses on balancing flexibility with stability. While attribute-based approaches (using existing `:(attr:)` syntax) offer more power, they require more configuration than a simple boolean flag. Eloy's latest response acknowledges the compatibility concerns, suggesting a `--porcelain` flag for scripts and an override mechanism while still advocating for some form of exclusion capability. Key participants remain divided - Junio and Thomas Braun emphasize script safety, while Eloy and others want better ergonomics for interactive use. The thread shows movement toward configurable solutions rather than default changes, but the exact implementation path remains unclear, with tradeoffs between simple configuration options and more flexible attribute-based approaches still being weighed.
