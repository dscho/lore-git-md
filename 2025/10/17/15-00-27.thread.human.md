This thread explores making `git grep` more configurable in how it filters files, originally sparked by Eloy's proposal to ignore binary files by default. After pushback from Junio and others about compatibility risks with default changes, the discussion shifted toward attribute-based solutions that users could opt into. Jeff King (Peff) has now proposed a concrete implementation using Git's existing pathspec machinery, suggesting a `grep.defaultpathspec` config that would apply only when no explicit pathspec is given—preserving backward compatibility for scripts while allowing per-user customization.

Key participants include Eloy (original proposer), Junio (maintainer emphasizing compatibility), and Peff (providing technical alternatives). The current direction favors Peff's approach of configurable pathspec defaults over changing `git grep`'s core behavior. This satisfies use cases like excluding translation files or binary data while ensuring scripts continue working unchanged. The proposal builds on earlier discussions about attribute filtering but avoids introducing new mechanisms by leveraging Git's well-tested pathspec system instead. While some interface questions remain, this represents a practical path forward that aligns with the project's compatibility-first ethos.
