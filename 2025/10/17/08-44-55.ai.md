Bugfix for consistent color handling in `git status --short -z` output.

This patch finalizes the resolution of an inconsistency in Git's status output coloring when using the `-z --short` combination. The fix ensures untracked file markers (`??`) are colored consistently with modified file markers (`M`), aligning with the documented behavior where `--short` maintains human-readable colors while `--porcelain` suppresses them.

The technical change moves the color application in `wt_shortstatus_other()` (in `wt-status.c`) to occur before the null-termination check, matching the pattern already used in `wt_shortstatus_unmerged()`. This maintains the unusual but intentional behavior where `-z --short` produces colored output with NUL separators, useful for scenarios where the output will be shown to humans outside a terminal.

The patch includes a new test case in `t/t7508-status.sh` that verifies color preservation by converting NULs to newlines for comparison with existing test expectations. Jeff King provides thorough rationale in the commit message, clarifying that while `-z` typically indicates machine-readable output, the explicit `--short` flag overrides this to request human-readable formatting.
