This thread reports a segmentation fault that occurs when writing commit-graphs in repositories configured with alternate object stores, particularly after the referenced repository's commit-graph files become inaccessible. The original report describes the crash happening in `write_graph_chunk_data()` during commit-graph generation when processing NULL tree hashes, with reproduction steps involving repositories cloned with `--reference` when upstream commit-graphs are removed.

Kristoffer Haugsbakk has since clarified that the German message "Warnung: konnte nicht alle Commit-Graph-Dateien finden" seen in the error path translates to "unable to find all commit-graph files" in English. This warning appears before the eventual segfault when commit-graph files in alternate repositories are missing. The core issue remains unresolved - the thread is still awaiting maintainer feedback or proposed patches to address the NULL pointer dereference during commit-graph writing with alternates.
