Bug report regarding inconsistent behavior of `protocol.file.allow` configuration between local and global scopes, affecting submodule operations. The core issue is that setting `protocol.file.allow=always` locally fails to enable file protocol access for `git submodule add` and `git submodule update` commands, while the same setting works when applied globally. Jeff King explains this is because submodule creation via `git-clone` doesn't inherit the parent repository's local configuration, confirming it as a known limitation rather than a bug. He provides two workarounds: using global config or passing the setting via `-c protocol.file.allow=always` command-line option. The response notes this has deeper architectural implications - while some configs should propagate to submodules, others shouldn't, making inheritance non-trivial. Technical details confirm the behavior stems from `git-clone` not seeing parent repo local config during submodule creation. The thread establishes this is unlikely to change soon, leaving users with the provided workarounds for enabling file protocol access in specific submodule operations while maintaining system-wide restrictions.
