This is part 9/10 of the hook subsystem refactoring series, converting the receive-pack update and post-update hooks to use the new callback-based API. The patch replaces direct `child_process` handling with the standardized `run_hooks_opt` interface, while maintaining the existing sideband output functionality through a new `hook_output_to_sideband` callback.

The changes simplify the hook execution code in receive-pack.c by removing about 40 lines of manual process setup and teardown. The implementation now uses the parallel-capable hook infrastructure (though still running sequentially for now) and properly integrates with the sideband output system introduced in earlier patches. The conversion follows the pattern seen in previous hook migrations in this series.

This appears to be a straightforward mechanical conversion that maintains all existing behavior while moving toward the series' goal of unified hook handling. The patch is well-contained, touching only receive-pack.c, and includes sign-offs from both the primary authors and a previous reviewer (Ævar). As with other patches in this series, it builds on the established hook API while leaving room for future parallel execution.
