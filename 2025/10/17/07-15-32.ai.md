This is a response in the ongoing thread about `protocol.file.allow` behavior in submodule operations. Jeff King explains why setting `protocol.file.allow=always` locally doesn't work for submodule operations - when Git clones a submodule, it creates a new repository that doesn't inherit the parent repository's local configuration. He confirms the reporter's observation that global configuration works, and suggests two alternative approaches: using the global config or passing the setting via command-line with `-c`. 

The response also notes this is a known limitation with deeper architectural implications - there have been discussions about inheriting superproject config in submodules, but it's complicated by the fact that some configs should propagate while others shouldn't. Jeff indicates this behavior is unlikely to change soon, suggesting users will need to work around it with the provided alternatives.

Key technical details for future reference: the issue stems from submodule creation being handled by `git-clone` which doesn't see the local config of the parent repository, and the suggested workarounds are either global config or the `-c protocol.file.allow=always` command-line option. The response implies this is a deliberate design choice rather than a bug, though one that may be unintuitive to users.
