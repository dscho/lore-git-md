This is a discussion about future hook support for `git replay`, following up on Kristoffer Haugsbakk's proposal for a `--format` option to better integrate with post-rewrite hooks.

Elijah Newren cautions against rushing to add hook support to `git replay`, drawing lessons from how hooks constrained `git rebase`'s implementation. He notes that while post-rewrite seems more reasonable than other hooks, any hook integration creates long-term API constraints. The current focus remains on server-side atomic updates, and while client-side features like hook support will be needed eventually, it's too early to commit to specific hook implementations that might limit future design flexibility.

The email reinforces the project's current priorities for `git replay` (atomic ref updates, server-side workflows) while acknowledging the eventual need for client-side features. Newren's perspective as a rebase expert carries weight here, suggesting the team should proceed carefully to avoid the same architectural constraints that affected rebase. The discussion shows the project balancing immediate needs against long-term maintainability concerns.
