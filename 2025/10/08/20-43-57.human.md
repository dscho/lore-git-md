This is a small refactoring patch in the ongoing packfile store API cleanup series. Taylor Blau is responding to Patrick Steinhardt's patch that simplifies packfile loading in `git grep`'s threaded mode.

The change replaces an indirect call to `packfile_store_get_packs()` (which loads packs and returns the first one) with a direct call to `packfile_store_prepare()` since the grep code only cares about the pack loading side effect, not the return value. This is a straightforward cleanup that aligns with the series' goal of simplifying pack iteration patterns.

Taylor confirms the technical soundness of the change, noting that the original function was just a wrapper that called `packfile_store_prepare()` anyway. The patch is minimal (just one line changed) and maintains the same behavior while making the intent clearer. This appears to be a non-controversial improvement that fits well with the broader API refactoring effort.
