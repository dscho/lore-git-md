This is a follow-up in the ongoing security proposal discussion about preventing arbitrary code execution in untrusted repositories. Michael Lohmann responds to Taylor Blau's clarification about nested bare repositories in the token-based security approach.

Michael confirms that submodules would need their own tokens in their `.git/modules/` directories to maintain security, and suggests these could be automatically signed during a `--recursive` clone operation. This addresses Taylor's concern about whether parent repository tokens would be respected in nested scenarios (they wouldn't, maintaining security boundaries).

The exchange highlights an implementation detail of the token proposal - each submodule would require its own verification token, which could be automatically handled during recursive operations. This maintains the security model where every repository operation requires explicit trust, even for nested cases. The response is technical but brief, focusing specifically on the submodule case without expanding on other aspects of the broader security discussion.
