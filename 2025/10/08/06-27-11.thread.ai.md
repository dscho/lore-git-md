CI infrastructure improvements for Rust support (v3 series by Patrick Steinhardt). This 6-patch series enhances Git's Rust development workflow with static analysis, Windows compatibility, and minimum version verification, building on prior Rustification work. Key changes:

1. CI optimization by removing redundant apt-get update calls - implemented with cleanup of duplicate package index refreshes in ci/install-dependencies.sh affecting ClangFormat, StaticAnalysis, sparse, and Documentation jobs
2. Rust code formatting enforcement via cargo fmt (defaulting to 100-column width, open to discussion) - adds new RustAnalysis jobs to GitHub Actions/GitLab CI, installs rustup/rustfmt via ci/install-dependencies.sh, and implements formatting verification in new ci/run-rust-checks.sh script
3. Added safety documentation for Rust FFI functions `decode_varint()` and `encode_varint()` in src/varint.rs, including behavior descriptions, `# Safety` sections specifying preconditions (NUL-terminated buffer for decoding, minimum buffer size for encoding), and edge case notes. Follows Rust conventions while maintaining C interface requirements, with guidance from "brian m. carlson"
4. Clippy linting integration - adds clippy installation to RustAnalysis job in ci/install-dependencies.sh and implements strict lint checking via `cargo clippy -Dwarnings` in ci/run-rust-checks.sh. Uses default Clippy configuration consistent with series' approach to Rust tooling
5. Minimum supported Rust version verification - establishes Rust 1.49.0 as MSRV for Git's Rust code and dependencies, chosen for compatibility with older toolchains including potential alternatives like gccrs. Implements through three key changes: adding `rust-version` field to Cargo.toml, installing cargo-msrv 0.18.4 (Ubuntu-compatible version) during CI setup, and adding MSRV verification to Rust checks pipeline. Downloads and installs cargo-msrv as binary during RustAnalysis job setup, placing it in custom PATH location. New check runs `cargo msrv verify` to validate all dependencies satisfy 1.49.0 requirement
6. Windows build support - final patch addressing platform-specific requirements: links against `userenv.dll` for `GetUserProfileDirectoryW()` dependency, handles Windows library naming conventions (`gitcore.lib` vs `libgitcore.a`) via platform-specific logic in Makefile and `cargo-meson.sh`, and enables Rust testing on Windows CI runners through toolchain installation in GitLab Windows job. Builds on prior Windows compatibility work by Johannes Schindelin and Ezekiel Newren, completing series goal of cross-platform Rust infrastructure. Changes limited to build system adjustments without core Rust modifications, maintaining low-risk profile

Technical scope includes modifications to .github/workflows/main.yml, .gitlab-ci.yml, Makefile, and meson.build, plus new ci/run-rust-checks.sh script. The series maintains backward compatibility while adding Rust-specific infrastructure. V3 incorporates prior feedback on comments and commit messages, with the column width preference remaining an open question. Changes systematically address Rust development needs from formatting to cross-platform support, starting with low-risk CI optimizations. The MSRV patch (5/6) follows the series' pattern of using standard Rust tooling (cargo-msrv) rather than custom solutions, and pins tool versions for reproducibility. Choice of Rust 1.49.0 reflects conservative stance on version requirements during early Rust adoption phase. Safety documentation (3/6) remains purely additive while improving auditability of unsafe FFI operations. Clippy integration (4/6) completes static analysis suite with strict warning enforcement, maintaining Git's CI standards for Rust code quality. Windows support (6/6) closes last major platform gap through targeted build system changes validated by CI enablement.
