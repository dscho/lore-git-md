CI infrastructure improvements for Rust support (v2 series by Patrick Steinhardt). This 6-patch series enhances Git's Rust development workflow with static analysis and Windows compatibility, building on prior Rustification work. Key changes:

1. CI optimization by removing redundant apt-get update calls - now implemented in v2 with cleanup of duplicate package index refreshes in ci/install-dependencies.sh affecting ClangFormat, StaticAnalysis, sparse, and Documentation jobs
2. Rust code formatting enforcement via cargo fmt (defaulting to 100-column width, open to discussion) - adds new RustAnalysis jobs to GitHub Actions/GitLab CI, installs rustup/rustfmt via ci/install-dependencies.sh, and implements formatting verification in new ci/run-rust-checks.sh script
3. Added safety documentation for Rust FFI functions `decode_varint()` and `encode_varint()` in src/varint.rs, including behavior descriptions, `# Safety` sections specifying preconditions (NUL-terminated buffer for decoding, minimum buffer size for encoding), and edge case notes. This anticipates upcoming Clippy integration (patch 4/6) and follows Rust conventions while maintaining C interface requirements, with guidance from "brian m. carlson".
4. Clippy linting integration - adds clippy installation to RustAnalysis job in ci/install-dependencies.sh and implements strict lint checking via `cargo clippy -Dwarnings` in ci/run-rust-checks.sh. Uses default Clippy configuration consistent with series' approach to Rust tooling, building on infrastructure from earlier patches. No production code changes - purely static analysis enhancement.
5. Minimum supported Rust version verification
6. Windows build support

Technical scope includes modifications to .github/workflows/main.yml, .gitlab-ci.yml, Makefile, and meson.build, plus new ci/run-rust-checks.sh script. The series maintains backward compatibility while adding Rust-specific infrastructure. V2 incorporates prior feedback on comments and commit messages, with the column width preference remaining an open question. The changes systematically address Rust development needs from formatting to cross-platform support, starting with this low-risk but measurable CI optimization that reduces redundant network operations during test runs. The formatting enforcement patch follows Rust ecosystem conventions by using rustfmt's default style rather than custom rules, mirroring Git's existing static analysis approach for Rust code. The safety documentation patch (3/6) is purely additive and maintains existing behavior while improving auditability of unsafe FFI operations. The Clippy integration (4/6) completes the static analysis suite with strict warning enforcement, maintaining Git's CI standards for Rust code quality.
