This is a refactoring and bugfix patch in a series modernizing Git's tag peeling behavior. It introduces a new flag to verify object types during peeling, addressing a subtle issue where tag objects could incorrectly report the type of their tagged objects.

The patch adds `PEEL_OBJECT_VERIFY_OBJECT_TYPE` to `peel_object()`, allowing callers to opt into strict type verification when peeling tags. Currently, Git may accept incorrect object types from tags when the objects aren't already cached, which could lead to subtle bugs. The change inlines and removes the `deref_tag_noverify()` function since its functionality is now covered by the new flag.

Key technical changes include:
- Adding the new flag to `enum peel_object_flags`
- Modifying `peel_object()` to verify types when requested
- Updating callers in ref-filter, refs backends, and test helpers
- Removing now-unnecessary `deref_tag_noverify()` function and its declaration

This is part of a larger series that has already received extensive review, with patches 1-7 confirmed merge-ready by Junio Hamano. The change maintains backward compatibility while adding stricter verification where needed, and follows the series' pattern of cleaning up technical debt in the refs subsystem.
