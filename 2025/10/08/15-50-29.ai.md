Performance optimization patch completing a ref-filter modernization series. This is the final patch (14/14) in Patrick Steinhardt's series that has been reviewed and deemed merge-ready by Junio Hamano and Taylor Blau. The series modernizes Git's ref iteration and tag peeling infrastructure while enforcing consistent tag verification.

This specific patch optimizes `git-for-each-ref` by making object parsing lazy - it only parses objects when an atom actually needs the parsed data, rather than always parsing up front. The change shows a measurable 13% speedup in the Chromium repository benchmark (344.7ms vs 388.7ms). The implementation introduces a new `get_or_parse_object()` helper that handles the lazy parsing, and modifies the various value-grabbing functions (`grab_tag_values`, `grab_commit_values`, etc.) to only parse when needed.

Key technical details:
- Adds `maybe_object` field to `struct expand_data` to cache parsed objects
- Introduces `get_or_parse_object()` helper that conditionally parses objects
- Modifies all value extraction functions to use lazy parsing
- Maintains existing behavior while reducing unnecessary object parsing
- Updates error handling to propagate parsing failures
- Preserves the performance gains demonstrated in earlier series patches

The change completes the series' goals by:
1. Removing the last performance bottleneck (unnecessary object parsing)
2. Maintaining all the verification improvements from earlier patches
3. Keeping the API clean and more efficient
4. Demonstrating measurable speedups in real-world use cases

With this patch, the series achieves its objectives of modernizing the infrastructure while improving both correctness (through consistent verification) and performance. The changes are well-contained to ref-filter.c and build logically on the prior patches in the series.
