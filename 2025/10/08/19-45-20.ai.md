This is a documentation patch that adds warnings about the potential pitfalls of using `--committer-date-is-author-date` in both `git-am` and `git-rebase`. The option, which was originally added to help maintain consistent commit IDs when importing patches via email, can create commit histories that violate Git's assumption of strictly increasing commit timestamps.

The patch updates the man pages to explicitly warn users that this option should only be used when applying commits on top of a base that is older than the patches being applied. It references Git's revision walking machinery's expectations about timestamp ordering and includes a note about clock skew tolerance.

The commit message provides historical context, tracing the option's origin to a 2009 patch where it was used to ensure consistent SHA-1 sums when re-importing patches. The author notes that while the option has legitimate uses in `git-am`, its application in `git-rebase` may be more questionable since rebasing inherently creates new commit IDs anyway.

The changes are purely documentation-focused, adding warning notes while preserving the existing option descriptions. The patch appears well-researched, with references to mailing list discussions and prior work, though it doesn't fundamentally change the behavior of the commands.
