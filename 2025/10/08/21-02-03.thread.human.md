This thread discusses a security proposal to prevent arbitrary code execution in untrusted repositories by introducing per-user secret tokens that would be verified before executing user-defined code like hooks. The original proposal suggested storing tokens in ~/.gitsecret and copying them during `git init`/`git clone`, with a phased migration plan.

Taylor Blau has raised an important concern about how this system would handle submodules. The key issue is whether tokens would propagate to recursively cloned submodules - if not, users would still need to manually verify submodules, which would undermine the proposal's goal of eliminating trust prompts. This exposes a gap in the original claim to maintain all existing functionality while improving security. The discussion now needs to address how the token system should handle transitive trust relationships in submodule graphs, as this will significantly impact both the security model and user experience. The thread remains open on this critical technical detail that could shape the proposal's viability.
