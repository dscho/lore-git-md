This is the 13th patch in a 14-part series refactoring Git's tag peeling behavior, focusing on fixing a subtle bug in tag verification. The patch ensures `git-for-each-ref` properly detects corrupted tags where the declared object type doesn't match the actual object type, even when the tag is only dereferenced once.

The issue occurs when a tag claims to point to one type of object (e.g. a commit) but actually points to another (e.g. a blob). Previously, Git would only catch this mismatch when comparing two tags pointing to the same object with different declared types. Now, by adding the `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag when peeling tags in `ref-filter.c`, the verification happens immediately during the first dereference.

The change is small but important for data integrity, modifying just 3 lines of code while expanding the test to verify both the original edge case and the new single-dereference scenario. This completes the series' goal of enforcing strict tag verification throughout Git's refs subsystem, building on earlier patches that modernized the peeling infrastructure and removed global state.
