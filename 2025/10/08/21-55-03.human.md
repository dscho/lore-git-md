This is a technical clarification in the ongoing Git 3.0 release planning thread regarding SHA-256 interoperability, specifically about JGit's architecture.

Randall Becker responds to Taylor Blau's question about JGit's dependencies on core Git functions. While Taylor had noted that JGit is a pure Java implementation that shouldn't need the Git binary directly, Randall provides a concrete example that JGit's garbage collection functionality does in fact delegate to Git. He also mentions there are other functions with similar dependencies, though doesn't specify which ones.

This exchange highlights an important architectural detail that could impact the SHA-256 transition planning. If JGit relies on core Git for certain operations like GC, then interoperability concerns become more pressing than if it were completely independent. The brief but pointed nature of Randall's response suggests there may be more to uncover about implementation boundaries between JGit and core Git.
