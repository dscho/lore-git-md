This is part 8/14 of Patrick Steinhardt's refactoring and bugfix series on tag peeling behavior, now focusing on converting `builtin/show-ref.c` to use the new `reference_get_peeled_oid()` API. The patch modernizes the `show-ref` command's internal handling of reference verification to align with the series' broader goal of eliminating `peel_iterated_oid()` usage.

The key change adapts `show-ref`'s exact-match verification mode (triggered via `--verify`) to construct a temporary `struct reference` when checking individual refs, allowing consistent use of `reference_get_peeled_oid()` across all code paths. This maintains the previous behavior while removing another dependency on the global `current_ref_iter`. The patch handles three distinct `show-ref` modes: pattern matching (already iterator-based), exact matching (now using temporary reference struct), and existence checking.

Technically, the patch modifies `show_one()` to accept a `struct reference*` instead of separate refname/OID parameters, updates the iterator callback to pass the complete reference, and constructs an on-stack reference in `cmd_show_ref__verify()` when handling exact matches. The peeled OID handling remains functionally identical but now uses the new API. Error handling and output formatting (including tag dereferencing with `^{}` notation) are preserved.

This change is part of the series' systematic conversion of callers to the new reference API, following earlier patches that introduced `struct reference` and `reference_get_peeled_oid()`. It demonstrates the API's flexibility by showing how non-iterator code paths can temporarily construct reference objects when needed. The implementation is straightforward and maintains all existing functionality while removing another use of deprecated interfaces.
