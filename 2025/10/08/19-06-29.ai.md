This is a documentation patch in an ongoing thread about the new `gitdatamodel.adoc` man page, now at version 2. The email focuses on two specific technical clarifications in the data model documentation.

First, regarding storage efficiency concerns, Julia Evans responds to Junio Hamano's suggestion to emphasize tree sharing (where unchanged files/directories are shared between commits) as the primary mechanism that makes snapshots practical, rather than focusing on delta compression. This addresses a common user misconception about Git's storage model.

Second, the discussion clarifies the status of `refs/remotes/<remote>/HEAD` - while initially unsure how to classify it, Julia proposes documenting it as a symbolic reference to the remote's default branch (the one `git clone` would check out), following Junio's observation that it now effectively behaves like other remote-tracking references despite its historical special status.

These refinements continue the thread's pattern of balancing technical accuracy with pedagogical clarity, particularly around edge cases and user misconceptions.
