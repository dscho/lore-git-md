This is a follow-up in the security proposal thread about preventing arbitrary code execution in untrusted repositories. Taylor Blau corrects and clarifies their earlier submodule-related concern, focusing now on nested bare repositories rather than submodules.

The key point is that if Git doesn't copy security tokens into nested bare repositories (which seems necessary for security), then users would still need to explicitly approve them - just shifting the approval prompt from editors to Git itself rather than eliminating it. This maintains the same security model but moves where the trust decision happens.

The email doesn't fundamentally change the security discussion but sharpens the analysis of one edge case. It suggests the token-based approach would still require user intervention for certain repository structures, contrary to the original claim that it would eliminate most trust prompts. The core architectural debate between token-based and config-based approaches remains unresolved.
