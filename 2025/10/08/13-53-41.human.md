Documentation patch introducing a new `gitdatamodel` man page to clearly explain Git's core concepts (objects, references, index, and reflogs). This is the second version of the patch, incorporating extensive feedback from reviewers.

The patch adds a comprehensive reference document that fills a gap in Git's documentation by providing a structured explanation of fundamental concepts that are currently scattered across glossary entries and implementation-focused documents. It organizes the four core data types into clear sections with examples, while deliberately avoiding implementation details like `.git` directory structure.

Key improvements in v2 include:
- Standardized terminology ("object name" as primary term with "ID" as synonym)
- More accurate hash algorithm description ("cryptographic hash" instead of "SHA-1")
- Complete listing of supported file modes
- Clearer distinction between annotated and lightweight tags
- Better explanation of HEAD and branch/tag differences
- Removal of `.git` directory references in favor of abstract hierarchy descriptions

The patch has undergone thorough technical review from storage-layer experts to ensure accuracy across backends (reftable/SHA-256) while maintaining pedagogical effectiveness. It represents a significant documentation improvement that should help both new and experienced users better understand Git's internals when reading other documentation.
