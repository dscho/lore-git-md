Platform compatibility patch for Windows Rust support in Git. This is the final patch in Patrick Steinhardt's v2 series improving Rust CI infrastructure, addressing Windows-specific build issues that were previously blocking Rust compilation on Windows platforms.

The patch makes three key changes: First, it adds linking against `userenv.dll` (via `-luserenv`) to satisfy the Rust runtime's dependency on `GetUserProfileDirectoryW()`. Second, it handles Windows' different library naming convention (`gitcore.lib` instead of `libgitcore.a`) by introducing platform-specific logic in both the Makefile and `cargo-meson.sh`. Third, it enables Rust testing on Windows CI runners by installing the Rust toolchain in GitLab's Windows job.

The changes span multiple build systems (Makefile, meson) and CI configurations (.gitlab-ci.yml), with careful attention to maintain consistency across platforms. The patch builds on prior work by Johannes Schindelin and Ezekiel Newren, indicating this addresses known Windows compatibility gaps. The implementation follows the series' approach of using standard tooling where possible, here leveraging cargo-meson for cross-platform builds.

This completes the series' goal of establishing comprehensive Rust infrastructure by removing the last major platform limitation. The changes are narrowly scoped to build system adjustments without modifying core Rust functionality, maintaining the low-risk profile of the overall series. The Windows CI enablement provides immediate validation of the fixes while following the pattern of earlier patches that added Rust testing to other platforms.
