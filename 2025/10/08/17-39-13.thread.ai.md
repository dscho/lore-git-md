Thread identity: Feature proposal for new core.whitespace check class to detect missing newlines at EOF, initiated by Junio C Hamano as a substantial internship project rather than quick fix.

Core problem/goal: Extend Git's whitespace checking to identify files lacking newlines at EOF through a new configurable core.whitespace class, requiring deep changes to diff and apply subsystems. The proposal aims to standardize handling of this common whitespace issue that currently lacks dedicated detection while addressing real-world problems where modern editors (like VS Code) often omit trailing newlines by default.

Current status: Early discussion phase (rfd) with no implementation started. Junio suggests this as a substantial project requiring study of three areas: (1) existing whitespace detection in diff, (2) naming the whitespace class, (3) apply subsystem's whitespace handling. Positive feedback from brian m. carlson supports the educational and tooling value of this feature.

Key technical details: Would introduce new core.whitespace class (name undecided) affecting:
- diff machinery: detecting missing newlines during diff generation
- apply machinery: enforcing new checks during patch application
Must maintain consistency with existing whitespace classes (blank-at-eol, blank-at-eof, space-before-tab, etc.)
Potential documentation updates (Git FAQ) to explain trailing newline importance as part of feature rollout.

Open questions:
- Naming convention for new whitespace class
- Exact scope of implementation across subsystems
- Impact on performance and existing workflows
- Whether to make it default-on or opt-in
- Documentation strategy for explaining the feature and its rationale

Participant positions:
- Junio C Hamano: Proposes as substantial work, suggests learning path for implementer, marks as rfd
- brian m. carlson: Supports proposal, highlights educational value for developers and CI integration potential, suggests documentation updates

Related work: Builds on existing core.whitespace infrastructure that currently checks for blank-at-eol, blank-at-eof, space-before-tab, but lacks specific handling for missing final newlines. Connects to broader ecosystem concerns about editor defaults and version control hygiene.
