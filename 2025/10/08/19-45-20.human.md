This is a documentation patch adding warnings about the `--committer-date-is-author-date` option in both `git-am` and `git-rebase` man pages.

Kristoffer Haugsbakk explains that while this option has legitimate uses (originally added to help maintain consistent commit IDs when importing patches via `git-am`), it can create commit histories that violate Git's assumption of strictly increasing commit timestamps. The patch adds clear warnings about this potential issue in both commands' documentation.

The warning notes that this option should only be used when applying commits on top of a base that's older than the patches being applied. The original motivation for the option was to help with reproducible commit IDs when importing patches via email, but the documentation now makes the tradeoffs more explicit.

The patch appears well-researched, with references to the original discussion thread and consideration of whether the option makes sense for rebase (where it forces new commit IDs anyway). The changes are focused and limited to documentation improvements.
