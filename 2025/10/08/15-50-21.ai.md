This is a refactoring patch in the ongoing series modernizing Git's refs subsystem, specifically converting `upload-pack.c` to use the new `reference_get_peeled_oid()` API introduced in patch 5/14. The change eliminates the last remaining use of `peel_iterated_oid()` in this file by ensuring `write_v0_ref()` always receives a proper `struct reference` rather than loose parameters.

The patch modifies how capabilities are announced during the ref advertisement phase. Previously, this special case constructed fake ref parameters directly, but now properly initializes a `struct reference` to maintain consistency with the new API. The key technical change is in `write_v0_ref()`, which now takes a `struct reference*` instead of separate refname/oid parameters, allowing it to use `reference_get_peeled_oid()` uniformly.

This completes the conversion of `upload-pack.c` to the new reference handling interface, removing one of the last dependencies on the global `current_ref_iter` state. The change is straightforward and maintains backward compatibility needed for the wire protocol. As part of the larger series that's already been reviewed by Taylor Blau and Junio Hamano, this patch appears ready for merging, continuing the series' goal of modernizing ref iteration while preserving the 13% performance improvement measured in the Chromium repository.
