This is a feature patch implementing signature handling parity between `git fast-import` and `git fast-export`, specifically for signed tags. It's the final patch in Christian Couder's series to unify signature handling across Git's fast-export/import pipeline.

The patch adds a `--signed-tags=<mode>` option to `git fast-import` with the same behavior and modes (verbatim, warn-verbatim, warn-strip, strip, abort) as fast-export's existing option, though with a different default (verbatim instead of abort). The implementation introduces a new `handle_tag_signature()` function in fast-import.c that uses `parse_signed_buffer()` to detect and process signatures consistently across all formats (PGP, X509, SSH).

Patrick Steinhardt's review identifies several minor issues: the option documentation should be alphabetized after `--signed-commits`, the abort message needs translation marking, and some fallthrough comments are misindented. He also asks a clarifying question about whether signatures always appear at the end of tag messages (a key assumption in the implementation). The patch appears technically sound otherwise, building on the shared signature parsing infrastructure established earlier in the series. The test coverage in t9306-fast-import-signed-tags.sh (from previous patches) should verify the behavior works as intended across all signature types and modes.
