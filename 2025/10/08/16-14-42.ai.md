This is a discussion response in the ongoing documentation patch series about SubmittingPatches guidelines. Kristoffer Haugsbakk provides feedback on Taylor Blau's proposed changes to topic naming conventions in patch submissions.

The email raises several specific concerns about the current proposal:
1. Questions the use of "primary author" terminology, suggesting it's unclear whether this refers to the Git author field or needs to account for co-authors
2. Notes that the experimental topic summary feature hasn't seen much adoption, likely because the special formatting blends in with regular cover letter text
3. Proposes more explicit formatting markers like "Topic summary:" and "Topic name:" prefixes to make these elements stand out and be machine-parseable
4. Suggests these markers could allow relaxing the requirement that these elements appear at the start of the cover letter

The response includes concrete examples of how the suggested formatting might look. It references Junio Hamano's earlier observation about low adoption of the topic summary experiment (from the linked email thread) as supporting evidence for making the formatting more distinctive.

This feedback focuses specifically on part 1 of the series (topic naming conventions) and doesn't address part 2 (multi-series submissions). The suggestions aim to improve machine and human readability of the proposed conventions while maintaining their experimental nature. The email maintains a constructive tone while identifying what it sees as usability issues in the current proposal.
