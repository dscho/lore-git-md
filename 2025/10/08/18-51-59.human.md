This is a clarification in the ongoing documentation discussion about `git bundle --all` behavior. Andreas Schwab responds to Andrew Harmon's surprise about bundle cloning not matching direct remote cloning behavior, explaining the key difference in repository states.

Andreas points out that the bundle's behavior is determined by the repository it's created from - a regular clone will have different refs than the original remote repository. He suggests comparing `git ls-remote` outputs between the local clone and original remote to see this difference directly.

The email reinforces the technical explanation that bundles inherit the ref state of their source repository, which may differ from the remote's full state unless created from a mirror clone. This aligns with the thread's established understanding that the behavior is correct but needs better documentation.

Andreas provides concrete commands to demonstrate the ref differences, offering a practical way for users to verify why bundle behavior differs from direct remote cloning. The response maintains the thread's technical consensus while adding another perspective on how repository state affects bundle contents.
