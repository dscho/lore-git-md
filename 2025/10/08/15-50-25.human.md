Refactoring patch in the tag peeling series, removing now-unneeded iterator peeling infrastructure. This is patch 10/14 in Patrick Steinhardt's series that has been through extensive review and is now merge-ready.

The patch explains that with the peeled object ID now being propagated through `struct reference`, there's no longer any need for the iterator-specific peeling mechanism. The changes are mostly straightforward deletions of the peeling infrastructure across various refs backend implementations. The most notable change is in `refs/packed-backend.c` where it now directly uses the peeled OID from the iterator's reference struct rather than performing a separate peel operation.

This continues the series' theme of simplifying the refs infrastructure by removing redundant code paths and consolidating functionality. The patch series as a whole has been validated by multiple reviewers (including Taylor Blau and Junio Hamano) and shows measurable performance improvements (13% speedup in the Chromium repo). This particular patch is a clean-up that follows naturally from the architectural changes made earlier in the series.
