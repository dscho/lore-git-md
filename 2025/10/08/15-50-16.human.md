This is the first patch in a 14-part series refactoring Git's tag peeling and ref iteration interfaces. The patch introduces a wrapper struct for the `each_ref_fn` callback type to make future interface changes less disruptive.

The change replaces direct callback parameters (refname, referent, oid, flags) with a single `struct reference` containing those fields. This requires updating 48 callers across the codebase to use the new struct-based interface. The motivation is to avoid the widespread churn seen in previous changes to the callback signature (like e8207717f1 which touched 48 files to add one parameter).

The patch is well-motivated and mechanically sound, touching only the callback interface and its callers without changing behavior. It's part of a larger performance-oriented refactoring that has already undergone significant review, with Junio Hamano and Taylor Blau validating the approach. The series as a whole shows a 13% speedup in the Chromium repository.

Key technical details:
- Introduces `struct reference` to bundle ref iteration data
- Updates all `each_ref_fn` callbacks to use the new struct
- Maintains exact same behavior as before
- Sets up infrastructure for future ref iteration improvements

This foundational change enables the rest of the series to modernize tag peeling and ref iteration with less disruption. The patch appears ready for merging as part of the larger series.
