This is patch 7/14 in a refactoring and bugfix series modernizing Git's refs subsystem, specifically focusing on tag peeling behavior and ref iteration. The patch propagates peeled object IDs through the ref-filter subsystem, eliminating the need for `peel_iterated_oid()` in this context.

The key technical changes include:
- Adds a `peeled_oid` field to `struct ref_array_item` to store pre-peeled tag targets
- Modifies `ref_array_push()` and related functions to accept and store peeled OIDs
- Updates `populate_value()` to use the stored peeled OID when available rather than re-peeling
- Adjusts callers in `builtin/ls-remote.c`, `builtin/tag.c`, and `builtin/verify-tag.c` to pass NULL for peeled OID (maintaining backward compatibility)
- Extends `pretty_print_ref()` to accept peeled OID parameter
- Simplifies `apply_ref_filter()` to take a `struct reference` rather than individual components

This change is part of the broader effort to eliminate global state (`current_ref_iter`) and improve performance by avoiding redundant object parsing. The patch demonstrates good attention to backward compatibility while modernizing the interface. All affected callers are updated consistently, and the changes align with the series' goal of making peeled OIDs available throughout the refs pipeline.
