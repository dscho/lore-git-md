Refactoring patch in a series modernizing Git's ref iteration and tag peeling infrastructure. This is patch 2/14 in a merge-ready series that has already received extensive review from Taylor Blau and Junio Hamano.

The change simplifies the ref iterator interface by introducing a `struct reference` field to hold ref metadata (name, target, oid, flags) rather than scattering these fields directly in the iterator struct. This eliminates repetitive copying of these fields when passing references to callbacks. The patch updates all iterator implementations (files, packed, reftable backends) to use the new approach and modifies helper functions like `should_pack_ref()` to work with the consolidated struct.

The changes are mechanical but touch many files (8 files, 175 lines changed) as they propagate through the ref iteration subsystem. The patch appears well-executed with consistent updates across all backends and no obvious omissions. It builds on patch 1/14 which introduced the `struct reference` type, and prepares for later patches that will optimize tag peeling behavior.
