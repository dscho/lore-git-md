This is a follow-up in a thread about Jenkins integration issues caused by Git's deprecation of `git whatchanged`. The original poster encountered build failures when Jenkins tried to use the deprecated command to retrieve change history for shared libraries.

Kristoffer Haugsbakk points to a fix that has already been implemented in the Jenkins issue tracker (JENKINS-76017). The response is brief but provides the key piece of information the original poster needs - that this is a known issue with an existing solution in the Jenkins project.

The thread shows a common integration challenge when Git deprecates legacy commands, in this case affecting the Jenkins Git plugin's use of `git whatchanged`. While the Git side requires either using the opt-in flag or switching to `git log`, the actual fix needs to happen in the Jenkins plugin itself. This email confirms that work is already done, saving the original poster from needing to implement a workaround themselves.
