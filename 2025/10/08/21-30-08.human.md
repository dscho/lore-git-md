This is a discussion thread about the security proposal to prevent arbitrary code execution in untrusted repositories. Taylor Blau raises two key concerns about the proposed solution involving secret tokens for repository verification.

First, Taylor questions how the token mechanism would handle recursive submodule clones, noting that the current proposal doesn't appear to address copying tokens into recursively cloned submodules. This suggests a potential gap in the security model for a common Git workflow.

Second, Taylor challenges the claim that this would eliminate trust prompts from editors, arguing that if tokens aren't propagated to submodules, users would still need to manually verify them - just through Git's mechanism rather than the editor's. This implies the proposal might not actually reduce user friction as claimed.

The exchange highlights important edge cases in the security design that would need resolution before the proposal could be implemented effectively. Taylor's questions suggest the current design may not fully account for real-world Git usage patterns involving submodules.
