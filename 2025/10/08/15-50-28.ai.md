This is patch 13/14 in a refactoring and bugfix series addressing tag peeling behavior in Git's refs subsystem. The patch focuses on improving corruption detection when dereferencing tags in `git-for-each-ref`.

The change modifies `ref-filter.c` to enforce tag type verification during peeling by passing the `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag (introduced in patch 11/14) when populating values. Previously, type mismatches were only detected when comparing multiple tags pointing to the same object with different declared types. Now the verification happens during the first dereference, catching corrupt tags more reliably.

The patch updates the test suite to verify this stricter behavior, adding a case that would have passed before but now properly fails due to the type verification. This completes the enforcement of tag type checking that was started in earlier patches, ensuring consistency between the packed-refs and reftable backends (patched in 12/14) and the ref-filter logic.

This is part of the series' broader goal to modernize ref iteration and tag peeling while eliminating global state and legacy interfaces. The change is small but important for ensuring data integrity when tags are dereferenced through `git-for-each-ref`. With this patch, the series now has comprehensive verification of tag object types across all relevant code paths.
