This is part 5 of Adrian Ratiu's hook subsystem refactoring series, focusing on the reference-transaction hook. The patch converts the hook execution to use the new `hook.h` infrastructure, introducing a `transaction_hook_feed_stdin` callback.

Patrick Steinhardt had raised a design inconsistency between this patch and patch 4 (pre-push hook) - while both handle reference updates, patch 4 processes one reference per callback invocation while patch 5 processes the entire transaction at once. Adrian acknowledges this is a valid concern and proposes a middle ground solution: batching 50-100 references per callback to balance throughput and blocking concerns.

The technical implementation shows the transition from direct child process management to using the new `hook_cb_data` and `run_hooks_opt` infrastructure. The callback receives transaction data through `feed_pipe_ctx` and processes updates in a loop, skipping `REF_LOG_ONLY` updates as before. This maintains the existing functionality while adopting the new hook framework.

Adrian plans to address the batching consistency in v2, aligning both reference-processing hooks to use similar patterns. The discussion highlights ongoing design considerations around optimal batch sizes for hook input processing, which affects both performance and potential blocking behavior. This patch remains technically sound but will see interface changes to resolve the architectural inconsistency noted by Patrick.
