This is a refactoring patch in Patrick Steinhardt's series modernizing Git's ref iteration and tag peeling infrastructure. It removes the `current_ref_iter` global variable and associated `peel_iterated_oid()` function, which were previously used as a performance optimization hack for tag peeling during ref iteration.

The patch builds on prior work in the series that introduced `struct reference` to propagate peeled OIDs through the refs subsystem. With all callers now using `reference_get_peeled_oid()` instead of the old peeling mechanism, this cleanup becomes possible. The changes touch core refs handling code in `refs.c`, the iterator implementation, and internal headers, removing 28 lines of now-unused code.

This represents a significant simplification of the refs subsystem by eliminating a global variable and the associated state management complexity. The removal aligns with broader efforts to reduce global state in Git's codebase. The patch maintains all existing functionality while making the code more robust and easier to understand, as the peeled OID information now flows explicitly through the `struct reference` rather than being accessed via a global side channel.

The change is part of a well-reviewed series that has already addressed all technical concerns and been validated for performance impact (13% speedup in the Chromium repo). Junio Hamano has confirmed merge-readiness for earlier patches in the series, with this patch being one of the final pieces completing the refactoring.
