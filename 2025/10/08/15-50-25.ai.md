This is patch 10/14 in a refactoring and bugfix series modernizing Git's refs subsystem, specifically removing the now-obsolete infrastructure for peeling references via iterators. The series has been reviewed and is merge-ready, with this patch completing the architectural simplification by eliminating the last vestiges of the old peeling approach.

The patch removes the `ref_iterator_peel()` function and all its implementations across various backends (files, packed, reftable), along with related documentation. The key change is in `refs/packed-backend.c` where the code now directly uses the peeled OID from the `struct reference` rather than calling the iterator's peel method. This builds on previous patches that propagated peeled OIDs through the reference structure.

All 141 deleted lines are straightforward removals of now-unused code, with no behavior changes beyond what was already established in earlier patches. The series has shown a 13% performance improvement in the Chromium repository by avoiding unnecessary object parsing, and this patch maintains those gains while further simplifying the codebase.

The removal aligns with the series' goals of cleaning up technical debt around ref iteration and tag peeling interfaces, and follows the earlier elimination of the `current_ref_iter` global in patch 9/14. With this change, all reference peeling now flows through the unified `struct reference` interface rather than having parallel peeling paths.
