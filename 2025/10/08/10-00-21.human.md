This is a test modernization patch in Christian Couder's series implementing signed tag handling parity between `git fast-export` and `git fast-import`. The change addresses a fragile test design in t9350-fast-export.sh where some tests hardcode expected tag counts, which could break if new tests add tags earlier in the test sequence.

Christian's approach replaces the hardcoded values with a dynamically maintained counter that tracks tag additions throughout the test file. While Patrick Steinhardt suggests alternatives like moving tests or using separate repositories, Christian argues this would obscure the underlying test interdependencies and potentially create more confusion later. The patch makes the technical debt explicit rather than hiding it through reorganization.

The change is preparatory work for upcoming tests in the signed tags series, ensuring they won't break existing tag-counting assertions. While the solution isn't ideal (as Patrick notes, test interdependencies are generally undesirable), it's a pragmatic fix that maintains the logical test ordering while making the dependencies clearer. This reflects the careful attention to test infrastructure that has characterized the series so far.
