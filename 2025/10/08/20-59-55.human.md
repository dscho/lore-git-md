This is a design discussion about the final interface for atomic reference updates in `git replay`, part of the ongoing effort to make atomic updates the default behavior.

Elijah Newren weighs in on the interface design debate between Siddharth Asthana and Phillip Wood. While Elijah had previously suggested a simple `--[no-]update-refs` flag, he now expresses preference for Phillip Wood's more extensible `--update-refs=<mode>` approach. The key advantage is that the mode-based interface would allow for future extensions (like partial updates) without introducing conflicting options later.

The discussion represents one of the last open questions in this otherwise implementation-ready patch series. While the technical implementation is complete with extensive test coverage, the maintainers are still deliberating between:
1. A simple boolean flag matching existing `rebase.*` conventions
2. A more flexible mode-based interface that anticipates future needs

This email moves the needle toward the more extensible design, though no final decision has been made yet. The exchange demonstrates how even small interface details receive careful consideration in Git's development process.
