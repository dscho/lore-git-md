Refactoring and bugfix in the refs subsystem, part of Patrick Steinhardt's ongoing series to modernize tag peeling behavior. This patch (12/14) addresses a subtle issue where invalid tags with type mismatches could have their peeled object IDs incorrectly stored in packed-refs and reftable backends.

The core change modifies both backends to use the new `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag (introduced in patch 11/14) when storing peeled values. This ensures tags with invalid type claims (e.g., a blob tagged as a commit) won't have their peeled values persisted, making corruption more detectable. The patch includes test cases demonstrating the fix for both packed-refs and reftable formats, showing that commands like `git-for-each-ref` will now properly detect and report type mismatches rather than silently using invalid peeled values.

This completes the series' goal of making tag verification consistent across Git's refs subsystem, building on the earlier removal of the `current_ref_iter` global and `ref_iterator_peel()` infrastructure. The implementation maintains backward compatibility while fixing a subtle bug that could mask corruption. With Taylor Blau's validation and Junio Hamano's merge-readiness for earlier patches, this appears to be the final technical refinement before series completion.
