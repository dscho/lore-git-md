Refactoring patch in a series modernizing Git's refs iterator interface. This is patch 2/14 in a performance-oriented series that has already received extensive review and is now merge-ready for its first half.

The change replaces scattered refname/oid/flags fields in `struct ref_iterator` with a consolidated `struct reference` member, simplifying callback handling across all ref iterator implementations. The patch updates 8 files (refs.c, iterator implementations, and backends) to use the new structure, including a bonus simplification of `should_pack_ref()` to take the reference struct directly rather than individual fields.

Key technical details:
- Introduces `iter->ref` field containing name, target, oid, and flags
- Updates 48 call sites to use the new consolidated structure
- Modifies `should_pack_ref()` signature to take `struct reference*`
- Maintains all existing behavior while reducing allocations
- Part of broader effort to optimize `git-for-each-ref` by avoiding object parsing
- Follows established patterns from earlier patches in the series

The change is mechanical but touches core refs infrastructure, with all affected code paths being exercised by existing tests. The series has already demonstrated 13% speedups in the Chromium repository from these optimizations.
