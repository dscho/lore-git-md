This is patch 12/14 in a refactoring and bugfix series addressing tag peeling behavior in Git's refs subsystem. The patch focuses on ensuring invalid tag objects don't have their peeled object IDs incorrectly stored in the refs database.

The key change is that both the files and reftable backends will now verify tag object types when peeling, skipping storage of peeled IDs when verification fails. This prevents corruption from propagating through the system - for example, `git-for-each-ref` would previously fail to detect broken tags when using certain formats if the peeled value was already stored.

The patch includes tests demonstrating the fix: one showing packed-refs won't store invalid peeled values, and another verifying the reftable backend similarly avoids persisting bad data. This maintains consistency in how Git handles corrupt tags regardless of the refs storage backend.

As part of the larger series that's already received extensive review, this patch completes the tag verification improvements by ensuring the stricter checking applies during ref storage operations. The change is straightforward and well-tested, continuing the series' trend of careful modernization while fixing subtle edge cases.
