Refactoring patch in the packfile store API cleanup series, responding to Patrick Steinhardt's earlier patch. This is part of the ongoing effort to simplify packfile iteration patterns by migrating from the stateful `packfile_store_get_packs()` to the more predictable `packfile_store_get_all_packs()`.

The email confirms and approves Patrick's changes to `object-name.c`, specifically the conversion of two functions (`find_short_packed_object` and `find_abbrev_len_packed`) to use `get_all_packs()`. Taylor Blau notes these are safe conversions since both functions already properly filter out MIDX'd packs through other mechanisms (`unique_in_pack` discards packs with `multi_pack_index` bit set).

The technical context shows this is part of eliminating the confusing statefulness between `get_packs()` and `get_all_packs()` where callers couldn't reliably predict whether MIDX'd packs would appear in results. The changes touch core object lookup paths but maintain identical behavior, just with more predictable internals. This appears to be straightforward mechanical work with no behavioral changes, continuing the series' pattern of careful, incremental refactoring.
