This is a documentation discussion within the ongoing `gitdatamodel.adoc` patch series, specifically addressing two technical points about Git's data model representation and remote reference terminology.

Junio Hamano responds to Patrick Steinhardt's suggestions about explaining Git's storage efficiency and remote HEAD references. On storage, while acknowledging the correctness of Patrick's proposed compression explanation, Junio suggests the primary space-saving mechanism is actually tree sharing between commits that modify few files. This gets to the heart of why snapshots are practical despite initial user skepticism.

Regarding remote-tracking references, the discussion clarifies the special case of `refs/remotes/<remote>/HEAD`. While Patrick distinguishes this from regular remote-tracking branches, Junio notes its historical role in recording preferred branches and how modern protocols now allow it to track remote state like other references. He concludes it's reasonable to consider it a remote-tracking branch despite its symref nature.

The exchange shows careful attention to both pedagogical effectiveness (what explanations best address user misconceptions) and precise terminology (how to classify special-case references). These are exactly the kinds of nuanced decisions the documentation effort must resolve, building on earlier consensus about core terminology while working through remaining edge cases.
