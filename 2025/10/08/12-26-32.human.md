This is part 5 of Adrian Ratiu's hook subsystem refactoring series, focusing on the reference-transaction hook. The patch converts the hook to use the new `hook.h` infrastructure, similar to previous patches in the series.

Patrick Steinhardt had raised a concern about inconsistency between this patch and patch 4 (pre-push hook) - while both handle reference updates, patch 4 processes one reference per callback while patch 5 processes the entire transaction at once. Adrian acknowledges this is a valid point and proposes a middle ground solution: batching 50-100 references per callback to balance throughput with avoiding write blocking.

The patch maintains all existing functionality while adopting the new hook infrastructure. Adrian plans to address the callback pattern inconsistency in v2 of the series, along with optimizing the batch size for reference processing. This continues the series' pattern of careful technical review and incremental improvements while maintaining compatibility.
