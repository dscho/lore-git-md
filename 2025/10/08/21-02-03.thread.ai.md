Security proposal for preventing arbitrary code execution in untrusted repositories (RFC). Core issue: Git executes user-defined code (hooks, core.pager, etc.) without verification when operating on any repository, creating security risks. Original proposal involved per-user secret tokens stored in `~/.gitsecret`, copied during `git init`/`git clone` and verified before executing user-defined code, with Brian Carlson critiquing this approach and proposing config-based allowlists instead. Taylor Blau identified nested bare repository constraints, while Michael Lohmann suggested token model modifications.

Jeff King (Peff) structured the problem into two phases: (1) defining unsafe behavior (skipping repo-level config, disabling hooks) and (2) safety marking mechanisms, proposing simpler alternatives like environment variables (`GIT_ASSUME_UNSAFE`) and config-based safe directories. Michael Lohmann's synthesis identified four discussion threads and agreed with Jeff King's phased approach.

Michael Lohmann now submits concrete patches implementing Jeff King's "assume unsafe" mechanism as a first step: new config option `safe.assumeUnsafe`, environment variable `GIT_ASSUME_UNSAFE`, and command-line flag `--assume-unsafe` to mark repositories as unsafe. This focuses on the behavior definition phase while leaving safety marking mechanisms (token vs config allowlist) for future work. The implementation integrates with existing security hooks and config skipping behavior.

Key technical details include the new unsafe marking mechanisms and their interaction with existing security infrastructure. Open questions remain about the architectural approach (token vs config), with this patchset representing an incremental step that doesn't resolve that debate. The thread now has both design discussion and concrete code, with Jeff King's pragmatic approach being implemented first while maintaining flexibility for future safety marking solutions.
