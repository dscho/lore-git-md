Test improvement in the `--signed-tags` series, addressing test fragility in t9350-fast-export.sh.

Christian Couder responds to Patrick Steinhardt's review of patch 3/5 in their series implementing signed tag handling parity between fast-import and fast-export. The patch fixes fragile test assertions in t9350-fast-export.sh that hardcode expected tag counts, which could break if prerequisite-enabled tests add tags earlier in the test sequence. Christian's solution introduces a counter that tracks tag additions dynamically.

Patrick had suggested alternatives like moving the affected tests to the end of the suite or isolating them in a separate repository, but Christian argues this would obscure the underlying test fragility rather than fix it. The current approach makes the test interdependencies explicit through the counter mechanism, which Christian considers preferable despite being "a bit ugly" because it surfaces the technical debt rather than hiding it through test reorganization.

This discussion occurs within the broader context of the series' test modernization efforts, which include updates to t/lib-gpg.sh and the new t9306-fast-import-signed-tags.sh. The exchange highlights differing philosophies about test design - Patrick favoring isolation where possible, while Christian prioritizes making implicit dependencies visible. The solution maintains the existing test structure while making it more robust against changes in prerequisite handling.
