The exchange highlights two key points about real-world usage patterns: (1) Many users are unaware of the committer/author date distinction because most Git hosting interfaces (like GitHub) only display the committer date by default, and (2) Some users actively try to preserve author dates during rewrites specifically to make this metadata visible on these platforms.

The discussion surfaces an important disconnect between Git's internal timestamp ordering requirements and how users actually interact with commit metadata through popular interfaces. While the original patch focused on technical correctness, this follow-up explores the human factors driving the potentially problematic usage patterns. No new technical details are introduced, but the exchange helps explain why users might persist in using `--committer-date-is-author-date` despite its potential to create revision-walking issues.
