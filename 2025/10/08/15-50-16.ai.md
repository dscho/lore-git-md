Refactoring patch introducing a wrapper struct for `each_ref_fn` callbacks. This is the first patch in a 14-part series modernizing Git's ref iteration and tag peeling infrastructure, now merge-ready after extensive review.

The patch introduces `struct reference` to encapsulate refname, target (for symrefs), oid, and flags - previously passed as separate parameters to `each_ref_fn`. This reduces churn when extending callback signatures, as seen when referent was added in e8207717f1 (requiring 48 file changes). The tradeoff is slightly more opaque call sites, but the struct is only populated in a few key locations (ref backends, iterator.c, and direct callback invocations).

Key technical details:
- Updates 48 callers of `each_ref_fn` across 65 files
- Introduces `struct reference` in refs.h with fields: `name`, `target`, `oid`, `flags`
- Modifies `each_ref_fn` typedef to take single struct parameter
- All existing callback functions converted to new signature
- No behavior changes, purely mechanical refactoring

This foundational change enables subsequent patches to more easily extend the ref iteration interface. The series as a whole addresses technical debt in tag peeling and ref iteration, with measured performance improvements (13% speedup in Chromium repo). Patch has been reviewed by Taylor Blau and Junio Hamano, with all prior concerns addressed.
