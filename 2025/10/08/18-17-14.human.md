This is a follow-up in the discussion about `git bundle` behavior regarding remote refs during cloning. Andrew Harmon provides a concrete demonstration script showing that while `git bundle --all` includes all refs, a subsequent clone only fetches local branches by default - matching Git's standard remote cloning behavior but differing from his expectations.

The email includes a complete reproduction case showing:
1. A normal SSH clone that fetches remote branches
2. Bundle creation with `--all` that correctly includes all refs
3) A subsequent bundle clone that only fetches local branches by default
4) The manual fetch needed to get remote branches

Andrew emphasizes his surprise as an end user, expecting bundle cloning to behave identically to direct network cloning. While maintainer Junio C Hamano has explained this is intentional design (mirroring Git's conservative remote cloning semantics), Andrew's script usefully documents the exact behavior and the extra step required for complete repository transfer.

The thread has now converged on this being expected behavior that needs better documentation rather than a bug. Andrew's reproduction script would serve well as an example in the documentation to clarify:
- The distinction between bundle contents and clone behavior
- How to perform complete transfers (either via mirror clone or explicit fetch)
- The philosophical alignment with Git's remote cloning defaults
