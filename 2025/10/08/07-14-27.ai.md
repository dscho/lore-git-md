Test infrastructure discussion regarding tag counting in fast-export tests.

Patrick Steinhardt responds to Christian Couder's patch that proposes counting annotated tags via an incrementing counter in t9350-fast-export.sh, rather than using hardcoded values. While acknowledging the immediate problem (upcoming tests will add more tags), Patrick questions the broader test design approach, suggesting two potentially better alternatives:

1. Making new tests work in standalone repositories to avoid interdependencies
2. Adding new tests at the end of the test sequence

The exchange reveals an underlying tension between maintaining existing test patterns (with their implicit dependencies) versus restructuring tests for better isolation. Patrick's feedback indicates this may be a longstanding issue in the test suite rather than a new problem introduced by the current series. The discussion focuses on test architecture rather than the core signature-handling functionality of the main patches.
