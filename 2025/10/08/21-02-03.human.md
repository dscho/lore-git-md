This is a security proposal addressing Git's vulnerability to arbitrary code execution via hooks and config settings in untrusted repositories. Michael Lohmann outlines a solution that would add a security token system to verify repository origins while maintaining all existing functionality.

The proposal involves generating a secret token stored in the user's home directory that gets copied into new repositories during `git init` or `git clone`. Before executing any user-defined code (hooks, pager commands, etc.), Git would verify the presence of this token, aborting if missing. This would protect users who accidentally interact with malicious repositories while keeping the workflow unchanged for legitimate use.

The main benefits include preventing accidental execution in untrusted repos and potentially eliminating the need for editor trust prompts. The key drawback is a one-time migration pain where existing clones would need manual approval via a new `git allow` command. Lohmann suggests a phased rollout where Git could silently add tokens to existing repos in a minor release before making the check mandatory in Git 3.0.

The proposal is well-motivated with references to real-world vulnerabilities and includes a prototype implementation as a bash wrapper. The tradeoff between security and migration pain is clearly articulated, making this a thoughtful starting point for discussion about hardening Git's security model. The approach appears technically sound while preserving Git's core functionality.
