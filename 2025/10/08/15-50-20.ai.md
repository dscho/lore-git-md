Refactoring patch in a series modernizing Git's tag peeling infrastructure. This is patch 5/14 in a performance-focused series that has already undergone extensive review and is now merge-ready for its first half.

The patch introduces a cleaner way to access peeled tag objects by adding a `peeled_oid` field to `struct reference` and a new `reference_get_peeled_oid()` function. This replaces the previous fragile approach that relied on global state (the `current_ref_iter` variable) and the `peel_iterated_oid()` function. The new design allows backends (files and reftable) to provide pre-peeled values when available, falling back to on-demand peeling via the ODB otherwise.

Key technical changes:
- Adds `peeled_oid` field to `struct reference` for backends to populate
- Introduces `reference_get_peeled_oid()` as the new preferred API
- Updates 8 callers across various commands (`describe`, `gc`, `pack-objects` etc.) to use the new interface
- Modifies both packed and reftable backends to populate the new field
- Maintains backward compatibility by falling back to ODB peeling when no pre-peeled value exists

The change is part of a larger effort to clean up ref iteration interfaces and optimize tag handling, with measured performance improvements (13% speedup in Chromium repo). This particular patch focuses on eliminating global state while maintaining the same functionality, following the series' pattern of incremental, carefully benchmarked improvements.
