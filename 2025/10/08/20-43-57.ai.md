This is a minor refactoring patch in the packfile store API series, specifically addressing the `git grep` command's pack preloading behavior. The patch simplifies how `git grep` preloads packfiles when using multiple threads by directly calling `packfile_store_prepare()` instead of going through the indirect `packfile_store_get_packs()` wrapper. As Taylor Blau confirms in his review, this is a straightforward improvement since the grep code doesn't use the return value from `get_packs()` - it only cares about the side effect of pack preparation.

The change is part of the larger packfile store API cleanup effort that has been systematically converting callers to more standardized patterns. This particular instance shows the kind of mechanical simplification that becomes possible after the foundational API changes in earlier patches of the series. The modification is limited to one line in `builtin/grep.c` and maintains the same behavior while making the code's intent clearer.

Technical details show this touches the interaction between grep's threading model and pack subsystem initialization, though the impact is minimal since it's just removing an indirection layer. The patch has already been reviewed and approved by Taylor Blau, who confirms the technical correctness of the change. This appears to be one of the final cleanups in the series, building on the earlier API standardization work.
