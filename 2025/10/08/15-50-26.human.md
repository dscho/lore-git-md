Refactoring and bugfix patch in a series modernizing Git's tag peeling behavior. This is patch 11/14 in a merge-ready series that has already received extensive review from Taylor Blau and Junio Hamano.

The patch addresses a subtle issue in tag peeling where Git doesn't properly verify the type of objects referenced by tags. Currently, when peeling a tag to its final non-tag object, Git may accept incorrect object types if they aren't already cached, potentially leading to later errors. The patch adds a new `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag to `peel_object()` that enables strict type verification when needed, while maintaining backward compatibility with existing tag parsing behavior.

Key changes include:
- Adding the verification flag to `peel_object()`
- Inlining and removing the `deref_tag_noverify()` function since its functionality is now covered by the flag
- Updating callers to use the new flag where appropriate (though most continue without verification for now)

The change is part of a larger effort to clean up Git's ref iteration and tag peeling interfaces while fixing inconsistencies in tag object verification. The series has already demonstrated a 13% speedup in the Chromium repository by avoiding unnecessary object parsing. This particular patch focuses on correctness rather than performance, ensuring tag peeling properly validates object types when requested.
