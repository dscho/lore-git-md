This is a discussion about potential future extensions to `git replay`'s output format capabilities, specifically regarding hook integration and client-side use cases. The email exchange between Siddharth Asthana and Kristoffer Haugsbakk explores how a `--format` option could improve `git replay`'s usability for client-side workflows, particularly for `post-rewrite` hook integration.

Kristoffer provides a concrete use case where they currently parse `git rebase` output to feed into `post-rewrite` hooks, suggesting that `git replay` could benefit from direct format support to avoid this parsing step. They also speculate about other client-side needs like customizable reflog messages. Siddharth acknowledges these as valid future directions but notes the current focus remains on server-side atomic updates, with client-side features like hook support planned for later development.

Key technical points mentioned include:
- Current output format is constrained by `git update-ref --stdin` compatibility
- Potential format atoms like `%(old)` and `%(new)` could simplify hook integration
- Server-side workflows prioritize simplicity while client-side needs may demand more flexibility
- The discussion doesn't affect the already-approved atomic update functionality

This exchange represents forward-looking design discussion that could inform future iterations of `git replay` as it evolves toward replacing interactive rebase functionality, though the core atomic ref update feature remains the immediate priority. The thread shows healthy consideration of both current server-side optimization goals and future client-side usability needs.
