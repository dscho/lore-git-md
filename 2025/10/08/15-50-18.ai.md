This is a refactoring patch in a larger refactoring/bugfix series about tag peeling behavior in Git's refs subsystem. Patch 3/14 specifically addresses iterator safety by ensuring complete reset of the `struct ref_iterator::ref` field between iterations.

The change prevents state leakage between iterations by zeroing out the reference structure at the start of each iteration cycle. This hardening measure ensures that (1) no stale data persists between iterations and (2) any future optional fields added to the structure will automatically initialize to zero rather than containing garbage values. The patch modifies three backend implementations (packed, cache, and reftable) to perform this reset.

Key technical details:
- Adds `memset(&iter->base.ref, 0, sizeof(iter->base.ref))` calls in each backend's advance function
- Maintains existing field assignments after the reset (name, target, oid)
- Handles special cases: files backend uses cache iterator internally, prefix iterators copy references
- Preserves the performance characteristics of the iteration (confirmed via benchmarks)
- Part of broader effort to modernize ref iteration interfaces and prevent tag peeling inconsistencies

The change originated from Karthik Nayak's safety suggestion and has been validated by multiple reviewers. It demonstrates the series' attention to both API cleanliness and robustness while maintaining the 13% performance improvement seen in earlier benchmarks.
