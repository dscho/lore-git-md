This is a refactoring and bugfix series (now 14 patches) focused on Git's tag peeling behavior and ref iteration infrastructure. Authored by Patrick Steinhardt, it originated from a performance optimization goal but uncovered deeper issues in how Git handles tag verification.

The series has evolved through review rounds, now including:
1. Core refactoring to eliminate the `peel_iterated_object()` hack (patches 1-8)
2. Removal of now-unneeded infrastructure (patches 9-10)
3. Fixes for tag verification issues where tag objects might store mismatched type information (patches 11-13)
4. The original performance optimization - lazy object parsing in `git-for-each-ref` (patch 14)

Key improvements in v2 include better commit messages and a new safety patch (patch 3) that resets iterator state during advancement. The series has received thorough review from Taylor Blau and Junio Hamano, with all technical concerns addressed. Performance benchmarks show a 13% speedup in Chromium repo tests.

The most contentious area remains patches 11-13, which Patrick acknowledges feel like "whack-a-mole" fixes for tag verification edge cases. He's open to alternative approaches but avoided deeper changes to `parse_tag_buffer()` that would break existing tests with intentionally corrupted tags. The series is now merge-ready, demonstrating how a simple optimization led to important architectural improvements in Git's ref handling.
