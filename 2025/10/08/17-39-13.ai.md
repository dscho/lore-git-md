This is a feature proposal for adding a new whitespace check class to Git's core.whitespace configuration, specifically targeting files that lack a newline at EOF.

The email from Junio C Hamano suggests this as a substantial internship project rather than a quick fix, noting it would require deep understanding of Git's diff and apply machinery. The proposal outlines three key learning areas for a potential implementer: (1) studying how existing whitespace issues are detected in the diff subsystem, (2) naming the new whitespace class appropriately, and (3) understanding how whitespace handling works in the apply subsystem to properly implement the new check.

The proposal is currently at an early discussion stage ("rfd" - request for discussion) with no specific implementation details yet. The focus is on gauging community interest and feasibility before proceeding with actual development work. The mention of this being too large for a microproject suggests the implementation would require non-trivial changes across multiple subsystems.
