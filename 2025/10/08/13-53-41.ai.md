Documentation patch introducing a new `gitdatamodel.adoc` man page that explains Git's core concepts (objects, references, index, reflogs) in a structured way. This is the second version of the patch, incorporating extensive feedback from reviewers.

The patch adds a comprehensive reference document that fills a gap in Git's documentation by providing a centralized explanation of fundamental concepts that are currently scattered across multiple files. It organizes the content into four main sections: Objects (commits, trees, blobs, tags), References (branches, tags, HEAD), The Index, and Reflogs. Key improvements in v2 include:

- Removed `.git` directory references in favor of more abstract descriptions
- Standardized terminology ("object name" as primary term with "ID" as synonym)
- Added complete file mode documentation listing all five possible modes
- Clarified tag behavior and lightweight vs annotated tags
- Improved explanations of HEAD and branch/tag differences
- Fixed reflog behavior documentation
- Added to glossary and build system

The document intentionally avoids implementation details like configuration and revision syntax to stay focused on core concepts. It provides concrete examples of how each data type is stored while maintaining backend-agnostic terminology (e.g. "cryptographic hash" rather than SHA-1). The patch includes both the new man page and updates to the glossary to standardize object naming terminology.

This represents significant progress in the ongoing effort to improve Git's conceptual documentation, with particular attention to making the content accessible while technically precise. The patch has undergone thorough review from storage-layer, documentation, and teaching perspectives, with consensus emerging on key terminology choices.
