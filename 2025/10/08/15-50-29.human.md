Performance optimization in ref-filter completing a large refactoring series.

This is the final patch (14/14) in Patrick Steinhardt's series modernizing Git's ref iteration and tag peeling infrastructure. The series has been validated by multiple reviewers and is now merge-ready. This particular patch optimizes `git-for-each-ref` by making object parsing lazy - we now only parse objects when a formatting atom actually needs the parsed data, rather than always parsing them upfront.

The change shows a 13% speedup in the Chromium repository (with ~40,000 refs), reducing runtime from ~389ms to ~345ms for a simple `%(raw)` format. The implementation introduces a new `get_or_parse_object()` helper that handles the lazy parsing, and refactors several value-grabbing functions to use it. The patch touches core formatting logic for tags, commits, and signatures.

This completes the series' performance optimization goals while maintaining all the earlier improvements around tag verification and global state removal. The change is well-tested and has already received positive feedback from Taylor Blau and Junio Hamano. The series now appears ready for merging into next.
