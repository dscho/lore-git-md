This is a review comment on a refactoring patch in the `--required` flag series for reference optimization. Patrick Steinhardt responds to Karthik Nayak's patch that cleans up leftover `pack_refs` references after consolidating backend operations under a unified `optimize` function.

Patrick agrees with the overall direction but suggests improving the documentation approach. Rather than moving the flags documentation to the new `refs_optimize()` function, he proposes documenting the flags directly in the `pack_refs_opts` struct (which despite its name is used by the optimization operation). This would provide better structural documentation since the flags are part of the options struct rather than the function signature.

The comment highlights an ongoing attention to detail in this series' interface design, where even documentation placement is being carefully considered. This patch is part of the preparatory work (patch 2/9) standardizing backend operations before introducing the new `--required` functionality.
