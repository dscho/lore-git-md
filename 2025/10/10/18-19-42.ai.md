Junio Hamano provides feedback on Philip Patsch's documentation patch about `git blame --incremental` output fields. The key points:

1. Questions the phrasing "from when the commit was made" as unclear about which commit it refers to, suggesting it doesn't add meaningful information.

2. Objects to using "current state" terminology since the blamed state may not be the current one (could be historical). Proposes alternative wording using "annotated state" to match the `--help` text's "annotating from given revision" language.

3. Suggests clearer phrasing for both fields:
   - For sourceline: "the line number in the file in the above blamed commit"
   - For resultline: "the line number in the file, where the line is found in the starting <rev>"

4. Notes the SHA-1 reference should be updated to be hash-agnostic (mentioning hex object name instead of 40-byte SHA-1) but considers this a separate issue.

The feedback focuses on making the documentation more precise in its terminology while maintaining accuracy about blame's behavior across historical revisions. The suggested changes would affect both the inline explanations and the format specification paragraph added by the original change.
