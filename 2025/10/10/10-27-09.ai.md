This is a test refactoring patch that improves whitespace consistency checking in command help text, specifically for commands with subcommands. The change is part of a larger series introducing a `--required` flag for `git refs optimize`.

The patch modifies `t/t0450-txt-doc-vs-help.sh` to better validate help text formatting for commands with subcommands like `git refs`. The original test simply checked that all indented lines used the same number of spaces, which fails for multi-subcommand help text where different subcommands may have different indentation levels (e.g., `git refs optimize` vs `git refs list`).

The new implementation uses awk to track subcommands and verify consistent indentation within each subcommand's section rather than globally. It creates a list of (subcommand number, indent level) pairs and checks for duplicates within subcommands. The test now properly handles cases where different subcommands legitimately use different indentation levels while still catching inconsistent indentation within a single subcommand's options.

This appears to be a well-motivated test improvement that addresses a real limitation in the existing whitespace validation. The change is focused and maintains the test's original purpose while accommodating more complex command structures. The implementation is clean, using awk to track subcommand context, and includes a clear explanation of why the original approach was insufficient. This prepares the test suite for future additions to commands with subcommand hierarchies.
