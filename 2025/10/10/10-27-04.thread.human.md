This thread introduces a new `--required` flag for `git refs optimize` and `git pack-refs`, primarily to support performance optimizations in GitLab's Gitaly service where read operations are cheaper than writes. The 9-patch series, authored by Karthik Nayak with extensive review from Patrick Steinhardt, includes preparatory cleanups, backend infrastructure changes, and the final user-facing feature.

The series standardizes reference backend operations by consolidating `pack_refs` and `optimize` functions into a unified `optimize` callback. Recent patches have focused on renaming and structural consistency - the latest iteration renames `pack_refs_opts` to `refs_optimize_opts` per Steinhardt's suggestion, with corresponding flag prefix updates. The implementation spans multiple files including the reftable backend, with careful attention to when optimization is truly needed (particularly for reftable's multi-table compaction).

Steinhardt has identified several remaining polish items: documentation should use generic reference store terminology rather than "pack-refs" language, test coverage should leverage existing reftable autocompaction infrastructure, and the `--required` flag's return semantics need explicit documentation (0 when optimization needed, 2 when not). The technical approach is sound after multiple review rounds, with only these final refinements needed before the series can be finalized.
