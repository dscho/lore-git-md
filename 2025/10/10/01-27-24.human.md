Post-series clarification on config file listing behavior.

Kristoffer Haugsbakk adds a precision to the recently completed patch series about global config file handling. The thread had addressed an inconsistency where `git config list --global` only showed `$HOME/.gitconfig` while Git actually reads both that and `$XDG_CONFIG_HOME/git/config`. 

Haugsbakk points out that the original issue description (and thus the series' motivation) only applies when both config files exist - the behavior was specifically about which of multiple existing files get listed, not about cases where only one exists. This doesn't invalidate the series' changes, but provides important context about the scope of the fixed behavior.

The note comes after the series was already reviewed and appears complete, suggesting it's more of a documentation clarification than a request for changes. The thread had already established robust handling of various config file states through its test coverage and platform-specific verification.
