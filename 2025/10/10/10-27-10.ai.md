Refactoring patch in the reftable backend optimization series. This is patch 6/9 in a series adding a `--required` flag for `git refs optimize` to support GitLab's Gitaly service needs.

The patch modifies `reftable/stack.c` to have `stack_table_sizes_for_compaction()` directly return compaction segments rather than just sizes. This eliminates an intermediate step where sizes were being passed to `suggest_compaction_segment()`. The change makes the code more direct and prepares for future functionality to check if auto-compaction is needed without performing it.

Key technical changes:
- Renames function to `stack_segments_for_compaction()`
- Now returns a `struct segment` directly via out parameter
- Handles memory allocation errors more cleanly
- Maintains same core logic for calculating table sizes and compaction segments
- Updates `reftable_stack_auto_compact()` to use the new interface

The change appears well-contained and motivated by the series' overall goal of optimizing reference backend operations. It follows the pattern seen in earlier preparatory patches of cleaning up interfaces before adding new functionality. The patch maintains the existing behavior while making the code more reusable for the upcoming `--required` flag implementation.
