This is a refactoring patch that's part of a larger series to add a `--required` flag for `git refs optimize`. It's the first of nine patches that will eventually introduce functionality to check if reference backends need repacking without actually performing the optimization.

The patch standardizes how different Git reference backends handle optimization by consolidating around the `.optimize` function in `struct ref_storage_be`. Previously, some backends used `.pack_refs` while others used `.optimize`, even though they performed similar functions. The changes touch four backend implementations (debug, files, packed, and reftable) to remove the redundant `.pack_refs` function and ensure all use `.optimize` consistently.

The changes are purely internal - no user-facing functionality is altered. The commit message explains this is preparatory work for later patches in the series. The diff shows straightforward mechanical changes to function names and call sites, with no behavioral modifications. This appears to be a clean, focused refactoring that improves code organization before adding new features.
