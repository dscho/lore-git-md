Junio Hamano provides suggested wording improvements for the documentation patch about `git blame --incremental` output fields. This is part of the ongoing thread clarifying the "sourceline" and "resultline" fields in blame's incremental output format.

The key changes proposed are:
1. More precise definitions of the fields:
   - "sourceline" as "the line number in the file in the above blamed commit"
   - "resultline" as "the line number in the file, where the line is found in the starting <rev>"
2. Correction of a typo ("stating" -> "starting")
3. Continued use of SHA-1 terminology (though earlier noted as a separate issue from this documentation fix)

This follows up on previous feedback about making the documentation more technically accurate regarding blame's behavior across historical revisions. The suggestions aim to clarify the relationship between line numbers in the original blamed commit versus the revision being examined, while maintaining consistency with existing `--help` text that uses "annotated state" terminology.

The changes remain focused on documentation precision without altering any functionality. The thread shows careful attention to getting the explanation right for users who need to parse the incremental blame output format programmatically.
