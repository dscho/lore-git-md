This is part 7 of a 9-patch series introducing a `--required` flag for `git refs optimize` to support GitLab's Gitaly service needs. The patch adds infrastructure to check if reftable optimization is needed without performing it.

The patch introduces `reftable_stack_compaction_required()`, a new function that checks whether the reftable backend would benefit from optimization. The function uses the same heuristics as the existing auto-compaction logic but only reports whether compaction would occur rather than performing it. The implementation checks if there are at least 2 tables in the stack and uses `stack_segments_for_compaction()` (refactored in patch 6) to determine if compaction would be beneficial.

The change includes unit test updates in `u-reftable-stack.c` that verify the new function's behavior during auto-compaction scenarios. Tests now check both the table count and the `required` flag's state at each step of a multi-table addition sequence. The patch maintains the series' focus on preparing the final `--required` flag implementation while keeping the reftable backend's existing behavior intact.

Key technical details:
- New function signature: `int reftable_stack_compaction_required(struct reftable_stack *st, bool *required)`
- Returns 0 on success, populating `required` with compaction need
- Uses same segment-based compaction logic as auto-compaction
- Test coverage verifies flag behavior during table additions
- Builds on previous stack segment refactoring from patch 6

This is a well-contained preparatory change that cleanly separates the compaction check from execution, setting up the final flag implementation in patch 10. The test modifications demonstrate thorough consideration of edge cases and integration with existing behavior.
