This is part of the ongoing series to add a `--required` flag for `git refs optimize`, primarily targeting performance optimizations for GitLab's Gitaly service. Patch 8 introduces the core infrastructure by adding an `optimize_required` field to `struct ref_storage_be` and implements it across all reference backends (debug, files, packed, and reftable).

The new `optimize_required_fn` function type allows checking if optimization is needed without performing it, which will be exposed to users in a subsequent patch. Each backend implements this differently: the files backend delegates to `should_pack_refs()`, the packed backend always returns false (since packed refs are already optimized), and the reftable backend uses the `reftable_stack_compaction_required()` function introduced in patch 7. The debug backend wraps the underlying backend's implementation with tracing.

The changes span multiple backend implementations and `refs-internal.h`, maintaining consistency with the series' goal of separating optimization checks from execution. This is a foundational change that enables the actual `--required` flag functionality while keeping the existing optimization behavior intact. The patch follows the series' pattern of thorough backend coverage and appears to be well-integrated with the preparatory refactoring done in earlier patches.
