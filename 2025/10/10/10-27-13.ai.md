This is the final patch in a series introducing a `--required` flag for `git refs optimize` and `git pack-refs`. The flag allows checking whether reference optimization is needed without actually performing it, which is particularly valuable for server-side maintenance where read operations are cheaper than writes.

The patch adds the user-facing `--required` flag to both commands' documentation and implements the core functionality through a new `refs_optimize_required()` function that checks optimization need via each backend's `optimize_required` method (prepared in earlier patches). The implementation returns exit code 0 when optimization is required, making it suitable for scripting. 

For the files backend, a test verifies the flag works as expected by checking the auto-compaction threshold (16 refs triggers optimization). The reftable backend's behavior is covered by unit tests from earlier in the series. The patch also includes minor documentation updates and usage string adjustments to accommodate the new flag across both commands.

This completes the series' goal of enabling GitLab's Gitaly service to efficiently check when reference optimization is needed before performing potentially expensive write operations. The changes touch command interfaces (`builtin/pack-refs.c`, `builtin/refs.c`), core refs infrastructure (`refs.c`, `refs.h`), and add tests while maintaining backward compatibility.
