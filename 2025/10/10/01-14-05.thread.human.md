This thread is about Delilah Ashley Wu’s three-patch series to fix a long-standing inconsistency in Git’s global config handling, where `git config list --global` only read `$HOME/.gitconfig` despite Git actually reading both that file and `$XDG_CONFIG_HOME/git/config`. The series has addressed all prior feedback, and the maintainer, Junio C Hamano, has now reviewed the final patch, finding it technically sound but suggesting structural and stylistic improvements for better maintainability.

The core issue is now resolved: the series correctly implements scoped config reading by reusing Git’s existing `do_git_config_sequence()` infrastructure, adding flags to restrict config reads to the global scope, and ensuring `--global` operations read both config files. Johannes Schindelin has reviewed the technical aspects of all three patches, and Junio has confirmed the design intent—though he now proposes consolidating config-scope filtering logic into `config_options` rather than scattering it across functions. For example, `git_config_system()` currently checks the `GIT_CONFIG_NOSYSTEM` environment variable separately from the `ignore_system` flag in `config_options`, which Junio suggests unifying. He also flags a misleading conditional (`if (!opts->ignore_global)`) that is always true, as well as line-wrapping issues and a convoluted ternary logic cascade that could be replaced with a clearer `else if` clause.

The series is nearly ready for integration, pending these refinements. The only remaining open questions are whether to keep the Windows path normalization in patch 1 (which Junio still questions) and how to structure the config-scope filtering logic. Delilah has already addressed all other feedback, including test methodology and a temporary regression, and the maintainer’s latest review does not introduce new functional concerns—just opportunities to make the code cleaner and more consistent with Git’s existing patterns. The thread remains active but is now focused on these final polish items.
