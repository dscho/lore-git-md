Delilah Ashley Wu's patch series to fix Git's global config file listing inconsistency is progressing toward a non-RFC state after initial maintainer feedback. The series addresses a known discrepancy where `git config list --global` only showed `$HOME/.gitconfig` while Git actually reads both that and the XDG config file (`$XDG_CONFIG_HOME/git/config`). 

Wu has acknowledged Junio Hamano's observation that this inconsistency exists "without good reason" and will include this point in her v2 cover letter. She clarified that the [RFC] tag was unintentional (resulting from a GitHub draft PR) and will be removed in the next version. Johannes Schindelin has consistently approved the technical approach with Reviewed-by tags, while Junio has raised more detailed concerns about Windows path normalization implementation and test methodology.

The discussion revealed a temporary regression in handling unreadable config files that Wu plans to address in the next patch. Junio suggested an alternative approach that might avoid this regression entirely, which Wu is considering. She has confirmed the specific conditions under which the original discrepancy occurs (when both config files exist) and will incorporate Junio's feedback on test improvements, including using `test_expect_failure` for negative assertions and restructuring tests for clarity. The series remains technically sound but awaits resolution on the finer points of Windows path handling before finalization.
