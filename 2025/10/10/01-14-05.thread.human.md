This thread is about Delilah Ashley Wu’s three-patch v2 series fixing a long-standing inconsistency in Git’s global config handling: `git config list --global` only read `$HOME/.gitconfig` while Git actually reads both that and `$XDG_CONFIG_HOME/git/config`. The series has addressed all prior feedback except for one remaining discussion point.

The core fix modifies `config_sequence()` in `config.c` to read both global config files when the `--global` flag is used, reusing existing infrastructure to avoid duplication. Patch 2 (the focus of this latest email) adds error-handling infrastructure, including a `success_count` counter and a `require_successful_config` flag to ensure `--global` operations fail if no config files are readable. Johannes Schindelin has reviewed the technical aspects of all three patches, while Junio C Hamano has raised concerns about the necessity of patch 1’s Windows path normalization and, in this latest email, suggested minor naming improvements for a helper function in patch 2.

The series is now technically complete and ready for integration, pending resolution of the Windows path normalization discussion in patch 1. Junio’s latest feedback is surface-level (naming and style) and doesn’t block progress. The maintainer has already confirmed the design intent—this was an unintentional discrepancy, not a deliberate choice—and no changes are needed to the write-side behavior (e.g., `--global --edit` still writes to only one file). The only open question is whether patch 1’s Windows-specific changes are truly required for the fix.
