This thread is about Delilah Ashley Wu’s three-patch series fixing a long-standing inconsistency in Git’s global config handling: while Git reads both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config`, `git config list --global` only showed the former. The series has now addressed all prior feedback—narrowing Windows path normalization, reordering patches to avoid regressions, and squashing test-only changes—and is technically complete with Reviewed-by tags from Johannes Schindelin on all three patches.

The core fix modifies `config_sequence()` in `config.c` to read both files when the global scope is requested, using existing infrastructure and adding flags to restrict config reading to the global scope. Tests verify the fix and edge cases, including unreadable files. Junio C Hamano’s earlier concerns about path normalization, test methodology, and temporary regressions have all been resolved, and the series is now ready for maintainer integration.

Chris Torek’s recent comment raises a related but separate question: which file does `git config --global --edit` currently edit, and which *should* it edit? This is a natural follow-up, as the edit operation is the write-side counterpart to the read-side fix. The question doesn’t challenge the series’ implementation but instead highlights a potential edge case that might need similar consistency work in the future. No action is required on the current series, but the point is worth noting for anyone extending the fix later.
