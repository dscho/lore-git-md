This thread resolves a long-standing inconsistency in Git’s global configuration handling. The issue was that `git config --global list` only showed settings from `$HOME/.gitconfig`, while Git actually reads both that file and `$XDG_CONFIG_HOME/git/config`. Delilah Ashley Wu’s three-patch series fixes this by ensuring `--global` operations read both files, aligning the behavior with Git’s documented design.

The series is now complete, with all feedback addressed. Johannes Schindelin has reviewed the technical implementation across all patches, and Junio C Hamano has confirmed the fix aligns with Git’s original migration-friendly design for the read path. The write path (`--global --edit` or `--global set`) remains unchanged—it still writes to only one file (`$HOME/.gitconfig` unless the user has explicitly migrated)—so no follow-up work is needed there. The implementation reuses existing config-reading infrastructure, avoids regressions, and maintains backward compatibility.

With Junio’s clarification that the discrepancy was unintentional and no further objections raised, the series is ready for integration. The key files touched are `config.c`, `builtin/config.c`, and the test scripts `t1300-config.sh` and `t1306-xdg-files.sh`. No new CLI options or on-disk format changes were introduced.
