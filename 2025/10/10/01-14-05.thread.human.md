This thread resolves a long-standing inconsistency in Git's configuration handling: `git config list --global` previously only showed settings from `$HOME/.gitconfig`, while Git actually reads both that file and `$XDG_CONFIG_HOME/git/config` when applying global configuration. Delilah Ashley Wu's three-patch series fixes this by making `--global` operations respect both files, matching the documented behavior.

The solution is clean and minimal. Patch 1 handles Windows path normalization for XDG config paths (already reviewed by Johannes Schindelin), patch 2 builds the necessary infrastructure with error handling and success tracking, and the just-posted patch 3 completes the work by enabling the fix. The implementation reuses `do_git_config_sequence()` with new scope-restriction flags rather than duplicating config-file reading logic, ensuring consistency between scoped and unscoped commands. Tests verify the fix works for both readable and unreadable config files.

Johannes Schindelin has reviewed the technical aspects of all three patches, and Wu has addressed all prior feedback from Junio C Hamano about path normalization, test methodology, and temporary regressions. The series is now complete and appears ready for maintainer review. The only remaining questions are about migration implications and whether the error-handling behavior fully satisfies Junio's concerns, but the core change is uncontroversial since it simply aligns `--global` behavior with what users already expect.
