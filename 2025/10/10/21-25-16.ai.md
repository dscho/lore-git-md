This is a follow-up in the thread about standardizing Makefiles for Git credential helpers in the contrib directory. Junio C Hamano points out a technical issue with Thomas Uhle's patch submission format - the email was sent with "format=flowed" which can corrupt whitespace when applying the patch with `git am`. This is a common pitfall when using certain mail clients that automatically reformat text.

The warning message shown indicates that spaces at the end of lines might be lost during patch application, which could potentially cause problems for Makefiles where whitespace can be significant. This isn't a critique of the patch content itself (which was about standardizing the libsecret and osxkeychain credential helper Makefiles), but rather about the submission mechanics.

The email serves as a gentle reminder about proper patch submission formatting, an important aspect of Git contribution workflow. It doesn't address the ongoing discussion about $(MAIN) variable naming or target placement in the Makefiles, keeping those threads separate from this technical submission note.
