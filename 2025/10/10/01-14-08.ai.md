This is the third patch in a series fixing Git's global config file handling, specifically addressing how `git config list --global` displays both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config` entries. The patch modifies `config_sequence()` in config.c to properly handle global scope by reading both config files when `--global` is specified, rather than just the home directory file.

Key technical changes include:
- Adding `ignore_system` and `ignore_global` flags to `struct config_options`
- Modifying `do_git_config_sequence()` to respect these flags and properly handle global scope
- Updating `builtin/config.c` to set appropriate ignore flags when `--global` is used
- Adjusting tests in t1300-config.sh and t1306-xdg-files.sh to expect the new behavior (changing `! test_cmp` to `test_cmp` where appropriate)

The patch introduces a known regression where `git config list --global` no longer fails when both global config files are unreadable (marked with test_expect_failure). This will be addressed in the next patch. The implementation follows Glen Choo's suggested approach from the original bug report and has already received a Reviewed-by from Johannes Schindelin.

The changes maintain backward compatibility for write operations by still populating `opts->source.file` with the home directory location, as this serves as the write destination. The patch is well-documented with implementation notes explaining the design decisions and potential areas for feedback.
