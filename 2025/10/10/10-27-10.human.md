Refactoring patch in the reftable optimization series. This is patch 6/9 in a series that's adding a `--required` flag to `git refs optimize` for GitLab's Gitaly service.

The patch modifies the reftable stack implementation to return compaction segments directly rather than intermediate size calculations. The change simplifies `reftable_stack_auto_compact()` by having `stack_table_sizes_for_compaction()` (renamed to `stack_segments_for_compaction()`) handle both size calculation and segment suggestion in one step. 

This is a preparatory change that enables future work where the same segment calculation will be needed for checking if optimization is required without performing it. The implementation looks clean - it maintains the same functionality while reducing intermediate allocations and simplifying the calling code. The change is well-contained to the reftable backend and follows the series' pattern of refactoring before adding new features.
