This is a feature patch series introducing a new `--required` flag for `git refs optimize`, aimed at optimizing reference backend operations in GitLab's Gitaly service. The series stems from a specific performance optimization need in Gitaly's transaction manager, where read snapshots are cheaper than write snapshots for housekeeping operations.

The series begins with several cleanup patches (1-4) addressing code organization and naming following the introduction of `git refs optimize`. Patch 5 fixes a documentation test to properly handle subcommands. The core functionality is built in patches 6-8, which add infrastructure to check if optimization is needed without performing it, including changes to the reftable stack and refs backend interfaces. The final patch (9) exposes this as the new `--required` flag.

The changes touch multiple backend implementations (files, packed, reftable) and their internal APIs, adding a new `optimize_required` field to `struct ref_storage_be`. Test coverage appears thorough, with updates to existing tests and new checks in `t1463-refs-optimize.sh`. The series builds on recent work around ref optimizations and peeled tags.
