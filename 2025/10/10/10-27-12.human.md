Feature implementation for reference backend optimization checks. This is patch 8/9 in a series introducing a `--required` flag for `git refs optimize`, primarily to support GitLab's Gitaly service where checking optimization need is cheaper than performing it.

The patch adds an `optimize_required` function pointer to `struct ref_storage_be`, implementing it for all four backends (debug, files, packed, and reftable). Each backend gets a tailored implementation: the packed backend always reports no optimization needed (since packed refs are already optimized), while the files and reftable backends use their existing optimization heuristics to determine need without performing the operation. The reftable implementation builds on the new `reftable_stack_compaction_required()` function from patch 7.

This is a clean, mechanical change that follows the series' pattern of interface consolidation. The implementation looks straightforward and well-tested, with each backend getting appropriate behavior. The next patch will presumably expose this functionality through the `git refs optimize` command line interface. The series continues to make steady progress toward its goal of supporting GitLab's performance optimization needs while improving Git's internal refs architecture.
