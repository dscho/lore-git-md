This is a discussion about naming the new repository statistics command in the ongoing `git repo stats` series.

Justin Tobler is reconsidering the command name after Junio Hamano raised concerns about the vagueness of "stats" and suggested a more targeted approach. Justin acknowledges that while a single command provides a simple way to generate a general repository report, the name "stats" may be too broad. He proposes alternatives like `git repo structure` that better reflect the command's purpose of showing repository characteristics that impact performance or are otherwise noteworthy.

The discussion highlights a philosophical difference in approach - Justin favors comprehensive reporting for sharing repository snapshots, while Junio leans toward more focused, composable commands. This naming question comes after the technical implementation (reference counting, object statistics, output formats) has been largely worked out in previous patches. The thread shows the project's careful consideration of both technical implementation and user-facing design.
