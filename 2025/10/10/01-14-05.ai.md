This is a feature/bugfix patch series addressing an inconsistency in Git's config file behavior. The series aims to make `git config list --global` show both `$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config` files, matching the documented behavior and actual config application logic.

The issue stems from Git correctly applying configs from both locations but only showing the home directory config with `--global`. The series includes preparatory cleanup (Windows path normalization), test coverage, and the core fix to read both config files in global scope. The implementation appears careful, with tests verifying both the regression and fix.

Key technical details:
- Modifies `config_sequence()` in config.c to handle global scope properly
- Adds new assertions in t1300-config.sh and t1306-xdg-files.sh
- Preserves existing error handling for unreadable files
- Windows path normalization in path.c affects config file path handling

The patch has already undergone GitHub-based review from Johannes Schindelin with only commit message tweaks since. The change aligns with documented behavior and appears uncontroversial, though the Windows path changes might warrant platform-specific scrutiny.
