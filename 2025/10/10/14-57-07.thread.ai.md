Thread summary:

Bug report and fix addressing Git's pattern matching behavior for double-asterisk (`**`) in `.gitignore` files, where patterns like `foo**/bar` incorrectly matched paths like `foobar` despite documentation stating `**` must be surrounded by slashes for special meaning. The issue stems from `match_pathname()`'s optimization that strips matching prefixes before `fnmatch()`, losing directory boundary context. 

The proposed solution modifies `dir.c` to preserve one character when passing to `fnmatch()`, preventing false matches while maintaining optimizations for non-wildcard patterns. A new test in `t/t0008-ignores.sh` verifies the fix. Jeff King reviewed the patch as RFC, calling it a "disgusting hack" but acknowledging it correctly addresses the core issue while noting potential edge cases. The change impacts pathspec matching in `.gitignore` and `.gitattributes`, aligning Git with both its documented behavior and JGit's interpretation. Performance impact appears minimal though further optimization of the prefix-matching approach may be possible. The thread remains open pending resolution of Jeff King's concerns about implementation approach and edge case handling.
