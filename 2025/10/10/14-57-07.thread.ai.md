Thread summary:

Bug report concerning Git's pattern matching behavior for double-asterisk (`**`) in `.gitignore` files, specifically when asterisks appear mid-pattern without surrounding slashes. The current implementation matches `foobar` against `foo**/bar`, while documentation states double asterisks must be surrounded by slashes to have special meaning (e.g. `**/foo`). Core question is whether this is an implementation bug or documentation gap. Issue originated from eclipse-jgit where behavior was observed, with clear references to both observed behavior and relevant docs. Impacts users relying on precise pattern matching across Git/JGit implementations. Needs maintainer input to determine if behavior is intended (requiring doc updates) or unintended (requiring code fixes). Likely touches pathspec matching logic in Git core.
