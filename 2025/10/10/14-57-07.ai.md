This is a bug report concerning pattern matching behavior in Git that appears to contradict the documented behavior for double-asterisk patterns in `.gitignore` files.

The reporter points to a GitHub issue in eclipse-jgit where a user noticed that Git matches the path `foobar` against the pattern `foo**/bar`, while the Git documentation states that double asterisks (`**`) must be surrounded by slashes to have special meaning. The documentation specifically says "A leading `**` followed by a slash means match in all directories" and gives examples like `**/foo`, but does not mention cases where asterisks appear mid-pattern without slashes.

The core of the report is determining whether this is:
1. A bug in Git's pattern matching implementation that incorrectly handles mid-pattern double asterisks without slashes, or
2. An inaccuracy in the documentation that fails to describe this valid pattern case

The issue appears to involve the pathspec matching logic in Git's core, potentially touching how wildcards are processed in `.gitignore` patterns. The reporter provides clear references to both the observed behavior (via the JGit issue) and the relevant documentation section, making this easy to verify.

This could be significant for users relying on precise pattern matching behavior, particularly those working across Git and JGit implementations. The next step would be for a Git maintainer to confirm whether the current behavior is intended (requiring doc updates) or unintended (requiring code fixes).
