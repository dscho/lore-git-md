Test refactoring to improve whitespace consistency checks in command documentation.

This patch modifies the test in `t0450-txt-doc-vs-help.sh` that verifies consistent whitespace indentation in command help text. The original test assumed all indented lines in a command's help text should use the same number of spaces, but this breaks down for commands with subcommands (like `git refs`) where different subcommands may have different indentation levels.

The new implementation tracks indentation separately for each subcommand by using awk to count subcommands and record their individual indentation patterns. This provides more accurate validation while maintaining the original goal of catching inconsistent formatting. The change is part of a larger series introducing optimizations to Git's reference backend, though this particular patch focuses solely on test infrastructure improvements.

The implementation looks solid, with a clear explanation of the problem and solution in the commit message. The test change itself is straightforward, replacing a simple whitespace count with a more sophisticated awk-based approach that handles subcommands properly. This should help maintain documentation consistency while accommodating Git's increasingly complex command structures.
