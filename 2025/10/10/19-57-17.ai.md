This is part 8 of Adrian Ratiu's hook subsystem refactoring series, focusing on converting the receive-pack 'update' hook to use the new `hook.h` infrastructure. The patch introduces sideband output handling for the update hook through a new `hook_output_to_sideband` callback function.

The key technical change replaces the direct child process management with the new `run_hooks_opt` API, while adding sophisticated sideband output processing that includes keepalive handling. The implementation now supports three keepalive modes (never, always, after-NUL) and properly chunks output around NUL character boundaries when using the after-NUL mode.

Emily Shaffer raises a concern about the introduction of keepalive functionality where it wasn't present before, questioning whether this might affect sideband consumers who aren't expecting keepalive packets. This appears to be a new behavior that wasn't documented in the githooks documentation, potentially representing a subtle behavior change.

The patch maintains the same hook arguments (refname, old_oid, new_oid) but routes them through the new `run_hooks_opt.args` interface. The sideband output handling is now more robust, with explicit handling of empty output (triggering keepalives when configured) and proper NUL-character splitting in the output stream.

This continues the series' pattern of converting individual hooks to the new infrastructure while adding capabilities like sideband support. The keepalive behavior appears to be a new feature that wasn't present in the original hook implementation, which may warrant either documentation updates or reconsideration of whether it's appropriate for this particular hook.
