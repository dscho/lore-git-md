This is a documentation refinement in response to review feedback about clarifying `git blame --incremental` output format. Junio Hamano provides suggested wording improvements for the patch that explains the "sourceline" and "resultline" fields in the blame output.

The key changes proposed are more precise definitions of these fields: "sourceline" should be described as "the line number in the file in the above blamed commit" (where the line originated), while "resultline" becomes "the line number in the file, where the line is found in the starting <rev>" (its current position). This replaces the previous less precise wording about "when the commit was made" and "current state".

The suggestions aim to make the documentation technically accurate about how blame operates across historical revisions, while maintaining clarity. This continues the thread's focus on properly documenting these previously-undocumented fields that had caused user confusion. The changes remain purely documentation-focused with no code impact.
