Bugfix patch completing the series to align `git config list --global` behavior with actual config file reading.

This final patch in the series fixes a regression introduced in the previous patch where `git config list --global` would incorrectly succeed when both global config files (`$HOME/.gitconfig` and `$XDG_CONFIG_HOME/git/config`) were unreadable. The patch restores the expected behavior of failing in this case while still succeeding when at least one global config file is readable.

Key technical details:
- Adds logic in `do_git_config_sequence()` to track successful reads of global config files via `global_config_success_count`
- Introduces `nonzero_ret_on_global_config_error` flag based on scope to determine when to enforce the failure condition
- Modifies the return value via a simple decrement`--ret` when both global configs fail (alternative approach of summing return codes is noted but not implemented)
- Updates tests in t1300-config.sh to remove the `test_expect_failure` markers since the regression is now fixed

The implementation maintains the series' goal of making config listing behavior match actual config reading behavior while preserving backward compatibility. With Johannes Schindelin's review and platform-specific verification, this appears to be a solid conclusion to the series, resolving the last known issue from the previous patch. The changes are focused and well-tested, with clear commit message documentation of both the problem and solution.
