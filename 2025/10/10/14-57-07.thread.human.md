This thread addresses a bug in Git's handling of double-asterisk (`**`) patterns in `.gitignore` files, where patterns like `foo**/bar` were incorrectly matching paths like `foobar` despite documentation stating `**` must be surrounded by slashes for special meaning. Jeff King (Peff) identified the root cause in `dir.c`'s `match_pathname()` function, which strips matching prefixes before `fnmatch()` calls, losing directory boundary context. He proposed an RFC patch that preserves one character of context as a targeted fix, calling it a "disgusting hack" that solves the immediate issue while maintaining optimization benefits for non-wildcard patterns. A test case was added to `t/t0008-ignores.sh`.

The fix impacts both `.gitignore` and `.gitattributes` matching, aligning Git with its documented behavior and JGit's interpretation. Performance impact appears minimal, though further optimization may be possible. Sruteesh Kumar recently chimed in to acknowledge Jeff's solution works but expressed concern about potential regressions, requesting wider community review. The thread remains open as the implementation approach undergoes scrutiny, though the core technical solution appears sound. This affects a subtle but important edge case in pattern matching behavior that had diverged from both documentation and user expectations.
