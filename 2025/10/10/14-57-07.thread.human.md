This thread addresses a bug in Git's pattern matching where `**` in `.gitignore` and `.gitattributes` files was incorrectly matching paths like `foobar` when the pattern was `foo**/bar`, despite documentation stating `**` must be surrounded by slashes for special meaning. The issue stems from an optimization in `match_pathname()` that strips prefixes before pattern matching, losing directory boundary context.

Jeff King (Peff) proposed an RFC patch that fixes this by preserving one character of context when passing to `fnmatch()`, preventing false matches while maintaining optimizations. He acknowledged it as a "disgusting hack" that correctly solves the core issue. Sruteesh Kumar responded positively but sought wider feedback on potential regressions.

Maintainer Junio Hamano has now reviewed the solution, suggesting two refinements: moving the "whole pattern" check before prefix stripping for cleaner logic, and considering a more targeted fix that only adjusts prefixes for `**/` patterns. Junio notes the performance benefit of aggressive prefix stripping may be minimal beyond non-wildcard cases. The test in `t/t0008-ignores.sh` verifies the fixed behavior where `foo**/bar` should match `foo/bar` but not `foobar`.

The discussion continues to weigh Jeff's general solution against potentially simpler targeted approaches, with no new edge cases identified. The change would align Git's behavior with both its documentation and JGit's interpretation. While the RFC appears sound, the thread remains open as Junio and others consider whether to refine the implementation approach before merging.
