This thread addresses a subtle bug in Git's pattern matching behavior for `.gitignore` and `.gitattributes` files, where patterns like `foo**/bar` were incorrectly matching paths like `foobar`. Jeff King (Peff) diagnosed the issue in `match_pathname()` and proposed an elegant "minusone" solution that preserves optimization benefits while fixing the matching logic. The fix was implemented in a two-patch series that has been reviewed and is ready for merging.

The discussion then turned to documentation, with D. Ben Knoble raising concerns about differences between gitignore patterns and pathspec matching behaviors. Jeff clarified these differences: pathspecs are implicitly anchored and allow `*` to cross directory boundaries, while gitignore patterns are not. While the current pathspec documentation is acknowledged to be complex, Jeff cautions against immediate changes due to backward compatibility concerns. The core gitignore fixes remain complete and merge-ready, with pathspec documentation questions noted as potential future work. The thread demonstrates Git's careful approach to both technical correctness and user understanding, even for subtle edge cases in pattern matching.
