This thread addresses a bug in Git's handling of double-asterisk (`**`) patterns in `.gitignore` files, where patterns like `foo**/bar` incorrectly match paths like `foobar` despite documentation stating `**` must be surrounded by slashes to have special meaning. The issue stems from an optimization in `match_pathname()` that strips too much prefix before calling `fnmatch()`, losing directory boundary context.

Jeff King initially submitted a fix (which he later clarified was meant as an RFC) that modifies `dir.c` to preserve one character when passing to `fnmatch()`, preventing false matches while maintaining optimizations. He described the solution as a "disgusting hack" that works but may need refinement for edge cases. The patch includes a new test in `t/t0008-ignores.sh` and affects pathspec matching in both `.gitignore` and `.gitattributes`.

The thread remains open as Jeff King's technical concerns about the implementation approach and edge case handling are still being discussed. The fix would align Git's behavior with both its documented semantics and JGit's interpretation, with minimal performance impact.
