This thread examines a discrepancy between Git's documented and actual behavior regarding double-asterisk (`**`) patterns in `.gitignore` files. A user reported that Git matches `foobar` against `foo**/bar`, while the documentation states double asterisks must be surrounded by slashes to have special meaning (as in `**/foo`). The core question is whether this represents a bug in Git's pattern matching implementation or an undocumented feature.

The issue touches Git's pathspec matching logic and could affect users relying on precise pattern matching behavior, particularly those working across Git and JGit implementations. The reporter provided clear references to both the observed behavior (via a JGit issue) and the relevant documentation. The thread awaits maintainer input to determine if this requires code fixes or documentation updates.
