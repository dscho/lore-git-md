This thread addresses a bug in Git's pattern matching where double-asterisk (`**`) in `.gitignore` and `.gitattributes` files incorrectly matches paths like `foobar` when the documentation specifies `**` must be surrounded by slashes. Jeff King (Peff) initially proposed an RFC patch to fix this by preserving one character of context in `dir.c`'s prefix-stripping optimization, calling it a 'disgusting hack' that works. Junio Hamano reviewed it, suggesting alternative approaches like moving the full-match check earlier or targeting only `**/` patterns. Sruteesh Kumar then questioned the optimization's value entirely, preferring Jeff's general solution despite its hackiness.

Jeff has now provided benchmark data showing the prefix-stripping optimization provides real performance benefits (1.46x faster for exact matches), with his one-character context approach performing equivalently to the original while fixing the bug. The data supports keeping the optimization with his adjustment, as it maintains speed while correcting the documented behavior. This shifts the discussion from theoretical concerns to concrete evidence favoring Jeff's solution, though the thread remains in RFC status as participants consider the implications. The fix would align Git's behavior with both its documentation and JGit's interpretation of the pattern matching rules.
