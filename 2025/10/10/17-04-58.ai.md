This is the second patch in a documentation series improving `git worktree` usage guidance, specifically focusing on demonstrating safe patterns for side-by-side branch checkouts from bare repositories.

The patch adds a new example to `git-worktree.txt` showing how to set up parallel worktrees from a bare repository clone. The example demonstrates:
1. Creating a bare clone (`some-repository.git`)
2. Adding two worktrees (`some-branch` and `another-branch`) using explicit `--git-dir` references
3. Using sibling directory structure (rejecting the previously suggested subdirectory approach)

Key technical details:
- The example enforces the safety requirement of using `--git-dir` when working with bare repositories
- Follows the maintainer's preference for sibling directory layout over nested structures
- Builds on prior discussion about bare repository worktree safety constraints
- Maintains consistency with the documentation formatting standards established in the thread (cross-references, anchors, placeholders)

The patch addresses feedback from Kristoffer Haugsbakk by removing the intermediate `mkdir` step, though the motivation text for bare repository usage (another requested addition) is not yet included. The maintainer has already queued the first patch in this series, and this second patch appears close to final form pending minor refinements.

The example serves as a concrete reference for the safe usage patterns discussed earlier in the thread, particularly the rejection of worktree subdirectories in bare repos due to potential conflicts with Git's internal structures. The explicit `--git-dir` usage provides a clear pattern for avoiding such conflicts.
