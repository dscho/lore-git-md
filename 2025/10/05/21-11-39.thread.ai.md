Standardizing Git documentation formatting - part 3 (git-stash, git-tag, git-worktree)

Jean-Noël Avila's documentation patch series converts man pages for `git-stash`, `git-tag`, and `git-worktree` to use Asciidoc's synopsis block format, completing this standardization effort for these commands. The series consists of three mechanical formatting patches with no content changes: the first updated `git-stash` (+85/-78 lines), the second converted `git-tag` (+104/-78 lines including config documentation), and this final patch standardizes `git-worktree` (+161/-84 lines for main command, +14/-14 for config).

All patches follow the same transformation pattern: converting verse-formatted synopses to synopsis blocks (enabling automatic styling), standardizing option formatting with backticks, replacing angle brackets with underscores for placeholders (`<placeholder>` -> _<placeholder>_), and properly including config sections in main man pages via conditional includes (`ifdef::git-command[]`). The work maintains existing functionality while improving consistency with project documentation standards, particularly for command syntax highlighting and placeholder notation. 

Technical details include updates to `git-stash.adoc`, `git-tag.adoc` (plus `tag.adoc` config), and `git-worktree.adoc` (plus `worktree.adoc` config), with standardized formatting applied to all subcommands and options. The series was submitted via GitGitGadget, indicating the author's GitHub-based workflow preference. This work continues Jean-Noël Avila's ongoing project-wide effort to convert Git documentation to consistent Asciidoc synopsis style, building on prior updates to numerous other commands' man pages.
