Standardizing Git documentation formatting - part 3 (git-stash, git-tag, git-worktree)

This documentation patch series converts man pages for `git-stash`, `git-tag`, and `git-worktree` to use Asciidoc's synopsis block format, continuing Jean-Noël Avila's project-wide effort to standardize Git documentation. The first patch focuses on `git-stash`, updating both `git-stash.adoc` and its config documentation in `stash.adoc` with mechanical formatting changes: converting command synopses from verse to synopsis blocks (enabling automatic styling of placeholders and keywords), standardizing option formatting with backticks, replacing angle brackets with underscores for placeholders in prose, adding conditional includes to avoid redundant references, and restructuring sections for better organization. The changes are purely presentational (+85/-78 lines) with no content alterations. The series will follow the same pattern for `git-tag` and `git-worktree`, applying consistent formatting updates to prepare for future documentation tooling improvements. The series arrives via GitGitGadget, indicating the author's preference for GitHub-based workflow over direct mailing list submissions. This work builds on prior documentation standardization efforts that have updated numerous commands' man pages.
