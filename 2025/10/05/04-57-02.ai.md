Bugfix for gitweb configuration path handling. This email reports an issue where gitweb fails to find the `gitweb_config.perl` configuration file when run from a web server, producing a "No such file or directory" error. The root cause appears to be Perl's `@INC` path behavior changes, where the current directory (`.`) is no longer included by default.

The reporter found two workarounds: either modifying `gitweb.cgi` to explicitly use `./gitweb_config.perl`, or updating the Makefile to set `GITWEB_CONFIG = ./gitweb_config.perl`. The latter solution proved successful when rebuilding and reinstalling gitweb. The issue was previously reported in Gentoo's bug tracker (bug #675864), suggesting this is a known compatibility problem with newer Perl versions.

The patch is straightforward and addresses a clear runtime failure, though it might be worth considering whether this should be handled more robustly (e.g., by using absolute paths) for production deployments. The change affects the gitweb installation process and CGI execution environment, specifically touching `gitweb.cgi` and the gitweb Makefile.
