Bugfix and test coverage for interactive add's hunk navigation.

This is the final patch in René Scharfe's series fixing and improving hunk navigation in `git add --interactive`. The patch addresses a subtle issue where the `permitted` bitmask (which tracks allowed operations for each hunk) was accumulating state across multiple hunks rather than being reset for each new hunk. Junio Hamano identified this as problematic behavior.

The fix moves the `permitted` bitmask declaration inside the hunk processing loop, ensuring each hunk starts with a fresh set of allowed operations. This prevents state leakage between hunks that could lead to incorrect command availability. The change is accompanied by a new test case that verifies invalid commands (like 's' for split when splitting isn't possible) are properly rejected.

This completes the series' work to make hunk navigation more consistent and predictable. The earlier patches established symmetrical forward/backward movement and clear roll-over behavior, while this final change ensures each hunk's command options are evaluated independently. The test coverage added here complements the extensive navigation tests from previous patches.
