Documentation and UI clarification for interactive add navigation.

This patch from René Scharfe is the first in a series addressing navigation behavior in `git add --interactive`. It focuses specifically on improving the help text for the hunk navigation commands (j/J/k/K) to make their behavior clearer. The key change is removing the potentially misleading phrase "leave this hunk undecided" from the help text, since these navigation commands don't actually affect the current hunk's state - they only move between hunks.

The changes appear in both the user documentation (git-add.adoc) and the runtime help text (add-patch.c), maintaining consistency between them. This is a straightforward documentation improvement that aligns with the broader thread's goal of making hunk navigation behavior more intuitive and consistent.

Technical details:
- Changes help text for four navigation commands (j/J/k/K)
- Maintains distinction between "next hunk" (J/K) and "next undecided hunk" (j/k)
- Updates both documentation and runtime help consistently
- Part of larger effort to clarify and standardize interactive add behavior

This patch appears uncontroversial and well-contained, focusing solely on documentation improvements while the subsequent patches in the series handle the behavioral changes discussed in the thread. The changes are minimal but meaningful for user understanding of the interface.
