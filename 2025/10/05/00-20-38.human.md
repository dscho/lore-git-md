Performance investigation into untracked files cache behavior. Matthew Hughes follows up on the reported issue where `--untracked-files=all` bypasses the untracked cache, negatively impacting tools/IDEs that use this flag. He points to commit e6a653554b which added support for this case when `status.showUntrackedFiles=all` is configured.

Through Linux benchmarks on a large synthetic repo (~100k files), Hughes demonstrates that while the cache=true + --untracked-files=all combination shows no speedup (1.25s), adding status.showUntrackedFiles=all brings the time down to 0.38s - matching the expected cache benefit. This suggests the issue isn't a cache bypass but rather a configuration requirement that tools may need to adopt. The findings confirm the cache works when both config and flag are aligned, though the need for this dual configuration may be non-obvious to users.
