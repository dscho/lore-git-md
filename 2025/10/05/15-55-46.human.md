Bugfix and consistency improvement for interactive hunk navigation in `git add -p`.

This patch (4/5 in René Scharfe's series) completes the unification of hunk navigation behavior in `git add --interactive`. While earlier patches made forward navigation commands (`j`/`J`) roll over at file boundaries, this one makes backward navigation (`k`/`K`) behave symmetrically by wrapping around to the last hunk when moving past the first one.

The change makes the interface more predictable and completes the symmetry between forward/backward movement that was discussed earlier in the thread. The implementation introduces a new `dec_mod()` helper (mirroring the existing `inc_mod()`) to handle the circular navigation logic cleanly.

Documentation and tests are updated to reflect the new behavior. The test changes are particularly thorough, verifying both the new roll-over behavior and ensuring all command prompts now properly show the `k`/`K` options when available. This appears to be a well-considered change that completes the navigation behavior unification started in earlier patches, with no obvious technical drawbacks.
