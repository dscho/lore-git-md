Thread identity: Discussion about deprecation and removal of `git whatchanged`, a legacy command for viewing commit logs with diff output, originally proposed for removal due to being functionally replaced by `git log`.

Core problem: The command is redundant with `git log` (using same machinery but different defaults) and has been effectively obsolete for 12+ years. The discussion focuses on how to deprecate it while minimizing user disruption.

Current status: Removal is proceeding, with plans to improve the deprecation warning to suggest specific alternatives. The command currently requires `--i-still-use-this` flag to suppress deprecation warnings.

Key technical details: `git whatchanged` can be replaced by `git log <opts> --no-merges --raw`, with `--stat` or `--name-only` as alternative output formats for better readability. The underlying diff machinery is identical between both commands.

Open questions: None remaining about whether to remove - focus has shifted to implementation details of the deprecation path. The exact wording of the replacement suggestion in the warning may need refinement.

Participant positions:
- Jeffery Carr initially questioned removal rationale and suggested alternative deprecation approaches (aliases or standalone binary)
- Kristoffer Haugsbakk clarified technical constraints (no built-in alias system) and provided specific replacement command syntax
- Consensus appears to have formed around direct removal with improved warning messaging

Related work: This follows Git's general pattern of removing redundant legacy commands after establishing better alternatives (e.g., `git filter-branch` deprecation). The `--i-still-use-this` deprecation pattern was previously used for other removed commands.
