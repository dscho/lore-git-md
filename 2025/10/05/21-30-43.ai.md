This is part 2 of René Scharfe's v2 patch series fixing and improving interactive add navigation behavior. The patch focuses on formally documenting and implementing roll-over behavior for the 'J' (next hunk) command in `git add --interactive`.

The key changes in this patch:
1. Explicitly documents that 'J' rolls over to the first hunk when at the last hunk, both in the man page (`Documentation/git-add.adoc`) and in the interactive help text (`add-patch.c`).
2. Modifies the hunk navigation logic to check `file_diff->hunk_nr > 1` rather than `hunk_index + 1 < file_diff->hunk_nr`, enabling the roll-over behavior.
3. Updates test cases to include 'J' in the command lists where appropriate.
4. Adds a new test case specifically verifying the roll-over behavior by checking hunk navigation sequence output.

The patch leverages an existing behavior where the `permitted` bitmask isn't reset between hunks, which allows the roll-over to work naturally. While this might appear buggy at first glance, the patch makes it an officially supported feature. The changes maintain consistency with the series' goal of improving navigation behavior symmetry, though it precedes the later introduction of the `inc_mod()` helper that will handle circular navigation more systematically.

Technical details worth noting for future reference:
- The roll-over behavior affects both documentation and implementation
- Test updates touch multiple existing test cases to include 'J' in command lists
- New test `option J rolls over` verifies the specific roll-over behavior
- Changes to `permitted` bitmask handling will be further refined in patch 5 of the series
- The hunk count check change (`file_diff->hunk_nr > 1`) enables the roll-over while maintaining safety
