This is the second patch in René Scharfe's v2 series improving interactive hunk navigation in `git add -p`. The patch focuses on formalizing and documenting the roll-over behavior of the 'J' (next hunk) command when reaching the last hunk.

The key changes are:
1. Explicitly documents that 'J' rolls over to the first hunk when used at the last hunk, updating both the man page and runtime help text
2. Modifies the hunk navigation logic to enable this roll-over by changing the hunk count check from `hunk_index + 1 < file_diff->hunk_nr` to `file_diff->hunk_nr > 1`
3. Adds a new test case verifying the roll-over behavior works as expected
4. Updates several existing tests to include 'J' in their expected output where appropriate

The patch leverages an existing behavior where the `permitted` bitmask isn't reset between hunks, which Junio Hamano noted could be useful for this roll-over case. While this might appear buggy at first glance, the patch makes this behavior intentional and documented for the 'J' command specifically.

Technical changes affect:
- Documentation/git-add.adoc (help text)
- add-patch.c (navigation logic and help string)
- t/t3701-add-interactive.sh (test updates and new roll-over test)

The patch maintains backward compatibility while making the interface more predictable. It's part of the broader effort to improve navigation symmetry between forward/backward movement commands in the interactive add interface.
