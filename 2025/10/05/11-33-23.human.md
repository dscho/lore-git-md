Bugfix clarification for `git clean` pathspec handling with ignored directories.

Devste Devste follows up on their earlier bug report to clarify the core issue: `git clean -X` isn't just failing to respect negated pathspecs, but is completely ignoring pathspec constraints when dealing with ignored directories. The problem manifests when users want to clean only specific ignored file types (like `.rej` or `.log` files) but find Git also targeting entire ignored directories (like `.idea/dictionaries`) that don't contain those file types, despite explicit exclusion in the pathspec.

The clarification emphasizes this isn't a simple negation failure, but a more fundamental issue where directory handling bypasses pathspec filtering entirely during clean operations. This creates a real risk of data loss, as users might see directories unexpectedly marked for deletion in dry runs, even when those directories don't match the specified patterns and are explicitly excluded.

The bug appears in Git 2.51.0 on Windows, but likely affects other platforms. No workaround is mentioned beyond avoiding `-X` with directory exclusions. The report provides clear reproduction steps and maintains the original concern's urgency, as this could lead to unintended directory deletions in real usage.
