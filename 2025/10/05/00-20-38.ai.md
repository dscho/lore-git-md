Performance optimization note regarding untracked files cache behavior. This email from Matthew Hughes investigates the reported issue where `--untracked-files=all` bypasses the untracked cache, confirming the behavior with Linux test case showing 1.25s vs 0.38s difference when using matching config. The key finding is that commit e6a653554b made the cache work with `--untracked-files=all` only when `status.showUntrackedFiles=all` is also set, creating a performance cliff for tools that hardcode the flag without matching config. The test demonstrates this by creating 100k files across nested directories, showing cache is active (3x speedup) only when config and flag align. This suggests the current implementation requires config/flag symmetry for optimal performance, which may not be obvious to users or tool authors. The email doesn't propose a fix but provides concrete reproduction steps that could help diagnose why the cache is bypassed when flags override defaults.
