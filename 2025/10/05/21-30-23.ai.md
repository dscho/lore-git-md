This is a documentation patch in René Scharfe's v2 series improving interactive add navigation behavior. The patch simplifies the help text for hunk navigation commands (j/J/k/K) in `git add --interactive` by removing redundant mentions of "leave this hunk undecided" since these commands only move between hunks without changing their state.

Junio Hamano suggests extending this clarity improvement to the y/n commands as well, noting they both decide the current hunk and move forward - a logical extension of the current patch's theme. The change is straightforward, touching only documentation and help strings while maintaining all existing functionality. This appears to be a well-justified documentation polish that fits naturally with the series' goal of making hunk navigation behavior more transparent.

Key technical details for future reference:
- Modified files: `Documentation/git-add.adoc` and `add-patch.c`
- Changes focus on help text clarity for navigation commands
- j/k move to next/previous undecided hunk
- J/K move to next/previous hunk regardless of state
- Open question about extending similar clarity to y/n commands
- Part of broader effort to formalize and document hunk navigation behavior
