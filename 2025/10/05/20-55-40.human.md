This is a review comment on patch 4/5 of René Scharfe's series fixing interactive hunk navigation in `git add -p`. Junio Hamano suggests two potential improvements to the patch's handling of hunk wrap-around behavior.

First, he questions whether the error message "No previous hunk" is the most accurate phrasing when wrap-around is prevented due to having only one hunk, suggesting "No other hunk(s)" might better convey the situation. He notes this applies equally to both 'K' (previous) and 'J' (next) commands.

Second, he points out an asymmetry in the implementation - while 'K' uses the new `dec_mod()` helper for circular navigation, 'J' still uses a simple increment without `inc_mod()`. He wonders if this inconsistency could be resolved, and whether doing so might allow removal of the overflow check at the start of the loop.

The review is generally positive, calling the resulting code "a very pleasant read," while offering these two specific suggestions for potential refinement. The comments focus on making the interface more consistent and the error messages more precise, continuing the thread's theme of improving navigation symmetry in the patch interface.
