This is a bug report about inconsistent color behavior in `git status --short -z` output. Langbart reports that when using the `-z` flag (which produces NUL-terminated output for machine parsing), the modified file status marker (`M`) incorrectly retains color while the untracked marker (`??`) does not, despite `-z` implying `--no-color`.

The report is well-structured with clear reproduction steps and expected/actual behavior. It references a related patch from 2010 (git@drmicha.warpmail.net) which may have introduced or failed to properly handle this edge case. The inconsistency suggests the color suppression logic isn't being uniformly applied to all status markers when `-z` is active.

This appears to be a legitimate bug that affects scripts parsing `git status -z` output, as the color codes would interfere with machine processing. The reporter is using Git 2.51.0 (a future version at time of writing), indicating this behavior persists in recent releases. The clear reproduction case makes this easy to verify and fix.
