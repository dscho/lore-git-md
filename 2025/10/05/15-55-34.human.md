Bugfix and behavior refinement for `git add --interactive` navigation.

This is the third patch in René Scharfe's series improving hunk navigation in interactive add. It addresses how the 'y', 'n', 'j', and 'e' commands handle roll-over when reaching the end of the hunk list. Previously, these commands would wrap around to the first hunk regardless of its state, which could be confusing. The patch makes them consistently seek the next undecided hunk when wrapping around, matching their behavior when moving forward normally.

The changes include:
1. A new `inc_mod()` helper function for circular hunk navigation
2. Updated documentation clarifying the 'j' command's roll-over behavior
3. Two new test cases verifying the improved roll-over behavior with different command sequences

The patch builds on earlier work in the series that formalized navigation behavior and fixed a regression in hunk state transitions. It maintains backward compatibility of the interface while making it more predictable. The implementation appears clean and well-tested, with clear commit message explaining both the current behavior and the improvement.
