This is a licensing clarification request regarding the ongoing Rust xdiff implementation effort. Yee Cheng Chin raises an important question about the status of xdiff's LGPL license as Rust components are introduced without explicit licensing headers. The concern stems from downstream projects like libgit2, Vim, and Neovim that currently rely on xdiff's LGPL status for compatibility with their own licenses.

The email highlights a potential conflict: if the Rust xdiff components inherit Git's GPL license by default (due to missing headers) rather than maintaining xdiff's LGPL, it could break compatibility for existing users. This comes at a sensitive time when the project is already deep in discussions about Rust code licensing strategies, with multiple proposals on the table (GPLv2+exception vs permissive approaches).

The thread context shows this is part of a broader debate, with Wood having previously expressed concerns about de-facto relicensing through incremental changes. Chin's message adds concrete urgency by pointing out real-world impacts on major projects that depend on xdiff's current licensing. The lack of license headers in the Rust files appears to be an oversight rather than a deliberate choice, but the implications are significant enough to warrant explicit clarification from the maintainers.
