This thread reports a bug in gitweb's configuration path handling that causes runtime failures when the CGI script can't find `gitweb_config.perl`. The issue stems from changes in Perl's default `@INC` path behavior, where the current directory (`.`) is no longer included automatically.

The reporter identified two potential fixes: either modifying `gitweb.cgi` to explicitly reference `./gitweb_config.perl`, or adjusting the Makefile to set `GITWEB_CONFIG = ./gitweb_config.perl`. Testing confirmed the Makefile-based solution works when rebuilding gitweb. This appears to be a known issue, having been previously reported in Gentoo's bug tracker (#675864).

While the proposed fix resolves the immediate problem, there's an open question about whether a more robust solution using absolute paths would be preferable for production environments. The change affects both the gitweb installation process (Makefile) and runtime behavior (CGI script).
