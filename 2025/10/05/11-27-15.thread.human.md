This thread reports and analyzes a serious bug in `git clean -X` where directory pathspecs are incorrectly handled when cleaning ignored files. The original report showed that `git clean -d -X` completely disregards path exclusions (like `:!/.idea/dictionaries`) during directory traversal, risking unintended deletion of explicitly excluded directories regardless of their contents.

Johannes Schindelin (Dscho) has now confirmed the issue occurs on both Windows and Linux, highlighting an ambiguity in the expected behavior when combining `-X` (clean ignored files) with path exclusions. He's provided a clear test case demonstrating the problem: a `build/` directory with a `lib.so` file that should be preserved when excluded via `:(exclude)build` but currently isn't. The test uses `test_expect_failure` to document the broken behavior while the architectural challenges in `dir.c`'s exclusion logic are addressed.

The discussion has revealed this isn't just about negated pathspecs (`:!`) but represents a deeper issue in how directory processing respects all pathspec constraints. While the test case provides a concrete reference point, the fundamental question remains unresolved: should exclusions filter the `-X` operation, or should `-X` override exclusions? This design decision now awaits input from the Git maintainers.
