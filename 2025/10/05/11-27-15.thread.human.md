This thread reports a serious bug in `git clean -X` where pathspec constraints are ignored when processing directories marked for removal with `-d`. The core issue is that excluded directories (like `:!/.idea/dictionaries`) get processed anyway during directory traversal, potentially leading to unintended deletions of explicitly excluded directory structures.

Devste Devste's follow-up clarifies that this isn't just a negated pathspec issue, but a broader failure of `git clean` to respect any pathspec constraints when handling directories. The reproduction case shows that even when targeting only `.rej` and `.log` files while excluding `.idea/dictionaries`, the command still attempts to remove the excluded directory structure regardless of its contents matching the specified patterns. The bug appears cross-platform and currently has no known workaround, representing a significant risk for unintended data loss during clean operations.
