This thread reports a serious issue in `git clean -X` where pathspec exclusions are ignored during directory processing, creating a data loss risk. The original report showed that negated pathspecs (like `:!/.idea/dictionaries`) fail to protect directories during dry runs. A follow-up clarified this isn't just about negated pathspecs - the command completely disregards all pathspec constraints when handling directories, even when they contain no files matching the positive patterns (like `*.rej` or `*.log`).

The bug occurs in `clean.c`'s directory traversal logic when using `git clean -X -d` (clean ignored files including directories). Despite explicit exclusions, the command may attempt to delete entire directory structures that users intended to protect. The reporter confirmed this on Windows (Git 2.51.0.windows.1) but the issue appears cross-platform. There's currently no workaround, making this a high-priority bug due to its potential for unintended data loss. The thread provides clear reproduction steps and technical details for debugging the pathspec handling flaw.
