Bugfix and behavior refinement for interactive add navigation.

This third patch in René Scharfe's v2 series addresses the roll-over behavior of several interactive add commands (y/n/j/e) when reaching the end of the hunk list. The key change makes these commands consistently seek the first undecided hunk when wrapping around, rather than always jumping to hunk 1 regardless of its state. This matches their behavior when moving forward normally.

The implementation introduces a new `inc_mod()` helper for circular hunk navigation and modifies `patch_update_file()` to use it when searching for the next undecided hunk. The patch updates both the documentation (clarifying j's behavior) and adds two new test cases that verify the roll-over behavior with different command sequences. The tests specifically check that the commands properly cycle through undecided hunks while skipping already-decided ones.

This builds on the thread's earlier work formalizing navigation behavior, now extending the consistency improvements to the y/n/e commands that modify hunk state. The changes maintain backward compatibility while making the interface more predictable. The patch appears technically sound, with careful attention to edge cases in the navigation logic and thorough test coverage of the new behavior.
