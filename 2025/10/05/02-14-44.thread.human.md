The thread discusses the planned deprecation and removal of the legacy `git whatchanged` command. Originally proposed for removal due to code quality concerns, the discussion has evolved into practical considerations for helping users transition. Jeffery Carr initially questioned the rationale and suggested alternative deprecation approaches, including creating an alias or standalone binary.

Kristoffer Haugsbakk clarified that Git doesn't support built-in aliases in the proposed way and explained that `git whatchanged` has been functionally redundant with `git log` for over 12 years, sharing the same underlying code but with different defaults. They provided specific replacement command (`git log <opts> --no-merges --raw`) and noted users might prefer `--stat` or `--name-only` for better readability. The deprecation warning will be updated to include this alternative, addressing Carr's suggestion.

While the initial email suggested the removal might be contentious, the discussion has shifted to implementation details, indicating the removal is proceeding with attention to user experience. The technical specifics about the replacement suggest this is moving toward finalization rather than reopening the decision to deprecate.
