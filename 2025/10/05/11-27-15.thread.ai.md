Git clean bug report: incorrect handling of pathspec constraints with ignored directories.

A serious bug in `git clean -X` (clean only ignored files) causes it to disregard all pathspec constraints (not just negated ones) when processing directories marked for removal with `-d`. The core issue is that pathspec exclusions (like `:!/.idea/dictionaries`) are completely ignored during directory traversal, leading to potential deletion of explicitly excluded directory structures regardless of whether their files match the positive patterns (e.g., `*.rej` or `*.log`).

Technical specifics:
- Command triggering the issue: `git clean -f -f -d -X --dry-run` with mixed pathspecs
- Affected components: directory traversal logic in `clean.c` and `dir.c` that fails to respect pathspec constraints
- Impact: High risk of unintended directory deletion despite explicit exclusion in pathspec
- Reproduction: Clear steps showing excluded directories being processed when they contain no matching files
- Platform: Confirmed on both Windows (Git 2.51.0.windows.1) and Linux by Johannes Schindelin

Johannes Schindelin's analysis reveals ambiguity in the spec when combining `-X` with explicit exclusions (`:(exclude)` patterns), presenting two possible interpretations:
1. Exclusions should filter the `-X` operation
2. `-X` should override exclusions

He provides a regression test case (`test_expect_failure`) demonstrating the issue with a `build/` directory containing `lib.so` that should be preserved when excluded via `:(exclude)build` but currently isn't. The test confirms equivalent behavior between `:!` and `:(exclude)` syntax.

Key challenges:
- Complex, organically evolved exclusion logic in `dir.c`
- Need for maintainer decision on intended behavior
- Cross-platform confirmation of issue (Windows/Linux)
- Architectural difficulties in modifying the exclusion handling

The test case serves as a reference point for future fixes, regardless of which interpretation is chosen. The discussion now awaits maintainer decision on the intended behavior before proceeding with implementation.
