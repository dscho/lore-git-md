Git clean bug report: incorrect handling of pathspec constraints with ignored directories.

A serious bug in `git clean -X` (clean only ignored files) causes it to disregard all pathspec constraints (not just negated ones) when processing directories marked for removal with `-d`. The core issue is that pathspec exclusions (like `:!/.idea/dictionaries`) are completely ignored during directory traversal, leading to potential deletion of explicitly excluded directory structures regardless of whether their files match the positive patterns (e.g., `*.rej` or `*.log`).

Technical specifics:
- Command triggering the issue: `git clean -f -f -d -X --dry-run` with mixed pathspecs
- Affected components: directory traversal logic in clean.c` that fails to respect any pathspec constraints
- Impact: High risk of unintended directory deletion despite explicit exclusion in pathspec
- Reproduction: Clear steps showing excluded directories being processed when they contain no matching files
- Platform: Originally reported on Windows (Git 2.51.0.windows.1) but confirmed as likely cross-platform

The bug represents a fundamental flaw in how `git clean` applies pathspec filtering to directories, with significant data loss implications. No workaround is currently known. The follow-up email from Devste Devste clarified that this is not limited to negated pathspecs but is a broader failure to constrain directory processing by the specified paths. The original reproduction case remains valid, showing that even when explicitly excluding `.idea/dictionaries` in the pathspec and only targeting `.rej` and `.log` files, the command still attempts to remove the excluded directory structure.
