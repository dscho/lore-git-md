Git clean bug report and maintainer response on pathspec constraints with ignored directories.

A serious bug in `git clean -X` (clean only ignored files) causes it to disregard all pathspec constraints (not just negated ones) when processing directories marked for removal with `-d`. The core problem involves pathspec exclusions (like `:!/.idea/dictionaries`) being ignored during directory traversal, potentially leading to unintended deletion of explicitly excluded directories regardless of their file contents.

Technical specifics:
- Affects `clean.c` and `dir.c` directory traversal logic
- Confirmed on Windows (Git 2.51.0.windows.1) and Linux
- Reproduction shows excluded directories processed despite containing no matching files
- Johannes Schindelin provided regression test case (`test_expect_failure`) demonstrating the issue with `build/` directory exclusion

Behavioral ambiguity identified:
1. Should exclusions filter the `-X` operation?
2. Should `-X` override exclusions?

Maintainer position:
- Junio Hamano acknowledges both interpretations as valid
- Expresses no personal preference ("not really my thing")
- Cautions against behavior changes without strong justification
- Implicitly accepts current behavior if logically explainable
- Decision ultimately rests with maintainer but won't be driven by him

Current status:
- Regression test exists for either resolution path
- Awaiting proposed resolution from Johannes Schindelin or other interested parties
- Architectural challenges remain in modifying exclusion handling
- Key participants: Johannes Schindelin (reporter), Junio Hamano (maintainer)
- Next step: Need clear proposal for either documenting current behavior or changing it with justification
