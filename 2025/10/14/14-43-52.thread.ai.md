Thread identity: Bugfix patch addressing HTTP authentication behavior when credentials in .netrc are insufficient, modifying how Git handles 403 (Forbidden) responses.

Core problem: Currently, Git only prompts for new credentials when receiving 401 (Unauthorized) responses, not 403 (Forbidden). This creates a poor user experience when shared systems have read-only credentials in .netrc (e.g. GitHub tokens) - users attempting write operations get an immediate 403 error rather than being prompted to supply their own credentials.

Key technical details:
- Modifies `http.c` to treat 403 responses similarly to 401 for credential prompting
- Adds test infrastructure in `set_netrc`/`clear_netrc` helpers
- Extends Apache test config to simulate forbidden users
- Adds three test cases covering .netrc scenarios (success, 401, 403)

Current status: Initial version of patch posted, with thorough test coverage. The implementation appears sound but may need discussion about whether 403-triggered prompting should be unconditional or configurable.

Open questions:
