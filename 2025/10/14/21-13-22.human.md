This is a bugfix for the `git replay` command's help text formatting, caught during integration testing. Junio Hamano reports that when the atomic ref updates series was merged to the 'seen' branch, it caused a test failure in t0450 which verifies consistency between `-h` output and the full `--help` documentation. The issue is a line break discrepancy - the usage text in `builtin/replay.c` splits the options across two lines while the documentation shows them on one line. Hamano provides a minimal fix to align them by adding a newline in the C source to match the documentation format. 

The patch is straightforward and clearly necessary to maintain consistency in Git's help output. While small, it's important for user experience and automated testing. The fix demonstrates Git's attention to detail in keeping documentation and command-line interfaces properly synchronized. Since this is a follow-up to an already-reviewed series about to be merged, it will likely be accepted quickly.
