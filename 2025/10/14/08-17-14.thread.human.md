The thread discusses the planned deprecation of `core.preferSymlinkRefs` in Git 3.0, which will remove support for writing symbolic references as symlinks (the original 2005 format) in favor of the modern "ref: " text format introduced in 2006. The initial patch added warnings when the deprecated feature is used and updated documentation to explain the change.

Junio C Hamano has now weighed in with suggestions to improve the messaging around this change. He recommends more positive phrasing in the documentation ("Symbolic refs will always be written as textual symrefs" rather than focusing on removal) and questions some implementation details like the use of `NOT_CONSTANT(-1)` and the terminology "symref format" (preferring "textual symref"). The technical approach remains unchanged - warnings are emitted once per process via a static variable, and the actual symlink writing behavior will be disabled when breaking changes are enabled. The discussion shows careful attention to how this backward-incompatible change is communicated to users, with Junio providing guidance to ensure clear and consistent messaging.
