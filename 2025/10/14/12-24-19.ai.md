Performance optimization in the interpret-trailers refactoring series.

This patch from Li Chen simplifies the non-in-place output path in `interpret_trailers()` by replacing a direct `fwrite()` call with `strbuf_write()`. The change eliminates the need to manually specify the buffer length since `strbuf_write()` handles that internally. While functionally equivalent, this makes the code slightly cleaner by using the strbuf API consistently.

The modification is part of the larger series refactoring trailer handling to move processing into Git's core while maintaining the same behavior. This particular change touches only one line in builtin/interpret-trailers.c, swapping the output mechanism while preserving all existing functionality. It follows the series' pattern of internal improvements that don't affect user-visible behavior but make the code more maintainable.

Key technical details: replaces `fwrite(out_buf.buf, 1, out_buf.len, stdout)` with `strbuf_write(&out_buf, stdout)` in the non-in-place output path. The strbuf API handles the length calculation internally, making the code more robust against potential future changes to the buffer structure. This is a straightforward optimization that doesn't introduce any new concepts or dependencies for future patches in the series.
