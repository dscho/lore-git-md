This thread addresses a conflict in Git's HTTP authentication behavior where the automatic use of .netrc credentials can prevent interactive credential prompts from appearing when read-only tokens are present. The discussion began with Ashlesh Gawande proposing protocol changes for 403 responses, but after feedback, the focus shifted to a more maintainable solution.

The current consensus favors introducing a new configuration option (likely `http.useNetrc`) to let users control whether .netrc credentials should be used when Git credentials exist. This approach, championed by brian m. carlson who confirmed it solves a real workflow problem, maintains backward compatibility while providing an escape hatch. The test infrastructure developed earlier remains valuable and may be merged separately.

With the solution direction now agreed upon, the thread is transitioning to implementation details. Key remaining questions include the exact configuration name and semantics, default behavior documentation, and handling edge cases with credential helpers. All participants are aligned on preserving backward compatibility as the primary constraint while solving the original credential conflict issue.
