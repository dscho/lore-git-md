This is a bugfix patch addressing HTTP authentication behavior when credentials are present in .netrc but insufficient for the operation.

The patch modifies Git's HTTP handling to treat 403 (Forbidden) responses similarly to 401 (Unauthorized) responses by prompting for credentials when existing ones fail. The motivation describes a real-world scenario where testers and developers share systems with read-only GitHub tokens in .netrc - developers currently get a hard 403 error when trying to push, rather than being prompted to supply their own credentials.

Key technical changes:
- Modifies `http.c` to trigger credential prompts on 403 responses (not just 401)
- Adds test infrastructure for .netrc testing (`set_netrc`/`clear_netrc` helpers)
- Extends Apache test config to simulate forbidden users
- Adds three new test cases covering .netrc scenarios (success, 401, 403)

The patch appears well-constructed with thorough test coverage. The commit message clearly explains the problem scenario, though it focuses specifically on GitHub workflows rather than general HTTP authentication. The solution seems reasonable but may warrant discussion about whether 403 should always trigger credential prompts or if this should be configurable.
