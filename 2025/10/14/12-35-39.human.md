This is a refactoring patch in Patrick Steinhardt's `git-history` series, specifically addressing the add-patch/add-interactive code structure. Karthik Nayak provides a review of patch 8/12, which splits out a new `struct interactive_options` to better separate concerns between the "git add -p" and "git add -i" subsystems.

The patch aims to untangle the shared `struct add_p_opt` that was being used by both subsystems, replacing it with clearer structures (`interactive_options` and `interactive_config`). Karthik notes the implementation looks sound but raises two thoughtful suggestions: whether these new interactive-related structures should live in add-interactive.h rather than add-patch.h, and whether they should use the `add_` prefix for consistency with existing code.

This appears to be a solid technical improvement to the codebase's organization, though Karthik's suggestions about naming and file location could lead to further refinements. The change is part of the larger infrastructure work supporting the new `git-history` command's interactive editing capabilities.
