This is a documentation discussion thread about reference hierarchy explanations in the new `gitdatamodel.adoc` man page.

Junio Hamano weighs in on the ongoing discussion about how to describe Git's reference hierarchy in the documentation. He notes that Julia Evans and Patrick Steinhardt have different mental models of where the reference hierarchy begins - Patrick sees it starting at `refs/` (excluding root-level refs like HEAD), while Julia (and Junio) view the hierarchy as beginning at the root level with `refs/` as a sub-hierarchy. 

Junio acknowledges both perspectives could be valid but raises the practical question of which view is more common among Git users, as this affects how the documentation should present the concept. This continues the thread's theme of balancing technical precision with pedagogical effectiveness, specifically around how to explain reference handling differences between branches, tags, and special refs like HEAD.

The discussion remains unresolved but maintains a constructive tone, with Junio positioning himself as agreeing with Julia's interpretation while recognizing Patrick's storage-layer perspective. This exchange highlights the challenge of documenting concepts that have both technical implementation details and user-facing conceptual models.
