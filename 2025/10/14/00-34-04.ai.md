Bugfix addressing incorrect `**` pattern matching in `.gitignore` files. This patch fixes a discrepancy where Git was matching paths like `foobar` against patterns like `foo**/bar`, contrary to documented behavior that requires `**` to be surrounded by slashes for special meaning. The issue stems from how `match_pathname()` optimizes pattern matching by stripping matching prefixes before calling `fnmatch()`, which loses context about directory boundaries.

The proposed solution modifies `dir.c` to preserve one character of the matched portion when passing to `fnmatch()`, preventing false matches where `**/` could incorrectly match zero directories. A new test case in `t/t0008-ignores.sh` verifies the corrected behavior. Jeff King notes this is an RFC patch due to concerns about being a "disgusting hack" and potential undiscovered edge cases, though the core issue is clearly identified and addressed.

The change impacts Git's pathspec matching logic, specifically for `.gitignore` and `.gitattribute` pattern handling. This aligns Git's implementation with its documented behavior and maintains consistency with JGit's interpretation. The patch maintains existing optimizations for non-wildcard patterns while fixing the `**` edge case. Performance impact appears minimal, though the author suggests further optimization might be possible by reevaluating the prefix-matching approach.
