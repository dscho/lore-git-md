This is a refactoring patch in the ongoing series adding `--trailer` support to `git rebase`. The change simplifies trailer handling by removing redundant `--trailer` prefix processing in the `amend_strbuf_with_trailers()` helper function. 

The patch modifies three files to make callers (`git commit` and `git tag`) pass trailer text directly rather than having the trailer helper strip the `--trailer=` prefix. The key change is in trailer.c where the `skip_prefix()` check is removed, trusting callers to pass properly formatted trailer text. This reduces code duplication and makes the interface more straightforward.

The changes are mechanical but meaningful - they clean up the boundary between option parsing and trailer processing. The patch maintains all existing functionality while making the code more maintainable. It's part of a larger effort to centralize and streamline trailer handling across Git commands. The modification aligns with the series' goal of moving trailer processing into core Git functionality rather than relying on `interpret-trailers` as a separate process.

Technical details: removes `skip_prefix()` check in trailer.c; changes `OPT_PASSTHRU_ARGV` to `OPT_CALLBACK_F` in builtin/commit.c and builtin/tag.c to handle trailer arguments more directly; maintains same behavior with simpler code. This builds on previous patches that moved core trailer functionality into trailer.c.
