This is a refactoring patch in the context of an Outreachy microproject. Bello Olamide confirms they will proceed with replacing `strbuf_split_max()` with `string_list_split()` in gpg-interface.c's SSH key handling functions, following Christian Couder's earlier approval. 

The change affects `get_ssh_key_fingerprint()` and `get_default_ssh_signing_key()`, where the string splitting is used in read-only contexts. Christian had noted this makes the functions good candidates for the refactoring, since `string_list_split()` is more appropriate when the split strings won't be modified. 

This appears to be a straightforward, low-risk change that serves as a good first contribution while modernizing the codebase's string handling. The patch itself hasn't been submitted yet, but the email indicates Bello is now preparing it. The commit message will need to document the rationale as Christian suggested. 

This continues a pattern seen elsewhere in the codebase of moving from strbuf to string_list where appropriate. No technical concerns have been raised about the approach, though reviewers will want to check the actual implementation when submitted.
