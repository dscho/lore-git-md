This is a deprecation notice targeting the files backend's handling of symbolic refs. The patch marks `core.preferSymlinkRefs` for removal in Git 3.0, which currently allows writing symbolic refs (like HEAD) as symlinks rather than the modern symref format (plain files with "ref: " prefix).

The change documents the history - symlinks were the original format (2005), replaced by symref files in 2006. The justification is that symlinks have no known advantages today, aren't supported on all platforms, and the migration happened nearly 20 years ago. The patch adds warnings when the deprecated feature is used, updates documentation in both config and breaking changes files, and modifies tests to handle both current and future behavior (via a new WITH_BREAKING_CHANGES test prerequisite).

Key technical details: the warning appears once per process via a static variable in `create_ref_symlink()`. The deprecation only affects writing symlinks - reading remains supported. The test changes verify both the new warning message and that symrefs are properly written as files when the breaking changes flag is set. The documentation updates clearly state the timeline and rationale for removal.
