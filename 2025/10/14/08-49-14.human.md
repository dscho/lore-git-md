This is a refactoring patch that extends the wt-status subsystem to support diffing arbitrary trees, rather than just working tree/index states. It's part of Patrick Steinhardt's larger `git-history` series (currently at v4) which aims to provide more flexible history editing operations.

The patch introduces a new function `wt_status_collect_changes_trees()` that takes two tree-ish objects and formats their differences into a `wt_status` struct, reusing much of the existing diff machinery and callbacks. Karthik Nayak's review confirms the technical approach looks sound, though he questions the `>= 0` checks in the diff options setup (likely carried over from existing code patterns).

While this is infrastructure work with no immediate user-facing impact, it's a clean extension of the wt-status API that will be used by subsequent patches in the series. The implementation appears straightforward and maintains consistency with existing code, though as Karthik notes, we'll need to see how it's actually used in the following commits to fully evaluate its design.
