This is a refactoring patch that removes a now-unused packfile API function as part of a larger series cleaning up Git's pack iteration patterns. Justin Tobler is responding to Patrick Steinhardt's patch that drops `packfile_store_get_packs()`, which had become obsolete after all callers were converted to use the newer `packfile_store_get_all_packs()` (soon to be renamed to just `packfile_store_get_packs()` in the final patch of the series).

The removal eliminates a confusing aspect of the packfile API where `packfile_store_get_packs()` would exclude packs referenced by MIDX (multi-pack index) files while its counterpart included them. Justin notes this is a positive cleanup, as the stateful behavior between the two similar-sounding functions was a potential pitfall for developers.

This change is purely internal - it doesn't affect end users or Git's behavior, but makes the codebase more maintainable by removing dead code and reducing API surface. The patch appears straightforward and well-justified, coming at the right point in the series after all callers were migrated. Justin's positive response suggests this is a non-controversial step in the larger refactoring effort.
