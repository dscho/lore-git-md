This is a refactoring patch in the ongoing series to add `--trailer` support to `git rebase`. It restores and centralizes the `interpret_trailers()` helper function in builtin/interpret-trailers.c that was removed in a previous commit, factoring out the duplicated read/process/write logic that was previously repeated for both file and stdin input paths.

The change maintains identical error handling and output behavior while reducing code duplication. The helper function handles both in-place file editing and stdout output cases, with the main command function now delegating to it for each input file path and for stdin processing. The patch shows careful attention to preserving existing behavior while cleaning up the implementation, with no functional changes beyond the internal restructuring.

This is part of the larger effort to move trailer processing into in-process Git functions (rather than fork/exec) while maintaining the same external behavior. The series has shown responsiveness to review feedback across multiple iterations, with this particular patch addressing code organization concerns raised in earlier rounds. The change touches only builtin/interpret-trailers.c and is part of the foundational refactoring needed before introducing the new rebase trailer functionality in later patches.
