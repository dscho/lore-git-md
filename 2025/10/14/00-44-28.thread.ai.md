[PATCH] refactor gpg-interface.c: replace strbuf_split with string_list_split

This thread proposes replacing strbuf_split_max() with string_list_split() in gpg-interface.c's SSH key handling functions (get_ssh_key_fingerprint and get_default_ssh_signing_key). Initiated by Bello Olamide as a potential Outreachy microproject, the discussion has received input from Christian Couder confirming these functions are suitable candidates since they only read split strings without modification.

Christian Couder provided the key technical rationale: string_list_split() is more appropriate than strbuf_split_max() when the split strings won't be modified, and suggested documenting this justification in the commit message. The change aligns with broader codebase modernization around string handling utilities.

The proposal remains at an early stage with no patch yet submitted. The identified functions appear to be straightforward, low-risk targets for this refactoring pattern, making them suitable for a first contribution. Future discussion is expected when the actual implementation is proposed, potentially addressing edge cases or performance considerations not yet examined. The thread currently serves as preliminary approval for the Outreachy applicant to proceed with the microproject.
