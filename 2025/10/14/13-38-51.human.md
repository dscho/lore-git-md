Feature patch (part of `git-history` series) with review feedback on the "split" subcommand implementation.

Karthik Nayak provides a technical review of Patrick Steinhardt's patch implementing the `git history split` command, which simplifies splitting a commit into two by interactively selecting hunks to move to a new commit. The review focuses on code quality and implementation details rather than fundamental design issues.

The review identifies several minor issues:
- A style nit with `*const` placement in a parameter declaration
- Redundant merge commit checks (present in both this function and `collect_commits()`)
- A missing space after `error` in an error message
- Comment formatting and a duplicate "new" in documentation
- The core implementation appears sound, with Karthik noting the straightforward handling of hunk selection and commit creation
- The test coverage is deemed good with no issues found
- Karthik questions whether the split-out hunks should become the parent commit (current implementation) or remain as the child, though acknowledges no strong preference

This continues the pattern of thorough but constructive review for this series, with only minor issues remaining to be addressed. The feedback suggests the implementation is nearly ready, needing only small polish before potential inclusion.
