This is a documentation follow-up in the ongoing thread about clarifying `git blame --incremental` output format. Philip Patsch responds to Junio Hamano's earlier review by pointing out an additional documentation gap - the manpage doesn't clearly define what a plain `<rev>` parameter means in the context of `git blame`.

While the thread initially focused on explaining the "sourceline" and "resultline" fields in incremental blame output, this email surfaces a related but distinct documentation issue. Patsch notes that while `--reverse` is documented, neither the basic `<rev>` parameter nor the `--since` option appear in the main options list (though `--since` is mentioned later in the "SPECIFYING RANGES" section).

This suggests the documentation could benefit from either:
1. Adding `<rev>` to the main options list with a brief explanation
2. Making the "SPECIFYING RANGES" section more discoverable
3. Both

The email doesn't propose a specific solution, but rather identifies what appears to be an oversight in the current documentation structure. This follows the thread's theme of improving `git-blame` documentation for users who need precise understanding of its parameters and output formats.
