This is a refactoring patch in the ongoing `--trailer` support series for `git rebase`. It moves trailer processing earlier in the commit sequence by modifying the in-memory commit message buffer directly in `do_pick_commit()` rather than writing to a file first.

The key changes:
- Moves trailer addition from post-commit file modification to pre-commit in-memory buffer processing
- Skips trailer processing for fixup/squash commands (preserving their special handling)
- Makes `amend_strbuf_with_trailers()` externally visible by moving its declaration to trailer.h
- Simplifies the code path by removing the file-based trailer addition that previously happened after commit
- Maintains the same error handling for trailer addition failures

The patch appears to be a straightforward improvement that eliminates an unnecessary file I/O roundtrip while keeping all existing functionality. It's a logical step in the series' progression toward more efficient trailer handling. The change is well-contained (19 lines net change) and maintains the same error checking behavior, just at a different point in the sequence.
