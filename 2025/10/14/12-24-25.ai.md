Refactoring patch in the ongoing `--trailer` support for `git rebase` series. This is patch 12/29 from Li Chen, addressing a minor memory management optimization in the rebase state handling code.

The change removes a redundant `strbuf_release()` call in `read_basic_state()` that was previously called both inside and outside a conditional block, potentially leading to double-free scenarios if `strbuf_read_file()` failed. The buffer is now only released once at the end of the function, regardless of the execution path. This maintains the same cleanup behavior while eliminating unnecessary operations and potential error cases.

The patch is a straightforward cleanup that follows from earlier refactoring in the series (particularly around state handling improvements in rebase.c). It touches only one line in builtin/rebase.c and doesn't require any test changes since it doesn't affect observable behavior - the existing test coverage for state persistence in t3440-rebase-trailer.sh continues to verify the functionality. This appears to be a clean, focused improvement responding to the series' code review process.
