Maintenance release announcement with documentation updates.

Junio C Hamano proposes bundling Kristoffer Haugsbakk's recent documentation about `git whatchanged` replacements into an upcoming Git 2.51.1 maintenance release. The release would also include other minor documentation fixes and some CI-related updates. This would be the first non-security maintenance release in some time, so Junio notes they'll need to refresh their memory on the release procedure.

The specific documentation change being referenced is Kristoffer's earlier email showing how to replace `git whatchanged` with equivalent `git log` commands using `--no-merges --raw` for programmatic use or `--stat`/`--name-only` for human-readable output. This continues the thread started by Samer Abdallah about continued use of the legacy command.

Key technical details:
- The release would include the `kh/you-still-use-whatchanged-fix` topic
- Other planned inclusions are documentation tweaks and CI fixes
- This would be a routine maintenance release (2.51.1) rather than a security update

The email suggests the Git maintainer sees value in documenting modern alternatives to deprecated commands like `git whatchanged`, enough to warrant including it in a maintenance release alongside other minor fixes. The tone is lighthearted about the need to "practice the procedure" for cutting a non-emergency update.
