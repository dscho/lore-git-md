This is a feature patch adding `--trailer` support to `git rebase`, part of a larger series refactoring Git's trailer handling internals. The patch implements the core functionality that allows appending custom trailers to rebased commits, while automatically forcing the merge backend (since the apply backend lacks message filtering capabilities) and enabling `--force-rebase` to rewrite fast-forwarded commits.

The implementation includes:
- New `--trailer` option parsing in `builtin/rebase.c`
- Validation of trailer arguments (rejecting empty trailers and malformed key-value pairs)
- State persistence for interrupted rebases via `$state_dir/trailer`
- Integration with the sequencer to append trailers during commit rewriting
- Comprehensive tests covering conflict scenarios, invalid inputs, and config mappings

The patch appears well-constructed with thorough test coverage (94 lines of new tests) and handles edge cases like interrupted rebases. It builds on the earlier refactoring work that moved trailer processing into core Git rather than forking `interpret-trailers`. The implementation forces the merge backend when trailers are used, which seems reasonable given the technical constraints.
