This is a follow-up discussion about the ongoing deprecation of `core.preferSymlinkRefs`, which will remove support for writing symbolic refs as symlinks in Git 3.0. Junio Hamano provides editorial feedback on the documentation and implementation details of the deprecation warning.

The email focuses on wording improvements for the deprecation notice, suggesting clearer phrasing to avoid making the feature sound newly introduced. Hamano questions whether "symref format" is the official terminology (preferring "textual symref") and notes a potential ordering issue where the warning appears before attempting to lock the ref. He also suggests using NOT_CONSTANT(-1) for consistency in the conditional compilation.

The discussion appears to be fine-tuning the messaging and technical details of a change that has already been agreed upon in principle. The thread context shows this is part of a long-planned removal of symlink-based symbolic refs after a 20-year migration period, with the current patch adding warnings ahead of the Git 3.0 removal.
