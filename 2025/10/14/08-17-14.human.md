This is a deprecation notice for the files backend's symlink-based symbolic refs feature. Patrick Steinhardt proposes removing the ability to write symbolic refs (like HEAD) as symlinks, which has been configurable via `core.preferSymlinkRefs` since 2006.

The patch notes this feature originated when symlinks were the only way to implement symbolic refs, but the current symref format (plain files with "ref:" prefixes) became the default nearly 20 years ago. The change documents the deprecation in BreakingChanges.adoc and adds warnings when the feature is used, while maintaining read support for existing symlinks. The removal is planned for Git 3.0.

The implementation is thorough - it updates documentation, adds runtime warning messages, and includes test coverage for both the warning behavior and the eventual removal path (gated by a WITH_BREAKING_CHANGES prereq). The commit references prior discussion (indicated by the [1] footnote), suggesting this isn't coming out of nowhere. This appears to be a well-justified cleanup of a legacy feature with clear transition guidance.
