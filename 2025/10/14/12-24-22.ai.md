This is the 9th patch in a 29-part series introducing `--trailer` support to `git rebase`. The patch implements the core functionality that allows appending custom trailers to commit messages during rebase operations. Key technical details:

The implementation forces use of the merge backend (rejecting apply/am) since it requires message filtering capabilities. It automatically enables `--force-rebase` to rewrite fast-forwarded commits when trailers are specified. The patch adds trailer state persistence across interrupted rebases by storing trailer arguments in `$state_dir/trailer`. Error handling validates trailer syntax early (rejecting empty trailers or those missing keys before separators) and properly propagates errors during message rewriting.

The changes span rebase.c (option parsing and state management), sequencer.c (trailer application during commit picking), and include a new test file t3440-rebase-trailer.sh with 94 lines of test coverage. Tests verify:
- Apply backend rejection
- Trailer syntax validation
- Duplicate trailer handling
- Conflict scenario behavior
- Full-history rewriting with `--root`
- State persistence across interruptions

The patch builds on earlier refactoring work that moved trailer processing into trailer.c, now using the new `amend_file_with_trailers()` function rather than forking `interpret-trailers`. It maintains compatibility with existing trailer configuration while adding the rebase-specific integration.
