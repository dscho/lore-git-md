Bugfix addressing incorrect `**` pattern matching in `.gitignore` files. Jeff King identifies and fixes a subtle edge case where Git was incorrectly matching paths like `foobar` against patterns like `foo**/bar`, contrary to documented behavior that requires `**` to be surrounded by slashes for special meaning.

The patch modifies `match_pathname()` to preserve one character of prefix context when passing paths to fnmatch, preventing false matches where `**/` could incorrectly match zero directories. The fix is marked as it may have performance implications and the author notes the solution feels like a disgusting hack, though it comes with a new test case to verify the corrected behavior.

This addresses the core issue raised in the thread about whether the current behavior is a bug or documentation gap, clearly siding with it being an implementation bug. The change is relatively small but touches core path pattern matching, so maintainer review will be needed to assess both correctness and performance impact.
