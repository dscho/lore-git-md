Hook subsystem refactoring series update regarding file descriptor handling in parallel processes.

Adrian Ratiu responds to earlier feedback from Patrick Steinhardt and Junio Hamano about using `-1` instead of `0` to mark invalid file descriptors in the parallel process stdin handling (patch 1/10 of the hook refactoring series). After attempting the change, Adrian reports that modifying the run-command API's file descriptor semantics would require extensive changes across the codebase, making it too risky and out of scope for this series.

The current implementation uses `0` to indicate "no file descriptor passed", which differs from Unix convention where `-1` typically marks invalid descriptors. While reviewers had suggested switching to `-1` for consistency, Adrian argues that maintaining the existing behavior is preferable to avoid destabilizing the broader run-command infrastructure. This decision affects how the `feed_pipe` callback mechanism interacts with child process file descriptors in the hook parallelization work.

This represents a reversal from Adrian's initial agreement to make the change in v2, now citing implementation complexity as the blocker. The discussion highlights the tension between API consistency and practical refactoring constraints in a mature codebase. The thread context shows this is part of a larger effort to modernize hook processing while maintaining compatibility, with most other aspects of the series progressing well through review cycles.
