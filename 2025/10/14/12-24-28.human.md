This is a refactoring patch in the ongoing series adding `--trailer` support to `git rebase`. The change moves trailer argument validation from `builtin/rebase.c` to `trailer.c`, where it can properly respect configured trailer separators.

The patch relocates the `validate_trailer_args_after_config()` function, which checks that `--trailer` arguments have valid syntax (non-empty and containing a proper key before the separator). The new implementation uses `find_separator()` to handle configured separator characters rather than hardcoding `:=` as valid separators. This makes the validation consistent with how trailers are processed elsewhere in Git.

The change is part of the larger effort to centralize trailer handling logic in `trailer.c` while keeping I/O operations in the calling builtins. It follows the pattern seen in earlier patches of moving functionality from `builtin/interpret-trailers.c` to the shared trailer implementation. The patch appears straightforward and maintains the same validation behavior while being more flexible about separator characters.
