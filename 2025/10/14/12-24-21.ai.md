This is a bugfix and refactoring patch in the ongoing `git rebase --trailer` series, focusing on error handling improvements.

The patch introduces a new `write_file_buf_gently()` function in wrapper.c that provides error-reporting file writing without terminating the program, complementing the existing `write_file_buf()` that dies on errors. This is then used in `amend_file_with_trailers()` to properly handle and propagate failures during trailer appending and file writing operations.

Key technical changes:
- Adds `write_file_buf_gently()` to wrapper.[ch] with same core logic as `write_file_buf()` but returns errors instead of dying
- Modifies `amend_file_with_trailers()` in trailer.c to:
  - Properly release buffers on error paths
  - Return errors from `amend_strbuf_with_trailers()` and file writing
  - Remove the unconditional `die()` call
- Maintains same functionality while improving error recovery

The change makes trailer operations more robust by allowing callers to handle failures gracefully rather than aborting. This is particularly important for the rebase integration where operations may need to be retried or state properly cleaned up after failures. The patch follows the series' pattern of internal improvements while maintaining all existing behavior.
