This is a refactoring patch that's part of Patrick Steinhardt's larger `git-history` command series (v4, patch 1/12). The patch introduces a new function `wt_status_collect_changes_trees()` that generalizes the working tree status collection to work with arbitrary tree objects rather than just the working tree/index.

The new function follows the same pattern as the existing working tree status collection but operates on two provided treeish objects instead of the working tree. It sets up diff options with the same callback mechanism used for working tree status, then runs the diff between the two trees and collects the results into a `wt_status` struct. The implementation reuses the existing `wt_status_collect_updated_cb` callback and handles rename detection parameters consistently with the working tree version.

Karthik Nayak's review confirms the technical approach makes sense, though they question the `>= 0` checks for rename parameters (which appear to be maintaining consistency with the working tree status behavior). The patch is clearly motivated by upcoming needs in the history editing series, though the specific use case isn't shown here yet. The implementation looks straightforward and maintains the existing patterns of the wt-status subsystem while cleanly extending its functionality.

This appears to be foundational infrastructure work for the larger history editing feature, with the new function providing tree-diffing capabilities that will presumably be used by subsequent patches in the series for operations like commit splitting and rewording. The patch maintains good separation of concerns while avoiding code duplication.
