This is a refactoring patch in the ongoing `--trailer` support for `git rebase` series. It moves trailer argument validation logic from `builtin/rebase.c` to `trailer.c` to better respect configured separator characters.

The key changes are:
- Relocates `validate_trailer_args_after_config()` from rebase.c to trailer.c
- Updates validation to use `find_separator()` which considers user-configured trailer separators (from `trailer.separators` config) rather than hardcoding `:=`
- Maintains the same error cases (empty trailers, missing keys) but now checking against the configured separators
- Adds the function declaration to trailer.h for cross-file access
- Removes 18 lines from rebase.c while adding 25 to trailer.c with the enhanced implementation

The patch continues the series' pattern of centralizing trailer-related logic in trailer.c while maintaining all existing functionality. The validation now properly honors Git's trailer configuration rather than using a fixed set of separators, making it more consistent with other trailer operations. This appears to be a straightforward improvement that better integrates with Git's existing trailer infrastructure.
