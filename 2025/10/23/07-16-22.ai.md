This is a bugfix patch in Patrick Steinhardt's refs subsystem optimization series, specifically addressing tag verification in `git-for-each-ref`. The patch enhances corruption detection when peeling tags by verifying object types earlier in the process.

The core issue involves tag peeling in `git-for-each-ref` where type mismatches between a tag's declared type and the actual object type could go undetected unless two tags pointed to the same object with different declared types. The current implementation only catches this specific edge case because it relies on subsequent lookups with different type assertions to reveal the inconsistency.

The fix modifies `populate_value()` in ref-filter.c to use the new `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag when peeling objects, ensuring type verification happens on the first dereference rather than requiring multiple lookups. This makes the corruption detection more robust by catching mismatches even with single tag dereferences.

The patch includes a test update that now verifies the detection works for both the original edge case and single-tag scenarios. This builds on the series' earlier introduction of the verification flag and completes the tag verification improvements for the ref-filter subsystem.

This change is part of the broader refactoring to remove the old peeling infrastructure and establish consistent verification behavior across Git's ref handling. It maintains the series' performance goals while improving correctness, with the verification overhead being justified by the corruption detection benefits. The implementation appears clean and focused, with a clear explanation of both the problem and solution in the commit message.
