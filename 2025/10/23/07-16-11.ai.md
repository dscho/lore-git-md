This is the second patch in Patrick Steinhardt's 14-part refactoring and performance optimization series for the refs subsystem. The patch focuses on refactoring the ref iterator interface to use a `struct reference` wrapper rather than separate fields.

The key change replaces the individual `refname`, `oid`, `flags`, and `referent` fields in `struct ref_iterator` with a single `struct reference` member. This simplifies the interface by allowing implementations to populate and pass around a single structure rather than managing multiple fields. The patch updates all iterator implementations (files, packed, reftable backends) and their callers to use the new approach.

Notable technical details:
- Changes 8 files with 75 insertions and 100 deletions
- Updates iterator implementations to populate the new `ref` field
- Modifies `should_pack_ref()` to take a `struct reference` rather than separate parameters
- Maintains all existing functionality while simplifying the interface
- Part of broader effort to separate transport-related `struct ref` from core `struct reference`

This is a foundational change that enables subsequent patches in the series, particularly the lazy object parsing optimizations. The refactoring appears cleanly implemented with thorough updates across all affected components. The patch follows the series' architectural direction while making the code more maintainable.
