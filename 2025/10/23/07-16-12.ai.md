Refactoring patch in a performance optimization effort, specifically addressing iterator state management in the refs subsystem.

This third patch in Patrick Steinhardt's 14-part series focuses on ensuring clean state transitions between iterations in the ref iterator interface. The change zeroes out the `struct ref_iterator::ref` field at the start of each iteration across all ref backends (packed, cache, and reftable). This prevents state leakage between iterations and provides predictable initialization for any future optional fields added to the struct.

The patch makes three key changes:
1. Adds `memset()` calls to clear the ref struct in each backend's iteration logic
2. Moves the OID assignment in packed-backend.c to after the memset
3. Leaves the files backend untouched as it inherits this behavior from cache_ref_iterator

This builds on the series' earlier work unifying iterator interfaces through `struct reference` while addressing a subtle correctness issue. The changes are mechanical but important for maintaining invariants as the interface evolves. The patch follows the series' pattern of careful refactoring before introducing performance optimizations in later patches.
