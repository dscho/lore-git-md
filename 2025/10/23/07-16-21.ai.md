This is a bugfix patch in Patrick Steinhardt's refs subsystem optimization series, specifically addressing tag verification during peeling operations. The patch ensures invalid tag objects (where the tagged object's type doesn't match the tag's claimed type) don't get their peeled OIDs stored in packed-refs or reftable backends.

The core issue is that both backends were silently storing peeled OIDs for tags even when the tag's object type didn't match its content (e.g., a tag claiming to point to a commit but actually pointing to a blob). This could mask corruption since tools like `git-for-each-ref` would use the stored (but invalid) peeled value rather than detecting the type mismatch. The fix introduces strict verification via the new `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag when peeling tags during ref storage.

Key technical changes:
- Modifies `write_with_updates()` in packed-backend.c to verify tag object types
- Updates reftable backend's `write_transaction_table()` similarly
- Adds tests verifying both backends reject invalid peeled values (pack-refs-tests.sh and t0610-reftable-basics.sh)
- Maintains consistency with the series' earlier introduction of the verification flag

The patch builds on the series' architectural work to cleanly separate peeling behavior from iteration patterns while fixing a subtle corruption-handling issue. The test cases demonstrate the direct impact on packed-refs storage and verify the reftable backend's consistency with the files backend. This change tightens the series' tag verification approach while maintaining its performance goals.
