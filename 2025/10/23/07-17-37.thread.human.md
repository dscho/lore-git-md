This thread discusses a 3-patch series introducing cbindgen support to Git's Rust infrastructure to facilitate Rust-C interoperability. The first patch, which updates CI configurations to switch 32-bit builds from Ubuntu to Debian for cbindgen compatibility, has been reviewed and approved by Junio Hamano and is queued for merging. The remaining patches rename the Rust library target for consistency and implement cbindgen integration starting with varint verification.

Ezekiel Newren has now provided detailed feedback on the cbindgen implementation. He suggests several improvements: moving generated headers to an `interop/` subdirectory for better organization, enhancing the cbindgen configuration with additional settings (including system includes and autogeneration warnings), and restructuring the build system to treat cbindgen as a Cargo dependency rather than installing it system-wide. Newren also proposes adopting a Cargo workspace structure for more modular header generation as the Rust codebase grows. These suggestions address important considerations for long-term maintainability and platform compatibility as Git's Rust integration progresses. The series now awaits the author's response to this feedback before the remaining patches can move forward.
