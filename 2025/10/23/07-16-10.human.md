This is the first patch in Patrick Steinhardt's v4 series of 14 patches, which refactors Git's ref iteration callback interface. The patch introduces a wrapper struct for the `each_ref_fn` callback type to make future interface changes less disruptive.

The change replaces the direct callback parameters (refname, referent, oid, flags) with a single `struct reference` parameter containing these fields. This requires updating 49 files to use the new interface, but makes the interface more flexible for future changes since new fields can be added to the struct without requiring mass updates.

The motivation comes from previous painful refactoring when adding the referent parameter required changing 48 files. While this change itself requires similar widespread updates, it prevents future churn. The author acknowledges the tradeoff that the interface is now more opaque, but notes there are relatively few sites that need to populate the wrapper struct.

This is a foundational refactoring that enables the rest of the series' performance optimizations around tag peeling and lazy object parsing. The patch appears well-executed with thorough updates across the codebase, though it doesn't include new tests since it's purely an internal interface change with no behavior differences.
