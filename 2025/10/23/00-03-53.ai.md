This is a discussion about output format options for the new `git repo structure` subcommand, part of the ongoing feature series for repository structural analysis.

Justin Tobler responds to Lucas Seiki Oshiro's suggestions about unifying the `--format` interface between `git-repo-info` and `git-repo-structure`. The current patch (v6 6/7) adds key-value and NUL-delimited output options to the structure subcommand, which already had table format. Justin explains that since the subcommands don't share all format types yet, keeping separate `--format` options makes sense for now, though unification could be considered later if `git-repo-info` gains table support.

Lucas also proposed adding key-based filtering (like `references.branches.count`) to match `git-repo-info`'s interface. Justin explains this wouldn't provide performance benefits for `git-repo-structure` since reference iteration is already required for all counts. He notes skipping path walking to only show reference data would limit functionality without clear advantages.

The exchange shows the series is feature-complete with all core functionality implemented, and this discussion focuses on potential future interface refinements rather than blocking issues. Justin remains open to interface alignment in future work while maintaining the current implementation's technical rationale.
