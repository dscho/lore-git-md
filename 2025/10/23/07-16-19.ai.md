This is a refactoring patch in Patrick Steinhardt's series modernizing Git's refs subsystem, specifically removing now-obsolete peeling infrastructure from reference iterators. The patch is part of a larger effort to clean up the refs architecture after introducing the `struct reference` interface for propagating peeled object IDs.

The key change removes the `ref_iterator_peel()` function and all its implementations across different ref backends (files, packed, reftable) and iterator types (merge, prefix, cache). The removal is straightforward except for one case in `write_with_updates()` where the packed backend now directly uses the peeled OID from the iterator's `peeled_oid` field rather than calling the peeling function.

The patch demonstrates the architectural simplification achieved by the series - peeling is now consistently handled through `struct reference` rather than having dual paths via both the iterator interface and direct peeling. This builds on previous patches that introduced the new peeling interface and migrated callers to use it. The changes are mechanical deletions with no behavior changes, showing confidence in the completeness of the earlier refactoring work.

Technical details removed include:
- The `peel` method from `struct ref_iterator_vtable`
- All backend-specific peeling implementations
- Documentation about iterator peeling in refs.h
- The `ref_iterator_peel()` wrapper function
- Special case handling in packed-backend.c's write path

The patch maintains the series' performance improvements (13% speedup in `git for-each-ref`) while further simplifying the codebase by removing now-unused infrastructure. It represents a key step in finalizing the refs subsystem modernization.
