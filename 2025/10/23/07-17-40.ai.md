Feature patch introducing cbindgen for Rust-C interoperability in Git's build system. This is the third and final patch in a series that establishes infrastructure for generating C headers from Rust's `extern "C"` functions.

The patch adds cbindgen configuration and integration to both Makefile and Meson builds, creating a `c-bindings.h` file that enforces type consistency between Rust and C implementations. The varint implementation serves as the initial test case - if Rust's `decode_varint` signature diverges from C's, compilation will now fail with a type conflict error. The header is included in `varint.c` rather than `varint.h` to avoid unnecessary recompilation of dependent files when Rust interfaces change.

Key technical changes include:
- New `cbindgen.toml` configuration specifying C-style includes and struct formatting
- Makefile rules for generating `c-bindings.h` from Rust sources
- Meson custom target for header generation
- CI updates to install cbindgen tool
- `.gitignore` entry for generated headers
- Conditional compilation in `varint.c` that includes the bindings when Rust is enabled

The implementation appears thorough, with consideration given to build system impacts (dependency tracking, clean rules) and compilation efficiency (header inclusion strategy). The varint example demonstrates the verification mechanism works as intended, catching signature mismatches at compile time. This lays groundwork for future Rust-C interoperability as more subsystems get Rust implementations.
