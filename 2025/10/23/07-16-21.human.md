This is a bugfix patch in Patrick Steinhardt's refactoring series that addresses tag verification issues in the refs subsystem. The patch ensures that invalid tags (where the tagged object's type doesn't match the tag's claimed type) don't get their peeled object IDs stored in either the files or reftable backends. This prevents Git from silently accepting corrupted tags when using features like `git for-each-ref --format=%(*objectname)`.

The change modifies both backends to use a new `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag when peeling tags, which causes them to skip storing the peeled value if verification fails. The patch includes thorough test coverage showing that neither backend will persist invalid peeled values, and that commands will properly detect tag corruption rather than using cached (but incorrect) values.

This is part of a larger effort to clean up and optimize the refs subsystem, with this particular patch focusing on maintaining data integrity while removing old peeling interfaces. The change appears well-considered, with clear motivation explained in the commit message and comprehensive tests demonstrating both the problem and solution.
