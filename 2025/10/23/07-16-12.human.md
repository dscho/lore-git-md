This is the third patch in a 14-part series refactoring Git's refs subsystem, focusing on performance optimizations and cleanup around tag verification and object parsing. The series builds on Patrick Steinhardt's previous work modernizing the refs backend.

The current patch addresses a potential issue with the new `struct ref_iterator::ref` field introduced earlier in the series. While this field makes it easier to add new reference-related fields without modifying every callsite, it could leak state between iterations or require unnecessary backend updates for optional fields. The solution is to explicitly zero out the struct at the start of each iteration in all backends (packed, files via ref-cache, and reftable).

The changes are straightforward - adding `memset()` calls to clear the struct - and touch only the three backend implementations. The patch notes that some wrapping iterators don't need modification as they already copy the full reference struct. This appears to be a defensive cleanup that prevents subtle bugs rather than fixing any currently observed issues.

As part of a larger performance-focused refactoring, this patch helps maintain consistency across the refs subsystem while enabling future extensions. The changes are mechanical but important for the series' goal of creating more robust interfaces for reference iteration.
