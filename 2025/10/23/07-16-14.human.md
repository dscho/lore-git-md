This is part 5 of Patrick Steinhardt's 14-part refactoring and performance optimization series for Git's refs subsystem. The patch focuses on improving how peeled tag object IDs are accessed during ref iteration.

The change eliminates a fragile global state mechanism where callbacks had to check a global iterator variable before peeling tags. Instead, it introduces a new `peeled_oid` field in `struct reference` that backends can populate, along with a new `reference_get_peeled_oid()` function to access it. This provides a cleaner interface while maintaining the same functionality.

The patch updates several callers across the codebase to use the new interface, including in `git describe`, `git gc`, and midx-related operations. The changes are mechanical but important for the series' goal of cleaning up the refs interface before introducing performance optimizations in later patches.

This continues the series' trend of methodical interface improvements that pave the way for more significant changes. The patch appears well-constructed with thorough updates to both backends (files and reftable) and proper documentation of the new API.
