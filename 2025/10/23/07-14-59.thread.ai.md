This thread addresses OpenSSH compatibility in the `t7528-signed-commit-ssh.sh` test, which verifies SSH commit signing. The core issue stems from OpenSSH 10.1+ moving agent sockets to `~/.ssh/agent`, hitting Unix domain socket path length limits. Patrick Steinhardt's solution uses `ssh-agent -T` to force `/tmp` socket creation, maintaining backward compatibility. Jeff King (peff) reviewed the patch, agreeing with the approach while identifying two pre-existing test fragility issues: (1) shell evaluation problems with spaces in Git's "trash directory" paths, and (2) potential exposure of real SSH keys when tests fall back to the user's SSH_AUTH_SOCK. 

Patrick acknowledges these as separate concerns not introduced by his patch. The discussion explores but rejects alternatives like relative paths ("./sshsock") due to working directory risks. Consensus emerges to proceed with the minimal `-T` fix for the immediate issue while leaving broader test improvements for future work. The technical focus remains on OpenSSH 10.1+ socket path limits, and test isolation, with no core functionality changes. Key participants are Patrick Steinhardt (author), Jeff King (reviewer), and brian m. carlson (earlier discussion). The patch is ready for merging, addressing the specific compatibility issue while noting areas for potential follow-up test infrastructure improvements.
