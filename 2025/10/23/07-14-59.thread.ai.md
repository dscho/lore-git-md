This thread addresses an OpenSSH compatibility issue affecting the `t7528-signed-commit-ssh.sh` test. The test verifies commit signing via SSH but fails on OpenSSH 10.1+ due to Unix domain socket path length limitations. Newer OpenSSH versions changed the agent socket location from `/tmp` to `~/.ssh/agent`, which - combined with Git's test directory structure - exceeds typical 108-character limits on Linux. The proposed fix uses `ssh-agent -T` to force the old `/tmp` behavior on newer OpenSSH while maintaining backward compatibility with older versions. The solution emerged from discussion with Jeff King and brian m. carlson, opting for this minimal approach (adding the flag with fallback) rather than path-shortening alternatives that might still hit limits. The commit message thoroughly documents the issue, OpenSSH version history, and solution rationale. The patch is focused on test infrastructure rather than core functionality, with clear motivation and no outstanding objections.
