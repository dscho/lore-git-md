This thread addresses an OpenSSH compatibility issue affecting the `t7528-signed-commit-ssh.sh` test, which verifies commit signing via SSH. The test fails on OpenSSH 10.1+ due to Unix domain socket path length limitations when the agent socket location moved from `/tmp` to `~/.ssh/agent`. The proposed solution uses `ssh-agent -T` to force the old `/tmp` behavior on newer OpenSSH while maintaining backward compatibility, developed through discussion with Jeff King and brian m. carlson.

Jeff King (peff) has responded to Patrick Steinhardt's solution, agreeing with the `-T` approach while identifying two additional test fragility issues: (1) spaces in Git's "trash directory" path could break shell evaluation regardless of path length, and (2) the test's fallback to using the user's real SSH_AUTH_SOCK when ssh-agent fails could expose real keys during testing. These are pre-existing problems not introduced by the current patch. Jeff considered but rejected alternatives like relative paths ("./sshsock") due to working directory change risks.

The technical core remains the interaction between `t7528`, OpenSSH 10.1+, and the 108-character Unix socket path limit, with `ssh-agent -T` as the workaround. While the solution doesn't address all test infrastructure concerns (path evaluation quirks, key exposure risk), there's consensus to proceed with this minimal fix for the immediate issue. The thread shows the patch is ready for merging, with broader test improvements potentially handled separately. Key participants are Patrick Steinhardt (solution author), Jeff King (reviewer identifying edge cases), and brian m. carlson (earlier discussion). The fix targets test infrastructure only, with no core functionality changes.
