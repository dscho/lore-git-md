This is a refactoring and bugfix patch in Patrick Steinhardt's ongoing refs subsystem modernization series, specifically addressing tag verification during peeling operations.

The patch introduces a new `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag for `peel_object()` that enables strict type checking when resolving tags. Currently, Git's tag peeling may accept incorrect object types if they aren't already cached, as `parse_tag_buffer()` doesn't fully validate the tagged object's type. The change inlines and removes `deref_tag_noverify()` since its functionality is now covered by the new flag-based approach.

Key technical changes:
- Adds flag-controlled type verification in `peel_object()`
- Removes `deref_tag_noverify()` and updates its two callers
- Maintains backward compatibility by making verification opt-in
- Touches core object handling code and all ref backends (files, packed, reftable)
- Updates test helper to use regular `deref_tag()`

The patch is part of a larger effort to clean up and optimize ref handling, building on previous interface improvements. It addresses a subtle correctness issue while maintaining the existing behavior for most callers. The verification flag will be selectively enabled in follow-up patches where stronger validation is needed.
