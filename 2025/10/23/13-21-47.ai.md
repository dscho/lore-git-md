This is a review comment on patch 09/29 of the v5 series adding `--trailer` support to `git rebase`. Phillip Wood notes that the code in this patch remains largely unchanged from v3, despite later patches in the series addressing his previous review feedback. He suggests those follow-up changes should be squashed into this foundational patch, referencing Kristoffer Haugsbakk's earlier explanation of this approach.

The patch itself introduces core `--trailer` functionality for rebase's merge backend, including:
- CLI option parsing via `OPT_STRVEC`
- Trailer validation logic in `validate_trailer_args_after_config()`
- State persistence through `rebase-merge/trailer` file
- Automatic `REBASE_FORCE` when trailers are specified
- Rejection of apply backend when trailers are requested
- Integration with sequencer via `opts->trailer_args`
- Comprehensive test coverage in new t3440 script

- Uses `strvec` for trailer argument storage
- Validates trailer syntax (rejects empty/malformed)

- Tests cover:

  - Syntax validation
  - Duplicate handling
  - Conflict scenarios
  - Root commit cases
- Touches `builtin/rebase.c`, `sequencer.c/h`, `trailer.c` infrastructure
