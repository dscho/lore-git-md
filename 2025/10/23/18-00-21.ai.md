This is a discussion about Rust-C interop infrastructure, specifically regarding the cbindgen integration patch from the ongoing series. Ezekiel Newren raises several technical points about the implementation details:

First, he suggests moving generated headers to an `interop/` subdirectory rather than the root, both for cleanliness and to simplify `.gitignore` management. He also questions how non-Rust platforms will handle C code that depends on these generated headers, hinting at a potential build system consideration.

On the cbindgen configuration, Newren shares his own `cbindgen.toml` template which includes additional settings like `sys_includes` pointing to `git-compat-util.h`, an autogeneration warning header, and explicit tab width specification (though notes cbindgen only supports spaces). This suggests possible improvements to the current configuration.

For CI dependencies, Newren argues that cbindgen should be specified as a build dependency in `Cargo.toml` rather than being listed in `install-dependencies.sh`. He further proposes converting to a Cargo workspace structure to enable per-crate header generation instead of a single monolithic file, which would provide better modularity as the Rust codebase grows.

These comments represent substantive technical feedback on the patch's approach to header generation location, configuration details, and build system integration - all key aspects for the Rust-C interop strategy. The suggestions indicate areas where the current implementation might need refinement before finalizing the cbindgen integration.
