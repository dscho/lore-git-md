This is a refactoring patch in Patrick Steinhardt's performance optimization series for the refs subsystem, specifically addressing tag peeling behavior. The patch (5/14 in v4) eliminates global state in the tag peeling mechanism by introducing a new `peeled_oid` field in `struct reference` and a corresponding accessor function `reference_get_peeled_oid()`.

The key technical changes:
- Adds `peeled_oid` to `struct reference` to store backend-provided peeled values
- Introduces `reference_get_peeled_oid()` that checks this field before falling back to ODB-based peeling
- Updates both packed and reftable backends to populate the new field
- Modifies 12 call sites to use the new interface instead of `peel_iterated_oid()`

The patch removes the fragile global iterator state previously used for peeling, making the interface more self-contained. This is part of the larger architectural cleanup needed for the final performance optimization (lazy object parsing) in patch 14/14. The changes are mechanical but important for maintaining consistency across the refactoring series.

The patch touches core refs infrastructure (refs.h, refs.c) and both backends, plus various callers that process tags (describe, gc, pack-objects, etc.). It builds on the earlier iterator unification work while preparing for the upcoming performance improvements. The implementation appears thorough, with all affected call sites updated to use the new interface.
