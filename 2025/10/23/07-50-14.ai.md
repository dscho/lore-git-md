Performance optimization for `git last-modified` command. This is the third version of a patch series that substantially reworks the algorithm to find the most recent commit modifying each path, building on prior work by Taylor Blau and Derrick Stolee.

The new implementation addresses performance issues in cases where paths haven't been modified in a long time by using a generation-sorted priority queue and path activity tracking via EWAH bitmaps. Key technical changes include:

- Adds PARENT1/PARENT2 object flags reusing SEEN/BOTTOM/BOUNDARY flag space
- Uses commit slab for active_paths_bitmap (renamed from commit_bitmaps)
- Modified diff processing to only examine active paths
- Bloom filter optimizations to skip unnecessary diffs

Performance improvements are significant: 2.5x-9.3x faster on git.git (depending on Bloom filter usage), 5.3x faster for extreme cases like `git last-modified -- COPYING t`, and 7.9x-111.7x faster on linux.git. The patch also fixes correctness issues where the old implementation could produce different results than `git log --max-count=1` due to maintenance branch merges.

Changes in v3 address compiler warnings and memory leaks:
- Fixed -Wsign-compare issues
- Removed path_idx() helper function
- Inlined bitmap handling code
- Added proper bitmap cleanup
- Small naming and comment tweaks

The implementation now uses EWAH bitmaps with pointer storage, which benchmarks show offers both memory efficiency and speed advantages at scale. The core algorithm has consensus with ongoing refinements to type safety and design questions about flag space documentation and bitmap lifecycle management.
