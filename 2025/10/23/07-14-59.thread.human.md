This thread addresses an OpenSSH compatibility issue affecting the `t7528-signed-commit-ssh.sh` test, which verifies commit signing via SSH. The test fails on OpenSSH 10.1+ due to Unix domain socket path length limitations, as newer OpenSSH versions changed the agent socket location from `/tmp` to `~/.ssh/agent`. The proposed solution uses `ssh-agent -T` to force the old `/tmp` behavior on newer OpenSSH while maintaining backward compatibility.

Jeff King (peff) has weighed in on the solution, agreeing with the approach while noting additional concerns. He points out that the space in Git's "trash directory" path could cause shell evaluation issues even with shortened paths, and that the test's fallback to using the real SSH_AUTH_SOCK could inadvertently use real keys during testing. These aren't new problems introduced by the patch but highlight existing test fragility. Jeff considered but rejected alternatives like relative paths due to potential working directory issues.

The discussion shows consensus forming around the `ssh-agent -T` solution as the most practical fix for the immediate issue, with broader test infrastructure improvements potentially addressed separately. The patch remains focused on test infrastructure rather than core functionality, with no outstanding objections to the current approach.
