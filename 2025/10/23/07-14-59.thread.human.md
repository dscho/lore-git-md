This thread addresses OpenSSH compatibility in the `t7528-signed-commit-ssh.sh` test, which verifies SSH commit signing. The core issue stems from OpenSSH 10.1+ moving agent sockets to `~/.ssh/agent`, hitting Unix domain socket path length limits. Patrick Steinhardt proposed using `ssh-agent -T` to force `/tmp` socket creation, maintaining backward compatibility.

Jeff King (peff) reviewed the patch, agreeing with the approach while identifying two pre-existing test fragility issues: shell evaluation problems with spaces in paths and potential exposure of real SSH keys. Patrick acknowledged these as separate concerns not introduced by his patch. After discussion rejecting alternatives like relative paths, consensus emerged to proceed with the minimal `-T` fix.

In the latest update, Jeff confirms the solution is sound and ready for merging, noting the patch cleanly addresses the immediate compatibility issue while leaving room for future test infrastructure improvements.
