This thread addresses an OpenSSH compatibility issue in the `t7528-signed-commit-ssh.sh` test, which verifies SSH commit signing. The test fails on OpenSSH 10.1+ due to Unix domain socket path length limitations when the agent socket location moved from `/tmp` to `~/.ssh/agent`. Patrick Steinhardt proposed using `ssh-agent -T` to force the old `/tmp` behavior, developed through discussion with Jeff King and brian m. carlson.

Jeff King identified two pre-existing test fragility issues unrelated to the immediate fix: potential shell evaluation problems with spaces in paths, and the risk of exposing real SSH keys when tests fall back to the user's SSH_AUTH_SOCK. While these warrant future attention, the thread reached consensus that they shouldn't block the current solution. Patrick has refined the patch to use the minimal `-T` workaround, rejecting alternatives like relative paths due to working directory risks. Both Patrick and Jeff agree the fix is ready for merging, leaving broader test infrastructure improvements for separate follow-ups. The discussion demonstrates careful consideration of edge cases while maintaining focus on the immediate OpenSSH compatibility problem.
