Performance optimization patch in Patrick Steinhardt's refs subsystem series. This is the final patch (14/14) in v4 of the series that has been iterating on performance improvements and architectural cleanup around ref handling.

The patch introduces lazy parsing of objects in `ref-filter.c`, only parsing object data when an atom actually needs it. This builds on previous work that separated ref handling into `struct ref` and `struct reference`. The change shows a measurable 13% speedup in `git for-each-ref --format='%(raw)'` benchmarks on a repository with 40,000 refs, with most time now spent on object decompression.

Key technical changes include:
- New `get_or_parse_object()` helper that parses objects on demand
- Modified `grab_*_values()` functions to handle deferred parsing
- Removal of eager object parsing in `get_object()`
- Careful handling of object memory management via `eaten` flag

The patch appears well-constructed with thorough benchmarking and maintains all existing functionality while improving performance. It completes the series' goal of optimizing ref handling while cleaning up the architecture. Given the positive feedback on previous iterations and the clear performance gains, this seems ready for inclusion.
