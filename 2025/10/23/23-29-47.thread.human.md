This thread reports issues with Git's handling of custom diff drivers and textconv configuration, particularly when misconfigured. The original problem involved a PDF diff driver using `pdftotext` without proper stdout redirection, leading to empty file outputs without clear warnings from Git. 

Several problematic behaviors were identified: textconv drivers with `cachetextconv` unexpectedly create commits that expose repository configuration issues; custom diff drivers execute in temporary directories that Git attempts to clean up poorly; and `git diff`/`git log` crash ungracefully when diff drivers fail. The `--simplify-by-decoration` behavior was also noted as potentially confusing. 

The reporter suggests improving documentation around these edge cases and adding better diagnostics for misconfigured textconv drivers. While the immediate issue stemmed from user error, the email highlights multiple areas where Git's behavior could be more robust, particularly around temporary file handling and error reporting for custom diff tools. The thread appears to be seeking both documentation improvements and potential code changes to make these failure modes clearer to users.
