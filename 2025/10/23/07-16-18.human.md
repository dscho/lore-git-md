This is a refactoring patch in Patrick Steinhardt's performance optimization series, removing obsolete infrastructure from the refs subsystem.

The patch eliminates the `current_ref_iter` global variable and associated peeling function that were previously used as a performance optimization during reference iteration. With the series' earlier refactoring to use `struct reference` and its `peeled_oid` field consistently across all callers, this hack is no longer needed. The change removes about 30 lines of code across three files while maintaining the same functionality through the cleaner interface.

This is part of a larger effort (patches 1-9 in the v4 series) to modernize the refs subsystem by separating transport-related `struct ref` from core `struct reference` and improving the peeling interface. The removal of this global variable makes the code more robust and easier to understand, as noted in the commit message. The change builds on previous patches that migrated all callers to use the new `reference_get_peeled_oid()` interface.

The patch appears well-contained and low-risk, being a straightforward cleanup of code that is no longer used. It follows logically from the series' earlier work and helps complete the architectural improvements to the refs subsystem.
