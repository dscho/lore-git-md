Refactoring patch in a performance optimization series, removing the `current_ref_iter` global variable hack after refactoring peeling behavior.

This patch eliminates the `current_ref_iter` global variable and associated peeling infrastructure that was previously used as a performance optimization during reference iteration. The change builds on prior work that moved peeling information into `struct reference`, making the global variable obsolete. The removal affects three files:
- Deletes the `peel_iterated_oid()` function from refs.c
- Removes `current_ref_iter` handling from iterator.c
- Eliminates the variable declaration and documentation from refs-internal.h

The change is part of a larger effort to modernize the refs subsystem by replacing ad-hoc optimizations with cleaner interfaces. The patch demonstrates good architectural hygiene by removing now-unused code paths while maintaining all existing functionality through the new `reference_get_peeled_oid()` interface. This represents the final step in eliminating the old peeling infrastructure after all callers were converted in previous patches.

The removal of global state improves thread safety and makes the code easier to reason about, though the performance impact appears neutral since equivalent optimizations are now handled through the `struct reference` interface. The change is low-risk as it follows extensive refactoring that already validated the new approach.
