Performance optimization for `git last-modified` command. This is the third iteration of a patch series that substantially reworks the algorithm to be more efficient when finding the most recent commit modifying each path in a repository.

The new implementation uses a priority queue sorted by generation number and tracks "active" paths (those not yet associated with a commit) using EWAH bitmaps. Key improvements include:
- Avoiding unnecessary diff computations by skipping parts of history where paths are known to be inactive
- Using Bloom filters to optimize first-parent diffs
- Fixing correctness issues where the old implementation could give different results than `git log --max-count=1`

Benchmarks show dramatic speedups:
- 2.5x-9.3x faster on git.git (depending on Bloom filter usage)
- 5.3x faster for extreme cases like `git last-modified -- COPYING t`
- 7.9x-111.7x faster on linux.git

The patch has undergone multiple rounds of review from Taylor Blau, Jeff King, and Junio C Hamano, addressing technical issues like NULL oid segfaults, memory management, and compiler warnings. The current version resolves sign comparison warnings and memory leaks while maintaining the performance gains.

This represents a significant improvement to a command that can be painfully slow on large repositories with rarely-modified paths. The algorithmic approach is now well-vetted through collaborative review and benchmarking across multiple codebases.
