This is a refactoring and bugfix patch from Patrick Steinhardt that adds stricter type verification when peeling tag objects. It's part of a larger series modernizing Git's ref handling code.

The patch addresses a subtle issue where Git doesn't properly verify the type of objects referenced by tags during peeling. Currently, if a tag points to an object with an incorrect type (like a blob masquerading as a commit), Git may not detect this until much later. The change introduces a new `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag that callers can use to enforce type checking during peeling.

Key technical changes include:
- Adding a flags parameter to `peel_object()`
- Inlining and removing the `deref_tag_noverify()` function since its functionality is now covered by the new flag
- Updating all callers to pass the flag (currently set to 0 to maintain backward compatibility)
- Adding proper type verification when the flag is enabled

The patch maintains backward compatibility while providing the infrastructure for stricter verification in future changes. It's a well-contained change that fits cleanly into the larger refactoring series, though the commit message notes there may be follow-up work needed to determine the right level of strictness for tag verification.
