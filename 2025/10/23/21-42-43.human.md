This is the third patch in a series introducing cbindgen support for Git's Rust-C interop, focusing on the core implementation. The patch sets up cbindgen infrastructure in both Makefile and Meson build systems, using varint implementation as a test case to verify type consistency between Rust and C.

The key technical aspect is the header generation approach - originally placing bindings in varint.h caused excessive recompilation, so the patch moves them to varint.c instead. The commit demonstrates how mismatched function signatures (like uint32_t vs uint64_t return types) now trigger compile-time errors. Junio Hamano's response shows the generated header output, which includes safety documentation for the varint functions.

The patch builds on earlier series components (CI preparation and build system standardization) and incorporates feedback from the mailing list discussion. While the core functionality appears sound, some architectural questions remain open from earlier reviews, particularly around header organization and build system integration for non-Rust platforms. The verification mechanism through varint type checking provides a concrete example of the interop benefits this series aims to deliver.
