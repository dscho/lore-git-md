Maintainer review of Rust cbindgen CI integration. Junio Hamano provides feedback on the third patch in the series introducing cbindgen support for Git's Rust-C interop. The specific focus is on CI script modifications to install cbindgen dependencies.

The review notes a formatting issue with the overly long line in `ci/install-dependencies.sh` that adds cbindgen to the package list for Fedora/AlmaLinux builds. Hamano observes this should be wrapped to stay within Git's 120-column limit. More critically, he reports the change causes CI failures on AlmaLinux 8 due to missing cbindgen package in contrast to the successful Fedora builds.

This surfaces a platform compatibility consideration for the Rust interop work - while the series has progressed through technical reviews of its core functionality (header generation, build system integration), this late-stage CI discovery shows some Linux distributions may not package cbindgen in their default repositories. The feedback doesn't block the overall approach but highlights a practical deployment hurdle that will need resolution, likely through either conditional installation logic or documentation of platform requirements.

The exchange continues the pattern seen throughout the thread where infrastructure-level concerns (here, CI reliability) receive equal attention to the Rust interop functionality itself.
