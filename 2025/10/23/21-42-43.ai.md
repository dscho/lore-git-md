This is the third patch in a series introducing cbindgen support for Git's Rust-C interop, focusing on the core implementation. The patch sets up cbindgen infrastructure in both Makefile and Meson build systems, demonstrating its use by generating a "c-bindings.h" header that's included in "varint.c" to verify type consistency between Rust and C implementations of varint functions.

Key technical details include:
- Generated header placement in root directory (though Ezekiel Newren suggested moving to `interop/`)
- Header inclusion strategy (directly in "varint.c" rather than "varint.h" to avoid excessive recompilation)
- CI adaptation to install cbindgen
- Example verification mechanism showing compiler errors when Rust/C signatures mismatch
- Safety documentation for the exported functions (decode_varint and encode_varint)

Junio Hamano notes the implementation looks reasonable, particularly the "make c-bindings.h" approach. The patch follows the series progression from CI preparation to build system changes to this core functionality. It addresses Rust-C interop challenges while leaving some architectural questions open from Newren's feedback about header organization and build system integration.

The verification mechanism is working as intended - the example shows it catching signature mismatches between Rust and C implementations. The safety documentation in the generated bindings shows attention to FFI boundary concerns. This represents a concrete step in Git's Rust infrastructure development, though some design decisions around header management may evolve based on ongoing discussion.
