Performance optimization and refactoring series for tag peeling and object parsing in Git's refs subsystem. This v4 series from Patrick Steinhardt builds on previous work to modernize ref handling, with a focus on lazy object parsing optimizations and tag verification improvements.

The series consists of 14 patches organized into several logical groups:
1. Interface refactoring (patches 1-8) removes the `peel_iterated_object()` hack, introducing cleaner iterator-based peeling
2. Cleanup (patches 9-10) removes now-unused infrastructure
3. Bugfixes (patches 11-13) address issues with tag verification where stored object types might not match actual objects
4. Performance optimization (patch 14) implements lazy object parsing in ref-filter

Key technical changes include:
- New `reference_get_peeled_oid()` interface for cleaner tag peeling
- Verification of tag object types during peeling via `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag
- Prevention of caching peeled OIDs for invalid tags
- Lazy parsing via new `get_or_parse_object()` helper that now returns object pointers directly
- Extensive test coverage for both files and reftable backends

The series has evolved through multiple versions with:
- Improved ergonomics for `get_or_parse_object()` in v4 (direct object pointer return)
- Rebase on pending topics (tb/incremental-midx-part-3.1 and jt/repo-structure)
- Additional test coverage and commit message improvements

Performance impact shows 13% speedup in `git for-each-ref --format='%(raw)'` operations. The author expresses some uncertainty about the tag verification approach (patches 11-13) being too incremental rather than a comprehensive fix, and welcomes alternative suggestions. The series is now complete with all substantive feedback addressed and awaits final integration.
