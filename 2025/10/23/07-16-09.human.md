This is the final version of a performance optimization and refactoring series for Git's refs subsystem, focusing on tag peeling behavior and lazy object parsing. The series has evolved through multiple iterations with input from several core contributors.

Patrick Steinhardt presents version 4 of his 14-patch series that began as a simple performance optimization for `git-for-each-ref` but uncovered deeper architectural issues. The series now combines refactoring, cleanup, bugfixes, and performance improvements while maintaining separation between transport-related and core ref handling.

Key aspects of this final version:
1. The first 10 patches refactor and clean up tag peeling infrastructure, removing the `peel_iterated_object()` hack while preserving behavior
2. Patches 11-13 address tag verification issues where tag objects might store mismatched type information
3. The final patch (the original motivation) implements lazy object parsing in ref-filter, showing a 13% speedup in certain operations

Notable changes in v4 include improved ergonomics for the new `get_or_parse_object()` helper function, following Junio Hamano's suggestion to return the object pointer directly rather than via an output parameter. The series has been rebased on pending topics (tb/incremental-midx-part-3.1 and jt/repo-structure) that are about to be merged.

Patrick expresses some reservations about patches 11-13, noting they feel like "whack-a-mole" fixes rather than a complete solution for tag verification. He invites alternative approaches but believes the core improvements are ready for merging while leaving architectural questions for follow-up work.

The series has received positive reviews and is now in its final form, with all substantive feedback addressed. It represents a significant step in the ongoing refs subsystem modernization while delivering measurable performance benefits.
