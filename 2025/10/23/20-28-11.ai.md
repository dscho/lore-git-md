Bugfix addressing edge case in Git's pattern matching for `.gitignore` and `.gitattributes` files, specifically around `**` patterns. This is a follow-up to Jeff King's RFC patch that fixed incorrect matches like `foo**/bar` matching `foobar`.

Junio Hamano reviews Jeff's solution - which preserves one character of prefix context when passing to `fnmatch()` to maintain directory boundary awareness - and suggests two refinements: (1) Moving the "whole pattern matched" check before prefix stripping for cleaner logic, and (2) Considering a more targeted fix that only adjusts the prefix when encountering `**/` patterns rather than always keeping one character.

The review notes that while Jeff's solution works, the performance benefit of prefix stripping may be minimal beyond skipping `fnmatch` entirely for non-wildcard patterns. A test case verifies the fixed behavior where `foo**/bar` should match `foo/bar` but not `foobar`.

Key technical details:
- Core issue remains in `match_pathname()` in `dir.c`
- Fix involves prefix length adjustment before `fnmatch` call
- Impacts both `.gitignore` and `.gitattributes` pattern matching
- Test added in `t/t0008-ignores.sh`

The discussion continues to weigh the tradeoffs between Jeff's general solution and more targeted approaches, with Junio leaning toward potentially simpler alternatives if performance data shows limited benefit from aggressive prefix stripping. No new edge cases or regressions are identified beyond what was covered in the original RFC.
