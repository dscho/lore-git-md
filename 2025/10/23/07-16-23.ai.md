Performance optimization patch completing Patrick Steinhardt's refs subsystem modernization series, introducing lazy object parsing in ref-filter.

This final patch in the v4 series (14/14) optimizes object parsing in `ref-filter.c` by making it lazy - objects are only parsed when an atom actually needs the parsed data, rather than always parsing up front. The key change is the introduction of `get_or_parse_object()` which handles the conditional parsing, plus modifications to the various `grab_*_values()` functions to use this new helper.

The patch shows a 13% speedup in `git for-each-ref --format='%(raw)'` benchmarks on a Chromium repository with ~40k refs (344.7ms vs 388.7ms). The commit message notes that after this change, ~90% of time is spent in object decompression, suggesting the ref-filter infrastructure itself is now quite optimized.

Technical changes include:
- New `maybe_object` field in `expand_data` to cache parsed objects
- `get_or_parse_object()` helper that parses only when needed
- Conversion of all value-grabbing functions to return errors and accept `expand_data` rather than parsed objects
- Removal of the separate `get_object()` path that did upfront parsing
- Maintenance of all existing functionality while making parsing lazy

This builds on the previous refactoring work in the series that separated peeling interfaces and verification behaviors. The performance gains come from avoiding unnecessary object parsing for atoms that don't need it (like raw`%`(raw)` which just outputs the object content directly). The change is particularly impactful for repositories with many refs where the parsing overhead was significant.
