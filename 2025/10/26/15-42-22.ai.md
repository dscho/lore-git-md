This is the second patch in Jeff King's series fixing a bug in Git's pattern matching behavior for `.gitignore` and `.gitattributes` files. The issue involves incorrect matching of patterns like `foo**/bar` against paths like `foobar` due to the optimization in `match_pathname()` that strips matching characters before calling `fnmatch()`.

The patch implements the "minusone" solution discussed in the thread, preserving one character of context during prefix stripping to maintain directory boundary awareness. The key changes are:
1. Decrementing the prefix length by 1 before passing to `fnmatch()`
2. Adding a test case that verifies `foo**/bar` correctly matches `foo/bar` but not `foobar`

The solution maintains the optimization's performance benefits (1.46x speedup for exact matches) while fixing the `**` pattern matching behavior. The implementation follows Junio Hamano's suggestion to separate the preparatory refactoring (patch 1/2) from this behavioral change.
