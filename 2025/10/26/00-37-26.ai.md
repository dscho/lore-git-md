This is a follow-up discussion in the `git add -p` refactoring thread about EOF handling behavior. The conversation clarifies the user experience design for silent exits (via Ctrl-D/EOF) versus explicit 'q' command exits.

Junio C Hamano notes that while explicit 'q' commands echo the character before exiting, EOF exits silently, which feels abrupt but may be more natural for shutdown scenarios. René Scharfe reinforces that silent EOF matches Unix conventions (like `cat` behavior) and prefers this approach. The discussion confirms the silent exit is intentional and consistent with user expectations, particularly in `interactive.singlekey` mode where 'q' shows feedback but EOF does not.
