This is a follow-up discussion about the recently approved `git add -p` refactoring series that simplifies exit handling. The conversation focuses on whether EOF (Ctrl-D) input should echo a 'q' character like explicit quit commands do, or remain silent.

Junio C Hamano notes that while the silent EOF exit feels slightly abrupt compared to the explicit 'q' command which echoes the character, he acknowledges it may be more natural for shutdown behavior. René Scharfe provides the rationale that silent EOF matches common Unix conventions (like `cat` behavior) and expresses personal expectation for no feedback in this case.

The discussion reveals that this EOF handling detail went unnoticed in existing tests, possibly because most test cases either use explicit 'q' commands or happen to be at the final hunk when EOF occurs. Both maintainers agree the silent behavior is acceptable, with Junio noting this completes the series' goal of consistent exit handling while maintaining stable interfaces.

This exchange confirms the design choice in the second patch of the series, which makes EOF trigger immediate exit without processing remaining hunks. The thread shows maintainer consensus on keeping the silent EOF behavior as it aligns with Unix conventions and the patch's goal of simplifying the code.
