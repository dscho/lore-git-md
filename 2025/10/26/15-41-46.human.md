This is the first of two patches fixing Git's `**` pattern matching behavior in `.gitignore` and `.gitattributes` files. The patch series addresses a bug where patterns like `foo**/bar` incorrectly matched `foobar`, despite documentation requiring slashes around `**` for special meaning.

Jeff King restructures the prefix-matching logic in `match_pathname()` to check for complete matches before adjusting the pattern and path strings. This is a preparatory refactoring for the actual bugfix in the second patch, making the code clearer and more flexible for the subsequent change. The patch moves the early-return check for exact matches before the string pointer adjustments, which will enable preserving context for wildcard matching in the next patch.

The change is minimal (11 lines modified) and maintains all existing functionality while improving code organization. Jeff notes there's no measurable performance impact from this change, though it might theoretically save a few instructions. This is a clean, focused refactoring that sets up for the more substantive fix to follow.
