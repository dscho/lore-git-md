This is the first patch in a two-part bugfix series addressing incorrect `**` pattern matching behavior in Git's ignore/attribute system. The patch reorganizes the prefix-matching logic in `match_pathname()` (dir.c) to check for complete matches before adjusting the pattern and pathname pointers. This structural change prepares for the subsequent fix that will preserve directory boundary context during prefix stripping.

The key technical change moves the early-return check for exact matches before the pointer adjustments, making the code flow more logical while maintaining the same behavior. Jeff notes this might offer minor optimization benefits, though measurements didn't show improvement. The diff is clean (6 insertions, 5 deletions) and maintains all existing functionality while setting up for the more substantive fix in patch 2/2.

This refactoring was suggested by Junio Hamano during review of the initial approach, separating the structural improvement from the behavioral fix. The change helps clarify the code's intent by checking complete matches first, rather than the previous "== 1" check after pointer adjustment. Test coverage for the fixed behavior will come in the second patch.
