Performance analysis of Git's pattern matching optimization in `dir.c`.

Jeff King provides detailed benchmark results comparing four variants of Git's pattern matching behavior for `.gitignore` files, specifically examining the performance impact of prefix-stripping optimizations in `match_pathname()`. The variants tested are: original implementation (`git.orig`), complete removal of prefix matching (`git.none`), keeping only the full-match optimization (`git.fullonly`), and the proposed "minusone" approach that preserves one character of context for `fnmatch()`.

Key findings show that prefix-stripping provides significant performance benefits (1.46x faster than no optimization for exact matches) and that the proposed one-character context preservation (`git.minusone`) performs equivalently to the original implementation for prefix matches while fixing the `**` matching bug. The benchmarks reveal that `fnmatch()` is substantially slower than direct string comparison (`strcmp`), validating the optimization's value despite initial skepticism.

The analysis suggests keeping the optimization with the one-character context adjustment, as it maintains performance benefits while fixing the documented behavior for `**` patterns. The email concludes by noting this doesn't address real-world frequency of different match types, but the small code footprint and clear performance wins make the optimization worth preserving. This provides concrete data to support Jeff's original RFC patch approach over Junio's suggested alternatives.
