This is a follow-up to the refactoring series for `git add -p`'s exit handling. Junio C Hamano provides a squashed version of René Scharfe's test case for EOF handling, replacing the raw `grep` calls with Git's `test_grep` helper. The test verifies that `git add -p` exits immediately on EOF (simulated via `/dev/null` input) after showing the first file's diff but before processing the second file.

The change is purely about test hygiene - replacing direct `grep` with the more robust `test_grep` wrapper that provides better error messages. This maintains the same test coverage while following Git's testing best practices. The test continues to validate the core behavior that was the subject of the original patch series: EOF should trigger immediate exit from the interactive interface, just like the 'q' command does.

This appears to be the final polish on the series, with Junio (the maintainer) incorporating René's test improvement suggestion directly into the codebase. The thread has reached consensus on both the implementation approach and the testing strategy for this EOF handling behavior.
