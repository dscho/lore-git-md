Bugfix targeting external diff output redirection. This is the first patch in a series cleaning up diff dry-run behavior, focusing on fixing a long-standing issue where external diff commands weren't properly respecting the `--output` file redirection.

The patch addresses a specific case where external diff programs (specified via `GIT_EXTERNAL_DIFF`) would ignore the output file specified in `diff_options.file`, instead writing to stdout. The fix involves carefully redirecting the external program's output while handling several edge cases around file handles and flushing behavior. Key technical details include proper descriptor duplication to avoid closing the original FILE pointer, and maintaining existing behavior for stdout and quiet modes.

The change is well-motivated with clear explanations of the technical considerations and comes with a new test case demonstrating the fix. This appears to be a straightforward correction of clearly wrong behavior that's been present since 2008, though it's worth noting this is just the first step in a larger refactoring effort around dry-run behavior. The patch touches `diff.c` and adds a test in `t/t4020-diff-external.sh`, with careful attention to descriptor management that will be relevant for the subsequent patches in the series.
