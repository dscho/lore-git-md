This is a refactoring patch that's part of a larger series introducing geometric repacking strategies for Git maintenance. It removes a global `repack` variable in `builtin/gc.c` that was used to accumulate arguments for `git repack` commands, replacing it with a stack-allocated version that gets passed around explicitly.

The change makes the code more transparent by eliminating hidden state and better supporting reuse of the repacking logic in other contexts (which will be important for the geometric repacking feature coming in later patches). The author notes the most subtle part is handling the `need_to_gc()` function, which is used by both `git gc --auto` and maintenance tasks - they solve this by using a throwaway variable for the maintenance case since the arguments will be recomputed anyway when spawning a child process.

The patch appears well-considered, with careful attention to edge cases and clear explanations of the rationale. It's a foundational change that enables the more interesting geometric repacking functionality to come in the series, which has already received positive feedback from maintainers in previous iterations.
