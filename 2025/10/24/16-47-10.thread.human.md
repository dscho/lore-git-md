René Scharfe has optimized the commit-reach code to handle pathological cases with large numbers of merge bases more efficiently. The change replaces quadratic-time sorting during merge base calculations with a linear append-and-sort pattern, yielding dramatic speedups in extreme cases - a test scenario with 16,384 merge bases now runs 94.5% faster (from 0.55s to 0.03s).

While most repositories won't see noticeable improvement (since they have few merge bases), the change protects against performance cliffs in complex merge histories. A new performance test (t/perf/p6010-merge-base.sh) demonstrates the optimization by constructing a stress test repository with parallel commit histories using git fast-import.
