This is the second patch in a 13-part series refactoring Git's loose object handling as part of the object database (ODB) abstraction effort. The patch introduces a new `odb_source_new()` helper function to consolidate duplicate code for creating ODB sources that was previously spread across three different locations.

The change is a straightforward refactoring that creates a single point of initialization for `struct odb_source` objects, which represent sources of Git objects (like loose object directories). The new function handles the common to all three call sites: memory allocation, setting the ODB pointer, storing the path, and marking whether the source is local. The patch touches odb.c, odb.h, and repository.c, with clean mechanical changes that don't modify behavior.

This is part of Patrick Steinhardt's larger effort to abstract and consolidate Git's object storage backend code. The patch appears well-contained and follows good practices - the commit message clearly explains the change, and the diff shows careful attention to memory management (noting where paths need to be freed or duplicated). As an early step in the series, it lays groundwork for more substantial refactoring to come.
