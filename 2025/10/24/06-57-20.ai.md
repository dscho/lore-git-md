This is a refactoring patch in the geometric repacking strategy series, introducing type-based task execution control for Git maintenance operations. The patch distinguishes between manual (`git maintenance run`) and scheduled (`git maintenance run --schedule=`) maintenance contexts, converting the previous boolean `enabled` field into a bitmask of `MAINTENANCE_TYPE_*` flags.

Key technical changes include:
- New `enum maintenance_type` with `MAINTENANCE_TYPE_SCHEDULED` and `MAINTENANCE_TYPE_MANUAL` flags
- Conversion of strategy definitions to use type flags instead of simple enabled/disabled
- Updated `initialize_task_config()` to handle type-based task filtering
- Preservation of existing behavior where default strategy only runs manually and incremental strategy only runs scheduled
- The patch maintains backward compatibility while enabling future expansion of type-based control
- Core logic remains in `builtin/gc.c` with strategy definitions now using type flags
- No test changes needed as this is purely internal refactoring preserving existing behavior

This change enables the subsequent patches in the series to implement the geometric repacking strategy that can operate in both manual and scheduled contexts, addressing one of the key limitations noted in earlier thread discussion. The implementation follows the thread's established pattern of using bitmask flags for configuration while keeping the changes focused and incremental.
