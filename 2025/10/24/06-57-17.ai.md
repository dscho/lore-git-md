This patch introduces configurable geometric repacking factors for Git maintenance, part of the ongoing geometric repacking strategy series that has received maintainer approval. It adds a new `maintenance.geometric-repack.splitFactor` configuration option that controls the geometric sequence factor used during repacking, defaulting to 2 (matching `git repack`'s default behavior). The implementation reads this config in both the main repack task and auto-condition checking logic, ensuring consistent behavior between manual and automatic maintenance runs.

The change allows repositories to tune how aggressively packs are merged - a higher factor results in fewer merges but potentially larger individual packs. This is particularly useful for very large repositories where the default factor of 2 might cause too frequent repacking. The patch includes thorough test coverage that verifies the configuration is properly honored by creating test packs and checking the repack command receives the correct geometric factor parameter.

Key technical details:
- New config option documented in maintenance.adoc
- Config read via `repo_config_get_int()` in both `maintenance_task_geometric_repack()` and `geometric_repack_auto_condition()`
- Uses `strvec_pushf()` to pass the configured factor to `git repack --geometric=`
- Test case creates packs with 9, 2 and 1 objects to verify different split factors
- Test helper `test_geometric_repack_needed` verifies auto-condition behavior
- Test uses `test_subcommand` to verify correct repack arguments

This completes the geometric repack task implementation by making its core parameter configurable, following the same pattern as the existing `maintenance.geometric-repack.auto` threshold. The change is well-integrated with the series' existing infrastructure and maintains consistency with `git repack`'s behavior while providing needed flexibility for large repositories.
