This is a technical discussion about the Rust-C interop implementation details in the cbindgen patch series, specifically addressing header location, cbindgen configuration, and build system integration.

Patrick Steinhardt responds to Ezekiel Newren's review comments on the cbindgen implementation. He argues against moving generated headers to an `interop/` directory for now, suggesting either keeping them in the root (current approach) or creating a general `generated/` directory for all build artifacts. He notes the header is included conditionally when Rust support is enabled, addressing concerns about non-Rust builds.

The discussion dives into cbindgen.toml configuration details, with Patrick agreeing on most points but suggesting:
- Omitting `git-compat-util.h` inclusion in generated headers to maintain project conventions
- Using 8-space indentation to better align with Git's style
- Keeping `parse_deps = false` as the default
- Adding `usize_is_size_t = true` for better type compatibility

Patrick pushes back on two suggestions:
1. Against specifying cbindgen in Cargo.toml build-dependencies, arguing it's unnecessary since the tool isn't used via build.rs and would slow CI
2. Against introducing Cargo workspaces now, preferring to wait until multiple crates justify the complexity

The exchange shows Patrick maintaining the current implementation approach while selectively incorporating improvements (like usize handling) and deferring structural changes (workspaces, header location) until clearer needs emerge. This continues the thread's pattern of balancing immediate Rust integration needs with long-term maintainability concerns.
