Feature completion with concerns about default behavior. This is the final patch in Christian Couder's series to unify signature handling between `git fast-import` and `git fast-export`. It adds a `--signed-tags=<mode>` option to `fast-import` that mirrors the existing `--signed-commits` option, completing the symmetry between the two commands.

Elijah Newren raises an important concern about the default behavior - while the patch sets the default to `verbatim` (keeping signatures as-is), he argues this may lock in a suboptimal choice long-term. He suggests changing the default to `abort` (which fails on signed tags) before the 2.52 release, allowing more discussion about the ideal default behavior later. The technical implementation itself looks solid, with comprehensive tests covering PGP, X.509 and SSH signatures across various modes.

The patch follows the same pattern as the earlier signed-commits work, using the shared `parse_signed_buffer()` infrastructure. It adds a new `handle_tag_signature()` function that applies the selected mode (verbatim, strip, warn, or abort) consistently. Test coverage is thorough, verifying both signature preservation and stripping behaviors across all supported signature types. While the implementation appears ready, the default behavior discussion may need resolution before final merge.
