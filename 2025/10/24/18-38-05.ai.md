This is a bug report and analysis of a platform-specific issue in Git's notes subsystem on NonStop systems (big endian x86). Randall Becker continues the investigation into why `git notes show HEAD` fails with an unusual exit code (-12) while direct invocation works.

Key technical details:
- The notes subsystem incorrectly converts `git notes show HEAD` into a `git show` command for blob hash 1aa950256... instead of the correct HEAD commit (3fc1917e0...)
- On NonStop, this triggers an immediate execvp() failure with platform-specific error -12 ("invalid object" referring to executable path)
- Direct invocation with the proper arguments correctly reports "no note found" (exit code 1)
- The discussion confirms the issue lies in the notes command construction path in builtin/notes.c, not in object validation

The email clarifies that the problem stems from the notes-to-show command conversion generating an incorrect blob hash, which then causes platform-specific execvp() behavior on NonStop. This narrows the debugging focus to the notes subsystem's command construction logic. The thread has effectively ruled out pager interaction and process execution paths, isolating the issue to hash handling during notes command conversion.
