Feature refinement for `git replay` atomic ref updates configuration.

Christian Couder provides final review feedback on the third patch in the atomic ref updates series for `git replay`, focusing on code organization and test improvements. The patch adds the `replay.refAction` config option to control whether reference updates are performed atomically (default) or just printed.

Couder suggests extracting the ref action mode parsing logic into a dedicated function `get_ref_action_mode()` that would handle both command-line and config values in a single place, improving code organization. The proposed function would first check the command-line argument, then fall back to config, and finally to the default update mode, with consistent error handling throughout.

For the test suite, Couder notes that using `test_grep` instead of raw `grep` would provide better error reporting when matching the output of the print mode. This matches the series' emphasis on robust test coverage for the new configuration option.

The feedback comes as the final round of review before merging, addressing minor code organization and testing nits after the core functionality and interface design had already been approved by maintainers. The changes suggested would polish the implementation without altering the already-approved behavior or user interface.
