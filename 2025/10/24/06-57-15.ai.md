This is a refactoring patch in the geometric repacking strategy series, specifically modifying the `too_many_loose_objects()` function in `builtin/gc.c` to make it more flexible for future callers.

The patch simplifies `too_many_loose_objects()` to take just the threshold limit as a parameter rather than the entire `gc_config` struct, since that was the only field being used. This change makes the function more reusable for contexts where the caller wants to specify a different threshold than what's in the standard GC configuration. The patch updates all existing callers to pass `cfg->gc_auto_threshold` directly.

This appears to be a straightforward preparatory change for the geometric repacking functionality introduced later in the series. The modification is clean and mechanical, with no behavior changes - it's purely an interface improvement to support the new maintenance strategy work. The patch maintains all existing functionality while making the code more flexible for future needs.

The change is part of a larger effort that has already received maintainer approval, with Junio C Hamano and Taylor Blau having signed off on the overall approach. This particular patch was reviewed in previous iterations of the current v3 series, with the final version incorporating any feedback.
