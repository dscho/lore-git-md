This is a bugfix discussion thread focused on a platform-specific issue with Git's notes subsystem on NonStop systems. The investigation has narrowed down to a problem where `git notes show HEAD` incorrectly converts to a `git show` command with the wrong blob hash (1aa950256...) instead of the actual HEAD commit (3fc1917e0...).

Randall Becker confirms Jeff King's suspicion that the notes subsystem is incorrectly constructing the command, passing the wrong hash to `git show`. On NonStop systems, this manifests as an immediate execvp() error (-12), while other platforms would likely show "no note found" (exit code 1). The key finding is that the notes command conversion logic in builtin/notes.c is generating an incorrect blob hash during the show operation.

The discussion remains technical but productive, with both participants carefully verifying their observations. The next step would be to examine the notes-to-show command construction path to identify why it generates the wrong hash. This appears to be a genuine bug rather than a platform-specific quirk, though NonStop's execvp behavior makes it more immediately visible there.
