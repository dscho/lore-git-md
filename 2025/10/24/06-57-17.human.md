Feature enhancement for geometric repacking in Git maintenance. This patch makes the geometric split factor configurable via `maintenance.geometric-repack.splitFactor`, defaulting to 2 (matching `git repack`'s behavior). The change allows repositories to tune how aggressively packs are merged during maintenance, which can be particularly useful for very large repositories where less frequent merging may be desired.

The implementation adds the new config option, updates the documentation, and modifies both the repack execution and auto-condition checking to respect the configured value. A new test verifies that the configured split factor is properly passed to `git repack`, demonstrating how different factors affect which packs get merged.

This is part of a larger series (v3 04/10) introducing geometric repacking strategies to Git maintenance, which has already received extensive review and maintainer sign-off. The patch appears well-crafted with clear documentation and thorough test coverage. The change is backward-compatible and maintains consistency with existing `git repack` behavior while providing additional flexibility.
