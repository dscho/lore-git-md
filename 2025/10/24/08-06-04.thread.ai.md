Thread identity: Documentation request for `git log` pretty formats, specifically regarding the "oneline" format string equivalent and undocumented placeholder terminology like "title-line" and "full-commit-message".

Core problem: The `git log` manpage describes built-in formats behaviorally but doesn't expose their exact format string implementations or make all descriptive terms consistently searchable/documentable. This creates discoverability issues for users trying to customize log output, particularly when incorporating notes (%N).

Key technical details:
- Built-in formats like "oneline" have undocumented equivalent format strings
- Placeholder terminology in descriptions (e.g. "title-line") isn't directly usable in custom formats
- Notes (%N) formatting could be better documented for compact display
- The `--oneline --notes` combo provides a practical workaround for notes display without format string construction
- Notes formatting complexity stems from their free-form text nature
