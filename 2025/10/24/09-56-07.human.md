Refactoring patch in Patrick Steinhardt's ODB abstraction series (8/13). This continues the work to move loose object handling into a dedicated `struct odb_loose_source`.

The patch relocates the loose object map - which translates between canonical and compatibility hashes - from the general `odb_source` to the more specific `odb_loose_source` where it logically belongs. This is a mechanical change that:
- The map's declaration and initialization
- All access points in loose.c
- The cleanup path in object-file.c
- Header files to reflect the new location

The changes are straightforward and maintain existing behavior while improving encapsulation. This continues the series' pattern of incrementally moving loose-object-specific functionality out of the generic ODB infrastructure. No functional changes or new edge cases introduced - just another step in the codebase reorganization to support pluggable backends.
