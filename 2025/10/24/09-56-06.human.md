This is patch 7/13 in Patrick Steinhardt's series refactoring Git's loose object handling as part of the object database abstraction effort. The patch focuses on cleaning up how the loose object cache is managed during repreparation.

The change introduces a new `odb_loose_source_reprepare()` function to handle cache clearing when repreparing loose object sources, matching the pattern already established for packfiles. This hides implementation details that were previously exposed in `odb_reprepare()`. The patch also renames `odb_clear_loose_cache()` to the more specific `odb_loose_source_clear()` to better reflect its scope.

This continues the series' pattern of mechanical cleanups that improve the ODB infrastructure's organization without changing behavior. The changes touch object-file.c/h and odb.c, moving toward a more consistent interface for managing loose object caches. The patch appears well-contained and follows the established direction of the series, though as with previous patches, the broader architectural impact will become clearer as the series lands.
