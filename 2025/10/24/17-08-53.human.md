This is the third patch in a 4-part series refactoring Git's dry-run diff behavior, converting from an explicit boolean flag to using the NULL state of the output file pointer as the dry-run indicator. The change represents a significant design shift in how dry-run mode is implemented.

The patch replaces all checks of `diff_options.dry_run` with checks for `diff_options.file == NULL`, then removes the now-unused `dry_run` flag from the struct. The key motivation is that any code path trying to write output during dry-run would be a bug, and NULL file pointers will cause immediate segfaults rather than silently sending garbage to `/dev/null`. This makes programming errors more visible while maintaining the same user-visible behavior.

The changes are mechanical but widespread, touching several diff output functions in `diff.c`. The author notes this approach was inspired by observing that all dry-run bugs found so far were cases where code was incorrectly using the output file when it shouldn't. The patch follows two preparatory cleanups (patches 1-2) and precedes one final refactoring (patch 4) in the series.

This represents a more opinionated design choice than the previous patches - while the changes are straightforward, the switch to NULL-pointer semantics could be controversial as it trades silent failures for crashes. The patch appears well-reasoned and carefully implemented, with all test cases passing, but reviewers may want to scrutinize whether this approach could have unintended consequences in edge cases.
