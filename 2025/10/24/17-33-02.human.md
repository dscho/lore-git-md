This is a bug report investigating platform-specific process execution issues on NonStop systems. Randall Becker follows up on Jeff King's debugging suggestions, narrowing down the problem in the `git notes show` execution path.

The key finding is that when `git notes show HEAD` converts to a `git show` invocation of a specific hash, the `execvp` call fails immediately with a NonStop-specific error code -12, rather than properly propagating the "no note found" error (exit code 1) that occurs when running the equivalent command directly. The investigation reveals the notes subsystem is passing an invalid hash (1aa950...) that doesn't match the actual HEAD (3fc1917...), suggesting the notes-to-show command translation is broken on this platform.

This appears to be a NonStop-specific interaction between Git's process execution machinery and the notes subsystem, where error handling differs between direct command execution and the wrapped `git notes` path. The debugging shows the issue occurs at the system call level during process execution, not in the notes functionality itself. The findings point to either a hash translation bug in the notes wrapper or platform-specific quirks in how NonStop handles process execution and error codes in this scenario.
