This is a v2 patch series introducing cbindgen support to Git's Rust infrastructure, building on previous discussions about Rust-C interoperability. The series has expanded from 3 to 5 patches, with new CI-related changes and refinements to the cbindgen implementation.

The core goal remains generating C headers from Rust's `extern "C"` blocks, currently used to verify varint implementation consistency between Rust and C. The series now includes preparatory CI changes (switching 32-bit builds to Debian, adding missing GitLab CI jobs) alongside the core cbindgen integration.

Key improvements in v2 address feedback from the previous round:
- Adopted some cbindgen.toml configuration suggestions (8-space indentation, autogen warnings)
- Fixed AlmaLinux 8 compatibility by handling its lack of cbindgen package
- Added back missing GitLab CI jobs to match GitHub's coverage
- Kept the generated headers in the root directory (as Junio approved) rather than moving them

The implementation looks solid, with careful attention to cross-platform compatibility and build system integration. The varint verification serves as a practical first use case while establishing the cbindgen infrastructure for future Rust-C interoperability needs. The series appears ready for merging pending final CI verification, representing an important step in Git's Rust integration.
