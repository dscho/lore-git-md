This is part 9 of Patrick Steinhardt's ongoing refactoring series to improve Git's loose object handling as part of the object database (ODB) abstraction effort. The patch focuses on shifting responsibility for reading loose objects from repository-level functions to the ODB source interface.

The key change moves the logic for reading loose object information and mapping loose objects from `loose_object_info()` and `map_loose_object()` (which operated on the repository level) to new functions `odb_loose_source_read_object_info()` and `odb_loose_source_map_object()` that work with individual ODB sources. This better aligns with the series' goal of having backends manage their own sources rather than the repository coordinating across all sources.

The patch touches core object-file handling code across object-file.c/h, odb.c, and streaming.c, with mostly mechanical changes to call the new interface. While the behavior remains the same, this is an important step in the architectural shift toward pluggable backends. The changes appear carefully done with thorough updates to all callers, though the commit notes that `open_istream_loose()` still needs future cleanup.

This continues the series' pattern of methodical, behavior-preserving refactoring to modernize Git's ODB infrastructure. The changes are focused and well-contained, building on previous patches that established the `odb_loose_source` structure.
