This is the final patch in a series introducing a new "geometric" maintenance strategy for Git repositories. The patch adds a hybrid repacking approach that combines the benefits of geometric repacking (better performance for large repos) with the full cleanup capabilities of traditional garbage collection.

The geometric strategy performs all the usual maintenance tasks like reflog expiration and worktree pruning, but uses geometric repacking instead of full repacks by default. It only falls back to a full repack (with cruft pack generation) when the geometric repack would merge all packs anyway. This provides a middle ground between the existing "gc" and "incremental" strategies.

The implementation includes documentation updates explaining the new strategy, configuration support in `builtin/gc.c`, and test coverage verifying the behavior. The strategy is designed to be a full replacement for "gc" while being more suitable for large repositories, though it does retain unreachable objects longer than traditional GC.

This patch completes the series which has already received thorough review and sign-off from both Taylor Blau and Junio C Hamano. The geometric strategy represents a significant technical improvement to Git's maintenance capabilities, particularly for large repositories where traditional GC can be too expensive.
