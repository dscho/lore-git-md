This is a follow-up discussion about the default behavior for signature handling in `git fast-import` and `git fast-export`. Elijah Newren raises a concern about the current default (`verbatim`) for the new `--signed-tags` option in Christian Couder's completed series that unified signature processing across these commands.

The key issue is forward compatibility - Newren suggests changing the default from `verbatim` to `abort` before the 2.52 release. This would allow for future improvements in signature validation without being locked into the current behavior. The concern applies to both the new `--signed-tags` option and the recently merged `--signed-commits` option (eaaddf579124).

The technical implementation itself is sound, having undergone extensive review from multiple contributors (Patrick Steinhardt, Collin Funk, Todd Zullinger, Junio Hamano) with robust test coverage in t9306 and t9350. The series successfully refactored signature parsing using `parse_signed_buffer()` and added consistent handling of PGP/X.509/SSH formats.

This represents the final decision point before merge, with all other technical and documentation feedback already addressed in v3. The discussion focuses purely on the default behavior choice rather than implementation correctness, as the shared infrastructure for signature handling is production-ready. The resolution of this default behavior question will complete the series' path to inclusion.
