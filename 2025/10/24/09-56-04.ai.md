This patch introduces a new `struct odb_loose_source` as part of the ongoing ODB abstraction effort. It's the first patch in the second phase of the series that moves loose object handling into a dedicated structure.

The patch creates a new `struct odb_loose_source` to hold loose object state that was previously stored directly in `struct odb_source`. The structure currently just wraps the parent `odb_source` pointer but is designed to eventually become the backend for loose object access. Key changes include:
- New `odb_loose_source_new()` and `odb_loose_source_free()` functions
- Addition of a `loose` field to `struct odb_source`
- Automatic creation/destruction of the loose source when managing ODB sources

The changes span object-file.c/h and odb.c/h, maintaining existing behavior while preparing for pluggable backends. This is a mechanical refactoring that follows the pattern of the series so far - moving state into better-organized structures without changing functionality. The commit message clearly states this is groundwork for future pluggable ODB backends.
