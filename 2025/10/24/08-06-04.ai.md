This is a documentation request and suggestion for improving the `git log` manpage. The email comes from David Moberg who is trying to understand and extend Git's pretty format capabilities, specifically:

1. They want to know the exact format string equivalent of the "oneline" format
2. They're looking for documentation about placeholders like "title-line" and "full-commit-message" which appear in the manpage descriptions but aren't directly usable in custom formats
3. They want to include notes (%N) in a compact, inline format

The key technical points are about the undocumented mapping between built-in formats (like "oneline") and their equivalent format strings, and the discoverability of format placeholders in the documentation. The email suggests two concrete improvements to the manpage: showing the equivalent format strings for built-in formats, and making descriptive terms like "title-line" searchable.

This appears to be a legitimate documentation gap - the current manpage describes the behavior of formats but doesn't expose their implementation details or make all terminology consistently searchable. The request focuses on practical usability for users trying to customize log output, particularly when incorporating notes. The suggestions seem reasonable and focused, though they might need refinement in terms of exactly how to present the format string equivalences in the documentation.
