This thread concerns a 4-patch series cleaning up diff dry-run behavior, building on Lidong's recent work. The core problem is simplifying how Git handles dry-run diffs by eliminating technical debt around output redirection and state management.

The first patch fixed a long-standing issue where external diff programs (via `GIT_EXTERNAL_DIFF`) ignored the `--output` file redirection, writing to stdout instead. The second patch (just received) removes unnecessary save/restore operations for the `color_moved` flag during dry-run diffs, demonstrating this flag couldn't affect dry-run output since move detection requires comparing multiple file pairs while dry-run examines individual pairs. The change removes three lines manipulating this flag in `diff.c` around `diff_flush()` while maintaining identical behavior.

The full series includes two additional forthcoming patches: one eliminating the dry_run flag entirely in favor of NULL file pointers (a more substantial behavioral shift), and another related refactor. These later changes represent a design shift by converting dry_run checks into potential NULL pointer dereferences. Technical changes are concentrated in diff.c and its header, with test coverage being added in `t/t4020-diff-external.sh`.

Open questions remain about whether the NULL pointer approach in upcoming patches is too risky compared to keeping explicit dry_run checks, and whether all edge cases have been considered in the behavioral change.
