Refactoring patch in Patrick Steinhardt's ODB abstraction series (6/13). This moves the loose object cache from `struct odb_source` to the newly introduced `struct odb_loose_source`, consolidating all loose object handling state. The cache stores object existence information for quick lookups, used in operations like `OBJECT_INFO_QUICK` and abbreviated hash resolution.

Key changes:
- Renames cache-related functions to use `odb_loose_source_` prefix
- Moves `subdir_seen` bitmap and `cache` pointer to `odb_loose_source`
- Updates all callers to use the new interface
- Maintains the same external behavior while improving internal organization

The patch continues the series' pattern of mechanical refactoring to prepare for pluggable ODB backends. It's a straightforward relocation of existing functionality with no behavior changes, following the groundwork laid in patch 5/13. The changes touch several object-handling files but are focused and well-contained.
