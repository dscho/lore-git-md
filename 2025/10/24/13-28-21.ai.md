Test improvement suggestions for atomic ref updates in `git replay`.

Phillip Wood provides specific recommendations to improve the test coverage for the `replay.refAction` config option in Siddharth Asthana's patch. The suggestions focus on test hygiene and better practices:

1. **Tag usage**: Recommends using existing tags from test setup rather than storing rev-parse output in variables, which would make the tests more maintainable and less fragile.

2. **Test utilities**: Suggests replacing manual config cleanup with `test_config` and using `test_cmp` instead of separate `test_line_count`/`grep` checks. This would make the tests more robust and consistent with Git's test suite conventions.

3. **Pattern consistency**: Notes these improvements should be applied throughout all the new tests in the file, not just the initial cases shown.

The feedback is narrowly focused on test implementation quality rather than the underlying functionality, which has already been approved. These are final polish items that align with Christian Couder's earlier suggestions about improving test coverage verification. The changes would not affect the behavior of the test assertions themselves, just make them more maintainable and consistent with Git's testing framework.
