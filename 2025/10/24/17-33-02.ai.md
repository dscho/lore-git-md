On NonStop platform, `execvp()` fails immediately with error -12 (a platform-specific "invalid object" code) when processing this converted command, while direct invocation with the same arguments properly reports "no note found" with exit code 1.

The critical discovery is that the notes subsystem appears to be passing an incorrect object hash to the underlying `git show` command during the conversion process. This explains why the direct invocation works (using the correct hash) while the wrapped path fails. The -12 error code appears to be a red herring caused by the platform's handling of failed exec calls when given invalid input, rather than being the root cause.
