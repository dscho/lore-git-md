This is a bug report about color formatting not working for error messages in Git for Windows. John Bevan reports that despite having `color.ui=always` and `color.error=red bold` set in his config, error messages like "pathspec did not match" appear in the terminal's default color rather than red.

The issue appears to stem from Git's `error()` function in usage.c not applying color formatting, even when color is explicitly enabled. The reporter has done thorough troubleshooting - they've verified ANSI color codes work in their PowerShell terminal, provided their complete Git and Windows configuration, and demonstrated the problem with a simple test case (`git checkout nonExistantBranch`).

This seems like a legitimate bug in Git's Windows color handling, though it's unclear whether the root cause is specific to Windows or affects other platforms too. The reporter originally filed this with Git for Windows but was redirected to the main Git list, suggesting it may be an upstream issue. The detailed system information and clear reproduction steps make this a well-documented bug report that should be straightforward to investigate.
