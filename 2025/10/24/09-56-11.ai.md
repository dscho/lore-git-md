This is patch 12/13 in Patrick Steinhardt's series refactoring Git's loose object handling as part of the object database (ODB) abstraction effort. The patch performs a straightforward rename of `write_object_file()` to `odb_loose_source_write_object()` to align with the new naming convention for ODB-related functions.

The change is purely mechanical, updating the function name in three locations: the implementation in object-file.c, its declaration in object-file.h, and its single caller in odb.c. The function's parameters and behavior remain unchanged. This continues the series' pattern of moving functionality under the ODB abstraction while maintaining existing behavior.

The rename makes it clear this is specifically a loose object backend operation, consistent with previous renames in the series (like `has_loose_object()` becoming `odb_loose_source_has_object()` in patch 10/13). The patch is small (11 lines changed) and focused, following the series' incremental approach to refactoring.

Key technical details:
- Function moved from generic object-file.h to ODB-specific naming scheme
- Still handles both primary and compat hash algorithms via repo->hash_algo
- Caller in odb.c updated to use new name
- No behavior changes - purely a naming update

This continues the mechanical groundwork for the ODB abstraction before later patches will modify behavior. The change is uncontroversial and aligns with the series' established direction.
