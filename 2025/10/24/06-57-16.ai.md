This is a feature patch introducing geometric repacking as a maintenance task, part of a larger series on geometric repacking strategies that has already received maintainer approval.

The patch adds a new "geometric-repack" maintenance task that uses Git's geometric repacking infrastructure. The key innovation is a hybrid approach: when packs would be merged via geometric repacking, it instead performs a full repack with cruft packs enabled. This addresses the limitation of geometric repacks which normally pack all loose objects (including unreachable ones) by allowing unreachable objects to be properly expired in subsequent repacks.

The implementation includes:
- New `maintenance.geometric-repack.auto` config (default 100 loose objects)
- Core logic in `maintenance_task_geometric_repack()` that decides between geometric and full repacks
- Auto-condition checking in `geometric_repack_auto_condition()`
- Comprehensive test coverage in t7900-maintenance.sh verifying:
  - Basic geometric repack behavior
  - Auto-condition triggering
  - Loose object handling
  - Cruft pack generation
  - Edge cases
  - Strategy verification

The patch builds on prior refactoring work in gc.c (eliminating global state) and integrates with the existing maintenance task framework. It follows the project's established patterns for maintenance tasks while introducing the new geometric-specific logic. The tests use `test_subcommand` verification and `git count-objects -v` checks to validate behavior.

This represents the final implementation of functionality that was discussed and refined across multiple rounds of review, with all technical feedback addressed. The hybrid strategy provides a balanced approach that maintains geometric repacking's performance benefits while properly handling object expiration.
