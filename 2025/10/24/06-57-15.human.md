This is a refactoring patch in the geometric repacking strategy series, which has already received maintainer approval. The patch simplifies the `too_many_loose_objects()` function in builtin/gc.c to take a direct integer parameter for the loose object threshold rather than requiring the full `gc_config` struct.

The change makes the function more flexible for future callers that may want to use different threshold values, while maintaining the same behavior for existing callers. The patch is part of a larger effort to implement configurable maintenance strategies, with this particular change preparing the codebase for subsequent patches that will introduce geometric repacking functionality.

The modification is straightforward - it simply replaces the struct parameter with an integer while keeping all the core logic intact. All existing call sites are updated to pass the threshold value from their config struct. This is a clean, focused change that follows the pattern of the overall series, which has been thoroughly reviewed and approved by both Taylor Blau and Junio C Hamano.
