This is a discussion about the default behavior for handling signed tags in `git fast-import` and `git fast-export`. 

Junio Hamano responds to Elijah Newren's concern that the default mode for `--signed-tags` should be `abort` rather than `verbatim`. Newren worries that keeping `verbatim` as the default will make it harder to change later when better signature verification is implemented. 

Hamano points out that the series is actually adding configurability where previously there was none - the tools have always treated signatures verbatim by default historically. Changing that default now would break existing users, so the series maintains backward compatibility while giving users new options. 

The exchange highlights a tension between forward-looking design (wanting to set good defaults for future verification features) and backward compatibility (not breaking existing workflows). Christian Couder's position in the thread context suggests this is likely to remain as `verbatim` by default unless Newren pushes harder for a change before the 2.52 release. The technical implementation itself is solid and already merged - this is purely a policy discussion about defaults.
