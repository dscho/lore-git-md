This is patch 6/13 in Patrick Steinhardt's series refactoring Git's loose object handling as part of the object database (ODB) abstraction effort. The patch moves the loose object cache from `struct odb_source` to the newly introduced `struct odb_loose_source`, consolidating all loose object state in one place.

Key technical changes:
- Moves `loose_objects_cache` and `loose_objects_subdir_seen` fields from `struct odb_source` to `struct odb_loose_source`
- Renames cache-related functions to use `odb_loose_source_` prefix (`odb_loose_cache()` -> `odb_loose_source_cache()`)
- Updates all callers to use the new names and locations
- Adds proper cleanup of the cache in `odb_loose_source_free()`
- Removes now-redundant cache clearing from `odb_source_free()`

The patch continues the series' pattern of mechanical refactoring to better organize the ODB code while maintaining existing behavior. The changes touch object-file.c/h, odb.c/h, loose.c, and object-name.c, with the bulk being straightforward field moves and function renames. The commit message explains the design choice to keep accepting `struct odb_source` parameters for future pluggable backend compatibility.

This is a clean, focused change that advances the series' goal of separating loose object handling from the core ODB infrastructure. The patch appears well-tested with no obvious issues, though reviewers may want to verify the cache clearing behavior in error paths.
