This is part 9/13 of Patrick Steinhardt's series refactoring Git's loose object handling as part of the object database (ODB) abstraction effort. The patch focuses on restructuring how loose objects are read, moving responsibility from repository-level functions to the ODB source interface.

The key change shifts loose object reading operations (`loose_object_info()` and `map_loose_object()`) from taking a `struct repository` parameter to working with a specific `struct odb_source`. This better aligns with the series' goal of having backends manage their own sources. The patch:
- Renames and relocates the core reading functions to `odb_loose_source_*` variants
- Updates callers in odb.c and streaming.c to use the new interface
- Maintains existing behavior while cleaning up the responsibility chain
- Leaves `open_istream_loose()` temporarily at the repository level (noted as future cleanup)

Technical details include:
- New functions `odb_loose_source_read_object_info()` and `odb_loose_source_map_object()`
- Modified helper functions (`stat_loose_object`, `open_loose_object`, `quick_has_loose`) to work with sources
- Updates to object-file.h interface declarations
- Careful handling of hash algorithm references through the ODB chain

The change continues the series' pattern of mechanical refactoring before behavioral changes, here better isolating loose object reading logic within the ODB abstraction. The patch appears well-contained and maintains existing functionality while progressing the architectural goal.
