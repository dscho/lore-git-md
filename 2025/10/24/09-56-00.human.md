This is the first patch in a 13-part series refactoring Git's loose object handling as part of the object database (ODB) abstraction effort. The patch fixes a subtle memory ownership issue in the alternate ODB checking logic.

Currently, `alt_odb_usable()` both checks if an alternate path is usable *and* stores the path in a map if it is. The path isn't copied, relying on later code to detach a strbuf and reuse the same memory. This implicit coupling is fragile and could break during refactoring.

The patch makes the relationship explicit by separating the checking and storing operations. Now `alt_odb_usable()` purely checks usability, and the path storage happens later when the alternate source is created. The changes are focused in odb.c and maintain the same functionality while being more robust.

As the first patch in a major refactoring series, this establishes cleaner foundations for the subsequent changes. The commit message clearly explains the subtlety being fixed and why the new approach is better. The change appears well-contained and low-risk, touching only the alternate ODB handling code.
