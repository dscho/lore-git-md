This is a follow-up bugfix patch to the dry-run refactoring series, submitted by Jeff King after the main 4-patch sequence was already sent. The patch simplifies the quiet-mode logic in `run_external_diff()` now that the dry-run behavior has been rearchitected to use NULL file pointers rather than explicit flags.

The key insight is that with the new architecture, there are only two paths into this function - either from `diff_flush_patch_quietly()` (always a dry-run) or from `diff_flush_patch_all_file_pairs()` (always has DIFF_FORMAT_PATCH set). This makes the previous dual-condition quiet check redundant - we can simply check for the NULL file pointer that now indicates dry-run mode. The change removes 3 lines of condition checking while making the logic more straightforward by handling all file pointer cases (NULL, stdout, other) in adjacent code.

This touches the same `diff.c` file modified in the series, specifically the external diff handling that was partially addressed in patch 1. The change is small but meaningful - it completes the simplification of dry-run logic by removing now-unnecessary conditionals that were made redundant by the NULL pointer approach. Given Jeff King's involvement in reviewing the original series and his demonstrated understanding of the dry-run architecture changes, this late addition appears to be a well-justified cleanup that fits naturally with the series' goals.
