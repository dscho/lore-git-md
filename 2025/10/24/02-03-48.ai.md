This is a review comment on the final patch in Christian Couder's series to unify signature handling between `git fast-import` and `git fast-export`. Elijah Newren raises a concern about the default behavior (`verbatim`) for the new `--signed-tags` option, suggesting it should be changed to `abort` before the 2.52 release to allow for future improvements in signature validation.

The review focuses on the default value choice rather than the implementation itself, which appears sound. Newren notes that while the current modes (verbatim, warn-verbatim, warn-strip, strip, abort) are well-implemented, making `verbatim` the default now could lock the project into maintaining that behavior indefinitely. He suggests using `abort` as a temporary default until more sophisticated signature validation can be implemented.

The technical implementation mirrors the earlier `--signed-commits` work, reusing the `parse_sign_mode()` function and adding comprehensive tests for PGP, X.509, and SSH signature handling. The test coverage in t9306-fast-import-signed-tags.sh verifies all modes across different signature types, including verification of warning messages and signature stripping behavior.

This feedback comes late in the review cycle (after v3) and represents one of the final outstanding issues before the series can be merged. The concern is primarily about future flexibility rather than any flaw in the current code.
