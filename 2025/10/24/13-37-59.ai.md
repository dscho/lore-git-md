This is a bug report about color output behavior in Git for Windows. The reporter, John Bevan, notes that error messages are not being colored red as expected when `color.ui=always` is set, despite the terminal supporting ANSI color codes. The issue appears specific to Windows and has been redirected from the Git-for-Windows issue tracker.

The problem stems from `usage.c`'s error reporting function not applying color formatting, even when color is globally enabled. The reporter provides thorough system details including Git version (2.51.1.windows.1), Windows 11 environment, and complete configuration. They demonstrate the issue occurs with commands like `git checkout` when given invalid branch names, where the error message appears in default terminal color rather than the configured red.

This appears to be a legitimate color handling bug in the Windows port, with clear reproduction steps and environment details. The reporter has done due diligence to verify terminal color support and configuration, though notes they couldn't access the recommended bug-reporting guide due to corporate HTTPS restrictions. The issue seems isolated to error message coloring rather than a broader color system failure.
