This is the first patch in a 13-part series refactoring Git's loose object handling as part of the object database (ODB) abstraction effort. The patch focuses on fixing subtle memory management logic in alternate ODB path checking.

The change modifies `alt_odb_usable()` to no longer store paths in the object source map during its usability check, separating the validation and storage steps. Previously, the function would both check path usability and store the path in a map, relying on implicit memory ownership where the path pointer would later be transferred to the ODB source. The new version makes this ownership explicit by first validating the path, then creating the source, and finally storing the source's path in the map.

Key technical changes include:
- Removing the `pos` parameter from `alt_odb_usable()`
- Moving the path map insertion to after source creation
- Adding a BUG() check if the path already exists in the map
- Simplifying the path comparison logic

This appears to be a well-motivated cleanup that makes the code's memory ownership model more explicit and less error-prone for future modifications. The change touches core ODB path handling code in odb.c but doesn't affect external behavior. As the first patch in a larger series, it sets up cleaner foundations for the subsequent refactoring work.
