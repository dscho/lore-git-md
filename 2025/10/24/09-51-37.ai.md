This is the final patch in a 5-part series introducing cbindgen support to Git's Rust infrastructure, focusing on automated C header generation from Rust code. The patch implements the core functionality: generating C bindings for Rust's `extern "C"` functions using cbindgen, specifically targeting the varint encoding implementation as an initial use case. It sets up build system integration (Makefile and meson) to generate `c-bindings.h` from Rust sources, then includes this header in `varint.c` to verify function signature consistency between Rust and C implementations. A mismatch now triggers a compiler error rather than silently allowing divergence.

Key technical details include:
- New `cbindgen.toml` configuration with Git-specific formatting (8-space indents, no standard includes)
- Makefile rules for generating and cleaning `c-bindings.h`
- Meson build system integration mirroring Makefile functionality
- CI updates to install cbindgen across platforms (with special handling for AlmaLinux 8)
- Header inclusion strategy that avoids unnecessary recompilation (directly in `varint.c` rather than `varint.h`)

The patch demonstrates the verification mechanism by intentionally breaking the varint signatures - the compiler catches the mismatch between `uint32_t` (Rust binding) and `uint64_t` (original C declaration). This completes the series' goal of enabling Rust-C interoperability while preventing interface mismatches, with the varint implementation serving as both proof-of-concept and first consumer.
