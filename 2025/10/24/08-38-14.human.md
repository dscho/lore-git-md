This is a bugfix for the debug ref backend. The patch adds a missing `remove_on_disk` implementation to the debug ref backend (`refs_be_debug`), which was causing a segmentation fault when running Git commands with ref tracing enabled during ref migration to the reftable format.

The issue manifests specifically when using `GIT_TRACE_REFS=1` with `git refs migrate --ref-format=reftable`. Without this function pointer, the debug backend would crash when trying to handle ref removal operations during migration. The fix follows the same pattern as other debug backend functions - it wraps the underlying backend's operation while adding trace output.

The patch is straightforward, adding just the missing function implementation and its pointer in the backend structure. It appears to be a clear case of an omitted but necessary piece of the debug backend's functionality. The change is well-contained and has a clear motivation explained in the commit message.
