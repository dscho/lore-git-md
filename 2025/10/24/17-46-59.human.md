This is a technical discussion about a platform-specific bug in Git's notes subsystem on NonStop systems. Jeff King (peff) is responding to Randall Becker's investigation into why `git notes show HEAD` fails with an unusual exit code (-12) on NonStop.

The key revelation is that the notes subsystem appears to be converting `git notes show HEAD` into a malformed `git show` command with an incorrect hash (1aa950256...) that doesn't match the actual HEAD commit (3fc1917e0...). On NonStop, this causes execvp() to fail immediately with a platform-specific error code (-12 for "invalid object"), while direct invocation with correct arguments properly reports "no note found" (exit code 1).

Jeff seeks clarification on two points: whether the "invalid object" refers to the Git binary itself (rather than a Git object), and whether Randall might be confusing `git show` with `git notes show` in his testing. The discussion is narrowing in on the notes subsystem's hash handling during command conversion as the likely source of the problem.
