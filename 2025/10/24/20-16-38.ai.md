Bug investigation in the Git notes subsystem on NonStop platforms.

Jeff King responds to Randall Becker's debugger output showing the exact command being passed to execvp() when `git notes show HEAD` fails on NonStop systems. The debug output confirms the notes subsystem is constructing a malformed command that passes a notes blob hash (1aa950256...) to `git show` instead of the expected commit hash (3fc1917e0...). 

Key technical details from this exchange:
- Randall demonstrates via gdb that the argv array passed to execvp() contains ["git", "show", "1aa950256...", NULL]
- When manually running this exact command in bash, Randall gets "no note found" output, which Jeff finds puzzling since `git show` shouldn't produce notes-related errors
- Jeff suspects Randall may have accidentally run `git notes show` instead of `git show` when testing manually
- The core issue remains that the notes subsystem is incorrectly converting the command, using the notes blob hash rather than the commit hash

This email narrows the focus to understanding why manual execution of the malformed command produces different behavior than the automatic path, with Jeff questioning whether the test methodology might explain the discrepancy. The debugger evidence solidifies that the notes command construction is broken, but the exact nature of the failure mode when executed manually remains unclear.
