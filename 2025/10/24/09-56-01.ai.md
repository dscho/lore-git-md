This is the second patch in Patrick Steinhardt's 13-part series refactoring Git's loose object handling infrastructure as part of the object database (ODB) abstraction effort. The patch introduces a new `odb_source_new()` helper function to consolidate duplicate logic for creating new ODB sources that was previously spread across three different locations.

The new function handles the common initialization pattern for `struct odb_source` objects which represent storage backends in Git's object database. It takes parameters for the parent ODB, path, and a `local` flag, then allocates and initializes the structure. The patch updates three call sites to use this new function: `link_alt_odb_entry()` (for alternate object directories), `odb_set_temporary_primary_source()` (for temporary object storage), and repository initialization code in `repository.c`.

Key technical details include:
- The function is declared in odb.h for use across the codebase
- It uses `CALLOC_ARRAY` for allocation and `xstrdup` for path copying
- The repository initialization code now handles path expansion before calling the helper
- Memory management remains equivalent to the original code, just more centralized

This is a straightforward refactoring that improves code organization without changing behavior. It's part of the larger effort to abstract loose object handling into a dedicated `struct odb_loose_source` interface. The change touches core ODB infrastructure in odb.c and repository setup code, but maintains all existing functionality while making the code more maintainable.
