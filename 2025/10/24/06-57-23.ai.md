Feature: This final patch in the series introduces the new "geometric" maintenance strategy, completing the geometric repacking infrastructure for Git repositories. The geometric strategy combines the full cleanup capabilities of the traditional `gc` strategy with the more efficient packfile management of geometric repacking. It performs all standard maintenance tasks (reflog expiration, worktree pruning, etc.) while using `git repack --geometric=2` for packfile consolidation, only falling back to a full repack when the geometric strategy would merge all packs anyway (which then creates a cruft pack for unreachable objects).

Key technical details include:
- New `geometric_strategy` struct in builtin/gc.c defining the task schedule
- Strategy runs daily geometric repacks with weekly auxiliary tasks (reflog, worktree, etc.)
- Documentation updates explaining the strategy's behavior and recommending it for large repos
- Test cases verifying both manual and scheduled execution paths
- Integration with the existing strategy parsing infrastructure
- Default geometric split factor of 2 matching `git repack` behavior

The strategy addresses the limitations of both the traditional `gc` (inflexible, always full repacks) and `incremental` (no pruning) approaches. While it retains unreachable objects longer than `gc`, the design assumes this tradeoff is acceptable for large repositories where reachable objects dominate. The implementation includes a clear path for future enhancements like time-based repack triggers if needed.

This patch represents the culmination of the series, having received thorough review from Taylor Blau and final sign-off from Junio C Hamano. It provides a complete solution for configurable maintenance strategies with geometric repacking at its core.
