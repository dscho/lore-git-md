This is a patch completing the maintenance strategy configuration series by making the "gc" strategy explicitly configurable. It's part of the ongoing work to unify and improve Git's repository maintenance capabilities.

The patch addresses two limitations in the current implementation: first, users couldn't explicitly select the "gc" strategy when a different global strategy was set, and second, the "gc" task wasn't available for scheduled maintenance runs. The changes make the "gc" strategy configurable and enable it for both manual and scheduled maintenance contexts.

Key changes include updating the documentation to list "gc" as a valid strategy, modifying the strategy initialization code to handle the "gc" case, and adding test coverage to verify the new behavior. The implementation maintains backward compatibility while expanding functionality, with the "gc" strategy remaining the default for manual maintenance.

The patch appears well-integrated with the rest of the series, which has already received thorough review and sign-off from both Taylor Blau and Junio C Hamano. It completes the strategy unification work by ensuring all maintenance strategies can be explicitly configured and applied consistently across both manual and scheduled contexts.
