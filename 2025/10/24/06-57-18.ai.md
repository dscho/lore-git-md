This is a bugfix and refactoring patch in the geometric repacking strategy series, addressing error handling for invalid maintenance strategies.

The patch fixes a silent failure case where Git would ignore unknown maintenance strategy values in the config, instead making it fail explicitly with an error message. This improves user experience by making configuration issues immediately visible rather than silently falling back to a no-op strategy. The change extracts the strategy parsing logic into a new `parse_maintenance_strategy()` function for reuse, which currently only recognizes the "incremental" strategy but will be extended in future commits.

Key technical changes include:
- New `parse_maintenance_strategy()` function that validates input and dies on unknown strategies
- Updated `initialize_task_config()` to use this function when reading `maintenance.strategy`
- Added test case verifying the error message when an invalid strategy is configured
- Maintains the existing fallback to `none_strategy` when no strategy is configured

The patch follows the series' pattern of improving error handling and configuration robustness while preparing for future geometric strategy implementation. It's a focused change that addresses a specific gap in the current implementation while keeping the door open for additional strategy types. The test addition follows the established pattern in t7900-maintenance.sh and uses `test_grep` for output verification.
