Refactoring patch in the geometric repacking strategy series. This is the first patch in v3 of the series, which removes the global `repack` variable in `builtin/gc.c` in favor of stack-allocated strvecs passed between functions. The change makes the code more maintainable by eliminating global state and better supporting reuse of the repacking logic in subsequent patches.

The patch modifies several key areas:
- Replaces the global `static struct strvec repack` with local variables
- Updates `keep_one_pack()`, `add_repack_all_option()`, and `add_repack_incremental_option()` to take a strvec pointer parameter
- Adapts `need_to_gc()` to work with temporary strvecs, including a new `gc_condition()` wrapper for maintenance tasks
- Maintains all existing functionality while cleaning up the control flow

The changes are straightforward mechanical conversions, with special attention paid to the maintenance auto-condition case where temporary arguments can be discarded since `git gc` will recompute them. This prepares for later patches in the series that will build on these refactored functions to implement geometric repacking strategies.

The patch has already been reviewed and approved by Taylor Blau and Junio C Hamano as part of the complete series. It demonstrates good attention to detail in handling edge cases while keeping the diff focused and minimal. The changes align with the series' goal of improving repacking infrastructure for both manual and scheduled maintenance operations.
