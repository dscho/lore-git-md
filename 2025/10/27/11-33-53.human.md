Feature implementation in the `git-history` series, adding the "reword" subcommand. This is patch 5/11 in Patrick Steinhardt's v6 series introducing a new `git-history` command for non-destructive history editing.

The patch implements `git history reword <commit>`, which functions similarly to an interactive rebase's "reword" action but operates in a single step. It preserves all commit metadata (author, date, tree) while allowing the message to be edited. The implementation handles the core workflow: spawning an editor with the existing message, validating the new message isn't empty, and reconstructing the commit chain while maintaining the original tree content.

Key technical aspects include integration with Git's existing sequencer infrastructure, reuse of the commit message editor workflow, and careful handling of commit parent relationships. The patch includes extensive tests covering edge cases like merge commits, empty messages, and worktree state preservation. Notably, it currently doesn't execute commit hooks during the rewrite operation.

This appears to be a well-constructed implementation with thorough test coverage (237 lines of tests). It builds on the foundational infrastructure from earlier patches in the series and follows Git's established patterns for history rewriting operations. The patch maintains the experimental nature of the overall `git-history` command while delivering a focused, single-feature implementation.
