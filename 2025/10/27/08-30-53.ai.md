This is a feature patch introducing geometric repacking as a maintenance task, part of the v4 series that has already received maintainer approval. The patch adds a new `geometric-repack` task that uses Git's existing geometric repack infrastructure with a hybrid strategy to handle unreachable objects more effectively.

The key technical elements include:
- New `maintenance.geometric-repack.auto` config to control automatic execution
- Implementation in `maintenance_task_geometric_repack()` that switches between geometric and full repacks based on pack geometry
- Auto-condition logic in `geometric_repack_auto_condition()` that considers both pack merging needs and loose object counts
- Comprehensive test coverage in t7900-maintenance.sh verifying:
  - Basic geometric repack behavior
  - Auto-repack triggering conditions
  - Cruft pack handling for unreachable objects
  - Edge cases around empty repos and config values

The patch addresses a known limitation of geometric repacking (its inability to expire objects) by falling back to full repacks with cruft packs when packs would be fully consolidated. This maintains the performance benefits of geometric repacking while allowing eventual object expiration. The implementation builds on prior refactoring work in the series, using stack-allocated structs and avoiding global state.

Test coverage is thorough, including verification of the repack strategy selection and auto-condition behavior. The tests use trace2 to verify the exact repack commands executed under different scenarios. This patch appears production-ready as part of the approved series, with all substantive feedback from prior iterations addressed.
