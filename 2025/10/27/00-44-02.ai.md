This is a feature patch introducing a new binary loose object map format for Git, part of a larger series (12/14) focused on improving object storage efficiency and compatibility mapping. The patch comes from brian m. carlson, a known contributor to Git's hash algorithm transition work.

The new format addresses two key problems with the current loose object handling: inefficient lookup (since object IDs aren't sorted) and the need to store special-case mappings (like shallow entries and submodules) that don't fit neatly into either loose or packed object storage. The design closely resembles Git's pack index v3 format for familiarity and efficiency.

Key technical components include:
- A binary format with sorted object ID tables for fast lookup
- Support for multiple hash algorithms (SHA-1 and SHA-256)
- Metadata to track object types (loose, shallow, submodule)
- In-memory mapping structures (LooseObjectMemoryMap) with batch writing capability
- Memory-mapped reader implementation (MmapedLooseObjectMap)
- Comprehensive test coverage including round-trip verification

The implementation is in Rust (src/loose.rs) with corresponding documentation in Documentation/gitformat-loose.adoc. The patch carefully handles alignment requirements and includes padding where needed. The format supports both a legacy text-based mapping and the new binary format, with the latter being the preferred going forward.

Notable design choices:
- The format maintains bidirectional mapping between hash algorithms
- Special handling for reserved objects (empty tree, empty blob, null OID)
- Batched writing capability for efficient bulk operations
- Checksum verification via trailing hash

The patch appears well-constructed with thorough documentation and clear motivation. It's part of Git's ongoing work to support multiple hash algorithms while maintaining performance. The Rust implementation suggests this is building toward future Rust integration in Git's core.
