This thread documents a straightforward but important cleanup of Git's whitespace handling code. Junio Hamano sent a patch series (now at v2) that corrects documentation inaccuracies and improves code clarity around bit assignments in the diff machinery's whitespace rules. The changes span diff.c, diff.h, and ws.h, fixing an off-by-one error in documented bit positions (0-11 instead of 0-10) and properly documenting the color-moved bits (17-19).

Patrick Steinhardt reviewed both versions, and v2 incorporates all his feedback: using consistent bit-shift notation (1<<N) instead of octal constants, better code organization, and explicit documentation of the WS_TAB_WIDTH_MASK limitation. The only remaining minor point is that WS_DEFAULT_RULE still uses a literal "8" for tab width, which could be cleaned up later but isn't blocking this change.

Both maintainers agree the patch is technically sound and ready for merging. Junio has now acknowledged Patrick's approval, confirming this documentation improvement to the stable diff machinery is complete. While Junio had mused about possibly expanding whitespace rule bits in the future, that remains speculative and doesn't affect these immediate corrections. The changes make the codebase more maintainable by preventing potential bit-counting errors in future modifications.
