This is a feature patch introducing a new binary format for mapping loose objects, part of a larger series (12/14) from brian m. carlson. The patch addresses inefficiencies in Git's current loose object handling and adds support for storing special objects like shallow entries and submodules that don't fit neatly into the packed/loose dichotomy.

The new format resembles pack index v3 and includes both an in-memory representation and batched writing capability. It provides efficient lookup across hash algorithms (important for SHA-1/SHA-256 interoperability) and tracks object types to enable proper pruning. The implementation is in Rust, with future C bindings planned (but not included here).

The patch is thorough, with extensive documentation of the file format, comprehensive Rust implementation (~900 lines), and robust test coverage. The commit message clearly explains the motivation and design tradeoffs, though it notes some functionality will be completed in later C-side integration. This appears to be a well-considered addition to Git's object storage infrastructure.
