This is the final patch in Patrick Steinhardt's v6 series introducing the `git history` command, specifically implementing the `split` subcommand. The patch adds functionality to interactively split a commit into two commits by selecting which hunks should be moved to a new commit that becomes the parent of the original.

The implementation builds on the infrastructure from previous patches in the series, particularly the in-memory index patching capability and tree-to-tree diff support. The `split` subcommand:
- Takes a commit to split and optional pathspec to limit changes
- Uses the interactive patch interface (from `add-patch`) to let users select hunks
- Creates a new commits: one with selected changes (with new message) and one with remaining changes (keeping original message)
- Validates that neither resulting commit would be empty
- Preserves authorship and handles worktree/index state
- Includes extensive tests covering various scenarios (root commits, tip commits, path limiting, etc.)

Key technical details:
- New `split_commit()` function handles core logic in `builtin/history.c`
- Uses `run_add_p_index()` for hunk selection
- Creates temporary index files for in-memory operations
- Validates tree OIDs to prevent empty commits
- Preserves original author information
- 432 lines of new tests in `t/t3452-history-split.sh`
- Documentation updates with examples and usage

The patch completes the initial implementation of `git history` after the series' extensive refactoring work. It demonstrates careful handling of edge cases while providing a much simpler UX than the manual rebase flow it replaces. The implementation appears thorough and well-tested, with clear documentation matching Git's style.
