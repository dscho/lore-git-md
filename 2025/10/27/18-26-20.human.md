Feature: Worktree support for ref storage migration.

This patch removes the previous limitation that prevented `git refs migrate` from working with repositories containing worktrees. The implementation uses a multi-phase approach to safely migrate each worktree's ref storage separately while maintaining atomicity - creating temporary staging areas, backing up existing storage, and moving new storage into place only after all worktrees are prepared. The migration must be run from the main worktree.

Key technical details include:
- Special handling for per-worktree refs (bisect, rewritten, worktree-specific)
- Proper commondir file creation for linked worktrees
- Backup/restore mechanisms for rollback safety
- Maintaining worktree isolation by keeping per-worktree refs as loose files
- Comprehensive test coverage for various worktree scenarios

The patch appears well-considered with thorough testing (446 lines of test cases) covering:
- Basic worktree migration in both directions (files ↔ reftable)
- Multiple worktrees
- Dry-run mode
- Physical separation of per-worktree refs
- Bare repositories with worktrees
- Edge cases like read-only directories and uncommitted changes

The author notes this was developed with AI assistance but has been reviewed and iterated on for quality. The implementation looks solid and addresses a real limitation in the migration tool.
