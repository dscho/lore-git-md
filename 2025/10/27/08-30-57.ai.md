This is a refactoring patch in the geometric repacking maintenance series, introducing type-based control for maintenance task execution. The patch distinguishes between manual maintenance (run directly or with `--auto`) and scheduled maintenance (run with `--schedule`), replacing the simple boolean `enabled` flag with a bitmask in the `maintenance_strategy` struct.

Key technical changes:
- New `enum maintenance_type` with `MAINTENANCE_TYPE_SCHEDULED` and `MAINTENANCE_TYPE_MANUAL` bits
- Conversion of `strategy.tasks[].enabled` to `type` field using the new enum
- Updated strategy definitions to specify which type(s) should run each task
- Modified `initialize_task_config()` to check type compatibility before running tasks
- Preserved existing behavior where default strategy runs only manual tasks and incremental strategy runs only scheduled tasks

The change enables future patches to make maintenance strategies apply consistently across all invocation types while maintaining backward compatibility. The patch maintains the current behavior where config overrides (`maintenance.<task>.enabled`) still work but now respect the type constraints. This is a mechanical refactoring with no intended behavior change, preparing for subsequent patches that will expand strategy support.
