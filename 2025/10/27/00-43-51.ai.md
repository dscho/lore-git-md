This is a feature patch that makes Rust a hard requirement for Git's interoperability code (specifically the loose object map functionality). It's part of a larger series (1/14) transitioning parts of Git's object handling to Rust.

The key changes are:
1. Modifies `repository.c` to error out if Rust support is missing when trying to set a compat hash algorithm
2. Adds a new `RUST` test prerequisite and updates multiple test scripts to skip interoperability tests when Rust is unavailable
3. Splits test setup into parts that don't require Rust and parts that do

The patch acknowledges this is technically a regression in functionality but argues it's acceptable because:
- The interoperability code is already marked experimental
- The current implementation is "mostly quite broken"
- The Rust-based implementation is coming soon

The changes affect several test files (`t1006-cat-file.sh`, `t1016-compatObjectFormat.sh`, etc.) by conditionally running tests based on Rust availability. The patch introduces a new `RUST` prerequisite in `t/test-lib.sh` to check for Rust support.

This appears to be a well-considered transitional step in the Rust migration effort, with careful attention to test coverage and backward compatibility concerns. The commit message provides clear rationale for the change and its impact.
