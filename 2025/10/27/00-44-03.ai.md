This is part 13 of a 14-part series introducing Rust infrastructure for Git's binary loose object map. The patch adds a Rust wrapper around Git's hashfile functionality to enable writing the loose object map data to actual files while maintaining the flexibility to use in-memory buffers for testing.

The new `src/csum_file.rs` implements a `HashFile` struct that wraps Git's C hashfile API, exposing it through Rust's `Write` trait. This allows the same interface to be used for both file output (via `hashfd`) and in-memory testing (via `Cursor<Vec<u8>>`). The implementation handles chunked writes (splitting large writes into `u32::MAX` sized chunks) and provides a `finalize` method that returns the computed hash of the written data.

Key components include:
- FFI bindings to Git's `hashfd`, `hashwrite`, `hashflush`, and `finalize_hashfile` functions
- Integration with Git's hash algorithm infrastructure through `HashAlgorithm`
- Proper handling of the maximum raw hash size (`GIT_MAX_RAWSZ`)
- Build system integration (Makefile and meson)

This appears to be a well-structured piece of infrastructure that cleanly bridges Git's existing C code with the new Rust components while maintaining testability. The implementation follows Rust idioms while properly handling the FFI boundary, and the commit message clearly explains the motivation for the wrapper.
