Refactoring patch in the `git-history` series that decouples add-patch from add-interactive. This is part of Patrick Steinhardt's ongoing effort to build history editing capabilities (currently `reword` and upcoming `split` subcommands) by refactoring Git's interactive patch selection infrastructure.

The patch removes the last direct dependency between `add-patch.c` and the `add-interactive` subsystem by moving interactive configuration handling into `add-patch.c`'s own state structure. Instead of initializing via `init_add_i_state()`, it now uses the new `interactive_config_init()` function introduced in the previous patch. This completes the separation of concerns between the two subsystems while maintaining all existing functionality.

The changes are mechanical but important for the series' goal of building standalone history editing operations. All color handling, diff configuration, and repository state management now lives within `add-patch.c`, making the code more self-contained. The patch follows Junio Hamano's earlier approval of similar refactoring in this series and appears ready for integration.
