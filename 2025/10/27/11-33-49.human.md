This is a refactoring patch that adds infrastructure for the upcoming `git-history` command series. It introduces a new function `wt_status_collect_changes_trees()` that compares two arbitrary trees and formats the diff output using the working tree status machinery. While this stretches the "working tree" status concept slightly, it avoids duplicating diff formatting logic that will be needed for the history editing operations.

The patch is cleanly implemented with proper documentation and follows Git's existing patterns for diff handling. It's the first of eleven patches in v6 of the series, setting up core functionality that will be used by subsequent commits to implement the `reword` and `split` subcommands. The change is well-contained and doesn't yet affect any user-facing behavior - it lays groundwork for the more visible features to come.
