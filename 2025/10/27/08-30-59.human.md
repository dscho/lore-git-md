This is a patch in the geometric repacking maintenance series that makes the "gc" strategy explicitly configurable. It addresses two limitations: allowing repositories to override a global strategy setting with the default "gc" strategy, and enabling git-gc to run during scheduled maintenance (previously it was limited to manual runs).

The patch modifies the strategy definitions so the "gc" task runs for both manual and scheduled maintenance (daily by default), updates the documentation to list "gc" as a valid strategy, and adds test coverage verifying the strategy works in both contexts. The changes are straightforward - mostly adjusting flags and adding test cases - and fit cleanly into the series' goal of making maintenance strategies more flexible and consistent across different invocation types.

This appears to be a well-justified refinement to the strategy system, with clear motivation and thorough test coverage. As the 9th patch in an approved series that has already addressed all substantive feedback, it seems ready for inclusion. The only notable change is that "gc" will now run during scheduled maintenance where it previously didn't, but since this matches the documented behavior and existing manual maintenance behavior, it shouldn't cause surprises.
