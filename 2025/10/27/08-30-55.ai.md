This is a bugfix patch in the geometric repacking maintenance series, addressing silent failure handling for invalid maintenance strategies.

The patch modifies the strategy parsing logic in `builtin/gc.c` to fail explicitly when encountering an unknown maintenance strategy, rather than silently falling back to a no-op behavior. A new `parse_maintenance_strategy()` helper function is introduced to centralize this validation, which will be reused in subsequent changes. The change ensures users are immediately aware of configuration errors rather than having maintenance tasks silently do nothing.

Key technical changes include:
- New `parse_maintenance_strategy()` function that validates strategy names
- Replacement of silent fallback with explicit error via `die()`
- Added test case in t7900-maintenance.sh verifying error behavior for invalid strategies
- Maintains existing behavior for valid strategies ("incremental") and unconfigured cases
- Part of broader strategy configuration work in the geometric repacking series
- Follows the series' pattern of making maintenance behavior more explicit and debuggable

The change is straightforward and well-tested, with no apparent controversy given it's part of an already-approved series. It addresses a real usability issue where invalid configurations could go unnoticed. The patch maintains consistency with the series' ongoing refactoring by extracting logic into reusable functions.
