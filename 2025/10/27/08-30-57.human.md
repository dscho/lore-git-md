This is a refactoring patch in the geometric repacking maintenance series, introducing type-based control for maintenance tasks. It's part of a v4 series that has maintainer approval and is nearing completion.

The patch distinguishes between three ways to run maintenance (manual, auto, and scheduled) and introduces a bitmask to control which tasks run in each context. The key change replaces a simple `enabled` boolean with a `type` field that can specify multiple execution contexts. This prepares for future changes where tasks may need to behave differently based on how they're invoked.

The patch maintains existing behavior by mapping the old `enabled` values to appropriate types: default strategy remains manual-only, while incremental strategy stays scheduled-only. The changes are mechanical but important groundwork - they don't yet change functionality but enable more flexible task control in later patches.

The implementation looks clean, with clear enum definitions and straightforward conversions of the strategy definitions. It fits well with the series' goal of making maintenance behavior more configurable while keeping the changes incremental and well-tested.
