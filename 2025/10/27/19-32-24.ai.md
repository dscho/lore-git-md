This is a follow-up in the ongoing investigation of GPG signature stability in the t1016-compatObjectFormat.sh test. Eric W. Biederman reports being able to reproduce the flakiness locally using `--stress` testing, confirming it's not just a CI environment issue. The key finding is that while SHA-256 repository signatures remain consistent, SHA-1 signatures vary between runs despite identical inputs and the timestamp-fixing wrapper.

Biederman provides concrete evidence showing different PGP signatures being generated for the same tag (`signedtag34`) in SHA-1 and SHA-256 repositories. The SHA-256 signatures match between runs, but the SHA-1 signatures differ, with different signature blocks shown in the same test run. This suggests the issue is specifically with SHA-1 signature generation stability in GPG.

The investigation has now shifted from test infrastructure problems to understanding why GPG produces inconsistent SHA-1 signatures even with fixed timestamps. This appears to be a genuine GPG behavior issue that the test is correctly detecting, rather than a test setup problem. Biederman continues to investigate the root cause of this signature generation instability.

Technical details show the divergence occurs in the PGP signature blocks themselves, with different signature values (`=7Jpz` vs `=G+Gp` endings) being generated for what should be identical SHA-1 signed content. The test failure manifests when comparing the resulting object IDs (`de9cabc2419f` vs `c87cd5157461`).
