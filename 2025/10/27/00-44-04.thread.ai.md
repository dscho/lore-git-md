Summary of Rust loose object map series (14 patches):

Final patch addressing zero-initialized object ID handling in Rust loose object map integration. Core issue involves object IDs with algo=0 causing lookup failures in Rust code due to strict comparison including algo field without access to global hash algorithm state. Solution modifies `repo_oid_to_algop()` in object-file-convert.c to create temporary copies of zero-algo object IDs, setting their algo field to repository's hash algorithm before processing. Key technical details: uses `hash_algo_by_ptr()` to get numeric algo ID, maintains existing behavior for valid algos, prevents propagation of malformed object IDs. Part of ongoing Rustification effort (Ezekiel Newren driving). Files touched: object-file-convert.c. Functions modified: `repo_oid_to_algop()`. Structs/fields involved: `object_id`'s `algo` field. Related infrastructure: `hash_algos[]` array, `hash_algo_by_ptr()` helper. This concludes the 14-patch series integrating Rust loose object map functionality.
