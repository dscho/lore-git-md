Feature patch in the geometric repacking maintenance series, making the geometric split factor configurable.

This patch introduces a new maintenance.geometric-repack.splitFactor configuration option that allows adjusting the geometric sequence factor used during repacking. While git-repack defaults to a factor of 2 (each pack must be at least twice as large as the previous), this change lets repository administrators set a higher factor for very large repositories to reduce packfile merge frequency. The implementation reads this config in both the main geometric repack task and its auto-condition logic, passing it through to the underlying git-repack command.

The change includes thorough test coverage verifying that:
- The configured factor is properly detected and passed to git-repack
- Different factors correctly influence whether repacking is triggered
- The default behavior remains unchanged when no configuration is set
- The feature works alongside other geometric repacking functionality

This is part of the v4 series implementing configurable geometric repacking strategies, which has already received maintainer approval. The patch follows the series' established patterns for config handling and testing, including the use of test_geometric_repack_needed helper functions and trace2 verification of exact command invocation. The implementation is clean, with minimal changes needed to integrate the new config option into the existing geometric repack infrastructure.
