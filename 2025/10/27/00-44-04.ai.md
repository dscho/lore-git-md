Bugfix patch addressing object ID handling in the Rust loose object map. This is the final patch in a 14-part series (no cover letter context provided).

The patch fixes an issue where zero-initialized object IDs (with algo=0) cause problems in the new Rust loose object map code. The Rust code can't find these objects because it does strict comparison including the algo field, and doesn't have access to the global hash algorithm state to compensate.

The solution copies zero-algo object IDs and sets their algo field to the repository's hash algorithm before processing. This both makes the Rust code work correctly and prevents propagation of malformed object IDs. The change is localized to `repo_oid_to_algop()` in object-file-convert.c, adding a temporary copy step when the source algo is zero.

Key technical points for future reference:
- Modifies `repo_oid_to_algop()` to handle zero algo values
- Introduces a `temp` object_id buffer for the fixed-up copy
- Uses `hash_algo_by_ptr()` to get the numeric algo ID
- Maintains same behavior when algo is already valid
