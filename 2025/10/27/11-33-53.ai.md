This is the fifth patch in an 11-part series implementing the new `git-history` command, specifically adding the `reword` subcommand. The patch builds on the foundational infrastructure established in earlier patches to provide a history-editing operation similar to interactive rebase's "reword" action.

The implementation handles core functionality for rewriting commit messages while preserving all other commit metadata. It includes comprehensive error checking (rejecting merge commits and unreachable revisions), maintains worktree/index state during the operation, and provides proper editor integration for message editing. The patch adds 331 lines to the core implementation and includes 237 lines of new test coverage across various scenarios (root commits, middle commits, edge cases).

Key technical details:
- New `cmd_history_reword()` function implementing the subcommand
- Uses existing `replay_create_commit()` infrastructure from earlier patches
- Preserves original author information while allowing message changes
- Validates commit reachability and rejects merges
- Includes tree-to-tree diff capability via `wt_status_collect_changes_trees()`
- Maintains worktree/index state during operation
- New test file `t/t3451-history-reword.sh` with 10 test cases
- Documentation updates in `git-history.adoc`
