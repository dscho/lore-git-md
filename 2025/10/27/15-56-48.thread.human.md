This thread discusses platform compatibility issues that surfaced during the Git v2.51.2 maintenance release, particularly around NonStop platform testing. The release initially included several fixes (including contributions from Jeff King, Jacob Keller, and Johannes Schindelin), but Randall Becker later reported test failures related to OpenSSL 3.5 and shell compatibility on NonStop systems. 

Brian Carlson identified the root cause as incompatibilities with AT&T ksh (ksh93), specifically around the `local` keyword and pipeline execution differences. Jeff King's workaround of setting `TEST_SHELL_PATH=/bin/bash` resolved the immediate issues. However, the discussion revealed deeper challenges - NonStop's CI system has a 2-3 week backlog due to lengthy test runs, meaning problems weren't caught before release.

SZEDER Gábor's recent contribution provides important clarification: neither the test library nor the problematic test script changed between v2.51.0 and v2.51.2, indicating the shell compatibility issues were pre-existing but only surfaced under specific conditions in this release. This reinforces that the workaround addresses a latent problem rather than new breakage, and highlights how CI bottlenecks can mask underlying compatibility issues.

While no new technical solutions are needed, the thread has documented important considerations about shell compatibility constraints and the challenges of platform-specific testing, particularly on resource-constrained systems. The discussion serves as a case study in how infrastructure limitations can impact release quality, even when the core code remains unchanged.
