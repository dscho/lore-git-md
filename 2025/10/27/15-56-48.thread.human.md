This thread discusses testing challenges for the Git v2.51.2 maintenance release on the NonStop platform, particularly around shell compatibility issues. The release initially surfaced problems with the AT&T ksh (ksh93) shell used on NonStop, where test failures occurred due to the shell's lack of `local` keyword support and different pipeline execution behavior compared to bash/zsh. Jeff King provided a workaround using `TEST_SHELL_PATH=/bin/bash`, which Randall Becker confirmed resolves the immediate issues.

Randall has provided important context about NonStop's testing constraints - their CI environment runs take over a day to complete, creating a 2-3 week backlog that makes continuous testing impractical. This explains why these latent shell compatibility issues weren't caught earlier. While v2.51.1 didn't exhibit these problems, the root cause remains unclear since no relevant test infrastructure changes occurred between versions. 

The discussion has also revealed an additional platform-specific issue with NonStop's sendmail implementation failing t9001 tests, prompting Randall to suggest adding a `SENDMAIL=NoThanks` option. While the immediate shell issues are resolved, the thread highlights systemic challenges in testing niche platforms where environmental differences and resource constraints complicate release validation. The consensus seems to be that while bisecting the exact cause might be informative, the effort required (weeks of testing time) likely isn't justified now that a working solution exists.
