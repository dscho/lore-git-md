Junio Hamano has weighed in on the discussion about maintenance release candidates that arose from the NonStop platform issues. He questions the need for separate maintenance release candidates, arguing that the existing 'master' and 'next' branches already serve as continuous testing grounds where changes should be vetted before reaching maintenance releases. Hamano suggests that platform-specific issues like the NonStop shell divergence should ideally be caught earlier in the development cycle rather than waiting for maintenance releases.

This response continues the thread's evolution from the specific technical fix (Jeff King's bash workaround for NonStop test failures) to broader questions about process. While Randall Becker had argued against maintenance release candidates from a stability perspective, Hamano approaches it from a workflow efficiency angle - doubting whether an additional pre-release step would meaningfully improve issue detection. The discussion now has two distinct but complementary perspectives favoring the status quo: Becker's emphasis on maintenance branch stability and Hamano's view of the existing branch structure as sufficient for testing. The original technical issue has been resolved, but the conversation about how to prevent similar issues in the future remains open.
