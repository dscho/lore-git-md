Refactoring patch in the `git-history` command series, focusing on interactive patch selection infrastructure.

This patch (7/11 in v6) restructures the code handling interactive options for `git add -p` and `git add -i` by introducing a new `struct interactive_options` to replace the shared `struct add_p_opt`. The change clarifies which options apply to which parts of the interactive add stack, though some entanglement between subsystems remains to be addressed in a follow-up.

The patch moves color configuration and diff settings into a new `interactive_config` structure, cleaning up the previous circular dependency where `add_p_opt` was used to initialize `add_i_state`. It touches multiple commands (`add`, `checkout`, `commit`, `reset`, `stash`) that use the interactive machinery, updating them to use the new structure.

The changes appear mechanical and well-contained, following the pattern of previous refactorings in this series. The patch maintains existing functionality while improving code organization in preparation for the upcoming `split` subcommand implementation. This continues the series' trend of building on Git's existing infrastructure while making targeted improvements.
