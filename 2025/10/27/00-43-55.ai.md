This is part of a series introducing Rust abstractions for Git's hash algorithms (patch 5/14). The patch focuses on creating a Rust equivalent of Git's hash algorithm abstraction, though it omits object-hashing functionality for now due to C/Rust interface challenges.

The implementation defines a `HashAlgorithm` enum with SHA-1 and SHA-256 variants, mirroring Git's C implementation. Key aspects include:
- Conversion methods between algorithm IDs and enum values
- Constants for special object IDs (null, empty tree, empty blob)
- Utility methods for algorithm properties (name, format ID, lengths)
- Slicing support for `ObjectID` based on algorithm

Notable implementation choices:
- Uses `self` instead of `&self` for size optimization
- Represents unknown algorithms with `Option` rather than a dedicated enum variant
- Includes precomputed hash values for common cases
- Maintains C-compatible representation via `#[repr(C)]`

The patch appears to be for internal plumbing rather than exposing new functionality. It's part of a larger Rust porting initiative, with careful attention to maintaining compatibility with Git's existing hash handling while adapting to Rust idioms. The implementation looks thorough, with comprehensive method coverage and clear documentation.
