This is a UX discussion thread about the `git history split` subcommand from Patrick Steinhardt's ongoing series. The conversation focuses on how commit messages should be handled when splitting a commit into two parts.

The key question is whether the split-out commit (S0) or the modified original (C0') should receive the new message. Karthik Nayak had suggested keeping the original message with the split-out commit and putting the new message on the modified original, while others proposed allowing both messages to be edited. D. Ben Knoble suggests a simpler approach - requiring editor-based message editing rather than supporting `-m` flags.

Patrick agrees to defer the decision, opting to require editor-based editing for now and revisit the design in future iterations. This keeps the current implementation simple while leaving room for more sophisticated multi-split functionality later. The discussion shows the team is carefully considering the UX implications of this history-editing feature before finalizing the design.
