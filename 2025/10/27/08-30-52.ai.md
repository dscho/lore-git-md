This is a refactoring patch in the geometric repacking maintenance series, specifically modifying the `too_many_loose_objects()` function in `builtin/gc.c`. The change makes the function more flexible by having it accept a direct threshold parameter rather than requiring the full `gc_config` struct, which will be needed for an upcoming caller that wants to use a different threshold value.

The patch mechanically updates all existing callers to pass `cfg->gc_auto_threshold` directly. The core logic remains unchanged - it still estimates loose object counts by checking the object directory and comparing against the threshold - but the interface is now more focused. This is part of the series' broader effort to clean up and modularize the repacking infrastructure.

Key technical details for future reference:
- Function signature change: `too_many_loose_objects(struct gc_config*)` -> `too_many_loose_objects(int)`
- All call sites updated to pass threshold directly
- Maintains same DIV_ROUND_UP calculation for auto_threshold
- Preserves existing loose object counting behavior
- Part of preparing for new maintenance strategy logic
-keeping with the series' theme of configurable repacking thresholds

The change is straightforward and mechanical, with no behavior modifications. It follows the series' pattern of incremental refactoring to support the geometric repacking strategy work while keeping individual patches focused.
