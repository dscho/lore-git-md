This is a feature patch series introducing a geometric repacking strategy for Git maintenance. The series has already gone through several rounds of review and is now in its fourth version, with maintainer approval pending only final discussion about multi-pack-index behavior in no-op cases.

The core change introduces a new "geometric" maintenance strategy that uses geometric repacking (via `git-repack`) as a more efficient alternative to the current all-into-one repacks performed by `git-gc`. This is particularly valuable for monorepos where full repacks are expensive. The strategy falls back to cruft packs when geometric repacking would collapse all packs into one, maintaining object phasing capabilities.

Key improvements in this version include:
- Configurable geometric factor via `maintenance.geometric-repack.splitFactor`
- Extended strategy support to cover both manual and scheduled maintenance
- Better test reliability (though a known MIDX rewrite issue in no-op cases is being deferred)
- Cleaner code organization with stack-allocated strvecs replacing global variables

The series builds on prior work to remove the `the_repository` global and includes comprehensive test coverage. While the MIDX behavior in no-op repacks has been identified as needing future attention, this doesn't block the current series which represents a significant improvement over both the default GC strategy and the existing incremental strategy.

This appears to be the final version before integration, with all major technical concerns addressed and only minor test-related discussions remaining. The changes since v3 are focused on test reliability and code readability rather than fundamental design changes.
