This is a refactoring patch in Patrick Steinhardt's `git-history` series, splitting the add-patch declarations into their own header file. The patch moves all add-patch related declarations from `add-interactive.h` to a new `add-patch.h`, leaving only the add-interactive specific declarations in the original header. This creates clearer boundaries between the two subsystems.

The technical changes include:
- Creating `add-patch.h` with declarations for `struct add_p_opt`, `enum add_p_mode`, and `run_add_p()`
- Moving the `ADD_P_OPT_INIT` macro to the new header
- Updating both `add-interactive.h` and `add-patch.c` to include the new header
- Removing now-redundant forward declarations from `add-interactive.h`

This change supports the larger `git-history` effort by improving code organization for the interactive patch selection functionality that will be used by the upcoming `split` subcommand. The patch follows Git's typical header file conventions and maintains all existing functionality while making the codebase more maintainable.

The change is straightforward and mechanical, with no behavior modifications. It builds on the series' pattern of refactoring existing Git infrastructure to support the new history editing capabilities while improving code organization. The patch follows the style of previous refactorings in the series and doesn't introduce any new technical challenges or open questions.
