Refactoring patch in the `git-history` series, adding in-memory index patching capability to the add-patch subsystem. This patch introduces `run_add_p_index()` as a variant of `run_add_p()` that operates on an arbitrary in-memory index rather than the repository's main index. The implementation modifies `add_p_state` to track both the target index and its file path separately from the repository's index, with careful handling of index refresh operations to avoid corrupting the in-memory state. The new function will be used by subsequent patches in the series for operations like `git history reword` that need to manipulate temporary indexes.

Key technical changes:
- Adds `index` and `index_file` fields to `add_p_state` struct
- Modifies `patch_update_file()` to use the specified index
- Updates index refresh logic to only refresh the repository index when appropriate
- Introduces new `run_add_p_index()` API in `add-patch.h`
- Maintains existing behavior for regular `run_add_p()` calls
- Handles binary files and empty changesets consistently

The patch continues the series' pattern of cleanly separating concerns while building infrastructure for history editing commands. It represents another step in decoupling the add-patch subsystem from assumptions about working with the repository's primary index.
