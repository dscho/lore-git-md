This is a refactoring patch that changes the data type used for hash algorithm identifiers from `int` to `uint32_t` throughout the codebase. The change is part of a larger series (3/14) preparing for Rust integration, specifically to ensure type compatibility when the object ID structure is defined in Rust.

The patch updates function return types, variable declarations, and struct fields across multiple files (hash.c, hash.h, oidtree.c, repository.c, repository.h, serve.c) to use the new type. The motivation is clearly stated: to maintain exact type matching between C and Rust implementations.

The changes appear mechanical and straightforward, touching only the type declarations while keeping all the same logic. The patch maintains consistency by updating both the implementations and their corresponding header declarations. This seems like a low-risk change that serves as groundwork for future Rust integration work.
