Randall Becker reports test failures on NonStop systems when building with OpenSSL 3.5, specifically in t7900 maintenance tests related to `test_subcommand` assertions. The issue manifests when testing `git gc` invocations, particularly with negated assertions (`test_subcommand !`), producing "test: argument expected" errors. Investigation revealed a shell selection mismatch: while Make uses `/bin/bash` for recipe processing, test scripts' `#!/bin/sh` shebang causes them to run under ksh on NonStop systems. SZEDER Gábor provided bash -x traces showing expected output patterns, helping identify the divergence point. Randall confirmed manually using bash resolves the failures but notes this creates maintenance burden.

Jeff King suggests trying `make TEST_SHELL_PATH=/bin/bash` as a potential solution, explaining the distinction between Git's `SHELL_PATH` (for #! lines and C program invocations) and Make's `SHELL` (for recipe processing). This offers a Git-specific configuration option beyond the basic Make `SHELL` variable that Randall had tried. The issue remains a platform-specific interaction between NonStop's shell configuration and GNU Make 4.1.2's handling of shell selection. Current focus is on evaluating Jeff's proposed workaround while maintaining awareness of the broader context that Randall Becker is the primary NonStop maintainer and that solutions should minimize platform-specific maintenance overhead. No resolution has been committed yet; the discussion continues to explore test harness modifications versus platform workarounds.
