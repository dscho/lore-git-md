Git v2.51.2 maintenance release announcement and subsequent NonStop platform bug reports, with analysis of shell compatibility issues. Fixes included: `git diff --quiet -w` behavior (Jeff King), `--no-index` trailing slash handling (Jacob Keller), `git status --short -z` coloring consistency, Windows CI fixes (Johannes Schindelin), OpenSSH test workarounds (Patrick Steinhardt), Unicode 17 updates, and GitHub Actions refreshes.

Randall Becker reported test failures on NonStop systems with OpenSSL 3.5 in t7900 maintenance tests involving `test_subcommand !` assertions, caused by a divergence between Make's `/bin/bash` usage and test scripts' ksh invocation. Jeff King's `TEST_SHELL_PATH=/bin/bash` workaround resolved this by ensuring consistent bash usage, confirmed effective by Randall. Brian Carlson's technical analysis explains the root cause: AT&T ksh (ksh93) fails Git tests due to lacking the `local` keyword used in test helpers, while other ksh variants (pdksh, mksh) generally work. Additional shell behavior differences noted include pipeline execution - ksh and zsh in native mode run the last pipeline command in the main shell rather than a subshell, potentially causing further incompatibilities. Zsh in sh-emulation mode mostly works but zsh mode has never passed the full test suite.

Kristoffer Haugsbakk proposed introducing release candidates for maintenance releases to catch such issues earlier, but Randall Becker argued maintenance releases should focus strictly on fixes without new functionality. Junio Hamano questioned the value given 'master' already serves as a test bed, with changes flowing through 'next' first. Kristoffer conceded Junio's point about the likely ineffectiveness of adding another pre-release step. While the immediate NonStop issue is resolved via `TEST_SHELL_PATH=/bin/bash`, open questions remain about other potential shell-related problems on NonStop and how to balance portability with maintainer workflow. The discussion has documented important shell compatibility constraints affecting test infrastructure, particularly regarding `local` variable support and pipeline execution differences between shell implementations.
