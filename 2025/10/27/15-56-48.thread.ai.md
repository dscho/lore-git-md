Git v2.51.2 maintenance release discussion, focusing on NonStop platform testing issues and shell compatibility problems. Thread covers: release announcement with fixes (Jeff King's `git diff --quiet -w`, Jacob Keller's `--no-index` trailing slash, Windows CI updates from Johannes Schindelin, OpenSSH test workarounds by Patrick Steinhardt), followed by Randall Becker's reports of test failures on NonStop with OpenSSL 3.5 in t7900 maintenance tests.

Root cause analysis from brian m. carlson identified AT&T ksh (ksh93) incompatibilities - lack of `local` keyword in test helpers and pipeline execution differences (ksh/zsh run last command in main shell). Jeff King's `TEST_SHELL_PATH=/bin/bash` workaround resolved immediate issues, confirmed by Randall. Kristoffer Haugsbakk proposed maintenance release candidates, but Junio Hamano and Randall Becker questioned effectiveness given existing testing bottlenecks.

SZEDER Gábor's technical follow-up shows neither test library (`test-lib.sh`, `test-lib-functions.sh`) nor t7900 maintenance test script changed between v2.51.0 and v2.51.2, disproving earlier assumptions about test changes causing failures. This indicates the shell compatibility issues were latent and only surfaced due to specific environmental conditions in v2.51.2 testing, despite being present in earlier versions. The CI backlog (2-3 week delays due to day-long test runs) prevented earlier detection.

Current status: `TEST_SHELL_PATH=/bin/bash` remains the working solution for NonStop's ksh93 incompatibilities. No new technical problems require resolution, but the thread has documented important platform testing constraints: shell behavior differences (`local` keyword support, pipeline execution), CI resource limitations masking latent issues, and the challenge of catching environment-specific failures when test infrastructure itself hasn't changed. These operational realities complicate maintenance release validation, particularly for niche platforms like NonStop.
