This is a documentation and code cleanup patch correcting bit assignments in whitespace handling code. Junio Hamano noticed and fixed an off-by-one error in comments describing the bit layout for whitespace rules in diff.c, where the comment incorrectly stated the range of bits used for whitespace rules versus new/old/context markers. The patch updates comments in diff.c to correctly reflect that bits 0-11 are for whitespace rules and bits 12-14 are for WSEH flags, while bit 16 remains for blank-at-EOF marking. 

The changes also modernize how these bit constants are defined, switching from octal notation to explicit bit shifts (1<<N) which makes the bit positions more immediately visible and helps prevent similar miscounting errors in the future. This affects definitions in diff.h and ws.h, where whitespace rule constants are converted to bit-shift style and tab width handling is clarified (now explicitly limited to 63 via bitmask). 

The patch is purely corrective - no behavior changes - and comes with a lighthearted note from Junio about his counting skills. He also hints at a future direction to create more space between whitespace rules and WSEH bits to allow for additional whitespace rules. The changes touch core diff and whitespace handling code but are straightforward and unlikely to be controversial.
