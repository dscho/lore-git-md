This is part of a series exposing Git's hash functionality to Rust code. The patch moves several inline hash context functions from `hash.h` to `hash.c` and makes them non-inline, while adding new allocation and initialization functions. The motivation is to enable Rust code to use Git's hash algorithms while avoiding manual memory management and inline function limitations.

Key changes:
- Adds `git_hash_alloc()` and `git_hash_free()` for context management
- Moves `git_hash_init()`, `git_hash_clone()`, `git_hash_update()`, `git_hash_final()`, and `git_hash_final_oid()` from inline to regular functions
- Keeps the same function signatures but makes them callable from Rust
- Maintains all existing hash algorithm functionality while making it more accessible

The changes are straightforward mechanical transformations of existing code to make it usable from Rust. The patch appears well-contained and focused on its stated goal of exposing hash functionality to Rust while maintaining memory safety. This is part of a larger effort to expand Git's Rust integration.
