This is part of a series adding Rust infrastructure to Git, specifically focusing on hash algorithm abstraction. Patch 5/14 introduces a Rust implementation of Git's hash algorithm handling, though it notably omits object hashing functionality for now to avoid complexity in C/Rust interface compatibility.

The patch defines a `HashAlgorithm` enum with SHA-1 and SHA-256 variants, mirroring Git's C implementation but with Rust-specific design choices. It includes methods for converting between algorithm IDs, getting hash lengths, and accessing special object IDs (null, empty tree, empty blob). The implementation carefully maintains binary compatibility with Git's existing structures while using Rust idioms like `Option` instead of special "unknown" values.

The changes appear well-considered, with attention paid to both functionality and performance characteristics. The commit message explains the deliberate omission of hashing functionality and the choice to use `self` rather than `&self` for size optimization. This looks like solid foundational work for Git's Rust integration.
