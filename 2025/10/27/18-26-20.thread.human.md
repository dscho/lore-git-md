This patch introduces support for migrating ref storage formats (between files and reftable) in repositories with linked worktrees, addressing a previous limitation. The implementation carefully handles multiple worktrees through a multi-phase approach that creates temporary storage, backs up existing refs, and ensures safe rollback if needed.

Key technical aspects include tracking per-worktree state, properly handling commondir files, filtering ref iteration for worktree-specific refs, and using non-INITIAL transactions to avoid packed-refs issues. The patch requires migration to be initiated from the main worktree and includes comprehensive tests covering various scenarios like multiple worktrees, dry-run mode, and error recovery.

The changes touch core refs migration logic in refs.c, worktree-specific handling in files-backend.c, and add extensive test coverage. Some open questions remain about edge cases with prunable worktrees, the robustness of the backup approach, and performance implications for repositories with many worktrees.
