This thread centers on adding worktree support to `git refs migrate`, enabling ref storage format conversion (between files and reftable) in repositories with multiple worktrees. The technical foundation is now settled: ref storage format must be uniform across all worktrees (enforced via `extensions.refStorage`), and operations must run from the main worktree for safety. Junio Hamano and Patrick Steinhardt have confirmed these constraints as necessary simplifications, though Patrick suggested reorganizing the patch series to separate backend changes from worktree logic.

The discussion has shifted to user experience concerns. Kristoffer Haugsbakk initially argued that requiring main-worktree operation feels unnecessarily restrictive to users, drawing parallels to `git gc`. Ben Knoble now reinforces this perspective, proposing that the command could automatically switch to the main worktree when needed (with appropriate feedback), rather than failing. While Patrick had cautioned against surprising behavior, Ben frames this as a polish issue that could be addressed post-stabilization.

Current open work includes: restructuring the patch series per Patrick's suggestions, finalizing the backup/restore mechanism, handling prunable worktrees, and - most prominently - crafting documentation that clearly explains the uniform storage requirement while minimizing user friction. The technical implementation is converging, but the team is still working through how to present these constraints in a way that feels intuitive to end users.
