This thread covers brian m. carlson's second version of a 14-patch series introducing Rust code to enable SHA-1/SHA-256 repository interoperability, marking Git's first major use of Rust. The implementation includes a new loose object format in Rust, hash algorithm abstractions, and build system changes to support Rust compilation. The series builds on brian's prior work making Git's internals hash-algorithm-agnostic.

Patrick Steinhardt, who leads Git's object storage modernization efforts, has now reviewed the series. While not objecting to the overall approach of using Rust for interoperability, he suggested a small but meaningful improvement to the C/Rust boundary code - using `MAYBE_UNUSED` instead of a void cast for the `the_repository` parameter when Rust support is disabled. This indicates technical alignment on the direction while maintaining Git's code quality standards. The series currently lacks Reviewed-by tags, and potential platform support concerns (particularly around NonStop/Rust compatibility) remain unaddressed. This represents an important step in both the interoperability work and Git's broader Rustification effort.
