This is a feature patch series introducing a new `git-history` command for history editing operations, now in its sixth iteration. The series has been significantly based on feedback from the Git Contributor's Summit, focusing on non-conflicting operations (`reword` and `split` subcommands) while avoiding more complex cases like merge handling.

The v6 changes simplify the implementation by:
1. Dropping the `-m` option for both subcommands, requiring editor-based message editing
2. Removing merge machinery usage in favor of direct commit creation
3. Eliminating redundant commit parsing safety checks
4. Rebased on latest upstream changes

Key technical components include:
- New `builtin/history.c` implementing both subcommands:
  - `reword` for commit message editing (now simplified without replay machinery)
  - `split` for interactive commit splitting using temporary index manipulation
- Shared `replay.[ch]` infrastructure extracted from `builtin/replay.c`
- Extensive test coverage (26 test cases across two test scripts)
- Documentation marked as experimental following Git conventions

The series appears ready for integration pending stabilization of its `sa/replay-atomic-ref-updates` dependency, with all substantive technical feedback addressed. Junio Hamano has already reviewed and approved key aspects like the `the_repository` removal in commit buffer handling. The implementation takes an incremental approach, deferring more complex features like merge commit handling and hook integration for future work.
