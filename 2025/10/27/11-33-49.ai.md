This is a refactoring patch that introduces new infrastructure for the `git-history` command series. It adds tree-to-tree diff functionality to the working tree status subsystem, though the immediate use case is for history editing rather than working tree operations.

The patch adds `wt_status_collect_changes_trees()` which diffs two arbitrary trees and formats the changes as if they were staged in the index. This generalizes existing wt-status machinery to work outside the context of the working tree/index. The implementation wraps the diff machinery with standard callbacks and handles rename detection configuration through the existing wt-status struct.

While this extends wt-status beyond its original working-tree-focused purpose, the commit argues this is preferable to duplicating the diff formatting logic. The function will be used by subsequent patches in the series for the `reword` and `split` subcommands of `git-history`. The implementation follows Git's existing patterns for diff handling and status collection, with all configuration options (rename detection thresholds etc.) properly forwarded from the status struct.

Key technical details:
- New public function in wt-status.h with documentation
- Uses standard diff callbacks (wt_status_collect_updated_cb)
- Forwards rename detection settings from wt_status struct
- Maintains existing diff formatting behavior
- Part of building blocks for git-history's in-memory index operations
- Follows same pattern as working tree/index diff collection but generalized to arbitrary OIDs
