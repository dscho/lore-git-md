This is a feature patch in the geometric repacking maintenance series, now in its fourth iteration. It makes the geometric repacking factor configurable via a new `maintenance.geometric-repack.splitFactor` setting, defaulting to 2 (the current hardcoded value). This allows repositories to tune how aggressively packs are merged - higher values mean fewer merges but potentially larger packs.

The patch adds the config option documentation, implements the config lookup in both the main repack task and auto-condition logic, and includes a thorough test verifying the setting is properly honored. The test creates a specific pack structure to demonstrate how different split factors affect which packs get merged.

This is a straightforward addition to the geometric repacking infrastructure that follows the pattern of other configurable maintenance parameters. The implementation is clean, with clear test coverage showing both the default behavior and custom configurations. As part of the v4 series that has maintainer approval, this patch appears ready for integration.
