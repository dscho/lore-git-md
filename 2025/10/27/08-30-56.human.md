Refactoring patch in the geometric repacking series. This is a code style improvement to make maintenance strategy definitions more readable by using nested designated initializers. The change doesn't modify any behavior - it just reorganizes how the strategy configurations are laid out in `builtin/gc.c`.

The patch converts flat initializations of maintenance task structures into nested blocks, with each task's fields grouped together. For example, where previously `TASK_COMMIT_GRAPH` had its `.enabled` and `.schedule` on separate lines at the same indentation level, they're now grouped in a nested block. This makes it visually clearer which fields belong to which task.

Taylor Blau suggested this improvement, and Patrick Steinhardt implemented it. The change affects all three strategy definitions in the file (none, default, and incremental) but is most noticeable in the incremental strategy which has multiple configured tasks. This is a straightforward quality-of-life improvement for developers working with the maintenance task code.
