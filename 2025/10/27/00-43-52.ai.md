Bugfix for hash algorithm conversion edge case. This is part of a larger series (position 2/14) about repository hash algorithm handling, though the cover letter wasn't provided for context.

The patch fixes a crash that occurs when converting object IDs between hash algorithms in repositories without a compatibility hash algorithm configured. Currently, when no destination algorithm is specified (to=NULL), the code would dereference NULL. The change makes this case a silent no-op that just copies the source OID when src and dest differ.

The fix is straightforward - just adding a `|| !to` condition to the existing equality check. This appears to be a defensive programming change to handle an edge case that wasn't previously considered. The commit message clearly explains the change and motivation, though it doesn't provide reproduction steps for the crash scenario.

Key technical details for future reference:
- Touches `object-file-convert.c`
- Modifies `repo_oid_to_algop()` behavior when `to` parameter is NULL
- Maintains same return semantics (0 for success)
- Still performs OID copy when src and dest pointers differ
- Part of broader work around hash algorithm handling
