Part of the ongoing effort to migrate Git's interoperability code to Rust. This patch makes Rust support mandatory for the compatibility hash algorithm feature, which handles conversion between different object hash algorithms (like SHA-1 to SHA-256). The change causes Git to error out if Rust support isn't available when compatibility mode is requested.

The patch acknowledges this is technically a regression, but argues it's acceptable because the feature is already marked experimental and largely broken in its current C-only implementation. The author states they're unaware of any real-world users relying on the current implementation.

Several test scripts are updated to skip compatibility-related tests when Rust support isn't available. The changes are mechanical but widespread, touching multiple test files to add RUST prerequisites where compatibility features are tested.

This appears to be a well-justified step in the Rust migration, with careful consideration given to backward compatibility impacts. The patch is part of a larger series (01/14) that will presumably introduce the Rust implementation being prepared for.
