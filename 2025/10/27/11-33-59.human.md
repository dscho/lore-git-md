This is the final patch in Patrick Steinhardt's v6 series introducing the `git history` command, adding the `split` subcommand. The feature enables users to interactively split a commit into two commits by selecting which hunks should be moved to a new commit that becomes the parent of the original.

The implementation builds on the infrastructure from previous patches in the series, using the refactored add-patch functionality for hunk selection and the generalized `write_in_core_index_as_tree()` for in-memory index operations. The command handles several edge cases - it rejects merge commits, ensures the split commit is reachable from HEAD, and verifies neither resulting commit would be empty. The patch includes extensive tests covering 432 lines across various scenarios like splitting root commits, using pathspecs, and preserving worktree state.

The documentation explains the command's behavior and provides an example workflow showing how it simplifies what would otherwise be a multi-step rebase operation. The implementation appears thorough, with clear attention to detail in handling authorship, commit messages, and tree validation. This completes the initial feature set for the experimental `git history` command alongside the previously implemented `reword` subcommand.
