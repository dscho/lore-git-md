This is a refactoring patch in Patrick Steinhardt's `git-history` series, adding infrastructure support for in-memory index operations. The patch introduces `run_add_p_index()`, which extends the existing add-patch functionality to work with arbitrary in-memory index states rather than just the repository's main index.

The change is part of the larger effort to enable flexible history editing operations (like `reword` and upcoming `split` subcommands) by decoupling components and making them work with temporary index states. The implementation carefully handles both the regular repository index and custom in-memory indexes, with appropriate fallbacks for refresh operations when working with the main index.

The patch appears well-constructed, with clear separation of concerns and thorough handling of edge cases like binary files. It builds on previous refactoring work in the series that separated add-patch from add-interactive subsystems. The changes are focused and mechanical, primarily adding the new capability while maintaining existing behavior for the traditional code paths.

This is one of the foundational pieces needed before the history editing commands can be fully implemented, and it follows the series' pattern of incremental, well-contained infrastructure improvements. The patch doesn't introduce user-facing changes but enables future functionality in a clean way.
