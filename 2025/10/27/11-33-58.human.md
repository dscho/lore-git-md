This is a refactoring patch in Patrick Steinhardt's `git-history` series, focusing on the cache-tree infrastructure. The change generalizes `write_in_core_index_as_tree()` to accept any `struct index_state` rather than always using the repository's main index. This prepares for future in-memory index operations needed by the history editing commands.

The patch is straightforward - it modifies the function signature and updates the single caller in `builtin/checkout.c`. The implementation remains largely the same, just without the hardcoded `repo->index` access. This follows the series' pattern of decoupling functionality from assumptions about working with the primary repository state.

As part of the larger effort to enable flexible history editing, this change helps support operations that will need to manipulate temporary in-memory indexes. The patch is cleanly implemented and maintains existing behavior while removing a limitation. It's a small but meaningful step in the series' infrastructure improvements.
