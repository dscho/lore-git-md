This is a refactoring patch in Patrick Steinhardt's v6 series introducing the `git-history` command. The patch focuses on cleaning up the interactive add/patch infrastructure that will be used by the upcoming `split` subcommand.

The main change splits out color and configuration handling from the add-patch and add-interactive subsystems into a new `struct interactive_options` and `struct interactive_config`. Previously, these were tangled together through `struct add_p_opt` and `struct add_i_state`, leading to circular dependencies where add-patch options were passed through add-interactive only to end up back in add-patch.

Key technical changes:
- Introduces `interactive_config_init()` and `interactive_config_clear()` to handle color/diff configuration
- Moves color initialization code from add-interactive.c to add-patch.c
- Updates all callers (add, checkout, reset, stash, etc.) to use the new `struct interactive_options` instead of `struct add_p_opt`
- Renames `ADD_P_OPT_INIT` to `INTERACTIVE_OPTIONS_INIT`
- Keeps the same functionality but with clearer separation of concerns

The patch is part of the larger effort to build history editing capabilities while reusing Git's existing interactive add/patch machinery. It doesn't complete the decoupling - a follow-up commit will fully detangle the subsystems by removing the remaining `init_add_i_state()` call from add-patch.

This appears to be a straightforward mechanical refactoring that improves code organization without changing behavior, continuing the series' pattern of careful incremental changes to Git's core infrastructure.
