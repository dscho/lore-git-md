This is a refactoring patch from Patrick Steinhardt, part of the v4 geometric repacking maintenance task series. It removes the global `repack` variable in `builtin/gc.c` that was used to accumulate arguments for `git-repack`, replacing it with stack-allocated `strvec` instances passed through function parameters.

The key changes:
- Eliminates the global `static struct strvec repack` variable
- Modifies `add_repack_all_option()`, `add_repack_incremental_option()`, and `keep_one_pack()` to accept a `struct strvec*` parameter
- Updates `need_to_gc()` to take repack arguments as a parameter
- Introduces `gc_condition()` wrapper for maintenance tasks to handle temporary argument storage
- Maintains all existing functionality while making the code more reusable

The patch demonstrates careful attention to edge cases, particularly around the dual use of `need_to_gc()` by both `git gc --auto` and maintenance tasks. The solution for maintenance tasks - using a temporary `strvec` that gets discarded - is clean and avoids complicating the control flow. This refactoring enables subsequent patches in the series to reuse the repack argument-building logic more cleanly.

The changes are mechanical with no behavior modifications, focused purely on improving code structure. The patch follows the series' established pattern of careful, incremental improvements to the geometric repacking infrastructure.
