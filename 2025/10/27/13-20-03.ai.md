Bugfix for whitespace highlighting in diffs. Alice Carlotti identifies an edge case where Git fails to highlight whitespace errors (specifically WS_BLANK_AT_EOF) when the final diff hunk has either zero old lines or zero new lines. This occurs most frequently with new files or when using `-U0` diff output.

The root cause lies in how hunk headers handle zero-length ranges - empty files use 0,0 while non-empty files use 1,N. The patch proposes fixing this in `diff.c:find_lno()` by adjusting line number calculations for zero-length hunks. The author notes that similar range parsing logic exists in `apply.c:parse_range()` and suggests this could potentially be reused.

This appears to be a well-analyzed bug with a focused fix targeting a specific whitespace detection edge case. The commit references prior discussion about the deliberate hunk header numbering scheme, showing awareness of the historical context. The proposed solution seems reasonable though it may need review regarding potential interactions with the apply machinery's parsing logic.
