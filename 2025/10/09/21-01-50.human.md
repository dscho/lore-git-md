Feature enhancement for commit-graph Bloom filters with new config option.

Emily Yang proposes adding a configuration option `commitGraph.changedPaths` to control whether changed-path Bloom filters are written by default during commit-graph operations. This builds on the existing `--changed-paths` command-line option, which has proven stable and beneficial for large repositories like Microsoft's Office MonoRepo. The new config provides a persistent way to enable this performance optimization without requiring explicit command-line flags.

The patch adds the config option with clear documentation, implements the logic in the commit-graph write code (respecting command-line precedence), and includes comprehensive tests verifying the interaction between config settings and command-line overrides. As a bonus, it enables the feature by default in Scalar, Git's large-repo optimization tool.

This appears to be a well-considered change from a new contributor working with experienced Git developers. The commit message clearly explains the motivation and behavior, the implementation is straightforward, and the test coverage is thorough. The change seems likely to be uncontroversial as it builds on an established feature while maintaining backward compatibility.
