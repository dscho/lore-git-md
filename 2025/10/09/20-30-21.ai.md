This is a platform compatibility patch addressing a clang compiler warning, with Junio Hamano providing feedback on Johannes Schindelin's original submission.

The core issue involves clang's `-Wunreachable` warning flagging code in `refs/files-backend.c` as unreachable when `NO_SYMLINK_HEAD` is defined, since `create_ref_symlink()` becomes hardcoded to `(-1)`. Schindelin's solution uses the existing `NOT_CONSTANT()` macro pattern (from commit 82e79c63642c) to suppress this false positive while preserving the warning's usefulness for genuinely unreachable code.

Hamano's response acknowledges the technical correctness of the fix but suggests a longer-term solution: deprecating and eventually removing the `core.preferSymlinkRefs` configuration, since all platforms should be able to handle text-file HEAD references even if they can't create symlinks. He notes this would be a change for Git 3.0, but approves the current warning-suppression approach as reasonable interim solution.

The actual code change is minimal - a 7-line addition (including explanatory comment) and 1-line modification in the files backend, using the `NOT_CONSTANT()` wrapper around the symlink creation check. This maintains identical runtime behavior while silencing the compiler warning. The discussion touches on platform-specific behavior (`NO_SYMLINK_HEAD`), compiler warnings (`-Wunreachable`), and configuration option philosophy (`core.preferSymlinkRefs`), making it relevant for both build-system maintainers and those working on refs backend internals.
