This is part 2 of a 6-patch series refactoring Git's packfile store API, focusing on converting callers to use standardized iteration patterns. The patch converts the incremental repack auto-condition check in `builtin/gc.c` from using `packfile_store_get_packs()` to `packfile_store_get_all_packs()`.

The change is straightforward but meaningful - the maintenance code needs to count non-MIDX'd packs to decide whether to repack, and while the old function avoided loading MIDX'd packs, the new approach loads all packs but explicitly skips MIDX'd ones in the loop. This aligns with the series' goal of eliminating confusing statefulness in the pack iteration API.

The patch is a clean mechanical conversion with a clear explanation of why the change is safe (the code already properly handles MIDX'd packs by checking `p->multi_pack_index`). It's part of a well-reviewed series that has already addressed potential concerns about API design and merge conflicts in earlier iterations. The change preserves behavior while moving toward more maintainable internals.
