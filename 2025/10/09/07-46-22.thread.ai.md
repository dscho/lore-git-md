Thread identity: Platform compatibility patch addressing clang compiler warning in `refs/files-backend.c`, originating from Johannes Schindelin with Junio Hamano providing feedback.

Core problem: Clang's `-Wunreachable` warning incorrectly flags code guarded by `!create_ref_symlink()` as unreachable on platforms with `NO_SYMLINK_HEAD` defined (where `create_ref_symlink()` hardcodes to `(-1)`). The immediate solution uses the existing `NOT_CONSTANT()` macro pattern from commit 82e79c63642c to suppress this false positive while preserving warning utility for genuinely unreachable code.

Current status: Junio approves the warning-suppression approach as reasonable interim solution, proposing to deprecate and remove `core.preferSymlinkRefs` configuration in Git 3.0 since all platforms should handle text-file HEAD references regardless of symlink capability. The 7-line change (including comment) in `refs/files-backend.c` maintains identical runtime behavior while silencing the warning.

Key technical details: Change affects the files backend's symlink handling, specifically the `create_symref_locked()` function. Uses `NOT_CONSTANT()` wrapper around symlink creation check. Preserves existing behavior where platforms with `NO_SYMLINK_HEAD` fall back to text-file HEAD references.

Open questions: Future removal of `core.preferSymlinkRefs` configuration option planned for Git 3.0, though not blocking current fix.

Participant positions: Johannes Schindelin proposed the warning-suppression fix. Junio Hamano approved it while suggesting longer-term configuration simplification. Both agree the current approach is correct for immediate needs.
