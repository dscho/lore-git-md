This is a discussion about documentation wording for the `--committer-date-is-author-date` option in Git's rebase` and `am` commands. Kristoffer Haugsbakk responds to Junio C Hamano's feedback about using the term "lie" rather than "override" in the warning text.

The exchange reveals deeper thinking about timestamp manipulation in Git. Kristoffer explains their evolving understanding of the option's purpose - from initially seeing it as a vanity feature to now recognizing its legitimate uses in `git-am` for preserving commit IDs when reapplying patches. They contrast this with the more problematic use in `git-rebase` which can violate Git's timestamp ordering assumptions.

Kristoffer supports Junio's suggestion to use the strong term "lie" in the documentation, arguing it better conveys the seriousness of misrepresenting commit metadata. They note that while author date manipulation can be reasonably judged by common sense (since authors know when they actually wrote code), committer date manipulation is more opaque to users who may not understand the committer concept.

This email shows the documentation patch is progressing with thoughtful consideration of both technical accuracy and user impact. The discussion has moved beyond just wording to address the philosophical question of how Git should represent and warn about intentional metadata manipulation.
