This is a bugfix and documentation patch in the SHA-1/SHA-256 interoperability series, focusing on GPG signature validation in tags.

The patch enhances `fsck` to properly validate GPG signature headers (`gpgsig` and `gpgsig-sha256`) in tag objects. Previously, these headers could trigger false positives under strict checking modes. The changes include:

1. New error messages in `fsck-msgids.adoc` for malformed signature headers (`badGpgsig`) and continuation lines (`badHeaderContinuation`).

2. Implementation in `fsck.c` that:
   - Recognizes both signature header types
   - Validates proper continuation line formatting
   - Reports errors for truncated signatures or malformed continuations

3. Comprehensive tests in `t/t1450-fsck.sh` covering:
   - Acceptance of valid signature headers (even with invalid signatures)
   - Rejection of malformed headers with junk data
   - Proper error message generation

The changes align with Git 2.29+ behavior where tag signatures appear in-body while alternate signatures use headers. This is part of the broader SHA-1/SHA-256 compatibility work, ensuring proper signature header handling is crucial for verifying objects across hash algorithms. The patch includes thorough documentation and test coverage, building on previous work in the series to accurately represent tag signature behavior.
