Documentation update clarifying tag signature behavior in hash transition.

This patch updates the hash function transition documentation to accurately reflect how tag signatures work in practice since Git 2.29. The docs previously described an intended design where SHA-256 signatures would always appear in headers, but the actual behavior that shipped places the current algorithm's signature in the body and the other algorithm's in a header. The changes:

1. Document that both `gpgsig` and `gpgsig-sha256` fields exist, with the current algorithm's signature in-body and the other in a header
2. Clarify the signed payload calculation excludes both signature fields and the PGP delimiter
3. Simplify the description of signing options to "one or both algorithms" rather than enumerating cases

The change aligns documentation with reality after a missed patch in Git 2.29 resulted in different behavior than originally planned. This is part of brian m. carlson's ongoing SHA-1/SHA-256 interoperability work, specifically addressing documentation accuracy for tag signature handling that has been in place since 2.29. The update maintains technical precision while making the behavior description clearer and more concise.
