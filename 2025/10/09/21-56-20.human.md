This is a documentation patch in brian m. carlson's SHA-1/SHA-256 interoperability series, correcting the tag signature documentation to match Git's actual behavior since version 2.29. 

The patch updates the hash function transition documentation to reflect that tag signatures now work differently than originally designed - the current hash algorithm's signature appears in the tag body while the alternate algorithm's signature goes in a header, the opposite of what was originally planned. This change happened unintentionally when a patch was missed during the 2.29 release cycle, and the documentation has been inaccurate since then.

The documentation now clearly explains that dual-signed tags will contain both an in-body signature (for the current algorithm) and a header signature (for the other algorithm), rather than the previously documented arrangement. The patch simplifies the explanation by removing the three separate cases (SHA-1 only, both, SHA-256 only) in favor of a more straightforward description covering all possibilities.
