This is part of a refactoring series cleaning up Git's packfile iteration patterns. The patch converts two functions in object-name.c from using `packfile_store_get_packs()` to `packfile_store_get_all_packs()`, as part of eliminating confusing stateful behavior in the two related functions.

The change affects how Git searches for abbreviated object IDs and disambiguations. The old `get_packs()` function had problematic behavior where its output depended on whether `get_all_packs()` had been called first, since both operated on the same underlying packfile list. This patch makes the behavior more predictable by always using `get_all_packs()`, which includes MIDX'd packs (multi-pack index files) in its results.

The author notes this is safe because the calling functions already know how to skip MIDX'd packs when needed. The change is straightforward, touching just two lines that iterate over packfiles during object lookup. This is the first of six patches in v2 of the series, which has already received positive technical feedback from Taylor Blau in previous iterations.
