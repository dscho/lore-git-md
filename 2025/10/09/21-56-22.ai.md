This is a documentation patch in brian m. carlson's SHA-1/SHA-256 interoperability series, specifically documenting the loose object storage format. The patch adds a new `gitformat-loose.adoc` file that comprehensively describes how Git stores individual objects as separate files before they are packed.

The documentation covers:
- The loose object file structure (prefix with type/size followed by compressed data)
- Object ID calculation (hash of uncompressed data)
- File naming convention (sharded by first two hex digits of hash)
- Examples showing concrete object contents and storage paths
- Relationship to packfiles (loose objects as initial storage before packing)

Key technical details include:
- Prefix format (`<type> <size>\0`) matching what's used for object ID computation
- Compression using zlib
- Storage path structure under objects/[0-9a-f][0-9a-f]/
- Explicit examples for empty tree and simple blob
- Clear distinction between SHA-1 and SHA-256 repository behavior

The patch integrates with the series' broader goal of formalizing Git's object storage formats, following Junio's approval of the documentation approach. It complements the previously added pack format documentation and maintains consistency with the series' technical precision. The implementation is straightforward - adding the new documentation file and updating build system files to include it.
