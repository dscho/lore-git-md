Bugfix patch for `git stash` output behavior when showing stash counts, addressing confusion from redundant status messages. This is the second version of the patch, incorporating feedback from the thread discussion.

The patch modifies `builtin/stash.c` to track stash counts before operations and show accurate post-operation counts, rather than showing pre-operation counts that become immediately incorrect. Key changes include:

1. Introduces `previous_stash_count` tracking and `print_stash_status()` helper to show updated counts after stash operations
2. Uses `--no-show-stash` flag when calling `git status` internally to avoid redundant pre-operation counts
3. Changes output order to show drop confirmation first, then updated stash count (or nothing if count didn't change)
4. Updates tests to verify the new output format and count accuracy

The solution now affects multiple stash subcommands (`pop`, `drop`, `branch`, `store`, `push`, `save`) that can change stash counts. The implementation avoids environment variable hacks by using the existing `--no-show-stash` flag, as suggested in thread discussion.

Test changes demonstrate the new behavior where stash counts reflect post-operation state rather than pre-operation state. The output format is now "Your stash now has X entries" shown after the operation completes, only when the count actually changed.
