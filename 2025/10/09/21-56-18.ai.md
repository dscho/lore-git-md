Documentation update for pack index v3 format as part of the SHA-1/SHA-256 interoperability series. This patch focuses specifically on expanding the pack index v3 documentation to use 8-byte integers for offsets and lengths, addressing potential limitations with the current 4-byte approach.

Key technical details:
- Changes 4-byte integers to 8-byte for offset/length fields to support repositories with over 67 million objects (current limit with 4-byte fields)
- Clarifies checksum handling - uses full-length main hash (32-byte SHA-256 or 20-byte SHA-1) for both packfile checksum and index checksum
- Explicitly documents "full main hash" terminology for the repository's primary algorithm
- Maintains backward compatibility with existing pack index v2 behavior for SHA-256 checksums
- Justifies design choices around checksum length (avoiding truncation debates, compliance requirements)

The changes reflect practical considerations for very large repositories while maintaining consistency with existing hash handling. The documentation updates align with Junio's previous feedback on object ID computation in this series. Since pack index v3 isn't yet implemented, these format changes can be made without compatibility concerns.
