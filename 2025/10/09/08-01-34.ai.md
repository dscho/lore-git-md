Refactoring patch series finalizing packfile store API cleanup.

This v2 series from Patrick Steinhardt concludes the packfile store API refactoring work, building on Taylor Blau's earlier review and approval. The core change is renaming `packfile_store_get_all_packs()` to `packfile_store_get_packs()` to eliminate confusion with the now-removed `get_packs()` variant. The series systematically converts all callers across 20+ files to use the standardized iteration pattern.

Key technical changes include:
- Introducing `repo_for_each_pack()` macro to simplify pack iteration (patch 5)
- Removing the deprecated `packfile_store_get_packs()` function (patch 4)
- Renaming `packfile_store_get_all_packs()` to `packfile_store_get_packs()` (patch 6)
- Converting various subsystems (gc, grep, pack-objects) to use the new patterns

The changes touch core pack operations, maintenance commands, object lookup paths, and grep's pack preloading. Patrick addresses Taylor's concern about potential merge conflicts by noting any new code using the old `get_packs()` would likely be incorrect due to its previous stateful behavior. The series demonstrates callers now properly handle MIDX'd packs.

This is a well-executed conclusion to the pack iteration cleanup, with thorough conversion of all call sites and clear technical rationale for the final naming choice. The work maintains backward compatibility while improving API clarity for future development.
