This thread addressed a clang compiler warning in the refs backend code, where `-Wunreachable` incorrectly flagged code guarded by `!create_ref_symlink()` as unreachable on platforms without symlink support. Johannes Schindelin proposed the fix, with Junio Hamano and Patrick Steinhardt weighing in.

The discussion converged on using Git's existing `NOT_CONSTANT()` pattern to suppress the warning, with agreement that the underlying `core.preferSymlinkRefs` functionality should be deprecated in Git 3.0. While two technically equivalent implementations were possible - either at the callsite or in the macro definition - Johannes has now decided to keep the workaround at the callsite in `create_symref_locked()`, maintaining the original patch structure. This concludes the technical discussion, with all participants aligned on both the immediate solution and the longer-term direction to remove this legacy symlink handling code.
