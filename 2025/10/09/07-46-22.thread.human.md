The thread addresses a clang compiler warning in `refs/files-backend.c` where code guarded by `!create_ref_symlink()` triggers a false positive `-Wunreachable` warning on platforms with `NO_SYMLINK_HEAD` defined. Johannes Schindelin proposed using the existing `NOT_CONSTANT()` macro pattern to suppress the warning while preserving its usefulness for genuinely unreachable code - a minimal 7-line change that maintains identical runtime behavior.

Junio Hamano acknowledged the technical correctness of the fix but suggested a longer-term direction: deprecating `core.preferSymlinkRefs` configuration since all platforms should handle text-file HEAD references even without symlink support. While this would be a change for Git 3.0, he approved the warning-suppression approach as a reasonable interim solution. The discussion touches on platform-specific behavior, compiler warnings, and configuration philosophy, making it relevant for both build-system maintainers and refs backend developers.
