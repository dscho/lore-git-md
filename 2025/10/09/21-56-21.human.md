Documentation patch clarifying pack format details, part of brian m. carlson's SHA-1/SHA-256 interoperability series. This patch improves the pack format documentation by addressing several ambiguous areas that could confuse contributors or implementers working with Git's storage formats.

The changes specify exactly what data CRC32 checksums cover (entire packed object including headers and compressed data) and which CRC32 variant is used (zlib's algorithm). It clarifies that packed objects don't store the loose-object-style "<type> <size>\0" prefix, though this prefix is still used in object ID computation. The patch also documents that size fields represent uncompressed sizes - for undeltified objects this means the raw object size, while for deltas it's the uncompressed delta size (excluding base object references).

These documentation improvements provide valuable precision for anyone working with Git's packfile internals, particularly those implementing alternative Git clients or storage backends. The changes are well-motivated and clearly explained in both the commit message and the actual documentation additions. As part of the larger hash interoperability effort, these clarifications help establish a solid foundation for future work on the storage layer.
