Bugfix for `git stash pop` output when `status.showStash` is enabled, addressing confusing status messages about stash counts. This is the second version of the patch, incorporating feedback from Karthik Nayak and Junio C Hamano.

The patch fixes a UI issue where running `git stash pop` with `status.showStash` enabled would show both a pre-pop stash count ("Your stash has X entries") and drop confirmation, creating redundant and potentially contradictory output. The new behavior shows the drop confirmation first, followed by an accurate post-pop count (or nothing if no stashes remain).

Key changes in v2:
- Uses the `--no-show-stash` flag internally rather than environment variables
- Shows stash counts only when they actually change
- Applies the fix to all stash operations that modify the stash count (pop, drop, branch, store, push, save)
- Includes comprehensive test updates to verify the new output format

The implementation tracks the previous stash count to determine when to show updates, and the output now clearly reflects the state after the operation completes. This makes the behavior more intuitive while maintaining all existing functionality.
