This is a feature patch introducing a new config option for commit-graph changed-path Bloom filters, with performance implications for large repositories.

The patch adds a `commitGraph.changedPaths` config option that controls whether changed-path Bloom filters are written by default during `git commit-graph write`. The config can be set to true (equivalent to `--changed-paths`), false (disables the config but preserves existing filters), or left unset (default). Command-line options retain precedence over the config. The change is motivated by the feature's proven stability and performance benefits in large monorepos, particularly for file history computations.

The implementation includes documentation updates, config handling in commit-graph.c, and adds the config to Scalar's recommended settings for large repositories. The patch includes thorough test coverage in t5318-commit-graph.sh that verifies the config's interaction with command-line options and existing filters. The tests demonstrate that command-line flags override the config, that the config properly enables filter writing, and that existing filters persist through config changes.

Key technical details: The config is implemented via a new `enable_changed_paths` field in the commit-graph options struct, with values 1 (enable), -1 (disable), and 0 (unset). The Scalar integration sets this as an optional recommended config, suggesting it for large repositories where the performance benefits would be most noticeable. The patch maintains backward compatibility with existing behavior while providing a more convenient configuration mechanism for automated maintenance tasks.
