This is a documentation patch that modernizes the `git-tag` man page to properly reflect support for multiple cryptographic signature types (PGP, X.509, SSH) rather than focusing exclusively on GPG. It's part of Christian Couder's series to achieve signature handling parity between `git fast-import` and `git fast-export`.

The patch systematically updates all sections of the man page to use more inclusive terminology ("cryptographic signature" instead of "GPG signature") and properly documents how the `gpg.format` configuration variable controls the signing backend. Key changes include updating the NAME section to remove GPG-specific wording, expanding the DESCRIPTION to explain backend selection, and clarifying how signing keys work across different formats in the OPTIONS and CONFIGURATION sections.

The changes align with Patrick Steinhardt's earlier suggestion to use "cryptographic signature" terminology consistently. The patch maintains all existing functionality while making it clearer that multiple signature types are supported. This documentation update serves as groundwork for the subsequent patches in the series that implement the actual signature handling improvements in the fast-import/export commands.

Technical details include updates to the signing key configuration documentation (now showing `<key-id>` instead of `<gpg-key-id>`), explicit mention of the `gpg.<format>.program` configuration variables, and proper cross-references to git-config(1) for backend-specific details. The patch follows the project's documentation conventions while expanding coverage of the supported signature types.
