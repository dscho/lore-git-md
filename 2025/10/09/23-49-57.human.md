This is a bugfix patch addressing timezone validation in `fast-import.c`, submitted by an Outreachy participant. The patch improves the validation of timezone offsets in commit timestamps during fast-import operations.

The existing code had a `NEEDSWORK` comment noting that the timezone validation was incomplete - it only checked for offsets greater than 1400 (14 hours) but didn't verify other invalid cases like minutes >= 60 or non-15-minute increments. The patch implements these additional checks by:
1. Splitting the timezone offset into hours and minutes components
2. Adding validation for minutes being < 60
3. Ensuring minutes are in 15-minute increments (matching Git's standard timezone format)

The changes are straightforward and focused, though the commit message could benefit from more context about why these particular validation rules matter. The patch appears to be a solid improvement to the existing validation logic, addressing a known limitation marked by the `NEEDSWORK` comment.
