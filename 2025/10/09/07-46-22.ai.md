This is a platform compatibility patch addressing a clang compiler warning. The change deals with a situation where code guarded by `!create_ref_symlink()` becomes unreachable when `NO_SYMLINK_HEAD` is defined, since the function is hardcoded to return `-1` in that case. While this is intentional behavior (the code remains reachable on platforms without `NO_SYMLINK_HEAD`), clang's `-Wunreachable` warning flags it as problematic.

The solution borrows a technique previously used in commit 82e79c63642c, introducing the `NOT_CONSTANT()` macro to trick the compiler into not analyzing the unreachability. This maintains the warning's usefulness for genuinely unreachable code while silencing the false positive in this specific case. The patch modifies `refs/files-backend.c` with a 7-line addition and 1-line deletion, adding a comment explaining the workaround.

The change is straightforward and appears well-justified, addressing a compiler-specific issue without affecting runtime behavior. The commit references prior art for the solution approach, suggesting this is a known pattern in the codebase. The patch maintains the existing behavior while making the build cleaner under clang.
