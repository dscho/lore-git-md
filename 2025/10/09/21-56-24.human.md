This is a bugfix and documentation patch in brian m. carlson's SHA-1/SHA-256 interoperability series, specifically improving GPG signature header validation in tags.

The patch enhances `git fsck` to properly validate `gpgsig` and `gpgsig-sha256` headers in tag objects, which were being ignored by default but could trigger errors in strict checking modes. The changes include:

1. New error messages for malformed signature headers (`badGpgsig`) and truncated continuation lines (`badHeaderContinuation`), documented in `fsck-msgids.adoc`
2. Core validation that checks for complete signature blocks and properly formatted continuation lines
3. Comprehensive tests verifying both valid and rejection cases, including tests that work with both SHA-1 and SHA-256 repositories via the test OID cache

The changes are well-motivated by the series' broader goal of hash algorithm compatibility, as signature headers need consistent handling regardless of the hash algorithm in use. The implementation looks thorough, with clear error messages and good test coverage that exercises both success and failure paths. This appears to be a straightforward improvement that closes a small but meaningful gap in tag validation.
