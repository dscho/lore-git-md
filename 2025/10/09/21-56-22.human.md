This is a documentation patch in brian m. carlson's SHA-1/SHA-256 interoperability series, adding formal documentation for Git's loose object storage format. The patch introduces a new `gitformat-loose.adoc` file that clearly explains how loose objects are structured and stored.

The documentation covers the key aspects of loose object storage: the prefix format (type, size, and null byte), zlib compression, object ID calculation, and the directory sharding scheme used to avoid filesystem performance issues. It includes concrete examples showing both the empty tree object and a simple blob, demonstrating the format in both SHA-1 and SHA-256 contexts.

This patch fills a notable gap in Git's documentation - while loose objects are fundamental to Git's storage model, their format wasn't previously documented in the official manuals. The explanation is thorough yet accessible, with clear technical details that will help developers understand and work with the storage layer.

As part of the larger hash algorithm interoperability effort, this documentation provides important baseline knowledge that will help contributors understand subsequent changes to object storage handling. The patch has already been reviewed and approved by Junio Hamano, indicating it meets Git's documentation standards.
