Test infrastructure patch improving GPG-related test prereq handling.

This patch refactors the setup of the `$GNUPGHOME` directory in `t/lib-gpg.sh` to make test prereqs more flexible. The key change introduces a new `prepare_gnupghome()` helper function that safely creates the directory with `mkdir -p` and updates most test prereqs (GPG, GPGSM, GPGSSH) to use it. This fixes an issue where tests could fail if `$GNUPGHOME` already existed when the GPG prereq ran after GPGSM or GPGSSH.

The patch documents that this helper should be used for all GPG-related prereqs, though it notes a `NEEDSWORK` comment explaining why it can't yet be used for the GPG2 prereq due to exposing a hidden bug in `t1016-compatObjectFormat.sh`. The change builds on prior investigation by Todd Zullinger and Collin Funk about how different GPG variants handle directory creation (GPG/GPGSM auto-create default directories while GPGSSH requires explicit creation).

This is part of Christian Couder's series to improve signature handling in fast-import/export, but the test infrastructure changes stand on their own. The patch maintains backward compatibility while making the test setup more robust, though it leaves the GPG2 case as a known issue to be resolved separately. The changes are straightforward and well-explained, with clear documentation of both the improvement and the remaining limitation.
