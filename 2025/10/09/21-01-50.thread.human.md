This thread centers on adding a `commitGraph.changedPaths` config option to control whether commit-graph Bloom filters are written during `git commit-graph write`. Taylor Blau initiated the discussion, with Junio Hamano and Derrick Stolee providing key review feedback. The feature is particularly relevant for large monorepos like Microsoft's Office repository, where new contributor Emily Yang is working on optimizations.

The design has evolved to clarify an important distinction: while the command-line `--no-changed-paths` flag removes existing filters, setting the config to `false` merely prevents writing new filters while preserving existing ones. Junio emphasized the need for clear documentation of this asymmetric behavior, which Derrick Stolee justified technically. Emily Yang has now submitted a second version of the patch that thoroughly documents these behaviors and adds comprehensive test coverage in t5318-commit-graph.sh. The patch also integrates the config as a recommended setting in Scalar for large repositories.

The current implementation uses three states (-1/0/1) in the `enable_changed_paths` field and ensures command-line options always override the config. All edge cases around config precedence and filter preservation are now explicitly documented. With the documentation concerns addressed and test coverage expanded, this feature appears ready for merging, pending any final feedback. Emily's upcoming work in the Office monorepo will serve as real-world validation of the design's effectiveness at scale.
