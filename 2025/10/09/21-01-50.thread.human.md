Taylor Blau proposed adding a `commitGraph.changedPaths` config option to control whether commit-graph writes include changed-path Bloom filters, which speed up file history operations in large repositories. The initial implementation allowed true/false/unset states while maintaining backward compatibility, with command-line flags overriding the config. Scalar integration suggests this is particularly useful for large monorepos.

Junio Hamano has now provided detailed feedback on the design and implementation. He argues the config should be fully symmetric - setting it to false should explicitly disable the feature, not just defer to defaults, to future-proof against any default behavior changes. He also questions the use of -1/0/1 values in the implementation, suggesting a simpler boolean approach would be more conventional. While acknowledging the feature's value, Junio wants the design cleaned up to better follow Git's standard configuration processing patterns (default -> config -> env -> command line) before merging.

The thread now awaits Taylor's response addressing these points, particularly around handling the false case and simplifying the implementation. Junio's review suggests the feature is conceptually sound but needs refinement to meet Git's configuration conventions.
