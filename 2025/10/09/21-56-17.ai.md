Feature and documentation series continuing SHA-1/SHA-256 interoperability work, part 1 of several planned series targeting Git 3.0. This installment focuses on documentation improvements and test infrastructure groundwork while deferring some implementation changes to future parts.

The series begins with comprehensive documentation updates covering pack index v3 format (now with clarified object ID computation details), tag signature handling (matching behavior since Git 2.29), and introduces new `gitformat-loose.adoc` for loose object storage. The documentation improvements address previously incorrect or missing specifications, particularly around pack formats and interoperability requirements.

Key technical additions include a new `rev-parse --show-object-format=compat` plumbing command to report compatibility hashes, enhanced `fsck` validation for GPG signature headers in tags (including continuation lines), and test infrastructure supporting `GIT_TEST_DEFAULT_HASH="sha256:sha1"` syntax. The test suite gains `COMPAT_HASH` and `BROKEN_OBJECTS` prerequisites for interoperability testing, with `t1010-mktree.sh` modified to properly handle broken object tests in compatibility mode.

Notable changes from v2 include refined pack format wording (incorporating Junio's suggestions), removal of loose object map documentation (deferred to later), and dropping an unnecessary `RUST` prerequisite. The series shows careful attention to documentation accuracy and test coverage, with all storage format documentation (pack v3, loose objects) now Junio-approved. While full compatibility mode testing remains impractical currently, these prerequisites enable incremental test improvements toward that goal.
