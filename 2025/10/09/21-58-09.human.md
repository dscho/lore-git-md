This is a discussion about deprecating the `--committer-date-is-author-date` option in `git-rebase` while keeping it for `git-am`, with ongoing refinement of the documentation changes.

Junio C Hamano responds to Kristoffer Haugsbakk's suggestion about adding a stderr warning for the option in `git-rebase`. He points out practical limitations: stderr messages would get buried in other progress output during normal rebase operations, and would be completely hidden during interactive rebase (`-i`) where users first see an editor interface. He implies that adding warnings to the interactive rebase instruction sheet might be more effective.

The exchange shows the maintainers carefully considering how to make the deprecation visible to users while minimizing disruption. The thread has already established that this option makes sense for `git-am` (where it preserves commit IDs when reapplying patches) but is problematic for `git-rebase` (where it can create timestamp ordering violations). This follow-up focuses on implementation details of the deprecation warning strategy.
