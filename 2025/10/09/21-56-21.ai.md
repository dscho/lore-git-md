Documentation patch clarifying pack format details, part of the SHA-1/SHA-256 interoperability series. This patch focuses on improving the technical documentation of pack file formats to aid implementers and contributors working with Git's storage layer.

The changes add several key clarifications to `gitformat-pack.adoc`:
1. Explicitly states that CRC32 checksums cover the entire packed object (including headers, base references, and compressed data) and specifies the zlib CRC32 algorithm is used
2. Documents that packed objects omit the type/size prefix found in loose objects (though this prefix is still used for object ID computation)
3. Clarifies that size fields in packs always represent uncompressed sizes - for undeltified objects this is the full object size, while for deltas it's the delta size (excluding base references)

These changes address potential ambiguities that could confuse developers working with pack formats directly, particularly around checksum coverage, object encoding differences from loose storage, and size field interpretation. The patch maintains the series' focus on precise technical documentation to support hash algorithm interoperability work.
