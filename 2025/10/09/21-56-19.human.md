This is a documentation patch in brian m. carlson's SHA-1/SHA-256 interoperability series, specifically addressing the pack index v3 format. The patch changes how offsets are ordered in the pack index documentation to better match actual usage patterns in Git's code.

The current pack index v3 format describes offsets being looked up by shortened object ID order, but most Git operations actually need to find objects by pack order. This creates an inefficient indirection where the code has to perform multiple lookups to get from pack order to the actual offset. The patch updates the documentation to reflect that offsets should be looked up by pack order instead, which better matches how the code works and improves cache efficiency.

This change aligns with the series' broader goal of improving hash algorithm compatibility documentation. The patch is straightforward - it modifies just one documentation file with a clear explanation of why the change makes sense. The commit message provides good technical rationale for the change, noting it eliminates the need for the revindex with pack index v3 and makes operations more efficient.
