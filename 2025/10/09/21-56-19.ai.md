Documentation update for pack index v3 format in the SHA-1/SHA-256 interoperability series. This patch changes how offsets are ordered in the pack index v3 documentation to better match actual usage patterns.

The key change is reordering the offset table to use pack order rather than shortened object ID order. The commit explains this makes operations more efficient by allowing direct lookup of pack offsets without needing intermediate object ID lookups. This eliminates the need for a reverse index with pack index v3 and improves cache usage.

Technical details:
- Updates `hash-function-transition.adoc` documentation
- Changes offset table description to specify pack order indexing
- Maintains same 4-byte offset format with 31-bit values and MSB encoding for large offsets
- Keeps 8-byte offset table for large packs (>2GiB)
- Part of broader pack format documentation improvements in this series

The change reflects actual code usage patterns where pack order lookups are more common than shortened ID lookups. This appears to be a well-considered documentation update that matches implementation realities, continuing the series' careful attention to pack format specifications.
