This is a review response from Junio Hamano on Emily Yang's feature patch introducing the `commitGraph.changedPaths` config option for commit-graph changed-path Bloom filters.

Junio agrees with the overall goal of making changed-path Bloom filters more accessible via config rather than requiring explicit `--changed-paths` flags. However, he raises several substantive concerns about the implementation details.

The main technical critique focuses on the config handling logic. Junio argues the current implementation's use of -1/0/1 values for `enable_changed_paths` is unnecessarily complex, suggesting a simpler boolean approach would better match Git's standard configuration patterns. He outlines the conventional precedence flow (hardcoded default -> config -> env -> command line) that the patch should follow.

Junio also questions the documentation phrasing, noting the description of how `false` interacts with `--no-changed-paths` could confuse users. He provides clearer mental models for how config values should behave, including considering future default changes.

While supportive of the feature's goals (especially for large monorepos like Microsoft's OMR), Junio suggests the implementation may need refinement to match Git's configuration conventions. His tone is constructive but firm, treating this as a teaching opportunity for a new contributor while maintaining high standards for core functionality.

The review doesn't block the feature but signals it needs revision, potentially including a preliminary cleanup of the existing option parsing before adding the new config option.
