Const correctness fix in patch-id comparison logic.

This is a small refactoring patch from an Outreachy participant that addresses a const correctness warning in the `patch_id_neq()` function in patch-ids.c. The function takes a callback data parameter that was being cast to a non-const `diff_options` pointer, despite the parameter being marked as const in the function signature. The patch simply makes the local variable const to match.

The change is straightforward and appears correct - it maintains the same behavior while properly respecting the const contract. The original code even had a NEEDSWORK comment acknowledging this issue. The patch touches only one line in a single file, modifying how the comparison callback handles its data parameter.
