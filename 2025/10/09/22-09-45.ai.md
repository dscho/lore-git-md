This is a discussion response in the ongoing `git repo stats` feature series, specifically addressing feedback on patch 4/7 (the core reference counting implementation). Justin Tobler clarifies the command's design philosophy in response to Junio Hamano's questions about actionable metrics and output formats.

Key technical points from the response:
- Defends including historical metrics even if not immediately actionable, arguing they provide valuable insight into repository performance characteristics
- Plans to add "level of concern" indicators in a future series, which would pair metrics with suggested remediation
- Confirms machine-readable output formats (key-value and NUL-delimited) are coming later in this series
- Agrees to change column width storage from `size_t` to `int` since values are small and used with `%*s` format strings
- Maintains that terminal-friendly ASCII table output remains valuable despite potential for HTML/CSV formats later

The discussion reveals philosophical differences:
- Junio emphasizes actionable metrics with clear remediation paths
- Justin prioritizes comprehensive visibility into repository structure, seeing diagnosis as separate from remediation
- Both agree the command could evolve to include more sophisticated output formats and concern-level indicators

This email doesn't introduce new code changes but provides important context for the series' direction, particularly around which metrics are considered valuable and how they might be presented to users. The response indicates Justin will incorporate some of Junio's feedback (like the `int` change) while maintaining the broader vision for the command's informational role.
