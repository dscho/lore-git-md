This is a documentation patch that's part of the ongoing SHA-1/SHA-256 interoperability work. It updates the specification for the proposed pack index v3 format to use 8-byte integers for file offsets instead of 4-byte ones, addressing potential limitations with very large repositories that might exceed 2^32 objects. The change anticipates future repositories with extremely high commit counts (the patch mentions existing repos with 55 million commits).

The documentation also clarifies that checksums will use the full length of the repository's primary hash algorithm (32 bytes for SHA-256, 20 for SHA-1) rather than truncating them. This decision is motivated by practical considerations - it matches existing pack index v2 behavior for SHA-256 and simplifies the code - while also avoiding potential security compliance issues that might arise from hash truncation.

The patch is well-justified with clear reasoning about both the size limitations and checksum choices. It's part of a larger series (1/9) that's already received Junio's approval on key documentation points. While the pack index v3 implementation isn't in Git yet, this documentation change helps future implementations get the format right from the start.
