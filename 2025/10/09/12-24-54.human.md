This is a test infrastructure patch that improves GPG-related test prereq handling in the `t/lib-gpg.sh` script. It's part of Christian Couder's series to add signature handling parity between `git fast-import` and `git fast-export`.

The patch refactors the creation of the GPG home directory (`$GNUPGHOME`) into a new `prepare_gnupghome()` function that uses `mkdir -p` to avoid failures when the directory already exists. This allows test scripts to list GPGSM or GPGSSH prereqs before GPG prereq without issues. The directory creation was previously duplicated in multiple places with potential race conditions.

A notable limitation is that this new function can't yet be used for the GPG2 prereq due to an existing bug in `t1016-compatObjectFormat.sh` that would be exposed by the change. The patch documents this with a NEEDSWORK comment pointing to the known issue.

The change builds on prior work by Todd Zullinger and Collin Funk investigating GPG-related test infrastructure. It's a clean, focused improvement that makes the test setup more robust while explicitly noting an area that needs future attention. The patch appears well-considered with clear commit message explanations and proper attribution to collaborators.
