Follow-up discussion about `--committer-date-is-author-date` documentation warnings. Phillip Wood responds to Kristoffer Haugsbakk's patch that added warnings about timestamp ordering violations when using this option in `git-am` and `git-rebase`.

Wood agrees the warnings are useful but questions the option's rationale in `git-rebase`, suggesting it may have been a mistake to port it from `git-am`. He notes that rebasing typically involves newer base commits, making timestamp violations more likely. The discussion reveals tension between the option's original purpose (consistent commit IDs for emailed patches) and its current broader usage.

Several technical suggestions are made for improving the documentation:
- Clarify the reference to clock skew in `git-rev-list`
- Replace "lie" with "override" for more neutral language
- Adjust phrasing from "applying commits" to "rebasing commits" for the rebase documentation
- Add a warning about using the option with interactive rebase

Wood supports the documentation improvements but hints at potentially deprecating the option for rebase in the future. The exchange highlights how historical features can persist beyond their original use cases, creating potential pitfalls for users unaware of the underlying assumptions they violate.
