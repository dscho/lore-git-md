This is the first part of a multi-series effort to support SHA-1/SHA-256 interoperability, focused on documentation updates and test infrastructure preparation. The series lays groundwork for Git 3.0 by improving documentation of pack formats and loose object storage, while adding test prerequisites for future compatibility testing.

The patch series starts with several documentation improvements: clarifying the pack index v3 format (including object ID computation details), updating tag signature documentation to match current behavior, and introducing new documentation for loose object storage. These changes come from the author's deep dive into the pack code and aim to correct inaccuracies while making the formats more understandable.

A key addition is the `gitformat-loose.adoc` document, which will eventually include loose object mapping details. The series also adds a `rev-parse --show-object-format=compat` plumbing command and enhances `fsck` to properly validate GPG signature headers in tags.

For testing, the series introduces compatibility hash prerequisites (`COMPAT_HASH` and `BROKEN_OBJECTS`) that will allow future patches to test interoperability scenarios. The changes include modifications to `t1010-mktree.sh` to properly handle broken object tests in compatibility mode.

The author notes that while full compatibility testing isn't yet possible (as many tests would still fail), these prerequisites will enable incremental improvements. The series has already incorporated feedback from Junio C Hamano and Patrick Steinhardt, particularly around documentation clarity and test infrastructure.

This appears to be a well-structured foundational series with thorough documentation updates and careful attention to test infrastructure - exactly what you'd want to see when preparing for a major compatibility change like SHA-1/SHA-256 interoperability. The changes are focused and incremental, with clear explanations of both the current state and future direction.
