Packfile API refactoring in the maintenance subsystem. This patch converts `builtin/gc.c`'s incremental repack auto-condition check from using `packfile_store_get_packs()` to `packfile_store_get_all_packs()`, as part of the broader packfile store API cleanup series.

The change affects how Git counts non-MIDX'd packfiles when deciding whether to trigger an incremental repack during maintenance. The patch leverages the fact that the function already explicitly filters out MIDX'd packs, making the switch to the more comprehensive `get_all_packs()` safe despite its name suggesting it would include all packs. This is a straightforward mechanical change that maintains the existing behavior while aligning with the series' goal of eliminating the stateful `get_packs()` function.

Key technical details: the modification touches the pack counting logic in `incremental_repack_auto_condition()`, where the iteration now uses the new API while preserving the MIDX exclusion check (`if (!p->multi_pack_index)`). The patch demonstrates the series' principle that callers already handling MIDX cases correctly can safely migrate to the more predictable `get_all_packs()` variant.

This change follows the series' established pattern of first proving safe migration paths before finalizing API names, with Taylor Blau having previously reviewed and approved the technical approach. The one-line diff shows the minimal impact on maintenance behavior while contributing to the larger goal of simplifying pack iteration patterns across the codebase.
