This is a test infrastructure patch in the SHA-1/SHA-256 interoperability series, adding support for testing compatibility hash scenarios.

The patch introduces a way to specify a compatibility hash algorithm when running tests via `GIT_TEST_DEFAULT_HASH="sha256:sha1"` syntax, which will be important for testing repositories that support both hash algorithms. It adds two new test prerequisites: `COMPAT_HASH` to detect when running in compatibility mode, and `BROKEN_OBJECTS` to skip tests that create deliberately broken objects (which won't work in compatibility mode since there's no way to map them).

The changes are focused on the test framework, modifying `test-lib-functions.sh` to parse the new hash syntax and `test-lib.sh` to implement the new prerequisites. This is groundwork for future patches that will actually implement the compatibility mode behavior in Git itself. The patch appears well-considered, with clear explanations of why these changes are needed and how they'll be used. It's part of a larger, carefully planned effort to support SHA-256 repositories while maintaining SHA-1 compatibility.
