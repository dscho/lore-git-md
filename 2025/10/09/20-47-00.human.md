Documentation follow-up discussing potential deprecation of `--committer-date-is-author-date` for `git-rebase`.

Kristoffer Haugsbakk is considering next steps for the documentation patch about the problematic `--committer-date-is-author-date` option. Building on Phillip Wood's suggestion that the option makes less sense for `git-rebase` than for `git-am`, Kristoffer proposes two potential enhancements: (1) explicitly marking the option as deprecated for rebase in the documentation, and (2) adding a stderr warning when the option is used with rebase.

The email raises an interesting implementation question about why Git typically avoids stderr warnings in rebase operations, speculating it might relate to tools parsing stderr output. This suggests the patch may need to consider both user-facing documentation changes and deeper behavioral questions about how Git surfaces warnings during rebase operations.

The discussion continues to focus on distinguishing between valid `git-am` use cases (where the option helps preserve commit IDs when reapplying patches) versus questionable `git-rebase` usage (where it often creates timestamp ordering violations). No new objections to deprecation have emerged since Phillip's initial suggestion.
