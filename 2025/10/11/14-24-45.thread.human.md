This thread discusses improving Git's CI whitespace checking to detect files missing trailing newlines, which the current `git log --check` doesn't catch. The proposal comes from an Outreachy applicant who suggests enhancing the `ci/check-whitespace` script to examine modified files directly.

The idea is technically sound - checking file contents for missing newlines would catch issues the log-based approach misses. However, the initial email is light on implementation details, particularly around efficiently scanning all modified files across commit ranges. The author is seeking feedback before proceeding with implementation, positioning this as a potential microproject for Outreachy.

As an RFC, this shows good engagement with Git's infrastructure, but the proposal would benefit from more concrete technical specifics in follow-up messages, particularly around performance considerations and edge cases in the file examination approach.
