This is a brief follow-up in the platform compatibility thread about suppressing a clang compiler warning in the refs backend.

Patrick Steinhardt confirms he has no objections to Johannes Schindelin's preferred approach for handling the clang `-Wunreachable` warning. The discussion had considered two equivalent solutions - modifying the `create_ref_symlink()` macro definition (Patrick's suggestion) versus applying the `NOT_CONSTANT()` workaround at the callsite (Johannes's original patch). 

With this email, Patrick explicitly endorses proceeding with the callsite solution, marking the conclusion of this technical discussion. The thread had already reached consensus that this was the right path forward, with Junio Hamano weighing in to settle the matter. The fix maintains current behavior while properly suppressing the compiler warning on `NO_SYMLINK_HEAD` platforms.

This wraps up the immediate issue, though the broader context includes plans to eventually deprecate the `core.preferSymlinkRefs` configuration option in a future Git release. The exchange demonstrates the project's careful consideration of even minor implementation details when maintaining platform compatibility.
