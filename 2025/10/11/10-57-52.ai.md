This is a follow-up in the CI/build system thread about Ubuntu 25.10's sudo-rs compatibility issues. Patrick Steinhardt responds to Junio C Hamano's suggestions about making the sudo implementation fallback more robust. He explains that the current check for `/etc/alternatives/sudo` is sufficient since no other distros currently have the sudo-rs/sudo.ws split, though he's open to adding an additional check for `/usr/bin/sudo.ws` if preferred. 

The email provides important context about the limited scope of the issue - Ubuntu has dropped 32-bit support (making the i386/ubuntu case irrelevant) and no other distributions currently face this sudo implementation split. Patrick mentions an upcoming patch series to migrate the 32-bit CI job to i386/debian instead. 

The technical discussion focuses on the detection logic in `ci/install-dependencies.sh`, weighing the tradeoffs between different approaches to checking for the traditional sudo implementation. Patrick maintains that while all solutions are somewhat brittle given potential upstream changes, the current version is adequate. The exchange shows the maintainers carefully considering edge cases while working toward a solution that handles the immediate CI breakage without introducing unnecessary complexity.
