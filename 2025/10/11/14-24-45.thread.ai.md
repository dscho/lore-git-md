Proposed CI enhancement for detecting missing newlines at EOF, from Outreachy applicant Bello Olamide. Current `ci/check-whitespace` uses `git log --check` which doesn't catch missing final newlines. Junio Hamano confirmed this limitation and explained the solution must detect when a commit *introduces* the missing newline condition by comparing against parent commits, avoiding false positives on historically non-newline-terminated files.

The discussion has clarified that the solution must handle two cases: commits that remove a terminating newline from existing files, and newly added files that lack a terminating newline from inception. Hamano has endorsed Olamide's understanding of these requirements. The implementation will examine both modified and newly added files in commit ranges, comparing against parents where applicable.

This remains a stopgap CI solution while the more complex core enhancement to `git log --check` itself (with corresponding whitespace configuration support) is deferred.
