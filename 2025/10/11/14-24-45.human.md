This is a proposal for a small improvement to Git's CI infrastructure, specifically the `ci/check-whitespace` script. The author, Bello Caleb Olamide, noticed that the script doesn't currently flag files missing a final newline character, even though this is something `git diff` would normally highlight.

The proposal suggests modifying the script to check each file in a commit range for the presence of a trailing newline. This would make the CI check more thorough by catching the same whitespace issues that `git diff` would show. The author is seeking feedback on whether this would make a good microproject (likely as part of the Outreachy program) and welcomes suggestions on the approach.

The change appears straightforward and well-motivated, addressing a minor but legitimate gap in the existing whitespace checking. The author has clearly done their homework by studying both the mailing list discussion and the current script behavior. This seems like a reasonable quality-of-life improvement for Git's CI system.
