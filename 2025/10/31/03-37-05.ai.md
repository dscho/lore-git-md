This is a bugfix targeting the debug ref backend. The patch addresses an issue where the debug ref backend's `read_raw_ref` function was unnecessarily clearing the OID before attempting to read the reference, causing valid reference reads to appear as failures. 

The problem manifests when running Git commands with `GIT_TRACE_REFS=1`, where operations like `git branch new_branch <commit_id>` would fail because the debug backend would report a null OID even when the underlying reference store successfully read the reference. The fix simply removes the premature OID clearing, allowing the actual reference data to propagate through.

The change is minimal - just a one-line deletion in `refs/debug.c` that removes the `oidcpy` call. This appears to be a straightforward correction of what looks like an oversight in the debug backend's implementation. The commit message clearly explains both the problem and the solution, though it might benefit from mentioning that the debug backend is primarily used for testing and debugging purposes.

This patch doesn't introduce any new tests, but given the nature of the change (removing incorrect behavior in debugging code) and its small scope, that seems reasonable. The fix aligns with the expected behavior of the debug backend properly reflecting the operations of the underlying ref store.
