This is part 4 of a 5-patch series introducing a 'git maintenance is-needed' subcommand to check if maintenance tasks are required without running them. The series builds infrastructure to query ref backend optimization state, with this patch specifically modifying the pack-refs maintenance task's auto-condition logic.

Previously, the pack-refs task would report that optimization was always needed, since there was no way to check without actually performing the optimization. This patch changes that by using the new `refs_optimize_required()` function (added in the previous patch) to properly check if ref optimization is needed. The implementation mirrors the behavior of 'git pack-refs --auto' but only performs the check, not the optimization.

The change involves setting up ref inclusion/exclusion options (checking all refs by default) and properly cleaning up allocated resources. A minor header cleanup is included to remove a duplicate SEEN flag definition that conflicted with including revision.h'.

This is a key piece enabling the new 'is-needed' subcommand, as it provides accurate information about whether ref optimization is actually required. The implementation appears thorough, with the series having already established the backend-specific checking logic in earlier patches.
