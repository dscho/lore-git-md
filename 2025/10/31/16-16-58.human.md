Refactoring patch in the ongoing ODB abstraction effort, specifically addressing naming conventions for the loose object source structure.

This email captures a minor naming discussion between Patrick Steinhardt and Junio Hamano regarding the `struct odb_loose_source` introduced in the ODB abstraction series. Patrick prefers the current naming ("odb_loose_source") for two reasons: it flows more naturally in language (similar to "files source"), and it aligns with existing patterns in the reference backends (like `files_backend`). Junio mildly disagrees, noting that "odb" feels redundant in this context, similar to how "ref" would be redundant when discussing ref backends.

Both maintainers emphasize they don't feel strongly about the naming choice, suggesting this is more of a stylistic discussion than a technical blocker. The exchange shows the careful attention to API design details that characterizes this refactoring series, even for relatively small naming decisions. The thread context indicates this discussion is part of a larger, well-reviewed effort to properly abstract Git's object handling.
