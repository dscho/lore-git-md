This is a discussion about build system integration in the ongoing SHA-1/SHA-256 interoperability series, specifically focusing on whether to maintain multiple static libraries or consolidate into a single `libgit.a`.

Ezekiel Newren responds to Junio Hamano's defense of the multi-library approach, arguing strongly for consolidation. He disputes the claimed developer experience benefits of separate libraries (`libxdiff.a`, `libreftable.a`), stating his own experience has been worse with the current setup. The key technical concern is the maintenance burden of keeping three build systems (Makefile, Meson, Cargo) in sync regarding library organization.

Newren makes a pragmatic case that consolidation would simplify Rust integration (Cargo only needs to link against `libgit.a`), maintain Meson's current behavior, and reduce future maintenance overhead when adding new code. He warns that maintaining separate static libraries would require ongoing coordination across all three build systems. The discussion remains unresolved but represents a key architectural decision point for the project's build infrastructure as it incorporates Rust components.
