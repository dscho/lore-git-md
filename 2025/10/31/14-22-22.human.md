This is a feature patch for the reftable backend, part of a series (2/5) to add functionality around reftable maintenance. It introduces a new function `reftable_stack_compaction_required()` that lets users check if their reftable needs optimization without actually performing the compaction.

Currently, Git's reftable backend automatically compacts tables to keep the stack size manageable, and users can manually trigger compaction via `git pack-refs` or `git refs optimize`. However, there was no way to check if compaction was actually needed first. This patch adds that capability through a new public function that returns a boolean indicating whether compaction would be beneficial.

The implementation checks two conditions: if there are fewer than 2 tables (no compaction needed), and when heuristics are enabled, it uses the existing segment analysis logic to determine if tables could be usefully merged. The patch includes thorough unit test coverage that verifies the function's behavior matches the auto-compaction logic.

This appears to be a well-constructed addition - the commit message clearly explains the motivation, the implementation is straightforward and builds on existing infrastructure, and tests validate the new functionality. It's part of a larger effort to give users more control over reftable maintenance operations.
