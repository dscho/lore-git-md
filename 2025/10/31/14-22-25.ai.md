This is the final patch in a 5-part series introducing a new 'is-needed' subcommand to `git maintenance`. The feature allows users to check whether maintenance tasks are required without actually running them, addressing the current limitation where the heuristics for auto-maintenance are only evaluated during execution.

The patch implements the core functionality by:
1. Adding the 'is-needed' subcommand to `git-maintenance` with support for `--auto` and `--task` flags
2. Reusing existing auto-condition logic from maintenance tasks but returning exit codes (0=needed, 1=not needed) instead of executing
3. Extending documentation to explain the new subcommand's behavior
4. Adding comprehensive tests in t7900 that verify the exit codes match the underlying auto-condition logic for all maintenance tasks

Key technical details:
- The implementation shares the `auto_condition` callbacks from existing tasks
- Returns immediately on first task needing maintenance when checking multiple tasks
- Maintains consistency with existing `--auto` behavior thresholds
- Removes a duplicate test case for worktree-prune task
- Adds new assertions for all maintenance tasks (commit-graph, loose-objects, incremental-repack, reflog-expire, worktree-prune, rerere-gc)

The patch builds on the ref backend optimization infrastructure from earlier in the series while remaining independent of those changes. It provides a foundation for future scheduled maintenance checking and integrates cleanly with the existing maintenance command structure.
