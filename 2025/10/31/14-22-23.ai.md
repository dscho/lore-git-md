This is part 3 of a 5-part series introducing reference backend optimization checks, falling under the feature category. The patch adds a new `optimize_required` field to `struct ref_storage_be` that allows checking whether a reference backend needs optimization before running potentially expensive operations.

The change introduces a new function pointer type `optimize_required_fn` and implements it for all four reference backends (debug, files, packed, and reftable). Each backend gets its own logic: the packed backend always returns false (as packed refs are already optimized), while the files and reftable backends implement actual checks. The reftable implementation in particular checks compaction requirements using the stack's heuristics when auto-optimization is requested.

The patch is well-structured with consistent implementation across all backends and includes the necessary plumbing through the refs API layer. It appears to be part of a larger effort to expose optimization capabilities through new `git pack-refs` and `git refs optimize` commands (mentioned as coming in a follow-up commit). The changes touch core refs infrastructure but are focused and don't appear to introduce any obvious risks or controversial design choices.
