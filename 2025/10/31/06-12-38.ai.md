This is a refactoring patch in Patrick Steinhardt's ongoing ODB abstraction series (patch 2/13 in v2). It introduces a new helper function `odb_source_new()` to centralize creation of ODB source objects, replacing three separate initialization patterns in the codebase.

The patch touches `odb.c`, `odb.h`, and `repository.c`, with the key change being the new function that handles allocation and initialization of `struct odb_source` objects. The function takes parameters for the parent ODB, path string, and a `local` flag, then performs the common initialization sequence that was previously duplicated in `link_alt_odb_entry()`, `odb_set_temporary_primary_source()`, and repository initialization code.

The refactoring makes memory ownership clearer by consistently using `xstrdup()` for path strings and consolidates error-prone manual initialization. It also slightly modifies the repository initialization path to use the new helper while maintaining the same behavior. The header file addition exposes the new function for future use.

This appears to be a straightforward quality-of-life change that reduces code duplication without altering functionality, continuing the series' pattern of incremental ODB improvements. The changes align with the thread's established direction and have already received positive feedback in prior reviews.
