This is a refactoring patch in the context of the reftable backend optimization work for the new `git maintenance is-needed` subcommand.

Justin Tobler provides a review of Karthik Nayak's patch that modifies how reftable stack compaction segments are determined. The change combines two steps - getting table sizes and determining compaction segments - into a single function call. This prepares for future `is-needed` functionality where we'll want to check if compaction is needed without performing it.

The review notes the change is logically sound but raises a question about error handling: should the new `stack_segments_for_compaction()` function also return the segment size to avoid a follow-up `segment_size()` call? This suggests the implementation could be made slightly more robust, though the current approach appears correct.

The patch is part of a larger series (1/5) that's already been discussed and appears to be on track for inclusion, with this being a relatively straightforward internal API improvement. The review is constructive and focused on potential refinements rather than fundamental issues.
