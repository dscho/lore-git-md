This is a feature patch for the reftable backend, part of a series introducing functionality to check if optimization is needed before performing compaction. The patch adds a new public function `reftable_stack_compaction_required()` that allows users to query whether the reftable stack needs compaction, without actually performing it.

The implementation provides both a simple check (when `use_heuristics` is false, it always returns true if there are 2+ tables) and a heuristic-based approach (when `use_heuristics` is true) that evaluates the actual segment structure. The function returns its result through an out-parameter `required` and follows the reftable error handling pattern.

The patch includes unit test updates that verify the new function's behavior in the context of auto-compaction scenarios. Tests check both the function's return value and the `required` output parameter across different stack states, including edge cases with small numbers of tables.

This appears to be a well-contained addition that follows existing patterns in the reftable code. The commit message clearly explains the motivation (allowing users to check optimization need without performing it) and the implementation approach. The patch includes appropriate test coverage and maintains the existing error handling conventions.
