Refactoring patch in Patrick Steinhardt's ODB abstraction series, specifically renaming a function to match the new naming scheme. This is part 10/13 in the v2 series that's been under active review.

The patch renames `has_loose_object()` to `odb_loose_source_has_object()` to better reflect its role in the object database abstraction. The change is mechanical but important for consistency with the new ODB interface patterns being established. The function checks for loose object existence without respecting replace references, and the rename makes clear its tight coupling to the loose object source component of the ODB.

Changes affect three files: object-file.[ch] (where the function is declared and implemented) and builtin/pack-objects.c (where it's called). The implementation remains identical - this is purely a naming update. The commit message notes this matches "our modern naming schema," referring to the ongoing standardization effort in the ODB work.

The patch continues the series' pattern of careful, incremental refactoring that maintains behavior while improving architectural clarity. It follows naturally from previous patches that established the `odb_loose_source` naming convention and moved related functionality. Reviewers have generally approved the technical direction of these changes, with naming conventions being the primary point of discussion in earlier patches.
