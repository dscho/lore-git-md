This is a discussion about Rust version compatibility in the ongoing cbindgen integration series. Patrick Steinhardt responds to Brian M. Carlson's concerns about targeting Rust 1.49 for gcc-rs compatibility, noting that gcc-rs development is progressing and may soon support newer versions (up to 1.80). While open to considering a more recent version like 1.63 as Carlson proposes, Steinhardt seeks clarification on why that specific version was chosen, preferring to make the version decision intentionally rather than arbitrarily.

The exchange highlights the tension between supporting older platforms through gcc-rs (which requires older Rust versions) versus enabling broader platform support through LLVM-based toolchains (which need newer Rust). This is a key decision point for the project's Rust infrastructure, with implications for both current and future platform compatibility. The discussion remains constructive, with both sides showing willingness to find a solution that balances these concerns.
