Reftable backend: introducing stack compaction check functionality. Patch series adds `reftable_stack_compaction_required()` public function to query whether reftable stack needs compaction without performing it. Implementation provides both simple check (returns true for 2+ tables when `use_heuristics=false`) and heuristic-based evaluation of segment structure (when `use_heuristics=true`). Follows reftable error handling pattern with result returned via out-parameter `required`. Includes unit tests verifying behavior in auto-compaction scenarios, checking both return value and output parameter across various stack states including edge cases with small table counts. Well-contained addition maintaining existing patterns, with clear commit message explaining motivation (check optimization need without performing compaction) and implementation approach.
