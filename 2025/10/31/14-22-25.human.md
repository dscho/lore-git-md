Feature addition to `git maintenance` for checking task requirements without execution.

This final patch in Karthik Nayak's series introduces the promised 'is-needed' subcommand to `git maintenance`, allowing users to check whether maintenance tasks should run without actually executing them. The subcommand works with both the `--auto` flag (to check repository state against maintenance thresholds) and `--task` (to check specific tasks). It returns exit code 0 when maintenance is needed, 1 otherwise.

The implementation builds on the infrastructure from earlier patches, reusing the same auto-condition checks that `maintenance run --auto` would perform. The tests demonstrate integration with all existing maintenance tasks (commit-graph, loose-objects, incremental-repack, etc.), showing the subcommand correctly mirrors the decision logic of the run operation. A duplicate test is removed as part of the cleanup.

This provides a useful inspection tool for scripts and users who want to understand maintenance requirements before triggering potentially expensive operations. The implementation appears thorough, with comprehensive test coverage matching the existing maintenance task behaviors. As the culmination of the series, it delivers the promised functionality while maintaining consistency with Git's existing maintenance architecture.
