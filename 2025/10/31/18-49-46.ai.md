This is the final patch in a series implementing atomic reference updates for `git replay`, adding persistent configuration support via `replay.refAction`. The patch introduces a config option that mirrors the existing `--ref-action` command-line flag, allowing users to set their preferred default behavior (atomic updates or pipeline output) in their Git config.

Elijah Newren's review focuses on tightening up the commit message and test hygiene. He suggests:
- Removing redundant implementation details from the commit message that merely restate the code
- Moving test cleanup improvements (like saving/restoring branch states) to earlier patches where they belong
- Avoiding unnecessary examples that just demonstrate standard Git config precedence behavior

The implementation itself is sound and follows Git conventions:
- Command-line `--ref-action` overrides config as expected
- Config parsing uses standard `repo_config_get_string_tmp()`
- Error handling provides clear messages for invalid values
- Tests verify config parsing, defaults, overrides, and error cases
