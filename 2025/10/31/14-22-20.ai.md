This is a cover letter for a feature patch series introducing a new 'is-needed' subcommand to `git maintenance`. The series builds on previous discussion about checking maintenance needs without performing the work, originally proposed as a refs-specific feature but now generalized to maintenance tasks.

The series adds infrastructure to check if reference backends need optimization (commits 1-3), then uses this to implement the new subcommand (commits 4-5). The 'is-needed' command will check maintenance requirements, with optional task-specific checks via '--task', and is designed to work with the existing '--auto' heuristics. Future work could add schedule checking.

Key technical points:
- Adds `optimize_required` field to `struct ref_storage_be` to query backend optimization state
- Implements backend-specific checks for files, packed, and reftable backends
- New reftable stack API `reftable_stack_optimize_required()`
- New `pack_refs_condition()` in maintenance checks ref optimization state
- 'is-needed' subcommand with '--task' filtering
- Tests in t7900 verify basic functionality

The series depends on two other pending topics (kn/refs-optim-cleanup and ps/ref-peeled-tags) but should merge cleanly with next. This appears to be a well-structured implementation of a previously discussed feature, with thorough test coverage across all ref backends.
