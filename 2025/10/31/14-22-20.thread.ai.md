Thread summary:

This thread introduces a new 'is-needed' subcommand for `git maintenance` to check whether maintenance tasks are required without performing them. The series generalizes prior discussion about ref optimization checks into a broader maintenance needs query system. Authored by Karthik Nayak, it consists of 5 patches building infrastructure to check ref backend optimization state (commits 1-3) then implementing the subcommand (commits 4-5).

Technical implementation adds `optimize_required` to `struct ref_storage_be` for backend-specific optimization checks, with implementations for files, packed, and reftable backends. The reftable stack gains `reftable_stack_optimize_required()` API. Maintenance integrates this via `pack_refs_condition()`. The new 'is-needed' subcommand supports `--task` filtering and works with existing '--auto' heuristics. Tests in t7900 cover all backends.

The series depends on two in-flight topics (kn/refs-optim-cleanup and ps/ref-peeled-tags) but merges cleanly with next. Future work could extend to schedule checking. Key participants so far are Karthik Nayak as author and Patrick Steinhardt as reviewer from previous related discussions about ref optimization checks. The implementation appears thorough with complete test coverage across ref backends.
