This thread introduces a new 'is-needed' subcommand for `git maintenance` that allows checking whether maintenance tasks are required without actually running them. Authored by Karthik Nayak, the 5-patch series has evolved through review feedback and is now technically complete.

The implementation builds on ref backend optimizations (patches 1-3) that improve reftable compaction checking and expose the functionality through the refs subsystem. Patch 4 integrates this with the maintenance machinery by modifying `pack_refs_condition()`. The final patch adds the user-facing 'is-needed' command with support for `--auto` heuristics and task filtering, returning exit status 0 when maintenance is needed and 1 otherwise.

The series has been reviewed by Patrick Steinhardt and Justin Tobler, with all technical points addressed. The implementation cleanly reuses existing task infrastructure while adding the new functionality, including comprehensive tests covering all maintenance tasks and their configurations. With the reviews in place and dependencies expected to be resolved, the series appears ready for Junio to consider queuing for the next release.
