Karthik Nayak has completed a 5-patch series introducing a new 'is-needed' subcommand to `git maintenance`. This allows checking whether maintenance tasks would run under `--auto` conditions without actually executing them, returning exit code 0 if maintenance is needed and 1 otherwise. The implementation builds on ref backend optimization checks that were generalized earlier in the series.

The subcommand supports `--task` filtering like other maintenance commands and reuses existing auto-condition logic while maintaining consistency with `maintenance run` behavior. In non-auto mode, it currently always returns "needed" (a documented limitation that could be refined later). Comprehensive tests verify integration with all maintenance tasks' auto conditions (gc, commit-graph, loose-objects etc.), config handling, and exit code behavior.
