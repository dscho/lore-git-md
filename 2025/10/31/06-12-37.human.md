This is a refactoring patch that fixes a subtle memory ownership issue in Git's alternate object database handling. It's the first in Patrick Steinhardt's 13-part series restructuring loose object handling as part of the object database abstraction effort.

The patch addresses a tricky interaction where paths for alternate object directories were being stored in a map before their memory was properly owned by the object source structure. The original code relied on the path being later detached into the source structure, creating an implicit relationship that was easy to break during refactoring. The new version makes this ownership explicit by first creating the source structure and then storing its path in the map.

The change is relatively small (17 lines added, 13 removed) but touches important object database plumbing. It maintains all existing behavior while making the code more robust against future modifications. The patch has already gone through multiple review iterations, with Karthik Nayak and Junio Hamano providing feedback on earlier versions.

This appears to be a well-justified change that improves code clarity without introducing new behavior. The commit message clearly explains both the problem and solution, making it easy to review. As the first patch in a larger series, it sets up cleaner foundations for the subsequent refactoring work.
