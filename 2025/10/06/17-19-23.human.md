Documentation and interface polish for `git add -p` navigation commands. This is part 1/6 in René Scharfe's v3 series improving interactive hunk selection behavior.

The patch clarifies the help text for the j/J/k/K navigation commands in `git add -p` by removing misleading wording. The old text suggested these commands would "leave this hunk undecided" when in fact they simply move between hunks without changing any hunk's state. The new wording ("go to the next/previous [undecided] hunk") more accurately reflects the commands' behavior.

This change appears in both the user documentation (git-add.adoc) and the in-program help text (add-patch.c). The modification is straightforward and uncontroversial, aligning with the series' goal of making the interactive interface more consistent and understandable. As the first patch in the series, it sets the stage for subsequent behavioral improvements to the navigation system.
