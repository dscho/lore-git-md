This is the cover letter for v3 of a feature series introducing URL-style encoding for submodule gitdir paths to prevent filesystem conflicts, now gated behind a new `extensions.submoduleEncoding` config.

The series has been significantly simplified from v2 by adopting Patrick Steinhardt and Phillip Wood's suggestion to use a repository extension rather than maintaining separate `.git/submodules/` and `.git/modules/` directories. This change allowed removing much of the directory-handling complexity while maintaining the core encoding functionality. The implementation now encodes paths in the existing `.git/modules/` directory when the extension is enabled.

Key technical changes in v3 include:
- New `extensions.submoduleEncoding` config to opt into the behavior
- Removal of the separate `.git/submodules/` directory scheme
- Reintroduction of `validate_submodule_git_dir()` for legacy path checking
- Consolidated test cases in a new `t7425-submodule-encoding.sh` file
- Fixes for unused variables and small bugs identified in v2 review

The series appears well-tested with 162-line test file specifically for the encoding behavior, plus additional coverage in existing submodule tests. Adrian Ratiu notes the CI tests pass except for an unrelated Windows+Meson failure. The implementation maintains backward compatibility while providing a path forward for cross-platform safety.

Review feedback from v2 has been thoughtfully incorporated, particularly around the extension mechanism and directory structure. The cover letter clearly credits contributors (Patrick Steinhardt, Phillip Wood, Kristoffer Haugsbakk, SZEDER Gábor) for their suggestions that shaped this revision. The changes look like a solid iteration that addresses the major technical concerns raised in previous rounds while keeping the core conflict-prevention benefits of the encoding scheme.
