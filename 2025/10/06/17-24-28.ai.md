Bugfix and test enhancement for `git add --interactive` navigation.

This final patch in René Scharfe's v3 series addresses a subtle issue in the interactive add interface where permitted command options were being accumulated across hunk iterations rather than being reset for each new hunk. The fix moves the `permitted` bitmask declaration inside the main loop to ensure each hunk starts with a fresh set of allowed commands based solely on its own context.

The change follows up on feedback from Junio Hamano and maintains the series' focus on consistent behavior across all navigation commands. The implementation now properly resets command availability for each hunk, preventing any carry-over of permissions from previous hunks that might incorrectly enable or disable certain operations.

A new test case verifies this behavior by attempting to use the invalid 's' (split) command on a hunk that cannot be split, confirming that the interface correctly rejects the operation and maintains proper command availability for subsequent hunks. The test checks both the rejection message and the command options presented for the next hunk.

This completes the series' systematic unification of interactive add navigation behavior, with all major feedback from previous rounds incorporated. The patch demonstrates careful attention to edge cases in the interface's state management while maintaining the improved consistency and test coverage established in earlier parts of the series.
