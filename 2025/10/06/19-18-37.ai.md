This is a discussion summary from the Git Contributor's Summit 2025, focusing on history rewriting tools and Change-IDs. The notes cover two main topics: the future of Git's history rewriting interface and the ongoing debate around Change-IDs.

The history rewriting discussion centers on improving user experience, particularly around `git rebase` and the newer `git replay` command. Key points include making rewriting more accessible for new users while maintaining power for advanced workflows, with proposals for a porcelain `git history` command built on `git replay`. Technical challenges include the sequencer's legacy issues (hook interactions, work tree updates) and backward compatibility concerns. There's interest in moving beyond the sequencer but recognition that its cleanup is non-trivial.

The Change-ID discussion reveals deep technical and philosophical disagreements. Change-IDs (deterministic identifiers for logical changes across rewrites) could help with range-diffs and conflict resolution but face challenges around predecessor tracking, protocol changes, and privacy. Key sticking points include: whether to track predecessors explicitly (Mercurial-style), how to handle Change-IDs during rewrites (squash/amend cases), and whether to make them optional. The Gerrit-style commit body embedding approach conflicts with Git's current handling of commit metadata. The discussion suggests Change-IDs could become more useful if Git supported commit headers more generally.

This appears to be an intermediate discussion in a larger thread about Git 3.0 features, connecting to other summit topics like SHA-256 transition and first-class conflicts. The notes capture active design debates without clear resolutions, indicating these are likely to be ongoing discussions rather than imminent changes. The technical depth suggests this is primarily of interest to core contributors working on Git's object model and history manipulation tools.
