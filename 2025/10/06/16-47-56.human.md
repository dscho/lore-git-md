This is a patch in the submodule gitdir path encoding series, adding a config override mechanism for submodule gitdir paths. Junio C Hamano questions the practical utility and potential pitfalls of allowing per-submodule gitdir path overrides via `submodule.<name>.gitdirpath`.

The patch introduces a config option that lets users specify custom paths for submodule gitdirs, bypassing both the legacy path scheme and the new encoding system. While the implementation is straightforward - adding config lookup in `submodule_name_to_gitdir()` and tests - Junio raises concerns about possible path collisions when mixing encoded and unencoded submodule names. He provides a concrete example where a submodule named "%41%42%43" (which would decode to "ABC") could conflict with an actual "ABC" submodule if the encoding scheme is enabled.

The technical implementation looks sound, with proper test coverage including a new helper script for verifying gitdir paths. However, the core question remains whether this flexibility is actually beneficial given the potential for confusion and conflicts. The patch appears to be a holdover from an earlier iteration of the series, and its necessity in the final design is now being re-examined.
