This is a refactoring patch in the reftable fsck validation series, moving a consistency check message from the files backend to the generic refs layer. The change ensures both files and reftable backends will show the same "Checking references consistency" message when fsck runs in verbose mode.

The patch relocates the message printing from `files_fsck_refs()` in `refs/files-backend.c` to `refs_fsck()` in `refs.c`, which serves as the common entry point for all ref backends. This is a straightforward change that improves code organization by eliminating duplicate message printing logic while maintaining identical functionality. The message remains conditional on `o->verbose` as before.

Key technical details include:
- Adds `fsck.h` include to `refs.c` for the `fsck_options` struct
- Keeps the same `fprintf_ln(stderr, _("Checking references consistency"))` call but moves it up the call stack
- Removes the now-redundant message from `files-backend.c`
- Maintains the same behavior where the message only appears in verbose mode

This change is part of the larger reftable fsck validation effort but stands alone as a simple refactoring that benefits both backends. The patch follows the series' pattern of cleaning up refs infrastructure while adding reftable support. Since this is a mechanical change with no behavior difference beyond message location, it's unlikely to be controversial.
