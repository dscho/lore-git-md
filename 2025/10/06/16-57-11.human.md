Feature implementation with design discussion on submodule path encoding. This is part of the ongoing series implementing path encoding for submodule gitdirs to prevent filesystem conflicts, particularly on case-insensitive systems. The patch introduces URL-style encoding (RFC 3986) with case-folding for uppercase letters (A becomes _a) and adds a new `extensions.submoduleEncoding` config option. Existing unencoded paths continue to work for backward compatibility.

Junio Hamano raises two key questions in his review: First, why not use standard URL encoding (%41 for 'A') rather than the custom _a scheme, since case-insensitive filesystems should handle the hex codes correctly. Second, he cautions against the "for now" language in the encoding documentation, arguing we should choose a single encoding scheme we can commit to long-term rather than leaving the door open for future incompatible changes.

The implementation includes thorough test coverage in t7425-submodule-encoding.sh that verifies mixed legacy/new-style submodules work correctly during clone, push, and nested submodule scenarios. The core functionality appears solid, though the encoding scheme choice may need revisiting based on Junio's feedback about whether the custom case-folding is truly necessary versus standard URL encoding.
