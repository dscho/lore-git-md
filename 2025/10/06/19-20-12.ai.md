This is a discussion summary from the Git Contributor's Summit 2025 about resumable fetch/push operations, continuing the thread's coverage of summit topics. The notes capture a working session led by Caleb (standing in for Scott) exploring technical approaches to interrupted transfers.

The discussion identifies key challenges around making both fetch and push operations resumable, with particular focus on large transfers and unreliable network environments. Current solutions like bundle-uris and packfile-uris only partially address fetch scenarios, leaving push operations unsolved. Participants propose several approaches including server-side caching with opaque tags, deterministic single-threaded pack generation, and protocol extensions for partial transfer resumption.

Technical considerations include attack surface implications, the determinism requirements for pack generation, and tradeoffs between server caching strategies versus client-side resumption capabilities. The notes highlight real-world pain points like GitHub support workarounds (creating branches with limited commits) and Gerrit mirroring failures with large refsets. Brian m. carlson and Peff contribute insights about stable pack generation and caching heuristics, while Elijah Newren questions chunk-based approaches for unreliable connections.

The discussion connects to broader ecosystem tools (GitButler, GitHub, Gerrit) and suggests this work may require protocol-level improvements rather than just client-side fixes. No clear consensus emerges on implementation path, but the notes capture several viable directions including TCP-based transfer protocols, server-side bundle handling, and offset-based resumption. The complexity suggests this will be a multi-release effort rather than targeting Git 3.0.
