Refactoring discussion about URL encoding helper placement in the submodule gitdir path encoding series.

This email continues the debate about where to place the `is_rfc3986_unreserved()` helper function needed for submodule path encoding. Junio Hamano pushes back against moving it to strbuf.[ch], arguing the function isn't related to strbuf's core functionality. He notes that while the helper was logically moved to credential-store.c when that was its only user, placing it in strbuf now would be inappropriate unless strbuf itself had URL encoding needs.

The discussion stems from Adrian Ratiu's patch to make the helper available for submodule path encoding work. Junio's response suggests keeping the function in submodule.c (its current user) rather than strbuf, maintaining that utility functions should live near their primary consumers unless they're truly general-purpose. This is part of the broader submodule encoding series' final architectural refinements before merging.
