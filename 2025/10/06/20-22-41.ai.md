This is a patch implementing the `:(optional)` prefix mechanism for pathname-type config values, part of the ongoing feature series to support optional file specifications in Git.

The patch introduces a new `:(optional)` prefix that can be prepended to pathname config values. When such a path doesn't exist, Git will silently skip it rather than erroring out. This is implemented through a new `is_missing_file()` function in wrapper.c` that distinguishes between missing files (which are skipped when optional) and empty files (which are still processed). The change affects `git_config_pathname()` in `config.c`, which now handles the optional prefix and checks file existence when requested.

Documentation is updated in `config.adoc` to explain the new syntax, and a test case in `t7500` verifies the behavior with a non-existent optional template file. The implementation maintains backward compatibility while adding the new functionality.

This builds on previous work in the thread that established the `:(optional)` concept and CLI support, now bringing it to the config subsystem. The patch follows the established pattern from the CLI implementation while adapting it for config-specific needs. It includes all suggested improvements from prior reviews, including proper type safety and test robustness.

Key technical details:
- New `is_missing_file()` in wrapper.c (distinct from existing `is_empty_or_missing_file()`)
- Modified `git_config_pathname()` in config.c to handle optional prefix
- Documentation of `:(optional)` syntax in config.adoc
- Test case in t7500 using commit.template with optional non-existent file
- Maintains same behavior as CLI implementation for consistency
- Follows established patterns from prior patches in series
