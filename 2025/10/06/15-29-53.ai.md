This is the second patch in a two-part series improving gitk's window geometry persistence, specifically addressing the Tags/Heads window behavior. Johannes Sixt builds upon Michael Rappazzo's initial work to fully restore both position and size of the Tags/Heads window across sessions, while resolving Windows-specific positioning issues.

The patch introduces several key changes:
- Stores window geometry as `geometry(showrefs)` in gitk's config file
- Modifies `make_transient` to accept an optional geometry parameter
- Adds proper scoping handling with `unset` and `global` declarations
- Implements Windows-specific logic that now respects both position and size
- Uses `bindtags` to ensure Configure events only affect the Tags/Heads window

The v2 changes specifically address a Windows-specific issue where only size was being restored in v1. The solution now properly handles both position and size restoration on Windows by modifying the `make_transient` proc to accept geometry parameters while maintaining the fallback centering behavior when no geometry is specified.

The implementation demonstrates careful attention to Tcl scoping rules and window management edge cases, particularly around the interaction between the main window and transient dialogs. The 25-line change (20 additions, 5 deletions) shows a focused solution that builds on the architectural consensus established in the thread while addressing platform-specific requirements.
