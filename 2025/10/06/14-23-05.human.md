This is the final patch in Karthik Nayak's reftable fsck validation series, adding table name validation for the reftable backend. The patch implements the glue code that connects Git's fsck infrastructure with the reftable library's validation checks.

The key addition is a check that validates reftable table names against the recommended format (${min_update_index}-${max_update_index}-${random}.ref). Non-conforming names trigger a new "badReftableTableName" warning in Git's fsck system. The patch includes thorough test coverage, verifying both valid repositories and various invalid table name patterns.

The implementation handles both main and worktree reftable backends, mapping reftable-specific error codes to Git's fsck message IDs. The patch also includes some minor header cleanup in refs/reftable-backend.c to maintain lexicographical ordering of includes.

This completes the technical work for reftable fsck validation that was already approved in previous iterations. The changes are well-contained with clear documentation and error handling, following the pattern established earlier in the series. The new test cases provide comprehensive coverage of the name checking functionality.
