This is the third version of a bugfix and improvement series for `git add --interactive` navigation behavior. The series addresses hunk selection regressions and makes navigation commands more consistent and intuitive.

René Scharfe's v3 expands on previous versions by:
1. Adding roll-over behavior for 'a' (add all) and 'd' (don't add) commands to match the existing y/n behavior
2. Making error messages direction-neutral (e.g., "No other hunk" instead of "No next hunk")
3. Removing a stray "only" from a commit message

The series now includes 6 patches that:
- Improve help text for navigation commands (j/J/k/K)
- Document and implement roll-over behavior for 'J'
- Make y/n/j/e commands roll over to next undecided hunk
- Extend roll-over to backward navigation (k/K)
- Add roll-over for 'a' and 'd' commands
- Fix state management by resetting "permitted" bitmask at loop start

The implementation introduces helper functions for circular navigation and maintains careful test coverage. The changes make the interface more consistent while preserving the distinction between undecided-hunk navigation (j/k) and any-hunk navigation (J/K).
