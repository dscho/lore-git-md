This is the final patch in the reftable fsck validation series, implementing table name validation for the reftable backend. The patch adds a new fsck check that verifies reftable files follow the recommended naming convention of `${min_update_index}-${max_update_index}-${random}.ref`. Non-conformant names trigger a new `badReftableTableName` warning (added to both documentation and the `fsck.h` enum).

The implementation integrates the reftable library's fsck checks into Git's refs backend through two key callbacks: `reftable_fsck_error_handler` maps reftable-specific errors to Git's fsck messages, while `reftable_fsck_verbose_handler` provides progress output. The check runs against both main and worktree reftable stacks.

Test coverage includes verification that:
1. Well-formed repositories with multiple tables pass silently
2. Various malformed table names (including wrong extensions, invalid hex prefixes, and malformed suffixes) trigger the expected warning
3. The warning message includes the problematic filename

The patch also includes minor header cleanup in `refs/reftable-backend.c`, maintaining lexicographical order of includes. This completes the series' goal of bringing reftable stack validation to parity with files-backend fsck capabilities, with all prior review feedback addressed and maintainer approval secured.
