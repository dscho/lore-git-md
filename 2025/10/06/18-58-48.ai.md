This is a documentation patch (v5 2/5) in Julia Evans' series improving Git's upstream branch documentation. The patch adds a new "UPSTREAM BRANCHES" section to `urls-remotes.adoc` to centralize explanations about upstream tracking behavior that was previously scattered across multiple man pages.

The new section covers:
- How upstream branches affect default behavior for `git pull`, `git fetch`, and `git push`
- Where the upstream configuration is stored in `.git/config`
- Automatic upstream setup scenarios (clone, `push.autoSetupRemote`, checking out remote branches)
- The relationship between "upstream" and "tracking" terminology
- How commands like `git status` use upstream information

Key technical details include:
- The config format example showing `remote` and `merge` fields
- Explanation of `push.default=simple` same-name requirement
- Note about `branch.<name>.pushRemote` overriding default push remote
- List of commands that automatically set upstreams

The patch addresses user confusion by consolidating this information in a logical location rather than burying it in `git branch --track` documentation. It maintains consistency with the rest of the series by using "upstream branch" terminology despite some variation in the codebase. The section will be referenced by other patches in the series that explain push/pull behavior.

This is part of the v5 documentation improvements that have already been through multiple rounds of review, including formatting feedback from Jean-Noël Avila (AsciiDoc anchors/fences) and syntax corrections from D. Ben Knoble. The thread shows consensus that upstream behavior deserves centralized documentation separate from branch-specific commands.
