This is part of the ongoing Rust integration discussion from the Git Contributor's Summit 2025 notes series. The email covers the Rust adoption debate, focusing on technical and policy challenges.

The discussion reveals strong community interest in Rust adoption but significant platform compatibility concerns, with NonStop, Alpha, and Cygwin lacking Rust support. Patrick Steinhardt is working on user notifications about upcoming Rust dependencies, while Ezekiel Newren focuses on technical implementation. Key technical points include whether Rust should be mandatory (to avoid dual implementations) or optional, with arguments that mandatory adoption would prevent maintenance burdens of supporting both C and Rust code paths.

The notes highlight Rust's potential benefits for threading, error handling, and memory safety, as well as its popularity for attracting new contributors. However, they also acknowledge the massive scope of a full C-to-Rust transition, suggesting incremental approaches like rewriting individual functions or new subcommands in Rust first. The discussion connects to other ongoing efforts like libification and the pluggable object store work, noting that Rust adoption could complement these architectural improvements.

Unresolved questions center on timeline, platform support trade-offs, and whether to pursue a full rewrite or targeted adoption. The email suggests starting with Rust-based tests for existing C code as a low-risk entry point, while acknowledging political pressures from organizations moving away from C for security reasons. This discussion appears closely tied to the SHA-256 interoperability work (some of which is already written in Rust) and broader architectural cleanup efforts around global state reduction.
