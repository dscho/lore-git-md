This is a test fix patch that addresses a flaky test in t8020-last-modified.sh, part of the ongoing CI/build system reliability series. The test was originally written to detect a bug in `git-last-modified` involving criss-cross merges, but Patrick Steinhardt discovered the test was actually triggering the bug through a different mechanism (directory modifications during merges) while also suffering from tag ambiguity issues.

The patch refactors the test to:
1. Use a standalone repository to avoid interference
2. Explicitly test the directory-modification scenario rather than the misleading criss-cross merge case
3. Remove a problematic `test_when_finished` call that wasn't working in subshells
4. Use clearer commit/tag names to prevent ambiguous output

Toon Claes reviews the changes and agrees with the approach, acknowledging they should have used a standalone repo initially. The changes maintain the test's ability to catch the original bug while making it more reliable and focused. This concludes the 5-patch series addressing Windows CI reliability and test improvements.
