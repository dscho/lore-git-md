This is a documentation patch (part 3/5 in Julia Evans' v5 series) that clarifies the "where to push" behavior in `git-push`'s man page. The patch simplifies and makes more precise the explanation of how Git determines the default push destination when no repository is specified on the command line.

The key changes replace a technical reference to `branch.*.remote` configuration with clearer language about "upstream" behavior, and restructures the sentence to use "defaults to" for better readability. The new wording directly states that the repository argument defaults to the current branch's upstream, falling back to 'origin' if no upstream is configured.

This continues the series' theme of making push behavior documentation more accessible while maintaining technical correctness. The change aligns with the thread's broader effort to improve documentation clarity, particularly around upstream branch concepts that were recently centralized in patch 2/5's new "UPSTREAM BRANCHES" section.
