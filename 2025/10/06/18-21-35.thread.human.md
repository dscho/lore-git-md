This thread reports an unusual case where patches generated from a Linux kernel tree (specifically targeting the SMB client code in `fs/smb/client/dir.c`) fail to apply back to the same source tree they were generated from. The author, Markus Elfring, notes these patches were created with Git 2.51.0-2.1 from the Linux next-20251003 tree and were previously rejected by the linux-cifs list as corrupted. 

The core mystery is why Git-generated patches wouldn't cleanly reapply to their source tree - this could indicate either a Git bug in patch generation or some environmental factor in the workflow (the mention of Coccinelle scripts suggests automated patch generation might be involved). As this is the initial report, there's no diagnosis yet, but the thread will likely explore whether this represents a Git issue or a kernel/SMB-specific peculiarity in how the patches were produced.
