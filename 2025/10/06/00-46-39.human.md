This is a discussion about validating symref names in the files backend, specifically regarding Junio C Hamano's concerns about the validation approach in the current patch series.

Jeff King (Peff) responds to Junio's feedback about whether `refname_is_safe()` alone provides sufficient validation for symref updates. He notes that while the patch adds validation, it's checking existing symref state rather than new input, and suggests this might be overkill since the target should have been validated when originally written. He mentions having his own upcoming series that addresses broader symref validation gaps.

Peff also points out a technical limitation - the test case added in the patch won't work with the reftable backend, since it directly manipulates `.git/HEAD` which isn't how reftable stores references. This suggests the test needs to be backend-agnostic to be truly effective.

The discussion reveals two key considerations: whether the validation is needed at this specific point in the code, and how to properly test the behavior across different ref storage backends. Peff's response indicates this might benefit from being folded into his broader symref validation work rather than being addressed as a standalone fix.
