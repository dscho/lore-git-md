This is part 6/7 of the reftable fsck validation series, implementing the core consistency checking infrastructure for the reftable backend. The patch adds a new `reftable/fsck.[ch]` pair that provides a callback-based API (`reftable_fsck_check()`) to validate reftable stacks independently of Git's internals.

The main check implemented here validates that all reftable files follow the expected naming pattern (hex-hex-hex.ref format). Invalid names trigger an error report through the callback mechanism. The design keeps the reftable library self-contained while allowing Git's fsck integration to handle the reports.
