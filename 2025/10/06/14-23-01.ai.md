This is a refactoring and validation patch in the reftable fsck series, specifically tightening the parser for 'tables.list' files. The patch modifies `parse_names()` to enforce that the file must end with a newline, returning `REFTABLE_FORMAT_ERROR` if it doesn't. The function signature is changed to return an error code rather than the names array, which is now passed via an output parameter.

Key technical changes:
1. `parse_names()` now returns error codes (0 for success, `REFTABLE_FORMAT_ERROR` for missing newline, `REFTABLE_OUT_OF_MEMORY_ERROR` for allocation failures)
2. The function's output is now passed via a `char ***out` parameter
3. New test case `test_reftable_basics__parse_names_missing_newline()` verifies the error case
4. Existing tests are updated to handle the new return value pattern
5. Documentation in `reftable/basics.h` is updated to reflect the new behavior

The change affects several files in the reftable implementation:
- `reftable/basics.c` gets the core parser changes
- `reftable/stack.c` adapts to the new error-returning API
- Unit tests are expanded to cover both success and error cases

This is part of the larger reftable fsck validation effort, with this particular patch addressing a specific format requirement that wasn't previously enforced. The change is well-contained and comes with thorough test coverage, including both positive and negative test cases. The patch follows the established pattern of the series by being careful about error handling and memory management.
