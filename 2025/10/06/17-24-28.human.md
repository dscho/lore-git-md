Bugfix for `git add -p` permission flag handling in the interactive add navigation series.

This final patch in René Scharfe's v3 series fixes a subtle issue where the set of permitted commands was incorrectly accumulating across multiple hunks in the interactive add interface. The fix moves the `permitted` flags declaration inside the hunk processing loop so they're reset for each new hunk, preventing commands allowed on one hunk from incorrectly remaining available on subsequent hunks where they shouldn't be.

The change addresses a bug report from Junio Hamano and comes with a new test case that verifies invalid commands (like 's' for split when splitting isn't possible) are properly rejected on a per-hunk basis. The test shows the interface correctly restricts options based on each hunk's capabilities rather than remembering what was allowed on previous hunks.

This is a clean, focused conclusion to the series that ensures the unified navigation behavior works correctly in all edge cases. The patch maintains the series' high standard with clear code changes and thorough test coverage.
