This is a follow-up patch in the submodule gitdir path encoding series, addressing a review comment from Junio Hamano on v3. The change converts `add_submodule()` to use the centralized `submodule_name_to_gitdir()` helper function for path resolution, bringing it in line with other submodule operations that were already using this helper.

The patch makes two main changes:
1. Replaces direct path construction (`xstrfmt(".git/modules/%s")`) with the helper function call
2. Moves the `submod_gitdir_path` variable declaration into a narrower scope since it's no longer needed outside the first conditional block

Junio notes the original commit message could have been clearer about this being a conversion to an existing helper rather than introducing new functionality. He also confirms the resource management (strbuf cleanup) is properly handled in all code paths, matching the behavior of the original implementation.

This appears to be a straightforward mechanical change that improves consistency in the submodule path handling code. The change is well-contained and maintains existing behavior while preparing for the path encoding functionality introduced later in the series. No new test cases are needed since the existing submodule tests should cover this code path.
