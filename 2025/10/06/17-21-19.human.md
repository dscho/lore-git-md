Bugfix and behavior refinement for `git add --interactive` navigation.

This patch is part 3 of a 6-part series improving the interactive add interface's navigation behavior. It focuses on making the 'y', 'n', 'j', and 'e' commands roll over to the next undecided hunk in a more consistent way, rather than always jumping to the first hunk when reaching the end.

The change makes these commands behave more predictably by:
1. Moving to the first undecided hunk when rolling over, rather than always going to hunk 1
2. Updating the error message for 'j' to match this new behavior ("No other undecided hunk")
3. Adding tests that verify the roll-over behavior works as intended

The patch builds on previous work in the series to create a more uniform navigation experience. The implementation introduces a new `inc_mod()` helper function to handle the circular navigation logic cleanly. Test coverage is thorough, with two new test cases that verify the behavior works correctly in different scenarios.

This appears to be a well-considered change that addresses a real usability issue in the interactive add workflow. The commit message clearly explains both the current behavior and the improvement, and the test cases provide good coverage of the new functionality. The change is part of a larger effort to make the interactive add interface more consistent and predictable.
