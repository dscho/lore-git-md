Documentation polish in interactive add navigation series.

This email continues René Scharfe's v2 series improving `git add --interactive` navigation behavior, specifically addressing documentation clarity. The patch simplifies help text for j/J/k/K commands by removing redundant references to the current hunk's status, making it clearer these are pure navigation commands. 

The key change removes phrases like "leave this hunk undecided" from the navigation command descriptions, replacing them with direct "go to next/previous [undecided] hunk" language. This better reflects the actual behavior where these commands only move between hunks without affecting their state.

Junio Hamano suggests extending similar clarity improvements to y/n commands, noting they both decide the current hunk and move forward. René agrees this would be valuable but considers it out of scope for this focused documentation patch, proposing it as potential future work. He raises an interesting question about whether y/n help text should dynamically adapt based on whether the current hunk is the final undecided one.

The changes affect both user documentation (git-add.adoc) and in-code help text (add-patch.c), with identical wording in both locations. This maintains consistency between what users see in the manual and what they encounter during interactive sessions.

Technical aspects:
- Documentation changes are purely textual with no behavior impact
- Maintains parallel structure between forward (j/J) and backward (k/K) commands
- Keeps the distinction between "undecided hunk" (j/k) and "any hunk" (J/K) navigation
- Sets up potential future work for dynamic y/n help text

This patch represents the documentation component of the broader navigation behavior improvements in the series, with the author choosing to keep the scope narrow rather than expanding to address all possible help text clarifications at once.
