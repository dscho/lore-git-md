Git Contributor's Summit 2025 discussion thread initiated by Taylor Blau, covering multiple in-depth technical topics from the event. The thread now includes detailed notes on SHA-256 interoperability, first-class conflict handling, history rewriting tools, Rust integration, pluggable object databases (ODB), packfile/MIDX optimizations, Change-ID standardization, and resumable fetch/push operations, with new focus on Git 3.0 planning and SHA-256 transition timelines.

SHA-256 interoperability work (brian m. carlson) faces complex challenges around repository transitions between hash algorithms, including submodule conversion, security implications of mixed hashes, and GPG signature verification. The new email highlights debate about setting a hard deadline for SHA-256 support in Git 3.0, with Taylor Blau noting end-of-2026 as an internal benchmark while acknowledging the project shouldn't delay purely for this feature. Brian m. carlson emphasizes security rationale ($10k SHA-1 collision cost) and argues for including SHA-256 in Git 3.0 with firm date, while Elijah Newren and Peff question ecosystem readiness, particularly forge support. Tension exists between technical readiness (Brian) and practical adoption concerns (Peff), with Taylor noting users will blame Git if major forges don't support the new hash algorithm.

First-class conflict handling explores representing merge conflicts as persistent Git objects rather than transient working directory states. Technical considerations include storage formats (special tree objects vs commit headers), GC behavior, backward compatibility, and integration with new commands like `git replay`. The complexity suggests this may be a longer-term project rather than a Git 3.0 candidate.

History rewriting and Change-IDs discussion includes detailed debate about standardizing Change-ID headers in commits, with agreement on header storage but disagreement on semantic rules for preservation versus regeneration. Technical specifics include treating Change-ID as opaque, forge handling of rebases/squashes, and edge cases around commit splitting/merging.

Rust integration discussion shows strong community interest but significant platform compatibility concerns (NonStop, Alpha, Cygwin lacking Rust support). Patrick Steinhardt works on user notifications about upcoming Rust dependencies while Ezekiel Newren focuses on technical implementation.

Pluggable ODB discussion (Patrick Steinhardt) focuses on making Git's object storage more modular, particularly for large binary files. Technical blockers include unclear database format (latency concerns) and packfile generation challenges. The conversation suggests this work will continue through 2026.

Packfile/MIDX optimization discussion (Taylor Blau) highlights geometric repacking improvements, with recent changes allowing exclusion of large cruft packs from MIDX. Taylor proposes a "unitary MIDX" concept to eliminate duplication between MIDX and pack index data, though backward compatibility concerns remain.

Resumable fetch/push operations discussion explores technical approaches to interrupted transfers, with proposed approaches including server-side caching with opaque tags and protocol extensions for partial transfer resumption. The discussion suggests protocol-level improvements may be needed.

The new email also touches on other Git 3.0 scope items including reftable becoming the default reference backend and planned deprecations. Patrick Steinhardt mentions maintaining a BreakingChanges document tracking removals, while Taylor suggests implementing "brown-outs" (temporary feature disablements) for deprecated functionality. Brian m. carlson volunteers to kick off further discussion on-list about SHA-256 transition timelines.

Open questions remain on SHA-256 transition blockers (particularly forge adoption), Rust adoption timeline given platform limitations, pluggable ODB implementation path, and Git 3.0 feature set. The thread shows increasing focus on coordination challenges between core Git development and broader ecosystem readiness for major changes.
