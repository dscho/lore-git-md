This is a documentation patch in René Scharfe's v2 series improving interactive hunk navigation in `git add -p`. The patch simplifies the help text for navigation commands (j/J/k/K) by removing redundant references to the current hunk's status, since these commands only move between hunks without affecting their state.

Junio Hamano suggests extending this clarity to the y/n commands as well, noting they both decide the current hunk *and* move forward. René agrees this would be valuable but sees it as a separate concern - the current patch focuses narrowly on removing misleading status references from navigation commands. He raises an interesting question about whether y/n's help text should dynamically reflect whether movement will occur, but proposes handling that in a future series.

The changes are straightforward doc updates in both the man page and code, with the improved wording making the commands' behavior more immediately clear to users. This is part of a larger effort to make interactive add's interface more consistent and intuitive.
