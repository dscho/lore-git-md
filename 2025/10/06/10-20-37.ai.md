This is a test refactoring patch that fixes a flaky test in t8020-last-modified.sh, part of a 5-patch series improving CI reliability and test reporting. The test was attempting to verify behavior around criss-cross merges but had several issues: it used ambiguous tag names (km2/k2 pointing to same commit), relied on an unintended fast-forward merge, and operated in a shared repository causing interference.

Patrick Steinhardt's refactoring:
1. Creates a standalone test repository to avoid interference
2. Focuses the test on directory-modification scenarios rather than the misleading criss-cross merge case
3. Removes a problematic `test_when_finished` call that wasn't working in subshells
4. Uses clearer commit/tag names to prevent ambiguous output

The changes maintain the test's ability to catch the original bug while eliminating the flakiness. Toon Claes reviewed and approved the changes, acknowledging the improved approach. The patch demonstrates good test hygiene by isolating the test case and removing incidental complexity, though the discussion revealed the original analysis of criss-cross merges being the trigger was incorrect - the actual issue involved directory modifications during merges.
