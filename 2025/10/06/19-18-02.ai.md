This is a detailed set of notes from the SHA-256 interoperability discussion at the Git Contributor's Summit 2025, led by brian m. carlson. The discussion focuses on the complex challenges around transitioning repositories between SHA-1 and SHA-256 hash algorithms, particularly regarding submodules and object compatibility.

Key technical points include the handling of submodules during conversion (including recursive/cyclic cases), security implications of divergent histories when different hash algorithms are mixed, and GPG signature verification across hash algorithms. The notes reveal several unresolved questions about the user experience for repository conversion and the potential need for server-client mapping of objects (not just commits). There's discussion of possible future extensibility to support additional hash algorithms beyond SHA-256, though client support remains a limiting factor.

The conversation highlights particularly thorny edge cases like handling submodules that no longer exist, with the current approach allowing for divergent histories in such cases. The notes also mention related challenges with LFS objects and potential format changes to tree objects to better handle mixed-hash scenarios. The discussion concludes with an action item to bring specific tree format modification ideas to the mailing list for broader review.

This appears to be part of the ongoing SHA-256 transition work that has been progressing toward Git 3.0, though the notes indicating uncertainty about completing everything by that deadline. The technical depth suggests this will require careful review from both the hashing and submodule subsystems maintainers.
