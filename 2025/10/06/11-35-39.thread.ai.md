Thread identity: Bugfix patch for `git stash pop` behavior when `status.showStash` is enabled, addressing redundant status messages. Authored by Miroma, with review feedback from Karthik Nayak and Junio C Hamano.

Core problem: When popping the last stash with `status.showStash` enabled, Git shows both a pre-pop stash count ("Your stash currently has 1 entry") and drop confirmation ("Dropped refs/stash@{0}"), creating redundant output. The count becomes misleading since it reflects pre-pop state while the stash is being dropped.

Technical solution evolution: Initial environment variable approach (`GIT_CONFIG_COUNT`) was replaced by Junio's suggested `-c status.showstash=false` alternative, now superseded by Miroma's discovery of `--no-show-stash` flag. The change modifies `builtin/stash.c` to handle status display during pop operations, with output reordering to show drop confirmation before updated stash count.

Miroma has clarified the core confusion stems from showing pre-pop counts that become immediately incorrect, and proposed output order: drop confirmation first, then updated stash count (or nothing if no stashes remain).

Key technical details: The solution will use `git status --no-show-stash` internally rather than environment variable manipulation.
