This is the first patch in a 4-part refactoring series for the string-list API, focusing on type safety improvements. The patch converts the `exact_match` parameter from `int` to `bool` throughout the string-list implementation, making the code more semantically clear since this parameter fundamentally represents a true/false condition.

The changes affect several key functions in `string-list.c` and `string-list.h`:
- The internal `get_entry_index()` helper now takes a `bool*` instead of `int*` for `exact_match`
- All callers are updated to use proper boolean values (`true`/`false`) rather than integer 1/0
- `string_list_has_string()` changes its return type from `int` to `bool` to match
- The `string_list_lookup()` function is also updated to use the new boolean type

The patch maintains identical behavior while improving type correctness. This change is part of a larger effort to eliminate sign comparison warnings and prevent integer overflow vulnerabilities in the string-list API, as documented in the thread context. The conversion to `bool` is a straightforward improvement that makes the code's intent clearer without introducing any functional changes.

This patch sets the stage for subsequent changes in the series that will further improve type safety by converting index types to `size_t` and removing sign comparison warning suppressions. The thread context shows this change was well-received in previous iterations, with the v3 version incorporating final documentation refinements.
