This is the second patch in a 4-part series refactoring the string-list API to improve type safety and prevent integer vulnerabilities. The patch focuses on `string_list_find_insert_index()`, which previously used a negative index encoding scheme to indicate exact matches (-1 - index). The new version replaces this with a cleaner `bool *exact_match` parameter and changes the return type to `size_t` for better overflow protection.

The changes affect several key areas: the internal `get_entry_index()` helper now takes an optional `bool*` parameter (NULL when callers don't need match information), all callers in `add-interactive.c`, `mailmap.c` and `refs.c` are updated to use the new API, and the function signature in `string-list.h` is modified. The `mailmap.c` changes include fixing a subtle underflow issue when working with `size_t`.

The patch maintains identical behavior while improving clarity and type safety. Callers that only need insertion indices (like in `refs.c`) can now pass NULL for `exact_match`, eliminating unnecessary variable declarations. The changes align with the series' security focus by preventing integer overflow through consistent use of `size_t` for indices.

This version (v3) incorporates feedback from previous iterations, particularly around documentation and the security rationale. The implementation is now stable with all callers properly adapted to the new API contract. The changes are straightforward mechanical conversions with no behavior changes, making this a low-risk refactor that paves the way for the subsequent patches in the series.
