Feature implementation for submodule path encoding, part 4/5 in the series. This patch introduces the `extensions.submoduleEncoding` config option to enable URL-encoded submodule gitdir paths, addressing filesystem conflicts from nested gitdirs and case insensitivity. The encoding uses RFC3986 URL encoding with an added case-preserving scheme (A -> _a, B -> _b etc.), though it notes Windows reserved names remain an open problem.

Key technical details:
- Adds `repository_format_submodule_encoding` flag to repository struct
- Implements `strbuf_addstr_case_encode()` helper for case-preserving encoding
- Modifies `submodule_name_to_gitdir()` to apply encoding when extension is active
- Preserves backward compatibility by checking for legacy paths first
- Adds comprehensive test suite `t7425-submodule-encoding.sh` covering:
  - Mixed legacy/new-style submodules
  - Cloning scenarios
  - Nested submodule cases
  - Parallel cloning
- Documents new config in `extensions.adoc` and `submodule.adoc`

The implementation builds on previous parts by:
- Using the shared URL encoding from part 3 (now in strbuf.c)
- Following the path resolution order established in parts 1-2
- Maintaining the config override mechanism from part 2

Open issues noted:
- Windows reserved names (COM1 etc.) still need worktree-side fixes
- The encoding scheme could be extended later with alternatives

The patch appears well-tested with thorough scenarios covering the mixed legacy/encoded transition path. The implementation cleanly integrates with the series' established architecture while documenting current limitations.
