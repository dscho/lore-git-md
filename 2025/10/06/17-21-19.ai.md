This is a feature patch in the interactive add navigation behavior series, specifically addressing roll-over behavior for several commands in `git add -p`.

The patch refines how the 'y' (yes), 'n' (no), 'j' (next undecided), and 'e' (edit) commands handle movement between hunks when reaching the end of the hunk list. Previously these commands would wrap around to the first hunk regardless of its state, but now they properly seek the first undecided hunk when wrapping, matching the behavior they exhibit when moving forward normally. This makes the interface more consistent and predictable.

Key technical changes include:
- New `inc_mod()` helper function for circular increment
- Updated hunk navigation logic to use this helper when searching for next undecided hunk
- Modified error message from "No next hunk" to "No other undecided hunk" to better reflect the circular model
- Documentation updates clarifying 'j' command's roll-over behavior
- Two new test cases verifying the roll-over behavior with different command sequences

The changes build on the thread's goal of unifying navigation behavior across all interactive add commands. The implementation maintains backward compatibility while fixing what appears to be an oversight in the original roll-over logic. The tests provide thorough coverage of both the basic roll-over case and more complex scenario where commands are interleaved with navigation.

This patch represents a logical extension of the series' work, addressing one of the remaining inconsistencies in the interactive add interface. The changes are well-contained and maintain the careful, incremental approach seen throughout the thread.
