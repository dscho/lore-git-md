This is a bugfix for the stash command's output behavior. When `status.showStash` is enabled, running `git stash pop` currently shows a redundant and confusing message about the stash entry count right before reporting that the stash was dropped. The patch from Miroma fixes this by temporarily disabling `status.showStash` during the status check that happens as part of `stash pop`.

The change is small but targeted - it adds environment variables to override the config just for the status subprocess spawned during stash operations. This prevents the irrelevant entry count from appearing when it's about to become immediately outdated anyway. The fix appears straightforward with no obvious downsides, and the commit message clearly explains both the problem and solution.

This seems like a quality-of-life improvement that removes confusing output without affecting any actual functionality. The patch touches only the stash command's implementation in builtin/stash.c, adding just 3 lines to modify the subprocess environment.
