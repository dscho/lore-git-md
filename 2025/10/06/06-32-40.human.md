This is the third patch in a 4-part series refactoring the string-list API to improve type safety and prevent integer overflow vulnerabilities. The patch changes the return type of `string_list_find_insert_index()` from `int` to `size_t` to match its internal helper function `get_entry_index()`, completing the transition to unsigned types for indices.

The changes are straightforward but require careful handling in callers. The most notable fix is in `mailmap.c` where the loop condition needed adjustment to properly handle `size_t` underflow (changing from `0 <= --i` to `i--`). The patch also removes the now-unneeded `DISABLE_SIGN_COMPARE_WARNINGS` from mailmap.c.

Callers in `add-interactive.c`, `mailmap.c`, and `refs.c` are updated to use `size_t` variables for storing the return value. The header file gains improved documentation explaining the function's purpose. This is a clean, well-motivated change that follows through on the type safety improvements started in earlier patches of the series.
