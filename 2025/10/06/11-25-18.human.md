Bugfix and platform compatibility patch for the submodule gitdir path encoding series. This is the final patch (5/5) in v3 of the series, addressing path length validation when encoding submodule names.

The patch adds error handling for cases where encoded submodule names would exceed filesystem filename length restrictions. It implements a portable solution using `pathconf(_PC_NAME_MAX)` to check path length limits, with a fallback to `NAME_MAX` (255) on platforms without `pathconf()` (like Windows). When a submodule name would exceed the limit after encoding, Git now fails with a clear error message rather than letting the OS produce cryptic errors.

The implementation includes new compatibility code for Windows and other platforms lacking `pathconf()`, plus test coverage verifying the error handling. The approach follows Jeff King's suggestion to error out cleanly now while leaving room for future enhancements like configurable sharding or trimming strategies.

This completes the submodule encoding series by handling an important edge case while maintaining cross-platform compatibility. The solution is intentionally minimal, deferring more complex length-handling strategies to potential future work.
