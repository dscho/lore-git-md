The Git Contributor's Summit 2025 discussion continues with a focus on SHA-256 transition timelines and Git 3.0 planning. Taylor Blau and Brian m. carlson are leading the conversation, with Brian advocating strongly for including SHA-256 support in Git 3.0 due to security concerns - he cites the now $10k cost to create SHA-1 collisions as a pressing reason to move forward. However, Peff and Elijah Newren raise practical concerns about whether major forges will be ready to support SHA-256 repositories when Git 3.0 ships, suggesting release timing should consider ecosystem readiness.

The discussion reveals a tension between technical implementation (where Brian argues the core functionality should be delivered) and real-world adoption (where Peff questions whether forges will be prepared). Taylor takes a pragmatic middle ground, noting there will always be some laggards in adoption, but that shouldn't indefinitely delay progress. The conversation also touches on other Git 3.0 considerations, including reftable as the default reference backend and managing deprecations through Patrick Steinhardt's BreakingChanges document and Taylor's suggestion of "brown-out" periods for deprecated features.

While the SHA-256 security arguments are compelling, the practical coordination challenges with the broader ecosystem remain unresolved. Brian has volunteered to start a dedicated mailing list thread to continue this important discussion, which will likely be a major focus in the lead-up to Git 3.0. The thread shows the project grappling with how to balance technical progress against real-world adoption constraints - a classic open source coordination challenge.
