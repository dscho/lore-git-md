This is part 2 of a 6-patch series improving `git add --interactive` navigation behavior. The patch documents and tests the roll-over behavior of the 'J' command (jump to next hunk), which was previously an undocumented side effect of how the `permitted` variable works. The change makes this behavior official by updating both the documentation and in-interface help text to explicitly state that 'J' rolls over to the first hunk when used at the last hunk.

The patch also improves the error message when no other hunks are available, changing it from "No next hunk" to the more accurate "No other hunk" since the navigation model is now circular. Test coverage is expanded to verify the roll-over behavior works as expected.

This continues the series' theme of making the interactive add interface more consistent and better documented. The changes are straightforward and well-tested, with the behavior having been implicitly present in earlier versions but now properly exposed to users. The patch addresses feedback from Junio Hamano about making this behavior official rather than leaving it as an undocumented side effect.
