This is the first patch in a 4-part series refactoring the string-list API to improve type safety and prevent integer overflow vulnerabilities. The patch converts the `exact_match` parameter in the string-list internals from `int` to `bool`, making the code more semantically clear since this parameter fundamentally represents a true/false condition.

The changes are straightforward mechanical conversions, touching both the internal helper functions and their callers. The patch updates `get_entry_index()` and all functions that use it, including `string_list_has_string()` which now returns `bool` instead of `int`. The header file declaration is updated to match.

This is part of a larger effort to modernize the string-list API's type usage, with subsequent patches in the series addressing return types and warning suppression. The change is well-contained and appears to be a clear improvement in code clarity without any behavior changes. The patch follows Git's established patterns for boolean usage and maintains compatibility with all existing callers.
