This is the final patch in the submodule gitdir path encoding series, adding length validation for encoded submodule names. The patch implements a platform-portable solution to detect when encoded submodule names would exceed filesystem filename length restrictions.

The core change adds a check in `submodule_name_to_gitdir()` that uses `pathconf(_PC_NAME_MAX)` to get the system's filename length limit, falling back to 255 if unavailable (particularly on Windows which lacks `pathconf`). When an encoded name would exceed this limit, Git now fails with a descriptive error rather than letting the OS produce potentially cryptic errors. The implementation includes:

1. New `NO_PATHCONF` build flag and stub implementation for Windows
2. Platform detection in config.mak.uname and meson.build
3. Length validation logic in submodule.c using the new pathconf infrastructure
4. Test case in t7425 that verifies the error handling by creating an intentionally too-long name

The patch follows Jeff King's suggestion to start with simple error handling rather than committing to a specific policy (like sharding or trimming) for too-long names. The commit message notes this could be made configurable in the future. The implementation maintains the series' cross-platform compatibility while providing better user feedback than OS defaults.

This completes the technical implementation of the submodule encoding series, with all major components now in place: path resolution order, config override, encoding scheme, and now length validation. The only open question from earlier reviews (pathconf vs fixed limit) is resolved here by using pathconf where available while maintaining a fallback.
