This is a bug report about patch application failures, though it appears to be cross-posted from Linux kernel development rather than being Git-specific. The author Markus Elfring reports that patches generated by `git format-patch` from the Linux kernel source (specifically SMB client code) fail to apply back to the same tree despite being generated from it. The error messages indicate line number mismatches when applying to `dir.c`.

The key technical details are:
- Patches were generated from Linux next-20251003 tree using Git 2.51.0-2.1
- Two specific patches for `fs/smb/client/dir.c` fail with "patch does not apply" errors
- The patches were previously submitted to linux-cifs mailing list and rejected as corrupted
- The author is seeking clarification on why exported patches might not reapply

The thread appears to be just starting, so there's no established diagnosis yet. The core question seems to be whether this represents a Git bug in patch generation or some environmental/process issue in the workflow. The mention of Coccinelle scripts in the patch paths suggests this might involve automated patch generation, which could be relevant to the failure mode.
