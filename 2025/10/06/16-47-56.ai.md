This is a follow-up discussion in the submodule gitdir path encoding series, specifically addressing Junio C Hamano's concerns about the config override mechanism introduced in v3 patch 2/5. The patch adds a `submodule.<name>.gitdir` config option to override default gitdir paths, with tests and documentation.

Junio questions the practical use case for this override, pointing out a potential collision scenario: if a user has a submodule named "%41%42%43" (which would decode to "ABC") and later adds a new submodule "ABC" with encoding enabled, the paths could collide. He expresses skepticism about whether allowing such overrides is wise given this edge case.

The technical implementation includes:
- New config documentation in `Documentation/config/submodule.adoc`
- `submodule_name_to_gitdir()` helper modified to check for config overrides
- New `module_gitdir` subcommand in `submodule--helper`
- Test helper `lib-verify-submodule-gitdir-path.sh` to verify config behavior
- Completion updates for the new config key

This discussion highlights a key design tension in the series - between providing configuration flexibility and maintaining safety against path collisions. Junio's concern suggests the override mechanism might introduce more problems than it solves, particularly around the interaction between encoded and unencoded paths. The thread context shows this was part of broader design discussions that were later resolved in v5, but this exchange captures an important moment where core maintainers scrutinized the safety implications of the config override approach.
