This is a discussion summary from the Git Contributor's Summit 2025, focusing on history rewriting tools and the potential introduction of Change-IDs. The notes capture a wide-ranging conversation about improving Git's history manipulation capabilities while maintaining backward compatibility.

The discussion highlights several pain points with current tools like `git rebase` and `git sequencer`, particularly around complexity for new users and the limitations imposed by backward compatibility requirements. There's interest in developing more user-friendly porcelain commands (possibly called `git history`) while continuing to evolve the underlying plumbing (`git replay`). A key tension emerges between wanting to modernize the infrastructure and the need to maintain existing workflows that rely on the sequencer's behavior.

A significant portion focuses on Change-IDs - persistent identifiers for tracking changes across history rewrites. The debate reveals multiple unresolved questions: how to handle Change-IDs during operations like squashing or splitting commits, whether they should be optional, and concerns about privacy when Change-IDs might expose information about private repository histories. The Gerrit-style approach of embedding Change-IDs in commit bodies is discussed, but current Git tooling doesn't easily support this.

The discussion suggests these are long-term challenges rather than immediate fixes, with no clear consensus yet on implementation details. The notes indicate this work intersects with other summit topics like first-class conflict handling and SHA-256 transition work, particularly around object formats and protocol changes.
