This is the third patch in a 4-part series refactoring the string-list API to improve type safety and prevent integer overflow vulnerabilities. The patch changes the return type of `string_list_find_insert_index()` from `int` to `size_t` to match its internal helper `get_entry_index()`, completing the transition to unsigned types for indices.

The changes affect several callers across the codebase, with the most notable fix being in `mailmap.c` where the loop condition is adjusted to properly handle `size_t` underflow by changing from `0 <= --i` to `i--`. The patch also removes the now-unnecessary `DISABLE_SIGN_COMPARE_WARNINGS` from `mailmap.c` since the proper unsigned types eliminate the sign comparison warnings.

The header file gains improved comments explaining the function's purpose and the `exact_match` parameter behavior. Callers in `add-interactive.c`, `mailmap.c`, and `refs.c` are updated to use `size_t` variables for storing the return value, with `refs.c` simplifying its code by declaring the index variable inline rather than at function scope.

This patch represents the final technical change in the series, with the subsequent patch focusing on enabling sign comparison warnings for refs. The changes are straightforward mechanical conversions that maintain the existing behavior while improving type safety.
