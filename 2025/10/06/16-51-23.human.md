This is a refactoring patch that revisits the placement of URL-encoding helper functions in the submodule path encoding series. Junio Hamano questions why the `is_rfc3986_unreserved()` function is being moved back to strbuf.c when it doesn't appear to be used by strbuf functionality. The function was previously moved to credential-store.c when it was only used there, but is now needed for submodule path encoding.

The patch author (Adrian Ratiu) explains the rationale - the function is needed for URL-encoding submodule names to prevent path conflicts. However, Junio points out that strbuf.c doesn't actually use this functionality, making its placement there questionable. This appears to be a minor architectural discussion in the larger submodule encoding series about where shared encoding utilities should live in the codebase.

The exchange shows careful consideration of code organization principles, with Junio advocating for keeping helper functions near their actual callers rather than creating artificial dependencies. This is part of the ongoing refinement of the submodule path encoding implementation, where even small implementation details are getting thorough review.
