This is part 5 of a 6-patch series improving interactive hunk navigation in `git add -p`. The patch extends the consistent "roll-over" behavior (where navigation wraps around to the first hunk when reaching the end) to the 'a' (add all) and 'd' (don't add all) commands, matching how 'y' and 'n' already work.

The change makes the interface more predictable - after using 'a' or 'd' to act on all undecided hunks, the selection now moves to the next undecided hunk if one exists, rather than always jumping to the first hunk. This matches user expectations better when working through multiple hunks.

The implementation introduces a new helper function `get_first_undecided()` to centralize the logic for finding the next undecided hunk. The patch includes thorough test updates to verify the new behavior works correctly in various scenarios, including when mixing 'a'/'d' with other navigation commands.

This continues the series' systematic approach to making hunk navigation more consistent. The change is well-motivated, with clear test coverage showing the before/after behavior. As with previous patches in the series, it maintains backward compatibility while improving the user experience.
