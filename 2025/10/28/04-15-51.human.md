This is a discussion about Rust version compatibility in the ongoing cbindgen integration series.

Junio Hamano responds to concerns raised by Brian M. Carlson and Ezekiel Newren about Rust version requirements for cbindgen. The key points:

1. There's no formal agreement yet on the minimum supported Rust version for Git, despite earlier discussions. Hamano references Brian's 2023 proposal about tracking Debian stable/oldstable versions, but notes this hasn't been formally adopted.

2. Current Debian oldstable (bookworm) provides Rust 1.63, which would become the de facto minimum if Brian's proposal were accepted. New stable (trixie) was recently released in 2025 with a newer Rust version.

3. The discussion highlights a tension between:
   - The project's current Rust 1.49 target (which may be too old for modern cbindgen)
   - Practical concerns about build tool compatibility
   - The need for a clear version support policy

This email doesn't propose solutions but clarifies the policy vacuum around Rust version requirements. It's an important thread for anyone working on Git's Rust integration, as it affects both current cbindgen work and future Rust development. The outcome will likely influence how build dependencies are managed and what Rust features can be used.
