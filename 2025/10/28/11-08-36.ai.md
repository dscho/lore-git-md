Refactoring patch in the ongoing packfile store abstraction series. This sixth patch moves the main packfile list management into the `packfile_store` structure, replacing direct `packed_git` linked list traversal with the new `packfile_list` API introduced earlier in the series.

The changes systematically replace all direct `p->next` iteration with `packfile_list` operations across several key areas: window scanning, pack closing, MRU list preparation, and bad object checks. The patch removes the `next` pointer from `struct packed_git` entirely, making packfile linkage solely managed through the store's list structures. It also drops the standalone `find_oid_pack()` function in favor of the list-based iteration pattern.

Key technical details:
- Changes affect core packfile operations in `packfile.c` and `fast-import.c`
- Introduces new `packfile_list_entry` iteration pattern via `repo_for_each_pack` macro
- Maintains sorting behavior (local packs first, then by mtime) but implements it through list operations
- Updates pack closing and window management to use list API
- Removes now-unused `find_oid_pack()` function
- Part of broader effort to consolidate packfile management in preparation for deeper integration with object source layer

The patch follows the series' pattern of maintaining existing behavior while modernizing the implementation. It builds on the list infrastructure introduced in earlier patches and sets up for the final consolidation of packfile lists in patch 8. The changes are mechanical but touch sensitive areas of packfile management, particularly around window handling and pack closing.
