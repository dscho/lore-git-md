Packfile refactoring series (4/8): Fixes object count approximation in presence of MIDX.

This patch addresses two issues in how Git approximates total object counts when MIDX files are present. First, it properly accounts for objects in all layers of an incremental MIDX chain by including `num_objects_in_base`. Second, it avoids double-counting objects by skipping packfiles that are already covered by an MIDX. The changes affect three relatively minor areas: commit-graph progress display, hash abbreviation length calculation, and repack memory estimation.

The patch converts the code to use `repo_for_each_pack()` and switches to `odb_prepare_alternates()` for proper object database preparation. The changes are straightforward with a clean 4-line diff, though the commit message notes the practical impact is limited since object count approximation is only used in non-critical paths. This continues the series' pattern of maintaining behavior while modernizing packfile infrastructure.

Key technical details:
- Adds `num_objects_in_base` summation for MIDX chains
- Skips packs with `p->multi_pack_index` set
- Uses new iterator pattern with `repo_for_each_pack()`
- Affects `repo_approximate_object_count()` in packfile.c
- Maintains behavior in commit-graph, abbreviation, and repack code
- Builds on previous packfile store preparation work

The patch appears well-justified and low-risk, addressing clear edge cases in the object counting logic while fitting naturally into the larger refactoring effort.
