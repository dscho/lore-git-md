Feature patch for atomic ref updates in `git replay`.

This patch changes `git replay`'s default behavior to perform atomic reference updates directly rather than outputting commands for `git update-ref`. The new `--ref-action` option provides backward compatibility with the old pipeline workflow via `--ref-action=print`.

The implementation uses Git's ref transaction API to ensure atomic updates (all-or-nothing behavior) and introduces a new `handle_ref_update()` helper to avoid code duplication between update and print modes. The patch includes thorough documentation updates and test coverage for both the new atomic behavior and backward compatibility.

This is part of a reviewed and approved series (now at v5) that has addressed all technical feedback from multiple maintainers. The changes follow Git's standard patterns and are production-ready, though the command remains marked as experimental. The atomic update behavior is particularly valuable for server-side operations where process coordination overhead was previously required.
