Patch review in ongoing SHA-1/SHA-256 interoperability series (Rust implementation)

This is patch 11/14 in the second version of a series introducing Rust code to handle Git's new loose object format for hash algorithm interoperability. The patch adds core hashing functionality in Rust, implementing a `Hasher` struct that wraps Git's C hash functions with safe Rust interfaces.

Ezekiel Newren provides a detailed review of the implementation, focusing on naming conventions and safety semantics. He suggests renaming `Hasher` to avoid confusion with Rust's standard library trait (proposing `CryptoHasher` or `SecureHasher` as alternatives). He also questions the utility of the `is_safe()` method, noting that Rust's `unsafe` blocks are about compiler verification rather than runtime behavior.

The patch itself (from brian m. carlson) introduces comprehensive hashing support including:
- Safe FFI wrappers for Git's hash algorithms
- `Write` trait implementation for streaming data
- Clone/Drop implementations for memory safety
- Thorough test coverage for both SHA-1 and SHA-256 cases

This appears to be a well-constructed piece of infrastructure code, though the naming and safety interface questions raised suggest some refinement may be needed before final acceptance. The review discussion shows active engagement with Rust idioms and safety considerations as this foundational work progresses.
