This is the seventh patch in an 8-part refactoring series consolidating packfile management in Git's packfile store abstraction. The patch focuses on MRU (most-recently-used) list handling when adding packfiles.

The change makes packfile MRU list management more consistent by always adding new packs to the MRU list when they're added to the store, rather than waiting until their objects are first accessed. This eliminates an inconsistency where some subsystems were manually adding packs to the MRU while others weren't. The patch removes the explicit MRU addition from `midx.c` since it's now handled automatically in `packfile_store_add_pack()`.

While this change makes MRU population more consistent, it doesn't yet allow removing `packfile_store_prepare_mru()` because the initial addition order remains non-deterministic. The MRU list still needs explicit sorting to maintain the existing behavior where local packs appear first, sorted by modification time.

The diff is minimal changes - removing one MRU addition in `midx.c` and adding one in `packfile.c`. This continues the series' pattern of mechanical but careful refactoring, maintaining all existing behavior while simplifying the code structure. The change helps unify packfile management under the store abstraction by making MRU handling more predictable.
