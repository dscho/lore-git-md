This is part 3/8 of a refactoring series for Git's packfile subsystem, continuing the work to abstract packfile management into a dedicated store. The patch focuses on the HTTP protocol implementation, which temporarily stores fetched packfiles before adding them to the repository.

Patrick Steinhardt refactors the HTTP subsystem to use the new `packfile_list` structure introduced in patch 2, replacing direct manipulation of `packed_git` linked lists. The changes affect HTTP push, walker, and fetch operations, with modifications to several core HTTP files. The patch introduces some temporary code duplication (notably between `packfile_list_find_oid()` and `find_oid_pack()`) that will be cleaned up later in the series.

The changes are mechanical but wide-ranging, updating all HTTP-related packfile handling to use the new API. This continues the series' pattern of moving global state into the packfile store while maintaining existing behavior. The patch appears well-contained and follows the established refactoring approach from earlier parts of the series.
