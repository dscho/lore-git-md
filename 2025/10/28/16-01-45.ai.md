Bugfix addressing GPG signature stability in SHA-1/SHA-256 compatibility tests. This patch follows up on the thread investigating intermittent test failures in t1016-compatObjectFormat.sh, where SHA-1 signatures were producing different hashes despite identical inputs.

The key fix modifies the GPG wrapper script to properly freeze timestamps by adding an exclamation mark to the `--faked-system-time` parameter. This prevents minute timing variations during heavy system load from causing signature differences. The patch includes both the code change and documentation explaining the test relies on this deterministic behavior.

The author confirms this resolves the flakiness when running with `--stress`. The solution maintains the test's original purpose of comparing identical content across hash algorithms while acknowledging future GPG changes might require deeper verification logic. The changes touch the test script and its GPG wrapper helper.

This appears to be the definitive solution to the SHA-1 signature instability issue identified in the thread discussion, though it leaves open the question of why GPG's SHA-1 implementation exhibits this behavior while SHA-256 remains stable. The patch is narrowly focused and well-explained, with clear justification for the change.
