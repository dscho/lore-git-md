This is a technical discussion in the SHA-1/SHA-256 interoperability patch series, focusing on Rust/C interface safety. Patrick Steinhardt is reviewing patch 06/14 which adds hash algorithm lookup functions.

The patch introduces two key pieces: a C function `hash_algo_ptr_by_offset` that returns a hash algorithm struct based on a numeric offset, and a Rust wrapper `hash_algo_ptr` that calls it through FFI. Patrick raises two concerns about the current implementation:

1. Safety: The C function lacks bounds checking on its input parameter, risking out-of-bounds array access if called with an invalid algorithm ID. This is particularly relevant since the function will be called from Rust code.

2. Future direction: He suggests using `bindgen` (a Rust tool to generate FFI bindings from C headers) for these declarations, which would allow returning the actual `git_hash_algo` struct rather than a void pointer. This would provide better type safety in the Rust/C interface.

The discussion continues the thread's theme of carefully designing the boundary between Rust and C code, with Patrick advocating for stronger safety guarantees and more maintainable FFI patterns. This is part of the broader effort to introduce Rust infrastructure for Git's new object storage format while maintaining compatibility with existing C code.
