This is a technical refinement in the ongoing SHA-1/SHA-256 interoperability series, specifically addressing Rust/C FFI interactions around hash algorithm handling.

Junio Hamano provides review feedback on patch 6/14, which adds Rust/C interoperability for accessing hash algorithm structures. The patch introduces a C function `hash_algo_ptr_by_offset` that returns a pointer to a hash algorithm struct given its numeric ID, with corresponding Rust bindings.

Key points raised in the review:
1. The function name "by_offset" is questioned as being too implementation-specific, since callers shouldn't need to know the array-based storage detail.
2. There's potential confusion between the numeric "hash_algo" ID and the struct pointer both being referred to with similar terminology.
3. The choice to use a void pointer (`*const c_void`) rather than a properly typed struct pointer is noted as surprising, given that previous patches used proper type conversions.

The feedback suggests the naming and typing could be clearer, but doesn't challenge the core functionality. This appears to be part of the ongoing refinement of the Rust/C boundary in this series, where implementation details are being polished based on review. The patch itself is straightforward technically, but the naming and typing choices warrant discussion to establish clear patterns for future FFI code.
