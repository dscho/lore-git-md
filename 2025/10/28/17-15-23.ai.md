This is a follow-up in the thread about GPG signature stability in the t1016-compatObjectFormat test. Junio C Hamano acknowledges Eric W. Biederman's discovery that adding an exclamation mark to GPG's `--faked-system-time` parameter properly freezes timestamps, resolving the intermittent test failures. The issue stemmed from GPG's SHA-1 signature generation being sensitive to minuscule timestamp differences under heavy load, while SHA-256 signatures remained stable.

Hamano expresses frustration at GPG's obscure documentation requiring the exclamation mark syntax, but appreciates Biederman's quick root cause analysis. He confirms the fix by removing his earlier proposed band-aid patch that would have disabled the flaky tests rather than solving the underlying issue.

The solution modifies both the test script and GPG wrapper helper to use `--faked-system-time=...!` to ensure completely deterministic signature generation. This maintains the test's original purpose of comparing identical content across hash algorithms while eliminating the flakiness that occurred during `--stress` runs. The thread confirms the test was correctly detecting a real behavioral difference in GPG's SHA-1 versus SHA-256 signature generation.
