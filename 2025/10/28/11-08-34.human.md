This is the fourth patch in an 8-part refactoring series for Git's packfile subsystem. It fixes two issues in how Git approximates object counts when both packfiles and multi-pack indices (MIDX) are present.

The patch corrects two counting problems: (1) MIDX layers weren't properly accounting for objects in parent layers, and (2) objects were being double-counted when they appeared in both an MIDX and a packfile. The fixes ensure more accurate object count approximations, though the impact is minor - it only influences progress displays, hash abbreviation lengths, and repack memory estimates.

The changes are straightforward: adding `num_objects_in_base` to include parent layer counts, and skipping packfiles that have an associated MIDX to prevent double-counting. The patch also modernizes the code by using newer helper functions like `repo_for_each_pack()` and `odb_prepare_alternates()`.

This continues the series' pattern of careful refactoring while maintaining behavior, with this particular fix being a nice-to-have cleanup rather than a critical correction. The changes are well-contained to packfile.c and build on the infrastructure introduced in earlier patches.
