This is the final version of a feature series making atomic reference updates the default behavior in `git replay`. The patch series has gone through multiple rounds of review and is now ready for merging, having addressed all feedback from maintainers and reviewers.

The key changes in v5 are minor refinements based on final review comments:
- Added trailing comma to enum definition for future extensibility
- Standardized error message formatting with quoted ref names
- Extracted config parsing into helper functions for cleaner code organization
- Improved test suite hygiene by switching to `test_grep` and better isolation
- Fixed documentation terminology and wording
- Reverted an incidental whitespace change to match Git's style conventions

The implementation uses Git's ref transaction API to provide atomic updates by default, with an option (`--ref-action=print`) to show what would be updated without making changes. The series also adds a `replay.refAction` config option to set the default behavior.

All technical concerns from reviewers have been addressed, and the series has maintainer approval pending these final polish commits. The changes are well-tested with comprehensive coverage in t3650-replay-basics.sh. This represents the conclusion of the RFC-to-production transition for atomic reference updates in `git replay`.
