This is the final patch in the atomic ref updates series for `git replay`, adding a configuration option to set the default ref update behavior. The patch introduces `replay.refAction` config with two values: "update" (default atomic behavior) and "print" (pipeline output mode). The command-line `--ref-action` option takes precedence over the config setting.

The implementation follows Git's standard config precedence pattern, with clear error handling for invalid config values. The patch includes comprehensive tests verifying:
- Config option parsing and validation
- Default behavior when unset
- Command-line override capability
- Error handling for invalid values
- State cleanup in tests

The config option provides a persistent way for users to set their preferred mode while maintaining the ability to override it per-invocation. The documentation clearly explains the relationship between the config and command-line options, addressing earlier feedback about interface clarity.

This completes the series' transition from experimental RFC to production-ready feature, with all reviewer feedback addressed and final approval from the maintainer.
