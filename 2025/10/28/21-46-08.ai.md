Feature implementation for atomic ref updates in `git replay`.

This patch (2/3 in the series) changes `git replay`'s default behavior from outputting ref update commands to performing atomic ref updates directly. The implementation uses Git's ref transaction API (`ref_store_transaction_begin`, `ref_transaction_update`, `ref_transaction_commit`) to ensure all-or-nothing behavior. The original pipeline output can still be obtained with `--ref-action=print`.

Key technical details:
- Introduces `enum ref_action_mode` with `REF_ACTION_UPDATE` (default) and `REF_ACTION_PRINT` values
- Extracts ref update logic into `handle_ref_update()` helper function that works for both modes
- Updates documentation to reflect new default behavior and `--ref-action` option
- Modifies tests to use `--ref-action=print` where needed while adding new tests for atomic behavior
- Includes bare repository testing to verify server-side use case
- Maintains backward compatibility through the print mode option

The patch follows the series' established patterns and addresses all prior review feedback, with clean separation between the core replay logic and ref update handling. The implementation is production-ready with comprehensive test coverage of both atomic and print modes.
