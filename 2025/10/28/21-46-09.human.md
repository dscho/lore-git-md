Feature patch adding config option for `git replay` ref updates.

This final patch in the atomic ref updates series for `git replay` introduces a `replay.refAction` config option to set the default reference update behavior. The option mirrors the existing `--ref-action` command-line flag, accepting either "update" (default atomic behavior) or "print" (pipeline output mode). Command-line arguments still override the config setting, following Git's standard precedence rules.

The implementation adds config parsing logic in `builtin/replay.c` with proper validation, plus comprehensive tests verifying:
- Config option precedence over defaults
- Command-line override of config
- Error handling for invalid values
- Behavior in both regular and bare repos

Documentation includes a new config file explaining the option. The patch has been reviewed by multiple maintainers (Junio Hamano, Elijah Newren, Christian Couder, Phillip Wood) and addresses all prior feedback. It completes the production-ready implementation of atomic reference updates for `git replay`, giving users both temporary (via flag) and persistent (via config) control over the update behavior.
