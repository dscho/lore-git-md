This is a review response in the ongoing SHA-1/SHA-256 interoperability series, focusing on patch 12/14 which introduces a new binary loose object map format. Patrick Steinhardt raises several substantive questions about the design choices in the proposed format.

The review questions whether "loose object map" is the right name given the format's broader purpose of storing mappings for non-loose objects like shallows and submodules. It also probes technical details of the format specification, including:
- Whether the legacy format can be dropped entirely
- Clarification needed about which hash function is used for checksums
- Concerns about putting format documentation in `git-pack-objects` instead of `git-repack`
- Implementation questions about header parsing, NUL byte alignment, and object name disambiguation

Most significantly, Steinhardt proposes an alternative design approach using separate lookup tables per hash format, explaining how it could reduce storage overhead while maintaining efficient lookups. The suggestion is framed as a discussion starter rather than a demand, inviting the author to explain the rationale behind the current design.
