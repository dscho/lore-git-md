Junio C Hamano weighs in on the Rust implementation details in patch 4/14 of the SHA-1/SHA-256 interoperability series. This patch introduces a Rust `ObjectID` struct that mirrors Git's C implementation for object IDs.

Hamano questions two aspects of the current approach: the per-file GPL license headers in Rust code (noting this differs from C code style) and whether `src/` is the right directory name for Rust code long-term. He suggests these might need separate discussion.

On the technical design, Hamano considers Patrick Steinhardt's proposed enum-based alternative for `ObjectID` but expresses concerns about C interoperability. He notes the current struct-with-array approach more clearly matches the C memory layout, making FFI safety more obvious, though potentially sacrificing some Rust type safety benefits.

This continues the thread's ongoing discussion about balancing Rust idioms with C compatibility requirements in Git's first major Rust code introduction. The exchange shows careful consideration of implementation choices with maintainability and safety tradeoffs.
