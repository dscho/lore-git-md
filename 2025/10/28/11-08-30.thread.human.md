This thread covers an 8-part series refactoring Git's packfile subsystem as part of the ongoing packfile store abstraction effort. The changes systematically modernize how Git manages packfiles while maintaining existing behavior, preparing for deeper integration with the object source layer.

The series has progressed through several key steps: replacing custom hashmap usage with `strmap`, introducing a new `packfile_list` API, updating HTTP and MIDX handling to use the new interfaces, and simplifying object lookup in `pack-objects`. The latest patch (v6) moves core packfile list management into the `packfile_store` structure, replacing direct linked list traversal with the new API. This eliminates the `next` pointer from `struct packed_git` entirely and introduces cleaner iteration patterns via `repo_for_each_pack`.

Patrick Steinhardt is leading this effort, with the changes touching sensitive areas like window scanning, pack closing, and bad object checks. The work builds toward patch 8's planned consolidation of MRU and mtime-sorted packfile lists. While the changes are largely mechanical, they systematically replace legacy patterns with more maintainable abstractions without altering functionality. The series targets Git v2.51.2 and represents another step in the long-term packfile store work that has been progressing through multiple release cycles.
