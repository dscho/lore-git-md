This thread covers an 8-part refactoring series that restructures Git's packfile management as part of the ongoing packfile store abstraction effort, plus a subsequent MIDX object counting fix. The work is led by Patrick Steinhardt with reviews from Taylor Blau and Toon Claes.

The series progressively simplifies packfile list management, eliminating separate MRU lists in favor of a unified system while maintaining compatibility. Key changes include introducing a new `struct packfile_list` API, fixing MIDX object counting, and updating HTTP protocol handling. Taylor Blau has reviewed most patches positively while suggesting optimizations, particularly around alternates handling and pack-objects caching. Toon Claes raised API design questions about the `packfile_list_find_oid()` interface and the purpose of the `last_found` cache.

In the latest exchange, Taylor Blau follows up on his earlier review of patch 5/8, providing technical justification for removing a `(void *)1` sentinel check in the packfile iteration logic. He argues this check is unnecessary given how `repo_for_each_pack()` behaves, addressing Toon's request for better documentation of the caching behavior. The discussion shows the careful API scrutiny this foundational refactoring is receiving, with Taylor building on his earlier optimization suggestions.

The series appears largely complete, with only minor documentation clarification remaining from Toon's review. Patrick has addressed all substantive feedback, and the changes maintain behavioral compatibility while modernizing the infrastructure for future per-source list changes. The work targets Git v2.51.2 as part of the broader packfile store abstraction effort.
