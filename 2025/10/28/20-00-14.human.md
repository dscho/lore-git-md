This is a technical review response in the ongoing SHA-1/SHA-256 interoperability series introducing Rust code to Git. Junio C Hamano examines patch 5/14, which implements a hash algorithm abstraction in Rust.

Junio notes two key observations about the implementation:
1. The `ObjectID` methods `as_slice()` and `as_mut_slice()` handle unknown hash algorithms by returning the full hash array rather than erroring out, which he finds surprising. This suggests the code may need to be more strict about invalid algorithm IDs.
2. He observes that the Rust implementation appears to be a fairly complete rewrite of the existing C code in `hash.h`, including even the `block_size` functionality that's only used in `receive-pack.c` for push certificates.

The response doesn't raise any major objections but highlights these subtle design choices that might warrant discussion. This fits with the thread's established pattern of careful technical review of the Rust/C FFI boundary and algorithm abstractions.
