This is the seventh patch in an 8-part refactoring series modernizing Git's packfile management as part of the packfile store abstraction effort. The patch focuses on making packfile MRU (most-recently-used) list handling more consistent.

The change ensures all packfiles are immediately added to the MRU list when they're added to the packfile store, rather than waiting until their objects are first accessed. This eliminates an inconsistency where some subsystems were manually adding packs to the MRU list while others weren't. The patch removes the explicit MRU addition from MIDX pack preparation since it's now handled automatically, and adds the MRU append operation to the core packfile addition function.

While this makes the MRU list more complete, the patch notes that the sorting behavior still requires special handling via `packfile_store_prepare_mru()` since the initial addition order isn't deterministic. The changes are minimal (just 3 lines modified across two files) but important for maintaining consistent behavior as the packfile store abstraction takes shape.

This continues the series' pattern of carefully restructuring packfile management while preserving existing functionality, with the changes touching sensitive areas of the MIDX and packfile handling code. The patch appears well-contained and builds logically on the previous infrastructure changes in the series.
