This is a translation (l10n) patch in Christian Couder's series to mark error/warning messages for internationalization. Junio C Hamano provides a brief review of patch 3/5, which focuses on `builtin/fast-export.c`.

The patch wraps 77 previously untranslated error and warning messages in `_()` gettext calls, completing the internationalization coverage for fast-export's user-facing output. Changes include:
- Standardizing error messages about unknown modes (signing, tag filtering, reencoding)
- Translating blob/tag/commit handling failures (read errors, oid mismatches)
- Wrapping signature handling warnings and export failures
- Marking messages about corrupt mark files and object type mismatches

Junio suggests considering whether to downcase some "Unknown"/"Unexpected" strings for consistency, and approves the improved error function argument indentation. The changes maintain existing error handling logic while enabling translation. This is part of the broader effort to standardize i18n across Git's command output, following similar work in fast-import and gpg-interface components.

The patch appears mechanically sound - it systematically wraps all remaining error paths without altering their behavior. The only open question is Junio's stylistic suggestion about capitalization, which doesn't block the technical correctness of the translation work.
