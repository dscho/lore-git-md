This is the third patch in an 8-part refactoring series moving packfile management into a dedicated store. The patch focuses on the HTTP subsystem, converting it to use the new `packfile_list` API introduced in patch 2.

The changes update HTTP-related code (http-push.c, http-walker.c, http.c) to track temporary packfiles using `struct packfile_list` rather than direct `packed_git` pointer manipulation. Key technical changes include:
- Replacing `find_oid_pack()` calls with new `packfile_list_find_oid()`
- Converting `struct repo` and `struct alt_base` to store `packfile_list` instead of raw `packed_git` pointers
- Updating packfile installation/removal to use `packfile_list` API methods
- Adding temporary code duplication that will be cleaned up later in the series

The patch maintains all existing HTTP protocol behavior while preparing for the eventual removal of `packed_git->next` pointers. It follows the series' pattern of incrementally moving packfile management into the store abstraction, with this piece focusing specifically on HTTP's temporary pack handling during fetches.
