Rust version policy discussion in cbindgen integration thread. This email from Ezekiel Newren weighs in on the ongoing debate about minimum Rust version requirements for Git's cbindgen support. 

The discussion stems from Brian M. Carlson's earlier proposal to set the minimum Rust version based on what's available in Debian stable and oldstable releases. Junio Hamano had tentatively agreed with this approach, noting that oldstable (bookworm) provides Rust 1.63. Newren strongly supports this position, arguing that Rust 1.49 (Git's current target version) is too old and would make cbindgen integration difficult or impossible.

The email is brief but significant as it adds another voice to the version policy discussion, which has become a prerequisite for finalizing the cbindgen integration work. Newren's practical experience with cbindgen lends weight to the argument for raising the minimum Rust version, though no final decision has been made yet. The thread continues to show how infrastructure choices in Git's Rust integration have broader implications for version compatibility and maintenance.
