This is a bugfix patch addressing intermittent test failures in the SHA-1/SHA-256 compatibility tests. Eric W. Biederman identifies and fixes a subtle issue with GPG signature generation that was causing non-deterministic test behavior.

The core problem stems from how GPG handles timestamps in signatures. While the test already used `--faked-system-time` to try to make signatures deterministic, Biederman discovered this wasn't fully effective - GPG could still use slightly different timestamps when the system was heavily loaded. The fix adds an exclamation mark to the timestamp argument (`'20230918T154812!'`), which forces GPG to completely freeze its time handling.

The patch includes both the code change (modifying the GPG wrapper script) and documentation explaining why this timestamp freezing is necessary for the test's validity. Biederman notes this solution may need revisiting if future versions of GPG change their signature generation behavior, but considers the current approach sufficient.
