This is a review response discussing a patch series that adds worktree support to `git refs migrate`. Patrick Steinhardt provides feedback on Sam Bostock's implementation for migrating ref storage formats in repositories with linked worktrees.

The review focuses on several key technical concerns. Patrick questions the need for creating commondir files in temporary migration directories, suggesting the information should already be available to the process. He also expresses concern about the implementation being too intimate with backend details, arguing that migration logic should be more self-contained within the backends themselves.

Patrick proposes an alternative approach structure: 1) preparatory backend changes, 2) refactoring migration into a reusable function, and 3) implementing worktree iteration. He suggests the backup/restore mechanism might be unnecessary since data isn't lost during the rename operations, only potentially left in an inconsistent state.

The review also notes some documentation phrasing could be improved to be more general rather than specifically calling out worktree support. Overall, while Patrick acknowledges the value of the feature, he recommends significant restructuring of the implementation to better separate concerns and potentially simplify the approach.
