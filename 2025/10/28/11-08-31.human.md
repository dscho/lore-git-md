This is the first patch in an 8-part refactoring series that's part of the ongoing packfile store abstraction effort. It simplifies how Git tracks packfiles by name by replacing a custom hashmap implementation with Git's built-in `strmap` type.

The change is straightforward - instead of manually managing hashmap entries stored within each `packed_git` struct, the patch uses `strmap` which handles string keys automatically. This removes about 20 lines of code, including a custom comparison function, while maintaining the same functionality. The packfile name lookup behavior remains identical, just implemented more cleanly.

As the first step in a larger series, this appears to be a well-contained, low-risk change that modernizes the code without introducing new behavior. The commit message clearly explains the change and the diff shows careful attention to updating all relevant callers. This sets a good foundation for the more substantial packfile management changes that follow in later patches.
