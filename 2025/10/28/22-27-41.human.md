Documentation patch aligning `git bisect` usage strings and manual pages, while adding missing documentation for the `next` subcommand.

Ruoyu Zhong submits a patch to synchronize the usage strings in `builtin/bisect.c` with the documentation in `git-bisect.adoc`. The changes make the command-line help and manual page consistent, including properly documenting all subcommands. Notably, this adds documentation for the previously undocumented `git bisect next` subcommand, which explicitly requests the next bisection step (normally done automatically after marking revisions).

The patch also moves the subcommand synopsis to the SYNOPSIS section where it belongs, fixing a test that checks for this structure. The changes are straightforward and uncontroversial, with clear motivation from both the commit message and linked discussion. This appears to be a well-scoped documentation improvement that closes a small but noticeable gap in the `git bisect` interface.
