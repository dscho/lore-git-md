This is a technical discussion about Rust type representation in the SHA-1/SHA-256 interoperability series. Patrick Steinhardt responds to patch 04/14's introduction of a Rust `ObjectID` struct with a proposed alternative implementation.

The email focuses on two main points: First, Patrick questions the inclusion of a full GPL header in the new Rust file when C files typically don't have them, suggesting consistency with existing practice. Second, and more substantially, he proposes an enum-based alternative to the current `ObjectID` struct that would provide stronger type safety by distinguishing SHA-1 and SHA-256 variants at the type level.

The enum approach would make the hash algorithm explicit in the type system rather than using a runtime `u32` field, potentially catching more errors at compile time. However, Patrick acknowledges this might introduce implementation complexity, leaving the tradeoff as an open question for discussion. This continues the thread's ongoing theme of carefully designing the C/Rust boundary interfaces.

- Discussion touches on type safety vs. implementation complexity tradeoffs
