Refactoring patch in a packfile store abstraction series.

This is the first patch in an 8-part series refactoring Git's packfile management. It replaces a custom hashmap implementation for tracking packfiles by name with Git's standard `strmap` utility. The change simplifies the code by eliminating a custom comparison function and directly using pack names as keys in the strmap. 

The patch changes:
- Replaces `hashmap` with `strmap` in the packfile store struct
- Removes the custom `pack_map_entry_cmp` function
- Updates all pack lookup and storage code to use strmap APIs
- Renames the map field from `map` to `packs_by_path` for clarity

This appears to be a straightforward quality-of-life improvement that reduces custom code while maintaining identical functionality. The change is part of a larger effort to abstract packfile storage, with subsequent patches handling more complex aspects of pack management. The diff shows significant line reduction (22 lines removed vs 6 added) by leveraging existing strmap infrastructure.
