This thread introduces a security-focused patch series that aims to prevent arbitrary code execution via Git hooks in untrusted repositories. The proposal builds on prior discussions about `safe.directory` protections and introduces two key mechanisms: a `--assume-unsafe` flag that treats all repositories as potentially unsafe by default, and a `safe.assumeUnsafe` config option for persistent enforcement. A `--allow-unsafe` flag provides temporary bypass capability when needed.

The series includes significant refactoring of the safety checking code, with function renames for clarity and restructuring of safety test priorities. The motivation demonstrates a concrete attack vector where a malicious zip file containing a Git repo could trigger code execution. The implementation touches core repository setup code and adds comprehensive tests in a new test script, with careful commit separation and thorough test coverage. The changes appear well-considered to provide stricter safety checks while maintaining workflow flexibility.
