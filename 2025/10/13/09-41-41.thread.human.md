This security-focused patch series from Michael Lohmann addresses the risk of arbitrary code execution via Git hooks in untrusted repositories, building on prior `safe.directory` hardening work. The v3 series is now complete with all review feedback addressed, providing both temporary and persistent mechanisms to control repository safety.

The series starts with preparatory refactoring (renaming functions like `ensure_safe_repository()` and reordering safety checks) before introducing the new security features. The key additions are a temporary bypass mechanism (`--allow-unsafe` flag and `GIT_ALLOW_UNSAFE` env var) in patch 4, and now in the final patch, persistent configuration options (`--assume-unsafe`, `GIT_ASSUME_UNSAFE`, and `safe.assumeUnsafe`) that prevent Git from automatically trusting user-owned repositories.

The implementation maintains strict security by preventing repositories from marking themselves as safe via local config. All changes are well-contained in security-sensitive paths (`setup.c`, `git.c`) with comprehensive test coverage in a new test script. Documentation has been thoroughly updated, with D. Ben Knoble and Junio Hamano's review suggestions incorporated throughout the series.

With all technical and documentation concerns resolved across the five patches, this appears ready for integration. The series provides a complete solution combining temporary workarounds with persistent safety controls, significantly hardening Git against hook-based attacks in untrusted repositories.
