This is the final version of a feature patch series that makes atomic reference updates the default behavior for `git replay`. The series has evolved through extensive mailing list discussion and now has consensus on all technical decisions.

The key change is switching from outputting ref update commands (requiring piping to `git update-ref`) to performing atomic ref updates directly by default. This better serves the primary server-side use case while maintaining backward compatibility through a new `--update-refs=<mode>` option with two modes:
- `yes` (default): atomic ref updates
- `print`: traditional command output for piping

The implementation uses Git's ref transaction API to ensure all updates succeed or none do. The series includes comprehensive test coverage, documentation updates, and a new `replay.defaultAction` config option for users who prefer the traditional behavior as their default.

The patches are well-organized with clear commit messages acknowledging contributors. The test suite has been enhanced to verify atomic behavior, bare repository support, and equivalence between traditional and atomic update methods. The series appears ready for final maintainer approval.
