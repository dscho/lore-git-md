This is a discussion about replacing the deprecated `git whatchanged` command in a file mtime preservation script. Kristoffer Haugsbakk responds to Roy Lomicka's PowerShell script that uses `git whatchanged` to set file modification times based on commit dates.

The email provides a recommended replacement using `git log --no-merges --raw` which should produce equivalent output in most cases, except when processing empty commits (those with no changes from their parent). Kristoffer notes this edge case might matter for scripted usage like Roy's mtime preservation tool, though it's unlikely to affect interactive use.

The discussion highlights the ongoing deprecation of `git whatchanged` and the need for users to update their workflows. Kristoffer's response is technical but practical, offering both a simple substitution and deeper analysis of when the replacement might differ in behavior. The exchange demonstrates careful consideration of backward compatibility during command deprecation.
