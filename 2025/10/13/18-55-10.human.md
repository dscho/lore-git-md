This is a user report about the deprecated `git whatchanged` command and a workaround script for preserving file modification times.

Roy Lomicka shares a PowerShell script that uses `git whatchanged` to set file modification times based on commit timestamps. The script parses `whatchanged` output (using `--reverse --pretty=%at` format) to track the most recent commit time for each file and updates the filesystem mtime accordingly.

The email notes that `git whatchanged` is slated for removal unless users actively indicate they still need it by using the `--i-still-use-this` option. Lomicka's script appears to be a practical workaround for users who rely on commit-based timestamps, though the approach is somewhat fragile as it depends on parsing `whatchanged` output format.

The script demonstrates a real-world use case for `whatchanged`, suggesting there may be users who haven't fully transitioned to alternatives like `git log`. The implementation handles edge cases like empty lines and missing files, though it's Windows-specific (using PowerShell and .NET filesystem APIs). This could be useful input for the Git maintainers evaluating whether to keep `whatchanged` or provide alternative functionality.
