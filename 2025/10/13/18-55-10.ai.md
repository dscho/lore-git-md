This is a user report about the deprecated `git whatchanged` command and a workaround script for preserving file modification times.

Roy Lomicka shares a PowerShell script that uses `git whatchanged` to set file modification times based on commit timestamps. The script parses `git whatchanged --reverse --pretty=%at` output, extracting commit timestamps and applying them as file mtimes. This serves as a workaround for Git's lack of native mtime preservation.

The email highlights that `git whatchanged` is slated for removal unless users explicitly opt-in with `--i-still-use-this`. Lomicka's script demonstrates a real-world use case where this command provides functionality not easily replaceable by other Git commands. The script handles the output format carefully, skipping empty lines and properly parsing both commit timestamps and file paths.

The submission serves both as a usage report (showing someone still depends on this command) and as a technical contribution (providing a concrete example of why the command might be valuable to preserve). The script appears to be functional PowerShell code that solves a specific problem some users might face when working with file timestamps in Git repositories.
