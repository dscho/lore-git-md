This thread examines a documentation and implementation discrepancy in Git's patch-id functionality, where the documentation specifies SHA-1 while the code respects the repository's hash algorithm (supporting SHA-256 since Git 2.29). Outreachy participant Okhuomon Ajayi initially raised the issue, sparking a technical debate between Junio C Hamano and brian m. carlson about the role of hash algorithms in patch IDs.

Junio maintains that patch IDs serve as stable content identifiers rather than security mechanisms, arguing SHA-1 should remain the standard for long-term consistency. brian m. carlson counters with regulatory concerns about SHA-1 deprecation, noting SHA-256 patch IDs are already in use in some repositories. In the latest development, brian proposes a compromise: adding configuration to select the hash algorithm explicitly. This would preserve SHA-1 for historical comparisons while allowing SHA-256 as the default, addressing both stability needs and compliance requirements. The discussion has progressed from identifying the discrepancy to considering concrete solutions that balance technical constraints with real-world usage patterns.
