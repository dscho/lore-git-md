This thread addresses a documentation and implementation inconsistency in Git's patch-id functionality, where the documentation specifies SHA-1 while the code respects the repository's hash algorithm (SHA-1 or SHA-256). The discussion has clarified that patch IDs serve content identification rather than cryptographic purposes, meaning SHA-1 stability is valuable for historical comparisons even as the project moves toward SHA-256.

The key participants are Outreachy contributor Okhuomon Ajayi (who submitted the initial patch), maintainer Junio C Hamano, and hash algorithm expert brian m. carlson. Junio emphasizes preserving SHA-1 stability for patch IDs, while brian proposes a configurable solution (`patchid.hashAlgorithm`) that would default to SHA-256 in SHA-256 repositories while allowing SHA-1 override when needed. Okhuomon's latest email shows growing understanding of these nuanced requirements and plans to revisit the implementation approach.

The emerging solution must balance several needs: maintaining backward compatibility for workflows comparing historical patches, supporting SHA-256 as the default, providing configuration flexibility, and clearly documenting the security/content-hashing distinction. While technical details like the exact configuration syntax remain to be finalized, the discussion has productively narrowed to a solution that could satisfy both stability and forward-compatibility requirements.
