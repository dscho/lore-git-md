This thread addresses a documentation and implementation mismatch in Git's patch-id functionality. The original issue was that while the documentation states patch IDs must use SHA1 hashes regardless of repository configuration, the code could use the configured hash algorithm via `the_hash_algo`. 

Okhuomon Ajayi, an Outreachy participant, submitted an initial patch to enforce SHA1 usage when no algorithm is specified. Junio Hamano reviewed this, noting the solution might be too narrow - the original NEEDSWORK comment suggested broader changes to make all patch ID computation use SHA1. He also raised concerns about safety, as globally setting `the_hash_algo` to SHA1 could interfere with other operations needing the repository's actual algorithm.

In the latest response, Okhuomon acknowledges these concerns and plans to revise the approach. The new version will avoid modifying `the_hash_algo` globally and instead isolate SHA1 usage specifically to patch-ID computation. This better separates the SHA1 requirement for patch IDs from repository-specific hash algorithms. The author also intends to document that this is part of broader standardization work.

While this direction addresses Junio's safety concerns, some open questions remain about whether all patch ID code paths will be covered and whether the isolation from repository operations is complete. The discussion shows good progress in aligning the implementation with both the documentation and Git's hash algorithm architecture.
