Security feature adding temporary bypass for repository safety checks. This is patch 4/5 in a series hardening Git against malicious repository execution.

Michael Lohmann introduces a new `--allow-unsafe` flag and `GIT_ALLOW_UNSAFE` environment variable that let users temporarily bypass `safe.directory` and ownership checks when running Git commands. This addresses the current limitation where users must permanently whitelist unsafe directories via `safe.directory` configuration, which could leave them vulnerable if the repository later becomes malicious.

The implementation adds the new flag to Git's core options, updates documentation, and includes tests verifying the bypass works while maintaining the default safety checks. The patch follows the series' pattern of careful, incremental changes - it builds on the earlier refactoring of safety check infrastructure while keeping behavior changes focused and testable.

A notable detail is the extended error message that now informs users about the temporary bypass option when they hit a safety check failure. The author notes Johannes Schindelin's feedback about maintaining backward compatibility in the message format. The patch appears well-constructed with thorough documentation and implementation, though the test infrastructure question suggests some minor process unfamiliarity.
