This thread centers on Christian Couder's `git replay` series (now at v3), which changes the command's default behavior to perform atomic reference updates rather than outputting update commands. The change addresses both server-side needs for atomicity and scripting compatibility through a new `--update-refs` option with "yes" (atomic) and "print" (legacy stdout) modes, plus a `replay.defaultAction` config option for user preferences.

The implementation uses Git's ref transaction API (`ref_store_transaction_begin`/`update`/`commit`) to ensure all-or-nothing updates, with a new `handle_ref_update()` helper unifying code paths. Reviewers including Patrick Steinhardt, Eric Sunshine, and Junio Hamano shaped the atomic-by-default approach, while Elijah Newren and Phillip Wood verified the config implementation follows Git's patterns. The series has evolved through three versions, with v3 adding standardized option validation and comprehensive tests for lock behavior, config precedence, and mode equivalence.

All prior feedback has been addressed, and the series is ready for integration. The changes align with ongoing ref backend work while maintaining backward compatibility through the print mode, demonstrating careful consideration of both technical and workflow impacts.
