This is part 8/9 of a series adding a `--required` flag for reference optimization operations, focusing on implementing the backend infrastructure for determining when optimization is needed.

The patch adds an `optimize_required` callback to `struct ref_storage_be`, implemented across all three reference backends. The files backend checks via `should_pack_refs()`, the packed backend always returns false (as packed refs are already optimized), and the reftable backend checks compaction requirements. Patrick Steinhardt points out that the reftable implementation should only indicate optimization is needed when there are at least two tables in the stack, which Karthik Nayak acknowledges and will fix by modifying `reftable_stack_compaction_required()` to include this check.

Key technical details:
- New callback signature: `int (*optimize_required)(struct ref_store *, struct optimize_refs_opts *, bool *required)`
- Files backend delegates to existing `should_pack_refs()` logic
- Packed backend trivially returns `false` since packed refs are always optimized
- Reftable backend will be updated to properly check table count before indicating optimization is needed
- Discussion clarifies separation of concerns between backends (packed backend shouldn't check files backend state)

The exchange shows the series nearing completion, with this being one of the last substantive implementation patches before the final user-facing flag addition in patch 9/9. The main remaining work is refining the reftable backend's optimization detection logic per Steinhardt's feedback.
