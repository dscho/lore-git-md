This is the final patch in a 9-part series introducing a `--required` flag for `git refs optimize` and `git pack-refs` to check if optimization is needed without performing it. The feature is primarily aimed at server-side use cases like GitLab's Gitaly service where read operations are cheaper than writes.

The patch implements the user-facing flag and handles reviewer feedback from Patrick Steinhardt. Key discussion points include:
- Naming debate between `--required` (current) vs `--dry-run` or `--check` alternatives
- Documentation updates to use generic "reference store" terminology rather than "pack-refs"
- Explicit return value semantics (0=optimization needed, 1=not needed, other=error)
- Test improvements using `GIT_TEST_REFTABLE_AUTOCOMPACTION` for reftable backend
- Code organization feedback about moving `refs_optimize_required()` to an earlier commit

The implementation looks solid with thorough review consideration. The main outstanding items are documentation polish and test coverage improvements before finalization. This completes the core functionality of the series, which has undergone multiple review iterations addressing naming conventions, error handling patterns, and backend-specific behaviors.
