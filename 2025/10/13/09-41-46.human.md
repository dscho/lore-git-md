Security patch completing a series to prevent arbitrary code execution via Git hooks in untrusted repositories. This final patch introduces the `--assume-unsafe` flag and corresponding `safe.assumeUnsafe` config option to disable the default behavior of treating user-owned repositories as safe. The change addresses a security risk where users could accidentally execute malicious hooks by simply entering a downloaded repository (e.g., from a zip file) and running commands like `git status`.

The patch adds three ways to enforce stricter safety checks:
1. Command-line flag `--assume-unsafe`
2. Environment variable `GIT_ASSUME_UNSAFE`
3. Configuration option `safe.assumeUnsafe`

Notably, the config option cannot be set in the repository's own config (only globally or via command line), preventing repositories from marking themselves as safe. The implementation includes thorough test coverage verifying all three mechanisms and their interactions with the existing `--allow-unsafe` bypass option introduced earlier in the series.

This completes the security hardening effort that began with preparatory refactoring in earlier patches. The series appears well-structured, with clear separation between infrastructure changes and behavior modifications, and maintains backward compatibility while adding the new safety features.
