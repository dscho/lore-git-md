This is the final patch in a series implementing atomic reference updates for `git replay`, adding a configuration option to control the default behavior. The patch introduces `replay.defaultAction` which lets users set their preferred mode (atomic updates or command output) in config rather than specifying it each time.

The config option uses enum-style values (`update-refs` and `show-commands`) for clarity and future extensibility, while maintaining command-line override capability with `--update-refs`. The implementation includes thorough validation - it will error out on invalid config values with a helpful message. The patch comes with comprehensive tests verifying config precedence, value validation, and interaction with command-line flags.

This completes the series' transition from RFC to production-ready code, having addressed all prior feedback about interface design and atomicity guarantees. The config option provides the flexibility users requested while keeping atomic updates as the safe default. The documentation is clear about the mapping between config values and command-line options.
