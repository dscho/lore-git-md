This is a feature patch series for `git replay`, making atomic reference updates the default behavior. The series is in its third iteration, having incorporated feedback from multiple reviewers.

The main change flips `git replay` from outputting reference update commands (which must be piped to `git update-ref`) to performing atomic updates directly by default. This better serves the command's primary use case in server-side operations where atomic updates are critical. The old pipeline behavior remains available via `--update-refs=print`.

Key improvements in v3:
- Simplified API by removing the `--allow-partial` option after determining there were no clear use cases
- Made the interface more extensible with `--update-refs=<mode>` (suggested by Phillip Wood)
- Added a `replay.defaultAction` config option (per Junio's suggestion)
- Improved commit messages and test isolation (based on Elijah and Christian's feedback)
- Added comprehensive test coverage for atomic behavior

The implementation uses Git's ref transaction API to ensure all-or-nothing updates. The series maintains backward compatibility while making the default behavior more suitable for server-side workflows.
