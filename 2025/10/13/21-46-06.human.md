Refactoring patch in a security-focused series about repository safety checks. This is the third patch in a 5-part v2 series addressing arbitrary code execution via Git hooks in untrusted repositories.

The patch reorders the safety checks in `ensure_safe_repository()` to give explicit `safe.directory` configurations higher priority than implicit ownership checks. The change makes the logic more straightforward by checking configured safe directories first before falling back to ownership verification. This also prepares the codebase for easier addition of future safety checks.

The implementation moves the ownership check block to the end of the function and adds an early return if the directory is marked safe via configuration. The change is behavior-preserving but improves code organization for the security work being done in this series. The patch follows good Git development practice by separating refactoring from behavior changes.

This continues the series' pattern of preparatory refactoring before introducing new security features in later patches. The changes are focused and well-contained to `setup.c`, with clear test coverage already established in the series.
