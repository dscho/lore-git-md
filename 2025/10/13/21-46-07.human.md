Security feature adding temporary bypass for repository safety checks. This is patch 4/5 in a series hardening Git against malicious repository execution via hooks.

The patch introduces a new `--allow-unsafe` flag and `GIT_ALLOW_UNSAFE` environment variable that let users temporarily skip the `safe.directory` and ownership checks when running Git commands. This addresses the workflow where users need to run a single command in an untrusted repo without permanently marking it as safe (which could leave them vulnerable if the repo later becomes malicious).

The implementation adds the new option to Git's core command-line interface and environment handling, updates error messages to mention the bypass option, and includes comprehensive tests verifying both the flag and environment variable work as expected. Documentation is added to both the command synopsis and environment variables section.

This appears to be a well-considered addition to the security hardening work, providing a safer alternative to permanently marking directories as safe. The patch follows the series' pattern of separating refactoring from behavior changes and includes thorough test coverage. The documentation clearly warns about the security implications of using the bypass.
