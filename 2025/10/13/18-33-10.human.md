Feature implementation for atomic ref updates in `git replay`. This patch makes atomic reference updates the default behavior for `git replay`, transitioning from the previous approach that output ref update commands to be piped to `git update-ref`. The change addresses server-side workflow efficiency by eliminating process coordination overhead while maintaining backward compatibility through a new `--update-refs=<mode>` option.

The implementation uses Git's ref transaction API (`ref_store_transaction_begin()`, `ref_transaction_update()`, `ref_transaction_commit()`) to ensure all-or-nothing updates. A new `handle_ref_update()` helper centralizes the logic for both direct updates and command output modes. The default mode is now `yes` for atomic updates, with `print` available for the traditional pipeline workflow.

Documentation updates clarify the new behavior and provide examples of both modes. The test suite has been expanded to verify atomic behavior, including tests for bare repositories, atomicity guarantees, and equivalence between pipeline and direct update modes. The changes maintain the experimental status warning while making the command more ergonomic for common use cases.
