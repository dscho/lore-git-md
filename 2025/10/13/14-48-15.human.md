This is a documentation patch in an ongoing thread about introducing a new `gitdatamodel.adoc` man page. The discussion focuses on technical accuracy and pedagogical clarity in explaining Git's core concepts.

Junio Hamano responds to Patrick Steinhardt's earlier corrections about Git's maintenance commands and reference storage hierarchy. The exchange clarifies that modern Git uses `git maintenance run --auto` rather than the older `git gc --auto`, noting this change was introduced in commit a95ce124. This is particularly for tools like `scalar` that may use alternative maintenance strategies.

On reference storage, Junio suggests avoiding the distinction between "root refs" and "pseudo refs" in favor of focusing on the data model's conceptual aspects. He emphasizes that what matters is understanding HEAD as a reference and the existence of symbolic references, rather than their physical storage locations.

The discussion shows careful attention to both technical accuracy (ensuring commands reflect current Git behavior) and pedagogical approach (deciding which implementation details belong in a conceptual overview).
