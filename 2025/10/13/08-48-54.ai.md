This is a test infrastructure patch that refactors GPG-related test prerequisites to be more robust and order-independent. It's part of Christian Couder's v3 series on consistent signature handling across Git commands.

The patch centralizes GNUPGHOME directory creation into a new `prepare_gnupghome()` function, replacing duplicate `mkdir` calls in the GPG, GPGSM, and GPGSSH test prerequisites. This fixes a potential issue where tests could fail if GPGSM/GPGSSH prereqs ran before GPG due to the directory already existing. The function uses `mkdir -p` to safely handle existing directories.

A notable limitation is intentionally not using this new function for GPG2 tests, as doing so would expose hidden bugs in t1016-compatObjectFormat.sh. The patch documents this with a NEEDSWORK comment referencing the known issue. The change builds on prior work from Todd Zullinger and Collin Funk in the signature handling series.

The modification affects test prerequisites in t/lib-gpg.sh, making test execution more reliable when different signature types are involved. This is particularly relevant for the broader series' goal of unified signature handling, as it ensures tests can properly exercise all supported signature formats (PGP, X.509, SSH) regardless of prerequisite evaluation order. The patch maintains all existing functionality while making the test infrastructure more robust.
