This is a refactoring patch in a series introducing a `--required` flag for reference optimization operations. Patch 6/9 modifies the reftable backend to make its compaction logic more reusable.

The change refactors `stack_table_sizes_for_compaction()` to directly return compaction segments rather than just table sizes, eliminating an intermediate step where sizes were passed to `suggest_compaction_segment()`. This prepares for upcoming functionality that will check if optimization is needed without performing it.

Patrick Steinhardt provided minor review feedback on wording and style, all of which Karthik Nayak has accepted for the next revision. The technical approach is sound, with the only discussion being whether to initialize a variable that will always be set before use (Nayak prefers explicit initialization for future-proofing but will remove it per the review).

This is a straightforward internal change that doesn't affect user-facing behavior but enables cleaner implementation of the series' main feature. The patch appears well-considered and has passed technical review with only minor editorial changes needed.
