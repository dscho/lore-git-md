This is the core implementation patch (2/3) in a feature series for `git replay` that changes its default behavior to perform reference updates atomically rather than outputting update commands. The patch introduces atomic ref updates as the new default while maintaining backward compatibility through a new `--update-refs=<mode>` option.

The key technical changes center around using Git's ref transaction API (`ref_store_transaction_begin()`, `ref_transaction_update()`, `ref_transaction_commit()`) to ensure all-or-nothing behavior for reference updates. A new `handle_ref_update()` helper function unifies the code paths between direct updates and the traditional print-to-stdout mode. The implementation maintains support for bare repositories and includes comprehensive test coverage verifying atomic behavior through lock file checks and equivalence testing between pipeline and direct update modes.

Documentation updates thoroughly explain the new default behavior and `--update-refs` option, which accepts either `yes` (atomic updates) or `print` (traditional pipeline output). The tests have been reworked to use `--update-refs=print` where they previously relied on stdout output, while new tests verify the atomic update behavior, bare repo support, and failure cases. The patch properly credits multiple contributors who helped shape the design through prior review feedback.

This change primarily benefits server-side use cases where atomic updates are critical, while preserving the flexibility needed for scripting and testing workflows. The implementation appears well-considered, with careful attention to backward compatibility and test coverage.
