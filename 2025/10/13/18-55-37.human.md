Feature update for `git replay` making atomic ref updates the default. This is part of a well-reviewed series (v3) that changes `git replay` to perform atomic reference updates by default rather than outputting update commands. The patch introduces a new `--update-refs=<mode>` option with "yes" (atomic updates) and "print" (traditional pipeline output) modes, replacing the previous `--output-commands` flag.

The implementation uses Git's ref transaction API to ensure all-or-nothing behavior for reference updates, which is particularly important for server-side operations. A new `handle_ref_update()` helper function consolidates the logic for both update modes. The patch includes thorough test coverage verifying atomic behavior, bare repository support, and equivalence between the traditional pipeline and atomic update methods.

Review feedback from Elijah Newren, Phillip Wood, and others shaped the design, resulting in a cleaner API that maintains backward compatibility while better serving the command's primary use case. The changes follow Git's established patterns and include comprehensive documentation updates. This appears to be a well-executed evolution of the feature based on real-world needs.
