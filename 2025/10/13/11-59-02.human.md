Security patch series completion with documentation feedback.

This is the final patch in a 5-part series addressing security concerns around arbitrary code execution via Git hooks in untrusted repositories. The series builds on prior `safe.directory` work to prevent accidental execution of malicious code when users unwittingly work with repositories from untrusted sources (like downloaded zip files).

The patch adds persistent configuration options to treat user-owned repositories as potentially unsafe by default, complementing the temporary bypass capability introduced earlier. It adds:
- A new `safe.assumeUnsafe` config option
- A `--assume-unsafe` command-line flag
- A `GIT_ASSUME_UNSAFE` environment variable
- Documentation updates and expanded test coverage

D. Ben Knoble provides minor documentation feedback, noting a typo ("arbitrariy" -> "arbitrary") and suggesting "overridden" is more accurate than "overwritten" when describing how `--allow-unsafe` interacts with the new flag. The author had also raised an implementation question about the best way to communicate the unsafe state internally (environment variable vs struct member), which remains unresolved.

The series appears well-structured, with the first three patches doing preparatory refactoring before introducing behavior changes. The final implementation maintains all existing safety checks while adding the new configuration options. With this patch, the series is now ready for review, addressing a clear security concern with comprehensive protection mechanisms.
