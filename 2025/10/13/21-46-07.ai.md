This is the fourth patch in a security-focused series introducing temporary bypass mechanisms for Git's repository safety checks. The patch adds a `--allow-unsafe` command-line option and `GIT_ALLOW_UNSAFE` environment variable that let users temporarily skip the `safe.directory` and ownership verification when running Git commands in potentially untrusted repositories.

The implementation touches several key areas: adding documentation for the new flag and env var in `git.adoc`, updating the environment variable definitions in `environment.h`, modifying the command-line parser in `git.c` to handle the new flag, and updating the safety check logic in `setup.c` to respect the bypass. A new test script `t0036-allow-unsafe-directory.sh` verifies the behavior, including both the command-line and environment variable variants.

The patch maintains security by making the bypass explicitly temporary (per-command) rather than persistent like `safe.directory`. Error messages are updated to inform users about the new bypass option when they encounter ownership issues. The implementation follows Git's standard pattern for command-line flags and environment variables, with clear documentation of the security implications.

This builds on the earlier refactoring in the series (renaming functions and reordering checks) to provide a complete solution for the temporary bypass use case. The test coverage appears thorough, verifying both successful bypass and default rejection behavior. The patch is well-integrated with the existing safety infrastructure while providing a clear escape hatch for trusted-but-technically-unsafe scenarios.
