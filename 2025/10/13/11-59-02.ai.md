This is the final patch in a security-focused series addressing arbitrary code execution via Git hooks in untrusted repositories. The patch adds a persistent configuration option (`safe.assumeUnsafe`) to complement the temporary bypass capabilities introduced earlier in the series.

The patch extends Git's security model by allowing users to disable the automatic trust of repositories owned by the current user, which could otherwise be exploited via malicious repositories (e.g., from downloaded zip files). It introduces three ways to enable this stricter safety check: a new `--assume-unsafe` command-line flag, `GIT_ASSUME_UNSAFE` environment variable, and the `safe.assumeUnsafe` config option. The implementation maintains all existing safety checks while adding these configuration options.

Key technical details include:
- Documentation updates in `safe.adoc` and `git.adoc` explaining the new options
- Expanded test coverage in `t0036-allow-unsafe-directory.sh`
- The patch touches multiple files (setup.c, builtin/clone.c, path.c, setup.h, git.c, environment.h) to implement the new functionality
- One open implementation question remains about whether using an environment variable in `safe_directory_cb()` is optimal versus adding a struct member
