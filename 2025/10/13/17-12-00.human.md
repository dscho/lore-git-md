Junio Hamano responds to a const-correctness fix for the patch-id subsystem, pointing out issues with the proposed solution. This is a technical discussion about callback contracts in Git's hashmap API.

The original patch from an Outreachy participant attempted to fix a const-correctness violation in `patch_id_neq()` by making the diff options parameter const. However, Junio notes this creates a new problem - the options structure must be modified later in the call chain by `diffcore_std()`, so it cannot truly be const. He identifies the deeper issue lies in the hashmap API's callback contract requiring const parameters, even when the data needs modification.

Junio suggests the NEEDSWORK comment (which the patch removed) was correctly noting this architectural tension. The response indicates this isn't a simple const-correctness fix but rather touches on API design questions for the hashmap subsystem. The discussion appears headed toward needing either a hashmap API change or finding another way to handle the non-const requirements while maintaining type safety.
