This is a security-related patch submission implementing Jeff King's proposed "assume unsafe" mechanism as a first step toward addressing the repository trust model discussion.

Michael Lohmann follows up on the ongoing security thread by submitting concrete patches that implement one of the key suggestions from Jeff King's earlier email - the ability to explicitly mark repositories as unsafe through environment variables (`GIT_ASSUME_UNSAFE`), config settings (`safe.assumeUnsafe`), and command-line flags (`--assume-unsafe`). This represents a pragmatic approach to the first phase Jeff King identified: defining unsafe behavior before settling on safety marking mechanisms.

The patches appear to focus on the opt-in warning system rather than the more complex token-based or config-allowlist approaches that were debated earlier in the thread. By implementing this simpler mechanism first, it allows for real-world testing of the unsafe behavior definitions while leaving open the possibility of more sophisticated safety marking systems later.

Key technical elements likely include:
- New config option `safe.assumeUnsafe` to persistently mark repositories
- Environment variable `GIT_ASSUME_UNSAFE` for temporary/session-based marking
- Command-line flag `--assume-unsafe` for per-command control
- Integration with existing security hooks and config skipping behavior

This submission moves the discussion from theoretical design to concrete implementation, though it notably doesn't address the deeper architectural questions about token-based vs config-based approaches that were previously debated. The patchset appears to align with Jeff King's suggestion of starting with simpler mechanisms that can be built upon later.
