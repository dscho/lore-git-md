This is the final patch in a 3-part feature series introducing configurable default behavior for `git replay`'s reference updates. The patch adds a `replay.defaultAction` config option that lets users choose between atomic reference updates (default) or the traditional stdout command output mode.

The implementation reads the config before processing command-line options, mapping config values ("update-refs" and "show-commands") to internal modes ("yes" and "print") that match the existing `--update-refs` CLI option. The command-line flag takes precedence when both are present. The patch includes comprehensive tests verifying config parsing, CLI override behavior, and error handling for invalid config values.

The config option uses descriptive string values rather than booleans to allow future expansion. Documentation in `Documentation/config/replay.adoc` explains the option and its relationship to the CLI flag. Test coverage in `t/t3650-replay-basics.sh` includes scenarios for config-driven behavior, CLI override precedence, and error cases.

This completes the series' transition to atomic updates by default while maintaining script compatibility through both config and CLI options. The implementation follows Git's standard config parsing patterns and includes appropriate error messages. The patch has been reviewed by multiple core contributors (Junio Hamano, Elijah Newren, Phillip Wood) and integrates cleanly with the atomic update infrastructure added in patch 2/3.
