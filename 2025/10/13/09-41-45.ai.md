This is the fourth patch in a security-focused series introducing a temporary bypass mechanism for Git's repository safety checks. The patch adds a new `--allow-unsafe` flag and `GIT_ALLOW_UNSAFE` environment variable that let users temporarily skip `safe.directory` and ownership verification for single commands, avoiding the need to permanently whitelist repositories.

The implementation modifies several key files:
- Adds documentation for the new flag and env var in `git.adoc`
- Defines the new env var constant in `environment.h`
- Implements flag handling in `git.c`
- Modifies `setup.c` to check the env var and skip safety checks when set
- Updates error messages to mention the new bypass option
- Adds a new test script `t0036-allow-unsafe-directory.sh` verifying the behavior

The patch follows the series' careful approach by maintaining all existing safety checks while adding the bypass capability. The test coverage appears thorough, verifying both the flag and environment variable approaches work as expected. One minor implementation note is the decision to append rather than rewrite the error message to maintain compatibility with external tools that might parse it.

This patch represents the first behavior-changing addition to the series after the preparatory refactoring in earlier patches. It provides a practical solution for users who need to occasionally work with untrusted repositories while maintaining security by default. The next patch in the series will presumably introduce the persistent `safe.assumeUnsafe` configuration option mentioned in earlier discussion.
