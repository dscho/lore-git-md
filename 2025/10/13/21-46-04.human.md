This is a refactoring patch that's part of a security-focused series addressing Git hook execution in untrusted repositories. It's the first of five patches in v2 of the series.

The patch renames `ensure_valid_ownership()` to `ensure_safe_repository()` in setup.c, with the rationale that the function does more than just check ownership - it also verifies the "safe.directory" configuration. The new name better reflects the broader safety checks being performed. This is a straightforward rename with no behavior changes, affecting four call sites in the same file.

As part of the larger security series, this preparatory refactoring helps pave the way for subsequent patches that will add new safety mechanisms. The change is well-contained and mechanical, with all tests passing. The commit message clearly explains the motivation for the rename, making this a clean, uncontroversial patch that sets up for more substantive changes to come.
