This is the final patch in a 3-part series implementing atomic reference updates for `git replay`, adding a configuration option to control the default behavior. The patch introduces `replay.defaultAction` which lets users set their preferred ref update mode (atomic updates or command output) via config, while maintaining the ability to override it per-invocation with `--update-refs`.

The implementation reads the config early in `cmd_replay()`, validating values and mapping them to internal modes ('update-refs' -> 'yes', 'show-commands' -> 'print'). Invalid config values trigger immediate error with helpful messaging. The command-line flag takes precedence over the config setting, preserving flexibility to temporarily override defaults.

Key technical aspects include:
- Config values use more descriptive names than CLI flags for clarity
- Enum-based design allows future expansion without breaking changes
- Comprehensive test coverage verifies:
  - Config-driven behavior (both modes)
  - CLI override precedence
  - Error handling for invalid config values
- Documentation clearly explains the option and its relationship to CLI flags

The patch follows the series' established pattern of thorough testing (including atomicity verification via lock files) and maintains clean separation of concerns. It completes the transition to atomic-by-default behavior while providing escape hatches for users who need pipeline output. The enum design satisfies earlier maintainer concerns about forward compatibility.
