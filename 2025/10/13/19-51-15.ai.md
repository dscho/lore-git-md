This is a discussion about replacing the deprecated `git whatchanged` command with `git log` for mtime preservation scripts. Kristoffer Haugsbakk responds to Roy Lomicka's PowerShell script that uses `git whatchanged` to set file modification times based on commit timestamps.

The key technical detail is the proposed replacement command: `git log --no-merges --raw` which should produce equivalent output to `git whatchanged` except in the case of empty commits (commits with no changes from their parent). The thread references prior discussions about this command substitution, noting that empty commits would be the only case where the outputs differ.

Haugsbakk acknowledges the scripted nature of Lomicka's use case makes the edge case of empty commits potentially relevant, though unlikely to matter for interactive usage. The email serves both as a) confirmation that `git log` can serve as a replacement in most cases and b) documentation of the one scenario where behavior would differ.
