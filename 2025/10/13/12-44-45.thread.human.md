This thread discusses the potential removal of the `git whatchanged` command, which has been marked as deprecated with a warning that prompts users to report if they still rely on it. The discussion began when Grzegorz Koperwas followed the prescribed procedure to notify the list of their usage. Kristoffer Haugsbakk responded with background on why the command is considered redundant (it's essentially `git log --no-merges --raw` with different defaults) and offered migration advice, suggesting alternative `git log` flags like `--stat` or `--name-only` that provide similar information in more readable formats.

So far, this is the only reported case of active `git whatchanged` usage since the deprecation warning was introduced. The response maintains a neutral stance on whether the command should be kept, focusing instead on educating users about equivalent functionality available through `git log`. The thread remains open for further reports from other users who might still depend on this command, which will help determine whether it should be removed or maintained despite its redundancy.
