This is a follow-up discussion about the legacy `git whatchanged` command. Kristoffer Haugsbakk responds to Samer Abdallah's note about still using `git whatchanged` by providing a modern equivalent using `git log`. The suggested replacement is `git log <opts> --no-merges --raw`, with additional recommendations to use `--stat` or `--name-only` for better human readability when not processing the output programmatically.

The email is purely informational, offering a helpful tip for those who might still be using the older command. It doesn't propose any changes to Git itself but serves as a practical guide for users transitioning from `git whatchanged` to `git log`. The tone is friendly and constructive, focusing on making the output more readable rather than criticizing the use of the legacy command.
