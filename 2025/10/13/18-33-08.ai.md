This is the final version of a feature patch series implementing atomic reference updates for `git replay`, transitioning from experimental RFC status to a merge-ready state. The series makes atomic ref updates the default behavior while maintaining backward compatibility through configurable output modes.

The key technical aspects include:
- Default atomic behavior via `--update-refs=yes` (replacing previous opt-in approach)
- Simplified command-line interface using `--update-refs=<mode>` enum (yes/print)
- Removal of `--allow-partial` option due to lack of concrete use cases
- New `handle_ref_update()` helper function to reduce code duplication
- Comprehensive test coverage including atomicity verification
- Added `replay.defaultAction` config option for users preferring traditional pipeline output

The implementation uses Git's ref transaction API (`ref_store_transaction_begin()`, `ref_transaction_update()`, `ref_transaction_commit()`) to ensure all-or-nothing behavior. The test suite has been enhanced with proper isolation using `test_when_finished` and includes new tests verifying atomic guarantees.

The series has addressed all feedback from previous iterations, with consensus reached on:
- Performance concerns via batched transactions
- Interface simplification to enum-based design
- Documentation updates reflecting new defaults
- Explicit exclusion of hook/formatting support in current version
- Clear separation between current atomic functionality and potential future extensions

The patches are well-organized with improved commit messages following maintainer feedback, and include acknowledgments of specific contributions via Helped-by trailers. The implementation preserves flexibility for future extension while delivering a minimal, well-tested atomic ref update feature as the initial stable version.
