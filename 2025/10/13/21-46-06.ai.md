Security-focused refactoring patch in a series hardening Git against malicious hooks. This is patch 3/5 in Michael Lohmann's v2 series addressing arbitrary code execution via untrusted repositories. The patch reorders safety checks in `ensure_safe_repository()` to prioritize explicit `safe.directory` configurations over implicit ownership tests.

The key change moves the ownership check (`is_path_owned_by_current_user`) to run *after* checking `safe.directory` configurations, reversing their previous order. This makes explicit configuration take precedence over implicit ownership, which the commit message argues is more logical priority. The change is behavior-preserving but reorganizes the control flow to make future additions of new safety checks easier.

Technical details:
- Modifies `setup.c`'s `ensure_safe_repository()` function
- Keeps all existing safety checks but reorders them
- Maintains same return values (1 for safe, 0 for unsafe)
- Preserves special case for `GIT_TEST_ASSUME_DIFFERENT_OWNER` testing
- No functional change to `safe.directory` or ownership check logic

This appears to be a preparatory refactoring for the later patches that will introduce new safety mechanisms (temporary bypass and persistent configuration options). The change follows the series' pattern of separating refactoring from behavior changes, with this patch focusing purely on code organization to support the security features coming in patches 4-5.
