This is a small refactoring patch for `git cat-file`'s batch mode, specifically around how submodule objects are reported. 

The patch simplifies the code by removing redundant logic in `report_object_status()` calls for submodules. Previously, when handling submodules in batch mode, the code was explicitly passing the hex OID string to `report_object_status()`, even though the function already handles NULL object names by automatically converting the OID to hex itself. This behavior has been present since 2015.

The change is straightforward and maintains the same functionality - when a submodule is encountered in batch mode, it will still report the submodule's commit hash, just with slightly cleaner internal plumbing. The patch touches only one line in `builtin/cat-file.c`.

Taylor Blau notes this was discovered while merging Git v2.50.1 into GitHub's fork, suggesting it's a minor cleanup rather than a bug fix. The change appears correct and well-contained, though it's quite small in scope - primarily of interest to those working on the cat-file internals.
