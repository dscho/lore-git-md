This is a feature patch series completing the implementation of consistent signature handling across Git's fast-import/export commands, building on previous work to standardize commit signature processing. The series adds symmetric `--signed-tags=<mode> support to fast-import, matching fast-export's existing capability while extending both to handle all signature types (PGP, X.509, SSH).

The cover letter explains the motivation: enabling tools like git-filter-repo to control tag signature handling during repository filtering operations. The implementation maintains backward compatibility while preparing for future signature modes like "re-sign" and "strip-if-invalid". The series includes preparatory cleanups to documentation (modernizing git-tag man page language to be format-agnostic) and test infrastructure (fixing GPGSM/SSH test prerequisites and tag counting logic).

Key technical changes include: centralizing signature parsing logic via parse_signed_buffer(), adding the new --signed-tags option to fast-import with identical mode support (verbatim, warn-verbatim, warn-strip, strip, abort), and fixing fast-export to properly handle non-PGP signatures. The test suite gains comprehensive coverage through new t9306-fast-import-signed-tags.sh and updates to t9350-fast-export.sh.

The v3 iteration incorporates all prior review feedback, with only minor documentation tweaks since v2 (clarifying git-tag's --verify description). The series appears production-ready, with thorough test coverage across signature types and processing modes. The implementation builds on established patterns from the earlier signed-commits work, suggesting low risk of unexpected behavior. The parallel test infrastructure discussions about GPG2 handling don't directly impact this series' functionality.
