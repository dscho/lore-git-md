This is a feature patch series (v3) for `git replay` that changes its default behavior to perform atomic reference updates. The series has evolved through multiple versions with input from key reviewers including Elijah Newren, Phillip Wood, and Christian Couder.

The core change makes `git replay` update refs directly using Git's ref transaction API by default, rather than outputting commands to be piped to `git update-ref`. The implementation uses `ref_store_transaction_begin()`, `ref_transaction_update()`, and `ref_transaction_commit()` to ensure atomic all-or-nothing behavior. A new `handle_ref_update()` helper function unifies the code paths between direct updates and the traditional print-to-stdout mode.

For backward compatibility, the series introduces a `--update-refs=<mode>` option with "yes" (default) and "print" (traditional pipeline output) modes. The final patch adds a `replay.defaultAction` config option that lets users set their preferred default mode while still allowing CLI overrides. The implementation follows Git's standard patterns for config options and ref transactions.

The test suite has been significantly enhanced to verify atomic behavior through lock file checks, config parsing, CLI override precedence, and equivalence testing between update modes. Tests use proper isolation with `test_when_finished` and have been updated to explicitly use `--update-refs=print` where they expect command output.

Key technical details include the removal of the `--allow-partial` option (deemed unnecessary), the use of enum string values for future extensibility, and careful handling of bare repository use cases. The commit messages properly credit reviewers and document design decisions, showing the series is well-vetted and ready for integration.
