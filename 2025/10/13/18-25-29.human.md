This is the second patch in a 3-part series that changes `git replay` to perform atomic reference updates by default, while maintaining the traditional pipeline output mode as an option. The patch comes from Siddharth Asthana with help from several reviewers.

The change makes atomic ref updates the default behavior for `git replay`, using Git's ref transaction API to ensure all-or-nothing updates. This is particularly beneficial for server-side operations where the previous pipeline approach required additional process coordination. The traditional output mode remains available via `--update-refs=print` for scripting use cases.

The implementation introduces a new `handle_ref_update()` helper function to unify the print and atomic update paths, reducing code duplication. Test coverage is extensive, verifying atomic behavior through lock file checks, bare repository support, and equivalence testing between the pipeline and atomic modes. Documentation updates clearly explain the new default behavior and options.
