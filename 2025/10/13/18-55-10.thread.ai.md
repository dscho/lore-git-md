[PATCH] git whatchanged mtime workaround script

Roy Lomicka presents a PowerShell script that leverages the deprecated `git whatchanged` command to preserve file modification times (mtimes) based on commit timestamps. The script processes `git whatchanged --reverse --pretty=%at` output, extracting Unix timestamps and applying them to corresponding files. This addresses a gap where Git does not natively preserve mtimes during checkouts.

The script demonstrates a concrete use case for `git whatchanged` ahead of its planned deprecation (requiring `--i-still-use-this` flag). It handles output parsing carefully - skipping empty lines and correctly processing both timestamps and file paths. The submission serves dual purpose: reporting active usage of a deprecated command and providing a functional workaround for mtime preservation.

Key technical details: PowerShell implementation processes commit timestamps in Unix epoch format, applies them via `[System.IO.File]::SetLastWriteTimeUtc()`. The `--reverse` flag ensures chronological application of timestamps. This represents a niche but valid use case where `git whatchanged` provides functionality not easily replicated by other Git commands like `git log`.
