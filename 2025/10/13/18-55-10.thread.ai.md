[PATCH] git whatchanged mtime workaround script

Roy Lomicka presents a PowerShell script using the deprecated `git whatchanged --reverse --pretty=%at` to preserve file modification times (mtimes) based on commit timestamps, demonstrating active usage of this command before its deprecation (requiring `--i-still-use-this` flag). The script carefully processes Unix epoch timestamps and file paths, applying them via `[System.IO.File]::SetLastWriteTimeUtc()`.

Kristoffer Haugsbakk responds with a migration path, noting `git log --no-merges --raw` produces equivalent output to `git whatchanged` except for empty commits (those with no changes from their parent). This edge case is acknowledged as potentially relevant for scripted usage but unlikely to affect interactive scenarios. The discussion documents the precise behavioral difference between the commands while maintaining focus on technical migration rather than deprecation debate.

Key technical details: PowerShell implementation handles timestamp parsing and file operations. The `--reverse` flag ensures chronological application. Empty commits represent the sole case where `git log` substitution would differ from `git whatchanged` output.
