This is a feature patch series for `git replay` that changes its default behavior to perform atomic reference updates rather than outputting update commands. The series is in its third iteration, having incorporated feedback from multiple reviewers.

The main change makes `git replay` update references directly using Git's ref transaction API by default, ensuring all updates succeed or none do (atomic behavior). The traditional pipeline output mode is still available via `--update-refs=print`. The series also adds a `replay.defaultAction` config option for users who prefer the old behavior as their default.

Key technical details:
- Uses `ref_store_transaction_begin()` with atomic behavior by default
- Introduces `handle_ref_update()` helper to unify print/update code paths
- Adds comprehensive tests verifying atomic behavior and backward compatibility
- Implements config option with enum values for future extensibility
- Maintains both bare repository support and test isolation
- Patch 1 cleans up option validation
- Patch 2 implements the core atomic update behavior
- Patch 3 adds the config option

The changes address server-side use cases where atomic updates are critical, while preserving the plumbing-style output for scripting via the print mode. The implementation appears thorough, with good test coverage including verification of the all-or-nothing guarantee via lock file tests.

The series has evolved through multiple rounds of review, with notable changes from v2 including removal of the `--allow-partial` option (no clear use case) and switching to an extensible `--update-refs=<mode>` interface. The commit messages are detailed and properly credit reviewer contributions.
