Feature patch adding a config option for `git replay`'s default behavior. This is the final patch in a 3-part series that makes `git replay` perform atomic reference updates by default while maintaining the ability to output update commands via `--update-refs=print`.

The patch introduces `replay.defaultAction` with two possible values: `update-refs` (default, for atomic updates) and `show-commands` (for pipeline output). The config uses different value names than the command-line `--update-refs` option (`yes`/`print`) for better semantics while maintaining the same underlying behavior. Command-line options override the setting, allowing temporary behavior changes.

Implementation reads the config early in `cmd_replay()`, validates values, and maps them to the internal modes used by the existing `--update-refs` logic. Invalid config values trigger immediate error with helpful messaging. The patch includes thorough tests verifying config behavior, command-line override precedence, and error handling.

This appears well-integrated with the series' atomic update functionality (introduced in patch 2/3) and maintains the scripting use case while making atomic updates the default. The commit message clearly documents the design decisions and includes sign-offs from multiple Git maintainers, suggesting it has already undergone review. The tests cover all config scenarios and edge cases.
