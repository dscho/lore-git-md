This is a security-focused patch series addressing potential arbitrary code execution via Git hooks in untrusted repositories. The series builds on prior discussion about hardening `safe.directory` protections.

The core proposal introduces two mechanisms to prevent accidental execution of malicious hooks: a `--assume-unsafe` flag that makes Git treat all repositories as potentially unsafe by default, and a `safe.assumeUnsafe` config option for persistent enforcement. A `--allow-unsafe` flag provides temporary bypass capability when needed.

The series includes significant refactoring of the repository safety checking code, with commits that:
1. Rename functions for clarity (`ensure_safe_repository` becomes `check_repository_safety`)
2. Align die/check function naming
3. Restructure safety test priorities
4. Implement the temporary bypass mechanism
5. Add configurable behavior for self-owned repositories

The motivation demonstrates a concrete attack vector where a malicious zip file containing a Git repo could trigger code execution through shell prompts or other Git-invoking programs. The solution aims to give users tools to opt into stricter safety checks while maintaining workflow flexibility.

The implementation touches core repository setup code, adds new documentation for the config options and flags, and includes comprehensive tests in a new test script. The changes appear carefully considered with clear commit separation and thorough test coverage.
