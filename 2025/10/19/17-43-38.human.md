Follow-up on Scalar configuration investigation. Matthew Hughes continues the discussion about Scalar's configuration settings, raising several specific questions about the rationale behind various options that Scalar modifies. This builds on the ongoing effort to document and clarify Scalar's configuration behavior.

The email identifies several categories of settings that warrant explanation:
1. Platform-specific settings (core.FSCache, credential.validate) that may be Windows/GCM relics from Scalar's origins
2. CRLF-related options (am.keepCR, core.autoCRLF, core.safeCRLF) where Matthew questions the performance impact
3. GC automation settings (gc.auto, gui.GCWwarning, receive.autoGC) disabled by Scalar
4. Index optimizations (index.threads, index.version, index.skipHash) with questions about read/write tradeoffs
5. General large-repo settings (pack.useBitmaps, fetch.writeCommitGraph, etc) where the rationale isn't immediately clear

This appears to be a thoughtful, well-researched inquiry that could help shape the documentation effort Derrick Stolee is leading. The questions touch on both historical context (what settings were inherited from Scalar's Microsoft origins) and technical rationale (why certain defaults are better for large repos). The thread seems poised to produce both better documentation and possibly some configuration cleanup.
