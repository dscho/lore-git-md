Part 2 of a refactoring series converting SSH key handling from `strbuf_split*()` to `string_list_split*()` in `gpg-interface.c`. This patch focuses on `get_default_ssh_signing_key()`.

The change replaces `strbuf_split_max()` with `string_list_split_in_place()` when parsing the output of the SSH key command. The key differences in this conversion are:
- Uses `STRING_LIST_INIT_NODUP` since the strings are read-only
- Adjusts the split count from 2 (tokens) to 1 (splits) to maintain the same 2-token output
- Checks for >0 splits rather than array indexing to verify successful parsing
- Returns the first token via `items[0].string` instead of `keys[0]->buf`

The commit message clearly explains the semantic difference between the old and new APIs regarding split counting. Like part 1, this maintains all safety checks while using the more appropriate API for read-only string splitting. The change is straightforward and maintains the same behavior, just with cleaner internals.

This completes the two-part series modernizing SSH key handling in gpg-interface.c, following feedback from Junio Hamano and Christian Couder. Both patches use the `_in_place` variant and proper initialization for read-only string lists.
