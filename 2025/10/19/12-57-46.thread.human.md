This thread addresses improvements to bash completion for `git log` and `git shortlog` commands. The initial patch from KIYOTA Fumiya fixes two issues: it adds the missing `--exclude=` option to the shared completion list for both commands, and properly separates the handling of `--committer` between the commands - keeping the pattern-based version for `git log` while making it valueless for `git shortlog` (which rejects values).

Junio C Hamano has reviewed and approved the technical changes, suggesting only a minor wording tweak to match Git's commit message style. He notes an underlying UI inconsistency worth future discussion - while `git log` uses `--committer=` for filtering commits, `git shortlog` uses the same flag for grouping output (and rejects values), which could confuse users. Despite this observation, the patch is being queued for inclusion as it correctly handles the current behavior rather than introducing new inconsistencies.

The changes are confined to `contrib/completion/git-completion.bash` and maintain all existing option patterns while fixing the completion behavior. This appears to be a straightforward improvement to the completion system that makes tab completion more accurate for these commands.
