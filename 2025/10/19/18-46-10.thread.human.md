This thread discusses a proposal to improve `git diff --stat`'s handling of file path display. The current behavior truncates long paths with ellipses even when users explicitly set wide display widths via `diff.statNameWidth` or `--stat-name-width`, as these options only control allocation within the terminal's available space rather than expanding it. The author demonstrates this with Java file paths that get abbreviated despite configuration attempts, creating workflow friction when trying to copy full paths into editors.

The proposal suggests two potential solutions: either modifying `diff.statGraphWidth` to expand beyond terminal constraints, or introducing a new configuration option to force full path display regardless of terminal width. The use case is well-motivated and the technical analysis appears sound, though the thread is just beginning and hasn't yet seen review feedback or alternative approaches. The core question for discussion will likely be whether to extend existing options or add new ones to address this behavior.
