This thread discusses improving `git diff --stat`'s path display behavior, which currently truncates long paths (like Java package paths) when they exceed terminal width constraints. The original proposal from Дилян Палаузов highlighted how this makes copying paths difficult, suggesting either extending `diff.statGraphWidth` or adding a new config option to show full paths regardless of terminal width.

Ben Knoble initially suggested `git-jump` as an alternative workaround for path copying, though this doesn't address the core `--stat` behavior. Jeff King (peff) has now weighed in, noting the asymmetry in existing stat-related config options and proposing `diff.statTotalWidth` as a logical addition. He points out that pagers handle horizontal scrolling well, reducing concerns about terminal overflow, and offers the practical workaround of using the `COLUMNS` environment variable to simulate a wider terminal.

The discussion remains focused on balancing technical implementation (whether to modify existing options or add new ones) with user workflow needs. While peff's environment variable suggestion provides an immediate solution, the question of whether to formalize this behavior through new config options remains open, with no strong opinions yet expressed about the preferred approach.
