This thread explores how `git diff --stat` handles path display when paths are too wide for the terminal. Дилян Палаузов raised the issue, noting that Java package paths often get truncated, making them hard to copy. Initial proposals suggested either extending the graph width or adding a new config option to show full paths.

Jeff King (peff) pointed out the asymmetry in stat-related configs and suggested using the `COLUMNS` environment variable as a workaround to simulate a wider terminal. Junio C Hamano later chimed in, defending `COLUMNS` as a legitimate solution rather than a hack, since it's a standard Unix mechanism for controlling terminal width assumptions. His response implies the core team may favor relying on existing Unix conventions rather than adding new Git-specific configs for this case.

The discussion has clarified that the immediate need can be met without code changes, though the question of whether to add a `diff.statTotalWidth` config remains open. For now, users needing full paths can use `COLUMNS` or tools like `git-jump` from contrib. The thread shows the project's preference for leveraging established system behaviors where possible.
