Refactoring patch modernizing SSH key fingerprint handling by replacing `strbuf_split_max()` with `string_list_split_in_place()` in `gpg-interface.c`. This is part 1 of a 2-patch series (v3) that follows up on feedback from Junio Hamano and Christian Couder.

The patch focuses on `get_ssh_key_fingerprint()`, which parses `ssh-keygen` output to extract fingerprint information. The key changes are:
- Switches from allocating multiple strbufs to using a string_list with `STRING_LIST_INIT_NODUP` since the split strings are only read, not modified
- Adjusts the split count logic - where `strbuf_split_max()` took 3 (number of tokens), `string_list_split_in_place()` now takes 2 (number of splits)
- Maintains the same safety check but now verifies at least 2 items were split (yielding 3 tokens) to ensure the fingerprint exists at index 1
- Includes detailed commit message explaining the counting logic difference between APIs

The change appears well-justified and carefully implemented, with clear attention to the behavioral equivalence between old and new approaches. The patch follows the broader project direction of using more appropriate string handling APIs where possible. Test coverage is implied via GitHub CI (PR #2074) though no new tests are added here.
