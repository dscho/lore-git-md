Feature proposal for `git diff --stat` path display behavior.

The email proposes adding a configuration option to control how `git diff --stat` displays file paths, specifically to prevent path truncation with ellipses. Currently, the output respects terminal width constraints even when `diff.statNameWidth` or `--stat-name-width` options are set to large values, as these only control allocation within the available space rather than expanding the space itself.

The author demonstrates this with examples showing identical truncated output whether using config settings or command-line options, where long Java file paths get abbreviated with `...`. The use case is practical - they want to copy full paths from the diff output directly into editors like `emacs` or `less`.

The proposal suggests either modifying the existing `diff.statGraphWidth` behavior to expand beyond terminal width, or adding a new config option that would allow forcing full path display regardless of terminal constraints. The request appears technically sound and addresses a specific workflow pain point, though the implementation approach (whether to extend existing options or add new ones) would need discussion. The email references relevant documentation sections and provides clear reproduction steps.
