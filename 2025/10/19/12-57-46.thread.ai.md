This thread introduces a patch by KIYOTA Fumiya to improve bash completion for `git log` and `git shortlog` commands in `contrib/completion/git-completion.bash`. The patch makes two specific changes: (1) adds the missing `--exclude=` option to the shared completion list for both commands, fixing an oversight where this valid option wasn't available for tab completion, and (2) properly separates the handling of `--committer` between the commands - maintaining the existing pattern-based `--committer=` for `git log` while implementing a valueless `--committer` for `git shortlog` which rejects values (matching `shortlog`'s actual behavior).

Junio C Hamano has reviewed and approved the technical changes, suggesting only a minor commit message wording tweak to match Git's style. He notes an underlying UI inconsistency that the patch surfaces: while `git log` uses `--committer=` for filtering commits, `git shortlog` uses the same flag for grouping output (and rejects values). The patch is being queued for inclusion, with Hamano hinting this inconsistency might warrant future discussion about command interface consistency.

The changes are localized to the completion script, specifically:
- Adding `--exclude=` to `__git_log_shortlog_options`
- Moving `--committer` handling for `shortlog` to a command-specific section while keeping `log`'s pattern-based completion
- Maintaining all existing option patterns while fixing the completion behavior

This is a focused improvement to the completion system that properly handles an existing command behavior inconsistency rather than introducing new functionality. The patch appears ready for merging with Hamano's suggested wording change.
