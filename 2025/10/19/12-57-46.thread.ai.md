This thread introduces and refines a patch by KIYOTA Fumiya to improve bash completion for `git log` and `git shortlog` commands in `contrib/completion/git-completion.bash`. The patch makes two specific changes: (1) adds the missing `--exclude=` option to the shared completion list for both commands, fixing an oversight where this valid option wasn't available for tab completion, and (2) properly separates the handling of `--committer` between the commands - maintaining the existing pattern-based `--committer=` for `git log` while implementing a valueless `--committer` for `git shortlog` (matching `shortlog`'s actual behavior that rejects values).

Junio C Hamano reviewed and approved the technical changes, suggesting a commit message wording tweak ("I'll" -> "Handle") to match Git's style. KIYOTA promptly incorporated this feedback in the follow-up. The discussion surfaced an underlying UI inconsistency where `--committer` serves different purposes between the commands (filtering for `log`, grouping for `shortlog`), though the patch deliberately maintains the current behavior rather than attempting to resolve this deeper issue.

The changes are localized to the completion script:
- Adding `--exclude=` to `__git_log_shortlog_options`
- Moving `--committer` handling for `shortlog` to a command-specific section
- Keeping `log`'s pattern-based completion unchanged
- Preserving all existing option patterns while fixing completion behavior

The patch is now ready for merging with the minor wording adjustment, having received maintainer approval. It serves as a focused improvement to the completion system that properly handles an existing command behavior inconsistency without introducing new functionality. The thread leaves open the broader question of whether the `--committer` flag's divergent behavior between commands should be addressed in future interface work.
