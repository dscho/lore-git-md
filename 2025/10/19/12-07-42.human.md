Refactoring patch modernizing SSH key fingerprint handling in `gpg-interface.c`. This is the first of two patches in v3 of a series converting from `strbuf_split*()` to `string_list_split_in_place()` for string splitting operations where the results are only used as read-only character pointers.

The patch focuses on `get_ssh_key_fingerprint()`, which parses output from `ssh-keygen`. The key change replaces `strbuf_split_max()` with `string_list_split_in_place()`, which is more appropriate since the split strings are only used as character pointers. The logic is adjusted to account for differences between the APIs - where `strbuf_split_max()` took a token count, `string_list_split_in_place()` takes a split count (so 2 splits produces 3 tokens).

Notably, the patch makes the parsing more robust by only requiring >=2 split items (rather than exactly 3), allowing it to work even when the key owner's identity is missing from the output. The implementation is clean, with clear commit message explanations of the API differences and rationale for the count change. The change has been reviewed by Junio Hamano and Christian Couder, and is part of a broader effort to use more appropriate string splitting APIs throughout the codebase.
