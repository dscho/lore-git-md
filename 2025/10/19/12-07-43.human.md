Refactoring patch (part 2/2) modernizing SSH key handling in gpg-interface.c by replacing `strbuf_split_max()` with `string_list_split_in_place()`. This follows part 1's similar conversion for `get_ssh_key_fingerprint()`.

The patch updates `get_default_ssh_signing_key()` to use the more appropriate string splitting API when processing SSH key output. The key changes are:
- Switches to `string_list_split_in_place()` with `STRING_LIST_INIT_NODUP` since the strings are only read, not modified
- Adjusts the split count logic (using 1` split to get 2 tokens instead of the old API's `2` count)
- Maintains the same safety checks while simplifying the code

The conversion appears well-considered, with clear explanations of the API differences in counting semantics. This is the second part of a v3 series that has already incorporated feedback from Junio Hamano and Christian Couder, suggesting the approach has consensus. The change is focused and maintains existing behavior while using more suitable string handling primitives.
