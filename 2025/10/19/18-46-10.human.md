This is a feature request for `git diff --stat` output formatting. Дилян Палаузов points out that while Git provides configuration options (`diff.statGraphWidth` and `diff.statNameWidth`) and command-line flags to control the width of statistics output, these only work within the constraints of the terminal width. The request is for a way to override the terminal width constraint entirely, either by modifying the existing options or adding a new one, to always show full file paths without truncation.

The motivation is practical: when paths are fully visible, they can be easily copied and used directly with tools like `less` or `emacs`. Currently, even with width settings maximized, paths are still truncated to fit the terminal width. The example shows Java file paths being abbreviated with `...` despite high width settings.

The patch appears well-motivated and clearly explained, addressing a specific workflow pain point. The request seems reasonable for users working with deep directory structures who frequently need to access files directly from `git diff` output. The change would likely require modifying how Git calculates available width for stat output when these configuration options are set.
