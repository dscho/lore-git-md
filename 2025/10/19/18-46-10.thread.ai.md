Proposal to modify `git diff --stat` path display behavior to allow full paths regardless of terminal width constraints. Currently, both `diff.statNameWidth` config and `--stat-name-width` option only allocate space within terminal boundaries, forcing truncation of long paths (e.g. Java package paths) with ellipses. Original author Дилян Палаузов demonstrates identical truncated output in both cases, highlighting workflow pain when copying paths to editors.

Two potential solutions proposed: 1) Extend `diff.statGraphWidth` to expand beyond terminal width, or 2) Introduce new config option to force full path display. Technical motivation is clear with practical use case (path copying) and references existing documentation.

Ben Knoble suggests an alternative solution using `git-jump` from contrib as a workaround for path copying, though this doesn't directly address the proposed `--stat` modifications. The suggestion leaves open whether `git-jump` should be considered instead of or in addition to the original proposals. Key open questions remain about implementation approach - whether to modify existing options or add new ones, and whether the `git-jump` alternative sufficiently addresses the use case for users who prefer working with `--stat` output directly.
