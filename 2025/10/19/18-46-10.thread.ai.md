Thread summary:

Proposal to modify `git diff --stat` path display behavior to allow full paths regardless of terminal width constraints, initiated by Дилян Палаузов. Current behavior forces path truncation via `diff.statNameWidth` and `--stat-name-width` when paths exceed terminal width, creating workflow issues for copying long paths (e.g. Java package paths). Two initial solutions proposed: 1) extend `diff.statGraphWidth` beyond terminal width, or 2) add new config option for full path display.

Jeff King (peff) identifies an asymmetry in stat-related configs, noting the lack of `diff.statTotalWidth` while suggesting it would complete the option set. He observes that pagers handle horizontal scrolling, reducing practical overflow concerns. Provides immediate workaround using `COLUMNS` environment variable to simulate wider terminals. Ben Knoble previously suggested `git-jump` from contrib as alternative path-copying solution.

Key technical points: Current truncation behavior documented in `git-diff` manpage, existing width controls (`diff.statNameWidth`, `diff.statGraphWidth`), pager scrolling capabilities. Open questions: whether to implement new `diff.statTotalWidth` config versus relying on environment variables, relative merits of code changes versus existing workarounds (`COLUMNS`, `git-jump`). Thread maintains focus on practical path display needs for developer workflows, with no strong positions yet on preferred solution path.
