This is a refactoring patch series that's part of an ongoing effort to replace `strbuf_split*()` with `string_list_split*()` where appropriate. The series focuses on two functions in `gpg-interface.c` that handle SSH key operations.

The changes follow Junio Hamano's earlier work noting that `strbuf_split*()` is overkill when the split strings are only used as read-only character pointers. The patch author, Olamide Caleb Bello, converts both `get_ssh_key_fingerprint()` and `get_default_ssh_signing_key()` to use `string_list_split_in_place()` instead of `strbuf_split_max()`, with careful attention to the different counting semantics between the two APIs.

Key technical details for future reference:
- In patch 1, the SSH fingerprint parsing now checks for at least 2 split items (was 3 with strbuf) to handle cases where key owner identity might be missing
- In patch 2, the default key retrieval checks for at least 1 split item (was 2 with strbuf) since it only needs the first token
- Both patches use `STRING_LIST_INIT_NODUP` since the strings are borrowed from existing buffers
- The changes include improved commit messages explaining the counting logic differences
- Testing was done via GitHub CI (PR #2074)

The v3 changes refine the approach from v2 by switching to `_in_place` variant and adjusting the split count checks, with credit given to Junio Hamano and Christian Couder for their input. The series appears well-considered with clear explanations of the technical rationale behind each change.
