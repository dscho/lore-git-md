This is the second patch in a two-part series improving gitk's window geometry persistence, specifically addressing the Tags/Heads window. The patch builds on the first one (which restored full geometry saving for the main window) by adding similar functionality for the secondary Tags/Heads window.

Johannes Sixt responds to Michael Rappazzo's v3 patch with a suggested simplification, though notes his version doesn't fully work across sessions due to an issue with variable scoping in Tcl. The original patch from Rappazzo is more comprehensive, adding four new procedures to handle geometry saving/restoring and window destruction cleanly. It stores the window position relative to the main window and uses careful event binding to avoid race conditions during window mapping.

The technical discussion reveals some subtle Tcl behavior around variable scoping that affects persistence between sessions. While both approaches aim to solve the same user experience problem (remembering the Tags/Heads window position/size), they differ in implementation complexity and robustness. The thread has consensus on the need for the feature but is working through the cleanest way to implement it given Tcl's quirks.

This appears to be the final round of review before the series (which has sign-offs and historical context from key contributors) gets picked up by the gitk maintainer. The remaining discussion focuses on implementation details rather than the feature's merit.
