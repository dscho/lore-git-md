This is the second patch in a two-part series improving gitk's window geometry persistence, specifically addressing the Tags/Heads window. The patch adds full geometry persistence (position + size) for the Tags/Heads window, stored as `geometry(showrefs)` in gitk's config file and maintaining relative positioning to the main window.

Johannes Sixt responds to Michael Rappazzo's v3 patch with a suggested simplification that reduces the 39-line change to a more focused 15-line version. The key technical difference is Johannes' approach uses a separate `bind$top` tag for Configure events to avoid child window interference, while Michael's version had four new procedures (`save_showrefs_geometry` etc.) with Map event binding. Johannes notes his version works within sessions but fails across sessions due to variable scoping issues with the saved geometry.

The thread context shows this is the final piece of a long-standing effort to restore full window management capabilities after historical Cygwin Tcl/Tk 8.4.1 limitations forced size-only persistence. Both approaches solve the core problem but differ in implementation complexity and robustness. Johannes' feedback suggests the technical solution is sound but could be more minimal, while Michael's version provides more explicit control flow. The discussion appears headed toward consensus with only implementation details to resolve.
