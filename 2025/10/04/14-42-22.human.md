This is a bugfix patch addressing an inconsistency in how Git handles invalid HEAD references. The patch comes from Han Young and is version 2 of a single-patch series.

The core issue is that while `git fsck` validates HEAD references, `git refs verify` does not, and the files backend doesn't perform runtime checks when updating symrefs. This can lead to situations where invalid HEAD references are silently accepted during operations like `git reset`.

The solution moves the HEAD validation logic from fsck into the refs subsystem so it can be shared by both commands, and adds runtime checking in the files backend. The v2 revision includes a new test case in t7102-reset.sh to verify the behavior.

The patch appears well-motivated and addresses a real gap in Git's reference validation. The changes are focused (just 10 lines of core code plus tests) and the commit message clearly explains both the problem and solution. This seems like a straightforward improvement to Git's reference safety checks.
