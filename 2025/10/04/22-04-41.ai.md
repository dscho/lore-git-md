This is the second patch in a two-part bugfix series addressing gitk's window geometry persistence, specifically focusing on the Tags/Heads window. Johannes Sixt builds upon Michael Rappazzo's earlier work but simplifies the implementation from 39 lines to 12, while fixing a subtle scoping issue.

The patch stores the Tags/Heads window geometry in gitk's config file as `geometry(showrefs)`, restoring both position and size across sessions. The key technical challenge involves variable scoping - the existing `savestuff` proc sources old settings before writing new ones, which would overwrite current values. The solution adds explicit `unset` and `global` declarations to properly access the geometry setting.

The implementation uses Tcl's `bindtags` to attach Configure event handlers specifically to the Tags/Heads window, avoiding interference with child windows. This contrasts with Rappazzo's more explicit control flow approach from the previous version. While functionally similar, Sixt's version is more minimal but required debugging the variable scoping issue mentioned in the thread.

This patch depends on the first patch in the series (reverting the main window geometry workaround) for complete functionality. The solution represents the culmination of discussion around modernizing gitk's window management now that Cygwin Tcl/Tk 8.4.1 limitations are no longer relevant. The thread shows consensus on the approach with only implementation details being refined.
