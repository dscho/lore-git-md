This is a bugfix patch for gitk's window geometry persistence, specifically addressing the Tags/Heads window positioning. It's part of an ongoing thread about restoring full window geometry management in gitk, where previous workarounds had limited persistence to just window sizes.

Johannes Sixt builds on Michael Rappazzo's earlier work to properly save and restore the Tags/Heads window position and size between sessions. The key insight here is fixing a subtle scoping issue where local variables were interfering with the global geometry settings. The patch adds proper handling to ensure the window's geometry is correctly stored in the config file as `geometry(showrefs)` and restored on subsequent launches.

The implementation is more minimal than Rappazzo's original proposal, using Tcl's bindtags mechanism to track window configuration changes. However, as noted in the thread, there's still some discussion about the best approach - Johannes's version works within sessions but had initial issues with persistence across sessions that this patch now resolves.

This appears to be a well-considered solution to a long-standing user experience issue in gitk, with careful attention to the technical details of Tcl variable scoping. The patch is small (12 lines) and focused, building on established patterns from the main window geometry handling.
