Bugfix targeting the files-backend's handling of symref names. This is the second version of a patch that adds runtime validation for HEAD ref names during updates, addressing an oversight where invalid HEAD refs could be created without error.

The patch moves validation logic from `fsck_head_link()` in fsck.c to the refs subsystem, making it available for both `git fsck` and `git refs verify`. The key addition is a check in `files-backend.c` that prevents creation of invalid HEAD refs during operations like `git reset`. The v2 revision adds a test case in t7102-reset.sh to verify the new behavior.

The change appears well-motivated by the discussion thread, which identified that while fsck checked HEAD ref names, the refs verify command did not, and runtime operations could bypass validation entirely. The implementation is straightforward, adding about 10 lines to the files backend with corresponding test coverage. The patch seems likely to be uncontroversial as it closes a clear gap in validation without introducing new complexity.
