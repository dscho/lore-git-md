Bugfix for files-backend symref validation, specifically preventing creation of invalid HEAD references. This is the second version of a patch that moves validation from `git fsck` into the core refs subsystem where it can catch problems during normal operations rather than after the fact.

The patch adds a check in `files-backend.c` to validate symbolic reference names before updates, preventing creation of references with invalid paths (like "refs/../foo"). It includes a new test case in t7102-reset.sh that verifies `git reset` fails when given a corrupt HEAD reference path.

This appears to be a straightforward and well-contained fix. The commit message clearly explains the problem (potential creation of refs outside the refs/ directory) and the solution (early validation). The test case provides clear regression protection. The patch builds on prior discussion that identified this validation gap in the refs subsystem.
