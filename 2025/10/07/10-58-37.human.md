Performance optimization and refactoring series for tag peeling and ref iteration.

Patrick Steinhardt presents a 13-patch series that started as a simple performance optimization for `git-for-each-ref` but expanded into broader refactoring of tag peeling infrastructure. The key changes:

1. The first 7 patches refactor the codebase to eliminate the `peel_iterated_object()` hack, replacing it with cleaner iterator-based peeling. This touches many callers across the codebase to use the new `reference_get_peeled_oid()` interface.

2. Patches 8-9 remove now-unneeded peeling infrastructure after the refactoring.

3. Patches 10-12 address edge cases in tag peeling where tag objects might store mismatched type information for their tagged objects. The author notes these feel like "whack-a-mole" fixes and expresses some uncertainty about the approach.

4. The final patch (the original motivation) optimizes `git-for-each-ref` by avoiding unnecessary object parsing when only the object ID is needed.

The series reveals some underlying fragility in Git's tag peeling implementation, particularly around type verification. While the refactoring appears thorough, the author openly acknowledges the later patches may not fully solve the deeper issues with tag verification. The changes are wide-ranging, touching 65 files, but appear focused on improving the code's maintainability while fixing some long-standing quirks in the ref iteration and peeling logic.
