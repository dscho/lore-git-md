**Thread Summary:**

Patrick Steinhardt has proposed a 13-patch series refactoring Git's tag peeling and ref iteration infrastructure, with goals of cleaning up technical debt, fixing tag verification issues, and optimizing performance. The series introduces a new `struct reference` to encapsulate ref metadata (including peeled object IDs), modernizes status flags with an enum, and removes fragile global state from the peeling process. 

The first twelve patches restructure the internals: they replace scattered iterator fields with the new reference struct, update all callers of the ref iteration API, remove obsolete peeling infrastructure, and add strict type verification for tag objects. The final patch (just received) delivers the performance payoff - modifying `ref-filter.c` to lazily parse objects only when needed during ref formatting. Benchmarks show a 13% speedup for `git-for-each-ref` in large repositories when using simple formats that don't require full parsing.

This work builds on Patrick's broader refs subsystem modernization efforts (including recent reftable work) and touches nearly every part of Git that handles references. The changes maintain backward compatibility while setting up future optimizations. No reviews have been posted yet for this initial version of the series. Key open questions remain about the verification approach, performance tradeoffs, and potential conflicts with ongoing MIDX work.
