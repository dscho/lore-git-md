This thread continues Patrick Steinhardt's ongoing refactoring of Git's refs subsystem, building on his earlier work separating transport-related `struct ref` from core `struct reference`. The series began as a performance optimization for `git-for-each-ref` but has grown to address deeper architectural issues around tag peeling and iterator state management.

The current 15-patch series is organized into five logical groups, with the latest addition being a mechanical but important cleanup patch that ensures iterator state is properly reset between iterations. This change prevents subtle bugs from leaking between ref lookups and makes the interface more maintainable for future extensions. It modifies three backend implementations (packed, ref-cache, reftable) to zero out reference structures, while leaving the files backend unaffected as it already handles this correctly.

While most of the series appears technically sound, Patrick has expressed some uncertainty about patches 12-14, which handle invalid tags where the stored type doesn't match the actual object. He notes these feel like "whack-a-mole" fixes, with a potential alternative being to modify `parse_tag_buffer()` directly - though that would break existing tests expecting corrupt tags. This architectural question about how to best verify tag consistency remains open for discussion.

The series as a whole represents both immediate performance improvements (~13% gain in ref-filter operations) and ongoing refinement of Git's refs subsystem. It builds on master with dependencies on Taylor Blau's MIDX work and Jonathan Tan's ref transport improvements, while maintaining clear separation between transport and core ref handling. The changes are substantial (touching 123 files) but carefully structured to preserve backward compatibility.
