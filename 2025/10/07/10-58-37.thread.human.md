This thread continues Patrick Steinhardt's ongoing refactoring of Git's reference handling subsystem, building on the recently merged separation between transport-related `struct ref` and core `struct reference`. The series began as a performance optimization for `git-for-each-ref` but has grown to address deeper architectural issues around tag peeling behavior.

The latest patch (8/14) focuses on `git show-ref`, converting it to use the new `reference_get_peeled_oid()` interface. This is a mechanical but important change that ensures consistent peeling behavior across all code paths in the command. The patch modifies `show_one()` to accept a `struct reference` parameter instead of separate name and OID parameters, eliminating the last remaining use of `peel_iterated_oid()` in this command. While the changes are largely interface updates rather than functional modifications, they're crucial for maintaining consistency of the refs subsystem.

The series as a whole represents both immediate improvements (a 13% performance gain in ref-filter operations) and long-term architectural cleanup. It introduces enum-based reference status flags, a new peeling interface, and better separation of concerns while maintaining compatibility with existing packed and reftable backends. The most significant open question remains how to handle invalid tags where the stored type doesn't match the actual object - Patrick has expressed some uncertainty about whether the current approach (patches 12-14) is the right architectural direction.
