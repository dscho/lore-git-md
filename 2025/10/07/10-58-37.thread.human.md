This thread focuses on Patrick Steinhardt's 13-patch series refactoring Git's refs subsystem, particularly around tag peeling behavior. The work aims to clean up technical debt in ref iteration interfaces, fix tag object verification inconsistencies, and optimize `git-for-each-ref` by avoiding unnecessary object parsing. 

The initial four patches introduce a new `struct reference` to encapsulate ref information, modernize reference status flags, and eliminate fragile global state in tag peeling. The latest patch (v1 5/13) converts `upload-pack.c` to use the new `reference_get_peeled_oid()` API, replacing the old `peel_iterated_oid()` function. This change affects ref advertisement in `write_v0_ref()`, including a special case for capabilities announcements that now constructs a temporary reference struct. The conversion is mechanical but demonstrates how the new API simplifies callers while maintaining identical behavior.

The series represents part of Patrick's broader effort to modernize refs infrastructure, building on his recent reftable and ODB abstraction work. While the technical changes are well-contained so far, open questions remain about later patches' approach to tag verification and potential conflicts with concurrent MIDX work. No reviews have been posted yet for this initial version of the series.
