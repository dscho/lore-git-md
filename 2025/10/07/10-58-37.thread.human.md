The core issue involves how Git handles "peeled" tags - where a tag points to another object. The system was previously vulnerable to silently accepting corrupted tags where the declared object type didn't match the actual object. The latest patches ensure this corruption gets caught consistently, whether dealing with single tags or cases where multiple tags point to the same object with conflicting type declarations.

Key improvements include:
- A complete separation between transport-related reference handling and core ref operations
- New validation that prevents storing invalid peeled object IDs
- Consistent corruption detection across both files-based and reftable storage backends
- Preservation of earlier performance gains (around 13% faster for some operations)
