This is a follow-up discussion about Rust code formatting in the ongoing Rust CI infrastructure series. Eric Sunshine raises an important stylistic consideration that wasn't addressed in the original patch - line width formatting in Rust code.

The core issue revolves around whether to enforce an 80-column limit for Rust code, similar to Git's existing guidelines for C and other languages. Eric makes several key points:
1. Many Git developers still use 80-column editors/terminals
2. The project has historically recommended 80 columns for all code/documentation
3. Without an explicit `rustfmt.toml` configuration, different developers' local rustfmt settings could cause disruptive whole-file reformats
4. This should be decided now while the Rust codebase is still young

Eric references two previous messages where he raised this concern in another thread, noting the discussion died without resolution. He suggests adding a project-wide `rustfmt.toml` with `max_width = 80` to maintain consistency with Git's existing style guidelines.

This email doesn't propose any code changes itself, but rather re-raises an important stylistic question that needs project consensus. The discussion touches on the intersection of Rust ecosystem conventions (which often use wider line lengths) with Git's established style guidelines. The resolution of this could impact how Rust code is formatted in future contributions.
