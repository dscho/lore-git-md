This is a bug report about unexpected behavior when cloning from Git bundles created with `--all`. Andrew Harmon reports that while `git bundle create --all` correctly includes all refs (`refs/heads/*` and `refs/remotes/origin/*`), these remote refs become inaccessible after cloning from the bundle, contrary to user expectations.

The issue particularly affects workflows where bundles are used to transfer complete snapshots to offline environments. While the bundle contains all refs, the clone operation only makes local branches available, requiring users to manually fetch the remote refs afterward. This creates a surprising gap between what `--all` promises and what actually gets restored.

The report is thorough, including clear reproduction steps, expected vs actual behavior, and a workaround (manual fetch). It also suggests three potential solutions: modifying clone behavior to fetch all refs automatically, changing how refs are stored in bundles, or at least documenting the current behavior more clearly. The Windows environment details suggest this was discovered in real-world usage rather than theoretical analysis.

This appears to be a legitimate usability bug that could be fixed either through code changes (preferred) or documentation updates. The impact is significant for users relying on bundles for offline repository transfers, making this worth attention from the bundle/clone maintainers.
