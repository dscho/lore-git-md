Thread identity: Refactoring and bugfix series (13 patches) on tag peeling behavior in Git's refs subsystem, originating from performance optimization goals. Authored by Patrick Steinhardt, targeting the refs iterator interface, tag object verification, and peeling infrastructure.

Core problem: The series aims to (1) clean up technical debt around ref iteration and tag peeling interfaces, (2) fix inconsistencies in how tag objects store/verify type information for their tagged objects, and (3) optimize `git-for-each-ref` by avoiding unnecessary object parsing. The work spans refs infrastructure, reftable backend, and ref-filter code.

Current status: Initial version (v1) of the series, with patches 1-5 now detailed. Patch 1 introduces a wrapper struct for the `each_ref_fn` callback interface. Patch 2 extends this encapsulation to ref iterators by replacing scattered fields in `struct ref_iterator` with a consolidated `struct reference` member. Patch 3 modernizes reference status flags by converting them from `int` and `#define` to an `unsigned` enum `reference_status`. Patch 4 eliminates fragile global state in tag peeling by introducing a new `peeled_oid` field in `struct reference` and implementing `reference_get_peeled_oid()` API. Patch 5 converts `upload-pack.c` to use the new peeling API, updating `write_v0_ref()` to take a `struct reference` parameter and replacing `peel_iterated_oid()` calls with `reference_get_peeled_oid()`. Notes merge conflict with concurrent MIDX work.

Key technical details:
- Introduces new `struct reference` encapsulating refname, target (for symrefs), oid, flags, and now `peeled_oid` (patches 1-4)
- Updates all 48 callers of `each_ref_fn` to use the new struct (patch 1)
- Replaces individual iterator fields with `struct reference`, affecting 65 files (patch 2)
- Modernizes reference flags with new `enum reference_status` (patch 3)
- Adds `peeled_oid` field and implements `reference_get_peeled_oid()` to replace `peel_iterated_object()` (patch 4)
- Converts `upload-pack.c` to new API, modifying `write_v0_ref()` to take `struct reference` and updating capabilities announcement case (patch 5)
- Updates packed and reftable backends to populate `peeled_oid`
- Converts 9 callers (describe, gc, pack-objects, upload-pack etc.) to new peeling API
- Maintains same peeling behavior while removing global state dependency
- Eliminates obsolete peeling infrastructure (patches 8-9 pending)
- Adds verification in `peel_object()` for tag object type consistency (patches 10-12 pending)
- Optimizes `git-for-each-ref` to skip object parsing when possible

Open questions:
