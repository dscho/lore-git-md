This is the final patch in the reftable fsck validation series, implementing table name validation for the reftable backend. The patch adds glue code in `refs/reftable-backend.c` that calls the reftable library's fsck checks and maps reftable errors to Git's fsck error system.

Key technical components:
- A new `badReftableTableName` warning (FSCK_MSG_BAD_REFTABLE_TABLE_NAME) is added to enforce the reftable specification's naming convention of `${min_update_index}-${max_update_index}-${random}.ref`
- The implementation includes error mapping infrastructure with `fsck_msg_id_map[]` and callback handlers (`reftable_fsck_error_handler`, `reftable_fsck_verbose_handler`)
- The fsck check is applied to both main and worktree reftable backends
- Includes comprehensive test coverage in `t0614-reftable-fsck.sh` verifying both valid repositories and various invalid table name patterns
- Maintains code hygiene with lexicographical ordering of includes in `refs/reftable-backend.c`

The patch completes the series' goal of bringing reftable fsck to parity with files-backend capabilities, with this final piece focusing on table-level validation. The callback-based design preserves extensibility for future reference-level validation work. Test cases cover both the happy path and edge cases for table name validation, including hexadecimal parsing and proper suffix requirements.
