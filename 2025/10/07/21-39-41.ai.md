This is the second part of a documentation patch series updating Git's SubmittingPatches guidelines, focusing on multi-series patch submission practices. The patch adds formal guidance for contributors working on large efforts that span multiple patch series. It documents the existing convention of using "-part-one", "-part-two" suffixes for topic branch names in such cases, building on the topic naming conventions established in part 1 of the series.

The change adds an 8-line section to Documentation/SubmittingPatches that recommends:
1. Briefly describing the broader goal when submitting a series that's part of a larger effort
2. Explicitly stating where the current series fits within that goal
3. Using consistent naming with "-part-one", "-part-two" suffixes when following the topic branch naming convention (XX/prefix) introduced in part 1

The patch maintains the same documentation-focused approach as part 1, with no code or test changes. It continues the collaboration with Junio Hamano (as evidenced by the Suggested-by tag) and builds on the same experimental-to-stable documentation pattern. The change is straightforward and uncontroversial, formalizing existing maintainer practices around multi-series contributions.

This completes the two-part series that began with topic branch naming conventions, together providing more structured guidance for contributors while preserving backward compatibility with existing workflows. The changes are well-contained within the SubmittingPatches documentation and follow Git's gradual approach to workflow improvements.
