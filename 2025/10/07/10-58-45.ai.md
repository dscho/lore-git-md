This is the 8th patch in Patrick Steinhardt's refactoring series targeting tag peeling behavior and ref iteration infrastructure. The patch removes the `current_ref_iter` global variable and associated `peel_iterated_oid()` function, which were previously used as a performance optimization hack for tag peeling.

The change builds on earlier patches (1-7) that introduced `struct reference` to encapsulate ref metadata including peeled object IDs. Now that peeled OIDs are properly propagated through the ref iteration system via `struct reference`, the hack is no longer needed. The patch deletes:

1. The `current_ref_iter` global variable declaration and its management in `do_for_each_ref_iterator()`
2. The `peel_iterated_oid()` function that depended on this global state
3. Related documentation comments about the hack

This removal simplifies the refs subsystem by eliminating fragile global state while maintaining the same functionality through the cleaner `reference_get_peeled_oid()` API introduced earlier in the series. The change affects core ref iteration logic but doesn't modify behavior - it's removing now-obsolete infrastructure after the refactoring made it redundant.

The patch is a straightforward cleanup that follows naturally from the architectural improvements in previous patches. It touches the same key files as earlier work (`refs.c`, `refs/iterator.c`, `refs/refs-internal.h`) and helps complete the transition to the new reference handling model.
