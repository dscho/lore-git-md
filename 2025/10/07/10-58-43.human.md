This is patch 6/13 in Patrick Steinhardt's refactoring series on tag peeling behavior. The patch focuses on the ref-filter subsystem, which handles reference formatting for commands like `git tag` and `git ls-remote`.

The key change propagates peeled object IDs through the ref-filter pipeline, avoiding redundant object database lookups when processing tags. Previously, ref-filter would discard the peeled OID information and re-peel tags via `peel_iterated_oid()`. Now it preserves the peeled OID from the reference struct and uses it through the formatting pipeline when available.

The patch updates several callers (`ls-remote`, `tag`, `verify-tag`) to pass NULL for the peeled OID parameter (maintaining current behavior), while refactoring the internals to handle peeled OIDs when they are provided. The changes are mechanical but touch many lines as they thread the new parameter through the ref-filter API.

This continues the series' theme of cleaning up tag peeling infrastructure while maintaining the same behavior. The change should provide a small performance boost by avoiding duplicate tag peeling work, though the main benefit is the cleaner interface that will be built upon in later patches.
