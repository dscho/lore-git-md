This is part 6/7 of the reftable fsck validation series, implementing table-level consistency checks for the reftable backend. The patch introduces the core infrastructure for fsck checks in `reftable/fsck.[ch]` with a callback-based design that keeps the reftable library independent from Git internals.

The main addition is `reftable_fsck_check()`, which validates reftable stack integrity by running checks (currently just table name validation) through a series of table check functions. The first implemented check, `table_check_name()`, enforces the `${min_update_index}-${max_update_index}-${random}.ref` format for table filenames, reporting errors via the provided callback interface when invalid names are found.

The patch also includes build system updates to add the new fsck module to both Makefile and meson.build, maintaining lexicographic ordering of object files. The implementation demonstrates careful attention to error handling with proper cleanup paths and uses the reftable library's existing buffer utilities for progress reporting.

Key technical details:
- New public API in `reftable/reftable-fsck.h` with error reporting callbacks
- `REFTABLE_FSCK_ERROR_TABLE_NAME` error code for invalid table names
- Validation function `table_has_valid_name()` with strict hexadecimal parsing
- Extensible architecture via `table_check_fn` function pointers
- Progress reporting through `reftable_fsck_verbose_fn` callback

This represents the core validation machinery that will be integrated with Git's fsck infrastructure in subsequent patches, while maintaining the reftable library's independence through callback-based design. The implementation follows the series' established pattern of thorough error handling and clean API boundaries.
