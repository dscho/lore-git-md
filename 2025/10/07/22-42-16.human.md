This is a discussion about Rust code formatting in Git's CI infrastructure, specifically addressing the line width debate that emerged in Patrick Steinhardt's Rust CI series. Brian m. carlson weighs in with a dissenting opinion on the previously agreed 80-column limit.

Brian argues for adopting Rust's default 100-character line limit rather than Git's traditional 80-column standard. They make several points: modern displays comfortably accommodate wider terminals (citing their own 213-column tmux pane), historical precedent of 132 terminals, and Rust's opinionated defaults which already handle other formatting concerns like indentation. While acknowledging they'll comply if the project insists on 80 columns, they suggest this is an opportunity to align with Rust ecosystem norms.

The email references Linus Torvalds' similar preference for wider lines and notes they'll update `.editorconfig` regardless of the outcome. This comes after earlier thread consensus for 80 columns from Junio C Hamano and Eric Sunshine, making it a late-stage reconsideration of a seemingly settled matter. The tone is collegial but presents a substantive technical argument against the prevailing view.
