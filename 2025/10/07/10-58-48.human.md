This is patch 11 in a 13-part series refactoring Git's tag peeling and ref iteration infrastructure, focusing on fixing inconsistencies in how invalid tags are handled.

The patch detects and prevents storing peeled object IDs for tags where the tagged object's type doesn't match what the tag claims. Currently, both the files and reftable backends store these invalid peeled values, which can mask corruption when commands like `git-for-each-ref` use the cached values rather than verifying the tags. The fix adds type verification during peeling and skips storing the peeled value if verification fails.

The change affects the packed-refs file format and reftable backend, with corresponding test cases added to catch these scenarios. The tests create deliberately corrupted tags (claiming a blob is a commit) and verify the backends don't persist invalid peeled values. This maintains consistency in how broken tags are detected across Git commands.

This continues the series' theme of cleaning up tag peeling behavior while removing global state. It builds on patch 10's introduction of the `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag, now applying it to prevent storing invalid peeled values. The patch appears well-constructed with thorough test coverage for both storage backends.
