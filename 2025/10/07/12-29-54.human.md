Documentation patch modernizing `git-tag` references to cover all signature types, not just GPG.

This is the first of five patches in a series introducing better signature handling in Git's fast-import/export components. The patch updates the `git-tag` documentation to be more inclusive of different signature formats (X.509, SSH) alongside GPG. It removes GPG-specific language from command descriptions and option explanations, instead referencing the configurable `gpg.format` setting that determines the signing backend.

The changes are thorough, touching the NAME, DESCRIPTION, OPTIONS, and CONFIGURATION sections to clarify that lightweight tags exist, that signatures aren't GPG-specific, and how to configure alternative signing methods. The commit message clearly explains the changes are needed to correct the documentation's over-emphasis on GPG, which could mislead users about the command's capabilities.

This appears to be a well-justified documentation improvement that aligns with Git's growing support for multiple signature formats. The patch is cleanly focused on documentation without introducing any behavioral changes.
