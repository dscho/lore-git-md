This is part 3 of a 7-part reftable fsck validation series that has already been merged to 'next' after several iterations. The patch tightens the parser for reftable's 'tables.list' file by requiring a trailing newline, which was previously accepted but not validated.

The change modifies `parse_names()` in reftable/basics.c to return an error if the input lacks a final newline, while also refactoring the function to use an output parameter rather than returning the names array directly. This makes error handling more explicit and allows proper propagation of error codes (REFTABLE_FORMAT_ERROR for missing newlines, REFTABLE_OUT_OF_MEMORY_ERROR for allocation failures).

The patch includes thorough test coverage in the unit tests, adding a new test case specifically for the missing-newline scenario. The change is part of the broader effort to bring reftable's fsck validation to parity with the files backend, with this particular piece focusing on file format correctness. The implementation looks clean and well-tested, continuing the high quality seen throughout this series.
