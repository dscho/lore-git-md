This is patch 12/13 in a refactoring and bugfix series addressing tag peeling behavior in Git's refs subsystem. The patch focuses on improving detection of corrupted tags when they are dereferenced through `git-for-each-ref`.

The key issue is that Git currently only detects tag corruption in very specific cases - when two tags point to the same object but declare different types. The patch fixes this by verifying the object type during tag peeling in `populate_value()`, ensuring corruption is caught even when dereferencing a single tag.

The change is relatively small but important - it modifies `ref-filter.c` to use the `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag (introduced in patch 10) when peeling tags, and updates the test to verify the new behavior catches corruption in single-tag cases. This completes the series' work on tag verification while maintaining backward compatibility.
