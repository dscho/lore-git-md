This is patch 10/13 in Patrick Steinhardt's series refactoring Git's tag peeling behavior. The patch focuses on adding type safety when peeling tag objects.

The core issue is that `peel_object()` currently doesn't verify the type of tagged objects when peeling tags, which could lead to inconsistencies if a tag claims an object is of one type when it's actually another. The patch adds a new `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag to `peel_object()` that callers can use to enforce type verification.

Key changes include:
- Adding the new verification option while maintaining backward compatibility
- Inlining and removing the `deref_tag_noverify()` function since its functionality is now be handled by the flag
- Updating all existing callers to pass `0` for the flags (maintaining current behavior)
- Adding proper type verification when the new flag is set

This is a technical improvement that makes tag peeling more robust while preserving existing behavior for most callers. The series as a whole is cleaning up technical debt in the refs subsystem, and this patch specifically addresses a subtle correctness issue in tag handling.
