This is a feature patch adding the `git sparse-checkout clean` command, part of a v3 series that has already received maintainer approval. The command removes tracked-but-sparse directories outside the sparse-checkout scope while preserving untracked files, addressing performance issues from lingering sparse directories.

The patch introduces core functionality that is more aggressive than `git clean` in removing tracked sparse files but more conservative in preserving untracked files not in sparse directories. It handles edge cases like merge conflicts and staged changes through interaction with `git sparse-checkout reapply`, though the error message currently only mentions conflict resolution when other states (staged/modified files) can also prevent cleaning.

Key implementation details include:
- Requires cone mode for recursive directory matching
- Uses in-memory sparse index conversion to identify sparse directories
- Preserves untracked files when their parent is within sparse-checkout
- Includes comprehensive tests covering modified/staged/committed states
- Documents special cases where files may remain (conflicts, modifications)

The patch shows thorough test coverage and clear documentation, with Newren suggesting a minor error message improvement to better guide users through all possible resolution steps. The series appears ready for merging with this being one of the core functionality patches.
