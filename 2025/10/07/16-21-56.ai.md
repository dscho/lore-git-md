This is a discussion about the migration strategy for the submodule gitdir path encoding feature, specifically whether to automatically migrate existing gitdirs when enabling the new encoding scheme.

Junio C Hamano argues against Adrian Ratiu's proposal to automatically migrate existing gitdir paths to the new encoding format when the extension is first enabled. Instead, Junio advocates for using the existing `submodule.<name>.gitdirpath` configuration mechanism to permanently record the paths of existing submodules, avoiding any physical directory moves during migration.

The key technical points are:
1. Using the config-based mapping is safer than physically moving directories
2. The only case where directory moves might be necessary is when existing gitdirs already have path conflicts (like `.git/modules/A` and `.git/modules/A/B`)
3. Junio notes that introducing new top-level `.git/` directories is rare but does happen (citing `.git/reftable/` as an example)

This email represents the final resolution of the migration strategy debate in this long-running series, with Junio's config-based approach being adopted over Adrian's proposed physical directory migration. The discussion has now moved from architectural decisions to implementation details of the config-based solution.
