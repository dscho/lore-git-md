Test infrastructure patch preparing for GPG/GPGSM testing improvements.

This is the second patch in Christian Couder's series improving signature handling in fast-import/export. It makes a small but important change to the test infrastructure in t/lib-gpg.sh, modifying the GPG prerequisite setup to use `mkdir -p` instead of plain `mkdir` when creating the GNUPGHOME directory. This allows test scripts to list the GPGSM prerequisite before GPG without failing when the directory already exists.

The change is straightforward and clearly motivated by the following patch in the series (as noted in the commit message). This is part of the preparatory work needed before implementing the main feature of adding signed tag support to fast-import. The patch maintains the same security properties (still setting 0700 permissions) while making the directory creation more robust.

The modification aligns with the series' goal of improving signature handling by ensuring the test infrastructure can properly support testing both GPG and GPGSM prerequisites in any order. This will be particularly useful for the subsequent tests of the new --signed-tags functionality. The change is minimal and low-risk, affecting only test infrastructure rather than production code.
