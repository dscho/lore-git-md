This is part 4 of Patrick Steinhardt's refactoring series on tag peeling behavior in Git's refs subsystem. The patch focuses on improving how peeled object IDs (the targets of tag objects) are accessed during ref iteration.

The current implementation relies on global state - storing the current iterator in a global variable and having callbacks use `peel_iterated_oid()` to access it. This patch introduces a cleaner approach by adding a `peeled_oid` field to `struct reference` that backends can populate directly. A new `reference_get_peeled_oid()` function provides access to this value, falling back to manual peeling if needed.

The change affects several commands that work with tags (`describe`, `gc`, `pack-objects`, etc.), updating them to use the new interface. The patch maintains backward compatibility while removing the fragile global state dependency. It's a well-contained change that fits into the series' broader goals of cleaning up ref iteration infrastructure.

The implementation looks solid, with thorough updates to both files and reftable backends. This appears to be a straightforward improvement that makes the code more maintainable without changing behavior.
