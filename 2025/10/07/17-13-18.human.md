Follow-up discussion on Rust formatting standards in CI. Eric Sunshine raises an important stylistic consideration that wasn't fully resolved in the original Rust CI patch series: enforcing an 80-column line width for Rust code to match Git's existing style guidelines for other languages.

The core issue is that while rustfmt provides consistent formatting, its default settings may produce lines wider than Git's traditional 80-column limit. Eric notes this could cause friction when developers with different rustfmt configurations edit files, potentially leading to large reformats. He suggests adding a project-wide `rustfmt.toml` to enforce the 80-column limit, citing Git's longstanding preference for this width across all languages.

This appears to be reopening a discussion that previously stalled, with Eric advocating for addressing it now while the Rust codebase is still small. The suggestion seems reasonable given Git's established conventions, though it may require revisiting the rustfmt configuration in the CI infrastructure patch. The thread context shows this is part of Patrick Steinhardt's broader Rust CI series which has otherwise seen only minor editorial feedback.
