Junio Hamano responds to Adrian Ratiu's questions about filesystem edge cases in the submodule gitdir path encoding series. This is part of the finalized v5 implementation that uses percent-encoding to prevent submodule path conflicts.

The email focuses on practical filesystem handling strategies, suggesting a try-fail-adjust-retry approach for two key scenarios: (1) path length limitations (ENAMETOOLONG) and (2) case-sensitivity conflicts (EEXISTS). Junio notes that while `core.ignorecase` can help detect case-folding filesystems during repository creation, the code should be resilient even without consulting it by attempting operations and adapting to failures.

For path length issues, the proposal is to generate an encoded name, attempt creation, and if it fails with ENAMETOOLONG, shorten the name and retry while maintaining uniqueness. Similarly for case conflicts - if mkdir() fails with EEXISTS and the path isn't already registered in the config, the code should modify the path and retry. This builds on the series' established principle of minimal encoding while handling real-world filesystem constraints.

The response confirms the implementation's direction aligns with the thread's consensus on robust handling of edge cases, though it doesn't introduce new architectural changes to the already-settled design.
