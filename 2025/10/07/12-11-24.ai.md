This is a v6 bugfix and feature series for reftable consistency checks, addressing final test case feedback from Jeff King. The series has already been approved and merged to 'next' after five iterations, with this version making a minor but important correction to test case hygiene.

The key change in v6 fixes the test case in t0614-reftable-fsck.sh to use properly namespaced refs (`refs/heads/branch-$i`) instead of root refs (`branch-$i`), as Jeff King pointed out in his review of v5. Karthik acknowledges this worked only because reference-level checks aren't yet implemented, and wants to avoid confusion when those checks are added later. This demonstrates attention to detail even after maintainer approval.

The series as a whole implements table-level validation for the reftable backend through a new `reftable/fsck.[ch]` interface that keeps fsck logic separate from the reftable library while providing integration points. Key features include table name validation (as a warning, since the spec only suggests formats), strict parsing of 'tables.list' with newline termination requirements, and moving fsck messages to a generic layer for cross-backend consistency.

With this final test fix, the series appears technically complete and ready for wider testing in 'next'. The callback-based design leaves room for future reference-level validation work, which Jeff's review suggests could be a natural follow-up to detect malformed ref names. The careful separation of concerns between library and Git integration, along with comprehensive test coverage, makes this a solid foundation for reftable integrity checking.
