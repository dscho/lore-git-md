This is part 4/6 of the packfile store API refactoring series, now removing the deprecated `packfile_store_get_packs()` function after converting all callers in previous patches. The change is a straightforward deletion of the now-unused function and its documentation from both packfile.c and packfile.h.

The patch completes the technical work started in part 3 by eliminating the problematic API entirely, leaving only the more predictable `get_all_packs()` variant. The removal is safe because the series has systematically migrated all callers - first in object naming, then maintenance operations, and finally grep internals - to alternative APIs that don't exhibit the call-order-dependent behavior that made `get_packs()` problematic.

Key technical details: the deletion removes 12 lines total across implementation and header files, with no functional changes since the function was already unused. The remaining `get_all_packs()` function provides the same pack preparation behavior but with more consistent semantics regarding MIDX handling. This patch represents the payoff of the careful incremental conversion work done in prior patches, demonstrating the series' methodical approach to API deprecation.

The change maintains the series' characteristics of being an internal-only cleanup with no user-facing impact, focused narrowly on pack subsystem internals. With this removal, the remaining patches in the series can focus on further cleanups knowing this problematic API is fully eliminated from the codebase.
