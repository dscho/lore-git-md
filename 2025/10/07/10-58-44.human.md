This is patch 7 in a 13-part series refactoring Git's tag peeling and ref iteration infrastructure. The patch converts `builtin/show-ref.c` to use the new `reference_get_peeled_oid()` API introduced earlier in the series, replacing the older `peel_iterated_oid()` function.

The change makes `git show-ref` handle peeled references more consistently across its different modes. The command has three main behaviors - pattern matching, exact matching, and existence checking - and this patch ensures they all use the same internal representation when dealing with peeled tags. The key adjustment is manually constructing a `struct reference` in the existence-checking path to match what the iterator-based paths already provide.

The patch is a straightforward mechanical conversion that maintains all existing functionality while adopting the new API. It's part of the broader effort to eliminate global state in tag peeling and standardize reference handling across Git's codebase. The changes are well-contained to `show-ref` and don't introduce any new behavior - they just make the code work with the new reference abstraction being built up in the series.
