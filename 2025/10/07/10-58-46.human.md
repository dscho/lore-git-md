Refactoring patch in a series modernizing Git's refs subsystem. This is patch 9/13 in Patrick Steinhardt's series to clean up tag peeling behavior and ref iteration infrastructure.

The patch removes the now-obsolete `ref_iterator_peel()` interface and related infrastructure across multiple ref backends (files, packed, reftable). This follows earlier patches that introduced a more direct way to access peeled object IDs via the new `struct reference`. The changes are mostly straightforward deletions, with one notable update in `packed-backend.c` where the code now directly uses the peeled OID from the iterator rather than performing a separate peel operation.

This continues the series' theme of removing technical debt and global state while maintaining the same functionality through better encapsulation. The patch appears mechanically sound, deleting code that is no longer needed after the architectural improvements in earlier patches.
