This is a follow-up discussion in the submodule gitdir path encoding series, where Adrian Ratiu responds to Junio Hamano's feedback on the encoding strategy. The thread has already reached consensus on using URL percent-encoding and a config-based transition approach via `submodule.<name>.gitdirpath`.

Adrian acknowledges Junio's point that encoding should only be applied when necessary (for case-folding or filesystem safety) rather than universally. He raises the practical challenge of detecting when encoding is actually required, noting that filesystem behaviors like case-folding can vary by mount options. While runtime detection would be ideal, Adrian suggests the simpler approach of always encoding might avoid these detection complexities.

The email confirms Adrian will implement Junio's preferred design where:
1. The exact encoding algorithm remains an implementation detail hidden from users
2. `submodule.<name>.gitdirpath` serves as the authoritative mapping
3. The encoding scheme can evolve internally without breaking existing repositories

This represents final alignment on the technical approach after several rounds of discussion, with Adrian preparing to incorporate these changes in v4 of the patch series. The exchange shows the series is in its polishing phase, with all major architectural questions now resolved.
