Performance optimization in the ref-filter subsystem, completing a 13-part series on tag peeling and ref iteration improvements.

This final patch in Patrick Steinhardt's series optimizes `git-for-each-ref` by making object parsing lazy - it now only parses objects when an atom actually needs the parsed data, rather than doing it unconditionally. The change shows a measurable 13% speedup in a Chromium repository benchmark (344ms vs 389ms), with most time now spent on object decompression rather than parsing.

The implementation introduces a new `maybe_object` field in `struct expand_data` to cache parsed objects, and refactors the value-grabbing functions to parse on demand. Error handling is carefully preserved, and the patch maintains all existing functionality while avoiding unnecessary work.

This builds on the previous 12 patches that modernized ref iteration interfaces, removed global state from tag peeling, and fixed tag verification issues. The series as a whole represents a significant cleanup and optimization of Git's ref handling infrastructure.
