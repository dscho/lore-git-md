Christian Couder's series unifying signature processing across `git fast-import` and `git fast-export` is complete and merged to 'next' (`--signed-tags`) and 'master' (`--signed-commits`), with thorough review from Patrick Steinhardt, Collin Funk, Todd Zullinger, and Junio Hamano. The shared `parse_signed_buffer()` infrastructure provides consistent handling of PGP/X.509/SSH signatures, with comprehensive test coverage in t9306-fast-import-signed-tags.sh and t9350-fast-export-signed-tags.sh.

The discussion has reached consensus on technical implementation but continues debating the default mode for `--signed-tags` (`verbatim` vs `abort`). Junio Hamano weighs in supporting the current `verbatim` default, arguing the series improves the status quo by making behavior configurable where previously only verbatim copying was possible. He notes changing defaults now would break existing users, and that future verification work may justify default changes later. Elijah Newren maintains concerns about forward compatibility but hasn't proposed specific changes.

Key aspects:
- Production-ready shared signature handling via `parse_signed_buffer()`
- Symmetric `--signed-tags=<mode>` support with five options: `verbatim`, `warn-verbatim`, `warn-strip`, `strip`, and `abort`
- Mirroring of commit/tag processing between import/export paths
- Documentation updates making git-tag man page format-agnostic
- GPG2 CI issues tracked separately
- Series merged to integration branches with `verbatim` default

The exchange clarifies historical context - verbatim was the only option pre-series - while leaving the technical implementation unchanged. Hamano's position is that configurability satisfies current needs, with default changes deferred until verification capabilities exist. The discussion remains open but unlikely to block merging given the maintainer's stance on backward compatibility.
