This thread introduces and implements a `--signed-tags=<mode>` option for `git fast-import` to provide signature handling parity with `git fast-export`. Christian Couder's series builds on Git's signature infrastructure to support all signature types (PGP, X.509, SSH) consistently across import/export operations.

The series progresses through documentation updates, test improvements, and implementation:
1. Modernizes git-tag documentation to reflect all supported signing methods (with Patrick Steinhardt reviewing and suggesting minor terminology improvements for clarity, recommending "cryptographic signature" consistently and considering whether to list all formats explicitly)
2. Prepares test infrastructure with improvements to t/lib-gpg.sh and t9350-fast-export.sh
3. Adds `--signed-tags` to fast-import.c with modes matching fast-export (verbatim, strip, abort)
4. Updates fast-export.c to use `parse_signed_buffer()` for signature detection
5. Final implementation adds comprehensive handling in fast-import:
   - New signed_tag_mode variable and handle_tag_signature() function
   - Support for all signature types via parse_signed_buffer()
   - Complete test coverage in t9306-fast-import-signed-tags.sh verifying:
     * Signature preservation in verbatim modes
     * Warning generation in warn-* modes
     * Clean stripping in strip modes
     * Proper failure in abort mode
     * Cross-format compatibility (PGP/X.509/SSH)

Patrick Steinhardt's review of the documentation patch approves the overall direction while suggesting minor wording improvements to maintain consistency in terminology and considering the tradeoffs between listing all signature formats versus referring to git-config(1). The implementation maintains consistency with existing signed-commits handling and demonstrates interoperability between fast-export and fast-import operations, with test coverage confirming correct behavior across all signature types and modes. The series achieves unified signature management for repository filtering workflows while modernizing Git's documentation and infrastructure to properly support all signature types.
