This is a response in the ongoing thread about `git bundle --all` behavior, where Junio C Hamano clarifies the expected behavior regarding remote refs in bundles.

Junio explains that the reported behavior is actually correct and intentional - when cloning from a bundle, only `refs/heads/*` should become remote-tracking branches by default, just as they would when cloning from a regular remote. The remote's own remote-tracking branches (stored as `refs/remotes/origin/*` in the bundle) are not meant to be automatically visible, mirroring how standard remote cloning works.

He provides two alternative approaches for users who want all refs: either use the explicit fetch syntax shown in the original report (which he notes is not a workaround but the proper way to request these refs), or do a mirror clone equivalent by initializing a new repo and fetching all refs with `refs/*:refs/*`. 

This response effectively closes the bug report by explaining that the behavior is by design, though it may be worth noting that the original reporter's expectation (that `--all` in bundle creation would imply complete accessibility after clone) represents a reasonable user perspective that might warrant documentation clarification. The thread now appears resolved unless someone wants to reopen discussion about changing the default behavior.
