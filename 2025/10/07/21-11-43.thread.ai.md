Thread identity: Discussion about `git bundle --all` behavior regarding remote refs during cloning, Originally reported by Andrew Harmon as potential bug but clarified by maintainer Junio C Hamano as expected behavior matching Git's standard remote cloning semantics.

Core problem: Discrepancy between bundle creation (which includes all refs with `--all`) and clone behavior (which only fetches local branch refs by default). Junio explained this mirrors Git's conservative approach to remote cloning - remote-tracking branches from original repository (`refs/remotes/origin/*`) represent bundle creator's remote state rather than content meant for transfer.

Current status: Behavior confirmed as intentional design. Two solutions established: (1) explicit fetch of remote refs using `git fetch origin 'refs/remotes/origin/*:refs/remotes/origin/*'` syntax, or (2) mirror clone via `git fetch repo.bndl "refs/*:refs/*"`. Andrew Harmon provided concrete reproduction showing bundle contains all refs but clone only imports local branches, confirming Junio's explanation.

Key technical details: Bundle creation with `--all` correctly includes all refs (verified via `git bundle verify`). Clone operation follows standard Git behavior by only fetching `refs/heads/*` as remote-tracking branches, identical to remote cloning behavior. The confusion stems from expecting bundle cloning to differ from regular remote cloning semantics.

Open questions: Documentation improvements needed to explain: (1) why bundle cloning behaves this way, (2) distinction between bundle contents and clone behavior, (3) recommended patterns for complete repository transfer. Andrew's reproduction provides concrete example that could inform documentation.

Participant positions: Junio C Hamano (maintainer) established this as expected behavior. Andrew Harmon's follow-up with reproduction confirms the behavior but shows ongoing user confusion about the semantics. Thread remains focused on documentation needs rather than code changes.

Impact: While core behavior won't change, clear documentation is needed to help users understand the standard Git semantics at work and the proper techniques for complete repository transfer via bundles. The explicit fetch patterns and mirror clone alternatives provide workable solutions once properly documented.
