Bugfix and refactoring patch in Patrick Steinhardt's tag peeling series (10/13). This patch addresses a subtle issue in tag object verification during peeling operations.

The core problem is that `peel_object()` currently doesn't properly verify the type of tagged objects when peeling tags. The existing code in `parse_tag_buffer()` trusts the type declared in the tag without validation, which could lead to incorrect type assumptions when the object isn't already cached. The patch adds a new `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag to `peel_object()` that enables strict type verification when peeling tags.

Key technical details:
- Introduces new `enum peel_object_flags` with `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag
- Modifies `peel_object()` to accept flags parameter and perform type checking when flag is set
- Inlines and removes `deref_tag_noverify()` function since its functionality is now covered by the flag
- Updates all callers of `peel_object()` to pass 0 for flags (maintaining current behavior)
- Modifies test helper to use `deref_tag()` instead of removed `deref_tag_noverify()`

The change preserves backward compatibility while allowing future patches to opt into stricter verification where needed. The patch notes that we can't simply change `parse_tag_buffer()` to always verify types due to existing tests that rely on the current behavior with potentially corrupted tags.

This is part of a larger effort to clean up tag peeling infrastructure and address inconsistencies in how tag objects store/verify type information. The next patches in the series will presumably start using the new verification flag at appropriate call sites.
