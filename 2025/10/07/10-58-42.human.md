Refactoring patch in a series modernizing Git's refs subsystem, specifically targeting tag peeling behavior. This is patch 5/13 from Patrick Steinhardt's series.

The patch updates `upload-pack.c` to use the new `reference_get_peeled_oid()` API introduced earlier in the series, replacing the older `peel_iterated_oid()` that relied on global state. The change affects how upload-pack announces references to clients during fetch operations.

Key changes:
- Modifies `write_v0_ref()` to take a `struct reference` parameter instead of separate refname/oid parameters
- Updates the capability announcement case to construct a temporary reference struct
- Maintains the same behavior while using the new API consistently
- The patch appears to be a straightforward mechanical conversion, keeping all existing functionality
- Touches only upload-pack.c, with no changes to protocol behavior
- Follows the series' pattern of eliminating global state in favor of encapsulated reference handling

This continues the series' goal of cleaning up ref iteration and tag peeling interfaces while maintaining backward compatibility. The change is well-contained and appears to be a logical next step after the foundational API changes in earlier patches.
