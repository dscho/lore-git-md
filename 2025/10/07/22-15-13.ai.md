This is a response in the ongoing thread about `git bundle --all` behavior, where Junio C Hamano clarifies the expected behavior regarding remote refs during cloning from bundles.

The email pushes back against the original bug report's characterization, arguing that the current behavior is correct and expected. Hamano explains that cloning from a bundle should mirror the behavior of cloning from a remote repository - only `refs/heads/*` become remote-tracking branches by default, while `refs/remotes/origin/*` refs (which represent the original repository's own remote-tracking branches) are not automatically fetched. This matches how regular remote cloning works, where you wouldn't expect to inherit the upstream repository's remote-tracking branches.

Hamano provides two alternative approaches for users who want all refs: either use the explicit fetch syntax shown in the original report (which he notes is not a workaround but the proper way to request remote-tracking branches), or do a mirror clone equivalent by initializing a new repo and fetching all refs with `git fetch repo.bndl "refs/*:refs/*"`. This positions the issue not as a bug but as a misunderstanding of Git's ref handling semantics during clone operations.
