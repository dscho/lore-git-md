This is a follow-up discussion in the submodule gitdir path encoding series, focusing on path handling mechanics during the transition period. Junio C Hamano responds to Adrian Ratiu's concerns about maintaining a mapping between submodule names and their encoded gitdir paths, pushing back against the argument that such mappings would introduce complexity or desynchronization risks.

Junio makes two key technical points: First, he argues that since the system already needs to manage `submodule.<name>.gitdirpath` configurations, centralizing path resolution through this mechanism would actually reduce complexity by providing a single authoritative source of truth. Second, he analyzes Adrian's alternative proposal of using hashed prefixes (`<hash>_<name>`), noting that while the hash prefix helps with uniqueness, it doesn't fully address the core issues of filesystem-unfriendly characters and potential collisions that still require proper encoding.

The exchange reveals remaining implementation-level decisions about how exactly to handle path resolution during the transition to encoded gitdir paths. Junio's position favors a more centralized mapping approach through config, while Adrian had previously preferred simpler transformation rules. This discussion occurs after all major architectural decisions (like using percent-encoding) have been settled in earlier rounds of review.
