This is a process discussion in the ongoing Git 3.0 release planning thread, specifically about coordinating the SHA-256 transition with ecosystem stakeholders.

Patrick Steinhardt responds to Michal Suchánek's additions to the list of projects to consult about SHA-256 compatibility. He clarifies that pygit2 (a Python binding for libgit2) doesn't need separate consideration from libgit2 itself, as it's just a wrapper. However, he agrees with Michal's suggestion to add Gitea to the list of forges that should be consulted.

The exchange is brief and technical, showing alignment on the process of gathering ecosystem input while maintaining precision about what constitutes an independent implementation versus a binding. This continues the thread's focus on thorough stakeholder engagement for the SHA-256 transition, though it doesn't introduce new substantive discussion points about the technical implementation or timeline considerations.
