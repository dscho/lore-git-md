Refactoring patch in the packfile store API cleanup effort, specifically converting object-name.c to use `packfile_store_get_all_packs()`.

This is the first patch in a 6-part series that follows Taylor Blau's earlier work on the packfile store API. The change focuses on eliminating the problematic distinction between `packfile_store_get_packs()` and `packfile_store_get_all_packs()`, where the former's behavior depends on whether the latter was called first. The patch converts two functions in object-name.c that handle object ID disambiguation and abbreviation length calculation.

The key technical points are:
1. The object-name subsystem searches packs in two phases - first MIDX-indexed packs, then non-MIDX packs
2. The current code uses `get_packs()` for the second phase but must handle MIDX packs anyway due to the API's statefulness
3. The change to `get_all_packs()` is safe here because the code already knows to skip MIDX'd packs in both `find_abbrev_len_packed()` and `find_short_packed_object()`

The patch is a straightforward mechanical conversion touching just two call sites in object-name.c. It maintains all existing functionality while moving toward the series' goal of removing the confusing dual-API. The change aligns with the broader packfile store abstraction work but doesn't introduce any user-facing behavior changes.
