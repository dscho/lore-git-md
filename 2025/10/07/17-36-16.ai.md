Randall Becker from HPE NonStop reports their specific blocking issue is Rust availability on their platform, with vendor discussions indicating at least a year's delay. While their front-end implementation has been SHA-256 ready for two years, the Git build dependency on Rust creates a hard blocker.

The email continues the thread's theme of ecosystem readiness assessment, with Randall providing concrete data about NonStop's situation. His implementation uses a decoupled architecture where the front-end is already prepared but the back-end Git build is stalled on Rust adoption. This adds another dimension to the coordination challenges, showing how platform-specific toolchain issues can create unexpected delays even when the code itself is ready.

The message reinforces Patrick Steinhardt's earlier point about needing comprehensive stakeholder input, while demonstrating the practical difficulties in establishing a unified timeline.
