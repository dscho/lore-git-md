Packfile store API refactoring (part 2/6) - converting git-gc's incremental repack auto-condition check. This patch by Patrick Steinhardt continues Taylor Blau's series to eliminate the confusing `packfile_store_get_packs()` function in favor of `packfile_store_get_all_packs()`.

The change focuses on the auto-condition logic in `builtin/gc.c` that determines when to trigger an incremental repack. The existing code counts non-MIDX-indexed packs using `get_packs()`, which intentionally excludes MIDX-covered packs. The patch switches to `get_all_packs()` while maintaining the same behavior, since the counting logic already explicitly checks each pack's `multi_pack_index` flag.

This is a straightforward conversion that demonstrates how callers can safely transition to the simpler API when they already handle MIDX/non-MIDX distinction themselves. The patch touches only one line in `builtin/gc.c`, changing the pack iteration function while preserving the existing filter logic. No behavior change is expected since the counting condition remains identical - it's just operating on a superset of packs now.

The change aligns with the series' goal of systematically converting all callers before removing the stateful `get_packs()` API. This particular conversion is low-risk as the caller's logic is already MIDX-aware, making it a good candidate for early adoption in the series. The patch follows the established pattern from part 1 (object-name.c conversion) while moving to a different subsystem (maintenance operations).
