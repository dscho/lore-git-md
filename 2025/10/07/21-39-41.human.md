This is the second part of a documentation patch series updating Git's SubmittingPatches guidelines, focusing on multi-series patch submission practices.

The patch adds formal guidance for contributors working on larger efforts that span multiple patch series. It documents the existing convention of using "-part-one", "-part-two" suffixes for topic names in line with maintainer practices. The change suggests contributors should both describe the broader goal and indicate where each series fits within that goal.

The patch is straightforward, adding 8 lines to the SubmittingPatches document. It builds on the first patch's work on topic naming conventions (which introduced the optional "XX/your-topic-name" format) by extending it to multi-series efforts. Like the first patch, this maintains an experimental tone while formalizing existing practices.

The change appears well-considered, with Junio Hamano's involvement indicated by the Suggested-by tag. It follows Git's gradual approach to workflow documentation improvements, building on practical conventions that have emerged organically rather than introducing new requirements. The patch series as a whole seems aimed at making contributor expectations clearer while preserving flexibility.
