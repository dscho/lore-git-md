Bugfix for inconsistent color handling in `git status --short -z` output.

Jeff King clarifies that the original reporter's expectation of color suppression with `-z` in short status output doesn't match Git's documented behavior - colors are meant to be preserved in `--short` mode regardless of `-z`. However, he confirms there is indeed a bug where the color behavior is inconsistent between modified (`M`) and untracked (`??`) markers in this mode.

The proposed fix adjusts the color handling in `wt-status.c` to make the untracked marker behavior consistent with other status outputs by moving the color application before the null-termination check. This matches how other status functions like `wt_shortstatus_unmerged()` handle colors.

While fixing the inconsistency, Jeff notes that using `-z --short` together is somewhat unusual since `-z` is typically used with machine-readable output (`--porcelain`) while `--short` is meant for human consumption. He suggests alternative commands that would fully suppress colors as the reporter expected.

The patch appears straightforward and well-justified, addressing a clear inconsistency in behavior while correctly documenting the expected color behavior in different output formats.
