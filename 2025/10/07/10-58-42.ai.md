Refactoring patch in a series modernizing Git's refs subsystem, specifically targeting tag peeling behavior. This patch converts `upload-pack.c` to use the new `reference_get_peeled_oid()` API introduced in patch 4, eliminating its dependency on the old `peel_iterated_oid()` function that relied on global state. The change affects two code paths in `write_v0_ref()`: the normal ref advertisement case (which already had access to a `struct reference`) and the special capabilities announcement case (which now constructs a temporary reference struct).

Key technical changes:
- Modifies `write_v0_ref()` to take a `struct reference` parameter instead of separate refname/oid parameters
- Updates the capabilities announcement case to construct a minimal reference struct for the null object ID case
- Replaces all `peel_iterated_oid()` calls with `reference_get_peeled_oid()`
- Maintains identical behavior while using the new API
- Updates the `send_ref()` callback to pass through the reference struct directly

The patch is a straightforward mechanical conversion that builds on the infrastructure changes from earlier in the series. It demonstrates how the new reference API simplifies callers by providing consistent access to peeled OIDs without global state. The changes are limited to `upload-pack.c` and don't introduce new functionality - they just migrate existing behavior to the new interface.

This appears to be a clean, focused change that follows the series' goal of removing global state from the refs subsystem. The patch maintains backward compatibility while moving toward the new API, and the manual reference construction for the capabilities case is a reasonable workaround for that special case.
