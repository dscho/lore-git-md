Rust safety documentation patch in the CI infrastructure series.

This is the third patch in Patrick Steinhardt's 6-part series improving Rust tooling in Git's CI. The change adds required safety documentation to unsafe Rust functions in `src/varint.rs` that interface with C code. The functions `decode_varint()` and `encode_varint()` are FFI implementations matching C counterparts and thus use raw pointers, requiring `unsafe` blocks.

The patch adds detailed Rustdoc-style safety comments explaining the preconditions callers must meet: for `decode_varint()`, the input must be NUL-terminated; for `encode_varint()`, the buffer must be large enough (with specific guidance about using a 16-byte array or NULL pointer probing). These comments address upcoming Clippy linter requirements being introduced in the series.

The changes are straightforward and well-justified, maintaining consistency with Rust best practices for unsafe code documentation. The patch fits cleanly into the series' broader goal of establishing robust Rust tooling infrastructure, specifically preparing for Clippy integration by preemptively addressing its safety documentation checks. The safety requirements documented here reflect the existing C interface rather than introducing new constraints.
