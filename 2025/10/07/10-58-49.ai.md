This is patch 12/13 in a refactoring and bugfix series addressing tag peeling behavior in Git's refs subsystem. The patch focuses on improving tag verification in `git-for-each-ref`.

The patch fixes a subtle bug where `git-for-each-ref` would only detect tag corruption (mismatch between declared and actual object type) when processing multiple tags pointing to the same object with different declared types. The root cause is that `peel_object()` was only verifying types when doing multiple lookups, not during the first dereference.

The solution modifies `populate_value()` in ref-filter.c to use the `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag (introduced in patch 10) when peeling tags, ensuring type verification happens on every dereference. The test is expanded to verify the fix catches single-tag corruption cases.

Key technical details:
- Modifies the single call to `peel_object()` in `populate_value()` to include verification
- Updates the test case to check both the original multi-tag scenario and a new single-tag case
- Builds on the verification infrastructure from earlier patches in the series
- Maintains backward compatibility while making verification more thorough

This completes the tag verification improvements started in patch 10, ensuring consistent type checking regardless of how tags are processed. The change is relatively small but plugs an important hole in the verification logic.
