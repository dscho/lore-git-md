This is part 1 of a 6-part refactoring series in the packfile subsystem, building on Taylor Blau's earlier packfile store work. The patch converts two functions in `object-name.c` from using `packfile_store_get_packs()` to `packfile_store_get_all_packs()` as part of eliminating the confusing stateful behavior between these two functions.

The change affects how Git searches for abbreviated object IDs and handles disambiguation. While the old `get_packs()` function would sometimes exclude MIDX-indexed packs depending on whether `get_all_packs()` had been called first, the new version always includes all packs. The commit explains this is safe because the calling functions already know to skip MIDX'd packs when needed.

This is a straightforward mechanical conversion that touches only two call sites in `object-name.c`. The change aligns with the series' goal of simplifying the packfile API by removing the problematic stateful behavior. As the first patch in the series, it handles a relatively simple case before tackling more complex conversions in subsequent patches. The change appears well-justified and low-risk, with no apparent impact on functionality.
