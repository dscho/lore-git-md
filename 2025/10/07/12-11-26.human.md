This is a refactoring patch from Karthik Nayak's reftable fsck validation series (now merged to 'next'). The change moves a consistency check message from being files-backend specific to the generic refs layer, allowing both files and reftable backends to use it.

The patch is quite straightforward - it relocates the "Checking references consistency" message print from `refs/files-backend.c` to `refs.c`, where it will be executed for any ref store implementation before calling the backend-specific fsck function. This ensures consistent messaging across both storage backends.

The change is minimal (4 lines added, 2 removed) and well-contained, with no behavior changes beyond the message location. It's part of the larger effort to bring reftable fsck capabilities to parity with the files backend, though this particular patch is purely about code organization rather than adding new functionality. The patch follows good hygiene by including the necessary `fsck.h` header in `refs.c` where it's now needed.
