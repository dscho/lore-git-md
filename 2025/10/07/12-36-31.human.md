This is part of Patrick Steinhardt's series improving Rust tooling in Git's CI infrastructure, specifically focusing on Rust code safety documentation. The patch adds safety comments to two unsafe functions in `src/varint.rs` that interface with C code.

The changes document the safety requirements for `decode_varint()` and `encode_varint()`, which use raw pointers to maintain compatibility with their C counterparts. The comments explain that callers must provide properly terminated buffers and specify size constraints. This preemptively addresses warnings that would be caught by Clippy, which the series is in the process of integrating.

The patch is straightforward and well-justified, following Rust best practices for unsafe code documentation. It's a small but meaningful step in the broader effort to properly instrument Rust code in Git's codebase. The changes are purely additive and don't modify any behavior, just adding documentation that will help maintainers understand the safety requirements of these FFI interfaces.
