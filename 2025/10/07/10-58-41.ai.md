Refactoring patch in a series modernizing Git's refs subsystem, specifically addressing tag peeling behavior. This is patch 4/13 in Patrick Steinhardt's series.

The patch eliminates fragile global state in tag peeling by introducing a new `peeled_oid` field in `struct reference`. Previously, callbacks had to use `peel_iterated_oid()` which relied on a global iterator variable. The new `reference_get_peeled_oid()` function provides direct access to pre-peeled values when available (from backends' storage), falling back to ODB peeling otherwise.

Key technical changes:
- Adds `peeled_oid` field to `struct reference`
- Implements new `reference_get_peeled_oid()` API
- Updates packed and reftable backends to populate the new member
- Converts 8 callers (describe, gc, pack-objects, etc.) to use new API
- Maintains same peeling behavior but with cleaner interface

The change is part of a larger effort to clean up refs iteration infrastructure. It follows patches 1-3 which introduced the `struct reference` wrapper and consolidated iterator fields. The implementation appears thorough, touching all relevant backends and updating multiple call sites while maintaining backward compatibility. The patch avoids behavior changes while making the peeling interface more robust and less dependent on global state.
