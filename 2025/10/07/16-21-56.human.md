This is a reply in the ongoing submodule gitdir path encoding thread, where Junio C Hamano is providing guidance on the migration strategy for existing submodule directories. 

Junio argues against Adrian Ratiu's proposed approach of migrating all existing gitdirs to the new encoding scheme when the extension is first enabled. Instead, he suggests leveraging the already-implemented `submodule.<name>.gitdirpath` configuration as a safer way to handle existing submodules without physically moving directories. 

The key technical point is that the config-based approach avoids potential risks of directory moves while still providing a way to resolve any existing problematic cases. Junio does acknowledge one exception where physical moves might be necessary - when existing submodule gitdirs already have path conflicts (like `.git/modules/A` and `.git/modules/A/B` existing simultaneously).

This email represents a refinement of the transition strategy rather than a fundamental change to the encoding approach. The discussion has moved from architectural decisions to implementation details of how to handle the migration period. Junio's position here favors minimal disruption to existing repositories while still allowing the new encoding system to be adopted.
