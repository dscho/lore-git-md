Refactoring patch in a series improving ref iteration and tag peeling. This is patch 2/13 in Patrick Steinhardt's series, which introduces a `struct reference` field in the base iterator to consolidate ref metadata handling.

The patch replaces scattered fields in `struct ref_iterator` (refname, referent, oid, flags) with a single `struct reference` member. This simplifies iterator implementations by having them populate this struct directly rather than setting individual fields. The change affects all ref iterator backends (files, packed, reftable) and supporting code, with mechanical updates to access the fields through the new struct.

Key technical details:
- Changes 65 files across refs handling code
- Updates all callers to use `iter->ref.name` instead of `iter->refname` etc.
- Affects core iterator operations like `advance()`, `peel()`, and selection logic
- Modifies ref filtering and packing logic to use the consolidated struct
- Preserves all existing behavior while making the interface more maintainable

The change is part of a larger effort to clean up ref iteration interfaces and optimize tag peeling, building on the series' first patch which introduced the `struct reference` wrapper for callback functions. This continues the pattern of encapsulating ref metadata to make future interface changes less disruptive.
