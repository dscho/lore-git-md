This is a review response in the ongoing refactoring series about tag peeling behavior in Git's refs subsystem. Karthik Nayak is reviewing patch 5/13, which converts `upload-pack.c` to use the new `reference_get_peeled_oid()` API.

The patch deals with how `upload-pack` handles reference writing and tag peeling during protocol communication. Karthik confirms the technical approach of manually constructing a `struct reference` for the capability-announcement case, allowing consistent use of the new peeling API. He notes the code currently mixes capability handling with reference writing in `write_v0_ref()`, suggesting these should be separate functions - though this is outside the scope of the current series.

Karthik gives implicit approval of the patch's solution while pointing to a potential future cleanup opportunity. The change is part of Patrick Steinhardt's larger effort to modernize ref iteration and eliminate global state in the peeling infrastructure. This particular conversion helps maintain consistency as the series removes the old `peel_iterated_oid()` function in later patches.
