This thread clarifies the behavior of `git bundle --all` when cloning repositories, which initially appeared inconsistent to reporter Andrew Harmon. Maintainer Junio C Hamano explained that while `--all` correctly includes all refs (both local branches and remote-tracking branches) in the bundle, cloning from such a bundle follows Git's standard behavior of only fetching local branch refs (`refs/heads/*`) as remote-tracking branches. This matches how regular remote cloning works - the original repository's remote-tracking branches (like `refs/remotes/origin/*`) represent the bundle creator's state, not content meant for the clone.

Andrew provided a concrete reproduction showing this behavior, confirming the bundle contains all refs but the clone operation imports only the local branches. Junio suggested two proper solutions for complete repository transfer: either explicitly fetching remote refs with `git fetch origin 'refs/remotes/origin/*:refs/remotes/origin/*'` or using a mirror clone approach. The discussion has shifted to improving documentation to better explain this behavior and the recommended patterns, as the current behavior is working as designed rather than being a bug. The thread remains focused on how to best document these nuances for users expecting different behavior from bundle cloning.
