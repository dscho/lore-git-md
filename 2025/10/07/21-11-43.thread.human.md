Junio C Hamano has clarified that the current behavior of `git bundle --all` is intentional, not a bug. He explains that when cloning from a bundle (just like when cloning from a remote repository), only `refs/heads/*` become remote-tracking branches by default - the bundle's own remote-tracking branches (`refs/remotes/origin/*`) are not automatically fetched, as this would mirror the original repository's remote state rather than create new tracking branches. 

For users who need all refs, Hamano confirms two proper approaches: either use the explicit fetch syntax (`git fetch origin 'refs/remotes/origin/*:refs/remotes/origin/*'`) as originally suggested, or perform a mirror clone by initializing a new repository and fetching all refs with `git fetch repo.bndl "refs/*:refs/*"`. This positions the issue as a documentation clarification rather than a code change, suggesting the behavior is working as designed according to Git's standard ref handling semantics. The thread may conclude with improved documentation explaining these expectations.
