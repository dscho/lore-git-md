This thread clarifies the behavior of `git bundle --all` when cloning, where a common expectation (that it would mirror cloning from a remote) doesn't match Git's actual conservative approach. The discussion was sparked by Andrew Harmon's report of what initially appeared to be a bug, but maintainer Junio C Hamano confirmed this is intentional design - bundles follow the same semantics as remote clones, where only local branch refs are fetched by default, even though the bundle contains all refs (including remote-tracking ones).

The thread has established two reliable methods for complete repository transfer via bundles: either an explicit fetch of remote refs using specific refspecs, or a mirror clone. Andrew provided a concrete reproduction case that clearly demonstrates both the default behavior and the workarounds, which could serve as excellent documentation material. While the technical behavior is now well-understood, the consensus is that the documentation should be enhanced to explain the design philosophy, the recommended patterns for different use cases. This would help users avoid similar confusion in the future.
