This thread explores a documentation gap in how `git bundle --all` handles remote refs during cloning. The discussion began when Andrew Harmon reported unexpected behavior where not all refs were fetched from a bundle, despite using `--all`. Junio Hamano confirmed this is intentional, matching Git's standard remote cloning semantics where only certain refs are fetched by default for security reasons.

Andreas Schwab provided key technical context, explaining that bundles reflect the state of the local clone used to create them - a regular clone will only include limited refs, while a mirror clone preserves everything. Andrew later confirmed this solution worked in practice, though they noted it took significant searching to discover. The thread has converged on clear documentation needs: explaining the security rationale behind the default behavior, showing examples of both regular and mirror clone approaches, and incorporating Andrew's diagnostic method of comparing `ls-remote` outputs.

The discussion highlights a real user pain point where the current documentation falls short, with multiple participants agreeing that adding these explanations would help others avoid similar confusion. With both the problem and solution now clearly demonstrated through concrete examples, this thread presents a valuable opportunity to improve the docs.
