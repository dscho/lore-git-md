This is a documentation patch series aimed at improving Git's contributor guidelines. Taylor Blau proposes two changes to the SubmittingPatches documentation based on earlier suggestions from Junio Hamano.

The first patch extends an existing experiment (started in March 2024) that encourages contributors to propose release notes entries along with their patches. The new version would also have them suggest a topic branch name. The second patch adds guidance about how to describe work that spans multiple patch series, helping maintainers understand how individual series fit into larger efforts.

The changes are relatively small (21 lines added, 8 removed) and focused on clarifying contributor expectations. The series appears well-motivated, referencing specific prior discussions, and builds on existing documentation practices. The author notes that one of Junio's three original suggestions is already covered, making this a logical completion of that documentation effort.

As an open question, Taylor suggests the community might want to evaluate whether the original release-notes experiment (from March 2024) has been successful enough to make permanent. This could be an interesting discussion point for reviewers.
