Taylor Blau has proposed a two-part update to Git's SubmittingPatches documentation, with input from maintainer Junio Hamano. The first part formalized the experimental "XX/your-topic-name" branch naming convention (where XX represents author initials), while this second part adds guidance for contributors working on large efforts that span multiple patch series. 

The new guidance recommends clearly describing the broader goal when submitting a series that's part of a larger effort, stating where the current series fits within that goal, and using consistent "-part-one", "-part-two" suffixes when following the topic branch naming convention. Both changes maintain the experimental status of these practices while documenting them more thoroughly for contributors.

The patches are purely documentation-focused, modifying only the SubmittingPatches file with no code or test changes. They build on prior work (commits d255105c99 and 0a02ca2383) and follow Git's gradual approach to workflow improvements. Junio Hamano has been involved in shaping both parts of the series, as evidenced by Suggested-by tags, and there have been no objections to these straightforward documentation updates. The series appears ready to be picked up for merging.
