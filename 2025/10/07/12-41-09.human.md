This is part 3/6 of the packfile store API refactoring series, focusing on `git grep`'s packfile preloading behavior. The patch simplifies how `git grep` initializes packfiles when running with multiple threads by directly calling `packfile_store_prepare()` instead of going through the indirect `packfile_store_get_packs()` wrapper.

The change is straightforward - the code was previously calling `get_packs()` just to trigger packfile initialization, ignoring its return value. Now it calls the initialization function directly, making the intent clearer. This aligns with the series' goal of eliminating confusion between the `get_packs()` and `get_all_packs()` functions.

The patch touches only one line in `builtin/grep.c` and maintains identical behavior, as the underlying initialization logic remains the same. It builds on recent changes that made `packfile_store_prepare()` publicly accessible. The change appears low-risk since it doesn't affect the actual searching logic - it just optimizes how packfiles are loaded before multi-threaded grep operations begin.

This continues the series' pattern of methodically converting callers of `get_packs()` before its eventual removal. The patch follows the same careful approach seen in previous parts, with a particularly clean justification since the return value was being ignored anyway.
