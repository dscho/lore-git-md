Performance optimization patch in Patrick Steinhardt's refs/tag peeling series (13/13). This final patch modifies `ref-filter.c` to parse Git objects on demand rather than eagerly when formatting ref output, specifically targeting `git-for-each-ref`.

The key change introduces lazy parsing through a new `get_or_parse_object()` helper that only parses objects when an atom actually needs the parsed data. This affects several value-grabbing functions (`grab_tag_values`, `grab_commit_values`, etc.) which now take the expand_data struct directly rather than a pre-parsed object. The patch shows a measurable 13% speedup in a Chromium repository benchmark (344.7ms vs 388.7ms for `--format='%(raw)'` across 40k refs), with object decompression becoming the dominant cost.

Technical details include:
- New `maybe_object` field in `struct expand_data` to cache parsed objects
- Modified return types for grab functions to propagate parsing errors
- Preservation of the `eaten` flag to properly handle object memory management
- Updated test infrastructure to handle the new error paths
- Maintained backward compatibility with all existing ref-filter atoms

This builds on the series' earlier work (particularly patch 6's ref-filter changes) and represents the performance payoff from the structural refactoring done in previous patches. The change is particularly impactful for workflows using simple formatting that doesn't require full object parsing.
