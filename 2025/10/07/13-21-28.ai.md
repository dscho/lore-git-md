This is a process discussion email in the ongoing Git 3.0 release planning thread focused on SHA-256 interoperability. Patrick Steinhardt responds to Michal Suchánek's suggestions about which projects and forges to include in ecosystem coordination for the SHA-256 transition.

The email clarifies that pygit2 (a Python binding for libgit2) and similar bindings like git2go/git2-rs don't need separate inclusion in the outreach list since they inherit their SHA-256 support from libgit2. Patrick agrees with Michal's addition of Gitea to the forge list alongside GitHub, GitLab, Bitbucket, Forgejo and SourceHut.

This is a minor but important clarification in the broader context of gathering ecosystem input for the SHA-256 transition. The exchange shows the careful consideration being given to which projects truly represent independent implementation/forge efforts versus those that are wrappers around existing implementations. No new technical details about the SHA-256 implementation itself are discussed here - this remains focused on the coordination process aspects of the transition.
