This is a bugfix patch in the reftable fsck validation series, specifically addressing parser validation for the 'tables.list' file format. The patch modifies `parse_names()` in reftable/basics.c to enforce strict newline termination requirements, returning `REFTABLE_FORMAT_ERROR` if the input lacks a trailing newline.

The key changes include:
1. Converting `parse_names()` from returning a `char**` to using an output parameter and returning an error code (0 for success, `REFTABLE_FORMAT_ERROR` for missing newline, `REFTABLE_OUT_OF_MEMORY_ERROR` for allocation failures)
2. Adding explicit error handling paths with proper cleanup
3. Updating the function's documentation to reflect the new error reporting behavior
4. Modifying callers in stack.c to handle the new error-returning interface
5. Adding new unit tests in u-reftable-basics.c to verify the missing-newline case

The patch maintains backward compatibility with existing valid inputs while adding stricter validation. This change is part of the larger reftable fsck validation effort that has already been approved and merged to 'next', with this being one of the final polishing patches addressing test case feedback from Jeff King. The implementation is thorough, with clear error handling and test coverage for both the happy path and error cases.
