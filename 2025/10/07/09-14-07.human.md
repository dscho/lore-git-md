This is a follow-up in the ongoing thread about performance issues with Git's untracked files cache behavior. Devste Devste confirms the "sticky cache" phenomenon where once the cache is created with certain flags, it persists even when those flags are later removed. They note a practical impact: users of tools like SourceTree (which may use these flags internally) would need to manually run `git status --untracked-files` periodically to keep the cache fresh.

The email builds on Matthew Hughes' earlier finding that `--no-optional-locks` is the specific flag preventing cache updates, causing significant performance degradation (1s vs 300ms). The discussion reveals a concerning interaction where tooling that uses common flags like `--no-optional-locks` can inadvertently degrade `git status` performance over time by preventing cache updates. This appears to be a real issue affecting multiple platforms, with clear performance implications for users of GUI tools that employ these flags.
