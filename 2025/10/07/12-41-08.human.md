This is part 2 of a 6-part series refactoring Git's packfile store API to eliminate confusion between two similar functions. The patch converts `builtin/gc.c` to use `packfile_store_get_all_packs()` instead of `packfile_store_get_packs()` when checking whether incremental repacks are needed.

The change affects Git's maintenance tasks, specifically the auto-condition that determines when to run an incremental repack (which combines smaller packs into larger ones via `git multi-pack-index repack`). The original code used `get_packs()` to count non-MIDX-indexed packs, but since the function already explicitly filters out MIDX'd packs, switching to `get_all_packs()` is safe and maintains the same behavior.

The patch is straightforward - just a one-line change in `builtin/gc.c` that replaces the function call. It's part of Patrick Steinhardt's continuation of Taylor Blau's work to simplify the packfile store API by removing the stateful `get_packs()` function in favor of the more predictable `get_all_packs()`. The change aligns with the series' goal while being low-risk since it touches a well-contained maintenance operation.
