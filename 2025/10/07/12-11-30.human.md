This is part 6 of a 7-part bugfix series adding fsck validation for the reftable backend, now merged to 'next' after several iterations. The patch introduces the core infrastructure for reftable consistency checks, specifically validating table name formats in the reftable stack.

Karthik Nayak adds a new `reftable/fsck.[ch]` module that provides a callback-based API (`reftable_fsck_check()`) to validate reftable stacks while keeping the reftable library independent from Git internals. The initial check enforces that table names follow the `${min_update_index}-${max_update_index}-${random}.ref` format pattern, reporting errors through a structured callback interface.

The implementation includes thorough error handling and verbose progress reporting, with the table name validation using careful strtoull/strtoul parsing to verify the numeric components. The patch also makes minor build system adjustments to maintain lexicographic ordering of object files in the Makefile.

This is a well-structured addition that completes an important piece of the reftable fsck functionality, following the pattern established in earlier parts of the series. The callback design leaves room for future expansion with additional validation checks while maintaining clean separation between the reftable library and Git-specific code.
