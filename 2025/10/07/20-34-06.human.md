Bugfix for inconsistent color handling in `git status --short -z` output.

Jeff King submits a final version of the fix for the color inconsistency in `git status` when using both `--short` and `-z` flags. While modified files (`M") were being colored, untracked files (`??`) were not. The patch moves the color application before the null-termination check in `wt_shortstatus_other()` to make the behavior consistent.

The commit message provides important context about this being an unusual but valid combination of flags - `--short` is meant for human-readable output (and thus keeps colors) while `-z` alone defaults to machine-readable `--porcelain` mode. The fix aligns with existing behavior in other parts of the status output code.

This version adds a test case to verify the behavior, addressing the only outstanding item from the earlier discussion. The change is small and focused, touching just 4 lines in `wt-status.c` while adding a thorough test. With Jeff King's review confirming the technical approach, this appears ready for inclusion.
