This is part 7 of Patrick Steinhardt's refactoring series on tag peeling behavior, converting `builtin/show-ref.c` to use the new `reference_get_peeled_oid()` API introduced earlier in the series.

The patch focuses on unifying the code paths in `git show-ref` that handle reference display. The command has two main modes - pattern matching and exact reference verification - which previously used different infrastructure. The pattern matching path already had access to a `struct reference` from the iterator, while the verification path used `refs_read_ref()` and worked directly with refname/OID pairs.

The key change creates a temporary `struct reference` in the verification path to maintain consistency with the pattern matching path. This allows both paths to use the new `reference_get_peeled_oid()` function rather than the older `peel_iterated_oid()`. The patch carefully preserves all existing behavior while eliminating the last direct use of the old peeling API in this file.

Technical details include:
- Modifies `show_one()` to take `struct reference` instead of separate refname/OID
- Constructs temporary `struct reference` in `cmd_show_ref__verify()`
- Updates error handling to maintain same behavior when references are invalid
- Keeps same output format but uses new API internally
- Follows the series' pattern of encapsulating ref data in `struct reference`

This continues the series' systematic conversion of callers to the new peeling infrastructure, with `show-ref` being a relatively straightforward case since it doesn't need the peeled OID in verification mode. The change is mechanical but important for completing the API transition.
