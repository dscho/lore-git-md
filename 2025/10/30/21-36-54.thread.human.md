Git's development status update thread tracks the progress of various in-flight topics, with recent focus on a version tag sorting regression in the ps/ref-peeled-tags changes. Jeff King identified the root cause as unreset object caching in ref-filter.c's grab_values() function, where both `oi` and `oi_peeled` were incorrectly treated as global rather than per-reference variables. His proposed one-line fix to reset `data->maybe_object` has now been confirmed correct by Patrick Steinhardt, the original author of the ref-peeled-tags changes.

Patrick agrees with the analysis and indicates he'll send an updated patch shortly, though he suggests using `get_object()` as the entry point for grab_values() as an alternative approach. The bug affects both loose and packed ref scenarios when using `git tag --list --sort=version:tag` with tags like vsample-1.0, vsample-2.0, and vsample-10.0. While the core issue is now understood and the solution path clear, minor implementation details remain regarding the exact placement of the object cache reset. The fix will preserve the performance benefits of the original on-demand object parsing changes while correcting the regression.
