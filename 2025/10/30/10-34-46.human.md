This is a refactoring patch in Patrick Steinhardt's ongoing series to improve Git's loose object handling as part of the object database abstraction effort. Karthik Nayak is reviewing patch 1/13, which fixes a subtle issue in how alternate object database paths are checked and stored.

The patch changes `alt_odb_usable()` to no longer modify the path map directly, making the ownership of paths more explicit. Instead of storing paths during the usability check, the path is now stored after creating the source object, using the source's path pointer directly. This clarifies the memory ownership pattern that was previously subtle and prone to breakage during refactoring.

Karthik approves the change, noting it makes the code's intent clearer by separating the path checking and storage operations. The patch maintains all existing behavior while improving the code structure - a common theme in this well-reviewed series. This is a straightforward improvement that addresses a real maintainability concern in the ODB code.
