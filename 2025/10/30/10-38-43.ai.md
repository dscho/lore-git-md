This is part 6 of an 8-part refactoring series moving packfile management into a new `packfile_store` abstraction. The patch continues consolidating packfile list handling by moving the main packfile list from a direct `struct packed_git` linked list into the `packfile_list` structure within `packfile_store`.

Key technical changes:
- Replaces direct `packed_git` linked list with `packfile_list` structure throughout packfile.c
- Updates all iteration patterns to use `packfile_list_entry` traversal
- Modifies `packfile_store_get_packs()` to return the list entry head rather than raw pack pointer
- Adjusts `repo_for_each_pack` macro to work with new list structure
- Removes standalone `find_oid_pack()` function (replaced by `packfile_list_find_oid()`)
- Updates fast-import.c to use new API for pack lookups

The changes are mechanical but thorough, touching pack window scanning, pack closing, MRU preparation, and store management. This continues the series' pattern of centralizing packfile management while maintaining existing behavior. The patch follows the same approach as the earlier MRU list migration (patch 2), completing the transition of all packfile lists to the new abstraction.

This represents a core piece of the packfile store refactoring, though it doesn't introduce new functionality. The changes are consistent with the series' direction and incorporate the established `packfile_list` API. With this patch, all packfile list management now flows through the store abstraction.
