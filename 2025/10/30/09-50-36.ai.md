This is a discussion about Rust version compatibility in the context of the cbindgen integration series. The email clarifies the current Rust version policy (1.49) and the rationale behind it, while leaving room for intentional updates if justified.

Patrick Steinhardt explains that the current Rust 1.49 target was chosen to align with gcc-rs's version requirements, which could help bring support to currently unsupported platforms sooner. However, he notes this isn't set in stone - he's previously stated willingness to update the minimum version if there are strong technical reasons to do so. The key point is that any version bump should be done deliberately rather than arbitrarily.

The email responds to concerns raised by Brian M. Carlson and Ezekiel Newren about cbindgen compatibility with older Rust versions. Brian had noted that newer cbindgen versions (like 0.27.0) require Rust 1.70+, which would conflict with the current 1.49 target. Junio Hamano had questioned whether there was any formal agreement on Rust version policy beyond Brian's earlier proposal to track Debian stable+oldstable versions (which would currently mean Rust 1.63).
