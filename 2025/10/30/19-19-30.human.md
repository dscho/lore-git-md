Feature patch for `git replay` making atomic ref updates the default behavior.

This patch (part 2/3 of the series) changes `git replay` to update references atomically by default, rather than outputting commands for `git update-ref`. The new behavior uses Git's ref transaction API to ensure all-or-nothing updates. The original pipeline output mode remains available via `--ref-action=print` for testing and special cases.

The implementation introduces a `handle_ref_update()` helper that works in both modes (print or update), with type safety via a new `enum ref_action_mode`. Tests are updated to explicitly use `--ref-action=print` where they expect command output, while new tests verify the atomic behavior in both regular and bare repositories.

This change addresses the main ergonomic pain point for server-side use, where the pipeline architecture created process coordination overhead. The patch is well-tested and follows Git's standard patterns, with all reviewer feedback from previous iterations addressed. The next patch in the series will add a `replay.refAction` config option for persistent preference setting.
