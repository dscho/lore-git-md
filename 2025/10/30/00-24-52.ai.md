This is a platform compatibility issue affecting test execution on NonStop systems. Randall Becker provides a key insight into the root cause of the test failures in t7900: while the Make environment specifies `/bin/bash` for outer processing, the test scripts' `#!/bin/sh` shebang causes them to run under ksh` instead on NonStop systems. This explains the earlier discrepancy in test output traces and the `test: argument expected` errors with `test_subcommand !` assertions.

The issue manifests specifically when running maintenance-related tests that verify `git gc` invocations with negated assertions. Randall confirms that manually running the tests with bash resolves the failures, but notes this creates a significant maintenance burden as it requires manual intervention for each failing test. The problem stems from GNU Make 4.1.2's behavior of only applying SHELL=/bin/bash to recipe processing while respecting the shebang's shell specification.

This email advances the debugging by identifying the shell selection discrepancy as the root cause, though it doesn't yet propose a solution. The issue appears specific to NonStop's shell configuration and GNU Make interaction, rather than being a bug in Git's test infrastructure itself. The frustration expressed suggests this may require either changes to the test harness's shell usage patterns or platform-specific workarounds in the NonStop environment.
