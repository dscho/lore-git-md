This is a refinement to the ongoing SHA-1/SHA-256 interoperability work, specifically addressing memory allocation at the FFI boundary between C and Rust code.

Junio C Hamano notes that the current implementation uses plain `malloc()` for allocating hash contexts at the FFI boundary, which deviates from Git's customary use of `xmalloc()`. Brian M. The exchange highlights an important mindset shift - rather than thinking of separate "C parts" and "Rust parts", the system should treat allocations seamlessly across the boundary. This reflects the series' broader goal of tight C/Rust integration for the new object storage infrastructure.

This change (to be implemented in patch 9/14) resolves one of the open questions in the thread about FFI memory allocation strategy. The discussion shows good technical alignment between the maintainer and implementer on this detail of the Rust integration.
