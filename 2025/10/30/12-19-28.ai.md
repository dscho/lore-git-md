This is patch 9/13 in Patrick Steinhardt's series refactoring Git's loose object handling as part of the object database (ODB) abstraction effort. The patch moves responsibility for checking loose object existence from individual backend functions up to the ODB level, cleaning up the interface between layers.

The key change is restructuring `stat_loose_object()`, `open_loose_object()`, and `quick_has_loose()` to operate on a single `struct odb_loose_source` rather than iterating through all sources at the repository level. The iteration is now handled by callers like `do_oid_object_info_extended()` and `open_istream_loose()`, which better reflects the architectural separation between the ODB (which manages sources) and individual backends (which handle specific sources).

Karthik Nayak reviews the patch positively, noting how the simplified backend functions now only need to worry about their specific source rather than repository-wide iteration. The changes span `object-file.c`, `odb.c`, and `streaming.c`, with the bulk being mechanical conversions to the new interface. One remaining architectural wart noted is that `open_istream_loose()` still operates at the repository level, which Patrick acknowledges will be cleaned up later.

This continues the series' pattern of behavior-preserving refactoring while improving code organization for future pluggable backends. The review suggests no outstanding technical issues, just the ongoing naming discussion about `struct odb_loose_source` vs `struct obd_source_loose` from earlier in the thread.
