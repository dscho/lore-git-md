This is part 3 of an 8-part refactoring series for Git's packfile subsystem, focusing on updating the HTTP protocol code to use the new `packfile_list` API. The patch converts the HTTP subsystem (http-push.c, http-walker.c, http.c) from direct linked list manipulation to the structured `packfile_list` interface, preparing for the eventual removal of the `->next` pointer in `struct packed_git`.

Key changes include:
- Replaces direct `struct packed_git *packs` with `struct packfile_list packs` in repository/alt_base structs
- Introduces `packfile_list_find_oid()` helper in packfile.c to replace direct `find_oid_pack()` calls
- Updates all packfile list operations to use the new API (`prepend`, `remove`, `clear`)
- Adds temporary code duplication with both old and new find functions (to be resolved later)
- Simplifies initialization code using `CALLOC_ARRAY`

The changes maintain identical behavior while moving toward the series' goal of abstracting packfile storage. The HTTP protocol handling now uses the same list management infrastructure as other parts of Git, though the author notes this creates some temporary duplication that will be cleaned up in a follow-up patch. The changes are mechanical but thorough, touching all HTTP-related packfile operations.
