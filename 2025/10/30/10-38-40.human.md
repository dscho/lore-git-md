This is part 3/8 of a refactoring series preparing Git's packfile subsystem for store/source layer integration. The patch updates the HTTP protocol code to use the new `packfile_list` API instead of directly manipulating linked lists of `packed_git` structs.

The changes affect HTTP push/fetch operations where packfiles are temporarily stored before being added to the repository's packfile store. The patch introduces some temporary code duplication with both old and new lookup functions (`find_oid_pack` and `packfile_list_find_oid`), but this will be cleaned up in a later commit.

The refactoring touches several HTTP-related files (http-push.c, http-walker.c, http.c) and adds new packfile list operations to packfile.c. While this is primarily an internal change, it's a key step in the series' goal of removing direct `->next` pointer manipulation from `struct packed_git`.

The patch appears well-contained and follows the established pattern from earlier in the series. It maintains existing behavior while moving toward the new abstraction layer. Reviewers have already engaged with earlier parts of this series, and this patch had one question about API design that was resolved.
