This is a technical discussion about type choices in the SHA-1/SHA-256 interoperability work, specifically addressing the use of `uint32_t` versus `int` for hash algorithm representation at the C/Rust FFI boundary.

The email responds to Junio C Hamano's concern about inconsistent type choices between C and Rust code. Brian m. carlson argues for systematic use of fixed-width types (`uint32_t` etc.) in structure definitions and FFI boundaries, contrasting with more flexible types like `int` for purely internal C usage. The rationale includes:
- Fixed-width types provide well-defined sizes crucial for FFI safety
- Unsigned types better represent values that can't be negative (like algorithm constants)
- Historical issues with size assumptions (Windows limitations, 1GiB diff limit) motivate more precise typing
- Key technical points:
  - Maintains current 32-bit width for algorithm field (sufficient given practical limits)
  - Distinguishes between FFI/structural types (fixed-width) and internal C types (more flexible)
  - References related platform compatibility issues (Windows, large file handling)
