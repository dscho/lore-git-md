This is a bugfix patch in the packfile refactoring series, addressing an object counting issue in MIDX (multi-pack index) handling. The patch corrects two problems in `repo_approximate_object_count()`:

1. It properly accounts for objects in MIDX base layers by including `num_objects_in_base` in the count, fixing an undercount when using incremental MIDX chains.

2. It prevents double-counting objects by skipping packfiles that have an associated MIDX, which would otherwise cause overcounting.

The impact is limited to three non-critical areas: commit-graph progress display, hash abbreviation length calculation, and repack memory estimation. The patch also includes two cleanups: switching to `repo_for_each_pack()` for iteration and using `odb_prepare_alternates()` instead of direct packfile store preparation.

Taylor Blau provided helpful input on the fix, which has already been incorporated. The changes are minimal (4 lines modified) but correct subtle counting issues in the MIDX infrastructure. This patch is part of the larger packfile store abstraction effort and follows naturally from the earlier refactoring work in the series.
