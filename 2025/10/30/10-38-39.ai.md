This is part 2/8 of a refactoring series for Git's packfile subsystem, moving towards a packfile store abstraction. The patch relocates the Most-Recently-Used (MRU) packfile list from `struct packed_git` to a new `struct packfile_list` within `struct packfile_store`.

Key technical changes:
- Introduces `struct packfile_list` with head/tail pointers and `struct packfile_list_entry` nodes containing packfile pointers
- Implements core list operations: `clear`, `remove`, `prepend`, and `append`
- Updates MRU handling in packfile.c to use the new list structure instead of direct `list_head` manipulation
- Modifies pack-objects.c, midx.c, and other callers to use the new API
- Removes the `mru` field from `struct packed_git` since it's now managed externally

The change is part of a larger effort to prepare for pluggable object databases by breaking up global packfile lists into per-object-source lists. This intermediate step moves the MRU list into the packfile store while maintaining identical behavior. The patch follows the pattern established in part 1 (strmap conversion) by introducing a dedicated data structure for packfile list management.

The implementation appears thorough, with all necessary updates to callers and comprehensive list operations. The MRU ordering semantics are preserved exactly, just with the list management moved to the store level. This is a clean architectural change that moves towards the series' goal while being mechanically straightforward.
