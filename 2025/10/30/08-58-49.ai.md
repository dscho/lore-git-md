This is a follow-up discussion in the packfile store abstraction series, specifically addressing patch 7/8 which standardizes MRU list handling for packfiles. Patrick Steinhardt responds to Taylor Blau's observation about the current MRU behavior, clarifying that while `packfile_store_prepare_mru()` does add packs eagerly, there are several direct callers of `packfile_store_add_pack()` that don't update the MRU list.

The key technical points are:
- The original commit message was misleading about MRU behavior
- Three subsystems (index-pack, fast-import, and http) currently add packs without MRU updates
- Since these cases all involve expected object reads, Patrick agrees packs should be in MRU immediately
- Patrick will rewrite the commit message to better reflect the actual behavior being fixed

This exchange resolves Taylor's concern about the description while confirming the technical approach of the patch. The discussion reinforces that this change is about consistency rather than introducing new behavior, as the affected subsystems already expect to read from these packs. The patch remains part of the broader effort to unify packfile list management in preparation for per-source lists.
