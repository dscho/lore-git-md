Bugfix discussion for `git clean -X` pathspec handling with excluded directories.

Johannes Schindelin confirms the reported issue where `git clean -d -X` ignores pathspec exclusions when processing directories, reproducing it on both Windows and Linux. He notes the command's behavior is unclear when combining `-X` (clean ignored files) with explicit exclusions (`:(exclude)` patterns), presenting two possible understandings: either exclusions should filter the `-X` operation, or `-X` should override exclusions.

The core difficulty lies in `dir.c`'s complex exclusion logic, which has evolved organically and is hard to reason about. Schindelin defers to the Git maintainer to decide which interpretation should prevail but provides a regression test case demonstrating the issue: a `build/` directory with a `lib.so` file that should be preserved when excluded via `:(exclude)build` but currently isn't.

Key technical points:
- Test case uses `test_expect_failure` to document current broken behavior
- Demonstrates exclusion of `build/` directory while cleaning other ignored files
- Highlights architectural challenges in `dir.c`'s exclusion handling
- Windows/Linux cross-platform confirmation of the issue
- Alternative exclusion syntax `:(exclude)` shown as equivalent to `:!` but more readable

This moves the discussion forward by clearly framing the ambiguity in the spec while providing concrete test coverage for whichever resolution the maintainers choose. The test case will serve as a reference point for any future fixes to this directory traversal behavior.
