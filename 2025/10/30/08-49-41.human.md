This is a response to a bug report about `git clean -X` incorrectly handling pathspec exclusions with directories. Johannes Schindelin confirms the bug is reproducible on both Windows and Linux, noting the syntax `:(exclude)` is preferable to `:!` for clarity and shell compatibility.

The core issue lies in conflicting interpretations of how `-X` (clean only ignored files) should interact with pathspec exclusions. The reporter believes exclusions should override `-X`'s implicit additions, while the current implementation treats `-X` as overriding exclusions. Schindelin acknowledges the complexity of the underlying `dir.c` code and defers to the Git maintainer for a decision on the correct behavior.

As a starting point for resolution, Schindelin provides a regression test case demonstrating the problematic behavior, though marked as `test_expect_failure` since it currently doesn't pass. The test shows that `:(exclude)build` should prevent `git clean -d -X` from removing the `build` directory, but currently fails to do so. This response moves the discussion forward by clearly framing the design question while providing concrete test infrastructure for any future fix.
