This is a discussion about Rust version policy in the context of the cbindgen integration series. Brian M. Carlson responds to Patrick Steinhardt's position on maintaining Rust 1.49 as the minimum supported version (MSRV) for gcc-rs compatibility, arguing that this approach is fundamentally flawed for unsupported platforms.

The key technical point is that gcc-rs inherits Rust 1.49's standard library limitations, meaning it cannot support platforms that weren't available in that Rust version (analogous to using an outdated glibc). Carlson advocates instead for targeting Rust 1.63, framing this as part of a broader strategy to direct platform maintainers toward LLVM-based Rust toolchains rather than relying on gcc-rs.

This email represents a continuation of the version policy debate that has run through the thread, with Carlson now making a stronger technical case against the 1.49 target. The argument centers on platform support timelines and standard library compatibility rather than the build system or header generation concerns that dominate other parts of the series. Carlson indicates they will follow up with a concrete patch proposing the 1.63 target, which would represent a significant policy shift from the current CI-enforced version.
