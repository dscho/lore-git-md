Platform compatibility discussion about ksh behavior in Git tests.

Brian Carlson provides technical context about why ksh might be failing Git's test suite, particularly on NonStop systems. They explain that AT&T ksh (ksh93) is known to be incompatible with Git's test suite because it lacks the `local` keyword, which is used in functions like `test_subcommand`. Other ksh variants (pdksh, mksh, OpenBSD's ksh) generally work fine as they do support `local`. 

The email also notes additional potential incompatibilities, like ksh and zsh (in zsh mode) running the last pipeline command in the main shell rather than a subshell, which could cause test failures. Carlson clarifies that zsh in sh mode should mostly work, though zsh mode itself has never successfully run Git's test suite.

This is a follow-up to Randall Becker's earlier report about test failures on NonStop systems where `/bin/sh` is ksh. While Jeff King's `TEST_SHELL_PATH=/bin/bash` workaround addressed the immediate issue, this email provides deeper technical background about shell compatibility that may help diagnose other potential issues. The discussion remains focused on technical specifics rather than revisiting the earlier debate about release candidates.
