This is a discussion about Rust version compatibility in Git's ongoing Rust integration work, specifically regarding the cbindgen tool for Rust-C interop.

Patrick Steinhardt responds to concerns about cbindgen's Rust version requirements by clarifying Git's current stance. The project currently targets Rust 1.49, matching what gcc-rs uses, to maximize platform compatibility. However, Patrick notes this was never meant to be set in stone - if there are strong technical reasons to require a newer version (like cbindgen's 1.70+ requirement), the team should consciously decide to update rather than arbitrarily picking a version.

The thread reveals an important policy question that needs resolution: whether to maintain backward compatibility with older Rust versions (potentially limiting tool choices) or adopt newer versions that enable better tooling but may exclude some platforms. Patrick's position is pragmatic - he's open to updating the requirement if justified, but wants the decision to be intentional rather than accidental.

This discussion sits within the larger context of a patch series introducing cbindgen for automated header generation between Rust and C code. The version compatibility issue has emerged as a key consideration that could impact both development workflow and platform support.
