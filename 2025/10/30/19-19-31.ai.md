Feature implementation for `git replay` configuration. This final patch in the v6 series adds persistent configuration support via `replay.refAction`, completing the atomic reference update feature. The config option accepts "update" (default atomic behavior) and "print" (pipeline output mode), with command-line `--ref-action` taking precedence as per Git's standard configuration hierarchy.

The implementation introduces a new parse_ref_action_mode()` helper that validates both config and command-line values, providing consistent error messages. The config is read via `repo_config_get_string_tmp()` after option parsing but before execution. Tests verify config parsing, default behavior, command-line override precedence, and error handling for invalid values. The documentation in `replay.adoc` clearly explains the options and their relationship.

This patch addresses all prior feedback, including Christian Couder's suggestions for config parsing consistency and test hygiene. It follows Git's established patterns for config handling, matching behaviors seen in `builtin/am.c` and `builtin/column.c`. The implementation has been reviewed and approved by all key stakeholders (Junio Hamano, Elijah Newren, Phillip Wood, Patrick Steinhardt) with no outstanding technical concerns.
