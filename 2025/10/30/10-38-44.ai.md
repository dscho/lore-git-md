This is a refactoring patch in the packfile store abstraction series, specifically addressing MRU (Most Recently Used) list handling for packfiles. The patch ensures packfiles are always added to both the main packfile list and MRU list when loaded, eliminating a fragile workaround where some callers had to reprepare the entire object database to make newly added packs accessible.

The key technical change moves MRU list population from `prepare_midx_pack()` to `packfile_store_add_pack()`, making the MRU update unconditional when adding any pack. This fixes cases where packs added via fast-import, index-pack, or HTTP fetches could be missing from the MRU until a subsequent reprepare operation. The patch removes the explicit MRU addition in midx.c since it's now handled automatically.

The commit message thoroughly analyzes the problematic scenarios, showing how object lookup would eventually work (via repreparation) but at unnecessary cost. It identifies all external callers of `packfile_store_add_pack()` and confirms their behavior remains correct with the change. The diff itself is minimal - removing one MRU update in midx.c and adding another in packfile.c.

This patch follows up on earlier MRU standardization work in the series and precedes the final consolidation patch (8/8) that Patrick Steinhardt has flagged for extra review. The change simplifies the MRU maintenance model while making packfile access more reliable, though the commit notes the MRU sorting still requires `packfile_store_prepare_mru()` for deterministic ordering.
