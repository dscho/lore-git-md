This is a follow-up in the ongoing discussion about Git test failures on NonStop systems and release processes.

Randall Becker from NonStop platform explains why their CI/CD setup couldn't catch the shell compatibility issues before the v2.51.2 release. Their Jenkins-based testing takes over a day per run, leading to a 2-3 week backlog when testing each commit individually. They've settled for weekly testing instead, which missed the window before v2.51.2 was released. The specific test failures (related to ksh vs bash differences) were only caught at v2.52.2.

The email confirms that Jeff King's `TEST_SHELL_PATH=/bin/bash` workaround has NonStop now building and testing correctly. It also notes that v2.51.1 didn't exhibit these issues, suggesting the problem was introduced between those versions. The response provides useful context about the practical challenges of comprehensive platform testing, especially for less common platforms with slower test infrastructure.

This adds important operational details to the earlier technical discussion about shell compatibility, showing how even with good intentions, testing bottlenecks can prevent issues from being caught pre-release. The email doesn't propose new solutions but helps explain why the problems weren't detected earlier despite NonStop's testing setup.
