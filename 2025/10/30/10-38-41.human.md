This is a bugfix patch in the packfile store abstraction series, addressing an issue with object count approximation in repositories with multi-pack indexes (MIDX).

The patch fixes two problems in how Git estimates repository object counts when MIDX files are present: (1) it wasn't accounting for objects in parent layers of incremental MIDX chains, and (2) it was double-counting objects by including both MIDX and individual packfile counts. The fix adds `num_objects_in_base` to track parent layer objects and skips packfiles that have an associated MIDX.

The impact is limited to minor cases like commit-graph progress displays, hash abbreviation length, and repack memory estimates - none critical, but worth fixing for accuracy. The patch also modernizes the code by using `repo_for_each_pack()` and `odb_prepare_alternates()`.
