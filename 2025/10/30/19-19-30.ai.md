This is the second patch in a 3-part series implementing atomic reference updates for `git replay`. The patch changes the default behavior from outputting update commands to performing atomic ref updates directly, while preserving the old pipeline behavior via a new `--ref-action=print` option.

Key technical details:
- Introduces `enum ref_action_mode` with `REF_ACTION_UPDATE` (default) and `REF_ACTION_PRINT` values
- Implements atomic updates using Git's ref transaction API (`ref_store_transaction_begin()`, `ref_transaction_update()`, `ref_transaction_commit()`)
- Adds `handle_ref_update()` helper function to unify print/update modes
- Updates documentation to explain new default behavior and `--ref-action` option
- Modifies tests to use `--ref-action=print` where needed while adding new tests for atomic behavior
- Includes bare repository testing for server-side workflows
- Follows Git's standard patterns for option parsing and error handling

The implementation addresses all prior review concerns about atomicity guarantees and test hygiene. The patch is well-structured with clear commit message explaining the motivation (reducing process coordination overhead for server-side operations) and implementation approach.

This is a production-ready change that maintains backward compatibility while improving the default workflow. The next patch in the series will add the `replay.refAction` config option.
