This is the first patch in an 8-part refactoring series for Git's packfile subsystem, replacing a hashmap implementation with `strmap` for tracking packfiles by name. The change simplifies the code by eliminating a manual hashmap implementation (including its custom comparison function) in favor of Git's built-in string map type, reducing the line count by 18 lines while maintaining the same functionality.

Key technical changes:
- Replaces `struct hashmap map` with `struct strmap packs_by_path` in `struct packfile_store`
- Removes the `pack_map_entry_cmp` comparison function and `hashmap_entry` from `struct packed_git`
- Updates all packfile lookup and storage operations to use `strmap` APIs (`strmap_put`, `strmap_get`, `strmap_init`, `strmap_clear`)
- Maintains identical behavior for packfile loading and management

The patch appears well-contained and focused, touching only packfile.c/h while providing a straightforward modernization of the code. Taylor Blau has already reviewed this change positively in previous iterations of the series. This initial patch sets up the foundation for subsequent refactorings in the packfile store abstraction effort.
