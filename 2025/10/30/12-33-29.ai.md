This is a refactoring patch in the ongoing series combining code cleanups and translation work in gpg-interface components. It's the second patch in a 5-part v2 series (originally part of a 6-patch v1 series that was reorganized).

The patch standardizes how boolean flags are defined in gpg-interface.h, changing from direct numeric values (1, 2, 4) to the more conventional bitwise left shift pattern (1<<0, 1<<1, 1<<2). This makes it clearer that these are bit flags meant to be combined, while maintaining identical runtime behavior. The change affects three verification flags: GPG_VERIFY_VERBOSE, GPG_VERIFY_RAW, and GPG_VERIFY_OMIT_STATUS. The patch also fixes a minor indentation issue with the OMIT_STATUS definition.

This is a mechanical change that follows Git's established conventions for flag definitions, as noted in the thread context. The patch builds on prior cleanup efforts in the gpg-interface code and aligns with the series' broader goals of code consistency. Since this is a straightforward refactoring with no behavior change and the pattern matches Git's standard practices, it's unlikely to be controversial. The thread context indicates Junio C Hamano had already approved similar changes in v1 of the series.
