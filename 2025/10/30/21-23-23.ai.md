Platform compatibility analysis focusing on shell behavior differences between bash and ksh implementations.

Brian Carlson provides technical context about known shell compatibility issues affecting Git's test suite, specifically regarding the NonStop` test failures reported by Randall Becker. The email clarifies that AT&T ksh (ksh93) is known to fail with Git tests because it lacks the `local` keyword used in test helper functions like `test_subcommand`. Other ksh variants (pdksh, mksh, OpenBSD's ksh) generally work as they support `local`. 

The analysis also notes pipeline execution differences - ksh implementations and zsh in native mode run the last pipeline command in the main shell rather than a subshell, which could cause additional incompatibilities. While zsh in sh-emulation mode mostly works with Git's tests, zsh mode has never successfully passed the full test suite.

This email provides important background for understanding why the `TEST_SHELL_PATH=/bin/bash` workaround was necessary for NonStop systems, while also documenting broader shell compatibility constraints that may affect future test development. The technical details about shell behavior differences (local variable support and pipeline execution) are particularly relevant for anyone working on test infrastructure or investigating similar failures on other platforms.
