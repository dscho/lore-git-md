Platform compatibility issue with test execution on NonStop systems. Randall Becker identifies the root cause of test failures in t7900 when using `test_subcommand !` assertions - the tests are being run with ksh rather than bash due to how the Make environment handles shell selection. 

The issue stems from Make 4.1.2 only applying the SHELL=/bin/bash setting to outer command processing, while the test scripts' #!/bin/sh shebang causes them to run under ksh on NonStop systems. This explains the unusual trace output and test failures seen earlier. Randall confirms the tests pass when manually run with bash, but notes this creates significant manual overhead for their CI/CD pipeline.

This appears to be a platform-specific interaction between Make and shell selection rather than a Git bug per se, though it does impact test reliability on NonStop. The discovery helps explain the earlier instrumentation discrepancies SZEDER Gábor observed, though it doesn't yet suggest a clear solution beyond manual workarounds.
