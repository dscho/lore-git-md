Refactoring patch in the packfile subsystem series, addressing caching logic in pack-objects.

This is a follow-up discussion on patch 5/8 of Patrick Steinhardt's series refactoring Git's packfile management. The patch simplifies the caching logic in `has_sha1_pack_kept_or_nonlocal()` which checks for objects in kept or non-local packs. 

Toon Claes questions the caching mechanism's effectiveness, noting it maintains a global "last_found" pack without control over the object IDs being checked. Patrick acknowledges this is likely a micro-optimization but chose to focus on making the existing logic more maintainable rather than questioning its purpose. The discussion confirms the earlier decision to remove an unnecessary `(void *)1` sentinel check while keeping the core caching behavior.

This exchange shows the series is now in the fine-tuning phase, with reviewers examining implementation details while the core refactoring approach has been accepted. The patch remains part of the broader effort to modernize packfile handling in preparation for future per-source list changes.
