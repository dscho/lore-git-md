This is a cover letter for an 8-part refactoring series in the packfile subsystem, part of the ongoing packfile store abstraction effort. The series moves packfile list management into the packfile store structure, eliminating global linked lists in preparation for deeper integration with object sources.

Key technical aspects:
- Replaces `struct packed_git::next` with `struct packfile_list` API
- Merges MRU and mtime-sorted packfile lists into single MRU list
- Introduces `skip_mru_updates` flag to prevent infinite loops during iteration
- Fixes MIDX object count approximation by properly handling `num_objects_in_base`
- Optimizes `has_sha1_pack_kept_or_nonlocal()` with Toon Claes' `last_found` cache check
- Replaces `(void *)1` sentinel with NULL pointer in pack-objects caching
- Standardizes MRU list additions to occur immediately when packs are loaded

The series affects core packfile handling in:
- packfile.c/h (primary changes)
- midx.c (object count fix)
- builtin/pack-objects.c (optimized caching)
- HTTP protocol files (API updates)

The cover letter highlights one area needing extra review - the final patch's merge of two packfile lists into a single MRU list with loop prevention via `skip_mru_updates`. Patrick Steinhardt expresses some concern about this approach's fragility while acknowledging it simplifies the overall design.

This v2 incorporates all prior review feedback including:
- Typo fixes
- MIDX object count optimization
- Further `has_sha1_pack_kept_or_nonlocal()` simplifications
- Clearer MRU list addition rationale
- Implementation of Toon Claes' cache optimization suggestion

The series appears ready for inclusion, having addressed all technical feedback while maintaining the original goal of preparing the packfile subsystem for deeper object source integration. The MRU list consolidation in patch 8 remains the most architecturally significant change warranting close review.
