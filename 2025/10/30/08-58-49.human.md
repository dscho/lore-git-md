This is a follow-up discussion in the packfile store refactoring series, specifically addressing patch 7/8 which standardizes MRU (most-recently-used) list handling for packfiles. Patrick Steinhardt responds to Taylor Blau's observation about the current behavior of MRU list additions.

The key clarification is that while `packfile_store_prepare_mru()` does add all known packs to the MRU list eagerly, there are several code paths (in index-pack, fast-import, and HTTP handling) that call `packfile_store_add_pack()` directly and currently don't add to the MRU list. Patrick agrees this inconsistency should be fixed and will update the commit message to better reflect the actual situation.

The discussion reveals an implementation detail: packs are currently added to the MRU list in two different ways - either eagerly during preparation or lazily during object access. The patch aims to standardize this by always adding packs to the MRU when they're first added to the store, which makes sense for the affected subsystems since they'll likely access the pack's objects soon anyway.

This is a minor refinement to the larger packfile store abstraction work, showing the careful attention to detail in this series. The exchange demonstrates how reviewer feedback helps improve both the code and its documentation.
