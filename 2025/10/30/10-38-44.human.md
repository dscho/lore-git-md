This is a refactoring patch in the ongoing packfile store abstraction series, specifically addressing MRU (most recently used) packfile list handling. 

The patch fixes a subtle issue where some code paths add packfiles to the store without properly adding them to the MRU list. While the current behavior works (falling back to reprepare the entire object database when needed), Patrick identifies this as fragile and inefficient. The solution is to always add packfiles to both the main list and MRU list when they're loaded.

Key changes:
1. Removes the explicit MRU addition from MIDX pack preparation (midx.c)
2. Makes packfile_store_add_pack() unconditionally add to both lists (packfile.c)

The patch is well-motivated, showing how the current behavior could lead to subtle bugs if other MRU-using code paths don't properly reprepare. It's a focused change that simplifies the logic while maintaining the same functionality. This continues the series' trend of cleaning up packfile handling, though as noted in the thread summary, there are still some concerns about the MRU consolidation's fragility that may need review attention.
