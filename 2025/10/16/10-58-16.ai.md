This is a review comment on the reference counting implementation in the `git repo structure` series. Patrick Steinhardt suggests optimizing the reference counting approach in patch 4/7 to avoid unnecessary memory usage and improve progress reporting.

The current implementation in `structure_count_references()` collects all refs into a `ref_array` before counting them by type (branches, remotes, tags, others). Patrick points out this is inefficient for large repositories since it requires storing all refs temporarily. He proposes using `refs_for_each_ref()` with a callback to count refs directly during enumeration, which would:
- Eliminate the temporary ref storage
- Make progress reporting more meaningful by showing counting progress during the actual enumeration phase rather than just during classification
- Accept the tradeoff of not having an exact reference count for progress percentage calculation

The suggestion specifically addresses the interaction with the progress meter being added in patch 7/7, noting the current approach would show most activity during the fast classification phase rather than the slower enumeration phase. Patrick confirms the other patches in the series look good aside from this optimization opportunity.

This feedback focuses on performance implications of the reference counting implementation while maintaining all existing functionality. The change would affect `structure_count_references()` in builtin/repo.c and its interaction with the ref-filter API, but wouldn't require modifications to the stats table formatting or output generation logic.
