This is a follow-up in the ongoing discussion about the future of `git whatchanged`. Kristoffer Haugsbakk provides a technical clarification in response to Julian Squires' comment about potentially creating an alias if the command were removed.

The email notes that while `git whatchanged` can indeed be replaced with `git log --raw --no-merges`, there's a version-specific caveat: users can only alias builtin commands starting from Git 2.51.1 (and the upcoming 2.52.0), but not in 2.51.0. This suggests that users on older versions would need to upgrade before being able to create such an alias.

The response is brief and technical, focusing solely on the version compatibility aspect of command aliasing. It doesn't take a position on whether `git whatchanged` should be deprecated, but provides practical information for users who might want to prepare for that possibility. The tone suggests this is a response to a specific request for information rather than an attempt to steer the broader discussion.
