Refactoring patch as part of a series introducing geometric maintenance strategy.

This is the first of eight patches proposing a new "geometric" maintenance strategy for Git, particularly aimed at improving performance in monorepos. The patch removes a global `repack` variable in `builtin/gc.c` that was used to accumulate arguments for `git-repack`, replacing it with a stack-based approach that passes the strvec around explicitly. 

The change makes the code more maintainable by eliminating hidden state and better supporting reuse of the repack argument-building logic. The author notes the trickiest part was handling the `need_to_gc()` function, which is used by both `git gc --auto` and `git maintenance run --auto`. The solution uses a temporary variable for maintenance runs since the arguments will be recomputed anyway when spawning the child process.

This is a clean, focused refactoring that lays groundwork for the geometric repacking functionality to come in later patches. The change appears well-reasoned and maintains all existing behavior while improving code structure. The patch follows Git's style well and includes updates to all affected call sites.
