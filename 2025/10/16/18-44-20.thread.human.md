This thread addresses a bug in Git's signature verification code where the `remove_cr_after()` function was incorrectly stripping all carriage return (CR) characters from signature data, potentially corrupting binary payloads or text containing legitimate standalone CRs (such as from older systems). The fix, from contributor brian m. carlson, renames the function to `trim_cr_before_lf()` and modifies its behavior to only remove CR characters when they immediately precede a line feed (LF), thus preserving valid standalone CRs while still properly handling Windows-style CRLF line endings. The change affects both GPG and SSH signature processing paths and includes updates to their documentation. The patch appears well-justified, addressing a prior NEEDSWORK comment in the code, with a clear commit message explaining the issue and solution. The function rename better reflects its refined behavior. This is a focused, technical correction with platform compatibility implications, particularly for non-Windows systems where standalone CR characters might legitimately appear in signature data.
