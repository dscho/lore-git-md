This is a follow-up in the ongoing discussion about potentially breaking changes to Git's diff syntax, specifically regarding the `X..Y` and `X...Y` notations. Martin von Zweigbergk responds to Kristoffer Haugsbakk's observation that `git checkout X...` works in some cases, clarifying that his earlier test failure was due to testing with ambiguous merge bases rather than a syntax issue.

The email reveals an important nuance: while the triple-dot syntax works in unambiguous cases, it fails with confusing error messages when merge bases are ambiguous. This technical detail adds complexity to the proposal to remove these notations, as it shows the current behavior isn't consistently intuitive even within Git's own commands.

Martin acknowledges Junio Hamano's point that any syntax changes would need to be coordinated across all commands using these notations (like `git checkout`), not just `git diff`. The discussion continues to balance the desire for clearer syntax against backward compatibility and cross-command consistency.
