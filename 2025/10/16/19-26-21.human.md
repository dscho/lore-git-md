Security feature discussion regarding temporary bypass mechanism for Git repository safety checks.

This is part of the ongoing security-focused patch series (v3 4/5) that aims to prevent arbitrary code execution via Git hooks in untrusted repositories. The current discussion focuses on whether to include a temporary bypass mechanism (`--allow-unsafe` flag and `GIT_ALLOW_UNSAFE` environment variable) for the repository safety checks.

Junio Hamano questions the justification for these new features, arguing that existing mechanisms (using `GIT_DIR` environment variable) already provide a way to temporarily work with untrusted repositories without modifying configuration files. He specifically objects to the environment variable approach, noting it has the same persistent vulnerability risk as temporary config changes if forgotten.

The core disagreement centers on whether the proposed bypass methods offer sufficient advantage over existing techniques to justify their inclusion. While Hamano concedes the command-line flag might be marginally more convenient, he remains unconvinced about its necessity and strongly opposes the environment variable approach. The discussion appears to be at an impasse regarding whether these features should be included in their current form.
