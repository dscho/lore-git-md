This is a feature patch series introducing a new "geometric" maintenance strategy for Git repositories, particularly targeting monorepo use cases. The series comes from Patrick Steinhardt and consists of 8 patches building on recent Git development.

The core problem being addressed is that Git's current maintenance strategies don't work well for large repositories. The default `git gc` does full repacks too aggressively for monorepos, while the existing "incremental" strategy doesn't prune old data and only works for scheduled maintenance, not manual runs.

The series introduces a new geometric repacking strategy that:
1. Uses Git's geometric repacking by default to maintain pack structure efficiently
2. Falls back to cruft packs when geometric repacking would collapse everything
3. Makes strategies apply to both scheduled and manual maintenance runs
4. Maintains backward compatibility with existing "incremental" strategy behavior

The changes touch core maintenance code in `builtin/gc.c`, add new config options documented in `maintenance.adoc`, and include extensive new tests in `t7900-maintenance.sh`. The implementation appears thorough, with careful attention to backward compatibility and clear separation of concerns in the refactoring steps.

This looks like a well-motivated improvement to Git's maintenance infrastructure, particularly valuable for large repository maintainers. The series is structured logically with preparatory refactors before introducing new functionality, and includes comprehensive test coverage.
