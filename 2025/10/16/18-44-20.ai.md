Bugfix targeting GPG/SSH signature handling, with platform compatibility implications.

The patch addresses an issue in Git's signature verification code where the `remove_cr_after()` function was indiscriminately stripping all carriage return (CR) characters from signature data, even when they weren't part of Windows-style CRLF line endings. This could corrupt binary payloads or text containing standalone CR characters from older systems.

The solution modifies the function (now called `trim_cr_before_lf()`) to only remove CR characters when they immediately precede a line feed (LF), preserving legitimate standalone CRs while still handling Windows line endings correctly. The change affects both GPG and SSH signature processing paths, with corresponding updates to their respective documentation comments.

The patch appears well-motivated, addressing a clear NEEDSWORK comment in the original code. The implementation is straightforward, changing the CR-stripping logic while maintaining the same interface. The commit message clearly explains both the problem and solution, though it might benefit from a real-world example of where the current behavior causes issues. The rename from `remove_cr_after` to `trim_cr_before_lf` better reflects the function's refined behavior.
