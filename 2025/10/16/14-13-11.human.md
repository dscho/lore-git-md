This is a documentation patch refining warnings about the problematic `--committer-date-is-author-date` option in `git-am` and `git-rebase`. The author Kristoffer Haugsbakk responds to Johannes Sixt's feedback on how to structure the warning messages in the man pages.

The discussion has clarified that while the option was originally added for a specific `git-am` use case (preserving commit IDs when emailing patches), it's now considered a misguided solution that can violate Git's timestamp ordering assumptions. The patch will be updated to use stronger "WARNING" language instead of "NOTE" and will explicitly advise against using the option.

There's some back-and-forth about the exact placement of the warning - whether it should come before the technical description (Johannes' preference) or after, and whether to include a blunt "Do not use this option" directive. The author is receptive to these suggestions and is working on a v2 patch that will incorporate both the stronger warning language and improved documentation structure.

This continues the thread's consensus to:
1) Keep the option for `git-am` but with clear warnings about its risks
2) Deprecate it for `git-rebase` due to timestamp ordering issues
3) Make the documentation more forceful in discouraging use of this option

The patch appears well-considered, with the author thoughtfully working through the documentation presentation details based on maintainer feedback.
