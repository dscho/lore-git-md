This is a refactoring patch in the ongoing maintenance strategy series, specifically addressing the `too_many_loose_objects()` function in builtin/gc.c. The patch simplifies the function's interface by having it accept just the loose object threshold parameter directly, rather than requiring the full `gc_config` struct. This change maintains the existing behavior while making the function more reusable for future callers that may want to use different threshold values.

The modification is straightforward - the function signature changes to take a simple integer parameter, and all internal logic remains the same except for accessing the threshold value directly rather than through the config struct. Junio C Hamano has reviewed the change and confirms it is "trivially correct and makes perfect sense," indicating this is a clean, uncontroversial refactoring.

This change serves as preparation for subsequent patches in the series that will introduce new maintenance strategies and need to check loose object counts with different thresholds. The patch demonstrates good forward-thinking design by making the utility function more flexible without adding complexity. As part of the larger maintenance strategy overhaul, this small but meaningful refactoring helps enable the more sophisticated geometric repacking functionality coming later in the series.
