This is a refactoring patch from an Outreachy participant, converting string splitting in GPG signature verification code from `strbuf_split_max()` to `string_list_split()`. It's the first of two patches in v2 of this series.

The change focuses on `get_ssh_key_fingerprint()` in `gpg-interface.c`, where SSH key output is parsed. The patch notes that since the split strings are only read (not modified), `string_list_split()` is more appropriate than the `strbuf`-based alternative. The conversion requires adjusting the split count parameter since the two functions interpret this number differently (number of splits vs number of tokens).

The v2 changes show attention to detail - the commit message was clarified, function names were properly parenthesized, and the test was updated to explicitly verify the expected token count. The security-sensitive nature of this code (handling cryptographic fingerprints) makes the behavior-preserving nature of this refactoring particularly important. The patch appears well-considered and follows an established refactoring pattern previously used by Junio Hamano.
