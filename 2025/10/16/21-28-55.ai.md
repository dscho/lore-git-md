Feature proposal discussion regarding Message-ID tracking in Git commits, specifically addressing header storage concerns.

Kristoffer Haugsbakk chimes into the ongoing discussion about storing Message-IDs in commit headers, responding to Junio Hamano's concerns about preserving mailing list archive links. The brief exchange highlights a key technical tension: while James Bottomley's proposal intentionally drops Message-IDs during format-patch operations to comply with RFC uniqueness requirements, Hamano argues this breaks the ability to trace commits back to their original mailing list discussions.

Haugsbakk's short but pointed response suggests an alternative approach - the `X-Git-Original-Message-ID` header - as a potential way to preserve archive provenance while still meeting RFC requirements. This builds on Hamano's concern that the current proposal's header storage approach would make it impossible to maintain links between forwarded patches and their original mailing list archives.

The discussion remains focused on the core tradeoff between kernel workflow needs (where trailers are often rejected) versus general Git workflow robustness and archive traceability. No new implementation details are proposed, but Haugsbakk's suggestion introduces a new technical direction that might satisfy both the RFC compliance requirement and archive linking needs. The thread continues to grapple with how to make Message-ID tracking work reliably across Git's various history manipulation operations while preserving valuable metadata links.
