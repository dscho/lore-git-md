Performance optimization for `git last-modified` command.

This patch significantly improves the performance of `git last-modified` by implementing a new algorithm that avoids unnecessary history traversal. The current implementation does a full revision walk and inspects diffs at each level, which can be slow when dealing with paths that haven't been modified in a long time.

The new approach uses a priority queue of commits sorted by generation number and propagates "active" paths (those not yet associated with a commit) up to parents, performing a truncated revision walk. It also leverages Bloom filters to avoid computing unnecessary diffs. Benchmark results show a 2.6x speedup on git.git, with even greater improvements (5.3x) for paths with very old modifications.

The patch also fixes a correctness issue where the old implementation could sometimes return different results than `git log --max-count=1`. The new implementation consistently matches `git log`'s output, though the order of results may differ (which isn't guaranteed anyway).

The implementation is based on earlier work by Taylor Blau and GitHub, but has been substantially reworked to be more efficient and correct. Changes include using Git's built-in bitmap implementation, removing global variables, and improving the algorithm's clarity.
