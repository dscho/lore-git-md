Junio Hamano provides feedback on Michael Lohmann's v3 patch series about repository safety controls. He notes that the commit message's description of safe repository conditions is incomplete - while it mentions `safe.directory` config and user ownership, there are other cases where Git considers repositories safe (like explicitly specified git directories) that don't go through the `ensure_valid_ownership()` check. Hamano suggests expanding the commit message to document these additional cases if the patch gets rerolled.

The feedback comes as part of final discussions on this nearly-ready security series, which introduces both temporary bypass (`--allow-unsafe`) and persistent safety controls (`--assume-unsafe`, `GIT_ASSUME_UNSAFE`, `safe.assumeUnsafe`) to prevent malicious hook execution. The series has already addressed previous feedback and appears technically sound, with this being a minor documentation clarification rather than a functional issue.

This email doesn't introduce new technical concerns but helps ensure the commit message accurately reflects all cases where Git considers repositories safe, which is important for both future maintenance and user understanding of the security model. The patch series remains in good shape with just this documentation clarification and the two previously noted open questions about environment variable implementation.
