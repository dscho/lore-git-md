Security patch series discussion regarding repository safety mechanisms.

Junio Hamano provides final review feedback on the v3 security patch series that introduces mechanisms to prevent arbitrary hook execution in untrusted repositories. The series adds both temporary bypass (`--allow-unsafe`) and persistent safety controls (`--assume-unsafe`, `safe.assumeUnsafe` config).

Hamano notes the commit message's description of safe repository conditions is incomplete - it should also mention cases where `ensure_valid_ownership()` (now renamed to `ensure_safe_repository()`) isn't called, such as when a git directory is explicitly specified. This suggests the safety model documentation needs to account for all code paths in `setup.c` that bypass the ownership check.

This feedback comes as the series nears completion, with only two open questions remaining from previous discussion: whether to keep the `GIT_ALLOW_UNSAFE` environment variable and how to best integrate the `GIT_ASSUME_UNSAFE` check. Hamano's comment here focuses on ensuring the conceptual model is complete before finalizing the implementation.

The patch being discussed (5/5) implements the persistent safety controls that let users declare repositories as unsafe by default. The feedback suggests expanding the commit message's description of safety conditions to cover all relevant `setup.c` scenarios, not just those handled by the renamed function. This would help users understand the complete safety model when using the new `--assume-unsafe` option and related configurations.
