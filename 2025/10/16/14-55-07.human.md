Bugfix follow-up for content-ignoring diff options. Johannes Schindelin relays a GitHub bug report about garbled output when combining `--patch --raw` with `--ignore-space-change`. The issue occurs because `diff_flush_patch_quietly()` outputs patch format even when only raw format was requested, corrupting the output stream.

The thread shows Lidong Yan (brandb97) has already proposed a fix that adds a `dry_run` check to skip symbol emission and modifies external diff handling to respect `dry_run`. A third-party tester (fcharlie) is verifying the solution, prompting Johannes to delay the Git for Windows 2.51.1 release pending test results.

This appears to be a last-minute catch of an edge case in the otherwise well-vetted v5 patch series that addressed content-ignoring diff behavior. The fix is narrowly targeted and maintains the core architecture while preventing malformed output. The temporary release hold suggests the maintainers consider this serious enough to warrant verification before shipping.
