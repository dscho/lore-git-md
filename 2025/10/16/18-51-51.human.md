Performance optimization for `git last-modified` command. Justin Tobler provides a code review of Toon Claes's patch that improves the algorithm for finding the most recent commit modifying each path. The new approach uses a priority queue and path activity tracking to avoid unnecessary history walking, particularly for rarely-modified paths.

Tobler's review focuses on understanding the implementation details, raising several technical questions about the design choices. He asks about the need for per-commit bitmaps, the purpose of the `PARENT1`/`PARENT2` flag names, and why certain data structures are initialized where they are. The review is thorough but notes that the patch currently causes test failures (segfaults) when applied locally.

The patch builds on prior work by Taylor Blau and represents a significant performance improvement (2.6-5.3x faster) while also fixing correctness issues where the old implementation could differ from `git log` results. Tobler's questions suggest the implementation could benefit from more explanatory comments about some of the design decisions, though the core algorithm appears sound.
