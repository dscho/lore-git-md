This is a clarification in the ongoing Message-ID tracking feature discussion. Kristoffer Haugsbakk responds to James Bottomley's explanation about how the proposed Message-ID header functionality differs from Change-ID systems.

The email reinforces the distinction between the two approaches: Message-ID tracking (as proposed in this series) specifically serves email-based automation needs like kernel tip bots, while Change-ID systems track changes across commits in Git-native workflows. Haugsbakk agrees they are not the same concept but notes they share the technical approach of using commit headers for implementation.

The exchange helps solidify the series' scope by clearly differentiating it from prior Change-ID work, which had been referenced for historical context. This positions the current proposal as complementary rather than competing with existing commit tracking solutions, addressing distinct email workflow automation requirements. The technical implementation remains focused on mailinfo.c modifications and commit header storage as outlined in the original series.
