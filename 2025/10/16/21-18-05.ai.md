This is a continuation of the discussion about Message-ID tracking in Git commits, specifically addressing concerns about header storage versus trailers. Junio Hamano responds to James Bottomley's explanation about Message-ID handling during format-patch operations.

The key new point is that Hamano strongly objects to storing Message-IDs in commit headers or allowing `-m` to overwrite existing trailers, as this would break the ability to trace a patch's origin through mailing list archives. His scenario involves forwarding a previously received patch - he wants the Message-ID preserved so recipients can find the original discussion, which would be lost if format-patch drops the ID or if it gets overwritten during rebasing.

This reinforces Hamano's earlier concerns about header storage being problematic for history operations, but now adds the specific workflow case where maintaining provenance through mailing list archives is important. The discussion continues to center on the fundamental tension between kernel workflow needs (where trailers often get rejected) versus maintaining robust history operations and provenance tracking.
