Refactoring patch in a security-focused series to prevent arbitrary hook execution. This is the first of five patches in v3 of Michael Lohmann's series addressing repository safety.

The patch renames `ensure_valid_ownership()` to `ensure_safe_repository()` to better reflect its expanded role. While the function originally checked repository ownership, it now also handles `safe.directory` configuration checks and will need to accommodate future safety validations. The new name more accurately describes the function's purpose of verifying a repository meets all safety criteria before operations proceed.

This is a straightforward preparatory change that doesn't modify behavior - it updates the function name and its call sites throughout `setup.c`. The patch appears clean with no obvious issues, and the commit message clearly explains the rationale for the rename. As the first patch in the series, it sets up clearer terminology for the security enhancements that follow.
