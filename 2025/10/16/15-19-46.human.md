Documentation refinement for Git data model explanation (v3 follow-up)

Julia Evans responds to Junio Hamano's detailed review of her v3 patch introducing `gitdatamodel.adoc`, addressing several technical precision and clarity points in the proposed documentation. The changes focus on making the data model description more accurate while maintaining accessibility for new learners.

Key adjustments include:
- Clarifying that commits store "the contents of all files" rather than "all files" to better convey snapshot semantics
- Removing a cherry-pick-specific example about author/committer fields in favor of letting the field separation speak for itself
- Changing "Git supports these file modes" to "uses these file modes" to better reflect Git's role in recording rather than enforcing modes
- Simplifying the reflog entry description to focus on user-visible information rather than internal storage details
- Considering alternative phrasing for index/staging area explanations to avoid implying it tracks all repository files

The response shows thoughtful engagement with technical feedback while maintaining the document's pedagogical goals. Evans demonstrates willingness to adjust phrasing for precision but also pushes back gently where she believes the current wording serves learners well (like the "name for a commit ID" phrasing that test readers found clear). The exchange highlights the careful balance required in foundational documentation between technical accuracy and newcomer comprehension.
