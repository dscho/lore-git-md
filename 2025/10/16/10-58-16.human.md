This is a review comment on the reference counting implementation in the `git repo structure` series. Patrick Steinhardt points out a memory efficiency issue in how references are currently counted - the code first collects all refs into an array before counting them, which wastes memory and makes progress reporting less useful since the slow part (enumeration) happens before the progress meter starts.

He suggests using `refs_for_each_ref()` with a callback to count references incrementally instead. This would:
1. Eliminate the temporary array storage
2. Make progress reporting more meaningful by showing progress during the actual enumeration
3. Only require giving up the ability to show percentage completion (since total ref count wouldn't be known in advance)

The change would affect patch 4/7 (reference counting) and patch 7/7 (progress reporting) in the series. Patrick indicates the rest of the patches look good. This is a focused technical suggestion that would improve both performance and UX of the new `git repo structure` command.
