Refactoring patch in a series converting string splitting in GPG verification code from `strbuf_split_max()` to `string_list_split()`. This first patch focuses on the SSH key fingerprint parsing in `gpg-interface.c`.

The change modifies `get_ssh_key_fingerprint()` to use `string_list_split()` instead of `strbuf_split_max()` when processing the output of `ssh-keygen`. The commit explains this is appropriate because the split strings are only read (not modified) before being returned as plain C strings. The patch includes a subtle but important adjustment to the split count parameter - where `strbuf_split_max()` took the number of desired tokens (3), `string_list_split()` takes the number of splits to perform (2) to achieve the same 3-token result.

Security implications are present but handled carefully - the code verifies the split produces exactly 3 tokens before proceeding, maintaining the same validation as the original.
