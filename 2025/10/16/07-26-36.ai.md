This is a refactoring patch in the geometric maintenance strategy series, introducing infrastructure to distinguish between manual and scheduled maintenance runs. The patch doesn't yet change behavior but prepares for upcoming changes where different maintenance strategies will be used in different contexts.

The key technical changes:
- Introduces a new `enum maintenance_type` with flags for `MAINTENANCE_TYPE_SCHEDULED` and `MAINTENANCE_TYPE_MANUAL`
- Converts the `enabled` field in `maintenance_strategy` to a `type` bitfield
- Updates strategy definitions to specify which type(s) they apply to (default strategy for manual runs, incremental for scheduled)
- Modifies task initialization to check the type match before running tasks

The patch maintains the current behavior where:
- Default strategy (`gc`) only runs for manual maintenance
- Incremental strategy tasks (commit-graph, prefetch, etc.) only for scheduled maintenance

This is groundwork for later patches that will make the new geometric strategy available in both contexts. The changes are mechanical refactoring with no functional changes yet, keeping the same test coverage while enabling future flexibility in strategy selection. The implementation appears clean and well-contained within builtin/gc.c.
