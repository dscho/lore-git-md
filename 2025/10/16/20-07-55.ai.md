This is a refactoring patch in the ongoing maintenance strategy series, specifically addressing the global `repack` variable in builtin/gc.c. The patch was originally submitted by Patrick Steinhardt and is now being reviewed by Justin Tobler.

The change removes the global `repack` strvec variable, replacing it with stack-allocated variables passed between functions. This improves code clarity and reusability while maintaining the same behavior. The key technical aspects are:

1. The `need_to_gc()` function now takes a pointer to a strvec for repack arguments rather than using the global variable
2. A new `gc_condition()` wrapper function handles the case for maintenance runs where the repack arguments can be discarded after checking the GC condition
3. The maintenance task configuration is updated to use this new wrapper

Justin's review confirms the approach is sound, noting that the temporary repack arguments in the maintenance case can safely be discarded since they'll be recomputed by the child git-gc process anyway. The patch maintains existing functionality while making the code more modular for future changes in the series.
