This is a performance optimization patch for the `git last-modified` command, which determines the most recent commit that modified each specified path. The current implementation can be slow when dealing with paths that haven't been modified in a long time, as it must walk through much history to find their last modification.

The patch introduces a new algorithm that:
1. Uses a priority queue of commits sorted by generation number
2. Tracks "active" paths (those not yet associated with a commit) using bitmaps
3. Only computes diffs for active paths, avoiding unnecessary work
4. Leverages Bloom filters to skip first-parent diffs when possible

Key technical details:
- Adds `PARENT1` and `PARENT2` object flags (reusing flag space from `object.h`)
- Introduces commit slab for storing per-commit path activity bitmaps
- Uses EWAH bitmaps from "ewah/ewok.h" for efficient path tracking
- Modifies the diff processing to only examine active paths

Performance improvements are significant:
- 2.6x faster on git.git repository
- 5.3x faster for extreme cases like `git last-modified -- COPYING t`

The patch also fixes correctness issues where the old implementation could return incorrect results compared to `git log --max-count=1`. The new implementation matches `git log` output exactly, though the order of results may differ (which is not documented as guaranteed).

The changes build on earlier work by Taylor Blau and GitHub, but have been substantially reworked by Toon Claes to be more efficient and correct while avoiding global variables and improving code clarity.
