Security feature adding temporary bypass for repository safety checks. This is patch 4/5 in Michael Lohmann's series hardening Git against malicious hooks in untrusted repositories.

The patch introduces a new `--allow-unsafe` flag and `GIT_ALLOW_UNSAFE` environment variable that temporarily bypass the `ensure_safe_repository()` checks. This provides a safer alternative to permanently marking a directory as safe via `safe.directory` when users need to run a one-off command in an untrusted context. The implementation adds the new option to `git.c`, documents it in `git.adoc`, and includes comprehensive tests in a new `t0036-allow-unsafe-directory.sh` file.

Key technical details:
- The bypass is implemented by checking `GIT_ALLOW_UNSAFE` in `setup.c`'s `ensure_safe_repository()` before other safety checks
- Error messages are updated to mention the new bypass option alongside the existing `safe.directory` instructions
- Tests verify both the command-line flag and environment variable work as expected
- The change builds on the renamed functions from earlier patches in the series (`ensure_safe_repository()` and `die_upon_unsafe_repo()`)
- Documentation clearly warns about the security implications of bypassing these checks

The patch appears well-structured with thorough test coverage and clear commit message explaining the motivation. It fits logically into the series' progression from refactoring to new functionality. The implementation addresses the security use case while maintaining the default safety checks as the strongly recommended path.
