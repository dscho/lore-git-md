This is a follow-up discussion in the performance optimization thread for `git last-modified`, focusing on correctness of the results. D. Ben Knoble questions Toon Claes' claim that the new implementation gives "more correct" results, pointing out that correctness should be binary. The example shows a discrepancy between `git log --max-count=1` and `git last-modified` outputs for `pkt-line.h`, where the latter shows different commit hashes in different invocations.

Knoble speculates this might relate to maintenance branch merges being topologically earlier despite having later timestamps, but expresses uncertainty about the root cause. The exchange highlights an important correctness consideration for the optimization work, suggesting the new algorithm may need to better align with Git's commit traversal semantics. This comes after Justin Tobler's earlier detailed code review raised other implementation questions, indicating the patch series is still undergoing active scrutiny.
