This is a feature patch series introducing a new "geometric" maintenance strategy for Git repositories, with particular focus on improving maintenance in monorepos. The series builds on ongoing work around repository maintenance and geometric repacking.

The core problem being addressed is that `git gc`'s all-into-one repacks don't scale well for monorepos, while the existing "incremental" strategy has limitations - it only applies to scheduled maintenance and avoids deleting any data. The new "geometric" strategy uses Git's geometric repacking capability for most operations, falling back to cruft packs when a geometric repack would collapse everything into one packfile. This provides better scaling while still allowing object expiration.

Key technical changes include:
- A "geometric-repack" maintenance task that implements the new strategy
- Extending maintenance strategies to cover both manual and scheduled runs
- Backward-compatible handling of the existing "incremental" strategy
- Various refactoring to support these changes (removing globals, making functions reusable)

The series touches core maintenance functionality in builtin/gc.c and builtin/maintenance.c, adds extensive tests in t7900, and updates documentation. The changes appear well-motivated and carefully implemented, with thorough test coverage (212 lines of new tests). This seems like a significant improvement to Git's maintenance capabilities, particularly for large repositories.
