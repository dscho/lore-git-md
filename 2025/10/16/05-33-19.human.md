Refactoring patch in a security-focused series to improve function naming clarity.

This is patch 2/5 in Michael Lohmann's v3 series addressing security around untrusted repository hooks. The patch renames `die_upon_dubious_ownership()` to `die_upon_unsafe_repo()` to better reflect its expanded role in repository safety checks. The function name change was suggested by Junio Hamano and has been incorporated in this revision.

The function now more accurately describes its behavior, which goes beyond just ownership verification to include checking the `safe.directory` config and will accommodate future safety checks. The change is mechanical, updating call sites in `builtin/clone.c`, `path.c`, `setup.c`, and `setup.h`.

This is part of the series' broader effort to prevent arbitrary code execution via Git hooks in untrusted repositories. The patch appears straightforward and well-justified, with all prior review comments addressed in this v3 submission.
