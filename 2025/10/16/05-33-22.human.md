This is the final patch in a security-focused series addressing arbitrary code execution via Git hooks in untrusted repositories. The patch introduces a persistent way to prevent Git from automatically treating user-owned repositories as safe, complementing the temporary bypass mechanism added in patch 4/5.

The change adds three ways to enforce explicit "safe.directory" configuration: a `--assume-unsafe` command-line flag, a `GIT_ASSUME_UNSAFE` environment variable, and a `safe.assumeUnsafe` config option. These prevent Git from considering repository ownership as sufficient for safety, requiring explicit allow-listing instead. The implementation carefully prevents repositories from marking themselves as safe via local config.

The patch includes thorough documentation updates and extensive test coverage in `t/t0036-allow-unsafe-directory.sh`, verifying all configuration methods and their interactions. This completes the series' goal of hardening against accidental execution of malicious hooks from downloaded repositories while providing both temporary and persistent control mechanisms.

With all prior review comments addressed and comprehensive testing, this appears ready for integration as a security enhancement to Git's repository safety model.
