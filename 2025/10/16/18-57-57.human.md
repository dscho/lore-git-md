Feature patch (2/3) adding Message-ID commit header support. This patch builds on the previous mailinfo changes to now include Message-IDs as commit headers when applying patches via `git am`. The implementation adds a new `msg_id` field to track the ID through the am process and creates a proper "message-id" extra header in the final commit.

The change maintains backward compatibility - when `-m` is used, the Message-ID still appears as a trailer as before, but now it will always be recorded in the header when available. The implementation is clean, with proper memory management and error handling. The patch touches only builtin/am.c, adding about 15 lines of well-contained changes.

This continues the series' goal of better linking commits to their mailing list origins, particularly useful for kernel-style workflows. The approach here is minimal and non-disruptive, keeping existing behavior while adding the new header capability. The next patch will presumably complete the series, possibly with documentation or test updates.
