This is a brief technical suggestion in the ongoing Message-ID tracking discussion. Kristoffer Haugsbakk proposes using an `X-Git-Original-Message-ID` header as a potential solution to Junio Hamano's concern about preserving mailing list archive provenance when commits are re-exported via format-patch.

The suggestion comes in response to Hamano's objection that the current header-based Message-ID storage would break archive linking when commits are rebased or re-exported, since format-patch must drop Message-IDs to comply with RFC uniqueness requirements. Haugsbakk's idea appears to be keeping the original Message-ID in a different header that wouldn't be subject to the same uniqueness constraints.

This is just a one-line proposal without detailed implementation discussion, but it directly addresses one of the key open questions in the thread about how to maintain archive links while still supporting kernel workflow requirements. The suggestion hasn't yet been acknowledged or discussed by either the original author (James Bottomley) or Hamano.
