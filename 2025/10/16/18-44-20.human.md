This is a bugfix for GPG signature handling that addresses potential data corruption when processing signatures containing standalone carriage return (CR) characters. 

The patch modifies how Git handles CR characters in GPG and SSH signatures. Currently, the code strips all CR characters it encounters, which can corrupt binary data or text from older systems that legitimately use standalone CRs. The new version only removes CRs when they appear immediately before a line feed (LF), preserving Windows-style CRLF line endings while leaving other CRs intact.

The change affects the `gpg-interface.c` file, renaming the function from `remove_cr_after()` to `trim_cr_before_lf()` to better reflect its more precise behavior. The implementation now carefully checks for CR-LF sequences rather than blindly removing all CRs.

The change is focused and maintains the existing Windows line ending normalization while fixing the data corruption case. The patch includes updates to all relevant call sites and preserves the original functionality where it's actually needed.
