This is a refactoring patch that removes a global variable in preparation for the geometric maintenance strategy series. It eliminates the global `repack` strvec in builtin/gc.c, replacing it with stack-allocated variables passed through function calls. The change makes the code more reusable for the upcoming geometric repacking functionality while maintaining identical behavior.

The key technical changes involve:
- Converting `repack` from global to local storage in `cmd_gc()`
- Modifying helper functions (`keep_one_pack`, `add_repack_all_option`, `add_repack_incremental_option`) to accept a strvec pointer parameter
- Special handling for `need_to_gc()` which is used by both `git gc` and `git maintenance` - it now takes a repack args parameter for gc but uses a temporary for maintenance
- Adding a new `gc_condition()` wrapper for the maintenance case that safely discards the temporary args

The patch touches core GC functionality but is strictly a refactoring - no behavior changes are introduced. The changes appear carefully implemented with attention to edge cases, particularly around the dual use of `need_to_gc()`. This sets up cleaner infrastructure for the geometric repacking strategy to be introduced in later patches.
