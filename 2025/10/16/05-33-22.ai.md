This is the final patch in a security-focused series addressing arbitrary code execution via Git hooks in untrusted repositories. The patch introduces persistent configuration options to prevent Git from automatically considering user-owned repositories as safe, requiring explicit `safe.directory` listing instead.

The patch adds three ways to enforce this stricter safety model:
1. Command-line `--assume-unsafe` flag
2. `GIT_ASSUME_UNSAFE` environment variable
3. `safe.assumeUnsafe` configuration option (which cannot be set in local repository config)

Key technical changes include:
- New `GIT_ASSUME_UNSAFE` constant in `environment.h`
- Command-line flag handling in `git.c`
- Configuration parsing in `setup.c`'s `safe_directory_cb()`
- Safety check modification in `ensure_safe_repository()` to respect the new flag
- Comprehensive test coverage in `t/t0036-allow-unsafe-directory.sh` verifying all configuration methods

The implementation ensures repositories cannot mark themselves as safe via local config, maintaining the security model established in earlier patches. Error messages reference the new bypass option (`--allow-unsafe`) when rejecting unsafe repositories. The patch appears complete with thorough documentation updates in both config and command reference pages.

This concludes the v3 series which has addressed all prior review feedback, now providing both temporary (`--allow-unsafe`) and persistent safety control mechanisms. The changes are well-contained to security-sensitive paths with extensive test coverage, suggesting it's ready for integration.
