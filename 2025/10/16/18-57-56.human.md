This is the first patch in a series proposing to track Message-IDs in Git commits as headers rather than trailers. The change is motivated by Linux kernel workflow needs to better link commits back to their mailing list discussions.

The patch modifies mailinfo.c to always collect the Message-ID from incoming emails, rather than only when add_message_id is set. This is a prerequisite for the series' goal of storing Message-IDs as commit headers. The change maintains backward compatibility by still checking add_message_id when deciding whether to include the ID as a trailer.

The implementation is straightforward - just a few lines changed to remove the conditional collection of the Message-ID. The patch appears well-scoped and properly explained, though as the first in a series, the full motivation becomes clearer when considering the cover letter's context about improving Message-ID tracking for kernel workflows.
