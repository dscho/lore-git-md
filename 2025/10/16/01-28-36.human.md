This is a discussion contribution about the proposed removal of `git diff X..Y` syntax, part of an ongoing thread about potentially breaking changes for Git 3.0.

Justin Tobler weighs in on Martin von Zweigbergk's proposal to remove the confusing `git diff X..Y` syntax. He suggests going further by also removing the triple-dot notation (`A...B`), arguing both are too easily confused with revision range syntax. Justin proposes simpler alternatives using space-separated arguments that would be just as concise.

While acknowledging the current syntax is problematic, Justin recognizes the potential disruption to existing scripts - agreeing with brian m. carlson's earlier objections about backward compatibility. He floats Git 3.0 as a possible inflection point for such changes, though doesn't take a firm position on whether the change should ultimately happen.

The email doesn't introduce new technical details but reinforces the core tension in the thread: balancing cleaner semantics against real-world compatibility concerns. Justin's perspective as someone who finds the dot notations confusing but recognizes their entrenched use adds weight to both sides of the debate. The discussion remains unresolved, with no clear consensus emerging about whether, when, or how to proceed with the syntax changes.
