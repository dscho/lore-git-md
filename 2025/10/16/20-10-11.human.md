This is a clarification in the ongoing discussion about adding Message-ID tracking to Git commits. James Bottomley responds to Kristoffer Haugsbakk's references to prior Change-ID discussions, explaining the key differences between the two approaches.

The thread began with Bottomley's proposal to store Message-IDs in commit headers to link commits to their originating emails, particularly useful for kernel development workflows. Haugsbakk then provided historical context about Change-ID implementations from 2025, which used trailer-based approaches inspired by tools like Gerrit.

Bottomley now clarifies that Message-ID tracking serves a fundamentally different purpose than Change-ID. While Change-ID tracks changes across commits in Git-native workflows (where emails aren't involved), Message-ID specifically links commits back to their email origins - crucial for email-based workflows where CI tooling needs to connect commits to mailing list discussions. He emphasizes these are orthogonal solutions addressing different needs.

The exchange helps frame the current proposal by distinguishing it from similar-sounding but functionally different prior work, potentially heading off confusion about the Message-ID feature's scope and purpose. The technical implementation (storing IDs in commit headers while maintaining trailer compatibility) remains unchanged from the original proposal.
