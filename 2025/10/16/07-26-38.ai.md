Feature patch in the geometric maintenance strategy series, making the "gc" strategy explicitly configurable.

This patch addresses a gap in the maintenance strategy configuration by making the "gc" strategy (previously only used as an implicit default) explicitly selectable. The change serves two purposes: allowing repository-specific overrides when a global strategy is set, and enabling `git gc` to run during scheduled maintenance (previously it only ran for manual maintenance).

Key technical changes:
- Adds "gc" to the documented list of valid strategies in maintenance.adoc
- Renames `default_strategy` to `gc_strategy` and extends it to work for both manual and scheduled maintenance (MAINTENANCE_TYPE_MANUAL | MAINTENANCE_TYPE_SCHEDULED)
- Updates the strategy parser in builtin/gc.c to recognize "gc" alongside "incremental"
- Modifies test cases in t7900-maintenance.sh to verify the new explicit gc strategy works equivalently in both manual and scheduled contexts

The patch maintains backward compatibility while adding flexibility - the gc strategy remains the default for manual maintenance, but can now be explicitly selected when needed. Test coverage is expanded to verify the new behavior matches expectations for both maintenance types.

This change fits naturally into the larger geometric maintenance series by completing the strategy configuration options, though it doesn't directly interact with the geometric repacking functionality itself. The implementation is straightforward and well-tested, with clear documentation of the new capability.
