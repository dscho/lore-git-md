This is the second patch in a series adding Message-ID tracking to Git commits, implementing the storage of Message-IDs as commit headers. The patch builds on the first one which modified mailinfo to always collect Message-IDs.

The key change adds a new `msg_id` field to the `am_state` struct and modifies `do_commit()` to store the Message-ID as an extra commit header when present. The implementation maintains backward compatibility by still allowing Message-IDs to be stored as trailers when `-m` is specified. The header will be visible in `--pretty=raw` output but hidden by default.

The patch makes several specific changes:
1. Adds `msg_id` to `am_state` with corresponding memory management
2. Captures the Message-ID from mailinfo during patch parsing
3. Constructs a commit_extra structure for the Message-ID
4. Passes this to commit_tree_extended when creating the commit

The implementation appears clean and focused, though it currently lacks test coverage (presumably will come in a later patch). The change is well-motivated by the series' overall goal of better linking commits to mailing list discussions, particularly for kernel workflow needs. The backward compatibility handling suggests careful consideration of existing use cases.
