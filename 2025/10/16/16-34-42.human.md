This is a continuation of the discussion about removing potentially confusing `git diff` syntax in Git 3.0. Martin von Zweigbergk responds to Justin Tobler's suggestion to also remove the triple-dot notation (`A...B`), agreeing that both forms are problematic since they reuse revision range syntax but with different semantics. 

Martin notes that `jj diff` (from the jujutsu VCS) handles range diffs more consistently, showing combined diffs for commit ranges in a way that aligns with range notation. He acknowledges the triple-dot notation is convenient for merge-base diffs but struggles to suggest an alternative shortcut syntax that wouldn't require shell escaping. 

The exchange highlights the tension between fixing confusing behavior and maintaining backward compatibility, with both participants recognizing Git 3.0 might be an appropriate time for such a breaking change. The discussion remains open-ended, as no clear alternative syntax has emerged yet for the triple-dot case, and concerns about script breakage persist.
