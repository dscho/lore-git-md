This is a documentation discussion about deprecating the `--committer-date-is-author-date` option in `git-am` and `git-rebase`. Junio C Hamano weighs in on the ongoing thread about how strongly to discourage use of this option, following Johannes Sixt's definitive rejection of its original use case.

The discussion has moved from technical debate to documentation strategy. While Johannes Sixt advocates for direct "Do not use" language, Junio suggests a more nuanced approach - either officially deprecating and scheduling removal (if the community is convinced the option is harmful) or simply explaining why the original use case was flawed while leaving the option available. He proposes framing the documentation as a warning about the option's pitfalls rather than an outright prohibition, noting "We'd give a long rope that we do not think is very useful, but it is up to you to get yourself tangled in it."

Key technical context remains unchanged from the thread summary: the option violates Git's timestamp ordering assumptions and the original 2009 use case (pseudo-import via `git-am`) has been conclusively rejected as invalid. The open question is purely about communication strategy - how strongly to word the documentation warnings, with Junio leaning toward descriptive rather than prescriptive language unless the community is ready to commit to removal.

This email represents the final decision point before Kristoffer Haugsbakk prepares the documentation patch revision. Junio's input suggests the documentation may stop short of outright deprecation unless there's consensus to back removal, instead focusing on clearly explaining why the original use case was misguided while leaving the option technically available.
