Documentation update on timestamp manipulation options in `git-am` and `git-rebase`.

Kristoffer Haugsbakk responds to feedback on his documentation patch about the `--committer-date-is-author-date` option, which can create commit histories that violate Git's timestamp ordering assumptions. The discussion has revealed deeper questions about the original use case for this option in `git-am`, where it was used to "pseudo-import" commits while preserving metadata.

The author plans to proceed with version 2 of his patch, which will:
1. Deprecate the option for `git-rebase` due to timestamp ordering issues
2. Keep it for `git-am` (with warnings) while raising new questions about whether this use case itself is valid

The email highlights two key technical questions that need resolution: whether abusing `git-am` for pseudo-imports is a reasonable workflow, and if so, whether there are better ways to achieve this without violating timestamp assumptions. The discussion shows careful consideration of documentation phrasing and warning placement, with the author actively incorporating feedback from Johannes Sixt and other contributors.
