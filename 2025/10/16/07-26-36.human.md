This is a refactoring patch in the geometric maintenance strategy series, preparing the system to handle different maintenance execution contexts (manual vs scheduled) more cleanly.

The patch notes that Git currently has three ways to run maintenance (manual, auto, scheduled) but strategies only affect scheduled runs. To support extending strategy behavior to other contexts, it introduces a new `maintenance_type` enum to distinguish between manual/auto and scheduled runs, converting the simple `enabled` boolean into a bitset that can specify which contexts should run each task.

The changes maintain existing behavior for the default and incremental strategies - default remains manual-only while incremental stays scheduled-only. The actual strategy behavior changes will come in later patches. The implementation touches the strategy definitions and task initialization code in builtin/gc.c, replacing boolean checks with bitmask operations.

This appears to be a well-contained preparatory change that cleanly separates the execution context concern from the strategy logic. The patch keeps the existing behavior while making the code more flexible for the geometric strategy work to follow in the series. The commit message clearly explains both the current limitations and how this change enables the planned improvements.
