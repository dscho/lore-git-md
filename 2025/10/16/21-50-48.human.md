This is a resubmission of the previously discarded `lc/rebase-trailer` patch series, which adds `--trailer` support to `git rebase` and moves trailer handling in-process rather than forking to `interpret-trailers`. The original version was dropped from the integration branches in August due to inactivity, but the author has now sent a new iteration (v2) with the same core functionality. 

The changes aim to make it easier to modify commit trailers during interactive rebases by allowing direct specification of trailers via a new `--trailer` option, similar to how `git commit --trailer` works. The implementation also eliminates the need to fork a separate `interpret-trailers` process, which should improve performance.

While the resubmission doesn't appear to include major changes from the original (based on the identical commit messages), its return suggests the author has addressed whatever issues kept it from progressing before. This was one of two stale topics mentioned in Junio's "What's cooking" report that had been removed from consideration, so its reappearance indicates renewed development activity on this feature.

The patch touches rebase and trailer handling code, areas that often require careful review due to their potential impact on commit history manipulation. The change to in-process trailer handling in particular may warrant scrutiny around edge cases and error handling.
