This thread follows an Outreachy participant's effort to modernize GPG/SSH signature parsing code by converting from `strbuf_split_max()` to `string_list_split()`, part of a larger 11-patch cleanup effort initiated by Junio Hamano. The two-patch series handles SSH key fingerprint parsing and GPG verification paths in `gpg-interface.c`, with the current v2 awaiting a v3 iteration.

Junio Hamano has weighed in on a key technical question about validation strictness for SSH key fingerprints. While the original code accepted any input with more than one token, the proposed change enforces exactly three tokens (key size, fingerprint hash, and comment). Junio questions whether this tightening is justified, particularly since the comment portion may not always be present. He recommends keeping the original lenient validation for now, deferring any stricter requirements to a future change. This maintains the series' focus on being a straightforward API modernization.

The author, Bello Olamide, has committed to several improvements for v3 based on earlier feedback from Christian Couder: adding broader context about the 11-patch effort, including a range-diff, CI test results, and better documentation of the validation rationale. They're also investigating Junio's suggestion to use `string_list_split_in_place()` where possible. The remaining open question is whether to maintain the original lenient validation or proceed with stricter checks - a decision that may depend on further analysis of real-world SSH key formats.
