This is a feature proposal to add Message-ID tracking to Git commits. James Bottomley introduces a 3-patch series that would store the email Message-ID header in commits, making it easier to link commits back to their original discussion threads. The change would only visible in `--pretty=raw` output, keeping it unobtrusive while enabling better tooling integration.

The motivation comes from kernel development workflows where linking commits to mailing list discussions is valuable, but the change is framed as generally useful for any Git project. The implementation preserves backward compatibility with existing `git am -m` behavior that adds Message-IDs as trailers, though the new approach would make this redundant.

The series includes core changes to `mailinfo.c` and `builtin/am.c` to handle the Message-ID collection, plus a test case in `t4150-am.sh`. The patches appear focused and well-contained, addressing both the core functionality and test coverage. This seems like a straightforward quality-of-life improvement for projects that rely heavily on mailing list workflows.
