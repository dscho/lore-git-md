Documentation update and deprecation discussion for `--committer-date-is-author-date` option in Git commands.

Kristoffer Haugsbakk responds to Johannes Sixt's feedback about the ongoing documentation patch regarding the `--committer-date-is-author-date` option. The discussion has evolved to question whether the original use case for this option in `git-am` (pseudo-importing commits while preserving author dates) is actually valid, given that it violates Git's timestamp ordering assumptions. 

Haugsbakk outlines two key questions that need resolution: (1) whether the pseudo-import use case via `git-am` is reasonable, and (2) if so, what alternative methods could achieve the same goal without timestamp violations. He references an old email thread that originally introduced the option, suggesting setting the timestamp to max Unix time as a potential alternative approach.

The author maintains his position to deprecate the option for `git-rebase` while keeping it for `git-am`, but acknowledges the need to address these deeper questions about the validity of the original use case. The discussion touches on fundamental aspects of Git's commit ordering assumptions and the proper use of `git-am` versus its intended design. This email represents a pivot point where the conversation moves beyond documentation wording to examine the underlying technical rationale for the option's existence.
