This thread focuses on optimizing the new `git last-modified` command, which efficiently finds the most recent commit modifying each path. The original implementation from GitHub was slow for rarely-modified paths, and Toon Claes has substantially reworked it with a new algorithm using priority queues, path activity bitmaps, and Bloom filters. The core improvements are significant - 2.6x faster on git.git and 5.3x faster for extreme cases.

The discussion has established `git log --max-count=1` behavior as the correctness benchmark. D. Ben Knoble identified a case where the old implementation gave different results between filtered and unfiltered runs due to maintenance branch merges, which the new version fixes. Taylor Blau and Jeff King provided detailed technical analysis, including tracing a NULL oid segfault to checks lost during refactoring from GitHub's original implementation.

In the latest update, Toon Claes presents benchmark results comparing bitmap implementations, showing EWAH bitmaps (793ms) are slightly faster than character arrays (809ms) while using less memory. Surprisingly, storing bitmaps as pointers (784ms) outperforms storing them as values (857ms). This data helps resolve open questions about optimal storage strategies. The thread shows steady progress refining the implementation while maintaining the core performance gains, with remaining work on bitmap lifecycle management, flag documentation, and finalizing data structures.
