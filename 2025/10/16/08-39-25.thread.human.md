This thread focuses on optimizing the `git last-modified` command to efficiently find the most recent commit modifying each path, while ensuring its behavior exactly matches `git log --max-count=1` as the correctness benchmark. The effort builds on prior work by Taylor Blau and Derrick Stolee, with substantial reworking by Toon Claes.

The current implementation introduces a new algorithm using generation-sorted commits with a priority queue, path activity tracking via EWAH bitmaps, and Bloom filter optimizations to skip unnecessary diffs. Initial benchmarks show promising speedups of 2.6x on git.git and 5.3x for edge cases. However, several implementation details need refinement.

Taylor Blau has now responded to the latest version, confirming the performance improvements but suggesting additional benchmarking on larger repositories like linux.git. He provides a fix for a segfault when mark_path() receives a NULL oid and offers detailed feedback on design choices like bitmap vs char* for path tracking and the use of generic slabs. While not challenging the core algorithm, Taylor identifies areas needing clarification around parent processing, flag usage, and the handling of the no_walk flag.

Ben Knoble surfaced a specific correctness case where the old implementation produced different results from `git log --max-count=1` when run with versus without path arguments. The thread remains focused on both performance optimization and ensuring exact behavioral parity with the established benchmark. Several open questions remain around edge case handling and implementation details, but the core approach appears sound.
