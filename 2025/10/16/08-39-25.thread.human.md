The thread concerns a performance optimization for `git last-modified` that introduced a regression in merge commit handling. Toon Claes' original series brought significant speedups (2.5x-111.7x) using generation-sorted priority queues and EWAH bitmaps, which was merged to 'next' after receiving Acked-by from Taylor Blau and positive reviews from Jeff King.

However, test failures emerged on s390x (reported by Anders Kaseorg) and HP NonStop (confirmed by Jeff King), revealing the optimization incorrectly attributed file modifications to merge commits rather than their actual sources. Initial suspicions of platform-specific endianness issues proved incorrect - the problem was algorithmic, affecting all platforms. The core issue involved wrong parent ordering during merge commit processing, causing files to be wrongly credited to merge commit da1857e0 instead of their true origins (b5 for file2, b2 for file).

Toon has submitted a fix that preserves the performance gains while correcting the merge handling logic. The solution addresses the test failures without platform-specific code and maintains the optimization's architectural improvements. Key contributors to diagnosing and resolving this include Jeff King's analysis of blame propagation and Anders Kaseorg's initial bug report. The fix has been verified across platforms and the optimized `git last-modified` command should now work correctly in all cases while keeping its substantial speed improvements.
