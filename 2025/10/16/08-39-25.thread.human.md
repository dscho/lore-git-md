This thread concerns a performance optimization for `git last-modified` that was recently merged to 'next' after extensive review. The new algorithm, developed by Toon Claes with input from Taylor Blau and Jeff King, uses priority queues and EWAH bitmaps to dramatically speed up finding the most recent commit modifying each path - showing 2.5x-9.3x improvements on git.git and up to 111.7x faster on linux.git. The series fixed a correctness issue identified by D. Ben Knoble where the old implementation could give different results between filtered and unfiltered runs due to merge commit timestamp handling.

However, Anders Kaseorg has now reported platform-specific test failures on s390x architecture, with the new code incorrectly attributing file modifications across merge boundaries in two test cases. The failures suggest either an endianness issue with the bitmap handling or some platform-specific behavior in merge commit processing. Kristoffer Haugsbakk has asked for more detailed test output to help diagnose the problem. The core developers involved will need this additional information to determine whether the issue requires platform-specific adjustments to the bitmap handling, merge processing, or test coverage. While the optimization itself remains sound on mainstream architectures, this s390x-specific regression will need to be addressed before the series can graduate to 'master'.
