This thread focuses on optimizing the performance of `git last-modified`, a command that identifies the most recent commit modifying each specified path. The original implementation was inefficient for rarely-modified paths due to excessive history walking. Toon Claes has led a substantial rework introducing a new algorithm using generation-sorted priority queues, EWAH bitmaps for path activity tracking, and Bloom filter optimizations.

The current implementation shows dramatic speedups—2.5x-9.3x faster on git.git and 7.9x-111.7x on linux.git—while fixing correctness issue where maintenance branch merges could produce inconsistent results. Key contributors like Taylor Blau, Jeff King, and Junio Hamano have provided extensive technical review, catching issues ranging from NULL oid segfaults to memory management tradeoffs between bitmaps and char arrays.

The latest email from Taylor Blau refines a previous suggestion by adding a `const` qualifier to the `path` parameter in the new `last_modified_mark_non_treesame()` function. This small but important change builds on Junio's earlier fixes for compiler warnings related to signed/unsigned comparisons, further improving code quality while preserving the algorithm's significant performance gains.

A few open items remain, including finalizing bitmap lifecycle management and documenting flag space usage, but the core algorithm has consensus. The thread demonstrates effective collaboration between multiple experts to refine both the high-performance algorithm and its implementation details.
