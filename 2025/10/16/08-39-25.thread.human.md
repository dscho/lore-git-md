This thread focuses on optimizing the performance of a proposed `git last-modified` command that identifies the most recent commit modifying each specified path. The original implementation was slow for rarely-modified paths due to excessive history walking. Toon Claes has led a substantial rework introducing a new algorithm using generation-sorted priority queues, EWAH bitmaps for path activity tracking, and Bloom filter optimizations.

The technical refinements have addressed several issues raised during review, including a NULL oid segfault, memory/performance tradeoffs between bitmaps and char arrays, and TREESAME handling. Benchmarking on git.git showed 2.5x-9.3x speedups. New results on linux.git demonstrate even more dramatic improvements - the new algorithm is 7.9x faster with Bloom filters (110ms vs 1.536s) and 111.7x faster without them, validating the approach scales well to large repositories.

Key contributors Taylor Blau and Jeff King have provided detailed technical analysis throughout, helping refine the implementation. While some documentation and final optimizations remain, the core algorithm has consensus. The latest benchmarks strengthen the case for merging this optimization, showing it substantially improves performance while maintaining correctness across repository sizes.
