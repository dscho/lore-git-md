This thread discusses performance optimizations for the `git last-modified` command, which identifies the most recent commit modifying each path. The current implementation is being reworked to address both speed and correctness issues, particularly for rarely-modified paths. The new approach introduces several optimizations: a priority queue for commit processing, path activity tracking via bitmaps, and Bloom filter optimizations to skip unnecessary diffs.

Key contributors include Toon Claes (primary author), with substantive reviews from Justin Tobler, D. Ben Knoble, Taylor Blau, and Jeff King (Peff). The patches show significant performance improvements (2.6x-5.3x faster) while fixing cases where the old implementation could differ from `git log --max-count=1` results. A specific correctness issue was identified where maintenance branch merges with later timestamps but earlier topological positions were being incorrectly reported - the new implementation fixes this as a side effect.

Recent discussion has focused on implementation details like bitmap lifecycle management, flag space documentation, and benchmarking needs. While the core algorithm has consensus, some design choices around path tracking data structures remain open. The thread maintains careful attention to technical precision, even in wording choices ("correct" vs "accurate"). Next steps include finalizing implementation details and additional benchmarking, particularly on larger repositories like linux.git.
