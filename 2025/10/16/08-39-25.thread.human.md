This thread focuses on optimizing the performance of `git last-modified`, a command that identifies the most recent commit modifying each specified path. The original implementation was slow for rarely-modified paths due to excessive history walking. Toon Claes has led the rework, building on prior work by Taylor Blau and Derrick Stolee, with substantial input from Jeff King (peff).

The new approach introduces several key optimizations: a priority queue of generation-sorted commits, path activity tracking via EWAH bitmaps, and Bloom filter usage to skip unnecessary diffs. These changes yield significant speedups - 2.5x faster on git.git and up to 5.3x for edge cases. The implementation also fixes a correctness issue where the old version could disagree with `git log --max-count=1` results, particularly around maintenance branch merges.

Recent progress includes fixing a NULL oid segfault, renaming the commit slab to better reflect its purpose ("active_paths_bitmap"), and removing redundant operations. Benchmark data shows EWAH bitmaps with pointer storage offer both speed and memory advantages over alternative approaches. While the core algorithm has consensus, some implementation details remain open, including finalizing path tracking structures and bitmap lifecycle management. The thread demonstrates effective collaboration between Toon Claes, Taylor Blau, and Jeff King to refine this complex optimization while maintaining correctness.
