The thread concerns performance optimizations for the `git last-modified` command, which was recently merged after showing dramatic speed improvements (2.5x-111.7x faster) on most platforms. The optimization uses generation-sorted priority queues and EWAH bitmaps to track file modifications more quickly.

However, Anders Kaseorg has reported test failures on s390x (IBM mainframe) systems, where the command incorrectly attributes file modifications to merge commits rather than their actual authors. The latest email provides concrete test output showing these failures, confirming earlier suspicions about platform-specific issues. In test 16, a file is wrongly credited to a merge commit instead of its true author, and test 19 shows similar misattribution for two files.

The core team (including Toon Claes who wrote the optimization, and reviewers Taylor Blau and Jeff King) are investigating whether this stems from endianness differences in bitmap handling, merge commit processing assumptions, or other platform-specific factors. While the optimization works well on most architectures, the s390x case requires special attention. The thread remains active as developers analyze the test failures to determine if the algorithm needs modification or if platform-specific adjustments will suffice.
