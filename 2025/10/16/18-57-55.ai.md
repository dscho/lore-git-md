This is a feature proposal to add Message-ID tracking to Git commits, motivated by discussions in the kernel community about linking commits to their originating emails. The 3-patch series introduces a new commit header that stores the email's Message-ID, making it available in `--pretty=raw` output for scripting purposes while keeping it hidden from normal view.

The changes modify `mailinfo.c` to always collect the Message-ID from incoming patches, update `builtin/am.c` to add it as a commit header, and add a test case in `t4150-am.sh` to verify the functionality. The implementation maintains backward compatibility with existing workflows that use `git am -m` to add Message-IDs as trailers, though the author suggests this may become redundant.

Key technical details include:
- New header stored in commit objects but not shown by default
- No changes to existing trailer-based Message-ID storage
- Test coverage for the new header collection
- Touches core mail handling code in mailinfo and am

The proposal appears well-motivated by real-world scripting needs in the kernel community, with clean implementation and test coverage. The backward compatibility approach suggests careful consideration of existing workflows. This could spark discussion about whether the trailer-based method should eventually be deprecated in favor of the new header approach.
