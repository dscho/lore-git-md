This thread proposes adding Message-ID tracking to Git commits to better link commits with their originating discussions, particularly for Linux kernel workflows. The initial patch modified mailinfo to always collect Message-IDs while maintaining backward compatibility with the existing trailer-based approach.

The second patch, just submitted, implements the core functionality by storing Message-IDs as commit headers. It adds a msg_id field to track the ID during patch application and modifies the commit creation process to include it as an extra header. The implementation carefully preserves the existing -m trailer behavior while adding the new header-based storage. The Message-IDs will be visible in raw commit views but hidden by default.

The changes so far appear well-scoped and backward-compatible, though test coverage is still pending. The series seems to be progressing methodically, with the first patch handling collection and this one implementing storage. The next patch will presumably add tests and possibly documentation. The approach shows thoughtful consideration of existing workflows while introducing the new capability.
