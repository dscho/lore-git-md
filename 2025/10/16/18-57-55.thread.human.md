This thread proposes adding Message-ID tracking to Git commits to link them back to mailing list discussions, particularly for Linux kernel workflows. James Bottomley's initial patch set (v1) implements this by storing Message-IDs as commit headers while maintaining backward compatibility with the trailer-based approach used by `git am -m`. The series includes mailinfo modifications, storage implementation, and test coverage.

Kristoffer Haugsbakk has now contributed valuable context by pointing to prior discussions about Change-IDs - an alternative approach to commit tracking that was inspired by Gerrit and other tools. These historical references show this isn't the first attempt to solve commit-origin tracking, though the current proposal differs by using headers rather than trailers. While no direct feedback on the implementation has been given yet, this background information may help evaluate whether the header-based approach represents an improvement over previous methods and how it might integrate with existing ecosystem tools. The thread remains open for technical review of the proposed implementation.
