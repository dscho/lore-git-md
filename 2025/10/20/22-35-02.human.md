Performance optimization for macOS mmap/munmap operations. This patch introduces a queueing system for munmap calls on macOS to address significant performance degradation when alternating between many mmap/munmap operations. The author reports dramatic speedups - from 27 minutes down to 24 seconds in one extreme case - by batching munmap operations and processing them when the queue fills.

The implementation creates a new `compat/osxmmap.c` file with thread-safe queueing logic that accumulates munmap requests and processes them in batches (using Linux's default max_map_count of 65530 as the queue size). The patch includes comprehensive build system updates to include the new file on macOS platforms.

The performance impact is demonstrated with before/after timings on both the Linux kernel repository (2.08s -> 0.24s) and a private repository with nearly a million mmap operations (27m -> 24s). The solution appears well-considered, with proper thread synchronization via pthread mutex and clean handling of the mmap/munmap wrappers.

This seems like a real performance pain point specific to macOS, addressed with a focused solution that maintains compatibility while solving the immediate problem. The dramatic speed improvements suggest this could be valuable for macOS users working with large repositories.
