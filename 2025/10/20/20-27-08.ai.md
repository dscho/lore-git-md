This is a follow-up discussion in the `:(optional)` prefix implementation thread, focusing on test path handling patterns on Windows.

Ben Knoble responds to Johannes Sixt's clarification about when to use `$(pwd)` versus `$PWD` in test scripts. While acknowledging that `$(pwd)` is generally safer for absolute paths, Sixt noted there are cases where the less expensive `$PWD` can be used when path format doesn't matter. Knoble agrees with the distinction but suggests a linting mechanism would be more effective than documentation alone for enforcing these patterns, since developers are more likely to run lints than search for documentation.

The exchange highlights the ongoing challenge of maintaining platform-specific knowledge in the test suite, even when documented (as in `t/README`). While this doesn't block the current series, it surfaces broader questions about how to effectively standardize and enforce platform-aware test practices. Knoble's response indicates willingness to follow best practices but recognizes most contributors won't proactively seek out this information.
