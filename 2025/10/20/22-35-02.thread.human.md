This thread introduces a performance optimization specifically targeting macOS's mmap/munmap system calls, which were causing significant overhead in operations like `git ls-tree` when processing repositories with hundreds of thousands of mapped regions. The patch proposes a queueing mechanism that batches munmap operations, reducing system call overhead by up to 98% in benchmarked cases (from 27 minutes to 24 seconds sys time).

The implementation is carefully scoped to macOS while maintaining thread safety through pthread mutexes and restricting itself to Git's common use case of private read-only mappings. The solution includes proper build system integration across Makefile, CMake and meson, suggesting it's ready for production use. The dramatic performance improvement indicates this could be particularly valuable for developers working with large repositories on macOS.
