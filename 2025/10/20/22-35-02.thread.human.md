This thread explored a proposed optimization for macOS's mmap/munmap operations that was ultimately withdrawn after further investigation. Koji Nakamaru initially observed extreme performance degradation (27+ minutes for a `git ls-tree` operation) caused by excessive mmap/munmap calls, and developed thread-safe wrappers with a 65,530-entry queue to mitigate this. While the optimization showed dramatic improvements in these constrained scenarios, deeper analysis revealed the root cause was Nakamaru's unusually small `packedGitLimit = 128m` local setting rather than a general Git issue.

Jeff King (Peff) raised early concerns about whether this addressed real usage patterns, suggesting testing with normally packed repositories. Subsequent testing confirmed normal operations show only 9 mmap calls versus the 3 million seen with the restrictive config. Torsten Bögershausen contributed documentation-focused review suggestions, but the consensus emerged that proper repository maintenance (`git gc`) and configuration are the real solutions. Nakamaru has withdrawn the patch as the optimization addresses a non-issue for standard Git usage, validating Peff's initial skepticism. The thread is now concluded with no remaining open questions.
