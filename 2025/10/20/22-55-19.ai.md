This is a refactoring patch series that continues work started by Junio Hamano to replace unnecessary uses of `strbuf_split*()` functions with simpler string parsing approaches. The series focuses on two cases in `gpg-interface.c` where strings are split but the resulting strbufs aren't actually modified, making the strbuf API overhead unnecessary.

The v4 series represents a significant change from previous versions, switching from using `string_list_split_in_place()` (as in v3) to an even simpler approach using `strchr()` and `xmemdupz()` to directly extract the needed portion of the string. The key changes in both patches involve:

1. Replacing `strbuf_split_max()` calls with direct string parsing
2. Simplifying the code by avoiding intermediate strbuf allocations when only simple string extraction is needed
3. Maintaining the same functionality while reducing overhead

The first patch handles one case in `gpg-interface.c`, while the second patch (marked "[Part 2]") addresses another similar case in the same file. Both follow the same pattern of replacing strbuf splitting with direct string manipulation when the split results are only used as simple strings.

The commit messages explain that this makes the code "cleaner, faster and more efficient" by removing unnecessary strbuf operations. The changes appear well-justified given the context of Junio's original series that identified this pattern as suboptimal. The patches have been tested via GitHub CI and have received input from multiple contributors including Junio Hamano and Christian Couder.

Key technical details:
- Changes focus on gpg-interface.c
- Replaces strbuf_split_max() with strchr() + xmemdupz()
- Maintains same security checks via is_literal_ssh_key()
- Properly handles memory allocation and error cases
- Follows established pattern from prior work in wt-status.c
