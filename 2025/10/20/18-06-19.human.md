This is a follow-up discussion about Windows path handling in Git's test suite, specifically around the `$(pwd)` vs `$PWD` usage when testing absolute paths. The exchange reveals an ongoing challenge with platform-specific test patterns, even among experienced contributors.

Johannes Sixt and Junio Hamano discuss the nuances of path handling on Windows, where `$(pwd)` produces native Windows paths while `$PWD` yields POSIX-style paths (which can cause issues). While `t/README` already documents this difference, Junio candidly admits he still gets it wrong about half the time despite knowing the rule and having been bitten by it multiple times before.

The conversation highlights a broader issue about the effectiveness of documentation for platform-specific patterns. While the information exists in `t/README`, discoverability and retention remain challenges. The discussion doesn't propose immediate solutions but surfaces important questions about how to better maintain and communicate platform knowledge in the test suite. This comes as a series of patches implementing optional file handling is being finalized, where proper path handling proved particularly important.
