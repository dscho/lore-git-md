Feature implementation for the experimental `git repo info` command. This is the second patch in a two-part series that adds a new `--all` flag to display all available repository metadata keys at once, rather than requiring users to specify individual keys.

The patch implements the core functionality for `--all`, building on the preparatory refactoring from patch 1/2. When used, it outputs all known metadata keys (layout.bare, layout.shallow, object.format, references.format) in a consistent order. The implementation handles edge cases: combining `--all` with key arguments duplicates those keys in the output, while invalid keys trigger warnings but don't prevent valid output.

Test coverage is thorough, verifying the all-keys output matches individual key requests, duplicate key handling, and proper warning behavior for invalid keys. Documentation updates clearly specify that `--all` is mutually exclusive with key arguments in the command syntax.

The patch appears well-constructed, with clean separation of concerns building on the earlier refactoring. The commit message could better explain why users would want this feature (beyond not having to "search what are the desired keys"), but the implementation itself looks solid with good test coverage. This completes the series' goal of adding comprehensive metadata access to the experimental repo-info command.
