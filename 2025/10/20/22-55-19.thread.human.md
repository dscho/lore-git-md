This thread continues Junio Hamano's ongoing effort to simplify string parsing in the codebase by eliminating unnecessary uses of `strbuf_split*()` functions. The current series focuses on two cases in `gpg-interface.c` where strings are split but the results aren't modified, making the strbuf overhead unjustified.

The v4 iteration represents a significant simplification from previous versions, moving from `string_list_split_in_place()` (used in v3) to an even more direct approach using `strchr()` and `xmemdupz()`. Both patches follow the same pattern: replacing strbuf operations with simpler string extraction when the results are only used as read-only strings. The changes maintain all security checks (including `is_literal_ssh_key()`) while reducing overhead.

Junio Hamano and Christian Couder have provided input on earlier versions, and the current iteration appears to incorporate their feedback well. The patches have passed GitHub CI testing and follow established patterns from similar work in `wt-status.c`. The series looks ready for merging as a straightforward improvement to code clarity and efficiency.
