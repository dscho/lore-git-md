Performance optimization for macOS mmap/munmap operations. This patch introduces a queueing mechanism for munmap calls on macOS to reduce system overhead when many mmap/munmap operations occur in alternation. The implementation creates a new `compat/osxmmap.c` file with thread-safe queueing that batches munmap operations, flushing them when the queue fills or discarding them at program exit since macOS automatically cleans up mapped regions.

Key technical details:
- Adds `git_mmap`/`git_munmap` wrappers that replace the system calls on macOS
- Uses a static queue of `munmap_queue` structs (size 65530, matching Linux's default `vm.max_map_count`)
- Thread safety via `pthread_mutex`
- Restricts mmap usage to private read-only mappings (the common Git case)
- Build system updates for Makefile, CMake, and meson

The commit shows dramatic performance improvements in `git ls-tree` benchmarks - from 27m15s to 24s sys time on a repository with 943k mmap/munmap operations. The approach appears well-scoped to macOS-specific performance characteristics while maintaining safety through argument validation and automatic cleanup. The implementation seems production-ready with proper synchronization and memory allocation.
