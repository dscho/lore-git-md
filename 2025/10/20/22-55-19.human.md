This is a refactoring patch series that continues Junio Hamano's earlier work to replace unnecessary uses of `strbuf_split*()` with simpler string operations when the strbuf functionality isn't needed. The series focuses on two cases in `gpg-interface.c` where strings are split but the resulting tokens are only used as simple character pointers, not as strbufs that might be modified.

The key change in v4 is a further simplification from using `string_list_split_in_place()` (as in v3) to just using `strchr()` to find the delimiter and `xmemdupz()` to copy the needed portion. This makes the code more direct when all we need is to extract a substring without any strbuf operations.

The changes appear well-motivated by Junio's original observation that strbuf splitting is overkill when no strbuf operations follow. The commit messages clearly explain the rationale and the evolution of the approach across versions. The patches modify only `gpg-interface.c` and have been tested via GitHub CI.

This looks like a straightforward cleanup that makes the code more efficient by removing unnecessary indirection. The series is ready for review, with the v4 changes addressing feedback to simplify even further than the string_list approach used in earlier versions.
