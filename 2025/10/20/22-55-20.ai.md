Refactoring patch in the ongoing strbuf cleanup effort in gpg-interface.c. This is the first of two patches in v4 of the series, continuing work originally identified by Junio Hamano to eliminate unnecessary strbuf operations where simpler string parsing suffices.

The patch modifies `get_ssh_key_fingerprint()` to replace its use of `strbuf_split_max()` with direct string manipulation via `strchr()` and `xmemdupz()`. The key insight is that the function was splitting the ssh-keygen output into strbufs only to immediately extract and return a simple string, making the strbuf overhead unnecessary. The new implementation directly finds and copies the relevant portion of the string between two space delimiters.

The change maintains all existing error checking and security validation (via the earlier `is_literal_ssh_key()` call) while simplifying the memory management. The patch follows the same pattern previously established in wt-status.c for similar string parsing cases. Error messages are slightly adjusted to match the new control flow, though the behavior remains identical.

This version represents a further simplification from v3's approach, which had used `string_list_split_in_place()`. The patch has received input from Christian Couder and Junio Hamano through previous iterations, suggesting the approach is well-vetted. The change is focused and mechanical, touching only the fingerprint extraction logic while leaving surrounding code unchanged.
