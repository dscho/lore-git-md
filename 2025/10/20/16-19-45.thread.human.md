This thread discusses adding an `--all` flag to the experimental `git repo info` command to show all available repository metadata keys. The original two-part patch series first refactored the field printing logic, then added `--all` support that initially allowed combining the flag with specific key arguments.

After review, Patrick Steinhardt and Junio Hamano identified an interface inconsistency - the documentation implied `--all` and key arguments should be mutually exclusive, while the code allowed both. The discussion converged on enforcing mutual exclusivity as the better design. Lucas Seiki Oshiro has now confirmed they'll implement this change in v3 of the series, updating both the code and tests accordingly.

The command will continue showing repository metadata fields like layout.bare and object.format, but with stricter argument validation. The core printing infrastructure from the first refactoring patch remains unchanged. Test cases in t1900-repo.sh will be adjusted to reflect the new interface constraints, particularly around duplicate key handling scenarios.
