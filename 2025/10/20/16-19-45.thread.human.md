This thread introduces a new `--all` flag for the experimental `git repo info` command to show all available repository metadata keys. The two-patch series implements this through preparatory refactoring (extracting field printing logic) followed by the main `--all` flag implementation.

The discussion revealed a design tension between interface flexibility and consistency. Initially, the implementation allowed combining `--all` with specific key arguments (outputting all fields first, then any specified keys), while the documentation implied these should be mutually exclusive. Patrick Steinhardt raised concerns about this inconsistency and the lack of clear use cases for duplicate output. After consideration, Junio Hamano agreed that enforcing mutual exclusivity would provide a cleaner interface, representing a pivot from his earlier preference for the combined approach.

The series remains technically sound but now requires modification to either enforce mutual exclusivity or update the documentation. With Junio's approval of Patrick's suggestion, the former approach is likely. This resolves the main open question about the command's interface behavior. The next step will be an updated version of the series implementing this design decision.
