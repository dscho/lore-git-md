This is a follow-up in the ongoing discussion about making `git grep` ignore binary files by default. The original proposal has evolved into a broader design discussion about file filtering mechanisms.

Eloy summarizes the current consensus points: (1) changing the default behavior is unacceptable due to script compatibility concerns, (2) a config option is more reasonable though still potentially problematic in shared environments, and (3) there may be more flexible approaches using attributes. He suggests some new ideas - a `--porcelain` option for scripts and a way to temporarily override any ignore settings.

The email shows the proposal moving toward a practical middle ground. While Eloy still believes ignoring binaries would make a better default, he acknowledges the compatibility costs. The discussion has shifted focus to implementation details - how to make the feature both flexible enough for various use cases (like excluding linguist-generated files) while remaining simple to configure. The need for a negation flag shows thoughtful consideration of real-world usage patterns.
