This is part of Taylor Blau's ongoing refactoring series to modularize Git's repack machinery and remove global variables like `the_hash_algo`. Patch 9/49 continues the systematic elimination of direct `the_hash_algo` usage in `builtin/repack.c`, this time focusing on the `finish_pack_objects_cmd()` function.

The change modifies `finish_pack_objects_cmd()` to accept a `git_hash_algo` parameter instead of using the global variable. This affects several callers throughout the file, which now pass the hash algorithm from their existing repository pointer. The most notable change is updating the object ID length check to use the passed algorithm's hex size rather than the global one.

This is a mechanical but important change in the series' broader effort to make the repack code more modular and repository-aware. The patch follows the established pattern seen in earlier parts of the series, carefully threading the hash algorithm through function calls while maintaining identical behavior. The diff is slightly larger than some previous patches due to multiple call sites, but each change is straightforward and consistent.

The change continues the series' high-quality approach with clear mechanical conversions and no behavior changes. It builds on earlier work in the series that has already been reviewed, with Jeff King having completed a full review of the series and providing mostly minor feedback that Taylor has been incorporating.
