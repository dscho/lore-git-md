This is a refactoring patch in Taylor Blau's ongoing series to modularize Git's repack machinery (tb/incremental-midx-part-3). It focuses on simplifying the interface for writing MIDX files during repack operations.

The patch inlines the pack list computation into `write_midx_included_packs()` rather than having it computed separately in `cmd_repack()`. This eliminates the need to pass the pack list` through the `repack_write_midx_opts` struct (removing the `include` field) and makes the function self-contained. The change prepares for future introduction of incremental MIDX writing by establishing a pattern where each MIDX-writing variant handles its own pack selection logic.

Key technical changes include:
- Removes `include` field from `repack_write_midx_opts` struct
- Moves `string_list` initialization into `write_midx_included_packs()`
- Updates all callers to the new interface
- Maintains existing functionality including bitmap handling
- Follows the series' pattern of simplifying interfaces while maintaining behavior

The change is part of the broader effort to make the repack code more modular and maintainable, particularly around MIDX handling. It builds on previous patches in the series (notably patch 37/49 which introduced the opts struct) and appears to be a straightforward improvement with no obvious drawbacks. The commit message clearly explains the motivation and future direction this enables.
