This is part 6 of a 9-part refactoring series modernizing xdiff's type system for better Rust FFI compatibility. The patch converts the `nrec` field in `xdfile_t` from `long` to `size_t`, as it represents array element counts (for both `recs` and `changed` arrays) where `size_t` is the conventional type choice.

The change requires careful casting at API boundaries where `long` is still expected, particularly in diff algorithm implementations (patience, histogram) and merge/emit logic. The patch updates all comparisons and arithmetic operations involving `nrec` across xdiff's core files (xdiffi.c, xemit.c, xmerge.c, xpatience.c, xprepare.c) to explicitly cast when needed. The modifications maintain identical behavior while using more semantically appropriate types.

This continues the series' pattern of precise, behavior-preserving type changes that improve type safety and prepare for Rust interop. The conversion is straightforward but touches many call sites due to `nrec` being a fundamental field used throughout xdiff's algorithms. Review considerations include verifying all casts are safe (no truncation) and that performance remains unaffected in hot paths like diff calculation and merge operations.
