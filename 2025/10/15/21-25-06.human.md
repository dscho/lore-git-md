This is the first patch in a 4-part refactoring series cleaning up reference optimization code across Git's refs backends. The patch standardizes on using the `.optimize` callback function name consistently across all ref backends (files, packed, reftable), removing redundant `.pack_refs` implementations where they existed.

The change is mechanical but meaningful - it unifies the interface for reference optimization operations that were previously named differently between backends. The commit explains that while `pack_refs` was specific to the files/packed backends, `optimize` is the more generic term that covers all backends. No behavior changes are introduced; this is purely about code organization and naming consistency.

The patch touches four backend implementation files, removing duplicate code paths and ensuring all backends implement only the `optimize` callback. Test coverage remains unchanged since all callers were already using the `optimize` interface. This appears to be a well-scoped, non-controversial cleanup building on Patrick Steinhardt's prior work on ref optimizations.
