Refactoring patch in the xdiff type modernization series, splitting a dual-purpose hash field into two distinct fields for clarity.

This fifth patch in the 9-part series continues the xdiff subsystem refactoring for Rust FFI compatibility by addressing a confusing dual-use of the `ha` field in `xrecord_t`. The field previously served both as a simple line hash and as a minimal perfect hash for line comparison, making code harder to understand. The patch splits this into two explicit fields: `line_hash` (a straightforward hash of line content) and `minimal_perfect_hash` (a classifier-assigned unique identifier for line matching).

The changes touch core diff algorithms (patience, histogram) and preparation logic, updating all references to use the appropriate hash type. The split clarifies that line comparisons use the minimal hash while other operations may use the content hash. This maintains existing behavior while making the code's intent clearer - particularly important for the Rust FFI work where explicit typing matters.

Key technical points:
- Changes field type from `unsigned long ha` to `uint64_t line_hash` + `size_t minimal_perfect_hash`
- Updates all comparison functions (`recmatch`, `cmp_recs`, `match`) to use `minimal_perfect_hash`
- Modifies hash table operations in patience and histogram diffs to use the new field
- Preserves all existing behavior while making the dual hash purposes explicit

The patch follows the series' pattern of focused, behavior-preserving type changes that improve code clarity and FFI readiness. It builds on previous hash system modernization (patch 4) and maintains compatibility with the type changes introduced earlier in the series.
