This is patch 48/49 in Taylor Blau's ongoing refactoring series to modularize Git's repack machinery, specifically moving the cruft pack writing functionality out of the builtin code.

The patch relocates `write_cruft_pack()` from `builtin/repack.c` to a new `repack-cruft.c` file, exposing it through the repack.h API. This continues the series' pattern of systematically moving repack components into dedicated compilation units. The implementation remains functionally identical - this is purely a code organization change that:
1. Creates a new compilation unit for cruft pack handling
2. Updates build files (Makefile and meson.build)
3. Exposes the function in repack.h

This follows the same approach as previous patches in the series (like patch 47/49 which moved `write_filtered_pack()`). The change helps reduce the size and complexity of `builtin/repack.c` while establishing clearer module boundaries. The patch appears straightforward with no behavior changes, just mechanical code movement and build system updates.

As with the rest of the series, this contributes to the larger goals of removing global variables and creating a more maintainable repack architecture. The patch is well-contained and follows established patterns from earlier in the series, suggesting it should integrate smoothly.
