This is part 23/49 of Taylor Blau's repack refactoring series (tb/incremental-midx-part-3), continuing the modularization of `builtin/repack.c` with a focus on removing static variable dependencies.

The patch modifies `generated_pack_install()` to take explicit `packdir` and `packtmp` parameters rather than relying on static variables, following the pattern established in previous patches. The change is mechanical - the function now receives these paths from its single call site in `cmd_repack()` where the values are already available. 

Taylor notes a minor API design concern: having three consecutive `const char*` parameters makes parameter ordering errors possible, though introducing a struct for just these parameters might be overkill. The implementation maintains all existing behavior while improving modularity by removing implicit state dependencies.

This continues the series' systematic approach to converting repack functionality into properly modularized components with clean interfaces. The change is small but fits into the broader pattern of eliminating global/static state that has been established across patches 1-22. No behavior changes are introduced, and the patch follows the same careful mechanical conversion approach seen throughout the series.
