This is a design discussion email in the ongoing patch-id hash algorithm thread, with Junio C Hamano weighing in on brian m. carlson's configuration proposal. The email focuses on the technical implementation approach for allowing explicit hash algorithm selection in `git patch-id`.

Junio agrees with brian's suggestion to allow users to explicitly specify the hash algorithm, which would enable SHA-1 usage in SHA-256 repositories when needed for historical comparison. He outlines the automatic selection behavior: using the repository's hash algorithm when inside a repository, and falling back to the default algorithm (from the patch preimage) otherwise.

The email proposes a layered configuration approach, suggesting two potential variables - one to override just the fallback behavior (for non-repository cases) and another to force a specific algorithm globally. However, Junio recommends starting with a command-line option as the initial implementation, following Git's incremental development philosophy. This would allow testing the core functionality before adding more complex configuration options.

The discussion continues to center around balancing backward compatibility (SHA-1 stability for patch IDs) with forward-looking flexibility (SHA-256 support), while maintaining a clean user interface. Junio's input helps solidify the technical direction while advocating for a cautious, step-by-step implementation approach.
