This is a refactoring patch in Taylor Blau's ongoing repack refactoring series (tb/incremental-midx-part-3), specifically patch 35/49 in v2. The change is purely mechanical, reordering the `remove_redundant_bitmaps()` function in `builtin/repack.c` to eliminate a forward declaration that would be needed when the function is inlined into `write_midx_included_packs()` in the next commit.

The patch moves the function definition before its caller without modifying any behavior, maintaining all existing functionality around removing stale pack bitmaps when packs are included in a MIDX. The implementation remains unchanged - it still walks through included packs, constructs bitmap filenames by replacing `.idx` with `.bitmap`, and attempts to unlink them while gracefully handling ENOENT errors.

This continues the series' pattern of incremental code organization improvements, in this case preparing for tighter coupling between MIDX pack tracking and bitmap cleanup. The change is straightforward and low-risk, with no expected impact on runtime behavior. It follows the established style of the series and doesn't introduce any new technical debt or open questions.
