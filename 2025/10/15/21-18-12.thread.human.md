This thread covers a 9-part refactoring series modernizing the xdiff subsystem's data structures to improve Rust FFI compatibility, building on two previously merged cleanup efforts. The work carefully updates types across xdiff's core structures (xrecord_t and xdfile_t) while maintaining behavior.

The latest patch (fifth in the series) splits a dual-purpose hash field in xrecord_t into two distinct fields - `line_hash` for content hashing and `minimal_perfect_hash` for line comparison - improving clarity for the Rust FFI work. This follows earlier patches that converted pointer-relative offsets to ssize_t, changed char* to uint8_t* for binary data, updated size types, and standardized hash value types. Each change is carefully contained to maintain behavior across platforms while making the code more type-safe and explicit.

The series demonstrates an incremental approach, with each patch building on the last to prepare xdiff for future Rust integration. Key considerations throughout include performance impact on diff operations, platform-specific behavior with new integer types, and maintaining hash stability. The work continues established xdiff cleanup patterns while supporting the broader Rustification effort through precise, behavior-preserving type modernization.
