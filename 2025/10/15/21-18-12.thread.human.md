This thread documents a completed 9-part refactoring of Git's xdiff subsystem to modernize its data structures for Rust FFI compatibility, building on two earlier cleanup efforts. The work systematically updates core xdiff structures (xrecord_t and xdfile_t) with unambiguous types and clearer naming while maintaining behavior. Key changes include type safety updates (converting fields to ssize_t, uint8_t*, size_t), field separation (splitting ha into line_hash and minimal_perfect_hash), and naming improvements (rindex to reference_index).

Recent discussion has focused on implementation details, particularly around type choices. Phillip Wood raised concerns about the char* to uint8_t* conversion in patch 2/9, arguing that C's char already represents bytes. Junio Hamano responded that uint8_t ensures consistent signedness across the FFI boundary, though he agreed the Rust compatibility motivation should be more explicitly stated. This follows earlier exchanges where Phillip questioned the use of ssize_t (suggesting ptrdiff_t might be better for pointer offsets) and highlighted cast proliferation issues.

The modernization maintains core behavior while preparing for Rust interoperability, with memory usage concerns already quantified. Open questions remain about specific type choices (ssize_t vs ptrdiff_t, uint8_t* vs char*), how to address cast proliferation, and documenting these transitional tradeoffs. The thread shows the maintainer balancing type purity with practical considerations during this cross-language refactoring.
