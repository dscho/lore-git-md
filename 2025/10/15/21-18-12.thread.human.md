Ezekiel Newren continues his multi-part series refactoring Git's xdiff subsystem to prepare for Rust FFI compatibility. The latest addition is a comprehensive technical document (`unambiguous-types.adoc`) that precisely defines type mappings between C and Rust, addressing edge cases and platform-specific behaviors. This documentation patch (v4 01/10 in part 4 of the series) builds on earlier work that has already received maintainer approval.

The document covers boolean, integer, floating-point, size, and character types, highlighting subtle but important differences between the languages - such as Rust's evolving `c_*` type definitions across versions (1.63.0 vs 1.89.0) and the dangers of using Rust enums for FFI due to ABI instability. It serves as a reference for the ongoing xdiff modernization, where type safety is critical, and will likely be valuable for future FFI work in Git.

The series as a whole has seen active engagement from maintainers, with Junio Hamano validating the approach and Patrick Steinhardt and Phillip Wood providing FFI safety review. While the current patch is documentation, it supports the broader technical changes already in progress across the xdiff subsystem, including type safety improvements to core structures like `xrecord_t` and `xdfile_t`. The work remains behavior-preserving while establishing patterns for cross-language interoperability, with maintainers having accepted the tradeoffs (such as a 33% per-record memory increase from splitting the `ha` field). Future patches in the series will continue the type consistency work across xdiff.
