This thread focuses on a refactoring series for Git's xdiff subsystem, preparing its data structures for better Rust FFI compatibility. The series builds on two previously merged cleanup efforts (en/xdiff-cleanup and am/xdiff-hash-tweak) and makes mechanical but widespread changes to type declarations in core xdiff types like xrecord_t and xdfile_t.

The changes include converting char* to uint8_t* for binary safety, replacing ambiguous 'long' types with specific size_t/ssize_t/uint64_t, splitting the 'ha' hash field into separate components, and renaming 'rindex' to 'reference_index' for clarity. The author has structured the series carefully, with each commit focusing on one specific type change while maintaining backward compatibility. The changes touch nearly all xdiff source files (xdiffi.c, xprepare.c, xutils.c, etc.) with a balanced 109 lines added and removed.

The primary motivation is preparing for Rust FFI integration, continuing Git's ongoing effort to make core subsystems more type-safe and cross-platform compatible. Reviewers will likely examine the changes for any subtle performance impacts, particularly since xdiff is performance-critical diff infrastructure. The mechanical nature of the changes and their alignment with prior cleanup work suggests this should be a straightforward review, though the widespread nature of the changes warrants careful verification.
