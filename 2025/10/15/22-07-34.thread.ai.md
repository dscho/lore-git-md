Thread identity: Documentation patch proposing breaking change for Git 3.0 regarding `git diff X..Y` syntax, authored by Martin von Zweigbergk, with Junio C Hamano and brian m. carlson participating. Now includes discussion of potential future revset-like functionality.

Core problem: The current `git diff X..Y` syntax shows a two-dot diff (from X to Y) while appearing to suggest a range diff (from merge-base to Y). The proposal would remove this syntax to allow potential future reintroduction with more intuitive semantics matching `git diff $(git merge-base X Y) Y` or to enable revset-like functionality similar to Mercurial/jj.

Current status: Patch v1 added a note about planned removal for Git 3.0. Junio agreed with the principle but noted implementation incompleteness (missing `WITH_BREAKING_CHANGES` macro). Martin now clarifies the patch was meant to start discussion, not be final, and reveals additional motivation - preparing for hypothetical revset-like features. brian m. carlson maintains strong objections about backward compatibility impacts on existing scripts and forges.

Key technical details: Original patch modified Documentation/BreakingChanges.adoc with 4 lines explaining deprecation. Current discussion reveals the change would be the only breaking change needed to enable potential future revset-like functionality (though Martin isn't volunteering to implement this). Junio previously noted current behavior stems from reusing revision range parser rather than dedicated diff parser. brian m. carlson highlighted specific risks for distributions moving from Git 2.51 to 3.xx where syntax could disappear/reappear with different semantics.

Open questions: Should the change proceed at all given backward compatibility concerns? If proceeding, should be gated behind `WITH_BREAKING_CHANGES`? What are concrete impacts on existing scripts/documentation? How does potential future revset functionality affect the decision? The thread now has fundamental disagreement about whether Git can/should make this breaking change.
