This is part of Taylor Blau's ongoing refactoring series to eliminate `the_repository` usage in the repack code (tb/incremental-midx-part-3), specifically patch 3/49 in v2 of the series.

The patch modifies MIDX-related ref snapshotting functions to stop using the global `the_repository` variable, instead passing a repository` parameter through the call chain. Key changes include:
- Adding a `repo` member to `struct midx_snapshot_ref_data`
- Updating `midx_snapshot_ref_one()` to use the passed repository rather than `the_repository` for peeling objects and checking object types
- Modifying `midx_snapshot_refs()` to take a `repository` parameter and pass it through to helper functions
- Updating the call site in `cmd_repack()` to pass the repository parameter

The changes are mechanical in nature, following the pattern established in earlier patches of the series. The patch maintains identical behavior while removing global state dependencies, which is a core goal of both this series and the broader `the_repository` removal effort. The modifications affect MIDX bitmap generation during repacking operations, particularly around handling preferred ref tips and commit object verification.

This continues the systematic elimination of `the_repository` usage seen in patches 1/49 and 2/49, with similar straightforward conversions of existing code to use repository parameters. The changes are focused and well-contained, affecting only the ref snapshotting portion of the repack machinery.
