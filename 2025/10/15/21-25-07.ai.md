This is the second patch in a refactoring series cleaning up reference optimization code in Git's refs subsystem. Following the first patch's standardization of backend function names, this change removes now-obsolete code related to the old `pack_refs` interface that has been fully replaced by the newer `optimize` functionality.

The patch deletes several components: the `refs_pack_refs()` wrapper function in refs.c, its declaration in refs.h, and the `pack_refs_fn` typedef in refs-internal.h. It also updates documentation comments to consistently refer to `refs_optimize()` rather than the removed `pack_refs` terminology. The changes are mechanical and focused, touching only three files with straightforward deletions and comment updates.

This continues the series' goal of consolidating the refs optimization code paths by eliminating legacy artifacts from before the `optimize` callback was introduced. The patch maintains the same as the first - purely organizational with no behavior changes, building toward the eventual unification of optimization code paths across all ref backends. The changes appear well-scoped and non-controversial, following logically from the first patch's vtable modifications.
