This is part of Taylor Blau's ongoing refactoring series to eliminate global variables in the repack machinery, specifically targeting `the_hash_algo` in this patch. The change focuses on pack deletion safety checks during repacking operations.

The patch modifies `mark_packs_for_deletion_1()` to accept a `git_hash_algo` pointer parameter instead of relying on the global `the_hash_algo`. This function is responsible for isolating pack checksums to avoid accidentally deleting newly written packs that might coincidentally have the same checksum as existing packs. The hash algorithm is now passed down from `mark_packs_for_deletion()`, which gets it from the repository structure (`existing->repo->hash_algo`).

This continues the series' systematic approach to removing global state, following the same pattern seen in earlier patches where repository-specific parameters are threaded through function calls. The change is mechanical but important for maintaining the pack deletion safety check while eliminating global variable usage. The diff shows straightforward modifications to the function signature and call sites, with the core logic remaining unchanged.
