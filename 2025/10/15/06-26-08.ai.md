This is a v2 patch in the ongoing deprecation of `core.preferSymlinkRefs`, part of the effort to remove support for writing symbolic refs as symlinks (the original 2005 format) in favor of the modern "textual symref" format (introduced 2006). The patch adds warning messages when the deprecated feature is used and updates documentation to reflect the planned removal in Git 3.0.

The key changes from v1 include terminology updates (using "textual symref format" instead of just "symref format"), moving the warning message to after symlink creation to avoid interfering with error messages, and documentation tweaks based on Junio C Hamano's feedback. The technical implementation remains the same: using a static `warn_once` variable to emit the deprecation notice once per process, with behavior controlled by the WITH_BREAKING_CHANGES prerequisite in tests.

The patch modifies four files: BreakingChanges.adoc and config/core.adoc for documentation updates, files-backend.c for the warning implementation, and t0600-reffiles-backend.sh to test both current (with warnings) and future (without symlink support) behavior. The test changes verify proper warning output when symlinks are used and confirm correct fallback to textual symrefs when WITH_BREAKING_CHANGES is set.

The rationale remains unchanged - symlinks offer no current advantages, have incomplete platform support, and the community has had 20 years to migrate from the original symlink format. The patch maintains backward compatibility for reading symlinks while preparing users for the eventual removal of write support.
