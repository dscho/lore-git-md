This is patch 19/49 in Taylor Blau's repack refactoring series, continuing the modularization of `builtin/repack.c` by moving the 'existing_packs' API to dedicated repack.[ch] files. The patch completes the isolation of pack tracking functionality that was started in earlier patches.

The change relocates the entire 'existing_packs' infrastructure - including its struct definition, initialization macro, and all related functions - from builtin/repack.c to repack.[ch]. This API tracks pack states (kept/non-kept/cruft) during repack operations and handles pack deletion marking. The move follows the series' pattern of systematically extracting repack components into modular units.

Key technical aspects:
- The `existing_packs` struct and its string lists (kept_packs, non_kept_packs, cruft_packs) are moved verbatim
- All public API functions gain proper declarations in repack.h
- Some functions become static to repack.c since they're now internal implementation details
- The patch maintains all existing behavior while cleaning up the builtin's namespace
- Follows the series' naming conventions with `existing_packs_` prefix for collection operations

This continues the architectural restructuring from patches 15-18/49, further establishing clear module boundaries. The change is purely organizational - no functional changes are introduced. It builds on prior work that eliminated static variables and established the repack.[ch] infrastructure. The patch appears mechanically sound and well-integrated with the series' systematic approach.
