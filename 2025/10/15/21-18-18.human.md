This is part 6 of a 9-part refactoring series modernizing xdiff's data types for better Rust FFI compatibility. The patch changes the `nrec` field in `xdfile_t` from `long` to `size_t`, as it represents a count of in-memory records and thus should use the standard type for memory sizes.

The change requires careful casting at API boundaries where `long` is still expected, particularly in diff algorithms that use `nrec` for iteration and bounds checking. The patch updates all such call sites across xdiff's core files (xdiffi.c, xemit.c, xmerge.c, etc.) with explicit casts where needed. This maintains behavior while moving toward more precise type usage.

This continues the series' pattern of behavior-preserving type changes that prepare xdiff for Rust interoperability. The change is well-contained and follows the established approach of previous patches, though reviewers will want to verify the casting doesn't introduce any platform-specific issues with type sizes.
