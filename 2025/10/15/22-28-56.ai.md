Refactoring patch in Taylor Blau's repack modularization series (patch 33/49). This change replaces a manually managed array of MIDX pack names with a `string_list` structure, simplifying memory management and reducing parameter passing between functions.

The patch modifies how repack tracks pack names from existing MIDX files when determining which packs need to be preserved. Previously this used a raw array of char pointers with separate size tracking, requiring manual memory management and forcing functions to accept both the array and its length. The new version uses Git's `string_list` API, which handles allocation and cleanup automatically while providing a more convenient iteration interface.

Key changes:
- Replaces `char** midx_pack_names` and `size_t midx_pack_names_nr` with `struct string_list midx_pack_names`
- Updates `midx_has_unknown_packs()` and `midx_included_packs()` to take the string_list directly
- Simplifies memory management by removing explicit allocations/frees
- Uses `for_each_string_list_item` for iteration
- Maintains all existing functionality for MIDX pack tracking

This continues the series' pattern of replacing ad-hoc data structures with Git's standard utilities while reducing parameter passing between functions. The change is straightforward and well-contained, with no apparent behavior changes. It builds on the MIDX handling infrastructure introduced in earlier patches while making the code more maintainable.
