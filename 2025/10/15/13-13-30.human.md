This is patch 3/4 in Julia Evans' documentation series refining the `git-pull` man page. The patch removes a historical example that was causing confusion by implying `git pull` defaults to merge behavior, when in fact it defaults to `--ff-only`. 

The example showed a merge commit being created (commit H merging branches at C and G), which doesn't reflect the default fast-forward behavior. Evans notes that while they could replace it with a fast-forward example, such examples may not add much value since fast-forwards are straightforward operations. The removal helps streamline the documentation while avoiding potential confusion about default behavior.

This change aligns with the series' goal of making the documentation more accurate and pedagogically clear. It follows patch 2/4's clarification of integration options and precedes patch 4/4's updates to conflict resolution guidance. The removal is a sensible simplification, though some readers might miss having a concrete example - the tradeoff favors precision over illustration here.
