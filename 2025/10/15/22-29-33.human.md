This is a refactoring patch in Taylor Blau's ongoing series to modularize Git's repack machinery (part 46/49). The change moves the `pack_kept_objects` flag from being a static variable in `builtin/repack.c` into the `pack_objects_args` struct where it more logically belongs, since it controls pack-objects behavior.

The patch makes several coordinated changes to maintain the same behavior while cleaning up the code:
- Centralizes the `--honor-pack-keep` flag handling in `prepare_pack_objects()`
- Updates all three call sites that previously handled this flag directly
- Preserves the default behavior where the flag depends on bitmap/MIDX writing
- Explicitly sets the flag to 0 for cruft pack writing (which always wants to honor keep files)

This continues the series' pattern of moving repack functionality out of the builtin and into dedicated modules while eliminating global state. The changes are mechanical but thorough, updating all affected code paths consistently. The patch appears well-tested with no obvious edge cases missed - it's a straightforward improvement to the code organization that doesn't introduce new behavior.
