Refactoring patch in Taylor Blau's repack modularization series (patch 14/49). This continues the effort to move repack functionality out of `builtin/repack.c` into dedicated modules, specifically targeting the `prepare_pack_objects` function.

The patch relocates `prepare_pack_objects` from `builtin/repack.c` to `repack.c` and exposes it via `repack.h`, making it available as generic repack infrastructure. This is now possible because the function no longer depends on static variables (a dependency that was eliminated in earlier patches). The function's behavior remains unchanged - it still constructs the `pack-objects` command line arguments from a `pack_objects_args` struct, including all existing options like window size, depth, threads, delta handling flags, and the recently moved `delta_base_offset` setting.

Key technical details:
- Function signature remains identical (`struct child_process*`, `const struct pack_objects_args*`, `const char* out`)
- All argument processing logic is preserved exactly
- New declaration in `repack.h` includes necessary forward declaration of `struct child_process`
- Follows the pattern established in earlier patches of moving standalone repack functionality to dedicated compilation units
- Maintains the series' incremental approach by only moving code that no longer has static variable ties

This change is part of the broader architectural restructuring to support future MIDX/bitmap repacking functionality while systematically removing global variables. The patch appears mechanically sound, simply relocating already-refactored code to its logical home now that external dependencies have been eliminated.
