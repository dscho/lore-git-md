This is patch 21/49 in Taylor Blau's ongoing refactoring series to modularize Git's repack machinery. The patch factors out the pack installation logic from `cmd_repack()` into a new `generated_pack_install()` function.

The installation process handles moving newly created pack files from their temporary location to their final destination, which involves several steps: adjusting file permissions, checking for required extensions, and cleaning up unneeded files. This was previously inline code that's now extracted for better organization and in preparation for making it part of the repack API in a future change.

The change is mechanical - the new function contains the exact same logic that was previously inline, just moved to a dedicated function. This continues the series' pattern of breaking down the monolithic repack.c into more modular components. The patch follows the naming conventions established earlier in the series (patch 15/49) and maintains all existing behavior while improving code organization.

This is part of the broader effort to modernize Git's repack infrastructure by eliminating global variables and creating cleaner interfaces between components. The change appears well-contained and follows the established patterns from previous patches in the series.
