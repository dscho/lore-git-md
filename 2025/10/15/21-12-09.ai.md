This is a refactoring patch that improves NULL-safety in the ref-filter subsystem, part of the ongoing `git repo structure` series. The change makes the `name_patterns` field in `struct ref_filter` properly handle NULL values by treating them equivalently to empty arrays, which simplifies calling code that doesn't need pattern matching.

The patch modifies two key functions in ref-filter.c:
- `filter_pattern_match()` now checks for NULL `name_patterns` before dereferencing
- `for_each_fullref_in_pattern()` similarly handles NULL patterns as a no-op case

This is a small but meaningful interface improvement that makes the API more robust and consistent. The change is mechanical and focused, touching only 4 lines with straightforward logic. It follows the pattern established in earlier patches of the series (particularly patch 1/7 which established the command structure) and helps pave the way for the reference counting functionality introduced in patch 4/7.

The patch has already been reviewed and merged as part of the series, indicating it was uncontroversial. Its inclusion helps support the larger goal of providing repository structural analysis while maintaining clean API boundaries.
