This is patch 11/49 in Taylor Blau's incremental MIDX refactoring series (tb/incremental-midx-part-3), focusing on modularizing `builtin/repack.c`. The patch introduces a new compilation unit for repack functionality by moving `struct pack_objects_args` and its related cleanup function `pack_objects_args_release()` into new `repack.[ch]` files.

The change is a mechanical refactoring that:
1. Creates new `repack.c` and `repack.h` files
2. Moves the `pack_objects_args` struct definition to `repack.h`
3. Moves the cleanup function implementation to `repack.c`
4. Updates both Makefile and Meson build systems to include the new compilation unit
5. Maintains all existing functionality while reducing the size of `builtin/repack.c`

The patch follows the series' pattern of incrementally breaking down the monolithic repack.c into logical units, with this being the first step in what will be a multi-patch effort to properly modularize the repack functionality. The commit message explains this is preparatory work for future MIDX-related repack improvements, noting that some code movement will be non-trivial and thus done in careful steps.

Key technical details:
- The moved struct contains configuration for `git pack-objects` (window size, memory limits, threads, filter options etc.)
- The release function handles cleanup of dynamically allocated members
- Both build systems are updated in lockstep
- No behavior changes are introduced - this is purely code reorganization
- The change continues the series' focus on maintainability and separation of concerns

This patch builds on the hash algorithm parameterization work from earlier in the series (patches 1-10) while beginning the architectural restructuring that will enable the MIDX chain functionality planned for later in the series.
