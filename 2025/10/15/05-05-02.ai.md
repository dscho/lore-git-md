Documentation fix for `git replay` help text consistency.

This email from Siddharth Asthana addresses a documentation inconsistency in the `git replay` command that was caught by Junio Hamano. The issue stems from a mismatch between the command's `-h` output (single line) and its `--help` documentation (split across two lines for readability). This breaks the t0450 test which verifies consistency between these two help formats.

The problem was initially noticed in CI testing but misdiagnosed as an AsciiDoc line continuation issue. Christian Couder correctly identified the real cause as the synopsis/help output mismatch. Junio provided a minimal fix to align the usage string in `builtin/replay.c` by adding a newline and proper indentation to match the two-line format used in the documentation.

Siddharth acknowledges this should have been caught earlier by running t0450 locally after Christian's hint, and plans to squash the fix into the next version of the patch series. The change is straightforward - modifying the usage string in `builtin/replay.c` to use consistent formatting with the documentation. This is the final polish needed for the otherwise complete atomic ref updates series.

Key technical details: The fix involves the `replay_usage` string in `builtin/replay.c`, specifically adding `\n` and `\t\t` to match the documentation's two-line format. The test failure occurs in t0450-txt-doc-vs-help.sh which verifies help text consistency. This is purely a documentation formatting issue that doesn't affect the command's functionality or the core atomic ref updates feature.
