This is a deprecation notice and bugfix for the `core.preferSymlinkRefs` configuration, part of the ongoing effort to remove support for storing symbolic refs as symlinks (the original 2005 format) in favor of the modern "textual symref" format (introduced in 2006).

Patrick Steinhardt's v2 patch finalizes the deprecation path after incorporating feedback from Junio Hamano. The changes now emit a clear warning when symlinks are used, update documentation in both config.txt and BreakingChanges.adoc, and modify tests to handle both current and future behavior. The implementation uses a static `warn_once` variable to ensure users see the deprecation message exactly once per process.

The patch maintains backward compatibility by continuing to support reading symlinks while only deprecating their creation. The rationale remains strong - symlinks offer no advantages over text files after 20 years of migration, and some platforms don't support them well. The changes are well-tested with new assertions verifying both warning messages and proper file creation under the new behavior.

This appears ready for inclusion, with careful attention paid to user messaging and a clear migration path (the warning includes exact commands to disable the deprecated feature). The changes align with Git's policy of giving ample notice for backward-incompatible changes, with removal slated for Git 3.0.
