This thread discusses a proposal to remove Git's potentially confusing `git diff X..Y` syntax in preparation for Git 3.0. Martin von Zweigbergk originally suggested the change to eliminate the current behavior where double-dot notation shows a two-dot diff rather than the range diff that users might expect. He later revealed an additional motivation: clearing the way for potential future revset-like functionality similar to Mercurial or Jujutsu (jj).

Junio Hamano agreed with the principle but noted the initial patch was incomplete, while brian m. carlson strongly objected due to backward compatibility concerns, particularly for scripts and forges that might rely on the current behavior. The discussion has now expanded with Justin Tobler's contribution, which supports removing the double-dot syntax but goes further to suggest also removing the triple-dot notation (`A...B`) for consistency. Justin provides concrete examples of alternative syntax that could replace both notations.

The core disagreement remains unresolved: Martin and Justin see value in cleaning up confusing syntax (with Justin expanding the scope of proposed changes), while brian maintains that the compatibility risks outweigh any benefits. The thread has evolved from discussing implementation details to a more fundamental debate about whether Git should make this breaking change at all, even in a major version bump. The potential future revset functionality Martin mentioned remains hypothetical, with no concrete plans for implementation yet.
