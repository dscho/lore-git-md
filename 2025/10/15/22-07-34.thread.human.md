This thread discusses a proposed breaking change for Git 3.0 regarding potentially confusing `git diff` syntax. Martin von Zweigbergk originally suggested removing the `X..Y` notation, which currently shows a two-dot diff despite looking like it should show a range. Justin Tobler expanded this to include the `X...Y` notation, noting both could be confused with revision range syntax. While Martin agrees with the expanded scope, he highlights practical challenges in finding alternative syntax that avoids shell escaping issues.

Junio C Hamano has emphasized implementation constraints, particularly how `X...Y` is used in commands like `git checkout` for fork points. brian m. carlson strongly opposes the change due to compatibility concerns, while Kristoffer Haugsbakk has suggested a more gradual deprecation approach, citing Git's historical patterns. The latest contribution from D. Ben Knoble supports removing the double-dot notation while noting that his own work on implementing revset-like "::" syntax wouldn't be blocked by this change. The discussion continues to weigh syntax cleanup against compatibility concerns, with participants considering whether Git 3.0 should include immediate removal or a more gradual deprecation path.
