This thread discusses a proposal to remove potentially confusing `X..Y` and `X...Y` syntax from `git diff` in Git 3.0, originally suggested by Martin von Zweigbergk. The double-dot notation currently shows a two-dot diff despite appearing to suggest range semantics, while the triple-dot notation has merge-base behavior that can be confusing. Justin Tobler expanded the proposal to include both notations, suggesting alternative syntaxes that would be clearer.

The discussion has revealed several challenges. Junio Hamano notes that these notations are used consistently across multiple Git commands (like `git checkout` for fork points), so any changes would need to be coordinated. brian m. carlson strongly opposes due to compatibility concerns. Testing has shown some unexpected behavior - while Kristoffer Haugsbakk found that `git checkout X...` works, Martin later clarified that it fails in edge cases with ambiguous merge bases, producing different error messages. This highlights the complexity of the current implementation.

Martin maintains that both notations should be considered for removal, though he acknowledges the practical challenges in finding alternative syntax that works within shell escaping constraints. The thread remains unresolved, balancing the desire for clearer syntax against backward compatibility and the need for consistent behavior across commands. Junio has emphasized that any changes would need to maintain stable meaning once introduced, and that removing `X...Y` would require introducing alternative fork-point syntax first.
