This thread discusses a proposed breaking change for Git 3.0 that would remove the potentially confusing `X..Y` and `X...Y` syntax from `git diff`, where they currently behave differently than in revision ranges. Martin von Zweigbergk initiated the discussion, noting these forms might be better reserved for future revset-like functionality. Justin Tobler expanded the proposal to include triple-dot notation, providing concrete alternatives for both cases.

Junio Hamano has expressed agreement with the motivation but raised practical concerns - he points out that removing `X...Y` would require introducing alternative syntax first, as it's used consistently across commands like `git checkout` to find fork points. brian m. carlson remains strongly opposed due to compatibility risks, arguing Git may be effectively locked into the current behavior. The discussion has revealed deeper questions about how far Git can go in cleaning up legacy behaviors for 3.0, with Junio's latest response emphasizing the need to consider these syntax patterns holistically across all commands that use them. The path forward remains unclear, balancing the desire for cleaner semantics against real-world usage and the principle of backward compatibility.
