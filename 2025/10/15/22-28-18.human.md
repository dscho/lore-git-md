This is a refactoring patch in Taylor Blau's ongoing series to modularize Git's repack machinery. It renames `struct generated_pack_data` to the simpler `struct generated_pack` and updates related function names to follow Git's naming conventions. The change makes the code more readable by eliminating redundant "data" references in names while maintaining the same functionality.

The patch is part of a larger effort (patch 20/49 in v2) to systematically clean up repack.c by establishing consistent naming patterns and moving code to dedicated modules. This particular change focuses on the temporary pack file handling infrastructure, making the API more intuitive with names like `generated_pack_populate()` and `generated_pack_has_ext()`.

The changes are mechanical and well-contained, touching only builtin/repack.c with straightforward renames. The patch follows the series' pattern of incremental improvements that don't change behavior while making the code more maintainable. It builds on previous patches that established subsystem naming conventions and continues the systematic elimination of awkward naming patterns.
