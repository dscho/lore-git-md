This is the first patch in Julia Evans' v3 documentation series refining the `git-pull` man page. The patch focuses on restructuring parameter documentation to improve clarity.

The key change moves the descriptions of `<repository>` and `<refspec>` parameters from the DESCRIPTION section to the OPTIONS section, separating parameter documentation from the high-level behavior explanation. This addresses user confusion about inconsistent terminology (`<branch>` vs `<refspec>`) and unclear examples. The patch introduces more precise definitions, using "upstream" terminology that's more familiar to users than the technical "remote and merge configuration" phrasing.

Technical details include:
- Adds new `<repository>` and `<refspec>` entries in OPTIONS with cross-references to related sections
- Introduces `[[DEFAULT-BEHAVIOUR]]` anchor for linking
- Adds `[[fetch-refspec]]` anchor in `pull-fetch-param.adoc`
- Maintains all existing functionality while improving organization
- Part of broader effort to clarify `git-pull`'s complex parameter passing

The changes are purely documentation restructuring with no behavior impact. This continues the series' focus on pedagogical clarity while incorporating prior technical accuracy feedback. The patch maintains all cross-references needed for the pending UPSTREAM BRANCHES documentation series that must land first to resolve test failures.
