This is the fourth patch in a 9-part refactoring series modernizing xdiff's type system for better Rust FFI compatibility. The patch focuses on type safety in the diff hashing subsystem, converting several key functions to use more precise integer types.

The main changes convert hash-related functions from using `unsigned long` to `uint64_t` for hash values and `char*` to `uint8_t*` for binary data pointers. This affects core hashing functions like `xdl_hash_record_verbatim()` and `xdl_hash_record_with_whitespace()`, along with their callers. The patch also converts some boolean flags from `int` to `bool` where appropriate.

Key technical details include:
- Hash accumulator variables now explicitly use `uint64_t` instead of `unsigned long`
- Pointer parameters changed from `char const**` to `uint8_t const**` for binary data handling
- Whitespace handling flags converted from `long` to `uint64_t` in function signatures
- Internal boolean state tracking (like `cr_at_eol_only`) now uses `bool` type
- Maintains all existing hash calculation logic while just changing the types

The changes span xdiff's core hashing infrastructure in xutils.c/h and propagate to callers in xprepare.c and xdiff-interface.c. This continues the series' pattern of precise type modernization while preserving behavior, with particular attention to maintaining hash stability across the type changes. The patch includes careful casting where needed at API boundaries to maintain compatibility with surrounding code that hasn't yet been updated.
