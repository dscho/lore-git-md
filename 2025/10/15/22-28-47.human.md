This is patch 30/49 in Taylor Blau's ongoing refactoring series to modularize Git's repack machinery, part of the effort to eliminate global variables like `the_repository`. The patch moves the pack geometry API - which handles geometric progression calculations for packfiles - out of `builtin/repack.c` and into its own dedicated files (`repack-geometry.c` and `repack.h`).

The change is purely structural - no behavior is modified. The patch extracts all pack geometry related functions and data structures, including the core logic for determining which packs to combine based on their sizes and the geometric progression factor. This continues the series' pattern of breaking down the monolithic repack implementation into focused components with clear interfaces.

The implementation is thorough, with all geometry-related code cleanly moved and properly exposed via the repack.h header. This is another incremental but meaningful step toward the series' goal of a fully modular repack architecture. The change follows the established pattern from earlier patches in the series and appears ready for inclusion.
