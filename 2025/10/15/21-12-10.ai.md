This is patch 4/7 in the `git repo structure` series, implementing the reference counting functionality for the new subcommand. The patch introduces the core infrastructure for analyzing repository structure by categorizing and counting references (branches, tags, remotes, and others).

The implementation centers around two main data structures: `struct ref_stats` for storing counts by reference type, and `struct stats_table` for formatting the output. The code uses existing ref-filter APIs to categorize references and implements dynamic column width adjustment using `utf8_strwidth()` for proper table formatting. The output mimics git-sizer(1)'s style with a two-column table showing reference categories and counts.

Key technical components include:
- `cmd_repo_structure()` as the subcommand entry point
- `structure_count_references()` to categorize references using `FILTER_REFS_*` types
- Table formatting helpers (`stats_table_*` functions) with i18n support
- Comprehensive tests in t1901-repo-structure.sh covering empty repos and repos with multiple reference types

The patch builds on the earlier merged patches (1-3) that established the subcommand naming convention and improved ref-filter NULL-safety. It represents the first user-visible functionality in the series, though the commit notes this is just the initial version - subsequent patches will add object counting and machine-readable output formats.

The implementation appears thorough with attention to detail in both functionality (proper reference categorization) and presentation (dynamic column widths, i18n). Test coverage is comprehensive, verifying both empty repository cases and repositories with multiple reference types. The use of existing ref-filter APIs rather than reimplementing reference walking suggests good architectural decisions.
