This is a refactoring series focused on cleaning up code related to reference optimization in Git's refs subsystem. The patches follow up on recent work that introduced `git refs optimize` functionality (merged in db0babf9b2) by unifying the code paths between the older `pack-refs` and newer `optimize` operations.

The series consists of 4 patches that:
1. Transition the refs subsystem to consistently use `.optimize` function naming
2. Clean up surrounding optimization-related code
3. Rename `pack_refs_opts` to the more accurate `refs_optimize_opts`
4. Adjust test infrastructure by moving `test_done` calls to test scripts

The changes touch multiple refs backend implementations (files, packed, reftable) and their headers, plus several test scripts. The author notes this was extracted from a larger series that took a different direction, but believes these cleanup patches stand on their own merit.

Key technical details:
- Removes duplicate code paths between pack-refs and optimize operations
- Standardizes on "optimize" terminology throughout the codebase
- Updates function signatures and struct names to match
- Maintains test coverage while adjusting test organization

The changes appear focused and mechanical, with no performance impact claimed - this is purely a code organization improvement. The series builds on recent work (db0babf9b2) and is based on master plus the 'ps/ref-peeled-tags' branch.
