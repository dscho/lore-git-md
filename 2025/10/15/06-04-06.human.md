This is part 2 of Patrick Steinhardt's Rust CI infrastructure series (v3, 6 patches), focusing on adding Rust code formatting checks to Git's CI pipelines. The patch introduces `rustfmt` validation through new CI jobs in both GitHub Actions and GitLab CI, ensuring Rust code follows the ecosystem's standard formatting conventions.

The implementation installs Rust tooling via `rustup` and uses `cargo fmt` to verify formatting against the edition specified in Cargo.toml. The author notes this deliberately avoids Git's typical `set -e` error handling pattern to allow future checks to run independently. The formatting follows Rust community defaults rather than Git's 80-column standard, a decision already approved in earlier thread discussion.

This is a straightforward technical addition that implements previously agreed-upon Rust infrastructure policies. The changes are cleanly scoped to CI configuration files and a new check script, with no impact on core Git functionality. As part of the mature v3 series, this patch appears ready for merging with the rest of the Rust CI work.
