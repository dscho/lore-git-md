This is a follow-up in the ongoing discussion about removing the potentially misleading `git diff X..Y` syntax in Git 3.0. Martin von Zweigbergk responds to Junio C Hamano's feedback on the initial proposal.

Martin acknowledges Junio's explanation about the historical reason for the current behavior (reusing the revision range parser) and shares additional motivation: clearing the way for potential future "revsets" functionality similar to Mercurial/jj, though he clarifies he's not volunteering to implement that. He notes this syntax appears to be the only breaking change needed for such a feature.

The email confirms the original patch was intended as a discussion starter rather than a final implementation. Martin expresses willingness to add the `WITH_BREAKING_CHANGES` macro protection in a v2 if the community agrees to proceed, showing responsiveness to Junio's technical feedback.

The thread has now evolved from the initial proposal into a deeper discussion about both the implementation approach and whether the change should happen at all, given brian m. carlson's strong objections about backward compatibility. Martin's response maintains the original motivation while engaging with the technical realities raised by maintainers.
