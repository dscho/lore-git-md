This is patch 24/49 in Taylor Blau's ongoing repack refactoring series (tb/incremental-midx-part-3), continuing the modularization of `builtin/repack.c` by moving the 'generated_pack' API to dedicated repack.[ch] files.

The patch completes the relocation of the generated pack handling infrastructure that was started in earlier patches (20-23/49). It moves three key functions and their supporting data structures from `builtin/repack.c` to `repack.c`:
- `generated_pack_populate()` - initializes pack metadata
- `generated_pack_has_ext()` - checks for pack extensions
- `generated_pack_install()` - handles final pack installation

The implementation remains functionally identical to its previous version in builtin/repack.c, with only mechanical changes needed for the relocation:
- Added necessary includes` for path.h and tempfile.h in repack.c
- Updated loop counters from `int` to `size_t` for consistency with the series' type safety improvements
- Added declarations to repack.h to expose the API to other compilation units

This continues the series' systematic approach of:
1. Extracting functionality from builtin/repack.c
2. Moving it to dedicated repack.[ch] files
3. Maintaining identical behavior while improving modularity
4. Following established naming conventions (generated_pack_ prefix)

The change further reduces builtin/repack.c's size (83 lines removed) while centralizing pack-related functionality in the repack module. This is part of the broader effort to eliminate static variables and create clean interfaces for the repack machinery.
