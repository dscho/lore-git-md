This is a user-facing documentation/UX issue regarding the deprecation warning for `git whatchanged`. Greg Couch points out that the current deprecation message suggests using `--i-still-use-this` flag and emailing the Git list, which they find unnecessarily cumbersome. They propose simply recommending `git log` as the alternative instead.

The email is brief and to the point, clearly identifying a real usability pain point in Git's deprecation messaging. While the tone is somewhat terse ("unappreciated"), the core suggestion is reasonable - deprecation warnings should guide users toward the recommended alternative rather than making them jump through hoops to continue using deprecated functionality. This appears to be a straightforward documentation fix that would improve user experience without any technical tradeoffs.
