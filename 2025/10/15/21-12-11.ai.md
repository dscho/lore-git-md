This is the 4th patch in a 6-part series introducing the `git repo structure` command, focusing on adding object counting functionality to complement the existing reference counting. The patch implements reachable object traversal and categorization by type (commits, trees, blobs, tags) using the path-walk API, presenting the results alongside reference counts in the structured output table.

Key technical additions include:
- New `struct object_stats` to track counts by object type
- `struct repo_structure` combining both reference and object metrics
- `count_objects()` callback for path-walk API to increment type counters
- `structure_count_objects()` using revision walking to process all refs
- Updated table formatting to include object statistics
- Expanded test coverage with object count assertions

The implementation builds on the ref-filter infrastructure from earlier patches, using `FILTER_REFS_*` types to determine which references to traverse. Object counting happens via the path-walk API with a callback that increments counters based on object type. The output format follows the same table style as the reference counting, now with an additional section showing object breakdowns.

Test coverage is thorough, verifying both empty repository cases and repositories with commits/tags/notes. The test counts are precise (expecting 130 total objects from 42 bulk test commits plus tags/notes), demonstrating careful validation of the counting logic. The implementation appears robust, with proper initialization/cleanup of revision walking and path-walk resources.

This patch completes the core functionality of the command by adding the object analysis component, leaving only output formatting (patch 6/6) and progress reporting (7/7) as remaining features in the series. The implementation quality is high, with clear separation of concerns between reference and object counting subsystems.
