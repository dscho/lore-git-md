Refactoring patch in Taylor Blau's incremental MIDX repack series (37/49), focusing on interface simplification for MIDX pack handling.

This patch continues the series' systematic refactoring of `builtin/repack.c` by consolidating parameters passed to `midx_included_packs()` into a single `repack_write_midx_opts` struct. The key changes are:
1. Adding an `existing` field to `repack_write_midx_opts` to track pack sets
2. Converting `midx_included_packs()` to take the struct pointer rather than individual parameters
3. Updating all callers (currently just `cmd_repack()`) to use the new interface

The change serves two purposes: reducing parameter passing complexity and preparing to inline `midx_included_packs()` into `write_midx_included_packs()`, which would further simplify the caller interface. The patch maintains all existing functionality while making the code more maintainable - it properly handles the `midx_must_contain_cruft` flag and unknown pack detection through the new struct-based approach.

This is part of the broader effort to modularize repack functionality and remove direct dependencies on global state. The change fits naturally with the series' established pattern of methodical interface improvements while preserving behavior. No functional changes are introduced - this is purely an internal refactoring that builds on previous patches' work to establish clear module boundaries and type-safe interfaces.
