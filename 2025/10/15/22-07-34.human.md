This is a documentation patch proposing a breaking change for Git 3.0. Martin von Zweigbergk suggests removing support for the `git diff X..Y` syntax, which currently shows the diff from X to Y but is often misunderstood as showing the range between X and Y. The patch adds a note to BreakingChanges.adoc stating the syntax will be removed, recommending users switch to `git diff X Y` instead.

The rationale is that the current behavior is confusing and could be replaced in the future with a more intuitive interpretation (showing changes from the merge base to Y). The commit references three past discussions about this syntax's confusing nature. The change is straightforward, just documentation at this stage, but would be a noticeable syntax change for users accustomed to the current behavior.
