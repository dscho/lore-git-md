This is a follow-up in the thread about simplifying the `git whatchanged` deprecation message. Kristoffer Haugsbakk notes that the current deprecation behavior (which Greg Couch had complained about as being unnecessarily cumbersome) will be included in the upcoming Git 2.51.1 release. 

The email serves as a heads-up that the existing behavior is about to reach more users via the imminent point release. This suggests the timing may be good for considering Greg's proposed change to make the deprecation message more user-friendly by directly recommending `git log` as the alternative, rather than requiring users to use a special flag and email the list.

No technical changes are proposed in this email - it's primarily an informational update about the release status of the current implementation. The thread remains open for discussion about whether to modify the deprecation warning text.
