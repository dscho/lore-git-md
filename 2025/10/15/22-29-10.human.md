This is part 38/49 of Taylor Blau's refactoring series for the repack machinery, focusing on MIDX (multi-pack index) handling. The patch simplifies the interface for writing MIDX files by moving the pack selection logic directly into `write_midx_included_packs()` rather than having it computed separately in the caller.

The change eliminates an awkward separation where `midx_included_packs()` would first compute which packs should be in the MIDX, then pass that list to `write_midx_included_packs()`. Now the writing function handles both steps itself, which better prepares the codebase for future extensions like incremental MIDX writing. The pack list is now a local variable rather than being passed through the options struct.

This is a clean, focused change that follows the series' pattern of improving modularity while maintaining existing behavior. It removes some boilerplate from the calling code in `cmd_repack()` and makes the MIDX-writing logic more self-contained. The patch appears well-considered as part of the larger refactoring effort, with no obvious drawbacks to the new approach.
