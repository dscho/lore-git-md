This is patch 30/49 in Taylor Blau's ongoing refactoring series to modularize Git's repack machinery (tb/incremental-midx-part-3). The patch continues the systematic extraction of repack components into dedicated compilation units, this time focusing on the pack geometry functionality.

The patch moves all pack geometry code from `builtin/repack.c` to new files `repack-geometry.c` and `repack.h`. The pack geometry API handles geometric progression calculations for packfiles during repacking, including:
- Initializing and sorting pack geometry based on pack weights
- Determining split points for geometric repacking
- Identifying preferred packs
- Removing redundant packs below the split line

Key technical details:
- The `struct pack_geometry` and all related functions are moved verbatim
- The implementation now lives in its own compilation unit (`repack-geometry.o`)
- The API is declared in `repack.h` alongside other repack components
- Build systems (Makefile and meson) are updated to include the new source file
- Follows the series pattern of making dependencies explicit at API boundaries

This continues the series' architectural restructuring while maintaining behavior, preparing for future incremental MIDX/bitmap repacking functionality. The change is part of the broader effort to eliminate global variables and create clean module boundaries in the repack code.
