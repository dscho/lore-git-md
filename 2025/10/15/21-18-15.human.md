Refactoring patch in the xdiff type modernization series. This is patch 3/9 in a set preparing xdiff data structures for better Rust FFI compatibility by making type choices more explicit and platform-independent.

The change converts the `size` field in `xrecord_t` from `long` to `size_t`, which is more appropriate for representing memory sizes. This affects several xdiff files (xdiffi.c, xemit.c, xmerge.c, xprepare.c) where the field is used for buffer length calculations and memory operations. The patch adds explicit `(long)` casts at API boundaries where existing functions still expect `long` parameters, maintaining backward compatibility while modernizing the internal representation.

The change is straightforward and well-contained, following the series' pattern of incremental, behavior-preserving type updates. It continues the effort to make xdiff's data structures more type-safe and cross-platform compatible, which will help with future Rust integration. The patch touches core diff functionality but shouldn't affect behavior since `size_t` and `long` are equivalent for the range of values Git handles.
