Refactoring patch standardizing ref backend optimization functions.

This is the first of a 4-part series cleaning up reference optimization code across Git's ref backends, following the recent `git refs optimize` functionality. The patch focuses on unifying the function naming by removing redundant `pack_refs` implementations in favor of the more general `optimize` callback across all backends (files, packed, reftable, and debug). The changes are mechanical - each backend's `pack_refs` function is either renamed to `optimize` or removed where it was just a wrapper calling `optimize`. 

The patch touches four key ref backend implementation files (debug.c, files-backend.c, packed-backend.c, reftable-backend.c), modifying their vtable structures to only expose the `optimize` operation. The commit message notes this is preparation for a subsequent patch that will fully consolidate the optimization code paths. No behavior changes are introduced - this is purely about code organization and naming consistency.

The changes appear straightforward and well-contained, with each backend following the same pattern of either renaming or removing the `pack_refs` function. The series builds on Patrick Steinhardt's prior optimization work and seems like a logical next step for cleaning up the refs subsystem's internal APIs. Since this is part of a larger refactoring effort, the real impact will become clearer as the series progresses, but this initial step looks like a clean, focused technical debt reduction.
