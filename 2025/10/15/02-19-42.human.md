This is a refactoring patch from an Outreachy participant, part of a series to simplify GPG/SSH key fingerprint parsing code. The change replaces `strbuf_split_max()` with `string_list_split()` in `get_ssh_key_fingerprint()`, since the code only needs to store and access the split tokens rather than modify them.

The patch focuses on SSH key fingerprint extraction, where the code parses output from `ssh-keygen`. The author notes the subtle difference in how the two splitting functions count tokens (`strbuf_split_max` takes desired token count while `string_list_split` takes split count), adjusting the parameter from 3 to 2 to maintain the same behavior.

This appears to be a straightforward quality improvement, reducing code complexity by using a more appropriate API for read-only token storage. The change is localized to GPG interface code and maintains the same functionality while being slightly more efficient (no need for strbuf` overhead when simple string storage suffices).
