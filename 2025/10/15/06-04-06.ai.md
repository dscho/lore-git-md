This is the second patch in Patrick Steinhardt's v3 series introducing Rust CI infrastructure, focusing specifically on enforcing Rust code formatting standards. The patch adds CI jobs to verify Rust code formatting using `cargo fmt` (rustfmt) on both GitHub Actions and GitLab CI platforms.

Key technical details:
- Adds new "rust-analysis" jobs to both CI systems that install Rust toolchain and run formatting checks
- Uses rustfmt's default style (derived from Cargo.toml's edition) for consistency with Rust ecosystem norms
- Includes manual error handling (not using `set -e`) to allow future checks to run even if formatting fails
- Installs rustup and rustfmt components via apt-get in the dependency installation script
- Files modified:
  - .github/workflows/main.yml (GitHub Actions config)
  - .gitlab-ci.yml (GitLab CI config)
  - ci/install-dependencies.sh (tool installation)
  - ci/run-rust-checks.sh (new formatting check script)

The implementation follows the thread's established consensus on accepting Rust's 100-character line length standard while maintaining Git's 80-column default for non-Rust code. This patch represents a straightforward application of the formatting policy decisions already approved in the thread, with the unusual error handling approach explicitly documented as intentional for future extensibility. The changes are focused and well-contained, building on the series' foundation of balancing Git conventions with Rust ecosystem standards.
