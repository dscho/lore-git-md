This is part 1/4 of Julia Evans' v3 documentation series improving the `git-pull` man page. The patch focuses on restructuring how repository and refspec parameters are documented, moving them from the DESCRIPTION section to the OPTIONS section for better organization.

The changes address user feedback about confusion between "branch" and "refspec" terminology, and clarify what refspec examples like `refs/heads/*:refs/remotes/origin/*` represent. The patch simplifies the DESCRIPTION section to focus on pull's high-level behavior (fetch + merge/rebase) while moving detailed parameter documentation to the OPTIONS section.

Key improvements include:
- Using "upstream" terminology instead of "remote and merge configuration" for better user familiarity
- Adding cross-references to other documentation sections
- Better separating concerns between parameter documentation and integration behavior
- Maintaining all technical accuracy while improving pedagogical flow

This continues the series' trend of thoughtful documentation restructuring that balances technical precision with user accessibility. The changes appear well-considered and build on previous feedback from maintainers.
