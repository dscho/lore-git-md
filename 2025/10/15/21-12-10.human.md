This is patch 4/7 in the `git repo structure` series, introducing the core reference counting functionality for the new subcommand. The patch adds a `git repo structure` command that analyzes and displays counts of different reference types (branches, tags, remotes, and others) in a human-readable table format.

The implementation includes:
- A `ref_stats` struct to track counts by reference type
- A `stats_table` system for formatting the output with dynamic column widths
- Integration with Git's existing ref-filter API to categorize references
- Comprehensive tests verifying output for both empty repositories and those with various reference types

The output format resembles git-sizer's table style, with automatic column width adjustment and proper i18n support. The command currently focuses only on reference counting, but the commit message notes this is just the first step toward broader repository structure analysis functionality.

This appears to be a well-constructed patch with thorough test coverage. It builds on the earlier preparatory patches in the series (the NULL-pattern safety improvements and naming conventions) while leaving room for future expansion (object counting and machine-readable formats come in later patches). The implementation carefully handles edge cases like empty repositories and properly integrates with Git's existing ref-filter infrastructure.
