This thread discusses user perspective on the potential deprecation of `git whatchanged`, a command that some find more intuitive than the equivalent `git log` options despite being functionally redundant. Benjamin Root started the conversation by expressing appreciation for `git whatchanged`'s verb-based interface in response to what appears to be deprecation warnings in Git 2.51.0.

Kristoffer Haugsbakk followed up with information about Git 2.51.1 allowing users to create aliases with the same name as built-in commands, providing a migration path for those who want to keep using the `whatchanged` interface. While this suggests the maintainers are moving toward deprecation, they're also trying to preserve compatibility. The email also mentions an unrelated regression in 2.51.1 that will be fixed in 2.51.2. The discussion highlights how the project balances technical evolution with user experience considerations, particularly for long-standing commands with dedicated users.
