Refactoring patch in the `--trailer` rebase series, moving trailer validation logic to shared location.

This patch relocates the `validate_trailer_args_after_config()` function from `builtin/rebase.c` to `trailer.c` as part of the ongoing effort to centralize trailer handling logic. The key change is that validation now properly respects configured trailer separators by using the existing `find_separator()` function rather than hardcoding `:=` as valid separators. This makes the validation consistent with other trailer processing in the codebase.

The implementation maintains the same error cases (empty trailers and missing keys) but now checks against the full set of configured separators. The function signature remains unchanged, continuing to use direct `die()` calls for validation failures as established in earlier patches. A new `#include "strvec.h"` is added to `trailer.c` to support the parameter type.

This appears to be a straightforward consolidation of functionality that improves consistency of trailer handling while reducing code duplication. The change fits naturally with the series' goal of moving trailer processing into core Git functionality. No behavioral changes are expected since the validation rules remain the same - just implemented more robustly by reusing existing trailer infrastructure.
