Performance optimization for `git last-modified` command, addressing signed/unsigned comparison warnings.

Taylor Blau responds to Junio Hamano's findings about signed/unsigned comparison issues in the `path_idx()` function, which returns `size_t` but tried to use `-1` for error signaling. The thread had previously established this as a true positive compiler warning under `DEVELOPER=1` mode. 

Blau notes GitHub's internal version (`diff2idx()`) uses `int` instead, but proposes a more robust solution: eliminating the exposed path-to-index mapping entirely by inlining the logic into a new `last_modified_mark_non_treesame()` function. The suggested change combines the path lookup, bitmap check, and update operations, avoiding the problematic intermediate index value. This builds on Hamano's earlier recommendation to use `(size_t)-1` for error cases while addressing the root cause through better encapsulation.

The patch demonstrates ongoing refinement of the performance-critical bitmap handling in the `last-modified` command, where earlier rounds had optimized the EWAH bitmap storage and parent commit processing. This change continues the pattern of simplifying the interface while maintaining the algorithmic improvements that showed 7.9x-111.7x speedups on linux.git. The discussion remains focused on type safety and clean abstraction boundaries rather than core algorithm changes.
