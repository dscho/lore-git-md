This is a refinement to the ongoing bugfix for the `git diff --quiet` regression. Junio Hamano is reviewing the proposed solution that redirects diff output to `/dev/null` when checking for changes under `--quiet` mode, which broke in v2.51.1.

The patch moves the `/dev/null` redirection and related state management into the `diff_flush_patch_quietly()` helper function, where it properly saves and restores the diff options (including file handle and color_moved settings) around the quiet check. This addresses Lidong Yan's concern about state restoration while maintaining the fix's core approach.

Junio expresses some reservations about the solution's elegance, noting it performs redundant `/dev/null` setups for multi-file diffs and questions whether other diff options (like word-diff) should also be disabled during quiet checks. However, the current implementation focuses on correctness first, with potential optimizations left for future consideration.

The change simplifies the caller in `diff_flush()` while making the quiet-check helper more self-contained. This appears to be the final refinement before the fix is accepted, with Junio actively evaluating the state management approach.
