Feature patch in the `git rebase --trailer` series, focusing on persistence of trailer options during rebase restarts.

This patch addresses an issue where rebase would lose trailer arguments (specified via `--trailer`) when resuming after conflicts. The problem occurred because each `--continue` created fresh `replay_opts` without preserving the original trailer arguments. The solution serializes these options into `rebase-merge/trailer` so subsequent runs can reload them.

Key technical changes:
- Adds new `rebase_path_trailer()` function to track the trailer state file
- Modifies `read_populate_opts()` to read and parse saved trailers from the state file
- Updates `write_basic_state()` to serialize active trailer arguments into the state file
- Uses `strvec_push()` to reconstruct the trailer arguments when reloading
- Maintains the trailer state through the same file-based persistence mechanism used for other rebase options

The implementation follows the pattern of other rebase state persistence, using the existing `rebase-merge` directory for storage. The trailer arguments are stored one per line in the state file, with empty lines skipped during reload. This matches the behavior seen in other parts of the rebase state machinery.

This change is part of the larger trailer integration effort that has been through multiple review iterations, with previous patches establishing the core trailer handling infrastructure. The persistence mechanism ensures the user's original trailer specifications remain intact across rebase interruptions, completing an important piece of the overall feature's reliability.
