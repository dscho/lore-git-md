**Refactoring and documentation discussion for xdiff type safety**

This email continues the discussion about type mapping between C and Rust in Git's xdiff subsystem, specifically addressing how to document type conversions at the FFI boundary. Ezekiel Newren responds to Junio Hamano's suggestion that each language should use its native type names with clear conversion documentation, rather than maintaining a shared header file.

Newren agrees with this approach and proposes `Documentation/unambiguous_types.adoc` as the location for this documentation, dropping his earlier idea of a `compat/rust_types.h` file. The discussion reflects the project's move toward establishing clear standards for type mapping between C and Rust, particularly focusing on signed integer types used for counting and error handling.

This exchange represents the final resolution of one of the open questions in the xdiff refactoring series, moving from implementation details to documentation standards. The conversation maintains the thread's technical rigor while showing alignment between the contributors on the preferred approach.
