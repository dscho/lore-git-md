This is a refactoring patch in Patrick Steinhardt's series modernizing Git's refs subsystem. It addresses a potential issue with the new `struct ref_iterator::ref` field where state could leak between iterations or new fields might not be properly initialized.

The patch ensures all reference backends fully reset the `ref` field on each iteration by adding explicit `memset()` calls. This provides two key benefits: it prevents state leakage between iterations, and ensures any future optional fields added to the struct will be zeroed by default. The change affects the packed, ref-cache, and reftable backends, though some wrapping iterators don't need modification as they already handle the field correctly.

This is part of a larger effort to improve the refs subsystem's architecture while maintaining the separation between transport-related and core ref functionality. The change is mechanical but important for maintainability, ensuring a clean slate for each iteration. The patch appears straightforward with clear reasoning in the commit message and minimal, focused changes to the three backend implementations.
