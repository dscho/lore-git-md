This is a refactoring patch in Patrick Steinhardt's ongoing refs subsystem cleanup series (patch 10/14). It removes the now-obsolete infrastructure for peeling references via iterator interfaces, as the peeled object IDs are now propagated through the new `struct reference` wrapper introduced earlier in the series.

The patch deletes 141 lines across 8 files, primarily removing:
- The `ref_iterator_peel()` function and its vtable entries
- All backend-specific peeling implementations (files, packed, reftable)
- Related documentation about iterator-based peeling
- The special case in `packed-backend.c` that used iterator peeling during ref updates, now directly using the peeled OID from the reference wrapper

Key technical points:
- The change builds on the new `reference_get_peeled_oid()` interface introduced in earlier patches
- All backends (files, packed, reftable) are updated consistently
- The packed backend's `write_with_updates()` now uses the peeled OID directly rather than re-peeling via iterator
- Maintains the architectural separation between transport-related `struct ref` and core `struct reference`

This is a straightforward cleanup patch that removes now-redundant code after the architectural changes in earlier patches. It doesn't introduce new functionality but helps simplify the codebase by eliminating an obsolete peeling pathway. The changes are mechanical deletions with one logical update in the packed backend's write logic.
