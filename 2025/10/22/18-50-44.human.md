Feature implementation for atomic ref updates in `git replay`. This is the second patch in a 3-part series that transitions atomic reference updates from RFC to merge-ready state, with all design questions resolved and maintainer approval on the final interface.

The patch makes atomic ref updates the default behavior for `git replay`, using Git's ref transaction API to ensure all-or-nothing updates. The traditional pipeline workflow (outputting commands for `git update-ref --stdin`) is preserved via a new `--ref-action=print` option. The implementation introduces a type-safe enum for mode handling and extracts a `handle_ref_update()` helper to avoid code duplication.

Key changes include:
- Default atomic behavior implemented via `ref_store_transaction_begin()` and related APIs
- `--ref-action` option with `update` (default) and `print` modes
- Comprehensive test updates to verify both atomic and print behaviors
- Bare repository support for server-side workflows
- Clear documentation of the new default behavior and options

The patch builds on previous review feedback, particularly Junio Hamano's suggestion to rename the option from `--update-refs` to `--ref-action` for semantic clarity. The implementation is thorough, with extensive test coverage and careful handling of error cases. This represents the core functionality of the series, with the final patch (3/3) adding configuration support.
