This is a bugfix discussion thread investigating an unusual exit code behavior in `git notes show` on the NonStop platform.

Jeff King responds to Randall Becker's debugging attempts, clarifying that the exit code anomaly likely originates from the underlying `git show` command that `git notes show` invokes via `execv_git_cmd()`. He suggests the pager might be complicating the exit code propagation and recommends testing with `--no-pager` to isolate the issue.

The discussion remains focused on understanding why the NonStop platform specifically converts the -12 exit code to 0xFF when it reaches bash, while other platforms handle it normally. Jeff notes he cannot reproduce the issue locally, reinforcing the platform-specific nature of the bug. The technical exchange suggests this involves deep process handling differences in how NonStop manages exit codes from child processes.
