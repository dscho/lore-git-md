This is a refactoring patch in the large trailer-handling series, specifically part of the effort to clean up how Git processes command-line trailer arguments. The patch simplifies the internal API by removing redundant `--trailer` prefix handling in the `amend_strbuf_with_trailers()` helper function, pushing that responsibility to callers instead.

The changes modify three files:
- `builtin/commit.c` and `builtin/tag.c` switch from `OPT_PASSTHRU_ARGV` to `OPT_CALLBACK_F` for the `--trailer` option, using `parse_opt_strvec`
- `trailer.c` drops the `skip_prefix()` check that previously handled both prefixed (`--trailer=value`) and bare (`value`) forms

This appears to be a straightforward cleanup that follows from earlier refactoring in the series, eliminating duplicate prefix-handling logic. The patch maintains the same functionality while making the code more consistent - callers now uniformly pass the trailer text directly rather than reconstructing the option format before passing it to the helper. The changes are minimal and focused, with corresponding updates to both major callers (`commit` and `tag` commands.
