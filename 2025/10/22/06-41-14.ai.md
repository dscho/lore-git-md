Performance optimization patch in Patrick Steinhardt's refs subsystem series, focusing on lazy object parsing in `ref-filter.c`. This is the final patch (14/14) in v3 of the series.

The patch introduces on-demand object parsing in the ref-filter machinery, only parsing objects when an atom actually needs the parsed data rather than doing it unconditionally. This provides measurable performance improvements - benchmarks show a 13% speedup in `git for-each-ref --format='%(raw)'` operations on a repository with 40k refs. The change moves most of the runtime to object decompression, suggesting the ref-filter infrastructure itself is now quite optimized.

Key technical aspects:
- Adds `maybe_object` field to `struct expand_data` to cache parsed objects
- Introduces `get_or_parse_object()` helper that parses objects only when needed
- Modifies value-grabbing functions (`grab_tag_values`, `grab_commit_values` etc.) to parse objects lazily
- Maintains all existing functionality while reducing unnecessary parsing
- Includes comprehensive error handling and cleanup

The change builds on the series' earlier refactoring of the refs subsystem and tag verification work, but focuses purely on the performance optimization aspect. It completes the performance improvements started earlier in the series while maintaining all the robustness gains from the tag verification patches.
