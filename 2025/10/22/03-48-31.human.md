Performance optimization follow-up for `git last-modified` algorithm.

Junio C Hamano and Taylor Blau discuss a compiler warning in the performance-optimized `git last-modified` implementation. The issue stems from `path_idx()` returning -1 for errors while being declared to return an unsigned `size_t`, making the `0 <= k` comparison always true (and thus useless). Taylor confirms GitHub's equivalent function uses `int` instead, though notes the practical impact is minimal given path count limits.

This is a technical refinement to the ongoing optimization work that introduced generation-sorted commits and EWAH bitmaps to dramatically improve `git last-modified` performance (2.5x-111.7x faster in benchmarks). While the immediate issue is a type safety fix, it touches on broader questions about signed/unsigned comparisons in the codebase that Junio has previously flagged for project-wide discussion. The exchange shows maintainers rigorously vetting edge cases even in performance-critical paths.
