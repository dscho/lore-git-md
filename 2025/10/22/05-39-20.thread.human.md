This thread introduces a new `--trailer` option for `git rebase`, now in its 5th iteration (v1-v5). The series refactors trailer handling infrastructure to move functionality from an external `interpret-trailers` helper into Git's core via new APIs, eliminating fork/exec overhead. The implementation forces the merge backend when trailers are specified, validates trailer syntax early, and persists state across operations.

The latest patches continue refining implementation details, with the most recent change simplifying error handling for invalid trailer arguments. The validation function now uses `die()` directly rather than returning errors through a `strbuf`, reducing code complexity while maintaining the same error checks for empty trailers or missing keys. This builds on earlier optimizations that improved memory usage, simplified argument processing, and cleaned up state management.

The series has undergone extensive review, with Kristoffer Haugsbakk among the contributors providing feedback.
