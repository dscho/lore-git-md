Error message style fix for atomic ref updates in `git replay`.

This is a review comment from Junio Hamano on the second patch in the series implementing atomic reference updates for `git replay`. The patch has already been reviewed and approved for its core functionality, but Junio is pointing out two minor coding style issues that should be fixed before merging.

First, he notes that enum definitions should typically include a trailing comma after the last item (unless it's a special sentinel value), as this makes future additions cleaner. The current `enum ref_action_mode` definition lacks this trailing comma after `REF_ACTION_PRINT`.

Second, he points to an error message that doesn't fully follow Git's error message guidelines. While the message is properly marked for translation and uses `%s` for the ref name, Junio references the coding guidelines which specify that error messages should: start with the error condition ("failed to..."), not capitalize the first word unless it's an acronym, and enclose the subject in single quotes. The current message follows most of these but could be more precisely aligned with the style guide.

These are minor polish items on an otherwise technically complete patch that has already achieved consensus on its core design and implementation. The feedback doesn't affect the functionality or interface of the atomic ref updates feature, but ensures the code style matches Git project conventions. Since this is the final patch series before merging, such style tweaks are expected as part of the maintainer's final review pass.
