Refactoring patch in the ongoing trailer API cleanup series. This is patch 4/29 in the v5 iteration of the work to integrate trailer handling directly into Git commands.

The change moves the initialization of two linked list heads (`config_head` and `arg_head`) inside the conditional block where they are actually used, rather than declaring them at function scope. This is a common optimization pattern to avoid unnecessary variable initialization when they won't be used (in the `only_input` case). The patch maintains identical behavior while slightly reducing memory overhead for the `only_input` code path.

This continues the series' focus on streamlining the internal trailer processing API, following earlier feedback about code organization. The change is straightforward and low-risk, affecting only `trailer.c` with no interface changes. It demonstrates the kind of incremental refinement typical of later iterations in a well-reviewed patch series.
