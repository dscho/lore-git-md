This is a feature patch series introducing a new `--trailer` option to `git rebase`, along with significant internal refactoring of trailer handling. The series has gone through 5 iterations with extensive review feedback incorporated.

The core change moves trailer manipulation from an external `interpret-trailers` helper into in-process Git code via a new `amend_strbuf_with_trailers()` function (patch 0). This enables the new `rebase --trailer` feature (patch 9) which:
- Forces use of the merge backend (since apply/am lack message filtering)
- Automatically enables `--force-rebase` to rewrite fast-forwarded commits
- Appends specified trailers to every rewritten commit
- Persists state for interrupted rebases
- Includes comprehensive tests in new t3440 covering various scenarios

The series shows careful attention to review feedback across all versions, with v5 specifically addressing Kristoffer Haugsbakk's comments from v4. The implementation appears thorough, with proper error handling, state management, and test coverage. The changes touch multiple components (trailer.c, rebase.c, sequencer.c) but maintain backward compatibility.

Key technical details for future reference:
- New `--trailer` option in `git rebase` with persistent state in `$state_dir/trailer`
- `amend_strbuf_with_trailers()` replaces fork/exec of `interpret-trailers`
- Trailer validation honors configured separators
- Special handling for `fixup -C` with trailers
- 29 patches total, with first 8 refining the trailer infrastructure and remainder focusing on rebase integration
- New test file t3440 exercises edge cases and verifies behavior across rebase operations

The series appears ready for consideration, having addressed multiple rounds of review feedback while maintaining a clear focus on the core functionality. The trailer handling refactor could have implications beyond rebase, though the current changes are scoped to support the immediate feature.
