This is a refactoring patch in Patrick Steinhardt's ongoing refs subsystem optimization series, specifically addressing iterator state management. The patch ensures `struct ref_iterator::ref` is fully reset between iterations to prevent state leakage and provide clean defaults for new fields.

The change modifies three backend implementations (packed, ref-cache, reftable) to zero out the reference structure before populating it with new data. This guarantees no residual state carries over between iterations and any future optional fields will be properly zero-initialized. The files backend is unaffected as it uses `cache_ref_iterator` internally, and wrapper iterators already copy references completely.

The patch is a mechanical but important cleanup that reduces subtle bugs from state leakage while making the interface more maintainable for future extensions. It's part of the larger effort to improve the refs subsystem's architecture following the `struct ref`/`struct reference` separation. The changes are straightforward and focused, touching only the necessary backend implementations with minimal churn (4 lines added, 1 removed across 3 files).
