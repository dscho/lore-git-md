This is part 5 of a 14-patch series refactoring Git's refs subsystem to improve performance and clean up the interface for tag peeling. The series builds on Patrick Steinhardt's earlier work separating transport-related refs from core ref handling.

The patch eliminates a fragile global-state mechanism for accessing peeled tag objects. Previously, callbacks had to check a global iterator variable and call `peel_iterated_oid()`, which was awkward and error-prone. The new approach adds a `peeled_oid` field to `struct reference` that backends can populate directly, along with a cleaner `reference_get_peeled_oid()` accessor function.

The change affects multiple callers across Git's codebase (describe, gc, pack-objects, etc.), all updated to use the new interface. The patch is mechanical but important - it removes a subtle dependency on global state while maintaining the same functionality. This is part of the broader effort to make the refs subsystem more maintainable and performant, particularly for operations involving tags.

The changes are well-contained and the commit message clearly explains both the problem and solution. This appears to be a straightforward improvement that should not be controversial, though reviewers will want to verify the updates to all the call sites.
