Performance optimization in ref-filter to lazily parse objects when needed.

This is the final patch in Patrick Steinhardt's 14-part series modernizing Git's ref handling and tag verification. The patch optimizes `ref-filter.c` to avoid parsing objects unnecessarily when formatting ref output. Currently, objects are parsed eagerly even when the formatting doesn't require parsed data (like with the `%(raw)` format).

The change makes object parsing lazy - only happening when an atom actually needs parsed data. This provides a measurable speedup: in a Chromium repo with 40k refs, `git for-each-ref --format='%(raw)'` becomes ~13% faster (344ms vs 389ms). The implementation introduces a new `get_or_parse_object()` helper and modifies the value-grabbing functions to parse on demand.

The patch builds on the series' earlier architectural work separating ref transport from core ref handling while maintaining all the robustness improvements around tag verification. It completes the performance optimization goals that originally motivated the series while keeping the code clean and maintainable.
