This is a refactoring and bugfix patch in Patrick Steinhardt's ongoing refs subsystem optimization series. It introduces stricter type verification when peeling tags by adding a new `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag to `peel_object()`. The change addresses a subtle issue where tag peeling could silently accept objects with mismatched types due to not verifying the tagged object's actual type against what the tag claimed it should be.

The patch inlines the now-obsolete `deref_tag_noverify()` function (removing 12 lines from tag.c) since its functionality is now covered by the new flag-based verification in `peel_object()`. The change touches core object handling code (object.c/h), ref filtering (ref-filter.c), and both packed and reftable backends, with all existing callers passing `0` for the new flags parameter to maintain current behavior.

This builds on the thread's earlier work to clean up tag peeling infrastructure, though Patrick notes uncertainty about whether this is the right architectural approach versus fixing `parse_tag_buffer()` directly. The change preserves backward compatibility with existing tests that expect to handle corrupt tags, while giving callers the ability to opt into stricter verification where needed. Subsequent patches in the series will wire up the new verification flag at selected call sites.
