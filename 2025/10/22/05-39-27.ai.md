This is a refactoring patch in the ongoing trailer processing series, specifically part of the effort to unify the output flow between `interpret-trailers` and the new in-process `trailer_process()` API.

The patch simplifies the control flow in `trailer.c` by removing a special-case early return path that previously handled a specific combination of options (`only_input`, `only_trailers`, etc.). Now all code paths go through the same unified exit sequence, ensuring consistent cleanup of trailer lists and buffers. The change mirrors the output behavior of the standalone `interpret-trailers` command more closely.

Key technical changes:
- Removes the `had_trailer_before` check and early return branch
- Consolidates three output path variants into two (trailers-only vs full message)
- Standardizes on `block_start`/`block_end` variable names for trailer block positions
- Maintains the same blank line insertion logic but with clearer condition naming (`need_blank_line`)
- Ensures all paths properly free allocated resources via the shared exit sequence

The patch appears to be a straightforward cleanup with no behavior change, continuing the series' trend of simplifying the trailer processing internals. It follows naturally from previous API unification work and helps maintain consistency between the in-process and standalone trailer handling.
