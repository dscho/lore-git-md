This is a bugfix for `git bisect` that addresses two related issues with subcommand handling, stemming from the 2022 builtin conversion. The patch fixes incorrect behavior where `git bisect help` would trigger an interactive autostart prompt instead of showing usage information, and where invalid subcommands were being processed through the state machine rather than being properly rejected.

Junio C Hamano has reviewed and approved the patch, noting that while the solution isn't perfectly elegant (due to historical constraints of the `help` subcommand), it's the most practical approach. The fix adds explicit handling for the `help` subcommand and properly validates unrecognized commands against the current state terms (good/bad/new/old). 

The maintainer confirms the logic is sound after careful analysis, particularly around the handling of custom terms and valid subcommands. While there was some discussion about potentially cleaner implementations (like using `OPT_SUBCOMMAND`), these are deemed non-essential improvements that could come later. The patch is now queued for inclusion.

This is a focused fix that restores documented behavior while maintaining backward compatibility, addressing a regression that's been present since the builtin conversion. The changes are well-reasoned and have passed maintainer scrutiny.
