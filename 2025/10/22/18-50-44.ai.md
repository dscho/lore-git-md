This is the core implementation patch in a 3-part series that makes atomic reference updates the default behavior for `git replay`. The patch transitions from the previous pipeline-based approach (where output was meant to be piped to `git update-ref`) to direct atomic updates using Git's ref transaction API.

Key technical changes include:
- Introduces a new `--ref-action` option with `update` (default) and `print` modes
- Implements atomic updates via `ref_store_transaction_begin()`, `ref_transaction_update()`, and `ref_transaction_commit()`
- Adds a `handle_ref_update()` helper function that works with both modes
- Uses an enum (`REF_ACTION_UPDATE`/`REF_ACTION_PRINT`) for type safety
- Updates documentation to reflect the new default behavior
- Modifies tests to use `--ref-action=print` where they expect command output
- Adds new tests for atomic behavior verification

The implementation addresses several previous concerns from the mailing list discussion:
- Performance via batched transactions (Patrick Steinhardt)
- Atomicity guarantees matching `git update-ref --stdin` (Phillip Wood)
- Clear separation between CLI and config interfaces (Christian Couder)
- Type-safe enum implementation (Junio Hamano)

The patch maintains backward compatibility while making the more ergonomic atomic behavior the default. Server-side workflows particularly benefit from eliminating the process coordination overhead of the pipeline approach. The extensive test coverage includes verification of the all-or-nothing atomic behavior.

This represents the consensus design from the mailing list discussion, with all technical questions resolved and naming finalized as `--ref-action`/`replay.refAction`. The implementation is ready for merging as part of the series.
