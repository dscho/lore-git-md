This is a follow-up discussion in the xdiff refactoring series regarding type mapping documentation for Rust FFI compatibility. Ezekiel Newren responds to Junio Hamano's suggestion about documenting type mappings between C and Rust without using a dedicated header file.

The email confirms alignment on the agreed approach: using native type names in each language with explicit documentation of conversions at the FFI boundary, rather than trying to maintain type name parity through a header file. Newren proposes `Documentation/unambiguous_types.adoc` as the location for this documentation and definitively drops the previously considered `compat/rust_types.h` approach.

Key technical points include:
- The documentation will need to cover bidirectional type mappings
- Special cases where types lack direct equivalents between languages must be documented
- The solution avoids forcing C code to use Rust-type-inspired names
- Maintains the series' focus on clear, platform-portable type choices while enabling Rust interoperability

This resolves one of the remaining open questions from the thread regarding how to formally document the type mapping strategy. The discussion has now shifted entirely to documentation standards rather than implementation details, with both parties in agreement on the technical direction. The email marks a clear transition point where architectural decisions are settled and the focus moves to documenting the agreed-upon.
