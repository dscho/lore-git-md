This is a bugfix patch in Patrick Steinhardt's ongoing refs subsystem series, specifically addressing tag verification in `git-for-each-ref`. The patch fixes an edge case where corrupted tags (those claiming an incorrect object type) could go undetected unless two tags pointed to the same object with conflicting type claims.

The core issue stems from how `peel_object()` verifies types - it only catches mismatches when different lookup functions are called for the same object. The fix adds `PEEL_OBJECT_VERIFY_OBJECT_TYPE` to ensure type verification happens during the initial peeling operation in `populate_value()`, making corruption detection more robust.

The patch includes an expanded test case that now verifies the fix catches corruption even with a single problematic tag. This builds on the series' broader goal of improving tag verification while maintaining the separation between transport`struct ref` and core `struct reference` types.

The change appears well-contained and focused, with a clear explanation of both the edge case and solution. It maintains consistency with the series' architectural direction while closing a subtle verification gap. The test expansion provides concrete validation of the improved behavior.
