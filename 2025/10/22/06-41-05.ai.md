Refactoring patch in the refs subsystem modernization series, focusing on tag peeling efficiency and interface cleanup.

This patch eliminates the awkward global-state-dependent `peel_iterated_oid()` function in favor of a cleaner approach where peeled object IDs are made available directly through the ref iterator interface. The key changes are:

1. Adds a new `peeled_oid` field to `struct reference` that backends can populate when they have the peeled value readily available (as both files and reftable backends do for tags)
2. Introduces `reference_get_peeled_oid()` as the new interface for accessing peeled objects, which first checks the new field before falling back to manual peeling via the ODB
3. Updates several callers across the codebase (describe, gc, pack-objects, etc.) to use the new interface
4. Modifies both packed and reftable backends to populate the new field when they have the peeled value

The change maintains all existing behavior while removing the fragile global state dependency. It's part of a larger effort to clean up the refs subsystem interfaces following the `struct ref`/`struct reference` separation. The patch touches 12 files with mostly mechanical conversions, though the packed and reftable backend changes show the new field being populated from their existing peeled value storage.

This fits into the series' group 2 (refactoring patches 3-9) that eliminate the `peel_iterated_object()` hack and introduce cleaner interfaces. The change is straightforward and unlikely to be controversial, serving as infrastructure for later optimizations while improving code maintainability.
