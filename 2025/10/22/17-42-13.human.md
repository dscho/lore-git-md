Junio C Hamano confirms the commit-graph changed-paths config patch is ready for merging. This is the final step in a series introducing a three-state `commitGraph.changedPaths` config option to control Bloom filter generation, with Microsoft's large monorepo use case driving the design.

The patch from Emily Yang (with Reviewed-by from Derrick Stolee) establishes clear semantics where command-line --[no-]changed-paths flags take precedence over config, and where setting the config to `false` preserves existing filters rather than removing them. Junio notes the documentation concerns from earlier rounds have been satisfactorily addressed.

This change enables Scalar to recommend `commitGraph.changedPaths=true` for large repositories while maintaining backward compatibility. The implementation includes thorough test coverage in t5318-commit-graph.sh and explicit documentation about the non-destructive nature of config changes. With Junio's approval, this appears ready to graduate from the mailing list to the main Git codebase.
