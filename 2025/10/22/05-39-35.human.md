This is a refactoring patch in the ongoing `--trailer` option series for `git rebase`. It moves trailer argument validation logic from `builtin/rebase.c` to `trailer.c` to better centralize trailer handling.

The key change is that validation now respects configured trailer separators (like `:` or `=`) rather than hardcoding them. The patch moves the validation function while maintaining the same error checking for empty trailers and missing keys, but now using the trailer subsystem's `find_separator()` function instead of a simple `strpbrk()`.

This is part of the larger effort to properly integrate trailer handling into Git's core rather than relying on external `interpret-trailers`. The change appears straightforward and maintains the same validation behavior while being more consistent with the rest of the trailer infrastructure. The patch follows the series' pattern of moving functionality into `trailer.c` where it belongs.
