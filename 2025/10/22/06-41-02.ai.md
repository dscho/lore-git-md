Refactoring patch in Patrick Steinhardt's refs subsystem optimization series, specifically modifying the ref iterator interface to use a `struct reference` wrapper.

This patch (02/14 in v3) simplifies the ref iteration interface by replacing individual fields in `struct ref_iterator` (refname, oid, flags, referent) with a single `struct reference` member. The change affects all ref backend implementations (files, packed, reftable) and supporting infrastructure. Key technical points:

- Eliminates repetitive field copying in iterator implementations by passing the reference struct directly
- Updates `should_pack_ref()` to take the reference struct rather than separate parameters
- Modifies 8 files with 75 insertions and 100 deletions, mostly mechanical updates to use the new wrapper
- Maintains all existing functionality while reducing boilerplate
- Part of broader effort to clean up ref iteration interfaces following the refs/transport separation

The change enables more maintainable future modifications to the ref iteration interface while being a straightforward mechanical conversion. It builds on the architectural foundation established in earlier patches while paving the way for the performance optimizations coming later in the series.
