Bugfix and refactoring patch adding type verification to tag peeling.

This patch from Patrick Steinhardt addresses an issue where Git doesn't properly verify the type of objects when peeling tags. Currently, when following a tag chain, Git trusts the type declared in each tag without validating it against the actual object in the ODB. This can lead to incorrect assumptions about object types when tags are corrupted or malformed.

The solution introduces a new `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag to `peel_object()` that enables strict type verification. When set, Git will check the actual object type in the database rather than just trusting the tag's declaration. The patch also removes the now-unnecessary `deref_tag_noverify()` function, folding its behavior into the main peeling logic.

This change is part of a larger series (now at v3) that began as a performance optimization but uncovered deeper architectural issues with tag peeling. The author notes this isn't a complete solution - some tests expect to handle corrupt tags, so we can't enforce verification everywhere yet. The flag-based approach allows incremental adoption while maintaining backward compatibility.

The patch touches core object handling code and affects several ref-related subsystems, including both packed and reftable backends. It's a focused change that improves type safety while maintaining the existing behavior for most callers, who continue using the default non-verifying mode.
