Final discussion in macOS mmap optimization thread. Jeff King (Peff) responds to Koji Nakamaru's findings that the extreme mmap/munmap counts were caused by an unusually small `packedGitLimit = 128m` configuration rather than inherent Git behavior. Peff confirms this explains the original performance issues and notes there's no good reason to use such a restrictive setting normally. While Nakamaru's munmap batching did show speed improvements in the artificially constrained scenario, both agree the proper solution is simply using standard configuration values rather than adding optimization code. The exchange concludes the investigation, with no further action needed on the original patch proposal. Peff does note the macOS performance characteristics Nakamaru uncovered could be useful background knowledge for future work, though they don't warrant immediate changes to Git's macOS implementation.
