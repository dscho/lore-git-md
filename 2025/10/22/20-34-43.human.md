This is a discussion about output format consistency in the new `git repo` subcommands. Lucas Seiki Oshiro suggests unifying the `--format` option between `git-repo-info` and `git-repo-structure` to create a more consistent interface, even though their implementations differ. He notes that while the two commands work differently internally, their user-facing interfaces are similar enough that they could benefit from shared formatting options.

Oshiro specifically proposes making the table format (currently only in `git-repo-structure`) available to `git-repo-info` as well. He also asks whether the author plans to add key-based output filtering to `git-repo-structure`, similar to what exists in `git-repo-info`, which would allow users to request specific statistics like branch and tag counts.

This is a design suggestion rather than a patch - it's exploring potential interface improvements that could make the two related commands more consistent. The suggestion comes late in the series (v6/7) after the core functionality is already implemented and approved, indicating this is more about future polish than blocking issues. The thread context shows the current custom table formatter was deliberately implemented to match git-sizer's output style, so any changes would need to maintain that compatibility.
