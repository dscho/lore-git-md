This is a bugfix for the `git bisect` subcommand handling, addressing two regressions from the 2022 builtin conversion. The patch has now received maintainer approval from Junio C Hamano and is being queued for inclusion.

The fix restores the documented behavior where `git bisect help` shows usage information rather than triggering an interactive autostart prompt. It also properly rejects invalid subcommands by checking them against the known state terms (good/bad/new/old) before processing through the state machine. The implementation adds explicit handling for the `help` subcommand and validates unrecognized inputs against the current terms.

Junio notes some theoretical improvements that could be made (like treating `help` as a proper subcommand or removing the special `help` handling entirely in favor of `--help`), but considers the current approach acceptable given backward compatibility constraints. The validation logic for unknown commands is confirmed correct after careful analysis of the interaction between `check_and_set_terms()` and the new `one_of()` check.

This appears to be the final version of the fix, with the maintainer's approval superseding Ben Knoble's earlier review suggestions about using `OPT_SUBCOMMAND` and updating usage text. The changes are focused and well-justified, directly fixing the reported regressions while maintaining compatibility with existing bisect workflows.
