This is a bugfix for the `git bisect` command's handling of subcommands. The patch addresses two related issues that emerged after the command was converted to a full builtin in 2022:

1. The documented `git bisect help` behavior stopped working - instead of showing usage info, it would either silently fail (if in a bisect session) or trigger an interactive autostart prompt.
2. Invalid subcommands (like `git bisect foobar`) were being incorrectly processed through the state machine rather than being rejected.

The root cause was that all unrecognized commands were being passed to `bisect_state()`, which would then call `bisect_autostart()`. The fix adds explicit handling for `help` to show usage info, validates unrecognized commands against valid state terms before processing, and shows proper errors for truly invalid commands.

The change is relatively small (6 lines modified) but important for command-line usability, ensuring the tool behaves as documented. The patch appears well-motivated with clear commit message explanation and references to the commits that introduced the regression. The fix maintains backward compatibility with alternate terms while properly rejecting invalid inputs.
