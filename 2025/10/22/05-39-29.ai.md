This is a feature patch introducing `--trailer` support for `git rebase`, part of a larger series refactoring Git's trailer handling infrastructure (now at v5). The patch adds the ability to append custom trailers to commit messages during rebase operations, currently limited to the merge backend.

Key technical details:
- Adds `--trailer=<text>` option to `git rebase` that appends trailers via `git-interpret-trailers`
- Automatically forces rebase (sets `REBASE_FORCE`) when trailers are specified
- Rejects invalid trailer syntax early (empty trailers, missing keys)
- Persists trailer state across rebase operations via state_dir/trailer file
- Includes comprehensive tests in new t3440-rebase-trailer.sh covering:
  - Backend compatibility checks
  - Trailer validation
  - Multiple/duplicate trailer handling
  - Conflict resolution cases
  - Root rebase scenarios

The implementation touches:
- Documentation/git-rebase.adoc (new option docs)
- builtin/rebase.c (option parsing, state management)
- sequencer.c/h (trailer processing integration)
- New test file with 7 test cases

The patch builds on prior work in the series that moved trailer processing into Git core, now exposing this capability through rebase. It follows the pattern of making error handling more robust (using the new `write_file_buf_gently()` from earlier in the series) and maintains consistency with existing rebase trailer behavior for `--signoff`.
