Refactoring patch in a series modernizing Git's ref handling. This is part 7 of 14 in Patrick Steinhardt's series that began as a performance optimization for `git-for-each-ref` but expanded into broader ref subsystem improvements.

The patch modifies the ref-filter subsystem to propagate peeled object IDs through the ref array when available, rather than discarding and re-parsing them. This eliminates the need for `peel_iterated_oid()` in many cases, building on earlier work to separate transport-related ref handling from core ref operations.

Key changes:
- Adds `peeled_oid` field to `struct ref_array_item`
- Updates `ref_array_push()` and related functions to accept and store peeled OIDs
- Modifies tag peeling logic to use stored peeled OID when available
- Updates callers in ls-remote, tag, and verify-tag commands

The change is part of a larger effort to clean up tag peeling behavior while maintaining the separation between `struct ref` (transport) and `struct reference` (core). The patch appears well-contained and mechanically sound, touching only the expected call sites while preserving existing behavior. It builds toward the series' goal of making object parsing lazy in ref-filter for performance gains.
