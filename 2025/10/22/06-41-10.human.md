This is a refactoring patch in Patrick Steinhardt's ongoing series to modernize Git's refs subsystem. It removes now-obsolete infrastructure for peeling references via iterators, since the peeled object IDs are now propagated through the new `struct reference` wrapper introduced earlier in the series.

The patch is straightforward cleanup - it deletes the `ref_iterator_peel()` function and all its implementations across various backends (files, packed, reftable), along with related documentation. The only non-trivial change is in `packed-backend.c` where it updates the peeled object handling to use the new `peeled_oid` field directly rather than going through the iterator interface.

This change is part of a larger effort to improve reference handling performance and maintainability. The series has already shown measurable performance gains (13% for `git-for-each-ref`) while cleaning up technical debt. This particular change builds on earlier work to eliminate thread-unsafe globals and standardize the reference interface.
