Maintainer review of regression fix for `git diff --quiet` behavior. This email from Junio Hamano discusses ongoing refinements to the fix for the `--quiet` regression, where staged files were incorrectly producing output. The core issue stems from commit b55e6d36eb which broke both `--quiet` and `-I` functionality.

The current approach involves redirecting output to `/dev/null` in `diff_flush_patch_quietly()` while carefully managing state restoration of `o->file` and `o->color_moved`. Junio expresses some frustration about not being able to find a test case where forgetting to restore `o->file` would cause problems, suggesting the current solution may be more complex than strictly necessary.

Jeff King had proposed moving the redirection logic into `flush_quietly()`, but Junio notes this would cause N redirections for N-path patches, which seems inefficient. The patch shown demonstrates the current working solution with explicit state saving/restoration around the diff flushing loop.

This appears to be a careful, iterative refinement of the fix, with the maintainer weighing architectural concerns and potential edge cases. The discussion suggests the solution is nearing completion but still has some open questions about optimal implementation details.
