Performance optimization withdrawal notice. Koji Nakamaru is withdrawing the macOS munmap queueing patch after discovering the extreme mmap counts were caused by a local `packedGitLimit = 128m` configuration rather than a general Git performance issue. The patch showed dramatic improvements in this artificial scenario (reducing sys time from 518m to 2m for `git log --raw` with the restrictive config), but Nakamaru acknowledges this represents an edge case rather than normal Git usage.

The withdrawal comes after Jeff King's review questioning whether the optimization addressed a real-world problem, suggesting repository maintenance (via `git gc`) would be more appropriate than the munmap queueing approach. Nakamaru's testing confirms normal Git operations show minimal mmap activity (9 calls vs 3 million with the restrictive config) and the batching provides no benefit in standard usage.

Key technical points from the investigation:
- The extreme mmap counts were entirely due to an unusually small `packedGitWindowSize` setting
- Normal Git operations show orders of magnitude fewer mmap calls
- The optimization only helps in artificially constrained scenarios
- Memory pressure impacts remain unverified but were not critical in testing

The thread concludes with the realization that the original performance issue was configuration-induced rather than inherent to Git's macOS implementation, making the optimization unnecessary for general use.
