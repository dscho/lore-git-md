This is the final version of a 3-patch series implementing atomic reference updates for `git replay`, now ready for merging. The series transitions the experimental command from RFC to production-ready status with all design decisions resolved and maintainer-approved naming (`--ref-action`/`replay.refAction`).

The cover letter highlights key changes in v4, including:
- Renamed `--update-refs` to `--ref-action` for semantic clarity (suggested by Junio Hamano)
- Unified config and command-line values to both use `update`/`print`
- Converted to type-safe enum implementation
- Improved documentation for the `--advance` option
- Fixed a failing synopsis test

The implementation uses Git's ref transaction API (`ref_store_transaction_begin()`, `ref_transaction_update()`, `ref_transaction_commit()`) to provide atomic updates by default while maintaining backward compatibility via the `--ref-action=print` option for pipeline workflows. The series includes comprehensive test coverage and documentation updates.

All outstanding feedback from v3 has been addressed, with maintainer consensus achieved on the final interface design. The patches are cleanly separated into:
1. Preparatory option validation refactoring
2. Core atomic update functionality
3. Configuration support via `replay.refAction`

This represents the culmination of several review rounds and is now in merge-ready state.
