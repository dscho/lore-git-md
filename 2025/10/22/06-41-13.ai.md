Bugfix patch in a refactoring series addressing tag verification issues. This is patch 13/14 in Patrick Steinhardt's series that builds on refs subsystem modernization work, specifically targeting corruption detection in tag peeling operations.

The patch fixes a subtle edge case in `git-for-each-ref` where tag corruption (mismatch between declared and actual object types) would only be detected when two tags pointed to the same object with different declared types. The root cause was that `peel_object()` would verify types only when different lookup functions were called for the same object. The fix adds `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag to the peeling operation in `populate_value()`, ensuring type verification happens even for single tag dereferencing.

Key technical changes:
- Modifies `ref-filter.c` to pass the verification flag when peeling tags
- Updates the test in `t/for-each-ref-tests.sh` to verify the fix works for single corrupt tags (`broken-tag-bad`) in addition to the existing test case
- Maintains consistency with the series' broader goal of robust tag verification while preserving the ref/transport separation

This patch completes the series' handling of invalid tags by ensuring corruption is caught at dereference time rather than allowing potentially invalid cached peeled OIDs to propagate. The change is minimal (3 lines) but has significant impact on corruption detection reliability. The test expansion demonstrates the fix works for both the original edge case and normal single-tag corruption scenarios.
