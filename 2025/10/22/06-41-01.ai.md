This is a refactoring patch that introduces a wrapper struct for the `each_ref_fn` callback interface used throughout Git's codebase. It's the first patch in a 14-part series focused on performance optimizations and architectural improvements to Git's refs subsystem.

The change replaces direct callback parameters (refname, referent, oid, flags) with a single `struct reference` containing those fields. This makes future interface changes less disruptive since new fields can be added to the struct without requiring changes to every callback implementation. The patch demonstrates this by updating 49 files to use the new interface.

Key technical details:
- Introduces `struct reference` in refs.h containing name, target, oid, and flags fields
- Modifies all `each_ref_fn` callbacks to take the struct instead of individual parameters
- Maintains the same functionality while reducing churn for future changes
- Affects core ref iteration code in refs/iterator.c and all callback implementations

The change builds on previous work that separated transport-related refs (`struct ref`) from core refs (`struct reference`), continuing the architectural cleanup of Git's ref handling code. While this initial patch is purely mechanical, it enables more substantive changes in later patches of the series.
