This is a refactoring patch in Patrick Steinhardt's ongoing refs subsystem cleanup series, specifically addressing technical debt in the reference iteration infrastructure.

The patch removes the `current_ref_iter` global variable and associated peeling logic, which was previously used as a performance optimization during reference iteration. With the recent introduction of `struct reference` and its `peeled_oid` field in earlier patches of this series, this hack is no longer needed - the peeled OID is now properly propagated through the reference wrapper structure.

The change touches core refs infrastructure, deleting 28 lines across three files (`refs.c`, `refs/iterator.c`, and `refs/refs-internal.h`). The removal is safe because all callers have already been converted to use the new `reference_get_peeled_oid()` interface in previous patches. This is a clean-up that follows through on the architectural improvements made earlier in the series, eliminating a global variable and making the code more straightforward to understand.

The patch appears well-contained and builds on the established direction of the series, which has already seen significant review and iteration. It represents the kind of technical debt cleanup that becomes possible after more fundamental refactoring work is completed.
