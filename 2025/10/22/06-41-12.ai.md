This is a bugfix patch in Patrick Steinhardt's refs subsystem optimization series, specifically addressing invalid tag handling. The patch prevents storing peeled object IDs for tags where the tagged object's type doesn't match the tag's claimed type, which could mask corruption.

The change modifies both the files and reftable backends to use the new `PEEL_OBJECT_VERIFY_OBJECT_TYPE` flag when peeling tags during ref storage operations. This ensures corrupted tags (where the stored type doesn't match the actual object type) won't have their peeled values cached in the refdb, forcing future operations to re-verify the tag and catch the corruption.

The patch includes tests demonstrating the fix:
- For the files backend, it verifies packed-refs doesn't store peeled values for invalid tags
- For reftable, it creates two tags pointing to the same object with conflicting type claims to verify the corruption is caught

This continues the thread's theme of improving tag verification while maintaining the refs subsystem's architectural separation. The change is particularly relevant for commands like `git-for-each-ref` that use peeled values, ensuring they'll detect tag corruption rather than silently using cached invalid data. The patch builds on the series' earlier introduction of strict type checking during peeling.
