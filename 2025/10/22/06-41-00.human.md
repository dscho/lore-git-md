This is a performance-focused refactoring series from Patrick Steinhardt that improves tag peeling behavior in Git's refs subsystem. The 14-patch series grew from a simple performance optimization for `git-for-each-ref` into a broader cleanup of tag handling infrastructure.

The series starts by refactoring the refs iterator interface to better expose peeled object IDs (patches 1-8), then removes now-unneeded peeling infrastructure (patches 9-10). Patches 11-13 address edge cases where tags might claim an object type that doesn't match their actual content. The final patch (14) delivers the original goal - avoiding unnecessary object parsing in `git-for-each-ref` when peeling isn't needed.

Patrick notes some hesitation about patches 11-13, which handle invalid tag cases in a piecemeal way rather than fixing the root cause in `parse_tag_buffer()`. The changes are already quite invasive, touching 66 files across the codebase, so this conservative approach may be prudent. The series builds on recent refs subsystem work and has gone through three revisions with minor improvements to commit messages and iterator safety.

For readers tracking refs subsystem development, this continues the modernization effort while delivering measurable performance benefit (the original optimization motivated the work). The changes are wide-ranging but focused on internal APIs, with minimal user-facing impact beyond potential behavior changes for malformed tags.
