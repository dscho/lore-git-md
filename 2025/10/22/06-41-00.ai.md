This is a performance optimization patch series that also includes refactoring and bugfixes related to tag peeling behavior. The series builds on Patrick Steinhardt's earlier merged work on refs subsystem modernization, specifically the separation between `struct ref` and `struct reference`.

The series originated from a simple performance optimization (patch 14) to avoid parsing objects in `git-for-each-ref` unless necessary, but uncovered deeper issues with tag peeling that required architectural changes. The 14 patches are organized into:
1. Refactoring (patches 1-8) to eliminate the `peel_iterated_object()` hack and introduce cleaner interfaces
2. Cleanup (patches 9-10) removing now-unneeded infrastructure
3. Bugfixes (patches 11-13) for issues with invalid tags where stored type information doesn't match actual objects
4. The original optimization (patch 14) making object parsing lazy in ref-filter

Key technical aspects:
- Introduces `struct reference` wrapper for ref iteration callbacks
- Adds `reference_get_peeled_oid()` as the new preferred peeling interface
- Adds type verification during peeling to catch tag/object mismatches
- Modifies ref-filter to parse objects only when needed (the performance win)
- Updates numerous callers across the codebase to use the new interfaces

The series touches 66 files with ~800 lines changed (insertions roughly balancing deletions). Patrick expresses some uncertainty about patches 11-13 being the ideal solution for invalid tag handling, noting they feel like "whack-a-mole" and that directly fixing `parse_tag_buffer()` would break tests expecting corrupt tags.

This builds on master with dependencies on two in-progress topics (tb/incremental-midx-part-3.1 and jt/16a93c03c7). The changes are primarily internal plumbing improvements with one user-visible performance optimization, continuing the refs subsystem modernization effort.
