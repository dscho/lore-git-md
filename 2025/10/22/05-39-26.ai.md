Performance optimization in the ongoing trailer refactoring series.

This patch (6/29 in v5 series) optimizes the non-in-place output path in `interpret_trailers()` by replacing a direct `fwrite()` call with `strbuf_write()`. The change eliminates redundant buffer handling when writing trailer-processed output to stdout, though the performance impact is likely minimal since both methods ultimately write the same content.

The modification is straightforward - a one-line change in `builtin/interpret-trailers.c` that maintains the same functionality while using Git's standard string buffer API. This continues the series' trend of internal cleanups and optimizations, though this particular change appears more about code consistency than measurable performance gains. The patch follows earlier work in the in-place writing path and keeps the same test coverage from t3440.

Technical details show the change affects only the non-in-place code path (when not using `--in-place`), switching from raw `fwrite()` of the strbuf contents to using the strbuf's own write method. The patch maintains the existing buffer lifecycle management with `strbuf_release()` calls. This appears to be a minor but sensible cleanup as part of the larger trailer infrastructure refactoring effort.
