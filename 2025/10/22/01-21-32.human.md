This is a performance optimization withdrawal notice. Koji Nakamaru is withdrawing their macOS munmap queueing patch after discovering that the extreme mmap/munmap behavior they observed was caused by a non-default `packedGitLimit = 128m` setting in their personal gitconfig, rather than a general macOS performance issue.

The patch had shown dramatic improvements in pathological cases (reducing `git ls-tree` sys time from 27m15s to 24s when processing 943k operations), but Jeff King's review identified that these cases were artificially created by the unusual config setting. Testing with normal configurations showed minimal mmap counts (9 vs 3 million) and the batching optimization actually performed slightly slower in normal case (1m5s vs 1m3s for `git log --raw`).

While the optimization did help in the artificial scenario, Nakamaru concludes it's an "unusual hack" not worth pursuing given that proper repository maintenance (`git gc`) and default configurations avoid the problem entirely. The thread demonstrates how careful performance analysis should first validate whether the observed behavior represents typical usage patterns.
