This is a bugfix patch in Patrick Steinhardt's refs subsystem optimization series, specifically addressing how invalid tags are handled. The patch prevents Git from storing peeled object IDs for tags where the tagged object's type doesn't match what the tag claims it to be (like a tag claiming to point to a commit when it actually points to a blob).

The change affects both the files and reftable backends, making them verify object types during peeling. This ensures corruption is caught consistently rather than being masked by cached peeled values. The patch includes tests showing that packed-refs won't store invalid peeled values and that commands like `git for-each-ref` will properly detect type mismatches.

This is part of a larger effort to clean up tag peeling behavior that emerged during performance optimization work. While the technical solution is straightforward (adding type verification during peeling), Patrick has expressed some reservations about this being a "whack-a-mole" approach versus fixing the root cause in `parse_tag_buffer()`. The patch appears well-tested with new test cases covering both storage backends.
