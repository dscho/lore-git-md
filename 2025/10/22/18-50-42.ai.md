This is the final version (v4) of a 3-patch series implementing atomic reference updates for `git replay`, now ready for merging. The series transitions the experimental `git replay` command from its original pipeline-based ref update approach to using atomic transactions by default while maintaining backward compatibility.

Key changes in v4:
- Renamed `--update-refs` to `--ref-action` for semantic clarity (suggested by Junio Hamano)
- Aligned config name with CLI option as `replay.refAction` (per Christian Couder's feedback)
- Unified config/CLI values to both use `update`/`print` (removing mental mapping needed in v3)
- Converted to type-safe enum implementation (Junio's suggestion)
- Fixed t0450 synopsis test that was failing in v3
- Improved `--advance` documentation by removing confusing cherry-pick analogy

Technical implementation remains robust:
- Uses Git's ref transaction API (`ref_store_transaction_begin()`, `ref_transaction_update()`, `ref_transaction_commit()`)
- New `handle_ref_update()` helper uses enum parameter and switch statement
- Comprehensive test coverage including config-driven behavior and CLI override precedence

The series has achieved full consensus on naming and design after maintainer review. Patch 1 refactors option validation, Patch 2 implements core atomic behavior, and Patch 3 adds the `replay.refAction` config option. All tests pass and documentation has been updated to reflect the new defaults and improved interface clarity.
