Refactoring patch eliminating the `current_ref_iter` global variable hack in the refs subsystem. This is part of Patrick Steinhardt's ongoing series to clean up and optimize the refactored reference handling code.

The patch removes the `current_ref_iter` global variable and its associated `peel_iterated_oid()` function, which were previously used as a performance optimization to avoid redundant object lookups during reference iteration. These are now obsolete since the series has introduced proper propagation of peeled object IDs through the new `struct reference` wrapper interface.

Key technical changes:
- Deletes the `peel_iterated_oid()` function from refs.c (10 lines)
- Removes `current_ref_iter` variable and its thread-unsafe manipulation from refs/iterator.c (5 lines)
- Eliminates the documentation of this hack from refs-internal.h (13 lines)
- Total 28 lines removed across 3 files

This change builds on previous patches that converted all callers to use the new `reference_get_peeled_oid()` interface instead. The removal of this global variable makes the code more robust and easier to understand while maintaining the same functionality through the cleaner reference wrapper approach.

The patch is part of the larger refs subsystem refactoring that includes interface changes, performance optimizations, and bugfixes. It specifically helps enable the final optimization patch (15/14) that makes object parsing lazy in ref-filter.
