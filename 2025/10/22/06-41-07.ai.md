Performance optimization and refactoring patch in the ref-filter subsystem, part of Patrick Steinhardt's larger refs modernization series.

This patch modifies the ref-filter code to preserve and utilize peeled object IDs when they're already available, rather than always re-peeling tags through the object database. The key changes are:

1. Adds a `peeled_oid` field to `struct ref_array_item` to store pre-peeled OIDs
2. Updates `ref_array_push()` and related functions to accept and propagate peeled OIDs
3. Modifies the tag peeling logic in `populate_value()` to first check for a pre-peeled OID before falling back to object database peeling
4. Updates callers in ls-remote, tag, and verify-tag to pass NULL for peeled OID (maintaining current behavior)
5. Simplifies the ref filtering interface by having `apply_ref_filter()` take a complete `struct reference` rather than individual fields

The changes enable future performance improvements by allowing peeled OIDs to be passed through from the ref iterator layer rather than being recomputed. This builds on the series' earlier refactoring work while maintaining all existing behavior. The patch touches 5 files with 66 lines added and 32 removed, primarily focused on the ref-filter implementation.

This is part of the series' second group (patches 3-9) that eliminates the `peel_iterated_object()` hack and introduces cleaner interfaces. The changes here are preparatory for patch 15's lazy object parsing optimization, though they provide independent value by reducing redundant peeling operations.
