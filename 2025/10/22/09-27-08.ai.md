This is a follow-up in the ongoing investigation of the NonStop platform's exit code anomaly in `git notes show`. Jeff King (peff@peff.net) provides technical analysis suggesting the observed -12 exit code may originate from the underlying `git show` call that `git notes show` executes via `execv_git_cmd()`, rather than from the notes subsystem directly. He notes the command actually runs `git show $(git notes list HEAD)` under the hood, with potential exit code propagation from `show_blob_object()`. 

Key technical details added: the pager might complicate exit code handling (suggesting testing with `--no-pager`), and confirmation that standard cases should return 0 when successfully showing the blob. The analysis implies the issue may involve either the pager's exit code preservation or `show_blob_object()`'s error paths, though Jeff couldn't reproduce the behavior on his system. This shifts focus slightly from the original notes-specific theory toward Git's general process execution and exit code plumbing, while maintaining the NonStop platform specificity established earlier in the thread.
