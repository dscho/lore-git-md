Refactoring patch in the `git rebase --trailer` series, focusing on trailer processing internals.

This patch reintroduces the `interpret_trailers()` helper function that was removed in a previous commit, consolidating the trailer processing logic that was previously duplicated in the command's file handling paths. The helper handles both in-place file editing and stdout output cases while maintaining the same error handling behavior. 

Key technical changes:
- Moves the strbuf initialization, trailer processing, and output writing into a single function
- Preserves all existing error cases (failed processing, missing input file for in-place)
- Keeps the same memory management pattern (strbuf cleanup)
- Maintains identical behavior for both file and stdin input paths
- Reduces code duplication between the file loop and stdin cases in cmd_interpret_trailers()

The change is part of the larger effort to refactor trailer handling in preparation for rebase integration, with this particular patch focusing on cleaning up the interpret-trailers command implementation. The patch appears mechanically sound, following the established patterns in the codebase while simplifying maintenance.
