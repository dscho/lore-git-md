Refactoring patch in a series modernizing Git's refs subsystem. This is patch 2/14 in Patrick Steinhardt's third revision of a performance optimization series that builds on earlier work separating transport-related refs from core ref handling.

The patch simplifies the ref iterator interface by replacing individual fields (refname, oid, flags) with a single `struct reference` member. This avoids repeatedly creating temporary reference structs when passing iterator results to callbacks. The change touches 8 files with 75 insertions and 100 deletions, mostly mechanical updates to use the new consolidated field.

Key changes:
- Base iterator now contains a `struct reference` instead of separate fields
- `should_pack_ref()` simplified to take the reference struct directly
- Updates all iterator implementations to populate the new field
- Maintains same functionality while reducing boilerplate

This is part of a larger effort to improve ref handling performance (particularly for `git-for-each-ref`) while cleaning up the architecture. The series has already identified some deeper issues around tag peeling that will be addressed in later patches. This particular change is a straightforward refactoring that enables cleaner interfaces in subsequent work.
