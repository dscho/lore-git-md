This is the final performance optimization patch in a refactoring and optimization series, focusing on lazy object parsing in `ref-filter.c`. The patch introduces a new `get_or_parse_object()` helper function that delays parsing object contents until actually needed, building on the series' earlier separation of `struct ref` and `struct reference`.

Key technical elements:
- Adds `maybe_object` field to `struct expand_data` to cache parsed objects
- New `get_or_parse_object()` helper centralizes object parsing logic with error handling
- Maintains existing error reporting through `strbuf` parameter
- Benchmarks show 13% speedup for `git for-each-ref --format='%(raw)'` operations

Junio Hamano suggests potential ergonomic improvements to the helper's calling convention, noting the repeated pattern of checking return values and type-casting. He proposes simplifying the call sites by having the object pointer be the direct return value when possible. However, he explicitly states these are optional refinements and approves the patch as-is, praising its alignment with `ref-filter.c`'s original goal of minimizing unnecessary work.

The patch is now being queued for integration, marking the conclusion of this performance-focused series that has progressed through multiple rounds of review and rebasing. The series combines architectural improvements with measurable performance gains while maintaining compatibility with both files and reftable backends.
