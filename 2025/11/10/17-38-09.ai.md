This is a discussion about the proposed `--committer` option for `git commit`, focusing on whether the feature is justified given existing mechanisms.

Junio C Hamano expresses skepticism about the need for a `--committer` option, contrasting it with the more established use case for `--author`. While acknowledging that Git traditionally gives users flexibility (including the "rope to hang themselves"), he questions whether making committer overrides more ergonomic is desirable. The key distinction is that author overrides serve legitimate human needs (like attributing work to others), whereas committer overrides primarily benefit scripting scenarios - which already have the `GIT_COMMITTER_*` environment variables as a dedicated interface.

This response shifts the debate from technical implementation (which was addressed in v2) to fundamental design philosophy. Hamano implies that unless proponents can demonstrate compelling human-facing use cases that aren't well-served by existing mechanisms, the feature may represent unnecessary interface expansion. The thread now hinges on whether the symmetry argument and scripting convenience outweigh potential misuse concerns and interface bloat.
