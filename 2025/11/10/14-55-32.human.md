This is a post-merge review comment on the final patch of Junio C Hamano's series that introduced and enforced incomplete-line whitespace checking across Git's codebase. Phillip Wood acknowledges the change to add `incomplete` to the whitespace rules for C/header files and shell scripts, but raises a follow-up question about whether we should also apply this check to documentation files.

The series didn't modify the default whitespace rules (WS_DEFAULT_RULE) to include incomplete-line checking, so documentation files would only be checked if explicitly included via attributes. Phillip's question suggests this might be an oversight worth considering, though he doesn't push strongly for a change - it's posed as an open question rather than a requested modification.

This continues the pattern of Phillip providing thoughtful, detailed feedback even after the series has been merged, focusing on completeness and consistency in the whitespace handling implementation. The core functionality is already in place and working as intended, but there may be room to expand the coverage to additional file types.
