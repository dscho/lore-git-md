This is a discussion thread about a proposed feature to add a `--committer` option to `git commit`, mirroring the existing `--author` option. Phillip Wood questions the practical need for this feature, noting that while the implementation looks technically sound (as shown in the previous review discussion), he's skeptical about real-world use cases where someone would need to specify different committer identities within a single repository. He suggests that existing mechanisms like per-repo config or environment variables already cover scripted workflows.

The thread shows healthy skepticism about feature creep, with Phillip raising valid questions about whether this addition solves a problem that actually needs solving. The original patch author ZheNing Hu had proposed four benefits (consistency, convenience, script support, and multi-identity management), but Phillip's response suggests these may not justify the added complexity for most users. This exchange represents the kind of design discussion that often happens around new options - even well-implemented ones need to demonstrate clear user benefit.
