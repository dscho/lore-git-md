Feature addition to `git commit` adding `--committer` option symmetry with `--author`. This v2 patch implements all technical feedback from the initial review while the thread now focuses on justifying the feature's necessity.

The patch adds a `--committer` option to `git commit` that mirrors the existing `--author` functionality, allowing command-line override of committer identity. It refactors identity handling code to share infrastructure between author and committer paths, with:
- New `find_identity_by_nickname()` replacing `find_author_by_nickname()`
- Consolidated `determine_identity()` replacing separate author/committer functions
- 8 new tests in t7509 covering basic override, pattern lookup, malformed input, amend behavior, environment interaction, and date handling

Key technical details:
- Accepts same formats as `--author`: explicit "Name <email>" or commit pattern lookup
- Maintains precedence chain: command line > environment > config > automatic
- Properly handles date overrides when specified in committer string
- Exports GIT_COMMITTER_* variables when overridden
- Documentation placed adjacent to `--author` in git-commit.adoc

The implementation follows established patterns but the thread has shifted to debating whether the feature provides sufficient value beyond existing identity management methods (environment variables, per-repo config). While technically sound with comprehensive test coverage, the patch now needs stronger justification for why current mechanisms are insufficient for scripted workflows or identity switching scenarios.
