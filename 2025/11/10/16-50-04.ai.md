This is a feature proposal for adding a `--committer` option to `git commit`, mirroring the existing `--author` functionality. Phillip Wood raises a question about the practical use case for overriding committer identity within a single repository, suggesting that existing mechanisms (config per-repo or environment variables) may already suffice for scripted workflows.

The technical implementation in the patch adds parallel infrastructure to handle committer identity similarly to author identity, including:
- New `force_committer` static variable and `determine_committer_info()` function in `builtin/commit.c`
- Same format parsing as `--author` (explicit "Name <email>" or commit lookup pattern)
- Precedence chain: command line > environment > automatic
- Comprehensive test coverage in t7509 (8 new tests verifying basic override, pattern lookup, malformed input, amend behavior, environment variable interaction, and date handling)

Key points for future thread context:
- The debate centers on whether command-line committer override provides sufficient added value beyond existing identity management methods
- Implementation follows established patterns from author handling
- Tests demonstrate all edge cases would be handled consistently with author behavior
- Documentation places the new option adjacent to `--author` in git-commit.adoc

The question shifts focus from implementation details (which were resolved in review) to the fundamental motivation, potentially requiring the original author to articulate more compelling real-world scenarios where environment variables or per-repo configs would be insufficient.
