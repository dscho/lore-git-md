This is a design discussion email in the submodule gitdir path encoding series, where Junio Hamano provides feedback on the case-folding collision detection approach. The email focuses on simplifying the implementation by suggesting a more robust filesystem-based solution rather than textual comparison.

Junio questions the current complexity of the case-folding detection that compares directory names, proposing instead to simply attempt creating the directory and handle failures (like EEXIST) as the trigger for name tweaking. He suggests this would naturally handle all collision cases, including the final edge case of all-lowercase conflicts, without special casing.

The email raises several important technical considerations:
1. The solution should work symmetrically regardless of addition order (Foo vs foo)
2. Current approach may not handle Unicode canonicalization collisions
3. Filesystem operations (mkdir) as the single source of truth would cover all cases
4. The mechanism should be consistent whether dealing with case-folding or other filesystem limitations

Junio's feedback indicates the architectural direction is sound but implementation could be simplified by relying more directly on filesystem operations rather than preemptive checks. This aligns with the series' goal of comprehensive collision protection while maintaining the opt-in `extensions.submoduleEncoding` config approach. The discussion continues converging on the automatic suffix solution ("foo2" or "foo_") as the fallback when direct creation fails.
