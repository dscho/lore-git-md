This is a code review of a refactoring patch in the `git fetch` tag handling bugfix series. Patrick Steinhardt suggests simplifying the control flow in the newly introduced `commit_ref_transaction()` helper by using a `goto` pattern rather than nested conditionals.

The proposed change would restructure the function to:
1. Attempt the transaction commit first
2. If it fails, jump straight to cleanup
3. Only proceed with non-atomic transaction handling if the commit succeeded
4. Unify cleanup in a single `out:` label

Steinhardt argues this makes the function "significantly easier to read" by eliminating the need to mentally track when the transaction` pointer might be NULL. The suggestion comes as part of final polishing for this preparatory refactoring patch before the functional fix in patch 2/2.
