This is a discussion about the proposed `--committer` option for `git commit`, which would mirror the existing `--author` functionality. Junio C Hamano pushes back on the feature's justification, questioning whether making it easier to override committer identity is actually desirable.

The thread had previously seen technical approval from Patrick Steinhardt, with the v2 patch implementing all requested code improvements. However, Junio raises fundamental concerns about the feature's purpose - while author overrides have clear use cases (like attributing work to others), he argues committer overrides are more questionable. He notes the existing `GIT_COMMITTER_*` variables already serve scripted use cases where identity override might be legitimate.

The core disagreement centers on whether symmetry with `--author` alone justifies the new option, or if there are compelling real-world scenarios where environment variables and per-repo configs would be inadequate. Junio's skepticism suggests this feature may face an uphill battle unless proponents can articulate stronger use cases beyond convenience. The patch appears technically sound but may need clearer justification to overcome maintainer concerns about encouraging potentially problematic workflows.
