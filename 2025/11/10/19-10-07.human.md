This is a discussion about the final edge case in the submodule gitdir path encoding series, focusing on case-folding collision detection. Junio Hamano responds to Adrian Ratiu's approach for handling case conflicts in submodule directories, suggesting a simpler solution.

Junio proposes replacing the current text-based case-folding logic with a more robust "try-and-retry" approach using `mkdir(2)`. Instead of preemptively checking for case conflicts, the system would simply attempt to create the directory and only apply encoding or suffixing (like "foo2" or "foo_") if the operation fails. This would naturally handle all conflict cases - whether from case-folding, Unicode canonicalization, or other filesystem quirks - with a single unified mechanism.

The email highlights two key advantages of this approach: it eliminates special-case handling for uppercase letters (making the code simpler and more consistent), and it would automatically extend to other filesystem collision scenarios like Unicode normalization. Junio also notes this maintains user expectations by handling conflicts symmetrically regardless of which submodule is added first.

This represents the final architectural refinement in the long-running submodule encoding effort, with all major technical questions now resolved. The implementation will need to track successfully created directories to avoid redundant checks, but the core idea aligns with the series' goal of robust, automatic conflict resolution while keeping the config opt-in.
