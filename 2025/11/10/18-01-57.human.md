This is a discussion about the proposed `--committer` option for `git commit`, which would mirror the existing `--author` functionality. The thread has shifted from implementation details to debating whether the feature is actually needed.

Brian M. Carlson responds to Phillip Wood's skepticism about use cases for overriding committer identity, providing several concrete scenarios where someone might need to switch between different committer addresses in the same repository. These include working on the same project under both personal and corporate identities (as Carlson does with Git itself), contributing to projects with CLA-mandated email addresses (like Google's requirement for Gmail addresses), and maintaining business logs requiring different identities for different types of transactions.

The examples aim to address the core objection raised by Junio Hamano and others - that committer overrides primarily benefit scripting (which could use environment variables) rather than human users. Carlson's response attempts to show legitimate human-facing use cases where the proposed `--committer` option would be more convenient than current alternatives like environment variables or per-repo configs.

The quality of the response is solid - it provides specific, plausible scenarios that go beyond just symmetry with `--author`. However, it remains to be seen whether these examples will satisfy those questioning whether the feature's benefits justify expanding Git's interface. The discussion continues to hinge on whether these use cases are common enough to warrant the new option.
