This is a follow-up in the submodule gitdir path encoding series, addressing case-folding filesystem collisions. Adrian Ratiu responds to Junio Hamano's feedback about simplifying the collision detection approach.

The key discussion point is whether to use filesystem operations (mkdir) as the primary collision detection mechanism, as Junio suggested. Adrian explains why a direct mkdir approach isn't sufficient - because `submodule_name_to_gitdir()` is called for all submodules (existing or new), we can't rely solely on mkdir failures to detect conflicts. The current double-test approach using case-folding and path validation is more reliable for detecting when two paths would collide on case-insensitive filesystems.

Adrian agrees with Junio that the solution should work symmetrically regardless of whether "Foo" or "foo" is added first. He proposes handling conflicts through an automatic retry mechanism with exponentially decreasing probability of further conflicts (e.g., trying "foo2", "foo_", etc.), falling back to hashing if needed. This addresses Aaron Schrab's earlier concern about order-dependent behavior.

The email also notes that while the solution doesn't need to handle every possible edge case perfectly, it significantly improves the status quo. Adrian plans to add more test cases in v5, including one for the "Foo/foo/%46oo" scenario. The discussion shows the implementation is converging toward a robust solution that handles both case-folding and Unicode canonicalization issues through this retry-based approach.
