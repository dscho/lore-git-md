This is a post-merge review comment on patch 04/12 from Junio's completed series introducing whitespace handling for incomplete lines (missing newlines at end of file). Phillip Wood questions the logic of incrementing line counters when processing the "\ No newline at end of file" annotation in diffs.

Phillip points out that since this annotation describes the previous line's state, it shouldn't increment any line counters at all. This differs from Junio's approach in the patch which tracks the previous line type ('+', '-', or ' ') to determine which counters to increment. The patch was already merged as part of the larger series, but Phillip's comment suggests there may be room for simplification in how line numbers are handled for incomplete line annotations.

The exchange shows the typical Git project workflow where even post-merge, experts like Phillip (a diff subsystem maintainer) review changes in their areas of specialty. While this doesn't indicate a functional problem (the series is merged and working), it highlights an area where the implementation might be more complex than necessary.
