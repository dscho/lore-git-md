This thread is discussing improvements to the interactive patch command interface (used by `git add -p`, `git reset -p`, and similar commands) to better indicate selection state during interactive sessions. The original patch by Abraham Samuel Adekunle added `[selected]`/`[deselected]` indicators to hunk prompts, but Junio Hamano pointed out several broader issues with this approach.

The discussion has revealed that the problem affects all interactive commands sharing this prompt machinery, not just `git add -p`, and applies to all prompt types (not just hunks). There's agreement that the current indicator placement breaks the established input flow, where choices should appear immediately before the question mark. The terminology ("selected"/"deselected") may also not clearly map to the internal USE/SKIP states.

Abraham has acknowledged these concerns and indicated they'll work on a revised solution that addresses the broader scope while maintaining UI clarity. They're considering more explicit phrasing like "previous decision: stage/skip" and will need to solve the challenge of providing consistent feedback across all interactive commands without disrupting the user experience. The next steps will involve designing an implementation that works for the entire prompt system while respecting display width constraints.
