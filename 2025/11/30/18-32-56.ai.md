This is a follow-up discussion on the `git add -p` hunk selection feedback UI improvement. Junio C Hamano provides detailed feedback on Abraham Samuel Adekunle's patch that added `[selected]`/`[deselected]` indicators to hunk prompts.

The key points raised are:
1) The issue affects other interactive commands like `git reset -p` that share the same prompt machinery, not just `git add -p`
2) The same feedback need exists for mode changes and other non-hunk prompts, not just hunks
3) The current placement of the state indicator after the prompt choices breaks the established pattern of having user input immediately follow the choices
4) The terms "selected"/"deselected" may not clearly convey the actual state (USE/SKIP)
5) The ideal solution would show the previous decision more explicitly (e.g. "you previously decided to use it") without being too verbose

The feedback suggests the current implementation is too narrowly focused on hunks and doesn't fully address the underlying usability issue across all prompt types. Junio proposes considering a solution that works consistently for all prompt modes while maintaining good UI flow. The discussion indicates this will require more design work to balance clarity and conciseness in the feedback mechanism.
