This is a bugfix patch in Jeff King's ASan findings series, converting cache-tree.c to use the new `parse_int_from_buf()` utility function introduced earlier in the series. The patch replaces a custom integer parser that lacked overflow checking with the more robust buffer-safe parser that properly validates input ranges and handles non-NUL-terminated buffers.

The change simplifies the code significantly, reducing 23 lines of custom parsing logic to just 5 lines that call the new utility function. The local `parse_int()` wrapper remains to manage the buffer pointer/length tracking, but now delegates the actual parsing work to the shared implementation. This maintains the same interface for callers while gaining the safety benefits of the centralized parser.

The commit message notes this fixes an existing issue where the original `strtol()`-based parser didn't catch overflow, though that wasn't considered critical since the cache-tree format is only used locally. The new version inherits the overflow checking and other safety features of `parse_int_from_buf()` while keeping the same behavioral contract with callers.

This patch builds on the parsing utilities infrastructure established earlier in the series, demonstrating their practical application in converting real code. It follows the pattern seen in other conversions (fsck.c was similarly updated) and maintains the series' focus on memory safety and undefined behavior prevention. The change is straightforward and low-risk since it doesn't modify the cache-tree format or behavior - it just uses a more robust parsing implementation.
