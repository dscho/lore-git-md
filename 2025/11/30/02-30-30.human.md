Bugfix for `git diff --max-depth` with merge commit comparisons.

Han Jiang reports a case where `git diff --max-depth` fails with a "fatal: object is not a blob" error when comparing a merge commit with its parents. The issue occurs when the specified depth would normally show no output (as the differences are deeper than the cutoff), but instead triggers an error. The problem appears consistently across different path specifications and depth values.

The bug manifests in a test repository with a merge commit containing changes in deep subdirectories. While regular `git diff` works fine, the `--max-depth` variant fails when the merge's parents are specified. The expected behavior would be to show nothing (when the diff is too deep) or a combined diff (when within depth limits), but instead the command errors out.

This appears to be a Windows-specific issue (reported on git 2.52.0.windows.1), though the underlying cause isn't immediately clear from the report. The bug seems serious enough to affect basic diff functionality when working with merge commits and path limits, though the narrow trigger conditions (requiring both merge commits and specific depth settings) may limit its impact.

The report is thorough, providing clear reproduction steps and expected/actual behavior comparisons. This should help maintainers quickly verify and address the issue. The problem appears to be a genuine bug rather than a usage error, though we'd need to see the actual fix to understand whether it's a Windows-specific quirk or a more general issue with the depth-limiting logic.
