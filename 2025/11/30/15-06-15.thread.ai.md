UI improvement for interactive patch commands (`git add -p`, `git reset -p` etc.) feedback system. Original patch by Abraham Samuel Adekunle added `[selected]`/`[deselected]` indicators to hunk prompts in `add-patch.c` by checking `hunk->use` flag (USE_HUNK/SKIP_HUNK), modifying only PROMPT_HUNK type prompts. Junio C Hamano's feedback identifies broader scope: 1) Issue affects all interactive commands sharing prompt machinery 2) Need exists for all prompt types (mode changes, non-hunk prompts) not just hunks 3) Current indicator placement after choices breaks input-flow convention 4) "selected"/"deselected" terms may not clearly map to USE/SKIP states 5) Suggests more explicit phrasing like "you previously decided to use it". Open questions: how to design consistent feedback across all prompt types while maintaining UI flow clarity, whether to adjust terminology to better match internal states, and how to position indicators without disrupting input patterns. Core challenge is extending solution beyond original hunk-focused implementation to address the fundamental usability issue in the shared prompt system.
