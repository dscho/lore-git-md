This is a developer experience report about the clar unit test framework, coming from Jeff King after writing tests for his parsing utilities series. The email documents several pain points encountered while using clar for the first time, focusing on test debugging and output issues.

Key technical complaints include:
- Uninformative error messages from test helpers, requiring manual line number cross-referencing
- Lack of context in assertion failures, making it hard to identify which input case failed
- Verbose boilerplate when splitting test cases into separate functions
- A bug with cl_assert_equal_i_fmt() that caused UB with certain compilers/optimizations
- Missing type-agnostic assertion macros for non-int comparisons
- CI integration problems where test output gets mangled by prove's TAP parser
- Lack of --verbose-log support in clar's test runner

The email suggests potential improvements like automatic context tracking, better assertion macros, and TAP output handling, but presents them as observations rather than concrete proposals. This appears to be a post-implementation retrospective rather than part of the active patch series discussion, though it relates to the testing infrastructure used by the recently completed parsing utilities work. The tone is constructive but clearly frustrated with some of clar's rough edges.
