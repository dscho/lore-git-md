This is a refactoring patch that changes the return type of several parsing functions in parse.[ch] from `int` to `bool`. The functions previously returned 1 for success and 0 for failure, which is the opposite of Git's usual convention where 0 means success. The change makes the same semantic return values clearer through type system without requiring any caller updates.

The patch modifies all numeric parsing functions in parse.c (git_parse_signed, git_parse_unsigned, git_parse_int, git_parse_int64, git_parse_ulong, git_parse_ssize_t, git_parse_double) to return bool instead of int. The header file declarations are updated to match. The actual logic remains identical - only the type signatures change. The patch is cleanly separated from the rest of the ASan-related work in the series, as noted in the commit message.

This change improves code clarity by making the return convention more explicit through types rather than documentation. It follows Git's general pattern of using bool for boolean returns while maintaining backward compatibility since the truth values remain the same. The patch is straightforward with no expected controversy, though it touches many lines due to the mechanical nature of the change.
