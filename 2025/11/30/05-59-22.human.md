This is a test fix in Johannes Schindelin's ongoing series to improve Windows symlink handling in Git's test suite. The patch addresses a specific issue in t0001-init.sh where `git diff --no-index` (used by `test_cmp` on Windows) doesn't resolve symlinks as expected, causing test failures.

The test checks if re-initializing a repo with `--separate-git-dir` correctly creates a symlink, but fails on Windows because `diff --no-index` shows the symlink target rather than the link itself. Junio Hamano suggests an alternative approach - using `cmp` directly when `--no-index` is detected - rather than skipping the comparison entirely as in the current patch.

This is part of a larger effort to make Git's test suite work properly with Windows symlinks in preparation for MSYS2's planned default enablement of symlink support. The discussion here highlights the subtle differences in symlink handling between platforms and the test infrastructure's assumptions. The patch appears technically sound, though the maintainer suggests a potentially better solution that maintains test coverage while working around the Windows-specific behavior.
