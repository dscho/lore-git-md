This is a UI improvement patch for `git add -p`, addressing a usability issue in the interactive hunk selection interface. 

The patch modifies the hunk selection prompt to show whether each hunk is currently selected or deselected when navigating between hunks with K/J keys. Currently there's no visual feedback about the selection state during navigation, which can be confusing. The change adds "[selected]" or "[deselected]" indicators to the prompt based on the hunk's current state.

The implementation touches only `add-patch.c`, adding conditional logic to display the state while maintaining all existing functionality. The change was requested by Junio Hamano, suggesting it addresses a real pain point in the interactive workflow. The patch appears focused and well-contained, with a clear commit message explaining both the problem and solution.

This seems like a straightforward quality-of-life improvement that should make the interactive staging interface more user-friendly, particularly for complex changes with many hunks. The implementation looks clean and maintains the existing code structure while adding the new functionality.
