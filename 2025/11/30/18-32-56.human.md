This is a follow-up discussion on a UI improvement for `git add -p`'s hunk selection feedback. Junio C Hamano provides detailed feedback on Abraham Samuel Adekunle's patch that added visual state indicators (`[selected]`/`[deselected]`) to hunk prompts.

The feedback raises several concerns: (1) the issue affects other interactive commands like `git reset -p` too, (2) the same problem exists for non-hunk prompts (like mode changes), and (3) the current implementation disrupts the prompt's visual flow by inserting state after the choices. Junio suggests the wording could be more direct than "selected/deselected" and proposes alternative phrasing that makes the previous decision clearer ("you previously decided to use/skip it").

The response indicates the current patch doesn't fully address the underlying usability problem while introducing some UI awkwardness. This appears to be mid-thread design feedback rather than a final verdict, suggesting the author may need to revisit the approach to handle all prompt types more consistently and elegantly.
