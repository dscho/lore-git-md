This is a refactoring and utility function addition that builds on the ongoing ASan hardening work. Jeff King (peff) introduces new parsing functions for reading integers directly from buffers (rather than NUL-terminated strings), addressing concerns raised in the cache-tree parsing safety discussion.

The 4-patch series:
1. Converts boolean return values from `int` to `bool` in parsing functions
2. Adds new `parse_int_from_buf()` and `parse_unsigned_from_buf()` functions
3. Updates cache-tree code to use the new buffer-parsing functions
4. Converts fsck timestamp parsing to use the new functions

The changes stem from Junio Hamano's preference for more explicit validation over clever arithmetic tricks, though both agree the security risk here is low (since it only handles local index files). The new functions provide a cleaner way to parse integers from buffers without NUL-termination, with thorough documentation of the design decisions. The implementation includes unit tests and works with both Makefile and Meson builds.

This appears to be a well-considered solution that addresses the parsing safety concerns while providing reusable utilities. The changes are focused and maintainable, though the thread suggests there may still be discussion around whether to pursue a more radical cache-tree format change instead. The series builds on the ASan work but stands alone as a quality-of-life improvement for integer parsing.
