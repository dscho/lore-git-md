This thread covers a series of performance optimizations to Git's diff machinery, specifically targeting copy detection across `diff-index`, `diff-files`, and now `diff-tree` commands. The work originated with René Scharfe, who introduced the `diff_same()` optimization for `diff-index`, showing measurable speedups by avoiding redundant operations when files are unchanged. Junio Hamano reviewed and approved this initial work, noting its potential applicability to other diff commands.

The optimization has been systematically extended: first to `diff-files` (fixing a long-standing copy detection bug from 2008 in the process), and now to `diff-tree`. The latest patch adds a `keep_fn_t` callback to the diff API to support this, completing the optimization's coverage across Git's core diff commands. While the gains for `diff-tree` are more modest than the original 1.33x speedup seen with `diff-index` (showing between 5% speedup to 1% slowdown depending on the test case), the changes maintain architectural consistency and close out this line of optimization work.

The changes touch several key areas of the diff machinery - from the core logic in `diff.c` to command-specific handling in `tree-diff.c` - while carefully maintaining the existing API structure. Test coverage has been expanded throughout the series, particularly around edge cases in preloading behavior. All patches are now queued for inclusion, representing a complete solution to copy detection inefficiencies across Git's diff commands.
