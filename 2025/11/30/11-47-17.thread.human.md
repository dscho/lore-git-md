This thread covers a series of performance optimizations for Git's copy detection across diff commands, building on René Scharfe's original work. The effort began with a 1.33x speedup in `diff-index` operations by using reference-counted filespecs and skipping redundant operations, which Junio Hamano confirmed met maintainer standards. The work then expanded to fix a long-standing 2008 bug in `diff-files` affecting index-to-working-tree comparisons.

The latest patch completes the series by extending these optimizations to `diff-tree`, introducing a new `keep_fn_t` callback in `struct diff_options`. While this maintains architectural consistency with the earlier work, benchmark results are more modest - showing neutral performance (1.00-1.01x speed) in the Linux repo test case with a slight memory reduction from ~36MB to ~35MB. This suggests the benefits may be command-specific, with tree-to-tree comparisons presenting different optimization challenges than index/worktree operations.

The changes span multiple subsystems including `diff-lib.c`, `diff.c`, `tree-diff.c`, and header files, with careful attention to maintaining the callback chain architecture. The series now provides optimized copy detection across all major diff commands, addressing both performance and long-standing testing gaps in preloading mechanisms.
