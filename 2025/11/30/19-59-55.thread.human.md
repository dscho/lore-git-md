This thread discusses adding a `-z` flag to `git repo structure` to support null-terminated output, matching similar behavior in other Git commands like `git-config`. The initial patch proposed implementing this as an alias for `--format=nul`, following the pattern from `git-repo-info`.

Junio Hamano reviewed the patch, suggesting improvements to the documentation formatting and test cases. He noted the test should directly check `-z` rather than `--format=nul` and raised the question of whether to test combined option behavior ("last one wins").

Patrick Steinhardt responded, defending the current documentation approach by pointing to consistency with `git repo info`, where options can combine with the last one taking precedence. He agreed with correcting the test case and proposed adding a test for the combined behavior, similar to how it's handled in `git repo info`. 

The discussion remains focused on implementation details, with agreement on most technical points but leaving open whether to implement the additional test case. The changes affect `builtin/repo.c`, documentation, and test files, building on recent work in the codebase. Both maintainers are engaged in refining the patch's technical correctness and consistency with existing conventions.
