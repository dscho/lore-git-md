This is a refactoring patch that changes the return type of several parsing functions in parse.[ch] from `int` to `bool`. The functions currently use `1` for success and `0` for failure, which is the opposite of Git's usual convention where `0` means success. While this works, it can be confusing since most other functions follow the standard convention.

Jeff King proposes switching to `bool` to make the return value semantics clearer, since `true`/`false` more obviously indicate success/failure than `1`/`0`. The change is purely about code clarity - the behavior remains exactly the same, and no callers need to be updated. The patch touches both the function declarations in parse.h and their implementations in parse.c, converting all the numeric parsing functions (signed, unsigned, int, double, etc.) to use bool returns.

This is a straightforward quality-of-life improvement that makes the code more readable without changing any functionality. It's part of a larger series about parsing utilities, but stands on its own as a sensible cleanup. The change is mechanical and low-risk, affecting only internal implementation details rather than any external interfaces.
