Bugfix for `git diff --max-depth` behavior with merge commits.

This report identifies a fatal error that occurs when using `git diff --max-depth` to compare a merge commit with its parents. The issue manifests when the specified depth limit causes Git to attempt diffing tree objects as if they were blobs, resulting in the error "fatal: object '...' is not a blob!".

The reporter provides a clear reproduction scenario involving a merge commit with deep directory structures. Key observations:
- The error occurs with specific depth limits (--max-depth=5 for root diff, --max-depth=4 when starting from subdirectory)
- The command works as expected with deeper limits (--max-depth=6)
- The expected behavior would be either showing a combined diff or no output, not an error

The bug appears to be in the depth-limiting logic's handling of tree objects during merge commit comparisons. The report includes comprehensive system information showing the issue occurs on Windows with Git 2.52.0, though the problem is likely platform-independent.

This looks like a legitimate bug in edge-case handling that could affect users trying to limit diff output depth when examining merge commits. The report is well-structured with clear reproduction steps and expected/actual behavior comparisons, making it easy to verify.
