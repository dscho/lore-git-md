This is part of Jeff King's ongoing series to improve parsing safety and establish reusable parsing utilities, building on earlier ASan findings. The patch introduces new functions in parse.c for safely parsing integers from non-NUL-terminated buffers, addressing a gap where existing string-based parsers could cause buffer overruns or ASan complaints.

The core additions are `parse_int_from_buf()`, `parse_signed_from_buf()`, and `parse_unsigned_from_buf()`, which handle bounds checking, overflow detection, and whitespace/sign parsing while returning both the parsed value and an end pointer. The implementation avoids temporary buffers by parsing digits directly, with careful overflow handling that assumes two's complement behavior (consistent with Git's existing parsers). The interface follows Git's bool-return convention rather than the strtol() errno pattern.

Key technical details include:
- Base-10 only (no hex/octal support)
- No unit suffixes (unlike git_parse_int)
- Requires non-NULL end pointer (unlike strtol)
- Includes comprehensive unit tests covering edge cases
- Build system updated to compile new test file
- The functions will be used immediately for cache-tree and fsck parsing
- Follows same error handling patterns as git_parse_int()
- Assumes negative range is one larger than positive (like git_parse_int)
- Documented assumptions about two's complement behavior

This is a well-considered addition to Git's parsing utilities, with thorough documentation and test coverage. The patch appears ready for integration as part of the larger series, which Junio Hamano has already approved. The only outstanding question is whether to incorporate Phillip Wood's pending parse_int() refinements, but that doesn't block this change.
