Follow-up discussion on `git clone -c` whitespace regression:

This is a continuation of the thread about the regression in `git clone` config parsing where whitespace around keys in `-c` arguments (like `'-c KEY=VALUE'`) stopped working in Git v2.52.0. Jeff King and Junio C Hamano are discussing whether to maintain backward compatibility for this behavior, which was originally an undocumented quirk rather than an intentional feature.

The discussion has reached consensus that the change should stand as an intentional correction of broken behavior, though Jeff notes some concern about impact on tools like Git LFS that may have relied on the old behavior. Junio humorously indicates he's not strongly motivated to fix it, and Jeff agrees while acknowledging the breakage might prompt affected tools to update their invocations.

Key points:
- The original whitespace-trimming behavior violated Git's config key format rules
- Similar behavior was already broken in other contexts since 2021 without notice
- While some tools may be affected, the change is seen as correcting long-standing technical debt
- No deprecation period or transitional measures are planned

The thread appears to be winding down with agreement to leave the stricter parsing in place, treating this as a bugfix rather than a regression needing mitigation.
