Performance optimization patch addressing inefficiency in `diff-index` when using `--find-copies-harder`. The current implementation unnecessarily allocates duplicate filespecs and performs redundant work for unchanged file pairs when this flag is set.

René Scharfe introduces a new `diff_same()` function that handles unchanged file pairs more efficiently by:
1. Allocating only a single filespec (reused via reference counting)
2. Skipping unnecessary operations that `diff_change()` performs
3. Avoiding misleading `has_changes` flag setting for unchanged files

The patch shows measurable improvements in the Linux repository benchmark - about 1.33x faster for `git diff --cached --find-copies-harder`. Changes are focused in `diff-lib.c` (logic change in `show_modified()`), `diff.c` (new `diff_same()` implementation), and `diff.h` (new function declaration).

This appears to be a well-motivated optimization targeting a clear performance bottleneck. The commit message provides concrete benchmark numbers and explains both the problem and solution clearly. The change is relatively contained, touching only the diff machinery without broader impacts. The v2 revision improved the memory usage description based on previous feedback.
