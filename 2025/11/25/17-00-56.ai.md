Feature addition to `git replay` introducing server-side revert capability. This single-patch implementation adds a `--revert` option that mirrors `git revert` functionality but operates directly on bare repositories, primarily targeting GitLab's Gitaly service to avoid client-side roundtrips.

The core mechanism swaps the merge operation arguments when processing commits - where cherry-pick merges parent->commit, revert merges commit->parent. This reuses existing merge infrastructure while reversing the diff direction. The patch introduces `sequencer_format_revert_header()` to share message generation between sequencer and replay, producing standard "Revert"/"Reapply" prefixes with original commit SHAs. Revert commits use the current user as author rather than preserving original authorship.

Key implementation details include:
- New `--revert` flag documented in git-replay.adoc with usage examples
- Incompatibility with `--contained` to prevent cross-branch inconsistencies
- Comprehensive test coverage in t3650-replay-basics.sh for basic reverts, revert-of-revert cases, conflicts, and multi-commit ranges
- Shared sequencer utilities while maintaining replay's simpler server-side focus

The change touches builtin/replay.c (main logic), sequencer.{c,h} (shared utilities), and documentation, with careful attention to existing behavior patterns. Test cases verify both happy paths and edge cases like conflict handling.
