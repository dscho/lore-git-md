Bugfix proposal for `git clone` config parsing regression:

Johannes Schindelin proposes a fix for the recently reported regression where `git clone -c` and `--config` arguments with whitespace around keys stopped working in v2.52.0. The patch introduces a new `STRING_LIST_SPLIT_TRIM_FIRST` flag to selectively trim whitespace only from the first part (the key) of config parameters during parsing, while leaving the value untouched.

The change modifies three files:
- `config.c` to use the new flag when splitting config parameters
- `string-list.c` to implement the new trimming behavior
- `string-list.h` to define the new flag constant

This would restore the pre-v2.52.0 behavior where whitespace around keys was automatically trimmed, while maintaining the current handling of values. The patch comes in response to reports that the regression is breaking real-world usage, including Git LFS workflows.

The implementation approach differs from the historical behavior by being more explicit about which parts get trimmed, rather than silently trimming both key and value. This aligns better with Git's config specifications while maintaining backward compatibility for the key-trimming case that existing scripts rely on.

The thread context shows this follows extensive analysis by Jeff King and Junio Hamano about the historical behavior being an accidental feature that violated config key format rules. Schindelin's patch attempts to balance backward compatibility with cleaner implementation by making the trimming behavior intentional and properly documented through the new flag.
