This is a feature addition to the `git replay` command, introducing a `--revert` option for server-side revert operations. The patch extends `git replay` to support reversing commits directly on bare repositories, primarily targeting GitLab's Gitaly service to eliminate client-side roundtrips.

The implementation cleverly reuses the existing cherry-pick infrastructure by swapping the base and pickme trees in merge operations while preserving all the existing handling for conflicts and atomic transactions. The patch includes comprehensive test coverage in t/t3650-replay-basics.sh that verifies various scenarios including conflict cases, multiple commits, and proper handling of revert-of-revert cases (which generate "Reapply" messages).

The documentation clearly explains the new option and its relationship to standard revert operations, with examples showing both `--onto` and `--advance` usage patterns. The implementation appears well-considered, with careful attention to maintaining consistency with `git revert` behavior while working within `git replay`'s server-side constraints.
