The thread discusses Wiktor Mis's patch series (now at v2) to add bash completion for Git's short options (-C, -P, -c, -h, -p, -v) when typing `git -<TAB>`. Junio C Hamano had initially reviewed and signed off on the technical implementation while noting an open question about whether completion should cover both short and long options together. The patch appeared headed for inclusion with minor commit message adjustments.

SZEDER Gábor has now raised substantive concerns about the feature's value, questioning whether short option completion meaningfully improves either efficiency (since it doesn't save keystrokes) or discoverability (given that single-letter options aren't self-documenting). This shifts the discussion from implementation details to whether the feature should exist at all. While not rejecting the patch outright, SZEDER's critique introduces skepticism that wasn't present in the thread's initial positive reception. The ball is back in the author's court to either justify the feature's benefits more strongly or reconsider the approach. The technical details of the patch remain sound, but its inclusion now depends on whether the project agrees the functionality provides sufficient user benefit.
