This is a follow-up in the build system thread about artifact handling in `make strip`, now touching on CMake/meson considerations.

Johannes Schindelin responds to Junio Hamano's suggestion for a broader Makefile restructuring to handle build artifacts more cleanly. While agreeing with the Makefile changes, Johannes notes that meson appears to handle stripping automatically via a `--strip` option, and questions whether CMake support is still needed at all given meson's adoption.

The email reveals two key points about the build system landscape: First, that meson is now considered Git's "modern build setup" (with CMake potentially being deprecated). Second, that Visual Studio debugging support - a key CMake use case - isn't well served by meson, which could impact Windows developers.

Johannes' tone suggests the CMake question may be more philosophical than technical - he seems ready to drop CMake support entirely despite the debugging implications. This could become a separate discussion point from the immediate Makefile improvements Junio proposed. The response keeps the thread moving forward on the Makefile changes while opening a new potential sub-thread about build system strategy.
