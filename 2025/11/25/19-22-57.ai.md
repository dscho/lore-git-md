Junio Hamano provides detailed review feedback on Siddharth Asthana's `git replay --revert` patch, focusing on code organization and documentation clarity. The core technical approach of swapping trees for revert operations is sound, but several implementation and presentation issues need addressing.

Key technical points raised:
1. The revert message generation logic in `sequencer_format_revert_header()` duplicates rather than refactors existing code from `do_pick_commit()`. Junio suggests either making the new function call the existing logic or introducing a shared helper to prevent future drift.
2. Documentation lacks explanation for why `--revert` is incompatible with `--contained`, leaving readers to guess whether this is an implementation limitation or fundamental design issue.
3. Example usage scenarios don't clearly explain the topological requirements between branches, potentially confusing users about when and how to apply reverts.
4. Implementation details like the `is_revert` boolean parameter could be clearer as an enum (`CHERRY_PICK`/`REVERT`), and code organization could be improved by showing the common case first.
5. Memory management concerns are noted around merge option fields being NULLed inconsistently after freeing.

The review maintains the thread's technical focus while pushing for higher code quality standards, particularly around shared functionality and documentation completeness. Junio's suggestions aim to make the patch more maintainable and user-friendly while preserving its core functionality.
