This is a discussion about the proposed `--revert` feature for `git replay` command. Johannes Schindelin responds to Siddharth Asthana's patch that adds server-side revert capability to `git replay`, primarily for GitLab's Gitaly service.

Schindelin suggests an alternative approach using `git merge-tree` that could potentially avoid merge conflicts when reverting entire Merge Requests at once, rather than commit-by-commit. He acknowledges the patch looks fine technically, but offers a critique of the test suite size, arguing for more focused testing rather than comprehensive coverage that might slow down CI runs.

The exchange highlights different perspectives on testing philosophy - the original author included extensive tests (160 lines of test cases) to cover various scenarios, while Schindelin advocates for a more minimal approach that catches bugs without becoming burdensome. The technical discussion remains productive, with Schindelin's alternative suggestion indicating interest in the feature's use case while proposing different implementation tradeoffs.
