This is a reply in the ongoing thread about improving Windows/Meson CI test output visibility. Johannes Schindelin responds to Jeff King's patch that introduced a Meson-specific test runner script to properly handle test options and failure output in Windows CI jobs.

Schindelin approves the patch ("looks good to me") but raises a broader concern about the value of using Meson for Windows builds, noting that it's a minority build system in the MSYS2 ecosystem compared to CMake and GNU make. He suggests this is another instance of repeating infrastructure work that was already done for make and CMake builds.

The reply also addresses a technical curiosity Jeff noted about path handling differences between PowerShell and bash in the test environment. Schindelin explains the Windows path conversion behavior that occurs when switching shells, which can cause test failures in mergetool tests due to path format mismatches.

The exchange highlights both the immediate technical solution (the new test runner script) and the ongoing challenges of maintaining multiple build systems on Windows. While the patch itself is uncontroversial, Schindelin's comments suggest there may be future discussion about whether supporting Meson is worth the maintenance overhead.
