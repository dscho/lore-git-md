This thread centers on adding a `--revert` capability to `git replay`, primarily for GitLab's Gitaly service. The technical implementation has stabilized through three iterations, with consensus from key contributors like Elijah Newren, Phillip Wood, and Patrick Steinhardt. The current design treats reverts as a distinct operation mode (alongside `--onto` and `--advance`), preserving commit-by-commit reversal with proper messages while handling complex revision ranges. The v3 patches include thorough test coverage and refinements from review feedback.

A new discussion point emerged from Toon Claes, suggesting the command might be clearer using subcommands (`replay revert`, `replay onto`) rather than flags. Junio Hamano has now weighed in, agreeing that subcommands would better highlight the mutually exclusive nature of these modes. This represents a potential late-stage design shift, as the flag-based approach was previously settled. While the core functionality remains technically sound, the team is now reconsidering the user interface structure before finalizing the feature. The thread shows how even well-developed features can undergo interface refinements based on maintainer feedback late in the process.
