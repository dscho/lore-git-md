This thread centers on adding a `--revert` capability to `git replay`, primarily for GitLab's Gitaly service to enable server-side reverts without client roundtrips. The initial implementation reuses cherry-pick infrastructure with tree-swapping logic and introduces a new `sequencer_format_revert_header()` helper to standardize revert messages. Johannes Schindelin suggested an alternative bulk-revert approach using `git merge-tree` but approved the current implementation while noting test suite runtime concerns.

Junio Hamano has been actively reviewing, guiding improvements to code organization (extracting shared helpers), documentation (clarifying `--revert`/`--contained` incompatibility), and implementation quality (enum usage, memory management). However, new test failures have emerged where revert operations produce empty output instead of the new commit hash in `t3650-replay-basics.sh` tests 23-25, 27, and 31. These failures appear fundamental rather than memory-related, occurring even without sanitizers. 

The patch also conflicts with Patrick Steinhardt's parallel "history" series refactoring work, leading Junio to recommend waiting for that work to land before proceeding with a v2. The core functionality remains agreed upon, but the current focus is resolving test failures while coordinating with other ongoing sequencer changes.
