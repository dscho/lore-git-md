This thread centers on adding a `--revert` capability to `git replay`, primarily for GitLab's Gitaly service. The feature is now in its third iteration, with the implementation handling reverts as a distinct operation mode (separate from `--onto` and `--advance`) that reverses commits individually while preserving their messages. The technical approach swaps merge arguments to undo changes and reuses the sequencer's message formatting logic.

Key contributors including Patrick Steinhardt, Phillip Wood, and Elijah Newren have reviewed the design, which has evolved through three versions with refinements to memory management, test coverage, and error handling. The current consensus treats revert as an operation mode rather than a combinable flag, with clear restrictions on how it interacts with other modes like `--contained`.

In the latest email, Toon Claes raises a new consideration about the command's interface, suggesting that operation modes might be better expressed as subcommands rather than flags. This comes somewhat late in the process, as the technical implementation has already undergone extensive review and iteration. The core functionality appears solid, with the discussion now shifting to higher-level interface questions while maintaining all the established technical properties of the revert operation. The thread remains active as participants weigh this new suggestion against the already well-vetted approach.
