This thread centers on adding a `--revert` capability to `git replay`, primarily for GitLab's Gitaly service. The feature allows reverting commits directly on bare repositories while preserving individual commit messages. The discussion has reached consensus on key design points: reverts are a distinct operation mode (not combinable with other modes), commit-by-commit reversal is preferred, and the interface requires explicit target branch and commit range specification.

The latest email introduces a refactoring that extracts revert message formatting logic into a shared helper function, preparing for the `--revert` implementation. This structural change moves the logic from `do_pick_commit()` to a new `sequencer_format_revert_header()` function while maintaining all existing behavior. The refactoring enables code reuse without functional changes, keeping revert message handling consistent across commands.
