This is a review/feedback email on a bash completion feature patch. Junio C Hamano provides editorial suggestions and mild improvements to Wiktor Mis's patch that enables tab completion for Git's short options (-C, -P, etc.) when typing `git -<TAB>`.

Key technical notes for future reference:
- The patch modifies `__git_main()` in `git-completion.bash` to add a new case for `-*` patterns
- Currently lists 6 short options (-C, -P, -c, -h, -p, -v)
- Junio suggests the subject line should be more specific about completing "git -<TAB>"
- Points out the current implementation separates short and long option completion (needing `--<TAB>` for long options)
- Raises the possibility of a follow-up to combine both short and long option completions
- Overall accepts the patch as a good incremental improvement

The review is constructive but points out some minor documentation and UX considerations. The change itself is straightforward and low risk, touching only the bash completion script. Junio's comments suggest the patch is acceptable as-is but hints at potential future enhancements to the completion behavior.
