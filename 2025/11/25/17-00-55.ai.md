Feature addition to `git replay` command, specifically adding `--revert` capability. This is a single-patch series introducing server-side revert functionality to complement the existing cherry-pick operations in `git replay`.

The patch adds a `--revert` flag that enables reversing commits directly on bare repositories, which is particularly useful for GitLab's Gitaly service to avoid client-side roundtrips. The implementation cleverly reuses the existing cherry-pick infrastructure by swapping base and pickme trees in the merge operation, while maintaining all the existing conflict handling and atomic transaction support.

Key technical details include:
- New `sequencer_format_revert_header()` function extracted for shared use between sequencer and replay
- Commit message generation follows standard `git revert` conventions
- Comprehensive test coverage in t/t3650-replay-basics.sh for various scenarios
- Modifications to builtin/replay.c and sequencer.c to support the new functionality
- Documentation updates in git-replay.adoc

The patch appears well-structured with thorough test coverage and clear motivation. The implementation leverages existing mechanisms where possible while cleanly extending the functionality. The documentation updates explain both the new option and its relationship to existing revert operations.
