Feature addition to `git replay` adding revert capability. This patch introduces a `--revert` option to the `git replay` command, enabling server-side reversal of commits in bare repositories. The change comes from GitLab's Gitaly team, where they need this for efficient server operations without client roundtrips.

The implementation cleverly reuses the existing cherry-pick infrastructure by swapping merge arguments to reverse the diff direction. It also shares revert message generation code with the sequencer, maintaining consistency with `git revert`'s message format. The patch includes thorough test coverage of various scenarios including conflicts and multiple commits.

This appears to be a well-considered addition that fills a functional gap in `git replay` while maintaining consistency with existing Git behaviors. The implementation leverages existing components intelligently and comes with comprehensive tests, suggesting it's production-ready. The motivation is clearly stated from a real-world use case at GitLab.
