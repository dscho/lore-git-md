This thread reports a bug in `git-subtree` where it fails to respect the `commit.gpgSign` configuration when generating commits during subtree operations. The reporter encountered this when pushing subtree-managed changes to their SteamworksParser repository (starting from commit `a2883a6`) - while their global Git config requires GPG signing for commits, the subtree-generated commits were created unsigned. 

The issue appears reproducible on Git 2.43.0 (Windows 10) and represents a clear gap in `git-subtree`'s configuration handling. The reporter suggests the fix should involve checking the `commit.gpgSign` setting before generating commits during subtree operations. This would bring subtree behavior in line with user expectations and Git's standard commit signing functionality.
