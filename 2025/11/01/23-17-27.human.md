Junio Hamano provides feedback on a documentation patch about HTTP protocol error handling. He raises two main points about the patch from QueenJcloud:

First, he notes the author's email identity mismatch between the From: header and Signed-off-by line, suggesting either fixing the mail client configuration or using an in-body "From:" header to ensure proper attribution.

Second, he questions whether the documentation should specify an exact error message format ("error invalid 'want' <object-id>") as a universal standard, given that other Git implementations may handle this differently. He suggests the commit message should clarify whether this documents existing behavior (and if so, which implementations) or proposes a new standard. He also proposes a more concise way to phrase the documentation itself.

The feedback is constructive but indicates the patch may need more justification and tighter wording before being accepted. This is part of an ongoing discussion about how to document protocol behavior in a way that accounts for multiple Git implementations.
