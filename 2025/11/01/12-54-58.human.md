This is a bug report about `git-subtree` not respecting the `commit.gpgSign` configuration. The reporter (Fa) describes that when pushing subtree-managed content with `commit.gpgSign=true` configured, the resulting commits are not GPG-signed as expected. They provide a concrete example showing unsigned commits starting from `a2883a6` in their GitHub repository.

The issue appears to be a straightforward oversight where `git-subtree` isn't checking the GPG signing configuration when generating commits. The reporter suggests the fix should involve checking `commit.gpgSign` before creating each subtree commit. They're using Git 2.43.0 on Windows 10.

This seems like a legitimate bug report with clear reproduction steps and expected behavior. The reporter has provided all the necessary technical details and even pinpointed where the fix might need to be implemented. The issue affects users who rely on GPG signing for their subtree operations, making it potentially important for security-conscious workflows.
