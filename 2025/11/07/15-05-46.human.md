This is part 3/4 of a feature series implementing submodule gitdir path encoding to prevent filesystem conflicts. The series has reached consensus among key contributors (Adrian Ratiu, Junio Hamano, and Patrick Steinhardt) on using URL percent-encoding as the solution.

The patch introduces the `extensions.submoduleEncoding` config which, when set, enables path encoding for submodule gitdirs. The core mechanism uses `submodule.<name>.gitdir` as the authoritative path source, with encoding only applied when filesystem conflicts are detected (via `EEXISTS`/`ENAMETOOLONG` errors). This maintains backward compatibility while solving nested gitdir and case-folding issues.

Key implementation details:
- Adds repository format extension flag and config handling
- Implements RFC3986 percent-encoding for path components
- Introduces `submodule_name_to_gitdir()` helper for centralized path resolution
- Includes comprehensive test coverage for mixed legacy/encoded setups
- Documents the new config options while hiding encoding internals

The patch appears well-structured with thorough test coverage. It builds on prior discussion and represents the agreed-upon solution, now in its final implementation form. The next patches in the series will handle case-folding and long path edge cases.
