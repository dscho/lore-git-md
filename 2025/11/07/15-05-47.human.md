This is the final patch in a series addressing submodule gitdir path encoding, specifically handling case-folding filesystem collisions. The patch adds a new check in `validate_submodule_git_dir()` to detect and prevent case conflicts on case-insensitive filesystems, using a stricter percent-encoding scheme for uppercase characters when needed.

The implementation introduces a new variant of URL encoding (`is_casefolding_rfc3986_unreserved`) that treats uppercase letters as reserved characters, forcing them to be percent-encoded (e.g., "Foo" becomes "%46oo"). This encoding is only applied when necessary, detected via a combination of `core.ignorecase` config and filesystem checks, leaving case-sensitive systems unaffected.

The patch includes thorough test coverage in t7425-submodule-encoding.sh, verifying the new case-folding behavior works correctly. This completes the series' implementation of the agreed-upon design, which has already received unanimous support from key contributors (Adrian Ratiu, Junio Hamano, and Patrick Steinhardt) in previous iterations. The solution maintains backward compatibility while providing a robust path forward for submodules on case-insensitive filesystems.
