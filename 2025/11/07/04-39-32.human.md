Bug report about `git cherry-pick` silently ignoring patch application failures that `git apply` would catch. 

Bhavik Bavishi reports that `git cherry-pick` command completes successfully even when it fails to properly apply some hunks, while `git apply --verbose` correctly identifies the failure. The issue occurs when cherry-picking changes that modify `mango/utils/apple_utils.cc`, where the patch fails to apply to a specific function. The reporter notes this behavior is consistent across Git versions (including 2.51.2) and also appears in JGit when using Gerrit's UI.

The key discrepancy is that `git cherry-pick` provides no indication of the failed hunk application, while `git apply` clearly shows the error. The reporter suggests adding a `--verbose` option to `git cherry-pick` to surface such issues. The bug appears well-documented with reproduction steps and clear before/after expectations, though the actual patch content has been sanitized (references to "mango" and "apple" appear to be placeholders for real code). 

This seems like a legitimate inconsistency in Git's error handling that could lead to silent corruption when cherry-picking certain patches. The report would benefit from maintainer attention to determine whether this is a bug in cherry-pick's error detection or an intentional difference in behavior.
