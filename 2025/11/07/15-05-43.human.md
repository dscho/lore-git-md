This is the fourth version of a feature series implementing submodule gitdir path encoding to avoid filesystem conflicts. The series has reached consensus among key contributors (Adrian Ratiu, Junio Hamano, and Patrick Steinhardt) on using URL percent-encoding as the solution, with `submodule.<name>.gitdir` config as the authoritative source of truth when the `extensions.submoduleEncoding` extension is enabled.

The v4 iteration makes several important refinements:
1. Makes the gitdir config mandatory when the extension is active (rather than optional)
2. Switches to a "try plain path first, then encode if needed approach" rather than encoding everything by default
3. Moves encoding helper functions to more appropriate locations (like `is_rfc3986_unreserved` to url.[ch])
4. Adds comprehensive test coverage through t7425-submodule-encoding.sh
5. Drops non-essential platform-specific path length checking

The implementation handles both nested submodule paths and case-folding filesystems by attempting multiple candidate paths and selecting the first valid one. The design allows future encoding improvements without breaking existing repositories, since the gitdir config serves as the stable reference point.

This appears to be a well-considered solution to a long-standing submodule path collision problem, with thorough test coverage and clear documentation. The series has evolved through multiple rounds of review and now has explicit agreement from all key stakeholders on the architectural approach.
