This is part 3/4 of the submodule gitdir path encoding series, implementing the core encoding mechanism to prevent filesystem conflicts in submodule gitdirs. The patch introduces the `extensions.submoduleEncoding` config extension and associated infrastructure.

The key technical elements are:
- New `repository_format_submodule_encoding` flag in repository.h
- Config handling in setup.c with `gitdirpath` key using `repo_config_get_string_tmp()`
- Centralized path resolution via `submodule_name_to_gitdir()` that implements the encoding logic
- Comprehensive test coverage in t7425-submodule-encoding.sh
- Documentation updates for both the extension and new config option

The implementation follows the agreed design where:
1. Encoding is only applied when needed (detected via filesystem errors)
2. The `submodule.<name>.gitdir` config serves as the single source of truth
3. URL percent-encoding is used for path safety
4. Existing paths remain unchanged unless conflicts exist

The patch shows careful attention to edge cases with:
- Validation of gitdir paths
- Handling of nested submodules
- Parallel job execution
- Migration of legacy paths
- Test coverage for mixed legacy/encoded environments
- Documentation clarifying the encoding permanence

This represents a well-executed implementation of the consensus design, with all key architectural decisions from the thread now properly reflected in the code. The test coverage is particularly thorough, exercising both the happy path and edge cases around path encoding and nesting.
