This is a follow-up in the ongoing discussion about deprecating `git whatchanged`. Kristoffer Haugsbakk provides additional technical details about the transition path, confirming that users can already set up an alias (`git config set --global alias.whatchanged 'log --raw --no-merges'`) in current Git versions (2.51.1+) to maintain their workflow. He notes this wasn't possible in 2.51.0 due to technical limitations around aliasing builtin commands.

The email includes the full deprecation warning message that appears in recent Git versions, which proactively suggests both the replacement command and alias setup. Kristoffer clarifies that this warning system is specifically for long-deprecated commands like `whatchanged` (which has been effectively deprecated for 12 years, though not explicitly marked as such until recently), not for fresh deprecations.

While Franz Brauße had suggested implementing versioned warnings for future deprecations (similar to `git pull`'s divergence notices), Kristoffer indicates this isn't the current approach for new deprecations. The exchange shows the deprecation is proceeding as planned with clear migration paths documented, and the thread appears to be reaching its conclusion with both technical and user-experience concerns addressed.
