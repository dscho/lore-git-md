Junio C Hamano's November 2025 "What's cooking" status update for Git development, now including a new bugfix for the recently merged `git last-modified` command. The original update covered topics across integration branches: graduated work (internationalization, parseopt fixes, CI updates), new proposals (rebase trailers, tag peeling), and ongoing efforts (maintenance subcommand, diff algorithm selection, Rust interoperability). 

Toon Claes has identified and fixed a correctness issue in `git last-modified` where it produced inconsistent results compared to `git log --max-count=1` for the same file, particularly when files were specified via grep output versus direct path. The fix ensures consistent commit hash output while maintaining the command's performance advantage. This patch has been in 'next' since November 3rd as part of a v4 series and is now being advocated for inclusion in v2.52 as a bugfix rather than just an optimization - especially relevant since this will be the first release to include the `last-modified` subcommand. The correction addresses the path-following algorithm that tracks file modifications through commit history. 

Other active areas remain: Patrick Steinhardt continues driving object storage refactoring and the `git history` command, Jeff King has tag peeling optimizations proposed, and Johannes Schindelin contributes Windows-specific updates. The Rust interoperability work by brian m. carlson and submodule path handling by Jiang Xin are still in progress. Junio indicates several branches may soon graduate to 'next' and requests feedback on open proposals.
