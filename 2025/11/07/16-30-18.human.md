This is a build system patch discussion about release timing for the Windows credential helper Makefile updates. Junio Hamano responds to Thomas Uhle's question about whether the changes can make it into the upcoming Git 2.52.0 release.

Junio explains that post-rc1 changes generally only qualify for the final release if they fix regressions or have similarly urgent justification. He notes this Makefile cleanup has existed in its current form for 13 years, so delaying it a few more months poses no hardship. He contrasts this with recent CI fixes and message typo corrections that were accepted post-rc1 due to their minimal risk and immediate benefits to developers and translators.

The response makes clear this is purely a timing question - the patch itself is already technically approved and ready to merge. Junio suggests the changes would be better suited for the next development cycle where users would have more time to adapt their build processes. The discussion reflects Git's conservative approach to late-cycle changes, prioritizing stability over non-urgent improvements.
