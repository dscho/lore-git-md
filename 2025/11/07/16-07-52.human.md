Junio Hamano raises a fundamental design question about where binary file attribute reporting should live in Git's command hierarchy. This is a conceptual challenge to the ongoing `--raw-extended` discussion, suggesting the diff machinery might be the wrong layer for this functionality.

Hamano argues that binary-ness is an inherent property of a file, not a characteristic of a diff between versions. He proposes that attributes like binary status belong more naturally in tree-oriented commands like `ls-tree` or `show`, where they describe the state of individual files rather than changes between them. This would make the information available during history inspection (`git log`) without tying it to diff output.

The email doesn't reject the technical format proposals (TAB-delimited attributes) but questions whether they're being applied to the right problem space. This could significantly redirect the RFC discussion, as it challenges the premise that diff is the appropriate interface for this feature. The response may require participants to either defend the diff-based approach or consider migrating the feature to tree-oriented commands.

This intervention from Git's maintainer carries weight and will likely shape the thread's next phase, potentially moving discussion from format details to architectural placement. Participants will need to address whether their use cases truly require diff-time reporting or if tree-based reporting would suffice.
