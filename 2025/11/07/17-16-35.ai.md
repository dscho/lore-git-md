This is a technical discussion about the output format for binary file attribute reporting in Git's diff machinery, continuing from Junio Hamano's architectural challenge about whether diff is the right place for this feature at all.

Justin Tobler responds to Torsten Bögershausen's suggestion about using TAB as a separator by proposing two alternative formats for the `--raw-extended` output. The first format keeps the traditional diff header structure but moves attributes before the TAB delimiter, while the second more radical format places attributes at the very start of the line. Both approaches maintain machine-parsability by using TAB as the definitive field separator while keeping human readability benefits.

Key technical details under consideration:
- Current `-z` option behavior with NUL bytes remains unchanged
- Both proposals preserve backward compatibility requirement for existing parsers
- The second format would require more substantial parser changes but offers cleaner visual separation
- All variants must handle the same core attributes (binary, crlf) in the output

The email shows the discussion pivoting from the fundamental "where" question raised by Junio back to the "how" of implementation details, suggesting participants may be leaning toward continuing with the diff-based approach despite the architectural concerns. Justin's tone indicates openness to either format but a mild preference for the more visually distinct second option, while explicitly soliciting further feedback before proceeding.
