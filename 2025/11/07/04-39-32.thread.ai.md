Thread identity: Bug report about `git cherry-pick` silently ignoring patch application errors that `git apply` would catch, affecting Git 2.34.1 and 2.51.2, also present in JGit via Gerrit UI.

Core problem: Discrepancy in error handling between three-way merge operations (`git cherry-pick` and `git apply --3way`) versus direct patch application (`git apply`). The case involves complex conditional logic in `mango/utils/apple_utils.cc` where three-way modes succeed while direct application fails. Technical analysis confirms this occurs when merge heuristics detect repeated text patterns and consider changes already applied, raising questions about whether this is expected merge behavior or an error reporting deficiency.

Current status: Strong technical consensus established that the behavior is expected. Both `cherry-pick` and `apply --3way` produce identical successful outcomes for the problematic case while regular `apply` fails, with multiple confirmations of this behavior. Chris Torek's detailed explanation of three-way merge fundamentals has been accepted as authoritative, showing this is inherent to three-way merge design rather than a bug.

Key technical details: The silent success occurs in all three-way merge scenarios with identical file outputs. Test case demonstrates this for `apple_utils.cc` modifications where context matching fails in direct application but merge heuristics accept. Three-way merging uses full commit history to recognize seemingly-applied changes when text patterns appear redundant, while direct patch application lacks this information and fails on context mismatches. `git apply --3way` attempts to reconstruct three-way merge context from patch metadata when possible.
