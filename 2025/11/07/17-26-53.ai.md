This is a continuation of the binary file attribute reporting discussion, with Junio C Hamano raising critical questions about the fundamental approach. While the thread had been focusing on format variants for diff output, Junio challenges whether the diff machinery is the right place for this feature at all.

Junio directly questions whether existing parsers could still function with Justin Tobler's proposed format variants, noting that moving attributes to the start of the line breaks compatibility more severely than previous proposals. He suggests the attributes might not logically belong in the diff output since they're intrinsic file properties rather than change-specific information. The key technical point is that diff's `--raw` format was designed to show changes between versions, while binary/CRLF attributes are properties of individual file versions.

This email represents a pivot point in the thread - Junio is steering discussion back to first principles rather than format details, implying that format refinements may be premature without resolving the architectural question. His skepticism about "shoehorning" suggests he may favor a tree-based approach where these attributes would be reported separately from diffs. The email leaves open whether future discussion should:
1. Defend the diff-based approach with stronger justification
2. Explore how a tree-based implementation might work
3. Find a middle ground that serves both use cases

The exchange highlights the tension between incremental improvement of an existing interface (diff) versus designing a new conceptual model (tree inspection). Junio's questions about what information parsers actually need suggest he's considering whether the entire output format might need rethinking if the feature moves to a different subsystem.
