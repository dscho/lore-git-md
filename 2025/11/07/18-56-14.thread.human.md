Junio Hamano's November "What's cooking" update included a new `git last-modified` command that was recently merged. Toon Claes discovered and fixed a subtle bug where the command would produce different commit hashes for the same file depending on whether it was specified directly or matched via grep output - an inconsistency compared to `git log --max-count=1`. 

Initially framed as a performance optimization, the patch's importance grew when it became clear it actually fixed incorrect behavior. While Junio had planned to defer this to a later release since it missed the v2.52 merge window, Toon successfully argued for inclusion as a bugfix - especially critical since this will be the first release shipping the `last-modified` command. The fix addresses the path-following algorithm that tracks file modifications through history.

Some communication gaps emerged: the original patch's test case didn't clearly demonstrate the hash inconsistency, and the cover letter emphasized performance over correctness. The follow-up provides concrete examples of the fixed behavior. Meanwhile, other major efforts continue across the project, including object storage refactoring by Patrick Steinhardt and Windows updates from Johannes Schindelin.
