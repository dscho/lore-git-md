This is a refactoring patch that finalizes the xdiff changes needed to support clean diff algorithm selection in `git blame`. It's the first of two patches in the v5 series that has already undergone extensive review.

The patch adds XDF_NEED_MINIMAL to the XDF_DIFF_ALGORITHM_MASK in xdiff.h, fixing an inconsistency where resetting the diff algorithm required separate clearing of the minimal diff bit. This change makes the DIFF_XDL_CLR macro obsolete (though its documentation is kept) and fixes missed cases in merge-ort.c and builtin/merge-file.c that weren't properly clearing the minimal bit.

Junio C Hamano's review confirms the technical approach but raises some forward-looking considerations:
1) The change means XDF_DIFF_ALG() will now properly reflect when minimal diff is set, though this is safe because the code enforces single-algorithm selection
2) Suggests future improvements like adding a BUG() check for multiple algorithm bits
3) Proposes a larger cleanup to move algorithm selection to a dedicated enum field rather than bitflags
4) Notes the existing comment about clearing previous settings could be kept for now

The patch is technically a breaking change for xdiff library consumers but this was previously agreed to be justified. It enables the subsequent blame feature patch to implement clean algorithm selection. All substantive review feedback has been addressed in previous rounds, and this final review focuses only on potential future improvements rather than blocking issues. The series has Phillip Wood's final approval and is ready for merge.
