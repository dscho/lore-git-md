This thread examines a concerning discrepancy in Git's behavior where `git cherry-pick` silently succeeds when applying patches that `git apply` would reject. The original report demonstrated this with a specific case involving conditional logic in `apple_utils.cc`, where a context mismatch during patch application goes unreported by `cherry-pick` but is caught by `apply --verbose`.

Johannes Sixt has now joined the discussion, focusing the investigation on whether the difference stems from how `cherry-pick` uses three-way merging internally. He asks whether the silent failure also occurs with `git apply --3way`, which would help determine if this is an intentional behavior of the three-way merge pathway or a bug specific to `cherry-pick`'s implementation. This is a key diagnostic question that could explain why the commands behave differently.

The thread currently has two main open questions: whether this represents a bug or intentional design difference, and whether adding `--verbose` output to `cherry-pick` would be an appropriate solution. The fact that JGit exhibits the same behavior via Gerrit suggests this might be a long-standing characteristic of the three-way merge machinery rather than a new regression. Further input from merge or apply subsystem experts would help clarify the expected behavior here.
