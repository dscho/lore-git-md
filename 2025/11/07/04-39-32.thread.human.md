This thread investigates a discrepancy in how `git cherry-pick` and `git apply` handle patch application errors. The original report noted that `cherry-pick` would silently succeed on a patch that `git apply` would reject, particularly when modifying complex conditional logic in a file called `apple_utils.cc`. 

Johannes Sixt suggested the difference might stem from three-way merge behavior, and Bhavik Bavishi has now demonstrated this empirically: using `git apply --3way` produces the same successful (but potentially misleading) result as `cherry-pick`. This confirms the behavior difference is tied to three-way merging rather than being a `cherry-pick`-specific bug.

The discussion now centers on whether this silent success in three-way mode is intentional design (perhaps because merge heuristics can validly resolve cases where direct patching would fail) or if it should still trigger some notification to users. The test case involves a mango codebase's apple-related utilities, where the three-way merge appears to handle conditional logic differently than direct patching. While the technical behavior is now understood, the thread remains open on whether this constitutes expected behavior or if porcelain commands like `cherry-pick` should provide more visibility into when they resort to three-way resolution.
