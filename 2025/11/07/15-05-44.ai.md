This is a refactoring patch in the submodule gitdir path encoding series, updating `submodule--helper` to use the centralized path resolution function rather than hardcoded paths.

The patch modifies `add_submodule()` in `builtin/submodule--helper.c` to use `submodule_name_to_gitdir()` for path resolution, which is the standard helper for handling submodule gitdir paths throughout the codebase. The change eliminates a hardcoded `.git/modules/` path construction that was causing test failures with the new encoding scheme. 

Key technical details:
- Replaces direct path construction with `submodule_name_to_gitdir()` call
- Switches from heap-allocated char* to `struct strbuf` for path handling
- Maintains same error checking and messaging flow but with encoded paths
- Narrowed scope of `submod_gitdir_path` variable since it's only needed in one branch
- Keeps all existing functionality including force-overwrite checks

This is a straightforward mechanical change that aligns the helper with the rest of the codebase's path handling, as part of the larger submodule path encoding effort that has already reached consensus on architecture. The patch demonstrates good hygiene by properly managing string buffers and maintaining the existing error handling patterns.
