This is the v4 cover letter for the submodule gitdir path encoding series, representing the final design consensus between Adrian Ratiu, Junio Hamano, and Patrick Steinhardt. The series implements path encoding via `extensions.submoduleEncoding` config to prevent filesystem conflicts in submodule gitdirs.

The key architectural change in v4 makes `submodule.<name>.gitdir` config mandatory when the extension is enabled, establishing it as the single source of truth for gitdir paths. This allows users to remain agnostic about the specific encoding implementation while giving Git flexibility to improve the encoding scheme over time. The implementation now uses a validate-and-retry approach, only applying encoding when filesystem conflicts are detected (via `ENAMETOOLONG` or `EEXISTS` errors).

Notable refinements from v3 include:
- Dropped platform-specific path length checking via `pathconf()` as non-essential
- Moved RFC3986 encoding helpers to url.[ch] for better code organization
- Fixed parallel job execution bug introduced in v3
- Improved test helper script to handle relative/absolute paths
- Squashed config-related commits for cleaner history
- Replaced custom A->_a encoding with simpler percent-encoding for case folding

The series now has comprehensive test coverage in t7425-submodule-encoding.sh and handles both legacy submodules and newly encoded paths. All major design questions have been resolved with three-way consensus, making this a production-ready solution for submodule path conflicts.

Implementation highlights:
- New `repository_format_submodule_encoding` flag
- Config handling using `repo_config_get_string_tmp()`
- Case-aware percent-encoding with filesystem conflict detection
- Centralized path helpers with adaptive retry logic
- Documentation clarifying the config-based approach

The migration strategy preserves existing gitdirs unless conflicts exist, with `gitdirpath` serving as the authoritative mapping. The series is now fully baked with all reviewer feedback incorporated and CI passing.
