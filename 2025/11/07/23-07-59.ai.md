Final polish on documentation wording for Git's data model documentation. Junio Hamano provides detailed feedback on two remaining phrasing issues in Julia Evans' v6 patch series introducing `gitdatamodel.adoc`.

First, he suggests further de-emphasizing Unix file mode representations in favor of describing Git's 5 tracked file types (regular, executable, symlink, directory, gitlink) as distinct categories, noting their bitpatterns are only "loosely modeled after" Unix modes. This builds on Julia's earlier proposal to name the types rather than show octal values.

Second, he clarifies branch reference phrasing should say refs "record" commit IDs rather than "reference" them, maintaining technical precision about how refs function. He also weighs in on the "root tree" vs "directory" terminology debate, accepting "root" but rejecting "root directory" as potentially confusing with filesystem roots, suggesting "top-level directory" if directory terminology is used.

These final wording tweaks follow extensive prior discussion and represent the last refinements needed before merging this long-standing documentation addition.
