This is a refactoring patch that moves a URL encoding helper function as part of the submodule path encoding series. The patch relocates `is_rfc3986_unreserved()` from `builtin/credential-store.c` to `url.[ch]` to make it available for submodule path encoding.

The function was previously made static in credential-store.c when it was only used there, but now needs to be shared for submodule path encoding. The patch moves it to the more logical `url.[ch]` location since it implements RFC3986 URL encoding rules, adding proper documentation comments about the unreserved character set.

Key technical details:
- Function tests if a character is unreserved per RFC3986 (alphanumerics plus '-', '_', '.', '~')
- Patch removes the static version from credential-store.c and adds public version to url.c
- Includes header declaration in url.h
- Maintains identical implementation while improving documentation
- Prepares for use in submodule.c in next commit

The change is straightforward and uncontroversial, being a simple code movement with improved documentation. It's part of the larger submodule path encoding effort where this helper will be used to safely encode submodule names in gitdir paths. The thread context shows this architectural approach has already reached consensus among key contributors.
