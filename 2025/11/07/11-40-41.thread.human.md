This thread discusses the potential deprecation or removal of `git whatchanged`, a long-standing Git command that shows commit history with file change information. The discussion appears to have begun with proposals to remove this command, likely due to maintenance burden or redundancy with other commands like `git log`.

Franz Brauße has chimed in with a user perspective, reporting that they regularly use `git whatchanged` to examine file modifications in commits and find it valuable for their workflow. This feedback provides concrete evidence of the command's continued utility, which maintainers will need to weigh against any maintenance costs when making a decision.

The thread so far shows the tension between keeping the codebase clean and maintaining functionality that real users depend on, though we don't yet see the full range of arguments from both sides of the discussion.
