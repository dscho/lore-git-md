This is a refactoring patch that's part of the submodule gitdir path encoding series. It moves the `is_rfc3986_unreserved()` function from being a static helper in credential-store.c to being a public function in url.[ch], where it can be shared with the submodule path encoding implementation.

The function checks whether a character is "unreserved" according to RFC 3986 (URL encoding standards), meaning it doesn't need percent-encoding. The patch explains this was previously moved to credential-store.c when it was only used there, but now needs to be shared with submodule.c for path encoding.

The implementation is straightforward - it just relocates the existing function and adds its declaration to url.h. The commit message clearly explains the change and its motivation, and the diff shows clean movement of code with no functional changes. This appears to be a well-justified refactoring that enables code sharing between subsystems while maintaining good code organization.
