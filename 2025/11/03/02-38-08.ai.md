Bugfix discussion regarding `git fetch --tags` behavior in bare repositories. David Bohman responds to Chris Torek's analysis of the regression introduced in Git 2.51.0, where tag fetches now fail atomically when any tag update is rejected, rather than partially succeeding as in pre-2.51 versions. Bohman raises two key concerns: first, that this behavioral change in a mature tool like Git risks widespread compatibility issues as users upgrade, and second, that the current error reporting is misleading - it correctly flags rejected tag moves but incorrectly reports new tags as successfully fetched when they are in fact not stored.

The discussion has evolved from diagnosing the regression to evaluating whether the old (per-tag) or new (atomic) behavior should be considered correct. The reference transaction system introduced in 2.51.0 appears to be the root cause, enforcing atomicity where previously operations could partially succeed. Bohman's perspective emphasizes the practical impact on users and the potential for confusion from the current error messaging, suggesting the change may need reconsideration despite its technical consistency with the new reference transaction model.
