This is the final patch in a 5-part series introducing a new 'is-needed' subcommand for `git maintenance`, allowing users to check if maintenance tasks are required without executing them. The patch implements the actual subcommand and its documentation.

Key technical details for future reference:
- The subcommand exits with status 0 if maintenance is needed, 1 otherwise
- Supports `--task` filtering and `--auto` mode (reusing existing auto-condition logic)
- Without `--auto`, currently assumes maintenance is always needed (though this may not be true for cases like single-table reftable stacks)
- Default behavior checks `maintenance.<task>.enabled` (only 'gc' by default)
- Implementation includes argument parsing, task initialization, and auto-condition checking
- Documentation explains the exit code behavior and `--task`/`--auto` usage
