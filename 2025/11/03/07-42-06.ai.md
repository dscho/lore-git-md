This is a refactoring patch in Patrick Steinhardt's ongoing ODB abstraction series (v3 11/13). It reorganizes object freshening logic (updating mtimes for existing objects) to better separate concerns between loose and packed object handling.

The patch introduces three new functions:
- `odb_freshen_object()` as the top-level interface in odb.[ch]
- `packfile_store_freshen_object()` in packfile.[ch] for packed objects
- `odb_source_loose_freshen_object()` in object-file.[ch] for loose objects

Key changes:
- Moves packed object freshening from object-file.c to packfile.c
- Simplifies loose object freshening to operate on single sources
- Shifts responsibility for iterating alternates from object sources to ODB layer
- Updates callers in object-file.c to use the new unified interface
- Maintains identical behavior while improving architectural separation

The change follows the series' pattern of moving format-specific operations to their respective subsystems while keeping cross-cutting concerns in the ODB layer. This continues the encapsulation work from previous patches, with packed object handling now properly separated from loose object code.

Files touched:
- object-file.[ch] (loose object changes)
- odb.[ch] (new top-level interface)
- packfile.[ch] (packed object implementation)

The patch-specific changes are:
- Removes `freshen_loose_object()` and `freshen_packed_object()` from object-file.c
- Adds new function declarations in respective headers
- Implements `odb_freshen_object()` to coordinate between sources
- Updates `write_object_file()` and `stream_loose_object()` callers

This appears to be a straightforward mechanical refactoring that follows the established patterns from earlier in the series, with no behavior changes or new edge cases introduced. The change helps further the ODB abstraction goal by properly separating packed and loose object concerns.
