Bugfix for tag fetching behavior in batched reference updates.

This patch addresses a regression introduced in commit 0e358de64a ("fetch: use batched reference updates") where non-conflicting tags would fail to be fetched when other tags had conflicts. The issue occurred because the code would skip committing the transaction entirely when encountering tag conflicts, rather than still applying the non-conflicting updates.

Karthik Nayak fixes this by:
1. Extracting transaction commit logic into a new `commit_ref_transaction()` helper function
2. Ensuring the transaction gets committed even when tag conflicts occur (in non-atomic fetches)
3. Adding two new test cases to verify the fix works for both existing tags and non-conflicting tags

The patch appears well-constructed with:
- A clear commit message explaining the problem and solution
- Clean refactoring of the transaction commit code
- Comprehensive test coverage of both the fixed behavior and edge cases
- A fix for a missing test cleanup noticed during development

This resolves a real-world issue reported by David Bohman where tag fetches weren't working as expected after the batched updates change. The change maintains the performance benefits of batched updates while fixing the tag handling corner case.
