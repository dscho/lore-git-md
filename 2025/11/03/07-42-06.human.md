This is a refactoring patch in Patrick Steinhardt's ongoing series to abstract Git's object database handling. It's patch 11/13 in version 3 of the series.

The patch moves the logic for "freshening" objects (updating their modification times when they already exist) from object-file.c to more appropriate locations in the codebase. It introduces three new functions:
- `odb_freshen_object()` at the object database level for the general case
- `packfile_store_freshen_object()` for packed objects
- `odb_source_loose_freshen_object()` for loose objects

The change better separates concerns by keeping format-specific freshening logic with their respective subsystems (packfile handling vs loose object handling) while providing a unified interface at the ODB layer. The patch also intentionally moves the responsibility for iterating through object sources from the individual sources up to the ODB layer, which better matches the intended architecture where sources shouldn't need to coordinate with each other.

This continues the series' pattern of mechanical refactoring with no behavior changes, just improved code organization. The changes touch several key files including object-file.c, odb.c, and packfile.c, updating their interfaces accordingly. The patch follows the naming conventions and architectural decisions established in earlier reviews by Karthik Nayak and Junio Hamano.
