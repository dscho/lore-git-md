A bug report highlights inconsistent behavior in `git diff` when combining the `--submodule=diff` and `--name-only` options. The reporter demonstrates that while `--submodule=diff` correctly shows changes within submodules, adding `--name-only` only displays the submodule path rather than the individual changed files inside it. This creates a mismatch between the actual changes and what the output suggests.

The issue affects all Git versions since `--submodule=diff` was introduced and is easily reproducible with a simple test case comparing output line counts. The reporter hasn't proposed a fix, but the clear reproduction steps should help identify where in the diff machinery this behavior originates. This appears to be a genuine oversight in how these two options interact, likely unnoticed because the combination isn't commonly used.
