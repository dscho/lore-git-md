Bugfix discussion for `git fetch --tags` regression in bare repositories. David Bohman follows up on a thread about tags not being properly stored in bare repos when another tag is rejected, a regression introduced in Git 2.51. While Randall Becker suggests using `--force` as a workaround, Bohman points out the key issue: prior to version 2.51, Git would correctly store new tags even when rejecting a conflicting tag, but now fails to store any new tags in this scenario. The discussion centers on whether this behavioral change was intentional or represents a bug, with Bohman providing clear reproduction steps showing the regression. The thread has already established this affects general bare repo behavior, not just the specific bind9 repository mentioned initially. The core question remains why the presence of one rejected tag now prevents other valid tags from being stored, when previously these operations worked independently.
