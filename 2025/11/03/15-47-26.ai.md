Performance optimization for `git last-modified` command, building on prior work by Taylor Blau and Derrick Stolee. This v4 patch implements a faster algorithm to find the most recent commit modifying each path, addressing slowness with rarely-modified paths in the original implementation.

The key technical changes introduce a priority queue sorted by generation number, path activity tracking via EWAH bitmaps, and Bloom filter optimizations. The new approach propagates 'active' paths (those not yet associated with a commit) up through parents, truncating the revision walk to only examine active paths. This matches `git log -1 -- $path` behavior but does it simultaneously for all paths.

Performance benchmarks show significant improvements: 2.5x-9.3x faster on git.git (depending on Bloom filter usage), 5.3x faster for extreme cases like `git last-modified -- COPYING t`, and 7.9x-111.7x faster on linux.git. The patch also fixes a correctness issue where the old implementation could produce different results between path-specified and unfiltered runs due to maintenance branch merges.

Changes in v4 address final review feedback: using CALLOC_ARRAY() instead of xcalloc(), small formatting tweaks, and removal of the path_idx() helper function that caused sign-compare warnings. The implementation now properly handles memory cleanup and has been thoroughly benchmarked across repositories of different sizes.

The patch carries Acked-by from Taylor Blau and represents the culmination of multiple rounds of review addressing NULL oid segfaults, memory leaks, type safety concerns, and performance tradeoffs between different bitmap implementations. The final version maintains the dual storage approach (hashmap + all_paths array) as the optimal balance after evaluating alternatives.
