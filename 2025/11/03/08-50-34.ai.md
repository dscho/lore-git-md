Bugfix discussion for `git fetch --tags` regression in bare repositories. Karthik Nayak confirms being able to reproduce the issue reported by David Bohman, where `fetch --tags` in bare repositories fails to store new tags when encountering a rejected force-pushed tag, despite reporting them as "[new tag]". The problem appears consistently reproducible in both the original bind9 repository case and a minimal test case.

Nayak indicates the issue is likely related to the reference transaction updates introduced in Git 2.51.0, aligning with prior technical analysis in the thread that traced the regression to the new atomic reference transaction behavior. While the exact mechanism isn't detailed in this email, the confirmation from another developer adds weight to the diagnosis that this is a genuine regression rather than an edge case.

The email maintains focus on the core symptoms: the discrepancy between reported tag fetches and actual storage, and the interaction between rejected force-pushed tags and new tag acceptance. This continues the thread's technical examination of whether the atomic failure behavior is working as intended or represents an undesirable side effect of the reference transaction system. The exchange shows the issue moving from initial report through reproduction to active investigation, with Nayak indicating further analysis is forthcoming.
