This is part 9/13 of Patrick Steinhardt's ongoing refactoring series to improve Git's object database (ODB) abstraction. The patch continues the encapsulation of loose object handling by moving the core reading operations (`loose_object_info` and `map_loose_object`) to operate on individual ODB sources rather than the whole repository.

The key change is that functions now take a `struct odb_source` parameter instead of `struct repository`, pushing responsibility for object lookup down to the source level. This better matches the architectural goal of having each backend handle its own objects, with the ODB coordinating between sources. The patch maintains all existing behavior while cleaning up the interface.

The changes are mechanical but thorough, touching object-file.c (where most logic lives), object-file.h (interface updates), odb.c (caller updates), and streaming.c (one caller). The commit message explains the motivation well - this reverses the responsibility so backends only care about their own sources rather than the whole repository.

This continues the series' pattern of incremental, behavior-preserving refactoring. Reviewers have been consistently positive about prior patches, and this one follows the same careful approach. The changes are focused and the diff shows a clear simplification of the code paths.
