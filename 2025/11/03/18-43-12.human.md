This is a bug report regarding a regression in version tag sorting functionality. Junio C Hamano reports that after merging the `ps/ref-peeled-tags` topic into the `next` branch, the `git tag --list --sort=version:tag` command no longer sorts version tags numerically as expected. Instead, it falls back to ASCII sorting, causing incorrect ordering where (for example) v2.10.0 appears between v1.19.0 and v2.2.0.

The regression appears to be introduced by commit 054f5f45 ("ref-filter: parse objects on demand"), which was a key part of the `ps/ref-peeled-tags` changes. Junio notes this is particularly unfortunate since this was the motivating commit for the entire topic. The issue was discovered through bisection, with the last known good commit being 9ab444ed from the previous merge.

This appears to be a significant regression in functionality that affects version tag sorting, which is commonly used for release management. The report is directed to Patrick Steinhardt (the author of the original changes) for investigation. No fix is proposed yet - this is purely an initial report of the issue with enough detail to reproduce and begin debugging.
