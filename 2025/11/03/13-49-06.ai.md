This is a bugfix for the fetch command's handling of tags when using batched reference transactions. The patch addresses a regression introduced in commit 0e358de64a where non-conflicting tags would fail to be committed when fetching if there were any conflicting tags in the same operation.

The core issue occurs in `fetch_and_consume_refs()` which returns 1 when encountering conflicting tags, causing the transaction to skip committing entirely. The fix extracts the transaction commit logic into a new `commit_ref_transaction()` helper function and ensures the transaction is committed even when tag conflicts occur, while still preserving the error reporting for those conflicts.

The changes affect `builtin/fetch.c`'s reference transaction handling, particularly around error cases. Two new test cases verify the fix: one for basic tag fetching and another specifically for the non-conflicting tags scenario. The tests use `git for-each-ref` to verify tag presence and check proper error output when conflicts occur.
