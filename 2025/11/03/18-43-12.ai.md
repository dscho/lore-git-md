This is a bug report regarding a version sorting regression in the recently merged `ps/ref-peeled-tags` changes. Maintainer Junio C Hamano reports that `git tag --list --sort=version:tag` now produces incorrect ASCII sorting rather than proper version sorting, with examples showing v2.10.0 appearing between v1.19.0 and v2.2.0. 

The regression appears in the tip of 'next' after merging this topic, and bisect points to commit 054f5f45 ("ref-filter: parse objects on demand") as the culprit. This is particularly problematic as this commit was the core motivation for the entire ref-peeled-tags series. The issue was not present in the previous merge (9ab444ed).

Key technical details:
- Affects version tag listing functionality (`--sort=version:tag`)
- Root cause appears to be the object parsing changes in ref-filter.c
- Impacts the recently merged ref-peeled-tags work (ps/ref-peeled-tags)
- Exact failure mode: numeric version components not being sorted numerically (2.10 coming before 2.2)

This represents a significant regression in core functionality that will need to be addressed, likely requiring either a fix to the ref-filter changes or a revert of the problematic commit. The report comes directly from the maintainer with clear reproduction steps and bisect results, indicating high priority for resolution.
