This is the final version (v3) of Patrick Steinhardt's refactoring series to encapsulate loose object handling in Git's object database (ODB) abstraction. The series has progressed through multiple rounds of review, with the primary discussion point now resolved by adopting Karthik Nayak's suggested naming convention (`odb_source_loose` prefix instead of `odb_loose_source`).

The 13-patch series:
1. Performs initial cleanups around object database handling
2. Introduces and populates the new `struct odb_source_loose`
3. Moves all loose object state (cache, hash mapping) into this structure
4. Updates all related functions to use the new naming and structure

Key technical changes in this version:
- Finalized naming convention for all loose object functions (`odb_source_loose_*`)
- Complete encapsulation of loose object state including:
  - Cache management (`subdir_seen` bitmap and `oidtree` cache)
  - Hash compatibility mapping
  - Allocation/free functions
- Streamlined write operations with new `odb_write_object_stream()` interface
- Updated callers including `builtin/unpack-objects.c`

The series demonstrates careful architectural work to improve separation of concerns while maintaining existing functionality. It's part of the broader ODB abstraction effort to enable pluggable object databases. All outstanding review feedback has been addressed, and the implementation has received consistently positive technical reviews throughout its progression.
