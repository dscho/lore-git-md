This is part 9/13 of Patrick Steinhardt's v3 series refactoring Git's object database (ODB) abstraction, specifically focusing on loose object handling. The patch moves loose object reading operations (`loose_object_info()` and `map_loose_object()`) to operate on individual ODB sources rather than repository-wide, better aligning with the ODB abstraction goals.

Key technical changes:
- Replaces repository-level loose object functions with new `odb_source_loose_*` variants
- Updates `stat_loose_object()` and `open_loose_object()` to work with single sources
- Modifies `do_oid_object_info_extended()` and `open_istream_loose()` to iterate sources
- Maintains existing behavior while improving encapsulation
- Follows established `odb_source_loose_*` naming pattern
- Touches object-file.c, object-file.h, odb.c, and streaming.c

The changes continue the series' pattern of moving loose object specifics into the ODB source interface while keeping the same functionality. This patch is a mechanical refactoring that builds on prior work to encapsulate loose object state, with no behavior changes intended. The commit notes this is part of a larger effort to properly separate concerns in the ODB layer, though some functions like `open_istream_loose()` remain at what the author considers the wrong abstraction level for future cleanup.

The patch follows the same high-quality standards as previous entries in the series, with thorough mechanical conversions and no outstanding technical concerns raised in prior reviews. It continues the logical progression of the ODB abstraction work while maintaining backward compatibility.
