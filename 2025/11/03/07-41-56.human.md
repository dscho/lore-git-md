This is a refactoring patch that improves the logic for checking alternate object database paths in Git's ODB abstraction work. It's the first patch in Patrick Steinhardt's 13-part series to refactor object handling.

The patch addresses a subtle bug in how alternate ODB paths are checked and stored. The original code had an implicit relationship where the path was temporarily stored in a map during the check, then later assumed to be moved to the source object. The new version makes this relationship explicit by separating the path validation from the storage operation, making the code more maintainable and less prone to breakage during future refactoring.

Key changes include:
- Splitting the `alt_odb_usable()` function to purely validate paths without side effects
- Moving the path storage operation to after source creation
- Adding a BUG() check to verify the path wasn't already stored
- Maintaining the same functionality while making the code's behavior more obvious

This is a well-motivated change that improves code clarity in a tricky area of Git's object database handling. As the first patch in a larger series, it sets up cleaner foundations for the subsequent ODB abstraction work. The change has been through multiple review iterations (now at v3) and appears ready for inclusion.
