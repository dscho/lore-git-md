This is patch 5/13 in Patrick Steinhardt's ongoing series refactoring Git's object database (ODB) abstraction. The patch introduces a new `struct odb_source_loose` to encapsulate all state related to loose objects, moving it out of the main `struct odb_source`.

The change creates a dedicated structure for loose object handling, with corresponding allocation and free functions (`odb_source_loose_new` and `odb_source_loose_free`). This is part of the larger effort to make the ODB backend pluggable, where loose object handling will eventually become one of several possible backends.

The patch is mechanical in nature, simply moving existing functionality into a new structure while maintaining all current behavior. It follows the naming convention (`odb_source_loose`) that was previously agreed upon in the thread's earlier discussion. The changes touch several files but are straightforward - adding the new struct, wiring it into the existing ODB source creation/destruction paths, and maintaining the loose object cache functionality.

This continues the careful, incremental refactoring approach seen in previous patches of the series, with no apparent technical concerns raised in the ongoing discussion. The change appears well-contained and maintains the existing functionality while moving toward the larger goal of pluggable ODB backends.
