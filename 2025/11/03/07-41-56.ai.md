This is a refactoring patch that improves the logic for checking alternate object database paths in Git's ODB abstraction work. The patch focuses on a subtle memory ownership issue in the `alt_odb_usable()` function, which checks if a path can be used as an alternate object store.

The key change separates the path usability check from the path storage operation. Previously, the function would both check usability and store the path in a map, relying on implicit memory ownership where the path would later be detached into an object source. The new version makes this explicit by having `alt_odb_usable()` perform only the validation, while the path storage happens after the object source is created.

The patch modifies the function signature (removing the `pos` output parameter) and splits the logic into clearer steps. It also adds a BUG() check to verify the path wasn't already in the map when storing it. This change is part of Patrick Steinhardt's larger series to refactor Git's object handling as part of the ODB abstraction effort, with this being the first of 13 patches in v3 of the series.

The change touches the odb.c file and affects how alternate object stores are validated and tracked. While the behavior remains the same, the implementation is now more robust against future refactoring and makes the memory ownership rules clearer. This appears to be a well-justified cleanup that addresses a potentially tricky edge case in the code.
