This is a bug report about inconsistent behavior in `git diff` when combining the `--name-only` and `--submodule=diff` options. The reporter, Sainan, demonstrates that when both flags are used together, `--name-only` only shows the submodule path itself rather than recursively listing changed files within submodules (which is what happens when using `--submodule=diff` alone).

The issue appears to have existed since `--submodule=diff` was introduced, affecting at least Git 2.51.2 on Windows. The bug report includes clear reproduction steps comparing the output of two commands that should theoretically show the same number of changed files but don't. The first command (with `--name-only`) undercounts by only showing top-level submodule paths, while the second properly recurses into submodules.

This seems like a genuine inconsistency in the command's behavior - the `--name-only` output should presumably match what `--submodule=diff` would show when it comes to file enumeration. The report is well-structured with specific reproduction steps but doesn't propose a solution, instead just documenting the unexpected behavior.
