This is a documentation patch that updates an outdated test comment in the merge-ort rename caching test suite. It's the first of three patches in a series addressing a rename detection edge case.

The patch corrects a comment in t6429-merge-sequence-rename-caching.sh that still referenced the old `test-tool fast-rebase` utility, which was replaced by the `git replay` command in late 2023. The comment explains why the test uses replay rather than rebase or cherry-pick - because the sequencer integration with merge-ort isn't deep enough to preserve cached rename results between operations.

While the comment could have been removed entirely since `git replay` is now a proper builtin, Elijah Newren chooses to keep and update it since the explanation about the test's design choices remains relevant. The change is straightforward - just updating the tool name while preserving the technical rationale. This appears to be routine maintenance as part of preparing the test suite for the subsequent bugfix patches in the series.
