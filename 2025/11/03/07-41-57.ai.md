Refactoring patch in Patrick Steinhardt's ODB abstraction series, introducing a helper function to centralize ODB source creation. This patch (2/13 in v3) adds `odb_source_new()` to consolidate three existing code paths that create new ODB sources. The new function handles the common allocation, initialization, and path duplication tasks that were previously duplicated in `link_alt_odb_entry()`, `odb_set_temporary_primary_source()`, and repository initialization code.

The implementation is straightforward - it allocates a new `odb_source` struct, sets the provided ODB pointer, path (duplicated via `xstrdup`), and local flag. The patch then updates all three call sites to use this helper, removing their individual allocation and initialization code. The repository.c changes also slightly reorganize the objects path handling to work with the new centralized approach.

This appears to be a clean, mechanical refactoring that improves code organization without changing behavior. It's part of the larger effort to abstract Git's object database handling, building on previous work that established the `odb_source` structure and naming conventions (now using the `odb_source_*` prefix pattern as agreed in earlier thread discussion). The change follows the incremental, well-reviewed approach seen throughout this series.
