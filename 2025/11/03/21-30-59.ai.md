This is a bugfix follow-up in the ongoing discussion about a version tag sorting regression in the ps/ref-peeled-tags changes. Jeff King identifies the root cause in `ref-filter.c` where `data->maybe_object` isn't being reset between tag evaluations, causing incorrect caching behavior that affects version sorting.

The issue manifests when using `git tag --list --sort=version:tag` with tags like vsample-1.0, vsample-2.0, and vsample-10.0, where numeric sorting fails due to the cached object state. Jeff proposes a simple fix that resets `data->maybe_object` at the start of `grab_values()`, though he notes there might be a more appropriate location for this reset.

The regression was previously bisected to commit 054f5f45 ("ref-filter: parse objects on demand") and affects both loose and packed ref scenarios. This follow-up provides a technical solution to the identified caching issue, though the placement of the fix may need further discussion. The patch is minimal (just one line change) and directly addresses the demonstrated problem.
