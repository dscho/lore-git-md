This is a refactoring patch in a completed 5-part series about `:(optional)` path handling. The patch converts an `int` flag to `bool` type in `parse-options.c` for better type safety, following Phillip Wood's earlier suggestion.

The change itself is straightforward - replacing `int is_optional` with `bool is_optional` and updating the initialization from `0` to `false`. However, Junio Hamano points out in his review that the subsequent NULL check on `value` appears unnecessary since `skip_prefix()` would never make `value` NULL in this context. He suggests removing that check entirely, which would further simplify the code.

This is part of a larger effort to improve consistency in how Git handles optional pathspecs, with each patch in the series making small, focused improvements. The changes are well-justified and build on prior feedback, though this particular patch may need a minor adjustment based on the maintainer's observation about the redundant NULL check.
