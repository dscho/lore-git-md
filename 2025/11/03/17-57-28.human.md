This is a bug report from the maintainer about a regression in the `ps/ref-peeled-tags` series that was just merged to 'next'. The series was meant to streamline handling of annotated tag objects in ref backends, but Junio C Hamano has discovered that it breaks version-sorted tag listing (`--sort=version:tag`), causing tags to appear in ASCII order instead (e.g., "v2.19.0" appears before "v2.2.0").

The issue appears immediately after merging this topic, as the previous merge (tc/last-modified-active-paths-optimization) still shows correct version sorting. Junio notes he hasn't investigated the root cause yet, but the correlation is clear. This is a significant regression for users who rely on version-sorted tag output.

The `ps/ref-peeled-tags` series had already gone through review and its dependencies were merged, making this an unfortunate late discovery. The bug affects a common use case (listing version tags) in a visible way, so it will need prompt attention from the original author or other contributors to diagnose and fix.
