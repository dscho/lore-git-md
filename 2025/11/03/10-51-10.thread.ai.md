Thread identity: Bug report about inconsistent behavior in `git diff` when combining `--submodule=diff` and `--name-only` options, affecting all versions since `--submodule=diff` was introduced.

Core problem: When using both `--submodule=diff` (which shows full diff output for submodules) and `--name-only` (which lists only changed files), Git incorrectly shows only the submodule path rather than recursing into the submodule to list individual changed files. This creates a discrepancy between the actual changes (files within submodules) and what `--name-only` reports (just submodule paths).

Current status: Bug reported with clear reproduction case but no proposed fix yet. The issue appears to affect all versions supporting `--submodule=diff`.

Key technical details: The bug occurs in the diff machinery when processing submodules with these combined options. The reporter demonstrates the issue by comparing output line counts between `git diff --submodule=diff` and `git diff --submodule=diff --name-only`, showing the latter fails to properly recurse into submodules.

Open questions: No solution proposed yet. The fix would need to modify how `--name-only` interacts with submodule diff output while maintaining backward compatibility with existing uses of both options.

Participant positions: Single reporter so far, no other participants yet. The clear reproduction case suggests this is a genuine bug rather than expected behavior.
