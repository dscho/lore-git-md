This is a refactoring patch in Patrick Steinhardt's ongoing object database (ODB) abstraction series (v3, patch 8/13). The change moves the loose object map - which handles hash compatibility mapping for loose objects - from the generic `struct odb_source` into the newly introduced `struct odb_source_loose` where it logically belongs.

The patch continues the established pattern from previous patches in the series by:
1. Moving the `loose_map` field from `struct odb_source` to `struct odb_source_loose`
2. Updating all related functions to access the map through the loose source structure
3. Adding proper cleanup of the map in `odb_source_loose_free()`
4. Removing the now-redundant cleanup from `odb_source_free()`

The changes are mechanical and maintain the same behavior while improving encapsulation. The patch touches several files (loose.c, object-file.[ch], odb.[ch]) with straightforward updates to function calls and structure access patterns. This continues the series' goal of properly separating concerns between generic ODB functionality and loose-object-specific handling.

The patch follows the naming conventions established earlier in the thread (`odb_source_loose_*` prefix) and maintains the header organization pattern where loose object specifics live in object-file.h while odb.h contains more general declarations. No new functionality is introduced - this is purely an internal code movement that builds on the infrastructure set up in previous patches.
