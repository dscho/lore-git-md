This is a technical clarification in the ongoing `git replay` feature discussion, specifically about the `--revert` option's ability to handle disconnected commits. Elijah Newren corrects Siddharth Asthana's claim that the current implementation can already revert specific non-contiguous commits (like just commit1 and commit4 from a series). 

Elijah explains that the current syntax (`git replay --revert <target> <commit1> <commit4>`) actually reverts all commits in the history of either commit, not just those two specific commits. He notes this matches how `git log` interprets multiple commit arguments. The implementation currently lacks proper support for true disconnected commit selection, though it could potentially be added via a `--no-walk` option (which currently causes errors or segfaults).

The email serves as both a technical correction and a suggestion for future work - while the immediate `--revert` feature could proceed without this capability, adding proper `--no-walk` support could be a useful follow-up enhancement for both `--revert` and `--advance` modes. The tone is constructive, pointing out the current limitations while acknowledging the potential value of the feature.
