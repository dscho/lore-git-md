Justin Su reported a segmentation fault on ARM64 Ubuntu 24.04 when running `git fetch` with submodules and commit-graph writing enabled in Git 2.43.0. Initial suspicion of repository corruption was ruled out when the issue was reproduced with fresh clones using specific configs (`fetch.writeCommitGraph=true` and `submodule.recurse=true`). The crash appeared platform-specific (ARM64 only) and timing-sensitive, suggesting a race condition during commit-graph cleanup in submodule operations.

In a follow-up, Justin Su reports that upgrading to Git 2.52.0 resolves the issue, though the exact fix remains unidentified. This suggests the problem was addressed in a commit between versions 2.43.0 and 2.52.0. While the technical root cause (whether an ARM64-specific memory handling issue or a general race condition) remains unconfirmed, the practical impact is now mitigated for users on current Git versions. The thread demonstrates how platform-specific edge cases can surface in complex interactions between Git features like submodules and commit-graphs.
