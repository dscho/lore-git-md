Bugfix for `git last-modified` regression affecting merge commit handling. This is a follow-up to the performance optimization series that introduced a new algorithm for the command, which was merged to 'next' but later found to have platform-independent issues with merge commit attribution.

The email corrects a minor attribution error in the thread (mistakenly crediting Kristoffer Haugsbakk instead of Anders Kaseorg for the initial s390x bug report) while confirming the underlying issue affects all platforms. The core problem involves incorrect file modification tracking across merge commits, where files were being wrongly attributed to the merge commit itself (da1857e0) rather than their actual sources (b5 for file2, b2 for file).

The thread context shows this was initially suspected to be a big-endian platform issue but was later determined to be an algorithmic problem in merge commit parent ordering. The fix maintains the original performance gains (2.5x-111.7x speedups) while correcting the merge handling logic. Test cases 16 and 19 in t8020-last-modified.sh specifically caught this regression, and the solution has been verified across platforms including s390x and HP NonStop without requiring platform-specific code.

Key participants in resolving this include Toon Claes (author of the original optimization and this fix), Jeff King (who provided critical analysis of the blame propagation issue), and Anders Kaseorg (who first reported the s390x test failures). The fix appears to be a focused correction to the merge commit processing while preserving the optimization's architectural improvements.
