Bugfix for memory initialization in `git-last-modified`'s bitmap handling.

This patch fixes an incorrect memory initialization in the `git-last-modified` command. The command uses a scratch bitmap to track changed paths between commits, reusing the bitmap across calls to `process_parent()`. The bug occurred because the code was passing just the allocation count to `memset()` rather than multiplying by the size of the underlying `eword_t` type (which is typedef'd to `uint64_t`).

The issue was discovered when tests failed on s390x (a big-endian architecture), though the problem wasn't actually endianness-related - the big-endian platform simply made the bug more visible. The fix is straightforward - multiplying the allocation count by `sizeof(eword_t)` in the `memset()` call.

The patch has been reviewed by Jeff King (as noted in the Helped-by tag) and addresses a specific test failure reported by Anders Kaseorg. The change is minimal (a single line modification) and focused on the memory initialization issue. The commit message provides clear context about how the bug was discovered and why the fix works.
