This is a technical clarification in the ongoing `git replay` feature discussion, specifically about the `--revert` option's ability to handle non-contiguous commits. Elijah Newren corrects Siddharth Asthana's claim that disconnected commits can already be specified via standard revision range syntax, explaining that the current implementation actually processes the full history of any listed commits rather than just the commits themselves.

Elijah demonstrates that the command `git replay --revert <target> <commit1> <commit4>` would revert all ancestors of both commits, not just those two specific commits. He notes this behavior matches `git log`'s interpretation of multiple commit arguments. The email reveals that true disconnected commit support would require implementing `--no-walk` functionality, similar to other Git commands, but this isn't currently working for either `--advance` or `--revert` modes.

The message includes implementation details showing that attempting to use `--no-walk` currently results in either an error about ill-defined ordering or segfaults due to uninitialized objects. While suggesting this could be fixed, Elijah leaves it to Siddharth to decide whether to address it in the current series or defer it as a separate change. This clarification impacts the feature's advertised capabilities and may require updates to both documentation and test plans to accurately reflect the current behavior versus desired functionality.
