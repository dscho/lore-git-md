Git fetch SIGSEGV during submodule operations bug report. Justin Su reports a segmentation fault on ARM64 (aarch64) Ubuntu 24.04 with Git 2.43.0 during `git fetch` involving submodules (catppuccin/bat, btop, micro, delta), occurring post-fetch completion after stale commit-graph lock removal, suggesting race condition or memory corruption in cleanup. System: AWS c8g.metal, fish shell, glibc 2.39, GCC 13.3. Brian m. carlson investigates the provided repository and finds corruption (missing `.git/refs`, blobs per `git fsck`), though cannot reproduce SIGSEGV on Debian unstable amd64 with Git 2.51.0 - observes different corruption errors instead. Suggests the crash may be fixed in newer versions but notes Git shouldn't segfault even with corrupt repositories. Platform differences (ARM64 vs amd64) may still be relevant to original issue. Repository corruption appears to be a factor, though not conclusively the root cause of the reported SIGSEGV.
