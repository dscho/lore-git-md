Git fetch SIGSEGV during submodule operations bug report. Justin Su reports a segmentation fault on ARM64 (aarch64) Ubuntu 24.04 with Git 2.43.0 during `git fetch` involving submodules (catppuccin/bat, btop, micro, delta), occurring post-fetch completion after stale commit-graph lock removal. Initial investigation by Brian m. carlson suggested repository corruption, but Justin Su later demonstrated the crash occurs with fresh clones when two specific configs are set: `fetch.writeCommitGraph=true` and `submodule.recurse=true`, eliminating repository corruption as the root cause.

The crash appears platform-specific (reproducible on ARM64 Ubuntu 24.04 but not on amd64 Debian unstable) and timing-sensitive, pointing to potential memory corruption or race condition in commit-graph writing and submodule recursion during fetch. Key technical details include commit-graph-chain.lock removal preceding the crash. Justin Su now reports the issue is no longer reproducible in Git 2.52.0, suggesting the problem was fixed between versions 2.43.0 and 2.52.0, though the specific commit remains unidentified. The thread's key technical questions about root cause (ARM64-specific memory handling vs timing-sensitive race condition) remain formally unresolved, but the practical impact appears resolved in current releases. The narrowed reproduction window (2.43.0 to pre-2.52.0) provides a bounded scope for future investigation if needed.
