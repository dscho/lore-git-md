Bugfix for `git last-modified` memory initialization issue. This patch corrects a bug where the scratch bitmap used to track changed paths between commits wasn't being properly zeroed out due to an incorrect memset length calculation.

The issue was discovered when tests failed on s390x (big-endian) systems, though the problem wasn't actually endianness-related - the big-endian platform simply made the bug more visible. The fix changes the memset call to multiply the word allocation count by the size of the eword_t type (uint64_t) when clearing the bitmap memory.

The patch is small (just one line changed) but important, as improper bitmap clearing could lead to incorrect behavior in tracking modified paths. It comes with sign-offs from both the reporter (Anders Kaseorg) and a helper (Jeff King), suggesting it's been reviewed. The commit message clearly explains both the problem and solution.
