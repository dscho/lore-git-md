Bugfix for `git-last-modified` bitmap initialization issue in `builtin/last-modified.c`, with architectural follow-up discussion. The immediate bug (incorrect `memset` size calculation causing incorrect behavior, more visible on s390x) was reported by Anders Kaseorg, fixed by Toon Claes with a one-line solution multiplying count by `sizeof(eword_t)`, reviewed by Jeff King (Helped-by), and merged to 'next' for backport to maint. The fix addresses behavior dating back to v2.52.0.

Discussion evolved to architectural improvements: Jeff King suggested (1) a `CLEAR_ARRAY` macro and (2) `bitmap_clear()` function encapsulation. Toon Claes submitted v2 proposing `MEMZERO_ARRAY` macro in `git-compat-util.h` using `st_mult()` for array zeroing. Jeff King's analysis shows 5 potential use sites across last-modified, simple-ipc, diff-delta, hashmap, and pack-revindex subsystems where the macro could replace existing `memset` patterns. While technically sound, King questions its broader value given limited use cases. Junio Hamano remains neutral between `MEMZERO_ARRAY` and `CLEAR_ARRAY` approaches, noting the immediate fix is already merged.

Key participants (Kaseorg, Claes, King, Hamano) have refined both solution and architectural context. The thread shows consensus on technical correctness while evaluating maintainability tradeoffs of new helper macros. Discussion has shifted from bug resolution to architectural decision-making, with King's objective metrics (5 use sites) informing the evaluation. The macro proposal remains open-ended with no strong push for or against adoption, awaiting maintainer preference on whether to standardize this pattern.
