Bugfix for `git-last-modified` bitmap initialization issue in `builtin/last-modified.c`, with architectural follow-up. The command tracks changed paths between commits using a scratch bitmap of `eword_t` (uint64_t) elements. Original bug passed element count rather than byte count to `memset()`, causing incorrect behavior (more visible on s390x big-endian but not endian-specific). Anders Kaseorg reported the test failure that revealed the issue. Toon Claes proposed the one-line solution multiplying count by `sizeof(eword_t)` in the `memset` call, which Jeff King reviewed (Helped-by) and agreed resolves the immediate issue. This direct fix has been merged to 'next' and marked for backport to maint.

King suggested two potential architectural improvements: (1) introducing a `CLEAR_ARRAY` macro to handle size calculations automatically, and (2) encapsulating bitmap clearing in a `bitmap_clear()` function. Anders Kaseorg provided a technical correction about pointer size calculation syntax. Junio C Hamano confirmed the fix is correct and noted the bug dates back to v2.52.0.

Toon Claes submitted version 2 introducing a new `MEMZERO_ARRAY` macro in `git-compat-util.h` that properly calculates the byte count for array zeroing using `st_mult()`, following the pattern of existing array helpers like `ALLOC_ARRAY`. Jeff King's response to v2 notes the macro is technically sound but questions its broader value, providing a `git grep` showing 5 potential use sites across last-modified, simple-ipc, diff-delta, hashmap, and pack-revindex subsystems. While maintaining neutral stance on adoption, King's analysis provides concrete data to assess the macro's impact.

The thread shows consensus on the technical solution while exploring implementation approaches, with the direct fix merged and the macro-based solution under consideration for its maintainability benefits. Discussion has evolved from immediate bugfix to evaluating broader code quality improvements, with Hamano noting the v2 patch's redundancy given the already-merged fix. Key participants (Kaseorg, Claes, King, Hamano) have refined both solution and context, with King's latest email providing objective metrics to inform the architectural change decision. The macro proposal remains open-ended with no strong push for or against adoption.
