This thread addressed a bug in `git-last-modified` where the scratch bitmap was incorrectly initialized due to passing an element count rather than byte count to `memset()`. The issue, originally reported by Anders Kaseorg through test failures on s390x, was fixed by Toon Claes with a one-line change to multiply by `sizeof(eword_t)`. Jeff King reviewed the fix and suggested some architectural improvements for future consideration, though these were deemed unnecessary for this immediate fix.

Junio C Hamano has now approved the patch for backport to the maint branch, noting the bug dates back to v2.52.0. He suggested a minor wording improvement to the commit message to better describe the issue as "uninitialized" rather than "improperly initialized" memory. The thread concludes with consensus on the fix and some useful discussion about type-safe memory operations that may inform future development. The patch will be merged as-is, resolving the issue that affected s390x systems.
