This thread addresses a bug in `git-last-modified` where a bitmap initialization issue caused incorrect behavior, particularly noticeable on s390x big-endian systems. The core problem was passing an element count rather than a byte count to `memset()`. Toon Claes provided the straightforward fix (multiplying by `sizeof(eword_t)`), which Jeff King reviewed and approved. 

Anders Kaseorg, who originally reported the test failure, later corrected a technical point in King's suggestion about pointer size calculation syntax, clarifying that `sizeof *lm->scratch->words` or `sizeof lm->scratch->words[0]` would be more robust than `sizeof(lm->scratch->words)`. King acknowledged this as a valid stylistic improvement for similar cases, though it doesn't affect the already-approved patch. 

Junio C Hamano confirmed the fix is correct and suitable for backporting to the maint branch, noting the bug dates back to v2.52.0. He suggested a minor wording tweak to the commit subject ("uninitialized" instead of "inproper initialized"), which Claes incorporated while keeping the patch unchanged. The thread has now concluded with maintainer approval, having thoroughly examined both the immediate fix and broader code hygiene considerations around pointer arithmetic. All participants—Kaseorg, Claes, King, and Hamano—contributed to refining the solution and its context.
