This thread addresses a memory initialization bug in `git-last-modified`'s bitmap handling. The command reuses a scratch bitmap to track changed paths between commits, but was incorrectly initializing the memory by passing just the allocation count to `memset()` rather than accounting for the size of the underlying `uint64_t` type. While the issue manifested on s390x (a big-endian architecture), the root cause wasn't endianness-related - the big-endian platform simply made the bug more visible.

The fix, which multiplies the allocation count by `sizeof(eword_t)` in the `memset()` call, has been reviewed by Jeff King (Peff) and addresses a test failure reported by Anders Kaseorg. The change is minimal and well-contained, with a commit message that clearly explains both the problem and solution. This appears to be a straightforward bugfix that should resolve the immediate issue without broader implications.
