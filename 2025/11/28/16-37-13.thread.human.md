This thread addresses a bug in `git-last-modified` where bitmap initialization was incorrectly passing an element count rather than byte count to `memset()`, causing issues particularly visible on s390x big-endian systems. The core fix, proposed by Toon Claes and reviewed by Jeff King, multiplies the count by `sizeof(eword_t)` to correct the byte calculation.

The discussion has since evolved into broader code quality considerations. Jeff King suggested potential architectural improvements like a `CLEAR_ARRAY` macro or `bitmap_clear()` function, while acknowledging these might be over-engineering for this stable code. Anders Kaseorg later contributed a precise technical correction regarding pointer syntax in one of the alternative implementations, demonstrating the list's attention to detail even after consensus on the main fix.

All participants agree the immediate bugfix is correct, and the additional discussion represents optional refinements rather than required changes. The thread shows how Git's review process often surfaces both immediate solutions and longer-term code hygiene considerations in parallel.
