This thread began with a bug report from Anders Kaseorg about incorrect bitmap initialization in `git-last-modified`, where a `memset()` call was passing an element count instead of a byte count. Toon Claes provided the immediate fix (multiplying by `sizeof(eword_t)`), which Jeff King reviewed and Junio Hamano merged to 'next' for inclusion in the next release. The bug dates back to Git v2.52.0 but was more visible on s390x big-endian systems.

The discussion then shifted to architectural improvements, with King suggesting a `CLEAR_ARRAY` macro or `bitmap_clear()` function to prevent similar issues. Claes followed up with a v2 patch introducing a `MEMZERO_ARRAY` macro that properly calculates byte counts using `st_mult()`, similar to existing array helpers. While the core fix is already merged, King's latest response examines whether this macro would be useful more broadly, identifying five potential use sites across various subsystems. He remains neutral on adoption, providing data but no strong recommendation either way. The thread shows consensus on the technical solution while exploring maintainability improvements, with Hamano noting the v2 patch's redundancy given the already-merged fix. All key participants (Kaseorg, Claes, King, Hamano) have contributed to refining both the immediate solution and the surrounding context.
