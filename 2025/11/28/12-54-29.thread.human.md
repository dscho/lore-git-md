This thread discusses a small but thoughtful documentation improvement to Git's advice messages, specifically around branch-related errors. The original patch from Kristoffer Haugsbakk proposed changing references from `man git check-ref-format` to `git help check-ref-format` in branch.c and builtin/branch.c, along with updating a test case to use modern syntax.

Junio C Hamano, the maintainer, has responded with additional rationale for preferring `git help` - not just as a general best practice to avoid external commands, but specifically because some platforms may not have `man` available at all. He also approved the stylistic choice to use single quotes for command references, though he noted with some humor that Git's advice system doesn't support more sophisticated markup formats.

The discussion remains focused on this narrow but worthwhile improvement to message consistency and platform compatibility. Junio's response appears to be guidance for strengthening the patch's justification rather than any substantive objections. The changes are minimal (just 5 lines across 3 files) and maintain the original technical approach while refining the reasoning behind it. This looks like a straightforward improvement that's likely to be accepted with perhaps minor wording adjustments to the commit message.
