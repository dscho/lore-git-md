This thread documents Junio C Hamano's comprehensive effort to implement end-to-end handling of incomplete-line whitespace errors (missing newlines at end of file) across Git's diff and apply pipeline. The 12-patch series introduces a new WS_INCOMPLETE_LINE flag (0x8000) that enables consistent detection, highlighting, and fixing of these cases through core.whitespace and .gitattributes configuration.

Through the series, Junio has systematically built up the infrastructure - first expanding the whitespace bitfield, then implementing diff-side detection with colored markers and --check integration, followed by apply-side parsing and automatic fixing. The implementation handles various edge cases like modifications of incomplete lines and maintains backward compatibility. Phillip Wood raised one reservation about line counting behavior in patch 4, but otherwise the technical approach has consensus, with acknowledgment that "\ No newline" annotations should be treated as metadata.

The final patch (12/12) now enables this functionality for Git's own codebase, applying incomplete-line validation to C/header files and shell scripts while explicitly excluding AsciiDoc documentation files from this particular check. This represents the operational completion of the feature - after all the plumbing work in previous patches, the series now enforces the policy on the project that developed it. The exclusion for documentation files suggests a pragmatic policy choice about where strict newline requirements matter most.

With all 12 patches now submitted, this series provides a complete solution for configurable incomplete-line handling throughout Git's diff/apply workflow, with the project itself serving as the first real-world adopter of the new capabilities.
