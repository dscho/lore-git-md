This thread is about Junio Hamano's patch series introducing a new "incomplete-line" whitespace error class to detect and handle missing newlines at the end of files. The series, now at version 2 with 12 patches, adds this as a configurable whitespace rule (WS_INCOMPLETE_LINE) that integrates with Git's existing diff and apply infrastructure, with enforcement planned for Git's own codebase.

The latest patch (04/12) fixes a subtle line number accounting issue when processing "\ No newline at end of file" markers in diffs. Previously, the code only incremented the preimage line counter for these markers, regardless of whether they followed an addition, deletion, or context line. The patch adds proper tracking mechanism to ensure both preimage and postimage line numbers are updated correctly, though this is more about internal correctness than user-facing behavior since these counters are mainly used for blank-at-EOF comparisons.

The series shows Junio's characteristic attention to detail, with each patch carefully preparing the codebase for the new functionality. Earlier patches have refactored whitespace handling to properly separate concerns (like moving blank-empty suppression logic in patch 03) and added defensive programming checks. The current version has expanded test coverage and documentation, with the final patch set to enable the new check for Git's *.c, *.h, and *.sh files via .gitattributes.

While the technical implementation appears solid, some open questions remain about the broader policy decisions - particularly around default enablement for the Git codebase, bitmask allocation strategy, and handling of edge cases like CRLF line endings. So far, Junio is the only participant actively commenting on the series, suggesting it may be nearing readiness for merging once any final review feedback is addressed.
