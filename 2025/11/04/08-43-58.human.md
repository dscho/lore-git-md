This is part 3 of a 5-patch series introducing a new 'is-needed' subcommand for `git maintenance` to check whether maintenance tasks are required without performing them. The patch adds infrastructure for checking if reference backends need optimization.

The patch introduces a new `optimize_required` field to `struct ref_storage_be`, along with a corresponding `refs_optimize_required()` function in the public refs API. It implements this new method for all ref backends (debug, files, packed, and reftable), with each backend providing its own logic to determine if optimization is needed. 

For the files backend, it reuses the existing `should_pack_refs()` logic. The packed backend always returns false since packed refs are already optimized. The reftable backend delegates to `reftable_stack_compaction_required()` which was introduced in earlier patches. The debug backend simply wraps the underlying backend's implementation.

The implementation looks clean and well-integrated with the refs API. The patch follows through on the series' goal of providing a way to query optimization needs without performing the optimization, and it maintains consistency with existing optimization behavior. The changes are nearing finalization with reviewers having signed off on the approach.
