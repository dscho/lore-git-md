This is a response from Junio C Hamano to Justin Tobler's RFC proposing a new `--report-binary-files` option for `git diff`. The response expresses skepticism about the approach and raises broader concerns about extending the raw diff format.

Junio's key objections are:
1. Questions whether this feature belongs in the raw diff format at all, suggesting it might lead to a proliferation of similar format extensions (like adding incomplete-line indicators)
2. Raises concerns about how this would scale to 3-way diffs (merge commits), where the current 2-character prefix would need to expand to 3 characters
3. Implicitly challenges the fundamental premise that raw diff output should be extended for this use case, with a clear "yuck" reaction to the proposal

The response doesn't offer alternative solutions but serves as a strong signal that the maintainer has reservations about the direction of the feature. This suggests the thread may need to either:
- A more comprehensive redesign of how binary file information is reported
- A different output format mechanism that doesn't modify the core raw diff syntax
- Stronger justification for why this specific change is worth the format disruption

The discussion now pivots from technical implementation details to more fundamental questions about the feature's design and placement in Git's output formats. Future replies will likely need to address these architectural concerns rather than just the specifics of the current patch.
