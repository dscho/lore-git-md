Patch 08/12 in Junio Hamano's series to improve incomplete-line handling in Git's diff/apply machinery. This patch focuses on revamping how `git apply` parses patches containing incomplete lines (those missing terminating newlines).

The key change moves the parsing of "\ No newline at end of file" markers from being handled as a special case after line processing to being integrated with the line parsing itself. A new `adjust_incomplete()` helper function now detects these markers immediately after their associated context/added/removed lines, allowing the parser to properly track incomplete-line state during normal processing.

The patch makes several important technical changes:
- Introduces `adjust_incomplete()` to centralize marker detection
- Modifies `parse_fragment()` to use this helper during line processing
- Removes the post-processing special case for incomplete lines
- Carefully maintains the existing line counting and offset tracking
- Adds detailed comments explaining the new parsing flow

This change prepares the codebase for the upcoming incomplete-line whitespace checking by ensuring the parser properly represents incomplete lines in its internal state. The patch follows the series' pattern of careful refactoring before introducing new functionality, with particular attention to maintaining existing behavior while improving the code structure. The changes align the parsing side's handling of incomplete lines with how the application side already processes them.
