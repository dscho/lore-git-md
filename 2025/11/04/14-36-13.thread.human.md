This thread addresses a bugfix for a regression in Git's ref-filter code introduced by commit 054f5f457e ("ref-filter: parse objects on demand"). The issue causes stale object data to persist between calls due to improper resetting of the `maybe_object` field in `struct expand_data`. 

The fix, proposed by the original author of the problematic commit, simply resets `maybe_object` to NULL in `get_object()` before processing each new object. Junio Hamano caught the regression, which manifests when sorting annotated tags by version with cached refs. The patch includes a new test case in t7004-tag.sh to verify correct behavior in this scenario.

The change is narrowly scoped to ref-filter.c's object parsing logic and builds on Jeff King's prior work. While the impact is limited (not all code paths use the affected function), the fix is important for maintaining correctness in version sorting operations. The patch has clear test coverage and appears ready for merging.
