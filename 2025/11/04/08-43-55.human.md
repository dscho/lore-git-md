This is a feature addition to `git maintenance`, introducing a new 'is-needed' subcommand that checks whether maintenance tasks are required without actually running them. The 5-patch series builds on prior work to generalize reference backend optimization checks into a broader maintenance needs query system.

The series adds infrastructure to check ref backend optimization state (patches 1-3), implements the checking logic (patch 4), and finally introduces the 'is-needed' subcommand (patch 5). The new command exits with status 0 if maintenance is needed, 1 otherwise, and supports `--task` filtering and `--auto` mode to match the existing `git maintenance run --auto` heuristics.

Key technical points:
- New `optimize_required` field in `struct ref_storage_be` with implementations for files, packed, and reftable backends
- Reftable backend checks compaction needs via `reftable_stack_compaction_required()`
- When no `--task` is specified, checks tasks based on configured maintenance strategy
- Currently limited to checking optimization needs (not schedule requirements)
