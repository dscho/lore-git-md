This is a follow-up cleanup patch to the completed series about `:(optional)` path handling. Junio Hamano adds a small but important improvement to patch 1's changes in parse-options.c, removing redundant NULL check logic that can never be reached.

The change eliminates an impossible condition in `do_get_value()` where `value` was being checked for NULL after `skip_prefix()`, which Junio explains can never happen because:
1) `skip_prefix()` either advances the pointer within the same string (never making it NULL)
2) Or leaves it unchanged (and it was already non-NULL to avoid dereferencing NULL)

The patch is minimal (2-line deletion) and clearly reasoned, with Phillip Wood credited as helping identify this cleanup opportunity. This comes as the series is being finalized for merging, with patch 1 already confirmed for inclusion in the upcoming 2.52.0 release. The change maintains all existing functionality while removing dead code path, following the series' theme of tightening up the implementation.
