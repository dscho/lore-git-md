This is a refactoring patch in Junio Hamano's series introducing "incomplete-line" whitespace error detection. It's the second patch in a 12-part series (preceded by preparatory cleanups and followed by bitmask infrastructure changes and core implementation).

The patch standardizes the brace style in `emit_line_ws_markup()` in diff.c, applying a consistent rule: when one branch of an if/else cascade uses braces, all branches should. The change is purely stylistic - it adds braces to three conditional branches that previously lacked them while keeping the same logic flow. The function handles whitespace markup for diff output lines, with different cases for when whitespace highlighting is needed versus when sign markers (like +/-) should be shown.

This continues the series' pattern of careful preparatory cleanups before introducing new functionality. The change touches the same diff.c file that will later be modified to support the new incomplete-line whitespace detection (as noted in the thread summary's bitmask discussion). While minor, such consistency improvements help maintainability and reduce cognitive load when reading the more complex changes coming in later patches.
