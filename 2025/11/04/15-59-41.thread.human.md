This thread began with René Rahn reporting a bug where `git add` would incorrectly warn about ignored files when they were explicitly excluded via pathspec magic (`:(exclude)`). Junio Hamano quickly proposed a fix that modified `dir.c` to properly handle exclude patterns, adding tests to verify the corrected behavior where excluded+ignored files would be silently skipped.

In the latest development, Junio has raised deeper concerns about the implementation approach. While the current fix works, he questions whether it's addressing the symptom rather than the root cause - specifically, why there's a separate `exclude_matches_pathspec` function instead of using Git's standard `match_pathspec` infrastructure. He traces this back to historical changes in 2010 and 2017, suggesting the issue might reflect a broader architectural question about pathspec handling.

The discussion has now moved beyond just fixing this particular bug to considering whether a more fundamental refactoring of pathspec processing is needed. While the current patch passes all tests, Junio remains cautious about potential unintended consequences, indicating this might turn into a larger design effort to properly unify pathspec matching logic across Git's codebase.
