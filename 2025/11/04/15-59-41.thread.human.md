René Rahn reported a bug where `git add` incorrectly warns about ignored files even when they're explicitly excluded via `:(exclude)` pathspecs. The current behavior forces users to use `-f` as a workaround, which can have unintended side effects. The issue stems from how pathspec exclusion logic interacts with `.gitignore` rules in the dir.c and pathspec.c components.

Junio Hamano has now proposed a fix that modifies the pathspec handling in `dir.c` to properly track exclude patterns separately from regular pathspec elements. The patch ensures Git will silently skip files that match either exclude patterns or ignore rules, eliminating the redundant warning. A new test case in t2204 verifies this corrected behavior.

Junio suspects this may fix a regression dating back to 2017, though he notes some uncertainty about edge cases. While the change cleanly addresses René's reported scenario, its broader impact on pathspec processing will need to be considered. The patch currently passes all existing tests, suggesting it doesn't break other expected behaviors.
