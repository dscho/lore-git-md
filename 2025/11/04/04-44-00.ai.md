Maintainer feedback on binary file reporting proposal. Junio C Hamano strongly objects to the current approach of extending the raw diff format with binary file indicators, arguing it would lead to format proliferation for other attributes like incomplete lines or line endings. He suggests this is a symptom of a larger design issue with the raw diff format's extensibility.

The maintainer proposes an alternative direction: an extensible `--raw-extended` option that could report multiple file attributes (binary status, incomplete lines, line endings) in a single machine-parseable format. This would use letter codes like "bt,ic,cl" to indicate binary/text status, incomplete line status, and CRLF/LF transitions respectively. The format would need to support N-way diffs (like 3-way merge diffs) by using N-letter tuples rather than fixed pairs.

Key technical concerns raised:
- Current patch singles out binary status when other attributes are equally important
- Need for forward-compatible design that can scale to N-way diffs
- Fundamental question of whether raw diff is the right vehicle for this information
- The "yuck" reaction signals the proposal needs significant redesign before consideration
- Suggests moving to a more general attribute reporting mechanism rather than binary-specific solution

This email effectively puts the RFC on hold pending a more comprehensive design that addresses:
1. Multiple attribute reporting needs
2. N-way diff compatibility
3. Clean extensibility mechanism
The ball is now in the author's court to either propose such a design or reconsider the approach entirely.
