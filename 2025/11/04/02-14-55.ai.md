Feature proposal adding a new diff option to report binary file status in raw diffs.

This RFC patch introduces a `--report-binary-files` option to `git diff` that adds a new column to raw diff output indicating whether each file in a diff pair was considered binary. Currently, Git only shows a generic "Binary files differ" message when either side is binary, making it impossible to tell which specific files triggered this. The new option adds a two-character column ('bb', 'bt', 'tb', or 'tt') before the status to explicitly mark binary status each file was given during diff calculation.

The implementation touches diff formatting internals, adding a new flag to `struct diff_options` and modifying the raw diff output generation in `diff.c`. Documentation updates explain the new format and option. Tests verify the behavior with various binary/text file combinations. The author considered but rejected modifying the human-readable "binary files differ" message in favor of this machine-parseable approach.

Key technical details:
- New `report_binary_files` flag in `struct diff_options`
- Output format adds two-character binary status before file status (b=binary, t=text)
- Does not affect combined diffs
- Test cases cover all combinations of binary/text files
- Documentation updates in both format and options manpages

Potential discussion points:
- Whether raw diff format is the right place for this (vs. human-readable output)
- The choice of 'b'/'t' markers (could use more descriptive codes)
- Impact on parsers that expect current raw diff format
- Whether this should be default behavior rather than opt-in
