This is a bugfix patch addressing a regression in the ref-filter code. The issue stems from commit 054f5f457e ("ref-filter: parse objects on demand") which introduced lazy parsing of objects via a new `maybe_object` field in `struct expand_data`. The problem occurs because this field isn't properly reset between calls, causing stale object data to be incorrectly reused in subsequent operations.

The fix is straightforward - reset `maybe_object` to NULL in `get_object()` before processing each new object. The patch includes a new test case that verifies correct behavior when sorting annotated tags by version, including when tag data is cached in packed-refs. The regression was caught by Junio Hamano and builds on prior work from Jeff King.

Key technical details:
- Affects `ref-filter.c`'s object parsing logic
- Introduces new test in `t/t7004-tag.sh` to exercise version sorting with cached refs
- Fixes a subtle issue where cached object state could leak between calls
- Builds on ps/ref-peeled-tags branch at 054f5f457e
- The impact is limited since not all code paths use the affected `get_or_parse_object()` function

The patch appears well-contained with a clear explanation of both the problem and solution, plus thorough test coverage for the regression scenario.
