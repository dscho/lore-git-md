This thread documents a regression in `git grep -l` output formatting where filenames containing dashes are incorrectly displayed with the first dash replaced by a colon and unintended color applied to the preceding text. The issue was first reported occurring between Git versions 2.49.1 and 2.51.1, with clean behavior in earlier versions.

Kristoffer Haugsbakk has now observed similar behavior when using the Delta pager, suggesting the issue might involve interactions with external tools in the output chain. While the core problem remains the dash-to-colon transformation, the Delta pager case shows the regression can manifest differently depending on output configuration - it doesn't occur with `--no-pager`, but the coloring behavior persists even with `--color=never`. This expands the scope of investigation to consider both Git's internal output handling and potential interactions with pagers.

The thread currently lacks analysis from grep or pager subsystem experts. Key open questions remain about what specific change introduced the behavior and whether it relates to color handling, filename parsing, or pager integration. The Delta pager observation provides another reproduction path that may help isolate the root cause.
