A bug report describes a regression in `git grep -l` where filenames containing dashes are incorrectly formatted - the first dash gets replaced with a colon and the text before it appears in pink color. The reporter has verified this occurs specifically in Git 2.51.1 (but not in earlier versions 2.47.3 or 2.49.1) across different shells and terminals. A simple test case demonstrates the issue: creating a file like "test-one" and running `git grep -l` shows the filename incorrectly as "test:one" with color highlighting. The problem appears to stem from changes in the grep output formatting between versions 2.49.1 and 2.51.1.
