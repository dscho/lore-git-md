This is a bug report about unexpected behavior in `git grep` output when searching files with dashes in their names. The reporter, Michael Roach, found that when running `git grep` on files containing dashes (like `ensure-string-env.rb`), the output incorrectly displays the first dash as a colon and applies color highlighting to part of the path. This occurs in Git 2.51.1 but worked correctly in earlier versions (2.47.3 and 2.49.1).

The issue is easily reproducible with a simple test case: creating a file with a dash (like `test-one`) and searching for content in it results in malformed output (`test:one`). The problem appears consistently across different shells (zsh and bash) and terminals, suggesting it's a Git regression rather than an environment issue.

The report includes thorough reproduction steps and version information, making it easy to verify. Since the behavior changed between versions, this likely represents a regression introduced in Git 2.51.x. The bug affects the display functionality of `git grep` but doesn't appear to impact the actual search results - it's purely a formatting/display issue.

This seems like a legitimate bug that would be worth investigating, particularly since it affects a common use case (searching files with dashes in their names) and represents a regression from previous behavior. The clear reproduction steps and version comparison make this a well-documented report.
