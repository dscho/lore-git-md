This RFC thread explores adding binary file status indicators to `git diff` output. The original proposal suggested modifying the raw diff format with two-character prefixes ('bb', 'bt', etc.) to show which files were considered binary. While the implementation was technically sound with thorough test coverage, maintainer Junio C Hamano raised fundamental design objections.

Junio strongly opposed extending the raw diff format, arguing it would lead to format proliferation as other attributes (like incomplete lines or line endings) might also need indicators. Instead, he proposed a more comprehensive solution: a new `--raw-extended` option that could report multiple file attributes in a machine-parseable format using letter codes (e.g., "bt,ic,cl" for binary/text status, incomplete lines, and line endings). This approach would need to support N-way diffs through N-letter tuples.

The discussion has shifted from implementation details to broader design questions. The maintainer's "yuck" reaction and alternative proposal indicate the current approach is unlikely to be accepted without significant redesign. The author now faces a choice between developing a more extensible attribute reporting mechanism or reconsidering whether to pursue this functionality at all. No other contributors have weighed in yet, leaving the next steps dependent on how the author responds to these architectural concerns.
