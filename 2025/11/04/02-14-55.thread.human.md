This RFC thread explores extending `git diff --raw` to report file attributes like binary/text status, line endings, and incomplete lines. What began as a binary-only reporting proposal has evolved into designing a general attribute reporting framework (`--raw-extended`) following Junio C Hamano's architectural guidance.

The discussion now centers on output format tradeoffs. Justin Tobler proposed a key=value approach ("binary=tt,incomplete=ic"), but Junio raises concerns about parseability and script-friendliness, noting that wide lines may be preferable to complex key-value syntax. The thread has established consensus on needing an extensible system but remains undecided between compact letter codes versus more verbose key-value pairs, with Junio emphasizing the importance of easy parsing for scripting use cases.

Key open questions include how to handle attribute separation, multi-parent diffs, and future extensibility. While the architectural direction is settled, the concrete syntax remains in flux, with Junio's latest feedback suggesting the key=value approach may introduce new parsing challenges. The discussion awaits either refinement of the current proposal or alternative format suggestions to move forward.
