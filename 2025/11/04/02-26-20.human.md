This is a response from Junio Hamano to Justin Tobler's RFC proposing a new `--report-binary-files` option for `git diff`. The response expresses skepticism about extending the raw diff format with binary file indicators.

Junio raises several concerns in his characteristically terse style. First, he questions where such format extensions might stop by drawing a parallel with incomplete line indicators - if we add binary indicators, why not add other metadata too?

He also points out potential issues with extending this to combined diffs (from merges), where the two-character prefix would need to become three characters to cover all parent versions. His "yuck ;-)" comment suggests he finds the proposal inelegant and potentially opening Pandora's box of format extensions.

The response doesn't outright reject the idea but challenges the author to think more deeply about the design implications. It's a classic maintainer response pushing back on what might be seen as a narrowly-focused solution without considering broader impacts on Git's diff machinery.

This moves the discussion forward by raising important architectural questions that the original proposal will need to address in any revision. The thread is now poised for either a refined proposal or alternative solutions to Justin's underlying use case.
