This is a discussion about finalizing the reflog message format for the atomic ref updates in `git replay`, part of the feature series that has already received broad approval.

Phillip Wood responds to Siddharth Asthana's proposal for simpler reflog messages that mirror the command-line syntax ("replay --onto main"). While agreeing the format makes sense, Phillip notes a tradeoff: using symbolic names (like "main") is more readable but makes it harder to determine exactly which commit was used historically, since you'd need to cross-reference the branch's reflog. He suggests this might be acceptable given the usability benefits.

For `--advance` mode, Phillip considers including the full revision range (e.g. "topic1..topic2") but acknowledges this could get unwieldy for complex ranges. He proposes a middle ground: use simple ranges when possible ("a..b") but fall back to something more general for complex cases, avoiding the per-commit reflog entries that `git cherry-pick` creates. The discussion remains open-ended on this point, with Phillip inviting further input on what would be most useful.

The email confirms Siddharth will add tests for the reflog messages in both modes, addressing one of the last remaining open items from the thread summary. The core technical implementation of atomic updates using ref transactions (with `REF_ACTION_UPDATE` and `REF_ACTION_PRINT` modes) remains unchanged and approved.
