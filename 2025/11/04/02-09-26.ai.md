Feature implementation for incomplete-line whitespace handling in `git apply`. This is patch 10/12 in Junio Hamano's series introducing configurable detection and correction of missing terminating newlines.

The patch adds the core implementation for `git apply` to recognize and handle incomplete lines (files missing a final newline) as a new whitespace error class. The new "incomplete-line" rule is disabled by default for backward compatibility. When enabled via `core.whitespace` or `.gitattributes`, `git apply --whitespace={fix,warn,error}` will detect, warn about, and optionally fix these cases.

Key technical changes:
- Adds WS_INCOMPLETE_LINE (0x8000) to ws.h's whitespace rule bitmask
- Extends ws.c to check for missing newlines when the rule is active
- Implements automatic fixing by appending missing newlines
- Adds comprehensive test coverage in t/t4124-apply-ws-rule.sh covering:
  - Context lines with incomplete status (not an error)
  - Introducing incomplete lines (error)
  - Removing incomplete lines (not an error)
  - Correcting incomplete lines (not an error)
  - Modifying incomplete lines (error)

The implementation treats modifying an incomplete line while keeping it incomplete as an error, with the rationale that changes to such lines should include fixing the newline. This may be a point of discussion as the commit message notes it could be controversial. The patch builds on the preparatory work in earlier patches (particularly the bitmask reallocation in patch 09) and maintains consistent behavior with the diff-side changes coming in patch 11.
