This is a bugfix addressing a regression in ref-filter's lazy object parsing logic. The issue was introduced by commit 054f5f457e ("ref-filter: parse objects on demand") which added on-demand parsing via a `maybe_object` field in `struct expand_data`. The field wasn't being properly reset between calls, causing stale object data to persist.

The fix, now queued for merging, resets `maybe_object` to NULL in `get_object()` before processing each new object. The regression was identified by Junio Hamano when it affected version sorting of annotated tags with packed-refs caching. The impact was limited to code paths using this specific lazy-parsing functionality.

The patch includes a new case in t/t7004-tag.sh to verify correct behavior with cached refs. While the fix is straightforward, Junio notes that the original "on demand" optimization might benefit from additional benchmarking, though the current test case using %(raw) wouldn't be affected by this particular issue.

This appears to be a well-contained fix for a clearly identified regression, with proper test coverage and acknowledgments to both the reporter and an earlier patch contributor. The thread shows consensus on both the problem and solution, with the fix now progressing through the integration process.
