This is a bugfix for the ref-filter subsystem, addressing a regression in object parsing logic that affected version sorting of annotated tags when ref data is cached in packed-refs. The issue was introduced by commit 054f5f457e ("ref-filter: parse objects on demand") which added lazy object parsing but failed to properly reset state between calls.

Junio Hamano confirms the fix proposed by Patrick Steinhardt, which resets the `maybe_object` field in `get_object()` before processing each new object. The impact was limited to code paths using the affected parsing functionality, which explains why it wasn't caught earlier despite Junio's regular use of the version tag sorting feature.

The patch appears straightforward and well-justified, with Junio indicating he will queue it immediately on top of the ps/ref-peeled-tags branch and merge it to 'next'. No further discussion seems needed as this is a clear-cut fix for a known regression with no open questions remaining.
