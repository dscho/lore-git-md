This is a maintainer review response in the gitk external diff bugfix thread, now at v7. Johannes Sixt provides detailed technical feedback on Tobias Boesch's implementation of rename detection for external diffs in gitk.

The review focuses on three specific issues in the current implementation: First, the rename detection only works when selecting the renamed-to file in the UI, contrary to the commit message's claim of handling both original and renamed files. Second, the string matching for "rename from/to" lines could be made more precise using `string equal` with length checks. Third, there's a potential issue with non-ASCII filenames that's noted but deferred as a separate bug.

Johannes also suggests a style improvement, recommending `ne` operator over `!=` for string comparison in Tcl. The feedback maintains the thread's productive tone while being technically precise about remaining issues in what is otherwise a well-evolved solution through seven iterations.

The patch remains focused on gitk's Tcl script, specifically the `check_for_renames_in_diff` proc and its integration with `external_diff`. Key technical points include the use of gitk's `difffilestart` variable and text widget (`ctext`) to parse rename information from diff headers, with paths extracted from lines +2/+3 after the header. The review doesn't suggest any architectural changes but rather precision improvements to the current approach.
