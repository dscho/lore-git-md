This is a feature patch series introducing a new 'is-needed' subcommand for `git maintenance`. The series builds on prior work to check if reference backends need optimization, generalizing it into a broader maintenance needs query system.

The 5-patch series:
1. Enhances the reftable backend to expose optimization state checking
2. Adds infrastructure for checking ref backend optimization state across all backends (files, packed, reftable)
3. Modifies `pack_refs_condition()` to use the new backend checks
4. Implements the 'is-needed' subcommand with `--task` filtering and `--auto` support
5. Includes comprehensive tests in t7900

Key technical details:
- New `optimize_required` field in `struct ref_storage_be`
- `reftable_stack_compaction_required()` API with `use_heuristics` parameter
- Exit status 0 if maintenance needed, 1 otherwise
- When no `--task` specified, checks tasks based on configured maintenance strategy
- Current limitation: non-auto mode always returns "needed" even for tasks with nothing to optimize
