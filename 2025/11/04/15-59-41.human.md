This is a bug report about `git add`'s handling of excluded pathspecs with ignored files. René Rahn reports that when using an exclude pathspec (like `:(exclude)ignored.txt`) to add files, Git still checks whether the excluded file is ignored by `.gitignore`, producing an unnecessary warning. The expected behavior would be to skip the ignored-file check for explicitly excluded paths.

The report includes clear reproduction steps showing that even when a file is both ignored and explicitly excluded, Git still warns about it being ignored. While using `-f` can suppress the warning, René argues this isn't the right solution since the file shouldn't be considered for addition in the first place.

This appears to be a legitimate edge case in pathspec handling that hasn't been discussed before. The report is well-structured with a specific example and clear expectations, making it easy to understand the issue. It seems like a reasonable candidate for fixing, though the solution might need careful consideration to avoid breaking other pathspec use cases.
