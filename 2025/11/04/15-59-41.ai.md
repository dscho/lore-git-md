This is a bug report about unexpected behavior in `git add` when combining exclude patterns with ignored files. The issue occurs when using an explicit pathspec with an exclude pattern (`:(exclude)`) that matches a file already ignored by `.gitignore`. Currently, Git still checks and complains about the ignored file, even though the exclude pattern should logically make that check redundant.

The reporter, René Rahn, provides clear reproduction steps: create a repo with an ignored file (`ignored.txt`), then try to add all files while excluding that same file. Git incorrectly warns about the file being ignored, when it should simply skip it due to the exclude pattern. The workaround of using `-f` (force) is noted as potentially problematic since it could affect other ignored files not meant to be excluded.

The bug appears to be a logical inconsistency in how Git processes exclude patterns versus ignore rules. The reporter suggests the exclude pattern should take precedence, making the ignore check unnecessary for explicitly excluded files. This seems like a valid point that could be addressed by modifying the pathspec processing logic in `git-add`.

Key technical details:
- Affects `git add` with `:(exclude)` pathspecs
- Involves interaction between pathspec exclusion and `.gitignore` rules
- Current behavior shows warning when excluded file is also ignored
- Expected behavior would skip both excluded and ignored files silently
- Related to pathspec.c and dir.c handling of exclusion patterns

The report is well-structured with clear reproduction steps and rationale, making it easy to verify and potentially fix. This seems like a legitimate bug that could be addressed with a focused change to how exclude patterns are processed relative to ignore rules.
