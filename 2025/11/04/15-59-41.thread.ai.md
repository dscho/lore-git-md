Thread identity: Bug report about `git add` behavior with exclude patterns (`:(exclude)`) interacting with `.gitignore` rules, reported by René Rahn.

Core problem: When using `git add` with an explicit exclude pathspec matching a file that is also ignored by `.gitignore`, Git incorrectly warns about the file being ignored. The exclude pattern should logically make this check redundant, as the file is explicitly excluded from the operation. Current behavior forces users to use `-f` (force) as a workaround, which may unintentionally affect other ignored files.

Current status: Bug reported with clear steps to reproduce. No patches or fixes proposed yet. Workaround exists (using `-f` flag) but has undesirable side effects.

Key technical details:
- Affects pathspec processing in `git add`
- Involves interaction between pathspec.c exclusion logic and dir.c ignore rules
- Expected behavior would be to silently skip files matching either exclude patterns or ignore rules
- Current implementation checks ignore rules even for explicitly excluded paths

Open questions:

- Are there edge cases where the current behavior is actually desirable?
