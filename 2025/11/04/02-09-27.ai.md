This is patch 11/12 in Junio Hamano's series introducing incomplete-line whitespace handling, focusing on `git diff` integration. The patch teaches `git diff` to highlight missing newline indicators ("\ No newline at end of file") as whitespace errors when the incomplete-line class is enabled, and makes `git diff --check` report them as errors.

Key technical changes include modifying `diff.c` to:
1. Colorize the incomplete-line marker when WS_INCOMPLETE_LINE is active in `emit_diff_symbol_from_struct`
2. Pass proper whitespace checking flags through `emit_incomplete_line`
3. Extend the `checkdiff_consume` logic to detect and report incomplete lines in added content
4. Track line types (added/removed/context) through the new `last_line_kind` field in `checkdiff_t`

The test suite (`t4015-diff-whitespace.sh`) is expanded with several new scenarios:
- Context lines with incomplete status (not flagged as they're not being modified)
- Incomplete lines in both pre- and post-image (flagged as errors when modified)
- Fixing incomplete lines (not flagged when corrected)
- Introducing new incomplete lines (flagged as errors)
- Integration with existing whitespace highlighting and config options

The implementation builds on the preparatory work from earlier patches, particularly the bitmask changes (patch 9) and parser improvements (patch 8). It maintains the series' philosophy of treating modification of incomplete lines (without fixing them) as errors, which the commit message notes may be controversial. The test coverage is thorough, exercising both the diff output coloring and the `--check` functionality.
