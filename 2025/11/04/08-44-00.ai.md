This is the final patch in Karthik Nayak's series adding a new 'is-needed' subcommand to `git maintenance`. The subcommand allows checking whether maintenance tasks would run (under `--auto` conditions) without actually executing them, returning exit code 0 if maintenance is needed and 1 otherwise.

The implementation builds on the ref backend optimization checks from earlier patches, exposing them through a new `maintenance_is_needed()` function that:
- Accepts `--auto` flag to use the same heuristics as `maintenance run --auto`
- Supports `--task` filtering like other maintenance subcommands
- Returns status based on whether any enabled/selected tasks meet their auto-condition thresholds
- Always returns "needed" in non-auto mode (current limitation noted in docs)

The patch includes comprehensive tests in t7900 that verify:
- Basic command behavior with/without `--auto`
- Integration with all maintenance tasks' auto conditions (gc, commit-graph, loose-objects, etc.)
- Correct exit code propagation
- Config option handling (maintenance.*.auto values)
- Removal of a duplicate test case

Documentation covers the new subcommand's purpose, flags, and current limitations. The implementation reuses existing auto-condition logic while maintaining consistency with `maintenance run` behavior. This completes the series' goal of providing visibility into maintenance heuristics without execution overhead.
