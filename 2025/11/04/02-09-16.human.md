This is a feature series introducing new whitespace handling for incomplete lines (files without terminating newlines). Junio C Hamano proposes adding an "incomplete-line" whitespace error class that can be enabled via config or gitattributes, with detection and auto-fixing support across `git diff` and `git apply`.

The series starts with preparatory cleanups to the diff and apply machinery (patches 1-8), then makes room in the whitespace bitfield (patch 9) before implementing the actual feature. The new checks will flag missing newlines in post-images as errors, except when the pre-image already had an incomplete line that wasn't modified. The final patch enables these checks for Git's own C and shell code.

The implementation looks thorough, with comprehensive test coverage across both diff` and `apply` behaviors. This addresses a long-standing gap in Git's whitespace handling (unchanged since 2007) and follows the project's typical pattern of making new checks opt-in via config before potentially enabling them by default for certain file types. The series builds on previous discussion (referencing an earlier cleanup patch) and appears ready for review.
