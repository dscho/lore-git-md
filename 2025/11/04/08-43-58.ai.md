This is part 3 of a 5-patch series introducing a new 'is-needed' subcommand for `git maintenance` to check if maintenance tasks are required. The patch adds infrastructure for checking ref backend optimization state across all supported backends (files, packed, reftable).

The key technical changes in this patch:
- Adds new `optimize_required` field to `struct ref_storage_be` with corresponding function type `optimize_required_fn`
- Implements the callback for each backend:
  - Files backend checks `should_pack_refs()`
  - Packed backend always returns false (already optimized)
  - Reftable backend uses new `reftable_stack_compaction_required()` (from previous patches)
  - Debug backend wraps and traces the underlying implementation
- Exposes new `refs_optimize_required()` public API that calls through to backend implementations
- Maintains consistent behavior with existing `refs_optimize()` infrastructure

The implementation follows the design agreed upon in earlier discussion, with clear separation between checking if optimization is needed (this patch) and performing the optimization (existing code). The reftable implementation specifically handles both auto-mode heuristics and full compaction checks via the `use_heuristics` parameter.

This is a well-structured patch that cleanly extends the refs backend interface while maintaining consistency across storage types. It provides the foundation for the upcoming 'is-needed' subcommand while keeping the optimization logic properly encapsulated within each backend.
