Maintainer feedback on binary file reporting proposal. Junio C Hamano expresses strong reservations about modifying the raw diff format to indicate binary file status, arguing this approach would lead to format proliferation as other developers request similar indicators for incomplete lines, line endings, and other file traits. He suggests the current patch's binary-file focus is too narrow given other equally valid format extension needs.

The maintainer proposes an alternative design direction: an extensible `--raw-extended` option that could support multiple format extensions (binary, incomplete lines, CRLF status) with corresponding output markers. This would avoid the need for separate options for each new format extension. He also raises the question of how such indicators would scale to 3-way diffs from merge commits.

The response signals that the original RFC needs significant redesign to be considered for inclusion, with the maintainer clearly preferring a more comprehensive solution over the current binary-specific approach. The discussion has shifted from implementation details to fundamental questions about Git's raw diff format evolution strategy.
