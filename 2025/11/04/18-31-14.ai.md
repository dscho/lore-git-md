This is a bugfix patch addressing a regression in ref-filter's object parsing logic. The patch follows up on the earlier discussion and solution for the issue where `maybe_object` in `struct expand_data` wasn't being properly reset between calls, causing stale object data to persist.

The technical fix resets `maybe_object` to NULL in `get_object()` before processing each new object, ensuring correct behavior when objects are parsed on demand. The regression specifically affected version sorting of annotated tags when ref data was cached in packed-refs, as encountered by Junio Hamano in `--sort=version:tag` operations.

The patch is now queued for merging to the 'next' branch, applying cleanly on top of commit 054f5f457e ("ref-filter: parse objects on demand") in the ps/ref-peeled-tags branch. While the impact was limited to code paths using the lazy-parsing functionality, the fix ensures proper behavior across all cases.

Junio notes that while the fix ensures correct parsing, it doesn't affect the performance benchmarks originally cited for the "on demand" feature since those used %(raw) which wasn't impacted by this bug. The solution appears straightforward and well-contained, addressing the specific regression without introducing new complexity.
