This is a bugfix for the ref-filter code that addresses a regression introduced in a recent optimization. The patch fixes a case where parsed objects could be incorrectly reused across calls due to missing cleanup of a cached object pointer.

The issue stems from commit 054f5f457e ("ref-filter: parse objects on demand"), which added lazy parsing of refs to improve performance. However, it failed to properly reset the `maybe_object` field between calls, causing some operations to reuse stale object data. The effect was limited to certain cases where `get_or_parse_object()` is called, which explains why it wasn't caught earlier.

Patrick Steinhardt's fix adds the missing cleanup by resetting `maybe_object` in `get_object()`. The patch includes a new test case that verifies correct behavior when sorting annotated tags by version, including when refs are packed. The test was likely chosen because it exercises the code path where the bug manifests while also being a realistic use case.

The patch is small (just 2 lines of code plus tests) and comes with good context about both the problem and solution. It's based on a report from Junio Hamano and incorporates input from Jeff King, suggesting it has already had some review. The fix appears straightforward and low-risk for a regression that could cause subtle issues with ref filtering.
