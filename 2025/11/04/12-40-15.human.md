This is a follow-up in the thread about a bugfix for the ref-peeled-tags regression. Patrick Steinhardt confirms Jeff King's analysis of the root cause - an unreset `data->maybe_object` in ref-filter.c that causes incorrect caching during version sorting of tags. 

Patrick agrees with Jeff's proposed one-line fix but suggests using the `get_object()` function instead as the entry point for `grab_values()`. He acknowledges the issue stems from misunderstanding that `oi` and `oi_peeled` were global variables rather than being populated per reference. 

The exchange shows the maintainers converging on a solution for this regression that affects `git tag --list --sort=version:tag` behavior. Patrick indicates he'll send an updated patch shortly incorporating this fix approach. The discussion demonstrates solid technical collaboration to resolve a subtle caching issue introduced by recent ref-filter changes.
