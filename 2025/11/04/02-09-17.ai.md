This is a preparatory refactoring patch in Junio Hamano's series introducing "incomplete-line" whitespace error detection. It focuses on documentation and code organization of bitmask constants used for whitespace and diff highlighting rules.

The patch makes several technical improvements to the bitmask infrastructure that will later support the new WS_INCOMPLETE_LINE feature. It corrects inaccurate comments about bit assignments in diff.c that had miscounted the bit positions (previously claiming bits 0-12 were for whitespace when actually 0-11). The changes clarify that bits 12-14 are for new/context/old line highlighting, 16 for blank-at-EOF, and 17-19 for color-moved detection.

Significant changes include:
- Converting octal constants to (1 << N) notation in ws.h for better readability and maintainability
- Adding blank lines between logical groups of macro definitions
- Updating WS_RULE_MASK and WS_TAB_WIDTH_MASK to use bit-shift math instead of octal
- Ensuring comments accurately reflect the current bit assignments

The changes are purely internal - no behavior changes or user-facing impacts. This appears to be careful, well-explained groundwork for the subsequent patches that will add the new incomplete-line functionality. The commit message clearly explains both the what and why of each change.
