Junio Hamano proposes a fix for the `git add` exclude-patterns bug. This is a bugfix targeting the interaction between pathspec exclusion and `.gitignore` rules.

The patch modifies `dir.c` to properly handle `:(exclude)` pathspec elements when checking if an ignored file matches the pathspec. The current code was treating exclude patterns as positive matches, causing Git to incorrectly warn about ignored files that were already excluded. The fix introduces separate tracking for exclude patterns versus regular pathspec elements, applying the correct "match any positive but no negative" logic.

The change is accompanied by a new test case in `t/t2204-add-ignored.sh` that verifies the fixed behavior: when using `:(exclude)` on a file that's also in `.gitignore`, Git should silently skip the file without warning about it being ignored. The test confirms both the warning behavior for regular adds of ignored files and the silent exclusion when using the pathspec magic.

Junio notes this might be a regression dating back to 2017's e1b8c7bd (dir: remove struct path_simplify) and expresses some uncertainty about potential edge cases, though the existing test suite passes with the change. The patch appears to be a direct solution to René Rahn's reported issue, though its impact on other pathspec processing scenarios remains to be fully explored.
