Feature: New 'is-needed' subcommand for git-maintenance

This is the final patch in Karthik Nayak's series adding a new 'is-needed' subcommand to `git maintenance`. The subcommand checks whether maintenance tasks should be run (exiting with status 0 if needed, 1 otherwise) without actually performing them. This provides visibility into the heuristics that normally only run during `--auto` maintenance.

The implementation reuses the existing auto-condition logic from each maintenance task but returns exit codes instead of running the tasks. When used with `--auto`, it checks the configured thresholds (like number of loose objects or pack files). Without `--auto`, it always reports maintenance is needed, matching the behavior of `run` without `--auto`.

The patch includes thorough tests in t7900-maintenance.sh that verify the exit codes match the expected maintenance conditions. It also removes a redundant test case and updates documentation to explain the new subcommand's behavior and options.

This completes the series that began with refactoring the reftable backend's compaction logic to support checking optimization needs. The implementation has been reviewed and refined through discussion with Patrick Steinhardt and Justin Tobler, addressing all feedback about API design and error handling. The result is a clean addition that provides useful insight into maintenance requirements while maintaining consistency with existing behavior.
