This is part of a series implementing a new 'is-needed' subcommand for `git maintenance` to check if maintenance tasks are required without running them. This particular patch focuses on the reftable backend's optimization checks.

The patch adds `reftable_stack_compaction_required()`, which allows checking if a reftable stack needs compaction without actually performing it. The function takes a `use_heuristics` parameter to distinguish between two modes: when false, it simply checks if all tables can be compacted to one; when true, it uses geometric progression heuristics to determine if compaction would be beneficial. The implementation handles edge cases like stacks with fewer than 2 tables and includes thorough unit test coverage.

This builds on previous discussion where the two-mode approach was defended as necessary to support both `--auto` mode (needing only compaction possibility) and full compaction (requiring detailed segment analysis). The patch appears well-considered, with clean separation between error checking and segment evaluation logic, and maintains consistency with existing compaction behavior. It's part of a larger effort to make maintenance operations more transparent and controllable.
