This is a follow-up in the ongoing discussion about the version tag sorting regression in the ps/ref-peeled-tags changes. Patrick Steinhardt confirms Jeff King's root cause analysis of the bug in ref-filter.c's object caching during `git tag --list --sort=version:tag` operations.

The key technical details:
- The issue stems from unreset `data->maybe_object` caching in ref-filter.c's grab_values() function
- Both `oi` and `oi_peeled` were incorrectly treated as global variables when they should be per-reference
- Jeff King's proposed one-line fix (resetting `data->maybe_object`) is confirmed as correct
- Patrick suggests using `get_object()` as the entry point for grab_values() instead
- The bug affects both loose and packed ref scenarios

Patrick indicates he will send an updated patch shortly incorporating this fix. The discussion shows consensus on the root cause and solution approach, with minor implementation details still to be finalized regarding the exact placement of the object cache reset. This moves the regression fix closer to resolution while maintaining the performance benefits of the original on-demand object parsing changes.
