This is a cover letter for a 12-part patch series introducing a new whitespace error class for incomplete lines (files missing terminating newlines). The series is authored by Junio C Hamano and targets both `git diff` and `git apply` functionality.

The core change adds "incomplete-line" as a new whitespace error class that can be enabled via `core.whitespace` or `.gitattributes`. When enabled, it flags cases where a patch introduces or fails to fix a missing newline at end of file. The series includes detection in `git diff --check`, highlighting in regular diffs, and correction via `git apply --whitespace=fix`.

The implementation is carefully staged: initial patches (01-08) are preparatory cleanups to diff and apply machinery, patch 09 makes room in the whitespace bitmask, patches 10-11 implement the core functionality for apply and diff respectively, and patch 12 enables the check for Git's own C and shell source files. The cover letter provides clear rationale for why only postimage incomplete lines are flagged as errors while context lines are ignored.

Key technical details for future reference: the new whitespace class is implemented via bitmask changes in ws.h, with logic in diff.c and apply.c to handle the new case. Tests are added in t4015 and t4124. The behavior specifically targets the "\ No newline at end of file" marker in patch output, with special handling to distinguish between context vs. changed incomplete lines. The series builds on previous work (referencing an earlier cleanup patch) and maintains backward compatibility by keeping the check disabled by default.
