This is a bugfix patch addressing a regression in ref-filter's object parsing logic. The issue stems from commit 054f5f457e ("ref-filter: parse objects on demand") which introduced lazy object parsing via `maybe_object` in `struct expand_data` but failed to properly reset this field between calls, causing stale object data to persist.

The fix, already proposed in the thread, resets `maybe_object` to NULL in `get_object()` before processing each new object. Junio C Hamano confirms the issue affects `--sort=version:tag` operations when ref data is cached in packed-refs, which he uses frequently. He notes the impact is limited to code paths using `get_or_parse_object()`.

The patch will be queued on top of the ps/ref-peeled-tags branch (where the regression originated) and merged to 'next'. This appears to be a straightforward fix for a real but limited-scope regression, with the original author Patrick Steinhardt involved in the solution. The thread shows consensus on both the problem and fix, with no outstanding questions.
