This is a bug report about unexpected behavior in `git grep`'s output formatting. The reporter describes a regression where filenames containing dashes are incorrectly displayed with color highlighting and the first dash replaced by a colon when using `git grep -l` (list filenames only mode).

Key technical points for future reference:
- The bug manifests when using `git grep -l` with filenames containing dashes
- The first dash in the filename gets replaced with a colon
- The text before the colon appears in pink color (likely unintended color highlighting)
- Reproducible across different shells (zsh, bash) and terminals
- Works correctly in Git 2.47.3 and 2.49.1, broken in 2.51.1
- Minimal reproduction: `echo foo > test-one; git add test-one; git grep -l foo` shows `test:one`
- System info shows this is on Fedora 42 with Git 2.51.1 built with GCC 15.2 and glibc 2.41

The report is well-documented with clear reproduction steps and version comparison, suggesting this is a legitimate regression introduced between Git 2.49.1 and 2.51.1. The behavior appears related to color output and filename parsing in the grep machinery. The reporter has done thorough testing to rule out shell and terminal-specific issues.
