This is a discussion about finalizing the reflog message format for atomic reference updates in `git replay`. Phillip Wood responds to Siddharth Asthana's proposal for simpler reflog messages that would show the mode and target (e.g., "replay --onto main") rather than commit hashes.

Phillip notes that while using symbolic names (like "main") is more user-friendly, it makes it harder to determine exactly which commit was used since you'd need to cross-reference with the branch's reflog. He suggests a middle ground for `--advance` mode: using simple revision ranges (like "a..b") when possible, but falling back to something more general for complex cases to avoid overly long messages.

The discussion is happening as the final polish on an otherwise merge-ready series that implements atomic ref updates for `git replay`. The core functionality has already been reviewed and approved, with this being one of the last details to settle before merging. Phillip confirms Siddharth's plan to add tests for the reflog messages in both modes.
