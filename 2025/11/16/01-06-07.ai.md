This is a maintainer response in the ongoing discussion about adding `--committer` functionality to `git commit`. Junio Hamano provides a detailed explanation of the fundamental asymmetry between author and committer fields in Git's data model, pushing back against ZheNing Hu's argument for interface symmetry.

The email clarifies that the distinction stems from the different roles these fields represent - the author as the original creator of the content versus the committer as the person physically creating the commit object. Junio argues this isn't an inconsistency but rather reflects real-world workflow differences, where multiple authors often contribute through a smaller number of committers (e.g., maintainers applying patches).

Key technical points emphasized:
1. The natural workflow where committer identity typically comes from the current environment/session rather than needing explicit specification
2. The rarity of scenarios where multiple committers would share a single shell session and need to alternate identities
3. The fundamental data model difference that makes author specification more commonly needed than committer specification

This response reinforces the maintainer's position that the proposed `--committer` option addresses an extremely niche use case that doesn't justify the interface complexity, despite the technical soundness of the implementation. The discussion appears to be reaching a philosophical impasse between interface consistency arguments and Git's intentional design choices around commit metadata.
