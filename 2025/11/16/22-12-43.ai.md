This is a follow-up discussion in the ongoing thread about adding a `--committer` option to `git commit`, which has reached an impasse due to philosophical differences about Git's author/committer model. Matej Dujava shares their workflow using `includeIf` patterns in Git config to manage multiple identities across different repositories, providing concrete examples of their configuration setup.

The email focuses on practical identity management scenarios, particularly when fixing misconfigured commits. Matej confirms that `git commit --amend --reset-author` can correctly update both committer and author information when the config is fixed, but notes this changes both dates. They also test and document the behavior of various rebase approaches for updating identities across multiple commits, finding that environment variables don't work as expected for author identity during rebase.

This contribution provides real-world context for the earlier discussion, showing a sophisticated multi-identity setup and exploring edge cases in commit rewriting workflows. However, it doesn't fundamentally change the maintainer's stated position about the intentional asymmetry between author and committer interfaces in Git's design. The technical details about date preservation during rebase operations may be useful background if the discussion continues, but the core philosophical objection to the feature remains unaddressed.
