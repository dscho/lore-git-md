This is a follow-up in the ongoing CI infrastructure discussion about macOS Perforce test reliability. Junio Hamano responds to Koji Nakamaru's proposed fix for the Perforce test flakiness on arm64 runners.

The email confirms Nakamaru's diagnosis that using x86_64 Perforce binaries on arm64 macOS runners (requiring Rosetta translation) was likely causing test instability. Junio expresses openness to Nakamaru's solution of switching to native arm64 binaries (bin.macosx12arm64) but raises two technical questions about the implementation details: whether to alternatively use the x86_64-based macos-14-large runners instead, and why Nakamaru chose Perforce version r24.2 specifically when both older (r23.2) and newer (r25.1) versions also offer arm64 binaries.

The response maintains the thread's focus on architecture compatibility while introducing new considerations about version selection and runner choice. Junio's questions suggest the decision point has shifted from whether to fix the tests to precisely how to implement the fix, with version compatibility implications for both macOS and Linux (since the same P4WHENCE URL serves both platforms). The email leaves open whether the version bump in Nakamaru's patch is strictly necessary for the arm64 fix or introduces other considerations.
