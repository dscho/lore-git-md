CI infrastructure proposal with technical counter-suggestion regarding macOS Perforce tests.

Koji Nakamaru responds to Junio Hamano's proposal to remove Perforce tests from macOS CI jobs by identifying a potential root cause and offering an alternative solution. The issue stems from the CI script downloading x86_64 binaries for Perforce (helix-core-server.tgz) while GitHub's macOS-14+ runners use arm64 architecture, requiring Rosetta translation that may contribute to flakiness.

Nakamaru proposes updating the download URL to fetch arm64-native Perforce binaries (changing from bin.macosx1015x86_64 to bin.macosx12arm64) and confirms this modified version runs successfully in their test environment. The patch also updates the Perforce version from r23.2 to r24.2. This suggests the test failures might be architecture-related rather than fundamental incompatibility, potentially preserving test coverage while improving reliability.

The response provides concrete technical details - the specific file being modified (ci/install-dependencies.sh), the exact URL changes needed, and a successful test run verification link. This positions the suggestion as a viable alternative to complete test removal, though it doesn't address Junio's broader concerns about test runtime costs and lack of user reports. The thread now presents two clear options: remove the tests entirely (Junio's original proposal) or update to arm64 binaries (Nakamaru's counter-proposal).
