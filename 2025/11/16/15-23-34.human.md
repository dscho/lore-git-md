CI infrastructure proposal with an alternative to disabling macOS Perforce tests.

Koji Nakamaru responds to Junio Hamano's proposal to remove Perforce testing from macOS CI jobs due to flakiness. Rather than removing the tests entirely, Nakamaru identifies that the failures may stem from using x86_64 binaries on newer ARM-based macOS runners, requiring Rosetta translation. They propose updating the test setup to use native ARM64 Perforce binaries instead.

The response includes a working patch that:
1. Updates the Perforce version from r23.2 to r24.2
2. Changes the binary download path from `bin.macosx1015x86_64` to `bin.macosx12arm64`
3. Confirms successful test runs with this change in their own GitHub Actions

This suggests the flakiness may be solvable without test removal, though it would require maintaining newer Perforce versions in CI. The proposal keeps the discussion open about whether to invest in fixing the tests or proceed with removing them, now with concrete data about a potential solution.
