This is a follow-up in the ongoing CI infrastructure discussion about macOS Perforce test reliability. Koji Nakamaru responds to Junio Hamano's question about why r24.2 was chosen for the Perforce version bump in the proposed fix for arm64 macOS test flakiness.

Nakamaru explains that his initial selection of r24.2 was based on not finding the arm64 binaries in r23.2 when first checking, but now confirms that r23.2 does indeed contain the needed bin.macosx12arm64 directory. He agrees with Junio that sticking with r23.2 would be preferable, and provides a successful test run [1] showing r23.2 works correctly.

This moves the discussion forward by resolving the version selection question, leaving the architectural solution (using native arm64 binaries) as the remaining technical point to evaluate. The exchange demonstrates careful verification of the proposed fix while maintaining cross-platform compatibility with Linux systems that also use the same Perforce source.
