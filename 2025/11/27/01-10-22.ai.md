This is a cover letter for an RFC patch series proposing a major refactoring of Git's Rust infrastructure to use a Cargo workspace instead of a single crate. The series is incomplete and explicitly marked as RFC to solicit feedback on the approach.

The key motivation is to improve modularity and compilation efficiency by splitting the Rust code into multiple crates (gitcore, link-with-c, generate-headers) rather than having everything in one monolithic crate. Benefits include avoiding full recompiles when only part changes, better dependency isolation, and per-crate C header generation via cbindgen. The series undoes some of Patrick Steinhardt's prior Rust work that assumed a single-crate structure.

Several known issues are flagged for discussion: broken GitHub workflows, Meson build failures on Windows, missing Rust unit test integration, and conflicts with Brian Carlson's SHA interoperability work. The implementation moves Rust crates under rust/ while keeping top-level Cargo.toml, adds new build scripts, and sets up infrastructure for header generation (though not yet used).

The 13 patches touch build systems (Makefile, Meson), CI workflows, and introduce new Rust crates while removing old single-crate infrastructure. This appears to be a serious, well-motivated proposal that would significantly restructure how Rust integrates with Git's build system, though still in early stages with several unresolved technical challenges. The RFC status suggests the author is primarily seeking architectural feedback before completing implementation.
