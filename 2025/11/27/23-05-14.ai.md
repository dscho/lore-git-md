This is a discussion about localization (l10n) inconsistencies in Git's porcelain commands versus plumbing stability requirements. Brian m. carlson responds to Peter Krefting's query about why `git push` shows an English-only "Everything up-to-date" message while `git pull` properly localizes its equivalent message.

The key points are:
1. The English string is marked as stable plumbing output in both builtin/send-pack.c and transport.c, though carlson notes no actual Git tooling depends on this specific message
2. There's a minor English grammar correction opportunity ("up-to-date" -> "up to date") that hasn't been fixed due to hypothetical external tool dependencies
3. carlson shares a precedent where localizing another message (`rev-parse`'s "Needed a single revision") caused temporary breakage but was ultimately accepted
4. They suggest potential solutions like a `--plumbing` flag or using `LC_ALL=C.UTF-8` for stable output, while being personally open to localization changes

The email provides concrete examples of localization working elsewhere in Git (Spanish and French translations shown) and surfaces the core tension between user-facing i18n needs and maintaining stable interfaces. The discussion appears to be moving toward finding an architectural solution that satisfies both requirements.
