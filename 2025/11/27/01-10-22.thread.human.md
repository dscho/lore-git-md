Ezekiel Newren has proposed an RFC patch series to refactor Git's Rust infrastructure from a single-crate approach (as implemented by Patrick Steinhardt) into a Cargo workspace with multiple crates (gitcore, link-with-c, generate-headers). The goal is to improve modularity and compilation efficiency by enabling partial recompilation when only subsets of the Rust code change. The series begins by completely removing the existing Rust build infrastructure from both Makefile and Meson builds to make way for the new approach.

The latest patch specifically targets the Meson build system, stripping out all of Patrick Steinhardt's prior Rust integration. It removes the `rust` feature flag, Cargo build wrapper script, source file tracking, linking rules, and test integration - leaving the build system in a non-functional state for Rust until the full series is applied. This is a mechanical change that clears the ground for the new multi-crate infrastructure to be introduced in subsequent patches.

As an RFC, this is still an incomplete prototype with known issues including broken CI workflows, Windows build failures, and missing test integration. The series is seeking architectural feedback on the multi-crate approach versus the current single-crate design, particularly regarding build system integration challenges and potential conflicts with ongoing work like brian m. carlson's SHA interoperability effort. So far there hasn't been any public feedback from other contributors on the proposed direction.
