This RFC thread from Ezekiel Newren proposes a significant restructuring of Git's Rust infrastructure, moving from Patrick Steinhardt's single-crate approach to a multi-crate Cargo workspace. The series is now at 7/13 patches, with the latest introducing a `link-with-c` crate that handles Rust-C interoperability.

The core idea is to improve modularity and compilation efficiency by splitting functionality into separate crates (`gitcore`, `link-with-c`, and `generate-headers`). The most recent patch provides the linkage mechanism between Rust and C code, including environment variable parsing, path management, and conditional library linking. It builds on prior infrastructure changes that removed the existing build system integration and established the workspace structure.

Several significant challenges remain unresolved, particularly around Windows compatibility (both MSVC and MinGW paths), test integration, and validation of generated FFI headers. The series hasn't yet addressed how this restructuring might impact Patrick Steinhardt's prior single-crate work or brian m. carlson's SHA interoperability efforts. The patches are currently focused on build system changes rather than modifying any actual Rust functionality.

While the technical approach appears sound for Unix-like systems, the lack of Windows-specific considerations and test coverage suggests this is still early-stage work. The thread hasn't yet attracted substantive review feedback, likely because it's marked as RFC. Key questions about architectural tradeoffs and platform support will need resolution before this approach could be considered for merging.
