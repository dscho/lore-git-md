This is a documentation patch finalizing warnings about the problematic `--committer-date-is-author-date` option in `git-am` and `git-rebase`. The patch series has reached consensus after technical discussion established that the original use case (preserving commit IDs when emailing patches) violates Git's timestamp ordering assumptions.

The v2 patch strengthens warnings in the documentation with explicit callout boxes, removes misleading suggestions of legitimate uses, and replaces ambiguous language about "clock skew" with clear statements about violating Git's non-decreasing timestamp expectations. Phillip Wood and Johannes Sixt have both approved this version, confirming the technical accuracy of the maintainer-preferred approach of warning users rather than removing the option entirely.

The documentation now makes clear that the original 2009 justification for this option was based on a flawed premise (treating mailboxes as commit storage), and that using it creates commit histories that may confuse Git's history-walking machinery. The warnings are presented in a way that should steer users away from the option while still allowing it for rare cases where users knowingly want to override the normal behavior.
