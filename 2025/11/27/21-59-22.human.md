This is a discussion about bash completion for Git's short options, where Junio C Hamano responds to SZEDER Gábor's concerns about the feature's usefulness.

Junio acknowledges SZEDER's point that completing single-letter options without explanatory help text may not provide much value to users. He references a 2007 discussion that touched on similar concerns about short option completion, suggesting this is a long-standing debate.

The key issue raised is whether completing `git -<TAB>` with short options like `-C` or `-p` is actually helpful when users can't know what these options do. Junio agrees with SZEDER that without accompanying help text explaining each option's purpose (which the current implementation doesn't provide), the feature may not be worth adding.

This response shifts the discussion from technical implementation (which was previously approved) to a more fundamental question about the feature's design philosophy. The patch's future now likely depends on whether the author or others can demonstrate concrete user benefits that outweigh these discoverability concerns.
