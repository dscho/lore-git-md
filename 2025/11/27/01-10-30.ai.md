This is patch 8/13 in Ezekiel Newren's RFC series refactoring Git's Rust infrastructure into a Cargo workspace. The patch focuses on linking the gitcore crate with C code.

The changes:
1. Adds link-with-c as a workspace member in the root Cargo.toml
2. Modifies gitcore's Cargo.toml to:
   - Remove the explicit rust-version (now inherited from workspace)
   - Add "rlib" as an output type alongside "staticlib"
   - Declare link-with-c as a build dependency
3. Introduces a new build.rs script for gitcore that uses link-with-c's BuildHelper to handle C linking, though header generation is commented out for now

The patch connects gitcore to the linking infrastructure introduced in patch 7, but leaves several aspects incomplete:
- Header generation is stubbed out (commented)
- No actual Rust code changes yet - this remains infrastructure work
- Still no resolution of the Windows build issues or test integration noted in earlier patches

This continues the incremental approach of the series, adding another piece of the multi-crate puzzle while deferring the harder questions about platform support and cross-crate coordination. The commented header generation suggests this may be addressed in a future patch.
