This is part 8 of Ezekiel Newren's RFC series refactoring Git's Rust infrastructure into a multi-crate Cargo workspace. The patch focuses on linking the gitcore crate with C code.

The changes are relatively small but important for the multi-crate approach. The patch:
1. Adds the link-with-c crate to the workspace members in the root Cargo.toml
2. Updates gitcore's Cargo.toml to specify both staticlib and rlib output types
3. Introduces a build.rs script for gitcore that uses the link-with-c crate's BuildHelper (though header generation is commented out for now)

This continues the incremental infrastructure work from previous patches, now establishing the linking mechanism between gitcore and C code. The patch appears technically sound but doesn't yet address the larger open questions from the series around Windows support, test integration, or cross-crate coordination. The commented-out header generation suggests this is still a work-in-progress piece of the puzzle.
