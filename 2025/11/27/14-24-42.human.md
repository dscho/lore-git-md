Hook subsystem refactoring: pre-push hook conversion to new API.

This is part 4/10 of the hook modernization series, converting the pre-push hook to use the new structured callback API. The patch moves away from custom `run-command` invocations to the standardized `run_hooks_opt()` interface while preserving all existing functionality.

The key change here is the introduction of a `pre_push_hook_feed_stdin` callback that handles the ref status processing previously done inline. This maintains the same behavior of writing the remote name/URL and ref status updates to the hook's stdin, but now does so through the new streaming interface. The callback properly handles all REF_STATUS_REJECT_* cases consistently.

Junio Hamano notes in his review that this cleanly separates the generic hook machinery from the pre-push-specific logic. The implementation appears solid, with proper pipe management handled by the underlying `run-command.c` infrastructure (specifically `pp_buffer_stdin()` closing the file descriptor after feeding completes).

This conversion follows the same pattern seen in earlier patches of the series, bringing the pre-push hook in line with the new standard while maintaining backward compatibility. The patch has already been reviewed by multiple contributors including Ævar Arnfjörð Bjarmason, suggesting it's reached a mature state in this v3 iteration.
