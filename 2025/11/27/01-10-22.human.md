This is an RFC cover letter for a major Rust infrastructure change, converting Git's Rust code from a single Cargo crate to a Cargo workspace structure. The series comes from Ezekiel Newren and consists of 13 patches that reorganize the build system, CI workflows, and Rust code layout.

The key motivation is to improve modularity and compilation efficiency by splitting the Rust code into multiple crates (gitcore, link-with-c, and generate-headers). This avoids recompiling everything when one part changes and allows for better dependency isolation. The series also introduces cbindgen for generating C headers per crate rather than one monolithic header.

The RFC highlights several known issues needing feedback: broken GitHub workflows, Meson build failures on Windows, missing Rust test integration, and conflicts with another in-progress patch series. The author notes this undoes some of Patrick Steinhardt's prior Rust work that assumed a single-crate model.

This appears to be a well-motivated but complex infrastructure change that touches multiple build systems (Make and Meson), CI, and the Rust code organization. The RFC status suggests the author is seeking early feedback on the approach before completing remaining work like test integration. The patch count and scope indicate this would be a careful review for build system experts, particularly those working on Git's Rust integration.
