This is a discussion about localization (l10n) inconsistencies in Git's output messages, specifically focusing on the "Everything up-to-date" message in `git push`.

Brian m. carlson responds to Peter Krefting's query about why `git push` shows an English-only message while `git pull` properly localizes its equivalent status message. The core issue stems from these strings being marked as stable output in plumbing code (send-pack.c and transport.c) that shouldn't be modified, despite appearing in the porcelain `git push` command.

Carlson notes there isn't actually any known tooling that depends on this specific message's exact wording, contrary to previous assumptions. They also point out the message contains a grammatical error ("up-to-date" should be "up to date") that wasn't fixed due to hypothetical compatibility concerns. The email shares a precedent where localizing another message ("Needed a single revision") did break some external tools, though the impact was manageable.

The response suggests potential solutions like a `--plumbing` flag or using `LC_ALL=C.UTF-8` for stable output, while indicating personal openness to change the message. This continues the thread's exploration of how to balance porcelain localization needs with plumbing stability requirements, with Carlson bringing new data points about actual versus assumed tool dependencies.
