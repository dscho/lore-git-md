Refactoring patch converting Git's Rust infrastructure from a single crate to a Cargo workspace structure. This is part 3 of Ezekiel Newren's 13-part RFC series proposing a major restructuring of Git's Rust code organization.

The patch moves the existing `gitcore` crate into a new `rust/gitcore` subdirectory while converting the top-level `Cargo.toml` into a workspace configuration. The actual Rust source files (`lib.rs` and `varint.rs`) are relocated but remain unchanged in content. This establishes the first member crate (`gitcore`) in what will become a multi-crate workspace.

The change is purely structural at this stage - no functionality is altered, just the build system organization. This matches the series' goal of improving modularity by splitting Rust code into separate crates. The patch appears mechanically sound, cleanly moving files while preserving their contents, though the broader RFC context notes the overall build system is currently in a non-functional transitional state.

As an RFC, this invites feedback on the workspace approach before completing the implementation. The patch itself is straightforward, but its significance lies in being part of a larger architectural shift away from Patrick Steinhardt's single-crate Rust integration.
