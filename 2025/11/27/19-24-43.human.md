This is a follow-up in the ongoing `git replay` feature series, specifically addressing the revert functionality interface design.

Siddharth Asthana responds to Phillip Wood's suggestion about the `--revert` syntax, agreeing to restructure it to take an explicit branch argument like the other operation modes. The new syntax will be `git replay --revert <branch> <revision-range>`, maintaining consistency with `--onto` and `--advance` modes. This change better supports the core use case of reverting arbitrary commit ranges onto a target branch, which Phillip illustrated with the example `git replay --revert main main..feature`.

The response shows Siddharth quickly incorporating feedback into the design, indicating the series is in its final stages of interface refinement. This particular change aligns with earlier thread consensus about making revert a distinct operation mode with clear parameter requirements. The discussion continues to focus on practical workflow needs while preserving the command's flexibility for both bulk and selective revert operations.
