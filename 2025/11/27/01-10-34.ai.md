CI / build system patch adding Rust toolchain installation to GitHub workflows, part of Ezekiel Newren's RFC series restructuring Git's Rust infrastructure. This is patch 12/13 in the series.

The patch introduces Rust toolchain setup across all CI workflows, with platform-specific version requirements (minimum 1.63.0, Windows 1.78.0, musl 1.72.0) and target architectures (x86_64-pc-windows-gnu for make, x86_64-pc-windows-msvc for meson, i686-unknown-linux-gnu for 32-bit Linux). It adds two new scripts: `ci/install-rustup.sh` for containerized environments where GitHub's actions-rs/toolchain doesn't work, and `ci/install-rust-toolchain.sh` for version/target management. The changes touch workflow definitions, dependency installation, and test artifact generation.

Key technical details include CARGO_HOME path standardization across platforms (/c/Users/runneradmin/.cargo on Windows, /Users/runner/.cargo on macOS, /home/builder/.cargo in Linux containers), rustup installation via both GitHub Action and manual curl|sh fallback, and PATH modifications to ensure rustc availability. The patch also adds curl and zlib1g to dependency lists where missing, suggesting these are needed for Rust toolchain operations.

This addresses one of the known issues from earlier in the series (broken GitHub workflows) but doesn't yet resolve the Windows Meson build failures or Rust test integration. The approach shows platform awareness with different Rust versions and targets per environment, though the hardcoded paths and version numbers may need adjustment as the Rust infrastructure evolves. The patch maintains the series' pattern of incremental infrastructure changes while leaving some cross-platform concerns (like MSVC/MinGW differences) for future work.
