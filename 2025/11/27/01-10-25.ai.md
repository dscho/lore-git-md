This is the third patch in Ezekiel Newren's RFC series refactoring Git's Rust infrastructure into a Cargo workspace. The patch converts the existing single-crate setup into a workspace structure, moving the core Rust implementation into a new `rust/gitcore` subdirectory while maintaining the same functionality.

The key changes are:
- Converts top-level `Cargo.toml` from a package definition to a workspace definition listing `rust/gitcore` as a member
- Creates a new `rust/gitcore/Cargo.toml` with identical package configuration to the original
- Moves the existing source files (`lib.rs` and `varint.rs`) from `src/` to `rust/gitcore/src/` with no content changes
- Maintains the same crate name (`gitcore`), version, Rust edition, and staticlib output configuration

This is a mechanical change that prepares for the multi-crate architecture described in the series' cover letter, where `gitcore` will be one of several crates (along with `link-with-c` and `generate-headers`). The patch preserves all existing functionality while restructuring the build layout, following the series' goal of improving modularity through crate separation.

The patch appears cleanly implemented with proper file moves and minimal diff noise, though as noted in the thread summary, the overall series is still in prototype state with known build system issues to resolve. This particular change doesn't introduce new functionality or behavior changes - it's purely an infrastructure preparation step for the larger architectural shift.
