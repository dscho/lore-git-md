This is part 4/13 of Ezekiel Newren's RFC series refactoring Git's Rust infrastructure into a Cargo workspace. The patch reintroduces Rust build support after the previous patches removed the existing infrastructure, now implementing it for both Makefile and Meson build systems.

Key technical changes:
- Adds new `rust/build-crate.sh` script that handles Rust compilation with Cargo, moving built artifacts to the correct locations
- Implements `WITH_RUST` build flag (default true) to control Rust inclusion
- Makes Rust compilation a dependency for building Git binaries and test tools
- Adds Rust library artifacts to linker flags when enabled
- Conditionally excludes C `varint.o` when Rust is enabled (since Rust will provide this)
- Handles platform-specific library naming (`.a` vs `.lib` on Windows)
- Sets appropriate debug/release build profiles and RUSTFLAGS
- Adds cleanup targets for Rust artifacts

The build system integration is currently minimal - it only supports the initial `gitcore` crate from the workspace structure introduced in patch 3/13. Future patches will add the remaining crates (`link-with-c` and `generate-headers`).

Notable considerations for future discussion:
- Windows compatibility appears partially addressed (MSVC vs MinGW paths) but may need more work
- Build script uses hardcoded paths that may not handle all build configurations
- No test integration yet (will come in later patches)
- The forced `cargo clean` in build-crate.sh may impact incremental build performance

This continues the series' pattern of making sweeping changes to the build infrastructure while keeping the actual Rust code unchanged. The patch appears mechanically sound but leaves several known issues unaddressed from the RFC cover letter (Windows Meson failures, GitHub workflow breaks).
