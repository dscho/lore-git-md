This thread has refined the behavior of the experimental `git replay` command to drop commits that become empty during replay (where changes already exist in the target branch), matching the behavior of `git rebase` and `git cherry-pick` with similar options. The implementation in `replay.c` now properly detects empty commits by comparing tree OIDs, preserves originally-empty commits, and correctly updates branch pointers when tip commits are dropped.
