This thread has reached consensus on modifying the experimental `git replay` command to drop commits that become empty during replay, matching the established behavior of `git rebase` and `git cherry-pick` with similar options. The core technical approach - using tree OID comparisons in `replay.c` to detect empty commits while preserving originally-empty ones - has been thoroughly reviewed and approved by maintainer Junio C Hamano, with Elijah Newren confirming it aligns with his own implementation.

Phillip Wood, the patch author, has iterated through four versions incorporating all technical feedback, including test simplifications from Newren and documentation improvements from Junio. The final v4 patch removes a non-essential `--only` flag from test cases while maintaining robust coverage. The only remaining question is whether to base this change on `master` or the experimental `ps/history` branch, as Junio considers whether this behavior change is too fundamental for the command's experimental phase. The patch is otherwise ready for inclusion, with agreement that dropping empty commits should be the default behavior (while leaving room for a future option to retain them if needed). All active participants have signed off on the technical approach.
