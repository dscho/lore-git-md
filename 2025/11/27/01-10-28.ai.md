This is part 6 of Ezekiel Newren's RFC series refactoring Git's Rust infrastructure into a Cargo workspace. The patch introduces a new `generate-headers` crate responsible for creating C header files from Rust code using cbindgen.

The new crate contains:
- A Cargo.toml with dependencies for header generation (cbindgen, textwrap, etc.)
- A main.rs implementing header generation logic that:
  * Reads a cbindgen template configuration
  * Creates a generated/ directory for output
  * Produces .h files with proper include guards
  * Currently hardcoded to process the gitcore crate
- A cbindgen-template.toml with basic C header generation settings

Key technical details:
- Uses cbindgen 0.24.0 for FFI header generation
- Outputs to generated/ directory (consistent with patch 5's .gitignore)
- Currently only processes gitcore crate but appears designed for extension
- Hardcoded paths may need adjustment for Windows compatibility
- No tests included for the header generation functionality

This continues the series' pattern of infrastructure-first changes before modifying actual Rust code. The header generation is a necessary step for the multi-crate approach's FFI needs, but doesn't yet address the known Windows build issues or test integration from earlier patches. The implementation appears straightforward but would benefit from handling more configurations beyond the basic case.
