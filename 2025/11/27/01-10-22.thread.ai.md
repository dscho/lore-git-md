RFC patch series proposing Rust infrastructure refactoring into a Cargo workspace (multiple crates: gitcore, link-with-c, generate-headers) instead of current single-crate approach. Authored by Ezekiel Newren, explicitly marked as RFC to gather feedback on architectural direction before completing implementation.

Core goal: Improve modularity and compilation efficiency by splitting Rust code into separate crates, enabling partial recompilation when only subsets change, better dependency isolation, and per-crate C header generation via cbindgen. This would undo some of Patrick Steinhardt's prior single-crate Rust work.

Technical details:
- First patch removes all existing Rust build infrastructure from Makefile and shared.mak (WITH_RUST flag, Cargo config, source tracking, linking rules)
- Second patch (new) removes Meson build system integration (rust feature flag, cargo-meson.sh wrapper, source tracking in src/meson.build, platform library naming, test integration)
- Moves Rust crates under rust/ directory while keeping top-level Cargo.toml
- Introduces new build scripts for multi-crate setup
- Sets up infrastructure for future header generation (not yet active)
- 13 patches touch build systems (Makefile, Meson), CI workflows
- New crate structure: gitcore (main Rust logic), link-with-c (FFI bindings), generate-headers (cbindgen integration)

Current status: Incomplete prototype with several known issues:
- Broken GitHub workflows
- Meson build failures on Windows
- Missing Rust unit test integration
- Potential conflicts with brian m. carlson's SHA interoperability work
- Build system currently in non-functional state for Rust between removal of old infrastructure and addition of new

Open questions:
- Architectural feedback on multi-crate approach vs single-crate tradeoffs
- Build system integration challenges, particularly Windows compatibility
- Test infrastructure adjustments needed
- Impact on existing Rust work (Patrick Steinhardt's single-crate, brian m. carlson's SHA work)

Participant positions: None yet (initial RFC)
