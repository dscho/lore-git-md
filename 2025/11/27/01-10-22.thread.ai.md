RFC patch series by Ezekiel Newren (7/13) refactoring Git's Rust infrastructure into a Cargo workspace (crates: gitcore, link-with-c, generate-headers) instead of single-crate approach, undoing some of Patrick Steinhardt's prior work. Core goal remains improving modularity and compilation efficiency through crate separation.

Current technical state:
- Patch 1 removed existing Rust build infrastructure from Makefile/shared.mak
- Patch 2 removed Meson integration
- Patch 3 converted to workspace structure with gitcore crate (rust/gitcore/src/)
- Patch 4 reintroduced build system support with rust/build-crate.sh and WITH_RUST flag
- Patch 5 added .gitignore rules and updated clean target
- Patch 6 introduced generate-headers crate for FFI header generation (cbindgen 0.24.0, outputs to generated/)
- New patch 7 adds link-with-c crate handling Rust-C linking:
  * Provides BuildHelper struct for path management and conditional behavior
  * Links against libgit.a, pcre2-8, and z/z-ng based on USE_LINKING env var
  * Validates GIT_BUILD_DIR configuration
  * Produces both static and rlib outputs
  * Triggers rebuilds on Git source changes
  * Currently no dependencies in Cargo.toml

Known issues:
- GitHub workflows still broken
- Meson build failures on Windows persist
- Rust unit test integration missing
- Hardcoded paths in build scripts may not handle all configurations
- Forced cargo clean impacts incremental builds
- Potential conflicts with brian m. carlson's SHA interoperability work
- Header generation currently limited to gitcore crate
- No validation of generated header correctness
- Link-with-c crate uses hardcoded library names (pcre2-8, z) that may need platform adjustments
- No demonstration yet of how link-with-c integrates with other crates

Open questions:
- Architectural feedback on multi-crate vs single-crate tradeoffs
- Windows compatibility depth (MSVC/MinGW paths)
- Build system integration robustness
- Test infrastructure adjustments needed
- Impact on Patrick Steinhardt's single-crate work and brian m. carlson's SHA efforts
- Header generation extensibility to future crates
- Verification strategy for generated headers
- Link-with-c's handling of platform-specific library variations
- How linking behavior will be coordinated across multiple crates

Participant positions: None yet (still early RFC stage)

Related work:

The series continues making incremental infrastructure changes while keeping actual Rust code unchanged. This patch adds the linking mechanism needed for the multi-crate approach but doesn't yet address the larger outstanding concerns around Windows support, test integration, or cross-crate coordination.
