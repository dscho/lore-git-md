RFC patch series by Ezekiel Newren (13/13) refactoring Git's Rust infrastructure into a Cargo workspace (crates: gitcore, link-with-c, generate-headers) as alternative to Patrick Steinhardt's single-crate approach. Core goal remains improving modularity and compilation efficiency through crate separation, with this final patch focusing on build system path handling.

Current technical state:
- Build system integration completed with path handling improvements:
  * MAKEFILE_DIR variable added to track Makefile location
  * build-crate.sh now uses $PWD for reliable root directory reference
  * Meson build receives proper source root path
  * Windows-specific adjustments for MSVC library naming and PATH
  * CARGO_TARGET_DIR moved to build directory
- Previous infrastructure changes from earlier patches remain:
  * Rust toolchain installation in CI with platform-specific versions
  * Workspace structure with gitcore, link-with-c, generate-headers crates
  * Build system support via rust/build-crate.sh and WITH_RUST flag
  * FFI header generation (cbindgen 0.24.0) in generate-headers crate
  * Rust-C linking via link-with-c crate (BuildHelper struct)

Known issues:
- Windows Meson build failures persist (not resolved by path changes)
- Rust unit test integration still unimplemented
- Header generation currently limited to gitcore crate
- No validation of generated header correctness
- Link-with-c's platform-specific library handling remains hardcoded
- Build.rs header generation still commented out in gitcore
- Outstanding CI issues beyond toolchain setup

Open questions:
- Architectural tradeoffs between multi-crate vs single-crate organization
- Windows compatibility depth (MSVC/MinGW paths)
- Test infrastructure integration strategy
- Impact on Patrick Steinhardt's work and brian m. carlson's SHA efforts
- Header generation extensibility to future crates
- Verification approach for generated headers
- Coordination of linking behavior across multiple crates
- Future type changes needed for FFI compatibility

Participant positions: None yet (still early stage RFC)

Related work:
- Patrick Steinhardt's prior single-crate Rust integration

The series now provides a complete but unproven alternative Rust infrastructure approach, with all 13 patches establishing build system viability while deferring deeper architectural questions. The path handling improvements in this final patch demonstrate attention to cross-platform concerns, though Windows Meson support remains problematic. The RFC leaves open whether this multi-crate direction will gain traction versus Patrick Steinhardt's established single-crate work.
