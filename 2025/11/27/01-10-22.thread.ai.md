RFC patch series by Ezekiel Newren (12/13) refactoring Git's Rust infrastructure into a Cargo workspace (crates: gitcore, link-with-c, generate-headers) instead of single-crate approach, undoing some of Patrick Steinhardt's prior work. Core goal remains improving modularity and compilation efficiency through crate separation.

Current technical state:
- Patch 1 removed existing Rust build infrastructure from Makefile/shared.mak
- Patch 2 removed Meson integration
- Patch 3 converted to workspace structure with gitcore crate (rust/gitcore/src/)
- Patch 4 reintroduced build system support with rust/build-crate.sh and WITH_RUST flag
- Patch 5 added .gitignore rules and updated clean target
- Patch 6 introduced generate-headers crate for FFI header generation (cbindgen 0.24.0, outputs to generated/)
- Patch 7 added link-with-c crate handling Rust-C linking (BuildHelper struct, static/rlib outputs, Git source change tracking)
- Patch 8 integrated gitcore with link-with-c and included preparatory type change in varint.h
- Patch 11 standardized Rust build flags in CI (WITH_RUST=true, -Dwith_rust=enabled)
- New patch 12 adds Rust toolchain installation to GitHub workflows:
  * Platform-specific version requirements (1.63.0 base, Windows 1.78.0, musl 1.72.0)
  * Target architecture variations (x86_64-pc-windows-gnu/msvc, i686-unknown-linux-gnu)
  * New scripts ci/install-rustup.sh (container fallback) and ci/install-rust-toolchain.sh
  * CARGO_HOME path standardization across Windows (/c/Users/runneradmin/.cargo), macOS (/Users/runner), Linux (/home/builder)
  * Added curl and zlib1g dependencies for toolchain operations
  * PATH modifications for rustc availability

Known issues:
- Meson build failures on Windows persist (not addressed by patch 12)
- Rust unit test integration still missing
- Hardcoded paths in build scripts may not handle all configurations
- Forced cargo clean impacts incremental builds
- Potential conflicts with brian m. carlson's SHA interoperability work
- Header generation currently limited to gitcore crate (stubbed in patch 8)
- No validation of generated header correctness
- Link-with-c crate uses hardcoded library names (pcre2-8, z) that may need platform adjustments
- No demonstration yet of how link-with-c integrates with other crates
- Build.rs header generation commented out in gitcore
- Remaining CI issues:
  * Windows MSVC/MinGW path handling differences
  * Workflow breakages beyond toolchain availability

Patch 12 addresses the GitHub workflow breakages by adding comprehensive Rust toolchain setup while maintaining the series' incremental approach. The platform-specific version and target architecture handling demonstrates awareness of cross-platform concerns, though the Windows Meson build failures remain outstanding. The patch introduces new infrastructure (installation scripts, path standardization) that may need maintenance as the Rust toolchain evolves. The series continues to defer deeper architectural questions about crate organization and FFI boundary management while making concrete progress on CI viability.
