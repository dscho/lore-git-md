This is the third patch in a 4-part series adding in-process trailer handling to `git rebase`, eliminating the need to fork `interpret-trailers`. The patch refactors trailer processing to work directly on buffers rather than files, removing the temporary file handling and fork/exec overhead from `interpret-trailers`.

The key changes move the core trailer processing logic into `amend_strbuf_with_trailers()` in trailer.c, which both `interpret-trailers` and `amend_file_with_trailers()` now use. The patch adds new helper functions `write_file_buf_gently()` for atomic file writes and modifies several builtins (`commit`, `interpret-trailers`, `tag`) to use the new strvec-based trailer API. The implementation maintains all existing behavior while centralizing the logic for the upcoming rebase integration.

The patch shows careful attention to error handling and resource cleanup, with thorough strbuf management and list operations. It builds on the previous refactoring work (moving `process_trailers()` to trailer.c) while keeping the changes focused and mechanical. The diff touches multiple files but follows a clear pattern of replacing fork-based operations with direct buffer processing. This sets up the final patch to add `--trailer` support to rebase with minimal new code.
