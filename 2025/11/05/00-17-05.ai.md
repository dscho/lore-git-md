This is a follow-up in the ongoing discussion about extending `git diff`'s raw format to report file attributes like binary status. Justin Tobler responds to Junio C Hamano's critique of the original binary-only proposal and explores the suggested `--raw-extended` approach.

The email focuses on design details for a more extensible attribute reporting system. Key technical considerations include:
- Output format options (key=value pairs vs. positional letter codes)
- Line placement of attribute data (inline vs. newline-separated)
- N-way diff support through additional letters in tuples
- Future extensibility mechanisms

Justin expresses agreement with the general direction but raises practical questions about implementation:
- Whether to use rigid yes/no values or allow mode-specific value formats
- How to structure the output to remain parseable while allowing future additions
- The handling of combined diffs with multiple parent commits

The discussion remains at the design level, with no code changes proposed yet. The thread has clearly shifted from the original binary-specific solution toward designing a general attribute reporting framework, though concrete implementation choices remain open.
