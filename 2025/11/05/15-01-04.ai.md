This is a follow-up in the thread investigating the `git grep -l` output formatting issue with filenames containing dashes. The discussion has shifted from being a potential Git regression to identifying the Delta pager as the root cause.

Kristoffer Haugsbakk confirms Michael Roach's earlier finding that the issue disappears when using `--no-pager`, reinforcing that the problem lies with Delta's handling of the output rather than Git itself. The email references Delta's issue #1259 which documents this exact dash-to-colon transformation behavior.

The thread has now established several key points:
1. The issue only manifests when using the Delta pager
2. The behavior is consistent with a known Delta bug
3. The problem doesn't occur with `--no-pager` or in Docker environments without Delta
4. Multiple participants have independently reproduced the behavior

While the primary culprit appears to be Delta, there remains an open question about whether changes in Git's pager handling between versions 2.49.1 and 2.51.1 might have exposed or triggered this Delta bug. The discussion suggests testing with alternative pagers like `less` or `cat` to further isolate the behavior, though no results from those tests are reported in this email.

The tone is now more conciliatory, with the original reporter acknowledging the pager connection and apologizing for the "bug report noise," while participants work collaboratively to understand the interaction between Git and Delta.
