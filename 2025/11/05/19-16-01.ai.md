Feature patch completing the atomic ref updates series for `git replay`. This final patch in the v7 series adds the `replay.refAction` configuration option to control the default reference update behavior, complementing the existing `--ref-action` command-line option. The implementation follows Git's standard configuration precedence rules where command-line arguments override config settings.

The patch introduces a new config section in `Documentation/config/replay.adoc` documenting the `replay.refAction` option with two possible values: "update" (default atomic behavior) and "print" (traditional pipeline output). The core implementation in `builtin/replay.c` adds a new `get_ref_action_mode()` helper that checks both command-line and config values, falling back to the default update mode. The change maintains backward compatibility while providing users the flexibility to set their preferred default behavior.

Test coverage in t3650-replay-basics.sh verifies all configuration scenarios: config-driven print/update modes, command-line override of config settings, and proper error handling for invalid config values. The tests follow established patterns using `test_config`, `test_when_finished`, and verify both output and actual ref state changes.
