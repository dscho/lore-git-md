Refactoring patch for git fast-import's commit buffer handling, part 1/3 of a series introducing signature stripping functionality.

This first patch extracts the commit buffer finalization code from `parse_new_commit()` into a new `finalize_commit_buffer()` function. The refactoring prepares for upcoming changes that will need to handle commit signatures differently - specifically, the ability to verify and potentially strip invalid signatures during import. The extracted function maintains the same behavior, just moving the existing logic that adds GPG signatures (both SHA1 and SHA256 variants) and commit messages to the buffer.

The change is straightforward mechanical refactoring with no behavior modification, touching only `builtin/fast-import.c`. The patch follows good practice by separating pure refactoring from functional changes, making the subsequent patches easier to review. The commit message clearly states the motivation (supporting future signature handling) without over-explaining the simple extraction.

Key technical details for future reference: introduces `finalize_commit_buffer()` function taking `strbuf` parameters for the commit data, signatures, and message; maintains current signature addition behavior via `add_gpgsig_to_commit()` calls; called from same point in `parse_new_commit()` as the original inline code. This is foundational work for the signature verification features coming in patches 2 and 3.
