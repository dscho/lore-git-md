Refactoring patch in the `--trailer` support series for `git rebase`.

This is the second patch in a 4-part series to enable in-process trailer handling during rebase operations. The patch moves the `process_trailers()` function from `builtin/interpret-trailers.c` to `trailer.c` and exposes it in `trailer.h`, making it available for reuse by other parts of Git. The function's implementation remains unchanged - it still takes the same parameters (options struct, trailer head list, input strbuf, and output strbuf) and performs the same trailer processing logic. This is a pure code movement to support the series' goal of eliminating fork/exec calls to `git interpret-trailers`.

The change enables subsequent patches to use this functionality directly from the rebase code. The patch maintains all existing behavior while preparing for the new in-process trailer manipulation capability. As noted in the thread context, this is part of a well-considered series with thorough test coverage (134 lines in t3440-rebase-trailer.sh) that has undergone multiple revisions incorporating maintainer feedback. The public API surface expands with the new `process_trailers()` declaration in trailer.h, which will be used by the rebase implementation in later patches.
