This is a discussion response in the ongoing thread about adding a 'strip-if-invalid' mode to `git fast-import`'s `--signed-commits` option. Junio C Hamano raises several important technical concerns about the proposed feature.

The response questions the fundamental assumptions behind signature validation in the context of history rewriting operations. Key concerns include: (1) the definition of "invalid" signatures and whether it accounts for missing public keys/revocation data, (2) clock accuracy issues affecting verification, and (3) the cascading effect where stripping early invalid signatures would invalidate all subsequent commit signatures in the rewritten history.

These questions go to the heart of whether signature stripping during import can maintain cryptographic integrity, suggesting the feature might have more complex implications than initially presented. The concerns imply that even valid signatures might become invalid after history rewriting, potentially making the proposed mode less useful than intended.

The response doesn't reject the feature outright but seeks clarification on these edge cases before proceeding. This suggests the feature may need additional design consideration around how signature validation interacts with history rewriting operations.
