This is patch 2/3 in the atomic ref updates series for `git replay`, implementing the core functionality to make atomic reference updates the default behavior. The patch has undergone multiple review cycles with all major technical concerns addressed, and is in final polish stage addressing minor documentation and test hygiene nits.

The key changes in this specific patch:
- Introduces `--ref-action` option with `update` (default) and `print` modes
- Implements atomic updates using Git's ref transaction API (`ref_store_transaction_begin`, `ref_transaction_update`, `ref_transaction_commit`)
- Adds `handle_ref_update()` helper to unify print/update modes
- Updates documentation to reflect new default behavior
- Modifies existing tests to use `--ref-action=print` to preserve expectations
- Adds new tests verifying atomic update behavior in both regular and bare repos

The implementation uses an enum `ref_action_mode` (REF_ACTION_UPDATE/PRINT) for type safety, with string parsing done once at option processing. Error handling ensures failed transactions don't partially update refs. The documentation changes clarify the new default behavior while preserving examples of the legacy pipeline workflow via `--ref-action=print`.

- Removal of implementation details from commit message

- Fixing test cleanup to properly restore original branch state

The patch maintains all existing functionality while adding atomic updates as the new default. The changes are well-contained, touching primarily the command implementation (`builtin/replay.c`), documentation, and tests.
