This is a feature patch series introducing `--trailer` support to `git rebase`, part of an ongoing effort to move trailer processing in-house rather than forking to `interpret-trailers`.

The series refactors trailer handling first (patches 1-3) to centralize logic and eliminate fork/exec overhead, then adding the new `--trailer` option to rebase in patch 4. The option currently only works with the merge backend, with explicit checks rejecting incompatible cases like the apply backend. The commit messages show thorough engagement with prior review feedback across multiple iterations (v2-v6).

The changes touch several key areas: trailer processing internals (now consolidated in trailer.c/h), rebase plumbing in sequencer.c, and new test coverage in t3440. The implementation looks well-considered, with careful error handling and validation. The series appears ready for review, though the merge-backend limitation may warrant discussion about whether to extend support to the apply backend later.
