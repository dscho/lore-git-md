This is the second patch in a 3-part series introducing signature verification improvements for `git fast-import`. The patch refactors commit signature verification code to work directly with commit buffers rather than requiring a full commit object.

The change extracts the core verification logic from `check_commit_signature()` into a new `verify_commit_buffer()` function, while keeping the original function as a wrapper for backward compatibility. This allows callers (like the upcoming fast-import changes) to verify signatures without first constructing a commit object they may discard if verification fails.

The refactoring is clean and mechanical - the new function maintains the same behavior as the original, just operating on raw buffer data. This enables the series' goal of adding a 'strip-if-invalid' mode to fast-import's signed commit handling in the next patch. The changes touch core commit verification code in commit.c and add the new function to commit.h's API.

This is a well-motivated preparatory change that cleanly separates the refactoring from the feature introduction coming in patch 3. The commit message clearly explains the rationale and the implementation approach.
