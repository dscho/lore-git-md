This is patch 10/12 in Junio Hamano's series introducing incomplete-line whitespace checking, implementing the core `git apply` functionality for detecting and fixing missing terminating newlines.

The patch adds `WS_INCOMPLETE_LINE` handling to `git apply`'s whitespace checking, making it recognize files lacking a final newline as a configurable whitespace error (off by default). Key changes include:
- Special handling in `record_ws_error()` to properly display incomplete lines in error messages
- Line number accounting fixes when parsing "\ No newline..." markers
- New `ws.c` logic to detect incomplete lines during whitespace check
- Automatic fixing by adding missing newlines when `--whitespace=fix` is used

The extensive test suite (187 new lines in t4124) verifies edge cases:
- Incomplete context lines don't trigger errors
- Making a line incomplete is an error
- Fixing/removing incomplete lines is allowed
- Modifying an incomplete line while keeping it incomplete is considered an error (a potentially controversial choice noted in the commit message)

This builds on the WS_INCOMPLETE_LINE bitmask infrastructure from patch 09/12, maintaining the series' pattern of thorough test coverage before the final Git codebase enforcement in patch 12/12. The implementation carefully handles line number accounting and error message formatting for incomplete lines.
