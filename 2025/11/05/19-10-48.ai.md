This is the final patch in the atomic ref updates series for `git replay`, adding config support for the ref update behavior. The patch introduces a `replay.refAction` configuration option that mirrors the existing `--ref-action` command-line flag, allowing users to set their preferred default behavior (atomic updates or print mode) in config rather than specifying it each time.

The implementation follows standard Git patterns - command-line options override config values, with clear error handling for invalid config entries. The patch includes comprehensive tests verifying config precedence and validation. While the patch itself is technically sound, the author acknowledges several improvements to the commit message and test organization based on Elijah Newren's feedback:

1. Removing redundant implementation details and examples that merely restate the code
2. Moving test cleanup fixes (using `START`/`test_when_finished`) to earlier patches where they belong
3. Eliminating a manual branch reset that should be handled by the test harness

Key technical details:
- New config option `replay.refAction` accepts "update" (default) or "print"
- Uses `repo_config_get_string_tmp()` for config lookup
- Shares validation logic with CLI option via `parse_ref_action_mode()`
- Tests cover config default, explicit settings, CLI override, and error cases
- Follows Git's standard config/CLI precedence rules

The patch represents the final piece of the atomic updates feature, with all prior review feedback addressed and the series now merge-ready pending only the reflog message format decisions being handled separately.
