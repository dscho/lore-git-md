Feature patch implementing atomic ref updates for `git replay` as the new default behavior. This is patch 2/3 in a merge-ready series that has already addressed all major technical feedback.

The patch changes `git replay` to update references directly using atomic transactions by default, rather than outputting commands for `git update-ref`. The original pipeline behavior is preserved via a new `--ref-action=print` option. The implementation uses Git's ref transaction API to ensure all-or-nothing updates, with a new `handle_ref_update()` helper function to avoid code duplication between modes.

Documentation is updated to reflect the new default behavior while maintaining clear examples of both atomic and pipeline workflows. The test suite is adjusted to use `--ref-action=print` for existing tests that expect command output, with new tests added to verify the atomic behavior in both regular and bare repositories.

- Cleaning up documentation to avoid combinatorial explosion in option descriptions

- Fixing test cleanup to properly preserve original state
