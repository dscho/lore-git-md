This is a thoughtful follow-up in the ongoing discussion about extending `git diff`'s raw output format to report file attributes. Ben Knoble weighs in on Justin Tobler and Junio C Hamano's design discussion about how to format attribute reporting in `--raw-extended` output.

The email focuses on implementation details of the proposed attribute reporting format, specifically comparing:
- Key=value pairs (like "binary=tt") versus letter codes ("tt")
- Whether to place attributes on the same line as the file entry or a new line
- The tradeoffs for script parsing between these approaches

Ben suggests that separate lines for attributes might be easier for line-oriented tools to process than comma-separated key=value pairs on the same line. This is a practical consideration that hadn't been raised in previous discussion, though Ben acknowledges they're not have the full context ("Idk").

The email doesn't introduce new design alternatives but provides useful feedback on the existing proposals, particularly from a scripting/parsing perspective. It continues the thread's progression toward a solution that balances human readability with machine parseability. The tone is constructive and thoughtful, though the brief nature means it doesn't fully explore the implications of the line-oriented approach.
