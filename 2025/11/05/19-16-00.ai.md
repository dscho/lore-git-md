Feature implementation for atomic ref updates in `git replay`. This is patch 2/3 in the final v7 series that has already received maintainer approval.

The patch changes `git replay`'s default behavior from outputting ref update commands (for piping to `git update-ref`) to performing atomic ref updates directly. The new `--ref-action` option provides control modes:
- `update` (default): Uses Git's transaction API for atomic updates
- `print`: Preserves the original pipeline behavior

Key implementation details:
- Adds `parse_ref_action_mode()` helper for option/config validation
- Uses ref transaction API (`ref_store_transaction_begin`, `ref_transaction_update`, `ref_transaction_commit`)
- Maintains backward compatibility via `--ref-action=print`
- Updates documentation to reflect new defaults and options
- Adds tests verifying atomic behavior, bare repo support, and reflog messages
- Test changes:
  - Existing tests use `--ref-action=print` to preserve expectations
  - New tests verify atomic updates, bare repo behavior, and reflog content
  - Uses `test_when_finished` for cleanup
  - Verifies all-or-nothing atomic behavior

The patch follows the series' established patterns and completes the core atomic update functionality after multiple review cycles addressing feedback from Patrick Steinhardt, Phillip Wood, and others. Documentation clearly explains the new default behavior and provides examples of both atomic and pipeline workflows.
