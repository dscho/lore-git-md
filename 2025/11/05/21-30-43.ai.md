This is a refactoring patch in Junio Hamano's series introducing "incomplete-line" whitespace error handling. It fixes a hack in the `suppress_blank_empty` feature that was misusing the `CONTEXT_INCOMPLETE` symbol meant for "\ No newline at end of file" cases.

The patch relocates the blank-empty suppression logic to where context lines are handled in `emit_line_ws_markup()`, making it more localized and less error-prone. It removes the previous approach that modified input lines in `fn_out_consume()`. The change also strengthens the incomplete-line detection by adding a BUG() check for unexpected line types and properly validating backslash-prefixed lines.

Key technical changes include:
- Moves `diff_suppress_blank_empty` handling from `fn_out_consume()` to `emit_line_ws_markup()`
- Simplifies the DIFF_SYMBOL_WORDS case by removing conditional line skipping
- Adds explicit case for backslash detection in incomplete-line handling
- Introduces BUG() check for unknown line types
- Maintains same behavior while making the code more robust

This is part of the series' preparatory cleanups (patch 3/12) that establish proper infrastructure before implementing the new whitespace error class. The change helps separate concerns between blank-empty suppression and incomplete-line handling, which becomes important as the series adds more whitespace checking capabilities.
