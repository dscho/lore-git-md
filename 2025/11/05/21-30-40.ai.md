This is version 2 of a feature series introducing "incomplete-line" whitespace error detection for missing terminating newlines in files. The series builds on the initial version with documentation updates, bugfixes for line counting in `git apply --check`, and expanded test coverage.

Key changes in v2:
- Moves the definition of WS_INCOMPLETE_LINE (0x8000) into patch 9/12 alongside the bit reallocation, updating core.whitespace documentation at the same time
- Fixes line number reporting in `git apply --check` when detecting incomplete lines
- Adds comprehensive test cases in t4124-apply-ws-rule.sh covering both apply and check operations in forward/reverse directions
- Maintains the same series structure: preparatory cleanups (01-08), bitmask changes (09), core implementation (10-11), and Git codebase enablement (12)

The implementation now properly handles edge cases around:
- Line number reporting in diagnostics
- Check vs apply behavior consistency
- Reverse patch application
- Error messaging for incomplete lines
- Interaction with other whitespace rules

The test coverage verifies all major scenarios including:
- Preserving existing incomplete lines
- Detecting newly introduced incomplete lines
- Fixing incomplete lines via whitespace=fix
- Correct line numbers in error messages
- Round-trip behavior with -R/--reverse

The final patch enables the check for Git's own C and shell source files via .gitattributes, completing the enforcement loop. The series remains backward compatible since the new check is opt-in via core.whitespace or .gitattributes.
