This is a preparatory refactoring patch in Junio Hamano's series adding "incomplete-line" whitespace checking. It fixes and clarifies bit assignments in the whitespace handling code, which is foundational for the later patches that will introduce the missing-newline detection.

The patch corrects miscounted bit positions in comments (the whitespace rules actually use bits 0-11, not 0-12) and adds documentation for color-moved bits that weren't previously described. It also modernizes the code to use `(1 << N)` notation instead of octal constants, which makes the bit positions more obvious, and adds spacing between logically grouped macro definitions for better readability.

The changes are mechanical but important groundwork - they ensure the bitmask infrastructure is properly documented before the new WS_INCOMPLETE_LINE feature (coming in patch 9) is added. The changes touch diff.c, diff.h and ws.h to maintain consistency across the whitespace handling system.

This is the first of 12 patches in v2 of the series, showing Junio's characteristic attention to detail in preparing the codebase before adding new functionality. The changes are straightforward and unlikely to be controversial, serving as clean groundwork for the more substantive whitespace changes to follow.
