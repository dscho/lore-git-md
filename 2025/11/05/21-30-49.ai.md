This is the infrastructure patch in the whitespace error series that introduces the new `WS_INCOMPLETE_LINE` bitmask and shifts existing whitespace-related flags to accommodate future expansion.

The patch makes several coordinated changes to prepare for detecting missing newlines at end of files as a configurable whitespace error. It reserves additional bits in the diff flags word (expanding from 12 to 16 bits for whitespace rules) and defines `WS_INCOMPLETE_LINE` (0x8000) without yet implementing the behavior. The documentation is updated to describe the new `incomplete-line` option for `core.whitespace`, though it remains disabled by default.

Key technical changes include:
- Shifts diff symbol flags (WSEH_NEW/CONTEXT/OLD and blank-line-EOF markers) to higher bit positions to make room
- Updates `WS_RULE_MASK` to cover the expanded 16-bit range
- Adds the new rule to `whitespace_rule[]` array and error string generation
- Maintains consistency with the series' preparatory refactoring approach

This follows the series' pattern of separating infrastructure changes from behavior implementation, with the actual incomplete-line detection and handling coming in subsequent patches. The changes are surgical and maintain backward compatibility while setting up for the feature implementation in patches 10-12.
