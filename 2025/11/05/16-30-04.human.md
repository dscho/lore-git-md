This is a thread reply from Junio Hamano regarding the `git rebase --trailer` patch series. The email points out some confusion in the cover letter's description of the changes.

Junio notes that the cover letter's claim about removing fork/exec to `interpret-trailers` seems to imply this was happening in `git rebase` before, but the series title suggests `git rebase` didn't support trailers at all previously. He clarifies that the fork/exec actually happens in `amend_file_with_trailers()` which is used by `git commit` and `git tag`, not `git rebase`.

The core of Junio's feedback is that the cover letter needs to be more precise about what's being changed and where. He suggests explicitly stating that the series is both (1) updating `amend_file_with_trailers()` to work in-process (affecting `commit` and `tag`), and (2) using this improved infrastructure to add new `--trailer` support to `git rebase`.

While Junio agrees the technical approach sounds sensible, he's asking for a clearer explanation in the cover letter to help reviewers understand the scope and motivation, especially those seeing the series for the first time. This is typical maintainer feedback about making the high-level description match the actual technical changes.
