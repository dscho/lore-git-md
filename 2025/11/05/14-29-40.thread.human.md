This thread has completed a 4-part series adding `--trailer` support to `git rebase`, allowing custom trailers to be appended to rebased commits. The series, which moved trailer processing in-process rather than forking to `interpret-trailers`, has undergone multiple revisions with feedback from Phillip Wood, Junio Hamano, and Kristoffer Haugsbakk.

The first three patches laid the groundwork by refactoring trailer handling - first extracting buffer-based processing, then moving core functions to `trailer.c`, and finally introducing `amend_strbuf_with_trailers()` for direct buffer manipulation. These changes were adopted by several builtins (`commit`, `interpret-trailers`, `tag`) while maintaining careful error handling.

The final patch implements the actual `--trailer` option for `git rebase`'s merge backend (the apply backend is explicitly blocked). It automatically forces rebase to ensure all messages are rewritten and includes thorough validation of trailer syntax before starting. The implementation stores the option in the rebase state directory and uses the new buffer-based processing infrastructure. Test coverage in `t3440-rebase-trailer.sh` (134 lines) verifies various scenarios including conflicts and edge cases.

While the series appears technically complete with solid test coverage, one open question remains about the long-term acceptability of the apply backend limitation. The implementation shows careful attention to error handling and builds logically on the preparatory refactoring in earlier patches.
