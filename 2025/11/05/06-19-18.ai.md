Feature addition to `git fast-import` for handling invalid commit signatures. This is the third and final patch in a series introducing a new 'strip-if-invalid' mode for `--signed-commits`.

The patch implements the new mode that automatically strips invalid commit signatures during import while preserving valid ones, addressing a need for tools like `git filter-repo` that rewrite repository contents. The implementation builds on the refactoring in previous patches, using the extracted `verify_commit_buffer()` function to check signatures before deciding whether to strip them.

Key technical details:
- New `SIGN_STRIP_IF_INVALID` enum value in gpg-interface.h
- `handle_strip_if_invalid()` helper in fast-import.c that verifies signatures and conditionally strips them
- Warning messages when invalid signatures are stripped, including commit subject and signer info
- Comprehensive test coverage in t9305 with scenarios for:
  - No signature
  - Valid OpenPGP signature
  - Invalid OpenPGP signature (modified message)
  - Dual SHA1/SHA256 signatures
  - X.509 signatures
  - SSH signatures

The patch explicitly does not implement this mode for tags (`--signed-tags`) or `git fast-export`, leaving those for future work. Error handling is added to reject attempts to use the mode where unsupported. Documentation is updated to describe the new mode alongside existing signature handling options.

The implementation appears thorough, with careful attention to warning messages and test coverage across different signature types. The changes are well-contained to the fast-import machinery and build cleanly on the preparatory refactoring in earlier patches.
