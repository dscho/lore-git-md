This is the final patch in a 4-part series adding `--trailer` support to `git rebase`. The feature allows appending custom trailers to rebased commits, building on earlier refactoring work to move trailer processing in-process rather than forking to `interpret-trailers`.

The patch implements the new `--trailer` option for `git rebase`, currently limited to the merge backend (apply backend is explicitly blocked). It automatically forces rebase (`--force-rebase`) when trailers are specified to ensure all messages are rewritten. The implementation includes thorough validation of trailer syntax before starting the rebase, with clear error messages for invalid input.

Key technical details: The option is stored in the rebase state directory and passed through to the sequencer via `replay_opts`. The core trailer processing uses the new `amend_strbuf_with_trailers()` function introduced in earlier patches. The test file `t3440-rebase-trailer.sh` provides 134 lines of coverage for various scenarios including conflicts, fixups, and edge cases around trailer syntax.

The patch touches several subsystems: rebase plumbing, sequencer state handling, trailer processing, and test infrastructure. It builds on the buffer-based trailer processing infrastructure from patch 3/4, completing the series' goal of enabling in-process trailer manipulation during rebase while maintaining existing behavior. The implementation appears thorough with careful error handling throughout.
