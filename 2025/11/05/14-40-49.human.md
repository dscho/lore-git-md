This is a discussion about the proposed 'strip-if-invalid' mode for `git fast-import`'s `--signed-commits` option. Junio C Hamano raises important questions about the practical implications of signature validation during history rewriting operations.

The core concern is about the definition of "invalid" signatures in the context of history rewriting tools like `git filter-repo`. Hamano questions whether the validation would account for all necessary cryptographic context (public keys, revocation data, timestamps) and points out that even valid signatures might become invalid when parent commits are rewritten - a fundamental limitation of commit signatures in Git.

This response suggests the proposed feature might have deeper implications than initially considered, particularly around how signature validity interacts with history rewriting. The questions imply that simply stripping signatures that fail verification might not be sufficient, as valid signatures could become invalid after rewriting their parent commits. This could potentially serious consequences for the integrity of signed histories after import operations.

The discussion appears to be moving from implementation details to more fundamental questions about the security model and practical limitations of commit signatures in rewritten histories. These concerns would need to be addressed before the feature could be considered for merging.
