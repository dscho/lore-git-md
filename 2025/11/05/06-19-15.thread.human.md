This thread explores adding a 'strip-if-invalid' mode to `git fast-import` that would remove invalid commit signatures during history rewriting while preserving valid ones. The initial patch series refactors commit buffer handling, extracts verification logic from commit.c, and implements the new signature-stripping functionality with comprehensive test coverage.

Maintainer Junio C Hamano raised important concerns about cryptographic integrity - particularly how to define "invalid" signatures and the cascading effects of rewriting history on downstream signatures. Elijah Newren provided use cases from `git filter-repo` where users want to preserve older valid signatures while rewriting recent history. Christian Couder, the series author, has clarified that validation will follow `git verify-commit`'s standards (requiring all keys/revocation data) and that checking must happen at import time to properly handle cases where validity changes between export and import.

In the latest exchange, Couder agrees with Newren's technical assessment that fast-import is the right place for validation but pushes back on an alternative proposal to track unsigned OIDs in the export format, noting this could allow invalid signatures to persist if keys are revoked. The discussion highlights the tension between cryptographic purity (where any rewrite invalidates all signatures) and practical needs (selective preservation of valid signatures). While the test infrastructure needs restructuring to avoid SHA-256/Rust dependencies, the core debate continues about whether the approach is fundamentally sound given maintainer concerns about cascading invalidation and whether alternative solutions might better serve both integrity and usability goals.
