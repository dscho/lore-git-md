This thread introduces a new 'strip-if-invalid' mode for `git fast-import`'s `--signed-commits` option, allowing invalid signatures to be automatically stripped during import while preserving valid ones. The 3-patch series refactors commit buffer handling and verification logic before implementing the new mode.

The first two patches laid the groundwork: refactoring commit buffer finalization and extracting signature verification logic to operate on raw buffers. The final patch, just submitted, implements the core functionality - validating signatures using the same logic as `git verify-commit` and stripping invalid ones with descriptive warnings. It handles OpenPGP, X.509, and SSH signatures with comprehensive test coverage.

Maintainer Junio C Hamano initially raised theoretical concerns about cascading invalidation and clock accuracy, but has approved the test restructuring approach. The practical use case - particularly for `git filter-repo` workflows where users want to rewrite recent history while preserving older valid signatures - is now well-articulated, with Elijah Newren providing key motivation. Christian Couder clarified that validity checks match `git verify-commit` behavior.

While some edge cases around cascading invalidation remain open for future consideration, the implementation is technically sound with thorough test coverage. The series appears ready for inclusion, having addressed review feedback while carefully maintaining backward compatibility. Tag support remains deferred to future work.
