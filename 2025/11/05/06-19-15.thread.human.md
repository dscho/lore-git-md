This thread discusses a proposed 'strip-if-invalid' mode for `git fast-import`'s `--signed-commits` option, which would allow tools like `git filter-repo` to automatically remove invalid signatures while preserving valid ones during history rewriting. The initial three-patch series refactors commit buffer handling and verification logic before implementing the new mode, with comprehensive test coverage.

Maintainer Junio C Hamano raised significant concerns about the feature's fundamental assumptions, questioning how "invalid" is defined (particularly regarding missing public keys), potential clock accuracy issues affecting verification, and cascading effects where stripping early signatures could invalidate subsequent commits in rewritten history. These concerns suggest deeper cryptographic integrity issues that may require redesign.

Elijah Newren has now responded, providing additional motivation for the feature - explaining that current behavior forces full history rewriting when signatures are involved, while users often want to preserve older valid signatures. He acknowledges the maintainer's concerns but questions whether there are viable alternatives, proposing one potential solution involving unsigned commit OID tracking in fast-export. The discussion remains open on whether the current approach can address these fundamental concerns or needs rethinking. No clear resolution has emerged yet, though the exchange has clarified the technical constraints in the export/import pipeline where signature validation occurs.
