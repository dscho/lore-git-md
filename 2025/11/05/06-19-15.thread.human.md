This thread discusses adding a 'strip-if-invalid' mode to `git fast-import`'s `--signed-commits` option, which would allow selectively removing invalid commit signatures during history rewriting while preserving valid ones. The initial patch series refactors commit buffer handling, extracts verification logic, and implements the new stripping functionality with comprehensive test coverage.

Maintainer Junio C Hamano raised important concerns about how "invalid" signatures are defined (particularly regarding missing keys and clock accuracy) and the cascading invalidation of downstream signatures in rewritten history. Elijah Newren provided use cases from `git filter-repo` where users want to rewrite recent history while keeping older valid signatures, arguing that signature validation must happen at import time. Christian Couder clarified that validity checks match `git verify-commit`'s behavior and acknowledged the cascading invalidation issue remains unresolved.

A test infrastructure problem emerged where the patches fail when merged due to depending on SHA-256 repositories created by another test that now requires Rust. Couder has confirmed this will be fixed in v2 by restructuring the tests to avoid the Rust dependency, either by making SHA-256 repository creation part of test setup with proper prerequisites or avoiding SHA-256 repositories entirely.

The discussion continues to weigh the tension between cryptographic purity (where history rewrites should invalidate all signatures) and practical use cases (where selective signature preservation is desired). Open questions remain about the feature's fundamental design, potential format changes to track unsigned OIDs, default behavior, and extension to signed tags. The test dependency issue must be resolved before merging, and the series still lacks Reviewed-by/Acked-by tags.
