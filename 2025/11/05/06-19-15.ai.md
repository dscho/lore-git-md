This is a feature patch series introducing a new 'strip-if-invalid' mode for `git fast-import`'s `--signed-commits` option, with potential future extensions to signed tags.

The series aims to help tools like `git filter-repo` by providing a way to automatically strip invalid commit signatures during import. The author suggests this could eventually become the default behavior, though acknowledges the backward compatibility implications and leaves that decision for future discussion.

The implementation involves refactoring both the fast-import commit buffer handling (patch 1) and the core commit verification logic (patch 2) before introducing the new mode (patch 3). The changes touch multiple components including the fast-import/export machinery, commit verification, and GPG interface code. Test coverage is expanded with over 100 new lines in the fast-import signature test script.

Key technical points for future reference:
- New `strip_if_invalid` mode added to `--signed-commits`
- Refactors `finalize_commit_buffer()` in fast-import to better handle signatures
- Extracts and modifies `verify_commit_buffer()` from commit.c to support signature stripping
- Adds new `GPG_VERIFY_STRIP_IF_INVALID` flag in gpg-interface
- Comprehensive test coverage in t9305 with various signature scenarios

The author notes this could be extended to `--signed-tags` in the future, and raises (but does not resolve) the question of whether this should become the default behavior. The implementation appears thorough with clean separation of concerns between the refactoring and feature introduction patches.
