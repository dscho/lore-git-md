Feature patch adding `--trailer` support to `git rebase` (final patch in series).

This is the culmination of a 4-part series that enables in-process trailer manipulation during rebase operations, rather than forking to `git interpret-trailers`. The patch adds a new `--trailer` option to `git rebase` that appends custom trailers to each rebased commit, with several notable behaviors:

1. The option only works with the merge backend (not apply/am) and automatically forces rebase (no fast-forward) when trailers are specified. The implementation rejects apply-backend options early to avoid confusion.

2. Trailers are validated up front before the rebase starts, with clear error messages for malformed input. The test suite (t3440-rebase-trailer.sh) provides 134 lines of coverage for various scenarios including conflicts, fixups, and edge cases.

3. The implementation builds on earlier refactoring work that moved trailer processing into reusable buffer-based functions. It maintains careful error handling and resource cleanup throughout.

The patch appears well-considered, with thorough test coverage and clear documentation updates. It completes the series' goal of enabling in-process trailer manipulation while maintaining existing behavior. The main limitation (apply backend incompatibility) is clearly documented and enforced.
