This is a feature patch in the atomic ref updates series for `git replay`. It changes the default behavior from outputting ref update commands (for piping to `git update-ref`) to performing atomic ref updates directly, while maintaining the old behavior as an option via `--ref-action=print`.

The patch makes atomic updates the new default, which is particularly beneficial for server-side operations where the previous pipeline approach required extra process coordination. The implementation uses Git's ref transaction API to ensure all-or-nothing behavior. Existing tests are updated to use `--ref-action=print` to maintain their expectations, while new tests verify the atomic behavior, bare repository support, and proper reflog messages.

The change is well-motivated with clear explanations of the benefits (especially for server workflows) and maintains backward compatibility. The implementation follows Git's standard patterns and has been thoroughly reviewed, with multiple contributors providing input on the technical approach, test hygiene, and documentation. This is the second patch in a 3-part series that has already gone through multiple review cycles and received maintainer approval.
