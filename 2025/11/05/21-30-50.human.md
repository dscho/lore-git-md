Feature/bugfix patch adding incomplete-line whitespace checking to `git apply`. This is patch 10/12 in Junio Hamano's series introducing configurable detection of missing newlines at end of files.

The patch implements checking for incomplete lines (files missing terminating newlines) in `git apply`, controlled by the `--whitespace` option. The behavior is off by default for compatibility but can be enabled via `core.whitespace=incomplete-line`. The implementation handles several edge cases through new test scenarios, including:
- Detecting when a patch makes a line incomplete
- Fixing incomplete lines when requested
- Special handling when modifying content on an incomplete line

The author notes one potentially debatable design choice: modifying content on an incomplete line (and leaving it incomplete) is considered an error, with the rationale that "you'd better fix it while at it". The extensive test suite (187 new lines across 5 test scenarios) verifies the various combinations of incomplete line detection and fixing.

This continues the series' pattern of thorough, well-tested changes to Git's whitespace handling infrastructure. The patch builds on the preparatory refactoring from earlier in the series and maintains consistent behavior between diff and apply operations.
