Refactoring patch in a series introducing incomplete-line whitespace handling. This is the 8th of 12 patches in v2 of Junio Hamano's series to detect and handle missing newlines at file endings as configurable whitespace errors.

The patch revamps how `git apply` parses incomplete lines (those ending without newlines) in patch files. Currently, the parser handles the "\ No newline at end of file" marker separately without tracking which line it applies to. This makes it impossible to properly check whitespace violations for incomplete lines. The change makes the parser properly associate the newline marker with its preceding line by dropping the newline character during parsing, matching how the application side already handles these cases.

This is a preparatory refactoring that enables the actual whitespace checking to be added in later patches. The implementation adds a new `adjust_incomplete()` helper to validate and measure the newline marker lines, then integrates this with the fragment parsing logic. The changes maintain backward compatibility while setting up for the new whitespace checking functionality.

The patch follows the series' pattern of careful, surgical changes with clear documentation and maintains the existing test coverage. It continues the progression from infrastructure cleanup (patches 1-8) toward the actual feature implementation (patches 9-12).
