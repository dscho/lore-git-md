This is part 8 of Junio Hamano's 12-patch series introducing "incomplete-line" whitespace error detection. The patch refactors how `git apply` parses incomplete lines (those missing terminating newlines) in patch files.

The patch addresses a long-standing issue where the apply machinery would parse the "\ No newline at end of file" marker independently without tracking which line it applied to. The new implementation:
- Introduces an `adjust_incomplete()` helper to properly associate the marker with its preceding line
- Modifies the fragment parsing logic to handle incomplete lines consistently with the rest of the diff
- Maintains backward compatibility while enabling future whitespace checking
- Drops the newline character during parsing so whitespace checker sees the true incomplete state

The changes are surgical and focused on the parsing path, building on previous infrastructure cleanups in the series. The patch follows the series' pattern of thorough documentation and careful handling of edge cases, with clear explanations of the commit message and code comments. This sets up the groundwork for the upcoming patches that will implement the actual whitespace checking functionality.
