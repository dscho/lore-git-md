This is version 2 of a feature series introducing "incomplete-line" whitespace error detection for missing terminating newlines in files. The series is now complete with 12 patches (up from 13 in v1) that add this as a configurable whitespace rule to both `git diff` and `git apply`, then enable it for Git's own codebase.

The key changes in v2 include:
- Moving the definition of the new WS_INCOMPLETE_LINE bit into the bit allocation patch (09/12) where it logically belongs
- Fixing a line number miscount in `git apply --check` output
- Expanding test coverage in t4124 to verify `--check` behavior

The series maintains its careful structure: preparatory cleanups (01-08), bitmask infrastructure (09), core implementation (10-11 for apply/diff respectively), and final enablement (12). Patch 10 now properly handles incomplete line detection in both apply and its `--check` mode, while patch 11 adds the corresponding diff integration. The final patch activates the check for Git's C and shell source files via `.gitattributes`.

The implementation is thorough, with comprehensive test coverage and clear documentation updates. The author (Junio) has clearly put thought into edge cases - particularly around when incomplete lines should be flagged as errors versus when they're just being preserved from the original file. The series appears ready for review, with its clean organization and incremental approach, should be straightforward to evaluate.
