This is a review comment on the ongoing `--trailer` support for `git rebase` series. Junio Hamano points out a contradiction in the cover letter's description of the changes versus the series title. The cover letter suggests the series removes fork/exec overhead from trailer processing, while the title implies this is new functionality for rebase.

He suggests the cover letter should more clearly explain which code paths are being modified (commit/tag vs. rebase) and how the changes benefit each.

The comment notes the rebase implementation approach (merge backend only with early validation) seems sensible, but requests a clearer explanation in any reroll to help new reviewers understand the scope and motivation. This maintains the thread's technical focus while highlighting an area where the patch presentation could better match its actual changes.
