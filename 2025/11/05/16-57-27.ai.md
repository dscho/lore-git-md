This is a refactoring patch in the context of the ongoing trailer processing improvements series. The patch extracts the core trailer processing logic from `interpret_trailers()` into a new `process_trailers()` helper function that operates on strbufs rather than directly writing to files. This prepares for in-process trailer manipulation that will be used by both the standalone `interpret-trailers` command and other Git commands like `rebase`.

The key changes include:
- Moving FILE* I/O operations to the caller (`interpret_trailers()`)
- Having the new helper work purely with strbufs for input and output
- Eliminating the intermediate `trailer_block_sb` buffer by writing directly to the output strbuf
- Maintaining the same functionality while making the code more reusable

Junio Hamano provides a detailed code review, noting the improvement in structure while suggesting minor documentation and cleanup opportunities (like using `fputs()` instead of `fwrite()`, and potentially better parameter naming). The changes align with the series' goal of enabling efficient in-process trailer manipulation while preserving existing behavior.

This is patch 1/4 in a series that will ultimately add `--trailer` support to `git rebase`, with this initial refactoring being a prerequisite for the later rebase integration. The careful separation of concerns here suggests the series is being developed with good architectural consideration.
