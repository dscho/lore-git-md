Refactoring and GPG verification changes for fast-import signature handling.

This is the second patch in a 3-part series introducing signature verification capabilities to `git fast-import`. The patch extracts commit signature verification logic from `check_commit_signature()` into a new `verify_commit_buffer()` function that operates directly on commit buffers rather than requiring a full commit object. This enables the subsequent patch to verify signatures during import without constructing temporary commit objects that may be discarded.

The refactoring maintains identical behavior while splitting the verification into two layers: the new lower-level `verify_commit_buffer()` handles the actual GPG checking, while `check_commit_signature()` becomes a thin layer that fetches the commit buffer and delegates to it. The changes touch commit.c and add a declaration to commit.h, with no functional changes to existing callers.

Key technical points: new `verify_commit_buffer()` function takes raw buffer/size instead of commit object, uses same `parse_buffer_signed_by_header()` as before, and preserves all existing error handling and result reporting through the `signature_check` struct. The patch enables the series' goal of signature verification during import by providing buffer-level verification needed for the upcoming 'strip-if-invalid' mode.

This is a clean refactoring that moves code in preparation for new functionality while maintaining backward compatibility. The changes are well-contained and follow the pattern established in patch 1 of extracting functionality to enable new features without disrupting existing behavior.
