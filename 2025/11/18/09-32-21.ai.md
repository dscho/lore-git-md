This is a cover letter for a 2-patch series addressing CI test output visibility issues in Windows/Meson builds. The series falls under both the "CI/build system" and "test" categories.

The core problem is that Windows test jobs using Meson don't show test script output when failures occur, making debugging difficult. The first patch modifies the unit test runner to ignore `--no-chain-lint` (a test harness option that apparently causes issues in this context). The second patch aligns the Windows Meson test job's behavior with other test jobs by properly handling options and output.

The changes touch the GitHub Actions workflow file, add a new test runner script, and modify the unit test infrastructure. The series appears focused and well-motivated by a concrete debugging pain point. The changes are relatively small (25 lines total) and focused on the CI system rather than core Git functionality.

Key technical details for future reference: the new `ci/run-test-slice-meson.sh` script handles test execution, while `unit-test.c` gains tolerance for `--no-chain-lint`. The GitHub Actions modifications suggest this affects the `windows-meson-test` job specifically. No behavioral changes to Git itself are introduced - this is purely about improving test infrastructure visibility.
