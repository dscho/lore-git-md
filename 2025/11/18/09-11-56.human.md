This is a small platform compatibility fix in the ASan series.

Jeff King addresses a compiler warning that appears when building with `NO_MMAP=1` and `DEVELOPER=1` flags. The compatibility layer that emulates mmap with malloc/free doesn't use the `length` parameter in `git_munmap()`, triggering an unused parameter warning. The patch simply marks this parameter with the `UNUSED` attribute to silence the warning while maintaining the function's interface compatibility with standard `munmap()`.

This is the first patch in a 9-part series focused on fixing ASan (AddressSanitizer) findings. While minor on its own, it's part of a larger effort to improve memory safety and build cleanliness across Git's codebase. The change is straightforward and uncontroversial, just marking an unused parameter as such while keeping the function signature intact for compatibility.
