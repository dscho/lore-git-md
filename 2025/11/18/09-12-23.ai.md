This is part of Jeff King's ongoing series addressing ASan findings, specifically focusing on hardening fsck_ident() parsing. The patch replaces strcspn() usage with explicit bounds-checked character iteration to parse author/committer lines more safely.

The change moves from relying on strcspn()'semi-safe' behavior (which technically expects NUL-terminated strings but works here due to known newline presence) to an explicit character-by-character loop with bounds checking. This makes the memory safety guarantees more obvious and avoids ASan's strict_string_checks false positives. The new implementation also consolidates the parsing logic by checking characters and handling errors immediately rather than separating the search (strcspn) from the validation.

Key technical details:
- Replaces two strcspn() calls with explicit loops checking p < ident_end
- Maintains identical error detection (missing/bad name/email, space validation)
- Adds explicit newline checks matching the original strcspn("\n") behavior
- Preserves all existing error messages and reporting behavior
- Follows the series' pattern of replacing string operations with length-aware alternatives

The change is a clear improvement in defensive programming while maintaining the same functionality.
