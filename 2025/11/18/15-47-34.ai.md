Refactoring of Windows thread handling code, specifically simplifying the pthread emulation layer's join operation. This is version 3 of a patch series that has been through previous review cycles.

The patch continues the simplification of `win32_pthread_join()` in `compat/win32/pthread.c`, now reducing the error handling to only check for `WAIT_FAILED` while treating all other outcomes uniformly. The key changes from v2 to v3 are:
- Switches from `WaitForSingleObject` to `WaitForSingleObjectEx` with explicit `alertable=FALSE` parameter
- Further streamlines the control flow by removing the switch statement entirely
- Maintains the same core justification that only `WAIT_FAILED` is a possible error case given the `INFINITE` timeout and non-alertable wait configuration

The commit message reiterates the technical rationale from previous versions:
- `WAIT_TIMEOUT` cannot occur with `INFINITE` timeout
- `WAIT_ABANDONED` only applies to mutex objects (not used here)
- `WAIT_IO_COMPLETION` is prevented by `alertable=FALSE`

The diff shows a net reduction of 13 lines while adding 7, with the main change being the replacement of the switch statement with a direct error check followed by uniform handling of the success case. This version appears to address all previous feedback while maintaining the original simplification goal. The change remains focused on the Windows compatibility layer's pthread emulation and doesn't introduce new functionality or affect other platforms.
