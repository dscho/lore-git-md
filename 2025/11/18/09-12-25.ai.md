Bugfix in the fsck_ident() parsing logic, part of Jeff King's ASan hardening series.

This patch removes a redundant timestamp validity check in fsck_ident(). The code was checking both for empty input (p == end) and invalid terminator (*end != ' '), but since commit 8e4309038f already ensures we have non-empty input before reaching this point, the empty check is unnecessary. The change simplifies the code while maintaining the same validation behavior.

The modification is small (just removing one condition from an if-statement) but contributes to the series' goal of making parsing code more robust and easier to reason about. This follows the pattern seen elsewhere in the series of removing redundant checks after previous hardening work has made them obsolete.

The patch maintains all existing error detection capabilities - it will still catch malformed dates in commit metadata, just without the redundant check. This change also sets up for future refactoring mentioned in the commit message, though the nature of that refactoring isn't specified here.

As with other patches in the series, this maintains compatibility with ASan's strict string checking and doesn't require any test updates since it doesn't change observable behavior. The change is straightforward and unlikely to be controversial given it's removing code that's provably redundant due to earlier hardening work.
