Refactoring in Ezekiel Newren's xdiff modernization series for Rust FFI compatibility. This patch (6/10 in v5) splits the dual-purpose `ha` field in `xrecord_t` into two distinct fields with clearer semantics:

1. `line_hash`: A straightforward `uint64_t` hash of the line content itself, used with `xdl_recmatch()` for accurate line comparisons even when hash collisions occur.

2. `minimal_perfect_hash`: A `size_t` value representing the classifier's unique minimal hash for array indexing, replacing the previous combined use of `ha` for both purposes. This change eliminates ambiguity in the field's usage while improving Rust interop by avoiding `as usize` casts.

The patch updates all xdiff algorithms (myers, histogram, patience) to use the new field names consistently. Key changes include:
- `xdl_hash_record()` now populates `line_hash` while the classifier sets `minimal_perfect_hash`
- Comparison functions now explicitly check `minimal_perfect_hash` for line matching
- Hash table operations use the appropriate field for their specific purpose

This continues the series' systematic type modernization while maintaining the behavioral invariants established in earlier patches. The split clarifies the distinct roles these hashes play in the diff algorithm and better documents the data flow through the xdiff subsystem.
