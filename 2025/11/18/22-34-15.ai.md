This is part of Ezekiel Newren's ongoing xdiff refactoring series to modernize core xdiff structures for Rust FFI compatibility. The patch changes `xrecord_t.ptr` from `char*` to `uint8_t*` to better reflect its role as a byte pointer rather than a character pointer, following the type mapping standards established earlier in the series.

The change requires numerous casts where the pointer is passed to functions expecting `char*`, particularly in string comparison and regex handling code paths. The commit notes several locations where casting was unnecessary but preserved for minimal disruption. Key impacted subsystems include diff generation (`xdiffi.c`), merge conflict handling (`xmerge.c`), and the patience diff algorithm (`xpatience.c`).

This mechanical change applies the series' established type mapping principles consistently, treating memory buffers as byte arrays rather than character strings where appropriate. The patch maintains backward compatibility through explicit casts at interface boundaries while progressing the broader goal of type safety for FFI. No new discussion points are introduced - this continues the systematic application of v5's agreed-upon standards.
