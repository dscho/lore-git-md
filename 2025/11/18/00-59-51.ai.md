Platform compatibility patch addressing Windows thread synchronization. The change modifies the Windows pthread emulation layer to properly handle failures in `SleepConditionVariableCS()` by returning an error code rather than silently succeeding. Previously, the macro implementation would unconditionally return 0 via `return_0()`, masking any underlying system errors.

The patch moves `pthread_cond_wait` from a macro to a proper function in pthread.c, where it can check the return value of `SleepConditionVariableCS` and convert Windows error codes to POSIX-style error numbers using the existing `err_win_to_posix()` helper. The corresponding header declaration is updated to match.

This appears to be a straightforward fix for a real issue - Windows API failures were being ignored in thread synchronization path - though the commit message could be more detailed about potential failure scenarios. The change is localized to Windows-specific compatibility code and follows the existing pattern of error handling seen elsewhere in the codebase.
