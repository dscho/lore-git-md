This is the foundational documentation patch for the xdiff refactoring series, establishing type mapping standards between C and Rust for FFI compatibility. The new `unambiguous-types.adoc` document provides detailed specifications for type conversions across language boundaries, with particular attention to problematic areas like character types and platform-specific behaviors.

Key technical points established:
- Standard mappings for boolean, integer, floating-point, and size types
- Special handling for C `char` type (including signedness warnings and platform considerations)
- Problems with Rust's `c_*` types (demonstrated through version-specific examples of `c_long` definitions)
- Enum type limitations in FFI contexts
- Platform-specific gotchas around arithmetic operations and type comparisons

The document serves as a reference for the type modernization work in subsequent patches, particularly the xdiff` struct updates. It includes maintainer-approved wording about character handling (preserving `char` for `get_indent()`) and documents the consensus around compiler warnings versus type safety. The patch adds this to both Makefile and meson build systems, ensuring it will be built with other technical documentation.
