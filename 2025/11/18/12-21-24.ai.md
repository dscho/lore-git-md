Bugfix for test helper memory and descriptor leaks. This patch addresses two issues in the test-mktemp helper program: a memory leak from the duplicated template string and a file descriptor leak from the unclosed temp file. While these leaks don't cause problems in current usage (since the program exits immediately and existing tests only exercise failure cases), the patch proactively fixes them to prevent future issues and silence static analysis tools.

The changes involve storing the duplicated template string and file descriptor in variables so they can be properly freed/closed before program exit. The fix touches only the test-mktemp.c helper file, modifying the cmd__mktemp() function to track and clean up these resources. The author notes this isn't urgent but worth fixing since the analysis was already done, and mentions the recent xmkstemp() changes likely made Coverity flag this as a new issue.

Key technical details for future reference: the patch introduces two new variables (template and fd) to track resources, adds close(fd) and free(template) calls, and keeps the same xstrdup/xmkstemp behavior otherwise. The test cases in t0070 that use this helper currently only test failure paths where die() prevents the leaks from occurring, but the fix ensures safety if successful calls are added later.
