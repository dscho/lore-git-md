Bugfix for `git worktree list` column alignment with multibyte characters, part 1/2 in a series addressing output formatting issues.

This patch fixes incorrect column spacing in `git worktree list` output when worktree paths contain multibyte characters. The current implementation uses byte length rather than visual width for column calculations, causing misalignment. Phillip Wood's solution introduces a `worktree_display` struct to cache visual widths (calculated once via `utf8_strwidth()`) and separates path printing from padding, eliminating redundant calculations. The change also fixes an off-by-one space in the output format that affected all cases, not just multibyte paths.

The implementation modifies `builtin/worktree.c` to track display widths in a new struct array and adjusts the formatting logic. Test updates in `t/t2402-worktree-list.sh` now include a worktree with multibyte characters (named "áááá") to verify proper alignment. The patch is technically sound with thorough test coverage, though it's worth noting this is part of a 2-patch series where the second commit will build on this infrastructure to handle control character quoting.

Key technical details for future reference:
- Introduces `struct worktree_display` to store visual width (will be extended in next patch)
- Replaces `path_maxlen` with `path_maxwidth` to track display units not bytes
- Modifies `measure_widths()` to populate display struct array
- Updates `show_worktree()` to use cached widths and new padding approach
- Test changes demonstrate multibyte handling without requiring `sed` normalization
- 35 lines changed in core logic vs 22 lines in tests
