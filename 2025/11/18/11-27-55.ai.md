This is the first patch in a 3-part bugfix series addressing `git fetch` reference update issues. It performs preparatory refactoring by extracting transaction commit logic into a new `commit_ref_transaction()` helper function.

The patch moves the transaction commit and rejection handling code from `do_fetch()` into a standalone function with parameters for the transaction pointer, atomic flag, remote name, and error buffer. The new helper centralizes the cleanup logic (including transaction freeing) and maintains the same behavior for both atomic and non-atomic fetches. Key technical details include:
- Pointer-to-pointer transaction parameter ensures proper cleanup
- Maintains existing atomic/non-atomic behavior paths
- Preserves error reporting through strbuf
- Keeps the same rejection handling for batched updates
- Follows existing control flow with `goto out` pattern

This refactoring enables the subsequent patches to reuse this logic when fixing the tag fetching regression. The change is mechanical with no behavior modifications - all existing tests pass unchanged. The commit message clearly explains the motivation as preparation for the bugfix while maintaining backward compatibility.
