Windows thread handling refactoring (v3). Greg Funni submits the third version of their patch simplifying Windows thread synchronization in Git's pthread emulation layer. This continues the effort to streamline `win32_pthread_join` by removing what the author considers impossible error cases.

The key change replaces a switch statement handling multiple wait outcomes with a single check for `WAIT_FAILED`, treating all other cases uniformly. Version 3 maintains the same technical approach as v2 but appears to be a rebase with no functional changes (the range-diff shows identical content). The commit message explains why certain Windows wait outcomes (`WAIT_TIMEOUT`, `WAIT_ABANDONED`, `WAIT_IO_COMPLETION`) cannot occur in this context due to the use of INFINITE timeout and non-alertable waits.

This appears to be a well-justified cleanup, though the thread history shows maintainers previously requested better documentation of the safety rationale, which the author has now provided. The patch touches low-level Windows compatibility code, so Windows platform maintainers would be the primary reviewers. The change seems focused and non-controversial, representing incremental progress on Windows thread handling rather than introducing new functionality.
