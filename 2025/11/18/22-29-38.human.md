This is a follow-up refactoring patch in the tempfile cleanup series. René Scharfe takes Jeff King's earlier suggestion to eliminate the last remaining direct `mkstemp(3)` call in Git's codebase, replacing it with Git's internal `git_mkstemp_mode()` function. The change removes Windows compatibility wrappers for `mkstemp()` and instead defines it as a macro pointing to Git's implementation.

The patch maintains the same behavior (creating tempfiles with mode 0600) while ensuring consistent tempfile handling across all platforms. René notes that while `mkstemp(3)` works fine for basic cases, Git needs additional functionality (custom permissions, suffix support, Windows compatibility) that the standard function doesn't provide. The change is straightforward - removing the Windows-specific implementation and adding a macro - and builds on the previous consensus that Git should use its own tempfile handling consistently.

This appears to be a logical next step in the tempfile cleanup, though as with the previous patch, it's purely a refactoring with no behavior change. The implementation looks clean and the motivation is well-explained, building on the earlier discussion.
