This is part of Ezekiel Newren's ongoing xdiff refactoring series to modernize type usage for Rust FFI compatibility. Patch 5/10 in v5 focuses on the hash record functionality, converting ambiguous C types to explicit fixed-width types for cross-platform consistency.

The patch updates `xdl_hash_record()` and related functions to use `uint8_t` for byte buffers (replacing `char*`) and `uint64_t` for hash values (replacing `unsigned long`). This ensures consistent behavior across platforms where `long` sizes vary. The changes affect core diff processing functions that handle whitespace and verbatim line hashing, with all arithmetic and bit operations now using well-defined types.

Key technical changes include converting the hash accumulator from `unsigned long` to `uint64_t`, updating pointer types to `uint8_t const*` throughout the call chain, and changing the `flags` parameter from `long` to `uint64_t` to prevent high-bit truncation. The patch maintains existing behavior while making the byte-oriented nature of the operations explicit through the type system.

This continues the series' pattern of methodical type updates following the established standards from earlier patches, with no new architectural changes or discussion points introduced. The changes align with the documented type mapping guidelines and have been reviewed by the core maintainers involved in the series.
