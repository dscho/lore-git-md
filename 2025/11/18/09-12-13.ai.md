Build system patch in Jeff King's ASan fixes series, focusing on memory safety testing coverage. This is patch 3/9 in v2 of the series.

The patch enables NO_MMAP when building with AddressSanitizer (ASan) to improve detection of out-of-bounds memory accesses. Currently, mmap() creates a blind spot in ASan coverage since the OS rounds accesses to page boundaries, potentially hiding small overruns. The change forces heap allocation instead of mmap when ASan is active, at a small memory cost that's acceptable for test suite runs.

The patch modifies both the Makefile and meson.build to implement this change consistently across build systems. The Makefile change is straightforward, while the meson.build modification is more involved due to its different architecture for handling platform-specific functionality. The patch notes this will help uncover several known (but not yet test-triggered) memory bugs.

This builds on the series' goal of hardening Git's memory handling by ensuring ASan can effectively catch boundary violations that would otherwise be masked by mmap behavior. The change is narrowly scoped to testing scenarios and doesn't affect production builds.
