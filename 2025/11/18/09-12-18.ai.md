This is a bugfix patch in Jeff King's ASan series, addressing memory safety issues in cache-tree parsing. The patch replaces `strtol()` with a custom `parse_int()` function to safely read numeric values from index entries without relying on NUL-termination.

The technical core involves fixing two problems: potential read overflows from malformed index entries (though with low security impact since the index is local), and ASan's strict string checking which flags the non-NUL-terminated buffer usage. The new `parse_int()` helper avoids these issues by explicitly tracking buffer length and enforcing stricter parsing rules than `strtol()` - it requires a newline terminator and rejects leading whitespace.

Key implementation details:
- New `parse_int()` helper advances buffer pointer and length as it parses
- Rejects malformed input more strictly than original code
- Maintains same basic numeric parsing behavior but with bounds checking
- Triggerable via ASan with `strict_string_checks=1` in test suite
- Part of broader ASan hardening effort (see Patch 3's NO_MMAP changes)

The patch fits cleanly into the series' focus on memory safety, though it notes some deferred work around making strict_string_checks default. The change is well-motivated and the implementation appears robust, with clear explanations of both the problem and solution. No test added due to difficulty constructing precisely malformed indexes, but existing tests can trigger the issue under ASan.
