This is part of Jeff King's ASan fixes series, specifically addressing memory safety in the cache-tree subsystem by replacing `strtol()` with a custom parser. The patch originally introduced a simple `parse_long()` helper without error handling, which Patrick Steinhardt noted could be fragile regarding overflow detection and input validation.

In this follow-up, Jeff King acknowledges the concerns but points out the original code also lacked overflow checking. He confirms the v2 version will include error handling for empty input (returning an error code rather than silently accepting 0) while deferring overflow checks since they weren't in the original and require careful implementation. The discussion highlights the balance between memory safety fixes (the primary goal) and input validation improvements, with Jeff indicating overflow checks could be layered on top later.

Key technical details: The `parse_long()` helper processes signed integers from a string buffer with length tracking, handling signs but originally lacking validation. The v2 interface will change to return error codes and reject empty input, while keeping the same basic parsing approach. The cache-tree parsing context means invalid numbers would eventually fail elsewhere, but tighter validation could catch issues earlier.
