This is a bugfix patch in Jeff King's ASan findings series, focusing on memory safety in `fsck_ident()`. The patch strengthens the validation of commit and tag headers by ensuring we properly handle buffer boundaries when parsing author/committer lines.

The current code assumes a newline exists in the buffer (as verified by `verify_headers()`) but uses `strchrnul()` which could theoretically read past the buffer if that assumption were violated. The patch replaces this with explicit bounds checking via `memchr()`, and adds a `BUG()` assertion if the expected newline is missing - catching any cases where the calling code fails to properly validate input first.

This change makes the memory safety guarantees more explicit and robust, particularly under ASan which would catch buffer overruns. The patch is narrowly focused on this one function, but fits into the broader series' goal of hardening Git against memory safety issues. The changes are straightforward and well-justified, with clear explanations of both the current behavior and why the new approach is safer.
