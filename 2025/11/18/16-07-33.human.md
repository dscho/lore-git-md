This is the second part of a bugfix series addressing output formatting issues in `git worktree list`. The patch focuses on properly quoting worktree paths that contain control characters like newlines, which previously disrupted the command's output.

Phillip Wood extends the `worktree_display` struct introduced in part 1 to store quoted paths, using `quote_path()` to handle special characters. The change ensures human-readable output remains clean while maintaining the existing behavior for scripts (which should use `--porcelain`). The patch includes tests verifying the behavior with both `core.quotepath` settings enabled and disabled.

The implementation is clean and builds logically on part 1's infrastructure. The test coverage is thorough, checking both quoted and unquoted scenarios. This appears to be a well-considered solution to a real usability issue, completing the series' goal of making worktree listing more robust against edge cases in path names.
