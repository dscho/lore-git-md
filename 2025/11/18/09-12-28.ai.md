This is a bugfix patch in Jeff King's ASan hardening series, specifically addressing a potential issue in `fsck_ident()`'s timestamp parsing. The patch replaces direct use of `parse_timestamp()` (which expects NUL-terminated strings) with a new helper function that safely copies digits into a temporary buffer before parsing.

The core issue is that while the current code works (relying on a newline that was checked earlier), it triggers ASan's strict_string_checks due to potential buffer overreads. The new `parse_timestamp_from_buf()` function explicitly bounds the digit collection to prevent any overrun, while maintaining all the existing validation (overflow checking, date format requirements).

Key technical details include:
- New helper function that copies digits into a 24-byte buffer (large enough for any timestamp)
- Maintains identical error detection for overflow and malformed dates
- Preserves the existing control flow of `fsck_ident()`
- Follows the series' pattern of making parsing more robust against memory safety issues
- Changes the calling convention slightly by updating the position pointer directly rather than returning an end pointer

This change is part of the broader effort to enable strict_string_checks by default across Git's codebase. The patch appears well-considered, with careful attention to maintaining all existing validation while making the code more obviously correct. It follows naturally from the previous hardening work in this series and doesn't introduce any obvious new risks.
