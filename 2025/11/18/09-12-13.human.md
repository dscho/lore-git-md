This is a build system patch in Jeff King's ASan fixes series, specifically addressing memory mapping behavior under AddressSanitizer.

The patch forces Git to use heap buffers instead of memory-mapped files when built with ASan (AddressSanitizer). The motivation is that ASan can't properly detect out-of-bounds accesses in mmap'd regions, since the OS rounds memory accesses to page boundaries. This creates a blind spot where small overreads might go undetected. The change affects both Makefile and Meson builds.

The patch follows naturally from the previous commit in the series, which demonstrated a real memory bug that was missed due to this mmap behavior. While this increases memory usage (since files are copied to heap buffers rather than mapped), the impact is considered acceptable given the test suite's small repository sizes and ASan's already significant performance overhead.

The implementation adds NO_MMAP to both build systems when ASan is enabled, with the Meson side requiring slightly more complex logic to maintain the mmap detection for non-ASan builds. This appears to be a straightforward, well-justified change that tightens ASan's memory checking capabilities.
