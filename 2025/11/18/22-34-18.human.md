This is part 6/10 of Ezekiel Newren's ongoing xdiff refactoring series to modernize core structures for Rust FFI compatibility. The patch splits the `ha` field in `xrecord_t` into two distinct fields: `line_hash` (a straightforward hash of the line content) and `minimal_perfect_hash` (a unique identifier used for array indexing). 

The change clarifies the code by separating these two distinct purposes that were previously conflated in a single field. The `line_hash` is now explicitly typed as `uint64_t` since it comes from a fixed-width hash function, while `minimal_perfect_hash` uses `size_t` as it's meant for array indexing (which also helps Rust integration by avoiding casts). 

The patch updates all the xdiff algorithms (myers, histogram, patience) to use the new field names. This is a straightforward refactoring that maintains all existing behavior while improving type safety and code clarity. The change builds on the type modernization work done in previous patches of this series, which has already been thoroughly reviewed and approved by the maintainers.
