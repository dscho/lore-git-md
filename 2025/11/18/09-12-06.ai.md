Bugfix for ASan findings in the pack-bitmap subsystem, specifically addressing out-of-bounds memory access in incremental midx bitmap name-hash lookups. This is patch 2/9 in Jeff King's v2 series fixing ASan-detected issues.

The patch fixes a subtle memory safety issue where name-hash lookups in incremental multi-pack index (midx) bitmaps could access memory outside the bounds of the mmap'd hash array. The problem occurs because each incremental midx bitmap only contains a slice of the full name-hash array, but the code was treating it as a single contiguous array. The fix introduces a new `bitmap_name_hash()` helper that properly walks the chain of bitmap_index structs to find the correct slice before accessing the hash value.

The issue was detected when building with NO_MMAP=1 and SANITIZE=address, which replaces mmap with heap allocations that ASan can instrument. The test case t5334-incremental-multi-pack-index.sh would fail without this fix. The patch maintains the existing validation approach confirmed by Taylor Blau in v1 review and adds defensive assertions to catch invalid states.

Key technical details:
- New `bitmap_name_hash()` function handles both regular and incremental midx cases
- For incremental midx, walks bitmap_index chain to find correct slice
- Adjusts position relative to found slice before access
- Adds BUG() assertions for invalid states
- Updates two call sites to use new helper
- Maintains existing hash-cache size validation
- Preserves lexical OID order handling

The patch is narrowly focused on fixing the memory safety issue while maintaining existing behavior. It's part of a larger effort to address ASan findings across Git's codebase, with this particular issue being one of the more subtle cases involving midx bitmap handling.
