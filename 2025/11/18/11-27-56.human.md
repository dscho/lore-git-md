This is the second patch in a three-part bugfix series addressing regressions in `git fetch`'s batched reference updates. The specific issue fixed here is that non-conflicting tags weren't being committed when other tag conflicts existed, a regression introduced by commit 0e358de64a which added batched updates.

The patch modifies the cleanup logic in `do_fetch()` to commit the transaction (for non-atomic fetches) even when some updates fail, ensuring non-conflicting tags still get applied. This fixes both direct tag fetching with `--tags` and backfilling of tags when fetching specific refspecs. The solution cleanly handles error cases while maintaining the existing behavior for atomic fetches.

Three new test cases verify the fix works for: basic tag fetching, non-conflicting tags alongside conflicts, and proper backfilling of tags when fetching specific refspecs. The tests also include proper cleanup handling. The patch builds on the refactoring from part 1/3 and has been through multiple rounds of review, with all feedback incorporated. This appears to be a well-tested, focused fix for a clear regression in batched fetch behavior.
