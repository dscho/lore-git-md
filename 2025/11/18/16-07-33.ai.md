Bugfix completing the `git worktree list` output formatting series by adding path quoting for control characters. This second patch in Phillip Wood's 2-part series addresses the remaining issue where paths containing control characters (like newlines) would disrupt the output formatting.

The patch modifies the same `builtin/worktree.c` and test file as part 1, extending the `worktree_display` struct to store quoted paths. It uses `quote_path()` to properly escape control characters while maintaining the alignment fixes from part 1. The changes include:
- Adding a `path` field to `worktree_display` to store quoted versions
- Updating `measure_widths()` to calculate display width after quoting
- Adding memory management for the quoted paths
- New test cases verifying behavior with `core.quotepath` both enabled and disabled
- Special handling for multibyte characters in the test expectations

The implementation maintains backward compatibility with scripts by noting they should use `--porcelain` output. The test coverage is thorough, checking both ASCII control characters and multibyte paths under different quoting configurations. The patch builds cleanly on part 1's infrastructure changes, completing the series' goal of making `git worktree list` output robust against unusual path characters.
