Bugfix for `git worktree list` column alignment with multibyte characters. This is the first patch in a 2-part series addressing output formatting issues in worktree listing.

Phillip Wood fixes a long-standing issue where paths containing multibyte characters (like accented letters) caused misaligned columns in `git worktree list` output. The problem stemmed from using string length rather than visual width for column calculations. The patch introduces a more efficient approach that calculates visual width once and stores it, rather than recalculating multiple times. It also fixes an off-by-one spacing issue that affected all outputs.

The changes are well-motivated and clearly explained, with the commit message detailing both the problem and solution. The implementation modifies `builtin/worktree.c` to use a new `worktree_display` struct for tracking widths, and updates tests to verify the fix works with multibyte characters (using "áááá" as a test case). The patch appears carefully crafted - it not only fixes the immediate issue but also sets up the structure for the second patch in the series (about control character quoting) by making the display data more extensible.

This is a straightforward improvement to a user-facing command that makes Git more reliable for users with non-ASCII paths. The changes are focused and come with matching test updates, suggesting it's ready for review.
