This is a follow-up discussion in the completed series adding 'strip-if-invalid' mode to `git fast-import`'s `--signed-commits` option. Christian Couder responds to Elijah Newren's query about the removal of dual-signature tests in the final version.

The exchange clarifies that while two dual-signature tests were removed to avoid conflicts with an unrelated Rust prereq series (f6581e23), five other tests remain that fully exercise the new 'strip-if-invalid' functionality. Christian explains the technical constraints around the test removal - the Rust prereq would need to be introduced in this series, which would be premature since the Rust series' merge status is uncertain. He leaves open the possibility of restoring the tests later if desired.

The discussion confirms the core validation behavior matches `git verify-commit` as documented, with no outstanding technical concerns about the implementation. The test coverage remains robust despite the removal, focusing on unsigned commits, valid signature preservation, and invalid signature stripping via message tampering. The exchange highlights careful consideration of test organization and dependency management in the final series refinement.
