Documentation patch establishing type mapping standards for C/Rust FFI.

This is the foundational documentation patch in Ezekiel Newren's 10-part series modernizing Git's xdiff subsystem for Rust FFI compatibility. It introduces a new technical document (`unambiguous-types.adoc`) that defines precise type mappings between C and Rust, with special attention to edge cases and platform-specific behaviors.

The document covers boolean, integer, floating-point, size, and enum types, noting where C and Rust semantics diverge. Key points include:
- Standard integer types (uint8_t/u8, etc.) have straightforward mappings
- Floating-point assumes IEEE-754 compliance which C doesn't enforce
- Character types (`char` vs `u8`) have platform-dependent signedness issues
- Rust's `c_*` FFI types have version-dependent definitions that may not match all C compilers
- Enum types have Rust-specific behaviors that make them unsuitable for direct FFI use

The documentation serves as a reference for the subsequent patches in the series that actually implement these type mappings in the xdiff subsystem. It has already undergone extensive review, with v5 incorporating final wording refinements from maintainers regarding character type handling and standards compliance.

This is a well-crafted, thorough document that clearly addresses a real need in Git's cross-language development. The attention to edge cases and versioning issues shows careful consideration of practical FFI challenges.
