This is a discussion about the build dependencies for the OSX keychain credential helper, following up on the bugfix thread.

Jeff King provides historical context about why credential helpers were originally designed to avoid linking with libgit.a. The rationale was twofold: first, to maintain the possibility of these helpers being independent projects outside the Git tree, and second, to avoid potential breakage when libgit.a internals change. He notes that while the xmalloc and strbuf interfaces are stable enough that linking might be reasonable, there could still be occasional breakage.

The email serves as background information rather than proposing any new changes to the current patch. It explains why the original patch author might have been hesitant to use Git's utility functions, while acknowledging that the tradeoffs may have shifted over time. This context helps explain the design decisions in the thread while not contradicting the already-approved approach of using standard Git utilities in the final patch.

Key points for future reference:
- Original design philosophy for credential helpers favored independence from core Git
- Potential concerns about breakage when linking with libgit.a
- strbuf and xmalloc interfaces considered stable enough for this use case
- Current CI may or may not catch breakage in credential helpers
- Discussion illustrates historical vs current tradeoffs in Git's contrib/ components

The email doesn't require any action on the patch itself, which has already incorporated the requested changes, but provides useful background for understanding the design constraints around credential helpers.
