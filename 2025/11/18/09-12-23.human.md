This is a memory safety patch in Jeff King's ongoing series to harden Git against ASan (AddressSanitizer) findings. It focuses on `fsck_ident()`, which validates author/committer lines in Git objects.

The patch replaces `strcspn()` with explicit character-by-character parsing in `fsck_ident()`. While the current code is technically safe (it relies on a known newline terminator), the change makes the bounds checking more obvious and avoids false positives from ASan's strict string checking mode. The new implementation also makes the parsing logic more straightforward by handling each special character (`<`, `>`, `\n`) as it's encountered rather than jumping around with `strcspn()`.

This is part of a larger effort to make Git's string handling more robust against buffer overreads. The change maintains all existing functionality while being more explicit about buffer bounds. The patch fits well with the series' theme of replacing string operations with length-aware alternatives, and appears to be a straightforward improvement with no obvious downsides.
