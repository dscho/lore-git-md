This is a follow-up refactoring patch that completes the tempfile cleanup work from the previous discussion. René Scharfe now proposes to stop using `mkstemp(3)` entirely in favor of Git's internal `git_mkstemp_mode()`, implementing Jeff King's suggestion from the earlier thread.

The patch removes the Windows-specific `mkstemp()` implementation from compat/mingw.c and instead defines `mkstemp()` as a macro that calls `git_mkstemp_mode()` with 0600 permissions. This ensures consistent tempfile creation behavior across all platforms while eliminating platform-specific compatibility code. The change affects three files: removing declarations/implementations from the Windows compatibility layer while adding the macro definition to git-compat-util.h.

The rationale explains that while `mkstemp(3)` works fine for basic cases, Git needs additional features (custom permissions, suffix support, Windows compatibility) that its internal implementation provides. This builds on the previous consensus that Git's tempfile handling is now robust enough to make the system `mkstemp()` redundant. The patch cleanly addresses the remaining direct `mkstemp()` call in entry.c that was noted as out of scope in the previous discussion.
