Windows/Meson CI test output visibility fixes (2-patch series)

Core problem: Windows test jobs using Meson build system fail to show test script output on failures, making debugging difficult. Series modifies test infrastructure to properly surface output while maintaining existing test behavior.

Changes:
- Patch 1 (updated): Makes unit test runner ignore `--no-chain-lint` option by adding it to no-op options list in `unit-test.c`, following pattern from commit 9faf3963b6. This is prerequisite for proper Windows Meson test output handling.
- Patch 2 (new): Introduces `ci/run-test-slice-meson.sh` wrapper script to properly handle test options and output for Windows Meson builds. Replaces direct `meson test` invocation in GitHub Actions, processes `GIT_TEST_OPTS`, and integrates with existing test handling infrastructure. Adds post-test failure details and artifact upload matching other CI jobs.

Technical scope:
- Touches GitHub Actions workflow configuration (`.github/workflows/main.yml`)
- Adds new test runner script (`ci/run-test-slice-meson.sh`)
- Modifies `unit-test.c` infrastructure (1 line added)
- Specifically targets `windows-meson-test` job
- References prior work (commit 9faf3963b6) for test option handling pattern
- Maintains Windows-specific shell choice (`pwsh`) due to path handling issues
- Preserves parallel test slicing (1-10) while adding proper test output
- No core Git functionality changes - purely test infrastructure improvement

Status: Initial version posted as RFC. No reviews or feedback yet. Changes remain small (39 lines total across both patches) and focused on CI system rather than Git core. Patch 1 handles `--no-chain-lint` as prerequisite; Patch 2 implements Meson-specific solution rather than sharing code with existing `run-test-slice.sh` due to build system differences in test handling (Meson requires explicit `--test-args` vs Make's automatic handling).
