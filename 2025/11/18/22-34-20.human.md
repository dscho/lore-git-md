This is part of Ezekiel Newren's ongoing xdiff refactoring series to modernize core xdiff structures for Rust FFI compatibility. Patch 8/10 in the series converts the `nreff` field in `xdfile_t` from `long` to `size_t`, as it describes the number of elements in memory for the `rindex` array.

The change is straightforward - the patch removes temporary `nreff` variables and directly updates the struct field during array processing in `xdl_cleanup_records()`. This follows the pattern established earlier in the series of using `size_t` for array element counts, which is more semantically correct and consistent with the type mapping standards documented in the series' earlier patches.

The change affects the diff preparation code that handles line matching and cleanup, but maintains the same behavior while using more appropriate type. This continues the series' systematic approach to type modernization while preserving backward compatibility through the existing interface boundaries.

The patch is well-contained, touching just two files with minimal changes, and builds on the extensive type mapping documentation and consensus established in previous patches reviewed by Junio Hamano and other maintainers. It represents another incremental step toward the series' goal of preparing xdiff for Rust FFI integration with properly specified core type mappings.
