This is a platform compatibility patch addressing a minor POSIX compliance issue in Git's Windows pthread emulation layer. Junio Hamano points out that the patch's subject line incorrectly references `pthread_cond_wait` when it actually modifies `pthread_cond_init`.

The patch itself (from Greg Funni) makes `pthread_cond_init()` explicitly return 0 for POSIX compliance, following the same pattern already used for `pthread_cond_wait` in the same file. While Git doesn't currently check this return value, the change makes the emulation layer more strictly conformant. The implementation uses the existing `return_0` macro wrapper.

Junio's note about the incorrect subject line suggests this might need a resubmission with a proper title before being considered for merging. The change is straightforward and low-risk, but the thread hasn't seen any other maintainer feedback yet. This appears to be a small, isolated improvement rather than part of any broader POSIX compliance effort for the Windows port.
