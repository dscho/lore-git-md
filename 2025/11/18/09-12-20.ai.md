Bugfix patch in Jeff King's ASan series, focusing on memory safety in fsck_ident() parsing. This is patch 5/9 in v2 of the series addressing ASan findings.

The patch strengthens the fsck_ident() function's handling of commit and tag identity lines by replacing unsafe strchrnul() usage with explicit buffer bounds checking. The key change is requiring callers to pass the buffer end pointer, allowing safe use of memchr() to find newlines. The function now BUG()s out if the expected newline is missing, enforcing the pre-condition that verify_headers() must have validated the input first.

This addresses a subtle memory safety issue where the previous code could theoretically read past buffer bounds if verify_headers()'s guarantees were violated. The change makes the implicit safety assumptions explicit while maintaining the same behavior for valid inputs. The patch updates all callers (commit and tag parsing) to pass the buffer_end parameter.

The fix connects to the series' broader theme of hardening Git against memory safety issues found by ASan. It follows the pattern seen elsewhere in the series of replacing string operations with explicit length-aware alternatives. The BUG() assertion aligns with the series' approach of failing fast when invariants are violated rather than risking undefined behavior.
