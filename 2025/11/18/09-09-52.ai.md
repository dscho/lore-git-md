This is a follow-up discussion on the documentation patch standardizing cross-references in `git-commit` manpage. Jeff King (peff@peff.net) responds to Kristoffer Haugsbakk's patch that improved linking between `git commit --dry-run` format options and their `git-status` counterparts.

The response confirms the changes make sense and acknowledges the historical inconsistencies in documentation style that the patch addresses. Jeff King humorously attributes the original inconsistency in his 2012 commit (f3f47a1e) to youthful impetuousness compared to the more thorough 2009 commit (7c9f7038) that did include proper links.

Key technical details mentioned include the specific format options being standardized (`--branch`, `--long`, `--null`), their relationship to `git-status` output formats, and the two historical commits that introduced these options with inconsistent documentation styles. The discussion confirms this is purely a documentation improvement with no behavior changes, maintaining consistency between the shared internals of commit and status commands.
