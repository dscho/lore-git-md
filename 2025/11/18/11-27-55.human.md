This is the first patch in a 3-part bugfix series addressing `git fetch` reference update issues. The patch extracts the reference transaction committing logic from `do_fetch()` into a new helper function `commit_ref_transaction()`. This refactoring prepares for fixing a bug where tag fetches with conflicts were causing other reference updates to fail.

The new helper centralizes transaction commit handling, including cleanup of the transaction pointer and rejection handling for non-atomic fetches. The changes maintain all existing behavior while making the code more modular. The patch is a straightforward refactoring with no functional changes, as confirmed by the unchanged test suite.

This is part of a well-reviewed series that has gone through six iterations, with all prior feedback incorporated. The change is cleanly separated from the actual bugfix (coming in patch 2/3) to make review easier. The patch demonstrates good coding practices with clear commit messages and proper attribution to contributors.
