This is a discussion about build dependencies for Git's credential helpers, specifically the OSX keychain helper. Jeff King (Peff) provides historical context for why credential helpers were originally designed to avoid linking with Git's core libraries, citing two main concerns: 

1) The intent was for helpers to be potentially independent projects that could be maintained separately, with minimal ties to Git's internals. This philosophy may now be at odds with the practical benefits of code reuse.

2) Linking with libgit.a risks breakage when core Git changes, with no clear process for detecting such issues. While basic utilities like xmalloc and strbuf are stable, the lack of CI coverage for contrib/ components is a concern.

The email doesn't propose any concrete action but serves as background for the ongoing discussion about whether to allow credential helpers to use Git's internal utilities. This comes in response to Junio Hamano questioning why the OSX keychain helper patch avoided standard Git utilities like strbuf.h. The thread shows the project weighing architectural principles against practical development needs, with Peff acknowledging the tradeoffs while not strongly opposing the change.
