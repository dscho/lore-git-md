Bugfix in the fsck subsystem addressing ASan strict string checks. This is patch 8/9 in Jeff King's series hardening Git against memory safety issues found by AddressSanitizer.

The patch fixes a potential issue in `fsck_ident()` where `parse_timestamp()` (which internally uses `strtoumax()`) could read past the intended buffer bounds when checking commit author/committer timestamps. While the current code is technically safe (it relies on a newline that was previously validated), the ASan strict string checker flags this as a potential problem.

The solution introduces a new helper function `parse_timestamp_from_buf()` that safely copies digits into a NUL-terminated buffer before parsing. This makes the behavior more obviously correct and allows enabling strict string checks by default in the future. The change maintains all existing validation of timestamps, including overflow detection.

This continues the series' pattern of making parsing code more robust by replacing implicit assumptions with explicit bounds checking. The patch is well-motivated and carefully implemented, with clear explanations of both the problem and solution. It follows naturally from earlier hardening work in this function.
