Platform compatibility patch simplifying Windows thread handling code.

This patch refactors the `win32_pthread_join` function in the Windows compatibility layer, removing what the author considers impossible error cases. The original code had a switch statement handling three possible outcomes from `WaitForSingleObject`: `WAIT_OBJECT_0` (success), `WAIT_ABANDONED` (thread terminated abnormally), and a default error case. The new version simplifies this to only check for `WAIT_FAILED`, treating all other cases as successful.

The commit message asserts that `WAIT_FAILED` is "the only real possible error here," though it doesn't provide evidence for why the other cases were considered worth removing. The change reduces the code by 13 lines while maintaining the same core functionality - waiting for thread completion, handling the return value if requested, and cleaning up the thread resources.

The patch touches low-level Windows thread synchronization code, specifically modifying how Git handles pthread emulation on Windows. The change appears straightforward but removes some defensive programming that was presumably added for completeness.
