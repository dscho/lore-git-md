This is a refactoring patch that completes the consolidation of Git's tempfile creation code by fully replacing system `mkstemp(3)` calls with Git's internal `git_mkstemp_mode()` implementation. The change follows up on Jeff King's earlier observation about one remaining direct `mkstemp()` call in `entry.c`.

René Scharfe proposes removing the Windows-specific `mkstemp()` implementation entirely and defining `mkstemp()` as a macro that calls `git_mkstemp_mode(0600)` in git-compat-util.h. This ensures consistent behavior across all platforms and eliminates platform-specific compatibility code. The patch removes 6 lines while adding 2, with the rationale that Git's internal implementation already provides needed features (custom permissions, suffix support, Windows compatibility) beyond basic `mkstemp(3)` functionality.

Junio Hamano's response considers potential downsides of abandoning the system `mkstemp()` (performance or security benefits), but finds none compelling enough to justify keeping the dual implementations. The change appears well-justified as a maintenance improvement that removes code duplication while making behavior more predictable across platforms.
