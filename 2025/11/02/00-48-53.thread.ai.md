CVE-2024-52005 security inquiry thread. Thomas Klausner initiated discussion about this vulnerability's status for pkgsrc packaging, noting NVD listed affected Git versions but lacked fix information, with only reference found in Git for Windows 2.47.1(2) release notes. The Git project, represented by Brian M. Carlson, maintains this was incorrectly classified as a Git vulnerability - the issue stems from terminal emulator behavior (particularly on Windows) allowing arbitrary binary execution when clicking hyperlinks created via terminal codes, not from Git itself. The project considers this out of scope for Git's security model since URL clicks should never result in code execution regardless of context, meaning no Git versions contain a fix because none was needed in Git codebase.

Randall Becker proposes a mitigation approach suggesting Git could add configurable filtering of non-printable characters (particularly escape sequences triggering terminal hyperlinks) via a hypothetical `core.filterUnprintableCharacters` option. He acknowledges this wouldn't address cases where terminals interpret plain URLs as clickable links. The suggestion introduces new technical considerations but doesn't challenge the project's core position about terminal responsibility. Open questions remain about the proposal's effectiveness given its limitations, and whether such filtering belongs in Git versus terminal emulators. Key tracking elements remain CVE-2024-52005 and GHSA-7jjc-gg6m-3329, now understood to reference Windows-specific terminal behavior rather than a Git security flaw. The thread appears largely resolved from Git's perspective unless Git for Windows maintainers respond regarding their differing assessment.
