This is a documentation patch in a 5-part series focused on improving `:(optional)` path handling and related code. The patch makes a small but meaningful clarification to the gitcli.adoc documentation, expanding a terse comment about command equivalence when using `:(optional)` with filenames.

The change makes it clearer that when a file marked as `:(optional)` doesn't exist, the command behaves as if the file argument wasn't provided at all. The example shows this for `git commit -F`, where a missing COMMIT_EDITMSG file makes the command equivalent to just `git commit`. This matches the behavioral fixes being made in other patches of the series.

The modification is straightforward and uncontroversial, following a suggestion from Phillip Wood.
