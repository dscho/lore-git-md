Bugfix for `:(optional)` path handling in parse-options. This patch aligns the command-line behavior of `:(optional)` paths with the config behavior by only ignoring missing files (not empty ones). The change modifies parse-options.c to use `is_missing_file()` instead of `is_empty_or_missing_file()`, matching the intended semantics from the original config implementation. The fix addresses an inconsistency introduced by commit ccfcaf399f and follows Phillip Wood's suggestion. The change is small (1 line) but meaningful for users relying on this path handling behavior. This appears to be part of a larger cleanup series addressing path handling and parse-options improvements.
