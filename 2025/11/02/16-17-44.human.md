This is a bugfix patch that aligns the behavior of `:(optional)` path handling between command-line parsing and configuration parsing. 

The patch fixes an inconsistency where the parse-options code was ignoring both missing *and empty* files when paths were marked with `:(optional)`, while the config code only ignored missing files. The change makes the command-line behavior match the config behavior by only ignoring missing files, which the commit message states was the original intended semantics.

The change is small (just one line modifying a condition in parse-options.c) but addresses a subtle behavioral difference that could cause confusion.
