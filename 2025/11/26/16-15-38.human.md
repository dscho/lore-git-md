This is a bug report regarding test failures on the NonStop platform, specifically in tests t8020.16 and t8020.19 involving the `git last-modified` command during merge operations. The issue appears to be a regression in Git 2.52.0 where `git last-modified` incorrectly reports commit hashes instead of expected tag names (m1.t, m2.t) when crossing merge boundaries.

Randall Becker, the NonStop packager, is trying to determine whether this is a test issue or a deeper problem in the merge code that would impact shipping Git 2.52.0. The thread suggests the issue likely lies in name resolution rather than the merge operation itself, as Junio Hamano has noted the merge topology appears correct.

The email explores a potential platform-specific angle regarding enum vs int handling on big-endian systems, though it's unclear if this is the root cause. There's also mention of build system issues where the SANITIZE option generates invalid CFLAGS for the NonStop compiler.

The discussion remains open on whether to ship 2.52.0 with known test failures or wait for a fix, with participants referencing prior analysis from Jeff King about tag resolution problems. The email also notes technical communication challenges due to aggressive line reflowing in email clients.
