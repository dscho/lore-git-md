This is a follow-up in the cc/fast-import-strip-if-invalid thread regarding an authorship attribution issue. The original patch series from Christian Couder added a --strip-if-invalid mode to `git fast-import`'s --signed-commits option, allowing automatic removal of invalid cryptographic signatures during history rewriting operations. While the technical content was marked for merging in Junio's previous status update, Christian noticed the commit now shows Junio as both author and committer.

Junio explains this was an unintended side effect of using `git commit --fixup amend` followed by `rebase --autosquash`, a workflow he recently adopted. The response acknowledges the issue but does not indicate whether the attribution will be corrected. This appears to be an administrative oversight rather than a technical problem with the patch itself. The core functionality of the fast-import signature handling remains unchanged from Christian's original work.
