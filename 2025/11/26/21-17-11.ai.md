This is a design discussion about the naming of `git replay` operation modes, occurring late in the thread about adding revert capability. Junio Hamano questions whether the existing `--onto` and `--advance` flags would be more clearly named as `--rebase` and `--cherry-pick` respectively, since they correspond to those well-known operations. He notes this would need to happen while `replay` is still experimental.

The email builds on Elijah Newren's earlier observation that the three replay modes (rebase, cherry-pick, and revert) parallel the three main sequencer operations. Junio suggests the current flag names obscure this correspondence. The discussion touches on an important interface question - whether to use technical terms (`--onto`) or operation names (`--rebase`) - with implications for user understanding.

This comes as the revert feature implementation is nearing completion, making it a timely moment for interface design reconsideration. The thread has previously established clear separation between the three operation modes, so this naming question doesn't challenge the architecture but rather its presentation to users. Junio's comment suggests this may be the last opportunity to make such a fundamental naming change before the command stabilizes.
