This is a feature patch series introducing a new `GIT_REF_URI` environment variable to specify reference backends and their storage locations. The primary motivation is enabling zero-downtime migrations between reference storage formats (files <-> reftable) by allowing writes to arbitrary reference directories.

The series builds on ongoing work to make reference backends more flexible. It refactors ref_store creation to support arbitrary directories (patch 1) and implements URI parsing for the new environment variable (patch 2). The URI format is `<backend>://<URI-for-resource>`, with validation for proper syntax and supported backends.

Karthik Nayak provides a concrete use case from GitLab's migration needs, where they must minimize downtime when switching large repositories to reftable. The proposed solution involves writing to a temporary reftable directory during migration while keeping the main repository operational.

The implementation appears thorough, with good test coverage for various URI validation cases and cross-backend operations. The v2 changes address previous feedback by improving error handling, test reliability, and documentation clarity. The series remains focused on the core functionality needed for migration workflows while leaving broader architectural questions (like environment variable semantics) for future discussion.
