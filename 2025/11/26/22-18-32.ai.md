Documentation and maintenance patch for Scalar's configuration settings, implementing "# set by scalar" annotations as previously discussed.

This first patch in the series addresses Patrick Steinhardt's suggestion to clearly mark which config options are set by Scalar operations. The change modifies `scalar.c` to append "# set by scalar" comments when setting config values through `scalar clone`, `register`, or `reconfigure`. The implementation uses `repo_config_set_multivar_in_file_gently()` to add these annotations while preserving existing config values.

Key technical changes:
- Adds path.h include for `repo_git_path()`
- Modifies both `set_scalar_config()` and `log.excludeDecoration` handling to use file-based config writes with comments
- Includes corresponding test updates in t9210-scalar.sh to verify the annotations appear in config files
- Maintains existing behavior where configs are only set if not already present (unless reconfigure forces overwrite)

The patch appears well-contained and properly tested, with clear commit message explaining the motivation. This establishes the pattern that will be followed for other config documentation improvements throughout the series. The implementation handles both single-value and multivar config settings consistently.
