Performance optimization for the patience diff algorithm.

This patch optimizes the `find_longest_common_sequence()` function in the patience diff implementation by reducing unnecessary binary searches. The key insight is that when a unique line appears after the current longest subsequence, we can skip the binary search and simply append it - a common case when diffing similar files.

The author provides detailed benchmarks showing 8-14% speedups across several large repositories (Vim, PyTorch, CPython, Git itself, etc. The optimization is particularly effective as the binary search path is rarely taken (0.01-1.46% of cases in the benchmarks).

The change itself is small (4 lines added) and focused - adding a boundary check before the binary search. The commit message is thorough, including methodology (xctrace instrumentation, hyperfine benchmarks on M1 hardware) and clear performance data. This appears to be a well-motivated, carefully measured optimization to a core diff algorithm.
