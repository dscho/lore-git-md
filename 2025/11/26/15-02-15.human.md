This is a follow-up in the ongoing discussion about whitespace handling in `git clone -c` config arguments. Jeff King (peff) responds to Junio Hamano's proposed minimal fix, pointing out that the issue affects more than just `git clone` - it also impacts the older `GIT_CONFIG_PARAMETERS` environment variable parsing path.

Key points in this email:
1. The whitespace-trimming behavior previously existed in `git_config_parse_parameter()`, which affects both clone operations and environment variable parsing.
2. Peff demonstrates that the old behavior trimmed whitespace on both sides of the equals sign, while Junio's proposed patch would only handle leading whitespace.
3. He remains skeptical about preserving backward compatibility, noting that similar changes to `git -c` in 2021 went unnoticed.
4. The email highlights that this is a judgment call about where to draw the line for compatibility, with Peff leaning toward treating the change as an intentional bugfix rather than maintaining what he views as accidental behavior.

The discussion continues to weigh the tradeoffs between strict correctness and maintaining compatibility with tools like Bamboo that relied on the old behavior. Peff's position suggests he would prefer to keep the current stricter behavior unless a strong case is made for compatibility.
