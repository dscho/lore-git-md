Performance fix in the Scalar config documentation series. This second patch corrects an inverted `index.skipHash` setting that was unintentionally disabling a performance optimization in Scalar repositories. The commit message explains that while the original commit intended to enable this optimization (which skips hash computation for index entries), it actually set the value to `false`. The patch flips this to `true` as originally intended.

The change affects both the main Scalar configuration in scalar.c and requires a test modification in t9210-scalar.sh. The test adjustment temporarily disables `GIT_TEST_SPLIT_INDEX` to work around an interaction between the skipHash optimization and split index behavior during test runs. The author notes this split index issue should be addressed separately in a dedicated series.

This appears to be a straightforward correction of an obvious mistake, though the test interaction suggests there may be deeper index behavior considerations that warrant future investigation. The patch maintains the series' focus on properly documenting and optimizing Scalar's configuration settings while fixing a clear performance regression.
