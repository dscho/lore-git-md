This is the conclusion to the `git clone -c` whitespace-trimming regression discussion. Junio C Hamano and Jeff King agree that the original behavior - which allowed whitespace around config keys in `-c` arguments - was effectively already broken and not worth maintaining. 

The key points are:
1. The behavior was a historical accident that violated Git's config format rules
2. It had been silently broken in `git -c` since 2021 without reports
3. The only affected cases appear to be third-party tools using incorrect argument passing
4. Both proposed fixes (from Johannes Schindelin and Junio) are being abandoned

Junio's closing remark ("I might [stop them] as it would consume my time") signals the discussion is effectively over - the regression will stand as an intentional correction of what was already broken behavior. Third-party tools will need to update their argument passing to match Git's documented format of `-c key=value` as separate arguments.
