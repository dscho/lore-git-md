This is a documentation patch adding warnings about the `--committer-date-is-author-date` option in both `git-am` and `git-rebase`. The patch represents the final resolution of a discussion thread that examined the technical validity of this option's original use case.

The documentation changes upgrade previous NOTE callouts to WARNING boxes, emphasizing that the option can create commit histories violating Git's assumption of non-decreasing commit timestamps. The warnings now explicitly prompt users to reconsider whether they truly need this functionality, while still allowing its use with appropriate caveats.

Key technical details carried forward from the thread include:
- The option was originally added to `git-am` in 2009 to enable reproducible commit hashes when applying patches from email
- This use case was fundamentally flawed as it required identical base commits and committers
- The option was later ported to `git-rebase` without clear justification
- The documentation now uses neutral "override" terminology instead of "lie"
- Warnings specify the timestamp ordering requirements more precisely as "non-decreasing" rather than "strictly increasing"

Phillip Wood's response indicates final approval of the v2 patch, which incorporates all previous feedback from Johannes Sixt and others. The changes represent a consensus approach - strongly warning users about the risks while stopping short of full deprecation, as suggested by Junio Hamano. The thread is now considered resolved with no outstanding questions.
