This thread introduces HTTP 429 (rate limiting) retry support for Git's HTTP client, with Taylor Blau providing key review input on the initial version. The v2 series consists of two patches: the first implements core retry functionality with configurable options (http.maxRetries, http.retryAfter, http.maxRetryTime), while the second adds detailed trace2 instrumentation for monitoring retry operations.

The implementation handles both delay-seconds and HTTP-date Retry-After formats per RFC standards, with a fail-fast approach when delays exceed configured limits. Significant refactoring in v2 improved code organization, including renaming http_request_reauth() to http_request_recoverable() and extracting rate limit handling into a dedicated function. The series includes comprehensive test coverage (286-line t5584 test) with LeakSanitizer verification.

The final patch focuses on observability, adding trace2 events to track retry attempts, server-provided delays, actual sleep durations, and error conditions. This completes the feature by enabling operators to monitor and troubleshoot rate limiting behavior in production. With Taylor Blau's v1 feedback fully addressed and no outstanding technical concerns, the series appears ready for merging.
