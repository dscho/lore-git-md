This thread centers on Vaidas Pilkauskas's series to add HTTP 429 (rate limiting) support to Git's HTTP client, now in its fifth version. The implementation handles Retry-After headers in both delay-seconds and HTTP-date formats, with configurable retry behavior through settings like http.maxRetries and http.maxRetryTime. It includes Trace2 integration and maintains Git's conservative defaults (maxRetries=0) to preserve fail-fast behavior.

Junio Hamano has reviewed and approved the first three patches, which fix strbuf_attach() usage across several files to ensure proper NUL termination and introduce a helper function in remote-curl.c for centralized error handling. He suggests these strbuf fixes could be merged independently if needed. The fourth patch—the core HTTP 429 implementation—awaits review from an HTTP transport expert, likely Jeff King or Taylor Blau, who have previously reviewed this work. The series is well-tested with new infrastructure in t/lib-httpd/http-429.sh and appears functionally complete, pending only this final review of the HTTP transport changes before merging.
