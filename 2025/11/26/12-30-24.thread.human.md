This thread introduces HTTP 429 (rate limiting) retry support for Git's HTTP client, implemented by Vaidas Pilkauskas across three patch versions. The final version adds RFC-compliant handling of Retry-After headers with both delay-seconds and HTTP-date formats, using curl's native parsing when available (curl >= 7.66.0) with a manual fallback. Three new config options control the behavior: http.maxRetries (default 0), http.retryAfter (default 0), and http.maxRetryTime (300s ceiling).

The implementation underwent significant refinement based on feedback from Jeff King and Taylor Blau. Key changes from earlier versions include switching to blocking sleep() for simplicity, adding trace2 instrumentation, and improving test portability by replacing GNU date with test-tool date. The series also includes preparatory refactoring to consolidate error handling paths in remote-curl.c.

Reviewers have validated the technical approach, particularly Jeff King's suggestions around leveraging curl's capabilities and ensuring robust test coverage. The implementation now handles edge cases like invalid Retry-After formats and configuration validation, with comprehensive tests in t/t5584-http-429-retry.sh. This feature will help Git interact more gracefully with rate-limited services like GitHub and GitLab, representing a meaningful improvement to the HTTP client's resilience. With all major feedback addressed and no outstanding objections, the series appears ready for merging.
