This thread is about adding HTTP 429 (rate limiting) retry support to Git's HTTP client, with Vaidas Pilkauskas leading the implementation. The v2 series introduced configurable retry behavior with three new options (http.maxRetries, http.retryAfter, and http.maxRetryTime) and comprehensive test coverage. Key reviewers are Jeff King (Peff) and Taylor Blau, who have provided substantive feedback on both the architecture and implementation details.

In the latest exchange, Peff suggested several technical improvements that Vaidas has agreed to implement in v3: using libcurl's built-in Retry-After parsing when available, moving the retry logic to a more appropriate layer (likely http_request_recoverable()), and making the tests more portable by using Git's test-tool date instead of GNU date commands. These changes address the major open questions from the v2 review while maintaining the core functionality.

The series is progressing well, with consensus forming around the design. Taylor has already signed off on the trace2 instrumentation aspect, and Peff's remaining architectural concerns are being actively addressed. Once these latest changes are implemented in v3, the series should be in good shape for final review and potential merging. The discussion remains focused and productive, with all participants aligned on delivering robust rate limit handling for Git's HTTP operations.
