Bugfix in the Scalar configuration documentation and maintenance series.

This is the second patch in a 5-part series improving Scalar's configuration handling. It fixes an incorrect setting of `index.skipHash` that was unintentionally set to `false` when it should have been `true`, which has been costing Scalar repositories a performance benefit. The commit that introduced this error (4933152cbb) actually intended to enable the performance optimization but got the value backwards.

The patch makes the straightforward config value correction in scalar.c and includes a test modification to work around an interaction between `index.skipHash=true` and `GIT_TEST_SPLIT_INDEX` during test execution. The author notes this split index issue should be properly fixed in a future series focused on that subsystem.

This appears to be a simple but meaningful fix - the incorrect setting was likely degrading performance for Scalar users, and the change aligns with the series' goal of properly documenting and maintaining Scalar's configuration settings. The test workaround is pragmatic for now while pointing to where a proper fix should land.
