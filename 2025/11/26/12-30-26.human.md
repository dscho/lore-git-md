This is a bugfix patch that addresses a memory leak in Git's HTTP client code, discovered while testing the new HTTP 429 rate limiting support. The leak occurs in `show_http_message()`, which displays error messages before terminating when HTTP requests fail. The function was modifying the caller's string buffer directly during character encoding conversion, leaving allocated memory unreleased when the program exits via `die()`.

The patch fixes this by working on a local copy of the message buffer instead, properly cleaning up before returning. While the issue existed in several existing error paths, it became more visible with the new retry logic because retries exercise error handling more frequently. The fix is straightforward - create a local buffer, perform operations on it, then clean it up - and comes with no behavior changes beyond eliminating the leak.

This is the second patch in a three-part series introducing HTTP 429 retry support. The first patch added core retry functionality, while this one cleans up a pre-existing issue that became more apparent with retries enabled. The third patch will add trace2 instrumentation for monitoring retry operations. The series shows good attention to both new functionality and underlying code quality.
