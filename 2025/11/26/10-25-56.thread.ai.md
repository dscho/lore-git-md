Optimization for patience diff's LCS calculation in xdiff/xpatience.c, originally proposed by Yee Cheng Chin. The patch reduces unnecessary binary searches in `find_longest_common_sequence()` by directly appending unique lines that appear after the current longest subsequence, avoiding searches in common cases. Junio C Hamano reviewed and approved the change as a "stupid and obvious" optimization that is actually quite clever, noting it maintains correctness while improving performance.

Key technical details: The modification to `xdiff/xpatience.c` adds a boundary condition check before calling `binary_search()`, testing either `longest == 0` (empty sequence) or `entry->line2 > sequence[longest - 1]->line2` (line appears after current sequence). In these common cases (50-60% of runtime in profiling), the line can be appended directly without search. The implementation preserves the fallback to binary search when needed, adding just 4 lines of logic while maintaining identical output.

Performance impact: Benchmarks across multiple repositories (Vim, PyTorch, CPython, Git) show 8-14% speedups in `git log --patience` operations, with the binary search path now being rarely taken (0.01-1.46% of cases). Measurements from an M1 Max system confirm real-world improvements. The optimization is particularly effective when diffing similar files where sequential line ordering is common.
