Feature patch introducing HTTP 429 (rate limiting) retry support for Git's HTTP client. This is the first of three patches in a series that adds configurable retry behavior when servers respond with rate limiting.

The patch adds three new configuration options to control retry behavior: `http.maxRetries` (defaults to 0 for opt-in behavior), `http.retryAfter` (fallback delay when no Retry-After header is provided), and `http.maxRetryTime` (300 second ceiling for delays). The implementation handles both RFC-compliant delay formats - numeric seconds and HTTP-date timestamps - with proper validation and fallback behavior.

Key aspects include a fail-fast approach when delays exceed configured limits, environment variable overrides for all settings, and comprehensive test coverage in the new t5584 test script. The implementation touches multiple HTTP-related files to add the new status code handling and retry logic while maintaining backward compatibility (retries are disabled by default).
