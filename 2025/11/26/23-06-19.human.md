This is a design discussion about naming the operation modes in the `git replay` command, specifically debating whether to use technical terms (`--onto`, `--advance`) or operation names (`--rebase`, `--cherry-pick`). 

Elijah Newren responds to Junio Hamano's suggestion to rename the modes, arguing that the proposed `--rebase` and `--cherry-pick` names could be misleading. He demonstrates with concrete examples that while the current `--onto` and `--advance` names may be technical, they more accurately describe what the command actually does - specifying where commits are being replayed (`--onto`) and which ref gets updated (`--advance`). 

The key concern is that operation-based names might imply the wrong subject of the action (e.g., suggesting `main` is being rebased when it's actually the base). Elijah emphasizes that since `replay` removes HEAD assumptions present in traditional commands, the command-line interface needs to be self-describing for users learning the command.

This discussion represents an important interface design decision point for the new `replay` command while it's still experimental. The thread shows careful consideration of both technical accuracy and user experience in command naming.
