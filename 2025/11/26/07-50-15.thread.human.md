This thread examines a long-standing localization inconsistency in Git's messaging: while `git pull` shows a properly translated "Already up to date" message, `git push` stubbornly remains in English with "Everything up-to-date". Peter Krefting surfaced this discrepancy, noting the push message originates from plumbing layers (builtin/send-pack.c and transport.c) where output strings are traditionally kept stable in English to avoid breaking external tools.

brian m. carlson's response provides important context - while these strings are marked as stable plumbing output, no actual Git tooling appears to depend on this specific message. He cites a precedent where localizing `rev-parse`'s output caused temporary breakage but was ultimately accepted, suggesting the project may be more open to such changes than the code comments imply. The discussion is now exploring architectural solutions that could satisfy both needs, including potential flags-based approach or leveraging locale settings, while also noting a minor English grammar correction opportunity that's been held back by the same stability concerns.
