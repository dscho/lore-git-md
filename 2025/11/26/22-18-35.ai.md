This is the fourth patch in a series improving Scalar's configuration handling, focusing on reorganization and simplification after the config audit in previous patches.

The patch alphabetizes Scalar's configuration settings for better maintainability, while keeping platform-specific options (like Windows' `http.sslBackend`) grouped at the end. It significantly relaxes enforcement of most settings by removing the `overwrite_on_reconfigure` flag (the `1` values in the config array), making them optional rather than required. The exception is `index.skipHash`, which remains enforced to correct its previously incorrect setting (from false to true) during upgrades.

Key technical changes include:
- Reorders 30+ config settings alphabetically in scalar.c
- Removes `overwrite_on_reconfigure` flag from all settings except `index.skipHash`
- Maintains special handling for Windows' untracked cache (`core.untrackedCache`)
- Groups platform-specific settings (`http.sslBackend` and `core.untrackedCache`) separately
- Preserves the temporary enforcement of `index.skipHash=true` to fix existing installations

This builds on the series' earlier work by applying the lessons from the config audit, while maintaining the performance fix for `index.skipHash` from patch 2. The changes make Scalar's config handling more maintainable and less restrictive for users, while keeping the important enforcement of the skipHash optimization.
