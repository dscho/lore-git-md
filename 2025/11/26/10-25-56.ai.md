Performance optimization for the patience diff algorithm.

This patch optimizes the `find_longest_common_sequence()` function in xdiff's patience diff implementation by reducing unnecessary binary searches. The key insight is that when a unique line appears after the current longest subsequence, we can append it directly without searching. This is a common case when diffing similar files.

The change adds a boundary check before calling `binary_search()`, which previously accounted for 50-60% of runtime in profiling. Benchmarks across several repositories (Vim, PyTorch, CPython, Git itself) show consistent 8-14% speedups in `git log --patience` operations. The optimization is particularly effective as the binary search path is rarely taken (0.01-1.46% of cases in tested repos).

The patch modifies `xdiff/xpatience.c` with a simple 4-line change that adds the boundary check while maintaining the existing fallback to binary search when needed. The commit includes thorough performance measurements from an M1 Max system, showing real-world improvements across diverse codebases. The optimization appears sound and low-risk, touching only the patience diff's internal LCS calculation without affecting output correctness.
