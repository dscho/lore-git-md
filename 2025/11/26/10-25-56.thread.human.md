This thread discusses an optimization to the patience diff algorithm's LCS (Longest Common Subsequence) calculation in xdiff/xpatience.c, proposed by Yee Cheng Chin. The key improvement reduces unnecessary binary searches by directly appending lines that appear after the current longest subsequence, which handles 50-60% of cases without search. Junio Hamano reviewed and approved the approach, calling it a clever optimization that maintains correctness while providing measurable speedups.

Benchmarks across multiple codebases (Vim, PyTorch, CPython, and Git itself) show 8-14% faster `git log --patience` operations, with the binary search path now being rarely needed. The optimization is particularly effective when diffing similar files where lines often appear in sequence. The only change between versions was fixing a typo in the commit message ("PyTorch" was misspelled in v1), with no code modifications needed as the approach had already been validated. The patch adds just four lines of conditional logic while preserving identical diff output, making it a clean, focused improvement to this core diff algorithm.
