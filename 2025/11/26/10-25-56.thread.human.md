This thread discusses an optimization to Git's patience diff algorithm that speeds up the `git log --patience` operation by reducing unnecessary binary searches. The original patch from Yee Cheng Chin modified `xdiff/xpatience.c` to check whether new lines could simply be appended to the current longest common subsequence rather than performing a binary search to find their position - a change that profiling showed could eliminate 50-60% of runtime in common cases. Benchmarks across several large codebases demonstrated 8-14% speedups, as the binary search path was rarely needed (only in 0.01-1.46% of cases).

Junio C Hamano has now reviewed and approved the change, calling it a "stupid and obvious" optimization that turns out to be quite clever in practice. The patch maintains correctness by keeping the binary search fallback while adding just four lines of boundary checking logic. The key insight was recognizing that when diffing similar files, many unique lines naturally appear in order after the current sequence and can be appended directly. This builds on earlier profiling work that identified binary searches as the patience diff's primary performance bottleneck. The optimization is now ready for merging.
