This is a bash completion patch that adds support for short options when typing `git -<TAB>`. It's the second version of a patch series that originally added completion for six common single-letter options (-C, -P, -c, -h, -p, -v).

Junio C Hamano is now queuing the patch with a slightly improved commit message, though he notes there's still an open question about whether `-<TAB>` should complete *only* short options (as currently implemented) or also include long options. He's leaving that decision for potential future discussion, but considers the current version good enough to proceed.

The patch itself is minimal - just a few lines added to `git-completion.bash` to include the short options alongside the existing long option completions. This follows the same pattern as the existing completion system while keeping the implementations separate for now. The change appears straightforward and well-contained, addressing a clear gap in the completion system.

This seems ready to move forward unless other maintainers have strong opinions about the short-vs-long option completion behavior. The patch has already incorporated Junio's earlier feedback about making the commit message more specific.
