HTTP 429 (rate limiting) retry support for Git's HTTP client. Series introduces three new config options: http.maxRetries (default 0, opt-in), http.retryAfter (fallback delay without Retry-After header), and http.maxRetryTime (300s delay ceiling). Implements RFC-compliant handling of both delay-seconds and HTTP-date Retry-After formats. Core retry logic in Patch 1 with struct slot_results gaining retry_after field, new HTTP_RATE_LIMITED (7) status code in http.h, configuration parsing in http_options(), and retry logic in http_request_reauth(). Extensive test coverage in new t5584-http-429-retry.sh verifying retry behavior, header formats, config combinations, and edge cases using mock HTTP server.
