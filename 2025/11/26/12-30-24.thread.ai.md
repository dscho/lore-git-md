Vaidas Pilkauskas's HTTP 429 rate limit retry series (v6) has received maintainer approval and will be merged into 'next' by Junio C Hamano, concluding its development cycle. The implementation adds configurable retry behavior for rate-limited HTTP requests through three new configs (http.maxRetries, http.retryAfter, http.maxRetryTime) and environment variables, handling both Retry-After header formats via CURLINFO_RETRY_AFTER (curl >=7.66.0) with backward compatibility. 

Technical implementation includes HTTP_RATE_LIMITED (7) result code, Trace2 instrumentation, and fail-fast behavior when delays exceed maxRetryTime. The v6 restructuring addressed all prior feedback by using http_get_options for parameter passing, separating REAUTH/RATE_LIMITED counters, moving CURLINFO_RETRY_AFTER handling into http_request(), and fixing test timing races. The series has comprehensive test coverage in t/t5584-http-429-retry.sh verifying header parsing, config combinations, and edge cases.

All preparatory strbuf fixes were previously merged. Taylor Blau's final review confirmed resolution of all concerns, particularly noting proper curl version handling and cleaner parameter passing. Jeff King provided HTTP expertise during review. With no outstanding issues and positive expert reviews, this marks a significant enhancement to Git's HTTP transport capabilities for rate-limited servers. The feature will now undergo integration testing in 'next' before progressing to 'master' for a future release. Related work continues on broader protocol improvements.
