HTTP 429 (rate limiting) retry support for Git's HTTP client. Series v2 from Vaidas Pilkauskas implements RFC-compliant handling of Retry-After headers with both delay-seconds and HTTP-date formats. Introduces three config options: http.maxRetries (default 0, opt-in), http.retryAfter (fallback delay without Retry-After header), and http.maxRetryTime (300s delay ceiling).

Core changes in v2:
- Renamed http_request_reauth() to http_request_recoverable() to reflect expanded role
- Implemented non-blocking retry delays using slot-specific timers (retry_delay_seconds and retry_delay_start fields)
- Extracted rate limit handling into handle_rate_limit_retry() function
- Added new http-429.sh test helper and improved test structure
- t5584-http-429-retry.sh (286 lines with LeakSanitizer verification)
- Comprehensive trace2 instrumentation tracking retry attempts, server-provided Retry-After values, sleep durations, error conditions, and delay sources (to be squashed into core retry commit per Taylor Blau's suggestion)

Jeff King (Peff) raises significant architectural concerns in his review:
1. Questions whether run_active_slot() is the right layer for retry delays, suggesting http_request_reauth() or run_one_slot() might be more appropriate
2. Proposes using curl's built-in CURLINFO_RETRY_AFTER (since curl 7.66.0) instead of manual header parsing, with conditional compilation
3. Identifies portability issues with date handling in tests, recommends using test-tool date
4. Advises against implementing 429 handling in legacy http-push.c and http-walker.c (WebDAV push/dumb HTTP), suggesting generic errors instead
5. Notes complexity of HTTP code and his own partial recollection of details, but provides clear alternative directions

Taylor Blau's v2 review feedback still pending resolution:
1. Questions default http.retryAfter value (-1 vs 0) given http.maxRetries=0 opt-in
2. Suggests consolidating HTTP_RATE_LIMITED error handling into shared function
3. Notes potential issues with Retry-After header parsing (handling of 0, continuation)
4. Raises concerns about run_active_slot() as retry delay location
5. Identifies style/documentation improvements (unnecessary braces, error message length, advise() usage)

Technical implementation details:
- struct slot_results gains retry_after field
- New HTTP_RATE_LIMITED (7) status code in http.h
- Configuration parsing in http_options()
- Uses trace2_data_intmax() and trace2_data_string() with trace2_region_enter/leave around sleep operations
- Maintains clean separation between core retry logic and observability layer
