HTTP 429 (rate limiting) retry support for Git's HTTP client. Series v2 from Vaidas Pilkauskas implements RFC-compliant handling of Retry-After headers with both delay-seconds and HTTP-date formats. Introduces three config options: http.maxRetries (default 0), http.retryAfter (default 0), and http.maxRetryTime (300s delay ceiling).

Core changes in v2:
- Renamed http_request_reauth() to http_request_recoverable()
- Non-blocking retry delays using slot-specific timers
- Extracted rate limit handling into handle_rate_limit_retry()
- Added http-429.sh test helper and t5584-http-429-retry.sh tests
- Comprehensive trace2 instrumentation (to be squashed per Taylor Blau)
