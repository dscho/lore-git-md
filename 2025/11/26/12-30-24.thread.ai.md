HTTP 429 (rate limiting) retry support for Git's HTTP client. Series v2 incorporates feedback from Taylor Blau on v1, with significant refactoring. Introduces three config options: http.maxRetries (default 0, opt-in), http.retryAfter (fallback delay without Retry-After header), and http.maxRetryTime (300s delay ceiling). Implements RFC-compliant handling of both delay-seconds and HTTP-date Retry-After formats.

Core changes in v2:
- Renamed http_request_reauth() to http_request_recoverable() to reflect expanded role
- Implemented non-blocking retry delays using slot-specific timers (retry_delay_seconds and retry_delay_start fields)
- Extracted rate limit handling into handle_rate_limit_retry() function
- Added new http-429.sh test helper and improved test structure
- Marked error messages for translation
- Fixed strbuf_reencode() leak by adjusting allocation size
- Added comprehensive trace2 instrumentation (second patch) tracking retry attempts, server-provided Retry-After values, sleep durations, error conditions, and delay sources

Technical details:
- struct slot_results gains retry_after field
- New HTTP_RATE_LIMITED (7) status code in http.h
- Configuration parsing in http_options()
- Uses trace2_data_intmax() and trace2_data_string() with trace2_region_enter/leave around sleep operations
- Instrumentation added at critical points: retry initiation, limit checks, sleep operations, error conditions
- Maintains clean separation between core retry logic and observability layer

Test coverage remains comprehensive in t5584-http-429-retry.sh (286 lines) with LeakSanitizer verification. Taylor Blau's v1 reviews suggested maintainability improvements which have been fully addressed in v2: code organization, non-blocking retry implementation, test helper consolidation, documentation clarity, and now complete with observability.
