HTTP 429 (rate limiting) retry support for Git's HTTP client. Series v2 from Vaidas Pilkauskas implements RFC-compliant handling of Retry-After headers with both delay-seconds and HTTP-date formats. Introduces three config options: http.maxRetries (default 0, opt-in), http.retryAfter (fallback delay without Retry-After header), and http.maxRetryTime (300s delay ceiling).

Core changes in v2:
- Renamed http_request_reauth() to http_request_recoverable() to reflect expanded role
- Implemented non-blocking retry delays using slot-specific timers (retry_delay_seconds and retry_delay_start fields)
- Extracted rate limit handling into handle_rate_limit_retry() function
- Added new http-429.sh test helper and improved test structure
- t5584-http-429-retry.sh (286 lines with LeakSanitizer verification)
- Comprehensive trace2 instrumentation tracking retry attempts, server-provided Retry-After values, sleep durations, error conditions, and delay sources (to be squashed into core retry commit per Taylor Blau's suggestion)
