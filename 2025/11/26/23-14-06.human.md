This is a discussion about the naming of operation modes for the `git replay` command's revert capability. Junio Hamano responds to Elijah Newren's concerns about potential confusion with proposed `--rebase` and `--cherry-pick` mode names.

Junio suggests that the perceived confusion stems from argument ordering rather than the names themselves. He argues that if the command's syntax placed the range being operated on near its corresponding option flag (e.g., `--cherry-pick <range>`), the naming would feel more intuitive. This continues the thread's ongoing debate about whether to use technical terms (`--onto`/`--advance`) or operation names (`--rebase`/`--cherry-pick`) for the modes.

The exchange highlights a key design tension: balancing technical precision against user familiarity. While Elijah worries the operation names could mislead about what's being modified, Junio implies the issue might be solvable through careful syntax design rather than abandoning the more familiar terms. This discussion represents one of the last open questions before the feature can be finalized.
