[PATCH] git push/pull l10n inconsistency: plumbing vs porcelain messages

Thread examines localization discrepancy between `git push` (always shows English "Everything up-to-date") and `git pull` (localized "Already up to date"). Peter Krefting reports the push message appears in builtin/send-pack.c and transport.c, both marked as stable plumbing output that shouldn't be modified. brian m. carlson responds that no actual Git tooling depends on this specific message, noting a minor English grammar correction opportunity ("up-to-date" -> "up to date") has been deferred due to hypothetical external tool dependencies. They cite precedent where localizing `rev-parse`'s "Needed a single revision" caused temporary breakage but was ultimately accepted, suggesting potential solutions like a `--plumbing` flag or using `LC_ALL=C.UTF-8` for stable output while being personally open to localization changes. Concrete examples of working translations (Spanish and French) are provided. Core tension remains between porcelain command (`git push`) needing localization and plumbing layer stability requirements, with architectural solutions being explored to reconcile these. Open questions include whether to modify the existing plumbing message (with possible breakage) or introduce new mechanisms to separate porcelain/plumbing output requirements.
