Feature and instrumentation patch completing the HTTP 429 retry support series. This final patch adds trace2 logging to monitor rate limiting behavior in production environments, building on the core retry logic from earlier patches.

The implementation introduces five new data points tracked via trace2: retry attempt counters, Retry-After header values, actual sleep durations, error conditions, and retry source (header vs config). Each is carefully placed at key decision points in the retry flow - when receiving a 429 response, calculating delays, handling errors, and during sleep periods. The trace2 regions and data points provide comprehensive visibility into retry operations while maintaining the existing error handling and user messaging.

Key technical details include:
- New trace2_data_intmax() calls for numeric metrics (attempt counts, delay values)
- trace2_data_string() for error conditions and source tracking
- trace2_region_enter/leave wrapping sleep operations
- All instrumentation scoped to the_repository
- Maintains existing error messages while adding machine-readable equivalents
- The patch touches the same http.c file modified in previous patches, adding 31 lines while removing 9 (mostly whitespace adjustments around new trace calls)

This completes the series' instrumentation story, complementing the functional retry support with observability features. The implementation shows attention to debuggability with clear event naming and coverage of all retry scenarios. Combined with the earlier memory leak fix and core retry logic, this provides a robust solution for HTTP rate limiting that's both functional and observable.
