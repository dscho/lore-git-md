Feature implementation for reference backend selection via URI syntax, with GitLab migration use case.

This cover letter introduces v2 of a series enabling reference backend selection through a `GIT_REF_URI` environment variable, following up on design discussions from v1. The key motivation is supporting zero-downtime migrations between reference backends (files<->reftable) in large repositories, specifically addressing GitLab's need to minimize blocking during migrations of repos with millions of references.

The implementation introduces URI syntax `<backend>://<URI-for-resource>` to specify both backend type and storage location, with validation for the "//" separator. The series splits into two parts: 1) refactoring ref_store creation to work with arbitrary directories, and 2) implementing the URI parsing logic in `get_main_ref_store()`. Test coverage in t1423 verifies both valid and invalid URI cases, including:
- Empty/malformed URIs
- Unknown backends
- Read/write operations across backend types
- The v2 changes focus on clarifying documentation, improving URI validation (now requiring "//"), and fixing test issues from v1. Notable improvements include making error messages translatable, better test variable handling, and more precise test descriptions.

While the technical implementation appears solid, the thread context shows ongoing architectural questions about migration workflows and whether this URI approach is the right long-term solution versus backend-specific alternatives. The patch seems production-ready for the stated GitLab use case but may need further design iteration based on community feedback about broader applicability.
