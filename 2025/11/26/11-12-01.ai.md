This is a feature patch introducing a new environment variable `GIT_REF_URI` to specify reference backends and their storage locations, addressing an asymmetry where Git already had `GIT_OBJECT_DIRECTORY` but no equivalent for references.

The patch adds `GIT_REF_URI` which follows a URI format `<ref_backend>://<URI-for-resource>`, allowing users to specify both the backend type (files or reftable) and storage location. The implementation checks this variable in `get_main_ref_store()` when initializing the repository's reference store, with proper error handling for malformed URIs. The change includes documentation updates and a comprehensive test suite (`t1423-ref-backend.sh`) that verifies error cases and cross-backend operations.

Key technical details for future reference:
- The URI parsing happens in `get_ref_store_from_uri()` which splits on ":" and validates the format
- Backend initialization is delayed until `get_main_ref_store()` because the hash algorithm isn't known earlier
- Tests cover error cases (empty URI, invalid format, unknown backend) and verify read/write operations between files and reftable backends
- The implementation maintains compatibility with worktrees by applying the specified directory to all worktree operations

The patch appears well-structured with thorough test coverage and clear documentation. It fills a genuine gap in Git's configuration options, though some might question whether the URI format is the most intuitive choice compared to separate variables for backend and path. The implementation carefully handles edge cases and maintains existing behavior when the variable isn't set.
