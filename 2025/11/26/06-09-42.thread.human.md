This thread has followed the evolution of the experimental `git-last-modified` command through multiple versions, focusing on refining its depth control behavior and documentation. The command, which tracks file modification times across commits, initially lacked depth controls before gaining a `--max-depth` option. The current v2 series makes a significant change by defaulting to non-recursive operation (depth=0) to better match user expectations for subdirectory use, while maintaining backward compatibility through explicit options.

Key participants include Toon Claes (the primary author), Patrick Steinhardt (who proposed alternative depth control approaches), and Junio Hamano (who has guided several refinements). The discussion has progressed from implementation details to comprehensive UX improvements, with recent attention to documentation consistency and option discoverability. Test coverage has been added to verify behavior with various depth settings and subdirectories.

These changes would make the behavior more intuitive while reducing code complexity.

The command remains experimental, allowing these behavior changes as it matures.
