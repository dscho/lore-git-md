This is the final patch in a series adding HTTP 429 (rate limiting) retry capabilities to Git's HTTP client. The patch adds trace2 instrumentation to monitor retry operations, completing the feature with production observability.

The instrumentation tracks key aspects of rate limit handling: retry attempt counts, server-specified delay values from Retry-After headers, actual sleep durations, and various error conditions. It also distinguishes between server-provided delays and configured fallback values. The logging is implemented through trace2's data and region APIs, adding about 30 lines of instrumentation code to the existing retry logic in http.c.

This follows the core retry implementation (Patch 1) and a memory leak fix (Patch 2) in the series. The trace2 data will help operators understand real-world rate limiting patterns and diagnose issues, particularly useful given the opt-in nature of the retry feature. The implementation appears thorough, covering all major retry scenarios and error paths while maintaining clean integration with existing HTTP error handling.
