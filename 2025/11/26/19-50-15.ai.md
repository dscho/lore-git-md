This is a feature addition to `git replay` that continues the discussion about implementing revert functionality. Siddharth Asthana responds to feedback from Elijah Newren and Phillip Wood about making `--revert` a distinct operation mode rather than a flag that combines with `--onto` or `--advance`.

The key technical points in this response are:
- Agrees to restructure the interface so users specify exactly one of `--onto`, `--advance`, or `--revert` as mutually exclusive operation types
- Explains the commit-by-commit revert approach preserves individual revert messages and cherry-pickability compared to bulk reverts
- Notes `--contained` will be restricted to only work with `--onto` mode
- Acknowledges the semantic confusion of combining `--advance` with `--revert`

The discussion shows convergence on the architectural approach while still needing to:
- Complete the test suite overhaul with realistic scenarios
- Document the tradeoffs between commit-by-commit reverts and bulk reverts via `merge-tree`
- Finalize the operation separation implementation

This email moves the design forward by accepting the operation mode separation while defending the utility of the commit-by-commit approach for certain workflows. The technical implementation will need to reflect these clarified semantics in the test suite continues to be a focus area.
