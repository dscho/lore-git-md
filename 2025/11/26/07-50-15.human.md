Localization issue in `git push` status message.

Peter Krefting points out that while `git pull` shows localized messages when there are no changes to fetch, `git push` always displays "Everything up-to-date" in English. This appears intentional - the string is marked in the source code with comments indicating it's stable plumbing output that shouldn't be modified or localized.

The email asks how to resolve this inconsistency, suggesting there may need to be a separation between the plumbing command (which needs stable English messages) and the porcelain `git push` command (which could be localized). The author is looking for guidance on which underlying plumbing command would need to maintain the stable output, allowing the user-facing message to be localized.

This appears to be a genuine usability concern for non-English users, though any solution would need to carefully consider backward compatibility with tools that might parse the plumbing output. The question is well-framed and shows the author has done some initial investigation into the codebase.
