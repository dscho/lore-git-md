Phillip Wood raises concerns about the usefulness and implementation of the `--revert` option in `git replay`. This is a follow-up in the ongoing discussion about adding server-side revert capability to Git.

Wood questions the practical use case for updating a feature branch with reverted commits rebased onto main, pointing out that the test case produces empty revert commits due to the test setup. He suggests the current implementation may not be realistic and proposes alternative approaches: either making `--revert` a separate mode that works like `--advance` but with reverts, or automatically reversing the commit order to minimize conflicts.

The email also identifies a bug in the revert message formatting that wasn't caught by the current tests. Wood suggests using `test_commit_message()` for more robust verification. His feedback indicates the patch needs more work on both the conceptual design (clarifying the use case) and implementation details (test coverage and message formatting) before it can move forward.
