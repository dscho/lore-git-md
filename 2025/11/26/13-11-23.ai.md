This is a technical discussion about the URI syntax for specifying reference backends, part of the ongoing ref storage backend selection thread. The email focuses on clarifying the proposed URI format for backend specification, particularly around how to handle filesystem paths versus more general resource URIs.

Toon Claes responds to Junio Hamano and Karthik Nayak's discussion about whether the path component should be treated as a filesystem path or a full URI. Junio had suggested the format `<ref_backend>:<URI-for-resource>` to better accommodate non-filesystem backends, which Karthik agreed was a clearer formulation. Toon notes they don't have a strong preference on format but wants consistency, mentioning Patrick Steinhardt's parallel work on pluggable object databases using a similar `<backend_type>://<URI>` syntax.

The key question raised is whether to make the filesystem case explicit by requiring `file://` prefixes (e.g., `reftable:file://path`) or keep the current simpler `reftable://path` syntax while implicitly treating paths as filesystem locations. This touches on the thread's broader architectural questions about URI design extensibility and consistency with other Git subsystems. The discussion remains unresolved but shows the implementation is converging on a more general URI-based approach rather than being filesystem-specific.
