Bugfix for signature handling in `git replay` operations. This email from Elijah Newren acknowledges Phillip Wood's patch that fixes an oversight where `git replay` wasn't properly excluding SHA-256 GPG signature headers when copying commit metadata. The original patch added "gpgsig-sha256" to the exclusion list in builtin/replay.c to match behavior in `git commit --amend`.

The thread context shows this was already been reviewed by Phillip Wood (who noted the code duplication of this exclusion logic across three files) and approved by Junio Hamano for whom bugfixes take precedence over conflicting development work. Newren's response is a simple acknowledgment of the fix, indicating no further discussion is needed on this particular change.

The technical change remains a one-line modification to builtin/replay.c's `exclude_gpgsig` array. The broader architectural question about centralizing signature exclusion logic (currently duplicated in builtin/commit.c, builtin/replay.c and sequencer.c) remains open but isn't addressed in this email. The patch appears ready for merging with maintainer approval already secured.
