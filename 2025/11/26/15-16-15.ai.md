This is a refactoring patch that's part of the ongoing reference storage backend selection work. It extracts the core logic from `get_main_ref_store()` into a new `get_ref_store_for_dir()` function to support creating ref_stores for arbitrary directories, which will be needed for the URI-based backend selection mechanism.

The patch is a straightforward code reorganization that:
1. Takes the ref_store initialization logic from `get_main_ref_store()`
2. Moves it to a new helper function that accepts explicit dir and format parameters
3. Updates `get_main_ref_store()` to use this helper

Junio Hamano notes this appears to be preparation for the REF_URI work, where the dir parameter would correspond to the path component in the URI syntax. The change is a clean no-op refactoring that maintains all existing behavior while making the code more flexible for future needs.

This is part of the v2 series that's already addressed several rounds of review feedback and has comprehensive test coverage. The patch itself is small (13 lines changed) and focused, with no behavior changes - just better organization to support the URI-based backend selection work.
