This is a feature patch series adding HTTP 429 (rate limit) retry support to Git's HTTP client. The series comes from Vaidas Pilkauskas and consists of three patches that together provide a configurable solution for handling rate-limited HTTP responses from Git servers.

The main patch introduces three new configuration options to control retry behavior when servers respond with HTTP 429 (Too Many Requests). The implementation supports RFC-compliant Retry-After headers and includes safeguards against excessive delays. The feature is opt-in (disabled by default) to maintain backward compatibility. The series also includes a memory leak fix that became more apparent with the new functionality, plus trace2 instrumentation for monitoring retry operations.

The patch appears well-considered, with thorough test coverage (a new 429-line test script) and clear documentation of the new config options. The author notes this builds on prior work that attempted to add retry support for 50x errors, raising the question of whether those should be included here as well.

This seems like a practical quality-of-life improvement for users interacting with rate-limited Git servers, particularly in CI/CD environments. The implementation looks solid and the opt-in design makes it low-risk to merge. The most notable discussion point may be whether to expand the retry support to other HTTP error codes as suggested in the cover letter.
