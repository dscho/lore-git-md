This is a bugfix patch for the `git replay` command, addressing an oversight in commit signature handling. The patch ensures `replay` properly excludes both `gpgsig` and `gpgsig-sha256` headers when copying commit metadata, matching the behavior of `git commit --amend`.

The change is straightforward - adding "gpgsig-sha256" to an exclusion list in builtin/replay.c that already handled the basic "gpgsig" case. Phillip Wood notes this duplicates similar logic found in builtin/commit.c and sequencer.c, suggesting future work could centralize this exclusion list.

The patch is based on maint for potential backporting, though it conflicts with an in-progress branch (ps/history) that moves this code. The author offers to rebase if backporting isn't deemed necessary. The change is small (1-line diff) and clearly motivated by maintaining signature validity when replaying commits.
