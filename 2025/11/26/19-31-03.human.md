This is a follow-up in the ongoing discussion about adding revert capability to `git replay`. Siddharth Asthana responds to Junio Hamano's test failure report from the previous patch submission.

The key issue was that some tests were failing because they expected output from `git replay` that wasn't being produced in the default configuration. Siddharth explains this was due to a mismatch between the test expectations (written for `--ref-action=print` behavior) and the patch's default behavior (using atomic ref updates which produce no output).

He indicates the test suite has been fixed in the upcoming v2 by either:
1. Explicitly using `--ref-action=print` when output is needed, or
2. Checking ref state directly rather than parsing stdout

This appears to be a straightforward test suite adjustment rather than a fundamental problem with the revert functionality itself. The response suggests progress is being made on the technical implementation, though broader design questions about the feature's structure (as noted in the thread summary) remain open for discussion.
