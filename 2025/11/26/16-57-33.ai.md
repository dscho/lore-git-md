This is a review response in the `git-last-modified` documentation thread, focusing on the NUL termination handling in patch 1. Junio C Hamano raises several technical points about the implementation approach for the `-z` flag documentation.

The review questions why the patch moves NUL termination handling from `rev.diffopt.line_termination` to a new `line_termination` field in the `last_modified` struct, suggesting this architectural change needs better justification. Hamano notes the current implementation is suboptimal because while it introduces a configurable termination character via `LAST_MODIFIED_INIT`, the output logic still hardcodes `\n` and `\0` rather than using the configured value.

He proposes an alternative approach using a simple boolean `null_termination` flag instead of the current integer field, which would simplify the implementation by:
- Removing the need for `LAST_MODIFIED_INIT`
- Converting the `OPT_SET_INT` to a simpler `OPT_BOOL`
- Making the output logic more straightforward by directly toggling between newline and NUL

The review doesn't reject the patch outright but identifies clear areas for improvement in both implementation and commit message explanation.
