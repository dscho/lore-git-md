This is a localization (l10n) issue regarding inconsistent behavior between `git push` and `git pull` when no changes need to be pushed/pulled.

Peter Krefting reports that while `git pull` shows a localized "Already up to date" message, `git push` always displays the English "Everything up-to-date" message. The investigation reveals this string appears in the codebase twice (in builtin/send-pack.c and transport.c), both marked with comments indicating they're considered stable plumbing output that shouldn't be modified or localized.

The core question is how to reconcile the user-facing porcelain command (`git push`) needing localization with the underlying plumbing commands' stability requirements. Krefting asks for guidance on which plumbing command would need to maintain the stable English output, allowing the porcelain layer to provide localized messages. This appears to be a long-standing inconsistency, as evidenced by the code comments protecting these strings from modification.

The patch doesn't propose a specific solution but rather seeks architectural guidance on how to properly separate the concerns between stable plumbing output and user-friendly porcelain messages in this case. The issue touches on Git's fundamental design principles around plumbing/porcelain separation and internationalization support.
