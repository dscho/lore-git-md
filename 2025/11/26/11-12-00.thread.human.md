This thread introduces a refactoring of the refs subsystem to support creating ref_stores for arbitrary directories, not just the main repository's $GIT_DIR. The first patch, which starts the series, extracts the ref_store creation logic from `get_main_ref_store()` into a new helper function `get_ref_store_for_dir()`. This generalized version takes a repository, directory path, and storage format as parameters while maintaining all existing behavior for the main ref_store case.

The change is cleanly implemented with minimal code churn (10 lines added, 3 removed) and preserves debug wrapper functionality. It affects both files and reftable backends since it operates at the abstract ref_store level. While the immediate patch doesn't reveal the specific use case, it clearly lays groundwork for future work with alternate reference directories. The change follows established patterns and appears uncontroversial in its current form.
