Refactoring patch for reference storage backend selection.

This is a preparatory patch in the ongoing effort to support reference storage backend selection via URI syntax. Junio Hamano notes it appears related to the `REF_URI` work, where the directory parameter would correspond to the path component in URIs like `<backend>:<path>`. The change extracts the ref_store creation logic from `get_main_ref_store()` into a new `get_ref_store_for_dir()` function that can handle arbitrary directories, not just the main repository path.

The refactoring looks clean and focused - it simply moves existing code into a more flexible function while maintaining identical behavior for the main repository case. This appears to be groundwork for upcoming patches that will implement the actual URI-based backend selection functionality discussed in the thread. The change is small (13 lines total) and well-contained to `refs.c`.

This patch seems uncontroversial and aligns with the thread's technical direction. It doesn't yet implement any of the debated URI syntax options but provides necessary infrastructure for whatever format is ultimately chosen. Reviewers have already given positive feedback on the architectural approach in previous discussion.
