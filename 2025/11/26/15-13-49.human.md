Bugfix discussion regarding `:(optional)` path handling in Git config.

Jeff King (Peff) responds to Junio Hamano's explanation of the current design for handling `:(optional)` paths in Git config. While agreeing that the current implementation enables useful system-wide configuration patterns, Peff points out that it prevents an alternative workflow where users might want to completely override system defaults with their own optional paths.

The discussion highlights two competing approaches:
1. Junio's system-wide pattern where `/etc/gitconfig` can define both a mandatory system path and an optional user override
2. Peff's observation that this prevents users from completely opting out of system defaults when they want to use only optional local paths

Peff notes this is somewhat theoretical since neither workflow is commonly used in practice, and suggests the issue might be better addressed by improving Git's config system to properly support unsetting variables. The exchange shows maintainers carefully considering edge cases in config handling while acknowledging the current solution works for most real-world scenarios.

This continues the thread's progression from bug report to design discussion, now focusing on whether the current behavior should be considered final or if there are remaining use cases to address. The tone remains constructive, with clear technical points being made on both sides.
