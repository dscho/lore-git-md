Final approval for documentation warning about `--committer-date-is-author-date`. Phillip Wood gives his sign-off on Kristoffer Haugsbakk's v2 patch, which adds strong warnings to both `git-am` and `git-rebase` documentation about how this option can violate Git's timestamp ordering assumptions.

This concludes a thread that examined the option's original 2009 rationale (creating consistent commit IDs when applying patches via email) and found it fundamentally flawed. The final version uses WARNING callout boxes and neutral "override" terminology while removing references to "legitimate uses" and "clock skew". The documentation now clearly states that history-walking machinery expects non-decreasing commit timestamps and prompts users to reconsider their need for this option.

With Johannes Sixt's earlier approval and now Phillip Wood's acknowledgment, this change appears ready for merging. The patch represents a consensus approach that warns users about the technical risks without fully deprecating the option, following Junio Hamano's "long rope" philosophy.
