This is a follow-up to Junio Hamano's "What's cooking" status update, pointing out an authorship discrepancy in the fast-import signature stripping patch. Christian Couder notes that while he originally authored the patch series (which adds a `--strip-if-invalid` mode to `git fast-import` for handling invalid cryptographic signatures during history rewriting), the commit now shows Junio as the author in the Git repository.

The patch itself addresses a practical issue where tools like `git filter-repo` can invalidate commit signatures during history rewriting operations. The series includes both the new fast-import mode and some refactoring of commit verification code. While the technical content appears sound and the use case is clearly explained, this email focuses on the metadata issue rather than the technical merits. The patch was previously marked for merging to 'next' in Junio's status update.
