This is a bugfix for `git replay`'s handling of commit signatures, following up on a thread about incomplete signature header exclusion. Junio Hamano weighs in on Phillip Wood's patch that adds "gpgsig-sha256" to the list of excluded headers when copying commit metadata during replay operations, matching the behavior of `git commit --amend`.

The patch itself is minimal (a one-line change to builtin/replay.c) but addresses a real issue where signature validity could be compromised. Phillip had noted this duplicates similar logic in two other files (builtin/commit.c and sequencer.c) and suggested future refactoring to centralize the exclusion list. He also mentioned potential conflicts with Patrick Steinhardt's ongoing ps/history branch work.

Junio's brief response indicates he prioritizes bugfixes over new development, implying this should move forward despite the conflicts. The patch appears well-justified and narrowly scoped, though the broader code duplication issue remains unaddressed for now. This seems ready to proceed, with any rebasing needs to be handled if backporting is deemed unnecessary.
