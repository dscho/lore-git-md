This is a follow-up in the security fix thread for Git's attribute macro expansion system, where Jeff King (Peff) responds to Patrick Steinhardt's suggestion about adding hard limits to the iterative solution.

The email shows consensus forming around the iterative approach to prevent stack overflow, with Peff agreeing that while hard limits could be added, they're not strictly necessary given the existing protections. Peff also suggests potentially reducing the maximum attribute file size from 100MB to 10MB as an additional safeguard, though he leaves this as an open question. The tone is collaborative, with Peff explicitly welcoming Patrick to implement limits if desired while indicating he won't pursue that path himself. 

Key technical context maintained from previous discussion includes: the security implications of converting stack overflow risk to heap exhaustion, the existing 100MB attribute file limit (commit 3c50032ff5), and Git's general philosophy of relying on OS-level resource limits rather than application-level restrictions.
