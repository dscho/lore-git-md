This is a technical refinement in the ongoing discussion about adding committer identity control to `git commit`. ZheNing Hu responds to Jeff King's suggestion about matching author and committer identities, proposing a more elegant `--user` parameter that would set both author and committer simultaneously, rather than the more verbose `--author`/`--committer` combination or Jeff's suggested `--committer-is-author` flag.

The exchange shows the discussion maturing toward finding the most ergonomic interface for correcting commit metadata, with:
- Recognition that single-commit corrections (via `--amend`) need a cleaner solution than environment variables
- Exploration of different flag naming approaches for setting both identities
- Continued distinction between this use case and bulk operations (which belong in `git rebase`)

The proposal appears technically sound and focused on improving a real pain point in Git's user interface. The discussion remains productive, with participants working toward consensus on the best API design for this narrow but legitimate use case.
