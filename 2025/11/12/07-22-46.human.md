This is a discussion email in the ongoing thread about adding a 'strip-if-invalid' mode to `git fast-import`'s `--signed-commits` option. Christian Couder responds to Elijah Newren's earlier email that provided additional motivation for the feature from `git filter-repo` use cases.

The key points in this response are:
1. Christian agrees with Elijah's analysis that fast-import is the only place in the pipeline that can properly validate signatures after history rewriting.
2. He considers but rejects an alternative approach where fast-export would include unsigned OIDs, noting this could allow invalid signatures to slip through and would require format changes.
3. Christian maintains that the current approach of signature validation and stripping at import time is what most users would expect, even if other strategies might be useful in some cases.

The email doesn't introduce new technical changes but reinforces the design decisions behind the patch series while acknowledging potential alternatives. The discussion continues to explore the best way to handle signed commits during history rewriting operations.
