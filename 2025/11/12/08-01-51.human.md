This is a bugfix patch addressing a memory safety issue in the pack-bitmap subsystem, specifically in how incremental midx bitmaps handle name-hash lookups. The patch is part of a larger series fixing ASan (AddressSanitizer) findings.

The core issue is that when accessing name-hash caches in incremental midx bitmaps, the code was incorrectly assuming all hashes were in a single contiguous array. In reality, incremental bitmaps split the hashes across multiple bitmap_index structs. The existing code could read out-of-bounds memory, though this was masked by mmap behavior in normal builds. The problem becomes visible when building with NO_MMAP=1 and SANITIZE=address.

Jeff King's solution introduces a new `bitmap_name_hash()` helper that properly walks the chain of bitmap_index structs to find the correct hash slice for a given position. The patch includes bounds checking and BUG() assertions for invalid states. While the bug was found through ASan testing, the author notes this likely caused incorrect hash values even in non-ASan builds.

The patch is well-motivated and appears technically sound, addressing a real memory safety issue in newer bitmap functionality. The author acknowledges the incremental bitmap code remains under-tested overall, but considers this fix important enough to submit now while leaving broader test improvements for future work. This seems reasonable given the clear safety implications of the current behavior.
