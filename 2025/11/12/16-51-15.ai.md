Maintainer follow-up on signature stripping in fast-import.

Junio C Hamano clarifies his earlier concern about cascading signature invalidation - he wasn't proposing an optimization as Christian Couder had interpreted, but rather questioning whether the feature remains useful if most signatures would need to be stripped anyway due to downstream effects. However, he acknowledges that Elijah Newren's explanation of the broader use case (selective signature preservation during history rewriting) addresses this concern sufficiently for now.

The exchange reveals an important technical nuance - even when only some signatures are invalid, the resulting history rewrite may invalidate all subsequent signatures due to changed parent relationships. While the current implementation doesn't handle this cascading effect, Hamano seems satisfied that the feature still has value in the context Newren described, where users want to preserve older valid signatures while rewriting recent history.

This moves the discussion forward by resolving the apparent misunderstanding about optimization versus fundamental usefulness, while leaving open the deeper question of how to handle cascading invalidations in non-linear histories - a complexity Couder acknowledges would require more sophisticated tracking. The maintainer's conditional approval ("OK as long as...") suggests the series may proceed while these edge cases remain for future consideration.
