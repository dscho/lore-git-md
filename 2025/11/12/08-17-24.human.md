This is a technical discussion about ASan (AddressSanitizer) behavior with mmap() in Git's test suite, specifically regarding Patch 3 of Jeff King's 9-part ASan fixes series.

Collin Funk responds to Jeff's patch that enables NO_MMAP for ASan builds by default, pointing out that modern compilers (both GCC 15.2.1 and Clang 21.1.4 in his tests) do appear to have ASan interceptors for mmap() that catch out-of-bounds access. He references a 2023 LLVM commit that added this interceptor, suggesting Jeff's observed behavior might be due to using an older compiler.

The test case Collin shares demonstrates that current compilers do detect mmap boundary violations through ASan, producing SEGV reports. This raises the question of whether NO_MMAP is still necessary for ASan builds with modern toolchains, though Jeff's original rationale about page boundary detection limitations remains valid. The exchange highlights an implementation detail that could affect the series' approach to memory safety testing.
