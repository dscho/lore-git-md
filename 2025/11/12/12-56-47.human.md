This is a bugfix for the new `git last-modified` command, which was recently merged to 'next' and is slated for inclusion in the upcoming v2.52 release. Toon Claes is advocating for its inclusion by pointing out that it not only performance issues but also correctness problems in the current implementation.

The patch fixes inconsistent results where `git last-modified` would sometimes return different commit hashes for the same file compared to `git log --max-count=1`. The example shows `pkt-line.h` getting different last-modified commits depending on whether it's queried directly or as part of a full scan. The new implementation makes these results consistent while also being faster.

Toon emphasizes this should be considered a bugfix (not just an optimization) since it corrects wrong behavior, making it release-worthy. This would be the first release containing this subcommand, so fixing its behavior before wider adoption seems prudent. The patch has already gone through multiple iterations (v3 and v4) and testing.
