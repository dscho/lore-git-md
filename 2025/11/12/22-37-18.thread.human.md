This thread addresses a bug in Git's HTTP authentication handling that affects filtered clones (`--filter=blob:none`). The issue occurs when using remote-curl with authenticated servers: while the commit history retrieval succeeds, subsequent blob requests fail with 401 errors because probe_rpc() wasn't including authentication headers. Aaron Plattner originally reported the problem with detailed trace logs showing the failure sequence.

The solution is a minimal 2-line change adding `http_append_auth_header()` to probe_rpc() in remote-curl.c, following existing authentication patterns. While the issue was particularly visible with git-credential-msal and Bearer tokens, the fix applies more broadly. Lucas De Marchi has tested and confirmed the solution works (Tested-by). Patrick Steinhardt reviewed the patch, noting it matches existing auth handling in post_rpc() and suggesting adding a test case based on t5563-simple-http-auth. The patch explicitly leaves HTTP_REAUTH cases (token expiration scenarios) for future work, focusing only on the immediate header-inclusion issue. This is a well-contained fix for a specific but impactful authentication failure in filtered clone operations.
