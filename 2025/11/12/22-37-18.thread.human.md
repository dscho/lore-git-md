This thread addresses a bug in Git's HTTP authentication when handling large requests through `remote-curl`. The issue occurs during filtered clones (`--filter=blob:none`) where initial authentication succeeds for commit history, but subsequent blob downloads fail with 401 errors because authentication headers weren't being passed in `probe_rpc()` requests.

The proposed fix is a minimal 2-line change to `remote-curl.c` that adds `http_append_auth_header()` to `probe_rpc()`, ensuring credentials are properly included. The patch demonstrates the problem using `git-credential-msal` and focuses specifically on cases where valid tokens exist but weren't being reused. While it doesn't address token expiration scenarios (which would require HTTP_REAUTH handling), it closes a clear authentication gap in the HTTP transport code for the common case of filtered clones. The change follows existing auth handling patterns and appears well-justified by the reproduction case.
