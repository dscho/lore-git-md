This thread addresses a bug in Git's HTTP authentication where filtered clones (`--filter=blob:none`) fail when using token-based authentication. The issue occurs because the `probe_rpc()` function in remote-curl.c wasn't properly including authentication headers for subsequent requests after the initial handshake, causing 401 errors during blob fetches. The fix is straightforward - a 2-line change to mirror the auth handling already present in `post_rpc()`.

While the problem was initially observed with git-credential-msal and Bearer tokens, the discussion revealed this is specifically a Bearer token issue since curl automatically handles Basic auth. Patrick Steinhardt reviewed the change and suggested adding test coverage, which Aaron Plattner proposed implementing by creating a large test repository (2000 branches) with a dummy Bearer token helper. The group confirmed this would effectively test the fix without performance concerns.

The conversation also touched on broader HTTP authentication design questions, particularly around whether to use curl's `CURLOPT_XOAUTH2_BEARER` option (as imap-send.c does) versus the current header-based approach, though this remains an open consideration. The immediate focus is on finalizing test coverage before submitting a v2 patch with both the fix and verification. Lucas De Marchi has already tested and confirmed the fix works (Tested-by). The discussion highlights the nuanced interaction between Git's authentication handling and curl's built-in mechanisms.
