This thread addresses a bug in Git's HTTP authentication during filtered clones (`--filter=blob:none`), where initial authentication succeeds for commit history but subsequent blob requests fail with 401 errors due to missing auth headers in `probe_rpc()` calls. The issue was particularly noticeable when using `git-credential-msal`.

Aaron Plattner originally reported the problem with detailed trace logs showing the authentication failure sequence. The fix, a minimal 2-line addition to `remote-curl.c`, ensures credentials are included in `probe_rpc()` calls by adding `http_append_auth_header()`. While the solution specifically helps the Bearer token flow, it isn't limited to that method. Lucas De Marchi has tested and confirmed the fix works, adding a Tested-by tag. The change follows existing auth handling patterns and addresses the immediate issue, though HTTP_REAUTH cases remain for future work. The patch is focused and well-contained, solving a clear pain point in filtered clone operations with authenticated servers.
