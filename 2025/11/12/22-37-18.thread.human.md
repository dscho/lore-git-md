This thread addresses a bug in Git's HTTP authentication that affects filtered clones (`--filter=blob:none`). The issue occurs in `remote-curl.c` where initial authentication succeeds for commit history fetches, but subsequent blob requests fail with 401 errors because the `probe_rpc()` function wasn't including authentication headers. 

The solution is a focused 2-line change adding `http_append_auth_header()` to `probe_rpc()`, mirroring the existing auth handling in `post_rpc()`. While the problem was demonstrated with git-credential-msal and Bearer tokens, the fix applies to all HTTP authentication methods. Patrick Steinhardt reviewed the change, confirming it follows existing patterns while suggesting a test case could be added based on `t5563-simple-http-auth`. 

Aaron Plattner provided detailed trace logs showing the authentication failure sequence in real-world filtered clone operations. The patch deliberately addresses only the immediate credential reuse issue, leaving broader HTTP_REAUTH handling (which depends on the `http_auth.multistage` flag) for future work. Lucas De Marchi has tested and confirmed the fix works (Tested-by). This is a minimal but important fix for a specific pain point in the HTTP transport layer.
