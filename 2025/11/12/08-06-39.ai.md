This is patch 6/9 in a series addressing ASan findings, focusing on memory safety in fsck's identity parsing. The patch replaces `strcspn()` usage in `fsck_ident()` with explicit character-by-character iteration when parsing author/committer lines.

The change addresses a subtle safety concern: while the current code works (relying on a known newline in the buffer to prevent overruns), it triggers ASan's strict_string_checks due to non-NUL-terminated buffers. The new implementation makes the parsing logic more explicit and self-contained, removing dependence on string.h functions while maintaining identical validation rules.

Key technical changes:
- Replaces two `strcspn()` calls with explicit loops checking for `<`, `>`, and `\n`
- Maintains all existing error conditions (FSCK_MSG_BAD_NAME, FSCK_MSG_BAD_EMAIL etc.)
- Preserves the buffer safety established in 8e4309038f
- Adds explicit bounds checking via `p >= ident_end`

The patch appears well-considered, with the author noting this both resolves the ASan warning and arguably improves code clarity by localizing the parsing logic. It builds on the fsck buffer handling improvements started in patch 5 of this series. The change is focused and maintains the same behavior for valid inputs while being more robust against malformed data.
