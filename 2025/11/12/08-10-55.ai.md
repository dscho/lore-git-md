This is the final patch in Jeff King's 9-part series addressing ASan (AddressSanitizer) findings in Git. The patch enables ASan's strict string checking option by default in the test suite, which verifies that strings passed to functions expecting NUL-terminated input are properly terminated.

The strict checking helped identify two issues: a real problem in cache-tree.c's strtol() parsing (already fixed in patch 4 of this series) and some false positives in fsck_ident() that nevertheless led to cleaner code (addressed in patches 5-8). While the option can produce false positives, the author argues its benefits outweigh the costs since the test suite now runs cleanly with it enabled.

The change is minimal - a single line added to t/test-lib.sh to set strict_string_checks=1 in ASAN_OPTIONS. This builds on the series' earlier work hardening string parsing and memory safety, particularly the cache-tree and fsck improvements. The patch serves as both a test suite enhancement and a validation mechanism for the series' other changes.

Key technical details for future reference:
- Enables ASan's strict_string_checks globally in tests
- Validates NUL-termination for string functions
- Follows from cache-tree.c strtol fixes (patch 4)
- Relates to fsck_ident() hardening (patches 5-8)
- Single-line change to test-lib.sh
- No behavior change outside test environment

The patch appears straightforward and well-justified, serving as a capstone to the series by ensuring future string handling issues would be caught by ASan during testing. It doesn't introduce new functionality but strengthens the test infrastructure based on lessons from the series' other fixes.
