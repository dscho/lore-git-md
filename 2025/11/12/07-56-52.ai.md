This is a refactoring patch that's part of a 9-part series addressing ASan findings. It marks an unused parameter in the `git_munmap()` compatibility function with the UNUSED macro to silence compiler warnings when building with DEVELOPER=1 and NO_MMAP=1.

The change is straightforward - the `length` parameter in `git_munmap()` isn't actually used (the function just calls `free()` on the pointer), but needs to be present to match the munmap() interface. The patch adds the UNUSED annotation to prevent -Wunused-parameter warnings.

The author notes this raises the question of whether NO_MMAP is actually being tested much, since this warning wasn't caught before. The change is simple and non-controversial, just marking an unused parameter as such. It's the first in a series that gets progressively more substantive, with later patches addressing actual memory safety issues found by ASan.

Key technical details:
- Modifies compat/mmap.c
- Adds UNUSED macro to length parameter in git_munmap()
- Only affects builds with both DEVELOPER=1 and NO_MMAP=1
- Part of broader ASan-related cleanup series

The patch appears well-justified and properly scoped for its position as the series opener - a simple warning fix that doesn't change behavior.
