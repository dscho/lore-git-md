This is a bugfix for the new `git last-modified` command, addressing inconsistent output when files are specified via grep versus direct path. Junio Hamano responds to Toon Claes' request to include the fix in the upcoming v2.52 release, which will be the first release containing the `last-modified` subcommand.

Junio initially planned to exclude the patch since it missed the usual pre-rc1 merge window, but Toon clarifies this isn't just an optimization - it fixes correctness issues where `git last-modified` could return different commit hashes than `git log --max-count=1` for the same file, particularly when using grep output. The patch ensures consistent results while maintaining the performance improvements.

The discussion reveals some communication gaps - Junio notes the original patch's test case didn't clearly demonstrate the bug, and the importance of the fix wasn't emphasized in the cover letter. Toon now makes a stronger case for inclusion by showing concrete examples of the inconsistent behavior being fixed. This appears to be a legitimate bugfix that improves the reliability of a new feature in its debut release.
