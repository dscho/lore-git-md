This is a bugfix for the new `git last-modified` command that was recently merged to 'next'. Toon Claes is advocating for its inclusion in the upcoming v2.52 release, clarifying that the patch not only optimizes performance but also fixes correctness issues in the command's output.

The key issue is that the unpatched version produces inconsistent results compared to `git log --max-count=1` for the same file. Toon provides a concrete example showing how `git last-modified` would return different commit hashes for pkt-line.h depending on whether the file was specified directly or found via grep output. The patched version aligns these results with `git log`'s output while also being faster.

The patch was previously submitted as part of a v4 series (referenced via lore.kernel.org link) and has been cooking in 'next' since November 3rd. Toon emphasizes this should be considered a bugfix rather than just an optimization, making it release-worthy - especially since v2.52 will be the first release to include the `last-modified` subcommand at all. The fix affects the path-following algorithm that determines modification history, ensuring both speed and accuracy when tracking file changes through the commit history.
