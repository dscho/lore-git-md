Documentation follow-up noting an inconsistency in option naming.

Patrick Steinhardt responds to Junio Hamano's documentation patch that updates "work tree" to "working tree" in `git-rev-parse`'s manpage. While agreeing with the terminology change, Patrick points out that the `--is-inside-work-tree` option name itself still uses the old terminology and should ideally be `--is-inside-working-tree`. He suggests this could be addressed with an alias but doesn't consider it urgent enough to block the current documentation-only patch series.

The email confirms the series is otherwise good and appreciates the consistency improvements. This is a minor observation about a lingering inconsistency rather than a substantive critique - the core documentation updates are uncontroversial and the thread shows maintainer alignment on standardizing to "working tree" terminology. The option naming issue could be addressed separately if someone wants to pursue it, but doesn't affect the current mechanical documentation updates.
