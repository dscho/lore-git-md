Feature and bugfix patch in Junio Hamano's ongoing whitespace handling series (11/12). This patch completes the diff-side implementation of incomplete-line whitespace detection by making `git diff` highlight missing newline markers as errors when configured via `core.whitespace=incomplete-line`.

The change makes "\ No newline at end of file" annotations visually stand out (colored as whitespace errors) when the incomplete-line rule is active, and teaches `git diff --check` to report these as errors. The implementation builds on previous refactoring in the series to handle this consistently in the diff output generation.

New test cases verify the behavior for various edge cases: files missing newlines in both old/new versions, partial fixes, and new incomplete lines introduced in changes. The patch also updates existing color output tests to include incomplete-line scenarios.

This appears to be a well-considered addition to the whitespace handling series, with thorough test coverage. It completes the symmetric treatment of incomplete lines that was partially implemented in earlier patches, making the feature fully operational on the diff side (following patch 10/12's apply-side implementation).
