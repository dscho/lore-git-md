This is a follow-up discussion in the security fix thread for Git's attribute macro expansion system.

Patrick Steinhardt responds to Jeff King's earlier message about converting the recursive macro expansion to an iterative approach. While Patrick had initially leaned toward enforcing a hard recursion limit, he now agrees with Jeff's approach of first converting to iteration without adding new limits. He notes that if abuse does occur in practice, limits could be added later.

The discussion shows consensus forming around the iterative solution as the immediate fix for the stack overflow vulnerability. Patrick suggests updating the commit message to document this decision process, though no specific technical changes to the patch are proposed. The question of whether to reduce Git's maximum attribute file size from 100MB to 10MB remains open but is not blocking the current fix.

This email represents the tail end of the technical discussion, with both parties now aligned on the solution approach. The patch appears ready to move forward with the iterative implementation as proposed.
