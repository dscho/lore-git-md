This is patch 5 in a 9-part series addressing ASan (AddressSanitizer) findings, focusing on memory safety fixes in Git's fsck functionality. The patch specifically targets `fsck_ident()`, which parses author/committer lines in commit objects.

The patch replaces unsafe string operations with explicit bounds checking. Previously, the code used `strchrnul()` to find newlines, which could theoretically read past buffer bounds if the input wasn't properly validated. The new version requires callers to pass buffer boundaries and uses `memchr()` for safe searching, adding a `BUG()` assertion if the expected newline is missing (which would indicate a caller violated the validation contract).

The change is well-justified by the commit message, which explains both the current safe-but-confusing behavior and why the new approach is better. The patch maintains the same functionality while making the memory safety guarantees more explicit and verifiable. This fits well with the series' overall goal of hardening Git against memory safety issues.
