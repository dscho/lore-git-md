This is a technical discussion about Patch 3 in Jeff King's ASan series, specifically addressing whether modern compilers already handle mmap() bounds checking under ASan. Collin Funk provides evidence that recent GCC (15.2.1) and Clang (21.1.4) versions do detect mmap overflows via ASan, contrary to the patch's assumption that mmap access isn't sanitized. He references a 2023 LLVM commit that introduced mmap interception for ASan.

The test case demonstrates that both compilers correctly flag an out-of-bounds write to a mmap'ed region with ASan`SEGV` detection. This suggests the `NO_MMAP` workaround in Patch 3 might be unnecessary on systems with sufficiently recent toolchains, though the original patch's rationale about page-aligned access patterns in Git's usage may still apply. The thread context shows this was considered one of the more critical patches in the series for ASan issues, so this new information could influence whether the change is needed or should be conditional on compiler version.
