This is a follow-up in the ongoing discussion about adding signature stripping to `git fast-import`. The patch series introduces a new 'strip-if-invalid' mode for signed commits, but has run into test infrastructure issue where some tests depend on SHA-256 repositories that now require Rust support (due to an unrelated change).

Christian Couder acknowledges the problem reported by maintainer Junio Hamano and confirms he will address it in the upcoming v2 of the patch series. The issue doesn't affect the core functionality (which doesn't need dual-hash interoperability) but requires test restructuring - either avoiding SHA-256 repositories entirely or making their creation part of test setup with proper prerequisites.

This email doesn't introduce new technical discussion but confirms the test issue will be fixed in the next revision. The broader thread continues to debate fundamental questions about signature validation semantics and potential alternative approaches, but those aren't advanced here. The response is brief and focused on the immediate practical blocker for the series.
