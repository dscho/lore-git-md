Security hardening follow-up in the attribute macro expansion thread.

Jeff King responds to Ben Knoble's questions about the security tradeoffs in converting the recursive attribute macro expansion to an iterative approach. The key points are that heap-based allocation is preferable to stack recursion for two reasons: heap limits are much larger (8MB stack vs potentially GBs of heap), and heap failures can be handled gracefully while stack overflows lead to crashes.

The discussion reveals some interesting constraints in Git's security model - there's already a 100MB limit on attributes files (which could likely be reduced), and macro expansion across nested directories could theoretically consume more resources. However, Git generally relies on OS-level resource limits rather than trying to police all possible resource exhaustion vectors internally.

This exchange highlights the practical reality that while the patch converts one failure mode (stack overflow) to another (heap exhaustion), the latter is both less likely to trigger and more gracefully handled. The thread continues to explore the right balance between security hardening and practical constraints, with hosting providers ultimately responsible for protecting against extreme resource consumption.
