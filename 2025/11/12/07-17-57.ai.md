This is a follow-up clarification in the ongoing security fix discussion about attribute macro expansion in Git.

Jeff King (Peff) corrects an earlier assumption about macro chaining across different `.gitattributes` files. While it was previously thought possible to create deep macro chains by defining macros in nested directories (where each level references the previous), Peff confirms that Git actually restricts macro definitions to top-level `.gitattributes` files only. This architectural choice prevents the creation of arbitrarily deep chains through file nesting, reinforcing that the primary attack vector remains within a single file's macro definitions.

The clarification is important for understanding the scope of the vulnerability being fixed - the stack overflow risk comes from deep macro expansion within a single file, not from chaining across directory levels. This aligns with the security analysis showing that triggering the issue would require "many millions or even billions" of attributes in practice. The note also implicitly supports the chosen iterative solution's adequacy, as cross-file chaining would have represented a more complex attack surface.
