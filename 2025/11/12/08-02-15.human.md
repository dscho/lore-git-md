This is a build system patch in a 9-part series addressing ASan (AddressSanitizer) findings. It changes how Git handles memory access during ASan builds to improve bug detection.

The patch forces NO_MMAP mode when building with ASan, meaning Git will read files into heap memory rather than using mmap(). This helps ASan detect out-of-bounds memory accesses that would otherwise be masked by page alignment in mmap'd regions. The author notes this was inspired by a real bug found in patch 2 of the series, where mmap's page rounding had hidden an out-of-bounds read in bitmap handling.

While NO_MMAP increases memory usage, the impact is minimal for the test suite. The change will help uncover additional memory safety issues that aren't currently caught by tests. The patch is straightforward - just a one-line Makefile addition - and builds on the series' goal of improving ASan's effectiveness across Git's codebase.

This appears to be a well-justified change that makes ASan builds more thorough at detecting memory issues, though it may slightly impact performance during testing. The patch fits logically in the series between the initial bitmap fix and subsequent fsck improvements.
