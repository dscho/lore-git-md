This is part 8 of Jeff King's 9-patch series addressing ASan (AddressSanitizer) findings, focusing on memory safety in fsck timestamp parsing.

The patch modifies `fsck_ident()` to avoid using `parse_timestamp()` (which relies on NUL-terminated strings) on potentially unterminated buffers. While the current code is technically safe (it checks for a trailing newline first), ASan's strict_string_checks mode flags this as a potential issue. The solution introduces a new helper `parse_timestamp_from_buf()` that copies digits into a temporary NUL-terminated buffer before parsing.

Jeff notes this is somewhat unsatisfying - a more thorough solution would validate all buffer accesses in fsck_ident(), but that would make the code more complex. This middle ground addresses the immediate ASan concern while leaving deeper hardening for potential future work. The change is part of the series' broader goal of making Git's memory handling more robust under ASan's scrutiny.
