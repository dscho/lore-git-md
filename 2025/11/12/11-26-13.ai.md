This is a follow-up to Patch 3 in the ASan memory safety series, adding Meson build system support for the NO_MMAP change.

Patrick Steinhardt provides a complementary change to the Meson build system that mirrors Jeff King's Makefile modification from Patch 3. The change ensures consistent behavior across build systems by adding NO_MMAP when AddressSanitizer is enabled, while maintaining the existing mmap functionality for non-ASan builds. The Meson implementation is slightly more involved, needing to handle the conditional addition of mmap.c to the source list and the checkfuncs table.

The change aligns with the thread's established technical consensus that malloc-based ASan detection is more reliable than mmap-based detection, as demonstrated by Jeff King's empirical testing showing mmap's inconsistent handling of page-sized and sub-page overflows. This maintains the series' goal of improving memory safety detection while keeping the test suite passing under SANITIZE=address.

The patch-specific discussion appears resolved, with Patrick's addition being a straightforward build system alignment rather than introducing new technical considerations. This follows the earlier validation of Patch 3's approach and doesn't raise any of the open questions from other patches in the series.
