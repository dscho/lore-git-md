This is a bugfix patch in a series addressing ASan (AddressSanitizer) findings, specifically targeting a potential buffer overread in the cache-tree parsing code. The patch replaces a `strtol()` call that could read past intended boundaries when parsing malformed index files, implementing a safer custom parser instead.

The issue arises when reading cache-tree extension entries from the index file. While the current code works fine with well-formed entries, a malicious or corrupted index could theoretically cause `strtol()` to read beyond the intended buffer. The patch introduces a new `parse_long()` helper that strictly bounds its parsing to avoid this, while maintaining the same basic functionality for valid inputs.

Jeff King notes this isn't a major security concern since index files are local, but it's still worth fixing both for correctness and to work with ASan's strict string checking mode. The change makes the parsing more robust by enforcing stricter rules about whitespace and newlines that match the documented format.

The patch is part of a larger series improving memory safety across Git, with this particular change focusing on the cache-tree subsystem. While it reimplements some `strtol()` functionality, the author justifies this as necessary given the specific constraints and notes it could potentially be generalized later if needed. The fix is verified using ASan's strict string checking mode in existing tests.
