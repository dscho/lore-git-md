Feature patch adding `--committer` option to `git commit` as a counterpart to `--author`. This v3 iteration from ZheNing Hu implements the standalone `--committer` flag approach, following earlier discussion about interface design alternatives. The patch:

1. Introduces `--committer` with identical syntax to `--author`, supporting both explicit identity strings (`Name <email>`) and pattern-based lookups in commit history
2. Refactors existing author-handling code into shared `determine_identity()` and `find_identity_by_nickname()` functions with `is_author` parameterization
3. Maintains all existing environment variable behaviors while adding the new option
4. Includes comprehensive tests covering:
   - Basic override functionality
   - Pattern matching
   - Interaction with `--amend`
   - Precedence over environment variables
   - Date handling consistency

Key technical changes include:
- New `force_committer` static variable in builtin/commit.c
- Refactored identity determination logic in `determine_identity()`
- New test cases in t/t7509-commit-authorship.sh
- Documentation updates in Documentation/git-commit.adoc

The implementation appears thorough, with careful attention to symmetry between author and committer handling. Notable differences from author handling:
- Committer dates are only set when explicitly provided in the override string
- Environment variable names differ (GIT_COMMITTER_* vs GIT_AUTHOR_*)

This addresses the previously discussed limitations of using `-c` config overrides by providing direct symmetry with the existing `--author` interface. The patch demonstrates good test coverage and maintains backward compatibility while introducing the new functionality.
