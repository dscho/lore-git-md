This is part 4 of a 9-patch series addressing ASan findings, specifically focusing on unsafe string parsing in the cache-tree code. The patch replaces `strtol()` with a custom parser when reading cache-tree extension entries from the index file, addressing two issues: potential buffer overreads from malformed index entries (though with limited security impact since the index is local), and ASan's strict_string_checks flag which would complain about the technically non-NUL-terminated buffer.

The new `parse_long()` helper implements a simpler version of strtol() that knows the specific format constraints of cache-tree entries (no leading whitespace, must end with newline) and avoids reading past the buffer bounds. While this reimplements some strtol() functionality, the author notes this is preferable to NUL-terminating a substring since the parsing rules would still need to be reimplemented to find the substring bounds.

The patch details show careful consideration of edge cases - it maintains the same overflow behavior as the original (none), enforces stricter newline termination matching the documented format, and includes analysis of the security implications (limited due to local-only index files). The change is verified using ASan's strict_string_checks in existing tests, though no new dedicated test is added due to the difficulty of constructing precisely-sized malformed index entries.

This appears to be a well-justified change that improves code safety without introducing new risks, though it does raise the question of whether a more general "strntol()" helper might be useful elsewhere in the codebase. The patch fits into the series' broader goal of hardening Git against memory safety issues found by ASan.
