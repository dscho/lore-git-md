This is part 8 of Jeff King's 9-patch series addressing ASan findings, focusing on memory safety in fsck timestamp parsing. The patch replaces direct use of `parse_timestamp()` (which internally uses `strtoumax()`) on potentially non-NUL-terminated buffers with a new helper function `parse_timestamp_from_buf()` that copies digits into a temporary buffer first.

The change avoids ASan complaints about reading past buffer bounds while maintaining the same validation logic for timestamps (overflow checking, zero-padding detection). The new helper manually copies up to 23 digits (enough for 64-bit timestamps) into a stack buffer before parsing, with explicit bounds checking against the input buffer.

Jeff notes this is a defensive change rather than fixing an actual bug - the current code is safe due to earlier newline validation, but the safety depends on subtle invariants. He suggests a more thorough hardening (explicit bounds checks on all buffer accesses) could be done later but isn't included here to keep the scope focused on ASan compatibility. The patch touches fsck.c with 19 lines added and 4 removed, introducing the new helper function while modifying the timestamp parsing logic in `fsck_ident()`. This continues the series' theme of replacing string functions with explicit buffer handling where ASan's strict checks would complain about potential overreads.
