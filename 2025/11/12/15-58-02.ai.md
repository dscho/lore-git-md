Feature proposal for committer identity control in `git commit`, part of ongoing discussion about identity override approaches.

ZheNing Hu responds to Phillip Wood's skepticism about the need for a `--committer` flag by refining the use case. The key scenario is fixing misconfigured identity information across multiple commits, where current workflows require either:
1. Multiple `git commit --amend` steps (one for author, one for committer)
2. Cumbersome environment variable setup for rebase operations

The proposed `--committer` flag would simplify this by allowing simultaneous author/committer correction through a single interface. The email includes implementation details showing:
- New `--committer` option mirroring `--author` syntax
- Nickname lookup functionality matching existing author behavior
- Comprehensive test coverage for various override scenarios
- Integration with existing date override behavior

Technical considerations from the implementation:
- Adds `force_committer` static variable in builtin/commit.c
- Introduces `determine_committer_info()` parallel to author handling
- Maintains consistency with environment variable precedence
- Handles date overrides for both author and committer simultaneously

This response shifts the discussion from abstract need to concrete workflow pain points, particularly around bulk identity correction. The implementation appears thorough but raises questions about:
- Whether this sufficiently addresses Junio Hamano's configuration-based alternative
- How this interacts with Jeff King's `--committer-is-author` proposal
- Whether the use case justifies adding another flag versus improving existing tools
