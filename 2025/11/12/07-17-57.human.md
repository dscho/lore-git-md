This is a follow-up clarification in the ongoing security fix discussion about attribute macro expansion in Git.

Jeff King (Peff) corrects his earlier speculation about macro chaining across different `.gitattributes` files. He confirms that Git only allows macro definitions at the top level, preventing the theoretical attack vector of chaining macros across directory levels. This simplifies the security analysis, as the potential attack surface is smaller than previously considered - macros can only be nested within a single file, not across the repository tree.

The clarification supports the team's consensus that converting the recursive implementation to an iterative one (using a LIFO queue) sufficiently addresses the stack overflow risk, since the worst-case scenario is now bounded by the size of a single attributes file (currently limited to 100MB) rather than being potentially amplified by directory depth. This aligns with the earlier decision that heap exhaustion from extremely large attribute files is an acceptable trade-off given Git's existing resource management approach.
