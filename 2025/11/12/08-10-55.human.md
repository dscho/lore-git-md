This is the final patch in a 9-part series addressing ASan (AddressSanitizer) findings, focusing on memory safety improvements. The series has been working through various memory handling issues detected by ASan, with each patch addressing a specific subsystem or type of problem.

Patch 9 enables ASan's strict string checking option by default in the test suite. This setting makes ASan verify that strings passed to functions expecting NUL-terminated input are properly terminated. While this can produce some false positives (like when a newline terminates parsing early), the author found it useful in catching two real issues: a potential problem in cache-tree.c's strtol() parsing and some fragile string handling in fsck_ident().

The change is minimal - just a one-line addition to test-lib.sh to turn on strict_string_checks. The patch notes that while this didn't uncover major bugs, the benefits (catching subtle issues and making code reasoning more robust) outweigh the occasional false positives. The test suite now runs cleanly with this setting enabled.

This appears to be a sensible hardening measure that builds on the previous patches' work to clean up string handling. As the final piece of the series, it provides ongoing protection against similar issues in future development. The series as a whole represents thorough work to improve Git's memory safety under ASan's scrutiny.
