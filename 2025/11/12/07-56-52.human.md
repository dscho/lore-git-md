Compatibility fix for NO_MMAP builds with developer warnings enabled.

This is the first patch in a 9-part series addressing ASan findings. It marks an unused `length` parameter in `git_munmap()` with the UNUSED macro to silence compiler complaints when building with DEVELOPER=1 and NO_MMAP=1. The change is straightforward - the author notes this compatibility code emulates mmap with malloc/free, where the length parameter isn't actually needed for freeing memory.

The patch appears clean and well-justified, though the author speculates this may indicate NO_MMAP builds aren't commonly tested with DEVELOPER warnings enabled. This is a minor preparatory change before more substantive ASan-related fixes in later patches.
