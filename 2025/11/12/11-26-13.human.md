This is a follow-up to Jeff King's patch series addressing ASan (AddressSanitizer) findings, specifically responding to patch 3 which enables NO_MMAP when building with ASan.

Patrick Steinhardt provides a complementary change to extend the NO_MMAP behavior to the Meson build system, matching the Makefile change from the original patch. The change ensures consistent memory handling between build systems when AddressSanitizer is enabled, using malloc-based detection instead of mmap for more reliable overflow detection.

The thread context shows this builds on empirical evidence that malloc-based ASan detection catches more issues than mmap-based detection, particularly for sub-page overflows. The change appears straightforward and aligns with the series' goal of improving memory safety detection.
