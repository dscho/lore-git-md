This is a follow-up discussion in the ongoing thread about adding a 'strip-if-invalid' mode to `git fast-import`'s `--signed-commits` option. Christian Couder clarifies several points raised by Junio Hamano about signature validation.

The key clarification is that the patch uses the same definition of "invalid" as `git verify-commit` - a signature is invalid if `git verify-commit` would return non-zero. Christian acknowledges this should be made clearer in the documentation and plans to add this to v2 of the patch series.

He confirms the implementation assumes availability of all necessary public keys, revocation data, and accurate clocks, just like `git verify-commit` does. Christian suggests any improvements to validation requirements should first be made to `git verify-commit` itself rather than in this feature.

Regarding Junio's concern about cascading invalidations when rewriting history, Christian agrees this could be optimized but argues the current simpler approach is better for an initial implementation, as tracking non-linear history would add significant complexity.

The response indicates this is still early in the discussion phase, with documentation clarifications planned but no major design changes yet. The exchange highlights some fundamental questions about signature validation that may need to be addressed either in this series or in related verification infrastructure.
