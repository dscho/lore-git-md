This is patch 5/9 in a series addressing ASan findings, focusing on memory safety in fsck's identity parsing. The patch tightens up fsck_ident() to explicitly require and verify newline termination, replacing strchrnul() with memchr() and adding a BUG() check if the expected newline is missing. The change enforces that callers must have validated input via verify_headers() first, making the memory safety assumptions more explicit and verifiable.

The patch modifies fsck_ident() to take an explicit buffer end pointer rather than relying on NUL-termination, matching the approach used elsewhere in fsck.c. The BUG() assertion codifies what was previously an implicit assumption from verify_headers()'s behavior. All call sites are updated to pass the buffer end pointer.

This appears to be a well-justified hardening change that makes the code's safety requirements more explicit while maintaining the same behavior for valid inputs.
