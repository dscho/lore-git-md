Jeff King's ASan memory safety series continues to progress, with Patrick Steinhardt now contributing complementary build system support. The 9-patch series addresses various memory safety issues found by AddressSanitizer, with the most critical changes (Patches 2-3) already receiving technical validation. Patch 3's approach of using malloc-based detection under ASan (rather than mmap) has been empirically shown to catch more memory issues consistently, and Patrick's new Meson build system patch ensures this behavior works across both build systems.

While the core technical approach appears settled, several open questions remain about specific implementations. The parse_long() helper in Patch 4 may need numeric overflow detection and could potentially be generalized, while some fsck changes may warrant softer validation than BUG() calls. Patrick has suggested considering a more general git_parse_int() utility based on the timestamp parsing work in Patch 8. The series remains under active review, with the test suite passing under SANITIZE=address at each step - including the newly added strict string checking in Patch 9.
