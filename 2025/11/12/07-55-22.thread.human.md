Jeff King's ASan series continues to evolve with a focused discussion on Patch 3's approach to memory safety. The thread began as a comprehensive set of fixes for ASan-detected issues, with particular attention to buffer overreads and string parsing. The latest exchange examines whether modern compilers have made the NO_MMAP workaround unnecessary for detecting bounds violations.

While Collin Funk initially suggested that recent GCC and Clang versions can catch mmap overflows via ASan, Jeff's follow-up testing reveals important limitations. Through careful test cases, he shows that mmap-based detection remains inconsistent - sometimes missing sub-page violations entirely and producing unreliable results across runs. This empirical evidence strengthens the case for keeping the NO_MMAP approach in Patch 3, as malloc-based checking provides more thorough and predictable overflow detection, especially for small buffers.

The series remains at version 1 with all patches available but still awaiting broader review. Key technical questions persist about several patches' design choices, including whether certain safety measures are overly defensive or could be implemented more elegantly. The discussion around Patch 3 exemplifies the careful tradeoffs involved - balancing detection reliability against potential performance impacts. As the thread develops, these implementation details will likely see further scrutiny from other contributors familiar with ASan and memory safety issues.
