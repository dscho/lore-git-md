This thread covers a 9-patch series addressing various memory safety issues and undefined behavior detected by ASan (AddressSanitizer). The series includes fixes for concrete bugs (like an out-of-bounds read in incremental bitmap name-hash lookups) and proactive improvements to code quality where ASan reports potential issues.

The latest patch focuses on improving test coverage by forcing NO_MMAP when building with ASan. This change helps surface memory issues that mmap's page rounding might otherwise mask, as demonstrated by the bitmap bug fixed earlier in the series. While this increases memory usage during tests, the author considers this an acceptable tradeoff given the test suite's small repository sizes. The change is implemented via a simple Makefile addition and is positioned as a proactive measure to improve testing rigor.

Key open questions include whether the NO_MMAP configuration is sufficiently tested (raised by an earlier patch), and whether some of the more subjective fsck improvements (in patches 5-8) are worth the code churn. The bitmap fix (patch 2) appears to be the most critical change in the series, addressing an actual bug in newer bitmap functionality. The series is structured to maintain test suite pass with SANITIZE=address at each step, showing careful attention to incremental safety. No reviews or acks have been posted yet, so the tradeoffs between safety and churn remain to be debated by the community.
