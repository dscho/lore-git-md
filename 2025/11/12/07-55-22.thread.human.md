This thread continues Jeff King's (Peff) work to harden Git's parsing code against memory safety issues found by ASan. The series has grown from specific fixes to include reusable parsing utilities, now adding functions to safely parse integers from non-NUL-terminated buffers. The new functions in parse.c handle bounds checking and overflow detection while following Git's bool-return convention, with comprehensive unit tests covering edge cases.

Junio Hamano has already approved the series for integration. The latest additions - parse_int_from_buf() and related functions - fill a gap where string-based parsers could cause buffer overruns. They'll be used immediately for cache-tree and fsck parsing. The implementation carefully documents its two's complement assumptions and includes thorough test coverage.

While the core work is ready, Phillip Wood's pending parse_int() refinements remain to be evaluated. The series maintains its focus on local index file safety but establishes patterns that could be reused more widely. With Junio's approval and the new utilities' solid test coverage, this represents another step toward more robust parsing throughout Git's codebase.
