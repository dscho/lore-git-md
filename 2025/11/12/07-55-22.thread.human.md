Jeff King (Peff) recently shared a 12-patch series that introduced buffer-safe parsing utilities while fixing ASan-detected issues in fsck timestamp parsing. As part of this work, he wrote unit tests using the clar framework and subsequently documented several pain points he encountered, including uninformative error messages, debugging difficulties, and CI output problems.

Phillip Wood has now responded to these concerns with a mix of workarounds and acknowledgments. For the immediate issues, he suggests using `cl_failf()` for better error context and notes an open PR that would add type-agnostic assertion macros. He also provides a concrete fix for the TAP output parsing problem (changing YAML terminators from `---` to `...`), though this still doesn't resolve the missing error messages in `prove` output. Phillip is neutral on Jeff's shell script wrapper idea, observing that the original parallel execution rationale no longer applies since clar tests run serially.

The exchange highlights real friction points in the developer experience when using clar for Git's testing needs. While some issues may be addressed by pending clar improvements, others represent deeper framework limitations. The discussion comes as the project weighs broader test infrastructure decisions, with Patrick Steinhardt having championed clar adoption but not yet weighing in on these specific concerns. The core parsing utilities work is unaffected, but the feedback may influence how the project approaches unit testing going forward.
