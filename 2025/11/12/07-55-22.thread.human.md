This thread began as Jeff King's series to address ASan findings across Git's codebase, focusing on memory safety and undefined behavior fixes. The series has evolved through two versions, with the final patch enabling strict string checking in the test suite. Junio Hamano has approved the series for integration, with all major technical discussions resolved.

A notable sub-thread emerged around Phillip Wood's suggestions to tighten validation in `parse_int()`, which handles integer parsing in various contexts. While Junio initially concluded the current implementation was acceptable, Phillip proposed two specific improvements to limit multiple minus signs and better handle empty input. Junio has now responded, agreeing that limiting to a single minus sign would be straightforward, but he raises a more fundamental question about why the cache-tree stores numbers as text at all.

Junio suggests that since the index is local (unlike object headers which need platform independence) and already has a 32-bit entry count limit, the cache-tree could use binary formats (network byte order or varint) in a new version 2 format. He outlines a backward-compatible transition path where new Git versions could ignore old text-formatted cache-trees and regenerate in the new format, with older versions continuing to work by automatically converting when writing the index.

This discussion connects to the series' broader theme of hardening parsing code but suggests a more structural solution than just fixing individual `strtol()` calls. While this tangent opens a new design direction, it doesn't block the current ASan hardening series, which remains approved for integration. The cache-tree format discussion may inform future optimization and safety work, building on the foundation established by this series.
