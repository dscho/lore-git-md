This is patch 7/12 in Junio C Hamano's series implementing comprehensive handling of incomplete-line whitespace errors (WS_INCOMPLETE_LINE). The patch refactors how rewrite diffs handle missing newlines at end of file, eliminating a special-case hack in favor of the standard incomplete-line handling path.

The change removes the DIFF_SYMBOL_NO_LF_EOF enum and its associated special handling, replacing it with proper use of the DIFF_SYMBOL_CONTEXT_INCOMPLETE path. The key technical changes include:
- Removing the static "No newline" string and its direct emission
- Modifying emit_rewrite_lines() to handle incomplete lines by:
  - Allocating and constructing temporary strings with added newlines when needed
  - Using the new emit_incomplete_line_marker() helper (introduced in patch 5/12)
  - Tracking line type via last_line_kind (from patch 4/12)
- Maintaining line counting behavior (lno_in_preimage/postimage) while changing the implementation

The patch demonstrates good technical hygiene by:
- Removing special cases in favor of unified code paths
- Building on infrastructure from previous patches in the series
- Preserving existing behavior while improving implementation
- Following the series' pattern of using sizeof()-1 for string literals
- Including appropriate memory management (xmalloc/free)

This change prepares for future whitespace error handling by ensuring rewrite diffs use the same incomplete-line code path as regular diffs. The implementation is thorough, with careful handling of memory allocation and line counting invariants. As part of the larger series, it contributes to the goal of consistent whitespace handling across Git's diff pipeline.
