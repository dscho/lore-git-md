This thread addresses a bug report about submodule checkout failures in SHA256 repositories when using `--depth=1`, which revealed a deliberate design choice: Git does not support mixing SHA1 and SHA256 hash algorithms in the same repository hierarchy. The discussion has progressed through both technical implementation and deployment considerations.

brian m. carlson has implemented validation to prevent creating such mixed-hash states through `git add` and `git submodule add`, with a v2 patch series that now has approval from both Junio C Hamano and Jeff King. The series includes hash algorithm validation in `index_path()` and removes duplicate submodule HEAD resolution as suggested by Jeff. The implementation cleanly prevents repository corruption with clear error messages and handles edge cases like uninitialized submodules.

While the technical solution has reached maturity with maintainer approval, Marc Branchaud's proposal for mirror-based workarounds remains available for deployment scenarios. Some open questions include potential documentation updates and broader compatibility considerations for SHA256 repositories with SHA1 remotes. The thread demonstrates how a bug report evolved into both a robust technical fix and practical deployment discussion, with consensus that mixed-hash repositories constitute invalid states that Git should actively prevent.
