This thread began with Martin Wilck reporting that `git submodule update --depth=1` fails for SHA1 submodules in SHA256 superprojects. Junio C Hamano confirmed this is by design - mixing hash algorithms constitutes repository corruption. brian m. carlson implemented validation in `index_path()` to prevent creating such invalid states via `git add` and `git submodule add`, with comprehensive tests.

Jeff King has now followed up with a refactoring that removes redundant submodule HEAD resolution from `add_to_cache()`, consolidating all validation logic into `index_path()`. This eliminates duplicate work while maintaining the same error handling, just with slightly modified output that includes the call stack. Junio agrees this is a sensible implementation improvement that doesn't change the core behavior.

Meanwhile, in a separate email, Martin provided real-world context from openSUSE's deployment, asking about alternatives to submodules for crossing hash-algorithm boundaries and the long-term implications of repositories with mixed-hash history. The technical consensus remains that such mixing is invalid by design, but Martin's questions highlight practical challenges for distribution maintainers during the transition period.
