This thread began with Martin Wilck reporting a failure when trying to check out SHA-1 submodules in a SHA-256 superproject using `--depth=1`. Junio C Hamano confirmed this is working as designed - Git intentionally does not support mixing hash algorithms between repositories, considering such configurations corrupt. 

brian m. carlson has now followed through with a concrete implementation to harden this boundary. Their patch modifies `git add` and `git submodule add` to actively detect and reject attempts to create mixed-hash scenarios, preventing repository corruption at the source. The change adds validation in `object-file.c` to compare hash algorithms and includes comprehensive tests covering both directions of mismatch (SHA-1 in SHA-256 and vice versa). 

The patch maintains the thread's established position that mixed-hash repositories are invalid by design, though it notes this can't be enforced by `git fsck` due to potential false positives. With this change, users will get immediate feedback when attempting invalid operations rather than encountering subtle failures later. The original submodule checkout limitation remains, with manual fetching as the only workaround. This appears to conclude the thread's actionable items while documenting the constraints more clearly in both code and tests.
