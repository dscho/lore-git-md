This is patch 6 in a 9-part series addressing ASan (AddressSanitizer) findings, focusing on memory safety fixes in Git's fsck functionality. The patch comes from Jeff King and modifies `fsck_ident()` to avoid using `strcspn()` when parsing author/committer lines.

The change replaces `strcspn()` with explicit character-by-character parsing for better safety and clarity. While the current code is technically correct (relying on a known newline terminator), the new implementation makes the buffer boundary checks more explicit and avoids confusing ASan's strict string checking mode. The logic remains functionally equivalent but becomes more straightforward to verify.

This continues the series' theme of hardening Git against potential memory safety issues, particularly in string parsing scenarios. The patch appears well-considered, with clear explanations of both the current behavior's subtlety and the benefits of the new approach. It builds on prior work in commit 8e4309038f that established fsck's buffer handling conventions.

The change affects fsck's validation of commit and tag headers, though normal operation should be identical for valid inputs. This is part of a broader effort to make Git's parsing more robust when dealing with potentially malformed input or when running under memory safety checkers like ASan.
