This is a follow-up in the thread about SHA1/SHA256 submodule interoperability, confirming the design limitation and proposing a code change to improve error handling.

brian m. carlson confirms Junio's assessment that mixing hash algorithms in submodules is fundamentally unsupported and will remain so without new extension mechanisms. They describe such repositories as "corrupt" to emphasize the severity of the mismatch. 

The key technical point is unchanged from earlier in the thread: the failure is working as designed, not a bug. However, brian announces an upcoming patch to improve the user experience by detecting and properly erroring on this case in `git add`, rather than allowing the corruption to persist silently.

This moves the discussion from diagnosis to potential solutions, though the core design constraint remains firm. The proposed change would make the limitation more visible to users, which could help prevent similar confusion in the future. The patch isn't included in this email, but the announcement suggests we'll see concrete implementation details soon.
