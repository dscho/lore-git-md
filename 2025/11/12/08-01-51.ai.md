This is a bugfix patch in a series addressing ASan findings, specifically targeting a memory safety issue in the pack-bitmap subsystem's handling of name-hash lookups in incremental bitmaps.

The patch fixes an out-of-bounds memory read that occurs when accessing name-hash caches in incremental multi-pack index (midx) bitmaps. Currently, the code assumes all name-hash entries are in a single contiguous array, but with incremental bitmaps, the entries are split across multiple bitmap_index structs. The fix introduces a new `bitmap_name_hash()` helper that properly traverses the chain of bitmap_index structs to find the correct slice containing the requested entry.

The bug is particularly subtle because it doesn't cause immediate crashes - the OS's page rounding of mmap'd regions masks the issue, and ASan doesn't instrument mmap'd memory. The author demonstrates the problem can be detected by building with NO_MMAP=1 and SANITIZE=address, which forces heap allocation that ASan can check.

Key technical details:
- Adds new `bitmap_name_hash()` function to handle the traversal logic
- Replaces direct array access in two locations (show_objects_for_type and create_bitmap_mapping)
- Includes BUG() assertions for invalid positions
- The fix matches the traversal pattern used elsewhere in the midx code

The author notes this is part of newer, less-tested bitmap functionality and acknowledges the area could benefit from more comprehensive testing. While the immediate fix is clear, there are open questions about the broader correctness of ordering in the incremental bitmap code. The patch is marked as particularly important within the series, addressing an actual bug rather than just an ASan warning.
