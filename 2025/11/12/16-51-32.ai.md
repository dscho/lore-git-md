This is a follow-up in the thread about adding 'strip-if-invalid' mode to `git fast-import`'s `--signed-commits` option. Maintainer Junio C Hamano confirms Christian Couder's plan to address test failures in v2 of the patch series. The failures occur because some tests depend on SHA-256 repositories created by another test that now requires Rust support, though the signature-stripping functionality itself doesn't need dual-hash interoperability.

Couder agrees to restructure the tests in v2 to either make SHA-256 repository creation part of test setup (with proper prerequisites) or avoid SHA-256 repositories entirely. This resolves the immediate technical issue raised by the maintainer about test compatibility when merged with other changes in the codebase.

The exchange shows progress on the practical implementation concerns while the broader discussion about cryptographic implications of signature stripping during history rewriting continues separately. The test fix is a straightforward prerequisite for moving forward with the feature.
