Bugfix for HTTP authentication in remote-curl when handling large requests with probe_rpc(). The patch addresses an issue where authentication headers weren't being included in probe_rpc() requests, causing failures when downloading blobs after initial authentication.

The problem manifests when cloning with `--filter=blob:none` - the initial authentication succeeds for commit history and promisor packs, but subsequent blob requests fail with 401 errors because probe_rpc() wasn't passing the auth headers. The patch adds `http_append_auth_header()` to probe_rpc() to ensure credentials are included.

The change is minimal (2-line addition in remote-curl.c) and well-justified with a detailed reproduction scenario using git-credential-msal. The author notes this doesn't fully solve token expiration cases (which would require HTTP_REAUTH handling), but focuses on the immediate issue where valid tokens weren't being reused.

Key technical details:
- Affects remote-curl.c's probe_rpc() function
- Adds auth headers via http_append_auth_header()
- Particularly impacts filtered clones with blob:none
- Uses Bearer token flow (though not specific to it)
- Leaves HTTP_REAUTH cases for future work

The patch appears well-targeted and addresses a clear authentication gap in the HTTP transport code. The reproduction case shows real-world impact, and the solution follows existing auth handling patterns.
