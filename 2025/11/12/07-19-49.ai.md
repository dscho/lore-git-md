This is a response in the ongoing discussion about adding a 'strip-if-invalid' mode to `git fast-import`'s `--signed-commits` option. Christian Couder clarifies several technical points raised by Junio C Hamano regarding signature validation behavior.

The response makes three key clarifications: (1) The validity check uses the same definition as `git verify-commit`, returning 0 for valid signatures. (2) It assumes availability of all necessary public keys, revocation data, and accurate clocks - same as `verify-commit`. (3) While acknowledging that signature invalidation could cascade through rewritten history, the current implementation takes a simpler approach without tracking non-linear history.

Christian suggests that any improvements to signature validation documentation (possibly in `verify-commit` or a new gitsignature(7) page) should be handled separately. He plans to include these clarifications in an upcoming v2 of the patch series.

The response doesn't directly address the test infrastructure issue with SHA-256 repositories or the fundamental concerns about cryptographic integrity raised earlier in the thread. It focuses narrowly on the validation behavior questions while deferring broader documentation improvements to future work. The tone remains constructive, positioning the current implementation as a starting point that could be enhanced later.
