Koji Nakamaru proposed reverting a problematic optimization in the OSX keychain credential helper (commit e1ab45b2dab from Git v2.46) that tracked credential state with a `state[]=osxkeychain:seen=1` flag. While intended to skip redundant storage operations, this caused failures when invalid credentials from one helper were followed by valid ones from another (e.g., git-credential-oauth), as the state flag incorrectly blocked valid credential storage.

Junio C Hamano has raised concerns about the revert approach, noting this isn't a recent regression and questioning whether a straight revert might cause new issues for users who've adapted to the current behavior. He suggests a proper fix would be preferable to a simple revert, expressing skepticism about the "revert now, fix later" approach unless addressing a critical regression. The technical discussion centers on credential helper chain behavior and the removal of state-tracking code from the OSX keychain helper implementation. The thread remains open as participants weigh the tradeoffs between fixing a known issue and maintaining stability for existing users.
