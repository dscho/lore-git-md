This is a security hardening discussion regarding Git's attribute macro expansion system.

Jeff King (Peff) responds to Patrick Steinhardt's suggestion about potentially adding hard limits to the recently converted iterative macro expansion implementation. Peff agrees with the iterative approach and notes that while he's not opposed to adding limits, there are easier ways to waste resources on a hosting site than through gitattributes.

The discussion reveals consensus on the core security fix (converting from recursive to iterative processing) while leaving open the question of additional limits. Peff suggests the max attribute file size could potentially be reduced from 100MB to 10MB as part of any future hardening, though he doesn't plan to implement this himself.

This email represents the winding down of the thread, with the technical solution settled and only peripheral questions remaining about possible follow-up hardening measures. The iterative approach has clearly won out as the solution to the original stack overflow vulnerability.
