This is a feature proposal for adding a `--committer` option to `git commit`, part of an ongoing discussion about identity control in Git commits. ZheNing Hu responds to Phillip Wood's concerns about the use case for this feature, clarifying their workflow needs.

The key points in this response:
1. Hu explains their specific need to correct both author and committer identities when fixing misconfigured commits, noting that current workflows require either multiple commands or cumbersome environment variable usage.
2. They acknowledge Phillip's point about `--amend` fixing committer info when config is corrected, but highlight the remaining need to separately fix author info.
3. The response suggests this could be particularly useful for bulk corrections via rebase, where environment variables become unwieldy.

The thread context shows this is one of three competing approaches being discussed (flag-based, configuration-based, and Jeff King's `--committer-is-author` shortcut). This email focuses on defending the flag-based approach's utility for identity correction workflows, though it doesn't directly engage with the configuration-based approach recently proposed by Junio Hamano.

The implementation appears thorough, with documentation updates, core changes, and extensive test coverage. However, the governance question about AI contribution authorship (mentioned in the thread context) remains unaddressed in this response.
