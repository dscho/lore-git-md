This is a bugfix patch that enforces Git's design decision to prevent mixing hash algorithms between repositories and their submodules. Following up on a recent discussion where Junio C Hamano confirmed that mixed hash-algorithm repositories are intentionally unsupported, brian m. carlson now implements validation to actively block such invalid configurations.

The patch modifies `index_path()` in object-file.c to reject attempts to add a submodule that uses a different hash algorithm than its parent repository. This prevents the problematic case where a SHA-1 submodule might be added to a SHA-256 repository (or vice versa), which would lead to corruption and operational failures. The change includes comprehensive tests for both `git add` and `git submodule add` scenarios.

The implementation is careful to note why this validation can't be done in `git fsck` - because malformed submodule entries could produce false positives when checking object IDs. The tests verify that both directions of hash algorithm mismatch are caught (SHA-1 in SHA-256 repo and vice versa) and that no submodule entry actually gets added to the index in these cases.

This appears to be a well-considered patch that cleanly implements the design constraints previously discussed on-list. The test coverage is thorough, checking both the direct `git add` case and the higher-level `git submodule add` command. The commit message clearly explains the rationale and limitations of the approach.
