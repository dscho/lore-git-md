This is a follow-up discussion in the resolved thread about submodule hash algorithm validation. Martin Wilck suggests adding a warning for the rare case where a SHA-1 submodule in a SHA-256 repository might coincidentally have an OID ending in 24 zeros, which the current implementation cannot distinguish from a padded SHA-1 OID.

The core technical context is that brian m. carlson's series (now approved) validates submodule hash algorithms at `index_path()` time to prevent creating mixed-hash repositories, which are considered corrupt by design. The implementation specifically avoids fsck checks for this case due to potential false positives from zero-padded OIDs, with Martin noting the statistical improbability (1 in 16 million) of such false positives occurring naturally.

Martin's suggestion introduces a new consideration about whether to add warning messages for these edge cases, though the thread had previously reached consensus on the technical solution. The proposal doesn't challenge the core validation approach but explores potential enhancements to user feedback. This connects to the thread's broader themes about hash algorithm interoperability and error detection.
