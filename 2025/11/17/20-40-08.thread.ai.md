Thread summary:

This thread addresses a CMake build system issue following recent changes to Git's static library structure. The core problem is that CMake configuration was still trying to build separate `xdiff` and `reftable` libraries after these were consolidated into the main `libgit` in the Makefile-based build (commits f3b4c89d59f1 and cf680cdb9543). The current status shows CMake builds failing with cryptic errors during Makefile parsing.

The patch provides a straightforward fix by removing obsolete CMake logic that set up separate library targets for xdiff and reftable, and adjusting the `common-main` target to link only against `libgit`. Key technical changes include: deleting 13 lines from CMakeLists.txt while adding 1, removing `libxdiff_SOURCES`/`reftable_SOURCES` parsing and their `add_library()` calls, and updating `target_link_libraries()` for `common-main`. The change aligns CMake with the Makefile's LIB_OBJS structure.

The author notes this is particularly important for Git for Windows CI builds, while also commenting on the broader maintenance challenges of keeping parallel build systems (CMake and Meson) in sync with the primary Makefile. This hints at potential future discussions about build system consolidation, though the current patch focuses strictly on fixing the immediate CMake breakage. The change appears to be a necessary synchronization with no functional impact beyond restoring build system compatibility.
