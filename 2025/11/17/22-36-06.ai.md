This is a documentation thread discussion with technical workflow implications, specifically about the safety and advisability of nested worktree directories. Johannes Schindelin weighs in with a concrete negative experience supporting Eric Sunshine's position that nested worktrees are technically valid and sometimes preferable.

The email provides first-hand evidence that the proposed warning against nested worktrees (from patch 1 in the series) could actively harm users by encouraging workflows that risk data loss. Schindelin describes losing carefully crafted commits when following the "worktrees outside main worktree" advice, because the secondary worktree became disconnected from Git's tracking after the primary worktree was deleted. This directly counters the argument that nested worktrees should be discouraged, showing they can provide important safety benefits by maintaining clear ownership relationships.

The message strengthens Eric Sunshine's case in the ongoing debate by:
1. Providing a real-world example where the "recommended" workflow caused data loss
2. Showing that even experienced users (the thread previously noted Schindelin as an example) find nested worktrees valuable
3. Demonstrating that the safety rationale for warning against nesting may be backwards - nesting can prevent accidental detachment

This likely tips the balance in the documentation debate, making it harder to justify including the nested worktree warning without equally strong counterexamples. The thread now has clear evidence that:
- Nested worktrees work technically (Eric's point)
- Avoiding them can be actively dangerous (Schindelin's experience)
- The only remaining downside is gitignore management (subjective)

Key technical detail: The failure mode occurs when a primary worktree is deleted while secondary worktrees exist outside it, causing those worktrees to lose their Git association silently. This wasn't previously discussed in the thread and provides new justification for nested worktrees as a safety measure. The message doesn't address the bare repository directory structure debate from patch 2, keeping that discussion separate.
