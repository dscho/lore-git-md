CI / build system fix to restore visibility of failed test outputs in Dockerized GitHub Actions jobs.

This patch addresses a regression introduced in January 2025 when containerized CI jobs were made to run as non-root users. The change inadvertently broke the mechanism that shows test failure outputs in the build logs, making it harder to debug CI failures. The root cause was a permissions issue - the `builder` user couldn't write to the `$GITHUB_ENV` file used to signal which test outputs should be included in logs.

Johannes Schindelin proposes a straightforward fix: make the environment file world-writable before running the tests. While this isn't the most secure approach (the file remains writable after the step completes), he notes this doesn't matter in practice since the file isn't reused. The patch is minimal - just a one-line change to the GitHub Actions configuration.

The commit message provides good context, tracing the regression to specific commits and mentioning prior reporting of the issue. The fix has already been tested in Git for Windows' fork during their v2.52.0-rc0 rebase. This appears to be a well-justified quality-of-life improvement for CI debugging.
