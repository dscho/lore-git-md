This is part of the ongoing SHA-1/SHA-256 interoperability work introducing Rust code to Git. It's patch 4/15 in the v2 series.

The patch adds a Rust `ObjectID` struct that mirrors C's `struct object_id`, designed for efficient FFI (Foreign Function Interface) usage between Rust and C code. The struct contains a fixed-size hash array and a hash algorithm` field (using `u32` per the type standardization from patch 3/15). The implementation prioritizes performance over Rust idioms since this will be used in hot paths like `index-pack` and `pack-objects` during hash algorithm conversion.

The changes are straightforward - a new Rust module (`hash.rs`) is added to the build system (both Makefile and Meson), exposing the struct definition with proper memory layout (`#[repr(C)]`) and basic traits for comparison and debugging. This foundational piece will be used throughout the Rust/C interoperability work for object handling.

The patch appears well-contained and properly integrated with the build system. As part of Git's first major Rust adoption, this represents a careful balance between Rust safety guarantees and the need for efficient C interop in performance-sensitive areas. The implementation follows the type standardization established in the previous patch while setting up infrastructure for future object handling code.
