This thread addresses a CI regression where test failure output stopped appearing in logs for Docker-based GitHub Actions jobs. The issue stemmed from a permissions problem when CI jobs switched to running as a non-root `builder` user, which couldn't write to `$GITHUB_ENV` to report test failures.

Johannes Schindelin (Dscho) diagnosed the root cause and proposed a fix - making `$GITHUB_ENV` world-writable before test execution. While this technically relaxes security slightly (the file should ideally have permissions tightened afterwards), the practical risk is minimal since the file isn't reused. The patch has already proven useful in Git for Windows' CI during the v2.52.0-rc0 rebase, helping debug test failures that would otherwise have been silent. The change is minimal - just a `chmod` command added to the workflow file - but restores critical debugging visibility.
