This thread addressed a regression where test failure output disappeared from CI logs when jobs ran as non-root via a `builder` user, caused by commit 2a21098b98a. The root problem was missing write permissions to `$GITHUB_ENV` needed to report test failures. Johannes Schindelin (Dscho) proposed adding `chmod o+w` to `.github/workflows/main.yml` before test execution as a pragmatic fix, acknowledging it's not ideal security practice but acceptable since the file isn't reused. 

Junio Hamano has now applied the fix, noting he might have used `a+w` rather than `o+w` if writing it himself, but accepts the implementation as it works. The change restores the previous behavior where failing test output appears in CI logs, making debugging easier. The solution is minimal and focused specifically on the CI configuration file, concluding the thread with the regression fixed. The fix was tested in Git for Windows where it helped debug test failures during the v2.52.0-rc0 rebase.
