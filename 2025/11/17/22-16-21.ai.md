This is the final patch in the 15-part series introducing Rust infrastructure for SHA-1/SHA-256 interoperability. It addresses an edge case in object ID handling that affects the new Rust-based loose object map implementation.

The patch fixes an issue where zero-initialized object IDs (with algo=0) could cause problems in the Rust object map code, which doesn't gracefully handle such cases. The solution modifies `repo_oid_to_algop()` to create a corrected copy of any incoming object ID with algo=0, setting it to the repository's hash algorithm. This ensures consistent behavior between the C and Rust implementations while also improving the handling of malformed object IDs in general.

Key technical details:
- Modifies `object-file-convert.c`'s `repo_oid_to_algop()` function
- Introduces a temporary `object_id` struct to hold corrected values
- Uses `oidcpy()` and `hash_algo_by_ptr()` to create valid object IDs
- Maintains the same function signature but changes parameter name from `src` to `srcoid`
- Preserves all existing behavior for non-zero algo cases

This change is particularly important for the Rust object map implementation which:
- Cannot access global state to determine the correct hash algorithm
- Uses strict equality comparisons that fail on algo=0 object IDs
- Forms a critical part of the new loose object storage system

The patch represents the last piece of the series' core functionality, addressing a subtle interoperability edge case that could affect object lookups. It demonstrates careful attention to maintaining compatibility between the C and Rust implementations while fixing a long-standing issue with zero-initialized object IDs.
