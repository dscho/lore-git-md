CI test output visibility regression fix for Dockerized jobs. The thread addresses a regression from commit 2a21098b98a where test failure output disappeared from CI logs when jobs ran as non-root via a `builder` user. The root cause was missing write permissions to `$GITHUB_ENV` needed to report test failures. The solution adds `chmod o+w` to `.github/workflows/main.yml` before test execution, making the file world-writable. Johannes Schindelin (Dscho) notes this technically violates security best practices (the permission should ideally be removed afterwards) but accepts the simpler solution since the file isn't reused. The fix has been tested in Git for Windows where it helped debug test failures during the v2.52.0-rc0 rebase. The patch restores the previous behavior of showing failing test output in CI logs for easier diagnosis. The commit references an earlier report of this regression that saw no movement, prompting this upstream submission. The change is minimal and focused specifically on the CI configuration file.
