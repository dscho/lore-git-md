This is a follow-up discussion in the ongoing thread about fixing `git fetch`'s tag handling regression. Junio Hamano is responding to Karthik Nayak's proposal about handling non-atomic fetch operations.

The conversation focuses on three post-fetch operations that are currently skipped when a fetch fails, even for non-atomic fetches where partial success might be acceptable: updating FETCH_HEAD, processing upstream tracking, and handling the remote's followremotehead setting. Karthik suggests these should still run for non-atomic fetches, while Junio confirms this is a pre-existing regression not caused by the current patch series.

Junio notes this isn't urgent enough for the upcoming Git 2.52 release but should be addressed soon after. The discussion remains open on whether to handle this as an addition to the current series or as a separate follow-up patch, with Karthik leaning toward the latter approach to get the core tag-fix merged sooner.

The exchange shows the patch series is nearing completion, with this being one of the final refinements to consider. The core regression (non-conflicting tags failing to commit) appears resolved, and attention is now turning to related cleanup behaviors that were broken by the original batched ref updates change.
