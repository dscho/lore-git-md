This is the final patch in a 3-part series introducing a 'strip-if-invalid' mode for `git fast-import`'s `--signed-commits` option. The feature allows automatically removing invalid commit signatures during history rewriting operations, which is particularly useful for tools like `git filter-repo` that rewrite repository history.

The patch implements the core functionality by:
1. Adding the new `strip-if-invalid` mode that checks signatures using the same validation as `git verify-commit`
2. Stripping invalid signatures while preserving valid ones, with appropriate warnings
3. Supporting OpenPGP, X.509, and SSH signature formats
4. Adding comprehensive tests covering various signature scenarios

The implementation builds on the refactoring work in the first two patches, which separated commit buffer handling and verification logic. The patch maintains backward compatibility while adding the new mode, and includes thorough documentation explaining the behavior.

The series has seen active discussion, with maintainer concerns about edge cases (like cascading invalidations) being acknowledged but left for future work. This final patch appears well-tested and addresses the practical use case of preserving valid signatures while rewriting recent history.
