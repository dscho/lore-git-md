Feature proposal for a new work item tracking system in Git.

Skybuck Flying proposes a new optional feature called Work Item Log (WIL) that would allow tracking small, atomic work items directly within Git repositories. The system would introduce new commands like `git work item add/done/list/status/diff` to manage a version-controlled log of tasks marked as either pending (-) or completed (+). The log would be branch-specific and could be implemented either as a dedicated Git ref or as a tracked file.

Key aspects include version-controlled task tracking that moves with branches, integration with commit workflows, and differentiation from external issue trackers by focusing on small, code-level tasks. The proposal suggests this could help with daily task management while maintaining auditability through Git's versioning capabilities.

Implementation options discussed are using a specialized ref namespace (`refs/worklog/`) or a tracked file (`.gitworklog`). The proposal emphasizes this would be optional and designed to complement rather than replace existing issue trackers. The author presents this as addressing a gap in short-term, high-frequency progress tracking that current tools don't handle well.

Technical details mentioned include potential commit hooks to link work item status changes with commit messages, and the ability to diff work item states across branches or commits. The proposal is at an early stage with implementation approach still to be determined.
