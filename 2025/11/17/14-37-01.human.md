This is a feature announcement and RFC for Skybuck's GitFlow, now at v0.11, along with a separate proposal for built-in Git versioning.

Skybuck Flying announces version 0.11 of their Windows-based Git workflow extension, which now supports specifying remote repositories beyond just "origin". The release was actually completed in September but is only now being announced, with the author noting it hasn't been thoroughly tested. The project continues to be developed as a set of Windows executables built with Delphi.

The email also references a new, separate RFC proposing an opt-in versioning system for Git that would automatically version commits, distinct from tags and branch names. Skybuck is considering two implementation approaches: modifying Git's source code (potentially with AI assistance) or creating external tools like the current GitFlow. The built-in approach is preferred as it would better solve the versioning problem while allowing branch name reuse.

The message has a somewhat informal tone, mentioning distractions and development struggles alongside the technical content. The GitFlow update appears to be a minor iteration on the existing Windows-specific toolchain, while the versioning RFC represents a more ambitious idea that would require core Git changes. Both projects remain in early stages with unclear adoption paths in the broader Git community.
