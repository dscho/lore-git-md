This is a small but important infrastructure patch in the ongoing SHA-1/SHA-256 interoperability series that introduces Rust code to Git. It adds fsync support for a new object map that will be used in the compatibility layer between different hash algorithms.

The patch adds `FSYNC_COMPONENT_OBJECT_MAP` to the existing fsync component enum in `write-or-die.h`, ensuring that writes to the new object map file will be properly synchronized to disk when fsync is enabled. This matches the pattern used for other critical Git files like packfiles, commit graphs, and references.

While the change is simple - just a new enum value and its inclusion in the default fsync components - it's a necessary piece of the larger object storage compatibility work. The patch follows the established pattern for fsync components and appears straightforward, though we'll need to see how this integrates with the actual object map implementation in later patches of the series.

This continues the series' careful attention to data integrity concerns while building out the Rust infrastructure for hash algorithm interoperability. The change is small but shows the thoroughness of the approach being taken in this major architectural change to Git's object storage.
