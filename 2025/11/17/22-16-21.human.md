This is the final patch in a 15-part series introducing Rust infrastructure for SHA-1/SHA-256 interoperability. The patch fixes an edge case where zero-initialized object IDs (with algo=0) could cause problems with the new Rust loose object map code.

The issue arises because the Rust implementation strictly compares object IDs including their algorithm field, while Git's C code often "paper[s] over" zero-algo IDs by substituting the repository's hash algorithm. The fix ensures any zero-algo object IDs get properly initialized with the correct algorithm before being processed, which both makes the Rust code work correctly and improves consistency in single-algorithm mode.

This is a defensive change that handles a known bad practice (zero-initialized object IDs) more robustly. While not a major functional change, it's an important safeguard for the new Rust infrastructure being introduced in this series. The patch is narrowly focused and appears well-justified given the context of the larger interoperability work.
