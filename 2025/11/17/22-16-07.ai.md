This is the first patch in a 15-part series introducing Rust infrastructure for SHA-1/SHA-256 interoperability. The patch enforces Rust as a requirement for compatibility mode operations, marking a significant step in Git's Rust adoption.

Key technical changes:
- Modifies `repo_set_compat_hash_algo()` to error out if Rust support is not compiled in
- Adds a new `RUST` test prerequisite to conditionally run compatibility tests
- Updates multiple test scripts to use this prerequisite, splitting setup into Rust-dependent and independent parts
- Documents the regression in functionality (removing C-only support) as acceptable since the feature is already experimental

The patch affects core repository handling and several test suites, particularly around object format compatibility testing. It introduces a build-time requirement that will impact CI configurations and platform support, though the cover letter notes Windows/Meson issues appear pre-existing.

This represents Git's first production Rust code requirement, with the series planning to implement the loose object map in Rust. The change is positioned as low-risk since the affected functionality is already marked experimental, but it does establish a precedent for Rust adoption in core Git operations.
