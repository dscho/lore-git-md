This is a foundational patch in the SHA-1/SHA-256 interoperability series, introducing Rust abstractions for hash algorithms that mirror Git's C implementation. It builds on the `ObjectID` struct from earlier in the series to provide algorithm-specific operations while maintaining FFI compatibility.

The patch adds a `HashAlgorithm` enum in `src/hash.rs` that represents the supported hash algorithms (SHA-1 and SHA-256) with associated constants and methods. Key features include:
- Conversion between algorithm IDs and enum variants (both numeric and format-specific IDs)
- Algorithm properties like raw/hex lengths, block sizes, and format IDs
- Precomputed special object IDs (null OID, empty tree, empty blob) for each algorithm
- Slice operations on `ObjectID` that respect the algorithm's raw length

Notably, the hashing operations themselves are omitted to simplify FFI compatibility, as the function pointers in C would complicate bit-for-bit matching across the interface. The implementation uses Rust's type system to ensure safety, with an `InvalidHashAlgorithm` error type for invalid conversions.

The patch maintains performance by using `self` rather than `&self` for small-enum operations and includes extensive compile-time constants for common object IDs. This provides the core infrastructure needed for subsequent patches that will implement actual object conversion between hash algorithms.

This is a well-structured addition that cleanly mirrors Git's existing hash algorithm handling while adapting it to Rust's type system. The careful attention to FFI concerns and performance characteristics suggests it will integrate smoothly with the C codebase while providing type safety for the Rust side.
