This is a refactoring patch in the SHA-1/SHA-256 interoperability series that introduces Rust code to Git. It changes the data type used to represent hash algorithms from `int` to `uint32_t` to ensure consistent representation between C and Rust code.

The patch updates several functions and struct fields across multiple files to use `uint32_t` for hash algorithm identifiers. The key changes include modifying the `algo` field in `struct object_id` and updating related functions like `hash_algo_by_name()`, `hash_algo_by_id()`, and `hash_algo_by_length()`. The motivation is to ensure type consistency when this structure is defined from Rust in future commits.

This is a straightforward mechanical change that doesn't affect behavior, just type safety. It's part of a larger effort to enable SHA-1 and SHA-256 repositories to exchange objects through a new Rust-based loose object format. The patch series as a whole represents Git's first major use of Rust in production code, with this particular change laying groundwork for future Rust interoperability.
