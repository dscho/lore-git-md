This is the cover letter for v2 of a 15-patch series implementing SHA-1/SHA-256 interoperability with Rust infrastructure, building on prior hash-algorithm-agnostic work. The series introduces Git's first major Rust code for a new object map format and related infrastructure.

The series makes several key technical changes from v1: switching to `MAYBE_UNUSED` instead of casts, improving Rust documentation (including clarifying that "safe hashing" refers to untrusted data rather than memory safety), renaming several functions and types for clarity (`hash_algo_ptr_by_number`, `CryptoHasher`), and extensive documentation improvements for the new object map format regarding padding/alignment/endianness. The implementation maintains the `uint32_t` approach for hash algorithms rather than using Rust enums to ensure clean FFI compatibility.

The Rust components include a new `ObjectID` struct, hash algorithm abstraction layer, object hashing functionality, and a custom binary object map format with comprehensive unit testing. The series also adds Rust build infrastructure (`build.rs`) and makes supporting changes to C code (like `hashwrite` count type changes) to enable the interoperability work. Testing now requires Rust support.

The cover letter notes ongoing considerations around FFI boundaries and upcoming Rust infrastructure changes (like the planned move to a Cargo workspace), but positions this as ready for review while remaining open to v3 fixes for any confirmed issues.
