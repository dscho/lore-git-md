This is part of the ongoing SHA-1/SHA-256 interoperability work introducing Rust infrastructure to Git (patch 5/15 in the series). It adds a hash algorithm abstraction in Rust that mirrors Git's existing C implementation but with some Rust-specific design choices.

The patch introduces a `HashAlgorithm` enum (SHA-1 and SHA-256 variants) with associated constants and methods for working with object IDs. Key features include conversion between algorithm IDs and names, length calculations for different representations (binary vs hex), and predefined special object IDs (null OID, empty tree, empty blob). The implementation is careful about FFI considerations - using `#[repr(C)]` and avoiding pointer-sized references where integers suffice.

Notably, this differs from the C version by not including hashing functionality yet, as that would complicate the FFI boundary. The `ObjectID` struct from the previous patch is enhanced with slice access methods that respect the algorithm's hash length. Error handling uses Rust's `Option` and a custom `InvalidHashAlgorithm` error type rather than an "unknown" enum variant.

This foundational piece provides the type-safe building blocks needed for upcoming object conversion work while maintaining compatibility with Git's existing C code. The implementation appears thorough, with good test coverage implied by the predefined test vectors for special object IDs.
