This is a feature patch series introducing a new 'strip-if-invalid' mode for `git fast-import`'s `--signed-commits` option. The v2 series maintains the same three-patch structure as v1, with refinements to commit messages, documentation, and tests based on maintainer feedback.

The core addition is a new mode that automatically strips commit signatures during import if they fail verification (using the same validation logic as `git verify-commit`). This addresses use cases like `git filter-repo` rewrites where users want to preserve valid signatures from older commits while rewriting recent history. The implementation builds on refactored verification code that now operates at the buffer level.

Key changes in v2 include: removing dual-signature tests that conflicted with another in-progress series, clarifying documentation about validation behavior, and incorporating Elijah Newren's use case explanations into the commit message. The series maintains the position that fast-import is the only point in the export/import pipeline where signature validity can be properly assessed.

While the technical implementation appears solid with comprehensive test coverage, some design questions remain open - particularly around how to handle cascading signature invalidation in rewritten history and whether this should become the default mode. The maintainer has conditionally approved proceeding while deferring these edge cases for future consideration.
