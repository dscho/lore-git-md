Feature patch in the SHA-1/SHA-256 interoperability series, introducing Rust-accessible hashing functions.

This patch (10/15 in v2) exposes Git's hash context functions to Rust by moving them from inline implementations in hash.h to regular functions in hash.c. The key changes are:

1. Adds three new functions for memory management: `git_hash_alloc()`, `git_hash_free()`, and `git_hash_init()` to create, destroy, and initialize hash contexts.

2. Converts four existing inline hash operations (`git_hash_clone()`, `git_hash_update()`, `git_hash_final()`, and `git_hash_final_oid()`) to regular functions that can be called from Rust.

The motivation is to enable Rust code to use Git's hashing infrastructure while avoiding manual memory management and inline function limitations. The changes maintain identical behavior while making the functions accessible through FFI. This is part of the larger effort to build Rust infrastructure for SHA-1/SHA-256 interoperability, where Rust code will need to work with Git's hash objects.

The patch follows the series' pattern of carefully exposing C functionality to Rust with proper memory safety. It builds on previous work standardizing types for FFI safety and adds to the growing set of Rust-accessible core functions. The implementation looks straightforward and well-contained, with no apparent behavioral changes beyond the function visibility.
