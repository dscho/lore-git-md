This is a follow-up in the CI/build system modernization series, specifically about the rootless container execution issue. Johannes Schindelin reports a critical problem with the proposed approach: when tests fail, the `builder` user lacks permissions to write debug logs to GitHub's `/__w/_temp/` directory, preventing proper failure analysis. This creates a functional blocker for the series despite earlier approvals of other components.

Schindelin notes this was observed in a real test failure where permission denial skipped both log display and artifact upload steps, making debugging impossible. He suspects a group permission adjustment may be needed but can't verify. Separately, he mentions contributing a related patch (accidentally omitting the thread from CC) that might help address this.

The issue represents a regression in debuggability that wasn't caught in earlier reviews, potentially requiring a v5 of the series. While other components (like the SIGPIPE tests) remain approved, this newly identified problem with rootless execution needs resolution before the changes can be safely merged. The security benefits of non-root operation must be balanced against maintaining essential debugging capabilities.
