This is a follow-up in the CI/build system modernization series, specifically addressing the rootless container permission issue raised earlier.

Johannes Schindelin provides additional context about the debugging failure problem in rootless container jobs, where the `builder` user cannot write to GitHub's `/__w/_temp/` directory. He notes this prevents both test log output and artifact uploads when tests fail, making debugging impossible. While he can't investigate further himself, he suspects a group permission adjustment might be needed.

Importantly, Schindelin reveals he has already contributed a patch to fix this issue (via a separate pull request he forgot to CC the thread on). This suggests the technical blocker may soon be resolved, though the patch's exact approach isn't described here. The fix appears to maintain the security benefits of non-root operation while restoring debuggability.

This moves the conversation forward from problem identification to potential solution, though the series may still need a v5 to incorporate the fix. The other approved components (SIGPIPE tests, Windows fixes, CI modernization) remain unaffected by this specific issue.
