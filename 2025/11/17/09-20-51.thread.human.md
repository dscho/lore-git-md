This thread reports a bug in `git submodule` where using `--single-branch` with a branch specified in `.gitmodules` leads to incorrect remote tracking configuration. The initial checkout correctly uses the specified commit (b33a8abe in the example), but sets up tracking for the remote's HEAD (master) rather than the configured branch (scarthgap). This causes subsequent `git submodule update --remote` operations to fail since they can't find the expected remote branch.

The reporter has provided clear reproduction steps showing the discrepancy across multiple Git versions (2.47.3 through current master 2.52.0.rc2). The issue appears to be in how `--single-branch` interacts with branch specifications in `.gitmodules`, where the initial fetch gets the right commit but sets up wrong tracking information. This contradicts expected behavior when specifying a branch in `.gitmodules` and affects both checkout and update operations in submodules. The well-documented report suggests this is a legitimate bug needing fixing.
