The original report showed that while Git correctly checks out the specified commit, it incorrectly sets the remote tracking branch to HEAD (master) rather than the configured branch (e.g. scarthgap), causing subsequent `submodule update --remote` operations to fail.

D. Ben Knoble has clarified that this is actually documented behavior - `--single-branch` defaults to cloning only HEAD unless explicitly given a `--branch` parameter. While this explains the current behavior, it may not match user expectations when working with submodules. Knoble suggests two potential improvements: encouraging explicit `--branch` usage when needed, or enhancing `--single-branch` to automatically use the `.gitmodules` branch specification when available.
