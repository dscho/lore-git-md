This thread started with Johannes Schindelin proposing a simple one-line change to include the `scalar` binary in Git's `make strip` target, fixing an oversight from Scalar's 2022 integration. The change appeared straightforward, following the pattern used for other Git binaries.

Junio Hamano responded by agreeing with the motivation but suggesting a more comprehensive solution. Rather than just adding `scalar` to the existing list, he proposed restructuring the Makefile to use variables like `OTHER_PROGRAMS` and introducing a new `OTHER_ARTIFACTS` category for non-program files (like DLLs). This would make the build system more maintainable by handling all similar cases consistently, not just the immediate Scalar case. The discussion has now expanded to consider Windows/MSYS2 build implications and whether parallel changes are needed in Git's CMake and meson build systems. What began as a simple fix has revealed a broader opportunity to improve how the build system categorizes and processes different types of artifacts.
