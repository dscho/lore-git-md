Platform compatibility patch addressing a clang warning about comma operator usage in Windows-specific code.

This patch modifies several error-handling patterns in `compat/mingw.c` where the comma operator was used to both set `errno` and return an error value in a single statement. The change responds to new clang warnings that flag this as potentially problematic usage. Each instance is rewritten to separate the `errno` assignment from the return statement, making the code more explicit while maintaining identical behavior.

The changes affect Windows-specific functions handling file operations (`mingw_open_append`), timer management (`start_timer_thread`, `setitimer`), and signal handling (`sigaction`). The patch appears straightforward with no functional changes - it's purely a style adjustment to satisfy modern compiler warnings. The commit references a specific CI run where clang flagged this issue in the Git for Windows SDK ARM64 build.

Key technical details for future reference:
- Modified files: `compat/mingw.c`
- Error codes involved: ENOSYS, ENOMEM, EINVAL
- Functions changed: `mingw_open_append()`, `start_timer_thread()`, `setitimer()`, `sigaction()`
- Compiler warning: clang's `-Wcomma` warning triggered in CI
- No behavior changes - purely syntactic update to avoid compiler warnings
