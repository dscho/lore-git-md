This is the second patch in a 3-part series introducing signature verification/stripping for `git fast-import`. It's a refactoring that extracts commit signature verification logic to work with raw buffers rather than requiring a full commit object.

The patch moves the core verification logic from `check_commit_signature()` into a new `verify_commit_buffer()` function that operates directly on commit buffers. The original function becomes a thin wrapper that gets the buffer from a commit object and passes it to the new function. This prepares for the series' final patch which will verify signatures during fast-import without constructing temporary commit objects.

Key technical changes:
- New `verify_commit_buffer()` function in commit.h that takes raw buffer/size
- `check_commit_signature()` now delegates to this new function
- Verification still uses the same underlying `parse_buffer_signed_by_header()` and GPG interface
- No behavior change - existing callers continue working as before

The refactoring is cleanly separated from the behavioral changes coming in patch 3, with clear commit message explaining the motivation (avoiding wasteful commit object creation when signatures might be invalid). The change touches core commit verification code but maintains all existing functionality while enabling the fast-import use case.

This continues the series' pattern of careful, incremental changes with good test coverage (though this particular patch doesn't add tests since it's purely refactoring). The thread context shows maintainers have already reviewed and approved the overall approach, with this patch being a straightforward preparation step for the signature-stripping functionality.
