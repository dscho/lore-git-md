This is a feature proposal for a new work-tracking system integrated with Git. Skybuck Flying suggests adding a "Work Item Log" (WIL) that would live in the repository and track small, code-level tasks with simple status markers (to-do/done). The proposal includes new Git commands like `git work item add` and `git work item done` to manage these items programmatically.

The system is designed to complement rather than replace external issue trackers, focusing on short-term, branch-specific task tracking that stays versioned with the code. Key features include branch-specific work plans, progress auditing via `git work item diff`, and potential commit message integration. The author suggests two possible implementations - either using a dedicated Git ref namespace or a tracked file in the working tree.

The proposal is clearly structured and presents a coherent vision, though it doesn't address how this would interact with existing Git tooling or what the migration path might look like for teams adopting it. The concept appears well-considered but would likely need significant discussion about use cases, edge cases, and implementation details before being considered for inclusion in Git proper.
