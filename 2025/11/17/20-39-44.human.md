This is a bugfix for the Windows credential helper that addresses memory corruption when reading passwords. The patch fixes an off-by-one error in memory allocation for the Windows credential storage API. The `wcsncpy_s()` function requires space for a terminating null character, but the original code didn't account for this, leading to buffer overruns.

The issue manifested as crashes when reading passwords, causing Git to repeatedly prompt for credentials since it couldn't properly store the retrieved password. The fix is straightforward - allocating one additional `WCHAR` (wide character) of space to accommodate the null terminator.

The patch comes from David Macek with a sign-off from Johannes Schindelin, suggesting it's been reviewed. The change is minimal (a single line modification) and clearly targets a real issue affecting Windows users. Given the security-sensitive nature of credential handling and the clear explanation of both the problem and solution, this appears to be an important fix that should be merged.
