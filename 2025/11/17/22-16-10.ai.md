This is part of the SHA-1/SHA-256 interoperability work introducing Rust code to Git's core. The patch specifically adds a Rust `ObjectID` struct that mirrors C's `struct object_id` for FFI compatibility.

The `ObjectID` struct is designed for efficient cross-language data sharing in performance-sensitive paths like `index-pack` and `pack-objects` during hash algorithm conversion. It uses a fixed-size 32-byte array for the hash and a `u32` field for the algorithm type, matching the C side's standardized types from patch 3/15. The struct is marked `#[repr(C)]` to ensure memory layout compatibility and includes standard Rust trait derivations (Debug, Clone, etc.) for usability.

Key technical points:
- New file `src/hash.rs` added to build system (Makefile and meson.build)
- `GIT_MAX_RAWSZ` constant defines maximum hash size (32 bytes)
- Struct design prioritizes FFI efficiency over Rust idioms
- Part of the infrastructure for upcoming object conversion work

This foundational piece enables safe Rust/C interoperability for object IDs while maintaining the performance characteristics needed for core operations. The patch follows the series' pattern of establishing type-safe Rust equivalents for existing Git data structures.
