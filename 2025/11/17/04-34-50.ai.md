This is the final patch in a 3-part series introducing a 'strip-if-invalid' mode for `git fast-import`'s `--signed-commits` option. The patch implements the core functionality to validate and conditionally strip commit signatures during import.

The implementation adds a new `SIGN_STRIP_IF_INVALID` mode that checks signatures using the same validation logic as `git verify-commit`. Invalid signatures are stripped with a warning that includes the commit subject and alleged signer. The patch handles OpenPGP, X.509, and SSH signatures, with comprehensive tests covering each case. Key technical components include:

- New `handle_strip_if_invalid()` function that performs validation via `verify_commit_buffer()`
- Warning messages that preserve commit subject context while truncating long lines
- Rejection of unsupported uses (tags, fast-export) with clear error messages
- Documentation updates explaining the new mode's behavior

The patch builds on the refactoring from earlier in the series, using the extracted `finalize_commit_buffer()` and `verify_commit_buffer()` functions. Test coverage is extensive, verifying:
- No-op behavior for unsigned commits
- Preservation of valid signatures
- Stripping of invalid signatures (tested via message tampering)
- Support for all three signature types (OpenPGP/X.509/SSH)

Open questions from earlier discussion remain about cascading invalidation edge cases, but the practical use case (rewriting recent history while preserving older valid signatures) is well-addressed. The implementation is careful to maintain existing behavior for other modes while adding the new functionality.
