This is a bug report about `git submodule` behavior when using `--single-branch`. Uwe Kleine-König demonstrates that when initializing a submodule with `--single-branch`, Git tracks the remote's HEAD (master) rather than the branch specified in `.gitmodules` (scarthgap in this case). This leads to problems when later trying to update the submodule with `--remote`, as the expected branch isn't tracked.

The report includes clear reproduction steps showing the discrepancy between the configured branch in `.gitmodules` and what actually gets tracked. The issue persists across both stable (2.47.3) and development (2.52.0.rc2) Git versions, suggesting it's a long-standing behavior rather than a regression.

The impact is that users who rely on `--single-branch` for submodule initialization may find their submodules tracking different branches than intended, with subsequent update operations failing. The report is well-documented with command outputs and appears to identify a genuine inconsistency in Git's submodule handling.
