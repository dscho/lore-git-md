Feature patch adding fsync support for the new object map in the SHA-1/SHA-256 interoperability work.

This patch introduces `FSYNC_COMPONENT_OBJECT_MAP` to the fsync component enum in preparation for writing the new object map file. The change adds the new component to both the enum definition and the default fsync components mask. This is part of the larger Rust infrastructure work for hash algorithm interoperability, specifically supporting the new loose object format implementation in Rust (`src/loose.rs`).

The modification follows the existing pattern for fsync components, adding a new bit flag (1 << 6) and including it in the default components mask. This ensures the object map will be properly fsynced according to the repository's fsync configuration, maintaining data integrity for the new object storage format.

The change is straightforward and mechanical, extending existing infrastructure rather than introducing new concepts. It connects to the series' broader goal of robust object storage handling by ensuring the new object map benefits from the same fsync guarantees as other critical repository components. The patch appears well-contained and properly integrated with the existing fsync system, though its full utility will only be apparent when the object map writing code is introduced in later patches.
