This is a build system fix addressing a CMake configuration issue following recent changes to how Git's static libraries are structured. The patch removes now-obsolete CMake logic that was trying to build separate `xdiff` and `reftable` libraries, after these were consolidated into the main `libgit` in the Makefile-based build system (commits f3b4c89d59f1 and cf680cdb9543). The change manifests as CMake build failures with cryptic errors about missing arguments in string operations when parsing the Makefile.

The fix is straightforward - it deletes the CMake code that was setting up separate library targets for xdiff and reftable, and updates the `common-main` target to link only against `libgit` rather than all three libraries. The patch notes this is particularly important for Git for Windows CI builds, though it also comments on the broader maintenance challenges of keeping parallel build systems (CMake and Meson) in sync with the primary Makefile-based build.

Key technical details for future reference:
- Removes 13 lines from CMakeLists.txt while adding 1
- Deletes `libxdiff_SOURCES`/`reftable_SOURCES` parsing and their corresponding `add_library()` calls
- Updates `target_link_libraries()` for `common-main` to remove `xdiff` and `reftable` dependencies
- The change follows from Makefile changes that moved these components into LIB_OBJS
- Build failure shows up as CMake errors during `parse_makefile_for_sources` operations

The patch appears to be a necessary synchronization change with no functional impact beyond fixing the build system, though the author's note about maintenance burden hints at possible future discussions about build system consolidation.
