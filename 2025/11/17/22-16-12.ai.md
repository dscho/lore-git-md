This is part of the ongoing SHA-1/SHA-256 interoperability work introducing Rust infrastructure, specifically focusing on FFI (Foreign Function Interface) compatibility between Rust and C hash algorithm representations.

The patch adds a new C function `hash_algo_ptr_by_number()` that safely retrieves a pointer to a `git_hash_algo` struct given a numeric algorithm identifier, with bounds checking to prevent invalid accesses. This is then wrapped in Rust through FFI bindings, allowing the Rust `HashAlgorithm` enum to obtain C-compatible pointers when needed for interoperability.

Key technical details:
- New C function `hash_algo_ptr_by_number()` returns NULL for invalid algorithm numbers
- Exposed in `hash.h` for both C and Rust consumption
- Rust FFI binding added via `src/hash.rs`'s `c` module
- `HashAlgorithm` enum gains `hash_algo_ptr()` method returning `*const c_void`
- Maintains safety by using Rust's enum-to-number conversion
- Builds on previous `ObjectID` and `HashAlgorithm` infrastructure

This is a straightforward FFI bridge that enables Rust code to safely pass algorithm pointers to C side when needed, while maintaining Rust's type safety for normal operations. The implementation is minimal and focused, with proper bounds checking on both sides of the FFI boundary. This continues the series' pattern of carefully introducing Rust infrastructure while maintaining compatibility with Git's existing C codebase.
