Type standardization patch in the SHA-1/SHA-256 interoperability series.

This is patch 8/15 in brian m. carlson's series introducing Rust infrastructure for hash algorithm interoperability. The change standardizes the `count` parameter of `hashwrite()` from `unsigned int` to `uint32_t` in both the declaration and implementation. The motivation is to ensure consistent type sizes when calling this code from Rust, as part of the broader effort to make Git's object handling work across different hash algorithms.

The change is straightforward and mechanical - it doesn't alter behavior, just makes the type explicit. The commit message notes this won't cause issues on any platform Git runs on since `unsigned int` is already 32 bits there. This appears to be a preparatory change for the Rust FFI work in later patches of the series, ensuring type compatibility between the C and Rust sides of the interface.

The patch follows the series' pattern of small, focused changes to support the Rust integration. It touches core hashing infrastructure (`csum-file.[ch]`) but in a minimal way that shouldn't introduce new risks. The change is well-contained and clearly motivated by the immediate needs of the Rust interoperability work.
