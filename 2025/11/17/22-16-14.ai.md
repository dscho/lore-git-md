This is a type standardization patch in the ongoing SHA-1/SHA-256 interoperability series, specifically addressing FFI compatibility between C and Rust code.

The patch changes the `count` parameter type in `hashwrite()` from `unsigned int` to `uint32_t` across both the declaration and implementation. The motivation is to ensure consistent type sizes when calling this function from Rust code, as part of the broader Rust interoperability work. The author notes that `unsigned int` is already 32 bits on all supported platforms, making this a safe change that doesn't affect runtime behavior.

This is a straightforward mechanical update that follows the series' pattern of standardizing types for FFI safety. It builds on previous patches that established the `ObjectID` struct and hash algorithm type standardization. The change is minimal (just 2 lines modified) and appears uncontroversial, though it does touch core hashing infrastructure (`csum-file`). The patch maintains the existing function signature's semantics while making it more explicit about its size expectations for Rust interop.
