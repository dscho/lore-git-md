This is the second phase of the SHA-1/SHA-256 interoperability work, introducing Git's first major Rust implementation for object storage. The 15-patch series from brian m. carlson builds on prior hash-algorithm-agnostic work to enable repositories with different hash algorithms to exchange objects through a new Rust-implemented loose object format.

The series makes several key technical changes: introducing a Rust `ObjectID` struct to handle hash algorithms without relying on global state, adding comprehensive Rust infrastructure for hashing and object mapping, and ensuring proper algorithm validation when looking up objects. The Rust implementation comes with extensive unit testing, particularly for the custom binary search implementation needed for variable-length slices.

Notable improvements since v1 include better documentation (clarifying the object map format's padding/alignment requirements), Rust API refinements (switching to `Result` types and adding helper methods), and build system fixes. The series also preserves the `uint32_t` representation for hash algorithms to maintain compatibility with generated bindings, avoiding potential issues with `None`/`GIT_HASH_UNKNOWN` mismatches.

The changes touch core areas like object storage and hashing while introducing new Rust components, making this a significant step in Git's Rust adoption.
