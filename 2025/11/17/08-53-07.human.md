This is a follow-up discussion in the resolved thread about submodule hash algorithm validation. Martin Wilck suggests adding a warning for the rare case where a SHA-1 submodule in a SHA-256 repository might coincidentally have an OID ending in 24 zeros (which would look identical to a padded SHA-1 OID). 

The thread had previously established that mixed-hash repositories are invalid by design, with brian m. carlson's implementation now preventing their creation. While fsck can't reliably detect these cases due to potential false positives (as explained in brian's earlier email), Martin proposes printing a warning anyway given the false positive probability is extremely low (1 in 16 million).

This is a minor suggestion on top of the already-approved solution, not a request to reopen the core issue. The thread remains resolved with the technical implementation complete, but Martin's idea about warning messages could be considered for future improvements if maintainers agree the warning would be useful despite the small false positive risk.
