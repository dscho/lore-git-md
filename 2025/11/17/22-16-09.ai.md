This is a refactoring patch in the SHA-1/SHA-256 interoperability series, changing the hash algorithm type from `int` to `uint32_t` to ensure consistent representation between C and Rust code. As patch 3/15 in the series, it prepares for upcoming Rust integration by standardizing the numeric type used for hash algorithm identifiers across the codebase.

The change affects several key components: the `object_id` struct (now using `uint32_t algo`), hash algorithm lookup functions (`hash_algo_by_name`, `hash_algo_by_id`, `hash_algo_by_length`), repository configuration functions (`repo_set_hash_algo`, `repo_set_compat_hash_algo`), and scattered usage sites like `oidtree.c` and `serve.c`. The patch maintains all existing behavior while ensuring future Rust code can share these data types without representation differences.

This is a mechanical change with no functional impact, but it's an important prerequisite for the Rust interoperability work. The commit message clearly explains the motivation (Rust FFI compatibility) and the change is consistently applied across all relevant locations. The patch follows the series' pattern of careful type system preparation before introducing Rust components.
