This is a refactoring patch from Patrick Steinhardt's v6 series introducing the `git-history` command, specifically extracting replay logic into shared infrastructure. Phillip Wood provides a positive review of patch 2/11 in the series.

The patch moves commit-picking logic from `builtin/replay.c` into new `replay.[ch]` files to share functionality between `git-replay` and the new `git-history` command. Key changes:
- Extracts `pick_regular_commit()` as `replay_pick_regular_commit()` with proper namespace prefix
- Moves supporting functions like `create_commit()` (now `replay_create_commit()`) and helper utilities
- Updates build systems (Makefile and meson.build) to include new files
- Maintains all existing functionality while making it reusable

Phillip Wood confirms the changes are clean - only adding the namespace prefix to now-public functions. He notes approval of using the replay machinery and the patch's readiness. This foundational refactoring enables the series' later patches to build shared history editing operations while keeping the replay functionality intact. The changes align with the series' goal of creating reusable components for history manipulation commands.
