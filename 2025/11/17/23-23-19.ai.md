Feature patch discussion about unifying Lisp dialect support in Git's userdiff drivers.

Scott L. Burson responds to Junio Hamano's suggestion about creating a unified userdiff driver for Lisp dialects. He identifies a bug in his original regex proposal - the Posix character class incorrectly includes tabs, which he'll fix by using literal spaces. He also notes the need for case-insensitive matching (via 'IPATTERN') since many Lisp dialects are case-insensitive by default.

The key technical discussion revolves around two pattern matching rules: 1) left parenthesis in column 0 indicating top-level definitions (which Scott argues must remain broad to catch all top-level forms), and 2) indented lines starting with "(def" for function/macro definitions. Scott agrees with Junio that a single driver could work across dialects but suggests naming it "lisp" rather than "scheme" for better discoverability.

Scott proposes a new technical solution - adding driver aliasing mechanism to support both names without breaking existing configurations. This would allow the same patterns to be referenced as either "scheme" or "lisp". The thread remains pending Atharva Raykar's evaluation of Scheme compatibility and a decision between unified vs separate drivers.
