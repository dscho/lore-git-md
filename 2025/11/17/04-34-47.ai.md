This is a v2 patch series introducing a 'strip-if-invalid' mode for `git fast-import`'s `--signed-commits` option, addressing signature handling during history rewriting. The series maintains its 3-patch structure from v1 with refactoring (patch 1-2) and feature implementation (patch 3), but now focuses solely on commit signatures while deferring tag support.

Key changes in v2 include: rebasing to avoid translation conflicts, removing dual-signature tests that conflicted with Brian Carlson's Rust-related changes, and enhancing documentation to clarify validation matches `git verify-commit` behavior. The commit message now better explains the technical rationale (with help from Elijah Newren) for why fast-import must handle validation, since neither fast-export nor filter-repo can determine signature validity during history rewriting.

The implementation introduces `GPG_VERIFY_STRIP_IF_INVALID` flag and refactors verification logic into buffer-level operations, with comprehensive tests for OpenPGP/X.509/SSH signatures. While the cryptographic purity concerns about cascading invalidation remain theoretically unresolved, the practical use case (preserving valid older commits during recent history rewrites) is now more clearly articulated. Maintainer Junio Hamano has approved the test restructuring approach for v2.

The series appears technically sound with thorough test coverage, though some design questions remain open about default behaviors and tag support. The changes are well-motivated by `git filter-repo` use cases and carefully avoid breaking changes while providing clearer validation semantics. The response to review feedback demonstrates good maintainer collaboration, making this likely to progress toward inclusion.
