This is the second and final patch in a feature series adding diff algorithm configurability to `git blame`. The patch implements the user-facing functionality, building on the xdiff refactoring from patch 1.

The change makes `git blame` respect both a new `--diff-algorithm` option (mirroring `git diff`'s values: myers, minimal, patience, histogram) and the existing `diff.algorithm` config, with CLI taking precedence. Myers remains the default. The implementation:
- Adds option parsing callbacks in `builtin/blame.c`
- Marks legacy `--minimal` as OPT_HIDDEN while maintaining backward compatibility
- Shares documentation via a new `diff-algorithm-option.adoc` include
- Includes comprehensive tests in `t8015-blame-diff-algorithm.sh` covering:
  - Default behavior verification
  - CLI/config precedence
  - Edge cases
  - Cross-algorithm comparisons
  - Option ordering effects
  - Optimized test script with combined sed operations

The test file demonstrates how different algorithms produce different blame outputs for the same file history, with histogram algorithm showing more distinct attribution patterns than the default myers. The implementation is cleanly integrated with existing diff infrastructure and maintains all prior behavior when not explicitly overriding the algorithm.

This completes the series which has gone through multiple review iterations addressing all technical feedback, with the xdiff changes in patch 1 enabling this clean blame integration. The change is well-motivated as preparation for potential future default algorithm changes while giving users immediate control over blame's diff behavior.
