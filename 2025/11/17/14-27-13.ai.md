This is a follow-up discussion in the ongoing thread about committer identity control in `git commit`. Phillip Wood responds to Matej Dujava's workflow examples, maintaining skepticism about the need for a `--committer` option.

The email clarifies several technical points about identity management:
- Confirms that `includeIf` patterns are a common solution for multi-identity setups when directory structures allow it
- Notes that `git commit --amend --reset-author` updates both identities but resets dates, which may be undesirable
- Explains why environment variables don't work for author identity during rebase (rebase itself sets these variables)
- Suggests `git rebase -x 'git commit --author=... --amend --no-edit'` as the most effective current method to update both identities while preserving dates

Phillip reiterates his core position that since committer identity is automatically corrected from config during amend, a `--committer` option seems unnecessary. This aligns with the maintainer's view that the proposed feature adds complexity without solving a clear problem. The discussion appears to be circling back to fundamental design philosophy rather than technical implementation, with workflow examples failing to shift the core objections.
