CI / build system fix addressing a regression in test failure reporting.

This patch fixes a regression introduced in commit 2a21098b98a where test failure output stopped being visible in CI logs for Dockerized jobs. The root cause was a permissions issue - when the CI jobs were made to run as non-root via a `builder` user, that user lacked write permissions to `$GITHUB_ENV` which is needed to signal which test failures should be included in the logs.

The solution is straightforward: make `$GITHUB_ENV` world-writable before running the tests. Johannes Schindelin notes this technically violates security best practices (the permission should ideally be removed afterwards), but since the file isn't reused, the simpler solution is acceptable. The patch has already been tested in Git for Windows where it helped debug test failures during the v2.52.0-rc0 rebase.

The change affects only `.github/workflows/main.yml`, adding a `chmod o+w` command before the test execution. This restores the previous behavior where failing test output was visible in CI logs, making it easier to diagnose test failures. The commit references an earlier report of this regression that saw no movement, prompting this upstream submission.
