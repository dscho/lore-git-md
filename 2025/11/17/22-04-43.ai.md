Build system patch addressing the `strip` target implementation, expanding on the earlier Scalar inclusion proposal.

Junio Hamano responds to Johannes Schindelin's patch to include `scalar` in the `make strip` target, agreeing with the motivation but suggesting a more comprehensive Makefile restructuring. Rather than just adding `scalar$X` to the `strip` target dependencies, Junio proposes using `$(OTHER_PROGRAMS)` instead of explicitly listing binaries, which would automatically include both `git$X` and `scalar$X`.

The response includes a more extensive Makefile modification that:
1. Introduces a new `OTHER_ARTIFACTS` variable for non-program files (like DLLs)
2. Moves DLL references from `OTHER_PROGRAMS` to `OTHER_ARTIFACTS`
3. Updates both the `strip` target and `artifacts-tar` target to use these variables
4. Raises the question of whether similar changes are needed in CMake and meson builds

This suggests the original patch was too narrowly focused on just the Scalar case, while the underlying Makefile structure could be improved to handle all similar cases more cleanly. The proposed changes would affect build artifact handling beyond just the stripping behavior, potentially impacting Windows/MSYS2 builds where DLL inclusion is important.

Key technical points:
- Changes to `Makefile` variables: `OTHER_ARTIFACTS` added, `OTHER_PROGRAMS` usage modified
- Build targets affected: `strip` and `artifacts-tar`
- Windows-specific consideration: DLL handling via `INCLUDE_DLLS_IN_ARTIFACTS`
- Cross-build system question: CMake/meson equivalents not yet addressed

The response indicates this simple one-line change has uncovered a broader build system design question about how different types of build artifacts should be categorized and processed.
