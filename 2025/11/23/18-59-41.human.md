This is patch 16/19 in Patrick Steinhardt's series refactoring Git's object database streaming interface, continuing the work to move implementation details into their proper subsystems. 

The patch relocates the packed object stream implementation from streaming.c to packfile.c, introducing a new public interface `packfile_store_read_object_stream()`. This follows the same pattern as the previous patch that moved loose object handling - encapsulating backend-specific code while maintaining the generic streaming interface. The change moves 128 lines into packfile.c while removing 135 lines from streaming.c, with minimal behavioral changes.

The implementation remains largely the same, just better organized - the packed object stream still handles non-delta objects (commits, trees, blobs, tags) by managing zlib inflation state and packfile windowing. The new location makes more sense architecturally since packfile.c already handles most other packfile operations.

This continues the series' steady progress in separating concerns between the generic streaming interface and backend implementations. The change is straightforward and builds on the type-safe stream containers and public stream interface established in earlier patches.
