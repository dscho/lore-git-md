This is part 7/19 of Patrick Steinhardt's object database streaming interface refactoring series, focusing on creating a dedicated structure for loose object streams. The patch continues the series' architectural improvements by extracting loose object stream implementation details from the union in `struct odb_read_stream` into a new `struct odb_loose_read_stream`.

The change introduces a type-safe container for loose object streams, mirroring the approach taken for in-core streams in patch 6/19. The 44-line diff moves all loose-stream-specific fields (mapped data, size, header buffers) into the new structure while maintaining the same functionality. The patch updates all related functions (`read_istream_loose`, `close_istream_loose`, `open_istream_loose`) to work with the new structure through proper casting.

Key technical changes include:
- New `struct odb_loose_read_stream` containing the base stream plus loose-specific fields
- Conversion of stream operations to use the new structure while preserving existing behavior
- Maintenance of zlib inflation state handling through the base stream
- Proper memory management of mmap'd regions during stream lifecycle

This continues the series' progression toward type-safe stream implementations, following the pattern established for in-core streams. The change is part of the larger effort to enable pluggable ODB backends by removing implementation details from the core streaming interface.
