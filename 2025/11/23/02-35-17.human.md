This is the final patch in Junio C Hamano's 12-part series implementing comprehensive handling of incomplete-line whitespace errors (WS_INCOMPLETE_LINE) across Git's diff/apply pipeline. The series has now reached its conclusion with this enforcement patch that applies the new whitespace rules to Git's own codebase.

The patch updates Git's `.gitattributes` to enable incomplete-line checking for C/header files (`*.[ch]`) and shell scripts (`*.sh`), while explicitly excluding AsciiDoc documentation (`*.adoc`) from these checks. Phillip Wood caught and corrected a syntax issue in the previous version regarding proper attribute negation (using `-indent` rather than `!indent`), which has been incorporated here.

The change means Git will now flag missing newlines as whitespace violations during both diff generation and patch application for the project's source files. This completes the end-to-end implementation that was developed across the series, with consistent handling from detection through correction. The enforcement is deliberately scoped to exclude documentation formats where incomplete lines may be intentional.
