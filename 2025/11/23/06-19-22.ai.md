This is a technical discussion about the parse_int() helper function being introduced in the ASan hardening series, specifically addressing feedback from Phillip Wood about input validation.

The email shows Junio Hamano responding to Phillip's concerns about two aspects of the parse_int() implementation: (1) allowing multiple '-' signs (where strtol() only allows one), and (2) accepting standalone '-' as valid input. Junio acknowledges these are technically correct observations but argues against adding complexity to enforce stricter validation, noting his own attempt to do so resulted in messy code.

Junio includes an alternative implementation attempt that:
- Handles whitespace skipping
- Allows exactly one optional sign (+/-)
- Validates digit presence after sign
- Checks for integer overflow
- Returns proper error codes

The discussion represents the final open question in the otherwise-approved ASan series - whether to refine parse_int()'s input validation before integration. Junio's position suggests the current implementation is acceptable despite being slightly more permissive than strtol(), as stricter validation would complicate the code without clear benefit. This leaves Phillip's feedback as a potential (but not required) follow-up improvement.
