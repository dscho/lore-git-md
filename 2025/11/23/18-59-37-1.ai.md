This is patch 12/19 in Patrick Steinhardt's object database streaming interface refactoring series, focusing on changing how object sources create streams. The patch shifts from a two-phase lookup (first finding object info, then creating stream) to having sources directly create streams when possible.

Key technical changes:
- Removes intermediate `odb_read_object_info_extended()` call in stream creation
- Modifies `open_istream_loose()` to take an `odb_source` parameter instead of repository
- Updates `open_istream_pack_non_delta()` to handle its own object info lookup
- Changes `istream_source()` to first try packed objects, then iterate through loose sources
- Introduces a semantic change in object selection precedence - now uses source list order rather than hardcoded packed-over-loose preference

The patch acknowledges this changes behavior when objects exist in multiple sources (now favoring earlier sources over later ones, regardless of packed/loose status), but argues this is safe since objects with same OID should have identical content. The commit message notes this is part of making the streaming interface more pluggable by reducing its awareness of backend details.

This continues the series' architectural direction of moving responsibility to object sources while simplifying the streaming interface. The changes touch 65 lines in streaming.c (24 added, 41 removed), primarily restructuring the stream creation flow. The patch builds on previous work that containerized stream types and extracted packfile info handling.
