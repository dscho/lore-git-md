This is patch 12/19 in Patrick Steinhardt's series refactoring Git's object database streaming interface. The patch changes how object streams are created by shifting responsibility to individual object sources rather than first looking up object info through `odb_read_object_info_extended()`.

The key change is moving from a two-step process (look up object info, then create stream) to having sources directly attempt to create streams. This eliminates redundant source iteration and better aligns with the series' goal of making the streaming interface more pluggable. The patch notes this does subtly change object selection precedence - now favoring loose objects from earlier sources over packed objects from later ones - but argues this shouldn't matter in practice since objects with the same OID should have identical content regardless of source.

The implementation removes 41 lines while adding 24, simplifying the control flow in `istream_source()` by having it directly try packed then loose sources. This continues the series' architectural improvements while introducing one intentional but low-risk behavioral change that Patrick and Junio have discussed. The patch appears well-considered and fits cleanly into the larger refactoring effort.
