Bugfix for `--shallow-since` edge case in shallow clone functionality. This is version 2 of the patch, incorporating feedback from Junio Hamano on improving the commit message and adding test coverage.

The patch addresses an issue where shallow clones using `--shallow-since` could incorrectly include descendant commits as border commits when both parent and child commits appear in the initial border candidate list. The current implementation would mark some commits as borders that should not be, potentially leaving them unreachable in the cloned repository.

The new implementation introduces a more thorough parent-checking algorithm in `shallow.c` that:
1. Only marks a commit as a border if *all* its parents weren't in the initial candidate list
2. Properly handles cases where some parents are in the candidate list while others aren't
3. Adds a new test case demonstrating the fixed behavior

The commit message has been significantly expanded from v1 to better explain both the problem and solution, and now includes a concrete test scenario that can be run to verify the fix. The technical approach appears sound, and the added test provides good verification of the edge case being fixed.
