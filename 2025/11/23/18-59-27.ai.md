This is a refactoring patch in Patrick Steinhardt's 19-part series to overhaul Git's object database streaming interface. The patch removes the deferred `open()` callback mechanism from the streaming infrastructure, opting instead for immediate stream opening during initialization.

The change addresses two key issues with the previous design: (1) the awkward two-step initialization where the structure had to be partially populated before calling the open function, and (2) the fact the open callback was only ever called once immediately after being set. The refactoring simplifies the control flow by directly calling the appropriate open function (`open_istream_loose`, `open_istream_pack_non_delta`, or `open_istream_incore`) based on the object source, rather than storing and then invoking a callback.

This change enables future work in the series where stream creation will be fully handled by object sources (like the loose object source) rather than requiring partial initialization first. The patch modifies `istream_source()` to make direct calls to the opening functions and removes the now-unused `open_istream_fn` typedef and `struct odb_read_stream::open` member. The diff shows 15 lines added and 22 removed in streaming.c, with the main changes being the removal of callback indirection and simplification of the object source switching logic.
