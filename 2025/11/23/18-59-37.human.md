This is patch 12/19 in Patrick Steinhardt's ongoing object database streaming interface refactoring series. The patch changes how object streams are created by having the object sources (loose objects vs packed objects) directly create the stream rather than going through an intermediate object info lookup.

Junio notes this subtly changes the semantics - previously the code would use `odb_read_object_info_extended()` which had explicit logic for choosing between duplicate objects (like favoring packed over loose objects). The new version just takes the first source that has the object. Patrick acknowledges this difference but argues it shouldn't matter in practice since the stream interface doesn't expose which source was used and the object contents should be identical regardless.

The change continues the series' architectural direction of simplifying the streaming interface and moving responsibility to the object sources. While technically a behavior change, Patrick doesn't expect it to have practical impact and will update the commit message to explain the rationale. The patch appears well-considered as part of the larger, carefully reviewed refactoring effort.
