This is part 5/19 of Patrick Steinhardt's object database streaming interface refactoring series, focusing on backend-specific stream initialization.

The patch moves stream allocation from the generic `open_istream()` function into the backend-specific opening functions (`open_istream_loose`, `open_istream_pack_non_delta`, `open_istream_incore`). This prepares for a future where each backend will define its own stream structure with `struct odb_read_stream` as the first member, enabling type-safe casting between the generic interface and backend-specific implementations.

Key changes:
- Modifies all backend open functions to take a `struct odb_read_stream **out` parameter instead of a pre-allocated stream
- Updates the loose object handler to allocate early (needed for zlib stream initialization)
- Simplifies the pack non-delta handler by using stack initialization before allocation
- Removes the allocation from `open_istream()` since it's handled by backends
- Maintains all existing functionality while changing the allocation pattern

The change enables future pluggable backends to define their own stream structures while presenting a consistent interface. This follows a similar design to Git's reference database implementation where backend-specific structures embed the base type. The patch is a clean refactoring with no behavior changes, continuing the series' progression toward a more modular ODB streaming architecture.
