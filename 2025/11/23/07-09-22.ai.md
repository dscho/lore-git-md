This is a performance optimization patch in the ongoing thread about `git diff` behavior with `--quiet` and rename/copy detection flags. The patch builds on René Scharfe's previous fix that disabled rename detection in quiet mode, now addressing a secondary performance issue in how unchanged filepairs are handled during copy detection.

The patch introduces a new `diff_same()` function to handle unchanged filepairs more efficiently when `--find-copies-harder` is active, avoiding unnecessary work done by `diff_change()`. The key insight is that unchanged filepairs don't need the full processing that changed files require, and importantly shouldn't set the misleading `has_changes` flag. The implementation cleverly reuses the same filespec for both preimage and postimage through reference counting, effectively halving memory usage for these cases.

Junio Hamano confirms the technical approach is sound, noting the clever memory optimization while correcting a minor inaccuracy in the original description about allocation behavior. The patch shows measurable performance improvements, particularly in large codebases like the Linux kernel repository, where handling many unchanged files is common during copy detection. This follows naturally from the thread's earlier discovery that expensive operations should be skipped when their results won't be used.

The change affects `diff.c` internals, specifically modifying how `show_modified()` processes filepairs when called through `diff_cache()`'s one-way diff pathways. This is a focused optimization that maintains the correct behavior established by the previous fix while making copy detection more efficient. The solution has already been validated through performance testing showing a 1.33x speedup (31.8ms to 23.9ms) for `git diff --cached --find-copies-harder`.
