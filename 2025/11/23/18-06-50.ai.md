This is a discussion about integer parsing and cache-tree serialization formats, emerging from the ASan hardening series.

Junio Hamano responds to Phillip Wood's suggestions about tightening `parse_int()` validation, agreeing that limiting to a single minus sign would be simple. However, he shifts focus to a more fundamental question: why cache-tree stores numbers as text at all. He notes that unlike object headers (which need platform independence), the index is local and already has a 32-bit entry count limit. This suggests cache-tree could use binary formats (network byte order or varint) in a new version 2 format.

Junio describes a backward-compatible transition path where new Git versions could ignore old text-formatted cache-trees and regenerate in the new format, with a one-time performance hit. Older Git versions would continue working, automatically converting when they write the index. The discussion connects to the series' broader theme of hardening parsing code, but suggests a more structural solution than just fixing individual `strtol()` calls.

Key technical points:
- Current cache-tree uses text decimals like object headers, but doesn't need the platform independence
- Index already limits entries to 2^32-1 via network byte order header
- Proposed cache-tree v2 could use binary formats (network byte order or varint)
- Transition plan maintains backward compatibility
- Connects to Phillip's `parse_int()` suggestions but proposes eliminating text parsing entirely

This tangent opens a new design direction while the original ASan series focused on hardening existing code. The suggestion doesn't block the current patches but could inform future work on cache-tree optimization and safety.
