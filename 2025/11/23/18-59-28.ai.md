This is part 3/19 of Patrick Steinhardt's object database streaming interface refactoring series, focusing on propagating object type information through the streaming interface. The patch simplifies how object types are handled during stream initialization by moving the responsibility for type determination entirely to the format-specific callbacks (loose, packed, and in-core object handlers) rather than having it split between multiple layers.

The key change moves the object type storage from being passed as a pointer through multiple function calls to being stored directly in the `odb_read_stream` structure alongside the existing size field. This eliminates redundant type lookups and makes the data flow more straightforward. The format-specific callbacks now write directly to the stream's type field, which is then copied to the caller's pointer when the stream is fully initialized.

This change is part of the larger effort to clean up and standardize the ODB streaming interface, with this particular patch preparing for the removal of an intermediate `odb_read_object_info_extended()` call in a subsequent patch. The diff shows 30 lines changed across streaming.c, with the main changes being the addition of the type field to the stream structure and the removal of type parameters from various callback signatures.

The patch maintains all existing functionality while making the internal implementation more consistent. It follows the series' overall direction of simplifying the streaming interface and reducing redundant operations, though it doesn't yet remove the redundant lookup it mentions - that will come in a later patch.
