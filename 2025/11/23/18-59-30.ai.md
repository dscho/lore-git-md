This is a refactoring patch in Patrick Steinhardt's 19-part series to overhaul Git's object database streaming interface. The email is a response to Junio Hamano's feedback on patch 2/19, which removes the deferred `open()` callback mechanism from the streaming interface.

The key discussion point is clarifying the motivation for removing the callback - Patrick explains that storing the `open()` callback in the stream structure is unnecessary since it's only called once during initialization. Junio agrees this is a valid simplification, noting the open methods don't cascade and can be handled directly in `istream_source()`.

The technical change makes the initialization flow more straightforward by:
1. Eliminating the intermediate step of storing the callback
2. Having `istream_source()` open streams immediately
3. Preparing for future changes where stream allocation will move to source-specific logic

This patch (2/19) is part of the broader architectural improvements to:
- Simplify initialization flows
- Remove unnecessary indirection
- Establish clearer subsystem boundaries
- Enable future backend-specific stream implementations

The discussion shows consensus on the approach, with Patrick addressing Junio's questions about the phrasing of the rationale and agreeing to drop an unnecessary diff hunk from the commit message. This represents one of the early foundational changes in the series that enables subsequent refactorings.
