This is a discussion about potential improvements to cache-tree integer parsing and storage format, building on the ASan hardening series.

Junio Hamano responds to Phillip Wood's suggestions about tightening the `parse_int()` implementation (changing a `while` to `if` for minus signs and improving empty input handling). While acknowledging these could work, Junio takes the opportunity to explore a more fundamental question: why cache-tree stores numbers as text in the first place.

He notes the textual format was originally chosen for platform independence (like object headers), but suggests this may be overkill for the index which is local-only. With cache-tree being an optional extension, he proposes a hypothetical version 2 format that could store numbers more efficiently using binary formats like network byte order or varint encoding. This would avoid string parsing entirely while maintaining compatibility - older Git versions would simply rebuild the cache-tree when encountering the new format.

The discussion remains speculative but highlights an interesting architectural consideration. Junio's response shows openness to Phillip's incremental improvements while also thinking bigger about long-term design.
