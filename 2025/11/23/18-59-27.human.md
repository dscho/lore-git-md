This is a refactoring patch in Patrick Steinhardt's 19-part series to overhaul Git's object database streaming interface. The patch removes an indirect function call pattern where stream initialization was split into two steps - first storing an "open" callback in a struct, then immediately calling it. The change simplifies the code by making stream initialization direct and immediate, which will help with future work to move stream creation fully into backend-specific code.

The patch eliminates the `open_istream_fn` callback type and modifies `istream_source()` to call the appropriate backend-specific open functions directly. This removes some indirection where the code previously stored a function pointer only to call it right away. The change is cleanly implemented with straightforward logic changes to the streaming backend selection code.

This appears to be a well-justified intermediate step in the larger refactoring effort, removing an unnecessary abstraction that was getting in the way of the planned architecture. The commit message clearly explains the motivation and the change fits naturally with the series' goal of making the streaming interface more direct and backend-oriented.
