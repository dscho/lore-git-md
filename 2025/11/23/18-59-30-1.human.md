This is part of Patrick Steinhardt's ongoing refactoring of Git's object database streaming interface (patch 5/19 in the series). The change moves stream allocation into backend-specific functions rather than doing it upfront, as preparation for making the streaming backend system more pluggable.

The patch reorganizes how stream objects are created - instead of allocating a generic stream structure first and then filling it via backend-specific functions, each backend now handles its own allocation. This enables future patches to use backend-specific structures that embed the generic `odb_read_stream` as their first member (similar to how ref backends work), while still presenting a consistent interface to callers.

The changes touch only streaming.c, modifying the loose object, packed object, and in-core stream opening functions to handle their own allocations. Error handling remains robust, with proper resource cleanup on failure paths. This is a well-contained change that follows the series' architectural direction while maintaining existing functionality.
