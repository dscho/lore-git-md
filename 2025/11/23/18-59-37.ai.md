This is patch 12/19 in Patrick Steinhardt's object database streaming interface refactoring series, focusing on how object sources create streams. The patch changes the object selection logic to iterate through available sources rather than using `odb_read_object_info_extended()`'s precedence rules.

Junio C Hamano raised a concern that this changes the explicit precedence rules (like favoring packed over loose objects) to whatever order the source list happens to be in. Patrick acknowledges the semantic difference but argues it shouldn't matter in practice since the stream interface doesn't expose the source was used, and objects with the same OID should have identical content regardless of source. He plans to update the commit message to explain this rationale.

The change continues the series' architectural direction of moving responsibility to object sources while simplifying the streaming interface. This patch builds on earlier work that containerized stream types and moved allocation to backend-specific functions. The discussion highlights an intentional but low-risk behavioral change that maintains the series' goal of cleaner subsystem boundaries while preserving functional correctness.
