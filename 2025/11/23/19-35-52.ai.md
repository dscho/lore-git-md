Bugfix for `--shallow-since` edge case in shallow clone functionality, addressing incorrect handling of descendant relationships between border commits. This is version 2 of the patch, responding to Junio C Hamano's review requesting better documentation and test coverage.

The patch modifies `shallow.c` to fix a case where the current implementation could mark both parent and child commits as borders during a `--shallow-since` clone, leading to unreachable border commits. The new algorithm introduces a `must_not_be_shallow` state and more thorough parent flag management to ensure all border commits remain reachable after grafting. Key changes include:

1. More detailed commit message explaining the problem (border commits becoming unreachable) and solution (new parent inspection logic)
2. Expanded code comments documenting the 4-step painting algorithm for commit states (NOT_SHALLOW/SHALLOW flags)
3. New test case 'clone shallow since all borders reachable' that creates a repository with parent/child relationships and verifies all border commits remain reachable after cloning

The technical approach remains similar to v1 but with better justification and documentation. The test demonstrates the fixed edge case where a merge commit and its parents are properly handled as borders. The patch now follows Git conventions with "shallow:" prefix in the subject line.
