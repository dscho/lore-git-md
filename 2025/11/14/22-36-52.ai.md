This is part 6 of Ezekiel Newren's xdiff refactoring series, focusing on type safety improvements for Rust FFI compatibility. The patch splits the dual-purpose `ha` field in `xrecord_t` into two distinct fields: `line_hash` (a `uint64_t` hash of the line content) and `minimal_perfect_hash` (a `size_t` index used in diff algorithms). 

The change clarifies the previously confusing dual role of `ha`, where it served both as a content hash and as a unique identifier for line comparison. The new separation makes the code's intent more explicit - `line_hash` handles content hashing while `minimal_perfect_hash` provides unique identifiers for the patience and histogram diff algorithms. This matches the thread's overall goal of improving type safety and documentation for cross-language interoperability.

The patch updates all xdiff algorithms (xdiffi.c, xhistogram.c, xpatience.c) to use the new field names and types. The changes are mechanical but extensive, touching comparison functions, hash table operations, and line matching logic. The `minimal_perfect_hash` field uses `size_t` to match Rust's slice indexing requirements, avoiding casts on the Rust side.

This continues the series' pattern of behavior-preserving changes with explicit type safety at interface boundaries. The split increases memory usage (adding a field to each xrecord_t) but provides clearer semantics. The changes align with maintainer feedback from earlier in the thread regarding type mapping strategies and documentation.
