This is a follow-up discussion about commit message conventions for AI-assisted development, specifically addressing the use of `Co-developed-by` versus `Co-authored-by` trailers. The email comes from Jiang Xin in response to Kristoffer Haugsbakk's question about the distinction between these trailers when attributing AI tool contributions.

Jiang Xin provides background on their team's practices at Alibaba Cloud, where they use various AI coding assistants (Cursor, Claude Code, Gemini-CLI, etc.) and developed a git commit-msg hook to track AI tool usage. They explain choosing `Co-developed-by` specifically to distinguish AI tools from human collaborators (who would use `Co-authored-by`), allowing clear tracking of both human contributors and the AI tools they employed. The email includes an example commit message showing both trailer types used together.

The response references prior discussion in the Linux kernel community, linking to a proposal by Sasha Levin (NVIDIA) about similar conventions for AI attribution. This is a meta-discussion about development practices rather than technical changes to the code - the underlying patch series (fixing UTF-8 alignment issues) remains unchanged.
