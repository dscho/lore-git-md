This is a discussion about the deprecated `git whatchanged` command and its potential restoration. Kristoffer Haugsbakk responds to Eduard Bloch's request to bring back the command by pointing out a workaround: users can create an alias for `git whatchanged` in Git versions (2.51.1 and later) that maps to `git log --raw --no-merges`. This provides the same typing convenience (6 keystrokes with tab completion) while avoiding the deprecation warning.

The email clarifies that the exact replacement for `git whatchanged` is `git log --raw --no-merges`, not just `git log --raw` as previously mentioned. The workaround is not available in Git 2.51.0 due to a limitation in aliasing built-in commands, but this restriction was lifted for deprecated commands in later versions.

The discussion highlights the tension between command-line ergonomics and deprecation policies. While the original poster argues strongly for restoring the command purely for typing convenience, this response offers a practical solution that maintains the workflow without requiring changes to Git itself. The exchange also reinforces the point that the deprecation warning could be clearer about the recommended replacement.
