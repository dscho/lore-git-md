This is a maintainer response in the ongoing discussion about AI tool attribution in commit messages, separate from the technical UTF-8 alignment fixes that were the main focus of the thread.

Junio C Hamano raises several concerns about Jiang Xin's proposal to use `Co-developed-by` trailers for AI tool attribution. The core argument is that while disclosure of tool usage is good, AI tools shouldn't receive special treatment compared to other development aids like static analyzers or Coccinelle. The response questions what value these trailers provide to the project beyond corporate metrics tracking, noting that:

1. Existing practice already documents tool usage in commit messages without dedicated trailers
2. The submitter's obligations (DCO, code reviewability) remain unchanged regardless of AI involvement
3. AI tools introduce unique licensing risks since they may unknowingly reproduce copyrighted code
4. The project bears no additional liability for AI-generated code versus other forms of problematic contributions

The tone is skeptical of formalizing AI attribution through commit trailers, suggesting the current practice of describing tool usage in the commit message body is sufficient. This maintains the thread's split focus between the now-complete technical solution for CJK alignment and the broader policy question about AI contribution norms.
