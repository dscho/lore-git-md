This is part 7 of Ezekiel Newren's xdiff refactoring series, continuing the type safety improvements for Rust FFI compatibility. The patch converts the `nrec` field in `xdfile_t` from `long` to `size_t`, as it represents a count of records (array elements) rather than a potentially negative value. This change affects multiple xdiff algorithm implementations (xdiffi.c, xemit.c, xmerge.c, xpatience.c, xprepare.c) which all needed corresponding casting when comparing against the new `size_t` field. The commit message notes `nrec` is used for both record counting and tracking changed lines.

The change follows the established pattern of the series by using explicit casting at interface boundaries while maintaining backward compatibility. Like previous parts, this is a mechanical update that preserves behavior while improving type safety. The patch shows careful attention to all comparison points where `nrec` is used, adding appropriate casts to maintain existing logic. This continues the incremental approach of updating one type at a time across the xdiff subsystem.
