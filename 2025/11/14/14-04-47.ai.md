Documentation patch improving cross-references in `git-commit` manpage. This patch adds missing links to `git-status(1)` for several `git commit --dry-run` format options (`--branch`, `--long`, `--null`) where the original text referenced status concepts without proper documentation pointers. The changes make the manual more navigable by ensuring related commands are properly linked.

The patch standardizes the documentation style by:
1. Adding a `git-status(1)` reference for `--branch` to match how `--short` is documented
2. Explicitly stating `--long` format matches `git-status` default output
3. Replacing a bare "status" mention with a proper `linkgit` reference for `--null`

The commit message notes this was inspired by inconsistencies between how similar options were documented in historical commits (7c9f7038 vs f3f47a1e). The changes are purely documentation improvements with no behavioral impact. The patch is focused and well-justified, touching only the intended sections of the manpage.
