This is a bugfix patch series addressing UTF-8 display alignment issues in Git's repository structure output. The problem occurs when displaying CJK (Chinese/Japanese/Korean) characters in the table format used by `git repo` commands, where multi-byte UTF-8 characters cause misalignment due to incorrect width calculations.

The series consists of two patches:
1. Adds new unit tests specifically for UTF-8 width calculations with CJK characters
2. Modifies the table printing logic in `builtin/repo.c` to use `strbuf_utf8_align()` instead of basic printf formatting

The issue was discovered during localization work for Git 2.52.0, where Chinese characters in the repository structure output were causing misaligned columns. The author notes they used AI coding tools (Claude Code and Gemini-CLI) to help generate the commits, with proper attribution via Co-developed-by trailers.

Key technical details:
- Adds new test file `t/unit-tests/u-utf8-width.c` with CJK character width tests
- Modifies `stats_table_print_structure()` in `builtin/repo.c` to handle UTF-8 properly
- Touches build files (Makefile, t/meson.build) to include new test
- Uses existing `strbuf_utf8_align()` utility function

The changes appear focused and well-motivated, with test coverage added for the specific issue. The use of AI tools is transparently disclosed, and the problem being solved (UTF-8 display alignment) is a known class of i18n/l10n issues in terminal output.
