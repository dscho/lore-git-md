This is part 7 of Ezekiel Newren's ongoing xdiff refactoring series, which continues the type safety improvements for Rust FFI compatibility. The patch changes the `nrec` field in `xdfile_t` from `long` to `size_t`, as it represents counts of elements in arrays and should use the standard size type.

The change is mechanical but widespread, requiring explicit casts in many places where `nrec` is compared with other `long` values. The patch updates all xdiff algorithms (xdiffi.c, xemit.c, xmerge.c, xpatience.c, xprepare.c) to handle the type conversion safely. The commit message notes this is particularly important because `nrec` describes array element counts for both `recs` and `changed` arrays.

This follows the series' established pattern of incrementally updating types while maintaining backward compatibility. The changes are behavior-preserving and have already received maintainer feedback in earlier parts of the series. The patch appears well-executed with thorough updates across all affected files.
