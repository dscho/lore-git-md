This is a follow-up discussion about the ongoing submodule gitdir path encoding series, focusing on migration challenges for existing deployments. Josh Steadmon from Google provides real-world feedback about their internal use of an early version of this encoding scheme.

Google has been using a similar submodule encoding approach for years without the new `extensions.submoduleEncoding` config. While testing shows the new series still works with their pre-encoded submodules, Josh raises two practical concerns about migration: 

1) There's no automatic way to migrate existing repos to use the new extension config, requiring manual intervention for each repository. Google can't distribute this via their normal config distribution system since repository format extensions must be set locally.

2) They'd like a way to enable the encoding by default for new repositories, similar to `init.defaultObjectFormat`, rather than requiring command-line configuration.

Josh suggests possibly carrying a downstream patch to force-enable the extension but is soliciting ideas from the list for better solutions. The email serves as both a status update about real-world compatibility and a request for input on configuration migration strategies, particularly relevant for large-scale deployments like Google's. The technical implementation itself appears sound, with the discussion now shifting to deployment concerns.
