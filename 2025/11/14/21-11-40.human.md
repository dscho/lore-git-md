This is a follow-up in the SHA-1/SHA-256 interoperability patch series, specifically addressing Rust CI warnings that were introduced by recent CI changes. Junio C Hamano points out that Clippy (Rust linter) warnings are appearing in patches 12 and 13 of the series, and provides a temporary workaround patch to make the CI pass.

The changes are mostly mechanical Rust style fixes:
- Replacing `assert_eq!(*, true/false)` with `assert!()` or `assert!(!)`
- Removing unnecessary borrows in function calls
- Adding a type alias for a complex test vector type

Junio notes that while some of these are reasonable style improvements, the first hunk in `src/loose.rs` may need more careful review from someone familiar with the code. The changes don't affect functionality but help align the code with Rust best practices as detected by Clippy.

This email shows the careful scrutiny being applied to Git's first major Rust adoption, with the maintainer actively helping to resolve CI issues while flagging areas that need deeper review from the original author (brian m. carlson). The changes are part of the ongoing refinement of the interoperability series before it can be merged.
