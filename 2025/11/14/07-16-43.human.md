This is a bug report follow-up about fsmonitor daemon processes failing to terminate properly on macOS. The original report identified this as a macOS 26 (Tahoe)-specific issue where detached fsmonitor daemons would accumulate and never terminate, causing resource exhaustion and locked repositories.

Koji Nakamaru adds that they've observed similar behavior on earlier macOS versions (Sequoia 15.7.2), suggesting the problem may not be entirely Tahoe-specific. They confirm the workaround of disabling fsmonitor globally or only enabling it for specific large repos, and note the daemons can be manually stopped via `git fsmonitor--daemon stop` or `pkill`.

The thread shows this is a serious issue affecting all Git clients and builds on macOS, with users reporting thousands of orphaned processes. While Apple has been notified (FB20956467), there's no clear solution yet. The persistence of the issue across macOS versions suggests it may require deeper investigation into Git's daemon spawning behavior rather than just a macOS 26 compatibility fix.
