This is part 6 of a 10-part series refactoring xdiff's core data structures for better type safety and Rust FFI compatibility. The patch splits the `ha` field in `xrecord_t` into two distinct fields: `line_hash` (a fixed-width hash of the line content) and `minimal_perfect_hash` (used for array indexing). 

The change increases memory usage per record by 33% (from one `ulong` to two 8-byte fields), but this was previously discussed and accepted as a reasonable tradeoff. The patch also includes a nice simplification in `xdl_classify_record()` where a cast can now be eliminated thanks to the clearer type separation.

Maintainer Junio Hamano notes the memory impact is acceptable and approves of the cleaner code that results from the change. The patch builds on earlier discussion in the thread, incorporating suggestions from Phillip Wood. This appears to be a well-considered change that advances the series' goal of modernizing xdiff's type system while maintaining behavior.
