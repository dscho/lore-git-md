This is a follow-up discussion about handling mixed SHA1/SHA256 repositories, specifically regarding submodule usage in openSUSE's packaging workflow.

Marc Branchaud suggests an alternative approach to Martin Wilck's problem of wanting to use SHA1 upstream repositories as submodules in SUSE's SHA256 superprojects. Rather than mixing hash algorithms (which the thread has established is unsupported and considered repository corruption), Marc proposes creating SHA256 mirrors of the upstream SHA1 repositories. This would allow SUSE to use submodules while maintaining hash consistency.

The suggestion draws a parallel to Git's early days when people created Git mirrors of Subversion repositories. Marc speculates that such mirrors could potentially be kept up-to-date automatically, though he's unsure whether brian m. carlson's SHA-256 interoperability work would allow a SHA256 repo to have a SHA1 remote. Even if not, he suggests scripting a translation process could be feasible.

This email doesn't introduce new technical changes but offers a practical workaround suggestion for SUSE's deployment scenario. The thread has already established that mixed-hash repositories are intentionally unsupported, so Marc's proposal provides a constructive path forward while respecting Git's technical constraints. The suggestion also hints at potential benefits for encouraging upstream adoption of SHA256.
