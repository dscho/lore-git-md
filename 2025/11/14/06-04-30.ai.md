Bugfix for OSX keychain credential helper addressing credential storage skipping issue. This is version 2 of the patch, incorporating feedback from Junio Hamano and brian m. carlson.

The patch fixes a regression introduced in e1ab45b2 where the credential helper would incorrectly skip storing valid credentials from other helpers due to an oversimplified `state_seen` flag. The key changes are:

1. Replaces the boolean `state_seen` flag with an encoded string state containing full credential details (host, port, path, username, password) for accurate comparison between get/store operations
2. Switches from custom string buffer utilities to using Git's standard `strbuf.h` and `wrapper.h` functions as requested in review
3. Updates both Makefile and meson.build to properly link with libgit.a
4. Adds proper memory management for the state string

The technical implementation now:
- Uses `struct strbuf` instead of custom `struct sb`
- Leverages `xstrdup()` and `free()` for state string management
- Maintains the same security characteristics as the original credential helper protocol
- Preserves backward compatibility

The patch appears well-tested and addresses all major concerns raised in the review. The changes are focused and maintainable, with clear commit messages explaining both the problem and solution. This should resolve the credential storage issue while meeting Git's code quality standards.
