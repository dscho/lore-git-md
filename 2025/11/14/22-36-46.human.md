This is part 4/10 of Ezekiel Newren's xdiff refactoring series aimed at modernizing core xdiff structures for Rust FFI compatibility. The series systematically updates xdiff's type system while maintaining behavior, with this particular version incorporating maintainer feedback from previous iterations.

Key changes in v4 include:
- Documentation updates to clarify type mappings between C and Rust, now avoiding Unicode mentions except where directly relevant
- Keeping dstart/dend fields in their original position within xdfile_t rather than moving them
- Improved justification for changing xrecord_t.ptr from char* to uint8_t*

The series converts all fields in xrecord_t and xdfile_t to unambiguous types, with notable transformations including:
- char* -> uint8_t* for memory pointers
- long -> size_t for size-related fields
- Splitting the ha field into line_hash (uint64_t) and minimal_perfect_hash (size_t)
- Renaming rindex to reference_index for clarity

Maintainers including Junio Hamano have engaged with the series, approving the type mapping approach and accepting the temporary 33% per-record memory increase from field splitting. The work is well-documented and appears carefully executed, with explicit casting at interface boundaries acknowledged as a temporary necessity until future follow-up work can complete the type unification.

This foundational work enables future Rust integration in Git's diff machinery while maintaining backward compatibility. The patch series shows good attention to detail in both technical implementation and documentation, making it a solid contribution to the ongoing modernization effort.
