This is part 4 of Ezekiel Newren's ongoing xdiff refactoring series to modernize core xdiff structures for Rust FFI compatibility. The patch focuses on type safety improvements in the xdiff subsystem.

The change converts the `dstart` and `dend` fields in the `xdfile_t` struct from `long` to `ptrdiff_t`, which is the proper type for pointer-relative offsets (both positive and negative). This matches the semantic meaning of these fields, which track offsets relative to a pointer rather than absolute sizes.

This is a straightforward mechanical change that continues the series' pattern of using more precise types for FFI safety. The patch is small and focused, touching only the type declaration in xtypes.h. It builds on previous work in the series that has already updated other xdiff struct fields to use more appropriate types like `size_t` and `uint8_t*`.

The change is behavior-preserving and follows the established approach of the series, which has already received maintainer approval for its type safety improvements. This appears to be a well-justified change that moves the codebase toward better type safety while maintaining compatibility.
