This is part 6 of Ezekiel Newren's xdiff refactoring series, focusing on type safety improvements for Rust FFI compatibility. The patch splits the dual-purpose `ha` field in `xrecord_t` into two distinct fields: `line_hash` (a straightforward hash of line contents) and `minimal_perfect_hash` (a unique identifier for line comparison). 

The change clarifies the code by separating concerns that were previously conflated - the `ha` field was being used both for initial line hashing and later for unique line identification during diff processing. The new `line_hash` uses `uint64_t` for hash values while `minimal_perfect_hash` uses `size_t` for array indexing, which better matches their respective purposes and improves Rust interoperability by avoiding casts.

The patch updates all xdiff algorithms (histogram, patience, etc.) to use the new field names, with mechanical changes to preserve the same behavior.
