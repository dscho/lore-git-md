This is a follow-up in the OSX keychain credential helper bugfix thread, addressing Junio Hamano's review comments. Koji Nakamaru responds to two key concerns about the patch:

1. **Dependency question**: Acknowledges Junio's point that using Git's standard `strbuf.h` utilities is preferable to custom string implementations, since the helper already links with libgit.a. Koji explains they were following the existing pattern (which has its own `xmalloc()` and `die()`), but agrees to refactor to use libgit utilities.

2. **Security implications**: Confirms the plaintext credential storage in the state buffer was considered, noting this matches the existing credential helper protocol's behavior where credentials are already transmitted in plaintext between helpers. Argues this doesn't introduce new security risks beyond what the protocol already accepts.

The response indicates the patch will be revising the implementation to use standard Git utilities while maintaining the core credential storage fix. The security discussion clarifies the design choice but doesn't propose changes to the credential handling approach. This moves the thread toward resolution while addressing the architectural concerns raised in review.
