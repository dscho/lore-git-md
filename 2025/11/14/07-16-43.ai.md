This is a follow-up to the fsmonitor daemon termination bug on macOS, expanding the scope beyond just macOS 26 (Tahoe). Koji Nakamaru reports observing the same fsmonitor daemon process accumulation behavior on macOS Sequoia 15.7.2 and earlier versions, contradicting the original report that this was specific to macOS 26. The key technical detail remains that `git fsmonitor--daemon run --detach --ipc-threads=8` processes spawn detached and don't terminate when parent applications exit, but this appears to be a broader macOS-wide issue rather than Tahoe-specific.

The email provides additional context about workarounds - while the original reporter suggested disabling fsmonitor globally, Nakamaru shares a more targeted approach of only enabling fsmonitor for specific large repositories. The core problem remains unaddressed: these detached processes must be manually killed via `git fsmonitor--daemon stop` or `pkill`, and they continue to accumulate, causing resource exhaustion and repository lock issues.

This expands the scope of the investigation from a macOS 26 regression to potentially long-standing macOS behavior, though the problem may be more severe or noticeable in Tahoe. The thread now has conflicting reports about version specificity that will need resolution, and no proposed fixes have been offered yet for the underlying daemon lifecycle management issue.
