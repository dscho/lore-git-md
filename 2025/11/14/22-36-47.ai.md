This is a documentation patch in Ezekiel Newren's ongoing xdiff refactoring series for Rust FFI compatibility. It introduces a new technical document `unambiguous-types.adoc` that defines precise type mappings between C and Rust for FFI purposes, with particular attention to edge cases and platform-specific behaviors.

The document provides comprehensive mappings for boolean, integer, floating-point, size, and character types, noting where semantic differences exist between languages. It highlights several problematic areas where Rust's `c_*` types don't reliably match C types across all platforms/compilers, demonstrating how Rust's internal definitions have evolved between versions (1.63.0 vs 1.89.0). The text warns against using Rust enums for FFI due to ABI instability and demonstrates subtle behavioral differences with character types under operations like subtraction and bit shifting.

Key technical points covered include: the implementation-defined nature of C's `char` type, IEEE-754 floating-point assumptions, discouraged use of `uintptr_t`/`ssize_t` for FFI, and platform-specific variations in Rust's `c_long` definition. The document serves as a reference for future FFI work in Git, particularly for the xdiff modernization effort where type safety is critical for cross-language interoperability.

This patch is the first in part 4 of the series (v4 01/10) and builds on previous maintainer-approved work, though it stands alone as documentation rather than code changes. The thorough treatment of type semantics and edge cases suggests it will be valuable reference material for both the current xdiff refactoring and future FFI work.
