This is a follow-up discussion about the SHA1/SHA256 submodule compatibility issue, now focusing on practical deployment solutions rather than technical validation.

Marc Branchaud suggests an alternative approach for openSUSE's use case: maintaining SHA256 mirrors of upstream SHA1 repositories that could then be used as submodules. He draws a parallel to early Git days when SVN repositories were mirrored into Git. The proposal acknowledges the technical constraints established earlier in the thread while offering a path forward that maintains submodule functionality.

Key technical points for future reference:
- Suggests SHA256 mirrors as workaround for SHA1 upstreams
- Questions whether SHA256 repos can have SHA1 remotes (unanswered)
- Proposes automated translation of new commits if direct fetch isn't possible
- Positions this as both a practical solution and migration incentive

The email doesn't introduce new technical changes to Git itself but extends the discussion about real-world deployment strategies following the earlier conclusion that mixed-hash repositories are invalid by design. It represents a constructive next step after the technical validation patches from brian m. carlson and Jeff King.
