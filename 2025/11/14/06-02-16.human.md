This is part 4/10 of Ezekiel Newren's xdiff refactoring series, focusing on type modernization for Rust FFI compatibility. The patch changes `xrecord_t.size` from `long` to `size_t` to properly represent memory sizes, a clear improvement for type safety. However, as Junio notes, this creates temporary messiness with casts to `long` at interface boundaries where dependent functions haven't been updated yet.

The patch touches several xdiff files (xdiffi.c, xemit.c, xmerge.c, xprepare.c) with mechanical updates to handle the type change. Ezekiel acknowledges the current state isn't ideal but explains these are necessary intermediate steps - the casts will be removed in a future series when the calling functions are updated. He notes the mmbuffer_t constraints make the long-vs-size_t distinction moot for now, though int-vs-size_t issues remain for later work.

This is a well-justified change that moves xdiff toward better type safety, though the temporary casting is visibly awkward. The patch maintains behavior while setting up for future cleanups, following the series' incremental approach. Junio's review confirms the technical soundness while highlighting areas needing future attention.
