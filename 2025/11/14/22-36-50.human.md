This is part 4 of Ezekiel Newren's xdiff refactoring series, focusing on type safety improvements for Rust FFI compatibility. The patch changes the `size` field in `xrecord_t` from `long` to `size_t`, which is the more appropriate type for representing memory sizes. 

The change is mechanical but touches several xdiff files (xdiffi.c, xemit.c, xmerge.c, xprepare.c) where the field is used. The patch adds explicit casts where needed to maintain compatibility with existing interfaces that still use `long`. This follows the series' pattern of incremental type safety improvements while preserving behavior.

As part of the ongoing effort to modernize xdiff's internals for better cross-language interoperability, this change aligns with previous patches in the series that updated other fields in the xdiff data structures. The work has already received maintainer engagement and appears to be on track, with careful attention paid to maintaining backward compatibility through the transition.
