This is part 4/10 of Ezekiel Newren's xdiff refactoring series, focusing on type modernization for Rust FFI compatibility. The patch converts `xrecord_t.size` from `long` to `size_t` to properly represent memory sizes, with mechanical updates across xdiff/ (xemit.c, xmerge.c, xprepare.c, etc.). 

The changes introduce temporary casts to `long` at interface boundaries where called functions still expect `long` parameters, particularly in `xdl_emit_diffrec()`, `xdl_recmatch()`, and other diff/merge operations. Junio Hamano notes these casts are messy but acknowledges they're a necessary intermediate step, with the understanding that future patches will update the function signatures to use `size_t` consistently.

Ezekiel clarifies that while `mmbuffer_t` constraints make the `long` vs `size_t` distinction moot for line counts in this series, other `int`-based limits remain to be addressed in future work. The patch includes one clean improvement in `xprepare.c` where a cast is eliminated in `crec->size` assignment. The series maintains backward compatibility while progressing toward type safety, with clear technical debt acknowledged for follow-up work on function signatures and broader xdiff cleanup.
