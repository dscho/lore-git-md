Bugfix addressing incorrect exit status in `git diff` with `--find-copies-harder` and `--quiet`. This patch fixes a specific interaction where the combination of `--find-copies-harder`, `--quiet`, and `--no-ext-diff` flags caused `git diff` to incorrectly report no changes (exit code 0) when changes actually existed.

The core issue stems from how the `quick` optimization in `diff_can_quit_early()` interacts with copy detection. When `--find-copies-harder` is active, `diff_change()` marks all entries as changed (setting `has_changes`), which then triggers the quick-exit optimization prematurely when combined with `--quiet`. The fix simply disables the quick optimization when `find_copies_harder` is set.

The patch includes two new test cases that verify the correct exit code behavior for both the regular and `--no-ext-diff` cases. The test demonstrates that the command now properly returns exit code 1 when changes exist, matching the behavior of `--exit-code`).

This builds on D. Ben Knoble's earlier analysis of the issue, particularly the observation about how `--no-ext-diff` affects the behavior through `diff_from_contents`. The fix is surgical and focused specifically on the quick-exit optimization path, leaving other aspects of the diff machinery unchanged. The change is small (one line in `diff.c`) but effectively addresses the reported issue while maintaining the expected behavior in other cases.
