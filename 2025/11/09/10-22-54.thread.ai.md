This thread introduces a new `--committer` option for `git commit` to provide symmetry with the existing `--author` option. The patch series (currently v1) adds functionality to override the committer identity directly via command line, mirroring how `--author` works today. The implementation in `builtin/commit.c` follows the same pattern as the author handling, adding `determine_committer_info()` parallel to `determine_author_info()`.

Patrick Steinhardt has reviewed the initial version, generally agreeing with the feature's utility while suggesting several technical improvements. His feedback focuses on: 1) reordering documentation to place `--committer` next to `--author`, 2) refactoring to share common infrastructure between committer and author determination logic to reduce duplication, and 3) questioning whether commit lookup should search by committer rather than author when given a pattern. He also notes minor style preferences regarding brace usage in single-line conditionals.

Key technical details:
- New option accepts same formats as `--author`: explicit "Name <email>" or existing commit lookup
- Current precedence remains: command line > environment > config > automatic
- Review suggests extracting shared identity determination logic
- Open question about lookup behavior (search by committer vs author)
- Comprehensive test coverage in t/t7509-commit-authorship.sh (8 new tests)
- Documentation updates in git-commit.adoc pending suggested reordering

The patch addresses an interface inconsistency where committer identity could only be set via environment variables while author had both env vars and a direct option. The review indicates the change is well-scoped but could benefit from implementation refinements in a revision. No fundamental objections have been raised to the feature itself, which is acknowledged as useful for scripting and multi-identity workflows. The author will need to address the code organization points and lookup behavior question in v2.
