This is a bugfix addressing incorrect exit codes from `git diff` with a specific combination of flags. The patch fixes a case where `--quiet` would incorrectly report no changes when used with `--find-copies-harder` and `--no-ext-diff`, even when staged changes exist.

René Scharfe's analysis shows the problem stems from an optimization in `diff_can_quit_early()` that triggers prematurely when `--find-copies-harder` queues unmodified files for copy detection. The patch simply disables this optimization when copy detection is active, ensuring the command properly reports changes. A test case is added to prevent regression.

The fix is straightforward and well-motivated, directly addressing the issue D. Ben Knoble reported where scripts (like git-prompt.sh) could get incorrect status information. The patch includes tests for both the basic case and the `--no-ext-diff` scenario that originally exposed the bug. This looks like a solid solution to a real behavioral inconsistency in Git's diff machinery.
