This thread discusses adding a `--committer` option to `git commit` to match the existing `--author` functionality, allowing command-line override of committer identity. The technical implementation in `builtin/commit.c` has been refined across two versions, with shared identity handling infrastructure and comprehensive test coverage.

ZheNing Hu has driven the discussion with concrete use cases, including corporate workflows where users need to correct misconfigured committer info after the fact - a scenario where repository-level configuration or separate clones (suggested by Jeff King) wouldn't help. Other contributors have added valid use cases like identity switching for CLAs and audit requirements. Patrick Steinhardt emphasizes the scripting advantages of command-line options over environment variables.

While Junio Hamano and others initially questioned whether this functionality was needed beyond symmetry with `--author`, the accumulation of real-world examples has strengthened the case. The discussion has moved past an initial concern about AI co-authorship (now resolved) to focus on the technical and workflow merits. The core debate now balances the principle of symmetry against whether this is truly the best solution compared to existing configuration methods, with the weight of practical examples tilting toward the new option.
