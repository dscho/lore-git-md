This thread discusses adding a `--committer` option to `git commit` to mirror the existing `--author` functionality. The initial proposal and v2 patch series from the author implemented all technical feedback, refactoring identity handling in `builtin/commit.c` to share infrastructure between author and committer paths while adding tests and documentation.

While Patrick Steinhardt approved the feature's utility and Phillip Wood questioned whether existing methods (environment variables, per-repo config) already cover the use cases, Junio C Hamano has now weighed in with deeper skepticism. He distinguishes between the well-established need for author` overrides (which serve legitimate attribution needs) and committer overrides (which primarily benefit scripting scenarios that already have `GIT_COMMITTER_*` environment variables). Hamano questions whether making committer overrides more ergonomic is desirable, suggesting the feature may represent unnecessary interface expansion unless proponents can demonstrate compelling human-facing use cases not well-served by current mechanisms.

The discussion has shifted from technical implementation - which was addressed in v2 - to fundamental design philosophy. The thread now hinges on whether symmetry with `--author` and scripting convenience outweigh potential for misuse and interface bloat. Without stronger justification of real-world needs beyond what environment variables provide, the feature's inclusion appears uncertain.
