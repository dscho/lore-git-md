This is a bugfix patch that implements the architectural solution discussed in the thread for `git diff`'s quiet mode behavior with rename/copy detection. The patch disables rename detection entirely when `--quiet` is used, addressing both the original reported issue and the broader architectural concern that quiet mode shouldn't waste cycles on expensive diff operations that won't be shown.

The key changes are in `diff.c` where the patch modifies `diff_setup_done()` to clear both `detect_rename` and `find_copies_harder` flags when `flags.quick` (set by `--quiet`) is active. This ensures consistent exit codes regardless of rename/copy detection settings. The patch adds two new test cases in `t/t4007-rename-3.sh` that verify the correct exit code behavior with `--find-copies-harder` both with and without `--no-ext-diff`.

This represents a more fundamental solution than the previous fix, which only special-cased `find_copies_harder`. The change aligns with the thread's consensus that quiet mode should skip rename detection entirely, as detecting renames is pointless when no output will be shown. The implementation is clean and minimal, directly addressing the diff machinery's setup phase rather than working around symptoms in the detection logic.

The patch maintains compatibility with existing behavior where `--quiet` without rename detection already worked correctly, while fixing the edge cases that combined quiet mode with copy detection. The test coverage specifically targets the originally reported problematic flag combination (`--cached --no-ext-diff --find-copies-harder --quiet`), ensuring this case won't regress.
