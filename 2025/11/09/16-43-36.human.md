Bugfix for `git diff` quiet mode behavior with rename detection. This patch from René Scharfe implements the architectural solution discussed in the thread, where quiet mode now completely disables rename and copy detection rather than just working around the `find_copies_harder` edge case.

The change makes `git diff --quiet` skip the expensive rename detection machinery entirely when output is suppressed, since the detection work would be wasted when not showing diffs. This fixes the original reported issue where certain flag combinations caused incorrect exit codes, but does so in a more fundamental way than the previous fix.

The patch adds two test cases to verify the exit code behavior with `--find-copies-harder` both with and without `--no-ext-diff`. The implementation is straightforward - when `--quiet` is set (which sets the `quick` flag), the diff options now explicitly disable both `detect_rename` and `find_copies_harder`.

This appears to be the consensus solution from the thread discussion, addressing Phillip Wood's observation that quiet mode shouldn't need rename detection at all. The change is cleanly scoped and well-tested, representing a proper resolution to the original bug report.
