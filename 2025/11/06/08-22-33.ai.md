Part of the 'is-needed' subcommand series for `git maintenance`, this patch integrates the new ref backend optimization checking capability into the pack-refs maintenance task.

The patch modifies `pack_refs_condition()` to use the new `refs_optimize_required()` API introduced in earlier patches, replacing the hard-coded `return 1` that previously forced pack-refs to always run in auto mode. The implementation mirrors the behavior of `git pack-refs --auto` by setting up ref inclusion/exclusion patterns and passing the appropriate optimization flags. A minor header cleanup removes a duplicate `SEEN` definition that conflicted with `revision.h`.

Key technical details:
- Sets up `refs_optimize_opts` with `REFS_OPTIMIZE_PRUNE | REFS_OPTIMIZE_AUTO` flags
- Uses wildcard include pattern ("*") to check all refs
- Returns the optimization requirement status from the backend
- Maintains existing memory management practices with proper cleanup
- Follows the established pattern of returning 0/1 for maintenance task conditions

This change enables the upcoming 'is-needed' subcommand to accurately report whether reference optimization is required without performing it, while maintaining backward compatibility with the existing auto-maintenance behavior. The implementation cleanly integrates with both the refs backend infrastructure and maintenance task system.
