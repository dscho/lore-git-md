Refactoring patch in the reftable optimization series. This is the second of five patches implementing a new `git maintenance is-needed` subcommand to check if maintenance tasks are required without running them.

The patch extracts the compaction heuristics logic from `reftable_stack_auto_compact()` into a new internal function `update_segment_if_compaction_required()`, then uses this to expose a new public API `reftable_stack_compaction_required()`. This allows checking if optimization is needed without actually performing compaction, which will be used by the upcoming maintenance command.

The implementation cleanly separates the checking logic from execution while maintaining the same behavior. The patch includes thorough unit tests that verify the new function matches the existing auto-compaction behavior. This is a well-structured change that builds on the refactoring from patch 1 and sets up the infrastructure needed for the maintenance integration in later patches.

The series has already received positive reviews and appears technically complete, with this patch being a key piece of the optimization checking infrastructure. The changes are focused and maintainable, with clear separation of concerns between checking and performing compaction.
