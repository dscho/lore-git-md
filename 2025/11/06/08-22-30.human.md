This is the first patch in a 5-part series introducing a new 'is-needed' subcommand for `git maintenance`. It's a refactoring change focused on the reftable backend.

The patch modifies `stack_table_sizes_for_compaction()` in reftable/stack.c to directly return compaction segments rather than just table sizes. This eliminates an intermediate step where sizes were calculated only to be immediately passed to `suggest_compaction_segment()`. The change makes the code more efficient and prepares for future functionality that will check whether compaction is needed without performing it.

The implementation looks clean and focused - it changes only what's necessary while maintaining the same behavior. The commit message clearly explains both the immediate benefit (removing redundant calculations) and how this enables future work. This is a solid foundation for the rest of the series, which will build on these changes to implement the new maintenance subcommand.
