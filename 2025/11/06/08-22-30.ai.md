This is the first patch in a 5-part series introducing a new 'is-needed' subcommand for `git maintenance`, focused on ref backend optimization infrastructure.

The patch refactors the reftable stack compaction logic to make it more reusable. It changes `stack_table_sizes_for_compaction()` to directly return compaction segments rather than just table sizes, eliminating an intermediate step where sizes were passed to `suggest_compaction_segment()`. The new `stack_segments_for_compaction()` function combines these operations and handles memory allocation more cleanly.

The change serves two purposes: it simplifies the existing auto-compaction path in `reftable_stack_auto_compact()`, and prepares for future functionality that will check whether compaction is needed without performing it (coming in later patches). The memory management is improved by consolidating the `sizes` array cleanup within the new function.

The patch is technically sound, with clear motivation explained in the commit message. It maintains the same behavior while making the code more maintainable. The change is relatively small (23 lines modified) and focused, touching only reftable/stack.c. This foundational work will be built upon in subsequent patches to implement the new maintenance subcommand functionality.
