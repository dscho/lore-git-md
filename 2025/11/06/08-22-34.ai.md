This is the final patch in a 5-part series introducing a new 'is-needed' subcommand to `git maintenance`. The feature allows checking whether maintenance tasks are required without actually running them, with exit status 0 indicating maintenance is needed and 1 otherwise.

The implementation adds:
- A new `maintenance_is_needed()` function in builtin/gc.c that evaluates task conditions
- Support for `--auto` flag to use the same heuristics as `run --auto`
- `--task` filtering to check specific tasks
- Documentation updates explaining the new subcommand
- Comprehensive tests in t7900-maintenance.sh covering:
  - Basic functionality and exit codes
  - Interaction with `--auto` and config settings
  - Integration with all maintenance tasks (gc, commit-graph, loose-objects, etc.)
  - Removal of a duplicate test case

The patch builds on the ref backend optimization infrastructure from earlier patches (1-3) and maintenance integration (patch 4). It follows the same pattern of using `auto_condition` callbacks for each task type. The implementation is clean separation of concerns - the new subcommand shares the task selection and auto-condition logic with the existing `run` command while avoiding any execution side effects.

Key technical details:
- Uses same `maintenance_run_opts` and task selection logic as `run`
- Evaluates `auto_condition` callbacks when `--auto` is specified
- Returns immediately when any task needs maintenance (no full evaluation)
- Maintains consistent behavior with existing task configurations
- Includes tests for all maintenance tasks with various config combinations

The series has received positive reviews and appears technically complete, with all feedback addressed across the iterations. This final patch provides the user-facing command to query maintenance needs while reusing the existing task infrastructure.
