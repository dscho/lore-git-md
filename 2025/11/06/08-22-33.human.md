This is the fourth patch in a 5-part series introducing a 'is-needed' subcommand to `git maintenance` that checks whether tasks are required without running them. The series has already established infrastructure for checking when ref backends need optimization.

The patch modifies the `pack_refs_condition()` function in `builtin/gc.c` to properly check if reference optimization is needed, rather than always returning true. It uses the new `refs_optimize_required()` API added in earlier patches, configuring it to check all refs with auto-optimization heuristics (matching `git pack-refs --auto` behavior). The change enables accurate reporting of whether ref packing is needed when using the new 'is-needed' subcommand.

The implementation follows the pattern of existing maintenance tasks, setting up ref includes/excludes and cleaning up properly. A minor cleanup removes a duplicate `SEEN` flag definition that conflicted with `revision.h`. The patch maintains the existing behavior when actually running maintenance, only changing the condition check.

This is a straightforward integration of the new ref backend checking capability into the maintenance framework. The change is well-contained and builds on the solid foundation established in the earlier patches, which have already been reviewed. The patch keeps the series moving toward its goal of providing maintenance status checking without execution.
