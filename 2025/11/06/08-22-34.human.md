This is the final patch in a 5-part series introducing a new 'is-needed' subcommand to `git maintenance`. The feature allows users to check whether maintenance tasks are required without actually running them, which is particularly helpful when combined with the `--auto` flag to evaluate the heuristics that normally trigger automatic maintenance.

The patch adds the new subcommand with support for `--task` filtering and `--auto` behavior, returning exit code 0 when maintenance is needed and 1 otherwise. It includes comprehensive documentation updates and extends the test suite to verify the new functionality across all maintenance tasks (gc, commit-graph, loose-objects, incremental-repack, reflog-expire, worktree-prune, and rerere-gc).

The implementation is clean and well-tested, with the tests demonstrating proper interaction with task-specific configuration options. The patch removes a duplicate test case while adding new assertions for the 'is-needed' behavior. The series has already received positive reviews and appears ready for inclusion, providing a useful tool for scripts and automation that need to check maintenance status before deciding whether to run potentially expensive operations.
