Bugfix for gitk's external diff functionality when dealing with renamed files, now at v8. This version addresses all three issues identified in v7 by gitk maintainer Johannes Sixt, completing a series that has evolved through eight iterations.

The patch fixes gitk's inability to properly handle file renames when launching external diffs, whether the original or renamed file is selected. The solution now correctly parses "rename from/to" lines from gitk's diff display (stored in the `ctext` widget) using precise string equal` comparisons with length checks, rather than the previous wildcard matching. It also properly handles cases where either the original or renamed filename is selected in the latter being a regression in v7.

Key improvements in v8 include:
- Fixed rename detection to work when selecting either original or renamed files
- Replaced `string match` with more robust `string equal -length` comparisons
- Maintained Tcl style consistency using `ne` operator
- Keeps the efficient approach of parsing gitk's internal diff display rather than shelling out to Git

The changes are focused entirely on gitk's Tcl script (38 lines added, 2 modified) with no impact on Git core. The implementation remains clean and well-contained, scanning diff headers to extract paths from subsequent "rename from/to" lines. This appears ready for final review and potential inclusion.
