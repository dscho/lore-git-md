This is a refactoring patch that's part of a series to make diff algorithm selection configurable in `git blame`. The patch focuses on the xdiff library internals, specifically fixing an inconsistency in how diff algorithm flags are handled.

The change adds the `XDF_NEED_MINIMAL` flag to the `XDF_DIFF_ALGORITHM_MASK` bitmask, which previously only included flags for patience and histogram diffs. This ensures the minimal diff algorithm is properly cleared when resetting to default settings, fixing potential issues in `merge-ort.c` and `builtin/merge-file.c` where this wasn't happening consistently.

The patch removes now-redundant explicit clearing of the minimal flag in `diff.c` and `merge-ort.c`, since it will now be handled automatically through the mask. This is a technical breaking change for xdiff library consumers, but the thread discussion has established this as the correct approach for consistency. The change is well-justified and has been thoroughly reviewed, with Phillip Wood confirming the technical correctness of the solution.

This is the first of two patches in the series, with the second patch implementing the user-facing `git blame` functionality. The change here provides the necessary xdiff foundation for that feature while also fixing some existing technical debt in the diff algorithm flag handling.
