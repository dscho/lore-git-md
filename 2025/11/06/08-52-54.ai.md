This is a performance fix addressing a regression in tag peeling operations, particularly affecting the reftable backend. The regression was introduced by commit 6ec4c0b45b which added verification of tag types to prevent storing corrupted peeled objects, but inadvertently caused unnecessary object lookups for all references (not just tags).

The patch narrows the verification to only check tagged objects' types (not the tags themselves), restoring performance to pre-regression levels while maintaining the corruption protection. Benchmark results show the fix brings a 3x speedup compared to the regression state, matching original performance. The change affects `peel_object()` and its callers in ref-filter and both ref backends, renaming the verification flag from `PEEL_OBJECT_VERIFY_OBJECT_TYPE` to `PEEL_OBJECT_VERIFY_TAGGED_OBJECT_TYPE` to clarify its purpose.

Key technical details:
- The regression manifested as 3x slower ref writes with reftable and 10x slower ref migrations between backends
- Problem stemmed from verifying object types for all refs, not just tags
- Fix maintains verification for tagged objects to prevent corruption cases
- Changes span object.[ch], ref-filter.c, and both packed/reftable backend implementations
- Performance impact is now limited to actual tag operations rather than all ref writes

The patch appears well-justified with clear benchmarks and maintains the original security benefit while eliminating the broader performance penalty. The analysis of why the regression affected different backends differently (reftable vs files) is particularly thorough.
