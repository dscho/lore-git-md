This is part 3 of a 5-part series introducing a new 'is-needed' subcommand for `git maintenance` to check whether optimization tasks are required without executing them. The patch adds infrastructure to support this feature across Git's reference backends.

The patch introduces a new `optimize_required` callback in the `struct ref_storage_be` interface, which each backend must implement to report whether optimization is needed. The implementation provides this functionality for all existing backends (files, packed, reftable, and debug), with appropriate logic for each:

- The files backend checks if refs should be packed
- The packed backend always reports no optimization needed (since it's already optimized)
- The reftable backend uses its existing compaction heuristics
- The debug backend wraps another backend's implementation

The change is well-contained and builds on existing optimization infrastructure. It's part of a larger effort that has already received positive review feedback, with this patch specifically focusing on the backend plumbing needed to support the new maintenance subcommand. The implementation looks clean and properly handles the different backend behaviors while maintaining consistent semantics.
