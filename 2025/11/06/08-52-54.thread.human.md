This thread addresses a performance regression in tag peeling operations, particularly impacting the reftable backend, caused by overly broad verification of tag types in commit 6ec4c0b45b. The proposed fix narrows verification to only check tagged objects' types, restoring performance while maintaining corruption protection. Key changes touch `peel_object()` and ref-filter code, with benchmarks showing 3x speedups for reftable writes and 10x improvements for ref migrations between backends.

Junio Hamano has reviewed and approved the solution, confirming it properly balances performance and security by focusing verification where it matters most. Patrick Steinhardt later clarified the original rationale - the broader verification was implemented to catch remote-originated tag corruption during writes rather than burdening every read operation. While the performance impact is real, the tradeoff makes sense since corruption typically enters through remotes and write-side checking avoids penalizing normal operations. The discussion has converged with maintainer approval, and the fix is queued for inclusion.
