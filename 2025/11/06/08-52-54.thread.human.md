This thread addresses a performance regression in tag peeling operations, particularly impacting the reftable backend, caused by commit 6ec4c0b45b which added overly broad verification of tag types. The regression led to unnecessary object lookups for all references, slowing ref writes by 3x with reftable and ref migrations by 10x. Patrick Steinhardt proposed a fix that narrows verification to only check tagged objects' types, restoring performance while maintaining corruption protection.

Junio C Hamano has now reviewed and approved the solution, confirming the original verification was overzealous by checking both tag and tagged object types when only the latter was needed. He agrees the fix properly maintains security while eliminating the performance impact, and indicates the patch will be queued for inclusion. The changes modify `peel_object()` and ref backend implementations, with benchmarks showing the fix brings performance back to pre-regression levels. This appears to be the final resolution, with the maintainer's approval signaling the technical approach is sound.
