This is a feature patch series that adds an 'is-needed' subcommand to `git maintenance` to check whether maintenance tasks are required without performing them. The series builds on previous work to expose optimization checks in the refs backend and integrates this with the maintenance framework.

The 5-patch series has evolved through review, with v3 addressing the last remaining concern about code duplication by refactoring the reftable compaction logic into a shared function. The implementation now cleanly separates the checking logic from execution while maintaining the same heuristics. The series has received Reviewed-by tags from Patrick Steinhardt and Justin Tobler, indicating technical approval.

Key aspects of the series:
- Patches 1-3 add backend infrastructure to check if optimization is needed (for files, packed, and reftable backends)
- Patch 4 integrates this with the maintenance's pack-refs condition check
- Patch 5 adds the new 'is-needed' subcommand with --task filtering and --auto support

The implementation provides a maintainable foundation for future extensions and handles auto-condition logic with clear exit code semantics (0 when maintenance is needed, 1 otherwise). The series depends on two other in-flight topics but is otherwise ready for integration.
