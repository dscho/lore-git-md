This is a technical response in the ongoing discussion about improving `git blame --reverse` functionality for tracking line removals. Ben Knoble suggests using `git log -S` (pickaxe search) as a workaround to identify when specific lines were removed, rather than waiting for potential enhancements to the blame machinery.

The response provides concrete usage examples showing how to search for when a line containing "hello world" disappeared from a file, starting from a known commit (deadbeef) where it was present. The technique relies on the pickaxe's ability to track content changes rather than line presence/absence tracking.

Key technical details:
- Demonstrates practical use of `git log -S` with file path and commit range
- Notes the importance of using sufficiently unique line content
- Suggests function/variable names as alternative search terms when full line content isn't available
- Implicitly contrasts this immediate solution with the proposed blame enhancement

This represents a pragmatic alternative approach while the more comprehensive blame improvements are being discussed, though it requires manual operation and line-specific searches rather than blame's automated tracking. The suggestion doesn't address the merge commit confusion problem directly but provides a workable solution for many cases.
