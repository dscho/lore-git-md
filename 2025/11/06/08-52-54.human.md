Performance bugfix addressing a regression in tag peeling during ref updates. The issue was introduced by a recent commit (6ec4c0b45b) that added verification of tag object types to prevent storing corrupted data, but inadvertently caused a 3-10x slowdown in ref operations, particularly noticeable with the reftable backend.

The patch narrows the verification to only check the tagged object's type (not the tag itself), which restores performance to previous levels while still maintaining the corruption protection. Benchmark results show the fix brings execution times back to baseline. The change affects several files that handle tag peeling, renaming the verification constant to better reflect its more targeted purpose.

This is a well-motivated fix with clear performance measurements showing both the regression and recovery. The explanation covers why the regression occurred (unnecessary object lookups) and why the more limited verification is sufficient (tags with invalid self-types don't cause the corruption issue being guarded against). The change appears straightforward with no obvious downsides.
