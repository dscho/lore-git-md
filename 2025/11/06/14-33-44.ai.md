This is a follow-up discussion on the performance regression fix for tag peeling verification. Junio C Hamano is responding to Patrick Steinhardt's analysis of the issue and proposed solution.

The email confirms understanding of the regression's root cause (introduced in commit 6ec4c0b45b) and validates the proposed fix's approach. Junio reconstructs the original reasoning behind the verification logic - that validating during caching would amortize type-checking costs - but agrees with Patrick's observation that verifying the tag object type itself is unnecessary overhead.

Key points confirmed in this response:
1. The verification was overzealous by checking both tag and tagged object types when only the latter was needed to prevent corruption
2. This caused performance degradation by forcing object lookups for all references, not just tags
3. The fix properly narrows verification to just tagged objects while maintaining corruption protection
4. Junio indicates the patch will be queued for inclusion

The discussion reinforces that the solution maintains security benefits while eliminating the broader performance impact, with Junio's approval signaling this is likely the final resolution to the regression issue.
