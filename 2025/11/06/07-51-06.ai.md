This is a follow-up discussion in the Meson build system enhancement thread about HTML documentation path configurability. Patrick Steinhardt provides historical context for the limited number of path configuration options in Meson, explaining that this was a conscious design choice during Meson's introduction to Git. He confirms that while Meson offers path-handling utilities through its Fs module, the underlying types remain string-based rather than having dedicated path/filename types.

The email serves to clarify two points raised by Junio Hamano: (1) why meson_options.txt contains so few directory configuration options (only perllibdir prior to this patch), and (2) why these options use string types rather than more specialized path types. Patrick notes the original decision to add options only as needed, and confirms Meson's string-based typing despite its path-handling capabilities.

This response doesn't introduce new technical elements to the patch series but provides important background that helps justify the implementation approach. The discussion reinforces that the current solution aligns with Meson's established patterns in Git's build system.
