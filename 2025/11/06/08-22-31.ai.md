This is a refactoring patch in the reftable backend optimization series, introducing a way to check if compaction is needed without performing it. The patch extracts the compaction heuristics from `reftable_stack_auto_compact()` into a new internal function `update_segment_if_compaction_required()`, then exposes this via a new public API `reftable_stack_compaction_required()`. 

The new function takes a `use_heuristics` parameter to toggle between strict compaction checking (when false, requiring all tables to be mergeable) and heuristic-based checking (when true, using the existing geometric progression logic). It returns the result through an out-parameter `required`. The implementation maintains the same behavior as the original auto-compaction logic while separating the checking phase from execution.

The patch includes unit test updates to verify the new API's behavior matches the existing in auto-compaction, checking both the required status and table counts at each step. This builds on the refactoring in patch 1 to provide the foundation for the maintenance integration in later parts of the series. The changes are cleanly separated with no behavior changes to existing functionality.
