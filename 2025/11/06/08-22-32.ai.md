This is part 3 of a 5-patch series introducing a new 'is-needed' subcommand for `git maintenance` to check whether optimization tasks are required without performing them. The series has already undergone significant refinement through previous review cycles.

The patch adds a new `optimize_required` callback to the `struct ref_storage_be` interface, which allows checking if a reference backend needs optimization. It implements this callback for all four ref backends (debug, files, packed, and reftable), with behavior matching each backend's characteristics:

- The debug backend wraps and traces calls to the underlying backend
- The files backend uses existing `should_pack_refs()` logic
- The packed backend always returns false (as packed refs are already optimized)
- The reftable backend uses the new `reftable_stack_compaction_required()` API from patch 2

The implementation maintains consistency with existing optimization behavior while providing the checking capability needed for the new maintenance subcommand. The changes are straightforward plumbing through the refs subsystem, with each backend implementing the callback according to its specific optimization characteristics.

Key technical points for future reference:
- New `optimize_required_fn` type in refs-internal.h
- Public `refs_optimize_required()` wrapper in refs.h
- Backend implementations vary by storage type but all follow same signature
- Reftable backend uses new compaction checking API with heuristics support
- Maintains existing behavior while adding checking capability

The patch builds on the refactoring work in earlier patches and provides the necessary infrastructure for the upcoming maintenance integration in patches 4-5. It has already received positive review feedback and appears technically sound.
