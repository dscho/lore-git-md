This is the final patch in a series adding a new 'is-needed' subcommand to `git maintenance`. Patrick Steinhardt provides a few final review comments on the documentation and implementation.

The patch adds the user-facing command that checks if maintenance tasks are needed without running them, exiting with status 0 when maintenance is required. Patrick notes a minor whitespace issue in the documentation (a tab character that should be a space) and suggests the description could reference `maintenance.strategy` but acknowledges it matches the existing 'run' subcommand's wording.

For the implementation, Patrick suggests adding a TODO comment about potentially being too eager in requiring maintenance for non-auto runs, since some tasks might not need to do anything even without --auto. This would be a future improvement rather than a blocker.

The series has already received positive reviews and appears technically complete, with this being the final polish before potential inclusion. The new subcommand provides a way to check maintenance needs programmatically while reusing the existing task infrastructure.
