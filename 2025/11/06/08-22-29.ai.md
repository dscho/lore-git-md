This is the cover letter for v3 of a feature series introducing a new 'is-needed' subcommand to `git maintenance`. The series has evolved through review feedback to its current technically complete state, with all architectural concerns addressed.

The implementation provides infrastructure to check if maintenance tasks are needed without executing them, particularly focusing on ref backend optimization. Key technical elements include:

1. Ref backend changes (patches 1-3):
   - Adds `optimize_required` callback to `struct ref_storage_be`
   - Implements backend-specific checks for files, packed, and reftable
   - For reftable, introduces `reftable_stack_compaction_required()` API that cleanly separates checking from execution

2. Maintenance integration (patches 4-5):
   - Adds `is-needed` subcommand with `--task` filtering
   - Supports `--auto` mode matching existing heuristics
   - Uses exit code 0 when maintenance needed, 1 otherwise

The v3 changes focus on code quality improvements, particularly eliminating logic duplication in the reftable compaction checks by extracting shared heuristics into `update_segment_if_compaction_required()`. The series has received Reviewed-by tags from Patrick Steinhardt and Justin Tobler, with all technical discussion points resolved. It remains on top of the in-flight `kn/refs-optim-cleanup` and `ps/ref-peeled-tags` series but is otherwise ready for integration.
