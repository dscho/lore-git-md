This is a feature proposal for extending Git's diff output format with file attributes, now focusing specifically on output format design. Justin Tobler responds to Ben Knoble's feedback about multi-line vs single-line attribute reporting in the proposed `--raw-extended` option.

The email marks a shift back to single-line output format after considering multi-line alternatives, with Justin proposing comma-separated key=value pairs appended to existing `--raw` format lines. The example shows `binary=yy,crlf=nn` attributes being added after the standard diff metadata but before the status character and filename. This maintains one-line-per-diff-entry while keeping attributes self-documenting.

Key technical details in this iteration:
- Attributes are specified as comma-separated key=value pairs
- The format preserves all existing `--raw` fields in their original positions
- Attributes appear between the SHA-1 hashes and the status/filename
- Example shows boolean-style values (`yy`/`nn`) for binary and crlf attributes

The discussion continues to balance competing priorities:
- Preserving parseability for existing tools (favoring single-line)
- Maintaining self-documenting properties (favoring key=value over positional codes)
- Keeping output compact while allowing future extensibility

This email doesn't introduce new architectural concerns but solidifies the single-line approach as Justin's preferred direction for the next version. The format remains uncommitted on whether to use boolean values or more descriptive states for attributes, leaving room for further discussion. The thread's central tension between machine-parseability and human-readability persists, with this proposal attempting to satisfy both through structured but verbose key=value pairs in a traditional single-line format.
