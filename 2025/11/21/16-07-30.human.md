This is a discussion about the URI syntax design for the `GIT_REF_URI` feature, which allows specifying reference storage backends and locations. 

Junio Hamano responds to Toon Claes' suggestion about future NFS support, offering an alternative interpretation of how URIs might be structured. The key points are:

3. Junio questions whether the current URI structure is optimal, wondering if a simpler `<backend>:<URI>` format might be more appropriate, as the path component might not always represent a filesystem path.

This exchange represents ongoing design discussion about how to best structure URIs to accommodate both local storage and potential future networked backends. The core functionality appears settled, but the syntax details for advanced cases are still being refined.
