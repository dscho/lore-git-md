This is patch 4/19 in Patrick Steinhardt's ongoing refactoring of Git's object database streaming interface, part of the larger effort to enable pluggable backends.

The patch modifies how packed object streaming works by making the packfile information (the pack itself and the object's position within it) explicit parameters to `open_istream_pack_non_delta()` rather than having the caller pre-populate the stream struct. This change serves two purposes: it makes the calling convention clearer, and it prepares for a future patch where the function will handle its own stream allocation. The change is mechanical, with 10 lines added and 10 removed, mostly moving where the pack and offset values get stored in the stream struct.

This continues the series' pattern of incremental interface improvements while maintaining existing behavior. The change is straightforward and builds on prior work in the series, particularly the stream interface restructuring from earlier patches. The patch doesn't introduce new functionality but makes the code more maintainable by reducing hidden dependencies between functions.

Key technical details for future reference:
- Modifies `open_istream_pack_non_delta()` to take explicit `pack` and `offset` parameters
- Moves pack/offset assignment into the function rather than having caller do it
- Maintains same control flow in `istream_source()` but with clearer parameter passing
- Touches only streaming.c, keeping changes localized to packed object handling
- Preserves all existing behavior while making the code more explicit

The change aligns with the series' goal of cleaning up the streaming interface in preparation for pluggable backends, though it doesn't yet address delta handling which remains a future consideration.
