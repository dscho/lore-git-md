This is a bug report thread about test failures in `git last-modified` during merge operations, specifically affecting the NonStop platform in Git 2.52.0.

Randall Becker reports that tests t8020.16 and t8020.19 consistently fail on NonStop, showing commit hashes instead of expected tag names (m1.t, m2.t) when crossing merge boundaries. While the issue appears in the final 2.52.0 release but not in rc0, Becker notes it's 100% reproducible and questions whether this indicates a real defect in either the test code or core merge functionality.

Kristoffer Haugsbakk points to a related thread where Jeff King has already analyzed the issue, suggesting the technical analysis may be available there. The discussion touches on practical packaging concerns - Becker's team is evaluating whether to ship 2.52.0 with these known test failures, weighing the impact and potential wait time for a fix.

A side note reveals email client issues (Outlook's aggressive line-wrapping breaking URLs) and compilation problems with SANITIZE flags, though these appear separate from the core test failure issue. The thread remains active with open questions about the root cause and appropriate response.
