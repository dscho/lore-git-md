This is a follow-up discussion on patch 7/13 in Patrick Steinhardt's ODB refactoring series, specifically addressing the deferred fsck validation fix for `index-pack` when run outside a repository.

The exchange confirms the behavior and limitations of the new `fsck_has_queued_checks()` helper function. Junio notes that while the solution works for Git-generated packfiles (which place trees before blobs), it may fail to validate packfiles from other implementations that might reverse this order. Both agree this is an acceptable "best-effort" approach for now, with Patrick acknowledging that proper validation of arbitrary packfiles would require more extensive changes to the object database infrastructure.

Key technical points:
- The function checks for unvalidated gitmodules/gitattributes by comparing `_found` and `_done` oidsets
- Current solution handles Git's own packfile format correctly
- Edge cases from non-Git implementations remain possible but are gracefully handled
- Future improvements are anticipated with pluggable ODB infrastructure

The discussion concludes with agreement that the current solution represents a practical improvement over the previous segfault behavior, even if not covering all theoretical cases. This aligns with the series' overall goal of methodical ODB abstraction while maintaining backward compatibility.
