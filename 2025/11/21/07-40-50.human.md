This is part of Patrick Steinhardt's ongoing refactoring of Git's object database streaming interface, specifically patch 5/19 in the series. The patch moves stream allocation into backend-specific logic as part of the effort to enable pluggable ODB backends.

The change modifies how stream objects are created - instead of allocating a generic stream first and then populating it with backend-specific data, the backend functions now handle both allocation and initialization. This prepares for a future where each backend can define its own stream structure with a common base, similar to how reference databases work. The patch affects loose objects, packed objects, and in-core object handling.

The implementation appears thorough, touching all three streaming backends consistently. It maintains the same external behavior while making the internal structure more flexible for future pluggable backends. The changes are localized to streaming.c and follow the incremental approach seen in earlier patches of the series.

This continues the architectural direction established in previous patches, with each change building on prior consensus. The patch doesn't introduce new functionality but makes the codebase more prepared for the pluggable backend work that will come in later patches.
