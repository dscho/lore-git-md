This is the final version of a bugfix series addressing regressions in `git fetch`'s batched reference updates, particularly around tag handling and post-fetch operations. The series has evolved through eight iterations with extensive review feedback incorporated.

The core issue fixes non-conflicting tags not being committed when other reference updates fail (introduced by commit 0e358de64a). The solution is structured in three parts: (1) refactoring transaction commit logic into a helper function, (2) fixing the tag commitment issue, and (3) ensuring post-fetch operations (`FETCH_HEAD` updates, upstream tracking, remote HEAD setting) persist through batched update failures.

Key technical improvements in v8:
- Test refinements as requested by Junio:
  - Explicitly deleting `FETCH_HEAD` at test start rather than checking its absence
  - Verifying `FETCH_HEAD` contents to confirm which refs were recorded during partial failures
  - Using `test_path_is_missing()` for clearer file existence checks
- Maintains all prior fixes:
  - Proper transaction cleanup to prevent double-free
  - Clear distinction between atomic and non-atomic fetch behavior
  - Backward compatibility
  - Comprehensive test coverage including edge cases

The series is now functionally complete with all major feedback addressed. Karthik has confirmed it handles several additional pre-existing issues (commit_fetch_head failures, upstream tracking problems, do_set_head processing). Junio has approved the core functionality with Signed-off-by, and the final test adjustments are being implemented in this version.
