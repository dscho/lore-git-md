This is part of Patrick Steinhardt's ongoing refactoring of Git's object database streaming interface, specifically introducing a type-safe container for filtered object streams. The patch continues the series' systematic replacement of union-based stream handling with dedicated structures.

The change moves the filtered stream implementation from using an embedded union in `struct odb_read_stream` to a standalone `struct odb_filtered_read_stream` that embeds the base stream structure. This follows the same pattern established in previous patches for in-core, loose, and packed object streams. The key technical changes include:

1. Removing the `filtered_istream` union member from `odb_read_stream`
2. Creating new `odb_filtered_read_stream` with all filter-specific fields
3. Updating the close and read functions to use the new structure
4. Modifying `attach_stream_filter()` to allocate and initialize the new structure

The patch maintains identical external behavior while improving type safety and maintainability. It's a well-contained change (54 lines modified) that fits cleanly into the series' architectural direction. The implementation follows the same callback pattern seen in other stream types, with `close_istream_filtered()` and `read_istream_filtered()` operating on the new structure.

This completes the type-safe containerization for all major stream types in the ODB interface, leaving only the final cleanup of redundant parameters (planned for patch 19/19) remaining in the series' core goals. The change paves the way for future work on pluggable backends by further decoupling stream implementations from the core interface.
