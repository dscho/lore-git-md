Refactoring patch in a series fixing `git fetch` batched reference updates. This is the first of three patches that together address a regression where non-conflicting tags weren't being committed when other reference conflicts existed.

The patch extracts the reference transaction committing logic from `do_fetch()` into a new helper function `commit_ref_transaction()`. This prepares for subsequent fixes by making the transaction handling reusable. The new function centralizes:
- Transaction committing with error handling
- Non-atomic transaction rejection processing
- Proper transaction cleanup
- Error reporting via strbuf

The refactoring maintains all existing behavior while making the code more modular. The helper handles both atomic and non-atomic cases, with the latter processing rejected updates through the existing `ref_transaction_rejection_handler`. The patch includes pointer-to-pointer transaction management to prevent double-free issues.

This foundational change enables the subsequent patches to reuse this logic when fixing the tag commitment issue. The series has undergone extensive review over eight versions, with this preparatory refactoring being a key architectural improvement suggested by reviewers.
