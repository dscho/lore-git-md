This is a refactoring patch in Patrick Steinhardt's ongoing series to enable pluggable object database backends. Patch 6/19 introduces a dedicated `struct odb_incore_read_stream` to hold in-core object stream data, moving it out of the union in `struct odb_read_stream`.

The change replaces the previous approach where in-core stream data was stored directly in a union within the base stream structure. The new design creates a proper container structure that embeds the base `odb_read_stream` and adds the stream-specific fields (`buf` and `read_ptr`). This matches the architectural direction of the series to make stream implementations more self-contained and prepare for pluggable backends.

The implementation maintains identical functionality while:
1. Removing the `incore` union member from `odb_read_stream`
2. Adding type-safe access via the new container structure
3. Preserving all existing behavior in the open/read/close operations
4. Following the same pattern used for other stream types in the series

The change is well-contained (44 lines modified) and builds on prior consensus in the thread. It continues the series' incremental approach to refactoring the streaming interface while keeping the code functional at each step. The patch appears technically sound and aligns with the overall goal of making the streaming interface more modular.
