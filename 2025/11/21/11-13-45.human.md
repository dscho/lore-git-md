This is the first patch in a three-part series fixing regressions in `git fetch`'s batched reference updates. It's a refactoring patch that extracts the reference transaction committing logic from `do_fetch()` into a new helper function `commit_ref_transaction()`.

The patch prepares for subsequent fixes by centralizing the logic for committing reference transactions and handling rejected updates. The new helper function:
- Takes the transaction as a pointer-to-pointer to ensure proper cleanup
- Handles both atomic and non-atomic fetch modes
- Includes error reporting via a strbuf
- Maintains the same behavior as the original code but in a more reusable form

This is a clean preparatory change that makes the follow-up bugfixes easier to implement by isolating the transaction handling logic.
