Refactoring patch in the ODB backend series, removing deferred stream initialization.

This is patch 2/19 in Patrick Steinhardt's ongoing series to refactor Git's object database for pluggable backends. It simplifies the streaming interface by removing the deferred `open()` callback mechanism, which required partially initialized structs before full initialization could occur. The change makes the code more straightforward by opening streams immediately during creation rather than setting up a callback to do it later.

The patch affects the streaming infrastructure, particularly the handling of loose objects and non-delta packed objects. It maintains all existing functionality while removing about 20 lines of indirection. The change paves the way for future patches that will move stream creation fully into backend-specific code.

The implementation looks clean and focused - it removes the callback indirection while preserving all the existing error handling paths. This continues the series' pattern of incremental, well-explained changes toward the larger pluggable ODB goal. The patch has already received positive feedback from Justin Tobler in previous iterations, indicating consensus on this direction.
