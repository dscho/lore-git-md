This is a refactoring patch in Patrick Steinhardt's series to make Git's object database (ODB) streaming interface more consistent and prepare for pluggable backends. The patch focuses on how object type information is propagated through the streaming code.

The change moves responsibility for determining object type entirely to the format-specific callbacks (loose, packed, and in-core object handlers) rather than having it partially handled at multiple levels. Instead of passing the type through a pointer parameter, it now stores the type in a new `type` field of the `odb_read_stream` struct alongside the existing `size` field. This simplifies the control flow and makes the code more maintainable by:
1. Removing redundant type lookups that were happening at different levels
2. Making the type propagation more explicit via the stream struct
3. Preparing for a future patch that will remove the `odb_read_object_info_extended()` call in `istream_source()`

The patch touches the streaming interface across all three object storage formats (loose, packed, in-core) but maintains identical external behavior. It's part of a larger effort to clean up the ODB streaming interface before introducing pluggable backends, with this specific change addressing a confusing aspect of type handling that was noted in earlier discussion. The changes are mechanical but important for the overall architecture, removing 15 lines while adding 15 (mostly due to the new struct field).
