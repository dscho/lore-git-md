This is a technical clarification in the ongoing discussion about Git's diff capabilities and potential `git cp` command. Lucas Seiki Oshiro responds to Martin Guy's wish for word-based diffing by explaining Git's snapshot-based architecture more thoroughly. 

Oshiro emphasizes that since Git stores snapshots rather than deltas, the diff granularity (line-based vs word-based) is purely a presentation-layer concern that can be customized during diff generation. They point out that `--word-diff` already exists for this purpose in several Git commands, and mention `git-latexdiff` as an example of specialized diff tooling built on top of Git's snapshots.

The response reinforces the thread's key architectural theme that Git's retrospective analysis is flexible enough to support various diff strategies without core changes. While not directly addressing the `git cp` proposal, this keeps the conversation grounded in Git's fundamental design principles. The tone is helpful and informative, providing concrete tools for those wanting more semantic diff capabilities.
