This is a technical clarification in the ongoing `git cp` feature request thread, focusing on Git's diff capabilities.

Lucas Seiki Oshiro responds to Martin Guy's wish for word-based diffing by reinforcing Git's snapshot-based architecture. He explains that since Git stores complete snapshots rather than deltas, the diff granularity (line-based vs word-based) is purely a presentation-layer concern handled during diff generation, not a fundamental storage limitation. 

The response highlights that users already have access to word-level diffing through existing flags like `--word-diff` in commands such as `git diff`, `git show`, and `git log`. Oshiro further suggests that specialized diff tools like git-latexdiff demonstrate how custom diff generation can be built atop Git's snapshot model when semantic analysis is needed.

This maintains the thread's architectural focus while providing practical solutions for the word-diff use case. The email doesn't directly address the original `git cp` proposal but reinforces the underlying technical principles that inform Git's approach to content tracking. The reference to git-latexdiff provides a concrete example of how Git's model can support domain-specific diff requirements.
