This is patch 12/19 in Patrick Steinhardt's ongoing refactoring of Git's object database streaming interface, continuing the architectural work to make object streaming more pluggable and efficient.

The patch changes how object streams are created by shifting responsibility to the object sources themselves. Previously, the code would first look up object info (requiring a full scan of sources) and then separately create the stream (requiring another scan). The new approach asks sources directly to create streams, eliminating the redundant scanning. This is particularly beneficial for loose objects where the double scan was most noticeable, and prepares for future per-source packfile stores.

Key technical changes include:
- `open_istream_loose()` now takes a `struct odb_source` parameter instead of a repository
- `open_istream_pack_non_delta()` is modified to handle object info lookup internally
- The main `istream_source()` function is simplified to try packed objects first, then iterate through loose sources
- The changes affect 65 lines across streaming.c with a net reduction of 41 lines

The patch maintains all existing behavior while making the code more efficient and better structured for future backend isolation work. It builds on previous patches that introduced type-safe stream containers (6-9/19) and moved zlib handling into backend-specific code (10/19). The series is progressing toward its goal of making the ODB streaming interface fully pluggable, with only the final parameter cleanup (19/19) remaining for the core refactoring.
