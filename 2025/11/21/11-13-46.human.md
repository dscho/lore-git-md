Bugfix for `git fetch`'s batched reference updates, specifically addressing non-conflicting tags not being committed when other conflicts exist. This is part of a 3-patch series that has gone through extensive review and iteration (now at v8).

The core issue stems from commit 0e358de64a which introduced batched updates for performance. When fetching tags, if any conflict occurred, the entire transaction would be skipped - including non-conflicting tags. The fix modifies the cleanup section to commit non-rejected updates in non-atomic fetches when errors occur.

The patch adds three new test cases that verify:
1. Basic tag fetching with `--tags`
2. Non-conflicting tags being fetched even when other tags conflict
3. Proper backfilling of tags when fetching specific refspecs

This is a well-tested solution that maintains backward compatibility while fixing the regression. The series has received thorough review from multiple contributors and maintainers, with all feedback addressed. The patch demonstrates careful consideration of edge cases and includes appropriate test coverage.
