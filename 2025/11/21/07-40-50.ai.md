This is part 5/19 of Patrick Steinhardt's series refactoring Git's object database streaming interface to support pluggable backends. The patch moves stream allocation into backend-specific functions, changing the architecture from a union-based approach to one where backends allocate their own structures with a common base.

The key technical change is converting the stream opening functions (`open_istream_loose`, `open_istream_pack_non_delta`, `open_istream_incore`) to take a double pointer output parameter and handle their own allocations. This prepares for future where each backend will define its own struct containing the base `odb_read_stream` as its first member, similar to how reference databases work. The patch maintains all existing behavior while making the code more explicit about ownership and memory management.

The changes affect streaming.c's internal implementation but not its external interface. The patch touches all three streaming backends (loose objects, packed non-delta objects, and in-core objects) with similar patterns:
1. Moving allocation from `open_istream()` to the backend functions
2. Using stack-allocated temporaries during initialization
3. Only allocating the final structure after successful validation
4/19's packed object changes are preserved while adding the new allocation scheme.

This continues the series' incremental approach, with each patch building on prior consensus while keeping the code functional. The change is well-contained (99 lines modified) and maintains the architectural direction toward pluggable backends. Future patches will introduce the backend-specific structs this allocation scheme enables.
