This is a refactoring patch in Patrick Steinhardt's ongoing series to make Git's object database pluggable. It removes the deferred `open()` callback mechanism from the streaming interface, which previously required partially initializing structures before calling their open functions. The change simplifies the control flow by opening streams immediately during initialization, eliminating an awkward two-phase setup process.

The patch modifies `streaming.c` to directly call the appropriate open functions (`open_istream_loose`, `open_istream_pack_non_delta`, or fallback to `open_istream_incore`) rather than storing them in the stream structure. This affects how packed objects are handled, particularly skipping the delta path when the object size exceeds the big file threshold. The change removes 23 lines while adding 17, with the diff showing the simplified logic in `istream_source()` and `open_istream()`.

This prepares for future work where stream allocation will be fully handled by backend-specific code, as noted in the commit message. The change maintains existing behavior while removing an intermediate step that would complicate the planned architecture. The patch follows Justin Tobler's confirmed consensus from previous discussion, indicating this direction was already agreed upon in the thread.
