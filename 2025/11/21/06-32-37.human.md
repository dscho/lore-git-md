This is part of Patrick Steinhardt's ongoing refactoring series to enable pluggable ODB backends by standardizing Git's object streaming infrastructure. The current patch (3/18) moves object type storage into the `odb_read_stream` struct, making data flow more explicit. 

In this follow-up email, Patrick responds to Justin Tobler's observation about the API design of `open_istream()`, which still accepts an object type pointer despite the type being stored in the stream struct. Patrick acknowledges the redundancy but explains he's keeping the parameter for now since `odb_read_stream` is currently opaque. He plans to address this with a later patch once the struct becomes public.

The exchange shows careful consideration of API design tradeoffs in this refactoring work. Patrick is taking an incremental approach, deferring some cleanups until later in the series when the necessary infrastructure is in place.
