This is a refactoring series (19 patches) that continues Patrick Steinhardt's work to enable pluggable object database backends by restructuring Git's object streaming infrastructure. The series moves stream creation and management logic from the object database backends themselves, allowing each backend to implement streaming in its own way.

Key technical changes in this version:
- Drops redundant `type` and `size` out parameters from `odb_read_object_stream()` in a new patch (19/19)
- Improves commit messages and code style based on previous review feedback
- Moves the zlib stream handling into backend-specific code
- Introduces `packfile_store_read_object_info()` to centralize packfile object info reading
- Makes the `odb_read_stream` struct definition public
- Systematically moves streaming logic for different object types (loose, packed, in-core, filtered) into their respective backend implementations

The series builds on previous review consensus around:
- The foundational rename from `git_istream` to `odb_read_stream` (acknowledged by Junio)
- Removal of deferred stream opening (agreed by Justin Tobler)
- Temporary interface redundancy during transition (acknowledged in earlier patches)

Notable progress since v1:
- Karthik Nayak identified and Patrick agreed to remove redundant parameters in the streaming interface
- The series now better isolates backend-specific streaming logic
- Documentation improvements have been made throughout

The changes span ~1500 lines removed and ~1700 added across 20 files, with the streaming code moving to a new `odb/streaming.[ch]` location. The series maintains all existing behavior while enabling the pluggable ODB architecture.
