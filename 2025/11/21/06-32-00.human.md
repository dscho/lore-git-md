This is a refactoring patch in Patrick Steinhardt's ongoing series to enable pluggable object database backends. It removes the deferred opening mechanism for object streams, which was unused in the codebase. 

The patch simplifies the streaming infrastructure by having streams open immediately upon creation rather than supporting a two-phase open process. Justin Tobler had questioned whether there was any valid use case for the deferred opening, and Patrick confirms there isn't - the current code doesn't using it and he couldn't think of any reason it would be needed.

This change is part of the systematic cleanup of Git's object access internals to make them more suitable for pluggable backends. The removal of unused complexity here follows the series' pattern of making focused, behavior-preserving changes. With maintainer approval already given to the foundational rename in patch 1/18, this second patch continues the technical progression with positive review feedback from Justin Tobler.

The change appears straightforward and low-risk, removing dead code rather than altering active behavior. It helps pave the way for future patches that will move more stream management into backend-specific code.
