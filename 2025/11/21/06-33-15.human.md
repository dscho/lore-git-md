This is a follow-up discussion in Patrick Steinhardt's ongoing refactoring series for Git's object streaming infrastructure, specifically addressing patch that makes the `odb_read_stream` struct public.

Patrick responds to Karthik Nayak's observation about redundant parameters in the `open_istream()` function interface. Karthik had noted that since the function returns an `odb_read_stream` struct containing the object type and size, there's no need to also accept these as separate output parameters.

Patrick acknowledges this is indeed redundant and agrees it should be cleaned up. While initially hesitant about making another tree-wide change, he's now convinced the improvement is worthwhile and plans to add it as a new patch at the end of the series. This shows the collaborative refinement of the API design as the series progresses, with maintainer approval already secured for the foundational changes earlier in the series.
