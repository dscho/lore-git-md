This is patch 5/18 in Patrick Steinhardt's series refactoring Git's object streaming infrastructure for pluggable ODB backends. The patch moves stream allocation into backend-specific logic, preparing for future changes where each backend will manage its own stream structure with `struct odb_read_stream` as a base member.

Key technical points:
- Changes stream allocation pattern so backends now receive a pointer-to-pointer (`out`) rather than a pre-allocated stream
- Maintains current behavior by statically defining and copying stream data, though this is temporary scaffolding
- Confirms future memory management approach where `close()` callbacks will handle backend-specific cleanup while `odb_read_stream_close()` frees the base structure
- Addresses Karthik Nayak's review question about static stream definition, explaining the temporary copy mechanism
- The change enables the series' goal of moving backend-specific functions (e.g. `open_istream_loose()`) out of streaming.c
- Builds on earlier patches' standardization of `odb_read_stream` naming and removal of deferred opening
- This intermediate step maintains existing functionality while setting up for more significant backend isolation in later patches
- The discussion confirms alignment between Patrick and Karthik on the overall direction, with Patrick providing implementation details about the temporary scaffolding
