This is a follow-up patch in the Rust CI infrastructure series, specifically targeting Windows platform compatibility. Junio C Hamano forwards a ported version of Johannes Schindelin's fix for handling different compiler toolchains on Windows, where MSVC produces `gitcore.lib` while GNU toolchains produce `libgitcore.a`.

The patch modifies both the meson build configuration and the cargo-meson.sh wrapper script to properly handle both compiler cases. Key changes include:
- Making the library filename conditional on compiler type in meson.build
- Passing the determined filename through to cargo-meson.sh
- Updating the comparison and copy logic in cargo-meson.sh to use the correct filename

Junio notes the patch passes Windows+Meson builds in CI, though observes that the current master branch appears to work without this fix in some configurations. The patch is based on Schindelin's earlier work but updated to apply cleanly to current master.

This addresses the Windows GNU toolchain support gap identified by Ezekiel Newren in post-merge review, where the original implementation assumed MSVC-only builds. The solution follows the pattern established in the series for platform-specific adaptations while maintaining the Rust integration's cross-platform goals. The patch demonstrates the ongoing refinement of Windows support in Git's Rust infrastructure.
