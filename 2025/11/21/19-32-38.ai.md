This is a performance and refactoring patch in Patrick Steinhardt's completed ODB streaming interface series, specifically addressing patch 12/19. The change shifts object stream creation to be source-oriented rather than first querying object info, eliminating redundant source iteration. Junio C Hamano raises an important semantic concern about the change in object precedence rules - where the code previously used odb_read_object_info_extended()'s well-reasoned selection logic (favoring packed over loose objects), it now simply takes the first source that has the object, which may differ if the source list ordering doesn't match the previous precedence rules.

The technical change removes the intermediate object info lookup phase, directly asking each source to create the stream until one succeeds. This reduces iteration overhead and better isolates the streaming subsystem from backend details, though as noted in the commit message, some packfile integration remains to be addressed. The diff shows the simplified control flow where pack objects are tried first, then loose objects via source iteration.

Junio's review identifies a subtle but important behavioral change regarding object selection precedence that wasn't explicitly called out in the original commit message. This could affect cases where multiple copies of an object exist (like both packed and loose versions). The series has already been applied, but this observation documents a potentially significant semantic shift that future work on the ODB streaming interface should consider when dealing with duplicate objects.
