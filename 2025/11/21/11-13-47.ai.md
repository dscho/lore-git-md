Bugfix for batched reference updates in `git fetch`, final patch in a series addressing regressions from commit 0e358de64a. This third patch ensures critical post-fetch operations (FETCH_HEAD updates, upstream tracking, and remote HEAD setting) still occur even when some reference updates fail in non-atomic fetches.

The patch modifies `do_fetch()` to only jump to cleanup on transaction failure when using `--atomic`, allowing batched updates to proceed with post-fetch operations. While FETCH_HEAD was already being updated via `append_fetch_head()`, the other two operations were being skipped entirely. The change maintains atomic fetch behavior while fixing the regression for batched updates.

Test coverage is comprehensive, verifying:
- FETCH_HEAD updates persist through reference conflicts (using locked refs to simulate failures)
- Upstream tracking information is properly set with `--set-upstream` even when conflicts
- Remote HEAD is updated despite reference update failures
- All tests use proper cleanup via `test_when_finished` and verify both presence and content of expected changes

The solution cleanly separates atomic and non-atomic fetch behaviors while fixing the core issue. This completes the series which has evolved through eight versions with thorough review from Junio Hamano and others, now addressing all identified regressions in batched reference updates.
