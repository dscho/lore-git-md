This is a follow-up discussion in Patrick Steinhardt's refactoring series for pluggable ODB backends, specifically addressing patch 3/18 which moves object type storage into the `odb_read_stream` struct.

Patrick responds to Justin Tobler's observation about the current redundancy in `open_istream()`'s interface - while the function returns an `odb_read_stream` containing the object type, it still accepts a separate type pointer parameter. He confirms this will be cleaned up in a later patch once the structure becomes public (as planned in patch 14/18).

The exchange shows careful attention to interface design in the series, with Patrick maintaining incremental changes while tracking technical debt to address later. This follows the pattern seen in earlier patches where foundational changes are made first, with interface refinements deferred until supporting infrastructure is in place.
