This is a major refactoring series targeting Git's object streaming infrastructure, part of the ongoing effort to make the object database more pluggable. Patrick Steinhardt proposes moving the streaming logic from a centralized implementation in streaming.c to being handled by individual object database backends.

The current architecture requires all streaming logic (for loose objects, packed objects, in-memory objects, and filtered objects) to live in one place, which doesn't work well with pluggable backends. The 18-part series reorganizes this by:

1. Renaming core structures (`git_istream` becomes `odb_read_stream`)
2. Breaking up the monolithic implementation into backend-specific components
3. Moving responsibility for stream creation to the object sources themselves
4. Removing repository-global state (`the_repository` usage)
5. Relocating the streaming code into the object database subsystem

The changes touch many parts of the codebase that deal with object streaming, including archive commands, cat-file, fsck, and pack operations. While extensive (20 files modified, +784/-719 lines), the series appears carefully structured with each commit focusing on one logical change. The end goal is a more modular design that will better support future work on pluggable object storage backends.

This looks like a well-motivated architectural improvement that builds on Patrick's previous work on object sources. The series is based on recent Git versions and appears ready for review, though the size may warrant careful examination of the intermediate steps.
