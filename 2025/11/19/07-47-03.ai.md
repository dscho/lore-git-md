This is part 3/18 in Patrick Steinhardt's series refactoring Git's object streaming infrastructure to support pluggable object databases. The patch focuses on cleaning up how object types are propagated through the streaming interface.

The change moves responsibility for determining the object type entirely to the backend-specific stream implementations (loose, packed, in-memory) rather than having it partially handled by the central `istream_source()` function. Instead of passing around a pointer to the type through multiple layers, the type is now stored directly in the `odb_read_stream` struct alongside the existing size field. This makes the data flow more straightforward and prepares for removing the redundant `odb_read_object_info_extended()` call in `istream_source()` in a future patch.

Key technical changes include:
- Adding a `type` field to `odb_read_stream`
- Removing the `type` parameter from all backend-specific open functions
- Updating the loose, packed, and in-memory stream implementations to set the stream's type field directly
- Having `open_istream()` copy the final type from the stream to the caller's pointer

The patch touches only `streaming.c` with 15 lines added and 15 removed, maintaining all existing behavior while making the code more maintainable. This is a logical step in the larger effort to move streaming responsibilities to backend-specific code.
