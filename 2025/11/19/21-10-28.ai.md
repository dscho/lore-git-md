Submodule case-folding collision detection and encoding. This patch (5/7 in the v5 series) enhances the submodule path encoding system to handle case-folding filesystem conflicts more robustly when `extensions.submoduleEncoding` is enabled.

The key technical changes introduce:
- A new `check_casefolding_conflict()` function that scans `.git/modules/` for existing directories that would collide with the new submodule name under case-folding
- A stricter variant of URL encoding (`is_casefolding_rfc3986_unreserved`) that forces uppercase letters to be percent-encoded (e.g. "Foo" becomes "%46oo")
- A fallback mechanism that appends digits to encoded paths when conflicts persist
- Comprehensive test cases covering mixed-case submodule names and encoding scenarios

The implementation maintains the series' architectural approach of only applying encoding when necessary (via the new collision detection) and keeping case-sensitive filesystems unaffected. The patch builds on the centralized validation in `submodule_name_to_gitdir()` established in earlier patches, adding the case-folding logic as an additional validation layer.

Test coverage includes verification of:
- Basic case-folding conflicts ("foo" vs "FOO")
- Mixed encoding scenarios ("foo%42ar" vs "fooBar")
- Fallback to numbered variants when needed
- Preservation of existing encoded paths

This represents a key piece of the overall submodule encoding solution, addressing one of the primary filesystem conflict scenarios the series aims to solve. The implementation follows the established pattern of the series while adding the case-specific handling needed for this edge case.
