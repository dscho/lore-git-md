This is part 3 of a 13-patch series refactoring object database (ODB) management in Git, specifically focusing on cleanup functionality. The patch moves the object database closing logic from packfile.c to odb.c, renaming it from `close_object_store()` to `odb_close()`.

The change recognizes that while much of the closing logic relates to packfiles, the function also handles object sources and commit graphs which are ODB-level concerns. The patch:
- Creates a new `odb_close()` function in odb.c that replicates the existing cleanup behavior
- Updates all callers (9 locations across builtins and core code) to use the new name
- Removes the old `close_object_store()` declaration from packfile.h
- Adds proper documentation for the new function in odb.h

The implementation remains functionally identical - it still closes:
- Packfile store resources
- Multi-pack indexes (midx) for each ODB source
- Commit graphs

This is a straightforward code movement that better aligns functionality with subsystem boundaries as part of the larger ODB abstraction effort. The patch appears mechanically sound with no behavior changes, just improved organization. It touches several key areas including clone, gc, repack, and midx operations, showing the wide impact of ODB management.
