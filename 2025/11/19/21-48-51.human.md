This is a feature proposal introducing a new environment variable to control Git's reference storage location and backend.

Karthik Nayak proposes adding `GIT_REF_URI` to specify both the reference backend (files or reftable) and storage path in URI format (e.g., `reftable:///foo`). The primary motivation is to enable non-blocking migrations between reference backends, particularly useful for large repositories where switching from files to reftable backend can take minutes.

The two-part patch series first adds infrastructure to create reference stores for arbitrary paths, then implements the URI parsing logic. The changes touch core refs handling code and include new tests, suggesting this is a serious proposal with test coverage.

The use case is clearly explained - allowing background migration while maintaining consistency between old and new reference stores. This could be particularly valuable for server administrators managing large repositories. The implementation appears straightforward, building on existing refs infrastructure while adding the new URI parsing capability.
