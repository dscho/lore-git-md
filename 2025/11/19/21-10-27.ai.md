Feature implementation for submodule path encoding, part of the ongoing series to handle filesystem conflicts in submodule gitdirs. This patch introduces the core `extensions.submoduleEncoding` mechanism that encodes problematic submodule paths to prevent filesystem collisions.

The key technical elements are:
- New `extensions.submoduleEncoding` config option that enables path encoding
- `submodule.<name>.gitdir` becomes the single source of truth for encoded paths
- Three-tier fallback system: plain path -> URL encoding -> error if both fail
- New `validate_submodule_encoded_git_dir()` helper for encoded path validation
- Comprehensive test suite in t7425-submodule-encoding.sh covering:
  - Mixed legacy/new-style submodules
  - Cloning scenarios
  - Nested submodule prevention
  - Parallel cloning
  - Config toggling

The implementation builds on prior work by Brandon Williams and incorporates design suggestions from Junio Hamano, Phillip Wood, and Patrick Steinhardt. It maintains backward compatibility while providing an opt-in path for repos needing collision protection.

This is patch 4/7 in the v5 series, following the architectural agreement reached in earlier discussion. The patch focuses on the core encoding logic while leaving case-folding and NAME_MAX handling for subsequent patches. The test coverage is notably thorough, including edge cases around nested submodules and parallel operations.
