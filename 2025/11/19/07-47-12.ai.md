This is part 12/18 of Patrick Steinhardt's series refactoring Git's object streaming infrastructure for pluggable ODB backends, focusing on performance optimization and architectural cleanup.

The patch changes how object streams are created by shifting responsibility to object sources rather than first looking up object info. Previously, the code would first discover an object's location (loose or packed) and then ask the appropriate backend to create a stream, resulting in redundant source iteration for loose objects. The new approach directly asks each source to create a stream, eliminating the double iteration and making the logic more straightforward.

Key technical changes include:
- `open_istream_loose()` now takes a `struct odb_source` parameter instead of `struct repository`
- `open_istream_pack_non_delta()` now handles its own object info lookup rather than receiving pre-looked-up pack info
- The main `istream_source()` function is simplified to try packed objects first, then iterate through loose sources
- All error handling paths and special cases (like delta objects and large file thresholds) are preserved

This continues the series' pattern of moving toward backend-specific implementations while maintaining external behavior. The changes particularly benefit loose object handling by reducing filesystem operations, and they further decouple the streaming subsystem from backend details. The commit notes this isn't yet the final state - packfile store integration and full source awareness remain for future patches.
