This is part 4/13 of the ODB abstraction refactoring series, focusing on cleanup semantics. The patch renames `odb_clear()` to `odb_free()` and changes its behavior to actually free the object database structure rather than just clearing its fields. This better matches the function's single caller in `repo_clear()` which immediately frees the structure anyway.

The change reveals and fixes a duplicate commit graph cleanup - the graph was being closed both directly via `free_commit_graph()` and indirectly through `odb_close()`. The patch removes the redundant direct call. The implementation simplifies by removing unnecessary field zeroing and using direct `free()` calls instead of `FREE_AND_NULL()` macros where the structure is being freed anyway.

Key technical details:
- Changes function signature in odb.h from `odb_clear()` to `odb_free()`
- Updates the single caller in repository.c
- Removes duplicate commit graph cleanup
- Drops field zeroing that served no purpose
- Uses direct memory management rather than macros when freeing entire structure
- Maintains all actual resource cleanup (alternates, replace map, cached objects, etc.)

This is a straightforward cleanup that tightens up the ODB management API as part of the larger refactoring effort. The change is mechanical and well-contained, with no expected behavioral impact beyond fixing the redundant graph cleanup.
