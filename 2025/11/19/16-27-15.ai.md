This is a documentation patch in an ongoing thread about deprecating the `--committer-date-is-author-date` option in `git-am` and `git-rebase`. The thread has reached consensus that the original use case for this option (pseudo-import via `git-am`) violates Git's timestamp ordering assumptions and should be discouraged.

Kristoffer Haugsbakk responds to Junio C Hamano's suggestion about how strongly to discourage the option. Junio had proposed two approaches: either officially deprecate with planned removal, or provide strong warnings while retaining the option. Kristoffer agrees with the latter approach of just warning users about the issues rather than full deprecation.

The email doesn't introduce new technical arguments but rather aligns with Junio's position that the documentation should clearly explain why the original use case was flawed ("who would apply the same series twice on the same base?") while stopping short of an outright prohibition. This maintains the option's availability while making it clear to users that it violates Git's object model assumptions.

The response suggests the documentation patch will likely be revised to include strong warning language about the option's problems without going as far as marking it for removal, unless there's broader community consensus to do so. This follows Junio's "long rope" analogy where users are warned but not prevented from using problematic features.
