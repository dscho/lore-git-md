This is the second patch in a three-part bugfix series addressing regressions in `git fetch`'s batched reference updates. The specific issue fixed here is that non-conflicting tags weren't being committed when other tag conflicts existed, a regression introduced by commit 0e358de64a which added batched updates.

The patch modifies the cleanup section of `do_fetch()` to commit the transaction when there's an error code and the fetch isn't atomic. This ensures non-conflicting references (including tags) still get updated even when some updates fail. The change handles both direct tag fetching and the backfilling of tags that occurs when fetching specific refspecs containing tags in their history.

Three new test cases verify the fix: basic tag fetching, handling of non-conflicting tags alongside conflicts, and proper backfilling of tags when fetching specific refspecs. The tests include proper cleanup and use `test_when_finished` to ensure repository state is reset.

This is a well-motivated fix with clear test coverage for the regression. The patch builds on preparatory refactoring from part 1/3 of the series and maintains the existing behavior for atomic fetches. The solution has evolved through seven versions with input from multiple reviewers, and this version addresses all prior concerns.
