Refactoring patch moving repository entry function to more logical location.

This is the first patch in a 13-part series reorganizing Git's object database source management. It relocates the `enter_repo()` function from path.c to setup.c, where it more naturally belongs given its role in repository setup. The function handles entering a repository at a given path, with logic for path resolution and validation.

The change is straightforward - the function and its supporting enum/flags are moved verbatim, with corresponding header updates. Several builtins and http-backend.c are updated to include setup.h instead of path.h where they use this functionality. The commit message clearly explains the motivation: while path.c handles general path operations, this function is specifically about repository setup.

This appears to be a well-considered first step in the larger series, cleaning up the code organization before more substantial changes. The patch content looks clean with proper header updates and no functional changes.
