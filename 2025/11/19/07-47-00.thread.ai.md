Patrick Steinhardt's 18-patch series refactoring Git's object streaming infrastructure for pluggable ODB backends continues with review feedback on patch 11/18. The series has standardized interfaces, restructured type handling, and isolated backend-specific logic across previous patches (1-10/18), with Karthik Nayak providing reviews on patches 2/18, 5/18, and 6/18.

Patch 11/18 specifically extracts packed object info reading logic into a new `packfile_store_read_object_info()` function, modifying `do_oid_object_info_extended()` to handle packed objects internally rather than via loop breaks. Karthik Nayak's review confirms the changes maintain behavioral equivalence while noting the subtle control flow change - packed object cases are processed within the new helper while preserving retry logic for submodules and promisor remotes. This continues the series' pattern of isolating implementation details (here making `find_pack_entry()` internal) as part of making the ODB backend pluggable.

The series (~1500/+1700 lines) systematically prepares for pluggable backends by:
- Eliminating union-based coupling between stream types
- Making zlib handling backend-specific
- Removing all global state dependencies
- Reducing filesystem operations
- Exposing core stream structure
- Standardizing interfaces (with `odb_` prefix in later patches)
- Fully parameterizing by ODB
- Relocating code to proper subsystems (streaming.{c,h} moving to odb/ in final patch)

Delta-packed objects remain the only case not yet handled in the stream type separation. Karthik's reviews (now covering patches 2/18, 5/18, 6/18, and 11/18) continue to validate the architectural direction while carefully analyzing implementation details like control flow changes in this patch. The changes maintain identical external behavior while enabling future backend implementations as part of Steinhardt's larger ODB abstraction effort.
