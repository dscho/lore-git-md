Patrick Steinhardt's 18-patch series refactoring Git's object streaming infrastructure for pluggable ODB backends continues with seven key changes:

1. Initial patches (1-4/18) standardized interface names, simplified initialization, restructured type handling, and modified packed object streaming to remove implicit coupling.

2. Patch 5/18 restructured stream allocation by moving it into backend-specific functions (loose, packed, in-memory) using double pointer output parameters and `CALLOC_ARRAY`, while maintaining zlib initialization in the loose path.

3. Patch 6/18 introduced a dedicated `struct odb_incore_read_stream` for in-memory object streams, moving previously union-embedded fields (`buf` and `read_ptr`) into this new type while maintaining external behavior.

4. New Patch 7/18 follows the same pattern for loose object streams with `struct odb_loose_read_stream`, moving union-embedded fields (`mapped`, `mapsize`, `hdr`, `hdr_avail`, `hdr_used`) into the new structure. The change:
   - Removes the `loose` union member from base `struct odb_read_stream`
   - Creates standalone structure with base fields plus stream-specific data
   - Updates all related functions (`read_istream_loose`, `close_istream_loose`, `open_istream_loose`) to cast between types
   - Preserves zlib initialization and error handling paths

5. The changes systematically prepare for future backend implementations by:
   - Eliminating union-based coupling between stream types
   - Allowing backend structures to be defined outside streaming.c
   - Maintaining identical external behavior while changing internal allocation
   - Enabling distinct stream types with `odb_read_stream` as base

6. Technical scope remains internal to object streaming with:
   - No user-visible behavior changes
   - Continued focus on error handling paths (cat-file, fsck)
   - Progress toward removing `the_repository` usage
   - Preparation for backend-specific stream implementations

7. The series (now ~700/+900 lines) builds on Steinhardt's prior object-source-loose work as part of the larger ODB abstraction effort. Next steps will likely introduce distinct backend structures for packed object streams while maintaining backward compatibility. The changes systematically prepare the plumbing for pluggable backends without disrupting existing functionality.
