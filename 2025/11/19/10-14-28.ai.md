This is a review comment on patch 6/18 of Patrick Steinhardt's series refactoring Git's object streaming infrastructure. Karthik Nayak provides a minor readability suggestion for the in-core object stream implementation.

The patch introduces a new `struct odb_incore_read_stream` to properly type the in-memory object stream case, separating it from the union-based approach used previously. Karthik notes that the changes look good overall but suggests declaring the `st` pointer on a separate line from the stream structure initialization for better readability. The pointer is used to allocate and initialize the new stream structure before returning it through the `out` parameter.

This is a small implementation detail in the larger context of the series' goal to properly type and separate the different stream backends. The change maintains the same functionality while improving type safety and preparing for pluggable backends. Karthik's review confirms the technical approach while flagging a minor readability improvement opportunity.
