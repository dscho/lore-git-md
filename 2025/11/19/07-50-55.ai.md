This is patch 7/13 in the ODB source management refactoring series, addressing a bug in `index-pack`'s fsck behavior outside repositories. The patch fixes a segfault that occurs when deferred fsck operations (specifically for .gitmodules and .gitattributes files) are attempted without an initialized object database.

The core issue stems from `index-pack --fsck-objects` working outside repositories for most checks, but crashing when deferred checks require ODB access. Patrick considers several solutions before settling on failing gracefully with an error message when queued checks exist outside a repository, rather than silently skipping or crashing. This maintains safety while providing better user feedback.

The implementation adds a new `fsck_has_queued_checks()` function to detect pending checks, moves packfile store loading later in the process, and includes a test case verifying the new behavior. The changes touch `index-pack.c`, `fsck.c/h`, and test scripts, with careful attention to maintaining existing functionality while fixing the edge case.

This patch demonstrates good technical decision-making by:
1. Clearly analyzing multiple solutions and their tradeoffs
2. Choosing the most robust option that preserves safety guarantees
3. Adding appropriate test coverage
4. Keeping related logic together through code reorganization

The change fits naturally into the larger series by addressing one of the problematic ODB interactions that the refactoring aims to clean up. The commit message provides thorough context about why this particular solution was chosen over alternatives.
