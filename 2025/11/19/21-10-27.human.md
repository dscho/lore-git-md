This is part 4/7 of a feature series introducing submodule gitdir path encoding to prevent filesystem conflicts. The series implements a new `extensions.submoduleEncoding` config that encodes problematic submodule names (like those with case conflicts or nested paths) in `.git/modules/`.

The patch establishes the core encoding mechanism, which:
- Uses URL percent-encoding for path components
- Relies on `submodule.<name>.gitdir` config as the single source of truth
- Validates paths to prevent nesting
- Falls back to hashed names if encoding fails

The implementation handles the tricky case of nested submodule paths (like "foo/bar") by encoding the slashes. The commit includes extensive tests verifying the encoding works across clones, updates, and parallel operations. The approach builds on Junio Hamano's design to only encode when necessary, keeping things simple for the common case.

This is a well-constructed patch with thorough test coverage that solves a real filesystem collision problem in submodules. The series has already gone through several rounds of review with input from key Git maintainers. The implementation looks solid and ready for final review.
