This is a review response in the ongoing refactoring series for Git's object streaming infrastructure. Karthik Nayak examines Patrick Steinhardt's patch 5/18 which moves stream allocation into backend-specific logic as part of the effort to make object streaming work with pluggable backends.

The key technical change is moving from a union-based approach where the generic stream structure contains backend-specific union members, to a design where backends embed a generic `struct odb_read_stream` as their first member (similar to how refs are handled). This requires moving allocation into the backend-specific open functions, which now take a double pointer to populate.

Nayak raises two specific concerns about the implementation:
1. Whether backend-specific functions like `open_istream_loose()` will be moved out of streaming.c (implied by the new design but not shown in this patch)
2. A potential issue with the packed stream implementation using a static `struct odb_read_stream` rather than dynamic allocation like the loose object case

The review confirms the overall approach makes sense ("Right") while flagging these implementation details for clarification. The patch is part of systematically decoupling streaming from specific backend implementations in preparation for pluggable ODB backends, with ~100 lines changed in streaming.c to move allocation logic.
