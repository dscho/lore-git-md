This is a refactoring patch in Patrick Steinhardt's ongoing series to prepare Git's object streaming infrastructure for pluggable ODB backends. Justin Tobler is reviewing patch 2/18, which removes the `open()` callback from `struct odb_read_stream` and refactors the initialization sequence to open streams immediately rather than deferring it.

The change simplifies the two-phase initialization where the stream structure was first created with an open callback, then later opened. The patch eliminates this indirection by having `istream_source()` perform the opening immediately during initialization. Justin notes this preserves the existing fallback behavior where failed opens still attempt `open_istream_incore()`, and agrees with the direction while asking if there are any cases where delayed opening would be beneficial (Patrick's commit message suggests there are not).

Key technical details:
- Removes `open_istream_fn` typedef and `open` field from `struct odb_read_stream`
- Modifies `istream_source()` to call the appropriate open function (loose, pack, or incore) directly
- Simplifies `open_istream()` by removing the secondary open step
- Maintains all existing error handling and fallback paths
- The change enables future patches to move stream creation fully into backend-specific code
- Part of broader effort to standardize interfaces for pluggable backends
- Follows from patch 1/18's renaming of `git_istream` to `odb_read_stream`

Justin's review is positive, noting the preserved behavior makes sense and asking a clarifying question about the design choice to always open immediately. The change appears uncontroversial and well-motivated as part of the larger refactoring series.
