This is part 4 of a 13-part series refactoring Git's object database (ODB) management. The patch renames `odb_clear()` to `odb_free()` and changes its behavior to actually free the ODB structure rather than just clearing its fields. 

The change makes sense because:
1. The function's only caller was already freeing the structure afterward
2. The "clear" terminology didn't match Git's coding guidelines since the structure couldn't be reused without reinitialization
3. The refactoring revealed and fixed a double-free issue with commit graphs

The patch is a straightforward cleanup that removes some boilerplate code while making the API more accurate. It touches odb.c, odb.h, and repository.c, with the main changes being the function rename and removal of redundant field zeroing. This continues the series' trend of carefully reorganizing ODB management code.
