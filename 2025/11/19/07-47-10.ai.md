This is part 10/18 of Patrick Steinhardt's series refactoring Git's object streaming infrastructure for pluggable ODB backends. The patch continues the systematic separation of backend-specific stream implementations by moving zlib stream handling from the shared `odb_read_stream` base structure into the individual backend structures for loose and packed objects.

The changes:
- Remove the shared `git_zstream` and state tracking from the base `odb_read_stream` struct
- Add dedicated zlib streams and state enums to both `odb_loose_read_stream` and `odb_packed_read_stream`
- Update all related functions to use the backend-specific streams instead of the base one
- Rename state constants to be backend-specific (e.g. `z_used` becomes `ODB_LOOSE_READ_STREAM_INUSE`)
- Maintain identical external functionality while changing internal implementation

The patch completes the decoupling of zlib stream handling between backends, following the same pattern used in earlier patches for other stream types. This is another step toward the series' goal of enabling pluggable ODB backends by removing implicit coupling between implementations. The changes are focused on internal plumbing with no user-visible effects.

Key technical details for future reference:
- Loose objects now use `ODB_LOOSE_READ_STREAM_*` states
- Packed objects use `ODB_PACKED_READ_STREAM_*` states
- All zlib initialization/cleanup is now backend-specific
- The `close_deflated_stream()` helper is removed as its functionality is now directly in backend close handlers
- Error handling paths remain unchanged (cat-file, fsck, etc. continue working as before)

This continues the methodical preparation for pluggable backends while maintaining existing behavior, following the established pattern of moving shared infrastructure into backend-specific implementations.
