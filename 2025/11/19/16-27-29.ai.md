This is a refactoring patch in Patrick Steinhardt's ongoing series to make Git's object streaming infrastructure pluggable. Patch 14/18 moves the definition of `struct odb_read_stream` from streaming.c to streaming.h, making it public so backend implementations can allocate and initialize these streams directly. The change is straightforward - the struct and its function pointer typedefs are relocated to the header with no functional modifications.

Karthik Nayak's review raises a valid question about API design: since the stream struct already contains the object type and size fields, why does `open_istream()` still take these as separate output parameters? This suggests a potential follow-up cleanup to simplify the interface by having callers read these values from the stream struct instead. The current patch maintains the existing behavior while enabling the architectural shift where backends will manage stream allocation.

The change continues the series' pattern of exposing previously internal structures to support pluggable backends, with 11 lines removed from streaming.c and 15 added to streaming.h. Karthik-Patrick review cycle remains productive, with this being Karthik's fifth review in the series, catching API consistency issues early.
