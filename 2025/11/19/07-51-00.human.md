This is part 12/13 of Patrick Steinhardt's series refactoring Git's object database (ODB) management, continuing the effort to move responsibilities from setup.c to odb.c. The patch focuses on handling repository directory changes when the working directory moves.

The core issue is that `repo_set_gitdir()` gets called both during initial repository setup and when the working directory changes (requiring path updates). Currently, relative paths in the ODB need updating in both cases, which creates complications. The patch introduces a callback system to handle these updates more cleanly.

Key changes:
1. Adds `odb_update_commondir()` callback to update ODB paths when the working directory changes
2. Registers/unregisters this callback during ODB creation/destruction
3. Splits `set_git_dir_1()` to avoid reinitializing an already-existing ODB
4. Adds safety checks to prevent accidental reinitialization

The solution is pragmatic rather than ideal - the author notes that a more thorough fix would require either splitting "display" vs "internal" paths (too disruptive) or reworking setup.c (too complex for now). This maintains compatibility while moving toward better ODB encapsulation.

The patch continues the series' careful, incremental approach, with clean separation of concerns and attention to edge cases. It touches odb.c, setup.c, and related headers, but keeps changes focused on the immediate need while laying groundwork for future improvements.
