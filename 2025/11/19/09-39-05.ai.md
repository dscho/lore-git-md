This is a review comment on patch 2/18 of Patrick Steinhardt's object streaming refactoring series. Karthik Nayak examines the removal of the `open()` callback from the streaming interface, noting two behavioral changes:

1. The direct call to `open_istream_loose()` now checks its return value immediately rather than through the callback indirection, though the error handling remains equivalent since both functions return -1/0.

2. The packed object case now uses early `break` to exit the switch when falling back to in-core streaming, which is logically equivalent to the previous fallthrough but perhaps clearer.

Nayak confirms the changes maintain correct behavior since both affected open functions use compatible return conventions (-1/0). The review focuses on verifying behavioral equivalence rather than suggesting improvements, as the patch is part of a larger, carefully structured series standardizing the streaming interface. The changes align with the series goal of simplifying and parameterizing the streaming subsystem by removing indirect function pointers where direct calls suffice.
