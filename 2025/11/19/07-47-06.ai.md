This is part 6/18 of Patrick Steinhardt's series refactoring Git's object streaming infrastructure for pluggable ODB backends, focusing on internal restructuring.

The patch introduces a dedicated `struct odb_incore_read_stream` to handle in-memory object streams, moving the previously union-embedded fields (`buf` and `read_ptr`) into this new structure. The change:

1. Removes the `incore` union member from `struct odb_read_stream`
2. Creates a new standalone structure containing:
   - The base `odb_read_stream` fields
   - Stream-specific `buf` pointer (from object info)
   - `read_ptr` tracking position

3. Updates all related functions (`close_istream_incore`, `read_istream_incore`, `open_istream_incore`) to:
   - Type-cast between base and derived structures
   - Access fields through the new structure
   - Maintain identical external behavior

The change continues the series' pattern of decoupling backend-specific implementations from the core streaming interface, preparing for future pluggable backends. Like previous patches, this maintains all existing functionality while removing implicit coupling - here by eliminating the need for a union of backend-specific data in the base stream structure.

Technical scope remains focused on internal streaming infrastructure with:
- No user-facing changes
- Continued use of `CALLOC_ARRAY` for allocation
- Preservation of all error handling paths
- Preparation for distinct stream type implementations

The patch cleanly separates concerns while keeping the diff minimal (25 insertions, 20 deletions), following the series' incremental refactoring approach.
