This is patch 12/18 in Patrick Steinhardt's series refactoring Git's object streaming infrastructure for pluggable ODB backends, with Karthik Nayak providing review feedback. The patch changes how object streams are created by shifting from a two-phase lookup (first find object info, then create stream) to directly asking each source to create the stream.

The key change moves from checking object info (which required iterating sources twice for loose objects) to having each source attempt stream creation directly. This eliminates redundant source iteration and better isolates backend-specific logic. The patch modifies `istream_source()` to first try packed objects via `open_istream_pack_non_delta()`, then fall through to loose object sources, with each source getting one attempt to provide the stream.

Karthik Nayak's review confirms the architectural improvement, noting the simplified control flow where sources are now tried sequentially rather than being selected via object_info metadata. The changes maintain behavior while removing the intermediate object info step, though the implementation still handles packed and loose objects separately (to be addressed in later patches).

This continues the series' pattern of isolating backend-specific operations while standardizing interfaces. The 65-line diff (24 insertions, 41 deletions) in streaming.c shows the simplified logic, with packed object handling moving first in the sequence and loose objects being tried per-source without pre-checking existence. The changes pave the way for future patches to fully parameterize the ODB backend interface.
