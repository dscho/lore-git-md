This thread presents a 13-part series refactoring Git's object database (ODB) management, moving responsibilities from setup.c to a new odb.c as part of the ongoing ODB abstraction effort led by Patrick Steinhardt. The series begins with preparatory cleanups - relocating the `enter_repo()` function and converting `set_git_dir()` to static - before tackling core ODB management.

The latest patch (3/13) moves database closing logic from packfile.c to odb.c, renaming `close_object_store()` to `odb_close()` to better reflect its broader scope. While the behavior remains identical (still handling packfiles, multi-pack indexes, and commit graphs), the reorganization better aligns functionality with subsystem boundaries. The change affects several key operations including clone, gc, and repack, demonstrating the wide impact of ODB management.

The series represents a significant architectural shift in how Git handles object sources, with changes spanning setup.c, odb.c, path.c and multiple builtins. While technically sound and well-motivated, the thread has not yet attracted review feedback despite touching sensitive areas like fsck, quarantine directories, and chdir-notify functionality.
