This is a documentation patch in an ongoing thread about deprecating the `--committer-date-is-author-date` option in `git-am` and `git-rebase`. The thread has reached consensus that the original use case for this option (maintaining consistent commit IDs when emailing patches) was flawed, as it violates Git's timestamp ordering assumptions.

Kristoffer Haugsbakk responds to Junio C Hamano's suggestion about how strongly to discourage the option's use. Junio had proposed either officially deprecating it (with planned removal) or just providing strong warnings while keeping the option. Kristoffer sides with the warning-only path, agreeing with Junio's "long rope" analogy that users should be informed of the risks but not outright prevented from using the option.

The patch appears to be following the technical consensus while taking a pragmatic approach to documentation - clearly warning about the problems without forcing removal of functionality that some users might still depend on. This seems like a reasonable middle ground given the discussion so far.
