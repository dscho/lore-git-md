This is a major refactoring series targeting Git's object database infrastructure, specifically focusing on how objects are read in streaming fashion. The series moves responsibility for stream creation from a centralized "streaming.c" to individual object database backends, better aligning with Git's move toward pluggable object storage.

The key technical changes involve:
- Renaming `git_istream` to `odb_read_stream` and making its definition public
- Creating distinct backend structures for loose, packed, in-memory and filtered object streams
- Moving zlib stream handling into the backends
- Eliminating `the_repository` usage from streaming code
- Relocating streaming code into the object database subsystem
- Updating numerous callers across the codebase to use the new interface

The series builds on Patrick Steinhardt's prior work on object sources (ps/object-source-loose) and touches core object handling code used by commands like `cat-file`, `fsck`, and `pack-objects`. The changes are extensive (18 patches touching 20 files with ~500 lines added and ~700 removed) but appear focused on improving architectural separation rather than changing behavior.

This refactoring appears well-motivated for supporting pluggable object databases, though the large scope means careful review will be needed to ensure no subtle behavior changes in the streaming interface. The series maintains backward compatibility while moving toward a more modular design where each backend controls its streaming implementation.
