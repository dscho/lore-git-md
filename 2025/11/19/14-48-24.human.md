This is a review response in Patrick Steinhardt's ongoing refactoring series for Git's object streaming infrastructure. Karthik Nayak is reviewing patch 11/18, which extracts packed object info reading into a standalone function `packfile_store_read_object_info()`.

The patch moves logic from `do_oid_object_info_extended()` into this new function, making `find_pack_entry()` an internal implementation detail. Karthik notes the change simplifies the control flow - where previously the code would break out of a loop upon finding a pack entry, it now directly returns success from the new function. He confirms the remaining loop handles submodule objects and promisor remote cases.

The review is positive overall, with Karthik pointing out one behavioral clarification about the loop logic but otherwise approving the changes. This continues the series' trend of isolating packfile-specific functionality while maintaining the same external behavior, as seen in earlier reviewed patches. The changes touch odb.c, packfile.c and packfile.h with about 70 lines added and 40 removed.
