Refactoring patch in Patrick Steinhardt's series to abstract Git's object streaming infrastructure. This is part of the ongoing effort to make object database backends pluggable.

Patch 7/18 introduces a dedicated `struct odb_loose_read_stream` for loose object streams, continuing the pattern established in patch 6/18 for in-memory streams. The change moves previously union-embedded fields (`mapped`, `mapsize`, `hdr`, `hdr_avail`, `hdr_used`) into this new type while maintaining identical external behavior. The implementation:
- Removes the `loose` union member from base `struct odb_read_stream`
- Creates a standalone structure containing both base fields and stream-specific data
- Updates all related functions (`read_istream_loose`, `close_istream_loose`, `open_istream_loose`) to cast between types
- Preserves existing zlib initialization and error handling paths

The change systematically eliminates union-based coupling between stream types, allowing future backend implementations to define their own stream structures outside streaming.c. Like previous patches, this maintains backward compatibility while preparing the plumbing for pluggable backends. The diff shows mechanical updates to field access patterns (changing `st->u.loose.x` to `st->x` after casting) and function signatures to work with the new structure.
