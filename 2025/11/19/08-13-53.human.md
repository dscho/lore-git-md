This is a documentation patch in an ongoing thread about improving `git worktree` usage guidance. The email captures a key clarification from maintainer Junio Hamano about the original design intent behind worktrees - they were never meant to be nested inside each other, though this was never explicitly documented. 

The thread has largely settled on removing warnings about nested worktrees (since they're technically safe) while improving documentation to guide users toward the intended "side-by-side" usage pattern. This particular message reinforces that the existing examples already show the preferred approach of placing worktrees next to the primary checkout rather than inside it.

The discussion has progressed to the point where the remaining work is primarily about finalizing the wording and presentation of these documentation improvements, with the technical substance largely agreed upon. The patch series appears well-considered, with active review from multiple documentation specialists and the maintainer.
