This is part of the submodule gitdir path encoding series (v5), specifically a refactoring patch that centralizes validation logic for submodule gitdir paths. The patch moves validation checks that were previously scattered across multiple call sites into the `submodule_name_to_gitdir()` function, which now always validates paths before returning them. This change makes the API safer by ensuring validation happens consistently, reduces duplicate code, and helps prevent parallel operation races where a gitdir could become nested after creation.

Key technical changes:
- Removes `validate_submodule_git_dir()` from the public API in `submodule.h`
- Makes the validation function static and calls it unconditionally from `submodule_name_to_gitdir()`
- Deletes validation checks from `builtin/submodule--helper.c` and `submodule.c` that are now redundant
- Maintains the same validation logic (preventing gitdir nesting) but applies it more consistently
- Updates error messages to remain consistent with previous behavior

The change affects several submodule operations including clone, move_head, and gitdir relocation. The implementation appears technically sound, building on the series' established architecture while simplifying the code surface. This follows the pattern seen in previous iterations of the series where implementation details are refined while maintaining the core technical approach.
