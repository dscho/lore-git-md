This is the final patch (13/13) in Patrick Steinhardt's series refactoring object database (ODB) source management, completing the relocation of ODB-related functionality from setup.c to odb.c.

The patch moves the handling of temporary quarantine directory reparenting during working directory changes into odb.c, matching the previous patch's relocation of commondir path updates. It introduces calls to `tmp_objdir_unapply_primary_odb()` and `tmp_objdir_reapply_primary_odb()` within the `odb_update_commondir()` callback, while removing this logic from setup.c's `update_relative_gitdir()`.

Key technical details:
- Adds tmp-objdir.h include to odb.c
- Maintains same quarantine directory behavior but now managed by ODB subsystem
- Preserves the temporary object directory's relative path correctness during chdir
- Removes tmp-objdir.h from setup.c as no longer needed there
- Touches only odb.c and setup.c with minimal changes (7 lines added, 5 removed)

This completes the architectural goal of the series by fully encapsulating all object database path management - both primary/alternate paths and quarantine directories - within the ODB subsystem. The change is straightforward and maintains existing behavior while improving code organization. With this patch, the systematic relocation of ODB management from setup.c to odb.c reaches its conclusion.
