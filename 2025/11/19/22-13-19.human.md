This is a review comment on the test suite for the `GIT_REF_URI` feature implementation. Eric Sunshine points out two potential improvements to the test coverage:

1. The tests currently use bare `!` for error checking rather than the preferred `test_must_fail` helper, which provides better error messages and handles edge cases more robustly.

2. The nested loop structure appears to be set up to test all combinations of reference backend formats (files and reftable), but the test bodies hardcode specific formats rather than using the loop variables. This makes the test output less informative since it doesn't show which combination is being tested, and may indicate the test isn't actually exercising all intended cases.

The feedback is constructive and focused on test quality - these are the kinds of nitpicks maintainers often catch during review. The issues don't affect the core functionality being implemented, just the thoroughness and maintainability of the test suite. The author will likely want to address these points in a v2 submission.
