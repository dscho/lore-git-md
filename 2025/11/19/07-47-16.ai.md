Refactoring patch in Patrick Steinhardt's ongoing ODB backend abstraction series, moving packed object stream handling to its logical home in packfile.c.

This patch (16/18) relocates all packed object streaming logic from streaming.c to packfile.c, following the same pattern established for loose objects in the previous patch. The changes include:

1. Moving the `odb_packed_read_stream` struct and its associated functions (`read_istream_pack_non_delta`, `close_istream_pack_non_delta`) to packfile.c
2. Introducing a new public function `packfile_store_read_object_stream()` as the packed streaming entry point
3. Updating `istream_source()` to call this new function rather than the old `open_istream_pack_non_delta()`
4. Maintaining all existing functionality while changing the implementation location

The patch continues the series' systematic approach to backend separation by:
- Keeping zlib stream handling packed-specific
- Preserving the same state machine for packed object reading
- Maintaining identical error handling paths
- Following the established pattern of moving stream allocation to backend-specific locations

Technical details of note:
- The packed stream implementation handles non-delta objects only (commits, trees, blobs, tags)
- Uses the same ODB_PACKED_READ_STREAM_* state enum as before
- Preserves the pack window management and zlib inflation logic
- Updates include paths to add streaming.h to packfile.c
- Adds the new function declaration to packfile.h

This change completes another major piece of the stream type separation, leaving only delta-packed objects as the remaining case not yet handled in the backend abstraction effort. The patch follows the series' consistent approach of maintaining external behavior while restructuring internals to support pluggable backends.
