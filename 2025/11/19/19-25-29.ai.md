This is a refactoring patch in Patrick Steinhardt's ongoing series to prepare Git's object streaming infrastructure for pluggable ODB backends. The patch focuses on how object type information is propagated through the streaming code.

The key change moves the object type storage from being passed around via pointer parameters to being stored directly in the `odb_read_stream` struct alongside the existing size field. This makes the data flow more explicit by having the type travel with the stream itself rather than being passed through multiple function layers. The format-specific callbacks now become solely responsible for populating the type.

Justin Tobler's review notes that while the stream struct now holds the type, `open_istream()` still accepts a type pointer parameter for output - similar to how it handles size - which makes sense given `odb_read_stream` remains opaque to callers. The change appears well-contained (30 lines modified) and maintains the existing behavior while cleaning up the internal implementation.

This patch continues the series' pattern of methodical, behavior-preserving refactors that standardize interfaces in preparation for pluggable backends. The change appears uncontroversial based on Justin's positive feedback, though it does highlight the ongoing question about the relationship between `open_istream()`'s parameters and the stream struct's fields.
