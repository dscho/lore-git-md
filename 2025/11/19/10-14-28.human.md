This is a review comment on patch 6/18 of Patrick Steinhardt's series refactoring Git's object streaming infrastructure. Karthik Nayak provides feedback on the implementation of in-core object streams.

The patch introduces a dedicated structure for in-memory object streams as part of the larger effort to make object database backends pluggable. Karthik notes a minor readability concern about the declaration of a pointer variable `*st` being combined with the struct declaration, suggesting it might be clearer on a separate line. This is a small style nit - he confirms the rest of the changes look good.

The change itself restructures how in-memory object streams are handled, moving from a direct `odb_read_stream` to using a new `odb_incore_read_stream` type that contains the stream as a base member. This is part of the series' systematic separation of different stream types (in-memory, loose, packed) to remove implicit coupling between them.

Karthik's review indicates the technical direction of the patch is sound, with only this minor presentation suggestion. The change maintains the same functionality while progressing the series' goal of cleaner backend separation.
