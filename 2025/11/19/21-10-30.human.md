This is the final patch in a series implementing submodule path encoding to prevent filesystem conflicts. It adds a build-time option to enable the `extensions.submoduleEncoding` feature by default, while still allowing repository-specific config to override it.

The patch adds build system support in both Makefile and Meson for setting `SUBMODULE_ENCODING_BY_DEFAULT` via `--enable-submodule-encoding` (autoconf) or `submodule-encoding` (Meson). The default remains disabled, matching the current behavior. The setting gets compiled into Git via a `-D` flag and is read during repository setup in `setup.c`, where it can still be overridden by repo config.

This addresses deployment challenges where users might want to enable the feature system-wide without modifying individual repositories. The implementation is straightforward, adding the build option while maintaining the series' principle that repository config takes precedence. Documentation is updated to explain the new option.

As the concluding patch in a well-reviewed series, this appears ready for inclusion, providing a useful deployment option while preserving the flexibility of the core design. The change is minimal and focused, completing the feature's implementation without introducing new complexity.
