This is a feature proposal introducing a new environment variable to control Git's reference storage location and backend. The cover letter describes a two-patch series that would allow specifying reference backends and paths via a URI-style `GIT_REF_URI` environment variable (e.g., `reftable:///foo` or `files://$GIT_DIR/ref_migration.0xBsa0`).

The primary motivation is to enable non-blocking migration between reference backends, particularly for large repositories where moving from the files backend to reftable could take minutes. The proposal would support writing to multiple backends simultaneously during migration. The first patch adds infrastructure to create ref_stores for arbitrary paths, while the second implements the URI parsing and integration with the main ref store creation.

The changes touch core refs handling (refs.c), add documentation, and introduce new test infrastructure (t1423-ref-backend.sh). The implementation appears thorough, with clear test coverage for the new functionality. This builds on ongoing work around reference backend flexibility and could be particularly relevant for server-side operations where reference migration downtime is problematic. The proposal doesn't mention any potential security implications of allowing arbitrary reference storage locations, which might be a point for discussion.
