This is a bug report identifying platform-specific test failures in the recently merged `git last-modified` performance optimization. Anders Kaseorg reports that test script t8020-last-modified.sh fails on s390x architecture, specifically in two merge-related test cases (16 and 19) that check cross-merge boundary behavior.

The failures occur after commit 2a04e8c293 ("last-modified: implement faster algorithm"), which introduced a new priority queue-based approach with EWAH bitmaps. The test failures show incorrect attribution of file modifications across merges - in test 16, it incorrectly attributes m1.t to the merge commit rather than m1, and in test 19, it attributes both files to the merge commit rather than their actual sources (b5 for file2 and b2 for file).

This appears to be a correctness regression in the merge handling logic of the new algorithm, though the issue only manifests on s390x. The report includes detailed test output showing the exact discrepancies between expected and actual attribution results. The thread context indicates this optimization had undergone extensive review and performance validation, but apparently missed this platform-specific edge case in merge handling.

Key technical details from the failure:
- Fails only on s390x (uname -m shows s390x)
- Two specific test cases fail: "cross merge boundaries in blaming" (test 16) and "last-modified merge undoes changes" (test 19)
- Shows incorrect attribution of merge parents' changes to the merge commit itself
- Diff output shows merge commit hash being incorrectly associated with files that should be attributed to parent commits

The report provides full reproduction details and bisection evidence pointing to the optimization commit as the regression source. This will likely need platform-specific debugging to determine why the generation-sorted priority queue behaves differently on s390x.
