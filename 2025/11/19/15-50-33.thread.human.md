This thread reports test failures in `git last-modified` during merge operations, primarily affecting the NonStop platform. The issue appears in Git 2.52.0, where tests t8020.16 and t8020.19 fail when the command outputs raw commit hashes instead of the expected tag names (m1.t, m2.t) across merge boundaries. Randall Becker confirms the problem is consistently reproducible on NonStop and raises concerns about whether to ship this version with known test failures.

The discussion connects to prior analysis from Jeff King in a related thread, suggesting the technical root cause may already be understood. While the core issue involves merge/tag resolution behavior, Randall also notes secondary problems with email client formatting (Outlook's line-wrapping breaking URLs) and build system quirks (`SANITIZE` flags), though these appear unrelated to the test failures. The key open question is whether this represents a test expectation issue or a deeper bug in Git's merge/tag handling, with implications for the 2.52.0 release on NonStop.
