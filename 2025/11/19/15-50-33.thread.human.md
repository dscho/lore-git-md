This thread concerns a bug report from Randall Becker about test failures in `git last-modified` during merge operations on NonStop platforms (tests t8020.16 and t8020.19). The issue appears to be a regression in Git 2.52.0 where the command incorrectly outputs commit hashes instead of the expected tag names (m1.t, m2.t) when crossing merge boundaries. While the failures are consistently reproducible on NonStop, it's unclear whether this is platform-specific or a more widespread issue - the tests pass on other platforms, but Randall suspects the problem may not be unique to NonStop environment.

Kristoffer Haugsbakk has now pointed to another related report that might provide additional context about the behavior of `git name-rev --tags` (which `git last-modified` uses internally) during merges. This suggests the issue may have broader implications beyond just the NonStop platform. The connection between these reports could help determine whether this is truly a platform-specific quirk or a more general regression in tag resolution behavior. The thread remains open with key questions about why this passed in testing (rc0) but failed in the final release, and whether OpenSSL version differences might be a contributing factor despite initial assessments suggesting they shouldn't affect this behavior.
