This thread continues to investigate test failures in `git last-modified` during merge operations, specifically affecting NonStop platforms. The issue first appeared in Git 2.52.0 (not in the release candidate), where the command incorrectly displays commit hashes instead of expected tag names (m1.t, m2.t) in tests t8020.16 and t8020.19.

Junio Hamano has confirmed the merge infrastructure itself is sound, pointing to a name resolution issue in `git last-modified`, which internally uses `git name-rev --tags`. Randall Becker, who originally reported the problem, has ruled out Jeff King's earlier suggestion about problematic casts and is now focusing on potential platform-specific behavior in how NonStop's compiler handles bitwise operations between enums and integers, particularly around the `BOUNDARY` flag. The big-endian architecture may be a factor here.

Randall's team faces packaging decision - whether to ship Git 2.52.0 on NonStop with known test failures - and is seeking debugging guidance for `builtin/last-modified.c` to better understand the discrepancy. While separate build system issues with `SANITIZE` flags remain, the core problem appears to lie in subtle platform differences in flag handling during merge operations. The platform-specific nature of the bug makes it particularly challenging to diagnose and fix.
