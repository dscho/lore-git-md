Bug report for test failures in t8020.16 and t8020.19 on NonStop platform. The reporter (Randall Becker) notes these failures appeared in the 2.52.0 release but weren't seen in rc0, though they are 100% reproducible and not transient. The failures involve the `git last-modified` command's behavior during merge operations.

The first failure (t8020.16) shows `git last-modified` incorrectly reporting the commit hash for m1.t instead of the expected tag name "m1" when crossing merge boundaries. The test expects the output to show tags (m2 m2.t and m1 m1.t) but gets commit hashes instead.

The second failure (t8020.19) demonstrates similar incorrect behavior during a more complex merge scenario where changes are undone. The test expects to see tags (b5 file2 and b2 file) but again gets commit hashes (da1857e... for both files).

The failures suggest a platform-specific issue with how `git last-modified` resolves commit references to tag names on NonStop systems, though the reporter suspects this might not be NonStop-specific. The test scripts themselves appear correct, as they follow standard Git test patterns with test_commit, merge operations, and verification steps. The core issue seems to be in the interaction between `git last-modified` and `git name-rev --tags` during merge operations.
