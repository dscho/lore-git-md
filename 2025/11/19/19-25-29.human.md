This is a refactoring patch in Patrick Steinhardt's ongoing series to prepare Git's object streaming for pluggable backends. Justin Tobler is reviewing patch 3/18, which changes how object types are propagated through the streaming interface.

The patch moves the object type storage from being passed around via pointer parameters to being stored directly in the new `odb_read_stream` struct (alongside the existing size field). This simplifies the control flow by making the type handling more self-contained within the stream object. Justin notes this is a positive change that reduces explicit parameter passing.

A key observation is that while the stream now internally tracks the type, the external `open_istream()` interface still accepts a type pointer parameter for output - similar to how it handles object sizes. Justin initially found this surprising but recognizes it's necessary since `odb_read_stream` is meant to be opaque to callers.

The change is part of a broader effort to clean up the streaming interface in preparation for pluggable backends, with each patch making incremental improvements while maintaining existing behavior. Justin's review suggests this particular change is well-justified and implemented cleanly.
