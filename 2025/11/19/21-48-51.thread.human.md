This thread focuses on implementing reference storage backend selection via URI syntax, primarily to support GitLab's need for zero-downtime migrations between files and reftable backends in large repositories. The discussion has progressed through two versions, with significant architectural questions being resolved.

The core implementation now includes a refactored `get_ref_store_for_dir()` helper and supports two proposed URI syntax formats: `<backend>://<URI>` (current implementation) and `<backend>:<URI>` (Junio and Karthik's alternative). A major breakthrough came when Junio Hamano accepted the use of environment variables (`GIT_REF_URI`) for temporary overrides, following Git's established patterns like `GIT_DIR`. Karthik Nayak confirmed this alignment in the latest message, noting that the v2 cover letter was updated to clarify the migration workflow will use `git update-ref` operations against dry-run folders rather than a direct `git refs migrate` command.

While the environment variable approach is now settled, two key design decisions remain open: the URI format separator (`://` vs `:`) and filesystem path handling (whether to require explicit `file://` prefixes). The implementation has seen thorough review from multiple contributors including Karthik Nayak (architecture), Toon Claes (validation), Eric Sunshine (tests), and Jean-Noël Avila (documentation), with the remaining work focused on finalizing these last syntax questions before the series can be merged.
