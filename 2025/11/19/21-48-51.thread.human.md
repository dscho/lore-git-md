This thread has been exploring how to implement reference storage backend selection in Git, particularly to support GitLab's need for zero-downtime migrations between filesystem and reftable backends. The current implementation (v3) uses a `GIT_REF_URI` environment variable following a `<backend>://<URI>` format, which has addressed many technical concerns through several iterations of review.

Patrick Steinhardt has now proposed a significant design alternative: extending the existing `extensions.refStorage` config option to support URI syntax instead of relying primarily on an environment variable. His approach would create a more consistent interface between configuration and environment overrides while better aligning with his parallel work on object database URIs. The proposal would require refactoring how worktree references are handled in `ref_store_init()`, letting backends determine reference locations rather than hardcoding the logic.

The thread has seen substantial technical refinement, with the v3 implementation already addressing feedback from multiple reviewers (Karthik Nayak on architecture, Eric Sunshine on tests, Junio Hamano on design principles). Key decisions remain about whether to stick with the environment variable approach or pivot to Steinhardt's config-based solution, along with unresolved questions about filesystem path handling (whether to require explicit `file://` prefixes). The discussion now centers on these architectural tradeoffs before the series can be finalized.
