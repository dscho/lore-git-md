This thread discusses a proposal to introduce a `GIT_REF_URI` environment variable for controlling Git's reference storage location and backend. The initial two-part series aims to enable specifying reference backends via URI syntax (like `reftable://` or `files://`), with a focus on non-blocking migrations between backends—particularly useful for large repositories transitioning from files to reftable where migrations can take minutes.

The first patch, now refined, extracts the ref_store creation logic from `get_main_ref_store()` into a new `get_ref_store_for_dir()` helper function. This mechanical refactoring maintains existing behavior while preparing the infrastructure for URI-based reference store creation in the second patch. The changes touch core refs.c functionality but are straightforward, focusing on code organization rather than behavioral changes. The proposal builds on ongoing ref backend flexibility work and includes thorough test coverage, though security implications around arbitrary reference storage locations remain an open discussion point.
