This thread centers on enabling Git to switch between reference storage backends (files and reftable) using URI syntax, particularly for GitLab's need to migrate large repositories without downtime. The v3 patch series has reached consensus on using the `GIT_REF_URI` environment variable as the mechanism, following the model of `GIT_OBJECT_DIRECTORY`.

The latest patch implements the environment variable support, with strict validation requiring the `<backend>://<path>` format and comprehensive test coverage. Core reviewers including Karthik Nayak, Toon Claes, and Eric Sunshine have validated the architecture and implementation details through multiple iterations. Junio Hamano has approved the refactoring approach and environment variable design.

One remaining design question involves filesystem path handling—whether paths should require an explicit `file://` prefix or allow implicit interpretation. This is the last significant open issue before the series can be finalized. The implementation otherwise appears robust, with thorough error handling and test coverage in t1423-ref-backend.sh. The work builds on prior refactoring to make the reference storage system backend-agnostic while maintaining compatibility with existing workflows.
