This thread introduces a new `GIT_REF_URI` environment variable that allows specifying Git's reference storage location via URI syntax (e.g., `reftable:///path`), primarily to enable non-blocking migrations between backends like files and reftable. The two-part patch series refactors the ref_store creation logic and implements URI parsing with comprehensive error handling and test coverage.

The implementation has received substantive review, with Eric Sunshine identifying two test suite improvements needed: replacing bare `!` error checks with `test_must_fail` and clarifying the nested loop structure in cross-backend tests. Karthik Nayak has acknowledged both issues as oversights and committed to address them in the next version. 

With these minor test suite polishings being the only outstanding items, the series appears functionally complete and well-vetted. The changes enable an important capability for large repositories needing to switch reference backends without downtime, particularly relevant for server-side operations. The thread shows the patches are now in their final refinement stage before likely merging.
