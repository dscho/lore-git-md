This is part 4/18 of Patrick Steinhardt's series refactoring Git's object streaming infrastructure for pluggable ODB backends, focusing on internal interface improvements.

The patch modifies how packed object streaming handles packfile information. Previously, `open_istream_pack_non_delta()` relied on the caller to pre-populate the stream's pack/offset fields before calling it, creating an implicit coupling. The change makes this explicit by having callers pass the packfile and offset directly as parameters, while moving the field assignments into the function itself.

Key technical changes:
- Adds `pack` and `offset` parameters to `open_istream_pack_non_delta()`
- Moves pack/offset assignments from callers into the function
- Updates the single call site in `istream_source()` to use the new interface
- Maintains all existing behavior while making the control flow clearer

This prepares for future changes where the function will handle stream allocation, as noted in the commit message. The change affects only the packed object path in streaming.c, with no user-visible impact. The diff shows straightforward mechanical changes to parameter lists and field assignments, with the core unpacking logic remaining unchanged.

This continues the series' pattern of cleaning up internal interfaces before introducing more substantial backend changes, with particular attention to the packed object handling path. The explicit parameter passing makes the code more maintainable and sets up for the next steps in the refactoring.
