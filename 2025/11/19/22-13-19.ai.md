This is a review comment on the test suite for the GIT_REF_URI feature. Eric Sunshine points out two specific issues with the test implementation in patch 2/2 of the series:

1. The tests use bare `!` for error checking rather than the preferred `test_must_fail` helper, which provides better error messages and handles edge cases more robustly. This appears in the test for empty URI validation.

2. The nested loop structure that iterates through reference backend formats (`files` and `reftable`) doesn't actually use the loop variables in the test bodies - the tests hardcode `files` and `reftable` values directly. This makes the loop structure misleading and potentially incomplete in its coverage. The reviewer also suggests including the format values in test titles if the loop approach is kept.

The review doesn't challenge the core functionality but focuses on test quality and correctness. The issues raised are straightforward to address and don't indicate deeper problems with the feature implementation. The feedback suggests the test suite needs minor polishing to follow Git's testing conventions and fully realize its intended cross-backend verification.
