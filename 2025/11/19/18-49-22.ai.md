This is a review comment on an early patch in Patrick Steinhardt's ongoing refactoring series for pluggable ODB backends. Justin Tobler responds to patch 1/18 which renamed `git_istream` to `odb_read_stream` as part of making the streaming interface more backend-controlled.

Justin agrees with the renaming rationale, noting it aligns with the existing `odb_write_stream` naming pattern. He observes the current `git_istream` implementation already shows some generic characteristics by supporting multiple object sources (loose/packed), though source handling remains centralized in streaming.c. The comment suggests moving toward direct backend control of streams without streaming.c mediation.

While approving the change, Justin suggests enhancing the header comment to better document the structure's purpose. This minor documentation improvement would complement the structural changes in this foundational patch of the series. The exchange shows careful consideration of interface design early in the multi-patch refactoring effort.
