This is a refactoring patch in Patrick Steinhardt's ongoing series to make Git's object streaming infrastructure work with pluggable ODB backends. Patch 14/18 moves the definition of `struct odb_read_stream` from streaming.c to streaming.h, making it public so backend implementations can allocate and initialize these streams directly.

Karthik Nayak reviews the change and raises a good question about API design: since the stream struct already contains the object type and size, why does `open_istream()` still take these as separate output parameters? This suggests the API could be further simplified by having callers read these values directly from the returned stream object.

The change itself is straightforward - just moving the struct definition to a public header - but it's part of the larger architectural shift where backends will take more responsibility for stream creation. The review discussion hints at potential follow-up cleanups to the streaming interface.
