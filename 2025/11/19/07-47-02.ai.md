Refactoring patch in the object streaming infrastructure series, focusing on simplifying stream initialization.

This second patch in the 18-part series eliminates the indirect `open()` callback from the `odb_read_stream` interface, opting for direct initialization calls. The change addresses an architectural awkwardness where stream structures needed partial population before initialization, which would complicate the planned move of stream creation responsibility to backend-specific code. The patch modifies `istream_source()` to immediately call the appropriate backend-specific open functions (loose, packed, or in-memory) rather than storing them for later use.

Key technical details: Removes the `open_istream_fn` typedef and associated callback field from `struct odb_read_stream`, while preserving the close/read callbacks. The logic in `istream_source()` now directly handles all three stream types with early returns, falling back to in-memory streams when needed. The change affects core streaming operations but maintains identical external behavior, as evidenced by the unchanged `open_istream()` interface.

This change is a prerequisite for subsequent patches that will move stream allocation into backend-specific code. The implementation appears clean and focused, with straightforward logic flow and no obvious edge cases left unhandled. Reviewers should verify the error handling paths (particularly the fallback to in-memory streams) maintain the expected behavior as the series progresses toward its goal of pluggable object database backends.
