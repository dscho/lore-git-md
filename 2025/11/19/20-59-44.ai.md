This is a refactoring patch that introduces a new `oidset_equal()` function for comparing two sets of object IDs, as part of Patrick Steinhardt's larger ODB abstraction series. The patch modifies `oidset_iter_init()` to take a const parameter since iterators shouldn't mutate their input sets, which Junio confirms is the correct approach.

The new comparison function will be useful for the ODB work where sets of object IDs need to be compared, though the immediate motivation isn't stated in the commit message. The change is straightforward and maintains the existing pattern of the oidset API. Junio's positive response suggests this is a non-controversial addition that fits well with the series' goals.

For future reference in this thread: the patch adds `int oidset_equal(const struct oidset *a, const struct oidset *b)` to oidset.h/c, and modifies `oidset_iter_init()`'s signature to take `const struct oidset *`. The implementation simply compares hashmap sizes and contents. This is a pure utility function with no direct behavior changes, but enables cleaner comparisons in the ODB refactoring work.
