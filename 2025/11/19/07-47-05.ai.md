This is part 5/18 of Patrick Steinhardt's series refactoring Git's object streaming infrastructure for pluggable ODB backends. The patch focuses on restructuring how stream objects are allocated and initialized.

The key change moves stream allocation from the generic `open_istream()` function into the backend-specific open functions (`open_istream_loose`, `open_istream_pack_non_delta`, `open_istream_incore`). This prepares for future changes where each stream type will have its own structure with `struct odb_read_stream` as a base member, similar to how reference databases work.

The patch modifies all three backend implementations to:
1. Take a double pointer output parameter instead of a pre-allocated stream
2. Handle their own memory allocation (using `CALLOC_ARRAY`)
3. Initialize the stream structure before returning it

The loose object streaming path gets special handling because it needs to initialize the zlib stream early, before knowing if the operation will succeed. The packed and in-memory backends are simpler, using stack-allocated temporary structures before copying to the final allocated stream.

This change makes the streaming interface more suitable for pluggable backends by:
- Removing the need for a union of backend-specific members
- Allowing backend-specific structures to be defined outside streaming.c
- Maintaining the same external behavior while changing internal allocation patterns

The patch is part of the larger effort to abstract object database backends and remove `the_repository` usage. It follows logically from the previous patches that standardized stream naming and simplified initialization. The changes are internal plumbing with no user-visible effects, but they enable future backend-specific stream implementations.
