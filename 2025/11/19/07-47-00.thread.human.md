Patrick Steinhardt's 19-part series refactoring Git's object database streaming interface continues to make steady architectural improvements. The latest patch (13/19) focuses on eliminating remaining uses of the global `the_repository` variable in the streaming code, a key goal of the overall effort. 

The changes are mechanical but important: `open_istream_pack_non_delta()` now properly uses its object database parameter instead of the global repository, and `stream_blob_to_fd()` has been renamed to `odb_stream_blob_to_fd()` while being updated to take an explicit object database parameter. This affects several callers across cat-file, fsck, log, entry, and parallel-checkout code, all of which now pass `the_repository->objects` explicitly.

Junio Hamano has been closely reviewing the series, having previously suggested the verb-first naming convention that was adopted. The changes maintain the series' trajectory toward clearer subsystem boundaries while removing implicit global state. With patch 12/19 recently merged, which changed object selection precedence rules to use source list iteration rather than hardcoded preferences, the streaming interface continues evolving toward a more modular design that could support pluggable backends in the future.
