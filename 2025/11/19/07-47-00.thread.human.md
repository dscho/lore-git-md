This thread discusses a major refactoring of Git's object streaming infrastructure to support pluggable object databases, led by Patrick Steinhardt. The 18-patch series moves stream creation responsibility from centralized code to individual ODB backends, building on Steinhardt's prior work in this area.

The first patch established the new canonical interface by renaming core streaming structures from `git_istream` to `odb_read_stream` across multiple files, setting up the architectural foundation without changing behavior. The second patch, just submitted, simplifies stream initialization by eliminating an indirect callback mechanism in favor of direct backend-specific calls. This change removes an architectural awkwardness that would complicate the planned backend-specific stream creation, maintaining identical external behavior while making the code more straightforward.

The series will next create distinct backend structures for different stream types, move zlib handling into backends, and continue eliminating `the_repository` usage. Reviewers should pay particular attention to the interface implications and error handling paths as the changes progress, given the broad scope touching core object handling across commands like `cat-file` and `fsck`. The work maintains backward compatibility while enabling future pluggable implementations.
