Patrick Steinhardt's series to refactor Git's object streaming infrastructure for pluggable ODB backends continues to progress, now at patch 14/18. The series systematically prepares for pluggable backends by standardizing interfaces and isolating backend-specific logic, with previous patches restructuring type handling and eliminating global state.

The latest change moves `struct odb_read_stream` from streaming.c to streaming.h, making this internal structure public so backend implementations can allocate streams directly. While the change itself is straightforward (11 lines moved), Karthik Nayak's review identified an opportunity to further improve the API design - questioning why `open_istream()` still takes object type/size as output parameters when these values are already available in the stream struct. This may lead to a follow-up cleanup.

Karthik has been consistently providing thorough reviews throughout the series (now his fifth review), helping catch API consistency issues early. The collaboration between Patrick and Karthik continues to be productive as they work through the architectural changes needed to make the object database backend properly pluggable. The series maintains its focus on exposing previously internal structures while preserving existing behavior during the transition.
