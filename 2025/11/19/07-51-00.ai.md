This is part 12/13 of Patrick Steinhardt's series refactoring object database (ODB) source management, continuing the systematic relocation of ODB responsibilities from setup.c to odb.c.

The patch addresses how Git handles repository directory changes, particularly focusing on the commondir path updates when the working directory changes. Currently, `repo_set_gitdir()` serves two purposes: initial repository setup and updating paths during working directory changes. The patch moves responsibility for updating ODB paths into odb.c itself by:

1. Adding a chdir notification callback (`odb_update_commondir`) that updates relative paths in the ODB when the working directory changes
2. Registering this callback during ODB creation and unregistering during cleanup
3. Preventing ODB reinitialization when only updating paths (via new `skip_initializing_odb` flag)
4. Splitting `set_git_dir_1()` to handle the two distinct cases (initial setup vs path updates)

Key technical details:
- Touches odb.c, odb.h, repository.c, repository.h, and setup.c
- Introduces `skip_initializing_odb` flag in `set_gitdir_args`
- Makes `odb_source_new()` static since it's now only used internally
- Uses `chdir_notify_register()`/`unregister()` from previous patch
- Maintains backward compatibility for relative path reporting

The change is part of the larger effort to properly encapsulate ODB management while working around current limitations where some paths must remain relative for compatibility. The implementation is careful to handle edge cases while keeping the changes focused and mechanical.
