Refactoring patch in Patrick Steinhardt's object streaming series, moving stream allocation into backend-specific logic. This fifth patch in the 18-part series continues the architectural cleanup of Git's object streaming infrastructure in preparation for pluggable ODB backends. The key change here is reversing the allocation pattern - instead of allocating a generic stream structure first and then populating it with backend-specific data, the backend functions now handle both allocation and initialization.

The patch modifies the three backend implementations (loose objects, packed objects, and in-memory objects) to allocate their own stream structures. This enables future patches to use backend-specific structures that embed the generic `odb_read_stream` as their first member, similar to how reference databases work. The changes are mechanical but important for the loose object case requires careful handling of the zlib stream initialization.

The commit message clearly explains the motivation: this change makes the code more maintainable by keeping backend-specific logic in their respective subsystems rather than requiring all knowledge to live in streaming.c. It's a well-contained change that touches only streaming.c, with no behavior modifications - just moving allocation points and adjusting function signatures. The diff shows thorough attention to error handling and memory management in each backend case.
