This is part 6/7 of the submodule gitdir path encoding series, implementing a final fallback mechanism for path conflicts. The patch adds a hashed-name fallback when all other conflict resolution strategies (plain path, URL encoding, digit appending) fail to find a valid gitdir path.

The key technical addition is in `submodule_name_to_gitdir()`, which now computes a hash of the submodule name (using the same blob-hashing mechanism as `git hash-object`) when all previous resolution steps fail. This serves as a last-resort solution to avoid filesystem conflicts, though it makes paths non-human-readable. The commit notes this is acceptable since `submodule.<name>.gitdir` config serves as the authoritative path reference.

The patch includes extensive test coverage in t7425, simulating an extreme case where 20+ conflicting submodule names exhaust all numeric fallback options before resorting to hashing. The test verifies the hash-based path works while all previous conflict variants maintain their expected paths. The hashing implementation uses Git's standard hash algorithms and follows the same pattern as object hashing for consistency.

This completes the series' conflict resolution ladder:
1. Plain path
2. URL-encoded path
3. Digit-appended variants
4. Hashed name (new in this patch)

The change maintains the series' architectural principles while handling an edge case that could occur with many similar submodule names. The implementation is careful to reuse existing hash infrastructure rather than inventing new naming schemes.
