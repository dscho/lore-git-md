This is a bug report regarding platform-specific test failures in the recently merged performance optimization for `git last-modified`. Anders Kaseorg reports that two tests in t8020-last-modified.sh are failing on s390x architecture after commit 2a04e8c293 ("last-modified: implement faster algorithm").

The failing tests involve merge scenarios:
1. Test 16 ("cross merge boundaries in blaming") shows the output order is reversed (m1.t appears before m2.t when it should be after)
2. Test 19 ("last-modified merge undoes changes") shows the merge commit hash being reported instead of the expected b5/b2 commits for file2/file respectively

The issue appears specific to s390x, suggesting an endianness or alignment problem in the new bitmap-based algorithm. This comes after extensive review and benchmarking that validated the approach on other platforms, with the series having been merged to 'next' with Taylor Blau's Acked-by.

The report includes detailed test output showing the exact differences between expected and actual behavior in these merge scenarios. Given the prior thorough review, this likely represents an edge case that wasn't caught in testing on other architectures. The bug doesn't appear to affect the core performance improvements but does impact correctness in merge-heavy workflows.
