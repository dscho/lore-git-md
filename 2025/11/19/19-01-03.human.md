This is a refactoring patch in Patrick Steinhardt's series to prepare Git's object streaming for pluggable backends. Justin Tobler is reviewing patch 2/18, which removes the `open()` callback from the streaming infrastructure.

The change simplifies the stream initialization process by opening streams immediately rather than first setting up a callback. This eliminates an awkward intermediate state where the structure was partially populated before being fully initialized. The patch maintains all existing fallback behavior while making the code more straightforward.

Justin notes the change looks correct and asks whether there's ever a case where we'd want delayed stream opening, suggesting the immediate approach makes sense if not. He also catches a minor typo in the original commit message ("it's" -> "its") and confirms the error handling preserves the original fallback behavior.

The change is part of the broader effort to move stream creation fully into backend-specific code, removing an obstacle for future patches in the series. The review interaction shows careful attention to both the immediate change and how it fits into the larger architectural direction.
