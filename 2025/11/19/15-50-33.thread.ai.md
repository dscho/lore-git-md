Thread identity: Bug report for test failures in t8020.16 and t8020.19 involving `git last-modified` command during merge operations, reported by Randall Becker against Git 2.52.0 on NonStop platform.

Core problem: `git last-modified` incorrectly reports commit hashes instead of expected tag names (m1.t, m2.t) when crossing merge boundaries, failing tests t8020.16 and t8020.19. The issue is reproducible on NonStop and may not be platform-specific. Tests use standard patterns (test_commit, merges) and expect tag names in output.

Current status: Failures appeared in 2.52.0 release (not in rc0), suggesting regression. Tests pass on other platforms but consistently fail on NonStop. Kristoffer Haugsbakk linked a related report (4dc4c8cd-c0cc-4784-8fcf-defa3a051087@mit.edu) that may provide additional context.

Key technical details:
- Tests create merge scenarios with tags (m1.t, m2.t)
- `git last-modified` uses `git name-rev --tags` internally
- Failure shows commit hashes (da1857e...) instead of tags
- Affects both simple (t8020.16) and complex (t8020.19) merge cases
- NonStop platform behavior differs from others
- Potential OpenSSL 3.4 version consideration (though likely unrelated)

Open questions:
- Is this truly NonStop-specific or a general issue?
- Why did it pass rc0 but fail final release?
- Does `git name-rev --tags` behave differently on NonStop?
- Does linked report contain relevant information about tag resolution behavior?
