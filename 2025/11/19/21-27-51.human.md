This is a bugfix in the index-pack command, part of Patrick Steinhardt's ongoing object database refactoring series. The patch addresses a segfault that could occur when running `index-pack --fsck-objects` outside a repository context.

The fix changes the behavior to fail with a clear error message when queued object checks (for gitmodules and gitattributes) cannot be completed due to the lack of a repository, rather than silently skipping them or crashing. Junio Hamano notes this is a reasonable approach, though it means some packfiles (particularly those from non-Git implementations that might order blobs before trees) may not be fully verifiable outside a repository context.

The patch includes a new helper function `fsck_has_queued_checks()` that uses the recently added `oidset_equal()` utility to detect pending checks. Junio confirms the solution is technically sound, though he points out it's a "best-effort" validation for repository-less cases. The change fits well with the series' goal of properly handling object database operations.
