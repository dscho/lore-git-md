Bugfix for `git fetch`'s batched reference updates, specifically addressing non-conflicting tags not being committed when other conflicts exist. This is patch 2/3 in a series that has evolved through seven versions, with all prior review feedback incorporated.

The core issue stems from commit 0e358de64a introducing batched updates, where tag fetching would skip transaction commits entirely when conflicts occurred. The fix modifies the cleanup section in `do_fetch()` to commit non-atomic transactions even when errors occur, ensuring non-conflicting references (including tags) still get applied. The change handles both direct tag fetching via `fetch_and_consume_refs()` and indirect backfilling during refspec fetches.

Key technical aspects:
- Adds transaction commit in cleanup when `retcode` is set but not using atomic_fetch
- Maintains existing behavior for pre-transaction failures (truncate_fetch_head, etc.)
- Preserves atomic fetch semantics where failures abort all updates
- Adds three new test scenarios:
  - Basic `--tags` fetching verification
  - Non-conflicting tags with parallel conflicts
  - Backfill tag verification during refspec fetches
- Includes test cleanup improvements using `test_when_finished`

The patch demonstrates careful consideration of edge cases while maintaining the performance benefits of batched updates. Test coverage is thorough, verifying both the regression fix and related scenarios. The solution aligns with the series' goal of fixing batched update regressions while preserving backward compatibility.
