This is the first patch in a 3-part series fixing batched reference update regressions in `git fetch`. It's a preparatory refactoring that extracts transaction committing logic into a new `commit_ref_transaction()` helper function.

The patch moves the transaction commit and rejection handling code from `do_fetch()` into a standalone function that:
- Takes the transaction as a pointer-to-pointer for proper cleanup
- Accepts atomicity flag and remote name parameters
- Uses an error strbuf for reporting
- Handles both atomic and non-atomic cases
- Maintains the same control flow with `goto out` pattern

The refactoring enables cleaner implementation of the bugfix in subsequent patches while preserving existing behavior. The new helper centralizes transaction lifecycle management, which will be reused when fixing the tag commitment issue. The change is purely structural - no behavior modifications are introduced in this patch.

Key technical details:
- New function signature: `commit_ref_transaction(struct ref_transaction **, bool, const char *, struct strbuf *)`
- Maintains identical error handling paths
- Preserves atomic/non-atomic distinction
- Keeps same rejection handler callback
- Uses same transaction cleanup pattern

This foundational change demonstrates careful preparation for the actual bugfix while keeping the diff focused and reviewable. The patch follows good practice by separating refactoring from behavior changes, making the subsequent fixes easier to verify.
