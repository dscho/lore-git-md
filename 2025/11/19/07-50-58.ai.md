This is part 10/13 of Patrick Steinhardt's series refactoring object database (ODB) source management, continuing the effort to centralize ODB initialization logic. The patch moves ODB source initialization from `repo_set_gitdir()` into `odb_new()`, making object database creation more self-contained.

The change modifies `odb_new()` to take two new parameters - `primary_source` and `alternate_sources` - and handles the full initialization of the ODB structure including its sources. This eliminates the previous split where an empty ODB was created in `initialize_repository()` and later populated in `repo_set_gitdir()`. The patch touches three files:
- odb.c: Adds source initialization logic to `odb_new()`
- odb.h: Updates function signature and adds detailed docstring
- repository.c: Simplifies `repo_set_gitdir()` by delegating to the enhanced `odb_new()`

Key technical points:
- Maintains backward compatibility by deriving default primary source from `commondir` when none provided
- Preserves existing behavior for alternate object databases
- Handles both fresh ODB creation and reinitialization cases
- The commit message notes this is preparatory work for further ODB source management changes

This continues the series' pattern of methodical, well-explained changes that incrementally move ODB management responsibilities to odb.c. The patch appears mechanically sound and maintains the series' focus on centralizing ODB logic while preserving existing behavior. The next patch (mentioned in the commit message) will address remaining direct source manipulation in `repo_set_gitdir()`.
