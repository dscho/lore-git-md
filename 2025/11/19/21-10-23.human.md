This is a feature patch series (v5) implementing submodule gitdir path encoding to prevent filesystem conflicts. The series has evolved through several rounds of review and now includes build-time configuration options and additional fallback mechanisms.

The core feature adds an `extensions.submoduleEncoding` config that encodes submodule gitdir paths to avoid conflicts on case-insensitive filesystems or with nested submodules. The implementation uses URL percent-encoding for conflicts and maintains backward compatibility through config-based transition.

Key changes in v5 include:
1. Added build-time configuration option to force-enable the extension (requested by Josh Steadmon for large-scale deployments)
2. Improved validation of gitdir paths with stricter checks
3. Added fallback to hashed names when encoding fails
4. Expanded test coverage for edge cases like case-folding conflicts and extension disabling
5. Code cleanups and bug fixes from previous review feedback

The series appears well-tested with comprehensive new tests in t7425-submodule-encoding.sh. It addresses real-world deployment concerns raised by Google's experience while maintaining the core architectural approach that has received broad agreement from maintainers. The build-time configuration option in particular helps address enterprise-scale adoption challenges.

This represents the final polishing phase before potential merge, with the technical approach settled and now focusing on deployment ergonomics. The changes are focused and incremental, building toward a solution that handles both new and existing repositories safely.
