This is a bug report follow-up regarding test failures in the `git last-modified` command during merge operations. Kristoffer Haugsbakk is responding to Randall Becker's original report about consistent test failures (t8020.16 and t8020.19) on the NonStop platform, where `git last-modified` outputs commit hashes instead of the expected tag names (m1.t, m2.t) when crossing merge boundaries.

The email notes that this issue was also reported elsewhere (linking to another mailing list thread), suggesting it may be getting broader attention. The core problem appears to be in how `git name-rev --tags` (used internally by `git last-modified`) resolves names during merge operations, though it's still not clear whether this is NonStop-specific or a more general issue.

The tests create standard merge scenarios with tags and expect tag names in the `last-modified` output, but instead see raw commit hashes. While Randall observed this only in the final 2.52.0 release (not in rc0), Kristoffer's reference to another report hints this might be affecting multiple users. The discussion continues to investigate whether this is platform-specific behavior or a more fundamental issue in the command's merge handling.
