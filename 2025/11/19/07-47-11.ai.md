This is part 11/18 of Patrick Steinhardt's series refactoring Git's object streaming infrastructure for pluggable ODB backends, focusing on packfile handling. The patch extracts object info reading logic from `do_oid_object_info_extended()` into a new `packfile_store_read_object_info()` function that operates directly on the packfile store. This change makes `find_pack_entry()` an internal implementation detail (now static) and requires moving `packfile_store_freshen_object()` in the file to maintain compilation order.

Key technical changes include:
- New public API `packfile_store_read_object_info()` that handles packed object info lookup and error cases
- Removal of direct `find_pack_entry()` calls from odb.c in favor of the new store-based interface
- Preservation of all existing error handling paths (bad objects, retries, etc.)
- Internal reorganization to keep `find_pack_entry()` visible to moved functions

The change continues the series' pattern of decoupling packfile operations from the core ODB interface while maintaining identical external behavior. It prepares for future backend implementations by further isolating packfile-specific logic. The patch touches core object lookup paths but maintains all existing behavior, including the handling of quick vs full lookups and object corruption cases.
