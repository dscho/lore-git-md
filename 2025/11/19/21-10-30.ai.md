This is a build system patch completing the submodule gitdir path encoding series by adding a build-time configuration option for the feature. The patch allows enabling `extensions.submoduleEncoding` by default at build time via both autoconf (`--enable-submodule-encoding`) and meson (`submodule-encoding` option), while maintaining the existing behavior where repository-specific configs override this default.

The implementation adds:
- Build system plumbing in both autoconf and meson
- Documentation update noting the build-time option takes lower precedence than repo config
- `SUBMODULE_ENCODING_BY_DEFAULT` preprocessor definition
- Initialization of `repo_fmt.submodule_encoding` in `setup.c` when the build flag is set

This addresses deployment challenges raised earlier in the thread by Josh Steadmon, providing an alternative path for organizations that want to standardize on the encoding without requiring per-repository configuration changes. The patch maintains the series' careful approach to backward compatibility while adding flexibility for large-scale deployments.

The change is straightforward and well-contained, touching only build infrastructure and initialization code. It follows the established pattern of other build-time configuration options in Git's codebase. The documentation clearly explains the precedence rules between build-time and repository settings.
