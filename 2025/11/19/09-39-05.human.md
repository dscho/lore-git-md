This is a review comment on patch 2/18 of Patrick Steinhardt's series refactoring Git's object infrastructure. Karthik Nayak examines the removal of the `open()` callback function from the streaming interface.

The patch simplifies the streaming interface by removing the indirect `open_istream_fn` callback in favor of direct function calls. Karthik notes two behavioral changes in the implementation: first, the loose object case now checks the return value immediately rather than through the callback, and second, the packed object case restructures the control flow to use early breaks. He confirms both changes are safe since the functions return consistent error codes.

Karthik's review is positive, finding the changes sensible and the patch overall good. This appears to be a straightforward simplification that maintains the same functionality while making the code more direct, in line with the series' goal of cleaning up the streaming interface. The review doesn't raise any concerns or suggest improvements, indicating this part of the refactoring is uncontroversial.
