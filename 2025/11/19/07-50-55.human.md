Bugfix for `index-pack`'s deferred fsck checks outside repositories. This is patch 7/13 in Patrick Steinhardt's series refactoring object database management.

The patch addresses a segfault that occurs when running `git index-pack --fsck-objects` outside a Git repository while checking packfiles containing .gitmodules or .gitattributes files. These special files trigger deferred checks that require an initialized object database, which doesn't exist outside repositories. The solution introduces a new `fsck_has_queued_checks()` function and makes `index-pack` fail with a clear error message when deferred checks would be needed outside a repo, rather than silently skipping them or crashing. The change comes with a test case that verifies the new behavior.

This is a well-motivated fix that maintains consistency while improving error reporting. The patch is part of a larger effort to clean up object database handling, but stands on its own as a clear improvement to edge case behavior in `index-pack`. The commit message thoroughly explains the problem space and justification for the chosen solution over other possible approaches.
