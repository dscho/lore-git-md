This is a feature patch series (v5) introducing submodule gitdir path encoding to prevent filesystem conflicts. The series has evolved through architectural reviews and now addresses deployment concerns raised by Google's Josh Steadmon, with Adrian Ratiu as the primary implementer.

Key technical changes in v5 include:
- Added build-time configuration option to force-enable the extension (requested by Josh Steadmon)
- Improved case-folding conflict detection with new validation logic
- Added fallback to hashed names when encoding attempts fail
- Split validation functions between encoded/non-encoded paths
- Expanded test coverage for edge cases (disabled extension scenarios, nested submodules)
- Fixed various corner cases in the encoding logic

The implementation maintains the core architecture where:
- `extensions.submoduleEncoding` remains the opt-in mechanism
- `submodule.<name>.gitdir` config serves as the source of truth
- URL percent-encoding handles case-folding conflicts
- Filesystem moves only occur when absolutely necessary

Notable test additions verify:
- Nested submodule prevention (both with and without encoding)
- Case-folding scenarios (with new CASE_INSENSITIVE_FS prereq)
- Config validation edge cases
- Backward compatibility when disabling the extension

The build-time configuration addition (new commit 7/7) provides a deployment workaround for large-scale adopters while preserving the opt-in design. The series appears technically mature with thorough test coverage, addressing all major feedback from previous rounds while maintaining architectural consistency.
