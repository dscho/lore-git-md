This is a response in the ongoing discussion about SHA1/SHA256 submodule interoperability, specifically addressing deployment concerns from openSUSE.

brian m. carlson responds to Martin Wilck's real-world concerns about using submodules across hash algorithm boundaries in openSUSE's package management. The email provides important context about the history of SHA-256 support in Git, explaining why mixed-hash submodules were never properly supported despite initial plans for interoperability. The response makes clear that the current `sha256-interop` branch (while functional for non-submodule cases) is not production-ready and recommends sticking with tarballs for now.

The email also addresses a key operational question: repositories with mixed-hash history will remain problematic even after removing the submodule, as the incompatible objects remain in the history. brian explains that future interoperability work won't help these cases because the SHA-1 values were incorrectly stored as padded SHA-256 values. This suggests openSUSE would need to rewrite any affected repository histories to be fully safe.

The tone is informative and sympathetic to the deployment challenges while maintaining the technical position that mixed-hash repositories are invalid by design. It provides useful pointers to experimental work while being clear about its limitations, helping openSUSE make informed decisions about their version control strategy during the hash transition period.
