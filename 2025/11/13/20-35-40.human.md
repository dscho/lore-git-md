Review of Junio Hamano's response to the OSX keychain credential helper patch.

Junio raises two substantive concerns about the proposed fix for the credential storage skipping issue. First, he strongly questions the justification for reimplementing string buffer utilities rather than using Git's standard `strbuf.h`, noting that since the helper ships with Git and links against libgit.a anyway, there's no meaningful dependency cost to using the existing utilities. This continues the architectural discussion from earlier in the thread.

Second, while acknowledging the technical correctness of the credential state tracking approach, Junio asks the author to confirm they've considered the security implications of storing credential material in plaintext within the state buffer. He notes this likely isn't introducing new vulnerabilities since the keychain already handles sensitive data, but wants explicit confirmation the consideration was made.

The response maintains Junio's characteristic thorough review style - accepting the core solution while scrutinizing implementation choices and potential edge cases. The thread remains focused on refining the patch's architecture (string utilities) and confirming security considerations, with the underlying bugfix approach appearing sound. This moves the discussion toward likely needing a v2 patch that either justifies the custom utilities or adopts strbuf.h.
