This is a refactoring patch that's part of a series fixing a regression in `git fetch`'s tag handling. It extracts the reference transaction committing logic from `do_fetch()` into a new helper function `commit_ref_transaction()`.

The patch cleanly separates the transaction commit and rejection handling code that was previously embedded in `do_fetch()`. The new helper function takes parameters for the transaction (passed as a pointer-to-pointer for safe cleanup), atomicity flag, remote name for error context, and an error strbuf. It handles both the commit operation and (for non-atomic transactions) processing any rejected updates.

This is the first of two patches in the series, serving as preparatory work for the actual bugfix that follows. The commit message clearly explains that this refactoring will enable fixing a bug where tag conflicts were causing unrelated reference updates to fail. The implementation looks clean and well-structured, with proper error handling and memory management.

Reviewers (including Patrick Steinhardt) have already vetted this approach through multiple iterations (now at v5), and the patch appears ready for merging as part of the complete solution.
