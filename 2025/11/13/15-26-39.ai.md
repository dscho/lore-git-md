This is a bugfix for the OSX keychain credential helper that addresses an issue with credential storage skipping. The patch modifies how the helper tracks whether it has already seen a credential to prevent incorrect skipping of store operations.

The problem stems from commit e1ab45b2 which introduced a state flag to skip redundant stores, but the simple boolean approach could incorrectly skip storing valid credentials from other helpers. The fix replaces the boolean `state_seen` with a string that encodes the full credential details, allowing proper comparison between get/store operations.

Key technical changes:
- Replaces `int state_seen` with `char *state_seen`
- Adds string buffer utilities (`struct sb`) for building the state string
- Implements `encode_state_seen()` to serialize credential fields (host, port, path, username, password)
- Modifies both get and store operations to use the encoded state for comparison
- Includes memory management for the state string

The patch appears well-constructed with:
- Clear explanation of the problem and solution
- Self-contained string buffer implementation (avoiding external dependencies)
- Proper memory cleanup
-keeping with the credential helper's existing patterns

This fixes a real issue reported by Petter Sælen where invalid credentials could prevent subsequent storage of valid ones, with Junio Hamano providing guidance. The change is focused and maintains backward compatibility while solving the specific problem.
