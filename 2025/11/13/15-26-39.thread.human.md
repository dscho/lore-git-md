This thread addresses a bug in the OSX keychain credential helper where credentials could be incorrectly skipped during storage. The issue originated from commit e1ab45b2 which introduced a simple boolean flag to avoid redundant stores, but this approach sometimes prevented valid credentials from being saved when multiple helpers were involved.

Petter Sælen reported the problem, with Junio Hamano providing review feedback. The solution replaces the boolean flag with a more sophisticated state tracking system that encodes the full credential details (host, port, path, username and password) as a string. This allows proper comparison between get and store operations while maintaining the original optimization goal of avoiding redundant storage.

The patch introduces a self-contained string buffer implementation to handle the state encoding without external dependencies, and includes proper memory management. The change is focused specifically on fixing this edge case while maintaining backward compatibility with existing credential helper behavior. The implementation follows the helper's established patterns and appears ready for inclusion.
