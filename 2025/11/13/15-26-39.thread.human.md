The thread addresses a bug in the OSX keychain credential helper where credentials could be incorrectly skipped during storage. Petter Sælen reported the issue, which stemmed from an oversimplified boolean flag that didn't properly track credential state across operations. The proposed fix replaces this with a more robust string-based state tracking system that encodes all relevant credential details.

The patch itself appears technically sound and well-targeted, solving the core issue while maintaining backward compatibility. However, Junio Hamano has raised an important architectural question in his review - he questions why the patch introduces custom string buffer utilities rather than using Git's existing `strbuf.h` infrastructure. Junio argues that since the credential helper is built as part of Git anyway, concerns about external dependencies are misplaced.

This has sparked a discussion about when helper utilities should reuse core Git components versus maintaining independence. The original author will likely need to either provide stronger justification for the custom implementation or revise the patch to use Git's standard string utilities. While this is a secondary consideration to the main bugfix, it's an important design decision that could affect future maintenance. The core solution for the credential tracking issue remains valid regardless of which string implementation approach is ultimately chosen.
