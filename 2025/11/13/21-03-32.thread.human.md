This thread discusses the deprecation of `git whatchanged` and whether it should be restored given its typing convenience (6 keystrokes with tab completion) compared to its suggested replacement, `git log --raw --no-merges` (12 keystrokes). The original author argued that the deprecation warning was unclear about the exact replacement and that the ergonomic benefit justified keeping the command.

A follow-up email provided a practical workaround: users can now create an alias for `whatchanged` in Git versions 2.51.1 and later (including the upcoming 2.52.0) using `git config --global alias.whatchanged 'log --raw --no-merges'`. This wasn't possible in Git 2.51.0, which didn't allow aliasing builtin commands at all. The response also clarified that `--no-merges` is part of the closest equivalent functionality, addressing the original complaint about the deprecation message's lack of specificity.

While the thread hasn't reached a consensus on whether `git whatchanged` should be fully restored, the alias workaround offers a middle ground—preserving the typing efficiency while adhering to the deprecation. The discussion remains open on whether the command should be reinstated, but the practical solution may satisfy many users who valued its convenience.
