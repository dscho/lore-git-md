Review feedback on submodule ignore behavior implementation (patch 1/5).

Junio Hamano provides detailed code review comments on the first patch of the series implementing `ignore=all` submodule behavior for `git add`. While not commenting on the overall design (which was previously agreed upon), he identifies several mechanical issues that need fixing:

   - Incorrect indentation of the new `OPT_BOOL` line
   - Extra spaces in function call parentheses
   - Use of `//` comments instead of `/* */` style

2. **Parameter passing concerns**:
   - Suggests converting the new `include_ignored_submodules` parameter into a flag bit rather than adding a new parameter
   - Provides an example patch showing how to refactor the existing `include_sparse` into a flag bit first

3. **Code organization**:
   - Notes the deeply nested submodule check should likely be a separate helper function
   - Points out the growing size of `update_callback_data` struct

The review focuses on implementation quality rather than design, indicating the technical approach is sound but needs polish. Junio's suggested refactoring to use flag bits would maintain better long-term maintainability of the `add_files_to_cache` interface. The feedback doesn't block the series but identifies cleanup needed before final submission.
