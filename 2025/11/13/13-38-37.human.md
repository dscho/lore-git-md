Bugfix for `git fetch` tag handling in batched reference transactions. This is the second and final patch in a series that fixes a regression where non-conflicting tags would fail to update if any tag conflicts existed in the same fetch operation.

The patch modifies `do_fetch()` to properly commit non-atomic reference transactions even when some updates fail, specifically targeting cases where `fetch_and_consume_refs()` or `backfill_tags()` return errors. This ensures non-conflicting tags still update while properly reporting conflicts on others. The change maintains backward compatibility and simplifies error handling by checking any non-zero retcode.

Three new test cases verify the fix:
1. Basic tag fetching functionality
2. Proper handling of non-conflicting tags alongside conflicts
3. Correct backfilling of tags when fetching specific refspecs

This version incorporates all prior review feedback and appears ready for merging, with clean test repository handling and comprehensive coverage of the affected scenarios. The solution addresses the original regression while keeping the code maintainable.
