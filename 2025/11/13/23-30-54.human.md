Credential helper bugfix discussion. Brian M. Carlson responds to Koji Nakamaru's proposed revert of an OSX keychain credential helper optimization, suggesting the root issue may lie deeper in the HTTP credential handling code rather than the helper itself.

Carlson agrees the current behavior is problematic - where invalid credentials from one helper incorrectly block valid ones from subsequent helpers via the `state[]=osxkeychain:seen=1` flag - but argues the solution requires more nuance than a simple revert. They propose that state headers should persist across multistage authentication flows (needed for NTLM/Kerberos) but be reset between distinct credential requests.

The response suggests the HTTP credential handling code may be incorrectly reusing credential structures without proper reset between operations, though Carlson acknowledges the HTTP code's complexity makes this difficult to verify. This shifts the discussion from whether to revert the optimization to where exactly the state management should be fixed - in the helper itself or in Git's core credential handling infrastructure.

The technical depth of Carlson's response indicates this requires careful consideration of how credential state flows through Git's authentication stack, particularly for complex protocols. The discussion remains focused on finding a proper architectural solution rather than quick fixes.
