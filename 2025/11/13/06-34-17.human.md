This is a discussion about build system synchronization between Makefile and Meson, emerging from an ASan-related patch series.

Patrick Steinhardt responds to Taylor Blau's question about maintaining consistency between Git's Makefile and Meson build systems. The conversation stems from Patch 3 in Jeff King's series, which added NO_MMAP to the Makefile for ASan builds. Patrick had previously suggested the same change should be mirrored in Meson.

Taylor raises a broader question about build system synchronization policy - how strictly should changes to one build system require updates to the other, especially when contributors may not be familiar with both. Patrick takes a pragmatic view, suggesting that only changes critical for keeping CI green (like adding new source files) need strict synchronization, while other changes can be handled on a best-effort basis.

The exchange shows the maintainers working through practical concerns about maintaining dual build systems without overburdening contributors. While the immediate NO_MMAP change is straightforward, the discussion reveals ongoing questions about how to manage the Makefile/Meson relationship as the project transitions build systems.
