Bugfix for `git fetch` tag handling in batched reference transactions. This is the final version of a series that fixes a regression where non-conflicting tags would fail to update if any conflicts existed in the same fetch operation.

The patch series has gone through multiple rounds of review and now cleanly separates the fix into two parts: first extracting the reference committing logic into a helper function, then applying the actual fix. The solution ensures that when using non-atomic fetches, valid tag updates will now properly commit even if other references in the same operation have conflicts.

Key improvements in v5 include corrected assumptions about pruning behavior (which happens before transaction creation) and proper test repository cleanup. The series has addressed all feedback from reviewers including Eric Sunshine, Justin Tobler, Junio Hamano, and Patrick Steinhardt, with comprehensive test coverage verifying the fix works across all fetch paths.

The regression was originally reported by David Bohman and affects users fetching tags alongside other references. The fix maintains backward compatibility while properly handling the batched reference transaction case that was previously mishandled. With all verification points resolved and the final clarification acknowledged by Junio Hamano, this series appears ready for merging.
