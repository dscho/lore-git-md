This is a feature patch series addressing submodule behavior consistency, specifically for `ignore=all` configurations. The series implements a new `--include-ignored-submodules` option for `git add` to align with how `status` and `diff` handle ignored submodules.

The implementation modifies `add_files_to_cache()` to respect `ignore=all` submodules, only allowing updates when explicitly requested via the new flag. The series includes comprehensive tests in `t2206-add-submodule-ignored.sh` that verify the new behavior, including edge cases with pathspec matching and different configuration sources (.gitmodules vs command line).

Key technical changes include:
- New `include_ignored_submodules` parameter in `add_files_to_cache()`
- Submodule path matching logic that checks `ignore=all` configuration
- Warning messages guiding users to use the new flag when needed
- Updates to existing tests that relied on the old behavior
- Documentation updates for both the new option and `ignore=all` configuration

The series addresses workflow friction where developers unintentionally tracked submodule changes, particularly when using branch tracking. The implementation preserves the internal use of `override_submodule_config` for warning generation while providing a cleaner UX for the common case of ignored submodules.

This v2 iteration incorporates feedback from Phillip Wood, switching from `--force` to the more specific `--include-ignored-submodules` option name and improving commit message explanations of the historical behavior. The thread context shows this addresses the main technical concerns while leaving broader command scope alignment (for `reset`/`restore`) for future work.
