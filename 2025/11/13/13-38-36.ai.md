This is a refactoring patch that is part of a series fixing a regression in `git fetch`'s tag handling during batched reference transactions. It's the first of two patches in the final version of the series.

The patch extracts the reference transaction committing logic from `do_fetch()` into a new helper function `commit_ref_transaction()`. This prepares for the actual bugfix in the next patch by making the transaction handling code reusable. The new function centralizes:
- Transaction committing with error handling
- Non-atomic transaction rejection processing
- Transaction cleanup
- Error reporting via strbuf

The helper takes parameters for the transaction (as a pointer to allow NULLing it after cleanup), atomicity flag, remote name for error context, and an error strbuf. It maintains all existing behavior while simplifying the control flow in `do_fetch()` by replacing nested conditionals with a single function call.

The implementation follows review feedback to use pointer-to-pointer for safe transaction cleanup and consolidates the previously scattered transaction handling code. This is a clean refactoring with no behavior changes, establishing foundations for the actual fix in patch 2/2. The commit message clearly states this is preparatory work for the subsequent bugfix.
