This is a feature patch series that aligns `git add` behavior with other commands when dealing with submodules configured with `ignore=all`. The series addresses a long-standing inconsistency where `git add` would ignore this configuration while `git status` and `git diff` respected it.

The key change introduces a new `--include-ignored-submodules` option (replacing the initially proposed `--force` flag based on feedback) that allows explicitly adding changes from ignored submodules. The implementation carefully preserves the `ignore=all` behavior by default while providing an escape hatch when needed. The series includes comprehensive tests in a new `t2206-add-submodule-ignored.sh` file and updates several existing tests to use the new option.

The motivation is to reduce friction when using submodules with branch tracking, where accidental updates to the submodule reference can cause unnecessary conflicts. The changes make Git behave more like the Android `repo` tool in this regard. Documentation updates explain both the new option and the `ignore=all` configuration behavior.

This v2 iteration incorporates feedback from Phillip Wood, notably switching from `--force` to the more specific `--include-ignored-submodules` flag and expanding the commit messages with historical context. The implementation appears thorough, with careful attention to edge cases and comprehensive test coverage. The series is now focused solely on `git add`, deferring similar changes to `git reset`/`git restore` for potential follow-up work.
