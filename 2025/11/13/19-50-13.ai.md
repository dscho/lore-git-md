This is a documentation patch discussion about branch terminology and conceptual scope in the new `gitdatamodel.adoc` man page.

Julia Evans responds to Junio Hamano's proposal about expanding the definition of branches beyond just being refs under `refs/heads/`. She argues against including workflow-specific details in the data model documentation, maintaining that Git's flexibility is a key strength and that prescribing workflows would limit the document's usefulness. The current text simply notes that branches change over time when new commits are made, which Julia believes is the only universally applicable statement about branch usage.

The discussion reveals a tension between Junio's desire to explain branches as tools for growing history (including their relationship to HEAD, branch descriptions, and reflogs) and Julia's preference for a minimal technical definition that avoids workflow assumptions. Julia specifically objects to phrasing like "which is incorporated when the branch gets merged to an integration branch" as being too workflow-specific.

This email represents the final substantive discussion point before merging the documentation series, with all other technical aspects having been resolved in previous iterations. The core disagreement centers on whether the data model documentation should include conceptual explanations of how branches are typically used in workflows, or maintain a narrow focus on their technical implementation as mutable references. Julia's position is informed by her teaching experience and the document's goal of explaining Git's core data structures rather than prescribing usage patterns.
