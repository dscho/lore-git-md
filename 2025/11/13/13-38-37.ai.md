This is the second patch in a two-part bugfix series addressing a regression in `git fetch`'s tag handling during batched reference transactions. The regression was introduced by commit 0e358de64a and caused non-conflicting tags to fail when any conflicts existed in the same operation.

The patch specifically fixes the case where `fetch_and_consume_refs()` or `backfill_tags()` would return an error code (like when encountering tag conflicts), causing the entire transaction to be skipped rather than committing the non-conflicting updates. The solution modifies the cleanup path in `do_fetch()` to commit non-atomic transactions when there's an error code but atomic fetching isn't enabled.

Key technical details include:
- The fix adds conditional transaction committing in the cleanup section when `retcode` is set and `atomic_fetch` is false
- Three new test cases verify the fixed behavior:
  - Basic tag fetching with `--tags`
  - Handling of non-conflicting tags when conflicts exist
  - Proper backfilling of tags when fetching specific refspecs
- The tests include proper repository cleanup via `test_when_finished`
- Error handling is simplified to check any non-zero `retcode`

The patch builds on the foundation established in patch 1/2 (which extracted transaction committing logic into `commit_ref_transaction()`) and represents the culmination of five review iterations. It addresses all previous feedback and verification points, including proper test coverage and repository cleanup. The solution maintains backward compatibility while fixing the regression.
