This is the first patch in a v2 series implementing the `--include-ignored-submodules` option for `git add`, part of the broader effort to make submodule `ignore=all` behavior consistent across Git commands.

The patch introduces the core plumbing changes needed to support the new functionality. It modifies `add_files_to_cache()` to accept an `include_ignored_submodules` parameter and updates all callers to pass this new parameter (defaulting to 0 for backward compatibility). The main logic in `update_callback()` now checks for submodules with `ignore=all` configuration and either skips them (with a warning) or includes them based on the new flag.

Key technical details:
- Adds `include_ignored_submodules` static variable and option in `builtin/add.c`
- Updates function signatures in `read-cache-ll.h` and all callers (`add.c`, `checkout.c`, `commit.c`)
- Implements submodule handling logic in `read-cache.c` with:
  * Pathspec matching verification
  * Warning messages when skipping ignored submodules
  * Trace output for debugging
  * Preservation of existing behavior when flag is not set
- Maintains the `override_submodule_config` warning mechanism from previous versions

The implementation follows the design consensus from the thread discussion, particularly Phillip Wood's recommendations around explicit option naming and warning behavior. This foundational change enables the user-facing `--include-ignored-submodules` option that will be exposed in subsequent patches of the series.
