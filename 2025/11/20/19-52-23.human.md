This is a follow-up in the ongoing discussion about Windows/Meson build failures affecting the Rust infrastructure series for SHA-1/SHA-256 interoperability. Ezekiel Newren provides important historical context, confirming these Windows/MSVC+Meson issues predate the current changes and trace back to Patrick Steinhardt's initial Rust introduction series.

The key revelation is that the build system incorrectly handles library naming conventions on Windows - it should produce `<crate>.lib` for MSVC builds and `lib<crate>.a` otherwise, but currently only checks for the Windows platform without considering the compiler. This explains why the "win+Meson build" CI job (using MSVC) fails while the "win build" job (using GNU) succeeds.

Newren links to his earlier retrospective review that identified this issue, showing the problem has been known but unresolved. This confirmation that the failures are unrelated to the SHA-1/SHA-256 work helps clarify the path forward for the series. The thread now awaits diagnostic results from the enhanced CI logging to confirm the root cause before deciding whether to proceed with merging.
