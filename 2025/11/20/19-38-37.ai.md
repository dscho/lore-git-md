This is a follow-up review comment on the GIT_REF_URI feature implementation, specifically addressing the interaction between the environment variable and repository configuration state. Justin Tobler notes that while `GIT_REF_URI` overrides the reference backend at runtime, it doesn't update the repository's stored `ref_storage_format` value, which could lead to inconsistencies when querying repository information.

The key technical point is that commands like `git repo info references.format` would still report the original configured format rather than reflecting the active backend specified via `GIT_REF_URI`. This creates a potential mismatch between the actual reference storage in use and the repository's self-reported configuration.

The suggestion is to consider modifying `r->ref_storage_format` to match the URI-specified backend, ensuring internal consistency. This would affect how the repository reports its reference format while maintaining the primary functionality of allowing runtime backend selection. The comment doesn't propose specific code changes but raises an architectural consideration about state management when environment variables override configuration.
