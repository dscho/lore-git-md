This thread began with a report that `git config get --type=path` would segfault on Windows when processing values starting with `:(optional)`. Jeff King (Peff) and D. Ben Knoble quickly identified the root cause in a recent change to `git_config_pathname()` that altered how NULL returns are handled for optional paths. The discussion evolved into a design review of how optional paths should behave across Git's configuration system.

Junio Hamano clarified that the current behavior - where each `:(optional)` declaration is evaluated independently - was an intentional design choice, not just an implementation artifact. He provided concrete examples showing how this allows system-wide configurations to define fallback paths while permitting optional local overrides. The thread has now converged on keeping this interface while improving its robustness.

Current focus is on finalizing the implementation details, particularly around how `--show-scope` should behave with optional paths. Peff suggested and Junio agreed on adding test coverage to verify that Git correctly suppresses all output (both value and scope information) when an optional path doesn't exist. This moves the thread toward resolution while preserving the existing, useful behavior pattern for optional path handling.
