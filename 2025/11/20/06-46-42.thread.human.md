The thread began with a report of Git segfaulting on Windows when using `git config get --type=path` with values starting with `:(optional)`. The initial report showed that instead of properly returning an error for invalid paths, Git crashes with a segmentation fault.

Jeff King (Peff) has now analyzed the issue in depth, tracing it back to commit 749d6d166d which changed how `git_config_pathname()` behaves. The function now requires callers to initialize destination pointers and check for NULL returns, since it may succeed without setting a value for optional paths. Peff found this affects more than just the reported case - several other callers like `blame.ignorerevsfile` handling are also impacted and could trigger double-free issues.

The discussion has expanded beyond a simple bugfix to consider broader interface design questions. Peff suggests the current behavior may be unintuitive for cases with multiple optional paths and proposes a more structural solution using a `struct config_pathname` to better communicate path existence. While the immediate Windows-specific crash can be fixed, the thread is now exploring how to best handle optional paths across Git's configuration system.
