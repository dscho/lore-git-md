This is a technical clarification in the ongoing discussion about implementing a `git cp` command for tracking copied files. Lucas Seiki Oshiro reinforces the architectural point that Git tracks file movements and copies through content-based detection rather than explicit metadata, building on Kristoffer Haugsbakk's earlier demonstration of existing copy detection capabilities.

The email emphasizes that even `git mv` works this way - it's simply a convenience wrapper around `git rm` and `git add` operations, with rename detection happening after the fact based on file similarity. Oshiro notes this similarity detection is tunable via the `--find-renames` flag in various Git commands.

This contribution doesn't introduce new functionality but helps solidify the technical understanding of how Git currently handles file movements and copies. It serves as a useful reference point for anyone considering how a potential `git cp` might work within Git's snapshot-based architecture. The email maintains the thread's focus on the core technical constraints while keeping the discussion grounded in Git's existing behavior.
