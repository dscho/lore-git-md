Performance regression investigation for `git last-modified` on big-endian platforms. Jeff King responds to Anders Kaseorg's report of s390x test failures in the recently merged performance optimization series. The failures show incorrect attribution of file modifications to merge commits rather than their actual sources in tests 16 and 19 of t8020-last-modified.sh.

Key observations from Jeff:
- The failing tests consistently misattribute changes to merge commits (ac29b6e and da1857e) rather than the correct source commits
- Both affected platforms (s390x and HP NonStop) are big-endian architectures, suggesting an endianness-related issue
- No obvious integer handling problems visible in the problematic commit (2a04e8c293)
- Suggests running tests with SANITIZE=address,undefined to check for memory access issues

The response advances the investigation by:
- Confirming the merge commit misattribution pattern
- Highlighting the common big-endian factor between failing platforms
- Proposing next steps for diagnosis via sanitizer builds

This appears to be a genuine platform-specific edge case in an otherwise successful optimization series, now narrowed to endianness considerations. The discussion remains technical and productive, with clear paths forward for diagnosis.
