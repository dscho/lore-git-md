Thread identity: Discussion about making internal Git functions static, starting with Junio C Hamano's patch to static-ify `git_configset_get_pathname()` in config.c.

Core problem/goal: Identify and reduce unnecessary function exports in Git's codebase by making functions static when they're only used within their own compilation unit. The initial patch addressed one such case in the config subsystem.

Current status: Junio has merged a change making `git_configset_get_pathname()` static in config.c. Ramsay Jones has identified 102-120 additional candidates across the codebase via their static-check.pl script, including other config-related functions (`git_configset_get_bool_or_int`, `git_configset_get_string`) and functions in various subsystems (add-interactive, hash, packfile, setup, trailer).

Key technical details: The static-check.pl script identifies functions that are declared in header files but have only one caller within their implementation file. The 'seen' branch introduces new potentially-static symbols that weren't present in earlier branches.

Open questions/loose ends: Which of the 100+ identified candidates should be made static? Are there legitimate reasons any of these functions need to remain exported? Should this become a systematic cleanup effort?

Participant positions: Junio demonstrated the approach with one concrete change. Ramsay provided data showing the scope of similar opportunities but hasn't proposed specific additional changes yet.

Related work: This connects to broader code hygiene efforts like René Scharfe's work on reducing global variables and header file pollution. The static-check.pl script appears to be an ongoing tool for identifying such opportunities.
