This is a follow-up discussion in the thread about consolidating Git's tempfile creation. Jeff King responds to Junio C Hamano's questions about why Git should use its internal `git_mkstemp_mode()` rather than platform-native `mkstemp()` implementations.

Jeff agrees with the direction of using Git's internal implementation consistently across all platforms, noting that Git already mostly uses `git_mkstemp_mode()` everywhere. He suggests that if Git is going to use custom code for tempfiles, it should do so consistently rather than mixing system and internal implementations. 

While acknowledging that platform-native `mkstemp()` might offer some platform-specific behavior, Jeff argues the consistency benefits of Git's unified implementation outweigh this. He notes René Scharfe's patch effectively implements this approach by defining `mkstemp()` as a macro that calls `git_mkstemp_mode()` with 0600 permissions.

The discussion shows consensus forming around making Git's tempfile handling completely internal and platform-consistent, removing the last remaining direct `mkstemp()` call. This is presented as a natural conclusion to the earlier refactoring work that simplified tempfile creation across the codebase.
