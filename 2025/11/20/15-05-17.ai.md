Refactoring patch in the `git-history` series, focusing on the interaction infrastructure.

This patch (v6 07/11) from Patrick Steinhardt restructures the add-patch and add-interactive code to better separate their concerns. The key change moves color and configuration handling from add-interactive.c into a new `interactive_config` struct in add-patch.c, while introducing `interactive_options` to pass common parameters. The patch affects multiple commands (`add`, `commit`, `reset`, `stash`) that use these interactive modes.

Phillip Wood raises concerns in his review that the new naming might not actually clarify the boundaries between subsystems, noting that `struct interactive_options` still only contains patch-specific parameters despite its generic name. He questions whether passing this struct to `run_add_i()` is any clearer than the previous approach. The review also points out that the config initialization still happens in add-patch.c rather than being properly separated.

The changes touch 10 files with significant code motion (270 insertions, 239 deletions), primarily:
- Moving color/config code from add-interactive.c to new functions in add-patch.c
- Replacing `struct add_p_opt` with `struct interactive_options`
- Updating all callers to use the new interfaces
- Introducing `struct interactive_config` to hold shared state

This appears to be part of the larger effort to support the `git-history` command's interactive operations, though the immediate motivation for this particular refactoring isn't clearly stated beyond general code organization. The patch follows the series' pattern of incremental infrastructure improvements, with Phillip's review suggesting the separation of concerns could be taken further.
