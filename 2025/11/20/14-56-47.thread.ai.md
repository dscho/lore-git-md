Git thread summary:

Feature request for a `git cp` command to copy files while preserving history/blame information, analogous to `git mv` for moves. Author Martin Guy presents a concrete use case of splitting mp3.c into mad.c, lame.c, and twolame.c while maintaining accurate attribution of code portions. Currently requires workarounds using `git mv` plus manual copying. The proposal focuses on the user-facing need without implementation specifics or analysis of rename detection interactions. No responses or discussion yet - this is the initial suggestion in what may become a design discussion thread. Key open points: technical feasibility, implementation approach, and whether existing commands could solve the use case.
