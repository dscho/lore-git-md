This is a technical review follow-up in the ongoing `git-history` feature series, specifically discussing the add-patch infrastructure refactoring.

Phillip Wood responds to Elijah Newren's question about the implementation approach for in-memory index patching in patch 09/11 of the series. The core question is why the patch introduces a new `run_add_p_index()` function that appears to be a modified version of `run_add_p()` rather than refactoring the existing function to handle both cases.

Wood acknowledges the concern about potential future divergence between the two functions and the risk of accidentally using the wrong index reference (`s->r->index` vs `s->index`). While he doesn't offer a solution, his response indicates this is a valid architectural consideration that warrants attention.

The exchange highlights an implementation detail that could impact maintainability of the new history editing functionality, though it doesn't appear to block the overall progress of the series. This follows earlier reviews where Phillip Wood had questioned other aspects of the infrastructure refactoring, showing continued engagement with the technical design decisions.
