Documentation patch implementing warnings for `--committer-date-is-author-date` option in `git-am` and `git-rebase`, following thread consensus that the original use case was flawed.

This v2 patch from Kristoffer Haugsbakk adds strong warning language to both `git-am` and `git-rebase` documentation about the `--committer-date-is-author-date` option, noting it can create commit histories that violate Git's timestamp ordering assumptions. The warnings follow Junio C Hamano's suggested approach of cautioning users without removing the option entirely.

Key technical details for future reference:
- Documents now use `WARNING` callout boxes (changed from `NOTE` in v1)
- Warning text emphasizes the history-walking machinery's expectation of non-decreasing commit timestamps
- Added explicit user prompt to consider whether they really need the option
- Removed references to "legitimate uses" and "clock skew" from v1
- Changed "lie" to more neutral "override" terminology
- Clarified timestamp requirements as "non-decreasing" rather than "strictly increasing"

The patch maintains the option's functionality while clearly documenting its risks, particularly around the original flawed use case of trying to use `git-am` as a deterministic importer. The warnings appear in both `git-am.txt` and `git-rebase.txt` with nearly identical wording, adjusted slightly for each command's context.
