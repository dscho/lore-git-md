Platform compatibility patch fixing POSIX return value behavior in Windows pthread emulation layer.

This is the third version of a minimal patch correcting the return value of `pthread_cond_init()` in Git's Windows pthread compatibility layer. The change makes the emulation more strictly POSIX-compliant by having the function explicitly return 0 (success) after initializing the condition variable, matching the behavior already established for `pthread_cond_wait` in the same file. The patch uses the existing `return_0` wrapper pattern seen elsewhere in the file.

The only change from v2 is fixing the subject line to correctly reference `pthread_cond_init` instead of the previously incorrect `pthread_cond_wait`. This addresses the maintainer's earlier observation about subject line accuracy. The actual code change remains the same - a one-line modification to the macro definition in compat/win32/pthread.h that wraps the Windows `InitializeConditionVariable` call with `return_0()`.
