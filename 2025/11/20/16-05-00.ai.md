Bugfix discussion for `git submodule`'s `--single-branch` behavior with branch specifications.

D. Ben Knoble responds to Uwe Kleine-König's bug report about submodule initialization tracking the wrong branch. The key observation is that `--single-branch` is documented to clone only HEAD by default unless `--branch` is explicitly specified, which explains the reported behavior where the submodule tracks master instead of the configured scarthgap branch.

Knoble suggests two potential improvements: first, that users should explicitly use `--branch` when they want a specific branch, and second, that `--single-branch` might be enhanced to default to the branch specified in `.gitmodules` when available. This would make the behavior more intuitive for submodule users who expect the configured branch to be tracked.

The response clarifies that the current behavior is actually working as documented (cloning HEAD by default with `--single-branch`), though potentially surprising. This shifts the discussion from being purely a bugfix to considering whether the documented behavior should be changed to better match user expectations in the submodule context.

Technical details mentioned include:
- Current `--single-branch` behavior documented in `git-submodule` manpage
- Interaction between `--branch` option and `.gitmodules` branch configuration
- Potential divergence between user expectations and actual behavior
