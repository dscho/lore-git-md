This is a review response in the ongoing `git-history` feature series, focusing on the newly introduced `split` subcommand implementation. Elijah Newren provides technical feedback on Patrick Steinhardt's v6 patch series that aims to bring Jujutsu-like history editing capabilities to Git.

The review acknowledges the series' progress in building on Git's replay infrastructure while noting several technical concerns. Key points include questioning whether the `split` subcommand should support N-way splits rather than just binary splits, examining the implementation of `run_add_p_index()` versus `run_add_p()`, and noting a test/hook execution discrepancy. Newren also raises questions about commit message retention behavior in split operations.

The feedback continues the pattern of careful architectural review that has characterized this series' development. While the review identifies several areas needing attention, it maintains a constructive tone, recognizing the work's value in enabling flexible history manipulation. The exchange represents an important technical discussion about how to best implement these new capabilities while maintaining Git's robustness and design coherence.
