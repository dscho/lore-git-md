Documentation patch finalizing warnings for `--committer-date-is-author-date` in `git-am` and `git-rebase`. This v2 patch follows the mailing list consensus to strongly warn users about timestamp ordering violations while retaining the option's availability.

Kristoffer Haugsbakk's updated documentation adds WARNING callouts to both commands' man pages, explaining that the option can create histories violating Git's assumption of non-decreasing commit timestamps. The warnings encourage users to reconsider their need for the option while still allowing its use in specific scenarios where the base commit is older than the patches being applied.

The patch drops earlier language about "legitimate uses" after discussion revealed the original 2009 use case (treating `git-am` as an import tool to recreate identical commits) was fundamentally flawed. The new wording is more neutral ("override" instead of "lie") while maintaining technical accuracy. Changes from v1 include moving the warning to appear after the option's basic description and using "non-decreasing" rather than "strictly increasing" to better match Git's actual timestamp handling.

This represents the settled approach from maintainer Junio C Hamano - warning users without full deprecation. The warnings should help prevent misuse while allowing the rare cases where the option might still be needed. The thorough commit message documents the option's history and the reasoning behind the current warnings.
