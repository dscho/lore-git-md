This is a follow-up discussion in the thread about consolidating Git's tempfile creation by replacing `mkstemp()` with `git_mkstemp_mode()`. Jeff King responds to Junio C Hamano's questions about why Git should prefer its internal implementation over platform-native `mkstemp()`.

Jeff acknowledges that platform consistency arguments cut both ways - while system `mkstemp()` would match the platform's behavior, Git's implementation provides cross-platform consistency. He notes Git already mostly uses `git_mkstemp_mode()` everywhere, so the "platform consistency" ship has sailed. His position is that if Git is going to use custom code at all, it should do so consistently rather than mixing implementations.

The discussion centers around René Scharfe's patch that would define `mkstemp()` as a macro calling `git_mkstemp_mode(0600)` in git-compat-util.h. Jeff suggests an alternative approach of explicitly banning `mkstemp()` to force callers to use `git_mkstemp_mode()`, though he's not opposed to the macro approach. The thread shows consensus forming around complete removal of direct `mkstemp()` usage in favor of Git's unified implementation, with the main question being about the exact mechanism (macro vs. banned function).
