This is a clarification in the ongoing discussion about making internal Git functions static. Brian Carlson points out that several hash-related functions identified by Ramsay Jones as potential candidates for being made static (`git_hash_alloc`, `git_hash_free`, `git_hash_init`, `hash_algo_ptr_by_number`) must remain public because they are called from Rust code. This is an important technical constraint that wasn't apparent from just analyzing the C codebase - these functions are part of Git's FFI interface with Rust components.

The note explains that these functions might appear unused in branches where Rust support isn't compiled in, but they serve a critical cross-language boundary purpose. This highlights a key consideration for the broader static-ification effort: some apparently internal-only functions may have external consumers that static analysis tools wouldn't detect when only examining the C code. The exchange serves as a useful data point about the need to consider Git's multi-language ecosystem when evaluating function visibility changes.
