This is a review email from Elijah Newren on the "split" subcommand patch in Patrick Steinhardt's `git-history` series (v6 patch 11/11). The review focuses on several technical and design aspects of the split functionality.

Newren raises multiple substantive questions about the implementation. He questions why the command only allows creating exactly two commits from a split rather than supporting arbitrary splits, and notes ambiguity in which commit gets which message when splitting. He also points out that the implementation discards extended commit headers during the operation.

The review highlights potential issues with hunk editing during the interactive split process, asking how edited hunks would be handled and whether this could cause problems with the subsequent commit replay. Newren suggests the auxiliary functions for commit collection and application could be replaced by leveraging Git's existing replay machinery, though notes complications from potential conflicts when edited hunks are involved.

Several test-related observations are made, including that one test description appears contradictory to the actual behavior regarding hook execution. Newren also questions the necessity of some test cases, particularly those enforcing that the commit being split must be reachable from HEAD - a requirement he sees as arbitrary.

The review maintains the thread's pattern of thorough technical scrutiny while acknowledging the patch's overall direction. It focuses on edge cases and potential improvements rather than fundamental objections, continuing the collaborative refinement of this history-editing feature.
