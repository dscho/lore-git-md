This is a follow-up in the `git cp` feature request thread, where Martin Guy clarifies his use case for explicit copy tracking. While acknowledging Kristoffer Haugsbakk's demonstration of Git's dynamic copy detection via `git log --find-copies-harder`, Martin explains his primary concern is with `git blame` behavior - he wants the copy relationship recorded in the commit history itself so blame traces back to the original file without requiring manual investigation.

The email reveals the core distinction between the two approaches: dynamic detection (which works retroactively for log) versus explicit recording (which would affect forward-looking tools like blame). Martin questions whether his expectation is reasonable given Git's current capabilities, while noting the conceptual similarity to how `git mv` already tracks moves. The thread remains open on whether Git's existing rename detection sufficiently addresses the blame use case for file splits, or if an explicit `git cp` command would provide meaningful additional value.
