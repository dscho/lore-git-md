This reveals an important constraint: static analysis tools examining only the C codebase might miss cross-language dependencies, particularly with Git's growing Rust integration.

The discussion highlights both the potential for widespread code hygiene improvements and the need for careful review of each candidate, especially functions that might interface with other parts of Git's ecosystem. While many functions could likely be made static safely, the hash functions example shows some will need to remain exported to support Git's FFI boundary with Rust. The thread leaves open how systematically this cleanup should proceed and which other functions might have hidden external callers.
