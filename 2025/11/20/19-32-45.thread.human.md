Junio Hamano started a thread about reducing unnecessary function exports in Git by making internal functions static, beginning with `git_configset_get_pathname()` in config.c. The discussion expanded when Ramsay Jones identified over 100 additional candidates using static-check.pl, but Brian Carlson noted that several hash-related functions must remain public since they're called from Rust code. This revealed an important constraint for the effort: any static-ification must account for cross-language dependencies.

Kristoffer Haugsbakk recently contributed a minor correction, fixing a typo ("otherise" to "otherwise") in Junio's original commit subject line. While this doesn't affect the technical direction, it maintains documentation accuracy. The core challenge remains - how to systematically identify which of the 100+ candidates can safely be made static while preserving interfaces with Rust components. The thread awaits proposals for handling this cross-language analysis, whether through tooling improvements or documentation of FFI requirements.
