This is a bugfix addressing a segfault in `git config get --path` when handling optional paths. The patch corrects the behavior when a configuration value uses the `:(optional)` prefix but the referenced path doesn't exist.

The issue occurs because `git_config_pathname()` wasn't properly clearing the destination pointer when encountering a missing optional path, while `format_config()` assumed it would always receive a string. This led to a segfault when trying to display the configuration value. The fix ensures proper NULL handling and adds return value signaling to indicate when an optional path is missing.

The patch includes thorough test coverage demonstrating both the fixed behavior and edge cases, like handling multiple values where some paths exist and others don't. Junio notes this is just the first part of the fix - another patch will follow to address other callers of `git_config_pathname()`.

The change is well-justified (fixing both a crash and incorrect behavior) and appears carefully implemented with clear documentation updates and comprehensive tests. It's a focused fix that maintains backward compatibility while properly implementing the documented optional path behavior.
