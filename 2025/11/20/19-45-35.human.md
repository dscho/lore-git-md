Bugfix follow-up addressing optional path handling in config callers. This is the second patch in a series fixing segfaults when handling optional path values marked with `:(optional)` in Git config.

The patch updates several callers of `git_config_pathname()` to properly handle NULL returns for missing optional paths. Each modified caller now checks if the path string is non-NULL before using it, preventing segfaults. The changes span multiple subsystems including blame, receive-pack, fetch-pack, fsck, gpg-interface, and setup.

The modifications follow the pattern established in the first patch (which fixed the core config machinery), applying the same defensive programming to all remaining call sites. The changes are straightforward and mechanical - each adds a NULL check before using the path value. The gpg-interface.c change is slightly more involved as it handles program paths for signature verification.

This completes the fix for the optional path handling issue across Git's codebase. The changes appear thorough and consistent with the solution approach established in the first patch.
