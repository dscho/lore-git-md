This is a technical discussion about optimizing the topological traversal fix for `git describe`. Jeff King responds to Ben Boeckel's proposed solution, pointing out performance concerns with the current implementation and suggesting alternative approaches.

The email focuses on the performance implications of Ben's patch, which uses `repo_is_descendant_of()` for topological comparisons - an approach Jeff notes would require two full traversals per comparison, making it extremely slow without commit-graphs. Jeff suggests more efficient alternatives:

1. Using generation numbers (either pre-computed in commit-graphs or calculated once during traversal) to enable faster ancestor checks
2. Leveraging existing topological sorting infrastructure from the revision traversal machinery (`init_topo_walk()` and `sort_in_topological_order()`)

Key technical points:
- The current patch's O(n²) performance characteristics would make it impractical for large repositories
- The revision.c code already handles topological ordering more efficiently
- Two potential integration paths: either adapt `git describe` to use revision machinery or port those optimization concepts to its custom traversal

This moves the discussion forward by identifying concrete performance bottlenecks in the proposed solution and pointing to existing Git infrastructure that could help solve them.
