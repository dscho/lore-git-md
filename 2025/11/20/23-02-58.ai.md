Bugfix targeting Windows/MSVC build system configuration for Rust infrastructure.

This email from brian m. carlson responds to Ezekiel Newren's analysis of the Windows/MSVC build issue by proposing a concrete fix. The patch modifies both the Makefile and cargo-meson.sh to properly distinguish between MSVC and GNU toolchain environments on Windows, addressing the library naming convention mismatch (`.lib` vs `.a` files) that was causing CI failures.

The changes specifically:
1. Replace the generic Windows check in Makefile with an MSVC-specific condition
2. Update cargo-meson.sh to check for `*-msvc` rather than just `*-windows-*`
3. Reference a specific CI run showing the failure being addressed

This builds on the thread's earlier confirmation that the issue predates the SHA-1/SHA-256 interoperability work and stems from Patrick Steinhardt's initial Rust introduction. The patch represents a direct attempt to resolve the identified MSVC/GNU naming convention mismatch while maintaining the series' technical completeness. The fix appears straightforward and well-targeted to the diagnosed problem, though its effectiveness remains to be confirmed by CI results.
