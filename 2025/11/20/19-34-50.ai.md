This is a bugfix addressing a segfault in `git config get --path` when handling optional path values. The patch fixes two issues in the config subsystem's handling of `:(optional)` path specifications.

The core problem stems from how `git_config_pathname()` handles missing optional paths - it returns success (0) but leaves the destination pointer unchanged, while `format_config()` assumes the pointer always gets a string. This mismatch causes a segfault when `git config get --path` processes a missing optional path.

The fix makes `git_config_pathname()` explicitly clear the destination pointer for missing optional paths, and teaches `format_config()` to return a new status code (1) indicating the caller should treat this as if the config entry didn't exist. The patch includes updates to all callers of `format_config()` to handle this new return value properly.

The changes are well-contained to the config machinery, touching `builtin/config.c` and `config.c`, with a new test file `t/t1311-config-optional.sh` that exercises both the basic case and edge cases like multi-value configs with mixed existing/missing paths. The commit message notes this is just the first of two patches, with another coming to fix other callers of `git_config_pathname()`.

The patch appears technically sound with clear commit message explaining both the problem and solution, thorough test coverage, and proper attribution to the reporter and helper. The changes follow Git's established patterns for config handling while cleanly extending them to support the optional path case.
