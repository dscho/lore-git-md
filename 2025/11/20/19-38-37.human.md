This is a feature patch implementing the `GIT_REF_URI` environment variable for specifying reference backends and storage locations, part of the ongoing effort to enable non-blocking reference migrations between backends (particularly files to reftable).

Justin Tobler provides a review of Karthik Nayak's patch that adds URI-based reference store configuration. The core functionality allows specifying both backend (files/reftable) and path via `<backend>://<path>` syntax, with the implementation handling validation, error cases, and worktree integration.

The review focuses on two documentation and behavior clarifications:
1. Suggests better documenting that the path refers to the parent directory (like `.git/` rather than `.git/refs/`) to avoid confusion with `GIT_OBJECT_DIRECTORY`'s more specific pathing.
2. Questions whether `repo->ref_storage_format` should be updated when using `GIT_REF_URI`, since currently it would still show the original configured format rather than the active one.

This follows up on previous review feedback that improved terminology (distinguishing reference directories from backend-specific subdirectories) and test/documentation quality. The patch appears technically sound but may need these final tweaks before merging. The feature enables important workflow improvements for large repository migrations between reference backends.
