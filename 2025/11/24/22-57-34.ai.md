This is a follow-up in the ongoing discussion about `git clone -c` config parsing behavior changes. Jeff King (peff@peff.net) provides historical context and analysis of the whitespace-trimming behavior that was recently removed.

Key technical points:
- Traces the whitespace-trimming behavior back to its 2010 origins, noting it predates the environment variable handling code
- Explains how the config parameter handling evolved through multiple changes (2010, 2011, 2021)
- Reveals the trimming was already effectively broken since 2021's config format changes
- Notes the current change only affects `git clone -c` since other paths use different mechanisms

The email suggests the removed behavior was likely never intentional and not worth restoring, given:
- The original implementation rationale is unclear
- The behavior was already been partially broken
- It conflicts with Git's config key format rules
- Only affects an undocumented usage pattern

This moves the discussion toward accepting the behavior change as a correction rather than a regression, though the final decision remains open. The analysis provides important historical context about the config parsing evolution that wasn't previously discussed in the thread.
