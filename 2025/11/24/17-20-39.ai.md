Hook subsystem refactoring (part 6/10): Ungroup behavior control

This patch adds configurability to the hook execution's output grouping behavior in the ongoing hook subsystem modernization series. The change allows callers to override the previously hardcoded `ungroup=1` setting in `run_hooks_opt()`, which was causing issues when sideband-reading collated output from child hooks (as sideband reading and ungrouping are mutually exclusive).

Key technical changes:
- Adds an `ungroup` bitfield to `struct run_hooks_opt` to make the behavior configurable
- Preserves existing ungrouping behavior in all current callers (`run_hooks()` API, `hook run` command, and commit hooks) via explicit `opt.ungroup = 1` assignments
- Adds documentation comments noting these are current requirements that could be made configurable if needed
- Maintains backward compatibility while enabling future use cases that require grouped output

The patch is a focused addition to the larger hook refactoring effort, addressing a specific limitation in the parallel execution infrastructure. It follows the series' pattern of careful API evolution while maintaining existing behavior for unchanged callers. The implementation is straightforward and well-commented, with clear indications of where future flexibility might be needed.
