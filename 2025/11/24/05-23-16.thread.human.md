A regression in `git clone` config parsing was reported where whitespace trimming around config keys in `-c` arguments was inadvertently removed in v2.52.0. The change, introduced by commit dcecac2580ef during config parsing refactoring, causes commands like `git clone '-c KEY=VALUE'` to fail with "invalid key" errors since the whitespace is now preserved rather than trimmed. 

While the reporter notes this isn't a common case (and their project has already worked around it), they highlight it as an undocumented backward-compatibility break. The original whitespace-trimming behavior was in config.c around line 649 in v2.51.2. The regression affects both `git clone -c` and `--config=` argument parsing. 

The report includes clear reproduction cases and code references but no proposed fix. Given Git's strong backward-compatibility commitments, this seems likely to warrant maintainer attention despite being an edge case.
