This thread examines a behavior change in `git clone`'s config parsing when using `-c` or `--config` arguments with whitespace around keys. What initially appeared as a regression in v2.52.0 (where commands like `'-c KEY=VALUE'` stopped working) has evolved into a deeper discussion about whether the old behavior was ever correct.

Junio Hamano's analysis of the documentation suggests the pre-v2.52.0 behavior allowing quoted forms may have been incorrect all along, as the docs specify `-c key=value` as separate arguments. Jeff King's follow-up provides crucial historical context, tracing the whitespace-trimming behavior back to 2010 and showing it was already partially broken by 2021's config format changes. His analysis reveals the behavior was likely never intentional and conflicts with Git's config key format rules.

The discussion has shifted from reporting a regression to considering this a documentation-correcting change. While the final decision remains open, the technical analysis suggests the current behavior better aligns with Git's config parsing rules, even if it breaks some existing undocumented usage patterns. The thread highlights how subtle behavior changes can uncover long-standing documentation and implementation inconsistencies.
