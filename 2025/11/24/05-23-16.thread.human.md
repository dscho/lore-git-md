Here's the human-readable summary of the thread:

A regression in Git 2.52.0 broke `git clone -c` and `--config` arguments that had whitespace around the equals sign (like `'-c KEY = VALUE'`). This behavior had existed since 2010 but was actually a bug - Git's config syntax never officially supported whitespace in keys. The change came from removing some overly-permissive whitespace trimming code that had effectively been broken since 2021's config format changes anyway.

After thorough analysis from Jeff King and Junio Hamano, the project concluded this wasn't really a regression but rather an accidental bugfix. While some tools like Git LFS and Atlassian Bamboo used the old behavior, the maintainers decided not to restore it. The stricter parsing aligns better with Git's documented config syntax rules and encourages tools to use the correct format (`-c key=value` without extra spaces).

The discussion is now closed with consensus that the "regression" should stand as an intentional correction. Tools needing the old behavior will have to update their command generation. Junio humorously noted this was an "inadvertent bugfix" that happened to make Git behave more correctly. No further changes are planned on the Git side.
