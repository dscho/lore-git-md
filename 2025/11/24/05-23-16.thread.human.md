This thread addressed a regression in `git clone` where `-c` and `--config` arguments with whitespace around keys (like `'-c KEY=VALUE'`) stopped working in Git 2.52.0+. The behavior change stemmed from the removal of whitespace trimming that had been present since 2010, though deeper analysis by Jeff King revealed the trimming was more extensive than initially thought and had already been partially broken since 2021's config format changes.

After thorough discussion, the project reached consensus that the original whitespace-trimming behavior was effectively a bug that had gone unnoticed for years. Jeff King and Junio Hamano agreed that maintaining backward compatibility for this edge case wasn't worthwhile, especially since the behavior violated Git's documented config key format rules. While Johannes Schindelin proposed a technical solution and Junio considered a minimal fix, both approaches were ultimately abandoned in favor of treating the change as an intentional correction.

The thread concluded with Junio humorously noting he wouldn't block a fix but wouldn't invest time reviewing one either, signaling clear agreement with Jeff King's position that third-party tools (like Git LFS and Bamboo CI) should adapt to Git's stricter parsing rather than Git maintaining what was effectively broken behavior. No further changes to Git's config parsing are planned, and the discussion is considered resolved.
