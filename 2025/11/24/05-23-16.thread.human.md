This thread discusses a regression in `git clone` where whitespace-trimming behavior for `-c`/`--config` arguments was removed in Git 2.52.0, breaking some third-party tools like Git LFS that relied on the old behavior. 

Jeff King (peff) and Junio C Hamano analyzed the history and concluded the original whitespace-trimming was an undocumented quirk that violated Git's config key format rules. While the change causes some breakage, both maintainers agree it's better to enforce stricter parsing rather than maintain backward compatibility with what was effectively already broken behavior. Jeff King acknowledges the impact on tools like Git LFS but argues they should adapt to Git's rules, and Junio indicates he wouldn't block a minimal fix but won't prioritize it.

The discussion has reached consensus that no fix will be implemented, treating this as an intentional correction. The thread is winding down with both maintainers comfortable letting the regression stand, though Jeff King leaves the door slightly open for a limited fix addressing only single-argument `-c foo=bar` cases if someone wants to pursue it. Documentation updates may follow to clarify the expected syntax.
