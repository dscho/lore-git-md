This thread examines a regression in `git clone` where `-c` and `--config` arguments with whitespace around keys (e.g., `'-c KEY=VALUE'`) stopped working in v2.52.0. Jeff King (peff) and Junio C Hamano have analyzed the behavior's history and concluded the removed whitespace-trimming was likely never intentional, despite existing since 2010. The old behavior conflicted with Git's config key format rules, where keys cannot contain whitespace.

Peff clarifies nuances in the syntax: the "stuck" form (`-cfoo`) is valid and equivalent to `-c foo`, while `--config=KEY=VALUE` (with equals) works but `--config KEY=VALUE` does not. Both agree the documentation should be updated to reflect the correct syntax consistently, though this is a broader project. The consensus is moving toward treating this as a correction of long-standing incorrect behavior rather than a regression, despite the change breaking some historical usage patterns. The discussion has shifted from diagnosing the issue to determining how to document the intended behavior clearly.
