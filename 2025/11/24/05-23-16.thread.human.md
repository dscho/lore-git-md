This thread discusses a regression in `git clone` where config arguments with whitespace around keys (like `'-c KEY=VALUE'`) fail in Git v2.52.0 and later. The issue stems from commit dcecac2580ef which refactored config parsing but unintentionally dropped long-standing whitespace trimming behavior around keys.

D. Ben Knoble provided historical context, tracing this trimming behavior back to its 2010 introduction. They noted that while the key-trimming was recently removed, value-trimming was actually dropped in 2011 without discussion, suggesting a pattern of silent behavior changes in config parsing. The regression appears unintentional as it wasn't mentioned in commit messages or release notes.

The reporter has already worked around the issue in their project, but given Git's backward-compatibility goals and the behavior's decade-long history, this likely warrants maintainer attention. The thread currently lacks a proposed fix, but the historical perspective strengthens the case that this was a meaningful regression rather than an edge case.
