Hook subsystem refactoring: pre-push hook conversion to structured API.

This patch from Emily Shaffer (with sign-offs from Ævar Arnfjörð Bjarmason and Adrian Ratiu) converts the pre-push hook to use the new hook API introduced earlier in the series. The key change moves from direct `run-command` usage with manual stdin feeding to the structured `run_hooks_opt()` interface with a dedicated callback (`pre_push_hook_feed_stdin`) for ref status processing.

The implementation demonstrates the series' core pattern: separating generic hook execution (handled by `run_hooks_opt()`) from hook-specific logic (the ref filtering and formatting in `pre_push_hook_feed_stdin`). The callback handles all REF_STATUS_REJECT_* cases consistently, writing "old_oid new_oid refname" lines to the hook's stdin via the provided file descriptor. Junio Hamano notes this clean separation while questioning pipe closure timing (though the series' earlier patches establish this is handled by the framework).

Technical details include:
- Preserved hook arguments (remote name and URL)
- Reused strbuf for ref line formatting
- EPIPE handling matching original behavior
- Status filtering expanded to cover all REF_STATUS_REJECT_* cases
- Memory management via strbuf_release in the wrapper function

This conversion follows the pattern established by earlier patches in the series, completing the pre-push hook's migration to the new API. The implementation appears thorough, maintaining existing behavior while benefiting from the series' centralized hook execution infrastructure. Junio's positive review suggests this meets the project's quality bar, though his pipe closure question indicates close reading of the details.
