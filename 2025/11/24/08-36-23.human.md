This is a discussion about the deprecation strategy for `git whatchanged`, a legacy command that shows commit history with diff output. Kristoffer Haugsbakk responds to Daniel Hammer's objection about the new `--i-still-use-this` opt-in requirement, defending the more aggressive deprecation approach.

Kristoffer notes the command has been documented as deprecated since 2013, with stronger warnings in Git 2.51.0. The forced opt-in flag is meant to actively alert users who might miss documentation updates. They suggest users can create an alias (`git log --raw --no-merges`) as a direct replacement and state the current deprecation approach won't be reversed.

The exchange highlights tension between maintaining backward compatibility and cleaning up legacy commands. While Daniel sees this as a developer experience regression, Kristoffer views it as necessary communication for an eventual removal. The thread shows no immediate resolution, with Kristoffer taking a firm stance against reverting the deprecation strategy.
