Hook subsystem refactoring (part 9/10): This patch converts the receive-pack update and post-update hooks to use the new hook API introduced earlier in the series. It's part of the larger effort to standardize hook execution with proper stdin handling and output capture capabilities.

The changes replace direct `child_process` management with the new `run_hooks_opt` interface, simplifying the code while maintaining the same functionality. Key changes include:
- Replacing manual hook setup with `RUN_HOOKS_OPT_INIT` and `run_hooks_opt()`
- Adding a `hook_output_to_sideband` callback to handle sideband output when needed
- Removing boilerplate code for finding hooks and managing child processes

The patch maintains backward compatibility while preparing for future enhancements like parallel hook execution. It follows the same pattern seen in previous conversions in this series, showing consistent application of the new API. The changes are straightforward and well-contained, focusing only on receive-pack's hook handling without introducing new behavior.

This conversion completes the receive-pack portion of the hook modernization effort, leaving just the pre-push hook conversion (handled in part 10) to finish the series. The implementation looks clean and aligns with the established patterns from earlier patches.
