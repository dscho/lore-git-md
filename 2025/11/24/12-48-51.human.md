This is the second patch in a documentation standardization series, converting the `git pull` man page to use consistent AsciiDoc synopsis formatting. The changes are purely presentational, aligning with the style already applied to `git fetch` in the first patch.

The patch updates the `git-pull.adoc` file and several related documentation files to use standardized syntax for placeholders (now marked as `_<placeholder>_`), monospace formatting for commands/options, and improved bulleted lists for complex options. The rebase options section gets particular attention with clearer presentation of the different modes. The changes maintain all existing content while making it more consistent with Git's modern documentation style.

This follows the same pattern as the `git fetch` conversion in patch 1, and like that patch, appears to be a straightforward mechanical conversion with no behavioral changes. The author (Jean-Noël Avila) has been leading this documentation standardization effort for some time, and this work fits cleanly into that established pattern. With no substantive feedback on v1 of the series beyond a minor typo fix, these changes seem uncontroversial and ready for inclusion.
