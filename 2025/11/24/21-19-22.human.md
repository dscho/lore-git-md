Bugfix discussion regarding `git clone` config parsing behavior.

Junio Hamano responds to the reported regression where `git clone -c` and `--config` arguments with whitespace around keys stopped working in v2.52.0. He questions whether the original behavior (trimming whitespace) was correct in the first place, pointing to documentation that suggests the option and key-value pair should be separate arguments.

The response highlights two potential issues: 1) whether the single-argument form (`'-c KEY=VALUE'`) should be accepted at all (documentation shows them as separate arguments), and 2) whether whitespace trimming around keys was ever intended behavior (Git config syntax doesn't allow whitespace in keys). Hamano notes the documentation may be incomplete since it doesn't show the `--config=K=V` form that other options use.

This moves the discussion from "fix the regression" to questioning the underlying assumptions about what behavior is correct. The maintainer appears skeptical that the old behavior was intentional, suggesting this might not be a regression to fix but rather an undocumented behavior that was incorrectly allowed. The thread now needs input on whether to restore the old behavior (with proper documentation) or enforce stricter parsing as the help text suggests.
