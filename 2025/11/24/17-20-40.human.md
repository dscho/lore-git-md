This is part 7/10 of the hook subsystem refactoring series, focusing on output handling in `run-command.c`. The patch introduces a new `consume_output_fn` callback that allows callers to capture and redirect child process output that would normally go to stderr. This is particularly useful for server-side hooks that need to relay output to clients.

The key change adds a `consume_output` field to `struct run_process_parallel_opts` that, when set, receives output via a strbuf instead of writing to stderr. The callback is called even when there's no output, enabling keepalive mechanisms. The implementation maintains the existing behavior when no callback is provided.

The patch includes a BUG() assertion to prevent mutually exclusive combinations (ungroup mode with output capture), adds test helper functions, and includes a test case verifying the output diversion works as expected. The changes are well-contained, touching only the parallel process machinery in run-command.c while maintaining backward compatibility.

This builds on the series' foundation of making hook output more flexible while keeping the core parallel execution behavior intact. The implementation looks solid with proper strbuf handling and clear documentation of the new API contract.
