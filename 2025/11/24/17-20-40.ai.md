This is part 7/10 of the hook subsystem refactoring series, focusing on output handling in `run-command.c`. The patch introduces a new `consume_output_fn` callback that allows callers to capture and process child process output programmatically rather than having it always written to stderr.

Key technical additions:
- A new `consume_output` field in `struct run_process_parallel_opts` that takes a callback receiving output in a `strbuf`
- The callback is called even when output is empty, enabling keepalive mechanisms
- BUG() assertion enforcing mutual exclusivity between `ungroup` and output capture modes
- Test coverage including a new `run-command-divert-output` test helper that writes output to a file
- Documentation of the new callback in `run-command.h` explaining memory management expectations

The change is particularly useful for server-side hooks that need to relay output to clients, as noted in the commit message. The implementation maintains the existing parallel processing infrastructure while adding this new capability, and includes proper cleanup of the output buffers. This builds on the series' earlier work standardizing hook execution while preserving the option for sequential operation.
