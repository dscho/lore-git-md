Bugfix for regression in `git clone` config parsing. This reports an unintended behavior change where whitespace trimming around config keys in `git clone -c` arguments was removed in v2.52.0, breaking commands that relied on the previous whitespace-tolerant parsing.

The regression stems from commit dcecac2580ef which refactored config parsing code but inadvertently dropped the whitespace trimming behavior. This causes commands like `git clone '-c KEY=VALUE'` to fail with "invalid key" errors since the literal whitespace is now preserved in the key name.

While the reporter notes this isn't a common case (and their project has already worked around it), they flag it as a backward-compatibility break that may affect other users. The commit that introduced the change didn't mention this behavior alteration in its message or release notes, suggesting it was unintentional.

Key technical details for future reference:
- Affects `git clone -c` and `--config=` argument parsing
- Old behavior (pre-v2.52.0): trimmed whitespace around keys
- New behavior: preserves whitespace, causing config key validation to fail
- Original whitespace-trimming code was in config.c around line 649 in v2.51.2
- Regression introduced by dcecac2580ef ("config: refactor config file reading")
