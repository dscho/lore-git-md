This is a technical discussion about the URI syntax design for Git's reference backend selection, specifically addressing how to structure URIs for future extensibility beyond local filesystem paths.

The email focuses on clarifying the URI format proposed for specifying reference backends (like files or reftable) and their storage locations. This change would better accommodate future backends that might use non-filesystem storage (like NFS or cloud services) while maintaining clarity about what part specifies the backend versus the storage location.

- Junio's proposed syntax better separates backend identification from resource location
- Karthik agrees this is more future-proof and will update the implementation
- The discussion reveals ongoing tension between current simplicity and future extensibility
