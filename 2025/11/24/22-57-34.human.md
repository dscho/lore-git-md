This is a discussion about config parsing behavior in `git clone` with `-c` and `--config` arguments, following up on a reported regression.

Jeff King (peff) digs into the history of whitespace trimming in config parsing, tracing it back to 2010. He finds that the behavior was likely unintentional - the code originally handled environment variables in a way that no longer exists, and the current implementation only affects `git clone`. The trimming was silently dropped in 2011 for values and more recently for keys, with no discussion in commit messages.

Peff notes that the current behavior (where whitespace isn't trimmed) is more correct, as the old behavior was already broken in some cases due to other changes. He suggests this isn't worth fixing as backward compatibility, since it was never an intended feature. The discussion has shifted from treating this as a regression to recognizing it as correcting undocumented behavior.

The email provides important historical context about how config parsing evolved, showing that what appeared to be a regression may actually be fixing long-standing quirks in the implementation. This suggests the current behavior should likely stand, though the thread remains open for further discussion.
