Bugfix for `git instaweb` path handling with special characters

This patch addresses an issue where `git instaweb` fails to properly handle repository paths containing special characters like `@`. The problem occurs because Perl interpolates `@` as an array variable when the path is embedded in double-quoted strings in the generated gitweb configuration.

The proposed fix changes the quoting from double to single quotes in the generated `gitweb_config.perl` file, which prevents Perl from interpreting `@` as a variable. However, the author notes this is only a partial solution - paths containing single or double quotes would still cause problems.

The email also raises a security concern about the current approach of generating and executing Perl scripts for configuration, suggesting this could be vulnerable to injection attacks. The author proposes moving to a safer configuration format like INI, JSON or plain .conf files, though this isn't implemented in the current patch.

The patch itself is minimal (just two line changes) and appears correct for its limited scope, though the broader security concern about the configuration mechanism remains unaddressed. The issue seems genuine and the fix straightforward, but the security implications may warrant a more comprehensive solution.
