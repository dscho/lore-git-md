Regression in `git clone` config parsing with `-c`/`--config` arguments:

A regression was reported where `git clone -c` and `--config=` arguments with whitespace around keys (e.g. `'-c KEY=VALUE'`) fail in v2.52.0+ due to removal of whitespace trimming behavior from commit dcecac2580ef. The behavior dated back to 2010's commit 8bfa77867.

Jeff King (peff) provided detailed historical analysis showing:
- Whitespace-trimming originated in 2010 predating environment variable handling
- Config parameter handling evolved through multiple changes (2010, 2011, 2021)
- The trimming was already effectively broken since 2021's config format changes
- Current change only affects `git clone -c` as other paths use different mechanisms
- Valid forms are `-cfoo` (stuck form) equals `-c foo`, `--config=KEY=VALUE` valid while `--config KEY=VALUE` invalid

Junio C Hamano's analysis confirms:
- Documentation specifies `-c key=value` as separate arguments without supporting quoted forms
- Whitespace-trimming violated Git's config key format rules and was likely unintentional
- Initially thought this was a bug but now sees it as a quirk of option parsing
- Questions utility of preserving leading whitespace in config values
- Suggests ideal would have been rejecting such whitespace from the start
- Floats regression fix idea but skeptical of engineering effort required

Technical details:
- Original whitespace-trimming code was in config.c around line 649 in v2.51.2
- Value-trimming was silently dropped earlier in 2011's commit 06eb708f33 (per D. Ben Knoble)
- Change specifically affects config parsing during clone operations

Current status:
- Consensus forming that change is correct despite breaking historical usage
- Discussion shifting from regression report to recognizing pre-v2.52.0 behavior as accidental feature
- Jeff and Junio agree change aligns with Git's config specifications

Open questions:
- Whether to document `--config=K=V` form consistently
- Broader documentation issues around option syntax in manpages (noted as larger project)
- Whether to deprecate whitespace feature while fixing regression (low likelihood)
