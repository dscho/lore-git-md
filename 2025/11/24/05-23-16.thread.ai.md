Summary of regression in `git clone` config parsing:

A regression was reported where `git clone -c` and `--config=` arguments with whitespace around keys (e.g. `'-c KEY=VALUE'`) fail in v2.52.0+ due to unintended removal of whitespace trimming behavior. This stems from commit dcecac2580ef ("config: refactor config file reading") which refactored config parsing code but inadvertently dropped the whitespace trimming that previously occurred around config keys.

Technical details:
- Pre-v2.52.0 behavior: whitespace around keys in `-c` arguments was automatically trimmed, a behavior dating back to its 2010 introduction in commit 8b1fa77867
- Current behavior: whitespace is preserved, causing config key validation to fail
- D. Ben Knoble notes value-trimming was silently dropped earlier in 2011's commit 06eb708f33 without discussion, suggesting a pattern of silent behavior changes in config parsing
- Original whitespace-trimming code was located in config.c around line 649 in v2.51.2
- The regression was not mentioned in commit message or release notes, suggesting it was unintentional

The reporter provided clear reproduction cases and code references but has not proposed a fix. The historical context from Knoble reinforces that this was a long-standing behavior (since 2010) that was silently changed, similar to prior config parsing changes. Given Git's backward-compatibility goals and the behavior's longevity, this appears to warrant maintainer attention despite being an edge case (the reporter's project has already worked around it). The change affects config parsing specifically during clone operations when using the `-c` or `--config` flags.
