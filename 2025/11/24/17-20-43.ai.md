This is the final patch in the hook subsystem refactoring series, converting receive-pack's hooks to use the new structured hook API. The patch focuses on the update and post-update hooks, completing the migration of all remaining hooks to the callback-based system.

Key technical changes include:
- Replaces direct `find_hook()` calls and manual child process management with `run_hooks_opt()`
- Introduces batched stdin feeding (500 lines per callback) to maintain performance with large inputs
- Preserves sideband output handling via new `hook_output_to_sideband` callback
- Maintains push certificate and push option environment variable handling
- Uses the `feed_receive_hook_cb` callback to generate stdin content in "old_oid new_oid refname" format
- Properly handles `skip_broken` flag to filter out failed commands
- Includes memory management for the feed state buffer and callback data

The implementation shows careful attention to performance, particularly in the batched stdin feeding approach which avoids excessive polling overhead. The patch maintains all existing functionality while providing the benefits of the new hook API - better signal handling, standardized execution, and preparation for future configurable hooks.

This completes the series' goal of converting all Git hooks to use the modern API, with receive-pack being the last holdout. The changes are consistent with the patterns established in previous conversions and have been through multiple review iterations addressing memory safety and performance concerns.
