This is part 9/10 of the hook subsystem refactoring series, converting receive-pack's update and post-update hooks to use the new structured API. The patch replaces direct `child_process` handling with the `run_hooks_opt` interface, maintaining the same functionality while benefiting from the series' earlier work on output capture and sideband handling.

Key technical changes include:
- Replacement of manual `child_process` setup with `run_hooks_opt` initialization
- New `hook_output_to_sideband` callback function that handles output redirection when sideband is enabled
- Removal of direct `find_hook()` calls in favor of the centralized hook execution API
- Preservation of existing behavior for both update and post-update hooks while using the new infrastructure
- Continued use of sequential execution (processes=1) as established in earlier parts of the series

The conversion follows the pattern established in previous patches, using the `consume_output` callback for sideband output when enabled. The patch demonstrates the series' goal of standardizing hook execution while maintaining backward compatibility with existing hook behavior. This completes the receive-pack portion of the hook modernization effort, with all hook types now using the new API.
