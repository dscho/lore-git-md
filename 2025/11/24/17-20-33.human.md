This is the v3 cover letter for a 10-part series converting Git's remaining hook implementations to use the new `hook.h` API, paving the way for config-based hooks and parallel execution. The series is a collaboration between Adrian Ratiu and Emily Shaffer, with contributions from Patrick Steinhardt and Kristoffer Haugsbakk.

The v3 iteration addresses critical memory leaks identified by Junio Hamano in the receive-pack hook conversion, along with several other refinements:
- Memory ownership fixes for receive hook allocations
- Simplified receive hook stdin callback by removing redundant context
- Moved ref pointer to callback data in pre-push hook per Patrick's suggestion
- Renamed output capture API to remove hook-specific terminology
- Added all REF_STATUS_REJECT_* cases to pre-push hook filtering
- Documentation improvements for hook.h and run-command.h
- Various code cleanups (data types, conditionals, BUG messages)

The series shows mature progress, with reviewers maintaining design approval while focusing on final implementation details. The memory safety fixes represent the last major category of pre-integration scrutiny for this long-running effort. The v3 refresh includes a CI run and range-diff for reviewer convenience, addressing the key blockers from v2.

This continues the project's gradual modernization of Git's hook system, with the immediate goal of enabling future features like config-based hooks while maintaining backward compatibility. The changes touch core hook execution paths but have been carefully reviewed for safety and performance.
