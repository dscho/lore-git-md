Bugfix for `git instaweb` path handling and security concerns.

This patch addresses an issue where `git instaweb` fails to properly handle repository paths containing special characters like `@`. The problem occurs because Perl interpolates `@` as an array variable in double-quoted strings, causing incorrect path resolution in the generated gitweb configuration. The fix changes the string delimiters from double to single quotes in the generated `gitweb_config.perl` file.

The author notes this is incomplete - paths containing single or double quotes would still break the configuration. They also raise a security concern about the current approach of generating executable Perl scripts for configuration, suggesting this could be vulnerable to injection attacks and should be replaced with a safer format like INI, JSON or plain config files.

The patch itself is minimal (just changing quote styles) and appears correct for the specific `@` case it targets. However, the broader issues around quote handling and security implications remain unaddressed. The security concern in particular seems valid - generating executable Perl config files from untrusted path names could potentially allow code injection if not handled extremely carefully. This might warrant a more comprehensive redesign of how `git instaweb` handles configuration.

Key technical details:
- Modifies `git-instaweb` script's `gitweb_conf()` function
- Changes string quoting in generated `gitweb_config.perl`
- Affects `$projectroot` and `$git_temp` variable assignments
- Original issue manifests when repository path contains `@` character
- Unresolved issues with `'` and `"` in paths
- Security concern about Perl script generation approach
