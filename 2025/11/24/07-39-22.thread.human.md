Chris Torek proposed an alternative approach of storing secrets in Git-ignored files while versioning templates, which avoids the filter limitations. However, Kache noted this becomes problematic for dotfiles and other mixed-content scenarios where configuration files contain both secrets and third-party-managed settings that should remain versioned.

Junio's latest contribution reinforces the technical constraints, detailing specific cases where working tree access would fail during smudging (like initial checkouts or mid-transition states). He clarifies that the path parameter in filters should only identify output destinations, not serve as input sources.

The discussion has now clearly established that the original filter-based approach is fundamentally incompatible with Git's design, while the template-based alternative may not fully address mixed-content use cases. Key open questions remain about handling dotfiles and selectively ignoring non-secret volatile fields like timestamps. The thread currently lacks a solution that satisfies all requirements while respecting Git's technical constraints.
