Hook subsystem refactoring converting the reference-transaction hook to use the new callback-based API. This is part 5 of a 10-part series modernizing Git's hook execution infrastructure.

The patch replaces the direct `run_command()` usage in `refs.c` with the new `run_hooks_opt()` API, eliminating manual child process management and signal handling. Key changes include:

1. Introduces a new `transaction_feed_cb_data` struct to track state during stdin feeding, containing an index counter and strbuf for building ref update lines.

2. Implements `transaction_hook_feed_stdin()` callback that processes one ref update per invocation, writing the update in the format "old_oid new_oid refname\n" to the hook's stdin. The callback handles all ref update variants (null OIDs, symbolic refs, regular refs) with proper formatting.

3. Maintains the same stdin content format as before but now streams it incrementally through the callback rather than buffering all updates at once. The implementation includes EPIPE handling and skips REF_LOG_ONLY updates.

4. Preserves the existing hook behavior while removing manual process management (find_hook, child_process setup, signal handling) by using the standardized `run_hooks_opt` infrastructure.

The conversion follows the pattern established in earlier series parts, using the new stdin feeding capability (introduced in part 1) while maintaining the same external behavior. Memory management appears correct with proper initialization and cleanup of the feed context strbuf. The change is focused and mechanical, with no apparent behavior changes beyond the internal implementation approach.
