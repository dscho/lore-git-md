This is a feature patch adding reference backend selection via URI syntax, part of the ongoing effort to enable non-blocking migration between ref storage backends (particularly files<->reftable). The patch introduces a `GIT_REF_URI` environment variable that follows the format `<backend>://<path>`, allowing users to specify both the reference backend and storage location.

The discussion has shifted from implementation details to addressing fundamental design concerns raised by Junio Hamano, particularly around whether the URI approach properly generalizes to future backends and migration scenarios. In this follow-up, Karthik Nayak responds to Justin Tobler's review comments about documentation clarity and whether the repository's ref_storage_format should be updated when using GIT_REF_URI.

Karthik explains that updating the repository's ref_storage_format wouldn't work with the lazy evaluation approach, and argues that commands like `git repo info references.format` should continue reporting the repository's configured format rather than the temporary override from the environment variable. The patch appears technically sound but exists within a larger architectural discussion about the best way to handle backend selection and migration.
