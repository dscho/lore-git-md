Bugfix for regression in `git clone` config parsing. This reports an unintentional behavior change introduced in Git v2.52.0 where whitespace-trimming around config keys was removed during a refactoring, breaking commands like `git clone '-c KEY=VALUE'`. The reporter notes this isn't a common case (their project has already worked around it) but flags it as a backward-compatibility concern worth addressing.

The regression stems from commit dcecac2580 which refactored config.c without preserving the whitespace handling that previously made quoted config arguments work. The patch appears well-identified and low-risk - it's clearly a regression from documented behavior, though the impact is limited since the failing case involves an unusual (but previously valid) quoting style. The reporter provides clear reproduction steps and links to the relevant code changes.
