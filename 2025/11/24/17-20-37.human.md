This is part 4/10 of the hook subsystem refactoring series, converting the pre-push hook to use the new hook API. The patch moves the pre-push hook implementation from manual `run_command` handling to the standardized `run_hooks_opt` interface, leveraging the new stdin feeding callback mechanism from earlier parts of the series.

The changes replace the custom child process management with a cleaner callback-based approach. The new `pre_push_hook_feed_stdin` callback handles the same ref filtering logic as before (skipping certain REF_STATUS_* cases) but now feeds refs incrementally through the new stdin streaming infrastructure. The implementation properly handles all REF_STATUS_REJECT_* cases that were previously only partially covered.

This conversion follows the pattern established in earlier patches, using the `feed_pipe` callback to stream ref data to the hook process while maintaining the same safety checks for EPIPE and other errors. The patch appears well-integrated with the series' broader goals of standardizing hook execution while preserving existing behavior.

The changes are focused and mechanical, with no apparent behavior changes beyond the internal implementation details. The patch maintains all existing functionality while removing about 40 lines of custom process management code in favor of the shared hook infrastructure.
