This is part 2/10 of the hook subsystem refactoring series, introducing stdin handling capabilities to the hook execution infrastructure. The patch adds a callback mechanism for feeding stdin to hooks as an alternative to the existing file-based approach (`path_to_stdin`), which is particularly useful for handling large data streams without filesystem overhead.

The key technical changes include:
- New `feed_pipe` callback in `struct run_hooks_opt` for incremental stdin feeding
- Two associated context pointers (`feed_pipe_ctx` and `feed_pipe_cb_data`) for managing state across callback invocations
- BUG() assertions ensuring mutual exclusivity between file-based and callback-based stdin approaches
- Integration with the parallel execution infrastructure via `run-command.c`'s pipe feeding mechanism
- Comprehensive documentation of the new callback API in `hook.h`

The implementation maintains backward compatibility while enabling more efficient stdin handling for hooks that process large inputs (like receive-pack hooks). The patch builds on the parallel stdin callback foundation from part 1 of the series and includes safety checks to prevent misuse of the new API. The documentation clearly explains the purpose and usage of each new field, including memory management responsibilities.
