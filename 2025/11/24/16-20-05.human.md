This is a follow-up discussion about the `git clone` config parsing regression, providing historical context.

D. Ben Knoble confirms the regression's long-standing behavior, tracing it back to 2010 commits that originally introduced the whitespace-trimming functionality for config keys. They note that the trimming of config values was removed in 2011 without discussion, suggesting this might be part of a broader pattern in config parsing changes.

The email adds useful historical perspective but doesn't propose a solution. It does highlight that the original authors of these changes are still active (and CC'd on the thread), which could help resolve whether the behavior change was intentional. The tone suggests this is more of an archival investigation than a call to action, though it reinforces that the regression affects behavior that's been stable for over a decade.
