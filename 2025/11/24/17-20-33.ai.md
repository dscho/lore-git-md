This is a cover letter for version 3 of a major hook subsystem refactoring series (10 patches) that converts remaining Git hooks to use the new hook.h API. The series is a collaboration between Adrian Ratiu and Emily Shaffer, with contributions from other reviewers.

The v3 iteration specifically addresses critical memory leaks identified by Junio Hamano in the receive-pack hook conversion, along with other feedback from Patrick Steinhardt and Kristoffer Haugsbakk. Key changes include:

1. Memory management fixes for receive hook allocations, moving them to caller-owned contexts
2. Simplified receive hook stdin callback by removing redundant context addition
3. Renamed run-command output API to remove hook-specific "sideband" terminology
4. Added all REF_STATUS_REJECT_* statuses to pre-push hook handling
5. Improved documentation for hook.h and run-command.h interfaces
6. Various code cleanups for data types, conditionals, and commit messages

The series continues the long-running effort to modernize Git's hook infrastructure, enabling future features like config-based hooks and parallel execution. While the current implementation still runs hooks sequentially (via processes=1), the API changes lay groundwork for parallelization.

Reviewers have approved the overall design direction, with v3 focusing on implementation robustness - particularly around memory safety and error handling. The cover letter notes successful CI runs and provides GitHub links for testing. With these memory leak fixes, the series appears ready for final review pending verification of the specific fixes.
