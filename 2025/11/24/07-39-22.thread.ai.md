Thread identity: Feature proposal/question about Git's clean/smudge filters for secret restoration workflows, from author Kache Hit, with Johannes Sixt providing technical clarification and Chris Torek proposing an alternative approach.

Core problem: Implementing secret management where secrets are redacted when committing but restored when checking out, while preserving local secret changes. Original approach using clean/smudge filters hit Git's architectural limitation where smudge filters cannot access working tree files (confirmed by Johannes Sixt).

Technical details:
- Original approach: replace prefixes with `##REDACTED##` via clean filter
- Smudge filter would need working tree access (blocked by Git's pure content transformation requirement)
- Python implementation with comprehensive idempotency checks
- Chris Torek's alternative: store secrets in Git-ignored files (foo.secret) while versioning templates (foo.template)
- New approach eliminates need for clean filters (though they could serve as safety checks)

- Chris Torek proposed viable workaround that respects Git's constraints
