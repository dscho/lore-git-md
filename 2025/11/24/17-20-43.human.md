This is the final patch in a 10-part series converting Git's hook subsystem to use a new structured API for stdin handling and output capture. The patch focuses on converting receive-pack's hooks (update and post-update) to the new system.

The key changes include:
- Replacing direct `find_hook()` calls and manual child process management with the new `run_hooks_opt` API
- Implementing batched stdin feeding (500 lines per callback) to maintain performance with large inputs
- Properly handling push certificates and options through the new API's environment variable support
- Maintaining sideband output functionality via a new `hook_output_to_sideband` callback

The conversion follows the same pattern as previous patches in the series, bringing consistency to hook execution across Git while removing boilerplate code. The batched stdin approach specifically addresses a performance regression noticed during testing.

This completes the hook modernization effort that has been progressing through the v3 series, with all major Git commands now using the new API. The changes have been reviewed for memory safety and received design approval from core maintainers.
