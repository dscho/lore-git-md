This is the foundational patch in a 10-part series refactoring Git's hook subsystem to use a new callback-based parallel execution API. It introduces stdin handling capabilities to `run_processes_parallel()`, addressing a key limitation where large stdin inputs could previously cause buffer overflows or memory exhaustion.

The patch adds a `feed_pipe_fn` callback that lets callers stream data to child processes' stdin incrementally rather than buffering everything upfront. The implementation carefully handles pipe writing with proper error checking (including EPIPE when children close stdin early) and integrates with the existing parallel process management. New test cases verify the functionality by feeding multiple lines of input to child processes.

Key technical elements include:
- New `pp_buffer_stdin()` helper that manages the stdin pipe feeding loop
- SIGPIPE handling to prevent crashes when children terminate early
- Memory management via `task_cb` for tracking feed state per-process
- Integration with both grouped and ungrouped output modes
- Comprehensive test coverage including EPIPE scenarios

This change enables the subsequent hook conversions in the series (particularly receive-pack and pre-push hooks) to handle their stdin needs safely. The implementation shows careful attention to edge cases and maintains the existing API's flexibility while adding the new capability. Review history indicates this approach has consensus from key maintainers after addressing earlier memory safety concerns.
