This is part 8 of a 10-part series refactoring Git's hook subsystem to support parallel execution with proper stdin handling and output capture. The patch adds output capture capability to hooks by exposing the `consume_output_fn` callback in `run_hooks_opt`. This allows server-side hooks to process output programmatically (e.g., for sideband transmission) rather than always printing to stderr.

The change is straightforward - it simply wires up the existing `consume_output` field from the parallel processes API into the hooks infrastructure. The commit message notes this is particularly useful for server-side hooks, though the implementation is general purpose. The documentation in `hook.h` explains how to use the new capability and points to test helpers for examples.

This appears to be a well-integrated piece of the larger hook modernization effort, building on previous patches that added stdin handling. The change is small but meaningful, with clear documentation and proper attribution to both the original author (Emily Shaffer) and a co-author. As part of a mature series that's already addressed review feedback, this patch seems ready for inclusion.
