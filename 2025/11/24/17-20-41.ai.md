Hook subsystem refactoring (part 8/10) - Output capture capability

This patch introduces output capture functionality to the hook execution infrastructure by exposing the `consume_output_fn` callback through `struct run_hooks_opt`. The change allows server-side hooks to process output programmatically rather than having it always printed to stderr, which is particularly useful for sideband transmission scenarios.

The implementation consists of two small but critical changes: wiring the `consume_output` callback from `run_hooks_opt` through to `run_parallel_processes()` in hook.c, and documenting the new field in hook.h. The documentation explicitly references `test-run-command.c` as containing example usage patterns.

This patch builds on the parallel execution foundation established in earlier parts of the series, maintaining consistency with the existing callback-based architecture for stdin handling. The change is minimal but strategically important, enabling structured output processing that complements the stdin streaming capabilities added previously. As with other parts of the series, this maintains backward compatibility while extending functionality.
