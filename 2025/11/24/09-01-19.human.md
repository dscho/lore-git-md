This is a technical response in the ongoing thread about Git's clean/smudge filters for secret restoration. Johannes Sixt (Hannes) clarifies the fundamental constraints around smudge filter behavior in response to Kache Hit's proposal.

Hannes confirms the documented restriction is absolute: smudge filters cannot access working tree files, only their names via the %f token. The filter must operate purely as a content transformation pipeline (stdin to stdout), regardless of any filename information available. This reinforces Git's design philosophy that filters should be side-effect-free content processors.

The response doesn't address the original poster's underlying use case (secret restoration) or suggest alternatives, focusing instead on correcting any potential misunderstanding about the %f token's capabilities. This suggests the core limitation is non-negotiable in Git's current design.
