This is the first patch in a 10-part series refactoring Git's hook subsystem to use a new callback-based API. The patch introduces a stdin callback mechanism for `run_processes_parallel()`, allowing large amounts of data to be efficiently piped to child processes without memory exhaustion.

The change adds a `feed_pipe_fn` callback that gets called repeatedly to write data to child processes' stdin pipes. This solves a practical problem where hook implementations previously had to buffer large inputs entirely in memory. The implementation handles edge cases like EPIPE (when children close stdin early) and integrates with the existing parallel execution infrastructure.

The patch includes thorough test coverage, adding new test cases that verify stdin handling works correctly across multiple parallel processes. It also maintains backward compatibility by making the callback optional. This foundational change enables the subsequent patches in the series to modernize specific hooks like receive-pack and pre-push.

The implementation looks solid, with careful attention to resource cleanup and signal handling (notably SIGPIPE). As the first in a well-reviewed series that has already addressed memory safety concerns from Junio Hamano, this appears ready for inclusion.
