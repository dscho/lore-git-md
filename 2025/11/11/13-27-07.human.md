This is the first of two patches in a bugfix addressing a regression in `git fetch`'s tag handling during batched reference transactions. The patch extracts the reference transaction committing logic from `do_fetch()` into a new helper function `commit_ref_transaction()` in preparation for fixing the core issue in the next patch.

The new helper centralizes the transaction commit, rejection handling, and cleanup logic that was previously duplicated in `do_fetch()`. It takes parameters for the transaction (passed as a pointer-to-pointer to safely handle cleanup), atomicity flag, remote name for error reporting, and an error strbuf. The implementation follows Patrick Steinhardt's earlier review suggestions, using a simpler `goto out` control flow pattern and more intuitive error checking.

This refactoring is a clean preparatory step that makes the actual bugfix in the next patch easier to implement and review. The commit message clearly explains the motivation and how this change enables the subsequent fix. The patch appears well-tested and maintains all existing behavior while improving code organization.
