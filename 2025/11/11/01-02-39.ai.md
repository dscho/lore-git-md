Feature proposal for gitignore functionality redesign.

Ryan Johnson proposes four significant changes to Git's ignore file handling, aiming to make the system more user-friendly and collaborative. The first suggestion introduces a `.gitignore.local` file that would be automatically ignored, providing a way for users to maintain personal ignore patterns without affecting team settings. The second and most controversial proposal advocates renaming `.gitignore` to simply `gitignore`, arguing that dot-files are inappropriate for user-facing configuration on both Linux (where they're hidden) and Windows (where they signal system files).

The third proposal introduces `gitignore.yaml` as an alternative format, enabling file inclusion and better organization through YAML's native features. This would allow teams to compose ignore rules from multiple sources and maintain cleaner hierarchies. The fourth suggestion recommends initializing all new gitignore files with a link to GitHub's template repository, making best practices more discoverable for beginners.

The YAML proposal specifically addresses two pain points: easier inclusion of authoritative templates (like those from framework maintainers) and better organization to prevent duplicate rules in large projects. Johnson notes this builds on previous discussion about include functionality, proposing YAML as a more palatable alternative to modifying the existing gitignore syntax. The changes would be backward compatible, allowing gradual adoption.

Key technical aspects include the parallel support for traditional and YAML formats, the automatic handling of `.gitignore.local`, and the proposed file naming convention change. The proposal touches multiple subsystems: ignore pattern parsing, file initialization, and potentially the config system for format selection. While ambitious, the author presents this as a logical evolution to support modern collaborative workflows, though some aspects (particularly the dot-file removal) may prove controversial among traditional Unix users.
