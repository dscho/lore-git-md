Bugfix for `git fetch`'s tag handling in batched reference transactions. This is the second patch in a two-part series addressing a regression introduced by commit 0e358de64a, where non-conflicting tags would fail to commit if any conflicts existed in the same operation.

The patch fixes a case where `git fetch` would skip committing any tags when encountering conflicts, even for non-conflicting ones. The solution modifies the cleanup path in `do_fetch()` to commit non-atomic transactions when there's an error code but atomic fetching isn't enabled. This ensures other references (including non-conflicting tags) still get applied even when some updates fail.

Key changes include:
- Adding logic to commit transactions on error for non-atomic fetches
- Maintaining backward compatibility with existing behavior
- Allowing partial pruning operations to succeed (a beneficial side effect)
- Adding comprehensive tests covering various fetch scenarios

The patch includes test cases verifying:
- Basic tag fetching
- Non-conflicting tags being fetched despite other conflicts
- Backfilling of tags when fetching specific refspecs

This appears to be a well-tested solution that addresses the original regression while maintaining the expected behavior for other fetch operations. The change has gone through multiple review iterations and incorporates feedback from several Git contributors. The patch series seems ready for merging.
