This is part 4 of Ezekiel Newren's 10-part series modernizing xdiff's type system for Rust FFI compatibility, now merged by Junio Hamano. The patch changes `xrecord_t.size` from `long` to `size_t` to better represent its purpose as a memory size measurement. The change is straightforward but requires casting at several call sites where the size is passed to functions still expecting `long` parameters, particularly in functions like `xdl_blankline()` and `xdl_recmatch()`.

The patch touches core xdiff files (xdiffi.c, xemit.c, xmerge.c, xprepare.c) and the type definition in xtypes.h. While mechanical in nature, it's a meaningful step in the larger type-safety effort, ensuring size values use the standard C type for memory quantities. The changes are consistent with the series' goal of establishing clear, cross-language compatible type semantics while maintaining existing behavior through careful casting during the transition.
