This is part 5 of Ezekiel Newren's xdiff refactoring series, focusing on type safety improvements for Rust FFI compatibility. The patch updates the `xdl_hash_record()` function and related code to use explicit, fixed-width types (`uint8_t` and `uint64_t`) instead of ambiguous types like `char` and `unsigned long`.

The changes ensure consistent behavior across platforms by:
- Using `uint8_t` for byte processing (replacing `char`)
- Using `uint64_t` for hash values (replacing `unsigned long`) to prevent truncation on 32-bit systems
- Updating the `flags` parameter to `uint64_t` to preserve all bits
- Maintaining the same hash algorithm behavior while making the types explicit

This is a straightforward technical update that follows the series' pattern of type modernization without functional changes. The patch touches several xdiff files but focuses narrowly on the hash computation logic, with careful attention to preserving the existing behavior through explicit type conversions.
