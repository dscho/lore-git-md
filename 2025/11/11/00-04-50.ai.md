This is patch 11/12 in Junio Hamano's series implementing complete handling of incomplete-line whitespace errors (WS_INCOMPLETE_LINE). The patch focuses on the display and error reporting aspects in `git diff`.

The patch teaches `git diff` to highlight the "\ No newline at end of file" message as a whitespace error when the incomplete-line whitespace class is enabled. It leverages the previous refactoring to implement this cleanly in one place. The implementation:
- Colors the no-newline marker line when WS_INCOMPLETE_LINE is active
- Extends `--check` to report incomplete lines as errors
- Adds comprehensive test coverage for various incomplete line scenarios

Key technical changes:
- Modifies `emit_diff_symbol_from_struct()` to handle DIFF_SYMBOL_CONTEXT_INCOMPLETE with WS_INCOMPLETE_LINE
- Updates `emit_incomplete_line_marker()` to pass through line kind and ws_rule flags
- Enhances `checkdiff_consume()` to detect and report incomplete lines in `--check` mode
- Adds 5 new test cases in t4015 covering:
  - Incomplete lines in both pre/post images
  - Fixing incomplete lines
  - Introducing new incomplete lines
  - Various combinations with reverse diffs

The patch maintains consistency with the series' approach of making incomplete line handling strict but configurable through `core.whitespace`. The test additions are thorough, covering both display coloring and error reporting paths. This completes the diff-side implementation to match the apply-side work from patch 10/12.
