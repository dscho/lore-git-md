This is the second patch in a two-part series fixing a regression in `git fetch`'s tag handling during batched reference transactions. The patch specifically addresses the case where non-conflicting tags would fail to commit if any conflicts existed in the same operation.

The fix modifies `do_fetch()` to commit non-atomic transactions when encountering reference conflicts, ensuring non-conflicting tags are still applied even when other updates fail. The change affects several scenarios:
- `fetch_and_consume_refs()` and `backfill_tags()` now properly commit non-conflicting tags despite other failures
- `prune_refs()` now allows partial deletions to succeed (a beneficial side effect)
- Error cases before transaction creation (`truncate_fetch_head`, `open_fetch_head`) remain unchanged

The patch includes comprehensive test coverage for:
- Basic tag fetching (`fetch --tags`)
- Non-conflicting tags alongside conflicts
- Backfilling of tags when fetching specific refspecs
- Cleanup of previous test cases

The solution maintains backward compatibility while fixing the regression, with all major review feedback from the thread incorporated. The change simplifies future maintenance by centralizing transaction commit logic in the new `commit_ref_transaction()` helper introduced in patch 1/2.
