This is a technical discussion in the ongoing submodule gitdir path encoding series, specifically addressing collision detection implementation details. Adrian Ratiu responds to Junio Hamano's suggestion about separating path availability checking from existing path validation.

Adrian argues that keeping the validation logic within `submodule_name_to_gitdir()` is necessary because it's the unified API that consistently handles gitdir computation. He proposes moving all validation inside this function rather than requiring callers to validate separately. The email outlines several planned improvements for v5, including better handling of case-folding edge cases, validating config-specified gitdir paths, and potentially splitting the validation logic for legacy vs. encoded cases.

The most interesting proposal is a potential simplification: using hashing for all encoded paths (with the config storing the mapping) to avoid complex collision handling entirely. This would represent a significant shift from the current percent-encoding approach but could eliminate many edge cases. The email shows careful consideration of the tradeoffs between implementation complexity and robustness in this tricky area of submodule path handling.
