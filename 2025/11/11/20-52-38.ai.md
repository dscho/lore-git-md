This is a documentation patch in the context of Ezekiel Newren's xdiff refactoring series for Rust FFI compatibility. Junio Hamano provides feedback on the proposed documentation about type mappings between C and Rust, specifically regarding character types.

The key technical points in this response are:
- Disagrees with including Unicode/Rust `char` discussion in the documentation, arguing it's irrelevant to the core FFI type mapping concerns
- Questions the practical scenarios where C `char` wouldn't represent bytes
- Suggests simplifying the documentation to focus on the direct `char`->`uint8_t`->`u8` mapping for byte representation
- Notes that encoding conversion (like UTF-8 validation) is a separate concern from the basic type mapping
- Points out that Rust `char` may have valid uses on the Rust side, just as C `char` does on the C side

This email represents a maintainer review pushing back on documentation content that appears technically correct but potentially distracting from the core goals of the type safety effort. The feedback suggests the documentation should be more narrowly focused on practical FFI mapping concerns rather than broader language comparisons. The discussion touches on important boundaries between type safety (the series' focus) and character encoding handling (a related but separate concern).
