This is a v3 resubmission of Ezekiel Newren's 10-part xdiff refactoring series, now focused on documentation and build system integration after the core type safety changes were merged. The series modernizes xdiff's core structures (`xdfile_t` and `xrecord_t`) for Rust FFI compatibility while maintaining behavior.

Key changes in v3:
- Added comprehensive documentation (`unambiguous-types.adoc`) detailing C/Rust type mappings and FFI guidelines, now properly integrated with both Makefile and meson build systems
- Switched documentation format to Markdown to avoid asciidoc source-highlight issues
- Clarified commit messages and technical explanations around type choices
- Maintained all structural changes from previous versions: converting `char*` to `uint8_t*`, splitting the `ha` field into `line_hash`/`minimal_perfect_hash`, and using fixed-width types throughout

The documentation additions are particularly notable, providing:
- Detailed guidance on problematic type mappings (especially around `char` signedness)
- Warnings about Rust's `std::ffi::c_*` type portability concerns
- Rationale for preferring specific fixed-width types in FFI contexts
- Platform-specific considerations and versioning caveats

The implementation changes span xdiff's core files (xdiffi.c, xprepare.c, etc.) but are now purely focused on documentation polish after the substantive type safety work was completed in earlier series. The thread shows careful attention to both technical accuracy and documentation quality, with Phillip Wood's feedback being incorporated into the latest revision.

This represents the final documentation and build system pieces for the xdiff modernization effort, establishing robust conventions for future Rust FFI work in Git. The changes are well-contained to xdiff subsystem internals with no expected user-facing impact.
