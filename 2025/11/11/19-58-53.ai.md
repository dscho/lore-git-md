Documentation patch continuing the standardization of "working tree" terminology, specifically addressing cases where the phrase was split across line breaks. This is the third and final patch in Junio C Hamano's series building on an earlier effort to align documentation with glossary definitions.

The patch mechanically updates 5 documentation files (git-add, git-read-tree, git-rm, git-submodule, and gitcli) where "work tree" appeared broken across lines. Junio describes the technical approach used to find these cases: a pickaxe search with regex matching "work" at line end followed by "tree" at start of next line, accounting for possible whitespace or asterisks in between. The changes are straightforward replacements of "work tree" with "working tree" in these split instances.

Key files modified include core command manuals (add, rm, status) and submodule documentation. The patch follows two previous parts: one covering 16 documentation files and another focused on git-notes.adoc. This completes the maintainer's contribution to the terminology standardization effort, which appears uncontroversial and aligns with established glossary definitions. No code changes are involved - purely documentation hygiene.
