This is a documentation patch in the context of Ezekiel Newren's xdiff refactoring series for Rust FFI compatibility. Junio Hamano provides feedback on the newly proposed documentation about type mappings between C and Rust.

The email focuses on the enum types section of the documentation, which explains why Rust enums (especially those with data variants) should not be used in FFI contexts due to their unstable ABI. Junio notes this is particularly relevant as Git already uses similar patterns, making the warning practical and well-motivated. He also approves of the documentation's broader goal to eliminate type ambiguity across languages while noting it goes beyond just type mapping to include important developer considerations.

Key technical points highlighted:
- Rust enums with data variants require compiler-generated discriminants
- These discriminants have unstable ABI (width/location/values)
- The documentation provides concrete examples (Fruit vs HashResult enums)
- The warning is timely given existing Git code patterns

This feedback comes as the final patch in a 10-part series that has systematically modernized xdiff's type system for FFI safety. The documentation now focuses more tightly on practical type mapping concerns following earlier maintainer feedback, while still covering important edge cases like enum handling.
