This thread addresses a minor but long-standing documentation issue in Git's `.gitattributes` file. The original commit in 2008 incorrectly specified `!indent` when the intended syntax to disable indent-with-non-tab checking should have been `-indent`. However, since indent-with-non-tab was never enabled by default, this misspelling had no practical effect.

Junio Hamano, the Git maintainer, proposes simply removing the ineffective `!indent` attribute rather than correcting it to `-indent`. His reasoning is that removal would make any future default whitespace policy changes immediately visible to developers, while correcting the syntax would silently override such defaults. The change is minimal - just removing one line from `.gitattributes` while preserving the existing `trail,space` checks. The thread also notes there's a similar issue in `git-gui/.gitattributes` that may need separate attention. This appears to be a straightforward cleanup of a harmless but misleading configuration that has persisted for over 15 years.
