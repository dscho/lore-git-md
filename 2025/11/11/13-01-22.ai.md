Feature proposal for `git commit --committer` option, continuing the ongoing discussion. ZheNing Hu responds to Phillip Wood's question about use cases by describing their corporate workflow where they frequently need to switch between different committer identities within the same repository. The key pain points they identify are:

1. Currently when misconfigurations occur, `--author` only fixes the author while environment variables are needed for committer info
2. Environment variables are cumbersome to set up repeatedly
3. A `--committer` option would provide symmetry with `--author` and reduce cognitive overhead

The technical implementation (shown in the patch) mirrors the existing `--author` functionality in `builtin/commit.c`, adding parallel handling for committer identity with:
- New `force_committer` static variable
- `determine_committer_info()` function matching `determine_author_info()`
- Same input validation and pattern search behavior
- 8 new tests in t7509 covering all edge cases
- Documentation placed adjacent to `--author` in git-commit.adoc

This response strengthens the scripting/automation use case by highlighting the inconvenience of environment variables in repeated workflows. The discussion continues to balance this against maintainer preferences for existing configuration methods, while the broader AI contribution policy questions remain unresolved in parallel.
