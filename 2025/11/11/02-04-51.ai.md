This is a response in the gitignore redesign proposal thread, raising concerns about several aspects of the original proposal. Brian m. carlson challenges the need for a new .gitignore.local mechanism when existing alternatives ($XDG_CONFIG_HOME/git/ignore and .git/info/exclude) already serve similar purposes. They defend the dot-file convention for VCS-related files, citing historical precedent and tooling benefits, and push back against removing the dot prefix from gitignore files.

The response strongly objects to linking GitHub templates by default, noting Git's forge-neutral stance and pointing out that comprehensive templates often include irrelevant patterns that hurt performance and maintenance. Regarding the YAML format proposal, carlson acknowledges YAML's popularity but highlights practical parsing issues (non-UTF-8 filename support, inconsistent implementations, and problematic type coercion) that make it unsuitable as a core Git format. They suggest the current practice of incrementally building project-specific ignore patterns is superior to template inclusion.

Key technical points raised include: the existence of two established ignore mechanisms (global and per-repo), dot-file conventions across VCS tools, GitHub template bloat concerns, and fundamental format limitations of YAML/JSON/TOML for Git's needs. The response indicates these concerns would need resolution before considering any format changes, with particular emphasis on maintaining compatibility with Git's existing filename handling requirements.
