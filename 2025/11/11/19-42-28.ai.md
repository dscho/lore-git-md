This is a refactoring patch in Ezekiel Newren's xdiff modernization series, specifically splitting the dual-purpose `ha` field in `xrecord_t` into two distinct fields for clearer semantics and better Rust FFI compatibility.

The patch separates the line content hash (`line_hash`) from the minimal perfect hash used for indexing (`minimal_perfect_hash`). The `line_hash` becomes a straightforward `uint64_t` hash of the line content, while `minimal_perfect_hash` is now explicitly a `size_t` used for array indexing. This change affects multiple xdiff algorithms (patience, histogram, and standard diff) by updating their comparison and hashing logic to use the new field names.

The refactoring improves code clarity by making it obvious that line comparisons use the minimal hash (which guarantees uniqueness across files) rather than the content hash (which could collide). It also aids Rust integration by providing more precise type information at the FFI boundary. The changes are mechanical updates to use sites with no intended behavior change, maintaining compatibility with existing diff output while better documenting the actual invariants.

This patch continues the series' pattern of type safety improvements while specifically addressing a confusing aspect of xdiff's internal representation. The split fields will be particularly helpful for future Rust implementations that need to interact with these core diff structures.
