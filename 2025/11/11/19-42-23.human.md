Documentation patch establishing type mapping guidelines for C/Rust FFI.

This is the first patch in Ezekiel Newren's 10-part series that accompanies the already-merged xdiff refactoring work. It introduces a new technical document defining unambiguous type mappings between C and Rust, with particular attention to FFI (Foreign Function Interface) considerations. The document covers:

1. Basic type mappings (booleans, integers, floating-point)
2. Size types and pointer arithmetic considerations
3. The problematic nature of `char` types across languages
4. Warnings about Rust's `std::ffi::c_*` types and their platform-specific behaviors
5. Enum type limitations in FFI contexts

The patch includes detailed explanations of edge cases and platform-specific gotchas, particularly around signedness issues and Rust version differences. It serves as both a reference for developers and a foundation for future FFI work in Git. The documentation is integrated with both Makefile and meson build systems.

This appears to be a well-considered addition to the project's technical documentation, building on the recently merged xdiff refactoring work. The level of detail suggests it will be particularly valuable for anyone working on Rust integration or cross-language interfaces in Git.
