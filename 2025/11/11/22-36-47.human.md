This is a security-oriented bugfix for Git's attribute handling system. Jeff King addresses a potential stack overflow vulnerability when processing deeply nested attribute macros. The issue could be triggered by maliciously crafted `.gitattributes` files containing long chains of macro expansions (e.g., a1 expands to a2, a2 to a3, etc.), which could cause Git to crash during operations like clone or checkout.

The fix converts the recursive macro expansion implementation to an iterative one using a LIFO queue, maintaining the same depth-first evaluation order while avoiding stack overflow risk. The solution is elegant - it replaces recursion with explicit queue management while keeping the same behavior. A new test case verifies the fix works by creating a 3000-deep macro chain and confirming Git can handle it without crashing.

While the vulnerability is unlikely to be hit accidentally (requiring ~200,000 expansions to crash on Linux), it's a worthwhile hardening measure since malicious repositories could exploit it. The patch is cleanly implemented with thorough test coverage, showing the problem and verifying the solution works under constrained stack conditions. This appears to be a solid, well-justified fix for a subtle edge case in Git's attribute system.
