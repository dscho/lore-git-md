Refactoring patch in a series fixing `git fetch` tag handling regression.

This is the first of two patches addressing a regression where `git fetch` would fail to commit non-conflicting tags when other references had conflicts. The patch extracts the reference transaction committing logic from `do_fetch()` into a new helper function `commit_ref_transaction()`, preparing for the actual fix in the next patch.

The new function centralizes transaction commit and rejection handling with several improvements:
- Takes a pointer-to-pointer to transaction for safe cleanup
- Accepts atomicity parameter and remote name for context
- Uses a simpler `goto out` control flow pattern
- Properly frees the transaction in all paths
- Maintains identical behavior to the original code

The extraction follows review feedback from Patrick Steinhardt to separate concerns and simplify the control flow.
