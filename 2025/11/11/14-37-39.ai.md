This is a follow-up discussion in the completed whitespace error handling thread, specifically addressing a line counting issue in patch 04/12 that introduced WS_INCOMPLETE_LINE handling in the diff machinery. The core debate centers on whether to increment line counters when processing "\ No newline" annotations in diffs.

Phillip Wood maintains that incrementing either preimage or postimage line numbers for these annotation lines is incorrect, as they are metadata about the preceding line rather than content lines themselves. Junio acknowledges this perspective but suggests leaving the existing preimage increment unchanged due to potential undiscovered compensating logic elsewhere in the codebase.

The exchange reveals the patch's primary purpose was introducing the `last_line_kind` member to properly handle newline annotations, with the line counting changes being a secondary cleanup that may be better omitted. This reflects the series' broader theme of careful, incremental whitespace handling improvements while avoiding unnecessary churn in adjacent systems.

- The debate focuses on `lno_in_preimage,postimage` counters in `diff.c`
- "\ No newline" annotations are confirmed to be non-content markers
- Original patch attempted to make line counting "more coherent" but possibly overreached
- Core `last_line_kind` infrastructure remains uncontroversial
