This is a refactoring patch in Ezekiel Newren's xdiff modernization series, addressing type safety for memory sizes. The patch changes `xrecord_t.size` from `long` to `size_t` to properly represent memory sizes, which is a clear improvement. However, Junio Hamano notes the transition creates some messy casting situations where the new `size_t` values must be temporarily cast back to `long` to match existing function signatures. These will need follow-up fixes when those functions are updated to take `size_t` parameters.

The patch touches several xdiff files (xemit.c, xmerge.c, xprepare.c) with mechanical updates to handle the type change. While the core change is straightforward, the interim casting reveals some technical debt in the xdiff interface that will need future attention. The maintainer seems generally positive about the change but notes the transitional ugliness is a necessary step in the modernization process. This appears to be a well-justified change that's part of a larger, carefully considered refactoring effort.
