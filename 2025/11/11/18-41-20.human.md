This is a documentation/cleanup patch fixing a long-standing but harmless whitespace attribute typo in Git's `.gitattributes` file.

Junio Hamano points out that since 2008, the top-level `.gitattributes` has contained a misspelled `!indent` rule that was meant to be `-indent`. The difference is semantic - `!indent` would negate the indent check if it were ever enabled by default, while `-indent` would explicitly disable it. Since indent-with-non-tab checking has never been Git's default, this typo has had no practical effect.

The patch simply removes the redundant `!indent` rather than correcting it to `-indent`, arguing this will make any future default whitespace rule changes more visible to Git's own developers first. The change is purely cleanup - it doesn't affect current behavior but prevents potential confusion if whitespace handling defaults change.

The commit notes there's a similar issue in `git-gui/.gitattributes` that may also need fixing, though that's not addressed in this patch. The change is straightforward and low-risk, touching only the project's whitespace configuration.
