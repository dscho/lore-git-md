The seventh patch in Ezekiel Newren's xdiff refactoring series continues the type modernization effort by changing the `nrec` field in `xdfile_t` from `long` to `size_t`. This field tracks the number of records in xdiff's file representation, and the change better reflects its role as a count of elements in arrays (both `recs` and `changed` arrays).

The patch updates all comparisons and arithmetic operations involving `nrec` across xdiff's core algorithms (xdiffi.c, xemit.c, xmerge.c, xpatience.c, xprepare.c) to explicitly cast to `long` where needed, maintaining compatibility with existing interfaces that expect `long` values. The changes are mechanical but thorough, touching boundary checks, loop conditions, and size calculations throughout the diff machinery.

This change aligns with the series' broader goal of type safety and Rust FFI compatibility, as `size_t` is the more appropriate type for array sizes in both C and Rust. The patch follows the established pattern of the series by preserving behavior through explicit casting at interface boundaries while modernizing internal representations.
