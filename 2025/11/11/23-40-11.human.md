This is maintainer feedback on the completed xdiff refactoring series aimed at Rust FFI compatibility. Junio Hamano acknowledges the successful conversion of core xdiff structures (`xrecord_t` and `xdfile_t`) to use unambiguous types like `size_t` and `uint8_t`, along with the splitting of the `ha` field. While praising the sensible data structure updates, he notes the work feels incomplete because surrounding code (function parameters and local variables) still uses legacy types like `int` where they interact with the updated struct members.

Hamano observes that temporary casts were necessary during the incremental conversion, but suggests a follow-up "part 3" series should align function signatures with the new struct types for full consistency. His feedback indicates the current series meets its stated goals but leaves room for future work to complete the type modernization across the entire xdiff codebase. The tone is constructive, treating this as an expected multi-phase effort rather than a shortcoming.
