This is a technical discussion email in the submodule gitdir path encoding series, focusing on implementation details of collision detection. Adrian Ratiu responds to Junio Hamano's suggestion about separating path availability checking from existing path verification, explaining why the unified `submodule_name_to_gitdir()` approach remains necessary.

The key points are:
1. Adrian argues that validation must remain integrated with path computation in `submodule_name_to_gitdir()` since this is the central API used throughout the codebase, with validation calls always following path computation.
2. He proposes moving all validation inside this function rather than requiring callers to validate separately, similar to how encoding cases are handled.
3. The v5 plans include validating config-specified gitdir paths, addressing case-folding edge cases (Foo/foo/%46oo), and potentially adding a hashing fallback when all path attempts fail.
4. An alternative idea surfaces: using hashing universally when the encoding extension is enabled, leveraging the `submodule.%s.gitdir` config as the source of truth, which could simplify the collision handling.

The discussion reveals tension between architectural purity (separate functions for different purposes) and practical API design (keeping related operations together). Adrian leans toward the unified approach while acknowledging the need to handle additional edge cases. The hashing alternative suggests a possible simplification path that would trade some human-readability for guaranteed uniqueness.
