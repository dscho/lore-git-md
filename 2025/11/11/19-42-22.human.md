This is the third version of a 10-part refactoring series that modernizes xdiff's core data structures for Rust FFI compatibility, now merged into Git's main branch. The series updates xdiff's `xdfile_t` and `xrecord_t` types with unambiguous fixed-width types while maintaining behavior, including type safety improvements and field separation.

Key changes in v3:
- Added comprehensive documentation (`unambiguous-types.adoc`) about C/Rust FFI type mappings, now properly integrated with both Makefile and Meson builds
- Clarified type conversion rationale, particularly around `char` semantics and Rust's `std::ffi::c_*` types
- Addressed review feedback on commit messages and documentation
- Switched to markdown style to avoid asciidoc source-highlight issues

The series converts all fields in xdiff's core structures to unambiguous types:
- `char*` becomes `uint8_t*` for byte pointers
- `long` becomes `size_t` for sizes/indices and `ptrdiff_t` for offsets
- Splits the dual-purpose `ha` field into separate `line_hash` (uint64_t) and `minimal_perfect_hash` (size_t) fields
- Renames `rindex` to the more descriptive `reference_index`

The work has been reviewed by Patrick Steinhardt and Phillip Wood, with Junio Hamano merging it. Current discussion focuses on final documentation polish, with Phillip Wood's detailed feedback being incorporated. The changes establish robust type safety foundations for future Rust FFI work while maintaining xdiff's existing behavior.
