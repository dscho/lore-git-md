Thread identity: Security fix for stack overflow in Git's attribute macro expansion system (attr.c).

Core problem: The recursive implementation of attribute macro expansion could be exploited via maliciously deep macro chains to cause stack exhaustion, potentially crashing Git during operations like clone or diff. While requiring ~200k nested macros to trigger naturally, this represents a real (if low-risk) vulnerability. Jeff King (Peff) has clarified that macro definitions are restricted to top-level `.gitattributes` files, preventing chaining across directory levels - the attack surface is thus limited to deep macro expansion within a single file.

Current status: Consensus has solidified around converting the recursive to iterative implementation using LIFO queue. The iterative solution is now clearly favored, with discussion shifting to whether additional safeguards like reduced file size limits should be added. Jeff King (Peff) has indicated he won't pursue hard limits himself but welcomes others to implement them. Patrick Steinhardt now agrees the iterative solution alone is sufficient for now, though leaves open the possibility of adding limits if real-world abuse emerges.
