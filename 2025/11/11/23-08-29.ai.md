This is a refactoring patch in Ezekiel Newren's xdiff modernization series, specifically addressing type safety by converting `xrecord_t.size` from `long` to `size_t`. The change is conceptually straightforward - `size_t` is the proper type for memory sizes - but reveals several messy edge cases in the implementation.

The patch updates all xdiff subsystems (xdiffi.c, xemit.c, xmerge.c, xprepare.c) to handle the type change, primarily by adding explicit casts to `long` at interface boundaries where the receiving functions still expect `long`. Junio Hamano notes this creates a temporary state where platforms with `long` narrower than `size_t` will remain broken until those interfaces are updated, but accepts this as a necessary intermediate step to avoid making the patch too noisy.

Key technical points:
- The cleanest changes are in xprepare.c where pointer arithmetic directly uses `size_t`
- Multiple xdiff algorithms (xdl_recmatch, xdl_emit_diffrec, etc.) still expect `long` parameters, requiring casts
- The `lines_contain_alnum` and `xdl_recs_copy_0` functions reveal particularly messy interactions with existing `int` parameters
- Junio observes the casts are acceptable as temporary measures since the underlying functions will eventually be updated to use `size_t`
- The patch maintains behavior while enabling future type safety improvements

This continues the series' pattern of incremental type safety improvements while preserving compatibility, though it highlights more transitional complexity than earlier patches. The changes are mechanical and well-contained within xdiff, with clear paths for future cleanup once dependent interfaces are updated.
