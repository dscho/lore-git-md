Bugfix for `git fetch` tag handling in batched reference transactions. This is the final version (v4) of a two-patch series addressing a regression where non-conflicting tags would fail to commit if any conflicts existed in the same fetch operation.

The first patch cleanly extracts reference transaction committing logic into a new `commit_ref_transaction()` helper function following Patrick Steinhardt's suggested control flow. The second patch modifies the error handling path in `do_fetch()` to ensure non-conflicting tags get committed even when other updates fail, while maintaining safety for pruning operations.

Key improvements in v4 include simplified error code checking (now using `if (retcode)` rather than `> 0`), expanded commit message documentation of all scenarios where the transaction might be committed, and confirmation that partial pruning is now safely supported as a side benefit. The series has incorporated all review feedback and appears ready for merging, with comprehensive test coverage demonstrating the fix works for both direct tag fetches and backfilling tags from refspecs.
