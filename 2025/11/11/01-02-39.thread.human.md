This thread discusses Ryan Johnson's proposal to redesign Git's ignore functionality, including changes to file formats and naming conventions. The initial proposal suggests removing the dot prefix from `.gitignore` files, adding a new local ignore file, introducing YAML-based format support, and linking to template repositories - aiming to improve team collaboration while maintaining backward compatibility.

brian m. carlson has raised significant concerns in response, defending the existing dot-file convention as a well-established VCS practice and questioning the need for new ignore mechanisms when `$XDG_CONFIG_HOME/git/ignore` and `.git/info/exclude` already serve similar purposes. They strongly object to linking GitHub templates by default, citing Git's forge-neutral philosophy and practical concerns about template bloat. On the YAML proposal, carlson acknowledges its popularity but highlights technical limitations (non-UTF-8 filename support, parsing inconsistencies) that may make it unsuitable as a core Git format.

Key open questions now include whether the benefits of removing the dot prefix outweigh the disruption to existing tooling, whether YAML support is technically viable given Git's filename handling requirements, and how to balance template convenience with the risk of including irrelevant patterns. The discussion appears poised to attract further input from both Unix traditionalists and contributors focused on Windows compatibility and modern tooling integration.
