Documentation patch standardizing terminology in the notes merge documentation. This is part 1 of a 3-part series aligning documentation with Git's glossary definitions around working trees vs. worktrees.

The patch updates the documentation for `git notes merge` to use "worktree" (one word) when referring to the NOTES_MERGE_WORKTREE feature, rather than the outdated "work tree" (two words) phrasing. This matches the glossary distinction where "working tree" refers to checked-out files while "worktree" refers to the multi-worktree mechanism and its associated metadata.

The change is purely mechanical, replacing two instances of "work tree" with "worktree" in the git-notes.adoc file. The patch explains that NOTES_MERGE_WORKTREE is specifically the latter case - a working tree plus repository metadata - making the terminology update appropriate.

This appears to be a straightforward documentation improvement that aligns with the project's established glossary definitions. As the first part of a larger series, it sets the pattern for similar mechanical updates across other documentation files.
