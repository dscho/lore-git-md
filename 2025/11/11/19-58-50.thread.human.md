This thread documents a straightforward but important effort to standardize Git's documentation terminology around working trees. The original patch series began aligning documentation with the glossary definitions, distinguishing between "working tree" (the checked-out files) and "worktree" (the multi-worktree feature). Maintainer Junio C Hamano has now contributed three follow-up patches to complete this cleanup.

Junio's latest patch specifically addresses edge cases where "work tree" was split across line breaks in documentation. Using a regex-based approach, he identified and fixed these instances in core command manuals (add, rm, status) and submodule documentation. This builds on his previous patches that updated git-notes documentation and 16 other files. The changes are purely mechanical terminology updates with no code impact, and the effort appears uncontroversial as it simply enforces existing glossary definitions. With this third patch, Junio has completed his contribution to this documentation standardization effort.
