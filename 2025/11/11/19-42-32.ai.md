Type safety refactoring completing the xdiff modernization series.

This final patch in Ezekiel Newren's xdiff refactoring series renames the `rindex` field in `xdfile_t` to `reference_index` for clarity. The change is purely a naming improvement - the field's type was already updated to `size_t` in the previous patch (9/10) to properly reflect its role in array indexing. The patch updates all references to the field across xdiff's core files (xdiffi.c, xprepare.c) and the type definition in xtypes.h.

The rename makes the field's purpose more explicit - it maintains a mapping between compacted array indices and the original file lines they reference during diff operations. This completes the series' systematic modernization of xdiff's type system while preserving all existing behavior. The changes maintain backward compatibility while improving code clarity and type safety, particularly for future Rust FFI integration.

With this patch, the series' goals are fully realized: all array-related fields in xdiff structures now use appropriate size types (`size_t` for counts/indices, `ptrdiff_t` for offsets), hash fields are properly separated, and pointer types are explicit. The work provides a solid foundation for future cross-language interoperability while keeping the existing C implementation stable and well-documented.
