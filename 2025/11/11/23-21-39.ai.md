This is a technical discussion in the xdiff refactoring series, specifically addressing the memory impact of splitting the `ha` field in `xrecord_t` into two separate fields (`line_hash` and `minimal_perfect_hash`). Junio Hamano raises a question about the memory overhead of this change, noting that while the per-record memory increase is about 33% (from one `ulong` to two 8-byte fields), it may not be significant in practice. The patch removes some type casting in `xdl_classify_record()` by using the new `line_hash` field directly with `XDL_HASHLONG`, which Junio acknowledges as a clean improvement. The change is part of the broader effort to modernize xdiff's type system for Rust FFI compatibility, with the split fields providing clearer semantics (`line_hash` for content hashing and `minimal_perfect_hash` for array indexing). The discussion occurs after maintainer feedback has been incorporated into the series, with Junio's comment focusing on practical considerations rather than blocking the change.
