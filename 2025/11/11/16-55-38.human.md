This is a technical review note on patch 3/4 of the trailer processing refactoring series. Phillip Wood points out that the `amend_strbuf_with_trailers()` function in trailer.c can never fail (it always returns 0) and thus should be changed to return `void` rather than `int`. This observation came while reviewing the subsequent patch 4/4, with Phillip noting he'll provide a fuller review of that patch soon.

The patch in question is part of the effort to move trailer processing in-process rather than forking `interpret-trailers`. The specific function being discussed handles the core work of modifying a strbuf with new trailer content. Phillip's observation is a straightforward cleanup opportunity - since the function has no error paths, its return value is meaningless and the interface should reflect that. This is a minor but sensible improvement to the already-reviewed patch 3/4, which has undergone significant refinement through previous rounds of review. The change would make the code's behavior more obvious to future readers.
