This is part 2 of a 3-patch documentation series standardizing terminology around working trees vs. worktrees, with Junio C Hamano now contributing as author. The patch mechanically updates 15 documentation files to replace historical "work tree" (two words) with "working tree" when referring to checked-out files, aligning with the glossary definitions.

Key technical changes include:
- Updates command manuals (git-add, git-rm, git-status, etc.) to use "working tree" consistently
- Modifies technical references (diff-format, gitattributes) to match
- Affects core documentation about index/worktree interactions
- Changes user manual examples to use current terminology
- No code changes - purely documentation updates

The changes are straightforward mechanical replacements where the context clearly refers to the checked-out files rather than the multi-worktree mechanism. This continues the terminology standardization effort started in the first patch of the series, with Junio now contributing focused updates to additional documentation files.
