This is a security fix addressing a potential stack overflow in Git's attribute macro expansion system. The patch converts recursive attribute macro resolution into an iterative approach using a LIFO queue, preventing stack exhaustion from maliciously crafted deep macro chains. While unlikely to occur naturally (requiring ~200k nested macros to trigger), this could be exploited to crash Git during operations like clone or diff.

The implementation introduces a new `attr_state_queue` struct to manage pending expansions, maintaining the same depth-first order as the original recursive version. The test case demonstrates the fix by creating a chain of 3000 macros (enough to overflow a limited stack) and verifying correct attribute resolution.

Key technical details:
- Affects `attr.c`'s macro expansion in `fill_one()` and removes `macroexpand_one()`
- Uses ALLOC_GROW for dynamic queue sizing
- Preserves all existing behavior while eliminating recursion
- Test uses ULIMIT_STACK_SIZE to force stack-constrained environment

This appears to be a well-considered fix for a low-risk but real vulnerability, with clear explanation and thorough testing. The change is surgical and maintains the existing attribute resolution semantics while removing the crash vector.
