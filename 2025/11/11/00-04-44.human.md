This is a refactoring patch in Junio C Hamano's series introducing incomplete-line whitespace handling. It prepares the codebase for unified handling of missing newlines by extracting the "\ No newline at end of file" marker emission into a dedicated helper function.

The patch creates `emit_incomplete_line_marker()` to handle these special markers, replacing direct calls to `emit_diff_symbol()`. While the behavior remains unchanged, this refactoring makes the code paths clearer in preparation for later patches that will properly implement the new WS_INCOMPLETE_LINE whitespace class.

The change is straightforward - it moves the marker emission logic into a named function while maintaining the same color handling and validation (including the BUG() check for unexpected line types). This is part of the broader effort to make Git's whitespace handling more consistent and configurable through core.whitespace and .gitattributes.

As with the rest of the series, this is a well-considered change with clear motivation and fits naturally into the larger context of improving Git's whitespace infrastructure. The patch is small and focused, touching only the necessary parts of diff.c while maintaining all existing behavior.
