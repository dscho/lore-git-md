This is part 3/10 of Johannes Schindelin's series improving Windows symlink handling in Git's test suite, specifically addressing test compatibility as MSYS2 prepares to enable symlink support by default.

The patch fixes a Windows-specific behavior where `_wopen()` would incorrectly create files through dangling symlinks when given `O_CREAT|O_EXCL` flags, unlike Linux which returns `EEXIST` in this case. The change modifies `mingw.c` to explicitly check for and reject this case, making Windows behavior match Git's expectations. This is needed to make test t4115.8 (which verifies `--reject` removes .rej symlinks) pass correctly on Windows with symlink support enabled.

The implementation adds a check using `GetFileAttributesExW()` to detect symlinks before attempting creation, returning `EEXIST` when the target is a symlink pointing to a non-existent file. The change is narrowly scoped to maintain existing behavior on non-Windows platforms while fixing the specific test case failure. This continues the series' pattern of making Windows behave more like Linux for symlink operations where Git's test suite expects POSIX-like behavior.
