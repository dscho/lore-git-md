Thread identity: Bugfix for `git last-modified` command's handling of `--` separator in sparse checkouts and paths outside worktree.

Core problem: The command fails to work with sparse checkouts or paths outside current worktree despite documentation suggesting `--` separator should enable this. The issue git-for-windows/git#5978 revealed an implementation-documentation mismatch.

Current status: Patch v1 from Johannes Schindelin adds `PARSE_OPT_KEEP_DASHDASH` to parse options in `builtin/last-modified.c`. Test case in `t/t8020-last-modified.sh` verifies sparse checkout scenario. Toon Claes has demonstrated the patched behavior matches other Git commands' handling of pathspecs after `--`.

Key technical details:
- Changes in `builtin/last-modified.c` (3 lines adding parse flag)
- Tests path 'a' when only 'b' is checked out
- Uses sparse-checkout testing infrastructure
- Confirmed behavior:
  * Paths outside sparse checkout only work with `--` separator
  * Non-matching pathspecs after `--` produce empty output (exit code 0)
  * Consistent with other Git commands' pathspec handling

Open questions resolved:
- Behavior specification clarified: `--` required for paths outside sparse checkout
- Current path validation is sufficient and matches Git conventions
