Johannes Schindelin (Dscho) continues his series improving Git's test suite compatibility with Windows symbolic links, particularly in preparation for MSYS2's planned default enablement of symlink support. The initial patches addressed Perl test failures, `git apply` executable bit handling, and Windows-specific `_wopen()` behavior with dangling symlinks.

The latest patch (the fourth in the series) fixes a test case in t0001-init.sh that fails when `git diff --no-index` (used by `test_cmp` on Windows) doesn't resolve symlinks as expected. The test compares the contents of `newdir/.git` (a symlink) against an expected file, but on Windows the comparison shows the symlink target rather than resolving it. The solution is to skip the symlink comparison when `GIT_TEST_CMP` uses `--no-index` while keeping the check on other platforms.

This continues the pattern of the series - making targeted adjustments to account for Windows-specific symlink behavior without changing core functionality. The changes are focused on test expectations rather than modifying Git's behavior, maintaining compatibility while allowing the test suite to pass when MSYS2 enables symlink support by default. So far the series has seen no other participants beyond Dscho as the initial submitter.
