This thread covers Johannes Schindelen's (Dscho) 10-part series preparing Git's test suite for Windows symlink support, particularly for MSYS2's planned default enablement of symlinks. The series has been through several iterations, with v4 currently under review by maintainer Junio Hamano pending final verification.

The latest patch (7/10) focuses on t1006-cat-file.sh, adjusting two test cases to account for MSYS2's path normalization behavior when creating native Windows symlinks. It handles platform-specific differences in how symlink paths are reported - expecting different output lengths on MINGW/SYMLINKS platforms and skipping certain assertions entirely on MINGW due to path normalization quirks. This follows the pattern established in earlier patches of making tests robust against Windows-specific symlink handling.

The series as a whole includes numerous test suite adjustments and core fixes for Windows symlink behavior across multiple test files (t0001, t0301, t0600, t1006, t1305, t6423, t7800) and core components (apply.c, mingw.c). Notable fixes include executable bit handling for symlinks, O_CREAT|O_EXCL behavior with symlinks, and path conversion handling via `cygpath`. The v4 iteration specifically restored proper credit to Patrick Steinhardt in patch 6/10 after an attribution error in v3.

With Junio performing final verification of patches 7-10, this series appears ready for integration once any last issues are addressed. The changes will help ensure Git's test suite remains reliable when MSYS2 enables symlink support by default, while also resolving some long-standing Windows-specific test issues dating back to 2009.
