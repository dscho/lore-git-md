This thread covers a 10-part patch series from Johannes Schindelin (Dscho) preparing Git's test suite for Windows environments where symbolic links are properly supported, particularly in anticipation of MSYS2's planned default enablement of symlink support. The series addresses long-standing test failures that would surface when symlink support becomes the default on Windows platforms.

The patches systematically fix test cases across multiple test scripts (t0001, t0301, t0600, t1006, t1305, t6423, t7800, t9700) that currently fail due to Windows path handling quirks and MSYS2's symlink normalization behavior. Key fixes include adjusting `git apply`'s executable bit handling for symlinks, correcting Windows-specific `_wopen()` behavior with dangling symlinks, and modifying various tests to account for platform differences in path representation and symlink handling. The final patch in the series, just submitted, fixes t7800-difftool.sh by changing how it verifies directory listings to work reliably across platforms by matching on trailing colons rather than Unix-style leading slashes.

All changes maintain the same test expectations while making the verification methods platform-neutral. The series represents an important step in improving Windows testing fidelity as part of Git for Windows' ongoing compatibility work, building on symlink support that has been available since 2015 but wasn't fully exercised in the test suite. This is Dscho's initial submission of the series, and as the maintainer of Git for Windows, he is the sole participant so far in this technical preparation for MSYS2's upcoming changes.
