Johannes Schindelen (Dscho) has prepared a 10-part series to get Git's test suite ready for Windows symlink support, particularly for MSYS2's planned default enablement of symlinks. The series has gone through several iterations, with v3 adding final refinements including three important bugfixes: executable bit handling for symlinks in apply.c, proper O_CREAT|O_EXCL behavior in mingw.c, and a symlink comparison fix in t0001-init.sh co-authored by maintainer Junio Hamano. The series is already queued for integration.

The latest patch addresses a Windows compatibility issue in the credential-cache tests, fixing how directory permissions are set in t0301-credential-cache.sh. Instead of using `mkdir -m<mode>` which doesn't work on Windows, it splits the operation into separate `mkdir -p` and `chmod` steps - following the same pattern as previous Windows compatibility work. This ensures the test will work correctly when Windows gains full symlink support.

The changes affect various test scripts (t0001, t0301, t0600 and others) and core files (apply.c, mingw.c), with careful attention to maintaining POSIX compliance while accommodating Windows behavior. The series has received thorough review from key contributors including Junio Hamano, Patrick Steinhardt and Eric Sunshine, and represents the final step in enabling proper symlink support for Windows users.
