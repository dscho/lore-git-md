This thread reports a bug in `git diff --max-depth`'s path handling. Han Jiang discovered that the command fails to produce output when given paths ending with a slash (like './1/2/') or just '.', though it works correctly with other path forms. The issue appears in Git for Windows 2.52.0 but likely affects all platforms, as it involves core path normalization logic. 

The bug manifests when the specified depth exceeds the actual path depth - for example, using depth 7 on a path with 6 components. Basic `git diff` without `--max-depth` works fine. So far this is just a bug report; no fix has been proposed yet. The thread includes detailed reproduction steps showing the exact commands that demonstrate the incorrect versus expected behavior.
