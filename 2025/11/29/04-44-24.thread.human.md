This thread documents a correction to the git-replay manual page to align it with the command's actual behavior. The original documentation incorrectly suggested git-replay could accept multiple revision ranges, when in fact it follows Git's standard single-range convention established in commit f302c1e4aa09. The patch removes misleading syntax and clarifies that --advance mode requires a single tip commit for unambiguous branch positioning.

Junio Hamano has reviewed the changes and confirmed their technical accuracy, noting he will apply the patch despite some remaining line length issues that could be improved separately. The correction updates both the manual page and the command's usage message in the code, removing an incorrect reference to "Commit Limiting options" that don't exist for this command.

While this is purely a documentation fix, the thread notes potential future work around revision walking enhancements in git-replay, as well as possible interactions with Phillip Wood's pending changes to empty commit handling. However, these remain separate concerns that don't affect the current documentation update. The patch provides clear historical context about when the incorrect documentation was introduced (between versions 3-4 and 6-7 of the original series) and references relevant past discussions.
