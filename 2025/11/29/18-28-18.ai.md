Bugfix targeting Windows symlink support in the test suite (part 2/10 of series). This patch fixes an unintended regression in `git apply`'s executable bit handling that was introduced by commit 0482c32c334b in December 2023. The original change correctly stopped `git apply` from warning about executable files when `core.filemode` is disabled, but it accidentally applied this logic to symbolic links and directories as well.

The fix narrows the special-case code path to only affect regular files, which allows test t4115.5 (symlink escape when creating new files) to pass on Windows when MSYS2's symbolic link support is enabled. The change is minimal - just a one-line modification to `apply.c` that adds a `!S_ISREG(st->st_mode)` condition to preserve the old behavior for non-regular files.

This is part of Johannes Schindelin's ongoing effort to improve Git's Windows test suite compatibility in preparation for MSYS2 enabling symlink support by default. The patch maintains the existing behavior on non-Windows platforms while fixing the Windows-specific test failure. The change is well-motivated by the test suite context and appears to be a straightforward correction of an unintended side effect from a previous change.
