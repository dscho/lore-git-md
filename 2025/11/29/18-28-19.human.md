Windows compatibility patch addressing symlink behavior in test t4115.8. This is the third patch in Johannes Schindelin's 10-part series preparing Git's test suite for MSYS2's upcoming default symlink support on Windows.

The change modifies `mingw.c` to make Windows handle `open(symlink, O_CREAT | O_EXCL)` calls consistently with Linux behavior. Currently, Windows would follow a symlink to a non-existent file and create it, while Git expects the call to fail with EEXIST when the symlink itself exists. The patch adds explicit checking for this case, returning EEXIST when attempting to create a file through an existing symlink.

This fixes test t4115.8 ("--reject removes .rej symlink if it exists") which would otherwise fail when MSYS2 enables symlink support. The implementation checks for the REPARSE_POINT attribute (Windows' equivalent of a symlink) before proceeding with the open operation. The change is narrowly scoped to maintain existing behavior on non-Windows platforms while fixing this specific test case.

The patch continues the series' pattern of carefully aligning Windows behavior with Linux expectations for symlink handling, with clear motivation tied to specific test failures. Like the previous patches, it demonstrates thorough understanding of both Git's expectations and Windows' peculiarities around symlinks.
