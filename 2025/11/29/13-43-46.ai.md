This is a bugfix patch for the `last-modified` command's behavior. The patch addresses an issue where the command fails to work with sparse checkouts or when targeting directories outside the current worktree, despite the documentation suggesting this should be possible via the `--` separator syntax.

The core change is adding `PARSE_OPT_KEEP_DASHDASH` to the parse options flags in `builtin/last-modified.c`, which ensures the `--` separator is properly handled. A new test case in `t/t8020-last-modified.sh` verifies the fix works in sparse checkout scenarios by checking that `last-modified` can still report on paths not present in the sparse worktree (specifically testing path 'a' when only 'b' is checked out).

The patch is small (3 lines changed) and focused, with a clear explanation linking to the GitHub issue (#5978 in git-for-windows/git). The test addition is thorough, using Git's sparse-checkout testing infrastructure to validate the fix. This appears to be a straightforward correction of an edge case where the command's implementation didn't fully match its documented behavior.
