This is the second patch in Johannes Schindelin's 10-part series improving Windows symlink support in Git's test suite, specifically a bugfix for `git apply` behavior with symbolic links.

The patch fixes an unintended regression from commit 0482c32c334b where changes meant to handle executable file warnings in `git apply` accidentally affected symbolic links and directories too. The fix narrows the special-case code path to only apply to regular files, which allows test t4115.5 (testing symlink escapes) to pass on Windows when MSYS2's symlink support is enabled.

The change is minimal (a one-line conditional modification in apply.c) but important for correct behavior. It demonstrates the careful attention needed when dealing with Windows path handling quirks, particularly around symlinks. This is part of the broader effort to prepare Git's test suite for MSYS2's planned default enablement of symlink support.
