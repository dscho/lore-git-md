This is a technical discussion email in the ongoing `git replay --revert` feature series, focusing on revision range parsing semantics. Junio Hamano responds to Elijah Newren's points about commit range handling, clarifying that the current implementation (and Git's standard revision walking) inherently deals with connected commit sets. He notes that while complex expressions like `master..topic1 topic2` or `^master topic1 topic2` are useful for selecting commits across branches, they still operate within Git's connected commit model.

The email emphasizes that supporting truly disconnected commit sets would require new syntax or flags beyond what `prepare_revision_walk()` currently provides. Junio suggests that if such functionality is needed, it should be clearly documented as an extension to the current range specification rather than implying it works with the existing syntax. This maintains consistency with how `git log` handles revision ranges while leaving room for future enhancements.

Key technical details mentioned include:
- Current range expressions always produce connected commit sets
- Negative refs (`^master`) and multiple branch specifications work within connected model
- `--no-walk` exists for individual commits but doesn't scale for many commits
- Documentation would need updating if disconnected set support is added

The discussion shows careful consideration of backward compatibility while acknowledging potential future needs, continuing the thread's pattern of balancing immediate feature implementation with Git's long-term architectural consistency.
