This is a cover letter for a 10-patch series focused on platform compatibility, specifically preparing Git's test suite for better symbolic link support on Windows. The series comes from Johannes Schindelin and targets the ongoing effort to improve Windows compatibility in Git's test infrastructure.

The cover letter explains that while Git for Windows has supported symlinks since 2015, the test suite hasn't properly exercised this due to limitations in MSYS2's POSIX emulation layer. With Windows 10+ now widely deployed and MSYS2 planning to enable symlink support by default, this series preemptively fixes test cases that would break when that happens. The changes accommodate Windows path handling quirks and MSYS2's symlink normalization behavior, where paths like "a/b/.." get simplified to "a". Some fixes address long-standing Perl test issues that went unnoticed because CI skips them for runtime reasons.

The series touches several test scripts (t0001, t0301, t0600, etc.) and a few core files (apply.c, mingw.c), with most changes being Windows-specific test accommodations. Notable technical points include special-casing `open(symlink)` in mingw.c, handling `/dev/null` symlinks differently on Windows, and working around MSYS2 path conversion in difftool tests. The changes appear focused and well-motivated, addressing real compatibility gaps rather than theoretical edge cases.

This is part of the broader effort to improve Windows testing fidelity, building on Git for Windows' existing symlink support. The cover letter provides useful historical context about Windows symlink permissions and MSYS2's planned changes, helping reviewers understand why these fixes are needed now. The series seems ready for review, with each patch targeting a clear test suite incompatibility.
