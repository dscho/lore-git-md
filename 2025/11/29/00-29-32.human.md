This is a bug report investigating a segmentation fault during `git fetch` operations involving submodules. Justin Su has narrowed down the crash to two specific configuration options: `fetch.writeCommitGraph=true` and `submodule.recurse=true`. The issue occurs on ARM64 (aarch64) Ubuntu 24.04 with Git 2.43.0, and persists even with a new clone of the repository on a fresh EC2 instance.

The thread has been investigating whether this is a platform-specific issue (ARM64 vs amd64), repository corruption, or a race condition during commit-graph lock cleanup. Previous discussion revealed discrepancies in `git fsck` results between the diagnostic snapshot and live repository, but Justin now confirms the crash reproduces with a clean clone, suggesting this may be a genuine bug rather than repository corruption.

The fact that the crash occurs with these two specific options enabled points to potential interaction issues between commit-graph writing and submodule recursion during fetch operations. This appears to be a serious issue affecting users on ARM64 systems, though it remains unclear why it hasn't been observed on other platforms. The clean reproduction case strengthens the case for this being a real bug worth investigating further.
