This thread addresses a bug in `git last-modified` where it wasn't properly handling the `--` separator in sparse checkouts, particularly for paths outside the current worktree. Johannes Schindelin (Dscho) submitted the initial fix (v1 patch) that enables the command to work with `--` in sparse checkouts, adding a test case to verify this scenario.

Derrick Stolee raised important questions about the expected behavior boundaries - specifically whether the command should work without `--` for paths at HEAD but outside the sparse checkout, and whether the current validation properly enforces sparse checkout rules. 

Toon Claes has now weighed in with a practical demonstration showing that the patched version correctly produces empty output (exit code 0) for non-matching pathspecs after `--`, which matches how other Git commands handle this case. Claes argues this behavior is correct and consistent, and recommends accepting the patch as-is rather than complicating it further. His analysis appears to address Stolee's concerns by showing the current implementation aligns with Git's established patterns for path handling.

The discussion has shifted from being purely about fixing an implementation-documentation mismatch to clarifying the expected behavior around sparse checkout edge cases. With Claes' confirmation that the patch maintains consistency with other Git commands, the thread seems to be moving toward resolution. The remaining open question about paths without `--` appears settled in favor of requiring the separator for paths outside the sparse checkout.
