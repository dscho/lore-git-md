This is part 5 of a 10-part series improving Windows compatibility in Git's test suite, specifically around symbolic link handling. The patch fixes a test in t0301-credential-cache.sh that was using `mkdir -m<mode>`, which doesn't work properly on Windows due to its different permission model.

The test was previously been skipped on Windows because it required the SYMLINK prerequisite, but with upcoming Windows symlink support, it would start failing. The fix splits the directory creation and permission setting into two steps (`mkdir -p` followed by `chmod`), which works correctly across platforms.

This continues the series' theme of preparing tests for Windows symlink support by addressing platform-specific behaviors. The change is straightforward and maintains the test's original intent while making it portable. The commit message clearly explains the rationale and connects it to prior similar fixes.
