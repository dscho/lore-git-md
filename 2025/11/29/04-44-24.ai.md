Documentation patch fixing inaccuracies in the git-replay manual regarding revision range syntax and behavior.

This patch corrects several issues in the git-replay documentation. The main changes clarify that git-replay takes a single revision range (not multiple ranges as previously suggested in some places), bringing it in line with most other Git commands as established by f302c1e4aa09. The documentation now properly states that in --advance mode, the range should have a single tip to unambiguously determine where the branch should point.

The patch also removes a misleading reference to non-existent "Commit Limiting options" and updates the command synopsis to match the single-range requirement. The changes appear to be catching up with existing behavior rather than introducing new functionality, though the commit message notes this may conflict with another pending patch from Phillip Wood about empty commit handling.

The commit message provides useful historical context, tracing when the incorrect documentation was introduced (between v3->v4 and v6->v7 of the original series) and referencing relevant mailing list discussions. It also notes Junio's past suggestions about potential future enhancements to revision walking in git-replay, though these remain unimplemented.

The changes are straightforward and focused on documentation accuracy, touching both the manual page and the builtin/replay.c usage message. The patch appears well-justified and properly researched, with clear references to prior discussions and commits.
