This is a review response about a proposed "lisp" userdiff driver patch. Johannes Sixt (Hannes) provides detailed technical feedback on the patch's approach to handling Common Lisp syntax differently from the existing Scheme driver.

The review focuses on whether the new driver is truly necessary versus extending the Scheme driver. Key points raised:
1. The commit message needs more concrete justification for why the Scheme driver is insufficient for Common Lisp
2. The subject line should follow Git convention ("userdiff:" prefix) and avoid technical jargon
3. The proposed regex patterns differ from Scheme's in ways that may or may not be justified (indentation rules, backslash handling)
4. There's a question whether the changes could be incorporated into the Scheme driver instead of creating a new one

Hannes suggests the author investigate whether the proposed patterns would cause false positives in existing Scheme code before deciding between a new driver versus modifying the existing one. The review is thorough but leaves the final determination to the author after addressing these technical questions.
