Gitk bug report and resolution regarding reference listing failure with stale tracking references. Thread originated by [reporter] describing a regression between git 2.42.0 and 2.51.0 on Windows, now confirmed fixed in v2.52.0 by maintainer Johannes Sixt. Core issue: gitk's `refill_reflist` Tcl procedure crashed when processing tracking references for locally-configured branches whose upstream branches no longer exist, resulting in empty ref list display. Specific reproduction case involved branch "testing" merged/deleted upstream but remaining in local .git/config with tracking configuration. Error manifested as missing array element access in `headids` during reference processing. BhaaL confirms they had delayed reporting this issue but verified it persisted in v2.51.2 before submission. Johannes Sixt's confirmation indicates the fix addresses the `headids` array handling for non-existent upstream branches, preventing the crash and empty display functionality. The resolution path is to upgrade to Git v2.52.0 or later, though the specific commit implementing the fix isn't detailed in this thread. Problem was specific to gitk's reference handling logic when dealing with orphaned tracking refs, with no workarounds needed post-fix. Maintainer confirmation and reporter follow-up confirm this is a closed issue with the fix working as intended. No outstanding technical questions or action items remain.
