Kiril Ivanov's series to add a quiet mode for Git's bash prompt upstream indicators has sparked a discussion about shell compatibility. The original patches modernized the test infrastructure and implemented a new quiet mode that suppresses the '=' indicator when a branch is in sync while preserving divergence indicators ('>', '<', '<>'). 

Junio C Hamano initially noted that while the bash-specific feature was appropriate, the test script's `#!/bin/sh` shebang was misleading since it contained bash-isms. Ivanov has since discovered that the prompt code actually supports multiple shells (zsh, dash, BSD sh) through historical modifications, raising new questions about the test implementation. The tests currently run under plain `sh` despite using bash features, and Ivanov found rewriting them for full portability while maintaining the test matrix structure unexpectedly challenging.

The core functionality remains sound, but the thread now has an open question about how to handle the shell compatibility issue - whether to keep the bash-isms, invest in portable test rewrites, or reconsider the feature's scope. The series remains at version 1 while this design consideration is discussed. Junio's original observation about the shebang mismatch stands, but the situation is more nuanced given the prompt's actual multi-shell support.
