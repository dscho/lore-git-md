This is a bugfix patch in Jeff King's ASan series, addressing memory safety in timestamp parsing during fsck operations. The patch avoids using `parse_timestamp()` on non-NUL-terminated buffers, which could trigger ASan warnings even though the current code is technically safe (it relies on a trailing newline that's checked earlier).

Jeff responds to Patrick Steinhardt's suggestion about using a generalized integer parsing helper, explaining why the existing `git_parse_int()` isn't suitable here. He details several mismatches: the need for different functions based on integer type/signedness, the fundamental difference between strict validation vs progressive parsing, and the fact that `git_parse_int()` still relies on the problematic `strtoimax()`. While acknowledging the theoretical value of a more robust parsing utility, Jeff argues it would require significant new work with tricky design decisions.

The exchange shows this patch is part of a larger effort to make Git's codebase more robust under ASan's strict checks, but also surfaces deeper questions about how to best handle integer parsing across the codebase. The immediate solution (copying digits to a NUL-terminated buffer) is pragmatic but highlights architectural questions that may need addressing in future work.
