Bugfix patch enforcing hash algorithm consistency for submodules, part of brian m. carlson's v2 series addressing mixed SHA1/SHA256 repository issues. This first patch in the two-part series implements validation in `object-file.c`'s `index_path()` function to prevent adding submodules with a different hash algorithm than their parent repository.

The patch adds explicit check in `index_path()` that compares the submodule's hash algorithm with the parent repository's after resolving the submodule's HEAD. If they differ, it returns an error message "cannot add a submodule of a different hash algorithm". This enforces the design principle that repositories should not mix hash algorithms, which was previously only implicitly assumed.

Test coverage is comprehensive, with new cases in both `t/t3700-add.sh` and `t/t7400-submodule-basic.sh` that verify the error occurs when attempting to add SHA1 submodules to SHA256 repositories and vice versa. The tests also confirm no submodule entry is actually added to the index in these cases. The implementation handles the edge case where a submodule has no commit checked out by maintaining the existing error path.

This builds on previous discussion where Junio C Hamano confirmed mixed-hash repositories constitute corruption and Jeff King provided a cleanup patch removing duplicate submodule resolution. The patch series appears well-considered, with clear commit messages explaining both the solution and why fsck cannot detect these cases (due to potential false positives from legitimate zero-padded OIDs). The tests follow Git's established patterns and cover both direct `git add` and `git submodule add` scenarios.
