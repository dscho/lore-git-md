This is a cleanup patch in the ongoing series about preventing mixed SHA1/SHA256 submodule checkouts. It removes a redundant submodule HEAD resolution check from `add_to_cache()` since the same check is already performed more thoroughly in `index_path()`. 

The patch comes from Jeff King (with brian m. carlson carrying it forward in v2) and has already been approved by Junio C Hamano. It eliminates duplicate work when adding submodules to the index while maintaining the same error checking - the validation just happens in one place now (`index_path()`) rather than two. 

The change makes the code more maintainable by centralizing the submodule validation logic and ensures all code paths get consistent error handling. The test update shows we still get the same user-visible error message when trying to add an empty submodule, though now with an additional line about the failed indexing (which more accurately reflects the actual control flow).

This is a straightforward improvement that builds on the earlier hash-algorithm validation work in the series. The patch is small, well-explained, and comes with test coverage showing it maintains the expected behavior. It's a clear win for code cleanliness with no apparent downsides.
