This is the final approval for a bugfix patch series that prevents creation of mixed SHA1/SHA256 repositories when adding submodules. The patch from brian m. carlson has now received approval from both Junio C Hamano and Jeff King, marking the technical solution as complete and ready for merging.

The core issue stems from Git's design decision to not support repositories mixing different hash algorithms. The patch adds validation in `index_path()` to explicitly check hash algorithm compatibility when adding submodules, returning a clear error message ("cannot add a submodule of a different hash algorithm") if there's a mismatch. The implementation handles edge cases like submodules with no checked-out commit and ensures no invalid entries get added to the index.

Junio notes the improved test coverage in this version, which now includes verification in both `t/t3700-add.sh` and `t/t7400-submodule-basic.sh`. The tests confirm the error occurs for both `git add` and `git submodule add` operations. The solution avoids potential fsck positives from zero-padded OIDs, showing careful attention to edge cases.

While the technical implementation is now settled, some related questions remain open about documentation updates and handling of SHA256 repositories with SHA1 remotes. The thread also includes discussion of mirror-based workarounds for deployment scenarios, though these are separate from the core validation being added here.

This represents the culmination of discussion that began with a bug report about submodule checkout failures, with the final solution providing robust protection against creating invalid mixed-hash repository states. The patch appears well-tested and carefully implemented, with thorough review from multiple core contributors.
