Bugfix patch enforcing consistent hash algorithms in submodules. This is the first of two patches in brian m. carlson's v2 series addressing the issue of mixed SHA1/SHA256 submodules, following feedback from Jeff King and Junio Hamano.

The patch modifies `index_path()` in `object-file.c` to explicitly reject adding submodules that use a different hash algorithm than their parent repository. This enforces Git's design principle that repositories should use a single hash algorithm throughout, including all submodules. The change prevents creation of invalid mixed-hash states that would cause problems during clone and checkout operations.

The implementation includes comprehensive tests in both `t/t3700-add.sh` and `t/t7400-submodule-basic.sh` covering both `git add` and `git submodule add` scenarios. The tests verify the error message and ensure no submodule entry is actually added to the index. The patch handles both SHA1-in-SHA256 and SHA256-in-SHA1 cases.

This is a clean, focused implementation that addresses the core issue while avoiding false positives in `git fsck`. The commit message clearly explains why fsck detection isn't feasible (due to potential zero-padded OIDs being valid). The patch appears ready for inclusion, having incorporated feedback from previous reviews.
