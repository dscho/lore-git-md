This is a technical clarification about SHA1/SHA256 repository interoperability in the context of submodules, following up on Marc Branchaud's mirror-based workaround suggestion from the resolved submodule checkout thread.

brian m. carlson confirms that repositories supporting both hash algorithms can interoperate with SHA1 remotes via simple `git fetch`, but notes two current limitations: the local repo must be a full clone (no shallow/partial clones) and cannot itself contain submodules. They clarify this functionality comes from their ongoing hash interoperability work, which remains incomplete and not production-ready, failing many tests that rely on unsupported clone types.

The response situates Marc's mirror proposal within the broader hash transition effort, while making clear the technical boundaries of what currently works. The limitations mentioned (no shallow clones, no nested submodules) help frame expectations for anyone considering this approach, and the note about test failures indicates these constraints are actively being worked on but not yet solved.

This follow-up doesn't change the thread's resolution status but provides important implementation context for the mirror workaround, particularly its relationship to the unfinished interoperability features.
