This is a test patch focusing on UTF-8 width calculations, specifically addressing CJK (Chinese, Japanese, Korean) character display alignment issues in Git's output. It's the first of two patches in Jiang Xin's v2 series, following maintainer feedback on the initial submission.

The patch adds comprehensive unit tests for `utf8_strwidth()` and `utf8_strnwidth()` functions in a new test file `t/unit-tests/u-utf8-width.c`. The tests verify proper width calculation for CJK characters (which should occupy 2 display columns each), including mixed ASCII/CJK strings and strings containing ANSI color sequences. Key test cases include:
- Basic ASCII strings (1 column per char)
- Chinese/Japanese/Korean strings (2 columns per char)
- Mixed ASCII and CJK strings
- Strings with ANSI color sequences (testing the skip_ansi parameter)
- Edge cases like empty strings and length-limited substrings

The patch also updates both Makefile and meson.build to include the new test suite in the build process. This follows the project's standard approach for unit tests, matching the structure of other unit test suites in the codebase.

The tests cover both the basic `utf8_strwidth()` and length-limited `utf8_strnwidth()` variants, with special attention to CJK characters and ANSI sequence handling - two areas known to cause display alignment problems.
