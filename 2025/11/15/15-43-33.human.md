Feature proposal for `git commit --committer` option, now in its fourth iteration. This patch adds a `--committer` flag to mirror the existing `--author` functionality, allowing users to override the committer identity without setting environment variables. The implementation shares infrastructure with the author handling through refactored identity determination functions.

The patch has evolved through several rounds of review, with v4 addressing specific technical concerns:
- Replaced boolean `is_author` parameter with enum `want_ident`
- Isolated author message parsing into new `set_author_from_message()` helper
- Updated documentation wording from "override" to "set"
- Added comprehensive tests covering various committer override scenarios

While the implementation appears technically sound, maintainers remain skeptical about the feature's fundamental value, arguing that committer updates already happen automatically during amend operations and that the asymmetry between author/committer fields is intentional. The patch's trajectory suggests it may face rejection unless the author can better justify why this functionality belongs in Git core.
