Thread identity: Feature patch adding a new "lisp" userdiff driver for Common Lisp and other Lisp dialects, complementing the existing "scheme" driver.

Core problem or goal: The existing "scheme" userdiff driver doesn't properly handle Common Lisp syntax. Scott L. Burson's initial proposal justified distinct patterns with three key dialect differences: 1) Common Lisp's 'defun'/'deftype' forms vs Scheme's 'define', 2) Lisp macros using "def" prefix rather than "define", and 3) Lisp indentation conventions. Junio C Hamano now suggests these differences may not preclude a unified solution covering Scheme, Emacs Lisp, and Common Lisp.

Key technical details: The proposed patterns in userdiff.c handle:
- Function/macro definitions (lines starting with "(" or indented "(def")
- Common Lisp symbol syntax (vertical bar delimiters and escape sequences)
- Word boundaries (whitespace or brackets/braces/parentheses)
Junio argues the "(def" pattern would be generally safe across dialects since syntactically valid code is unlikely to misuse "def" prefixes. The vertical bar pattern remains a Common Lisp-specific case.
