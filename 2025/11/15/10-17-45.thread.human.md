This thread discusses adding a new "lisp" userdiff driver to better handle Common Lisp syntax, complementing the existing "scheme" driver. The initial patch from the author proposes distinct patterns for Lisp function definitions, symbol syntax, and word boundaries, arguing the current scheme driver doesn't properly support Common Lisp.

Johannes Sixt has provided the first substantive review, questioning whether a separate driver is truly necessary. He points out that many patterns are similar to the scheme driver's and suggests the differences might not justify a new driver. His technical analysis examines the regex patterns in detail, noting where the lisp version is stricter (indentation rules) or looser ("(def" matching) than scheme's. He also identifies style issues in the patch submission and requests clearer justification for why modifying the existing scheme driver wouldn't suffice.

The key open question is whether these pattern differences would cause problems for actual scheme code if merged into a single driver. The thread now awaits either a revised justification from the original author explaining why separate drivers are needed, or a new version that attempts to unify the patterns in the existing scheme driver. Johannes has left the possibility open for either approach, provided the technical merits are clearly demonstrated.
