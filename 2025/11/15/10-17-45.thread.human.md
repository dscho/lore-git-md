This thread discusses adding improved Lisp dialect support to Git's userdiff functionality. The initial proposal was for a new "lisp" driver specifically for Common Lisp, complementing the existing "scheme" driver, with technical justification showing key syntax differences between the dialects. Johannes Sixt raised concerns about potential false positives in the proposed regex patterns.

Junio C Hamano has now weighed in, arguing that a unified solution covering Scheme, Common Lisp and Emacs Lisp may be possible, since syntactically valid code is unlikely to trigger false positives Johannes was concerned about. Junio's perspective adds significant weight to considering a unified approach, though the technical specifics of the patterns remain unchanged.

The discussion now awaits input from Atharva Raykar, maintainer of the scheme driver, on whether the proposed patterns would cause issues for Scheme code. The core question remains whether to create a separate driver (as originally proposed) or extend the existing scheme driver to handle all Lisp dialects - with Junio's comments suggesting the latter may be preferable if technically feasible. Documentation updates will be needed once the architectural decision is finalized.
