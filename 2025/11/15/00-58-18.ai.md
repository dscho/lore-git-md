This is the second patch in brian m. carlson's v2 series addressing submodule hash algorithm validation, building on Jeff King's earlier work. The patch removes redundant submodule HEAD resolution from `add_to_cache()` in `read-cache.c`, consolidating this check in `index_path()` where the actual OID resolution occurs.

The change eliminates duplicate work when adding submodules and ensures consistent error handling across all code paths that might index a submodule. The patch moves the error message about uncommitted submodules to `index_path()` while maintaining the same user-facing text. This matches the pattern used for other indexing errors and properly propagates the error up the call stack.

Key technical changes include:
- Removal of `repo_resolve_gitlink_ref()` call from `add_to_cache()`
- Addition of error propagation in `index_path()` for uncommitted submodules
- Updated test in `t/t3700-add.sh` to expect the new error propagation format
- Preservation of the hash algorithm validation added in the first patch of the series

The patch follows Jeff King's original suggestion and has already received approval from Junio C Hamano. It represents the final piece of the technical solution to prevent mixed-hash repositories while maintaining clear error messages. The implementation avoids false positives from zero-padded OIDs and handles edge cases where submodules have no commits checked out.
