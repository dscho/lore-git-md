This is a bugfix response for gitk's handling of stale tracking references. Johannes Sixt confirms that the issue reported by BhaaL - where gitk crashes when trying to display references that track deleted upstream branches - has been fixed in Git v2.52.0. The original report showed gitk failing with an array access error when processing a local branch that still had tracking configuration for a since-deleted upstream branch.

The fix appears to be already released, suggesting this was a regression that was caught and corrected during the 2.52.0 development cycle. No technical details about the fix are provided in this response, but the confirmation from a known gitk maintainer indicates this was a legitimate issue that has been addressed. Users experiencing this problem can upgrade to 2.52.0 or later to resolve it.
