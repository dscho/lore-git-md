This is a technical clarification about SHA1/SHA256 repository interoperability in the context of submodules, following up on the now-resolved bug about mixed-hash repository validation.

brian m. carlson confirms that Marc Branchaud's mirror-based workaround for SHA1 submodules in SHA256 repositories is feasible, with some caveats. A repository can be configured to support both hash algorithms, allowing simple `git fetch` operations between them. However, this requires full (non-shallow) clones and currently excludes repositories with their own submodules.

The response notes this functionality is part of ongoing interoperability work that isn't yet production-ready, as it still fails many tests related to shallow and partial clones. This provides important context for users considering mirror-based solutions while the broader hash transition work continues. The exchange maintains the thread's consensus that mixed-hash states remain invalid by design, while offering practical guidance for deployment scenarios.
