Feature proposal for committer identity control in `git commit`, now at v4. This patch continues ZheNing Hu's effort to add a `--committer` flag to `git commit` that mirrors the existing `--author` functionality, despite ongoing maintainer skepticism about the feature's necessity.

The implementation has evolved through several key changes in response to feedback:
1. The boolean `is_author` parameter has been replaced with an enum `want_ident` for clearer type safety
2. Author-specific message parsing has been isolated into a new `set_author_from_message()` helper function
3. Documentation wording was adjusted from "override" to "set/use" while maintaining consistency with existing flags
4. The shared `determine_identity()` function now takes explicit environment variable names as parameters

Technical components include:
- New `--committer` flag with identical format/behavior to `--author`
- Refactored identity determination logic in `builtin/commit.c`
- Comprehensive test coverage in `t/t7509-commit-authorship.sh` for:
  - Explicit committer specification
  - Pattern-based committer lookup
  - Interaction with `--amend`
  - Environment variable precedence
  - Date handling

The philosophical divide remains between ZheNing's argument for interface symmetry and Junio Hamano's position that committer updates should happen automatically during amend operations. While the implementation quality has improved through the review process, the core disagreement about whether this functionality belongs in Git persists. The patch appears well-crafted but faces an uphill battle for acceptance given the maintainer stance.
