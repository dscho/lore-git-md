Bug report and investigation into fsmonitor daemon processes failing to terminate properly on macOS, originally thought to be specific to macOS 26 (Tahoe) but now shown to affect earlier versions including Sequoia 15.7.2. The core issue is that `git fsmonitor--daemon run --detach --ipc-threads=8` processes spawn in detached mode but never receive termination signals when parent applications quit, leading to resource exhaustion and locked repositories due to lingering index.lock files.

Original reporter (a GitX maintainer) provided detailed reproduction showing this affects all Git clients (Xcode, VS Code, GitX, terminal with Starship) and builds (system Git, Homebrew, Xcode CLI tools) on macOS 26. Koji Nakamaru's follow-up expanded the scope by reporting the same behavior on macOS Sequoia 15.7.2 and earlier versions, contradicting the initial version-specific hypothesis. 

Current understanding is this may be a long-standing macOS behavior rather than a Tahoe regression, though potentially more severe in newer versions. Two workarounds exist: 1) disabling fsmonitor globally (original suggestion) or 2) selectively enabling fsmonitor only for large repositories (Nakamaru's approach). The fundamental problem remains unaddressed - these processes must be manually killed via `git fsmonitor--daemon stop` or `pkill` and continue accumulating.

Key technical details: affects arm64 macOS across multiple Git versions and configurations, reported to Apple as FB20956467. No proposed fixes yet for the underlying daemon lifecycle management issue. Thread now contains conflicting version-specific reports needing resolution.
