Thread identity: Bug report and comprehensive solution for `git diff` exit status behavior with `--quiet` and rename/copy detection flags, originally triggered by `--cached --no-ext-diff --find-copies-harder --quiet` combination.

Core problem: The interaction between quiet mode (`--quiet`/`--exit-code`) and rename/copy detection (`-M`/`-C`/`--find-copies-harder`) caused inconsistent exit codes, particularly when external diff was disabled. The original symptom showed `--quiet` incorrectly returning 0 with staged changes when copy detection was active, while `--exit-code` worked correctly.

Current status: Final solution implemented via René Scharfe's v2 patch that fundamentally changes quiet mode behavior to skip rename detection entirely, now merged by Junio Hamano. Performance benchmarks from D. Ben Knoble confirm a 3.6x speedup (72ms to 20ms) for the problematic flag combination. The bug's origin traces to 2011's b4194828dc commit where the assumption that users wouldn't combine complex diffcore operations with `--quiet` proved incorrect.

Key technical details: The fix modifies `diff_setup_done()` in `diff.c` to disable all rename detection when in quiet mode, as detecting renames serves no purpose when no output will be shown. Two new test cases in `t/t4007-rename-3.sh` verify correct behavior. Performance measurements show significant improvement from skipping unnecessary rename detection work. The diff queue processing mechanics were clarified: `run_diff_index()` initially queues all entries, then `diffcore_std()` with `diffcore_rename()` filters non-changes, meaning early termination before rename processing would produce incorrect results. Jeff King notes this incidentally fixes exit code issues with certain flag combinations.
