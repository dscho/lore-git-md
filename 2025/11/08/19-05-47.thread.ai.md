Thread identity: Bug report about incorrect exit status from `git diff --cached --no-ext-diff --find-copies-harder --quiet` when there are staged changes.

Core problem: The combination of `--cached`, `--no-ext-diff`, `--find-copies-harder`, and `--quiet` flags causes `git diff` to incorrectly exit with status 0 when changes exist, while the equivalent `--exit-code` variant behaves correctly. This affects scripts relying on the exit code, particularly git-prompt.sh when configured with diff.renames=copies-harder.

Current status: Unresolved bug in unpatched Git, though discovered through a distro patch that sets copies-harder by default. Technical analysis has progressed with new insights about contributing factors.

Key technical details: The issue stems from diffcore internals where file queue processing differs between --quiet and --exit-code modes. With --quiet, processing stops prematurely after the first file when find-copies-harder is active due to the "quick" flag interaction with rename detection. The bug manifests in how `has_changes` gets incorrectly reset to 0 in the --quiet path due to an empty diff queue after rename processing. D. Ben Knoble's new analysis suggests the interaction between `diff_setup_done` and `diff_from_contents` when external diffs are disabled (`--no-ext-diff`) may be another contributing factor, though the exact mechanism with all three flags remains unclear. The `diff_from_contents` path appears to play a role in the divergence between modes.

Open questions: Why the queue processing diverges between modes, and how the external diff configuration path interacts with the other flags. Need to determine whether the fix should focus on queue handling, has_changes tracking, or both. The reproduction case clearly demonstrates the problem with staged changes.

Participant positions: The original reporter provided detailed technical analysis showing the behavioral difference between --quiet and --exit-code paths. D. Ben Knoble has added new observations about potential interactions with the external diff configuration path, though hasn't yet traced the full interaction with all three flags.

Related work: The report mentions this affects git-prompt.sh when copies-harder is enabled, suggesting it may impact other scripts relying on diff exit codes. The distro patch enabling copies-harder by default brought this latent issue to light. The bug appears long-standing in unpatched Git but only surfaces with this specific combination of flags and configuration.
