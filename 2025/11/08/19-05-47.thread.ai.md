Thread identity: Bug report and comprehensive solution for `git diff` exit status behavior with `--quiet` and rename/copy detection flags, originally triggered by `--cached --no-ext-diff --find-copies-harder --quiet` combination, now extended with performance optimizations.

Core problem: The interaction between quiet mode (`--quiet`/`--exit-code`) and rename/copy detection (`-M`/-C`/`--find-copies-harder`) caused inconsistent exit codes and performance issues. The original symptom showed `--quiet` incorrectly returning 0 with staged changes when copy detection was active, while `--exit-code` worked correctly. A secondary inefficiencies were revealed in handling unchanged files during copy detection and memory usage patterns.

Current status: Final behavioral solution implemented via René Scharfe's v2 patch that fundamentally changes quiet mode behavior to skip rename detection entirely, now merged by Junio Hamano. Performance optimizations complete with two improvements: (1) D. Ben Knoble confirmed 3.6x speedup (72ms to 20ms) for original flag combination, and (2) new `diff_same()` optimization showing 1.33x speedup (31.8ms to 23.9ms) for `git diff --cached --find-copies-harder` through more efficient unchanged filepair handling and memory reuse.

Key technical details: The main fix modifies `diff_setup_done()` in `diff.c` to disable all rename detection when in quiet mode. The new optimization introduces `diff_same()` function to handle unchanged filepairs more efficiently when `--find-copies-harder` is active, avoiding unnecessary work and incorrect `has_changes` flag setting. Implementation splits logic in `show_modified()` to use `diff_change()` only for actual changes and `diff_same()` for unchanged files during copy detection, with clever reuse of filespec through reference counting to halve memory usage. Two new test cases in `t/t4007-rename-3.sh` verify correct behavior of the original fix.
