This thread addressed a subtle bug in `git diff` where the `--quiet` flag incorrectly returned exit code 0 when used with rename/copy detection flags (`-M`/`-C`/`--find-copies-harder`) on staged changes. The issue was rooted in an assumption from 2011 about flag combinations that no longer held true.

René Scharfe led the solution with two key patches. The main fix disabled rename detection entirely in quiet mode since its results wouldn't be used, resolving the exit code inconsistency while also providing a 3.6x speedup (72ms to 20ms) as measured by D. Ben Knoble. The follow-up patch optimized how unchanged files are handled during copy detection by introducing a new `diff_same()` function, avoiding unnecessary processing and memory usage for unchanged filepairs. This delivered an additional 1.33x speedup (31.8ms to 23.9ms) for `git diff --cached --find-copies-harder`.

The solution received thorough review from multiple experts. Phillip Wood provided architectural guidance, Jeff King offered historical context, and Junio Hamano merged both patches after confirming their technical soundness. The discussion also served as an educational deep dive into Git's diff machinery internals, particularly around how the diff queue processes filepairs. Both fixes are now merged with consensus that they correctly address the original bug while improving performance in real-world scenarios like large codebases.
