This thread began with a bug report about `git diff` incorrectly returning exit status 0 when using `--cached --no-ext-diff --find-copies-harder --quiet` with staged changes, despite the presence of changes. The initial fix, contributed by René Scharfe, addressed the symptom by disabling a quick-exit optimization when copy detection was active. However, Phillip Wood and others pointed out this was treating a symptom rather than the root cause - quiet mode shouldn't be running expensive rename/copy detection at all when it won't show the results.

The discussion has now reached consensus on a more architectural solution, implemented in this latest patch. The new approach disables rename detection entirely in quiet mode, ensuring consistent exit codes while avoiding unnecessary computation. The patch modifies `diff.c` to clear rename detection flags during setup when `--quiet` is active, and adds test cases specifically covering the originally reported flag combination. This cleanly addresses both the immediate bug and the broader design question about quiet mode's behavior.

All active contributors - including the original reporter, René Scharfe, and Phillip Wood - appear to agree this is the right direction. The solution is minimal, maintains existing correct behavior for simple cases, and properly handles the edge case that started the thread. With this patch, the thread appears to have reached a satisfactory conclusion, providing both a specific fix and an improved architectural approach to quiet mode's interaction with expensive diff operations.
