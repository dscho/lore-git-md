This thread addressed a subtle bug in `git diff` where the `--quiet` flag (which suppresses output and makes Git return an exit code indicating whether changes exist) behaved inconsistently when used with rename/copy detection flags like `--find-copies-harder`. The issue was particularly noticeable with staged changes when external diff was disabled, where `--quiet` would incorrectly return 0 (no changes) despite actual differences being present.

René Scharfe provided the definitive solution in v2, which fundamentally changes how quiet mode interacts with rename detection. The fix makes Git skip rename detection entirely in quiet mode since detecting renames serves no purpose when no output will be shown. This not only fixes the exit code behavior but also provides a significant performance improvement - benchmarks show a 3.6x speedup for the problematic flag combination. The solution has been validated through new test cases and performance measurements from D. Ben Knoble.

The discussion has now moved to clarifying some underlying mechanics, with René explaining why the diff queue can't terminate earlier in quiet mode when changes are found. This is because rename detection fundamentally changes what counts as a "change" for exit code purposes - the initial state of the queue isn't reliable until after rename detection has run. This technical follow-up confirms the v2 solution's correctness while providing deeper insight into Git's diff machinery.
