This is a refactoring patch that is part of a series fixing a `git fetch` tag handling regression. It extracts the reference transaction committing logic from `do_fetch()` into a new helper function `commit_ref_transaction()` in preparation for the bugfix in the next patch.

The new helper function centralizes the transaction commit and rejection handling logic that was previously duplicated in `do_fetch()`. It properly handles both atomic and non-atomic transactions, including cleanup to avoid double-free issues. The function takes parameters for the transaction pointer (passed by reference to allow nulling), atomicity flag, remote name for error reporting, and an error strbuf.

The refactoring maintains all existing behavior while making the code more maintainable. The commit message clearly states this is preparatory work for the actual bugfix in the next patch, which will address the issue where tag fetches fail when other reference updates conflict. The patch follows the series structure suggested in earlier reviews, cleanly separating the refactoring from the functional fix.
