This is a test infrastructure note regarding the signed commits patch series. Maintainer Junio C Hamano points out that the new tests in patch 3 will fail when merged because they depend on SHA-256 repositories created by another test that now requires Rust support (added in commit f6581e23). The signature-stripping functionality itself doesn't need dual-hash interoperability, so the tests should be restructured to avoid this dependency.

The issue is specific to the test setup - the tests currently assume an explicit-sha256 repository exists, but this assumption breaks when Git is built without Rust support. This doesn't affect the core functionality being proposed (signature stripping in fast-import), but does need to be addressed before the series can be merged.

The maintainer suggests rearranging the tests to remove this dependency, likely by either making the SHA-256 repository creation part of the test setup (with appropriate prerequisites) or restructuring the tests to not require SHA-256 repositories at all. This is a practical merge conflict rather than a conceptual issue with the patch series itself.
