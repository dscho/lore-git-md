Bugfix for `git fetch`'s batched tag handling, addressing a regression from commit 0e358de64a. This is the second patch in a two-part series that first refactored the transaction commit logic (in patch 1/2) and now applies the actual fix.

The issue occurs when fetching tags in batched mode - if any tag conflicts exist, the entire transaction (including non-conflicting tags) would fail to commit. The fix modifies the cleanup path in `do_fetch()` to commit non-atomic transactions even when errors occur, ensuring non-conflicting references are still applied. The change is guarded by checking both the error code and atomic_fetch flag.

Three new test cases verify the fix:
1. Basic tag fetching functionality
2. Handling of non-conflicting tags when conflicts exist
3. Proper backfilling of tags when fetching via refspec

The patch builds on the preparatory refactoring from part 1, using the new `commit_ref_transaction()` helper. It maintains all existing error handling while fixing the tag commitment issue. Test coverage appears thorough, including cases for both direct tag fetching and indirect backfilling scenarios. The solution cleanly addresses the reported regression while preserving the performance benefits of batched updates.
