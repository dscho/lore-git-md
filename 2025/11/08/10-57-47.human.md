This is a technical explanation in the ongoing discussion about `git cherry-pick` vs `git apply` behavior. Chris Torek provides a detailed comparison between direct patch application and three-way merging, clarifying why the commands behave differently in the reported case.

The email explains that `git cherry-pick` performs a three-way merge using complete version history, while `git apply` works with just the patch content. When `--3way` is used with `git apply`, it attempts to reconstruct the three-way merge by finding the original file version referenced in the patch's index line. This allows it to handle cases where changes appear redundant more intelligently than direct patching.

Chris emphasizes this is expected difference in behavior, not a bug. Three-way merging can legitimately succeed where direct patching fails because it has more context about the changes' origins. The explanation includes concrete examples of how each method processes changes differently, particularly when dealing with repeated patterns or seemingly-already-applied modifications.
