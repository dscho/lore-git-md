This is a follow-up discussion about case-folding collision handling in the submodule path encoding series. Aaron Schrab raises an important edge case regarding the encoding strategy: what happens when a submodule with uppercase letters (e.g. "Foo") is added first without conflicts, and later a lowercase variant ("foo") is added that would collide on case-insensitive filesystems.

The current solution only applies uppercase encoding when a collision is detected during submodule creation, but this leaves a potential gap where future additions could still collide with existing unencoded paths. This appears to be the last remaining open question in an otherwise well-vetted series that has reached consensus among the main contributors (Adrian Ratiu, Junio Hamano, and Patrick Steinhardt).

The thread context shows the series has comprehensive handling for most edge cases, including URL percent-encoding, config-based transitions, and filesystem feedback mechanisms. This new scenario tests whether the case-folding solution is truly complete or needs one final adjustment to handle this temporal collision case. The question is posed directly to Adrian Ratiu, who proposed the original case-folding solution.
