This is the final patch in a series adding a new 'is-needed' subcommand to `git maintenance`. The feature allows users to check whether maintenance tasks would run (when using --auto) without actually executing them, addressing the current limitation where the heuristics are only checked during execution.

The patch introduces the user-facing command with support for both --auto mode (which uses the same thresholds as 'run --auto') and --task flags to check specific tasks. The implementation returns 0 if maintenance is needed, 1 otherwise, making it suitable for scripting. The documentation is updated to explain the new subcommand's behavior.

The patch includes comprehensive tests that verify the command works correctly with all maintenance tasks (gc, commit-graph, loose-objects, incremental-repack, reflog-expire, worktree-prune, and rerere-gc). The tests demonstrate proper interaction with task-specific auto-configuration and show the command can be used to check conditions before running maintenance.

This is a well-polished addition that has gone through multiple review rounds, with Reviewed-by tags from Patrick Steinhardt and Justin Tobler. The implementation builds on the ref backend optimization infrastructure added in earlier patches of the series. The tests are thorough and include cleanup of a duplicate test case. The patch appears ready for integration.
