This is a feature patch series introducing a new 'is-needed' subcommand for `git maintenance` to check whether tasks require execution without performing them. The 5-patch series builds on prior work to expose ref backend optimization checks and integrates them with the maintenance framework.

The series has evolved through multiple rounds of review, with key technical refinements including:
- Renaming `use_heuristics` parameter to `use_geometric` for clarity in the reftable compaction logic
- Settling on simple `return required` boolean style after discussion of alternatives
- Adding TODO for future improvements to non-auto mode behavior

The implementation provides:
1. Ref backend infrastructure (patches 1-3):
   - Cleaned-up reftable segment handling
   - New `optimize_required` callback in ref storage backend
   - Public API for checking optimization needs

2. Maintenance integration (patches 4-5):
   - `pack_refs_condition()` using new refs API
   - User-facing `is-needed` subcommand with `--auto` support
   - Comprehensive test coverage

The series is technically complete with Reviewed-by tags from Patrick Steinhardt and Justin Tobler, and has addressed all feedback including Junio Hamano's guidance on boolean handling. It depends on two in-flight topics (`kn/refs-optim-cleanup` and `ps/ref-peeled-tags`) but is otherwise ready for integration, providing a maintainable foundation for future maintenance checking functionality.
