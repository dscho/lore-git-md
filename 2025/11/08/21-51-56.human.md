This is part 4 of a 5-patch series introducing a 'is-needed' subcommand to `git maintenance` that checks whether tasks require execution without performing them. The series is now technically complete after multiple rounds of review.

This patch modifies the `pack_refs_condition()` function to use the new `refs_optimize_required()` API added in earlier patches, rather than always returning true. The change allows the maintenance system to accurately determine when reference optimization is needed, which is crucial for the new 'is-needed' subcommand. The implementation checks all references (using "*" pattern) and respects the same auto-optimization heuristics used by `git pack-refs --auto`.

A minor cleanup removes a duplicate `SEEN` flag definition from object.h that conflicted with one in revision.h. The patch has already received Reviewed-by tags and addresses all previous feedback, including final stylistic guidance from Junio Hamano about boolean handling. This is a well-polished change that completes the plumbing needed by the upcoming user-facing command in patch 5.
