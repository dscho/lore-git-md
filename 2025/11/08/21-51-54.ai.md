This is part of the ref backend optimization infrastructure in a series introducing a 'is-needed' subcommand for `git maintenance`. Patch 2/5 adds the core functionality to check if reftable compaction is needed without performing it.

The patch extracts the compaction heuristics from `reftable_stack_auto_compact()` into a new internal function `update_segment_if_compaction_required()`, then exposes this via a public API `reftable_stack_compaction_required()`. The function takes a `use_heuristics` parameter (later renamed to `use_geometric` per discussion) to choose between strict checking (all tables compactable to one) or geometric progression-based checking. It returns the result through an out-parameter `required`.

Key technical details:
- The implementation maintains the same compaction logic while splitting the checking from execution
- Unit tests verify the new function's behavior, including edge cases
- The change is part of enabling `git maintenance is-needed` to check ref optimization status
- Follows the refactoring in patch 1 which prepared the infrastructure

The patch has already been reviewed with all technical points resolved, including the final naming of the `use_geometric` parameter. It provides the foundation for the higher-level maintenance command while improving the reftable API surface.
