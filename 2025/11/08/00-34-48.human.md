This is a discussion about the proposed 'strip-if-invalid' mode for signed commits in `git fast-import`, part of an ongoing thread about signature handling during history rewriting. Elijah Newren responds to Junio Hamano's concerns about the feature's assumptions regarding signature validation.

The email clarifies the motivation: users of `git filter-repo` want to rewrite only recent history while preserving older signatures, but current behavior forces full rewriting when signatures are involved. The proposed mode would let fast-import validate and conditionally strip signatures during import. Newren acknowledges the challenge of requiring all public keys for validation and explores an alternative approach where fast-export could provide unsigned commit OIDs for comparison instead of full signature validation.

The discussion highlights fundamental questions about signature integrity when rewriting history, with the maintainer's concerns about cryptographic implications still unresolved. Newren's response suggests the current approach may be the only practical solution despite its limitations, though he proposes one alternative involving format changes to fast-export/import. The thread remains in exploratory phase regarding how to best handle signatures during history rewriting operations.
