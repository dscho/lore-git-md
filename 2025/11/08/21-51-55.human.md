This is part 3 of a 5-patch series adding a 'git maintenance is-needed' subcommand to check if maintenance tasks require execution. The series has been through multiple rounds of review and is now technically complete.

This patch introduces backend infrastructure for checking if reference storage optimization is needed. It adds an `optimize_required` callback to `struct ref_storage_be` and implements it for all ref backends (debug, files, packed, and reftable). The packed backend always returns false since packed refs are already optimized, while the files and reftable backends implement proper checks. The reftable implementation builds on the compaction checking logic added in patch 2.

The changes are straightforward plumbing to expose the new capability through a consistent interface. The patch follows the established pattern of the existing `optimize` callback, adding a parallel `optimize_required` version. This is a key building block for the upcoming 'is-needed' subcommand that will use these backend checks to determine if maintenance tasks should run.

The implementation looks solid, with each backend getting appropriate implementations. The reftable version in particular benefits from the preparatory work in earlier patches. The series has already received positive reviews and appears ready for integration.
