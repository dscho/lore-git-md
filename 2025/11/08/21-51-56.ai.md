This patch integrates the new ref backend optimization checking infrastructure into the maintenance system's pack-refs task. It modifies `pack_refs_condition()` to use the recently added `refs_optimize_required()` function instead of always returning true, enabling proper auto-condition checking for reference optimization.

The implementation sets up ref inclusion/exclusion parameters similar to `git refs optimize --all`, using a wildcard pattern to check all references. It properly handles the optimization options structure and cleans up allocated resources. The change also includes a minor cleanup by removing a duplicate `SEEN` flag definition from `object.h` that conflicted with `revision.h`'s version.

This is the fourth patch in a 5-part series introducing the `git maintenance is-needed` subcommand. It builds on the ref backend infrastructure from patches 1-3 to provide accurate pack-refs task condition checking. The implementation follows the final agreed-upon boolean handling style (simple `return required` form) after discussion in the thread, with Junio Hamano confirming this as the preferred approach.

The patch demonstrates careful integration with the existing maintenance system while leveraging the new optimization checking capability. It completes the technical foundation for the upcoming `is-needed` subcommand by ensuring the pack-refs task can properly report whether optimization is required without performing it. The change maintains backward compatibility with the existing `--auto` behavior while enabling the new functionality.
