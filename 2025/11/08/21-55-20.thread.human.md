Here's a human-readable summary of the thread:

This thread reports a serious macOS 26 (Tahoe) compatibility issue where Git's fsmonitor daemon processes fail to terminate properly. When core.fsmonitor is enabled, the daemon processes (spawned in detached mode) remain running indefinitely after their parent applications quit, leading to resource exhaustion and locked repositories due to lingering index.lock files. 

The bug affects all Git clients (including Xcode, VS Code, GitX, and terminal usage) and all Git installation methods (system Git, Homebrew, Xcode CLI tools) on macOS 26. A GitX maintainer reports seeing thousands of orphaned processes in some cases. The current workaround is to disable fsmonitor globally. Apple has been notified (FB20956467), but the root cause of this macOS-specific interaction isn't yet understood. The issue doesn't occur on earlier macOS versions.
