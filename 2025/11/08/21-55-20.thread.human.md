Here's the updated human-readable summary:

The thread began with a report about fsmonitor daemon processes failing to terminate properly on macOS 26 (Tahoe), where detached `git fsmonitor--daemon` processes would linger after their parent applications quit, causing resource exhaustion and locked repositories. The original reporter, a GitX maintainer, provided detailed reproduction steps showing this affected all Git clients and builds when core.fsmonitor was enabled, with some users reporting thousands of orphaned processes. The workaround was to disable fsmonitor globally.

A follow-up from Koji Nakamaru has expanded the scope, reporting the same behavior on macOS Sequoia 15.7.2 and earlier versions, suggesting this may be a long-standing macOS issue rather than specific to Tahoe. Nakamaru shared an alternative workaround of selectively enabling fsmonitor only for large repositories rather than disabling it completely. 

The core problem remains unresolved - these detached processes continue to accumulate and must be manually killed. There's now some disagreement about whether this is a Tahoe-specific regression or a broader macOS issue, which will need further investigation. No proposed fixes for the underlying daemon lifecycle management have been offered yet, though the workarounds provide temporary relief while the root cause is being investigated.
