This is part of a series introducing a new 'is-needed' subcommand for `git maintenance` to check if tasks require execution without performing them. Patch 2/5 focuses on the reftable backend infrastructure.

The patch extracts compaction heuristics from `reftable_stack_auto_compact()` into a new internal function `update_segment_if_compaction_required()`, then exposes this via a public API `reftable_stack_compaction_required()`. This allows checking if optimization is needed without actually performing compaction. The function supports two modes: a strict check (all tables can be compacted to one) and a geometric progression-based heuristic.

The implementation is thorough, with proper error handling and comprehensive unit tests added to verify the new functionality. The patch has already gone through several rounds of review, with parameter names and boolean handling clarified based on feedback. It's part of a well-structured series that's now technically complete and ready for integration.
