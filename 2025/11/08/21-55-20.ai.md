This is a bug report about fsmonitor daemon processes failing to terminate properly on macOS 26 (Tahoe). The issue affects all Git clients and builds on this macOS version, causing daemon processes to accumulate indefinitely when core.fsmonitor is enabled.

The key technical details are that fsmonitor--daemon processes spawn in detached mode (not as children of parent applications) with the command `git fsmonitor--daemon run --detach --ipc-threads=8`. These processes never receive termination signals when parent applications quit, leading to resource exhaustion and locked repositories due to lingering index.lock files. The problem is specific to macOS 26+ and doesn't occur on earlier versions.

The reporter provides clear reproduction steps showing this affects all Git clients (Xcode, VS Code, GitX, terminal with Starship) and all Git builds (system Git, Homebrew, Xcode CLI tools). The current workaround is to disable fsmonitor globally. The issue is serious enough that some GitX users are seeing thousands of orphaned processes, and it's already been reported to Apple as FB20956467.

The bug appears to be a macOS 26-specific interaction with Git's fsmonitor daemon spawning behavior, though the root cause isn't yet diagnosed in this initial report. The reporter is a GitX maintainer who has clearly done thorough investigation, providing system info showing this occurs on arm64 macOS with various Git versions and configurations.
