This is a test infrastructure note regarding the fast-import signature stripping patch series. Maintainer Junio Hamano points out that the tests in patch 3/3 will fail when merged because they depend on an explicit-sha256 test repository that requires Rust support (added in a separate recent change), even though the signature stripping functionality itself doesn't care about hash algorithms.

The issue is purely about test portability - the tests assume the existence of a dual-hash test environment that may not be present in all builds. Hamano suggests rearranging the tests to avoid this dependency, since the signature verification/stripping feature being tested is hash-agnostic. This appears to be a straightforward test adjustment needed before the series can proceed, unrelated to the earlier substantive discussion about the cryptographic implications of signature stripping.
