Refactoring patch preparing for a bugfix in `git fetch`'s tag handling. This is the first of two patches in v3 of the series, which fixes a regression where non-conflicting tags would fail to update if any conflicts existed in the same batched reference transaction.

The patch extracts the reference transaction committing logic from `do_fetch()` into a new helper function `commit_ref_transaction()`. This prepares for the subsequent bugfix by making the transaction handling reusable across different parts of the fetch operation. The helper properly handles both atomic and non-atomic transactions, including cleanup and rejection handling.

The changes look clean and focused - this is purely a refactoring with no behavior changes. The commit message clearly explains the motivation (enabling the bugfix in the next patch) and the patch itself is well-structured, moving 26 lines of code into the new helper while maintaining all the existing functionality. The series has already gone through several rounds of review, with this version incorporating feedback about separating the refactoring from the actual bugfix.
