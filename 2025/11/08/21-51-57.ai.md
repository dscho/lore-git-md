This is the final patch in a 5-part series introducing a new 'is-needed' subcommand for `git maintenance`. The patch adds the user-facing command that checks whether maintenance tasks should run without actually executing them, completing the functionality built up in the previous patches.

The new subcommand supports both `--auto` mode (using the same heuristics as `maintenance run --auto`) and explicit task selection via `--task`. It returns exit code 0 if maintenance is needed, 1 otherwise. The implementation reuses the existing task infrastructure and auto-condition checks from the maintenance system while avoiding any actual maintenance operations.

Key technical details:
- New `maintenance_is_needed()` function implements the core logic in builtin/gc.c
- Handles both auto mode (checking task-specific conditions) and non-auto mode (currently always returns true, with a TODO for future optimization)
- Integrates with all maintenance tasks via their existing `auto_condition` callbacks
- Adds comprehensive tests in t7900-maintenance.sh covering all task types (gc, commit-graph, loose-objects, etc.)
- Documents the new subcommand in git-maintenance.adoc
- Removes a duplicate test case for worktree-prune task

The patch builds on the ref backend optimization infrastructure from earlier in the series (patches 1-3) and the integration with maintenance conditions (patch 4). It has received positive reviews and is technically complete, with all prior discussion points resolved. The implementation provides a clean foundation for future enhancements to the non-auto mode behavior noted in the TODO comment.
