This is patch 3/5 in a series adding a 'is-needed' subcommand to `git maintenance` to check if tasks require execution without performing them. The patch introduces backend infrastructure for checking optimization needs across different ref storage backends.

The patch adds a new `optimize_required` callback to `struct ref_storage_be` and implements it for all four ref backends (debug, files, packed, and reftable). The packed backend trivially returns false since packed refs are always optimized, while the files and reftable backends implement actual checks. The reftable implementation builds on the compaction checking logic introduced in patch 2, while the files backend uses existing `should_pack_refs()` logic.

Key technical details:
- New `optimize_required_fn` type and `optimize_required` field in `struct ref_storage_be`
- Public `refs_optimize_required()` wrapper in refs.h
- Debug backend passes through to wrapped backend with tracing
- Files backend checks via `should_pack_refs()`
- Packed backend always returns false
- Reftable backend uses `reftable_stack_compaction_required()` from patch 2
- All implementations respect `REFS_OPTIMIZE_AUTO` flag in opts

The patch is well-structured and follows the established pattern for ref backend operations. It provides the necessary plumbing for the upcoming maintenance command while maintaining consistency with existing backend interfaces. The implementation appears technically sound, with each backend providing appropriate behavior for its storage model.
