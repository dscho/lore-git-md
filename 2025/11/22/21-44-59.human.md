This is a performance optimization follow-up to the recently merged fix for `git diff --quiet` behavior with rename/copy detection. The patch addresses an inefficiency in how unchanged filepairs are handled when `--find-copies-harder` is active.

René Scharfe introduces a new `diff_same()` function that more efficiently queues unchanged filepairs during copy detection, avoiding unnecessary work done by the more general `diff_change()`. The change shows a measurable 1.33x speedup when running `git diff --cached --find-copies-harder` on the Linux repository.

The optimization is safe because it builds on the previous fix that disabled rename detection in quiet mode. The patch cleanly separates the handling of changed and unchanged files, with `diff_same()` doing just the minimal work needed for copy detection while avoiding misleading `has_changes` flags. This appears to be a well-considered refinement of the earlier solution, with clear performance benefits and no apparent downsides.
