This is a bugfix for the `--shallow-since` functionality in Git's shallow clone feature. The patch addresses an edge case where border commits in the shallow clone list could incorrectly include descendant relationships between commits.

The core issue occurs when generating a shallow clone based on date ranges (`--shallow-since`). Currently, if the list of border commits includes both a parent and its child commit, the logic fails to properly handle their relationship. The patch modifies the commit flagging logic in `shallow.c` to:

1. Better track which commits should remain shallow versus those that should be borders
2. Properly handle cases where a border commit has parents that also need to be considered as borders
3. Ensure descendant commits are excluded from the border list when their ancestors are present

The changes introduce a more sophisticated flag management system that:
- Tracks when a commit "must_not_be_shallow" due to having parents marked as not shallow
- Cleans up shallow flags on parents when appropriate
- Adds proper border commit selection logic that considers the full parent-child relationship graph
