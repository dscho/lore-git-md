This is a performance optimization follow-up to the recently merged `--quiet` rename detection fix. René Scharfe addresses a secondary inefficiency in the diff machinery that was revealed during the investigation of the original bug.

The patch introduces a new `diff_same()` function to handle unchanged filepairs more efficiently when `--find-copies-harder` is active. Previously, these were processed through `diff_change()`, which performed unnecessary work and incorrectly set the `has_changes` flag. The new function skips this overhead by only allocating one half of each filepair and avoiding the change-tracking logic.

Benchmarks on the Linux repository show a 1.33x speedup (31.8ms to 23.9ms) for `git diff --cached --find-copies-harder`. The change is particularly beneficial for large repositories with many unchanged files when copy detection is active.

The implementation splits the logic in `show_modified()` to use `diff_change()` only for actual changes and `diff_same()` for unchanged files when copy detection is needed. This maintains correct behavior while eliminating the misleading `has_changes` flag setting and reducing memory allocations. The patch includes the new public function in `diff.h` and updates the relevant call sites.

This optimization builds on the recently merged solution that disabled rename detection in quiet mode`, but stands independently as a general improvement to the diff machinery's handling of unchanged files during copy detection. The change is well-contained and comes with measurable performance benefits, making it a straightforward improvement to the diff backend.
