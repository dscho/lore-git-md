This is a naming discussion in Patrick Steinhardt's object database streaming interface refactoring series (specifically patch 17/19). The patch reorients the streaming interface to be object-database-centric rather than repository-centric, renaming functions accordingly.

Junio C Hamano approves the general direction but suggests an alternative naming scheme that maintains verb-first consistency with file I/O APIs while keeping the clearer "read stream" terminology. He proposes `odb_read_stream_open()`, `odb_read_stream_read()`, and `odb_read_stream_close()` as alternatives to the current naming, noting this would preserve the familiar open/read/close pattern while being more descriptive than the original "istream" naming.

The discussion occurs late in a largely completed 19-patch series that has already:
- Renamed core types (1/19)
- Simplified control flow (2/19)
- Centralized type handling (3/19)
- Made parameters explicit (4/19)
- Moved stream allocation (5/19)
- Introduced type-safe containers (6-9/19)
- Isolated zlib handling (10/19)
- Extracted packed object reading (11/19)
- Optimized stream creation (12/19)
- Removed `the_repository` usage (13/19)
- Exposed stream structure (14/19)
- Relocated implementations (15-16/19)

This naming suggestion comes after the structural work is largely complete, representing a final polish consideration. The series has already achieved its major goals of better encapsulation, explicit dependencies, and cleaner organization while eliminating `the_repository` usage.
