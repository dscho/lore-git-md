This is a refactoring patch that exports a previously internal reflog update function as part of the reftable migration infrastructure work.

Patrick Steinhardt is preparing to add another user of the `ref_transaction_update_reflog()` function, which currently lives only in refs.c. The patch makes this function public by moving its declaration to refs.h and adjusting its signature to hardcode the flags parameter (which all current callers use identically) rather than passing it in. The flags are now set internally as `REF_HAVE_OLD | REF_HAVE_NEW | REF_LOG_ONLY | REF_FORCE_CREATE_REFLOG | REF_NO_DEREF`.

The commit message explains this is groundwork for a subsequent change, though it doesn't specify what that change will be. The patch appears straightforward - it's a mechanical change that doesn't modify behavior, just makes the function available to other parts of the codebase. The documentation comment is preserved and slightly improved, clarifying that a zero index value means ordering by refname.

This is part of a larger v2 series (3/8) that's been through significant review and refinement, with all core functionality already validated. The change looks clean and well-justified, following the pattern of earlier patches in this thread that have been preparing reflog infrastructure for the reftable transition.
