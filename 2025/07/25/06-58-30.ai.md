This is a bugfix patch in Patrick Steinhardt's reflog migration series, addressing incorrect old object IDs in migrated reflog entries. The patch introduces a new `REF_LOG_USE_PROVIDED_OIDS` flag to properly preserve old OIDs during migration between storage formats (files <-> reftable).

The core issue occurs when migrating reflogs - instead of using the caller-provided old OID, the code was incorrectly resolving the reference's current value, resulting in all-zero OIDs since the reference didn't yet exist in the target storage. The fix ensures backends use the provided OIDs when this new flag is set, which is now enabled in `ref_transaction_update_reflog()`.

Key technical changes include:
- New `REF_LOG_USE_PROVIDED_OIDS` flag definition in refs.h
- Flag validation checks in both files and reftable backends
- Updated test infrastructure using `test-tool ref-store` to properly verify old/new OIDs
- Fixes for test cases that were previously masking the issue
- Documentation of the new flag's purpose and requirements

The patch completes the reflog migration functionality by ensuring OID integrity is maintained during format transitions. It builds on previous work in the series that fixed identity handling and added the migration infrastructure. Test coverage is expanded to catch this class of issues, addressing a previous gap where the problem went unnoticed due to limited reflog inspection tools.
