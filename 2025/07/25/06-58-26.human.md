This is a feature patch adding a new `git reflog write` subcommand, part of Patrick Steinhardt's ongoing series to improve reflog infrastructure for the reftable backend transition. The patch introduces the ability to manually append reflog entries, which was previously impossible with the binary reftable format.

The new subcommand takes a ref, old/new object IDs (which must be full hashes of existing objects), and a message. It's intentionally minimal - no batch operations, custom timestamps, or handling of nonexistent objects yet. The implementation includes thorough validation of inputs and proper error handling, with tests covering invalid arguments, bad refnames, nonexistent/abbreviated OIDs, and message normalization.

The patch appears well-crafted with:
- Clear documentation updates
- Comprehensive test coverage (101 lines of new tests)
- Careful error handling throughout
- Integration with existing ref transaction infrastructure

This fills a gap that becomes more important with reftable adoption, though the commit message notes this isn't a commonly needed operation. The implementation leaves room for future expansion while providing solid basic functionality now.
