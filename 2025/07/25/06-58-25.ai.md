This is a refactoring patch that exports the `ref_transaction_update_reflog()` function from refs.c to refs.h, making it available to other parts of the codebase. The change is part of Patrick Steinhardt's ongoing reflog migration infrastructure work between storage formats (files <-> reftable).

The patch removes the `flags` parameter from the function since all current callers use the same set of flags (REF_HAVE_OLD, REF_HAVE_NEW, REF_LOG_ONLY, REF_FORCE_CREATE_REFLOG, and REF_NO_DEREF), which are now hardcoded inside the function. The documentation is updated to clarify that when the index parameter is zero, updates will be ordered by refname.

Key technical details for future reference:
- Function moved from static to public visibility
- Flags parameter removed (now hardcoded internally)
- Documentation updated to clarify index field behavior
- All existing callers (like `migrate_one_reflog_entry`) updated to match new signature
- Part of preparing for new reflog writing functionality
- Maintains existing behavior while making API more widely available
