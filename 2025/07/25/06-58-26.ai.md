Feature implementation for reflog infrastructure, part of Patrick Steinhardt's ongoing reftable migration series (patch 4/8). This introduces a new `git reflog write` subcommand that allows manually appending entries to reflogs, particularly important for the reftable backend where manual editing isn't feasible. The implementation is intentionally minimal - it only supports appending single entries with strict validation (full OIDs, existing objects, normalized messages) and doesn't yet handle features like custom timestamps or multiple entries. The patch includes thorough tests covering error cases (invalid refs, abbreviated/nonexistent OIDs) and basic functionality, though it currently has a known issue with old OID handling in sequential writes that will be fixed later in the series. The subcommand is integrated into the reflog command structure alongside existing operations like delete/drop/expire.
