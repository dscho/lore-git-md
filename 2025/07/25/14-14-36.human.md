Feature refinement for `git rebase` warning messages. 

Cameron Steffen follows up on the discussion about warning users when commits are skipped during rebase due to conflict resolution removing all changes. He points out that there's already an existing warning message ("skipped previously applied commit <hash>") that could potentially be reused for this case, maintaining consistency in the user experience.

This builds on Junio C Hamano's initial implementation suggestion to warn about "omitting a step that has become empty" and Phillip Wood's technical analysis of edge cases where such warnings might incorrectly trigger. The thread has been exploring how to distinguish legitimate empty-step skips from other rebase operations while providing sufficient commit context through REBASE_HEAD.

The current discussion appears focused on implementation details rather than fundamental objections, suggesting the feature is likely to proceed once the edge cases and message wording are resolved. The reuse of existing warning messages could simplify the implementation while maintaining a consistent user interface.
