This is a refactoring patch in Patrick Steinhardt's reflog migration infrastructure series, specifically reorganizing the `git reflog` subcommands for better logical grouping. The patch moves read-only commands (`show`, `list`, `exists`) before write operations (`delete`, `drop`, `expire`), and positions the broadest-scope write command (`expire`) last. This prepares for adding a new `write` subcommand in a future patch.

The changes are purely organizational - no behavior is altered. Documentation and code are updated in parallel to maintain consistency. The new ordering follows a clear progression from inspection to targeted modification to system-wide operations. While subjective, the new structure appears more logical than the previous seemingly random ordering.

This is part of a mature series (now at v2) that has already addressed core technical issues and is now focusing on polish. The change is straightforward and unlikely to be controversial, though some may have opinions about the exact ordering. The patch maintains all existing functionality while making the command's structure more approachable.
