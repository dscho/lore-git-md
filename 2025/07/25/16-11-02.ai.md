This is a bug report about git-daemon failing to properly handle user directories after a Fedora 40 upgrade. The reporter, Russell King, notes that git-daemon no longer exports his "public_git" directory despite correct configuration, which worked previously.

The issue manifests when git-daemon attempts to serve repositories under user paths (like `~rmk/linux-arm.git`). While the daemon correctly identifies this as a user path and prepends "public_git", it fails to properly expand the tilde (`~rmk`) to the home directory path (`/home/rmk`). The logs show the daemon rejecting the path with "'~rmk/public_git/linux-arm.git': not in directory list".

Key technical details include:
- The system is configured with safe directories in `/etc/gitconfig` including `/home/rmk/public_git/*`
- The git-daemon service runs with `--user-path=public_git` and `--export-all` flags
- The service runs as user 'nobody' which might be relevant for path resolution
- The regression appeared after upgrading to Fedora 40 (which includes Git 2.49.0)

This appears to be a regression in path handling, possibly related to tilde expansion or user path resolution in the daemon. The reporter has provided detailed configuration and log output but hasn't been able to identify the root cause. The mention of the kernel merge window suggests this is impacting important infrastructure, increasing the urgency.
