Feature implementation patch in the `git refs` command consolidation effort, specifically adding the `git refs list` subcommand as a wrapper around `git for-each-ref`. This is patch 1/3 in the v3 series, addressing prior maintainer feedback through implementation refinements.

The patch establishes the core forwarding mechanism from `git refs list` to `git for-each-ref` by:
- Adding `REFS_LIST_USAGE` macro in both `builtin/refs.c` and `builtin/for-each-ref.c` (currently duplicated)
- Modifying `cmd_for_each_ref()` to check `argv[0]` and select appropriate usage strings
- Following the pattern from `builtin/blame.c` for command dispatch

Key discussion points in this email exchange with mentor Patrick Steinhardt:
- Usage string synchronization between the two commands needs fixing (currently differs between man page and implementation)
- Duplicated `REFS_LIST_USAGE` macro identified as maintenance hazard
- Three potential solutions proposed:
  1. Move usage strings to shared location (current approach)
  2. Extract core logic into helper function (preferred by both author and Junio Hamano)
  3. Simplify to generic `git refs list [<options>]` (rejected as harming discoverability)

The author commits to implementing the helper function extraction approach in the next version, aligning with Junio Hamano's architectural suggestion from earlier in the thread. This addresses both the usage string synchronization and macro duplication concerns while maintaining the discoverability benefits of the full options listing.

The email also notes a test suite gap where usage string differences weren't caught due to being marked as "known breakage" - this will be fixed in the next iteration. The discussion shows the author's responsiveness to mentor feedback and understanding of the tradeoffs between implementation approaches.
