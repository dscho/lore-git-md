This is a refactoring patch in Patrick Steinhardt's reflog migration infrastructure series, specifically addressing type safety in identity parsing.

The patch changes the `split_ident_line()` function's length parameter from `int` to `size_t` to better match its actual usage. The function parses identity strings (like those in commit messages and reflogs), and all callers pass positive length values derived from string operations (`strlen()`, `strbuf::len`, or pointer differences). Using `size_t` is more appropriate since string lengths can't be negative, and it matches the types used by the callers.

This is a straightforward improvement that makes the interface more type-safe and self-documenting. It's part of a larger effort to clean up and improve the reflog infrastructure, particularly around identity handling, which has been a focus of recent discussion in the thread. The change is minimal (just two lines) and low-risk since it doesn't affect behavior - it just makes the types more accurate.
