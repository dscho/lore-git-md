This is a refactoring patch in Patrick Steinhardt's ongoing reflog migration infrastructure series, specifically addressing the `REF_HAVE_OLD` flag behavior for log-only updates. 

The patch changes how Git handles the `REF_HAVE_OLD` flag during reflog updates. Previously, this flag was unset for log-only operations (like reflog migrations) since the old object ID didn't need to match the current ref state. However, this removes useful information about whether an old OID was provided. 

The change preserves the `REF_HAVE_OLD` flag while still skipping old-OID verification for log-only updates. This prepares for a future commit that will use the flag as a signal that an old OID was intentionally provided. The patch updates the flag handling consistently across all ref backends (files and reftable) and adds appropriate checks to skip verification when needed.
