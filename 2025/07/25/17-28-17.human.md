This is a follow-up discussion about the behavior of `--force` in patch 1/2 of K Jayatheerth's submodule configuration series. The patch prevents accidental overwrites of moved submodules' config entries when adding new submodules at the same path, with `--force` originally implementing an auto-increment naming scheme (e.g., turning "child" into "child2").

D. Ben Knoble suggests that the current `--force` behavior (auto-incrementing names) might be unintuitive to users who would expect `--force` to completely replace the existing submodule configuration instead. K Jayatheerth acknowledges this concern and proposes changing the implementation to match this more conventional understanding of forceful operations - removing the old submodule configuration entirely rather than creating a new numbered entry.

This represents the final UX decision needed before the patch can be integrated, as the core functionality (preventing accidental config overwrites) has already been approved. The discussion shows good responsiveness to user experience concerns while maintaining the patch's safety improvements.
