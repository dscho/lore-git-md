Bugfix addressing the `git grep -h` alias interaction issue. This patch modifies Git's alias handling to only show alias information when `-h` is the sole argument, matching the behavior of builtin commands.

The change tightens the condition in `handle_alias()` that triggers alias information display, changing from checking if `-h` is the first argument to requiring it be the only argument. This fixes the reported case where `git g -h -A20` (with `g` aliased to `grep`) incorrectly showed alias help instead of passing `-h` to grep. The patch maintains the stderr output for alias information since non-builtin aliases might use `-h` differently.

The fix is minimal (a one-line change in `git.c`) and maintains backward compatibility while resolving the inconsistency between builtin and alias behavior. The commit references the original 2018 change (a9a60b94cc) that introduced the current behavior and credits Kevin Brodsky for the bug report. The solution appears well-considered, preserving the stderr output path while fixing the core issue of when to trigger alias help display.

Key technical details: The patch modifies the `args->nr > 1` check to `args->nr == 2` in `handle_alias()`, affecting how Git processes the first argument after an alias. This maintains the existing behavior for actual help requests (`git cmd -h` alone) while allowing `-h` to pass through when used with other flags. The change is specific to alias handling and doesn't affect direct command invocations.
