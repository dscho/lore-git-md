This is a follow-up test fix for the recently merged GPG path expansion work. Jeff King points out a Windows-specific test failure in the newly added test cases for `gpg.program` path handling. The issue occurs when testing PATH lookup behavior - the test constructs a PATH environment variable with mixed forward and backward slashes on Windows-style paths, which appears to break path resolution.

The test in question verifies that Git can find a GPG program specified by a relative path (without slashes) by searching the PATH. On Windows, the test fails because the constructed PATH contains both "D:/" and "/d/" style paths, suggesting the test needs to normalize path separators when building the PATH variable. Jeff suggests using $PWD instead of $(pwd) to get consistent path formatting.

This is a minor but important fix to make the new test coverage fully portable. The core functionality (tilde expansion and PATH lookup for GPG programs) is already working correctly - this just addresses a test implementation detail on Windows. The fix should be straightforward and uncontroversial given the context of the already-merged series.
