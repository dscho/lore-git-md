This is a bugfix patch for submodule handling that prevents configuration overwrites when reusing paths. It's the first of two patches in a series that has already been reviewed and approved by Junio Hamano.

The patch addresses a subtle issue where `git submodule add` could silently overwrite `.gitmodules` configuration when adding a submodule at a path that previously hosted another submodule. The problem occurs when a submodule is moved (e.g., from 'child' to 'child_old') but not renamed - the original configuration would be lost if another submodule was later added at the original path.

The solution adds a check in `module_add()` to detect when a submodule name is already in use, requiring either an explicit rename or the `--force` flag (which generates numbered names like "child1"). The change includes documentation updates and a new test case that verifies the protection works as intended.

This appears to be a well-crafted fix for a real-world issue that could cause configuration loss. The patch has thorough test coverage and has already incorporated all review feedback from the previous round. Since it's part of an approved series, it's likely to be merged soon.
