This is the first patch in a two-part series improving submodule handling, specifically addressing a bug where `.gitmodules` could be silently overwritten during submodule path reuse. The patch modifies `module_add()` in `builtin/submodule--helper.c` to detect when a path-derived submodule name conflicts with an existing entry, preventing accidental configuration loss.

The core change adds a check using `submodule_from_name()` to verify the proposed name isn't already registered to a different path. When a conflict exists, the command now fails unless `--force` is used, in which case it generates unique numbered names (like "child1"). The implementation includes proper memory management with `strbuf` for name generation and cleanup.

Documentation updates clarify the new `--force` behavior for name conflicts, and a new test in `t7400-submodule-basic.sh` verifies the protection works by simulating a scenario where a moved submodule's name would otherwise be reused. The test checks both the error message and that the operation fails without `--force`.

This appears to be a well-considered solution to a real footgun in submodule management, with thorough test coverage and clear documentation. The patch has already incorporated Junio Hamano's feedback from earlier review rounds, including proper error messaging and variable scoping.
