Thread identity: RFC proposal for a permanent-history Git workflow with structured branch lifecycle management and AI-assisted development coordination, originating from Skybuck Flying.

Core problem/goal: Design an alternative Git workflow preserving all development history via non-deleting branches with explicit state tracking (active/merged/rejected) and sequential versioning, now implemented as Windows executables after previous AI-assisted parallel development proposal. Replaces pull requests with direct pushes plus PostgreSQL-based communication (previously described) and now delivers concrete tools.

Key technical details:
- Branch naming: `UserPrefixContributionNNN-Description` with sequential versioning
- State management via directory-like tags: `active/`, `merged/`, `rejected/`, `revive/`
- Seven Delphi-compiled Windows executables implementing core workflow:
  * `git-new-contribution.exe`: Creates numbered branches from master
  * State transition commands: `git-set-active.exe`/`git-set-merged.exe`/`git-set-rejected.exe`
  * History commands: `git-back-to.exe` (historical branching), `git-the-future.exe` (rebase)
  * `git-set-revive.exe`: Reactivates archived branches
- Tools execute Git operations via spawned `cmd.exe` processes
- Maintains PostgreSQL communication layer (`AICommPostgreSQL.exe`) from previous proposal
- Implementation remains external (Windows executables + Bash scripts) with no core Git integration
- Requires manual PATH configuration and Delphi toolchain for building
- Windows path length concerns still unaddressed
- All code now provided but remains untested in real workflows
