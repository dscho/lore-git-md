A regression in git-daemon's path handling is preventing access to user repositories after a Fedora 40 upgrade. Russell King reports that repositories under user paths (e.g., `~rmk/linux-arm.git`) are no longer being served, despite correct configuration that previously worked. The daemon appears to be failing at the tilde expansion step when prepending the configured public_git directory, rejecting paths with "'~rmk/public_git/linux-arm.git': not in directory list" errors.

The system is properly configured with safe directories in /etc/gitconfig and the daemon is running with --user-path=public_git and --export-all flags. The issue emerged after upgrading to Fedora 40 (Git 2.49.0), suggesting a regression in path resolution. Of particular concern is that the daemon runs as user 'nobody', which may affect how it handles home directory paths. This is impacting critical infrastructure during the kernel merge window, adding urgency to the resolution.
