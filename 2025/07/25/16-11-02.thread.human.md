Russell King reported a regression in git-daemon on Fedora 40 (Git 2.49.0) where repository paths containing tildes (`~user`) fail to expand properly when using `--user-path=public_git`. This breaks existing infrastructure during the critical kernel merge window. The daemon correctly identifies user paths but rejects them with "not in directory list" errors, despite the paths being properly listed in safe.directory configuration.

Jeff King investigated but couldn't reproduce the issue in his test environment. His analysis suggests the problem may lie in path validation (`daemon.c:path_ok()`) or possibly systemd service configuration quirks specific to Fedora 40. While the daemon appears to be looking in the correct expanded paths internally, something in the logging or validation chain is failing. The investigation remains open with no clear root cause yet identified - the issue appears environment-specific rather than a universal Git bug.
