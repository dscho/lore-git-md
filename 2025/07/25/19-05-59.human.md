This is an RFC proposal for a structured Git workflow that preserves all development history through permanent branches and explicit status tracking. Skybuck Flying expands on their initial proposal with more details about the problems it aims to solve and the workflow would operate in practice.

The workflow addresses four main pain points: loss of history from branch deletion, branch sprawl without clear status, lack of developer continuity, and risk of accidental data loss. The solution centers around never deleting branches, instead managing their lifecycle through tags (`active/`, `merged/`, `rejected/`) and providing custom commands for branch operations. The proposal includes detailed descriptions of key commands like `new-contribution` for creating properly named branches and `back-to` + `TheFuture` for historical branching and rebasing workflows.

The author acknowledges Windows compatibility as a current limitation since the workflow relies on Bash scripts, and requests community input on how to better support such workflows natively on Windows. The proposal is thorough and clearly the result of long-term refinement, though its viability at scale (particularly regarding branch proliferation and Windows path length limits) remains an open question. No implementation exists yet - this remains a conceptual proposal seeking feedback.
