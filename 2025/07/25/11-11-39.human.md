This is a discussion about the UX implications of `git diff`'s behavior when combining `--ignore-matching-lines` with `--name-only`. Jeff King (peff) weighs in on the thread, agreeing with Arne's argument that the current behavior is surprising from a user perspective.

The core issue is between performance optimization (avoiding content examination for metadata outputs) and behavioral consistency (having `--name-only` respect content-ignoring options). Peff provides a compelling example where `--name-only` lists a file that wouldn't appear in the actual diff output when whitespace changes are ignored, which he argues is counterintuitive.

While acknowledging Junio's earlier technical rationale about keeping metadata outputs content-agnostic, peff suggests the optimization might be an implementation detail that shouldn't dictate user expectations. He notes we already make an exception for `--quiet` with `-w`, and questions whether similar consistency should apply to `--name-only`.

The email raises but doesn't resolve concerns about potential backward compatibility issues if the behavior were changed. The discussion remains open, now with multiple maintainers engaged on both technical and UX perspectives.
