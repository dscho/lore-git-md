Performance optimization patch for submodule configuration handling. This is the second patch in K Jayatheerth's v2 series, building on the earlier submodule path conflict protection patch.

The change modifies `configure_added_submodule()` in `builtin/submodule--helper.c` to avoid writing redundant `submodule.<name>.active` configuration when the submodule's path is already covered by existing `submodule.active` patterns. The new implementation uses `git_config_get_string_multi()` to fetch all active patterns at once and checks them with `wildmatch()`, rather than making separate calls to `is_submodule_active()`. This eliminates unnecessary configuration bloat when patterns like "lib/*" already activate the submodule.

The patch includes a new test case in `t7413-submodule-is-active.sh` that verifies no redundant active entry is created when adding a submodule under a matching pattern. The implementation follows Junio's earlier feedback to simplify the configuration checking logic. This completes the series' optimizations for submodule path handling, with both patches now incorporating all review feedback and demonstrating thorough test coverage.
