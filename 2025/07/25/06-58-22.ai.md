This is a bugfix and feature patch set addressing reflog migration issues between storage formats (files <-> reftable) and introducing a new `git reflog write` subcommand. The series is version 2 of an ongoing effort, now rebased on v2.50.1 for backporting.

The core issues being fixed are:
1. Incorrect identity information in migrated reflog entries
2. Invalid all-zero old object IDs appearing in migrated reflogs
3. The `REF_HAVE_OLD` flag being incorrectly unset for log-only updates

Key technical changes include:
- New `ref_transaction_update_reflog()` API exported from refs.c
- Implementation of `git reflog write` subcommand for manual reflog entry creation
- Fixes to identity handling during migration by preserving name/mail buffers
- Corrected `REF_HAVE_OLD` flag semantics for log-only updates
- Backward-compatible build system changes (using `object-store.h` instead of `odb.h`)
- Extensive test coverage including new t1421-reflog-write.sh

The series shows careful attention to detail with:
- Documentation updates matching subcommand reordering
- Memory management optimizations
- Thorough test cases for edge cases (nonexistent objects, abbreviated IDs)
- Message normalization handling
- Backward compatibility considerations

This work is part of the broader reftable transition effort and addresses concrete issues found during libgit2 implementation testing. The patches appear well-structured and address all identified problems from the v1 review.
