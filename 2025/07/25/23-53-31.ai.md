This is a discussion about the potential Rustification of Git's xdiff library and its implications for downstream projects. The thread context shows ongoing debate about introducing a hard Rust dependency, with concerns raised about platform support (particularly Gentoo, HPPA, Alpha, m68k) and circular dependencies with libgit2.

Ben Knoble's email responds to Patrick Steinhardt's assessment that libgit2 is unlikely to adopt Rust-based xdiff changes, noting there's already a maintained C-only xdiff fork available. Ben suggests Vim could use this fork if needed, but expresses preference for Vim to eventually support Rust-based xdiff to benefit from performance/safety gains. He offers to assist with Vim integration and proposes an intermediate solution allowing custom xdiff library linking.

Key technical considerations mentioned:
- The libgit2-maintained xdiff fork at github.com/libgit2/xdiff as a C-only alternative
- Potential need for build system changes to support alternate xdiff implementations
- Concerns about Rust compiler availability on niche platforms
- The git2 crate's dependency on libgit2 creating potential circular build dependencies

The discussion highlights the tension between modernization efforts and broad platform compatibility, with no clear resolution yet on whether/when to proceed with Rust-based xdiff changes.
