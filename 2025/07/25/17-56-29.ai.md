This is a follow-up in the ongoing discussion about `git clone` failures on NFS-mounted FSx Ontap storage due to permission issues. Tim Cederquist confirms brian m. carlson's assessment that this is indeed a storage server bug, reporting that their team found the issue only occurs with dual-NIC Ontap configurations while single-NIC setups work correctly. The email serves as an acknowledgment that the problem lies with the NFS server's non-compliant behavior rather than Git's implementation, closing the loop on the earlier technical discussion about whether Git should modify its permission handling. No new technical details or proposals are introduced - this is primarily a confirmation that the storage team is now properly engaged on what has been identified as a server-side compliance issue with POSIX file handling semantics. The thread appears to be reaching resolution with agreement that the core issue is in the FSx Ontap implementation rather than Git's behavior.
