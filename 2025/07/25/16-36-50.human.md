This is a discussion response in the thread about the proposed `commit.requireIgnoreFirst` config option. Torsten Bögershausen questions whether the problem described by Kirill Sploshnov is actually be reproduced, demonstrating with a simple test case that adding a `.gitignore` and ignored file doesn't show the described behavior (the ignored file isn't staged). 

The response raises several practical concerns about the proposal: difficulty enforcing the config across all workstations, alternative solutions like server-side hooks or CI checks, and the importance of user education. Torsten suggests the first step should be clearly demonstrating the technical problem with a test script before discussing solutions.

This moves the discussion toward validation of the core problem statement rather than implementation details. The response doesn't reject the idea outright but emphasizes needing concrete reproduction steps and considering simpler alternatives before adding new configuration options to Git core.
