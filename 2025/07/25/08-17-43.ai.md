This is a bug report about unexpected behavior in Git's alias handling when used with the `grep` command. The issue occurs when `-h` is passed to an aliased `grep` command, where Git incorrectly shows alias information even when `-h` is being used for its grep-specific purpose (suppressing filename output) rather than requesting help.

The reporter, Kevin Brodsky, demonstrates that when using an alias `g` for `grep`, running `git g -h -A20 alias .gitconfig` still prints "'g' is aliased to 'grep'" even though no help is being shown. He suggests this alias information should only appear when `-h` is actually triggering help output, not when it's being used as a grep flag.

This appears to be a long-standing issue (present since at least 2015) in how Git handles the interaction between command aliases and the `-h` flag's dual meaning (help vs grep-specific behavior). The bug is specific to the `grep` command since it's one of the few Git commands where `-h` has a non-help meaning. The report is clear and well-documented with a concrete reproduction case, suggesting it would be straightforward to verify and potentially fix.
