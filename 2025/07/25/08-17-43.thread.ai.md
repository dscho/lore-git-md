The initial fix addressed the immediate `grep -h` case but revealed broader design questions.

Current status: Jeff King's fix (modifying `handle_alias()` to only show help when `-h` is sole argument) remains correct for the original case. Junio Hamano has identified additional edge cases requiring consideration, particularly around external commands and argument handling consistency.

The underlying issue stems from Git's alias expansion happening before command-specific argument parsing.

Open questions and loose ends: Should Git: 1) Distinguish between internal/external commands in alias handling? 2) Suppress alias info when `-h` appears with other arguments? 3) Preserve all arguments when showing help? 4) Consider safety implications of running external commands after alias expansion?
