Thread identity: Bug report about unexpected alias behavior with `git grep -h`, reported by Kevin Brodsky.

Core problem: When using an alias for `grep` (e.g. `g = grep`), passing `-h` as a grep flag (to suppress filename output) incorrectly triggers alias help text display. This occurs because Git's alias handling doesn't distinguish between `-h` as a help request versus `-h` as a grep-specific flag.

Current status: Newly reported issue, no fixes or versions mentioned yet. The bug has existed since at least 2015.

Key technical details: Affects the interaction between `builtin/grep.c`'s `-h` flag handling and the alias subsystem. The issue is specific to `grep` since few other Git commands give `-h` a non-help meaning.

Open questions: Whether to modify alias help display logic to be command-aware, or change how `grep` processes `-h`. No responses or proposed solutions yet.

Participant positions: Only Kevin Brodsky so far, with clear reproduction case showing `git g -h -A20 alias .gitconfig` incorrectly showing alias help.

Related work: None mentioned yet, but potentially connects to broader alias handling improvements.
