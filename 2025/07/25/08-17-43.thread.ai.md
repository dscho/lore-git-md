Thread identity: Bug report and fix for unexpected alias behavior with `git grep -h`, reported by Kevin Brodsky and fixed by Jeff King (Peff), with design discussions involving Junio Hamano, Peff, and D. Ben Knoble about edge cases and implementation philosophy.

Core problem: Git's alias handling didn't properly distinguish between `-h` as a help request versus command-specific flag usage. The discussion evolved from technical fixes to fundamental questions about Git's alias model, culminating in Junio Hamano establishing clear principles for consistent `-h` behavior across all alias types (built-in and shell commands).

Current status: Consensus reached that `git foo -h` should always show alias expansion without executing the underlying command, regardless of alias type. Jeff King's initial fix (modifying `handle_alias()` for `-h` as sole argument) will be adapted to implement this simpler approach. The solution preserves Git's textual substitution model for normal operation while making a carefully constrained exception for help requests.

Key technical details: The final approach modifies `handle_alias()` to consistently intercept `-h` before command execution, showing only the alias expansion. This avoids edge cases that would arise from trying to execute the underlying command while maintaining the principle that `-h` should work predictably across all alias types. Peff acknowledges that automatically showing the sub-command's output (his original suggestion) would introduce unnecessary complexity compared to Junio's simpler solution.

Open questions and loose ends: Documentation updates needed to clarify the consistent `-h` behavior. The philosophical tension between practical UX and Git's design principles has been resolved in favor of Junio's guidance - simple, consistent behavior that treats `-h` as special while maintaining textual substitution for all other cases. No outstanding technical objections remain.
