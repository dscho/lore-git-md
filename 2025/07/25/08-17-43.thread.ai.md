Thread identity: Bug report and fix for unexpected alias behavior with `git grep -h`, reported by Kevin Brodsky and fixed by Jeff King (Peff).

Core problem: When using an alias for `grep` (e.g. `g = grep`), passing `-h` as a grep flag incorrectly triggered alias help text display due to Git's alias handling not distinguishing between `-h` as a help request versus `-h` as a grep-specific flag.

Current status: Fixed by Jeff King with a minimal one-line change in `git.c`. The solution modifies `handle_alias()` to only show alias information when `-h` is the sole argument, matching builtin command behavior. The patch maintains stderr output for alias information while allowing `-h` to pass through when used with other flags.

Key technical details: The fix changes the condition in `handle_alias()` from checking `args->nr > 1` to `args->nr == 2`, affecting how Git processes the first argument after an alias. This preserves behavior for actual help requests (`git cmd -h` alone) while fixing the grep case. The change references the 2018 commit (a9a60b94cc) that introduced the current behavior.

Participant positions: Kevin Brodsky reported the issue with a clear reproduction case. Jeff King provided the fix that addresses the core issue while maintaining backward compatibility. The solution is minimal and well-considered, preserving the stderr output path for alias information while allowing `-h` to pass through in other contexts.

Related work: The fix connects to broader alias handling improvements but doesn't require changes beyond the immediate issue. The patch maintains compatibility with non-builtin aliases that might use `-h` differently.
