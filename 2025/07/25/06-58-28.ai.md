This is a bugfix in the reflog migration infrastructure, specifically addressing incorrect identity handling when migrating reflog entries between storage formats. The patch is part of Patrick Steinhardt's ongoing series to improve reflog migration between files and reftable backends (now at v2 6/8).

The core issue is that the migration code was passing the full committer identity string (name + email) as just the email parameter to `fmt_ident()`, resulting in malformed output like "pks <Patrick Steinhardt ps@pks.im>". The fix properly splits the identity line using `split_ident_line()` to extract name and email components separately before formatting.

Key technical details:
- Adds new `name` and `mail` string buffers to both `migration_data` and `reflog_migration_data` structs to avoid repeated allocations
- Uses `split_ident_line()` to parse the committer string (with its parameter now safely typed as `size_t` from a previous patch)
- Maintains the same `WANT_BLANK_IDENT` and date formatting behavior
- Follows through with proper buffer cleanup in `repo_migrate_ref_storage_format()`

The patch defers adding tests until a subsequent fix is in place, when stricter verification in t1450 will catch both issues. This appears to be a straightforward correctness fix with clear motivation and implementation, though the test coverage timeline remains an open question in the thread. The change fits naturally with the series' focus on robust reflog migration infrastructure.
