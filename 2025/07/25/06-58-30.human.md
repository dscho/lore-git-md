This is the final patch in Patrick Steinhardt's series fixing reflog migration between storage formats (files <-> reftable). The patch addresses a bug where migrated reflog entries were incorrectly getting all-zero old object IDs instead of preserving the original old OIDs.

The root cause was that during migration, the code was trying to resolve the old OID by looking up the reference in the target storage (where it didn't exist yet) rather than using the OID provided by the caller. The fix introduces a new `REF_LOG_USE_PROVIDED_OIDS` flag that tells the backend to use the caller-provided OIDs directly. This flag is now set in `ref_transaction_update_reflog()`.

The patch includes thorough test updates that now verify both old and new OIDs in migrated reflogs using a new test helper. This also provides coverage for the previous commit's identity handling fixes. The changes affect both files and reftable backends consistently.

This appears to be a well-constructed fix that closes out the series by addressing the last known issue with reflog migration. The patch maintains the series' high standard with clear commit message explanation, proper flag documentation, and comprehensive test coverage. With this change, the reflog migration infrastructure should now handle all key cases correctly.
