Performance optimization and bugfix for `git remote rename` ref transactions.

This email from Patrick Steinhardt responds to Junio Hamano's review of the ongoing `git remote rename` rewrite. The key issue being discussed is how to handle directory/file (D/F) conflicts during ref transactions when renaming remotes. Junio had raised concerns about potential conflicts when renaming a ref to a path that could create directory structures (e.g., renaming "A" to "A/B").

Patrick confirms the D/F conflict issue exists in the current implementation and describes the solution: splitting the rename operation into two concurrent transactions. This approach maintains atomicity while avoiding the directory/file conflicts that could occur with a single transaction. The change builds on the earlier performance improvements that reduced the operation from hours to seconds for large repositories.

The discussion focuses on the low-level ref transaction handling in `builtin/remote.c`, specifically around the `REF_ISSYMREF` flag processing and the use of `ref_transaction_delete`/`ref_transaction_update`. The solution preserves symbolic ref status during renames through direct string manipulation of refnames using `strbuf_splice`, avoiding expensive resolution operations.

This is part of the larger effort addressing both the original bug (unborn HEAD ref handling) and severe performance issues in remote rename operations. The thread has progressed from initial bug report to comprehensive rewrite, with Junio's review now focusing on edge cases before finalizing the patch.
