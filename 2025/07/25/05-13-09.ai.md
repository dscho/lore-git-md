Windows CI test fix for gpg.program PATH testing.

This is a follow-up to the recently merged series that standardized path handling for `gpg.program` configuration. Jeff King identifies and fixes a Windows-specific test failure where `$(pwd)` produces a Windows-style path with drive letters (D:/) that causes issues when placed in PATH, since colons are path separators. The solution uses `$PWD` instead to get a Unix-style path (/d/), matching prior fixes for similar PATH-related test cases.

The patch is minimal - a one-line change to `t/t7510-signed-commit.sh` that replaces `$(pwd)` with `$PWD` in the PATH environment variable setup for testing non-absolute `gpg.program` paths. Jeff notes this could be squashed into the original series since it hasn't hit 'next' yet, and also questions whether the HOME variable setup in another test is strictly necessary given the test harness already sets it.
