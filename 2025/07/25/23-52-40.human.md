This is a thoughtful follow-up to the recent bugfix for `git grep -h` behavior with aliases. Junio Hamano raises some deeper questions about the broader implications of how Git handles `-h` with aliases.

The core observation is that while the current fix (showing alias info only when `-h` is the sole argument) works well for the immediate `grep` case, there are edge cases where the behavior might still be surprising or even risky. Hamano demonstrates this with two scenarios:

1. For external command aliases (like `!grep`), blindly passing `-h` could be dangerous if the external tool interprets `-h` differently than Git does.

2. For Git command aliases (like `checkout`), we might lose the alias expansion information when `- h` is combined with other arguments, making the output potentially confusing.

Hamano doesn't propose a specific solution but highlights that the current approach, while correct for the immediate case, might need more comprehensive consideration of how aliases and `- h` interact in various contexts. The message maintains a neutral tone, acknowledging the improvement while thoughtfully questioning whether it fully addresses the underlying design questions about alias handling.
