Bug report and resolution regarding git-daemon regression in Fedora 40 (Git 2.49.0) where user directory paths with tildes (`~user`) fail to expand when serving repositories via `--user-path=public_git`. Original report from Russell King described production impact during kernel merge window with configuration including `/etc/gitconfig` safe directories listing `/home/rmk/public_git/*` and daemon running as 'nobody' with `--export-all --user-path=public_git`. Daemon correctly prepended "public_git" but rejected paths like "'~rmk/public_git/linux-arm.git': not in directory list" without expanding `~rmk` to `/home/rmk`, behavior that worked in previous versions.

Jeff King's investigation found tilde expansion working in test environments, suggesting the issue might relate to path validation in `daemon.c:path_ok()` rather than expansion itself. The problem appeared environment-specific with no clear root cause identified in Git's code.

Todd Zullinger's follow-up identified SELinux as the root cause in Fedora 40, providing a complete solution path involving: 1) setting proper directory permissions (ensuring home directories are searchable by 'nobody'), 2) correcting SELinux context types to `git_user_content_t`, and 3) enabling the `git_system_enable_homedirs` SELinux boolean. Diagnostic steps using `audit2allow` confirmed the policy requirements. This revealed the issue as Fedora-specific (due to tightened SELinux policies in the upgrade) rather than a Git regression, though it highlighted a documentation gap in the Fedora git-daemon package regarding SELinux configuration similar to what's provided with cgit. The solution fully explains and resolves the originally reported regression.
