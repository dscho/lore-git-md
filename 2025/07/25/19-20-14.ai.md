Feature proposal for a permanent-history Git workflow with initial script implementation.

Skybuck Flying provides the first concrete implementation of their proposed Git workflow for permanent branch history, delivering seven Bash scripts that implement the core commands described in earlier RFC emails. The scripts are untested and generated by an AI (Gemini Flash 2.5), with the author noting limited availability for follow-up testing or refinement. The implementation remains Bash-only, with acknowledged Windows compatibility challenges.

The scripts implement the full workflow lifecycle:
- `git-new-contribution`: Creates sequentially numbered branches from master
- `git-set-active`/`git-set-merged`/`git-set-rejected`: Manages branch state via tags
- `git-set-revive`: Reactivates archived branches
- `git-back-to`: Creates new branches from historical points
- `git-the-future`: Rebases branches onto current master

Key technical aspects:
- Uses tag-based state tracking (`active/`, `merged/`, `rejected/` prefixes)
- Enforces sequential branch numbering with user prefixes
- Implements slugification for branch descriptions
- Includes basic error handling and validation
- Requires Git Bash on Windows (no native CMD/PowerShell support)

The email includes detailed setup instructions for storing, making executable, and testing the scripts in a Git repository. The author emphasizes this is a starting point rather than a polished solution, with several caveats about untested code and platform limitations. The implementation remains separate from core Git, operating as external scripts that leverage existing Git commands.

This moves the RFC from conceptual discussion to a testable prototype, though significant questions remain about scaling, Windows support, and integration with core Git features. The author's limited availability for iteration suggests this may need community adoption to progress further.
