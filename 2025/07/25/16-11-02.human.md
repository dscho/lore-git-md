This is a bug report about `git-daemon` failing to properly handle user directories after a Fedora 40 upgrade. The reporter, Russell King, notes that while the daemon correctly identifies user paths (prefixed with `~username/`), it fails to translate them to the actual home directory path (`/home/username/`) when combined with the `--user-path=public_git` option. The daemon logs show it attempting to access `~rmk/public_git/linux-arm.git` but failing to find it in the directory list, despite the path being properly configured in `/etc/gitconfig`.

The setup appears correct on the surface - the systemd service specifies `--user-path=public_git` and the safe directories are properly listed in gitconfig. This suggests a regression in Git 2.49.0's handling of user path expansion, particularly when combined with the `--export-all` flag. The timing is particularly problematic as it affects the reporter's ability to serve git repositories during the kernel merge window.

The report includes relevant configuration details (systemd service file, gitconfig) and logs showing the failed path resolution. While the reporter has done basic troubleshooting with strace, they're seeking help from the Git community to identify the root cause. The bug appears to affect the core path resolution logic in `git-daemon` when processing user-specified paths.
