Bugfix and performance optimization for `git remote rename` ref handling.

Patrick Steinhardt responds to Junio Hamano's review of the `git remote rename` rewrite, confirming that the patch does have the same directory/file conflict issue seen in recent ref transaction work. The issue occurs when renaming a ref to a path that would create a directory/file conflict (e.g., renaming "A" to "A/B").

The response is brief but important - Patrick indicates he's addressed this by splitting the operation into two concurrent transactions. This maintains the atomicity benefits of the new implementation while avoiding the D/F conflict problem. The change builds on the major performance improvements already described in the thread, which reduced rename operations from hours to seconds for large repos.

This appears to be the final technical hurdle before the patch can be finalized, as Junio had previously approved the overall approach. The interaction shows careful attention to edge cases in the ref transaction system, particularly important given this code handles both correctness (symbolic ref preservation) and performance at scale.
