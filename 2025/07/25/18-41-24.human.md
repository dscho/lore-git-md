Bugfix for `git grep -h` alias behavior. René Scharfe proposes a solution to the recently reported issue where `-h` flags passed to aliased commands incorrectly trigger alias help text. The patch makes Git's alias help display consistent with builtin commands by only showing alias information when `-h` is the *only* argument.

The change is minimal - a one-line modification to `git.c` that tightens the condition for showing alias help from "`-h` is present" to "`-h` is the only argument". This preserves the special meaning of `-h` for commands like `git grep` while maintaining the help functionality for aliases. The patch keeps the stderr output behavior since aliases might invoke non-builtin commands.

This appears to be a well-targeted fix for a long-standing inconsistency (dating back to 2015) that was recently surfaced by Kevin Brodsky's bug report. The change is small, clearly explained, and maintains backward compatibility while fixing the specific `git grep` case that triggered the report. No test changes are included, but the behavior being fixed is straightforward and the risk of regression seems low.
