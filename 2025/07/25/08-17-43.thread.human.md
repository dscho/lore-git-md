Here's a human-readable thread summary:

This thread reports a bug in Git's alias handling when used with the `grep` command. Kevin Brodsky discovered that when using an alias like `g` for `grep`, passing `-h` (which normally suppresses filename output in grep) incorrectly triggers Git to also display alias information. For example, `git g -h -A20 alias .gitconfig` shows both the grep output and the "'g' is aliased to 'grep'" message, even though no help was requested.

The issue stems from how Git handles the `-h` flag's dual purpose - it can mean "show help" for most commands but has grep-specific behavior (hiding filenames). The bug has existed since at least 2015 and specifically affects grep since it's one of the few commands where `-h` isn't purely a help flag. The report includes a clear reproduction case that makes the problem easy to verify.
