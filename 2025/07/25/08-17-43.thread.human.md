This thread began with Kevin Brodsky reporting a bug where `git grep -h` behaved unexpectedly when used through an alias (e.g., `g = grep`). The issue stemmed from Git's alias system interpreting `-h` as a request for help rather than passing it through as a grep flag. Jeff King (Peff) quickly provided a minimal fix that modified `handle_alias()` to only show help when `-h` is the sole argument, preserving the flag's meaning in other contexts.

The discussion has now expanded with Junio Hamano raising deeper questions about how aliases should interact with both Git commands and external tools. He acknowledges Jeff's fix addresses the immediate issue but points out remaining inconsistencies: external commands (like GNU grep) still show both alias information and their own help output when given just `-h`, while Git commands behave differently when `-h` is combined with other arguments. These edge cases reveal fundamental questions about whether and when Git should show alias expansion information versus passing arguments through verbatim, particularly for non-Git commands where the behavior of `-h` isn't predictable. The thread has shifted from a straightforward bugfix to a more nuanced discussion about alias system design.
