This is a naming discussion in the ongoing `git for-each-ref` pagination feature series. The thread has reached consensus that the new option should clearly indicate it excludes the specified reference from output (seeking to the insertion point after it rather than matching it exactly).

Karthik Nayak responds to Junio C Hamano's analysis of naming options, agreeing that names like `--start-at` or `--start-from` incorrectly imply inclusion of the specified ref. After considering the behavior where clients want to skip both the ref and everything before it, Karthik proposes changing the option name to `--start-after` for the next version of the patch series.

The discussion shows the careful attention being paid to UX semantics in this feature, with the naming choice aiming to accurately reflect the underlying seeking behavior (O(log N) position-based seeking across all ref backends) while being intuitive for pagination use cases. This follows previous naming suggestions in the thread, including Andreas Schwab's earlier advocacy for `--start-with`.
