This is a feature patch in the ongoing `git for-each-ref` pagination discussion, specifically addressing the naming of the new seeking functionality option. 

Karthik Nayak responds to Andreas Schwab's critique of the `--skip-until` naming proposal, agreeing that the current name is misleading since the behavior isn't about pattern matching but rather about sorted-list positioning. Schwab had strongly advocated for `--start-with` as a clearer alternative that better describes the actual behavior - seeking to a position in the sorted ref list where a reference would appear (skipping that exact ref if it exists), rather than performing pattern matching.

The exchange highlights an important semantic distinction in the pagination feature's behavior: it works by finding insertion points in the sorted refs rather than matching patterns, which makes the operation more robust against concurrent ref modifications. Karthik acknowledges the point and commits to updating the documentation and description in the next version of the patch series to better reflect this behavior, likely adopting Schwab's suggested `--start-with` naming.

This email moves the naming discussion forward, with the technical implementation remaining unchanged but the documentation and interface naming being refined based on community feedback. The thread appears close to resolution on this naming question, which was the last major point of discussion for this feature.
