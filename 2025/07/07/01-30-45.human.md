Junio C Hamano responds to the ongoing discussion about change IDs in email workflows, strongly advocating for using commit message trailers rather than custom headers. This is a key maintainer response in the thread about preserving change IDs through email exchanges.

Hamano makes several technical arguments against the X-Change-ID header approach: custom headers are harder to inspect with standard Git tools, don't propagate automatically during operations like rebase, and require explicit support from email clients. He argues trailers would be more visible and work with existing tools by default. He also questions whether change IDs are important enough to warrant special handling if they're considered "not precious."

While firmly rejecting the current proposal, Hamano suggests a more generic solution for future cases where commit metadata needs email round-tripping: a standardized way to encode arbitrary extra commit headers as email headers. This would solve the general problem rather than adding one-off solutions.

The response indicates significant skepticism about the current approach from Git's maintainer, while leaving the door open for alternative implementations. The thread now faces a clear fork - either pivot to using trailers as Hamano suggests, or make a stronger case for why headers are necessary despite the drawbacks he outlines. This will likely shape the direction of any future revisions to the patch series.
