Documentation patch converting line range option (`-L`) formatting to the new AsciiDoc standard, part of the v3 series addressing final formatting issues in the documentation conversion effort.

This patch updates `line-range-format.adoc` to match the project's new documentation style guidelines. It wraps command-line options and syntax elements in backticks (like `/<regex>/` and `+<offset>`) and converts angle-bracketed placeholders to italicized format (`_<start>_` instead of `<start>`). The changes are purely presentational - all content and functionality remains identical, just rendered more consistently with the rest of Git's documentation.

The patch continues Jean-Noël Avila's comprehensive effort to standardize Git's documentation format, following up on Junio Hamano's approval of the v2 series. It specifically addresses the line range options documentation that was previously converted to AsciiDoc but hadn't yet adopted the new styling conventions. The changes affect how `-L` option syntax is displayed when viewing the man pages, particularly the various forms for specifying line ranges (absolute numbers, regex patterns, and offsets).

Key technical changes include converting all instances of `<placeholder>` to `_<placeholder>_` and wrapping regex patterns (`/<regex>/`), offsets (`+<offset>`), and special syntax like `^/<regex>/` in backticks. The patch maintains all existing functionality while improving rendering consistency across documentation. This completes the mechanical conversion work for the line range options documentation as part of the v3 series.
