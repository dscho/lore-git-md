This is a bugfix patch improving error reporting in `git stash` when index operations fail. The patch is now in its second version, having incorporated feedback from Junio C Hamano and Justin Tobler.

The core change remains simple - passing `LOCK_REPORT_ON_ERROR` to `repo_hold_locked_index()` to provide more detailed error messages when index lock operations fail, while maintaining backward compatibility with the existing "could not write index" output. Junio notes a minor formatting issue (line wrapping) but indicates it can be fixed during application without requiring a resend.

The patch has evolved from v1 by adding comprehensive test coverage that verifies both the new detailed error messages and the legacy output format work as intended. This addresses prior review feedback about testing gaps. The changes are focused and minimal, touching just one line in read-cache.c while updating the stash tests to use more maintainable `test_grep` checks rather than static expected output files.

This appears ready for inclusion - it solves a real usability problem (vague error messages) in a backward-compatible way, with thorough test coverage demonstrating the solution works. The thread shows consensus that the v2 changes address all prior concerns.
