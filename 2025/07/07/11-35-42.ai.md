This is a performance optimization patch in the bloom filter pathspec series, specifically addressing the data structure changes needed to support multiple pathspec optimizations. The email from Derrick Stolee provides additional technical context and review feedback on patch 3/4 of Lidong Yan's v4 series.

The key technical clarification explains the subtle logic change in how bloom filters evaluate pathspec matches. Previously, a commit was considered TREESAME if *any* bloom key reported no change (using EXISTS logic). The new approach requires *every* pathspec to have at least one matching bloom key (FOR EVERY logic), necessitating the new `bloom_keyvec` structure to manage these relationships.

Stolee confirms the value of the optimization but suggests improvements to the implementation:
1. Using `CALLOC_ARRAY()` to simplify memory management in `bloom_keyvec_new()`
2. Adding clarifying comments for the non-obvious logic in `bloom_filter_contains_vec()` where it returns early if any key fails to match

The email provides important historical context, noting this builds on c525ce95b46's work for multi-component pathspecs while changing the evaluation semantics.
