This is the second patch in a bugfix series addressing `git apply --intent-to-add` behavior. It specifically fixes when intent-to-add entries are written to the index during patch application.

The patch modifies the `create_file()` function in `apply.c` to ensure intent-to-add entries are only created for genuinely new files, not all patched files. The key change is distinguishing between different index update scenarios - the previous version could incorrectly create intent-to-add entries for modified files when only new files should get them.

The commit message provides a thorough technical explanation of why the fix is needed, detailing how the `update_index` flag was too broad and how the new condition properly separates `--index`/`--cached` modes from intent-to-add behavior. This appears to be a well-considered fix that maintains the original feature's intent while preventing incorrect index updates.

As part of the v3 series, this patch now includes more detailed rationale about the index handling decisions, building on feedback from earlier versions. The change is small (just one line modified) but important for correct behavior, and comes with expanded test coverage in other patches of the series.
