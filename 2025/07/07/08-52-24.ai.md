This is a feature patch in the ongoing `git for-each-ref` pagination series, specifically addressing the naming discussion for the new seeking functionality. Karthik Nayak responds to Andreas Schwab's critique of the `--skip-until` naming by agreeing to change it to `--start-with` in the next version, as Schwab argues this better describes the positional seeking behavior that divides the sorted ref list.

The key technical clarification here is that the seeking functionality works by finding the insertion point in the sorted ref list where the specified reference would appear (whether it exists or not), rather than doing pattern matching. This ensures robustness against concurrent ref modifications during pagination. Schwab's point about avoiding "pattern" terminology is accepted since the operation is fundamentally about sorted-list positioning.

The discussion confirms that while the technical implementation remains unchanged (with its O(log N) performance across all ref backends), the naming needs to clearly convey the seeking-to-insertion-point behavior rather than implying pattern matching. This email marks consensus on using `--start-with` as the clearest option name for the functionality, with Karthik indicating the documentation will be updated accordingly in the next version.

The thread context shows this naming decision comes after extensive discussion of alternatives (`--skip-to`, `--start-after`, etc.) and Junio Hamano's input that the name should unambiguously indicate the exclusion of the seek target from results. The implementation's technical merits (handling of edge cases, validation against `--sort`, and concurrent modification safety) remain unaffected by this naming choice.
