This is the first patch in a bugfix series addressing `git apply --intent-to-add` functionality. The patch fixes a long-standing issue where the `--intent-to-add` flag would clobber the index by failing to read it before writing new intent-to-add entries. The problem dates back to the feature's introduction in Git 2.19 and causes the index to incorrectly mark existing files as deleted.

The core fix is straightforward - modifying `apply.c` to read the index whenever it will be either checked or updated, rather than just when checked. The commit message provides clear technical rationale for why the original condition was insufficient and how the new behavior properly handles all cases. The patch builds on prior reports from Ryan Hodges and Johannes Altmanninger, with the latter having originally identified the issue.

This appears to be a well-constructed fix for a real bug that has persisted for years. The commit message thoroughly explains both the problem and solution, making it easy to review. As the first in a series that has already gone through multiple iterations, it addresses previous architectural concerns and sets up the subsequent patches that will handle index writing behavior and test coverage.
