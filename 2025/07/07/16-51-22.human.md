This is a follow-up discussion on a platform compatibility fix for FreeBSD builds. The original patch addressed build failures caused by a conflict between `sysinfo()` detection and FreeBSD's preferred `sysctl()` approach by reordering checks in build configuration files.

The discussion confirms consensus on the current solution, with Eric Sunshine noting that while a more comprehensive fix (modifying preprocessor conditionals in `builtin/gc.c`) would handle edge cases where both macros are manually defined, the simpler build-system-only fix is adequate. Junio Hamano agrees with this assessment.

Ramsay Jones acknowledges the theoretical possibility of someone setting both macros in a Makefile build, but considers it extremely unlikely. He offers to provide a follow-up patch if desired, noting it would conflict with an in-progress series from Carlos but would be simple to resolve.

The thread appears effectively closed with maintainer approval, with all parties satisfied by the well-documented solution that preserves behavior on non-BSD systems while fixing the FreeBSD-specific issue.
