Bugfix patch addressing core issue in `git apply --intent-to-add` functionality. This is the first of four patches in the v3 series fixing incorrect index handling that has made the feature non-functional since its introduction in Git 2.19.

The patch modifies `apply.c` to properly read the index when either checking or updating it, which is necessary for correct `--intent-to-add` operation. The current implementation incorrectly only reads the index when checking it, causing the command to clobber existing index entries with an empty-tree index before writing intent-to-add entries. This results in all existing repository files being incorrectly marked as deleted in the index.

The technical rationale is clearly explained: the index must be read when either checking or updating it, since reading is a prerequisite for both operations. The change is minimal (a single line modifying the condition` in `apply.c`) but critical for correct behavior. The commit message provides thorough background on the three apply modes and how `--intent-to-add` was meant to interact with them.

This patch builds on prior reports from Ryan Hodges and Johannes Altmanninger, with the latter having provided an original patch. The v3 iteration includes enhanced technical explanations compared to previous versions, addressing architectural concerns raised earlier in the thread. The change is focused specifically on the index reading behavior, with subsequent patches in the series handling index writing and test coverage.
