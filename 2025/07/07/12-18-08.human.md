This is a bug report about Git for Windows failing to start on Windows 11 Pro after upgrading to version 2.50.0. The reporter, Fabio Frumento, describes a situation where the Git Bash terminal window appears briefly then immediately closes, making the software unusable. They confirm that downgrading to version 2.49 resolves the issue, indicating this is a regression specific to the 2.50 release.

The report includes a screenshot showing the failed startup attempt, though the image itself isn't visible in the text version. No additional technical details are provided about error messages or system configuration. The problem appears to be a straightforward startup failure rather than a functional issue once running.

This seems like a potentially serious regression for Windows users upgrading to Git 2.50, though without more reports it's unclear how widespread the issue is. The maintainers will likely need more information to diagnose the root cause, such as whether this affects all Windows 11 Pro systems or specific configurations, and what error might be occurring during startup. The clean workaround of downgrading suggests this isn't a system corruption issue but rather a compatibility problem introduced in the new release.
