This is a naming discussion in the `git for-each-ref` pagination feature series. The thread has reached consensus on implementing reference seeking behavior where the specified ref is excluded from results (seeking to the insertion point after it in sorted order). 

Junio C Hamano provides key analysis that names like `--start-at` or `--start-from` incorrectly imply inclusion of the specified ref, while the actual behavior skips it. Karthik Nayak initially proposed `--skip-until` in v2, but after this discussion agrees that `--start-after` better conveys the exclusion semantics. This follows Andreas Schwab's earlier strong advocacy for `--start-with` (which also implies exclusion), showing the naming is still being refined even as the technical implementation is settled.

The technical behavior remains unchanged: seeking uses binary search for O(log N) performance across all ref backends, maintains consistency during concurrent modifications, and is incompatible with `--sort`. The discussion now focuses purely on UX naming clarity, with all participants agreeing the name should unambiguously indicate the exclusion of the seek target ref.
