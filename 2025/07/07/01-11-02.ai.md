This is a follow-up discussion in the thread about relaxing Git's real-name requirement for Signed-off-by trailers. Junio Hamano responds to brian m. carlson's proposed documentation changes with several substantive points about the policy's wording and rationale.

Hamano emphasizes that any requirement essential for DCO enforceability must be kept, even if it excludes some contributors, while non-essential requirements like "real name" can be loosened if "known identity" suffices. He strongly agrees with accepting well-known pseudonymous contributors but wants the language to be more definitive about rejecting anonymous contributions, suggesting removing the "unfortunately" qualifier since anonymity fundamentally conflicts with provenance needs.

The response questions whether referencing the Linux kernel's policy is necessary, proposing Git should establish its own language. Hamano approves of the general direction but wants the wording to be more assertive about anonymity being unacceptable (not just "unfortunate") and more clearly distinguish between essential vs. non-essential identity requirements.

This moves the discussion toward refining the policy's tone and project-specific framing while maintaining consensus on the core principle of allowing pseudonyms for contributors with valid reasons (privacy, safety, established pseudonyms) while prohibiting untraceable anonymity. The exchange suggests the patch will likely be accepted with minor wording adjustments to strengthen the prohibition language and remove external project references.
