Performance optimization for Git's pathspec bloom filters, part of an ongoing series to improve multi-pathspec queries. This patch enables bloom filter optimization for multiple literal pathspecs while maintaining the fast path for single pathspecs.

Derrick Stolee provides review feedback on Lidong Yan's v4 patch. The core functionality looks solid, as evidenced by comprehensive test coverage showing consistent results between bloom-filter-optimized and non-optimized pathspec handling. Stolee suggests two potential improvements: adding performance measurements to quantify the speedup (recommending tests on standard repos like git.git and Linux kernel), and refactoring the code to extract single-pathspec handling into a helper function before looping over multiple pathspecs.

The changes touch revision.c and t4216-log-bloom.sh, with key modifications to `forbid_bloom_filters()` to allow multiple literal pathspecs and a new `release_revisions_bloom_keyvecs()` cleanup function. Test cases verify both the new optimization (for literal pathspecs) and continued exclusion of wildcard pathspecs from bloom filtering.

This appears to be a well-considered optimization nearing readiness for inclusion, with Stolee's feedback focusing on final polish rather than fundamental issues. The thread context shows this has undergone multiple rounds of review addressing technical concerns from various contributors.
