This is a policy discussion email in the ongoing RFC series about making Rust a hard dependency for Git with xdiff optimizations. Brian m. carlson responds to Ezekiel Newren's cover letter, strongly supporting the Rust dependency based on consensus from the Berlin Contributor Summit and citing U.S. government security recommendations about memory-unsafe languages. They propose formalizing a Rust version policy aligned with Debian stable (current version plus one year) rather than latest (1.87.0), suggesting this provides a 3-year support window that balances distro needs with security requirements. The email references their draft policy document on GitHub and acknowledges platform support tradeoffs, arguing platform maintainers should handle toolchain availability rather than blocking progress. While endorsing the technical direction, they emphasize the need for clear policies before merging, offering their draft as a starting point. The response continues their practical focus from earlier CI discussions while addressing higher-level concerns about version support and platform compatibility.
