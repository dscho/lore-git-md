This is a discussion about output format design for the new `git repo` command, specifically focusing on how to balance human-friendly and machine-readable output modes. Justin Tobler responds to Patrick Steinhardt's preference for prioritizing human-readable output (particularly for the `size` subcommand) while maintaining stable machine-readable formats.

Justin originally envisioned `git-repo` as more of a plumbing command, but now agrees it should serve both purposes under one command. He proposes three output modes via `--format=<mode>`: `user` (default, changeable), `keyvalue` (stable), and `nul` (NUL-terminated key-value pairs). He acknowledges the `user` and `keyvalue` modes might initially be identical for the `info` subcommand while allowing future divergence.

The discussion shows consensus forming around Patrick's architecture where human-friendly output can evolve while machine formats remain stable, with Justin now aligned on this approach. The thread continues to refine how this balances with Git's existing CLI conventions (`-z` as an alias) and subcommand-specific needs.
