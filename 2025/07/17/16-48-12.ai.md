This is a review comment on the `git refs list` wrapper feature, focusing on documentation style. Eric Sunshine provides a nitpick about the comment in the newly created `refs-list-options.adoc` file, suggesting removing the explicit listing of which commands share the documentation. His rationale is that such comments can become stale, and `grep` would be more reliable for determining usage.

The comment in question marks the file as containing options shared between `for-each-ref` and `refs list`. While the intent is good (documenting the relationship), Eric argues this creates maintenance overhead since the comment would need updating if more commands start sharing these options. The alternative of using `grep` to find include references would always be accurate.

This is a minor documentation polish suggestion that doesn't affect the functionality of the `refs list` wrapper itself. The core approach of sharing documentation between commands via includes remains unchanged. The comment removal would slightly improve long-term maintainability by eliminating a potential source of documentation drift. The suggestion aligns with Git's general preference for self-documenting approaches over explicit comments that might require manual updates.
