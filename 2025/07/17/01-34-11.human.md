This is a feature patch adding verbose output to `git sparse-checkout clean`, part of the ongoing effort to improve sparse-checkout usability.

The patch introduces a `--verbose` option to `git sparse-checkout clean` that shows individual files being removed (or would be removed with `--dry-run`), rather than just reporting directories. This addresses feedback from Junio Hamano and others who wanted more visibility into what exactly the command is doing. The verbose output helps users understand why certain directories exist and what files they contain before deletion.

The implementation adds a new `list_every_file_in_dir()` helper that recursively traverses directories using the existing `for_each_file_in_dir()` infrastructure. When `--verbose` is used, it prints each file path with the same "Would remove"/"Removing" prefix used for directory-level output. The patch includes tests verifying the verbose output matches expectations.

This change builds on the safety controls (--force/--dry-run) added in previous iterations of the series, giving users more information while maintaining the same careful approach to file deletion. The verbose mode should help debug cases where directories persist due to ignored files, Windows file handles, or merge conflicts - common pain points the clean command aims to address.

The patch appears well-integrated with the existing code and follows Git's established patterns for verbose output options. It's a focused improvement that responds directly to reviewer feedback while maintaining the command's core functionality.
