This is a test patch (2/2 in the series) for the new `git refs list` subcommand, which is being introduced as a thin wrapper around `git for-each-ref`. The patch focuses on testing infrastructure, adapting existing `for-each-ref` tests to work with the new subcommand.

The key technical aspects are:
- Adds new test file `t/t1461-refs-list.sh` that runs the existing `t6300-for-each-ref.sh` tests but with `GIT_REFS_LIST_CMD` set to `refs list`
- Modifies `t6300-for-each-ref.sh` to use `${GIT_REFS_LIST_CMD:-for-each-ref}` throughout, making it work with either command
- Skips the `-h` help test for `refs list` since it would show the wrong usage
- Updates test descriptions to use the variable command name
- Adds the new test to `t/meson.build`

The patch demonstrates thorough test coverage by reusing all existing `for-each-ref` tests to verify identical behavior between the commands. It's part of an RFC series that has already addressed maintainer concerns about code duplication in v1, with Patrick Steinhardt and others mentoring the GSoC contributor Meet Soni. The testing approach validates that `refs list` maintains full compatibility with `for-each-ref` while establishing the new subcommand's position in the `git refs` hierarchy.
