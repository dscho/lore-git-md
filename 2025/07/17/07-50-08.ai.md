This is the first patch in a 2-part feature series introducing a new `git refs list` command as a wrapper around `git for-each-ref`. The patch implements the core functionality while addressing maintainer feedback from v1 by avoiding code duplication.

The implementation forwards all arguments to `cmd_for_each_ref` through a new `cmd_refs_list` function in `builtin/refs.c`, ensuring identical behavior. The patch includes significant documentation restructuring - extracting shared option descriptions into a new `refs-list-options.adoc` file that both commands now include, reducing duplication. The man pages for both commands are updated to reflect the new shared documentation approach.

Key technical details include:
- New `REFS_LIST_USAGE` constant defining the command syntax
- Modified `cmd_for_each_ref` to detect when called via `refs list` and adjust usage strings accordingly
- `cmd_refs_list` implementation that constructs argument array for `cmd_for_each_ref`
- Preservation of all existing `for-each-ref` functionality including `--include-root-refs`

The patch maintains the series' goal of reference command consolidation while addressing Junio Hamano's v1 concerns about code duplication. Performance considerations around ODB lookups (raised by Patrick Steinhardt) remain deferred for potential future optimization. Documentation standardization work continues with Jean-Noël Avila's input on shared option syntax.
