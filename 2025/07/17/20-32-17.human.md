This is a cover letter for an RFC patch series proposing to accelerate xdiff performance by 5-19% while introducing Rust as a hard dependency. The series represents the beginning of a larger effort to potentially convert all of xdiff to Rust.

The key points from Ezekiel Newren's proposal:
1. Performance improvements come from switching from DJB2a to xxhash for hashing (with parsing/hashing split into separate steps) and using memchr() optimizations.
2. The series currently fails some CI workflows - Windows builds don't work, and 32-bit tests fail due to platform-specific primitive size issues.
3. The larger question raised is whether Git is ready to accept Rust as a hard dependency, building on previous discussions at Git Merge 2024.

The 7-part series:
- Introduces Rust infrastructure
- Cleans up xdiff code to be more Rust-friendly
- Implements the hash algorithm changes
- Adds CI support for Rust

This is clearly a significant and potentially controversial change, as the author notes. The performance claims are substantial, but the Rust dependency and platform issues will need careful consideration. The patch appears well-structured with clear explanations of both the changes and open questions.

The RFC nature suggests the author is seeking feedback on both the technical approach and the broader Rust adoption question before proceeding further. This will likely spark significant discussion on the list about Git's future direction regarding Rust integration.
