This is a feature patch proposing a new `pull.autoStash` configuration option as part of the ongoing discussion about configuration validation and inheritance between Git commands.

Lidong Yan proposes adding a `pull.autoStash` option that mirrors the existing `rebase.autoStash` functionality but with clearer naming for pull operations. The patch implements this by:
1. Documentation in config/pull.adoc explaining the new option and its precedence over `rebase.autoStash`
2. Code changes in builtin/pull.c to check both config values, with `pull.autoStash` taking priority

The motivation is improved user experience - the current reliance on `rebase.autoStash` for pull operations isn't obvious from the naming. The implementation is straightforward and maintains backward compatibility while adding the more intuitive option.

This comes amid broader discussions about configuration validation and inheritance patterns in Git, where Junio Hamano has raised concerns about adding new config keys versus fixing the underlying architecture. The patch represents one approach to the immediate documentation/UX problem while the larger design questions continue to be debated.
