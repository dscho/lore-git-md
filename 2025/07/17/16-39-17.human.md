This is a follow-up in the Git for Windows certificate verification thread, confirming the root cause analysis.

Johannes Schindelin responds to Junio Luan Pereira's attempt to switch from WinSSL to OpenSSL as a workaround for the Norton Antivirus interference issue. He explains that Git for Windows maintains a deliberate design choice where `curl.exe` always uses WinSSL/Schannel regardless of the OpenSSL setting, due to technical constraints documented in PR #4410. This confirms why changing the CURL option in install-options.txt had no effect on the behavior.

The email serves as a technical clarification that reinforces the thread's key finding: the certificate verification failures stem from Norton's Safe Web" feature interfering with Schannel, and backend switching isn't a viable solution due to Git for Windows' architecture. The discussion remains focused on documenting the precise technical boundaries of the issue rather than proposing new fixes, as the two known workarounds (temporary curl flag or disabling Safe Web) remain the only effective solutions.
