This is a follow-up discussion about MemorySanitizer (MSan) issues in Git's test infrastructure, specifically around temporary file creation.

Jeff King responds to Kyle Lippincott's report of MSan warnings during `git add` operations, tracing back to uninitialized memory in `git_mkstemps_mode()`. The issue stems from random bytes generated by `csprng_bytes()` not being properly marked as initialized for MSan's purposes. Jeff notes this is a known challenge when mixing sanitized and non-sanitized libraries.

He suggests two approaches: either manually unpoisoning the memory (showing a sample patch to do so in `wrapper.c`), or the more thorough solution of building all dependencies with MSan support. While the manual fix would work, Jeff cautions it may not be sustainable long-term compared to properly MSan-enabled libraries.

The discussion is somewhat tangential to the main thread about `for-each-ref` pagination, showing how testing infrastructure issues often surface during feature development. Jeff confirms Karthik Nayak's earlier fix resolved the original MSan/valgrind issues in the pagination code. This exchange demonstrates Git maintainers' attention to toolchain and testing hygiene even when diagnosing edge cases.
