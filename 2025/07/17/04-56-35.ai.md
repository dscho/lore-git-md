This is part of Patrick Steinhardt's ongoing series to refactor object-file.c to eliminate `the_repository` dependencies, enabling pluggable object database support (the_repository removal category). 

The patch introduces `odb_write_object()` as a new backend-agnostic interface for writing objects into an object database. Currently it's implemented as a simple wrapper around the existing `write_object_file()` function, which is specific to the loose object format. The key changes are:

1. Adds new `odb_write_object()` and `odb_write_object_ext()` functions in odb.[ch] that accept an explicit `struct object_database` parameter
2. Updates 21 files (106 insertions, 67 deletions) to use the new interface instead of direct `write_object_file()` calls
3. Moves write-related constants from object-file.h to odb.h (renaming `WRITE_OBJECT_FILE_*` to `WRITE_OBJECT_*`)
4. Makes `write_object_file()` itself a thin wrapper that calls through to the new interface

The patch maintains identical behavior while providing the plumbing needed for future patches that will make the backend selection more flexible. The extensive call site updates demonstrate how widely used this object writing functionality is across Git's codebase. This is a foundational change in the series that doesn't yet implement pluggable backends but establishes the interface that will enable that work.

Technical details likely to be referenced in follow-ups include:
- The new `WRITE_OBJECT_PERSIST` and `WRITE_OBJECT_SILENT` flags
- The `odb_write_object_ext()` function signature with its `compat_oid` parameter
- The relationship between the new functions and the existing `write_object_file()` implementation
- The 21 affected files span core operations like commit creation, merge resolution, and cache management
