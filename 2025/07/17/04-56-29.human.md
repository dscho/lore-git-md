This is part of Patrick Steinhardt's ongoing series to remove `the_repository` dependencies from object-file.c, enabling pluggable object database support. Patch 3/16 focuses on `has_loose_object()` and related functions.

The patch changes `has_loose_object()` to operate on a single `odb_source` rather than checking all sources via `the_repository`. This is a semantic change - callers now need to explicitly loop through sources when they want to check all possible locations. The commit explains this as a step toward making the function more generic and format-aware in the future. As part of this change, `has_loose_object_nonlocal()` becomes obsolete and is removed.

The changes affect several call sites in builtin/pack-objects.c, which now need to explicitly iterate through object sources. The patch maintains the same behavior but with more explicit control flow. This continues the series' pattern of methodically removing global state while preserving functionality, though it does shift some complexity to callers.

The changes are well-contained (30 lines added, 17 removed across 3 files) and follow the established pattern of the series. The commit message clearly explains the rationale behind the semantic change, which helps reviewers understand this isn't just a mechanical refactor but part of a larger architectural direction.
