Merge conflict resolution for the `core.commentChar=auto` deprecation series. This email from Junio Hamano provides a merge-fix patch that resolves conflicts with Phillip Wood's recently approved config refactoring (which removed the `kvi->path` field). The fix updates the comment character configuration logic in `builtin/commit.c` to use `kvi->origin_type` and `kvi->filename` instead of the now-removed `path` field.

The changes are straightforward mechanical updates to match the new config API, replacing path checks with origin type checks and using `filename` where file-origin configs are involved. Junio notes this is a temporary resolution since the area will see more changes when the actual deprecation of `core.commentChar=auto` is implemented under `WITH_BREAKING_CHANGES`.

This is a clean, focused conflict resolution that maintains the behavior of both changesets while keeping the codebase buildable. The patch demonstrates good awareness of the intersecting changes and provides a clear path forward until the larger deprecation work lands.
