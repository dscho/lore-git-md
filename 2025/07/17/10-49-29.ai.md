This is part 9 of Patrick Steinhardt's ongoing series to remove implicit `the_repository` usage from config functions, continuing the mechanical conversion pattern established in previous patches. The patch removes the `git_config_get_int()` wrapper function and updates all callers to use `repo_config_get_int(the_repository, ...)` instead.

The changes touch 13 files across various subsystems, converting calls that read integer config values like credentialstore.locktimeoutms, pack.indexversion, gc.autopacklimit, maintenance settings, checkout.workers, and core.filesreflocktimeout. The patch follows the established pattern of making repository dependencies explicit while maintaining identical behavior, with a net reduction of 5 lines (removing the wrapper from config.h while adding repository parameters to calls).

Key config options affected include maintenance-related settings (gc.auto, maintenance.reflog-expire.auto), fetch/unpack limits, merge/diff configuration (merge.verbosity, diff.renamelimit), and parallel checkout thresholds. The commit notes this is a mechanical conversion that doesn't yet optimize call sites that already have repository handles available - those will be addressed in future work.

This continues the systematic elimination of `git_config_*` wrappers as part of the long-running `the_repository` removal effort, with 12 more patches planned in the series after this one.
