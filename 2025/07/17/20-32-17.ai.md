This is a cover letter for a major RFC series proposing to introduce Rust as a hard dependency while optimizing xdiff. The series claims 5-19% performance improvements through several changes: replacing DJB2a hashing with xxhash, separating parsing from hashing operations, and making xdiff's data structures more Rust-friendly. The work is positioned as the beginning of a potential larger effort to convert xdiff to Rust.

Key technical changes include:
- Adding Rust infrastructure (Cargo files, CI scripts)
- Refactoring xrecord_t and xdfile_t structures
- Introducing xxhash via Rust's implementation
- Platform-specific issues around primitive types (u32/u64 vs ambiguous C types)

The cover letter explicitly raises the fundamental question of whether Git is ready for a Rust dependency, noting this was discussed at Git Merge 2024 without resolution. Current blockers include Windows build failures and 32-bit test failures, with the author seeking input on handling platform-specific primitive types through the Rust FFI.

This appears to be a serious, well-considered proposal with measurable performance gains, though the Rust dependency would be controversial. The author acknowledges this is work-in-progress (some CI failures remain) and seeks community feedback on both the technical approach and the broader Rust question. The changes touch core diff algorithms but appear to maintain compatibility through careful refactoring.
