RFC series proposing Rust as hard dependency with xdiff optimizations (5-19% claimed perf gain), now at version 7/7 with CI integration complete. Series refactored xdiff internals through structural changes (line parsing/hashing separation in `xrecord_t` type changes to u32/u64, xxhash optimization showing 19% speedup in `git log --oneline --shortstat` when `XDF_WHITESPACE_FLAGS` unset). Final patch adds `build_rust.sh`, CI workflows, and Makefile/Meson integration.

Performance analysis from Phillip Wood shows 8% speedup from inlining whitespace flag check in `xdl_hash_record()` and 6% additional from XXH3_64bits in C, matching Rust performance (15% total), suggesting most gains come from hash algorithm choice rather than Rust. Junio Hamano questions XXH3 performance on non-SIMD architectures.

Platform discussions include Windows target considerations (`i686-win7-windows-gnu`/`x86_64-win7-windows-gnu` targets requiring Rust 1.78+), Windows build fixes addressing toolchain compatibility and critical `xrecord_t.ha`/`s_xdlclass.ha` type mismatch (u64 vs unsigned long) that would break `xdl_classify_record()` with 32-bit overflow. Licensing concerns raised.

Gentoo Rust support constraints detailed: no support for HPPA/Alpha/m68k, partial s390 (s390x only), and 32-bit issues (musl, i486, sparc32, riscv32). macOS/Solaris Prefix users lack Rust despite official macOS compatibility. Two systemic barriers identified: (1) Rust's LLVM dependence blocks architectures without LLVM (Alpha/HPPA), (2) 32-bit architectures face more limitations. GCC-rs mentioned as potential solution leveraging existing GCC backends.

Elijah Newren contextualizes Rust adoption as inevitable given project trajectory, citing sustained interest from new contributors and established developers. Proposes "L2 norm" approach favoring broad benefits over preserving all platforms, suggesting affected systems could use last C-only Git release until gccrs matures. Gentoo maintainers clarify their concerns are practical rather than ideological, highlighting bootstrapping problems and supply chain risks from 500+ transitive dependencies.

Brian Carlson provides operational experience from Git LFS about security maintenance challenges with Rust dependencies, advocating against checking in `Cargo.lock` to avoid becoming a magnet for security vulnerability reports. Junio Hamano validates these security maintenance concerns while keeping door open for future Rust adoption if ecosystem conditions improve.

New status update from Pierre-Emmanuel Patry on GCC-based Rust compiler efforts: progress on compiling Rust's libcore using Rust 1.49, with expectations to complete this work by end of summer but significant testing remains. Next target version would be Rust 1.78 to align with Rust-for-Linux requirements, though full compilation support for even the older 1.49 code is not expected until next year at best. The `rustc_codegen_gcc` project could help address Gentoo's platform support concerns for architectures not supported by LLVM.
