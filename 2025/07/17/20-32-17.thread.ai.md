Eli Schwartz provides detailed Gentoo Rust support constraints: no support for HPPA/Alpha/m68k, partial s390 (s390x only), and 32-bit issues (musl, i486, sparc32, riscv32). Notes macOS/Solaris Prefix users lack Rust despite official macOS compatibility. Identifies two systemic barriers: (1) Rust's LLVM dependence blocks architectures without LLVM (Alpha/HPPA), (2) 32-bit architectures face more limitations. Mentions GCC-rs as potential solution leveraging existing GCC backends. Gentoo's wd40 feature set currently handles Rust-dependent features through opt-out.

Elijah Newren contextualizes Rust adoption as inevitable given project trajectory, citing sustained interest from new contributors (xdiff series) and established developers (2023 contributor summit). Presents platform support as one competing need against security benefits (code audit findings) and performance improvements (xdiff speedups). Proposes "L2 norm" approach favoring broad benefits over preserving all platforms, suggesting affected systems could use last C-only Git release until gccrs matures. Links to prior Rust discussions, security audits, and benchmarks to support migration path.

Sam James from Gentoo responds to Newren, clarifying their position is not to block Rust but to ensure practical obstacles are properly considered. Highlights Gentoo-specific concerns: (1) Rust's platform support gaps for new architectures despite platform relevance, (2) bootstrapping problems leaving new platforms without any Git version, (3) backporting issues making old C-only versions impractical, and (4) supply chain risks from Rust crate dependencies. Emphasizes they're not opposing Rust adoption but want these issues addressed, countering Newren's perception of false dichotomies.

This contributes to the build system interactions debate but doesn't shift the broader platform support considerations.
