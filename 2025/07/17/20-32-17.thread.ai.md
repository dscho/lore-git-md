- Cleaner separation between parsing and line classification
- Maintains existing behavior while enabling future hash algorithm swaps

This structural change makes the code more modular and prepares for independent hash algorithm changes. The parsing/hashing separation could help isolate performance analysis of different hash implementations.

Performance analysis from Phillip Wood shows 8% speedup from inlining whitespace flag check in `xdl_hash_record()` and 6% additional from XXH3_64bits in C, matching Rust performance (15% total), suggesting most gains come from hash algorithm choice rather than Rust. Phillip Wood continues questioning the value of C-side type alignment, arguing that if Rust code will create safe wrappers or slices regardless, the type matching provides little benefit and introduces invasive casts in C code. He presents alternatives: implementing safe methods on FFI structs that handle conversions internally, or performing conversion once at interface boundary. While acknowledging `char` to `u8` conversion is harmless, he notes `long` to `usize`/`u64` changes require careful review but might benefit C code long-term.
