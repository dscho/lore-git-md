Maintainer feedback on test infrastructure for `git refs list`. Junio C Hamano responds to Meet Soni's test approach for the `git refs list` subcommand, which currently reuses `t6300-for-each-ref.sh` tests by overriding a variable. While acknowledging the intent, he suggests two improvements:

First, he proposes using a more readable variable name like `$git_for_each_ref` in the test files rather than the generic `GIT_REFS_LIST_CMD`, since the tests fundamentally remain about `for-each-ref` functionality. This would better document the relationship between the commands.

Second, he cautions against directly including `test-lib.sh` multiple times via the shared test file, noting potential idempotency risks. Instead, he references historical precedent (commit 8752d11d) where shared test logic was properly extracted into a separate file included by both test scripts, suggesting this as a more robust approach.

The feedback maintains the project's cautious stance on test maintenance while recognizing the wrapper command's goals. This appears to be a refinement rather than a rejection of the approach, focusing on long-term maintainability of the test suite as the `git refs` subcommand hierarchy evolves.
