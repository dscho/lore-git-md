This is part of Patrick Steinhardt's ongoing series to remove `the_repository` dependencies from object-file.c, enabling pluggable object database support. Patch 03/16 focuses on refactoring loose object existence checking.

The patch modifies `has_loose_object()` to operate on a single `odb_source` rather than implicitly checking all sources via `the_repository`. This changes the function's semantics - callers must now explicitly loop through sources when they want to check all possible locations. The change enables future generalization to `odb_source_has_object()` that can work with any object source type. As a side effect, this makes `has_loose_object_nonlocal()` obsolete, which is removed.

Key technical changes:
- `has_loose_object()` now takes an `odb_source` parameter
- Callers in `builtin/pack-objects.c` and `object-file.c` are updated to loop through sources
- The function now returns whether the object exists in the specific source rather than globally
- `has_loose_object_nonlocal()` is dropped as its functionality is covered by the new approach

This continues the series' pattern of methodically removing global state while maintaining functionality, though it does shift some complexity to callers who need to check multiple sources.
