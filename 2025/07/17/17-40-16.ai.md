Bugfix for Windows symlink regression in `git difftool --dir-diff`. Johannes Schindelin responds to Chris Conti's report about symlinks failing during directory diff operations in Git 2.49.0 on Windows, where a custom difftool alias that temporarily enables `core.symlinks` now fails with "Function not implemented" errors.

Schindelin identifies this as similar to GitHub issue #5517 and pinpoints commit 8241ae63d821 ("difftool: eliminate use of global variables") as the likely culprit, suggesting it inadvertently changed the symlink behavior default on Windows. The commit was part of a refactoring effort to remove global variables from difftool.c, and while not Windows-specific, appears to have affected symlink handling during the temporary file setup phase of directory diffs.

The response notes this is a regression from Git 2.48.1 where the same configuration worked correctly. Schindelin mentions being time-constrained on investigating the GitHub issue but provides the key reference point for further debugging. The technical context involves how `difftool --dir-diff` creates symlinks in temporary directories when comparing changed files, with the Windows implementation apparently broken by the global variable removal changes.

This appears to be a legitimate regression affecting Windows users who rely on symlink functionality during difftool operations, particularly those using custom aliases that temporarily enable symlinks. The response provides enough technical detail to understand the scope (limited to dir-diff operations) and points to the specific commit that introduced the behavior change, though doesn't yet propose a fix.
