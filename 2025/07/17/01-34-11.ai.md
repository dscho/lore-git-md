This is a feature patch adding verbose output to `git sparse-checkout clean` as part of the ongoing sparse-checkout improvements series.

The patch introduces a `--verbose` flag that shows individual files being removed (or would be removed with `--dry-run`), rather than just reporting directories. This addresses feedback requesting more visibility into the clean operation's effects. The implementation uses a new `list_every_file_in_dir()` helper that leverages the recently added `for_each_file_in_dir()` infrastructure to recursively traverse directories.

Key technical details:
- New `--verbose` option shows per-file operations while default remains directory-focused
- Uses `list_file_iterator` callback with `for_each_file_in_dir()` to traverse directories
- Maintains existing dry-run and force behavior while adding verbose output
- Updates documentation to explain the verbose mode's purpose
- Adds test cases verifying verbose output shows individual files

The change builds on previous work in the thread where output granularity was debated, with Junio Hamano suggesting showing kept directories by default and using --verbose for detailed removal information. This patch implements that compromise while maintaining all existing safety controls (force/dry-run flags and clean.requireForce config).

The implementation appears clean and focused, with appropriate test coverage added for the new verbose output. This addresses one of the remaining open items from the thread's discussion while keeping the command's core directory-focused optimization behavior intact.
