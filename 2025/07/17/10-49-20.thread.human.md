Patrick Steinhardt continues his systematic refactoring of Git's configuration handling as part of the broader effort to eliminate the `the_repository` global variable. This thread documents the eleventh patch in the series, which removes the `git_config_get_bool()` wrapper function in favor of explicit `repo_config_get_bool(the_repository, ...)` calls.

The change affects boolean configuration settings across 21 files, touching various subsystems including upload-archive, am (apply-mailbox), gc, and http. While the behavior remains identical, the patch makes the repository dependency explicit by requiring callers to pass `the_repository` rather than using the implicit global. This follows the established pattern from previous conversions in the series (referencing commit 036876a1067), where each patch methodically converts specific configuration functions while maintaining the existing behavior.

Phillip Wood has reviewed earlier patches in the series, providing feedback that was incorporated in version 2. The changes build cleanly and resolve cleanly with the 'seen' branch, demonstrating the disciplined approach that has made this series relatively uncontroversial despite its wide reach across the codebase. As with previous patches, this is an intermediate step - future work will optimize these calls by passing actual repository instances rather than always using the global `the_repository`.

The series continues to make steady progress in its goal of eliminating implicit repository dependencies from Git's configuration subsystem, improving code clarity while carefully maintaining existing behavior at each step.
