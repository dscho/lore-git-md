This thread follows Patrick Steinhardt's 21-patch series that refactors Git's config-related functionality as part of the broader effort to remove the `the_repository` global variable. The series systematically replaces `git_config_*()` wrapper functions with explicit `repo_config_*()` variants that take a repository parameter, making dependencies clearer at call sites.

The latest patch (6/21) removes the `git_config_get_string_multi()` wrapper, converting all call sites to use `repo_config_get_string_multi(the_repository, ...)` instead. This affects configuration handling in several areas including maintenance operations, log decoration filters, GC hooks, and version comparison. Like previous patches in the series, this is a mechanical conversion that maintains existing behavior while making repository dependencies explicit - optimizations for cases where a repository is already available at call sites are left for future work.
