This is part 13/16 of Patrick Steinhardt's ongoing series to remove `the_repository` dependencies from object-file.c, enabling pluggable object database support. The patch refactors two key loose object iteration functions to operate on `struct odb_source` rather than implicitly using the global repository state.

The main changes are:
1. Renaming `for_each_loose_file_in_objdir()` to `for_each_loose_file_in_source()` and making it take an `odb_source` parameter instead of a path
2. Modifying `for_each_loose_object()` to accept an explicit `object_database` parameter
3. Updating all callers across 10 files to use the new interfaces

The changes are mechanical but widespread, touching core commands like `git fsck`, `git gc`, and `git prune`. The patch continues the series' pattern of methodically removing global state while maintaining existing behavior. The modifications appear straightforward and well-contained, with no obvious functional changes beyond the intended refactoring.

This is another incremental step in the larger effort to make Git's object storage backend pluggable, building on previous patches that established the `odb_source` infrastructure. The changes here clean up the remaining loose object iteration paths to use the new interfaces consistently.
