Bugfix investigation for uninitialized memory in ref-cache iteration.

Jeff King (Peff) follows up on Kyle Lippincott's MemorySanitizer report about uninitialized memory access in `cache_ref_iterator_advance()`. He confirms the issue using valgrind on commit 4ea3c74afd (the merge of the `--start-after` pagination series), showing a clear stack trace where uninitialized values propagate through the files backend iteration path. The problem appears during test t6302-for-each-ref-filter.sh.

While Peff couldn't bisect further (the issue appears in the first commit introducing the test), his valgrind output provides a more accessible reproduction path than the original MSan report. The stack trace points to memory allocation in `cache_ref_iterator_begin()` propagating through the ref iteration chain, suggesting an initialization issue in the ref-cache interaction with the new seeking functionality.

This adds concrete debugging information to the ongoing discussion about iterator state management, though it's not yet clear if this relates to the semantic questions Junio raised about prefix persistence.
