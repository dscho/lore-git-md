This is part of Patrick Steinhardt's ongoing series to remove `the_repository` dependencies from object-file.c, specifically focusing on the object ID mapping system for repositories with compatibility hash algorithms. The patch refactors how loose object mappings are written to better reflect their backend-specific nature.

The key change moves the loose object map writing logic from operating on a repository to operating directly on an `odb_source`. This affects three main areas:
1. The `write_one_object()` helper now constructs paths using the source's path directly rather than via `repo_common_path_replace()`
2. The `repo_add_loose_object_map()` interface now takes a `struct odb_source` instead of `struct repository`
3. All call sites in object-file.c (`stream_loose_object()`, `write_object_file_flags()`, `force_object_loose()`) are updated to pass `the_repository->objects->sources` instead of `the_repository`

The changes maintain identical behavior while better reflecting the architectural reality that these mappings are inherently tied to specific object sources rather than being repository-wide. This continues the series' pattern of methodically removing implicit global dependencies while preparing for future pluggable backend support. The patch touches 3 files with 15 lines added and 11 removed, showing a focused scope within the larger refactoring effort.
