This RFC thread continues to debate the introduction of Rust infrastructure into Git's xdiff subsystem, now at version 3 of the patch series. While the technical implementation is largely settled—with the `ivec` interoperability type finalized and build system changes under review—the policy questions around platform support and transition timing remain contentious.

The latest exchange centers on Patrick Steinhardt's response to Brian Carlson's push for immediate Rust adoption. Steinhardt acknowledges Rust's demonstrated productivity benefits (like BTreeMap's advantages for loose object mapping) but proposes making Rust optional until Git 3.0 to allow build system iteration and platform maintainer preparation. This differs from Carlson's position that delaying adoption risks losing contributor momentum for features planned for Git 3.0. 

Key stakeholders have staked out positions: Taylor Blau sees Rust's security benefits outweighing portability reduction, while Junio Hamano expresses concerns about unsustainable dual maintenance. Randall Becker's NonStop platform remains a sticking point—it's a commercially maintained x86_64 system that would be excluded, despite its modern architecture, due to lacking Rust support. Gentoo's Sam James has formally endorsed Steinhardt's LTS transition plan targeting Git 3.0, citing parallels with past C99 transitions, while providing updated technical context on gccrs development.

The thread shows growing consensus around a Git 3.0 timeline for mandatory Rust adoption, with optional earlier use possible, though core questions remain about governance of the backporting model and whether the project can justify excluding platforms like NonStop. The technical work appears ready to proceed whenever the policy questions are resolved.
