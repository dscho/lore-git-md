This RFC thread continues to debate the technical and policy challenges of introducing Rust infrastructure into Git, specifically around the xdiff module. The core conflict remains between the security benefits of Rust adoption and the platform compatibility requirements, particularly for NonStop systems.

The latest development comes from Sam James (Gentoo), who provides a technical assessment that effectively closes the door on using mrustc as a compatibility solution. James explains that mrustc was never intended as a full Rust implementation - it's strictly a bootstrapping tool for rustc itself. This reinforces Randall Becker's earlier concerns about NonStop compatibility and eliminates what had been seen as a potential middle path.

With mrustc now ruled out, the discussion is moving toward more fundamental questions about Git's platform support policies. The technical implementation (including the ivec type in the new interop/ directory) remains ready, but the policy debate continues between:
1) Those prioritizing Rust's security benefits (Brian Carlson, Ezekiel Newren)
2) Those emphasizing broad platform support (Randall Becker, now with support from Sam James)

Junio Hamano continues reviewing the implementation details while this higher-level discussion plays out. The thread appears to be reaching a point where the project will need to make an explicit policy decision about whether Rust's advantages justify potentially dropping support for platforms that can't meet its toolchain requirements.
