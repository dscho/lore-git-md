The RFC series introducing Rust as a hard dependency with xdiff optimizations has reached its final version (17/17), completing the C-to-Rust transition for core diff operations. The changes deliver 5-19% performance gains by replacing key xdiff functions with Rust implementations while maintaining all functionality. Ezekiel Newren has driven the implementation, which now handles all whitespace flags and establishes zero-copy FFI patterns.

Platform compatibility remains a key discussion point. Following Ramsay Jones' Cygwin build failure report and Matthias Aßhauer's Windows target specifications, Junio Hamano has weighed in on Windows version support. He argues pragmatically that Git shouldn't maintain support for end-of-life Windows versions (8.1 reached EOL in 2023), suggesting clear documentation of any support changes would suffice. This reflects an ongoing tension between modernization and backward compatibility, particularly where Microsoft's own support policies create constraints.

Several open questions remain unresolved from earlier discussions, including performance impacts of specific optimizations, Rust code style guidelines, licensing policies, and supply chain considerations. While the technical implementation is now complete, these broader architectural and policy questions will need resolution before the changes can be considered for merging. The series shows the complex tradeoffs involved in introducing Rust to Git's core, where performance gains must be balanced against platform support and long-term maintainability concerns.
