This RFC series proposes making Rust a hard dependency for Git, focusing on xdiff optimizations that claim 5-19% performance gains. The current version (7/7) includes CI integration and refactors xdiff internals, particularly around line parsing and hashing. Performance analysis shows most gains come from hash algorithm choice (XXH3) rather than Rust itself, with Phillip Wood demonstrating comparable speedups in C. 

A key debate centers on type compatibility between C and Rust. Ezekiel Newren advocates for matching C-side types to Rust primitives (u8, usize) to simplify FFI boundaries, while Junio Hamano questions whether this sacrifices C idiomaticity for marginal benefit. Phillip Wood's latest contribution challenges whether this type alignment actually helps, noting that Rust code will likely convert the data to slices regardless, potentially making the C-side changes unnecessary. This raises questions about where type conversion complexity should live.

Platform support remains a major discussion point, with detailed analysis of constraints on Windows, Gentoo, and non-LLVM architectures. The timeline for GCC-based Rust compilation (gccrs) suggests a multi-year path to full platform coverage. Security concerns around dependency management have led to a proposed compromise on Cargo.lock handling.

The thread shows growing consensus that Rust adoption is inevitable for Git, but important questions remain about implementation strategy, particularly around FFI design choices and platform support tradeoffs. The discussion remains technical and constructive, with participants working to balance performance, maintainability, and broad compatibility.
