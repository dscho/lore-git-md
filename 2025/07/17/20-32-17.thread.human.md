This RFC thread explores making Rust a hard dependency in Git, focusing on performance gains from xdiff optimizations (5-19% claimed) while addressing platform compatibility concerns. The series, now at v7/7, refactors xdiff internals and integrates CI workflows, with performance analysis showing most gains come from hash algorithm choice (XXH3) rather than Rust itself. 

Key technical discussions include Windows build fixes for type mismatches, licensing concerns, and platform limitations - particularly for Gentoo (HPPA/Alpha/m68k unsupported) and NonStop systems. Patrick Steinhardt and Pierre-Emmanuel Patry have clarified timelines for GCC-based Rust compilation (gccrs), noting it would take over a year to support the required Rust 1.78 version for Windows targets. The latest email confirms that using rustc_codegen_gcc would primarily fall to distributors, reducing Git's implementation burden while still addressing non-LLVM platform needs.

Open questions remain around Windows target selection, dependency management, and build system interactions. The discussion has evolved to consider practical tradeoffs - with performance benefits weighed against multi-year timelines for full platform support and ongoing maintenance challenges like Rust's 500+ transitive dependencies. While technical solutions are emerging (like gccrs), the thread reflects broader project tension between modernization and maintaining wide platform compatibility.
