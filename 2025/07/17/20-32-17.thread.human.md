This RFC thread explores introducing Rust as a hard dependency in Git, initially motivated by Ezekiel Newren's work on `git replay` but now focused on xdiff optimizations showing 5-19% performance gains. The 17-patch series has stabilized technically, with Rust implementations handling line hashing and comparison through XXH3 hashing (the source of the speedups, not Rust itself). Key discussions revolve around balancing performance claims with architectural foundations, platform support policies, and documentation standards.

The latest exchange addresses Windows build configuration specifics. Matthias Aßhauer pointed out that the current Rust target specifications would inadvertently raise the minimum Windows version requirement from 8.1 to 10, suggesting alternative targets (`*-win7-windows-gnu`) to maintain backward compatibility. He also corrected an aarch64 target specification. Ezekiel has acknowledged these points and will incorporate the changes in the next version.

The thread has seen active participation from maintainers and domain experts. Junio Hamano and Elijah Newren have provided guidance on maintaining architectural coherence while adopting Rust optimizations. Platform support remains a key concern, with Ramsay Jones tracking Cygwin compatibility issues and Johannes Schindelin weighing in on Git for Windows policies. Documentation standards are being established, including corrections to policy file references. While code style (rustfmt defaults) has reached consensus, version requirements, performance contextualization, and architectural adjustments remain open for discussion as the series moves toward potential integration.
