This RFC thread explores introducing Rust as a hard dependency for Git, specifically targeting xdiff optimizations that show 5-19% performance gains in certain cases. The series, now at version 7/7, has completed CI integration and includes structural refactoring of xdiff internals, type system changes for Rust compatibility, and a conditional Rust-based xxhash implementation when whitespace flags are disabled.

Junio Hamano has been actively engaged, praising the preparatory refactoring patches while questioning performance attribution. He clarifies this isn't a full xdiff replacement in Rust - the current scope only introduces Rust for specific hash optimizations. Technical discussions have coalesced around type system changes (u8/uint8_t vs char) and error handling regressions identified by Phillip Wood, who also raised important concerns about maintaining xdiff as a standalone C library for consumers like libgit2 and Vim.

The latest response, Junio acknowledges the xxhash optimization as a good proof of concept but notes it's not yet ready for upstreaming. He identifies a key gap - the need for a whitespace-aware variant of xxhash to handle all diff modes - while reinforcing ecosystem concerns about third-party consumers needing to maintain C implementations. This maintains the project's cautious approach to Rust integration while leaving the door open for future optimizations. The thread now balances measurable performance gains against technical debt considerations and library compatibility, with several open items around build failures, version policy, and NonStop platform concerns still needing resolution.
