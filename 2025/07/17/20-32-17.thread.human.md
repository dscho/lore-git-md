This RFC thread proposes making Rust a hard dependency for Git, primarily to enable xdiff optimizations that show 5-19% performance gains. The series is now at version 7/7 with CI integration complete, having methodically refactored xdiff internals and added build system support. Key participants include Patrick Steinhardt (advocating for Rust adoption), Phillip Wood (who demonstrated most performance gains come from hash algorithm choice rather than Rust itself), and Johannes Schindelin (addressing Windows-specific concerns).

Recent discussion has shifted to platform compatibility challenges. Eli Schwartz provided a detailed breakdown of Gentoo's Rust compiler limitations, showing no support for HPPA/Alpha/m68k architectures and partial support for others. This adds concrete data to earlier concerns raised by Randall S. Becker about NonStop support. The core tension remains between performance improvements and platform support tradeoffs, with Schwartz's email highlighting how Rust's LLVM dependency creates systemic constraints for certain architectures.

Open questions include: whether to proceed given these platform limitations, how to handle Windows target selection, licensing alignment for the Rust xdiff code, and version policy documentation. While performance improvements are measurable, the architectural constraints - particularly for 32-bit systems and LLVM-incompatible platforms - present a significant hurdle that the proposal must address. Junio Hamano has acknowledged that some optimizations (like the whitespace flag check) could be valuable independently of Rust adoption.
