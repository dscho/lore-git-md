This RFC thread explores making Rust a hard dependency in Git, focusing on performance optimizations in the xdiff subsystem. The series, now at version 7/7, demonstrates 5-19% speedups by refactoring xdiff internals with Rust, particularly through line parsing/hashing separation and XXH3 hash optimizations. While Phillip Wood's analysis shows most gains come from hash algorithm choice rather than Rust itself, Ezekiel Newren counters with concrete FFI examples where type alignment enables zero-copy interop benefits.

A key tension has emerged between optimizing for zero-copy interop (requiring C-side type changes to match Rust primitives) versus maintaining idiomatic C code. Phillip Wood questions the value of invasive C type changes when Rust will convert data anyway, suggesting either handling conversions at the interface boundary or implementing safe wrapper methods. Meanwhile, platform support concerns persist, with Windows toolchain fixes and Gentoo constraints documented, though Elijah Newren argues Rust adoption is inevitable for the project's future.

The thread has reached consensus on dependency management (adding Cargo.lock to .gitignore while preserving it in CI), but open questions remain about Windows targets, whitespace-handling performance tradeoffs, and whether the demonstrated zero-copy benefits justify the C code changes. The discussion remains technical and constructive, with participants like Junio Hamano and Phillip Wood probing the design while acknowledging the long-term trajectory toward Rust integration.
