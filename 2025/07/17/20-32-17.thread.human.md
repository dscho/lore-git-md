This RFC series proposes making Rust a hard dependency for Git, with initial focus on xdiff optimizations showing 5-19% performance gains. The discussion has evolved through seven versions, with CI integration now complete and key technical issues addressed (Windows build fixes, type consistency problems, and performance attribution showing most gains come from hash algorithm choice rather than Rust itself).

The thread has surfaced significant concerns from distribution maintainers, particularly Gentoo's Sam James and Eli Schwartz, about Rust's limited platform coverage (missing HPPA/Alpha/m68k support) and bootstrapping challenges. New data shows Rust pulls 500+ transitive dependencies, raising supply chain concerns. Patrick Steinhardt's latest response acknowledges these issues while maintaining support for Rust adoption if solutions can be found - suggesting possible delays if alternative implementations like gccrs could help, and emphasizing Git's traditional conservatism around dependencies.

Key open questions remain around Windows target selection, licensing alignment, and how to balance Rust's benefits against platform support limitations. The discussion has moved from pure technical implementation to weighing broader ecosystem impacts, with Junio Hamano and other maintainers now having concrete data about the tradeoffs involved. The thread shows the project grappling with whether Rust's performance and security benefits justify potentially leaving some platforms behind or accepting new supply chain risks.
