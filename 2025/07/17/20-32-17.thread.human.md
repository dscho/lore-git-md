This RFC thread about introducing Rust infrastructure for xdiff has reached a critical juncture, with the technical implementation now complete but facing significant platform compatibility concerns. Ezekiel Newren has confirmed that the changes will make Rust a mandatory dependency, directly impacting platforms like NonStop that lack Rust support.

The latest email from Randall Becker escalates the debate by strongly objecting to this requirement, calling it "disappointing and exclusionary" for NonStop users. He provides concrete numbers (tens of thousands of affected users) and details about HPE's uncertain Rust support timeline, directly contradicting claims in the proposed platform policy about Rust's interoperability. This moves the discussion beyond technical implementation into clear policy conflict.

While Johannes Schindelen's technical concerns about hash alignment have been resolved, the core Rust implementation is ready, and build system changes are under review, the series remains blocked on this platform support question. Becker's email frames the choice starkly: either maintain NonStop compatibility or accept that these users will lose Git access. With Kristoffer Haugsbakk advocating for existing platform policies and Ramsay Jones monitoring Cygwin precedents, the thread now clearly needs PLC input to resolve this governance-level decision about how to balance modernization against backward compatibility.
