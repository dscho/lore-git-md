This RFC thread explores making Rust a hard dependency for Git to enable xdiff optimizations that claim 5-19% performance gains. The series has evolved through seven versions, with CI integration now complete. Phillip Wood's detailed performance analysis revealed that most gains come from hash algorithm choices (switching to XXH3) and hot-path optimizations rather than Rust itself - achieving 15% speedup in C. This finding, acknowledged by Junio Hamano, raises questions about whether introducing Rust is justified when similar improvements appear possible without it.

The discussion has expanded to platform compatibility concerns, particularly for Windows (Matthias Aßhauer and Johannes Schindelin contributed build fixes) and less common architectures. Licensing questions around the Rust xdiff code remain unresolved, with Schindelin advocating for proactive alignment while Wood prefers maintaining current GPL/LGPL structures. Distribution maintainers have raised practical concerns about Rust deployment across various platforms.

Key open questions center on whether the Rust implementation provides unique benefits beyond what C optimizations can achieve, especially on platforms without optimized XXH3 implementations. The thread remains technically focused, with Junio's latest response reinforcing Wood's findings while keeping the performance discussion architecture-aware. The series appears to be at a decision point - whether to proceed with Rust integration or pursue the demonstrated C optimizations independently.
