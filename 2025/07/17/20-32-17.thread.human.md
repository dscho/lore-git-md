This RFC thread proposes making Rust a hard dependency for Git, focusing on performance gains from xdiff optimizations (5-19% claimed). The series is now at v7/7 with CI integration complete, featuring structural changes to xdiff internals and XXH3 hash optimizations. Phillip Wood's analysis shows most gains come from hash algorithm choice rather than Rust itself, with comparable speedups achievable in C (15% total).

Key technical discussions include platform-specific considerations: Matthias Aßhauer outlined Windows target requirements, Johannes Schindelin fixed critical type mismatches and raised licensing concerns, while Eli Schwartz detailed Gentoo's Rust support constraints across various platforms. Elijah Newren framed Rust adoption as inevitable given security and performance benefits, proposing to prioritize broad benefits over preserving all platforms.

The thread took a significant turn when Brian Carlson shared operational experience from Git LFS about the security maintenance burden of Rust dependencies, strongly advising against checking in `Cargo.lock` to avoid vulnerability report noise. Junio Hamano has now validated these concerns, agreeing that Git's long-term stability needs outweigh immediate build reproducibility benefits. While keeping the door open for future Rust adoption, the maintainer emphasizes caution until the Rust ecosystem better supports system-level software requirements.

Open questions remain around Windows targets, type consistency fixes, licensing, dependency management policies, and platform support tradeoffs - particularly for NonStop and niche architectures. The discussion has evolved from technical implementation to broader ecosystem considerations, with security maintenance emerging as a critical factor in the decision-making process.
