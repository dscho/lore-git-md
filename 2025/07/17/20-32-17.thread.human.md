This RFC thread continues to debate the timeline and policy implications of introducing Rust infrastructure to Git's xdiff subsystem, with the technical implementation remaining stable but the transition plan facing scrutiny. 

Junio Hamano has weighed in with concerns about the proposed timeline, particularly questioning whether a 6-month optional period provides sufficient notice before making Rust mandatory, and suggesting an 18-month security update window rather than the proposed 3 years. This reflects his focus on platform maintainers' needs, particularly for NonStop and Cygwin systems that may struggle with Rust support.

Elijah Newren's latest contribution shifts the discussion to what constitutes adequate notice, pointing to existing public communications (LWN articles, release notes) about Rust adoption while acknowledging these may still fall short. He distinguishes between user-facing breaking changes (which warrant deprecation periods) and implementation changes like Rust adoption that don't directly affect workflows. Newren also questions whether extending the transition period would actually resolve open questions about security fix backporting, suggesting these will remain case-by-case decisions regardless.

The thread now centers on balancing competing priorities: the desire to move forward with Rust adoption (championed by Phillip Wood, Patrick Steinhardt and Newren) against concerns about adequate notice and platform support (voiced by Hamano and Randall Becker). While the technical implementation appears settled, the policy discussion needs resolution around transition timelines, notice requirements, and backporting policies before the RFC can proceed.
