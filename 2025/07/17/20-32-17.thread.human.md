This RFC thread proposes making Rust a hard dependency in Git, primarily for memory safety and performance gains in the xdiff subsystem. The series is now at version 2/17, with significant discussion around technical tradeoffs and platform support.

The core proposal refactors xdiff internals with Rust optimizations, showing 5-19% performance improvements in certain operations. Key contributors have debated the balance between zero-copy interop (via type alignment) and maintaining idiomatic C code, with Phillip Wood and Ezekiel Newren presenting competing approaches. Performance analysis reveals tradeoffs - Rust's xxhash shows speed benefits in default modes but struggles with whitespace handling compared to C's byte-by-byte processing.

Platform support remains a challenge, with Windows compatibility patches from Johannes Schindelin addressing toolchain issues, while Gentoo maintainers highlight bootstrapping problems on niche architectures. The thread has reached consensus on excluding Cargo.lock from version control while preserving dependency auditing through CI.

The new documentation patch establishes Git's Rust adoption policy, providing rationale based on memory safety and setting technical guidelines. It ties version support to Debian stable and acknowledges platform constraints discussed in the thread. This document serves as a foundation for the ongoing technical discussions about implementation details and tradeoffs.

Open questions remain about Windows target selection, type consistency approaches, and how to handle the performance tradeoffs in whitespace handling modes. The discussion continues to balance the benefits of Rust adoption against the project's commitment to broad platform support and stable maintenance.
