This RFC thread explores making Rust a hard dependency for Git to enable performance optimizations in xdiff (the diff engine), with measured speedups of 5-19% in certain cases. The series, now at version 7/7, has evolved from xhistogram improvements to focus on Rust-based hash functions while keeping most xdiff in C. Key technical work includes structural refactoring of xdiff internals, type system alignment between C and Rust, and xxhash optimizations that show particular promise when whitespace flags are disabled.

The discussion has revealed significant technical and policy challenges. Johannes Schindelin has just contributed Windows build fixes addressing toolchain compatibility issues, demonstrating progress on cross-platform support. However, broader concerns remain unresolved: distribution maintainers like Eli Schwartz (Gentoo) and Haelwenn Monnier highlight practical deployment obstacles, particularly for architectures lacking Rust support (HPPA/Alpha/m68k) and the auditability concerns around precompiled binaries. The technical consensus favors type system alignment for Rust interoperability, but Phillip Wood has identified several specific issues in the xdiff implementation that need addressing, particularly around error handling and external library compatibility.

Junio Hamano has acknowledged the series' value while cautioning that performance gains may stem more from algorithm changes than Rust itself. He's also emphasized that there's no consensus to fully replace xdiff's C implementation. The thread has surfaced policy questions about minimum Rust version requirements, dependency management (including whether to include Cargo.lock), and build system choices, with some suggesting meson as an alternative to cargo. These issues may ultimately require input from the Project Leadership Committee. While the technical work shows promise, the path forward remains uncertain due to the significant ecosystem implications of making Rust mandatory.
