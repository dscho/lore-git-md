This RFC thread about introducing Rust infrastructure to Git's xdiff implementation has reached a critical juncture. The technical implementation is largely settled, with Rust modules complete and build system changes under review. The debate has shifted from whether to adopt Rust to how and when, with Patrick Steinhardt advocating for a gradual transition path where Rust remains optional until Git 3.0.

Key technical decisions include using a custom `ivec` type for C/Rust interop (after ruling out Rust's native `Vec` due to version instability) and identifying `varint.c` as a potential test case - though Junio Hamano now suggests the more substantial `patch-delta.c` might be better. The community has coalesced around Steinhardt's LTS transition plan, which has gained formal support from Gentoo's Sam James, though Brian Carlson argues for faster adoption to maintain momentum.

Platform support remains the biggest sticking point. NonStop (Randall Becker) and Cygwin (Ramsay Jones) would be effectively excluded, with Jones already unable to build Git on Cygwin due to Rust unavailability. While some like Taylor Blau see this as an acceptable tradeoff for Rust's safety benefits, Junio continues to question the long-term maintenance implications and whether vendors will step up to support their platforms.

The thread shows growing consensus on implementation mechanics but unresolved tensions around timing and governance. Steinhardt's latest proposal to use small test balloons like `varint.c` or `patch-delta.c` offers a path forward that could validate technical assumptions while keeping policy options open. With Gentoo endorsing a 2026 timeline aligned with gccrs stabilization, the debate now centers on whether to proceed sooner (as Carlson advocates) or maintain a more cautious pace to accommodate distributor realities.
