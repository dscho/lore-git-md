This RFC thread proposes making Rust a hard dependency for Git, focusing initially on optimizing the xdiff subsystem with claimed performance gains of 5-19%. The series, now at version 9/17, has evolved to address platform compatibility concerns while maintaining the core goal of zero-copy interop between C and Rust.

The technical work centers around refactoring xdiff internals - separating line parsing from hashing, optimizing with xxhash, and carefully aligning C/Rust types for efficient FFI. Performance analysis from Phillip Wood suggests most gains come from the hash algorithm choice rather than Rust itself, with some limitations around whitespace handling. The discussion has surfaced architectural questions about whether to modify C types for zero-copy interop (Ezekiel Newren's position) or handle conversions in Rust wrappers (Phillip Wood's alternative approach).

Platform support has been a major focus, with recent patches completing Windows coverage for both GCC-compatible and MSVC toolchains. The latest patch adds linking against Windows' `userenv` library to support Rust's home directory handling, following earlier work on CI integration and build system changes. While Gentoo and other niche platforms remain constrained by Rust toolchain availability, there's growing consensus around prioritizing broadly beneficial changes even if some platforms require follow-up work.

Key open questions include:
- The ongoing debate about type alignment strategies
- Performance tradeoffs in whitespace handling
- Licensing and supply chain considerations
- Finalizing Rust code style guidelines

Junio Hamano has raised important questions about XXH3 performance on non-SIMD architectures and the necessity of the C-side type changes, indicating these areas may need further discussion before the series can progress. The thread remains active with contributors working through both technical and architectural concerns.
