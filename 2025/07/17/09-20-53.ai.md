Performance optimization follow-up discussing implementation details of the prio_queue_replace() functionality in René Scharfe's priority queue series. This email explores an alternative approach to the heap maintenance optimization from patch 2/3, proposing to make the sift-down operation lazy by tracking pending work with a new `sift_down_root_pending` flag.

The key technical proposal is to defer the sift-down operation after `prio_queue_get()` until the next queue access (either `peek` or `put`), which would maintain heap invariants while avoiding immediate rebalancing. The patch shows this implemented through:
- New `sift_down_root_pending` flag in struct prio_queue
- Modified `prio_queue_get()` to set the flag instead of sifting
- Updated `prio_queue_put()` and `prio_queue_peek()` to check and clear the flag
- Extracted `sift_down_root()` helper now called from multiple locations

Scharfe notes this would keep .nr and .array consistent for direct access patterns while optimizing the common get+put sequence. He questions whether this automatic approach might be preferable to the explicit prio_queue_replace() from the original patch, though acknowledges potential risks from direct prio_queue internals access in some callers (citing examples from commit-reach.c and negotiator/skipping.c).

The email also surfaces broader questions about the negotiator/skipping.c implementation's linear search pattern, suggesting alternative approaches using object flags or commit slabs might be more efficient. This appears to be a tangent from the main optimization work but indicates Scharfe's thorough review of related code paths.

This proposal represents a significant implementation shift from the original patch's explicit replace operation to an implicit lazy-evaluation model. While maintaining the same big-O characteristics, it could provide cleaner integration at the cost of more complex state tracking. The thread context shows previous consensus around the explicit approach, so this email may reopen design discussion just as the series appeared ready for merging.
