This is a test infrastructure patch in the ongoing `git refs list` wrapper effort. Junio C Hamano provides review feedback on the test implementation approach for the new subcommand's compatibility testing with `git for-each-ref`.

The key technical concern raised is about the test structure - specifically the double-inclusion of `test-lib.sh` when sourcing `t6300-for-each-ref.sh` from the new `t1461-refs-list.sh`. Junio suggests this could cause subtle future breakage since test-lib.sh inclusion isn't guaranteed to remain idempotent. He proposes two alternative approaches: using a variable like `$git_for_each_ref` that could be overridden, or following the historical pattern from blame/annotate tests where shared test logic was moved to a separate file included by both test scripts.

The review also notes the current implementation's bias toward `refs list` is understandable but makes the test less readable since the original test suite was designed around `for-each-ref`. The suggested variable approach would make it clearer that this is testing substitutability while keeping the test code focused on its original subject.

This feedback indicates the test infrastructure design needs refinement before the series can proceed, with maintainer preference leaning toward established patterns for command substitution testing rather than the current environment variable approach. The comment about historical precedent (git-blame/git-annotate test sharing) provides a concrete model to follow.
