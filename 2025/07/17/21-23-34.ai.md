This is a discussion about CI integration for the Rust dependency series, specifically focusing on Rust version policy and build flags. The email is part of the ongoing RFC series proposing Rust as a hard dependency with xdiff optimizations (currently at patch 7/7).

Brian m. carlson raises two key points about the CI setup. First, they suggest aligning the Rust version policy with Debian stable's toolchain (1.63.0) plus one year of support, rather than using the latest version (1.87.0 as shown in the patch). This is motivated by maintainer concerns about forcing distros to constantly update their toolchains, given Rust's rapid 6-week release cycle. They leave open the possibility of revisiting this if Rust introduces LTS releases.

Second, they question the need for custom RUSTFLAGS in the build script (-Aunused_imports, -C debuginfo=2 etc.), noting that default options work fine in their other projects. They also suggest future CI enhancements: running cargo tests and adding a clippy lint job that checks against both the minimum supported version and latest stable Rust.

The discussion touches on important practical considerations for the Rust integration - version support policy impacts downstream packagers, while build flags and test coverage affect maintenance burden. These points come from someone with Rust experience (referencing personal and work projects), adding weight to the concerns. The thread context shows this is the final patch in a series that has already addressed core technical challenges but still has open questions around platform support and mandatory dependency concerns.
