This is a feature patch series introducing a new `git sparse-checkout clean` command, building on ongoing work to improve sparse-checkout performance and refactor away from `the_repository` global state.

The series adds a command to remove tracked-but-sparse directories that remain outside the sparse-checkout scope, which can cause performance issues with the sparse index. The command specifically targets cone mode sparse-checkouts and handles cases where directories persist due to .gitignore rules or filesystem locks. Version 2 adds a --verbose option and better handling of merge/rebase conflicts.

Key technical details:
- Operates on in-memory sparse index state regardless of `index.sparse` setting
- Preserves directories with staged changes or merge conflicts
- Uses same --force/--dry-run options as `git clean` for safety
- Adds new `for_each_file_in_dir()` helper for verbose output
- Includes extensive tests for edge cases like merge conflicts

The series is well-motivated by real-world performance issues users encountered, and builds on previous advice warnings about sparse index expansion. The implementation appears thorough, with careful consideration of edge cases and safety mechanisms. The documentation and tests are comprehensive, though some design decisions around output granularity and ignored file handling remain open for discussion.

This represents both immediate performance improvement and long-term architectural progress, though it needs to be rebased on recent `the_repository` refactoring changes before integration. The series is currently blocked on that rebase while design discussions continue about the optimal user interface.
