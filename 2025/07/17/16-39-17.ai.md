This is a follow-up in the Git for Windows certificate verification thread, confirming technical details about the SSL backend behavior. Johannes Schindelin explains that despite the "Curl option" being set in Git for Windows' install-options.txt, the curl.exe program will always use WinSSL/Schannel due to a deliberate design choice in Git for Windows to avoid OpenSSL dependencies (referencing PR #4410). This confirms Junio Luan Pereira's observation that switching to OpenSSL in the installer options doesn't actually change the backend being used, as evidenced by the curl --version output showing Schannel support.

The email reinforces the thread's key finding that the root issue lies with Norton Antivirus's "Safe Web" feature interfering with certificate verification, not with Git or its SSL backend selection. The technical details about Git for Windows' forced Schannel usage and the underlying architectural reasons provide important context for understanding why the workarounds (disabling Norton Safe Web or using --ssl-revoke-best-effort) remain the only viable solutions. This serves as a definitive clarification about Git for Windows' SSL backend behavior that future contributors may need to reference.
