This is part of Patrick Steinhardt's ongoing series to remove `the_repository` dependencies from object-file.c, enabling pluggable object database support. Patch 13/16 refactors the loose object iterators to eliminate their reliance on the global repository state.

The patch modifies two key iterator functions:
- `for_each_loose_file_in_objdir()` is renamed to `for_each_loose_file_in_source()` and now takes an `odb_source` parameter instead of a path
- `for_each_loose_object()` now requires an explicit `object_database` parameter

The changes propagate through 10 call sites across various builtin commands (cat-file, count-objects, fsck, gc, pack-objects, prune) and utility functions (prune-packed, reachable). Each caller is updated to pass the appropriate object database context from `the_repository->objects` rather than relying on implicit global state.

This continues the series' pattern of methodically converting global dependencies to explicit parameter passing while maintaining identical functionality. The changes are mechanical but important for the loose object iteration subsystem's independence from the global repository context. The patch follows the established approach seen in previous patches of the series, with straightforward updates to callers and no behavioral changes.
