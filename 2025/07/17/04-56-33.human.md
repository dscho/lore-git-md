Refactoring patch in the ongoing `the_repository` removal series. This is patch 7/16 in v2 of Patrick Steinhardt's effort to eliminate global repository dependencies from object-file.c.

The patch modifies `finalize_object_file()` and related functions to accept an explicit `struct repository` parameter instead of implicitly using `the_repository`. The change is straightforward - the function primarily handles file permissions and collision checking when moving temporary files into their final object locations, so it needs repository context for permission handling but not full ODB access.

The change touches 11 files with mechanical updates to call sites. The commit message clearly explains why passing a repository (rather than an object database) is the right level of abstraction here. This continues the series' pattern of methodically removing global state while maintaining existing behavior.

The patch appears well-contained and follows the established pattern from earlier patches in the series. It doesn't introduce new functionality but makes another incremental step toward the goal of pluggable object databases by removing another subtle dependency on global state.
