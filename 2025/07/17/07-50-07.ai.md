This is a feature patch series proposing ref command consolidation under `git refs list` as a wrapper for `git for-each-ref`. The v2 version significantly redesigns the implementation based on maintainer feedback, moving from a code-duplicating approach to a thin wrapper that calls `for-each-ref` directly. This addresses earlier concerns about maintenance overhead while preserving the goal of command consolidation.

Key technical changes in v2 include refactoring the shared documentation into a standalone `refs-list-options.adoc` file included by both commands' man pages, ensuring consistency. The test suite now runs existing `for-each-ref` tests through the new command via environment variable substitution, avoiding test duplication. The implementation in `builtin/refs.c` is now minimal, simply forwarding arguments to the existing `cmd_for_each_ref` function.

The series maintains its original motivation of improving discoverability through command hierarchy while addressing performance concerns raised in the thread. Notably, it preserves the ability to reconsider default behaviors (like format strings) in the future while currently maintaining strict compatibility. The documentation improvements standardize option syntax across related commands, with shared options now maintained in a single location.

This version appears more maintainer-friendly by eliminating code duplication concerns while still establishing the `git refs` namespace infrastructure. The approach suggests future direction where new ref-related functionality could be added under this hierarchy while legacy commands remain unchanged. Performance optimizations (like reducing default ODB lookups) could potentially be implemented here without disrupting existing `for-each-ref` users.
