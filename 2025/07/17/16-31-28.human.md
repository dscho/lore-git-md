This is a discussion about the `--extended` output format for the new `git last-modified` command, part of the feature series implementing tree-level path modification tracking.

Toon Claes responds to Junio Hamano's detailed feedback about the proposed extended output format documentation. The format aims to provide structured metadata about commits that last modified each path, with special handling for message indentation and delimiters. Junio identified several issues with the current proposal, particularly around message termination detection and future extensibility when adding new multi-line fields.

The key concerns raised are:
1. Unclear documentation about how message boundaries are detected in the extended format
2. Potential parsing ambiguity when future multi-line fields are added
3. Inconsistency in delimiter usage (mixing NUL and LF) in `-z` mode
4. Compatibility questions with `git-cat-file` output format

Toon acknowledges these are valid concerns and indicates the extended format implementation may need to be reworked or possibly dropped from the initial series, as the core single-line output format is sufficient for their immediate needs. This suggests the extended format discussion may continue in future iterations of the feature.

The exchange shows careful consideration of the interface design, particularly around output format stability and future extensibility - important qualities for a new plumbing command. The discussion remains productive, with Toon receptive to the feedback and considering simplifying the initial implementation.
