This is a policy discussion thread about Rust integration, specifically regarding whether to include `Cargo.lock` in the Git repository. Junio Hamano concurs with brian m. carlson's earlier position against checking in `Cargo.lock`, citing the file's auto-generated nature (as noted in its own header comment) and version compatibility challenges. The key concern is that pinned dependencies in `Cargo.lock` would create maintenance headaches when supporting both older distro toolchains (Debian stable policy) and newer Rust versions with security updates. This aligns with the broader version policy discussion from earlier in the thread, where brian m. carlson advocated for a Debian-aligned Rust version support window rather than always tracking latest. The exchange shows consensus forming around excluding `Cargo.lock` as part of the Rust integration strategy, though the final policy documentation (referenced earlier in the thread) will need to formalize this decision. This is one of several open policy questions remaining in the Rust dependency proposal, alongside version support windows and platform compatibility concerns.
