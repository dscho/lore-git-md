Test patch documenting `sparse-checkout clean` behavior with merge conflicts.

This is part 7/8 of Derrick Stolee's series combining Victoria Dye's `sparse-checkout clean` feature with the ongoing `the_repository` refactoring. The patch adds test coverage for how the clean command handles merge conflicts, documenting current behavior before planned changes.

The test creates a merge conflict scenario where:
1. A file exists in conflicting versions on different branches
2. After a failed merge, the file remains present despite being outside the sparse checkout
3. The test confirms `sparse-checkout clean` currently doesn't remove such files due to SKIP_WORKTREE bit not being cleared by the merge
4. Shows `reapply` can later remove the directory as expected

This is a well-constructed test that:
- Realistic merge conflict scenario setup
- Clear documentation of current limitations
- Verification of both clean and reapply behaviors
- Follows the pattern of earlier tests in the series

The test helps ensure future changes to conflict handling won't regress expected behavior. It's part of the broader effort to make sparse-checkout operations more robust in edge cases.
