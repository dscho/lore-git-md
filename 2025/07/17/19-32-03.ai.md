- Junio previously suggested removing `rebase.autostash` inheritance entirely
- Ben argues this would break the conceptual model of `pull` as fetch+operation
- Notes the current inconsistency where `merge.autostash` isn't respected while `rebase.autostash` is
- The discussion touches on backward compatibility concerns and whether changes should wait for Git 3.0

This email represents a middle position in the thread - while not proposing new code, it reinforces the conceptual argument for operation-specific configuration inheritance, which differs from Junio's earlier position of wanting to remove such inheritance entirely.
