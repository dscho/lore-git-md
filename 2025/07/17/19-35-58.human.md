Memory safety fix for ref-cache iterator during seeking operations.

Kyle Lippincott reports MemorySanitizer warnings in the ref-cache iteration code when using `--start-after` in `git for-each-ref`. Jeff King confirms the issue via valgrind, showing uninitialized memory access during ref iteration. The problem occurs when seeking without setting a prefix, where the `prefix_state` field remains uninitialized in newly created level entries.

Karthik Nayak provides the authoritative analysis and fix, explaining that the ref-cache iteration uses a stack-like structure for directories. When seeking without a prefix (as needed for pagination), the correct default state should be `PREFIX_CONTAINS_DIR` (0) since we want to include all references in the directory. This differs from Kyle's initial tentative fix using `PREFIX_EXCLUDES_DIR`. The root directory case is handled separately with its state set elsewhere.

The fix is minimal one-line change initializing `prefix_state` in `cache_ref_iterator_seek()`. This resolves the memory safety issue while maintaining correct behavior for both pagination and prefix filtering use cases. The discussion also surfaces unrelated MemorySanitizer warnings in object-file.c during test setup, which appear to be pre-existing issues.

This exchange demonstrates careful debugging and review of a subtle memory safety issue in the ref-cache subsystem, with the fix now clearly explained and verified. The pagination functionality in `for-each-ref` remains safe to use with this correction.
