This is a technical discussion about FFI type handling in the ongoing Rust integration series. Brian m. carlson responds to Taylor Blau's question about whether type adaptation for Rust interoperability should happen on the C or Rust side of the FFI boundary.

The exchange clarifies that Rust's type system naturally prefers fixed-size types (like u8, u64) over system-dependent types (like C's long), which helps avoid platform-specific issues. Brian argues that moving to Rust-friendly types on the C side (as done in this patch) has advantages: it keeps system-dependent quirks in C while letting Rust code be more portable, and may help remove xdiff's 2GB diff size restriction in the future. However, they remain open to doing the casting on the Rust side if that's the consensus.

This is part of the broader technical groundwork being laid in patches 1-4 of the series to prepare xdiff internals for eventual Rust migration. The discussion shows careful consideration of both immediate FFI needs and long-term code health, with Brian providing context about Rust's type system benefits that may not be obvious to C-focused contributors. The tone remains collaborative despite differing initial expectations about where type adaptation should occur.
