This is a feature patch introducing the `git sparse-checkout clean` command, part of a series combining performance improvements with `the_repository` refactoring. 

The new subcommand removes tracked-but-sparse directories that remain on disk after sparse-checkout definition changes, which can otherwise cause performance degradation with the sparse index feature. It specifically targets cone mode sparse-checkouts and handles several edge cases: preserving directories with staged changes or merge conflicts, while removing others (including their ignored/excluded contents). The implementation uses an in-memory sparse index to identify deletable directories.

The patch adds basic functionality without safety warnings (marked as temporary), documentation of the new subcommand, and initial test coverage. It builds on previous work removing `the_repository` usage in sparse-checkout.c. The command operates independently of the `index.sparse` config setting.

This appears to be a technically sound addition that addresses a real performance pain point for sparse-checkout users. The implementation shows careful consideration of edge cases, though the current lack of safety controls (to be added in follow-up patches) means reviewers will want to scrutinize the interaction with staged changes and merge conflicts. The test cases demonstrate core functionality but will likely expand as safety features are added.
