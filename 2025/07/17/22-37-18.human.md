This is a follow-up discussion about the `--extended` output format in the `git last-modified` feature series. Junio C Hamano points out several issues with the current test implementation for the extended output format.

The test hardcodes specific SHA-1 hashes and commit metadata, which would break when run with SHA-256 repositories (which will become the default in Git 3.0). Junio also notes an inconsistency in how the test displays object names - showing tree objects with their full hash but not doing the same for commits.

This continues the thread's ongoing discussion about the extended format implementation, where Junio had previously raised concerns about using `pretty_print_commit()` for this purpose. The test case shown appears to validate the current implementation, but Junio's comments suggest it may not be robust enough for production use, particularly as Git transitions to SHA-256 by default.

The feedback indicates that either the test needs to be made more flexible (to handle different hash algorithms) or the extended format feature may need to be reworked or deferred as previously discussed in the thread. This is likely one of the final issues to resolve before the series can be merged.
