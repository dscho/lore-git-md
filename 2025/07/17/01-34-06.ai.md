This is a feature patch series introducing a new `git sparse-checkout clean` command, building on both the ongoing `the_repository` refactoring work and Victoria Dye's sparse-checkout improvements. The series addresses performance issues in cone mode by removing tracked-but-sparse directories outside the sparse-checkout scope.

The key technical aspects of the new command include:
- Operates only in cone mode with sparse index enabled (SPARSE_INDEX_MEMORY_ONLY)
- Removes S_ISSPARSEDIR entries that exist on disk but shouldn't
- Preserves directories with staged changes via sparse index mechanics
- Treats .gitignore and .git/info/exclude files identically
- Uses in-memory sparse index to identify deletable directories
- Now confirmed to work regardless of `index.sparse` setting
- Present-despite-skipped checks prevent collapsing directories with any tracked files
- May need pairing with `git sparse-checkout reapply` for full performance restoration

The series has evolved through discussion, with V2 adding:
- --verbose option showing full removal details
- New for_each_file_in_dir() helper in dir.h
- Expanded test coverage for merge/rebase conflict scenarios
- Better handling of staged changes (must be committed first)
- Rebasing on top of 2c5b556 (removing sparse_expect_files_outside_of_patterns global)

The implementation carefully navigates several edge cases:
- Merge/rebase conflicts are handled safely via sparse index behavior
- Staged changes block directory removal until committed
- Untracked directories outside sparse directories remain untouched
- Safety controls mirror git clean's --force and --dry-run options

The series represents both immediate performance improvement (clearing cruft that slows sparse index) and long-term architectural progress (removing the_repository usage). Current discussion focuses on output granularity (default vs --verbose) and safety controls, with Stolee defending the directory-level approach while open to feedback. The implementation appears thorough, with expanded test coverage addressing earlier concerns about edge case handling.
