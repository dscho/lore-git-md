Performance patch in the Rust xdiff optimization series, introducing xxhash for faster hashing. This is part 6/7 of Ezekiel Newren's series to make Rust a hard dependency while improving xdiff performance. The patch conditionally uses Rust's xxhash implementation (via FFI) when no whitespace flags are present, falling back to the existing DJB2a algorithm otherwise.

Benchmarks show modest speedups (5-19% faster) for `git log --oneline --shortstat` across three different machines, with the most significant gains on an 8-core desktop. The implementation adds the xxhash dependency to Rust's Cargo.toml and exposes a simple FFI wrapper for the hash function. The core change is in xprepare.c where it routes hash computation through either the new Rust function or the legacy path based on whitespace flags.

This represents the first measurable performance improvement in the series, though the gains are smaller than the 5-19% range previously claimed (likely requiring the full series). The patch maintains functional compatibility while introducing the first Rust-accelerated code path. It follows the series' methodical approach, building on earlier structural changes to xdiff's preparation code.

The change is technically sound but continues the series' controversial aspects: it makes Rust mandatory (via the new xxhash-rust dependency) and assumes platform support for Rust FFI that some maintainers have questioned. The performance improvement, while measurable, may not yet be compelling enough to overcome those concerns for skeptical reviewers.
