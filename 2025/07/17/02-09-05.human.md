Bugfix addressing a signed/unsigned integer conversion issue in the ref-cache iterator.

Jeff King spots a potentially problematic `int` cast in Karthik Nayak's ref iterator seek implementation. While the current behavior is technically safe (the value gets cast back to `size_t` when used in `strncmp()`), the code could produce incorrect results for extremely long refnames (over 4GB) and sets a bad example for future code. The proposed fix simply changes the `len` variable from `int` to `size_t` to properly match the string length type used throughout Git.

This is a minor but correct change to code that was recently added as part of the `--start-after` pagination feature. While not directly related to the memory safety issue discussed elsewhere in the thread, it shows ongoing scrutiny of the ref iteration code paths. The change is straightforward and unlikely to be controversial.
