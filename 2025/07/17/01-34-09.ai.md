This is a patch in the `the_repository` removal effort and part of the `git sparse-checkout clean` feature series. The patch adds safety controls to the new `clean` subcommand, mirroring behavior from `git clean` by requiring `--force` or `--dry-run` unless `clean.requireForce` is disabled.

The key technical changes include:
- Adding `--force` and `--dry-run` options with corresponding config `clean.requireForce`
- Implementing safety check that prevents execution without force/dry-run
- Adding dry-run output showing "Would remove" instead of actually deleting
- Updating documentation to explain the safety requirements
- Expanding test coverage to verify force/dry-run behavior and config option

The patch builds on previous work by:
- Maintaining the core sparse directory removal logic from earlier patches
- Preserving the sparse index integration and staged change handling
- Adding new test cases that verify behavior with merge conflicts and staged changes
- Following the repository parameter pattern established in the `the_repository` removal work

Notable implementation details:
- Uses `repo_config_get_bool()` to read `clean.requireforce` config
- Maintains separate message strings for actual vs dry-run removal
- Preserves the existing directory scanning and removal logic
- Adds comprehensive tests for all new safety features
- Documents the behavior alongside existing sparse-checkout documentation

The changes address safety concerns raised in earlier discussion while maintaining the command's core functionality. The patch fits into the larger series by completing the safety controls before finalizing the documentation and output behavior decisions.
