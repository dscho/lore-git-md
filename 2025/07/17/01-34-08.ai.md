This is a feature patch introducing the `git sparse-checkout clean` command, part of Derrick Stolee's ongoing work to optimize sparse-checkout performance while also removing `the_repository` global variable usage.

The patch adds a new subcommand that removes tracked-but-sparse directories outside the current sparse-checkout scope, which is needed when directories remain on disk despite being excluded (due to open handles, ignored files, etc.). This helps maintain sparse index performance by preventing index expansion. The implementation:
- Requires cone mode sparse-checkout
- Uses an in-memory sparse index (SPARSE_INDEX_MEMORY_ONLY) to identify deletable directories
- Preserves directories with staged changes or merge conflicts
- Currently lacks safety controls (to be added in follow-up patches)
- Includes basic tests showing directory removal and staged change preservation

Key technical details:
- New sparse_checkout_clean() function in builtin/sparse-checkout.c
- Uses remove_dir_recursively() for actual deletion
- Checks S_ISSPARSEDIR flag in index entries
- Skips non-directories and directories that don't exist on disk
- Prints removal messages using msg_remove string
- Fails if not in sparse-checkout or cone mode
- Requires clean index state (fails with merge conflicts)

The patch builds on previous work removing sparse_expect_files_outside_of_patterns global (commit 2c5b5565) and is part of a larger series addressing both performance optimization and architectural cleanup. The current implementation is intentionally minimal, with safety features like dry-run and force flags planned for follow-up patches. Test cases verify basic functionality and staged change handling, though merge conflict scenarios remain to be addressed.
