Feature patch adding JSON output format to `git status` with `--json` flag, now receiving initial review feedback.

Phillip Wood raises several technical concerns about the implementation's robustness in handling edge cases. The key issues identified are: (1) improper handling of filenames containing newlines or double quotes, (2) assumption of UTF-8 encoding for filenames, (3) generation of trailing commas in JSON arrays (which violates the JSON spec), and (4) lack of accompanying tests. He suggests using the existing `json-writer.h` infrastructure to address most of these issues, though notes it wouldn't solve the filename encoding problem. The reviewer also asks for clarification about what specific problems the author encounters when parsing the existing `--porcelain` output formats, suggesting the motivation for this new format needs stronger justification. The implementation currently adds JSON formatting functions in `wt-status.c` and exposes the `--json` flag through both `git status` and `git commit` commands, but appears to need significant refinement to meet Git's robustness standards.
