This is the foundational patch for the new `git last-modified` command, implementing the core functionality to track tree-level path modifications. The patch introduces:

1. A new builtin command with `-r` (recursive) and `-t` (include tree entries) options, following `git diff-tree` path handling
2. Core algorithm that walks history backwards to find when paths last matched their final state
3. Hashmap-based tracking of paths and their target OIDs
4. Basic output format showing commit hash and path
5. Comprehensive test suite covering:
   - Basic file and directory cases
   - Recursive vs non-recursive behavior
   - Subdirectory handling
   - Merge scenarios (including conflict resolution)
   - Revision range limiting
   - Error cases

The implementation uses a callback-based diff approach to track path changes, with special handling for merge commits. The command is marked as EXPERIMENTAL in its documentation, with behavior subject to change. Test coverage is thorough, including edge cases around merges and path resolution.

Key technical details for future reference:
- Uses `last_modified_entry` struct with hashmap lookups
- Implements `mark_path()` helper for change detection
- Handles both content and metadata changes (modes, types)
- Follows `git diff-tree` path conventions
- Output format matches `git blame` style (hash + path)
- Test suite in `t/t8020-last-modified.sh` covers 19 scenarios
