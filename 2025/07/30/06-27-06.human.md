Feature: JSON output format for `git status`

This patch introduces a new `--json` flag to `git status` that outputs repository state in a structured JSON format. The implementation provides machine-readable output including branch information (current branch, detached state, ahead/behind counts), staged files, unstaged files, untracked files, and (with `--ignored`) ignored files.

The change adds a new `STATUS_FORMAT_JSON` enum value and implements JSON formatting helpers in `wt-status.c` to handle arrays and branch information. The output structure is designed to be easily parseable while allowing for future extensibility. The patch also updates `git commit` to support the same JSON output format when showing status.

The motivation appears to be providing a more robust alternative to parsing Git's traditional output formats for tooling and automation. The implementation looks thorough, with clear separation of concerns between the JSON formatting logic and the existing status reporting infrastructure. The example output in the commit message demonstrates a clean, straightforward JSON structure that should be easy for tools to consume.

This is a standalone feature addition that doesn't appear to conflict with any ongoing efforts. The patch touches only the status reporting code paths and maintains compatibility with existing formats. The change could be particularly useful for developers building Git integrations or automation tools that currently rely on parsing porcelain output.
