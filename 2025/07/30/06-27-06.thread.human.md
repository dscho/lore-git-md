This thread introduces a new `--json` output format for `git status`, providing machine-readable status information in a structured JSON format. The patch adds a `STATUS_FORMAT_JSON` enum and implements JSON formatting in `wt-status.c`, with output including branch information (current branch, detached state, ahead/behind counts) and arrays for staged, unstaged, untracked, and ignored files (when using `--ignored`).

The implementation introduces new functions `wt_json_print_string_array` and `wt_json_print_change_array` to handle the formatting, and carefully matches the porcelain v2 format's classification of changes. The JSON structure is designed to be both easily parseable and extensible for future needs. The change touches both `builtin/commit.c` (to expose the flag in both `git status` and `git commit`) and the core status formatting code in `wt-status.c`.

This feature fills a gap for tooling that needs reliable machine-readable status information, providing a more robust alternative to parsing the existing human-readable or porcelain formats. The initial implementation appears thorough, with a clear output structure and good documentation in the commit message, including example output.
