Bugfix targeting git-gui's askpass helper resolution, specifically addressing macOS compatibility issues but introducing potential RUNTIME_PREFIX problems.

Johannes Sixt identifies a regression in the patch that propagates git's exec-path for askpass resolution. The core issue is that the hardcoded exec-path breaks builds with RUNTIME_PREFIX, where the build-time path may not exist at runtime. The patch attempts to fix macOS-specific problems with system-provided askpass helpers but creates new portability issues.

Key technical concerns raised:
1. The exec-path resolution occurs too early in git-gui.sh, before the `git` proc is available, though the current implementation handles this correctly
2. Error handling uses `error` rather than the project's typical `puts stderr` pattern and lacks an explicit exit
3. The change affects the about dialog display, which while consistent, wasn't the primary focus

The feedback suggests the patch needs:
- Proper RUNTIME_PREFIX handling
- Consistent error reporting style
- Explicit process termination on failure
- Verification of behavior across different build configurations

This follows up on the broader git-gui modernization series' goal of fixing cross-platform askpass handling, but reveals edge cases in the implementation that need addressing before the change can be considered complete. The interaction highlights the tension between macOS-specific fixes and general build system portability requirements.
