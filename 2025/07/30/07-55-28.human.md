This is a discussion about DWIM (Do What I Mean) behavior in `git reflog` subcommands, following up on the recently merged reflog infrastructure series. Karthik Nayak and Junio Hamano are examining the current behavior where some reflog subcommands (`drop`, `delete`, `expire`) use DWIM resolution for refnames while the new `write` subcommand requires fully-qualified names.

The key points are:
1. Junio considers the DWIM behavior in existing subcommands to be a bug, as `git reflog` is more plumbing-like and should be explicit
2. Karthik notes the current DWIM implementation uses `repo_dwim_log()` with standard ref resolution rules and ambiguity checking
3. Both agree that consistency across subcommands is important, whether that means removing DWIM entirely or adding it to the new `write` subcommand
4. Documentation would need to clearly indicate the resolution behavior

This discussion represents a follow-up to the design decision in the reflog series where DWIM was deliberately excluded from the new `write` subcommand. The thread suggests there may be room to reconsider this choice for consistency, though Junio's position leans toward plumbing-like explicitness.
