This is a feature patch in a series about improving `-h` and `--help-all` behavior across Git commands. The email is a follow-up to Junio C Hamano's review of patch 3/4, which handles `--help-all` outside repository contexts.

D. Ben Knoble explains their earlier unsuccessful attempt to make commands call `parse_options` early (before repository setup) to handle `--help-all`, which proved messy. The current approach (special-casing `--help-all` in `git.c`) works better and has Junio's approval as "obvious and straight-forward". The author notes they'll drop the confusing explanation about the abandoned approach in future versions.

This patch appears to be on solid ground technically, with Junio's positive review and the author's willingness to clarify the commit message. It's part of a larger effort where the more controversial aspects (like argument-tolerant `-h`) are being debated separately in patch 4.
