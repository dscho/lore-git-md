Performance optimization patch for the `git last-modified` command series, implementing Bloom filter integration to avoid unnecessary diff computations.

This final patch in the v6 series adds Bloom filter optimization to the `last-modified` command, building on the core algorithm established in earlier patches. The implementation checks changed-path Bloom filters before computing diffs, skipping the diff when the filter indicates no possible changes to tracked paths. Key technical details include:

- New `bloom_key` field in `last_modified_entry` struct to store path hashes
- `maybe_changed_path()` helper that checks Bloom filters for all tracked paths
- Proper cleanup of Bloom keys via `bloom_key_clear()` in both the main release and path removal paths
- Integration with the commit-graph system via `prepare_commit_graph()`
- Bloom filter settings retrieved from repository config

Performance results show significant improvements for focused checks (50.6% faster for top-level, 36.4% for subdirectory) while recursive checks see minimal change (0.4% improvement). The implementation handles all necessary memory management and maintains the series' focus on forge-style use cases. This completes the core optimization work for the feature, though the performance test suite shows room for further improvement in recursive scenarios.
