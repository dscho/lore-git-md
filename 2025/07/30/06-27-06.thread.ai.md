Thread identity: Feature patch adding JSON output format to `git status` with `--json` flag, providing machine-readable status information in a structured format.

Core problem or goal: Enable reliable machine parsing of Git status by providing a well-defined output format that complements existing porcelain formats, avoiding the need to parse human-readable or porcelain output.

Current status: Initial version implementing JSON output format for `git status` and `git commit` commands. Output includes branch information (current branch, detached state, ahead/behind counts) and arrays for staged, unstaged, untracked, and ignored files (with `--ignored` flag).

Key technical details:
- New `STATUS_FORMAT_JSON` enum value in status reporting
- JSON formatting implemented in `wt-status.c` with helper functions `wt_json_print_string_array` and `wt_json_print_change_array`
- Output structure designed for parsing and future extensibility
- Matches porcelain v2's change classification (WT_STATUS_UPDATED for staged, WT_STATUS_CHANGED for unstaged)
- Changes in `builtin/commit.c` to expose flag in both `git status` and `git commit`

Open questions and loose ends: None raised yet in initial patch.

Participant positions: Initial patch from author only at this stage.

Related work: Builds on existing porcelain format work, particularly porcelain v2 classification scheme.
