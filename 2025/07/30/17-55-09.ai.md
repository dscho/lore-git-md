This is a refactoring patch that exports the `prepare_commit_graph()` function as part of the `git last-modified` series. The change makes the previously static function available to other parts of Git, specifically to support Bloom filter usage before revision walks.

The patch moves the function declaration from commit-graph.c to commit-graph.h and removes its static qualifier, keeping the same implementation. The commit message explains this enables Bloom key usage prior to `prepare_revision_walk()`, which will be leveraged in a follow-up commit for the `last-modified` command's performance optimizations.

The change is straightforward with minimal risk - it simply exposes an existing internal function that was already well-contained and documented behavior. The patch maintains the function's documentation in the header file, preserving its contract of returning 1 if the graph is loaded and 0 otherwise, with lazy loading on first invocation.

This appears to be a necessary plumbing change to support the Bloom filter optimizations in the larger series, following the pattern of other exported commit-graph functions like `parse_commit_graph()`. The implementation remains identical, just with broader visibility.
