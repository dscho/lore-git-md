Feature: New `git last-modified` command for tracking tree-level path modifications

This is the foundational patch in the v6 series introducing the new `git last-modified` subcommand, which tracks when paths in a tree were last modified (as opposed to line-by-line blame). The command is marked as EXPERIMENTAL in its documentation.

The implementation walks backwards through history to find when each path in a tree last changed to its current state, with options for recursive traversal (`-r`) and including tree entries themselves (`-t`). The core logic uses a hashmap to track paths of interest, then examines diffs between commits to determine modification points. The patch includes comprehensive tests covering basic functionality, edge cases like merges and conflicts, and path handling behaviors.

Key technical aspects:
- New `builtin/last-modified.c` implementing the core command
- Documentation in `git-last-modified.adoc`
- 200+ lines of test coverage in `t/t8020-last-modified.sh`
- Follows `git diff-tree` conventions for path handling
- Uses revision walking infrastructure with boundary commits
- Handles both file and tree entries

The implementation appears solid with thorough test coverage, though being marked experimental suggests there may be future refinements. This addresses a clear use case distinct from `git blame` by operating at tree level rather than line level. The patch builds on prior work from Jeff King and Ævar Arnfjörð Bjarmason, with Toon Claes as the primary implementer.
