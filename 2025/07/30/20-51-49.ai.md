This is a response in the ongoing git-gui platform support thread, addressing fundamental architectural questions about Tcl/Tk handling on macOS. Carlo Arenas clarifies the relationship between Tcl/Tk and macOS in response to Junio Hamano's questioning of the series' core premise.

- Current git-gui Makefile prioritizes finding system Tcl/Tk, which creates compatibility issues

The response emphasizes that the core issue isn't about user upgrades (which are possible) but about git-gui's automatic detection behavior favoring an incompatible system version. This directly addresses Junio's question about whether Tcl/Tk should be treated as a system component versus a third-party dependency.

The email doesn't resolve the architectural question but provides important context about macOS's Tcl/Tk integration that will be crucial for deciding the series should proceed.
