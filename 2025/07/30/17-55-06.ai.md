Feature implementation cover letter for the `git last-modified` command series, now at v6. This version consolidates the implementation after extensive discussion and benchmarking, focusing on core functionality while deferring some optimizations and features to future series.

The command tracks tree-level path modifications (distinct from line-by-line `git blame`), primarily targeting forge-style tree views that show when files were last changed. Key changes in v6 include: removing the controversial `--format` option patches (now deferred), exporting `prepare_commit_graph()` for Bloom filter integration, and simplifying the callback architecture by moving all logic into the builtin. The implementation now uses a direct approach rather than the library-style separation from earlier versions.

Performance characteristics remain mixed - while top-level checks show 55% speedup, some scenarios still exhibit slowdowns (44% in recursive checks). The series includes comprehensive tests (`t8020-last-modified.sh`) and performance benchmarks (`p8020-last-modified.sh`), with subdirectory test selection improved via `git ls-tree -d` instead of grep/cut. Bloom filter integration is now properly synchronized with the evolving API.

Open questions from previous versions about code organization (builtin vs subsystem) appear resolved by the monolithic builtin approach, though some architectural details like callback structure and error messages were refined. SHA-256 compatibility issues identified in v5 are addressed by dropping problematic test implementations rather than forcing a solution. The cover letter explicitly credits prior work from GitHub's implementation while explaining the delta in approach.

Notable technical changes include removal of the `last_modified_callback` indirection, consolidation of path emission logic into `last_modified_emit()`, and proper Bloom filter cleanup via `bloom_key_clear()`. The implementation now spans about 300 lines of core logic with thorough test coverage, positioned as a focused solution for the forge view use case while leaving room for future optimizations like caching and depth limiting.
