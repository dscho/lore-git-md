This is a response in the ongoing feature patch series about expanding `-h` and `--help-all` behavior in Git commands. The email addresses Junio C Hamano's security concerns about allowing `-h` to work mid-command.

D. Ben Knoble clarifies their position on the controversial final patch (4/4) that would enable `-h` to work with additional arguments. While maintaining they're open to dropping it, they push back slightly on Junio's characterization - noting the patch isn't encouraging `git rebase new-base -h` but rather `git rebase -h new-base`. They confirm `grep -h` still works as expected (grepping rather than showing help) unlike `rebase -h`.

The key technical point is that the current behavior differs between commands - some like `rebase` show help with `-h` plus arguments while others like `grep` don't. Junio had suggested making `-h` only work as a sole argument and erroring otherwise, which D. Ben Knoble notes is partially implemented (`argc == 2` check) but declines to implement the error case if the patch is dropped.

The discussion reveals deeper security concerns about aliases - appending `-h` to arbitrary aliased commands could be dangerous if the alias points to destructive operations. This appears to be part of a broader discussion happening elsewhere. The exchange suggests this final patch is likely to proceed in its current form, with Junio favoring a more conservative approach to `-h` behavior.
