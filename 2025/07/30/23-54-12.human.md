This is a technical discussion in the ongoing git-gui modernization series, specifically addressing macOS Tcl/Tk integration issues. Carlo Arenas responds to Johannes Sixt's questions about the patch series' motivations and implementation details.

Carlo clarifies that the macOS "Git Gui.app" bundle has been broken for multiple reasons over time, not just due to Tcl 8.6 requirements. He explains the system Tcl/Tk framework has caused problems since macOS 11, with Homebrew users already bypassing it by tricking the build system. The recent meson changes further broke the App bundle generation, making removal the proposed solution.

Regarding RUNTIME_PREFIX concerns, Carlo acknowledges the issue with the current askpass implementation and suggests Mark Levedahl's alternative approach (using Tcl's argv0 resolution) might be better. He also provides testing notes for the askpass helper, including environment variable requirements and Windows-specific considerations.

The email reveals deeper context about the macOS Tcl/Tk situation - it's a system-integrated Framework that's outdated (version 8.5) but difficult to replace cleanly. The discussion highlights the tension between treating Tcl/Tk as an immutable system component versus a managed dependency, which remains unresolved. Carlo's response provides important macOS-specific details but doesn't fully address the architectural questions raised earlier in the thread.
