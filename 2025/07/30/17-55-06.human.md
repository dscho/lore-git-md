Cover letter for the `git last-modified` command series (v6).

This is the sixth iteration of a feature introducing a new `git last-modified` command that tracks tree-level path modifications, distinct from line-by-line `git blame`. The command is designed to support forge-style views showing when files were last changed, with output similar to GitHub's tree view.

Key changes in v6:
- Drops the controversial `--format` option patches from v5, focusing on core functionality
- Further consolidates the implementation by removing callback remnants and moving to direct output
- Updates Bloom filter integration to use the new `prepare_commit_graph()` API
- Improves subdirectory selection in performance tests using `git ls-tree -d`

The series now consists of 4 patches:
1. Core command implementation
2. Performance test suite
3. Commit-graph API export needed for Bloom filters
4. Bloom filter optimization

Notable characteristics:
- Non-recursive by default (-r flag for recursion)
- Uses Bloom filters for optimization when available
- Comprehensive test coverage including performance benchmarks
- Shows 55% speedup for top-level checks but some mixed results in other scenarios

The implementation has evolved significantly from GitHub's original `blame-tree` version, with name changes, architectural simplifications, and performance optimizations. The author has deferred several features (caching layer, max-depth option) to keep this initial version focused.

The series appears well-tested and documented, with performance characteristics clearly measured. The v6 changes address several technical concerns raised in previous reviews while maintaining the core functionality. The remaining open questions appear to be around test methodology refinements rather than fundamental design issues.
