This is a follow-up discussion in the git-gui macOS modernization series, focusing on the fundamental justification for removing the deprecated Tcl/Tk 8.5 support. Junio Hamano raises a key architectural question about whether Tcl/Tk is truly a system component on macOS that can't be upgraded, or if it should be treated like any other third-party dependency that users can update independently of the OS.

The email challenges the series' core premise by noting that if users can upgrade Git (a third-party tool), they should equally be able to upgrade Tcl/Tk. This directly questions whether the macOS bundle removal is solving a real technical constraint or just shifting the dependency management burden. The implication is that the series may need stronger justification for its approach if Tcl/Tk isn't actually a fixed system component.

This intervention from the Git maintainer suggests the series may need to revisit its foundational assumptions before proceeding. The thread's previously identified technical issues (RUNTIME_PREFIX breakage, Meson compatibility) now have an additional high-level concern about the very motivation for the changes. The discussion appears to be shifting from implementation details to first principles.
