This is a discussion about config precedence in the ongoing `the_repository` removal effort, specifically regarding the `fmt-merge-msg` command's handling of deprecated config options.

Phillip Wood responds to Ayush Chandekar's patch that changed how `merge.log` and `merge.summary` config options interact. The key issue is that Chandekar's implementation gave precedence to `merge.log` (the non-deprecated option) regardless of config file order, while the original behavior respected the "last one wins" rule of config parsing.

Wood makes a clear distinction between deprecation and behavior change - even though `merge.summary` is marked for future removal, its current functionality must remain unchanged until that removal actually happens. This maintains backward compatibility for users who might still be using the deprecated option.

The exchange highlights an important principle in Git's development: deprecation warnings don't justify breaking existing behavior. The thread shows the careful consideration needed when refactoring config handling code, especially when touching deprecated-but-still-supported features. This discussion will likely influence how similar cases are handled in the broader `the_repository` removal effort.
