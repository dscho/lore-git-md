This is a response in the ongoing discussion about git-gui's macOS support and Tcl/Tk dependency handling. Carlo Arenas clarifies the architectural question raised by Junio Hamano about whether Tcl/Tk should be treated as a system component or updatable dependency on macOS.

The key points are:
1. Tcl/Tk is indeed more ingrained in macOS as a system Framework, though it's been unmaintained for years and shows deprecation warnings.
2. Git, by contrast, is installed separately as part of development tools.
3. The current issue isn't about users upgrading Tcl/Tk (which they can do), but about git-gui's Makefile preferentially using the system Tcl/Tk even when it's incompatible.

This response doesn't directly address the technical implementation issues from earlier in the thread, but provides important context about macOS's Tcl/Tk integration that could help shape the architectural direction of the series. The tone suggests the author sees the system Tcl/Tk usage as problematic now that git-gui has moved beyond compatibility with that version.
