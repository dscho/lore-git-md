Follow-up patch in final review for pull.autoStash configuration. This is the implementation patch for a previously discussed configuration hierarchy in Git's pull command, adding `pull.autoStash` as a new top-level option that overrides the existing `rebase.autoStash` and `merge.autoStash` settings when set.

Junio Hamano has completed a detailed review of the patch, confirming the technical soundness while requesting some refinements. The main changes needed are:

1. Documentation needs to be moved to a more appropriate section in pull.adoc (before the `pull.octopus` description) and rewritten to be more precise about when autostash is actually needed (primarily for rebase operations, since merges can often handle dirty worktrees when changes don't conflict).

2. Test cases should be reorganized to combine some redundant scenarios and add a few more edge cases, particularly around command-line flag interactions with the new config.

The patch already has comprehensive test coverage and implements the agreed precedence rules: command-line flags > `pull.autoStash` > operation-specific configs. With these final documentation and test tweaks, this feature appears ready for merging. The thread shows clear consensus on the approach, with no major technical objections raised.
