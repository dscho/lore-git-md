This is a discussion about performance optimization tradeoffs in René Scharfe's series converting commit traversal to use priority queues. Jeff King reflects on their differing approaches to using prio_queue versus commit_list in the rev_info.commits structure.

King notes that while Scharfe kept rev_info.commits as a commit_list (due to concerns about memory overhead and type safety), his own unpublished work fully converted to prio_queue for traversal. He speculates this difference might explain why Scharfe saw a performance hit while his approach did not, since the prio_queue becomes the hot path in his version. 

The exchange highlights an interesting design tension - Scharfe's more conservative approach maintains existing interfaces while King's bolder conversion might offer better performance but requires more invasive changes. King acknowledges some of the implementation details (like using prio_queue's FIFO behavior in clever ways) might seem "horrible" but worked in practice.

This discussion provides valuable context about alternative approaches to the optimization problem, though it doesn't change the fact that Scharfe's series (which takes the more conservative path) is complete and ready for merging. The conversation may inform future work on further optimizing commit traversal.
