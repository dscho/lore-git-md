This is a follow-up discussion about a refactoring patch that moved `struct rev_list_info` from bisect.h to builtin/rev-list.c. The original patch was part of codebase cleanup work, correctly relocating a struct that was only used by rev-list.

Jeff King (peff@peff.net) responds to Junio Hamano's patch, agreeing with the main change but questioning an incidental comment fix about option parsing. The original comment stated the loops don't understand "that the options they are skipping are broken," while Junio's patch changed it to say they don't understand "the options they are skipping."

Peff argues the original wording was actually more accurate - the issue is that the loops fail to recognize when options are broken/misinterpreted, not just that they don't understand the options generally. This is a subtle but potentially important distinction about the nature of the parsing bug.

The exchange shows careful attention to detail in code comments, even in what might seem like a straightforward cleanup patch. The core refactoring work appears uncontroversial, but this side discussion about comment wording demonstrates how Git maintainers scrutinize all aspects of changes.
