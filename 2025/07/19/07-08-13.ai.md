This is a refactoring patch removing the long-dormant `--early-output` feature from Git's revision machinery. The feature was originally added in 2007 to support progressive rendering in GUI tools like gitk and QGit, but was never documented or widely adopted. Jeff King proposes removing it entirely since it has been broken multiple times (including currently not working with commit-graphs) without anyone noticing, suggesting no active users exist.

The patch deletes 154 lines across `builtin/log.c`, `revision.c`, and `revision.h`, removing all `--early-output` related code including the timer-based progressive output system, signal handlers, and the global `show_early_output` function pointer. The commit message provides historical context showing the feature was never properly integrated into GUI tools and has been broken for extended periods (2011-2017 and currently with commit-graphs).

Key technical details removed include:
- The `early_output` field from `struct rev_info`
- The `show_early_output_fn_t` function pointer type and its volatile global instance
- The `estimate_commit_count()` helper and timer-based output logic
- All `SIGALRM` signal handling infrastructure
- The feature's interaction with `--topo-order` (which it implicitly enabled)

The author considers but rejects a "soft" removal option that would keep accepting the option while making it a no-op, arguing the clean removal is justified given the feature's unused state. The change is motivated by wanting to simplify the revision code for future work.
