This is a small bugfix suggestion for the Rust integration CI setup in the final patch of the RFC series introducing Rust as a hard dependency with xdiff optimizations. Johannes Schindelin points out that the error message when failing to find the Rust static library during build is not sufficiently informative. The current message simply states "cannot find path of static library" without showing the actual paths being checked (`$src`, `$dir_rust`, `$rust_target`, `$libfile`), making debugging build failures more difficult than necessary.

The suggestion comes from Schindelin's practical experience hitting this issue, indicating this is a real pain point in the build process. While minor, this improvement would make the CI system more maintainable by providing immediate visibility into what went wrong when the Rust library cannot be located. The change would affect the GitHub Actions workflow setup introduced in patch 7/7 of the series.

This follows Schindelin's pattern of contributing Windows-specific build fixes throughout the RFC series, though here the suggestion applies to CI error reporting generally rather than being platform-specific. The proposed change is straightforward and unlikely to be controversial, addressing a clear usability issue in the new Rust build infrastructure.
