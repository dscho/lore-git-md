This is a reply in the ongoing discussion about making Rust a hard dependency for Git, specifically addressing distribution and platform compatibility concerns raised by Gentoo maintainers.

Haelwenn Monnier adds to Eli Schwartz's concerns about Rust adoption, noting that if the xdiff changes propagate to libgit2, there could be circular dependency issues since Cargo itself depends on libgit2 (via the git2 crate). They suggest ensuring the Rust integration can be built via meson's Rust support rather than through Cargo to avoid this problem. This builds on Schwartz's earlier points about Gentoo's packaging challenges, where some architectures lack Rust support entirely and others would require building multiple Rust versions from source.

The reply reinforces the practical deployment obstacles for distributions, particularly the cascading effects on dependent projects like libgit2. While not opposing Rust direction outright, it highlights real-world constraints that need addressing before mandating Rust. The comment suggests meson-based builds as one potential solution path, indicating this remains an active area needing technical and policy resolution.
