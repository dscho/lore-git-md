This is a bugfix patch that completes the implementation of diff context configuration support for interactive patch commands (like `git add -p`). It's part of a larger series that has been through several rounds of review and refinement.

The patch teaches the add-patch infrastructure to respect the user's `diff.context` and `diff.interHunkContext` configurations, which previously weren't being used in interactive patch selection. The implementation:

1. Adds fields to store these values in the `add_i_state` struct
2. Reads the config values during initialization, rejecting negative numbers
3. Passes the values to the underlying plumbing commands when generating diffs
4. Includes new tests verifying the behavior works and rejects invalid values

This appears to be a well-crafted patch that addresses a real inconsistency in Git's behavior. The implementation follows the established patterns from earlier parts of the series, and the tests provide good coverage of both the happy path and error cases. The patch has already received positive feedback from reviewers, with only minor outstanding comments remaining before the series can be merged.
