This is a bugfix patch completing the diff context configuration support for interactive patch commands, part of the v4 series that has been under review. The patch teaches the add-patch infrastructure to respect `diff.context` and `diff.interHunkContext` configurations, ensuring consistent diff display behavior across Git commands.

The implementation adds two new fields (`context` and `interhunkcontext`) to `struct add_i_state`, initializes them with validation to reject negative values, and passes them to the underlying plumbing commands via command-line options. The changes affect `add-interactive.c`, `add-interactive.h`, and `add-patch.c`, with corresponding test cases added to `t/t3701-add-interactive.sh` to verify the new behavior.

Key technical details:
- Adds config reading for `diff.context` and `diff.interHunkContext` in `init_add_i_state()`
- Validates against negative values with `die()` on invalid config
- Passes configured values via `--unified` and `--inter-hunk-context` options when spawning diff
- Maintains backward compatibility with default (-1) values
- Includes three new test cases:
  - Verifies `diff.context` affects hunk display
  - Verifies `diff.interHunkContext` affects hunk merging
  - Verifies negative values are rejected

The patch represents the final piece of config support in the series, following earlier work on test modernization and command-line option handling. It has already received approval from Phillip Wood for the config reading implementation, with only minor review comments remaining per Junio's earlier feedback. The implementation aligns with the established pattern of using command-line options to override config values while maintaining consistent validation.
