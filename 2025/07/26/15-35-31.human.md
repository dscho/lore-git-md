Security feature proposal for interactive authentication before sensitive Git operations.

Victor Duprez proposes a new `git-secure` command that would require explicit user authentication before performing potentially risky operations like `git push` or `git clone`. The motivation stems from concerns about credentials being silently available in the environment, which could lead to accidental pushes or credential misuse on shared systems.

The proposal suggests either GitHub personal access tokens or password manager-generated credentials as authentication methods, with the credentials being ephemeral (used once then discarded). This would add an interactive confirmation step for operations that currently rely on pre-existing credentials. A prototype script demonstrates the concept, though it's currently GitHub-specific.

The RFC appears well-motivated by legitimate security concerns, particularly for shared or untrusted environments. However, the current implementation seems narrowly focused on GitHub, and the proposal would need to consider broader Git hosting providers and authentication methods to be generally useful. The security benefits would need to be weighed against the friction this would add to common workflows.
