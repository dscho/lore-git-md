Victor Duprez has proposed a new security feature for Git called `git-secure`, aimed at preventing accidental or unauthorized use of stored credentials during sensitive operations like push and clone. The proposal highlights three key security risks in Git's current credential handling: accidental pushes, insecure credential storage, and potential misuse on shared systems. The suggested approach would require explicit user confirmation via either GitHub token or password manager before allowing such operations, with credentials designed for one-time use.

The initial concept shows promise in addressing real security concerns, particularly for users working on shared systems or with sensitive repositories. However, several open questions remain about how this would integrate with Git's existing credential system, handle non-GitHub remotes, and accommodate Git's sometimes-repeated authentication needs during complex operations. The accompanying prototype script demonstrates the basic concept but suggests this would require significant development work to become a core Git feature. The thread is currently in the early discussion phase, with the community likely to weigh in on both the security benefits and implementation challenges.
