Git RFC proposal for a `git-secure` command to enhance authentication security, authored by Victor Duprez. The command would require explicit user confirmation before sensitive operations (push/clone) to mitigate three risks: accidental pushes, insecure credential storage, and credential misuse on shared systems. Proposed implementation would prompt for GitHub tokens or password manager credentials with one-time use and secure disposal. Current prototype demonstrates interactive GitHub token prompts but raises open questions about integration with Git's existing credential system, handling non-GitHub remotes, and compatibility with Git's repeated authentication needs during operations. The proposal is in RFC stage with significant integration work needed for core inclusion.
