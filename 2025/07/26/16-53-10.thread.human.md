This thread centers on a patch series to improve how Git handles `-h` and `--help-all` options across commands, particularly making them work outside repository contexts and allowing `-h` to coexist with other arguments. The series is currently at version 1, with test fixes contributed by D. Ben Knoble already merged into the test branch.

Junio Hamano, the maintainer, has approved the core change enabling `--help-all` outside repositories as straightforward, but raised significant security concerns about allowing `-h` to work alongside other arguments. He worries this could enable dangerous aliases and questions whether the workflow is worth supporting. The parse-options refactoring using enums is also under review for readability impact.

In the latest email, Junio confirms that two test fixes (removing outdated commands from t1517-outside-repo.sh and fixing syntax in t5200-update-server-info.sh) can be dropped from future patch versions since they're already upstream. This administrative note helps streamline the series by identifying settled changes that no longer need review.

The author appears likely to drop the controversial `-h` coexistence patch following Junio's objections, while the enum refactoring and repository-less `--help-all` changes seem on track pending readability adjustments. The thread remains active with open questions about the best design for help behavior and parse-options internals.
