This thread discusses a patch series to improve how Git handles `-h` and `--help-all` options across commands. The main goals are making `--help-all` work outside repositories and allowing `-h` to appear anywhere in command arguments while preserving special cases like `grep -h`.

The series is currently at version 1 with four patches. Patch 3, which enables `--help-all` outside repositories by modifying `git.c`, has been positively reviewed by Junio as "obvious and straightforward." D. Ben Knoble explained they initially tried a more invasive approach (modifying each builtin's early option parsing) but found the current solution - special-casing `--help-all` similar to `-h` - works better. This patch is now in good shape.

However, the final patch (enabling `-h` mid-command) faces strong opposition from Junio due to security concerns about aliases potentially executing destructive commands when `-h` is appended. The patch would change behaviors like making `rebase -h new-base` show help instead of starting a rebase. Junio has also raised questions about the enum-based refactoring in parse-options.c, suggesting simpler approaches might be better.

Test infrastructure fixes from D. Ben Knoble have been upstreamed and can be dropped from future versions. The author prefers squashing test fixes rather than keeping them as separate commits. While most of the series appears ready, the future of argument-tolerant `-h` behavior remains uncertain due to the security implications.
