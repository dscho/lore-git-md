This thread covers a 3-part patch series that improves how Git handles `-h` and `--help-all` options, particularly when used outside a repository context. The series builds on test infrastructure from the ua/t1517-short-help-tests branch and was authored with input from D. Ben Knoble and Jeff King.

The initial patches refactored parse-options.c to use clearer USAGE_NORMAL/USAGE_FULL constants and modified git.c to bypass repository checks for help requests, while preserving special cases for `ls-remote -h` and `grep -h`. After some discussion and test adjustments, the controversial fourth patch (which would have allowed mid-command `-h`) was dropped due to technical and security concerns raised by Junio Hamano.

The final patch, which just arrived, completes the series by extending the same repository-less behavior to `--help-all`. It modifies git.c, parse-options.c, merge-recursive.c, and usage.c to ensure consistent handling, while expanding the test coverage in t1517-outside-repo.sh. The implementation maintains all existing special cases and follows the pattern established for `-h` support.

With this patch, the series achieves its goal of making help consistently available regardless of repository context, while avoiding the more complex changes needed for mid-command help support. The changes have been reviewed by key contributors and address all outstanding concerns, so the series appears ready for merging.
