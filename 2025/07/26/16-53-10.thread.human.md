This thread concerns a patch series aiming to improve how `-h` and `--help-all` options work across Git commands. The key goal is to make `--help-all` available outside repository contexts and allow `-h` to appear alongside other arguments, while preserving special cases like `ls-remote -h` and `grep -h`. The series is currently at version 1, with test infrastructure fixes already merged into the ua/t1517-short-help-tests branch.

The first three patches have seen positive feedback, particularly patch 3 which enables `--help-all` outside repositories. However, the final patch (allowing `-h` mid-command) faces significant challenges. Junio Hamano has raised security concerns about this change, while Jeff King identified technical inconsistencies in the implementation - notably that the patch doesn't properly handle the "lone -h" case in parse-options.c and could interact poorly with RUN_SETUP flags. The author, D. Ben Knoble, now suggests possibly dropping this patch entirely given these issues.

The discussion reveals that the current approach works for commands like `grep` precisely because they bypass the problematic code paths. There's also uncertainty about whether the series has unpublished dependencies, as Jeff encountered patch application difficulties. While the test infrastructure improvements are uncontroversial, the core functionality change for `-h` behavior appears unlikely to proceed in its current form due to both technical and security objections. The thread leaves open whether the author will attempt a reworked version or simply focus on the non-controversial parts of the series.
