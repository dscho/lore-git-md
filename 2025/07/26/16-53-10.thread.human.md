This thread centers on a patch series to improve how Git handles `-h` and `--help-all` options, particularly making `--help-all` work outside repository contexts while preserving special cases for `ls-remote` and `grep`. The series has gone through three iterations, with the latest version incorporating test prerequisite fixes for `instaweb` and other refinements based on feedback.

The key participants are the original author, D. Ben Knoble (who helped shape the technical approach), and Jeff King (who provided early technical validation). Maintainer Junio C Hamano has now weighed in to confirm the scope: while the repository-less `--help-all` improvement is approved, the more controversial idea of allowing `-h` with other arguments remains off the table due to technical and usability concerns. Junio provided concrete examples showing how such behavior could produce misleading output.

The series is now in its final form, with all feedback addressed. It modifies parse-options.c to use clearer constants (USAGE_NORMAL/USAGE_FULL) and updates git.c to bypass repository checks for help options. The test changes have been consolidated per Junio's suggestion. With this clarification about the intentionally limited scope, the series appears ready for merging. The remaining open question about contributor workflow efficiency (CC list management) doesn't block integration.
