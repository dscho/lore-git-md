This is a follow-up discussion in the ongoing thread about improving `git rebase` to notify users when commits are skipped during conflict resolution.

Cameron Steffen responds to Junio Hamano's concerns about the proposed warning message format. The core issue revolves around whether the warning should only trigger when Git can definitively determine a commit was skipped because it was already applied (Hamano's stricter view), or more broadly whenever any commit is skipped during rebase due to becoming empty (Steffen's original proposal).

The exchange reveals a key technical disagreement: Steffen initially thought checking for unstaged changes would be sufficient to detect skips, but Hamano points out this would make the warning message ("skipped previously applied commit") potentially inaccurate. The discussion is now focused on finding the right balance between detection accuracy and warning usefulness.

This email doesn't introduce new code but rather clarifies the conceptual tension in the design approach. The thread remains active with fundamental questions about the rebase state machine's behavior that need resolution before implementation can proceed.
