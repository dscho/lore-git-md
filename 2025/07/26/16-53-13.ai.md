Feature patch extending `--help-all` support to work outside repository contexts, part 3/4 in a series improving Git's help system behavior.

This patch modifies several key components to make `--help-all` behave consistently with `-h` when run outside a Git repository. The main obstacle was that commands would fail during repository setup before reaching option parsing. The solution involves:

1. Adjusting `git.c`'s `run_builtin()` to treat `--help-all` like `-h` for repository setup purposes
2. Updating `parse-options.c` to properly handle `--help-all` requests with full help output
3. Adding `--help-all` support to the legacy `merge-recursive` command
4. Extending test coverage in t1517-outside-repo.sh to verify the new behavior

The changes are relatively surgical, touching about 20 lines across 5 files. The author notes some technical considerations in the commit notes:
- Most commands can't reach parse-options without repository setup
- `merge-recursive` uses older help APIs but isn't worth modernizing
- Some commands like `check-ref-format` could benefit from parse-options migration

This builds on the parse-options refactoring from patch 2/4, using the new `style_full` enum for `--help-all` output. The test additions mirror existing `-h` tests, providing consistent verification. The patch maintains special case handling for commands like `ls-remote` and `grep` while expanding the help system's capabilities.
