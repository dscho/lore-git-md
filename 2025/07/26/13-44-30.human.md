This is a bug report about inconsistent behavior in `git grep` when handling exclude pathspecs (those starting with `:^`). D. Ben Knoble observes that while `git ls-files` correctly processes the exclude pathspec `:^:Documentation/RelNotes`, `git grep` rejects it with an "ambiguous argument" error, even though the syntax appears unambiguous (no valid revision syntax starts with `:^`). The email notes several alternative forms that do work with `git grep`, suggesting this is a parsing quirk rather than a fundamental limitation.

The report is well-formulated, showing clear reproduction steps and demonstrating the author has already done some investigation into valid alternatives. This appears to be a genuine inconsistency in path exclusion handling between Git commands, though the impact seems limited since workarounds exist. The question is narrowly scoped and technical, making it likely to attract attention from Git's grep/rev-parse experts.
