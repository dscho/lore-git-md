Bugfix follow-up discussing edge cases in Git's alias handling with `-h` flags. Jeff King (Peff) responds to Junio Hamano's concerns about the recent patch that fixed `git grep -h` behavior in aliases, acknowledging additional problematic cases while defending the current fix as a strict improvement.

The discussion reveals several tricky scenarios: aliases that add their own arguments (like `grep --cached`) can prevent `-h` from triggering help mode, and external commands may show both alias info and their own help text. Peff proposes two potential enhancements: stripping alias-added arguments when showing help, and not executing shell aliases when given `-h`.

While the current patch solves the immediate `grep -h` issue, the thread highlights deeper design questions about how Git should handle help requests versus command flags in aliases, particularly regarding argument preservation and external command behavior. Peff argues these remaining cases, while real, represent a lesser evil than the original bug and could be addressed separately.

This continues an ongoing examination of Git's alias expansion behavior, showing how a simple bugfix can uncover more fundamental questions about the interface between command-line parsing and alias processing. The exchange demonstrates careful consideration of edge cases while maintaining practical progress on the immediate issue.
