This is a feature proposal introducing a new security mechanism for Git operations. Victor Duprez suggests adding a `git-secure` command that would require explicit user authentication before sensitive operations like push or clone, addressing potential security risks from stored credentials.

The proposal identifies three main security concerns with current credential handling: accidental pushes, insecure credential storage, and credential misuse on shared systems. The solution would prompt users for either a GitHub token or password manager-generated credential that would be ephemeral - used once then discarded.

The RFC includes a prototype implementation as a shell script that demonstrates the basic flow: collecting credentials, username, and operation type. The proposal appears well-motivated by security considerations but raises several open questions about integration with Git's existing credential system, cross-platform support beyond GitHub, and whether this should be a built-in command or external tool.

Key technical aspects for future reference: the proposed command name `git-secure`, the GitHub token/password manager credential flow, and the prototype's current implementation as an external script. This touches Git's credential storage subsystem and would need to interface with existing auth mechanisms like SSH keys. The security vs convenience tradeoff seems likely to generate discussion.
