This is a feature proposal for `git clean` regarding its behavior with ignored files in nested repositories. 

Alon Bar-Lev notes that while `git clean -dxff` can clean directories and ignored files in the main repository while handling nested repositories, it doesn't extend the ignored-file cleaning (`x` flag) to those nested repositories. The current workaround requires manually running `git clean` in each submodule, which is less convenient.

The proposal suggests either making the existing `-x` flag apply recursively to nested repositories (treating it as a bug fix) or introducing a new `-xx` flag variant to explicitly enable this behavior. The motivation is to provide a more consistent and simple way to clean an entire repository tree, including submodules, in one command.

The email acknowledges this may have been discussed before but couldn't find prior threads. The tone is exploratory, seeking feedback on whether this is an intentional limitation and what approach (bugfix vs new flag) would be most appropriate. The change would affect users who frequently clean repositories with complex submodule structures.
