Thread identity: RFC proposal for a new `git-secure` command to add authentication requirements for sensitive Git operations like push/clone, authored by Victor Duprez.

Core problem: Current Git credential handling has security risks from stored credentials, accidental pushes, and shared system usage. The proposal aims to require explicit user authentication via ephemeral credentials (GitHub tokens or password manager) before sensitive operations.

Current status: Initial RFC with prototype demonstrating GitHub token authentication. No version history yet as this is the thread root.

Key technical details:
- New `git-secure` command/option
- Interactive credential prompting flow
- GitHub token and password manager integration points
- Ephemeral credential lifecycle (used once then discarded)
- Initial prototype focuses on GitHub operations

Open questions:
- Scope beyond GitHub (currently limited)
- Integration with existing credential helpers
- Whether this belongs in core Git vs external tooling
- General design approach feedback

Participant positions: Only author Victor Duprez so far, proposing the initial design via RFC.

Related work: Connects to broader Git credential security discussions but no specific prior threads referenced.
