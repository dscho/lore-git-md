Thread summary:

Victor Duprez proposes `git-secure`, a new security mechanism requiring explicit user authentication for sensitive Git operations like push/clone to address credential misuse risks. The RFC identifies three current security gaps: accidental pushes, insecure credential storage, and silent credential misuse on shared systems. The proposed solution would prompt for one-time GitHub tokens or password manager-generated passwords, discarded after use. A prototype script demonstrates interactive prompts for token/password, username, and operation type.

Key technical elements include the `git-secure` command/option name, two authentication methods (GitHub tokens and password manager integration), and memory/disk handling requirements. The implementation would need to interface with Git's existing auth systems while adding this verification layer. This is an early-stage RFC with a working prototype but no patch yet. Open questions include integration with non-GitHub hosting providers, credential manager compatibility, and whether this belongs in core Git versus an external tool. The security benefits are clear but adoption would depend on implementation details and UX tradeoffs.
