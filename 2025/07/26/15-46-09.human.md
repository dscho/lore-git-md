Feature proposal for a new security mechanism in Git.

Victor Duprez proposes adding a `git-secure` command that would require explicit user authentication before sensitive operations like push or clone. The motivation is to prevent accidental or unauthorized repository modifications when credentials are available in the environment (like stored SSH keys or tokens). The command would prompt for either a GitHub token or password manager-generated credential, using it once before securely discarding it.

The proposal addresses real security concerns around credential misuse, particularly in shared or untrusted environments. The current prototype is a standalone script rather than integrated Git functionality, suggesting this is an early-stage proposal. The implementation approach (new command vs. flag to existing commands) and scope (currently GitHub-focused) would likely need discussion.

This appears to be a serious proposal with clear motivation, though it would need to address broader Git hosting providers beyond GitHub and consider integration with existing credential systems. The security vs. convenience tradeoff may spark debate in the community.
