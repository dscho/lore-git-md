This is a post-merge review comment in the ongoing test organization effort for Git command help output testing. D. Ben Knoble follows up on the recently merged patch series that standardized help test organization, noting an observation about exit code behavior in certain commands.

The email points out that some commands (like `quiltimport` and `request-pull`) actually work fine with `-h` outside a repository, contrary to their current classification as exceptions. The issue appears to be primarily about exit codes rather than fundamental incompatibility. Knoble suggests this as a potential cleanup item (#leftoverbits) rather than requesting immediate changes, maintaining the constructive tone of post-merge review.

This observation builds on the series' goal of properly categorizing help tests - while the main work of separating repository-dependent and repository-independent tests is complete, this note identifies a subtle pattern in the test failures that might warrant future standardization of exit code behavior for help output.
