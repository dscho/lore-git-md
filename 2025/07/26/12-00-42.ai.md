Feature proposal for `git clean` behavior in nested repositories. Alon Bar-Lev suggests extending the `-x` flag's functionality to apply to nested repositories when using `-ff` (force clean in nested repos). Currently, `git clean -dxff` only removes ignored files (`-x`) in the top-level repository, requiring a separate `git submodule foreach` command to clean ignored files in submodules.

The proposal centers on whether this is an intentional limitation or an oversight. Bar-Lev offers two potential solutions: either modify the existing `-x` behavior to work recursively with `-ff`, or introduce a new `-xx` flag to explicitly request this behavior. The goal is to provide a more consistent cleaning experience across nested repositories without requiring multiple commands.

This touches on Git's submodule handling and the `clean` command's behavior with ignored files. The discussion would need to consider whether recursively cleaning ignored files in submodules should be the default behavior with `-x`, or if it warrants a separate flag given the potentially destructive nature of the operation. The proposal doesn't include a patch yet, but seeks feedback on the conceptual approach before implementation.
