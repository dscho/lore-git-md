Bug report follow-up identifying SELinux as the likely cause of git-daemon regression in Fedora 40. Todd Zullinger provides a detailed reproduction and solution path for the issue where `~user` paths fail in git-daemon operations, building on Russell King's original report and Jeff King's unsuccessful reproduction attempts.

The email documents a working solution involving three key adjustments: setting proper directory permissions (ensuring home directories are searchable by the 'nobody' user), correcting SELinux context types to `git_user_content_t`, and enabling the `git_system_enable_homedirs` SELinux boolean. The solution is presented with specific command-line examples and includes diagnostic steps using `audit2allow` to identify the required policy change.

Notably, this identifies the issue as being Fedora-specific (particularly its default SELinux configuration) rather than a Git regression, though the behavior change after a system upgrade suggests Fedora may have tightened its SELinux policies. The email concludes with a suggestion that the git-daemon package should include SELinux documentation similar to what's provided with cgit. This appears to fully explain and resolve the originally reported regression while highlighting a documentation gap in the Fedora packaging.
