Git thread summary:

Bug report and discussion about inconsistent path exclusion syntax handling between `git ls-files` and `git grep`. The `:^:Documentation/RelNotes` exclude pathspec works in `git ls-files` but fails in `git grep` with "ambiguous argument" error, incorrectly interpreting it as a revision. The reporter demonstrated understanding of Git's pathspec vs revision parsing rules and provided clear reproduction steps. Junio C Hamano confirmed the issue in `setup.c`'s filename verification code path (`die_verify_filename()` and `looks_like_pathspec()`), noting the shorthand `:^:` syntax is "deliberately confusing" while the longhand `:(exclude)` form works correctly. He suggested the shorthand could potentially be taught to work but cautioned about unintended consequences, indicating this is a known parsing edge case requiring careful consideration due to possible side effects in other code paths. The discussion reveals the inconsistency stems from `git grep`'s argument handling rather than a fundamental limitation, with the maintainer weighing the tradeoffs of fixing the shorthand behavior versus recommending the unambiguous longhand syntax.
