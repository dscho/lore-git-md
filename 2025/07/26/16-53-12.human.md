This is a refactoring patch in a series improving Git's help system. It focuses on making the parse-options.c internals more readable by replacing magic numbers with named enums for the flags passed to `usage_with_options_internal()`.

The patch introduces two new enums - `usage_style` (normal vs full help output) and `usage_output` (stdout vs stderr) - to replace the previously cryptic `0,0` and `1,0` parameter pairs. This makes the call sites more self-documenting when showing different help variants (normal help, full help, error cases).

The changes are mechanical but meaningful, touching 10 call sites across parse-options.c. The author notes this helps when reading or editing these calls, as the behavior remains identical - it's purely a code clarity improvement. This fits well with the series' goal of cleaning up help system internals while expanding functionality.

As part of a larger effort to improve `-h` and `--help-all` behavior, this patch stands out as a straightforward internal cleanup that should be uncontroversial. The changes are localized to parse-options.c and don't affect user-facing behavior, making it a safe refactor.
