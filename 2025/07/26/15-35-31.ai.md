This is a feature proposal introducing a new security mechanism for Git operations. Victor Duprez suggests adding a `git-secure` command that would require explicit user authentication before sensitive operations like push or clone, addressing potential security risks from stored credentials.

The proposal identifies three main security concerns with current credential handling: accidental pushes, insecure credential storage, and potential misuse on shared systems. The solution would prompt for either a GitHub token or password manager-generated credential that would be ephemerally used then discarded. A prototype script demonstrates the concept with GitHub token authentication.

Key technical aspects include:
- New command/option named `git-secure`
- Interactive credential prompting
- Support for GitHub tokens and password manager integration
- Ephemeral credential handling
- Initial prototype targeting GitHub operations

The proposal appears well-motivated for security-conscious workflows but raises several open questions about scope (currently GitHub-focused), integration with existing credential helpers, and whether this should be core Git functionality versus an external tool. The prototype suggests serious consideration of the problem space, though the RFC nature indicates the design is still formative.
