Thread summary:

Victor Duprez proposes a new `git-secure` command to address credential security risks in Git operations. The RFC outlines three vulnerabilities: accidental pushes, insecure credential storage, and shared system misuse. The solution would require explicit authentication via one-time GitHub tokens or password manager passwords before sensitive operations like push/clone, with credentials discarded after use.

Current status is an early-stage proposal with a GitHub-focused prototype demonstrating interactive token prompts. No implementation path is specified - it could be an external wrapper or core Git integration. The security model initially targets GitHub PATs but leaves room for password manager support. Key open questions include integration with existing credential helpers, scope of protected operations, and whether this belongs in core Git or as a separate tool. The prototype suggests feasibility but lacks details on memory safety and broader authentication methods.
