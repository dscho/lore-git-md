This is the fourth and final patch in a series expanding `-h` and `--help-all` functionality across Git commands. The patch modifies help request handling to work when additional arguments are present, addressing a usability pain point where users couldn't get help after recalling a command with arguments from shell history.

Key technical changes:
- Modifies help detection in `git.c`'s `run_builtin()` to trigger on `-argc >= 2` rather than `== 2` when `-h` or `--help-all` appears
- Updates similar checks in `parse-options.c`, `usage.c`, and `merge-recursive.c` to match
- Preserves special case behavior for `grep -h` (suppresses filenames) and `ls-remote -h` (lists heads)
- Adds notes about verifying existing behavior remains unchanged in these special cases

The patch is small (4 files, 4 lines changed) but touches core command dispatch and help system components. The author acknowledges this may be the most controversial change in the series, noting it's primarily a typing-reduction convenience while offering to drop it if problematic. The implementation appears careful to maintain backward compatibility with existing help-related behaviors.

This completes the series' goal of making help requests more flexible while preserving special cases, building on the earlier parse-options refactoring and repository-context handling changes. The changes are consistent with the series' overall direction and maintain the established pattern of verifying edge cases.
