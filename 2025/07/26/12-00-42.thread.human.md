Alon Bar-Lev has proposed extending `git clean`'s behavior to handle ignored files in nested repositories more consistently. Currently, using `git clean -dxff` (where `-x` cleans ignored files and `-ff` forces cleaning in nested repos) only affects the top-level repository's ignored files, requiring separate submodule commands to clean nested repos.

The discussion centers on whether this limitation is intentional design or an oversight. Bar-Lev suggests two possible solutions: either make `-x` work recursively with `-ff` by default, or introduce a new `-xx` flag to explicitly requesting this recursive behavior. The goal is to provide a more unified cleaning experience across nested repositories without requiring multiple commands.

This proposal touches on Git's submodule handling and the potentially destructive nature of cleaning ignored files. The thread is currently in the conceptual discussion phase, seeking feedback on whether recursive cleaning of ignored files should be the default behavior or require an explicit opt-in via a new flag. No implementation patch has been submitted yet while the design approach is being discussed.
