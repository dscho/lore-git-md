Bug investigation response regarding git-daemon's tilde expansion behavior. Jeff King responds to Russell King's report that git-daemon in Fedora 40 (Git 2.49.0) fails to properly expand `~user` paths when serving repositories via `--user-path=public_git`.

Jeff shares that he cannot reproduce the issue locally - his test setup with similar parameters successfully expands `~peff` paths. He examines the daemon's path validation logic in daemon.c and suggests the problem might stem from unexpected arguments being passed via systemd's git@.service template, though he acknowledges this is speculative. 

The key observation is that while both setups log the tilde-prefixed paths similarly, Russell's fails with a "not in directory list" error that suggests additional path validation is occurring. Jeff provides several diagnostic suggestions (checking systemd logs, strace output) but concludes he's out of ideas after testing various configurations including inetd mode and systemd service files.

This appears to be a genuine regression that only manifests in Russell's production environment, possibly related to systemd integration or Fedora-specific packaging. The response is thorough and diagnostic-focused, though no root cause is identified yet.
