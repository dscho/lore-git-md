This is the final discussion thread for the `core.commentChar=auto` deprecation series, now with maintainer approval. Junio C Hamano checks in on the status as Phillip Wood prepares the final re-roll of the two-patch series that will remove this problematic feature.

The key technical decision has been settled: Git will error out when encountering `auto` post-3.0 rather than silently falling back to `#`, avoiding potential commit message corruption. The implementation now properly handles configuration scopes and includes comprehensive deprecation advice that leverages `git config list --show-scope` for diagnosis, following Oswald Buddenhagen's suggestion which Junio has explicitly endorsed.

The patches touch documentation (BreakingChanges.adoc, core.adoc), core functionality (config.c, builtin/commit.c), and test cases (t7502, t3404). The series is architecturally sound with all feedback incorporated, including minor editorial improvements from Ayush Chandekar. Phillip indicates he'll finalize the re-roll next week, concluding this long-running effort to remove the flawed auto-comment feature whose heuristics caused problems with commit templates and rebase operations.
