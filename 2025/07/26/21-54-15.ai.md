This is a discussion thread about the `git-repo-info` command implementation, specifically focusing on output format quoting considerations. The email from Lucas Seiki Oshiro responds to Patrick Steinhardt's suggestion about handling special characters in the human-readable output format.

Lucas acknowledges that while quoting would be needed for future path outputs (which may contain problematic characters like newlines), the current implementation only deals with simple values ("true", "false", "files", "reftable") that don't require quoting. He notes that `git config --list` doesn't quote its key=value output either, though he recognizes this might not be the perfect comparison.

The key technical point is that while quoting with `quote_c_style()` would be easy to add later, Lucas proposes deferring this until the command actually needs to handle paths with special characters. This maintains the current simple output format while leaving the door open for future expansion. The discussion shows the implementation is progressing with careful consideration of edge cases, though some design questions about output formatting remain open for future patches.
