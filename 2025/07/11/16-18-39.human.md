This is part 3 of a 4-part series implementing efficient pagination for `git for-each-ref` via a new `--start-after` option. The series has already been reviewed and approved for merging by Junio C Hamano.

This patch refactors the `ref_iterator_seek()` function to clearly distinguish between two operations: seeking to a specific reference (like a cursor) versus setting a prefix filter for iteration. It introduces a `REF_ITERATOR_SEEK_SET_PREFIX` flag to explicitly control which behavior is desired. When the flag is set, it maintains the existing prefix-filtering behavior; when unset, it seeks to the specified reference while clearing any previous prefix.

The changes affect all ref backends (files, packed, reftable), with the files backend requiring more involved modifications since it uses the ref-cache mechanism. The patch includes thorough updates to documentation and tests to reflect the new behavior. Patrick Steinhardt provided key feedback that helped shape the final API design.

This is a well-crafted change that cleanly separates concerns in the ref iteration API while maintaining backward compatibility. It serves as important infrastructure for the pagination feature while also making the iterator interface more intuitive. The patch has already gone through multiple rounds of review and refinement, with all feedback addressed.
