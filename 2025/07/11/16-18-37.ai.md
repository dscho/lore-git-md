This is the first patch in a 4-part series introducing pagination support for `git for-each-ref` via `--start-after`. The patch moves the foundational `ref_iterator` API from internal headers to public `refs.h`, enabling more flexible reference iteration patterns.

The change exposes key iterator operations (`ref_iterator_advance`, `ref_iterator_seek`, `ref_iterator_peel`) and the `do_for_each_ref_flags` enum that controls iteration behavior. The comprehensive documentation block explains iterator lifecycle management, including resource ownership rules and error handling. This public API will allow callers to implement custom iteration patterns without requiring new wrapper functions for every combination of options.

The implementation is clean - it simply relocates existing well-tested code from `refs-internal.h` to `refs.h` while maintaining all functionality. The commit message clearly explains the motivation: avoiding combinatorial explosion of wrapper functions as iteration requirements grow. This foundational change enables the subsequent pagination work while being generally useful for other advanced ref iteration use cases.

Key technical components exposed:
- `struct ref_iterator` with its vtable-based operations
- `do_for_each_ref_flags` enum values (INCLUDE_BROKEN, PER_WORKTREE_ONLY etc.)
- Core iterator functions: `advance`, `seek`, `peel`, `free`
- `do_for_each_ref_iterator` adapter between callback and iterator styles

The patch establishes the public API contract that will be used by the pagination feature in later patches, while maintaining backward compatibility with existing iteration patterns.
