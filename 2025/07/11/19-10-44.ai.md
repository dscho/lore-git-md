Refactoring of the tag idempotency discussion, reintroducing a lightweight-only version of Junio Hamano's withdrawn proposal. This patch modifies `builtin/tag.c` to allow recreating lightweight tags pointing to the same commit without requiring `--force`, while maintaining the existing behavior for annotated tags and cases where the target commit differs.

The implementation adds a special case in `cmd_tag()` that exits successfully when:
1. The tag exists
2. It's a lightweight tag (`create_tag_object` is false)
3. The new target object matches the existing tag's target (`oideq(&object, &prev)`)

Test updates verify this behavior:
- Lightweight tag recreation succeeds when pointing to same commit
- Lightweight tag recreation still fails when pointing to different commit
- Annotated tag recreation continues to require `--force` even for same commit

Key technical points:
- Maintains strict behavior for annotated tags due to metadata differences
  (tagger identity, timestamps)
- Preserves safety by requiring `--force` when changing tag targets
- Aligns with Randall Becker's workflow needs for lightweight tags
- Does not address the original error message improvement goals

This appears to be a focused, technically sound implementation of the lightweight tag idempotency case that Junio previously described as conceptually sound. The patch is small (2-line code change) with corresponding test updates, though it doesn't resolve the broader discussion about error message improvements or Hilco Wijbenga's more comprehensive attribute validation approach.
