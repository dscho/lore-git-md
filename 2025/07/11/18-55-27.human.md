This is a brief discussion about configuration parsing in the ongoing `the_repository` removal effort. Junio Hamano responds to Phillip Wood's concern about moving compression level settings into repository settings, which caused a regression in `git fast-import` where invalid values were no longer silently accepted.

Phillip argues that scattering `prepare_repo_settings()` calls throughout the code is problematic and that config settings should still be parsed at startup to avoid regressions. Junio agrees this principle should apply broadly when moving globals into repository settings, not just for this compression level case. The exchange highlights an important architectural consideration for the series as it refactors configuration handling while removing global state.
