Bugfix for interactive rebase state cleanup when instruction format is invalid. This is a follow-up to Øystein Walle's earlier patch addressing an edge case where an invalid `rebase.instructionFormat` configuration could leave the repository in a half-initialized state during interactive rebase failure.

The patch reorders operations in `do_interactive_rebase()` to validate the instruction format via `sequencer_make_script()` before initializing rebase state with `init_basic_state()`. This prevents the repository from being left in a confusing state where `git status` shows both normal branch status and incomplete rebase information when the format validation fails. The changes are accompanied by a new test case in t3415 that verifies the rebase-merge directory is properly cleaned up when an invalid format is provided.

This version adds the missing sign-off and fixes some commit message typos from the initial submission. Walle acknowledges Phillip Wood's more comprehensive suggestion to modify `get_commit_format()` to avoid direct `die()` calls, but explains he's unable to implement that approach at this time. The current patch represents a focused improvement over the existing behavior while leaving the broader error handling architecture unchanged.

The technical approach was previously reviewed and approved by Junio C Hamano, though the discussion suggests there may still be value in pursuing Wood's more thorough solution in the future. For now, this provides a clear fix for the immediate issue with minimal risk.
