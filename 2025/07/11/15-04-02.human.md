This is a bug report about path expansion in Git's GPG configuration. Ross MacArthur reports that `gpg.program` doesn't expand the `~` character to the user's home directory, unlike other Git path configurations such as `core.excludesfile`. The bug manifests when trying to use a GPG binary located in a user's local bin path, causing Git to fail with a "No such file or directory" error when the path contains a tilde.

The report includes a clear reproduction case: creating a symlink to GPG in `~/.local/bin/` and setting `gpg.program` to use that path with a tilde. The commit operation then fails, while the expected behavior would be for Git to expand the tilde to the absolute home directory path.

This appears to be a genuine inconsistency in Git's path handling, as other similar configurations do perform tilde expansion. The impact is relatively minor since users can work around it by using absolute paths, but it's a papercut that affects usability, particularly for users who prefer to keep their local binaries in home-relative paths.

The report is well-structured with a clear problem description, reproduction steps, and expected behavior. It doesn't propose a solution, but the bug seems straightforward to fix by applying the same path expansion logic used elsewhere in Git. This would be a small but welcome quality-of-life improvement for users who sign commits with custom GPG binaries.
