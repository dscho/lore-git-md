Bug report and discussion about path expansion and command parsing in Git's GPG configuration, focusing on `gpg.program` behavior. Original report showed inconsistent tilde expansion between `gpg.program` and other path settings. The thread has progressed through a v2 series that implements tilde expansion via `git_config_pathname()` while maintaining the current limitation of not parsing command-line parameters.

Current status is a completed two-patch v2 series that:
1. Modifies `gpg-interface.c` to use `git_config_pathname()` for `gpg.program` expansion
2. Adds test coverage for relative paths and home-directory expansion (now included)

Key technical details:
- Implementation in `gpg-interface.c` handles tilde expansion consistently by switching from `git_config_string()` to `git_config_pathname()`
- Documentation in `gpg.adoc` updated to specify pathname semantics (now calling it a "pathname" rather than just "program")
- Test suite verifies three scenarios: absolute paths, home-directory expansion (using HOME override), and PATH lookup (with modified PATH)
- Current behavior still treats entire value as single path (no argument parsing)
- Test cases carefully control environment variables to avoid false positives

Thread evolution:
1. Initial bug showing tilde expansion inconsistency
2. Junio Hamano initially resisted change due to command-line argument concerns
3. Empirical demonstration showed current behavior fails both as path and command
4. v1 patch implemented path expansion while documenting limitations
5. v2 refines approach with better documentation and adds comprehensive test coverage

Open questions remain about whether to support command-line argument handling in the future, but the current series represents a complete solution to the path expansion problem. The test additions provide necessary coverage for the new behavior while following established test suite patterns. The thread may continue to explore approaches for argument handling, but the immediate issue is now fully addressed with both implementation and verification in place.
