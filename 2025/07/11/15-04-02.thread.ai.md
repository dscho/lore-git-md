Bug report and discussion about path expansion and command parsing in Git's GPG configuration, focusing on `gpg.program` behavior. Original report showed inconsistent tilde expansion between `gpg.program` and other path settings. Initial fix proposed using `git_config_pathname()` for consistent tilde expansion.

Junio Hamano initially argued `gpg.program` differs from pure path settings by potentially containing command lines with arguments, but later acknowledged (after Andreas Schwab's demonstration) that the current implementation fails both as path (no tilde expansion) and command (can't parse arguments like "echo --compat=gnupg" is treated as single filename).

Key technical points:
- Current behavior satisfies neither path nor command-line expectations
- Implementation limitations:
  * No tilde expansion (path expectation fails)
  * No argument parsing (command expectation fails)
- Shell wrapper remains only workaround despite being suboptimal

Core design questions:
- Should setting follow:
  * Pure path semantics (with expansion)
  * Full command parsing (with shell)
- Would either change break existing configurations?
- Need solution addressing both tilde expansion and argument handling

Thread evolution:
1. Started as simple expansion bug report
2. Revealed deeper configuration semantics issue
3. Junio corrected initial position after empirical evidence
4. Now examining fundamental design of how Git should interpret this setting

Open questions remain about whether to modify behavior to properly support one semantic model or document current limitations. No proposed solution yet satisfies both expansion needs and argument handling capability.
