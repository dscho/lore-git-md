Bug report and discussion about path expansion and command parsing in Git's GPG configuration, focusing on `gpg.program` behavior. Original report showed inconsistent tilde expansion between `gpg.program` and other path settings. Initial fix proposed using `git_config_pathname()` for consistent tilde expansion.

Junio Hamano initially argued `gpg.program` differs from pure path settings by potentially containing command lines with arguments, but later acknowledged (after Andreas Schwab's demonstration) that the current implementation fails both as path (no tilde expansion) and command (can't parse arguments like "echo --compat=gnupg" is treated as single filename). The thread has now produced a concrete patch that implements path expansion while leaving command-line argument handling unchanged.

Key technical points:
- Current behavior satisfies neither path nor command-line expectations
- New patch implements path expansion via `git_config_pathname()` in gpg-interface.c
- Documentation updated to clarify parameter is a "pathname"
- Implementation limitations remain:
  * Now handles tilde expansion (fixes path expectation)
  * Still no argument parsing (command expectation fails)
- Shell wrapper remains only workaround for argument cases despite being suboptimal
