Review feedback on loose object map refactoring in the object-file.c series.

Karthik Nayak provides a focused review comment on patch 08/19 of Patrick Steinhardt's series to make object-file subsystem repository-agnostic. The patch refactors loose object map handling to operate on `struct odb_source` rather than repository, aligning with the series' goal of separating loose object backend operations from global state.

Nayak notes a naming inconsistency with the established pattern in earlier patches, where functions operating on specific sources use a `_source` suffix. While acknowledging this function is inherently tied to the loose files backend (and may eventually move to a dedicated file), he suggests considering the suffix for consistency with the series' established conventions.

The feedback doesn't block the patch but highlights an opportunity to maintain naming consistency across the refactored codebase. This aligns with previous reviews from Nayak that have focused on architectural patterns and parameter passing conventions in the series. The comment continues the thread's pattern of careful attention to interface design as the object-file subsystem transitions to repository-agnostic operation.
