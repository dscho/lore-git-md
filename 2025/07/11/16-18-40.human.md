Feature patch adding pagination support to `git for-each-ref`. This is the final patch in a series that has been reviewed and approved for merging, adding the user-facing `--start-after` option to efficiently skip past already-processed references.

The implementation builds on earlier refactoring work that exposed the iterator API and added seeking capabilities to reference backends. The new `--start-after=<marker>` option allows paginating through large reference sets by remembering the last seen reference and starting the next iteration from there, with O(log N) performance. The patch includes thorough documentation of the behavior (including edge cases like concurrent modifications) and extensive test coverage.

Key points:
- Works with all ref backends (files, packed, reftable)
- Maintains lexicographic ordering guarantees
- Forbids use with patterns or custom sort options that would break pagination
- Includes comprehensive tests for edge cases (directory boundaries, non-existent markers, etc.)
- Documents that concurrent modifications behind the marker won't be seen

This completes the pagination feature that was proposed and refined through multiple rounds of review, with all feedback addressed. The implementation looks solid and well-tested, providing an efficient way to process large reference sets in chunks.
