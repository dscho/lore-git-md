Bugfix for interactive rebase state cleanup when instruction format is invalid. This is Øystein Walle's v2 patch addressing the same issue as before - an invalid `rebase.instructionFormat` configuration leaving the repository in a half-initialized state during interactive rebase failure. The patch now includes the missing sign-off and fixes some commit message typos from v1.

The technical approach remains unchanged from v1: reordering operations in `do_interactive_rebase()` to validate the instruction format via `sequencer_make_script()` before initializing rebase state with `init_basic_state()`. This prevents the repository from entering a confusing state when format validation fails. The patch adds a test case in t3415-rebase-autosquash.sh to ensure the rebase-merge directory is properly cleaned up when an invalid format is provided.

Walle acknowledges Phillip Wood's more comprehensive review suggesting changes to `get_commit_format()` error handling but states he cannot implement those changes at this time. The current patch represents a focused fix for the immediate issue rather than addressing the root cause of format validation's `die()` behavior. The changes are limited to builtin/rebase.c and the test file, with no modifications to the broader format handling infrastructure.

Key technical details for future reference: the fix moves the `sequencer_make_script()` call before any state initialization in `do_interactive_rebase()`, ensuring format validation fails cleanly. The test verifies `.git/rebase-merge` is properly removed when format validation fails. The patch remains based on the original approach rather than Wood's suggested error handling improvements in revision.c` and related files.
