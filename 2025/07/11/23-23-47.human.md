This is a bugfix addressing inconsistent path expansion in Git's GPG configuration. Jonas Brandstötter's patch makes `gpg.program` properly expand `~` to the user's home directory, bringing it in line with how other Git path configurations work. The change is minimal - just switching from `git_config_string()` to `git_config_pathname()` in the GPG interface code and updating the documentation to clarify this is a pathname setting.

The patch directly addresses the thread's issue where tilde paths in `gpg.program` were failing, while similar configurations like `core.excludesfile` worked fine. The solution appears straightforward and well-scoped, with appropriate documentation updates. The author notes this is their first mailing list contribution, but the patch itself looks technically sound and properly formatted.

This should be a welcome change for users who want to store their GPG program in home-relative paths, improving consistency with Git's other path handling behavior. The fix is small enough that it seems unlikely to introduce new issues while solving a clear inconsistency.
