Bugfix for interactive rebase cleanup when instruction format is invalid. This is the second version of Øystein Walle's patch addressing an edge case where an invalid `rebase.instructionFormat` configuration could leave the repository in a half-initialized state during interactive rebase failure.

The core fix remains unchanged from v1: reordering operations in `do_interactive_rebase()` to validate the instruction format via `sequencer_make_script()` before initializing rebase state with `init_basic_state()`. This ensures format validation fails cleanly before any rebase state is written. The patch includes a test case in t3415-rebase-autosquash.sh that verifies proper cleanup of the rebase-merge directory when format validation fails.

Junio C Hamano acknowledges this as a step forward, noting that while Phillip Wood had suggested more comprehensive error handling changes (which Walle acknowledges but can't implement now), this focused fix improves the current behavior without blocking future improvements. The patch is now properly signed off and has minor commit message fixes from v1.

The fix addresses a real user-facing issue where an invalid format would leave confusing state information visible in `git status`. While not a complete solution to all error handling in this area, it's a clear improvement that doesn't preclude future work. The test case will remain valuable for regression testing regardless of how the broader error handling is eventually implemented.
