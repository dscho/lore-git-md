This is a test organization discussion in the ongoing thread about consolidating help tests (-h flag behavior) across Git's test suite. Junio Hamano responds to Usman Akinyemi's concerns about the current inconsistent placement of help tests between t1517-outside-repo.sh and command-specific test files.

Hamano proposes two potential long-term solutions: either move all non-help tests out of t1517 to create a dedicated help test file, or distribute the existing t1517 tests back to their command-specific files. He favors the latter approach, suggesting the `nongit` test helper could make this less cumbersome than the current situation. The email includes a concrete example showing how this might work - moving the update-server-info test back to t5200 while generalizing t1517 to automatically test -h behavior for all commands using `git --list-cmds`.

Key technical points include:
- Current t1517 tests both help output (-h) and other outside-repo behavior
- Proposed solution would separate these concerns
- `nongit` helper could reduce boilerplate in command-specific tests
- Example shows pattern matching to handle commands that should/shouldn't work outside repo

This moves the discussion forward by providing concrete implementation options to address the architectural concerns raised earlier, while acknowledging the practical benefits of the original consolidation. The proposal attempts to balance consistency with the reality that some commands have special outside-repo requirements.
