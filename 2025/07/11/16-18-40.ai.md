Feature implementation for `git for-each-ref` pagination via `--start-after` option. This is the final patch in a 4-part series that has been reviewed and approved for merging.

The patch introduces the user-facing `--start-after` option to `git for-each-ref`, building on the ref iterator seeking infrastructure added in previous patches. The option enables efficient O(log N) pagination by allowing iteration to start from a specified reference marker. The implementation handles edge cases through:

1. A `start_ref_iterator_after()` helper that seeks to the next reference by incrementing the marker's last character
2. Comprehensive test coverage including:
   - Empty/partial/overflow markers
   - Directory boundaries
   - Option conflicts with patterns and custom sort
   - End-of-list behavior
3. Documentation of concurrent modification behavior (changes lexicographically before the marker won't appear)
4. Enforcement of usage constraints (no patterns or custom sort)

Key technical details:
- The option conflicts with pattern matching (`--start-after` vs `refs/tags`) and custom sort options
- Uses the ref iterator's `seek` operation with `REF_ITERATOR_SEEK_SET_PREFIX` unset for pure positional seeking
- Test cases verify behavior with:
  - Partial matches (`refs/odd/sp`)
  - Directory boundaries (`refs/odd/`)
  - Non-existent markers (seeks to next valid ref)
  - Overflow conditions (both in length and path depth)

The implementation completes the pagination feature set with all review feedback addressed, including Junio C Hamano's final documentation polish and Patrick Steinhardt's API naming improvements. The series is now ready for merging with full backend support (files, packed, reftable) and comprehensive edge case handling.
