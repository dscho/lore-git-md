This is a final administrative note in the completed signal handling improvement series. Phillip Wood provides an Ack for the v4 patches while expressing a minor philosophical disagreement about errno handling in the SIGCHLD implementation. The core technical work has already been approved by Junio Hamano and accepted by Carlo Arenas, with all platform-specific issues resolved.

Phillip's comment focuses on a subtle point about errno behavior in the Windows compatibility layer - he argues future callers would expect errno to be set on failure, contrary to the current implementation that preserves Windows' signal() behavior. However, he acknowledges this is currently moot since no callers check the return value. The thread is effectively closed, with the self-pipe wake mechanism deferred to future work as previously agreed.
