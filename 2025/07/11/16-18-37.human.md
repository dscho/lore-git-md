This is the first patch in a series adding pagination support to `git for-each-ref`. It's a refactoring that moves the `ref_iterator` API from internal headers to the public `refs.h` interface.

The change exposes Git's internal reference iteration machinery, which was previously hidden in `refs-internal.h`. The commit explains that while most users interact with references through wrapper functions like `refs_for_each_ref()`, exposing the iterator directly allows more flexible usage patterns without requiring new wrapper functions for every combination of options.

The patch moves:
- The `ref_iterator` struct definition and related functions (`advance`, `seek`, `peel`, `free`)
- The `do_for_each_ref_flags` enum controlling iteration behavior
- Comprehensive documentation about iterator usage patterns

This foundational change enables the subsequent pagination work by making the seeking functionality available to higher-level code. The implementation looks clean and well-documented, with all the relevant iterator functionality moved in one logical chunk. The commit message clearly explains the motivation without over-promising - this is solid infrastructure work that enables future features rather than adding user-facing functionality directly.
