This is a technical follow-up in the ongoing thread about HTTP protocol compliance for language tag handling. Carlo Marcelo Arenas Belón responds to Collin Funk's suggestion about length-based validation of language tags, pointing out that RFC5646 defines language tags more broadly than just 2-3 character codes. He notes that including territory information (after the underscore) is valuable for distinguishing between language variants like Chinese in different regions (zh_CN vs zh_HK).

The email reinforces the thread's earlier conclusion that simple length-based filtering would be too restrictive, supporting the current approach of specifically filtering only "C" and "POSIX" locales while preserving other valid variations. This maintains the practical solution favored in the thread while ensuring proper standards compliance. The discussion continues to focus on finding the right balance between correctness and maintainability in the HTTP Accept-Language header handling.
