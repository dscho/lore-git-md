This is a discussion about HTTP protocol compliance regarding locale handling, continuing the thread about filtering invalid locale values from Accept-Language headers. Han Young responds to Collin Funk's suggestion about mapping system locales to BCP 47 language tags, pointing out practical limitations with this approach.

The email notes that even if Git attempted to convert locales to BCP 47 tags, there would still be issues with incomplete locale support across different Linux systems (particularly mentioning musl's lack of locale support) and the ambiguity in language matching (like distinguishing between pt_PT and pt_BR). While acknowledging the database requirement Funk mentioned, Young suggests hardcoding locale names might work but highlights the separate problem of filtering locales unsupported by glibc as more problematic.

This continues the thread's technical discussion about the tradeoffs between standards compliance and practical implementation, with Young leaning toward the simpler filtering approach due to platform variability and implementation complexity. The exchange shows the patch's scope may need to remain focused on basic filtering rather than comprehensive locale conversion, given the cross-platform challenges involved.
