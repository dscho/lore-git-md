Refactoring patch for the ref iterator API, addressing final review feedback in the pagination series.

This email from Karthik Nayak responds to Patrick Steinhardt's review comments on the ref iterator changes needed for the `--start-after` pagination feature. The changes focus on two small but important refinements to the API documentation and parameter naming:

1. Consolidates documentation about the `REF_ITERATOR_SEEK_SET_PREFIX` flag behavior into the enum declaration rather than splitting it between the enum and function docs, making the behavior easier to understand in one place.

2. Renames the `seek` parameter to `refname` in the `ref_iterator_seek()` function to better indicate what the parameter represents, following Patrick's suggestion that this makes the API's intent clearer.

These changes represent the final polish on the ref iterator API changes that underpin the pagination feature, which has already received Junio Hamano's approval for merging. The email shows the collaborative refinement process, with Karthik accepting both of Patrick's suggestions and indicating he'll implement them.

This patch is part of the now-completed effort to add efficient O(log N) pagination to `git for-each-ref` across all ref backends. With these last documentation improvements, the technical implementation is fully settled and ready for merge.
