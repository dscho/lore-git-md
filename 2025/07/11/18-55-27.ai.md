This is a brief response in the ongoing discussion about moving compression level settings into repository settings as part of the object-file refactoring series. Hamano endorses Wood's position that settings moved from global config should maintain the same early parsing behavior as builtin commands, generalizing this as good practice for any effort moving globals into repository or repository_settings structures. This reinforces an important architectural principle for the series as it continues to repository-agnostic operation - that config parsing timing needs careful consideration when relocating settings. The comment doesn't propose specific changes but signals maintainer alignment with Wood's critique of the current approach's potential pitfalls.
