This is a follow-up discussion in the thread about deprecating `core.commentChar=auto`. Phillip Wood responds to Junio C Hamano's questions about how the deprecation warnings will handle different scopes of configuration (system, global, local).

The key points in this email are:
1. Phillip confirms the deprecation advice will recommend updating the configuration in the same scope where `auto` is currently set (system, global, or local)
2. He raises a new consideration about whether to recommend ~/.gitconfig instead of /etc/gitconfig when the user may not have write access to the system config file
3. Phillip indicates he's leaning toward making Git die with an error when encountering `auto` in Git 3.0 rather than silently using "#", to avoid potential confusion with actual comment lines
4. He plans to send an updated version of the patch series next week

This continues the technical refinement of the deprecation approach, with the new wrinkle being how to handle system-wide configurations where the user may not have write access. The discussion appears to be converging toward a solution, with Phillip maintaining his position that the feature should be fully removed rather than kept with limitations.
