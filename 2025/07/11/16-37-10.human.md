This is a test organization discussion in the ongoing thread about consolidating help tests (-h flag behavior) for Git commands.

Junio Hamano responds to Usman Akinyemi's concerns about the current inconsistency in help test locations, where some tests remain in their original files while others have been moved to t1517-outside-repo.sh. Hamano proposes two potential long-term solutions: either distribute the non-help tests from t1517 back to their command-specific test files, or create a new dedicated file for non-help outside-repo tests. He leans toward the first approach.

The email includes a concrete demonstration of how to implement the first approach, showing how to:
1. Automate help testing for all commands in t1517 using `git --list-cmds`
2. Move the update-server-info test back to its original file (t5200)
3. Handle special cases where commands should fail outside a repository

This continues the thread's exploration of how to balance test organization principles against practical implementation concerns, particularly for commands with complex prerequisites. The proposal aims to address both the current inconsistency and Hamano's earlier concerns about t1517 accumulating unrelated tests over time.
