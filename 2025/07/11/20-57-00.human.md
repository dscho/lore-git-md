This is a brief discussion point in the ongoing thread about lightweight tag idempotency. Justin Tobler raises a potential behavioral consideration with the proposed change to allow recreating identical lightweight tags without `--force`.

The core observation is that making tag creation idempotent for identical lightweight tags would change the exit status behavior - currently, users can detect when a tag was actually created versus when it already matched, which some workflows might rely on (like conditionally pushing new tags). While not opposing the change outright, Tobler suggests this feedback might be valuable to preserve.

This is a relatively minor point in the broader discussion, but touches on an important aspect of CLI design - whether idempotent operations should be silent successes or provide some indication they were no-ops. The thread already has a working implementation of the idempotency change, so this would be a consideration for whether to adjust that behavior further.
