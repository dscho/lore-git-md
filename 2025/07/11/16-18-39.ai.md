Refactoring of the ref iterator seek functionality to distinguish between prefix filtering and positional seeking. This patch is part of the v4 series implementing `--start-after` pagination for `git for-each-ref`.

The change introduces a new `REF_ITERATOR_SEEK_SET_PREFIX` flag to explicitly control whether a seek operation should set the iteration prefix (old behavior) or perform pure positional seeking (new behavior). The core modification splits the existing `ref_iterator_seek()` into two logical operations: prefix-based filtering when the flag is set, and direct reference seeking when it isn't.

Key technical changes:
- Adds `enum ref_iterator_seek_flag` with `REF_ITERATOR_SEEK_SET_PREFIX`
- Modifies all backend implementations (files, packed, reftable) to handle both seek modes
- For files backend, extracts prefix-setting logic into new `cache_ref_iterator_set_prefix()`
- Updates callers like `refs_verify_refnames_available()` to use the flag when they want prefix behavior
- Renames `prefix` parameter to `refname` throughout for clarity

The patch maintains backward compatibility while enabling the new pagination use case. It's a foundational change that enables the `--start-after` functionality in subsequent patches while cleaning up the iterator API's semantics. The implementation handles all three ref backends (files, packed, reftable) consistently.
