This is a follow-up discussion in the ongoing thread about HTTP protocol compliance for language tag handling. Justin Tobler reviews Brian Carlson's patch that filters invalid "C" and "POSIX" locales from Accept-Language headers.

Tobler confirms the patch's approach aligns with existing NO_GETTEXT behavior and validates the test cases showing proper filtering. He suggests an alternative approach could be to filter based on ISO 639 language code length requirements (2-3 characters), which would implicitly catch "C" and "POSIX" while noting this stricter validation may not add practical value.

The review is positive overall, with Tobler verifying the test coverage demonstrates correct behavior: (1) no header sent when only invalid locales are present, (2) valid languages are preserved when mixed with invalid ones. This maintains the thread's focus on standards compliance rather than fixing observed breakage, with no new technical concerns raised about the implementation.
