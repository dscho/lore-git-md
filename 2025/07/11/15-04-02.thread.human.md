This thread examines a subtle but important inconsistency in how Git handles the `gpg.program` configuration setting. The discussion began with a bug report showing that tilde expansion works differently in `gpg.program` compared to other path settings. Initial attempts to fix this revealed a deeper issue: the current implementation satisfies neither path semantics (it doesn't expand tildes) nor command-line semantics (it can't handle arguments), despite being used for both purposes.

Junio Hamano initially argued the setting should support command-line arguments, but Andreas Schwab demonstrated this isn't actually possible with the current implementation. Hamano has now acknowledged this correction, moving the discussion forward. The core question remains unresolved: should Git modify this setting to properly support either path expansion (with tilde handling) or full command parsing (with shell-like argument splitting), or is there a third approach that could satisfy both needs?

The thread has evolved from a simple expansion bug to a fundamental discussion about configuration semantics in Git. With the maintainer now recognizing the current behavior's dual failure mode, participants are well-positioned to explore more comprehensive solutions that could properly define and implement the intended behavior for this important security-related setting.
