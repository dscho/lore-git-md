Refactoring patch in the performance optimization series for remote ref renaming. This is the second of six patches, following the standardization of the reflog callback interface in patch 1/6.

The patch simplifies reflog migration logic by eliminating the redundant `reflog_migration_data` struct. With the refname now passed directly to `migrate_one_reflog_entry()` (from patch 1/6), the indirection through this struct is no longer needed. The key change moves the `index` counter into the existing `migration_data` struct, maintaining the same ordering guarantees while reducing code complexity.

Technical changes include:
- `struct migration_data` gains a `uint64_t index` field
- `struct reflog_migration_data` is removed entirely
- Callbacks now operate directly on `migration_data` members
- Strbuf operations now use `&data->sb` instead of `data->sb->buf` indirection

The patch was acked by Junio Hamano in the thread and represents a straightforward cleanup after the foundational changes in patch 1/6. It doesn't affect functionality but makes the code more maintainable by reducing indirection and eliminating a now-unnecessary struct. The change is part of a larger effort to optimize ref operations that shows dramatic performance improvements (238s->2s for files backend in bulk operations).
