This is a refactoring patch in Patrick Steinhardt's performance optimization series for remote ref renaming. It's the fourth of six patches in v2 of the series.

The patch separates the logic that determines whether refs need renaming from the actual renaming operation. Currently these are interleaved, but this change prepares for a future commit where the reference transaction will be prepared before rewriting the configuration. The key change moves the check for whether refspecs need updating into an earlier loop, storing the result in a renamed variable (`refspec_updated` becomes `refspecs_need_update`).

This is a straightforward preparatory change that doesn't affect functionality but improves the code structure. It's part of the larger effort to optimize remote operations that was previously shown to dramatically improve performance (from hours to seconds for large repositories). The patch has a clean implementation and fits logically into the series' progression toward better transaction handling.
