This is a refactoring patch (part 3/11 in the series) converting string handling in `builtin/clean.c` from `strbuf_split()` to `string_list_split_in_place()`. The change focuses on the `parse_choice()` function which processes interactive menu selections for `git clean`.

The key changes are:
- Replaces `strbuf_split_max()` with `string_list_split_in_place_f()` which handles both comma and space delimiters natively
- Uses `STRING_LIST_INIT_NODUP` and `STRING_LIST_SPLIT_TRIM` to avoid memory allocations while preserving whitespace trimming
- Eliminates manual comma-to-space conversion that was previously needed
- Maintains all existing functionality for range selection ("1-3"), negation ("-s"), wildcards ("*"), and exact matches
- Reduces code by 4 lines (27 deletions vs 23 additions) while making the logic clearer

The patch follows the series' pattern of replacing problematic `strbuf_split*()` usage with more appropriate string utilities. It specifically addresses the awkwardness of `strbuf_split()`'s array-of-strbufs return value and the need for delimiter preprocessing. The change is straightforward with no behavior modifications, just cleaner implementation.
