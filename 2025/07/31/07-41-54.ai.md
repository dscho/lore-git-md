This is the final patch (9/9) in a series refactoring Git's string handling to replace `strbuf_split*()` with more appropriate alternatives. The patch focuses on sub-process status reading in `sub-process.c`.

The change simplifies the packet line parsing logic that looks for "status=<foo>" messages from subprocesses. Rather than splitting each line into an array of strbufs (which was overkill and required manual memory management), it now uses `skip_prefix()` to directly check for and extract the status value. This provides several improvements:

1. Eliminates the need for allocating and freeing temporary strbuf arrays
2. Reduces code complexity by removing the intermediate array handling
3. Maintains the same behavior where the last "status=" line wins
4. Results in a net reduction of 2 lines (-9/+7)

The change is consistent with the series' overall goal of replacing `strbuf_split*()` usage where simpler alternatives exist. This particular case shows how direct string operations can be clearer than splitting when only simple prefix matching is needed. The patch follows the established pattern of the series by reducing code while preserving functionality.

Key technical details:
- Replaces `strbuf_split_str()` with `skip_prefix()`
- Removes `strbuf_list_free()` cleanup
- Keeps same packet reading loop structure
- Maintains last-status-wins behavior
- Updates include to add `string-list.h` (though not directly used here)
