Maintainer approval for Windows CRLF fix in interactive prompts.

Junio Hamano (the Git maintainer) has reviewed and approved Johannes Sixt's fix for CRLF handling in interactive commands on Windows. The patch addresses an issue where `git reset -p` shows corrupted output due to leftover carriage returns when reading user input.

Hamano notes the explanation makes sense and expresses surprise that this long-standing issue (at least 5 years) wasn't reported earlier. The fix is minimal - replacing `strbuf_getline_lf()` with `strbuf_getline()` in `git_read_line_interactively()` to properly handle both CR and LF removal in one step.

The maintainer indicates he will queue the patch for inclusion, suggesting this straightforward fix is likely to be merged soon. While the immediate impact is limited to `git reset -p`, the underlying prompt reading function is shared by other interactive commands, so this fix may prevent similar issues elsewhere.
