This is part 4/11 of a refactoring series converting `strbuf_split*()` usage to more appropriate alternatives. The patch focuses on `builtin/clean.c`'s interactive exclude pattern handling.

The change replaces `strbuf_split_max()` with `string_list_split_in_place_f()` in the `filter_by_patterns_cmd()` function, which processes user-provided exclude patterns during interactive cleaning. The new version uses `STRING_LIST_SPLIT_TRIM` to handle whitespace trimming automatically, eliminating the need for manual `strbuf_trim()` calls. The conversion maintains all existing functionality while:
- Moving the `ignore_list` declaration into the loop scope where it's used
- Switching from array-of-strbuf to string_list iteration
- Preserving the pattern position tracking via negative numbers
- Keeping the same empty-string filtering logic
- The patch reduces the code by 2 lines (20->18) while making the pattern processing clearer
- Follows the series' pattern of replacing manual memory management with string_list
- Maintains identical behavior for interactive exclude pattern handling
- Uses `STRING_LIST_INIT_NODUP` to avoid allocations since patterns are processed immediately

This continues the series' systematic replacement of `strbuf_split*()` where `string_list` offers better ergonomics, in this case for whitespace-trimmed splitting. The change is straightforward and aligns with the series' goal of modernizing string handling while reducing code complexity.
