Refactoring patch completing a series modernizing Git's string handling by replacing `strbuf_split*()` with simpler alternatives. This final patch in the 9-part series targets subprocess status parsing in `sub-process.c`.

The change simplifies the code that reads status packets from subprocesses by replacing an over-engineered `strbuf_split_str()` approach with direct string matching using `skip_prefix()`. Instead of splitting each line into two strbufs to check for "status=", it now directly checks the line prefix and extracts the value when found. This eliminates memory management overhead while maintaining the same behavior where the last "status=" line wins.

The patch follows the series' pattern of reducing code (-9/+7 lines) while preserving functionality. It demonstrates a case where string splitting was unnecessary for the task at hand.
