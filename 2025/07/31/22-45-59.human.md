This is a refactoring series updating Git's string-list API, now at version 2 with 7 patches. Junio Hamano continues work to unify and enhance the string_list_split() and string_list_split_in_place() functions, building on the v1 series that was previously summarized.

The key additions in v2 are:
1. Two new patches (6/7 and 7/7) that add functionality to omit empty string pieces during splitting, eliminating the need for follow-up string_list_remove_empty_items() calls
2. Fixes for minor typos noted in v1's review (already incorporated into these patches)
3. The core unification work from v1 remains, now extended with these new features

The series follows a clear progression:
- Patches 1-3 establish the unified implementation foundation
- Patch 4 adds whitespace trimming capability
- Patch 5 demonstrates the payoff by simplifying diff.c's color-moved-ws parsing
- New patches 6-7 add the empty-item filtering during splitting

The changes are well-motivated, showing both immediate simplifications (like the 13-line reduction in diff.c) and laying groundwork for future extensions. The implementation appears careful, maintaining backward compatibility while adding functionality. Review feedback from v1 has been addressed, with only minor documentation fixes needed.

This continues to be a high-quality internal cleanup that improves both maintainability and potential for future enhancements to the string-list API. The v2 additions make the series even more valuable by handling another common use case (empty item removal) directly in the split operation.
