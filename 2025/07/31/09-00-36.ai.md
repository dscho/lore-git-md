Documentation patch that factors out common options for ref listing commands. This is the first of five patches in the v4 series introducing `git refs list` functionality.

The patch extracts all option documentation from `git-for-each-ref.adoc` into a new shared file `for-each-ref-options.adoc`, replacing the original content with an include directive. This prepares for sharing these option descriptions with the upcoming `git refs list` documentation while maintaining identical rendered output for `git-for-each-ref`. The change is purely organizational with no functional impact, following the series' goal of consolidating ref listing functionality. 

Key technical details: The new `for-each-ref-options.adoc` contains 79 lines of option documentation covering all existing `for-each-ref` flags including pattern matching, sorting, formatting, filtering by commit relationship, and output control. The patch maintains exact option text fidelity while enabling future reuse. This foundational change addresses prior review feedback about documentation sharing in the series.

The patch has multiple mentor sign-offs and builds on Jean-Noël Avila's documentation standardization work. It demonstrates the series' careful attention to maintainability by establishing shared documentation infrastructure before adding new commands. The clean separation of concerns here supports the architectural goal of having both `for-each-ref` and the new `refs list` share common implementation and documentation.
