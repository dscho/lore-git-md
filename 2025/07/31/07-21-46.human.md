This is a technical discussion about case sensitivity in the promisor-remote protocol implementation, part of the ongoing series to extend promisor-remote with configurable field validation.

Christian Couder responds to Junio Hamano's feedback on case sensitivity handling in the field name comparisons. The discussion focuses on whether field names (like "partialCloneFilter" and "token") should be compared case-sensitively or case-insensitively when validating promisor remote attributes.

Christian agrees to make the protocol-level field comparisons case-sensitive (changing `strcasecmp` to `strcmp` in `parse_one_advertised_remote()` and documenting this requirement), but maintains that case-insensitive comparisons are more user-friendly for config file parsing. He provides rationale about config option key comparisons being traditionally case-insensitive in Git and potential user confusion with camelCase field names.

The email also notes that v7 of the patch series incorporates Junio's earlier feedback about static initialization and pointer declaration style. Christian remains open to alternative implementations (canonicalizing field names or using enum IDs) but questions whether they would significantly simplify the code.

This represents one of the final discussion points in the otherwise technically complete series, with the implementation now addressing all previous feedback while maintaining test coverage and documentation. The case sensitivity policy appears to be the last substantive issue before potential merging.
