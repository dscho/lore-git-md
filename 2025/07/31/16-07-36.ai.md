Bugfix for Windows CRLF handling in interactive commands.

This patch addresses a specific issue where `git reset -p` fails to properly handle line endings on Windows, showing corrupted output when users respond to prompts. The problem occurs because the input processing chain incorrectly handles CRLF line endings - `strbuf_getline_lf()` removes only the LF while leaving the CR, which then causes display corruption when the CR moves the cursor to the start of the line.

The fix is straightforward: replace `strbuf_getline_lf()` with `strbuf_getline()` which properly handles both CR and LF removal in one step, eliminating the need for the subsequent `strbuf_trim_trailing_newline()` call. The change is minimal (7 lines removed, 1 added) and focused specifically on the interactive prompt reading function.

The patch includes a clear reproduction case showing the corrupted output on Windows CMD, and the technical explanation correctly identifies the interaction between the two line-ending handling functions. This appears to be a well-scoped fix for a real platform-specific issue, though it might be worth checking if other interactive commands could be affected by similar line-ending handling problems.
