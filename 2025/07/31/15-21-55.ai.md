This is the final patch in a three-part series deprecating and removing the `core.commentChar=auto` configuration option. The patch adds user-friendly advice generation when Git encounters the deprecated `auto` setting, helping users transition to explicit comment character configurations.

The implementation tracks where comment character configs are set (system/global/local/worktree) and whether they appear multiple times in config files. This allows generating precise migration instructions, including handling cases where users lack write access to system configs. The advice shows both how to unset the auto behavior (reverting to default '#') and how to set a custom comment character, with appropriate `--system`/`--global` flags based on the config file locations.

Key technical components include:
- New `comment_char_config` struct tracking config locations and scopes
- `add_config_scope_arg()` helper for generating correct CLI flags
- `can_unset_comment_char_config()` checks for write permissions
- Updated tests in t3404 and t7502 verifying both warning (pre-3.0) and error (post-3.0) behaviors with the new advice output

The patch maintains the series' dual behavior via `WITH_BREAKING_CHANGES`:
- Without flag: shows deprecation warning + advice
- With flag: dies with error + same advice (previewing Git 3.0 behavior)

This completes the deprecation process with maintainer-approved user guidance, following earlier patches that added documentation and warning infrastructure. The implementation handles edge cases like include files and multiple definitions while providing actionable migration steps.
