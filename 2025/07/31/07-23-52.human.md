This is a feature patch series (v7) extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series is technically complete with all implementation feedback addressed, CI passing, and test coverage in place.

The core change allows servers to advertise additional remote attributes (currently limited to `partialCloneFilter` and `token`) via a new `promisor.sendFields` config, while clients can validate these against local expectations using `promisor.checkFields`. The protocol enforces case-sensitive comparisons for field names while maintaining case-insensitive config values.

Key technical improvements in v7 include:
- Replaced `strbuf_split()` with `string_list_split_in_place()` for cleaner string parsing
- Removed redundant `strbuf_strip_suffix()` calls
- Clarified case sensitivity rules in documentation
- Standardized code style and memory ownership patterns

The series builds on Git's promisor-remote infrastructure as part of the larger "LOP" (Large Object Promisors) effort. While implementation is complete, two open discussion points remain: whether to use "field" or "configuration variable" terminology in the new configs, and how to handle malformed percent-encoded input. These appear to be the final blockers before potential merge.

The patchset shows thorough attention to detail with comprehensive test coverage and documentation updates. It represents a well-considered extension to Git's partial clone capabilities that maintains backward compatibility while adding useful validation controls.
