Refactoring patch that standardizes the reflog callback interface across Git's codebase. This is the first of six patches in Patrick Steinhardt's series optimizing remote ref renaming performance.

The patch modifies the `each_reflog_ent_fn` callback signature to include the refname as a parameter, eliminating the need for callers to pass it through callback data. This affects 17 files across builtins, refs handling, and test code. The change simplifies cases where callers previously had to track the refname separately, particularly in the upcoming ref migration logic (which will be simplified in the next patch).

The changes are mechanical but widespread, touching core components like `refs.[ch]`, various builtin commands, and both files and reftable backends. The patch maintains backward compatibility by updating all existing callers to handle the new parameter, though most simply mark it as unused for now. This preparatory work enables cleaner implementations in subsequent patches while being a straightforward, non-controversial change on its own.
