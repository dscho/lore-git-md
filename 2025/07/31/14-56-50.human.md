Refactoring patch in a performance optimization series for remote ref handling. This is the second of six patches in v2 of the series, following preparatory work to standardize reflog callback interfaces.

The patch simplifies reflog migration logic by eliminating a redundant `reflog_migration_data` struct. With the refname now available in callbacks (from patch 1/6), the patch moves a global index counter into the existing `migration_data` struct and removes the intermediate data structure. This maintains the same ordering guarantees while reducing indirection.

The change is straightforward - it consolidates data handling while preserving the same behavior. The patch has already been acked by Junio Hamano, indicating it's a clean improvement to the code structure. As part of a larger performance-focused series, this simplification helps pave the way for more significant optimizations in later patches while being a worthwhile cleanup on its own.
