This is a refactoring series that continues the effort to modernize Git's string handling by replacing `strbuf_split*()` usage with more appropriate alternatives. The 11-patch series builds on previous work to extend the `string_list` API, now targeting additional subsystems including `trace2` and cleaning up some edge cases.

Junio Hamano leads with a clear rationale: `strbuf_split*()` often creates an array of strbufs when simpler string handling would suffice, particularly when the main goal is whitespace trimming. The series demonstrates consistent patterns across multiple files:
- Replaces `strbuf_split*()` with `string_list_split*()` where trimming is needed
- Uses direct string operations like `skip_prefix()` when possible
- Maintains existing behavior while reducing code complexity
- Adds two new patches (10-11) addressing `strbuf_split*()` in trace2 config handling

Notable changes include:
- Patch 6 simplifies notes stdin parsing while preserving two-token validation
- Patch 7 improves `GIT_CONFIG_PARAMETERS` parsing with better delimiter handling
- Patch 9 eliminates temporary strbuf allocations in sub-process status reading
- New trace2 patches remove redundant trimming and split operations

The series shows net code reduction (-137/+125) and appears ready for merging as a focused, non-controversial improvement to Git's string handling internals. It follows established patterns from earlier conversions while expanding to new subsystems.
