Refactoring patch in a series converting string handling from `strbuf_split*()` to `string_list_split*()`.

This patch (6/9) updates the notes subsystem's stdin parsing in `builtin/notes.c` to use `string_list_split_in_place_f()` with `STRING_LIST_SPLIT_TRIM` for processing copy instructions. The change simplifies whitespace handling by eliminating manual `strbuf_rtrim()` calls and replaces the `strbuf_list_free()` cleanup with `string_list_clear()`. The input format remains unchanged - each line must contain at least two whitespace-separated refs (from/to object names), though the patch notes the existing leniency toward extra tokens is preserved rather than fixed.

Key technical details:
- Maintains identical error checking via `split.nr` count
- Preserves the two main code paths (direct copy vs rewrite-cmd handling)
- Changes object reference access from `split[0]->buf` to `split.items[0].string`
- Shows a net reduction (-11/+12 lines) typical for this conversion pattern

The patch follows the series' established approach of mechanical replacements where `string_list` offers cleaner whitespace handling, though it notes the existing loose input validation (ignoring extra tokens) remains unaddressed as out of scope. This continues the thread's theme of focused, non-disruptive refactoring that reduces manual memory management while keeping behavior identical.
