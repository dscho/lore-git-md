This is a bugfix addressing a Windows-specific issue with interactive commands like `git reset -p`. 

The patch fixes a problem where the interactive prompt incorrectly processes user input containing CRLF line endings on Windows. Currently, when a user responds to prompts (like "Unstage this hunk?"), the input parsing gets confused by the carriage return, leading to corrupted error messages like "'nly one letter is expected" instead of "Only one letter is expected".

The root cause is a subtle interaction between two functions: `strbuf_getline_lf()` removes just the LF while `strbuf_trim_trailing_newline()` expects to handle full CRLF sequences. The fix simplifies the code by using `strbuf_getline()` which properly handles both CR and LF removal in one step.

The change is small (just 7 lines removed, 1 added) but effectively solves the Windows command-line usability issue. The patch appears well-targeted, with a clear explanation of both the symptom and solution in the commit message. This should improve the experience for Windows users running Git in CMD without affecting other platforms.
