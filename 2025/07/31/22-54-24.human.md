Refactoring patch in the string handling series, addressing a potential memory safety issue in `builtin/clean.c`. This is patch 2/11 in Junio Hamano's series modernizing string processing across Git.

The patch fixes a dangerous pattern where `parse_choice()` was taking a `strbuf` by value rather than by pointer. While this appeared to work in practice, it created a subtle memory management hazard - if the callee caused the `strbuf` to reallocate, the caller's buffer would become invalid, risking a double-free. The fix changes the parameter to pass by pointer, which is the correct way to handle `strbuf` structures that contain pointer members.

The change maintains all existing functionality for processing user input in the interactive clean command, including both comma and space separated choice lists. It's a straightforward but important fix that eliminates a latent bug while fitting into the broader series' goal of improving string handling safety and clarity.
