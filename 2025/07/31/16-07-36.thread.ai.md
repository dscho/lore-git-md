Bugfix for Windows CRLF handling in interactive commands, specifically `git reset -p`.

The thread addresses a Windows-specific issue where interactive commands show corrupted output due to incorrect CRLF line ending handling. The problem stems from `strbuf_getline_lf()` removing only LF while leaving CR, causing cursor movement artifacts. Johannes Sixt proposed replacing it with `strbuf_getline()` in `git_read_line_interactively()` (prompt.c) to properly handle both CR and LF removal, eliminating the need for `strbuf_trim_trailing_newline()`. The change is minimal (7 lines removed, 1 added).

Junio C Hamano confirmed the fix, noting the explanation makes sense and expressing surprise this longstanding issue (5+ years) wasn't reported earlier. The patch is accepted for inclusion. While focused on `git reset -p`, the solution in prompt.c could affect other interactive commands using the same input reading function. The immediate issue is considered resolved, though the question of whether other commands need similar fixes remains open but unexplored in this thread.
