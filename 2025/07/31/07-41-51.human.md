This is part 6 of a 9-patch refactoring series converting Git's string handling from `strbuf_split*()` to `string_list_split*()`. The patch focuses on `builtin/notes.c`, specifically the stdin parsing in `notes_copy_from_stdin()`.

The change replaces `strbuf_split()` with `string_list_split_in_place_f()` for processing note copy instructions, using the `STRING_LIST_SPLIT_TRIM` flag to handle whitespace trimming during splitting. The conversion maintains the same input format requiring at least two tokens per line (source and destination refs) while ignoring extra tokens, though the author notes this loose validation could be tightened in future work.

The patch shows a typical net reduction (-11/+12 lines) by eliminating manual `strbuf` management in favor of `string_list`'s built-in memory handling. Like others in the series, this is a straightforward conversion that preserves behavior while modernizing the code. The change affects note copying functionality when reading instructions from stdin, used by commands like `git notes copy --stdin`.
