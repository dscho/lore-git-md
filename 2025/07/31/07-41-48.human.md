This is part 3 of a 9-patch series refactoring Git's string handling to use `string_list` instead of `strbuf` where appropriate. The patch focuses on `builtin/clean.c`, specifically the `parse_choice()` function used in interactive `git clean` for processing user selections.

The change replaces `strbuf_split()` with `string_list_split_in_place()`, which offers several advantages: it eliminates the need to preprocess commas into spaces (since the new API handles multiple delimiters natively), removes temporary strbuf management, and follows the project's preferred string handling patterns. The conversion maintains all existing functionality for processing number ranges (like "1-3"), prefixes (like "s" for select), and special cases like "*" for "select all".

The patch is a straightforward mechanical conversion that reduces line count while preserving behavior. It's part of a larger, well-motivated effort to modernize Git's string handling code. The changes are focused and non-controversial, building on previous API improvements to `string_list`.
