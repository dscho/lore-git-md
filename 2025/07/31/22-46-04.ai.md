This is a refactoring patch that demonstrates the practical benefits of the string-list API improvements from earlier in the series. Patch 5/7 in Junio Hamano's v2 series simplifies the parsing of `diff.colormovedws` configuration values by leveraging the new `STRING_LIST_SPLIT_TRIM` functionality.

The patch removes manual string trimming in `diff.c` by using the new `string_list_split_f()` API with the `STRING_LIST_SPLIT_TRIM` flag. Previously, the code would split the comma-separated config values, then manually trim each resulting string using a `strbuf`. Now the trimming happens automatically during the split operation, allowing direct comparison of the pre-trimmed `i->string` values. The change reduces 13 lines of code to 7 while maintaining identical functionality.

Key technical points:
- Modifies `parse_color_moved_ws()` in `diff.c` to use the new flag-based API
- Eliminates temporary `strbuf` allocations and manual trimming operations
- Preserves all existing error handling and validation logic
- Demonstrates real-world simplification enabled by the API changes from patches 1-4
- Maintains backward compatibility since the behavior remains identical

This patch serves as a practical demonstration of how the string-list API improvements can simplify caller code. It's a straightforward application of the new functionality with no behavioral changes, showing the series' benefits in a real context. The change is low-risk since it touches only one well-contained function and the test coverage for color-moved whitespace handling remains unchanged.
