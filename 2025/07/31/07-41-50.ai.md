This is part 5 of a 9-patch refactoring series converting string splitting operations from `strbuf` to `string_list` APIs. The patch focuses on `builtin/merge-tree.c`, specifically the input parsing logic for merge instructions.

The change replaces `strbuf_split()` with `string_list_split_in_place_f()` for parsing stdin input lines, using the `STRING_LIST_SPLIT_TRIM` flag to handle whitespace trimming during splitting. Key technical aspects include:

1. The input format remains unchanged - lines are split on spaces with optional `--` merge-base marker
2. Error checking is simplified by using `split.nr` (number of items) rather than checking array elements
3. The patch maintains two valid input patterns:
   - `base -- left right` (4 tokens with merge base)
   - `left right` (2 tokens without merge base)
4. Memory management is cleaner with `string_list_clear()` replacing manual `strbuf_list_free()`
5. The diff shows a net reduction of 2 lines (-14/+12) while improving readability

This follows the series' pattern of mechanical conversions where `string_list` provides better ergonomics for whitespace-heavy parsing. The change is low-risk as it preserves all existing behavior while eliminating manual string trimming operations.
