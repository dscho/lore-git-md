This is the first patch in an 11-part refactoring series converting Git's string handling from `strbuf_split*()` to more appropriate alternatives, primarily `string_list_split*()`. The patch focuses on `wt-status.c`'s `abbrev_oid_in_line()` function which processes rebase todo list lines.

The change replaces the existing `strbuf_split_max()` usage with `string_list_split()` for parsing rebase todo lines (like "pick <oid> title"). The key improvements are:
- Eliminates manual memory management of the temporary `strbuf` array
- Simplifies the code by using direct string access via `string_list`
- Maintains identical behavior for OID abbreviation
- Reduces line count from 31 to 10 (net -21)
- Preserves the special handling of "exec", "x", "break", and "l" commands

The conversion follows the series' pattern of moving away from `strbuf_split*()` where simultaneous string editing isn't needed, as noted in the commit message. This initial patch establishes the approach that subsequent patches in the series will apply to other subsystems. The change is straightforward and non-controversial, with no behavior changes beyond the internal implementation.
