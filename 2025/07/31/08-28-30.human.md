This is a preparatory refactoring patch in a performance optimization series for remote ref operations. It modifies the reflog entry callback interface to include the reference name as a parameter, simplifying callers that need this information (particularly the upcoming ref migration logic changes). The change affects 17 files but is straightforward, just adding the new parameter consistently across all implementations.

Karthik Nayak confirms this addresses real pain points he encountered in the migration code, and Patrick Steinhardt has accepted minor formatting suggestions but won't respin just for those. The patch has already received positive review from Justin Tobler as part of the larger series, indicating it's a well-scoped foundational change that enables the subsequent performance fixes.

This is infrastructure work rather than a direct optimization itself, but it's part of a series that ultimately delivers dramatic speedups (hours to seconds for large ref counts). The maintainer has already approved the full set of changes, with this first patch being the least controversial piece that standardizes an awkward interface.
