This is part 3 of a 5-patch series extending the promisor-remote protocol to support configurable validation of remote attributes. The series is currently at v7 with implementation complete, pending final terminology decisions.

The patch refactors the parsing logic for promisor remote advertisements into a new `parse_one_advertised_remote()` function that populates a `struct promisor_info`. This centralizes the parsing logic that was previously scattered across multiple functions. Key changes include:

- Introduces a new `promisor_info_free()` helper to consistently handle memory cleanup
- Replaces direct field parsing with structured population of `struct promisor_info`
- Updates `should_accept_remote()` to take the structured info rather than raw strings
- Uses `string_list_split_in_place()` for cleaner parsing of remote info strings
- Maintains all existing functionality while preparing for additional field support

The refactoring is part of the series' goal to enable servers to advertise additional remote attributes (like partialCloneFilter and token) while allowing client validation. This particular patch focuses on the foundational parsing infrastructure, making the code more maintainable and extensible for the new fields being added in subsequent patches.

The changes appear well-contained and focused on the stated goal, with no behavior changes intended. The patch builds on the series' earlier introduction of `struct promisor_info` to replace parallel strvec arrays, continuing the move toward type safety and clearer structure. Test coverage for the existing functionality remains intact, though new tests for the additional fields will come in later patches.
