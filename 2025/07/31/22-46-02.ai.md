Refactoring of Git's string-list API, part 3/7 in Junio Hamano's series. This patch unifies the implementations of `string_list_split()` and `string_list_split_in_place()` into a single internal helper function `split_string()`, with the public functions becoming thin wrappers around it.

The key technical changes are:
- Introduces a new `append_one()` helper that handles the string copying vs in-place modification distinction between the two split variants
- Moves common splitting logic into `split_string()` which now takes an `in_place` parameter
- Maintains all existing behavior while reducing code duplication
- Adds BUG() checks for invalid strdup_strings configurations
- Uses strpbrk() consistently for delimiter handling (established in patch 2)

The patch builds on patch 2's delimiter unification and prepares for future flag additions (mentioned in the commit message) by centralizing the core splitting logic. The implementation carefully preserves the const-correctness requirements of the two public APIs while sharing their internals. This is a clean internal refactoring with no expected behavior changes for callers.
