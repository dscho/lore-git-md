This is a feature series extending the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations. The series is now at v7 with implementation complete, pending final terminology decisions.

The core change allows servers to advertise additional remote attributes (currently limited to `partialCloneFilter` and `token`) via a new `promisor.sendFields` config, while clients can validate these against local expectations using `promisor.checkFields`. The protocol enforces case-sensitive field name comparisons while maintaining case-insensitive config handling.

Key technical changes in v7:
- Replaced `strbuf_split()` with `string_list_split_in_place()` for parsing
- Removed redundant `strbuf_strip_suffix()`
- Clarified case sensitivity rules in protocol documentation
- Fixed style issues and static initialization
- Maintained existing memory ownership model

The series builds on the promisor-remote infrastructure and is part of the larger "LOP" (Large Object Promisors) effort. CI tests confirm the implementation works as expected. Remaining open questions center on terminology ("field" vs "configuration variable") and error handling strategy for malformed input, though these don't block the technical implementation.

The patches show careful attention to detail with thorough test coverage and documentation updates. The v7 changes address all substantive feedback from reviewers, leaving only minor terminology preferences to resolve. This appears ready for final review pending resolution of the remaining non-technical discussion points.
