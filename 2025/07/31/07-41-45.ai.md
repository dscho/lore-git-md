This is a refactoring series targeting the overuse of `strbuf_split*()` functions in the Git codebase. The cover letter makes the case that `strbuf_split*()` is often misused when `string_list_split*()` would be more appropriate, particularly for common operations like whitespace trimming. The series builds on previous work extending the string list API to handle multiple delimiters and trimming.

The 9 patches systematically replace `strbuf_split*()` usage across several subsystems:
- `wt-status` and `clean` (multiple patches for the latter)
- `merge-tree` and `notes` commands
- Core components like `config`, `environment`, and `sub-process`

The changes are mechanical conversions that don't appear to change behavior, just the underlying string handling implementation. The diffstat shows a net reduction in lines (-113/+103) suggesting some code simplification. The patches touch a mix of command implementations and core infrastructure, with `clean.c` seeing the most extensive changes.

This appears to be part of an ongoing effort to modernize string handling in the codebase, following improvements to the `string_list` API. The changes are focused and well-scoped, with each patch targeting a specific component. The cover letter provides clear rationale for why these changes are worthwhile, though it doesn't cite specific performance or maintenance benefits beyond general code quality.
