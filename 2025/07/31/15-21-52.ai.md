This is the final cover letter for a three-part series deprecating and removing the problematic `core.commentChar=auto` configuration option, following extensive discussion and maintainer approval. The series implements a planned breaking change that will make Git error out when encountering this setting in Git 3.0, with clear deprecation warnings and migration advice in the meantime.

The series has been reworked since v1 based on feedback, splitting the implementation into clearer logical steps: documentation updates, config warning infrastructure, and commit-specific advice generation. The patches now properly handle configuration scopes and include files when generating advice, and will die with an error when `WITH_BREAKING_CHANGES` is enabled (previewing the Git 3.0 behavior).

Key technical changes include a new `struct comment_char_cfg` to track config state, updates across multiple builtin commands (commit, merge, rebase, revert), and test updates in several interactive workflow test files. The advice generation has been simplified to leverage `git config list --show-scope` as suggested by Oswald Buddenhagen and approved by Junio Hamano.

The cover letter provides a concrete example of the deprecation warning output, showing how it guides users through either removing the setting or choosing an explicit comment character. The change addresses known bugs where the auto` heuristic fails with commit templates and rebase operations, while modern Git's support for multi-byte comment strings reduces the need for automatic selection.

This represents the culmination of a long-running discussion about removing this problematic feature, with all technical and user experience questions now resolved. The series is ready for final review and merging, with Phillip Wood indicating it will be submitted imminently.
