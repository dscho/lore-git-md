This is patch 4/5 in Junio Hamano's string-list API refactoring series, introducing optional whitespace trimming functionality to the string splitting operations. Building on the unified `split_string()` helper established in patch 3, this change adds a flags parameter with `STRING_LIST_SPLIT_TRIM` as its first flag, which when set will trim whitespace from both ends of each split string piece before adding it to the list.

The implementation modifies the core `append_one()` helper to handle right-trimming and adds left-trimming logic in `split_string()`. Two new public functions are introduced (`string_list_split_f()` and `string_list_split_in_place_f()`) to expose the flags parameter while maintaining backward compatibility with the existing functions. The patch includes comprehensive unit tests demonstrating the trimming behavior with various edge cases: leading/trailing whitespace, multiple spaces, and combinations with maxsplit limits.

This change completes the functionality previewed in the series' earlier patches, showing how the unified implementation allows new features to be added consistently to both split variants. The implementation carefully preserves the existing behavior when the flag is not set, ensuring no regression for existing callers. With this addition, the string-list API now offers more flexible string splitting capabilities while maintaining its clean internal structure.
