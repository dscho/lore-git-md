Refactoring patch in a series modernizing string handling. This is part 5 of 9 in Junio C Hamano's series converting `strbuf_split*()` calls to `string_list_split*()` where appropriate.

The patch updates `builtin/merge-tree.c` to use `string_list_split_in_place_f()` for parsing merge instructions from stdin, replacing the previous `strbuf_split()` approach. The key changes are:

1. Uses `STRING_LIST_SPLIT_TRIM` to handle whitespace trimming during splitting rather than manual `strbuf_rtrim()` calls
2. Simplifies the parsing logic by checking `split.nr` (number of items) rather than array indexing
3. Maintains the same input validation and error messages
4. Reduces code by eliminating temporary strbuf management (-14/+16 lines)

The change follows the series' pattern of mechanical conversions where `string_list` provides cleaner handling of whitespace-trimmed splits. The patch appears straightforward with no behavior changes, just internal API modernization. As with previous patches in the series, this is a focused improvement that builds on Git's ongoing string handling cleanup efforts.
