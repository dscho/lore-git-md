This is the 4/5 patch in a series extending the promisor-remote protocol to support configurable validation of remote attributes. The patch implements client-side validation of additional fields ("partialCloneFilter" and "token") that servers can advertise.

The patch introduces a new `promisor.checkFields` configuration variable that lets clients specify which fields to validate before accepting a promisor remote. The validation requires three conditions: the field must be locally configured, advertised by the server, and have matching values (case-sensitive comparison). The implementation builds on the `struct promisor_info` infrastructure introduced earlier in the series.

Key technical details include:
- New `fields_checked()` helper to parse the config
- `match_field_against_config()` and `all_fields_match()` functions implementing the validation logic
- Integration with existing `should_accept_remote()` flow
- Comprehensive tests showing field validation in action
- Documentation explaining the validation rules and use cases

The validation is particularly useful for ensuring filter consistency (preventing mismatched partial clone filters) and verifying authentication tokens. The patch maintains the series' case sensitivity approach (strict protocol-level comparisons but case-insensitive config parsing).
