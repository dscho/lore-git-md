This is part 3/11 of a refactoring series replacing `strbuf_split*()` with safer string handling alternatives. The change focuses on `builtin/clean.c`'s interactive menu parsing.

The patch converts `parse_choice()` from using `strbuf_split()` to `string_list_split_in_place()`, which offers several improvements. The function processes user input for Git's interactive clean menu, handling both comma/space separated lists and range selections (like "1-3"). The new version eliminates manual string buffer management while maintaining all existing functionality - it still supports the same input formats, error checking, and selection logic.

Key changes include:
- Replacing the temporary `strbuf` array with a `STRING_LIST_INIT_NODUP` string list
- Removing the need to pre-process commas into spaces
- Simplifying the parsing loop using `for_each_string_list_item`
- Keeping identical behavior for range validation and error messages

The conversion follows the series' pattern of moving away from `strbuf_split*()` due to its awkward memory management, while demonstrating `string_list`'s advantages for delimiter-heavy parsing. The patch is a straightforward, well-contained refactoring that reduces code by 4 lines while improving safety.
