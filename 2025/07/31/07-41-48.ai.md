Refactoring patch in the `git clean` string handling conversion series. This is the third patch in a 9-part series replacing `strbuf_split*()` with `string_list_split*()` across Git's codebase.

The patch focuses on `parse_choice()` in `builtin/clean.c`, which handles interactive selection parsing for `git clean`. The function previously used `strbuf_split()` to process comma/space-separated input into temporary strbufs, requiring manual comma-to-space conversion. The new version uses `string_list_split_in_place_f()` which natively handles multiple delimiters (comma or space) and trimming, eliminating the need for preprocessing.

Key technical changes include:
- Replaces strbuf array with `STRING_LIST_INIT_NODUP` for direct string access
- Uses new multi-delimiter support ("\n" for single, ", " for multiple selections)
- Maintains identical parsing logic for ranges (1-3), prefixes ('s'), and special cases ('*')
- Preserves all error handling and output formatting
- Reduces line count (-4 net) while improving memory safety

The change aligns with the series' goal of phasing out problematic `strbuf_split()` usage while demonstrating `string_list`'s advantages for delimiter-heavy parsing. The patch appears well-contained, touching only the parsing logic while keeping the surrounding menu selection behavior identical. This conversion precedes more extensive `clean.c` changes in later series patches.
