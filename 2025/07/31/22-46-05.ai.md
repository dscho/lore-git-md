This is patch 6/7 in Junio Hamano's string-list API refactoring series, introducing a new STRING_LIST_SPLIT_NONEMPTY flag to omit empty string pieces during splitting operations. The patch builds on the unified split_string() helper established in earlier patches, adding empty-string filtering directly into the split operation rather than requiring post-processing with string_list_remove_empty_items().

The core change modifies the append_one() helper function to skip adding empty strings when the NONEMPTY flag is set, checking for empty segments (where end <= p) before appending. The flag is defined in string-list.h alongside the existing STRING_LIST_SPLIT_TRIM flag, and comprehensive tests are added to u-string-list.c covering various edge cases: leading/trailing/multiple delimiters, combinations with the TRIM flag, and cases with no empty strings to verify the flag doesn't break normal operation.

The implementation maintains the series' pattern of extending functionality while preserving backward compatibility. This follows the methodical progression seen in previous patches, where foundational changes (error handling, delimiter unification) enabled feature additions (trimming, now empty-string omission) that simplify caller code. The tests demonstrate the standalone use of NONEMPTY as well as its combination with TRIM, showing how the flags compose cleanly in the unified API.
