This is patch 4/5 in Junio Hamano's series refactoring Git's string-list API, introducing optional whitespace trimming for split string pieces. The patch adds a new `STRING_LIST_SPLIT_TRIM` flag that, when set, will trim both leading and trailing whitespace from each split piece before adding it to the string list.

The implementation modifies the shared `split_string()` helper introduced in earlier patches to handle trimming, adding new `_f` variants of both split functions that accept flags. The changes include comprehensive unit tests demonstrating the trimming behavior with various edge cases (empty strings, multiple spaces, maxsplit limits). The patch maintains backward compatibility by keeping the original functions as wrappers that pass 0 for flags.

This continues the series' pattern of unifying functionality between the in-place and copying split variants while adding new capabilities. The changes are well-contained and thoroughly tested, with clear documentation of the new flag. As with previous patches in the series, this appears to be a straightforward internal API improvement that builds logically on the foundation laid by earlier refactoring.
