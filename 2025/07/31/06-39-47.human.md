This is the third patch in a refactoring series for Git's string-list API, focusing on unifying the implementations of `string_list_split()` and `string_list_split_in_place()`. The patch consolidates the nearly identical logic of these two functions into a single internal helper function called `split_string()`, with each original function becoming a thin wrapper around it.

The key difference between the two functions remains preserved: `string_list_split()` works on a const string and makes copies of the split pieces, while `string_list_split_in_place()` modifies the original string. The unification makes the core splitting logic DRY (Don't Repeat Yourself) while maintaining the distinct behaviors needed by callers. The patch includes safety checks to ensure each wrapper is used correctly with respect to the list's string-duplication setting.

This change is part of a larger effort to clean up and standardize the string-list API, following earlier patches that aligned delimiter handling between the functions. The implementation is clean and maintains all existing functionality while paving the way for future extensions via a flags parameter that could be added to the internal helper. The changes are confined to string-list.c with no impact on callers, showing good separation of concerns.
