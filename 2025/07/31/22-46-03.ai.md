This is patch 4/7 in Junio Hamano's string-list API refactoring series, introducing whitespace trimming functionality to string splitting operations. The patch adds a new STRING_LIST_SPLIT_TRIM flag that automatically trims whitespace from both ends of each split string before adding it to the string list.

The implementation modifies the internal split_string() helper and append_one() function to handle trimming, adding both left-trim (during scanning) and right-trim (before appending) operations. Two new public API functions are introduced: string_list_split_f() and string_list_split_in_place_f() that accept the flags parameter, while maintaining backward compatibility with the existing non-flag versions.

Key technical details include:
- The trimming occurs during the split operation itself rather than requiring a separate pass
- Both leading and trailing whitespace are removed (using isspace())
- The existing test file is extended with new test cases demonstrating the trimming behavior
- The implementation handles edge cases like empty strings and maxsplit limits correctly
- The patch follows the series' pattern of unifying functionality between the in-place and copying variants

This builds on the previous patches' unification work while adding new functionality in a way that maintains the API's clean separation of concerns. The tests verify both basic functionality and interaction with other features like maxsplit. As with the rest of the series, the changes are focused and well-contained within the string-list subsystem.
