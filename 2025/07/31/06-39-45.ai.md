This is a refactoring patch that changes error reporting in Git's string-list API. It's the first in a 5-part series modernizing the string-list splitting functions.

The patch notes that passing incorrectly configured string_list structs to either `string_list_split()` or `string_list_split_in_place()` constitutes a programming error. Currently these cases trigger `die()`, but the patch changes them to use `BUG()` instead, which is Git's preferred mechanism for reporting unrecoverable programming errors. The error messages themselves remain unchanged for now, though the commit suggests they could be made more concise in the future.

The change affects both split functions in string-list.c, modifying their error handling paths while leaving the core functionality intact. This appears to be a straightforward improvement to error reporting consistency, aligning with Git's conventions for internal API usage. The patch is small (4 lines changed) and focused, serving as groundwork for the subsequent changes in the series that will refactor and enhance the string-list splitting behavior.
