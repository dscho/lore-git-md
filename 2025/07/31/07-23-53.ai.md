This is the first patch in a 5-part series refactoring the promisor-remote protocol to support configurable validation of remote attributes. The patch introduces foundational changes to prepare for handling additional remote fields beyond just name and URL.

The patch replaces the existing `struct strvec`-based storage of promisor remote information with a new `struct promisor_info` that explicitly stores name and URL fields. This provides type safety and clearer documentation of the data structure's purpose. The change moves from parallel arrays (one strvec for names, another for URLs) to a unified string_list where each item contains both fields in a single struct.

Key technical changes include:
- New `struct promisor_info` with `name` and `url` members
- `promisor_config_info_list()` populates the new structure from config
- `promisor_info_list_clear()` handles memory cleanup
- Updated `should_accept_remote()` to work with the new structure
- Removal of the `remote_nick_find()` helper now that string_list provides lookup

The refactoring maintains all existing functionality while making the code more maintainable for the planned extensions. The patch is well-contained, touching only promisor-remote.c, and includes thorough updates to all affected code paths. This foundational work enables the subsequent patches in the series to add support for additional remote attributes and their configuration.

The implementation appears solid, with proper memory management and preservation of existing behavior. The commit message clearly explains the motivation and technical approach. This is a typical preparatory refactoring that makes the codebase more amenable to the feature additions coming in later patches.
