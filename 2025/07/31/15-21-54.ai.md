This is the second patch in a three-part series deprecating and removing the `core.commentChar=auto` configuration option. The patch introduces warning infrastructure for the deprecated setting, with behavior that differs based on whether `WITH_BREAKING_CHANGES` is enabled.

The implementation adds a new warning system` that triggers when running commit-related commands (commit, merge, rebase, revert). Without `WITH_BREAKING_CHANGES`, it prints a one-time warning about the deprecation using an environment variable to prevent duplicate warnings. With `WITH_BREAKING_CHANGES` enabled (representing Git 3.0+ behavior), it instead dies with an error message.

Key technical changes include:
- New `warn_on_auto_comment_char` flag in environment.h
- `struct comment_char_config` to track which config key was used (`core.commentChar` or `core.commentString`)
- Modified `repo_read_config()` to check for deprecated settings
- Test updates in t3404-rebase-interactive.sh and t7502-commit-porcelain.sh showing both warning and error behaviors
- Special handling in `repo_config_set_multivar_in_file_gently()` to suppress warnings during config changes

The patch maintains backward compatibility while preparing for the eventual removal, with clear transition behavior documented in the tests. The implementation follows the maintainer-approved approach from earlier discussion, using the new config checking infrastructure to provide targeted warnings only when needed.
