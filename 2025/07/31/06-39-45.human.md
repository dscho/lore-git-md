This is the first patch in a refactoring series for Git's string-list API. The change converts error messages from `die()` to `BUG()` when the string-list functions `string_list_split()` and `string_list_split_in_place()` are called with incorrect `strdup_strings` settings. This is a clear programming error case where the API is being misused, so using `BUG()` is more appropriate than `die()`.

The patch is straightforward and uncontroversial, touching only two lines in string-list.c. It's part of a larger 5-patch series from Junio Hamano that aims to improve and unify the string-list splitting functionality. The commit message notes that the error message could be more concise (as it's developer-facing), but leaves that for potential future cleanup.

This appears to be a solid internal improvement that better matches Git's error handling conventions for programming mistakes. The change is small but meaningful, and since it comes from the Git maintainer as part of a coordinated series, it's likely to be merged without controversy.
