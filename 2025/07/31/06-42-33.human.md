This is the first patch in the v6 series implementing the new `git last-modified` command, which tracks file modifications at the tree level rather than line-by-line like `git blame`. Patrick Steinhardt provides detailed code review feedback on the implementation details.

The review focuses on documentation style (suggesting long option names be included in synopses), code clarity (requesting more comments around the diffopt copying logic), and stylistic consistency (noting unusual assignment-in-condition patterns). Patrick also questions the need for explicit output flushing and suggests renaming the `--tree-in-recursive` option to something clearer like `--recursive-with-trees`.

Several technical points are raised about edge case handling - particularly around rename detection and mode changes - with suggestions to document these behaviors in the manual. The review maintains a constructive tone while identifying areas where the implementation could be made more robust or consistent with Git's coding style.

This patch establishes the core algorithm with hashmap tracking and merge commit support, and Patrick's feedback helps refine the implementation details before the series moves forward. The review doesn't challenge the fundamental design but focuses on polish and maintainability concerns.
