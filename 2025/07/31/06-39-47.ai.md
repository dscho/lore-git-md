Refactoring patch in the string-list API unification series. This is patch 3/5 in Junio Hamano's series to consolidate the string-list splitting functions.

The patch merges the implementations of `string_list_split()` and `string_list_split_in_place()` into a shared helper function `split_string()`, with the original functions becoming thin wrappers. The key differences between the functions (const vs mutable input, string duplication behavior) are now handled via an `in_place` parameter in the unified implementation. The change includes safety checks via `BUG()` for incorrect `strdup_strings` configurations.

Technical details: The new `split_string()` helper takes all parameters from both original functions plus the `in_place` flag. It uses `strpbrk()` for delimiter handling (established in patch 2) and delegates to `append_one()` for the actual string storage, which either duplicates strings or modifies them in place based on the flag. The implementation carefully handles const-correctness through a documented cast when operating in-place.

This refactoring prepares for future extensions (mentioned in the commit message) where new functionality could be added to both split variants by modifying only the shared helper. The changes maintain all existing behavior while reducing code duplication - a clean internal API improvement that builds on the delimiter unification from the previous patch.
