Refactoring patch converting `strbuf_split*()` to `string_list_split*()` in `wt-status.c`.

This is the first patch in a 9-part series modernizing Git's string handling by replacing `strbuf_split*()` with `string_list_split*()` where appropriate. The patch focuses on `wt-status.c`'s `abbrev_oid_in_line()` function, which processes rebase todo list lines to abbreviate object names.

The function previously used `strbuf_split_max()` to split lines into tokens stored as strbufs, despite only needing string content without strbuf operations. The new version uses `string_list_split()` which better matches the actual usage pattern. The change simplifies the code by eliminating temporary strbuf management while maintaining identical behavior - it still handles the same rebase commands (`exec`, `x`, `label`, `l`) and abbreviates object names in the second token position.

Key technical details: The patch removes 21 lines while adding 10, demonstrating the simplification. It introduces a `string_list` struct to hold split tokens and modifies the reassembly logic to use direct string access rather than strbuf operations. The core functionality (oid abbreviation via `repo_get_oid` and `strbuf_add_unique_abbrev`) remains unchanged.

This appears to be a straightforward, mechanical conversion that improves code clarity by using the more appropriate string_list API for this read-only string splitting use case. The change aligns with the series' broader goal of modernizing string handling while being a self-contained, low-risk modification to a specific subsystem.
