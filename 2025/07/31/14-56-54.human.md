Performance optimization for remote ref renaming, final patch in a series addressing quadratic behavior in remote operations. This sixth patch introduces `refs_for_each_rawref_in()` to only iterate through relevant refs when renaming a remote, rather than scanning all refs and filtering in the callback. The change provides measurable speedups: 1.35x faster for the files backend and 2.07x for reftable in benchmarks renaming a remote with 100k unrelated refs. The implementation moves prefix filtering into the refs backend by adding the new iterator API and updating `builtin/remote.c` to use it.

This completes the series' transition from O(n^2) to linear scaling for remote renames. The patch builds on previous work standardizing reflog callbacks and restructuring transactions, with the reftable backend showing particularly strong gains (8.8ms vs original 18.2ms). While focused on the rename operation, the new `refs_for_each_rawref_in()` may be useful for other prefix-limited ref iterations. The series has been reviewed and acked, with this final patch maintaining the atomicity guarantees established earlier while eliminating unnecessary iteration overhead.
