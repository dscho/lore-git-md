Refactoring patch in a series modernizing string handling by replacing `strbuf_split*()` with more appropriate alternatives.

This is patch 5/11 in Junio Hamano's series converting Git's string processing to use better-suited utilities. The patch refactors `builtin/merge-tree.c`'s input parsing to use `string_list_split_in_place_f()` instead of `strbuf_split()`. Key changes include:

1. Replaces the manual `strbuf_split()` + per-item `strbuf_rtrim()` pattern with a single `string_list_split_in_place_f()` call using `STRING_LIST_SPLIT_TRIM`
2. Simplifies error checking by using `split.nr` rather than array indexing
3. Maintains the same input validation for both merge-base and non-merge-base cases
4. Preserves the dual input format handling (with/without merge-base)
5. Reduces code by 2 lines (30->28) while making the input validation clearer

The patch follows the series' established pattern of replacing manual string handling with more robust utilities while maintaining identical functionality. The changes are straightforward and align with the thread's goal of modernizing string processing across Git's codebase.
