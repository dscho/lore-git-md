Refactoring patch in a series modernizing Git's string handling. This is patch 6/11, converting `notes.c`'s stdin parsing from `strbuf_split()` to `string_list_split()` with automatic whitespace handling.

The change simplifies the code that reads note-copying instructions from stdin, where each line contains two whitespace-separated object IDs. The new version uses `string_list_split_in_place_f()` with `STRING_LIST_SPLIT_TRIM` to handle splitting and trimming in one operation, replacing the previous approach of splitting first then trimming each token separately. This reduces manual memory management while maintaining the same validation (requiring exactly two tokens per line) and error handling.

The patch follows the series' pattern of replacing `strbuf_split*()` calls with more appropriate alternatives, here achieving a net reduction of 11 lines removed vs 12 added. The author notes that while the code still loosely handles extra tokens (only checking for minimum two), tightening this behavior is considered out of scope for this refactoring series.
