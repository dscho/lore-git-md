This is a bugfix patch in the ongoing string handling refactoring series. It addresses a dangerous strbuf usage pattern in `builtin/clean.c` where a strbuf was being passed by value to `parse_choice()`, risking memory corruption.

The key issue is that passing a strbuf by value while it contains pointers (to its buffer) creates a potential double-free scenario if the callee reallocates the buffer. The patch changes the function signature to take a pointer to the strbuf instead, which is the correct way to handle strbuf parameters.

The change affects interactive selection in `git clean` when processing user input for multiple selections. The patch maintains all existing functionality (comma/space separated choices, singleton mode) while fixing the memory safety issue. This is a straightforward fix that aligns with the series' broader goal of improving string handling safety and correctness.

The modification is minimal (5 line changes) and focused, touching only the parameter passing and subsequent access patterns in `parse_choice()`. This patch follows logically from the series' work on `clean.c` seen in earlier thread discussion (patch 4/11), though it addresses a different aspect of string handling than the main series focus on replacing `strbuf_split*()` calls.
