Performance optimization patch in the remote ref renaming series, focusing on early detection of refspec changes. This is the fourth patch in Patrick Steinhardt's six-part series addressing inefficiencies in remote ref renaming operations. The change restructures the code to determine whether refs need renaming earlier in the process, separating this check from the actual refspec updating logic. 

The key technical change moves the refspec update detection into a separate loop before the configuration rewrite, using a new `refspecs_need_update` flag (renamed from `refspec_updated`). The patch modifies `builtin/remote.c` to first check if any fetch refspecs contain the old remote name pattern (`:refs/remotes/<oldname>/`), then only proceeds with the expensive ref updates if needed. This prepares for a subsequent change that will restructure the transaction handling.

The implementation maintains the same behavior while making the control flow clearer - the actual ref updates still happen in the same way, just with the early check factored out. This is a preparatory change that enables more significant transaction handling improvements in later patches of the series. The patch follows the established pattern of the performance optimization series by carefully restructuring code without changing functionality.
