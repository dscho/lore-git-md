Junio Hamano has posted a v2 version of his string-list API refactoring series, expanding it from 5 to 7 patches. The series continues its systematic cleanup of Git's string splitting functionality, now adding the ability to skip empty items during splitting - a feature that previously required separate post-processing steps. 

The new version incorporates all feedback from the v1 review, fixing several documentation typos that Eric Sunshine caught. The core improvements remain: unifying the split implementations, adding whitespace trimming, and demonstrating real-world simplifications in diff.c. The two new patches introduce STRING_LIST_SPLIT_OMIT_EMPTY and update callers to use this instead of explicit empty-item removal.

With these additions, the series now provides a more complete solution for common string splitting patterns while maintaining backward compatibility. The changes touch 21 files but follow a careful, incremental approach that has drawn no technical objections. Junio, as both author and maintainer, will likely merge this once any final review feedback is addressed.
