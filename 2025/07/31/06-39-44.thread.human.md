Junio Hamano continues refining the string-list API with part 4/7 of his refactoring series, introducing whitespace trimming capability to the string splitting functions. The new STRING_LIST_SPLIT_TRIM flag automatically strips whitespace from both ends of each split string before adding it to the list. The implementation carefully maintains the series' pattern of internal unification while preserving external API compatibility - the new _f-suffixed wrapper functions expose the new functionality while leaving existing functions unchanged.

The patch builds on earlier work that unified the string_list_split() and string_list_split_in_place() implementations through a shared split_string() helper. Reviewers shejialuo, Patrick Steinhardt, and Eric Sunshine have been following the series, which remains focused on internal cleanup with no user-facing changes. The change is well-tested with 64 lines of new unit tests covering various whitespace patterns and edge cases. This continues the series' pattern of adding capabilities through flags while maintaining existing behavior, with previous patches having already standardized error handling, added multi-delimiter support, and aligned the split functions' implementations.
