Junio Hamano continues his effort to modernize Git's string-list API with a new patch converting `wt-status.c`'s `abbrev_oid_in_line()` function from `strbuf_split` to the newer `string_list_split`. This change is part of a larger series that has already unified string splitting behavior across 30+ call sites in the codebase.

The patch simplifies the rebase todo list processing by replacing a `strbuf_split_max()` call followed by manual trimming with a single `string_list_split()` operation. This eliminates intermediate buffer management while maintaining identical functionality, reducing the code by 11 lines overall. The change demonstrates the series' core goal of removing unnecessary `strbuf` operations when the string-list API's built-in features suffice.

This work builds on earlier patches that established flag-based control over string operations (like `STRING_LIST_SPLIT_TRIM`) and introduced type-safe wrapper functions. The series has received positive reviews from shejialuo, Patrick Steinhardt, and Eric Sunshine, with this latest patch following the established pattern of converting targeted subsystems while preserving backward compatibility. The changes are internal improvements with no user-visible effects, focusing on code maintainability and consistency.
