Performance optimization patch for remote ref renaming, part 5/6 in a series. This patch dramatically improves the efficiency of renaming remote references by using a single atomic transaction rather than performing O(n^2) operations. The key changes:

1. Fixes dangling symref handling during remote renames by using `RESOLVE_REF_NO_RECURSE` and `refs_for_each_rawref()` to properly track all references.

2. Restructures the rename operation to use a single atomic transaction, providing both correctness (all-or-nothing behavior) and massive performance improvements. Benchmarks show a 113x speedup for the files backend (238s -> 2s) and 7x for reftable (8.6s -> 1.2s).

3. Adds conflict detection when nesting remotes (e.g. renaming "origin" to "origin/foo" when "origin/foo" exists), providing helpful error messages when such conflicts occur.

4. Maintains reflog history through the rename operation, though progress reporting is sacrificed for the atomic transaction approach.

The patch includes comprehensive tests covering symref handling, nested remote scenarios, and reflog preservation. This is a significant improvement over the previous behavior which could leave references partially renamed and took hours for large repositories.
