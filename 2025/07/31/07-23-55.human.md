Refactoring patch in the promisor-remote protocol extension series. This is the third of five patches in v7, focusing on cleaning up the parsing logic for advertised remote attributes.

The patch introduces a new `parse_one_advertised_remote()` function to centralize the parsing of server-advertised promisor remote information into a `struct promisor_info`. This replaces the previous scattered parsing logic that handled name and URL separately. The change makes the code more maintainable and prepares for adding new fields (filter and token) in subsequent patches.

Key technical changes include:
- Moving memory management into a new `promisor_info_free()` helper
- Using `string_list_split_in_place()` for cleaner parsing
- Passing the complete `promisor_info` struct rather than individual fields to `should_accept_remote()`
- Better error handling for malformed input

The refactoring appears thorough and well-motivated, with clean separation of concerns. It builds on the series' earlier introduction of `struct promisor_info` while maintaining the same functionality. The changes align with the overall goal of making the protocol more extensible while keeping the code maintainable.

This is a solid middle step in the series - not flashy, but important plumbing work that enables the more visible protocol extensions coming in later patches. The implementation looks clean and the commit message clearly explains the rationale.
