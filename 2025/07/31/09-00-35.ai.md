This is the v4 cover letter for the `git refs list` feature series, implementing the architectural refinements suggested in previous reviews. The series now cleanly factors out common logic between `for-each-ref` and the new `refs list` command into shared infrastructure.

Key technical changes in v4:
- Core ref listing logic extracted to a helper function in new `for-each-ref.h`, with both commands becoming thin wrappers
- Shared usage strings now defined via macro in the header, fixing prior duplication issues
- Series reorganized with preparatory refactoring commits (doc and code) before feature introduction
- Fixes a pre-existing man page inconsistency for `for-each-ref` as a side effect
- Removes a known breakage in t0450 documentation tests

The implementation follows Junio Hamano's preferred approach of helper function extraction rather than direct command-to-command calls. The test infrastructure remains maintainer-approved from v3, now complemented by cleaner architectural separation.

Notable improvements over v3:
- Eliminates the problematic `REFS_LIST_USAGE` macro duplication
- Resolves usage string synchronization issues
- Better separation of concerns in the commit sequence
- More maintainable header-based sharing of common elements

The cover letter reiterates the long-term vision for `git refs` command consolidation while emphasizing this series remains behavior-preserving. It invites discussion about future refinements to the ref listing interface now that the architectural foundation is solid.

Series structure:
1. Documentation refactoring (new in v4)
2. Core logic extraction to helper (new in v4)
3. `refs list` command implementation
4-5. Test refactoring and new tests (carried forward from v3)

The changes demonstrate active engagement with maintainer feedback while preserving the original goals of discoverability and command consolidation. With the architectural concerns addressed, the series appears ready for final review pending any new feedback on the implementation approach.
