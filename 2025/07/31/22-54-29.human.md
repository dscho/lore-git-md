This is part 7 of an 11-patch series refactoring Git's string handling by replacing `strbuf_split*()` with more appropriate alternatives. The patch converts `config.c`'s parsing of the `GIT_CONFIG_PARAMETERS` environment variable from using `strbuf_split_str()` to `string_list_split()`, eliminating the need for manual delimiter trimming.

The change simplifies the code by:
- Using `string_list_split()` with a max split count of 1 (to split into up to 2 pieces)
- Removing explicit delimiter trimming since `string_list` handles this automatically
- Switching from array-of-strbuf to string_list iteration
- Maintaining the same validation logic for empty keys
- Preserving the existing behavior for both key-only and key=value inputs

The commit message notes the somewhat awkward API design of `string_list_split()`'s max parameter (where you pass n-1 for n splits), but this is a known ergonomic issue that doesn't affect functionality. The patch reduces the code by 3 lines (23->20) while making it more maintainable.

This follows the series' consistent pattern of replacing manual string handling with more robust utilities, and like the other patches, appears to be a straightforward improvement with no behavior changes. Eric Sunshine previously noted minor typo fixes in the commit message that have been addressed in this version.
