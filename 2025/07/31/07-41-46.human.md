This is the first patch in a 9-part refactoring series modernizing Git's string handling by replacing `strbuf_split*()` with `string_list_split*()` where appropriate. The patch focuses on `wt-status.c`, specifically the `abbrev_oid_in_line()` function that processes rebase todo list lines.

The change converts the function from using `strbuf_split_max()` to `string_list_split()`, which better matches the use case since the split strings are only used as read-only inputs for composing a new line with abbreviated object IDs. The new version is more straightforward - it splits into a string list, checks for an OID in the second token, and reconstructs the line with an abbreviated hash when found.

The patch reduces code complexity by eliminating manual string trimming and buffer management, while maintaining identical behavior. This appears to be a clean, focused change that improves code clarity without introducing new functionality. As the first in a larger series, it sets the pattern for similar conversions to follow in other parts of the codebase.
