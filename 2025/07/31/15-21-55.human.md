This is the final patch in a three-part series removing the deprecated `core.commentChar=auto` configuration option. The patch adds user-friendly advice that appears when Git encounters the deprecated setting, guiding users on how to update their configuration.

The advice is context-sensitive - it detects where the setting appears (system/global/local config files) and whether the user has write access, then generates appropriate `git config` commands. For example, if the setting is in a system config the user can't modify, it suggests changing the global config instead. The advice shows both how to unset the option (falling back to the default '#') and how to set a custom comment character.

The implementation tracks config file locations and duplicate settings to generate precise instructions. Tests demonstrate the advice appears correctly in both warning mode (pre-3.0) and error mode (post-3.0). The patch follows Junio C Hamano's approved approach of using `git config list --show-scope` for configuration diagnosis.

This completes the deprecation process for the problematic auto-comment feature, providing clear migration path while maintaining backward compatibility until Git 3.0. The series has maintainer approval and is ready for merging.
