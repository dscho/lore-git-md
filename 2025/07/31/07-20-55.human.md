This is a discussion about terminology in the ongoing series extending promisor-remote protocol support, specifically whether to use "field" or "configuration variable" in the new `promisor.sendFields`/`checkFields` config options.

Christian Couder responds to Junio Hamano's concerns about the use of "field" terminology, arguing that:
1. The parallel submission of v6 shouldn't discourage discussion of v5 feedback
2. The mixed comma/space list parsing follows existing Git conventions
3. The term "field" was chosen to avoid confusion with config variables since these values become immutable after transmission

Junio maintains that:
1. "Configuration variable" is the established Git concept users understand
2. The new terminology adds unnecessary cognitive load
3. If keeping "field", the series should first standardize list parsing across Git

The exchange reveals a fundamental terminology disagreement that may require renaming the config options to "sendVariables"/"checkVariables" or similar. Christian indicates willingness to make this change if consensus favors it, though he sees value in distinguishing these protocol-transmitted values from regular config variables.

This is the key remaining blocker for the otherwise complete series, which has already incorporated all other technical feedback. The discussion remains constructive, with both sides explaining their reasoning clearly.
