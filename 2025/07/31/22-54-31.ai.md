This is patch 9/11 in a refactoring series converting `strbuf_split*()` usage to more appropriate alternatives. The patch focuses on sub-process status reading in `sub-process.c`.

The change replaces an over-engineered approach that used `strbuf_split_str()` to parse "status=<foo>" lines with a simpler `skip_prefix()` check. The old code would split each line on "=" into two strbufs, then check if the first part was "status=", while the new version directly checks for the prefix and captures the value portion.

Key technical details:
- Removes allocation/free of temporary strbuf array
- `skip_prefix()` provides direct access to the value after "status="
- Maintains the "last status wins" behavior
- Reduces code from 15 to 6 lines (net -9/+7)
- Drops now-unneeded `string-list.h` inclusion (as noted in thread context)

The change follows the series' pattern of replacing delimiter-heavy parsing with simpler alternatives when appropriate, in this case showing `skip_prefix()` as a better fit than splitting for this simple prefix-matching case. The thread context indicates this approach was reviewed and confirmed as correct by Christian Couder.
