This thread addressed a Windows-specific bug where `git reset -p` showed corrupted output due to incorrect CRLF line ending handling during interactive prompts. The issue, which had gone unnoticed for over five years, stemmed from `strbuf_getline_lf()` removing only LF while leaving CR in the buffer, causing cursor movement artifacts.

Johannes Sixt proposed a clean fix that replaces `strbuf_getline_lf()` with `strbuf_getline()` in `git_read_line_interactively()`, properly handling both CR and LF removal in one step. The solution eliminates the need for a subsequent `strbuf_trim_trailing_newline()` call, actually simplifying the code by removing more lines than it adds. 

Junio C Hamano reviewed and accepted the patch, noting the explanation made sense and expressing surprise the issue hadn't been reported earlier. While the discussion acknowledged this might affect other interactive commands using similar prompt reading logic, the immediate fix was considered complete for the `git reset -p` case. The patch's minimal, targeted nature and clear technical rationale appear to have satisfied all review concerns.
