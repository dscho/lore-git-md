This is a build system discussion about integrating git-gui and gitk into Git's meson build system, specifically addressing the subproject location challenge. Patrick Steinhardt responds to Carlo Arenas and Johannes Sixt about the meson integration progress in the ongoing git-gui modernization effort.

The key points are:
1. The meson build for git-gui currently works when tested independently, but isn't yet wired into Git's main meson.build
2. The main technical hurdle is meson's requirement that subprojects must live in a "subprojects/" directory, requiring moving git-gui and gitk from their current top-level locations
3. Patrick has local patches ready but hesitates to submit them due to concerns about how this structural change will be received
4. The change is technically straightforward but organizationally awkward since it requires relocating directories that have historically lived at the top level

This discussion occurs in the context of the broader git-gui modernization effort that has already made architectural decisions about Tcl/Tk handling and removed deprecated bundle infrastructure. The meson integration represents the final piece needed to complete the build system unification. The subproject location issue appears to be the last remaining technical blocker before full integration can proceed.
