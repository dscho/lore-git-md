This is the first patch in a three-part series deprecating and removing the problematic `core.commentChar=auto` configuration option. The feature, which automatically selects a comment character when amending commits, has several fundamental limitations that make it incompatible with commit templates, prepare-commit-msg hooks, rebase operations, and git notes.

The patch updates documentation in BreakingChanges.adoc and config/core.adoc to formally deprecate the feature, noting it will be removed in Git 3.0. It also adds conditional compilation guards (`WITH_BREAKING_CHANGES`) around the auto-comment functionality in preparation for its eventual removal. Several test cases are marked to skip when this flag is set.

The commit message thoroughly explains the technical limitations of the current implementation and why they can't be easily fixed. Phillip Wood notes this is a breaking change but leaves open the possibility of reverting if someone later proposes a maintainable solution. The changes are well-scoped and focused on the deprecation notice, with subsequent patches handling user warnings and migration advice.

This appears to be the final iteration of the series, having incorporated maintainer feedback and gained Junio Hamano's approval for the approach. The patch is cleanly implemented with appropriate documentation and test updates.
