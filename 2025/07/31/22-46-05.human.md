This is patch 6/7 in Junio Hamano's series refactoring Git's string-list API, adding a new feature to optionally omit empty strings when splitting. The patch introduces a STRING_LIST_SPLIT_NONEMPTY flag that, when set, prevents empty string pieces from being added to the resulting list after splitting. This builds on the unified split_string() helper introduced earlier in the series.

The implementation is straightforward - it adds a check in append_one() to skip adding the string if it would be empty (when end pointer is less than or equal to the start). The patch includes comprehensive tests showing the new flag works both alone and in combination with the existing STRING_LIST_SPLIT_TRIM flag. Test cases demonstrate handling of leading/trailing delimiters and interleaved empty pieces.

This is a logical extension of the API that provides a common need - many callers currently have to manually filter empty strings after splitting. The change maintains backward compatibility while giving callers a cleaner way to handle empty pieces. As with the rest of the series, the implementation is clean and well-tested, with clear documentation of the new flag. The patch continues the series' pattern of methodically improving the string-list API while reducing boilerplate in calling code.
