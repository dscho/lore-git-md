This is the final patch in a performance optimization series addressing remote ref renaming inefficiencies, specifically focusing on optimizing iteration during remote renames. The series has been through multiple iterations and thorough review.

The patch replaces `refs_for_each_rawref()` with `refs_for_each_rawref_in()` to limit iteration to only relevant refs under "refs/remotes/$OLDNAME/", providing significant speedups (1.35x for files backend and 2.07x for reftable when renaming a remote with single reference among 100k unrelated ones). The implementation moves prefix filtering into the iteration itself rather than the callback while maintaining the same `rename_one_ref()` logic.

Key technical details include:
- `refs_for_each_rawref_in()` exposed in refs.h via existing `do_for_each_ref()` infrastructure
- Maintains the same refname rewriting, reflog processing, and transaction update logic from previous patches
- Builds on the atomic transaction handling and conflict detection established earlier in the series

The series has been approved for integration with understanding that some edge cases (D/F conflict handling in files backend, reflog optimizations) may need future attention. Performance improvements are substantial, with cumulative results showing operations improving from 238s->2s (files) and 8.6s->1.2s (reftable) for bulk operations.
