Refactoring patch for promisor-remote protocol infrastructure. This is the first of a 5-part series (now at v7) that extends the promisor-remote protocol to support configurable validation of remote attributes during clone/fetch operations.

The patch replaces the existing `struct strvec` approach for storing promisor remote information with a new `struct promisor_info` that explicitly tracks name and URL fields. This provides better type safety and scalability as the protocol grows to support additional attributes. The change centralizes remote information in a string list where each item's util pointer points to a structured promisor_info instance.

The refactoring appears thorough, touching all relevant promisor-remote.c functions to use the new structure while maintaining the same behavior. The commit message clearly explains the motivation - the current approach wouldn't scale well when adding new fields. Test coverage is implied by the series being at v7 with CI passing, though this particular patch doesn't add new tests since it's purely a refactor.

This foundational change enables the subsequent patches in the series to add support for validating additional remote attributes. The implementation looks clean and follows Git's established patterns for similar structured configurations.
