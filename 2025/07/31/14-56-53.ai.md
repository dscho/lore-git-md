Performance optimization patch in the remote ref renaming series, addressing both dangling symref handling and quadratic performance issues. This fifth patch in the six-part series restructures the reference transaction mechanism in `builtin/remote.c` to use a single atomic transaction for all remote reference updates, replacing the previous O(n^2) approach that used separate transactions per ref.

Key technical changes include:
- Introduces `rename_one_ref()` callback that queues both direct and symref updates into a single transaction
- Handles reflog migration through `rename_one_reflog()` and `rename_one_reflog_entry()`
- Adds conflict detection for nested remote renames (e.g. "origin" -> "origin/foo")
- Uses `refs_for_each_rawref()` to properly handle broken/dangling references
- Maintains atomicity - either all refs are renamed or none are
- Includes comprehensive tests for edge cases (unborn HEAD, nested remotes, reflog preservation)

The patch shows dramatic performance improvements: 238s -> 2s (113x) for files backend and 8.6s -> 1.2s (7.3x) for reftable in benchmarks. Tradeoffs include losing progress meter granularity and requiring conflict-free refnames, but these are deemed acceptable given the massive performance wins and atomicity guarantees. The implementation carefully handles edge cases like symref resolution (using `RESOLVE_REF_NO_RECURSE`), reflog ordering, and provides helpful error messages when conflicts occur.
