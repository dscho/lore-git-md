Bugfix for git-gui's askpass helper location on macOS, with follow-up improvement.

This email continues the thread about ensuring git-gui uses its own version of the askpass helper rather than potentially picking up a broken system version. The original change from Carlo Arenas Belón modified git-gui.sh to locate the helper relative to the git-gui executable rather than using git's exec-path, which could point to a different Git installation (particularly problematic on macOS).

Johannes Sixt notes that his integration branch handles additional askpass-related environment variables (GIT_ASKPASS and GIT_ASK_YESNO) that weren't addressed in the original patch. He proposes squashing in a follow-up change that:
1. Moves the directory calculation to a variable for reuse
2. Applies the same location logic to all three askpass-related variables
3. Cleans up the temporary variable afterward

The changes appear straightforward and well-considered, building on the architectural decision to colocate git-gui with its helper scripts. This is part of the broader git-gui modernization effort that has included removing macOS bundle infrastructure and improving build system integration. The patch seems ready for inclusion, though it may need coordination with the parallel meson build system work.
