This is the second patch in a three-part series deprecating and removing the problematic `core.commentChar=auto` configuration option. The series has maintainer approval and is in its final form.

The patch introduces warning infrastructure for the deprecated `auto` setting. When users run commands that invoke the commit machinery (commit, merge, rebase, revert), Git will now print a one-time warning if `core.commentChar` or `core.commentString` is set to "auto". The warning clearly states this feature will be removed in Git 3.0. The implementation prevents warning spam by using an environment variable to track when the warning has been shown.

For users compiling with `WITH_BREAKING_CHANGES` (which previews Git 3.0 behavior), the patch makes Git die with an error instead of just warning. The error message similarly explains the removal. The patch includes comprehensive test coverage showing both the warning and error behaviors.

This is a well-constructed transitional step that gives users clear advance notice while maintaining backward compatibility. The implementation carefully handles edge cases like nested Git invocations and configuration changes via `git config`. The series as a whole follows Git's standard deprecation process, with this warning infrastructure in place, the final patch can safely remove the feature entirely.
