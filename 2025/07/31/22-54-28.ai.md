This is part 6/11 of a refactoring series converting `strbuf_split*()` usage to more appropriate alternatives. The patch focuses on `builtin/notes.c`'s stdin parsing for note copy operations.

The change replaces manual `strbuf_split()` with `string_list_split_in_place_f()` using `STRING_LIST_SPLIT_TRIM` to handle whitespace trimming during splitting. The key modifications are:
- Switches from array-of-strbuf to string_list iteration
- Uses `split.nr` for simpler validation (still requiring exactly 2 tokens per line)
- Maintains the same error messages and validation logic
- Preserves the existing behavior of ignoring extra tokens beyond the first two
- Reduces code by 1 line (23->22) while making the parsing clearer

The commit notes this is part of a broader effort to modernize string handling, though it explicitly leaves tightening the loose token validation (which ignores extra tokens) as out of scope for this series. The change follows the established pattern in this series of using `string_list` utilities where they provide better ergonomics than direct `strbuf` manipulation.
