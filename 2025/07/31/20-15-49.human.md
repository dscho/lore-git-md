This is a refactoring patch in a series modernizing Git's string handling by replacing `strbuf_split*()` with more appropriate alternatives. It focuses on converting the parsing of `GIT_CONFIG_PARAMETERS` environment variables in `config.c`.

The patch replaces `strbuf_split()` with `string_list_split()` for parsing key=value pairs, eliminating the need for manual delimiter trimming. The commit message notes the somewhat awkward API design of `string_list_split()`'s `max` parameter (where you pass 1 to split into 2 pieces), but this is a known characteristic rather than a new issue introduced here.

Eric Sunshine provides two minor typo fixes to the commit message (correcting "spliting" to "splitting" and "leafes" to "leaves"), but these are purely editorial changes that don't affect the code. The substantive changes in this patch maintain identical parsing behavior while simplifying the implementation, continuing the series' pattern of reducing manual memory management in favor of more robust string utilities.
