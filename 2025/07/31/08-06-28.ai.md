This is a bugfix patch in the git-gui modernization series, specifically addressing askpass helper resolution on macOS. The patch changes how git-gui locates its askpass helper script, moving from querying git's exec-path to deriving the path from the location of the git-gui binary itself.

The key technical change replaces `[git --exec-path]` with `[file dirname [file normalize $::argv0]]` to find git-gui--askpass. This ensures git-gui always uses its own bundled helper rather than potentially picking up a system version, which on macOS may be broken. The change implements Mark Levedahl's suggested approach that was discussed earlier in the thread.

This patch represents the final piece of the v2 series' askpass resolution strategy, complementing the earlier build system changes that generate the askpass script with proper TCLTK_PATH handling. It specifically addresses the macOS edge case where system git might provide an incompatible helper, while also being more robust against PATH/exec-path mismatches in general.

The implementation is minimal (4 lines changed) and focused, though it does assume git-gui and its askpass script will be colocated - a reasonable assumption given the build system changes in earlier patches. This completes one of the thread's original goals of standardizing Tcl/Tk path handling across git-gui components.
