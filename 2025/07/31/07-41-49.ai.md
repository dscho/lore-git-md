This is part 4 of a 9-patch refactoring series converting `strbuf_split*()` to `string_list_split*()` usage in Git's codebase. The patch focuses on `builtin/clean.c`, specifically the interactive pattern filtering in `filter_by_patterns_cmd()`.

The change replaces `strbuf_split_max()` with `string_list_split_in_place_f()` for parsing user-provided exclude patterns during interactive `git clean`. Key technical aspects include:
- Uses `STRING_LIST_SPLIT_TRIM` flag to handle whitespace trimming directly during splitting
- Maintains identical pattern matching behavior while simplifying memory management
- Moves the `ignore_list` declaration into the processing loop scope
- Preserves all existing functionality including pattern position tracking (`-(i+1)`)
- Reduces line count (-9/+11) while eliminating manual strbuf management

This builds on the series' earlier work demonstrating `string_list`'s advantages for delimiter-heavy parsing, following the pattern established in patch 3's conversion of `parse_choice()`. The change is mechanical but meaningful, removing a class of potential memory management errors by using the more robust string_list API. The patch maintains all existing behavior including colorized output and pattern position tracking while simplifying the implementation.
