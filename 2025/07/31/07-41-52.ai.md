Refactoring patch converting `strbuf_split()` to `string_list_split()` in config parsing.

This is part 7 of a 9-part series modernizing Git's string handling by replacing `strbuf_split*()` with `string_list_split*()` where appropriate. The patch focuses on `config.c`'s handling of the `GIT_CONFIG_PARAMETERS` environment variable parsing.

The key changes are:
- Replaces `strbuf_split_str()` with `string_list_split()` for parsing key=value pairs
- Eliminates manual delimiter trimming since `string_list_split()` handles this automatically
- Simplifies the value extraction logic by checking `pair.nr` rather than array indexing
- Replaces `strbuf_list_free()` with `string_list_clear()`
- Maintains the same parsing behavior while reducing code (-13/+10 lines)

The commit notes the slightly awkward API of `string_list_split()`'s `max` parameter (which counts splits rather than pieces), but this doesn't affect the actual functionality. The change follows the series' pattern of mechanical conversions that simplify memory management while preserving existing behavior.

This continues the series' consistent approach of:
- Using string_list's built-in whitespace handling
- Converting array access patterns
- Reducing manual memory management
- Maintaining identical input validation

The patch appears straightforward and well-contained like the others in the series, with no apparent behavioral changes or new edge cases introduced.
