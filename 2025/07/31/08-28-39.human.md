Performance optimization patch series (final patch). This is the fourth and last patch in a series addressing inefficiencies in remote ref renaming operations. The patch introduces `refs_for_each_rawref_in()`, a new API that allows prefix-limited iteration over refs, providing an additional 1.35x speedup for the files backend and 2.07x for reftable on top of previous optimizations.

Karthik Nayak suggests using the recently merged `kn/for-each-ref-skip` iterator infrastructure instead of adding this new function, but Patrick Steinhardt prefers to keep the current implementation to avoid adding dependencies to the series. The discussion is minor and doesn't affect the core performance improvements, which are already substantial (reducing bulk operations from 238s to 2s for files backend).

This patch completes the series that has already received maintainer approval, with Junio C Hamano noting the dramatic performance gains (hours to seconds for large ref counts) while acknowledging some edge cases that may need future attention. The series is now ready for integration.
