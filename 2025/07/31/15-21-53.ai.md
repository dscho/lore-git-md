This is the first patch in a three-part series deprecating and removing the `core.commentChar=auto` configuration option, classified as a breaking change. The patch documents the deprecation in BreakingChanges.adoc and updates the core.commentChar documentation to explain why the feature is being removed.

The commit message explains that `core.commentChar=auto` fails in several scenarios: with commit templates containing comments, prepare-commit-msg hooks that introduce comments, and during rebase fixup/squash operations. These issues stem from architectural limitations in how Git coordinates comment characters across different commit workflow components.

The implementation uses `#ifndef WITH_BREAKING_CHANGES` guards to maintain backward compatibility while preparing for removal in Git 3.0. The changes span documentation, config handling, and test updates, with tests marked to skip when `WITH_BREAKING_CHANGES` is enabled. Key files modified include Documentation/config/core.adoc, builtin/commit.c, and environment.c.

This patch lays the groundwork for the subsequent patches that will add warnings and user advice about migrating away from `auto` mode. The approach has maintainer approval and follows Git's standard deprecation process, with all technical issues resolved in the thread discussion.
