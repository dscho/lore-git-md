This is patch 4/7 in Junio Hamano's series refactoring Git's string-list API, introducing whitespace trimming functionality to string splitting operations. The patch adds a new `STRING_LIST_SPLIT_TRIM` flag that automatically trims whitespace from both ends of each split string before adding it to the string list.

The implementation modifies the internal `split_string()` helper and its `append_one()` function to handle both left-trimming (removing leading whitespace) and right-trimming (removing trailing whitespace) when the flag is set. Two new public functions are introduced (`string_list_split_f` and `string_list_split_in_place_f`) that accept the flags parameter, while maintaining backward compatibility with the existing functions.

The patch includes comprehensive unit tests demonstrating the new trimming behavior, including edge cases with multiple spaces and mixed whitespace around delimiters. This is a clean, well-tested addition to the string-list API that follows the series' pattern of methodical improvements while maintaining backward compatibility. The changes are focused and uncontroversial, building on the unified implementation introduced in patch 3/7.
