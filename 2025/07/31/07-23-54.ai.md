This is the second patch in a 5-part series extending the promisor-remote protocol to support configurable validation of remote attributes. The series is currently at v7 with implementation complete, pending final terminology decisions.

The patch introduces server-side mechanism to advertise additional remote attributes (currently "partialCloneFilter" and "token") through a new `promisor.sendFields` config variable. Key technical aspects:

- Defines protocol extension allowing servers to send additional fields beyond just name/url
- Implements config parsing for `promisor.sendFields` (comma/space separated list)
- Restricts allowed field names to predefined set ("partialCloneFilter" and "token")
- Modifies `struct promisor_info` to store new fields alongside name/url
- Updates protocol documentation with new field specifications
- Adds test case verifying field transmission

The implementation uses `string_list_split_in_place()` for config parsing (a v7 improvement) and maintains case sensitivity rules (protocol-level comparisons case-sensitive, config values case-insensitive). Error handling for malformed percent-encoded input remains as future work.

The patch builds on the series' foundation (patch 1's `struct promisor_info`) and enables the client-side validation that follows in patch 4. Documentation updates clarify the protocol extension's behavior and constraints.
