This is the final patch in Junio Hamano's 7-part series refactoring Git's string-list API. The patch demonstrates the practical application of the new STRING_LIST_SPLIT_NONEMPTY flag introduced in patch 6/7, showing how it can simplify common patterns in the codebase.

The change eliminates the need for a two-step process where callers would first split a string and then manually remove empty items from the resulting list. Now they can do both operations in one step by using the new flag. The patch updates four call sites across notes.c, pathspec.c, and test helpers to use the more efficient combined operation.

The changes are straightforward mechanical conversions, replacing pairs of split+remove_empty calls with single split_f calls that include the NONEMPTY flag. This is a clean-up that builds naturally on the API improvements made earlier in the series, showing the practical benefits of the refactoring work.

As the concluding patch in a well-executed series, this change completes the transition to the improved string-list splitting API. All changes are uncontroversial and follow the pattern established in previous patches, with no new test changes needed since the functionality was already thoroughly tested in patch 6.
