This is a refactoring series targeting the overuse of `strbuf_split*()` functions in the Git codebase. Junio C Hamano argues that `strbuf_split*()` is often misused when `string_list_split*()` would be more appropriate, especially for common cases involving whitespace trimming.

The 9-patch series systematically replaces `strbuf_split*()` calls with more suitable alternatives across several subsystems:
- `wt-status` and `clean` commands get the most attention with multiple patches
- Other affected areas include `merge-tree`, `notes`, config handling, environment variables, and sub-process handling

The changes appear to be straightforward mechanical conversions, building on recent improvements to the `string_list` API that now better supports splitting with multiple delimiters and automatic trimming. The series follows logically from previous work extending `string_list` functionality.

This looks like a well-motivated cleanup that should make the code more maintainable by using the right data structures for the job. The patch titles clearly indicate the scope of each change, and the diffstat shows a net reduction in code (-113/+103 lines) while improving clarity.
