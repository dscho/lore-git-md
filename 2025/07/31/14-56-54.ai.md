Performance optimization patch in the remote ref renaming series, focusing on reducing unnecessary iteration during remote renames. This is the sixth and final patch in v2 of Patrick Steinhardt's series addressing quadratic performance in remote operations.

The patch replaces the use of `refs_for_each_rawref()` with `refs_for_each_rawref_in()` when renaming remote references, allowing iteration to be limited to only the relevant refs under "refs/remotes/$OLDNAME/" rather than scanning all references. This provides measurable speedups: 1.35x faster for the files backend and 2.07x for reftable in benchmarks renaming a remote with a single reference among 100k unrelated ones. The implementation moves the prefix filtering from the callback into the iteration itself, eliminating the need to check and skip irrelevant refs.

Key technical details: The patch modifies `builtin/remote.c` to construct the prefix string and pass it to the new iterator, while keeping the same `rename_one_ref()` callback logic. It also exposes `refs_for_each_rawref_in()` in refs.h and implements it via the existing `do_for_each_ref()` infrastructure. The changes maintain all existing functionality while being more efficient.

This builds on the series' earlier work to make remote renames atomic and handle dangling symrefs properly. The performance gains here are in addition to the much larger improvements (hours to seconds) already achieved in previous patches. The reftable backend continues to show better absolute performance than files, though both benefit proportionally from this optimization.
