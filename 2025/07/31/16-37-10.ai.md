Bugfix follow-up confirming the Windows CRLF handling solution.

Junio C Hamano confirms Johannes Sixt's patch fixing the Windows-specific CRLF handling issue in interactive commands. The maintainer notes the explanation makes sense and expresses surprise this longstanding issue (5+ years) wasn't reported earlier. The patch is accepted for inclusion, with Junio mentioning he happened to be familiar with this code area recently.

The technical solution remains as originally proposed - replacing `strbuf_getline_lf()` with `strbuf_getline()` in `git_read_line_interactively()` to properly handle both CR and LF removal in one step, eliminating the need for the subsequent `strbuf_trim_trailing_newline()` call. The change affects the prompt.c file's interactive input reading function, which is used by `git reset -p` and potentially other interactive commands.

While this specific thread focused on `git reset -p`, the maintainer's acceptance without further discussion suggests this solution is considered complete for the immediate issue. The broader question of whether other interactive commands might need similar fixes remains open but isn't pursued in this exchange. The patch's minimal nature (1 line replacing 7 lines removed) and clear explanation appear to have satisfied any review concerns.
