Refactoring patch in Junio Hamano's string-list API cleanup series (3/7). This patch unifies the implementations of `string_list_split()` and `string_list_split_in_place()` into a single internal helper function called `split_string()`. The key difference between the two functions is preserved - one works on const strings and makes copies, while the other modifies the input string in place, but now they share most of their logic.

The patch introduces a new `append_one()` helper to handle the string copying/placement differences, and carefully maintains the existing behavior while reducing code duplication. The changes are internal to string-list.c and don't affect callers, though the consolidation will make it easier to add new features (like the empty-string handling coming in later patches) in a single place.
