This is part 7 of a 9-part refactoring series converting Git's string handling from `strbuf_split*()` to `string_list_split*()`. The patch focuses on config parameter parsing, specifically the handling of old-style `GIT_CONFIG_PARAMETERS` environment variables.

The change replaces `strbuf_split_str()` with `string_list_split()` when parsing key=value pairs, eliminating the need for manual delimiter trimming that was previously required. The conversion follows the pattern seen in earlier patches: using `string_list`'s built-in whitespace handling, replacing array-style access with `items[]` notation, and swapping `strbuf_list_free()` for `string_list_clear()`.

Junio notes an ergonomic quirk in `string_list_split()`'s max parameter (it counts splits rather than pieces), but this doesn't affect the correctness of the change. The patch maintains identical behavior while reducing the line count (-13/+10) and simplifying the memory management.

This continues the series' consistent, mechanical improvements to string handling across Git's codebase, showing the benefits of `string_list` for delimiter-heavy parsing tasks. The change is straightforward and unlikely to be controversial, following the established pattern of the previous conversions.
