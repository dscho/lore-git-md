This is a policy clarification request regarding the ongoing xdiff Rustification effort. Christian Brabandt, representing the Vim/Neovim projects which use Git's xdiff library as a dependency, seeks confirmation about whether the long-term plan involves completely replacing the C implementation with Rust. 

The question comes in the context of the RFC series that has been methodically restructuring xdiff internals (including type system changes and performance optimizations) while introducing Rust as a hard dependency. While the current series focuses on initial Rust support with measured performance gains (5-19% improvements), Christian's inquiry highlights a key downstream impact consideration - many projects like Vim/Neovim rely on xdiff's C implementation as an external library.

The email doesn't propose any technical changes but surfaces an important architectural question that wasn't fully addressed in the prior technical discussions about type casting approaches, CI integration, and version policies. This suggests the Rust transition may need explicit documentation about backward compatibility guarantees or migration paths for external consumers of xdiff as a library, beyond Git's internal usage. The response to this will likely influence how aggressively the project can proceed with complete Rust replacement versus maintaining dual implementations.
