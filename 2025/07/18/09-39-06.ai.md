Performance optimization converting commit traversal from linked lists to priority queues. This is the first patch in René Scharfe's v2 series addressing quadratic complexity in merge-heavy histories by replacing commit_list operations with prio_queue.

The patch converts pop_most_recent_commit() and its callers across multiple files (commit.c, fetch-pack.c, object-name.c, walker.c) to use prio_queue instead of commit_list. The key change replaces commit_list_insert_by_date() with prio_queue_put() when adding parent commits during traversal. A new performance test (t/perf/p1501-rev-parse-oneline.sh) demonstrates a 92% speedup for pathological cases with 50% merges, though normal traversals see a negligible 1% slowdown.

Technical details include:
- New prio_queue initialization in fetch-pack.c and walker.c replacing static commit_list variables
- Removal of now-unnecessary commit_list_sort_by_date() calls
- Memory management changes (clear_prio_queue() instead of free_commit_list())
- Header file changes updating pop_most_recent_commit() prototype
- Meson build system updates to include new test

The patch maintains existing interfaces while improving worst-case performance, with comprehensive test coverage including both unit test (t/unit-tests/u-prio-queue.c) and the new performance benchmark. The series has already addressed all technical feedback from v1 and appears ready for merging.
