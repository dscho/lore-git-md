This is a discussion about output format design for the new `git repo` command, part of Lucas Seiki Oshiro's GSoC project. The email continues the conversation about how to use for different output formats, responding to Justin Tobler's earlier suggestions.

The key points being discussed are:
1. Naming alternatives for the format types - Lucas suggests `porcelain` instead of `user` for the default human-readable format, and `null` instead of `nul`
2. Whether the human-readable format should differ meaningfully from the key-value format for the `info` subcommand
3. A proposal to automatically switch to null-terminated output when piping (similar to `git diff`'s color behavior)

This discussion comes after the thread had largely settled on having three format types (`user`, `keyvalue`, and `nul`), so Lucas is offering some last-minute alternatives before the design is finalized. The email shows careful consideration of both user experience and consistency with existing Git conventions. The automatic format switching idea in particular seems like a potentially useful refinement, though it would need to be weighed against the principle of least surprise.
