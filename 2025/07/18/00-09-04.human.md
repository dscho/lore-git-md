This is a bug report narrowing down a Git Bash startup issue on Windows. Fabio Frumento has identified that any command substitution (`$(command)`) in shell initialization files causes Git Bash 2.50.x to crash silently on their Windows 11 Pro system. The problem occurs during processing of `/etc/bash.bashrc` and `/etc/profile.d/git-prompt.sh`, specifically when trying to set `PS1` and `GIT_EXEC_PATH`. 

The reporter demonstrates the issue is reproducible with simple command substitutions like `$(ls -al)`, suggesting a fundamental problem with command execution in the Windows port of bash. They note the shell works when started with `--norc` (skipping initialization files), but fails with Git Bash's default `--login -i -v` options. 

This appears to be a serious regression affecting at least some Windows 11 configurations, though the reporter wonders if it might be environment-specific. The detailed reproduction steps and clear isolation of the failure mode (command substitutions) provide maintainers with actionable information to diagnose the underlying cause. The thread shows active collaboration between the reporter and Git for Windows maintainer Johannes Schindelin to pinpoint the issue.
