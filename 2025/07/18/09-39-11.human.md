Performance optimization completing a series to improve commit traversal with priority queues. This final patch in René Scharfe's 3-part series introduces `prio_queue_replace()` to optimize the common case in `pop_most_recent_commit()`. Instead of removing and re-adding the first parent commit (via `prio_queue_get()` and `prio_queue_put()`), it now uses a more efficient in-place replacement operation.

The benchmark results show this change successfully neutralizes the small performance regression introduced by the initial conversion to priority queues, making the new implementation at least as fast as the original commit-list version in Git's own repository. The patch modifies just 11 lines in commit.c, adding a new state variable (`get_pending`) to track when the replacement optimization can be used.

This completes the series' goal of improving worst-case performance for merge-heavy histories while maintaining (or slightly improving) performance for normal cases. All feedback from previous versions has been addressed, and the changes appear ready for merging. The series represents a focused, well-tested optimization that preserves existing interfaces while making the commit traversal internals more efficient.
