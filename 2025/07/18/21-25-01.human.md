Platform compatibility concern from a Gentoo maintainer regarding Rust as a hard dependency. Eli Schwartz raises practical issues for several architectures where Rust support is limited or non-existent (HPPA, Alpha, m68k, s390), noting that even on amd64 it would require building multiple Rust versions from source. This is framed as a significant barrier for distribution packaging, potentially forcing some architectures to either drop Git or remain on old versions. The email questions the minimum supported Rust version for the proposed changes but does not engage with the technical merits of the xdiff optimization itself. This adds a new dimension to the ongoing discussion about Rust adoption, highlighting real-world deployment challenges beyond the previously noted NonStop concerns. The tone is matter-of-fact rather than oppositional, presenting concrete packaging constraints that would need resolution if Rust becomes mandatory.
