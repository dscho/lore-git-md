This is a policy clarification request regarding the ongoing xdiff Rustification effort. Christian Brabandt, maintainer of Vim/Neovim which uses Git's xdiff library, asks whether the long-term plan is to completely replace the C implementation with Rust. 

The question comes in response to Ezekiel Newren's RFC series (now at v7) that introduces Rust as a hard dependency while optimizing xdiff internals, achieving 5-19% performance gains. The series has seen extensive technical discussion about type safety and platform compatibility, with consensus forming around certain implementation approaches.

Brabandt's inquiry highlights an important downstream consideration - many projects outside Git rely on xdiff as a standalone C library. The current RFC doesn't explicitly address whether the C API will remain available long-term or if external users like Vim would eventually need to interface with Rust code. This could significantly impact projects that have built upon xdiff's current C implementation.

The thread context shows the Rust integration effort is still working through several open items including Windows/32-bit build issues and platform-specific concerns, but hasn't yet discussed the implications for external consumers of the xdiff library. This appears to be the first direct question about the project's plans regarding complete C removal versus maintaining dual implementations.
