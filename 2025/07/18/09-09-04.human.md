Performance optimization converting commit traversal to use priority queues, now in its second revision. This 3-patch series from René Scharfe replaces quadratic-time commit list operations with logarithmic-time priority queue operations, particularly benefiting merge-heavy histories. The key changes since v1 include improved commit message clarity about the target use case, meson build integration for the new test, and a variable rename from `delete_pending` to `get_pending` for better code readability.

The series shows a clear 92% speedup for pathological cases (50% merges/50% root commits) while maintaining performance for normal cases. A new performance test (t/perf/p1501-rev-parse-oneline.sh) demonstrates the improvement with a carefully constructed merge-heavy history. The implementation now uses `prio_queue_replace()` to optimize the common get+put sequence pattern.

This appears ready for merging, with all prior technical concerns (timestamp ordering, meson integration) resolved. The changes are well-tested with both performance measurements and unit tests. While Scharfe had previously proposed an alternative lazy heap design, this version sticks with the more straightforward approach that had reached consensus in the thread.
