This is a feature patch introducing a new `pull.autoStash` configuration option, implementing the consensus from the ongoing thread about auto-stash behavior in `git pull`. The patch establishes a three-level configuration hierarchy where `pull.autoStash` serves as an explicit override to the operation-specific `rebase.autoStash` and `merge.autoStash` settings.

The implementation modifies `builtin/pull.c` to:
1. Add a new `config_pull_autostash` variable (-1 for unset)
2. Read the `pull.autoStash` config in `git_pull_config()`
3. Apply precedence rules: command-line options > `pull.autoStash` > operation-specific configs
4. Maintain existing behavior for `rebase.autoStash` while adding the new override logic

The patch includes comprehensive test coverage in t/t5520-pull.sh, verifying:
- All combinations of `pull.autoStash` with both rebase and merge operations
- Interaction with command-line `--autostash` and `--no-autostash` flags
- Precedence rules when conflicting with `rebase.autoStash`/`merge.autoStash`
- Both true/false/unset states for all relevant configs

Documentation in Documentation/config/pull.adoc clearly explains:
- The new option's purpose and behavior
- The configuration hierarchy and precedence rules
- Interaction with command-line flags
- Default value (false)

The implementation aligns with the thread's emerging consensus while fixing the previously noted inconsistency where `merge.autoStash` wasn't properly respected. The thorough test coverage suggests this is production-ready, though the thread indicates some documentation updates may still be needed to fully explain the configuration hierarchy to users.
