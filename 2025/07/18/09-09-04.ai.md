Performance optimization series converting commit traversal to use priority queues, now in its second version. This 3-patch series from René Scharfe replaces commit_list operations with a prio_queue to improve worst-case performance for merge-heavy histories while recovering best-case performance through a new prio_queue_replace() operation.

The key technical changes remain:
1. Conversion of pop_most_recent_commit() to use prio_queue (commit.c, walker.c, fetch-pack.c, object-name.c)
2. Addition of prio_queue_replace() to efficiently update the queue head (prio-queue.[ch])
3. Integration of the replace operation into commit traversal

Version 2 incorporates several documentation and test improvements:
- Clearer commit message explaining the merge-heavy history optimization target
- Added performance test (t/perf/p1501-rev-parse-oneline.sh) with detailed comments about the synthetic merge-heavy history it creates
- Meson build system integration for the new test
- Variable renaming from delete_pending to get_pending for clarity

The series appears ready for merging, having addressed all previous technical feedback including timestamp ordering semantics, meson integration, and test coverage. The changes are focused and well-motivated, with performance measurements showing:
- 92% speedup for pathological cases (50% merges/50% root commits)
- Neutral impact on normal traversal after the replace() optimization
- Comprehensive unit tests in t/unit-tests/u-prio-queue.c

This represents a clean optimization that maintains the existing interface while improving worst-case behavior, with no outstanding technical objections from prior discussion. The second version's improvements to documentation and testing make the changes even more reviewable.
