Junio Hamano responds to patch 6/7 in the Rust xdiff optimization series, which conditionally uses Rust's xxhash implementation when whitespace flags are disabled. This is a technical discussion about the future direction of the optimization work.

Junio acknowledges the current patch as a good proof of concept but notes it's not yet ready for upstreaming in its current form. The key missing piece is a whitespace-aware variant of xxhash that could handle all diff modes, which would allow completely replacing `xdl_hash_record()`. He suggests this enhanced hash function could be implemented in Rust as part of future work.

The response also highlights an important ecosystem consideration: third-party consumers of xdiff (like libgit2 and Vim) may need to maintain C implementations of these optimizations, reinforcing Phillip Wood's earlier concerns about library compatibility. This continues the thread's tension between Rust optimization benefits and maintaining xdiff as a standalone C library.

Junio's comments position this patch as an intermediate step toward a more complete solution, while technically sound, needs additional work to address both functional gaps (whitespace handling) and ecosystem concerns (C compatibility). His response maintains the project's cautious approach to Rust integration while acknowledging the potential benefits.
