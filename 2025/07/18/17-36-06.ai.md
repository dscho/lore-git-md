This is a fixup patch addressing SHA-256 compatibility in the `git last-modified` test suite. Junio C Hamano points out two issues with the test script for the `--extended` format output: hardcoded object hashes that would break with SHA-256 repositories, and an inconsistency in how trees versus commits are displayed. The patch focuses on the first issue by replacing hardcoded tree hashes with dynamically generated ones stored in `$TREE1` and `$TREE3` variables during test setup.

The changes are straightforward technical improvements to make the tests work with both SHA-1 and SHA-256 repositories. While Junio notes broader concerns about test maintainability and output format consistency, this patch specifically targets the immediate SHA-256 compatibility problem. The fix aligns with the series' ongoing refinement of test robustness, though it leaves the larger format design questions (like commit vs tree display) for future discussion.

This continues the pattern of Junio providing high-level design feedback while also contributing concrete fixes for immediate issues. The patch should be uncontroversial to include in the series, as it doesn't change functionality but rather makes existing tests more portable.
