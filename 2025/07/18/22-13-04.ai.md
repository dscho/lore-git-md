This is a feature patch implementing the `pull.autoStash` configuration option, part of the ongoing discussion about configuration precedence for auto-stash behavior in Git's pull command. Junio Hamano provides a detailed review of Lidong Yan's implementation, focusing primarily on documentation placement and test coverage.

The review notes the documentation needs to be moved to a different section of pull.adoc and suggests improved wording that more accurately describes the behavior (particularly clarifying that pull can sometimes work with dirty worktrees even without autostash). The proposed documentation text emphasizes that autostash is more critical for rebase operations than merges.

For the test suite, Junio analyzes each new test case, identifying which are most valuable for verifying the precedence rules (command-line > pull.autoStash > operation-specific configs). He suggests some test consolidations and additions to better cover edge cases, particularly around command-line overrides interacting with various config combinations. While noting several tests are "uninteresting" (either redundant or not testing unique scenarios), he confirms the overall test coverage is solid.

The review indicates technical consensus on the implementation approach, with only minor documentation and test tweaks needed. This suggests the patch is in good shape for finalization, marking the near-completion of this configuration hierarchy effort that began with conceptual discussions about auto-stash behavior.
