Performance optimization patch completing René Scharfe's series converting commit traversal to use priority queues. This final patch introduces a key optimization in `pop_most_recent_commit()` by using `prio_queue_peek()` and the new `prio_queue_replace()` operation instead of the less efficient `prio_queue_get()`/`prio_queue_put()` combination.

The change specifically targets the first parent traversal case, where we can now update the queue head in-place rather than removing and re-adding the commit. Benchmark results show this restores the original performance in Git's own repository, with the new version actually slightly faster (1.01x) than both the original implementation and the intermediate `prio_queue` version from earlier in the series.

The implementation adds a `get_pending` flag to track whether we're processing the first parent (where replace is optimal) versus subsequent parents (which still use put). The patch modifies only `commit.c`, with 9 lines added and 2 removed in the core traversal logic. This completes the series' goal of improving worst-case performance for merge-heavy histories while maintaining or improving best-case performance through careful use of the priority queue operations.

With all feedback addressed in v2 patches and no outstanding technical concerns, this appears ready for merging as the final piece of the optimization effort. The series demonstrates measurable improvements while maintaining clean interfaces and comprehensive test coverage.
