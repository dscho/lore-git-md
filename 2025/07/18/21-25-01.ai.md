This is a platform compatibility concern regarding the proposed Rust dependency for Git, specifically addressing distribution and architecture support challenges. Eli Schwartz from Gentoo raises several practical issues with making Rust a hard dependency:

The email highlights that Gentoo on amd64 would need to build multiple Rust compiler versions (13+) from source via mrustc, which is burdensome. For less common architectures like HPPA, Alpha, and m68k, Rust simply isn't available, potentially forcing these platforms to either abandon Git or remain on version 2.50 indefinitely. Even s390 support is limited to precompiled binaries that some users reject for auditability reasons.

Schwartz questions what minimum Rust version the series requires (a detail not specified in the thread so far) and notes that GCC-rs might eventually solve these cross-platform issues. The concerns directly counter Phillip Wood's position that Rust is "widely supported" enough to justify a hard dependency, particularly highlighting how distribution packaging realities differ from theoretical language availability.

This adds a significant new dimension to the ongoing discussion about Rust adoption, introducing concrete deployment obstacles that weren't previously addressed in the technical debates about performance gains and xdiff compatibility. The email comes from a distribution maintainer's perspective, emphasizing real-world constraints that affect users on niche architectures and those with strict source-build policies.
