This is a technical clarification in the ongoing RFC discussion about Rust integration and xdiff optimizations. Junio Hamano responds to Christian Brabandt's inquiry about whether the Git project plans to completely replace xdiff's C implementation with Rust, explaining that no such consensus exists yet. He notes that the current RFC only introduces a Rust-based hash function for specific cases (when whitespace flags are disabled) while keeping the rest of xdiff in C.

Junio shares his personal opinion that xmerge would have been a better starting point for Rust integration than xdiff, though he presents this as an individual perspective rather than project policy. The response maintains the thread's technical focus while providing important context about the limited scope of the current changes and the absence of any broader Rust migration plan for xdiff at this stage. This helps clarify the project's position for external consumers like Vim/Neovim who rely on xdiff as a library.
