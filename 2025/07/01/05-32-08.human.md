This is a documentation patch that clarifies misleading comments in the bitmap loading code. It's the second patch in a three-part series fixing memory leaks in pack-bitmap.c.

The patch rewrites comments in `test_bitmap_commits()` to accurately reflect the function's behavior. The original comments incorrectly suggested the commit table could be skipped entirely, when in fact the function must load bitmap entries to obtain commit IDs for output. The new wording makes it clear that while the function bypasses the commit lookup table (if one exists), it still needs to load bitmap entries to access the commit information.

This change was suggested by Taylor Blau in earlier iterations of the series, who recommended minor editorial improvements to the wording (preferring "bitmapped commits" over "bitmap selected commits"). The patch serves as preparatory work for the test infrastructure improvements in the subsequent patch, helping ensure the code's comments accurately describe the actual behavior before adding more complex test cases.

The change is purely textual and non-controversial, having already received positive feedback from reviewers. It demonstrates good attention to detail in ensuring code comments match implementation behavior.
