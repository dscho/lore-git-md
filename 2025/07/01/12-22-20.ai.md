This is part of Patrick Steinhardt's ongoing series (v6 08/17) to eliminate `the_repository` global state from Git's object database (ODB) subsystem, enabling pluggable backends. The patch converts alternates-handling functions to take explicit `object_database *odb` parameters instead of relying on `the_repository`, renaming them with an `odb_` prefix for consistency.

Key changes:
- `prepare_alt_odb()` -> `odb_prepare_alternates()`
- `has_alt_odb()` -> `odb_has_alternates()`
- `add_to_alternates_file()` -> `odb_add_to_alternates_file()`
- `add_to_alternates_memory()` -> `odb_add_to_alternates_memory()`

The patch updates 14 call sites across core functionality (clone, fsck, repack, commit-graph) and test helpers. The commit notes this is transitional - alternates still use the repository's path, which will be addressed in later patches. The mechanical conversion maintains existing behavior while progressing the architectural goal of removing global state.

This continues the series' pattern seen in previous patches (5-7/17) of methodically updating ODB APIs to explicit parameters. The changes are straightforward with no implementation concerns, building on established patterns from earlier conversions. Review feedback from Justin Tobler on path handling has been incorporated, and Derrick Stolee provided Reviewed-by on foundational patches.
