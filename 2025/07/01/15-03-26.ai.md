This is a feature patch series introducing pagination capabilities to `git for-each-ref`. The main addition is a `--skip-until` option that allows starting iteration from a specific reference rather than always beginning from the start, which is particularly useful for large repositories with millions of references.

The series makes significant changes across the refs subsystem to enable this functionality. It exposes the `ref_iterator` interface publicly in refs.h and modifies seek behavior to work with the new pagination feature. The implementation touches all major ref backends (files, packed, reftable), with the files backend requiring more extensive changes due to its ref-cache implementation. A new test file (t6302) is added with 180 lines of tests for the new functionality.

The author notes they initially considered broader refs API cleanup but deferred that to keep this series focused. The changes appear thorough, with modifications to documentation, core functionality, and comprehensive test coverage. The commit messages explain the technical approach clearly, though they don't quantify the performance benefits for large repositories. This seems like a well-considered addition that could significantly improve performance for tools that need to paginate through large numbers of references.
