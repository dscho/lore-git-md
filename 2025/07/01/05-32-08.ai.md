This is a documentation patch that clarifies misleading comments in the bitmap loading code, part of a bugfix series addressing memory leaks in pack-bitmap.c.

The patch rewrites comments in `test_bitmap_commits()` to accurately reflect the function's behavior. The original comments incorrectly suggested the commit table could be skipped entirely, while in reality the function must load bitmap entries to obtain commit IDs for output. The new comments explain that while the function bypasses the commit lookup table (if present), it still needs to load bitmap entries to access the commit information.

This change was suggested by Taylor Blau in earlier iterations of the series, who noted the original comments were misleading. The patch represents a minor but important clarification that helps maintain accurate documentation of the bitmap loading behavior. While purely textual, this change serves as preparatory work for the test infrastructure improvements in the subsequent patch of the series.

The patch maintains the same technical approach as previous versions, with only the comment wording being updated. Taylor Blau had suggested preferring "bitmapped commits" over "bitmap selected commits" in the comments, but considered this too minor to require a reroll. The change has been reviewed and approved as part of the overall series addressing bitmap memory leaks.
