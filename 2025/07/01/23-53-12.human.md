This is the final patch in a refactoring series that moves sparse-checkout configuration from global variables to repository-specific settings, part of the ongoing `the_repository` removal effort. The patch localizes the `sparse_expect_files_outside_of_patterns` variable to the function that uses it, reading the config value directly via `repo_config_get_bool()` rather than through global initialization.

Phillip Wood points out a subtle but important behavioral change: invalid config values for `sparse.expectfilesoutsideofpatterns` will now be detected mid-command rather than at startup, potentially leading to commands failing partway through execution. Ayush Chandekar acknowledges this but notes it aligns with how other repository settings handle invalid values in `prepare_repo_settings()`.

The patch appears technically sound and completes the series' goal of eliminating these globals, but the config validation timing change introduces a tradeoff between architectural consistency and user experience. This is the last remaining open question in an otherwise well-reviewed series that has addressed initialization safety and other concerns through five iterations.
