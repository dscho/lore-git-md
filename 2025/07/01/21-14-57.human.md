This is a discussion about hash algorithm selection for Git commands that operate outside repositories, part of the SHA-256 transition series.

The thread centers on whether commands like `index-pack` and `ls-remote` should default to SHA-1 (for backward compatibility with scripts) or use the new default hash algorithm (SHA-256 when built with WITH_BREAKING_CHANGES). Patrick Steinhardt suggested using GIT_HASH_LEGACY_SHA1 to maintain historical behavior, but brian m. carlson argues this would create long-term inconvenience for users who want to work with SHA-256 objects outside repositories.

The exchange highlights a key design tension in the SHA-256 transition: backward compatibility versus forward-looking defaults. The author makes a pragmatic case that repository-object operations should align with the built-in default rather than hardcoding SHA-1, even if it means some script adjustments may eventually be needed. This appears to be one of the final open questions in the otherwise well-vetted series.
