This is a discussion about patch 1/5 in the `git apply --intent-to-add` bugfix series, focusing on whether to error out when using `-N` outside a repository. Raymond Pasco originally proposed making it an error, but Junio Hamano suggests the current silent ignore behavior might be preferable.

The key debate centers on user expectations: Raymond argues that using `-N` implies the user thinks they're in a repository, while Junio counters that since `-N` is less repository-dependent than `--index`/`--cached`, silently ignoring it (like the current behavior) may be more user-friendly. This reflects a broader discussion about when Git should fail loudly versus quietly adapt to context.

The exchange shows the careful consideration going into this series' design decisions, with Junio providing architectural perspective as the original `add -N` inventor. The discussion remains open-ended, with no clear resolution yet on whether to maintain the silent behavior or switch to explicit errors.
