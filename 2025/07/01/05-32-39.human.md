This is a bugfix patch in the `git apply --intent-to-add` series, specifically addressing the core issue where the index wasn't being properly read in intent-to-add mode. The patch fixes the behavior where `git apply -N` was incorrectly creating a new index with only intent-to-add entries, effectively making it appear that all existing files were deleted.

Raymond Pasco explains that the root cause was the index not being read before writing ITA entries, which led to starting from an empty tree state. Junio Hamano, the original inventor of `add -N`, had questioned whether writing only ITA entries was conceptually correct, and this patch aligns with that concern by ensuring the existing index is properly read and updated rather than replaced.

The discussion reveals this is a longstanding issue that made `--intent-to-add` effectively non-functional except in empty repositories. The fix modifies `read_apply_cache()` to properly handle intent-to-add mode while maintaining the index's existing state. This is part of a larger series that includes test coverage and documentation updates to solidify the corrected behavior.

The patch appears technically sound and addresses a clear bug, though there's ongoing discussion about some philosophical questions around the intended behavior of intent-to-add operations. The exchange between Raymond and Junio shows careful consideration of both the technical implementation and conceptual model.
