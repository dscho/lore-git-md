This is part 10/11 of the SHA-256 default hash transition effort, focusing on improving visibility into the default hash algorithm selection. The patch adds a new "default-hash" line to `git version --build-options` output, showing which hash algorithm is configured as the default (SHA-256 when built with WITH_BREAKING_CHANGES, otherwise SHA-1).

The change is straightforward - a single line addition to help.c that reports the default hash algorithm name. This will make it easier when users report issues, as they won't need to dig through build configurations to determine which hash algorithm their Git was compiled to use by default. The patch follows the established pattern of the existing hash-related build option reporting in the same function.

This is a small but useful quality-of-life improvement that complements the larger hash transition work. It doesn't introduce any new behavior or configuration - it makes the existing behavior more transparent. The change is cleanly implemented and clearly motivated in the commit message. As part of the broader series that's already received technical approval, this patch seems uncontroversial and ready for inclusion.
