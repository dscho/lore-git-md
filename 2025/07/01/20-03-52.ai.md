Platform compatibility patch addressing FreeBSD build issues with libsysinfo. Ramsay Jones proposes a third approach to the ongoing FreeBSD sysinfo detection problem, distinct from the two solutions previously discussed in the thread. The patch modifies both configure.ac and meson.build to only define HAVE_SYSINFO if HAVE_BSD_SYSCTL is not already set, giving BSD sysctl precedence over the GNU sysinfo compatibility library.

Key technical details: The patch restructures the sysinfo detection logic to be conditional on BSD sysctl availability, moving the sysinfo check after the sysctl check in configure.ac. It makes parallel changes in meson.build to maintain consistency between build systems. The approach assumes BSD systems should prefer their native sysctl interface when available, falling back to sysinfo only when necessary.

This differs from the earlier proposed solutions by avoiding any linker flag modifications (-lsysinfo) and instead solving the problem through preprocessor logic. The patch appears minimally invasive but lacks test verification (as noted by the author's inability to test on FreeBSD) and commit message justification. The change follows Git's build system conventions but may need validation from FreeBSD users to confirm it resolves the original linker errors while maintaining correct functionality on all affected platforms.
