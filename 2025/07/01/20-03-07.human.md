Platform compatibility fix for FreeBSD builds with libsysinfo. Eric Sunshine responds to Renato Botelho's inquiry about fixing build failures that occur when libsysinfo (a GNU libc sysinfo port) is installed on FreeBSD systems. The current issue causes linker errors due to missing `-lsysinfo` in LDFLAGS.

Sunshine outlines two potential solution paths. The minimal approach would modify configure.ac to use `AC_LINK_IFELSE` instead of `AC_COMPILE_IFELSE` for the sysinfo check, preventing HAVE_SYSINFO from being defined if linking fails. For a more complete solution that enables sysinfo functionality on FreeBSD, he suggests: (1) adding NEEDS_LIBSYSINFO to Makefile with corresponding EXTLIBS handling, (2) optionally updating config.make.uname for direct builds, and (3) enhancing configure.ac to properly detect when `-lsysinfo` is needed.

The response provides clear technical guidance while leaving the choice of approach to Botelho, noting the trade-off between minimal effort (just fixing the build) versus more comprehensive support (enabling the feature). This moves the thread forward by offering concrete implementation options while maintaining flexibility for the FreeBSD maintainer's preferences.
