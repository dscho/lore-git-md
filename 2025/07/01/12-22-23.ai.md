This is part 11/17 of Patrick Steinhardt's series refactoring Git's object database (ODB) subsystem to eliminate `the_repository` global state. The patch focuses on submodule ODB handling, specifically the mechanism that allows `git grep --recursive` to search across submodules by temporarily adding their object stores as alternates.

The key change moves submodule source path tracking from a global string list in submodule.c to being stored directly in the object_database struct. This eliminates the need for the `r == the_repository` check when registering submodule alternates, since the paths are now stored in the repository's ODB rather than a global variable. The patch renames related functions to use the new `odb_` prefix convention (`add_submodule_odb_by_path` -> `odb_add_submodule_source_by_path`) and moves their implementations from submodule.c to odb.c.

Behavior remains identical - submodule paths are still registered as alternates when objects can't be found - but the implementation is now repository-aware rather than relying on global state. The patch removes the old global string list and functions from submodule.{c,h} while adding equivalent functionality to odb.{c,h}, including proper cleanup in `odb_clear()`. 

This continues the series' pattern of making ODB operations repository-agnostic while maintaining backward compatibility. The changes are localized to submodule handling code and the ODB infrastructure, with callers in builtin/grep.c and submodule-config.c updated to use the new API. The commit message clearly explains the motivation (libification) and maintains the series' high standard of documentation.
