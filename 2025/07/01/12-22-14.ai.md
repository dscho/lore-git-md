This is part 2/17 of Patrick Steinhardt's series to refactor Git's object database (ODB) subsystem, continuing the architectural work to eliminate `the_repository` global state and enable pluggable ODB backends. The patch renames `struct object_directory` to `struct odb_source` to better reflect its role as an access point for object storage that may not always be directory-based in the future.

The change affects 28 files with mechanical updates to type names and function signatures. The new name `odb_source` was chosen over alternatives like `odb_backend` (too implementation-focused) and `odb_alternate` (misleading for primary object stores). This naming prepares for future introduction of format-specific implementations like `odb_files_source`.

Key technical points:
- The structure represents access points for object storage locations (like ".git/objects")
- Current directory-based storage will eventually support pluggable backends
- Changes propagate through commit-graph, loose object, and packfile handling
- Maintains backward compatibility while establishing clearer terminology

The patch follows the naming convention established in the series (prefixing ODB-related types/functions with `odb_`) and has already incorporated review feedback from Justin Tobler on naming choices. It's a foundational change that enables the subsequent patches to build proper self-contained ODB sources with explicit parameter passing.
