Bugfix patch addressing a memory leak in pack-bitmap.c's bitmap loading paths. This is the first of three patches in a series that has undergone extensive review (now at version 6) to handle memory leaks when loading corrupt bitmaps.

The patch simplifies error handling in `load_bitmap()` by removing redundant cleanup code and relying on callers (`prepare_bitmap_walk()` and `prepare_bitmap_git()`) to perform cleanup via `free_bitmap_index()`. The key change replaces all `goto failed` jumps with direct `return -1`, eliminating ~17 lines of error-handling code while maintaining safety. This fixes a leak where partially-loaded bitmap entries weren't being freed when loading failed, since the cleanup path was destroying the bitmap map before the entries could be processed.

The solution demonstrates the rare case where fixing a bug removes code rather than adding it. The patch has been reviewed by Jeff King and received positive feedback from Junio C Hamano for this simplification. It includes sign-offs from both Taylor Blau (who authored the fix) and Lidong Yan (who originally reported the issue). The changes are focused on pack-bitmap.c, with no test modifications needed since the series' test coverage comes in later patches.

This represents the technical consensus from multiple review iterations to use centralized cleanup via `free_bitmap_index()` rather than per-error-path handling. The patch is now in its final form with all substantive feedback incorporated.
