This is part 5/11 in the series transitioning Git to use SHA-256 as the default hash algorithm when built with WITH_BREAKING_CHANGES. The patch focuses on repository initialization behavior.

The key change updates the default hash algorithm initialization in `REPOSITORY_FORMAT_INIT` from hardcoded SHA-1 to `GIT_HASH_DEFAULT`, while maintaining SHA-1 fallback for legacy cases. The patch makes several specific behavioral guarantees:

1. New repositories will use the default algorithm (SHA-256 when enabled)
2. Version 0 repositories and those without explicit objectFormat extension continue using SHA-1 via `GIT_HASH_SHA1_LEGACY`
3. Repositories with missing/invalid config files (version == -1) are explicitly set to SHA-1 legacy mode
4. The `clear_repository_format()` function now preserves the legacy SHA-1 default when reading existing repositories

The changes touch `setup.c` and `setup.h`, modifying the repository format initialization and reading logic. The author acknowledges the potentially questionable behavior of ignoring all repository configuration when core.repositoryformatversion is missing, but maintains the existing behavior for backward compatibility while documenting the tradeoffs.

This patch builds on the infrastructure established in earlier patches (particularly the hash algorithm constants introduced in patch 1) and handles one of the key backward compatibility cases in the SHA-256 transition. The changes are mechanical but important for maintaining consistent behavior across different repository version scenarios.
