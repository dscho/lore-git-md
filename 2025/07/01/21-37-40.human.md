Maintainer feedback on clang-format changes. Junio C Hamano shares observations after running clang-format on the recently merged `for-each-ref` seeking functionality series. While acknowledging some improvements (like better line wrapping in `refs_ref_iterator_begin()`), he critiques several aspects of the automated formatting:

1. The tool makes overly aggressive changes to the `opts[]` array in `builtin/for-each-ref.c`, reformatting existing entries when only one new option (`--skip-until`) was added.
2. It poorly handles commented-out code in `refs.h`.
3. Some line wrapping changes (in `ref_iterator_seek()` and `do_for_each_ref_iterator()` declarations) reduce readability compared to the original.

Hamano questions whether clang-format could be made more focused to avoid unnecessary reformatting of unchanged code sections. This isn't a critique of the patch series itself (which was already merged) but rather a general observation about the formatting tool's behavior with Git's codebase. The feedback suggests room for improvement in clang-format's handling of complex option arrays and commented code.
