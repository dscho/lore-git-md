This is a bugfix discussion regarding the sparse-checkout configuration refactoring series.

Phillip Wood points out a subtle but important behavior change in Ayush Chandekar's patch that moves the `sparse.expectfilesoutsideofpatterns` config check from global initialization to the point of use. Previously, invalid config values would cause Git to fail immediately at startup, but now they'll only trigger when the specific function needing the config is called, potentially mid-operation.

The observation highlights a regression in error handling that wasn't caught in earlier reviews. While the refactoring's main goal of removing globals is sound, this side effect means invalid configs could now cause partial command execution before failing. The issue sits at the intersection of configuration validation and user experience, requiring consideration of whether the new behavior is acceptable or if additional validation should be added elsewhere.

This comes as the final review feedback on what was otherwise considered a ready-to-merge series, showing how even well-vetted changes can have subtle consequences. The thread's participants will need to decide whether to accept the new behavior, add early validation, or find another solution that preserves both the global removal and immediate error checking.
