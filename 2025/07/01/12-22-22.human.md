This is part of Patrick Steinhardt's ongoing series to remove `the_repository` global state from Git's object database (part of the `the_repository` removal effort). Patch 10/17 focuses on eliminating `the_repository` usage from temporary primary ODB handling functions.

The patch converts two key functions - `set_temporary_primary_odb()` and `restore_primary_odb()` - to take explicit `object_database` parameters instead of implicitly using `the_repository`. The functions are renamed to follow the established `odb_` prefix convention (`odb_set_temporary_primary_source` and `odb_restore_primary_source`). The changes affect temporary object directory handling used in operations like `git fetch` and `git push`.

The conversion is straightforward, with the main changes being:
1. Adding the `odb` parameter to both functions
2. Updating all internal references from `the_repository->objects` to use the passed `odb`
3. Renaming variables for clarity (`restore_alt` -> `restore_source`)
4. Updating callers in `tmp-objdir.c` to pass the repository's ODB explicitly

This continues the series' systematic approach to removing global state while maintaining clear API boundaries. The changes are well-contained and follow the established pattern seen in earlier patches, suggesting this is a low-risk but important step in the larger refactoring effort.
