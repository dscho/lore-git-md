This is a discussion about hash algorithm defaults in the SHA-256 transition series. Patrick Steinhardt responds to brian m. carlson's patch that changed commands operating outside repositories to use the default hash algorithm (GIT_HASH_DEFAULT) rather than hardcoded SHA-1.

Patrick suggests an alternative approach - using GIT_HASH_ORIGINAL (later renamed to GIT_HASH_LEGACY_SHA1 in the series) for these cases. His rationale is that since these commands historically treated such cases as SHA-1 repositories, maintaining that behavior explicitly would prevent script breakage regardless of how Git was built. This touches on the core distinction in the series between explicit SHA-1 usage (GIT_HASH_SHA1) and legacy SHA-1 fallback behavior (GIT_HASH_LEGACY_SHA1).

The discussion highlights an important edge case in the transition - how to handle commands that operate both inside and outside repositories. Patrick's suggestion would maintain backward compatibility for scripts by preserving the historical SHA-1 behavior when no repository exists, rather than potentially changing behavior based on the build configuration's default hash algorithm. This relates to the series' broader goal of carefully distinguishing between explicit SHA-1 usage and legacy fallback cases.
