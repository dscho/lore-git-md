This thread began with the merged 4-part series introducing `--skip-until` pagination to `git for-each-ref`, which added efficient seeking capabilities through a new `ref_iterator_seek()` interface. After merging, discussion turned to usability considerations - first around the skip behavior's interaction with sorting (where `--skip-until` operates on native storage order before `--sort` applies), and now to code formatting impacts.

The latest exchange focuses on clang-format's unintended changes to the merged code. Karthik Nayak and Junio Hamano identified several problematic formatting cases, particularly in `refs.h` and `builtin/for-each-ref.c`, where the tool:
1. Mangled array initializers and commented-out code
2. Applied non-standard if/else bracing via the "RemoveBracesLLVM" rule
3. Disrupted Git's conventional code layout in function declarations

Karthik proposes scaling back the formatting rules to eliminate these false positives before considering wider enforcement. This practical adjustment acknowledges the challenge of applying automated formatting while preserving Git's established style and readability. The core pagination functionality remains unchanged, but the discussion highlights ongoing maintenance considerations around tooling adoption.
