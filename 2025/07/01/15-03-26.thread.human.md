This thread discusses the development of a pagination feature for `git for-each-ref`, now in its third iteration. The technical implementation is complete, with all backends (files, packed, reftable) supporting O(log N) performance via sorted reference seeking. The series awaits final naming consensus for the new option that enables pagination by seeking to a position in the sorted ref list.

Karthik Nayak has implemented the feature with current patches using `--skip-until=<pattern>`, but Andreas Schwab argues this name is misleading since the operation performs positional seeking rather than pattern matching. Andreas maintains that `--start-with` better describes the actual behavior of dividing the ref list at the position where a given name would appear in the sorted order. This builds on Karthik's earlier clarification that the feature seeks to insertion points (where a ref would be if it existed) rather than doing exact matches.

The naming discussion has seen multiple proposals including `--skip-to`, `--start-after`, `--seek`, and others, with no clear consensus yet. The technical aspects are settled - the implementation handles edge cases, maintains robustness against concurrent modifications, and works across all ref backends. The remaining question is selecting the name that most clearly conveys the positional seeking behavior to users. Karthik continues to maintain the implementation while considering the naming feedback.
