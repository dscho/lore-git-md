This thread documents the recently merged `--skip-until` pagination feature for `git for-each-ref`, which enables efficient skipping in ref listings using name-based markers rather than numeric offsets. The implementation includes a new `ref_iterator_seek()` interface with O(log N) performance, supported across all ref backends (files, packed, reftable), plus comprehensive test coverage.

Patrick Steinhardt has been leading post-merge refinements, focusing on interface documentation clarity - particularly around whether `--skip-until` includes or excludes the matching pattern, and ensuring consistent prefix handling. The latest discussion, involving Junio C Hamano, examines race condition implications. While the name-based approach avoids numeric offset invalidation from concurrent writes, Junio notes it's not completely race-proof - if the marker ref is deleted or new refs are inserted before it, pagination could still break. This exchange documents an inherent limitation in both approaches when dealing with concurrent modifications, though the name-based solution was chosen for its superior performance characteristics.

The thread shows consensus on the core design while continuing to polish documentation and edge case handling.
