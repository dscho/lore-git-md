This thread documents the implementation and refinement of the `--skip-until` pagination feature for `git for-each-ref`, which has now been merged. The feature enables efficient name-based skipping of refs with O(log N) performance through a new `ref_iterator_seek()` interface, with adaptations across all ref backends (files, packed, and reftable).

Junio C Hamano initially raised concerns about potential race conditions when refs are modified during pagination. Patrick Steinhardt's follow-up clarified that the implementation handles these cases as designed: if the marker ref is deleted between requests, pagination continues working correctly, and new refs inserted before the marker are properly excluded. This confirms the name-based approach maintains consistency by tracking sort position rather than ref existence.

The discussion has shifted from active development to documenting the solution's characteristics and tradeoffs. While the implementation shares some race condition limitations with numeric offsets, its predictable behavior under concurrent modification and superior performance make it the preferred approach. The thread now stands as comprehensive documentation of the feature's design, including its technical justification, interface refinements, and edge case handling.
