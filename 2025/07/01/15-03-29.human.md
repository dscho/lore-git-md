This is the third patch in a 4-part series adding `--skip-until` pagination support to `git for-each-ref`. The patch refines the behavior of the `ref_iterator_seek()` function to make it more flexible and less confusing.

The key change is splitting the function's behavior into two modes via a new `set_prefix` parameter. When true, it maintains the current behavior of setting the iteration prefix (filtering subsequent results). When false, it simply seeks to the specified reference without changing the prefix, allowing iteration to start from that point. This addresses the confusion where the function's name suggested seeking behavior but actually performed prefix filtering.

The implementation requires changes across all ref backends (files, packed, reftable), with the files backend needing the most work due to its ref-cache mechanism. The patch moves prefix-setting logic into a new `cache_ref_iterator_set_prefix()` helper and adds detailed seeking logic for the files backend case.

This appears to be a well-considered change that makes the API more intuitive while maintaining backward compatibility. The commit message clearly explains the motivation and implementation approach. The changes are focused and touch only the relevant parts of each backend. As part of a larger series to enable efficient reference pagination, this patch provides important groundwork for the final pagination feature.
