This is part of Patrick Steinhardt's ongoing series to eliminate `the_repository` global state in Git's object database (ODB) subsystem. Patch 6/17 continues the mechanical conversion of ODB-related functions to take explicit object database parameters rather than relying on global state.

The patch converts `assert_oid_type()` to take an explicit `object_database` parameter and renames it to `odb_assert_oid_type()` for consistency with the new naming convention. The function verifies that a given object ID matches the expected type (commit, tree, etc.), and this change ensures it operates on a specific ODB instance rather than implicitly using `the_repository`.

The changes are straightforward - updating the function signature and its single call to `oid_object_info()` to use the passed-in ODB's repository pointer. Three call sites are updated to pass `the_repository->objects` explicitly. This is part of the broader architectural shift to make ODB operations repository-aware without global state.

The patch follows the established pattern seen in earlier parts of the series, with careful mechanical conversions and clear documentation. Review feedback from previous versions has been addressed, and the changes appear well-contained and correct. This continues the steady progress toward pluggable ODB backends by removing another dependency on global state.
