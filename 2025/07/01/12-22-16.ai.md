This is part of Patrick Steinhardt's ongoing series to eliminate `the_repository` global state in Git's object database (ODB) subsystem, specifically patch 4/17. The patch introduces parent pointers between ODB components to enable repository access without relying on global state.

The change adds two key parent pointers:
1. `struct object_database` gains a `repo` field pointing to its owning repository
2. `struct odb_source` gains an `odb` field pointing to its owning object database

These pointers allow functions that previously relied on `the_repository` to instead traverse from an ODB or source to its parent repository when needed (e.g. for config lookups). The patch updates several functions to pass through the ODB explicitly rather than implicitly using `the_repository`, including `link_alt_odb_entry()` and related alternate-handling functions. The changes are mechanical but important for maintaining correct relationships as the code moves away from global state.

The patch affects 3 files with 35 lines added and 21 removed, primarily updating function signatures and call sites to handle the new parent pointers. It builds on the structural renaming from earlier patches in the series (converting `raw_object_store` to `object_database`) while maintaining backward compatibility. The changes are well-contained within the ODB subsystem and follow the series' pattern of explicit state passing.
