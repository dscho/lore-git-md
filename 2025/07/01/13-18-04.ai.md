This is a bugfix discussion regarding the final patch in Ayush Chandekar's sparse-checkout refactoring series, which moves configuration from globals to repository settings. Phillip Wood points out a subtle but important behavioral regression in how invalid config values are handled.

The patch changes `sparse.expectfilesoutsideofpatterns` to be read via `repo_config_get_bool()` at point of use in `clear_skip_worktree_from_present_files()`, rather than during global config parsing. Phillip notes this means invalid values will now only be caught when that specific function runs, rather than failing fast during command startup. This could lead to mid-command failures where previously Git would have aborted immediately with a config validation message.

The observation highlights a tradeoff in the global-to-local migration approach: while the change improves modularity by removing global state, it potentially degrades the user experience for config validation. The thread context shows this is the final version of a carefully reviewed series, so this appears to be the first notice of this particular side effect. The issue doesn't invalidate the architectural approach but may require either documentation of the changed behavior or consideration of alternative validation timing.

Key technical points:
- Current behavior: invalid values fail during `git_default_config()` at startup
- New behavior: invalid values only fail when `clear_skip_worktree_from_present_files()` is called
- Impact: moves validation from command entry to possible mid-command failure
- Related to patch 3's localization of `sparse_expect_files_outside_of_patterns`
- Not caught in prior reviews of the series' initialization safety focus

This raises a question about whether config validation timing is considered part of the contract for this setting, and whether the change requires mitigation through either documentation or additional validation plumbing. The thread's prior focus on initialization safety didn't anticipate this particular consequence of moving validation from global to local scope.
