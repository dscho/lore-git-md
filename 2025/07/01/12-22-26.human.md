This is part of Patrick Steinhardt's ongoing series to refactor Git's object database (ODB) subsystem, specifically patch 14/17 in v6. The patch continues the systematic renaming of ODB-related functions to use consistent `odb_` prefixes and remove reliance on the `the_repository` global.

The key change here is renaming `repo_read_object_file()` to `odb_read_object()`, updating 47 call sites across the codebase. The function's behavior remains the same - it reads an object from the ODB and returns its contents - but the new name better reflects its purpose and fits with the series' goal of making ODB operations more self-contained. A compatibility wrapper is provided to avoid breaking in-flight topics.

This change follows the established pattern from previous patches in the series (like patch 13/17 which renamed `oid_object_info()`). The patch appears mechanically sound, touching only the expected call sites with straightforward replacements. Given the thorough review process this series has undergone and the uncontroversial nature of this rename (which maintains backward compatibility), this patch seems ready to proceed.

The series as a whole is methodically eliminating `the_repository` usage in the ODB layer while improving API consistency, with this patch representing another incremental step toward that goal.
