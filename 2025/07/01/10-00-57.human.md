This is a bugfix patch in the ongoing series to make interactive patch commands respect diff context configuration. The patch specifically addresses `git add -p` not honoring `diff.context` and `diff.interHunkContext` settings, which was an inconsistency compared to other diff-related commands.

The change adds config reading and validation to the add-patch infrastructure, storing the values in a new `struct add_i_state` and passing them through to the diff machinery. The implementation includes proper error handling for negative values and adds test coverage for both the positive case (showing the config affects the diff output) and negative case (rejecting invalid values).

Phillip Wood has reviewed the patch and approves the approach, marking another step toward completing this series. The changes look straightforward and well-tested, with clear additions to both the core logic and test suite. This brings the interactive commands in line with the behavior of other Git commands that show diffs.
