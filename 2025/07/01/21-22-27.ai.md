This is the first patch in v2 of the SHA-256 default hash algorithm series, introducing foundational infrastructure for the transition. The patch adds a new constant `GIT_HASH_DEFAULT` currently set to `GIT_HASH_SHA1`, preparing the codebase for a potential future change to SHA-256 as the default when built with `WITH_BREAKING_CHANGES`.

The change is minimal but strategically important - it creates a single point of control for the default hash algorithm rather than having SHA-1 hardcoded throughout the codebase. The patch touches only `hash.h`, adding the new constant alongside existing hash algorithm definitions. This follows the series' goal of making hash algorithm selection more explicit and maintainable.

As noted in the thread context, this is part of a larger effort to transition to SHA-256 as the built-in default while maintaining backward compatibility. The constant naming (`GIT_HASH_DEFAULT` vs `GIT_HASH_SHA1_LEGACY`) was discussed in v1 and resolved in this revision. The patch appears straightforward and well-contained, with no apparent controversy in this specific change.
