Patch 14/17 in Patrick Steinhardt's series continues the systematic renaming of object database (ODB) functions as part of the `the_repository` removal effort. This patch renames `repo_read_object_file()` to `odb_read_object()`, updating 47 call sites across the codebase while maintaining backward compatibility through a wrapper function.

The change follows the established pattern in this series of moving from repository-centric function names to ODB-centric ones, with the new name better reflecting that the operation works directly with the object database rather than the repository abstraction. The patch includes a mechanical update of all callers to pass `the_repository->objects` as the first parameter instead of `the_repository`.

This is a straightforward rename with no behavior changes, similar to the earlier `oid_object_info()` to `odb_read_object_info()` in patch 13/17. The change affects core object reading operations used throughout Git, including in commands like `cat-file`, `grep`, `log`, and the merge machinery. The patch maintains the function's error behavior where it dies on corrupt objects, leaving that handling to callers who want more control.

The rename is part of the broader effort to eliminate global state by making ODB operations explicitly take their database context, preparing for pluggable ODB backends. With all review feedback from previous iterations addressed and no outstanding implementation issues, this change follows the series' established patterns and is expected to be uncontroversial.
