Documentation follow-up with test implications. Kristoffer Haugsbakk responds to feedback about their patch standardizing `--value=<pattern>` terminology in git-config documentation, acknowledging that the change causes test failures in t0450.142. This test verifies consistency between documentation and command-line help output, where the help text still uses `--value=<value>`. 

The thread context shows this was an oversight - the author confirms they didn't run the t0450 tests during preparation, which would have caught the terminology discrepancy earlier. While the documentation standardization makes sense conceptually (the option accepts patterns, not just generic values), the implementation now needs to be updated to match, either by changing the help text or reconsidering the terminology choice.

This is part of a larger effort to document config subcommand options following the ps/config-subcommands merge, where multiple terminology inconsistencies were introduced. The discussion has helpfully surfaced both the specific test gap and remaining undocumented instances of the old terminology that need cleanup.
