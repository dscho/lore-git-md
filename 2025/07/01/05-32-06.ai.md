This is the sixth version of a bugfix series addressing memory leaks in pack-bitmap.c's bitmap loading paths. The series has been through extensive review and is now in its final form, incorporating all feedback from previous iterations.

The series consists of three patches:
1. Taylor Blau's fix for EWAH bitmap leaks by removing redundant cleanup code in `load_bitmap()`, simplifying error handling to rely on callers' `free_bitmap_index()`
2. Lidong Yan's comment rewording in `test_bitmap_commits()` to clarify bitmap lookup table behavior
3. Lidong Yan's addition of comprehensive test coverage using a new `test-tool bitmap list-commits-with-offset` helper

Key technical aspects include:
- Removal of duplicate cleanup paths in favor of centralized `free_bitmap_index()` handling
- New `map_pos` field in `struct stored_bitmap` to track bitmap file positions
- Test case that corrupts xor_offset field while verifying correct object lists
- Simplified test infrastructure using file-based output capture and sorted outputs

The series has received final approval from Taylor Blau after addressing all review comments, with only trivial wording suggestions remaining. The changes affect pack-bitmap.c, pack-bitmap.h, t/helper/test-bitmap.c, and t5310-pack-bitmaps.sh. This represents the culmination of five review iterations and provides both the memory leak fixes and improved test coverage for bitmap corruption scenarios.
