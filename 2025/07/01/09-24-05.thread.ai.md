Thread identity: Bug report about treeless and blobless clones failing after time delay, reported by Дилян Палаузов (Dilyan Palauzov).

Core problem: After performing a filtered clone (--filter=tree:0 or blobless), waiting 5 days, then running git pull, the first attempt fails with missing object errors suggesting repository corruption, while the second attempt succeeds. The issue appears consistently across repositories in Git 2.50.0.

Key technical details:
- Initial clone succeeds (git show works)
- After delay, first git pull fails with errors about missing objects in commit graph but not object database
- Second git pull succeeds, fetching 22 objects (137.56 KiB) with fast-forward
- Issue suggests promisor remote mishandles cases where commit graph exists but objects are missing
- Workaround is running git pull twice, but this is not ideal behavior

Current status: Bug report filed with clear reproduction steps and version information. No maintainer response or fix yet.

- Whether this affects other Git versions
