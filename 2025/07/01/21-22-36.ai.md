This is part 10/11 of the SHA-256 default hash algorithm transition series, focusing on developer visibility into the active hash algorithm. The patch adds a new build option output to `git version --build-options` that displays the default hash algorithm (SHA-256 when built with WITH_BREAKING_CHANGES, otherwise SHA-1).

The change is straightforward - it adds a single line to help.c that prints the name of the default hash algorithm (accessed via the existing hash_algos array and GIT_HASH_DEFAULT constant). This builds on the infrastructure established in earlier patches while addressing a new use case: making the default hash algorithm visible for debugging and bug reporting purposes.

The implementation is clean and minimal, fitting naturally with the existing build options output format. It complements the test infrastructure changes from patch 6/11 (GIT_TEST_BUILTIN_HASH) by providing a runtime way to check the active default hash. The change is well-motivated in the commit message, explaining how this will help with troubleshooting during the SHA-256 transition period.

This patch doesn't introduce any new technical complexity or unresolved questions - it's a focused addition that completes the visibility story for the hash algorithm transition work. The implementation is consistent with the series' approach of making the hash algorithm selection explicit and introspectable.
