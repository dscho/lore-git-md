This is the final patch in Patrick Steinhardt's v6 series refactoring Git's object database (ODB) subsystem to eliminate `the_repository` global state. The patch renames `read_object_with_reference()` to `odb_read_object_peeled()`, completing the systematic conversion of ODB-related functions to use explicit `odb_` prefixes and object database parameters.

The renamed function handles "peeling" objects - recursively resolving tags and commits until reaching an object of the requested type. The new name better describes this behavior compared to the more generic original name. The change affects several callers across `cat-file`, `fast-import`, `grep`, `pack-objects`, and tree-walking code, all updated to use the new function signature that takes an explicit `object_database` parameter rather than a `repository` struct.

As with previous conversions in this series, no compatibility wrapper is provided since the function has relatively few callers. The patch follows the established pattern seen in earlier patches (renames like `has_object()` to `odb_has_object()` in 15/17) and completes the ODB API modernization. Documentation is updated to reference the new function name while maintaining the same explanatory context.

This concludes the architectural refactoring that systematically converted all core object access functions to use explicit ODB parameters with consistent naming, removing the last remaining `the_repository` dependencies from the ODB subsystem while preserving all existing behavior.
