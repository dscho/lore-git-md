This is a bugfix patch that improves error reporting when Git fails to lock the index file. Currently, commands like `git stash` simply report "could not write index" when index locking fails, which doesn't help users understand the root cause. The patch modifies `repo_refresh_and_write_index()` to use `LOCK_REPORT_ON_ERROR` when not in gentle mode, which makes the underlying locking error (like being unable to create the lock file) visible to users.

The change is small but meaningful - just a one-line modification to the locking flags in `read-cache.c`, plus updates to several stash-related tests that now expect the more specific error message. The patch appears well-scoped and focused, with clear test coverage showing the improved error messages in action when index locking fails during stash operations. This should help users better diagnose and resolve index-related issues.
