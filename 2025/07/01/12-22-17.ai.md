This is part of the ongoing `the_repository` removal effort, specifically patch 5/17 in Patrick Steinhardt's series refactoring Git's object database (ODB) subsystem. The patch converts the `find_odb()` function to take an explicit `object_database` parameter instead of implicitly using `the_repository`, renaming it to `odb_find_source()` in the process.

The changes are mechanical but important for eliminating global state: the function now searches within a specific ODB's sources rather than assuming `the_repository->objects`. The patch updates 3 call sites in `builtin/commit-graph.c` and `midx-write.c` to pass `the_repository->objects` explicitly. The header comment is updated to clarify the function's behavior (it asserts the source must exist rather than returning NULL).

Key technical details for future reference:
- Function renamed from `find_odb()` to `odb_find_source()`
- Parameter changed from `struct repository *r` to `struct object_database *odb`
- Internally uses `odb->repo` and `odb->sources` instead of repository access
- Maintains same die-on-missing behavior but now documented in header
- Touches commit-graph and midx code paths that locate object directories

This continues the series' pattern of methodically converting ODB function signatures while maintaining behavior. The changes are straightforward and build on the parent pointer relationships established in patch 4/17. With Justin Tobler's prior review feedback incorporated and no outstanding issues, this appears ready for inclusion as part of the larger architectural shift.
