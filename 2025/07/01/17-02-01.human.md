Bugfix confirmation for Git for Windows credential manager override issue. Aditya Garg confirms that Johannes Schindelin's suggested solution works - setting an empty-string credential helper followed by the desired helper successfully prevents Git for Windows's default credential manager from overriding custom configurations. 

This email serves as validation of the previously proposed fix, though it doesn't introduce new technical information. The confirmation comes from the original reporter who was experiencing the issue, adding real-world verification that the workaround is effective. The solution involves modifying the global gitconfig to first clear any system-configured helpers with an empty string before specifying the preferred helper.

While this doesn't address the root cause (Git for Windows updates resetting system configurations), it provides a reliable workaround that users can implement immediately. The thread now has both the technical explanation from Johannes Schindelin and Brian m. carlson, plus practical confirmation from someone who successfully applied the fix. The issue appears resolved from a user perspective, though the underlying behavior in Git for Windows's update mechanism remains unchanged.
