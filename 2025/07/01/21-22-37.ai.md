This is the final patch (11/11) in the series implementing SHA-256 as Git's default hash algorithm when built with WITH_BREAKING_CHANGES, completing the transition work for Git 3.0.

The patch makes SHA-256 the default hash algorithm when Git is compiled with WITH_BREAKING_CHANGES defined, while maintaining SHA-1 as the default otherwise. This implements the planned breaking change documented for Git 3.0. The change is made in hash.h by conditionally defining GIT_HASH_DEFAULT based on the presence of WITH_BREAKING_CHANGES.

A corresponding update to t/test-lib.sh makes the test suite automatically detect the built-in hash algorithm by querying `git version --build-options` rather than hardcoding SHA-1. The author notes this provides a safety check - if the Git binary is broken and can't report its hash algorithm, the test suite will fail rather than silently proceed with incorrect assumptions.

This patch builds on the infrastructure established in previous patches, particularly the GIT_HASH_DEFAULT constant (introduced in earlier patches) and the `--build-options` output added in patch 10/11. It completes the technical implementation of the SHA-256 default transition while maintaining backward compatibility through the GIT_HASH_SHA1_LEGACY constant for cases that explicitly need SHA-1 behavior.

The implementation is straightforward with minimal changes - just two files modified with clear conditional logic. The test suite update ensures comprehensive coverage of the new default behavior. This appears to be the final piece of the technical implementation, though documentation updates (mentioned as outstanding in the thread summary) remain to be addressed separately.
