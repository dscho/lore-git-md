This is the final patch in a series implementing SHA-256 as Git's default hash algorithm when built with WITH_BREAKING_CHANGES, targeting Git 3.0. The patch makes SHA-256 the default hash algorithm when the WITH_BREAKING_CHANGES build flag is set, fulfilling the project's stated goal for Git 3.0's breaking changes.

The change is implemented through a simple conditional in hash.h that sets GIT_HASH_DEFAULT to either SHA-256 (with breaking changes) or SHA-1 (without). The test suite is updated to automatically detect the build's default algorithm via `git version --build-options` rather than hardcoding SHA-1, ensuring tests use the correct hash algorithm for the build configuration.

The author notes this is an important security upgrade since most users stick with defaults. The implementation appears straightforward and builds on extensive preparatory work in earlier patches of the series. The test suite change includes a failsafe - if the hash detection fails, the tests will fail obviously rather than silently continuing with incorrect assumptions.

This completes the technical implementation of SHA-256 as default, though some documentation and testing logistics remain open from earlier discussion. The patch follows through on the series' goal while maintaining backward compatibility pathways through the GIT_HASH_SHA1_LEGACY constant introduced earlier.
