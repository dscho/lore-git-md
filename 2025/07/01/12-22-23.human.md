This is part 11/17 of Patrick Steinhardt's series to eliminate `the_repository` global state from Git's object database (ODB) subsystem, specifically focusing on submodule handling. The patch moves submodule ODB tracking from a global string list into the object database structure itself, removing the last remaining `the_repository` dependency in this area.

The change affects how Git handles submodule object lookups when using commands like `git grep --recursive`. Previously, submodule paths were stored in a global list before being registered as alternates. Now they're tracked per-repository in the ODB's `submodule_source_paths` field. The key functions are renamed from `add_submodule_odb_by_path()` to `odb_add_submodule_source_by_path()` and the registration logic is updated accordingly.

The patch maintains the same behavior while making the implementation more repository-aware, which is crucial for the series' goal of enabling pluggable ODB backends. It touches several files but the changes are straightforward - mostly moving code from submodule.c to odb.c and updating callers. The commit message clearly explains the change and its motivation, and the patch appears well-tested with trace2 instrumentation preserved.

This continues the series' pattern of methodically removing global state while keeping behavior consistent. Reviewers have been actively engaged on previous patches, and this one appears to follow the same careful approach.
