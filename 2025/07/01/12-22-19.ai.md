This is part of Patrick Steinhardt's ongoing series to eliminate `the_repository` global state from Git's object database (ODB) subsystem, specifically targeting the `odb_mkstemp()` function in patch 7/17. The change follows the established pattern from previous patches in the series, converting the function to take an explicit `object_database *odb` parameter and updating all callers to pass `the_repository->objects` as a transitional step.

The patch modifies `odb_mkstemp()` to use `odb->repo` internally instead of `the_repository`, affecting temporary file creation paths in several key areas: packfile writing (fast-import, index-pack), bundle URI handling, bitmap generation, and pack utilities. The function signature change propagates through 7 files with straightforward mechanical updates to call sites.

Notable technical details include:
- Maintains identical behavior for temporary file creation while removing global state dependency
- Updates function documentation to clarify it operates on the primary alternate's directory
- Preserves existing error handling and fallback paths
- Touches core pack-writing infrastructure (pack-bitmap-write.c, pack-write.c) and import/export paths (fast-import.c, bundle-uri.c)

This continues the series' systematic conversion of ODB functions to explicit parameters, building on prior work to:
- Establish `odb_` prefix convention (patches 5-6/17)
- Add parent pointers between ODB components (patch 4/17)
- Prepare for upcoming high-impact conversions of `oid_object_info()` and `repo_read_object_file()` (patches 13-14/17)

The changes are mechanical but architecturally significant, maintaining backward compatibility while progressing toward pluggable ODB backends. All review feedback from previous iterations appears addressed, with no outstanding implementation issues noted.
