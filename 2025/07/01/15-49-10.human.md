This is a Windows-specific issue report about credential manager behavior. Aditya Garg describes a frustrating interaction where Git for Windows' Git Credential Manager (GCM) keeps popping up despite having configured a different credential helper in `.gitconfig`. The workaround of closing the popup works, but the problem recurs after each Git for Windows update, suggesting the GCM configuration is being reinstated during updates.

The report is brief and doesn't include diagnostic details like exact Git versions or configuration files, but it clearly describes a real usability pain point for Windows users who prefer alternative credential storage. The behavior suggests either a configuration precedence issue (where system config overrides user config) or an update process that's too aggressive about restoring default settings.

This appears to be a known Windows-specific behavior that may require either documentation clarification or a change in how Git for Windows handles credential helper configuration during updates. The report is directed to Johannes Schindelin, a key Git for Windows maintainer, suggesting the submitter recognizes this as a platform-specific issue.
