Bugfix addressing a memory leak in pack-bitmap.c when loading corrupt bitmaps. This is the first patch in a three-part series that has gone through multiple review iterations.

The patch fixes a case where partially-loaded bitmap entries would leak memory if an error occurred during loading. Currently, `load_bitmap()` has its own cleanup path that nulls out data structures, preventing the caller's `free_bitmap_index()` from properly freeing already-loaded entries. The solution is simple and elegant: remove the redundant cleanup code in `load_bitmap()` and let the caller handle all cleanup uniformly via `free_bitmap_index()`.

Notably, this fix actually removes code (17 lines deleted) while making the error handling more robust - a rare win-win scenario that Junio C Hamano noted as particularly positive. The change has been reviewed by Jeff King and incorporates sign-off from the original reporter Lidong Yan, indicating broad consensus on the approach.

This patch sets the stage for the rest of the series which adds test coverage and improves comments around bitmap loading behavior. The fix is focused and well-contained, touching only pack-bitmap.c with straightforward changes to error handling paths.
