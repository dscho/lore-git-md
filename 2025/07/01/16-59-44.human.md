This is a discussion contribution about Git's code formatting approach, specifically responding to Toon Claes' argument for full automation adoption modeled after `gofmt`. Johannes Schindelin (Dscho) voices strong agreement with Toon's position that code formatting should be fully automated rather than subject to human judgment, citing successful examples from other ecosystems like Go (`gofmt`), Rust (`rustfmt`), and JavaScript (ESLint).

The email reinforces the argument that automated formatting tools eliminate bikeshedding in code reviews by establishing an unambiguous standard, even if the output isn't perfectly preferred by all developers. Schindelin specifically highlights how projects like cURL use automated style checking (`make checksrc`) to shift focus from formatting nits to code correctness.

This intervention strengthens the "full automation" side of the ongoing debate, counterbalancing the emerging consensus around removing problematic line-wrapping rules from `.clang-format`. While not proposing new technical solutions, it provides philosophical weight to Toon's position by showing broader industry precedent for uncompromising automation, coming from a long-time Git contributor with experience across multiple language ecosystems.
