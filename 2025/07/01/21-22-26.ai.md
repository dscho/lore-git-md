This is the cover letter for v2 of a feature series implementing SHA-256 as Git's default hash algorithm when built with WITH_BREAKING_CHANGES, targeting Git 3.0. The series builds on the hash-algorithm-agnostic internals work and represents a major step in the SHA-256 transition.

The key changes in v2 address feedback from the previous round: renaming of constants (GIT_HASH_ORIGINAL becomes GIT_HASH_SHA1_LEGACY), improved commit message explanations, and preprocessor formatting fixes. The series now includes a build option for the default hash and corresponding test adjustments.

Technical highlights include:
- New hash.h constants (GIT_HASH_DEFAULT for SHA-256, GIT_HASH_SHA1_LEGACY for SHA-1 fallback)
- 25 files modified to handle repository initialization and commands outside repos
- Test infrastructure updates with GIT_TEST_BUILTIN_HASH and --hash=builtin test_oid
- Careful handling of version-less repositories defaulting to SHA-1 via GIT_HASH_SHA1_LEGACY
- The series maintains backward compatibility while preparing for SHA-256 as the future default
- Notable debate remains about whether commands outside repositories should use GIT_HASH_DEFAULT (author's preference) or GIT_HASH_SHA1_LEGACY (Patrick Steinhardt's suggestion) to maintain script compatibility

The patch series is well-structured with comprehensive test coverage, though some documentation updates remain pending. The technical approach has Junio C Hamano's approval, with only minor style issues noted. The remaining open question about external command behavior represents a fundamental design choice between forward compatibility and script stability.
