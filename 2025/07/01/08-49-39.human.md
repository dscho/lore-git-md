This is a debugging follow-up in the ongoing credential helper behavior discussion. Michal Suchánek reports on attempts to verify the HTTP status codes returned by servers during failed operations, a key point in the debate about when Git should be invalidating credentials.

Using mitmweb to inspect SSL-encrypted traffic, Michal observes that 401 responses appear frequently even in successful operations, likely due to Git's initial unauthenticated probe. More notably, they find servers never return 403 status codes - failures appear to surface at the Git protocol level instead. This contradicts the expected behavior where 403 would indicate valid-but-insufficient credentials while preserving the authentication token.

The findings suggest either widespread server misimplementation of HTTP status codes or that some failures bypass HTTP layer reporting entirely. This practical observation adds weight to earlier arguments that Git's credential invalidation may be overly aggressive when based solely on HTTP semantics. The email doesn't propose solutions but provides empirical data supporting the need for either server-side fixes or Git behavior adjustments.
