This is the third and final patch in a bugfix series addressing memory leaks in pack-bitmap.c's bitmap loading paths. The patch adds comprehensive test coverage for corrupt bitmap handling, building on the previous two patches that addressed the memory leaks themselves.

The key technical addition is a new `test_bitmap_commits_with_offset()` function that outputs structured data about bitmap entry positions in the bitmap file. This enables targeted corruption testing by:
- Adding a `map_pos` field to `struct stored_bitmap` to track each bitmap's file position
- Outputting commit OID along with positions of key fields (commit index, xor offset, flags, EWAH bitmap)
- Providing a test helper (`test-tool bitmap list-commits-with-offset`) to expose this data

The test case in t5310-pack-bitmaps.sh demonstrates the functionality by:
- Creating a bitmap
- Using the helper to find a xor_offset field position
- Corrupting that field by writing a non-zero value
- Verifying the bitmap still produces correct object lists despite the corruption

The implementation builds on the series' earlier work by:
- Leveraging the clarified comments from patch 2/3 about bitmap lookup behavior
- Using the centralized `free_bitmap_index()` cleanup approach established in patch 1/3
- Following the review-suggested naming convention for the test helper

This completes the series' goal of fixing memory leaks while improving test coverage for corrupt bitmap handling. The new test infrastructure provides reusable instrumentation for future bitmap corruption testing scenarios.
