This is part 3 of an 11-patch series implementing SHA-256 as Git's default hash algorithm when built with WITH_BREAKING_CHANGES, focusing on commands that operate outside repositories. The patch changes the hash algorithm selection for several builtin commands (`apply`, `diff`, `hash-object`, etc.) when they run outside a repository context, switching from hardcoded SHA-1 to using GIT_HASH_DEFAULT.

The key technical change is replacing GIT_HASH_SHA1 with GIT_HASH_DEFAULT in 8 commands that can operate outside repositories. This maintains the current SHA-1 behavior (since that's still the default) but prepares for a future where the default could be SHA-256. The commit message notes this is a forward-looking change with no immediate functional impact.

This patch directly addresses one of the open questions from the thread - whether commands outside repositories should use GIT_HASH_DEFAULT (author's position) or GIT_HASH_SHA1_LEGACY (Patrick Steinhardt's suggestion). The author maintains their stance that GIT_HASH_DEFAULT is the right choice to ease the SHA-256 transition, though the debate remains unresolved in the thread.

The changes are mechanical and consistent across all affected commands, with each getting the same one-line change to use the default hash algorithm. The patch includes comments explaining why each command needs hash algorithm initialization, though these explanations remain unchanged from before. Test coverage for this behavior would presumably be handled by the series' overall test infrastructure updates mentioned in the thread context.
