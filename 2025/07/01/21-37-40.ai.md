This is a maintainer follow-up regarding the recently merged `--skip-until` ref iteration series, focusing on clang-format's behavior rather than the feature itself. Junio C Hamano shares observations from running clang-format on the merged code, noting several formatting changes he considers undesirable:

1. The tool aggressively reformatted the `opts[]` array in `builtin/for-each-ref.c`, introducing unnecessary line breaks and alignment changes despite only one new `--skip-until` entry being added. Hamano questions whether clang-format could be made more surgical when modifying existing arrays.

2. The formatting of commented-out code in `refs.h` was altered in ways that don't improve readability.

3. While some changes like wrapping `refs_ref_iterator_begin()` were improvements, others like the reformatting of `ref_iterator_seek()` and `do_for_each_ref_iterator()` declarations made them less readable in Hamano's view.

4. The diff shows clang-format inserting mid-line comments in awkward positions (e.g., in `refs/ref-cache.c`) and making purely stylistic spacing changes that don't aid comprehension.

The email doesn't propose specific changes but raises the broader question of whether clang-format's behavior could be tuned to be less disruptive when working with established code patterns, particularly for array initializations and function declarations. This is framed as a general tooling consideration rather than a critique of the original patchset's code quality.
