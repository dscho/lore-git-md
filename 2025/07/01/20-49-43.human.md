This is a brief follow-up in the clang-format rules refinement series, focusing on a minor formatting observation.

Junio Hamano responds to Toon Claes's note about clang-format automatically adding spaces around bit-shift operators (changing `(1<<7)` to `(1 << 7)`). While Claes couldn't find a configuration to disable this behavior, Hamano considers it a positive change, noting that Git's style doesn't object to spaces around binary operators like `<<`. He also mentions a separate (non-formatting) concern about the lack of a `U` suffix to ensure unsigned bitmasks, but clarifies this is unrelated to the clang-format changes.

This exchange confirms the operator spacing behavior is an intentional (if not configurable) part of clang-format's output, and that the Git maintainers find it acceptable. The discussion appears to be wrapping up, with no further action needed on this particular formatting quirk. The thread's main technical work - making RemoveBracesLLVM permanent and adding meson support - remains unchanged by this observation.
