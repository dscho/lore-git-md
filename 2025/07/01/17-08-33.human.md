This is a follow-up discussion on the `--skip-until` pagination feature for `git for-each-ref`. Junio C Hamano raises some important clarification points about the user experience and documentation.

The core concern is about ensuring users understand that `--skip-until` operates on references in their native storage order (before any `--sort` is applied), not on the final sorted output. This distinction matters because some might expect to be able to skip references based on sorted criteria (e.g., "skip the most recently modified refs"), but the implementation specifically seeks in the underlying storage order first, then applies sorting.

Hamano notes this is acceptable behavior but emphasizes the need for clear documentation to prevent misunderstandings. He also confirms the technical feasibility given how reference backends already handle internal sorting. The exchange suggests the feature is conceptually sound but needs precise wording to set proper user expectations.

The thread also reveals the author considered broader ref iterator cleanups but deferred them to keep this series focused - a decision Hamano appears to support. This looks like final pre-merge clarification rather than substantive technical concerns.
