This is a debugging follow-up in the ongoing credential helper behavior discussion. Michal Suchánek reports on attempts to verify the HTTP status codes returned by servers during failed operations, a key point in the credential persistence debate. Using mitmweb to intercept SSL traffic, he observes that 401 responses appear even in successful cases (likely from Git's initial unauthenticated probe), while the problematic 403 responses never materialize - failures seem to occur at the Git protocol level instead. This suggests the server may not be properly implementing the HTTP status code semantics that Brian M. Carlson cited from RFC 9110 as governing credential invalidation behavior.

The email shifts the technical focus from protocol interpretation to practical observation challenges, highlighting the difficulty of verifying server behavior in encrypted communications. Michal's findings imply the credential invalidation issue might stem from either server misimplementation (failing to send proper 403/404 for operation failures) or Git protocol-level interactions obscuring the HTTP layer. This moves the discussion toward needing better diagnostic tools or server-side changes rather than client behavior modifications. The core disagreement about credential persistence remains unresolved, but now with empirical evidence suggesting the HTTP status code theory may not fully explain the observed behavior.
