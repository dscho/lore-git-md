Bugfix targeting index locking error reporting in `git stash` operations. This patch improves error reporting when index operations fail due to lock contention. Currently, commands like `git stash` simply report "could not write index" when failing to acquire the lock, which obscures the root cause. The change modifies `repo_refresh_and_write_index()` to pass `LOCK_REPORT_ON_ERROR` to `repo_hold_locked_index()` when not in gentle mode, causing the underlying lock failure message to be shown.

The patch affects the core index writing machinery in read-cache.c and updates several `git stash` tests in t/t3903-stash.sh to expect the more detailed lock error messages instead of the old generic ones. The test modifications show the new behavior will specifically report inability to create the index.lock file when one already exists.

This appears to be a straightforward improvement to error reporting quality, with minimal code changes (just one line modified in read-cache.c) and comprehensive test updates. The change is well-contained and doesn't introduce new behavior - it just surfaces existing lock failure details that were previously hidden behind a generic message. The patch follows Git's standard patterns for lock error reporting and maintains the gentle/non-gentle mode distinction in index operations.
