This is a follow-up to a memory leak bugfix in `send-pack`'s handling of the `extra_have` oid array. The original patch addressed a 2160-byte leak during push operations involving alternate object stores, but Junio Hamano noted it missed cleanup during early error exits. Jacob Keller now acknowledges Junio's suggested refinement, which consolidates resource cleanup under a single `cleanup` label to handle both success and error paths consistently.

The change doesn't introduce new functionality but ensures proper resource management when `match_push_refs()` fails early. This is a straightforward improvement to the original fix, maintaining the same pattern used for other resources in the function. The thread has been collaborative, with both contributors agreeing on the technical approach. While test coverage for alternate-store push scenarios remains an identified gap, this particular cleanup improvement appears uncontroversial and ready for inclusion.
