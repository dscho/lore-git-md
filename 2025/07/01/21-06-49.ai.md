This is a discussion about the path handling behavior of the proposed `git last-modified` command, specifically regarding its non-recursive default behavior and interaction with pathspecs.

Junio C Hamano weighs in on Kristoffer Haugsbakk's concerns about the command's path handling patterns. The key points are:

1. Junio finds the behavior with `-r` flag (recursive mode) to be completely expected, showing individual files when requested. He questions why Kristoffer considers this unusual.

2. For non-recursive mode, Junio compares the behavior to `git ls-tree` without `-r`, noting that showing directories rather than their contents is standard Git plumbing behavior. He provides an example of `git ls-tree` output to illustrate this pattern.

3. Junio expresses no objection to the non-recursive default, particularly since this is intended as a plumbing command primarily for repository browsers. He sees this as consistent with Git's existing conventions.

4. The discussion confirms that recursive mode (`-r`) works as expected, showing all requested files including those in subdirectories, and properly recursing through directories when specified.

This email reinforces the design choice of non-recursive behavior as the default, positioning it as consistent with Git's existing plumbing commands.
