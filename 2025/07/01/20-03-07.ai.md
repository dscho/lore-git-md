This is a platform compatibility discussion about fixing FreeBSD builds when libsysinfo is present. Eric Sunshine responds to Renato Botelho's request for guidance on how to properly handle the libsysinfo dependency in Git's build system.

Sunshine outlines two potential solution paths with different levels of complexity. The minimal approach would modify configure.ac to use AC_LINK_IFELSE instead of AC_COMPILE_IFELSE for the sysinfo check, which would prevent HAVE_SYSINFO from being defined if linking fails due to missing -lsysinfo. This would maintain current behavior while fixing the build breakage.

For a more comprehensive solution that enables sysinfo functionality on FreeBSD, Sunshine proposes a three-part approach: (1) adding NEEDS_LIBSYSINFO to Makefile following existing patterns, (2) optionally updating config.make.uname for direct builds, and (3) enhancing configure.ac to properly detect when -lsysinfo is needed. He notes this would require careful handling to maintain compatibility with older FreeBSD versions that might lack sysinfo support.

The response provides clear technical direction while leaving the choice between minimal and comprehensive solutions to Botelho, acknowledging tradeoffs between implementation effort and functionality. The suggestions follow Git's existing build system patterns (NEEDS_* variables, config.make.uname conventions) and demonstrate awareness of backward compatibility concerns.
