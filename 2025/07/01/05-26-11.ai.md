This is a discussion about patch 1/5 in the `git apply --intent-to-add` bugfix series, focusing on whether to error out when `--intent-to-add` is used outside a repository. 

Raymond Pasco responds to Junio Hamano's feedback about the patch's rationale. Raymond acknowledges Junio's point that `-N` is a weaker indicator of repository awareness compared to `--index` or `--cached`, since users might primarily be focused on file manipulation rather than repository operations.

The discussion highlights a philosophical difference in error handling approaches - whether to fail loudly when encountering nonsensical operations or silently ignore them when they can't have effect. This remains an open question in the thread, with Junio favoring the silent ignore approach that matches the existing "better GNU patch" behavior, while Raymond originally proposed explicit error checking. The exchange shows Raymond reconsidering his position based on the relative strength of user intent signaled by `-N` versus other repository-affecting flags.
