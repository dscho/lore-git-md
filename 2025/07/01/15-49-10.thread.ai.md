Git for Windows credential manager interference issue. Aditya Garg reported that custom-configured credential helpers in `.gitconfig` are overridden by Git for Windows's default credential manager popup, which persists across updates. Johannes Schindelin (Dscho) provided the technical solution: setting an empty-string helper in global config (`git config --global credential.helper ""`) followed by the desired helper, leveraging Git's documented behavior where empty-string clears the helper list. Aditya later encountered a syntax issue when implementing this, trying `git config set --global --add credential.helper ''` (incorrect `--add` flag), but confirmed the approach works when using correct syntax or manual config editing.

Technical details:
- System-level (`--system`) credential configuration takes precedence over user config
- Correct syntax is `git config --global credential.helper ""` (no `--add`)
- Empty-string helper followed by desired helper creates persistent override
- Issue recurs after Git for Windows updates due to system config reset during upgrades

Open questions:
- Why system configuration resets during upgrades remains unanswered (requires Git for Windows update mechanism changes)
- Original syntax suggestion may have contained a typo (`--add` vs proper flag)
