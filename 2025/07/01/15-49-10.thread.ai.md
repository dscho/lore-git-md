Git for Windows credential manager interference issue. Aditya Garg reports that custom-configured credential helpers in `.gitconfig` are being overridden by Git for Windows's default credential manager popup, which reappears after each Git for Windows update despite user configuration. The core problem is unwanted UI interference from the system-level configuration that persists across updates.

Technical details:
- System-level (`--system`) credential configuration appears to take precedence over user configuration
- The credential flow ultimately works after dismissing the popup, indicating this is a UI/configuration issue rather than a functional break
- Issue recurs after Git for Windows updates, suggesting the system configuration resets during upgrades

Open questions:
- Is this a configuration precedence issue or a Windows-specific credential helper initialization behavior?
- What is the proper way to persistently override the system credential helper on Windows?
- Does this affect all non-default credential helpers or only specific ones?

The thread begins with a Windows-specific configuration issue that may require Git for Windows maintainer input (likely Johannes Scharfe/Dscho) to address the update-resilient configuration problem. The reporter is seeking a more permanent solution than manual reconfiguration after each update.
