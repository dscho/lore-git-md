This is the final patch in a 4-part series adding pagination support to `git for-each-ref` through a new `--skip-until` option. The series has been building up the necessary infrastructure in the ref iteration internals, with this patch exposing the functionality to users.

The patch adds the `--skip-until=<pattern>` option to `git-for-each-ref`, which allows starting iteration from a specific reference rather than always beginning from the start. This enables efficient pagination workflows by combining with `--count`. The implementation uses the `ref_iterator_seek()` functionality added in earlier patches, with careful handling of edge cases like empty values, partial matches, and directory prefixes.

Key technical details:
- The option is mutually exclusive with general pattern matching (`--skip-until` cannot be used with other ref patterns)
- The ref-filter machinery is updated to use the new seeking capability when `filter->seek` is set
- Special cases are handled for different ref types (branches, remotes, tags)
- Extensive tests cover various seeking scenarios including exact matches, partial matches, directory prefixes, and edge cases
- Documentation is updated to explain the new option

The implementation appears thorough, with good test coverage (180 lines of tests) for the new functionality. This completes the series' goal of enabling efficient pagination for repositories with millions of references. The changes build logically on the preparatory work in the earlier patches, maintaining consistency with the existing ref iteration API while adding the new capability.
