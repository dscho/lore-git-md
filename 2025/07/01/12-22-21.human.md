This is part of Patrick Steinhardt's ongoing series to eliminate `the_repository` global state in Git's object database (ODB) subsystem. Patch 9/17 converts iterator-style functions that operate on alternate object databases to take explicit `object_database` parameters instead of relying on the global.

The patch renames two key functions: `foreach_alt_odb()` becomes `odb_for_each_alternate()` and `for_each_alternate_ref()` becomes `odb_for_each_alternate_ref()`. Both now take an `object_database *odb` parameter. The changes propagate through 8 files including builtins like `count-objects` and `receive-pack`, plus core components like the revision walker and fetch-pack.

The conversion is mechanical but thorough - each call site is updated to pass `the_repository->objects` explicitly. The implementation remains functionally identical, just with the dependency on global state removed. This continues the series' pattern of methodically converting ODB functions to explicit parameters while maintaining backward compatibility.

As with previous patches in the series, this is a well-executed step toward the larger goal of making Git's object storage layer properly repository-aware and paving the way for pluggable backends. The changes are straightforward and the patch follows the established pattern of the series.
