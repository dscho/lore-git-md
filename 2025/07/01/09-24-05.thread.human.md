This thread addresses a bug where treeless and blobless clones fail after a 5-day delay when running `git pull`, with the first attempt failing due to missing objects while the second succeeds. Jeff King (Peff) diagnosed this as a race condition between commit graph lookups and object repacking during fetches in filtered repositories. He proposed a focused fix modifying `fetch-pack.c` to recheck packed objects after commit graph lookups, referencing commit 5d4cc78f72 which introduced the current behavior.

The discussion has now expanded to consider broader design questions about submodule behavior in tree-less clones. However, this approach currently fails because the diff machinery isn't prepared to handle missing trees gracefully. This reveals a deeper technical challenge: the diff system would need new "permissive mode" handling to make this solution work.

While the initial race condition fix is ready for review (with Jonathan Tan suggested as a relevant reviewer given his promisor remotes expertise), these new considerations about submodule behavior in filtered clones may require additional design work.
