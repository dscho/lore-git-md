This is part of Patrick Steinhardt's ongoing series to eliminate `the_repository` global state in Git's object database (ODB) subsystem, specifically focusing on the temporary primary ODB handling functions.

The patch converts `set_temporary_primary_odb()` and `restore_primary_odb()` to take explicit `object_database *odb` parameters, renaming them to `odb_set_temporary_primary_source()` and `odb_restore_primary_source()` respectively. The changes follow the series' established pattern of making ODB operations repository-agnostic by passing the ODB context explicitly rather than relying on `the_repository`.

Key technical changes include:
- Updated function signatures in odb.h with new names and explicit `odb` parameters
- Modified implementations in odb.c to use the passed ODB instead of `the_repository->objects`
- Updated all 4 call sites in tmp-objdir.c to use the new API
- Added BUG() checks to verify path consistency during restoration
- Maintained the same behavior while removing global state dependency

The changes are straightforward mechanical conversions that build on previous patches in the series (particularly patch 4/17 which established parent pointers between ODB components). The patch continues the systematic elimination of `the_repository` usage while maintaining the existing functionality for temporary object directory handling, which is critical for operations like `git fetch` and `git push` that use temporary object stores.

This is a well-contained change that follows the established pattern of the series, with clear documentation updates and comprehensive call site updates. The patch appears ready for inclusion as part of the larger ODB refactoring effort.
