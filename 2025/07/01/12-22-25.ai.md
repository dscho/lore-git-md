This is patch 13/17 in Patrick Steinhardt's v6 series refactoring Git's object database (ODB) subsystem to eliminate `the_repository` global state. The patch renames `oid_object_info()` to `odb_read_object_info()` and its `_extended()` variant to match modern naming conventions for ODB-related functions. 

The change affects 48 call sites across the codebase, updating them to use the new function names. The patch introduces compatibility wrappers to maintain backward compatibility with in-flight topics. The rename is part of establishing consistent `odb_`-prefixed API naming (patches 5/17-10/17) and follows the pattern of making ODB operations explicitly take an object_database parameter rather than implicitly using `the_repository`.

Key technical details:
- The core implementation moves from `oid_object_info_extended()` to `odb_read_object_info_extended()`
- The simpler `oid_object_info()` wrapper becomes `odb_read_object_info()`
- Both functions now take an `object_database` parameter instead of `repository`
- The changes touch object info lookups across commands like `cat-file`, `fsck`, `grep`, and the object database internals
- Compatibility wrappers ensure existing code continues to compile

This is a straightforward mechanical rename that follows the established pattern in earlier patches of the series. It maintains all existing behavior while advancing the architectural goal of removing implicit `the_repository` usage. The patch has no implementation changes beyond the renaming, and the thorough review process on earlier patches suggests this change will be uncontroversial.
