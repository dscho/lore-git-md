This is part 8/17 of Patrick Steinhardt's series to eliminate `the_repository` global state from Git's object database (ODB) subsystem, continuing the architectural refactoring for pluggable ODB backends. 

The patch converts alternates-handling functions to take an explicit `object_database *odb` parameter instead of implicitly using `the_repository`. Key functions renamed and updated include:
- `prepare_alt_odb()` -> `odb_prepare_alternates()`
- `has_alt_odb()` -> `odb_has_alternates()`
- `add_to_alternates_file()` -> `odb_add_to_alternates_file()`
- `add_to_alternates_memory()` -> `odb_add_to_alternates_memory()`

The changes are mechanical but thorough, updating 14 call sites across clone, fsck, repack, commit-graph, and other areas. The commit notes this is transitional - while the functions now take an ODB parameter, they still internally use the path from `odb->repo`, which will be addressed in later patches. 

This continues the series' pattern of methodically converting ODB functions to explicit parameters while maintaining backward compatibility. The changes are well-contained and follow the established `odb_` prefix convention from prior patches. Review feedback from Justin Tobler on path handling appears incorporated, and the patch carries forward Derrick Stolee's Reviewed-by from earlier in the series.
