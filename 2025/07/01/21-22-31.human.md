This is part 5/11 in a series implementing SHA-256 as Git's default hash algorithm when built with WITH_BREAKING_CHANGES. The patch focuses on repository initialization behavior.

The change updates how Git initializes the repository format structure, switching from hardcoded SHA-1 to using GIT_HASH_DEFAULT (which will be SHA-256 when configured) for new repositories. However, it carefully maintains backward compatibility by explicitly setting GIT_HASH_SHA1_LEGACY when reading older repositories (v0 format or those missing core.repositoryformatversion). The patch handles several edge cases including repositories without config files and pre-0.99.3 repositories.

The implementation follows the series' pattern of distinguishing between explicit SHA-1 usage (GIT_HASH_SHA1), legacy SHA-1 fallback (GIT_HASH_SHA1_LEGACY), and the default algorithm (GIT_HASH_DEFAULT). The changes are mechanical but important for ensuring proper hash algorithm selection during repository operations.
