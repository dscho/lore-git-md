This is the third patch in a 4-part series introducing reference iteration improvements, specifically adding `--skip-until` pagination support to `git for-each-ref`. The patch refines the `ref_iterator_seek()` function to better separate seeking behavior from prefix filtering.

The key change introduces a `set_prefix` parameter to `ref_iterator_seek()`, allowing callers to choose whether seeking should also set a new iteration prefix (the existing behavior) or just position the iterator at a specific reference without changing the prefix. This makes the API more flexible and its behavior more explicit. The patch updates all ref backends (files, packed, reftable) to handle both modes, with the files backend requiring the most significant changes due to its ref-cache mechanism.

The implementation splits the files backend's seeking logic into `cache_ref_iterator_set_prefix()` (for prefix changes) and enhances `cache_ref_iterator_seek()` to handle pure seeking by walking the ref hierarchy to position the iterator at the requested reference. The packed and reftable backends get simpler adjustments since they already work with sorted reference lists.

This change maintains backward compatibility while enabling more precise control over iteration, which will be used by the upcoming `--skip-until` feature. The series appears well-structured, with each patch building logically on the last, though the thread has not yet received review feedback.
