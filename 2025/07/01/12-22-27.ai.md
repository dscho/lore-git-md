This is part of Patrick Steinhardt's ongoing `the_repository` removal series (v6 15/17), continuing the systematic conversion of object database (ODB) APIs to use explicit ODB contexts rather than relying on the global `the_repository`. 

The patch renames `has_object()` to `odb_has_object()` to match the established `odb_` prefix pattern seen in previous patches (13/17 renamed `oid_object_info()` to `odb_read_object_info()`, 14/17 renamed `repo_read_object_file()` to `odb_read_object()`). The change affects 30 files across the codebase, updating 47 call sites to use the new name while maintaining identical behavior. A compatibility wrapper preserves compilation for in-flight topics.

Key technical details:
- The function signature takes an explicit `struct object_database *odb` parameter instead of implicitly using `the_repository->objects`
- Flags behavior remains unchanged (`HAS_OBJECT_RECHECK_PACKED`, `HAS_OBJECT_FETCH_PROMISOR`)
- The wrapper ensures backward compatibility by routing `has_object(repo,...)` calls to `odb_has_object(repo->objects,...)`
- All conversions are mechanical renames with no logic changes

This follows the series' established pattern of methodically converting ODB functions to explicit parameters while maintaining the architectural goal of removing `the_repository` global state. The patch appears well-contained and consistent with the high-quality transformations seen throughout the series.
