This is a discussion about the path handling behavior of the new `git last-modified` command, specifically around its default non-recursive behavior. Junio C Hamano weighs in on Kristoffer Haugsbakk's concerns about the command's output format when given both files and directory paths.

The key points:
- Junio finds the current behavior reasonable and consistent with other Git commands like `ls-tree` that show directories rather than contents by default
- He notes the command is primarily intended as plumbing for repository browsers, where non-recursive output makes sense
- The discussion confirms that `-r` works as expected for recursive traversal when needed
- Junio seems satisfied with the current design, seeing the behavior as expected for a plumbing command

This continues the ongoing discussion about the command's user interface, with the maintainer signaling acceptance of the current path handling approach. The exchange suggests the non-recursive default is likely to stay unless stronger objections emerge.
