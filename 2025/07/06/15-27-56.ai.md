Follow-up discussion on git-log documentation conversion regarding syntax parsing challenges.

Jean-Noël Avila responds to Junio Hamano's approval of the git-log documentation conversion series, expressing lingering concerns about the approach taken in patch 5/9 for handling special characters in the synopsis format. The core issue involves distinguishing between syntax markers (like parentheses and three-dot notation) that are part of the documentation format versus those that appear as literal content in Git's log formatting syntax.

Avila notes this is a recurring problem that was previously addressed for git-scm.com by implementing a parser combinator extension in Asciidoctor, but laments that asciidoc.py lacks similar extensibility. The current solution requires manually escaping special characters throughout the documentation, which Avila considers suboptimal but currently unavoidable given the tooling constraints.

This follow-up doesn't propose any immediate changes to the approved series, but highlights an architectural limitation in the documentation toolchain that may need addressing for future conversions. The discussion remains technical rather than contentious, with Avila open to better solutions if they can be implemented within asciidoc.py's constraints.
