Bugfix discussion for `git stash` message handling discrepancy. Darren Rambaud provides additional technical details showing that while the custom message from `git stash create` doesn't appear in `git stash list`, it is preserved in the commit object's message and visible via `git log` when checking out the stash commit directly. This confirms Jeff King's earlier analysis that the issue is specifically about reflog message handling during the `store` operation, not message loss in general.

The email demonstrates the current behavior through a concrete example, showing the custom "changes to readme" message appears in the commit log but not the stash reflog. This adds empirical evidence to the ongoing discussion about whether to document the current behavior or modify `git stash store` to preserve the commit message by default. The technical details help clarify the exact scope of the issue for readers following the thread.
