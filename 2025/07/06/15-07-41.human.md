Documentation follow-up discussion about space notation in man pages. This is a brief exchange about potential use of the `␣` symbol to explicitly mark spaces in Git documentation, particularly in verbatim blocks where spaces might be hard to see.

Kristoffer Haugsbakk had previously suggested using `␣` (the Unicode symbol for space) in documentation, noting it could be useful for sequences like `:␣` in `git-interpret-trailers(1)`, though acknowledging it might not work well for all cases like arrow notation (`->`). 

Jean-Noël Avila responds that while this could help with visibility of spaces in some contexts (especially where backtick-wrapped commands don't preserve spacing clearly in manpage output), using `␣` universally would be excessive. He suggests it should be reserved for cases where space visibility is particularly problematic.

This is a minor but thoughtful discussion about documentation formatting details that follows up on the recently completed conversion of `git-log` documentation to the new AsciiDoc format. The exchange doesn't propose any immediate changes but may influence future documentation work where space visibility is an issue.
