This is a discussion about the technical implementation of change ID tracking in Git's email workflow, specifically addressing concerns about email header reliability. Drew DeVault responds to Aditya Garg's objections about header-based change IDs being stripped by email providers.

Drew's email makes several technical points: First, he disputes the claim that ProtonMail and MS Graph strip custom headers, stating his investigation found they do preserve them. He notes that while Thunderbird doesn't preserve headers when composing emails, the X-Change-ID would still survive if the patch is attached. He argues that header loss isn't catastrophic as it just reverts to the current state where change IDs aren't tracked in emails.

The email then addresses the alternative proposal to use in-body trailers (like Signed-off-by) rather than headers. Drew argues trailers and headers serve different purposes, and that using in-body headers could cause older Git versions to incorrectly ingest the X-Change-ID into commit messages. He maintains that mail headers are the correct technical solution despite the infrastructure concerns raised.

Key technical details mentioned include the behavior of various email clients (ProtonMail Bridge, MS Graph, Thunderbird, Mutt), the distinction between headers and trailers, and backward compatibility issues with older Git versions. The discussion remains focused on the implementation mechanism rather than questioning the feature's overall value.
