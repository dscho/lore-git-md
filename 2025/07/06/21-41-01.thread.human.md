This thread documented the finalization of Git's test organization strategy for command help output verification, originally proposed by Patrick Steinhardt and implemented through multiple patch series by Usman Akinyemi. The work consolidated repository-dependent help tests back into command-specific files (like moving the prune test to t5304-prune.sh) while automating outside-repo testing via `git --list-cmds=main` in t1517-outside-repo.sh. The v5 series completed the effort after addressing test breakages and Windows-specific Perl dependency issues with instaweb.sh.

Junio Hamano maintained architectural oversight throughout, with D. Ben Knoble providing key technical review - notably confirming the exit code 129 pattern for script-based commands and identifying the root cause of Windows test failures. The now-merged solution serves as a reference model for future test additions.

In a recent administrative follow-up, Usman acknowledged Junio's clarification about documenting base commits in cover letters for multi-patch series, confirming the mailing list convention that patches should maintain their original base commit unless non-trivial conflicts arise. This note about submission practices doesn't affect the technical implementation but provides useful guidance for future contributors.
