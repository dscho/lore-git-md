This thread has been working through a systematic reorganization of how Git tests verify command help output. The effort began with Patrick Steinhardt's suggestion to consolidate help tests, which led to an initial 7-patch series that grouped them in t1517-outside-repo.sh. Junio Hamano then proposed a refined strategy: automated testing for outside-repo cases (using `git --list-cmds`) while moving repository-dependent tests back to their command-specific files.

The current 2-patch series demonstrates this approach in action. The first patch implemented automated outside-repo testing for all main commands via a `--list-cmds=main` loop in t1517, handling exceptions like archimport explicitly. The just-received second patch completes the picture by showing how repository-dependent tests should be organized - it moves the `update-server-info -h` test from t1517 to t5200-update-server-info.sh where it logically belongs with other tests for that command.

Both Patrick Steinhardt and Junio Hamano have reviewed and acked the approach, indicating solid consensus. The changes are minimal in terms of line count but significant for long-term test maintainability, properly separating outside-repo verification (now automated) from command-specific testing. This work may influence broader test organization patterns and could serve as a model for other standardized test types. The series appears ready for merging once the final debugging artifact (an echo statement) is removed from the first patch.
