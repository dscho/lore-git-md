This thread documents the completion and refinement of a test strategy for verifying Git command help output, particularly when run outside a repository. The core work was a 2-patch series that automated help testing using `git --list-cmds` while moving repository-dependent tests back to command-specific files. The series has been merged after review.

Post-merge discussion has focused on edge cases and implementation details. D. Ben Knoble recently raised two technical refinements: first, that the suffix-stripping logic for command names (handling `.sh` and `.perl` variants) might make the explicit `p4.py` exception redundant; and second, a Windows-specific issue with `instaweb.sh` handling that surfaced in CI testing. These follow-ups align with the expected post-merge refinement process, where the core approach remains settled but platform-specific and edge cases receive attention.

Earlier discussion had already identified script-based commands (those ending in `.sh` or `.perl`) as having inconsistent exit code behavior (typically 129 for `-h` requests), which is being tracked for standardization. The current conversation continues that theme while adding Windows compatibility to the list of considerations. Junio Hamano and other participants maintain the view that such refinements can proceed incrementally now that the core test strategy is in place.
