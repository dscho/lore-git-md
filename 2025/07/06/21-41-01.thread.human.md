This thread documents the completion of a multi-series effort to reorganize Git's command help output testing. The work originated from Patrick Steinhardt's suggestion and was implemented through several patch series, culminating in Usman Akinyemi's v5 series that finalized the strategy. The changes moved repository-dependent help tests back to their command-specific test files while automating outside-repository help testing through a new `nongit` helper and `git --list-cmds=main` approach in t1517-outside-repo.sh.

The implementation established several key patterns: script-based commands (.sh/.perl) now consistently use exit code 129 for -h behavior outside a repository, while Windows-specific Perl dependency issues (like with instaweb.sh) are handled separately. All main commands are automatically tested, with exceptions handled through a case statement. The work built on prior test relocations and accommodated intervening changes like the_repository refactoring.

With the technical work merged, the thread has shifted to discussing patch submission conventions. Junio Hamano confirmed the practice of maintaining consistent base commits across patch versions unless merge conflicts arise, suggesting that series authors note the base commit in cover letters or after the three-dash line. This administrative note doesn't affect the already-completed implementation but serves as a helpful reminder about mailing list norms. The core test reorganization is now complete, with any remaining follow-ups being incremental refinements to the established patterns.
