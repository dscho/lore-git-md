This thread is part of an ongoing effort to reorganize Git's test suite by consolidating tests for command help behavior (triggered by the -h flag) into a dedicated test file (t1517-outside-repo.sh). The series was suggested by Patrick Steinhardt, following a similar previous reorganization of verify-tag tests.

The current patch (v2, third in a 7-part series) moves the 'ls-files -h' test from t3004-ls-files-basic.sh to the consolidated file. Like previous patches in the series, it verifies that the command exits with code 129 and shows the usage message, testing both repository and non-repository contexts. The test uses case-insensitive pattern matching to accommodate output variations.

The changes are purely organizational - test behavior remains unchanged. The series is progressing smoothly, with the author having already addressed typo feedback in v2. The main open question for reviewers is whether tests that verify behavior in both repository and non-repository contexts belong in a file named "outside-repo", though this appears consistent with the established pattern. The patch appears technically sound and ready for review, continuing the series' clean approach to test consolidation.
