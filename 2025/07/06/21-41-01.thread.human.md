This thread documents the completion of a multi-series effort to reorganize and automate Git's help output testing. The work originated from Patrick Steinhardt's suggestion and was implemented through several patch series, culminating in Usman Akinyemi's v5 series that was recently merged. The changes establish a clear separation between repository-dependent help tests (now moved to command-specific test files) and automated outside-repository testing (handled by t1517-outside-repo.sh).

The implementation uses `git --list-cmds=main` with the `nongit` helper to comprehensively test help output, with special handling for script-based commands (using exit code 129) and platform-specific exceptions. Recent discussion has focused on Windows-specific behavior, particularly around `instaweb.sh`, which appears to have Perl dependency requirements that may need special marking in the test framework. D. Ben Knoble noted this as a distinct case while confirming the overall approach is working as intended.

While the core work is complete, there remain some loose ends being addressed incrementally: standardizing exit codes for script-based commands, investigating minor output mismatches in a few commands, and refining platform-specific handling (now including both Windows and Perl-related cases). The thread shows consensus around this follow-up model, with Junio Hamano maintaining architectural oversight and multiple contributors providing focused technical input on edge cases. The completed work serves as a reference for future test additions while accommodating necessary variations.
