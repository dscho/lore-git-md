This is a documentation patch discussion about template handling in `git init`. Jeff King (peff) responds to Todd Zullinger's historical context about the long-standing behavior where an empty template path (`--template=`) skips copying templates, noting this was intentionally added in 2008 to prevent filesystem corruption. 

Peff agrees this behavior should be documented but suggests also mentioning the newer `--no-template` flag (introduced in Git 2.38.0) as a more ergonomic alternative where available. He notes the empty string behavior remains relevant for cases where the flag isn't applicable (like config/environment variables). The discussion centers on how to document both mechanisms clearly, with `--no-template` being the preferred CLI method while maintaining backward compatibility with the empty path approach. No technical changes are proposed - this is purely about improving documentation to reflect these two related features.
