This is a bugfix discussion regarding message handling in `git stash create` and `git stash store`. Jeff King analyzes the reported discrepancy where custom messages from `create` are lost during `store` operations. He confirms the commit object itself contains the correct message, but the reflog entry (shown by `stash list`) gets overwritten with a generic message during storage.

The analysis suggests two potential fixes: either document the current behavior more clearly (requiring users to pass the message to both commands), or modify `stash store` to automatically preserve the commit's message. The discussion highlights these are primarily scripting interfaces, which may not have received much attention until now. The patch direction isn't settled yet, but the technical root cause is clearly identified.
