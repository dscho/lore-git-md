This is the foundational patch for a new `git repo-info` command, part of Lucas Seiki Oshiro's GSoC project to create a dedicated tool for repository metadata reporting. The patch establishes the command skeleton by:

1. Adding all the basic plumbing: new source file (`builtin/repo-info.c`), build system entries (Makefile, meson.build), documentation stub (git-repo-info.adoc), and command registration in git.c and command-list.txt
2. Defining the command's purpose as a machine-readable alternative to `git rev-parse` for repository-specific information, with planned JSON and null-terminated output formats
3. Introducing the `<category>.<field>` query syntax that will structure the metadata system
4. Marking the command as experimental in the documentation

The implementation currently just provides an empty command framework that returns success, with the actual metadata reporting functionality to come in subsequent patches. The documentation outlines the planned architecture but doesn't yet describe specific fields or categories beyond the conceptual structure.

Key technical elements established:
- Command registered as "plumbinginterrogators" in command-list.txt
- Basic option parsing infrastructure in place via parse-options.h
- RUN_SETUP flag specified, requiring repository initialization
- Documentation follows standard manpage format but leaves sections like CATEGORIES AND FIELDS as stubs

This patch sets up the scaffolding for the metadata system while leaving all substantive behavior for follow-up patches. The thread context shows this is part of a v3 series that has already progressed through several iterations of design discussion.
