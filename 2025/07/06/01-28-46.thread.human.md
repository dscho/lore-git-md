Here's the updated human-readable thread summary:

This thread examines a discrepancy in how `git stash` handles custom messages between the `create` and `store` subcommands. José Miguel Armijo Fidalgo originally reported that messages provided to `git stash create` (like "On main: example message") don't appear in the final stash entry when later stored via `git stash store` - instead showing a generic "Created via git stash store" message in the reflog.

Jeff King's analysis confirmed the commit object itself properly retains the custom message (visible via `git log`), but the reflog entry gets overwritten during storage. The discussion has clarified this as two separate behaviors: commit message preservation (working correctly) versus reflog message handling (currently overwriting custom messages).

Darren Rambaud's follow-up provided concrete reproduction steps showing the custom message remains intact in the commit object metadata while the reflog shows the generic message, reinforcing the technical distinction. The thread now considers two solutions: either documenting this as expected behavior (requiring users to provide messages to both commands), or modifying `stash store` to automatically use the commit's message when none is explicitly given. The choice involves tradeoffs between backward compatibility for existing scripts and making the behavior more intuitive for users.
