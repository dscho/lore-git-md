This thread addresses a discrepancy in how `git stash` handles custom messages between the `create` and `store` operations. José Miguel Armijo Fidalgo originally reported that when creating a stash with a custom message via `git stash create "message"` and later storing it with `git stash store`, the stored stash shows a generic "Created via git stash store" message instead of preserving the custom message. The initial discussion considered whether this was a documentation issue (clarifying that `create`'s message is ignored) or a behavioral bug.

Jeff King (Peff) has now analyzed the technical details and found that the commit object itself does contain the correct custom message, but the reflog entry gets overwritten with the generic text during the `store` operation. He suggests two possible solutions: either document the current behavior (requiring users to provide the message to both commands) or modify `stash store` to automatically use the commit's message when none is specified. This shifts the discussion from whether there's a bug to how the behavior should be designed, with implications for scripting and user expectations. The core question now is whether to preserve backward compatibility with the current behavior or change the implementation to be more intuitive.
