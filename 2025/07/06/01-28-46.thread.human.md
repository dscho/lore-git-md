This thread examines a discrepancy in how `git stash create` and `git stash store` handle custom stash messages. The issue, originally reported by José Miguel Armijo Fidalgo and confirmed by Darren Rambaud, shows that while `git stash create` preserves custom messages in commit objects (visible via `git log`), `git stash store` overwrites them with a generic message in the reflog (`git stash list`). Jeff King's analysis identified this stems from separate message-handling paths in `stash.c`.

The discussion has narrowed to two resolution approaches: either document the current split behavior (making it clear users must provide messages to both commands for full visibility) or modify `stash store` to automatically use the commit's message when none is specified. José's latest email advocates for the documentation route, suggesting explicit clarification about the reflog message behavior if the implementation remains unchanged.

Participants agree the core issue involves `create_stash()` setting commit messages while `do_store_stash()` controls reflog messages, but differ on whether to treat this as a bug or documented behavior. With Jeff's technical analysis and Darren's reproduction steps establishing the mechanics, the thread now weighs the tradeoffs between backward-compatible documentation updates versus more user-friendly code changes.
