This thread addressed a subtle discrepancy in how `git stash` handles custom messages between commit objects and reflog entries. José Miguel Armajo Fidalgo initially reported that messages provided to `git stash create` appear in commit objects but get replaced by a generic "Created via git stash store" message in reflog entries. Jeff King analyzed the implementation, identifying the split between `create_stash()` (which sets commit messages) and `do_store_stash()` (which overwrites reflog messages).

The discussion converged on documenting this behavior rather than changing it, given the current implementation's historical roots and backward compatibility considerations. Junio C Hamano has now contributed a documentation patch that makes several clarifications: it explicitly lists which stash subcommands accept custom messages (`push`, `save`, `store`), better explains that `git stash list` shows the stored message rather than the commit description, and notes that `git stash create` is primarily for internal use with its message argument being an implementation detail. The patch updates only the documentation in `git-stash.adoc`, preserving the existing behavior while making it more transparent to users. This appears to resolve the thread by adopting the conservative documentation approach suggested earlier.
