This thread examines a discrepancy in how `git stash` handles messages between commit objects and reflog entries. The discussion began with José Miguel Armajo Fidalgo and Darren Rambaud reporting that custom messages from `git stash create` appear in commit objects but get replaced by a generic "Created via git stash store" message in reflog entries. Jeff King traced this to the implementation's split between `create_stash()` (which sets commit messages) and `do_store_stash()` (which overwrites reflog messages).

Junio C Hamano initially proposed a documentation patch to clarify the current behavior, noting that `git stash create` is primarily an internal plumbing command, while `push`, `save`, and `store` are the user-facing ways to set stash messages. The documentation update explains that `git stash list` shows the stored message rather than the base commit description, setting clearer expectations without changing the implementation.

The latest development comes from Junio responding to Jeff's suggestion about improving `git stash store` for scripting use cases. While interactive users are steered toward higher-level commands, script writers using `create` to craft detailed messages (potentially for reuse) currently face an awkward experience when using `store` without a custom message, as it discards their carefully written commit message in favor of a generic one. The thread leaves open whether to modify this behavior, but the discussion on balancing backward compatibility with better scripting ergonomics continues. The core technical distinction between commit and reflog message handling in `stash.c` remains unchanged.
