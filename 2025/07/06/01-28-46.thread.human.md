This thread examines a subtle discrepancy in how `git stash` handles commit messages between the `create` and `store` subcommands. José Miguel Armajo Fidalgo initially reported that custom messages set in `git stash create` appear in commit objects but not in reflog entries, which show a generic message instead. Jeff King traced this to the implementation split in `stash.c` between `create_stash()` (which sets commit messages) and `do_store_stash()` (which overwrites reflog messages with a fixed string).

Junio C Hamano proposed documentation updates to better explain which stash commands accept custom messages (`push`, `save`, `store`) and noted that `create` is primarily meant for internal scripting. The discussion then considered whether `store` should be enhanced to reuse commit messages for better scripting ergonomics, but Jeff King has now expressed reservations about this change. He questions its practical utility beyond niche cases like `rebase.autostash`, noting the command has seen little scripting use in its 12-year existence. Without stronger use cases from reporters, the focus remains on improving documentation rather than modifying behavior. The thread illustrates Git's careful balance between fixing inconsistencies and maintaining stability for existing (if obscure) use cases.
