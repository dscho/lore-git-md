Bugfix discussion regarding `git stash` message handling between create/store operations. Jeff King analyzes the reported discrepancy where custom messages from `git stash create` are lost during `git stash store`. He confirms the commit object itself contains the correct message ("On main: example message"), but the reflog entry shows a generic "Created via git stash store" message.

The analysis reveals the core issue lies in `stash store` overwriting the reflog message rather than `stash create` failing to record it. Jeff suggests two potential solutions: (1) documenting the current behavior and proper usage pattern (providing the message to both commands), or (2) modifying `stash store` to automatically use the commit's message when no explicit message is provided.

This response clarifies the technical distinction between commit messages and reflog messages in the stash implementation, moving the discussion from bug-or-documentation to specific implementation choices. The proposed solutions would affect both the documentation and potentially the behavior of these plumbing commands, with implications for scripted stash usage.
