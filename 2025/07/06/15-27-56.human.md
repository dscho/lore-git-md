This is a follow-up discussion about the recently completed documentation conversion of the `git-log` man page to the new synopsis format style. Jean-Noël Avila responds to Junio Hamano's approval of the patch series while expressing some lingering concerns about the technical approach.

The core issue revolves around handling special characters in documentation - particularly parentheses and percent signs - that serve both as syntax markers and literal content in Git's log format descriptions. Avila notes the increasing complexity of using regex patterns to distinguish between these cases, suggesting that a parser combinator approach (as implemented in asciidoctor for git-scm.com) would be more robust.

While the current solution works, Avila openly acknowledges it's not ideal, describing it as reintroducing "complicated format marks everywhere" rather than properly handling the parsing logic. He invites suggestions for implementing parser combinators in asciidoc.py if anyone has examples, indicating this may be an area for future improvement in Git's documentation toolchain.

This email doesn't propose any immediate changes to the already-merged series, but serves as both a technical postmortem and a call for input on better solutions to a recurring documentation formatting challenge. The tone is constructive but candid about the limitations of the current implementation.
