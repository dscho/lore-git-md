This is a discussion about the proposed X-Change-ID header implementation for Git email workflows. Drew DeVault responds to Aditya Garg's concerns about email providers stripping custom headers, arguing that ProtonMail and MS Graph do in fact preserve them, and that Thunderbird's limitations are already a known issue for patch workflows.

DeVault makes several technical points: custom headers are preserved in Mutt when editing normally, Thunderbird's limitations affect all headers (not just custom ones), and losing the header would simply revert to the current state where change IDs aren't preserved. He opposes storing the ID in the email body like trailers, noting this was previously discussed and rejected, and raises concerns that older Git versions might incorrectly ingest such body headers into commit messages.

The exchange highlights an ongoing design debate in the thread about whether headers (more fragile but cleaner) or body storage (more robust but potentially messier) is the right approach for preserving change IDs through email workflows. DeVault firmly advocates for the header approach currently implemented in the patch series.
