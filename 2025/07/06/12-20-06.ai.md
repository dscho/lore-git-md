This is a continuation of the discussion about modifying `git grep` to show only the first match per file. Markus Elfring responds to Andreas Schwab's suggestion that the existing `-l/--files-with-matches` flag already provides similar functionality by noting that sometimes seeing the actual matching line content (rather than just the filename) would be valuable. This suggests the proposed feature would sit between the current `git grep` (shows all matches) and `git grep -l` (shows only filenames), providing a middle ground that shows the first matching line from each file.

The email doesn't propose any implementation details but reinforces the use case where users might want to quickly scan matching content across files without seeing duplicate matches from the same file. This keeps open the question of whether this behavior warrants a new flag or could be achieved through existing options with some adjustment. The thread remains in exploratory phase regarding both the need for and implementation of such a feature.
