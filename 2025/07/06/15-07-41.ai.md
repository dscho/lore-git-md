This is a follow-up discussion about documentation formatting, specifically regarding space notation in verbatim blocks.

Jean-Noël Avila responds to Kristoffer Haugsbakk's suggestion about using the `␣` symbol to explicitly mark spaces in documentation. While acknowledging the idea's merit for certain cases (like `:␣` in `git-interpret-trailers`), Jean-Noël notes that blanket use would be excessive. The core issue stems from how backtick-wrapped commands in the new AsciiDoc format don't always preserve space visibility in rendered manpages, though the git-scm.com site handles this better.

The exchange continues the thread's theme of refining documentation presentation, now focusing on micro-level typography rather than the structural conversion work completed in the main patch series. Jean-Noël suggests reserving `␣` for cases where space visibility is particularly problematic, maintaining a balanced approach to documentation markup. This positions the suggestion as a potential future refinement rather than something needing immediate action in the already-approved `git-log` conversion series.
