Thread summary:

Bug report and analysis of `git stash create`/`store` message handling discrepancy, with documentation patch proposed as resolution. José Miguel Armajo Fidalgo initially reported and Darren Rambaud confirmed that custom messages in `git stash create` appear in commit objects but not in reflog entries, which show a generic "Created via git stash store" message. Jeff King's technical analysis identified the root cause in `stash.c`'s split handling between `create_stash()` (sets commit message) and `do_store_stash()` (overwrites reflog message).

Junio C Hamano now provides historical context and rationale for this behavior through a documentation patch that clarifies several points: it updates which commands accept custom messages (`push`, `save`, `store`), explains `git stash list` shows the stored message not the base commit description, and notes `git stash create` is primarily for internal script use with its message argument being an implementation detail. The patch maintains backward compatibility while making the documentation more accurate about the current behavior.

Key technical aspects remain the `stash.c` implementation's separation of commit and reflog message handling, with the historical evolution from a simple emergency-stashing tool to one supporting custom messages. The documentation approach resolves the reported discrepancy by setting clearer expectations without altering the implementation, following the conservative path suggested earlier in the thread. The changes touch only `Documentation/git-stash.adoc`, modifying descriptions of the `list`, `create`, and overall command behavior. This appears to be the final resolution, with Junio's patch providing the authoritative documentation update to close the issue.
