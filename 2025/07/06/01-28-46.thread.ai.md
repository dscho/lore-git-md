Thread summary:

Bug report and analysis of `git stash create`/`store` message handling discrepancy. José Miguel Armijo Fidalgo reported that custom messages provided to `git stash create` are not preserved when the stash is later stored via `git stash store`, with the reflog showing a generic "Created via git stash store" message instead. Jeff King's analysis confirms the commit object itself contains the correct custom message (e.g. "On main: example message"), but the reflog entry is overwritten during the store operation.

The discussion has identified two distinct aspects of message handling: commit messages (preserved correctly) versus reflog messages (overwritten). Jeff proposes two resolution paths: (1) documenting the current behavior and recommending users provide the message to both commands, or (2) modifying `stash store` to automatically use the commit's message when no explicit message is provided. The choice between these approaches involves tradeoffs between backward compatibility, script-friendliness, and intuitive behavior.

Key technical details: the issue stems from `stash.c`'s implementation where `create_stash()` properly sets the commit message but `do_store_stash()` overwrites the reflog message unconditionally. The discussion now focuses on whether to treat this as a documentation clarification or a behavioral change in the plumbing commands, with implications for existing scripts that may rely on the current behavior.
