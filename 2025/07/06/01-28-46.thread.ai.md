Thread summary:

Bug report and analysis of `git stash create`/`store` message handling discrepancy, with documentation patch proposed as resolution. José Miguel Armajo Fidalgo initially reported and Darren Rambaud confirmed that custom messages in `git stash create` appear in commit objects but not in reflog entries, which show a generic "Created via git stash store" message. Jeff King's technical analysis identified the root cause in `stash.c`'s split handling between `create_stash()` (sets commit message) and `do_store_stash()` (overwrites reflog message).

Junio C Hamano provided historical context through a documentation patch that clarifies which commands accept custom messages (`push`, `save`, `store`), explains `git stash list` behavior, and notes `git stash create` is primarily for internal script use. Jeff King initially suggested improving `git stash store` ergonomics for script writers by having it pull the default message from the commit rather than using a generic one, but in a follow-up expresses reservations about this change, questioning its real-world utility beyond `rebase.autostash` implementation needs. He notes the command appears rarely used in scripting contexts despite being available for 12 years, and seeks more concrete use cases before considering changes that might affect existing (though likely minimal) usage.

Key technical aspects remain the `stash.c` implementation's separation of commit and reflog message handling, with the historical evolution from simple emergency-stashing to supporting custom messages. The discussion now balances between potential improvements for script users and maintaining stability for obscure use cases, with Jeff's skepticism suggesting the behavior change may not proceed without stronger motivation. Current resolution path focuses on documentation updates in `Documentation/git-stash.adoc` while leaving open the possibility of future ergonomic improvements if compelling use cases emerge. The split between `create_stash()` (commit messages) and `do_store_stash()` (reflog messages) remains unchanged pending further input from the original reporter or other script users.
