Thread summary:

Bug report and analysis of `git stash create`/`store` message handling discrepancy. José Miguel Armijo Fidalgo reported and Darren Rambaud confirmed that custom messages provided to `git stash create` appear in the commit object's message (visible via `git log`) but not in the reflog entry shown by `git stash list`, which shows a generic "Created via git stash store" message instead. Jeff King's analysis confirms this stems from `stash.c`'s implementation where `create_stash()` sets the commit message while `do_store_stash()` overwrites the reflog message unconditionally.

The discussion has identified two distinct aspects of message handling: commit messages (preserved correctly) versus reflog messages (overwritten). Jeff proposes two resolution paths: (1) documenting the current behavior and recommending users provide the message to both commands, or (2) modifying `stash store` to automatically use the commit's message when no explicit message is provided. Darren's email provides concrete command-line evidence showing the commit properly retains "On main: changes to readme" while the reflog shows the generic message, reinforcing the technical distinction.

Key technical details: The issue involves `stash.c`'s split handling of commit versus reflog messages, with reproduction steps demonstrating how to inspect both locations (commit object via detached HEAD, reflog via `stash list`). The choice between documentation clarification versus behavioral change remains open, with tradeoffs around backward compatibility, script-friendliness, and intuitive behavior for plumbing commands. No new solution proposals have emerged since Jeff's initial options, but Darren's confirmation strengthens the case for addressing the discrepancy one way or another.
