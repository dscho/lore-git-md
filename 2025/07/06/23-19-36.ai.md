This is an implementation patch in the `repo-info` command series, adding support for reporting the reference storage format (files vs reftable). It's part of Lucas Seiki Oshiro's GSoC project to create a new command for querying repository metadata.

The patch introduces a new `references.format` field that reports whether the repository uses the traditional files-based reference storage or the newer reftable format. The implementation leverages Git's existing `--show-ref-format` functionality from `git-rev-parse` but presents it through the new `repo-info` command's interface.

Key technical details include:
- New enum values and struct fields to track reference format queries (`CATEGORY_REFERENCES`, `FIELD_REFERENCES_FORMAT`)
- Output handling for both JSON and null-terminated formats
- Integration with the repository's `ref_storage_format` field
- Comprehensive tests in t1900-repo-info.sh covering both output formats
- Documentation updates in git-repo-info.adoc

The implementation follows the series' established patterns for field handling and output formatting. It demonstrates the command's ability to surface repository metadata through a consistent interface while maintaining the flexibility to support additional fields in future patches. The test coverage is thorough, verifying both the basic functionality and edge cases across output formats.

This represents solid progress on the core functionality envisioned for `repo-info`, though as noted in the thread summary, questions remain about the overall field system architecture and output format consistency with other Git commands.
