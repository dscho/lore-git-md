Feature implementation for the new `git-repo-info` command, adding the `layout.bare` field to report whether a repository is bare. This is part of the v3 series introducing repository metadata reporting functionality.

The patch adds support for detecting and reporting bare repository status through both JSON and null-terminated output formats. It leverages Git's existing `is_bare_repository()` function, which is also used by `git-rev-parse --is-bare-repository`. The implementation follows the established pattern from previous fields in the series, with:
- New `CATEGORY_LAYOUT` and `FIELD_LAYOUT_BARE` enum values
- JSON output via `json-writer.h` showing `"bare": true/false`
- Null-terminated output matching the format used for other fields
- Test cases verifying both output formats for bare and non-bare repos

The changes touch documentation (adding the new field to git-repo-info.adoc), core command implementation (adding the field handling logic), and tests (new cases for bare repo detection). The implementation appears clean and consistent with the existing code, though it does use `the_repository` global via the `USE_THE_REPOSITORY_VARIABLE` macro, which remains an open question in the thread about modernization approaches.

This continues the series' pattern of surfacing repository metadata through a structured interface, with the bare/non-bare status being a fundamental property users would want to query. The patch maintains the command's dual-format output capability and adds comprehensive test coverage for the new field.
