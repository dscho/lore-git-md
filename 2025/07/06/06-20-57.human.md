This is a discussion about the proposed X-Change-ID header feature for Git email workflows. Aditya Garg raises concerns about the approach of using custom email headers, arguing that many email providers and clients (including ProtonMail, MS Graph, Thunderbird, and Mutt) don't reliably preserve custom headers. They suggest instead including the change ID in the email body alongside other standard metadata like Signed-off-by lines.

The comment comes in response to Drew DeVault's v2 series which aims to help patch management systems track changes through email review by preserving change IDs. While the technical implementation appears sound (as noted in the thread summary), this new objection questions the fundamental design choice of using email headers rather than body content.

This represents a significant design consideration that wasn't previously raised in the thread. The reliability of header preservation across different email ecosystems could impact whether this feature works as intended for all users. The comment doesn't propose an implementation alternative, focusing instead on the architectural concern. This may prompt discussion about whether to modify the approach or document known limitations.
