This is a bugfix patch in the reflog migration infrastructure series, specifically addressing race conditions in HEAD reflog updates. The patch introduces a new `REF_LOG_VIA_SPLIT` flag to help detect when HEAD has been concurrently updated during reflog generation.

The core issue involves the `split_head_update()` function which generates reflog entries for HEAD when updating references that HEAD points to. The current implementation has two race conditions: it might miss writing a reflog entry when it should, or write one when it shouldn't, due to not locking HEAD after reading its target.

The solution adds post-lock verification that HEAD still points to the expected reference, using the new flag to identify split updates. It also improves old-oid handling by using the parent update's state rather than resolving it separately. The patch acknowledges this only fixes one of the two race conditions, as fully preventing the other would either require serializing all writes or is fundamentally unfixable due to potential flip-flopping during transactions.

Junio Hamano's response notes this is an improvement over the current state, though he muses about whether HEAD reflog updates for underlying branch changes were a good design choice in the first place. The implementation matches the described solution and moves the code in a better direction despite the inherent limitations.
