This is a review comment on a patch from the `the_repository` removal effort, specifically addressing the first patch in a 2-part series that removes the `merge_log_config` global variable. Junio Hamano points out a subtle behavioral change in how invalid configuration is handled.

The original patch moved configuration handling for merge message formatting from a global variable to a new `adjust_shortlog_len()` function. Junio notes that while the technical implementation is correct, it changes error reporting behavior: previously, invalid `merge.summary` values would trigger an error even when overridden by command-line `--log`, but now invalid config is silently ignored when command-line options are present.

Junio doesn't reject the change outright but suggests documenting this behavioral difference in the commit message, as it could affect future debugging or maintenance. The comment maintains a constructive tone while highlighting an important consideration that wasn't addressed in the original submission. This exemplifies the careful attention needed when modifying configuration handling, even in mechanical refactoring work.
