This is a discussion about refname resolution behavior in Git's reflog subcommands, specifically focusing on the inconsistency between `write` and `drop` operations. Kristoffer Haugsbakk responds to Ben Knoble's confirmation of real-world user confusion with the current behavior.

The email reinforces the known issue where shorthand refnames (like "branch" vs "refs/heads/branch") behave differently across Git commands. While `git update-ref` has consistent (though sometimes surprising) behavior that's well-documented, the new `git reflog write` subcommand currently doesn't resolve shorthands like `reflog drop` does, creating potential for user mistakes.

Kristoffer shares personal experience with similar confusion in `update-ref`, highlighting that documentation is key - the behavior is less problematic when properly documented. This adds weight to the ongoing discussion about whether to unify DWIM (Do What I Mean) behavior across all reflog subcommands, with Junio Hamano having proposed making `write` match `drop`'s behavior rather than removing DWIM entirely.

The exchange shows growing consensus that the current inconsistency is problematic, with multiple contributors now reporting real-world confusion. The thread appears to be moving toward a solution that would either document the differences clearly or implement consistent behavior across commands.
