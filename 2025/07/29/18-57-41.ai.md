This is a cover letter for a 3-patch series introducing a new `--max-depth` option to Git's diff machinery, originally authored by Jeff King (Peff) and now being proposed by Toon Claes. The series aims to add depth-limiting functionality similar to what exists in `git grep`, but for diff operations.

The core change adds `max_depth` and `max_depth_valid` fields to `struct diff_options`, allowing diff operations to stop recursive tree traversal at a specified depth from the pathspec. The implementation differs from `git grep`'s approach which uses `struct pathspec`, raising a potential design question about whether these should be unified, though the cover letter notes this may not be critical since the code paths are separate.

The series includes preparatory cleanups (zeroing memory in combine-diff and fixing an edge case in depth calculation) before introducing the main feature. Test coverage appears thorough with 109 lines of new tests in t4072-diff-max-depth.sh. The change touches core diff infrastructure across multiple files (diff.c, tree-diff.c) and updates documentation.

Historical context is provided linking this to prior discussions around git-blame-tree/git-last-modified functionality, where the need for depth-limiting in diffs was previously identified. The patches are presented as nearly verbatim from Peff's GitHub fork with minor commit message tweaks, maintaining his authorship.
