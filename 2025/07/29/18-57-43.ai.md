This is the second patch in a 3-part series introducing a `--max-depth` option for Git's diff machinery. It's a bugfix addressing an edge case in the depth calculation logic.

The patch fixes the `within_depth()` function in dir.c, which checks if pathspecs with max-depth limits are acceptable. The original implementation had inconsistent behavior when the base path had no slashes (depth 0) versus when it had a positive depth. While this didn't cause user-visible bugs in current callers (which all pass base depth 0), it could affect future uses like diff operations that might want to show directory entries themselves.

The fix changes the return condition to consistently compare the calculated depth against max_depth. The commit message provides a detailed analysis of the current behavior with examples showing how directory traversal works at different depth limits, and explains why the inconsistency doesn't currently matter for `git grep` (the only current max-depth user) but might for future diff operations.

The change itself is minimal - a one-line modification to the return statement in dir.c. The patch maintains Jeff King's original authorship while being submitted by Toon Claes as part of bringing this series to the list. This appears to be a well-justified fix that tightens up the depth calculation logic in preparation for the main feature addition in patch 3/3.
