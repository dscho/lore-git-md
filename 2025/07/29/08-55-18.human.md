This is a patch series addressing reflog migration issues between Git's files and reftable backends, with a focus on fixing identity information and old commit IDs in migrated entries. The series also introduces a new `git reflog write` subcommand.

Patrick Steinhardt discovered these issues while implementing reftable support in libgit2, where test failures revealed problems in Git's reflog migration: incorrect committer identity and all-zero old commit IDs. The series fixes both issues while adding the new `write` subcommand for testing and debugging.

Key changes in v3 include requiring fully-qualified refnames for the new `write` command and adding race condition detection for HEAD reflog updates in the files backend. The series has been rebased on v2.50.1 for potential backporting.

The 9 patches cover documentation updates, subcommand implementation, type safety fixes, identity correction, race detection, and old-OID handling. Test coverage has been expanded, particularly for the new `write` subcommand. The changes appear well-motivated and carefully implemented, with clear connections to the ongoing reftable adoption effort.
