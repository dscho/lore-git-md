This is a feature patch series introducing a `--max-depth` option to Git's diff machinery, originally authored by Jeff King (Peff) and now being proposed by Toon Claes. The series adds the ability to limit recursive tree traversal depth during diffs, similar to functionality found in `git grep`.

The cover letter explains this work emerged from discussions around the git-last-modified feature, where the need for depth-limited diffs was repeatedly raised. The implementation adds new `max_depth` fields to `diff_options` rather than reusing the pathspec approach from grep, which the author acknowledges might warrant future consolidation but considers acceptable for now.

The series includes three patches: a memory initialization fix, a bugfix for empty path handling, and the main feature implementation. It comes with thorough documentation updates and a new test file with 109 lines of test coverage. The patches appear well-structured and maintain authorship credit to Jeff King while being submitted by Toon Claes with only minor message tweaks.

This looks like a focused, well-motivated addition to the diff machinery that could be useful for both direct use and as a building block for other features. The historical context and clear separation of concerns in the patches suggest it's likely to receive serious consideration.
