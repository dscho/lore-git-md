This thread centers on adding a `--max-depth` option to Git's diff machinery, originally conceived by Jeff King (Peff) and now being shepherded by Toon Claes. The feature would limit recursive tree traversal depth during diffs, similar to `git grep --max-depth`, with use cases like optimizing blame-tree operations.

The series consists of three patches: two preparatory cleanups (fixing depth calculations and memory allocation) followed by the main implementation. The core functionality has been validated by Patrick Steinhardt, who suggested several improvements that Toon incorporated - including proper type handling, const-correctness, and better error messages. The current version handles edge cases like empty paths and includes comprehensive tests.

In the latest exchange, Patrick raises two remaining technical questions about option parsing: whether to use `OPT_UNSIGNED()` for cleaner initialization, and whether to support -1 as "no limit" like grep does. The discussion remains focused on these implementation details, with Patrick offering alternatives while acknowledging the current approach may be acceptable if changes prove difficult.
