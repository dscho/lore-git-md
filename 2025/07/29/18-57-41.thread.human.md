This thread discusses a 3-patch series adding a `--max-depth` option to Git's diff machinery, originally conceived by Jeff King and now being shepherded by Toon Claes. The feature allows limiting recursive tree traversal depth during diffs, similar to `git grep --max-depth`, which is particularly useful for optimizing operations like git-blame-tree where full traversal is unnecessary.

The v2 series incorporates all prior feedback, with key improvements including comprehensive unit tests for the depth calculation logic, support for `-1` as unlimited depth, better error handling using BUG() macros, and documentation refinements. Patrick Steinhardt has reviewed and validated the core approach. The implementation carefully handles edge cases - depth is measured from pathspec matches rather than the repository root, and the option is explicitly incompatible with wildcard pathspecs and non-tree diffs.

Junio Hamano has now weighed in, noting the series appears ready for consideration and may be suitable for inclusion after the 2.51 release. While some minor design questions remain around option parsing defaults and the `max_depth_valid` flag, these don't block progress. The series represents a well-vetted addition to Git's diff capabilities, building on existing infrastructure while adding careful constraints for performance-sensitive use.
