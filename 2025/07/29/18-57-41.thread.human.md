This thread introduces a new `--max-depth` option for Git's diff machinery, allowing users to limit how deeply Git traverses directory trees when comparing changes. The feature was initially prototyped by Jeff King (Peff) and is now being finalized by Toon Claes in a 3-patch series currently at version 2.

The core implementation adds depth tracking to Git's diff infrastructure, with careful handling of edge cases like empty paths and proper integration with pathspecs. The series includes both unit tests for the low-level `within_depth()` helper and extensive integration tests covering various depth combinations and edge cases. Patrick Steinhardt has reviewed the implementation and validated the core logic, suggesting several improvements that have been incorporated.

The most recent patch (3/3) implements the main feature, building on fixes from the first two patches. It adds thorough test coverage and handles several special cases, like explicitly prohibiting the option with wildcard pathspecs or non-tree diffs. The team has addressed all feedback from the first version, including making error messages translatable and using proper error handling patterns.

A few minor implementation details remain open for discussion, mostly around how to best handle the option parsing internals and whether to simplify the `max_depth_valid` flag usage. The core functionality appears solid and well-tested, with the main architectural questions already resolved. The series looks ready for final polishing before potential inclusion.
