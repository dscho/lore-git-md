This thread introduces a new `--max-depth` option for Git's diff machinery, originally authored by Jeff King (Peff) and now proposed by Toon Claes. The feature limits recursive traversal during tree diffs, similar to `git grep --max-depth`, which will be particularly useful for optimizing operations like git-blame-tree and git-last-modified where full tree traversal is unnecessary.

The series consists of three patches: two preparatory fixes (ensuring proper memory initialization and fixing depth calculation consistency) followed by the main implementation. The core patch adds depth checking to tree diffs while maintaining separation from grep's implementation approach. It includes thorough documentation and test coverage (109 new test lines) that exercises various depth levels and edge cases.

Toon Claes has updated the preparatory patches based on feedback, including switching to `CALLOC_ARRAY()` for memory allocation and fixing a subtle depth calculation inconsistency. The implementation appears solid, though there are open questions about whether the depth-limiting approach should eventually be unified with grep's pathspec-based method and whether combine-diff filepairs need special handling. These don't block the current implementation but may inform future work.

The thread shows careful attention to edge cases and builds on Jeff King's original design while incorporating improvements. With the test coverage and documentation in place, this looks like a well-prepared feature that could graduate to `next` after any final review comments are addressed.
