This is a preparatory refactoring patch in a performance optimization series for remote ref operations. Karthik Nayak is responding to Patrick Steinhardt's patch that modifies the reflog callback interface to include the refname parameter, which will be used in subsequent patches to simplify ref migration logic.

The change standardizes the `each_reflog_ent_fn` callback signature across 17 files by adding a `const char *refname` parameter, eliminating the need for callers to track the current refname through callback data. Karthik confirms this addresses a pain point he encountered in the migration code and approves the changes, while also providing some minor clang-format style suggestions for the callback function signature formatting.

This is part of a larger effort (already reviewed and approved by Junio Hamano and others) that ultimately delivers significant performance improvements for remote operations (238s->2s for files backend). The current patch is a straightforward infrastructure change that enables the more complex optimizations in later patches.
