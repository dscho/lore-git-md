Feature implementation for reflog management. This is patch 4/9 in Patrick Steinhardt's series to improve reflog infrastructure, particularly for the reftable backend transition.

The patch introduces a new `git reflog write` subcommand that allows manually appending entries to a reflog. This fills a gap in Git's tooling, especially important for the reftable backend where manual editing isn't feasible. The implementation is intentionally minimal - it only supports appending single entries with strict validation: refnames must be fully-qualified, OIDs must be complete and exist, and messages get normalized.

The command includes thorough error checking and comes with a comprehensive test suite covering invalid inputs, object validation, message normalization, and basic write operations. The tests reveal a known issue with old-OID tracking that will be addressed in later patches. This appears to be a well-considered addition that maintains Git's safety guarantees while enabling new reflog management workflows needed for the reftable transition.
