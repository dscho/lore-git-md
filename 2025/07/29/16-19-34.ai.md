`the_repository` removal effort targeting `merge_log_config` global variable.

This is the first patch in a 2-part series (originally started by René Scharfe) that removes the global `merge_log_config` variable used for merge log configuration. The patch moves this functionality into a new `adjust_shortlog_len()` function in fmt-merge-msg.c, which handles the configuration lookup when `shortlog_len` is negative.

Key changes:
1. Removes `merge_log_config` from environment.c entirely
2. Adds new `adjust_shortlog_len()` that checks both "merge.log" and "merge.summary" configs
3. Updates callers in builtin/fmt-merge-msg.c and builtin/merge.c to use the new function
4. Maintains the same behavior - using DEFAULT_MERGE_LOG_LEN (20) when config is true, the config value when numeric, or 0 when unset/negative

The implementation is clean and maintains all existing functionality while removing the global state. The patch is part of the broader effort to eliminate globals and improve code modularity, though it still uses `the_repository` (which will be addressed in patch 2). The changes touch core merge machinery components but are well-contained to configuration handling.
