Shell scripting style suggestion in test suite review.

Ben Knoble chimes in on the ongoing discussion about test implementation details in Lucas Seiki Oshiro's `git repo info` series. He agrees with Eric Sunshine's suggestion to use `printf` rather than `lf_to_nul` for null-terminated output, but adds a refinement: using `printf %s\\0 "$var"` syntax to avoid potential issues with format specifiers in the variable content. This is a subtle but important shell scripting best practice that prevents interpretation of percent signs in the output as format directives.

The email also implicitly endorses Eric's broader point about avoiding fragile `tail -n 1` extraction in favor of comparing complete output with `test_cmp_bin`, though Ben doesn't restate that part of the suggestion. His contribution focuses specifically on the safer way to handle null-terminated output in shell scripts, which is relevant to the series' implementation of the `--format=nul` output option.

This is a small but technically precise suggestion that shows attention to cross-platform robustness and shell scripting edge cases - the kind of detail that often matters in Git's test suite. The thread continues to refine the implementation with input from multiple experienced contributors.
