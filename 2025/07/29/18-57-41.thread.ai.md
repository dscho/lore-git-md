Thread identity: 3-patch series introducing `--max-depth` option for Git's diff machinery, originally authored by Jeff King (Peff), now proposed by Toon Claes. Thread type: feature addition to diff subsystem.

Core problem/goal: Add depth-limiting functionality to diff operations (similar to `git grep --max-depth`) by stopping recursive tree traversal at specified depth from pathspec. Primary use case is optimizing operations like git-blame-tree/git-last-modified where full tree traversal is unnecessary.

Technical details:
- Adds `max_depth` and `max_depth_valid` fields to `struct diff_options` (confirmed unsigned/boolean types)
- Touches diff.c, tree-diff.c, combine-diff.c, and dir.c core infrastructure
- Includes 2 preparatory patches:
  1. Switches combine-diff to use `CALLOC_ARRAY()` for `diff_filepair` allocation
  2. Fixes edge case in `within_depth()` function in dir.c with comprehensive test coverage
- Main patch adds `--max-depth` option with 109 lines of new tests in t4072-diff-max-depth.sh
- Implements depth checking in tree-diff.c with const-correct helpers
- Explicitly disallows use with wildcard pathspecs and non-tree diffs
- Supports -1 as "no limit" value (pending implementation)
