René Scharfe has been working on removing global state dependencies in Git's merge message formatting code as part of the ongoing `the_repository` removal effort. His two-patch series focused on the `fmt-merge-msg` builtin, systematically eliminating two key global dependencies: first the `merge_log_config` variable, then the remaining `the_repository` usage. The changes maintained all existing behavior while improving the code structure.

Junio Hamano has now reviewed the work and identified an important subtle issue. While the technical conversion from `git_config()` to `repo_config()` is correct, the patch inadvertently changed the order of configuration parsing - moving it after command-line option processing rather than before. This violates Git's standard pattern where config values are read first, then overridden by command-line options. Hamano notes this could cause subtle bugs if future options or config variables are added that interact with these settings. The review suggests either restoring the original order or providing justification for the change.

The core of the series remains sound - removing global state while maintaining functionality - but this configuration ordering issue will need to be addressed before the changes can proceed. It serves as a good example of how even mechanical refactoring in the `the_repository` removal effort requires careful attention to surrounding code patterns and conventions.
