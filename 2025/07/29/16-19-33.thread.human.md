This thread covers Ayush Chandekar's 2-patch series to remove `the_repository` usage from `fmt-merge-msg`, mentored by Christian Couder. The changes restructure configuration handling in `builtin/fmt-merge-msg.c` while carefully preserving all existing behavior, including the precedence of `merge.summary` over `merge.log` settings and proper handling of boolean values.

The first patch, now approved by Phillip Wood, localizes the `merge_log_config` variable that was previously stored globally in `environment.c`. It moves this into `cmd_fmt_merge_msg()` and `cmd_merge()`, passing it via callback instead of using the deprecated global variable. Phillip's review confirms the changes meet the technical requirements without introducing regressions.

The second patch completes the transition by removing the `USE_THE_REPOSITORY_VARIABLE` macro, activating the `repo` parameter, and replacing `git_config()` with `repo_config()`. It also adds a test case verifying `git fmt-merge-msg -h` works outside a repository, addressing Junio Hamano's earlier guidance. The minimal but complete changes (5 lines of code plus a 7-line test) appear ready for final review, marking another step forward in the ongoing effort to eliminate `the_repository` dependencies.
