Documentation and code reorganization patch in Patrick Steinhardt's reflog migration series. This is patch 2/9 in v3, following the documentation standardization in patch 1. The change reorders `git-reflog` subcommands for better logical grouping: read-only commands (`show`, `list`, `exists`) now precede write commands (`delete`, `drop`, `expire`), with `expire` moved last to accommodate the upcoming `write` subcommand. The patch makes matching changes to both the documentation (man page) and the command-line help text ordering in `builtin/reflog.c`, keeping the implementations synchronized. No behavior changes are introduced - this is purely an organizational improvement to make the command structure more intuitive and prepare for the new `write` functionality coming later in the series. The commit message clearly explains the rationale for the current ordering and how it sets up for future additions.
