This is a discussion about the new `git reflog write` subcommand's behavior regarding refname resolution, part of Patrick Steinhardt's ongoing reflog migration infrastructure work.

Ben Knoble responds to Kristoffer Haugsbakk's observation about inconsistent refname resolution between `git reflog write` and other reflog subcommands. While `show` and `drop` accept shorthand branch names (resolving `branch` to `refs/heads/branch`), the new `write` command requires full refnames, which could lead to users accidentally creating reflog entries for the wrong ref.

The thread has previously discussed Junio Hamano's proposal to unify this behavior by adding DWIM (Do What I Mean) resolution to `write` for consistency. Ben supports this approach, noting that users expect shorthand names to work consistently across Git commands, and that the current behavior could cause confusion when entries appear to "truncate" reflogs due to incorrect ref resolution.

The discussion highlights an important UX consideration for the new subcommand - whether to maintain strict refname requirements (as in `git update-ref`) or adopt the more forgiving behavior of other reflog commands. This ties into broader questions about command consistency in Git's interface.
