This is a bugfix patch that completes the implementation of diff context configuration support for interactive patch commands (like `git add -p`). It's part of a larger series that has been through multiple rounds of review and is now in its final stages.

The patch specifically ensures that the add-patch infrastructure properly reads and respects the `diff.context` and `diff.interHunkContext` configuration values. Key changes include:

1. Adding new `context` and `interhunkcontext` fields to `struct add_i_state` to store these configuration values
2. Reading these config values in `init_add_i_state()` with validation to reject negative values
3. Passing the values to the underlying diff machinery via `--unified` and `--inter-hunk-context` options when generating diffs
4. Adding comprehensive tests in t3701 to verify:
   - Basic respect of `diff.context` configuration
   - Proper handling of `diff.interHunkContext`
   - Rejection of negative context values

The implementation matches the behavior of other diff-generating commands and completes the series' goal of providing consistent diff context configuration across all interactive patch commands. The patch follows the established patterns from earlier in the series and includes thorough test coverage for the new functionality.

This is the third patch in a 4 series that has been extensively reviewed, with all major design questions resolved. The only remaining items are some minor test adjustments (restoring accidentally removed config tests and removing redundant tests) which are being handled in other patches of the series. The implementation is considered complete and ready for merging.
