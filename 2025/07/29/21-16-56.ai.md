This is a follow-up in the `the_repository` removal thread, specifically addressing the config precedence behavior change in the `fmt-merge-msg` refactoring. Ayush Chandekar responds to Phillip Wood's observation that the new implementation breaks Git's config precedence rules by always preferring `merge.log` over `merge.summary`, whereas the original code processed values in order (last one wins).

Chandekar explains their rationale for the documentation states `merge.summary` is deprecated, which led them to intentionally give precedence to `merge.log`. This reveals a tension between maintaining backward compatibility with config precedence rules versus following deprecation guidance. The response doesn't propose a solution but provides context for the design decision.

Key technical points include:
- The conflict between deprecation policy (`merge.summary` marked for removal) and config processing semantics (last-value-wins)
- The specific behavior change where `merge.log` now always overrides `merge.summary` regardless of order in config files
- Reference to `Documentation/git-fmt-merge-msg.adoc` as justification

This email doesn't resolve the issue but provides important context about the intentional (rather than accidental) nature of the precedence change, setting up further discussion about whether to preserve backward compatibility or accelerate the deprecation path.
