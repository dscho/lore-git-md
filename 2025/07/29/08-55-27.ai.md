Bugfix for reflog migration between storage formats, addressing invalid old object IDs in migrated entries. This is the final patch in Patrick Steinhardt's v3 series (9/9) focused on reflog infrastructure improvements.

The patch fixes a subtle issue where reflog entries migrated between storage formats (e.g. files to reftable) would incorrectly show all-zero old object IDs. The root cause was that the migration code wasn't properly using the caller-provided old OIDs, instead trying to resolve them from references that didn't yet exist in the target storage. The solution introduces a new `REF_LOG_USE_PROVIDED_OIDS` flag that tells backends to use the explicitly provided OIDs rather than attempting resolution.

Key technical details:
- Adds flag definition and documentation in refs.h
- Modifies both files and reftable backends to honor the flag
- Updates tests to verify both old and new OIDs using a new test helper
- Fixes a related test case in t1421 that was masking the issue
- Maintains safety checks requiring both old/new OIDs when flag is set

The changes are well-contained and focused, with thorough test coverage that now properly exercises the old OID preservation. This completes the series' work on OID integrity during reflog migration, building on earlier patches that addressed committer identity formatting and race conditions. The solution is particularly important for the reftable backend where correct historical reflog data is critical.
