This is the final patch in Patrick Steinhardt's series addressing reflog migration between storage formats, specifically fixing a bug in old object ID preservation during migration.

The patch corrects a subtle but important issue where migrated reflog entries were incorrectly getting all-zero old object IDs instead of preserving the original old OIDs. The root cause was that the migration code was trying to resolve the old OID from the reference value rather than using the provided OID from the original reflog entry. Since the reference didn't exist in the target storage yet, this resolution always failed, resulting in zeros.

The solution introduces a new `REF_LOG_USE_PROVIDED_OIDS` flag that tells the backend to use the caller-provided OIDs directly rather than attempting resolution. The patch updates both the files and reftable backends to honor this flag and includes comprehensive test updates to verify the fix. The test changes are particularly thorough - they introduce a new helper to examine reflog entries in detail (showing both old and new OIDs) and update existing tests to catch this class of error.

This completes the technical work in the series, which has progressed through multiple iterations with careful attention to atomicity, race conditions, and cross-backend consistency. The patch maintains the high standard seen throughout the series, with clear commit message explanation, proper flag documentation, and robust test coverage.
