Bugfix for race conditions in HEAD reflog updates. This patch from Patrick Steinhardt addresses a subtle race in the files backend when generating reflog entries for HEAD during reference updates. The core issue occurs when HEAD's target changes between when we check it and when we actually write the reflog entry, potentially leading to missing or incorrect reflog entries.

The solution introduces a new `REF_LOG_VIA_SPLIT` flag to mark these special reflog updates and adds validation after locking HEAD to ensure it still points to the expected reference. While this fixes one class of races (preventing incorrect reflog entries), it can't fully prevent all possible races without unacceptable performance penalties from locking HEAD too aggressively.

This is part of a larger series improving reflog handling, particularly around the files-to-reftable migration. The patch builds on previous work that standardized reflog command structure and improved type safety. While the solution isn't perfect (some races remain unfixable), it represents a careful balance between correctness and performance in a tricky edge case.
