Refactoring of reflog update flag behavior in the reftable migration series. This patch modifies how the `REF_HAVE_OLD` flag is handled during reflog updates, preserving it as a signal that an old OID was provided while still preventing unwanted verification for log-only updates.

The change affects multiple backend implementations (files and reftable) to maintain consistent behavior. The key technical points are:
1. Stops unsetting `REF_HAVE_OLD` for log-only updates (previously done in `ref_transaction_update_reflog()` and split updates)
2. Adds explicit checks to skip old-OID verification when `REF_LOG_ONLY` is set
3. Updates documentation to clarify that log-only updates never require old state matching
4. Maintains the same safety checks for non-log updates

This prepares for a subsequent change that will use `REF_HAVE_OLD` as a signal for new reflog-writing behavior. The patch demonstrates careful attention to maintaining atomicity guarantees while enabling future functionality, with changes spread across the refs subsystem's core and both backend implementations.
