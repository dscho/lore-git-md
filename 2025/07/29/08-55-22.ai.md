Feature implementation in Patrick Steinhardt's reflog migration series (patch 4/9). This introduces a new `git reflog write` subcommand to manually append entries to reflogs, primarily motivated by the reftable backend transition where manual editing isn't feasible.

The implementation enforces strict validation: refnames must be fully-qualified, OIDs must be complete and reference existing objects, and messages get normalized. The command currently supports only single-entry appends without date specification or nonexistent object references, though the commit notes these could be future extensions. 

Key technical aspects:
- Adds `cmd_reflog_write()` in builtin/reflog.c handling the new subcommand
- Validates inputs through `check_refname_format()` and `get_oid_hex_algop()`
- Uses `ref_transaction_update_reflog()` with hardcoded flags (from previous patch)
- Includes comprehensive tests (t1421-reflog-write.sh) covering:
  - Argument validation
  - Refname qualification requirements
  - OID existence checking
  - Message normalization
  - Basic write functionality
  - Special case for ROOT_REF_HEAD

The patch fits into the broader series by providing the user-facing tooling that will work with both files and reftable backends, though its immediate utility is greater for reftable where manual editing isn't possible. The strict validation aligns with the series' focus on correctness during the backend transition.
