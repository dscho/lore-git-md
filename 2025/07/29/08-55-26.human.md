This is a refactoring patch in Patrick Steinhardt's ongoing reflog migration series, specifically addressing the `REF_HAVE_OLD` flag behavior for log-only updates. The patch changes how the flag is handled to better support upcoming reflog functionality while maintaining race condition safety.

Currently, Git unsets the `REF_HAVE_OLD` flag for reflog updates since the old OID doesn't need to match the reference's current state. However, this removes useful information about whether the caller provided an old OID at all. The patch preserves this signal by keeping `REF_HAVE_OLD` set while skipping old-OID verification for log-only updates. This prepares for a subsequent change that will use the flag to validate provided OIDs in reflog entries.

The changes touch core refs handling code across multiple backends (files and reftable), modifying the flag checks to explicitly skip verification for log-only updates while maintaining all other safety checks. The patch appears well-contained and builds logically on the series' previous work, though readers should be aware it's part of a larger effort to improve reflog handling during storage format migrations.
