Part of the `the_repository` removal effort, this patch eliminates the global `merge_log_config` variable used by `git merge` and `git fmt-merge-msg` to control shortlog output length. Ayush Chandekar moves this configuration handling into a new `adjust_shortlog_len()` function in fmt-merge-msg.c, keeping the logic closer to where it's actually used.

The change removes the variable from environment.c and updates both commands to use the new function instead. The implementation checks both "merge.log" and "merge.summary" configs (the latter being a deprecated alias) to determine the shortlog length, maintaining backward compatibility. A negative length check is preserved to catch invalid configurations.

This appears to be a clean, focused refactoring that advances the libification effort by reducing global state. The patch is part of a 2-patch series (with the second patch addressing `the_repository` usage directly) and carries mentorship tags from Christian Couder and Ghanshyam Thakkar, suggesting it's a GSOC project. The changes are straightforward and maintain existing behavior while improving code organization.
