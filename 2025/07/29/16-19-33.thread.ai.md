This thread contains a 2-patch series by René Scharfe as part of the ongoing `the_repository` removal effort, focusing on the `fmt-merge-msg` builtin and related merge configuration. The series systematically removes two global state dependencies in the merge message formatting code.

Patch 1 removed the global `merge_log_config` variable from environment.c, moving its functionality into a new `adjust_shortlog_len()` function in fmt-merge-msg.{c,h} that handles "merge.log" and "merge.summary" configuration lookup when `shortlog_len` is negative. The change maintained all behavior (DEFAULT_MERGE_LOG_LEN=20 when config is true, config value when numeric, or 0 when unset/negative) while updating callers in builtin/fmt-merge-msg.c and builtin/merge.c.

Patch 2 completes the work by removing the remaining `the_repository` dependency from builtin/fmt-merge-msg.c through several mechanical but precise changes: eliminating the `USE_THE_REPOSITORY_VARIABLE` define, converting `the_repository` references to use passed `repo` parameters, switching from `git_config()` to `repo_config()` for configuration lookup, and updating the `adjust_shortlog_len()` call to use the passed repository. The patch adds a test verifying `git fmt-merge-msg -h` works outside a repository (demonstrating help text doesn't need repo access), matching the pattern used for other commands.

Junio Hamano has reviewed Patch 2 and identified a subtle but important issue with the patch's reordering of configuration parsing. While the technical changes to remove `the_repository` usage are correct (converting to `repo_config()` and updating `adjust_shortlog_len()`), the patch moves config parsing after `parse_options()`, which violates the standard pattern of reading config first then letting command-line options override those values. The commit message doesn't explain this ordering change, making it appear unintentional. This needs addressing before proceeding - either justifying the change or restoring the original order while keeping the `the_repository` removal.

The series is a clean, well-scoped example of the `the_repository` removal effort - each patch tackles one specific global dependency while maintaining all functionality and adding appropriate test coverage. The changes touch environment.c, fmt-merge-msg.{c,h}, builtin/fmt-merge-msg.c, and the test suite. Junio's review highlights how even mechanical `the_repository` removals require careful consideration of surrounding code patterns. The config/options ordering issue is now the key open question needing resolution.
