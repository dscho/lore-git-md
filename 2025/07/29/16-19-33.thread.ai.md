Thread summary update:

This thread contains René Scharfe's 2-patch series removing `the_repository` usage from the `fmt-merge-msg` builtin, part of the ongoing global state elimination effort. The series modifies merge message formatting configuration handling while maintaining functionality.

Patch 1 introduced `adjust_shortlog_len()` to replace the global `merge_log_config`, changing behavior when invalid `merge.summary` values are overridden by `--log` (now silently ignored vs previous error reporting). Junio Hamano questioned if this was intentional, with Ayush Chandekar joining the discussion on silent behavior acceptability. Phillip Wood subsequently identified a more serious issue: the new implementation breaks Git's config precedence rules by always preferring `merge.log` over `merge.summary`, whereas the original processed values in order (last one wins). This affects core configuration semantics beyond just error reporting.

Patch 2 mechanically converts `the_repository` usage to explicit `repo` parameters but was flagged by Junio for incorrectly reordering config parsing after `parse_options()`, violating Git's standard pattern where command-line options override config. Both patches now have unresolved issues: (1) whether to restore config validation and precedence behavior while keeping the refactoring, and (2) whether to revert the config/option parsing order while maintaining `the_repository` removal.

Technical scope includes `fmt-merge-msg.{c,h}`, `builtin/fmt-merge-msg.c`, and tests. Key changes are the new `adjust_shortlog_len()` function and `repo_config()` adoption. The discussion highlights how mechanical refactoring must carefully preserve both behavior and Git's configuration philosophy, particularly around validation of overridden values and precedence rules. Junio's conservative stance on behavior changes remains a guiding principle, with Phillip's input adding technical depth about config processing semantics. The series now requires adjustments to address both the validation reporting and config precedence issues while achieving its original goal.
