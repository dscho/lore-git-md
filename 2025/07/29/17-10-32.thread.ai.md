[PATCH] git-send-email: add SMTP autoconfiguration via --get-smtp-server

This patch series introduces SMTP server autodiscovery for git send-email, implementing a feature that automatically determines SMTP settings for a given email address. The implementation follows Thunderbird's autoconfig protocol with three fallback methods: querying Mozilla's ISPDB, checking the email provider's autoconfig endpoint, and falling back to MX record lookup for custom domains.

The technical implementation adds 153 lines to git-send-email.perl and 55 lines of documentation, introducing new helper functions (fetch_config_mozilla_ispdb, fetch_config_domain_autoconfig, get_mx_base_domain) and requiring additional Perl modules (Net::DNS, URI::Escape, XML::LibXML). The author has already prepared a v2 iteration (accidentally sent as a new thread) indicating active development, likely addressing the key open questions from v1 review: Perl module dependency concerns and whether to more tightly integrate the autoconfig behavior with the main send-email flow rather than keeping it as a separate --get-smtp-server mode.

The current implementation presents the feature as a standalone configuration discovery tool that outputs detected settings without automatically applying them, mapping discovered settings to Git's existing sendemail.* configuration options (smtpServer, smtpServerPort, etc.). The v2 iteration suggests the author is working on feedback about module dependencies and integration approach, though the exact changes are not yet visible in this thread. The technical approach remains consistent with Thunderbird's autoconfig protocol, documented with links to Thunderbird's implementation details.
