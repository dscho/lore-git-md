This is a preparatory refactoring patch in a 3-part series introducing `--max-depth` functionality to Git's diff machinery. The patch addresses a minor memory initialization issue in the combine-diff code path.

The change switches from using `xmalloc()` to `CALLOC_ARRAY()` when allocating `diff_filepair` structs in `combined_pair()`, ensuring all fields are zero-initialized. This matches the behavior of the regular diff code and prevents potential issues from uninitialized fields like `rename_score` or `broken_pair` flags that aren't meaningfully set in this context.

The original author (Jeff King) notes that while setting a new `DIFF_STATUS_COMBINED` flag might make sense for these special filepairs, the patch conservatively leaves the status as zero since the proper semantics aren't yet clear. This is a straightforward cleanup that improves consistency and safety in the diff infrastructure, serving as groundwork for the subsequent `--max-depth` feature patches.

Key technical details:
- Touches `combine-diff.c`
- Changes allocation method for `struct diff_filepair`
- Maintains existing behavior while preventing undefined values
- Part of preparatory work for diff depth-limiting feature
