This is a follow-up discussion in the ongoing thread about Git's alias handling with `-h` flags, focusing on implementation philosophy and edge cases. Jeff King (Peff) responds to D. Ben Knoble's concerns about whether special handling of `-h` in aliases violates Git's textual substitution model.

Peff clarifies that while aliases are fundamentally textual replacements, `-h` is already special-cased in Git's help system. He defends the idea that `git foo -h` should consistently show help for alias `foo` rather than executing the underlying command, even if that means dropping alias-injected arguments. The discussion reveals tension between pure textual substitution and practical UX considerations for help behavior.

Key technical points include: 1) The current behavior already treats `git foo -h` as help when `foo` is an alias, 2) Third-party commands violating the `-h`-as-help convention would be problematic but rare, 3) The proposed `--help-all` work (from Knoble) might benefit from similar pre-repo checks as `-h` but doesn't need the same alias-specific handling.

The exchange highlights the broader challenge of balancing Git's design principles against user expectations, with Peff leaning toward pragmatic solutions while acknowledging the philosophical concerns. This follows Junio Hamano's earlier guidance favoring simple, consistent behavior over complex case-specific logic. The thread appears to be converging on treating `-h` as a special case that shows alias expansion without execution, regardless of alias type.
