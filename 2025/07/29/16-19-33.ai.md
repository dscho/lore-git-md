This is a cover letter for a 2-patch series that's part of the ongoing `the_repository` removal effort, specifically targeting the `fmt-merge-msg` builtin. The series aims to eliminate two dependencies on global state: the `merge_log_config` variable and the `the_repository` global.

The first patch removes the global `merge_log_config` variable from environment.c, replacing its functionality with a new `adjust_shortlog_len()` function in fmt-merge-msg.{c,h}. This appears to be a straightforward refactoring that moves configuration handling closer to where it's actually used.

The second patch removes `the_repository` usage from builtin/fmt-merge-msg.c, allowing the removal of the `USE_THE_REPOSITORY_VARIABLE` define. It also adds a test case verifying that `git fmt-merge-msg -h` works with a NULL repository, suggesting the command's help text doesn't need repository access. The changes touch several files including the merge machinery and add a new test case.

The series appears well-scoped and focused on the specific goal of removing global state dependencies. The cover letter clearly explains the motivation and approach, though it doesn't discuss why these particular globals were chosen or whether there are remaining globals to address in this area. The test addition suggests attention to maintaining functionality while making these changes.
