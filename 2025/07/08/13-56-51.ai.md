This is the first patch in a two-part series to deprecate and remove the `core.commentChar=auto` configuration option, following up on the thread summary's context. The patch focuses on documentation updates and implementation groundwork for the deprecation.

The commit message thoroughly explains why `auto` mode is problematic, listing specific scenarios where it fails: with commit templates containing comments, prepare-commit-msg hooks that add comments, and commands like rebase's fixup/squash that rely on comment parsing. The design limitations make these issues fundamentally hard to fix, justifying deprecation.

Technically, the patch:
1. Adds a BreakingChanges.adoc entry announcing the deprecation
2. Updates core.adoc documentation with detailed limitations
3. Guards all auto-commentchar functionality behind `WITH_BREAKING_CHANGES` ifdefs
4. Marks affected tests with `!WITH_BREAKING_CHANGES` conditions

The changes span config handling (config.c), commit message processing (builtin/commit.c), and test adjustments (t3404, t7502). The implementation takes a conservative approach by keeping the code but disabling it through compilation flags, making the actual removal in Git 3.0 a straightforward deletion of the guarded blocks.

This appears to be a well-justified deprecation with clear technical reasoning and thorough documentation of the migration impact. The patch maintains backward compatibility while clearly signaling the future removal path.
