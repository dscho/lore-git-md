This is a feature patch series introducing a new `git sparse-checkout clean` command to help maintain sparse-checkout performance. The series comes from Derrick Stolee and addresses a pain point in cone-mode sparse-checkouts where leftover "out of scope" directories can cause significant performance degradation with sparse indexes.

The core problem occurs when tracked directories outside the sparse specification remain on disk, forcing Git to expand the entire index - an expensive operation. While recent advice warned users about this situation, it didn't provide clear guidance on resolution. The new `clean` command specifically targets these problematic directories without affecting other ignored files within the sparse-checkout area.

The implementation includes a dry-run mode and focuses only on cone-mode sparse-checkouts for now. Stolee notes considering alternative approaches like augmenting existing commands but settled on this dedicated interface as the clearest solution. The series also includes preparatory refactoring to remove `the_repository` usage and updates the sparse-index advice to point users to the new command.

This appears well-motivated with clear performance benefits for sparse-checkout users, particularly those working with large repositories. The commit messages thoroughly explain the problem space and design decisions, suggesting careful consideration of the solution. The accompanying test additions indicate good test coverage for the new functionality.
