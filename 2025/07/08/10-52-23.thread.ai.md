Sahil Gautam proposes storing issue tracking data natively in Git through private branches, motivated by wanting independence from hosting provider implementations (specifically mentioning moving to Gitea and referencing Gitea issue #34993). The idea would involve Git core supporting storage of issues, comments, and project management data directly in the repository rather than external databases. No implementation details or patches are provided - this is an initial exploration of whether such functionality belongs in Git core versus being an external tool. Key considerations would be the impact on Git's data model and performance characteristics. The proposal seeks community feedback on the general concept before any technical design work.
