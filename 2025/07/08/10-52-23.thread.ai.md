Thread summary:

Sahil Gautam proposes storing issue tracking data natively in Git through private branches, seeking independence from hosting provider implementations (referencing Gitea issue #34993). The proposal explores whether Git core should support storing issues, comments, and project management data directly in repositories rather than external databases, without providing implementation details.

Junio Hamano responds with skepticism about implementing this in Git core, while acknowledging the valid concern about vendor lock-in for project metadata. He suggests the solution lies in standardization between hosting providers through an open interchange format, enabling both migration between providers and potential federated workflows. Hamano positions this as a social/standards challenge better solved at the ecosystem level rather than requiring Git core changes. The response indicates no technical objections but clearly marks this functionality as outside Git's current scope. The thread remains open with no clear resolution, presenting two approaches: Git-native storage versus standardized external formats.
