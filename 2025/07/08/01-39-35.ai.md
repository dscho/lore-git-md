This is a technical follow-up in the Meson build system series, specifically addressing the CI test parallelization issue from patch 8. Jeff King provides two alternative solutions to the problem where Meson rejected GitHub Actions' 0-based matrix numbering for test slices.

The first proposed solution changes the matrix numbering from [0..9] to [1..10], which would make the slice indices 1-based as Meson requires, though it would cause job titles to no longer match non-Meson test runs. The second, more minimal solution keeps the original 0-9 numbering but uses PowerShell arithmetic to add 1 when passing the slice argument, with proper quoting to avoid argument splitting.

Key technical details:
- The fix targets `.github/workflows/main.yml`
- The issue stems from Meson requiring 1-based slice indices while GitHub Actions uses 0-based numbering
- PowerShell syntax quirks require careful quoting of arithmetic expressions
- The solution preserves the existing 10-way parallel test slicing
