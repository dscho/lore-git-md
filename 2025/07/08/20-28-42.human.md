This is a test-related follow-up to the recent security release. Todd Zullinger reports two failing tests when building Git v2.45.4 on an older system, both involving CR (carriage return) handling in config operations. The failures occur because the tests use newer `git config` subcommands (`set`, `get`, `unset`) that aren't available in these older releases.

The proposed fix converts the tests to use the older syntax (`config --get` instead of `config get`, etc.), which should make them pass while maintaining the same test coverage for CR handling. This appears to be a straightforward test modernization issue rather than a security concern, though it's related to the broader CRLF fixes in the security release.

Zullinger notes he hasn't investigated exactly when the syntax changed, but provides the test fixes in case others encounter the same issue or want to backport them to older maintenance branches. The changes look correct at a glance, though they would need verification on the affected versions.
