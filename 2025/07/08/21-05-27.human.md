This is a test infrastructure patch addressing a compatibility issue discovered during the security release testing. Todd Zullinger found that recent security fixes introduced new `git config` subcommands (`get`, `set`, `unset`) that aren't available in older Git versions (pre-2.46). This caused test failures in the v2.45.4 builds.

The patch reverts two test files (`t1300-config.sh` and `t7450-bad-git-dotfiles.sh`) to use the older `--get` and `--unset` syntax instead of the newer subcommands. The changes are minimal and focused, just replacing the problematic syntax while maintaining the same test functionality. Zullinger has verified the changes work with versions 2.43 through 2.45 and set up CI testing via GitHub Actions.

This isn't a security fix itself, but rather ensures the security updates can be properly tested across all supported versions. The patch appears straightforward and well-tested, addressing a clear compatibility issue that could affect backporting workflows.
