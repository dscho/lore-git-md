This is a follow-up in the ongoing signature handling improvements for `fast-export`/`fast-import`, specifically addressing test improvements for the v5 patch series. Christian Couder responds to Junio Hamano's feedback about making test assertions more precise regarding hash algorithm expectations.

The email confirms that v5 will use `$GIT_DEFAULT_HASH` in test assertions to explicitly check for the expected hash algorithm (SHA-1 or SHA-256) rather than the more permissive "1 or 256" check from v4. However, Christian pushes back slightly on Junio's suggestion to also verify the absence of the other hash algorithm, considering it unnecessary overhead.

More significantly, v5 will include a test case for commits with both SHA-1 and SHA-256 signatures - a previously missing test scenario that Junio had highlighted. The test will verify that both signature types are properly handled, addressing a key gap in the test suite.

This email shows the patch series progressing through the review cycle, with Christian incorporating specific technical feedback about test precision while making judgment calls about which suggestions to implement. The discussion remains focused on the test infrastructure aspects rather than reopening the broader design debates about signature handling that were prominent earlier in the thread. The response indicates steady forward motion on the technical implementation following Junio's earlier concerns about stagnation in the development process.
