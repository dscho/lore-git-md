Documentation patch correcting an inaccuracy in gitglossary(7) about glob pathspec behavior. Russell Hanneken fixes a subtle but important documentation error where the glossary incorrectly claimed that "**/foo" and "foo" were equivalent patterns in glob pathspecs. In reality, while "**/foo" matches "foo" anywhere in the directory tree, the plain "foo" pattern does not have this same behavior.

The patch is minimal and focused, removing just the incorrect equivalence claim while preserving the rest of the surrounding documentation about glob pathspec syntax. The commit message clearly explains the nature of the error and its likely origin (a copy-paste from gitignore documentation where the equivalence does hold true).

This appears to be a straightforward and well-justified documentation correction. The change is small and uncontroversial, touching only glossary-content.adoc to fix the misleading statement without affecting any actual Git behavior. The patch seems ready for inclusion with no obvious issues.
