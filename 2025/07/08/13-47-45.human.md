This is the final version of a feature series adding pagination support to `git for-each-ref` via a new `--start-after` option. The series has gone through three iterations with extensive discussion about naming and behavior, now reaching consensus on all aspects.

The patch enables efficient pagination in large repositories by allowing iteration to start after a specified reference marker, skipping earlier refs. The implementation works across all ref backends (files, packed, reftable) with O(log N) performance. Key points:

- The option was renamed from `--skip-until` to `--start-after` after discussion clarified it should unambiguously indicate exclusion of the marker ref
- Output shows only refs lexicographically after the marker, handling concurrent modifications by maintaining consistent seeking position
- Pagination is mutually exclusive with custom sorting, as seeking happens before sorting
- Comprehensive test coverage verifies edge cases like partial matches and directory boundaries

The series is now fully ready for merging, having addressed all technical and UX concerns through iterative refinement. The implementation is cleanly separated across 4 patches that expose needed iterator infrastructure, clean up unused code, refactor seeking behavior, and finally add the user-facing option.
