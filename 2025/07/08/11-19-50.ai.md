This is a feature patch series introducing a new `sparse-checkout clean` command to address performance issues with leftover sparse directories in cone mode. The series also includes some refactoring to remove `the_repository` usage.

The core problem being solved occurs when sparse directories remain on disk despite being outside the current sparse-checkout scope, often due to ignored files or filesystem locks. These leftovers force expensive full index expansions when using sparse index, significantly impacting performance. While previous advice warned users about this situation, it didn't provide a complete solution.

The new `git sparse-checkout clean` command specifically targets cone-mode sparse-checkouts by:
1. Collapsing the index to be as sparse as possible
2. Removing any sparse directories that shouldn't exist
3. Listing affected directories (with --dry-run available)

The implementation touches documentation, the sparse-checkout builtin (with significant refactoring to remove `the_repository`), and sparse-index.c. The series includes tests in t1091 and updates the advice message to point users to the new command.

Key technical details:
- Operates only in cone mode
- More precise than `git clean -dfx` as it preserves excluded files within sparse-checkout
- Outputs directories that would be/were removed
- Future extensions could add --quiet/--verbose options

The author considered alternative approaches like augmenting `reapply` or adding a `--sparse` flag to `git clean` before settling on this dedicated command. The implementation appears thorough with test coverage and documentation updates.
