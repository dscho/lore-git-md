Junio's latest "What's cooking" report outlines the major changes being prepared for Git 3.0, with several significant infrastructure updates in progress. The reftable backend (Patrick Steinhardt) and SHA-256 default mode (brian m. carlson) are the headline changes, alongside performance improvements to fetch/prune operations and Taylor Blau's cruft pack optimizations that have been tested in production at GitHub.

The SIGCHLD handling series by Carlo Marcelo Arenas Belón, which aims to standardize signal behavior across platforms, has drawn new technical feedback. Johannes Sixt, a Windows porting expert, points out that the Windows/MinGW environment fundamentally lacks proper POSIX signal support, making some of the proposed changes irrelevant or misleading for that platform. He specifically questions the focus on signal numbers (17 vs 22) since code should use symbolic names, and notes that Windows' limited signal emulation behaves differently than true POSIX signals. This complicates the platform compatibility work, particularly around patch 2's signal number handling.

Meanwhile, several other topics are progressing well - René Scharfe's parse-options refactoring is nearly ready for merging (awaiting a final version), while various `the_repository` removal patches and documentation updates have already graduated to 'master'. The report shows Git 3.0 shaping up with both major infrastructure changes and important platform-specific fixes, though some like the SIGCHLD work now face new platform-specific considerations that may require design adjustments.
