This is a feature proposal email discussing the idea of storing issue tracking data in Git itself rather than relying on external databases from hosting providers like GitHub or Gitea.

The author, Sahil Gautam, explains their motivation for moving from GitHub to Gitea - wanting more control over their development workflow and avoiding sudden UI/feature changes imposed by large companies. They propose that Git could natively support storing issues, comments, and project management data in separate private branches, making this data independent of any specific hosting provider.

The email references a discussion with Gitea developers where it was noted that current implementations are database-based. The author is floating the idea of Git core potentially supporting this functionality directly. No specific implementation details or patches are provided - this appears to be an initial exploration of the concept to gauge interest from the Git community.

- Proposal to store issue tracking data in Git branches
