This is a documentation patch addressing the `git stash` message handling behavior that was discussed in the thread. Junio C Hamano provides historical context and rationale for the current behavior where custom messages in `git stash create` appear in commit objects but not in reflog entries (which show a generic message). He traces this back to stash's original purpose as a quick context-switching tool where detailed messages weren't a priority.

The patch clarifies several documentation points:
1. Explicitly states which commands accept descriptive messages (`push`, `save`, `store`)
2. Updates the `list` subcommand description to properly attribute messages to their source commands
3. Adds a clearer warning about `create` being primarily for internal/script use
4. Explains that `create`'s message argument is meant for internal consumption by other stash commands

The changes aim to better document the existing behavior rather than change it, aligning with the thread's discussion about whether to treat this as a documentation issue versus an implementation one. The patch is thorough in addressing the immediate confusion while preserving backward compatibility.
