This is a documentation patch updating the `git-pack-refs` man page to reflect the current behavior of the `--auto` flag with the "files" backend. 

The patch corrects outdated documentation that claimed the "files" backend had no special handling for `--auto`. In reality, since commit c3459ae9ef2 (September 2024), the files backend uses a heuristic based on the ratio of loose references to the size of the packed-refs file to determine when repacking is needed. The larger the packed-refs file, the more loose references must exist before triggering a repack.

The change is straightforward and well-justified, fixing a discrepancy between documented and actual behavior. The commit message clearly explains both the historical context (originally only reftable had heuristics) and the current state. The patch was prompted by a report from Karthik Nayak and maintains Git's usual high standard for documentation accuracy.

This is a small but useful improvement that helps users understand when automatic reference packing will occur with the traditional files backend. The change aligns with Git's principle of transparently documenting implementation details that affect user experience.
