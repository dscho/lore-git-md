Junio Hamano responds to Sahil Gautam's proposal about storing issue tracking data natively in Git. This is a conceptual discussion about whether Git should support project metadata like issues and comments directly in its data model.

Hamano acknowledges the real concern about hosting providers locking in project metadata, making migration difficult. However, he suggests an alternative approach: encouraging hosting providers to standardize on an open, interchangeable format for this metadata rather than building it into Git itself. This could enable not just migration between providers but even federated operations where different sites interact with the same metadata.

The response indicates skepticism about expanding Git's core functionality to include issue tracking, instead favoring an ecosystem solution. Hamano doesn't outright reject the idea but points toward a different direction that would address the same underlying concern about vendor lock-in. The discussion remains at a high level without diving into technical implementation details.
