Refactoring patch for the ref iterator interface, part 3/4 in the pagination series. This patch clarifies the behavior of `ref_iterator_seek()` by introducing a flag to distinguish between seeking to a position (like `fseek()`) versus setting an iteration prefix. The new `REF_ITERATOR_SEEK_SET_PREFIX` flag makes the dual-purpose nature of the function explicit while maintaining backward compatibility.

The changes touch all ref backends (files, packed, reftable) with the most complex modifications in the files backend's ref-cache implementation. The patch cleanly separates the prefix-setting logic into a new `cache_ref_iterator_set_prefix()` helper while preserving the existing behavior when the new flag is set. This prepares the ground for the final pagination patch while improving the API's clarity.

The implementation appears thorough, with clear commit message explaining both the motivation and technical approach. As part of an already well-reviewed series that has reached consensus on naming and design, this refactoring looks ready to proceed.
