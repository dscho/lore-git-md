Subject: Coordinated security release for Git versions v2.43.7 through v2.50.1 addressing seven CVEs. Core issues involve Gitk, Git GUI, and core Git functionality with potential for arbitrary code execution, file manipulation, and protocol injection attacks.

Key vulnerabilities fixed:
- Gitk: CVE-2025-27613 (file creation/truncation) and CVE-2025-27614 (arbitrary command execution) via malicious repositories
- Git GUI (Windows): CVE-2025-46334 (malicious executables) and CVE-2025-46835 (file overwrites)
- Core Git: CVE-2025-48384 (CRLF handling in config/submodules), CVE-2025-48385 (bundle URI validation), CVE-2025-48386 (wincred buffer overflow)

Primary contributors: Johannes Sixt (27 commits) and Mark Levedahl (13 commits) focused on Gitk/Git GUI argument sanitization and Windows path handling. Justin Tobler fixed config CR quoting while Patrick Steinhardt addressed bundle-uri validation. The fixes demonstrate comprehensive attention to argument sanitization, path handling, and protocol validation across components.

Impact: Critical security update affecting all listed versions, with particularly severe implications for Windows users and Gitk/Git GUI users. The coordinated multi-version release indicates wide-ranging production impact. Detailed vulnerability descriptions and attack vectors are included in the release notes.

Additional issue reported by Todd Zullinger during security release testing: test failures in v2.45.4 builds on older systems due to config syntax changes. Affected tests are `t1300.237` (CR handling) and `t7450.50` (submodule directories), which use newer `git config` subcommands not available in older versions. Zullinger provides backward-compatible syntax replacements (`--get`/`--unset` instead of subcommands) for test compatibility. This is a test infrastructure issue rather than a security vulnerability but affects backporting workflows. The exact timeline of the syntax change remains to be investigated.
