This is a follow-up in the Meson build system CI optimization thread. Jeff King (peff) responds to Junio Hamano's report of test failures when using Meson's `--slice` option for parallel test execution in CI. The issue stems from the slice numbering - Meson expects positive integers starting from 1, but the CI matrix was using 0-based numbering (0-9). Jeff proposes a simple fix to change the matrix numbering to 1-10 in `.github/workflows/main.yml`.

This appears to be a straightforward correction to align with Meson's expectations, though it's unclear if this fully resolves the test failures Junio observed. The fix maintains the same parallelization approach (10 slices) while conforming to Meson's argument requirements. This is the last remaining issue in Patrick Steinhardt's otherwise solid Meson build system improvement series.
