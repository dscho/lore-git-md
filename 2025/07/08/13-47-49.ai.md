Feature implementation completing the `git for-each-ref` pagination series. This final patch introduces the user-facing `--start-after` option, building on the ref iterator seeking capability added in previous patches. The option enables efficient O(log N) pagination by starting iteration from a specified reference marker, with comprehensive edge case handling and test coverage.

Key technical aspects:
- New `start_ref_iterator_after()` helper seeks to next reference by incrementing marker's last character
- Documents concurrent modification behavior (only refs lexicographically after marker are shown)
- Forbids combining with patterns or custom sort options (enforced via die() calls)
- Handles all ref types (branches, tags, remotes) through unified codepath
- Extensive test suite (t6302) verifies:
  - Empty/partial/overflow marker cases
  - Directory boundary conditions
  - Pattern/sort option conflicts
  - End-of-list behavior

The implementation leverages the refactored seeking infrastructure from patch 3, completing the pagination feature with all technical aspects settled per thread discussion. The series has reached consensus on naming (`--start-after`), behavior under concurrent modifications, and error messaging, making this ready for merge.
