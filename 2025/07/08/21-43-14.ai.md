This is a feature addition to the sparse-checkout subsystem, introducing a new `clean` subcommand to remove tracked-but-sparse directories outside the current sparse-checkout scope. The command specifically targets cone mode and aims to improve sparse index performance by eliminating directories that would otherwise cause unwanted index expansions.

Elijah Newren's review raises several technical concerns about edge cases and safety. Key points include:
- Questions about behavior in non-cone mode and without sparse index enabled
- Safety concerns around removing files during merge/rebase conflicts
- Clarification needed on handling of untracked directories
- Potential need for more granular output than just directory names
- Whether staged changes should truly prevent directory removal
- Suggestion to improve error messages when sparse conversion fails

The implementation currently:
- Requires cone mode and sparse-checkout to be active
- Uses in-memory sparse index conversion (SPARSE_INDEX_MEMORY_ONLY)
- Scans for and removes S_ISSPARSEDIR entries that exist on disk
- Preserves directories with staged changes
- Includes --dry-run option
- Has basic test coverage for simple cases and staged changes

The review suggests the command may need additional safeguards and documentation around edge cases, particularly regarding file states during merges and the treatment of untracked content. The interaction between this command and ongoing repository operations appears to be a key area needing clarification before finalization.
