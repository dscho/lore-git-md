Feature implementation for `git for-each-ref` pagination, now with finalized `--start-after` option naming. This is the cover letter for the third version of a series adding pagination support to `git for-each-ref`. The implementation provides O(log N) seeking across all ref backends (files, packed, reftable) by leveraging sorted reference iteration. The key change in v3 is the renaming of the option from `--skip-until` to `--start-after` to better reflect the exclusion semantics, following mailing list discussion where Junio C Hamano and others analyzed the naming implications.

The series consists of 4 patches: ref iterator interface exposure, ref-cache cleanup, flags-based seek implementation, and the user-facing pagination option. The implementation handles edge cases like concurrent modifications (where references may change between pagination calls) by maintaining consistent lexicographic positioning. The documentation now explicitly notes this behavior and the option cannot be combined with custom sorting or pattern matching.

Technical highlights include:
- New `start_ref_iterator_after()` helper that seeks to next reference by incrementing the marker
- Comprehensive test coverage in t6302-for-each-ref-filter.sh
- Error message fix for the `--sort` restriction (now says "with custom sort options")
- Backend-specific handling for files, packed, and reftable formats
- Maintained separation between seeking and prefix filtering in the API

The thread shows consensus on all technical aspects, with the naming discussion settled on `--start-after` as it most precisely conveys the exclusion of the seek target. The series is now ready for merging with all review feedback addressed.
