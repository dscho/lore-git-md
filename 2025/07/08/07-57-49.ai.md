CI/build system optimization patch completing Patrick Steinhardt's Meson build system improvement series. This final patch (8/8) replaces complex PowerShell test-slicing logic in GitHub Actions and GitLab CI with Meson's new native `--slice` option, introduced in Meson 1.8. The change simplifies parallel test execution by using Meson's built-in slicing capability rather than manual PowerShell arithmetic to distribute tests across jobs.

The patch modifies two key CI configuration files: `.github/workflows/main.yml` and `.gitlab-ci.yml`. The changes replace multi-line PowerShell pipelines that previously handled test distribution with single-line `--slice` invocations. For GitHub Actions, it uses `$(1+${{ matrix.nr }})/10` syntax to maintain compatibility with the existing 10-way parallelization, while GitLab CI uses `$Env:CI_NODE_INDEX/$Env:CI_NODE_TOTAL` to match GitLab's parallel job numbering.

This builds on earlier work in the series that addressed Meson build system correctness and performance, particularly for Windows testing. The patch leverages Meson 1.8.2, now available on both CI platforms, to provide a more maintainable solution for test parallelization. The change appears straightforward and well-tested, completing the series' goal of modernizing Git's build infrastructure.
