This is a cover letter for a breaking change proposal targeting the `core.commentChar` configuration. Phillip Wood proposes deprecating and eventually removing support for `core.commentChar=auto`, which automatically selects a comment character by analyzing commit messages. The feature has been problematic, with recent bug reports showing it can cause issues when the auto-selected character appears in commit message content.

The series consists of two patches: the first documents the deprecation in BreakingChanges.adoc and updates the core.commentChar documentation, while the second implements the deprecation warning system. When users have `core.commentChar=auto` set, Git will print detailed advice showing how to either unset the configuration (falling back to the default '#') or explicitly set a custom comment character.

The implementation touches several areas: documentation files, commit.c (where the interactive commit message handling lives), config handling code, and test updates. The warning message includes specific git config commands to help users migrate their configuration. Test coverage appears thorough, with updates to existing tests for interactive rebase and commit porcelain.

This change follows up on previous discussion (linked in references) about the feature's design flaws and maintenance burden. The approach is conservative - first deprecating with clear migration instructions before eventual removal. The patch series is well-structured with clear commit messages and references to prior discussions.
