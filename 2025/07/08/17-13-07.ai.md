This is a documentation patch that follows up on the `git stash` message handling discussion. Junio C Hamano responds to Jeff King's suggestion about improving the ergonomics of `git stash store` for script writers by considering having it pull the default message from the commit rather than using a generic one. 

The email acknowledges that while interactive users are discouraged from using the `create`/`store` combination, script writers who use `create` to craft detailed log messages (potentially for later reuse in actual commits) would currently get an unpleasant experience with large stash entries if they use `store` without a custom message. This suggests the current behavior could be suboptimal for scripting use cases, though the email stops short of proposing a concrete implementation change.

The discussion continues the thread's focus on balancing backward compatibility with better documentation and potential improvements for script users, while maintaining the historical separation between commit messages and reflog messages in the stash implementation. The technical context remains the split between `create_stash()` (handling commit messages) and `do_store_stash()` (handling reflog messages) in `stash.c`.
