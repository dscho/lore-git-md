This thread continues development of the `git sparse-checkout clean` feature, which removes tracked-but-sparse directories outside the sparse-checkout scope while preserving untracked files. The current v3 series combines Victoria Dye's original concept with Derrick Stolee's refactoring to eliminate `the_repository` global state dependencies.

The latest patch from Stolee expands test coverage for merge conflict scenarios, replacing a simpler test with a more comprehensive case. It demonstrates that files involved in a merge conflict (with SKIP_WORKTREE bits set) cannot currently be cleaned, even with the `-f` force option, due to implementation limitations around sparse index conversion during merges. The test maintains the series' focus on safety by verifying this protection remains in place.

Key developments in the thread include:
- Core functionality for targeted cleaning of sparse directories
- Safety mechanisms matching `git clean` behavior (force/dry-run requirements)
- Complete removal of `the_repository` usage in sparse-checkout code
- Comprehensive test coverage, now expanded to include merge conflicts
- Clear documentation of current limitations around SKIP_WORKTREE bit handling

The series has evolved through multiple iterations with input from Elijah Newren (who identified edge cases) and Junio Hamano. While some functionality around merge conflicts remains deferred, the current version represents a stable implementation that addresses the core use case while maintaining robust safety checks.
