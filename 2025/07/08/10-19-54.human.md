This is a bugfix for the files ref backend that cleans up empty directories left behind after failed reference creation.

Patrick Steinhardt noticed that when creating a new reference in the files backend, Git creates the parent directories first, but if the transaction fails or is aborted, those empty directories remain. While not a critical issue, it can lead to clutter in the refs directory over time. The patch fixes this by calling the existing `try_remove_empty_parents()` function during transaction rollback.

The change is straightforward - it adds the directory cleanup call in `files_transaction_cleanup()`, which handles both explicit aborts and implicit cleanup cases. The patch includes two new test cases that verify empty directories are properly pruned in both abort and non-commit scenarios. 

This appears to be a well-contained change with clear motivation and proper test coverage. It addresses a minor but real issue that was discovered in Gitaly (GitLab's Git storage service). The fix aligns with Git's general principle of keeping the repository in a clean state.
