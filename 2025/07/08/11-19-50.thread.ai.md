This is a new patch series introducing `git sparse-checkout clean` to handle leftover sparse directories in cone mode, addressing performance issues from unwanted full index expansions. Authored by Victoria Dye, the series targets sparse-checkout and sparse-index subsystems.

The core problem involves sparse directories persisting on disk outside the sparse-checkout scope (due to ignored files/locks), forcing expensive full index expansions. While previous advice warned about this, there was no complete solution. The new command specifically handles cone mode by:
- Collapsing the index to be maximally sparse
- Removing sparse directories that shouldn't exist
- Listing affected directories (with --dry-run)

Technical implementation:
- Only works in cone mode
- More precise than `git clean -dfx` (preserves excluded files within sparse-checkout)
- Outputs removed/would-be-removed directories
- Future options could include --quiet/--verbose
- Touches documentation, sparse-checkout builtin (with `the_repository` removal refactoring), and sparse-index.c
- Test coverage in t1091
- Updates advice message to reference new command

Alternatives considered but rejected:
- Augmenting `reapply`
- Adding `--sparse` flag to `git clean`

The series appears thorough with documentation and test coverage. This addresses a known pain point in sparse-checkout performance by providing a dedicated solution rather than workarounds.
