This thread documents the completion and merging of Phillip Wood's series removing the `core.commentChar=auto` configuration option, a breaking change that will take effect in Git 3.0. The feature's heuristic for selecting comment characters had caused problems in commit templates, hooks, and rebase operations. The three-part series provides a simple removal but includes sophisticated migration assistance - when users encounter the deprecated setting, Git detects where it appears in config files and offers tailored advice for either unsetting it or choosing a specific character. The implementation avoids spamming users by only showing warnings once per command.

The technical work includes new infrastructure in `config.c` for deprecation detection, environment variable tracking, and dual behavior via a compilation flag. Test coverage in t3404 and t7502 verifies the changes. The series was rebased against ongoing repository refactoring work (`ps/config-wo-the-repository` branch) before merging. 

While Oswald Buddenhagen argued for a simpler approach, maintainer Junio C Hamano approved the final balance between user assistance and implementation complexity. The solution provides a reference for future configuration deprecations, particularly around migration advice granularity and read-only config handling. With all discussion points resolved and the series now merged, this thread serves as documentation of both the technical change and the project's approach to breaking changes.
