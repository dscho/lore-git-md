This thread discusses the deprecation and planned removal of Git's problematic `core.commentChar=auto` configuration option, which handles comment character selection in interactive workflows like commits and rebases. Phillip Wood's two-part series lays the groundwork for removal in Git 3.0, with comprehensive deprecation warnings and documentation updates. The implementation detects affected configurations across all scopes and generates precise migration instructions.

Junio C Hamano, the Git maintainer, has now provided feedback focusing on improving the user experience. While not challenging the deprecation itself, he suggests alternative approaches to the warning messages and post-removal behavior. Key suggestions include using shell loops to clear configurations more thoroughly, avoiding over-recommending `--global` settings that might not suit all contexts, and considering simpler post-removal behavior where "auto" would simply mean using "#" rather than dying. These refinements aim to make the transition smoother while still achieving the goal of removing the unreliable auto-selection logic.

The thread shows consensus on removing the feature but continues to refine how to best guide users through the change. Phillip Wood will likely incorporate some of Junio's suggestions in a revised version of the series.
