This thread concludes the deprecation and removal of Git's problematic `core.commentChar=auto` configuration option. Phillip Wood has led the effort through a three-part series that first documented the issues, then added warning infrastructure, and now provides clear migration advice. The feature's heuristic for automatically selecting comment characters (like '#' in commit messages) has architectural limitations that cause failures in commit templates, hooks, and rebase operations.

The final implementation makes Git show deprecation warnings (or die with Git 3.0) when encountering the `auto` setting, while generating precise advice about how to migrate. The advice intelligently handles different configuration scopes (system/global/local) and even detects when users lack write permissions for system files. Junio C Hamano has approved the approach, particularly the use of `git config list --show-scope` (suggested by Oswald Buddenhagen) to diagnose configuration issues. The series is now complete and ready for merging, with all test cases verifying both warning and error behaviors across commit, rebase, and other interactive workflows.
