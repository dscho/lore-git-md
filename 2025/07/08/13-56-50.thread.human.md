This thread documents the removal of Git's `core.commentChar=auto` configuration option, a breaking change that affects interactive commit and rebase workflows. Phillip Wood led the effort with a three-part series that first identified the feature's architectural limitations (failing with commit templates, hooks, and rebase operations), then built a deprecation framework, and finally implemented user-facing migration advice. The change will first warn about the deprecated setting, then make it a fatal error after Git 3.0.

The implementation includes sophisticated tracking of where the setting appears in config files (system, global, or local) to generate tailored advice, with fallbacks for read-only system configs. Tests in t3404 and t7502 verify the behavior. While Oswald Buddenhagen argued for a simpler approach directing users to existing tools, Junio C Hamano approved Wood's more verbose solution as user-friendly. The series also establishes a reusable deprecation framework in `repo_read_config()` for future config removals. The change is now fully merged, concluding a discussion that highlighted tensions between implementation simplicity and user assistance during breaking changes.
