This thread documents the deprecation and removal of Git's `core.commentChar=auto` configuration option, a breaking change affecting interactive workflows like commit and rebase. Phillip Wood led the effort with a three-part series that has now been fully merged. The change addresses long-standing issues where Git's automatic comment character selection would fail in various scenarios involving commit templates, hooks, and rebase operations.

The implementation provides a migration path for users, first warning about the deprecated setting (with careful controls to avoid spamming) before eventually making it a fatal error in Git 3.0. The final version includes a comprehensive advice system that detects where the setting appears in config files and provides customized guidance for each case, even handling read-only system configs by recommending global config changes instead. Technical reviewers like Oswald Buddenhagen raised some edge case concerns that were addressed in the final implementation, while maintainer Junio Hamano approved the balance struck between user convenience and code complexity.

The series not only resolves this specific issue but also leaves behind reusable infrastructure for future config deprecations, particularly through the new `repo_read_config()` callback system. The discussion provides a model for how to handle breaking changes in Git while minimizing user disruption.
