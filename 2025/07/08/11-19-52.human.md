Feature and performance patch introducing `git sparse-checkout clean` to handle leftover sparse directories in cone mode. This is part 2 of a 3-part series addressing performance issues caused by unwanted full index expansions when sparse directories persist outside the sparse-checkout scope.

The new `clean` subcommand specifically targets cone mode sparse-checkouts, where it:
- Removes tracked-but-sparse directories (including any excluded/ignored files underneath)
- Offers a `--dry-run` option to preview deletions
- Preserves untracked directories and directories with staged changes
- Outputs removed/would-be-removed directories for visibility

The implementation works by collapsing the index to be maximally sparse in-memory, then removing directories marked as sparse in the index. This is more precise than `git clean -dfx` as it preserves excluded files within the sparse-checkout scope. The patch includes thorough test coverage in t1091 demonstrating both basic functionality and edge cases (like handling staged changes).

This addresses a known performance pain point where leftover sparse directories force expensive full index expansions. The command provides a more targeted solution than existing tools while maintaining safety through dry-run capability and clear output. The implementation appears solid with careful consideration of edge cases and good test coverage.
