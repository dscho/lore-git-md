This is a feature proposal for Git to natively support storing issue tracking data (issues, comments, projects) in Git repositories rather than relying on external databases from hosting providers like GitHub or Gitea.

The author, Sahil Gautam, explains their motivation stems from wanting independence from platform changes (citing GitHub's addition of AI features as an example) and suggests storing this metadata in private Git branches. They reference a Gitea issue where developers noted these features currently rely on databases, prompting this idea for native Git support.

The proposal is currently at a very early conceptual stage - it presents the general idea but lacks technical details about implementation, data formats, or how this would interact with existing Git workflows. The author appears to be gauging interest from the Git community before developing the idea further. Given Git's focus as a version control system rather than an issue tracker, this would likely require significant discussion about scope and design if pursued.
