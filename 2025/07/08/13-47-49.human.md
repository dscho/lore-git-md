Feature implementation for `git for-each-ref` pagination. This is the final patch in a 4-part series that adds a `--start-after` option to efficiently paginate through references in large repositories. The option allows starting iteration from a given reference marker, skipping all prior references, with O(log N) performance across all ref backends.

The implementation builds on the ref iterator seeking capability added in earlier patches, introducing a `start_ref_iterator_after()` helper that finds the lex position by incrementing the marker's last character. The documentation clearly notes that concurrent ref updates lexicographically behind the marker won't be shown, which is an intentional tradeoff for performance.

The patch includes extensive test coverage (194 lines) verifying edge cases: empty markers, partial matches, directory boundaries, and invalid combinations with patterns or custom sorting. The implementation appears thorough, with clear error messages when incompatible options are used together. This completes the pagination feature that has been through multiple rounds of review and naming discussion in the thread.
