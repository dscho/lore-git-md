Refactoring patch in the `git for-each-ref` pagination series, focusing on iterator seek behavior. This is patch 3/4 in the v3 series, building on the earlier iterator interface exposure and ref-cache cleanup.

The key change refactors `ref_iterator_seek()` to distinguish between two operations: seeking to a position (like `fseek()`) versus setting an iteration prefix. A new `REF_ITERATOR_SEEK_SET_PREFIX` flag controls this - when set, it maintains the current prefix-filtering behavior; when unset, it seeks to the reference while clearing any prefix. This provides more precise control over iteration.

The implementation touches all ref backends (files, packed, reftable) with backend-specific handling:
- Files backend: Most complex change, moving prefix logic to new `cache_ref_iterator_set_prefix()` and adding detailed seeking logic in `ref-cache.c`
- Packed backend: Simpler changes to handle prefix flag and clear previous prefix
- Reftable backend: Similar flag handling to packed backend

The patch includes comprehensive updates to all iterator implementations (empty, merge, prefix, debug) to handle the new flag parameter. Documentation in `refs.h` is expanded to clarify the seek vs prefix distinction.

This refactoring enables the pagination feature (implemented in patch 4) by providing the low-level seeking capability while maintaining backward compatibility. The changes are mechanical but touch sensitive ref iteration code, requiring careful review of each backend's implementation. The commit message clearly explains the motivation (avoiding confusion between seeking and prefixing) and the technical approach.
