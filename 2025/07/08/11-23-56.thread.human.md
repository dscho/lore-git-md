This thread addressed a documentation discrepancy in the `git-pack-refs` man page regarding the `--auto` behavior for both the "files" and "reftable" ref backends. Karthik Nayak initially noticed that the documentation incorrectly stated the "files" backend had no special handling for `--auto`, when in fact since commit c3459ae9ef2 (September 2024) it uses a ratio-based heuristic where larger packed-refs files require more loose refs to trigger repacking.

Patrick Steinhardt submitted a patch to update the documentation, accurately describing both backends' behaviors: maintaining the existing description of reftable's geometric sequence approach while adding the files backend's ratio-based heuristic. Karthik reviewed positively, suggesting an optional clarification about the ratio being logarithmic, but Patrick preferred keeping the description focused on user-visible behavior rather than implementation details.

Junio C Hamano has now given final approval to the patch, indicating it's ready for merging. The change modifies just 4 lines in the documentation to correct this inaccuracy, providing users with proper understanding of how `--auto` works across both ref storage backends. With this consensus reached, the thread concludes with this straightforward but important documentation improvement.
