This thread documents a straightforward correction to the `git-pack-refs` man page regarding the `--auto` behavior in both ref backends. The discussion was initiated by Karthik Nayak, who noticed the documentation incorrectly stated the "files" backend had no special handling for `--auto`. In reality, since commit c3459ae9ef2 (September 2024), the files backend uses a ratio-based heuristic where larger packed-refs files require more loose refs before repacking occurs.

Patrick Steinhardt submitted a patch to update the documentation, accurately describing both backends' behaviors. Karthik reviewed the change positively, suggesting only an optional clarification about the ratio being logarithmic. In the latest exchange, Patrick explains his preference to avoid mentioning "logarithmic" as it hints at implementation details without adding useful context, though he remains open to revisiting this if others express a preference. The core documentation update about the ratio-based behavior is uncontested, and the thread shows consensus with no outstanding issues beyond this minor wording consideration. The change modifies just 4 lines in git-pack-refs.adoc to align the docs with the actual behavior.
