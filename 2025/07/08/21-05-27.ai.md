Test infrastructure patch addressing backward compatibility in security release testing. This is a follow-up to the security release thread where test failures were observed in older Git versions (2.43-2.45) due to use of newer `git config` subcommands (`get`/`set`/`unset`) that were introduced in Git 2.46.

The patch modifies two test files (`t1300-config.sh` and `t7450-bad-git-dotfiles.sh`) to replace the newer subcommand syntax with backward-compatible alternatives (`--get` and `--unset` flags). The changes specifically affect tests dealing with CR character handling in config values and submodule directory validation, which were modified in the security fixes. The author has verified the changes work with Git 2.45.4 and expects them to apply cleanly back to 2.43.

Key technical details:
- Reverts to pre-2.46 config syntax while maintaining the same test functionality
- Affects tests for CRLF security fixes (CVE-2025-48384)
- Changes are minimal (4 lines total) and focused on test compatibility
- CI testing is underway via GitHub Actions across multiple branches

This is a straightforward maintenance patch that doesn't affect the security fixes themselves, but ensures the test suite remains runnable across all maintained versions during backporting workflows. The patch appears well-scoped and correctly targets the compatibility issue identified during security release testing.
