This is the first patch in a 4-part series introducing pagination support for `git for-each-ref`. The patch moves the `ref_iterator` interface and related functions from the internal `refs/refs-internal.h` header to the public `refs.h` header, exposing them to external callers.

The change enables more flexible ref iteration by allowing advanced users to directly use the iterator interface rather than being limited to the predefined `for_each_*` wrapper functions. The commit message explains that as requirements grow, creating new wrapper functions for every combination becomes impractical. The exposed interface includes core iterator functions like `ref_iterator_advance()`, `ref_iterator_seek()`, and `ref_iterator_peel()`, along with the `do_for_each_ref_flags` enum that controls iteration behavior.

The patch maintains all existing functionality while making the internals available for direct use. It includes comprehensive documentation of the iterator API in the public header, with example usage showing how to properly iterate and handle errors. The implementation is clean, moving 147 lines to the public header while removing 143 lines from the internal one, with no functional changes beyond the visibility scope.

This foundational change enables the pagination feature in later patches by providing direct access to the seeking functionality needed for efficient O(log N) reference lookups.
