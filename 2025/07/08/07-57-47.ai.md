This is a bugfix patch in Patrick Steinhardt's Meson build system series, addressing a regression in how Git's exec-path is configured when libexecdir is overridden. The patch fixes a case where custom libexecdir paths weren't properly appending the 'git-core' subdirectory, causing Git to fail finding its own binaries (demonstrated by `git daemon` failing to work).

The issue was reported by a user (irecca.kun@gmail.com) who found that overriding libexecdir via `-Dlibexecdir=` would break command execution. The root cause was that while the path was correctly set to the custom location, it wasn't including the required 'git-core' subdirectory where Git's binaries are actually installed. The fix is minimal - just one line changing how the path is constructed in meson.build to always include 'git-core'.

This patch is technically sound and follows the pattern established in the rest of the series for handling build configuration paths. It maintains backward compatibility while fixing the regression, and includes both the failure case and corrected behavior in the commit message. The change specifically targets line 1596 of meson.build, modifying the path concatenation logic when a custom libexecdir is specified.

As part of the v2 series that's now considered ready for merging, this patch completes the last remaining correctness issues in the Meson build configuration. The fix is straightforward and unlikely to be controversial, addressing a clear regression from a previous Meson build system improvement.
