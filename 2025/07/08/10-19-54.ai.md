Bugfix for the files ref backend cleaning up empty directories during transaction cleanup. This patch addresses a minor but persistent issue where the files ref backend would leave behind empty directories when reference creation fails or transactions are aborted. Currently, while lockfiles are cleaned up, the parent directories created for new references remain. The change modifies `files_transaction_cleanup()` to also remove empty parent directories using the existing `try_remove_empty_parents()` function.

The patch includes two new test cases in t1400-update-ref.sh that verify empty directories are properly pruned both when explicitly aborting a transaction and when not committing changes. The tests create nested references (refs/heads/nested/something) and confirm the intermediate directory (refs/heads/nested) is removed when the operation doesn't complete.

While not a functional bug, this improves repository hygiene by preventing accumulation of useless empty directories. The change is low-risk as it builds on existing directory-pruning infrastructure used elsewhere in the codebase. The patch comes from a real-world observation in Gitaly and maintains consistency with the ref backend's general cleanup behavior.
