This is a review response to Derrick Stolee's patch adding a `git sparse-checkout clean` command, which aims to remove tracked-but-sparse directories that remain on disk outside the sparse-checkout scope. The command is designed to prevent unwanted full index expansions that hurt performance.

Elijah Newren raises several thoughtful questions and concerns about edge cases and safety:

1. **Scope clarification**: He questions whether the command should work in non-cone mode or without sparse index enabled, noting the current implementation requires cone mode.

2. **Safety concerns**: He flags potential dangers when running during merge/rebase conflicts, where modified files outside the sparse specification might exist. The current implementation could delete these precious files.

3. **Implementation details**: He examines the code's handling of staged changes and suggests the error message for failed sparse index conversion could be more specific about why it failed (e.g., due to uncommitted changes).

4. **Output fidelity**: He wonders whether showing individual files (like `git status` does) would be more useful than just showing directories, though acknowledges this may not be necessary.

The review is constructive and technical, focusing on real-world usage scenarios that the current implementation might not handle well. Newren clearly understands the sparse-checkout subsystem deeply and is helping ensure the new command is robust before merging. His questions suggest the patch may need some refinement around edge case handling and safety warnings before final acceptance.
