Feature and performance patch introducing `git sparse-checkout clean` command to handle leftover sparse directories in cone mode.

This patch adds the core implementation of the new `clean` subcommand to `git sparse-checkout`, building on the series' goal of addressing performance issues from unwanted full index expansions. The command specifically targets cone mode sparse-checkouts, where it can safely identify and remove tracked-but-sparse directories that persist due to ignored files, locks, or other edge cases.

Key technical details:
- Operates by first converting the index to a sparse index in-memory (SPARSE_INDEX_MEMORY_ONLY)
- Scans for sparse directory entries (S_ISSPARSEDIR) that still exist on disk
- Provides --dry-run option to preview deletions
- Preserves directories containing staged changes (detected via index state)
- Outputs removed/would-be-removed directory paths
- Includes comprehensive tests in t1091 covering:
  - Basic cleanup of untracked sparse directories
  - Dry-run behavior
  - Handling of staged changes (preserving affected directories)

The implementation carefully handles filesystem operations with proper cleanup and error reporting (strbuf for paths, warning_errno for failures). The command is positioned as a more precise alternative to `git clean -dfx` for sparse-checkout users, specifically targeting the performance-impacting case of lingering sparse directories.

The patch maintains consistency with the series' architectural direction by:
- Following the established sparse-checkout subcommand pattern
- Using repository-aware index operations (aligned with `the_repository` removal)
- Including thorough documentation of behavior and limitations

Test coverage appears robust, verifying both the happy path and edge cases like staged changes. The implementation seems well-considered, with clear attention to safety (dry-run, staged change preservation) while solving a concrete performance pain point in sparse-checkout usage.
