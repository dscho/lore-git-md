This is a follow-up in the Meson build system series, specifically addressing the CI test parallelization issue in patch 8/8. Jeff King (peff) responds to Junio Hamano's report of test failures where Meson rejects the `--slice` argument with "SLICE is not a positive integer".

The problem stems from the GitHub Actions matrix configuration using 0-based numbering (`[0, 1, 2...9]`) while Meson expects 1-based slice indices. Peff proposes changing the matrix to `[1, 2, 3...10]` in `.github/workflows/main.yml` as the likely solution. This would align with Meson's requirement for positive integers while maintaining the same number of parallel test slices (10).

The reply is technical but concise, focusing narrowly on the CI configuration fix needed for the parallel test slicing feature. It doesn't address the broader series or other CI platforms like GitLab CI that might need similar adjustments. The proposed change appears straightforward and likely correct, though it remains to be seen if it fully resolves the issue across all CI platforms.
