Deprecation of `core.commentChar=auto` feature. This is the first of two patches from Phillip Wood to remove this problematic configuration option that automatically selects comment characters in commit messages.

The feature, introduced in 2014, was meant to avoid conflicts when amending commits by choosing a comment character not already used in the message. However, it has proven unreliable in several scenarios: it fails with commit templates containing comments, conflicts with `prepare-commit-msg` hooks, breaks `git commit --cleanup=strip` workflows (affecting rebase fixup/squash commands), and doesn't work with conflict comments from operations like cherry-pick or rebase. It's also ignored by `git notes`.

The patch updates documentation in BreakingChanges.adoc and config files to announce the deprecation (with planned removal in Git 3.0) and adds compile-time guards around the feature's implementation. Test cases are marked to expect failure when the breaking changes flag is enabled. The changes are thorough and well-documented, with clear explanations of the technical limitations that motivated the deprecation.

This appears to be a well-justified removal of a feature whose maintenance burden outweighs its benefits, following Git's standard deprecation process. The patch provides a migration path while leaving the possibility open for future improvements if someone can address all the edge cases.
