This is a documentation patch addressing the `git stash` message handling behavior discussed in the ongoing thread. Junio C Hamano provides historical context and rationale for the current behavior where custom messages in `git stash create` appear in commit objects but not in reflog entries (which show a generic "Created via git stash store" message).

The patch clarifies several documentation points: it updates the description of stash messages to explicitly mention which commands accept custom messages (`push`, `save`, `store`), improves the explanation of `git stash list` output to indicate it shows the stored message rather than the base commit description, and adds a more detailed caveat about `git stash create` being primarily for internal script use with its message argument being implementation detail.

Key technical aspects include the distinction between commit messages (set by `create_stash()`) and reflog messages (set by `do_store_stash()`), and the historical evolution from a simple emergency-stashing tool to one supporting custom messages. The patch maintains backward compatibility while making the documentation more accurate about the current behavior, aligning with the "document rather than change" approach suggested earlier in the thread.

The changes touch only `Documentation/git-stash.adoc`, modifying descriptions of the `list`, `create`, and overall command behavior. This appears to be the conservative resolution path for the reported discrepancy, providing clearer expectations without altering the implementation.
