This is a breaking change proposal to deprecate and eventually remove support for `core.commentChar=auto`. Phillip Wood is leading this effort in response to recent bug reports and design challenges with the feature.

The cover letter explains that the auto-detecting comment character feature has proven problematic, citing two specific bug reports. The proposed solution is a two-step deprecation process: first adding warnings when the setting is used, then removing it entirely in Git 3.0. The warning includes clear instructions for users to either unset the configuration (reverting to the default '#' character) or explicitly set their preferred comment string.

The patch series consists of two parts: documentation updates to announce the deprecation in BreakingChanges.adoc and config documentation, and implementation changes to print helpful advice when the deprecated setting is detected. The changes touch several areas including commit.c (where most of the comment character logic lives), config handling, and test updates.

This appears to be a well-motivated change with thorough documentation and clear user guidance. The implementation includes test coverage and follows Git's standard deprecation process. The change is relatively contained but affects a configuration option that some users may have set, so the clear warning messages are particularly valuable.
