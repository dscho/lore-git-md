Here's a human-readable summary of the thread so far:

Sahil Gautam proposed adding native issue tracking support to Git itself, suggesting that storing issues, comments, and project management data directly in Git repositories could help avoid vendor lock-in with specific hosting platforms. He mentioned Gitea's issue tracking as motivation for the idea, though no implementation details were provided.

Junio Hamano responded with reservations about putting this functionality in Git core. While recognizing the real problem of platform lock-in for project metadata, he suggested the better path would be developing an open standard format that different hosting providers could adopt. This would allow issue data to move between platforms without requiring Git itself to handle issue tracking. Junio framed this as primarily a standardization challenge for the ecosystem rather than something Git should implement directly. The exchange highlights differing views on where the solution should live - in Git itself versus in interoperable tools built around Git.
