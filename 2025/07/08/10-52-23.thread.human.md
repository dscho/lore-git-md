Sahil Gautam has proposed an idea to make Git natively support storing issue tracking data (like tickets, comments, and project management information) directly in Git branches, rather than relying on external databases from hosting providers like GitHub or Gitea. The motivation comes from their experience moving from GitHub to Gitea, wanting more control over their workflow and avoiding sudden changes imposed by large platforms.

The proposal references a discussion with Gitea developers (issue #34993) where it was noted that current implementations use databases. Sahil is exploring whether Git core could support this functionality directly, making issue tracking data portable across different hosting providers. At this stage, it's a conceptual discussion - no specific implementation details or patches have been shared yet.

This would be a significant change to Git's data model if pursued, potentially raising questions about performance implications and whether such functionality belongs in core Git versus being implemented as an external tool. The thread appears to be in early exploratory stages, gauging community interest in the concept.
