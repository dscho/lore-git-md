This is the second patch in a two-part series deprecating the `core.commentChar=auto` feature, focusing on user notification. Phillip Wood implements the warning system that will advise users when they're using the deprecated auto-commentchar functionality.

The patch adds detailed advice messages that appear when Git detects `core.commentChar=auto` in the config. The advice explains the deprecation and provides specific commands to either unset the config entirely (reverting to the default '#' comment character) or set a fixed comment string. The implementation carefully tracks where config values are set across multiple files to generate accurate unset commands.

The technical work involves parsing config with a new callback that records file locations and duplicate settings, then generating appropriate `git config` commands to help users transition away from the auto behavior. The patch includes tests verifying the advice output matches expectations when multiple config files contain commentchar settings.

This follows the standard Git deprecation process by first warning users before removal (planned for Git 3.0). The implementation is thorough, handling edge cases like multiple config files and duplicate keys while providing clear migration instructions. The patch maintains the temporary nature of this code by keeping it guarded under `WITH_BREAKING_CHANGES`.
