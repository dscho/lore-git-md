This is the second patch in a two-part series deprecating and removing the `core.commentChar=auto` configuration option, following the groundwork laid in patch 1/2. The series is a breaking change targeting interactive commit/rebase operations where Git automatically selects comment characters.

The current patch implements user-facing deprecation warnings when `core.commentChar=auto` is detected. It adds comprehensive advice generation that:
1. Detects all configuration files where comment-related settings appear
2. Shows exact `git config` commands to either unset the auto behavior or switch to a fixed comment character
3. Handles complex cases like multiple definitions in include files and different config scopes (system/global/local)

Key technical components include:
- New `struct comment_char_cfg` to track config file state
- Config callback that records file locations and duplicate keys
- Special handling for different config scopes (with some hardcoded paths as temporary measure)
- Advice messages showing both unset and set commands with proper scoping

The implementation spans `builtin/commit.c` with new config parsing infrastructure and updates `t/t7502-commit-porcelain.sh` to verify the advice output. The warning cannot be disabled except by changing the config value, reinforcing the deprecation path.

This completes the deprecation process started in 1/2, providing clear migration guidance while maintaining backward compatibility until Git 3.0. The approach is thorough and considers edge cases like multiple config files, suggesting the change is well-received and unlikely to face significant opposition.
