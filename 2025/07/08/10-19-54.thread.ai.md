files ref backend cleanup thread summary:

Subject: files ref backend cleanup of empty directories during transaction cleanup. Patch from Patrick Steinhardt addresses minor issue where empty parent directories remain after failed reference creation or aborted transactions. Currently lockfiles are cleaned up but empty parent dirs persist. Change modifies files_transaction_cleanup() to use existing try_remove_empty_parents() function to remove these, maintaining consistency with ref backend's general cleanup behavior.

Includes two new test cases in t1400-update-ref.sh verifying empty dir pruning works for both explicit transaction abort and non-committed changes. Tests create nested refs (refs/heads/nested/something) and check intermediate dir (refs/heads/nested) is removed when operation doesn't complete. Originated from real-world Gitaly observation.

Junio Hamano reviewed and approved the change, confirming edge case behavior is safe:
- Existing try_remove_empty_parents() protects critical top-level directories (like .git/refs/tags/) from being removed when empty
- Safety check prevents accidental deletion of essential directory structure when creating first reference in new namespace
- Straightforward improvement building on existing infrastructure with no unexpected side effects

Patch will be included in next integration cycle. Low-risk change improving repository hygiene by preventing empty dir accumulation. Thread concluded with maintainer approval.
