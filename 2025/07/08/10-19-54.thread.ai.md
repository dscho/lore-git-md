Files ref backend cleanup thread summary:

Subject: files ref backend cleanup of empty directories during transaction cleanup. Patch addresses a minor issue where empty parent directories remain after failed reference creation or aborted transactions. Currently lockfiles are cleaned up but empty parent dirs persist. Change modifies files_transaction_cleanup() to use existing try_remove_empty_parents() function to remove these.

Includes two new test cases in t1400-update-ref.sh verifying empty dir pruning works for both explicit transaction abort and non-committed changes. Tests create nested refs (refs/heads/nested/something) and check intermediate dir (refs/heads/nested) is removed when operation doesn't complete.

Not a functional bug but improves repository hygiene by preventing empty dir accumulation. Low-risk change building on existing dir-pruning infrastructure. Originated from real-world Gitaly observation, maintains consistency with ref backend's general cleanup behavior.
