Performance optimization series for `git fetch --prune` that's ready for final review. This is the fourth iteration of a patch set that dramatically improves the performance of pruning operations in repositories with many refs. The core change replaces an O(N^2) algorithm with an O(N log N) approach by sorting the prune list and using binary search, reducing a 470-second operation to under 1 second in real-world cases.

The series has already received positive review from Jacob Keller on the main optimization patch, with the remaining two patches being mechanical cleanups of now-obsolete code paths. The author notes this version fixes an accidental omission of the first commit from v3. The changes touch `builtin/fetch.c`, `builtin/remote.c`, and `refs.c` to restructure the prune logic while maintaining the same output format (though now including deleted ref names in warning messages).
