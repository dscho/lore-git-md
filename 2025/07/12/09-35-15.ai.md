This is part 3/5 of a performance optimization series for Git's pathspec bloom filters, introducing a key abstraction change to support multiple pathspec queries.

The patch replaces the direct `struct bloom_key *` usage in `rev_info` with a new `struct bloom_keyvec` that groups bloom keys by pathspec item. This enables the stricter "for every" matching requirement where ALL pathspec items must report "definitely not changed" (previously ANY match would suffice). The implementation maintains backward compatibility by keeping `bloom_keyvec_nr` limited to 0 or 1 in this patch.

Key technical changes:
- Adds `bloom_keyvec` struct with flexible array of bloom keys and count
- Introduces `bloom_keyvec_new()` to create keyvecs by splitting paths on '/' and generating keys for each prefix component
- Implements `bloom_filter_contains_vec()` to check ALL keys in a keyvec
- Updates revision.c to use keyvec API while preserving single-pathspec fast path
- Adds cleanup helper `release_revisions_bloom_keyvecs()`

The changes touch bloom.c/h and revision.c/h, with careful handling of path normalization and trailing slashes. The patch maintains all existing wildcard fallback behavior while laying groundwork for future multi-pathspec optimization. It follows through on the v5 feedback by properly isolating pathspec conversion logic and cleaning up variable usage.

This represents a core architectural change in the bloom filter handling that enables the performance improvements demonstrated in the series' benchmarks, while maintaining clean API boundaries and comprehensive test coverage.
