This is the final performance optimization patch in a series addressing bloom filter handling for multiple pathspecs in revision traversal. The patch completes the implementation by:

1. Modifying `forbid_bloom_filters()` to iterate through all pathspec items (removing the previous `nr > 1` check) and only reject pathspecs containing non-literal elements (wildcards or magic bits). This enables bloom filter optimization for multiple literal pathspecs.

2. Updating `prepare_to_use_bloom_filter()` to allocate and initialize a bloom keyvec for each pathspec item when optimization is possible, using a loop to process all items through `convert_pathspec_to_bloom_keyvec()`.

3. Adding comprehensive test cases in t4216-log-bloom.sh that verify:
   - Bloom filter usage with multiple literal pathspecs (including glob patterns that resolve to literals)
   - Correct fallback behavior when pathspecs contain actual wildcards (escaped or unescaped)
   - Result equivalence between bloom-optimized and non-optimized queries

The patch includes performance benchmarks showing significant improvements: 1.33x faster in the Git repository (55.1ms vs 73.1ms) and 7.5x faster in the LLVM repository (263ms vs 1.4s) for multi-pathspec queries. The implementation maintains backward compatibility with single-pathspec cases while adding support for multiple pathspec optimization.

Key technical details:
- Uses the new `struct bloom_keyvec` abstraction introduced earlier in the series
- Preserves the strict "all pathspecs must match" requirement
- Handles escaped wildcards correctly (e.g., `file\*` falls back to non-bloom path)
- Updates test infrastructure to use `eval` for proper shell variable handling
