Thread identity: Platform compatibility issue with Git 2.50+ on RHEL 6, reported by Азат Усманов, with follow-up from Phillip Wood, Ramsay Jones, and Carlo Marcelo Arenas Belón.

Core problem: Compilation and linking failures starting from Git 2.50 on RHEL 6 (versions 6.6 and 6.10) while working fine on RHEL 8 with same GCC 13.4.0. Issues progressed through multiple layers: (1) missing `random.h` header, (2) syntax failures in `sane-ctype.h` character type macros (`sane_istest` macro with `expected expression before ']' token` errors), and (3) linker errors for undefined `getrandom()` symbol during final binary linking.

Current status: Phillip Wood identified a patch addressing the `sane-ctype.h` regression introduced in Git 2.50. After applying this, build now fails at linking stage due to RHEL 6's older libc lacking `getrandom()`. Ramsay Jones clarified RHEL 6 is likely too old for official support (minimum being RHEL 8) and provided workaround using `CSPRNG_METHOD=` in configuration. Carlo Marcelo Arenas Belón refined the workaround instructions, noting the setting must go in `config.make` (not `config.mak`) to properly override defaults from `config.mak.uname` and `config.mak.autogen`.

Key technical details: Issues stem from platform header interactions through `compat/posix.h` inclusion in `git-compat-util.h`. The `sane_istest` macro failures affected multiple compilation units (base85.o, cbtree.o etc.). Current linker errors occur in `wrapper.c` during final binary linking for `git-http-backend`, `git-daemon` and others. Wood's patch properly addresses the `sane-ctype.h` regression. The refined `CSPRNG_METHOD` workaround uses Git's existing fallback mechanism for systems without `getrandom()` and requires careful configuration file placement to override defaults.

Open questions: (1) Whether Wood's `sane-ctype.h` fix will be merged upstream, (2) if RHEL 6 support should be officially documented, (3) whether to improve `CSPRNG_METHOD` documentation/discovery, (4) maintainer guidance on legacy system support strategy, (5) potential need for clearer build system documentation regarding configuration precedence.
