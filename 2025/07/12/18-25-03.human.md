Platform compatibility bugfix follow-up with new compilation issues.

Азат Усманов reports that while the `sane-ctype.h` patch from Phillip Wood helped progress compilation, they've now hit a new linking error about `getrandom()` being undefined during the final build stage. This appears when building several binaries including `git-http-backend` and `git-daemon`. The error suggests RHEL 6's older libc doesn't provide this system call that Git 2.50+ now uses for cryptographic randomness.

The email includes two key questions: how to properly apply the `sane-ctype.h` patch (since they only have the diff), and whether this fix will be merged upstream. The thread shows this is part of broader RHEL 6 compatibility issues that started with Git 2.50, where the same GCC version behaves differently between RHEL 6 and 8 due to system header differences.

This appears to be a genuine platform support regression that will need maintainer attention. The patch application question suggests the contributor could use guidance on Git's patch workflow, while the `getrandom()` issue may require either a compatibility shim or build-time detection for older glibc versions. The fact that multiple independent compilation issues are surfacing indicates this RHEL 6 support breakage runs deeper than any single fix.
