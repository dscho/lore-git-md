This thread documents a series of platform compatibility issues encountered when building Git 2.50+ on RHEL 6 systems, reported by Азат Усманов. The problems started with header syntax errors in `sane-ctype.h` (fixed by a patch from Phillip Wood) and have now progressed to linker failures due to missing `getrandom()` support in RHEL 6's older libc.

Ramsay Jones has weighed in, noting that RHEL 6 is likely too old for official Git support (with RHEL 8 being the current baseline) and advising against workarounds that involve copying newer glibc headers. He provided a practical solution: building with `CSPRNG_METHOD=` to bypass the `getrandom()` dependency. While this unblocks immediate compilation, it raises the broader question of how much effort should be spent maintaining compatibility with such legacy systems.

The thread reveals a layered compatibility challenge - first with header syntax, now with system library availability - with no clear consensus yet on whether these fixes should be incorporated upstream. The discussion remains open on whether Git should improve its build system to better handle such legacy environments or simply document RHEL 6 as unsupported platform.
