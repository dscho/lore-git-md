This thread addresses compatibility issues when building Git 2.50+ on RHEL 6 systems, which are now considered legacy platforms. The original reporter, Азат Усманов, documented a progression of build failures - first with missing headers, then syntax errors in character type macros, and finally linker errors for the modern `getrandom()` function.

Phillip Wood contributed a fix for the `sane-ctype.h` regression, while Ramsay Jones clarified that RHEL 6 (specifically versions 6.6 and 6.10) likely falls outside Git's official support window, which now targets RHEL 8 as the minimum. Jones initially suggested using `CSPRNG_METHOD=` as a workaround for the `getrandom()` issue. Carlo Marcelo Arenas Belón has now refined this advice, explaining that the workaround must be written to `config.make` (not `config.mak`) to properly override the system defaults, and should be applied after cleaning the build directory.

The discussion reveals a layered approach to platform compatibility - while the project maintains clear support boundaries, contributors are helping users with practical workarounds for legacy systems. The thread remains open for maintainer input on whether Phillip Wood's fix will be merged and whether to document these edge cases in the official documentation.
