Platform compatibility question about line ending behavior on Windows, specifically with Git for Windows 2.47.0.windows.2. Jason Cho reports that despite setting `core.eol=lf` and `core.autocrlf=false`, the file `license_header.txt` (from DBeaver project) is still being checked out with CRLF line endings (`^M$` visible in `cat -A` output). The user provides a complete reproduction case showing the commands used and their outputs. Key technical details: the file has no special attributes per `git check-attr`, and the behavior persists despite the explicit configuration settings. This suggests either a misunderstanding of Git's line ending conversion hierarchy (where `.gitattributes` would override core settings) or a potential bug in Git for Windows' handling of these settings. The case highlights the complex interaction between `core.autocrlf`, `core.eol`, and per-file attributes in Git's CRLF/LF conversion system on Windows platforms.
