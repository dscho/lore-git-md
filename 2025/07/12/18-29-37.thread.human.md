This thread discusses proposed improvements to Git's submodule handling to make it more intuitive for new users while preserving backward compatibility. The author suggests four changes: 

First, they propose changing the default `push.recurseSubmodules` behavior from "no" to "check" (when `submodule.recurse` isn't set) to prevent accidental pushes of un-pushed submodule commits. Second, they suggest enhancing the "check" mode or adding a "checkStrict" variant to verify submodule references exist specifically on the target remote.

Third, they recommend adding a `clone.recurseSubmodules` option (defaulting to true) to automatically initialize submodules during clone, preventing common build failures. Finally, they propose a general Git feature - a `--builtin` flag for `git config get` to query default values, which would help with troubleshooting configuration across environments.

The author has personally tested the first and third proposals via config overrides and is seeking feedback on these changes, particularly regarding the rationale behind current defaults. The thread appears to be starting fresh discussion on submodule usability improvements.
