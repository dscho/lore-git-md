Performance optimization for Git's pathspec bloom filters, finalizing a series that speeds up multi-pathspec queries. This patch removes the previous restriction that prevented bloom filter optimization when multiple pathspecs were given, now allowing the optimization as long as all pathspecs are literal (no wildcards or special magic bits). The implementation iterates through all pathspec items to verify they are literal before applying the bloom filter optimization.

Key changes include modifying `forbid_bloom_filters()` to check all pathspec items rather than just the first one, and updating `prepare_to_use_bloom_filter()` to handle multiple pathspecs by allocating a bloom keyvec for each one. The patch includes comprehensive test updates that verify both the optimization's correctness (showing equivalent results with and without bloom filters) and its proper fallback behavior when any pathspec contains non-literal elements.

Benchmarks show significant speedups: 1.33x faster in the Git repository (55.1ms vs 73.1ms) and 7.5x faster in the LLVM repository (263ms vs 1.4s). The patch has received Reviewed-by tags from both Derrick Stolee and Junio Hamano, indicating it's ready for merging as the final piece of this optimization series.
