Performance optimization patch completing the bloom filter pathspec series by enabling multi-pathspec optimization when all items are literal.

This final patch in the v6 series modifies `forbid_bloom_filters()` to allow bloom filter usage for multiple pathspec items when all are literal, removing the previous hardcoded `spec->nr > 1` rejection. The implementation now checks each pathspec item's magic bits via a loop rather than just checking the first item. The `t4216-log-bloom.sh` tests are updated to verify the new behavior, including confirming bloom filters are still skipped for actual wildcards (escaped or unescaped).

Key technical changes:
- `forbid_bloom_filters()` now iterates through all pathspec items with `for (size_t nr = 0; nr < spec->nr; nr++)` to check magic bits
- `prepare_to_use_bloom_filter()` allocates and initializes a bloom keyvec for each pathspec item via new loop
- Test cases verify both the optimization works for multiple literal pathspecs (including `-- file4 A/file1` and glob patterns that resolve to literals like `-- *`)
- Additional test cases confirm bloom filters are still skipped for paths containing actual wildcards (escaped with `\*` or unescaped)

The patch includes benchmark results showing significant speedups: 1.33x faster in Git's repo (55.1ms vs 73.1ms) and 7.5x faster in LLVM's repo (263ms vs 1.974s) for multi-pathspec queries. The implementation has been reviewed by Derrick Stolee and Junio Hamano, with all feedback from previous rounds addressed. This completes the series' goal of optimizing bloom filter usage for multiple literal pathspecs while maintaining correct behavior for wildcard cases.
