Platform compatibility follow-up regarding RHEL 6 build issues, focusing on the `getrandom()` linking problem.

Ramsay Jones responds to Азат Усманов's ongoing RHEL 6 compilation struggles, now addressing the linker errors for `getrandom()` after the `sane-ctype.h` issues were resolved. Jones makes several key points: (1) RHEL 6 is likely too old to be officially supported (minimum being RHEL 8), (2) warns against copying newer glibc headers as a solution, and (3) provides the immediate workaround of building with `CSPRNG_METHOD=` either in `config.mak` or directly in the make invocation. The warning about implicit `getrandom()` declaration in `wrapper.c` line 782 confirms the system lacks this modern glibc function.

This moves the thread forward by clarifying the support policy and providing a concrete workaround, though it raises questions about whether such legacy system support should be maintained upstream. The `CSPRNG_METHOD` build option appears to be Git's existing mechanism for handling systems without `getrandom()`, though its documentation and discoverability may need improvement. The response leaves open whether this should be handled via better build system detection or if RHEL 6 users should simply use older Git versions.
