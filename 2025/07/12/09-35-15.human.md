Performance optimization patch introducing `struct bloom_keyvec` to support multiple pathspec items in Git's bloom filter queries. This is part of a series addressing performance issues when combining pathspec queries.

The patch replaces the direct `struct bloom_key *` usage in `rev_info` with a new `bloom_keyvec` abstraction that groups keys by pathspec item. The key change is requiring ALL pathspec items to report "definitely not changed" rather than ANY, which necessitates tracking keys per-pathspec. The implementation maintains backward compatibility with single-pathspec cases while laying groundwork for future multi-pathspec optimization.

New functions include `bloom_keyvec_new()` for key creation, `bloom_keyvec_free()` for cleanup, and `bloom_filter_contains_vec()` to check all keys in a vector. The changes touch bloom.c/h and revision.c/h, updating the bloom filter checking logic while preserving existing behavior for single pathspecs.
