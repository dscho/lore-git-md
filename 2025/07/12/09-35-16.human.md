This is a refactoring patch in the performance optimization series for Git's pathspec bloom filters. It extracts the pathspec-to-bloom-keyvec conversion logic into a dedicated helper function, `convert_pathspec_to_bloom_keyvec()`, as part of preparing the codebase to handle multiple pathspec queries more efficiently.

The change moves the key creation logic out of `prepare_to_use_bloom_filter()` into its own function, which will make it easier to extend the code to handle multiple pathspecs in future patches. The helper handles path normalization (removing trailing slashes) and empty path checking, returning the new bloom keyvec through an output parameter.

This is a clean mechanical change that doesn't alter behavior - it just reorganizes the code to be more maintainable as the series progresses. The patch has already been reviewed and signed off by Derrick Stolee, indicating it's a straightforward preparatory step in the larger optimization effort. The change touches only revision.c and maintains all existing functionality while making the code more modular.
