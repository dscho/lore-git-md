Platform compatibility issue with Git 2.50+ on RHEL 6. Азат Усманов reports compilation failures starting from Git 2.50 on RHEL 6 (both 6.6 and 6.10), while the same source compiles fine on RHEL 8. The initial error about missing `random.h` in `compat/posix.h` can be worked around by copying the file, but this leads to deeper compilation errors in `sane-ctype.h` with syntax errors around character type macros. The reporter notes both systems use the same GCC 13.4.0 compiler, and that Git 2.49.1 was the last version that compiled successfully on both platforms.

The error output shows multiple compilation failures across core components (`base85.o`, `bisect.o`, `blame.o`, etc.) all stemming from the `sane_istest` macro definition in `sane-ctype.h`. The issue appears to be related to how character type checking macros are being processed differently on the older RHEL 6 platform despite using the same compiler version. This suggests either a platform header incompatibility or an assumption in Git's compatibility layer that doesn't hold on RHEL 6's C library implementation. The report provides detailed configure output showing the environment differences that might help diagnose the root cause.
