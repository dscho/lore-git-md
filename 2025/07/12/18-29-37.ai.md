Feature proposal for git-submodule defaults and config improvements. This email suggests four changes to make submodule handling more novice-friendly while maintaining backward compatibility for advanced users.

The first proposal changes the default of `push.recurseSubmodules` from "no" to "check" when `submodule.recurse` isn't set, preventing accidental pushes of un-pushed submodule commits while avoiding automatic pushes. The second suggests either modifying the existing "check" mode or adding a "checkStrict" mode to verify submodule references exist on the specific remote being pushed to, not just any remote.

Third, the author proposes adding a `clone.recurseSubmodules` config option (defaulting to true) to automatically initialize submodules on clone, preventing common build failures. They argue this would eliminate the need for projects to handle submodule initialization in build scripts. The fourth suggestion is a general Git feature - adding `--builtin` flag to `git config get` to query default values, aiding in troubleshooting across different environments.

The author acknowledges some assumptions about edge cases and seeks feedback, particularly on the current defaults' rationale. The changes aim to reduce novice frustration while minimizing impact on existing users, with the first and third proposals being personally tested by the author via config overrides. The thread appears to be starting fresh discussion rather than continuing an existing one.
