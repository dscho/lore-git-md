This is the final discussion before submission of the two-part series deprecating `core.commentChar=auto`. Junio C Hamano and Oswald Buddenhagen are reviewing the last details of the implementation, specifically around how users should be advised to handle existing `auto` settings in their configuration.

The key points settled in this exchange are that:
1. The advice to users will be simplified to recommend using `git config list --show-scope` to identify where `auto` settings originate, rather than providing specific unset commands that might involve policy decisions about which config files to modify.
2. There is agreement that Git should refuse to operate when encountering `auto` settings after the deprecation period (post-Git 3.0), as this is the most fail-safe approach.

This concludes the design discussion for this change, with Phillip Wood preparing to submit the final patch series incorporating all feedback. The implementation will now focus on clear user guidance through the deprecation period rather than trying to automate the migration path.
