This is a refactoring patch in the performance optimization series for pathspec bloom filters. It extracts the pathspec-to-bloom-keyvec conversion logic into a dedicated helper function `convert_pathspec_to_bloom_keyvec()` to simplify the state management in `prepare_to_use_bloom_filter()`.

The patch moves the core conversion work - handling trailing slashes, empty paths, and creating new bloom keyvecs - into the new helper. This makes the main bloom filter preparation function cleaner and prepares for future changes to support multiple pathspecs. The helper returns an error code (-1) for empty paths while maintaining all existing behavior.

Key technical details:
- New `convert_pathspec_to_bloom_keyvec()` takes output parameter `out` for the created keyvec
- Handles path normalization (trailing slash removal via `xmemdupz`)
- Preserves empty path checking that triggers fallback behavior
- Maintains exact same memory management (path_alloc cleanup)
- Updates `prepare_to_use_bloom_filter()` to use the new helper
- Touches only revision.c
- Part of v6 series addressing performance of combined pathspec queries
- Builds on earlier work introducing `struct bloom_keyvec`
- Signed-off by both original author and Derrick Stolee indicating review approval

The change is purely structural with no behavior modification, keeping all existing functionality while making the code more maintainable for the upcoming multi-pathspec support. The patch follows the series' pattern of careful refactoring before adding new features.
