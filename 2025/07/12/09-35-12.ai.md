Performance optimization series for Git's pathspec bloom filters, final version. This v6 series from Lidong Yan introduces bloom filter optimization for multiple literal pathspec elements in revision traversal, addressing Kai Koponen's reported issue where combined pathspec queries were slower than separate invocations.

The series builds on previous rounds by:
1. Extracting pathspec-to-bloom-keyvec conversion into a dedicated `convert_pathspec_to_bloom_keyvec()` helper
2. Fixing bugs identified in v5
3. Including comprehensive benchmark results showing 1.33x speedup in Git repo (55.1ms vs 73.1ms) and 7.5x in LLVM repo (263ms vs 1.974s)
4. Maintaining all pathspec magic/wildcard fallback behavior while optimizing the literal pathspec case

Key technical changes in this version:
- Finalized `forbid_bloom_filters()` logic allowing bloom usage for all-literal pathspecs
- Loop processing of all `revs->pruning.pathspec.items` via new helper
- Updated test coverage for multiple pathspec cases including escaped wildcards
- Cleaned up variable usage in `prepare_to_use_bloom_filter()`
- Preserved single-pathspec fast path while adding multi-pathspec support

The implementation now uses `struct bloom_keyvec` to manage multiple bloom keys, replacing direct `struct bloom_key *` usage in `rev_info`. Changes touch bloom.c/h, revision.c/h, blame.c, line-log.c with test updates in t4216-log-bloom.sh and t/helper/test-bloom.c.

Reviewers including Derrick Stolee (who provided benchmark numbers) and Junio Hamano have signed off on the technical approach. The series appears ready for merging after addressing all substantive feedback from multiple review rounds. The cover letter notes this is the final version with all known issues resolved.
