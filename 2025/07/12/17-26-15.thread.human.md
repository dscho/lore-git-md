This thread discusses changes to how the meson build system handles PCRE2 dependency configuration, particularly addressing macOS compatibility issues. The original patch proposed disabling PCRE2 by default in meson builds to match the Makefile's opt-in approach, as macOS systems often have a broken system PCRE2 installation (missing headers despite appearing available). 

In the latest update (v2), the patch has evolved to implement more nuanced platform-specific handling. It now auto-disables PCRE2 only on macOS by default, while introducing a new `macos_workaround_system_pcre2` option for users who have properly installed PCRE2 via alternative means. The global default for PCRE2 is changed from 'enabled' to 'auto', allowing other platforms to keep their existing behavior. 

brian m. carlson has suggested maintaining PCRE2-by-default on Linux while only disabling it on problematic platforms like macOS, which aligns with this v2 approach. The discussion continues around whether this platform-specific solution is preferable to a blanket disable, and whether documentation should be added to guide macOS users on proper PCRE2 installation. Notably, the patch still lacks test coverage for this platform-specific behavior, which may need addressing before finalization. The changes are part of broader efforts to align behavior across Git's various build systems (Makefile, cmake, and meson).
