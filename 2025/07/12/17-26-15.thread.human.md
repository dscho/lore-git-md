This thread began as a discussion about fixing PCRE2 dependency handling in Git's meson build system, particularly addressing macOS issues where system-provided PCRE2 is broken. The current patch series (v3) proposes platform-specific handling that auto-disables PCRE2 on macOS unless explicitly enabled, while maintaining 'auto' as the global default.

The conversation has since expanded into a deeper architectural discussion about Git's regex handling. Junio Hamano outlined a vision for unifying Git's regex architecture under PCRE2 by exposing the `grep_pat` struct and converting direct regex calls throughout the codebase. However, Carlo Arenas has raised practical concerns about this approach, calling it "probably unrealistic" in the near term. Instead, Carlo suggests a more incremental solution: isolating PCRE2 functionality into a semi-private header and making `git-grep` a standalone binary that optionally links with PCRE2.

There are now two parallel tracks of discussion: (1) the immediate build system fixes for PCRE2 handling (where the v3 patch awaits decisions about platform-specific vs global solutions), and (2) the longer-term question of whether and how to unify Git's regex architecture. The thread reveals an interesting tension between architectural vision and practical implementation concerns, with implications for both the build system and Git's internal API design. Key participants include the original patch author (who implemented platform-specific solutions as suggested by brian m. carlson), Junio as maintainer, and Carlo as a voice for pragmatic build system considerations.
