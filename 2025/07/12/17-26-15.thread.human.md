This thread addressed a build system issue with PCRE2 dependency handling in Git's meson build configuration, particularly for macOS where system-provided PCRE2 installations can be broken (missing headers despite appearing available). The discussion converged on implementing Eli Schwartz's approach of actively detecting PCRE2 via `compiler.has_header()` verification, replacing a macOS-specific workaround. The solution maintains static linking preference while changing the default setting from 'enabled' to 'auto' in meson_options.txt.

The final patch series (v3) was confirmed to properly handle all edge cases, including maintaining the subprojects wrapper fallback when in auto mode - a point verified by both Carlo Arenas and Patrick Steinhardt in this last exchange. The changes provide clear error messages when PCRE2 is explicitly enabled but unavailable, while allowing graceful degradation in auto mode.

While the immediate build system issue is now fully resolved, the thread surfaced broader architectural questions about Git's regex handling that remain open: whether to pursue Junio's vision of abstracting grep.[ch], Carlo's proposal for a standalone binary approach, or the long-term strategy around supporting multiple regex engines versus a PCRE2-only future.
