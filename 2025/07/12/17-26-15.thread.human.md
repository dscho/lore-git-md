This thread has been working through build system improvements for handling PCRE2 dependencies, particularly focusing on macOS where system installations are often broken due to incorrect header paths. The core solution, now in its sixth iteration, implements a three-way approach: when system PCRE2 is detected as broken (via compiler header checks), it either falls back to a subproject (if explicitly enabled), disables with a warning (in auto mode), or errors out (if required). The patch maintains special handling for Windows builds to stay consistent with cmake behavior while changing the default PCRE2 option from 'enabled' to 'auto'.

The implementation carefully handles edge cases like --wrap-mode=nofallback through meson's dependency resolution rules, while preserving the project's preference for static linking. The solution has been vetted by multiple contributors - Eli Schwartz suggested the core approach, Eric Sunshine provided editorial improvements, and the author confirmed it works on macOS.
