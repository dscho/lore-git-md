This thread addressed a build system problem where macOS systems with broken PCRE2 installations (missing headers despite appearing available) were causing Git builds to fail. The solution, now implemented in the meson build configuration, uses active header detection to properly identify these cases. The approach provides three behaviors: failing when PCRE2 is required but broken, falling back to a submodule when possible, or gracefully disabling with a warning in auto mode. The default setting in meson_options.txt was changed from 'enabled' to 'auto' to match this new behavior.

While the solution worked well for macOS (as verified by Carlo Arenas), a follow-up discussion revealed an unintended consequence for Windows builds. Changing to 'auto' doesn't automatically trigger the subproject wrapper fallback as previously assumed, meaning Windows builds that relied on this behavior would now fail unless explicitly built with `-Dpcre2=enabled`. This platform-specific side effect suggests the default behavior might need adjustment or clearer documentation for Windows users.

The thread has successfully resolved the original macOS issue while surfacing this new consideration. Broader questions about Git's regex architecture remain as future work items, but the immediate build system configuration is complete with this caveat noted for Windows users. Key participants included the original author, Patrick Steinhardt, Eli Schwartz, and Carlo Arenas who provided important platform-specific verification.
