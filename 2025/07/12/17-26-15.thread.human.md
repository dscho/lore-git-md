This thread discusses how the meson build system should handle PCRE2 dependency configuration, particularly in light of platform differences. The original patch proposed disabling PCRE2 by default in meson builds to match the Makefile's opt-in behavior and address macOS-specific issues where the included system PCRE2 library is broken (missing headers despite passing initial checks).

brian m. carlson has raised an important consideration, suggesting the change should be platform-specific rather than global. They note that while macOS has problematic system PCRE2 libraries, Linux systems typically provide working versions, and Linux users generally expect PCRE support by default for features like `git grep --perl-regexp`. This introduces a tension between build system consistency (having the same behavior across all build systems) and platform-appropriate defaults.

The discussion now centers on whether to:
1) Keep the original "disable everywhere" approach for consistency with Makefile/cmake
2) Implement platform-specific defaults that would disable PCRE2 only on problematic platforms like macOS while keeping it enabled by default on Linux

No code changes have been proposed yet in response to this feedback. The thread would benefit from input from both macOS users about their typical PCRE2 installation practices and Linux users about their expectations regarding default PCRE2 support. The decision may also need to consider how this aligns with Git for Windows' preferences and the broader goal of build system consistency.
