This is a proposal to improve submodule handling defaults, with some additional configuration suggestions. The author, Klaus Frank, suggests four modifications aimed primarily at making submodules more novice-friendly while minimizing impact on existing workflows.

The first three suggestions focus on submodule behavior: changing `push.recurseSubmodules` to default to "check" (preventing pushes with un-pushed submodule commits), enhancing the "check" mode to verify references exist on the specific remote being pushed to (or adding a "checkStrict" mode), and introducing a `clone.recurseSubmodules` option to automatically initialize submodules on clone. The author argues these changes would prevent common novice pitfalls while having minimal impact on advanced users.

The fourth suggestion is more general - proposing a `--builtin` flag for `git config` to show default values, which would aid in troubleshooting configuration issues across different Git versions.

The proposal appears well-considered, with the author noting they've personally used variants of some suggestions without issues. However, they acknowledge some assumptions may need vetting by the community, particularly around edge cases for the stricter submodule checking. The changes seem aimed at reducing support burdens and improving out-of-the-box behavior for new users, which aligns with Git's general usability goals.
