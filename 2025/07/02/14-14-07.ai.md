This is a follow-up discussion about the recently merged `--skip-until` pagination feature in `git for-each-ref`. Phillip Wood questions whether the current implementation fully addresses pagination use cases, suggesting that a numeric offset (`--start=N`) might be more practical than requiring users to know the exact ref name to skip until.

The key technical point raised is that the current `--skip-until` design forces users to track the last-seen ref name between paginated calls, which may be less convenient than simply specifying a numeric offset. Phillip's proposed alternative would allow pagination by position rather than by ref name, potentially simplifying client-side implementation for common pagination workflows.

This represents a usability consideration rather than a technical flaw in the merged implementation. The discussion touches on the API design tradeoffs between name-based seeking (which matches the underlying ref storage order) versus position-based pagination (which may be more intuitive for some use cases). No changes to the existing code are proposed in this email - it's raising a question about potential future improvements.
