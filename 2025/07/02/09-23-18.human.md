This is the first patch in a 3-part series refining Git's clang-format integration, now approved for merging. The patch removes the hard 80-character column limit from the clang-format configuration, shifting line-wrapping responsibility to developers while maintaining the project's 80-character recommendation as a guideline.

The change addresses long-standing issues where the formatter would aggressively reflow code to fit within 80 columns, sometimes reducing readability. The patch notes two previous attempts (in 2017 and 2024) to adjust line break penalties, but concludes that completely disabling column limits produces fewer false positives while still encouraging good practices. The accompanying .editorconfig file (from a previous commit) suggests 120 characters as a more flexible upper bound.

This represents a pragmatic compromise in the ongoing discussion about code formatting, sidestepping debates about exact line lengths while making the formatter more usable. The change is well-documented in the configuration file with a NEEDSWORK comment about potentially revisiting this with better penalty settings in the future.
