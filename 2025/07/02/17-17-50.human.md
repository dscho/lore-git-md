This is a discussion response to Patrick Steinhardt's patch proposing to make reftable the default ref storage format in Git 3.0. Justin Tobler provides feedback on the documentation portion of the patch, suggesting some wording improvements to better describe the benefits of reftables.

Justin notes that modern macOS still uses case-insensitive filesystems by default, so the documentation should generalize the case-sensitivity issue to cover both Windows and macOS platforms rather than calling out older macOS versions specifically. He also suggests adding a more user-friendly summary of reftables' scaling benefits to complement the detailed technical advantages already listed.

The response confirms the technical implementation approach (using WITH_BREAKING_CHANGES to toggle the default format) and test coverage look correct. While supportive of the change overall, Justin's feedback focuses on making the documentation more precise and accessible to end users who may not need all the implementation details. The exchange shows the careful consideration being given to both technical correctness and clear communication around this significant default change.
