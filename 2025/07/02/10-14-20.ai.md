This is a cover letter for a feature patch series proposing to make reftable the default Git ref storage backend, with a breaking change planned for Git 3.0. The series comes from Patrick Steinhardt and consists of two patches that work together to transition users to the reftable format.

The first patch adds documentation to BreakingChanges.adoc announcing the planned switch to reftable as the default backend in Git 3.0, which would be a breaking change requiring ecosystem support from libraries like Gitoxide, libgit2 and JGit. The second patch makes reftable backend the default immediately when the experimental features flag is enabled, allowing power users to test it more widely before the full transition.

The changes touch documentation (BreakingChanges and feature config docs), core setup code, and add new tests in t0001-init.sh. This appears to be a serious proposal building on prior discussion (referencing an earlier thread) that takes a measured approach to rolling out a significant change to Git's storage layer. The patches seem well-structured with documentation updates matching the code changes and new test coverage. The breaking change is clearly flagged and the experimental rollout strategy shows consideration for ecosystem impact.
