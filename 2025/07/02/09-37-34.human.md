This is a platform compatibility patch series updating FreeBSD build configurations, following up on the ongoing discussion about `memmem()` support policies. The two patches refine how Git handles FreeBSD-specific build settings, particularly around memory function implementations.

The first patch implements the consensus from the thread by setting `NO_MEMMEM` only for FreeBSD versions where the platform's `memmem()` is known to work correctly (version 12+). This actively prevents builds on older FreeBSD versions with problematic implementations, rather than just documenting the limitation. The second patch removes the now-obsolete `NO_UINTMAX_T` setting, which appears to be cleanup of legacy compatibility code.

The changes touch build system files across multiple build backends (Makefile, meson) and affect how Git detects and uses system functions on FreeBSD. The implementation follows the technical approach discussed in the thread, using version checking to determine when to use the system's `memmem()` versus Git's fallback implementation.

This appears to be the final implementation of the policy change the thread was converging toward, with clean separation between the functional change (patch 1) and unrelated cleanup (patch 2). The patches are focused and well-contained, modifying only build system files with straightforward version checks.
