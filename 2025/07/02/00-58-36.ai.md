This is a performance optimization patch series addressing an O(N^2) bottleneck in `git fetch --prune`. The core issue stems from an inefficient nested loop that checks for dangling refs, which becomes painfully slow in repositories with many refs (demonstrated by a case going from 470 seconds to under 1 second).

The series replaces the quadratic-time implementation with a more efficient O(N*logN) approach borrowed from `git remote prune`, which first sorts the refs to enable binary search. The v3 iteration focuses on cleaning up the API interface for dangling symref warnings, removing an obsolete function declaration, and dropping some questionable ref-shortening logic from earlier versions.

Key technical changes involve refactoring the `refs_warn_dangling_symrefs()` interface in refs.c and updating both fetch.c and remote.c to use the new version. The patch touches core refs handling code but maintains backward compatibility in the warning output format, with only minor improvements to dangling symref reporting clarity.
