This is the first patch in a two-part series proposing to make reftable the default ref storage backend in Git 3.0. The patch documents the planned breaking change in BreakingChanges.adoc while keeping the actual switch gated behind a `WITH_BREAKING_CHANGES` flag for now.

Patrick Steinhardt lays out a compelling case for the reftable format, highlighting several key advantages over the current files-based backend: better handling of case-sensitive and Unicode reference names on problematic filesystems, more efficient reference deletion and housekeeping, atomic multi-reference writes, and significantly better performance for bulk operations. The documentation is thorough and clearly explains the technical benefits.

The patch also emphasizes that ecosystem readiness is a prerequisite, specifically calling out the need for JGit, libgit2 and Gitoxide to support reftable before making it default. This shows good consideration for downstream impacts. The implementation includes a test verifying the default ref format behavior, though the actual switch is currently only enabled when `WITH_BREAKING_CHANGES` is set (which the second patch in the series will expose via the experimental flag).

This appears to be a well-considered first step in a major architectural change, with clear documentation of both the technical rationale and ecosystem coordination needs. The patch is clean and focused on just the documentation aspect while laying groundwork for the actual switch.
