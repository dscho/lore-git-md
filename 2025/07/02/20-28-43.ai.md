This is a bug report about unexpected behavior in `git log --diff-filter`. Eric Salem demonstrates that while `--diff-filter=D` correctly shows only commits that delete files, the lowercase `--diff-filter=d` (which should exclude deletion commits) shows no output unless combined with additional options like `--stat` or `--name-only`. The test case shows three commits: one creating file1.txt, one deleting it, and one creating file2.txt. The behavior contradicts the documented in the manual, which states lowercase letters should exclude matching changes.

Key technical details:
- Tested with Git 2.50.0
- Reproducible with simple repository setup (init, add/commit, add/commit, rm/commit)
- Affects the diff filtering logic when using exclusion filters
- Works correctly with `--diff-filter=D` but not `--diff-filter=d`
- Additional output options (`--stat`, `--name-only`) make the exclusion filter work

The report suggests either a documentation inaccuracy or a bug in the diff filtering implementation, particularly around how exclusion filters interact with default output formats. The behavior appears to be a regression or oversight in how excluded diffs are handled in the absence of explicit output formatting.
