This is a follow-up discussion about the recently merged `--skip-until` pagination feature for `git for-each-ref`. The thread has been examining both interface design and code formatting aspects post-merge.

Karthik Nayak responds to Phillip Wood's question about why the feature uses reference names rather than numeric offsets for pagination. The key technical rationale is performance - Git's reference backends are optimized for binary search by refname (O(log N)), while numeric offsets would require linear iteration (O(N)). This matters most in repositories with millions of references, where name-based seeking can skip large portions of the ref namespace efficiently.

The exchange highlights an important design tradeoff: while numeric offsets might be more intuitive for pagination use cases, the implementation leverages Git's existing ref storage optimizations. The discussion remains focused on practical considerations rather than proposing changes to the merged implementation.
