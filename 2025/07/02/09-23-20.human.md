This is the final patch in a 3-part series improving Git's clang-format integration, now ready for merging. The patch adds a meson build target for `git clang-format` to match the existing Makefile's 'style' target, completing the cross-build system support for Git's code formatting tools.

The change creates a new 'style' target in meson that runs `git clang-format` with the same parameters as the Makefile version, formatting only the files changed between the working directory and HEAD (unlike meson's built-in `clang-format` target which formats everything). The implementation properly checks for the `git-clang-format` program using meson's `find_program()` with the `native: true` flag as established in earlier discussion.

This patch represents the last piece of the series' technical work, following the earlier decisions to permanently enable the RemoveBracesLLVM rule and remove the ColumnLimit setting. The implementation incorporates feedback from the thread, including Patrick Steinhardt's recommendation about cross-compilation handling and Toon Claes' suggestion to store the program path in a variable. With Junio Hamano's approval on the series, this change provides consistent formatting support across both build systems.
