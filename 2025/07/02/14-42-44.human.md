This is a platform compatibility fix for BSD systems (excluding macOS). The patch corrects how Git calculates total system RAM when deciding whether to run automatic garbage collection (`git gc --auto`).

The issue stems from a 2018 change that introduced memory-based heuristics for gc. On BSD systems, the code was using the wrong type size for physical memory values from sysctl(), potentially causing incorrect memory calculations. The patch makes three improvements: (1) uses the correct type for physical_memory based on which sysctl constant is available, (2) ensures the variable is always initialized, and (3) adds an explicit cast to uint64_t for consistency.

The changes are straightforward and focused - just 14 lines modified in builtin/gc.c. The commit message clearly explains both the problem and solution, though it might help to mention which BSD systems are affected (the diff shows this handles HW_MEMSIZE, HW_PHYSMEM64, and HW_PHYSMEM cases). This appears to be a solid, low-risk fix for a real issue that could affect gc behavior on BSD platforms.
