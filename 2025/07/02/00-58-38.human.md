Refactoring patch improving the dangling symref warning interface in `git fetch --prune` optimization series.

This second patch in the v3 series cleans up the interface for reporting dangling symrefs during pruning operations. The author notes the previous implementation was fragile, requiring callers to pass printf-style format strings with positional arguments. The patch moves the formatting logic into the `refs_warn_dangling_symrefs()` function itself, making the interface more robust by having callers simply pass an indent string and dry-run flag instead.

The changes affect both `git fetch` and `git remote prune` operations, though the warning message content remains functionally identical - this is purely an internal API improvement. The patch follows through on the series' theme of cleaning up the ref handling code after the core O(N^2) performance fix was implemented in earlier patches.

The implementation looks clean and focused, with straightforward changes to the two call sites and the underlying warning infrastructure. This appears to be a logical next step after the performance optimization, making the code more maintainable while preserving all existing behavior.
