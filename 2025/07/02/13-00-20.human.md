This is a follow-up discussion about the `git last-modified` command's path handling behavior, specifically regarding how it displays directories versus files compared to `git ls-tree`.

Toon Claes acknowledges that the current behavior of `git last-modified` differs from expectations when showing directory modifications. While `git ls-tree` shows individual files when given specific paths (even under directories), `git last-modified` currently shows only the directory hash for directory paths. This came to light through testing by Kristoffer Haugsbakk and discussion with Junio C Hamano.

The email demonstrates the difference in output between the two commands when run against the same set of paths. Toon agrees this behavior should be changed and plans to address it in the next version of the patch series. This appears to be one of the final interface polish items remaining for this feature before it can move out of experimental status.

The discussion shows good responsiveness to user feedback about command behavior, with the maintainers and contributors working to ensure the new plumbing command follows Git's established conventions for path handling.
