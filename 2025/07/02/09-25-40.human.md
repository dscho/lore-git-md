This is a troubleshooting update in the ongoing Windows-specific regression investigation. Johannes Schindelin provides a correction to his earlier debugging instructions for Jörg Hohwiller, who has been experiencing multiple Git failures (lock file errors, reflog failures, and ref mismatches) since upgrading to Git 2.48.1 on Windows.

The key new information is that the build environment setup step was incomplete - Johannes clarifies that Jörg needed to run `sdk cd git` to properly initialize the Git source tree before attempting to build`. He provides the specific commands to fetch and checkout the v2.50.0.windows.2 tag to get the source into a buildable state.

This exchange shows the debugging effort remains blocked at the environment setup stage, preventing collection of the GDB backtraces needed to diagnose the root cause. The persistence of these issues across multiple Git versions (2.48.1 through 2.50.0) while working fine on 2.46.0 continues to point to a Windows-specific filesystem interaction regression, but without successful debugging the exact failure mechanism remains unclear.

The thread demonstrates both the challenges of remote debugging complex filesystem issues and the careful process needed to establish reproducible build environments for investigation. Johannes' patient corrections suggest this is a high-priority issue warranting continued attention from Windows Git maintainers.
