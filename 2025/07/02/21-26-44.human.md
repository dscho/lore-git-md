This is the first patch in a bugfix series addressing `git apply --intent-to-add` functionality that has been broken since Git 2.19. The patch fixes the core issue where the index wasn't being properly read when using `--intent-to-add` (-N), which caused the operation to incorrectly mark existing files as deleted.

The problem occurs because the code only read the index when checking it (`state->check_index`), but not when updating it (`state->update_index`). The fix makes the index reading conditional on either checking or updating, since both operations require the index to be loaded first. This restores the intended behavior where intent-to-add entries can be properly recorded without corrupting the existing index.

The patch is well-motivated with a detailed explanation of the problem and solution. It builds on previous work by Johannes Altmanninger and addresses a bug report from Ryan Hodges. The change itself is minimal (just one line modified in `apply.c`) but crucial for correct behavior.

This is part of a v2 series that has already seen some of Junio Hamano's architectural concerns addressed. The patch appears ready for inclusion, with the broader series waiting primarily on discussion about index writing conditions in patch 2.
