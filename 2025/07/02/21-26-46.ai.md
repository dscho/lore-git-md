Test patch in the `git apply --intent-to-add` bugfix series, expanding test coverage for index interactions.

This is the third patch in a 4-part series fixing `git apply -N` (intent-to-add) behavior. It adds two new test scenarios to `t4140-apply-ita.sh` that verify correct handling when applying patches to repositories with existing index entries. The first new test checks that a creation patch properly interacts with pre-existing index files, while the second verifies correct behavior when applying a complex patch containing both modifications to tracked files and new intent-to-add files.

The test file grows from 31 to 61 lines total, with the new tests specifically exercising edge cases that weren't covered in previous versions. The setup now includes a file (`committed-file`) that remains tracked throughout the tests, allowing verification of mixed scenarios where some files are modified while others are newly added with `-N`. The test assertions focus on verifying the index state after patch application using `git ls-files` and `git diff`.

This patch follows the series' established pattern of thorough test coverage for the intent-to-add functionality. It builds on the core fixes from patches 1-2 by validating their behavior in more complex real-world scenarios. The test cases appear well-constructed to catch regressions in the index handling logic that was refined in earlier patches.
