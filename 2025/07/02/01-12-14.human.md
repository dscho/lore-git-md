Refactoring patch in the performance optimization series for `git fetch --prune`. This is the second of three patches in v4 of the series, following the core optimization that addressed quadratic time complexity in dangling ref reporting.

The patch removes `refs_warn_dangling_symref()`, a helper function that was previously used to warn about a single dangling symref. The function is no longer needed after the refactoring in the first patch, which consolidated the warning logic to work with a list of refs rather than individual ones. The change is straightforward - deleting 17 lines of implementation and 2 lines of header declarations while keeping the more general `refs_warn_dangling_symrefs()` function.

This appears to be a mechanical cleanup following the architectural changes in the series' first patch, with no functional changes to Git's behavior. The removal is safe because all callers have been updated to use the list-based interface instead. The patch builds on the foundation established by the performance optimization while simplifying the codebase.
