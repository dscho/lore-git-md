The thread started with Eric Salem reporting unexpected behavior in `git log --diff-filter`, where using the lowercase `d` filter (to exclude deletion commits) produced no output unless combined with flags like `--stat`. The initial report suggested this might be a bug, as it contradicted the documentation's description of exclusion filters.

K Jayatheerth clarified that this is actually expected behavior, not a bug. The key insight is that diff filters only apply when Git actually computes diffs - the default output format doesn't generate diffs, so the filter has nothing to operate on. Flags like `--stat` work because they explicitly request diff computation. Jayatheerth provided two workarounds for Eric's use case of getting commit hashes while excluding deletions, both involving piping to `grep` after forcing diff generation.

The discussion reveals this is more a documentation clarity problem than an implementation issue. The behavior makes technical sense once you understand that diff filters require actual diff computation, which doesn't happen with minimal output formats. This affects all exclusion filters (lowercase letters), not just the deletion case. The thread suggests the documentation could be clearer about this interaction between output formats and filter application.
