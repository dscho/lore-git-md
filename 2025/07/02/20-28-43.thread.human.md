This thread reports unexpected behavior in `git log --diff-filter` where the lowercase exclusion filter `-d` fails to work as documented. Eric Salem demonstrates that while `--diff-filter=D` correctly shows only deletion commits, the documented exclusion form `--diff-filter=d` (which should show all commits except deletions) produces no output unless combined with additional output options like `--stat`. The test case uses a simple repository with three commits: creating file1.txt, deleting it, and creating file2.txt.

The behavior contradicts Git's documentation, which states lowercase filter letters should exclude matching changes. The issue appears to be in how diff filtering handles excluded changes when no explicit output format is specified. The report suggests this could be either a documentation inaccuracy or a bug in the diff filtering implementation, particularly around exclusion filters' interaction with output formatting. The problem is reproducible in Git 2.50.0 with a minimal test case.
