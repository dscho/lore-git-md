This is a follow-up discussion about the recently merged `--skip-until` pagination feature in `git for-each-ref`. Phillip Wood raises a practical concern about the feature's usability for pagination workflows. He points out that the current `--skip-until` approach requires knowing the exact name of the last ref from the previous batch, which may be cumbersome for users. 

Phillip suggests an alternative pagination interface using numeric offsets (`--start=N`) would be more intuitive, allowing users to directly specify ranges like "show refs 200-300" without tracking ref names between batches. This is presented as a friendly suggestion rather than a criticism, building on the already-merged functionality.

The comment doesn't propose any code changes but opens a design discussion about whether numeric pagination might be a useful complement to the name-based skipping that was just implemented. The thread context shows this is a post-merge discussion, so any changes would need to come as a follow-up patch series if the idea gains traction.
