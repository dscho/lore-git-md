This is a follow-up discussion about the recently merged `--skip-until` pagination feature for `git for-each-ref`. The thread has moved from implementation details to usability considerations, particularly around the interaction between `--skip-until` and `--sort`.

Karthik Nayak responds to Junio Hamano's questions about the feature's behavior with sorting. The key technical clarification is that `--skip-until` operates on the native ref storage order (after `sort_ref_dir()` processing) before any `--sort` is applied, which Junio notes could be confusing for users expecting the skip to happen after sorting. Karthik acknowledges this potential confusion and suggests possibly preventing `--skip-until` and `--sort` from being used together, though no code changes are proposed in this email.

The discussion reveals an important design consideration that wasn't fully addressed in the original implementation - the ordering of operations between seeking and sorting. While the technical implementation (using `ref_iterator_seek()` and backend adaptations) remains sound, this exchange surfaces a potential documentation gap and possible future interface refinement. The email also confirms the filesystem-backed ref storage already sorts via `sort_ref_dir()` before iteration, making the skip operation feasible.

For future reference in this thread, note the specific concern about operation ordering (`skip -> sort` vs desired `sort -> skip`), the mention of `sort_ref_dir()` as the current sorting mechanism, and the open question about whether to allow/disallow combining `--skip-until` with `--sort`. These points are likely to resurface in any future discussion about evolving the pagination interface.
