This is a follow-up discussion about the recently merged `--skip-until` pagination feature for `git for-each-ref`. The thread has moved from implementation details to usability considerations.

Junio Hamano raises an important point about the interaction between `--skip-until` and `--sort` options, noting that skipping currently happens in the native ref order before any sorting is applied. He suggests this behavior should be clearly documented to avoid confusion, as some users might expect skipping to occur after sorting.

Karthik Nayak acknowledges this oversight and expresses concern about the current behavior being potentially counterintuitive. He suggests it might be worth preventing the two options from being used together entirely, though no concrete proposal is made yet. The discussion also touches on implementation details like how filesystem` backends already sort references internally via `sort_ref_dir()`.

This exchange highlights a post-merge design consideration that wasn't fully explored during the initial review - whether name-based skipping in storage order provides the right mental model when combined with sorted output. The core functionality remains unchanged, but the thread may lead to future documentation updates or interface refinements based on real-world usage patterns.
