This is a documentation patch, the final part of a 4-patch series fixing `git apply --intent-to-add` behavior. The patch clarifies the man page description of `--intent-to-add` to avoid double negatives and better distinguish between `--index` and `--cached` modes. The changes make it clearer that the option is ignored when either `--index` or `--cached` is used (rather than just when `--index` isn't specified), and that it has no effect outside a Git repository. The wording change aligns with the technical fixes in earlier patches of the series, particularly the decision to silently ignore the option in non-repository contexts rather than erroring.

The documentation update is straightforward and uncontroversial, matching the technical behavior established by the previous patches in the series. It maintains consistency with the implementation while improving clarity. The patch follows the same pattern as the rest of the series in being focused and well-explained, though as documentation it naturally lacks test coverage (which was handled in patch 3). This appears ready for inclusion as the final piece of the series.
