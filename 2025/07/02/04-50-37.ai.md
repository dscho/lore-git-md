This is a technical note about case-insensitive filesystem edge cases in the ongoing `git pull --prune` discussion. Chris Torek expands the scope beyond simple case-folding conflicts to highlight macOS's Unicode normalization behavior, where different Unicode sequences representing the same character (like decomposed vs. precomposed umlauts) can collide on HFS+/APFS filesystems. He notes this creates additional refname collision scenarios beyond the ASCII case conflicts previously discussed, though he doesn't propose specific solutions. The observation complicates the strmap-based approach under consideration since it would need to handle both case folding and Unicode normalization equivalences. Chris's comment serves as a reminder that filesystem-specific behaviors may require more sophisticated conflict detection than currently proposed, though he stops short of rejecting any particular solution. This adds another dimension to the technical tradeoffs between the strmap interim fix and Patrick Steinhardt's advocated reftable backend solution.
