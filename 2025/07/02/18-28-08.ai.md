Bloom subsystem API naming discussion.

This is a follow-up in the bloom filter optimization thread, where Junio Hamano responds to Patrick Steinhardt's suggestion about function naming conventions. The exchange focuses on the proposed `bloom_keyvec_fill_key()` name versus the existing inconsistent naming in bloom.h's API.

Junio points out that the bloom.h header already has significant naming inconsistencies, listing several functions that don't follow the "bloom_" prefix convention. He specifically calls out `murmur3_seeded_v2()` as particularly problematic since it doesn't indicate its bloom filter connection and appears to be test-only code. This suggests the naming discussion might need to expand beyond just the new keyvec functions to address broader API consistency.

The email implies that if the project wants to enforce stricter naming conventions for the new keyvec functions, it should first clean up the existing API. This could mean either:
1. Accepting the inconsistency for now
2. Adding a preliminary cleanup patch to standardize names
3. Revisiting how test helpers interact with production bloom code

This is a design discussion rather than a code change, continuing the thread's focus on final polish items before merging the bloom optimization series. The exchange shows the maintainer's attention to API consistency even as the core functionality appears settled.
