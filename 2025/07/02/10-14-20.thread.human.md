Patrick Steinhardt is leading an effort to make reftable the default reference storage format in Git 3.0, with the v2 patch series now including an experimental feature flag path for early testing. The change would bring benefits like atomic writes, better Unicode handling, and performance improvements, but will only activate when WITH_BREAKING_CHANGES is set (for Git 3.0). The implementation uses a versioned default macro pattern in repository.h following Junio Hamano's suggestion, with a clear override hierarchy that respects both config (init.defaultRefFormat) and environment (GIT_DEFAULT_REF_FORMAT) settings.

Karthik Nayak has reviewed the latest patches, offering constructive suggestions to improve both documentation and implementation. He notes the BreakingChanges documentation should more explicitly mention the WITH_BREAKING_CHANGES conditional logic and could better highlight reftable's space efficiency. On the code side, he questions whether the default format initialization belongs in REPOSITORY_FORMAT_INIT rather than setup.c, though he agrees with the overall version-dependent macro approach.

The series has incorporated feedback from several key contributors - Justin Tobler helped clarify aspects of the implementation, while brian m. carlson suggested the version output mechanism. The main open items are confirmation of compatibility with alternative implementations (JGit and libgit2) and any edge cases that might emerge during experimental testing. The documentation is considered nearly complete pending real-world feedback from early adopters using the new experimental flag.
