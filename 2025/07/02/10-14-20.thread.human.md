This thread documents Patrick Steinardt's proposal to make reftable the default reference storage backend in Git 3.0, replacing the current files-based approach. The two-patch series includes both implementation changes (adding experimental flag support) and detailed documentation explaining the rationale for this breaking change, particularly focusing on benefits for case-insensitive filesystems and cross-platform compatibility.

The discussion has seen active participation from key contributors. Junio Hamano suggested consolidating breaking-change defaults in a dedicated header file, while Justin Tobler provided documentation feedback that Patrick has now incorporated - though they differ on whether to emphasize specific technical examples (Patrick's preference) or broader performance statements. brian m. carlson raised important points about ecosystem coordination and version output detection that remain to be addressed.

The current sticking points center on architectural decisions (header-based defaults vs direct conditionals) and ensuring the wider Git ecosystem (particularly JGit, libgit2 and Gitoxide) is prepared for this change. While the documentation appears nearly complete, the implementation path forward awaits resolution of these open questions and confirmation from other storage backend maintainers. The thread demonstrates the careful balancing act required when introducing breaking changes that affect the entire Git ecosystem.
