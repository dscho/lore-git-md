Patrick Steinhardt has proposed making reftable the default reference storage backend in Git 3.0, with a two-phase approach to ease the transition. The first patch documented the planned breaking change in BreakingChanges.adoc, while this second patch enables practical testing by making reftable the default when `feature.experimental=true` is set. The implementation carefully maintains existing override mechanisms through `init.defaultRefFormat` and `GIT_DEFAULT_REF_FORMAT` environment variables, with new tests verifying the priority of these controls.

The reftable format offers several advantages over the current files-based backend, including better case-sensitivity handling, Unicode support, atomic multi-ref operations, and improved performance for bulk operations. While the technical implementation appears solid with thorough test coverage, the main outstanding question is ecosystem readiness - particularly whether libgit2, JGit and Gitoxide will be prepared to handle the transition. The experimental flag approach allows broader testing while maintaining a clear path to the planned Git 3.0 change. So far the thread has only seen Patrick's initial patches; feedback from key reviewers like Karthik Nayak and storage experts will be important next steps in evaluating this significant change.
