Patrick Steinhardt's patch series to make reftable the default ref storage backend in Git 3.0 has progressed to its third version, now focusing on rollout strategy and ecosystem coordination. The technical implementation was settled in previous rounds, with consensus to set the default in repository_format_configure() while keeping REPOSITORY_FORMAT_INIT changes as future work.

The new version introduces a dual rollout approach: while reftable will become the official default in Git 3.0, users can opt-in immediately via the `feature.experimental` flag. This allows testing while ecosystem support (JGit, libgit2, Gitoxide) is confirmed. The series adds documentation of reftable's benefits - including case-sensitivity resolution, Unicode handling, performance gains, and space efficiency via compression - to BreakingChanges.adoc. New test coverage in t0001-init.sh verifies the experimental flag behavior.

Steinhardt maintains the series' tight focus, carrying forward key elements like REF_STORAGE_FORMAT_DEFAULT while avoiding scope creep into REPOSITORY_FORMAT_INIT unification. The implementation remains guarded by WITH_BREAKING_CHANGES for conditional compilation. Documentation refinements from prior reviews appear addressed, with compression benefits being the most notable addition in v3. The series is now in its final refinement phase, with all technical decisions confirmed and approvals from Junio Hamano and brian m. carlson still standing.
