Patrick Steinhardt's proposal to make reftable the default ref storage backend in Git 3.0 continues to evolve with constructive feedback. The two-patch series documents the planned breaking change and implements experimental flag support, with Junio C Hamano having already weighed in on both the architectural approach and documentation structure.

Justin Tobler has now provided focused improvements to the BreakingChanges.adoc documentation, suggesting two key refinements: correcting the description of macOS filesystem behavior (modern versions still default to case-insensitive) and adding a high-level summary of reftable's scaling benefits before the technical details. These changes aim to make the documentation both more accurate and more accessible to users evaluating this significant change.

While the implementation in setup.c and test coverage remain uncontested, the thread still awaits input from storage experts like Karthik Nayak and brian m. carlson on ecosystem compatibility, particularly regarding libgit2 and JGit integration. Junio's earlier architectural feedback about centralizing breaking change defaults also remains an open consideration for the implementation approach. The discussion continues to balance technical precision with clear communication of this major storage format transition.
