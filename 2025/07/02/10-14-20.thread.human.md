Patrick Steinhardt has proposed making reftable the default reference storage backend in Git 3.0, marking a significant change from the current files-based approach. The first patch in this series focuses on documenting the planned breaking change in BreakingChanges.adoc, outlining reftable's advantages: better case-sensitivity handling on Windows/macOS, improved Unicode support, efficient reference deletion via tombstones, automatic compaction, atomic multi-reference writes, and superior bulk operation performance. The documentation emphasizes this change depends on ecosystem readiness, particularly in JGit, libgit2 and Gitoxide.

The technical implementation includes preparatory changes in setup.c to make reftable the default when WITH_BREAKING_CHANGES is defined, though this isn't yet activated. A new test in t0001-init.sh verifies the default ref format behavior. This appears to be the start of a carefully planned transition strategy, though we're still waiting for initial review comments from other storage experts like Karthik Nayak (reftable co-author) and libgit2 maintainer Ed Thomson. The discussion is just beginning, with the actual implementation of the switch to follow in a subsequent patch.
