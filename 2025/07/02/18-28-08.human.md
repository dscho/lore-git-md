This is a code style discussion in the context of the ongoing bloom filter performance optimization series.

Junio Hamano points out an inconsistency in the bloom filter API naming conventions. While Patrick Steinhardt suggested renaming `fill_bloom_keyvec_key()` to follow the `bloom_keyvec_*` pattern, Junio notes that the existing bloom.h API already has several functions that don't follow this convention - some don't even have the "bloom_" prefix. He specifically calls out `murmur3_seeded_v2()` as particularly problematic since it doesn't indicate its connection to the bloom filter subsystem.

The email suggests this naming inconsistency should be addressed in a preliminary cleanup patch before the performance optimization series. Junio also questions whether `murmur3_seeded_v2()` needs to be exposed at all, as it appears to only be used for testing.

This is a minor but important style discussion that could affect how the bloom filter API evolves. The thread shows the careful attention to detail in Git's codebase maintenance, even for functions that are primarily internal implementation details. The naming convention issue doesn't block the performance work but would be good to address for consistency.
