Thread identity: Patch series from Patrick Steinhardt proposing to make reftable the default ref storage backend in Git 3.0, with an experimental flag to test it earlier. Current version is v1 with two patches - documentation and experimental flag activation.

Core problem/goal: Transition Git's reference storage from files-based to reftable format as the standard backend, requiring ecosystem coordination with libgit2, JGit and Gitoxide. The series takes a two-phase approach - documenting the planned breaking change for 3.0 while enabling early testing via experimental features.

Current status: First version includes (1) detailed documentation of planned 3.0 change in BreakingChanges.adoc, (2) makes reftable default when `feature.experimental=true`. Tests in t0001-init.sh verify experimental flag behavior. The implementation includes preparatory code in setup.c for future WITH_BREAKING_CHANGES activation.

Key technical details: Documents specific advantages of reftable over files backend: case-sensitivity resolution, Unicode handling, tombstone-based deletion, geometric compaction, atomic multi-ref writes, and bulk operation performance.
