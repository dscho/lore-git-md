Feature implementation for the reftable transition effort. This is the second patch in Patrick Steinhardt's series to make reftable the default ref storage backend, following the documentation patch that announced the planned breaking change for Git 3.0.

The patch enables reftable as the default ref storage when `feature.experimental=true` is set, aiming to expand testing before the full 3.0 transition. The implementation modifies `setup.c` to check the experimental flag during repo initialization, defaulting to reftable format unless overridden by `init.defaultRefFormat` or `GIT_DEFAULT_REF_FORMAT`. Documentation is updated in `feature.adoc` to explain the new behavior and reftable benefits (case-sensitivity handling, compression, performance).

Three new test cases in `t0001-init.sh` verify the behavior: (1) experimental flag enables reftable, (2) explicit `init.defaultRefFormat` overrides experimental, and (3) environment variable `GIT_DEFAULT_REF_FORMAT` takes highest priority. The tests follow the same pattern as existing ref format tests, maintaining consistency.

This appears to be a well-considered incremental step in the reftable transition strategy, providing a controlled rollout mechanism while maintaining all existing override capabilities. The patch builds cleanly on the series' first documentation patch and includes thorough test coverage of the new behavior. The main open question remains ecosystem readiness, which this experimental flag approach aims to address by broadening real-world usage.
