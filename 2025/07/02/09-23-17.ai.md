This is the final version of a 3-patch series improving Git's clang-format integration, now ready for merging. The series makes three key changes to reduce formatting noise and improve usability: (1) removes ColumnLimit to stop clang-format from line-wrapping (leaving that to developers), (2) permanently enables the RemoveBracesLLVM rule in .clang-format, and (3) adds a meson build target matching the existing Makefile's 'style' target for running git-clang-format.

The v3 iteration incorporates two final refinements from Toon Claes and Patrick Steinhardt: using `native: true` in meson's find_program() (a project convention for cross-compilation clarity) and storing the git-clang-format path in a variable rather than hardcoding. Sample diffs show the reduced formatting churn, particularly in string literal alignment and operator spacing (like changing `1<<7` to `1 << 7`). While the author considers making the style-check CI job required, that remains future work.

All technical discussions from earlier versions are resolved, including the dropped .editorconfig change (v2) and proper git-clang-format detection (v1). The series represents consensus improvements to Git's code formatting infrastructure while sidestepping the more philosophical line-length debates. Junio Hamano has already approved the changes, marking this as merge-ready.
