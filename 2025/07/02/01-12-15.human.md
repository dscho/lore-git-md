This is the final patch in a series optimizing `git fetch --prune` performance, focusing on cleaning up the dangling symref warning interface. The patch simplifies the `refs_warn_dangling_symrefs()` function by moving format strings into the function itself rather than passing them as parameters, making the interface more robust. The changes affect `builtin/fetch.c`, `builtin/remote.c`, and the refs subsystem.

The patch consolidates the warning message generation logic, which previously duplicated format strings at each call site. Now the function takes a simple prefix string and dry-run flag, handling the message formatting internally. This makes the interface less error-prone while maintaining the same user-facing behavior. The changes are mechanical and build on the earlier architectural improvements in the series.

This cleanup follows the major performance optimization in the first patch (which reduced prune time from 410s to 1s in large repos) and the removal of obsolete code in the second patch. The series has gone through multiple iterations (now at v4) with review feedback incorporated, and this final patch appears to be a straightforward improvement to the new interface.
