This is a discussion about the final patch in Ayush Chandekar's series to remove sparse-checkout-related global variables, specifically addressing the validation behavior of `sparse.expectfilesoutsideofpatterns`.

The key point of contention is whether config validation should maintain its original fail-fast behavior (erroring immediately on invalid input) or follow the pattern of other repo_settings (silently using a default value). Ayush argues the latter is consistent with how other migrated configurations behave, while Junio questions whether silently accepting invalid input provides a good user experience.

This represents the last remaining decision point in the otherwise complete series. The technical work to localize this variable and remove its global declaration is uncontroversial, but the behavioral change in validation timing (from startup to mid-operation) may impact users who rely on immediate feedback about config errors. The discussion suggests this could influence future similar migrations regarding config validation patterns when moving away from globals.

The patch itself:
- Removes the global `sparse_expect_files_outside_of_patterns` variable
- Localizes its use to `clear_skip_worktree_from_present_files()`
- Changes validation timing to match other repo_settings behavior
- Completes the series' goal of eliminating sparse-checkout globals

Technical details:
- Variable now accessed via `repo->settings.sparse_checkout` after `prepare_repo_settings()`
- Single-use configs read via `repo_config_get_bool()` when needed
- Validation now happens during operation rather than at startup
- Follows the established pattern for other migrated settings
