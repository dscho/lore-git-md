This is the second patch in a two-part series cleaning up FreeBSD compatibility code, specifically removing obsolete `NO_UINTMAX_T` support. The patch follows the first one that implemented version-aware `memmem()` handling for FreeBSD.

The change removes all traces of `NO_UINTMAX_T` from the build system, including Makefile definitions, configure.ac checks, and meson.build tests. The commit message notes this is safe because the codebase has already moved to C99 (which guarantees uintmax_t) and the last user of this compatibility define was removed in a previous commit. The removal is comprehensive, touching all three build systems (Makefile, autoconf, and meson) in parallel.

Key technical details removed include:
- Makefile's uintmax_t fallback to uint32_t
- configure.ac's AC_CHECK_TYPE for uintmax_t
- meson.build's compiler check for uintmax_t support
- Related substitution variables and conditional compilation flags

This patch represents the final step in cleaning up FreeBSD 4.x era compatibility code, following the thread's consensus to drop support for obsolete versions. The changes are straightforward deletions with no behavior impact on modern systems, aligning with the series' goal of simplifying the build system while maintaining compatibility with supported FreeBSD versions.
