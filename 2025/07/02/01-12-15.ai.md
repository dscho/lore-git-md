This is the third and final patch in a performance optimization series for `git fetch --prune`. The series addresses quadratic time complexity in dangling ref reporting, with the main optimization in patch 1 (already reviewed by Jacob Keller) implementing a sorted prune list with binary search.

This patch cleans up the interface for `refs_warn_dangling_symrefs()`, which had become fragile due to printf-formatting strings with positional arguments. The changes move the format strings into the function itself and pass a prefix string and dry_run flag instead. This makes the interface safer and more maintainable by:
- Eliminating duplicate format strings in `builtin/fetch.c` and `builtin/remote.c`
- Consolidating the dry-run vs actual deletion message logic inside the warning function
- Maintaining the same output format while making the implementation more robust

The changes touch the same files modified in the earlier patches (`builtin/fetch.c`, `builtin/remote.c`, `refs.c`, `refs.h`), completing the architectural improvements started in patch 1. This appears to be a straightforward cleanup following the more substantial performance changes, with no visible controversy or outstanding issues. The patch maintains all existing functionality while making the code more maintainable.
