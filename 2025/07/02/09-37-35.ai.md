This is a platform compatibility patch that implements version-aware `memmem()` handling for FreeBSD as part of the ongoing build system modernization effort. It's the first of two patches in this version of the series.

The patch changes how Git handles `memmem()` on FreeBSD by only disabling the system's `memmem()` (via `NO_MEMMEM`) for versions older than FreeBSD 12, rather than blanket-disabling it for all FreeBSD versions. The commit message explains the historical context: FreeBSD's `memmem()` had functional issues until version 10.4 (EOL 2018) and performance issues until 11.4 (EOL 2021). The new policy draws the line at FreeBSD 12+ for using the system implementation.

Key technical changes include:
- Replaces unconditional `NO_MEMMEM = YesPlease` with a version check using shell expression `test $${v%%.*} -lt 12`
- Uses `UnfortunatelyYes` instead of `YesPlease` for the `NO_MEMMEM` value (a stylistic change to indicate this is a fallback)
- Removes FreeBSD 4.x specific code (PTHREAD_LIBS, NO_UINTMAX_T, NO_STRTOUMAX) that was previously guarded by version check
- Maintains other FreeBSD-specific settings like paths and flags

The patch follows the thread's direction of enforcing version requirements through build system changes while cleaning up obsolete compatibility code. It implements the consensus approach discussed earlier, with input from Brad Smith and Brian m. carlson. The change affects both the Makefile and meson.build systems (though the meson changes appear in the second patch of the series).
