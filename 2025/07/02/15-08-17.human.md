Feature patch in the SHA-256 transition series, addressing behavior of commands outside repositories. This is part of brian m. carlson's larger effort to make SHA-256 the default hash algorithm when Git is built with WITH_BREAKING_CHANGES.

The patch changes commands that can operate both inside and outside repositories (like `git index-pack` and `git ls-remote`) to use the default hash algorithm (GIT_HASH_DEFAULT) rather than hardcoding SHA-1 when no repository is present. While currently this makes no functional difference (since the default is still SHA-1), it prepares for a future where SHA-256 becomes the default.

Patrick Steinhardt had suggested using GIT_HASH_SHA1_LEGACY instead for script compatibility, but brian m. carlson argues that commands dealing with repository objects should use the current default to avoid forcing users to specify object formats long after the transition. Steinhardt acknowledges this tradeoff, noting the initial pain for edge cases but agreeing the change will become more useful over time.

This appears to be one of the few remaining points of discussion in an otherwise technically complete series that has already been approved by both Steinhardt and Junio C Hamano. The debate centers on balancing backward compatibility with forward-looking defaults for commands that work with repository objects.
