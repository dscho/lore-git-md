This is a technical discussion about the BSD memory detection fix for `git gc --auto`. Junio Hamano is reviewing Carlo Marcelo Arenas Belón's v3 patch and raising concerns about potential endianness issues in the handling of partial `sysctl()` returns.

Junio questions whether the current approach of bit-shifting partial results is safe across different byte orders. He notes that on big-endian systems, the shifting might discard meaningful data, while on 32-bit little-endian systems with signed types, it could introduce incorrect sign extension. He suggests reverting to the v2 approach of only accepting full 8-byte returns when using a uint64_t variable.

This email represents the final review feedback on a series that has already seen multiple iterations addressing BSD-specific memory calculation issues. The core problem (incorrect RAM detection on BSD systems) was previously solved, but this exchange shows the careful attention to edge cases that characterizes Git's code review process.
