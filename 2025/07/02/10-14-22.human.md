Feature patch enabling experimental reftable backend testing. This is the second patch in Patrick Steinhardt's series to transition Git's reference storage to the reftable format, following the documentation patch in v1.

The patch makes reftable the default ref storage format when `feature.experimental=true` is set, providing a way to test the upcoming Git 3.0 change more widely before the full switch. The implementation modifies the ref backend selection logic in setup.c to check the experimental flag when no explicit format is specified. Three new tests verify the behavior: confirming reftable is used with experimental mode, that explicit config overrides the experimental default, and that environment variables take highest precedence.

The commit message notes reftable has proven stable in limited testing (including at GitLab) but needs broader validation. This approach balances risk by expanding testing while maintaining user control - the experimental flag acts as an opt-in for early adopters, while the documented Git 3.0 plan remains unchanged. The clean separation of concerns and thorough test coverage suggest this is a well-considered step in the reftable migration strategy.
