This is a code review comment on a performance optimization patch series for Git's pathspec bloom filters. Patrick Steinhardt provides feedback on the first patch in the series, which introduces a new `struct bloom_keyvec` to handle multiple bloom keys more efficiently.

The review focuses on naming conventions and coding style issues. Patrick notes the patch deviates from Git's standard patterns - functions operating on the new struct should follow the `bloom_keyvec_<verb>()` naming pattern rather than `create_*/destroy_*`. He also questions why the patch converts a loop to a single call in revision.c when the next patch changes it back, and points out an opportunity to fix an existing `int` type that should probably be `size_t`.

While the technical approach of the patch series (to optimize combined pathspec queries) appears sound based on the thread context, this review highlights some rough edges in the implementation details that could be cleaned up. The feedback is constructive and focused on making the code more idiomatic for the Git codebase. The issues raised don't appear to affect the core functionality but would improve maintainability.
