This is the first patch in a two-part series proposing to make reftable the default ref storage backend in Git 3.0. The patch focuses on documenting the planned breaking change while leaving the actual switch to a follow-up patch.

The commit adds a detailed section to BreakingChanges.adoc explaining the rationale for switching from the files-based backend to reftable. It lists several key advantages: resolving case-sensitivity issues on Windows/macOS, better handling of Unicode references, more efficient reference deletion via tombstones, automatic geometric compaction for better performance, atomic multi-reference writes, and significantly better performance for bulk operations. The documentation explicitly notes this change depends on ecosystem readiness, particularly support in JGit, libgit2 and Gitoxide.

The patch also includes preparatory code changes in setup.c that will make reftable the default when WITH_BREAKING_CHANGES is defined, though this isn't yet activated in this patch. A new test in t0001-init.sh verifies the default ref format behavior. The implementation appears thorough, with clear documentation of both technical benefits and ecosystem considerations. This looks like a well-prepared first step in a carefully planned transition strategy.
