This is a follow-up discussion in the thread about the `--skip-until` pagination feature for `git for-each-ref`. The email addresses Phillip Wood's concern about the interface design, specifically comparing name-based skipping (`--skip-until`) versus numeric offset skipping (`--start`).

Karthik Nayak explains the current implementation's performance rationale: using reference names allows leveraging the existing binary search capability in Git's ref backends (files, packed, reftable) for O(log N) performance, while numeric offsets would require O(N) iteration. The performance difference becomes significant in repositories with ~1 million refs, though negligible in smaller ones (~1000 refs).

The discussion highlights a key design tradeoff in the merged feature - better performance for large scales versus potentially more intuitive numeric pagination. No code changes are proposed here; this is purely an interface discussion about the already-merged functionality. The exchange shows maintainers considering real-world usability implications of the technical implementation choices.
