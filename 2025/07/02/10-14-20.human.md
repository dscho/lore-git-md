This is a feature proposal that would make the reftable backend the default for Git repositories, presented as a breaking change for Git 3.0. Patrick Steinhardt proposes a two-patch series to both announce this planned change and enable reftable by default for users who opt into experimental features.

The first patch adds documentation to BreakingChanges.adoc, signaling the intent to switch to reftable as the default backend in Git 3.0. The second patch modifies the initialization logic to use reftable when `feature.experimental` is enabled, giving power users early access while gathering real-world testing data. The commit message references a prior discussion thread (linked via Message-ID) that motivated this proposal.

The approach is cautious - making the change opt-in first via experimental features before any hard switch in Git 3.0. The author notes this depends on ecosystem support from major Git implementations (Gitoxide, libgit2, JGit). The patches include both documentation updates and test coverage in t0001-init.sh, suggesting this is a well-prepared proposal rather than just an idea. This would be a significant change to Git's core behavior, but one that has been discussed in the community before.
