Initial analysis showed the uppercase inclusion filter `D` works correctly while exclusion filters only take effect when combined with diff-generating flags like `--stat`. K Jayatheerth clarified this is expected - diff filters only apply when Git computes diffs, which doesn't happen with minimal output formats like `%H`. The behavior is not a bug but rather a documentation clarity issue regarding the interaction between output formats and diff generation. 

Key details: exclusion filters (a-z) require explicit diff computation to have any effect. Jayatheerth provided two workarounds for Eric's use case of getting commit hashes while excluding deletions: using `--name-only` piped to `grep` to filter empty lines, or using `--stat` with more complex `grep` filtering. The technical insight is that this affects all exclusion filters with minimal output formats, not just the deletion case. The thread suggests documentation could be improved to better explain this dependency between output format selection and filter application. The core implementation is working as designed, though the design may not match user expectations from reading the current documentation.
