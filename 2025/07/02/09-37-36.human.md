This is the second patch in a two-part series cleaning up FreeBSD compatibility code, specifically removing obsolete build flags. The patch removes `NO_UINTMAX_T` support since the codebase no longer needs it (the last user was removed in a previous commit) and Git now assumes C99 compliance which guarantees `uintmax_t`.

The changes remove the flag from all three build systems (Makefile, configure.ac, and meson.build), showing thorough cleanup. The patch is straightforward and appears well-justified - it's removing dead code rather than changing functionality. Since this was part of an agreed-upon cleanup effort discussed earlier in the thread, it likely won't be controversial. The patch follows the same pattern as the first in the series (which handled `memmem()` compatibility) by making parallel changes across all build systems.
