This is a bug report about unexpected behavior in `git log --diff-filter`. Eric Salem demonstrates that while `--diff-filter=D` correctly shows commits that delete files, the lowercase `--diff-filter=d` (which should exclude deletions) shows no output unless combined with additional options like `--stat` or `--name-only`. 

The email includes a clear reproduction case showing the issue occurs with Git 2.50.0. The test creates three commits (adding file1, deleting file1, adding file2) and shows the lowercase `d` filter fails to exclude deletion commits as documented, unless combined with other output-affecting options. 

This appears to be a legitimate bug in the diff-filter implementation where the exclusion logic doesn't work properly for the default output format. The report is well-structured with complete reproduction steps and version information, making it easy to investigate.
