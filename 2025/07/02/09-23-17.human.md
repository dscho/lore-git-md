**Finalized clang-format improvements for Git**

This is the third and final version of a series that refines Git's clang-format integration, now ready for merging. The patches make three key improvements to reduce formatting noise and improve usability:

1. Removes the ColumnLimit rule entirely, shifting line-wrapping decisions to developers rather than automated formatting. This eliminates many false positives where clang-format would unnecessarily reformat lines.

2. Makes the RemoveBracesLLVM rule permanent by moving it into the main .clang-format configuration. This rule helps clean up redundant braces in certain cases.

3. Adds meson build system support through a new 'style' target that matches the existing Makefile functionality, allowing developers to run `meson compile style` for formatting checks. The implementation now properly uses `native: true` for cross-compilation scenarios and references the found git-clang-format program directly.

The series has evolved through community feedback, with earlier versions dropping an editorconfig change that caused unwanted line combining and refining the meson implementation details. Sample diffs show the improvements in action, particularly in files like builtin/diff.c where the formatting changes are now more minimal and focused. While the author considers making the style check a required CI job, that remains future work. The patches have reached consensus and Junio Hamano has indicated they are ready for inclusion.
