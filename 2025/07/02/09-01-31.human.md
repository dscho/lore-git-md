This is a discussion about the final patch in a refactoring series that moves sparse-checkout configuration from global variables to repository settings. Phillip Wood points out a subtle but important behavioral change in how invalid config values are handled.

The patch changes `sparse.expectfilesoutsideofpatterns` to be parsed on-demand in `clear_skip_worktree_from_present_files()` rather than at startup via `git_default_config()`. Phillip notes this means invalid values will now cause Git to die mid-operation rather than failing immediately at startup, which is a worse user experience. 

Ayush had responded that other settings moved to `repo_settings` use fallback values for invalid inputs, but Phillip clarifies this case is different - the config is being read directly via `git_config_bool()` which will die on invalid values, and there's no opportunity for commands to validate the config early like they can with `prepare_repo_settings()`.

This appears to be the last open issue in the otherwise well-reviewed series. The discussion highlights the careful attention needed when changing config parsing behavior, even in refactoring work. Phillip's observation suggests the patch might need adjustment to maintain the current validation timing, though the series as a whole represents significant progress in removing global variables.
