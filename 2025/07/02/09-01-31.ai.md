This is a discussion about the final patch in a refactoring series that moves sparse-checkout configuration from global variables to repository settings. Phillip Wood points out a subtle but important behavioral change in how invalid config values are handled.

The key issue is that the patch changes when Git validates `sparse.expectfilesoutsideofpatterns` values. Previously, invalid values would cause Git to error out immediately during startup via `git_default_config()`. Now, validation only happens when `clear_skip_worktree_from_present_files()` is called, which may be mid-operation. Phillip notes this could lead to commands failing partway through rather than failing fast.

Ayush responds that this matches the pattern used for other settings moved to `repo_settings`, where invalid values get defaults rather than causing errors. However, Phillip clarifies this isn't actually the case here - the patch uses direct `repo_config_get_bool()` which will still `die()` on invalid values, just at a different time. He also notes that while many commands call `prepare_repo_settings()` early to fail fast, this patch provides no such option.

This discussion highlights a tension between consistency in the refactoring approach (treating all settings similarly) and maintaining existing user experience (failing fast on config errors). The thread shows the architectural decision to centralize config handling in `repo_settings` may need reconsideration for this particular case to preserve the original validation timing behavior.
