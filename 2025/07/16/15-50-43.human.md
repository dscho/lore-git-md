This is a follow-up discussion about the pretty-print indentation changes in the `git last-modified` series. Junio C Hamano points out a potential issue with Toon Claes' patch that adds a `no_indent` flag to suppress commit message indentation.

The concern is that simply disabling indentation via `pretty_print_commit()` may not be sufficient for the `--extended` format's goal of faithful output reproduction, since that function performs many other transformations beyond just indentation. Junio suggests the implementation might need to avoid calling `pretty_print_commit()` entirely for this use case rather than just suppressing indentation.

This comes as part of the final polishing for the `git last-modified` feature, which is otherwise complete with comprehensive tests and performance benchmarks. The series introduces a new command for tracking tree-level path modifications using Bloom filters, with an `--extended` output format designed for machine parsing. While the core functionality is solid, this exchange shows there's still some refinement needed in the pretty-printing implementation details.
