This is a performance optimization thread discussing the conversion of commit traversal to use priority queues (prio_queue). The email from Junio C Hamano confirms that Jeff King has addressed the final outstanding question about tie-breaking behavior when commits have identical timestamps. King explains that the prio_queue implementation maintains insertion order as a tie-breaker, matching the original commit_list_insert_by_date() behavior. This confirmation resolves the last technical concern about the patch series.

The series, from René Scharfe, refactors commit traversal to use prio_queue for better worst-case performance (92% faster for pathological histories) while recovering the initial 1% regression in normal cases through subsequent optimizations. Key changes include introducing prio_queue_replace() and applying it to first parent processing with a get_pending flag. The optimization particularly benefits operations like `:/` rev-parse and fetch's mark_recent_complete_commits() with many refs.

With this confirmation of stable ordering semantics, the series appears technically complete.
