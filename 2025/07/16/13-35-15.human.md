Performance optimization for `git last-modified` using Bloom filters. This patch from Toon Claes adds Bloom filter support to skip unnecessary diff computations when checking path modifications. The key optimization checks Bloom filters first - if they indicate no paths were modified at a commit, it can skip the expensive diff calculation entirely.

The implementation adds Bloom filter checks via a new `maybe_changed_path()` helper, with proper memory management for the Bloom keys. Performance tests show dramatic improvements: a 50.6% speedup for top-level checks and 36.4% for subdirectory checks, though recursive checks see minimal benefit (0.4%) since they must still examine most commits. 

This builds on Taylor Blau's prior Bloom filter work and integrates cleanly with the existing `last-modified` infrastructure. The patch appears well-tested and follows the established pattern for Bloom filter usage in Git. It's part of the larger `last-modified` series that's now in its fifth iteration with maintainer approval on the core design.
