This is a status update on the compression level configuration discussion within the larger "pluggable loose object backends" series. Patrick Steinhardt reports back after attempting Phillip Wood's suggestion to call `prepare_repo_settings()` within `repo_config()` to maintain consistent config parsing timing.

The experiment revealed significant implementation challenges, particularly around `core.shared_repository` which is widely used throughout the codebase. After 15 patches worth of attempted fixes, Steinhardt concludes the approach isn't currently viable and proposes dropping the last three patches of the series (including this compression level migration) to unblock progress on the main refactoring work.

This email marks a pivot point in the thread - the practical difficulties of Wood's proposed solution have been demonstrated, leading to a tactical retreat from the compression level migration while preserving the core repository-agnostic changes. The discussion highlights the complexity of Git's configuration system and the tradeoffs between architectural purity and practical progress. The `core.shared_repository` issue emerges as a key technical blocker that would need to be addressed for any comprehensive solution to config parsing timing.
