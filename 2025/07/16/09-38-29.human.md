This is the second patch in a refactoring series to standardize Git's use of C99 `bool` type for predicate functions. The patch converts two case-insensitive string prefix functions (`skip_iprefix` and `skip_iprefix_mem`) from returning `int` to `bool`, matching their case-sensitive counterparts that were already converted in an earlier experimental change.

The change is purely mechanical - replacing `int` with `bool` return types and updating the `1`/`0` return values to `true`/`false`. The author notes this makes the predicate nature of these functions clearer in the type signature. This follows the successful 18-month experimental period for using `bool` that was documented in patch 1/3 of the series.

The patch has already undergone thorough review from multiple core maintainers, with all feedback addressed in previous iterations. As part of a fully-acked series that's ready for merging, this represents the final step in formalizing Git's use of `bool` for predicate functions after careful, conservative adoption. The changes are low-risk with no behavior impact, just improved type clarity.
