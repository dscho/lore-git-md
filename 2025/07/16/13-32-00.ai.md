This is the v5 cover letter for the `git last-modified` feature series, introducing a new plumbing command to track when paths were last modified in a repository's history. The series has evolved through multiple versions with key design decisions now settled, including the command name (`last-modified` instead of `blame-tree`) and path handling behavior (following `git diff-tree` conventions).

The core implementation provides tree-level modification tracking (as opposed to line-by-line like `git blame`), with Bloom filter support for performance. The command includes `-` and `-r` flags for recursive operation and tree entry display, plus a new `--extended` format option in v5 to better support forge-style tree views. Performance benchmarks show significant speedups (55% for top-level checks) when Bloom filters are available.

Key changes in v5:
1. Added `--extended` format support (with preparatory changes to `pretty.[ch]`)
2. Removed test sorting that was previously required
3. Added a fixup commit for upcoming Bloom filter API changes
4. Consolidated implementation into `builtin/last-modified.c` (from separate library code)

The series is technically complete with all major feedback addressed, though the Bloom filter API change remains pending (a trivial 3-line update when that lands). Performance characteristics are documented with both improvements and regressions noted where certain optimizations were excluded for further study. The implementation includes comprehensive tests (basic cases, merges, pathspecs) and performance benchmarking.

The cover letter clearly positions this as a plumbing command for use by forges and tools rather than end users, with the extended format specifically targeting forge tree views. All major technical decisions have maintainer approval, and the series appears ready for final review.
