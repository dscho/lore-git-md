This is a design discussion about the output format for the `git last-modified --extended` command, specifically focusing on how commit messages should be formatted and terminated in both regular and NUL-delimited modes.

Junio C Hamano raises several concerns about the current documentation and implementation of the extended output format. He notes that the "unless" phrasing in the documentation is confusing and suggests "if" would be clearer. More importantly, he identifies fundamental issues with how message termination is handled in both formats.

For the non-NUL format, he questions how a reader would detect the end of the message, suggesting it currently relies on either EOF or an unindented line (which could be problematic if pretty-printing behavior changes). For the NUL format, he points out the inconsistency in terminators (some fields use LF while others use NUL) and the potential ambiguity if a message starts with "path ".

Hamano also considers future extensibility, suggesting the message should be explicitly tagged (like "message SP <message>") rather than being a special case, and questions whether the current design allows for adding new fields after the message. These concerns suggest the output format may need more rigorous specification around field ordering, termination, and future compatibility.

This feedback comes at a critical point in the series' development, where all other technical aspects have been resolved but the extended output format's design needs finalization. The discussion touches on both immediate implementation details (termination markers) and long-term maintainability (field ordering).
