This is the second patch in a v3 series implementing SHA-256 repository support in git-gui, completing the feature work started in patch 1/2. The changes make git-gui's UI components properly handle both SHA-1 and SHA-256 hash lengths throughout the interface.

Key technical changes include:
- Adds a global `$hashlength` variable (40 or 64) determined at startup via `git rev-parse --show-object-format`
- Replaces hardcoded SHA-1 length (40) with `$hashlength` throughout, using Tcl's `string map` for regex patterns
- Generates `$nullid` and `$nullid2` dynamically based on hash length
- Special-cases the repository picker dialog which runs before hash length is known
- Updates blame interface, commit validation, branch deletion, and repository cloning to handle variable hash lengths

The patch touches multiple UI components including blame display, commit interface, repository selection, and branch operations. It builds on core Git's existing SHA-256 infrastructure while maintaining backward compatibility with SHA-1 repositories. The v3 changes from v2 include additional documentation, fixes to null ID generation, and improved handling of abbreviated IDs in blame.

This appears to be a thorough implementation that systematically addresses all hash-length-sensitive operations in git-gui. The changes are focused and well-explained, with careful attention to edge cases like the repository picker dialog that can't use the global hash length variable. The patch series as a whole brings git-gui to feature parity with command-line Git's SHA-256 support.
