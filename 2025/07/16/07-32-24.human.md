This is a refactoring patch for git-gui, part of a 2-patch series (position 1/2) preparing for SHA-256 repository support. The change standardizes on using the `$nullid` variable instead of the equivalent `$null_sha1` throughout the git-gui codebase.

The patch makes straightforward mechanical replacements in two files (`git-gui.sh` and `checkout_op.tcl`), removing the redundant `null_sha1` variable declaration and updating all references to use `nullid` instead. The commit message explains that both variables pointed to the same content (a string of 40 zeros representing the null SHA-1 hash).

This appears to be a clean, focused change with a clear motivation - reducing variable aliasing before introducing SHA-256 support. The patch is small (5 lines changed) and touches only the minimal necessary code paths. While part of a larger effort, this particular change stands on its own as a simple cleanup that shouldn't introduce any behavior changes.
