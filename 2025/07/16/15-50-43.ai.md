This is a follow-up discussion about the pretty-printing changes in the `git last-modified` series, specifically regarding the `--extended` output format. Junio C Hamano points out a potential issue with the approach taken in patch 4/6 to suppress indentation in the pretty-printed output.

The key observation is that the current patch only addresses indentation via a new `no_indent` flag in `struct pretty_print_context`, but the `pretty_print_commit()` function does much more than just indentation (including re-encoding, email header processing, etc.). For the `--extended` format which aims for faithful original output, simply disabling indentation may not be sufficient - the entire pretty-printing machinery might need to be bypassed.

The discussion suggests the implementation may need revisiting to either:
1. More comprehensively control pretty-printing behavior for the extended format case, or
2. Avoid calling `pretty_print_commit()` entirely when `--extended` is requested

This is a design-level concern about the architectural approach rather than a mechanical issue with the patch itself. The thread context shows this is part of the final polishing phase for the `last-modified` series, where the core functionality is otherwise complete and reviewed.
