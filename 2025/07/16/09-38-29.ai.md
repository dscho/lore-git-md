This is the second patch in a refactoring series standardizing the use of C99 `bool` for predicate functions in Git's codebase. The patch converts two case-insensitive string prefix matching functions (`skip_iprefix()` and `skip_iprefix_mem()`) in `git-compat-util.h` from returning `int` to `bool`, aligning them with their case-sensitive counterparts that were converted in an earlier experimental change (commit 8277dbe987).

The changes are purely mechanical type signature updates - replacing `int` with `bool` return types and adjusting the `1`/`0` return values to `true`/`false`. The patch maintains identical behavior while making the predicate nature of these functions more explicit through their return type. The commit message notes this clarity improvement as the primary motivation.

This patch follows the first one which updated CodingGuidelines to formally permit `bool` usage, and precedes a third patch that will convert `strbuf` methods. The series has already received thorough review from multiple core maintainers addressing both technical and stylistic aspects, with all feedback incorporated in this v3 submission. The changes affect 12 lines across 6 hunks in a single header file, with no impact on functionality or performance.
