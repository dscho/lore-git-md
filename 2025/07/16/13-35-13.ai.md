This is the first patch in the v5 series introducing the new `git last-modified` plumbing command, which tracks when paths were last modified at tree-level (unlike line-by-line `git blame`). The command uses a `last_modified_entry` hashmap structure and revision walking to compare tree states.

The patch adds core infrastructure:
- New `builtin/last-modified.c` implementing the command with `-r` (recursive) and `-t` (tree entries) flags
- Documentation in `git-last-modified.adoc` marking it as EXPERIMENTAL
- Comprehensive test suite in `t/t8020-last-modified.sh` covering:
  - Basic file/directory tracking
  - Merge scenarios
  - Pathspec handling
  - Boundary cases

Key technical details:
- Uses `hashmap` with `last_modified_entry` structs to track paths
- Implements `mark_path()` for change detection logic
- Follows `git diff-tree` path handling conventions
- Output format shows commit hash and path (NUL or newline separated)

The implementation builds on prior work from Jeff King and Ævar Arnfjörð Bjarmason, with the v5 series having settled on the `last-modified` name (originally `blame-tree`) and finalizing the core behavior before later adding Bloom filter optimizations. The tests demonstrate correct handling of merges, including cases where changes are later reverted or conflict-resolved.
