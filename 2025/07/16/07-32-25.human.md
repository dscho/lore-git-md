This is the second patch in a series adding SHA-256 repository support to git-gui, completing the graphical interface's compatibility with Git's SHA-256 hash algorithm. The patch systematically replaces SHA-1-specific assumptions throughout the UI components, introducing a `$hashlength` variable (40 for SHA-1, 64 for SHA-256) and updating all hash-related operations to use it.

Key changes include updating the blame interface, repository picker, commit handling, and branch deletion to work with variable-length hashes. The patch handles several subtle cases like regex pattern matching (using string substitution to avoid hardcoded lengths) and null ID generation. One notable edge case is the repository picker dialog, which must work before the hash length is known, requiring special handling of the initial hash matching.

The patch appears thorough, with changes spanning multiple UI components and careful attention to hash-length-agnostic operations. This v3 iteration includes refinements from previous feedback, such as fixing null ID generation and improving the blame interface's abbreviated hash checking. The changes are part of Git's broader SHA-256 transition effort, bringing git-gui to parity with the command-line interface's existing SHA-256 support.
