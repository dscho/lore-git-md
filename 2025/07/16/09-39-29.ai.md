Performance optimization patch series (part 1/3) converting commit traversal to use priority queues. This first patch replaces commit_list_insert_by_date() with a prio_queue in pop_most_recent_commit() to improve worst-case performance from O(n^2) to O(log n), showing a 92% speedup in pathological test cases (50% merges/50% root commits) while incurring a 1% performance hit on normal Git history.

The patch modifies commit.h's interface, changing the parameter from commit_list** to prio_queue*, with callers now responsible for proper queue configuration. Review discussion confirms the change maintains existing ordering semantics, particularly for commits with identical timestamps (FIFO ordering preserved via insertion order). Performance tests in t/perf/p1501-rev-parse-oneline.sh demonstrate the improvements, with pathological cases being the primary beneficiaries.

Key technical details include:
- Modified files: commit.h, commit.c, fetch-pack.c, object-name.c, walker.c
- New test coverage in t/perf/p1501-rev-parse-oneline.sh
- Caller responsibility shift for maintaining ordering via prio_queue configuration
- Preserved timestamp tie-breaking behavior matching original commit_list_insert_by_date()
- Performance impact: 92% faster for pathological cases, 1% slower for normal history
