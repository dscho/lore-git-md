This is the second patch in a bugfix series addressing issues with `core.commentChar="auto"` behavior during conflict resolution. The patch implements Phillip Wood's architectural solution to standardize comment character handling by resetting to '#' when the auto mode is selected.

The core change modifies `config.c` to clear any previously set comment character when `core.commentChar="auto"` is encountered, forcing a fresh selection starting from the default '#' baseline. This prevents edge cases where conflict markers using a different comment character (like '%') could end up in the final commit message due to inconsistent state between the conflict resolution and auto-selection phases.

The patch is small (4 insertions, 2 deletions) but has significant implications for configuration state management. It ensures predictable behavior during transitions between explicit comment characters and auto mode, though as noted in the commit message, this doesn't fully solve the conflict marker inclusion issue - that was addressed in patch 1 of the series. The solution will remain relevant until `core.commentChar="auto"` is removed in Git 3.0.

Key technical points:
- Resets `comment_line_str` to '#' when auto mode is activated
- Frees any previously allocated comment string via `FREE_AND_NULL`
- Maintains the same user-visible behavior but with more consistent internal state
- Properly attributes Wood's original solution while incorporating maintainer feedback on attribution format

The patch represents the final piece of the series after extensive discussion about both the technical approach and proper credit assignment. With both the immediate bugfix (patch 1) and this architectural standardization now complete, the maintainer has indicated the series is ready for inclusion.
