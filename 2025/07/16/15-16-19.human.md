This is a discussion about Git's autostash configuration behavior, specifically around `pull.autostash` and related settings. Junio Hamano responds to Johannes Sixt's suggestion to document the behavior rather than implement complex validation, but raises deeper questions about the design.

The email reveals that `git pull` currently respects `rebase.autostash` (when doing a rebase-style pull) but not `merge.autostash` (for merge-style pulls), which Hamano considers inconsistent. He suggests this might be a bug, as users setting `rebase.autostash` for local work may not want the same behavior when pulling from remote repositories. 

Hamano considers two potential solutions: either remove support for `rebase.autostash` in `git pull` (though this would break existing configurations), or add support for a new `pull.autostash` that would set the appropriate rebase/merge autostash setting. However, he expresses reservations about both approaches, leaning against adding `pull.autostash` as it would perpetuate what he sees as problematic design.

The discussion highlights tensions between backward compatibility, configuration consistency, and user expectations. While the thread had been moving toward documentation fixes, Hamano's response suggests deeper architectural questions about how Git should handle these related but distinct configuration options.
