Performance optimization patch for `git last-modified` command, adding Bloom filter support to skip unnecessary diff computations. This is part of the v5 series implementing the new tree-level modification tracking command.

The patch introduces Bloom filter checks before computing diffs during revision walks, significantly improving performance when filters are available. Key technical elements:
- Adds `bloom_key` to `last_modified_entry` struct and handles its lifecycle
- Implements `maybe_changed_path()` helper to consult Bloom filters
- Integrates with commit-graph Bloom filter settings via `rev.bloom_filter_settings`
- Shows dramatic speedups in perf tests (50.6% faster for top-level checks)

The implementation gracefully falls back to full diff computation when filters are unavailable. Performance impact is validated by new test suite showing:
- 50.6% speedup for top-level checks (4.49s -> 2.22s)
- 36.4% speedup for subdirectory checks
- Minimal impact on recursive checks (0.4% improvement)

The patch builds on Taylor Blau's prior Bloom filter work and maintains compatibility with upcoming API changes (noted in thread context). Core functionality is in `builtin/last-modified.c` with Bloom filter integration touching key functions like `add_path_from_diff`, `mark_path`, and the new `maybe_changed_path` helper.
