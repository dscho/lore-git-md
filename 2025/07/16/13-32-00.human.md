This is the fifth version of a feature series introducing a new `git last-modified` plumbing command, which tracks when paths were last modified in a repository's history at the tree level (as opposed to line-by-line like `git blame`). The command is designed to support forge-style tree views that show when each file was last changed.

The series has evolved significantly from its origins as `git blame-tree`, with v5 adding an "extended" format option to better support the forge use case. Key technical details include Bloom filter integration for performance (50% speedup for top-level checks) and following `git diff-tree` conventions for path handling. The implementation is now consolidated in `builtin/last-modified.c` with comprehensive test coverage.

Notable changes in v5:
- Added an extended format option (name still open for discussion)
- Removed test dependency on `sort(1)`
- Added a fixup commit for pending Bloom filter API changes
- Kept non-recursive as the default behavior (`-r` required for recursion)

The patch appears well-considered, with performance tradeoffs carefully evaluated and controversial optimizations deferred to future series. The extended format addition seems motivated by real-world needs but could potentially be split out if reviewers prefer. The series has benefited from extensive collaboration, with credit given to GitHub contributors and multiple rounds of review feedback incorporated.
