Performance optimization patch completing the prio_queue conversion for commit traversal. This final patch in René Scharfe's 3-part series uses the new prio_queue_replace() helper (introduced in patch 2) to optimize the pop_most_recent_commit() function. The key change replaces a prio_queue_get()+prio_queue_put() sequence with prio_queue_replace() when processing the first parent, avoiding redundant heap operations.

The implementation introduces a delete_pending flag to track whether the queue head still needs removal after parent processing. Junio Hamano noted initial confusion about the variable name (suggesting first_parent might be clearer), with Scharfe proposing get_pending as an alternative that better reflects the underlying prio_queue_get() operation being deferred. The discussion confirms this is a clean optimization that maintains the existing behavior while improving performance.

The patch completes the series' goal of converting commit traversal to use priority queues, achieving O(log n) worst-case performance (92% faster for pathological histories) while restoring original performance for normal cases. All technical concerns from earlier reviews have been addressed, with only minor naming questions remaining. The changes affect commit.c's core commit traversal logic, building on the prio-queue.[ch] infrastructure modified in earlier patches. Performance impacts were validated through existing tests in t/perf/p1501-rev-parse-oneline.sh.
