This is a follow-up in the C99 `bool` refactoring series, specifically addressing the second patch that converts string predicate functions in `git-compat-util.h` to return `bool` instead of `int`. Elijah Newren provides a review of Phillip Wood's patch, confirming its correctness while raising a question about hyphenation in the commit message.

The patch mechanically converts the case-insensitive string prefix functions (`skip_iprefix()` and `skip_iprefix_mem()`) to match their case-sensitive counterparts that were already converted during the experimental period. Changes are straightforward type signature updates (6 lines per function) replacing `int` with `bool` and `1`/`0` with `true`/`false` literals, with no behavioral impact.

Newren notes the patch looks good overall but questions whether "case independent" and "case dependent" in the commit message should be hyphenated. This follows Eric Sunshine's earlier typo corrections to the same commit message. The changes complete the standardization of string predicate functions in `git-compat-util.h` to use `bool` returns, building on 18 months of proven safe usage of this pattern in production.

Technical details:
- Affects `git-compat-util.h` only
- Updates two functions: `skip_iprefix()` and `skip_iprefix_mem()`
- Changes are purely syntactic (return type and literals)
- Maintains identical ASCII case-insensitive comparison behavior
- Follows established pattern from case-sensitive conversions
- Part of broader effort documented in commit 8277dbe987

The review confirms the mechanical correctness of the changes while catching minor documentation polish opportunities, indicating the patch is ready to proceed as part of the series.
