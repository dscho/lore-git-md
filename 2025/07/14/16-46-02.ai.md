This is a refactoring patch that completes the standardization of `bool` return types for string predicate functions in Git's codebase. Eric Sunshine provides minor typo corrections to Phillip Wood's patch (the second in a 3-part series) that converts the case-insensitive string prefix functions (`skip_iprefix()` and `skip_iprefix_mem()`) to return `bool` rather than `int`.

The changes are purely mechanical type signature updates (6 lines per function) with no behavioral modifications, bringing these functions in line with their case-sensitive counterparts that were converted during the 18-month experimental period. The patch follows the established pattern of Git's gradual C99 feature adoption, building on commit 8277dbe987 from December 2023.

Eric's review is light, catching two minor typos in the commit message ("sting" -> "string" and "lets" -> "let's") and suggesting a small wording clarification ("return type" -> "return type of"). The changes affect `git-compat-util.h` and maintain identical runtime behavior while making the predicate nature of these functions more semantically clear through the type system.

This patch represents the middle step in a well-planned refactoring series that has already received Junio Hamano's approval for the documentation changes in patch 1, with patch 3 handling the `strbuf` predicate methods. The series follows Git's conservative approach to language feature adoption, having proven the change safe through 18 months of production use.
