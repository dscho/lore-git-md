This is a feature patch in the `git repo info` subcommand series, adding bare repository detection capability. It implements the `layout.bare` field to report whether the current repository is bare, following the table-driven architecture established in previous patches.

The patch adds a new boolean field type handler (`add_bool`) to the field system, which converts the `is_bare_repository()` result into "true"/"false" strings. The implementation leverages Git's existing `is_bare_repository()` function (via `environment.h`) and follows the same null-terminated output format convention used for other fields. Documentation is updated to include the new field under the "layout" category, and tests verify both bare and non-bare repository cases.

Key technical details include:
- New `add_bool` helper function for boolean field formatting
- `layout.bare` field registration in the `repo_info_fields` table
- Use of `is_bare_repository()` from environment.h
- Test cases in t1900-repo.sh covering both bare and non-bare scenarios
- Documentation update in git-repo.adoc

The implementation appears clean and well-integrated with the existing field system architecture. It maintains consistency with the series' design decisions around output format (null-terminated) and field organization (lexicographical ordering in the table). The test coverage is thorough for this simple boolean field case.
