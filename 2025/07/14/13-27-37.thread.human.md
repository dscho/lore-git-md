This thread examines the use of C99 compound literals in Git's codebase, sparked by Phillip Wood's initial test patch modifying `strbuf_init()`. The discussion has evolved to focus on existing examples in the reftable subsystem, where `REFTABLE_FLOCK_INIT` and `REFTABLE_TMPFILE_INIT` macros (introduced in Git 2.50) already use this pattern to initialize structs containing file descriptors set to -1.

Phillip Wood and Patrick Steinhardt agree these reftable macros effectively serve as real-world test cases for compound literal usage. Phillip suggests documenting them in CodingGuidelines as intentional examples rather than creating new demonstration patches, since reftable is a mandatory part of Git builds and thus provides reliable compatibility testing. This approach would establish precedent while avoiding redundant work.

The thread remains open on broader questions about when and how to use compound literals, particularly for structs requiring cleanup. The reftable examples offer concrete data points for evaluating both the pattern's utility and potential pitfalls, moving the discussion toward possible formal guidelines. Junio C Hamano's initial maintainability concerns about struct evolution and resource management remain central to the ongoing evaluation.
