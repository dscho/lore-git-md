This is the second patch in a 4-part series implementing the new `git repo info` subcommand, focusing on adding reference format detection. The patch introduces the `references.format` field to report whether the repository uses 'files' or 'reftable' reference storage.

The implementation:
- Adds a table-driven field system in `builtin/repo.c` with callback functions for each metadata field
- Implements `add_references_format()` to query the ref storage format using existing `ref_storage_format_to_name()` infrastructure
- Includes comprehensive tests in `t1900-repo.sh` verifying both files and reftable formats
- Updates documentation in `git-repo.adoc` to describe the new field
- Key technical details:
  - Uses null-terminated output format as decided in the thread
  - Implements lexicographical sorting of requested fields
  - Handles duplicate field requests by only outputting each field once
  - Maintains proper error handling for unknown field requests
  - Follows the table-driven architecture approved in the thread

The patch builds on the v4 architectural foundation from patch 1/8, implementing the first concrete metadata field while establishing patterns for future fields.
