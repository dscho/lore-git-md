This is a discussion about Git's build system and regex architecture, specifically around PCRE2 dependency handling. Carlo Arenas responds to Junio Hamano's technical exploration of how Git might unify its regex handling under PCRE2.

The conversation has split into two tracks: immediate build system decisions (whether to enable PCRE2 by default) and long-term architectural questions. Junio outlined a substantial refactoring that would expose Git's internal regex structures (`grep_pat` and `compile_regexp()`) to allow broader PCRE2 usage beyond just `git grep`.

Carlo acknowledges this as an ambitious long-term plan ("dreamware") and raises a more immediate concern: if PCRE2 becomes a default dependency, how will that affect Git's libification efforts? He suggests an alternative approach where PCRE2 functionality could be isolated in a way that keeps it optional for the core library, potentially making `git-grep` a standalone binary that links with PCRE2 as needed.

The discussion shows the tension between making PCRE2 more widely (which many packagers already do) and maintaining flexibility in Git's architecture. The thread continues to explore both tactical build system choices and strategic direction for Git's regex handling.
