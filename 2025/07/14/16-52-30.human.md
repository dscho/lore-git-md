This is a follow-up to the SHA256 support patch for gitk, now in its second version. Johannes Sixt is queuing the patch but making a small organizational tweak - moving the new hash length detection code to better group it with related initialization logic rather than having it interrupt the encoding section. 

The patch itself (authored by Takashi Iwai) enables gitk to work with both SHA1 and SHA256 repositories by introducing variable hash length handling. It builds on prior work by Rostislav Krasny, with v2 revision simplifying the approach by using a unified configuration for auto-selection length rather than separate SHA1/SHA256 paths.

The change appears well-considered, maintaining compatibility while adapting UI elements and validations to handle both hash lengths. Some technical debt remains with "sha1" terminology in the code that could be confusing, but this was intentionally left to minimize changes. The patch seems ready for inclusion with this minor organizational adjustment.
