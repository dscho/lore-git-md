Bugfix patch addressing path expansion in GPG configuration, with documentation clarification.

This patch modifies `gpg-interface.c` to use `git_config_pathname()` for the `gpg.program` setting, enabling tilde expansion for paths under user home directories. The change is accompanied by a documentation update that more precisely describes the setting as taking a "pathname" rather than just a program name. 

The implementation is straightforward - a one-line change switching from `git_config_string()` to `git_config_pathname()`. Junio Hamano acknowledges the correctness of the change and the value of the documentation improvement, though he suggests adding a test to protect the new functionality from regression. 

This appears to be a well-contained fix for a specific limitation in GPG configuration handling, though it doesn't address the broader command-line argument parsing issues discussed in the thread. The patch maintains backward compatibility of the existing interface while adding the expected path expansion behavior. 

The thread context shows this is part of a larger discussion about how Git should interpret the `gpg.program` setting - whether as a path (with expansion) or as a command line (with argument parsing). This patch takes the path interpretation route, which aligns with the documented behavior but doesn't resolve the command-line use case that some users might expect.
