This thread documents the final steps in standardizing the use of C99 `bool` type for predicate functions across Git's codebase, following an 18-month experimental period. The series consists of three mechanical refactoring patches that update documentation and convert string utility functions to use `bool` returns instead of `int`.

The first patch, already accepted by Junio C Hamano, updates Documentation/CodingGuidelines to formally permit `bool` usage for predicate functions, citing the successful production use over the past year and a half. The second patch converts case-insensitive string prefix functions in git-compat-util.h (`skip_iprefix()` and `skip_iprefix_mem()`) to match their case-sensitive counterparts that were converted earlier. Elijah Newren reviewed this patch, confirming its correctness while raising a minor question about hyphenation in the commit message (following Eric Sunshine's earlier typo corrections). The third patch completes the effort by updating strbuf predicate methods.

The changes are purely syntactic - replacing `int` with `bool` return types and `1`/`0` with `true`/`false` literals - with no behavioral modifications. The series builds on established precedent and follows Git's pattern of gradually incorporating C99 features after proving them safe in production. With Junio's approval of the documentation change and positive reviews from both Eric Sunshine and Elijah Newren, this standardization effort appears ready to be merged.
