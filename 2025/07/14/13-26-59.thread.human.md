This thread documents a straightforward refactoring effort to standardize Git's predicate functions to use C99 `bool` return types, building on 18 months of successful experimental use. The series consists of three patches that methodically convert string utility functions across the codebase.

The first patch updated Documentation/CodingGuidelines to formally permit `bool` usage for predicate functions, citing the experimental period that began in December 2023. The second patch converted core string utilities in git-compat-util.h, including case-sensitive variants that had already been tested in production. The newly arrived third and final patch completes the effort by converting the remaining string predicate functions in strbuf.[ch], including case-insensitive variants and memory-based operations.

All changes are mechanical type signature updates that preserve existing behavior - simply changing return types from `int` to `bool` and values from `1`/`0` to `true`/`false`. The series follows Git's established pattern for gradually adopting C99 features, similar to previous standardization of loop variable declarations. With no open questions or objections raised during review, this appears to be a low-risk cleanup that improves type safety while maintaining perfect backward compatibility.
