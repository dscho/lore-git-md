This is a follow-up to the SHA256 support patch for gitk, focusing on code organization. Johannes Sixt (Hannes) acknowledges Takashi Iwai's v2 patch for adding SHA256 repository support to gitk, which introduces a `hashlength` variable that adapt to either SHA1 (40-char) or SHA256 (64-char) hashes. While queueing the patch, Hannes notes he will move the `hashlength` initialization code block to follow the `gui_encoding` setup rather than having it in the middle of the encoding section. This is a minor structural improvement to the otherwise unchanged patch.

The technical context remains: gitk now detects repository object format via `git rev-parse --show-object-format` and sets the corresponding hash length, with fallback error handling for unknown formats. The patch maintains the v2 simplifications like unified configuration between hash types and drops the separate `autosellensha256` config from v1. The change being discussed is purely about code organization within the initialization sequence, not affecting functionality.
