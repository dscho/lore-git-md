This is a cover letter for a major architectural revision of the `git repo-info` command, now rebranded as part of a new `git repo` hierarchy. The series represents a complete rewrite following mentor discussions that established a clear separation between lightweight metadata reporting (`repo info`) and computational metrics (`repo stats`).

The key changes in v4 include:
1. Command restructuring into a `git repo` namespace with `info` as the first subcommand, leaving room for future `stats` functionality (based on Justin Tobler's git-survey work)
2. Removal of JSON output support in favor of a simpler null-terminated format matching Git's existing conventions
3. Simplified field handling using a table-driven callback system instead of nested enums and switches
4. New infrastructure designed for easy addition of future subcommands

The implementation introduces three initial metadata fields (`references.format`, `layout.bare`, `layout.shallow`) with a test suite covering basic functionality. The series creates all the plumbing for the new command hierarchy including documentation (git-repo.adoc), build system integration, and command registration.

This version supersedes the previous v3 approach entirely, as noted in the thread summary, with consensus now clearly favoring the hierarchical command structure and simplified format. The patch appears well-structured with thorough documentation and test coverage, though reviewers will likely focus on the architectural decisions around field handling and output format as the most critical aspects. The transition path from standalone `repo-info` to subcommand model seems thoughtfully considered, with clear separation between the lightweight operations and future computationally intensive stats functionality.
