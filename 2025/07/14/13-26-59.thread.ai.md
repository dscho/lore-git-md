Refactoring series to standardize use of C99 `bool` type for predicate functions in Git's codebase, following an 18-month experimental period that began with commit 8277dbe987 in December 2023. Series consists of 3 patches with cover letter:

1. Cover letter summarizes the effort: updates Documentation/CodingGuidelines to permit `bool` usage (already accepted by Junio C Hamano), converts string utilities in `git-compat-util.h` (including case-insensitive variants), and updates `strbuf` predicate methods. All changes are mechanical type signature updates (29 insertions, 26 deletions across 4 files) with no behavioral impact.

2. Documentation patch updates CodingGuidelines to explicitly permit `bool` for predicate functions, formalizing 18 months of production use. Junio confirmed acceptance, comparing this to Git's pattern for gradual C99 feature adoption (dynamic initializers, enum trailing commas, etc.). The 18-month timeframe matches previous feature adoptions. This is the first patch in the series, adding three lines to document `bool` alongside other accepted C99 features, following Git's conservative approach to language feature adoption.

3. Core string utility conversion in `git-compat-util.h` affects `skip_prefix()`, `starts_with()`, and their case-insensitive variants (`skip_iprefix()`, `skip_iprefix_mem()`). Eric Sunshine provided typo corrections ("sting" -> "string", "lets" -> "let's") and wording improvements. Elijah Newren reviewed technical correctness while raising hyphenation questions ("case independent"/"case dependent"). Brian m. carlson cited Chicago Manual of Style guidance on hyphenating compound modifiers before nouns ("case-dependent functions"). All feedback incorporated.

4. `strbuf` predicate methods updated in `strbuf.[ch]`, affecting six functions (`starts_with`, `istarts_with`, `starts_with_mem`, `skip_to_optional_arg_default`, plus inline `skip_to_optional_arg`, `ends_with`). Changes maintain identical runtime behavior while switching from `1`/`0` to `true`/`false`.

Technical scope remains unchanged: pure refactoring across `Documentation/CodingGuidelines`, `git-compat-util.h`, `strbuf.h`, and `strbuf.c`. Series builds on established precedent with 18 months of incident-free production use. Junio's acceptance of the documentation patch represents final standardization. All reviewer feedback addressed, including Eric Sunshine's typo fixes, Brian m. carlson's style guidance, and Elijah Newren's technical review. Demonstrates Git's attention to both technical correctness and documentation quality for mechanical changes. The documentation patch serves as the policy foundation enabling the subsequent technical conversions.
