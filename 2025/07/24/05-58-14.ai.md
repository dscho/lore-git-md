This is a follow-up review in the `git refs list` feature series, where Patrick Steinhardt provides minor feedback on the implementation details. The patch being discussed is part of the v3 series that has already addressed major maintainer concerns and received informal approval from Junio Hamano.

Patrick notes several small technical points about the implementation:
1. Suggests the documentation changes (extracting common options) might have been better as a separate preparatory commit
2. Questions whether the usage strings for `git-for-each-ref` and `git-refs-list` should be identical except for command name
3. Observes the current implementation makes `for-each-ref` aware of `refs list` in a way that's not ideal but pragmatically follows the blame/annotate pattern
4. Expresses concern about the duplicated `REFS_LIST_USAGE` macro that could drift apart, suggesting either:
   - Moving to a shared location
   - Refactoring `cmd_for_each_ref()` to accept usage array
   - Simplifying to just show `[<options>]` in usage

The feedback focuses on code organization and maintainability rather than functionality, as the core approach has already been approved. These are minor polish items that could be addressed in a future iteration but don't block the current series. The thread shows active mentoring with attention to detail in the implementation.
