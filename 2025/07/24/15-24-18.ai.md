Performance and bugfix patch for submodule activation handling. This is the second patch in K Jayatheerth's v2 series improving submodule operations.

The change addresses a case where `configure_added_submodule()` would always write an explicit `submodule.<name>.active` entry, even when the submodule's path was already covered by existing `submodule.active` patterns. The patch introduces wildmatch-based pattern checking to avoid these redundant configuration writes, reducing config file clutter and unnecessary processing.

Key technical changes include:
- Adds wildmatch.h and strbuf.h includes to submodule--helper.c
- Restructures the active flag logic to first check for pattern matches against the submodule path
- Only writes the active entry when no existing pattern matches
- Adds a new test case in t7413-submodule-is-active.sh verifying the optimization works when adding submodules under paths covered by wildcard patterns

The implementation appears thorough, with proper handling of both the absence of submodule.active configuration and cases where patterns exist. The test coverage demonstrates the expected behavior when adding a submodule under a path matching an existing wildcard pattern. This aligns with the series' goal of refining submodule configuration handling while maintaining existing behavior boundaries.
