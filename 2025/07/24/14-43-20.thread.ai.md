Proposed feature for `git rebase` to notify users when a commit is skipped during conflict resolution because all changes were removed. Currently this happens silently, which can lead to unintended history modifications going unnoticed. The change would modify builtin/rebase.c's conflict resolution feedback system to explicitly indicate when a commit is being skipped due to empty resolution. No implementation details proposed yet - this is an initial discussion of the UX implications for this quality-of-life improvement to make rebase behavior more transparent. The proposal addresses a real workflow pain point but would need to carefully balance added verbosity against clarity of important state changes.
