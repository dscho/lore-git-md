Proposed feature for `git rebase` to notify users when a commit is skipped during conflict resolution because all changes were removed, addressing silent behavior that can lead to unnoticed history modifications. Junio C Hamano has responded to Cameron Steffen's initial suggestion with a concrete but untested implementation approach in sequencer.c that would add a warning message ("omitting a step that has become empty") when Git skips such commits.

The minimal 2-line change would make rebase behavior more transparent when users resolve conflicts by removing all changes. Open questions remain about appropriate warning verbosity (ensuring user awareness without being intrusive) and potential edge cases where the warning might trigger in inappropriate contexts. Hamano is soliciting input from recent sequencer.c contributors as the discussion moves from problem identification to implementation exploration.

Key technical detail: the warning would be emitted from sequencer.c rather than builtin/rebase.c, suggesting the change affects the underlying sequencer machinery used by multiple commands. The thread has not yet addressed whether similar warnings should apply to other commands (like cherry-pick) that use the same conflict resolution pathways.
