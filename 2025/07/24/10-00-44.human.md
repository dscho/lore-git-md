This is a follow-up discussion in the ongoing RFC thread proposing Rust integration for Git's xdiff performance optimizations. Patrick Steinhardt seeks clarification from Pierre-Emmanuel Patry about timelines for GCC-based Rust compiler alternatives (gccrs and rustc_codegen_gcc) that could help address platform compatibility concerns raised earlier in the thread.

Key points from this exchange:
- Patry confirms gccrs progress remains on track to compile Rust's libcore (version 1.49) by end of summer, though significant testing remains
- Next target version would be Rust 1.78 to align with Rust-for-Linux, but full support for even the older 1.49 code isn't expected until next year
- rustc_codegen_gcc is mentioned as a potential solution for architectures unsupported by LLVM, though it's unclear whether Git would need to directly support this or if distributors would handle it

The discussion helps clarify the realistic timeline for alternative Rust implementations that could mitigate some of the compatibility concerns raised earlier in the thread, particularly for non-LLVM architectures. Steinhardt's questions suggest the Git project is seriously considering these alternatives as part of their Rust adoption strategy.
