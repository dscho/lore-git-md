Test helper refactoring (part 1/3 of test-delta cleanup)

This first patch in Jeff King's test-delta.c cleanup series simplifies error handling by replacing manual cleanup jumps with direct `die()` calls. The changes affect the test helper's main function, which previously used explicit error paths with `goto cleanup` and manual descriptor closing. The new version relies on Git's standard error reporting functions (`die()`, `die_errno()`, `xopen()`) while maintaining the same functionality.

Key technical changes include:
- Replacing `fprintf(stderr)` with `usage()` for command-line errors
- Converting `open()`+`perror()` patterns to `xopen()`+`die_errno()`
- Removing the `cleanup` label and associated jumps
- Simplifying memory management by removing redundant cleanup paths
- Changing error exit codes from 1 to 128 (matching Git's convention)

The patch reduces the file by 19 lines while fixing several subtle issues: potential descriptor leaks in error paths and inconsistent error reporting. As noted in the thread context, this aligns with the emerging consensus that test helpers can take shortcuts with cleanup since they exit immediately, though memory handling remains important for SANITIZE=leak checks. The changes make the code more idiomatic while maintaining correctness.
