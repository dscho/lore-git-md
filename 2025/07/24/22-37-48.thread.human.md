This thread reports a bug in Git's URL rewriting behavior, specifically affecting how `url.<base>.pushInsteadOf` rules interact with `git remote get-url --push`. The reporter has provided a detailed test case showing that while `insteadOf` rewrites work as expected for push-specific URLs, the `pushInsteadOf` counterpart is being ignored when querying push URLs - the command incorrectly shows URLs rewritten with `insteadOf` rules instead.

The issue appears to be in the interaction between `remote.c` and `urlmatch.c`, where push-specific URL rewrites aren't being properly honored during URL queries. The bug is reproducible on Git 2.50.1 (Windows) and likely affects all platforms. Both single URL queries (`--push`) and multiple URL listings (`--push --all`) exhibit the same incorrect behavior.

The test case clearly demonstrates the problem by setting up a repository with multiple push URLs and both types of rewrite rules, showing that `git remote get-url --push` returns URLs rewritten with the wrong scheme. This looks like a legitimate bug that would need fixing in how push-specific URL rewrites are processed when the `--push` flag is present.
