Performance and cleanup patch for submodule handling. This is the second patch in K Jayatheerth's series, focusing on optimizing submodule activation when adding new submodules.

The change prevents redundant configuration entries when a submodule's path is already covered by existing `submodule.active` patterns. Currently, Git always writes an explicit `submodule.<name>.active` entry during submodule addition, even when unnecessary. The patch modifies `configure_added_submodule()` to first check if the new submodule's path matches any active patterns before writing the config entry.

The implementation adds wildmatch-based pattern checking against the submodule path, only writing the active flag when no match exists. This reduces configuration clutter while maintaining the same effective behavior. The change includes a new test case in t7413-submodule-is-active.sh that verifies the optimization works as expected when adding a submodule under a path already covered by a wildcard pattern.

This appears to be a straightforward optimization that follows existing submodule handling patterns while cleaning up unnecessary config entries. The patch builds on the submodule infrastructure without introducing new concepts, and the test coverage helps ensure the behavior remains correct.
