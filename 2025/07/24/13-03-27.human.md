Performance optimization for `git remote rename` ref handling, building on Jeff King's earlier fix for symbolic ref issues. Patrick Steinhardt proposes a major architectural improvement to address severe performance problems in the current implementation.

The current issues include:
- Extremely slow operation (hours for 100k refs) due to quadratic overhead from separate ref transactions
- Non-atomic updates that could leave repos in inconsistent states
- Unnecessary ref resolution calls

Steinhardt's solution:
- A single atomic transaction approach using the ref transaction API
- Eliminates the quadratic overhead, reducing runtime from hours to seconds
- Leverages Karthik Nayak's reflog migration infrastructure (though reflog support isn't shown in this WIP patch)

The patch demonstrates a working prototype that already shows dramatic speed improvements (7 seconds vs. hours for large ref counts). Steinhardt plans to polish and submit this as a proper patch series soon.

This represents both a bugfix (for the original symbolic ref issue) and a major performance optimization, though the thread shows there may be more work needed to fully handle reflog migration. The approach looks technically sound and addresses core architectural limitations in the current implementation.
