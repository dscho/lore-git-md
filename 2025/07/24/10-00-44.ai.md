This is a technical discussion about Rust compiler alternatives for Git's potential Rust integration, specifically focusing on GCC-based Rust compiler timelines and architecture support.

Patrick Steinhardt follows up on Pierre-Emmanuel Patry's update about GCC-based Rust compiler progress (gccrs). The discussion clarifies that while libcore compilation for Rust 1.49 may be possible by end of summer, full testing and bug fixing will extend into next year. The next target version (1.78) to align with Rust-for-Linux requirements would likely take until the following year.

Steinhardt explores whether gccrs could help address architecture support limitations, particularly non-LLVM platforms. He seeks clarification on whether rustc_codegen_gcc (a GCC backend for rustc) would require project-level support or could be handled by distributors. This touches on key open items from the RFC thread regarding platform compatibility and build system integration.

The exchange provides concrete timelines for GCC-based Rust compiler availability while highlighting remaining uncertainties about implementation responsibilities and version support. This directly addresses Gentoo maintainers' earlier concerns about platform limitations while offering potential paths forward for the Rust RFC's architecture support challenges.
