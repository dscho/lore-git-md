This is a proposed bugfix/UX improvement for `git rebase`'s conflict resolution behavior. Junio C Hamano responds to Cameron Steffen's suggestion about making it clearer when rebase skips a commit due to empty conflict resolution. Currently this happens silently, which can lead to users unintentionally dropping changes without realizing it.

Hamano proposes a simple warning message ("omitting a step that has become empty") as a starting point, though he notes it's untested and might need refinement to avoid false positives. The change would modify sequencer.c to add this warning when commits are skipped during rebase continuation. 

The patch itself is minimal (just 2 lines added) and targets a real pain point in the rebase workflow. Hamano is soliciting feedback from recent contributors to sequencer.c to help refine the approach, suggesting this needs careful consideration about when exactly the warning should trigger. The change would make Git's behavior more transparent while maintaining the existing functionality.
