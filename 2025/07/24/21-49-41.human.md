Bug report: Git clone fails with fsync permission error on NFS (FSx Ontap)

Tim Cederquist reports a permission issue when cloning repositories to an NFS-mounted FSx Ontap filesystem. The key symptom is that `git clone` fails with a "Permission denied" error during the fsync operation on the temporary pack index file, despite the user having appropriate permissions for basic file operations.

The root cause appears to be that Git opens the temporary pack index file with read-only permissions (444) but then attempts to write to it, which conflicts with the NFS server's permission model. The reporter demonstrates that adding explicit append permissions through ACLs works around the issue, and suggests that Git should instead open the file with 600 permissions (read-write) initially, similar to how the `install` command handles file creation.

This seems to be a specific interaction between Git's file handling and FSx Ontap's NFS implementation, where the reporter has verified that basic file operations work correctly outside of Git. The report includes detailed reproduction steps, strace output, and a proposed solution, making it a well-documented issue that warrants investigation by Git developers familiar with filesystem interactions.
