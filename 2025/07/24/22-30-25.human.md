Bugfix for MemorySanitizer issue in ref-cache iterator.

This is a follow-up to Karthik Nayak's pagination work for `git for-each-ref`, specifically addressing a MemorySanitizer warning that was detected during testing. The issue stems from commit 090eb5336c that separated seeking functionality from prefix matching in reference iterators. While the change was correct functionally, it left the `prefix_state` field uninitialized when creating new iterator levels, causing MSan to flag an uninitialized memory read.

The fix is straightforward - explicitly set `prefix_state` to `PREFIX_CONTAINS_DIR` when initializing new levels, which is the correct default value when seeking without prefix matching. This matches the intended behavior of yielding all entries during pure seeking operations.

The patch has already been reviewed by Jeff King and Kyle Lippincott (who originally reported the MSan issue), and Junio Hamano is now acknowledging Karthik's version of the fix. This appears to be the final piece needed to fully resolve the memory safety concerns around the pagination feature, which has otherwise been thoroughly tested and documented.
