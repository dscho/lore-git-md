This is a discussion about the output format design for the new `git repo info` command, part of Lucas Seiki Oshiro's GSoC project to create a repository metadata command hierarchy.

Patrick Steinhardt responds to concerns raised by Junio Hamano about using LF as a field separator in the machine-readable output format. While acknowledging that scripts should use NUL-delimited output (which the command will support via `--format=null`), Patrick argues that LF separation is still useful for human inspection of repository properties during development or debugging. He suggests that while strict quoting isn't critical for this human-readable output, it wouldn't be difficult to implement proper C-style quoting if needed.

The exchange highlights an ongoing design decision in this series - how to balance machine-parsable rigor with human usability in the command's output formats. Patrick's position leans toward keeping the LF-separated format as a convenience for interactive use while maintaining the NUL-delimited option for scripting. This follows the thread's earlier resolution to use LF separation while keeping the format robust enough for future needs.
