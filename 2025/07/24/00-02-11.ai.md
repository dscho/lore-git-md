This is the second patch in Jeff King's series to modernize and fix resource handling in the `test-delta` helper. Building on the first patch's error handling improvements, this change replaces manual file reading with `strbuf` for simpler and safer memory management.

The patch converts the input file handling from raw buffers to `strbuf` structures, using `strbuf_read_file()` to read file contents. This eliminates 26 lines of manual buffer management code while incidentally fixing two subtle issues: potential integer truncation when converting `off_t` file sizes to allocation sizes, and a race condition where file contents could lead to reading uninitialized memory if the file changed during reading. The `strbuf` approach naturally handles both cases by reading to EOF and growing buffers as needed.

Key technical changes include replacing `xmalloc()`+`read_in_full()` pairs with `strbuf_read_file()`, updating the delta functions to use `strbuf.buf` and `strbuf.len`, and switching to `strbuf_release()` for cleanup. The output buffer handling remains manual since it's produced by the delta functions. The patch maintains the same error handling approach established in v1, using `die_errno()` for failures.

This continues the series' pattern of making the test helper more idiomatic while fixing latent issues. The changes align with the thread's established consensus that test helpers can take process-termination shortcuts while still properly handling memory for SANITIZE=leak. The remaining patch in the series will address the output file descriptor leak, completing the modernization effort.
