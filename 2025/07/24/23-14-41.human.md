This is a bug report response regarding `git clone` failures on NFS-mounted FSx Ontap storage. Brian m. carlson confirms the reported issue stems from the NFS server not properly implementing POSIX file permission semantics, where writes to a file descriptor should succeed regardless of the file's permission bits once opened with O_RDWR.

The core disagreement centers on whether Git should adapt to the non-compliant NFS server behavior. The original reporter suggested changing Git's temporary pack index file permissions from 444 to 600 to work around the issue, similar to how the `install` command operates. However, carlson argues this would be working around a server-side POSIX compliance bug that affects many other tools (including zsh, Emacs, and other Git implementations), and that proper NFS servers handle this case correctly.

The response emphasizes that POSIX explicitly allows writing to files opened with O_RDWR regardless of their permission bits, and that the current Git behavior is correct by standard. While acknowledging the practical problem, carlson suggests the real fix belongs in the NFS server implementation rather than in Git. This positions the issue as part of a broader class of NFS permission problems that various software encounters with non-compliant servers.
