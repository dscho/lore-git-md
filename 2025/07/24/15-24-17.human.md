Bugfix for submodule path reuse that prevents silent .gitmodules overwrites. This is the first patch in a two-part series addressing submodule handling issues.

The patch fixes a case where adding a submodule at a path that previously contained another submodule could silently overwrite the original submodule's configuration in .gitmodules. This happens when the original submodule was moved but not renamed, and the path-derived name gets reused. The change makes `git submodule add` check if the computed name already exists in the submodule config, failing unless either:
1. The user explicitly renames the submodule, or
2. Uses `--force` to auto-generate a unique name (e.g., appending "1", "2", etc.)

The implementation adds checks in `module_add()` in builtin/submodule--helper.c, updates the documentation for the `--force` option, and includes a new test case in t7400-submodule-basic.sh. The change appears well-motivated by real-world confusion cases and maintains backward compatibility through the `--force` option. The test coverage looks thorough, verifying both the failure case and that the original configuration remains intact.
