This is a performance optimization and refactoring of the remote rename operation, building on the earlier bugfix discussion about symbolic ref handling. Patrick Steinhardt proposes a major rewrite of `builtin/remote.c`'s rename logic to address severe performance issues in the current implementation.

The key improvements in this work-in-progress patch:
- Replaces N+M*2 separate ref transactions with a single atomic transaction
- Eliminates quadratic behavior in the files backend by avoiding repeated packed-refs rewrites
- Removes unnecessary `refs_resolve_ref_unsafe()` calls by using the raw ref iterator
- Demonstrates dramatic speedup (from hours to 7 seconds for 100k refs)
- Uses Karthik Nayak's reflog migration infrastructure (though reflog handling isn't implemented yet)

Technical details:
- Introduces new `queue_one_rename()` helper that builds updates in a transaction
- Uses `refs_for_each_rawref` to catch all refs including unresolved ones
- Splices refnames directly rather than resolving and reconstructing
- Maintains symbolic ref status through the rename operation
- Still needs to handle reflog migration (marked as TODO)

The patch represents a significant architectural improvement over both the original broken behavior and Jeff King's proposed fix, though it builds on the same core understanding of the symbolic ref issue. It demonstrates how the immediate bugfix intersects with broader ref backend performance concerns, particularly for large repositories.
