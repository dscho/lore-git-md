This is a usability improvement proposal for `git rebase`. Cameron Steffen suggests adding a notification when a commit gets skipped during rebase due to having all its changes removed during conflict resolution. Currently, this happens silently, which can be confusing for users who might not realize a commit was dropped from the rebase.

The proposal is straightforward and addresses a real pain point in the rebase workflow. While the impact is minor (it's more about user awareness than functionality), it would make the rebase process slightly more transparent. The change would likely be uncontroversial and relatively easy to implement, though it would need to be careful not to add noise to successful rebases.

This appears to be a new thread rather than part of an ongoing discussion. The suggestion is clearly motivated by personal experience with the workflow, though the email doesn't propose any specific implementation approach. It's the kind of quality-of-life improvement that often gets positive reception in the Git community.
