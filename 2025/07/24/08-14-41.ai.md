This is a cover letter for a series of small ref-filter cleanups and fixes, following up on Karthik Nayak's earlier work adding the `--start-after` flag to `git for-each-ref`. The series addresses minor issues identified during review of that previous work.

The patches include:
1. A type fix in ref-cache.c changing an `int` to `size_t` for length handling
2. Documentation fixes for `git-for-each-ref` argument ordering and clarification of `--start-after` behavior
3. A new test case combining `--start-after` with `--exclude`
4. A ref-filter change to use the proper constant `REF_ITERATOR_SEEK_SET_PREFIX` instead of magic number `1`

The changes are small and focused - each addresses a specific nit found during code review. The test addition is particularly useful as it verifies behavior of the new `--start-after` feature in combination with existing options. The documentation improvements help users understand the command's behavior more clearly.

The series builds on recent Git master (3f2a94875d) with Karthik's previous `--start-after` work merged in. The cover letter acknowledges these might be too minor to justify separate patches, suggesting they could be combined if reviewers prefer.
