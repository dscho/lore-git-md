This is a refactoring patch that fixes a type mismatch in the ref-cache iterator code. The change addresses a subtle issue introduced in commit 090eb5336c where an `int` was used to store string lengths that should have been `size_t`. The patch notes two specific problems with the current code: the type mismatch with `strncmp`'s expected parameter type, and potential truncation of large string lengths to negative numbers.

The change is straightforward - it replaces the `int len` declaration with `size_t len` and removes the problematic cast of `strlen` to `int`. The diff shows the modification in the `cache_ref_iterator_seek` function where string comparisons are made during ref iteration. This is part of Karthik Nayak's series cleaning up small issues from their earlier `--start-after` work in ref-filter.

For future reference, this touches the ref-cache iterator's seeking logic in `refs/ref-cache.c`, specifically around how refname segments are compared during iteration. The change is technically correct but unlikely to have practical impact since refnames are typically short, though it does properly align with string handling conventions in C.
