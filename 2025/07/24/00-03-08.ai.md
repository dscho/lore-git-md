Bugfix completing the test-delta resource leak series.

This final patch in Jeff King's three-part series adds an explicit `close()` for the output file descriptor in the `test-delta` helper program. While the descriptor would be closed automatically on program exit, the patch enforces proper resource management practices by explicitly checking for and reporting close errors, and prevents potential descriptor leaks that could occur if the error handling pattern were copied elsewhere.

The change follows the established pattern from previous patches in the series, using `die_errno()` for error reporting. The commit message explains the rationale clearly, noting both practical benefits (error detection) and pedagogical value (setting a good example). The diff itself is minimal - just two lines adding the close check after the existing write operation.

This completes the series' modernization of `test-delta.c`, which has now addressed multiple resource management issues including memory leaks, integer truncation risks, and file descriptor handling. The thread has shown clear consensus on the approach, with this final patch following the same principles as the earlier ones that were already reviewed positively.
