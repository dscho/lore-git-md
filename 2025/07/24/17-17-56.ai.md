Ref-cache type safety follow-up addressing pointer arithmetic concerns. This is a continuation of Karthik Nayak's series fixing type issues in the ref-cache iterator code, specifically addressing feedback from Junio C Hamano about safe pointer arithmetic conversions.

The patch changes the type of `len` from `int` to `size_t` in `cache_ref_iterator_seek()` to properly match string length handling, fixing potential truncation issues from commit 090eb5336c. The key changes are:
1. Splitting the `int len` declaration into separate `int idx` and `size_t len` declarations
2. Removing the problematic `(int)strlen(refname)` cast
3. Adding an explicit `(size_t)` cast for the pointer difference `slash - refname`

Junio confirms the pointer arithmetic is safe in this context since `slash` always points within the same memory block as `refname`. The change aligns with previous discussions about safe type conversions in Git's codebase, though Junio notes there was a more recent discussion about `ptrdiff_t` to `size_t` conversions that isn't directly referenced here.

This appears to be the final refinement of the type safety fixes in the ref-cache iterator code, with Junio indicating he will queue the patch. The change is narrowly focused on correct type handling without introducing new functionality or behavior changes.
