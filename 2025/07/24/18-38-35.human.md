This is a performance optimization and bugfix for `git remote rename`'s handling of symbolic refs, particularly for unborn HEAD refs created with `-m`. Junio C Hamano is reviewing Patrick Steinhardt's proposed rewrite that addresses both the original issue and severe performance problems in the current implementation.

The patch completely reworks the rename operation to use a single atomic transaction via a new `queue_one_rename()` helper, rather than the previous inefficient approach that could take hours for repositories with 100k refs. The new implementation shows dramatic speed improvements (7 seconds for 100k refs vs. hours before) while also properly maintaining symbolic ref status through renames.

Key technical changes include using `refs_for_each_rawref` to catch all refs (including unresolved ones), direct refname splicing without resolution/reconstruction, and leveraging Karthik Nayak's reflog migration infrastructure. The review notes the transaction-based approach is much cleaner but raises one question about potential D/F conflicts during rename operations.

This appears to be a well-considered solution that builds on Jeff King's initial analysis while significantly improving both correctness and performance. The patch is nearly ready for submission, with only reflog migration handling remaining to be implemented. The dramatic performance improvement (from hours to seconds) makes this particularly noteworthy for users with large repositories.
