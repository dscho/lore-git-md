This is a bugfix patch in Patrick Steinhardt's reflog migration infrastructure series, addressing the handling of the REF_HAVE_OLD flag during log-only updates. The patch clarifies that while unsetting REF_HAVE_OLD was originally sensible for reflog writes (since the old OID doesn't need to match the current ref state), keeping it set provides useful information about whether the caller provided an old OID. This becomes important for proper reflog migration where we want to preserve the original OIDs rather than defaulting to all-zero values.

The discussion reveals some nuances: the current patch isn't sufficient by itself to fix the OID recording issue (that comes in a follow-up), but serves as groundwork by preserving the flag. Patrick also notes that the REF_LOG_ONLY flag's documentation is outdated - it's now used in combination with several other flags during reflog migration operations. The complexity of these interactions led to introducing a new REF_LOG_USE_PROVIDED_OIDS flag rather than trying to repurpose existing ones.
