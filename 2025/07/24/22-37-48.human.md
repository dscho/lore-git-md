Bugfix for `url.<base>.pushInsteadOf` behavior in `git remote get-url --push`

Han Jiang reports an inconsistency in how Git handles URL rewrites for push operations. The `url.<base>.pushInsteadOf` configuration, which should rewrite push URLs specifically, is being ignored by `git remote get-url --push`, while the more general `url.<base>.insteadOf` is being applied instead.

The bug report includes a detailed reproduction case showing that when querying push URLs with `git remote get-url --push`, the system incorrectly applies the `insteadOf` rewrite rather than the `pushInsteadOf` rewrite that was specifically configured for push operations. This affects both single URL queries and queries with the `--all` flag.

The issue appears to be specific to the URL rewriting logic in the `get-url` subcommand, as other push operations (like actual pushes) correctly respect the `pushInsteadOf` configuration. The bug was found on Windows but likely affects all platforms, as it appears to be a logic error rather than a platform-specific issue.

This seems like a straightforward bug that needs fixing, as it breaks the documented behavior where `pushInsteadOf` should take precedence for push-related operations. The reproduction steps are clear and the expected vs. actual behavior is well-documented, making this a good candidate for review and patching.
