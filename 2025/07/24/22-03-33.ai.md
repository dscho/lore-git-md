This is a feature proposal for improving rebase conflict resolution feedback, specifically addressing the silent skipping of commits that become empty after conflict resolution. Junio C Hamano responds to Cameron Steffen's suggestion with a concrete but untested implementation approach.

The proposed change would add a warning message ("omitting a step that has become empty") in sequencer.c when Git skips a commit during rebase due to empty resolution. The patch is minimal - just 2 lines added to emit the warning. Hamano notes this is just a starting point and identifies several open questions: determining the right verbosity to ensure user awareness without being intrusive, and whether this warning might trigger in inappropriate contexts. He's also soliciting input from recent contributors to sequencer.c.

The change would make rebase behavior more transparent when users resolve conflicts by removing all changes, addressing a real workflow pain point where such skips currently happen silently. However, the implementation needs careful consideration of edge cases and appropriate warning contexts. The thread appears to be moving from problem discussion to concrete implementation exploration.
