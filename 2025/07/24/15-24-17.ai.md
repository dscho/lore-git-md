Bugfix and behavior change for submodule path reuse. This is the first patch in a two-part series addressing submodule handling issues, specifically preventing silent overwrites of .gitmodules configuration when reusing paths for new submodules.

The patch modifies `module_add()` in builtin/submodule--helper.c to detect when a proposed submodule name (derived from the path) is already registered for a different path in the repository. In such cases, the operation will fail unless --force is used, which then generates a unique name by appending numbers (e.g., "child1", "child2"). The change includes documentation updates explaining the new --force behavior and adds a test case in t7400-submodule-basic.sh that verifies the protection against name reuse.

Key technical details include:
- New checks using submodule_from_name() to detect name conflicts
- A strbuf-based mechanism for generating unique names when --force is used
- The test case demonstrates the scenario by moving a submodule then attempting to add a new one at the original path
- Documentation updates clarify that --force now serves this additional purpose beyond its existing ignore-path functionality

The change addresses a real-world edge case where submodule moves could lead to configuration loss, though the implementation maintains backward compatibility through the --force option. The patch appears well-constructed with appropriate test coverage and documentation updates.
