Test helper modernization (part 2/3)

This is the second patch in Jeff King's series to clean up the `test-delta` helper, following the first patch that simplified error handling. The change replaces manual file reading with `strbuf` operations, reducing the line count by 26 while incidentally fixing two subtle issues.

The patch switches from stat-and-malloc patterns to using `strbuf_read_file()`, which automatically handles buffer growth and EOF conditions. This addresses potential problems with integer truncation (when file sizes exceed size_t) and racy file changes (where stat and read could disagree). While these edge cases weren't critical for a test helper, their resolution comes as a free benefit of the refactoring.

The code now reads more idiomatically, with the input files stored in `strbuf` structs rather than separate pointer/length pairs. This matches Git's modern conventions and eliminates manual memory management for the input buffers. The output buffer remains heap-allocated since it's passed to delta functions that expect raw pointers.

As with the first patch, this maintains the pragmatic approach agreed in the thread - while test helpers can rely on process exit for cleanup, we still properly manage memory due to SANITIZE=leak requirements. The changes are straightforward improvements with no apparent downsides, continuing the series' trend of making the code both simpler and more correct. One final patch remains to address the output file descriptor handling.
