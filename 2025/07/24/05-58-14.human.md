This is a review follow-up in the `git refs list` feature series. Patrick Steinhardt provides minor feedback on Meet Soni's v3 patch that introduces the new `git refs list` subcommand as a wrapper around `for-each-ref`.

The review notes three small technical points about the implementation: (1) suggesting the documentation changes could have been split into a preparatory commit, (2) questioning whether the usage strings between `for-each-ref` and `refs list` should be identical except for the command name, and (3) expressing concern about duplicating the `REFS_LIST_USAGE` macro definition between files. 

Steinhardt acknowledges the current approach of making `for-each-ref` aware of `refs list` (modeled after `blame.c`) is pragmatic despite not being ideal, and suggests potential alternatives like moving the usage strings to a shared location or simplifying the usage text. These appear to be minor polish items rather than blocking issues, as the maintainer has already given informal approval to the overall approach in this v3 series. The feedback maintains the constructive tone of the thread while identifying small opportunities for improvement.
