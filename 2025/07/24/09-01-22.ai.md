This is a status update on GCC-based Rust compiler efforts, relevant to the ongoing Rust adoption discussion in Git. Pierre-Emmanuel Patry from Embecosm provides a timeline estimate for GCC-based Rust compilation support, which could help address platform compatibility concerns raised earlier in the thread.

The email reports progress on compiling Rust's libcore (a minimal subset of the standard library) using an older Rust version (1.49), with expectations to complete this work by end of summer. However, they note significant testing remains and anticipate bugs. The next target version would be Rust 1.78 to align with Rust-for-Linux requirements, though full compilation support for even the older 1.49 code is not expected until next year at best.

Key technical details include: the focus on libcore as a smaller initial target than the full standard library, the `rustc_codegen_gcc` project as a potential bridge for architectures not supported by LLVM (addressing Gentoo's platform support concerns), and the explicit version targeting (1.49 and 1.78) that could inform Git's Rust dependency strategy. The response comes in context of Patrick Steinhardt's query about timelines for alternative Rust implementations, showing this could help mitigate some of the compatibility issues raised by Gentoo maintainers earlier in the thread.
