This thread addressed a subtle inconsistency in Git's diff behavior where content-ignoring options (-w, -I) weren't properly respected in metadata outputs (--name-only, --raw, etc.). The issue was first reported by Lidong Yan, who noticed that files could appear in metadata outputs but not in patch output when using ignore options - a clear inconsistency.

After technical analysis revealed the root cause (metadata outputs were only comparing SHA values for performance), the discussion evolved through several design approaches. Jeff King and Junio Hamano provided key insights, with Jeff arguing this constituted a bug and Junio ultimately accepting the need to align the behaviors. The solution went through four iterations, settling on a clean `dry_run` mode approach that avoids full content examination when not needed.

The final v4 patch from Lidong implements this with a new `dry_run` flag and `quick_consume()` callback, maintaining performance while fixing the inconsistency. It has Jeff's Reviewed-by and addresses all technical concerns. Junio's final review focused on polishing commit messages, tests, and documentation. The patch is now ready for merging, resolving the original issue while preserving Git's performance characteristics for common diff operations.
