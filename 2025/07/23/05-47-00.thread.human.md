This thread examines an unexpected interaction between `git diff --ignore-matching-lines` and `--name-only` in Git 2.49.0, where the ignore pattern has no effect when combined with name-only output. Lidong Yan initially reported this as a bug, confirming it occurs even without external diff tools. Technical analysis traced the issue to how filtering happens in `diffcore_std()` versus `builtin_diff()`.

Junio Hamano has now weighed in, explaining that this behavior is actually intentional design. The core principle is that metadata-focused outputs like `--name-only` deliberately avoid examining file contents for performance reasons. While some content-sensitive options (like whitespace ignoring) are special-cased to affect exit codes, Hamano argues it wouldn't make sense for them to impact metadata outputs. He details the technical mechanisms like `diff_from_contents` and flag interactions that enforce this separation.

The discussion has shifted from treating this as a bug to recognizing it as a deliberate design choice. Hamano's position is that content-ignoring options shouldn't affect metadata outputs, as that would make their behavior unpredictably dependent on ignore patterns. The likely resolution appears to be documenting this behavior rather than changing it.
