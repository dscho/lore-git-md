Here's the human-readable thread summary:

The thread began with a bug report about `git diff`'s `--ignore-matching-lines` option not working when combined with `--name-only` in Git 2.49.0. The pattern matching was being ignored, causing all changed files to be listed regardless of the ignore pattern. Initial investigation ruled out external diff tools as the cause.

Lidong Yan followed up with a technical analysis pinpointing the issue. The problem stems from how the diff filtering pipeline works - the ignore_regex filter is only applied in `builtin_diff()`, but `--name-only` output bypasses this stage by going through `diffcore_std()` instead. This explains why the pattern matching fails in this mode.

While the behavior isn't explicitly documented as either intended or a bug, the implementation appears to be an oversight in how the filtering stages interact. The analysis provides clear technical details about where the filtering breaks down, though no patch has been proposed yet. Fixing this would require modifying the diff filtering pipeline to make `--ignore-matching-lines` work consistently across all output modes, including `--name-only`.
