This thread examines the interaction between Git's content-ignoring options (like `--ignore-matching-lines` and `-w`) and metadata output formats (`--name-only`, `--raw`). The discussion began with Lidong Yan reporting unexpected behavior where ignored changes still appeared in metadata outputs, which Junio Hamano explained stems from Git's design: metadata outputs deliberately avoid examining file contents for performance reasons.

The debate has evolved with strong technical and UX perspectives. Jeff King (peff) and Arne argued the current behavior violates user expectations, demonstrating cases where `--name-only` lists files that wouldn't appear in a full diff. Junio's latest response maintains the technical rationale while acknowledging these concerns. He clarifies that machine-readable `--raw` output must remain stable, and only `--name-status`/`--name-only` might be candidates for change - though he expresses caution about modifying longstanding behaviors.

The discussion now balances three factors: performance optimization (avoiding content examination), behavioral consistency, and backward compatibility risks. While Junio won't initiate changes himself, he remains open to reviewing proposals. Eric Sunshine has contributed documentation improvements to better explain the current behavior. The thread remains active with no clear resolution, representing a classic tradeoff between technical design purity and user experience.
