This thread addresses a subtle but important inconsistency in Git's diff behavior, where content-ignoring options like `-w` (ignore whitespace) and `-I<regex>` don't affect metadata outputs such as `--name-only`. Jeff King (peff) argued the current behavior violates user expectations, demonstrating cases where `-w` hides changes in regular diffs but still lists files in `--name-only` output. The technical discussion has progressed through several iterations, with Lidong proposing a solution that would apply filtering at the diffcore level while preserving performance for machine-readable formats.

The latest exchange focuses on implementation refinements. Lidong responds to Jeff's suggestion to use the existing `diff_from_contents` flag, agreeing to generalize the solution while addressing Junio's concerns about performance. The key challenge is avoiding redundant diff operations while maintaining output ordering - particularly tricky because some formats like `--stat` already run diffs internally. The discussion remains technical but productive, with all participants working toward a solution that balances consistency, performance, and backward compatibility.
