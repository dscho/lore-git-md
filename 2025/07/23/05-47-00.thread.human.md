This thread discusses the interaction between `git diff --ignore-matching-lines` and `--name-only` options, originally reported as a bug by Lidong Yan. The core issue is that `--ignore-matching-lines` (which filters diff output based on regex patterns) has no effect when combined with `--name-only` (which only shows changed filenames). 

Junio C Hamano, the Git maintainer, established the design principle behind this behavior: metadata-focused outputs like `--name-only` deliberately avoid examining file contents for performance reasons, instead comparing SHA values directly. Content-ignoring options shouldn't affect these metadata outputs, as that would make the results dependent on ignore patterns in potentially surprising ways.

Lidong Yan and others have explored whether `--name-only` could be considered a formatting variant of full diff output (where files with all changes ignored would be excluded), but recent discussion reinforces that these are fundamentally different operations under the hood. The SHA-comparison approach for `--name-only` is a key optimization that avoids generating full diffs when only filenames are needed.

Eric Sunshine contributed documentation improvements and suggested using `git log --format=reference` for standardized commit citations, which Yan adopted. While the maintainer's position is clear, some participants continue discussing alternative interpretations of how these options might interact. The thread remains open with no changes planned to the current behavior.
