Bug report and design discussion about interaction between `git diff --ignore-matching-lines` and `--name-only` in Git 2.49.0. Original report from Lidong Yan showed `--ignore-matching-lines` has no effect when combined with `--name-only`, confirmed not caused by external diff tools. Technical analysis revealed the behavior stems from `diffcore_std()` not applying ignore_regex filtering to file pairs, with filtering only in `builtin_diff()`. 

Junio C Hamano provides authoritative design context, explaining this is intentional rather than a bug. Core design principle: metadata-focused outputs like `--name-only` and `--raw` deliberately avoid examining blob contents when possible for performance. While some content-sensitive options (like whitespace ignoring) are special-cased to affect exit codes, Hamano argues content-ignoring options shouldn't affect metadata outputs as it would make answers pathologically dependent on ignore patterns. 

Lidong Yan confirms understanding of the design principle in follow-up: `--ignore-matching-lines` suppresses diff output for matching changes but doesn't affect whether a file is considered modified at the metadata level. This maintains the invariant that answers to "was this path modified?" don't depend on content-ignoring patterns.
