This is a performance optimization thread for `git blame` that has taken an interesting turn. The original patch aimed to reduce commit parsing overhead by requesting only basic author information in two `blame.c` call sites, but performance testing revealed negligible gains (less than 1 second improvement on a 180-second run). 

Han Young now reports their test results showing the optimization provides minimal benefit, confirming Patrick Steinhardt's earlier request for concrete measurements. More significantly, they acknowledge Junio Hamano's architectural point - since all callers actually need full commit details, maintaining the partial-parse capability may not be worth the code complexity. 

The email indicates Han will follow up with a patch to remove the `detailed` parameter from `get_commit_info()` entirely, effectively reverting the 2006 optimization (cee7f245d) that introduced this capability. This represents a pivot from optimization to simplification, as the thread has shown the partial parsing path is effectively dead code. The discussion exemplifies Git's empirical approach - even long-standing optimizations get re-evaluated when their value comes into question.
