This is a follow-up in the test helper resource leak fixes thread, where Jeff King proposes a more radical simplification of the `test-delta` helper's error handling. Building on the thread's established consensus that test helpers can take shortcuts with cleanup (since they exit immediately), King now suggests replacing all error recovery with direct `die()` calls.

The patch series (3 parts) completely overhauls `test-delta.c`'s approach: [1/3] replaces manual error checking with `die()` calls, [2/3] converts file reading to use `strbuf` for simpler memory management, and [3/3] adds a missing `close()` for the output file descriptor. The net result is a 53-line reduction in code while fixing several subtle issues - the potential integer truncation in `xmalloc()` and unchecked short reads that were noted earlier in the thread.

King acknowledges this diverges from Hoyoung Lee's original approach but argues it better aligns with the thread's emerging consensus about test helper simplicity. The changes eliminate all explicit resource cleanup paths (relying on process termination) while still maintaining compatibility with SANITIZE=leak checks through proper memory handling. The `strbuf` conversion in [2/3] particularly stands out as a significant improvement, making the code both safer and more idiomatic.

This appears to be the culmination of the thread's technical discussion, implementing the pragmatic approach that both Eric Sunshine and Junio Hamano had endorsed in prior messages. The patches now await final review, though given the maintainer's earlier positions, they seem likely to be accepted as the resolution to this cleanup effort.
