Feature patch for `git imap-send` adding message read/unread control.

Aditya Garg proposes adding configuration options to control whether sent messages are marked as read in IMAP folders. Currently, the behavior is inconsistent - messages are marked read when using curl but unread when using OpenSSL. The patch standardizes this by making "read" the default behavior for both backends while adding new `--[no-]mark-as-read` command-line and `imap.markAsRead` config options to override this.

The implementation touches documentation, command-line parsing, and both the OpenSSL and curl backend code paths. The author also clarifies that the `imap.folder` config setting will be used when no `--folder` option is specified, making the behavior more predictable.

One potential issue noted is that the new curl flag being used requires libcurl 8.13.0 or newer, which may not be available in all environments. The patch doesn't currently include version checking for this, which could cause problems on systems with older curl versions. The implementation otherwise looks straightforward and addresses a clear inconsistency in the existing behavior.
