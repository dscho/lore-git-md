Bugfix analysis for `git diff` option interaction between `--ignore-matching-lines` and `--name-only`. This email provides technical analysis of the previously reported issue where `--ignore-matching-lines` has no effect when combined with `--name-only`.

Lidong Yan confirms the reported behavior is not specific to external diff tools like difftastic, as the issue persists with `--no-ext-diff`. The analysis traces the problem to `diffcore_std()` not applying the ignore_regex filter to file pairs, with the filtering only occurring in `builtin_diff()`. This explains why the pattern matching fails to affect the output in `--name-only` mode, since that path bypasses the builtin diff rendering.

The email notes this behavior isn't explicitly documented as either intended or a bug, though the implementation suggests an oversight in how the filtering stages interact. The technical details provided (diffcore_std() vs builtin_diff() handling) give clear pointers for anyone investigating a fix, though no patch is proposed yet. The analysis implies this would require changes to the diff filtering pipeline to make `--ignore-matching-lines` work consistently across all output modes.
