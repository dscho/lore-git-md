This is a documentation patch clarifying the behavior of `push.default` configuration options, specifically the difference between `simple` and `current` modes.

The patch updates the documentation in `Documentation/config/push.adoc` to make the distinction between these two push behaviors clearer. While both modes push the current branch to a remote branch with the same name, `simple` has additional restrictions: it requires the upstream tracking branch to have exactly the same name as the current branch, and will error out if this isn't the case (unless `push.autoSetupRemote` is enabled). The documentation previously made these modes sound more similar than they actually are.

The changes include rewording the description of `simple` to explicitly state its stricter requirements, while keeping the description of `current` more straightforward. The patch also updates the introductory text to suggest `simple` rather than `upstream` as the recommended default for centralized workflows, which aligns with Git's current defaults since version 2.0.

This is a straightforward documentation improvement that should help users better understand these subtle but important differences in push behavior. The changes are focused and well-explained in the commit message. The patch touches only the relevant documentation file with clear, targeted edits.
