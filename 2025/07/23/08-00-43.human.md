This is a bug report follow-up regarding the interaction between `git diff --ignore-matching-lines` and `--name-only` options. Lidong Yan confirms the reported behavior where `--ignore-matching-lines` has no effect when used with `--name-only`, tracing it to how `diffcore_std()` handles filtering. 

The analysis suggests this isn't an issue with external diff tools (like difftastic), but rather a limitation in Git's core diff machinery - the ignore regex filtering only applies during the built-in diff output generation, not during the file pair filtering stage. While the documentation doesn't explicitly forbid this combination, the current behavior seems unintentional given the option's purpose.

The email provides useful technical context about where in the diff pipeline the filtering occurs (or fails to occur), but doesn't propose a specific fix. This appears to be a genuine implementation gap rather than a documentation issue, affecting both the core functionality and external diff helper integration. The thread remains open for further discussion or patches to address the behavior.
