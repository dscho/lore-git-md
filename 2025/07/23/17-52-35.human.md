This is a follow-up in the ongoing discussion about `git imap-send` message marking behavior. Junio C Hamano points out two technical concerns with the current patch:

1. **Code formatting**: The patch unnecessarily uses braces around single-statement blocks in the curl flag setting code, which doesn't match Git's typical style.

2. **Version compatibility**: The patch relies on `CURLULFLAG_SEEN` which was introduced in curl 8.13.0, while Git's minimum required version is 7.61.0. Junio clarifies that this "may not be OK" (correcting his earlier ambiguous wording).

The email doesn't introduce new arguments about the feature itself, focusing instead on these implementation details that would need to be addressed before the patch could be accepted. The thread's larger questions about default behavior and `send-email` integration remain open, but this response narrows in on concrete technical blockers.
