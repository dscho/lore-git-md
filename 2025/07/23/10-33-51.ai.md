Feature implementation adding pure-IMAP mode to `git send-email`, completing the v4 series' dual-workflow support. This patch introduces the "B2" mode from earlier discussions, allowing users to archive messages to an IMAP folder without SMTP transmission while retaining `send-email`'s formatting features.

Key technical additions:
- New config `sendemail.useImapOnly` and `--use-imap-only` flag
- Validation requiring `imap-sent-folder` when in pure-IMAP mode
- Maintains all existing `send-email` features (Cc manipulation, cover letters) for IMAP output
- Fixes documentation formatting for `--smtp-encryption` backtick usage

The implementation cleanly separates the pure-IMAP path from SMTP operations, with the same dry-run protections as the SMTP+archive workflow. Error handling enforces folder specification when in IMAP-only mode. The patch demonstrates tight integration with the existing IMAP-sent-folder infrastructure while avoiding SMTP codepaths entirely when requested.

This completes the series' technical scope by delivering both promised workflows:
1. Original SMTP+archive (messages sent via SMTP then copied to IMAP)
2. New pure-IMAP (messages archived directly without SMTP transmission)

With no outstanding technical issues and all review feedback addressed, the series now hinges solely on the philosophical question of whether this functionality belongs in core Git versus external scripts - a debate the author themselves initiated but which saw no new participants in v4. The pure-IMAP implementation may strengthen the case for inclusion by demonstrating a distinct use case beyond what simple piping could achieve.
