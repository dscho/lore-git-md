This is the second patch in a series adding IMAP-based message archiving to `git send-email`, now implementing the "pure-IMAP" mode that was previously discussed theoretically. The patch introduces a new `--use-imap-only` option (and corresponding `sendemail.useImapOnly` config) that allows users to bypass SMTP entirely and only archive messages to an IMAP folder. This complements the existing SMTP+archive workflow, giving users the full `send-email` feature set (like cover letters and Cc list manipulation) while still using IMAP as the final destination.

The implementation is straightforward, adding the new option to documentation and plumbing it through the Perl script with appropriate validation. A minor documentation fix (backtick formatting for `--smtp-encryption ssl`) is included as well. The patch maintains the "imap-sent-folder" terminology settled in previous iterations and properly handles dry-run scenarios.

This appears technically sound and completes the dual-mode vision for IMAP integration in `send-email`. While the author has previously questioned whether this belongs in core Git, the implementation itself seems uncontroversial - the remaining discussion appears to be about the feature's philosophical justification rather than technical merits.
