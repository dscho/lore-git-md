This is part of the ongoing `git repo info` implementation series, specifically addressing format design questions in the machine-readable output mode. The email responds to Junio Hamano's concerns about using LF as a field separator in the `--format=null` output mode. Lucas Seiki Oshiro defends the current design, noting it was suggested by Phillip Wood and aligns with `git config`'s behavior. Key technical points include: the separator appears between field names and values, field names are restricted to letters/dots (preventing embedded LFs), and values can contain LFs since parsing stops at the first LF after the key. The discussion reveals an implementation constraint where the first LF always marks the key/value boundary, even if values contain subsequent LFs. This thread interaction shows the careful balancing act between consistency with existing commands (`git config -z`) and ensuring robust parsing of the new `repo info` output format.
