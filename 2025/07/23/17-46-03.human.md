This is a response regarding a bugfix for `git imap-send`'s hitting version compatibility issues. Junio Hamano (the Git maintainer) is advising Aditya Garg to hold off on the patch due to CI failures caused by the patch's dependency on a very recent libcurl feature (v8.13.0, released just 3 months ago). 

The maintainer makes two key points: 1) They don't want to add conditional compilation to work around older libcurl versions, and 2) The patch should wait until Git's minimum libcurl requirement naturally increases in a few years. This effectively puts the proposed `--mark-as-read` feature on hold, though the technical approach was otherwise sound.

The exchange highlights a common challenge in open source maintenance - balancing new features against backward compatibility requirements, especially when CI infrastructure runs older software versions. The maintainer's stance suggests they prioritize broad compatibility over this particular feature at this time.
