This is a feature patch series (v3) introducing `git refs list` as a wrapper for `git for-each-ref`, part of the ongoing effort to consolidate ref-related commands under a unified `git refs` hierarchy. The series has evolved through maintainer feedback, with v3 specifically addressing test infrastructure concerns raised by Junio Hamano.

The key change in v3 restructures the test approach to follow the established shared test pattern used by git-blame/annotate. The core test logic has been extracted to a new `for-each-ref-tests.sh` file that both the original `t6300-for-each-ref.sh` and new `t1461-refs-list.sh` tests source. This replaces the previous environment variable substitution approach with clearer shell variable usage (`$git_for_each_ref`).

The implementation remains a thin wrapper forwarding all arguments from `cmd_refs_list` to `cmd_for-each_ref`, ensuring identical behavior. Documentation has been reorganized with shared options now in `refs-list-options.adoc`. The series maintains its conservative approach - introducing no behavior changes while establishing the framework for future ref command consolidation.

Technical details include:
- New files: `t/for-each-ref-tests.sh` (2141 lines of shared test logic), `t/t1461-refs-list.sh` (new test driver)
- Modified files: Documentation updates across `git-for-each-ref.adoc`, `git-refs.adoc`, plus new `refs-list-options.adoc`
- Implementation in `builtin/refs.c` adds the list subcommand while `builtin/for-each-ref.c` sees minor adjustments

The series appears well-considered, with clear responses to prior feedback. The test restructuring directly addresses maintainer concerns about readability and established practices. Performance considerations from earlier discussions remain deferred, as the focus remains on establishing the basic wrapper functionality and test infrastructure first.
