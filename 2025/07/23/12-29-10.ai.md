This is a feature patch for `git imap-send` that addresses an inconsistency in how sent messages are marked (read/unread) and adds user control over this behavior. The patch standardizes the default to marking messages as read regardless of whether curl or OpenSSL is used, while introducing both command-line option (`--[no-]mark-as-read`) and config setting (`imap.markAsRead`) to override this.

The changes touch documentation (adding the option to both config and man pages) and implementation (adding the flag handling in both the OpenSSL and curl code paths). The patch also clarifies that `imap.folder` serves as a fallback when `--folder` isn't specified, though this appears incidental to the main change.

The implementation looks straightforward - it adds a new global `mark_seen` flag defaulting to true, uses it to conditionally add the IMAP `\Seen` flag when using OpenSSL, and sets the corresponding `CURLULFLAG_SEEN` when using curl. The config parsing handles the new option alongside existing ones.

This seems like a well-scoped quality-of-life improvement that gives users more control while eliminating an implementation detail (SSL backend choice) from affecting observable behavior. The patch follows Git's standard patterns for adding new options and includes the expected documentation updates.
