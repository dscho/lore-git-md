Refactoring patch in Patrick Steinhardt's reflog migration series. This is the second patch in an 8-part series addressing reflog storage format migration issues, now complete with all technical components and test infrastructure finalized.

The patch reorganizes `git reflog` subcommands to group read-only operations (show, list, exists) before write operations (delete, drop, expire), and moves the broadest-scope write operation (expire) to the end. This restructuring prepares for adding a new "write" subcommand in a subsequent patch while making the command structure more logical. Changes appear in both documentation (git-reflog.adoc) and implementation (builtin/reflog.c).

Justin Tobler suggests adding a comment to document the ordering rationale for future contributors, noting that while the new structure makes sense, the pattern might not be obvious to others adding subcommands later. The patch itself is straightforward - just reordering declarations and usage strings - and fits cleanly into the larger series' goal of improving reflog handling during storage format migrations.
