This is a follow-up discussion to Patrick Steinhardt's patch adding a `git reflog write` subcommand, part of the reflog migration series between storage formats. Justin Tobler raises two documentation-related points about the implementation:

1. The new "write" subcommand should have a descriptive entry in the `git-reflog.adoc` man page, consistent with how other subcommands are documented. Currently it's listed in the SYNOPSIS but lacks its own section explaining usage and purpose.

2. The order of subcommands in the description section doesn't match their order in the SYNOPSIS after adding "write". The SYNOPSIS shows "write" between "exists" and "delete", while the description section keeps the original ordering.

The technical implementation of the same patch is reviewed positively - Justin notes the thorough validation of reference names and object IDs, and the correct use of the ref transaction API to write reflog entries. The accompanying test suite (t1421-reflog-write.sh) is also examined and found to be comprehensive, covering error cases and basic functionality.

This is a minor documentation polish request for an already-merged feature. The core functionality (adding manual reflog writing capability, particularly important for the reftable backend) remains unchanged. The discussion focuses solely on improving the user-facing documentation to match project conventions.
