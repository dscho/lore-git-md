This is a bugfix in the reflog migration infrastructure, part of Patrick Steinhardt's series to support moving reflogs between storage formats (files and reftable). Justin Tobler is reviewing a patch that fixes how committer identities are reconstructed during migration.

The issue occurs when migrating reflog entries between storage formats - the code was incorrectly passing the full committer info (name + email) as just the email field to `fmt_ident()`, resulting in malformed output like "pks <Patrick Steinhardt ps@pks.im>". The fix properly splits the identity into name and email components before formatting.

Justin confirms the technical approach looks correct: the identity is now split using `split_ident_line()`, the components are stored separately, and passed correctly to `fmt_ident()`. He notes some initial confusion about the strbuf management but sees it's needed for proper cleanup. The patch is part of a series where tests will be added in a follow-up commit.

This appears to be a straightforward fix for a clear bug in the reflog migration path. The change is well-contained and Justin's review gives confidence in the implementation, though the lack of immediate test coverage (to be added later) means readers may want to watch for the test follow-up.
