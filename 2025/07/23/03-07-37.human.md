This is a bug report about an unexpected warning message related to `core.fsync` configuration. The reporter encounters a warning "ignoring unknown core.fsync component 'true'" during clone/fetch operations, but finds no `core.fsync` configuration in their local repository. The warning appears consistently in Git versions 2.25.1 and 2.34.1.

The issue seems to originate from the remote repository's configuration rather than the local one, as the warning comes from the remote side (prefixed with "remote:"). The reporter is seeking an explanation for what might be causing this warning, as they cannot find any `core.fsync` configuration in their local setup.

This appears to be either a configuration parsing bug or an undocumented interaction with some server-side configuration. The warning suggests Git is receiving a value 'true' for `core.fsync` that it doesn't recognize as valid, though the standard boolean values for this setting would typically be 'true' or 'false'. The report is clear and reproducible, making it a good candidate for investigation by Git maintainers familiar with the fsync configuration system.
