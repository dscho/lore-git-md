Thread identity: Bug report about unexpected warning "ignoring unknown core.fsync component 'true'" during clone/fetch operations, reported across Git versions 2.25.1 and 2.34.1.

Core problem: Remote repository has malformed `core.fsync` configuration where 'true' is incorrectly used as a component name, triggering parser warnings during clone/fetch. The warning occurs when remote has `core.fsync=true` (boolean syntax) instead of proper component-based syntax (e.g., `core.fsync=loose-object`). Patrick Steinhardt confirmed this is purely a server-side configuration issue.

Current status: Issue fully resolved - original reporter Wang Jinfeng acknowledged the diagnosis and solution. Remote admin needs to correct configuration from `core.fsync=true` to proper syntax like `core.fsync=all`. No client-side changes required since malformed config isn't transferred locally. The warning serves its intended function of reporting invalid configuration.

Key technical details: `core.fsync` expects component names like 'loose-object' or 'pack'. The string 'true' is incorrectly interpreted as component name during remote operations. Warning appears with "remote:" prefix confirming server-side origin. Correct syntax for enabling fsync globally is `core.fsync=all`.
