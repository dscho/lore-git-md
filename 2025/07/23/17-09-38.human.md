This is a discussion about the behavior of `git diff --ignore-matching-lines` when combined with `--name-only`. Junio Hamano responds to Lidong Yan's bug report, clarifying the design principles behind these options.

The thread had previously identified that `--ignore-matching-lines` has no effect when used with `--name-only`, tracing the issue to how diff filtering is implemented. Hamano explains this is intentional - options like `--name-only` that deliberately lose information (showing only filenames rather than full diffs) traditionally ignore content-based filters like whitespace or regex matching for optimization reasons.

He notes that while some content-aware options (like `--quiet`) do properly consider ignore patterns when determining exit codes, output formats like `--name-only` and `--raw` intentionally bypass these filters. Hamano argues this makes sense conceptually - when asking "which files changed", the answer shouldn't depend on whether we're ignoring certain line patterns.

The discussion provides important context about Git's diff machinery design philosophy, suggesting this isn't a bug but rather a deliberate (if perhaps underdocumented) behavior. This helps frame future discussion about whether the current behavior should be changed or just better documented.
