Test helper simplification proposal

Jeff King responds to the ongoing discussion about test-delta resource cleanup with a radical simplification: rather than carefully managing file descriptors and cleanup paths, he proposes just using `die()` on errors. This lets the OS handle cleanup when the process exits, matching the "quick-and-dirty" nature of test helpers. His patch removes 33 lines of cleanup code while maintaining the same functionality.

The new version replaces manual error checking with `xopen()` and `die_errno()`, eliminating the need for explicit `close()` calls on error paths. King notes this approach also incidentally fixes two minor bugs: potential integer truncation when allocating buffers (a possible security issue) and incomplete read handling. He suggests further improvements could be made by using `strbuf` instead of manual memory management.

This represents a significant departure from the original resource-leak-fixing goal of the series, but King argues it's more appropriate for test code. The change is clean and well-justified, though it may surprise those expecting incremental fixes. The patch appears technically sound and simplifies maintenance while actually improving correctness in subtle ways.
