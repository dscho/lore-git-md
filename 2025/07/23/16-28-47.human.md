This is a discussion about output format details in the ongoing `git repo info` implementation, part of Lucas Seiki Oshiro's GSoC project. The thread has been debating the choice of field separators in the machine-readable output format (`--format=null`). Junio Hamano questioned the use of LF as a separator between keys and values, suggesting NUL might be more consistent with other Git commands. Lucas defends the LF choice, noting it matches `git config`'s behavior and that keys are restricted to letters/dots so parsing remains unambiguous. The discussion highlights an ongoing tension between consistency with existing commands and the specific constraints of this new subcommand. This is a relatively minor point in the larger architecture, but shows the careful consideration going into the design.
