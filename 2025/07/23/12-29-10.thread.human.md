This thread discusses Aditya Garg's proposal to standardize and control how `git imap-send` marks messages as read/unread in IMAP folders. The current implementation introduces a global `mark_seen` flag (defaulting to true) with backend-specific handling for both OpenSSL and curl, along with new command-line (`--[no-]mark-as-read`) and config (`imap.markAsRead`) options.

Junio C Hamano raised several concerns in review: questioning the change from the previous unmarked default behavior (particularly given minimal OpenSSL backend usage), suggesting the need for per-invocation control granularity, and flagging some code style issues. Garg has responded that the curl backend already marked messages as read by default (making this less of a breaking change), noted the CLI option provides invocation-level control, and committed to fixing the style issues.

The latest response from Garg further clarifies that the command-line option does provide the per-invocation control Junio wanted, and raises (but doesn't implement) the idea of adding similar controls to `git send-email` for FCC operations, since users might want different policies for direct `imap-send` versus email-sent-via-FCC cases.

Key open questions remain about curl version compatibility (the patch requires 8.13.0+ while Git's minimum is 7.61.0) and whether the default-mark-as-read behavior is justified. The discussion is currently between Garg and Junio, with code changes affecting `builtin/imap-send.c` and related documentation. While some progress has been made on clarifying the control mechanisms, the fundamental questions about compatibility and defaults remain unresolved.
