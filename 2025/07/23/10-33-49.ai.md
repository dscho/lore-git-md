This is a feature patch series extending `git send-email` with IMAP integration capabilities, now in its fourth iteration. The v4 series addresses the dry-run bug identified in v3 while adding a new pure-IMAP mode that allows archiving messages without SMTP transmission.

The first patch maintains the core "archive-after-SMTP" functionality with fixes to prevent IMAP operations during dry runs. The second patch introduces a significant new capability: users can now bypass SMTP entirely and only archive messages to IMAP folders via a new workflow. This implements what was previously discussed as a potential future direction (the "B2" pure-IMAP mode).

Technical changes in v4 include:
- Dry-run protection added to both IMAP operations (preventing unintended archiving during test runs)
- New pure-IMAP mode via `--imap-sent-folder` without SMTP transmission
- Documentation clarifications and error message refinements
- Maintained backward compatibility with existing `sendemail.imapSentFolder` config

The series continues to use the "imap-sent-folder" terminology settled in v3 while expanding its functionality. The implementation now spans both major workflows: SMTP+archive (original use case) and archive-only (new in v4). The patches touch message handling in `git-send-email.perl` and header processing in `imap-send.c`, with corresponding documentation updates.

While the technical implementation appears solid, the philosophical question about the feature's necessity - raised by the author themselves in previous iterations - remains unresolved. The v4 expansion to include pure-IMAP mode may reignite discussion about whether this belongs in core Git versus external scripts, though no such debate has emerged in this submission. The dry-run fix addresses the only outstanding technical issue from v3, making this series functionally complete.
