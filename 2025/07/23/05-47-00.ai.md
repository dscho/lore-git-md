This is a bug report regarding `git diff` behavior with the `--ignore-matching-lines` and `--name-only` options. The reporter notes that when both flags are used together, `--ignore-matching-lines` has no effect on the output - all changed files are listed regardless of the ignore pattern. The issue is reproducible in Git 2.49.0 without external diff tools (`--no-ext-diff`).

The report also mentions a separate but possibly related issue where the external diff helper difftastic ignores the `--ignore-matching-lines` option entirely. The reporter is unsure whether this is a problem with difftastic itself or with Git's external diff helper interface.

Key technical details:
- Core command: `git diff` with `--ignore-matching-lines` and `--name-only`
- Version affected: Git 2.49.0
- Related component: external diff helper interface
- External tool mentioned: difftastic

The report doesn't include a proposed fix but clearly documents the unexpected behavior. The interaction between these two options appears undocumented, suggesting this may be an oversight in the implementation rather than a documented limitation. The mention of external diff helpers adds a potential second dimension to the issue that may need investigation.
