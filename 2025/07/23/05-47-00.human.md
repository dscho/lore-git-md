This is a bug report about unexpected interaction between `git diff` options. The author, Arne, notes that `--ignore-matching-lines` (which filters diff output by skipping hunks matching a pattern) has no effect when combined with `--name-only` (which shows only filenames). The behavior persists in Git 2.49.0 and appears undocumented. 

The report is well-formed, showing the exact command to reproduce (`git diff --no-ext-diff --name-only --ignore-matching-lines`) and noting a possibly related issue where the same filtering option is ignored by the external diff helper difftastic. The author is unsure whether the external helper issue is Git's responsibility or difftastic's.

This looks like a legitimate bug report that warrants investigation - the combination of these options should either work as expected (filtering the file list based on the ignore pattern) or be explicitly documented as incompatible. The mention of external diff helpers suggests there may be deeper plumbing issues around how diff filtering is implemented.
