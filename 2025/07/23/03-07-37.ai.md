This is a bug report about an unexpected warning message related to `core.fsync` configuration. The reporter encounters a warning "ignoring unknown core.fsync component 'true'" during clone/fetch operations, but finds no `core.fsync` configuration in their local repository. The issue persists across Git versions 2.25.1 and 2.34.1.

The warning suggests the remote repository has some malformed `core.fsync` configuration that's being rejected by Git's configuration parser. The string 'true' is being treated as an invalid component name for the fsync configuration, which normally expects specific component names like 'loose-object' or 'pack'. The warning appears during the remote operation but doesn't persist locally because the invalid configuration isn't being transferred.

This appears to be a server-side configuration issue where someone has incorrectly set `core.fsync=true` (likely intending it as a boolean) rather than using the proper component-based syntax. The report doesn't include investigation of the remote repository's configuration, which would be needed to confirm the exact cause. The behavior is consistent across multiple Git versions, suggesting it's not a version-specific regression but rather a configuration syntax misunderstanding.
