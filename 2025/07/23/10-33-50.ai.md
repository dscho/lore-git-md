This is the first patch in a 2-part series implementing IMAP-based sent mail archiving for `git send-email`. The patch introduces core functionality for archiving sent emails to an IMAP folder after SMTP transmission, addressing cases where email providers (like iCloud) don't automatically save SMTP-sent messages to the Sent folder.

Key technical elements:
- New config option `sendemail.imapSentFolder` and CLI flag `--imap-sent-folder` specify the target IMAP folder
- Implementation pipes messages to `git imap-send` after SMTP transmission completes
- Preserves Bcc headers in archive copies (which are normally stripped from SMTP messages)
- Adds documentation for the new feature in both config and command manpages
- Modifies `imap-send.c` to handle the special "From git-send-email" header format

The patch touches several components:
- `git-send-email.perl` gains new message handling logic and IMAP piping
- `imap-send.c` gets modified message parsing to accommodate the new header format
- Documentation updates explain the feature and its configuration

This represents the SMTP+archive workflow portion of the series, where emails are first sent via SMTP then archived via IMAP. The implementation appears thorough, including proper dry-run protection and error handling. The commit message clearly explains the motivation (iCloud's SMTP behavior) and the solution's relationship to existing email client workflows.

The patch builds on previous discussion that settled on the "imap-sent-folder" naming (changed from earlier "imapfolder") and maintains backward compatibility. While the author has questioned whether this belongs in core Git, the implementation itself seems technically sound and well-documented.
