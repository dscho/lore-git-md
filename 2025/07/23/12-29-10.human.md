Feature patch for `git imap-send` adding message read-status control.

Aditya Garg addresses an inconsistency in `git imap-send` where sent messages were marked as read when using curl but unread when using OpenSSL. The patch standardizes the behavior to mark messages as read by default in both cases, while adding new `--[no-]mark-as-read` command-line options and `imap.markAsRead` config setting to let users override this.

The changes include documentation updates for both the config and man page, plus implementation in both the OpenSSL and curl code paths. The patch also clarifies that `imap.folder` will be used when the `--folder` option isn't specified, though this appears to be a minor documentation fix rather than a behavior change.

The implementation looks straightforward, with clear additions to handle the new option in both transport backends. The commit message explains the motivation well, and the patch touches all the right places (documentation, command-line interface, and both implementations). This seems like a useful quality-of-life improvement for users who care about their IMAP folder state.
