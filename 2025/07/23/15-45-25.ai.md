This is a feature patch for `git imap-send` that addresses an inconsistency in how sent messages are marked (read vs unread) between different backends. The patch standardizes the behavior to mark messages as read by default for both curl and OpenSSL implementations, while adding configuration options to control this behavior.

The changes introduce a new `--[no-]mark-as-read` command-line option and corresponding `imap.markAsRead` config setting. The implementation modifies both the OpenSSL path (by adding the `\Seen` flag to APPEND commands) and the libcurl path (using the new `CURLOPT_UPLOAD_FLAGS` with `CURLULFLAG_SEEN`). The documentation is updated to reflect these changes and clarify folder selection behavior.

A potential issue is noted regarding libcurl version compatibility - the `CURLOPT_UPLOAD_FLAGS` feature requires libcurl v8.13.0 or newer, which may not be available in all environments. The patch doesn't currently include version checking logic to handle older libcurl versions, which could cause build or runtime failures in CI systems with older dependencies.

The patch appears well-structured with documentation and implementation changes aligned, though the version compatibility concern may need addressing before merging. The change is focused and maintains backward compatibility by keeping the default behavior (marking as read) consistent with one of the existing implementations.
