This thread introduces a patch to standardize how `git imap-send` marks sent messages (read vs unread) across different backends. The current behavior is inconsistent between the OpenSSL and libcurl implementations. The proposed solution adds a new `--[no-]mark-as-read` command-line option and corresponding `imap.markAsRead` config setting to control this behavior uniformly.

The patch modifies both backend implementations to mark messages as read by default, which matches one of the existing behaviors. For OpenSSL path, it adds the `\Seen` flag to APPEND commands, while for libcurl it uses the new `CURLOPT_UPLOAD_FLAGS` feature. The documentation has been updated to clarify these changes and the folder selection behavior.

A notable concern is that the new libcurl feature requires version 8.13.0 or newer, which might not be available in all environments. The patch currently lacks version checking logic, which could cause issues in CI systems with older libcurl versions. This compatibility consideration may need to be addressed before the patch can be merged. The change is otherwise well-structured and maintains backward compatibility while resolving the inconsistency.
