The thread discusses standardizing how `git imap-send` marks sent messages as read between its OpenSSL and curl backends. The proposed solution would make both backends mark messages as read by default, with new `--[no-]mark-as-read` and `imap.markAsRead` configuration options. However, the curl backend requires libcurl 8.13.0 or later for the necessary `CURLOPT_UPLOAD_FLAGS` feature, and Junio Hamano has rejected adding version-checking workarounds to support older libcurl versions. This means the patch cannot proceed until future Git versions can require newer libcurl, leaving the current inconsistent behavior (OpenSSL marks as read, curl does not) in place for now. Aditya Garg has acknowledged this decision, confirming the patch is shelved but remains valid for future consideration once the dependency situation changes. The documentation updates included in the patch will still be useful when the change is eventually implemented. For now, the thread is effectively on hold with no further action expected until libcurl version requirements can be raised.
