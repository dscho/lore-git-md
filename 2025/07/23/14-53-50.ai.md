This is a technical discussion about the field system implementation in the `git repo info` command series. Phillip Wood responds to Justin Tobler's concerns about the callback-per-key architecture, focusing on string handling limitations.

Phillip identifies a key constraint in the current design: the `get_value_fn` callback returns a `const char*`, preventing allocation of dynamic strings. He proposes two alternative approaches:
1. Passing a `struct strbuf` to callbacks for building values incrementally
2. Having callbacks invoke a function pointer to emit key-value pairs directly

The discussion continues architectural questions from the thread about how the field system might need to evolve for future subcommands like `repo stats`, where batch operations may be more efficient than per-key callbacks. Phillip's suggestions address both immediate string handling concerns and potential future flexibility needs.
