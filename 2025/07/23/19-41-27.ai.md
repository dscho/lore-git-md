This is a bugfix in the reflog migration infrastructure, specifically how committer identities are handled when moving reflogs between storage formats. The patch addresses an issue where the full committer info (name + email) was being incorrectly passed as just the email field to `fmt_ident()`, resulting in malformed output like "pks <Patrick Steinhardt ps@pks.im>".

The fix involves properly parsing the committer string into separate name and email components using `split_ident_line()`, then passing these correctly to `fmt_ident()`. The changes include adding new `strbuf` fields to `migration_data` and `reflog_migration_data` structs to store these components separately, with proper initialization and cleanup.

Justin Tobler's review confirms the technical correctness of the approach, noting the patch properly handles the identity parsing and maintains the ref transaction API usage. The review also clarifies that the additional `strbuf` fields are necessary for proper memory management, even though their use isn't immediately obvious at first glance.

This appears to be a well-justified fix that maintains the reflog migration functionality while correcting a clear bug in identity formatting.
