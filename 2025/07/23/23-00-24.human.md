This is a documentation patch clarifying the behavior of `push.default` configuration options. Dan Fabulich noticed that the documentation made `simple` and `current` sound identical when they actually have an important difference. 

The patch updates the docs to clearly explain that while both modes push the current branch to a same-named remote branch, `simple` has stricter requirements: it will fail if the upstream tracking branch's name doesn't match the current branch name, or if no upstream is configured (unless `push.autoSetupRemote` is enabled). The docs now also better explain that `simple` is the default and recommended mode for centralized workflows.

The changes are straightforward and improve clarity in an area that could confuse users about these similar-but-different push behaviors. The patch maintains the existing documentation structure while making the distinctions more precise. This seems like a useful clarification that shouldn't be controversial.
