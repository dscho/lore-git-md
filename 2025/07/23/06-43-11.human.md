Feature patch introducing `git refs list` as part of the ref command consolidation effort. This is the first of three patches in v3 of the series, implementing a thin wrapper around `git for-each-ref` with identical functionality.

The patch moves all option documentation into a shared `refs-list-options.adoc` file that both `git-for-each-ref` and `git-refs` man pages include, eliminating duplication. The implementation forwards all arguments directly to `cmd_for-each_ref` while adding the necessary plumbing in `builtin/refs.c` to expose the new subcommand.

This version follows the established pattern from previous rounds of review, with thorough documentation updates and careful attention to maintaining backward compatibility. The changes are well-scoped - the 2141-line test restructuring mentioned in the thread context will appear in later patches of the series.

The patch appears technically sound, with multiple mentors (Patrick Steinhardt, shejialuo, Karthik Nayak) having reviewed it. The approach of wrapping rather than duplicating `for-each-ref` ensures behavior consistency and makes future maintenance easier. Documentation changes follow Jean-Noël Avila's standardization work and address Eric Sunshine's earlier feedback.
