This is a bugfix proposal related to Git's comment character handling during commit message processing. The patch addresses an edge case where `core.commentChar=auto` interacts poorly with existing conflict markers in commit messages.

The issue occurs in two scenarios: when conflict comments remain in the message, and when those comments use a non-standard character (like "%" instead of "#"). In both cases, Git's auto-selection of a comment character can inadvertently include conflict markers in the final commit message rather than treating them as comments.

The author presents two potential fixes. The first approach (suggested by Phillip Wood) would force the comment character to "#" when in auto mode, ensuring consistent behavior even if it means some edge cases might break cleanly. The second approach would skip auto-selection entirely when conflict markers are detected, preserving the existing comment character but potentially ignoring the auto setting in some cases.
