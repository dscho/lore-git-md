This is a bugfix patch addressing remote naming collisions in Git's porcelain commands. Jeff King proposes a solution for the edge case where remote names like "outer" and "outer/inner" can create confusing refspec overlaps during operations like `git fetch --all`.

The patch adds validation in `git remote add` to prevent users from accidentally creating such ambiguous remote names through the porcelain interface, while still allowing manual config edits for advanced cases. It detects both subset ("outer/inner" after "outer") and superset ("outer" after "outer/inner") naming conflicts, with clear error messages. The implementation includes tests verifying the new validation behavior.

King acknowledges this doesn't solve all possible refspec collision cases (like mirror remotes), but focuses on preventing the most obvious foot-guns in the porcelain interface. The approach maintains backward compatibility while adding sensible guardrails for common workflows. The patch appears well-considered, with thorough test coverage for the new validation logic.
