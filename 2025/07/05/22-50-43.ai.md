This is a follow-up in the thread about both the SSH signing tempfile leak fix and the DCO/pseudonym policy discussion. The email contains two main components:

First, redoste responds to the earlier suggestion about adding a test for the tempfile leak by proposing a test that would verify no temporary signing key files remain after operations. The test would use `TMPDIR` to avoid touching system `/tmp` and check that no `.git_signing_key_tmp*` files exist after signing operations. The author is willing to include this in a v2 if reviewers think it appropriate.

Second, redoste provides personal context about their use of a pseudonym, explaining it relates to gender identity considerations similar to those brian m. carlson mentioned earlier. They reference the Linux kernel's move away from "real name" requirements and express willingness to use a different name if needed, though they note the triviality of the patch may make copyright concerns minimal.

Key technical details for future reference: The proposed test would modify `t/t7528-signed-commit-ssh.sh` to add TMPDIR control and file existence checking.
