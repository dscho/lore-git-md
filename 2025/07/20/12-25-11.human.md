This is a follow-up discussion about patch 1/2 in K Jayatheerth's submodule configuration series, which was previously approved with minor documentation suggestions. The patch prevents `.gitmodules` overwrites when adding submodules at paths that previously hosted other submodules.

The current discussion focuses on the behavior of the `--force` option when a name collision occurs. D. Ben Knoble raised concerns that automatically incrementing names (e.g., turning "child" into "child2") might be unintuitive for users expecting `--force` to simply overwrite. K Jayatheerth acknowledges this concern and offers to modify the behavior to instead remove the previous submodule entry when `--force` is used, which they suggest might be more intuitive.

This appears to be a final polish discussion before integration, as the technical implementation has already been approved. The author is responsive to feedback and willing to make this last behavioral adjustment if it aligns with maintainer expectations. The core functionality - preventing accidental configuration overwrites - remains uncontroversial and well-tested.
