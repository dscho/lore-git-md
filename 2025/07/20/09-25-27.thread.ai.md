[PATCH v2] git send-email: add IMAP folder archiving for sent messages

Aditya Garg's patch series implements IMAP-based message archiving in `git send-email`, enabling providers like iCloud Mail to store SMTP-sent messages via IMAP. The implementation uses config and CLI options to route messages through `git imap-send` after SMTP transmission, with work spanning `git-send-email.perl` (message handling) and `imap-send.c` (header preservation).

Version 2 incorporated Eric Sunshine's doc fixes and improved IMAP failure handling. The discussion has evolved through three phases:
1. Initial naming debate between maintainers (Junio C Hamano, brian m. carlson) advocating for sent-specific terminology versus Garg's generic "imapfolder" design
2. Junio's architectural proposal distinguishing IMAP archiving (B1) from transport (B2) modes
3. Current discussion where Garg accepts "sent-folder" naming but questions its implications, while expressing doubts about B2 mode's practical value given `imap-send`'s maintenance history

Technical implementation remains stable in `git-send-email.perl` and `imap-send.c`. The debate now focuses on:
- Whether to support both B1 (archiving) and B2 (transport) modes, with Garg arguing B2 has limited use
- How to name the archiving option to be clear about purpose without implying folder naming restrictions
- Balancing semantic clarity ("sent-folder") with flexibility to archive to any IMAP folder

Participant positions:
- Junio maintains preference for explicit mode separation
- Garg accepts "sent-folder" terminology but seeks to preserve folder flexibility
- brian m. carlson continues to balance feature value with naming concerns

Open questions:
- Should B2 mode be implemented given Garg's reliability concerns?
- Does "sent-folder" adequately communicate support for custom folders?
- Is there a naming alternative that satisfies both semantic clarity and flexibility?

The thread approaches resolution with Garg showing willingness to compromise on terminology while maintaining the core archiving functionality. Final decisions needed on mode support and exact option naming before merge.
