[PATCH v2] git send-email: add IMAP folder archiving for sent messages

Aditya Garg's patch series implements IMAP folder archiving in `git send-email` to address email providers (notably iCloud Mail) that don't save SMTP-sent messages to Sent folders. The feature adds `sendemail.imapfolder` config and `--imap-folder` CLI option to route successfully sent messages through `git imap-send` for IMAP storage.

Technical implementation spans:
- `git-send-email.perl` collects messages during SMTP sending and batches them to `imap-send`
- `imap-send.c` handles "From git-send-email" prefixed messages with special header preservation (including Bcc)
- Documentation covers the workflow and IMAP credential setup

Version 2 incorporated Eric Sunshine's documentation fixes:
- Commit message wording improvements
- "the all" -> "all" correction
- More concise `git imap-send` setup instructions
- "setup" -> "set up" in help text

Junio C Hamano's latest feedback focuses on naming semantics, suggesting more specific terms like "sent" or "fcc" (file carbon copy) instead of generic "imapfolder" to:
- Better reflect the current sent-message archival purpose
- Avoid constraining future IMAP-related `send-email` enhancements
- Maintain consistency with email terminology

No technical objections remain - the discussion has progressed from initial implementation through documentation polish to this final naming consideration. The feature remains opt-in with all core functionality validated. Open points from earlier discussion (IMAP failure handling, header preservation) were addressed in v2 without further comment.

Key files affected:
- `git-send-email.perl` (message handling)
