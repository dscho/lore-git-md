[PATCH v3] git send-email: add IMAP sent-folder archiving

Aditya Garg's patch series implements IMAP-based message archiving in `git send-email`, enabling providers like iCloud Mail to store SMTP-sent messages via IMAP. The v3 iteration finalizes naming as "imap-sent-folder" while maintaining core functionality to archive messages through `git imap-send` after SMTP transmission. Implementation spans `git-send-email.perl` (message handling) and `imap-send.c` (header preservation).

Key technical details:
- Config option: `sendemail.imapSentFolder`
- CLI flag: `--imap-sent-folder`
- Preserves Bcc headers in archive copies
- Uses existing `git imap-send` infrastructure with header parsing adjustments

Evolution from previous versions:
- v1: Initial "imapfolder" implementation
- v2: Incorporated Eric Sunshine's doc fixes and improved failure handling
- v3: Renamed to "imap-sent-folder" per Junio's preference while maintaining folder flexibility

Participant positions:
- Junio C Hamano: Advocated for sent-specific terminology and proposed two distinct modes (B1: archive, B2: pure IMAP send)
- Aditya Garg: Accepted "sent-folder" naming but notes it might imply unwanted restriction to "Sent" folders; skeptical about implementing B2 mode due to `imap-send` maintenance concerns and existing pipe-to-imap workflow
- brian m. carlson: Balanced feature value with naming concerns

Resolved:
- Naming debate settled on "imap-sent-folder" terminology
- Core archiving functionality stabilized

Open questions:
- Whether "imap-sent-folder" name should be clarified to not restrict folder choice
- Pure-IMAP transport mode (B2) remains unimplemented due to Garg's concerns about `imap-send` maintenance and existing workflow alternatives
- No outstanding technical objections to current archiving approach

The series appears ready for merge with its current focus on the archiving use case, having addressed naming concerns while maintaining the ability to archive to any IMAP folder. Garg's latest response provides important context about real-world usage patterns (custom folder needs) and clarifies the technical distinction between the proposed archive-after-send functionality and existing pipe-to-imap workflows.
