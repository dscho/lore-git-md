[PATCH v2] git send-email: add IMAP folder archiving for sent messages

This patch series introduces IMAP folder archiving to `git send-email`, addressing email providers (notably iCloud Mail) that don't save SMTP-sent messages to Sent folders. The core change adds a new `sendemail.imapfolder` config option and `--imap-folder` command-line flag that pipes successfully sent messages to `git imap-send` for storage in the specified IMAP folder.

Technical implementation spans Perl and C code:
- `git-send-email.perl` collects messages during SMTP sending and batches them to `imap-send` after successful transmission
- `imap-send.c` adds special handling for "From git-send-email" prefixed messages to properly parse headers including Bcc (which SMTP normally strips)
- Documentation updates explain the new workflow and required IMAP credential setup

Version 2 changes from v1:
- Fixed indentation in `imap-send.c` modifications
- Improved commit message wording
- Maintained all core functionality from v1

The feature remains opt-in and backward compatible when not configured. Key open considerations for review feedback:
- Whether this functionality belongs in core vs remaining external
- Robustness of IMAP connection failure handling
- Header preservation requirements (particularly for Bcc fields)

Implementation appears thorough with clear documentation and edge case handling. No reviews or objections have been raised yet in this thread. The changes are focused on the email-sending workflow without broader architectural impacts, touching `git-send-email.perl`'s message handling, IMAP-specific header processing in `imap-send.c`, and documentation of the new option.
