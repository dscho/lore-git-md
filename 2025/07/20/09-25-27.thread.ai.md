[PATCH v2] git send-email: add IMAP folder archiving for sent messages

Aditya Garg's patch series implements IMAP-based sent message archiving in `git send-email`, addressing providers like iCloud Mail that don't save SMTP-sent messages. The current implementation uses `sendemail.imapfolder` config and `--imap-folder` CLI option to route messages through `git imap-send` for IMAP storage after successful SMTP transmission.

Technical implementation spans:
- `git-send-email.perl` collects and batches messages for `imap-send`
- `imap-send.c` handles special header preservation (including Bcc)
- Documentation covers workflow and credential setup

Version 2 incorporated Eric Sunshine's documentation fixes. Junio C Hamano and brian m. carlson raised naming concerns about the generic "imapfolder" terminology potentially limiting future IMAP-related enhancements in `git send-email`. Garg now responds defending the generic naming as intentional design to support multiple IMAP use cases (Sent, Outbox, Drafts etc.), suggesting future exclusive-IMAP functionality could use a separate `use_imap_only` config alongside folder settings.

The discussion represents the final naming debate before merge, with:
- Junio/brian advocating for more specific sent-message terminology
- Garg maintaining generic naming preserves flexibility
- Technical implementation stable (IMAP failure handling and header preservation addressed in v2)
- All core functionality validated as opt-in feature

Key files affected remain:
- `git-send-email.perl` (message handling)
- `imap-send.c` (header processing)
- Documentation (new options and workflow)

No technical objections remain - this is purely about configuration naming semantics as the last pre-merge discussion point. Garg shows willingness to consider alternatives while preserving design's flexibility for future IMAP use cases beyond sent-message archival. Next step is resolution of naming consensus between maintainers and author.
