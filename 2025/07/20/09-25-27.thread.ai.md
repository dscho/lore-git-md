[PATCH v2] git send-email: add IMAP folder archiving for sent messages

Aditya Garg's patch series implements IMAP-based sent message archiving in `git send-email`, addressing providers like iCloud Mail that don't save SMTP-sent messages. The current implementation uses `sendemail.imapfolder` config and `--imap-folder` CLI option to route messages through `git imap-send` for IMAP storage after successful SMTP transmission.

Technical implementation spans:
- `git-send-email.perl` collects and batches messages for `imap-send`
- `imap-send.c` handles special header preservation (including Bcc)
- Documentation covers workflow and credential setup

Version 2 incorporated Eric Sunshine's documentation fixes. Junio C Hamano and brian m. carlson now agree the naming should be more specific than "imapfolder" to:
- Better reflect the sent-message archival purpose
- Avoid constraining future IMAP-related enhancements
- Maintain email terminology consistency
Carlson provides real-world validation from self-hosted mail perspective.

No technical objections remain - discussion has progressed from implementation through documentation to this final naming consideration. The feature remains opt-in with all core functionality validated. Earlier concerns (IMAP failure handling, header preservation) were addressed in v2.

Key files affected:
- `git-send-email.perl` (message handling)
- `imap-send.c` (header processing)
- Documentation (new options and workflow)
