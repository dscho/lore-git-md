This is a licensing discussion in the Rust xdiff optimization series, specifically addressing concerns about compatibility between Git's GPL/LGPL code and Gitoxide's MIT/Apache dual-license.

Phillip Wood responds to Johannes Schindelin's suggestion to add a license header allowing Rust xdiff code to be used in Gitoxide. Wood raises two key concerns: (1) gradually increasing Rust code under different licenses could effectively relicense Git without proper process, and (2) license incompatibility would complicate future C-to-Rust conversions of existing code (particularly xdiff's LGPL components). He argues any license changes should be discussed separately from this technical optimization series.

The email highlights an important policy question about how Git's traditional GPL/LGPL licensing interacts with Rust components and related projects like Gitoxide. Wood maintains a conservative position, preferring to keep the current license structure unless there's explicit community consensus for change. This discussion remains unresolved in the thread, with implications for both the immediate Rust xdiff work and longer-term Rust adoption in Git.
