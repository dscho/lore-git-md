This is a feature patch implementing the `pull.autoStash` configuration option, addressing the final documentation and test refinements from Junio's review of the v1 patch. The patch establishes a three-level precedence for autostash behavior in `git pull`:

1. Command-line flags (`--autostash`/`--no-autostash`) take highest priority
2. New `pull.autoStash` config (when set) overrides operation-specific settings
3. Falls back to `rebase.autoStash` or `merge.autoStash` based on `pull.rebase`

Key technical changes in v2:
- Documentation reorganized before `pull.octopus` with clearer wording about rebase/merge differences
- Test suite expanded to verify all precedence rules and edge cases:
  - `pull.autoStash` overriding operation-specific configs
  - Command-line flags overriding configs
  - Interaction between all three configuration levels
- Implementation in `builtin/pull.c` now properly handles the three-level precedence chain

The patch maintains the same core behavior from v1 but with more comprehensive test coverage and improved documentation as requested in review. The test changes show particular attention to validating the override behavior between config levels and command-line flags. The documentation now better explains why autostash is more critical for rebase operations than merges.
