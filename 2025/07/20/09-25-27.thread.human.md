This thread centers on Aditya Garg's patch series adding IMAP-based sent message archiving to `git send-email`, allowing emails sent via SMTP to be automatically archived in an IMAP folder. The current version (v3) has settled on the "imap-sent-folder" naming while maintaining support for custom folder names, addressing earlier concerns about flexibility. Core functionality is stable, preserving Bcc headers in archive copies through adjusted header parsing in `imap-send.c`.

Junio Hamano and Aditya Garg have resolved the naming debate, confirming the terminology doesn't restrict folder choice. The thread had briefly considered implementing pure-IMAP transport (B2 mode) but concluded the archive-after-send approach (A2) provides sufficient value without duplicating `send-email`'s advanced features like dynamic CC management. Junio's latest email reinforces this by noting that manual alternatives (piping `format-patch` to `imap-send`) would lose these capabilities.

With all technical and naming concerns addressed, the series appears ready for merging in its current form, focusing solely on the archive-after-send use case. The implementation meets real-world needs while avoiding the complexity of reimplementing `send-email`'s full feature set for IMAP transport. No further changes are expected before the patches are picked up.
