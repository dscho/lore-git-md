Aditya Garg's `git send-email` IMAP archiving series has reached a technically complete state with the v4 patches, now supporting both SMTP+archive and pure-IMAP workflows. The core functionality allows archiving sent emails to IMAP folders either after SMTP transmission or as a standalone operation without SMTP. Key additions in v4 include fixing a dry-run bug and fully implementing the previously theoretical pure-IMAP mode, which preserves all of `send-email`'s formatting features while bypassing SMTP entirely.

The implementation introduces new configuration options (`sendemail.imapSentFolder` and `sendemail.useImapOnly`) and corresponding command-line flags. Error handling enforces that a folder must be specified in pure-IMAP mode, and dry-run operations properly avoid any IMAP interactions. The code cleanly separates the IMAP and SMTP paths while sharing common infrastructure.

Junio C Hamano has approved the "imap-sent-folder" naming that accommodates both workflows, and Eric Sunshine's documentation feedback has been incorporated. The only remaining discussion point - raised by the author themselves - is whether this functionality belongs in core Git rather than being implemented via external scripts. This philosophical question hasn't seen new input since v4 was posted, though the pure-IMAP implementation may strengthen the case for inclusion by demonstrating unique value beyond simple piping. With all technical issues resolved and no outstanding review feedback, the series appears ready for potential merging pending resolution of this final conceptual question.
