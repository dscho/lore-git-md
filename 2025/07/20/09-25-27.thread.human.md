Aditya Garg's patch series to add IMAP-based message archiving to `git send-email` has progressed through three versions, with the latest settling on "imap-sent-folder" terminology at Junio's suggestion while maintaining the ability to archive to any IMAP folder. The implementation handles the iCloud Mail workflow that motivated the feature, preserving Bcc headers in archive copies through existing `git imap-send` infrastructure.

In the latest discussion, Garg responds to Junio's proposal for two distinct IMAP modes (archive vs pure sending). He expresses reservations about implementing pure IMAP sending (B2 mode), noting that SMTP is more commonly used and that `git imap-send` has maintenance concerns. While accepting the "imap-sent-folder" name, Garg raises a practical concern that it might unintentionally suggest the feature only works with standard "Sent" folders when users may want to archive to custom locations like a "git" folder. He clarifies that pure IMAP sending can already be achieved by piping `format-patch` to `imap-send`, reinforcing that this patch's specific goal is archiving sent messages rather than replacing SMTP transport.

The series appears ready for merge with its current focus on the motivating archiving use case, having addressed naming concerns while preserving implementation flexibility. The open question about supporting custom folder names may require minor documentation clarification, but no technical changes appear necessary.
