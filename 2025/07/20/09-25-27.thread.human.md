Aditya Garg's IMAP sent-folder archiving feature for `git send-email` has progressed through three versions, settling on naming ("imap-sent-folder") and technical implementation that preserves messages via IMAP after SMTP transmission. While Junio Hamano confirmed the design and naming, Garg himself has recently raised doubts about whether the feature belongs in Git at all, despite its technical readiness.

A new issue has surfaced in the current implementation: emails are incorrectly archived during `--dry-run` operations when they should be skipped. Garg notes this bug also reveals an opportunity - fixing it would provide a cleaner path to implement a pure-IMAP mode (`--use-imap-only`) that was previously discussed as a potential enhancement. The core functionality remains sound, with the dry-run issue confined to `git-send-email.perl` and its interaction with `imap-send.c`.

The thread now has two parallel tracks: the immediate technical work (fixing dry-run behavior and potentially enabling future IMAP-only mode) and the broader question of whether this feature should be merged at all. While the technical path forward is clear (a v4 addressing the dry-run issue), the philosophical debate about the feature's necessity - initiated unexpectedly by its own author - remains unresolved. Junio has not yet responded to Garg's fundamental concerns, leaving the feature's future uncertain despite its technical maturity.
