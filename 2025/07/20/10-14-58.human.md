This is a licensing discussion in the context of the Rust xdiff optimization series. Phillip Wood responds to Johannes Schindelin's suggestion to add a license header that would allow code sharing with Gitoxide, raising two key concerns.

Phillip argues against Schindelin's proposal to dual-license the new xxhash Rust implementation. He acknowledges the historical precedent of libgit2's incompatible license but sees this as a cautionary tale rather than justification for changing Git's licensing approach. His first objection is that incremental dual-licensing of Rust components could effectively relicense Git over time as more C code is replaced. Second, he notes this would complicate future C-to-Rust conversions since xdiff code is currently LGPL-licensed.

The email positions this as a policy question requiring broader discussion, not something to resolve within the technical optimization series. Phillip suggests any relicensing effort should be a separate, explicit initiative with proper administrative support, rather than being introduced piecemeal through individual patches.

This exchange highlights an important open question in the Rust integration effort - how to handle licensing compatibility with the growing Rust ecosystem while maintaining Git's existing licensing structure. The discussion remains unresolved but surfaces key considerations for future architectural decisions.
