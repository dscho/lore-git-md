This is a feature patch adding IMAP folder archiving to `git send-email`. The change addresses a limitation where some email providers (notably iCloud Mail) don't save SMTP-sent messages to the Sent folder. The patch introduces a new `sendemail.imapfolder` config option and `--imap-folder` command-line flag that, when set, will use `git imap-send` to store copies of sent messages in the specified IMAP folder after successful SMTP delivery.

The implementation pipes the sent messages to `git imap-send` after SMTP transmission completes, preserving all headers including Bcc (which is specially handled since it's normally stripped). The IMAP-send functionality requires proper setup of IMAP credentials as documented in `git-imap-send`. The patch includes documentation updates and modifies the Perl and C code to support this new workflow.

Key technical details: The `imap-send.c` changes add special handling for messages prefixed with "From git-send-email" to properly parse their headers. The Perl changes collect messages for IMAP storage during SMTP sending, then batch them to `imap-send` after SMTP completes. The feature is opt-in and doesn't affect existing send-email behavior when not configured.

This appears to be a well-motivated change with clear documentation and thorough implementation. The patch handles edge cases like Bcc fields and maintains backward compatibility. The main consideration for reviewers would be whether this functionality belongs in send-email core or should remain an external script, and whether the IMAP integration could be made more robust against connection failures.
