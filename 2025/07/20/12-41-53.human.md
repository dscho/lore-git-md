This is a speculative proposal about adapting Git for AI-scale collaboration, raising both immediate integration ideas and long-term architectural considerations.

Skybuck Flying outlines the challenges Git faces when used by large numbers of AI agents working on machine learning projects: human-centric workflows that don't scale, binary asset handling, merge conflict resolution at high velocity, authentication bottlenecks, and the semantic gap in tracking AI-specific changes. The email suggests these problems will become more pressing as AI development intensifies.

For near-term solutions, the proposal focuses on deeper integration with existing MLOps tools (DVC, MLflow, LakeFS) to handle large files, experiment tracking, and smarter merges. It also suggests adding orchestration layers to manage concurrent AI contributions through batching, prioritization, and conflict mitigation - essentially creating traffic control systems for AI-generated commits.

Longer-term, the email floats more radical idea of an "AI-native" version control system with semantic conflict resolution, graph-based change tracking, and dynamic permissions tailored for autonomous agents. The tone is exploratory rather than prescriptive, inviting discussion about whether to evolve Git or build something new.

The proposal is ambitious in scope but grounded in recognizable pain points from ML development. While some suggestions like semantic versioning would require fundamental changes, the MLOps integration ideas seem practically actionable. The email serves primarily to start a conversation rather than present concrete patches, and the lack of specific implementation details makes it hard to assess feasibility of the more transformative suggestions.
