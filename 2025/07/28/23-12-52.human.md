This is a feature patch proposing a new submodule validation option, continuing a long-running thread about symlink handling in submodules. Vadim Zeitlin follows up on earlier discussion by submitting an implementation for a `submodule.<name>.validate` config option that would allow bypassing the path validation checks (notably the symlink check introduced in e8d0608944).

The patch adds documentation and modifies `submodule.c` to check the new config setting before validating paths. The author acknowledges some implementation uncertainties - particularly around using `the_repository` (noting the ongoing effort to remove it) and the lack of test coverage. The commit message explains the motivation is to support workflows where symlinks are intentionally used to share submodule checkouts across projects.

This appears to be a well-considered solution to the previously discussed issue, though the implementation questions around testing and repository access may need addressing. The patch arrives after months of discussion where the core tension between security validation versus workflow flexibility was already explored, with Junio Hamano previously suggesting the proposed config name was reasonable. The thread seems to be converging on this approach.
