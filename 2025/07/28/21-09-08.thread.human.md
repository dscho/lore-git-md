This thread reports a bug in Git's pattern matching behavior on case-insensitive filesystems (like Windows), where uppercase character ranges in `.gitignore` files (e.g., `[A-Z]`) fail to match filenames while lowercase ranges work correctly. The original reporter provided a reproduction case using Git 2.50.1 on Windows 10.

Junio C Hamano has now confirmed the issue is not Windows-specific and traced it to the `wildmatch.c` implementation. The problem occurs because Git's pattern matching code expects pattern characters to be lowercase when performing case-insensitive matching, but doesn't properly handle uppercase ranges. Junio proposed a fix that modifies the wildmatch machinery to downcase pattern characters when case folding is active, similar to how it already handles text characters. The change would affect all case-insensitive pattern matching contexts, not just `.gitignore` rules.

The proposed solution appears technically sound but is currently untested. If validated, this would resolve an inconsistency in Git's case-insensitive pattern matching that has likely existed for some time. The fix maintains the documented behavior that character classes (like `[[:alnum:]]`) should use lowercase names even when matching case-insensitively.
