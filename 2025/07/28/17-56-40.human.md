This is a follow-up discussion in the ongoing "repo" command implementation series, focusing on output format handling and quoting considerations.

Junio Hamano responds to Lucas Seiki Oshiro's question about whether to implement quoting for the new `git repo info` command's output format. The discussion references `git config --list`'s behavior as a similar case, with Junio noting that while config key names technically forbid newlines and null bytes, the lack of quoting in `git config --list` makes it unparseable when keys contain "=" characters unless using the `-z` option.

Junio makes the key point that historical design mistakes in other commands shouldn't be repeated here - if the non-null output format needs to remain parseable, proper quoting will likely be necessary. This suggests the new command may need to implement more robust output handling than `git config --list` currently provides.

The exchange shows the series is now focusing on final polish and design decisions around output formatting, building on the already-implemented core functionality. Junio's input carries significant weight as the Git maintainer, indicating this quoting question may be an important final design consideration before the series can be merged.
