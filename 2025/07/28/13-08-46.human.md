Refactoring patch in the remote ref renaming performance optimization series. This is the second of four patches that simplify reflog migration logic during ref storage format changes.

The patch eliminates an intermediate `reflog_migration_data` struct that was previously needed to pass the refname between callbacks. Now that the refname is passed directly through the callback interface (thanks to preparatory work in patch 1), this indirection can be removed. The patch also moves a reflog entry index counter from per-entry data to the main `migration_data` struct, maintaining the same ordering guarantees while simplifying the code.

The changes are mechanical but meaningful - they reduce the code by 26 lines while making the same functionality clearer. This continues the series' trend of cleaning up the reflog migration infrastructure before tackling the core performance issues in remote ref renaming operations. The changes are focused and well-explained, with a clear connection to the preparatory work done in the series.
