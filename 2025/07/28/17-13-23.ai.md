Feature patch for bash completion ref sorting, with technical feedback. This is a follow-up to Nelson Benítez León's patch introducing `GIT_COMPLETION_REFS_SORT_BY_FIELDNAME` for configurable ref sorting in completion. SZEDER Gábor provides detailed technical review:

1. **Implementation Limitations**: Notes the current approach only supports single sort keys despite `git for-each-ref` accepting multiple `--sort` options. The validation regex `^[a-zA-Z0-9%:=*(),_\ -]+$` remains unchanged.

2. **Performance Concern**: Flags the subshell overhead in `__git_get_sort_by_fieldname()` as problematic on Windows, suggesting adopting the `__git_decode()` pattern of variable output instead of command substitution.

3. **Sorting Side Effects**: Objects to the blanket `-o nosort` addition in `___git_complete()`, arguing it would disrupt sorting for other completion cases (subcommands, parse-options output, multi-source completions) where Bash's sorting is still needed.

The review focuses on implementation details rather than the feature's merit, which appears accepted in principle. Key technical points for future discussion include Windows performance optimization and the scope of sorting modifications. The thread context shows maintainer Junio Hamano previously emphasized test coverage requirements and commit message style, neither addressed in this response.
