This is a clarification about `git status` behavior regarding intent-to-add files, continuing the historical investigation thread.

Junio Hamano responds to D. Ben Knoble's observation that the TODO item about differentiating intent-to-add files in `git status` output appears unimplemented in current Git versions (2.48.1 and 2.50.0.rc0). While initially believing this was implemented long ago, Junio now provides a technical explanation of why the behavior is actually already present through different output indicators.

The key points are:
1. The short status format (`-s`) shows intent-to-add files with "A" in second column (working tree vs index) and blank in first column (index vs HEAD), while actually added files show "A" in first column.
2. The long status format clearly separates "Changes to be committed" (actually added) from "Changes not staged for commit" (intent-to-add).
3. Junio demonstrates this with concrete examples using files P (intent-to-add) and Q (actually added), showing how their status differs in both output formats.
4. The response suggests the original TODO item may have been addressing an older version's limitations that no longer relevant, as current output already sufficiently distinguishes these states.

This email provides authoritative clarification about the current behavior while leaving open the historical question of whether the TODO item was implemented and reverted or simply became obsolete as the status output evolved. The technical examples serve both to document current behavior and demonstrate how to verify such claims through practical testing.
