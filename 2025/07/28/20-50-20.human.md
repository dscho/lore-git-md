This is a platform compatibility note from Junio Hamano regarding Alexander Monakov's performance optimization patch for xdiff string hashing. The issue arises when compiling with clang instead of gcc, where clang treats the inline assembly directive in the REASSOC_FENCE macro as a language extension and raises a warning (treated as error in DEVELOPER mode).

The macro in question is part of Monakov's optimized djb2 hash implementation, which previously showed promising 1.5x speedup results. While the licensing concerns were resolved earlier in the thread, this reveals a practical portability issue that needs addressing before the patch can be merged. The problem is specific to clang's stricter handling of inline assembly syntax compared to gcc.

This appears to be a straightforward fix - either adjust the macro to be clang-compatible or find another way to achieve the same compiler optimization barrier. The core performance optimization approach remains sound, but this needs resolution to maintain cross-compiler compatibility, especially important for Git's broad platform support.
