This is a technical follow-up in the ongoing Rust integration discussion, specifically addressing platform compatibility concerns through GCC-based Rust compilation.

Pierre-Emmanuel Patry responds to Patrick Steinhardt's questions about timelines and responsibilities for GCC-based Rust compiler support (gccrs and rustc_codegen_gcc). The key points clarify that:

1. Full Rust 1.78 support via gccrs is realistically at least two years away, even with foundational work completed.

2. The rustc_codegen_gcc approach (using GCC as a backend for rustc) would primarily be a distributor responsibility rather than something the Git project needs to directly support. Distributors would need to configure the backend path via environment variables when building.

This provides important operational context for the earlier Gentoo maintainer concerns about platform support limitations. The response suggests that while GCC-based solutions could eventually address non-LLVM architectures, the timeline is long and the implementation burden falls on distribution maintainers rather than the Git project itself. This helps frame the practical constraints around Rust adoption for platforms like HPPA and Alpha that lack LLVM support.
