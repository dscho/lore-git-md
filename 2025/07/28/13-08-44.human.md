This is a performance-focused patch series that also fixes a bug in remote ref renaming. Patrick Steinhardt addresses two main problems with `git remote rename`: 

1. A bug where dangling symrefs weren't being properly renamed
2. A severe performance issue where renaming many refs had quadratic runtime (taking hours for 100k refs)

The series completely reworks the ref renaming logic to use just two transactions rather than one per ref, yielding dramatic speedups: 113x faster for the files backend (from ~4 minutes to ~2 seconds for 10k refs) and 7x faster for reftable. The reftable backend continues to outperform files, though the gap narrows after these optimizations.

The changes touch several areas of the codebase but focus primarily on ref handling in builtin/remote.c and the refs subsystem. The series builds on recent reflog migration fixes and appears well-benchmarked with clear before/after comparisons. This looks like a substantial improvement to a real pain point in large repositories.
