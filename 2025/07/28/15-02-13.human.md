This is a clarification about `git status` behavior regarding intent-to-add files, continuing a thread that started as a new contributor inquiry. Junio Hamano responds to D. Ben Knoble's observation that a TODO item about improving intent-to-add status output appears unimplemented in current Git versions.

Junio explains that while the TODO entry from 2011 suggested more verbose output, the current behavior already sufficiently distinguishes between intent-to-add ("A" in second column) and actually added files ("A" in first column). He demonstrates with examples showing how `git status -s` and the normal output format clearly indicate whether a file is merely intended for addition or actually staged.

The response suggests this historical TODO item may have been rendered obsolete by subsequent changes to how Git represents these states, though Junio notes he hasn't verified the mailing list history. The thread continues to serve as both a technical reference for status output and a case study in how Git's behavior evolves over time, with contributors helping verify historical claims against current implementation.
