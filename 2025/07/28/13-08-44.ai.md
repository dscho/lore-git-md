This is a performance-focused patch series that reworks how remote refs are renamed, addressing both a bug and significant performance issues. The series stems from prior discussion about dangling symrefs not being properly renamed during remote operations.

The key improvements are:
1. Fixes a bug where dangling symrefs weren't being renamed during `git remote rename`
2. Replaces the one-transaction-per-ref approach with a two-transaction model, dramatically improving performance (113x faster for files backend, 7x for reftable)
3. Includes benchmarks showing the files backend going from 238s to 2s for ref renaming, while reftable improves from 8.6s to 1.2s

The series touches several areas of the codebase but primarily modifies `builtin/remote.c` and `refs.c`. It builds on recent work around reflog migration fixes. The changes involve refactoring how reflog callbacks work (passing refnames explicitly) and optimizing the remote ref renaming logic to avoid quadratic behavior.

Notable technical details:
- Introduces changes to reflog entry callback signatures to pass refnames
- Modifies ref migration logic to be more straightforward
- Restructures remote ref renaming to use bulk operations
- Adds filtering to only process refs that actually need renaming

The series appears well-motivated with clear performance data and addresses both correctness and scalability issues in remote operations. The changes are fairly invasive across multiple files but seem focused on the stated goals.
