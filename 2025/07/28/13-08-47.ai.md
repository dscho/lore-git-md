Performance optimization patch addressing remote ref renaming issues, particularly severe performance problems with dangling symrefs. This is patch 3/4 in Patrick Steinhardt's series, building on Karthik Nayak's earlier preparatory refactoring work.

The patch fixes two key issues with remote renaming: (1) dangling symrefs weren't being properly renamed due to missing `RESOLVE_REF_NO_RECURSE` flag and broken ref iteration, and (2) the operation had severe performance problems (quadratic time for files backend) from using O(|refs| + |symrefs|*2) transactions. The solution restructures the operation into two transactions (delete then create) rather than per-ref transactions, while properly handling symrefs via `refs_for_each_rawref()`.

Performance improvements are dramatic: 113x faster for files backend (238s -> 2s for 10k refs) and 7x for reftable (8.6s -> 1.2s). The tradeoff is loss of precise progress reporting since refs are queued before counting. The patch includes extensive tests covering symref handling, nested remote cases, and reflog preservation. Changes focus on `builtin/remote.c` with new helper functions for refname rewriting and reflog migration. The approach avoids atomicity issues when nesting remotes while providing major speedups.
