Performance optimization for xdiff's hash function. This is the second patch in a series (following a refactoring of xdl_hash_record()), switching xdl_hash_record_verbatim from XOR-based to additive hashing and implementing an optimized loop inspired by Noah Goldstein's work on ELF symbol lookup in glibc.

The patch replaces the original djb2 hash variant with a more efficient implementation that processes two characters per iteration. It includes a REASSOC_FENCE macro to prevent compiler reordering of operations, which could otherwise break the carefully optimized dependency chain. The commit shows benchmark results comparing four versions: baseline master (A), with the refactor (B), with this optimization (C), and with Phillip Wood's xxhash patch (D). Version C shows a 1.5x speedup for xdl_hash_record_verbatim itself, with overall improvements in both cycles and instructions for the test case 'git log --oneline --shortstat v2.0.0..v2.5.0'.

Key technical details: The new implementation uses additive hashing (ha = ha * 33 + c) instead of XOR, processes two chars per iteration with careful operation ordering to minimize dependency chains, and handles edge cases (newlines, odd-length inputs) explicitly. The optimization focuses on xdiff/xutils.c's hash computation, a critical path for diff operations. The patch includes both the optimized version and a commented-out reference implementation for comparison.
