This thread explores performance improvements to Git's xdiff string hashing, building on Phillip Wood's earlier refactoring work. Alexander Monakov proposed two key optimizations: splitting the hash function into verbatim and whitespace-aware variants (8% speedup) and implementing an optimized djb2 hash (targeting 1.5x speedup), with changes focused on xdiff/xutils.{c,h}. While inspired by Glibc's approach, Alexander confirmed his implementation is original and GPLv2-compatible, which Junio Hamano has now verified.

Benchmark results show architecture-dependent performance gains - Alexander's Skylake tests show 7.6-12% improvements, while Phillip Wood's i5-8500 measurements show more modest 2-11% gains. Phillip also noted his xxhash implementation remains slightly faster. Technical discussion revealed nuances around compiler optimizations like REASSOC_FENCE, with Alexander explaining why standard C atomics wouldn't achieve the same effect.

In the latest development, Junio clarified two important points: he welcomes C-based optimizations (addressing Alexander's earlier question about Rust-focused work) and he accepts the licensing explanation. This removes potential blockers, allowing the discussion to focus on reconciling performance measurements across architectures and evaluating whether the maintenance cost of compiler-specific optimizations justifies the gains. The thread remains active with open questions about conditional optimization enablement and standardized benchmarking approaches.
