This thread focuses on Alexander Monakov's performance optimizations for xdiff's string hashing, building on Phillip Wood's earlier refactoring work. The proposed changes aim to speed up diff generation through two key improvements: splitting the hash function into specialized variants and implementing a faster djb2 hash algorithm inspired by (but independently written from) Glibc's approach. Initial benchmarks showed promising microbenchmark gains of 1.5x for the hash function itself.

The licensing concerns have been resolved - while inspired by Glibc, Monakov's implementation is original work adapted for Git's needs and confirmed GPLv2-compatible by Junio Hamano. A Clang compilation issue was also fixed by using more portable `__asm__` syntax.

However, Phillip Wood's follow-up testing revealed more modest real-world improvements - only 2-11% speedup in `git log` depending on measurement method and environment, with his existing xxhash implementation still 3% faster. This has shifted the discussion from technical approval to practical value assessment. Monakov has responded by clarifying his benchmark methodology and suggesting platform-specific conditional compilation as a compromise, while maintaining that the optimizations should still help on most modern CPUs.

The thread now centers on whether the demonstrated performance gains justify the maintenance cost, with open questions about cross-platform behavior and compiler compatibility beyond GCC/Clang. While the changes are technically sound, their practical impact may be marginal compared to existing alternatives.
