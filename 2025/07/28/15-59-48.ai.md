This is a refactoring patch that modifies the reflog callback interface to include the reference name as a parameter. The change standardizes the callback signature (`each_reflog_ent_fn`) across 17 files in the codebase, affecting both files and reftable backends. 

The patch originates from Patrick Steinhardt's performance optimization series for remote ref operations, where this change serves as preparatory work to simplify subsequent refactoring of reference migration logic. Justin Tobler reviews the change positively, noting it will eliminate awkward bookkeeping in cases where callers need to track reference names during nested reflog iterations.

Key technical details: The modification adds a `const char *refname` parameter to the callback function signature and updates all implementations to pass through this value. The changes are mechanical but widespread, touching core reflog handling in `refs.[ch]`, both backend implementations, and several builtin commands that process reflogs (fsck, gc, stash, etc.). The patch maintains all existing behavior while making the interface more flexible for future use cases.

This change is low-risk as it doesn't alter functionality - it provides additional context to callback handlers. The thorough updates across all call sites suggest careful attention to consistency. As part of an already-approved performance optimization series, this foundational change helps enable more significant refactoring in subsequent patches.
