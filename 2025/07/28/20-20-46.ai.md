This is a refactoring patch that fixes type safety issues in the ref-cache iterator code. It's part of Karthik Nayak's follow-up cleanup series after their `--start-after` feature was merged.

The patch addresses a type mismatch introduced in commit 090eb5336c where an `int` was used to store string lengths that should have been `size_t`. The original code performed unsafe truncation of `strlen` results and used the wrong type for `strncmp` operations. The fix changes the `len` variable from `int` to `size_t` and removes the problematic cast, while keeping the same logic for comparing refnames during iteration.

This is a straightforward correctness improvement that follows up on earlier refactoring work in the ref-cache subsystem. The change is small (3-line diff) but important for handling large refnames correctly. The patch maintains the existing behavior while making it type-safe, and is part of the final polish for the `--start-after` feature series.
