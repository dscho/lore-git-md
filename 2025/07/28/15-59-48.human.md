Refactoring patch that modifies the reflog callback interface. This is the first preparatory patch in a performance optimization series that was already approved for merging.

The patch standardizes the `each_reflog_ent_fn` callback signature across 17 files to include the reference name as a parameter. Previously, callers had to track the refname separately when needed, which could be awkward in nested iteration scenarios. Patrick Steinhardt's original commit explains this will simplify upcoming ref migration logic changes.

Justin Tobler reviews the changes and agrees the modification is reasonable, noting it will clean up some bookkeeping code. The patch touches core refs handling code in both files and reftable backends, plus various commands that use reflogs (fsck, gc, stash, etc.). While mechanical in nature, this foundational change enables more significant optimizations in later patches of the series.

The changes are straightforward - adding the refname parameter to callback declarations and propagating it through all implementations. The series has already been vetted by the maintainer, with Junio Hamano noting the significant performance improvements it enables (reducing some operations from hours to seconds). This particular patch doesn't change behavior, just prepares the infrastructure for more impactful optimizations to come.
