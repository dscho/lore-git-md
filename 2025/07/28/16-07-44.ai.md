This is a preparatory refactoring patch in a performance optimization series, specifically standardizing the reflog callback interface. The patch modifies the `each_reflog_ent_fn` callback signature to include the refname as an explicit parameter rather than requiring callers to pass it through callback data. 

The changeset updates 17 files to use the new interface, eliminating awkward workarounds where callers were packing refnames into callback data structures. Key examples shown include `fsck_handle_reflog_ent()` which previously extracted the refname from cb_data, and `read_ref_at_ent()` which no longer needs to store refname in its callback struct. The modifications are mechanical but enable cleaner implementations for subsequent optimizations in the series.

The patch has already been reviewed positively by Justin Tobler for eliminating bookkeeping complexity in nested iteration cases. Junio C Hamano's response confirms the approach makes sense, particularly noting how it simplifies call sites that previously had to pass refnames through callback data. This change serves as foundational work for the later performance improvements in the series while maintaining all existing behavior.
