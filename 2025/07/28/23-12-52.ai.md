This is a feature patch proposing a new submodule validation configuration option, continuing the long-running thread about symlink validation in submodule paths. Vadim Zeitlin submits an implementation of the `submodule.<name>.validate` option discussed earlier, defaulting to true but allowing disabling path validation (specifically the symlink check) when needed.

The patch adds documentation for the new config option in `submodule.adoc` and modifies `submodule.c` to check the setting before performing path validation. The implementation uses `submodule_from_path()` with `the_repository` (acknowledging this may not be ideal given ongoing efforts to remove global repository state) and includes basic error handling via `BUG()` if submodule info can't be found.

Key technical details:
- New config key: `submodule.<name>.validate` (boolean, default true)
- When false, skips the symlink validation check from e8d0608944
- Affects `validate_submodule_path()` in submodule.c
- No test included yet (author couldn't find existing symlink test to modify)

The author notes two unresolved implementation questions:
1. Whether using `the_repository` is acceptable or if there's a better way to access config
2. Lack of test coverage (couldn't find existing symlink validation test to extend)

This moves the discussion from theoretical design to concrete implementation while maintaining the thread's core tension between security and workflow flexibility. The patch appears to follow the naming consensus from earlier discussion (`validate` rather than more specific `allowSymlinks`), though the thread remains open for final review. The implementation is minimal but functional, with clear areas marked for potential improvement.
