This is part 3 of a 4-part series expanding `-h` and `--help-all` support across Git commands. The patch focuses on enabling `--help-all` to work outside repository contexts by modifying help handling in several key areas.

The changes are straightforward and well-contained:
1. Updates `merge-recursive.c` to recognize `--help-all` alongside `-h`
2. Modifies `git.c`'s `run_builtin()` to treat `--help-all` the same as `-h` for repository setup purposes
3. Extends `parse-options.c`'s usage helper to handle `--help-all` with full help output
4. Adds corresponding test coverage in `t1517-outside-repo.sh`
5. Updates `usage.c` to recognize `--help-all`

Junio C Hamano reviews the changes positively, calling them "obvious and straight-forward" and approving the approach of treating `--help-all` consistently with `-h`. He specifically endorses the decision to special-case both help flags early in execution to avoid unnecessary repository setup.

The review notes some confusion about the author's original considerations regarding `show_usage_with_options_if_asked` and parse-options API interactions, but concludes these changes are the right approach regardless. The patch maintains existing special cases for commands like `merge-recursive` while expanding help functionality.

This patch appears uncontroversial and technically sound, building on the series' goal of unified help handling while avoiding deeper refactoring of legacy code like `merge-recursive`.
