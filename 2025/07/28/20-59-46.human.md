This is a discussion about refname resolution behavior in `git reflog` subcommands, specifically focusing on the plumbing/porcelain boundary and consistency between commands.

Junio Hamano responds to Karthik Nayak's technical explanation of how `git reflog drop` currently resolves shorthand names using `repo_dwim_log()` with `ref_rev_parse_rules`. While acknowledging the implementation details, Hamano maintains his position that this DWIM (Do What I Mean) behavior feels like a bug for what he considers a plumbing command. 

He suggests two possible paths forward: either make all reflog subcommands use the same DWIM resolution (which would make `write` more lenient) or make them all require full refnames (which would make `drop` stricter). Hamano leans toward the latter approach for consistency and plumbing purity, but notes that either solution would be acceptable as long as the behavior is documented and users can always use full refnames to avoid ambiguity.

The exchange highlights an ongoing tension between user convenience (shorthand resolution) and command purity (explicit ref specifications) in Git's design philosophy, particularly for commands that sit on the plumbing/porcelain boundary. The discussion remains open-ended, but Hamano's position as maintainer carries significant weight in suggesting the direction this might take.
