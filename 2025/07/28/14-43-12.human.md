This is a refactoring patch in Patrick Steinhardt's ongoing reflog migration infrastructure series, specifically addressing the `REF_HAVE_OLD` flag behavior during log-only updates. The patch responds to Jeff King's observation about inconsistent handling of `REF_HAVE_OLD` between `split_head_update()` and `split_symref_update()`.

The key change is to stop unsetting `REF_HAVE_OLD` for log-only updates, preserving it as a signal that the caller provided an old object ID. This prepares for a subsequent commit that will use this flag to verify provided OIDs when writing reflog entries. The patch maintains the same safety checks by adding an explicit `REF_LOG_ONLY` condition to skip old OID verification when appropriate.

Patrick argues that the inconsistency Jeff found actually points to a deeper issue - `split_head_update()` should resolve the old OID when `REF_HAVE_OLD` isn't set, rather than the other way around. This maintains consistency with the refactoring approach while supporting the upcoming functionality that relies on the flag being preserved.
