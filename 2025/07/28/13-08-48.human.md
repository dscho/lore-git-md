Performance optimization patch completing a series addressing remote ref renaming issues. This final patch introduces `refs_for_each_rawref_in()` to avoid scanning all refs when only those under a specific prefix (like `refs/remotes/oldname/`) need processing during remote renames. 

The change replaces the previous approach that filtered unwanted refs in the callback with direct prefix-based iteration. Benchmarks show significant speedups: 1.35x faster for the files backend (42.6ms -> 31.7ms) and 2.07x for reftable (18.2ms -> 8.8ms) when renaming a remote among 100k unrelated refs. The improvement is more pronounced for reftable since it was already faster than files.

This builds on earlier preparatory work in the series that standardized reflog callbacks and simplified migration logic. The patch touches core refs infrastructure (`refs.c`) while keeping the remote-specific changes in `builtin/remote.c`. It maintains the careful, measurable approach seen throughout the series, with clear performance data justifying the change.
