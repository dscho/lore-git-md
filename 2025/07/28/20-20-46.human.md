This is a refactoring patch that fixes type safety in the ref-cache iterator code. It's part of Karthik Nayak's follow-up cleanup series after their `--start-after` feature was merged.

The patch addresses a type mismatch introduced in commit 090eb5336c where an `int` was used to store string lengths that should have been `size_t`. The current implementation could potentially cause problems with very long refnames by truncating their lengths to negative numbers when converted from `size_t` to `int`. The fix is straightforward - changing the `len` variable's type to `size_t` and removing the problematic cast.

This appears to be a well-justified change that properly aligns with C string handling conventions. The patch is small and focused, with a clear explanation of both the problem and solution. Since it's part of a post-merge cleanup series, it represents final polish rather than introducing new functionality.
