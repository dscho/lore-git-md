Refactoring patch simplifying the blame internals by removing an unused parameter.

This patch removes the `detailed` parameter from `get_commit_info()` in `builtin/blame.c`, which was previously used to control whether to fetch just author info or full commit metadata. The parameter was effectively unused as all callers passed `1` (true), making the conditional early return dead code. The change simplifies the function signature and removes 11 lines while adding 4, with all call sites updated to use the simpler interface.

The modification touches several blame output functions that display commit metadata (`emit_one_suspect_detail`, `emit_other`, `find_alignment`), but doesn't change their behavior - they continue to show full commit information as before. The change appears to be a straightforward cleanup of an unused feature rather than a behavior change.

The patch is small and focused, with no apparent impact on functionality. It follows the pattern of removing dead code paths that were likely vestigial from an earlier implementation. No test changes are included since this is an internal refactoring that shouldn't affect observable behavior. The commit message could be more detailed about why the parameter became unused over time, but the change itself looks correct and low-risk.
