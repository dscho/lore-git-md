Performance optimization completing a series addressing ref renaming inefficiencies. This final patch introduces `refs_for_each_rawref_in()` to avoid scanning all refs during remote rename operations, instead only processing refs under the specific "refs/remotes/$OLDNAME/" prefix. The change builds on previous preparatory work that standardized reflog callbacks and simplified migration logic.

Key technical details: The patch modifies `builtin/remote.c` to use the new prefix-aware iteration when renaming remote refs, removing the need for manual prefix checking in the callback. It adds the new API to `refs.[ch]` with the same signature as the existing rawref iterator but with a prefix parameter. Benchmarks show significant speedups: 1.35x faster for files backend (42.6ms->31.7ms) and 2.07x for reftable (18.2ms->8.8ms) when renaming a remote among 100k unrelated refs.
