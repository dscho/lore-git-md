Bugfix targeting Git's wildmatch pattern matching behavior under case-insensitive conditions. This is a response to the reported issue where uppercase character ranges in `.gitignore` patterns fail to match filenames when `core.ignorecase` is true.

Junio C Hamano confirms the issue is not Windows-specific and traces it to the wildmatch machinery's handling of case folding in character classes. The code currently expects pattern characters to be lowercase to match their uppercase counterparts, which appears to be a bug. The proposed fix modifies `wildmatch.c` to downcase pattern characters when `WM_CASEFOLD` is active, similar to how text characters are already downcased.

The patch adds case conversion for pattern characters in three contexts: regular character matches, escaped characters, and character ranges. It also includes a clarifying comment about the lowercase requirement for character classes like `[[:alnum:]]` even under case-insensitive matching. The change is focused on the `dowild()` function where the pattern matching logic resides.

This appears to be a straightforward fix for an inconsistency in case-insensitive pattern matching, though Junio notes the patch is "totally untested". The solution aligns with the existing case-folding behavior for text characters and maintains the documented expectation that character classes should use lowercase names. The fix would affect all case-insensitive pattern matching contexts, not just `.gitignore` rules.
