Performance optimization refactoring for xdiff string hashing. This is the first of two patches in a series, building on Phillip Wood's prior work to optimize Git's diff generation performance.

The patch refactors `xdl_hash_record()` by splitting it into two variants: `xdl_hash_record_verbatim` (the fast path) and `xdl_hash_record_with_whitespace` (handling whitespace flags). The key change moves the whitespace flag check outside the hashing loop via an inline wrapper, allowing the compiler to optimize the common case better. Phillip Wood's benchmarks show an 8% speedup in `git log` operations with this change.

The changes are focused in xdiff/xutils.{c,h}, modifying 17 lines total. This appears to be a well-constructed optimization that follows established patterns in the codebase. The patch includes clear benchmarking data showing the performance improvement, and builds on prior reviewed work in this area. The second patch in the series will introduce further optimizations to the hashing algorithm itself.
