Feature patch for bash completion ref sorting, with review feedback. This is a follow-up to Nelson Benítez León's patch adding configurable ref sorting via `GIT_COMPLETION_REFS_SORT_BY_FIELDNAME`. SZEDER Gábor provides detailed technical review, noting the original motivation (sorting by committer date for recently worked-on branches) is reasonable but should be in the commit message.

Key points from the review:
1. The current implementation only allows one sort key, while `for-each-ref` supports multiple `--sort` options
2. The helper function's use of command substitution is inefficient on Windows and should use variable output instead
3. Disabling bash's default sorting entirely (via `-o nosort`) breaks other completion cases that still need sorting
4. The implementation otherwise appears sound, with proper input validation

The review maintains the maintainer's earlier position that tests are required, while providing concrete technical guidance on improving the implementation. The discussion remains focused on technical merits, with the reviewer clearly explaining each concern and suggesting specific alternatives.
