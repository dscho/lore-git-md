This thread discusses a straightforward cleanup in Git's blame subsystem, removing an unused parameter from the `get_commit_info()` function in `builtin/blame.c`. The parameter, called `detailed`, was originally added in 2006 to enable early termination of commit parsing, but testing showed negligible performance benefit, and all callers were passing `1` (true) for this parameter anyway, making the early termination path effectively dead code.

Han Young proposed the patch to remove this unused parameter and associated conditional logic while maintaining identical functionality. Patrick Steinhardt, a core contributor with deep knowledge of Git's internals, confirmed the technical correctness of the change, noting the parameter's history and lack of practical use. The thread shows clear consensus that this is a harmless cleanup with no behavior change, and there were no objections or additional discussion points raised. This appears ready to be picked up by the maintainer for inclusion.
