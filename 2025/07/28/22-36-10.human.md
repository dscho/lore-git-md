Bugfix for case-insensitive pattern matching in wildmatch. Junio C Hamano confirms the reported issue with uppercase character ranges in `.gitignore` files affects more than just Windows - it's a general wildmatch problem when `core.ignorecase` is enabled. The root cause appears to be that the wildmatch code only handles lowercase pattern characters matching uppercase filenames, not the reverse case.

The proposed fix modifies `wildmatch.c` to downcase pattern characters in character classes when case folding is active, similar to how filename characters are already downcased. The patch adds case conversion for pattern characters in three key places: basic character matching, escaped characters, and range expressions. A comment also clarifies that character classes like `[[:alnum:]]` must still be spelled in lowercase.

This looks like a straightforward fix for an obvious inconsistency in case handling. The patch is small and focused, though untested as noted. The change would make pattern matching behavior more consistent between uppercase and lowercase character ranges when `core.ignorecase` is true. Since this affects core pattern matching, it could have wide-ranging implications beyond just `.gitignore` files.
