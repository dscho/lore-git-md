Minor technical correction in Rust/C FFI discussion. Collin Funk points out that while Ezekiel Newren correctly noted Rust's `char` is 32-bit versus C's 8-bit, the C standard actually leaves `char` signedness implementation-defined. He demonstrates with a test program showing `char` is signed on x86_64 Linux but unsigned on aarch64 Linux, emphasizing portable code must handle both cases.

This is a small but important clarification in the ongoing discussion about type compatibility between C and Rust in the xdiff subsystem. While it doesn't change the core technical direction (using `u8` for byte strings remains correct), it reinforces the need for careful attention to platform-specific behaviors when designing cross-language interfaces. The note comes from an experienced contributor (Collin has previously worked on portability issues in Git) and serves as a useful reminder in this complex FFI work.
