This is a technical clarification in the ongoing Rust integration discussion, specifically addressing platform compatibility concerns through GCC-based Rust compilation.

Pierre-Emmanuel Patry responds to Patrick Steinhardt's questions about timelines and responsibilities for GCC-based Rust compiler support (gccrs and rustc_codegen_gcc). The email confirms that supporting Rust 1.78 (needed for Windows targets) would take at least another year after initial libcore support is achieved. 

Key technical clarification is that using rustc_codegen_gcc would primarily be a distributor responsibility, requiring them to configure rustc with the path to the alternative backend via environment variable. This suggests Git itself wouldn't need special handling beyond standard Rust compatibility, though it does imply downstream packaging complexity.

The response helps address Gentoo maintainers' earlier concerns about non-LLVM platform support by outlining a practical path forward, though with clear multi-year timelines for full functionality. This continues the thread's theme of balancing Rust performance benefits against platform compatibility constraints.
