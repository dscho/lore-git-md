Interface refinement discussion for the `--skip-until` pagination implementation.

This email continues the thread's examination of the iterator interface design for the recently merged `--skip-until` feature in `git for-each-ref`. Patrick Steinhardt expresses concerns about the current split between prefix-setting in `refs_ref_iterator_begin()` and optional prefix-updating in `ref_iterator_seek()`, calling the interface confusing and potentially error-prone due to inconsistent state management.

The key technical points under discussion are:
- Current behavior where `refs_ref_iterator_begin()` sets the initial prefix while `ref_iterator_seek()` can optionally update it via flags
- Potential inconsistency in how internal state is handled between these operations
- Patrick's concern that this design invites mistakes by sometimes acting like a new iterator (when updating prefix) while retaining other state
- Karthik's defense of the current naming scheme but openness to alternatives
- The alternative approach would unify the operations by extending `refs_ref_iterator_begin()` to handle seeks

This follows earlier interface refinements that replaced a `set_prefix` boolean with a flags field in `ref_iterator_seek()`. The discussion now focuses on whether to maintain the separation between prefix-setting and seeking operations or consolidate them for clearer semantics. The files backend currently requires split logic between these operations, while packed and reftable backends need simpler adjustments.
