This is a clarification about the `git log --diff-filter` behavior that was reported as a bug. K Jayatheerth explains that the exclusion filter `d` only works when Git is actually computing diffs - it has no effect with simple output formats like `--format="%H"` that don't generate diffs. The behavior isn't a bug but rather a consequence of when diff filtering is applied in the output pipeline.

The email provides workarounds for the original reporter's use case of filtering commit hashes while excluding deletions, suggesting either combining `--name-only` with `grep` or using `--stat` output. The explanation makes it clear this is expected behavior, not a documentation inaccuracy as initially suspected in the bug report.
