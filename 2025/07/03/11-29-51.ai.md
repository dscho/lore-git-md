This is a feature patch introducing a new email header for Git-generated emails. The patch adds an X-Change-ID header to emails produced by `format-patch` and `send-email` when commits contain a "change-id" line in their message. This is designed to help patch management systems like Patchwork and Sourcehut track changes through their review lifecycle.

The implementation modifies `pretty.c` to scan commit messages for "change-id" lines and convert them into email headers when the mail format is being used. The author notes this is the first step toward preserving change IDs through the entire email-based workflow from sending to applying patches.

A notable limitation mentioned is the lack of testing strategy, since Git itself doesn't generate change IDs - they're typically added by third-party tools. The patch is marked as v2 but carries no changes from v1, suggesting the author is waiting for feedback on the core approach before addressing testing concerns.

Key technical details for future reference:
- Adds parsing of "change-id" lines in commit messages
- Only activates for mail formats (checked via `cmit_fmt_is_mail`)
- Formats output as "X-Change-ID: <value>" header
- Modifies the `pp_header` function in pretty.c
- No test coverage included yet

The change appears straightforward but may need discussion around:
- The "X-" prefix convention (though common for email headers)
- Whether this belongs in core Git vs. being handled by external tools
- How to properly test the functionality given Git's current workflow
