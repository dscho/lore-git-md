This is a documentation patch proposing to clarify an existing but undocumented behavior in `git init`. 

Boris Kolpackov points out that passing an empty path to `--template` (like `--template=`) has silently skipped template directory copying since at least Git 2.1, but this behavior isn't mentioned in the documentation. The code shows this is handled by checking for empty strings in the template directory logic.

The patch suggests adding a sentence to the TEMPLATE DIRECTORY section of git-init(1) to explicitly document this behavior. The motivation comes from tooling use cases - package managers and other automation that creates repositories just for fetching data don't need template files like hooks, and skipping them saves time and space.

This appears to be a straightforward documentation improvement for a long-standing behavior. The change is small and focused, just adding clarity about an existing feature rather than introducing new functionality. The code analysis shows the empty path handling is intentional and stable across versions.
