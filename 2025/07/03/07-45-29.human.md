This is a feature patch adding email header support for change tracking systems. Drew DeVault proposes adding an X-Change-ID header to emails generated by `git format-patch` and `git send-email`, which would help tools like Patchwork and Sourcehut track changes through the review process.

The patch modifies the pretty-printing code to detect a "change-id" line in commit messages and convert it to an email header when formatting patches. The implementation is minimal, touching just 7 lines in pretty.c to add the new header while preserving existing functionality.

The author notes this is just the first step - they've deliberately avoided implementing the complementary `git am` side that would preserve these IDs when applying patches, citing uncertainty about how this might interact with tools like Jujutsu that may have their own change ID generation schemes. The patch stands on its current merits for the outgoing side alone, while inviting discussion about the more complex receiving side.

The change appears well-contained and thoughtfully implemented, with clear motivation for the email header addition. The author demonstrates awareness of potential downstream implications, making this a solid starting point for discussion about change tracking integration.
