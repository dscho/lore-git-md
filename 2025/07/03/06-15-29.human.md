This is a cover letter for Patrick Steinhardt's v2 patch series proposing to make reftable the default ref storage backend in Git 3.0. The series builds on previous discussion and incorporates feedback from v1, while maintaining the core goal of transitioning from files-based to reftable storage.

The cover letter explains the two-patch approach: first documenting the breaking change for Git 3.0, and second enabling reftable by default for users with `feature.experimental` set. This allows wider testing before the full transition. Key changes in v2 include improved breaking change documentation, introduction of a `REF_STORAGE_FORMAT_DEFAULT` macro, and adding ref format info to `git version --build-options`.

The implementation appears well-considered, with clear attention to ecosystem readiness (noting dependencies on Gitoxide/libgit2/JGit support) and platform-specific concerns (Windows/macOS filesystem limitations). The test coverage in t0001-init.sh looks thorough, and the use of experimental flag rollout shows good practice for a major change. The series seems ready for review, though coordination with other Git implementations remains an open question.
