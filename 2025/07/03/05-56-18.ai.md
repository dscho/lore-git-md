This is a follow-up discussion on the recently merged `--skip-until` pagination feature for `git for-each-ref`, focusing on race condition implications.

Junio C Hamano responds to Patrick Steinhardt's earlier point about numeric offsets being invalidated by concurrent writes, noting that the name-based approach has similar race vulnerabilities. The key observation is that while the current implementation avoids numeric offset races by using ref names as markers, it's not completely race-proof - if the marker ref is deleted before being used in `--skip-until`, or if new refs are inserted before it in the sort order, the pagination could still break.

This exchange highlights an inherent limitation in both approaches (numeric and name-based) when dealing with concurrent repository modifications. The discussion doesn't propose any code changes but serves to document the tradeoffs in the design - the name-based approach was chosen for its O(log N) performance characteristics despite sharing some race condition vulnerabilities with numeric offsets. The thread continues to refine the implementation's documentation and edge case handling while maintaining the core architectural decisions.
