This is a feature patch adding SHA-256 support to git-gui, part of the ongoing effort to support alternative hash algorithms in Git. Takashi Iwai updates several Tcl scripts in git-gui to handle variable-length object IDs rather than hardcoding SHA-1's 40-character length. The changes affect core functionality like commit handling, repository cloning, blame display, and branch operations.

The patch introduces a global `hashlength` variable set by querying `git rev-parse --show-object-format`, then updates regex patterns and string operations throughout the GUI to use this dynamic length. The v2 revision fixes an oversight in the commit tree handling code that wasn't adjusted in the first version.

The changes appear thorough, touching all the obvious places where SHA-1 lengths were previously hardcoded. The implementation uses Tcl's `string map` to dynamically construct regex patterns with the correct length, which seems like a clean approach. This is a foundational change needed for git-gui to work with SHA-256 repositories, though it doesn't yet appear to expose any new SHA-256-specific functionality to users.
