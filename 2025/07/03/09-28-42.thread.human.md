Patrick Steinhardt's series improving Git's Meson build system has progressed with most patches being technically sound, but hit a snag with the final patch introducing test parallelization. The first seven patches clean up various aspects of the build system, from Python version detection to subproject wrapper updates, with Ramsay Jones having already acknowledged the libexecdir regression fix.

The issue arose when Junio Hamano reported that Meson was rejecting the `--slice` argument in CI with an error about non-positive integers. Jeff King (peff) has now identified the root cause: GitHub Actions uses 0-based numbering for its matrix jobs while Meson expects 1-based indices. Peff's proposed solution is straightforward - adjust the matrix configuration in `.github/workflows/main.yml` to use `[1, 2, 3...10]` instead of `[0, 1, 2...9]`.

While this should resolve the immediate issue for GitHub Actions, the GitLab CI configuration may need similar adjustments. The series remains nearly complete, with just this CI-specific parallelization detail needing resolution before the full set can be merged. The first seven patches could potentially be picked up independently if the CI fix requires more extensive rework.
