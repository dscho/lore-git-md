This is the first patch in Patrick Steinhardt's v2 series proposing to make reftable the default ref storage format in Git 3.0. The patch focuses on documenting the planned change in BreakingChanges.adoc while implementing the necessary plumbing to make it work.

The documentation section provides a thorough list of advantages reftable has over the current files backend, including better handling of case-insensitive filesystems, Unicode normalization, atomic writes, and significant performance improvements for operations involving many references. The change is framed as addressing longstanding limitations that can't be fixed in the files backend while maintaining backward compatibility.

The implementation side adds a new REF_STORAGE_FORMAT_DEFAULT macro that will switch to reftable when WITH_BREAKING_CHANGES is set (for Git 3.0), while keeping files as the default for now. It also adds version output support via `git version --build-options` and corresponding test coverage.

The patch appears well-considered, with clear technical rationale and attention to ecosystem readiness (noting the need for JGit/libgit2/Gitoxide support). This is part of a carefully planned transition that follows the SHA-256 migration pattern, with experimental opt-in available now via config before the eventual default switch.
