This is a feature patch adding email header support for change tracking systems. Drew DeVault proposes adding an X-Change-ID header to emails generated by Git's mail formatting (like `format-patch` and `send-email`). The change would help tools like Patchwork and Sourcehut better track changes through review cycles by preserving unique change identifiers.

The patch modifies `pretty.c` to scan commit messages for "change-id" lines and include them as X-Change-ID headers in the generated emails. The author notes this is a first step toward preserving these IDs through the full email review workflow (from sending to applying patches), though the current implementation only handles the formatting side.

The v2 submission notes uncertainty about testing, as Git itself doesn't generate change IDs - they're typically added by third-party tools. The implementation looks straightforward, adding about 6 lines with a simple string prefix check and header formatting. While the change is small, it could be useful infrastructure for projects using change-tracking systems that rely on these identifiers.
