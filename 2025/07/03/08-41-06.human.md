This is a follow-up in the X-Change-ID header support thread, providing feedback from a Jujutsu developer about the proposed git-am integration. Remo Senekowitsch confirms that Jujutsu would welcome Git preserving change-id headers when applying patches via git-am, since Jujutsu's change-id generation is random rather than deterministic. They note this behavior can already be tested by round-tripping commits between Git and Jujutsu repositories.

The email provides concrete steps to verify Jujutsu's handling of imported change-ids, suggesting this aspect of the proposal is technically sound from Jujutsu's perspective. This removes a potential concern raised in the original patch about downstream tool compatibility, opening the door for implementing the git-am side of the feature. The response is positive and constructive, coming from a maintainer of one of the affected tools.
