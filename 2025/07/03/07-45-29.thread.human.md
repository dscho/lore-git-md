This thread discusses adding X-Change-ID header support to Git's email-based workflows, specifically targeting interoperability with change tracking systems like Patchwork and Sourcehut. The initial patch from the author modifies Git's pretty-printing code to include change IDs from commit messages as email headers when using format-patch and send-email, while deliberately avoiding git-am integration to prevent conflicts with downstream tools.

A key development came from Remo Senekowitsch, a Jujutsu developer, who confirmed there would be no conflict with Jujutsu's change-id handling. Jujutsu generates its own stable change IDs independently of Git's headers, and testing shows it can already import change IDs from Git-managed repositories. This removes a major technical concern about expanding the feature to include git-am integration.

The thread now has positive feedback from at least one major downstream tool maintainer, though broader ecosystem impacts would still need consideration. The small, focused patch (7 lines changed) remains uncontested technically, and the author appears to be waiting for maintainer feedback before potentially expanding the scope to include git-am support. The testing methodology provided offers a clear verification path for any future implementation.
