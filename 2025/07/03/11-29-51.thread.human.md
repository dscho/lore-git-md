This thread explores how to reliably preserve commit metadata (like change IDs and signatures) when patches are emailed. The original proposal by Drew DeVault suggested adding X-Change-ID headers to patch emails, but the discussion has expanded to consider broader solutions. Junio Hamano, the Git maintainer, strongly advocates for a more generic approach that would preserve all commit headers, not just change IDs.

After six weeks of inactivity, Junio nudged Drew to move the discussion forward. Drew has now responded, acknowledging he mistakenly thought he had already prepared an updated version incorporating Junio's feedback. He commits to working on a v3 patch series "in the foreseeable future" that will implement the generic header preservation approach.

The technical debate remains open between three approaches: commit message trailers, specific mail headers, or Junio's generic solution. Key unresolved questions include how to handle signatures, whether to support different workflow modes, and how email clients might interact with the proposed changes. Several participants have contributed use cases and technical analysis, with the Jujutsu version control system's needs being a notable example.

While this email doesn't advance the technical discussion, it signals that the thread will likely see movement soon with Drew's promised v3 series. The maintainer's clear preference for the generic approach suggests this is the direction the solution will take, though implementation details remain to be worked out.
