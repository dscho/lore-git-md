This thread explores how to reliably track change IDs through Git's email workflow. The original proposal suggested adding X-Change-ID mail headers when commits contain change-id trailers, but the discussion has evolved significantly. Junio Hamano has firmly rejected using mail headers specifically for change-IDs, arguing commit trailers are the proper place for them. However, he's now proposing a more generic solution - a `--extra-headers` option for `git format-patch` that would preserve arbitrary commit headers during email transfer by encoding them as X-git-extra-commit-header mail headers.

The debate has shifted from change-ID-specific solutions to discussing a framework for header preservation in general. While this would technically work for change IDs, Junio emphasizes it's not an endorsement of that approach - he's providing a mechanism that could handle cases where headers are used, whether wisely or not. The proposal would require coordinated changes to both format-patch and mailinfo, with encoding schemes still to be specified.

Several open questions remain: How would this interact with Git's existing commit_extra_header mechanism? Would it satisfy the original use case that prompted the thread? And fundamentally, is the complexity of a generic solution justified when commit trailers might suffice? Participants including Drew DeVault, Jeff King, and Aditya Garg have contributed testing data and perspectives, but we're still waiting to hear from the original patch submitter about this new direction.
