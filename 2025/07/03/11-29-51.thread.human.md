This thread explores how to best track change IDs and preserve commit metadata in Git's email workflow. The discussion began with a proposal to add X-Change-ID headers to patch emails, but has evolved into a broader conversation about Git's handling of commit signatures and metadata during format-patch/am operations.

Junio Hamano has emerged as the key voice advocating for a general solution rather than change-ID-specific code. He's now proposed two complementary approaches: preserving arbitrary commit headers via a new `--extra-headers` flag, and potentially adding an exact-reproduction mode that would include full commit metadata (including signatures) in patch emails. His latest email explains that signatures are currently omitted from format-patch output by design, as the workflow assumed human-readable patches rather than bit-for-bit reproduction - though he acknowledges this assumption may need updating.

Drew DeVault strongly supports the generic header approach, questioning whether it should be optional at all. Other participants have raised concerns about email client limitations (Aditya Garg) and implementation specifics (Martin von Zweigbergk, who first asked about signature preservation). Jeff King has contributed testing methodology but remains neutral on design direction.

The discussion now centers on several open questions: whether to implement a general metadata preservation mechanism versus case-specific solutions, how to handle signatures and other metadata (with three placement locations under consideration), and whether such features should be opt-in or always-on. The original change-ID proposal remains in play as v2 patch series, but appears likely to be superseded by Junio's more comprehensive approach if consensus forms around it.
