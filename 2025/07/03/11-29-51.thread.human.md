This thread explores how Git can better preserve commit information like change IDs and signatures when patches are emailed. The discussion began with Drew DeVault's proposal to add X-Change-ID headers to format-patch output, but has since broadened into a deeper examination of Git's email workflow design.

Junio Hamano has proposed a more generic solution that would preserve any commit header via X-git-extra-commit-header lines, while also revealing that Git intentionally omits signatures from emailed patches - a design choice now being reconsidered. The debate centers on whether to maintain the current human-readable format or add an exact-reproduction mode that would preserve all metadata. Technical considerations include header encoding schemes, email client compatibility, and how different tools like Jujutsu (which relies on change IDs) would interact with the solution.

Remo Senekowitsch's recent contribution highlights the real-world impact of these limitations, describing how their code review tool suffers from the lack of reliable change ID preservation when working with mailing list patches. While not taking sides in the technical debate, this reinforces the importance of finding a robust solution that works across different version control systems and tools. The thread remains active with open questions about implementation details and which approach best balances reliability with backwards compatibility.
