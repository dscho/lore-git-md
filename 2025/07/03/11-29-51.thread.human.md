This thread continues the discussion about reliably tracking change IDs in Git's email workflow. The original proposal suggested adding specific X-Change-ID headers to patch emails, but the conversation has evolved toward a more generic solution for preserving commit metadata through the format-patch/am workflow.

Junio Hamano has proposed a generic mechanism to preserve arbitrary commit headers as email headers, which has gained support from several participants including Drew DeVault. Drew's latest email reinforces this direction while clarifying important technical details about signature handling. He explains that commit signatures (like GPG signatures) currently don't survive the format-patch/am roundtrip, and that these are distinct from PGP email signatures. He strongly advocates for using email headers rather than placing metadata in the message body, arguing headers provide better structure and tooling support.

The discussion has identified several technical challenges that need resolution:
1. How to best preserve signatures and other metadata through the email workflow
2. Whether to place metadata in email headers (preferred by Drew and Junio) or in the message body
3. Whether header preservation should be opt-in or always-on
4. How different email clients and infrastructure will handle these changes

While the technical direction appears to be converging on Junio's generic header preservation approach, several implementation details remain open. The thread shows active participation from key contributors including Junio, Drew DeVault, and Martin von Zweigbergk, with the original patch author yet to respond to the latest developments. The discussion remains productive as the group works toward a solution that balances technical correctness with practical usability across different email environments.
