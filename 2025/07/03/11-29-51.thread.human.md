Here's the updated human-readable thread summary:

This thread discusses adding Change-ID tracking to Git's email workflow to help patch management systems track changes through review cycles. The proposed solution involves two parts: generating X-Change-ID headers when emailing commits, and parsing those headers back into commit messages when applying patches.

The v2 series implements both generation (scanning commit messages for change-ids and adding headers) and parsing (extracting headers back to commits). Testing has revealed email client behaviors vary - ProtonMail and MS Graph preserve headers while Thunderbird drops them when composing replies. A debate has emerged between header-based (better separation of concerns) versus trailer-based (more email-compatible) approaches.

Jeff King provided a clever testing methodology using low-level Git commands to programmatically create test commits with change-ids, which Drew DeVault has indicated they'll incorporate in the next version. The discussion continues to weigh technical tradeoffs while awaiting broader feedback on whether this belongs in core Git or external tooling.
