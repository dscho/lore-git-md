Bugfix for `git blame` behavior with missing ignoreRevsFile. The patch addresses an issue where setting `blame.ignoreRevsFile` globally (e.g. in ~/.gitconfig) would make `git blame` fail in repositories that don't have the specified file present, even though the feature is meant to be optional.

The fix modifies `builtin/blame.c` to first verify the file exists via `stat()` before attempting to parse it, skipping non-existent files rather than erroring out. A new test case in `t/t8002-blame.sh` verifies this behavior by setting a global ignoreRevsFile configuration and ensuring blame still works when the file doesn't exist in the repository.

This appears to be a straightforward quality-of-life improvement that maintains backward compatibility while fixing an edge case in the ignoreRevsFile feature. The patch is small and focused, with both code changes and corresponding test coverage. The commit message clearly explains the problem and solution, though it might benefit from mentioning that this affects global configurations specifically (the test case makes this clear).
