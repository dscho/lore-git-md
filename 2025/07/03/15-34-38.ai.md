Bugfix investigation regarding `--diff-filter` behavior with exclusion filters. Jeff King identifies a regression in how `git log --diff-filter=d` (lowercase exclusion filter) works with minimal output formats like `%H`, tracing it to commit 75408ca949 from 2022. While the thread previously concluded this was expected behavior, Jeff's analysis suggests it may actually be a bug that changed existing functionality.

The key technical detail is that the exclusion filter `d` (to omit commits with deletions) fails to produce any output with `--format="%H"` unless combined with diff-generating flags like `--stat`. Jeff notes this behavior changed from what he would consider correct, where the filter should work independently of output format. He CCs the author of the suspect commit for further investigation but doesn't propose a specific fix.

This email introduces new evidence that contradicts the thread's earlier conclusion about this being purely a documentation issue. The reproduction recipe shows the regression clearly: with Git 2.50.0, `--diff-filter=d` produces no output for the test case where it previously would have shown commits without deletions. The interaction between output formats and diff computation appears more complex than initially thought, potentially requiring code changes rather than just doc updates.
