This is the first patch in Patrick Steinhardt's v2 series proposing to make reftable the default ref storage format in Git 3.0. The patch focuses on documenting the planned change in BreakingChanges.adoc while implementing the necessary plumbing to make the default format version-dependent.

The documentation section provides a comprehensive list of advantages reftable has over the current files backend, including case-insensitivity handling, Unicode normalization, atomic multi-ref writes, and performance characteristics. It notes the change will only take effect when WITH_BREAKING_CHANGES is set (for Git 3.0) and emphasizes ecosystem readiness as a prerequisite.

Technically, the patch introduces a REF_STORAGE_FORMAT_DEFAULT macro in repository.h that conditionally selects reftable based on WITH_BREAKING_CHANGES, matching the pattern used in SHA-256 transition. It adds version output support via `git version --build-options` and includes a test verifying the default format matches what's reported in version info. The setup.c changes ensure the default format is properly initialized.

Key implementation details include: the versioned default macro pattern, new version output integration, and the conditional documentation that only appears when WITH_BREAKING_CHANGES is enabled. The test in t0001-init.sh verifies the version output integration works as expected. The patch maintains backward compatibility while paving the way for the future default change.
