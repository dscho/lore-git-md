This is a documentation patch proposing to clarify an existing but undocumented feature in `git init`. The patch notes that passing an empty path to `--template` (like `--template=`) has silently skipped template copying since at least Git 2.1, and suggests documenting this behavior in the man page.

The author's use case involves tooling (like package managers) that create repositories just for fetching remote data, where copying template files (like hooks) is unnecessary overhead. The implementation shows this behavior is consistent across Git versions, with the empty string check moving from `copy_templates()` to `get_template_dir()` in newer versions.

The proposed documentation change would add a sentence to the TEMPLATE DIRECTORY section of git-init(1) explicitly stating that an empty path skips template copying. This appears to be a straightforward, non-controversial documentation improvement of existing behavior rather than a behavior change.

Key technical details for future reference:
- Affects `builtin/init-db.c` template handling logic
- Behavior exists since at least Git 2.1 (2014)
- Empty string check moved to `get_template_dir()` in current code
- Proposed doc location: TEMPLATE DIRECTORY section of git-init(1)
- Use case: tool-created repos where templates are unnecessary overhead
