Bugfix discussion regarding `git log --diff-filter` behavior with exclusion filters. Jeff King identifies this as a regression introduced in Git 2.35 (commit 75408ca949) where lowercase exclusion filters like `d` stopped working with minimal output formats. While earlier analysis suggested this was expected behavior due to diff computation requirements, Jeff's observation that it previously worked indicates this may be an unintended change.

The thread now has conflicting technical perspectives - one view that the behavior is working as designed (filters only applying when diffs are computed) versus Jeff's recollection that exclusion filters used to work with simple formats like `%H`. Jeff has CC'd the author of the suspected regression commit for further investigation.

This affects users trying to filter commits by excluded change types (like `d` for non-deletion commits) when using basic output formats. The discussion highlights how subtle behavior changes in diff filtering can surface years later, and how documentation may need to clarify both the current behavior and historical changes.
