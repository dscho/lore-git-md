Bugfix for `--diff-filter` regression affecting negative filters. Jeff King (peff) follows up on his earlier bug report with a concrete patch to fix the issue where lowercase exclusion filters (like `d` to exclude deletions) weren't working with default output formats.

The problem stems from a 2022 change that split diff filtering into separate `filter` and `filter_not` fields, but the revision setup code wasn't checking both fields when deciding whether to compute diffs. This caused purely negative filters to incorrectly show no commits at all. The fix is straightforward - make the setup code check both filter fields.

The patch includes a new test case that verifies the corrected behavior for negative filters. Jeff considered but rejected a more invasive solution (reordering function calls) in favor of this minimal change to avoid potential new issues. This directly addresses the regression while maintaining the existing behavior for positive filters.

The fix restores the pre-2022 behavior where exclusion filters work regardless of output format, matching both the documented behavior and user expectations. This resolves the core issue that was previously being worked around with `--name-only` or `--dirstat` workarounds.
