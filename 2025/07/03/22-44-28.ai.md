Bugfix addressing a regression in `git log --diff-filter` behavior for lowercase exclusion filters. This patch from Jeff King fixes an issue where negative diff filters (like `d` to exclude deletions) weren't working with default output formats, causing Git to incorrectly show no commits at all.

The problem stems from commit 75408ca949 (2022) which split negative filter bits into a separate `filter_not` field, but the revision setup code wasn't updated to check this new field when deciding whether to enable diffs. The patch modifies `setup_revisions()` to consider both `filter` and `filter_not` fields when determining if diffs are needed for filtering purposes. This restores the pre-regression behavior where exclusion filters work regardless of output format.

Key technical details: The fix involves a one-line change in `revision.c` to check both filter fields, plus a new test case in `t/t4202-log.sh` verifying the corrected behavior for all-negative filters. The commit message explains why this is the safest solution rather than reordering function calls that might have subtle dependencies.
