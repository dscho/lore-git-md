This is the second patch in Patrick Steinhardt's v2 series to make reftable the default ref storage backend in Git 3.0, focusing on expanding testing coverage through experimental feature flags. The patch enables reftable format for new repositories when `feature.experimental=true` is set, while maintaining the existing override hierarchy where `init.defaultRefFormat` and `GIT_DEFAULT_REF_FORMAT` take precedence.

The implementation adds documentation for the new `init.defaultRefFormat=reftable` option in feature.adoc, explaining its benefits for case-insensitive filesystems, compression, and performance. The core change is in setup.c where it hooks into the experimental feature flag to set the default format to reftable when enabled. Three new test cases in t0001-init.sh verify the behavior: experimental flag enabling reftable, explicit init.defaultRefFormat overriding experimental, and environment variable overriding both.

This follows the series' pattern of using versioned defaults while expanding real-world testing. The patch maintains backward compatibility requirements while strategically increasing adoption through experimental users. Test coverage is thorough, checking all precedence rules for format selection. The change is low-risk as it only affects new repository initialization when experimental features are explicitly enabled, keeping the current files backend as the true default until Git 3.0.
