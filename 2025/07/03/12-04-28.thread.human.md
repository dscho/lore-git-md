This thread is about adding SHA-256 support to git-gui, the Tcl/Tk-based graphical interface for Git. The original patch (v2) modified git-gui to handle SHA-256 repositories by replacing SHA-1 length assumptions with dynamic hash length checks throughout the codebase. Johannes Sixt reviewed the changes and confirmed the approach was fundamentally sound while suggesting some polish.

In the latest follow-up, Takashi Iwai addresses Johannes' feedback and identifies several edge cases needing attention. He acknowledges the need to fix a regex that incorrectly checks partial hashes, questions why the original code checked up to 39 characters rather than 40, and plans to clean up duplicate null SHA variables. The discussion has revealed two tricky cases where the hash length isn't yet available during initialization (repository picker dialog and post-checkout hook), with Takashi proposing alternative approaches like using length ranges or parsing git rev-parse output directly.

The thread shows steady progress on making git-gui fully hash-algorithm-agnostic, with the main open questions now centering on initialization timing issues and the cleanest way to handle hash length checks in early code paths. The changes follow established patterns from Git's core SHA-256 support but need to account for git-gui's Tcl-specific implementation details.
