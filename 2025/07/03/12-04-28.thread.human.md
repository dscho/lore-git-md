Takashi Iwai's patch series to add SHA-256 support to git-gui is making steady progress through review. The changes replace hardcoded SHA-1 assumptions with dynamic hash length checks throughout the Tcl codebase, using `git rev-parse --show-object-format` to determine the correct length (40 for SHA-1, 64 for SHA-256). 

Johannes Sixt, the git-gui maintainer, has been providing detailed review feedback. In the latest exchange, they've reached agreement on several key issues: using a length range (40-64) for early initialization cases, measuring `git rev-HEAD` output length for the post-checkout hook, and standardizing on the existing `$nullid` variable. One remaining question is why the original code checked partial hashes up to 39 characters - this historical behavior needs to be preserved while adapting it for SHA-256.

The discussion remains focused on edge cases work correctly before the full hash length is known, particularly in the repository picker dialog and FETCH_HEAD parsing. With these solutions taking shape, the series appears on track for acceptance once the final polish is applied. No tests are included yet, but the changes follow established patterns from Git's core SHA-256 support.
