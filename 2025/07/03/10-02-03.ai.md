Refinement of the `--skip-until` interface for `git for-each-ref` pagination. This follow-up addresses two specific points from Patrick Steinhardt's review of the merged series:

1. **Behavior clarification**: Confirms the `--skip-until` option includes references up to *and including* the specified pattern in the output, and will update documentation to make this explicit. This matches the intuitive cursor-based pagination behavior where the marker reference serves as both the end of the skipped section and the start of the new page.

2. **Interface alignment**: Discusses the current split between prefix handling in `refs_ref_iterator_begin()` (which sets the prefix) and `ref_iterator_seek()` (which can optionally set prefix via flags). Karthik defends the current separation as logically named but is open to unifying the approaches if preferred. The alternative would be to extend `refs_ref_iterator_begin()` to also handle seek operations.

The email also notes a pending code style fix to add curly braces to an if branch in `do_filter_refs()`. This continues the thread's pattern of post-merge refinements focusing on documentation clarity and interface consistency, following the earlier discussions about race conditions and performance characteristics.
