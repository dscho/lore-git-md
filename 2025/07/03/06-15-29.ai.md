This is a v2 cover letter for Patrick Steinhardt's series proposing to make reftable the default ref storage backend in Git 3.0, following up on architectural and documentation feedback from the v1 discussion. The cover letter outlines the two-phase approach: announcing the breaking change for Git 3.0 while enabling reftable as default for experimental users now. Key changes in v2 include improved breaking change documentation (addressing Justin Tobler's feedback while maintaining technical specifics), introduction of a `REF_STORAGE_FORMAT_DEFAULT` macro (responding to Junio Hamano's header-based approach suggestion), and adding ref format info to `git version --build-options` (implementing brian m. carlson's suggestion).

The technical implementation now uses a versioned default macro in repository.h rather than direct conditionals in setup.c, with the breaking change gated behind `WITH_BREAKING_CHANGES` for Git 3.0. The documentation patch (1/2) strengthens the rationale with clearer platform-specific benefits (case-insensitivity, Unicode normalization) and performance comparisons, while the setup patch (2/2) remains focused on experimental user enablement. Test coverage in t0001-init.sh now verifies the version output integration.

The series still awaits confirmation from alternative implementations (JGit/libgit2/Gitoxide) about readiness, which Patrick notes as a prerequisite for the Git 3.0 change. The experimental flag approach aims to broaden real-world testing while maintaining the files backend as default for stable releases. The architectural discussion appears resolved in favor of the header-based approach, though the implementation still needs coordination with external projects before finalizing the breaking change.
