Build system fix addressing GIT_EXEC_PATH configuration when libexecdir is overridden. This is the sixth patch in Patrick Steinhardt's Meson build system cleanup series.

The patch fixes a regression introduced in commit 837f637cf51 where overriding libexecdir via `-Dlibexecdir=` caused Git to lose track of its core binaries. While the previous change correctly propagated the custom libexecdir path, it failed to append the 'git-core' subdirectory where Git expects to find its executables. This manifested as commands like `git daemon` failing with "not a git command" errors.

The fix is straightforward - modifying meson.build to append 'git-core' to any custom libexecdir path. The patch includes before/after test cases showing the corrected behavior where `git --exec-path` now properly reports the full path including the git-core suffix, allowing commands to work again. The change is minimal (a single line modifying the git_exec_path assignment) but important for correct operation when customizing installation paths.

This continues the series' pattern of precise technical fixes to the Meson build configuration. The issue was reported by irecca.kun@gmail.com, who also provided the initial patch. The problem appears to be a straightforward oversight in the earlier change rather than any deeper architectural issue.
