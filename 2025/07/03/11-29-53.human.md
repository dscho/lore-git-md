This is the second patch in a two-part series implementing change-ID preservation in email workflows. It complements the first patch (which added X-Change-ID headers when sending patches) by teaching `git am` to recognize and preserve these headers when applying patches.

The patch modifies `git am` to:
1. Parse incoming X-Change-ID headers from emails
2. Store the change ID in the am_state structure
3. Include the change ID in the final commit when applying the patch
4. Handle the change ID properly during --resume operations

The implementation appears thorough, touching all the necessary components in builtin/am.c and mailinfo.c. The author notes they're unsure about testing strategy and would appreciate review feedback before investing in test coverage. This seems reasonable given the change is straightforward and the series is still in early discussion.

The patch completes the round-trip functionality for change IDs in email workflows, which will help patch management systems like Patchwork and Sourcehut track changes through review cycles. The implementation looks clean and properly integrated with Git's existing am machinery.
