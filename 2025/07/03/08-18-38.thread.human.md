This thread addresses a bug in `git blame` where setting `blame.ignoreRevsFile` globally (e.g., in ~/.gitconfig) causes failures in repositories that don't have the specified file, despite the feature being designed as optional. Francesco Nicoletta Puzzillo's patch modifies `builtin/blame.c` to first check file existence before parsing, skipping non-existent files rather than erroring. Test coverage in `t/t8002-blame.sh` verifies the fix.

Kristoffer Haugsbakk has provided additional context by linking to Noah Pendleton's 2021 thread introducing the ignoreRevsFile feature, suggesting this isn't just a simple bugfix but touches on a design question about how optional configuration files should behave. The reference raises the question of whether the current fix aligns with the original design intent - whether such files should fail loudly or silently skip when missing. The patch itself remains unchanged and appears uncontroversial, being a focused improvement that maintains backward compatibility. Reviewers may want to consult the historical discussion to ensure the solution matches the feature's intended behavior.
