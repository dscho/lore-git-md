This is a follow-up discussion about the interface design for the recently merged `--skip-until` pagination feature in `git for-each-ref`. Patrick Steinhardt adds a key technical consideration to the ongoing debate about name-based versus numeric offset approaches.

The email reinforces Karthik Nayak's performance argument for the name-based `--skip-until` implementation by highlighting a critical correctness issue with numeric offsets: they would be invalidated by concurrent reference updates that insert new refs in the skipped range. This makes the name-based approach not just more performant (O(log N) via binary search vs O(N) iteration) but also more robust in multi-process scenarios.

The discussion continues to focus on the tradeoffs between usability (where numeric offsets might be more intuitive) and technical requirements (where name-based skipping provides both performance and correctness benefits). Patrick's contribution strengthens the case for the current implementation by identifying a race condition that would affect numeric offsets but not name-based skipping.

Key technical details mentioned:
- The binary search mechanism in reference backends that enables efficient name-based skipping
- The O(N) nature of numeric iteration
- The race condition where concurrent ref insertions would invalidate numeric offsets
- The performance impact being most noticeable in very large repositories (~1M refs)

This email doesn't propose any modifications to the merged code but provides important additional justification for the design decisions already made. The thread continues to explore both the interface design rationale and separate code formatting concerns from the implementation.
