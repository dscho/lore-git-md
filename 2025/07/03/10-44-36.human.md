This is a follow-up in the ongoing discussion about credential helper behavior, specifically investigating why authentication tokens get cleared after failed operations. Michal Suchánek reports back after using Junio Hamano's suggested `GIT_TRACE_CURL` debugging technique to examine HTTP status codes from the server.

The key finding is that the problematic forge instance Michal is working with consistently returns HTTP 401 status codes (which trigger credential clearing) even when it shouldn't, while a development version of the same software correctly returns 403 codes in those cases. This suggests the issue may be server-side rather than with Git's credential handling, and that upgrading the server software could resolve the problem.

The email is brief but provides important empirical evidence supporting the theory that inconsistent server behavior is at the root of the credential clearing issue. This moves the discussion forward by identifying a concrete difference between working and non-working server implementations. The finding aligns with earlier debugging efforts but provides more direct evidence through Git's native HTTP tracing.
