Feature patch adding SHA-256 support to git-gui. This is version 2 of a patch that modifies git-gui to properly handle SHA-256 repositories by making hash length checks dynamic rather than hardcoded for SHA-1's 40-character length.

The changes span multiple git-gui components including the main script, blame viewer, repository chooser, commit interface, and remote branch deletion. Key modifications include:
- Adding a global `hashlength` variable set by querying `git rev-parse --show-object-format`
- Replacing hardcoded "40" with `$hashlength` in regex patterns and string operations
- Special handling for null SHA values (now using `string repeat 0 $hashlength`)
- Adjusting commit tree validation to account for variable hash lengths

The patch appears thorough, touching all the obvious places where SHA-1 assumptions were baked in. The v2 fixes an oversight in commit_committree handling that wasn't addressed in the first version. The changes are mechanical but necessary for SHA-256 compatibility, following the pattern established in other parts of Git's codebase. No tests are included, but the changes are straightforward and the risk of regression seems low given the nature of the modifications.
