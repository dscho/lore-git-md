This thread discusses a documentation patch to clarify the behavior of `git init --template=` when passed an empty path, which skips copying template files. This behavior has existed since Git 1.5.6.4 (2008) and was originally intended to prevent accidentally linking root directory files. Han Young first pointed out that this undocumented feature is widely used by package managers and other tools that create temporary repositories, where template files would add unnecessary overhead. Boris Kolpackov has now chimed in to agree, reinforcing that the behavior is both long-standing and legitimately relied upon in practice, particularly for temporary repository setups. The consensus is that this behavior should be documented more prominently in the git-init(1) manpage, as the current obscurity doesn't change the fact that tools depend on it. The patch remains non-controversial as it only documents existing behavior without making any functional changes.
