This thread discusses a documentation patch to clarify the behavior of `git init --template=` when passed an empty path. The feature, which skips template copying entirely, has existed since Git 1.5.6.4 in 2008 to prevent dangerous filesystem operations. Han Young and Boris Kolpackov initially confirmed this is widely used by package managers and tools that create temporary repositories where template files would be unnecessary overhead.

Todd Zullinger has now provided historical context, pointing to the original 2008 commit that introduced this behavior. He suggests expanding the documentation to explicitly cover all three ways to specify templates (CLI option, config, and environment variable) if they behave consistently with empty values. The thread shows clear consensus that documenting this stable, 17-year-old implementation detail is worthwhile, with no objections raised. The patch would only update git-init(1) documentation without changing any code in the template handling logic.
