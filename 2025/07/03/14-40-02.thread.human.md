This thread documents two ways to skip template copying during `git init`: the long-standing behavior of specifying an empty path (via `--template=`, `init.templatedir`, or `GIT_TEMPLATE_DIR`) and the newer `--no-template` flag introduced in Git 2.38.0. 

The empty path approach, implemented in 2008, was designed to prevent filesystem corruption and is widely used by package managers. Todd Zullinger provided historical context confirming this was an intentional safety feature. Jeff King (peff) notes that while the empty path behavior remains valid, `--no-template` flag is now the preferred CLI method when available, as it's more explicit. However, the empty path approach still matters for cases where the flag isn't applicable, like config or environment variables.

Kristoffer Haugsbakk initially contributed to this discussion and caught an important detail - the flag is singular (`--no-template`) not plural. The documentation needs to clearly explain both methods and their interaction (where `--no-template` takes precedence when both are specified). There's consensus that both features should be documented, with careful wording to avoid confusion between them. The patch will update the TEMPLATE DIRECTORY section of git-init(1) to cover these related but distinct mechanisms.
