This is a follow-up discussion about the recently merged `--skip-until` pagination feature in `git for-each-ref`. The thread focuses on interface design tradeoffs between name-based versus numeric offset approaches.

Patrick Steinhardt reinforces Karthik Nayak's earlier performance argument for the current name-based skipping approach, pointing out an additional critical issue with numeric offsets: they would be invalidated by concurrent reference updates that insert new refs in the skipped range. This makes the name-based approach not just more performant (O(log N) via binary search vs O(N) iteration) but also more robust in multi-process scenarios.

The discussion remains theoretical - no changes to the merged implementation are proposed - but provides important rationale for the design. The exchange highlights how Git's ref storage architecture naturally favors name-based operations while numeric offsets would introduce both performance and correctness challenges in real-world usage.
