Bug report from Per Cederqvist about remote naming ambiguity in Git, expanded by Jeff King to cover general refspec collision cases. Core issue involves refname resolution ambiguity when remote names contain slashes (e.g. "origin" vs "origin/chat") or when fetch refspec destinations overlap.

Jeff King's patch adds validation in `builtin/remote.c` to prevent ambiguous remote names via `git remote add` while preserving manual config editing capability. Implementation includes new `check_remote_collision` function scanning for subset/superset name conflicts, with test coverage for collision cases. Maintains backward compatibility and clear error messaging.

Recent discussion clarified two implementation details:
1. Parameter naming: `vname` in `check_remote_collision` follows void pointer convention ("v" prefix); Jeff King suggests "data" would be more conventional than alternatives like "payload" while avoiding underscore prefixes.
2. Slash handling: New validation allows slashes passing `check_refname_format()` while older `valid_remote_nick()` rejects all slashes. Behavior is platform-independent (only forward slashes as separators, backslashes always forbidden) based on `refname_disposition` table.

Patrick Steinhardt reviewed implementation, suggesting parameter naming improvements and noting slash handling inconsistency. Junio Hamano maintains preference for minimal restrictions but accepts porcelain-only enforcement approach. Patch direction approved pending minor fixes.

Open considerations:
- Performance impact of refspec overlap detection at scale
- Mirror remotes' refspec overlaps not addressed
- Inconsistency between new validation and legacy `valid_remote_nick()`
- Potential future work on refspec-level validation

Key files: `builtin/remote.c` (validation), `remote.c`, refspec handling code. Participants: Per Cederqvist, Junio Hamano, Patrick Steinhardt, Jeff King (patch author), Lidong Yan.
