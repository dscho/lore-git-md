This thread discusses a proposed enhancement to Git's bash completion that would allow configurable sorting of refs during tab completion, using a new `GIT_COMPLETION_REFS_SORT_BY_FIELDNAME` configuration variable. The original patch from Nelson Benítez León introduced the feature with alphabetical sorting as the default but allowed customization via fieldnames like `-committerdate`. 

Maintainer Junio Hamano provided initial feedback focusing on process requirements: commit messages should follow Git's standard format, and tests are mandatory for new features. He noted no technical objections to the core implementation but emphasized these prerequisites before merging.

SZEDER Gábor has now contributed a technical review identifying several implementation concerns. He points out that the current approach only handles single sort keys despite `git for-each-ref` supporting multiple sort options, raises performance concerns about subshell usage on Windows, and argues against disabling Bash's sorting globally in the completion helper. These are substantive technical points that the author will need to address in a revised version.

The feature itself appears uncontroversial in principle, but the next version should incorporate both Junio's process requirements (tests and commit message style) and SZEDER's technical suggestions around multi-key sorting, Windows performance, and targeted sorting modifications. The thread remains open pending these revisions.
