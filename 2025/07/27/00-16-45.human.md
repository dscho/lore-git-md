Bugfix discussion regarding `git grep`'s handling of shorthand exclude pathspecs.

Junio C Hamano responds to a bug report about inconsistent behavior between `git ls-files` and `git grep` when using the shorthand `:^:` exclude pathspec syntax. While `git ls-files` correctly processes this syntax, `git grep` currently fails with an "ambiguous argument" error, incorrectly interpreting it as a revision.

Hamano notes that the longhand `:(exclude)` syntax works correctly in `git grep` and suggests the issue stems from how `setup.c` verifies filenames. He identifies the specific code paths involved (`die_verify_filename()` and `looks_like_pathspec()`) that handle this differently between the two commands.

The response indicates this is likely a fixable inconsistency, though Hamano cautions there may be unintended consequences to modifying the shorthand pathspec handling. The discussion remains technical and productive, focusing on the underlying implementation details rather than just the surface behavior. This appears to be a legitimate bug that affects users expecting consistent pathspec behavior across Git subcommands.
