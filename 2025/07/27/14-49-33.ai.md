Feature patch for bash completion, adding configurable ref sorting.

This patch introduces a new configuration variable `GIT_COMPLETION_REFS_SORT_BY_FIELDNAME` that allows users to customize how refs are sorted in bash completion (e.g. when tab-completing branch names). The default remains alphabetical (`refname`) to maintain backward compatibility, but users can now set alternative sort orders like `-committerdate` to see recently worked-on branches first.

The implementation adds a new helper function `__git_get_sort_by_fieldname()` that validates and applies the sort parameter, then modifies all relevant `for-each-ref` calls in the completion script to use this sorting. It also adds `-o nosort` to completion to prevent bash's default alphabetical sorting from interfering.

Key technical details:
- New config var accepts any valid `--sort` parameter for `for-each-ref`
- Input is validated with regex `^[a-zA-Z0-9%:=*(),_\ -]+$`
- Affects all ref completion scenarios (local/remote branches, tags, etc.)
- Changes 8 call sites in git-completion.bash
- No test coverage included (author notes unfamiliarity with test framework)

The author suggests potentially changing the default to `-committerdate` in a future patch if there's agreement that recently-used branches are more useful than alphabetical order. The patch appears well-structured with clear commit message explaining motivation and implementation.
