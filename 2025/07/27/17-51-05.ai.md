This is a feature implementation patch series (v6) introducing a new `git repo info` command for retrieving repository metadata. The series is part of Lucas Seiki Oshiro's GSoC project mentored by Karthik Nayak and Patrick Steinhardt.

The key technical changes in v6 include:
- Transitioned value retrieval functions to use `struct strbuf` for output (planned since v5)
- Renamed the machine-readable format from "null" to "nul" (matching Git conventions)
- Added test cases for invalid CLI inputs
- Deferred quoting implementation until path handling is added (as discussed in v5)

The implementation now provides:
- Three metadata fields: `references.format`, `layout.bare`, and `layout.shallow`
- Dual output formats: human-readable `keyvalue` (default) and machine-readable `nul`
- Basic error handling for invalid keys and formats

The thread context shows consensus on the phased approach, with quoting deferred until needed for path values. The core architecture appears stable with all major technical questions resolved. The series is progressing toward finalization with only minor documentation and naming concerns remaining open.

Notable technical details for future reference:
- Output formats:
  - `keyvalue`: LF-separated key=value pairs
  - `nul`: LF between key/value, NUL after each record
- Current fields (all simple values not requiring quoting):
  - `references.format`: files/reftable
  - `layout.bare`: true/false
  - `layout.shallow`: true/false
- String handling now uses `strbuf` throughout
- Error cases:
  - Dies on invalid keys with "key 'foo' not found"
  - Dies on invalid formats with "invalid format 'foo'"
