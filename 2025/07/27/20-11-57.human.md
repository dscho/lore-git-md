This is a review comment on the "repo info" command series, focusing on output formatting considerations. Eric Sunshine responds to Lucas Seiki Oshiro's v6 patchset, which implements a new plumbing command to report repository metadata (ref storage format, bare/shallow status) with both human-readable and machine-parsable output formats.

The key point of contention is whether to implement value quoting with `quote_c_style` now rather than deferring it. Eric argues strongly for immediate implementation, noting that establishing proper quoting behavior from the start prevents future compatibility issues when new fields with "funny" characters are added. He acknowledges this isn't just about paths - any future metadata value could need quoting. His position is that documenting and implementing robust output handling early creates better long-term behavior and clearer expectations for tooling.

This comes as the series appears otherwise complete, with v6 having addressed all major technical feedback (format naming, string handling, test coverage) and now implementing three functional metadata fields. The discussion represents one of the final design decisions before potential inclusion, with Eric providing a maintainer perspective on output format stability concerns.
