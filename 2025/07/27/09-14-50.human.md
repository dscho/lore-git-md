This is a follow-up in the git-daemon regression thread, providing additional context about the systemd workaround that was previously in place.

Russell King shares that he had forgotten about a systemd override configuration that was originally added to work around an earlier issue with git-daemon. The override included explicit paths in the ExecStart command, which may have been masking the current SELinux-related problem. He notes that after removing the last two paths from the override and adding `--base-path`, the daemon is now working correctly.

The email suggests some confusion about whether `--export-all` behavior changed in a way that inverted the meaning of directory listings, but this appears to be speculation rather than a confirmed issue. The main takeaway is that the SELinux solution identified earlier in the thread works, and the systemd override was an unrelated factor that complicated initial debugging.

This doesn't introduce new technical information about the core issue (which was resolved as Fedora-specific SELinux policy tightening), but provides useful context about why the original reporter's setup behaved differently than test cases. The thread appears to be winding down with the issue understood and resolved.
