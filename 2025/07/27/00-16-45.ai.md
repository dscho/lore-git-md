Bugfix discussion regarding `git grep` pathspec parsing inconsistency.

Junio C Hamano responds to a bug report about `git grep` failing to handle the `:^:` exclude pathspec syntax that works in `git ls-files`. He confirms the issue but notes the shorthand syntax is "deliberately confusing" and suggests using the longhand `:(exclude)` form as a workaround. The error occurs in `setup.c`'s filename verification code path, where the longhand magic pathspec is properly handled but the shorthand is not.

Junio identifies the technical location of the issue (`setup.c:die_verify_filename()` and `setup.c:looks_like_pathspec()`) and suggests it might be possible to teach the code to handle the shorthand syntax, but expresses caution about potential unintended consequences of such a change. The response indicates this is a known parsing edge case rather than a fundamental limitation, but one that requires careful consideration before fixing due to possible side effects in other code paths.
