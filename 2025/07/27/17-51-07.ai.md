Feature implementation for the new `git repo info` command, specifically adding reference format detection. This patch introduces the `references.format` field to report whether a repository uses files or reftable for reference storage, migrating functionality from `git rev-parse --show-ref-format`.

The implementation:
- Adds a field system with bsearch-based key matching
- Implements `get_references_format()` using `ref_storage_format_to_name()`
- Includes comprehensive tests verifying:
  - Correct format detection for both files and reftable backends
  - Error handling for invalid keys
  - Deduplication of duplicate key requests
- Documents the new field in `git-repo.adoc`
- Integrates with the build system via new test file `t1900-repo.sh`

Key technical details:
- Uses `struct strbuf` for string handling (per v6 series updates)
- Maintains lexicographical field ordering
- Returns simple key=value output (foundation for future format options)
- Error message format: "key 'foo' not found"

This appears to be a well-constructed implementation with thorough test coverage, cleanly integrating existing ref storage detection into the new command structure. The patch follows the series' architectural decisions and shows attention to edge cases like duplicate key handling.
