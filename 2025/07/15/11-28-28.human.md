This is a refactoring patch that clarifies and extends the behavior of the `ref_iterator_seek()` function in Git's ref iteration API. It's part of the v5 series adding pagination support to `git for-each-ref` via `--start-after`.

The patch introduces a flags parameter to `ref_iterator_seek()` with `REF_ITERATOR_SEEK_SET_PREFIX` as the first flag. When set, it maintains the existing behavior of setting the iteration prefix. Without the flag, the function now seeks to a specific reference while clearing any previous prefix, making the API more flexible for pagination use cases.

The changes are implemented consistently across all ref backends (files, packed, reftable), with the files backend requiring the most work due to its ref-cache mechanism. The patch includes thorough updates to documentation and tests to reflect the new behavior.

This is a well-structured change that cleanly separates the two distinct operations (prefix filtering vs pure seeking) that were previously conflated in the API.
