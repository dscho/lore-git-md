This is the first patch in a v5 series introducing pagination support for `git for-each-ref`. The patch exposes Git's internal `ref_iterator` API through the `refs.h` header, moving documentation and type definitions from the internal header to the public one.

The change makes the ref iteration machinery available to advanced users who need more flexibility than the existing `for_each_ref` wrapper functions provide. The commit message explains that as requirements grow, creating new wrapper functions for every combination becomes impractical. The exposed API includes functions for creating iterators, advancing through refs, seeking to specific prefixes, peeling refs, and cleanup.

The patch is well-documented with clear explanations of iterator lifecycle and usage patterns. It preserves all existing functionality while making the internals available for more sophisticated use cases. This foundational change enables the pagination feature that follows in the rest of the series, where the `--start-after` option will use these iterator capabilities.

The implementation looks clean and thorough, with comprehensive documentation moved verbatim from the internal header. This appears to be a well-considered change that maintains backward compatibility while opening up useful functionality.
