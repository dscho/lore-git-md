This is part 3 of a 7-patch refactoring series moving MIDX tracking from global state to per-source storage in `struct odb_source`. The series is now in its second iteration after incorporating review feedback.

The patch eliminates the global MIDX list traversal in `close_midx()` by switching to per-source iteration. Instead of recursively walking the linked list of MIDX structures, it now iterates through object database sources and closes each one's MIDX directly. The changes affect both `midx.c` and `packfile.c`, with the key transformation being the replacement of recursive list traversal with explicit source iteration.

The patch maintains the same cleanup behavior while removing global state - all MIDX files are still properly closed, just via a different mechanism. The author notes there are some remaining cases where `close_midx()` is called without iterating through all sources, but these are intentional for cases where only a specific MIDX needs closing.

This continues the series' clean separation of concerns by treating MIDX files as properties of individual object sources rather than global database state. The changes are mechanical but important for the larger goal of making the object database more modular. The patch appears well-contained and builds on the foundation established in earlier parts of the series.
