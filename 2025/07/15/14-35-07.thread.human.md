René Scharfe has proposed a 3-patch series optimizing commit traversal by replacing sorted linked lists with priority queues, significantly improving worst-case performance from O(n²) to O(log n) for pathological histories (like Git's own merge-heavy history) while maintaining normal-case speeds. The changes touch core commit handling in commit.c and related files, introducing a new prio_queue_replace() helper to optimize first-parent processing.

Junio Hamano and Justin Tobler have reviewed the technical approach, validating the performance improvements (92% faster for bad cases with only 1% initial regression in normal cases) and suggesting minor documentation clarifications. The series appears technically sound and ready for merging, with Junio now raising a final semantic question about whether the priority queue implementation preserves exact commit ordering when timestamps are identical - an important consideration for deterministic behavior. This appears to be the last verification needed before the optimization can be accepted.
