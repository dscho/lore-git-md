René Scharfe has proposed a performance optimization series that refactors Git's commit traversal to use priority queues (prio_queue) instead of commit lists, significantly improving worst-case performance. The three patches achieve a 92% speedup for pathological histories (those with many merges and root commits) while maintaining near-identical performance for normal cases. The series has been reviewed by Junio Hamano, who validated the performance measurements and approach. The optimization particularly benefits Git's own development history, which contains many merges.

Justin Tobler recently responded to the first patch, confirming his understanding of the technical approach. He notes that while the implementation changes from O(n) list insertion to O(log n) priority queue operations, callers still need to ensure proper initial ordering - just configured differently now. Justin suggests clarifying in the documentation which repository types would see the most benefit from these pathological case improvements.

The core of the series replaces commit_list_insert_by_date() with prio_queue operations, adds a new prio_queue_replace() helper, and then uses that helper to optimize first parent processing. Performance tests show the final version recovers the initial 1% regression seen in normal cases while keeping the dramatic improvements for complex histories. The changes touch several key areas including commit handling and object name resolution, with comprehensive tests covering both functionality and performance.
