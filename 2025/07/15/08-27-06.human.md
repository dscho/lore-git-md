This is part 5/8 of Patrick Steinhardt's refactoring series to move MIDX tracking from global state to per-source storage in preparation for pluggable backends. The patch refactors `get_multi_pack_index()` to operate on individual `struct odb_source` instances rather than the global object database.

The key change converts MIDX lookups to work per-source, with callers now iterating through sources to find MIDX files. The patch updates several call sites including pack-objects, object-name, and pack-bitmap code. A notable addition is an explicit `m->local` check in `builtin/repack.c` to handle edge cases with temporary object sources.

Taylor Blau reviewed the changes, confirming the per-source iteration pattern is correct while questioning whether a utility function for MIDX iteration might be useful. Patrick agrees the pattern is more verbose but feels it's not worth abstracting unless others feel strongly. They also discuss edge cases around local object sources and agree to handle NULL returns from `odb_find_source()` in a follow-up series.

The changes maintain existing behavior while moving toward the series' goal of eliminating global MIDX state. The patch builds on prior work in the series and has been updated to incorporate review feedback about code style and edge case handling.
