This is a refactoring series (7/7 patches) that completes the transition of MIDX tracking from global object database state to per-source storage, part of the ongoing effort to prepare for pluggable backends.

The series removes the last remnants of global MIDX tracking by eliminating the linked list of multi-pack indices from `struct object_database`. All MIDX handling now operates through individual `struct odb_source` instances, with each source maintaining its own MIDX pointer (renamed from `multi_pack_index` to `midx` in v2). The changes build on prior feedback and have been reviewed by Taylor Blau and Justin Tobler.

Key technical changes in this final patch:
- Removes the global `multi_pack_index` field from `struct object_database`
- Eliminates the `next` pointer from `struct multi_pack_index`
- Updates remaining MIDX-related functions to work with per-source storage
- Confirms compatibility with recently merged cruft pack/MIDX interaction changes

The series has evolved through review feedback, with v1's redundant state tracking patch dropped and various style improvements incorporated. The changes are now focused and well-contained, passing tests while maintaining clean separation between object database and MIDX implementation details. This represents a significant milestone in the object database abstraction effort.
