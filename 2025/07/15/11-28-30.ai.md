This is the final patch in a series implementing efficient pagination for `git for-each-ref` via a new `--start-after` option. The feature builds on earlier work exposing the ref iterator API and implementing seek operations across all ref backends (files, packed, reftable).

The patch introduces the user-facing `--start-after` option which allows paginating ref listings by specifying a marker reference. The implementation seeks to the next reference lexicographically by incrementing the last character of the marker (via new helper `start_ref_iterator_after()`). The option cannot be combined with custom sort orders or pattern matching, enforced by explicit error checks.

Key technical details include:
- New `start_after` field in `struct ref_filter`
- Extraction of iteration logic into `for_each_fullref_with_seek()`
- Comprehensive test coverage for edge cases (empty markers, partial matches, directory boundaries, overflow scenarios)
- Documentation of the pagination behavior and its limitations regarding concurrent ref updates
