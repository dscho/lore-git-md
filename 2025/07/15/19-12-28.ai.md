This is a refactoring patch in the byte-swapping optimization series, focusing on standardizing the ntohl/ntohll macro definitions across platforms. It comes from Sebastian Andrzej Siewior as part of Carlo Marcelo Arenas Belón's broader effort to improve byte-order handling.

The patch reorganizes how ntohl/htonl and ntohll/htonll macros are defined in compat/bswap.h, making the logic more consistent. Key changes include:
1. Always redefining the macros after determining endianness, rather than having conditional definitions
2. Grouping all macro undefinitions together before the new definitions
3. Using the same pattern for both 32-bit and 64-bit variants
4. Maintaining the existing behavior but with cleaner organization

The changes preserve all existing functionality while making the code more symmetrical and easier to follow. The patch continues the series' trend of removing platform-specific optimizations in favor of compiler-optimized versions where possible. It builds on the previous MSVC support work by using the GIT_BYTE_ORDER constants that were standardized in earlier patches.

Technical details to note for future reference:
- Still uses bswap32/bswap64 when available (compiler intrinsics)
- Falls back to default_swab32/default_bswap64 otherwise
- Maintains big-endian fast paths
- All changes are confined to compat/bswap.h
- No behavior changes - just code reorganization

This appears to be a straightforward cleanup that follows logically from the previous patches in the series. The changes are mechanical and well-contained, suggesting low risk of introducing new issues while improving maintainability.
