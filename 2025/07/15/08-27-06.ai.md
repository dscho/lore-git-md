Refactoring patch in the series moving MIDX tracking from global state to per-source storage. This is patch 5/8 in the updated series (patch 4/8 was dropped as redundant after review feedback).

The patch refactors `get_multi_pack_index()` to operate on individual `struct odb_source` instances rather than the global object database state. Key changes include:
- Updates callers in `builtin/repack.c`, `midx-write.c`, and `object-name.c` to use the new per-source interface
- Adds a `m->local` check in `builtin/repack.c` to handle edge cases with temporary object sources
- Simplifies `lookup_multi_pack_index()` by leveraging `odb_find_source()`
- Implements per-source iteration pattern in `find_short_packed_object()`

The discussion with Taylor Blau confirms:
- The first source is almost always the local one (exception being temporary quarantine directories)
- `odb_find_source()` will never return NULL (currently dies on invalid input)
- The per-source iteration pattern is more logical but more verbose
- A potential follow-up could add a utility function for MIDX iteration

Patrick acknowledges the feedback and notes:
- The `m->local` check could be dropped but adds safety
- A follow-up series will refactor `odb_find_source()` to return NULL rather than die
- Open to adding a looping macro if reviewers prefer it

This patch continues the series' clean separation of concerns while maintaining existing behavior. The changes align with the overall goal of preparing for pluggable backends by removing global MIDX state.
