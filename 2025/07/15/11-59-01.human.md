This is a feature patch introducing a new `git repo` command hierarchy, part of Lucas Seiki Oshiro's GSoC project to create a dedicated tool for repository metadata queries. The patch establishes the basic command structure with an initial `info` subcommand, moving functionality from `git rev-parse` to a more appropriate home.

Patrick Steinhardt provides review feedback on the initial implementation. He suggests:
1. Removing the bulleted file list since it's redundant with the diffstat
2. Avoiding forward-looking language in the documentation that makes promises about future capabilities
3. Considering whether the default output format should be human-readable (with a `--porcelain` option) rather than machine-readable by default
4. Adding error handling when `git repo` is called without arguments

The patch appears technically sound but still in early stages - it currently just declares the command structure without implementing any actual functionality. The review focuses on establishing good patterns for documentation and error handling from the outset. This is part of an ongoing discussion about the command's naming (with `git-repository` as an alternative proposal) and output format design.
