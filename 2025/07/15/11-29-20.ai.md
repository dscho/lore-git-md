Refactoring patch in the ongoing ODB abstraction effort, specifically part 3/7 of Patrick Steinhardt's series to move MIDX tracking from global state to per-source storage. This patch eliminates the global MIDX linked list iteration during cleanup operations in favor of direct per-source MIDX handling.

The key change replaces recursive `close_midx()` calls that walked the global linked list with direct iteration through `struct odb_source` instances. The patch modifies two main functions:
- `clear_midx_file()` now iterates through sources to close and clear their MIDX pointers rather than using the global `multi_pack_index` field
- `close_object_store()` similarly transitions to source iteration while maintaining the same cleanup behavior

The changes touch midx.c and packfile.c, updating the MIDX cleanup paths to work with the new per-source model. The patch notes that some remaining `close_midx()` callsites are intentionally left unchanged where they only need to operate on a specific MIDX rather than all sources.

This continues the series' pattern of eliminating global MIDX infrastructure while maintaining functionality. The changes are mechanical but important for the larger goal of decoupling MIDX handling from global object database state. The patch builds on previous work establishing per-source MIDX tracking and prepares for the eventual removal of the global `multi_pack_index` field in later patches.
