This is the cover letter for a 7-patch refactoring series that moves MIDX tracking from global object database state to per-source storage, part of the ongoing effort to prepare for pluggable backends. The series builds on prior work restructuring object store internals and is now confirmed compatible with recently merged cruft pack/MIDX interaction changes.

The key change moves MIDX tracking from `struct object_database` to individual `struct odb_source` instances, since MIDX files are fundamentally packfile optimizations that should be associated with their specific source rather than treated as a database-wide concern. This eliminates the global MIDX linked list and associated infrastructure while simplifying several code paths that can now access MIDX data directly via the source.

Version 2 incorporates review feedback by renaming fields (`multi_pack_index` -> `midx`), dropping a redundant patch that guarded MIDX reloading, and improving commit message explanations. The series has been rebased on recent changes including the cruft pack/MIDX interaction fixes. Reviewers Taylor Blau and Justin Tobler have verified the core approach and identified only minor follow-up work needed (moving the `local` flag to `struct odb_source` and potentially adding a MIDX iteration helper).

The technical changes systematically replace all global MIDX access with per-source variants, removing the linked list infrastructure in the final patch. Key transformations include refactoring `prepare_packed_git_one()` to work on sources, converting MIDX cleanup to source iteration, and updating MIDX lookup in critical paths like `find_pack_entry()` and `get_all_packs()`. The series passes tests and maintains compatibility while paving the way for future backend pluggability work.
