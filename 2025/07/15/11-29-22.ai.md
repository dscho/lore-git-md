This is part 5 of Patrick Steinhardt's 7-patch refactoring series moving MIDX tracking from global state to per-source storage in `struct odb_source`. The series is now in version 2 after incorporating review feedback.

The patch removes the last remaining use of the global MIDX linked list in `find_pack_entry()`, completing the transition to per-source MIDX tracking. The key change replaces iteration over `r->objects->multi_pack_index` with iteration over `r->objects->sources`, checking each source's `midx` pointer directly. This builds on previous patches that established per-source MIDX tracking and eliminated the global linked list infrastructure.

The change simplifies the code by:
1. Removing the explicit MIDX list traversal
2. Leveraging the existing `prepare_packed_git()` call which already handles source preparation
3. Maintaining the same lookup behavior while using the new per-source storage

The patch demonstrates the benefits of the refactoring - callers no longer need to manage MIDX state directly and can rely on the source iteration pattern. This is a clean mechanical conversion that follows the established pattern from earlier patches in the series. The diff is small (11 lines changed) and focused, with no behavior changes beyond the internal implementation details.

This continues the series' progress toward fully decoupling MIDX handling from global object database state, an important step in the larger ODB abstraction effort for pluggable backends. The change is well-contained and builds on the foundation established by previous patches in the series.
