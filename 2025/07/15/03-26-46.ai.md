This is a bug report about `git pull` failing to honor the `pull.autostash` configuration when used with `--git-dir` and `--work-tree` flags on a bare repository. The reporter demonstrates a clear reproduction case where autostash works in regular repositories but fails in this specific setup, despite identical configuration.

The issue occurs when managing dotfiles via a bare repository with separate work tree. The reporter shows that while the configuration is properly loaded (`pull.autostash=true` and `pull.rebase=true`), Git still errors about unstaged changes rather than auto-stashing them. The workaround of using explicit `--autostash` flag works, suggesting the configuration parsing is being bypassed in this mode.

Key technical details include:
- The bare repository setup (`--git-dir=$HOME/.dotfiles/ --work-tree=$HOME`)
- Configuration verification showing settings are properly loaded
- GIT_TRACE output showing autostash isn't being attempted
- The bug appears specific to the combination of bare repository + work-tree flags

The report is thorough with multiple verification steps and workaround attempts, making a strong case that this is a genuine bug rather than user error. The issue affects a common dotfile management pattern and represents a divergence from expected behavior in regular repositories.
