This is a follow-up in the SHA-256 support for git-gui thread, addressing review feedback on the v2 patch. Takashi Iwai responds to Johannes Sixt's technical suggestions about handling hash lengths more robustly in the Tcl/Tk GUI code.

The email focuses on several specific improvements needed before resubmitting:
1. Fixing a regex that checks partial hash IDs (currently allowing 1-39 chars when it should match full hashes)
2. Avoiding `$hashlength` usage in repository picker code where it isn't yet available
3. Using existing `$nullid` variable instead of generating null hashes dynamically
4. Cleaning up duplicate null SHA variables (`$null_sha1` vs `$nullid`)

The discussion reveals some subtle timing issues around when hash length information becomes available during GUI initialization. Takashi proposes workarounds like using length ranges (40,64) in regexes for the picker dialog, and checking HEAD's length directly in post-checkout hooks.

The exchange shows good technical engagement - Takashi is responsive to the feedback while also questioning some original design choices (like why a partial hash check existed). The next version should be more robust, though test coverage for the hash-length transitions remains an open question.
