Performance optimization patch adding a new helper function to the priority queue implementation. This is the second patch in René Scharfe's 3-part series optimizing commit traversal performance (following the initial conversion to use priority queues in patch 1).

The patch introduces `prio_queue_replace()` which combines the operations of getting the top element and putting a new one, avoiding the redundant heap rebalancing that would occur if done separately. This optimization targets the common commit traversal pattern where we process a commit and immediately add its parents to the queue.

Key technical details:
- Extracts heap rebalancing logic into new `sift_down_root()` helper function
- Implements `prio_queue_replace()` in prio-queue.c with corresponding header declaration
- Adds comprehensive unit tests covering both FIFO and LIFO (stack) modes
- Maintains all existing functionality while adding the optimization

The change is focused on the prio-queue.[ch] core with tests in t/unit-tests/u-prio-queue.c. This builds on the foundation from patch 1 to address the 1% performance regression in normal cases by optimizing the get+put sequence. The implementation handles edge cases (empty queue, non-comparison/LIFO mode) while providing the optimization for the primary comparison-based use case.
