Feature patch completing the pagination support for `git for-each-ref`. This is the final patch in a series that adds efficient O(log N) pagination across all ref backends (files, packed, reftable).

The patch introduces a `--start-after` option to `git for-each-ref` that allows paginating through references by specifying a marker reference to start after. This enables efficient workflows where scripts can remember the last reference from a previous invocation and use it as the starting point for the next batch. The implementation builds on the ref iterator API changes from earlier in the series, using a helper function that seeks to the next reference by incrementing the marker's last character.

The documentation clearly notes that pagination is exclusive to the marker (references lexicographically before the marker won't be shown) and that concurrent updates behind the marker won't be visible. The patch includes extensive test coverage for edge cases like partial matches, directory boundaries, and invalid combinations with patterns or custom sorting.

This appears to be the polished final version of the feature, incorporating all feedback from the mailing list discussion. The implementation is clean and well-tested, with clear documentation of both the user-facing behavior and internal implementation details. The series as a whole provides a useful performance optimization for large repositories while maintaining consistency across ref backends.
