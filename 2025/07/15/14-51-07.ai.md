Performance optimization converting commit traversal to use priority queues. This is the first of a 3-part series addressing quadratic complexity in commit list operations by replacing commit_list_insert_by_date() with a prio_queue implementation.

The patch focuses on pop_most_recent_commit(), which previously used O(n) insertion for each parent commit. The prio_queue replacement ensures O(log n) worst-case performance. Performance tests show dramatic improvements (92% faster) for pathological histories with many merges and root commits, though normal histories see a slight 1% regression due to prio_queue overhead.

Key technical details:
- Modifies pop_most_recent_commit() to take prio_queue instead of commit_list
- Updates callers in fetch-pack.c, object-name.c, and walker.c
- Adds new performance test t/perf/p1501-rev-parse-oneline.sh that creates a deep history
- Changes affect core commit handling but maintain backward compatibility
- Includes both microbenchmark results and real-world Git history measurements

The commit message clearly explains the tradeoffs between worst-case and best-case performance. Subsequent patches in the series will address the performance regression for normal cases.
