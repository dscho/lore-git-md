Performance optimization patch in the byte-swapping series, focusing on compiler optimizations.

This patch removes the x86-specific inline assembly implementation of bswap32/64 functions, relying instead on modern compilers to optimize the generic shifting implementations. The author shows through testing that compilers from gcc-4.5 onward (and clang-3.0 onward) can recognize the shifting patterns and generate the same efficient bswap opcode that the hand-written assembly would produce. The change simplifies the code by removing 40 lines of platform-specific implementation while maintaining performance.

The patch is part of a larger series (v3 4/5) standardizing byte-swapping operations across platforms. It follows the pattern of trusting compiler optimizations where possible, similar to how the series has handled other platforms. The change appears well-motivated with clear testing data showing equivalent optimization across multiple compiler versions and architectures (x86, arm64, MSVC, gcc, clang).

This continues the series' trend of removing redundant platform-specific code when general solutions work just as well. The change is low-risk since it's behavior-preserving - the same machine code should be generated, just via compiler optimization rather than explicit assembly. The thorough testing matrix provided gives confidence in the approach.
