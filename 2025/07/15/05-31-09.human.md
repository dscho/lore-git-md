This is a bug report and discussion about Git configuration behavior. Bryan Lee confirms that `pull.autostash` is not actually a valid Git configuration option (despite Git silently accepting it), and that the correct setting is `rebase.autostash` when using rebase-based pulls. The original report about bare repositories turns out to be a red herring - the issue occurs in regular repositories too.

The email raises two important points: First, that Git silently accepts invalid configuration keys without warning, which can lead to wasted debugging effort. Second, it suggests either adding warnings for invalid config keys or at least documenting common misconceptions like `pull.autostash` in the documentation.

The discussion appears to have resolved the immediate issue (using the correct config key works), but opens up a valid question about Git's config handling behavior that might warrant further discussion or changes to prevent similar confusion in the future.
