This is a brief discussion about extending the `--start-after` pagination feature to other Git commands. The thread follows a recently merged series that added efficient pagination support to `git for-each-ref`.

Christian Couder had suggested expanding the new `--start-after` option to `git branch` and `git tag` commands, since the underlying ref-filter infrastructure now supports it. Junio C Hamano responded that while technically straightforward, it may not be worthwhile for these interactive commands where users typically rely on pager tools rather than built-in pagination.

Karthik Nayak agrees with Junio's assessment that there's no strong need to expose this feature to the porcelain commands, even though the plumbing is now in place. The discussion confirms the pagination feature will remain focused on scripting use cases via `git for-each-ref`, with no plans to expand it to the interactive branch/tag commands. This appears to be the final decision on the matter, closing out the remaining open point from the feature's development.
