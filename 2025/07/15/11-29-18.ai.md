This is the first patch in a 7-part refactoring series moving MIDX tracking from global object database state to per-source storage in `struct odb_source`, part of the ongoing ODB abstraction effort for pluggable backends.

The patch introduces per-source MIDX tracking by adding a `midx` field to `struct odb_source` and refactoring `prepare_multi_pack_index_one()` to operate on a specific source rather than searching globally. The changes maintain backward compatibility by keeping the global linked list while transitioning to the new model - subsequent patches will fully remove the global infrastructure. Key technical changes include:
- Added `struct multi_pack_index *midx` field to `struct odb_source`
- Modified `prepare_multi_pack_index_one()` to take `struct odb_source` instead of repository+dir
- Updated cleanup paths in `clear_midx_file()` and `close_object_store()` to clear per-source MIDX pointers
- Kept global linked list maintenance for now (to be removed later)

The patch lays groundwork for the series by establishing the per-source storage while maintaining existing behavior. It addresses the architectural mismatch where MIDX files (which are source-specific) were tracked globally in the object database. The changes are mechanical with no behavior changes yet - the actual migration of callers to use per-source MIDX comes in later patches.
