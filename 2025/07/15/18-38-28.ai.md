This is a discussion about output format design for the new `git repo info` command, part of the ongoing feature implementation series. Justin Tobler responds to Patrick Steinhardt's suggestion about default human-readable output by proposing an alternative approach.

Justin argues against the current NUL-terminated default format, suggesting instead a simple `<key=value>` per-line format as the default, with `-z` flag for NUL-delimited output. This would align with existing Git conventions where `-z` typically enables machine-parsable output. He also proposes separating more decorated human-readable output into a potential future `git repo summary` subcommand, similar to `git-sizer`.

The email continues the thread's debate about output formats while introducing new considerations:
- Consistency with existing Git CLI patterns (`-z` flag convention)
- Separation of concerns between simple machine-readable data and decorated human output
- Potential future expansion points (`summary` subcommand)

This represents an important interface design decision point in the series, with Justin advocating for stronger alignment with Git's existing output format conventions rather than introducing new default behaviors. The suggestion to defer more complex output formatting to a separate subcommand also addresses concerns about the command's scope while keeping the initial implementation focused.
