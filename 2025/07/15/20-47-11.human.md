Performance optimization follow-up discussing René Scharfe's commit traversal improvements. Justin Tobler responds to the first patch in the series, which replaces commit_list with a prio_queue to improve worst-case performance from quadratic to log-linear time.

Justin confirms understanding of the change's motivation - that repeated list insertions in date order could lead to poor scaling with many merge commits. He notes the impressive 92% speedup shown in the pathological test case (50% merges/50% roots), while observing that normal histories see a minor 1% regression.

The response suggests it might be helpful to more explicitly document which repository structures benefit from the change, though acknowledges the patch already shows both the best and worst case scenarios. Justin also points out that while the original implementation required callers to maintain date ordering, the new version relies on proper prio_queue configuration by callers - a subtle but important behavioral note for maintainers.

This appears to be a straightforward technical clarification rather than raising any objections to the change itself. The discussion remains focused on understanding and potentially improving documentation of the optimization's tradeoffs.
