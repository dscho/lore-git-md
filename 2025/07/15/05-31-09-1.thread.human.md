Lidong Yan's patch to standardize auto-stash configuration in `git pull` has completed its review cycle and been approved for merging. The change establishes a clear three-level precedence system: command-line flags take highest priority, followed by the new `pull.autoStash` configuration, with operation-specific settings (`rebase.autoStash` or `merge.autoStash`) as defaults. This resolves a long-standing inconsistency where `merge.autoStash` wasn't properly respected during pull operations.

The implementation in `builtin/pull.c` introduces a `config_pull_autostash` variable and handles all configuration reading in one place. Accompanying the code changes are extensive tests (adding 60+ lines to t/t5520-pull.sh) that verify all combinations of flags and configurations, plus documentation improvements that better explain the behavior.
