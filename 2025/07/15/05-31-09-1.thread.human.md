This thread explores how Git should handle configuration keys that are silently ignored or invalid, with a focus on the undocumented `pull.autostash` setting. The discussion began by identifying the core problem: Git's config system currently accepts many keys without validation, leading to user confusion when settings appear to have no effect.

Lidong Yan initially proposed a comprehensive technical solution involving a registration system where Git subsystems would declare their valid configuration keys, addressing maintainer Junio Hamano's concerns about preserving extensibility for third-party tools. The proposal outlined two implementation approaches - direct API registration and external specification files.

Johannes Sixt (Hannes) then suggested a simpler alternative: improving documentation for specific problematic keys like `pull.autostash`, which currently appears in neither the `git-config` nor `git-pull` man pages despite being a valid setting. Lidong has now agreed that documentation updates should be the immediate solution for this particular issue, while keeping the door open for broader validation systems in the future.

The thread now presents parallel paths forward: targeted documentation improvements for known pain points versus architectural changes to enable systematic validation. While the registration system remains a viable long-term solution, there's growing recognition that better documentation can resolve many user-facing issues more quickly. The next steps will likely involve both updating the relevant man pages and continuing to refine the technical proposal for config validation.
