This is a design discussion about output formatting for the new `git repo info` command, part of Lucas Seiki Oshiro's GSoC project to create a repository inspection tool.

Justin Tobler responds to Patrick Steinhardt's suggestion about default output formats, proposing a different approach. Rather than defaulting to NUL-terminated output (as in the current patch) with a `--format=porcelain` option for scripts, Justin suggests making the default human-readable key=value pairs and using a `-z` flag for machine parsing, aligning with conventions from other Git commands. He also floats the idea of a future `git repo summary` subcommand for more decorated, human-oriented output.

The discussion touches on important interface design questions: balancing human usability with scriptability, following existing Git conventions, and planning for future extensibility. Justin's proposal would make the command more immediately useful for interactive use while maintaining machine-readability options.
