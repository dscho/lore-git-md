Performance optimization converting commit traversal to use priority queues.

This is the first of a 3-part series from René Scharfe that refactors commit traversal to use priority queues (prio_queue) for better worst-case performance. The change addresses quadratic complexity in `pop_most_recent_commit()` by replacing date-sorted commit lists with a priority queue, ensuring logarithmic worst-case behavior.

The patch shows dramatic improvements (92% faster) on pathological histories with many merges, though there's a small (1%) regression on normal histories. It includes a new performance test that creates a complex merge-heavy history to demonstrate the optimization. The changes touch core commit handling code in commit.c and several callers (fetch-pack, object-name, walker).

This appears to be a well-motivated change with thorough performance analysis and testing. The tradeoffs between best-case and worst-case performance are clearly documented. The patch maintains backward compatibility while addressing a known performance bottleneck in commit graph traversal.
