Performance optimization completing the prio_queue series. This final patch in René Scharfe's 3-part series recovers the 1% performance regression introduced in patch 1 by using the new `prio_queue_replace()` helper (added in patch 2) when processing commit parents in `pop_most_recent_commit()`.

The change replaces the sequence of `prio_queue_get()` + `prio_queue_put()` with `prio_queue_peek()` + `prio_queue_replace()` for the first parent, avoiding redundant heap rebalancing operations. Subsequent parents still use the standard put operation. Benchmark results show this brings performance back to parity with the original implementation (1.069s vs 1.073s for `rev-parse :/^Initial.revision`).

The implementation carefully maintains the same behavior while optimizing the common case where commits have exactly one parent (the typical case in Git histories). The change is localized to `commit.c` and builds on the infrastructure established in the previous patches. This completes the series' goal of improving worst-case performance (from quadratic to log-linear) while preserving best-case behavior.
