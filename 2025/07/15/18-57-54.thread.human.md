This thread addresses a test infrastructure fix for how `GIT_TEST_INSTALLED` interacts with hash algorithm detection in the Git test suite. The original patch from Kyle Lippincott corrects an inconsistency where some test paths weren't properly respecting the `GIT_TEST_INSTALLED` environment variable when determining the default hash algorithm, particularly noticeable when building with `WITH_BREAKING_CHANGES` (which switches the default hash from SHA-1 to SHA-256).

Junio C Hamano has already reviewed and approved the change, which introduces a `GIT_BINARY` variable in `t/test-lib.sh` to ensure consistent binary path usage throughout the test environment. The solution handles platform-specific considerations while maintaining test reliability. Justin Tobler's follow-up email provides additional technical context about the failure scenario and confirms the patch's correctness, noting it properly uses the stored binary path for both initial checks and hash detection. While the review approval is somewhat redundant given Junio's prior acceptance, it serves as useful validation of the solution's technical soundness. The patch is now queued for inclusion in the next integration cycle.
