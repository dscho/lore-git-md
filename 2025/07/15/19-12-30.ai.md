Performance optimization patch in the byte-swapping series, focusing on compiler built-ins for bswap operations.

This final patch in the v3 series reintroduces compiler built-in optimizations for byte swapping (bswap32/bswap64) when available, originally seen in an earlier commit (6547d1c9). The change is motivated by performance considerations on architectures like RISC-V and MIPS where manual shift operations would generate inefficient code sequences, while built-ins can call optimized functions instead.

The patch adds detection for `__builtin_bswap32/64` availability via `__has_builtin`, with a fallback definition for older compilers. When these built-ins are present, they're used directly rather than the default shift-based implementations. The implementation maintains compatibility across architectures, including big-endian systems where the optimization won't regress performance.

Key technical details:
- Adds compiler feature detection via `__has_builtin`
- Uses built-ins when available (Clang 10+/GCC 10+)
- Falls back to existing shift implementations otherwise
- Maintains behavior on all architectures
- Part of broader series standardizing byte-swapping operations
- Builds on previous work to remove platform-specific assembly

The change is behavior-preserving but aims to improve code generation efficiency, particularly on architectures where shift operations are expensive. This completes the series' transition from platform-specific optimizations to compiler-assisted approaches where possible.
