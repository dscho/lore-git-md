This is part 2/7 of Patrick Steinhardt's refactoring series to move MIDX tracking from global state to per-source storage in `struct odb_source`. The patch focuses on aligning packfile loading with the new per-source approach established for MIDX handling in the previous patch.

The key change refactors `prepare_packed_git_one()` to operate directly on an `odb_source` rather than searching for matching MIDX data by object directory path. The function now:
- Takes a `struct odb_source*` instead of repository/objdir parameters
- Directly uses the source's pre-loaded MIDX pointer (`source->midx`)
- Simplifies the data preparation by eliminating the MIDX search loop
- Maintains the same garbage collection behavior but with cleaner initialization

The patch demonstrates good mechanical refactoring discipline - it preserves all existing functionality while making the code more direct by leveraging the new per-source MIDX storage. The changes are focused and well-contained, touching only packfile.c with straightforward modifications to the pack preparation logic. This continues the series' pattern of methodically moving infrastructure from global to per-source handling while maintaining compatibility with the temporary global state that will be removed in later patches.
