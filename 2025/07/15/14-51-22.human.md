This is the second patch in René Scharfe's performance optimization series introducing a new helper for commit traversal. The patch adds a `prio_queue_replace()` function that combines the operations of removing and adding queue elements more efficiently than separate `get` and `put` calls.

The new function is specifically designed for commit history processing where we frequently pop a commit and immediately push its parents. By avoiding the full rebalancing that would happen with separate operations, it helps recover the slight performance regression (1%) noted in the first patch's normal-case scenarios. The implementation handles both priority-sorted and LIFO queue modes, with comprehensive unit tests added to verify the behavior.

This is a focused, well-tested change that builds on the first patch's conversion to priority queues. The commit message clearly explains the optimization opportunity and the patch includes tests for both the priority queue and stack modes of operation. The change is contained to the prio-queue implementation and doesn't affect callers yet - that optimization will come in the next patch.
