This is a follow-up discussion about the PCRE2 dependency handling in the meson build system, specifically regarding the default behavior on different platforms. Carlo Arenas points out a potential regression in Windows builds that wasn't previously considered in the thread.

The key technical detail is that changing the meson option from 'enabled' to 'auto' for PCRE2 doesn't automatically fall back to the subproject wrapper as previously thought - this means Windows builds that relied on this fallback would now fail unless explicitly built with `-Dpcre2=enabled`. This contrasts with the macOS case where the change was intended to gracefully handle broken system installations.

The email serves as a correction to earlier assumptions in the thread about how meson's 'auto' feature setting interacts with the subproject wrapper fallback mechanism. While the macOS solution is working as intended, this reveals a platform-specific side effect that needs consideration for Windows users. The thread had previously considered the technical solution complete, but this new information suggests the default behavior might need platform-specific adjustments or documentation updates.
