Junio C Hamano weighs in on the ongoing naming discussion for the new repository information command. This is part of the larger thread about implementing a new command hierarchy for repository metadata access.

The email is brief but significant as it comes from the Git maintainer. Junio suggests two alternative naming approaches: using "git repository" as the base command with "query" and "stat" subcommands, rather than the currently proposed "git repo". This directly addresses Oswald Buddenhagen's concern about collision with the established Google `repo` tool.

The suggestion maintains the subcommand structure (keeping "info" functionality under "query" and future "survey" under "stat") while avoiding the naming conflict. Junio doesn't strongly advocate for either option, presenting them as possibilities for consideration. The email doesn't resolve the naming debate but provides a concrete alternative that could satisfy both the desire for clear hierarchy and avoidance of tool conflicts.

This continues the thread's pattern of architectural decisions being mostly settled while naming remains an open question, with the maintainer now offering potential solutions. The technical implementation work continues in parallel with this naming discussion.
