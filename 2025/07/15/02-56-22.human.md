This is the final patch in a performance optimization series for Git's pathspec bloom filters, addressing a case where combined pathspecs were slower than separate invocations. The patch enables bloom filter optimization for multiple literal pathspecs by removing the previous restriction that blocked bloom filters when more than one pathspec was present.

The key change is modifying `forbid_bloom_filters()` to check each pathspec item individually rather than rejecting all multi-pathspec cases outright. This allows bloom filter usage when all pathspec items are literal, while still rejecting wildcards and non-literal magic bits. The implementation shows significant speedups - 1.33x faster in the Git repo and 7.5x faster in the LLVM repo for multi-pathspec queries.

The patch includes thorough test updates in t4216-log-bloom.sh to verify:
1. Bloom filters are now used for multiple literal pathspecs (like "-- file4 A/file1")
2. Results match between bloom-optimized and non-optimized pathspec queries
3. Bloom filters are still not used when any pathspec contains non-literal elements

This completes the series' goal of optimizing multiple-pathspexec performance through the new `struct bloom_keyvec` abstraction.
