This is the first patch in a two-part bugfix series addressing issues with comment character selection when `core.commentChar="auto"` during operations like rebase with conflicts. The patch specifically targets the immediate problem where Git incorrectly scans conflict markers (like "<<<<<<<") as candidate comment characters, which can cause these markers to appear in final commit messages.

The technical solution introduces a cutoff point in the character scanning logic using `ignored_log_message_bytes()` to prevent scanning the trailing conflict marker section of commit messages. This ensures Git preserves the original '#' comment character when conflict markers are present, rather than potentially selecting a different character that would cause the markers to be included in the final commit. The change is focused in `builtin/commit.c` with a new test case added to `t/t3418-rebase-continue.sh` that verifies the comment character remains '#' even with conflict markers present.

The patch represents a compromise between Chandekar's initial simpler solution and Phillip Wood's preferred config-parsing approach, now addressing both the immediate bug and some architectural concerns. The implementation maintains backward compatibility while fixing the regression introduced in commit a6c2654f83. The test case is optimized to reuse existing files and focuses specifically on verifying the comment character behavior during rebase operations with conflicts.

Key technical elements include:
- New cutoff calculation using `ignored_log_message_bytes()`
- Modified character scanning loop in `adjust_comment_line_char()`
- Preservation of '#' as comment character when conflict markers exist
- Test verification of comment character stability during rebase with conflicts
- Fixes regression from a6c2654f83 (rebase -m: fix --signoff with conflicts)

The patch appears well-crafted with clear motivation and appropriate test coverage, representing a focused solution to the immediate problem while setting up for the broader architectural changes proposed in patch 2 of the series.
