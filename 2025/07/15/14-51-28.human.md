Performance optimization completing a series to improve commit traversal efficiency. This third patch from René Scharfe applies the new `prio_queue_replace()` helper (introduced in patch 2) to `pop_most_recent_commit()`, recovering the 1% performance regression seen when the function was first converted to use a priority queue in patch 1.

The change replaces the previous `prio_queue_get()` + `prio_queue_put()` sequence with a more efficient `prio_queue_peek()` + `prio_queue_replace()` combination when handling the first parent commit. Benchmark results show this brings performance back to parity with the original implementation (v2.50.1) while maintaining the worst-case improvements from earlier in the series.

The implementation carefully handles both the first parent (using the new optimized path) and subsequent parents (falling back to the standard put operation). This completes the series' goal of optimizing commit traversal with priority queues while maintaining or improving performance across both normal and pathological cases. The change is focused and well-tested, building on the thorough test infrastructure established in earlier patches.
