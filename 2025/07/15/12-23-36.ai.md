This is a feature patch in the ongoing `git repo info` subcommand series, adding reference format detection capability. The patch introduces a new `references.format` field that reports whether the repository uses 'files' or 'reftable' reference storage, leveraging existing `git rev-parse --show-ref-format` functionality.

The implementation uses a table-driven field system with sorted argv handling and duplicate filtering. Karthik Nayak's review suggests moving formatting logic to `print_fields()` for better separation of concerns and future format flexibility. He also recommends removing the explicit 'files/reftable' documentation to avoid future maintenance burden when new formats emerge.

The patch includes comprehensive tests verifying both reference formats and duplicate key handling. Karthik notes the usage string update should likely have been in the previous commit. The implementation appears solid but could benefit from the suggested refactoring to centralize output formatting.

Key technical details for future reference:
- Adds `references.format` field outputting canonical names ('files'/'reftable')
- Uses `ref_storage_format_to_name()` for format detection
- Implements sorted argv handling with `qsort_strcmp()`
- Includes duplicate key filtering
- Test coverage for both formats and duplicate requests
- Output uses null-terminated format matching Git conventions
- Field system designed for extensibility with new fields
