This is the first patch in a 7-part refactoring series that moves MIDX (multi-pack index) tracking from global object database state to per-source storage in `struct odb_source`. The change is part of a larger effort to abstract the object database for pluggable backends.

The patch introduces a new `midx` field in `struct odb_source` to store MIDX data, while maintaining the existing global linked list as a transitional step. The key changes include:
- Modifying `prepare_multi_pack_index_one()` to operate on a specific source rather than searching globally
- Updating cleanup paths in `clear_midx_file()` and `close_object_store()` to handle the per-source MIDX pointers
- Adding the new field to `struct odb_source` with documentation about its restricted access

The commit message clearly explains the motivation: MIDX files are fundamentally tied to individual object sources (like alternate directories) rather than being a global concern, and this mismatch makes some operations awkward. The change also better aligns with potential future pluggable backends where MIDX may not be relevant.

This appears to be a well-constructed first step in the series, with clean separation of concerns and clear documentation. The patch maintains backward compatibility while setting up for the global state removal in later patches. Reviewers Taylor Blau and Justin Tobler have already provided positive feedback on the overall approach in previous iterations.
