This is a refactoring and platform compatibility patch series focused on improving byte-swapping operations in Git's codebase. The series continues work on optimizing how Git handles ntohl() and related functions across different platforms and compilers.

The main motivation is to simplify and standardize byte-swapping operations while maintaining performance. The author notes that modern compilers (gcc/clang) can optimize manual shifting operations into efficient opcodes, making Git's custom implementations less necessary. The series specifically addresses musl libc's function-call implementation of ntohl() and Windows' lack of ntohll() in winsock.h.

Key technical changes include:
- Adding __BYTE_ORDER__ support for better compiler compatibility
- Explicitly defining endianness for MSVC
- Standardizing ntohl/ntohll macro definitions across platforms
- Removing x86-specific optimized bswap implementations
- Providing compiler-based bswap implementations where possible

The series touches only compat/bswap.h, modifying 114 lines with a net reduction of 18 lines. The author notes that put/get_be*() macros are left unchanged as compilers already optimize them well, except for MSVC which still struggles with byte operations. This appears to be a well-motivated cleanup that builds on previous discussion (referencing v2->v3 changes) and focuses on making the code more maintainable while preserving performance characteristics.
