Configuration validation proposal - Lidong Yan suggests adding a `git config verify` subcommand to help users detect invalid configuration settings like the non-functional `pull.autostash` key discussed in this thread. This builds on the earlier discussion about Git silently accepting but ignoring certain configuration keys, which Bryan Lee had identified as a source of user confusion.

The proposed solution would introduce a new verification mechanism separate from the existing config system behavior. Unlike Bryan's suggestions of either warning on invalid keys or improving documentation, Lidong's approach would provide an explicit tool for users to validate their configuration without changing how Git handles invalid keys during normal operation.

Key technical aspects:
- New subcommand would presumably scan config files and validate keys against known options
- Would need to handle both core Git options and extension/plugin configurations
- Could potentially integrate with existing config machinery in `config.c`

This represents a shift from reactive solutions (warnings/documentation) to proactive validation. The proposal doesn't specify whether this would be a read-only verification or include automatic correction capabilities. The thread continues exploring different approaches to the underlying configuration usability issue, with this being the first concrete implementation suggestion beyond documentation changes.
