This is a refactoring patch that clarifies and extends the behavior of the `ref_iterator_seek()` function in Git's ref iteration API. The patch introduces a new `REF_ITERATOR_SEEK_SET_PREFIX` flag to distinguish between two distinct operations that were previously conflated in the API: seeking to a specific reference versus setting an iteration prefix.

The key changes are:
1. Adding a flags parameter to `ref_iterator_seek()` with `REF_ITERATOR_SEEK_SET_PREFIX` to explicitly control whether the operation should set a new prefix (old behavior) or just seek to a position (new behavior)
2. Implementing the new seek-without-prefix behavior across all ref backends (files, packed, reftable)
3. Extracting prefix-setting logic into a separate `cache_ref_iterator_set_prefix()` function in the files backend
4. Updating all callers and documentation to use the new API

The patch maintains backward compatibility while making the API's behavior more predictable and better documented. It's part of the v5 series adding pagination support to `git for-each-ref` via `--start-after`, where this refined seek behavior enables efficient O(log N) pagination across all ref backends. The implementation handles edge cases like concurrent ref modifications and properly clears previous prefix state when doing non-prefix seeks. Test coverage is expanded to verify the new behavior.
