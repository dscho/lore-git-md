This is patch 4/7 in Patrick Steinhardt's series refactoring MIDX handling to work per-source rather than globally, part of the ongoing ODB abstraction effort. The patch focuses on `get_multi_pack_index()`, converting it from returning a global linked list to operating on individual `struct odb_source` instances.

Key technical changes:
- `get_multi_pack_index()` now takes a `struct odb_source*` parameter instead of a repository
- Callers must now explicitly iterate through sources (including alternates via `odb_prepare_alternates()`) rather than getting all MIDXs at once
- The function `get_local_multi_pack_index()` is removed as redundant since callers can check the `local` flag on the returned MIDX
- Multiple call sites are updated to use the new per-source iteration pattern, including in pack-objects, repack, midx-write, object-name resolution, and bitmap handling
- The lookup logic in `lookup_multi_pack_index()` is simplified to use `odb_find_source()`

The changes maintain the same behavior while removing global state access patterns. The patch touches several key subsystems that interact with MIDX files, demonstrating the wide impact of moving from global to per-source MIDX tracking. All changes appear mechanical and consistent with the series' goal of eliminating global MIDX infrastructure.
