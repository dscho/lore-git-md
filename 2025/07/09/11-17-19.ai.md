This is part 9/19 of Patrick Steinhardt's series refactoring object-file.c for pluggable loose object backends, continuing the `the_repository` removal effort. The patch introduces a new backend-agnostic interface `odb_write_object()` for writing objects to the object database, replacing direct calls to `write_object_file()` which was specific to the loose object format.

The new function currently just wraps `write_object_file()` and doesn't yet use the passed-in object database parameter, but sets up the infrastructure for future patches that will make it backend-aware. The patch updates 21 files (106 insertions, 67 deletions) to use the new interface, including core commands like `git commit`, `git tag`, and `git merge` as well as internal APIs like the notes and cache-tree subsystems.

Key technical details:
- Introduces `odb_write_object()` and `odb_write_object_ext()` in odb.h
- Moves write flags (`WRITE_OBJECT_PERSIST` and `WRITE_OBJECT_SILENT`) from object-file.h to odb.h
- Updates all callers of `write_object_file()` and `write_object_file_flags()`
- Maintains existing behavior while changing the interface
- Touches object writing paths across various subsystems
- Prepares for future backend-specific write implementations

The change is mechanical but widespread, systematically replacing the old loose-object-specific write interface with the new backend-agnostic one. This continues the pattern seen in earlier patches of the series where global dependencies are removed incrementally while maintaining existing behavior.
