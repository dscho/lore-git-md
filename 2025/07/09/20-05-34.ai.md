This is a discussion about the relationship between the new `git repo-info` command and Justin Tobler's proposed `git-survey` tool, focusing on command namespace organization and output format considerations.

Justin clarifies that `git-survey` is intended as a future replacement for `git-sizer`, with an initial plaintext key-value output format and eventual support for human-friendly tables. He explores whether to integrate survey functionality into `repo-info` via a `--stats` flag or keep it as a separate subcommand under a shared `git repo` namespace. The discussion reveals two key constraints: (1) `git-survey` operations are computationally expensive compared to `repo-info`'s metadata queries, and (2) `git-survey` needs specialized presentation formats that may not align with `repo-info`'s JSON structure.

The email confirms Patrick Steinhardt's earlier position that the tools should share a namespace (`git repo info` and `git repo survey`) but maintain separate implementations. Justin suggests `git-survey` could become a porcelain frontend that uses `repo-info` internally, while keeping the computationally intensive operations optional. This builds on the thread's emerging consensus about namespace organization while addressing performance concerns about combining the tools' functionality. The discussion remains open about how to handle output format consistency between the commands.
