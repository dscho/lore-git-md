This is the fifth patch in an 8-part refactoring series moving MIDX (multi-pack index) tracking from global state to per-source storage, part of the larger effort to enable pluggable object database backends.

The patch refactors `get_multi_pack_index()` to operate on individual object sources rather than returning a global linked list. Callers now need to explicitly iterate through alternates when checking for objects, which better matches the actual on-disk organization of MIDX files. The changes touch several key areas including pack-objects, repack, and bitmap handling, updating them to use the new per-source approach.

The conversion appears thorough, with careful updates to all MIDX-related functions. The patch maintains backward compatibility during the transition by keeping the preparation of packed git objects. This continues the series' methodical approach - each patch tackles a specific aspect of the MIDX migration while keeping the code functional at each step.

The changes are fairly mechanical but important for the architectural goal of properly associating MIDX files with their corresponding object sources. The patch series is building toward Patrick Steinhardt's larger object database backend work, with this being one of the foundational cleanups needed for that effort.
