Bugfix for a leak in reflog expiration configuration handling. This patch addresses a memory leak in `reflog_expire_config()` where a `struct reflog_expire_entry_option` allocated via `FLEX_ALLOC_MEM` was not being freed. The leak was detected by ASAN and shows a 39-byte allocation that persists through the config parsing and reflog expiration process.

The fix is straightforward - adding a `free(ent)` call before returning from `reflog_expire_config()`. The patch notes this properly cleans up both the structure and its embedded pattern array due to the use of `FLEX_ALLOC_MEM`. The change is minimal (just 3 lines added) and focused specifically on fixing this leak without introducing any other changes.

The commit message provides clear evidence of the leak via ASAN output showing the allocation stack trace, making the problem and solution easy to verify. This appears to be a well-contained fix for a real issue, though it's worth noting the patch doesn't include a test case to prevent regression. The change touches core reflog functionality but is low-risk since it only adds cleanup code without modifying any behavior.
