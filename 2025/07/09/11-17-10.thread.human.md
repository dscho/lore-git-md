Patrick Steinhardt continues his series refactoring Git's object-file handling to remove dependencies on `the_repository` global variable, preparing for pluggable object backends. The third patch in this 19-part series focuses on object existence checks, modifying `has_loose_object()` to work with specific object sources rather than implicitly checking all sources through the global state.

The changes introduce a more explicit model where callers must now iterate through object sources themselves when checking for loose objects. This affects `pack-objects` in particular, which previously relied on the implicit global behavior. While the patch maintains the same external functionality, it represents a semantic shift in how object existence is checked internally - a necessary step toward the larger goal of making the object database pluggable.

This work builds on René Scharfe's long-running `the_repository` removal effort, with Steinhardt focusing specifically on the object-file subsystem. The series follows an incremental approach, carefully maintaining backward compatibility while systematically eliminating global state dependencies. Each patch tackles a specific area of functionality, with this one addressing the core object existence checking paths. The changes are mechanical but require careful handling of the call sites, particularly in performance-sensitive areas like `pack-objects`.
