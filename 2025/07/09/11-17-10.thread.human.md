Patrick Steinhardt continues his systematic refactoring of Git's object storage layer with part 18 of his series, now tackling the object creation mode configuration. This patch moves the `core.createobject` setting from a global variable to repository-specific storage, following the pattern established in previous patches.

The change affects how Git handles object placement during write operations, maintaining the existing behavior (defaulting to hardlinks when unconfigured) while properly scoping the configuration to each repository. The implementation is clean and focused, removing the global `object_creation_mode` variable and updating the relevant functions to use the repository-specific setting instead.

This patch represents another incremental step in the larger effort to eliminate global state from Git's object storage layer. The series has now addressed compression levels (part 17) and object creation modes (part 18), with each change following a consistent pattern of moving configuration into `repo_settings` while preserving all existing behavior. The changes are narrowly focused and maintain backward compatibility, demonstrating the careful, methodical approach that has characterized this long-running refactoring effort.
