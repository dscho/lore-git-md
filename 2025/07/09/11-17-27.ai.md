Continuing the `the_repository` removal effort, this patch moves compression level settings from global variables into repository-specific settings. This is part of Patrick Steinhardt's series preparing for pluggable loose object backends.

The patch eliminates two global variables (`zlib_compression_level` and `pack_compression_level`) and their configuration handling from `config.c`, moving them into the `repo_settings` struct. The new settings are initialized in `repo-settings.c` with the same logic as before, including handling of the three relevant config options (`core.compression`, `core.loosecompression`, and `pack.compression`). The patch carefully maintains backward compatibility while converting all compression initialization calls to use the repository-specific settings.

A notable complexity is in `builtin/pack-objects.c` where the compression level can be overridden via command line. The solution uses `INT_MIN` as a special value to detect when no command-line override was provided, since any valid compression level must be between -1 and `Z_BEST_COMPRESSION`. The changes affect multiple commands including fast-import, index-pack, pack-objects, bulk-checkin, and http-push, all of which now initialize compression using repository settings.

This change follows the series' pattern of systematically removing global state while maintaining existing behavior. It touches core object writing paths but doesn't introduce new functionality or change compression behavior - it relocates where the settings are stored. The patch demonstrates how repository-specific configuration should flow through the system rather than relying on globals.
