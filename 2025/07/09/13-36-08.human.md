Performance-focused response to ref command consolidation discussion. Patrick Steinhardt weighs in on the proposed `git refs list` subcommand, agreeing with Junio Hamano's concerns about command proliferation but highlighting a specific performance pain point with `git-for-each-ref`'s default format. 

The key issue is that the current default format includes `%(objecttype)`, which forces unnecessary object database lookups. Steinhardt provides concrete data from the Chromium repository showing a 6.65x speedup when using a simpler format that omits object type resolution. While supporting the idea of shared infrastructure for most options, he suggests this particular default behavior should be reconsidered for any new ref-listing command.

This moves the discussion forward by identifying a measurable performance optimization opportunity while still aligning with the maintainer's preference for unified behavior. The benchmarks provide concrete evidence that could inform either a wrapper implementation or (if the new command proceeds) its default configuration. The thread remains focused on balancing discoverability, performance, and maintenance concerns.
