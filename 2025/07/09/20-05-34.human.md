This is a discussion about the relationship between the new `git repo-info` command and Justin Tobler's proposed `git-survey` tool, as part of the ongoing GSoC project to add repository metadata capabilities.

Justin clarifies that `git-survey` is intended as a future replacement for `git-sizer`, with a focus on repository statistics and size information. He proposes two possible integration approaches with `repo-info`: either adding a `--stats` flag to append survey data to `repo-info`'s output, or keeping them as distinct subcommands under a common `git repo` namespace (e.g., `git repo info` and `git repo survey`).

The key points of consideration are:
1. Performance - survey operations are computationally expensive compared to basic metadata queries
2. Output formats - survey needs both machine-readable and human-friendly presentations
3. Command scope - whether to combine the tools or keep them separate but related

Justin leans toward having `repo-info` handle the machine-readable data collection while `git-survey` could serve as a porcelain frontend. The discussion shows healthy consideration of both technical constraints (performance characteristics) and user experience (output formats and command organization). The emerging consensus appears to favor the `git repo` namespace approach while maintaining some separation between the metadata and statistics functionalities.
