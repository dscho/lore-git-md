This is a follow-up discussion in Patrick Steinhardt's Meson build system improvement series, specifically about Python detection in the build process. Justin Tobler responds to Junio Hamano's concern about how `find_program()` handles Python installations where Python 3 might be named simply "python" rather than "python3".

The discussion clarifies that the Meson build system's `find_program()` won't automatically handle cases where Python 3 is installed as `/usr/bin/python` without being a symlink to `python3`. Justin notes that such cases would likely require explicit definition in a cross-file. He also confirms Junio's reading of Meson's documentation - that the fallback to the build interpreter only applies to build-time Python scripts, not the target system's runtime Python needed for git-p4.

This exchange shows the series maintainers carefully considering edge cases in the Python detection logic, though the core approach (only checking for target Python since it's only needed for git-p4) remains sound. The thread context indicates this was one of the final points being resolved before the series could be merged.
