This is part 18 of Patrick Steinhardt's series to eliminate `the_repository` global, specifically targeting the object creation mode configuration. The patch moves the `core.createobject` config setting from a global variable to repository-specific storage in `repo_settings`.

The change affects how Git handles final object placement during write operations, switching between hardlinks and renames based on configuration. The patch:
1. Removes the global `object_creation_mode` variable and its declarations
2. Adds the setting to `struct repo_settings` with the same enum values
3. Moves config parsing from `config.c` to `repo-settings.c`
4. Updates `finalize_object_file_flags()` to use the repository-specific setting
5. Maintains the same default behavior (hardlinks) when unconfigured

The implementation follows the pattern established in previous patches of the series, using `prepare_repo_settings()` to initialize the value. Like earlier changes, this maintains existing behavior while moving configuration into the proper repository context. The patch touches core object writing functionality but is narrowly focused on the configuration aspect.
