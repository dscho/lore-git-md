This is part 3/19 of Patrick Steinhardt's series refactoring object-file.c to remove `the_repository` dependencies, continuing the broader effort to enable pluggable loose object backends. The patch focuses on `has_loose_object()` and related functions.

The key change is making `has_loose_object()` operate on a specific `odb_source` rather than checking all object sources implicitly. This requires callers to explicitly loop through sources when they want to check all possible locations. The patch also removes the now-obsolete `has_loose_object_nonlocal()` function, adapting its sole caller in pack-objects.c to use the new approach.

The change appears well-motivated as part of the larger architectural shift toward repository-specific object handling. The implementation looks clean, with straightforward adaptations to the affected call sites. The commit message explains the seemingly backwards-incompatible change by framing it as preparation for a future generic `odb_source_has_object()` function.

This is a mechanical but important step in the series, touching core object existence checking logic while maintaining external behavior. The changes are limited to three files and follow the pattern established in earlier patches of the series.
