This is a bugfix patch addressing a memory leak in the reflog expiration code. Jacob Keller identifies that `find_cfg_ent()` allocates `reflog_expire_entry_option` structs that are never freed, causing leaks during both manual reflog expiration (`git reflog expire`) and automatic garbage collection. The leak was detected via ASAN (AddressSanitizer) showing a 39-byte allocation.

The fix introduces a new `reflog_clear_expire_config()` function to properly free these allocations, calling it at exit points in both `cmd_reflog_expire()` and `reflog_expiry_cleanup()`. This is version 2 of the patch, with Jacob acknowledging Jeff King's review that helped correct an earlier attempt.

The change is straightforward - adding cleanup logic for a clear memory leak - and touches three files: `reflog.h` for the new function declaration, and both `builtin/reflog.c` and `reflog.c` for the implementation and call sites. The patch appears well-targeted and properly motivated, with the ASAN trace providing evidence of the issue.
