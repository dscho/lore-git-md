This is the first patch in v4 of the `git last-modified` feature series, introducing a new plumbing command to track when paths were last modified in a repository's history. The command works similarly to `git blame` but operates at tree-level rather than line-by-line.

The implementation centers around a `last_modified_entry` struct that tracks paths and their object IDs, using a hashmap for efficient lookups. The core algorithm walks backwards through history using revision walking infrastructure, comparing tree states to identify when each path last changed to its current state. The command supports recursive operation (`-r` flag) and can optionally show tree entries themselves (`-t` flag).

Key technical details:
- New files: `builtin/last-modified.c`, `Documentation/git-last-modified.adoc`, test script `t/t8020-last-modified.sh`
- Core data structure: `struct last_modified` with hashmap of `last_modified_entry` items
- Path comparison logic in `mark_path()` handles various diff cases (deletions, renames, etc.)
- Standard `parse_options()` interface with `-r`/`-t` flags
- Comprehensive test coverage including:
  - Basic file/directory cases
  - Merge scenarios
  - Pathspec handling
  - History limiting

The patch appears well-structured with thorough documentation and follows Git's established patterns for new commands. It builds on previous iterations of the series (originally called `blame-tree`) that have already addressed several rounds of review feedback. The implementation is now consolidated into a single file with proper memory management and standard command-line parsing.
