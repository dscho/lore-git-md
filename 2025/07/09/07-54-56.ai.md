This is the final patch in a refactoring series moving MIDX tracking from global state to per-source storage, part of the ongoing object database backend abstraction work.

The patch removes the now-unused global linked list of multi-pack indices from `struct object_database` and related infrastructure, completing the transition to per-source MIDX storage. Key changes include:
- The `next` pointer from `struct multi_pack_index`
- The `multi_pack_index` field from `struct object_database`
- All remaining code paths that maintained the global structures
- Cleanup operations that previously handled the global state

The diff shows straightforward removal of now-dead code, with the most significant change being the simplification of `prepare_multi_pack_index_one()` which no longer needs to maintain the linked list. The patch maintains all existing functionality while eliminating the global state, achieving the series' goal of better matching MIDX organization to their on-disk representation in preparation for pluggable backends.

This concludes the technical work of the series, having methodically migrated all MIDX handling to the per-source model while maintaining backward compatibility. The changes touch core packfile/MIDX code in `midx.c`, `midx.h`, `odb.h` and `packfile.c`, with the removal of 24 lines of now-unnecessary code.
