Performance-focused critique of the proposed `git refs list` subcommand's default behavior. Patrick Steinhardt identifies a significant performance issue with `git for-each-ref`'s default format requiring object type resolution, demonstrating a 6.65x speed difference in the Chromium repository when omitting `%(objecttype)`. While agreeing with maintainer Junio C Hamano's position on shared infrastructure and avoiding divergence, Steinhardt argues this specific default warrants reconsideration for the new subcommand given its real-world impact on large repositories.

The email provides concrete benchmarking data showing the current default format (`%(objectname) %(objecttype)\t%(refname)`) takes ~150ms versus ~22ms when simplified to `%(objectname) %(refname)`. This performance gap stems from unnecessary ODB lookups to determine object types when only refnames are typically needed. Steinhardt positions this as an exception to the general wrapper approach, suggesting the new command could improve upon this specific default while maintaining parity for all other options.

This introduces a new technical consideration to the thread's ongoing discussion about command consolidation - whether performance optimizations justify controlled divergence in default behaviors when the underlying ref-filter infrastructure remains shared. The Chromium repository benchmark provides concrete data supporting the optimization claim, though it remains to be seen whether this will sway the maintainer's preference for strict behavioral parity.
