This is the final patch in the v4 series implementing the `git last-modified` command, adding Bloom filter support to optimize performance. The patch builds on the established infrastructure from previous versions, now leveraging changed-path Bloom filters when available to avoid unnecessary diff computations during the revision walk.

The implementation adds Bloom filter checks through a new `maybe_changed_path()` helper function that consults the commit-graph's Bloom filters before computing diffs. When filters indicate no possible changes to tracked paths, the expensive diff operation is skipped. The patch components include:
- Bloom key management for tracked paths via `fill_bloom_key()` and `clear_bloom_key()`
- Integration with the commit-graph Bloom filter settings
- Memory management for Bloom keys in `last_modified_release()`
- The core optimization logic in `maybe_changed_path()`

Performance results show significant improvements in the non-recursive case (50% faster for top-level checks, 36% for subdirectories), though recursive mode sees minimal change as expected since it must still examine all paths. The implementation gracefully falls back to full diff computation when Bloom filters are unavailable.
