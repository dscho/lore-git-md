This is a discussion about the behavior of the new `git last-modified` plumbing command, specifically regarding how it handles directory paths compared to `git ls-tree`. The command is part of an ongoing series that has evolved through multiple versions with extensive review.

Toon Claes responds to Kristoffer Haugsbakk's observation that `git last-modified` shows different output than `git ls-tree` when given the same paths. While acknowledging the discrepancy, Toon argues for keeping the current behavior because:

1. It matches `git diff-tree`'s output (both are plumbing commands, unlike `ls-tree`)
2. The implementation relies on diff machinery, making behavior changes non-trivial
3. Future work could add a `--max-depth` option for more control over directory traversal

The message references a new version of the patches that maintains this behavior while addressing other feedback. This appears to be a deliberate design choice rather than an oversight, with the command aligning itself with similar plumbing commands rather than porcelain ones. The discussion shows the careful consideration being given to the command's behavior as it nears completion.
