This is part 3/19 of Patrick Steinhardt's series to remove `the_repository` usage from object-file.c, continuing the broader `the_repository` removal effort. The patch refactors `has_loose_object()` to operate on a specific `odb_source` rather than implicitly checking all sources via `the_repository`.

Key changes:
- Replaces `has_loose_object()` with a version that checks a single specified `odb_source`
- Makes `has_loose_object_nonlocal()` obsolete by having callers explicitly loop through non-primary sources
- Updates `pack-objects.c` to manually iterate through object sources when checking for loose objects
- Modifies `force_object_loose()` to check all sources sequentially
- Introduces a semantic change where existence checks are source-specific rather than database-wide

The patch affects core object existence checking logic, particularly in `pack-objects` where it now requires explicit iteration over object sources. This is part of the larger transition toward pluggable object backends by removing implicit global state dependencies. The changes are mechanical but require careful handling of the object source iteration pattern in calling code.
