Feature implementation for a new `git last-modified` command, version 4 of the series that has been through several rounds of review. This cover letter explains the evolution from GitHub's original `blame-tree` prototype to the current state, with key changes including:

1. Renamed from `blame-tree` to `last-modified` based on community feedback
2. Removed several performance optimization patches that showed inconsistent results (some tests 55% faster, others 44% slower)
3. Consolidated implementation into `builtin/last-modified.c` rather than split between library and command code
4. Added proper `parse_options()` handling and help text
5. Fixed memory leaks and removed `USE_THE_REPOSITORY_VARIABLE`

The command shows when files were last modified in a commit, with `-r` for recursive directory traversal and `-t` to include tree entries. Bloom filters provide 36-50% speedups in non-recursive mode with minimal impact on recursive traversals. The implementation uses a hashmap of `last_modified_entry` structs with Bloom filter support (`bloom_key` field) and `maybe_changed_path()` helper for filter checks.

- New `builtin/last-modified.c` with core implementation
- Documentation in `Documentation/git-last-modified.adoc`
- Tests in `t/t8020-last-modified.sh` and `t/perf/p8020-last-modified.sh`

Open issues from previous reviews now addressed:

- Command-line parsing uses standard `parse_options()`
- Memory leaks fixed
- Code organization simplified

The series appears ready for final review with core functionality complete, good test coverage, and most interface questions resolved. Performance characteristics are documented with both improvements and regressions clearly noted where optimizations were removed.
