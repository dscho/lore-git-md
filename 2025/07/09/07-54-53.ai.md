Refactoring patch in a series moving MIDX tracking from global to per-source storage. This is patch 5/8 in v1 of the series.

The patch refactors `get_multi_pack_index()` to operate on individual `struct odb_source` instances rather than returning a global linked list. This continues the architectural shift from tracking MIDX files globally to associating them with their respective object database sources. Key changes include:

- Removes the repository-level `get_multi_pack_index()` and `get_local_multi_pack_index()` functions entirely
- Introduces a new `get_multi_pack_index(source)` that returns just the MIDX for a single source
- Updates all MIDX-using callers to iterate sources themselves and handle alternates properly
- Touches 7 files with mechanical but widespread changes to MIDX access patterns
- Requires callers to explicitly prepare alternates before iteration

The changes are straightforward mechanical conversions following the pattern established in earlier patches. Each caller now handles its own source iteration, with the common `odb_prepare_alternates()` call added where needed. The patch maintains consistency with the series' goal of moving MIDX tracking to be source-local while preserving all existing functionality.

This continues the careful, incremental approach seen in previous patches - each step focuses on one logical piece of the transition from global to per-source MIDX handling. The changes are extensive but appear to be well-contained within the established refactoring pattern.
