This thread discusses Patrick Steinhardt's 8-patch series refactoring MIDX (multi-pack index) tracking to move from global state to per-source storage, a key step in enabling pluggable object database backends. The series has drawn detailed technical reviews from Taylor Blau and Justin Tobler.

The core change removes all global MIDX infrastructure, attaching MIDX state to individual `struct odb_source` instances instead. This better reflects that MIDX is fundamentally a packfile optimization rather than an object-database-level concern. The latest discussion focuses on patch 4/8, which introduced a `multi_pack_index_loaded` flag per source. Reviewers questioned whether this flag was strictly necessary given the existing global `packed_git_initialized`, with Taylor speculating it might be preparatory work for future global state removal. 

While the implementation is technically correct, the exchange reveals reviewers seeking clarity about which state-tracking mechanisms are transitional versus permanent in this architectural shift. The series has already addressed all prior feedback and builds cleanly, with the final patch successfully removing all transitional compatibility code. This represents an important milestone in the ongoing object database abstraction effort, resolving interactions with recent cruft pack/MIDX work while following established refactoring patterns from earlier ODB preparation.
