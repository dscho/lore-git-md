Feature proposal for gitk: Visual indication of remote tag status.

Adi Shavit proposes adding visual cues in gitk to distinguish between local tags and those that exist on remotes. Currently, gitk shows all tags in a single list without indicating their publication status, unlike branches which clearly separate between local and remote-tracking. This can lead to confusion where users might assume a local-only tag has been shared with collaborators.

The proposal suggests three possible UI approaches: adding remote names in parentheses after tags (e.g., "v1.2.3 (origin)"), using different colors similar to branch display, or showing remote information in tooltips. The change would be opt-in to maintain backward compatibility.

The motivation is to maintain gitk's strength as an at-a-glance history viewer while preventing common workflow mistakes where users forget to push tags. The proposal is well-considered, with clear problem statement and multiple implementation options presented for discussion. The change would be particularly useful for teams coordinating releases via tags.
