Performance optimization for the new `git last-modified` command. This final piece in the v4 series adds Bloom filter support to skip unnecessary diff computations during the revision walk. When changed-path Bloom filters are available (from the commit-graph), the command first consults them to see if a commit might have modified any paths of interest before computing the full diff.

The patch shows significant speedups in benchmarks: a 50% reduction in runtime for top-level queries and 36% for subdirectory checks. The recursive mode sees minimal impact since it must still compute diffs for directory contents. The implementation carefully handles Bloom filter setup/teardown and falls back gracefully when filters are unavailable.

This completes the performance optimization work for the series, leaving only minor architectural questions about command delegation patterns as the last open item before potential merging. The patch builds on Taylor Blau's Bloom filter work and maintains the clean memory management established in earlier revisions.
