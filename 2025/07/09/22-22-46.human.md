This is a follow-up discussion in the Meson build system improvement series, specifically addressing Python detection concerns raised by Junio Hamano.

Eli Schwartz provides additional context on Python version naming conventions to alleviate concerns about the `find_program('python3')` approach used in Patrick Steinhardt's patch. The key points:

1. The patch maintains the existing behavior of explicitly looking for `python3` rather than just `python`, which Eli strongly endorses as the correct approach given Python's versioning history.

2. Eli explains the historical context of Python naming, noting that `python3` has been the reliable name since Python 3.x was introduced, while `python` could point to either 2.x or 3.x depending on the system.

3. He asserts it's effectively impossible to have a system where `python` points to Python 3 while `python3` doesn't exist, making the patch's approach robust.

4. For cross-compilation scenarios, Eli notes the proper solution is to specify the target Python interpreter in the cross env setup, just as one would specify the target C compiler.

This email doesn't propose any changes to the patch but provides authoritative confirmation that the approach taken is correct and addresses Junio's concerns about edge cases. The explanation comes from someone with deep Python packaging expertise (Gentoo maintainer), lending weight to the technical assessment.
