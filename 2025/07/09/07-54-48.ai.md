This is a refactoring patch series that reorganizes how multi-pack-indices (MIDX) are tracked in Git's object database implementation. The series moves MIDX tracking from being a global property of the object database to being associated with individual object sources, which better matches their actual on-disk organization and prepares for future pluggable backends.

The cover letter explains two key problems with the current approach: (1) MIDX files are per-source but tracked globally, creating an awkward mismatch, and (2) MIDX is a packfile-specific optimization that shouldn't be exposed at the object database level. The series refactors the code to attach MIDX data to `struct odb_source` instead, removing the global linked list of MIDX files and updating all related functions to work with the new organization.

The changes touch core packfile and MIDX handling code across 10 files, with significant modifications to `packfile.c` and `midx.c`. The series builds on recent work in the object store area and appears to be a well-motivated cleanup that simplifies the code while better matching the actual data organization. The commit messages and cover letter provide clear rationale for each change, suggesting this is a thoughtful refactoring rather than a superficial reorganization.
