This is a feature patch series introducing a new `git last-modified` command, version 4 of a previously proposed `git blame-tree` command. The command shows when files were last modified by walking through commit history.

The series comes from Toon Claes, who has built upon work originally shared by Taylor Blau and others at GitHub. Key changes in this version include:

1. Renaming from `blame-tree` to `last-modified` based on mailing list consensus
2. Moving all implementation into `builtin/last-modified.c` (previously split across files)
3. Adding proper `parse_options()` usage for better help messages
4. Implementing Bloom filter support (showing 36-50% speedups in benchmarks)
5. Fixing memory leaks and removing `USE_THE_REPOSITORY_VARIABLE`

The command has two main modes:
- Non-recursive (default) shows when directories themselves were modified
- Recursive (`-r`) shows individual file modifications

Performance tests show significant speedups from Bloom filters (50% faster for top-level checks) with minimal impact on recursive traversals. The implementation appears thorough, with good test coverage and documentation.

This version addresses several previous review comments while deferring some features (like caching and max-depth support) to future series. The path handling behavior has been clarified to match `git ls-tree` conventions, fixing a bug where non-recursive mode incorrectly showed directory contents rather than the directory entry itself.

The series looks production-ready aside from two remaining interface design questions about command-line parsing architecture and adding a help flag. These appear to be the last major items before the command could graduate from experimental status.
