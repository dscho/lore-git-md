Refactoring patch in the MIDX tracking series, moving from global to per-source storage. This is patch 6/8 in v1 of the series.

The patch modifies `find_pack_entry()` to stop using the global linked list of multi-pack indices, instead iterating through the per-source `multi_pack_index` pointers that were introduced earlier in the series. The key change replaces the direct MIDX list traversal with iteration through `r->objects->sources`, checking each source's attached MIDX` if present. The commit notes this is safe because `prepare_packed_git()` already handles the necessary preparation of these data structures.

The diff shows a straightforward conversion - removing the MIDX list traversal and adding a sources iteration loop while maintaining the same lookup logic via `fill_midx_entry()`. The patch also cleans up the early return condition since we no longer need to check both `packed_git` and `multi_pack_index` separately. This continues the series' pattern of methodically updating each MIDX access point to use the new per-source storage model while maintaining existing behavior.

The change touches core packfile lookup logic in `packfile.c` but appears to be a direct mechanical conversion following the pattern established in prior patches. No new test changes are included, suggesting the existing test coverage is sufficient to verify the refactoring. This brings the series one step closer to completely removing the global MIDX tracking infrastructure.
