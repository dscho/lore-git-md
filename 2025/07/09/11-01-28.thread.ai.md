Documentation bug report for git-subtree. Alexander Krupp initially reported the example command in git-subtree documentation fails with "fatal: '0a8f4f0^..' does not refer to a commit" when run verbatim from the docs, tested with Git 2.43.0 on Linux. Marc Branchaud confirmed the issue stems from invalid commit range syntax `0a8f4f0^..` being rejected by the subtree script's internal `rev-parse` check (from commit 10a49587fab). While removing the `..` suffix allows the command to run, it produces empty results, indicating the example may need more substantial revision than just syntax adjustment. The thread awaits input from subtree maintainers (CC'd Avery and David) on whether to fix the commit range syntax or replace the example entirely. Key technical detail: the problematic command attempts to split the gitweb subtree from git.git repository using this invalid range syntax. Open question remains about what the correct working example should be.
