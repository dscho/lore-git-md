This is a performance test patch for the new `git last-modified` command series. It adds a new performance test script to measure the execution time of various `last-modified` operations, complementing the existing correctness tests in the regular test suite.

The test script measures three scenarios:
1. Basic top-level operation (`git last-modified HEAD`)
2. Recursive mode (`git last-modified -r HEAD`)
3. Operation on a subdirectory (found dynamically via `git ls-tree`)

The patch is part of the v4 series implementing the new `last-modified` plumbing command, which tracks when paths were last modified in a repository's history at tree-level rather than line-by-line like `git blame`. Based on the thread context, this series has evolved through multiple versions with most review feedback addressed, and this performance test appears to be one of the final pieces before potential merging.

The implementation looks straightforward and follows Git's standard performance test patterns. The test cases cover both basic and recursive usage, plus a real-world scenario of checking a subdirectory. This should help catch any performance regressions as the command evolves. The patch is based on work by Jeff King and signed off by Toon Claes, indicating it has already seen some review.
