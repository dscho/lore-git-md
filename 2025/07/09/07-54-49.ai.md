Refactoring patch moving MIDX tracking from global to per-source storage, part of a series preparing for pluggable backends.

This first in the series modifies MIDX handling to store the multi-pack index pointer within each `struct odb_source` rather than maintaining a global linked list in `struct object_database`. The change addresses architectural mismatches where MIDX files are fundamentally per-source optimizations but were tracked globally. Key changes include:
- Adds `multi_pack_index` field to `struct odb_source`
- Updates `prepare_multi_pack_index_one()` to work with sources instead of paths
- Maintains backward compatibility by keeping the global linked list temporarily
- Touches core MIDX/packfile handling in `midx.c`, `packfile.c`, and header files

The patch demonstrates careful refactoring with clear commit message explaining the motivation and future direction. It builds on recent object store refactoring work and lays groundwork for subsequent patches to fully migrate MIDX handling. The changes are focused and well-contained, with some temporary duplication that will be cleaned up later in the series.
