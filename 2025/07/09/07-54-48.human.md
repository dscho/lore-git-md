This is a refactoring series targeting Git's multi-pack-index (MIDX) handling, part of the ongoing effort to improve the object storage subsystem architecture.

Patrick Steinhardt proposes moving MIDX tracking from the global object database level down to individual object sources. Currently, MIDX files are managed via a linked list in `struct object_database`, which creates awkwardness because MIDX files actually correspond to specific object sources (like individual packfiles) rather than being truly global. The series also notes this change will help future work toward pluggable object backends.

The 8-patch series systematically refactors MIDX handling to store the index with each object source rather than in a global list. Key changes include modifying `prepare_packed_git_one()` and `get_multi_pack_index()` to work with sources directly, removing the global MIDX list from lookup functions like `find_pack_entry()`, and finally eliminating the now-unused linked list infrastructure.

The changes touch core packfile and MIDX handling code across 10 files, with about twice as many lines removed as added - a good sign this is simplifying the codebase. The series builds on recent object store refactoring work and appears carefully constructed, with each commit focused on a logical step in the transition. This looks like a solid architectural improvement that could enable future storage backend work.
