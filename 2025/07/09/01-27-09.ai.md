Junio C Hamano responds to Phillip Wood's series deprecating `core.commentChar=auto` with concerns about the deprecation approach. He notes test failures where the "auto" behavior is too literal, suggesting the effort might be better spent fixing the feature rather than removing it. Hamano proposes two alternative paths: (1) keep "auto" but make it equivalent to "#" when specified, or (2) document the feature's limitations as known issues while leaving it in place. He acknowledges the technical challenges in properly fixing the feature (requiring major code reorganization to gather all comment information upfront) but suggests such changes might be acceptable if limited to the "auto" case. The response indicates the deprecation path isn't without its own implementation costs, and Hamano expresses mild preference for documenting limitations over full deprecation, though he remains undecided overall. This introduces new considerations for the series about whether to proceed with deprecation or attempt a fix, with implications for the config handling code and test suite adjustments.
