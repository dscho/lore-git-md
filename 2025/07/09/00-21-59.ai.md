The response strengthens the original proposal by introducing new threat models (account blocking, infrastructure failures) that standardized formats alone wouldn't address. The argument shifts from interoperability (the focus of Hamano's reply) to disaster recovery and censorship resistance.

Key points for future reference: the proposal now explicitly ties Git-native issue storage to scenarios of provider account termination ("blocking my account"), infrastructure collapse ("disaster striking some data center"), and data destruction ("malware deleting all the data"). These represent new dimensions to the discussion beyond the original vendor lock-in concern. The email maintains the position that Git core changes would be preferable to external standardization for ensuring complete project portability.
