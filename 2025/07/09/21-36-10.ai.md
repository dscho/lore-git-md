This is a follow-up discussion in Patrick Steinhardt's Meson build system improvement series, specifically addressing Python detection behavior. Justin Tobler responds to Junio Hamano's concern about how `find_program()` handles Python installations where the binary is named simply `python` rather than `python3`.

The key technical points:
- The series already changed Python detection to only look for target Python (not build-time Python) since it's only needed for `git-p4`
- Junio questions whether `find_program('python3')` properly handles systems where Python 3 is installed as `/usr/bin/python`
- Justin confirms `find_program()` won't handle this case automatically
- They discuss Meson's fallback behavior (since 0.50.0) to use the build interpreter if `python3` isn't found, but note this isn't relevant for their use case since they only need target Python

This discussion clarifies edge case behavior but doesn't require changes to the series, as the current implementation correctly handles the target Python detection needs while documenting the limitations. The thread shows careful consideration of cross-platform compatibility issues in the build system modernization effort.
