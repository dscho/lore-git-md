This is a brief contribution to the ongoing discussion about Git-native issue tracking, pointing to an existing implementation. Eli Schwartz suggests looking at git-bug, a third-party tool that already implements distributed issue tracking using Git as a backend. The suggestion comes as a practical middle ground between Sahil Gautam's proposal for core Git integration and Junio Hamano's preference for ecosystem solutions.

The email doesn't take a position in the debate but offers a concrete example of how issue tracking can work with Git today, without requiring changes to core. The git-bug project demonstrates that distributed issue tracking is technically feasible using Git's existing capabilities, though it doesn't address all the resilience concerns raised in the thread.

This is a useful reference point in the discussion, showing that some of the desired functionality already exists in the ecosystem, though likely with different tradeoffs than a core implementation would have. The suggestion keeps the conversation grounded in practical implementations rather than theoretical possibilities.
