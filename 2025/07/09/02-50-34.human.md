This is a bugfix patch in the submodule configuration management series that has already been approved by Junio Hamano. The patch prevents `.gitmodules` entries from being silently overwritten when adding a new submodule at a path that previously hosted a moved (but not renamed) submodule.

D. Ben Knoble provides some user perspective on the implementation, noting that the `--force` behavior (which auto-increments the submodule name when conflicts occur) might be unexpected to users who specify a particular name. They suggest documenting this behavior in `git help submodule` to clarify the interaction. The reviewer also expresses mild disappointment that the patch doesn't implement a "clever trick" to allow reuse of the same name, though they acknowledge the test case demonstrates the intended protection.

The patch itself adds checks in `module_add()` to detect name conflicts and either error out or generate a new name when forced. Test coverage in t7400-submodule-basic.sh verifies the protection works as intended. While Knoble's feedback raises some usability considerations, these don't challenge the technical correctness of the solution, which remains approved for merging as part of the series.
