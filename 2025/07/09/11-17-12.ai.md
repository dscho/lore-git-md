This is part 2/19 in the `the_repository` removal effort, specifically targeting the `the_hash_algo` global in object-file.c. The patch systematically replaces direct `the_hash_algo` usage with repository-specific hash algorithms, either derived from existing context (like `istate->repo->hash_algo`) or temporarily falling back to `the_repository->hash_algo` where immediate removal isn't practical.

Key changes:
- Modifies `fill_loose_path()` to take explicit `algop` parameter
- Updates `odb_loose_path()` to use repository-specific hash algorithm from odb source
- Changes hash algorithm usage in object indexing functions to use `istate->repo->hash_algo`
- Adds `algop` parameter to `for_each_file_in_obj_subdir()` and updates all callers
- Updates `check_stream_oid()` to use passed algorithm rather than global
- Touches core object handling paths including loose object iteration and verification

The patch follows the series' pattern of incremental refactoring, with some temporary uses of `the_repository` that will be addressed in later patches. It affects object storage internals but maintains external behavior. The changes are mechanical but widespread, touching 40 lines across object-file.c with one header file addition to expose the new parameter. This continues the groundwork for pluggable object backends by removing another global dependency.
