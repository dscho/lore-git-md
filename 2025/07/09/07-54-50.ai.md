This is the second patch in an 8-part refactoring series moving MIDX tracking from global state to per-source storage. The patch continues the architectural shift by refactoring `prepare_packed_git_one()` to work directly with `struct odb_source` rather than searching for matching MIDX files.

The key change removes the MIDX lookup logic from `prepare_packed_git_one()` since the MIDX pointer is now directly available in the `odb_source` struct. The function signature changes to take a source parameter instead of repository+path, and the MIDX is accessed via `source->multi_pack_index`. This eliminates redundant MIDX directory matching that was previously needed to connect packs with their MIDX files.

The patch demonstrates careful mechanical refactoring - it maintains all existing functionality while simplifying the code by leveraging the new per-source MIDX storage introduced in patch 1. The changes are localized to `packfile.c` and focus on the pack preparation logic, keeping the diff small (14 lines removed, 9 added) and straightforward. This appears to be a well-executed step in the larger series' goal of moving MIDX handling to be properly scoped to individual object sources.
