This is a technical response in the ongoing discussion about SIGCHLD handling in `git daemon`, specifically regarding Windows compatibility.

Johannes Sixt (a Windows porting expert) pushes back on some assumptions in Carlo Marcelo Arenas Belón's SIGCHLD series. He makes two key points: (1) signal numbers shouldn't matter in portable code (only the SIGCHLD macro should be used), and (2) Windows doesn't actually have real signals outside of Cygwin, making the SA_RESTART discussion irrelevant for MinGW builds. He notes Windows only has a crude SIGALRM emulation that doesn't behave like POSIX signals.

This email highlights platform-specific complexities in the proposed signal handling changes. While the thread previously focused on POSIX systems, Johannes reminds everyone that Windows signal handling is fundamentally different, suggesting parts of the patch series may need rethinking for MinGW compatibility. The exchange shows the careful balancing act required when making cross-platform system changes in Git.
