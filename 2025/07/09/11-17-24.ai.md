This is part 14 of Patrick Steinhardt's ongoing series to eliminate `the_repository` global in the object-file subsystem, continuing the pluggable loose object backends effort. The patch refactors `read_loose_object()` to explicitly take a `struct repository` parameter instead of implicitly using `the_repository`.

The change is straightforward but touches core object reading functionality. The function now requires callers to pass in the repository context explicitly, which affects:
1. The big file threshold check (now uses passed-in repo settings)
2. Stream verification (uses repo's hash algorithm)
3. Object hashing (uses repo's hash algorithm)

The only caller updated is in `builtin/fsck.c`, which now passes `the_repository` explicitly. The patch maintains all existing behavior while removing another dependency on the global variable. This follows the series' pattern of mechanical but careful refactoring to prepare for pluggable backends.

Technical details:
- Updates function signature in object-file.h
- Modifies three call sites in object-file.c to use passed repository
- Touches object reading path but not writing
- Preserves all existing error handling and validation
- Affects loose object verification in `git fsck`
- Does not yet address potential performance impact of additional parameter passing
- Keeps same function logic while changing interface

This continues the incremental progress toward eliminating `the_repository` from object-file.c, with each patch tackling a specific function or subsystem. The changes are focused and well-contained, following the established pattern of the series.
