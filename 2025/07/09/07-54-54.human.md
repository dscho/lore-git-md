This is the sixth patch in an 8-part refactoring series moving MIDX (multi-pack index) tracking from global state to per-source storage, part of the larger effort to enable pluggable object database backends.

The patch simplifies `find_pack_entry()` by removing its direct use of the global MIDX linked list. Instead, it leverages the per-source MIDX storage that was set up in earlier patches, iterating through the object database sources rather than the MIDX list directly. The change is straightforward - the function now checks each source's `multi_pack_index` field rather than walking the old global list.

A key observation in the commit message notes that this refactoring is safe because `prepare_packed_git()` (called at the start) already handles all the necessary preparation of the MIDX data structures. The diff shows a clean simplification of the control flow, with the MIDX-specific check now fitting naturally alongside the packed-git MRU list iteration that follows.

This continues the series' pattern of methodically converting each MIDX access point to use the new per-source storage model. The changes are focused and mechanical, building confidence that the core object lookup behavior remains correct while the internals are reorganized.
