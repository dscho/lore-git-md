This is a feature patch adding a `git sparse-checkout clean` command, part of the ongoing effort to improve sparse-checkout performance and usability. The command removes tracked-but-sparse directories outside the current sparse-checkout scope, addressing cases where lingering files cause unnecessary index expansion.

The patch responds to Elijah Newren's review feedback, clarifying several design decisions:
- The command currently only works in cone mode (dies otherwise), though non-cone mode support could be added later if needed
- It preserves untracked directories outside sparse directories (unlike `git clean`)
- Staged changes prevent directory removal due to sparse index mechanics (they don't collapse as sparse entries)
- Merge/rebase conflicts are handled safely since conflicted files prevent sparse directory collapsing

Key open questions center on output granularity and safety:
- Should --dry-run show individual files or just directories? (currently directories only)
- Could better error messages help users understand why some directories aren't being removed?
- Should there be warnings when running in cone mode without sparse-index?

The implementation uses an in-memory sparse index (SPARSE_INDEX_MEMORY_ONLY) to identify which tracked sparse directories still exist on disk, then removes them. This is more targeted than `git clean -dfx` for sparse-checkout scenarios. The patch appears well-considered but awaits resolution of the output granularity questions before finalization.
