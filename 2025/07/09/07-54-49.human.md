This is the first patch in an 8-part refactoring series that moves MIDX (multi-pack index) tracking from global object database state to per-source storage. The change better aligns the code with how MIDX files are actually stored on disk (one per source) and prepares for future pluggable backends.

The patch modifies `prepare_multi_pack_index_one()` to work with individual `struct odb_source` instances rather than the global state, storing MIDX pointers directly in each source. While the global linked list remains temporarily for compatibility, subsequent patches will transition users to the new per-source approach.

The changes touch core packfile/MIDX handling code across 4 files (`midx.c`, `midx.h`, `odb.h`, `packfile.c`). This appears to be a well-motivated architectural improvement that builds on recent object store refactoring work, with cleanly separated changes that maintain backward compatibility during the transition.
