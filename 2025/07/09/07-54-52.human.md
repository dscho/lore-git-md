This is the fourth patch in an 8-part refactoring series moving MIDX tracking from global state to per-source storage. The series is part of the larger effort to prepare for pluggable object database backends.

The patch addresses a subtle edge case in MIDX (multi-pack index) loading. Currently, Git avoids reloading an already-loaded MIDX, but doesn't track failed attempts to load a nonexistent MIDX. As the series moves away from global MIDX tracking, this could lead to repeated failed load attempts for sources without MIDX files.

Patrick Steinhardt fixes this by adding a `multi_pack_index_loaded` flag to track whether we've attempted to load a MIDX for each source, regardless of success. The change is straightforward - just 12 lines of net additions across 3 files - but prevents unnecessary filesystem operations once the global MIDX list is removed.

The patch maintains the series' careful, incremental approach, touching only the minimal necessary code while keeping behavior identical. It follows logically from the previous patches that moved MIDX tracking to per-source storage, and will enable the subsequent removal of the global MIDX list.
