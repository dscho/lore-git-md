This is the fourth patch in an 8-part refactoring series moving MIDX tracking from global state to per-source storage. The patch introduces a new `multi_pack_index_loaded` flag in `struct odb_source` to track whether we've attempted to load a MIDX for each source, even when no MIDX exists.

The change addresses a subtle optimization gap in the current per-source MIDX loading logic. Currently, `prepare_multi_pack_index_one()` skips loading if one is already present (`source->multi_pack_index`), but doesn't remember failed attempts to load nonexistent MIDX files. As the series removes the global MIDX linked list, callers will need to query each source individually, potentially causing repeated failed load attempts for sources without MIDX files.

The patch modifies three files:
- Adds the new flag to `struct odb_source` in `odb.h`
- Updates `prepare_multi_pack_index_one()` in `midx.c` to set/check the flag
- Ensures proper cleanup by resetting the flag in `clear_midx_file()` and `close_object_store()` in `midx.c` and `packfile.c`

This is a straightforward but important optimization that becomes necessary as part of the larger architectural shift to per-source MIDX tracking. The implementation is clean separation of concerns, with MIDX-specific state properly encapsulated in the odb_source structure.
