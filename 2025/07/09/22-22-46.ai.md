This is a follow-up discussion in the Meson build system improvement series, specifically addressing Python detection concerns raised by Junio Hamano. Eli Schwartz provides additional context about Python naming conventions to confirm that the series' approach of using `find_program('python3')` is correct.

The email explains why searching for 'python3' directly is the right approach, detailing the evolution of Python naming conventions since Python 1.4. Key points include:
- Modern Python installations always provide 'python3' symlinks (to versioned binaries like python3.13)
- The unversioned 'python' name is unreliable (may point to Python 2.x or not exist)
- Cross-compilation environments already require explicit toolchain setup, where Python would be specified alongside other host tools
- Historical context shows 'python3' naming was introduced precisely to avoid version ambiguity

The response confirms the patch's approach is sound and addresses Junio's concern about systems where Python 3 might only be installed as '/usr/bin/python'. This discussion provides important validation for the series' Python detection changes, which had already been reviewed and acked by Justin Tobler. The thread shows consensus forming around the technical solution, with Eli's expertise in Python packaging providing additional confidence in the approach.
