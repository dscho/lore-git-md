This is a discussion about path handling behavior in the `git last-modified` plumbing command (formerly `blame-tree`). The thread has been working through the command's interface design, with v4 recently addressing most technical feedback. The current question is whether the command should match `git ls-tree`'s path handling (showing individual files) or `git diff-tree`'s (aggregating directory changes).

Toon Claes explains the decision to keep the current `diff-tree`-like behavior where directory changes are reported as a single entry (e.g. showing "Documentation" rather than individual files). Three key reasons are given: 1) consistency with other plumbing commands like `diff-tree`, 2) implementation constraints since it uses diff machinery internally, and 3) potential future extensibility via a `--max-depth` option (referencing a past attempt by Peff). A new patch series [2] has been submitted maintaining this behavior.

The discussion highlights an important design tradeoff between consistency with existing commands and intuitive output. While Kristoffer Haugsbakk had raised concerns about the unexpected aggregation, the response argues this matches plumbing conventions. The reference to Peff's past work on `--max-depth` suggests a path forward for users who need finer-grained control, though that would be a separate follow-up.

This appears to be the final design decision before potential merging, with the v4 series having addressed all other major feedback (performance, memory management, test coverage). The thread shows the command is now technically complete, with this being the last interface question to resolve.
