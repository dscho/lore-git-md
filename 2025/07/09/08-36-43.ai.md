This is a feature proposal for gitk, the Git repository browser. The author identifies a usability issue where tags in gitk's interface don't visually distinguish between local-only tags and those that exist on remotes, unlike branches which are clearly separated. This can lead to confusion about whether tags have been shared with collaborators.

The proposal suggests three possible UI approaches to indicate remote-tracking status for tags: (1) appending the remote name in parentheses, (2) using different colors similar to branch display, or (3) showing remote information in a tooltip. The author argues this enhancement would maintain gitk's "at-a-glance" strength while preventing common workflow issues around tag sharing.

Key technical details include the current branch display behavior (local vs remote branches shown separately with color coding) and the lack of similar differentiation for tags. The proposal is opt-in, suggesting configurability. The change would primarily affect gitk's tag rendering logic and potentially its configuration options.

This appears to be a well-motivated quality-of-life improvement targeting gitk's visualization capabilities. The proposal is presented clearly with multiple implementation options for discussion. The change would likely involve modifying gitk's Tcl/Tk interface code to query and display tag remote status, possibly adding new configuration knobs for the visual presentation.
