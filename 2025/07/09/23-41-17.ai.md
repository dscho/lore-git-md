This is a bugfix patch addressing a memory leak in the reflog expiration code. The leak occurs when `find_cfg_ent()` allocates `reflog_expire_entry_option` structs that are never freed during reflog expiration operations, both in `cmd_reflog_expire` and the gc maintenance task.

The patch introduces a new `reflog_clear_expire_config()` function to properly free these allocations. It's called at exit points in `cmd_reflog_expire()` and `reflog_expiry_cleanup()`. The v2 fixes an earlier incorrect attempt at addressing the leak (as noted in the changelog).

Key technical details for future reference:
- The leak occurs in the `entries` linked list within `reflog_expire_options`
- New function `reflog_clear_expire_config()` iterates through and frees the list
- Fix affects both direct reflog expiration and garbage collection paths
- Changes span `reflog.h`, `builtin/reflog.c`, and `reflog.c`
- The ASAN trace shows 39-byte allocations from `find_cfg_ent()` going unfreed
