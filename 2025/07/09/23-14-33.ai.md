This is a status update on the SHA-256 default hash transition effort, part of the broader Git 3.0 infrastructure changes. Brian m. carlson confirms their series to enable SHA-256 by default in breaking changes mode is ready for merging to 'next', having received positive feedback from Patrick Steinhardt and no outstanding objections. The 11-commit series includes changes to repository initialization, test infrastructure adjustments, and new hash algorithm constants, all aimed at making SHA-256 the default when operating in Git's breaking changes mode (3.0+). The technical implementation appears solid, having addressed key areas like test suite compatibility and legacy format handling. This represents a major step in Git's multi-year SHA-256 transition, though the change only affects new repositories created in Git 3.0's breaking changes mode - existing repositories continue using their configured hash algorithm. The lack of requested changes and explicit positive review from Patrick Steinhardt suggests this is likely to proceed smoothly, though Brian leaves the door open for any last-minute concerns from other maintainers.
