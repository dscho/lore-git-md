This is a technical discussion about Windows signal handling compatibility, part of the ongoing git daemon signal handling redesign effort. Carlo Marcelo Arenas Belón and Phillip Wood are debating how `sigaction(SIGCHLD)` should behave on Windows when replacing existing `signal()` calls.

The key disagreement centers around whether the Windows compatibility layer should:
1. Initially match Windows' current `signal()` behavior (Carlo's preference to avoid potential regressions)
2. Immediately implement POSIX-compliant `sigaction()` behavior (Phillip's preference for consistency)

Carlo notes that Windows CRT's `signal()` doesn't set errno for SIGCHLD as documented, possibly due to Git's custom signal numbering (17 vs Windows' standard 20). He suggests handling this inconsistency in a future change rather than as a prerequisite. Phillip argues for immediate POSIX compliance, seeing platform divergence as a greater risk than potential errno-related regressions.

The discussion remains unresolved, with Carlo hinting at involving Windows expert Johannes Schindelin for deeper insight into the platform's signal handling quirks. This represents one of the final technical hurdles in the pipe-based child tracking solution path of the signal handling redesign.
