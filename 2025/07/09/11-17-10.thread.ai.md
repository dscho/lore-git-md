[PATCH 0/19] object-file: prepare for pluggable loose object backends

Patrick Steinhardt's series refactors object-file.c for pluggable object database support as part of the `the_repository` removal effort. The series has progressed through thirteen patches, systematically eliminating `the_repository` and introducing new interfaces for loose object handling.

Current state:
- Parts 1-7 addressed compiler warnings, hash algo usage, loose object checks, freshening operations, and object finalization
- Part 8 refactored loose object map functionality to use `struct odb_source` instead of `struct repository`
- Part 9 introduced backend-agnostic `odb_write_object()` interface
- Part 10 refactored loose object writing to use `struct odb_source` explicitly
- Part 11 inlined `for_each_loose_file_in_objdir_buf()` into its sole caller
- Part 12 removed unused public interface `for_each_file_in_obj_subdir()` declaration
- Part 13 (new) refactors loose object iteration to eliminate global repository dependencies

Core changes:
- Introduces `odb_write_object()` as new interface for writing objects
- Migrates repository-specific settings into repo settings
- Refactors loose object handling to use `struct odb_source`
- Systematically replaces `the_hash_algo` with repository-specific parameters
- Modifies loose object map to operate on odb_source rather than repository
- Updates path construction to use source's path directly
- Replaces direct `write_object_file()` calls with new backend-agnostic interface
- Adds `odb_source` parameters to all object writing functions
- Moves repository-specific hash algorithm lookups to use source's ODB
- Modifies temporary file creation/finalization to operate on source
- Renames `for_each_loose_file_in_objdir()` to `for_each_loose_file_in_source()` with odb_source parameter
- Updates `for_each_loose_object()` to accept `object_database` parameter
- Maintains external behavior while changing internal implementation
- Affects 98 files with ~700 lines added and ~640 lines removed overall

Technical details:
- `check_and_freshen_odb()` renamed to `check_and_freshen_source()`
- Three helper functions inlined into `freshen_loose_object()`
- Freshening operations now explicitly take ODB parameter
- `loose_object_info()` no longer falls back to `the_repository`
- `finalize_object_file()` takes explicit repository parameter
- `write_one_object()` and `repo_add_loose_object_map()` now take odb_source
- Introduces `odb_write_object()` and `odb_write_object_ext()` in odb.h
- Moves write flags (`WRITE_OBJECT_PERSIST` and `WRITE_OBJECT_SILENT`) to odb.h
- Updates all callers of `write_object_file()` and `write_object_file_flags()`
- Path construction uses source's path directly
- Touches core object operations: reading, writing, existence checks, iteration, freshness verification, finalization, mapping
- Affects commands: commit, tag, merge, pack-objects, fsck, gc, http-fetch, unpack-objects, cat-file, count-objects
- Updates `stream_loose_object()`, `write_object_file_flags()`, and `force_object_loose()` call sites
- Modifies temporary file handling in object writing path
- Adds explicit source parameter to object writing call chain
- Makes `for_each_file_in_obj_subdir()` static
- Converts `builtin/fsck.c` to use `fsck_source()` with direct ODB source
- Updates `builtin/gc.c` loose object counting to source-based iteration
- Preserves iteration logic while changing interface parameters

Open questions:
- Performance impact from additional parameter passing
- Backward compatibility for external tools
- Long-term suitability of odb_source approach
- Future work needed in other subsystems
- Semantic implications of source-specific existence verification
- Remaining temporary use of `the_repository` in `stream_loose_object()`
- Whether ODB parameter would be more appropriate than repository for `finalize_object_file()`
- When backend-specific write implementations will be introduced
- How new interface will handle non-loose backends
- Future handling of `the_repository->hash_algo` in iteration code

This continues the multi-year `the_repository` removal effort led by René Scharfe and Patrick Steinhardt, with the latest patch converting loose object iteration to use ODB sources directly. Part 13 follows the series' incremental approach, systematically eliminating another set of `the_repository` dependencies while maintaining existing behavior. The changes are mechanical but widespread, affecting multiple commands as the series prepares the object storage layer for pluggable backends. The patch updates core iteration interfaces while preserving their logic, continuing the pattern of making focused improvements to the object storage architecture.
