[PATCH 0/19] object-file: prepare for pluggable loose object backends

This series by Patrick Steinhardt refactors object-file.c as part of the `the_repository` removal effort, preparing for pluggable object database support. The series has progressed through eight patches, systematically eliminating `the_repository` and `the_hash_algo` dependencies while introducing new interfaces for loose object handling.

Current state:
- Parts 1-7 addressed compiler warnings, hash algo usage, loose object checks, freshening operations, and object finalization
- Part 8 (new) refactors loose object map functionality to use `struct odb_source` instead of `struct repository`

Core changes:
- Introduces `odb_write_object()` as new interface for writing objects
- Migrates repository-specific settings into repo settings
- Refactors loose object handling to use `struct odb_source`
- Systematically replaces `the_hash_algo` with repository-specific parameters
- Now modifies loose object map to operate on odb_source rather than repository
- Updates path construction to use source's path directly
- Maintains external behavior while changing internal implementation
- Affects 63 files with ~477 lines added and ~431 removed overall

Technical details:
- `check_and_freshen_odb()` renamed to `check_and_freshen_source()`
- Three helper functions inlined into `freshen_loose_object()`
- Freshening operations now explicitly take ODB parameter
- `loose_object_info()` no longer falls back to `the_repository`
- `finalize_object_file()` takes explicit repository parameter
- `write_one_object()` and `repo_add_loose_object_map()` now take odb_source
- Path construction uses source's path directly
- Touches core object operations: reading, writing, existence checks, iteration, freshness verification, finalization, mapping
- Affects commands: pack-objects, fsck, gc, http-fetch
- Updates `stream_loose_object()`, `write_object_file_flags()`, and `force_object_loose()` call sites

Open questions:
- Performance impact from additional parameter passing
- Backward compatibility for external tools
- Long-term suitability of odb_source approach
- Future work needed in other subsystems
- Semantic implications of source-specific existence verification
- Remaining temporary use of `the_repository` in `stream_loose_object()`
- Whether ODB parameter would be more appropriate than repository for `finalize_object_file()`

This continues the multi-year `the_repository` removal effort led by René Scharfe and Patrick Steinhardt, with the latest patch extending the refactoring to the loose object map functionality. The changes remain mechanical but widespread, preparing for pluggable backends by removing global dependencies while keeping temporary fallbacks where needed. The series maintains its incremental approach, with each patch focusing on a specific subsystem while preserving existing behavior. The part 8 changes clarify that the loose object map belongs to the backend source rather than the repository abstraction, further separating these concerns in preparation for pluggable ODB support.
