[PATCH 0/19] object-file: prepare for pluggable loose object backends

Patrick Steinhardt's 19-part series refactors object-file.c to eliminate `the_repository` dependencies, enabling pluggable object database support. The series has completed removal of `the_repository` from object-file.c, establishing subsystem independence. Key changes include introducing `odb_write_object()` as backend-agnostic interface (with a documentation typo in patch 09/19 where "gose" should be "goes" as reported by Toon Claes), migrating compression levels to repo settings, and refactoring loose object handling using `struct odb_source`.

A regression was found in `git fast-import` due to delayed config parsing (Phillip Wood reports `git -c core.compression=500 fast-import` now fails where it previously accepted invalid values silently). Junio C Hamano endorsed Wood's concern that scattering `prepare_repo_settings()` calls could lead to regressions, emphasizing settings moved from global config should maintain early parsing behavior like builtin commands. In response, Steinhardt acknowledges the architectural concern and proposes initializing repository settings when repositories are first opened as a potential solution, while identifying significant challenges around handling invalid configurations - some commands (like `git config`) must function even with invalid settings, while others may need to fail fast. He outlines the current messy state of config parsing in Git (inconsistent timing, scope, and validation behavior) and an ideal end state with centralized, typed configuration validated at startup, though acknowledges this would require major refactoring beyond current scope.

Technical clarification emerged regarding patch 15/19 (removing `the_repository` from `force_object_loose()`). Toon Claes and Karthik Nayak analyzed the function's dual-scope behavior where it checks loose object existence across the entire object database (via `has_loose_object()`) while writing to a specific source. This explains the current implementation where the function writes if the object is packed (not loose) and skips if already loose. While architecturally notable for its mixed scope, the behavior is confirmed as intentional through this review discussion.

Karthik Nayak's review feedback across multiple patches includes:
- Patch 02/19: grammatical error in commit message regarding `the_hash_algo` alternatives and question about `read-cache-ll.h` header inclusion
- Patch 05/19: confirmation of architectural consistency in parameter passing patterns
- Patch 08/19: noted naming inconsistency with established `_source` suffix pattern. Steinhardt responds that comprehensive naming cleanup is deferred until later backend separation.

Current technical state:
- Object-file.c fully repository-agnostic with all operations parameterized
- 100 files modified (~730/+670 lines) in total
- Compression level validation now via `prepare_repo_settings()` with ongoing discussion about initialization timing
- Loose object iteration converted to source-based interface
- Maintains backward compatibility except for fast-import edge case
- Clear pattern established: database-wide ops use `object_database`, source-specific use `_source` suffix (with acknowledged temporary exceptions)

Open considerations:
- Config parsing timing and validation behavior (Steinhardt's proposal to initialize at repository instantiation, but challenges around invalid config handling remain)
- Performance impact of additional parameter passing
- Future handling of non-loose backends
- Platform-specific considerations for object creation modes
- Architectural quirk in `force_object_loose()` behavior now technically clarified but scope mismatch remains
- Consistency of parameter passing patterns across all object-file functions (naming conventions acknowledged as deferred cleanup)
- Documentation typo in `WRITE_OBJECT_QUIET` flag description to be fixed
- Long-term vision for centralized config system identified but not part of current series scope

The series demonstrates successful conversion of core subsystems to repository-agnostic operation while maintaining compatibility, with maintainer feedback on config parsing timing and detailed technical review of architectural decisions. The latest discussion around `force_object_loose()` provides important implementation clarity while confirming the current behavior's intentionality, even as it highlights an architectural nuance in scope management. Steinhardt continues to engage with both high-level maintainer concerns and detailed technical feedback from reviewers.
