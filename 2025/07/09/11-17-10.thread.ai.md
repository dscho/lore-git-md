[PATCH 0/19] object-file: prepare for pluggable loose object backends

This series refactors object-file.c as part of the `the_repository` removal effort, preparing for pluggable object database support. Authored by Patrick Steinhardt, it systematically eliminates `the_repository` and `the_hash_algo` dependencies in object file operations while introducing new interfaces for loose object handling. The first patch addressed compiler warnings (-Wsign-compare) in object-file.c by properly typing variables and comparisons. The second patch (part 2/19) focused on removing `the_hash_algo` usage, modifying core object handling paths to use repository-specific hash algorithms. Part 3/19 refactors `has_loose_object()` to operate on a specific `odb_source` rather than implicitly checking all sources via `the_repository`.

Core changes:
- Introduces `odb_write_object()` as new interface for writing objects
- Migrates repository-specific settings (compression_level, object_creation_mode) into repo settings
- Refactors loose object handling to use `struct odb_source` instead of global state
- Systematically replaces `the_hash_algo` with repository-specific hash parameters
- Modifies `fill_loose_path()`, `odb_loose_path()`, `for_each_file_in_obj_subdir()` to take explicit `algop` parameters
- Updates object indexing functions to use `istate->repo->hash_algo`
- Replaces `has_loose_object()` with source-specific version and removes `has_loose_object_nonlocal()`
- Updates `pack-objects.c` to manually iterate through object sources
- Maintains external behavior while changing internal implementation
- Affects 49 files with ~430 lines added and ~367 removed overall
- Touches core object operations: reading, writing, existence checks, iteration
- Affects commands: pack-objects, fsck, gc

Technical details:
- Adds `source` parameter to `has_loose_object()`
- Makes existence checks source-specific rather than database-wide
- Requires explicit iteration over object sources in calling code
- Modifies `force_object_loose()` to check all sources sequentially
- Open questions:
- Performance impact on critical paths from additional parameter passing
- Backward compatibility considerations for external tools
- Long-term suitability of odb_source approach
- Future work needed in other subsystems to complete hash algorithm transition
- Semantic implications of source-specific existence verification

This continues the multi-year `the_repository` removal effort led by René Scharfe and Patrick Steinhardt, with part 3 focusing specifically on object existence checking while maintaining the series' incremental refactoring approach. The changes are mechanical but widespread, preparing for pluggable backends by removing global dependencies while keeping temporary fallbacks to `the_repository` where immediate removal isn't practical.
