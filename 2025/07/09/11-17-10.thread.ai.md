[PATCH 0/19] object-file: prepare for pluggable loose object backends

Patrick Steinhardt's completed 19-part series refactors object-file.c to eliminate `the_repository` dependencies, enabling pluggable object database support. The final patch removes `USE_THE_REPOSITORY_VARIABLE` from object-file.c, marking subsystem independence from global state. Phillip Wood reports a regression in `git fast-import` caused by patch 17/19's move of compression level validation to `prepare_repo_settings()`. The command `git fast-export HEAD^ | git -c core.compression=500 fast-import` now fails with "bad zlib compression level 500" where it previously accepted invalid values silently.

Current state:
- Parts 1-19 complete with `the_repository` fully removed from object-file.c
- Regression found in `fast-import` due to delayed config parsing
- Phillip Wood argues settings moved from `git_default_core_config()` should still parse during command initialization

Core changes:
- Introduced `odb_write_object()` as backend-agnostic interface
- Migrated compression levels and object creation mode to repo settings
- Eliminated global variables including `zlib_compression_level`
- Refactored loose object handling using `struct odb_source`
- Systematically replaced `the_hash_algo` with repository parameters
- Modified temporary file handling to operate on source
- Converted all object operations to explicit parameter passing
- Affected 100 files with ~730 lines added and ~670 lines removed

Regression details:
- Compression level validation now happens via `prepare_repo_settings()`
- `fast-import` fails on invalid levels (500) that were silently accepted before
- Phillip suggests maintaining early validation for critical settings
- Reveals need to carefully consider repository settings timing
- Does not affect series' core goal of removing `the_repository`

Technical implications:
- Object-file.c now fully repository-agnostic
- All operations properly parameterized
- Demonstrates `the_repository` removal pattern
- Maintains backward compatibility except for this edge case
- Performance characteristics unchanged
- Compression settings remain configurable per-repository

Open questions:
- How to handle delayed config parsing for critical settings like compression
- Performance impact of additional parameter passing (to be measured)
- Backward compatibility for external tools (likely maintained)
- Future handling of non-loose backends (follow-up work needed)
- Platform-specific considerations for object creation modes

This remains a major milestone in the `the_repository` removal effort, though the `fast-import` regression shows one area needing refinement in the configuration handling approach. The series successfully demonstrates how core subsystems can be converted to repository-agnostic operation while maintaining compatibility, positioning Git for future pluggable storage backends.
