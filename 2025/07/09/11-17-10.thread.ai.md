[PATCH 0/19] object-file: prepare for pluggable loose object backends

Patrick Steinhardt's series refactors object-file.c for pluggable object database support as part of the `the_repository` removal effort. The series has progressed through eighteen patches, systematically eliminating `the_repository` and global state while introducing new interfaces for loose object handling.

Current state:
- Parts 1-7 addressed compiler warnings, hash algo usage, loose object checks, freshening operations, and object finalization
- Part 8 refactored loose object map functionality to use `struct odb_source` instead of `struct repository`
- Part 9 introduced backend-agnostic `odb_write_object()` interface
- Part 10 refactored loose object writing to use `struct odb_source` explicitly
- Part 11 inlined `for_each_loose_file_in_objdir_buf()` into its sole caller
- Part 12 removed unused public interface `for_each_file_in_obj_subdir()` declaration
- Part 13 refactored loose object iteration to eliminate global repository dependencies
- Part 14 converted `read_loose_object()` to take explicit `struct repository` parameter
- Part 15 refactored `force_object_loose()` to use `struct odb_source` instead of `the_repository`
- Part 16 converted `index_fd()` and `index_path()` to use `istate->repo` instead of `the_repository`
- Part 17 moved compression level settings from globals to `repo_settings`
- Part 18 (new) migrates `core.createobject` config to repository-specific storage

This continues the multi-year `the_repository` removal effort led by René Scharfe and Patrick Steinhardt, with part 18 converting the object creation mode configuration to repository-specific storage. The patch follows the series' incremental approach, systematically eliminating global variables while maintaining existing behavior. The change demonstrates how repository-specific configuration should flow through the system, further reducing reliance on global state while preserving all existing functionality including the hardlink/rename behavior. The patch maintains careful backward compatibility while moving another configuration setting into the repository context.
