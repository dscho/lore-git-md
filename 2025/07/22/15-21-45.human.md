This is a review comment on the `git repo` command implementation, specifically addressing the output format design. Junio C Hamano responds to Karthik Nayak's observation about the field-value separator syntax proposed in the patch series.

The discussion focuses on the machine-readable output format for `git repo info`, which currently proposes using LF as a field separator and NUL as a value terminator. Junio questions this design choice, noting that:
1. The LF separator only applies to the `info` subcommand, not necessarily others
2. Once consumers must handle NUL terminators anyway, LF separators don't provide additional parsing simplicity
3. Field names might themselves contain LFs, potentially requiring escaping that would negate any parsing benefits

This continues the thread's ongoing discussion about output format design decisions, with Junio raising practical concerns about the current implementation's approach to machine-readable output. The comment doesn't propose a specific alternative but suggests the current design may need rethinking to properly handle edge cases.
