Test helper resource leak fixes (v3)

This patch series addresses file descriptor leaks in test helper programs `test-truncate` and `test-delta`, now in its third iteration. The core issue involves ensuring proper resource cleanup in test infrastructure code, with v3 first fixing `test-truncate` and now completing the work with `test-delta`. The changes add missing cleanup logic while maintaining existing error handling patterns.

For `test-truncate`, the patch adds a missing `close(fd)` call after file truncation operations in `t/helper/test-truncate.c` (3 lines changed). Junio C Hamano has questioned the practical necessity of this change since the process exits immediately after the leak would occur, making the patch technically unnecessary (though not harmful). The motivation for the fix remains unclear - whether from automated checkers or part of broader cleanup efforts.

Jeff King has now proposed a significantly simplified approach for `test-delta`, responding to earlier discussion about cleanup complexity. Rather than carefully managing cleanup paths, he suggests using `die_errno()` on errors since the test helper exits immediately anyway. His patch converts `t/helper/test-delta.c` to use `xopen()` and `die_errno()` consistently, reducing the code by 33 lines while also fixing two subtle bugs (potential integer truncation in `xmalloc()` and unchecked short reads). This eliminates the need for explicit cleanup paths while maintaining the same failure behavior through process termination. King notes this could be taken further by using `strbuf` APIs to automatically handle size-related bugs.

The approach represents a philosophical shift from the original series - instead of meticulously cleaning up resources before exit, it embraces the test helper's throwaway nature by failing fast. This avoids the complexity that caused problems in earlier iterations (like the double-close bug Eric Sunshine found) while still preventing resource leaks. The `test-truncate` portion remains accepted despite questions about its practical impact, while the `test-delta` changes now follow King's simplified approach after his and Sunshine's reviews exposed flaws in the original solution. Both patches are well-scoped but represent different approaches to test helper resource management - one adding explicit cleanup, the other embracing immediate termination.
