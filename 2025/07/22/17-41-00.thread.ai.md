Test helper resource leak fixes (v3)

This patch series addresses file descriptor and memory leaks in test helper programs `test-truncate` and `test-delta`, now in its third iteration. The core issue involves ensuring proper resource cleanup in test infrastructure code, with v3 first fixing `test-truncate` and now completing the work with `test-delta`. The discussion has converged on distinct but complementary approaches for test helper resource management.

For `test-truncate`, the patch adds a missing `close(fd)` call after file truncation operations in `t/helper/test-truncate.c` (3 lines changed). Junio C Hamano questioned the practical necessity since the process exits immediately, making the patch technically unnecessary though harmless.

Jeff King has now proposed a comprehensive simplification of `test-delta.c` in three parts: [1/3] replaces manual error checking with `die()` calls, [2/3] converts file reading to use `strbuf` for simpler memory management, and [3/3] adds a missing `close()` for the output file descriptor. This results in a 53-line reduction while fixing several subtle issues: potential integer truncation in `xmalloc()`, unchecked short reads, and making the code more idiomatic through `strbuf` usage. The approach aligns with the thread's emerging consensus that test helpers can take shortcuts with cleanup (relying on process termination) while still handling memory leaks due to SANITIZE=leak constraints.

Eric Sunshine reviewed King's earlier proposal, acknowledging its technical soundness and noting the original cleanup code was superficially correct but flawed. Sunshine concurs with the pragmatic direction, observing test helpers don't need sophisticated cleanup since they exit immediately. Junio C Hamano has explicitly agreed with this stance, reinforcing the consensus that test helpers should prioritize simplicity and correctness, with memory handling being the exception due to build system requirements.

The discussion serves as an educational example of proper error handling patterns, with Sunshine demonstrating how earlier patches introduced a double-close bug through cleanup path unification. King's current proposal appears to be the culmination of the thread's technical discussion, implementing the pragmatic approach that both Sunshine and Hamano endorsed. The patches now await final review, with maintainer approval likely given the established positions. The thread has effectively concluded with consensus on balancing correctness with test helper constraints through process termination for file descriptors and careful memory handling for leak checks.
