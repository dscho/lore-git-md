Test helper resource leak fixes (v3)

This patch series addresses file descriptor leaks in test helper programs `test-truncate` and `test-delta`, now in its third iteration. The core issue involves ensuring proper resource cleanup in test infrastructure code, with v3 first fixing `test-truncate` and now completing the work with `test-delta`. The changes add missing cleanup logic while maintaining existing error handling patterns.

For `test-truncate`, the patch adds a missing `close(fd)` call after file truncation operations in `t/helper/test-truncate.c` (3 lines changed). Junio C Hamano has questioned the practical necessity of this change since the process exits immediately after the leak would occur, making the patch technically unnecessary (though not harmful). The motivation for the fix remains unclear - whether from automated checkers or part of broader cleanup efforts. The patch is being accepted regardless, maintaining consistency with the project's resource management patterns.

For `test-delta`, the patch initializes `fd` to -1 and consolidates all `close()` calls under a single cleanup label in `t/helper/test-delta.c` (9 lines changed), preventing undefined behavior from uninitialized descriptors while ensuring all opened descriptors are properly closed. This change is more clearly beneficial as it addresses potential undefined behavior in addition to resource cleanup.

The series modifies test infrastructure (not production code) with minimal changes. While only affecting test helpers, such leaks could impact test reliability by exhausting file descriptors during test runs. The changes maintain the existing `die_errno()` pattern for failures while ensuring cleanup on success. This version completes the work from v2 which addressed both helpers, with reviewers having previously provided feedback that has been incorporated. Both patches appear well-scoped and uncontroversial, directly addressing issues identified in prior review rounds. The `test-truncate` portion remains accepted despite questions about its practical impact, reflecting the project's general preference for proper resource management discipline.
