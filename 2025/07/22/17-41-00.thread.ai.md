Test helper resource leak fixes (v3)

This patch series addresses file descriptor and memory leaks in test helper programs `test-truncate` and `test-delta`, now in its third iteration. The core issue involves ensuring proper resource cleanup in test infrastructure code, with v3 first fixing `test-truncate` and now completing the work with `test-delta`. The discussion has converged on distinct but complementary approaches for test helper resource management.

For `test-truncate`, the patch adds a missing `close(fd)` call after file truncation operations in `t/helper/test-truncate.c` (3 lines changed). Junio C Hamano questioned the practical necessity since the process exits immediately, making the patch technically unnecessary though harmless. The motivation remains unclear - whether from automated checkers or broader cleanup efforts.

Jeff King proposed a significantly simplified approach for `test-delta`, using `die_errno()` on errors since test helpers exit immediately. His patch converts `t/helper/test-delta.c` to use `xopen()` and `die_errno()` consistently, reducing code by 33 lines while fixing two subtle issues: potential integer truncation in `xmalloc()` and unchecked short reads in `read_in_full()`. This eliminates explicit cleanup paths while maintaining failure behavior through process termination. King later clarified that while file descriptor cleanup could be omitted (as the OS reclaims them), memory cleanup must remain to avoid triggering the SANITIZE=leak checks that test helpers share with main code.

Eric Sunshine reviewed King's approach, acknowledging its technical soundness and noting the original cleanup code was superficially correct but flawed. Sunshine concurs with the pragmatic direction, observing test helpers don't need sophisticated cleanup since they exit immediately, though memory leaks must be handled differently than file descriptors due to build system constraints. He recognizes the additional bug fixes as worthwhile benefits, though less critical in test helper context.

The discussion presents clear consensus that test helpers should prioritize simplicity over meticulous cleanup given their transient nature, with memory leaks requiring special handling due to sanitizer integration. King's `die_errno()` approach is accepted as the `test-delta` solution, while the `test-truncate` changes remain included despite questions about necessity. The exchange demonstrates careful consideration of tradeoffs between code hygiene and maintainability in test infrastructure, with both patches representing valid approaches to resource management in different contexts.
