Test helper resource leak fixes (v3)

This patch series addresses file descriptor and memory leaks in test helper programs `test-truncate` and `test-delta`, now in its third iteration. The core issue involves ensuring proper resource cleanup in test infrastructure code, with v3 first fixing `test-truncate` and now completing the work with `test-delta`. The discussion has converged on distinct but complementary approaches for test helper resource management.

For `test-truncate`, the patch adds a missing `close(fd)` call after file truncation operations in `t/helper/test-truncate.c` (3 lines changed). Junio C Hamano questioned the practical necessity since the process exits immediately, making the patch technically unnecessary though harmless. The motivation remains unclear - whether from automated checkers or broader cleanup efforts.

Jeff King proposed a significantly simplified approach for `test-delta`, using `die_errno()` on errors since test helpers exit immediately. His patch converts `t/helper/test-delta.c` to use `xopen()` and `die_errno()` consistently, reducing code by 33 lines while fixing two subtle issues: potential integer truncation in `xmalloc()` and unchecked short reads in `read_in_full()`. This eliminates explicit cleanup paths while maintaining failure behavior through process termination. King clarified that while file descriptor cleanup could be omitted (as the OS reclaims them), memory cleanup must remain to avoid triggering the SANITIZE=leak checks that test helpers share with main code.

Eric Sunshine reviewed King's approach, acknowledging its technical soundness and noting the original cleanup code was superficially correct but flawed. Sunshine concurs with the pragmatic direction, observing test helpers don't need sophisticated cleanup since they exit immediately, though memory leaks must be handled differently than file descriptors due to build system constraints. He recognizes the additional bug fixes as worthwhile benefits, though less critical in test helper context. In a follow-up, Sunshine acknowledges his initial thought about removing all cleanup code didn't account for the memory sanitizer constraints, expressing appreciation for King's `die()` approach as a more refined version while maintaining compatibility with leak checker requirements.

Junio C Hamano now responds to Sunshine's detailed critique of Hoyoung Lee's earlier `test-delta` patch, highlighting Sunshine's identification of two key issues: a misleading commit message claiming to fix an uninitialized `fd` (which wasn't actually broken) and a more serious double-close bug introduced by the patch's cleanup path unification. The discussion serves as an educational example of proper error handling patterns, with Sunshine demonstrating how the double-close occurs when `fd` is manually closed mid-function but remains non-negative, causing a second close on error paths.

Junio C Hamano has now explicitly agreed with Jeff King's pragmatic stance on resource management in test helpers, reinforcing the consensus that test helpers can take shortcuts with file descriptor cleanup since the OS will reclaim them on process exit, while still needing to handle memory leaks due to SANITIZE=leak constraints. This maintainer endorsement confirms the thread's convergence on principles: test helpers should prioritize simplicity and correctness over comprehensive cleanup, with memory handling being the exception due to build system requirements. The discussion appears to be winding down with clear agreement on Jeff King's `die_errno()` approach for `test-delta` as the preferred solution. Junio's latest response, a smiley face acknowledgment to Sunshine's analysis, serves as final confirmation of this consensus without adding new technical content. The thread has effectively concluded with maintainer approval of the pragmatic approach balancing correctness with test helper constraints.
