This is a bugfix patch addressing a file descriptor leak in the test-truncate helper. It's the first of four patches in a series focused on fixing resource leaks in test helpers and the archive builtin.

The patch adds a missing `close(fd)` call in `t/helper/test-truncate.c` after the file truncation operation completes. The test helper was previously opening a file descriptor with `open()`, performing the truncation with `ftruncate()`, but failing to close the descriptor before returning. This could lead to resource exhaustion if the helper were called repeatedly in test scenarios.

The change is minimal and focused - just three lines added to ensure proper cleanup. The patch maintains the existing style and error handling patterns of the surrounding code. Since this is a test helper rather than production code, the impact is limited to test execution environments, but fixing such leaks helps maintain clean test hygiene and prevents potential issues in long-running test suites.

The patch follows the established pattern seen elsewhere in the codebase for similar file operations, where descriptors are explicitly closed after use. No behavioral changes are introduced beyond the resource cleanup.
