This is a feature patch adding format selection to the new `git repo info` command, part of Lucas Seiki Oshiro's GSoC project to create a repository metadata inspection tool. The patch introduces two output formats for `git repo info`: a default `keyvalue` format (key=value pairs separated by newlines) and a `null` format (key\nvalue\0) designed for machine parsing, inspired by similar options in `git config`. The implementation adds format parsing via `OPT_STRING`, modifies the printing logic to handle both formats with different delimiters, and updates tests to verify both formats work correctly with existing fields like `references.format` and `layout.bare`.

Key technical details include:
- New `enum output_format` with `FORMAT_KEYVALUE` and `FORMAT_NULL_TERMINATED` values
- Modified `print_fields()` function that takes the format as input and uses different delimiters (`=`/`\n` vs `\n`/`\0`)
- Test cases that verify both formats work with `lf_to_nul` helper for null format verification
- Documentation updates explaining both formats and their use cases

The patch follows the series' established patterns and maintains the direct-printing approach rather than buffering. It builds on the three implemented fields from previous patches while leaving open the question of whether to add `-z` as an alias for `--format=null`. The change is cleanly implemented with thorough test coverage for both formats.
