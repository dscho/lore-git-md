This is a refactoring patch in Patrick Steinhardt's 8-part series fixing reflog migration issues for the reftable backend. It reorganizes the `git reflog` subcommands to group them more logically - read-only commands first (`show`, `list`, `exists`), followed by write operations (`delete`, `drop`), with the broadest write operation (`expire`) last. 

The change is primarily code organization, with matching updates to both the documentation and implementation. The reordering serves two purposes: making the command structure more intuitive, and preparing for the introduction of a new `write` subcommand in a later patch (which will slot in with the other single-ref write operations).

The patch is mechanical and straightforward, touching both the man page and the command dispatch code in `builtin/reflog.c`. While not fixing any bugs directly, this cleanup helps maintainability and sets up for the more substantive changes coming later in the series. The changes appear well-considered and unlikely to be controversial.
