Performance feature for `git for-each-ref` pagination, finalizing the implementation with documentation and test improvements.

This is the final patch in Karthik Nayak's series adding `--start-after` pagination to `git for-each-ref`, building on the ref iterator seek functionality introduced earlier. The patch implements the user-facing option and documents its behavior, including the limitation that it cannot be used with custom sorting or pattern matching due to implementation constraints in how ref iteration works.

Junio Hamano provides several documentation improvements, noting that:
1. The `--exclude` option should be parenthesized in SYNOPSIS like other multi-options
2. The pattern matching restriction should be clarified to explicitly mention `--sort` and `--stdin` incompatibility
3. The interaction with `--exclude` is an implementation detail that doesn't need documentation but could use a test

The implementation uses a new `start_ref_iterator_after()` helper that seeks to the next reference by incrementing the marker character. The patch includes extensive tests (194 lines added) covering various pagination scenarios. Some technical notes from the discussion:
- The current implementation clears the prefix when using `--start-after`, which would need adjustment if the feature is later added to `git branch/tag`
- The seek operation properly uses the `REF_ITERATOR_SEEK_SET_PREFIX` flag
- Memory safety and initialization issues from earlier iterations have been resolved

This represents the final implementation of the pagination feature, with only minor polish remaining before full stabilization. The thread shows consensus on the technical approach and the MSan instrumentation issues have been separately addressed.
