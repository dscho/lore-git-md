This is the second patch in a series implementing a new `git repo info` subcommand, focusing on adding reference format detection. The patch introduces a `references.format` field that reports whether the repository uses 'files' or 'reftable' for ref storage.

The implementation leverages `git rev-parse --show-ref-format` internally, wrapping it in a new callback-based field system. Key technical elements include:
- A `struct field` array with lookup via `bsearch()`
- A `get_references_format()` callback that queries `repo->ref_storage_format`
- Sorting of requested fields and deduplication of repeated keys
- New test cases in `t1900-repo.sh` verifying both ref formats and duplicate key handling

The patch follows the series' architectural decisions by:
- Using direct printing rather than buffering
- Implementing the string-returning callback interface
- Maintaining the key=value output format
- Including thorough test coverage

The implementation appears clean and well-integrated with the existing infrastructure from patch 1/5. The test cases verify both positive cases (correct format reporting) and edge cases (duplicate key requests). Documentation is updated to include the new field in the man page.

This represents solid progress on the series' goal of exposing repository metadata, with the reference format being a logical first concrete field to implement given its existing plumbing via rev-parse. The patch maintains the series' focus on read-only introspection while establishing patterns for future field additions.
