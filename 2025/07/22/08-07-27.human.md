This is the final patch in a series implementing pagination support for `git for-each-ref`, adding the `--start-after` option to efficiently skip past already-seen references. The feature enables workflows where scripts can process references in chunks by remembering the last reference from each batch.

The patch follows up on Junio Hamano's review comments, agreeing to:
1. Improve documentation formatting for `--exclude` in the SYNOPSIS
2. Clarify the interaction between `--start-after` and other options
3. Add a test case for `--exclude` behavior with pagination
4. Clean up redundant prefix checks in the implementation

The discussion confirms that while `--start-after` currently can't be combined with pattern matching or custom sorting (due to implementation constraints), the exclusion filtering works as expected by operating late in the process. The code is future-proofed for potential integration with `git branch/tag` commands later.

With all major technical issues resolved in previous patches (including MemorySanitizer instrumentation fixes), this final version focuses on documentation polish and minor code improvements before the feature graduates from 'next' to 'master'. The implementation provides O(log N) seeking performance across all ref backends while clearly documenting the pagination behavior's limitations regarding concurrent reference updates.
