This is a review of patch 2/8 in a series introducing a new `git repo info` subcommand, focusing on the `references.format` field implementation. The patch adds functionality to report whether a repository uses 'files' or 'reftable' reference storage.

Karthik Nayak provides feedback email on Lucas Seiki Oshiro's implementation. The core functionality - exposing the reference storage format via `references.format` - looks solid, using `ref_storage_format_to_name()` to convert the internal enum to a string. Karthik suggests some naming improvements for clarity: renaming `add_field_callback` to better reflect its current role (it now returns values rather than adding fields) and proposes `get_value_fn_for_key` as a clearer alternative to `get_value_callback`.

The review highlights the clean design of the field printing system, noting it will easily accommodate future format variations. Karthik approves of the overall approach while catching some minor documentation and naming issues. The patch appears to be in good shape, with the feedback focusing on polish rather than structural changes. This continues the series' progress toward a flexible repository metadata reporting tool.
