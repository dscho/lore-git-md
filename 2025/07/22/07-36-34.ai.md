Bugfix for resource leak in test-delta's error path. This is the fourth and final patch in Hoyoung Lee's series addressing file descriptor leaks in test helpers and builtin commands.

The patch fixes a case in `t/helper/test-delta.c` where the file descriptor opened for argv[3] would leak if `fstat()` failed after a successful `open()`. The fix adds a simple `close(fd)` call in the error path, matching the pattern from patch 3 which fixed a similar issue with the first file descriptor in the same helper.

The change is minimal (2 lines added) and follows the same straightforward approach as the rest of the series - adding proper cleanup for error paths where file descriptors were previously being leaked. Like the other patches in the series, this appears to be a code-review-discovered issue rather than something that was causing user-visible problems, but it improves the robustness of the test helper.

Key technical details:
- Fixes second of two file descriptor leaks in test-delta.c
- Handles case where fstat() fails after opening argv[3]
- Uses same pattern as patch 3 (check fd >= 0 before close)
- No behavioral change on success paths

The series as a whole demonstrates consistent attention to resource management, with each patch addressing a similar class of issue in different parts of the codebase. This final change completes the coverage for the test-delta helper.
