Bugfix patch addressing file descriptor leaks in both the archive builtin and test-delta helper. This is the fourth and final in a series fixing similar resource leaks across different parts of the codebase.

The patch makes two distinct fixes. First, in `builtin/archive.c`, it corrects the error handling in `create_output_file()` to ensure the output file descriptor is properly closed when `dup2()` fails, moving the `close()` call inside the error condition while maintaining the existing `die_errno()` behavior. Second, in `t/helper/test-delta.c`, it adds a missing `close(fd)` call when `fstat()` fails after a successful `open()` of the input file, matching the pattern established in earlier patches of the series.

Both changes follow the same conservative approach seen in previous patches - adding only necessary cleanup in error paths without modifying successful execution flows. The archive.c change slightly restructures the error handling to make the control flow more explicit while preserving the same behavior. The test-delta.c change mirrors the earlier fix for test-truncate.c, closing the descriptor when `fstat()` fails after `open()` succeeds.

Key technical details include the file descriptors being opened with different flags (O_CREAT|O_WRONLY|O_TRUNC with mode 0666 for archive, O_RDONLY for test-delta) and the consistent use of existing error reporting mechanisms (`die_errno()` for archive builtin, `perror()` for test helper). This completes the series' systematic approach to fixing file descriptor leaks across test helpers and builtins.
