This discrepancy can lead to users accidentally creating reflog entries in unexpected locations.

Junio Hamano initially suggested unifying this behavior by extending DWIM (Do What I Mean) resolution to the `write` subcommand rather than removing it from others. Karthik Nayak provided implementation details showing how the existing DWIM resolution works through `repo_dwim_log()`. Now Ben Knoble has weighed in, sharing his own experience with this confusion when using similar commands like `git update-ref`. He strongly supports Junio's unification proposal, noting that the current behavior is both more intuitive for users and better aligned with existing Git conventions.

The thread has revealed several important considerations: the need for clearer documentation about refname resolution, the potential for data integrity issues when commands behave inconsistently, and the balance between technical precision and user expectations. With multiple contributors now supporting DWIM unification, the discussion appears to be converging on this approach as the path forward. The remaining questions focus on implementation details and documentation updates needed to ensure users understand both the shorthand and full-refname options.
