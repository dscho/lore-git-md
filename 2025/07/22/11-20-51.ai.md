Refactoring patch in a series improving reftable backend migration, specifically focusing on reflog subcommand organization. This is patch 2/8 in Patrick Steinhardt's v1 series addressing reflog handling issues discovered during libgit2 testing.

The patch reorganizes `git reflog` subcommands for better logical grouping, separating read-only operations (`show`, `list`, `exists`) from write operations (`delete`, `drop`, `expire`). It also moves the `expire` subcommand to the end of the list to prepare for the upcoming introduction of a new `write` subcommand in patch 4. Changes are made in both documentation (git-reflog.adoc) and implementation (builtin/reflog.c), maintaining identical functionality while improving code organization.

The reordering affects the help text display order but not the actual command behavior. This appears to be a straightforward preparatory change with no expected controversy, though reviewers may want to verify the new grouping makes sense before the subsequent `write` subcommand patch builds on it. The patch follows the documentation standardization started in patch 1, continuing the series' incremental approach to reflog improvements.
