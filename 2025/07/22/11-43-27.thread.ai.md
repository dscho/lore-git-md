Git imap-send documentation update. Thread root introduces a patch improving the `git imap-send` man page by adding a new section explaining the `--list` option for discovering IMAP folders, with Gmail as a concrete example showing client-visible vs server-side folder name mapping (e.g. "Junk" -> "[Gmail]/Spam"). Version 2 follows up with a minor but important wording fix, changing "need to be" to "need not be" when describing the relationship between client and server folder names. The documentation clarifies how to interpret verbose IMAP LIST output to determine correct folder names for patch submission, with annotated example output showing Gmail's specific naming scheme while noting the approach generalizes to other providers. No code changes - purely a documentation improvement addressing a common point of confusion.

Junio C Hamano responds to Aditya Garg's patch, agreeing the current docs are insufficient but questioning whether verbosity is the core issue. He suggests the unfriendliness of exposing raw IMAP protocol messages (with attributes like `\HasNoChildren` and server-side paths such as "[Gmail]/Spam") might warrant a code change to present folder names in a more user-friendly way rather than just documenting the current output format. The thread remains open on whether to accept the doc improvement as-is or push for an implementation change that would make such explanations unnecessary. Key technical detail remains the IMAP LIST output format showing folder attributes in parentheses followed by server-side paths, with Gmail's "[Gmail]/" prefix being the concrete example while the approach generalizes to other providers.
