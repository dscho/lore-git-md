Performance optimization patch for `git blame` that avoids unnecessary commit parsing. The change modifies two calls to `get_commit_info()` in `builtin/blame.c` to skip detailed commit information when only basic author metadata is needed.

The patch builds on a 2006 optimization in commit cee7f245d that allowed early termination of commit parsing, but notes this capability wasn't being fully utilized. The changes affect two code paths:
1. The `emit_other()` function used for blame output
2. The alignment calculation in `find_alignment()`

In both cases, the third parameter to `get_commit_info()` is changed from `1` (request full details) to `0` (basic info only), since these callers only need author information. The diff shows straightforward changes to the two call sites with no other modifications needed.

The commit message is clear about the optimization opportunity being addressed, though it doesn't provide performance measurements. The change appears safe as it's explicitly targeting code paths that don't require the detailed information being skipped. This seems like a low-risk optimization that could provide small but measurable improvements in blame performance, particularly for large repositories.
