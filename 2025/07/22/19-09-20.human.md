This is a bugfix patch series addressing path expansion in Git's GPG configuration. The changes focus on making `gpg.program` handle tilde expansion consistently with other Git path settings, while leaving the command-line argument handling behavior unchanged.

The series builds on previous discussion that revealed `gpg.program` was failing both as a path (lacking tilde expansion) and as a command (unable to parse arguments). This v2 iteration adds test cases for non-absolute paths, though the author notes some awkwardness in testing home directory expansion by overriding $HOME rather than creating a test user.

The implementation uses `git_config_pathname()` for consistent path handling while maintaining the current limitation that arguments in the value (like "gpg --option") still won't work properly. The documentation is updated to clarify this is a pathname parameter. The patch appears well-scoped to address the immediate path expansion issue while leaving larger design questions about argument handling for future work.
