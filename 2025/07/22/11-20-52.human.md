This is a refactoring patch in Patrick Steinhardt's series improving reflog handling for the reftable backend. It exports the previously internal `ref_transaction_update_reflog()` function to make it available for other parts of the codebase that need to write reflog entries, which will be used by a new reflog write subcommand in a later patch.

The change removes the `flags` parameter since all current callers use the same set of flags (REF_HAVE_OLD, REF_HAVE_NEW, etc.), hardcoding them in the function instead. The patch includes the expected documentation move from the .c to .h file and updates the one existing caller in the reflog migration code.

This is a straightforward preparatory change that follows the series' pattern of cleaning up infrastructure before adding new functionality. The patch appears well-contained and mechanically sound, with no obvious issues in the diff. It sets up for the more interesting reflog writing functionality coming in patch 4 of the series.
