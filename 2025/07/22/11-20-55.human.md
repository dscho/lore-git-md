This is a bugfix patch addressing identity handling in reflog migration between storage formats, part of Patrick Steinhardt's ongoing reftable backend series.

The patch fixes an issue where migrated reflog entries were getting malformed committer identities. The problem occurs because the migration was passing the full identity string (name + email) as just the email parameter to `fmt_ident()`, resulting in incorrectly formatted output like "pks <Patrick Steinhardt ps@pks.im>". The solution properly splits the identity line first using `split_ident_line()` to extract name and email components separately before formatting.

The changes add new `name` and `mail` strbuf fields to the migration data to properly handle the split components, and updates all relevant call sites to initialize and clean up these new fields. The fix is part of the larger effort to ensure correct reflog handling during the transition between files-based and reftable storage backends.

While the patch doesn't include new tests yet, the commit message notes that stricter verification will be added in a follow-up patch that will catch this issue along with another related bug. The changes appear focused and well-contained, building on the infrastructure work done in earlier patches of the series.
