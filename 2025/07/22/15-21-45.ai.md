This is a discussion about the output format syntax for the new `git repo info` subcommand, part of the ongoing feature series introducing repository metadata commands.

Junio C Hamano responds to Karthik Nayak's observation that the initial patch description inappropriately generalized the NUL-delimited output format as applying to all `git repo` subcommands when it's actually specific to the `info` subcommand. Hamano further questions the design choice of using LF as a field separator in the NUL-delimited format, noting that since consumers must already handle NULs, there's no parsing advantage to using LF rather than NUL for field and value separation. He also points out that fields might contain LFs themselves, which would require escaping and thus negate any simplicity benefits of the proposed format.

This exchange highlights two key design considerations for the `info` subcommand's machine-readable output: 1) the documentation needs to be precise about which subcommands use which formats, and 2) the NUL-delimited format's field separation syntax may need reevaluation to properly handle edge cases. The thread context shows this is part of v5 of an 8-patch series implementing repository metadata reporting, with three fields currently supported (`references.format`, `layout.bare`, `layout.shallow`) and two output formats (`keyvalue` and `null`). The discussion occurs between the series mentor (Karthik Nayak) and Git maintainer (Junio C Hamano), suggesting these are high-level design questions rather than implementation issues.
