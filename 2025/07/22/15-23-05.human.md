This is a bugfix series addressing several corner cases in Git's rename detection and merge handling, particularly in the `merge-ort` backend. The patches stem from real-world failures encountered at GitHub where certain combinations of renames and deletes could trigger assertion failures.

The series starts with some preparatory cleanups (comment updates, test fixes) before tackling two main issues: incorrect file handling during merges and a tricky directory rename interaction that occurs when one rename's target becomes another rename's source. The author notes the debugging process was particularly challenging due to interacting bugs and optimization behaviors that sometimes masked the true issues.

The changes touch both the merge-ort implementation and its test suite, with the bulk being test additions (520 lines added) to properly exercise these edge cases. While the author acknowledges the explanation might not be perfectly linear, the patches appear thorough and well-motivated by concrete failures. This looks like important stabilization work for users experiencing complex rename scenarios during merges.
